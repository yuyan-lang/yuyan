# 豫言操作系统底层接口

状态：源级接口草案 0.2（2026-10-01 加底层显示）。这里是仓库根目录下的独立规范树，只含接口包、纯声明和规范文字；各平台后端与 shim 在别处。Linux x86-64、arm64 与 macOS arm64 的 45 个底层函数已有后端，裸机已有用于验证与运行客体的后端；Windows 后端仍在规划中。GC 与 WASI shim 已部分改接，跨平台全量一致性仍待验收。设计缘由与整体方案见[总体架构](../豫言操作系统/文档/豫言操作系统总体架构.汉语.md)。文言本见[文言版](总纲.文言.md)。

## 是什么

一套**不含垃圾回收**的操作系统接口：值只有 32 位整数，数据以（地址，长度）与出址传递，每个函数返回状态码。它是各平台与上层之间的“窄腰”：Windows、macOS、Linux 和裸机各实现一份后端，WASI shim 与 GC shim 架在它上面。

它**只有两个使用者**：WASI shim 与 GC shim。应用不直接调用它：非 GC 应用用 WASI，GC 应用用[豫言操作系统接口](../豫言操作系统接口/总纲.汉语.md)。

## 与 GC 接口的关系

| | GC 接口（豫言操作系统接口） | 底层接口（本树） |
| --- | --- | --- |
| 值 | 豫言值类型：字符串、列、变体、资源…… | 32 位整数 |
| 编译模式 | 高级（有垃圾回收），依赖标准库 | 底层（无垃圾回收），依赖底层库 |
| 使用者 | 应用 | WASI shim、GC shim |
| 实现 | 宿主适配包（豫言写）与宿主库 | 平台后端实现包（豫言写），每平台一份 |
| 错误 | 变体结果与共用的系统错误 | 状态码（WASI errno 的子集） |
| 授权 | 授权表、目录权、显示面等 | 启动时的初始句柄表（预开目录） |

两棵树互不依赖。底层接口里没有的东西（HTTP、JSON、日期拆分、路径规范化、当前目录）由 shim 用豫言实现，不进后端。

## 文件与身份

- 每个能力组是独立的包 `豫言操作系统底层<能力>`，放在目录 `底层<能力>/` 里：`名称。包。豫`（`「编译模式」者『底层』也。`，依赖 `底层库` 与所需的本树其他包）、若干 `模块。接口。豫`、`规范.汉语.md` 与 `规范.文言.md`。
- 目录名等于包名去掉 `豫言操作系统` 前缀：现行检查器据此定位兄弟包，本树不需要另改定位规则。
- 接口文件的写法沿用 GC 接口的[接口文件规则](../豫言操作系统接口/接口文件规则.汉语.md)，差异与本树的通用规则见[调用约定](调用约定.汉语.md)：签名里只有 `整数`（返回值可以是 `有`），类型来自 `底层库` 的 `基础`，不写函数体。
- 同一依赖闭包内编译模式必须一致（豫构检查），所以本树的包不会混进 GC 类型，也不能依赖标准库。
- 目录根的 `豫言操作系统底层接口。包。豫` 是本树的父包，说明文件就是本总纲：它用「包含包」按“首批能力组”表格的顺序登记全部底层接口包，各包用「包含在」指回本包（规则见[包系统](../应用/豫构/包系统.汉语.md)“层级包”一节）。父包与库类型子包须同编译模式，所以父包也声明底层。父包不含模块，用于按层级发现。新增能力组时，在表格与父包「包含包」的相同位置登记，并在新包写「包含在」。

依赖关系：底层基础 ← 底层句柄 ← {底层文件、底层网络、底层终端、底层进程、底层显示}；所有包依赖 `底层库`。

## 检查

- 接口检查器 `yy豫言操作系统接口检查` 已改为按包索引定位包（原先只认自身、`标准库` 和以 `豫言操作系统` 开头的包，找不到 `底层库`；见[检查器说明](../豫言操作系统/应用/豫言操作系统接口检查/说明.汉语.md)），本树可以直接检查：`node 豫言操作系统/宿主/节点/宿主.cjs yy豫言操作系统接口检查.wasm 豫言操作系统底层接口/底层文件/豫言操作系统底层文件。包。豫`，`--清单` 与 `--核对清单` 同样可用。修复前后对全部 GC 接口包与适配清单做过对照，输出逐字相同。
- 状态码、标志、类别号等常量的统一机器可读定义仍待完成；现有后端和 shim 各持所需常量。
