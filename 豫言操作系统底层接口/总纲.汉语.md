# 豫言操作系统底层接口

状态：源级接口草案 0.1（框架，尚不完备）。这里是仓库根目录下的独立规范树，只含接口包、纯声明和规范文字；各平台后端与 shim 在别处。设计缘由与整体方案见[底层接口方案](../文档/豫言操作系统底层接口方案.汉语.md)。文言本见[文言版](总纲.文言.md)。

## 是什么

一套**不含垃圾回收**的操作系统接口：值只有 32 位整数，数据以（地址，长度）与出址传递，每个函数返回状态码。它是各平台与上层之间的“窄腰”：Windows、macOS、Linux 和裸机各实现一份后端，WASI shim 与 GC shim 架在它上面。

它**只有两个使用者**：WASI shim 与 GC shim。应用不直接调用它：非 GC 应用用 WASI，GC 应用用[豫言操作系统接口](../豫言操作系统接口/总纲.汉语.md)。

## 与 GC 接口的关系

| | GC 接口（豫言操作系统接口） | 底层接口（本树） |
| --- | --- | --- |
| 值 | 豫言值类型：字符串、列、变体、资源…… | 32 位整数 |
| 编译模式 | 高级（有垃圾回收），依赖标准库 | 底层（无垃圾回收），依赖底层库 |
| 使用者 | 应用 | WASI shim、GC shim |
| 实现 | 宿主适配包（豫言写）与宿主库 | 平台后端实现包（豫言写），每平台一份 |
| 错误 | 变体结果与共用的系统错误 | 状态码（WASI errno 的子集） |
| 授权 | 授权表、目录权、显示面等 | 启动时的初始句柄表（预开目录） |

两棵树互不依赖。底层接口里没有的东西（HTTP、JSON、日期拆分、路径规范化、当前目录）由 shim 用豫言实现，不进后端。

## 文件与身份

- 每个能力组是独立的包 `豫言操作系统底层<能力>`，放在目录 `底层<能力>/` 里：`名称。包。豫`（`「编译模式」者『底层』也。`，依赖 `底层库` 与所需的本树其他包）、若干 `模块。接口。豫`、`规范.汉语.md` 与 `规范.文言.md`。
- 目录名等于包名去掉 `豫言操作系统` 前缀：现行检查器据此定位兄弟包，本树不需要另改定位规则。
- 接口文件的写法沿用 GC 接口的[接口文件规则](../豫言操作系统接口/接口文件规则.汉语.md)，差异与本树的通用规则见[调用约定](调用约定.汉语.md)：签名里只有 `整数`（返回值可以是 `有`），类型来自 `底层库` 的 `基础`，不写函数体。
- 同一依赖闭包内编译模式必须一致（豫构检查），所以本树的包不会混进 GC 类型，也不能依赖标准库。

## 首批能力组

| 包 | 语义范围 | 函数 | 性质 |
| --- | --- | --- | --- |
| [底层基础](底层基础/规范.汉语.md) | 状态码、时钟、随机、命令行参数与环境、退出、中断、平台探测 | 11 | 核心 |
| [底层句柄](底层句柄/规范.汉语.md) | 句柄的读写、寻址、同步、等待、管道 | 13 | 核心 |
| [底层文件](底层文件/规范.汉语.md) | 按目录句柄授权的打开、状态、目录读取与增删改名 | 9 | 核心 |
| [底层网络](底层网络/规范.汉语.md) | TCP 监听、连接、接受 | 7 | 可选 |
| [底层终端](底层终端/规范.汉语.md) | 终端模式与尺寸 | 2 | 可选 |
| [底层进程](底层进程/规范.汉语.md) | 运行程序、取退出码、终止 | 3 | 可选 |

共 45 个函数。“可选”指平台可以没有：没有时所有函数返回 58（不支持），shim 据此降级。显示与输入预留为 `豫言操作系统底层显示`，v2 再做。

依赖关系：底层基础 ← 底层句柄 ← {底层文件、底层网络、底层终端、底层进程}；所有包依赖 `底层库`。

## 检查

- 接口检查器 `yy豫言操作系统接口检查` 已改为按包索引定位包（原先只认自身、`标准库` 和以 `豫言操作系统` 开头的包，找不到 `底层库`；见[检查器说明](../工具/豫言操作系统接口检查/说明.汉语.md)），本树可以直接检查：`./yy豫言操作系统接口检查 豫言操作系统底层接口/底层文件/豫言操作系统底层文件。包。豫`，`--清单` 与 `--核对清单` 同样可用。修复前后对全部 GC 接口包与适配清单做过对照，输出逐字相同。
- 状态码、标志、类别号等常量目前只写在各包的规范里；随第一个后端补一个机器可读的常量库，避免 shim 与后端各抄一份。
