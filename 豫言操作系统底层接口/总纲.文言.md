# 豫言操作系统底层接口

状：源级接口之草案〇点一（框架，尚未备）。此仓库根目录下之独立规范树，唯含接口包、纯声明与规范之文；诸平台后端与垫层，皆在他处。设计之由与全案，见[底层接口方案](../文档/豫言操作系统底层接口方案.文言.md)。汉语本见[汉语版](总纲.汉语.md)。

## 是何物

一套**无垃圾回收**之操作系统接口：值唯三十二位整数，数据以（址，长）与出址相授，每函数返状态之码。乃诸平台与上层之间之“窄腰”：Windows、macOS、Linux 与裸机各成一后端，WASI 垫层与 GC 垫层架于其上。

其用者**唯二**：WASI 垫层与 GC 垫层。应用不径呼之：非 GC 应用用 WASI，GC 应用用[豫言操作系统接口](../豫言操作系统接口/总纲.文言.md)。

## 与 GC 接口之系

| | GC 接口（豫言操作系统接口） | 底层接口（本树） |
| --- | --- | --- |
| 值 | 豫言值类型：字符串、列、变体、资源…… | 三十二位整数 |
| 编译之模 | 高级（有垃圾回收），依标准库 | 底层（无垃圾回收），依底层库 |
| 用者 | 应用 | WASI 垫层、GC 垫层 |
| 实现 | 宿主适配包（豫言书之）与宿主库 | 平台后端实现包（豫言书之），每平台一 |
| 误 | 变体之果与共用之系统错误 | 状态之码（WASI errno 之子集） |
| 授权 | 授权表、目录权、显示面等 | 启动时之初始柄表（预开之目录） |

二树互不相倚。底层接口之所无者（HTTP、JSON、日期拆分、路径规整、当前目录），由垫层以豫言为之，不入后端。

## 文件与身份

- 每能力组各为一包 `豫言操作系统底层<能力>`，置于目录 `底层<能力>/`：`名称。包。豫`（`「编译模式」者『底层』也。`，依 `底层库` 及所需之本树他包）、若干 `模块。接口。豫`、`规范.汉语.md` 与 `规范.文言.md`。
- 目录名即包名去 `豫言操作系统` 前缀：今之检查器据此定位兄弟之包，本树不必另改定位之规。
- 接口文之书法，沿 GC 接口之[接口文件规则](../豫言操作系统接口/接口文件规则.文言.md)，其异与本树通用之规，见[调用约定](调用约定.文言.md)：签中唯有 `整数`（返值可为 `有`），类型取诸 `底层库` 之 `基础`，不书函数体。
- 同一依赖闭包之内，编译之模必同（豫构校之），故本树之包不混入 GC 之型，亦不得依标准库。

## 检查

- 接口检查器 `yy豫言操作系统接口检查` 已改循包索引以定位诸包（昔唯识自身、`标准库` 与以 `豫言操作系统` 起首之包，不得 `底层库`；见[检查器说明](../工具/豫言操作系统接口检查/说明.文言.md)），本树可径检之：`./yy豫言操作系统接口检查 豫言操作系统底层接口/底层文件/豫言操作系统底层文件。包。豫`，`--清单` 与 `--核对清单` 亦可用。修前修后，于全部 GC 接口包与适配之清单，皆作对照，所出逐字相同。
- 状态之码、标志、类别之号等常量，今唯书于各包之规范；随首个后端，补机器可读之常量库，免垫层与后端各抄一份。
