# 豫言操作系统底层接口

状：源级接口之草案〇点二（二〇二六年十月一日增底层显示）。此仓库根目录下之独立规范树，唯含接口包、纯声明与规范之文；诸平台后端与垫层，皆在他处。Linux x86-64、arm64 与 macOS arm64 之后端，已备四十五底层函数；裸机亦有供验与行客体之后端，Windows 犹待为。GC 与 WASI 垫层已改接其一部，跨平台全量一致之验犹待行。设计之由与全案，见[总体架构](../豫言操作系统/文档/豫言操作系统总体架构.文言.md)。汉语本见[汉语版](总纲.汉语.md)。

## 是何物

一套**无垃圾回收**之操作系统接口：参皆以六十四位传之（柄、标志与状码为三十二位整数，址、长、偏与时刻为六十四位之量），数据以（址，长）与出址相授，每函数返状态之码。子任务与豫行启动器中之客经底层转送呼之，服务之号见[调用之约](调用约定.文言.md)“七之二”。乃诸平台与上层之间之“窄腰”：Windows、macOS、Linux 与裸机各成一后端，WASI 垫层与 GC 垫层架于其上。

其用者，WASI 垫层、GC 垫层与行在核（共用系统核心）也。非 GC 应用用 WASI，GC 应用用[豫言操作系统接口](../豫寓榫卯/总纲.文言.md)。

## 硬件接口

底层接口兼为共核与机器之界，循提案 00067 第二版三之一至三之三。任务簿、仓阍、消息、剪贴、起居之记，皆由共核掌之；各平台下层授已映已许之状址，供文件、网络、终端、进程、显示、时钟诸务。裸机仍授旧全局、槽区、缓冲之址，其布局、务号、返值皆循故约。

机器之务有四：

| 务 | 裸机所司 | 宿主所司 |
| --- | --- | --- |
| 起收执行上下文 | 内核下层分收任务槽、页表、调度现场与浮点之状 | 底层进程后端由发起之进程起宿主之务，子务登记父籍号，后端收其上下文 |
| 结束送信号 | 内核下层依所授上下文结束、打断，掌调度与现场 | 宿主后端以核心籍号对宿主进程号，乃结束送信 |
| 配上下文之存 | 内核下层分、映、收物理页，共核记仓籍 | 宿主后端佐共核记账，诸进程自掌址域，执行器司换页文件 |
| 控制面之门 | 内核陷入之口受请求而交共核 | 执行器之行在（宿主上的豫言系统）门与宿主后端本机之连，载登记帧、问帧、答帧 |

初迁之存务，循导入“内核”之六签：读四受长整数址而返整数；写四受长整数址、整数值而返有；读八受长整数址而返长整数；写八受长整数址与值而返有；清零受长整数址与长而返有；复制字节受目、源、长三长整数而返有。声在 `豫言操作系统/裸机/库/行在核/内核。底层接口。豫`，裸机由旧内核态原语供之，宿主接入列第二步。读写之界在下层所授之状区与缓冲；滴答之址由旧核授于存注之期，共核经存务接口依旧序读累计与今时。上下文诸函之签，随任务簿之分而登。

## 与 GC 接口之系

| | GC 接口（豫言操作系统接口） | 底层接口（本树） |
| --- | --- | --- |
| 值 | 豫言值类型：字符串、列、变体、资源…… | 整数与长整数（以六十四位传） |
| 编译之模 | 高级（有垃圾回收，`模块。接口。豫`），依标准库 | 底层（无垃圾回收，`模块。底层接口。豫`），依底层库 |
| 用者 | 应用 | WASI 垫层、GC 垫层、共用核心 |
| 实现 | 宿主适配包（豫言书之）与宿主库 | 平台后端实现包（豫言书之），每平台一 |
| 误 | 变体之果与共用之系统错误 | 状态之码（WASI errno 之子集） |
| 授权 | 授权表、目录权、显示面等 | 启动时之初始柄表（预开之目录） |

二树互不相倚。底层接口之所无者（HTTP、JSON、日期拆分、路径规整、当前目录），由垫层以豫言为之，不入后端。

## 文件与身份

- 每能力组各为一包 `豫言操作系统底层<能力>`，置于目录 `底层<能力>/`：`名称。包。豫`（依 `磐石` 及所需之本树他包）、若干 `模块。底层接口。豫`、`规范.汉语.md` 与 `规范.文言.md`。
- 目录名即包名去 `豫言操作系统` 前缀：今之检查器据此定位兄弟之包，本树不必另改定位之规。
- 接口文之书法，沿 GC 接口之[接口文件规则](../豫寓榫卯/接口文件规则.文言.md)，其异与本树通用之规，见[调用约定](调用约定.文言.md)：签中唯有 `数`（返值可为 `有`），类型取诸 `磐石` 之 `基础`，不书函数体。
- 接口之文为底层之文（`。底层接口。豫`），所导唯求底层之模（编译器校之），故本树之签唯用底层库之类。
- 目根之 `豫言操作系统底层接口。包。豫` 为本树之父包，其说即此总纲：以「包含包」依首批能力组之表序登诸底层接口包，诸包以「包含在」还指之（其制见[包制](../应用/豫构/包系统.文言.md)“层级之包”之节）。父包无模，以便循层寻包。增能力组者，表与父之「包含包」同处并登，新包书「包含在」。
