# 豫言操作系统底层网络 0.2.0

## 本地套接字与传句柄

`寓听`（本地监听）、`寓连`（本地连接）按路径地址、字节数与出址监听或连接本地流式套接字，路径上限一百零三字节，队列一千二十四。成功写出原始宿主句柄，接受复用 `迎`（接受连接）。`传柄寄`（发送句柄）、`传柄收`（接收句柄）的六参为连接、帛缓冲、帛长度、柄表、柄容量、字节数出址；柄表为四字节个数后接至多八个四字节句柄。成功为零，暂不可用为六，其他正值为底层状态码。成功收零字节表示对端关闭。

服务号一百八十六至一百八十九依次对应四项；虚机服务方先把客体缓冲读入本机暂存，调用共用核心，先登记新柄，再写回结果。接收柄归发起任务，发送保留属主。短写续帛使用普通写入，首封句柄只交付一次。控制消息截断、容量超限及设置执行即闭失败时回收本次全部新柄。真裸机返回五十八；轩窗实现列为后续事项。

本机实现位于客体二号（执行器）的寓套基（本地套接字基础）子包，林檎与林纳各循本机的消息头、辅助头与本地地址布局。规范的句柄数限制及缓冲布局同时适用于薄启动器与客体。

状态：草案，可选能力。文言本见[文言版](规范.文言.md)。通用规则见[调用约定](../调用约定.汉语.md)，状态码表见[底层基础](../底层基础/规范.汉语.md)，数据收发与等待见[底层句柄](../底层句柄/规范.汉语.md)。

## 范围

TCP 的监听、连接与接受，UDP 数据报的建、连、发、收，以及取套接字的本端与对端地址。TCP 的数据收发、等待、关闭都用底层句柄的 `读`、`写`、`等待`、`关闭`；数据报用本包的 `投书`、`得书` 收发，等待与关闭同样用底层句柄的函数。套接字是句柄（类别 6）。平台没有网络时，本包所有函数返回 58。TLS、域名解析接口与套接字选项（除 `设勿滞`）不在本包；HTTP 与 TLS 由 shim 在 TCP 之上用豫言实现。

## 流程

**服务端。** `开门` 得到监听句柄；用 `等待`（可读）得知有待接受的连接；`迎` 得到连接句柄。

**客户端。** `叩门` 立即返回一个非阻塞的连接句柄（域名解析可能在此期间阻塞，首版接受这一点）；用 `等待`（可写）等连接完成；`入门` 取得结果：状态码 0 表示已连上，否则是失败原因（14 连接被拒、73 超时、……）。

**收发。** 连接句柄用 `读`、`写`：读得 0 表示对端有序关闭；对端重置返回 15；写到已关闭的连接返回 64。`缄口` 只关写方向，对端读到文件尾，本端仍可读。`关闭` 释放句柄。

新接受的连接句柄默认阻塞；需要非阻塞时用 `设非阻塞`。

**数据报（0.2.0）。** `置雁` 建一个绑在（主机，端口）上的 UDP 句柄（主机为空串表示任意地址，端口 0 由平台挑一个）；`投书` 把一个报文整个发给（主机，端口）；`得书` 收一个报文，同时得到来源地址。`连雁` 给句柄设对端：此后 `投书` 的主机长为 0 时发给对端，`得书` 只收来自对端的报文。用 `等待`（可读）等报文到来。新建的数据报句柄默认阻塞，没有报文时 `得书` 等到有为止；需要非阻塞时用 `设非阻塞`，此时没有报文返回 6。数据报句柄在建立时一律开广播许可（`SO_BROADCAST`），所以 `投书` 可以发往 `255.255.255.255`，用于代理动态主机配置这类需要广播答复的协议；广播报文到达哪些网卡由平台的路由与子网掩码决定。开广播许可失败时，`置雁` 关闭刚建的套接字并返回平台的错误码（负值），不留下半开的句柄；调用方按普通建套接字失败处理。

## 函数（`网络。底层接口。豫`）

| 函数 | 参数 | 作用 |
| --- | --- | --- |
| 监听 | 主机址, 主机长, 端口, 队列长, 出 | 在（主机，端口）上监听；主机为空串表示任意地址；解析不出返回 44；监听句柄 4 字节写入出址；地址已用返回 3 |
| 连接开始 | 主机址, 主机长, 端口, 出 | 开始连接，非阻塞；主机可以是名字或数字地址；解析不出返回 44；句柄 4 字节写入出址 |
| 连接完成 | 句柄 | 取得连接结果，状态码即结果；连接尚未完成返回 6 |
| 接受 | 监听句柄, 出 | 新连接句柄 4 字节写入出址；非阻塞且没有待接受的连接返回 6 |
| 关闭写 | 句柄 | 半关闭 |
| 取本地端口 | 句柄, 出 | 本地端口，4 字节（监听时端口为 0 的场合用它取得实际端口） |
| 设无延迟 | 句柄, 开关 | 开关 1 置无延迟（关闭 Nagle），0 取消 |
| 建数据报 | 主机址, 主机长, 端口, 出 | 建 UDP 句柄并绑在（主机，端口）上；句柄 4 字节写入出址；地址已用返回 3 |
| 连数据报 | 句柄, 主机址, 主机长, 端口 | 设对端；主机可以是名字或数字地址；解析不出返回 44 |
| 发数据报 | 句柄, 缓冲址, 缓冲长, 主机址, 主机长, 端口 | 把缓冲作为一个报文发给（主机，端口）；主机长为 0 时发给对端，没设对端返回 53；报文过长返回 28 |
| 收数据报 | 句柄, 缓冲址, 缓冲长, 来源址, 出 | 收一个报文：报文长于缓冲时多出的部分丢掉；收到的字节数 4 字节写入出址；来源址不为 0 时把来源写成地址块（见下）；非阻塞且没有报文返回 6 |
| 取套接字地址 | 句柄, 对端, 出 | 对端为 0 取本端地址、为 1 取对端地址，写成地址块；流套接字与数据报套接字都可用；没有对端返回 53 |

后加的函数（0.2.0）排在扩展号段，服务号见调用约定“服务号与转送”：建数据报 165，连数据报 166，发数据报 167，收数据报 168，取套接字地址 169。

## 地址块

普通豫言通过豫章（标准库）`驿/宾主` 的 `问连址`（套接字地址查询）读取同一地址块：阳取对端，阴取本端，结果为操作结果于字节串。宿主原语号三百一十八；成功状态为零，失败为底层状态码的负值并附空字节串。

24 字节，小端：

| 偏移 | 宽 | 字段 |
| --- | --- | --- |
| 0 | 4 | 地址族：4 为 IPv4，6 为 IPv6 |
| 4 | 4 | 端口 |
| 8 | 16 | 地址，网络字节序（IPv4 用前 4 字节，其余为 0） |

## 平台注记

### 浏览器

浏览器通过原生豫言中继服务访问外网 TCP。中继运行于林纳、林檎的行在（宿主上的豫言系统）与豫言操作系统；九府（自建云服务）的外府（对外服务）承载其对外入口。

连接地址为 `wss://<中继主机>/中继?主机=<主机>&端口=<端口>`；查询参数按网址成分编码。本机验证使用 `ws://`。一条笔谈（WebSocket）连接对应一条目标 TCP 连接。

握手与传输按以下次序办理：

1. 客户端发送文字帧 `凭 <令牌>`，其中空格为一个半角空格，后面为完整令牌。
2. 中继核验令牌、Origin、目标地址与连接配额，连接目标并核验实际对端地址，然后发送文字帧 `连上`。
3. 双向数据采用二进制帧，每帧载荷为字节流的一段，按到达次序拼接；零字节和帧内全部字节原样传递。
4. 客户端发送文字帧 `缄口` 时，中继先把此前收到的数据全部写入 TCP，再关闭 TCP 写方向，继续转发对端数据。
5. 目标 TCP 有序结束时，中继先发完已经收到的目标数据，再以关闭码 1000 结束笔谈连接。

错误关闭码为四千加底层状态码。使用现有全树状态码：4014 为连接被拒，4073 为超时，4058 为能力不支持，4002 为令牌或 Origin 核验失败，4076 为目标无效或越出许可范围，4019 为令牌连接配额已尽，4028 为协议消息无效。目标主机与端口的解析、许可检查统一以 4076 拒绝。客户端可据关闭码取得原始底层错误码。

服务配置采用籍册（数据文件）`名。数据。豫`，保存令牌的沙二五六（SHA-256）摘要与 Origin 白名单。鉴权函数由服务程序传入中继库。带 Origin 的请求依白名单逐项核验；Origin 缺席的客户端依令牌核验。每个令牌摘要同时至多三十二条中继连接，连接结束时归还配额。

目标端口取一至六万五千五百三十五，端口二十五列入禁区。四版、六版地址中的私网、环回、链路本地、运营商级 NAT、组播与保留地址列入禁区。字面地址在连接前核验；域名目标在连接成功后以 `问主址`（取套接字地址，对端参数为一）取得实际对端地址再核验，核验通过后发送 `连上` 并开始转发。

每条连接结束时写一行日志，字段为令牌摘要的前八个十六进制字符、目标主机与端口、客户端至目标的字节数、目标至客户端的字节数、连接持续时长。日志中的身份字段采用令牌摘要前缀。

### 各宿主

- 桌面：BSD 套接字（Linux、macOS）与 ws2_32（Windows）；IPv4 与 IPv6 由平台决定；`开门` 与 `置雁` 的主机串为空时监听双栈或任意地址。数据报的四个函数与 `问主址` 在 Linux、macOS 上用 `bind`、`connect`、`sendto`、`recvfrom`、`getsockname`、`getpeername`；Windows 上留待后续版本，现在返回 58。
- 裸机：网络栈在初始任务的执行器里（以太网、ARP、IPv4、IPv6、ICMPv6、邻居发现、UDP、TCP、环回）。子任务的调用经底层转送由初始任务办理（见调用约定“服务号与转送”）；初始任务不阻塞，套接字与数据报句柄都按非阻塞办理，没有数据时返回 6，子任务用 `等待` 等就绪。主机名按数字地址（点分十进制或 IPv6 字面量，字面量可加方括号）、`localhost` 与域名服务器查询解析；连接域名时，配出全局 IPv6 地址后先查 AAAA 记录、先试 IPv6，连不上再回落到 IPv4（RFC 8305 的最简做法）。IPv6 的链路本地地址按以太地址以 EUI-64 生成，全局地址与缺省路由取路由通告，重复地址检测做最简的一次；开机发一次路由请求就往下走，通告到了在网络轮询里再配地址，没到就每隔三秒补发一次、至多五次，不挡开机；`::1` 走环回。
- 与标准库现有的传输控制协议原语（14 个，`豫言_传输控制协议_*`）一一可以由本包加底层句柄实现：监听、开始连接、完成连接、接受、读取、写入、等待、获取本地端口、设置无延迟、关闭写入、关闭。标准库的数据报交换（原语 176）由 `置雁`、`连雁`、`投书`、`等待`、`得书` 与 `关闭` 实现。
