# 豫言操作系统底层网络 0.2.0

状态：草案，可选能力。文言本见[文言版](规范.文言.md)。通用规则见[调用约定](../调用约定.汉语.md)，状态码表见[底层基础](../底层基础/规范.汉语.md)，数据收发与等待见[底层句柄](../底层句柄/规范.汉语.md)。

## 范围

TCP 的监听、连接与接受，UDP 数据报的建、连、发、收，以及取套接字的本端与对端地址。TCP 的数据收发、等待、关闭都用底层句柄的 `读`、`写`、`等待`、`关闭`；数据报用本包的 `发数据报`、`收数据报` 收发，等待与关闭同样用底层句柄的函数。套接字是句柄（类别 6）。平台没有网络时，本包所有函数返回 58。TLS、域名解析接口与套接字选项（除 `设无延迟`）不在本包；HTTP 与 TLS 由 shim 在 TCP 之上用豫言实现。

## 流程

**服务端。** `监听` 得到监听句柄；用 `等待`（可读）得知有待接受的连接；`接受` 得到连接句柄。

**客户端。** `连接开始` 立即返回一个非阻塞的连接句柄（域名解析可能在此期间阻塞，首版接受这一点）；用 `等待`（可写）等连接完成；`连接完成` 取得结果：状态码 0 表示已连上，否则是失败原因（14 连接被拒、73 超时、……）。

**收发。** 连接句柄用 `读`、`写`：读得 0 表示对端有序关闭；对端重置返回 15；写到已关闭的连接返回 64。`关闭写` 只关写方向，对端读到文件尾，本端仍可读。`关闭` 释放句柄。

新接受的连接句柄默认阻塞；需要非阻塞时用 `设非阻塞`。

**数据报（0.2.0）。** `建数据报` 建一个绑在（主机，端口）上的 UDP 句柄（主机为空串表示任意地址，端口 0 由平台挑一个）；`发数据报` 把一个报文整个发给（主机，端口）；`收数据报` 收一个报文，同时得到来源地址。`连数据报` 给句柄设对端：此后 `发数据报` 的主机长为 0 时发给对端，`收数据报` 只收来自对端的报文。用 `等待`（可读）等报文到来。新建的数据报句柄默认阻塞，没有报文时 `收数据报` 等到有为止；需要非阻塞时用 `设非阻塞`，此时没有报文返回 6。

## 函数（`网络。底层接口。豫`）

| 函数 | 参数 | 作用 |
| --- | --- | --- |
| 监听 | 主机址, 主机长, 端口, 队列长, 出 | 在（主机，端口）上监听；主机为空串表示任意地址；监听句柄 4 字节写入出址；地址已用返回 3 |
| 连接开始 | 主机址, 主机长, 端口, 出 | 开始连接，非阻塞；主机可以是名字或数字地址；句柄 4 字节写入出址 |
| 连接完成 | 句柄 | 取得连接结果，状态码即结果；连接尚未完成返回 6 |
| 接受 | 监听句柄, 出 | 新连接句柄 4 字节写入出址；非阻塞且没有待接受的连接返回 6 |
| 关闭写 | 句柄 | 半关闭 |
| 取本地端口 | 句柄, 出 | 本地端口，4 字节（监听时端口为 0 的场合用它取得实际端口） |
| 设无延迟 | 句柄, 开关 | 开关 1 置无延迟（关闭 Nagle），0 取消 |
| 建数据报 | 主机址, 主机长, 端口, 出 | 建 UDP 句柄并绑在（主机，端口）上；句柄 4 字节写入出址；地址已用返回 3 |
| 连数据报 | 句柄, 主机址, 主机长, 端口 | 设对端；主机可以是名字或数字地址；解析不出返回 44 |
| 发数据报 | 句柄, 缓冲址, 缓冲长, 主机址, 主机长, 端口 | 把缓冲作为一个报文发给（主机，端口）；主机长为 0 时发给对端，没设对端返回 53；报文过长返回 28 |
| 收数据报 | 句柄, 缓冲址, 缓冲长, 来源址, 出 | 收一个报文：报文长于缓冲时多出的部分丢掉；收到的字节数 4 字节写入出址；来源址不为 0 时把来源写成地址块（见下）；非阻塞且没有报文返回 6 |
| 取套接字地址 | 句柄, 对端, 出 | 对端为 0 取本端地址、为 1 取对端地址，写成地址块；流套接字与数据报套接字都可用；没有对端返回 53 |

后加的函数（0.2.0）排在扩展号段，服务号见调用约定“服务号与转送”：建数据报 165，连数据报 166，发数据报 167，收数据报 168，取套接字地址 169。

## 地址块

24 字节，小端：

| 偏移 | 宽 | 字段 |
| --- | --- | --- |
| 0 | 4 | 地址族：4 为 IPv4，6 为 IPv6 |
| 4 | 4 | 端口 |
| 8 | 16 | 地址，网络字节序（IPv4 用前 4 字节，其余为 0） |

## 平台注记

- 桌面：BSD 套接字（Linux、macOS）与 ws2_32（Windows）；IPv4 与 IPv6 由平台决定；`监听` 与 `建数据报` 的主机串为空时监听双栈或任意地址。数据报的四个函数与 `取套接字地址` 在 Linux、macOS 上用 `bind`、`connect`、`sendto`、`recvfrom`、`getsockname`、`getpeername`；Windows 上留待后续版本，现在返回 58。
- 裸机：网络栈在初始任务的执行器里（以太网、ARP、IPv4、UDP、TCP、环回）。子任务的调用经底层转送由初始任务办理（见调用约定“服务号与转送”）；初始任务不阻塞，套接字与数据报句柄都按非阻塞办理，没有数据时返回 6，子任务用 `等待` 等就绪。主机名按点分十进制、`localhost` 与域名服务器查询解析。IPv6 留待后续版本。
- 与标准库现有的传输控制协议原语（14 个，`豫言_传输控制协议_*`）一一可以由本包加底层句柄实现：监听、开始连接、完成连接、接受、读取、写入、等待、获取本地端口、设置无延迟、关闭写入、关闭。标准库的数据报交换（原语 176）由 `建数据报`、`连数据报`、`发数据报`、`等待`、`收数据报` 与 `关闭` 实现。
