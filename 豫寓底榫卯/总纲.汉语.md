# 豫言操作系统底层接口

## 单进程宿主任务的内存绑定

行在核（共用任务与资源核心）的六项内存接口保留原声明：读四、写四、读八、写八、清零、复制字节。冶铸（原生后端）在宿主目标上将这六项“内核”导入绑定到既有内核内存原语，使用硬件层授予的绝对地址。裸机继续按原内核态条件绑定。任务、邮箱与仓共用同一套核心代码。

宿主硬件适配在数值服务边界封装编号和地址，普通辅助接口用抽象类型区分任务编号、宿主句柄、客体偏移和宿主绝对地址。挂起请求与返回位置由任务记录持有，等待集合保存事件所属任务和原订阅序号。

状态：源级接口草案 0.2（2026-10-01 加底层显示）。这里是仓库根目录下的独立规范树，只含接口包、纯声明和规范文字；各平台后端与 shim 在别处。Linux x86-64、arm64 与 macOS arm64 的 45 个底层函数已有后端，裸机已有用于验证与运行客体的后端；Windows 后端仍在规划中。GC 与 WASI shim 已部分改接，跨平台全量一致性仍待验收。设计缘由与整体方案见[总体架构](../豫言操作系统/文档/豫言操作系统总体架构.汉语.md)。文言本见[文言版](总纲.文言.md)。

## 是什么

一套**不含垃圾回收**的操作系统接口：参数按六十四位传递（句柄、标志与状态码是 32 位整数，地址、长度、偏移与时刻是六十四位的量），数据以（地址，长度）与出址传递，每个函数返回状态码。子任务与豫行启动器里的客体经底层转送调用它，服务号见[调用约定](调用约定.汉语.md)“七之二”。它是各平台与上层之间的“窄腰”：Windows、macOS、Linux 和裸机各实现一份后端，WASI shim 与 GC shim 架在它上面。

它的使用者是 WASI shim、GC shim 与行在核（共用系统核心）。非 GC 应用用 WASI，GC 应用用[豫言操作系统接口](../豫寓榫卯/总纲.汉语.md)。

## 硬件接口

底层接口兼作共用核心与机器之间的硬件接口（提案 00067 第二版 3.1–3.3）。共用核心保存任务表、内存池、准入、消息、剪贴板与内核日志的状态；各平台硬件层提供已映射、已授权的状态区地址，以及文件、网络、终端、进程、显示、时钟等机器能力。裸机硬件层传入原全局区、原槽区与原缓冲区地址，状态布局、服务号、返回值沿用原约定。

机器级功能分为四组：

| 功能 | 裸机实现者 | 宿主实现者 |
| --- | --- | --- |
| 起与收执行上下文 | 内核硬件层分配与回收任务槽、页表、调度现场、浮点上下文 | 底层进程后端由发起方进程起宿主进程，子进程向核心登记父籍号，后端收回执行上下文 |
| 结束与送信号 | 内核硬件层按核心给出的上下文执行结束或打断，办理调度与现场 | 宿主后端将核心籍号对应到所持的宿主进程号，再结束或送信号 |
| 给上下文配内存 | 内核硬件层分配、映射、回收物理页，共用核心更新内存池记录 | 宿主后端配合核心记账，各宿主进程管理自己的地址空间，执行器办理换页文件 |
| 控制面的门 | 内核陷入入口接收服务请求并交共用核心 | 执行器的行在（宿主上的豫言系统）门与宿主后端的本机连接承载登记帧、问帧与答帧 |

第一批迁移的内存硬件接口沿用导入模块“内核”的六项签名：读四（长整数地址）→整数，写四（长整数地址、整数值）→有，读八（长整数地址）→长整数，写八（长整数地址、长整数值）→有，清零（长整数地址、长整数长度）→有，复制字节（目、源、长，皆长整数）→有。其声明在 `豫言操作系统/裸机/库/行在核/内核。底层接口。豫`，裸机由既有内核态原语实现；宿主后端接入列为第二步。内存读写限于硬件层授予的状态区与缓冲区；滴答状态地址由内核接线函数传入日志的到期判断，核心经内存硬件接口按原次序读取累计与当前滴答。机器级上下文函数的具体签名随任务表拆分登记。

### 任务表的机器级签名

行在核（共用系统核心）的任务簿（任务表记账）通过本包 `实约机。底层接口。豫` 调用以下机器能力，裸机实现在 `内核/机约。底层。豫`。每项首参均为带标签的“簿：长整数”，表示硬件层交入的原全局状态区。下表列其余参数与结果；“通道”在源码中沿用标签“帧”，为硬件层解释的不透明执行上下文，核心原样传递。整数、长整数、爻与有均为底层类型。

| 函数 | 其余参数 | 结果 | 裸机职责 |
| --- | --- | --- | --- |
| 机域址 | 槽：整数、字段：整数 | 长整数 | 选择原旧槽或动态槽字段地址 |
| 机仓格址、机槽区址、机槽块数址、机切入滴答址、机累计滴答址、机记账址 | 槽：整数 | 长整数 | 授予原状态区域地址 |
| 机区址 | 槽：整数、偏：整数 | 长整数 | 选择原槽区字段地址 |
| 机静态基、机滴答址 | 仅首参 | 长整数 | 授予静态区或时钟状态地址 |
| 机取基 | 通道：长整数 | 长整数 | 提取调用者线性内存基址 |
| 机旧槽数、机当前槽 | 仅首参 | 整数 | 提供上下文枚举边界与当前身份 |
| 机槽位占、机是动态槽 | 槽：整数 | 爻 | 查询槽映射存在与上下文类别 |
| 机下个任务槽 | 从：整数 | 整数 | 枚举已映射的在用上下文 |
| 机环后 | 槽：整数 | 整数 | 查询调度环后继 |
| 机环插、机环出、机槽位清、机组还 | 槽：整数 | 有 | 入环、出环及收执行上下文 |
| 机固块数 | 槽：整数 | 整数 | 计量固定物理块 |
| 机任务堆用量 | 槽：整数 | 长整数 | 查询目标地址域里的堆计量 |
| 机交回 | 通道：长整数、值：整数 | 有 | 将服务结果交回当前上下文 |
| 机交槽 | 槽：整数、值：整数 | 有 | 将服务结果交回指定上下文 |
| 机让行 | 通道：长整数 | 整数 | 保存、选择与恢复执行上下文 |
| 机催闲核 | 目：整数、醒：爻 | 有 | 根据唤醒结果通知空闲处理器 |
| 机唤闲核 | 仅首参 | 有 | 通知待命处理器 |
| 机是多核、机网卡有新帧、机有受托间歇 | 仅首参 | 爻 | 提供机器运行与输入就绪条件 |
| 机冲刷、机放资源 | 槽：整数 | 有 | 输出原行缓冲、回收原物理资源 |
| 机辍宿程 | 槽：整数、信：整数 | 有 | 打断（信二）或终止（信九）任务时，给它起的、还在运行的宿主程序发同样的信号；裸机为空 |
| 机任务终记 | 槽：整数、码：整数 | 有 | 输出原任务结束诊断 |
| 机陷阱记 | 槽：整数、码：整数、通道：长整数 | 有 | 输出原异常诊断 |
| 机拷任务名 | 槽：整数、址：长整数 | 有 | 映射原启动块名区并拷贝八十八字节 |

接线复用实约（接口静态接线）的内部协议。底层总装按导出名把实约机声明绑定到本程序唯一的同名导出函数，核对元数后生成普通直接调用；已有的生成分派入口沿用同一路径。裸机导出包装继续调用原内核函数，任务表与邮箱的状态读写由核心完成。宿主实现第二步沿用同一接口，负责上下文、地址授予、运行结果交付与通知。

## 与 GC 接口的关系

| | GC 接口（豫言操作系统接口） | 底层接口（本树） |
| --- | --- | --- |
| 值 | 豫言值类型：字符串、列、变体、资源…… | 整数与长整数（六十四位传递） |
| 编译模式 | 高级（有垃圾回收，`模块。接口。豫`），依赖标准库 | 底层（无垃圾回收，`模块。底层接口。豫`），依赖底层库 |
| 使用者 | 应用 | WASI shim、GC shim、共用核心 |
| 实现 | 宿主适配包（豫言写）与宿主库 | 平台后端实现包（豫言写），每平台一份 |
| 错误 | 变体结果与共用的系统错误 | 状态码（WASI errno 的子集） |
| 授权 | 授权表、目录权、显示面等 | 启动时的初始句柄表（预开目录） |

两棵树互不依赖。底层接口里没有的东西（HTTP、JSON、日期拆分、路径规范化、当前目录）由 shim 用豫言实现，不进后端。

## 文件与身份

- 每个能力组是独立的包 `豫言操作系统底层<能力>`，放在目录 `底层<能力>/` 里：`名称。包。豫`（依赖 `磐石` 与所需的本树其他包）、若干 `模块。底层接口。豫`、`规范.汉语.md` 与 `规范.文言.md`。
- 目录名等于包名去掉 `豫言操作系统` 前缀：现行检查器据此定位兄弟包，本树不需要另改定位规则。
- 接口文件的写法沿用 GC 接口的[接口文件规则](../豫寓榫卯/接口文件规则.汉语.md)，差异与本树的通用规则见[调用约定](调用约定.汉语.md)：签名里只有 `数`（返回值可以是 `有`），类型来自 `磐石` 的 `基础`，不写函数体。
- 接口文件是底层文件（`。底层接口。豫`），导入只找底层模块（编译器检查），所以本树的签名只用底层库的类型。
- 目录根的 `豫言操作系统底层接口。包。豫` 是本树的父包，说明文件就是本总纲：它用「包含包」按“首批能力组”表格的顺序登记全部底层接口包，各包用「包含在」指回本包（规则见[包系统](../应用/豫构/包系统.汉语.md)“层级包”一节）。父包不含模块，用于按层级发现。新增能力组时，在表格与父包「包含包」的相同位置登记，并在新包写「包含在」。
