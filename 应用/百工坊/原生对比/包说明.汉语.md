# 原生对比

比较原生工具链与 Node 工具链的构建耗时。原生工具链是仓库目标「原生工具链」生成的 `豫构。林檎。豫行` 与 `编译器。林檎。豫行`，Node 工具链是 `豫构.wasm` 与 `编译器.wasm`。原生的中位耗时慢于 Node 时，打印 GitHub 警告（`::warning`）；两边产物不同或构建失败时，打印错误（`::error`）并以 1 退出。CI 的「Wasm 包起步」作业在 Linux x64、Linux arm64 与 macOS 上跑完「全部」后运行它。

## 用法

先在仓库根目录运行「全部」，它会生成原生工具链。然后：

```sh
./豫构。林檎。豫行 构建 原生对比 --输出 原生对比.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs 原生对比.wasm                      # 探针 3 轮、完整构建 2 轮
node 豫言操作系统/宿主/节点/宿主.cjs 原生对比.wasm --探针轮数 5 --构建轮数 3 -j 24
node 豫言操作系统/宿主/节点/宿主.cjs 原生对比.wasm --场景 全部 --轮数 5 -j 24      # 提案 00007 议五的全部场景
```

`--场景 名` 可重复，名为 探针、构建、系统、增量、你好、测试、原生产物、交互，或 全部；不给时跑探针、构建与交互（CI 照此）。`--轮数` 是探针、构建之外各场景的轮数，默认 3。

## 测量的内容

- 冷编打印探针：`豫构 文件 应用/百工坊/原生对比/打印探针。脚本。豫`。探针只用标准库打印一行；工作任务不读缓存（`-- --do-not-load-cache`），标准库的各模块都要现编。
- 完整构建豫言编译器：`豫构 构建 豫言编译器`，工作任务同样不读缓存。
- 冷编豫言系统（系统）：`豫构 文件 豫言操作系统/裸机/豫言系统。豫`，工作任务不读缓存。
- 改一个文件后重建豫言系统（增量）：先各跑一遍填好缓存；每轮在 `豫言操作系统/裸机/库/冶铸/兼降级本术。豫` 末尾追加一行各不相同的注释，重建豫言系统，再还原。
- 小程序构建并运行（你好）：构建打印探针并运行，输出须含“你好，豫言”。Node 一边出 `.wasm`、经 Node 运行；原生一边按默认原生的做法直出原生可执行文件（编译器 `--目标 本机 --执行器 执行器。树码`，降级缓存放 `.豫构缓存/降级缓存/原生对比.机器片`），直接运行。先各跑一遍填好缓存。
- 测试子集构建并运行（测试）：标准库里不涉网络与进程的六个测试（字符串术、可选值、字节串、多态列、路径对拍、字节缓冲），逐个按上一条的做法构建并运行，退出码须为零。
- 完整构建豫言编译器出原生产物（原生产物）：同完整构建，原生一边直出原生编译器，并运行它的 `--version` 核对。
- 交互会话逐句对照（交互，网页行在提案 00043 的双端对照）：同一组句子（定义后再用、裸式印值、小数、组合句、编译错误、没接住的运行时异常）作开头句，分别交给原生 `豫构 交互 --直读` 与 Node 上的 `豫构.wasm 交互 --直读`（都设 豫言行在=关）。两边的输出抹去交互会话目录的随机号后写成 `原生对比-交互-<链>.txt`，每轮核对逐字相同；网页行在跑的就是 Node 这一边的同一份网页汇编程序，两边不同即报错。

每种场景跑若干轮。奇数轮先跑 Node、后跑原生，偶数轮反之。两边都出 `.wasm` 的场景（探针、构建、系统、增量），每轮都用「藏书」的「同卷」核对两边产物逐字节相同。最后打印 Markdown 表，列出两边的中位数、原生与 Node 之比和各轮秒数；设了环境变量 `GITHUB_STEP_SUMMARY` 时，表同时写进该文件，成为作业摘要。产物写在仓库根目录的 `原生对比-*.wasm`，以 `yy` 开头，Git 会忽略。

墙钟受机器上别的负载影响。CI 的运行器之间差别也大，所以只打印警告，不让作业失败。
