# 源码格式化

## 格式检查

以 `豫构 构建 源码格式化 检查 --输出 格式检查。林檎。豫行 -j 24` 造只读核验之器。
借编译器析词，寻名（`「…」`，数之字面亦在焉）中之英文字母、阿拉伯数字与下划线，复以既有排版器百六十列之果比原文。串与注中之英文字母、阿拉伯数字、下划线皆可用。诸篇保持原貌。

- `./格式检查。林檎。豫行`：核 Git 所录 `.豫` 与 `。豫` 诸篇，略 `*_v0` 之目、`yuyan-vscode` 与会话之文（`。会话。豫`，提案〇〇〇三六；排版亦仍其旧）。名或篇径含英文字母、阿拉伯数字或下划线之篇，逐篇书 GitHub Actions 之误，核毕以一退。排版之失惟告警。所录之篇以 `git ls-files` 列之；无 git 时（如豫言操作系统中）由库「稽古」径读 Git 之索引，列已录与未见略之新篇。
- `./格式检查。林檎。豫行 --只查标识符`：惟校名与径、不核排版，有犯则以一退；约十秒，云仓 CI 于云仓之根行之。
- `./格式检查。林檎。豫行 --只查排版 篇径……`：惟核所授诸篇之排版，有失惟告警，退出之态恒零；可分篇为批，数程并行核之。
- `./格式检查。林檎。豫行 --标识符 径之前缀……`：逐处列径以此诸前缀起之篇之犯，每行“篇径：名”，末行总数；无前缀则列尽。
- `./格式检查。林檎。豫行 --标签 【基准之提交】`：检相对基准之提交（默认 `yybs`；先取其与 `HEAD` 之合并基，不得则用基准）所改之声明，合 AGENTS.md 标签参数之条否，其检有二：
  - 标签参数：顶层签名之参依所书字面之类相较，字面同类之参须系标签；函数恰二参者不检；类之后、`又`或`为` 之前有注之参不检。
  - 命名元组：签名、类之别名（`即`）、类与构造器（`立`）所书之元组类，相邻二项字面同类者，宜改用命名元组 `「组类」【「名」乃 类 也，…】`；以 `合` 相连之链与未命名之 `「组类」【…】` 皆检，括中所套之元组亦检；元组恰二项者不检（与函数恰二参同例）；项类之后有注者为合。

  声明自名接 `乃`、`即`、`立` 之行始（可缩进），至去注而以 `也。` 终之行止。所较者工作树，未录之改与 Git 未录之新篇皆在焉。不合者逐一书附行号之 GitHub Actions 之警，末行总数；退出之态恒零。函体中类之实参与标注、局部之签名，留待后续之版检之。
- `./格式检查。林檎。豫行 --文件名`：列 Git 所录之篇与目录、名除半角点外皆汉字者（依 AGENTS.md 其缀当以全角句号「。」隔之），每行一径，有则别书一 GitHub Actions 之警；略 `*_v0` 之目及 `yuyan-vscode`；退出之态恒零。
- `./格式检查。林檎。豫行 篇径……`：核所指诸篇，名与排版之失皆惟告警。

提案 00013（标识符规范化）既清仓中旧犯，自此有犯皆败。析文败之篇告警，惟核其径。
CI 之 `formatting check` 作业先行 `--标签`（标签参数与命名元组；基准取上一推之提交，拉取请求取所归分支之提交），次行 `--文件名`，皆惟告警，作业不以之败；复取无参之核所检之篇，按处理器之数并行 `--只查排版`（一程一篇），惟告警；终行 `--只查标识符`，有犯则作业败。造器败亦报败。

解析并格式化豫言源文件。

## 籍与用

所有者曰豫言，版本暂定 0.1.0。此包之版本，非编译器命令所报之版本。

此包不供他包所依，包内诸书仍可相引。程序名曰 `源码格式化`，入口依包籍所载。

在仓库之根行 `./豫构。林檎。豫行 检查 源码格式化` 以验其籍。行 `./豫构。林檎。豫行 构建 源码格式化` 以成其器，不自行之。

所依与组成皆见[包籍](源码格式化。包。豫)。变接口则修说明，变身份与组成则修包籍。说明不作模块。
