# 源码格式化

## 格式检查

核状态之格，收文件系统之区（三千九百二十至四千零七十一，百五十二字）及其三十八域，各广四字；复收显示代办之描述（三千七百六十至三千七百七十五，十六字）、子画之标与等候之计。诸域之址皆出执行器布局，格与所属之区并核焉。

以 `豫构 构建 源码格式化 检查 --输出 格式检查。林檎。豫行 -j 24` 造只读核验之器。
借编译器析词，寻名（`「…」`，数之字面亦在焉）中之英文字母、阿拉伯数字与下划线，复以既有排版器百六十列之果比原文。串与注中之英文字母、阿拉伯数字、下划线皆可用。诸篇保持原貌。

- `./格式检查。林檎。豫行`：核 Git 所录与未录而未略之 `.豫` 与 `。豫` 诸篇，略 `*_v0` 之目、`yuyan-vscode` 与会话之文（`。会话。豫`，提案〇〇〇三六；排版亦仍其旧）。名或篇径含英文字母、阿拉伯数字或下划线之篇，逐篇书 GitHub Actions 之误，核毕以一退。排版之失惟告警。所核之篇以 `git ls-files --cached --others --exclude-standard` 列之；无 git 时（如豫言操作系统中）由库「稽古」径读 Git 之索引，亦列已录与未见略之新篇。
- `./格式检查。林檎。豫行 --只查标识符`：惟校名与径、不核排版（未录而未略之新篇亦在），有犯则以一退；约十秒，云仓 CI 于云仓之根行之。
- `./格式检查。林檎。豫行 --只查排版 篇径……`：惟核所授诸篇之排版，有失惟告警，退出之态恒零；可分篇为批，数程并行核之。
- `./格式检查。林檎。豫行 --标识符 径……`：逐处列此诸径下之篇（未录而未略之新篇亦在）之犯，每行“篇径：名”，末行总数；无径则列尽。径在仓中则取 Git 所列（目或篇之实径；止书一半之径亦以前缀合之）；径在仓外（全径，或豫构 `--外部包目录` 之私仓目）则递归列其下 `.豫` 与 `。豫` 之篇；径不在仓中而又不存，则书一误而以二退，不复默报零处。
- `./格式检查。林檎。豫行 --标签 【基准之提交】 【径……】`：检相对基准之提交（默认 `yybs`；先取其与 `HEAD` 之合并基，不得则用基准）所改之声明中元组之名：
  - 命名元组：签名、类之别名（`即`）、类与构造器（`立`）所书之元组类，相邻二项字面同类者，宜改用命名元组 `「组类」【「名」乃 类 也，…】`；以 `合` 相连之链与未命名之 `「组类」【…】` 皆检，括中所套之元组亦检；元组恰二项者不检（与函数恰二参同例）；项类之后有注者为合。

  签名同类之参缺签，自提案〇〇〇六五起由编译之器（`库/译场/分职/证义/参签察。豫` 之「察签缺签」）断之，格式之检不复核。声明自名接 `乃`、`即`、`立` 之行始（可缩进），至去注而以 `也。` 终之行止。所较者工作树，未录之改与 Git 未录而未略之新篇皆在焉。不合者逐一书附行号之 GitHub Actions 之警，末行总数；退出之态恒零。函体中类之实参与标注、局部之签名，留待后续之版检之。基准之后可复接径：径在仓中则惟查相对基准之改中属于此诸篇之声明；径在仓外则无基准可较，全篇为新。不得所改而授仓外之径者，仓外之径仍照全篇查。
- `./格式检查。林檎。豫行 --文件名 【径……】`：列 Git 所录与未录而未略之篇与目录、名除半角点外皆汉字者（依 AGENTS.md 其缀当以全角句号「。」隔之），每行一径，有则别书一 GitHub Actions 之警；略 `*_v0` 之目及 `yuyan-vscode`；退出之态恒零。授径者惟查其径下之篇（仓外之目递归列其下之全篇）。
- `./格式检查。林檎。豫行 --兜底`：核执行器（豫言操作系统/裸机/客体二号）中诸定义之兜底（失败果四四、五八）处数与执行器供籍之兜底之记合否（提案〇〇〇四〇）：未登、数不合、登而已无、品不识者逐条列之，别书一 GitHub Actions 之警；合则印定义之数与兜底之总处数；退出之态恒零。无参亦检；无供籍之源（如云仓）则不检。
- `./格式检查。林檎。豫行 --状态格 【布局篇之径】`：核执行器布局之单格与占用之段（议五九五、六六三、一四四〇）。收「状态」「浮槽」「浮格」「析格」「大数」「浮串」诸族，及所登之区与大格。布局书常数以定宽，如 `「状态中转区占宽」者「五六」也。`，谓中转据五十六字。核者先取「占宽」之书；单格次取定表、注文、原语、邻址，余依八字而列之。独占之段与单格同核，相交则报，全含亦报；状基、暂存基、字面串基、软浮点暂存、状态盘区五容区可全纳所登子项。误则列二者之名、址、宽，以一退。复察客体二号诸 `。底层。豫` 篇，布局之外别定格、槽、段者报之。授径可验反例，外定之格仍察实源。惟读其篇。
- `./格式检查。林檎。豫行 --验收`：核 `验收/` 目下之程（Git 所列 `.豫` 与 `。豫` 之篇）曾导宿主专用之库借道否（议一二零五）。借道惟诺驿与林檎有之，林纳、轩窗取不得动态之库；验收之程，等待、时钟、临时之文当取于豫章（等待用「差遣」之限时让），诸宿主皆可行。有犯则逐篇书 GitHub Actions 之误（附篇径），末行总之，以一而退；皆合则书一行。导按雅言记号之列，认文为借道之名记者，串与注中之字不计。无参之核亦为此。
- `./格式检查。林檎。豫行 --弃果 【--基准 提交】 【径……】`：列以「令」弃其果之处（议一一八八）。「令」系所还于名而续行，弃其还则误码与果俱隐；提案〇〇〇六二惟禁「而后」前弃值，此窦不能塞，故别立此检，CI 以为硬检（用户二〇二六年十月二十八日定）。认果有二：一曰所还之类书成否（提案〇〇〇五七）或在弃果登记表（本包弃果登记之数据）所列之类名者；二曰在登记函数表以模块与函名所登者（底层误码多为整数之常，其签惟书整数，视类不能辨）。诸函之签，本检自扫其源而得，不假编译之器。登记之函惟于此篇本身、或曾导其所居之模块者算；呼作「模块」之「函」者，依所书之模块核之。如是则他处同名之函（如豫章与客体二号皆有表删、迁）不致误报。所列者，「令」之值即此呼（或此呼为若、否则一支之值；取所还而较、而算、而传者不计），而其名为无，或此定义之后（至次顶格之行）不复用其名者也；一律列之，不设注免，改之惟二途：以「鉴」分成败，或上传之。每处书一行 GitHub Actions 之警，附篇、行、列（列自一）、函名与所书之还类，末行总数；有弃果之处则别书一误而以一退。不授参则查诸待查之篇；授径则惟查其径下之篇（仓外之目递归列其下之篇），签名仍按全仓扫之。先书 `--基准` 而继以提交之名，则惟查相对其提交之改：取其与 `HEAD` 之合并基（不得则用基准），较工作树（未录之改与未录之新篇亦在），惟列行号在所改之段者；其后可复接径。登记表之认类与函名依仓中现状增删。
- `./格式检查。林檎。豫行 --试印 【径……】`：列 `库/` 下非试之源所留临时打点「试印」者（议一四五三）。库中之文常行之时不当书于常出、误出；排查之际用豫章 `试印` 插一行以观其值，事毕即撤，留于库中则此步拒之。名后接 `乃`、`者`、`即` 之定义处不计，串、注与名前缀（若 `「试印数」`）之字不计；试例（径含 `测试/`、`验收/`，或篇名以 `。测试。豫` 终）不在所检。每处书一附篇与行列之说之 GitHub Actions 误注，末行总数而以一退；无则书一行。不授径则查全树，授径则惟查其下之篇。
- `./格式检查。林檎。豫行 篇径……`：核所指诸篇，名与排版之失皆惟告警。

仓外之径依文件系统递归列篇，略点首之目与 `.豫构缓存`。其目本为别一 Git 仓者，亦依文件系统列之，不读彼仓之 `.gitignore`：此途最简，亦不系于彼仓 Git 之态，所费者，见略之源亦并检之。仓外之篇，径之规惟视所授径下之相对径，宿主之目名（如 `/tmp`、私仓英文之目名）不与焉。

提案 00013（标识符规范化）既清仓中旧犯，自此有犯皆败。析文败之篇告警，惟核其径。
CI 之 `formatting check` 作业先行 `--标签`（命名元组；基准取上一推之提交，拉取请求取所归分支之提交），次行 `--文件名` 与 `--兜底`，皆惟告警，作业不以之败；复行 `--状态格`，状态格或区段相犯、或有篇在布局之外别定格者则作业败；复行 `--验收`，验收之程导借道则作业败；复行 `--弃果`，有以「令」弃成否或误码之处则作业败；复行 `--试印`，`库/` 下非试之源留临时打点「试印」者则作业败；复取无参之核所检之篇，按处理器之数并行 `--只查排版`（一程一篇），惟告警；终行 `--只查标识符`，有犯则作业败。造器败亦报败。

## 籍与用

所有者曰豫言，版本暂定 0.1.0。此包之版本，非编译器命令所报之版本。

此包不供他包所依，包内诸书仍可相引。程序名曰 `源码格式化`，入口依包籍所载。

在仓库之根行 `./豫构。林檎。豫行 检查 源码格式化` 以验其籍。行 `./豫构。林檎。豫行 构建 源码格式化` 以成其器，不自行之。

器逐篇析而排之，印已复析，较前后记号之列（注较规范之形）：记有增损或文有改易，则书其卷与首异之处，非零而退，诸篇皆仍其旧。皆协而后逐篇就地写回。

## 改得

提案〇〇〇六九迁移之二段所用：依译器 `--列模式裸名` 之清单，改作系之裸名为 `得「名」`。其用为 `格式化 --改得 清单之篇`。

三步之例（在仓之根；`<包>` 易为包名，`清单` 易为所写之篇名）：

```sh
# 一、列清单：逐处书“卷:行:列：所在之名：作绑定的裸名「名」”
./豫构。林檎。豫行 类型检查 <包> -- --列模式裸名 --do-not-load-cache > 清单

# 二、依清单改之：合者加「得」，所改之卷随即依百六十列排而写回
./源码格式化。林檎。豫行 --改得 清单

# 三、复核：再列一过，本包当为零
./豫构。林檎。豫行 类型检查 <包> -- --列模式裸名 --do-not-load-cache
```

器逐处按其卷之行、列核之：其处果为名记 `「名」`，则于其前加 `得`；不合者不改，逐处书 `未改：卷:行:列：由`（行列出界、其处非此名，或非名记，如落于串、注之中）。同卷诸处并核，插入自后而前，一位惟改一次；所改之卷随即依百六十列排而写回。末行书 `改得：改了 N 处，未改 M 处，涉及 K 个文件。`，K 为写回之卷数；有未改者则退以一。

行列之揆与译器同：行、列皆自一起数；列以通字（一码点）计，一汉字、一全角之标各为一列，非字节之数。

清单中惟含“作绑定的裸名「”之行为条，豫构之程与依赖包他诊之文皆略。`--列模式裸名` 亦及所依之包，故清单中带依赖包之裸名；按包分片而迁者，先取清单中属本包之行而后授此模式，复核时亦惟视本包之行。

树中每注与其锚词并记隔数，谓此注离锚词隔几记也（议题七三八）。印者书锚词已，复书足其隔数之记乃书此注，故式中行中之后注留其故处，重排前后记次相符。
