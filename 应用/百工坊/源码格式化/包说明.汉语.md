# 源码格式化

解析并格式化豫言源文件。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为可执行文件类型，不可被其他包依赖；包内模块仍可互相引用。类型典中的入口和文件名见包配置，程序产物为 `源码格式化`。

## 使用

在仓库根目录运行：

```sh
./豫构。林檎。豫行 检查 源码格式化
./豫构。林檎。豫行 构建 源码格式化
```

依赖及说明路径以 [包配置](源码格式化。包。豫) 为准。构建不会自动运行程序；有发布或服务副作用的工具应先阅读其入口源码。

程序逐篇解析并排版，重排后重新解析，再比较排版前后的记号列（注释按规范形比较）：记号有增减或内容改动即报出文件与第一处不同，以非零状态退出，全部文件保持原样。全部核对通过后才逐个原地写回。

语法树里每条注释与它的锚词一起记着隔数，即这条注释离锚词隔着几个记号（议题 #738）。打印器写完锚词之后，再写够隔数那样多的记号才写出这条注释，于是表达式中间的行中后置注释留在原处，重排前后的记号次序一致。

## 格式检查

使用 `豫构 构建 源码格式化 检查 --输出 格式检查。林檎。豫行 -j 24` 构建只读检查工具。
工具通过编译器词法解析找出标识符（`「…」` 名称，含数字字面量）中的英文字母、阿拉伯数字与下划线，并与现有格式化器的一百六十列结果比较。字符串和注释中的英文字母、阿拉伯数字、下划线可以正常使用。检查保持源文件原样。

- `./格式检查。林檎。豫行`：检查仓库中已跟踪与未跟踪、未被忽略的 `.豫` 与 `。豫` 文件，跳过 `*_v0` 目录、`yuyan-vscode` 与会话文件（`。会话。豫`，提案 00036；格式化也原样不动）。标识符或文件路径含英文字母、阿拉伯数字或下划线的文件，逐个输出 GitHub Actions 错误，全部检查完后以状态一退出。排版问题只发警告。文件用 `git ls-files --cached --others --exclude-standard` 列出；没有 git 时（如豫言操作系统里）由库「稽古」直接读 Git 索引，同样列出已跟踪与未被忽略的新文件。
- `./格式检查。林檎。豫行 --只查标识符`：只核对标识符与路径、不查排版（含未跟踪、未被忽略的新文件），有违规时以状态一退出；约十秒，云仓 CI 在云仓根运行它。
- `./格式检查。林檎。豫行 --只查排版 文件路径……`：只查所给文件的排版，问题只发警告，退出状态总为零；可以把文件分批、几个进程并行检查。
- `./格式检查。林檎。豫行 --标识符 路径……`：逐处列出这些路径下的文件（含未跟踪、未被忽略的新文件）里的违规，每行“文件路径：名称”，末行是总数；不写路径时列出全部。路径在仓库里时取 Git 所列（目录或文件的实际路径；只写到一半的路径也按前缀匹配）；路径在仓库外时（绝对路径，或豫构 `--外部包目录` 那样的私有项目仓目录）递归列出其下 `.豫` 与 `。豫` 文件来查；路径既不在仓库里又不存在时报一条错误并以状态二退出，不再静默报 0 处。
- `./格式检查。林檎。豫行 --标签 【基准提交】 【路径……】`：检查相对基准提交（默认 `yybs`；先取它与 `HEAD` 的合并基，取不到时用基准本身）改动过的声明里的元组命名：
  - 命名元组：签名、类型别名（`即`）、类型与构造器（`立`）里写出的元组类型，相邻两项字面类型相同时应改用命名元组 `「组类」【「名」乃 类型 也，…】`；`合` 连成的链与不命名的 `「组类」【…】` 都查，括号里套着的元组也查；元组恰好两项时不查（与函数恰好两个参数同例）；项的类型之后写了注释的项算合规。

  签名里同类型参数缺标签一条自提案 00065 起由编译器（`库/译场/分职/证义/参签察。豫` 的「察签缺签」）判定，格式检查不再核对。声明从名称接 `乃`、`即`、`立` 的一行起（可以缩进），到去掉注释后以 `也。` 结尾的一行止。对比的是工作树，未提交的改动与未跟踪、未被忽略的新文件都算在内。不合规之处逐条输出带行号的 GitHub Actions 警告，末行是总数；退出状态总为零。函数体里的类型实参与标注、局部签名留待后续版本检查。基准之后还可以接路径：路径在仓库里时只查相对基准的改动里属于这些文件的声明；路径在仓库外时没有基准可比，整篇算新增。取不到改动而给了仓外路径时，仓外路径仍照整篇查。
- `./格式检查。林檎。豫行 --文件名 【路径……】`：列出已跟踪与未跟踪、未被忽略的文件与目录里名字除半角点外全是汉字的（按 AGENTS.md 后缀应以全角句号「。」分隔），每行一个路径，有则另发一条 GitHub Actions 警告；跳过 `*_v0` 目录和 `yuyan-vscode`；退出状态总为零。给了路径时只查这些路径下的文件（仓外目录递归列其下的全部文件）。
- `./格式检查。林檎。豫行 --兜底`：核对执行器（豫言操作系统/裸机/客体二号）里各定义的兜底（失败果四四、五八）处数与执行器供籍模块里的兜底登记是否一致（提案 00040）：没登记、处数不符、登记了而源码里已没有、品不认得的逐条列出，另发一条 GitHub Actions 警告；相符时印定义数与兜底总处数；退出状态总为零。无参数时也查；没有供籍源文件（如云仓）时不查。
- `./格式检查。林檎。豫行 --状态格 【布局文件路径】`：核对执行器状态格布局（`豫言操作系统/裸机/客体二号/布局。底层。豫`）里各状态格、暂存槽与区段的偏移有没有重叠（议题 595、663）。收全部登记名：名字以「状态」「浮槽」「浮格」「析格」「大数」「浮串」开头的格，以及「状基」「暂存基」「块设备暂存基」「字面串基」「软浮点暂存」「缺省选项区」等区段与固定大格。宽度先取内置定表（如状态自由表 264、状态林时 16、状态远程描述 20、状态例外载荷 512、状态熵池 176、软浮点暂存 1920），再按客体二号源码里读写该格的原语判：读四、写四 四字节；读址、写址、读长数、写长数、读八、写八、宽低、宽高 八字节；读二、写二 二字节；读一、写一 一字节。布局注释里写明的段也认（「甲–乙」「甲 至 乙」「甲 起 丙 字节」，十六进制也认）。仍判不出的，下一格恰在四字节之后时按四字节（布局的密排惯例），其余按八字节算并逐格列出。格与格、区与区、格与区部分重叠就逐对印出两者的名称、偏移与宽度，另发一条 GitHub Actions 错误，以状态一退出；单格整格落在区段里、区段整段含在另一段里时视为相容（块设备暂存在暂存区里、缺省选项在状态格区里），部分相交才报错。再核对客体二号全部 `.底层。豫` 源文件，有在布局之外另定格、槽、区段的一样报错。只读，不改布局；给了路径时核对那个文件（用来验故意重叠的样例），模块外定义仍按客体二号的实际源码查。
- `./格式检查。林檎。豫行 --验收`：核对 `验收/` 目录下的程序（Git 所列的 `.豫` 与 `。豫` 文件）有没有导入宿主专用库「借道」（议题 1205）。借道只在诺驿与林檎上有，林纳、轩窗上取不到动态库；验收程序的等待、时钟、临时文件这类测试脚手架应从豫章取（等待用豫章「差遣」的限时让出），各宿主都能跑。有违反就逐篇输出 GitHub Actions 错误（带文件路径），末行汇总，以状态一退出；都符合时印一行说明。导入按雅言记号列认内容为「借道」的名称记号，字符串与注释里的字不算。无参数检查也做这一项。
- `./格式检查。林檎。豫行 --弃果 【--基准 提交】 【路径……】`：列出用「令」丢掉结果的地方（议题 1188）。「令」把调用的返回值系在名字上接着往下做，忽略返回值时出错码与结果值就悄悄丢了；提案 00062 只挡「而后」前面丢值，挡不住这个逃生口，故另设这一检查供合入前审查。认「结果」有两途：返回类型里写着「成否」（提案 00057）或弃果登记表（本包 [弃果登记。数据。豫](弃果登记。数据。豫)）所列类型名的函数；登记表函数表里按模块与函数名登记的函数（底层出错码多是整数常量、签名只写「整数」，光看返回类型认不出）。函数签名由检查自己扫源码得来，不调编译器。登记表里的函数只在这个文件本身、或导入了它所在那个模块的篇里算；调用写作 `「模块」之「函数」` 时按写出的模块核对。这样别处的同名函数（如豫章与客体二号都有「表删」「迁」）不会误报。列出的地方是「令」的值就是这个调用（或者这个调用是「若」「否则」某一支的值；拿返回值去比较、再算、再当实参传的不算）、而名字是「无」或在这个定义后面（到下一个顶格行止）再没有用到的；一律列出，不设注释豁免，改法只有用「鉴」分开成败或者往上传两种。每处印一行带文件、行、列（列从一起）的 GitHub Actions 警告，末行是总数；退出状态总为零。不给路径时查全部待查文件；给了路径只查这些路径下的文件（仓外目录递归列其下的文件），签名仍按全仓扫。先写 `--基准` 再接提交名时只查相对那个提交的改动：取基准与 `HEAD` 的合并基（取不到时用基准本身），对照工作树（含未提交的改动与未跟踪的新文件），只列行号落在该篇改动段里的；其后还可接路径。登记表里的认类与函数名按仓里现状增删。
- `./格式检查。林檎。豫行 文件路径……`：检查指定文件，标识符与排版问题都只发警告。

仓外路径按文件系统递归列文件，跳过点开头的目录与 `.豫构缓存`。目录本身是另一个 Git 仓时同样照文件系统列，不读那个仓的 `.gitignore`：这条路最简单，也不依赖那个仓的 Git 状态，代价是被忽略的源文件也会一并检查。仓外文件的路径规则只看所给路径之下的相对路径，宿主目录名（如 `/tmp`、私有仓的英文目录名）不参与。

提案 00013（标识符规范化）已把仓库里的存量违规清理完毕，此后任何违规都会让检查失败。源码解析失败的文件发警告，只查路径。
CI 的 `formatting check` 作业依次运行 `--标签`（命名元组；基准取上一次推送的提交，拉取请求取目标分支的提交）、`--文件名` 与 `--兜底`，三者都只发警告，作业不因此失败；随后运行 `--状态格`，有状态格或区段重叠、或有模块在布局之外另定格时作业失败；再运行 `--验收`，验收程序导入了借道时作业失败；再取与无参检查相同的文件，按处理器数并行运行 `--只查排版`（每个进程查一个文件），只发警告；最后运行 `--只查标识符`，有违规时作业失败。工具构建失败同样由作业报告失败。`--弃果` 暂未接入 CI，供合入前人工过目。
