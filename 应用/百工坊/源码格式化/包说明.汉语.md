# 源码格式化

解析并格式化豫言源文件。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为可执行文件类型，不可被其他包依赖；包内模块仍可互相引用。类型典中的入口和文件名见包配置，程序产物为 `yy源码格式化`。

## 使用

在仓库根目录运行：

```sh
./yy豫构.exe 检查 源码格式化
./yy豫构.exe 构建 源码格式化
```

依赖及说明路径以 [包配置](源码格式化。包。豫) 为准。构建不会自动运行程序；有发布或服务副作用的工具应先阅读其入口源码。

## 格式检查

使用 `豫构 构建 源码格式化 检查 --输出 yy格式检查.exe -j 24` 构建只读检查工具。
工具通过编译器词法解析找出标识符（`「…」` 名称，含数字字面量）中的英文字母、阿拉伯数字与下划线，并与现有格式化器的一百六十列结果比较。字符串和注释中的英文字母、阿拉伯数字、下划线可以正常使用。检查保持源文件原样。

- `./yy格式检查.exe`：检查仓库中 Git 受控的 `.豫` 与 `。豫` 文件，跳过 `*_v0` 目录和 `yuyan-vscode`。标识符或文件路径含英文字母、阿拉伯数字或下划线的文件，逐个输出 GitHub Actions 错误，全部检查完后以状态一退出。排版问题只发警告。受控文件用 `git ls-files` 列出；没有 git 时（如豫言操作系统里）由库「版本库」直接读 Git 索引，列出已跟踪与未被忽略的新文件。
- `./yy格式检查.exe --只查标识符`：只核对标识符与路径、不查排版，有违规时以状态一退出；约十秒，云仓 CI 在云仓根运行它。
- `./yy格式检查.exe --只查排版 文件路径……`：只查所给文件的排版，问题只发警告，退出状态总为零；可以把文件分批、几个进程并行检查。
- `./yy格式检查.exe --标识符 路径前缀……`：逐处列出路径以这些前缀开头的文件里的违规，每行“文件路径：名称”，末行是总数；不写前缀时列出全部。
- `./yy格式检查.exe --标签 【基准提交】`：检查相对基准提交（默认 `yybs`；先取它与 `HEAD` 的合并基，取不到时用基准本身）改动过的顶层签名是否按 AGENTS.md 带标签参数：参数按签名里写出的字面类型比较，字面类型相同的参数须带标签；函数恰好两个参数时不查；类型之后、`而` 之前写了注释的参数不查。对比的是工作树，未提交的改动与未受 Git 控制的新文件都算在内。不合规的签名逐个输出带行号的 GitHub Actions 警告，末行是总数；退出状态总为零。
- `./yy格式检查.exe --文件名`：列出 Git 受控的文件与目录里名字除半角点外全是汉字的（按 AGENTS.md 后缀应以全角句号「。」分隔），每行一个路径，有则另发一条 GitHub Actions 警告；跳过 `*_v0` 目录和 `yuyan-vscode`；退出状态总为零。
- `./yy格式检查.exe 文件路径……`：检查指定文件，标识符与排版问题都只发警告。

提案 00013（标识符规范化）已把仓库里的存量违规清理完毕，此后任何违规都会让检查失败。源码解析失败的文件发警告，只查路径。
CI 的 `formatting check` 作业依次运行 `--标签`（基准取上一次推送的提交，拉取请求取目标分支的提交）与 `--文件名`，两者都只发警告，作业不因此失败；再取与无参检查相同的文件，按处理器数并行运行 `--只查排版`（每个进程查一个文件），只发警告；最后运行 `--只查标识符`，有违规时作业失败。工具构建失败同样由作业报告失败。
