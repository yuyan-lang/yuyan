# 源码格式化

解析并格式化豫言源文件。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为可执行文件类型，不可被其他包依赖；包内模块仍可互相引用。类型典中的入口和文件名见包配置，程序产物为 `源码格式化`。

## 使用

在仓库根目录运行：

```sh
./豫构。林檎。豫行 检查 源码格式化
./豫构。林檎。豫行 构建 源码格式化
```

依赖及说明路径以 [包配置](源码格式化。包。豫) 为准。构建不会自动运行程序；有发布或服务副作用的工具应先阅读其入口源码。

## 格式检查

使用 `豫构 构建 源码格式化 检查 --输出 格式检查。林檎。豫行 -j 24` 构建只读检查工具。
工具通过编译器词法解析找出标识符（`「…」` 名称，含数字字面量）中的英文字母、阿拉伯数字与下划线，并与现有格式化器的一百六十列结果比较。字符串和注释中的英文字母、阿拉伯数字、下划线可以正常使用。检查保持源文件原样。

- `./格式检查。林檎。豫行`：检查仓库中已跟踪与未跟踪、未被忽略的 `.豫` 与 `。豫` 文件，跳过 `*_v0` 目录、`yuyan-vscode` 与会话文件（`。会话。豫`，提案 00036；格式化也原样不动）。标识符或文件路径含英文字母、阿拉伯数字或下划线的文件，逐个输出 GitHub Actions 错误，全部检查完后以状态一退出。排版问题只发警告。文件用 `git ls-files --cached --others --exclude-standard` 列出；没有 git 时（如豫言操作系统里）由库「稽古」直接读 Git 索引，同样列出已跟踪与未被忽略的新文件。
- `./格式检查。林檎。豫行 --只查标识符`：只核对标识符与路径、不查排版（含未跟踪、未被忽略的新文件），有违规时以状态一退出；约十秒，云仓 CI 在云仓根运行它。
- `./格式检查。林檎。豫行 --只查排版 文件路径……`：只查所给文件的排版，问题只发警告，退出状态总为零；可以把文件分批、几个进程并行检查。
- `./格式检查。林檎。豫行 --标识符 路径……`：逐处列出这些路径下的文件（含未跟踪、未被忽略的新文件）里的违规，每行“文件路径：名称”，末行是总数；不写路径时列出全部。路径在仓库里时取 Git 所列（目录或文件的实际路径；只写到一半的路径也按前缀匹配）；路径在仓库外时（绝对路径，或豫构 `--外部包目录` 那样的私有项目仓目录）递归列出其下 `.豫` 与 `。豫` 文件来查；路径既不在仓库里又不存在时报一条错误并以状态二退出，不再静默报 0 处。
- `./格式检查。林檎。豫行 --标签 【基准提交】 【路径……】`：检查相对基准提交（默认 `yybs`；先取它与 `HEAD` 的合并基，取不到时用基准本身）改动过的声明是否合乎 AGENTS.md 的标签参数一条，两项都查：
  - 标签参数：顶层签名的参数按签名里写出的字面类型比较，字面类型相同的参数须带标签；函数恰好两个参数时不查；类型之后、`又`或`为` 之前写了注释的参数不查。
  - 命名元组：签名、类型别名（`即`）、类型与构造器（`立`）里写出的元组类型，相邻两项字面类型相同时应改用命名元组 `「组类」【「名」乃 类型 也，…】`；`合` 连成的链与不命名的 `「组类」【…】` 都查，括号里套着的元组也查；元组恰好两项时不查（与函数恰好两个参数同例）；项的类型之后写了注释的项算合规。

  声明从名称接 `乃`、`即`、`立` 的一行起（可以缩进），到去掉注释后以 `也。` 结尾的一行止。对比的是工作树，未提交的改动与未跟踪、未被忽略的新文件都算在内。不合规之处逐条输出带行号的 GitHub Actions 警告，末行是总数；退出状态总为零。函数体里的类型实参与标注、局部签名留待后续版本检查。基准之后还可以接路径：路径在仓库里时只查相对基准的改动里属于这些文件的声明；路径在仓库外时没有基准可比，整篇算新增。取不到改动而给了仓外路径时，仓外路径仍照整篇查。
- `./格式检查。林檎。豫行 --文件名 【路径……】`：列出已跟踪与未跟踪、未被忽略的文件与目录里名字除半角点外全是汉字的（按 AGENTS.md 后缀应以全角句号「。」分隔），每行一个路径，有则另发一条 GitHub Actions 警告；跳过 `*_v0` 目录和 `yuyan-vscode`；退出状态总为零。给了路径时只查这些路径下的文件（仓外目录递归列其下的全部文件）。
- `./格式检查。林檎。豫行 --兜底`：核对执行器（豫言操作系统/裸机/客体二号）里各定义的兜底（失败果四四、五八）处数与执行器供籍模块里的兜底登记是否一致（提案 00040）：没登记、处数不符、登记了而源码里已没有、品不认得的逐条列出，另发一条 GitHub Actions 警告；相符时印定义数与兜底总处数；退出状态总为零。无参数时也查；没有供籍源文件（如云仓）时不查。
- `./格式检查。林檎。豫行 --状态格 【布局文件路径】`：核对执行器状态格布局（`豫言操作系统/裸机/客体二号/布局。底层。豫`）里各状态格的偏移有没有重叠（议题 595）。宽度按客体二号源码里读写该格的原语判：读四、写四 四字节；读址、写址、读长数、写长数、读八、写八、宽低、宽高 八字节；读二、写二 二字节；读一、写一 一字节。布局注释里写明的段也认（「甲–乙」「甲 至 乙」「甲 起 丙 字节」，十六进制也认；段里还有别的状态格时那是若干格共用的区，不算一格的宽）。仍判不出的，下一格恰在四字节之后时按四字节（布局的密排惯例），其余按八字节算并逐格列出。任意两格区间重叠就逐对印出两格的名称、偏移与宽度，另发一条 GitHub Actions 错误，以状态一退出。只读，不改布局；给了路径时核对那个文件（用来验故意重叠的样例）。
- `./格式检查。林檎。豫行 文件路径……`：检查指定文件，标识符与排版问题都只发警告。

仓外路径按文件系统递归列文件，跳过点开头的目录与 `.豫构缓存`。目录本身是另一个 Git 仓时同样照文件系统列，不读那个仓的 `.gitignore`：这条路最简单，也不依赖那个仓的 Git 状态，代价是被忽略的源文件也会一并检查。仓外文件的路径规则只看所给路径之下的相对路径，宿主目录名（如 `/tmp`、私有仓的英文目录名）不参与。

提案 00013（标识符规范化）已把仓库里的存量违规清理完毕，此后任何违规都会让检查失败。源码解析失败的文件发警告，只查路径。
CI 的 `formatting check` 作业依次运行 `--标签`（标签参数与命名元组；基准取上一次推送的提交，拉取请求取目标分支的提交）、`--文件名` 与 `--兜底`，三者都只发警告，作业不因此失败；随后运行 `--状态格`，有状态格重叠时作业失败；再取与无参检查相同的文件，按处理器数并行运行 `--只查排版`（每个进程查一个文件），只发警告；最后运行 `--只查标识符`，有违规时作业失败。工具构建失败同样由作业报告失败。
