# 内府台（自己的对象存储服务程序）

通称内府服务程序（own object storage service）。这是提案 00064《内府》第一步的服务程序：读配置、起服务、收请求、回话。

## 起法

```
内府台。林檎。豫行 [配置路径]
```

配置路径省略时取台默认径：豫言操作系统上是 `/系统/内府/内府台。数据。豫`，宿主上是家目录下的 `.豫言/内府/内府台。数据。豫`。

数据目录要按名授给程序，写才在回话之前同步到盘。**没授目录时内府台起不来**：报中文错误（写明授权办法）并以退出码一退出——提案 00064 议五要求写入落盘才回话，不授目录就做不到。

宿主上这样起：

```
内府台。林檎。豫行 --授权目录写 内府=<数据目录> -- <配置路径>
```

豫言操作系统上作常役起（`--授权目录写` 这一对与宿主上同形，写在常役的参数里，执行器启动时自行认去）：

```
「登记常役」于「名」曰『内府』于「程序」曰『/系统/内府/内府台。豫行』于「参」曰「列」【『--授权目录写』，（『内府=/系统/内府』）】于「重起」曰『常』
「起常役」于「名」曰『内府』
「常役态」于「名」曰『内府』
```

临时在前台起一次（调试用）用「行」，授权写法相同：

```
「行」于「程序」曰『/系统/内府/内府台。豫行』于「参」曰「列」【『--授权目录写』，（『内府=/系统/内府』）】于「授权」曰「列」【（『内府=/系统/内府』）】
```

（壳的「行」若还没有单独的授权栏，就照常役那样把 `--授权目录写 内府=/系统/内府` 直接写进参数列；两种写法执行器都认。）

## 配置

```yuyan
「内府台」者 「典」
　【「数据目录」者『/系统/内府』也
　，「地址」者『127.0.0.1』也
　，「端口」者「九零九一」也
　，「虎符」者『虎符』也
　，「桶们」者「列」【『jiufu』】也
　，「授权目录」者『内府』也
　】
也。
```

- `数据目录`：金匮根与内府台配置所在；缺省豫言操作系统上 `/系统/内府`，宿主上家目录下的 `.豫言/内府`。
- `地址`、`端口`：监听；端口缺省 9091。
- `虎符`：虎符文件的路径；相对路径按数据目录算。虎符的内容只从文件读，日志不写。
- `桶们`：许用的桶名单；不在名单里的桶答“桶不在内府台的桶名单里”。
- `授权目录`：启动时 `--授权目录写` 用的名，缺省 `内府`。

## 三副本

配置里再加一节「盟」，这一台就按三副本起；不写这一节照旧是单机内府台：

```yuyan
「内府台」者 「典」
　【「数据目录」者『/系统/内府』也
　，「地址」者『127.0.0.1』也
　，「端口」者「九零九一」也
　，「虎符」者『虎符』也
　，「桶们」者「列」【『jiufu』】也
　，「授权目录」者『内府』也
　，「盟」者 「典」
　　【「本员号」者『甲』也
　　，「员们」者「列」【
　　　　「典」【「员号」者『甲』也，「地址」者『127.0.0.1』也，「端口」者「二一零零一」也】，
　　　　「典」【「员号」者『乙』也，「地址」者『127.0.0.1』也，「端口」者「二一零零二」也】，
　　　　「典」【「员号」者『丙』也，「地址」者『127.0.0.1』也，「端口」者「二一零零三」也】
　　　】也
　　，「快照门限」者「二六八四三五四五六」也
　　】
　】
也。
```

**只有这一种写法**：「盟」必须写在「内府台」一节的栏里（如上面的例子）；在顶层另起一节「盟」、或在「内府台」/「盟」里写不认识的栏，起台时都会报中文错误并以退出码一退出，不会悄悄退成单机。

- 「快照门限」以字节计，缺省 268435456（256 MiB）。载书各段字节总数过了它，这一员就在两次交付之间把金匮抄成快照、调盟府立照并截掉旧的载书段；盟主另把最新快照送给落后太多的远员，远员收全核过后装进来。测试里把它调到几万字节，好在一小批写之后就立照。快照的目录与清单格式、送照与装照的次序、崩在中途的收拾、重起的三项核对，见「内府」包说明的「快照」一节。
- 本员按本员址里的地址与端口听客与盟员；`内府台` 一节的 `地址`、`端口` 在单机模式用，三副本时以「盟」里本员那一条为准。
- 客户端与盟员共用一个端口。理由：配置里每员只写一个端口，一台上只有一门；连接建立后先走合符，认过之后按第一封的顶层名分辨「请」与「信」，两路互不相扰。另起一个端口要在每员配置里多写一项、多开一门，还要多维护一条监听，不如共一门省。
- 三台用同一份虎符（各台的 `虎符` 指向同一个文件或内容相同的文件）。
- 数据目录下的 `盟态`、`载书` 是共识的稳定存储：每次发信之前先写它们并同步到盘；重起从这两卷恢复。不要手改。

```yuyan
「登记常役」于「名」曰『内府甲』于「程序」曰『/系统/内府/内府台。豫行』于「参」曰「列」【『--授权目录写』，（『内府=/数据/内府甲』），（『/数据/内府甲/内府台。数据。豫』）】于「重起」曰『常』
「起常役」于「名」曰『内府甲』
```

三台的常役各起一架，配置里的数据目录与端口各各不同。

## 故障时的行为

- 客户端连到不是盟主的台：答「非主」并附所知盟主的地址；适配改连过去（见「豫寓府库内府榫」）。
- 盟主进程被杀或断网：余下的台在选举超时（三百至六百毫秒）后选出新盟主；期间到达的写要么改连新盟主，要么在重试上限内重发。已经答「成」的写都过了半数落盘，不会丢。
- 某一台重起：先收拾装照留下的临时目录与旧目录，再读 `盟态`、快照清单与 `载书` 追上来（有快照点时先读 `快照/<照点>/`，再读照点之后的载书）；照点、已行与金匮目录对不上就报中文错误退出。追上之前它还不是盟主、读答非主；追上之后照常参与。重起时同一数据目录、同一端口。
- 落后的从员：盟主发现它要的载书已截掉，就改送最新快照（照始、一块一兆的照块、照终）；从员收全、核过大小与沙二五六才装，装完答载成，盟主随后从照后重发。装照中途断线或核不过，就丢掉临时照目，等盟主下次再送。
- 两员同时断、不足过半：写不能盟成、读确认也数不过半，客户端等到超时或重试上限，服务等余员回来才恢复；这是过半数的本分。
- 载书或盟态损坏、已行超过载书条数：起台时报中文错误并以退出码一退出，不带坏盘跑。
- 同步到盘失败：这一步不往下走，进程报错退出（落不了盘的步不配发信、不配回话）。

## 停止

- 收到请求「息」：答成后停收新请求，办完手头的写、同步，收场退出。
- SIGTERM：执行器不接这个信号，进程直接结束。每次写都在回话之前同步到盘、写入本身整份原子，所以已回话的写不会丢，也不留半写的状态。

## 日志

写成人看的文字行，前缀 `内府台｜`：起时的地址、桶名单与落盘是否授了目录；收场一行。虎符的内容不进日志。
