# 曲突（静态防错榜）

读 `持续改进目标/静态防错/建议。数据。豫` 之建议表，按每议所防之数而列其次，复依类而总之，书 Markdown 之报告。CI 之工作流「静态防错」（`.github/workflows/静态防错.yml`）每推 `yybs` 而涉静态防错之数据、提案、本包与此工作流者辄行之，书报告于作业之摘要，且为发行之页[语言设计建议](https://github.com/yuyan-lang/yuyan/releases/tag/language-feature-suggestions)之说明（惟列表中未落实之语言设计之议）；页未立则立之。

有 `--开签` 与 `--全议` 者，改为建议一致之核：读稿府所给之议与 `提案/`，核其签、其表与其案之状，三处同异，只报不阻。

名取《汉书·霍光传》之曲突徙薪：客劝主人曲其突、远其薪，主人不听，俄而失火；防患于未然，本榜之意也。

## 用法

于仓之根行之：

```sh
豫构 构建 曲突 --输出 曲突。林檎。豫行 -j 24
./曲突。林檎。豫行
./曲突。林檎。豫行 --表 径 --批次 目录
./曲突。林檎。豫行 --开签 开签.json --全议 全议.json
```

`--表` 指建议表之数据文，`--批次` 指诸批议题析表之目录。阙则取今目录下之 `持续改进目标/静态防错/建议。数据。豫` 与 `持续改进目标/静态防错/批次/`；批次之目不在或空者，报告如故。

`--开签` 指开而带「语言设计建议」之签者，`--全议` 指全部议题之号与态，二者皆 `gh issue list` 之出（结绳）。核议之式另读今目录下之 `提案/`，依案号取其「状态」之行。只报不阻，有异亦以退码零终；数据不合结绳者告祸。

## 报告

次第为：题、引言、三链、总数、排行之表、按类之表与各条之说明：

- 总数一句：共几议，涉几题（去重）；读得批次者，又加一句：已析几题（去重），其中有议者几、只能运行时几、不适用几。
- 排行：依议题之多寡自多而少，同数者依建议表之先后；列为名次、建议、类、议题数、议题与状态。议题之号自小而大，以空隔之；有提案者，状态之后书提案之号。
- 按类：类、建议数、议题数（去重），依议题之多寡自多而少，同数者依类名之先后。
- 各条说明：每条一段，次第同排行。

## 核对

以一表为源，核三处：稿府上开而带「语言设计建议」之签者、建议之表、`提案/` 中各篇之状态行。核对之报告首列开签、建议、待审与待引之数，次列不合之处：

- 开而带签之议，必为某待审之议所引；表中无之，或独为不待之议所引者，列其号与由，宜摘签或书结论而关之。
- 待审之议所引而开者，必带此签；缺者列其号与议名，宜补签。
- 待审者，其状为待办或暂缓而所立之案未定（无案，或案之状为讨论中）。案已接受、已否决、已落实、实施中、暂缓实施或已取代者，其议出待审之列，由案跟进。
- 议所引之号必有其题；不存，或提案之卷、状态之行不得，状态不识者，别列为表之过。

## 数据

建议表之顶为「建议们」之「建议」记录列，每条之栏为名、类、说明、议题（议题号之列）、状态与提案（无则空）。批次目录下每 `X。数据。豫` 之顶为「析们」之「析」记录列，每条之栏为议题（议题之号）、题、类、建议与说明。二者皆以库「籍册」读写，议题之号为整数，报告书以阿拉伯数字。

## 局限

排序、计数与去重皆在内存为之，议至数万条则迟（码中留待办之注）。
