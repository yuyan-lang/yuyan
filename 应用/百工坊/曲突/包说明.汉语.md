# 曲突（静态防错榜）

读 `持续改进目标/静态防错/建议。数据。豫` 里的建议表，按每条建议防得住的议题数排出先后，再按类汇总，以 Markdown 打印报告。CI 工作流「静态防错」（`.github/workflows/静态防错.yml`）在每次推送到 `yybs`、改动涉及静态防错的数据、提案、本包或该工作流时运行它，报告写进作业摘要，并设为发行页[语言设计建议](https://github.com/yuyan-lang/yuyan/releases/tag/language-feature-suggestions)的说明（只列建议表里还没落实的语言设计建议）；页还没有就新建。

带 `--开签` 与 `--全议` 时改做建议一致核对：读稿府给出的议题数据与 `提案/`，核对标签、建议表与提案状态三处是否一致，只报不挡。

名取《汉书·霍光传》的曲突徙薪：客劝主人把烟囱改弯、把柴挪远，主人不听，后来失火；防患于未然，正是本榜的意思。

## 用法

在仓库根目录运行：

```sh
豫构 构建 曲突 --输出 曲突。林檎。豫行 -j 24
./曲突。林檎。豫行
./曲突。林檎。豫行 --表 路径 --批次 目录
./曲突。林檎。豫行 --开签 开签.json --全议 全议.json
```

`--表` 指建议表的数据文件，`--批次` 指各批议题析表的目录。缺省为当前目录下的 `持续改进目标/静态防错/建议。数据。豫` 与 `持续改进目标/静态防错/批次/`；批次目录不在或为空时照常出报告。

`--开签` 指开着的、带「语言设计建议」标签的议题，`--全议` 指全部议题的号与状态，两者都是 `gh issue list` 的输出（结绳）。核对模式另读当前目录下的 `提案/`，按提案号取各篇的「状态」行。只报不挡，有不一致也以退出码零结束；数据不合结绳时告祸。

## 报告

依次是标题、引言、三个链接、总数、排行表、按类表与各条说明：

- 总数一句：共几条建议，涉及几个议题（去重）；读到了批次时再加一句：已析几个议题（去重），其中有建议的几个、只能运行时几个、不适用几个。
- 排行：按议题数从多到少，同数按建议表里的先后；列为名次、建议、类、议题数、议题与状态。议题号从小到大，空格分隔；有提案的，状态后写提案号。
- 按类：类、建议数、议题数（去重），按议题数从多到少，同数按类名先后。
- 各条说明：每条一段，次序同排行。

## 核对

以建议表为唯一来源，核对三处：稿府上带着「语言设计建议」标签的开着议题、建议表、`提案/` 里各篇的状态行。核对报告给出开签数、建议数、待审数与待审建议引用开着的议题数，再逐一列出对不上之处：

- 开着的带标签议题，须被某条待审建议引用；表里没有它的，或只被不待审建议引用的，列出议题号与缘由，建议摘标签或写明结论后关议题。
- 待审建议引用的开着议题，须带这个标签；缺的列出议题号与建议名，建议补标签。
- 待审指状态为待办或暂缓、所挂提案还没定（没有提案，或提案状态为讨论中）。提案已接受、已否决、已落实、实施中、暂缓实施或已取代的，建议移出待审队列，由提案跟进。
- 建议引用的议题号都要存在；不存在或提案文件、状态行找不到、状态认不出的，另列建议表自身的问题。

## 数据

建议表顶层是「建议们」的「建议」记录列，每条的字段为名、类、说明、议题（议题号列）、状态与提案（没有就空着）。批次目录下每个 `X。数据。豫` 顶层是「析们」的「析」记录列，每条的字段为议题（议题号）、题、类、建议与说明。两处都用库「籍册」读写，议题号是整数，报告里写成阿拉伯数字。

## 局限

排序、计数与去重都在内存里做，建议多到几万条时会变慢（代码里留有待办事项）。
