# 社区包工具

`社区包工具` 是社区包仓库 [yuyan-lang/yuyan-community-packages](https://github.com/yuyan-lang/yuyan-community-packages) 的检查与构建程序：拉取请求的元数据检查、独立构建树里的构建与测试、向 yuyan-lang.org 推送程序与软件目录、合入机器人的决定，以及把语言仓的包复制进社区仓库。社区仓库的工作流按 `工具链钉。数据。豫` 检出语言仓的同一提交、解开同一提交的原生工具链包，再用包里的 `豫构稳定。林檎。豫行` 构建本工具。

## 为什么放在语言仓

- 合入机器人靠它的结论自动合入；它放在语言仓，社区仓库的拉取请求改不到它。
- 它直接用语言仓的库（包配置解析包描述、构建基础发现包、版本库列出 Git 文件），随语言仓 CI 一起类型检查；库接口变了，语言仓里就会报错。
- 社区 CI 用同一份钉住的工具链构建它和社区包，不另管版本。
- 语言仓 CI 的复制作业也用它。

## 命令

| 命令 | 作用 |
| --- | --- |
| `检查 --社区 <根> --语言仓 <根> --基 <提交> [--头 <提交>] [--输出 <包清单>]` | 拉取请求的元数据检查，只读不跑包里的代码：改动的文件须在 `包/<所有者>/<包名>/` 里；不收符号链接、子模块与可能含凭据的文件（如 `.env`、`*.pem`）；所有者名“社区”保留；包描述在 `包/<所有者>/<包名>/<包名>。包。豫`，所有者等于目录名，不写「包含在」「包含包」；「许可」必写，且在白名单里；有名帖的包核对类别在九类之内、提要不超过三十字、图标文件存在、所开只含小写字母数字与空格，包描述写「界面」者『图形』的图形软件必须有名帖（提案 00046 第二节）；每个非合并提交带与作者邮箱相符的 `Signed-off-by`（DCO）。问题以 GitHub 注解打印，有问题时退出码 1。要构建的包（改动的包、依赖它们的包；工具链钉改了就是全部）写进包清单（数据子语言，顶层「包们」，每个记录「包」带所有者与包名）。 |
| `改动 --社区 <根> --语言仓 <根> (--基 <提交> \| --全部) [--头 <提交>] --输出 <包清单>` | 只算要构建的包，main 上的构建用。 |
| `构建 --社区 <根> --语言仓 <根> --包清单 <文件> --树 <目录> --产物 <目录> [--提交 <提交号>] [--目标 <目标,…>] [--测试] [--归档] [-j <并发>]` | 把要构建的包连同依赖闭包复制进构建树 `<树>/<所有者>/<包名>/`，再用语言仓根下的 `豫构稳定。林檎。豫行` 与 `执行器。树码` 构建：库做类型检查；可执行包按目标编程序，放在 `<产物>/程序/<所有者>/<包名>/<目标>`；图形软件（包描述写「界面」者『图形』）只编 `豫言-兼容六十四`、`豫言-臂六十四`、`林檎-臂六十四`，跳过林纳两个目标、不算失败（提案 00046 第三节）。名帖写了图标时，用 `豫构 设计 编译` 把图标设计作品编好，再用徽识的画图标与画谱的便图编码渲成 128×128 的 PNG，放在 `<产物>/图标/<所有者>/<包名>/<版本>.png`，程序清单记下相对路径。`--测试` 时编并运行包里的 `*。测试。豫`（在包目录里运行，每个至多十分钟）。`--归档` 时给每个包写源码与文档归档 `<产物>/归档/<所有者>/<包名>/<版本>.zip`（`源码/` 是构建树里这个包的全部文件，`文档/` 有阅读首页、`包信息.json`、`生成状态.json`；超过 16 MiB 不写），记进 `<产物>/归档清单。数据。豫`。程序清单（十五列）写进 `<产物>/清单。数据。豫`，失败原因写进 `<产物>/失败.txt`。 |
| `推送 --产物 <目录> [--演练] [--网址根 <网址>]` | 推送到 yuyan-lang.org：有图标的先 `PUT /api/ci/图标/<所有者>/<包名>/<版本>`（正文是便图字节，带 `x-yuyan-sha256`），程序 `PUT /api/ci/程序/<所有者>/<包名>/<版本>/<目标>`（带 `x-yuyan-sha256`），归档 `PUT /api/ci/归档/<所有者>/<包名>/<版本>`，最后是软件目录：每个所有者一份 `PUT /api/ci/软件目录/<所有者>/<目标>。数据。豫`，另有汇总全部社区程序的 `软件目录/社区/<目标>。数据。豫`；目录是数据子语言（提案 00028）的记录列，顶层「软件们」、每个程序一个记录「软件」，十五个字段（名称、版本、网址、沙256、字节数、简介、包名、所有者、提交、界面、显示名、类别、提要、图标、所开）。图标的网址写 `https://yuyan-lang.org/豫/<所有者>/包/<包名>/<版本>/图标.png`，没有图标时为空串。线上旧的九列记录先补足十五列（界面按终端，显示名取名称，类别“命令行”，提要取简介第一句，图标与所开空）。内容没变就不重传（用户 2026-10-14 定）：程序的沙256 与所有者现有目录里同一个包、同一目标那个记录相同时，沿用旧版本与旧记录，不 PUT 程序或图标；目录先读线上现有的，换掉这次重编的包的记录，与现有的相同就不重传。归档上传失败（如所有者未绑定）只告警。令牌取环境变量 `YUYAN_CI_UPLOAD_TOKEN`，经权限 600 的 curl 配置文件传入；没有令牌或带 `--演练` 时只打印将要发送的请求。 |
| `合入核对 --拉取请求 <pr.json> --文件 <files.json> --运行 <run.json> --作业 <jobs.json> --所有者应答 <owner.json> --所有者状态 <状态码> [--输出 <理由文件>]` | 合入机器人的决定，只看 GitHub 接口与 yuyan-lang.org 的元数据。可以合入时退出码 0，不能时 10，理由写进理由文件。 |
| `复制 --语言仓 <根> --社区 <根> --钉网址 <网址> --钉沙256 <摘要> --钉提交 <提交号>` | 把清单「社区复制包们」里的语言仓包复制到社区仓库的 `包/豫言/<包名>/`：只复制属于该包的 Git 文件，去掉层级字段与模板目录，补上「许可」`AGPL-3.0-only`，放一份语言仓的 LICENSE；把 `包/豫言/` 下不在清单里的包目录删掉（移出清单即从社区仓下架，别的所有者的目录不动），删掉的包逐个打印出来；并改写工具链钉。 |

## 名帖与界面

包描述「类型」里可选「界面」者『图形』或『终端』（不写为终端），用牌记的 `包界面`、`包为图形` 读取，`述界面` 写回“图形”“终端”（提案 00046 第一节）。

包目录里可放 `名帖。数据。豫`，顶层「名帖们」、记录「名帖」，字段是显示名、类别、提要、图标、所开（提案 00046 第二节）。工具用数据文件库「籍册」按字段名读第一项；没有名帖时用缺省：显示名取软件名，类别“命令行”，提要取简介第一句，图标与所开空。名帖的类别是工具、办公、影音、图像、游戏、开发、网络、系统、学习之一；提要三十字以内；图标是包内设计作品的相对路径（画法同徽识：二十四格视框，墨色、朱色描线，纸色底），写了图标时构建会把该作品渲成 128×128 的便图；所开是能打开的文件后缀，小写、不带点、以空格分隔。

名帖规则在语言仓合入前就查：全树测试里的 `测试/名帖。测试。豫` 调用同一个「名帖问题们」，核对清单「社区复制包们」里的每个包与所有带名帖的包，有问题时测试失败并印出包名与问题。

## 语言仓 CI 的复制作业

`.github/workflows/main.yml` 的作业 `community-copy`（复制到社区包仓库）在推送 yybs、历史版本发布之后运行：用本轮的原生豫构构建本工具，找到本轮发布的 Linux x64 原生工具链包（算出沙256），检出社区包仓库，运行 `复制`（移出「社区复制包们」的包随之从 `包/豫言/` 下架，删了哪些写进拉取请求正文），以 `github-actions[bot]` 的身份带 DCO 签名提交（GitHub 认得这个账户，cla-bot 按它的用户名查官网的贡献协议旧放行名单），推送分支 `语言仓/<提交号前九位>` 并开拉取请求，由社区仓库的检查与合入机器人合入。新拉取请求开好后，关掉此前由语言仓复制、检查失败的拉取请求（评论指向新的，并删除其分支）；检查还没跑完的先留着，关不掉只发警告。跨仓写入用机密 `YUYAN_COMMUNITY_TOKEN`（细粒度个人令牌，只授社区仓库的 Contents 与 Pull requests 写权限；拉取请求的作者就是令牌的主人，合入机器人按他关联的所有者核对，所以令牌的主人要关联到所有者“豫言”）。没有这个机密时演练：照样复制、提交，把补丁存为构件“社区复制补丁”，不推送。本轮历史版本没发布（某个平台没过）时不复制。

## 约定

- 目标写成“系统-架构”：`豫言-兼容六十四`、`豫言-臂六十四`、`林纳-兼容六十四`、`林纳-臂六十四`、`林檎-臂六十四`。`豫言-兼容六十四` 与 `林纳-兼容六十四` 必须编成，其余编不成只告警。图形软件只编 `豫言-兼容六十四`、`豫言-臂六十四`、`林檎-臂六十四`，跳过林纳两个目标、不算失败（提案 00046 第三节）。
- 目标专用入口：编豫言系统的目标时，包根有「豫行入口」模块就用它；编林檎的目标时，有「林檎入口」就用它；否则用包的默认入口。
- 程序的版本是 `<包描述的版本>+<社区仓库提交号前九位>`，与云仓提案 C00004 的规则相同。
- 软件目录十五列：名称、版本、下载网址、沙256、字节数、简介、包名、所有者、源码提交号、界面、显示名、类别、提要、图标、所开（提案 00046 第三节）。所有者目录的名称是包名；汇总目录里所有者“豫言”的程序用包名，其他所有者用“所有者之包名”。
- 许可白名单：Apache-2.0、MIT、BSD-2-Clause、BSD-3-Clause、ISC、Zlib、0BSD、AGPL-3.0-only、AGPL-3.0-or-later，可用 `AND`、`OR` 组合；括号与 `WITH` 不收。
- 合入机器人的规则：拉取请求开着、不是草稿、目标分支 main；触发它的“拉取请求检查”来自 `.github/workflows/拉取请求检查.yml`、由拉取请求触发且成功，“元数据检查”“构建与测试”两个作业都成功，头提交相同；作者的 GitHub 账号在 yuyan-lang.org 关联了已绑定所有者名称的豫言账户，数字编号对得上；改动全在 `包/<该所有者>/` 下（所有者“豫言”还可以改工具链钉）。
