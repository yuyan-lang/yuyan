# 社区包工具

`社区包工具` 者，社区包仓库 [yuyan-lang/yuyan-community-packages](https://github.com/yuyan-lang/yuyan-community-packages) 检与构之程也：拉取请求元数据之检、独立构建之树中之构与试、推程与软件目录于 yuyan-lang.org、合入之机之断，及抄语言仓之包入社区仓库。社区仓库之工作流依 `工具链钉。数据。豫` 检出语言仓之同一提交，解同提交之原生工具链包，乃以包中之 `豫构稳定。林檎。豫行` 构此器。

## 何以置于语言仓

- 合入之机依其断而自合；置于语言仓，社区仓库之拉取请求不能改之。
- 径用语言仓之库（包配置解包籍、构建基础求包、版本库列 Git 之文），随语言仓 CI 核其型；库口变则语言仓即报之。
- 社区 CI 以同一所钉之工具链构此器与社区诸包，不另管其版。
- 语言仓 CI 之抄录亦用之。

## 诸令

| 令 | 所为 |
| --- | --- |
| `检查 --社区 <根> --语言仓 <根> --基 <提交> [--头 <提交>] [--输出 <包清单>]` | 拉取请求元数据之检，惟读而不行包中之代：所改之文须在 `包/<所有者>/<包名>/`；不收符号链接、子模块与或含凭据之文（如 `.env`、`*.pem`）；所有者名“社区”保留；包籍在 `包/<所有者>/<包名>/<包名>。包。豫`，所有者同目名，不书「包含在」「包含包」；「许可」必书而在白名单；有名帖之包核其类别在九类、提要不过三十字、图标之文必存、所开惟小写字母、数字、汉字、全角句号与空格，包籍书「界面」者『图形』之图形器必有名帖（提案〇〇〇四六第二节）；每非合并之提交带与作者邮箱相符之 `Signed-off-by`（DCO）。问题以 GitHub 之注印之，有则退码一。所构之包（所改者、依之者；工具链钉改则皆是）书于包清单（数据子语言，顶名「包们」，每记「包」具所有者与包名）。 |
| `改动 …` | 惟算所构之包，main 之构用之。 |
| `构建 …` | 抄所构之包并其所依之闭包于构建之树 `<树>/<所有者>/<包名>/`，乃以语言仓根下之 `豫构稳定。林檎。豫行` 与 `执行器。树码` 构之：库核其型；可执行之包依目标编为程，置于 `<产物>/程序/<所有者>/<包名>/<目标>`；图形之器（包籍书「界面」者『图形』）与终端之器同，编全部五目标（提案〇〇〇四六第三节）。名帖书图标则先以 `豫构 设计 编译` 编其设计之作为，次以徽识画图标之法与画谱便图之编，渲为 128×128 之 PNG，置于 `<产物>/图标/<所有者>/<包名>/<版本>.png`，程序清单记其相对之径。`--测试` 则依语言仓之试规表（见下节）处置而行包中之 `*。测试。豫`（于包目行之，每试至多十分）。`--归档` 则书每包源码与文档之档 `<产物>/归档/<所有者>/<包名>/<版本>.zip`（逾十六 MiB 不书），录于 `<产物>/归档清单。数据。豫`。程序清单（十五列）书于 `<产物>/清单。数据。豫`，败因书于 `<产物>/失败.txt`。 |
| `推送 --产物 <目> [--演练] [--网址根 <网址>]` | 推于 yuyan-lang.org：有图标者先 `PUT /api/ci/图标/<所有者>/<包名>/<版本>`（正文为便图之字，带 `x-yuyan-sha256`），程 `PUT /api/ci/程序/…`（带 `x-yuyan-sha256`；程逾九十 MiB 则分段：`POST …?分段=始` 以整份摘要求号，逐段 `PUT …?上传号=<号>&段号=<N>`（每段六十四 MiB，末段可小），`POST …?分段=终&上传号=<号>` 交 `{"段们":[…]}` 收之，败则 `DELETE …?上传号=<号>` 弃之），档 `PUT /api/ci/归档/…`，终为软件目录：每所有者一份，又汇诸社区之程为 `软件目录/社区/<目标>。数据。豫`；目录为数据子语言（提案〇〇〇二八）之记列，顶名「软件们」、每程一记「软件」，十五字段（名称、版本、网址、沙256、字节数、简介、包名、所有者、提交、界面、显示名、类别、提要、图标、所开）。图标之址书 `https://yuyan-lang.org/豫/<所有者>/包/<包名>/<版本>/图标.png`，无图标则空串。线上旧九列之记先补足十五列（界面作终端，显示名取名称，类别“命令行”，提要取简介首句，图标与所开空）。内容不变则不复传（用户二〇二六年十月十四日定）：程之沙256 同于所有者现有目录中同包同目标之记，则沿用旧版与旧记，不 PUT 其程与图；目录先读线上，易此次重编之包之记，与现有同则不复传。档传之败（如所有者未绑）惟告警。令牌取环境变量 `YUYAN_CI_UPLOAD_TOKEN`，作 `Authorization: Bearer` 之请首，由尺素径发，不书于命令或磁盘；无令牌或带 `--演练` 则惟印所将发之请求。 |
| `合入核对 …` | 合入之机之断，惟视 GitHub 之口与 yuyan-lang.org 之元数据。可合则退码零，否则十，其因书于理由之文。 |
| `复制 …` | 抄清单「社区复制包们」诸语言仓包于社区仓库之 `包/豫言/<包名>/`：惟抄属其包之 Git 文，去层级之字段与模板之目，补「许可」`AGPL-3.0-only`，置语言仓之 LICENSE 一份；去 `包/豫言/` 下不在清单之包目（出清单即自社区仓下架，他所有者之目不犯），所去者逐印之；并改书工具链钉。 |

## 试规

`--测试` 时读语言仓之 `应用/百工坊/全树测试/测试规则。数据。豫`（全树测试之试规表，规则项之型与查规则在考课之 `试规。豫`，二处共之），依语言仓中之包目加试之相对径，合包中之每 `*。测试。豫`：

- `验收`：不编不行。云页脚本之属须仓外之数，社区之容器无之。
- `只检查`：惟核其型，不编程、不行。真站之属须连公网，社区之容器不联网。
- `已知失败`：仍编而行，败惟印之、不计其败；成则告可出表。
- `参数`：依注传行参，以空格分段，`{豫构}` 易为所钉之豫构径；注引 `{仓根}`、`{编译器}` 之类社区之树所无之径则惟核其型。
- `诺驿`：社区之容器无诺驿之宿主，惟核其型。
- 无规则、或表不在：仍编为本机之程而行。

## 名帖与界面

包籍「类型」可书「界面」者『图形』或『终端』（不书为终端），用牌记之 `包界面`、`包为图形` 读之，`述界面` 书回“图形”“终端”（提案〇〇〇四六第一节）。

包目可置 `名帖。数据。豫`，顶「名帖们」、记「名帖」，字段为显示名、类别、提要、图标、所开（提案〇〇〇四六第二节）。工具以数据文件库「籍册」依字段名读其首项；无名帖则用缺省：显示名取软件名，类别“命令行”，提要取简介首句，图标与所开空。名帖之类别为工具、办公、影音、图像、游戏、开发、网络、系统、学习之一；提要三十字以内；图标为包内设计作品之相对径（画法同徽识：二十四格视框，墨朱描线，纸色底），书图标则构时渲其为 128×128 之便图；所开为能开之文之后缀，小写、去点、以空格间之；豫言之缀带汉字与全角「。」（若“会话。豫”），汉字与全角句号亦为合式。

名帖之则于语言仓合入之前即检：全树测试之 `测试/名帖。测试。豫` 调同一「名帖问题们」，核榜「社区复制包们」之每包与凡带名帖之包，有则试败而印其包名与问题。

## 语言仓 CI 之抄录

`.github/workflows/main.yml` 之作 `community-copy`（抄于社区包仓库）行于推 yybs、史版既发之后：以本轮之原生豫构构此器，求本轮所发之 Linux x64 原生工具链包（算其沙256），检出社区包仓库，行 `复制`（出「社区复制包们」之包随之自 `包/豫言/` 下架，所去者书于请之正文），以 `github-actions[bot]` 之名带 DCO 之签录之（GitHub 识其户，cla-bot 以其名问官网贡献协议之旧放行名录），推枝 `语言仓/<提交号前九位>` 而开拉取请求，由社区仓库之检与合入之机合之。新请既开，则闭前此语言仓所抄而检败之请（评以新请之址，并去其枝）；检犹未竟者姑存之，闭之不成则惟警之。跨仓之写用机密 `YUYAN_COMMUNITY_TOKEN`（细粒度之个人令牌，惟授社区仓库 Contents 与 Pull requests 之写；拉取请求之作者即令牌之主，合入之机依其所联之所有者核之，故令牌之主当联于所有者“豫言”）。无此机密则演练：照抄照录，存其补丁为构件“社区复制补丁”，不推。本轮史版未发（某平台未过）则不抄。

## 约

- 目标书“系统-架构”：`豫言-兼容六十四`、`豫言-臂六十四`、`林纳-兼容六十四`、`林纳-臂六十四`、`林檎-臂六十四`。`豫言-兼容六十四` 与 `林纳-兼容六十四` 必成，余不成惟告警。图形之器与终端之器同，编全部五目标（提案〇〇〇四六第三节）。
- 目标专用之入口：编豫言系统之目标，包根有「豫行入口」则用之；编林檎之目标，有「林檎入口」则用之；否则用包之默认入口。
- 程之版为 `<包籍之版>+<社区仓库提交号前九位>`，同云仓提案 C00004。
- 软件目录十五列：名、版、下载之址、沙256、字数、简介、包名、所有者、源码之提交号、界面、显示名、类别、提要、图标、所开（提案〇〇〇四六第三节）。所有者之目录以包名为名；汇总之目录，所有者“豫言”之程用包名，余所有者用“所有者之包名”。
- 许可之白名单：Apache-2.0、MIT、BSD-2-Clause、BSD-3-Clause、ISC、Zlib、0BSD、AGPL-3.0-only、AGPL-3.0-or-later，可以 `AND`、`OR` 合之；括号与 `WITH` 不收。
- 合入之机之则：拉取请求开而非草稿，入 main；所触之“拉取请求检查”出 `.github/workflows/拉取请求检查.yml`、由拉取请求所触而成，“元数据检查”“构建与测试”二作皆成，头提交相同；作者之 GitHub 账号于 yuyan-lang.org 联已绑所有者名之豫言之户，数号相合；所改皆在 `包/<其所有者>/` 下（所有者“豫言”亦可改工具链钉）。

## 待办事项

- 接口之文档与源码之览（文档网站生成器、源码树浏览器）；今 文档/ 惟读之首页、包信息与生成之状。
- 软件目录去已删之包、不复编成之目标。
- 依赖之闭包循包籍之「依赖」，层级之包所隐之子不计（构建之树同批量发布去层级之字段）。
- 依改动之包者，每社区包求一闭包，包多则当藏之。
- 程字未变而惟改图者，不重传其图，图标之址随旧版。
