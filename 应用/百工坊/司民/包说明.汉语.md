# 司民（代码行数统计）

统计仓库里 git 受控的全部 `。豫` 源文件的代码行数，按种类、顶层目录与二级目录分类，以 Markdown 打印报告。CI 工作流「代码行数」（`.github/workflows/代码行数.yml`）在每次推送 `yybs` 与每个拉取请求上运行它，报告写进作业摘要；推送 `yybs` 时还把本次记入版籍，连同报告发布到发行版 [code-line-stats](https://github.com/yuyan-lang/yuyan/releases/tag/code-line-stats)，发行说明就是最新一次的报告。推送 `yybs` 时还画出近三十天的折线图，推到分支 [代码行数图](https://github.com/yuyan-lang/yuyan/tree/代码行数图)，嵌在报告里。

名取《周礼·秋官》的司民：“掌登万民之数，自生齿以上皆书于版，辨其国中与其都鄙及其郊野，异其男女，岁登下其死生。”以篇为户，以行为口。

## 用法

在仓库根目录运行：

```sh
豫构 构建 司民 --输出 司民。林檎。豫行 -j 24
./司民。林檎。豫行                                                  # 打印报告
./司民。林檎。豫行 --版 版籍。数据。豫                              # 读写版籍，报告里多出增减与近来各次
./司民。林檎。豫行 --版 版籍。数据。豫 --图 近三十天.svg            # 另画近三十天的折线图
./司民。林檎。豫行 --版 版籍。数据。豫 --图 近三十天.svg --图址 网址  # 报告里再按网址嵌入折线图
```

## 怎么数

- 范围：`git ls-files -- '*。豫'` 列出、且实际存在的文件。
- 每行归一类：有代码的行算代码，只有注释的行算注释，只有空白（空格、全角空格、制表符、回车）的行算空行。末行没有换行结尾的也算一行。
- 照词法逐字节扫描：外层遇注释起符进入注释，注释按深度计数，可以嵌套；名称读到右角括号；字符串读到未转义的右书名号，字符串里的转义整个跳过。名称与字符串跨行时，续行算代码。
- 种类是文件名从第一个全角句号起的后缀，如 `。测试。豫`、`。底层。豫`、`。包。豫`；普通源文件是 `。豫`。
- 目录取文件所在目录的前一层（顶层目录）与前两层（二级目录）；直接放在顶层目录里的文件归入顶层目录本身。

## 报告

依次是：合计（文件数、总行数、代码、注释、空行）；按种类、按顶层目录、按二级目录的三张表，各按代码行数从多到少排。带 `--版` 时，合计下面多一句与上次相比的增减，三张表多一列代码增减，末尾多一张近来三十次的表（新的在前）。带 `--图址` 时，合计后面多一节“近三十天”，按网址嵌入折线图。

## 折线图

`--图 路径` 把版籍里最近一次往前三十天的各次（含本次）画成一张白描（SVG）折线图，写到这个路径：

- 五条彩色线依次是文件、总行数、代码、注释、空行，都取合计。
- 横轴是提交时间。每天零点（按最近一次的时区）画一条竖格线，下面标“月-日”；日子多时隔几天标一个，全图标十来个。
- 纵轴是线性的读数，自零起。每条线按最近一次的值取十的幂作倍数，最近一次的读数因此落在一至十之间；图里只画读数，倍数写在图例里，如“总行数 ×10⁶”，读数乘倍数就是实数。纵轴的顶取各点读数的最大值，至少为十。
- 同一像素列里只画最晚的一次，末点加圆点。副题写起止时间与次数。
- 颜色按系统的浅色、深色模式（`prefers-color-scheme`）各取一组。

`--图址 网址` 让报告按这个网址嵌入折线图。CI 把图推到分支 `代码行数图`：每次是一个只含这张图的孤立提交，强推换掉旧的；报告里的网址是 raw.githubusercontent.com 上这张图的地址，后面带 `?提交=<提交号>`，每次的图各有其址。稽府（GitHub）的发行版资产一律以 `application/octet-stream` 下载，raw.githubusercontent.com 以 `image/svg+xml` 伺服，图才能在页面里显示。

## 版籍

`--版` 指一个数据文件（`名。数据。豫`，用库「籍册」读写），有两张表：

- 「历次」：每次一条「次」，字段为 提交、时（提交时间）、篇（文件数）、码、注、空（代码、注释、空行数）。
- 「近况」：最近一次按类的户口，每类一条「目」，字段为 组（种类、顶层、二级）、名、篇、码、注、空。

文件不存在时从这一次记起；同一提交再记一次时，换掉旧的那条。合计的增减比历次里的上一次，各类的代码增减比近况，上次没有的类按从零增加算。

## 局限

- 历次只增不删，每次都整篇读写。记到几万次、读写变慢时，再按时间稀疏旧记录（代码里留有待办事项）。
- 三十天里的记录都在同一天之内时，横轴按小时标刻度，留待后续版本（代码里留有待办事项）。
