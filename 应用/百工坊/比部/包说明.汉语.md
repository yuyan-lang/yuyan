# 比部（对象存储长跑核账程序）

通称对象存储长跑核账程序（object store long-run auditor）。这是提案 00054《九府》完成判据所用的核账程序：在第四台机器上一直对对象存储写、读、删、改，把每一笔已确认的操作记进只追加的账，末了逐条勾对，量出可用率与最长中断。它经九府的守藏（库术）办事，所以内府、邸阁（S3 协议）与金匮三种库类都能测。

名字取《唐六典》卷六“比部郎中、员外郎掌句诸司百寮俸料、公廨、赃赎、调敛、徒役课程、逋悬数物，以周知内外之经费而总勾之”：比部是唐代勾覆内外经费的审计之司，本程序勾覆存储里的每一笔。两个子命令：长跑写核叫「巡」，末了逐条勾对叫「总勾」。

## 构建与起法

```
豫构 构建 比部 --输出 比部。林檎。豫行
./比部。林檎。豫行 总勾 --配置 … --前缀 … --账 …
```

（林纳上把输出名换成 `比部。林纳。豫行`。）

## 配置

配置是一份数据文件 `比部。数据。豫`，与九府台同形，顶层是「九府」一节：`库`（`类`、`桶`、`凭据`）与 `数据目录`。数据目录就是金匮根：内府适配的 `内府。数据。豫` 与虎符都在它下面；凭据写相对路径，按数据目录算。数据目录省略时取府署默认目（豫言操作系统上 `/系统/九府`，宿主上是家目录下的 `.豫言/九府`）。

样例（包里的 `比部。数据。豫`）用金匮：

```yuyan
「九府」者「典」
　【「库」者「典」
　　　【「类」者『金匮』也，「桶」者『jiufu』也，「凭据」者『对象存储。数据。豫』也】也
　】
也。
```

测内府时把「类」改成『内府』，并在数据目录下备好 `内府。数据。豫`（地址们、虎符、超时）与虎符文件；测邸阁时改成『邸阁』并备好 S3 的凭据文件。库类、桶与凭据都直接复用九府「府署」「择库」，比部不再另设一套。

## 「巡」（长跑写核）

```
比部。林檎。豫行 巡 --配置 <路径> --前缀 <键前缀> --账 <账路径> --时长 <秒> [--间隔 <毫秒>] [--小 <字节>] [--大 <字节>]
```

- 单线程循环，直到时长用完。
- **写**：键 `<前缀><序>`，序从一递增，接旧账里已用的最大序号往下；正文按（前缀，序）确定地造：长度由序在 `小`、`大` 之间取，正文是沙二五六（SHA-256）的链式展开，写成小写十六进文。写物选项带 `sha256`，让内府台按摘要核验；答「成」之后才把这一笔记进账。
- **读**：从已确认、未删的键里随机抽一个读回，按（前缀，序，读回长度）重算正文比对；不符记「错」。
- **删**：每十轮挑最旧的已确认键删掉。先把「将删」记进账并强刷到盘，再发删；答成后记「已删」。这样比部自己崩在中途，总勾也不会把「删了没记」误报成丢失。
- **计**：计数对象 `<前缀>计数`，正文是十进制整数。读出值与摘要，用 `ifMatch` 写成加一；对象不在时用 `ifNoneMatch` 写一。成了把新值记进账；超时、出错或反复冲突算「疑」，记一笔疑，下一轮重读再续。
- **列**：每一百轮、且最大序号不足一万时，列一遍前缀下的键，条数少于应有就记疑。
- **中断与可用率**：每笔操作记起止单调毫秒与成败；中断从一次成功之后第一个失败操作的起点，到下一次成功的终点。可用率 = 1 − 中断总时长 ÷ 总时长。
- 每分钟印一行摘要（轮数、成败数、读错数、疑数、延迟中位与九十九分位、当前最长中断），结束印总表。

缺省 `--间隔` 一千毫秒、`--小` 六十四、`--大` 二百五十六。

## 账的格式

账是只追加的二进制文件：每条记录先写八字节小端长度，后接一份籍册（数据文件）数据值的二进制编码，分帧写法与内府载段相同（长度头与解长帛直接复用 `库/内府/载段` 的实现）。记录种类：

| 类 | 栏 | 意思 |
| --- | --- | --- |
| 写成 | 键、序、长、起、止、摘 | 写成功，摘是写后版本的摘要 |
| 将删 | 键、序、起、止 | 删除之前先记，并强刷到盘 |
| 已删 | 键、序、起、止 | 删除成功 |
| 计成 | 键、值、起、止、摘 | 计数写成加到的新值 |
| 疑 | 键、序、起、止、成、缘由 | 写失败、计数出错或列举不全等不肯定的操作 |
| 起止 | 段、起、止、附 | 段是「起」或「止」，附栏带参数或统计 |

写成、将删、已删、计成、疑都带起止单调毫秒；写失败也记一条疑（序大于零），故旧账知道哪些序号从没写成，续写时当空洞跳过。记录先在内存里攒着，每秒刷一次；「将删」与起始记录另加强刷。开账时若末条只写了一半，先截掉再续。账可以跨多次巡续写，同一前缀接着序号往下。

## 「总勾」（逐条勾对）

```
比部。林檎。豫行 总勾 --配置 <路径> --前缀 <键前缀> --账 <账路径>
```

读账并按前缀分出各类，然后：

- 写成且未删（也没有将删）的键必须读得出，正文按（前缀，序，长）重算相符；读不出记「丢失」，不符记「正文错」。
- 已删的键必须不在；还在记「删后仍在」。
- 只有将删、没有已删的键，在不在都算对。
- 计数：已确认的值（计成记录里的值）互不重复、严格递增；从存储读末值，末值不得小于已确认的最大值，也不得大于最大值加疑的笔数。

印出账里的笔数、丢失、正文错、删后仍在与计数违例的清单（各列前二十条）与总数；全对退出码零，否则一。

## 长跑的建议设法

- 间隔取一千毫秒（二十四小时约八万六千轮）；要更快压出毛病可取一百至二百毫秒。
- 正文小取六十四、大取四千零九十六；一轮写入量落在两者之间。
- 内府适配的「超时」在 `内府。数据。豫` 里设五千毫秒；长跑时留有足够余量，又不至于一次超时卡住太久。
- 账放在与对象存储不同的盘或机器上，账路径所在盘按每轮约一百多字节估算（八万六千轮约十兆）。
- 三台节点按完成判据每十分钟随机杀、重启或断网一台；此时「巡」会记下失败与疑，可用率与最长中段照实印出，跑完「总勾」应当零丢失、零正文错、零删后仍在、零计数违例。

## 故障时的行为

- 对象存储暂时不通：写失败记疑并推进序号、把序记进空洞；读失败记读错；删失败记疑并推进删除游标（只有将删的键，总勾算对）；计数失败记疑，下一轮重读再续。这些都不打断巡，中断时长照实累计。
- 比部自己崩掉：账里最多丢最后一秒的记录，它们只会是「没记上的成功」，不会造成误报；末条半截在下次开账时截掉。
- 起不来（配置读不出、库类不认、凭据或内府配置不在）：印一行缘由并以退出码一退出。
