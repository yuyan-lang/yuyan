# 全树测试

遍求全仓之试而行之，以一律断其成败，可分片并行；CI 之「全树测试」矩阵，逐片召此器。

## 用法

于仓根行之，先以 `豫构 目标 全树测试工具 -j 24` 造此器（今行之豫构径编之）。诸试由原生豫构编为本机原生之程而径行：仓根有 `豫构。林檎。豫行` 则用之，无则用 PATH 中之 `豫构。林檎。豫行`，新工作树以已装之工具链即可行；皆无（Windows 之原生工具链待后版）则退用 `豫构.wasm`，试编为 `.wasm` 交诺驿宿主行之：

```sh
豫构 构建 全树测试 --输出 全树测试。林檎。豫行 -j 24
./全树测试。林檎。豫行                      # 尽行之
./全树测试。林檎。豫行 --列出               # 但列将行者
./全树测试。林檎。豫行 --分片 3/16          # 行第三片（凡十六片）
./全树测试。林檎。豫行 --只 库/豫章/      # 但行径首合此者
./全树测试。林檎。豫行 --验收 --只 库/结绳/   # 并验收之层而行之
```

`--分片` 与 `--只` 皆可更加 `--列出`；`--验收` 可与余参并用，位不拘。有不虞之败则退码一，否则零。

## 试之类与其断

试之清单出于 `git ls-files`，略 `_v0` 之目：

- **单元之试**（`X。测试。豫`）：以 `./豫构。林檎。豫行 文件 <径> --输出 …` 构而行之。退码非零，或所出有非零之“当前失败数：N”（单元测试之库每断必书），则为败。
- **但检**：规则表记为 `只检查` 之单元试（云工宿主、浏览器宿主须于其宿主行之），唯核其型，即 `./豫构。林檎。豫行 文件 <径> -- --type-check-only`。
- **金样**（`名其一。豫`、`名其二。豫`……配 `名。成功` 或 `名。失败`；号逐位书以汉字，如 `名其一零。豫`）：同组之中，不为他篇以“名其N之书”所引者，及 `名其一`，各为一试：
  - `。成功`：须构成、行成；标记非空，则常出去首尾之空后须与之同。
  - `。失败`：构或行须败；标记非空，则所出须含其文。
- **脚本之试**（`名。脚本。豫` 配同名之 `名。期望` 或 `名。成功`）：依二法各行一遍，皆须零退，常出去首尾之空后须与所期同（所期空则不校）：编译而行（如单元之试构而行之）；单元装载（`./豫构。林檎。豫行 运行 <径>`，装单元于豫构之身而行之，见提案〇〇〇〇三；Linux 之原生豫构暂编单元为 `.wasm` 交诺驿行之，原生装载待后版；用 `豫构.wasm` 则书为单元之目，以 `node 豫言操作系统/宿主/节点/宿主.cjs <目>` 装而行之）。无所期之文之脚本非试。
- **JS 之试**（`.test.mjs`、`.test.cjs`、`。测试.mjs`、`。测试.cjs`、`.e2e.mjs`）：`node --test --test-timeout=1800000 <径>`。
- **试页**（`。测试页.html`）须于实浏览器行之（浏览器之试页别有总验），属验收之层；带 `--验收` 则列为略。

每试行时以三十分为限：以趣使依秒强之，并以所用之时断其逾限；构不限时。构成之物置 `dist/全树测试/`，行毕即删。

## 验收之层

须命参、外产外材、实器实境之试，属验收之层，居常集之外，带 `--验收` 乃并行之；常行之首一行书验收之层另有几项。属验收之层者：

- 浏览器之试页；
- 规则表登为 `验收` 之试，注书其所须之境。

验收之层行于四处：

- 本机或开发之机手行：`./全树测试。林纳。豫行 --验收 --只 <径前缀>`，依注备境；
- CI 之「抽样验收层」之役：提交号末位为四、五之轮及手发者行之，行全量之轮（域名百万变异、模糊核验、正则模糊、简册变异、编码模糊、封套官方），及能以公数备齐之验收试（同文域名官方、简象消息包参考、云工持久对象壳、VS Code 语法高亮核验），其所取之源自书于规则表对应之注；
- CI 之「抽样 Wasm 包起步与诺驿验证」之役：构本轮之共核，乃行须产之验收试（共享传输控制回环、定位读取、实终端之尺寸）；
- 仍留手行者：声律流无损官方全集（约四百八十八兆，于本机或 pit-mac 手行）、方印原始照片与三参照图（由 ZXing 公样经仓内脚本而成，乃于本地行）、表册烟核（先于仓外构出表格字节.wasm）、起居注训练消费（须用手写数字训练所生之记）、普通探针数据盘（由普通豫言验证于备 KVM 之本机或自托管之机行）、进程资源（于 pit-mac 以林檎实进程行）、原生子程序桥（先备原生服务与试具之程乃行）。

能于常集行通之试（全量之目中不带参而能毕者亦然），皆留常集。费时之全量之试，常集以 `参数` 唯行其一分（如变试少行其轮），全量之全由抽样验收之役别行之。批模糊之驱所登者，仓内小种与小次也，新登之项于常集不逾一分。

## 规则表

`测试规则。数据。豫` 者，数据之文也，其顶层「全树规则」乃「规则」之录之列，每条书「类别」「路径」「说明」三域，如 `「规则」【「类别」者『跳过』也，「路径」者『库/甲/』也，「说明」者『须浏览器』也】`。径以 `/` 终者为前缀。入口编译时导入此表，增删其条，重构全树测试乃行。其类：

- `验收`：属验收之层，注书其所须之境（如实器、外材、豫言操作系统数据盘）。
- `诺驿`：单元之试或金样编为 `.wasm`，交诺驿宿主（`node 豫言操作系统/宿主/节点/宿主.cjs`）行之，`参数` 所登之参次于 `.wasm` 之后授宿主；用于唯诺驿宿主所实之接口（如试具之「边界回环」、诺驿东道之文件定位）。
- `只检查`：单元试唯核其型。
- `参数`：行单元试时所加之参，以空格为界（相对仓根）。
- `已知失败`：已登之败。败则报“已知失败”，不令 CI 败；若已成则报“意外通过”，促其出表。
- `只编译执行`：脚本之试唯编译而行，不行单元装载，注书其故（如探以己之程名为子程而复起）。

## 分片

`--分片 序/总` 依径序切为相连之段，同片之试多属一包，可共编译之缓存；诸片合之无重无漏。

## 维护

新增之试无须登记，自能寻得；唯须但检、加参、只编译执行、归验收之层或暂列已知之败，乃改规则表。试误则删之或正之，试是则修其码。改断之律，则同改此文与汉语之篇。
