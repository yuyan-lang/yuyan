# 全树测试

发现并运行整个仓库的测试，按统一规则判定结果，可按分片并行；CI 的「全树测试」矩阵作业逐片调用本工具。

## 用法

在仓库根目录运行（需先有原生豫构 `豫构。林檎。豫行`，也可用 `./豫构。林檎。豫行 目标 全树测试工具 -j 24` 造本工具）。仓库根有原生豫构 `豫构。林檎。豫行` 时，测试都由它编成本机原生程序直接运行；没有时（Windows 的原生工具链留待后续版本）退回 `豫构.wasm`，测试编成 `.wasm` 交诺驿宿主运行：

```sh
./豫构。林檎。豫行 构建 全树测试 --输出 全树测试。林檎。豫行 -j 24
./全树测试。林檎。豫行                      # 运行全部
./全树测试。林檎。豫行 --列出               # 只列出将运行的测试
./全树测试。林檎。豫行 --分片 3/16          # 运行第 3 片（共 16 片）
./全树测试。林檎。豫行 --只 库/豫章/      # 只运行路径以此开头的测试
./全树测试。林檎。豫行 --验收 --只 库/结绳/   # 连同验收层一起运行
```

`--分片` 与 `--只` 都可再加 `--列出`；`--验收` 可与其他参数并用，放在任何位置。有意外失败时退出码为 1，否则为 0。

## 测试的种类与判定

测试清单来自 `git ls-files`，忽略 `_v0` 目录：

- **单元测试**（`X。测试。豫`）：用 `./豫构。林檎。豫行 文件 <路径> --输出 …` 构建后运行。退出码非零，或输出里出现非零的“当前失败数：N”（单元测试库每次断言都会打印），即判为失败。
- **只检查**：规则表里标为 `只检查` 的单元测试（云工宿主、浏览器宿主须在对应宿主里运行）只做类型检查，即 `./豫构。林檎。豫行 文件 <路径> -- --type-check-only`。
- **黄金样例**（`名其一。豫`、`名其二。豫`……配 `名。成功` 或 `名。失败`；编号逐位写成汉字，如 `名其一零。豫`）：同组里没被其他文件以“名其N之书”导入的每一份，以及 `名其一`，各自作为独立用例：
  - `。成功`：必须构建、运行成功；标记文件非空时，去掉首尾空白后的标准输出须与它相同。
  - `。失败`：构建或运行必须失败；标记文件非空时，输出须包含它的文字。
- **脚本测试**（`名。脚本。豫` 配同名的 `名。期望` 或 `名。成功`）：按两种方式各跑一遍，都要零退出、且去掉首尾空白后的标准输出与期望相同（期望为空则不查）：编译执行（同单元测试那样构建后运行）；单元装载（`./豫构。林檎。豫行 运行 <路径>`，把单元装进豫构自己运行，见提案 00003；Linux 的原生豫构暂时把单元编成 `.wasm` 交诺驿运行，原生装载留待后续版本；用 `豫构.wasm` 时写成单元目录，由 `node 豫言操作系统/宿主/节点/宿主.cjs <目录>` 装入运行）。没有期望文件的脚本不是测试。
- **JS 测试**（`.test.mjs`、`.test.cjs`、`。测试.mjs`、`。测试.cjs`、`.e2e.mjs`）：`node --test --test-timeout=1800000 <路径>`。
- **测试页**（`。测试页.html`）须在真实浏览器里运行（浏览器测试页另有批量验证），属验收层；带 `--验收` 时列为跳过。

每个测试的运行时限为 30 分钟：有 `timeout` 命令时以它强制，并按用时判定超时；构建不限时。构建产物放在 `dist/全树测试/`，运行后即删除。

## 验收层

要命令行参数、外部产物与素材、真实设备或运行环境的测试属验收层，在默认集之外，带 `--验收` 时一起运行；默认运行的开头一行写明验收层另有几项。属验收层的有：

- 浏览器测试页；
- 规则表登记为 `验收` 的测试，说明写它要的环境。

验收层由四处运行：

- 本机或开发机手工：`./全树测试。林纳。豫行 --验收 --只 <路径前缀>`，按说明准备环境；
- CI 的「抽样验收层」作业：提交号末位是 4、5 的轮次与手动触发时运行，跑完整轮数（域名百万变异、模糊核验、正则模糊、简册变异、编码模糊、封套官方）和能用公开数据备齐的验收测试（同文域名官方、简象消息包参考、云工持久对象壳、VS Code 语法高亮核验），数据来源写在规则表对应规则的说明里；
- CI 的「抽样 Wasm 包起步与诺驿验证」作业：构建本轮的共享核后运行须产物的验收测试（共享传输控制回环、定位读取、真实终端尺寸）；
- 仍留手工的：声律流无损官方全集（约 488MB，在本机或 pit-mac 手工运行）、方印原始照片与三幅参照图（由 ZXing 公开快照经仓内脚本生成后在本地运行）、表册烟核（须先在仓外构建出表格字节.wasm）、起居注训练消费（须用手写数字训练生成的记录）、普通探针数据盘（由普通豫言验证在装有 KVM 的本机或自托管机上运行）、进程资源（在 pit-mac 上用林檎真实进程运行）、原生子程序桥（先备好原生服务与夹具程序再运行）。

能在默认集里跑通的测试（包括全量目录下不带参数就能跑完的）一律留在默认集。耗时长的全量测试在默认集里用 `参数` 只跑一部分（如变异少跑轮数），完整的全量由抽样验收作业另行运行。批模糊驱动登记的是仓内小种子与小次数，新登记的每项在默认集里不超过一分钟。

## 规则表

`测试规则。数据。豫` 是数据文件，顶层「全树规则」是「规则」记录的列，每条写「类别」「路径」「说明」三个字段，如 `「规则」【「类别」者『跳过』也，「路径」者『库/甲/』也，「说明」者『须浏览器』也】`。路径以 `/` 结尾时按前缀匹配。入口在编译时导入这张表，增删规则后重新构建全树测试即生效。类别有：

- `验收`：属验收层，说明写它要的环境（如真实设备、外部素材、豫言操作系统数据盘）。
- `诺驿`：单元测试或黄金样例编成 `.wasm`，交诺驿宿主（`node 豫言操作系统/宿主/节点/宿主.cjs`）运行，`参数` 一类登记的参数接在 `.wasm` 之后交给宿主；用于只有诺驿宿主才实现的接口（如测试夹具的「边界回环」、诺驿东道的文件定位）。
- `只检查`：单元测试只做类型检查。
- `参数`：运行单元测试时追加的参数，以空格分隔（相对仓库根目录）。
- `已知失败`：已登记的失败。失败时报告为“已知失败”，不使 CI 失败；若已通过则报告“意外通过”，提醒把它移出规则表。
- `只编译执行`：脚本测试只跑编译执行、不跑单元装载，说明写原因（如探针把自己的程序名当子程序再启动）。

## 分片

`--分片 序/总` 按路径顺序把测试切成连续的若干段，同一片内的测试多属同一包，可以共用编译缓存；各片合起来不重不漏。

## 维护

新增测试无需登记，会被自动发现；只有需要只检查、附加参数、只编译执行、归入验收层或暂列已知失败时才改规则表。测试错了就删去或改正，测试对就修代码。修改判定规则时同步更新本说明与文言版。
