# 吉特

吉特是用豫言写成的吉特（Git）命令行程序，克隆、提交、合并、推送等操作都由它自己完成，不调用外部 git。仓库格式与 git 一致：松散对象、包文件与第二版包索引、第二版索引文件、引用与打包引用、配置文件、链接工作树都按 git 的格式读写，同一个仓库可以交替使用 git 与吉特。功能写在库「稽古」里，本包解析命令行并调用它。

## 用法

    吉特 [--仓库 目录] [--凭据 文件] 子命令 [选项…] [参数…]

`--仓库` 缺省为当前目录，可以是工作树里的任何子目录，也可以是链接工作树。命令成功时退出码为零；失败时退出码非零，并在标准错误写明原因。`吉特 帮助` 打印完整用法。

| 子命令 | 作用 |
| --- | --- |
| `状态 [--不含未跟踪]` | HEAD、暂存区、工作区三方比较，格式同 `git status --short`，首行写当前分支 |
| `差异 [--暂存] [修订 [修订]] [-- 路径…]` | 统一格式差异：不给修订时比较暂存区与工作区，`--暂存` 比较 HEAD 与暂存区，一个修订比较它与工作区，两个修订比较两棵树 |
| `暂存 路径…` | 暂存改动、新文件与删除；`.` 或 `-A` 表示全部 |
| `撤销暂存 [路径…]` | 暂存区恢复成 HEAD 的内容，工作区保持原样 |
| `提交 -m 消息 [-a] [--允许空]` | 提交暂存区；`-a` 先暂存全部已跟踪文件的改动 |
| `历史 [修订] [-n 条数] [--单行\|--oneline] [--since 日期]` | 按提交时间倒序列出历史；`--since` 只要提交时间不早于该日期的提交，日期写 `2026-10-19` 或 `2026-10-19 10:30` |
| `列卷` | 列出受控文件（暂存区里的路径），同 `git ls-files`，路径原样印汉字 |
| `查看 [修订 或 修订:路径]` | 提交说明与差异，或某个版本里的文件内容 |
| `分支 [名 [起点]]`、`分支 -d 名`、`分支 -D 名` | 列出、新建、删除分支；`-d` 只删已并入当前 HEAD 的分支，`-D` 强制删除 |
| `合并基 甲 乙`、`合并基 --is-ancestor 甲 乙` | 两个提交的最近共同祖先；`--is-ancestor` 只以退出码答甲是否为乙的祖先（0 是、1 否），不打印合并基 |
| `切换 分支`、`切换 -c 新分支 [起点]`、`切换 --分离 修订` | 切换分支，会覆盖本地改动时停下，`--强制` 丢弃这些改动；本地没有而 `origin` 有同名分支时，自动建立跟踪它的本地分支 |
| `合并 分支 [--不快进] [-m 消息]`、`合并 --放弃` | 能快进时快进，否则三方合并；`--不快进` 总是生成合并提交 |
| `变基 上游`、`变基 --继续`、`变基 --跳过`、`变基 --放弃` | 把当前分支独有的提交逐个重放到上游之上 |
| `工作树 新增 路径 [分支] [-b 新分支] [--起点 修订] [--分离]`、`工作树 删除 路径 [--强制]`、`工作树 列出` | 管理链接工作树，与 `git worktree` 互通 |
| `克隆 网址 [目录]` | 经 HTTPS 克隆 |
| `拉取 [远端] [--只取]` | 取回远端的新对象、更新远端跟踪分支，再合并上游；`--只取` 只更新远端跟踪分支 |
| `推送 [远端] [规格…] [--强制]` | 推送分支；规格写 `名`、`本地:远端`，或 `:远端` 删除远端分支 |

提交的作者与提交者取环境变量 `GIT_AUTHOR_NAME`、`GIT_AUTHOR_EMAIL`、`GIT_COMMITTER_NAME`、`GIT_COMMITTER_EMAIL`，没有时取配置 `user.name` 与 `user.email`。时区取环境变量 `时区`（如 `+8`、`+05:30`），其次取 `TZ` 里 `UTC+8` 一类的写法，都没有时写 `+0000`。

## 冲突

合并遇到冲突时，吉特把冲突文件写成带 `<<<<<<<`、`=======`、`>>>>>>>` 标记的形式，在 `.git` 里写下 `MERGE_HEAD` 与 `MERGE_MSG`，列出冲突文件并停下。改好文件后用 `吉特 暂存 文件…` 标记已解决，再 `吉特 提交`（不给 `-m` 时用合并说明作消息）；`吉特 合并 --放弃` 回到合并前的状态。

变基遇到冲突时同样停下。改好并暂存后用 `吉特 变基 --继续`；`--跳过` 丢下当前这个提交；`--放弃` 回到变基前的分支与提交。变基的进度记在 `.git/吉特变基` 里，期间 HEAD 处于分离状态。

## 克隆、拉取与推送

网址写 `https://主机/路径`，如 `https://github.com/yuyan-lang/yuyan.git`。克隆与拉取走智能 HTTP 第二版协议：克隆取回全部分支与标签，把包文件与包索引写进 `.git/objects/pack`，建立远端 `origin` 与远端跟踪分支，检出远端的缺省分支；拉取告诉远端本地已有哪些提交，只收取缺少的对象。推送走 receive-pack：算出远端缺少的对象，打成包发送，再按远端的回报逐条打印引用的更新结果。远端分支无法快进时推送停下，`--强制` 时照样更新。

## 令牌

推送需要令牌，克隆与拉取私有仓库时也需要。吉特依次查找：

1. 环境变量 `吉特令牌`；
2. 凭据文件：`--凭据 文件` 指定的文件，缺省为 `/系统/吉特/凭据`（豫言操作系统里的位置）。文件每行写一个令牌，或写“主机 令牌”（如 `github.com 令牌内容`）；带主机的行优先，用于网址主机相同的仓库；空行与 `#` 开头的行略过。

令牌经 HTTP 基本认证发送（用户名 `x-access-token`，密码为令牌），GitHub 的个人访问令牌可以直接使用。吉特的任何输出都不含令牌。

## 构建

    豫构 构建 吉特 --输出 吉特。林檎。豫行 -j 24

在豫言操作系统里运行时编成豫行：

    豫构 构建 吉特 --输出 吉特。豫行 -j 24 -- --目标 本机 --目标系统 豫言 --目标架构 兼容六十四 --执行器 <仓根>/执行器。树码

## 性能

在本仓（约一万一千五百个文件、十三万个对象、一亿八千万字节的包）上，林檎臂六十四原生实测：工作区干净时 `状态` 约 0.5 秒；经 HTTPS 整仓克隆约 193 秒，时间主要花在 HTTPS 传输上。索引为每个文件记下修改时间，修改时间相同且早于索引写入时刻的文件直接沿用记下的散列。克隆时吉特自己生成包索引，内容与 `git index-pack` 生成的逐字节相同。
