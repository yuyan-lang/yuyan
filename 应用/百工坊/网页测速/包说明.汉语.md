# 网页测速

离线、可重复的浏览器性能基准。一页连同全部子资源先录进一个「浏览久存」的资料目录，此后回放只读册子、不联网，量出来的数不随网速与本机负载抖。分段报单调微秒、CPU 时间（用户与内核分开）、分配字节、读资次数与耗、常驻峰值，以及豫言回收统计的分配总字节与峰值堆；另有滚动基准、一页一行的汇总命令与两份结果逐段对比的工具。

## 怎么录

先联网录一页：

```
豫构 构建 网页测速 --输出 网页测速。林檎。豫行
./网页测速。林檎。豫行 录 github https://github.com/ 1280 800
```

录制时浏览器用的抓取交换是「尺素」的同步取驿地址：主文档、样式表、脚本、图像与 `@font-face` 字体都经它取回，每一件二零零的 GET 响应连状态、首部与解压后的正文一起写进资料目录（索引 `缓存。数据。豫`，正文 `缓存体/` 下的帛，与浏览器磁盘缓存同一个册子）。录完当场以放的方式再载一遍核对：主文档栽不成的、有资源没录上的都报出来并以非零退出，先补齐再量。

录好的页放在测速页根下，每个页一个目录：

- 缺省根是 `/Users/zc/repos/yuyan-worktrees/豫言数据/网页数据/测速页`，环境变量 `豫言测速页` 可以改；换机器时设这个变量或同步这个目录。
- 每个页目录里另有 `页。数据。豫`，记名字、网址、视口宽高、录制时刻（纪元秒）、资源数与总字节。

`列` 打出已录的页与它们的资源数、总字节。

## 怎么跑

```
./网页测速。林檎。豫行 量 github 3 0
```

`量` 起三个子程，每个子程载一页一次（放的方式，不联网），取每段的最小值写成 `结果/github。数据。豫`；第四个参数是存名，可以写成 `量 github 3 0 改前` 存成 `结果/改前。数据。豫`。子程印出来的段表有十二段：解析、预取、脚本、读样、样源、读记、盒树、量树、布局、成组、映列、栅格。每一行六栏：段名、单调微秒、CPU 用户微秒、CPU 内核微秒、分配字节（另有一栏留给以后）；另有 `测速首屏`（第一版页面图出来的时刻）、`测速总`（载完）、`测速用`（整页的 CPU 用户、内核微秒与分配字节）与读资（读回了几件、合计多少微秒）。另有 `测速误	脚本	<N>` 一行：这一页的页脚本报出诊断的处数（加载、编译或执行被接住的每一支都算一处，脚本载里「网页脚本：地址：诊断」那条就是它）。脚本报错的页面，脚本段的微秒再好看也代表不了脚本真的跑通了——所以它单列一行，不和十二段混在一起比。

CPU 与分配两列取自宿主原语 313「问己时」与 314「问己配」：载入时间线在每一段收尾时同时记下当时的单调微秒与这两个累计数，两刻相减就是这一段用掉的处理器时间与分配字节——所以它们不受别的任务抢占与配时的影响，跟墙钟微秒互为对照。取不到这两个数的宿主（诺驿、浏览器、云工、裸机的 CPU）报负一，相减后记零。

**要新执行器**：原语 313、314 是本轮（2026-10-28）新加的，旧的执行器里没有这两条，用它量出来的 CPU 与分配两列全是零。工作树里编：

```
豫构 构建 客体二号 --输出 执行器新。树码
豫构 构建 网页测速 --输出 网页测速。林檎。豫行 -- --执行器 $PWD/执行器新。树码
```父程另收子程的常驻峰值字节，并从标准错误里取豫言回收统计那一行的分配总字节与峰值堆——要这两个数就带上环境变量：

```
env 豫言回收统计=1 ./网页测速。林檎。豫行 量 github 3 0
```

量一页的性能，机器的负载会影响墙钟；回放本身是纯算的（没有网络等待，只有读册与读体），所以取三轮的最小值即可比出快慢。要看进程 CPU 时间，用本机的时间工具跑同一条命令：

- 林檎：`/usr/bin/time -l ./网页测速。林檎。豫行 量 github 3 0`（末段最大常驻内存与用户／系统 CPU 时间）
- 林纳：`/usr/bin/time -v ./网页测速。林纳。豫行 量 github 3 0`

滚动基准：

```
./网页测速。林檎。豫行 滚 github 30
```

载一页后连滚三十帧，每帧四十像素，一帧印一行 `测速滚`、帧号与微秒。滚动走的是浏览器的那一条滚动重绘路（「舒卷重绘网页盒页」）：平移上一帧的页面图、只重画露出的条带、右栏与向上滚时的底条，不整页重排重栅。

## 一页一行

```
./网页测速。林檎。豫行 总 github 30
```

载一页、滚三十帧（第二参缺省三零），把首屏、载完、峰值内存、CPU 用户与内核、分配字节、滚动帧数、中位与最慢一帧压成一行印出，例如：

```
github｜首屏 1234567 微秒｜载完 4469144 微秒｜峰值内存 3428 MiB｜CPU 用 4900000 系 630000 微秒｜分配 1431013720 字节｜滚动 30 帧 中位 265619 最慢 451994 微秒
```

要给别的路（例如各路性能优化的人）一条现成的命令，就用这一条：一页一行，抄进报告不用再算。

## 怎么比

```
./网页测速。林檎。豫行 比 结果/改前。数据。豫 结果/改后。数据。豫
```

逐段打出旧值、新值与变化的百分比，再打总时、峰值内存、分配字节、峰值堆与读资的变化。同一台机器上新旧交替各跑三遍取最小，一条命令即可：

```
for i in 1 2 3; do ./网页测速。林檎。豫行 量 github 1 0 改前; ./网页测速。林檎。豫行 量 github 1 0 改后; done
```

## 录制回放的开关

抓取交换的录放开关在「抓取」的「录放」一处：环境变量 `豫言录放` 取 `录` 或 `放`，`设录放` 也可以直接设；空串是关（照旧走磁盘缓存与网络）。浏览器的资源读取与量具共用这一处，所以浏览器也能整页录放：

```
env "豫言录放=录" ./浏览器。林檎。豫行 https://example.com/
```

## 各段的含义

- 解析：读主文档、嗅编码、解析文档、套响应头，到文档成形。
- 预取：扫出脚本、样式表与图像外链，按来源取回（回放时是读册与读体），再把样式表里的 url() 与 @font-face 展开再取一遍。
- 脚本：按文档顺序执行不置后的脚本、延后与模块脚本，每项后过微任务检查点。
- 读样：读样式表、解码，到样式资源成形。
- 样源：把用户代理样式与文档里的样式合成样式源。
- 读记：建样式读者（选择器索引与级联的入口）。
- 盒树：由文档与样式读者生成盒树（含样式匹配与级联）。
- 量树：把每个盒选中字体的上升、下降、行距写进计算样式。
- 布局：块流、行盒与定位。
- 成组：生成绘制组（裁剪、图层、内容图）。
- 映列：生成显示列表。
- 栅格：把绘制组栅格成页面图。

样式的匹配与级联在盒树一段里，尚未细分；这一层要细分得由样式引擎自己记段刻。

## 量法的边界

- 段表里的微秒是墙钟（单调时钟），CPU 两列是进程累计处理器时间，两者之差就是这段时间被别的任务抢走或等待的部分。
- 分配字节是执行器回收堆的口径（每次回收把这一轮的分配计并进累计），只增不减；它数的是**分配**，不是活着的字节。
- 「脚本误」是计数不是时长：一页有几支脚本没过。它大于零时，脚本段与依赖脚本产出的段（布局、成组、栅格）都不可与脚本全过的页直接比。
- 「首屏」是本工具的口径：同步整页载入里第一版页面图出来（排绘毕）。浏览器异步管线的首屏（脚本之前那一版）不在这一次载入里，两者不可直接比。

- 量的是「接引」的整页载入（脚本执行一次、排最后的版），不是浏览器异步载入的首屏与分批重绘；浏览器的异步载入要窗口与显示面，本工具不要窗口。
- 回放时字体从录里取：`@font-face` 外链的字体在录制时已经取回并存进册子。
- 结果里的分配字节与峰值堆来自豫言回收统计，是执行器回收堆的口径，不是进程常驻内存；后者看峰值内存。

## 基准表（2026-10-29，pit-pc 林纳 x86-64，回放，1280×800）

四栏同一条 `总 <页> 0` 的汇总行取：墙钟是「载完」微秒，CPU 是「用/系」两数，分配来自「问己配」（累计分配字节），峰值内存来自「问使」。

| 页 | 资源 | 墙钟 | CPU 用 | CPU 系 | 分配 | 峰值内存 | 滚动 |
|---|---|---|---|---|---|---|---|
| guanwang（https://yuyan-lang.org/） | 30 件 | 9.31 秒 | 9.09 秒 | 0.13 秒 | 167.8 MiB | 582 MiB | 30 帧中位 0.44 秒、最慢 1.17 秒 |
| 维基（https://zh.wikipedia.org/wiki/Wikipedia:首页） | 60 件 | 110.43 秒 | 109.64 秒 | 0.53 秒 | 621.5 MiB | 1552 MiB | **30 帧中位 5.95 秒、最慢 11.26 秒**（前 5 帧均 1.83 秒，后 5 帧均 9.84 秒；3 帧时中位 1.73 秒） |
| github（https://github.com/） | — | 录不下来（见下） | — | — | — | — | — |

- **维基**：录制时「资源 60 件、字节 2,868,536，放一遍自册读回 60 件、未录 0」。载一页 110.43 秒（早前一轮 94.10 秒，机器负载不同），CPU 合计 110.17 秒，几乎全是算、没在等；分配 621.5 MiB。
- **github**：录制跑到 40 分钟限时被杀（退出码 124）。页脚本当场抛五处错——`environment-…js`「类的父类的 prototype 须是对象或 null」两处、`behaviors-…js` 与 `marketing-essentials-…js`「对象操作需要有值的接收者」、`landing-pages-…js`「需要构造函数」——载入不返回，段表出不来。这不是量具的问题，是引擎对 github 那套脚本的兼容缺口；录不下就先不列数。
- **峰值内存已在林纳上修好（2026-10-29）**：执行器每次采到运行中的子进程，就把它的 VmHWM 记进异步表项（+56 为「记过峰」标记、+64 起八字节为迄今最大者），子进程退出后再问，答的是退前最后一刻的峰；表项里没记过峰时答「误」（缘由「未可观」），不再答「成」带零。
- **维基的滚动（30 帧实测）**：合计 202.7 秒，中位 5.95 秒、最慢 11.26 秒；**每帧随滚动递增**——前 5 帧均值 1.83 秒、后 5 帧均值 9.84 秒，前半程 3.74 秒、后半程 9.78 秒。载入本身 76.9–98.6 秒，贵在布局（49.8 秒）与成组（33.3 秒）；每帧贵在像素合成（`测滚一帧` 占在栈 58.4%，其中合成相关栈顶约 23%）。剖析与栈采样见 `维基滚动剖析.汉语.md` 与 `维基滚动采样汇总.txt`。
- **`豫言测速限秒`**（2026-10-29 加）：轮询子进程的预算，单位秒，每步让二十毫秒，缺省 180 秒即九千步；维基载一页就一百多秒、30 帧再要两百秒，量它请写 `--环境 豫言测速限秒=600` 以上并避开机器高峰。
