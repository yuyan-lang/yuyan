# 豫言试写间

浏览器中编辑豫言、请求 AI 编写或修改代码、在 Cloudflare Container 中编译运行。
默认使用 DeepSeek 官方 API。浏览器不持有模型密钥。

已上线：[豫言试写间](https://playground.yuyan-lang.org)。Pro 工具版通过 19 项本地测试、4 项 Linux 容器集成测试、Wrangler 配置检查和仓库编译器类型检查。线上九九乘法表由模型主动调用运行工具，一次编译运行成功；递归六的阶乘任务在标准库查询纠正后，调用运行工具输出 720。模型响应确认使用 `deepseek-v4-pro`，完整调用与诊断通过实时事件流返回浏览器。


## 对话与调试日志

右侧运行结果中有独立的“编译器日志”区域，默认隐藏，旁边的“隐藏／显示”按钮可切换。生成或运行时，编译阶段进度和 stdout/stderr 会实时显示在这里；每次新请求重新开始计数。下方完整日志仍保留本页的全部请求记录。

页面下方的“对话与调试日志”默认折叠，可点击标题隐藏或显示。它实时记录浏览器提交内容、范围判断、每轮完整模型消息与回复、编译 stdout/stderr、自动修复及运行输出。日志只属于当前请求的调用者；本页的多次请求记录会保留，刷新后清空，不主动写入服务器日志或浏览器持久存储。

请求使用 `Accept: application/x-ndjson` 获得实时事件流；不指定时仍返回原有 JSON 结果。编译过程保持 64 KB 输出限制。网络中断后保留已经收到的日志；慢连接积压超过上限时明确提示部分日志省略。认证标头和 secret 不进入日志，上游若回显实际密钥会由 Worker 抹去。

本次验证预算用尽时，返回具体诊断和最后一版待修复稿，日志保持用户选择的展开状态；未经编译验证的稿件不会自动应用到编辑器。模型协议依旧限制为豫言编程，调试区按用户要求展示原始往来内容，便于检查生成错误和拒绝原因。

## 架构

浏览器 → Worker（静态页面、请求校验、全站与访客额度）→ Container（AI 助写流程、编译调度）→ 每次请求独立的 Bubblewrap 隔离空间。

容器内的助写流程通过 `model.internal` 访问 Worker 出站代理；Worker 注入 DeepSeek secret，目标地址固定为官方 API。模型权重不部署在容器中。
生成过程使用 `deepseek-v4-pro`：先独立判断请求范围，再开启 high 思考模式，最多六轮编写与工具调用，最多六次编译运行、十二次工具调用，总时限八分钟。48 个标准库模块的 651 条公开签名与四个已验证示例进入上下文；模型可调用 `query_library`、`read_example`、`compile_yuyan`、`run_yuyan`。工具结果及 API 返回的 reasoning_content 随对话保留。最终源码必须与验证通过的源码一致，否则重新编译。累计 token 超过 250000 后停止后续调用；这是应用层软预算，不是供应商账单硬限额。不提供通用聊天接口、终端工具或用户自定义模型/系统提示词。

镜像提前编译可信标准库，每个请求复制一份固定缓存到私有工作目录；访客生成的缓存从不回写镜像或传给其他访客。编译器固定调用的 `make yy_runtime_lib` 由只读构建规则检查预构建运行库，无需每次重新构建运行时。

“只接受豫言请求”是产品策略，不是可证明的语义保证。分类器可能被诱导，合法豫言也能在字符串或注释中包含其他内容。编译通过只证明源码可编译，不能证明请求主题合规。当前使用独立分类、固定输出结构、编译门禁及费用上限降低风险，必须结合真实模型攻击测试评估。

## 本地验证

在本目录执行 `npm ci`、`npm test`、`npm run 检查配置`。
在仓库根目录构建镜像：

```sh
docker build --platform linux/amd64 --provenance=false -f 应用/豫言体验/容器构建文件 -t yy-playground:local .
docker run --rm --init --platform linux/amd64 --security-opt seccomp=unconfined -p 127.0.0.1:8080:8080 yy-playground:local
```

启动时必须通过 Bubblewrap namespace 自检。不支持嵌套 user namespace 的宿主会拒绝启动；不得删去隔离选项或回退为直接执行。这里的 Docker Desktop 默认 seccomp 拒绝 namespace 创建，因此本地测试命令允许 Bubblewrap 创建 namespace；用户代码仍在 Bubblewrap 的完整隔离中执行，且不挂载 `/proc`。仅在专用测试容器中使用该参数，不挂载私密宿主目录。Cloudflare 上是否支持这些能力须通过实际部署验证，不能由本地 Docker 测试推定。

## 配置与部署

`发布配置.jsonc` 记录已上线的账户和固定镜像摘要，`ENABLED=true`。`云端配置.jsonc` 用于从源码重新构建，默认 `ENABLED=false`，避免尚未验证的改动直接接受公开代码。更新容器代码后须重新构建、验证和上传镜像，再更新发布配置中的摘要。

在本目录使用 Wrangler 的交互 secret 输入，不把密钥写入源码、命令行参数或聊天：

```sh
npx wrangler secret put DEEPSEEK_API_KEY --config 发布配置.jsonc
npx wrangler deploy --config 发布配置.jsonc
```

开放前先验证云端隔离和实际编译运行，再将 `ENABLED` 设为 `true` 并重新部署。需要 DeepSeek 账户有可用余额，Cloudflare 账户启用 Workers Paid 和 Containers。

首次按本地 OCI 索引上传时出现 `blob unknown`，改为 `linux/amd64` 单架构清单后上传成功。若手动上传现有索引镜像，可使用 `docker push --platform linux/amd64 <镜像地址>`。当前镜像摘要见 `发布配置.jsonc`。应用层更新可复用已验证编译器镜像，复制新应用源码后重新验证。更新镜像时使用 `--containers-rollout immediate` 并验证实际响应，避免仅更新页面而实例仍运行旧服务。

`RUNNER_RELEASE` 标识本次容器池版本。镜像升级后若旧身份仍返回旧服务，更新此值可创建新身份；实例总数仍受 max_instances=2 限制。新身份首次请求可能返回冷启动提示，稍后重试。上线验证必须看到“已加载 48 个标准库模块、651 条公开签名”的事件和 Pro 工具轮次，不能只检查 Worker 状态中的型号。

默认两台 standard-1 容器，空闲一分钟休眠。每个容器同一时间处理一个请求，繁忙时返回稍后重试。每次编译运行清理私有工作目录，不复用访客缓存。编译时限 30 秒，运行时限 5 秒，单阶段输出 64 KB，地址空间 2 GiB，单文件 32 MiB，进程数 32。容器内 namespace 切断用户代码到网络、AI 代理和服务进程的访问；Bubblewrap 不挂载服务源码或密钥。

默认全站每天 100 次助写、1000 次手动运行；每个 IP 每天 10 次助写、50 次运行，每分钟总计 6 次。AI 内部验证与修复包含在一次助写内。额度按 UTC 日期更新，失败/繁忙请求也计数。IP 哈希用于限制滥用，不代表匿名化；共享出口用户共享额度。该限制不是身份认证，不能阻止分布式滥用，但全站限额仍生效。源码和提示词不主动持久化，模型提供商仍会接收它们。

## 助写知识维护

`标准库签名导出。豫` 复用编译器类型检查结果，导出标准库全部模块中的公开声明，包含别名和推导类型。标准库变更后，在仓库根目录重新生成目录，再验证示例并重建容器：

```sh
./yy_bs_stable 应用/豫言体验/标准库签名导出。豫 -o /tmp/yy标准库签名导出 --no-debug-print
/tmp/yy标准库签名导出 应用/豫言体验/知识/标准库签名.json
```

四个示例覆盖函数分支、列表匹配、递归求和和嵌套递归乘法表。`npm test` 检查连续工具调用、诊断回传、工具参数边界及最终源码重新验证；Linux 容器测试还逐一编译运行全部示例。

当前已改用 Pro。上述 Flash 价格仅供原方案比较，不能用于估算 Pro 助写费用；完整签名上下文及多轮工具调用会增加输入 token，用量可在模型接收日志的 usage 字段查看。
