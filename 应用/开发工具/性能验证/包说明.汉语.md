# 性能验证

按登记表运行基础库的性能入口，比较原生与诺节的耗时。每个入口先构建成 `.wasm`，经诺节运行一遍，再预编译成本机原生可执行文件运行一遍；两边输出里同一个标签的耗时相比，原生慢过容差（默认 1.25 倍）时，打印一条汇总的 GitHub 警告（`::warning`），并把对比表写进作业摘要。作业始终以零退出，达标不作门槛。

这是提案 00004「共用基础库」性能验证在 CI 里的落地，也把提案 00007 议五“原生都不慢于 Node”的度量延伸到库的基准。提案 00008 设想把结果上传到包管理器长期展示，目前暂缓，这里只发警告。

## 用法

先在仓库根目录运行「全部」，它会生成 `yy原生生成.wasm` 与 `yy执行器.wasm`（以及原生工具链）。然后：

```sh
./yy豫构.exe 构建 性能验证 --输出 yy性能验证.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy性能验证.wasm                       # 运行全部入口
node 豫言操作系统/宿主/节点/宿主.cjs yy性能验证.wasm --基准提交 提交号     # 只运行相对该提交有改动的入口
node 豫言操作系统/宿主/节点/宿主.cjs yy性能验证.wasm --列出               # 只列出将运行的入口
node 豫言操作系统/宿主/节点/宿主.cjs yy性能验证.wasm --容差 150 -j 8      # 容差 1.50 倍，构建并发 8
```

没有原生工具链（`yy豫构.exe`、`yy4_bs.exe`）时，构建改用 Node 上的豫构；缺 `yy原生生成.wasm` 或 `yy执行器.wasm` 时，打印一条警告并跳过。

## 登记表

`性能目标.tsv` 每行以制表符分栏，空行和以 `#` 开头的行忽略。两种行：

- `全局　前缀们`：改动这些路径时所有入口都运行。登记了工具链、标准库和本工具自身的路径。
- `入口　名称　源文件　关注前缀们　参数组们`：一个性能入口。关注前缀用空格分隔，是这个入口依赖的包目录；参数组用竖线分组、空格分词，每组参数运行一次，省略则运行一次不带参数。更后的栏是说明。

## 选包

没有 `--全部` 时，工具用 `git diff --name-only <基准提交> HEAD` 取改动文件，运行改动落在“全局前缀”或入口自己关注前缀下的入口。基准提交来自 `--基准提交`，也可来自环境变量 `YY_PERF_BASE`；它为空、全是零（分支新建）或取不到改动文件时运行全部入口。CI 在推送时传入 `github.event.before`，手动触发时运行全部。

## 耗时结果的提取

入口的标准输出里，数字紧跟在 `：` 或 `=` 之后，数字之前（自行首或上一个结果之后）的文字含“秒”而不含“每秒”时，这个数字就是耗时结果，那段文字是它的标签。一行里可以有多个结果，结果之间不必有空白。数字之前的其他数字（如 `次数=20`）并入标签。诺节与原生输出里标签相同的结果两两配对，比值与单位无关。

已接入的入口都满足这个形式，新入口按它打印即可。

## 判定与警告

比值是原生耗时占诺节耗时的百分数。超过容差判为“慢”，低于一万除以容差判为“快”，其余为“相当”。作业里：

- 有“慢”的项时，打印一条 `::warning title=性能验证::…`，写出慢的项数、总项数和最慢的三项。
- 有入口构建或运行失败、超时、没有可比结果时，另打印一条 `::warning title=性能验证::…` 汇总失败说明。
- 设了 `GITHUB_STEP_SUMMARY` 时，把对比表和失败说明写进作业摘要。
- 每个结果另打印一行 `基准记录`（制表符分隔：入口、标签、诺节值、原生值），便于日后转换成提案 00008 的记录格式。

单次运行限时 300 秒（有 `timeout` 命令时强制），整个工具预算 1500 秒，超出后剩下的入口记为未运行。

## CI

`.github/workflows/main.yml` 的“Wasm 包起步”作业在 Linux x64、Linux arm64 与 macOS 上，于“原生与 Node 性能对比”之后运行本工具。步骤带 `continue-on-error`，只在推送与手动触发时运行。

## 测试

`核心。测试。豫` 覆盖登记表解析、耗时结果提取、配对、比值与判定、选包：

```sh
./yy豫构.exe 文件 应用/开发工具/性能验证/核心。测试。豫 --输出 yy性能验证核心测试.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy性能验证核心测试.wasm
```

全树测试自动发现它。
