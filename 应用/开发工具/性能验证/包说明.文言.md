# 性能验证

依登记而行基础库之性能入口，较原生与诺节之耗时。每入口先构为 `.wasm`，诺节行一遍，复预编为本机原生之可执行而行一遍；二侧所出同标之耗时相较，原生逾容差（默认一又四分之一倍）者，书一条 GitHub 之警（`::warning`），并书对比之表于作业之摘要。作业恒以零退，达标不为门槛。

此提案 00004「共用基础库」性能验证于 CI 之落地，亦提案 00007 议五“原生皆不慢于 Node”之度，推及于库之基准。提案 00008 欲上传其果于包管理器以久示之，今暂缓，此惟书警。

## 用法

先于仓根行「全部」，以生 `yy原生生成.wasm` 与 `yy执行器.wasm`（及原生之器）。乃：

```sh
./yy豫构.exe 构建 性能验证 --输出 yy性能验证.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy性能验证.wasm                       # 行其全
node 豫言操作系统/宿主/节点/宿主.cjs yy性能验证.wasm --基准提交 提交号     # 但行相对该提交有改之入口
node 豫言操作系统/宿主/节点/宿主.cjs yy性能验证.wasm --列出               # 但列将行者
node 豫言操作系统/宿主/节点/宿主.cjs yy性能验证.wasm --容差 150 -j 8      # 容一又二分之一倍，构建并发八
```

无原生之器（`yy豫构.exe`、`yy4_bs.exe`）则构建改用 Node 上之豫构；缺 `yy原生生成.wasm` 或 `yy执行器.wasm` 者，书一警而止。

## 登记

`性能目标.tsv` 每行以制表分栏，空行与井号起首者略之。二种行：

- `全局　前缀们`：所改在此诸径，则诸入口皆行。载工具链、标准库与本器之径。
- `入口　名称　源文件　关注前缀们　参数组们`：一性能入口。所关之前缀以空格分，乃此入口所依之包目；参数之组以竖线分，各组以空格断词，每组行一次，省则行一次而无参。更后之栏为注。

## 择入口

无 `--全部` 者，以 `git diff --name-only <基准提交> HEAD` 取所改之文，行所改在“全局前缀”或入口自关之前缀下者。基准提交取自 `--基准提交`，亦可取自环境变量 `YY_PERF_BASE`；空、皆零（新分支）或不得所改之文者，行其全。CI 于推送时传 `github.event.before`，手发则行其全。

## 取耗时之果

入口标准输出之中，数紧随 `：` 或 `=` 之后，数前（自行首或上一果之后）之文含“秒”而不含“每秒”者，其数即耗时之果，其文即其标。一行可有多果，果间不必有空。数前别有之数（如 `次数=20`）并入标。诺节与原生所出同标之果两两相配，比与单位无涉。

已入之入口皆合此式，新入口依此式书之即可。

## 断与警

比者，原生之耗为诺节之耗之百分几。逾容为“慢”，不及万除容为“快”，余为“相当”。作业之中：

- 有“慢”者，书一条 `::warning title=性能验证::…`，言慢者之数、总数与最慢三项。
- 有入口构建或运行失败、逾时、无可比之果者，别书一条 `::warning title=性能验证::…` 以汇其败说。
- 设 `GITHUB_STEP_SUMMARY` 者，书对比之表与败说于作业之摘要。
- 每果另书一行 `基准记录`（以制表分：入口、标、诺节之值、原生之值），以便日后转为提案 00008 之记录式。

单次所行限三百秒（有 `timeout` 者强之），全器之算一千五百秒，逾则余者记为未行。

## CI

`.github/workflows/main.yml` 之“Wasm 包起步”作业，于 Linux x64、Linux arm64 与 macOS，在“原生与 Node 性能对比”之后行此器。此步带 `continue-on-error`，惟推送与手发时行之。

## 验

`核心。测试。豫` 覆盖析登记、取耗时之果、配对、比与断、择入口：

```sh
./yy豫构.exe 文件 应用/开发工具/性能验证/核心。测试。豫 --输出 yy性能验证核心测试.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy性能验证核心测试.wasm
```

全树测试自发现之。
