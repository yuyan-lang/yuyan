# 网页一致性

本工具整理提案 00009 的官方数据，并运行官方测试集。

## 命令

- `字符引用 原始结森路径 输出源码路径`：读取网超组的命名字符引用表，生成完整名称及码点列表。输出使用中文标识符，保留带分号及历史无分号的名称。原始数据放仓外，生成源码入库。
- `超文本词法 测试文件或目录`：运行超文本5库测试的词法数据（tokenizer 的 `.test` 文件），每个用例按各初始状态各跑一遍，比较词元流与错误码。
- `超文本构树 测试文件或目录 [失败详情上限]`：运行超文本5库测试的树构造数据（tree-construction 的 `.dat` 文件）。每个用例解析源码（整页，或 `#document-fragment` 指定上下文元素的片段），把结果树按标准的转储格式与期望比较，不比较错误列表；`#script-on` 的用例以脚本开启的标志解析，脚本本身不执行。逐文件报告通过数，末尾给出合计；失败详情默认最多打印 30 条，第三个参数可以改。
- `超文本编码 测试文件或目录`：运行超文本5库测试的编码数据（encoding 目录的 `.dat` 文件）。每个用例把 `#data` 当作字节流，依次做字节序标记、前一千零二十四字节的预扫描和整流预扫描，得不到编码时按缺省的 windows-1252，与 `#encoding` 不分大小写比较。

## 期望表

`树构造期望表。豫` 登记已知不通过、不算失败的用例：文件名、原因（过时或待办）和用例序号（从一数起，按文件里的次序）。名字以 `scripted_` 开头的文件需要真正执行脚本，整个计入跳过。期望表里的用例不运行，计入跳过。

官方测试运行器的其余部分（期望表比较的增量报告）列入本任务后续实施；参照图运行见下文“网平测参照测试”。

## 捷思脚本运行与验收

- `捷思运行 脚本文件`：把一个 `.mjs` 当作模块放进捷思引擎求值并打印状态（求值成功，或首个错误与用时）。宿主对象（`window`、`globalThis`、`self`、`document`、`navigator`、`console`、`WebAssembly` 以及常见的构造器和函数名）由 `宿主桩。豫` 提供最小桩，只保证脚本顶层不因缺名而抛错，不模拟行为。模块按 `import` 关系经加载器从本地文件读取：相对路径依引用者所在目录，站点绝对路径（如 `/豫言操作系统/浏览器/引导检查.mjs`）依当前目录；打包时平铺在同一目录的脚本在仓库里分散在几处，找不到文件时到 `豫言操作系统/装载`、`豫言操作系统/宿主/网页汇编`、`豫言操作系统/宿主/浏览器` 按文件名补找；`node:` 开头的模块只提供空函数桩。
- `捷思验收 脚本目录`：对目录里的每个 `.mjs` 运行一次 `捷思运行`。
- `捷思分析 脚本文件`：调试用，打印模块的依赖说明符、导入项与导出项。

## 网平测参照测试

网平测（web-platform-tests）的参照测试由本引擎自己渲染：测试页与参照页各渲染一遍（视口 800×600），逐像素比较，容差照网平测的 `fuzzy` 元标签。网平测数据放在仓外的数据目录（`/Users/zc/repos/yuyan-worktrees/豫言数据/网页数据/wpt`，git 稀疏检出；补目录用 `git sparse-checkout add css/css-flexbox …`）。

### 用法示例

构建：`豫构 构建 网页一致性 --输出 yy网页一致性.exe -j 24`。在林纳克斯的 x86-64 机器上用六十四位豫构并加 `-- --目标 本机 --执行器 yy执行器六四。树码`。运行：

```
./yy网页一致性.exe 网平测参照 /Users/zc/repos/yuyan-worktrees/豫言数据/网页数据/wpt html/rendering css/css-flexbox --输出 结果.tsv --并发 12 --时限 60
./yy网页一致性.exe 网平测对比 旧结果.tsv 结果.tsv
```

### 命令

- `网平测参照 数据目录 子路径… [--输出 清单] [--并发 个数] [--时限 秒] [--内存 兆] [--深度 汇总深度] [--续] [--只列]`：批量运行。子路径是数据目录下的子目录或文件（如 `css/css-flexbox`、`html/rendering`）。运行器递归找出带 `<link rel="match">` 或 `<link rel="mismatch">` 的测试页（略过 `support`、`resources`、`reference`、`tools` 目录与 `-ref`、`-notref` 命名的参照页），每个测试在独立子进程里运行（程序以 `网平测单测` 自调用），同时最多跑“并发”个（默认 4）。单测超过“时限”（默认 120 秒）或常驻内存超过“内存”（默认 8192 兆）即被终止，崩溃、超时与内存超限都只记为出错，其余测试照常运行。`--输出` 指定结果清单文件，每一百条刷新一次；`--续` 读取已有清单，只跑清单里还没有的测试；`--只列` 只列出会运行的测试。结束时按路径排序写清单，并打印各级目录的汇总（总计，以及深度一至“汇总深度”的各级目录，默认三级）。
- `网平测单测 数据目录 路径`：运行一个测试，打印一行 `网平测结果`、结论、差异像素数、说明（制表符分隔）。
- `网平测存图 数据目录 路径 输出目录`：把测试页、第一条参照页与差异图（不同处标红，相同处淡化）存成三个 PNG，用来查看失败的原因；输出目录须已存在。
- `网平测汇总 清单 [深度]`：对结果清单打印各级目录的汇总。`网平测对比 旧清单 新清单`：逐路径比较两份清单，打印结论变化的测试以及退步、进步、新增、消失的数量。
- `网平测字体 数据目录`：打印三个标准族名与 Ahem 能否取得字体，用来诊断某台机器的字体。

### 结果清单

每行四列，制表符分隔：路径、结论、差异像素数、说明。

| 结论 | 含义 |
| --- | --- |
| 通过 | 找到一条每一步都成立的参照通路；说明写“两页皆纯色”表示两页都是纯色（多半是什么也没画出来而恰好相同） |
| 失败 | 渲染结果与要求不符；说明写出哪一页是纯色、最大通道差以及差异框（不同像素的包围盒），要求不等价却等价时写“两页相同” |
| 出错 | 页面读取失败、子进程崩溃、超时或内存超限 |
| 跳过 | 页面含可执行脚本或要等待脚本（`reftest-wait`）、分页或需人工交互、服务端替换（`.sub.`）、参照是图像或矢量图，或没有参照；脚本一律当数据看，不执行 |

差异像素数取各次比较中不同像素最少的一次。汇总里的通过率 = 通过 ÷（通过 + 失败 + 出错），跳过不计入；“其中皆纯色”一栏记两页都是纯色就通过的测试数，“去之后”的通过率另外去掉这些测试。

### 判定规则

- 同一页的几条参照是“或”（任一条成立即可）；参照页自己再带参照时沿链依次成立（深度优先，最深八层）。
- `match` 要求两页等价，`mismatch` 要求两页不等价。
- `<meta name="fuzzy" content="[参照页:]maxDifference=a-b;totalPixels=c-d">` 给出容差：单个数表示零到该数，带参照页前缀的只对那个参照页生效；没有 `fuzzy` 就要求逐像素相同。
- 页面里的相对地址按测试页地址解析，以斜杠开头的地址映射到数据目录根。
- `.xht`、`.xhtml` 页面先去掉 CDATA 标记并展开自闭合的非空元素，再按超文本标记解析（近似 XML 解析）。
- `font-family: Ahem` 取数据目录的 `fonts/Ahem.ttf`，其余字体用系统字体；林纳克斯上的原生执行器暂无字体宿主，运行器按候选路径读 Liberation 字体。
