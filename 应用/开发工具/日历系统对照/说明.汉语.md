# 日历系统对照

这是私有验证工具。底层入口 `系统农历` 在 macOS ARM64 原生运行，调用苹果自带 Foundation 的 NSDateFormatter、NSCalendar 和 NSTimeZone，输出固定 UTC+8 中文农历的制表符分隔向量。相关公历年模式 `r`、数值月 `M`、日 `d` 和完整月名 `MMMM` 提供独立年、月、日及闰月标签。

复用 `苹果。底层接口。豫` 的现有 Objective-C 消息绑定和原生后端苹果表，工具使用私有声明副本。公共接口维持现状。CFCalendar 可变参数分解调用留待需要结构化分量时再评估；本工具先用系统日期格式器取得完整结果。

向量包括 1900-01-31 起七十日、2101-01-01 至农历 2100 年最后一日，以及固定种子的 10000 个随机日。每日输入固定在 UTC+8 正午，日数以 1900-01-31 为零。输出保留系统原文，具体差异按运行结果记录。苹果系统实现可能与历史颁历表在近午夜月首发生模型差异。

参考为 Apple Foundation 系统实现与 Unicode LDML 日期模式。系统库随操作系统提供，工具输出为本次自行取得的计算向量；外部库代码与第三方实现留在系统边界外。

底层文件 `系统农历。底层。豫` 导出 `启动：0：0`，以既有苹果原生生成器生成 ARM64 程序。GC 入口 `入口。豫` 从工作目录读取 `yy系统农历参考.tsv`，按五列解析并比较 `日数转农历`。闰月由中文全月名的“闰”标记识别，数值月栏允许闰月前缀。

出处为 [Apple NSCalendar](https://developer.apple.com/documentation/foundation/nscalendar)、[Apple DateFormatter](https://developer.apple.com/documentation/foundation/dateformatter) 与 [Unicode LDML 日期模式](https://www.unicode.org/reports/tr35/tr35-dates.html)。只引用接口语义，库代码由本仓自行实现；系统向量为工具即时计算结果。系统参考属于当前系统的计算历法模型，历史颁历表和其他系统版本的差异按运行记录保存。
