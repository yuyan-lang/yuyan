# 社区包工具

`yy社区包工具` 者，社区包仓库 [yuyan-lang/yuyan-community-packages](https://github.com/yuyan-lang/yuyan-community-packages) 检与构之程也：拉取请求元数据之检、独立构建之树中之构与试、推程与软件目录于 yuyan-lang.org、合入之机之断，及抄语言仓之包入社区仓库。社区仓库之工作流依 `工具链钉。数据。豫` 检出语言仓之同一提交，解同提交之原生工具链包，乃以包中之 `yy豫构_stable.exe` 构此器。

## 何以置于语言仓

- 合入之机依其断而自合；置于语言仓，社区仓库之拉取请求不能改之。
- 径用语言仓之库（包配置解包籍、构建基础求包、版本库列 Git 之文），随语言仓 CI 核其型；库口变则语言仓即报之。
- 社区 CI 以同一所钉之工具链构此器与社区诸包，不另管其版。
- 语言仓 CI 之抄录亦用之。

## 诸令

| 令 | 所为 |
| --- | --- |
| `检查 --社区 <根> --语言仓 <根> --基 <提交> [--头 <提交>] [--输出 <包清单>]` | 拉取请求元数据之检，惟读而不行包中之代：所改之文须在 `包/<所有者>/<包名>/`；不收符号链接、子模块与或含凭据之文（如 `.env`、`*.pem`）；所有者名“社区”保留；包籍在 `包/<所有者>/<包名>/<包名>。包。豫`，所有者同目名，不书「包含在」「包含包」；「许可」必书而在白名单；每非合并之提交带与作者邮箱相符之 `Signed-off-by`（DCO）。问题以 GitHub 之注印之，有则退码一。所构之包（所改者、依之者；工具链钉改则皆是）书于包清单（数据子语言，顶名「包们」，每记「包」具所有者与包名）。 |
| `改动 …` | 惟算所构之包，main 之构用之。 |
| `构建 …` | 抄所构之包并其所依之闭包于构建之树 `<树>/<所有者>/<包名>/`，乃以语言仓根下之 `yy豫构_stable.exe` 与 `yy执行器。树码` 构之：库核其型；可执行之包依目标编为程，置于 `<产物>/程序/<所有者>/<包名>/<目标>`；`--测试` 则编而行包中之 `*。测试。豫`（于包目行之，每试至多十分）。`--归档` 则书每包源码与文档之档 `<产物>/归档/<所有者>/<包名>/<版本>.zip`（逾十六 MiB 不书），录于 `<产物>/归档清单。数据。豫`。程序清单书于 `<产物>/清单。数据。豫`，败因书于 `<产物>/失败.txt`。 |
| `推送 --产物 <目> [--演练] [--网址根 <网址>]` | 推于 yuyan-lang.org：程 `PUT /api/ci/程序/…`（带 `x-yuyan-sha256`），档 `PUT /api/ci/归档/…`，终为软件目录：每所有者一份，又汇诸社区之程为 `软件目录/社区/<目标>。数据。豫`；目录为数据子语言（提案〇〇〇二八）之记列，顶名「软件们」、每程一记「软件」。内容不变则不复传（用户二〇二六年十月十四日定）：程之沙256 同于所有者现有目录中同包同目标之记，则沿用旧版与旧记，不 PUT 其程；目录先读线上，易此次重编之包之记，与现有同则不复传。档传之败（如所有者未绑）惟告警。令牌取环境变量 `YUYAN_CI_UPLOAD_TOKEN`，经权六〇〇之 curl 配置之文授之；无令牌或带 `--演练` 则惟印所将发之请求。 |
| `合入核对 …` | 合入之机之断，惟视 GitHub 之口与 yuyan-lang.org 之元数据。可合则退码零，否则十，其因书于理由之文。 |
| `复制 …` | 抄清单「社区复制包们」诸语言仓包于社区仓库之 `包/豫言/<包名>/`：惟抄属其包之 Git 文，去层级之字段与模板之目，补「许可」`AGPL-3.0-only`，置语言仓之 LICENSE 一份；并改书工具链钉。 |

## 语言仓 CI 之抄录

`.github/workflows/main.yml` 之作 `community-copy`（抄于社区包仓库）行于推 yybs、史版既发之后：以本轮之原生豫构构此器，求本轮所发之 Linux x64 原生工具链包（算其沙256），检出社区包仓库，行 `复制`，以 `github-actions[bot]` 之名带 DCO 之签录之（GitHub 识其户，cla-bot 以其名问官网贡献协议之旧放行名录），推枝 `语言仓/<提交号前九位>` 而开拉取请求，由社区仓库之检与合入之机合之。新请既开，则闭前此语言仓所抄而检败之请（评以新请之址，并去其枝）；检犹未竟者姑存之，闭之不成则惟警之。跨仓之写用机密 `YUYAN_COMMUNITY_TOKEN`（细粒度之个人令牌，惟授社区仓库 Contents 与 Pull requests 之写；拉取请求之作者即令牌之主，合入之机依其所联之所有者核之，故令牌之主当联于所有者“豫言”）。无此机密则演练：照抄照录，存其补丁为构件“社区复制补丁”，不推。本轮史版未发（某平台未过）则不抄。

## 约

- 目标书“系统-架构”：`豫言-兼容六十四`、`豫言-臂六十四`、`林纳克斯-兼容六十四`、`林纳克斯-臂六十四`、`苹果-臂六十四`。`豫言-兼容六十四` 与 `林纳克斯-兼容六十四` 必成，余不成惟告警。
- 目标专用之入口：编豫言系统之目标，包根有「豫行入口」则用之；编苹果之目标，有「苹果入口」则用之；否则用包之默认入口。
- 程之版为 `<包籍之版>+<社区仓库提交号前九位>`，同云仓提案 C00004。
- 软件目录九列：名、版、下载之址、沙256、字数、简介、包名、所有者、源码之提交号。所有者之目录以包名为名；汇总之目录，所有者“豫言”之程用包名，余所有者用“所有者之包名”。
- 许可之白名单：Apache-2.0、MIT、BSD-2-Clause、BSD-3-Clause、ISC、Zlib、0BSD、AGPL-3.0-only、AGPL-3.0-or-later，可以 `AND`、`OR` 合之；括号与 `WITH` 不收。
- 合入之机之则：拉取请求开而非草稿，入 main；所触之“拉取请求检查”出 `.github/workflows/拉取请求检查.yml`、由拉取请求所触而成，“元数据检查”“构建与测试”二作皆成，头提交相同；作者之 GitHub 账号于 yuyan-lang.org 联已绑所有者名之豫言之户，数号相合；所改皆在 `包/<其所有者>/` 下（所有者“豫言”亦可改工具链钉）。

## 待办事项

- 接口之文档与源码之览（文档网站生成器、源码树浏览器）；今 文档/ 惟读之首页、包信息与生成之状。
- 软件目录去已删之包、不复编成之目标。
- 依赖之闭包循包籍之「依赖」，层级之包所隐之子不计（构建之树同批量发布去层级之字段）。
- 依改动之包者，每社区包求一闭包，包多则当藏之。
