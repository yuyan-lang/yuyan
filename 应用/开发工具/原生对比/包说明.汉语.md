# 原生对比

比较原生工具链与 Node 工具链的构建耗时。原生工具链是仓库目标「原生工具链」生成的 `yy豫构.exe` 与 `yy4_bs.exe`，Node 工具链是 `yy豫构.wasm` 与 `yy4_bs.wasm`。原生的中位耗时慢于 Node 时，打印 GitHub 警告（`::warning`）；两边产物不同或构建失败时，打印错误（`::error`）并以 1 退出。CI 的「Wasm 包起步」作业在 Linux x64、Linux arm64 与 macOS 上跑完「全部」后运行它。

## 用法

先在仓库根目录运行「全部」，它会生成原生工具链。然后：

```sh
./yy豫构.exe 构建 原生对比 --输出 yy原生对比.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy原生对比.wasm                      # 探针 3 轮、完整构建 2 轮
node 豫言操作系统/宿主/节点/宿主.cjs yy原生对比.wasm --探针轮数 5 --构建轮数 3 -j 24
```

## 测量的内容

- 冷编打印探针：`豫构 文件 应用/开发工具/原生对比/打印探针。豫`。探针只用标准库打印一行；工作任务不读缓存（`-- --do-not-load-cache`），标准库的各模块都要现编。
- 完整构建豫言编译器：`豫构 构建 豫言编译器`，工作任务同样不读缓存。

每种负载跑若干轮。奇数轮先跑 Node、后跑原生，偶数轮反之。每轮都用 `cmp -s` 核对两边产物逐字节相同。最后打印 Markdown 表，列出两边的中位数、原生与 Node 之比和各轮秒数；设了环境变量 `GITHUB_STEP_SUMMARY` 时，表同时写进该文件，成为作业摘要。产物写在仓库根目录的 `yy原生对比-*.wasm`，以 `yy` 开头，Git 会忽略。

墙钟受机器上别的负载影响。CI 的运行器之间差别也大，所以只打印警告，不让作业失败。
