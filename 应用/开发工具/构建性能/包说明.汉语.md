# 构建性能

读取构建日志，列出各次运行，并汇总一次运行的耗时，供分析构建性能、寻找提速方向。日志由豫构、构建编排与并行编译写出，格式见[构建日志格式](../../性能研究/构建性能/日志格式.汉语.md)。

## 用法

在仓库根目录运行：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 构建性能 --输出 yy构建性能.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy构建性能.wasm 列出            # 最近 20 次运行，新的在前
node 豫言操作系统/宿主/节点/宿主.cjs yy构建性能.wasm 列出 50
node 豫言操作系统/宿主/节点/宿主.cjs yy构建性能.wasm 摘要            # 最近一次运行
node 豫言操作系统/宿主/节点/宿主.cjs yy构建性能.wasm 摘要 <运行名>
node 豫言操作系统/宿主/节点/宿主.cjs yy构建性能.wasm 清理 1000       # 只保留最新 1000 次运行
```

日志根目录依次取 `--根 目录`、环境变量 `YY_BUILD_LOG_DIR`，都没有时为当前目录的 `.yy构建日志`。

## 摘要的内容

- 运行信息：命令、目录、分支、提交、有无未提交改动、系统、处理器数、标签、用时、退出码，以及开始和结束时的系统负载。负载高说明有别的构建在抢处理器，此时的计时不宜与别次比较。
- 进程树：各进程的用时、种类与参数，按父子缩进；豫构进程附各区间（包发现、包图、包上下文、编译器调用）的用时。
- 编排目标：每个目标从“检查”开始到“完成”结束的用时，按用时降序；跳过的目标注“已最新”。
- 每次编译（按墙钟降序）：
  - 墙钟、任务数（含失败与未运行数）、任务用时合计；
  - 平均并行度 = 任务用时合计 ÷ 墙钟；利用率 = 平均并行度 ÷ 并发上限；
  - 关键路径：沿依赖的最长链，只计任务用时、不计等待；占墙钟的比例；
  - 等槽位合计：各任务从就绪到开始的时间之和；关键路径上的任务等槽位合计：槽位被别的任务占着时，关键路径被拖长的时间；
  - 各阶段的任务数、用时合计、均值与最大值；
  - 最慢的十个任务；关键路径上的任务（超过六十个时只列前后各三十个）。
  - 可用时，列出并行 worker 的 Node 宿主统计汇总：模块准备毫秒、实例执行毫秒与宿主调用数；旧日志或未提供统计的宿主不显示此项。

判读：墙钟接近关键路径时，加并发无用，要缩短依赖链；利用率高而墙钟远大于关键路径时，是算力不够，要减少工作量；利用率低而墙钟远大于关键路径时，是调度或等待出了问题。

## 局限

待办事项：关键路径的“结束”是调度器收取到完成的时刻，含收取延迟；缓存命中及工作进程读依赖、计算、写出各步用时与字节数尚未记录；Windows 上 `清理` 依赖 `rm`。
