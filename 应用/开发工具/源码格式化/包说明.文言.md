# 源码格式化

## 往返之核

以 `豫构 构建 源码格式化 往返核对 --输出 yy往返核对.exe -j 24` 造今制之印（提案〇〇〇二六）之核器。

- `./yy往返核对.exe [篇径……]`：逐篇依今制析为具体语法之树，印之，复析之，较二树并核注数，列不过之篇与首异之处，末行为过者之数与诸败之数；不授篇则核 Git 所录诸源。原篇自不可析者另计（旧书法之样等）。有不过或印时出误，则以一退。可分篇为批，数程并行核之。
- `./yy往返核对.exe --写回 篇径……`：过核之篇写回所印，惟供试。
- `./yy往返核对.exe --印 篇径……`：以所印出于标准输出。
- `./yy往返核对.exe --超宽 篇径……`：列显示之宽逾百六十列之行（行号与宽）。
- `./yy往返核对.exe --雅言 [篇径……]`：雅言转写之核（提案〇〇〇二七，见《雅言之体》）：逐篇依今制析之、依雅言印之、复依雅言析之，二树须同（括号不较），雅言之果复印须不易；末行为过、原篇析败、转写不过、印时出误、不幂等之数，并今制之析与雅言之析各自之总时。不授篇则核 Git 所录诸源；有不过、出误或不幂等，以一退。
- `./yy往返核对.exe --印雅言 篇径……`：以篇依今制析之、依雅言印之者出于标准输出（观排版用）。

## 格式检查

以 `豫构 构建 源码格式化 检查 --输出 yy格式检查.exe -j 24` 造只读核验之器。
借编译器析词，寻名（`「…」`，数之字面亦在焉）中之英文字母、阿拉伯数字与下划线，复以既有排版器百六十列之果比原文。串与注中之英文字母、阿拉伯数字、下划线皆可用。诸篇保持原貌。

- `./yy格式检查.exe`：核 Git 所录 `.豫` 与 `。豫` 诸篇，略 `*_v0` 之目及 `yuyan-vscode`。名或篇径含英文字母、阿拉伯数字或下划线之篇，逐篇书 GitHub Actions 之误，核毕以一退。排版之失惟告警。所录之篇以 `git ls-files` 列之；无 git 时（如豫言操作系统中）由库「版本库」径读 Git 之索引，列已录与未见略之新篇。
- `./yy格式检查.exe --只查标识符`：惟校名与径、不核排版，有犯则以一退；约十秒，云仓 CI 于云仓之根行之。
- `./yy格式检查.exe --只查排版 篇径……`：惟核所授诸篇之排版，有失惟告警，退出之态恒零；可分篇为批，数程并行核之。
- `./yy格式检查.exe --标识符 径之前缀……`：逐处列径以此诸前缀起之篇之犯，每行“篇径：名”，末行总数；无前缀则列尽。
- `./yy格式检查.exe --标签 【基准之提交】`：检相对基准之提交（默认 `yybs`；先取其与 `HEAD` 之合并基，不得则用基准）所改之顶层签名，依 AGENTS.md 系标签参数否：诸参依签名所书字面之类相较，字面同类之参须系标签；函数恰二参者不检；类之后、`而` 之前有注之参不检。所较者工作树，未录之改与 Git 未录之新篇皆在焉。不合之签名逐一书附行号之 GitHub Actions 之警，末行总数；退出之态恒零。
- `./yy格式检查.exe --文件名`：列 Git 所录之篇与目录、名除半角点外皆汉字者（依 AGENTS.md 其缀当以全角句号「。」隔之），每行一径，有则别书一 GitHub Actions 之警；略 `*_v0` 之目及 `yuyan-vscode`；退出之态恒零。
- `./yy格式检查.exe 篇径……`：核所指诸篇，名与排版之失皆惟告警。

提案 00013（标识符规范化）既清仓中旧犯，自此有犯皆败。析文败之篇告警，惟核其径。
CI 之 `formatting check` 作业先行 `--标签`（基准取上一推之提交，拉取请求取所归分支之提交），次行 `--文件名`，皆惟告警，作业不以之败；复取无参之核所检之篇，按处理器之数并行 `--只查排版`（一程一篇），惟告警；终行 `--只查标识符`，有犯则作业败。造器败亦报败。

解析并格式化豫言源文件。

## 籍与用

所有者曰豫言，版本暂定 0.1.0。此包之版本，非编译器命令所报之版本。

此包不供他包所依，包内诸书仍可相引。程序名曰 `yy源码格式化`，入口依包籍所载。

在仓库之根行 `./yy豫构.exe 检查 源码格式化` 以验其籍。行 `./yy豫构.exe 构建 源码格式化` 以成其器，不自行之。

所依与组成皆见[包籍](源码格式化。包。豫)。变接口则修说明，变身份与组成则修包籍。说明不作模块。
