# 源码格式化

解析并格式化豫言源文件。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为可执行文件类型，不可被其他包依赖；包内模块仍可互相引用。类型典中的入口和文件名见包配置，程序产物为 `yy源码格式化`。

## 使用

在仓库根目录运行：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 检查 源码格式化
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 源码格式化
```

依赖及说明路径以 [包配置](源码格式化。包。豫) 为准。构建不会自动运行程序；有发布或服务副作用的工具应先阅读其入口源码。

## 格式检查

使用 `豫构 构建 源码格式化 检查 --输出 yy格式检查.wasm -j 24` 构建只读检查工具。
运行 `node 豫言操作系统/宿主/节点/宿主.cjs yy格式检查.wasm 文件路径……` 检查指定文件。
省略路径时检查仓库中 Git 受控的 `.豫` 与 `。豫` 文件，跳过 `*_v0` 目录和 `yuyan-vscode`。
工具通过编译器词法解析检查标识符中的 `[a-zA-Z_]`，并与现有格式化器的一百二十列结果比较。
字符串和注释中的英文字母、下划线可以正常使用。每项问题输出 GitHub Actions 警告；源码解析失败同样发出警告并继续检查后续文件。检查保持源文件原样，发现问题后正常退出。
CI 的 `formatting check` 作业使用此入口，工具构建失败由作业报告失败。
