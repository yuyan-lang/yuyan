# 源码格式化

解析并格式化豫言源文件。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为可执行文件类型，不可被其他包依赖；包内模块仍可互相引用。类型典中的入口和文件名见包配置，程序产物为 `yy源码格式化`。

## 使用

在仓库根目录运行：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 检查 源码格式化
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 源码格式化
```

依赖及说明路径以 [包配置](源码格式化。包。豫) 为准。构建不会自动运行程序；有发布或服务副作用的工具应先阅读其入口源码。

## 格式检查

使用 `豫构 构建 源码格式化 检查 --输出 yy格式检查.wasm -j 24` 构建只读检查工具。
工具通过编译器词法解析找出标识符（`「…」` 名称）中的英文字母与下划线，并与现有格式化器的一百二十列结果比较。字符串和注释中的英文字母、下划线可以正常使用。检查保持源文件原样。

- `node 豫言操作系统/宿主/节点/宿主.cjs yy格式检查.wasm`：检查仓库中 Git 受控的 `.豫` 与 `。豫` 文件，跳过 `*_v0` 目录和 `yuyan-vscode`。每个文件的违规处数（标识符含英文字母或下划线的出现次数；文件路径含英文字母或下划线时另计一处）与登记表 `标识符例外.tsv` 比较：超出登记数、或未登记的文件出现违规，输出 GitHub Actions 错误，全部检查完后以状态一退出；少于登记数时提示调低。排版问题只发警告。
- `yy格式检查.wasm --更新例外`：按现状重写登记表，每行是文件路径、制表符、处数，只收有违规的文件。清理一批违规、或改动文件名后运行，随改动一起提交。
- `yy格式检查.wasm --标识符 路径前缀……`：逐处列出路径以这些前缀开头的文件里的违规，每行“文件路径：名称”，末行是总数；不写前缀时列出全部。
- `yy格式检查.wasm 文件路径……`：检查指定文件，标识符与排版问题都只发警告。

登记表是提案 00013（标识符规范化）的检查棘轮：只许减少，不许增加。全部清理完后删去登记表，任何违规都会失败。源码解析失败的文件发警告，只计路径。
CI 的 `formatting check` 作业运行无参数的检查，标识符超出登记时作业失败；工具构建失败同样由作业报告失败。
