# WasmGC 编译器自举优化结果

两轮 Wasm 自举产物都与种子逐字节一致。详细实现过程见 [优化过程](优化过程.汉语.md)。

## 具体慢在哪里，改了什么

1. **列表反转重复遍历、分配。** 旧实现先反转尾部，再追加单个元素，复杂度 O(n²)。初始采样的 8338 个活动线程样本中，附加函数至少占 3337 个，调用栈主要指向反转。改为首插累积的尾递归，变为 O(n)。
2. **大量短命对象与过长的缓存生命周期触发复制式 GC。** 现在及时移除已消费的抽象树、擦除树、优化树的内存缓存根；磁盘缓存与后续必需的数据保留。自由变量替换对绑定变量和无子节点的叶子直接复用原节点。
3. **ANF 为每个临时 let 重写后续树。** 最终生成阶段的另一次 3339 样本窗口，`抽象替换自由变量` 的栈顶合计至少 700 个。Wasm 路线改为保留临时变量和原有 let 的名字，生成局部变量时直接解析；原有 let 先生成新的唯一名字，并使用既有解构函数检查自由变量冲突，避免捕获后续表达式。不再逐层闭合并重写后续整树。`let x = call in x` 仍恢复尾调用。
4. **WAT 文本和名字查找重复处理长前缀、长尾。** 连续 let 和顺序执行现在积累片段、最后一次拼接；局部名字使用 64 桶，函数与全局名字使用 4096 桶，碰撞仍比较完整名字。编号按原遍历顺序分配。最终转义预生成 256 项三字符表，逐字节查表，避免每字节反复计算十六进制和构造小字符串；任意字节仍精确转义，不假设有效 UTF-8。
5. **原语封装和整数包装有额外开销。** 小型非递归原语封装只在调用位置内联；已知小整数和布尔结果直接使用 i31，通用整数解码就地展开，仍保留完整 i64 路径。
6. **并行阶段重复启动与装载。** Wasm 每个模块合并前端阶段，任务数从 1191 减到 341；依赖模块完成后再编译使用者。

这些结论来自实际自举和采样。静态检查调用的数量不等于执行次数，也不能直接换算成耗时占比。采样百分比只描述对应窗口，不能当作整个自举的精确时间分解。

## 实现位置

- `库/标准库/数据结构/多态列。豫`：线性反转。
- `库/编译器核心/编译数据/抽象绑定树结构/抽象语法树/抽象语法树基础操作。豫`：叶节点共享。
- `库/编译器核心/编译步骤/求值正则变换/无类型正则变换。豫`：有名临时绑定策略。
- `库/编译器核心/编译步骤/代码生成/网页汇编直生。豫`：i31、文本片段、名字索引。
- `库/编译器核心/编译步骤/优化/跨文件优化/常量内联。豫`：原语调用内联。
- `库/编译器核心/编译步骤/总体过程/编译文件缓存工具。豫`、`分布编译步骤。豫`：缓存生命周期。
- `库/构建基础/并行编译。豫`、`单一编译工作。豫`：模块工作进程。

## 验证

`yy转义表种子.wasm` 与 Wasm 自举生成的 `yy最终并行二代.wasm` 一致。宿主不替代客体执行编译算法，只提供运行时系统接口、字节桥接与 WAT 组装。独立生成器也已更新。校验和见 `优化记录/最终校验和.txt`。

最新复测的 `yy开盖并行一.wasm`、`yy开盖并行二.wasm` 都与该种子一致。串行生成的 `yy开盖串行一.wasm` 再次完整串行自举，得到逐字节一致的 `yy开盖串行二.wasm`，因此串行也达到固定点。串行与并行不要求彼此字节相同：实际闭包缓存可见同一提升函数的序号分别为 5376 和 792，运行方式会改变跨模块编号。
