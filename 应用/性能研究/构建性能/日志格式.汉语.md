# 构建日志格式

构建日志是豫构、构建编排与并行编译在每次构建时写下的事件记录，存放在半永久的日志目录里，供日后分析构建性能。它不随下一次构建覆盖，清理 `.yybuild` 也不受影响；用 `yy构建性能 清理 保留条数` 删除旧记录。分析工具见 [构建性能](../../开发工具/构建性能/包说明.汉语.md)，调查的做法见[调查方案](调查方案.汉语.md)。

## 位置

```text
<仓库根>/.yy构建日志/
  运行/
    20260930-102540-构建-全树测试-679333/   一次运行一个目录：本地时间-命令段-纳秒末六位
      运行.json                             运行的元数据（只由顶层进程写）
      豫构-438613786679333.jsonl            每个进程一份事件文件：种类-启动时的纳秒读数
      编译-438614852029250.jsonl
```

- 每个 worktree 各有一份，目录以点开头，包发现不会扫描它，`.gitignore` 已忽略。
- 环境变量 `YY_BUILD_LOG_DIR` 改日志根目录（相对路径按当前目录解析）；`YY_BUILD_LOG=0` 关闭日志；`YY_BUILD_LOG_TAG` 给运行贴标签，写进 `运行.json`，便于把同一组实验归在一起。
- 日志不自动删除。

## 何时记录

- 豫构的构建类命令（`构建`、`类型检查`、`文件` 与仓库目标 `自举`、`测试`、`全部`、`目标 …` 等）新建一次运行；`发现`、`检查`、`定位` 与帮助不记录。
- 记录开启后，豫构、构建编排启动 `.wasm` 子程序时包成 `env YY_BUILD_LOG_RUN=<运行目录> YY_BUILD_LOG_PARENT=<本进程标识>/<任务名> 程序.wasm …`；宿主拆开这层包装，把变量并入子程序的环境。嵌套的豫构与编译器据此加入同一次运行，各写一份事件文件。
- 直接运行编译器（`--parallel`）时编译器不新建运行，只在继承到运行目录时记录。
- 事件先存在内存，进程结束时一次写盘；`运行.json` 在开始时写一次（状态“进行中”），结束时补上结果重写。

## 时刻

事件里的时刻都是单调时钟的纳秒读数（Node 的 `hrtime`），同一台机器上各进程、各线程共用这一时钟，可以直接放在一条时间线上比较。本地时间只记在 `运行.json` 的“开始本地时间”。

## 运行.json

| 字段 | 含义 |
|---|---|
| 格式 | 日志格式版本，现为 1；字段只增不改 |
| 运行 | 运行目录名 |
| 状态 | 进行中、完成或失败 |
| 命令 | 豫构的命令行参数（字符串数组） |
| 目录 | 当前目录 |
| 分支、提交 | `git rev-parse` 的结果；取不到时为空串 |
| 有未提交改动 | `git status --porcelain --untracked-files=no` 是否有输出 |
| 系统、处理器数 | macOS、Linux 或 Windows；在线处理器数 |
| 标签 | `YY_BUILD_LOG_TAG` 的值 |
| 开始本地时间 | 如 `2026-09-30 10:25:40` |
| 开始、结束 | 单调时钟纳秒 |
| 用时毫秒、退出码 | 结束时写入 |
| 负载开始、负载结束 | Linux 读 `/proc/loadavg`，macOS 用 `sysctl -n vm.loadavg`；负载高说明有别的构建在抢处理器 |

## 事件

每行一个 JSON 对象，字段“种”区分事件种类。第一行是本进程的“进程”事件。

**进程**：`标识`（种类-纳秒）、`父`（`<父进程标识>/<任务名>`，顶层为空串）、`种类`（豫构或编译）、`参数`、`目录`、`开始`、`结束`、`退出码`。

**区间**（豫构）：`名`、`开始`、`结束`。名有：包发现、包图（含写语言服务文件）、包上下文、编译器调用。

**目标**（构建编排）：`名`、`跳过`（缓存键未变而跳过时为真）、`算键开始`、`算键结束`（计算缓存键的用时，其中要遍历目录输入）。

**步骤**（构建编排）：`任务`（如 `编译器三级#1`）、`描述`（命令及参数，即缓存键里的步骤描述）。

**编译**（并行编译开始时一条）：`程序`（编译器路径）、`主文件`、`上限`（并发数）、`仅检查`、`缓存目录`（`.yybuild/<编译器路径转义>+<修改时间>.nosync`）、`缓存目录已存在`（为假即从冷缓存编起）。

**任务**（构建编排与并行编译的调度任务）：

| 字段 | 含义 |
|---|---|
| 名 | 任务名；编排任务如 `豫构#检查`、`豫构#1`、`豫构#完成`，编译任务如 `parse：库/标准库/总集。豫` |
| 依赖 | 所待任务的名称 |
| 加入 | 任务创建的时刻 |
| 就绪 | 调度器首次发现其依赖全部成功的时刻 |
| 开始 | 派发启动的时刻 |
| 结束 | 调度器收取到完成的时刻（含收取延迟） |
| 在途 | 开始时在途的任务数（含自己） |
| 状态 | 成功、失败、未运行或运行中 |
| 阶段、文件 | 只有编译任务有：阶段显示名（依赖分析、语法解析、类型检查、跨模块优化、闭包转换、最终链接等）与去掉目录前缀的文件 |
| 后于全图 | 只有最终链接有：它在全部任务结束后开始，依赖列为空 |
| 节点统计 | 并行编译任务可有的对象：`模块准备毫秒`、`执行毫秒`、`宿主调用数`；仅继承 `YY_BUILD_LOG_RUN` 的 worker 写出。未开启日志时，显式设置 `YY_NODE_STATS=1` 仍用旧详细 JSON 行，不产生新 marker。旧运行没有此字段，按无统计处理 |

未发生的时刻为 0。三段等待由此算出：等依赖 = 就绪 − 加入，等槽位 = 开始 − 就绪，执行 = 结束 − 开始。

## 分析

先 `yy构建性能 列出` 找到运行，再 `yy构建性能 摘要 <运行名>` 看汇总；需要别的统计时直接读 JSON 行。比较两次运行时，先核对命令、提交、有无改动与负载；负载高或与别的运行时间重叠的计时不宜比较。

## 局限

待办事项：旧运行没有“节点统计”，分析器按无统计处理；进程被中途杀死时，内存里未写盘的事件会丢失，`运行.json` 停在“进行中”；宿主写盘失败会中止进程；缓存是否命中、工作进程内部各步（读依赖、计算、写出）的用时与字节数尚未记录；Windows 上宿主按冒号拆 PATH，找不到 git，分支与提交为空。
