# 构建性能调查方案

这是系统分析构建耗时、寻找提速办法的工作方案。数据来自[构建日志](日志格式.汉语.md)，分析工具是 [yy构建性能](../../开发工具/构建性能/包说明.汉语.md)。

## 判读框架

每次编译的墙钟拆成两部分：关键路径（沿依赖的最长链，只计任务用时）与调度松弛（等槽位、收取延迟等）。看三个量：

- 关键路径占墙钟的比例；
- 平均并行度 = 任务用时合计 ÷ 墙钟；
- 利用率 = 平均并行度 ÷ 并发上限。

据此归入三种情形，各有对策：

| 情形 | 表现 | 对策 |
|---|---|---|
| 链长受限 | 墙钟接近关键路径 | 加并发无用；缩短依赖链：拆阶段、提速链上的长任务、减少模块间的串行依赖 |
| 算力受限 | 利用率高，墙钟远大于关键路径 | 减少工作量：提高缓存命中、给编译器提速、去掉重复工作 |
| 调度受限 | 利用率低，墙钟远大于关键路径 | 查调度：等槽位、收取延迟、进程与实例的固定开销 |

同时看进程树里编译器之外的时间（豫构的包发现、包图、包上下文，编排的算键），以及编排目标之间是否因独占组而串行。

## 数据

- **日常采集**：豫构的每次构建都自动记日志，据此统计实际最常等待的是哪些构建、各花多久。
- **基准场景**：固定的一组场景，贴上标签（`YY_BUILD_LOG_TAG=基准:冷` 等），每个跑三次取中位数：
  1. 冷缓存：`构建 豫言编译器 -- --do-not-load-cache`；
  2. 无改动重跑：缓存全部命中，量出纯开销；
  3. 改一个叶子文件后重建；
  4. 改标准库底层文件（如内建类型）后重建，失效面最大；
  5. `全部`（自举）；
  6. `目标 类型检查`。
- **可信度**：本机常有并行会话同时构建。负载明显高于处理器数，或与别的运行时间重叠时，计时只作参考；正式对比要在负载低时跑。

## 待验证的疑点

读代码时看到、尚待数据证实或否定：

1. 编译器缓存目录过去按“编译器路径＋修改时间”命名（`库/编译器核心/编译步骤/总体过程/编译过程工具。豫`），编译器一重建（哪怕字节相同）就换新目录，从冷缓存编起。2026-10-03 起改按运行中编译器文件的 SHA-256 命名，并以定向测试核对标识；构建日志也按传入的编译器文件 SHA-256 记录缓存目录。旧目录统计（2026-09-30：129 个、242G）仍是历史数据。本改动使相同字节内容复用同一缓存根；阶段缓存的修改时间判新旧仍另行处理，尚无性能提速结论。
2. 阶段缓存按修改时间判新旧，切分支、`touch` 会引起不必要的重编。
3. 每个任务的固定开销（Wasm 实例化、读依赖的中间表示、写出）占多少；无改动重跑的场景可以直接量出。
4. 调度延迟：任务结束到被调度器收取、依赖它的任务启动之间的空档。
5. 最终链接（整模块代码生成）是否成了单线程长尾。
6. 仓库目标里的嵌套构建都在“独占豫构”组里，是否因此全部串行。
7. 豫构每次都扫描全仓做包发现、编排每次都遍历目录输入算缓存键，各花多少时间。

## 初步观察

2026-09-30，Apple M5 Pro（18 个处理器），负载约 80，并发上限 24：

- 用新编译器冷编全树测试工具（50 个模块、251 个任务）：墙钟 15.33 秒，关键路径 14.75 秒（占 96%），平均并行度 7.8，利用率 32%，等槽位合计 0.52 秒。属于链长受限：链上几乎全是标准库各模块的类型检查（内建类型 → 爻术 → 整数操作 → 多态列 → 多态列工具 → 字符串术 → …），加并发无用。
- 同一构建中豫构自身：包发现 0.36 秒、包图 0.15 秒、包上下文不到 0.01 秒；另一次负载约 147 时，包发现 1.68 秒、包图 1.27 秒。
- 自举（`全部`，标签“自举验证”，负载约 50 至 90）共 250.9 秒，是一条串行链：编译器二级 42 秒（稳定工具链，缓存命中）、三级 66 秒、四级 78 秒、豫构 40 秒、值桥 24 秒；值桥声明依赖豫构，两者又同在“豫构缓存”独占组，所以先后执行。三级、四级编译都从冷缓存编起（新编译器即新缓存目录），墙钟 64.6 秒与 75.8 秒，关键路径占 92% 与 91%，1201 个任务里类型检查合计 322 至 363 秒；关键路径上最长的一环是 `抽象语法树反序列化节点名称。豫` 的类型检查（10 至 13 秒），最慢的任务是 `回收运行时。豫` 的类型检查（13 至 16 秒，不在关键路径上）。关键路径上的任务等槽位合计 4.8 秒，槽位争抢对墙钟影响不大。
- 疑点 4 得到证实：编排的调度循环（不限时的让出）在子进程没有输入输出事件时不醒。“自举#完成”在第 186.1 秒就已完成，直到第 226.6 秒豫构子进程结束才被收取，晚了 40 秒；这次没有目标依赖它，所以未拖慢整体。

## 报告

每个疑点或改进写一篇报告，放在本目录，成对的 `题目.汉语.md` 与 `题目.文言.md`，沿用[前端合并与拆分](../前端调度/合并与拆分.汉语.md)的体例：环境与负载、命令、结果表、结论、复现方法与验证边界。改进落地后用同一场景复测，结果写进报告。

## 分期

- 第一期（已完成）：日志目录与跨进程串联、调度器的四个时刻、编排／豫构／编译三类事件、`列出`／`摘要`／`清理`、CI 上传日志（构件 `yy-build-logs-*`，可用 `gh run download <运行号> -n <构件名>` 取回）。

- 第三期：“构建基准”仓库目标、按命令看趋势、把全树测试的各次构建归入同一运行。
