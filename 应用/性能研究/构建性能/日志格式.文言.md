# 构建日志之式

构建之志，乃豫构、构建编排与并行编译于每构所书之事录，存于半久之目，以备日后析构建之迟速。后构不覆之，清 `.yybuild` 亦不及之；以 `yy构建性能 清理 保留之数` 去其旧录。析之器见[构建性能](../../开发工具/构建性能/包说明.文言.md)，察之法见[调查之方](调查方案.文言.md)。

## 所在

```text
<仓根>/.yy构建日志/
  运行/
    20260930-102540-构建-全树测试-679333/   一运行一目：本地之时-令段-纳秒末六位
      运行.json                             运行之要（惟顶层之进程书之）
      豫构-438613786679333.jsonl            一进程一事文：类-启时之纳秒
      编译-438614852029250.jsonl
```

- 每 worktree 各一，目以点起，包之搜求不及，`.gitignore` 已略之。
- 环境 `YY_BUILD_LOG_DIR` 易志之根（相对之径依今目录而解）；`YY_BUILD_LOG=0` 则止；`YY_BUILD_LOG_TAG` 书运行之签，入 `运行.json`，以聚同组之试。
- 志不自删。

## 何时录之

- 豫构之构建诸令（`构建`、`类型检查`、`文件`，及仓库目标 `自举`、`测试`、`全部`、`目标 …` 等）立一运行；`发现`、`检查`、`定位` 与帮助不录。
- 志既启，豫构、构建编排启 `.wasm` 子程，则裹以 `env YY_BUILD_LOG_RUN=<运行之目> YY_BUILD_LOG_PARENT=<本进程标识>/<务名> 程序.wasm …`；宿主自解其裹，并其变量于子程之环境。苹果与 Linux 上之原生子程（`.exe`，如原生编译器 `yy4_bs.exe`）亦裹之，由系统之 env 设其变量。嵌套之豫构与编译器由此入同一运行，各书一事文。
- 径行编译器（`--parallel`）者，编译器不立运行，惟承运行之目乃录。
- 事先存于内，进程将终乃一书于盘；`运行.json` 始时书一次（状曰“进行中”），终时补其果而重书。

## 时刻

事中诸刻皆单调钟之纳秒（Node 之 `hrtime`），同机诸进程、诸线程共此一钟，可置一时线而较。本地之时惟录于 `运行.json` 之“开始本地时间”。

## 运行.json

| 字段 | 义 |
|---|---|
| 格式 | 志式之版，今为一；字段惟增不改 |
| 运行 | 运行之目名 |
| 状态 | 进行中、完成、失败 |
| 命令 | 豫构之命令行参（字串之数组） |
| 目录 | 今目录 |
| 分支、提交 | 支取 `git branch --show-current` 之全名，提交取 `git rev-parse --short HEAD`；不得或头离支者，支为空串 |
| 有未提交改动 | `git status --porcelain --untracked-files=no` 有出否 |
| 系统、处理器数 | macOS、Linux、Windows；在线处理器之数 |
| 标签 | `YY_BUILD_LOG_TAG` 之值 |
| 开始本地时间 | 如 `2026-09-30 10:25:40` |
| 开始、结束 | 单调钟之纳秒 |
| 用时毫秒、退出码 | 终时书之 |
| 负载开始、负载结束 | Linux 读 `/proc/loadavg`，macOS 用 `sysctl -n vm.loadavg`；负高则有他构争核 |

## 诸事

一行一 JSON 之物，以字段“种”别其类。首行为本进程之“进程”事。

**进程**：`标识`（类-纳秒）、`父`（`<父进程标识>/<务名>`，顶层空串）、`种类`（豫构或编译）、`参数`、`目录`、`开始`、`结束`、`退出码`。

**区间**（豫构）：`名`、`开始`、`结束`。名有：包发现、包图（并书语言服务之文）、包上下文、编译器调用。

**目标**（构建编排）：`名`、`跳过`（缓存之键未变而跳者为真）、`算键开始`、`算键结束`（算缓存之键之时，其中遍目录之输入）。

**步骤**（构建编排）：`任务`（如 `编译器三级#1`）、`描述`（令及其参，即缓存键中之步述）。

**编译**（并行编译始时一条）：`程序`（编译器之径）、`主文件`、`上限`（并发之数）、`仅检查`、`缓存目录`（`.yybuild/sha256_<程序文之 SHA-256>.nosync`）、`缓存目录已存在`（假则自冷缓存编起）。

**任务**（构建编排与并行编译之调度诸务）：

| 字段 | 义 |
|---|---|
| 名 | 务名；编排之务如 `豫构#检查`、`豫构#1`、`豫构#完成`，编译之务如 `parse：库/标准库/总集。豫` |
| 依赖 | 所待诸务之名 |
| 加入 | 务立之刻 |
| 就绪 | 调度初见其所待皆成之刻 |
| 开始 | 派而启之之刻 |
| 结束 | 调度收其成之刻（含收取之迟） |
| 在途 | 启时在途之务数（并己） |
| 状态 | 成功、失败、未运行、运行中 |
| 阶段、文件 | 惟编译之务有之：段之显名（依赖分析、语法解析、类型检查、跨模块优化、闭包转换、最终链接等）与去目录前缀之文 |
| 后于全图 | 惟最终链接有之：诸务皆毕乃启，所待之列空 |
| 节点统计 | 并行编译之务可有之对象：`模块准备毫秒`、`执行毫秒`、`宿主调用数`；惟承 `YY_BUILD_LOG_RUN` 之工进程书之。未启志而显设 `YY_NODE_STATS=1`，仍用旧详 JSON 行，不书新标。旧志无此字段，则视为无计 |

未至之刻为零。三段之候由此而算：候所待 = 就绪 − 加入，候槽 = 开始 − 就绪，行 = 结束 − 开始。

## 析之

先 `yy构建性能 列出` 以得运行，次 `yy构建性能 摘要 <运行名>` 以观其总；需他计者径读 JSON 之行。较二运行，先核其令、提交、有改否与负载；负高或与他运行同时者，其时不宜相较。

## 所限

待办事项：旧志无“节点统计”，析器则视为无计；进程中途见杀，则内存未书之事亡，`运行.json` 止于“进行中”；宿主书盘而败则进程止；缓存之中否、工作进程内诸步（读所依、算、书出）之时与字节尚未录；Windows 上宿主以冒号拆 PATH，不得 git，分支与提交皆空。
