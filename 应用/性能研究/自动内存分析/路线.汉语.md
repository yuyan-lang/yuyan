# 自动内存分析与分配选择

用户于 2026-09-19 明确决定不采用长期保留的私有缓冲，要求自动分析栈分配、逃逸与线性使用，不依赖源码手动标记。编译器应自动选择分配方式，证明不足时保留通用 GC；公开 ABI 与程序语义不变。

当前已存在的分析是起点，并非完整的所有权类型系统：整数局部值可不装箱；数组的初始化、写入、转交与逃逸检查可选择宽整数或字节 GC 数组；新加入的双数组参数分析沿静态调用图证明两个数组的用途。它们都由编译器自动完成，无需用户标注。私有 GC 数组仍由 GC 回收，不是先前提议的持久缓冲。

源码调查确认，旧的 `栈分配优化。豫` 仅识别受限的直接函数调用；`统一正则构造。豫` 当前把 `栈元组构造节点` 与普通元组同样变成 `正则造元组`。因此，前端产生“栈”节点不代表 Wasm 已经使用栈存储。需要以实际分配指令和运行数据验证。

## 编译器内部应推导的事实

| 事实 | 应回答的问题 | 可支持的选择 |
|---|---|---|
| 形状与值域 | 字段数、元素类型、大小上界是否已知？ | 去装箱、紧凑布局、固定大小存储 |
| 逃逸摘要 | 参数是否被返回、捕获、存入其他对象或交给未知调用？ | 消除局部分配、局部生命周期管理 |
| 指向与别名 | 哪些值可能指向同一对象？某点是否只有一个可用所有者？ | 安全原地更新、避免复制 |
| 使用与活跃性 | 各条路径上的最后一次使用在哪里？ | 提前结束生命周期、复用已死亡对象 |
| 调用效果 | 调用会读、写、捕获什么？是否返回参数的别名？ | 跨函数传播上述证明 |
| 生命周期区域 | 对象需存活到当前调用、调用者还是更长？ | 标量局部值、调用栈存储或 GC |

“不逃逸”不等于“没有别名”；“唯一所有者”不等于“只读一次”；线性使用与最多使用一次也需要区分。不能用一次简单计数替代路径和别名分析。分支合流取保守结果，递归调用图通过不动点求摘要，未知调用保留安全后备。

这些事实宜作为中间表示的内部资格与效果信息，由编译器推导和验证；暂不要求源语言增加复杂类型、模式标记或所有权注解。全部自动运行，不意味着所有程序都能被证明可优化。

## 实现顺序与验收

1. 完成并验证双数组非逃逸证明与 GC 布局选择，保留全部索引检查。矩阵原型显示明确收益，正式编译器产物需独立复测和自举验证。
2. 对每个分配点输出可复核的分析报告：形状、逃逸原因、别名信息、候选分配方式及无法优化的原因。静态分配点数与实际执行次数分开记录。
3. 对局部元组和构造器做标量替换：把字段保留在 Wasm 局部值中，直接消除对象分配；先验证可变字段、分支、闭包捕获和异常退出。
4. 推导跨函数参数及返回别名摘要，扩展非逃逸证明；为生命周期受限的调用生成内部入口，避免改变公开 ABI。
5. 在别名与最后使用证明成立后，尝试自动存储复用和原地更新。递归树等负载必须保留共享子树的可观察行为，不能把表面上的一次使用当作唯一所有权。
6. 仅对表示适合且生命周期已证明的对象探索真实栈存储。Wasm GC 引用应保留在引擎可追踪的局部值或 GC 对象中，不能直接当整数指针写入线性内存。任何栈方案都需验证异常、尾调用和重入的清理行为。

每步都同时记录分配次数、布局或对象大小变化、GC 行为与运行时间；最终性能目标仍是已有多程序达到同机 C/Wasm 对照，完整冷编译缓存自举不超过 30 秒。静态报告和局部微基准不能代替这些验收。

进度更新：第一步已通过自举与 30 项回归；第二步已有分配点报告、七项分配分析回归，以及保守的跨函数来源/外存摘要和八项摘要回归；精确字段路径、最后使用与完整所有权推导仍未实现。第三步及之后尚未实施，详见 `首轮结果.汉语.md`。长期保留私有缓冲的原型仅存档，不作为下一步实施方案。

调用摘要的实现、证明范围与实际树程序结果见 `调用摘要进展.汉语.md`。
