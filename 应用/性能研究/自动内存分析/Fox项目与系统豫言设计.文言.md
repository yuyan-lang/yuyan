# 考 Fox 而议豫言治系统

此为设计之议，非已成之制。宜守豫言之文法，增机器之形、系统之约与硬件之权，因今之原生后端而生裸机程序，不必别造一语。

FoxNet 以 Standard ML 组网络协议，重模块与类型；其本为用户态栈，裸机之移植另见 Hello。不得混称完整内核。见 [FoxNet 项目](https://www.cs.cmu.edu/~fox/foxnet.html)。其论文论外存、字长、装箱及回收之限，非谓高级语言诸事皆胜 C。见[原论文](https://www.cs.cmu.edu/~rwh/papers/foxnet/hosc.pdf)。

TIL 留类型于中间诸层，以验转换之正；豫言亦宜留寿命、表示与效果之证。见[项目说明](https://www.cs.cmu.edu/~fox/til.html)。作者追述亦戒小例、整程序优化及编译之费，不可以小试夸全功。见[回顾](https://www.cs.cmu.edu/~rwh/papers/til-retro/retrospective.pdf)。House 以受控硬件接口使 Haskell 行于裸机，可为旁证。见[作者论文页](https://ogi.altocumulus.org/~hallgren/ICFP2005/)。

今豫言原生循统一 ANF，生直接调用 C，而后付 clang；通值容器百二十八位，非诸整数皆百二十八位。旧帧接口之文不尽合今路，当以代码为准。网页线性栈虽不经 GC，仍非物理内存，亦非中断与特权之制。

所当增者：定宽整数与位运算；外部结构之尺寸、对齐与端序；栈、区域、页与固定址池之寿命；托管分配、回收、阻塞、挂起与异常之效果；原子、设备访存与屏障；外部调用及回调之约；中断与线程之栈界。易变访存与原子同步不可混，见 [LLVM 说明](https://llvm.org/docs/Atomics.html)。

普通对象之别名、不逸与独用，宜自动推之，不令作者逐物标栈。然设备何时还其缓冲、外部函数是否保留参数，必有接口之约，不能凭名臆知。普通模式证不足可用 GC；严禁托管分配之入口，证不足则止编，并明告调用之径。无 GC 亦非无分配，无分配亦非必有时限。

私门当分三义：C ABI 定其二进制约；系统入口定其可行效果；硬件原语定其权限与机器行为。三者各立，不可以一名兼保。闭包有捕获者须携环境与寿命；中断须先存现场而后入函数。普通应用 ABI 可守，系统 ABI 另立其约，桥接亦受效果之验。

以网卡为例：中断读状态、收完成、入预置队列而应答。局部视图可置栈，DMA 载荷则由固定址池持之，待设备归还始可复用。设备协议定交接之时，类型检查程序之用；地址映射、对齐与一致性仍由平台负责。

宜先证无 GC 调用链与双向 C 接口；次择单核虚拟机，以少量汇编/C 启动，而由豫言治页、时钟与调度；再验驱动、缓冲池与包解析；最后论多核及托管服务。裸机环境不能只删 main，尚须供启动、链接与编译辅助，见 [GCC 说明](https://gcc.gnu.org/onlinedocs/gcc/Standards.html)。

首机何选、内核高层可否 GC、初期可否小型汇编/C 受信任层，此三者须用户定。其余先以最小实物验设计，不先许任意程序皆可自动证明。
