# 循环关系与索引宽度

本轮继续研究排序约为 C 耗时 1.62 倍的差距。默认编译器未修改；以下是生成 WAT 的诊断原型，不能计作豫言已经获得的正式优化。没有私有持久缓冲，没有改变数组布局、公开入口或排序算法。

## 不变参数写回

尾递归先读取所有实参，再逆序写回形参。一部分形参完全不变。原型省去了连续局部读取及写回中的 32 对同值操作。五进程交替执行、每进程六轮，首轮单列，后 25 个样本的中位数：旧 53.899 毫秒、新 54.235 毫秒，稳态无收益。首次执行有所改善，但暂不为此增加默认编译器规则。该文本原型不是通用语义证明，特别不能随意消除可能失败的引用转换。数据见 `不变参数探索.json`。

## 带守卫的循环范围

分区私有函数已有裸整数参数和返回值，但仍在每轮检查索引是否能表示为无符号 32 位整数。另建快入口，调用前检查以下关系；不满足就调用原函数：

```
0 ≤ 存放序数 ≤ 扫描序数 ≤ 上界 ≤ 2^32−1
```

实际守卫使用无符号比较，因此同时排除负值。上界在循环中不变。当扫描序数等于上界时返回；否则扫描序数严格小于上界，下一轮增加一不会溢出允许范围。存放序数保持原值或增加一，都保持小于等于新的扫描序数。因此所有循环内数组索引都能表示为无符号 32 位整数。

快入口仅删除三个索引宽度检查，保留每次 GC 数组自身的边界检查。没有把“索引宽度合法”误作“数组足够长”。守卫不访问数组，不引发陷阱；不满足前提时保留原函数，包括原来的零次循环返回和失败路径。枢轴仍可为任意全宽整数。

| 数组元素数 | 原实现稳态毫秒 | 带守卫原型毫秒 |
|---|---:|---:|
| 1,000,000 | 13.003 | 11.725 |
| 4,000,000 | 54.168 | 48.457 |
| 8,000,000 | 118.871 | 106.568 |

四百万项使用五进程交替执行，各六轮，首轮单列，其余 25 次取中位数；其他规模使用三进程、15 个稳态样本。四百万项首轮旧 76.15～81.87 毫秒、新 70.11～74.51 毫秒。所有校验值一致。主实验无并行构建；规模复测作为辅助证据，期间曾提交独立的边界验证命令，未记录两进程重叠时间，正式接入后应独占复测。数据见 `关系索引探索.json` 与 `关系索引规模复测.json`。

四百万项稳态减少约 10.5%。仍高于上一轮 C/Wasm 约 33.34 毫秒；此次没有重跑 C，不能把跨轮比例作为新的正式对照结论。

## 边界验证

以真实 GC 数组调用旧入口和新守卫入口，分别比较：

- 7,986 组常量数组：返回值或异常类型及消息相同，其中 7,108 组失败、504 组满足快入口守卫。
- 15,972 组非均匀数组：初始元素为 `23−17×索引`，比较返回值、异常类型和消息，以及执行后的完整数组，包括 14,248 组失败前发生的写入；全部相同。

覆盖长度 0、1、4，参数包括最小和最大有符号 64 位整数、负一、零至五、最大无符号 32 位值和其后继，枢轴包括整数两端。记录见 `关系索引边界.json`、`关系索引状态边界.json`。原型差异与 SHA-256 见 `关系索引原型.补丁`、`关系索引产物摘要.json`。

## 默认编译器需要的证明

不能按函数名或排序算法匹配。下一步在统一正则 IR 中推导带入口条件的差分约束，并验证每条回边：

1. 建立整数形参之间的大小关系与常量上界，不把 GC 数组长度和索引宽度混为一谈。
2. 从相等退出分支及其反面推导严格上界；证明加一的数学结果仍在允许范围，之后才能使用该数学转移描述机器整数。
3. 同时代入全部尾递归实参，验证关系在所有回边保持。交换参数、不同步更新、未知调用和复杂控制不能套用未证明的规则。
4. 只在已通过守卫的私有克隆内消除被证明的检查。原函数和公开函数表保持不变；不同入口的事实不能互相泄漏。
5. 限制分析规模和克隆数量，检验其对编译器冷缓存自举的开销，并执行规定的完整自举与边界回归。

本轮取得可重复的优化机会与错误路径证据，尚未实现上述通用分析。整体目标仍未完成。
