# 中间数组消除探索

本轮编译器源码保持上一轮已完整验证的状态，只对产物做诊断实验，目标是选择下一项值得实现的通用分析。原型不计作豫言已经获得的优化。

## 排序分区内联被否决

把已经返回 i64 的分区循环直接嵌入排序函数，完整重命名局部值和循环标签，保留所有检查与算法。五进程交替执行、每进程六轮、首轮单列，其余 25 样本中位数：基线 54.040 毫秒，内联 62.728 毫秒。没有采用。见 `分区内嵌原型.json`。

## 数组完全消除的收益

现有数组程序创建长度 n 的局部数组，依次写入 `数组[n-1]=n`，然后按相同方向读取并累加。数组不作为结果返回。手工原型在调用者内部保留原先的整数长度解码和 0..2^32-1 范围检查，把每次读取替换为此前写入的值，消除数组分配与填充过程。

仍执行 n 次 i64 加法与递减，没有使用求和公式、跨调用缓存、持久缓冲或源码修改。公开入口参数和返回表示保持原样。空数组及小数组结果一致，负数和 2^32 长度仍失败。这些检查不构成对所有程序的通用证明。

| 元素数 | 当前编译器毫秒 | 消除数组原型毫秒 |
|---|---:|---:|
| 2,000,000 | 1.984 | 0.487 |
| 10,000,000 | 14.599 | 2.389 |

大规模各五进程交替运行，各六轮，首轮单列，其余 25 样本取中位数；结果均一致，无并发编译。原始数据见 `消数组原型.json`。千万项时间减少约 83.6%，但这不是默认编译器已经达到 C 的证据。消除分配也会消除相应的资源消耗；本实验不保证与原来的资源耗尽失败时机相同。

## 自动分析与实现条件

目标是在中间表示中推导“虚拟数组”：只保存长度和元素生成规则，读取时生成值，最终完全不分配该数组。应按分配点和调用图分析，不按基准文件名、函数名或函数编号匹配。

1. 分配结果及其所有别名必须封闭在可分析的调用链内；返回数组、存入外部对象、闭包捕获或交给未知调用均放弃优化。
2. 初始化循环须被证明完整覆盖每个合法索引，且每个索引的最终值可确定。首批可分析从 n 递减到零、写入索引为计数器减一的循环；值允许来自计数器与常量的总整数表达式，并不限于当前基准的值。
3. 消除初始化不能抑制原有可观察副作用或整数类型、除零等错误。首批只接受已知整数上的加减乘与常量；未知调用和未证明安全的除法拒绝。捕获值的检查时机也必须保留，不能因为消费者少读而漏掉初始化原本必然触发的错误。
4. 消费者只能读取这份数组，所有调用和别名均需分析。写入、未知传递或对象身份观察保留原实现。读取使用的索引仍须检查，不能因没有实体数组就放行越界。
5. 容量检查、整数回绕、空数组及控制流保持原语义。对证明不足的分配点保留原 GC 数组和公开 ABI，不要求源语言增加标记。

这比把同一个数组移到栈上更进一步：若内容可以安全重建，就不必为它选择任何实际存储区。通用栈分配、完整线性与别名推导仍未完成，不应把该原型等同于完整内存类型系统。

## 完整初始化证明进展

已实现独立模块 `网页汇编初始化证明。豫`。它识别两参数的完整递减初始化循环，要求计数大于零时写入计数减一的位置，恰好写一次，并以相同数组和计数减一进行尾递归；零分支必须直接返回单元。结果记录数组参数、计数参数和纯整数生成表达式，参数顺序与函数名称不固定。调用者仍须证明计数初值等于新数组长度且通过容量检查；此模块不是可直接删除分配的完整许可。

值表达式限于计数器、整数常量与加减乘，保留 i64 回绕，表达式展开费用上限 64，函数局部值上限 128。未知调用、数组读取依赖、除法、重复写、错误索引或步长、非零结束阈值及复杂控制保守拒绝。未将任何源码标注作为证明。

独立 Wasm 测试通过：基础数列、仿射数列、常量填充、全宽整数回绕、不同参数顺序，以及上述拒绝边界；另验证了表达式膨胀预算。编译器入口及新测试的类型检查通过。模块尚未接入默认生成，故没有新的正式提速数字，也没有替代上一轮编译器自举结论。下一步需证明消费者只读、分配点不逃逸和调用参数对应，再接入虚拟数组表示。源码补丁、测试输出和哈希已保存。

## 只读消费者与调用链证明

已增加 `网页汇编虚组消费。豫` 和 `网页汇编虚组调用链。豫`，并通过独立测试与类型检查。消费者只能读取目标数组、执行整数原语、分支和保持同一数组参数的自递归；写入、捕获、返回数组、未知调用和参数别名传播均拒绝。这个证明不意味着索引合法，也不允许省略读取或条件判断的类型检查。

调用链证明把此前初始化结果连到新分配点：首批要求函数体完整对应“新建数组、初始化、消费”三条指令，直接返回消费结果。初始化计数必须与分配长度是同一原子，新数组在消费实参中恰好出现一次，初始化结果不能被消费，消费者须通过只读证明。新鲜分配和严格用途共同满足其他消费者参数不含该数组别名的前提；不能仅靠消费者单体证明推断调用者没有别名。

临时诊断编译器在真实数组程序上自动识别了一个候选：`基准库_数组基准_提升函数131`，分配结果编号 2，消费者为基准库的满参递归函数，数组实参位置 0。这里的函数名与编号是报告结果，分析没有按这些值匹配。详见 `真实虚组候选.json`。

诊断接线随后恢复，默认编译器重新生成后与上一轮已完整验证的三代产物逐字节一致；诊断版生成的数组程序也与基线逐字节一致。因此本轮完成的是可作用于真实程序的组合证明，尚未消除默认产物中的数组，也没有新的正式提速数字。测试、研究编译器哈希和临时诊断补丁均已保存。

下一步生成阶段应以初始化表达式和消费者为键建立内部虚拟入口，以长度代替数组实体；每次读取在原位置解码并检查索引，然后以“索引加一”代入生成式。入口仍须执行原长度解码和容量检查。消费者的除法、全宽整数条件判断与非整数参数后备行为不能因虚拟表示而改变。若采用裸整数入口，需同时证明参数与递归传递满足表示要求；证明不足保留原 GC 路径。另需衡量表达式重算成本，不能仅因能够消除数组就默认认为一定更快。

## 保留检查的读取生成

新的带检查原型保留每次读取的 64→32 位范围检查及与数组长度的比较，再计算元素生成式。五进程交替、每进程六轮、首轮单列：200 万项基线 1.908 毫秒，带检查 0.512，旧原型 0.497；千万项基线 15.115，带检查 2.747，旧原型 2.525。千万项减少约 81.8% 时间，证明保留检查后仍值得继续，但仍不是默认编译器性能。见 `虚组带检原型.json`。

已增加通用的 `网页汇编虚组取值。豫`，生成容量检查、索引检查和整数表达式。原子解码必须由调用者在原语义位置完成；生成器接收 i64 值，不自行假定原引用一定是整数。正常路径不分配数组，数组越界失败路径通过空 GC 数组读取产生与真实数组相同种类的陷阱，不保留缓冲。

由豫言测试程序生成独立 Wasm 模块，45 次数值断言覆盖普通数列、仿射值、全宽溢出及 wasm32 长度边界；21 次失败对照覆盖负数、2^32、空数组和数组内界外索引。失败的异常类别及消息与实际 GC 数组读取逐项一致；没有对巨大有效长度实际分配数组。证据见 `虚组读取边界验证.json`。新测试及编译器入口类型检查通过。

默认生成仍未接入这一模块。下一步须生成完整消费者入口和调用者的快速路径，并处理未满足整数参数前提时的原 GC 后备路径。消费者原有除法、条件的 i31 限制、递归实参类型和读取顺序均须保留；不能仅因读取生成器通过边界测试就认为整个转换已获验证。

## 完整消费者入口生成

已实现 `网页汇编虚组整数。豫` 与 `网页汇编虚组生成。豫`。前者在只读证明基础上，假设所有非数组参数已经过整数守卫，验证运算、分支结果和递归实参都能保持整数表示；读取值由已证明的初始化生成式保证为整数。递归实参换类、非整数运算数和无法使用整数表示的分支会拒绝。

后者生成独立的内部 i64 函数，以长度代替数组形参，其他参数和局部值使用 i64。读取调用已验证的生成器；尾递归先把全部实参压栈，再反向赋给形参，变成循环，保留参数交换语义。非尾递归使用普通内部调用。比较结果可直接判断；其他整数条件仍通过原 box 和 i31 转换，不能把大整数条件误当作真值。除法保留 i64.div_s 的原错误位置。

豫言测试程序生成独立 Wasm 模块，31 次数值断言覆盖求和、全宽回绕、十万次尾递归及参数交换、非尾递归和条件值；7 个失败断言覆盖容量、读取越界、i31 条件上下界、除零及除法溢出。生成模块通过 Wasm 验证并实际执行；新测试与默认编译器入口的类型检查通过。详情见 `虚组消费者生成验证.json`。

默认调用者尚未接线，没有新的正式提速数字。下一步应以调用链描述建立每个 owner 的虚拟入口，保留原 owner 为同 ABI 后备函数。公开包装先按原位置解码并检查长度，再用无陷阱类型守卫检查消费者其余实参；满足前提时调用虚拟入口并装箱返回，否则调用原 GC 后备。新数组实参用长度替换，不能读取已经不再分配的数组局部值。原公开函数表仍指向原编号的包装，新增入口放在表外。全套回归、完整自举、冷缓存时限与真实基准仍需在正式接线后重新验证。
