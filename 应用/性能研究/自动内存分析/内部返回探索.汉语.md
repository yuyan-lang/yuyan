# 内部整数返回探索

本轮以已验证的 `yy索引种子.wasm` 产物为基线，进一步拆分排序成本。以下均为手改 Wasm 的诊断实验，尚未接入编译器，不计作语言已获得的优化。

## 读取复用未显示收益

分区循环在比较元素后，交换步骤再次读取同一元素。仅在已有读取支配该位置、且期间没有写入的片段，用原局部值代替第二次读取；另设只省去第二次宽度检查的对照。

五进程交替执行，各六轮，首轮单列，其余 25 样本取中位数：基线 58.725 毫秒，复用读取 58.674，省去支配路径中的重复检查 58.700。没有明确收益，不为这一原型新增编译器规则。数据见 `读取复用原型.json`。

## 内部返回表示有明确机会

当前分区私有入口 `$d756` 的参数已经部分为 i64，但结果仍为 `(ref null eq)`。调用者 `$d762` 把分区结果用作索引及整数运算，重复解码。原型增加独立的 `$rd756`，只让这一内部调用直接返回 i64，并使调用者把结果保存在 i64 局部值中。原公开入口、原分区函数和函数表保留；没有改排序算法、数组表示或索引边界检查。

五进程交替执行，各六轮：基线 59.191 毫秒，内部整数返回 53.787，减少约 9.1% 时间。400 万项的全部校验结果均为 6000002。数据见 `分区裸返原型.json`。仍未达到现有 C/Wasm 对照约 34 毫秒；这不是全语言性能结论。

## 编译器实现必须满足的证明

1. 返回证明必须带入口前提。仅内部已检查的整数参数可以当作整数；公开函数的通用后备路径可能返回其他表示，不能一并改掉。
2. 对递归函数，检查所有终止路径，并验证递归实参维持入口前提。不能仅因某条分支返回整数，就把全部递归调用结果当整数。
3. 保留分支、异常、尾调用及原检查位置。无法证明的非局部退出、动态调用或混合结果回退到引用返回。
4. 调用者必须满足对应私有参数签名，才能采用裸返回入口。未知调用及公开函数表维持原 ABI；不依赖手写源语言标注。
5. 传播返回资格后，重新计算局部整数和分支结果表示；引用使用点仍需按原语义装箱。先覆盖已证明的整数数组调用链，再扩展其他函数。

下一轮应先实现并单测这个入口条件下的返回证明，再接代码生成。需要特别测试零次递归的非整数返回、递归中实参换类、全宽整数、混合分支和公开入口的后备语义。原型没有这些通用证明，不能直接作为默认编译行为。

规模复测：每项三个进程、每进程六轮，首轮单列。100 万项为 14.259 / 12.630 毫秒，800 万项为 127.315 / 115.363 毫秒；全部结果与基线一致，收益约 9%～11%。详见 `分区裸返规模复测.json`。原型补丁与哈希已保存，编译器源代码本轮未改变，沿用上一轮完整验证的版本。

## 返回证明模块进展

已增加独立的 `网页汇编返回证明。豫` 与 `整数返回证明。测试。豫`，十项测试通过。输入是经过作用域验证的统一正则函数及其已保证为整数的参数编号；输出只表示该前提下的正常返回是否必为整数。整数常量与成功执行的整数原语建立事实，分支结果要求两条路径都能证明，递归调用要求实参保持原前提后才使用归纳假设。未知调用结果、混合结果、无前提的直接参数返回、参数换类和未知控制结构均保守处理。

模块暂未链接到默认代码生成，当前编译器行为没有改变，因此没有新的正式性能数字。正式接入还需把证明与现有私有参数签名绑定，生成独立整数返回入口，并在普通后备体清除只对快入口成立的结果资格。必须避免快速体推导出来的整数局部值泄漏进未检查参数的后备体。测试输出及源码、产物哈希见 `整数返回证明输出.txt`、`整数返回证明摘要.json`。
