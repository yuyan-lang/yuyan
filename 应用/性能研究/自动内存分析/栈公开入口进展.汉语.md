# 自动栈入口与 GC 后备

新增 `网页汇编栈入口。豫`，为已通过表示分析的函数生成公开引用 ABI 包装。数组创建必须是第一条指令，初值和长度只能来自整数常量或参数。入口先对实际使用的参数做无陷阱类型检查，再拆箱；未使用的环境参数不检查，私有体传入零占位。

`reserve(0,n)` 的容量不足、负长度、超出 64 MiB 探索上限或 memory.grow 失败返回 -1，包装随后以原参数尾调用原 GC 函数。参数类型未知也直接走 GC 后备。成功时写数组长度头并完整初始化每个元素；零初值使用 memory.fill，其他完整 i64 初值逐项写入。每次调用重新初始化，不缓存内容。整数返回通过原 box 约定重新装箱，单元返回恢复空引用。

新增 `栈入口生成。测试。豫`：数组创建及读取来自 ANF，私有函数和公开包装都由豫言生成器自动产生；手写的 GC 参考体与测试导出用于差分验证。参考 box/unbox 约定来自现有 Wasm 产物。

正常内存和强制增长失败两种夹具各通过 295 项数值/异常/路由对照、12 项单元返回检查和 3 项类型后备检查，共 620 项。覆盖零及非零初值、完整 i64 极值、空数组、负索引和超过 wasm32 的索引、数组越界、超过栈容量后的真实 GC 分配、类型错误、未使用的空引用参数、陷阱后复用。增长失败夹具内存始终为零页，所有调用由 GC 后备完成。正常夹具内存最高为两页，超过栈容量的调用没有扩大它。原始记录为 `栈自动入口验证.json`。新模块类型检查通过，Wasm 由 Node 实际验证并执行。

这个生成器仍未由默认统一后端导入。上层必须证明整个数组活跃调用图封闭、无宿主重入、无子数组分配且不逃逸，才可从零使用帧；单独的表示检查不是这份证明。下一步连接调用图资格、函数签名与根入口生成，再接入默认后端并重新做完整自举、冷缓存计时和多程序回归。当前没有新的默认编译器性能成绩，目标仍未完成。
