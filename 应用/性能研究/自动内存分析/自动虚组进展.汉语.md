# 自动消除中间数组

虚拟数组已接入默认 Wasm 生成。编译器自动识别“新分配、完整初始化、只读消费”的封闭调用链，用长度和元素生成表达式替代实体数组。没有源码标注、私有持久缓冲或求和公式，消费者仍逐项执行原来的整数运算。

公开引用 ABI 与函数表保留。原函数成为表外 GC 后备；公开包装先在原位置解码并检查长度，再以无陷阱检查确认消费者其他实参的整数表示，满足条件时调用内部虚拟入口，否则执行原函数。每次读取仍检查索引宽度和数组边界；其他整数条件继续保留 i31 限制，除法错误也不消失。

当前只处理主体恰为三步的调用链，不穿越额外的闭包字段读取或其他控制结构。消费者须通过只读、无外传、递归传参和整数表示证明。初始化须完整覆盖每个索引，生成式只含整数常量、计数器和加减乘。正式启用的表达式重算费用不超过七个节点；更复杂或无法证明的程序保留原实现。分析不按文件名、函数名、函数编号或输入规模匹配。

正常快速路径不分配中间数组，但公开返回的大整数等仍可能装箱，不能称整个函数完全没有分配。编译完成函数生成后会清空虚拟数组的模块分析上下文，避免额外保留完整中间表示。消除分配会改变相应的资源需求，不承诺与旧实现的资源耗尽时机相同。

## 正式编译产物测量

Apple M5 Pro，Node 26.3.0 / V8 14.6。每项五进程交替执行，进程内六轮；首轮单列，下表是其余 25 次的中位数。无并发构建，所有结果一致。C/Wasm 是既有相同算法源文件的 clang -O3 对照。

| 数组元素数 | 改前毫秒 | 自动虚拟数组毫秒 | C/Wasm 毫秒 |
|---|---:|---:|---:|
| 2,000,000 | 1.873 | 0.711 | 2.188 |
| 10,000,000 | 15.593 | 3.578 | 10.800 |

千万项相比改前减少约 77.1% 时间，稳态时间约为该 C 对照的三分之一。真实产物由编译器生成，不是手改原型。数据见 `自动虚组正式数据.json`、`自动虚组正式汇总.json`。

千万项首轮仍为约 22.30～23.17 毫秒，C 为 16.17～17.28 毫秒；虽已好于改前的约 50.60～53.31 毫秒，但首轮未追平 C。排序也仍落后，不能据此宣布全语言达到 C 或已达到性能极限。

## 语义与边界验证

34 项程序回归通过。新增端到端用例确认实际生成六个虚拟入口，覆盖仿射填充、全宽元素乘法与累加回绕、动态公开调用、零长度的非整数后备透传，以及不能优化的写入、缺失初始化和数组逃逸。八个非法路径的失败消息与改前逐项一致，包含负长、超宽长度、空读、越界、负索引、超宽索引、初始化除零和非整数累加值。不是只对未触发优化的程序进行测试。

数组产物的导入、导出和公开函数表与改前一致，见 `自动虚组模块边界.json`。完整自举、冷缓存时限和其他程序复测结果将在完成后补记。

最终验证：规定的本机自举完成，三代四代逐字节一致；两种入口类型检查通过。清理分析上下文后的完整冷编译缓存 Wasm 自举为 21.68、19.92 秒，二代三代逐字节一致，未清操作系统页缓存。定稿数组产物与正式测量产物逐字节一致。

斐波那契、筛法、矩阵、排序的定稿产物与上一轮逐字节一致。树程序所在库包含未调用的数组辅助函数，因此产物增加了虚拟入口；五进程交替复测深度 20，旧 14.414、新 14.297 毫秒，结果一致，未见退化。详见 `自动虚组产物复核.json`、`自动虚组树复测.json`。

单独进行六轮千万项带 GC 跟踪诊断，仅统计运行线程 1：事件数从 8 到 4，记录区间 allocated 合计从 406,631,008 到 6,669,144 字节，记录到的最大堆对象量从 85,280,240 到 5,359,112 字节。它们不包含末次 GC 后的尾段，不是精确总分配、真实峰值或进程 RSS；跟踪会扰动时间。正常路径的中间数组分配消除可由生成代码直接确认，数据只是辅助证据。见 `自动虚组GC汇总.json`。

当前结论：数组稳态已超过既有 C/Wasm 对照，首次执行仍未追平；排序的代码及此前约 1.62 倍 C 耗时的差距尚在。整体目标保持未完成。
