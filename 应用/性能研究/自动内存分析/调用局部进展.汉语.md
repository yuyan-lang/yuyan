# 自动识别调用期间的局部对象

已把跨函数逃逸摘要接入分配点报告。源码不需标记，公开 ABI 不变，不使用持久私有缓冲；这轮增强诊断证明，没有改变程序的分配方式，也没有新的运行时提速结论。

此前，一个元组只要作为调用实参，就无法在分配报告中获得不逃逸结论。现在对已知静态调用的每个实参，查询已收敛摘要：既不能被外存，返回值也不能可达该参数，还须排除未知副作用。只要其中一个用途不满足条件，就保留“未证明”。对象传出当前函数、被容器捕获、动态调用和复杂控制仍保守拒绝。

例如 `p = (整数值, 整数值); 消费(p); 返回整数`：当消费函数仅读取字段并进行整数运算时，可以证明调用不会保留 p。若消费函数返回 p、返回包含 p 的新对象，或者调用未知函数，则不能用这层证明放行。即使返回值随后被丢弃，本轮也仍保守拒绝，尚未分析该返回值的最后使用。

报告区分两种结论：

- 仅在当前函数中读取合法字段：保留此前的局部元组消除候选。
- 包含已证明不保留的静态调用：标为“调用局部候选，尚未改变分配”，所有权仍为“未证明唯一或线性”。

重复把同一对象传给两个形参，也可能不逃逸，但这不是唯一引用证明。未来的存储复用必须另行证明没有活着的别名，不能用词法出现次数替代。当前对象使用的是 Wasm GC 引用表示；把它放到线性内存栈上，还需要新的内部表示与消费者入口，不能直接用栈地址替换 GC 引用。

十项新的中间表示测试覆盖消费、返回参数、返回容器、参数位置区分、重复实参、未知调用、返回字段以及调用后返回原对象。已有七项分配报告回归也通过。测试直接构造 IR，避免前置内联把对象消掉。

下一步需要字段路径与返回别名分析，再与控制流上的最后使用及容器生命周期结合。所得事实作为编译器内部的证明信息：优先消除整个分配，其次改变布局；只有证明完备且实测有收益时，才考虑区域存储或原位复用。暂不要求用户采用线性类型标注。

实际检查树、快速排序、矩阵，原始静态分配点分别为 1713、1684、1689，新增调用局部候选均为零。这些统计包含库与未执行分支，不能当作动态分配次数。三者的新 Wasm 产物与此前经过性能验证的默认产物逐字节相同。负结果说明下一步应细化字段与返回值来源，而不是把窄证明包装成运行时优化。

采集报告时，Node 宿主下的长调试输出出现截断，未以缺失输出推断候选数。最终改用已完成自举的原生 yy3_bs 采集完整报告；记录在 `调用局部实测摘要.json` 及三个报告文本。此轮没有改动宿主工具。

最终验证：规定的本机自举、两种入口类型检查通过，三代四代逐字节一致；Wasm 禁编译缓存自举为 **21.04、21.86 秒**，二代三代逐字节一致，未清空操作系统页缓存。新增十项、既有七项分配测试及八项调用摘要测试均通过。产物校验和见 `调用局部产物摘要.json`。
