# 自动栈的按需长度复用

新增 `网页汇编栈长度复用。豫`。在同一个正则区域中，对同一数组的多个实际范围检查，记录第一次检查的指令编号。生成器在原来的第一次头部读取处保存长度，后续检查使用该局部值；第一次索引的 64 位范围检查仍在头读取之前。不会在函数入口或未执行的分支中提前读取长度。

该证明依赖封闭栈调用图、SSA、表示验证与不可变的数组头。调用可以修改载荷，不能修改长度。每个子分支独立选择来源，不向父区域或另一分支输出事实。已有范围证明或重复访问分析已经省掉的检查，不得作为长度来源；只剩一次实际检查时不创建额外局部。检查后备体保持原样。

当前真实排序产物中，只有根函数和排序私有函数改变：各自的头部读取由三次降到一次，范围检查数量仍各为三次。841 个具名函数签名及导入导出不变。见 `栈按需长度接口审计.json`。

## 验证范围

- `栈长度复用。测试。豫` 的十三项测试逐槽验证长度来源、已省检查的排除、数组身份及分支隔离。
- 原有循环夹具没有实际触发本优化，其二进制与上一版完全相同，因此复用既有百万项验证，不能把它单独当作新优化的覆盖证据。
- 新增 `栈长度生成。测试。豫`，从正则数据生成先读、跨函数写入、再读的程序和保留完整检查的参考体。5,799 组、12,201 项检查覆盖不同帧、相同和不同索引、载荷变化、负数及大整数索引、异常后内容，并确认实际生成长度槽、第一次范围检查仍先于头读取。
- 最终排序产物通过 6,919 组排序与 10,287 组分区，共 270,003 项返回值、异常和内容检查；根函数另通过 1,024 个长度及空数组异常检查。

记录为 `栈按需长度专用差分.json`、`栈按需长度排序差分验证.json` 与 `栈按需长度根与既有夹具.json`。最终产物还优化了根函数，与仅改排序私有函数的原型不完全相同，故另行测量最终产物。

## 性能

入口提前读取长度的原型未显示收益，未采用。按需原型两批热轮分别为 34.796 → 33.865 ms、34.439 → 34.092 ms。最终产物的五进程配对改善较小，因此追加九进程独立复测。

每进程六轮，轮换版本顺序；四百万元素，校验和全部为 6000002。首轮和其余热轮分别取中位数。计时包含分配、填充、排序及校验和，排除参数解析和打印。

| 最终产物复测 | 旧版首轮 ms | 新版首轮 ms | 旧版热轮 ms | 新版热轮 ms |
|---|---:|---:|---:|---:|
| 五进程，与 C 同批 | 45.406 | 44.074 | 34.044 | 33.944 |
| 九进程独立配对 | 45.753 | 43.625 | 33.963 | 33.536 |

九进程中七组热轮中位数改善，整体约减少 1.3%。收益较小，不能引用最初原型的较大改善作为最终结论。五进程同批 C 热轮为 33.028334 ms，新版仍慢约 2.8%，目标尚未达成。不能将九进程新版时间与另一批 C 时间直接比较。

原始记录见 `栈长度复用原型实测.json`、`栈按需长度原型实测.json`、`栈按需长度独立复测.json`、`栈按需长度排序实测.json` 与 `栈按需长度九进程复测.json`。

完整本机自举与两项类型检查通过，`yy3_bs` 与 `yy4_bs` 逐字节一致。默认模式使用 `--do-not-load-cache --parallel -j 18` 的完整冷缓存 Wasm 自举为 23.08、23.21 秒，种子及二、三代产物一致。该自举未开启实验栈，不能归因于运行时长度复用提速。见 `栈按需长度本机验证.json` 与 `自动栈按需长度冷自举.json`。

本机与 Wasm 编译器生成的实验排序二进制一致。其余五个基准、关闭实验开关的排序产物与上一版逐字节相同，未重复测量这些程序。见 `栈按需长度六核产物.json`。实验栈开关仍默认关闭。

后续可测试：对于已有长度局部的检查，将正常路径的 64 位索引范围判断合并，并在失败分支保留原有异常区分；第一处头部读取及首次检查顺序继续保持。此方向尚未实现或计入成绩。
