# 自动构造布局与分配消除

本轮把分析结果用于真实代码生成。源码无需标注，公开 ABI 保持原样，不使用持久私有缓冲。优化后的对象仍由 Wasm GC 管理；尚未实现通用栈分配或完整线性类型推导。

原先一个动态树节点需要两个对象：构造器保存标签与载荷引用，载荷元组再保存子树。现在编译器证明创建者的形状、消费者的字段用途及调用者中的封闭使用后，生成内部专用入口，将标签和子树字段合成单个 GC 结构。载荷元组分配消失，字段访问也少一次间接读取。原公开函数继续处理通用表示。

证明区分普通公开值、创建者产生的对象和虚拟载荷。创建者支持形状一致的有限字段构造和自递归；消费者逐路径追踪标签、字段类别以及返回值。共享子树可以保留，不能把单次调用者使用当作子树唯一所有权。载荷自身须单次使用；共享载荷、私有对象外传、未知调用、形状不一致和无法证明的控制流均放弃优化。共享常量节点保留公开表示，混合路径生成检查；能够确定布局的路径直接读取。

本轮的专用形状证明独立于此前诊断用的跨函数来源摘要。它覆盖受限但实际有用的调用链，不意味着所有非逃逸对象都已被发现。当前限制包括创建者至多四个参数、函数至多 128 个局部值、载荷至多四个字段，以及调用者中相邻的静态创建与消费调用。预算或证明不足保留通用实现。

## 实测

Apple M5 Pro，Node 26.3.0 / V8 14.6；与已有 C/Wasm 对照使用同机引擎。每项五个独立进程，每进程六轮，轮换执行次序；首轮单列，表中为其余 25 次的中位数。没有同时执行构建。

| 树深度 | 改前毫秒 | 仅静态包装内联毫秒 | 自动单对象毫秒 | C/Wasm 毫秒 |
|---|---:|---:|---:|---:|
| 18 | 3.871 | 4.136 | 2.790 | 4.391 |
| 20 | 20.328 | 20.559 | 13.796 | 18.0395 |

深度 20 相比改前减少约 32.1% 时间，相比这一 C 对照减少约 23.5%。这只是该树程序的结果，不代表整个语言已经超过 C。完整数据及首轮耗时见 `单对象正式数据.json`、`单对象正式汇总.json`。

## 验证与后续

31 项 Wasm 程序回归和四组编译器内部回归通过。新回归包含共享子树、多个消费者、对象外传、四字段构造、全宽整数、常量与动态同标签混用，以及不应被提前拆箱的普通值。对照产物的导入、导出和公开函数表一致。本机规定三级自举通过，三代四代逐字节一致；两种入口类型检查通过。Wasm 完整冷编译缓存自举为 21.65、21.68 秒，二代三代逐字节一致。

C 树计时包含显式释放；豫言在同一进程连续执行六轮，由引擎决定 GC 时机。该比较反映两种现有运行方式，并非逐轮强制等量回收的比较。对象分配减少可由生成指令直接确认，不能由时间降幅推断出相同百分比的内存下降。

后续优先补足自动值域、字段路径、别名与最后使用证明，再据此消除对象、收紧布局或复用已死亡存储。不应先要求用户采用复杂类型标注，也不应以“不会逃逸”直接推出“可以原地改写”。

## 当前全组六轮复测

同样使用五个进程、首轮单列、25 个后续样本取中位数。与上表是不同批次，树的 GC 与运行波动应保留呈现。每项全部结果与 C 一致。

## 分配证据及下一步实验

生成代码中，每个动态内部树节点从 `tuple + variant` 两次分配变为一次 `flat2` 分配。深度 20 有 1,048,575 个内部节点，因此每轮省去这么多个载荷对象；叶节点继续共享常量。没有把共享子树误当独有对象，也没有改变树算法。

另外单独执行带 GC 跟踪的六轮深度 20 工作负载，只统计运行线程 1：改前/改后 GC 事件为 37/23，记录区间的 allocated 合计为 459,679,104 / 249,797,112 字节，记录到的最大堆对象量为 327,192,560 / 112,699,736 字节。这是一次诊断样本，事件间分配统计不包含末次 GC 后尾段，最大堆对象量也不是进程 RSS；不可解读为精确总分配或稳定峰值。原始跟踪与限制见 `单对象GC汇总.json`。

进一步手工修改 Wasm 产物试验 unsigned 32 位 GC 数组，仅对现有数据范围有效，未接入编译器。五进程复测：数组从 14.646 到 11.761 毫秒；排序从 62.337 到 66.858 毫秒，反而退化。说明布局更小不保证更快；目前不实施统一窄化。原型缺少自动值域证明，不能用于通用程序，也不能作为已完成的自动分析成果。详见 `窄组原型数据.json`。
