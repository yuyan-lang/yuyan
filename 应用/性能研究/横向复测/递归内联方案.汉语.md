# 递归内联方案

这是单层间接内联后的第二阶段实验方案。已完成五轮冷编比较：AOT 中位数 239.53 秒，Node 193.47 秒，产物全部一致，AOT 仍慢约 23.81%。Node 对同一冻结函数 1205 的调用序三选择函数 1205，并继续展开自递归；当前原生实现跳过自身且不展开内联体里的调用。完整构建比较仍在运行，本方案尚未实现。

沿用已授权的 `--内联样本` 及现有 JSON 字段，不增加公共 ABI、对象布局、命令行参数或兼容层。冻结样本拟记录函数 1205 调用序一到 1494，以及调用序三到 1205；原指令调查已确认后者是类型三的间接尾调用，自身类型亦须再核对。

每个原始调用者共享新增展开字节预算 6000，展开深度上限 64。每次展开按被调函数原指令段字节数扣预算，预算或深度耗尽即保留原调用。目标守卫、判空及验签仍保留；第一阶段的旧异常与尝试表目标拒绝规则沿用。内联体内允许符合既有小函数规则的直接叶调用展开，并计入同一预算。无样本仍走原路径。

把当前函数号、原调用序、局部映射基与尾状态视为每层展开的上下文：进入被调体时保存调用者状态，改用被调函数号并从原调用序零开始；结束后恢复。新增层次复用原块临时、控制栈与事实栈。内联体里的尾调用在完成守卫分支后须跳出最近内联层；只有原函数语境才直接返回。禁止继续使用会越过调用者后续代码的裸返回。

验证须覆盖递归命中与预算耗尽回退、其他目标、调用序恢复、局部映射恢复、内层尾调用后外层继续计算、多结果、异常捕获、判空与错签、GC 存活压力。另核对无样本产物与第一阶段一致。冻结编译器须经冷编产物对照，再做同机交替测速及完整构建比较，Node 保持默认策略。若代码增长或寄存器压力抵消收益，保留实验结果并调整方案，不合入未证实的候选。

本方案扩展第一阶段的单层能力。用户已于本会话明确答复「允许调整」，授权按上述方案推进。当前已实现共享预算、逐层上下文保存及恢复、内层尾调用退出最近层；尚未组合参数事实转存。

备用机生成器完成 701 项构建、退出零。上下文测试完成 421 项构建，运行退出零，覆盖两层函数号、调用序、局部映射与深度恢复，预算累计扣除、恰好足够、不足及深度耗尽；尾态在递归展开中保持退出最近块。标准 WasmGC 运行夹具工具完成 326 项构建，生成四个普通及尾调用模块，分别以零与 128 条填充指令触发深度及预算耗尽。每个模块递归 80 次，并在外层继续加七、通过同一调用点调用其他目标；Node 与备用机 AOT 四项均退出零。分派函数的实际机器码分别有 64 与 40 个目标一的守卫，证明确已展开并在限额处回退。主机生成器正在构建；异常、多结果、GC 与冻结编译器及正式性能仍待复验。
