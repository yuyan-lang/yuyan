于 pit-mac 禁缓存，更番编同一打印探针 `豫言操作系统/裸机/普通探针/打印。豫`。改前以洁净快照 `9aa6a9d7e` 自举所得 `yy4_bs.wasm`，改后以 `c1a66871c` 自举所得 `yy4_bs.wasm`。两快照之探针源码 SHA-256 同，皆生其出。

### 负载与调用形态

始测时负载均值为 2.22 / 2.00 / 1.77（近一、五、十五分钟）。第四组始、终为 1.63 / 1.86 / 1.75 与 1.72 / 1.87 / 1.75；第五组始、终为 1.81 / 1.88 / 1.76 与 1.93 / 1.90 / 1.76。未逐进程录负载；第五组负载上升且旧直调较慢，诸样仍悉留于统计。

静审：类型擦除先于跨模块优化；c1 默认开此优。无捕直调者为三参闭拉姆达，局绑之名唯被满三参而调；其函体最高绑序二，小于元数三，无自由名，亦不逃，合局部直调之守。捕获者读取外层动偏，故不合无捕之守，应仍为闭包。既有 AST 回归已正验满参无捕之转，反验有捕之留。

又以本机 LLVM 22.1.7 观两 Wasm。其能读段，然不解 WasmGC `call_ref`，且无符号可系此源之定义。可解之全模块计数，旧/新 `call_indirect` 为 824/824，`return_call_indirect` 为 368/368，`call` 为 5519/5519，`return_call` 为 4032/4032，`ref.func` 为 23/24。此等全模块计数不足断目标函数直/间调之异，故不妄断逐函数之 Wasm 形。Node 时与可解调用计数俱未显有义之增，此轮止，不复开第二微基准。
