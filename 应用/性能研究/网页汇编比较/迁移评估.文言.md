# 豫言迁网页汇编与组件互通议

后增可选编译宿主，授可信 P1 程序以原生进程、完成事件、实径与包上下文真锁。此自定义扩展也；WIT 双向绑定与完整 Wasm 自举尚未成。

考于二〇二六年九月七日，美东时；源码本于 `1a1bb90f`。详考见《迁移评估.汉语.md》，实测见《结果.汉语.md》。此行惟增实验与文书，编译器、运行时未改。

## 可行与未备

豫言应用可主以 WebAssembly 行之，Component Model 可为异言互通之约。今 LLVM 后端已成 P1 核心模块，此验又成命令组件，校验而行之。然欲尽去原生，而功能、性能无损，证据未足。

应用以组件发行，C 所作运行时亦可编入其中；宿主仍须备引擎与所导入之能力。编译器若亦欲居标准 WASI，则其今所调用之 llvm-as、opt、clang、make 与子进程调度，皆须另筹。可使前端为组件，工具链归宿主；若连工具链亦尽求可移植，则当移植之，或自为 Wasm 生成与链接。

与他软件互通，须双方有约。原生软件可嵌组件宿主，或实现 WIT 导入；旧有 C ABI、平台框架，不因生成 Wasm 而自通。[宿主接口](https://docs.wasmtime.dev/api/wasmtime/component/index.html)、[异言支持](https://component-model.bytecodealliance.org/language-support.html)。

## 所当治

今十六字节值、显式栈、复制回收与续延可留；尾调用为运行之所必需。内用 i128 之约，不可径充 Canonical ABI。包构建今传原生清单，WASI 拒之，当依目标分列其库。

网络与异步等待，今适配尚以明错止之；P1 之封装不补其实现。子进程、终端原始模式、拼音转换，或取宿主能力，或另作可移植实现。现后端线性内存限二百五十六 MiB，单堆默认限六十四 MiB；此乃今实现之限，非 Wasm 皆止于此。

## 互通之约

WIT 定契约，Canonical ABI 定传值，WASI 定系统接口。官方今已发 WASI 0.3，引入原生异步；本机 Wasmtime 48.0.1 亦列异步选项，然此验所成乃 P1 转 P2 命令组件，未验 P3 异步。[路线图](https://wasi.dev/roadmap)、[传值之约](https://component-model.bytecodealliance.org/advanced/canonical-abi.html)。

初宜通整数、小数、字符串、字节串、记录、有限变体、可选值与结果。泛型当于界上具体化；闭包、引用、对象图、续延，不可以内存地址妄传，可约以资源句柄及方法。异常当化为明定结果，续延不得逸出外调生命周期。移动回收须与句柄根相合，拥有、借用、销毁皆有定法。

WIT 名惟容 ASCII kebab-case，故中文名留于豫言，别定稳定外名。资源句柄与借用非改名即足。[WIT 规范](https://component-model.bytecodealliance.org/design/wit.html)。

字符串与列越独立内存，常须分配、复制，异编码又须转之。句柄可免尽复制对象，读取其内容则未必免。宜以整次解析、批量计算为方法，勿逐元素往返。内部诸书可并入一组件，以存优化之利。[Canonical ABI](https://raw.githubusercontent.com/WebAssembly/component-model/main/design/mvp/CanonicalABI.md)。

## 次第

先保原生为较，正式成组件，并按目标构建依赖。次作双向绑定，以异言调用豫言、豫言调用异言验之，兼验中文、列表、错误与资源释放。再接异步，明暂停、恢复、取消、重入与资源寿命。复测小调用、批量调用、字符串、HTTP、编译器实务与内存峰值，而后议以 Wasm 为默认。

系统能力、实务性能、自举皆备，乃可议去原生；获互通之益，不必先更 GC、弃 LLVM。线程及组件 memory64，各依所定工具链验之，不以核心 Wasm 有之而谓全栈皆备。[Wasmtime 状态](https://docs.wasmtime.dev/stability-wasm-proposals.html)、[SDK 所限](https://github.com/WebAssembly/wasi-sdk#notable-limitations)。
