# 豫言编译器

解析、检查并编译豫言程序。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为可执行文件类型，不可被其他包依赖；共享编译功能请依赖编译器核心库。入口只调用库 编译器入口 的「编译器主」，豫构也用它（提案 00007 合一）。类型典中的入口和文件名见包配置，程序产物为 `yy`。

## 使用

在仓库根目录运行：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 检查 豫言编译器
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 豫言编译器
```

依赖及说明路径以 [包配置](豫言编译器。包。豫) 为准。构建不会自动运行程序；有发布或服务副作用的工具应先阅读其入口源码。

## 原生产物

给编译器参数 `--目标 本机 --执行器 yy执行器.wasm` 时，最终链接直接写出本机原生可执行文件（macOS 为 Mach-O，Linux 为 ELF），不经 `.wasm` 文件：豫汇模块在同一进程里交给裸机后端的「原生产物」，经预编二与寄存器降级生成（提案 00007 第 3 步）。`--降级缓存 路径` 指定降级缓存：执行器函数按号、客体函数按内容缓存机器码，整个产物按摘要缓存，程序不变时重建直接取用。原生编译器生成大程序（客体超过 4 MiB）时另起子进程，免得最终链接进程的堆不够。经豫构构建时，这些参数写在 `--` 之后，例如：

```sh
./yy豫构.exe 构建 某包 --输出 yy某包 -j 24 -- --目标 本机 --执行器 yy执行器.wasm
```

编译器因此依赖裸机后端。

## 浏览器检查点

给编译器参数 `--浏览器检查点`（默认关）时，最终链接写 `.wasm` 时一并装入浏览器宿主需要的两样东西：顶层异常处理器（导入 `yuyan:browser/v1` 的 `fail`，以程序没有接住的异常字符串报错）与时限检查点（导入 `yuyan:browser/v1` 的 `check`，每 1024 次函数进入调用一次，宿主借此打断死循环）。浏览器编译宿主（`豫言操作系统/宿主/浏览器/编译器/`）编译用户程序时总加这个参数；云仓构建浏览器编译资源时，编译编译器本身也加它。实现见编译器核心的 `编译步骤/代码生成/网页汇编浏览器检查点。豫`。经豫构构建时写在 `--` 之后，例如：

```sh
./yy豫构.exe 构建 豫言编译器 --输出 yy浏览器种子.wasm -j 24 -- --浏览器检查点
```

原生目标与汇编树码配合这个参数留待后续版本。

## 装载单元

给编译器参数 `--目标 单元 -o 目录` 时，最终链接改为按文件编译顺序给每个模块各生成一个装载单元（提案 00003 脚本运行模式）：单元是只含本模块代码的豫汇模块，引用别的模块的函数与全局写成从“单元”的导入，零号表、表基与异常标签从“运行时”导入。单元写成目录下的“单元序号.wasm”，“顺序.txt”按装载次序列出各单元。诺节宿主遇到这样的目录时依次装入各单元并运行，例如：

```sh
./yy豫构.exe 文件 甲。脚本。豫 -j 24 -- --目标 单元 -o yy甲单元
node 豫言操作系统/宿主/节点/宿主.cjs yy甲单元
```

再加 `--执行器 yy执行器.wasm` 时（macOS ARM64），每个单元另写“单元序号.单元”：豫汇模块连同按单元模式预编的机器码、重定位与符号（格式见《豫行格式》“装载单元”）。再给 `--降级缓存 目录` 时按内容缓存原生单元（键是单元豫汇模块、执行器与编译器自身的摘要），命中就直接拷贝。原生单元由豫构的「运行」装进进程运行（见豫构包说明“运行脚本”）。

逐组编译（库 编译器核心 的 `编译步骤/总体过程/逐组编译。豫`）供豫构的「交互」用：一组（一句，或「乃」加随后的定义）写成一个源文件，在调用者的进程里依次做语法分析、名称解析、类型检查、擦除与闭包转换，检查后定义只记进内存里的阶段缓存；前面各组的导入在后面的组里重放，前面各组作打开的模块排在其后。组单元按交互模式生成：没接住的异常交给会话给的处理函数，处理后返回。
