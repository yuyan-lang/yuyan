# 底层模式（无垃圾回收编译模式）

底层模式是豫言编译器的第二种编译模式：用**普通豫言语法**书写执行器、驱动、文件系统、张量内核等系统代码，编译时不使用垃圾回收，也不依赖标准库运行时，直接生成标准 Wasm 模块。产出的模块可在 Node（诺节）等 Wasm 引擎里运行，也可由豫言操作系统的寄存器降级后端编成 ARM64、x86-64 机器码（原生二进制与裸机）；用到小数（f64）、单精度（f32）、长整数（i64）、向量（v128 SIMD）与原子操作的模块在降级前先经数值转译（见 `豫言操作系统/裸机/文档/数值降级.汉语.md`）。它取代此前自造的括号式“低阶语言”：语言只有一种，差别在于编译模式。

## 一、声明模式：在包描述里

编译模式是**包的属性**，在 `包名。包。豫` 中用可选字段声明，不看文件扩展名，源文件仍一律是 `。豫`：

```
「编译模式」者『底层』也。
```

- 取值只有 `高级`（缺省，有垃圾回收）与 `底层`。
- 同一依赖闭包内的包必须同一模式。豫构在解析包图时检查，不一致即报错；因此底层包不能依赖标准库，只能依赖底层包（如 `底层库`）。
- 豫构读取该字段，把“底层包文件列表”写入传给编译器的包上下文（第三版格式，仅在含底层包时出现；无底层包时上下文与旧版字节相同，缓存不受影响）。编译器据入口文件所属的包选择管线。
- 底层可执行包的产物是 Wasm 模块而非原生程序：豫构不做原生链接，`「文件名」` 仍须以 `yy` 开头或以 `.exe` 结尾（如 `yy客体执行器.wasm`）。

## 二、语言子集

底层模式沿用全部豫言语法与类型检查；差别只在**后端能接受什么**。凡不可入无垃圾回收之境者，编译期明确报错，不会退回垃圾回收。

| 支持 | 不支持（报错） |
| --- | --- |
| 整数、爻、单元 `元`、`若…则…否则`、`虑`、`；` | 元组、构造器（枚举）、`鉴` 于构造器 |
| 小数（f64）、单精度（f32）、长整数（i64）、向量（v128） | 字符串值、异常、续延 |
| 对整数常量的 `鉴`（编译为分派） | 闭包、把函数当值传递、间接调用 |
| 一阶函数：全局函数、局部函数（按调用处使用情况处理，见下） | 引用类型 `引用类`、数组、字典等运行时数据结构 |
| 自递归与尾调用（尾位置的自调用变成回跳） | 同一个函数在不同调用处用不同的值类型（泛型函数须单态使用） |
| 外部调用原语（见 `底层库`）、类型声明 `立「元类型」`（只作类型用） | 未在 `底层库` 中给出的外部调用名 |

值的类型对应 Wasm 的数值类型：整数、爻、单元是 **i32**（整数按补码回绕，爻为 0/1，单元为 0）；小数是 **f64**；单精度是 **f32**；长整数是 **i64**；向量是 **v128**。函数恒返回一个值。简树本身不带类型，后端的**类型推定**按原语的签名、字面量、调用与绑定关系双向推出每个变量与每个函数结果的类型，推不出的按 i32；同一变量推出两种类型时报“类型不一致”。

## 三、函数与循环

- **顶层函数**：`「名」乃化…也。「名」者会…也。` 编译为 Wasm 函数；仅被导出函数（见下）沿调用图可达者才会生成。
- **自递归**：豫言编译器已把满参递归提升成全局函数；后端把尾位置的自调用改成回到函数起点的跳转（`br`），非尾位置的自调用是普通调用。互递归需要自行改写（豫言无前向引用）。
- **局部函数**（`虑「f」者（化…）也（会…）而`、`递归虑「f」其…者…而`）按使用情况三选一：
  1. 不被调用：丢弃；
  2. 只被调用一次且不自调：展开进调用处；
  3. 只被调用一次且自调都在尾位置：做成**内联循环**（共用外层函数的局部变量，可读写外层的可变格）；
  4. 其余：提升为全局函数，自由变量作为前置形参（**不能捕获可变格**，否则报错）。
- 因此惯用写法是“单次调用的局部递归函数 = 循环”。循环形参可以是任何值类型，例如小数、单精度或向量的累加量。

## 四、可变格

`新格`、`读格`、`写格` 提供函数内的可变变量：

```
虑「和」者「新格」于「零」而
虑「位」者「新格」于「零」而
递归虑「当」其化「有」而「整数」者会「无」而
  若「小于」于（「读格」于「位」）于「数」
  则（（「写格」于「和」于（「加」于（「读格」于「和」）于（「读格」于「位」）））；（「写格」于「位」于（「加」于（「读格」于「位」）于「一」））；「当」于「元」）
  否则「读格」于「和」
而「当」于「元」
```

格编译为 Wasm 局部变量，必须直接由 `虑 名 者 新格 … 而` 绑定，且只能作 `读格`/`写格` 的首个实参；不能作为普通值传递或被提升函数捕获。其他类型的格用 `数值格` 模块的 `新小数格`/`读小数格`/`写小数格` 及单精度、长整数、向量的同名形式，格的类型由初值决定。

## 五、内存、静态数据与声明

- 线性内存的读写：`读四`、`读二`、`读二有符号`、`读一`、`读一有符号`、`写四`、`写二`、`写一`；`内存页数`、`内存增长`、`内存复制`、`内存填充`。其他类型的读写见第六节（`读小数`、`读单精度`、`读长整数`、`读向量` 等）。
- 顶层值定义必须是**编译期常量**：整数常量、常量间的整数运算、对其他常量的引用、`静态串` 的结果。它们在函数里出现时被代入为数字。小数等其他类型的常量写在函数里（如 `「单」于「0.5」`）。
- **声明**是顶层值定义：`「内存」者（「声明内存」于「初始页」于「最大页」）也。`；`「数据区」者（「声明数据区」于「起」于「止」）也。` 各只能声明一次；使用 `静态串` 前须先声明数据区（编译器先求含声明的定义，故书写顺序无关）。
- **共享内存**：`声明共享内存 初始页 最大页`，供原子操作与多线程使用（Wasm 要求共享内存有最大页数）。
- **六十四位地址内存**（memory64）：`声明内存六四`（或 `声明共享内存六四`）。此时一切地址都是长整数，用 `内存六四` 模块的 `长址读四`、`长址写单精度`、`长址读向量`、`长址内存页数` 等；用整数地址的函数会在编译时报类型不符。待办事项：六十四位地址下的静态串、内存复制与填充、原子操作的长址包装。
- `「串址」者（「静态串」于『你好』）也。`：把字符串按 UTF-8 加零字节放入数据区，值为其地址；相同内容共用一份。
- **内存的导入与导出**：`「来处」者（「声明内存导入」于『环境』于『内存』）也。` 使模块不自建内存，改从宿主导入（模块名、字段名为字符串字面）；页数、是否共享、是否六十四位地址仍由内存声明给出，须先声明内存，只能声明一次。宿主据导入的限制建内存，多个实例、多个工作线程可以共用同一块共享内存。`「出口」者（「声明内存导出」于『内存』）也。` 把内存以该名导出，供宿主读写，可声明多次。声明了其一，模块就走新路径。待办事项：导入共享内存时数据段在每次实例化都会重写，这时宜避免静态串。

## 六、数值类型与原语

`寻观「底层库」之书。` 只导入整数部分（与旧版相同，旧版编译器仍能编译只用整数的程序）；数值扩充另用 `寻观「底层库」之「数值」之书。` 导入。各原语都只是外部调用名的包装，编译器内联后对应一条 Wasm 指令（取整、比较等的语义即 Wasm 的语义）。

- **小数（f64）**：字面量 `「1.5」`；`小数加`、`小数减`、`小数乘`、`小数除`、`小数最小`、`小数最大`、`小数复号`、`小数绝对值`、`小数取负`、`小数向上取整`、`小数向下取整`、`小数截断`、`小数就近取整`、`小数开方`；比较 `小数等`、`小数不等`、`小数小于`、`小数大于`、`小数小等`、`小数大等`；转换 `小数转整数`（越界陷阱）、`小数饱和转整数`、`整数转小数`、`无符号整数转小数`、`小数转长整数`、`小数饱和转长整数`、`长整数转小数`、`小数转单精度`、`单精度转小数`；位型 `小数位`、`位转小数`；内存 `读小数`、`写小数`；`小数选择`。
- **单精度（f32）**：常量写 `「单」于「0.5」`（小数就近舍入）；运算、比较、取整、开方与小数同名而以 `单精度` 为前缀（`单精度加` … `单精度开方`、`单精度等` …）；`单精度转整数`、`单精度饱和转整数`、`整数转单精度`、`无符号整数转单精度`、`单精度位`、`位转单精度`、`读单精度`、`写单精度`、`单精度选择`。
- **单精度超越函数**（`单精度函数` 模块，普通函数，范围归约加多项式逼近，常用范围内相对误差约 1e-6）：`单精度指数`、`单精度对数`、`单精度双曲正切`、`单精度逻辑斯谛`（S 形函数）、`单精度正弦`、`单精度余弦`、`单精度幂`。待办事项：非正规数、上溢为无穷、零与负数的对数、极大自变量的三角函数只作了粗略处理；四车道向量版本尚未提供。
- **长整数（i64）**：`「长」于「一二三」`（整数按有符号扩展），超出三十二位的常量写 `「长常量」于『123456789012』`（十进制字符串，编译期解析）；`长整数加`、`长整数减`、`长整数乘`、有符号与无符号的除与余、`长整数位与`/`位或`/`位异或`、`长整数左移`、`长整数有符号右移`、`长整数无符号右移`、循环移位（移位量也是长整数）；`长整数为零`、`长整数等` 与有符号、无符号比较；`长整数转整数`（取低三十二位）、`整数转长整数`、`无符号整数转长整数`；`读长整数`、`写长整数`；`长整数选择`。
- **向量（v128）**：同一向量按形状解读——字节十六（i8x16）、短整数八（i16x8）、整数四（i32x4）、长整数二（i64x2）、单精度四（f32x4）、小数二（f64x2）。
  - 内存：`读向量`、`写向量`；装载扩展 `读字节八扩展`、`读字节八无符号扩展`、`读短整数四扩展`、`读短整数四无符号扩展`；`读单精度广播`。
  - 广播与车道：`字节十六广播` … `小数二广播`；`单精度四取道`、`单精度四改道` 及各形状的取道、改道（车道号须是编译期整数常量）。
  - 单精度四：`单精度四加`、`减`、`乘`、`除`、`最小`、`最大`、`绝对值`、`取负`、`开方`、四种取整、六种比较（结果是掩码）、`单精度四求和`、`单精度四乘加`（先乘后加）、`整数四转单精度四`、`单精度四饱和转整数四`。
  - 整数：`整数四加`、`减`、`乘`、`取负`、`绝对值`、`最小`、`最大`、移位、`等`、`小于`、`大于`；`整数四点积短整数八`（量化点积）；`整数四扩展短整数八低`/`高` 及无符号版；`短整数八加`、`减`、`乘`、`短整数八扩展字节十六低`/`高` 及无符号版、`短整数八收窄整数四`；`字节十六加`、`减`、`字节十六收窄短整数八`。
  - 位运算与重排：`向量与`、`向量或`、`向量异或`、`向量非`、`向量与非`、`向量位选`、`向量任真`；`向量洗牌`（车道打包成四个整数常量）、`单精度四洗牌`（四个 0 到 7 的三十二位车道号）、`向量换序`；`向量常量`；`向量选择`。
  - relaxed SIMD：`单精度四融合乘加`、`单精度四融合负乘加`、`短整数八点积字节十六`、`整数四点积累加字节十六`。它们的结果可能随平台略有差异（是否真正融合、第二个字节操作数须在 0 到 127）；不依赖它们时用 `单精度四乘加` 与 `读字节八扩展` 加 `整数四点积短整数八`。
- **原子**（`原子运算` 模块，须声明共享内存；地址须按宽度对齐）：`原子读四`、`原子写四`、`原子加四`、`原子减四`、`原子与四`、`原子或四`、`原子异或四`、`原子交换四`、`原子比较交换四`；`原子读八`、`原子写八`、`原子加八`、`原子交换八`、`原子比较交换八`；`原子等待四`、`原子等待八`（超时为长整数纳秒，负数不限时；返回 0 被唤醒、1 值不等、2 超时）、`原子唤醒`（返回唤醒个数）、`原子栅栏`。

## 七、导入与导出

- **导出**：定义名以 `导出：` 开头的函数是模块的导出函数，导出名是其后的部分（`「导出：启动」` 导出为 `启动`）。只有导出函数及其调用图会被生成。
- **导出签名**：导出名后可再加 `：参数数：结果数` 指定 Wasm 签名，例如 `「导出：启动：0：0」`（豫言里 `有 → 有` 的函数导出成无参无果的入口）。总装时为它生成一个包装函数：形参比所定多出的补各自类型的零，所定结果数为 0 时丢弃返回值；没有后缀的导出函数照原样导出（形参与结果的 Wasm 类型由类型推定决定）。`「导出：_start：0：0」` 使模块可以直接由 Node 宿主运行（宿主调用 `_start`）。
- **导入**：外部调用名 `导入：模块：字段：参数：结果` 是对宿主函数的导入，如 `《《外调》》名『导入：平台：写字节：1：0』传「字节」`。参数与结果写个数时全是 i32（旧写法）；也可写类型字串，类型字为 整、长、单、双、向，如 `导入：数学：正弦：双：双`。结果至多一个；结果为零个时值为单元 0。参数为零个的导入（如 `导入：平台：读字节：0：1`），调用处按豫言的写法传一个单元 `无`，生成指令时丢弃这个实参。

## 八、分派

对整数变量的等值判断链（包括对整数常量的 `鉴`）会合成分派：不多于四项时逐项比较，更多时按键折半。同键取先者。

## 九、编译管线

底层模式下每个文件依次做：语法分析、名称解析、类型检查、类型擦除、跨模块优化、**闭包前优化**（到此为止，不做递归转换、闭包环境、全局存储、函数提升）。入口文件的最终阶段由底层后端读取各文件的闭包前优化形式：

1. **读取**：把树转成无类型简树，给每个绑定分配全局唯一名，拉平柯里化调用，把局部函数收成 `局函`，拒绝闭包、元组、构造器值、异常、续延、字符串值；小数字面量转成其 IEEE-754 位型；类型声明留一个占位（真被当值用时报错）；
2. **顶层常量**：按需求值；先求含声明的定义；
3. **化简**：代入字面（整数、长整数、小数、字符串）、折叠纯整数运算、静态串定址、`长常量` 解析、常量引用取值，`令 x = v 于 若 x …` 且 x 不再出现时并成 `若 v …`；
4. **提升**：如第三节；全局函数里的尾自调化为回跳；等值链成分派；
5. **类型推定**：对全部可达函数反复施加约束直到不再变化（`底层定型`）；
6. **生成**：每个式在操作数栈上留一个值；局部变量按名引用，形参在前、按作用域分配、同级分支复用下标，名字带类型前缀；块类型取推定的类型；分派用嵌套块加决策树；
7. **总装**：从导出函数沿调用图收集可达函数，附导入、内存、数据段。全是 i32、只用旧指令且内存不共享、非六十四位时走**旧路径**：转回网页汇编核心的状态模块，编码时**验证**，字节与改版前相同（寄存器降级后端与客体执行器照旧可用）；否则走**新路径**：装成通用模块项，用通用编码器写出标准 Wasm 二进制，由引擎装载时验证。

## 十、验证与工具

- **回归示例** `库/底层库/测试/底层示例`：只用整数，覆盖尾递归、非尾递归、分派、内联循环、可变格、位运算、多参数、无符号比较、静态串与内存。构建：`node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 底层示例 --输出 /tmp/yy底层示例.wasm`。
- **扩充回归示例** `库/底层库/测试/底层扩充示例`：小数、单精度（含超越函数）、长整数、向量（含 relaxed SIMD）、原子与共享内存、控制结构；另有入口 `六四`（六十四位地址内存）、`补充`（逐个覆盖其余原语）、`导入`（带类型的导入，只编译与验证）、`内存导入`（从宿主导入共享内存并导出，多个工作线程用原子操作协作）。每项不符即陷阱，由导出的 `_start` 运行。
- **单精度矩阵乘** `库/底层库/测试/单精度矩阵乘`：标量、向量、寄存器分块向量与融合乘加分块四种内核，核对结果逐位相同；`标量`、`向量`、`分块`、`融合` 四个入口各重复一种内核二十遍用来计时。
- **宿主侧校验器** `应用/开发工具/底层测试`：`yy底层测试 模块.wasm` 读入只用整数的模块，做标准验证与二进制往返，装配成带内存与数据段的状态实例，在宿主整数执行器里逐项调用导出函数并核对结果（二十六项）；`yy底层测试 --诺节 模块.wasm` 把用到扩充类型的模块交给 Node 宿主运行，按退出状态判定并报告用时。
- **诺节宿主**（`豫言操作系统/宿主/节点/底层宿主.cjs`）：底层模块导入内存时按导入段的限制建内存；导入「数学」（`指数`、`对数`、`正弦`、`余弦`、`正切`、`双曲正切`、`反正切`、`幂`、`以二为底对数`，都是双精度）与「诺节」（`写字节 址 长`、`写整数`、`写长整数`、`写小数`、`毫秒`、`线程数`）的函数由宿主提供；模块导出「工作线程」时，宿主先起若干工作线程（环境变量 `YY_底层线程数`，缺省为可用处理器数减一），每个用同一模块、同一块共享内存实例化并调用 `工作线程(序号)`（序号从 1 起），再在主线调用 `_start`，返回后结束各工作线程。
- **试验工具** `应用/开发工具/底层生成`：`yy底层生成 读|编译 …` 直接读阶段文本，便于检查简树与生成结果；开发后端不必重建编译器。
- 豫构测试 `应用/豫构/包资料。测试。豫`、`包系统。测试。豫` 覆盖编译模式字段、依赖闭包同模式检查与第三版包上下文往返。
- 编译器改动按 `AGENTS.md` 三轮自举校验：`yy3_bs` 与 `yy4_bs` 字节一致，并通过 `--type-check-only`。

## 十一、限制与待办

- 寄存器降级后端（Wasm → x86-64/arm64）经数值转译支持扩充类型，豫言系统内核在任务切换时保存浮点与向量寄存器（限制见 `豫言操作系统/裸机/文档/数值降级.汉语.md`）。客体执行器（客体二号）只解释 i32 的底层模块；待办事项：执行器解释扩充类型的指令。
- 泛型函数在底层模式须单态使用；向量车道号、洗牌车道、向量常量须是编译期整数常量（经内联与化简后成为字面量）。
- 块的结果类型取推定的类型；各分支都是回跳或陷阱的块作为实参使用时，其类型可能推不出（按 i32），极少见，遇到时把它绑定到有类型的变量上。
