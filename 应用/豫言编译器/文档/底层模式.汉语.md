# 底层模式（无垃圾回收编译模式）

底层模式是豫言编译器的第二种编译模式：用**普通豫言语法**书写执行器、驱动、文件系统、张量内核等系统代码，编译时不使用垃圾回收，也不依赖标准库运行时，直接生成标准 Wasm 模块。产出的模块可在 Node（诺驿）等 Wasm 引擎里运行，也可由豫言操作系统的寄存器降级后端编成 ARM64、x86-64 机器码（原生二进制与裸机；编译器 `--目标 本机` 直接写出原生可执行文件，不经 .wasm，交叉目标加 `--目标系统`、`--目标架构`；图形程序要的宿主授权（如显示面）由 `--缺省宿主选项 '--授权显示面 主窗口=1280x860'` 写进产物，启动时补命令行没写的项，命令行写了同一项的以命令行为准，见冶铸包说明的“缺省宿主选项”）；用到小数（f64）、单精度（f32）、长整数（i64）、向量（v128 SIMD）与原子操作的模块在降级前先经数值转译（见 `豫言操作系统/裸机/文档/数值降级.汉语.md`）。它取代此前自造的括号式“低阶语言”：语言只有一种，差别在于编译模式。

## 一、声明模式：看文件名

底层模块内部符号复用普通程序的包模块身份：所有者、包名、包内路径与定义名共同标识一个定义。函数调用、顶层常量与附加函数使用同一标识，汇编树码在不同源码目录构建时保持相同内部名称。公开导出使用源文件声明的导出名。

编译模式是**文件的属性**，由文件名决定：文件名带「。底层」的是底层文件，其余文件是高级文件（有垃圾回收）。

| 后缀 | 内容 |
| --- | --- |
| `名。底层。豫` | 底层源文件 |
| `名。底层。测试。豫` | 底层测试，全树测试照常按 `。测试。豫` 发现 |
| `名。底层接口。豫` | 底层接口：只写类型与 `乃` 签名，每个无体声明编成一个 Wasm 导入（见第七节） |
| `名。底层内建。豫` | 底层内建声明：底层库的本术（基础原语）、规度（布局原语）与广规度（六十四位地址的布局原语），路径为 `库/底层库/本术。底层内建。豫`、`库/底层库/规度。底层内建。豫`、`库/底层库/广规度。底层内建。豫`（见第六节） |
| `名。底层签名。豫` | 底层模块签名：与同目录同名底层源文件配对，声明类型的种、透明类型定义、值类型与具体类型块，核对规则同普通签名（见[签名文件](../../../提案/00060-签名文件.汉语.md)） |

- 底层签名的种名照底层现行的写法：底层签名先 `寻观「磐石」之「数值类型」之书。`，抽象类型的种写「元类型」，如 `「页号」乃「元类型」也。`。签名文件里的名字照底层文件的导入规则先导入、后使用。

- 程序的模式看入口文件：入口是底层文件时，编译器走底层管线。
- 底层文件的 `寻`、`观`、`寻观` 只找 `名。底层。豫`、`名。底层接口。豫` 与 `名。底层内建。豫`，所以底层代码只依赖底层库等含底层文件的包；高级文件导入底层模块时报“这是底层模块，高级代码不能导入”。
- 编译模式只看文件名，同一个包里可以同时放底层文件与高级文件，包的层级也与模式无关。包描述里写“编译模式”字段会报错。
- 底层可执行包的产物是 Wasm 模块：豫构照常输出 `.wasm`，`「文件名」` 以 `.wasm` 结尾时豫构照原名输出（如 `客体执行器.wasm`）。输出路径以 `。树码` 结尾时写汇编树码（底层豫汇），如执行器 `执行器。树码`；只用 i32 与旧指令、走旧路径的模块写成汇编树码留待后续版本。
- 豫言的全部文件后缀（含高级、着色文件与文档、测试数据）见[文件后缀](语言技术规范/文件后缀.汉语.md)。

## 二、语言子集

底层模式沿用全部豫言语法与类型检查；差别只在**后端能接受什么**。凡不可入无垃圾回收之境者，编译期明确报错，不会退回垃圾回收。

| 支持 | 不支持（报错） |
| --- | --- |
| 整数、爻、单元 `元`、`若…则…否则`、`令`、`；`；元组布局类型、卦（定宽无号整数）、指向（带类型地址）；小变体的构造与 `鉴` | 元组值、超出小变体范围的构造器 |
| 小数（f64）、单精度（f32）、长整数（i64）、向量（v128） | 字符串值、异常、续延 |
| 对整数常量的 `鉴`（编译为分派） | 闭包、把函数当值传递、间接调用 |
| 一阶函数：全局函数、局部函数（按调用处使用情况处理，见下） | 引用类型 `匣`、数组、字典等运行时数据结构 |
| 自递归与尾调用（尾位置的自调用变成回跳） | 同一个函数在不同调用处用不同的值类型（泛型函数须单态使用） |
| 底层库本术、规度与广规度里的内建声明（见磐石（底层库））、接口文件里的导入声明（见第七节）、类型声明 `立「元类型」`（只作类型用） | 不在底层原语表里的内建名、签名与原语表不符的内建声明 |

上表里“闭包、把函数当值传递、间接调用”与“元组值”这几条限界由**类型检查**报出。底层文件逐个定义检查完，证义的「底限察」沿检查后的定义走一遍：按名簿分清哪个名是普通值、局部具名函数还是顶层（自递归）函数，遇到拿函数作值（绑定、传参、返回）、调用函数类型的参数（间接调用）、拉姆达或递归出现在值的位置、元组构造，就报 `编译错误：文件:行:列：…`，并写出所在定义的名字与被调用的参数名。这些判定与报错文字只在译料「底限」声明一份，证义与底读都调它；底读在入口文件的最终读取里仍会拒绝这些写法，正常流程里那是类型检查已经报过之后的兜底。

值的类型对应 Wasm 的数值类型：整数、爻、单元是 **i32**（整数按补码回绕，爻为 0/1，单元为 0）；小数是 **f64**；单精度是 **f32**；长整数与小变体是 **i64**；向量是 **v128**。函数恒返回一个值。简树本身不带类型，后端的**类型推定**按原语的签名、字面量、调用与绑定关系双向推出每个变量与每个函数结果的类型，推不出的按 i32；同一变量推出两种类型时报“类型不一致”。

小变体使用现有的类型块、`立` 构造器声明、构造器应用与 `鉴…或有…则…` 写法。类型本身写作 `立「元类型」`（「元类型」由「数值类型」模块给出），例如：

```
「签果」立「元类型」也。
　「得签」立化「整数」为「签果」者也。
　「缺签」立「签果」也。
```

每个构造器可有零个或一个载荷；载荷类型为整数、爻或至多三十二位的卦。声明处检查范围，越界诊断以“底层小变体的载荷”开头。每个值用单个六十四位整数表示，高三十二位保存构造器序数，低三十二位保存载荷位型；空载构造器的低位为零。参数、返回值与局部变量均按值传递，构造直接使用整数指令。鉴由共用前端检查分支穷尽，随后降为标签比较与载荷取出；负整数的补码与卦的无号位型原样保留。

小变体的布局字段表示、多载荷与宽载荷留待后续版本；现阶段作为组类布局字段时在编译期报错。

## 三、函数与循环

- **顶层函数**：`「名」乃化…也。「名」者会…也。` 编译为 Wasm 函数；仅被导出函数（见下）沿调用图可达者才会生成。
- **自递归**：豫言编译器已把满参递归提升成全局函数；后端把尾位置的自调用改成回到函数起点的跳转（`br`），非尾位置的自调用是普通调用。互递归需要自行改写（豫言无前向引用）。
- **局部函数**（`令「f」为（得…）属（化…）而`、`复令「f」属…即…而`）按使用情况三选一：
  1. 不被调用：丢弃；
  2. 只被调用一次且不自调：展开进调用处；
  3. 只被调用一次且自调都在尾位置：做成**内联循环**（共用外层函数的局部变量，可读写外层的可变格）；
  4. 其余：提升为全局函数，自由变量作为前置形参（**不能捕获可变格**，否则报错）。
- 因此惯用写法是“单次调用的局部递归函数 = 循环”。循环形参可以是任何值类型，例如小数、单精度或向量的累加量。

## 四、可变格

`置格`、`读格`、`写格` 提供函数内的可变变量：

```
令「和」为「置格」于「零」而
令「位」为「置格」于「零」而
复令「当」属化「有」为「整数」
　即得「无」而
　　若（「读格」于「位」）小于「数」则
　　　（（「写格」于「和」于（（「读格」于「和」）加（「读格」于「位」）））而后
　　　　（「写格」于「位」于（（「读格」于「位」）加「一」））而后
　　　　「当」于「元」）
　　否则
　　　「读格」于「和」而
「当」于「元」。
```

格编译为 Wasm 局部变量，必须直接由 `虑 名 者 新格 … 而` 绑定，且只能作 `读格`/`写格` 的首个实参；不能作为普通值传递或被提升函数捕获。其他类型的格用 `数格` 模块的 `置小数格`/`读小数格`/`写小数格` 及单精度、长整数、向量的同名形式，格的类型由初值决定。

## 五、内存、静态数据与声明

布局写成命名元组或按序号访问的元组类型。字段依声明次序紧排，偏移等于前面各项大小之和，总大小等于全部字段大小之和。字段起点须满足自然对齐，空位用显式字段补齐；元组的对齐取各字段对齐的最大值。

| 字段类型 | 大小（字节） | 自然对齐（字节） |
| --- | --- | --- |
| 卦，八、十六、三十二、六十四爻 | 一、二、四、八 | 同大小 |
| 整数、单精度 | 四 | 四 |
| 长整数、小数 | 八 | 八 |
| 向量 | 十六 | 十六 |
| 指向 T | 当次内存地址宽度，四或八 | 同大小 |
| 元组 | 各字段大小之和 | 字段对齐的最大值 |

`p` 为 `「指向」于 R` 时，`p 中「字段」` 得到指向该字段的地址，嵌套投影逐层计算。按序号投影从零起。检查阶段保存两种地址宽度的布局资料，底层总装依实际内存声明核对对应对齐并选出常量偏移，降为地址加法；同一份阶段缓存可用于三十二位与六十四位目标。

`「址作指」以 T 于 地址` 保存所指类型，`「指作址」于 指针` 取得原始地址；两者保持地址位型，表示随内存地址宽度。六十四位地址内存的代码用 `「长址作指」以 T 于 地址` 与 `「指作长址」于 指针` 在长整数地址与指向之间转换。

- 线性内存的读写：`读四`、`读二`、`读二有号`、`读一`、`读一有号`、`写四`、`写二`、`写一`；`存页数`、`存增长`、`存摹`、`存填`。其他类型的读写见第六节（`读小数`、`读单精`、`读长数`、`读向量` 等）。
- 顶层值定义必须是**编译期常量**：整数常量、常量间的整数运算、对其他常量的引用、`静态文` 的结果。它们在函数里出现时被代入为数字。小数等其他类型的常量写在函数里（如 `「单」于「0.5」`）。
- **声明**是顶层值定义：`「内存」者（「声明存」于「初始页」于「最大页」）也。`；`「数据区」者（「声明数据区」于「起」于「止」）也。` 各只能声明一次；使用 `静态文` 前须先声明数据区（编译器先求含声明的定义，故书写顺序无关）。
- **共享内存**：`声明共享内存 初始页 最大页`，供原子操作与多线程使用（Wasm 要求共享内存有最大页数）。
- **六十四位地址内存**（memory64）：`声明存六四`（或 `声明共享存六四`）。此时一切地址都是长整数，用 `广仓` 模块的 `长址读四`、`长址写单精`、`长址读向量`、`长址存页数` 等；用整数地址的函数会在编译时报类型不符。一、二字节读写（`长址读二`、`长址读一有号`、`长址写二` 等）、批量复制与填充（`长址存摹`、`长址存填`，地址与长度都是长整数）和原子操作（`长址一气读四`、`长址一气加四` 等）都有长址版。静态串仍返回三十二位地址（数据区在 4 GiB 之下），用 `「无号数作长数」于（「静态文」于『…』）` 得到长整数地址。原生二进制与豫言系统里的线性内存可增长到 4 GiB 以上（macOS 与 Linux 至 68 TiB，裸机 AMD64 与 ARM64 至 127 TiB，Windows 与 macOS x86-64 至 8 GiB，见 `豫言操作系统/裸机/文档/数值降级.汉语.md`）。
- **址（地址宽度的整数）**：底层库 `址算` 模块的 `址加`、`址减`、`址乘`、`址交爻`、`址升位`、`址无号降位`、`址等于`、`址无号小于` 等，以及 `数作址`（无符号扩展）、`有号数作址`、`址作数`（取低三十二位）、`读址`、`写址`（按址的宽度读写四或八字节）、`址宽`（四或八）。前端类型一律写整数，后端按地址参数推出宽度：声明六十四位地址内存时是六十四位；声明普通内存时，原生产物（`--目标 本机` 直出的可执行文件，或输出 。树码 的汇编树码）也是六十四位，输出 .wasm（浏览器、云工、诺驿）时是三十二位。同一份源码用它们写地址与指针的运算，换一种内存声明就得到另一种宽度；三十二位时这些函数生成的指令与普通整数运算相同。六十四位构建里，三十二位的值（如「读四」的结果）传给址参数时按无号零扩展，源文不必写 `数作址`；把六十四位的值传给三十二位的参数或写进四字节时才报“既是 长整数（i64），又是 整数（i32）”。
- **原生产物默认六十四位地址**（用户 2026-10-13 定）：原生产物里的普通内存声明一律按六十四位地址内存生成，保留声明的页数；输出 .wasm 时仍是三十二位。编译器参数 `--三十二位地址`（经豫构写作 `豫构 构建 <包> -- --三十二位地址`）把所有内存声明（含 `声明存六四`）改回三十二位、最大页数不超过 65535，只做性能对比用。
- **六十四位地址开关**：编译器参数 `--六十四位地址`（默认关；经豫构写作 `豫构 构建 <包> -- --六十四位地址`）把程序的普通内存声明改成六十四位地址内存，最大页数 2130706432（实际上限由降级器按平台定：macOS 与 Linux 68 TiB，裸机 AMD64 127 TiB），可用来编出堆超过 4 GiB 的底层程序；执行器的入口直接用 `声明存六四` 声明六十四位地址内存，构建时不用这个开关。六十四位地址内存的模块另按三条规则推定类型：整数运算与比较（加、减、乘、除、余、位运算、移位、比较、判零、选择）随操作数取三十二或六十四位，两个操作数须同型；整数字面量随所需类型；读写内存的地址实参可以是三十二位整数，生成时零扩展。地址运算因此自动推成六十四位；址运算（`址加`、`址减`、`读址`、`写址` 等）的址实参也可以是三十二位整数，生成时同样零扩展，所以三十二位的读取结果可以直接当地址或偏移用。把六十四位的值传给三十二位的参数、写进四字节或与非址的三十二位值混算时报类型冲突：消息说清两面的宽度各是在哪个函数里、哪一次调用处定下来的，末了附两处源码位置：形参写成“函数〈丙〉的参数〈名〉既是 X（在函数〈甲〉里调用〈丙〉时定下），又是 Y（在函数〈乙〉里调用〈某〉时定下）”；函数结果写成“函数〈名〉的结果在它的体里是 X，在函数〈乙〉里调用〈某〉时又按 Y 用”；其余变量写成“〈名〉既是 X（在函数〈甲〉里调用〈丁〉时定下），又是 Y（在函数〈乙〉的体里定下）”。宽度是在某函数的体里用它时定下的，写作“在函数〈甲〉的体里定下”。每面末了附该函数顶层定义的源码位置，如“（前者定义于 文件:行:列，后者定义于 文件:行:列）”。一次报出全部，至多一千条；位置取自名称解析留下的「定义范围」，取不到时省去位置那一半。冲突在类型推定里报出，所以底层程序的 `豫构 类型检查`（第九、十节）就能看到，不必等到构建；在这些地方用 `址作数`、`数作址`、`读址`、`写址` 写明。编译期的常量折叠按三十二位算，超过三十二位的常量用 `长常` 或运行时移位得到。这三条规则只用于六十四位地址内存的模块（原生产物默认如此）；输出 .wasm 的普通内存模块产物与改动前逐字节相同。
- `「串址」者（「静态文」于『你好』）也。`：把字符串按 UTF-8 加零字节放入数据区，值为其地址；相同内容共用一份。
- **内存的导入与导出**：`「来处」者（「声明存引」于『环境』于『内存』）也。` 使模块不自建内存，改从宿主导入（模块名、字段名为字符串字面）；页数、是否共享、是否六十四位地址仍由内存声明给出，须先声明内存，只能声明一次。宿主据导入的限制建内存，多个实例、多个工作线程可以共用同一块共享内存。`「出口」者（「声明存出」于『内存』）也。` 把内存以该名导出，供宿主读写，可声明多次。声明了其一，模块就走新路径。待办事项：导入共享内存时数据段在每次实例化都会重写，这时宜避免静态串。

## 六、数值类型与原语

规度（布局内建原语，`库/底层库/规度。底层内建。豫`）提供 `「卦」于「爻数」曰 n`、`「指向」于 T`、多态的「读」「写」，以及三十二位整数地址的「址作指」「指作址」。用时显式写 `寻观「磐石」之「规度」之书。`；六十四位地址内存的代码另导入广规度（`库/底层库/广规度。底层内建。豫`）取长整数地址的「长址作指」「指作长址」。默认导入与本术（基础内建原语）保留旧工具链支持的声明，支持布局的新工具链检查规度与广规度。

整数字面量按期望卦类型核对零至二的 n 次方减一。可准确表示的有号六十四位正负整数使用原整数节点；数学值与位型值不同的字面量保留十进制原文到检查阶段，六十四位正数上界与负数分别核对。卦码按无号数学值核对。普通整数表达式与模式检查后使用统一的整数节点，覆盖分析、常量折叠与代码生成沿用此表示。三十二爻及以下用三十二位整数表示，其余用长整数表示。

`「卦作长数」` 对任意爻数零扩展，`「长数作卦」` 取低 n 位，`「卦作有号长数」` 以最高有效位为符号位扩展至长整数。`「卦作数」` 把三十二爻及以下的卦按位型读成三十二位整数，爻数为三十二且最高位为阳时读作负数；`「数作卦」` 只取低 n 位，与 `「长数作卦」` 一致，爻数为三十二时原样。这两条只许三十二爻及以下，超过时报带源位的编译错误，宽的卦改用 `「卦作长数」`、`「长数作卦」`。

爻数使用编译期整数常量；闭合的整数索引加减乘表达式按既有数学整数规约。底层本术的相应声明按所有者、包名与包内路径核定身份，与标准库运算共用规约入口。

「读」「写」的所指类型为上表的标量。八、十六、三十二、六十四爻依次选读一、读二、读四、读长数及对应写入原语；整数、长整数、单精度、小数、向量选各自读写原语；指向选读址、写址。卦的读取按无号零扩展。元组字段按投影所得的地址逐项读写。

`寻观「磐石」之书。` 按底层库的默认导入（基础、内存、格、址运算）只导入整数部分（与旧版相同，旧版编译器仍能编译只用整数的程序）；数值扩充按模块另行导入：`数值类型`、`小数算`、`单精算`、`长数算`、`向量算`、`一气算`、`广仓`、`数格`、`单精术`，如 `寻观「磐石」之「小数算」之书。`。各函数都只是底层库「本术」模块（`库/底层库/本术。底层内建。豫`）里内建声明的包装：类型检查按底层原语表（`库/译场/分职/笔受/底/底定型。豫`）核对名字、参数个数与各参数和结果的类型，把调用改成内部名 `底层_名`（以“声明”开头的名字改成 `声明：` 加其余部分，如「声明存」改成 `声明：内存`）；编译器内联后对应一条 Wasm 指令（取整、比较等的语义即 Wasm 的语义）。按地址宽度或元素类型多态的原语（读写内存、内存页数与增长、选择、可变格）在「原语」里写成类型变量。

- **小数（f64）**：字面量 `「1.5」`；`小数加`、`小数减`、`小数乘`、`小数除`、`小数小者`、`小数大者`、`小数复号`、`小数绝对值`、`小数取负`、`小数向上取`、`小数向下取`、`小数截尾`、`小数约`、`小数开方`；比较 `小数等于`、`小数不等于`、`小数小于`、`小数大于`、`小数不大于`、`小数不小于`；转换 `小数作数`（越界陷阱）、`小数饱和作数`、`数作小数`、`无号数作小数`、`小数作长数`、`小数饱和作长数`、`长数作小数`、`小数作单精`、`单精作小数`；位型 `小数位`、`位作小数`；内存 `读小数`、`写小数`；`小数择`。
- **单精度（f32）**：常量写 `「单」于「0.5」`（小数就近舍入）；运算、比较、取整、开方与小数同名而以 `单精度` 为前缀（`单精加` … `单精开方`、`单精等于` …）；`单精作数`、`单精饱和作数`、`数作单精`、`无号数作单精`、`单精位`、`位作单精`、`读单精`、`写单精`、`单精择`。
- **单精度超越函数**（`单精术` 模块，普通函数，范围归约加多项式逼近，常用范围内相对误差约 1e-6）：`单精指数`、`单精对数`、`单精双曲正切`、`单精逻辑斯谛`（S 形函数）、`单精正弦`、`单精余弦`、`单精幂`。待办事项：非正规数、上溢为无穷、零与负数的对数、极大自变量的三角函数只作了粗略处理；四车道向量版本尚未提供。
- **长整数（i64）**：`「长」于「一二三」`（整数按有符号扩展），超出三十二位的常量写 `「长常」于『123456789012』`（十进制字符串，编译期解析）；`长数加`、`长数减`、`长数乘`、有符号与无符号的除与余、`长数交爻`/`兼爻`/`位变爻`、`长数升位`、`长数有号降位`、`长数无号降位`、循环移位（移位量也是长整数）；`长数为零`、`长数等于` 与有符号、无符号比较；`长数作数`（取低三十二位）、`数作长数`、`无号数作长数`；`读长数`、`写长数`；`长数择`。
- **向量（v128）**：同一向量按形状解读——字节十六（i8x16）、短整数八（i16x8）、整数四（i32x4）、长整数二（i64x2）、单精度四（f32x4）、小数二（f64x2）。
  - 内存：`读向量`、`写向量`；装载扩展 `读字节八扩`、`读字节八无号扩`、`读短数四扩`、`读短数四无号扩`；`读单精广播`。
  - 广播与车道：`字节十六广播` … `小数二广播`；`单精四取道`、`单精四改道` 及各形状的取道、改道（车道号须是编译期整数常量）。
  - 单精度四：`单精四加`、`减`、`乘`、`除`、`最小`、`最大`、`绝对值`、`取负`、`开方`、四种取整、六种比较（结果是掩码）、`单精四求和`、`单精四乘加`（先乘后加）、`数四作单精四`、`单精四饱和作数四`。
  - 整数：`数四加`、`减`、`乘`、`取负`、`绝对值`、`最小`、`最大`、移位、`等于`、`小于`、`大于`；`数四点积短数八`（量化点积）；`数四扩短数八低`/`高` 及无符号版；`短数八加`、`减`、`乘`、`短数八扩字节十六低`/`高` 及无符号版、`短数八收窄数四`；`字节十六加`、`减`、`字节十六收窄短数八`。
  - 位运算与重排：`向量交爻`、`向量兼爻`、`向量变爻`、`向量错卦`、`向量交非`、`向量位择`、`向量有阳`；`向量洗牌`（车道打包成四个整数常量）、`单精四洗牌`（四个 0 到 7 的三十二位车道号）、`向量换序`；`向量常`；`向量择`。
  - relaxed SIMD：`单精四融合乘加`、`单精四融合负乘加`、`短数八点积字节十六`、`数四点积累加字节十六`。它们的结果可能随平台略有差异（是否真正融合、第二个字节操作数须在 0 到 127）；不依赖它们时用 `单精四乘加` 与 `读字节八扩` 加 `数四点积短数八`。
- **原子**（`一气算` 模块，须声明共享内存；地址须按宽度对齐）：`一气读四`、`一气写四`、`一气加四`、`一气减四`、`一气交爻四`、`一气兼爻四`、`一气变爻四`、`一气交换四`、`一气较换四`；`一气读八`、`一气写八`、`一气加八`、`一气交换八`、`一气较换八`；`一气待四`、`一气待八`（超时为长整数纳秒，负数不限时；返回 0 被唤醒、1 值不等、2 超时）、`一气醒`（返回唤醒个数）、`一气栅`。

## 七、导入与导出

- **入口**：入口文件（依赖序的最后一个文件，如 `入口。底层。豫`，测试是 `名。底层。测试。豫` 本身）顶层的入口函数「入口」（类型 `化「有」为「有」`，与普通程序的入口函数同名，编译器参数 `--入口函数 名` 可改名）由编译器导出成 `启动`，签名无参无果：
  ```
  「入口」乃化「有」为「有」者也。
  「入口」者得「无」而「运行全部校验」于「元」也。
  ```
  入口函数名、导出名与参数的个数、结果的个数都在 `库/译场/网汇/篇入口。豫`（模块入口约定）声明一处，前端总装与原生后端都取它：前端照它写导出，原生后端照它找入口并核对签名，两端不再各写一个字符串。四个原生目标（裸机、林纳、林檎、轩窗）与网页汇编模块的同一条约定都用这个名；WasmGC 一类程序由宿主调用的 `_start` 是另一套，由洒扫运行时生成。Node 宿主（`底层宿主.cjs`）与 `底层测试 --诺驿` 调用 `启动` 运行模块。
- **导出**：定义名以 `导出：` 开头的函数是模块的导出函数，导出名是其后的部分（`「导出：合计」` 导出为 `合计`）。只有导出函数（含入口函数）及其调用图会被生成。显式导出名与入口导出名相同（同一个程序里既写入口函数、又写 `「导出：启动：0：0」`）时，总装在「底察重名」处报“导出名重复”并写出两个定义的名字。
- **导出签名**：导出名后可再加 `：参数数：结果数` 指定 Wasm 签名，例如 `「导出：合计：0：0」`（豫言里 `有 → 有` 的函数导出成无参无果的入口）。总装时为它生成一个包装函数：形参比所定多出的补各自类型的零，所定结果数为 0 时丢弃返回值；没有后缀的导出函数照原样导出（形参与结果的 Wasm 类型由类型推定决定）。入口函数按 `启动：0：0` 导出。
- **导入**：底层接口文件（后缀 `。底层接口。豫`）只写类型与 `乃` 签名，每个无体声明编成一个 Wasm 导入：模块名是接口文件名（去掉后缀，如 `林纳。底层接口。豫` 是“林纳”），字段名是声明名。参数与结果的 Wasm 类型由声明的类型决定：整数与爻为 i32，长整数为 i64，单精度为 f32，小数为 f64，向量为 v128；类型为“有”的参数不进签名，结果为“有”时没有结果（值为单元 0）；其他类型报错。类型检查把调用改成内部名 `导入：模块：字段：参数：结果`（参数与结果写类型字串，类型字为 整、长、单、双、向，没有就写 0），后端照此生成导入。例如 `平台。底层接口。豫` 里的 `「写字节」乃化「整数」为「有」者也。` 就是导入“平台”.“写字节”，签名 (i32) → ()。接口文件放在用它的包里（如 `豫言操作系统/裸机/客体二号/平台接口/`）；`豫寓底榫卯` 下的接口包在构建时没有绑定适配实现的，也照此编成导入。
- **系统符号**：`林纳`、`林檎`、`轩窗` 三个接口文件声明系统调用与系统库函数，声明名用中文（译名见《翻译列表》“系统符号”一节，即提案 00013 附录），如 `「书」乃化「整数」又化「整数」又化「整数」为「整数」者也。` 是系统调用 write。原生目标上，裸机后端按字段名查 `豫言操作系统/裸机/库/冶铸/降级鹄。豫` 的导入对照表：林纳表的每行是中文名、系统调用原名、两种架构的调用号、参数类别与结果数；林檎表是中文名、系统库符号名（如 `_write`）、参数类别等；轩窗表是中文名、符号名（如 `CreateFileW`）、所在动态库、参数类别与结果数，导入表与动态库符号解析用符号名。系统原名只记在这张对照表里；新增系统符号时在接口文件加中文声明、在对照表加一行，并把译名补进提案 00013 附录与《翻译列表》。

## 八、分派

对整数变量的等值判断链（包括对整数常量的 `鉴`）会合成分派：不多于四项时逐项比较，更多时按键折半。同键取先者。

## 九、编译管线

底层模式下每个文件依次做：语法分析、名称解析、类型检查、类型擦除、跨模块优化、**闭包前优化**（到此为止，不做递归转换、闭包环境、全局存储、函数提升）。入口文件的最终阶段由底层后端读取各文件的闭包前优化形式：

1. **读取**：把树转成无类型简树，给每个绑定分配全局唯一名，拉平柯里化调用，把局部函数收成 `局函`，拒绝闭包、元组、构造器值、异常、续延、字符串值；小数字面量转成其 IEEE-754 位型；类型声明留一个占位（真被当值用时报错）；
2. **顶层常量**：按需求值；先求含声明的定义；
3. **化简**：代入字面（整数、长整数、小数、字符串）、折叠纯整数运算、静态串定址、`长常` 解析、常量引用取值，`令 x = v 于 若 x …` 且 x 不再出现时并成 `若 v …`；
4. **提升**：如第三节；全局函数里的尾自调化为回跳；等值链成分派；
5. **类型推定**：对全部可达函数反复施加约束直到不再变化（`底定型`）；这一步报出整数宽度的冲突。编译器参数 `--宽度检查`（经豫构在类型检查底层程序时传）让总装做到这一步为止：不生成指令、不写产物，专为在类型检查阶段就报出这类冲突；
6. **生成**：每个式在操作数栈上留一个值；局部变量按名引用，形参在前、按作用域分配、同级分支复用下标，名字带类型前缀；块类型取推定的类型；分派用嵌套块加决策树；
7. **总装**：从导出函数沿调用图收集可达函数，附导入、内存、数据段。全是 i32、只用旧指令且内存不共享、非六十四位时走**旧路径**：转回网页汇编核心的状态模块，编码时**验证**，字节与改版前相同（寄存器降级后端与客体执行器照旧可用）；否则走**新路径**：装成通用模块项，用通用编码器写出标准 Wasm 二进制，由引擎装载时验证。

## 十、验证与工具

- **回归示例** `库/底层库/测试/底层示例`：只用整数，覆盖尾递归、非尾递归、分派、内联循环、可变格、位运算、多参数、无符号比较、静态串与内存。构建：`./豫构。林檎。豫行 构建 底层示例 --输出 /tmp/底层示例.wasm`。
- **扩充回归示例** `库/底层库/测试/底层扩充示例`：小数、单精度（含超越函数）、长整数、向量（含 relaxed SIMD）、原子与共享内存、控制结构；另有入口 `六四`（六十四位地址内存），两处入口都校验址运算（主入口三十二位、`六四` 六十四位）、`补充`（逐个覆盖其余原语）、`导入`（带类型的导入，只编译与验证）、`内存导入`（从宿主导入共享内存并导出，多个工作线程用原子操作协作）。每项不符即陷阱，由导出的 `启动` 运行。
- **单精度矩阵乘** `库/底层库/测试/单精度矩阵乘`：标量、向量、寄存器分块向量与融合乘加分块四种内核，核对结果逐位相同；`标量`、`向量`、`分块`、`融合` 四个入口各重复一种内核二十遍用来计时。
- **宿主侧校验器** `应用/百工坊/底层测试`：`底层测试 模块.wasm` 读入只用整数的模块，做标准验证与二进制往返，装配成带内存与数据段的状态实例，在宿主整数执行器里逐项调用导出函数并核对结果（二十六项）；`底层测试 --诺驿 模块.wasm` 把用到扩充类型的模块交给 Node 宿主运行，按退出状态判定并报告用时。
- **诺驿宿主**（`豫言操作系统/宿主/节点/底层宿主.cjs`）：底层模块导入内存时按导入段的限制建内存；导入「数学」（声明写在使用者包的 `数学。底层接口。豫` 里，`指数`、`对数`、`正弦`、`余弦`、`正切`、`双曲正切`、`反正切`、`幂`、`以二为底对数`，都是双精度）与「诺驿」（`写字节 址 长`、`写整数`、`写长数`、`写小数`、`毫秒`、`线程数`）的函数由宿主提供；模块导出「工作线程」时，宿主先起若干工作线程（环境变量 `豫言底层线程数`，缺省为可用处理器数减一），每个用同一模块、同一块共享内存实例化并调用 `工作线程(序号)`（序号从 1 起），再在主线调用 `启动`，返回后结束各工作线程。
- **试验工具** `应用/百工坊/底层生成`：`底层生成 读|编译 …` 直接读阶段文本，便于检查简树与生成结果；开发后端不必重建编译器。

## 十一、限制与待办

- 寄存器降级后端（Wasm → x86-64/arm64）经数值转译支持扩充类型，豫言系统内核在任务切换时保存浮点与向量寄存器（限制见 `豫言操作系统/裸机/文档/数值降级.汉语.md`）。客体执行器（客体二号）只解释 i32 的底层模块；待办事项：执行器解释扩充类型的指令。
- 泛型函数在底层模式须单态使用；向量车道号、洗牌车道、向量常量须是编译期整数常量（经内联与化简后成为字面量）。
- 块的结果类型取推定的类型；各分支都是回跳或陷阱的块作为实参使用时，其类型可能推不出（按 i32），极少见，遇到时把它绑定到有类型的变量上。
