# 底层模式（不用垃圾回收之编译模式）

底层模式者，豫言编译器之第二编译模式也。执行器、驱动、文件系统、张量内核等系统之代码，以**常豫言之语法**书之；编译之时，不用垃圾回收，亦不倚标准库之运行时，径生标准之 Wasm 模块。所生之模块可行于 Node（诺节）诸 Wasm 引擎，亦可由豫言操作系统之寄存器降级后端译为 ARM64、x86-64 之机器码（原生之二进制与裸机）；用小数（f64）、单精度（f32）、长整数（i64）、向量（v128）与原子之令者，降前先经数值转译（见 `豫言操作系统/裸机/文档/数值降级.文言.md`）。此代前所自造括号式“低阶语言”者：语言唯一，所异者编译之模而已。

## 一、模之所在：包描述

编译之模，包之性也，书于 `包名。包。豫` 之可选字段，不视文件之后缀，源文仍皆 `。豫`：

```
「编译模式」者『底层』也。
```

- 其值唯二：`高级`（缺省，有垃圾回收）、`底层`。
- 同一依赖之闭包，诸包必同其模。豫构解包图时校之，不合则报错；故底层之包不得依标准库，唯得依底层之包（如 `底层库`）。
- 豫构读此字段，以“底层诸包之文件列”授于编译器之包上下文（第三式，唯有底层包时乃见；无则与旧式字节全同，缓存不失）。编译器依入口文所属之包择其管线。
- 底层可执行之包，所成者 Wasm 模块，非原生程序：豫构不作原生链接；`「文件名」` 仍须以 `yy` 起或以 `.exe` 终（如 `yy客体执行器.wasm`）。

## 二、语言之子集

底层模式全用豫言之语法与类型检查；所异者，后端之所受也。凡不可入无垃圾回收之境者，编译之时明报其错，不退回垃圾回收。

| 所受 | 所拒（报错） |
| --- | --- |
| 整数、爻、单元 `元`、`若…则…否则`、`虑`、`；` | 元组、构造器（枚举）、构造器之 `鉴` |
| 小数（f64）、单精度（f32）、长整数（i64）、向量（v128） | 字符串之值、异常、续延 |
| 整数常量之 `鉴`（成分派） | 闭包、以函数为值而传、间接调用 |
| 一阶函数：全局函数、局部函数（依其被调之情处之，见下） | 引用类、数组、字典等运行时之数据结构 |
| 自递归与尾调用（尾位之自调化为回跳） | 一函数于诸调处用异型之值（泛型函数必单态而用） |
| 底层库「原语」之内建之声（见 `底层库`）、接口文件之导入之声（见第七节）、类型之声 `立「元类型」`（唯作类型） | 不在底层原语表之内建名、签与原语表不合之内建之声 |

值之型应 Wasm 之数值型：整数、爻、单元为 **i32**（整数按补码回绕，爻为零一，单元为零）；小数为 **f64**；单精度为 **f32**；长整数为 **i64**；向量为 **v128**。函数恒返一值。简树本无型，后端之**定型**依原语之签、字面、调用与绑定，往复推之，得诸变量与函数结果之型，推之不得者以 i32 论；一变量推得二型者，报“类型不一致”。

## 三、函数与循环

- **顶层函数**：`「名」乃化…也。「名」者会…也。` 成 Wasm 函数；唯自导出函数（见下）沿调用图可至者乃生。
- **自递归**：豫言编译器已升满参递归为全局函数；后端以尾位之自调改为回函数起点之跳（`br`），非尾位之自调则为常调。互递归须自改写（豫言无前向引用）。
- **局部函数**（`虑「f」者（化…）也（会…）而`、`递归虑「f」其…者…而`）依其被调之情三取其一：
  1. 未被调：弃之；
  2. 仅被调一次而不自调：展之于调处；
  3. 仅被调一次而自调皆在尾位：成**内联循环**（共用外层函数之局部变量，可读写外层之可变格）；
  4. 余者：升为全局函数，自由变量为前置形参（**不得捕获可变格**，否则报错）。
- 是以惯常之写法：“单次调用之局部递归函数 = 循环”。环之形参可为任一值型，如小数、单精度或向量之累加。

## 四、可变格

`新格`、`读格`、`写格` 供函数内之可变变量：

```
虑「和」者「新格」于「零」而
虑「位」者「新格」于「零」而
递归虑「当」其化「有」而「整数」者会「无」而
  若「小于」于（「读格」于「位」）于「数」
  则（（「写格」于「和」于（「加」于（「读格」于「和」）于（「读格」于「位」）））；（「写格」于「位」于（「加」于（「读格」于「位」）于「一」））；「当」于「元」）
  否则「读格」于「和」
而「当」于「元」
```

格成 Wasm 局部变量，必直接由 `虑 名 者 新格 … 而` 所绑，且唯作 `读格`、`写格` 之首实参；不得为常值而传，亦不得为提升之函数所捕。他型之格，用 `数值格` 模块之 `新小数格`、`读小数格`、`写小数格` 及单精度、长整数、向量之同形者，格之型随其初值。

## 五、内存、静态数据与声明

- 线性内存之读写：`读四`、`读二`、`读二有符号`、`读一`、`读一有符号`、`写四`、`写二`、`写一`；`内存页数`、`内存增长`、`内存复制`、`内存填充`。他型之读写见第六节（`读小数`、`读单精度`、`读长整数`、`读向量` 等）。
- 顶层值定义必为**编译时之常量**：整数常量、常量间之整数运算、他常量之引用、`静态串` 之结果。其入函数者，代以数字。小数诸型之常，书于函数之中（如 `「单」于「0.5」`）。
- **声明**乃顶层值定义：`「内存」者（「声明内存」于「初始页」于「最大页」）也。`、`「数据区」者（「声明数据区」于「起」于「止」）也。` 各止一声；用 `静态串` 之前须先声数据区（编译器先求含声明之定义，故书写之序无碍）。
- **共享内存**：`声明共享内存 初始页 最大页`，供原子之令与多线程（Wasm 令共享内存必有最大页数）。
- **六十四位址之内存**（memory64）：`声明内存六四`（或 `声明共享内存六四`）。此时诸址皆长整数，用 `内存六四` 模块之 `长址读四`、`长址写单精度`、`长址读向量`、`长址内存页数` 等；用整数之址者，编译时报型不合。一二字节之读写（`长址读二`、`长址读一有符号`、`长址写二` 等）、成批之复制与填充（`长址内存复制`、`长址内存填充`，址与长皆长整数）、原子之操作（`长址原子读四`、`长址原子加四` 等）皆有长址之版。静串仍返三十二位之址（数据区在四吉之下），以 `「无符号整数转长整数」于（「静态串」于『…』）` 得长整数之址。原生二进制与豫言系统之线性内存可增逾四吉（macOS、Linux 至六十四 TiB，裸机 AMD64 至一百二十七 TiB，见 `豫言操作系统/裸机/文档/数值降级.文言.md`）。
- **址（址宽之整数）**：底层库 `址运算` 之 `址加`、`址减`、`址乘`、`址位与`、`址左移`、`址无符号右移`、`址等`、`址无符号小于` 等，及 `整数转址`（无号而扩）、`有符号整数转址`、`址转整数`（取低三十二位）、`读址`、`写址`（依址之宽读写四或八字节）、`址宽`（四或八）。前端之型皆书整数，后端依址参推其宽：常内存三十二位，六十四位址之内存六十四位。同源以之书址与指针之算，易内存之声即易其宽；三十二位时所生之令与常整数之算同。址与常整数之算混用，六十四位之构报“既是整数，又是长整数”。
- **六十四位址之开关**：编译器之参 `--六十四位地址`（默关；经豫构书 `豫构 构建 <包> -- --六十四位地址`），改程序之内存为六十四位址，最大页二之三十次幂（六十四太字节），以编六十四太字节堆之执行器。六十四位址之模另有三则：整数之算与较随其操作数取三十二或六十四位，二者须同型；整数之字面随所求之型；读写内存之址参可为三十二位之整数，生成时零扩之。故址之算自推为六十四位；三十二位与六十四位之值混算、以六十四位之值传三十二位之参或书于四字节者，报型之冲突（一次尽报，至多千条），于此以 `整数转址`、`址转整数`、`读址`、`写址` 明之。编译时之折叠以三十二位算，逾三十二位之常以 `长常量` 或运行时之移得之。此三则唯用于六十四位址之模；常内存之模，产物与改前逐字节同。
- `「串址」者（「静态串」于『你好』）也。`：字符串以 UTF-8 附零字节置于数据区，其值为址；文同者共一份。
- **内存之导入与导出**：`「来处」者（「声明内存导入」于『环境』于『内存』）也。` 令模块不自建内存，而自宿主导之（模块名、字段名为字符串之字面）；页数、共享否、六十四位址否仍依内存之声，须先声内存，唯一次。宿主依所导之限建内存，诸实例诸工作线程可共一共享之内存。`「出口」者（「声明内存导出」于『内存』）也。` 以其名出内存，供宿主读写，可声数次。声其一者，模块由新路。待办：导共享之内存者，每实例化则数据段复书，宜避静态串。

## 六、数值之型与原语

`寻观「底层库」之书。` 唯引整数之部（同于旧版，旧编译器犹能编唯用整数之程序）；数值之扩充，另以 `寻观「底层库」之「数值」之书。` 引之。诸函皆底层库「原语」之模（`原语。内建。豫`）内建之声之包装：类型检查依底层原语表（`底层定型。豫`）校其名、参数之数与参果之型，易其调为内名 `底层_名`（以“声明”起之名易为 `声明：` 加其余，如「声明内存」易为 `声明：内存`）；编译器内联之后应一 Wasm 之令（取整、较等之义，即 Wasm 之义）。依址之宽或元素之类而多态之原语（读写内存、内存页数与增长、选择、可变之格），于「原语」书为类变。

- **小数（f64）**：字面如 `「1.5」`；`小数加`、`小数减`、`小数乘`、`小数除`、`小数最小`、`小数最大`、`小数复号`、`小数绝对值`、`小数取负`、`小数向上取整`、`小数向下取整`、`小数截断`、`小数就近取整`、`小数开方`；较之 `小数等`、`小数不等`、`小数小于`、`小数大于`、`小数小等`、`小数大等`；转之 `小数转整数`（越界则陷）、`小数饱和转整数`、`整数转小数`、`无符号整数转小数`、`小数转长整数`、`小数饱和转长整数`、`长整数转小数`、`小数转单精度`、`单精度转小数`；位型 `小数位`、`位转小数`；内存 `读小数`、`写小数`；`小数选择`。
- **单精度（f32）**：其常书 `「单」于「0.5」`（小数就近而舍）；算、较、取整、开方与小数同名而冠以 `单精度`（`单精度加` … `单精度开方`、`单精度等` …）；`单精度转整数`、`单精度饱和转整数`、`整数转单精度`、`无符号整数转单精度`、`单精度位`、`位转单精度`、`读单精度`、`写单精度`、`单精度选择`。
- **单精度之超越函数**（`单精度函数` 模块，常函数，以范围归约与多项式逼近，常用之域相对误差约百万分之一）：`单精度指数`、`单精度对数`、`单精度双曲正切`、`单精度逻辑斯谛`（S 形之函数）、`单精度正弦`、`单精度余弦`、`单精度幂`。待办：非正规数、上溢为无穷、零与负数之对数、极大之三角，皆粗略处之；四道向量之版未备。
- **长整数（i64）**：`「长」于「一二三」`（整数依有符号而扩）；逾三十二位之常书 `「长常量」于『123456789012』`（十进制之串，编译时解之）；`长整数加`、`长整数减`、`长整数乘`、有符号与无符号之除与余、`长整数位与`、`位或`、`位异或`、`长整数左移`、`长整数有符号右移`、`长整数无符号右移`、循环之移（移位之量亦长整数）；`长整数为零`、`长整数等` 及有符号、无符号之较；`长整数转整数`（取其低三十二位）、`整数转长整数`、`无符号整数转长整数`；`读长整数`、`写长整数`；`长整数选择`。
- **向量（v128）**：同一向量，依形而解——字节十六（i8x16）、短整数八（i16x8）、整数四（i32x4）、长整数二（i64x2）、单精度四（f32x4）、小数二（f64x2）。
  - 内存：`读向量`、`写向量`；读而扩之 `读字节八扩展`、`读字节八无符号扩展`、`读短整数四扩展`、`读短整数四无符号扩展`；`读单精度广播`。
  - 广播与车道：`字节十六广播` … `小数二广播`；`单精度四取道`、`单精度四改道` 及诸形之取道、改道（道号必为编译时之整数常量）。
  - 单精度四：`单精度四加`、`减`、`乘`、`除`、`最小`、`最大`、`绝对值`、`取负`、`开方`、四种取整、六种之较（其果为掩码）、`单精度四求和`、`单精度四乘加`（先乘后加）、`整数四转单精度四`、`单精度四饱和转整数四`。
  - 整数：`整数四加`、`减`、`乘`、`取负`、`绝对值`、`最小`、`最大`、移位、`等`、`小于`、`大于`；`整数四点积短整数八`（量化之点积）；`整数四扩展短整数八低`、`高` 及无符号者；`短整数八加`、`减`、`乘`、`短整数八扩展字节十六低`、`高` 及无符号者、`短整数八收窄整数四`；`字节十六加`、`减`、`字节十六收窄短整数八`。
  - 位与重排：`向量与`、`向量或`、`向量异或`、`向量非`、`向量与非`、`向量位选`、`向量任真`；`向量洗牌`（诸道打为四整数常量）、`单精度四洗牌`（四个零至七之三十二位道号）、`向量换序`；`向量常量`；`向量选择`。
  - 宽松之集：`单精度四融合乘加`、`单精度四融合负乘加`、`短整数八点积字节十六`、`整数四点积累加字节十六`。其果或随平台微异（融否、字节之次操作数必在零至一二七）；不欲依之者，用 `单精度四乘加` 与 `读字节八扩展` 加 `整数四点积短整数八`。
- **原子**（`原子运算` 模块，须声共享内存；址必对齐于其宽）：`原子读四`、`原子写四`、`原子加四`、`原子减四`、`原子与四`、`原子或四`、`原子异或四`、`原子交换四`、`原子比较交换四`；`原子读八`、`原子写八`、`原子加八`、`原子交换八`、`原子比较交换八`；`原子等待四`、`原子等待八`（限时以长整数纳秒计，负为不限；返零被唤，一值不等，二逾时）、`原子唤醒`（返所唤之数）、`原子栅栏`。

## 七、导入与导出

- **导出**：定义名以「导出：」起者，为模块之导出函数，导出之名乃其后之部（`「导出：启动」` 导出为 `启动`）。唯导出函数及其调用图乃生成。
- **导出之签**：导出名后可缀〈：参数数：结果数〉以定 Wasm 之签，如 `「导出：启动：0：0」`（豫言之“有→有”函数由此导出为无参无果之门）。总装时为之造包装函数：形参多于所定者补其型之零，所定结果数为零者弃其返值；无缀之导出函数则如故（形参与结果之 Wasm 型由定型所推）。`「导出：_start：0：0」` 使模块可径由 Node 宿主行之（宿主调 `_start`）。
- **导入**：底层包之接口文件（后缀 `。接口。豫`）唯书类型与 `乃` 之签，每无体之声编为一 Wasm 之导入：模块名乃接口文件之名（去其后缀，如 `林纳克斯。接口。豫` 为“林纳克斯”），字段名乃声之名。参果之 Wasm 型依声之类而定：整数与爻为 i32，长整数为 i64，单精度为 f32，小数为 f64，向量为 v128；类为有之参不入签，果为有者无果（其值为单元零）；他类则报错。类型检查易其调为内名 `导入：模块：字段：参数：结果`（参果书型字之串，型字为 整、长、单、双、向，无则书零），后端依之生导入。如 `平台。接口。豫` 之 `「写字节」乃化「整数」而「有」也。`，即导入“平台”.“写字节”，其签 (i32) → ()。接口文件置于用之之包（如 `豫言操作系统/裸机/客体二号/平台接口/`）；`豫言操作系统底层接口` 之接口包，构建时未绑适配之实者，亦依此编为导入。

## 八、分派

对整数变量之等值判断之链（含对整数常量之 `鉴`）合而为分派：至多四项则逐项较之，多则依键折半。同键取先者。

## 九、编译管线

底层模式下，每文依次行：语法分析、名称解析、类型检查、类型擦除、跨模块优化、**闭包前优化**（止于此，不作递归转换、闭包环境、全局存储、函数提升）。入口文之终阶，由底层后端读各文之闭包前优化形式：

1. **读取**：转树为无类型简树，予每绑定以全局唯一之名，平柯里化之调用，收局部函数为 `局函`，拒闭包、元组、构造器之值、异常、续延、字符串值；小数之字面转为其 IEEE-754 位型；类型之声置一占位（真以为值则报错）；
2. **顶层常量**：随用随求；先求含声明者；
3. **化简**：代入字面（整数、长整数、小数、字符串），折叠纯整数运算，静态串定其址，解 `长常量`，常量引用取其值；`令 x = v 于 若 x …` 而 x 不复见者，并为 `若 v …`；
4. **提升**：如第三节；全局函数之尾自调化为回跳；等值之链成分派；
5. **定型**：于诸可达函数反复施约，至不复变而止（`底层定型`）；
6. **生成**：每式于操作数栈留一值；局部变量以名引之，形参居前，依作用域分配，同级分支复用其号，名冠型字；块之型取所定之型；分派以嵌套块加决策树；
7. **总装**：自导出函数沿调用图集可达之函数，附导入、内存、数据段。皆 i32、唯用旧令而内存不共享、非六十四位者由**旧路**：转回网页汇编核心之状态模块，编码时**验证**，字节同于前（寄存器降级后端与客体执行器如故可用）；否则由**新路**：装为通用之模块项，以通编码器书标准 Wasm 之二进制，引擎装载时验之。

## 十一、所限与待办

- 寄存器降级后端（Wasm → x86-64、arm64）经数值转译而支扩充之型，豫言系统之内核易任务时存浮点与向量之寄存器（所限见 `豫言操作系统/裸机/文档/数值降级.文言.md`）。客体执行器（客体二号）唯释 i32 之底层模块；待办：执行器释扩充之型之令。
- 泛型函数于底层模式必单态而用；向量之道号、洗牌之道、向量之常，必为编译时之整数常量（经内联与化简而为字面）。
- 块之果型取所定之型；诸支皆回跳或陷之块而为实参者，其型或推之不得（以 i32 论），甚罕，遇之则绑于有型之变量。
