# 文件后缀

豫言用文件后缀区分文件的种类。源文件一律以全角句号加“豫”字结尾（`。豫`），模块名与种类段之间也用全角句号，如 `字节串。豫`、`宿主。接口。豫`、`逐元。底层。测试。豫`。后缀决定四件事：文件里能写什么、无体声明由谁提供、按哪种模式编译，以及导入时能找到哪些模块。本篇按当前仓库列出全部后缀，每种附一个仓库里的例子：缀一是源文件，缀二是导入时的查找次序，缀三是文档、测试数据、构建产物等其他文件。

各条以“缀”编号。

## 缀一：源文件

导入路径只写模块名，种类段由编译器按缀二补上。例如 `寻观「标准库」之「数据结构」之「字节串」之书。` 找到的文件是 `库/标准库/数据结构/字节串。豫`。

### 高级源文件

高级源文件有垃圾回收，编成 WasmGC 模块。

| 后缀 | 含义 | 例子 |
| --- | --- | --- |
| `名。豫` | 普通源文件，一个文件是一个模块；顶层只有定义，值由编译器确定（见[执行与编译](执行与编译.汉语.md)行一） | `库/标准库/数据结构/字节串。豫` |
| `名。脚本。豫` | 脚本：顶层就是程序体，按次序执行；可以单独构建运行，不能被导入，全树测试不发现 | `应用/性能研究/列表数组段/基准。脚本。豫` |
| `名。测试。豫` | 单元测试：顶层就是程序体，可以单独构建运行；构建库时跳过，全树测试自动发现并运行；只有测试与脚本能导入测试 | `应用/豫构/包系统。测试。豫` |
| `名。接口。豫` | 宿主接口：只写类型与 `乃` 签名，由宿主或构建时绑定的适配提供实现；每个声明编成带类型的 Wasm 导入，导入模块名是所在包的短名 | `库/标准库/宿主。接口。豫`，导入模块“标准库” |
| `名。应用接口。豫` | 应用接口：由应用实现，入口定义了同名顶层函数时编成导出 | `豫言操作系统接口/网页服务/网页处理。应用接口。豫` |
| `名。内建。豫` | 内建声明：编译器提供的语言原语，签名按编译器的原语表核对 | `库/标准库/语言核心/原语。内建。豫` |

### 着色文件

着色文件用豫言标准语法写 GPU 着色程序，详见[着色语言](着色语言.汉语.md)。

| 后缀 | 含义 | 例子 |
| --- | --- | --- |
| `名。着色器。豫` | 着色源：类型检查后译成 WGSL、MSL 与 PTX；高级代码导入它，得到构建时生成的模块 | `库/张量内核/公用。着色器。豫` |
| `名。着色器。接口。豫` | 着色内建声明：着色目标提供的运算与内建函数 | `库/着色库/着色内建。着色器。接口。豫` |
| `名。着色生成。豫` | 虚拟路径：高级代码导入着色源时得到的生成模块，由翻译器在构建时生成，只存在于编译过程中 | 导入 `公用。着色器。豫` 得到 `公用。着色生成。豫` |

### 底层文件

文件名带“。底层”的是底层文件：无垃圾回收，编成整数 Wasm，用于执行器、驱动、张量内核等系统代码。语言子集与后端见 `应用/豫言编译器/文档/底层模式.汉语.md`。

| 后缀 | 含义 | 例子 |
| --- | --- | --- |
| `名。底层。豫` | 底层源文件 | `豫言操作系统/裸机/客体二号/入口。底层。豫` |
| `名。底层。测试。豫` | 底层单元测试，全树测试照常发现并运行 | `库/底层库/中央张量内核/测试/逐元。底层。测试。豫` |
| `名。底层接口。豫` | 底层接口：每个无体声明编成一个 Wasm 导入，导入模块名是文件名去掉后缀 | `豫言操作系统/裸机/原生样例/你好/林纳克斯。底层接口。豫`，导入模块“林纳克斯” |
| `名。底层内建。豫` | 底层内建声明：底层库的原语表，调用就地编成 Wasm 指令 | `库/底层库/原语。底层内建。豫` |

### 包描述

| 后缀 | 含义 | 例子 |
| --- | --- | --- |
| `名。包。豫` | 包描述：名称、所有者、版本、简介、说明、类型、依赖等字段，由豫构读取；当作模块导入时报错 | `库/标准库/标准库。包。豫` |

### 约定的文件名

- `总集。豫`：只写包名的导入取包根的总集，如 `寻观「标准库」之书。` 取 `库/标准库/总集。豫`。底层文件取 `总集。底层。豫`，如 `寻观「底层库」之书。` 取 `库/底层库/总集。底层。豫`。
- `入口。豫`：可执行包常用的入口模块名，包描述的「类型」里写 `「入口」者『入口』也`；它定义入口函数「入口」（类型 `化「有」而「有」`），包描述可以用「入口函数」另指一个名字。底层可执行包的入口文件是 `入口。底层。豫`。

兼容输入另接受以 `.yuyan` 结尾的源文件路径。

## 缀二：模块查找

导入路径的末段是模块名。编译器按导入方的种类给模块名依次补上下列后缀，取第一个存在的文件：

| 导入方 | 依次查找 |
| --- | --- |
| 高级文件 | `名。豫`、`名。接口。豫`、`名。应用接口。豫`、`名。内建。豫`、`名。着色器。豫` |
| 着色文件 | `名。着色器。豫`、`名。着色器。接口。豫` |
| 底层文件 | `名。底层。豫`、`名。底层接口。豫`、`名。底层内建。豫` |

- 各项都不存在时报“包内模块不存在”。高级文件要导入的模块只有底层文件时，报错附上“这是底层模块，高级代码不能导入”；底层文件找不到模块时，报错列出它可以导入的三种后缀。
- 包入口与 `豫构 文件` 指定的文件可以是高级文件，也可以是底层文件，查找次序是表中高级与底层两行相接。
- 测试与脚本按全名导入（末段写 `名。测试`、`名。脚本`）：测试只能被测试与脚本导入，普通模块导入测试时报“普通模块不能导入测试”；脚本不能被导入，导入时报“脚本不能被导入”。
- 程序的编译模式看入口文件：入口是底层文件时，整个程序走底层管线；其余程序走高级管线，编成 WasmGC。

例如 `豫言操作系统/裸机/原生样例/你好/入口。底层。豫` 是底层文件，它的两条导入：

```
寻观「底层库」之书。
寻「原生你好」之「林纳克斯」之书。
```

第一条取 `库/底层库/总集。底层。豫`，第二条取同包的 `林纳克斯。底层接口。豫`。

## 缀三：其他文件

文档、测试数据与构建产物的文件名用半角点分隔后缀，个别沿用全角句号。

### 文档

| 后缀 | 含义 | 例子 |
| --- | --- | --- |
| `名.汉语.md`、`名.文言.md` | 一篇文档的现代汉语稿与文言稿，成对存放、同步修改；包描述的「说明」登记包说明这一对 | `库/标准库/包说明.汉语.md`、`库/标准库/包说明.文言.md` |

### 测试数据

| 后缀 | 含义 | 例子 |
| --- | --- | --- |
| `名-编号。豫` 配 `名。成功` 或 `名。失败` | 黄金样例：同组源文件按编号命名，标记文件写明期望。`。成功` 要求构建、运行成功，标记文件非空时标准输出须与它相同；`。失败` 要求构建或运行失败，标记文件非空时输出须包含它的文字 | `库/标准库/测试/内建/一元积-1。豫` 配 `一元积。成功` |
| `名.期望` | 期望输出：命令壳测试、原生一致性探针等按它核对程序输出 | `豫言操作系统/裸机/WASI库/测试/WASI.期望` |
| `名。测试页.html` | 浏览器测试页，在浏览器里打开运行 | `豫言操作系统/宿主/浏览器/中断。测试页.html` |
| `名。测试.mjs`、`名。测试.cjs`、`名.test.mjs`、`名.test.cjs`、`名.e2e.mjs` | 宿主代码（JS）的测试，全树测试用 `node --test` 运行 | `豫言操作系统/宿主/云工/公网取。测试.mjs` |
| `名。包。豫.txt` | 包描述模板：验收用的包描述，双宿主构建的自动模式把它复制成真正的 `。包。豫` 后使用；包的发现只收 `。包。豫` | `库/基础库/存储与时间/嵌入数据库/验收/目录文件/目录文件验收。包。豫.txt` |

### 构建产物与缓存

| 后缀 | 含义 | 例子 |
| --- | --- | --- |
| `yy名`、`yy名.wasm`、`名.exe` | 工具与程序的构建产物：文件名以 `yy` 开头或以 `.exe` 结尾，仓库据此忽略 | `yy豫构.wasm`、`yy4_bs.exe` |
| `名.树码` | 编译器各阶段的中间产物，存放在构建缓存里 | `.yybuild/豫构语言服务/<包描述基名>.语言服务.树码` |
| `yy名.树码` | 汇编树码：编译器的输出路径以 .树码 结尾时写出的豫汇模块（提案 00001 议十），豫言系统可直接从它生成豫行文件 | `yy豫构.树码` |

### 豫言系统造盘

| 后缀 | 含义 | 例子 |
| --- | --- | --- |
| `名.预置` | 预置目录（也可以是指向目录的链接）：造盘时整棵放进盘里，其中的 `名。豫` 编成 Wasm | `豫言操作系统/裸机/壳/测试/示例.预置` |
| `名.底层库` | 预置目录里的标记文件：构建同名的底层包，产物放进盘里 | `豫言操作系统/裸机/普通探针/盘/动态.预置/库/库甲.底层库` |
