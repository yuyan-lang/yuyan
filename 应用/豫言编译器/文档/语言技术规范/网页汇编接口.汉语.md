# 网页汇编接口

## 网一：唯一的目标

编译器只有一个目标：WasmGC。它使用引擎引用、类型数组、结构及 Wasm 调用栈，不依赖任何“裸指针 ABI”。本篇各节编号保持稳定，便于引用；原第二节已随旧目标删除。

## 网三：WasmGC 值型

所有普通表达式结果统一为 `(ref null eq)`，允许以下实际值型：

| 值 | WasmGC 表示 |
| --- | --- |
| 单位/擦除类型 | `ref.null eq` |
| -2^30 至 2^30-1 整数 | `ref.i31`，按有符号 i31 解码 |
| 其余 i64 整数 | `$big = struct(field i64)` |
| 爻 | i31 的 0/1；非任意对象真值 |
| 小数 | `$float = struct(field f64)` |
| 元组/引用/闭包/数组 | `$tuple = array(mut (ref null eq))` |
| 字符串/字节串/字节缓冲 | `$bytes = array(mut i8)`，长度为逻辑字节数，不附隐藏的末尾零字节；字节缓冲是可写的，只在类型上与字节串区分 |
| 构造器实例 | `$variant = struct(field i32, field (ref $tuple))`；首字段编号，次字段载荷 |
| 资源（接口文件里没有构造器的类型） | `$外 = struct(field (ref null extern))`，字段不可变；装着宿主交来的对象。字段可空只为让原型全局能用 `struct.new_default` 构造 |
| 函数代码引用 | i31 的函数表索引 |

闭包首项仍是代码引用，随后为捕获值。普通源码函数沿用擦除后的逐参闭包链；下述多参数函数型对应内部 IR，不能直接由源箭头数量推定。取函数引用须 `ref.cast (ref i31)`、`i31.get_u`，然后以对应参数数目的函数类型 `call_indirect`。不能拿宿主地址填 i31。

## 网四：调用、模块、异常

本基线总是生成 `$t0`…`$t16`；模块里的函数或动态调用用到更多参数时，按用到的最大参数数目 N 接着生成 `$t17`…`$tN`。每种类型有相应数量的 `(ref null eq)` 参数及一个同型结果。闭包 self 算在运行时参数数目内。尾调用用 `return_call_indirect`。正常分支合并点用带结果块及 `br`，不分配续延帧。

函数表按收集的闭包函数顺序分配索引；全局以 `路径#定义名` 作键分配可变 eq 引用全局；本基线该键未包含定义序号。生成器输出一个合并模块，不提供可任意拼接的独立模块 ABI。要换掉单个函数，必须保持表索引、类型和相应全局映射，或显式适配。

入口导出 `_start`。先从 data 段初始化字符串全局，再在捕获 `$error` 的 `try_table` 里按收集顺序调用模块初始化函数并丢弃结果，随后执行启动文本。未被接住的 `$error` 落到 `_start`，以异常字符串调用 `$exception` 全局里的顶层未捕获处理器（闭包）；处理器返回则执行 `unreachable`，处理器为空时类型转换失败而陷入。字节常量按 `\hh` 生成，不能先假定是有效文本而改变原始字节。

字符串异常采用 `$error` 异常标签，携带一个 eq 引用（异常字符串）。抛出即 `throw $error`，模式缺支同样如此。尝试运行调用模块内函数 `$try(操作, 处理)`：在 `(try_table (catch $error …))` 里以 `元` 调用操作闭包，正常结束直接返回其结果；捕获后离开 `try_table`，以异常字符串尾调用处理闭包。两个闭包都按公开约定间接调用（类型 `$t2`，首参为闭包自身）。`$exception` 可变全局只保存顶层未捕获处理器，由标准库经 `豫言_设置当前异常处理器` 登记。

提前返回采用 `$escape` 异常标签，携带两个 eq 引用（标识与值）；每次动态入口新分配一个空 `$tuple` 作标识，按 `ref.eq` 比较，没有次数上限。捕获时比较标识，不相等则重抛；离开动态范围的续延恢复不受支持。两个标签都在模块内定义；`$error` 以 `yy_错误` 之名导出，宿主的导入实现可用它抛出能被尝试运行捕获的异常，载荷是本模块的 `$bytes` 错误消息（JS 宿主写 `new WebAssembly.Exception(exports.yy_错误, [消息字节])`）；`$escape` 只在模块内部使用。普通算术、索引越界、类型 cast 失败的 Wasm trap 不是自动可捕获的语言字符串异常。

## 网五：宿主边界

客体与宿主之间有两条路：带类型的导入，以及过渡期保留的旧通用宿主调用 `call`。新代码只用前者。

### 带类型的导入

`。接口。豫` 文件里的无体声明（构建时没有被适配替换的）编成带类型的 Wasm 函数导入。导入的模块名是声明所在包的短名，字段名是声明名，都不带版本；同一模块的（模块，字段）唯一，同一导入两次出现时签名必须相同。导入在函数编号里排在定义的函数之前，次序由编译器决定、每次相同，宿主按（模块，字段）绑定。一个接口模块只要被链进程序，它声明的全部函数都会成为导入；宿主没有实现的，给调用时才报“接口函数未绑定：模块.字段”的桩。

标准库的宿主服务声明在 `库/标准库/宿主。接口。豫` 与 `宿主带列。接口。豫`（用到列的八个函数单独成文，免得模块成环），导入模块都是“标准库”，共六十五个函数；构建基础的工具服务声明在 `库/构建基础/构建宿主。接口。豫`，导入模块“构建基础”，三个函数。标准库的公开函数改调这些声明，公开名与参数次序不变。编译器与豫构因此只导入这两个模块、不再导入 `call`，运行编译器的宿主都要提供它们；Node 工具宿主提供全部，只有读取终端按键、进入与退出终端原始输入模式、两个拼音转换与绘监视面板是桩。

类型检查按参数与结果的类型算出边界签名，写作“参数形，参数形→结果形”。参数里的“元”不写出，所以签名的参数与 Wasm 参数一一对应。形的文法：

```
签名 = [形 {"，" 形}] "→" 形
形   = "整" | "小" | "爻" | "串" | "元" | "资"
     | "组〔" [形 {"，" 形}] "〕"
     | "列〔" 形 "〕"
     | "变〔" 支 {"｜" 支} "〕"
支   = [形 {"，" 形}]
```

| 豫言类型 | 形 | 顶层参数、结果的 Wasm 类型 | 嵌在元组里的表示 |
| --- | --- | --- | --- |
| 整数 | 整 | `i64` | 规范化的 i31 或 `$big`（与客体 `$box` 相同） |
| 小数 | 小 | `f64` | `$float` |
| 爻 | 爻 | `i32`，只许 0、1 | i31 的 0、1 |
| 字符串、字节串、字节缓冲 | 串 | `(ref $bytes)` | `$bytes` |
| 有 | 元 | 参数省去；结果没有 | 空引用 |
| 接口文件里没有构造器的类型（资源） | 资 | `(ref extern)` | `$外` |
| 元组、命名元组（按字段次序） | 组〔…〕 | `(ref $tuple)` | `$tuple` |
| `列 于 T` | 列〔T〕 | `(ref $tuple)`，元素逐项是 T 的嵌套表示 | `$tuple` |
| 有构造器的类型 | 变〔支｜…〕 | `(ref $tuple)`：首项是支序（构造器在类型声明里的次序，从零起）的 i31，其后是载荷各项 | `$tuple` |

- 顶层引用一律非空，只有元组元素可以为空。
- 转换都在客体内完成：整数拆箱、装箱，小数取出、装进 `$float`，爻转 i31，资源拆出、装进 `$外`（参数拆箱后先 `ref.as_non_null`）。列、变体与含列变的组，由编译器按形去重生成的转换函数处理；只含整、小、爻、串、元、资的组原样直传，宿主只读，不得改写客体传来的元组，只往自己新分配的对象里写引用。
- 不能过边界的类型在类型检查时报错：函数（回调请用应用接口）、泛型函数与类型变量、除列以外的递归类型、引用与数组引用等非接口文件里没有构造器的类型、动态分类值。

### 自定义段「豫言边界」

每个 WasmGC 模块都带一个名为 `豫言边界` 的自定义段，内容是 UTF-8 文本，一行一项，每行以换行结尾，字段以制表符分隔：

- `导入⇥模块⇥字段⇥签名`：每个带类型的导入恰有一行，次序与导入段相同；
- `导出⇥导出名⇥签名`：每个应用接口导出恰有一行，签名里已去掉类型为“有”的参数。

没有带类型的导入与导出时内容为空。读者遇到不认识的首字段，整行跳过。JS 宿主据此认出豫言程序，并按签名转换值；原生执行器可以不读，按 Wasm 类型核对。

### 应用接口导出

入口模块（编译顺序的最后一个）定义了某个链进程序的 `。应用接口。豫` 模块所声明的同名顶层函数时，编译器把它编成导出，导出名为 `包名/函数名`（如 `豫言操作系统启动/启动程序`）。导出函数的参数是各非“有”参数的顶层 Wasm 类型，结果是结果形的顶层类型（“有”则没有结果）。包装函数把参数转成客体值（“有”参数补空引用），有顶层直接调用的工函数时直接调用它，否则经全局槽里的闭包逐个参数调用，再把结果转回边界表示；未捕获的 `$error` 交给与 `_start` 相同的顶层处理器（打印“未捕捉的豫言异常”并以退出码 1 结束）。入口没有实现、程序却调用了的应用接口，运行时抛出可捕获的豫言异常“应用接口函数没有由应用实现：包名/函数名”。

宿主先调 `_start` 初始化各模块，再调导出；`豫言操作系统启动/启动程序` 由各宿主在 `_start` 之后调用一次，旧产物没有这个导出时只跑 `_start`。JS 宿主经胶水 `读边界导出`、`造边界导出`（JS 值按形转成 Wasm 值，结果转回 JS 值；异步时经 `WebAssembly.promising`）与 `启动导出名` 调用导出。

### 原型全局与值桥

模块向宿主暴露不可变的类型原型全局 `yy_bytes`、`yy_tuple`、`yy_big`、`yy_float`、`yy_extern`，另导出异常标签 `yy_错误`（见网四）。宿主从这些实例取得引擎实际的类型，构造返回引用；不能仅凭相同字段形状另造一个无法通过 cast 的类型。原型与宿主所用的引擎属于同一目标配置，未经验证不能跨版本混用。

JS 宿主经值桥模块（与编译器同代生成，类型定义与客体运行时逐字相同）读写嵌在元组里的值：`kind` 判别种类（空 0、小整数 1、字节串 2、元组 3、大整数 4、小数 5、资源 6），`int`/`new_int`、`float`/`new_float`、`ext_get`/`new_ext`、`tuple_len`/`tuple_get`/`tuple_set`/`new_tuple`、`bytes_len`/`bytes_out`/`bytes_in` 读写各种值，字节经值桥的线性内存交换。三家 JS 宿主共用胶水 `豫言操作系统/宿主/网页汇编/边界.mjs`：它读「豫言边界」段，按签名把 Wasm 值与 JS 值互转（整为 BigInt，小为 Number，爻为布尔，串为 Uint8Array，资为宿主对象本身，组与列为数组，变为 `[支序, …载荷]`），没有实现的导入给桩；只给标了“异步”的实现套 JSPI。各 JS 宿主提供标准库、构建基础的哪些函数，以及退出、标准错误、小数文字等的统一语义，见仓库的 `豫言操作系统/宿主/标准库宿主.汉语.md`。

### 旧的通用宿主调用（过渡）

模块里还有 `《《外调》》` 时，编译器才写出导入 `yuyan:gc-host/v1` 的 `call`，类型为 `(eqref, eqref)→eqref`。第一参是表示原语名的 bytes，第二参是按外调参数次序排列的 tuple。桥接可支持单位、i31/i64、f64、bytes、普通 tuple；i31 交给宿主时得到整数编码，宿主返回的爻再映成 i31。桥接递归深度上限 512；不通传任意构造器实例、语言闭包或宿主指针。转换使用每次调用独立的宿主侧临时存储，返回引用构造完成后全部释放。逐次复制不保证保留任意循环/共享身份，因此引用读写和闭包等操作必须留在 guest 内部。

已在 guest 内实现的核心外调包括：引用及数组新建/读写、抛出异常与尝试运行、登记顶层未捕获处理器、不安全恒等转换、整数加减乘除/相等、串与字节拼接、串比较、字节长度、取字节与截取字节串、字节缓冲的新建、读写单字节与小端四字节、填充、复制与转字节串、若干 UTF-8/JSON 字符串操作，以及字节转字符串（只收一至二百五十五）、字节串_单字节（收零至二百五十五；两者越界都陷阱）、字节串_空与字符串转整数（语义见执行与编译的编四）。它们必须遵循对应参数次序。这些名字也是「。内建。豫」内建声明可用的原语（见[类型与模块](类型与模块.汉语.md)类六）。

小数加、减、乘、除与整数转小数、小数转整数也在 guest 内完成：编译器按名字就地生成 `f64.add`、`f64.sub`、`f64.mul`、`f64.div`、`f64.convert_i64_s`、`i64.trunc_f64_s`，参数从 `$float` 或整数拆箱，结果再装箱，语义见执行与编译的编四。宿主仍保留这六个名字的实现，供旧编译器编出的产物使用。超出 i31 的整数字面量与小数字面量各登记为一个可变 eq 引用全局 `$n号`，`_start` 在初始化字符串全局之后把它们各装箱一次存入，用处读全局；直接作上述运算或整数运算参数的字面量写成 `i64.const`、`f64.const`，不装箱。

第二批数值原语由编译器按代码生成里的原语登记表就地生成，声明名与粗形签名列在原语表里：整数取余（`i64.rem_s`）；整数位与、位或、位异或（`i64.and/or/xor`）与位非（与 −1 异或）；整数左移、右移、无符号右移、循环左移、循环右移（`i64.shl/shr_s/shr_u/rotl/rotr`）；整数前导零数、末尾零数、置位数（`i64.clz/ctz/popcnt`）；整数小等、大等、无符号小于、无符号大于（`i64.le_s/ge_s/lt_u/gt_u`）；整数无符号除与无符号余（`i64.div_u/rem_u`）；小数等、不等、小于、大于、小等、大等（`f64.eq/ne/lt/gt/le/ge`）；小数最小、最大、复号（`f64.min/max/copysign`）；小数绝对值、取负、向上取整、向下取整、截断、就近取整、开方（`f64.abs/neg/ceil/floor/trunc/nearest/sqrt`）；小数饱和转整数（`i64.trunc_sat_f64_s`）、无符号整数转小数（`f64.convert_i64_u`）、小数位与位转小数（`i64.reinterpret_f64`、`f64.reinterpret_i64`）。参数照类别从整数或 `$float` 拆箱，字面量直接写常量；结果照类别装箱（整数调 `$box`，小数 `struct.new $float`，爻 `ref.i31`）；比较的结果放进 i32 局部，作条件时不装箱。语义见执行与编译的编四。这一批只经「。内建。豫」声明使用，宿主没有对应实现。
