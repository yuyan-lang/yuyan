# 标签函数类型

这是当前编译器在独立实现基线之上增加的语言规则。标签属于函数类型，按参数位置核对，检查后擦除。本文与[文言稿](标签函数类型.文言.md)同步。

## 签一：语法

```yuyan
寻观「豫章」之书。

「差」乃化「被减数」曰「数」又化「减数」曰「数」为「数」者也。
「差」者得「被减数」曰「甲」又得「减数」曰「乙」而
　「甲」减「乙」
也。

「入口」乃化「有」为「有」者也。
「入口」者得「无」而
　「书」于（「述数」于（「差」于「被减数」曰「一零」于「减数」曰「三」））
也。
```

标签写在完整操作符中：`化〇曰〇为〇`、`化〇曰〇属〇为〇`、`得〇曰〇属〇而〇`、`得〇曰〇而〇`、`〇于〇曰〇`。`得` 的标签右边须为局部名称；带参数类型时在局部名称之后写 `属 类型`，如 `得「签」曰「局部名」属「数」而 体`。独立标签项与标签项外括号无法解析。

标签须为非空名称，数字记号、注释和编译器内部名称不可作标签。标签文字独立于名称环境，局部名可以与标签相同。同一个函数类型（以及它下面的定义）里标签不重名：标签写了两次时，编译错误印出函数名、重复的那个标签与行列，如“「试」的签名里标签「甲」出现了两次”“「试」的定义里标签「甲」出现了两次”。各位置的真实参数类型可以不同。

查[规约关系表](规约关系表.汉语.md)之前，五个带标签操作符分别映射为 `化〇为〇`、`化〇属〇为〇`、`得〇属〇而〇`、`得〇而〇`、`〇于〇`，沿用原操作符的规约关系。调用照旧左结合。定义域可以直接写类型应用，如 `化「表」为「列」于「数」而「数」`；调用中的复合实参须自行括起，如 `于「值」曰（「加」于「一」于「二」）`。

顶层函数的定义带标签参数时，签名要紧挨在定义之前。定义之前没有紧邻签名时，编译错误印出定义名、文件、行列与源码那一行，并提示“「甲」的定义带标签参数，但前面没有签名（签名要紧挨在定义之前）”；同一文件里前面已有同名定义时，报重复定义并指出前一个定义的位置。

## 签二：类型规则

记普通箭头为 `A→B`，标签箭头为 `~签:A→B`。

| 规则 | 普通箭头 | 标签箭头 |
| --- | --- | --- |
| 形成 | A、B 均为类型 | A、B 均为类型且标签合法 |
| 引入 | 将局部名按 A 加入环境，按 B 检查体 | 将局部名按 A 加入环境，按 B 检查体；定义的标签须为签 |
| 消去 | 实参按 A 检查 | 实参标签须为签，实参值按 A 检查 |
| 相等 | 域与结果逐项相等 | 标签文字、域与结果逐项相等 |

`得` 在验参数类型后合成函数体类型，按参数有无标签合成相应箭头。标签保持原文，局部变量依原有绑定规则换名。

两种箭头是独立的类型构造。完整标签函数类型可以作为类型别名、参数、返回值、元组项、容器元素或泛型类型实参。变量、条件选择和调用返回的函数值均按完整类型检查。

合一比较标签和子类型。待求类型变量可以解为完整标签函数类型；独立标签项是参数描述，不能作为待求类型变量的解。期望普通回调的位置须接收普通函数；可用普通匿名函数调用标签函数来显式转接。

## 签三：应用与模式

第 n 个实参对应第 n 个形参，标签与真实类型均逐位检查。带标签位须写同一标签；普通位直接写实参。实参少于形参时，编译错误印出被调函数名与调用处的行列，并列出缺的是第几个参数、标签是什么，如“函数「求」的调用缺少显式参数，不允许部分应用；缺少显式参数：第2个参数「乙」”。

调用处的标签错写明被调函数名、第几个实参与缺、多或不符，并带出错处的文件、行列与源码行，如“函数「求」的第2个实参：参数缺少标签：期望「乙」”“函数「求」的第1个实参：无标签参数不接受标签「甲」”“函数「求」的第2个实参：参数标签不匹配：期望「甲」，实际「乙」”。记录字段里取出的函数值、回调与高阶函数返回的函数值同样照签名逐位核对标签。定义里的标签与签名不符时，就地报在定义那个参数上，如“「求」的定义里第2个参数多写了标签「乙」”“「求」的定义里第1个参数缺少标签「甲」”，列出行列，不再等到调用处才报一句没有位置的错。签名、定义与调用处的标签由同一处判定（`参签察。豫` 的「核参签」），免两处各判一半（[议题 787](https://github.com/yuyan-lang/yuyan/issues/787)）。

参数组、完全应用、字面右箭头展平、返回函数类型别名另起一组、隐式 `凡` 与 `以` 均沿用原有规则。隐式参数可以是类型参数，也可以是隐式值参数（`凡「x」属 A 而 B`，见[依值类型](依值类型.汉语.md)）；两者都不带标签，标签项不能作为其实参。依值箭头可以带标签：`化「签」为 A 者「x」而 B`。

隐式参数求解预读实参时穿过标签包装，按真实域类型匹配；读取类型的五种入口与一次有序推定规则见[类型与模块](类型与模块.汉语.md)类四。实参值、构造器子模式与局部变量按剥去标签后的真实类型检查。

回调位置的函数类型与实参函数的标签不合时，报错是一句话，写明第几个参数、期望与实际各是什么，如“第 4 个参数：期望不带标签，实际带标签「模」”“第 4 个参数：期望标签「甲」，实际标签「乙」”。一般的类型不相等报错仍印两侧的类型述文，过长的述文只留首尾两端。

## 签四：擦除与边界

类型检查后调用与模式中的标签包装消失。带类型抽象的域中保留标签，供阶段文件、接口类型、相等与悬停使用，随后随类型标注擦除。标签不参与自由变量、名称查找或换名。

运行时实参顺序、求值交错、尾位置、直接调用与原有整数去装箱保持原规则。构造器字段形、签名类别和宿主边界形按真实类型计算。无体声明按各参数有无标签合成相应匿名函数；宿主字段名和 Wasm 参数形照旧。

JSON 与豫言阶段源码保存标签项和未检查的标签抽象。标签项有一个子式；标签抽象有一个绑定体；检查后的阶段拒绝残留的未检查标签抽象。悬停中的标签箭头显示 `（化「标签」曰 类型 为 结果类型）`。

## 签五：实现范围

普通值函数、匿名函数、值构造器与模式、类型构造器参数、GC 和底层模式、无体接口签名均适用。类型应用沿参数位置核对标签，检查后的类型保留标签供签名复核，类型擦除时一并消去；同一类型构造器的应用按头与真实参数比较。着色语言的标签参数留待后续版本。顶层函数的标签参数可以设为可省参数，见签六；可变参数、乱序调用、部分应用、标签简写和自动转接均维持既有语言边界。

当前编译器已删除 `循□以〇`。顶层递归以紧邻的完整签名与定义建立；局部递归写 `复令`。仓内原来 `循「名」以` 的用例已改用上述签名递归。

## 签六：可省参数

顶层函数的标签参数可以设为可省参数（[提案 00019](../../../../提案/00019-可省参数.汉语.md)）：签名在参数类型之后写 `可阙`（后面还接参数时写 `可阙 又化…`，可省参数排在最后一组时写 `可阙为 结果类型`），定义在同一位置写 `得「标签」曰「局部名」阙则 值`，调用时可以不传。

```yuyan
寻观「豫章」之书。

「框」乃
　化「宽」曰「数」可阙
　又化「高」曰「数」可阙
　又化「名」曰「文」
　为「文」者也。
「框」者得「宽」曰「宽值」阙则「二六」又得「高」曰「高值」阙则「一六」又得「名」曰「名值」而
　「名值」接『：』接（「述数」于「宽值」）接『×』接（「述数」于「高值」）
也。

「入口」乃化「有」为「有」者也。
「入口」者得「无」而
　「书」于（「框」于「名」曰『甲』）而后
　「书」于（「框」于「高」曰「三六」于「名」曰『乙』）
也。
```

两条调用依次印出 `甲：26×16` 与 `乙：26×36`。

规则：

1. **写法。** 签名在参数类型之后写 `可阙`：后面还接参数时写 `化「标签」曰 类型 可阙 又化…`，可省参数排在最后一组时写 `化「标签」曰 类型 可阙为 结果类型`。可省参数必须带标签，写成 `化 类型 可阙为 …` 报“可省参数必须带标签：写作 化「标签」曰 类 可阙为 …”。定义的参数处写 `得「标签」曰「局部名」阙则 值`。签名里带 `可阙` 的参数，定义必须写默认值；签名里不带 `可阙` 的参数，定义写默认值时报错。
2. **默认值。** 默认值是数据：字面量、构造器作用于数据、顶层数据的名字，与[提案 00006](../../../../提案/00006-模块无计算与入口函数.汉语.md)的顶层数据规则相同，按签名里的参数类型检查。默认值含其他计算时报“可省参数的默认值只能是数据”。
3. **配对与补齐。** 调用照常写 `于「标签」曰 值`，实参按签名次序书写。类型检查沿签名第一组显式参数逐个配对：可省参数的下一个实参标签相同就用这个实参，否则补上默认值；必填参数缺少、标签写错、次序与签名不同时分别报错。补齐后的调用是参数齐全的普通标签调用，标签照旧擦除，运行时没有额外开销。隐式参数照常用 `以` 给出或推定。
4. **只能当场调用。** 带可省参数的函数出现处必须是调用的头（`「函」于 …`、`「函」以 … 于 …`）；当值传递、存进组值、作返回值都报“「函」带可省参数，只能当场调用；要当值用，请包一层 λ”。函数值的类型因此只有普通的带标签箭头。函数体里递归调用自己同样可以省掉可省参数。一条语句只有一个函数名、该函数的参数又全可阙时，这个函数名就是占据整句的调用头，等于全省调用（[议题 201](https://github.com/yuyan-lang/yuyan/issues/201)）：类型检查把它补成参数齐全的调用，默认值照常补齐。这个函数名出现在别的式子里（当实参、存组值、作返回值、写在 `令` 的定义处）时仍按值用报错；给函数起别名的具名定义（`「甲」者「函」也。`）同样按值用报错。
5. **跨模块。** 默认值随模块的检查后定义导出，别的模块调用时照样补齐；默认值改了，调用方随依赖重新编译。
6. **适用文件。** 普通源文件、测试、脚本与 `。底层。豫` 都可以用。`。接口。豫`、`。应用接口。豫`、`。底层接口。豫`、`。内建。豫` 等无体声明与构造器暂不用 `可阙`，写了报错。
7. **转发。** 包装函数要把可省参数转给内层函数时，自己也声明为可省参数并写默认值。

实现：可省参数的标签在类型里带内部后缀，与必填标签互不相等；签名与定义归并时，每个默认值拆成排在函数之前的隐藏顶层定义「《《默认：函数：标签》》」，类型取该参数的类型；参数类型引用函数的类型参数时，隐藏定义带上函数同样的类型参数（相当于 `凡「甲」又凡「乙」而 参数类型`，值也套上同名的 `设「甲」…而`），默认值照常是数据；调用处省掉的实参补成对它的引用，引用照常推定类型参数，推出的类型与该参数在这次调用里的类型相等。顶层匿名语句（脚本与壳里的一句）只写全可阙的函数名时，类型检查把整句补成不带实参的调用再照常补齐默认值；具名定义与别处按值用仍报错。悬停把可省参数显示为在参数类型之后加 `可阙`，如 `化「宽」曰「数」可阙又化…`。格式化器把含 `可阙` 的签名排成每个参数单独一行。

后续版本事项：默认值引用前面的参数或类型参数；接口文件里的可省参数；调用处显式取默认值的写法。

## 签七：构造写法

`「头」【项，…】` 的头是「列」「典」「组值」「组类」与「《《扩展名》》」以外的名字时，这是构造写法（[提案 00018](../../../../提案/00018-设计语言与引擎.汉语.md) 议十九）。语法分析器照旧；阐述把它记成构造节点（头加项列），名称解析按普通名字找头，类型检查按构造调用约定把它降为带标签调用，此后照常编译。

```yuyan
寻观「豫章」之书。

「框」乃
　化「宽」曰「数」可阙
　又化「名」曰「文」
　又化「子项」曰（「列」于「文」）
　为「文」者也。
「框」者得「宽」曰「宽值」阙则「二六」又得「名」曰「名值」又得「子项」曰「子项值」而
　「名值」接『：』接（「述数」于「宽值」）接『：』接（「缀文」于「子项值」）
也。

「入口」乃化「有」为「有」者也。
「入口」者得「无」而
　「书」于（「框」【「名」者『甲』也，『子一』，『子二』】）
也。
```

这一处等于 `「框」于「宽」曰「二六」于「名」曰『甲』于「子项」曰（「列」【『子一』，『子二』】）`（「宽」取默认值 26）。

构造调用约定：

1. **头。** 头是第一组显式参数全带标签的函数；有不带标签的参数时报“「头」不接受构造写法”。头找不到时报“未定义的构造「头」”。
2. **命名项。** `「名」者 值 也` 对应带标签参数 `于「名」曰 值`，可按任意次序书写，降级时按签名排好。签名里没有这个标签时报“构造「头」没有属性「名」”，并列出可用的属性。
3. **可省与必填。** 签名里带 `可阙` 的参数可以不写，取定义里 `阙则` 给的值（签六）；其余参数必填，缺少时报“构造「头」缺少必填属性「名」”。
4. **子项。** 字符串项与其余项依次放进标签为「子项」的参数（类型须是 `（「列」于 甲）`），没有子项时是空列；头没有「子项」参数却写了子项时报“「头」不接受子项”。甲是「文」时字符串项直接放入；甲是恰有一个只收字符串的构造器的和类型时，字符串项用这个构造器包一层；其余情况报错。
5. **信号提升。** 参数类型是 `「信号」于 甲`、命名项的值合成出信号以外的类型时，值用「信号」类型名为「常量信号」的构造器包一层（只在构造写法里）。
6. **小数字面。** 参数类型（或信号的元素类型）是「小数」时，整数字面量当作小数字面量。
7. **表达式码。** 参数类型是 `「式码」于 甲`（设计库，提案 00018 第五节）、值是顶层函数名时，值用「造表达式码」构造器包一层，并附编译器把这个函数（连同它调用的函数）译成的受限中间表示文字（`库/译场/分职/匠心译/式码译。豫`）。降级时先写占位文字，整份文件检查完后才翻译（此时同文件的函数都已检查）。表达式层只收整数、小数、爻与元组上的算术、比较、若、虑与对顶层函数的调用，调用图须无环。
8. **当场调用。** 构造写法就是当场调用，合乎签六第 4 条。「列」「典」「组值」「组类」保留给内建写法，同名函数只能用普通调用写法。

实现：阐述（`本算符物定义。豫` 的「阐述通序列」）对其余的头返回通用序列节点，命名项记成命名项节点；类型检查的合成与检查两个入口遇到它时调用 `构造写法降级。豫` 的「降构造写法」，生成带标签调用后照常检查。

后续版本事项：字符串项的包装目前只认字符串字面量，类型为「文」的变量与表达式在后续版本包装；构造节点的悬停与语义标记。

## 签八：同类型参数须带标签

签名第一组显式参数里有按写出的类型文字相同的（按签名里写出的类型文字比较，不展开类型别名），这些参数都须带标签。缺了默认是编译错误，写明函数名、哪几个参数与相同的类型文字，位置落在第一个缺标签的参数上，如“「截取」的签名里第 1、2 个参数类型都是「数」，须带标签”。例外两条：函数恰好两个参数时可以不带；确实不宜带标签的参数（如要当普通回调传）在该参数类型之后、`又`或`为` 之前写一条注释说明，就放过它。

```yuyan
「截取」乃化「起」曰「数」又化「止」曰「数」又化「文」为「文」者也。
「拼」乃化「前三」曰「文」又化「后三」曰「文」又化「中」曰「数」为「文」者也。
```

第一条报了错：第 1、2 个参数类型都是「数」，又没有标签；第二条合规。

适用范围是顶层签名（`乃`）、值构造器（`立`）与无体接口文件里的声明。局部匿名函数的签名、类型别名与函数体里的类型实参不在此列。类型构造器参数的标签由提案 00066《由组类算布局》实现，在它落地之前 `立` 的构造器不查这一条。

迁移期间，包上下文携带“缺标签只警告”属性。牌记（包配置）补全包图时，按每个包的包描述目录上寻最近的迁移名单（`应用/豫构/缺标签迁移名单。数据。豫`），只为名单内的本包设置此属性。编译器按模块所属包的属性降为警告，名单外照常报错；子进程与进程内编译共用此判定。该位计入包及模块的编译缓存身份，包移出名单后旧的警告结果随即失效。包改完就从名单里删掉，名单清空后删去这份文件。

名单由 `豫构 迁移名单` 生成：它按包把整包检查的源文逐篇读出，用编译器的词法入口（章句的「析源卷定义列标域」）解析，再按编译器同一判据（`参签察。豫` 的「签名参记们」与「缺签组们」）数出各包的处数，按包名排好重写名单，并印出有缺标签的包与处数。名单与编译器同出一份实现，不再另有一套文本扫描，只在造盘路上编、不在全仓类型检查范围内的包也不会漏（议题 #1027）。

实现：判在 `库/译场/分职/证义/参签察。豫` 的「察签缺签」一处，由卷结构察在检查定义之前调用；注释不在编译器的语法树里（语法分析把注去掉了），所以“类型之后写了注释”的豁免看源码：取这个参数类型最右一个名字的止位，往后略去空白与收括，第一个字是注释开头就算。格式检查（`应用/百工坊/源码格式化/检查。豫`）不再另判一份标签参数，只留元组命名的警告。
