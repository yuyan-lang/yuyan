# 问簿

## 一、缘起

问簿（SQL）的表与查询写成普通豫言：一张表是一个行类型（命名元组）加一条表声明，查询是带行参数的匿名函数。表的运行库是芥子的「册府」，它拿到的表声明里有两样值由编译器按类型补出，程序里不必手写：

1. **行谱**（`「行谱」于 甲`）：一行有哪些栏、每栏是什么类型，以及一行与问值列之间的编码与解码。
2. **取径**（`取径`）：从表的哪条路取候选行——全扫，或按键取行。

两样都在共用前端里按类型头名认，不看类型所在的模块，所以任何高级文件都能用，测试可以用同名的替身类型。行谱的合成与取径的补值（从查询的条件推出按键取行的等值）都在本篇规定。

## 二、行谱的合成

### 2.1 时机

构造写法（[标签函数类型](标签函数类型.汉语.md)第六节）降成带标签调用时，签名里类型为 `（「行谱」于 甲）` 的参数没有写，编译器就按甲合成一个行谱值补上；写了就用写的。

### 2.2 行类型从期望类型来

甲取自构造写法的期望类型：表声明写成

```
「邮箱账户行」即「组类」【「用户编号」乃「数」也，「邮箱」乃「文」也】也。
「邮箱账户」乃（「册」于「邮箱账户行」）者也。
「邮箱账户」者「置册」【「名」者『邮箱账户』也，「主键」者『用户编号』也，「子项」者（「列」【】）也】也。
```

时，值 `「置册」【…】` 的期望类型是 `（「册」于「邮箱账户行」）`，编译器从中取出甲 `邮箱账户行`，展开透明别名，行类型就是那个命名元组。

推不出甲时报错：`合成行谱要知道行类型：给表声明写上签名`。所以表声明要写签名；不写签名的表声明不能由定义自己推出行类型，报的就是这一条。

甲须是命名元组（`组类` 的带名项的写法），每一项的类型限于「数」「小数」「文」「帛」「爻」与这五种类型各自的 `（「或可有」于 …）`。别的类型报错：

```
表的行类型「坏行」里「名单」一项的类型「列 于 文」存不进表：只收数、小数、文、帛、爻与它们的或可有
```

### 2.3 合成的值

合成的值是 `（「造行谱」于「栏们」曰 … 于「编」曰 … 于「解」曰 …）`，甲由期望类型定：

- **栏们**：按命名元组项的次序一项一栏，是 `栏` 的列。栏名取项名；`型` 照项的类型取 `整栏`、`实栏`、`文栏`、`块栏`、`爻栏`（或可有取里面的类型）；`可空` 在或可有时为阳，其余为阴。
- **编**：`（得「行」而「列」【编一，编二，…】）`，按项次编成问值的列。数作 `值整`，小数作 `值实`，文作 `值文`，帛作 `值块`，爻在阳时作 `值整` 一、阴时作 `值整` 零；或可有的栏在可无时作 `值空`，在可有时照里面的类型编。
- **解**：`（得「列」而 …）`，按项次把问值解回各项。数、小数、文、帛取里面的值；爻按非零为阳；或可有的栏在 `值空` 时得 `可无`，否则把里面的值包成 `可有`。栏数不对或值的种类对不上时，以 `行与表结构不合：…` 抛祸，写明第几栏、应为什么、实得什么。

合成的值只含匿名函数、列与构造器，是数据，所以表声明照样能放顶层（[执行与编译](执行与编译.汉语.md)第五节）。

### 2.4 实现位置

合成在 `库/译场/分职/证义/构造写法降级。豫` 的「降构造写法」里，紧挨着表达式码那一段。降级入口多收一个「期望类型」，检查对象的入口（`物验类。豫`）把期望类型传进来，按定义合成类型的入口（`验类具。豫` 的物类合成）传可无；于是有签名的表声明合成得出来，没签名的表声明在合成类型那一步报上面那条错。

## 三、取径的补值

取径的补值从查询的条件里推出按键取行的等值：写了默认值的「径」在条件里有可推的整数等值时换成「键等」，推不出就留着默认值。眼下只认单表的「径」与整数的等于。

### 3.1 时机

可省参数取默认值的那一处（[标签函数类型](标签函数类型.汉语.md)第六节），编译器从同一调用里标签为「择」的实参推一条按键取行的等值条件，插推出的「键等」值；推不出就照旧插默认值的引用。时机在类型检查之前，插入的式子照常过检查，所以规则都按未检查的形态写：按名投影是命名元组投影节点，短路且是短路且节点，「行」写作匿名函数的参数（在体中是绑定变量，第一个参数为一，逐层加一）。

「择」须是字面的匿名函数。

### 3.2 单表

「检」「聚」「改」「删」的「择」形如 `得「行」而 体`。沿体最外层的短路且（可以嵌套）逐项看，取第一条 `（「行」中「名」）等于 X` 或 `X 等于（「行」中「名」）` 的项，补

```
「键等」于「栏名」曰『名』于「值」曰（「值整」于 X）
```

其中 X 里不出现「行」（「行」指匿名函数的参数，名照用户写的）。

实参里写了「径」的用写的，不补。短路或里面的等值不补；X 里出现「行」的也不补。

### 3.3 后续版本

「文同」（文字栏的等值）与两表连接的「右径」留待后续版本。文字栏眼下全表扫；连接的「右径」眼下照默认值 `（得「左行」而「全扫」）`。范围条件、或、排序走索引也留待后续版本。

### 3.4 补出来的值

补的只是候选行从哪里来：候选行照样经「择」筛一遍，结果与全扫相同。造值用「取径」的构造器「键等」与「问值」的构造器「值整」，都按类型头名认，按默认定义所在文件与名字取引用。

### 3.5 实现位置

补值单写一篇 `库/译场/分职/证义/取径补值。豫`，入口「补取径」由「补齐可省参」（`术应用隐参合成。豫`）在插默认值那一处调用，收参数类型、本次调用的实参列与默认值的引用，推得出就给推出的式子，推不出就给默认值的引用。补出的值只含构造器调用、字符串与原有的式子，随后照常过类型检查。

## 四、两条规则为谁而设

两条规则为芥子「册府」而设：表声明里不写行谱，册府拿到的就是编译器按行类型合成的栏与编解码；查询里不写取径，册府拿到的就是编译器从条件里推出的访问路径（眼下是整数的等于）。程序里看不到行谱与取径的构造，表与查询照常写成普通豫言。
