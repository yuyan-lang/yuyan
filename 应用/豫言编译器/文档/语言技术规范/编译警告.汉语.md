# 编译警告

这是提案 00002 的编译警告通道规范。当前实现处于开发与验收阶段，整步状态见[实施记录](../../../../提案/00002-实施记录.汉语.md)。

编译警告默认启用，构建继续进行。警告、定稿错误与内部错误共用诊断格式 `文件:行:列：所在定义：说明`，行与列从一开始。诊断的级（错或警）是必填字段：警告行（级为警）整行前加 `警告：`，错误行照旧不带冠，于是同一条输出里哪条编不过一眼可辨（议题 #1419）。顶层匿名语句的所在定义写 `顶层语句`，内部错误的说明冠 `内部错误：`。`--no-warnings` 关闭本次编译的警告输出及警告资料记录；覆盖分析、成块归属检查等照常进行，结论属于编译错误时照常报出。并行工作进程接受相同参数，成功任务产生的警告行转发到父进程标准错误。

类型检查找不到名字时报编译错误，首行是 `文件:行:列：所在定义：未定义的名字「名」`。名字是标准库改名前的旧名时，另起一行 `「旧名」今作「今名」`；有相近的可见名字（本地绑定、本文件顶层名与“观”打开的模块里，按编辑距离取，至多三个）时，另起一行 `相近的名字：「甲」「乙」`。外层类型检查原样传出定稿诊断。旧调用缺少源码范围时由统一出口报告内部错误。

类型检查推不出函数应用的隐式参数时报编译错误，首行是 `文件:行:列：所在定义：函数「名」的隐式参数无法完全确定：未能确定 甲`，指向出错的那次函数应用；随后依次列出 `函数的隐式参数：`、`形参类型：`、`期望类型：` 与 `提示：`。期望类型是检查模式下这一位置要求的结果类型；合成模式写作 `没有期望类型（合成模式）`。外层类型检查原样传出定稿诊断。

类型不相等与拉姆达检查失败也报编译错误：物验类（按期望类型检查表达式）、物类合成（按值合成类型）遇到以 `不相等！` 或 `拉姆达只能检查为明确的函数类型：` 起头的报错时，取正在处理的表达式自己的源码范围（「本式源域」，不往子式里找），依次退到「今源域」「今定义域」，经统一出口加上所在定义与原报错说明。外层类型检查原样传出；`-vv` 时同样使用这个格式。

「告定讯」（报告定稿诊断）按“调用处给定的范围、进入源码范围标注节点时记下的「今源域」、进入定义时记下的「今定义域」”的次序取第一个有解者。调用处给的是出错子式自己的范围（字面量、类型位置、调用头、标签、元组项等出错处的「本式源域」），不取整条语句；整个定义都错的（如泛型定义漏写 `设`）才给定义范围。「今定义域」是名称解析记下的定义声明名范围；顶层匿名语句记整句的范围。三者皆无时当场报内部错误“诊断缺少源位”。「报定」（构造诊断）的源码范围参数必填，文件名为空或行列为负时当场报内部错误。诊断组类保存完整起止行列、所在定义与原说明。待报队列在登记时构造诊断、保存当时的源位与定义名，卷末按登记顺序一次报出。

类型位置上写的名字解析到局部绑定的值时，编译器报出遮蔽：说明这个值遮住了同名的类型，并把两处位置都写出来——局部绑定的位置与被遮住的定义的位置。例：`「笔」：局部绑定在 甲。豫:12:9，遮住了 甲。豫:3:5 定义的类型「笔」`。函数调用的头是局部绑定的值、而同名的顶层函数另有定义时，同样报出两处位置：`函数调用的当前结果不是函数：局部绑定在 甲。豫:5:9，遮住了 甲。豫:2:1 定义的函数「移积」`。这两类报错带出错子式的文件、行列与所在定义名（议题 691、1056）；环境里找不到那个局部绑定的位置或同名的定义时，退回原来的一句话。

模式里的裸名与可见的构造器同名、被当成构造器而所属类型又不合时，编译器在模式名自己的位置报错：`模式的裸名「名」被认成了构造器（定义在 文件:行:列），不属于被鉴值的类型「类」；要在这里绑定新名字，请写 得「名」`。要在这里绑定新名字，写 `得「名」` 即可（[提案 00069](../../../../提案/00069-模式新名写得.汉语.md) 第一段，议题 950）。环境里找不到同名的构造器定义时，照旧报“模式的构造器「名」不属于被鉴值的类型「类」”。

编译入口以「成否」（结果类型）接收阶段执行的结果，成功支交回成功值，失败支将诊断写到标准错误并以退出码 1 结束。内部传递的定稿标记在出口移除，调度转达诊断及失败状态。内部异常在这个边界补上当前源码范围与定义名；尚未进入源码节点时取本次任务文件的首行首列。全构建与工作进程经过同一出口。语法树每个子式在展开后都带自己的源码范围（提案 00059 第二步），类型检查进入子式时记下它，未显式给范围的诊断也落在出错子式上。

语言服务产物沿用零起始、左闭右开的源码范围。警告资料包含 `种类：警告`、完整 `范围`、`内容`、`定义`，与定义位置和悬停资料共同保存。类型检查资料通过阶段快照持久化；模式展开恢复该资料并写回新增警告，保留已有定义和悬停信息。编译警告阶段产物同样保存完整范围与定义名（级固定为警，不另存一栏），冷编与缓存命中使用同一格式化出口。

警告开关与覆盖分析的步数上限参与编译缓存身份。开启与关闭分别保存语言服务产物，避免关闭模式复用含警告的旧产物；覆盖分析的结论是编译错误，编译不成功就不留检查结果，所以开关只影响仍走警告通道的警告。步数上限不同也分别保存，恢复原配置后可复用原缓存。

未使用的匹配分支编译错误指向该支的 `有` 或 `或有` 关键字。名称解析从原源码重建关键字范围，跳过注释、字符串和引号名称；分支类型检查与模式转换保留范围，决策树展开移除标注。

重复分支报编译错误“未使用的匹配分支”。GADT 构造器结果与分析式类型合一时确定冲突的分支报编译错误“不可达的匹配分支”；该分支体跳过类型检查，其他类型错误继续报告。

顺序执行（`甲 而后 乙`）要求甲的类型是「有」。甲不是「有」时报编译错误：错误指向甲，正文以 `而后前面的值被丢弃（类型「爻」）：要处理就用它；不要就写 令「」为（…）而 …` 为例，写出甲的类型与两种改法。甲的类型是「有」时不报；前式明写 `令「」为 甲 而 乙` 的属于「令」的绑定，不报。

## 纯调用丢值与令绑名未用（议题 1458 第一段）

另有两种警告，第一段只发警告、不挡编译，第三段整体改成编译错误。

`令「名」为 值 而 体` 里的「名」在体里一次都没用到时，发警告，指向绑定名，正文为 `「名」没用到（值的类型是「…」）：要用就接住；要丢就写 令「」为`，其中 `…` 是值按悬停写法的类型。名字是通配 `「」` 的、函数参数（`得`）、`复令` 与顶层定义不在此列。

没有副作用的函数被直接调用、结果又没被用到时，发警告，指向这次调用，正文为 `「名」没有副作用，它的结果没被用到，这一句什么也没做；要用新值就接住它`。覆盖 `令「」为 调用`、绑了名字而没用、以及 `调用 而后 …`；后一种前式的类型是「有」时也报，因为它本来就什么也没做。只认最外层就是函数调用的式子；值是「若」「鉴」「令」一类复合式时宁可漏报，不误报。

副作用按调用关系推断（`库/译场/分职/证义/纯性察。豫`）。写匣、改数组、输入输出、宿主接口（`。接口。豫`、`。底层接口。豫`、`。应用接口。豫`）与抛出算有副作用；读匣、造新匣、算术与构造值不算；经函数参数、闭包、函数值的调用说不准，一律当有副作用。递归的顶层函数按强连通分量求不动点：先全当纯，见不纯则降，宁可漏报、不误报。推断结果写进模块接口的「纯性表」分区，跨模块可用；有签名文件的模块从实现推出。`。内建。豫` 里的名字只认一张纯的内建原语名单，名单之外一律当有副作用。

「--弃果」检查（`应用/百工坊/源码格式化/检查。豫`）把 `令「」为` 也算作丢弃：成否与出错码用通配丢掉时照报。

可识别的匹配在分支类型检查后保存覆盖矩阵，文件类型检查结束时用完整定义进行有用性与缺例分析。冗余分支报编译错误，指向对应分支；缺失报编译错误“缺少匹配分支”，指向 `鉴` 关键字，最多打印三个例子。运行期缺分支异常里的源位也取同一处（「鉴报域」），同样指向 `鉴` 关键字，两种报错因此行列一致（议题 1452）。名称按匹配处的原始声明前缀、已检定义与局部避名解析，导入别名保留限定名；内建构造器（阳、阴、元，以及内建列表的罄、缀）没有声明，名字未被本地定义或局部绑定占用时用内建名。不带鉴范围的中间形式暂沿用原首支范围。冗余分支不因分支体只是抛错而豁免。这些结论在类型检查末尾一次排成定稿诊断报出，不在第一处就停；模式展开阶段不再重复报未使用的分支。语言服务产物照旧供编辑器显示悬停、跳转与警告。待办事项：补全全部模式转换。

覆盖分析把结论分成三类，都是编译错误。证出缺例的报“缺少匹配分支”，附最多三个缺例；已证明有缺例而当前作用域表示不出名字时，仍报“缺少匹配分支”并省略例子。证得多余的报“未使用的匹配分支”，只在证出来时报告；证不出多余的不报。既没有证出缺例、也没有证尽时报“鉴的穷尽证不出”，缘由有两类：候选补全的步数预算用尽，或候选回溯留下未知（原始引用字段、未定类型循环等），这两种写成“鉴的穷尽证不出：补全分支，或加一个兜底分支（可调大环境变量「豫言穷尽步数」）”；模式不能转换成覆盖分析用的模式、分支缺范围或分析类型不是单列时，整条匹配不能参与证明，写成“鉴的穷尽证不出：此处的模式无法分析，请改写模式或补一个兜底分支”。已证出缺例时只报缺例，不再报“证不出”；证不出的匹配不据此报告多余，也不把未知候选打印成缺例。

没有构造器的名义类型（如标准库 `帛`、接口文件里的资源类型）由原语或不安全转换创建，候选查询按无穷域处理，不能用空构造器集合证明无居民，含这类字段的分支不据此报冗余；有构造器而全被 GADT 剪去的类型仍是空域。标准库 `匣`、`匣列`、`强杂匣列` 在选列时也按无穷域处理；含这些引用类型的全通配候选保留为未知，因此不据此报告冗余，也不把未知候选打印成缺例。身份按标准库包所有者、包名及包内模块路径核对，其他包的同名类型继续按自己的构造器分析。待办事项：补全引用字段的联合可居性分析。

候选补全的步数预算由整个搜索共享，候选回溯与列交换都消耗同一预算，各分支不能重置；上限读环境变量 `豫言穷尽步数`，没设或设成空串时取缺省一万步（一百万步时含递归大类型的文件要编一分多钟），同时保留递归路径的深度限制。每个匹配各有一份这样的预算，零与负数照收，零预算立刻证不出。编译器的命令行入口启动时读一次环境变量，写进全局设置；这个值计入编译缓存身份，与警告开关同样处理，CI 与将作一律用缺省值，环境变量留给本地试验。预算耗尽返回未知，不把未知当作无候选证明，也不打印为缺例。构造器名称环境在打印缺例首次请求名称时准备，每个匹配至多准备一次，包含不可见结果；没有名称请求的匹配省去该准备过程。

递归候选路径同时登记闭合类型与含自由类型变量的类型。闭合类型的重复路径先单独证该类型无居民，证出才剪去展开路径，证不出记未知；未定类型的重复路径记未知；两者都继续尝试其他构造器，不据此证明整类为空，也不据此把分支判成多余。构造器的命名参数（标签项）在取类型头时剥去标签，按真实字段类型做有限性判断与字面特化。显式子模式仍逐层检查。泛型递归专项验证未知保留与后续终止候选可用，实际大型文件的正常警告验收仍在进行。

文件类型检查结束时还报出无法分析的鉴：模式不能转换、分支缺范围或分析类型不是单列时，登记鉴的关键字范围，卷末逐个报编译错误“鉴的穷尽证不出”，不再静默跳过整条匹配。文件覆盖队列为空时直接返回；警告开关关闭时这两项分析照做，不清空待验项与无法分析项，结论照记作编译错误。独立类型检查的原声明输入现已补齐，须提供“抽象语法”；模式展开须提供“类型检查资料”。已检分支保留的诊断范围在模式展开时移除，独立阶段按此契约验证。

词法层的字符串未闭合报编译错误 `文件:行:列：所在定义：字符串未闭合（『 起于第 N 行第 M 列）`，位置指向开引 `『`。字符串字面里的原样换行照《词法与语法》允许，所以漏写闭引时串常被后面某个 `』` 收住；词法记下这个串的起止行，此后语法错或定稿诊断的位置落在这个串开始之后时，在诊断说明之后另起一行写 `前面第 N 行起的字符串跨了 K 行，是否漏了『』`，提示错可能出在漏写的闭引上。

名称解析层：局部名（参数、`令`、`复令`、内部定义与模式变量）与 `寻` 导入的模块别名同名、这个名字又在绑定范围之外被当成值用时，在“命名空间不是一等值，不能作为参数、返回值、类型或数据使用：文件”之后另起一行写 `局部名「名」（第 N 行绑定）与导入的模块「名」同名`，把绑定的那一行与同名的模块一起指出。绑定处由名称解析记下，报错照常中止编译。
