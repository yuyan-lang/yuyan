# 证明层

这是[提案 00016](../../../../提案/00016-证明层与精化擦除.汉语.md)的证明层规范，写当前实现的技术事实。证明层与实现层分在两个文件：实现层照常编译，证明层写精化类型与证明，编译产物只来自实现层。证明由证核（证明内核）核对，由证场（证明细化器）细化成证明项。本文与[文言稿](证明层.文言.md)同步，后续版本的事项列在证九。

## 证一：两层文件与目录

| 层 | 文件 | 内容 | 编译产物 |
| --- | --- | --- | --- |
| 实现层 | `X。豫`、`X。接口。豫` | 现行语言 | 照常生成 |
| 证明层（人写） | `证明/…/X。证明。豫`、`证明/…/X。证明接口。豫` | 精化类型、一般依值类型与证明 | 无 |
| 证明层（证场生成） | `证明/…/X。证明项。豫`、`证明/…/X。证明项接口。豫` | 细化后的签名与证明项、归纳规则 | 无 |

包的 `证明/` 子目录与源码目录一一对应：`<包>/<相对路径>/X。豫` 配 `<包>/证明/<相对路径>/X。证明。豫`，`X。接口。豫` 配 `X。证明接口。豫`。生成的证明项与手写证明同目录，后缀换成 `。证明项。豫` 与 `。证明项接口。豫`。例如 `库/豫章/形制/次第。豫` 配 `库/豫章/证明/形制/次第。证明。豫`，生成 `库/豫章/证明/形制/次第。证明项。豫`。

- 证明文件按相对路径找配对的实现文件；配不上实现文件时，命令报出证明路径与预期的实现路径。
- 实现文件可以配证明文件，也可以单独存在；单独存在的定义记作未证。
- 证明层可以读配对的实现文件与它的导入闭包；闭包里实现层的定义进入证核的核验境，依赖包的证明项文件按已有文件核对来源与摘要。实现层的构建只读实现层。
- 整个 `证明/` 按目录排除在实现层构建之外，格式检查与全树测试的文件发现也按目录区分。
- 证明文件留在本包；每个包照旧一份包描述与包说明，仓库根目录的目录结构照旧。

四种后缀都入库。手写的两种是证场的输入；生成的两种是证核的输入，证核读证明项文件；实际定义由译场（编译器核心）前端经证场取来交给它。证场生成证明项时依次写文件头、本模块严格正类型的归纳规则与细化后的正文。

## 证二：证明层的语言

证明层沿用现行豫言文法，新增的只有证核提供的内建名字，以及四条只在证明文件里生效的规则。

### 内建名字

| 名字 | 签名或写法 | 用处 |
| --- | --- | --- |
| 「辞类」 | 宇宙 | 命题的类；类型属它的是命题，擦除时删去。 |
| 「侔」 | `「侔」乃凡「甲」而化「甲」又化「甲」为「辞类」者也。` | 相等命题：两边算得同一类型的相等成员时，恰有一个成员「元」。 |
| 「自反」 | `「自反」乃凡「甲」而凡「值」属「甲」而（「侔」于「值」于「值」）者也。` | 两边算得相同即证；也用来证一个爻式算得「阳」。 |
| 「代入」 | `「代入」乃凡「甲」而凡「左」属「甲」又凡「右」属「甲」而化「所证」属（化「甲」为「辞类」）又化（「侔」于「左」于「右」）又化（「所证」于「右」）为（「所证」于「左」）者也。` | 以等代等；表层由证场补「所证」。 |
| 「悖」 | `「悖」乃凡「丙」而化「阴」为「丙」者也。` | 由谬得一切，用在不可达分支。 |
| 「爻分」 | `「爻分」乃凡「丙」而化「判」属「爻」又化（化「判」为「丙」）又化（化（非「判」）为「丙」）为「丙」者也。` | 按爻分情形，两支各得一个证据；擦成「若」。 |
| 「择类」 | `「择类」乃化「甲」属「类」又化（化「甲」为「辞类」）为「类」者也。` | 精化类型（子集型）：甲里谓词成立的那些值；值就是甲的值，可以直接当甲用；擦成甲。 |
| 「择证」 | `「择证」于 目标类型 于 值 于 证据` | 显式造一个择类的值；证据在零次位置，擦除时删去。 |
| 「必返」 | `「必返」乃化「类」为「类」者也。` | 结果修饰：必定正常返回，以资源够用为前提；擦成原类型。 |
| 「隶」 | `「隶」乃凡「甲」而化「项」属「甲」又化「类」为「辞类」者也。` | 成员命题：项属于给定的类型；项可以是可抛的实现层项，常是实际定义或对它的调用。 |
| 「已返」 | `「已返」乃凡「乙」而化「值」属「乙」为（「隶」于「值」于（「必返」于「乙」））者也。` | 已经是值的项正常返回。 |
| 「接返」 | `「接返」乃凡「乙」又凡「丙」而化「项」属「乙」又化「续」属（化「乙」为「丙」）又化（「隶」于「项」于（「必返」于「乙」））又化（化「值」属「乙」为（「隶」于（「续」于「值」）于（「必返」于「丙」）））为（「隶」于（「续」于「项」）于（「必返」于「丙」））者也。` | 先算的项正常返回，续的语境对每个值也正常返回，整体就正常返回；「续」是求值语境。 |
| 「幽」 | `「幽」乃化「类」为「类」者也。` | 只为证明而用的值；擦除时删去。 |
| 「假」 | 定义体写 `「假」` | 记作假设，列进可信基。 |
| 「待证」 | 定义体或子项写 `「待证」` | 还没写完的证明，算未证。 |
| 「某归纳」 | 证核为每个严格正的「立」类型生成，如「列归纳」 | 归纳规则；证明项文件里照抄全文。 |

### 四条规则

- **爻式即命题。** 类型位置上写爻式，就是命题“它算得「阳」”：`「阳」` 是真，`「阴」` 是谬，`（「序数」小于「长」）` 这类比较与 `且`、`或`、`非` 直接写成爻式。
- **命题参数是交类型。** 签名里写成单独的参数，如 `又化（（「计」于「列值」）大于「零」）`；在证核里它是交类型：成员对每个证据都成立，证据留在零次位置，运行时省去参数位置。调用时用 `于` 显式给出证据；证场把源码里给出的证据放进证明项，从上下文自动补证据列在证九。「幽」的参数同样是交类型。
- **择类是子集型。** `「择类」于 A 于 谓词` 的值就是 A 的值，可以直接当 A 用；谓词是这个子集型的成员条件。「择证」把值与证据配成一个择类的值，供需要显式证据的地方使用。
- **精化签名谈实际定义。** 证明文件里给实现层定义写的签名 `「定义名」乃 T 者也。`，读作命题 `「隶」于「定义名」于 T`：实际的定义属于 T。T 擦除后的计算部分与实现层的签名一致；证场与证核按这条成员命题核对实际定义。证明文件里同名的 `「定义名」者 … 也。` 是写法甲的副本，读法见证六。

### 证明项

证明就是带依值类型的豫言项，写法沿用现行语法（`得…而`、`于`、`鉴…而 或有…则`，模式里的新名字照 00069 写 `得「名」`）。证核对证明项做类型检查，这一步可判定：相等改写要写明所证，计算有步数上限，子集型与交类型的证据都在项里给出。找证明由人、AI 与证场承担；证核做检查。

### 表层的两种写法

用到归纳的证明，表层可以直接写归纳规则，也可以递归写，两种都由证场细化成同一种证明项。

- **直接写归纳规则。** 证明里直接写 `「列归纳」` 这类规则，「所证」可省，证场从目标与被归纳的变量推出。例：

```yuyan
「连结合」者设「物」而得「前」曰「甲表」又得「中」曰「乙表」又得「后」曰「丙表」而
　「列归纳」
　　于「自反」
　　于（得「头」又得「尾」又得「归」而「代入」于「归」于「自反」）
　　于「甲表」
也。
```

- **递归写。** 证明里直接递归调用同一个定理；证场识别对原形参的构造器分支，把递归调用换成归纳假设，并补全省略的所证。递归须是结构递归，递归实参为该支拆出的同类型字段；互递归、嵌套递归与对类型参数递归列在证九。

## 证三：语义：计算类型论

**计算系统。** 证明层的计算系统是豫言的按值求值，规则见[执行与编译](执行与编译.汉语.md)编一至编四。证核用自己的按值符号求值器做化简与反射计算；编译出来的代码只在被证程序以编译形式运行时进入可信基。

**类型。** 类型是闭合豫言值上的部分等价关系：它规定哪些值是成员、哪些成员相等，成员之间自反、对称、传递。`a` 属于 `A`，指 `a` 求值得到 `A` 的成员；抛出的情形见下。

- `「列」于「物」`：成员是有限个 `「缀」` 最后接一个 `「罄」` 的值，各元素是 `「物」` 的成员；两个列相等，当且仅当长度相同、逐项相等。成员一律有限，这是归纳之所以成立的根源。
- `「侔」于 甲 于 乙`：甲、乙都算得出同一类型的成员且相等时，恰有一个成员「元」；否则是空的。命题都这样：真则有成员，假则空。爻式作命题时，算得「阳」则有成员「元」，否则空。
- `化「x」属 A 为 B`：成员是这样的豫言函数 f：对 A 里任意相等的 a 与 a'，`f` 于 a 与 `f` 于 a' 都正常算完，并在 B 里相等。
- `「择类」于 A 于 P`：A 的成员里 P 成立的那些，相等照 A；它是 A 的子类型。
- 交类型（命题参数、「幽」）：对每个证据都属于结果类型、证据留在零次位置的那些值。
- `「隶」于 t 于 T`：t 求值得到 T 的成员时，恰有一个成员「元」；否则是空的。T 是 `「必返」于 B` 时，说的是 t 正常算完、得 B 的成员。T 是函数类型 `化「x」属 A 为 B` 时，等于对 A 的每个成员 a 都有 `「隶」于（t 于 a）于 B`；定义域是商类型时，还要证相等的实参得相等的结果。

**一切函数都可能抛出。** 实现层签名 `化 A 为 B` 在证明层读作可抛的 B：对 A 的任一成员，结果要么是 B 的成员，要么抛出、中止或不终止。每个通过类型检查的实现层定义自动属于它自己类型的基本解释，这是精化的起点。

**逐步精化。** 在基本解释之上可以逐条加：

- 必返：在前置条件下一定正常返回，前置条件写成命题参数，结果写 `「必返」`，如 `化「列值」属（「列」于「乙」）又化（（「计」于「列值」）大于「零」）为（「必返」于「乙」）`。
- 返回什么：结果写成 `「择类」`，如 `为（「必返」于（「择类」于「数」于（得「值」而（非（「值」小于「零」））且（「值」小于「二五六」））））`。
- 何时抛出、抛出什么：抛出的信息满足某个谓词；豫言的异常带字符串信息。写法随有状态代码的方案一并定。

结果写 `「必返」` 时承诺正常返回；只写结果类型时按基本解释可抛，要把它当证明用，先证 `「必返」`。`「必返」` 以资源够用为前提：栈用尽、内存耗尽造成的中止由运行环境承担。

前置条件能写成结构谓词的（如“列有项”写成规约谓词「有项」），优先写成结构谓词：它靠计算与归纳就能证，也容易跟着数据传下去。写成算术时，前置条件穿过别的函数要先证出等式，线性算术的判定过程列在证九。

**相等。** 类型对求值封闭：a 算一步得 a'，则 a 与 a' 在任何类型里相等。证核核对相等时做符号求值：被鉴的是构造器就往下算，遇到变量就停。符号求值照按值调用：实参是值，或取值于全类型的变量时，才把它代进函数体；实参尚未成为值时，用按值调用下成立的等式，如实参在函数体里恰好用一次、用到它之前只有不抛不中止的计算，就可以把它挪进去。例如 `「接列」于「罄」于 X` 照「接列」的定义算成 X，X 可以是尚未求值的项。步数按抽象步计，附注随证明项文件存放列在证九。

相等用外延相等；函数外延与商类型列在证九。

**整数。** 「数」是六十四位补码。加、减、乘按 2⁶⁴ 回绕；除法与取余向零截断，余数的符号随被除数；比较为六十四位有符号比较，结果为爻。除数为零、最小整数除以负一一律中止；最小整数对负一取余得零。中止就是程序终止，尝试运行接不住。四种宿主同一规则：网页汇编由指令陷阱实现；冶铸在 AMD64 与 ARM64 上生成同样的检查，ARM64 硬件除零不陷，由冶铸先查除数再跳陷阱。证明层照这套语义建模，与[执行与编译](执行与编译.汉语.md)编四一致。

**可靠。** 证核的每条类型规则对这套语义成立；擦除定理由此得到，见证五。

## 证四：证核与证场

**两包与分工。** 证核只依赖豫章（标准库），检查一种小的核心演算，是可信基；证场依赖豫章、章句（语法树）、译场（编译器核心）与证核，把 `。证明。豫` 细化成证明项，不可信。证场出错时，证核拒收。实现层的构建只依赖实现层。

**核心项。** 证明项与实际定义共用核形（核心项定义）的「核项」；约束变量用从零起的德氏下标，全局名带模块身份与名称，次数分零次、多次、未定次。证明项文件读入后先核定次数，再求值。

**证核认什么。** 证核的递归与终止只经归纳规则：证明里的递归由证场译成归纳规则，证核核归纳规则的应用。核一条定义时，环境里只有在它之前核过的定义；定义自己的名字留在环境之外。证场漏判一处非结构递归时，译出的项里留着自身的名字，证核报“「名」尚未定义：证明不得引用自身”。

**步数上限。** 证核的求值器共用一千万抽象步的预算；超预算的计算报「步数超限」并拒收。证核只收算完了的计算，检查一定停。步数按抽象步计，各宿主得同一结论。

**严格正性。** 严格正指被定义的类型只出现在构造器字段的正位置。负位置有三种：函数的定义域；「匣」「匣列」这类可变容器的元素；签名文件里抽象类型的参数（看不见实现，第一版一律当负位置）。经「列」等别的「立」类型嵌套时，查那个类型的参数在它自己的构造器里严格正。证明层自己定义的「立」类型须严格正；证核对判为不严格正的声明报“非严格正：证明层的立声明被拒绝”。归纳规则只给严格正的类型；实现层的非严格正类型照样存在，这类值的性质用步数归纳（步进索引）去证，列在证九。

**宇宙。** 「类」是类型宇宙，「辞类」是命题宇宙；两者分层，「类」不属于自己。第一期的宇宙层级到一为止。

**归纳规则的生成与照抄。** 证核为每个严格正的「立」类型生成一条归纳规则与一条计算规则，名字是类型名接「归纳」，如「列归纳」。归纳规则的所证落到「类」，命题也是类型，所以命题与计算类型都能证。生成函数对一切严格正声明做同一套构造：按构造器次序生成分支，每个直接递归字段配一条归纳假设；内建列的规则独立生成，归给为它起别名的模块（豫章的形制/次第）。

证场把归纳规则照抄进定义该类型的模块的证明项文件，谁定义类型谁生成；下游包只核对已有文件，生成的内容留在本包。那个模块未配证明文件时，生成一份只含归纳规则的证明项文件。证核照「立」声明重新生成签名与计算规则，与文件里的照抄逐字比对（绑定名归一后比较），有不同即拒收。

**大小论证只做一次。** 每条归纳规则的计算内容是一个结构递归的豫言函数，如「列归纳」的「行」。「列」于「物」的成员都是有限的列，对长度做一次归纳，就证明了「行」对每个成员都算得完、结果属于所证于表。归纳规则由证核里同一个生成函数照「立」声明生成，这个论证对生成函数做一次，对一切严格正声明都成立。

**可信基。** 证明成立依赖这些内容：按值求值规则；证核（求值器、定宽整数与帛的原语、严格正性检查与归纳规则的生成函数）；证核各条规则对计算类型论语义可靠的纸面证明；豫言类型系统的安全性；译场前端产出的实际定义；宿主实现的接口契约与一切「假」。证明项文件按输入对待：证核只认自己核过的内容，文件里照抄的归纳规则由证核重新生成后比对。

**证场。** 证场解开名字、取实际定义、把递归证明译成归纳规则、补全省略的所证、处理手写成员证明、生成证明项文件。证场的终止检查不进可信基；证场不可信，它出错只会让证核拒收。写法甲与只写签名的自动证列在证九。

## 证五：精化擦除

**按类型分类。** 证明层的每个子项要么是计算，要么是证明。类型属「辞类」的是证明，其余是计算。实现上给每个绑定标次数：零次表示只在检查时用，多次表示运行时用。证核保证零次的值只出现在零次的位置。两个例外在计算上都是平凡的：「悖」对应不可达，「代入」对应恒等。

**擦除规则。**

| 证明层 | 擦除后 |
| --- | --- |
| 命题参数：签名里的 `化（命题）`、定义里的 `得「据」`、调用里的 `于「据」` | 删去 |
| 「幽」于 A 的参数与绑定 | 删去 |
| 「择类」于 A 于 谓词 | A |
| 「必返」于 B | B |
| `「爻分」于 c 于（得「据」而 甲）于（得「反据」而 乙）` | `若 c 则 甲 否则 乙` |
| `「悖」于 证` | 不可达 |
| 「代入」「自反」与其他证明 | 整个删去 |
| `「某归纳」于 所证 于 各支 于 值`，所证是命题 | 整个删去 |
| `「某归纳」于 所证 于 各支 于 值`，所证是计算类型 | 计算规则作用于值，各支代入 |
| 依值函数类型 | 普通函数类型；类型索引按现有规则擦除 |

**擦除管什么。** 精化签名擦除后的计算部分就是实现层的签名；证明层自己的定义（引理、规约里用的函数、「幽」）留在证明文件里。可靠性由证明直接谈实际定义保证（见证六）。证场按擦除规则核对精化签名与写法甲的副本，这一步列在证九。

**擦除定理。** 证核接受 e 属于 T，则 e 擦除后的豫言程序属于 T。这条定理把证核的接受与实现层的程序连起来：证明层检验通过，擦除后的程序就是实现层运行的程序，产物里只有它。

## 证六：证明谈实际定义

**精化签名是关于实际定义的命题。** 证明文件看得见配对实现文件的实际定义。给实现层定义写的精化签名，就是命题 `「隶」于 定义 于 T`；T 是函数类型时，证核把它展开成逐个实参的形式。证明引入实际定义，用归纳规则、照实际定义展开一步、「已返」「接返」这类规则去证。对应关系就在证明里：证明谈的就是实际定义。

**「已返」与「接返」。** 「已返」于一个值，证这个值是「必返」于它的类型的成员；「接返」于项、续、前证与续证，证 `「隶」于（「续」于「项」）于（「必返」于「丙」）`，其中「续」是求值语境，前证说项正常返回，续证说语境对每个值正常返回。

**实际定义从哪来。** 证核手里的实现层定义由译场（编译器核心）前端产出，落在与编译器共用的那层核心项上，编译器也从这一层往下编。这层项的类型出自一份声明，证核与译场共用；证场只搬运原样。证场的 `取实定` 把检查后定义转成证核的核声明列；`按源文取实定` 是入口的常式，豫构（构建工具）的 `证明` 命令先对实现模块跑类型检查，再调这个入口。

**写法甲：照着实现写证明。** 证明文件里照实现层的定义写一个同名副本，在需要的地方夹上证据。这是表层写法：证场照副本的结构生成关于实际定义的成员证明，写进证明项文件，交证核核对；证核读证明项文件，副本留在证明文件里。副本与实际定义对不上时，证场报“联结不符”，指出哪一支不同。写法甲的这一生成列在证九；当前证场处理写法乙、手写成员证明与局部函数。

**写法乙：另立定理。** 命题里直接写实现层的名字，如「连结合」里写「连」；证核算到它时照实际定义展开一步。

**只写签名。** 证明文件里只写精化签名时，交证场自动找成员证明；这一步列在证九。

**手写成员证明。** 精化签名的成员证明可以手写，写在 `「定义名之隶」` 名下（如「计之隶」），命题由证核照签名推出，这里只写证明。例：

```yuyan
「计」乃凡「乙」而化（「列」于「乙」）为（「必返」于「数」）者也。
「计之隶」者设「乙」而得「输入」而
　「其计必返」于「输入」于「零」
也。
```

**局部函数怎么谈。** 实现里常用 `「复令」` 写局部函数，如「倒」里的倒置、「计」里带累加器的其计。证明文件里先写一个与它逐字相同的证明层定义（如「倒置式」「其计式」）：证核把实际定义展开一步，得到的局部函数与它换名后相同，所以关于它的引理就是关于实际局部函数的引理。这种定义照实现层的基本解释算可抛，正常返回另证（如「倒置必返」）。直接引用局部函数的写法列在证九。

**两种写法的分工。** 不变量与代码结构缠在一起的（如循环中维持的性质），用写法甲；事后陈述的性质（如往返、幂等、结合律），用写法乙。

**其他规则。**

- 证明层里多出来的定义（引理、规约里用的函数、幽灵定义）留在证明文件里。
- 骨架生成：豫构可以从实现层生成证明层骨架，抄出定义、在类型和证明处留「待证」，人或 AI 补洞。这一步列在证九。
- 实现改动后，照实际定义展开得到的项变了，关于它的证明在证核那里检查失败。

## 证七：`豫构 证明` 命令

**用法。** 在仓库根目录运行 `豫构 证明 <包> [--核对]`；`<包>` 是包短名，参数只收 `--核对`，多写时报“用法：豫构 证明 <包> [--核对]”。

**普通模式。** 命令递归配对目标包与导入图内各包的 `证明/` 下的 `。证明。豫`、`。证明接口。豫` 与实现文件，先经将作（构建服务）对导入图内各配对模块做类型检查，再经译场的文件依赖阶段取配对模块及其导入闭包的实际定义，按深度优先后序排列。随后调证场细化，写出证明项，再按次序交证核核对；先核过的报告传给证核。依赖包的证明项按已有文件核对，更新依赖包时运行该包的证明命令。

目标包模块未写手写证明、但定义了严格正类型时，命令生成只含归纳规则的证明项专卷。生成的内容与旧文件相同时保留旧文件。

**`--核对`。** 配对模块照常先做类型检查；命令只读证明项文件，重建文件头核对来源与摘要，再交证核；写文件这一步留给普通模式。证明文件改过而证明项未重新生成时，报：

```
证明项过期：库/豫章/证明/形制/次第。证明项。豫 记的是旧摘要，请运行「豫构 证明」
```

**报告与退出码。** 命令逐条印定义状态，形如：

```
首项：已证
连：已证
连结合：已证
汇总：精化签名 3，已证 3，待证 0；可信基：
```

状态有三种：`已证`、`待证`、`假`。末尾汇总精化签名数、已证数、待证数与可信基清单。全部通过返回零；有证明不成立或命令失败返回一。失败的文件印出诊断，其他文件照常核对。

**证明项文件头。** 文件头是一条豫言注释，写“证场（证明细化器）生成，不得手改”、来源包内相对路径与原文按八位同文字节算的沙二五六（SHA-256）十六进制摘要。归纳规则专卷以实现包内径标识来源，正文为空，摘要为空输入的摘要。证明项文件由证场生成；合并冲突时重跑命令重新生成，照旧入库。

证明项文件里的实现层名字是全局名，指向实现层的实际定义；文件里写全证核要核对的一切：每条精化签名化成的成员定理与它的证明、别的定理与证明项、归纳规则与「代入」的所证、命题参数的证据。评审看证明项文件里的命题；证明文件改动后摘要对不上，核对时报证明项过期，证明项文件与证明文件由此保持同步。

## 证八：报错

报错写成豫言的项，带文件、行、列与要证的命题。证核核一条定义的报错以“证明不成立”开头，后接定义名与源位，下面是“要证”“得到”与缘由；命令层面的报错是一行。几种：

```
证明不成立：「连罄」，列算。证明。豫 第 5 行第 25 列
要证：（「侔」于（「缀」于「头」于（「连」于「尾」于「罄」））于（「缀」于「头」于「尾」））
得到：「自反」
自反两边须正常算得相同；可抛项没有证「必返」
```

```
证明不成立：「谬」，坏证。证明。豫 第 3 行第 8 列
要证：「阴」
得到：「伪证」以「阴」于「零」
得到可抛的命题：没有证「必返」
```

```
细化不成：证明的递归不是结构递归：「连罄」调用「连罄」于「表」，实参不比形参小（列算。证明。豫 第 5 行第 40 列）
```

```
缺少成员证明：首项之隶
```

```
证明不成立：「列归纳」，次第。证明项。豫 第 1 行第 1 列
要证：（「列」于「物」的归纳规则）
得到：（文件里照抄的规则）
归纳规则与证核生成的不同
```

证明项文件过期、证明前类型检查失败、证明文件配不上实现文件这三类错误由命令直接报出，分别提示重新生成、先修实现模块、补上配对文件。

## 证九：后续版本

- 有状态代码：引用与可变状态、有状态接口、Hoare 类型论式的前后条件。
- 底层（无 GC）代码的证明：证场细化、证核核对 `。底层证明。豫`、`。底层证明接口。豫`（这两种后缀与对应的证明项后缀已登进源文种类表，判作证明，见《文件后缀》）。
- 立方结构与沿等价搬运。
- 并发。
- 反射判定过程：位运算与线性算术写成豫言函数，证一次可靠，由证核执行。
- 良基归纳与度量；商类型与函数外延。
- 依值组类、依值构造器字段。
- 嵌套与高阶严格正类型的归纳规则携证映射；开放递归实际定义的全性与正规形核对。
- 写法甲副本生成成员证明；只写签名的自动证；从实现层生成证明层骨架。
- 互递归、嵌套递归、局部递归证明、嵌套或省略字段的递归模式。
- 命题参数证据的自动补全。
- 步数附注随证明项文件存放。
- 步数归纳（步进索引）与可容许性检查。
- 证明文件的跨文件引用：依赖报告的载入与跨包引用已证定理。
- 证明接口与模拟适配（`。证明接口。豫` 与 `。证明项接口。豫`），以及应用接口的证明配对。
- 擦除规则的逐条落实、精化签名与写法甲副本的擦除核对、擦除定理的纸面证明。
- 证核原语与编译器原语共用一份声明，及求值结果对拍。
