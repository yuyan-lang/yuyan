# 着色语言

着色语言以豫言之常法书图形处理器之着色程序：着色之源经编译器之析文、解名、检类（佐以着色内建之声），乃译为 WGSL（网页图算着色语言），亦可译为 MSL（金属着色语言，见着九）或 PTX（统算，见着十）。WebGPU 造着色模块之时，复察其 WGSL（地址之域、一致之析等）。

诸条以“着”编号。译器在 `库/编译器核心/编译步骤/着色翻译/`，着色内建之声在「着色库」包（`库/着色库/`），命令之器为「着色器翻译」包（`应用/开发工具/着色器翻译/`，所成曰 `yy着色器`），试在「着色库测试」包（`库/着色库/测试/`）。

## 着一：文之缀

| 缀 | 所载 |
| --- | --- |
| `名。着色器。豫` | 着色之源：惟用豫言常法（`乃`、`者`、`即`、`虑…而`、`递归虑`、`若…则…否则`、`；`、`于`、`授以`、`中`、`也`、`「组值」【…】`、`「组类」【…】`） |
| `名。着色器。接口。豫` | 着色内建之声：书法同 `。接口。豫`，惟有 `立`、`即` 与无体之 `乃` 签，析文时为之补占位之义。其函由着色之的具之：译器以 WGSL、MSL 之算符与内建之函或 PTX 之令代其召，运行之时无此召 |
| `名。着色生成。豫` | 所留之缀：高级之代导着色之源，构建所得之模之虚径；盘上无此文 |

## 着二：寻模与构建之合

着色之文（前二缀）之 `寻`、`观`、`诵`，惟求 `名。着色器。豫` 与 `名。着色器。接口。豫`。皆不得则报“包内模块不存在：……（着色文件只能导入着色源「名。着色器。豫」与着色内建声明「名。着色器。接口。豫」）”，故着色之源导标准库、操作系统接口或常模皆报误。着色内建之声所须之「整数」「小数」「爻」「有」「元类型」，径取编译器之内建类名 `「《《内建类型：…》》」`。

余文（高级之代）依次求 `名。豫`、`名。接口。豫`、`名。应用接口。豫`、`名。着色器。豫`。得着色之源，则得构时由之所生之模（虚径 `名。着色生成。豫`），其所出者：

- `「着色源」`：WGSL 之文；
- `「金属源」`：MSL 之文（见着九）；MSL 译败则为一行注明其故，WGSL 照用；
- `「PTX源」`：PTX 之文（见着十）；PTX 译败亦为一行注明其故；
- 每入口项一同名之字串常量，其值为入口之函之名（WGSL 与 MSL 同）；又有“入口项名PTX名”之常量，其值为 PTX 中改为 ASCII 之入口名。

如 `寻「应用」之「加倍」之书。` 之后，`「加倍」之「着色源」` 为 WGSL 之文，`「加倍」之「加倍入口」` 为 `『加倍』`，`「加倍」之「加倍入口PTX名」` 为 `『yy_e5_8a_a0_e5_80_8d』`。高级之代导着色内建之声则报误。

所生者成于编译器之中，应用之产惟载所生之字串：

1. 虚模之依赖分析返空列（所生之模无所导），惟备空之文件依赖缓存。
2. 词法之阶召译器。译器于内析着色之源及其所导之着色模（所依先析），不书阶段缓存，故并行编译之诸工不争书一缓存之文。所生豫言之源与旧词法缓存同则不复书，后阶与导之之文仍中其缓存；着色之源或着色内建有改，所生之源随之而变。
3. 阶段之境读虚模之源（如语言服务），取于其词法缓存；缓存之效以词法缓存之改时为源之时。
4. 虚模依其着色之源断所属之包与编译之模。

## 着三：着色内建

`库/着色库/着色内建。着色器。接口。豫` 声着色之源可用之名，「着色库」包无所依。着色之源书 `寻观「着色库」之「着色内建」之书。`，其所在之包须依「着色库」。

**标量与定长之度**：标量之宽与符之有无，以类别之，宽书为整数之索引（见[依值类型](依值类型.文言.md)）。「定长小数」「定长整数」「定长无符号」各由一整数之宽构成标量之类：「浮三二」即「定长小数」于「三二」（f32），「浮十六」即「定长小数」于「一六」（f16），「整三二」即「定长整数」于「三二」（i32），「无三二」即「定长无符号」于「三二」（u32）；WGSL 所无之配（如「定长整数」于「一六」）译时报误。此皆异类，混用其宽或其符则类型之检报误。布尔用「爻」（bool）。

**字面**：整、小数之字面，其类为「整数」「小数」，经构造「新浮三二」「新浮十六」「新整三二」「新无三二」而得标量之类：「新无三二」于「二」译为 `2u`，「新浮三二」于「0.5」译为 `0.5f`，「新整三二」于「三」译为 `3i`，「新浮十六」于「1.0」译为 `f16(1.0)`；实参非字面则译为类之转，如 `u32(x)`。不经构造之字面（如「读纹素」之层级）译为 WGSL 抽象字面。

**向量与矩阵**：向量为无名之组之别名，如「二维浮」（vec2&lt;f32&gt;）、「三维无」（vec3&lt;u32&gt;）、「四维整」（vec4&lt;i32&gt;）、「二维半」（vec2&lt;f16&gt;）、「三维爻」（vec3&lt;bool&gt;）；`向量 中「零」` 即 `.x`。矩阵「二阶浮」「三阶浮」「四阶浮」为列向量之组，`矩阵 中「一」` 为第二列。

**内建入出之类**：于类型之检为向量、标量之别名；书于入口之参、入口之返值或入口所用结构之项，译器依类名加 `@builtin`。

**类之构造**：「数组」于 T 为运行之数组 `array<T>`，「定长数组」于 T 于 N 为 `array<T, N>`（N 书为整数之字面，如「定长数组」于「浮三二」于「八一九二」），「原子」于 T 为 `atomic<T>`，「纹理二维」于 T 为 `texture_2d<T>`，「采样器」为 `sampler`，「子组矩阵片甲」「子组矩阵片乙」「子组矩阵片累」为子组矩阵片（见着十二，WGSL 无之），「张量片累」为张量片（见着十三，惟金属有之）。资源「存储缓冲」「均匀缓冲」「工作组变量」惟用于顶层资源之声；存储缓冲之访问方式为「只读」或「读写」。

**资源之绑**：「绑定项」即「组类」【「组」乃「整数」也，「号」乃「整数」也，「访问」乃「访问方式」也】；「资源位」即「组类」【「组」乃「整数」也，「号」乃「整数」也】。「绑定」由绑定项得存储缓冲，「均匀绑定」「纹理绑定」「采样器绑定」由资源位得均匀缓冲、二维纹理、采样器，「工作组共享」于「元」得工作组变量。组号、绑号须为整数字面。

**函**：多态之函以 `承` 声之。下标（读数组、写数组、读共享数组、写共享数组、取元素与原子之操之序）为「无三二」，字面之下标书为「新无三二」于「零」（译为 `0u`）。

## 着四：顶层之定之分

译器读析文所得之定列（名未解，存源之名与类之别名），寻名依次察局部之名、此着色之程之顶层之名、着色内建。着色之源之顶层之定，依下规译之：

1. `即` 定带项名之组类：译为 `struct`。结构用为入口之参或返类，则内建入出之类之项加 `@builtin(…)`，余项依出现之序编 `@location(0)`、`@location(1)`……；整类之项用为顶点之出或片元之入，又加 `@interpolate(flat)`。余 `即` 之定为类之别名，惟译时展之。
2. `乃` 签之类为资源（存储缓冲、均匀缓冲、工作组变量、二维纹理、采样器）：其定须为召「绑定」等，译为 `@group(g) @binding(b) var<storage, read_write> 名: T;`（只读为 `var<storage, read>`，均匀缓冲为 `var<uniform>`，纹理与采样器为 `var`），工作组变量译为 `var<workgroup> 名: T;`。
3. `乃` 签之类为计算、顶点或片元之入口：其定须为召相应之入口项，所指之函加 `@compute @workgroup_size(n)`、`@vertex` 或 `@fragment`。入口之函之参为内建入出之类则加 `@builtin`，为结构则不加，余依序编 `@location`（片元之整类之入加 `@interpolate(flat)`）；计算入口之参惟可为内建之入或其所成之结构。顶点、片元入口之返类为内建之类则书 `-> @builtin(…) T`，为结构则书 `-> S`，余书 `-> @location(0) T`。
4. `乃` 签之类为函（化…而…）：译为 `fn`，参与返类取于签；类为「有」之参省之，返「有」之函无返类。
5. 余有签之定与无签之定译为 `const`（其值须为常量之式）。
6. `立`、裸式、多态之函（`承`）与自召之顶层之函皆报误。

所出依源之序，所导之着色之源在前；用 f16 则首加 `enable f16;`。

## 着五：函体之译

函体之值为返值。

| 豫言 | WGSL |
| --- | --- |
| `虑「甲」者 值 而 …` | `let 甲 = 值;`；值惟由字面成者用 `const`，以存抽象字面之类；单位之值不绑名 |
| `虑「甲」者「新格」于 初值 而 …` | `var 甲: T = 初值;`，T 取 `授以` 所给之类，否则取初值之类之默认具体之类 |
| `「读格」于 甲`、`「写格」于 甲 于 值` | `甲`、`甲 = 值;` |
| `甲；乙` | 依次行之，前者之值有副作用则书 `_ = 值;` |
| `若 条件 则 甲 否则 乙` | 二支皆无副作用之简式、其类为标量或向量，则译为 `select(乙, 甲, 条件)`；否则于值处以临时之 `var` 与 `if/else`，于尾处二支各自 `return` |
| `递归虑「环」其 类 者 会…而 体 而 …「环」于 初值…` | 局部尾递归：于召处展为 `loop`，参为 `var`；尾自召译为赋而 `continue`（多参经临时之量并赋），余尾之值书 `return`，或书入果变而 `break` |
| `函 于 实参…` | 用户之函译为 `f(…)`，着色内建译为算符或内建之函（见着三） |
| `值 中「零」`、`值 中「项」` | 向量取 `.x/.y/.z/.w`，矩阵取列 `[i]`，结构取项 `.项` |
| `「组值」【「项」者 值 也，…】` | 结构之造 `S(…)`：所期为结构则用之，否则依项名求已声之结构 |
| `甲 与 乙 …` | 向量或矩阵之造：所期之类给其维与元则从之，否则由诸元推之（标量得向量，同维之向量得矩阵） |
| `类 也 值` | 值以所标之类为所期而译；值为抽象字面，则以其类之构造转之 |
| 不经构造之数之字面、`「阳」`、`「阴」` | WGSL 抽象字面、`true`、`false` |

名原样书为 WGSL 之标识（WGSL 许中文之标识）；遇 WGSL 之关键字、保留字，或首为阿拉伯数字，则冠以 `豫_`。一函之中局部之名重者，依次缀 `_2`、`_3`……。

他种递归（局部递归之函不于尾处自召、顶层之函自召）、闭包与无名之函、以函为值、`鉴`、字串与模之投影（`之`）皆报误，报误附其文与顶层之定名。

## 着六：例

计算之着色：

```yuyan
  「写数组」于「数据」于「序」于（「乘」于（「读数组」于「数据」于「序」）于（「新无三二」于「二」））
也。

「加倍入口」乃「计算入口」也。
「加倍入口」者「计算入口项」于「加倍」于（「组值」【「工作组大小」者「四」也】）也。
```

```wgsl
@group(0) @binding(0) var<storage, read_write> 数据: array<u32>;

@compute @workgroup_size(4)
fn 加倍(@builtin(global_invocation_id) 号: vec3<u32>) {
  let 序 = 号.x;

}
```

## 着八：所限

- 隐式类参惟由变量或定义之引之实参与所期之类推之：实参为投影、召等复式而无所期之类，则报“函数应用的隐式参数无法完全确定”。此时先以 `虑` 绑其子式，或以 `也` 标其类；惟见于返类之类参（如「转换」）以 `授以` 给之。
- 组之字面，其最右一项为括中之组则被摊平（`甲 与（乙 与 丙）` 得三元之组），故矩阵之诸列先定为常量或绑为变量。
- WGSL 常量之求不许非数与无穷：`bitcast` 一常量之位型而得非数或无穷，建模即报误。须用非数或无穷者，借运行之值依位合成之（如 `库/张量内核/公用。着色器。豫` 之「成非数」「成正无穷」）。
- 定长之度与标量之宽须于类中书为整数之字面，译器依字面读其数；书为变量或算式则译时报误。
- 定长数组惟于工作组变量可逐元书之；局部之变与缓冲中之定长数组逐元书之，待办事项。
- 点积、长度、距离返浮三二；整向量之点积、按模取名（`之`）、诸着色模块间重名之察，皆待办事项。

## 着九：金属之的（MSL）

着色之源亦可译为 MSL（金属着色语言），以供金属运行之时编之（如经诺节之 node:ffi 召 `newLibraryWithSource`）。金属之的惟支计算之入口；顶点、片元之入口书一行注而略之（待办事项）。类型之检与着四、着五之规，二的共之；下惟列 MSL 之异书。

- 首书 `#include <metal_stdlib>` 与 `using namespace metal;`，次结构、常量、函依源之序；资源不另书。
- 类：f32、f16、i32、u32、bool 书为 `float`、`half`、`int`、`uint`、`bool`；向量书为 `float4` 等，矩阵书为 `float4x4`（列×行）；原子书为 `atomic_uint`、`atomic_int`；定长数组书为 `array<T, N>`；二维纹理书为 `texture2d<float>`，采样器书为 `sampler`。结构之项书为 `T 名;`，不带属。
- 资源：MSL 无模之资源，资源皆为函之参。存储缓冲之运行数组书为 `device T*`（只读为 `const device T*`），余存储缓冲书为 `device T&`，均匀缓冲书为 `constant T&`，纹理、采样器照书其类，工作组变量书为 `threadgroup T&`。常函以其直用或经召所用之资源依次附于原参之后，召处依次传之。
- 计算之入口书为 `kernel void`，前加 `[[max_total_threads_per_threadgroup(N)]]`（N 为工作组之大；宿主派发，每组之线宜取 N，可由计算管线之 `maxTotalThreadsPerThreadgroup` 读之）。其参依次为内建之入与所用之资源；内建之入所成之结构依项展为名“参名_项名”之参，函体之首复拼为结构。内建之入之属：全局调用号 `[[thread_position_in_grid]]`，局部调用号 `[[thread_position_in_threadgroup]]`，局部调用序 `[[thread_index_in_threadgroup]]`，工作组号 `[[threadgroup_position_in_grid]]`，工作组数 `[[threadgroups_per_grid]]`。工作组变量于函体之首声为 `threadgroup T 名;`，不为参。
- 绑之序：存储缓冲与均匀缓冲加 `[[buffer(n)]]`，纹理加 `[[texture(n)]]`，采样器加 `[[sampler(n)]]`，n＝组号×16＋绑号（三类各有其序之域）。宿主依此序置其缓冲，如组 0 号 2 置于序 2，组 1 号 0 置于序 16。金属一函至多三十一缓冲，故组号惟可用 0 与 1（未察，待办事项）。
- 句：`let` 书为 `const auto 名 = 值;`，`var 名: T = 值;` 书为 `T 名 = 值;`，`loop` 书为 `while (true)`，`_ = 值;` 书为 `(void)(值);`，`select(乙, 甲, 条件)` 书为 `(条件 ? 甲 : 乙)`，结构之造书为 `S{…}`，顶层之常量书为 `constant T 名 = 值;`。
- 字面：小数之字面加 `f`；「新浮十六」于「1.0」书为 `1.0h`，「新整三二」于「三」书为 `int(3)`，「新无三二」于「二」仍书 `2u`。
- 内建之函：多与 WGSL 同名；逆平方根为 `rsqrt`，四舍五入为 `rint`（舍入于偶，同 WGSL 之 round），浮之取余为 `fmod`，位转换为 `as_type<T>(x)`；半精之解包、打包为 `float2(as_type<half2>(x))`、`as_type<uint>(half2(v))`；工作组屏障为 `threadgroup_barrier(mem_flags::mem_threadgroup)`，存储屏障为 `threadgroup_barrier(mem_flags::mem_device)`，舍弃为 `discard_fragment()`；原子之操为 `atomic_fetch_add_explicit(&a[i], v, memory_order_relaxed)`、`atomic_fetch_max_explicit`、`atomic_fetch_min_explicit`、`atomic_load_explicit`、`atomic_store_explicit`；采样纹理、读纹素、纹理尺寸书为纹理对象之 `sample`、`read`、`get_width()` 与 `get_height()`。抽象之字面与具体之值共算，则先化为其类（如 `max(x, uint(1))`）。
- 名同 WGSL 之的（中文之标识照书）；二的共一保留字之表，故入口之函于二的同名。

所限（待办事项）：顶点与片元之入口；「数组长度」（MSL 无运行数组之长，须宿主另传）；结构与缓冲之存布与 WGSL 不尽同（如 `float3` 占十六字节）；函名与金属内建之函同者未改。

## 着十：统算之的（PTX）

着色之源亦可译为 PTX（英伟达统算之虚指令之集），由 `库/统算` 付驱动即时编之（`「载入统算模块」`），不经 C++ 与 NVRTC。统算之的惟支计算之入口；顶点、片元之入口书一行注而略之（待办事项）。类型之检与着四、着五之规，诸的共之；下惟列 PTX 之书。

- 首书 `.version 8.0`、`.target sm_80`、`.address_size 64`：算力八点零以上（安培以降）之卡皆可即时编之，于 RTX 5090 驱动编为 sm_120a。所出惟含 ASCII 之字（ptxas 遇非 ASCII 之字即报误，注中亦然）。
- 名：中文之名定而改为 ASCII。名之 UTF-8 字节中，ASCII 之字母与数原样存之，余每字节（兼下划线）书为下划线加二位十六进制，前冠以前缀。入口之 PTX 名由其于 WGSL 之函名改之、冠 yy，如『加倍』得 `yy_e5_8a_a0_e5_80_8d`；工作组变量冠 ys；寄存器惟用编号（%p 谓词、%h 十六位、%r 三十二位、%rd 六十四位）。所生之模为每入口项另出“入口项名PTX名”之常量（着二）。
- 入口：每计算入口书一 `.visible .entry`，以 `.reqntid N, 1, 1` 定每块之线为工作组之大 N，宿主发射之时块之维须恰为 (N, 1, 1)，网格之维即所派工作组之数。内建之入由特寄存器算之：全局调用号 = %ctaid × %ntid + %tid（逐维），局部调用号 = %tid，局部调用序 = tid.x + ntid.x × (tid.y + ntid.y × tid.z)，工作组号 = %ctaid，工作组数 = %nctaid；内建之入所成之结构依项各算之。
- 参：各为一 `.param .u64` 之器之指，名曰 `p_g组号_b绑号`。入口（直或经召）所用之缓皆在组零，则绑零至所用最大绑号每号各占一参（入口所不用之占位之绑亦占一位），合于宿主依绑号次第传缓之约；否则为所用之存储缓冲与均匀缓冲，依（组号，绑号）升序。均匀缓冲亦以器之指传之，宿主先书其容于一小块显存。无标量之参。入口之首以 `ld.param.u64` 取其参，复以 `cvta.to.global.u64` 化为全局之址。宿主经 `库/统算` 发射，参列依次为诸缓之「统算显存参」。
- 工作组变量于入口体中声为 `.shared .align A .b8 名[字数]`，以 `ld.shared`、`st.shared` 读写之；工作组屏障与存储屏障皆译为 `bar.sync 0`。
- 存之布依 WGSL 存储缓冲之规：f16 齐二，余标量齐四；二维向量之齐倍其元，三维、四维四之；矩阵依列向量；结构取项齐之最大；数组之步为元之大进至其齐。均匀缓冲亦依此布（WGSL 均匀缓冲另须齐于十六字，待办事项）。布尔惟于共享之存依四字存之。
- 值：每值依其分置于寄存器（向量依分，矩阵依列，结构依项之序）；格为一组可重书之寄存器，「读格」则抄之。立即之数径书于令中（f32 带小数之点）；半精之立即之数先依 f32 搬入寄存器而后转之（PTX 不收 f16 之立即之数）。
- 控之流：「若」译为条件之跳与标，于值处二支搬其值入同一组果之寄存器；局部尾递归展为带标之环，尾自召先算新实参入临时之寄存器，复搬入参之寄存器，乃跳回环首；用户之函与顶层之常量于用处内联，不另书 `.func`。
- 算：算术、位之算、移位、比（浮之不等用无序之比 neu）与逻辑之算，逐分译为 PTX 之令；f32 之除用 `div.rn`，浮之取余为 x − trunc(x/y)·y。数学之函用 PTX 之令：`sqrt.rn`、`rsqrt.approx`、`ex2.approx`、`lg2.approx`、`sin.approx`、`cos.approx`、`tanh.approx`，指数与对数换其底，幂为 ex2(y·lg2 x)，取整用 `cvt.rmi`、`cvt.rpi`、`cvt.rni`、`cvt.rzi`，饱和用 `cvt.sat`；半精之除与数学之函以 f32 算之。原子加、最大、最小用 `atom.global`，原子读、原子存用 `ld.relaxed.gpu`、`st.relaxed.gpu`。位转换于三十二位之类之间不易其位，二维半精与 u32 之间以 `mov.b32` 包之或析之。

所限（待办事项）：顶点与片元之入口；纹理与采样器；「数组长度」（须宿主另传）；反三角之函（反正弦、反余弦、反正切、反正切二）与半精之平滑阶跃；越界之访不察。

## 着十一：子组之算

子组者，同行之一组线也：网页图算谓之 subgroup，金属谓之 simdgroup，统算谓之线束（warp）。子组之算于子组之线间相易其数，不经工作组之存，亦不用屏障，宜以代工作组内对半而归之末数步。

| 豫言 | WGSL | MSL | PTX |
| --- | --- | --- | --- |
| 「子组内序号」（内建之入） | `@builtin(subgroup_invocation_id)` | `[[thread_index_in_simdgroup]]` | `%laneid` |
| 「子组大小」（内建之入） | `@builtin(subgroup_size)` | `[[threads_per_simdgroup]]` | `WARP_SZ`（三十二） |
| 子组求和、子组最大、子组最小 于 值 | `subgroupAdd`、`subgroupMax`、`subgroupMin` | `simd_sum`、`simd_max`、`simd_min` | 五步 `shfl.sync.bfly.b32`（掩码十六、八、四、二、一；成员取 `activemask`，源线不活则代以单位之元），每步后 `add`、`max`、`min` |
| 子组广播、子组洗牌 于 值 于 序 | `subgroupShuffle` | `simd_shuffle` | `shfl.sync.idx.b32` |
| 子组异或洗牌 于 值 于 掩码 | `subgroupShuffleXor` | `simd_shuffle_xor` | `shfl.sync.bfly.b32` |

其规：

- 值惟用三十二位之标量（浮三二、无三二、整三二）。统算之的遇他类则报误；WGSL 与 MSL 虽亦受向量，本库不恃之。
- 须于一致之控流召之：全子组皆行至此召，不得置于惟部分之线所入之「若」之支或环中。WGSL 以一致之析察之，违则建模报 `must only be called from uniform control flow`；统算之 `shfl.sync` 以其时活线（`activemask`）为员，归时不活之线代以单位之元（和取零，大取 −∞ 或最小之整，小取 +∞ 或最大之整），故线束不满（如工作组四十八线）则同金属，惟于活线间算之；广播与洗牌之源线不活则其果无定。译器以子组之算为有副作用之召，「若」之二支有子组之算则不译为 select。
- 广播须诸线所予之序同（其果为子组中第「序」线之值）；WGSL 之 `subgroupBroadcast` 须序为常量之式，故广播与洗牌皆译为 `subgroupShuffle`。
- 最大、最小遇非数，其果随的而定（PTX 之 `max.f32` 还非非数之一方）；欲非数相传，则以异或洗牌取值而自并之。
- 子组之大：金属与统算皆三十二；网页图算随器而定（八至百二十八），可由适配器之信之 `subgroupMinSize`、`subgroupMaxSize` 察之。恃子组之核，率设子组由连续之局部调用序而成、子组之大不小于三十二（如依三十二线一段行异或洗牌之归），器不合则宜改用不带子组之算之核。
- 网页图算：用子组之算或子组内建之入之着色源，译为 WGSL 则首加 `enable subgroups;`（并用 f16 则二者皆加）。器须有 `subgroups` 之特，且于 `requestDevice` 时求之；Chrome 一百三十四起支之，本机 Dawn 亦支之。无此特之器建模即报误，故用子组之核与不用子组之核宜置于异之着色源，由后端依器之特而择之。

所限（待办事项）：子组之投（ballot、any、all）、前缀之和与上下移之洗牌；十六位与向量之子组之算；译器不察子组之算是否处于一致之控流。

## 着十二：子组矩阵片

预填之试内建「载入矩阵片累」自单精共享列载十六乘十六累片，起、步以单精元计；「载矩阵片乙自转置存储」自半精位型设备缓载乙之转置布，乙[n][k] = 缓冲[起+k×步+n]，起、步以半精元计。二者全域在界、起与步为八之倍、全子组一致召之。今惟支Metal。

深学推理少行之口「载入矩阵片累前八行」惟自单精共享列载前八乘十六元，还十六乘十六累片，下八行置零。起与行步以单精元计，皆八倍，惟所读八行须在界；全子组一致召之，今惟Metal。惟用此口乃生辅源。

深度学习缓存直读之试「载矩阵片甲自存储」「载矩阵片乙自存储」自无三二存储缓读半精十六乘十六片，每字二元，低半字在先；起、步以半精元计，皆为八之倍，全片在界，乙以转置之布载之。少行之试「载矩阵片甲前八行」惟自半精共享列载前八乘十六元，后八行置零；「存矩阵片累前八行」惟向单精共享列书前八乘十六元，余元保旧值。少行之召惟须八行在界。诸召皆须全子组一致行之，今惟支金属，余的译则报误。

「存矩阵片累到存储」受读写单精存储缓冲、无三二起、无三二步、子组矩阵片累，而返单位值。书之布局为缓冲[起+行×步+列]，行列各零至十五；起、步须为八之倍，召者察全域之界。全子组须于一致控流召之。Metal以设备指针召`simdgroup_store`，PTX以`st.global.v2.f32`书之，WGSL译则报误。

子组矩阵片者，全子组共持之十六 × 十六之阵块，以用器之阵乘加之单元：于金属译为 simdgroup_matrix，于统算译为 `ldmatrix` 与 `mma.sync`。诸线各持何元由的定之，着色之源不得见，惟可全块载之、乘加之、存回之。

| 豫言 | 义 | MSL | PTX |
| --- | --- | --- | --- |
| 「子组矩阵片甲」「子组矩阵片乙」 | 半精之十六 × 十六之块 | 结构，含四 `simdgroup_half8x8` | 四三十二位之寄存器（每一含二半精） |
| 「子组矩阵片累」 | 单精之十六 × 十六累加之块 | 结构，含四 `simdgroup_float8x8` | 八三十二位之寄存器 |
| 载入矩阵片甲 于 数组 于 起 于 步 | 片[行][列] = 数组[起 + 行 × 步 + 列] | 四 `simdgroup_load` | `ldmatrix.sync.aligned.m8n8.x4.shared.b16` |
| 载入矩阵片乙 于 数组 于 起 于 步 | 同上（乙依 [n][k] 存） | 四转置之 `simdgroup_load`（所存为乙ᵀ） | 同上，诸线所予行址不同 |
| 零矩阵片累 于 元 | 全零之累加之块 | `make_filled_simdgroup_matrix` | 八 `mov.b32 …, 0` |
| 矩阵片乘加 于 累 于 甲 于 乙 | 累[m][n] + Σₖ 甲[m][k] × 乙[n][k]（加 甲 · 乙ᵀ） | 八 `simdgroup_multiply_accumulate` | 二 `mma.sync.aligned.m16n8k16.row.col.f32.f16.f16.f32` |
| 存矩阵片累 于 数组 于 起 于 步 于 累 | 数组[起 + 行 × 步 + 列] = 累[行][列] | 四 `simdgroup_store` | 四 `st.shared.v2.f32` |

其规：

- 所载之列须为半精（「浮十六」）之工作组之列，所存之列须为单精（「浮三二」）之工作组之列；「起」与「步」依元计，须为八之倍（PTX 之 `ldmatrix` 须每行之址齐于十六字节，译器声诸工作组之列皆齐于十六字节）。
- 须于一致之控流由全子组共召之；译器以此诸召皆为有副作用之召，不察其一致。
- 金属：用子组矩阵片之源首加一段结构与内联之函（「金属矩阵片序幕」）。乙片载时转之，故乘加径得 甲 · 乙ᵀ；半精乘、单精累。
- 统算：甲片为 `mma` 之 A（行主序），乙片之前二与后二寄存器各为二 n8 块之 B（`.col`，即依 [n][k] 存），累片之前四与后四寄存器各为二 n8 块之 C 与 D；须 sm_80（PTX 之的为 `.target sm_80`）。
- 网页图算：WGSL 无子组矩阵片，译则报误。高级之代导此着色源，则「着色源」为一行注明其故，入口之表取于 MSL；用子组矩阵片之核宜置于别之着色源，由后端依的而择之。
- 精度：甲、乙为半精（有效之位十一，最大 65504），累加为单精；单精之数入片之前，召者须自转为半精，逾其界则为无穷。

所限（待办事项）：惟十六 × 十六 × 十六一形与半精乘单精累一类；片不可径自存储缓冲载之或存回存储缓冲；不可取片中单元。

## 着十三：张量片（Metal 4 之张量之算）

张量片者，全工作组（恰百二十八线、四子组）共持之六十四 × 六十四单精之累块，以 Metal 4 之张量之算（Metal Performance Primitives 之 `matmul2d`）算之，于 M5、A19 以后之 GPU 由神经加速器行之。诸线各持何元由的定之，着色之源不得见。惟金属支之；网页图算与统算译则报误。器支之否由宿主判之（金属张量之器依 MTLGPUFamilyApple10 询之），着色之源自不验。

| 内建 | 义 |
|---|---|
| 「张量片累」 | 类：六十四 × 六十四单精之累块 |
| 「零张量片累」于「元」 | 全零之累块 |
| 「张量片乘加」于 累 于 甲 于 甲起 于 甲步 于 甲行数 于 乙 于 乙起 于 乙步 | 得 累[m][n] + Σₖ 甲[甲起 + m × 甲步 + k] × 乙[乙起 + n × 乙步 + k]（m、n 取零至六十三，k 取零至三十一）；甲为单精之存储缓冲，m 不小于甲行数之行视为零；乙为半精之工作组之列（六十四行在界） |
| 「存张量片累」于 出 于 起 于 步 于 行数 于 列数 于 累 | 出[起 + m × 步 + n] = 累[m][n]，惟书 m < 行数、n < 列数者；出为可读写之单精存储缓冲 |

此诸召皆须于一致之控流由全工作组共行之。MSL 之译：用张量片之源首加 `#include <metal_tensor>` 与 `#include <MetalPerformancePrimitives/MetalPerformancePrimitives.h>`，`matmul2d_descriptor(64, 64, 32, false, true, true, multiply_accumulate)` 配 `execution_simdgroups<4>`；累块为其的协作张量（`yy_张量片累`），甲依 `tensor<device float, dextents<int32_t, 2>, tensor_inline>` 带步而裹之（行数为外层之长），乙依线组半精张量裹之，存回依（列数，行数）截之。累块可置于「新格」，于环中「读格」「写格」。
