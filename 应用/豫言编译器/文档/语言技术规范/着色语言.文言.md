# 着色语言

着色语言以豫言之常法书图形处理器之着色程序：着色之源经编译器之析文、解名、检类（佐以着色内建之声），乃译为 WGSL。WebGPU 造着色模块之时，复察其 WGSL（符之有无、地址之域、一致之析等）。

诸条以“着”编号。译器在 `库/编译器核心/编译步骤/着色翻译/`，着色内建之声在「着色库」包（`库/着色库/`），命令之器为「着色器翻译」包（`应用/开发工具/着色器翻译/`，所成曰 `yy着色器`），试在「着色库测试」包（`库/着色库/测试/`）。

## 着一：文之缀

| 缀 | 所载 |
| --- | --- |
| `名。着色器。豫` | 着色之源：惟用豫言常法（`乃`、`者`、`即`、`虑…而`、`递归虑`、`若…则…否则`、`；`、`于`、`授以`、`中`、`也`、`「组值」【…】`、`「组类」【…】`） |
| `名。着色器。接口。豫` | 着色内建之声：书法同 `。接口。豫`，惟有 `立`、`即` 与无体之 `乃` 签，析文时为之补占位之义。其函由着色之的具之：译器以 WGSL 之算符、内建之函代其召，运行之时无此召 |
| `名。着色生成。豫` | 所留之缀：高级之代导着色之源，构建所得之模之虚径；盘上无此文 |

## 着二：寻模与构建之合

着色之文（前二缀）之 `寻`、`观`、`诵`，惟求 `名。着色器。豫` 与 `名。着色器。接口。豫`。皆不得则报“包内模块不存在：……（着色文件只能导入着色源「名。着色器。豫」与着色内建声明「名。着色器。接口。豫」）”，故着色之源导标准库、操作系统接口或常模皆报误。着色内建之声所须之「整数」「小数」「爻」「有」「元类型」，径取编译器之内建类名 `「《《内建类型：…》》」`。

余文（高级之代）依次求 `名。豫`、`名。接口。豫`、`名。应用接口。豫`、`名。着色器。豫`。得着色之源，则得构时由之所生之模（虚径 `名。着色生成。豫`），其所出者：

- `「着色源」`：WGSL 之文；
- 每入口项一同名之字串常量，其值为入口之函之 WGSL 名。

如 `寻「应用」之「加倍」之书。` 之后，`「加倍」之「着色源」` 为 WGSL 之文，`「加倍」之「加倍入口」` 为 `『加倍』`。高级之代导着色内建之声则报误。

所生者成于编译器之中，应用之产惟载所生之字串：

1. 虚模之依赖分析返空列（所生之模无所导），惟备空之文件依赖缓存。
2. 词法之阶召译器。译器于内析着色之源及其所导之着色模（所依先析），不书阶段缓存，故并行编译之诸工不争书一缓存之文。所生豫言之源与旧词法缓存同则不复书，后阶与导之之文仍中其缓存；着色之源或着色内建有改，所生之源随之而变。
3. 阶段之境读虚模之源（如语言服务），取于其词法缓存；缓存之效以词法缓存之改时为源之时。
4. 虚模依其着色之源断所属之包与编译之模。

## 着三：着色内建

`库/着色库/着色内建。着色器。接口。豫` 声着色之源可用之名，「着色库」包无所依。着色之源书 `寻观「着色库」之「着色内建」之书。`，其所在之包须依「着色库」。

**标量**：「浮三二」「浮十六」即「小数」，「无三二」「整三二」即「整数」，布尔用「爻」；WGSL 之类依次为 f32、f16、u32、i32、bool。皆透明之别名，符之有无由 WGSL 编译器察之。

**向量与矩阵**：向量为无名之组之别名，如「二维浮」（vec2&lt;f32&gt;）、「三维无」（vec3&lt;u32&gt;）、「四维整」（vec4&lt;i32&gt;）、「二维半」（vec2&lt;f16&gt;）、「三维爻」（vec3&lt;bool&gt;）；`向量 中「零」` 即 `.x`。矩阵「二阶浮」「三阶浮」「四阶浮」为列向量之组，`矩阵 中「一」` 为第二列。

**内建入出之类**：于类型之检为向量、标量之别名；书于入口之参、入口之返值或入口所用结构之项，译器依类名加 `@builtin`。

| 类 | 别名 | WGSL |
| --- | --- | --- |
| 「全局调用号」 | 三维无 | `@builtin(global_invocation_id)` |
| 「局部调用号」 | 三维无 | `@builtin(local_invocation_id)` |
| 「局部调用序」 | 无三二 | `@builtin(local_invocation_index)` |
| 「工作组号」 | 三维无 | `@builtin(workgroup_id)` |
| 「工作组数」 | 三维无 | `@builtin(num_workgroups)` |
| 「顶点序号」 | 无三二 | `@builtin(vertex_index)` |
| 「实例序号」 | 无三二 | `@builtin(instance_index)` |
| 「裁剪位置」 | 四维浮 | `@builtin(position)`（顶点之出） |
| 「片元坐标」 | 四维浮 | `@builtin(position)`（片元之入） |
| 「正面朝向」 | 爻 | `@builtin(front_facing)` |
| 「片元深度」 | 浮三二 | `@builtin(frag_depth)` |
| 「采样序号」 | 无三二 | `@builtin(sample_index)` |
| 「采样掩码」 | 无三二 | `@builtin(sample_mask)` |

「片元颜色」即「四维浮」，依位次编号而出。

**类之构造**：「数组」于 T 为运行之数组 `array<T>`，「原子」于 T 为 `atomic<T>`，「纹理二维」于 T 为 `texture_2d<T>`，「采样器」为 `sampler`。资源「存储缓冲」「均匀缓冲」「工作组变量」惟用于顶层资源之声；存储缓冲之访问方式为「只读」或「读写」。

**资源之绑**：「绑定项」即「组类」【「组」乃「整数」也，「号」乃「整数」也，「访问」乃「访问方式」也】；「资源位」即「组类」【「组」乃「整数」也，「号」乃「整数」也】。「绑定」由绑定项得存储缓冲，「均匀绑定」「纹理绑定」「采样器绑定」由资源位得均匀缓冲、二维纹理、采样器，「工作组共享」于「元」得工作组变量。组号、绑号须为整数字面。

**入口**：「计算入口」「顶点入口」「片元入口」为入口项之类；「计算选项」即「组类」【「工作组大小」乃「整数」也】。`「计算入口项」乃承「甲」而化（化「甲」而「有」）而化「计算选项」而「计算入口」也。`；顶点、片元之入口项取一函，其入出之类随所指之函。

**函**：多态之函以 `承` 声之。

| --- | --- |

## 着四：顶层之定之分

译器读析文所得之定列（名未解，存源之名与类之别名），寻名依次察局部之名、此着色之程之顶层之名、着色内建。着色之源之顶层之定，依下规译之：

1. `即` 定带项名之组类：译为 `struct`。结构用为入口之参或返类，则内建入出之类之项加 `@builtin(…)`，余项依出现之序编 `@location(0)`、`@location(1)`……；整类之项用为顶点之出或片元之入，又加 `@interpolate(flat)`。余 `即` 之定为类之别名，惟译时展之。
2. `乃` 签之类为资源（存储缓冲、均匀缓冲、工作组变量、二维纹理、采样器）：其定须为召「绑定」等，译为 `@group(g) @binding(b) var<storage, read_write> 名: T;`（只读为 `var<storage, read>`，均匀缓冲为 `var<uniform>`，纹理与采样器为 `var`），工作组变量译为 `var<workgroup> 名: T;`。
3. `乃` 签之类为计算、顶点或片元之入口：其定须为召相应之入口项，所指之函加 `@compute @workgroup_size(n)`、`@vertex` 或 `@fragment`。入口之函之参为内建入出之类则加 `@builtin`，为结构则不加，余依序编 `@location`（片元之整类之入加 `@interpolate(flat)`）；计算入口之参惟可为内建之入或其所成之结构。顶点、片元入口之返类为内建之类则书 `-> @builtin(…) T`，为结构则书 `-> S`，余书 `-> @location(0) T`。
4. `乃` 签之类为函（化…而…）：译为 `fn`，参与返类取于签；类为「有」之参省之，返「有」之函无返类。
5. 余有签之定与无签之定译为 `const`（其值须为常量之式）。
6. `立`、裸式、多态之函（`承`）与自召之顶层之函皆报误。

所出依源之序，所导之着色之源在前；用 f16 则首加 `enable f16;`。

## 着五：函体之译

函体之值为返值。

| 豫言 | WGSL |
| --- | --- |
| `虑「甲」者 值 而 …` | `let 甲 = 值;`；值惟由字面成者用 `const`，以存抽象字面之类；单位之值不绑名 |
| `虑「甲」者「新格」于 初值 而 …` | `var 甲: T = 初值;`，T 取 `授以` 所给之类，否则取初值之类之默认具体之类 |
| `「读格」于 甲`、`「写格」于 甲 于 值` | `甲`、`甲 = 值;` |
| `甲；乙` | 依次行之，前者之值有副作用则书 `_ = 值;` |
| `若 条件 则 甲 否则 乙` | 二支皆无副作用之简式、其类为标量或向量，则译为 `select(乙, 甲, 条件)`；否则于值处以临时之 `var` 与 `if/else`，于尾处二支各自 `return` |
| `递归虑「环」其 类 者 会…而 体 而 …「环」于 初值…` | 局部尾递归：于召处展为 `loop`，参为 `var`；尾自召译为赋而 `continue`（多参经临时之量并赋），余尾之值书 `return`，或书入果变而 `break` |
| `函 于 实参…` | 用户之函译为 `f(…)`，着色内建译为算符或内建之函（见着三） |
| `值 中「零」`、`值 中「项」` | 向量取 `.x/.y/.z/.w`，矩阵取列 `[i]`，结构取项 `.项` |
| `「组值」【「项」者 值 也，…】` | 结构之造 `S(…)`：所期为结构则用之，否则依项名求已声之结构 |
| `甲 与 乙 …` | 向量或矩阵之造：所期之类给其维与元则从之，否则由诸元推之（标量得向量，同维之向量得矩阵） |
| `类 也 值` | 值以所标之类为所期而译；值为抽象字面，则以其类之构造转之 |
| 数之字面、`「阳」`、`「阴」` | WGSL 抽象字面、`true`、`false` |

名原样书为 WGSL 之标识（WGSL 许中文之标识）；遇 WGSL 之关键字、保留字，或首为阿拉伯数字，则冠以 `豫_`。一函之中局部之名重者，依次缀 `_2`、`_3`……。

他种递归（局部递归之函不于尾处自召、顶层之函自召）、闭包与无名之函、以函为值、`鉴`、字串与模之投影（`之`）皆报误，报误附其文与顶层之定名。

## 着六：例

计算之着色：

```yuyan
寻观「着色库」之「着色内建」之书。

「数据」乃「存储缓冲」于（「数组」于「无三二」）也。
「数据」者「绑定」于（「组值」【「组」者「零」也，「号」者「零」也，「访问」者「读写」也】）也。

「加倍」乃化「全局调用号」而「有」也。
「加倍」者会「号」而
  虑「序」者「号」中「零」而
  「写数组」于「数据」于「序」于（「乘」于（「读数组」于「数据」于「序」）于「二」）
也。

「加倍入口」乃「计算入口」也。
「加倍入口」者「计算入口项」于「加倍」于（「组值」【「工作组大小」者「四」也】）也。
```

译为：

```wgsl
@group(0) @binding(0) var<storage, read_write> 数据: array<u32>;

@compute @workgroup_size(4)
fn 加倍(@builtin(global_invocation_id) 号: vec3<u32>) {
  let 序 = 号.x;
  数据[序] = 数据[序] * 2;
}
```

他例（顶点与片元、局部尾递归、格、二种「若」、均匀缓冲、纹理、原子）及所期之 WGSL，见 `库/着色库/测试/样例/`。

## 着八：所限

- 隐式类参惟由变量或定义之引之实参与所期之类推之：实参为投影、召等复式而无所期之类，则报“函数应用的隐式参数无法完全确定”。此时先以 `虑` 绑其子式，或以 `也` 标其类；惟见于返类之类参（如「转换」）以 `授以` 给之。
- 组之字面，其最右一项为括中之组则被摊平（`甲 与（乙 与 丙）` 得三元之组），故矩阵之诸列先定为常量或绑为变量。
- 点积、长度、距离返浮三二；整向量之点积、定长之数组、按模取名（`之`）、诸着色模块间重名之察，皆待办事项。
