# 网站资料生成

整理官方网站需要的教程与资料，并生成整个官网静态站（取代原先的 Jekyll）。语料放在 `应用/书院/门庭/内容/`，页面稿、资料、共用资源、产品、性能、条款与 Cloudflare 的响应头、转址都在那里。

## 功能

程序在仓库根目录运行，分三步：

1. `入口。豫` 从语言仓文档生成带前言的 Markdown 页面：教程写到 `dist/网站稿/教程/`，指南写到 `dist/网站稿/指南/`，十七篇技术规范写到 `dist/网站稿/文档/`。页面网址是中文的目录式干净网址：教程章 `/教程/<名>/`、指南 `/指南/<名>/`、技术规范 `/文档/<名>/`，文言页在 `/文言/` 前缀下；正文里的章节链接与仓内文档链接同时改成新网址。技术规范页的提要由库「提要」取自该篇源文，写进页面前言的 `description`，与编简同出一源。中间稿只落在 `dist/网站稿/`，源码树不写。技术文档页的文稿快照取 `dist/语言来源.txt`，由仓库目标「官网」在运行前写好。
2. `整站。豫` 先把 `内容/` 抄进 `dist/网站稿/`（`响应头`、`转址` 写成 `_headers`、`_redirects`，`资料/` 与 `条款/` 不抄），把条款四个 HTML 按新网址抄进稿根（`/条款/条款/`、`/条款/隐私/` 与它们的文言页），再把教程各章的示例程序抄成 `/教程/示例/`，给稿根里带 `<!-- 附表：路径 -->` 标记的页面补上所指文档的表格部分（库「附表」；译名页的翻译列表由此取自《翻译列表》），然后用静态站库（语言仓 `库/刊刻`，Markdown 由 `库/圈点` 转换）读取稿根，写出 `dist/网站`：带前言的页面按 `layout` 套用 `布局。豫` 中的布局（`default`、`技术文档`），其余文件原样复制；另写技术文档搜索索引 `文档/搜索.json`、`sitemap.xml` 与 `robots.txt`。写完后先补一遍没有文言稿的页（复制成 `/文言/<路径>/index.html`，改 `lang` 与对页属性），再生成全部页面、补汉语页的对页属性、补第二遍文言页（全部页面与目录页的文言版），把补出的地址追加进 `sitemap.xml`；然后把文言页里的站内链接改成文言对页，最后把旧网址的 301 规则追加到 `_redirects`（路径按平台要求做百分号编码，无连跳）。首页没有文言稿，`/文言/` 由这一步补出。
3. `全部页面。豫` 在整站写完后扫描 `dist/网站` 的全部网页（说明取第一个 h1，没有时取 title），并入包管理、控制台（`/cloud/` 下的全部固定页面：控制台、本机算力、GitHub 同步与账户级服务；项目与任务由控制台的项目列表列全）、试写间、账户等动态入口，按目录写出 `/全部页面/`：每层先列目录、再列页面。扫描到的目录没有首页时生成只列该目录的首页（如 `/指南/`、`/条款/`），使网址栏的上级目录链接都能打开；这些目录与 `/全部页面/` 的目录规则追加到 `dist/网站/_redirects`（平台不自动找 index.html）。

## 社区包页

社区包仓库（`yuyan-lang/yuyan-community-packages`）的 CI 在跑「文档站」之前设两个环境变量：`豫言社区包目录` 是社区仓 `包/` 目录的绝对路径，在语言仓目录树之外；`豫言社区包提交` 是社区仓的提交号。程序在整站写出稿根之后、套版之前读这两个变量，往稿根写包页：

- `/包/`：全部包，按所有者分组，所有者与包名都按字序；页首写一句共多少个所有者、多少个包。
- `/包/<所有者>/`：这位所有者的全部包。
- `/包/<所有者>/<包名>/`：包页，列出名称、所有者、版本、种类（可执行文件在括号里注界面）、许可、依赖与源码，下面是简介与渲染后的 `包说明.汉语.md`；名称、版本、种类、许可与一句简介取包描述，一句简介优先取名帖的提要，没有就取简介第一句。

三种页各出汉语与文言两份（文言页在 `/文言/包/…`，用简介的文言稿与 `包说明.文言.md`）。包描述与名帖用籍册（数据文件库）读，不手写解析；名帖有显示名就在列表里与名称并列。`依赖` 里在社区包目录中有包页的链到它的包页，没有的只写名字。包页的源码链接指向社区仓这个包的目录 `https://github.com/yuyan-lang/yuyan-community-packages/tree/<社区仓提交>/包/<所有者>/<包目录>`；包说明里的相对链接改指同一处的 GitHub 源码（文件用 `blob`，目录用 `tree`）。

没设 `豫言社区包目录`（本机出主站、云仓出主站）时一页不出，其余照旧。社区仓的 `包/` 放在语言仓目录树之外：语言仓找包时会连 `dist/` 底下一起扫，社区仓里的包与语言仓自己的同名包会撞名。

站点数据：技术规范的章节目录由库「页录」出（`内容/资料/页录。数据。豫` 一份声明，侧栏、翻页、总览卡片与站点导航共用），各篇的标题、网址与分组都从它来；`内容/资料/问答.json` 是“十万个为什么”的问答，正文由 `问答。豫` 生成。技术文档总览中的 `<div class="技术篇目"></div>` 在生成时换成章节卡片，卡片的标题、网址取自篇目，一句提要取自各篇稿件的提要（库「提要」）。站内链接一律写中文网址，不做百分号编码；文言页的站内链接指文言对页。

后续版本：`资料/` 余下的 `问答.json` 改成数据子语言 `名。数据。豫`（提案 00028）；技术文档.yml 已并进页录。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为可执行文件类型，不可被其他包依赖；包内模块仍可互相引用。类型典中的入口和文件名见包配置，程序产物为 `网站资料生成`。

## 使用

在仓库根目录运行仓库目标「官网」，它用正在运行的豫构编出本程序并运行：

```sh
./豫构。<系>。豫行 目标 官网
```

也可以单独检查、构建本包（`./豫构 检查 网站资料生成`、`./豫构 构建 网站资料生成`）。依赖、原生源文件及说明路径以 [包配置](网站资料生成。包。豫) 为准。构建不会自动运行程序；运行前先备好 `dist/语言来源.txt`，或者在仓库根目录用仓库目标「官网」。
