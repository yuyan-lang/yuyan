# 官网

通称官网，指 `yuyan-lang.org`（主站）与 `docs.yuyan-lang.org`（docs 站）共用的页面。云仓提案 C00005《静态站与动态站分离》实施中：同一份页面源在构建时出两种呈现——主站的页面由浏览器里的豫言系统排版绘制，docs 站的页面是构建时写好的 HTML 与 CSS。

这是 `应用/书院/门庭/` 的父包，只有包描述与本说明，不含模块。它登记网站资料生成、网站产物守卫、共用界面应用、首页应用、产品应用、问答应用、技术文档应用、编简、附表、提要、页录与问答页；新增程序时，须在本包「包含包」登记，并在新包写「包含在」。

## 目录

| 路径 | 内容 |
| --- | --- |
| `内容/` | 网站内容：页面稿 `*.汉语.md` 与 `*.文言.md`、`资料/`、`共用/`、`资源/`、`产品/`、`性能/`、`条款/`、`响应头`、`转址` |
| `生成/` | 包「网站资料生成」：读页面稿与语言仓的教程、指南、技术文档，写出 `dist/网站` |
| `守卫/` | 包「网站产物守卫」：核对问答数据、静态正文、站内链接与技术文档索引 |
| `共用界面/` | 包「共用界面应用」：全站导航、网址栏、页脚与双语文字；连同它的 `静态渲染。脚本。豫` 与收尾的 `静态收尾。脚本。豫` |
| `首页/`、`产品/`、`问答/`、`技术文档/` | 包「首页应用」「产品应用」「问答应用」「技术文档应用」：四个页面应用及其静态渲染脚本 |
| `编简/` | 包「编简」：把页面稿读成匠心的文档，把整站写成文档站并跑守卫 |
| `附表/` | 包「附表」：把页面稿里的附表标记换成所指文档的表格部分，使译名页的表格只有《翻译列表》一个来源 |
| `提要/` | 包「提要」：一页的一句话提要取自该页源文（前言的 `description` 或源文首行的提要标记），供网站资料生成与编简共用 |
| `页录/` | 包「页录」：页面集合、题、址、对页与正文来源的一处声明，官网与编简共读 |
| `问答页/` | 包「问答页」：“十万个为什么”的正文生成，官网与编简共用同一函数，按语出可见文字 |

页面稿可以写一行 `<!-- 附表：路径 -->`，路径相对仓库根；网站资料生成与编简读入页面时把它换成该文档的表格部分（自第一个以 `### ` 起首的行到末尾）。译名页的翻译列表就是这样取自语言仓的《翻译列表》，改名与增删只改那一份。

页面稿与规范篇的提要写在源文里：介绍页写前言里的 `description:`，技术规范写源文里的一行 `<!-- 提要：… -->`。网站资料生成与编简都从这一份取提要，页面目录与技术文档目录不再另抄一份。

`内容/` 是网站内容，包发现只认本目录下的包目录。页面稿的文件名、`资料/` 里的 `问答.json` 与 `页录。数据。豫`、Cloudflare 的 `响应头` 与 `转址` 都按中文命名；网站资料生成把 `响应头`、`转址` 写成产物里的 `_headers`、`_redirects`（Cloudflare 要的文件名）。网址一律用中文的目录式干净网址，不做百分号编码：页面是 `<路径>/index.html`，汉语页在 `/教程/启机第一/` 这样的路径下，文言页一律在 `/文言/` 前缀下（`/文言/教程/启机第一/`）；没有文言稿的页面由生成程序补一份 `/文言/<路径>/`。产品页网址是 `/产品/`。

## 两种产物

- `dist/网站`：主站与 docs 站共用的页面，由仓库目标「官网」写出。
- `dist/文档站`：docs 站的 HTML 与 CSS，由仓库目标「文档站」在 `dist/网站` 上依次跑共用界面、首页、技术文档、产品四个静态渲染脚本写出（编页面应用时门庭目录也是包根，页面应用可以依赖页录等门庭子包），再由 `静态收尾。脚本。豫` 给每页顶上挂横幅、清掉除横幅那一条以外的全部去主站链接并核对产物，不带脚本与网页汇编文件。

docs 站的规矩是“只此一条去主站”：每个网页顶上那条横幅说明这是豫言静态站、请去动态站获得更佳体验，横幅里的链接指主站上的同一页；此外站头、导航、页脚、全部页面与正文里都不留指向主站的链接（指向主站动态页的条目去掉，正文句子只留文字）。这条规矩由 `静态收尾。脚本。豫` 落实，并作为「文档站」目标末尾的核对：不合就让目标失败。

## 社区包页

docs 站另有社区包页：社区包仓库的 CI 在跑「文档站」之前设环境变量 `豫言社区包目录`（社区仓 `包/` 的绝对路径，在语言仓目录树之外）与 `豫言社区包提交`，网站资料生成据此往稿根写 `/包/`、`/包/<所有者>/`、`/包/<所有者>/<包名>/` 三级页，各出汉语与文言两份（文言页在 `/文言/包/…`）。包描述与名帖由该程序用籍册（数据文件库）读，包说明里的相对链接改指社区仓同一处的 GitHub 源码；`/全部页面/` 与 `sitemap.xml` 随之收录这些页。

`静态收尾。脚本。豫` 在有包页时把站头与站点导航里的「包管理」从 `/packages/` 改成站内链接（文言页指 `/文言/包/`），并把旧的 `/packages/` 网址 301 到 `/包/`（各级用 `:splat`）。它还把 docs 站的 `_redirects` 整份重排：去掉 200 改写规则（Pages 会自己给目录取 `index.html`、给不带斜线的目录补斜线），不带 `*` 也不带 `:名` 的静态规则排在前面、带 `*` 或 `:名` 的动态规则挪到最末；核对时动态规则不过一百条、静态规则不过两千条。主站那份 `dist/网站/_redirects` 不动，Worker 要那些 200 规则。
