# 提要

一页的一句话提要取自页面源文本身。介绍页写在前言的 `description` 里，技术规范篇写在源文首行的摘要标记里，网站资料生成与编简都从这里取同一份。

提要（page summary）把页面的简介与页面的源文连在一处：读一页的提要，就是读这份源文——有 YAML 前言（front matter）的页取前言里的 `description`，没有前言的页取源文里的一行 `<!-- 提要：… -->`。提要改了源文即变，各处生成的页面随之而变，不必再抄第二份。

## 包身份

所有者：豫言。包版本：0.1.0。本包为库类型，依赖标准库与章程（前言解析）。

## 用法

```yuyan
寻观「提要」之书。

「页之提要」于『应用/书院/门庭/内容/译名.汉语.md』
```

路径按仓库根解析，调用程序在仓库根运行。默认导入（`提要` 模块）提供：

- `「页之提要」`：读仓库根下的一页源文，取它的提要。
- `「文之提要」`：由一份源文的全文取提要，供已经读进内存的调用方使用。
- `「前言述」`：源文 YAML 前言里的 `description`，没有前言或没有这一栏时得空串。
- `「标记提要」`：源文里第一条提要标记中的一段，包在「可有」里；没有标记时得「可无」。
- `「提要标首」`、`「提要标尾」`：提要标记的开头与结尾，写作 `<!-- 提要：` 与 ` -->`。

## 提要的来源

两处只选一处，先前言后标记：

1. YAML 前言里的 `description:`，介绍页的写法，与站点页面的 description 同出一源；
2. 源文里的一行 `<!-- 提要：… -->`，技术规范篇的写法，标记在渲染时不可见。

## 报错

两种情形报错，免得提要悄悄空掉：

- 提要标记没有结尾 ` -->`；
- 两处都没有提要。

## 调用处

页面稿都在 `应用/书院/门庭/内容/`，技术规范在 `应用/豫言编译器/文档/语言技术规范/`。网站资料生成在写技术文档页时取提要，写进页面前言的 `description`，总览卡片也从这里取；编简在出站时逐页取提要，作为该页网页的 description。两处的写法见各自的包说明。
