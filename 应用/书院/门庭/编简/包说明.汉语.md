# 编简

把页录里登记的介绍页、数据页与技术文档页读成匠心的文档，供两站共用。

## 包身份

所有者：豫言。包版本：0.1.0。本包为可执行文件类型，不可被其他包依赖；包内模块仍可互相引用。程序产物为 `编简`。

## 用法

在仓库根目录构建并运行：

```sh
./豫构。林檎。豫行 构建 编简 --输出 编简。林檎。豫行 -j 12
./编简。林檎。豫行 列出
./编简。林檎。豫行 全部
./编简。林檎。豫行 出站 /tmp/编简站
./编简。林檎。豫行 渲染 /译名/ 1200 1 /tmp/译名.png
./编简。林檎。豫行 切片 /译名/ 1200 1200 /tmp/译名片
```

- `列出`：打印全部页面的路径与标题。
- `全部`：把每页编成文档并打印顶层块数，核对没有异常。
- `出站 目录`：把全部页面写成 docs 整站（清空目标目录），跑整站守卫，打印文件数与字节数。
- `渲染 路径 宽 倍 输出`：按宽度排成连续版面，画成宽乘倍、高乘倍的 PNG。
- `切片 路径 宽 片高 前缀`：同一版面纵向切片，每片画成宽乘片高的 PNG，文件名是前缀接一、二、三。

页面集合在 [页录](../内容/资料/页录。数据。豫) 里登记一处，标题、地址、对页地址与正文来源由库「页录」取自页面源文：介绍页与数据页取前言里的 `title`、`permalink` 与 `han_page`、`wen_page`，技术文档取篇首的 `# 标题`，地址由章名推出（写有 `permalink` 的就以它为准）。正文来源为原稿的页读源文的标记文；正文来源为问答的页（现为「十万个为什么」）调库「问答页」的 `「问答正文」`，与官网同一个生成函数，按页的语只出那一语的可见文字。介绍页的 markdown 稿取 `应用/书院/门庭/内容/`（与网站生成共用一份），技术文档取语言仓 `应用/豫言编译器/文档/语言技术规范/` 的原文。每页的提要由库「提要」取自该页源文本身：介绍页取前言里的 `description`，技术文档取源文里的一行 `<!-- 提要：… -->`，与网站生成同出一源。稿里写一行 `<!-- 附表：路径 -->` 的，读入时把这一行换成所指文档的表格部分（库「附表」）；译名页的翻译列表就是这样取自语言仓的《翻译列表》，与网站生成同出一源。

技术文档的汉语页写在 `/文档/名/`，文言页写在 `/文言/文档/名/`；文言总览页以 `内容/文档首页.文言.md` 前言的 `permalink` 为准，写在 `/文言/文档/总览/`，与官网同址。出站另写根上的 `_redirects`，把旧地址（`/文档/名.汉语.html`、`/文档/名.文言.html`、`/豫言操作系统.汉语.html` 等，按页源文件名推出）以 301 转到新路径；总览页旧的 `/文档/总览.文言.html` 单独写一条。站内链接在成篇时改写成这些干净路径。

## 文档的形

每页的文档由三部分组成：站头（站名与全站导航）、网址栏（本页路径逐段链接）、正文，末尾是页脚。站头、网址栏与页脚都是匠心的文档组件（「文档组件保存」），展开块是一段；主站的设计树码可以按组件名保留它们。

正文由匠心的「标记文篇」从 markdown 编成：标题、段、列表、表、引用、围栏代码与网页块。围栏代码编成「码块」，豫言的代码再经译场的语义标记切成带 `tok-` 样式类的「码片」；段落里的行内代码、强调、加粗、链接与公式照标记文的行内规则。

## 维护

改动页面的集合时改 `页面目录` 那一份声明（现为库「页录」的 `页录。数据。豫`）；改动 markdown 的转换规则时同步 `库/匠心/篇引。豫` 与本节。说明文件不参与模块导入。
