# 仓库构建

语言仓的构建程序：原生运行时、编译器自举链、豫构、类型检查、豫构测试、全树测试与网页汇编宿主，统一用普通豫言声明，由 [构建编排](../../库/构建编排/包说明.汉语.md) 并行调度与缓存。取代原来的根 Makefile 与运行时 Makefile。

## 用法

在仓库根目录运行。稳定工具有两种来源，构建程序自动选择：仓根有原生的 `yy_bs_stable`、`yy豫构_stable` 就用它们；否则用 Wasm 工具链包（见下节）的 `yy_bs_stable.wasm`、`yy豫构_stable.wasm`，经 Node 运行。有原生稳定工具时：

```sh
./yy豫构_stable 构建 仓库构建 --编译器 ./yy_bs_stable --输出 yy仓库构建 -j 24
./yy仓库构建 --列出                  # 列出全部目标
./yy仓库构建                         # 默认目标“全部”：自举并构建豫构
./yy仓库构建 类型检查 豫构测试 -j 24
./yy仓库构建 全树测试 --不连带       # 只运行测试，不重建其依赖
```

## 从 Wasm 工具链包起步

CI 每轮发布跨平台的 Wasm 工具链包 `yuyan-wasm.tar.gz`（GitHub 发布 `continuous-binaries`；`historical-binaries` 按提交号存档）：编译器、豫构与本构建程序的 WasmGC 模块（`yy_bs_stable.wasm`、`yy豫构_stable.wasm`、`yy仓库构建_stable.wasm`），以及 Node 宿主与值桥（`yy稳定节点宿主/`）。任何有 Node 与 clang 的平台都能用它从零构建本机工具链。包必须解压到仓库根目录，因为豫构以编译器所在目录为工具链根（运行时头文件与归档都相对它）：

```sh
tar -xzf yuyan-wasm.tar.gz
node yy稳定节点宿主/宿主.cjs yy仓库构建_stable.wasm 运行时 -j 24
node yy稳定节点宿主/宿主.cjs yy豫构_stable.wasm 构建 仓库构建 --编译器 ./yy_bs_stable.wasm --输出 yy仓库构建 -j 24
./yy仓库构建 -j 24
```

第一步用包里的构建程序构建原生运行时（运行时源码由目录枚举，包里的旧构建程序也能处理新增源文件）；第二步用包里的豫构与编译器构建当前源码的构建程序；之后一切交给它。编译器二级由 Wasm 编译器在 Node 下构建，三级、四级及豫构仍由稳定豫构调度。

## 目标

| 目标 | 内容 |
| --- | --- |
| 运行时调试、运行时优化 | 在 `豫言操作系统/宿主/原生/运行时支持库/构建/<变体>` 里编译 `运行时/` 下全部 C 与 LLVM 源码，归档为 `lib豫言运行时<变体><版本>.a`（先写临时归档，成功后再移入）。macOS 的优化版加 `-flto` 并用 `llvm-ar`，Linux 用 `ar`。 |
| 运行时 | 再复制出包链接所用的 `包调试`、`包优化` 两份归档。 |
| 编译器二级、三级、四级 | 分别用稳定编译器（`yy_bs_stable` 或 `yy_bs_stable.wasm`）、`yy2_bs`、`yy3_bs` 构建豫言编译器，得 `yy2_bs`、`yy3_bs`、`yy4_bs`；输入为编译器源码（三个目录下的豫言、C 与头文件，除测试与文档）。 |
| 自举 | 核对 `yy3_bs` 与 `yy4_bs` 逐字节相同。 |
| 豫构、类型检查、豫构测试 | 用 `yy4_bs` 构建 `yy豫构`、类型检查豫言编译器、运行包配置与豫构的八项测试。 |
| 全树测试工具、全树测试 | 构建 `yy全树测试` 并运行全仓测试。 |
| 网页汇编宿主、网页汇编复制宿主 | C 桥接 Wasmtime C API（仓根 `yy_wasmtime_c_api` 等），由豫构链接。 |
| 网页汇编工具链 | 用 `yy4_bs` 把编译器、豫构与本构建程序编成 WasmGC 模块，连同值桥与 Node 宿主放进 `yy网页汇编工具链/`（布局即解压到仓根的布局）；编译器直接写出 Wasm 二进制，节点值桥由 `yy4_bs` 按当前源码构建的 `yy值桥接生成` 写出（结构化表示在 `库/编译器核心/编译步骤/代码生成/回收值桥接。豫`），整个目标不需要 Wasmtime。 |
| 清理 | 删除缓存、构建产物（含 `yy网页汇编工具链/`）与运行时归档。 |
| 全部 | 自举与豫构。 |

所有调用豫构的步骤都在同一个独占组里，逐个执行，保证同一编译缓存同一时刻只有一个构建；原生运行时的两个变体可以并行。

## 维护

新增构建步骤时在 `入口。豫` 里增改目标；改动目标后同步更新本说明与文言版。
