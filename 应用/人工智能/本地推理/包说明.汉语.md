# 本地推理

这是在本机跑大语言模型的路一应用：读奥拉玛（Ollama）模型目录或 GGUF 文件，套千问对话模板（模型模板支持 enable_thinking 时用不思考模式），分词、整段预填充、逐词元生成并边生成边打印，最后打印预填充与解码的每秒词元数。计算全部经[张量计算接口](../../../豫言操作系统接口/张量计算/规范.汉语.md)交给宿主，权重经张量文件接口直接从文件载入宿主张量。分词器与文件头解析在「深度学习」，各架构的前向在「深度学习模型」，生成在「深度学习推理」。按文件头的 general.architecture 选架构，现支持 qwen3（如 `qwen3:0.6b-q8_0`）、qwen3moe（如 `qwen3-coder:30b`）与 qwen35（如 `qwen3.8:27b`）。

## 包身份

所有者：豫言。包版本：0.1.0。本包为可执行文件（入口 `入口`，产物名 `yy本地推理`），登记在「人工智能」分组下。它实现启动接口（`实现接口。豫` 声明提供角色为应用），依赖文件、张量计算与张量文件接口，所以用 `yy双宿主构建` 的节点模式构建成 Node 发行包。

## 构建与运行

在仓库根目录（需先有 `yy双宿主构建.wasm` 与 `yy4_bs.wasm`）：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy双宿主构建.wasm --自动 节点 应用/人工智能/本地推理 dist/本地推理 --包根 库/深度学习
node dist/本地推理/启动.mjs --授权只读目录 模型=$HOME/.ollama/models -- --奥拉玛 qwen3:0.6b-q8_0 --提示 你好
```

模型目录须以“模型”为名只读授予；应用参数写在 `--` 之后：

| 参数 | 含义 |
| --- | --- |
| `--奥拉玛 名:标签` | 读清单 `manifests/registry.ollama.ai/library/<名>/<标签>`（名里含斜杠时不加 `library/`，省略标签即 `latest`），取媒体类型为 `application/vnd.ollama.image.model` 的层，得 `blobs/sha256-…` |
| `--文件 路径` | 直接用模型目录里的 GGUF 文件（相对授权目录的路径） |
| `--提示 文字` | 用户提示，套进 `<\|im_start\|>user\n{提示}<\|im_end\|>\n<\|im_start\|>assistant\n<think>\n\n</think>\n\n`；提示里的特殊词元文字按特殊词元处理 |
| `--最多 N` | 最多生成的词元数，默认 256 |
| `--温度 T` | 默认 0（贪心，取最大下标）；大于零时按概率抽样，前 20 个、累积概率 0.8 |
| `--种子 S` | 抽样用的伪随机种子，默认取单调时钟 |
| `--显示词元` | 另打印“提示词元：[…]”与“生成词元：[…]”（含停止词元），便于对拍 |
| `--只分词` | 只把 `--提示` 的原文（不套模板）分词并打印词元号，不载入权重 |
| `--加速要求 值` | 取张量上下文时的加速要求：`不限`（默认）、`偏好`、`必须`（也可写全称“必须加速”等）；必须加速而宿主没有加速后端时报错退出 |
| `--功耗偏好 值` | 取张量上下文时的功耗偏好：`不限`（默认）、`低功耗`、`高性能` |
| `--不套模板` | 不套对话模板，直接把 `--提示` 的原文分词后作提示（与 llama-server 的 /completion 对拍用） |
| `--显示几率 N` | 每生成一个词元，在标准错误打印产生它的对数几率里前 N 个候选：`词元号(自然对数概率)`（对应 llama-server 的 n_probs） |

生成的文字写到标准输出；“张量后端：…（已加速或未加速）”与“已载入 …”写到标准错误。宿主选项 `--张量后端 名`（写在 `--` 之前）可强制指定张量后端，供测试。遇 `<|im_end|>`、`<|endoftext|>` 或元数据里的结束词元即停。参数不全时打印用法并以退出码 2 结束。

## 对拍

参考数据由 llama.cpp 的 llama-server 在 CPU 上对同一文件生成：`/tokenize`（`add_special: false`、`parse_special: true`）得分词结果，`/completion`（`temperature: 0`、`top_k: 1`、`n_predict: 32`、`n_probs: 5`、`return_tokens: true`）得贪心续写。设参考目录为 `$R`，第 i 组文字存为 JSON 字符串 `$R/分词i.文本.json`、结果为 `$R/分词i.json`：

```sh
for i in 1 2 3 4 5 6 7 8 9; do
  T="$(jq -j . $R/分词$i.文本.json; echo .)"; T="${T%.}"
  GOT="$(node dist/本地推理/启动.mjs --授权只读目录 模型=$HOME/.ollama/models -- --奥拉玛 qwen3:0.6b-q8_0 --提示 "$T" --只分词 | tr -d ' ')"
  [ "$GOT" = "$(jq -c .tokens $R/分词$i.json)" ] && echo "分词$i 相同" || echo "分词$i 不同"
done
node dist/本地推理/启动.mjs --授权只读目录 模型=$HOME/.ollama/models -- --奥拉玛 qwen3:0.6b-q8_0 --提示 'What is the capital of France? Answer in one sentence.' --最多 32 --显示词元
```

“提示词元”应与 `/tokenize` 对套好模板的提示所得相同，“生成词元”应与 `/completion` 返回的 `tokens` 相同。命令里的 `jq -j` 加句点再去掉，是为了保留文字末尾的换行。

2026-09-30 在 macOS arm64（Node 26.3.0）上对 `qwen3:0.6b-q8_0`（`sha256-31db9797…`，832 MB）的结果：

- 分词九组（英文句子、中文句子、Python 代码、年份与小数、表情与中文、连续空白与制表、英文缩写、带特殊词元的对话模板、豫言源码）全部逐号相同。
- 两个对话提示的提示词元与参考相同；贪心续写 “The capital of France is Paris.”（8 个词元）与 “北京是中国的首都，位于中国北方，是世界著名的历史文化名城。”（18 个词元）逐号相同。
- 速度：权重载入约 0.2 秒（文件已在页缓存中）；宿主用 18 个线程时预填充约 35–43 词元/秒，解码约 14–22 词元/秒，随主机上其他负载波动（改为多线程与融合量化点积之前，单线程为预填充 2.4、解码 2.9 词元/秒）。

混合专家与千问三点五两种架构另用合成模型对拍：按真实模型的元数据键与张量名造两个随机权重（单精度）的小 GGUF（qwen3moe：嵌入维 64、2 层、8 个专家选 2 个；qwen35：嵌入维 64、4 层，其中第 4 层为门控全注意力，键头 2 个供值头 4 个，旋转 8 维），分词器元数据照抄 Qwen3-0.6B，用 Ollama.app 自带的 llama-server（`-ngl 0 --device none`）与本应用（`--不套模板 --显示几率 3`）对同一原文提示贪心续写 8 个词元：2026-09-30 混合专家 8 个词元逐号相同，每步前三名的自然对数概率相差不到 0.003；千问三点五前 4 个词元相同，第 5 步前两名相差仅 0.0002（llama.cpp 与本实现的排序相反，属数值误差），此后把本实现的前缀交给 llama-server 续算，后 3 步的词元与前三名的对数概率也都一致（差不到 0.001）。两个大模型（Qwen3-Coder-30B-A3B 约 18.6 GB、Qwen3.8-27B 约 16.8 GB）当天因本机内存吃紧（交换区约 30/30.7 GB 已用、负载 80 以上）未能实跑。

## 已知限制

- 只支持 qwen3、qwen3moe、qwen35 三种架构与 gpt2（字节级 BPE）分词器；分词器的已知差异见「深度学习」的说明。千问三点五的多词元预测层不用。
- 对话模板只有一轮用户消息，没有系统提示与多轮对话；不支持思考模式。
- 权重整个读进宿主内存，要有与模型文件差不多大的空闲内存。
- 键值缓存按“提示长 + 最多”一次建好。
- 奥拉玛清单只认 `registry.ollama.ai`（待办事项：其他仓库地址）。
- 速度受限于路一 Node 宿主的 JS 张量内核（标量运算）与每次派发给工作线程的开销；主机繁忙时多线程的加速会打折扣，可用宿主选项 `--张量线程数` 调整。
