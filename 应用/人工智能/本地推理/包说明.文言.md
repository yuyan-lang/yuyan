# 本地推理

此路一之应用，于本机行大语言模型：读奥拉玛（Ollama）模型之目或 GGUF 文件，套千问对话之模（模型之模支 enable_thinking 者用不思之式），分词、全段预填、逐词而生，且生且书，终书预填与解码每秒之词数。诸算皆由[张量计算之接口](../../../豫言操作系统接口/张量计算/规范.文言.md)付宿主，权由张量文件之接口自文件径入宿主之张量。分词器与文件头之解在「深度学习」，诸架构之前向在「深度学习模型」，生在「深度学习推理」。依文件头之 general.architecture 择架构，今支 qwen3（如 `qwen3:0.6b-q8_0`）、qwen3moe（如 `qwen3-coder:30b`）与 qwen35（如 `qwen3.8:27b`）。

## 籍

所有者曰豫言，版本 0.1.0。此包为可执行（入口 `入口`，产物名 `yy本地推理`），登于「人工智能」之组。实启动之接口（`实现接口。豫` 声明所供之角为应用），依文件、张量计算与张量文件之接口，故以 `yy双宿主构建` 之节点式构为 Node 之发行包。

## 构与行

于仓根（须先有 `yy双宿主构建.wasm` 与 `yy4_bs.wasm`）：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy双宿主构建.wasm --自动 节点 应用/人工智能/本地推理 dist/本地推理 --包根 库/深度学习
node dist/本地推理/启动.mjs --授权只读目录 模型=$HOME/.ollama/models -- --奥拉玛 qwen3:0.6b-q8_0 --提示 你好
```

模型之目须以“模型”之名只读授之；应用之参书于 `--` 之后：

| 参 | 义 |
| --- | --- |
| `--奥拉玛 名:标签` | 读清单 `manifests/registry.ollama.ai/library/<名>/<标签>`（名含斜线则不加 `library/`，略标签即 `latest`），取媒类为 `application/vnd.ollama.image.model` 之层，得 `blobs/sha256-…` |
| `--文件 路径` | 径用模型之目中之 GGUF 文件（相对所授之目） |
| `--提示 文` | 用者之提示，套入 `<\|im_start\|>user\n{提示}<\|im_end\|>\n<\|im_start\|>assistant\n<think>\n\n</think>\n\n`；提示中特殊之词之文，以特殊之词处之 |
| `--最多 N` | 所生之极数，缺省二百五十六 |
| `--温度 T` | 缺省零（贪心，取最大之序）；大于零则按概率抽样，前二十、累积概率 0.8 |
| `--种子 S` | 抽样之伪随机之种，缺省取单调之钟 |
| `--显示词元` | 又书“提示词元：[…]”与“生成词元：[…]”（兼止词），以便对拍 |
| `--只分词` | 惟以 `--提示` 之原文（不套模）分词而书词号，不载权 |
| `--加速要求 值` | 取张量之境时加速之求：`不限`（缺省）、`偏好`、`必须`（亦可书全称如“必须加速”）；必须而宿主无加速之后端则报误而退 |
| `--功耗偏好 值` | 取张量之境时功耗之好：`不限`（缺省）、`低功耗`、`高性能` |
| `--不套模板` | 不套对话之模，径以 `--提示` 之原文分词为提示（以与 llama-server 之 /completion 对拍） |
| `--显示几率 N` | 每生一词，于标准误书生之之对数几率之前 N 候选：`词号(自然对数之率)`（对 llama-server 之 n_probs） |

所生之文书于标准输出；“张量后端：…（已加速或未加速）”与“已载入 …”书于标准错误。宿主之选 `--张量后端 名`（书于 `--` 之前）可强指张量之后端，以供验。遇 `<|im_end|>`、`<|endoftext|>` 或元数据所记之终词则止。参不全则书用法，以退出码二终。

## 对拍

参考之数，由 llama.cpp 之 llama-server 于 CPU 对同一文件所生：`/tokenize`（`add_special: false`、`parse_special: true`）得分词之果，`/completion`（`temperature: 0`、`top_k: 1`、`n_predict: 32`、`n_probs: 5`、`return_tokens: true`）得贪心之续。设参考之目为 `$R`，第 i 组之文存为 JSON 之文 `$R/分词i.文本.json`，其果为 `$R/分词i.json`：

```sh
for i in 1 2 3 4 5 6 7 8 9; do
  T="$(jq -j . $R/分词$i.文本.json; echo .)"; T="${T%.}"
  GOT="$(node dist/本地推理/启动.mjs --授权只读目录 模型=$HOME/.ollama/models -- --奥拉玛 qwen3:0.6b-q8_0 --提示 "$T" --只分词 | tr -d ' ')"
  [ "$GOT" = "$(jq -c .tokens $R/分词$i.json)" ] && echo "分词$i 相同" || echo "分词$i 不同"
done
node dist/本地推理/启动.mjs --授权只读目录 模型=$HOME/.ollama/models -- --奥拉玛 qwen3:0.6b-q8_0 --提示 'What is the capital of France? Answer in one sentence.' --最多 32 --显示词元
```

“提示词元”当同 `/tokenize` 于已套模之提示所得，“生成词元”当同 `/completion` 所还之 `tokens`。命令中 `jq -j` 加句点而后去之，所以存文末之换行。

2026-09-30 于 macOS arm64（Node 26.3.0）对 `qwen3:0.6b-q8_0`（`sha256-31db9797…`，832 MB）之果：

- 分词九组（英文之句、中文之句、Python 之码、年与小数、表情与中文、连白与制表、英文缩写、含特殊之词之对话之模、豫言之源）皆逐号相同。
- 二对话提示之提示词与参考同；贪心之续 “The capital of France is Paris.”（八词）与 “北京是中国的首都，位于中国北方，是世界著名的历史文化名城。”（十八词）逐号相同。
- 速：载权约 0.2 秒（文件已在页缓存）；宿主用十八线时，预填每秒约 35–43 词，解码每秒约 14–22 词，随主机他负而变（未以多线与融合量化之点积之前，单线预填每秒 2.4 词、解码 2.9 词）。

混合专家与千问三点五二架构，又以合成之模对拍：依真模型之元数据键与张量名，造二随机权（单精度）之小 GGUF（qwen3moe：嵌入维六十四、二层、八专家择二；qwen35：嵌入维六十四、四层，第四层为门控全注意，键头二供值头四，旋八维），分词之元数据抄 Qwen3-0.6B，以 Ollama.app 所附之 llama-server（`-ngl 0 --device none`）与此应用（`--不套模板 --显示几率 3`）于同一原文之提示贪心续八词：二〇二六年九月三十日，混合专家八词逐号皆同，每步前三名之自然对数之率差不逾 0.003；千问三点五前四词同，第五步前二名相差仅 0.0002（二者序反，数值之差也），此后以此应用之前缀付 llama-server 续算，后三步之词与前三之对数之率亦皆合（差不逾 0.001）。二大模型（Qwen3-Coder-30B-A3B 约 18.6 GB、Qwen3.8-27B 约 16.8 GB）是日以本机之存甚紧（交换区约 30/30.7 GB 已用、负载逾八十）未得实行。

## 所未及

- 惟支 qwen3、qwen3moe、qwen35 三架构与 gpt2（字级 BPE）之分词器；分词之已知差异见「深度学习」之说。千问三点五之多词预测之层不用。
- 对话之模惟一轮用者之言，无系统之示与多轮之话；不支思之式。
- 权尽读入宿主之存，须有与模型文件相若之空存。
- 键值缓存依“提示长 + 最多”一次建之。
- 奥拉玛之清单惟识 `registry.ollama.ai`（待办事项：他仓之址）。
- 速限于路一 Node 宿主 JS 之张量内核（标量之算）与每派于工作线程之费；主机繁时多线之益减，可以宿主之选 `--张量线程数` 调之。
