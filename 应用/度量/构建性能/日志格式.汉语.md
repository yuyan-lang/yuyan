# 构建日志格式

构建日志是豫构、构建编排与并行编译在每次构建时写下的事件记录，存放在半永久的日志目录里，供日后分析构建性能。它不随下一次构建覆盖，清理 `.豫构缓存` 也不受影响；用 `构建性能 清理 保留条数` 删除旧记录。分析工具见 [构建性能](../../百工坊/构建性能/包说明.汉语.md)，调查的做法见[调查方案](调查方案.汉语.md)。

## 位置

```text
<仓库根>/.构建日志/
  运行/
    20260930-102540-构建-全树测试-679333/   一次运行一个目录：本地时间-命令段-纳秒末六位
      运行.json                             运行的元数据（只由顶层进程写）
      豫构-438613786679333.jsonl            每个进程一份事件文件：种类-启动时的纳秒读数
      编译-438614852029250.jsonl
      编译-438614852029250.调试印.txt       工作进程里调试印的记录（有调试印时才有）
```

- 每个 worktree 各有一份，目录以点开头，包发现不会扫描它，`.gitignore` 已忽略。
- `<进程标识>.调试印.txt` 收这一次构建里工作进程打的调试印（`--debug-print-add` 打开）：一行任务题头（`# 阶段名：文件`），其下是该任务写出的「察印条」记录行；一条也没有时不建这个文件。构建收尾客户端印一行“调试印 N 条，见 <路径>”（议题 #1703）。
- 环境变量 `豫言构建日志目录` 改日志根目录（相对路径按当前目录解析）；`豫言构建日志=0` 关闭日志；`豫言构建日志标签` 给运行贴标签，写进 `运行.json`，便于把同一组实验归在一起。
- 日志不自动删除。

## 何时记录

- 豫构的构建类命令（`构建`、`类型检查`、`文件` 与仓库目标 `自举`、`测试`、`全部`、`目标 …` 等）新建一次运行；`发现`、`检查`、`定位` 与帮助不记录。
- 记录开启后，豫构、构建编排启动 `.wasm` 子程序时包成 `env 豫言构建日志运行=<运行目录> 豫言构建日志父项=<本进程标识>/<任务名> 程序.wasm …`；宿主拆开这层包装，把变量并入子程序的环境。在 macOS 与 Linux 上，原生子程序（`.exe`，如原生编译器 `yy4_bs.exe`）也这样包，由系统的 env 设好变量。嵌套的豫构与编译器据此加入同一次运行，各写一份事件文件。
- 直接运行编译器（`--parallel`）时编译器不新建运行，只在继承到运行目录时记录。
- 事件先存在内存，进程结束时一次写盘；`运行.json` 在开始时写一次（状态“进行中”），结束时补上结果重写。

## 时刻

事件里的时刻都是单调时钟的纳秒读数（Node 的 `hrtime`），同一台机器上各进程、各线程共用这一时钟，可以直接放在一条时间线上比较。本地时间只记在 `运行.json` 的“开始本地时间”。

## 运行.json

| 字段 | 含义 |
|---|---|
| 格式 | 日志格式版本，现为 1；字段只增不改 |
| 运行 | 运行目录名 |
| 状态 | 进行中、完成或失败 |
| 命令 | 豫构的命令行参数（字符串数组） |
| 目录 | 当前目录 |
| 分支、提交 | 分支取 `git branch --show-current` 的完整名称，提交取 `git rev-parse --short HEAD`；取不到或分离头指针时分支为空串 |
| 有未提交改动 | `git status --porcelain --untracked-files=no` 是否有输出 |
| 系统、处理器数 | macOS、Linux 或 Windows；在线处理器数 |
| 标签 | `豫言构建日志标签` 的值 |
| 开始本地时间 | 如 `2026-09-30 10:25:40` |
| 开始、结束 | 单调时钟纳秒 |
| 用时毫秒、退出码 | 结束时写入 |
| 负载开始、负载结束 | Linux 读 `/proc/loadavg`，macOS 用 `sysctl -n vm.loadavg`；负载高说明有别的构建在抢处理器 |

## 事件

每行一个 JSON 对象，字段“种”区分事件种类。第一行是本进程的“进程”事件。

**进程**：`标识`（种类-纳秒）、`父`（`<父进程标识>/<任务名>`，顶层为空串）、`种类`（豫构或编译）、`参数`、`目录`、`开始`、`结束`、`退出码`。

**区间**（豫构与编译器）：`名`、`开始`、`结束`；另有可选附栏，只在给了时写出。豫构的名有：包表（纯读包籍）、补全（按依赖闭包解析包描述与包图，含写语言服务文件）、包上下文、编译器调用。编译器最终链接与原生生成的名以“链接：”起头，如算链接印、查成品缓存、读入与合并模块、跨模块处理、生成机器无关码、侧表与全局映像、降级成机器码、符号表、编客体树码、豫汇并入、格式编码与写出、写出、文件读写；并行降级另按片记 `链接：降级分片<片号>（<块数>块）`、主进程记 `链接：降级主进程（<块数>块）`，名里的块数就是这一片认领的块数，区间的开始是加入时刻、结束是退出时刻；构建性能的“链接分段”一节按名汇总印出。

链接的缓存与文件附栏：`命中`、`未中`（降级共享库与整产物缓存的中未件数）、`读次`、`读字节`、`查次`、`等待`（链接期读文件次数、读入字节数、查文件次数与这些调用的总等待毫秒，见营造的「记营链接读写」与「记营区间中未」）。附栏按名相加，构建性能在链接分段一行里印出；工具与库的解释器按无附栏的旧条目处理。

**事**（豫构）：`种` 为“事”的普通事件，`类` 为事件类别。`类` 为“包表”时带 `读表纳秒`、`条目数`、`表数`、`用时纳秒`，分别记纯读包籍的时间、读到的登记条数、读了几份表与从起步到读完表的总时间。

**目标**（构建编排）：`名`、`跳过`（缓存键未变而跳过时为真）、`算键开始`、`算键结束`（计算缓存键的用时，其中要遍历目录输入）。

**段**（客的构建段，议题 #1653）：`名`、`开始`、`结束`、`单位`、`已`、`总`、`占槽`。客在自己的进程里把构建分成几段（开工准备、查缓存、实约生成、写产物、收尾），每段起止时由豫构或编译器写下一条（见营造的「记营段」）；`名` 是段名，`单位` 是进度单位（如 `已查/总数`，无进度为空串），`已` 与 `总` 是进度与总数，`占槽` 表示这一段是否占构建服务的槽。构建性能按 `名` 汇总各段用时；同一段可能出现多次（如逐篇构建时每篇各一次）。

**步骤**（构建编排）：`任务`（如 `编译器三级#1`）、`描述`（命令及参数，即缓存键里的步骤描述）。

**编译**（并行编译开始时一条）：`程序`（编译器路径）、`主文件`、`上限`（并发数）、`仅检查`、`缓存目录`（`.yybuild/sha256_<本程序摘要>.nosync`，与编译缓存目录同名；原生程序的摘要是生成时嵌入的客体摘要）、`缓存目录已存在`（为假即从冷缓存编起）。

**任务**（构建编排与并行编译的调度任务）：

| 字段 | 含义 |
|---|---|
| 名 | 任务名；编排任务如 `豫构#检查`、`豫构#1`、`豫构#完成`，编译任务如 `parse：库/豫章/形制/次第。豫` |
| 依赖 | 所待任务的名称 |
| 加入 | 任务创建的时刻 |
| 就绪 | 调度器首次发现其依赖全部成功的时刻 |
| 开始 | 派发启动的时刻 |
| 结束 | 调度器收取到完成的时刻（含收取延迟） |
| 在途 | 开始时在途的任务数（含自己） |
| 状态 | 成功、失败、未运行或运行中 |
| 阶段、文件 | 只有编译任务有：阶段显示名（依赖分析、语法解析、类型检查、跨模块优化、闭包转换、最终链接等）与去掉目录前缀的文件 |
| 后于全图 | 只有最终链接有：它在全部任务结束后开始，依赖列为空 |
| 节点统计 | 并行编译任务可有的对象：`模块准备毫秒`、`执行毫秒`、`宿主调用数`；跨模块优化任务另有 `跨模块优化内联`、`跨模块优化特化`、`跨模块优化停手`、`跨模块优化大小`（这一件展开后的大小，议题 #1691）。仅继承 `豫言构建日志运行` 的 worker 写出。未开启日志时，显式设置 `豫言诺驿统计=1` 仍用旧详细 JSON 行，不产生新 marker。旧运行没有此字段，按无统计处理 |
| 执行处、排队毫秒、传输毫秒、传输字节 | 经构建服务（将作，提案 00035）执行的任务才有：执行处（本机代役为“本机”，外派时为同僚名）、在服务里排队的毫秒数、外派传物的毫秒数与字节数（本机执行为零）。不用服务的运行没有这四个字段 |

未发生的时刻为 0。三段等待由此算出：等依赖 = 就绪 − 加入，等槽位 = 开始 − 就绪，执行 = 结束 − 开始。

## 不合规的文字

写进日志的文字先核验 UTF-8。命令行参数、当前目录、分支、提交、标签、负载这类从外部取来的字段若含截断的多字节字符（例如命令行从别处抄来时被截掉半个汉字），坏字节换成问号，标准错误上印一行，写出字段名与坏字节的十六进制：

```text
营造：构建运行记录字段「参数」含不合规的 UTF-8 字节，已换成问号：e4 b8
```

字段先经净化再编码，所以 `运行.json` 与事件文件照常写成，构建照常进行。某条事件的字段编不成结绳时只跳过这一条（同一次运行里只报一次），写盘失败同样只报一行，日志缺这几条。

## 分析

先 `构建性能 列出` 找到运行，再 `构建性能 摘要 <运行名>` 看汇总（其中“客段”一节按段名列出次数、合计、均值与最大用时）；需要别的统计时直接读 JSON 行。比较两次运行时，先核对命令、提交、有无改动与负载；负载高或与别的运行时间重叠的计时不宜比较。

## 局限

待办事项：旧运行没有“节点统计”与“段”，分析器按无统计、无段处理；进程被中途杀死时，内存里未写盘的事件会丢失，`运行.json` 停在“进行中”，最后一段的起止也写不进去；缓存是否命中、工作进程内部各步（读依赖、计算、写出）的用时与字节数尚未记录；Windows 上宿主按冒号拆 PATH，找不到 git，分支与提交为空。
