# 豫言并行编译

今派事先收毕者，展新依赖，而于就绪者中择早阶：依赖分析、解析、检查并擦除、跨卷优化、闭包、正则、代码生成，依序为先。同级守加入之序，不夺在途者；高位事未就绪，毋塞已就绪者之槽。

编译器默认用此前端阶段图，至闭包而入整卷后端，省旧正则续延及逐卷机器码之事。`--frontend-tasks=split` 明选拆分，`--frontend-tasks=combined` 合一卷前端于一客，以供对照。算法与导出如旧，惟诊辞之新鲜名号或因进程界而异。二选项及于并行之构建；仅检查与串行仍其法。旧种子未识新选项，须先自源码制新器。实测见[合并与拆分](../性能研究/前端调度/合并与拆分.文言.md)。

编译器受 `--parallel`，则以豫言之任务图调度诸工作进程，不假 Python。其书今置于 `库/构建基础` 包，编译器与豫构共用之。

`-j N`、`--num-cpu N` 皆限在途进程之数；未言其数，则取在线之核数。`--very-parallel`、`--yuyan-parallel` 亦行此法。

一文件之事，次为察依赖、解析、类型检查并擦除、跨模块优化、闭包转换、求值正则变换、代码生成。解析至跨模块优化，必候所依文件之同阶段皆毕；其后唯候自身前阶段。察得新依赖，则增文件与任务。终以有序候选反复拓扑扫描，定链接之序，不以进程毕时为序。

诸工作仍受 `--mode=worker`，缓存之约如故。唯检查类型者，止于检查并擦除。依赖以换行分，参数各为一串，故路径有空格亦可。事败或启事有误，则止启新事，候在途者毕而收之，返非零码；所待成环或缺失，则报未毕之事。

`yy_parallel_log.txt` 记进程号、退出码及两路输出，`yy_parallel_deps.txt` 记文件依赖。任务图毕与链接毕时存之；中途骤止，未必得存。诸构建不可同时写同一缓存与日志。

终端今设监视之屏，原处更新，示总时、成败与在途之数、诸阶段及在途文件之用时，不列进程号。每二百毫秒至多绘一次，以限时候输入输出，非空转也。事久未毕，其时亦进。先示总数与诸阶段，后列在途文件；屏狭则裁，先存统计；窗改则存旧影而另绘，勿误删旧辞。不改原始输入，不隐光标。

依赖渐明，事总数亦增；待依赖与待槽位别列，所待皆成而未启者为待槽位，每轮派发后计之，已行者不计。败而止派，不复称待槽。已毕兼缓存命中，非实重编之数。末次链接亦入屏。成则撤屏留要，败则先撤后告，诊辞不掩。stderr 非终端、`TERM=dumb`、无终端之能或窗太小时，仍逐行报启毕成败。`--no-debug-print` 止屏与报，错误仍告。工作内部输出先收集，详录 `yy_parallel_log.txt`，非逐字即传。

## 异步子进程

`标准库/操作系统/异步子进程` 有 `异步获取输出`，受程序名与参数列，即启进程，返 `异步任务于子进程结果`。结果四者：进程号、退出码、标准输出、标准错误也。同一任务，可再候之。

启而不成，进程号为零，退出码为 127，并告系统错误。信号致止，则码为 128 加信号号；收集或回收有误，则为 125。已启之任务，调用者当候之，以释宿主之进程记录。此术收文本，尚无取消、超时之法。

豫言之调度仍在一线程。于 Node 宿主，子进程由进程之桥（`豫言操作系统/宿主/节点/进程桥接.cjs`）代治：Wasm 之客同步行于工作线程，以消息之端发启、收、候之请，以 `Atomics.wait` 止而待主线程之答；Node 主线程启子进程而收其两出，俟其既退、两出俱阖，乃记其毕，以答所候之请。桥唯递进程与毕事，任务图仍行于豫言之客。多核之用，在诸工作进程；同一编译器所派 `--mode=worker` 之事，宿主默以编译线程池（`编译线程.cjs`）行于 Node 工作线程，余子程仍为真进程。

## 自举与验

于仓根行豫构之自举目标，诸级皆由豫构按包图构之：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 自举 -j 24
```

其始于稳定之种 `yy_bs_stable.wasm`，逐级以前级之器造 `yy2_bs.wasm`、`yy3_bs.wasm`、`yy4_bs.wasm`，校 `yy3_bs.wasm` 与 `yy4_bs.wasm` 逐字相同；目标定于 `应用/豫构/仓库目标。豫`，初举详见[仓库包构建](文档/仓库包构建.文言.md)。文件式之命亦委同目录之豫构（`yy豫构.wasm`），皆循包图。验书在 `库/标准库/测试/异步/子进程-1。豫` 与 `应用/豫构/调度器。测试。豫`，验众输出、信号、错误码、再候、回收、并发之限、依赖之序、动态增事及败后收拢。验子进程，可先行 `ulimit -n 64`。
