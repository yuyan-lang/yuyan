# 仓库包构建

于仓根行豫构。包名取 `。包。豫` 之文件名，其所在即包根。配置唯解语法，不行其文。主名与依赖之制，见[包系统](../包系统.文言.md)。

## 目录

仓根惟五目：`库/` 藏众用之库，依父库层层而置；`应用/` 藏可执行之程序，分发布、网页汇编、文档站、开发工具、人工智能诸组，另有豫言编译器、豫构、性能研究、本地模型验收；`豫言操作系统接口/` 为带回收之接口；`豫言操作系统底层接口/` 为无回收之底层接口；`豫言操作系统/` 为其实现，内有宿主、适配、装载、裸机，及操作系统之工具（`应用/`）。

库之试置其库下之 `测试/`；试若须外依，则于其处别立试包（如 `库/标准库/测试` 之「标准库测试」），试包依所试之库，登于其上一层之父（见“包之层级”）。唯一应用所用之库，置其应用下之 `库/`，登为其应用之子；众用者乃入顶层 `库/`。WasmGC 客体运行时书于编译器之内（`库/编译器核心/编译步骤/代码生成/回收运行时。豫`），编译器直书 Wasm 二进制。

## 包之层级

诸包以「包含包」「包含在」相系，成若干之树，以便循层而览。`node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 发现 --树` 录诸包之树：根依其目而排，子依「包含包」之序缩进，每行书包名、目录与简介。层级不改包名，不改导入；应用仍径依具体之包。

| 根 | 目录 | 子 |
| --- | --- | --- |
| 共用库 | `库/` | 众用之高级库；安全外壳（分组之父，其下四库与验程）；诸库 `测试/` 下之试包 |
| 底层库 | `库/底层库` | 无；底层之模，自成一根 |
| 中央张量内核 | `库/底层库/中央张量内核` | 无；底层之模，依底层库（不得为其子，父之库子为隐依），自成一根；其试「中央张量内核测试」为可执行之包，登于共用库之下 |
| 发布、开发工具、文档站、网页汇编、人工智能 | `应用/` 下同名之组 | 组中之程；数据库连接兼为其私库「工具包」之父 |
| 豫言编译器 | `应用/豫言编译器` | 测试（语言回归之试）、文例（文档之例） |
| 豫构、性能研究 | `应用/豫构`、`应用/性能研究` | 无 |
| 豫言操作系统适配 | `豫言操作系统/适配` | 诸接口之适配，依接口总纲之序；基础适配之验收程 |
| 豫言操作系统工具 | `豫言操作系统/应用` | 操作系统构建、绑定、装载、检查之具 |
| 豫言裸机 | `豫言操作系统/裸机` | 裸机后端、客体二号及诸例与探针；WASI库 依客体二号之内模，不能独编，自成一根 |
| 豫言操作系统接口 | `豫言操作系统接口/` | 诸接口包，依总纲表序；其说即总纲 |
| 豫言操作系统底层接口 | `豫言操作系统底层接口/` | 诸底层接口包（底层之模）；其说即总纲 |

分组之父唯有包述与双语包说，无模，置于组之目；目中不属诸子之文（如 `应用/开发工具/yuyan-vscode/`、`应用/文档站/库/文档界面/`）属之。

规：

- 新包入上表之目者，必于父之「包含包」登之，新包书「包含在」；两向不合，豫构报之。
- 子不得依其祖。试包依所试之库，故登于其上一层之父，如「标准库测试」在「共用库」下，安全外壳之验程在「安全外壳」下。
- 父与库子其模必同：底层之库唯可挂于底层之父，故 `底层库` 自成一根；可执行之子不在此限，惟以归类。
- 父子不越云仓所复之目界。云仓之构建唯复 `库/`、`豫言操作系统/`（除 `裸机/`）、`豫言操作系统接口/` 与 `应用/` 下之豫言编译器、豫构、文档站、网页汇编，而于其中行豫构；故 `应用/` 与 `豫言操作系统/` 之根不设父包，`裸机/` 自成一树。
- 批量发布为单包立构建之时，暂存构建树中之包述去此二字段，发行之源码存其原文。

## 包界

库有标准库、单元测试、结森工具、网页客户端、云工宿主、浏览器宿主、构建基础、编译器核心、包配置、源码排版诸包（单元测试至浏览器宿主五者旧合为拓展库，今各自成包；旧之网页服务端无所用，简易网页服务器自具其能，故删之）；工具包唯数据库连接所用，移入其下之 `库/`。标准库无外依；构建基础司包定位、上下文与并行调度，不依编译器。编译器居 `应用/豫言编译器`，依标准库、结森工具、构建基础。包配置用编译器之 parser；豫构复依包配置，故不可反使编译器依豫构。着色语言之内建之声为着色库（`库/着色库`，无所依），其译器在编译器核心；着色语言之试为「着色库测试」（`库/着色库/测试`），依编译器核心，故别为一包。张量计算之 GPU 算核为张量内核（`库/张量内核`，依标准库、着色库），其试为「张量内核测试」（`库/张量内核/测试`），依系统库调用、金属与张量内核，无金属则略之。

工具各有目录、包籍与入口，不复立工具总包，分居 `应用/<组>/` 与 `豫言操作系统/应用/`。共享排版之术别置库/源码排版。语言之试为测试包，居 `应用/豫言编译器/测试`；文档及其例为文例包，居 `应用/豫言编译器/文档`；性能研究居 `应用/性能研究`。标准库之试居 `库/标准库/测试`（「标准库测试」），免反依成环。测试有预期失败之文，不可尽以构建成功为验。`*_v0` 不察。

## 导入

```text
寻观「标准库」之书。
寻观「标准库」之「数据结构」之「多态列」之书。
寻观「构建基础」之「包定位」之书。
```

首例独书标准库，则取 `库/标准库/总集。豫`，模块仍称标准库。众包同此法：总集须手书，缺则报，不择他书，不循当前目录。内核入标准库目录。总集非程序入口，不删诵，不易重导出之义。

库、应用及其下分组之目，皆为分类，分组之目另有父包（见“包之层级”）；导入不书分类之目。旧标准库转发书与特殊搜索之途皆除。

包可用「包含在」「包含包」二字段成组：父登记其直子，子明其父。依父，即得以 `父之子之模块` 引其子之模块；路径止于子，则取子之总集。成组乃逻辑之系，不改包名，不系于目录之相套。字段、校验与上下文，见[包系统](../包系统.文言.md)。

## 构建

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 目标 豫构
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 目标 类型检查 豫构测试
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 检查 豫言编译器
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 豫言编译器 --输出 yy编译器.wasm
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 文档网站生成器 --输出 yy文档网站.wasm
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 标准库测试 数据结构 可选值。测试 --输出 yy可选值测试.wasm
node 豫言操作系统/宿主/节点/宿主.cjs yy可选值测试.wasm
```

构建与类型检查可于包名后明言入口各段，不带扩展名，不复书包名。不言则取包文件之入口。无默认入口者仍可供依赖，亦可明择程序而建之。入口虽异，不越子包，不宽直依之禁。

## 初举

凡构建皆由豫构之仓库目标（`应用/豫构/仓库目标。豫`）行之：于仓根行 `node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 自举|测试|打包|清理|全部 [-j 并发] [--强制] [--不连带] [--列出]`，或以 `… yy豫构.wasm 目标 名…` 行任一目标。稳定之器出自 CI 所发之 Wasm 工具链包（`historical-binaries` 之 `<提交之时>-yuyan-wasm-<提交号>.tar.gz`，时取 UTC，若 `20260930T090727Z`；CI 所用之址与 SHA-256 见 `.github/workflows/main.yml` 之 `YY_WASM_TOOLCHAIN_URL`、`YY_WASM_TOOLCHAIN_SHA256`；最新之连续版为 `continuous-binaries` 之 `yuyan-wasm.tar.gz`），包中有 `yy_bs_stable.wasm`、`yy豫构_stable.wasm` 与 Node 宿主 `yy稳定节点宿主/`。解包于仓根，唯须 Node：

```sh
node yy稳定节点宿主/宿主.cjs yy豫构_stable.wasm 构建 豫构 --编译器 ./yy_bs_stable.wasm --输出 yy豫构.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 全部 -j 24
```

工具链既备，可行 `node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 目标 模拟器冒烟 -j 24`：重造普通豫言之验证器，于 QEMU 之 ARM64、AMD64 各验打印。二〇二六年九月二十八日本机热缓存约三十二秒而过。此为 WP10 快检中 QEMU 冒烟之一部；按所改择试及全快检目标尚待接之。

首步以包中稳定之豫构与编译器，据今源造 `yy豫构.wasm`；今所定之种默生 Wasm，无须指定目标。次步“全部”自初级即由稳定豫构按包图造 `yy2_bs.wasm`、`yy3_bs.wasm`、`yy4_bs.wasm`，比定点，乃以 `yy4_bs.wasm` 造正式之豫构 `yy豫构.wasm`；于苹果与 Linux，终以同源之原生生成器与执行器预编二 `yy4_bs.wasm`、`yy豫构.wasm` 为本机之原生程序 `yy4_bs.exe`、`yy豫构.exe`（仓库目标「原生工具链」），此后常用 `./yy豫构.exe`，默用原生编译器，所启之 .wasm 子程改经 node 行之；视窗暂不生，仍用 Node 之工具链；不复造单文件引导器。

文件式编译命令仍可用，然皆委豫构，非旧搜索也。

依赖、位置、子包之界有变，则缓存别域，不误用旧绑定。远程获取、版本求解与锁文件，皆未设。
