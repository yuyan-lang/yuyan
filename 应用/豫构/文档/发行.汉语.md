# 豫构发行

`豫构 发行` 把豫言应用构建成能直接在宿主上运行的发行物，宿主有四种：云工（Cloudflare Workers）、浏览器、节点（诺驿单文件发行包）与原生（本机可执行文件）。它读应用的包描述，传递解析依赖，为用到的每个 `豫言操作系统XXX` 接口按宿主选择适配并绑定，生成包上下文，编译应用，复制宿主外壳，最后封装接口清单。接口检查、接口绑定与装载接口都在豫构进程里完成；编译器缺省就是豫构自己。

豫构发行用豫言编写，源码在 `应用/豫构/发行/`。应用编译为 WasmGC；值桥按编译器核心的结构化表示直接写出；JS 外壳从浏览器或云工宿主库复制，只负责加载 Wasm、传递宿主能力，应用行为都在豫言中。

## 用法

```sh
豫构 发行 <云工|浏览器|节点|原生|豫行> <应用目录> <输出目录> \
  [--包根 <目录>]… [--许可 <文件>|-] [--命名入口 <名>] [--启动器 <文件>]… [--编译器 <路径>] [--类型检查]
豫构 发行 <云工|浏览器> <入口源码> <输出目录> --包上下文 <文件> \
  [--许可 <文件>|-] [--命名入口 <名>] [--编译器 <路径>]
```

`豫构` 指仓库根的 `./豫构。林檎。豫行`；Windows 或只有 Wasm 工具链时写 `node 豫言操作系统/宿主/节点/宿主.cjs 豫构.wasm`。`豫构 发行 --帮助` 打印用法。

**构建根**：在构建根目录运行。构建根含 `库/`（标准库与内置基础库）、`豫寓榫卯/` 与 `豫言操作系统/`（`适配/`、`宿主/`、`装载/`）。语言仓根目录本身就是构建根，云仓的 `dist/构建源码` 也是。原生模式另用构建根里的执行器 `执行器。树码`（「全部」会生成）。这些目录可以是指向语言仓的符号链接：豫构发行用规范化（解析符号链接后）的物理路径生成包上下文，因为包上下文要求规范的绝对路径，且编译缓存按路径计，同一份源码只能以一个路径出现。

**参数**（选项可以写在位置参数之前、之间或之后）：

- `云工|浏览器|节点|原生|豫行|模拟`：宿主模式（豫行模式与模拟模式见下文同名两节）。
- `应用目录`：含 `入口。豫`（或脚本 `入口。脚本。豫`，用于要导入测试的验收应用）与恰好一个包描述的目录。
- `输出目录`：产物目录；构建前会先删除（见“产物与临时文件”里的安全检查）。
- `--包根 <目录>`：可重复，指定到哪些目录（递归）里找库包，只认 `<包名>。包。豫`。目录相对构建根，也可写绝对路径；同一文件经多个包根重复出现只算一个。
- `--许可 <文件>|-`：云工模式的许可文件；缺省时取 `<应用目录>/许可。数据。豫`（存在时；目录里留着旧的 `许可.json` 时报错），否则不用；`-` 表示明确不用。其他模式不使用许可文件，给出文件会报错。
- `--命名入口 <名>`：只用于云工模式，须为 ASCII 标识符（见下文“命名入口”）。
- `--入口 <文件名>`：只用于模拟模式，入口文件（相对应用目录），缺省 `模拟验收。脚本。豫`。
- `--编译器 <路径>`：缺省用豫构自己（原生 `豫构。林檎。豫行` 或 `豫构.wasm`）；不含斜杠的名字会补 `./`。
- `--类型检查`：只对入口做类型检查（编译器带 `--type-check-only --parallel -j 24`，诊断直接打印到终端），不构建产物，不装载清单。
- `--包上下文 <文件>`：按给定包上下文直接构建（见“给定包上下文”）。
- 编译器恒带 `--parallel -j 24`（构建并行度不低于二十）。

**做什么**（按顺序）：

1. 应用目录须恰有一个 `*。包。豫`，读其名称、所有者与依赖；没有时，须恰有一个 `*。包。豫.txt`（语言仓一致性验证目录把包描述存成 `.txt`，免得被全仓库包发现当成包）：此时把应用目录复制到 `dist/.自动构建/<输出名>/应用`，并把 `.txt` 改回原名，此后以副本为应用目录。
2. 传递解析依赖：`豫章` 与内置基础库（`考课`、`结绳`、`营造`、`译场`、`网页客`、`云工东道`、`网览东道`；网页客户端的源码高亮用编译器核心的语法分析，所以编译器核心及其依赖构建基础也内置）内置；`豫言操作系统XXX` 表示操作系统接口 `XXX`；其余依赖到各 `--包根` 里找恰一个 `<名>。包。豫`，找不到或多于一个都报错（写明包名、被谁依赖、已搜索的包根或全部候选），并递归解析它的依赖；环用已访问表截断。库与应用的排列是依赖在前、应用在末；接口按名字的字节序排列，与依赖声明顺序、包根顺序无关，产物可复现。所有包的所有者须为「豫言」，依赖须是平铺的名字列表，包名与接口名不得为空、`.`、`..`，也不得含斜杠、反斜杠、制表符与换行。
3. 对每个接口 `XXX`（连同接口包自己依赖的接口，如显示依赖基础）：接口目录 `豫寓榫卯/XXX`（一个或多个 `*。接口。豫` 模块），适配按该模式的宿主支持清单 `豫言操作系统/宿主/<节点|浏览器|云工>/宿主支持清单。数据。豫` 选（每行“接口名⇥适配目录⇥宿主支持清单文件”）：适配写 `-` 的接口由应用提供，写 `宿主` 的由宿主以带类型导入直接提供，两者都不绑定，包上下文直接指向接口的规范包描述；表里没有的接口报“宿主不支持接口”。宿主直接提供的接口所依赖的接口也须写成 `宿主`，否则报错，因为同一类型在客体里只能有一种表示。节点模式必须有表；浏览器与云工模式没有表时，适配目录按宿主模式取第一个存在的：云工模式 `豫言操作系统/适配/XXX云工`、`XXX`，浏览器模式 `XXX浏览器`、`XXX`。原生模式依次选择 `XXX原生`、`XXX节点`（诺驿适配只用豫言库，原生共用）与共用的 `XXX`，额外的适配子包可以通过 `--包根 豫言操作系统/适配` 发现。适配目录里须有与每个接口模块同名的实现模块。先删旧的 `dist/.自动构建/<输出名>/操作系统绑定/XXX`，再做接口绑定（与 `豫构 接口绑定 <接口包描述> <适配包描述> <各实现模块…> dist/.自动构建/<输出名>/操作系统绑定/XXX` 相同）。找不到适配时报错，并提示是否只存在另一宿主的适配。适配包描述里既不是内置包、也不是操作系统接口的依赖（额外库，如张量适配依赖的 `金属`）连同其传递依赖并入包节点，放在应用之前，并写进该接口绑定包的上下文行，应用本身不必依赖它们；额外库先在各 `--包根` 里找，找不到时到构建根的 `库/` 里找（`--包根` 里的同名包优先）；额外库还需要应用没有依赖的操作系统接口时，把这些接口（连同其接口闭包）补进接口集合，自动补绑后重跑一遍。
4. 生成包上下文到 `dist/.自动构建/<输出名>/包上下文`（一行一个包：标准库、各内置基础库、各接口绑定包（依赖列出它所依赖的其他接口与其适配依赖的额外库）、库、应用；路径都是规范绝对路径，字段以真制表符分隔）。
5. 按包上下文构建：云工与浏览器模式编出 `程序.wasm`、写出 `值桥.wasm` 并复制宿主外壳（与 `--包上下文` 形式是同一个函数）；节点模式另编文件定位与传输控制两个共享核心，写 `启动.mjs` 与 `清单.json`；原生模式由编译器在最终链接里直出 `<输出目录>/程序。林檎。豫行`（编译器参数 `--目标 本机 --执行器 <构建根>/执行器。树码`，不经 `.wasm`）。原生模式的类型检查沿用普通客体的流程。
6. 装载接口清单（与 `豫构 装载接口 <输出目录> dist/.自动构建/<输出名>/操作系统绑定/<各接口>…` 相同），写入 `接口要求组.json` 与 `宿主提供组.json`。宿主直接提供的接口也有这样一个目录，里面只有接口检查写出的 `规范清单.json` 与 `宿主清单来源.txt`（取支持清单的第三列）；应用提供的接口没有目录（待办事项：浏览器与云工模式尚未核对应用提供的接口）。

**产物与临时文件**：

- `<输出目录>`：先删后建。安全检查：输出目录最后一段不能是空、`.`、`..`；已存在的必须是目录；不能位于 `dist/.自动构建` 内；不能等于构建根、应用目录、任一包根，也不能是它们的上级目录。
- `dist/.自动构建/<输出名>/操作系统绑定/<接口名>/`：接口绑定包，每次构建都重新绑定；按输出名分开，几个应用可以同时构建。放在隐藏目录 `.自动构建` 下，是因为包发现（豫构与接口检查）跳过隐藏目录：接口之间有依赖（如图形显示依赖显示与图形处理器）时，检查后绑定的接口不会同时见到规范包与先绑定好的同名绑定包而报“包短名不唯一”，豫构也不会报“包名冲突”。节点模式的绑定在 `dist/.节点绑定/`。
- `dist/.自动构建/<输出名>/`：生成的 `包上下文`（可用来复查）与 `.txt` 描述时的 `应用/` 副本。云仓与语言仓都已忽略 `/dist/`。

**错误信息**：一律中文并写明原因，以 `豫构 发行失败：` 开头。包括：当前目录不是构建根；缺少工具或文件；应用目录没有或有多个包描述；包描述格式不对（带文件名与病因）；找不到依赖包、有多个候选、名称或所有者不符；接口没有适配；接口检查不过；输出目录不安全；编译器等外部命令失败（带命令行与退出码，编译失败还附编译器输出）。失败时退出码为 1。

**例子**：

```sh
# 云工：云工作台用户目录持久对象（云仓，构建根里，包根用绝对路径）
豫构 发行 云工 $C/应用/豫言云工作台/用户目录应用 dist/云用户目录 --包根 $C/应用/豫言云工作台/库 --包根 $C/库
# 浏览器：包服务阅读页
豫构 发行 浏览器 $C/应用/包管理服务/阅读应用 dist/阅读应用 --包根 $C/应用/包管理服务/库
# 语言仓一致性验证（.txt 描述，无需包根），产物 dist/持久对象壳一致性
豫构 发行 云工 豫言操作系统/宿主/云工/一致性验证/应用/持久对象壳一致性应用 dist/持久对象壳一致性
# 节点发行包（一致性驱动见 豫言操作系统/宿主/节点/一致性验证/）
豫构 发行 节点 豫言操作系统/宿主/节点/一致性验证/应用 dist/节点一致性
```

**须知**：编译缓存目录按编译器 `.wasm` 文件内容的 SHA-256 命名；字节相同的编译器会共享缓存。编译缓存原子写入，绑定按输出名分开，多个构建可以同时进行。清单里的构造编号取自编译器运行时序数，接口检查每次开始时把序数复位到进程起始值，同一进程里检查多个接口时编号与单独运行一致；接口检查一律按 UTF-8 字节序遍历接口文件，原生与诺驿生成的清单相同。已知限制：只支持所有者为「豫言」的包；依赖列表须是平铺名字；接口逐个绑定（不并行）；编译失败时编译器的全部输出原样带回，较长。

**单元测试**（纯函数部分：包描述解析、依赖解析、包上下文生成、接口适配选择、命令行解析）在 `应用/豫构/发行/`，测试名依次是 `文本工具。测试`、`包描述。测试`、`依赖解析。测试`、`上下文生成。测试`、`接口适配。测试`、`自动参数。测试`、`宿主构建。测试`。在语言仓根目录构建并运行，例如：

```sh
豫构 构建 豫构 发行 包描述。测试 --输出 发行包描述测试.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs 发行包描述测试.wasm
```

## 豫行模式

`豫构 发行 豫行` 把应用编成豫行文件（[提案 00021](../../../提案/00021-豫行跨平台运行.汉语.md)）：同一个豫行在豫言操作系统里、在各宿主的豫行启动器里都能运行。适配的选法与原生模式相同（`XXX原生`、`XXX节点`、`XXX`），显示、声音输出与设备接口（查询设备、网卡、声卡，关机、重启）按豫言操作系统由执行器直接提供；编译器参数是 `--目标 本机 --目标系统 豫言 --目标架构 <架构> --执行器 <构建根>/执行器。树码`。

- 产物：ARM64 为 `程序臂。豫行`，AMD64 为 `程序兼。豫行`。没给 `--启动器` 时只编本机架构；给了就编各启动器的架构。
- `--启动器 <文件>`（可重复，只用于豫行模式）：豫行启动器的可执行文件（`豫构 构建 豫言裸机 豫行启动器 …` 编出，Linux 版加 `--目标系统 林纳 --目标架构 臂六十四|兼容六十四`，Windows 版加 `--目标系统 轩窗 --目标架构 兼容六十四`）。按文件头认出宿主（Mach-O 64 位与 ELF 的 ARM64、x86-64，PE 的 x86-64），取同架构的豫行合成单文件 `程序<宿主名>`：`程序林檎臂`、`程序林臂`、`程序林兼`、`程序轩窗兼。林檎。豫行`，并加执行位（宿主是 Windows 时不加）。单文件在该宿主上直接运行，命令行参数全部交给豫行。

```sh
豫构 发行 豫行 <应用目录> dist/某应用 --启动器 豫行启动器。林檎。豫行 --启动器 豫行启动器兼。林纳。豫行
```

## 模拟模式

`豫构 发行 模拟` 把应用连同它的验收脚本编成一个工具宿主程序，在 [模拟宿主](../../../库/沙盘/包说明.汉语.md) 上运行：页面、事件、时钟、随机数与网络都是纯豫言的内存实现，由测试控制，验收整个用豫言书写。

```sh
./豫构。林檎。豫行 发行 模拟 <应用目录> <输出目录> [--入口 <文件名>] [--包根 <目录>]…
node 豫言操作系统/宿主/节点/宿主.cjs <输出目录>/程序.wasm
```

- 入口：`--入口` 给出的文件（相对应用目录）；缺省为应用目录里的 `模拟验收。脚本。豫`，没有时同其他模式（`入口。豫`，再取 `入口。脚本。豫`）。验收脚本放在被测应用自己的目录里（可执行包不能被依赖），用 `寻「应用名」之「入口」之书。` 导入应用，调用 `「入口」之「入口」`；脚本里的应用入口与脚本程序体互不冲突。
- 适配：按 `豫言操作系统/宿主/模拟/宿主支持清单。数据。豫` 选。浏览器侧接口绑到 `XXX模拟` 适配（状态在模拟宿主），网址、网址定位、网址查询绑到本来就不依赖宿主的纯豫言适配（网址通用、网址定位、网址查询）。表里没有的接口构建失败。
- 浏览器宿主：直接依赖浏览器宿主库的应用，构建时由 `库/网览东道沙盘` 顶替（复制到 `dist/.自动构建/<输出名>/浏览器宿主/` 并改名为浏览器宿主），句柄反射、事件、fetch 等原语都落在模拟宿主上。
- 模拟宿主：自动并入包上下文，并加进应用的依赖，验收脚本可直接 `寻观「沙盘」之书。`；应用的包描述不用改。
- 产物：只有 `<输出目录>/程序.wasm`，是普通工具宿主程序，没有 JS 外壳、启动文件与装载清单；不读许可文件。程序按验收结果设退出码（`沙盘报`：有失败时为一）。读页面模板等相对路径以运行时的当前目录为准。
- 可与 `--类型检查` 合用，只对验收脚本做类型检查。

## 给定包上下文

适配目录可用与应用接口同名的普通 `.豫` 文件提供纯豫言回调接线，如 `事务处理。豫` 对应规范的 `事务处理。应用接口。豫`。绑定时优先复制接线并保留应用接口文件名；其余应用接口采用规范声明。持久事务模拟用此机制把事务的引用状态直接传给测试登记的真实应用回调。

手写包上下文的调用者（如云仓构建程序）用 `--包上下文` 直接构建，只用于云工与浏览器模式。第二个位置参数是入口源码；不读包描述、不绑定接口，产物里的 `接口要求组.json` 与 `宿主提供组.json` 先写成待封装（包上下文没有接口绑定时写空列表），调用者另用 `豫构 装载接口` 封装：

```sh
豫构 发行 浏览器 应用/入口。豫 dist/浏览器 --包上下文 包上下文
豫构 发行 云工 应用/入口。豫 dist/云工 --包上下文 包上下文 --许可 许可。数据。豫 --编译器 ./编译器三.wasm
豫构 发行 云工 应用/入口。豫 dist/云工 --包上下文 包上下文 --许可 许可。数据。豫 --命名入口 CloudModel
```

`许可。数据。豫` 是数据文件，顶层「许可们」按绑定种类列出可用名称，每条如 `「许可」【「种类」者『KV』也，「名们」者「列」【『账户缓存』】也】`；豫构发行把它转成产物里的 `许可.json`（如 `{"KV":["账户缓存"],"R2":["项目资源"]}`）交给云工宿主。没写 `--许可`、应用目录里也没有许可文件时不用许可。云工模式产物的 `入口.mjs` 是 Wrangler 的 `main`，同一豫言 Wasm 可由 `fetch` 或 `queue` 事件调用；浏览器模式由页面导入 `入口.mjs` 并调用 `启动豫言浏览器应用()`。编译应用时禁用旧缓存，避免共享工作树中的过期产物；豫构发行不创建 Wrangler 部署配置，也不修改云仓代码。

## 宿主外壳与产物

**命名入口**：`--命名入口` 只用于云工模式，指定一个 ASCII 标识符作为命名 `WorkerEntrypoint` 导出名。上例生成 `CloudModel`，其 `fetch(Request)` 以 `service-fetch` 事件进入同一豫言 Wasm；公开默认入口继续以 `fetch` 事件进入，由豫言分别处理。Wrangler 的 Service binding 可配置 `{"binding":"内部服务","service":"当前Worker名","entrypoint":"CloudModel"}`。Wrangler 4.129.0 本地同 Worker 绑定已验证公开默认路径与内部服务路径分离；非法别名会被拒绝。自定义 RPC 方法、多命名入口和云端部署留待后续版本。[Cloudflare 命名入口文档](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/rpc/#named-entrypoints)说明绑定配置。

浏览器模式还会复制 `自动启动.mjs`。页面直接写 `<script type="module" src="/产物/自动启动.mjs?标识=应用根"></script>` 即可启动，不需另写调用 JS；只有 `id="应用根"` 的元素存在时才加载 Wasm。省略 `标识` 时直接启动。真实 Chrome 已验证存在时执行豫言 Wasm、缺少标识时跳过且不请求 Wasm 文件。`入口.mjs` 的显式启动函数仍可用于需要自行控制生命周期的页面。

浏览器模式还复制 `图形.mjs`：显示、图形处理器与图形显示接口的宿主实现，`宿主.mjs` 第一次调用这些能力时才动态导入它，不用这些能力的应用不会请求它。浏览器发行也复制 `文件能力.mjs` 与 `控制台.mjs`，供宿主按需载入已授目录的文件原语与控制台能力。

云工与浏览器模式都复制 `中央张量.mjs`（张量计算接口中央处理器后端的宿主部分，放在浏览器宿主目录，两种宿主共用；`宿主.mjs` 第一次调用张量原语时才动态导入），浏览器模式另复制 `中央张量工作线程.mjs`（跨源隔离页面的工作线程脚本）。包上下文里有张量计算的绑定包（`操作系统绑定/张量计算/`）时，还编出中央张量内核模块：由包上下文里标准库的路径推出 `库/` 目录，在应用包上下文旁写一份第二版包上下文（`<包上下文>.中央张量内核`：底层库、中央张量内核、中央张量内核模块，都是底层模式），用同一编译器编 `库/底层库/中枢算阵/模块/单线程。底层。豫` 为 `中央张量内核.wasm`；浏览器模式再编 `多线程。底层。豫` 为 `中央张量内核多线程.wasm`；云工模式在 `动态资源.mjs` 末尾加 `export {default as 中央张量内核模块} from './中央张量内核.wasm';`，入口壳据此把内核模块交给宿主（Workers 不能在运行时编译 Wasm 字节）。见[张量计算网页适配](../../../豫言操作系统/适配/张量计算/说明.汉语.md)。

浏览器模式也复制 `工作线程自动启动.mjs`。将 Worker 的豫言程序另构建至页面产物子目录后，页面豫言可用 `浏览器工作线程新建("./子目录/工作线程自动启动.mjs", "{}")` 启动它。外壳在 Dedicated Worker 中加载同目录的 `程序.wasm` 与 `值桥.wasm`；Worker 业务须用豫言写，并调用 `网览工作缕自身柄`、`网览事订阅选`、`待网览事` 及 `网览工作缕向主缕发值`。真实 Chrome 已验证两侧豫言 Wasm 的 ready 与回显往返。

云工模式的 `入口.mjs` 还导出通用 `豫言持久对象` 类，可在 Wrangler 的 Durable Object 绑定和 SQLite `exports` 中引用。类的 fetch、alarm 外层分派由宿主库完成，实际对象逻辑与持久数据读写由同一豫言 Wasm 执行。

云工模式另生成 `动态资源.mjs`：它把宿主库的隔离入口、宿主桥和句柄桥源码以及值桥 Wasm 字节打包给 Dynamic Worker Loader；另附文件式程序的隔离运行入口 `隔离运行客.mjs` 与浏览器编译器宿主 `编译宿主.mjs`（内存文件系统与 `执行模块`），供[隔离运行接口](../../../豫寓榫卯/隔离运行/规范.汉语.md)的云工适配使用。业务只需编译豫言源码；要使用 Loader 时，许可文件需在 `LOADER` 下列出绑定名，并在 Wrangler 中配置 `worker_loaders`。同一 `get` 标识必须使用不变的代码和限额。

**节点发行**：节点模式的发行包有 `程序.wasm`、内联共用模块的 `启动.mjs`、发行清单 `清单.json`，以及纯豫言共享核心 `文件定位共享.wasm` 与 `传输控制共享.wasm`（由同一次发行所选的编译器从客体二号底层入口构建）。启动文件内联共用的 `终端输入.mjs`、控制台能力、文件定位胶水与 FFI 系统胶水；应用宿主提供标准库既有终端原语，并在能力清理时恢复输入模式。应用启动按 `--允许源` 中的地址、端口授权网络操作；监听使用显式来源，连接也可使用发行既有全来源配置。构建终端浏览器时，启动包默认允许全部 HTTP(S) 来源，网页、外链脚本、样式表及重定向无需逐一传入 `--允许源`；其他应用按来源授权。Node 公共控制台正式探针构建、装载及授权读写实测通过；浏览器控制台页面实测留待后续版本。

**用户态系统发行**：仓库目标 `用户态系统节点发行` 把当前命令壳源码与 `应用/豫构/发行/原壳发行/` 里的包描述模板复制到 `dist/.用户态系统节点/应用`，用 `豫构 发行 节点` 绑定控制台、文件、子程序、字体与显示接口，输出 `用户态系统节点发行`，再做发行核对并附上文楷字体与许可；`用户态系统浏览器发行` 同样输出 `用户态系统浏览器发行`。运行 `豫构 目标 用户态系统节点发行 -j 24`；已有自举工具可加 `--不连带`。详见 `应用/豫构/发行/原壳发行/说明.汉语.md`。
