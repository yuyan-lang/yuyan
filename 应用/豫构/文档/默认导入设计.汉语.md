# 默认导入设计

库包在包描述的「类型」里声明必填的「默认导入」，决定只写包名的导入（`寻观「X」之书。`）展开成哪些模块。它取代写死在包定位里的「总集」约定，并让“诵”（重新导出）从语言中退出。字段、语义与检查见[豫构包系统](../包系统.汉语.md)“默认导入”；本篇记录动机、实现位置、迁移指引与待办事项。

状态：2026-10-09 已切换。仓库里每个库包都写明了默认导入；纯门面的总集和其余转出文件已删除；含实现的总集已改名为普通模块并列入默认导入；语言里没有 `诵`、模块别名定义和“模块名与同名定义”的特殊规则；构建工具一律写第五版包上下文。

## 动机

- 「总集」原是 2023 年起的目录门面约定，2026-09-05 起成为解析规则：只写包名的导入取包根的 `总集。豫`。这个名字写死在 `库/构建基础/包定位。豫` 与接口检查工具里，没有属于任何包的声明。
- 总集靠“诵”把别的模块的名字摊平再转出，标准库还要用 `「控制」者「控制」也` 把命名空间重新绑成定义。这些写法让模块看起来像值，而语言没有一等模块。
- 门面与实现混用：约 13 个总集装着几十行到几千行实现。单段导入把总集转出的整棵模块树拉进依赖图，标准库总集的传递依赖是 54 个模块，典型文件实际只用其中 5 个前置模块（闭包 11 个）。

## 设计要点

- 字段在库的「类型」里，必填。值是条目列表，空列表表示没有默认导入，这样的包只能导入具体模块。条目是包内模块路径（用 `/` 分段）或登记的子包名，子包优先于模块，子包条目递归展开。可执行文件包没有这个字段。
- 展开发生在编译器前端：一条导入语句在语法树里仍是一条，`抽象语法分析` 把它转成文件打开（`观`）与文件命名（`寻`）两个伪定义，文件名是多文件名（制表符连接的路径，最前再加一个制表符作记号）；只有一个文件时与单文件导入完全相同。`导入预测` 返回全部叶子文件，供依赖分析。
- 名称解析把多文件名当作一个整体：`名称解析文件投影` 逐文件找第一个有此名的定义；`寻` 与 `观` 的第一次处理时检查条目间不重名（每个进程每个多文件名只查一次），报“默认导入的条目导出了同名定义「名」”。覆盖检查用 `读覆盖模块` 把各文件定义接在一起。
- 包记录第六项是条目列表。构建工具一律写第五版包上下文：第四版加“默认导入”一列。第二至四版没有这一列，读取时从包描述文件里取该字段（构建基础用一个小扫描器读 `「默认导入」者「列」【…】`），云仓与云工作台手写的第二版上下文因此照常可用。
- 包名仍可作限定前缀（`X之名`），因为 `寻` 把 X 绑成对应全部叶子模块的命名空间。条目自己的模块命名空间不额外绑定：要写 `字典术之查` 就显式 `寻「标准库」之「数据结构」之「字典术」之书。`。
- 模块是静态的名字作用域。名字空间只能作 `之` 的底，不能作参数、返回值、类型或数据，也不能被顶层定义重新绑成名字（`「X」者「X」也` 报“命名空间不是一等值”）。解析名字 N 时，先查局部绑定和已打开的文件，最后才看名为 N 的名字空间；空间里有同名定义 N 的特殊规则已删除。
- `观` 只打开已经导入的模块的名字，自己不加载文件；导入并打开用 `寻观`。

## 迁移指引

| 旧写法 | 新写法 |
| --- | --- |
| `观「P」之「总集」之书。`、`寻观「P」之「总集」之书。` | `寻观「P」之书。`（含实现的总集已改名为 `P。豫`，需要这个模块本身时写 `寻观「P」之「P」之书。`） |
| `总集之f`（`寻「P」之「总集」之书。` 绑定的名字空间） | `P之f`（先 `寻「P」之书。`） |
| `寻诵`、`观诵`、`寻观诵`、`诵` | 删去 `诵`：包装模块只保留自己的代码，使用者通过包的默认导入或直接导入具体模块；本文件要用的名字写 `寻观` 或 `观` |
| 一个包的总集转出另一个包的名字（图像处理→图像量化、深度学习框架→深度学习等） | 使用者直接依赖并导入底层包 |
| `「X」者「X」也`（把名字空间重新绑成定义）、依赖“名字空间与同名定义”的写法 | 显式 `寻` 导入模块，用 `X之名` 限定 |
| 标准库：`寻观「标准库」之书。` 之后写 `字典术之f`、`数据结构之字典术之f` | 默认导入只打开 15 个前置模块的名字；写 `寻「标准库」之「数据结构」之「字典术」之书。`，再写 `字典术之f` |
| 标准库：`寻观「标准库」之「豫言标准内核」之书。` 或目录门面 `寻观「标准库」之「数据结构」之书。` | `寻观「标准库」之书。` 或逐模块 `寻观「标准库」之「数据结构」之「字符串术」之书。` |
| 库包描述没有「默认导入」 | 在「类型」里补 `「默认导入」者「列」【…】`；不需要被只写包名导入的包写空列表 `【】` |

## 迁移结果

- 总集转列表：包根总集 114 个，其中纯门面 97 个删除，含实现的 16 个改名为普通模块（如 `总集。豫` 改为 `源码排版。豫`）。
- 非总集的转出文件：60 个，纯门面删除，带代码的去掉 `诵` 并把名字写成 `寻观`。
- 标准库：九个门面（总集、豫言标准内核、七个目录门面）删除，默认导入为 15 个前置模块；用户补显式 `寻` 约 740 行，目录层限定去掉约 160 处。
- 跨包转出：图像处理、深度学习、深度学习框架、静态站，使用者直接导入底层包。
- 数值类型原用 26 个“值别名”选择性转出，现在默认导入整批模块。

## 待办事项

- 接口检查工具（`豫言操作系统/应用/豫言操作系统接口检查`）把单段导入当作单个文件，遇到多项默认导入的接口包要改（现有接口包的默认导入都是空列表）。
- 着色文件与底层文件导入多项默认导入时只做了类型上的支持，没有专门测试。
- 同一个进程里包文件改变后，已检查过的多文件名不会重新检查重名。
- 语言服务还没有给「默认导入」的条目生成跳转。
- 读取旧版包上下文时，包描述里「默认导入」出现在注释中或写成别的形式，扫描器不识别。
