# 仓库包构建

在仓库根目录运行豫构。包名取自 `。包。豫` 文件名，包根就是文件所在目录。配置只调用 parser，不执行代码。依赖声明和用户身份规则见[包系统](../包系统.汉语.md)。

## 目录结构

仓库根目录只有五个目录：

| 目录 | 内容 |
| --- | --- |
| `库/` | 多个应用共用的库，按父库层层排布（如 `库/安全外壳/安全外壳密码`） |
| `应用/` | 可执行程序，按领域分组：`发布/`、`网页汇编/`、`文档站/`、`开发工具/`、`人工智能/`；另有 `豫言编译器/`、`豫构/`、`性能研究/`、`本地模型验收/` |
| `豫言操作系统接口/` | 带垃圾回收的操作系统接口规范 |
| `豫言操作系统底层接口/` | 不带垃圾回收的底层接口规范 |
| `豫言操作系统/` | 操作系统实现：宿主、适配、装载、裸机（`裸机/`），以及操作系统工具（`应用/`） |

规则：

- 库的测试放在该库之下的 `测试/`，如 `库/编译器核心/测试/`。测试若需要被测库以外的依赖，就在该目录另立测试包（如 `库/标准库/测试/` 的「标准库测试」）；测试包依赖被测库，登记在上一级父包之下（见“包层级”）。
- 只被一个应用使用的库放在该应用之下的 `库/`，如 `应用/开发工具/数据库连接/库/工具包`，并登记为该应用的子包；多个应用共用的才放顶层 `库/`。
- WasmGC 客体运行时写在编译器内（`库/编译器核心/编译步骤/代码生成/回收运行时。豫`），编译器直接写出 Wasm 二进制。

## 包层级

全部包用「包含包」「包含在」组成若干棵树，便于按层级浏览。`node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 发现 --树` 打印全部包树：根按目录排列，子包按「包含包」的顺序缩进，每行是包名、目录与简介。层级不改包名与导入，应用仍直接依赖具体的包。

| 根 | 目录 | 子包 |
| --- | --- | --- |
| 共用库 | `库/` | 共用的高级模式库；安全外壳（分组父包，其下四个库与验证程序）；各库 `测试/` 下的测试包 |
| 底层库 | `库/底层库` | 无；底层模式，自成一根 |
| 发布、开发工具、文档站、网页汇编、人工智能 | `应用/` 下同名分组 | 分组内的程序；数据库连接兼作其私有库「工具包」的父包 |
| 豫言编译器 | `应用/豫言编译器` | 测试（语言回归测试）、文例（文档示例） |
| 豫构、性能研究 | `应用/豫构`、`应用/性能研究` | 无 |
| 豫言操作系统适配 | `豫言操作系统/适配` | 全部接口适配，按接口总纲的顺序；基础适配的验收程序 |
| 豫言操作系统工具 | `豫言操作系统/应用` | 操作系统的构建、绑定、装载与检查工具 |
| 豫言裸机 | `豫言操作系统/裸机` | 裸机后端、客体二号及各样例与探针；WASI库 依赖客体二号的内部模块、不能单独构建，自成一根 |
| 豫言操作系统接口 | `豫言操作系统接口/` | 全部接口包，按总纲表序；说明文件即《总纲》 |
| 豫言操作系统底层接口 | `豫言操作系统底层接口/` | 全部底层接口包（底层模式）；说明文件即《总纲》 |

分组父包只有包描述与双语包说明，不含模块，放在分组目录；目录里不属于任何子包的文件（如 `应用/开发工具/yuyan-vscode/`、`应用/文档站/库/文档界面/`）归它所有。

规则：

- 新包放进上表的目录时，须同时在父包「包含包」登记、在新包写「包含在」；两向不一致时豫构报错。
- 子包不能依赖其祖先。测试包依赖被测库，所以登记在被测库的上一级父包，如「标准库测试」在「共用库」下，安全外壳的验证程序在「安全外壳」下。
- 父包与库类型子包须同编译模式：底层模式的库只能挂在底层父包下，所以 `底层库` 自成一根；可执行文件类型的子包不受此限，只作归类。
- 父子关系不跨越云仓复制的目录边界。云仓构建只复制 `库/`、`豫言操作系统/`（不含 `裸机/`）、`豫言操作系统接口/` 与 `应用/` 下的豫言编译器、豫构、文档站、网页汇编，并在其中运行豫构；所以 `应用/` 根与 `豫言操作系统/` 根不设父包，`裸机/` 自成一树。
- 批量发布为单个包做独立构建时，暂存构建树里的包描述会去掉这两个字段，发行源码保持原样。

## 包边界

| 包 | 目录 | 职责 |
| --- | --- | --- |
| 标准库 | 库/标准库 | 语言核心与基础库；不依赖其他包 |
| 标准库测试 | 库/标准库/测试 | 标准库的测试；要用单元测试框架，故独立成包 |
| 单元测试 | 库/单元测试 | 单元测试框架 |
| 癸象工具 | 库/癸象工具 | 癸象（JSON）的数据结构、解析、访问与转义 |
| 网页客户端 | 库/网页客户端 | 纯函数式网页前端组件、文档组件与源码高亮 |
| 云工宿主 | 库/云工宿主 | Cloudflare Workers 宿主能力的豫言封装 |
| 浏览器宿主 | 库/浏览器宿主 | 浏览器宿主能力的豫言封装 |
| 构建基础 | 库/构建基础 | 包定位、上下文、并行调度；不依赖编译器 |
| 编译器核心 | 库/编译器核心 | 语法分析、类型检查、优化、代码生成与着色语言翻译 |
| 包配置 | 库/包配置 | 静态配置解析与包依赖图；使用编译器的 parser |
| 源码排版 | 库/源码排版 | 共享排版库及测试 |
| 着色库 | 库/着色库 | 着色语言的内建声明（着色源导入的类型与函数签名）；不依赖其他包 |
| 着色库测试 | 库/着色库/测试 | 着色语言的翻译测试与构建集成样例；依赖编译器核心，所以独立成包 |
| 豫言编译器 | 应用/豫言编译器 | 编译器；默认入口为入口。豫 |
| 测试 | 应用/豫言编译器/测试 | 语言回归测试：语法、网页汇编、名称解析、缺陷等黄金样例 |
| 文例 | 应用/豫言编译器/文档 | 语言文档及其中的可编译源码示例 |
| 豫构 | 应用/豫构 | 独立构建工具与自身测试；默认入口为入口。豫 |
| 其余工具 | 应用/<分组>/<工具名>、豫言操作系统/应用/<工具名> | 每个工具独立目录、包描述与入口，不再有工具总包 |
| 性能研究 | 应用/性能研究 | 性能实验源码与报告 |

核心依赖顺序为“标准库 → 构建基础／癸象工具 → 编译器核心 → 包配置 → 豫构”（箭头表示先构建者在前）。不能把构建基础放回依赖编译器的包配置或豫构，否则会形成包依赖环。

标准库的测试放在 `库/标准库/测试`（包「标准库测试」），防止标准库反向依赖测试框架。测试包中有预期失败用例，不能将其所有源码一律视为成功构建目标。`*_v0` 不参与迁移。

## 导入

```text
寻观「标准库」之书。
寻观「标准库」之「数据结构」之「多态列」之书。
寻观「构建基础」之「包定位」之书。
```

单段“标准库”固定定位 `库/标准库/总集。豫`，导入后的模块名称仍为“标准库”。所有包遵循同一规则：总集必须手写，不存在就报错，不尝试其他文件，也不按当前目录搜索。内核位于 `标准库/豫言标准内核。豫`。总集与程序入口无关；“诵”的重新导出语义保持不变。

`库`、`应用` 及其下的分组目录是分类目录，分组目录另有父包（见“包层级”）。导入不带分类目录；标准库转发文件及特殊搜索路径已删除。

包还可以用「包含在」「包含包」两个字段成组：父包登记直接子包，子包声明自己的父包。依赖父包即可用 `父之子之模块` 引用其子包中的模块，路径止于子包时取该子包的总集；成组是逻辑关系，不改包名，也与目录嵌套无关。字段、校验与上下文见[包系统](../包系统.汉语.md)。

## 构建与测试

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 目标 豫构
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 目标 类型检查 豫构测试
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 检查 豫言编译器
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 豫言编译器 --输出 yy编译器.wasm
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 源码树浏览器 --输出 yy源码树.wasm
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 文档网站生成器 --输出 yy文档网站.wasm
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 标准库测试 数据结构 可选值。测试 --输出 yy可选值测试.wasm
node 豫言操作系统/宿主/节点/宿主.cjs yy可选值测试.wasm
```

构建、类型检查命令可在包名后指定入口的各路径段；不带扩展名，不重复包名。省略时使用包文件中的入口字段。没有默认入口的库仍可被依赖，也能通过显式入口构建其中的程序。入口覆盖不允许跨越子包边界，不放宽直接依赖要求。

## 自举启动

构建统一由豫构的仓库目标（`应用/豫构/仓库目标。豫`）执行：在仓库根目录运行 `node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 自举|测试|打包|清理|全部 [-j 并发] [--强制] [--不连带] [--列出]`，或用 `… yy豫构.wasm 目标 名…` 运行任意目标。稳定工具来自 CI 发布的 Wasm 工具链包（`historical-binaries` 中的 `<提交时间>-yuyan-wasm-<提交号>.tar.gz`，提交时间取 UTC，形如 `20260930T090727Z`；CI 所用版本的地址与 SHA-256 见 `.github/workflows/main.yml` 的 `YY_WASM_TOOLCHAIN_URL`、`YY_WASM_TOOLCHAIN_SHA256`；最新连续版是 `continuous-binaries` 中的 `yuyan-wasm.tar.gz`），包内有 `yy_bs_stable.wasm`、`yy豫构_stable.wasm` 与 Node 宿主 `yy稳定节点宿主/`。把包解压到仓库根目录后只需 Node：

```sh
node yy稳定节点宿主/宿主.cjs yy豫构_stable.wasm 构建 豫构 --编译器 ./yy_bs_stable.wasm --输出 yy豫构.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 全部 -j 24
```

已有工具链后，可运行 `node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 目标 模拟器冒烟 -j 24`：它重建普通豫言验证器，并在 QEMU 的 ARM64、AMD64 上运行打印探针。2026-09-28 本机用热缓存约 32 秒通过。这是 WP10 快检中的 QEMU 冒烟步骤；按变更范围选测试及完整快检目标仍待接入。

第一步用包中的稳定豫构与编译器以当前源码造出 `yy豫构.wasm`；固定种子默认生成 Wasm，无须指定目标。第二步“全部”从首级起就用稳定豫构构建包，依次生成 `yy2_bs.wasm`、`yy3_bs.wasm`、`yy4_bs.wasm`，比较固定点，再以 `yy4_bs.wasm` 构建正式豫构 `yy豫构.wasm`。不再生成 `yy豫构引导`，也不使用旧单文件启动模式。

更改依赖、包路径或子包边界后，上下文缓存会隔离，不复用旧绑定。此版本不获取远程依赖、不求解版本，也没有锁文件。
