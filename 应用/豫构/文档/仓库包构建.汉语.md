# 仓库包构建

在仓库根目录运行豫构。包名取自 `。包。豫` 文件名，包根就是文件所在目录。配置只调用 parser，不执行代码。依赖声明和用户身份规则见[包系统](../包系统.汉语.md)。

## 目录结构

仓库根目录只有五个目录：

| 目录 | 内容 |
| --- | --- |
| `库/` | 多个应用共用的库，按父库层层排布（如 `库/密壳/安全外壳密码`） |
| `应用/` | 可执行程序，按领域分组：`发布/`、`网页汇编/`、`文档站/`、`开发工具/`、`人工智能/`；另有 `豫言编译器/`、`豫构/`、`性能研究/`、`本地模型验收/` |
| `豫寓榫卯/` | 带垃圾回收的操作系统接口规范 |
| `豫寓底榫卯/` | 不带垃圾回收的底层接口规范 |
| `豫言操作系统/` | 操作系统实现：宿主、适配、装载、裸机（`裸机/`），以及操作系统工具（`应用/`） |

规则：

- 库的测试放在该库之下的 `测试/`，如 `库/译场/测试`。测试若需要被测库以外的依赖，就在该目录另立测试包（如 `库/豫章/测试` 的「豫章试」）；测试包依赖被测库，登记在上一级父包之下（见“包层级”）。
- 只被一个应用使用的库放在该应用之下的 `库/`，如 `应用/百工坊/数据库连接/库/工具包`，并登记为该应用的子包；多个应用共用的才放顶层 `库/`。
- WasmGC 客体运行时写在编译器内（`库/译场/分职/笔受/回收运行时。豫`），编译器直接写出 Wasm 二进制。

## 包层级

全部包用「包含包」「包含在」组成若干棵树，便于按层级浏览。`./yy豫构.exe 发现 --树` 打印全部包树：根按目录排列，子包按「包含包」的顺序缩进，每行是包名、目录与简介。层级不改包名与导入，应用仍直接依赖具体的包。

| 根 | 目录 | 子包 |
| --- | --- | --- |
| 共用库 | `库/` | 共用的高级模式库；安全外壳（分组父包，其下四个库与验证程序）；各库 `测试/` 下的测试包 |
| 底层库 | `库/底层库` | 无；底层文件（`名。底层。豫`），自成一根 |
| 中央张量内核 | `库/底层库/中枢算阵` | 无；底层文件，依赖底层库（不能作其子包，父包的库类型子包是隐含依赖），自成一根；其测试包「中央张量内核测试」是可执行文件类型，登记在共用库之下 |
| 发布、开发工具、文档站、网页汇编、人工智能 | `应用/` 下同名分组 | 分组内的程序；数据库连接兼作其私有库「行囊」的父包 |
| 豫言编译器 | `应用/豫言编译器` | 测试（语言回归测试）、文例（文档示例） |
| 豫构、性能研究 | `应用/豫构`、`应用/度量` | 无 |
| 豫言操作系统适配 | `豫言操作系统/适配` | 全部接口适配，按接口总纲的顺序；基础适配的验收程序 |
| 豫言操作系统工具 | `豫言操作系统/应用` | 操作系统工具与用户态程序（发行构建、接口检查、绑定与装载是豫构的命令） |
| 豫言裸机 | `豫言操作系统/裸机` | 裸机后端、客体二号及各样例与探针；瓦西库 依赖客体二号的内部模块、不能单独构建，自成一根 |
| 豫言操作系统接口 | `豫寓榫卯/` | 全部接口包，按总纲表序；说明文件即《总纲》 |
| 豫言操作系统底层接口 | `豫寓底榫卯/` | 全部底层接口包（`名。底层接口。豫`）；说明文件即《总纲》 |

分组父包只有包描述与双语包说明，不含模块，放在分组目录；目录里不属于任何子包的文件（如 `应用/百工坊/yuyan-vscode`、`应用/书院/库/文档界面`）归它所有。

含 `。包。豫.txt` 包描述模板的目录（如各适配的一致性验证应用）是另行构建的应用：双宿主构建把模板复制成真正的包描述再构建它。这样的目录不算上级包的源码，豫构的整包类型检查与依赖核对都跳过它。

规则：

- 新包放进上表的目录时，须同时在父包「包含包」登记、在新包写「包含在」；两向不一致时豫构报错。
- 子包不能依赖其祖先。测试包依赖被测库，所以登记在被测库的上一级父包，如「豫章试」在「百家」下，安全外壳的验证程序在「密壳」下。
- 编译模式看文件名（见[包系统](../包系统.汉语.md)“编译模式”），包的层级与模式无关；可执行文件类型的子包只作归类。
- 父子关系不跨越云仓复制的目录边界。云仓构建只复制 `库/`、`豫言操作系统/`（不含 `裸机/`）、`豫寓榫卯/` 与 `应用/` 下的豫言编译器、豫构、文档站、网页汇编，并在其中运行豫构；所以 `应用/` 根与 `豫言操作系统/` 根不设父包，`裸机/` 自成一树。
- 批量发布为单个包做独立构建时，暂存构建树里的包描述会去掉这两个字段，发行源码保持原样。

## 包边界

| 包 | 目录 | 职责 |
| --- | --- | --- |
| 标准库 | 库/标准库 | 语言核心与基础库；不依赖其他包 |
| 标准库测试 | 库/豫章/测试 | 标准库的测试；要用单元测试框架，故独立成包 |
| 单元测试 | 库/单元测试 | 单元测试框架 |
| 结森工具 | 库/结森工具 | 结森（JSON）的数据结构、解析、访问与转义 |
| 网页客户端 | 库/网页客户端 | 纯函数式网页前端组件、文档组件与源码高亮 |
| 云工宿主 | 库/云工宿主 | Cloudflare Workers 宿主能力的豫言封装 |
| 浏览器宿主 | 库/浏览器宿主 | 浏览器宿主能力的豫言封装 |
| 构建基础 | 库/构建基础 | 包定位、上下文、并行调度；不依赖编译器 |
| 编译器核心 | 库/编译器核心 | 语法分析、类型检查、优化、代码生成与着色语言翻译 |
| 包配置 | 库/包配置 | 静态配置解析与包依赖图；使用编译器的 parser |
| 源码排版 | 库/源码排版 | 共享排版库及测试 |
| 着色库 | 库/着色库 | 着色语言的内建声明（着色源导入的类型与函数签名）；不依赖其他包 |
| 着色库测试 | 库/点染/测试 | 着色语言的翻译测试与构建集成样例；依赖编译器核心，所以独立成包 |
| 张量内核 | 库/张量内核 | 张量计算接口的 GPU 算子内核（着色源译成 WGSL 与 MSL）、绑定约定与参数打包；依赖标准库、着色库 |
| 张量内核测试 | 库/算阵/测试 | 张量内核在金属上的数值测试与计时；依赖系统库调用、金属与张量内核，没有金属时跳过 |
| 豫言编译器 | 应用/豫言编译器 | 编译器；默认入口为入口。豫 |
| 测试 | 应用/豫言编译器/测试 | 语言回归测试：语法、网页汇编、名称解析、缺陷等黄金样例 |
| 文例 | 应用/豫言编译器/文档 | 语言文档及其中的可编译源码示例 |
| 豫构 | 应用/豫构 | 独立构建工具与自身测试；默认入口为入口。豫 |
| 其余工具 | 应用/<分组>/<工具名>、豫言操作系统/应用/<工具名> | 每个工具独立目录、包描述与入口，不再有工具总包 |
| 性能研究 | 应用/性能研究 | 性能实验源码与报告 |

核心依赖顺序为“标准库 → 构建基础／结森工具 → 编译器核心 → 包配置 → 豫构”（箭头表示先构建者在前）。不能把构建基础放回依赖编译器的包配置或豫构，否则会形成包依赖环。

标准库的测试放在 `库/豫章/测试`（包「豫章试」），防止标准库反向依赖测试框架。测试包中有预期失败用例，不能将其所有源码一律视为成功构建目标。`*_v0` 不参与迁移。

## 导入

```text
寻观「豫章」之书。
寻观「豫章」之「形制」之「次第」之书。
寻观「营造」之「访包」之书。
```

单段“标准库”按标准库的默认导入展开，共 15 个前置模块：语言核心的内建类型、异步原语、引用、异常，数据结构的多态列、多态列工具、字符串术、爻术、整数操作、小数术、可选值、字典术、对子术，控制的惰性求值，输入输出的笔；导入后绑定的命名空间名称是“标准库”。其他标准库模块按路径显式导入。所有库包遵循同一规则：包描述里必填的默认导入列出只写包名的导入所展开的条目，展开只依这份列表，条目都从包根解析，不按当前目录搜索（见[包系统](../包系统.汉语.md)“默认导入”）。

`库`、`应用` 及其下的分组目录是分类目录，分组目录另有父包（见“包层级”）。导入不带分类目录；标准库转发文件及特殊搜索路径已删除。

包还可以用「包含在」「包含包」两个字段成组：父包登记直接子包，子包声明自己的父包。依赖父包即可用 `父之子之模块` 引用其子包中的模块，路径止于子包时按该子包的默认导入展开；成组是逻辑关系，不改包名，也与目录嵌套无关。字段、校验与上下文见[包系统](../包系统.汉语.md)。

## 构建与测试

```sh
./yy豫构.exe 目标 豫构
./yy豫构.exe 目标 类型检查 豫构测试
./yy豫构.exe 检查 豫言编译器
./yy豫构.exe 构建 豫言编译器 --输出 yy编译器.exe
./yy豫构.exe 构建 源码树浏览器 --输出 yy源码树.exe
./yy豫构.exe 构建 文档网站生成器 --输出 yy文档网站.exe
./yy豫构.exe 构建 标准库测试 数据结构 可选值。测试 --输出 yy可选值测试.exe
./yy可选值测试.exe
```

构建、类型检查命令可在包名后指定入口的各路径段；不带扩展名，不重复包名。省略时使用包文件中的入口字段。没有默认入口的库仍可被依赖，也能通过显式入口构建其中的程序。入口覆盖不允许跨越子包边界，不放宽直接依赖要求。

## 自举启动

构建统一由豫构的仓库目标（`应用/豫构/仓库目标。豫`）执行：在仓库根目录运行 `./yy豫构.exe 自举|测试|打包|清理|全部 [-j 并发] [--强制] [--不连带] [--列出]`，或用 `./yy豫构.exe 目标 名…` 运行任意目标。macOS 与 Linux 的稳定工具来自 CI 发布的原生工具链包（`historical-binaries` 中的 `<提交时间>-yuyan-native-<平台>-<提交号>.tar.gz`，平台为 `linux-x64`、`linux-arm64`、`macos-arm64`，提交时间取 UTC，形如 `20260930T090727Z`；CI 自举所用的 Linux x64 包的地址与 SHA-256 见 `.github/workflows/main.yml` 的 `YY_NATIVE_TOOLCHAIN_URL`、`YY_NATIVE_TOOLCHAIN_SHA256`；最新连续版是 `continuous-binaries` 中的 `yuyan-native-<平台>.tar.gz`），包内有原生豫构 `yy豫构_stable.exe` 与执行器汇编树码 `yy执行器。树码`。把包解压到仓库根目录后直接运行：

```sh
./yy豫构_stable.exe 构建 豫构 --输出 yy豫构.exe -j 24 -- --目标 本机 --执行器 yy执行器。树码
./yy豫构.exe 全部 -j 24
```

已有工具链后，可运行 `./yy豫构.exe 目标 模拟器冒烟 -j 24`：它重建普通豫言验证器，并在 QEMU 的 ARM64、AMD64 上运行打印探针。2026-09-28 本机用热缓存约 32 秒通过。这是 WP10 快检中的 QEMU 冒烟步骤；按变更范围选测试及完整快检目标仍待接入。

第一步由包中的稳定豫构配包中的执行器，以当前源码直出一级原生豫构 `yy豫构.exe`。一级驱动是当前源码的代码跑在包里的旧执行器上，所以工具链自身（编译器、豫构）要用执行器新加的原语时，先合入执行器的支持、等 CI 发布新包并改好钉点，再在工具链代码里用。第二步“全部”原生自举：一级是正在运行的原生豫构，二级、三级各用上一级先构建执行器汇编树码（客体二号，只有六十四位地址一种构建），再直出原生豫构 `yy豫构2.exe`、`yy豫构3.exe`，核对二、三级的豫构与执行器逐字节相同（定点），把三级装成日常用的 `yy豫构.exe`、`yy4_bs.exe` 与执行器 `yy执行器。树码`；最后由原生豫构构建网页后端用的 `yy4_bs.wasm`、`yy豫构.wasm` 与值桥。本机冷缓存约五至八分钟，全程只用原生程序。日常用 `./yy豫构.exe 构建|类型检查|目标 …`。仓库目标「原生打包」把原生豫构与执行器打成原生工具链包（`yy原生工具链/`：原生豫构 `yy豫构_stable.exe` 与 `yy执行器。树码`）：CI 的自举作业打 Linux x64 包，各平台原生自举作业用 Linux 上交叉直出的豫构起步，打 Linux arm64 与 macOS arm64 包。推送到 yybs 时，各平台自举通过就覆盖连续版本（`continuous-binaries`）里的本平台包；三个平台都自举通过后，再按提交发布历史版本（`historical-binaries`）。测试失败不挡发布。

Windows 从 Wasm 工具链包起步（Windows 的原生工具链包留待后续版本）：包在 `historical-binaries` 中名为 `<提交时间>-yuyan-wasm-<提交号>.tar.gz`，最新连续版是 `continuous-binaries` 中的 `yuyan-wasm.tar.gz`，内有 `yy_bs_stable.wasm`、`yy豫构_stable.wasm` 与 Node 宿主 `yy稳定节点宿主/`。解压到仓库根目录后用 Node 运行：

```sh
node yy稳定节点宿主/宿主.cjs yy豫构_stable.wasm 构建 豫构 --编译器 ./yy_bs_stable.wasm --输出 yy豫构.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 全部 -j 24
```

**豫行工具链包**（[提案 00021](../../../提案/00021-豫行跨平台运行.汉语.md)）：`./yy豫构.exe 目标 豫行打包 -j 24` 在 `yy豫行工具链/` 里放两架构的豫构豫行（`yy豫构臂。豫行`、`yy豫构兼。豫行`）、四个宿主的豫行启动器（`yy豫行启动器林檎臂`、`yy豫行启动器林臂`、`yy豫行启动器林兼`、`yy豫行启动器轩窗兼.exe`）与执行器汇编树码 `yy执行器。树码`。同一个豫行在豫言操作系统里与各宿主的启动器里都能运行，例如在 macOS 上 `./yy豫行启动器林檎臂 yy豫构臂。豫行 构建 …`。CI 每轮打这个包，在 Linux 两架构与 macOS 上用启动器运行豫构豫行（发现包、构建并运行原生你好的豫行版），在 Windows 上用启动器运行原生你好的 AMD64 豫行版，把 AMD64 豫构豫行合成单文件 `yy豫构.exe`，发现包（输出与 Linux 上原生豫构的逐字对照）、构建原生你好的豫行版（与 Linux 上原生豫构编出的逐字节对照）并以 `-j 4` 类型检查一个库（几个常驻工作进程同时运行），推送 yybs 时上传为连续版本的 `yuyan-yuxing-toolchain.tar.gz`。新检出的仓库也可以从这个包起步：用本机的启动器运行豫构豫行，写明宿主的目标系统与架构直出本机原生豫构，再「全部」，见[《快速开始》](../../豫言编译器/文档/快速开始.汉语.md)。

**启动光盘**：`./yy豫构.exe 目标 启动光盘 -j 24` 连带「造盘工具」，在 `yy启动光盘/` 里放两架构的 BIOS/UEFI 混合启动 ISO `豫言系统-兼容六十四.iso` 与 `豫言系统-臂六十四.iso`（预置为空、带工具链，同 `yy豫言系统 启动盘 --预置 无 --只出光盘`）。这个目标每次都跑，CI 拿它的产物当发行物发布。

**下载产品**：`./yy豫构.exe 目标 下载产品 -j 24` 连带「原生工具链」，在 `yy下载产品/` 里放官网下载中心的编译器包 `编译器-<系统>-<架构>.tar.gz`（豫言、林檎、林纳、轩窗四个系统 × 两种架构；整份源码加交叉构建的豫构、`yy编译器.exe`、`yy4_bs.exe` 与执行器汇编树码）和桌面包 `桌面-<系统>-<架构>.tar.gz`（林檎、林纳、轩窗 × 两种架构；编译器包加豫言工作台 `yy豫言桌面.exe` 与文楷字体）。这个目标每次都跑；社区包仓库的 CI 把它和「启动光盘」的产物挂到连续发行，官网下载中心只链这些发行物。

**可执行包程序**：`./yy豫构.exe 目标 可执行包程序 -j 24` 把 `应用/豫构/仓库目标。豫` 的清单「可执行包程序们」里的可执行包编成各目标的程序，放进 `yy可执行包程序/<目标>/<软件名>`，连同清单 `yy可执行包程序/清单。数据。豫`（数据子语言，顶层「程序们」，每个程序一个记录「程序」，十个字段：软件名、包名、所有者、版本、目标、文件（相对 `yy可执行包程序/`）、沙256（小写十六进制）、字节数、简介、源码提交号；版本是包描述里的版本加 `+` 与 `git rev-parse HEAD` 的前九位）。目标写成“系统-架构”：`豫言-兼容六十四`、`豫言-臂六十四`（豫行，`--目标 本机 --目标系统 豫言 --目标架构 …`，与造盘放进 `/工具` 的工具同一种格式）、`林檎-臂六十四`、`林纳-兼容六十四`、`林纳-臂六十四`；环境变量 `可执行包目标` 选目标（逗号分隔，`全部` 即全部目标），没设时只编 `豫言-兼容六十四`。语言仓 CI 每轮编 AMD64 豫行，用林兼启动器运行你好作冒烟。发布走社区包仓库：语言仓 CI 推送 yybs 后把这些应用复制进 yuyan-lang/yuyan-community-packages 的 `包/豫言/`（作业 community-copy，清单是社区包工具的「社区复制包们」），由社区仓库的 CI 编全部目标、把程序与软件目录发布进包仓库 yuyan-lang.org；豫言操作系统的“安装软件”读全部社区程序的汇总目录 `https://yuyan-lang.org/豫/社区/软件/豫言-兼容六十四。数据。豫`（所有者“豫言”的程序以包名为名称）。清单只收能用 `--目标系统 豫言` 编过、并在豫言操作系统里装上后能运行的应用；发布新软件时在这份清单与「社区复制包们」里各加一项。

第一步用包中的稳定豫构与编译器以当前源码造出 `yy豫构.wasm`；固定种子默认生成 Wasm，无须指定目标。“全部”在 Windows 上走 Wasm 自举（`yy2_bs.wasm` → `yy3_bs.wasm` → `yy4_bs.wasm`，比较三、四级定点）。在 macOS 与 Linux 上从 Wasm 包起步时，“全部”先由「原生起步」在 Node 上用当前源码的 `yy豫构.wasm`（自带编译器）构建六十四位执行器汇编树码并直出一级原生豫构，再照上文原生自举；CI 按提交号抽样约四分之一的轮次（手动触发时必跑），在三个平台上验证这条路。不再生成 `yy豫构引导`，也不使用旧单文件启动模式。

更改依赖、包路径或子包边界后，上下文缓存会隔离，不复用旧绑定。此版本不获取远程依赖、不求解版本，也没有锁文件。
