# 豫构

发现软件包、解析依赖并调度编译；构建云工、浏览器、节点、原生与豫行发行物；运行语言仓的仓库目标。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为可执行文件类型，不可被其他包依赖；包内模块仍可互相引用。类型典中的入口和文件名见包配置，程序产物为 `yy豫构`。

## 使用

在仓库根目录运行：

```sh
./yy豫构.exe 检查 豫构
./yy豫构.exe 构建 豫构
./yy豫构.exe 发现 --树
```

最后一条按层级（「包含包」／「包含在」）打印全部包树，用来浏览仓库里的包。

## 运行脚本

`豫构 运行 路径 参数…` 把一个 `。脚本。豫`（或任何 `。豫` 程序文件）连同它依赖的模块编成装载单元（提案 00003），装进豫构自己的进程运行：

```sh
./yy豫构.exe 运行 应用/豫构/脚本样例/例一。脚本。豫 甲 乙
```

- 脚本看到的程序名是脚本路径，命令行参数是路径之后的参数（原样交给脚本，不当作豫构选项）。
- 包与仓库根按脚本所在位置找：仓库根依次从脚本所在目录、当前目录、豫构所在目录往上找（含 `库/标准库` 的目录），再看豫构旁边的 `源`（日用发行）与 `/源`（豫言操作系统的工具链盘）；构建期间切到仓库根，运行脚本前切回原来的当前目录。不属于任何包的脚本（如 `/数据/甲。脚本。豫`）拷进自动生成的包「脚本运行」（`.yybuild/脚本外部包/豫言/脚本运行/`，依赖标准库与壳命令）再编译，程序名仍是原路径，改了原文件下次运行会重编。
- 单元放在当前目录 `.yybuild/单元运行/` 下按脚本绝对路径排的目录里，目录里的 `印记.txt` 记着豫构、单元目标、执行器与各模块源文件的摘要；印记相同就不再调用编译器，直接装入，打印探针这样的脚本整个运行约 30 毫秒。要重新编译时编译器只为改过的模块生成原生单元，其余从 `.yybuild/单元缓存/` 按内容取用。
- 设环境变量 `豫构运行计时` 时在标准错误打印构建与装入运行各用的毫秒数。
- 脚本首行可以写 `#!/usr/bin/env -S yy豫构 运行`（`yy豫构` 在 PATH 里时），编译器把首行当作空白；`应用/豫构/脚本样例/首行。脚本。豫` 是例子。
- macOS ARM64 的原生豫构把原生单元装进自己的进程，豫构旁须有执行器 `yy执行器。树码`（或 `yy执行器.wasm`）。诺驿（`node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 运行 …`）、轩窗与 Linux 上编成网页汇编单元（放在 `.yybuild/单元运行诺驿/` 下，目录里的 `程序名.txt` 记脚本路径），由诺驿宿主另起子进程装入运行，脚本的退出码就是命令的退出码；缓存命中时约 0.2 秒。豫言操作系统两架构里同样装入原生单元：开机的豫构与盘上的 `/工具/yy豫构` 都能运行脚本（造盘时加 `--工具链`）。`应用/豫构/脚本样例/` 里是提案例一至例三的宿主版，两种运行方式输出相同。

## 交互

`豫构 交互` 逐句读入豫言并运行（提案 00003 第 3 步）：

```text
壳> 「文件」之「列出」于『应用/豫构』
入口。豫
…
壳> 「源」者『应用/豫构/脚本样例』也
壳> 「文件系统」之「读文件夹」于「源」
「列」【『例一。脚本。豫』，…】
壳> 「加」于「12」于「30」
「42」
```

- 会话开头相当于已写了 `寻观「标准库」之书。寻观「壳命令」之书。寻「壳命令」之「文件」之书。寻「壳命令」之「实现」之书。寻「标准库」之「操作系统」之「文件系统」之书。寻「标准库」之「操作系统」之「命令行参数」之书。`（宿主与豫言操作系统相同）：[壳命令](../../库/诏令/包说明.汉语.md)（如 `「文件」之「列出」于『/』`、`「运行」于『/bin/echo』于「列」【『甲』】`）与标准库直接可用。一行里的句子都闭合时依次处理，行末的句号可以省略；没闭合时印续行提示 `…> ` 接着读。`「名」乃…` 与随后的同名定义合成一组。
- 每句（含壳命令）都编成组单元运行，不设快路；只有用户输入才编译（2026-10-14 用户定）。会话做法（「实现」之「登记会话做法」）在装入前导单元时登记，请求文件、编译器与异常标志作为单元的命令行参数传入，会话开头不编译。豫言操作系统里的壳命令做法分部按需装入：每编一句之前，句中用到哪些部（见 [用户态桌面](../../库/几席/包说明.汉语.md) 的 `部居`），就装入这些部造盘时预编好的单元并运行登记脚本，开机壳、桌面终端与远程登录的会话相同。会话开头依次执行开头句（开机壳给开机自启的各句；`豫构 交互 --开头句 句` 给命令行上的各句，2026-10-14 起桌面终端把用户输入的第一行这样交给新会话）。开头句与读到的行一样先切成句子，一行可以有几句或只有注释。
- 每组在豫构进程里编译（语法分析、名称解析、类型检查、闭包转换），生成原生单元后装入运行；前面各组的定义在后面的组里可用，后定义遮住前定义。一组导入了还没装进来的模块时，先把这些模块编成单元装进来。
- 命令脚本：`「脚本」于『路径.txt』` 把文件的每一行当作交互的一句处理，先印 `+ 行`，出错继续；只有空白与注释的行跳过；`「脚本」于『甲。脚本。豫』` 交给 `豫构 运行`。
- 最后一句是裸式时按类型印值：整数与小数印成 `「…」`，字符串 `『…』`，爻 `「阳」` `「阴」`，列 `「列」【…】`，元组 `（… 与 …）`，无参函数印它的结果；类型为「有」的句子只运行。
- 编译出错或有异常没接住时，打印诊断并丢弃这一组，会话继续；读到输入末尾结束，退出码是最后一句出错为 1、否则为 0。输入分两种，命令行可指定（2026-10-16 用户定）：`豫构 交互 --组字` 是交互输入，逐键编辑，有输入法（拼音组字）、候选、补全与历史，用壳核心的「闻言」，与开机壳是同一个编辑器（读行时终端在原始模式，读完恢复；空行上按 Ctrl+D 结束会话，Ctrl+C 放弃正在输入的行）；`豫构 交互 --直读` 是非交互输入，原样按行读入，不经输入法与补全（豫言操作系统开机控制台上用壳核心的「直闻」逐键读，等键时照办子任务的消息与「图形」请求）。都不写时标准输入是终端（且没有 `--提示`）就组字，否则直读。宿主原生、豫行启动器与豫言操作系统里相同。`--编译器 路径` 另指编译器（缺省是豫构自己，执行器取编译器旁边的 `yy执行器。树码`）；`--先装前导` 在前导单元已经编好时一起来就装入（没编好不装，留到第一句）。直读时标准输入是终端才印提示符 `壳> `；`豫构 交互 --提示` 每行之前都印（桌面终端与远程登录把会话开在管道上，见提示符就知道上一句办完了）。`豫构 交互 --预装` 一起来就装入前导单元（不印装入提示），开头句办完、第一次读行之前印一行 `豫构交互：备用会话已就绪`；远程登录预先起一个这样的备用会话，exec 来了直接接手。
- 会话的源文件写在仓库根的 `.yybuild/交互外部包/豫言/交互会话/` 下；仓库根先看豫构旁边的 `源` 目录（日用发行：单文件旁放一份源码树，在哪个目录起都用它，前导只编一次），再从当前目录往上找，找不到再从豫构所在目录往上找，都找不到时什么句子都运行不了（豫言操作系统里仓库根是 `/源`）。第一句（或预装）时准备会话包与前导单元；会话目录 `会话<纳秒><随机后缀>/` 里放各组的源文件、请求文件与异常标志。原生豫构（macOS ARM64、Linux x86-64、豫言操作系统两架构）与豫行启动器（macOS、Linux 两架构）里的豫构豫行上编成原生单元。单元目录的印记与单元缓存的键里记着单元的目标系统与架构，启动器里的豫构豫行与原生豫构共用一个仓库时互不误用。每句约 50 毫秒（实测见提案 00003 实施记录）。
- 预编前导：`豫构 预编前导 仓根 [-- 编译器参数…]` 照交互第一次编译时的做法，为仓根下的交互会话备好会话包与前导单元（编译器是豫构自己，执行器是它旁边的 `yy执行器。树码`），单元与编译缓存留在仓根与编译器目录的 `.yybuild` 里；`--` 之后的参数接在单元参数之后交给编译器（如 `--目标系统 豫言 --目标架构 臂六十四`）。豫言系统造盘时在宿主上以照盘内摆好的树为虚根（客体二号的环境变量 `豫言根目录`）运行它，把结果放进盘。

## 开机程序

`开机。豫` 是豫言操作系统的开机程序入口（提案 00003 第 8 步）：造两架构启动盘时，豫言系统把它编成开机程序，开机就进豫构的交互模式（做法在 `开机壳。豫`）。文件与环境命令照库 用户态桌面 的命令壳（已授“桌面”根下的路径、.环境），「运行」「构建启动盘」同步运行子程序，「图形」进入桌面，「退出」结束。全系统只有一个壳（2026-10-16）：开机壳与宿主、桌面终端、远程登录一样经「交互命令」进会话，输入方式也由交互参数选：`/系统/开机。数据。豫` 的「交互参数」（如 `「交互参数」者「列」【『--直读』】也。`），没有这个文件或这一项时为 `--组字`（逐键编辑：拼音组字、候选、补全、历史，Ctrl-C 放弃这一行）；`--直读` 原样按行读入，串口脚本整行送进来不经拼音。每句都用盘上的 `/工具/yy豫构`、`/工具/yy执行器。树码` 与源码树 `/源` 编译，编译缓存的程序标识取 `/工具/yy豫构.摘要`，与盘上的豫构共用缓存；造盘缺省带工具链，盘上没有工具链时什么句子都运行不了。开机自启（`/系统/开机自启`）的各句当会话的开头句（`--开头句`）编译执行；「图形」写下进入桌面的请求（见库 用户态桌面 的壳请求），读下一行之前与等键的空当在这里进入桌面。造盘时已预编前导单元（单元目录印记与盘上的相符）时，开机就把前导单元装进来再读第一句（`--先装前导`），第一句不再等编译与装载。带参数运行时就是普通的豫构。

## 发行

`豫构 发行` 把应用连同它用到的操作系统接口构建成能在云工、浏览器、节点或原生宿主上直接运行的发行物：读包描述、解析依赖、按宿主选适配并绑定、生成包上下文、编译、复制宿主外壳、封装接口清单，一条命令完成；编译器缺省用豫构自己。`豫构 接口检查`、`豫构 接口绑定` 与 `豫构 装载接口` 单独提供其中的接口检查、绑定与清单封装。源码在 `发行/`，用法见 [发行](文档/发行.汉语.md)、[接口检查](文档/接口检查.汉语.md)、[接口绑定](文档/接口绑定.汉语.md)、[装载接口](文档/装载接口.汉语.md)。

```sh
./yy豫构.exe 发行 节点 豫言操作系统/宿主/节点/一致性验证/应用 dist/节点一致性
```

在 macOS 与 Linux 上跑过仓库目标「全部」后，还有原生豫构 `./yy豫构.exe`：命令与上面相同（如 `./yy豫构.exe 构建 豫构`），比 Node 版快，是日常构建的默认工具。豫构带着编译器（提案 00007 合一，见库 编译器入口）：没写 `--编译器` 时用自己当编译器，并行编译的工作进程也是同一个程序文件；首个参数是源文件、`stage`、`debug`、`--mode=…` 或 `--原生产物子进程` 时，豫构按编译器运行。原生豫构启动的 `.wasm` 子程序改经 node 运行。

默认产物（提案 00007 议一）：在 macOS、Linux 与豫言操作系统上，编译器旁有执行器 `yy执行器。树码`（仓库目标「全部」经「执行器」生成；豫言操作系统里是 AMD64 数据盘的 `/工具/yy执行器。树码`）时，`构建` 与 `文件` 默认产出本机原生可执行文件（macOS 为 Mach-O，Linux 为 ELF，豫言操作系统为豫行文件），由编译器在最终链接里直出，不经 `.wasm`：豫构给编译器加 `--目标 本机 --执行器 yy执行器。树码 --降级缓存 .yybuild/降级缓存/产物名.机器片`（传的是绝对路径：执行器取编译器所在目录里的，降级缓存放在当前目录下；编译器在自己的目录下运行）。`--输出` 以 `.wasm` 结尾时产出 `.wasm`，以 `。树码` 结尾时产出汇编树码；没写 `--输出` 时产物名是包的程序名加本机系统的后缀：macOS 加 `。林檎。豫行`，Linux 加 `。林纳。豫行`，豫言操作系统里产出豫行文件，不加后缀。编译器参数里已写 `--目标` 时豫构不再添加；交叉目标（`--目标系统`、`--目标架构`）与底层程序的写法见[编译器包说明](../豫言编译器/包说明.汉语.md)“原生产物”。Windows 与找不到执行器时仍产出 `.wasm`。

依赖及说明路径以 [包配置](豫构。包。豫) 为准。构建不会自动运行程序；有发布或服务副作用的工具应先阅读其入口源码。

## 构建日志

构建类命令（构建、类型检查、文件与仓库目标）每次在当前目录的 `.yy构建日志/运行/` 下新建一次运行，记下命令、提交、负载、包发现与包图等区间的用时；它启动的嵌套豫构与编译器经环境变量加入同一次运行，各写一份事件文件。`YY_BUILD_LOG=0` 关闭，`YY_BUILD_LOG_DIR` 改根目录，`YY_BUILD_LOG_TAG` 贴标签。格式见[构建日志格式](../性能研究/构建性能/日志格式.汉语.md)，分析用 `yy构建性能`。

## 维护

修改接口时更新本说明；修改包身份、版本或构建组成时同步更新包配置。说明文件不参与模块导入。

值桥目标同步构建纯豫言文件定位共核，工具链打包把 `yy文件定位共享.wasm` 放在稳定节点宿主旁，供正式定位读取接线复用。
