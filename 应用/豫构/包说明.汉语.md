# 豫构

发现软件包、解析依赖并调度编译；构建云工、浏览器、节点、原生与豫行发行物；运行语言仓的仓库目标。

整包类型检查收集包内的实现、测试与脚本入口。普通签名与底层签名随配对实现参与接口检查，数据文件随导入方检查。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为可执行文件类型，不可被其他包依赖；包内模块仍可互相引用。类型典中的入口和文件名见包配置，程序产物为 `豫构`。

## 使用

在仓库根目录运行：

```sh
./豫构。林檎。豫行 检查 豫构
./豫构。林檎。豫行 构建 豫构
./豫构。林檎。豫行 发现 --树
```

最后一条按层级（「包含包」／「包含在」）打印全部包树，用来浏览仓库里的包。

命令名与参数个数先照子命令参数表（入口篇的「命令参数表」）核对、不合就立刻报错，之后才发现包：错命令不必扫当前目录（议题 #661；在 `/tmp` 下原要等三四分钟）。发现包时跳过隐藏目录、`_v0`、`node_modules` 与编译缓存根（`豫构缓存-*`），见构建基础（营造）包说明。

## 整包类型检查

`豫构 类型检查 <包>` 不以构建范围为限：包内全部普通源文（包根平铺、`测试/` 下的测试入口与各 `。脚本。豫`）一次交给编译器，各篇都作入口验类；库包与可执行文件包、默认导入有无、命令行给不给入口段一律照此。子语言源文按后缀分开处理：豫汇源文（`名。网页汇编。豫`）交「析中文网汇篇」只解析与验证、不运行；签名文件（`名。签名。豫`、`名。底层签名。豫`）随同目录同名的实现文件核对，不单独编；数据文件随导入方检查；着色器、设计源与底层文件照旧作入口，由编译器按文件名定编译模式。模拟应用（包里有 `模拟验收。脚本。豫`）的脚本（`。脚本。豫`）用与 `豫构 发行 模拟` 同一份上下文检查：就地跑同一套自动构建，补上沙盘、芥子与模拟适配器的绑定，包里不必为验收声明这些依赖；当前目录不是模拟构建根（缺 `库/豫章`、`库/结绳`、`库/沙盘` 或 `库/网览东道沙盘`）时印出缘由跳过。查完印出所查源文篇数，并按非零的类别补出豫汇源文、签名文件与模拟验收脚本的篇数，跳过什么、为什么跳过都写在这一行里（议题 1072）。

适配包（目录里有 `实现榫卯。豫`，如 `豫言操作系统/适配/` 下的各包）单独类检时缺的是发行期才由宿主绑定补进来的名字。整包检查先按它在 `豫言操作系统/宿主/<模式>/宿主支持清单。数据。豫` 里登记的模式，用与发行同一套接口检查与接口绑定，把包图闭包中的接口绑进 `<源码树根>/dist/.整包绑定/<模式>/`，再照常检查；绑定只出自接口检查与接口绑定这一处，不另抄名字表。未在任何清单登记的专用适配（如金匮、内府）不补绑定并印出缘由；名字以“原生”结尾的适配按普通构建的原生绑定补。普通构建与整包检查各用各的绑定根，按模式绑出来的实现不会盖掉原生适配（议题 1072）。

## 语言服务资料

`豫构 语言服务 源文件` 按译场的「讯储读径」取这个源文件的语言服务资料：先按所属包的包索引编出并启用包上下文（与「类型检查」用的是同一份编码），再按旁记找产物——产物在共享缓存的物库里时读 `物/<摘要前二>/<摘要>。树码`，产物留在本树时读本树的缓存文件；读出后按编辑器树码解成结绳，印到标准输出（一行结绳文字）。资料不在时先按「类型检查」的办法把这份源文验类一遍再取；仍不在时报出文件与它应在的缓存位置。

缓存布局由译场一处解析，豫构入口只调用译场的取径函数；编辑器扩展等外部工具都经这条子命令取资料，布局再变时照常取到。

## 构建产物

`豫构 产物 源文件` 列出这个源文件各阶段缓存的阶段名、实际路径与在不在，印成一行结绳文字。它先按所属包的包索引编出并启用包上下文（与「类型检查」「语言服务」用的是同一份编码），阶段名照译场的「阶段名们」逐项取，实际路径一律经译场的「讯储读径」解析：产物在共享缓存的物库里时得到 `物/<摘要前二>/<摘要>。树码`，产物留在本树时得到本树的缓存文件。输出是 `{"源文件":…,"包上下文":…,"阶段产物":[{"阶段":…,"路径":…,"在":…},…]}`，阶段按流水次序排列。包上下文是豫构写出的上下文文件路径，编辑器读树码时把它交给 `树码` 的 `--包上下文`。

缓存布局由译场一处解析，豫构入口只调用译场的取径函数；这条子命令只列已写出的产物，构建或类型检查之后再用。

## 运行脚本

`豫构 运行 路径 参数…` 把一个 `。脚本。豫`（或任何 `。豫` 程序文件）连同它依赖的模块编成装载单元（提案 00003），装进豫构自己的进程运行：

```sh
./豫构。林檎。豫行 运行 应用/豫构/脚本样例/例一。脚本。豫 甲 乙
```

- 脚本看到的程序名是脚本路径，命令行参数是路径之后的参数（原样交给脚本，不当作豫构选项）。脚本路径之前可以写四个选项：`--只编`（只编出装载单元，不装不跑，退出码就是构建的状态）、`--目标系统 名`、`--目标架构 名`（照此出单元，见单元的目标）与 `--执行器 路径`（用这一份执行器出原生单元）。整客远行时构建由豫构派出的编译器子进程做，交役照它自己的命令行把执行器送到对方、把单元目录（`-o`）登记成要送回的一个产物，并按客端的系统与架构补进对方的命令行（见营造包说明的交役）；对方把目录展成文件逐个送回，回来与本机编的一样按本机的根找到源文件。构建成功之后先核单元齐不齐、是不是这次构建写的（见单元产物验），不齐就报错退出，不写印记、也不跑旧单元（议题 #698）。
- 包与仓库根按脚本所在位置找：仓库根依次从脚本所在目录、当前目录、豫构所在目录往上找（含 `库/豫章` 的目录），再看豫构旁边的 `源`（日用发行）与 `/源`（豫言操作系统的工具链盘）；每一级与每个候选都用 `探有` 问，落在附庸表外的算没有、执行器不印表外提示（2026-10-26，议题 812）。构建期间切到仓库根，运行脚本前切回原来的当前目录。豫构经符号链接调用时按真径认自己（程序名取真实路径），程序名是相对路径时先按当前目录补成绝对路径，取不到真实路径时退回这条补全后的路径，得到的一律是绝对路径（议题 352、#527）；它旁边的执行器、源与仓根照此找，链接可以放在别的目录。不属于任何包的脚本（如 `/数据/甲。脚本。豫`）拷进自动生成的包「脚本运行」（`.豫构缓存/脚本外部包/豫言/脚本运行/`，依赖标准库与壳命令）再编译，程序名仍是原路径，改了原文件下次运行会重编。
- 单元放在当前目录 `.豫构缓存/单元运行/` 下按脚本绝对路径排的目录里（脚本路径去掉 `。豫` 后缀后经译场 分职 译主 译程具 的「储镜」换成接得进目录名的写法：macOS、Linux 上原样、目录与从前逐字相同，Windows 上盘符冒号、反斜线与网络共享路径冠 `境外/` 一段避开，2026-10-27，钩轩窗交互三，同议题 #937），目录里的 `印记.txt` 记着编译语义号、单元目标、单元的布局、执行器与各模块源文件的摘要（布局是相对址式或绝对址式，见下条）；印记相同就不再调用编译器，直接装入，打印探针这样的脚本整个运行约 30 毫秒。要重新编译时编译器只为改过的模块生成原生单元，其余从 `.豫构缓存/单元缓存/` 按内容取用。
- 设环境变量 `豫构运行计时` 时在标准错误打印构建与装入运行各用的毫秒数。
- 路径以“豫行”结尾时当作清单豫行（提案 00038 第一步，格式见《豫行格式》“清单豫行”）：不编译，按段的次序把各单元装进本进程运行，程序名是这个路径；清单里的单元是网页汇编单元时（不能装原生单元的宿主上用 `--清单` 构建所出）改由诺驿宿主另起子进程运行：把各单元写到当前目录的 `.豫构缓存/清单运行/<清单末名>/` 下，写“顺序.txt”与“程序名.txt”，程序名与命令行参数照传，退出码照传；找不到 `node` 或诺驿宿主脚本时报“本宿主需要诺驿才能运行清单豫行”。清单豫行由 `豫构 构建 包 --清单 --输出 名。清单。豫行` 写出（`豫构 文件 路径 --清单 --输出 名` 对单文件入口同样可以）：先照「运行」的办法以单元目标编出单元目录（当前目录的 `.豫构缓存/清单/<输出的末名>`），再按装入次序打包；单元的目标照 `--` 之后的 `--目标系统`、`--目标架构`，没给取本机。入口是底层文件（底层程序）时在开头报“底层程序不支持 --清单”，不建清单：底层程序只直出整程序（本机原生程序或 `.wasm` 模块），没有可装入的装载单元（议题 241）。能装原生单元的豫构（macOS ARM64、Linux x86-64 与 Windows x86-64 的原生豫构与豫言操作系统里的豫构）编原生单元、也运行原生单元的清单；不能装的宿主（诺驿、浏览器与 Linux ARM64）编网页汇编单元。清单豫行也可以写成引用式：`豫构 构建 包 --引用清单 --输出 名。清单。豫行`（`文件` 命令同样可用） 把各单元按内容摘要存进共享缓存根下的 `单元/`（同摘要只存一份，文件名是摘要的小写十六进制加 `。单元`），清单里每个单元只留三十二字节摘要；`豫构 运行` 按摘要取单元、重算沙二五六核对，仓库里缺单元或摘要不符时报出摘要与路径。内嵌式清单照常能读，运行引用式清单要与构建用同一个共享缓存根。原生单元的清单在装入任何单元之前先汇总全部单元导入的宿主函数，有本平台未具的（提案 00040）就一次列出、不予运行；设了环境变量 `豫言所供=关` 则只报不拒。脚本与单元装入时同样核对。单元按模块分给几个工作进程并行生成（议题 255）：父进程先算好常祸理定义、入口函数调用与去装箱签名表写进单元目录的 `计划.txt`，再起分片工作进程（各带 `--单元分片 起 止`，只读自己那份闭包形式，写完一个单元就放掉它），片数取环境变量 `豫言单元分片数`，没设时取处理器核数、至多八，豫言操作系统里不并行。分片按估重切：先看单元目录里上次构建留下的 `单元序号.单元` 的大小（原生单元生成的重活都在这里），没有就看单元目录旁的耗时文件 `<单元目录>.耗时.txt`（上次各单元的生成耗时），都没有就看闭包形式缓存文件的字节数；估重不小于一片平均量的模块单独成一片，余下的按估重均分。装入清单时按段次序逐个取出单元装入（内嵌式用「清单单元于」、引用式按摘要逐个从单元仓库取），不为汇总缺项一次取出全部单元；单元字节与模块概况装完即弃，常驻内存只剩装入状态与机器码。
- `豫构 运行 --授 案牍,驿 名。清单。豫行 参数…` 是受限清单（提案 00038 第二步）：先读完清单，核对附录种类二记的所需之节都已授予、附录种类三不含底层单元（受限清单不收底层单元），再取出各单元（引用式清单按摘要从单元仓库取，取单元要读文件，所以在收节之前办），然后用执行器的「收节」把本进程的能力掩码收窄到所列的节，最后装入单元运行。清单所需之节由构建时逐个单元看它的重定位（调用宿主导入的调用点与调用执行器函数的跳板）、相或而来，声明了却没调用的宿主函数不计，接口文件编成的声明壳单元略去，记进附录种类二；内嵌式与引用式清单都记附录种类二、三。节名以逗号分隔：案牍（文件）、使者（子进程）、驿（网络）、水土（环境变量）；节名不认识时报错。不给 `--授` 时按全节运行，行为与以前相同。旧清单没有种类二、三时按不要求任何节、不含底层办；网页汇编的豫构构建的清单没有「单元带型码」可问，附录种类二记四二九四九六七二九五（四字节全一）表示没记，受限运行遇到它就拒收，请用原生豫构重编清单。
- 脚本首行可以写 `#!/usr/bin/env -S 豫构 运行`（`豫构` 在 PATH 里时），编译器把首行当作空白；`应用/豫构/脚本样例/首行。脚本。豫` 是例子。
- macOS ARM64、Linux x86-64 与 Windows x86-64 的原生豫构把原生单元装进自己的进程，豫构旁须有执行器 `执行器。树码`（或 `执行器.wasm`；新版豫构自带执行器，见下节）。诺驿（`node 豫言操作系统/宿主/节点/宿主.cjs 豫构.wasm 运行 …`）与 Linux ARM64 上编成网页汇编单元（放在 `.豫构缓存/单元运行诺驿/` 下，目录里的 `程序名.txt` 记脚本路径），由诺驿宿主另起子进程装入运行，脚本的退出码就是命令的退出码；缓存命中时约 0.2 秒。豫言操作系统两架构里同样装入原生单元：开机的豫构与盘上的 `/工具/豫构。豫行` 都能运行脚本（造盘时加 `--工具链`）。`应用/豫构/脚本样例/` 里是提案例一至例三的宿主版，两种运行方式输出相同。

## 交互

`豫构 交互` 逐句读入豫言并运行（提案 00003 第 3 步）：

```text
壳> 「案牍」之「列目」于『应用/豫构』
入口。豫
…
壳> 「源」者『应用/豫构/脚本样例』也
壳> 「藏书」之「列目」于「源」
「列」【『例一。脚本。豫』，…】
壳> 「加」于「12」于「30」
「42」
```

- 会话开头相当于已写了 `寻观「豫章」之「形制」之「分厘」之书。寻观「豫章」之书。寻观「诏令」之书。寻「诏令」之「案牍」之书。寻「诏令」之「实现」之书。寻「豫章」之「寓所」之「藏书」之书。寻「豫章」之「寓所」之「号令」之书。`（宿主与豫言操作系统相同；分厘写在豫章之前，裸式印小数用的「述小数」由它来，豫章的整数加、减、乘、除以仍遮住分厘里同名的）：[壳命令](../../库/诏令/包说明.汉语.md)（如 `「案牍」之「列目」于『/』`、`「行」于『/bin/echo』于「列」【『甲』】`）与标准库直接可用。一行里的句子都闭合时依次处理，行末的句号可以省略；没闭合时印续行提示 `…> ` 接着读。`「名」乃…` 与随后的同名定义合成一组。
- 每句（含壳命令）都编成组单元运行，不设快路；只有用户输入才编译（2026-10-14 用户定）。会话做法（「实现」之「登会话做法」）在装入前导单元时登记，请求文件、编译器与异常标志作为单元的命令行参数传入，会话开头不编译。豫言操作系统里的壳命令做法分部按需装入：每编一句之前，句中用到哪些部（见 [用户态桌面](../../库/几席/包说明.汉语.md) 的 `部居`），就装入这些部造盘时预编好的单元并运行登记脚本，开机壳、桌面终端与远程登录的会话相同。会话开头依次执行开头句（开机壳给开机自启的各句；`豫构 交互 --开头句 句` 给命令行上的各句，2026-10-14 起桌面终端把用户输入的第一行这样交给新会话）。开头句与读到的行一样先切成句子，一行可以有几句或只有注释。
- 每组在豫构进程里编译（语法分析、名称解析、类型检查、闭包转换），生成原生单元后装入运行；前面各组的定义在后面的组里可用，后定义遮住前定义。一组导入了还没装进来的模块时，先把这些模块编成单元装进来。
- 命令脚本：`「脚本」于『路径.txt』` 把文件的每一行当作交互的一句处理，先印 `+ 行`，出错继续；只有空白与注释的行跳过；`「脚本」于『甲。脚本。豫』` 交给 `豫构 运行`。
- 最后一句是裸式时按类型印值：整数与小数印成 `「…」`，字符串 `『…』`，爻 `「阳」` `「阴」`，列 `「列」【…】`，元组 `（… 与 …）`，命名元组（组值）`「组值」【「字段」者 值 也，…】`（字段依声明次序），无参函数印它的结果；类型为「有」的句子只运行。

## 开机程序

`开机。豫` 是豫言操作系统的开机程序入口（提案 00003 第 8 步）：造两架构启动盘时，豫言系统把它编成开机程序，开机就进豫构的交互模式（做法在 `开机壳。豫`）。文件与环境命令照库 用户态桌面 的命令壳（已授“桌面”根下的路径、.环境），「行」「营启盘」同步运行子程序，「图形」进入桌面，「辞」结束。全系统只有一个壳（2026-10-16）：开机壳与宿主、桌面终端、远程登录一样经「交互命令」进会话，输入方式也由交互参数选：`/系统/开机。数据。豫` 的「交互参数」（如 `「交互参数」者「列」【『--直读』】也。`），没有这个文件或这一项时为 `--组字`（逐键编辑：拼音组字、候选、补全、历史，Ctrl-C 放弃这一行）；`--直读` 原样按行读入，串口脚本整行送进来不经拼音；直读的会话里子程序直接继承标准流（库 几席 的「子程序承流」，2026-10-22，议题 348），输出即时上串口、串口送来的答话直接进子程序。每句都用盘上的 `/工具/豫构。豫行`、`/工具/执行器。树码` 与源码树 `/源` 编译，编译缓存的程序标识取 `/工具/豫构。豫行。摘要`，与盘上的豫构共用缓存；造盘缺省带工具链，盘上没有工具链时什么句子都运行不了。开机自启（`/系统/开机自启`）的各句当会话的开头句（`--开头句`）编译执行；「图形」写下进入桌面的请求（见库 用户态桌面 的壳请求），读下一行之前与等键的空当在这里进入桌面。造盘时已预编前导单元（单元目录印记与盘上的相符）时，开机就把前导单元装进来再读第一句（`--先装前导`），第一句不再等编译与装载。开机最先看有没有「葺寓」暂存的 `/新版`（2026-10-17）：有就运行 `安装系统 换上`，这次开机是新系统的试启时把暂存的 `/源` 与 `/工具` 换上，否则删去暂存，之后才读程序标识、找仓根、进会话。设了系统口令（`/系统/远程登录/口令`）时，读第一句之前先要口令（2026-10-21）：屏幕与串口都印「口令：」，按键回显圆点，回车核对；错了重问，每次多等一秒，不限次数。未设口令时照旧。带参数运行时就是普通的豫构。开机自启的开头句后面接「自动对时」一句（2026-10-21）：设置里开着自动对时，就在开机联网后对一次时（见库 几席 的 `对时令`）。「确认系统槽」改在开机壳第一次等键的空当后台办（2026-10-23，议题 380）：这一句要装入近百兆的 `/工具/豫构。豫行` 才能跑引用式清单的 `安装系统 确认`，原先排在开头句里会把首提示符压住百来秒；现在提示符先出来，试启的槽由后台子程序随后确认，结果照旧印在串口上（见 `开机壳。豫` 的「开机确认槽一巡」）。

## 发行

`豫构 发行` 把应用连同它用到的操作系统接口构建成能在云工、浏览器、节点或原生宿主上直接运行的发行物：读包描述、解析依赖、按宿主选适配并绑定、生成包上下文、编译、复制宿主外壳、封装接口清单，一条命令完成；编译器缺省用豫构自己。`豫构 接口检查`、`豫构 接口绑定` 与 `豫构 装载接口` 单独提供其中的接口检查、绑定与清单封装。源码在 `发行/`，用法见 [发行](文档/发行.汉语.md)、[接口检查](文档/接口检查.汉语.md)、[接口绑定](文档/接口绑定.汉语.md)、[装载接口](文档/装载接口.汉语.md)。

普通构建也给本机整程序接适配（议题 217、226）：`豫构 构建` 要编出能运行的本机程序时，包图闭包里用到的豫寓接口若有 `豫言操作系统/适配/XXX原生/` 适配，就先把接口检查与接口绑定做到 `dist/.普通绑定/<接口目录>` 旁的临时目录里，改好绑定包的父包再逐个文件原子写进那个目录，然后把包图里该接口包的包描述换成绑定包，编译器便编适配的实现模块，不编规范里没有函数体的声明。绑定包里的实现模块按接口模块取名 `模块名。接口。豫`，不照适配源文件的 `模块名。豫` 照抄：接口模块的包内相对路径在绑与不绑两种构建里因此相同，阶段缓存把绝对路径换成的信标相同，同一份缓存才能在两种上下文之间共用（#1196）。绑的是闭包：接口自己依赖的接口、适配包依赖的接口随重析的包图进入闭包后接着绑，绑到不再有可绑的接口为止；`--又` 给出的其余程序也一起绑。绑定目录不分根包，各程序、各次构建绑同一接口都写进同一目录：绑出来的产物只取决于接口与适配，逐字节相同；包缓存编号不含目录，同一模块在两次构建里的路径相同，缓存里记下的导入路径才对得上。接口目录、适配目录与接口检查的包发现都从包图闭包推出来的源码树根找（该根下有 `豫寓榫卯` 与 `豫言操作系统/适配`），仓外（外部包目录、工具链旁的 `源`）也找得到。`文件`、`类型检查`、`--清单`、`--目标`、`--目标系统`、`--目标架构` 与 `.wasm` 产物都不绑。没有原生适配的接口、以及本机执行器直接提供的接口（如显示）照旧按规范声明编成宿主导入，调用时中止并印出是哪个接口、哪个函数没接（待办事项：链接“不可用”的兜底实现）。绑定包的「包含在」改回规范包的父包，包图的两向校验才过得去；几个构建同时绑同一接口时各绑自己的临时目录，写进去的内容相同，任何时刻读到的每个文件都是完整的一份，编译缓存照内容复用。源码在 `发行/普通绑定。豫` 与 `发行/自动构建。豫` 的「执行多模块绑定」。

```sh
./豫构。林檎。豫行 发行 节点 豫言操作系统/宿主/节点/一致性验证/应用 dist/节点一致性
```

在 macOS 与 Linux 上跑过仓库目标「全部」后，还有原生豫构 `./豫构。林檎。豫行`：命令与上面相同（如 `./豫构。林檎。豫行 构建 豫构`），比 Node 版快，是日常构建的默认工具。豫构带着编译器（提案 00007 合一，见库 编译器入口）：没写 `--编译器` 时用自己当编译器，并行编译的工作进程也是同一个程序文件；`--编译器` 给的路径按启动时的目录补成绝对路径，路径不存在时报明这条路径退出，不再把它变成空串、报成“编译器旁边却没有执行器”或“要起的子程序路径是空串”（议题 #527）；首个参数是源文件、`stage`、`debug`、`--mode=…` 或 `--原生产物子进程` 时，豫构按编译器运行。原生豫构启动的 `.wasm` 子程序改经 node 运行。

默认产物（提案 00007 议一）：在 macOS、Linux、Windows 与豫言操作系统上，编译器旁有执行器 `执行器。树码`（仓库目标「全部」经「执行器」生成；豫言操作系统里是 AMD64 数据盘的 `/工具/执行器。树码`）时，`构建` 与 `文件` 默认产出本机原生可执行文件（macOS 为 Mach-O，Linux 为 ELF，豫言操作系统为豫行文件），由编译器在最终链接里直出，不经 `.wasm`：豫构给编译器加 `--目标 本机 --执行器 执行器。树码 --降级缓存 <共享缓存>/降级/产物名.机器片`（传的是绝对路径：执行器取编译器所在目录里的，降级缓存放在共享缓存里，见下节；编译器在自己的目录下运行）。`--输出` 以 `.wasm` 结尾时产出 `.wasm`，以 `。树码` 结尾时产出汇编树码；没写 `--输出` 时产物名是包的程序名加本机系统的后缀：macOS 加 `。林檎。豫行`，Linux 加 `。林纳。豫行`，豫言操作系统里产出豫行文件，不加后缀。编译器参数里已写 `--目标` 时豫构不再添加目标与执行器；只写了 `--执行器` 时仍补 `--目标 本机` 与降级缓存，执行器用写下的那个（不再补默认的：`--又` 各组的专属参数排在 `--` 之后的参数后面，处理器取最后写的一项，再补一个就会盖过它，最终链接与整产物缓存也按默认执行器算而取回旧成品，议题 #502）；写的是 `--目标 本机` 而没写 `--降级缓存` 时补上降级缓存，文件名带上目标系统与架构（如 `降级/豫构。豫行-豫言-兼容六十四.机器片`）；交叉目标（`--目标系统`、`--目标架构`）与底层程序的写法见[编译器包说明](../豫言编译器/包说明.汉语.md)“原生产物”。给图形程序写缺省宿主选项（2026-10-27）：`--` 之后的编译器参数原样交给编译器，所以 `豫构 构建 包 -- --缺省宿主选项 '--授权显示面 主窗口=1280x860'` 就把这组宿主选项写进原生产物，双击打开时执行器自己补上，命令行上另写同一项的仍以命令行为准（见编译器包说明的“缺省宿主选项”）。包描述眼下没有承载窗口缺省尺寸的字段（`「界面」者『图形』也` 只说明这个包是图形程序、轩窗上写成图形子系统），所以窗口尺寸与其它授权要么写在这条编译器参数里，要么在启动时手写；等 CI 换链、包描述能加字段之后再议。Windows 上也照此产出原生程序（豫构旁有 `执行器。树码`，或豫构自带执行器时）。找不到执行器时，没写 `--输出` 或 `--输出` 以 `.wasm` 结尾照旧产出 `.wasm`；`--输出` 写的是原生程序的名字（不以 `.wasm`、`。树码` 结尾）时报错退出，写明缺的执行器路径与 `-- --目标 本机 --执行器 <路径>` 的用法（议题 #489）。

缺省执行器（2026-10-25，议题 #635）：豫构编自己（包标识 `豫构`）而成的本机原生程序自动带 `--自带执行器`，把编它时用的执行器汇编树码字节嵌进自己的可执行文件（模块尾块之前，尾标“YUYANEXE”加 8 字节长度，见冶铸包说明）。豫构跑起来先读自己的文件取回这块，按它的沙二五六放进共享缓存根下的 `执行器/<摘要>。树码`（文件不在或内容不对就先写同目录临时文件再改名），此后没写 `--执行器` 的一切构建、运行脚本、交互会话与预编前导都用这一份缺省执行器。几个工作树、几个豫构共用同一个文件，执行器与编译器总是配套；树根不必再放 `执行器。树码`，换链只换豫构。旧版豫构（没有自带执行器，如诺驿、浏览器与豫言操作系统里的豫构）照旧用它旁边的 `执行器。树码`（没有时 `执行器.wasm`，再没有就报错）。显式 `--执行器` 一律照用，不被缺省覆盖；只写 `--执行器` 而不写 `--目标` 的构建照旧补 `--目标 本机` 与降级缓存。轩窗的原生豫构（`豫构.exe`）同样从自己的文件里读回执行器块（PE 的尾块在文件末尾）；交叉编出的 `豫构.exe` 用编译器旁带去的 `执行器。树码`。

依赖及说明路径以 [包配置](豫构。包。豫) 为准。构建不会自动运行程序；有发布或服务副作用的工具应先阅读其入口源码。

## 共享缓存与多程序构建

编译缓存放在共享缓存根里（提案 00034）：环境变量 `豫言缓存目录` 给出的目录，没有时是宿主常居基目录（macOS、Linux 与豫言操作系统上是 /tmp；Windows 上是 LOCALAPPDATA，没有时 USERPROFILE 下 AppData/Local）下的 `豫构缓存-<用户名>`（豫言操作系统里是当前目录的 `.豫构缓存`）。常驻工作进程跨任务共用，工作任务按自己那份环境变量取缓存根：编译器的「储根」记住决定根的两项环境值，值没变才复用上次算出的根，所以客换了 `豫言缓存目录`，工作任务写进的仍是客的缓存根。根下按编译语义号分目录，语义号写在库 译场 的 `译料/译设/语义号。数据。豫`，编译语义变了就换（规则见 AGENTS.md）。语义号目录里有：

- `引/<树号>/`：各工作树自己的阶段缓存索引（树号是仓库根的沙二五六前十六个十六进制字，见译场的「树号自」；网页行在固定为 `网页`），层下按语义选项号与源文件相对径分条目（见译场的「所出相对」）：每份缓存旁边的“。记”记着写出时的阶段键与内容摘要，另有依赖快照与核对记号，按修改时间与阶段键判新旧。索引只由本树的构建写（2026-10-28：全机共用一份时，两棵源码不同的树同时构建会互相改写对方的旁记，一棵树照另一棵树的上一阶算键、取到另一棵树的产物）；跨工作树、跨机共享只走下面按内容寻址的 `键/` 与 `物/`。产物本身按摘要放在 `物/`，内容里夹着本仓库根绝对路径或算不出阶段键的放在 `引/本/` 下（按仓库根摘要与包上下文号分开）。文件依赖、抽象语法、语义标记与语言服务里落在已登记包目录下的绝对路径，写树码串表时换成包身份与包内相对路径、读回时按本次构建的包上下文还原（`库/译场/译料/系树/章句树/述/树码表` 的「藏径串」「还径串」），所以这四样也入共享缓存、跨工作树命中。
- `键/` 与 `物/`：按内容寻址的共享阶段缓存。阶段键是输入清单的沙二五六：编译语义号、信息名、模块缓存身份，以及源文件摘要或本模块上一阶段与各导入模块同阶段产物的摘要。键库存产物摘要，旁边的“。料”存输入清单；物库按摘要存产物。本工作树的缓存过时时先按阶段键查这里，命中就直接取来。
- `产物/`：最终链接的成品，键是链接键清单（编译语义号、产物名、目标、执行器摘要、原生目标、各模块闭包形式与元数的摘要）的沙二五六；豫行文件旁的“。摘要”一起存取。
- `降级/`：`片/` 下是降级共享库（每个函数一个文件，各程序、各工作树共用，见冶铸包说明，提案 00041）；旁边是整产物缓存，按产物名（与目标系统、架构）分文件。两处的键都带执行器字节的沙二五六（`片/` 的前缀是生成器的程序摘要接执行器摘要，整产物缓存的键里也有这两样），同一架构、同一执行器的程序才共用彼此的机器码；生成器按内容认，同一份豫构放在不同工作树也共用（议题 340）。
- `单元/`：引用式清单的单元仓库（提案 00038 第一步之六），在共享缓存根下、不在编译语义号目录里。按内容摘要存装载单元，文件名是摘要的小写十六进制加 `。单元`，同摘要只存一份；`豫构 构建 --引用清单` 往这里写，`豫构 运行` 从这里取，删掉后引用式清单就取不到单元。

装载单元另按内容缓存在工作树或交互缓存根的 `单元缓存/` 里（`豫构 运行`、清单构建与交互会话编前导、各部时给 `--降级缓存` 的目录），键的前缀是单元目标（系统、架构）、执行器内容的沙二五六与豫构自身的沙二五六，执行器或豫构一换就重编。单元目录里的 `印记.txt` 记着编出单元的编译器的编译语义号、单元的目标、单元的布局、执行器与各模块源文件的摘要，同名目录的单元按这份印记复用：`豫构 运行` 的脚本目录、交互缓存里的前导与各部目录在宿主上都比对印记，换了执行器、单元的目标或布局（同一套指令集下 Windows AMD64 是绝对址式，macOS 与 Windows ARM64 是相对址式）或编译语义号就重编。单元目录里另有 `印记源.txt` 记各源文件上次算印记时的修改时间、字节数与摘要：改时与字节数都没变的源不再重读（2026-10-24，交互提速）。印记记语义号而不记豫构自身的摘要（2026-10-24）：语义号相同的豫构编出的单元一样，可以互用，造盘时宿主豫构与盘上豫构语义号相同就能预编前导（豫言操作系统里各部的单元只看印记在不在；前导的印记照样要核，源码读不到时按「印记权宜」照用盘上预编的单元、往起居注记一行，不让开机壳退出，2026-10-24，议题 #514）。

一次豫构调用可以构建多个程序：

```sh
./豫构。林檎。豫行 构建 包甲 --输出 甲 --又 构建 包乙 [入口段…] --输出 乙 --又 文件 路径 --输出 丙 --编参 --开机程序 -j 24 -- 公共编译器参数…
```

前端只编一次各程序依赖的并集，再各自做最终链接；`--编参` 后面的一个参数只交给本组程序的最终链接，`--` 之后的编译器参数各程序共用。以「文件」打头的命令同样认 `--又`（`豫构 文件 甲。豫 --输出 甲 --又 文件 乙。豫 --输出 乙 -- --type-check-only` 一次把几篇单文件入口一起检查）：单文件入口按所属包算出入口，主文件与各组一起交给编译器，只做类型检查时与主程序一起检查（议题 #480）；`--清单` 一次出一个清单豫行，与 `--又` 同用时报错。各程序的最终链接与原生生成由豫构另起进程并行，同时至多 `豫言链接并行数` 个（缺省为核数除以六、在一到三之间），依赖模块多的程序先链；这些进程经「将交役」交本机构建服务（将作）排队，编译器就是豫构自己时登门报能代，任务交代役执行、内存算进代役那棵进程树；给了别的编译器（`--编译器`）时按借槽在本机执行、先领一个槽；设了 `豫言将作=关` 时照旧直接起子进程（议题 #582；用户 2026-10-25 定客不自己执行任务，原先一律按借槽让客自己跑）。参数只差输出、降级缓存与目标架构的几组（如两种架构的同一程序）只做一次最终链接，各自起原生生成；原生生成先等同一架构里依赖最多的程序生成完，降级共享库先由它填满（提案 00041）。造盘的开机程序与豫行工具就是这样一次编完的。加 `--链参存 文件` 时只编前端，把各程序的最终链接参数存进这个文件；之后 `豫构 链接 文件 [--只链 前缀] [--编译器 编译器]` 接着链，`--只链` 只链输出路径以前缀开头的程序（造盘时父进程一次编完两种架构的前端，再用「链接」链好两种架构的全部程序）。

`--` 之后与 `--又` 组 `--编参` 里取路径的选项（`-o`、`--package-context`、`--执行器`、`--降级缓存`、`--符号表`）按豫构启动时的当前目录补成绝对路径再交给编译器：豫构起编译器之前会切到编译器所在目录，不先补全的相对路径就会按那个目录解析（议题 #238）。

可改，零或负为不限）还没答自毕时，服务查它客的连接还在不在（登门时登记客连接表，客断时移去）：在就续等、下一个时限再查，不在才收回还槽并记一行日志。理一条连接的任务自己出错停了（异步任务抛异常收场）时，善后照样跑一遍客断的清理，不必等一小时。客连不上服务时在后台起它并等它起来，起不来就一直等（每三十秒重起一次、印一行提示），不退回本机全速执行；连接出错先重交，再出错同样等到服务回来。只有设了 `豫言将作=关` 的构建在服务不在时才在本机按 `-j` 并行。连接的第一行都带令牌（`~/.豫构/将作/令牌`，权限 0600），服务只认同一用户；对不上时服务先答一行“令牌不符”再关连接，客据此报错（只借槽的构建在本机执行），与连接暂断分开。消息都是一行数据子语言（籍册）。服务启动时写门文件 `~/.豫构/将作/门。数据。豫`（端口与启动时刻）。

服务与代役都只有一条线程，所以发消息走按连接排队的非阻塞写（「将作投」）：写不进的部分等可写再续写，一条连接积压超过二百五十六兆字节就当对端已死，读得慢的连接不会卡住别人；主循环每轮先限时让出，再把就绪的任务接着跑完（至多二百五十六步）。每个交役只更新本客的任务图进度，一小时没再记过的顺手删去，开销与同时在跑的构建数成正比。

共享缓存按最近使用时间回收（议题 #580）：主循环每趟调一次（见「将作巡」，实现在 `将作回收。豫`）。服务隔五分钟给在用的东西写记号 `.将作用`，内容是当时的墙钟秒数：连着本服务的客的工作目录在各自语义号目录 `引/` 下的条目（译场的工作树号有两种写法——启用包上下文时用带结尾斜线的仓库根前缀，未启用时用不带斜线的当前目录——护名两样都算，未启包上下文写出的 `引/` 条目同样护住，议题 #629）、共用链名册里近七天用过的那几条工具链（名册本身按最近使用淘汰，见下）与本服务自己的语义号目录、登记着的借场镜像根与「将作远行们」各客经「将作远镜于」求出的镜像根。扫描分步做（议题 #1133）：主循环每趟只挑一个语义号目录（过二十毫秒就停）、收八项，扫到哪记在续态里，下趟接着扫，紧态下也一样，免得主循环被回收拖住；开扫只清续态，列缓存根这一次列目放到第一步扫里（一次列目拆不开，至少不占开扫那一趟）。隔六小时扫一趟，把七天没用过的语义号目录（本服务自己的与近七天用过的名册语义号不碰）、这些目录里 `引/` 下七天没用过的条目、临时目录下 `借场/` 里七天没用过的镜像根（登记着的借场与远行之镜不碰）改名成同一父目录下的 `.将作回收-随机数`，入待走队；`引/` 下没主而工作树已经删掉的条目（静置十分钟以上、名字编码出的目录在文件系统里找不到）不待七天，当场改名入队；语义号目录 `降级/` 下七天没用过的机器片与产物也一并入队；会所 `工具链/` 下七天没用过的副本同样入队（名册里的、本服务自己的、正在用的指纹不碰）。判新旧只看那个根：根上有记号读记号的内容，没有记号读那个根本身的修改时间，不为判新旧走整棵树（一个语义号目录可能有几十万个小文件）。删除逐目录走：目录栈跨趟存在模块里，每趟主循环至多列八个目录、至多核五百一十二个条目、至多删六十四件；扫与走共用一个总时额（二十毫秒，议题 #1133），超了就停、下趟接着做；先删文件，一个目录里的东西删空了再删目录本身（后序），符号链接只删链接本身。改名根整个删完才在日志记一行 `回收 <说法> 腾出 <字节> 字节`，腾出的字节在逐件删时累计，不再递归量整棵树（议题 #1133）。回收的每个小步都记耗时，最慢的一步跟着“慢的一趟”报出来（见下文日志一节）。客自己设了 `豫言缓存目录` 的、本机工具链更新脚本另设的 `/tmp/豫构缓存-本机工具链`，都不在这个服务的缓存根下，留待后续版本。

另按空间收（议题 #1013）：主循环每五秒问一次缓存所在卷的余量（豫寓察役的「问数据盘」，原生林檎、林纳量服务所在的卷，不起 df），可用低于门槛（设置“回收余量百分”，缺省 15%）或卷的已用超过预算（“回收总量预算”，吉字节，缺省不设）就当场按最近使用从最旧的语义号目录起收，每次至多挑四个、待走积到四个就先不挑；刚变紧的那一趟先照六小时那一趟扫一遍，把工作树已删的 `引/` 条目与旧的 `降级/` 产物先收掉，再按最近使用收整号；开工后一直收到可用回到目标（“回收目标百分”，缺省 20%）且不超预算为止，余量回到门槛与目标之间仍接着挑。近七天用过的名册号、在跑客报来的号、本服务自己的编译语义号，以及 `引/` 下有在用条目（护名，含旧客不报号的情形）的目录都不收；工具链副本余量紧时也按最近使用收（静置十分钟以上的才算，见下）。问数据盘只报整卷，缓存根与会合点不在同一卷时（如以 tmpfs 挂 `/tmp` 的机器）量到的是会合点那一卷，留待接口能按径问卷。

共用链名册按最近使用淘汰、工具链副本跟着出册（议题 #1097、#1098）：名册每条记最近一次有客或代役用到它的时刻（`最近使用`，墙钟秒），只认真用：客登门报来的语义号、客交役时算到的工具链指纹、代役取工具链时更新（记号文件与将作自己刷的时刻都不算凭据，2026-10-27 将作主人实证：旧将作按整本名册每五分钟刷 `.将作用`，九个换下的旧号目录因此看起来一直在用），盘上五分钟至多写回一次。旧版名册没有这一栏的条目算没有真用记录，先出册；它们目录上的旧记号不再作数，回收按该号目录二层内各目录（不取顶层、不逐个文件取改时）的最新修改时刻估，估出的值缓存一小时：七天内目录改时新过的不当陈；没有估值的号算未知、不当陈，由分步扫描每步估一个号把估值填进缓存（见下）。名册至多「将作名册限」条（二百五十六条），七天没用过的出册；超过上限时按最近使用从旧到新再出册。出册记一行 `共用链名册出册 <指纹> <语义号>（七天没用／名册超上限、最久没用）`；会所下它的工具链副本（`~/.豫构/将作/工具链/<指纹>/`）不在「将作活纹」（本服务自己的、排队与运行中使用着的、活着代役用着的、在连着本服务的客的树里用过的指纹）里就改名入回收的待走队，由逐目录走分趟删掉，删完才在日志记明指纹、字节数与缘由（议题 #1133：不递归量大小、不同步删整份副本，免得服务起来头一两分钟卡十几秒），有人在用则副本暂留。回收的碰记号与按空间收只护“近七天用过的名册号”（见上文）；名册用的那条链与副本也在用到时碰 `.将作用`，回收据此判副本多久没用。

客在一条连接上等过三十秒没有答复时，它从那条连接上送一行问客役（议题 #206），列出在途任务的序号与任务名；服务只答（`将作理问客役`），不改任何状态：每件任务答在排队、在跑、借行（借槽任务已由客在本机作它）还是不认得，另答本客还认不认得，并记一行 `对役 客 <客号> 树 <工作目录> 认识／不认识 问 n`。共用连接上的任务按客内序号认，每任务一条连接的任务送交时序号记负一，按任务名认。合符的客也可以在自己那条连接上重送登门行（服务据此重新登记本客，回应议题里“登门记录丢了”的情形）。测试开关 `豫言将作丢答=<数>` 让服务随机挑第 1 到该数之间的某一条客答（役毕或自行）丢掉（只丢一条，记 `丢答（测试开关 豫言将作丢答）客 …`），用来复现重压下的“答复丢了而连接未断”；缺省不设即关。

服务首次运行时生成虎符（`~/.豫构/将作/虎符`：三十二字节随机数的十六进制，权限 0600），所以缺省就在 0.0.0.0 监听，并开多播名籍（邻籍）：服务类型 `_yuyan-build._tcp.local`，实例 `将作＠<主机名>`，TXT 带节点号、虎符指纹、平台、核数与协议版本；启动时自报并查询，此后每六十秒一次，停止时告别。虎符指纹相同的服务互相发现，节点号（会合点下的 `节点`）小的一方主动连对方：双方各出随机数，以虎符对随机数与节点号的密钥杂凑码互证（合符），之后结为同僚链路，链路上每行附会话钥对行序与行文的杂凑码。被动接受结交、暂时没有对方地址的同僚行，地址栏照合符带来的对方机名与端口显示；同僚录的地址留待邻籍或静态配置填上。结交限时十秒：到时还没结完就关掉本侧连接、把这位同僚标为离线，下一轮主动结交照常去连；对方关掉结交中的连接、连不上或出错也一样复位，在线的同僚连接断了照样复位。同僚链路的任务自己出错停了（异步任务抛异常收场）时，善后照样跑一遍连接结束的清理：撤链、关连接、把这位同僚标为离线，并立刻在日志里记 `同僚链终 节点 <节点> 因 <原因>` 一行，写明真正的原因；正常结束时只记 `因 正常结束`。两边同时主动结交会撞车（同一台机器上两台将作互写对方为静态同僚时常见）：两条链路各在一头被当成重复链关掉，十秒一轮重结。现在按“节点号小的一方连出去的那条留下”裁：新链是本机连出去、本机节点号小，或新链是对方连过来、对方节点号小，就留新链，由主动结交的那一方把旧链按连接结束的清理撤掉（被动的一方只登记新链、不撤旧链，免得两头一起动手把两条都关了）；否则留旧链、关掉新链。节点号是同一长度的十六进制文字，按字典序比就是按数比。让位的那条在日志里记 ## 行在（宿主常驻系统实例）

每个用户在每台宿主上一个常驻进程「行在」（提案 00039），做这台宿主上的豫言操作系统实例：林檎与林纳上的原生豫言程序起来时连上来登记（执行器的「行在门」），任务表的句柄就是宿主进程号，行在自己是零号；壳命令「列出役」「辍役」「辍」与任务管理器经任务监测接口问的就是这张表。豫构交互会话找不到行在就在后台起一个，加入了行在的会话另装几席里「行在诸部名」列的几部（任务、图形、屏键、声音、电源、剪贴、软件、设置、游戏与归档；声音在网页行在里经 AudioWorklet 出声，宿主原生由执行器供之；软件部 2026-10-21 加，议题 244，装到私有根的 /软件；设置部 2026-10-25 加，议题 607，「屏列」按九宫写下的各显示面答；归档部 2026-10-26 加，议题 657，三份清单由「部居」每部的「所在」算出，不再手写，见「部居」）。会话包的依赖也由各部的「所依」算出（见「依赖名单」）。目录是 `~/.豫言/行在/`：门文件 `门。数据。豫` 写端口（缺省从 37431 起，被占往后试，`豫言行在端口` 改起点）、进程号、启动时刻与「司阍」一项（『阳』，新版执行器见到它才发新登记帧、在门口等放行），`钥`（权限 0600）是连接要出示的钥。没有任务、没有连接满三小时自动退出。

司阍与仓（提案 00056 第二至五期，2026-10-25）：本机新起的豫言进程先在门口等行在放行。新版执行器见门文件里有 `司阍` 一项才发新登记帧 YXZ2（钥、进程号、标志、优先、缺存、程序路径），门文件里再有 `户籍` 一项就发 YXZ3（在 YXZ2 之后加父籍号与役号各四字节；2026-10-27，提案 00067），行在按优先（交互、前台、后台）与先到先放：池里余量（上限减已给合计）至少一块才回一封“许行”；放不下就回“候行”（排第几、缺内存），每三十秒再回一封，名次变了也回。只按内存放行：处理器由系统分时调度，行在不让谁为处理器排队，并发由将作（构建服务）按槽排（2026-10-26 用户定）。带“免”的（标志第零位）、带“随作”的（第一位，常驻工作者与代役起的子进程）与行在自己起的子进程（桌面、桌面程序、作业、捉刀）立刻许行。旧执行器发的 YXZ1 帧照旧收下、不回帧、视同已放行。池的用量就是全部登记任务的已给合计：内存由行在按块给（许行时给一块、领存时再给），行在不向内核问实占与处理器时间（2026-10-26，议题 683，用户定；原先每秒量各最上层进程树的实占与各任务的处理器时间，要沿父进程链判上下层、扫整张进程表，任务一多每秒问上万次，行在把一核占满、答不上话，门口全堵）。父进程号（原语 292）只在登记时判是不是行在自己起的、给旧版记父籍、收场找子孙时现问；拍任务表快照不再问 292，处理器滴答改由执行器在 300、301、303、304 的丙里自报（2026-10-27，提案 00067）。行在运行时门文件记的行在进程还在（只是一时连不上）就不另起，免得忙不过来的行在被当成没有、再起第二个；几个程序同一秒另起的，各行在每五秒看一次门文件，归了别的活着的行在就收场退出，收敛成一个。池的上限 X 取 `豫言行在内存上限`（兆；没设取物理内存的七成），核数上限取 `豫言行在核数上限`（没设取在线核数），块取每槽额的八分之一、至少六十四兆（每槽额＝X÷核数上限）。仓（第三期）：许行后执行器问额（服务 300，甲为软额；答块、限、已给，千字节；限取软额与 X 的小者，没有软额为 X），堆要长过已给就领存（301）：上限内、池里有余量当场许；超过上限时池里有余量、又没有人排在前面也许并把限抬上去；否则照缺存三法——止答不许（八字节：缺什么，一池满、二超限），窖答自换，候压着不答、让出处理器（这条连接仍由自己的常驻读任务读，行在主循环的「在候巡检」每趟看池里有没有余量，有余量而没人排在前面就把 301 的答应出去、先于新任务许），等的时候每三秒请它换出一块，请了就等它的 303 换毕：303 当即作答，答过才答 301，执行器先收到 303 的答；池满时在候的排头等满十秒仍领不到就照许（破死锁），可以超过池上限 X，直到全局硬上限 H（`豫言行在硬上限`，兆；缺省物理内存的九成，不低于 X）；带“免”的进程（将作、行在、交互、监工等）照许不候。要到的总量（已给加这次要的）超过 H 时答不许；全部在候、排头已给加要的超过 H、又已换不出东西时也答不许，执行器印“内存不够（超过行在内存的全局硬上限）”退出。换毕（303）与还存（304）减已给，千字节为负数时答负二十二。将作通道（第四期）：『将作』带令牌得门合，此后收『领』（件、优）按池里余量回『许』（可以分几次回）、收『还』减租，连接断了没还的租约收回；租约一件算一核，池里余量至少一块时许到租约正好满核数上限为止，不看处理器实际占用（2026-10-26）。『余』照旧保留，答余件（只按内存余量算）、内存余兆、上限兆、已用兆与已给兆（两项同值，都是已给合计）。任务注销时删掉它的窖文件（`<行在目录>/窖/<进程号>`）；行在起来时清掉窖目录里上一代行在没来得及删的窖文件。`豫构 行在 状态` 首行写“仓 上限 X 兆，已给 G 兆，将作租约 K 件，排队 M，窖 S 兆”，下面列各任务的已给、限与换出量，以及排队中的任务（进程号、程序路径、已等几秒、缺什么、缺存法）与在候的任务（进程号、程序路径、已等几秒、要多少、缺存法）。过司阍的连接、在候的连接与将作通道都由各自的一条常驻读任务读，回帧（许行、候行、301 的答、许帧）由写的一方（主循环或同一条连接的读任务）直接写进连接，不再每三百毫秒起一趟巡检（议题 660）。


籍号与新旧协商（提案 00067 第二版 3.4–3.6，2026-10-27）：门文件在「司阍」之外再写「户籍」一项（『阳』）时新版执行器才发 YXZ3 登记帧（2026-10-27 修订：原定的 `籍号` 一栏作废、永不写，认它的乙路一期执行器照旧发 YXZ2，免得把宿主进程号与籍号混用），旧执行器照旧发 YXZ2 或 YXZ1。行在给每个登记（YXZ1、YXZ2、YXZ3）发籍号，从一起、活着期间不重用，零号是行在自己；只对 YXZ3 的许行答帧带四字节籍号，旧版仍是数据长零。任务表每项记下种（哪一版登记；零是 323 附籍建的无连接记录）、籍、父籍、役、峰给（已给的最大值）与时毫（本进程自报的累计处理器毫秒：300、301、303、304 的丙记进来，只增不减）。46 任务表快照按问者版本答：YXZ3 问者看到的「号」是籍号、「主」是父籍号、「滴」由时毫折成十毫秒的滴答；旧版问者仍看宿主进程号与登记时记下的父进程号。64、65 也按问者版本认：YXZ3 按籍号认、65 答籍号，旧版照旧用宿主进程号；65 对 YXZ3 问者按父籍链在各版任务里找子孙。新服务 320 领役（记下役号）、321 毕役（役号相同就清零）、322 辍籍（甲是目标籍号，乙是信号号：零照「行在辍宿」先十五、三百毫秒不退再九；一至一百二十七经「遣信宿主役」按宿主进程号发，没有这个进程（八）当作早已退出答零，其余答二十九；信号号不在零至一百二十七内答二十二，没有这个籍号答八），只有 YXZ3 的进程发这些服务。323 附籍：YXZ3 进程第一次问某个子进程的「使者役号」时发，甲是子进程的宿主进程号；行在按宿主进程号在任务表里找（有连接、无连接都算），有就答它的籍号、父籍与役不动，没有就新建一条无连接记录——新籍号、父籍是问者的籍号、役取问者当前的役、名为空、已给与限为零（种记零、连记负一，不占池），答新籍号；甲不大于零答二十二，问者不是 YXZ3 答负三十八。YXZ3 登记撞上已有的无连接记录时把连接接到这一条上、籍号不变，许行答这个籍号，名换成程序路径，帧里父籍、役不为零就用帧里的、为零留原值；先登记后附籍也一样，323 按宿主进程号找到的就是登记时建的那一条。324 除籍：无连接记录删掉答零，有连接的不动答零，没有这个籍号答八。一个进程的连接断开注销时，父籍是它的无连接记录一并删掉（孤儿，没有人再除它们的籍）。46、65、「余」的「籍们」与 `豫构 行在 状态` 把无连接记录与有连接的同样列出；322 对无连接记录照样按它的宿主进程号发信号。『余』答复加「籍们」：每个已登记进程（含无连接记录）一条籍、父籍、役、已给千、限千、峰给千与时毫，全部数据整数，行在自己不列。`豫构 行在 状态` 的任务行开头写「籍 N 父 N 役 N」。拍任务表快照不再问原语 292、293。行在与将作的本进程号改问「问本役」（执行器原语 310，第十节），不再起带 `--问本号` 的子进程去问父进程号。

构建类命令（`构建`、`类型检查`、`文件`、`链接`、`目标`、`全部` 等）照提案 00056 议二留在行在里、只把附庸撤掉（2026-10-25，钩司作）：入口开头照 `行在保起` 的办法先保起本机行在（不在 CI、没设虚根、没设 `豫言行在=关` 时），再经执行器原语「辞附庸」（295）在当前进程里撤掉附庸、仍留在行在里——当前目录与程序名换回宿主路径，此后起的子进程照常加入行在、看到的是宿主路径，构建的任务照旧登记在行在里、受司阍与仓管。原先（2026-10-22，议题 #281）是整个辞出行在：带 `豫言行在=关` 用 `/usr/bin/env` 重起自己一次，把 `豫言附庸`、`豫言行在目录` 从环境里去掉（`应用/豫构/入口。豫` 的「辞行在」），构建的子进程与代役便都不再连行在；现在只在旧执行器没有「辞附庸」（返阴）时退回那条老路。`交互` 与 `运行` 会话照旧加入；`行在` 服务自己（`豫构 行在 …`）不辞，它把环境交给图形桌面；常驻工作者与编译工作进程本来就不撤。环境变量 `豫言行在已退` 挡住重来；已设 `豫言行在=关`、或网页行在的会话（`豫言行在=网页`，这个值只是缓存与单元目录的摆法标记，并不连着宿主行在）时不做：撤了它，编译子进程算出的工作树号就跟会话本身不同，阶段缓存各写各的（议题 #443）。设了虚根（`豫言根目录`，造盘的预编前导即此）时也不做（「辞附庸」自己就返阴）。当前目录在私有根的系统路径（/系统、/数据、/软件）下时也不做（待办事项）。

加入了行在的程序按附庸表（挂载表，提案 00039 第二步）看文件，做法在执行器（见客体二号说明“附庸”）：「/」是私有根 `~/.豫言/行在/根`，/系统、/数据、/软件在私有根下可写，起程序时当前目录所在的仓库、主工作树的上一级目录（同仓的其他工作树、云仓与数据目录都在里面）、共享构建缓存根、`~/.豫构`、`~/.豫言` 、/tmp 与工具链目录（会话缓存与构建日志写在它下面）按原路径附入（仓库与工具链目录可写，主工作树的上一级只读），系统目录按原路径只读。环境变量 `豫言附` 加附庸（冒号分隔的宿主路径），`豫言全宿主` 把宿主根透进来；壳命令「附庸」印本任务的附庸表。将作与行在两个服务照宿主的命名空间运行。豫构自己在命令行里收到 `--外部包目录` 或 `--包根` 给的、宿主上确实存在的绝对目录时，启动时把它们按原路径只读加进自己的附庸表：带着扩展后的 `豫言附庸` 重起自己一次（环境变量 `豫言附补过` 挡住第二次），编出的子程序继承同一张表，因此外部包目录放在工作树与 /tmp 以外也能发现与类型检查；别的程序、别的参数照旧，设了虚根（`豫言根目录`）时也不加（议题 213）。

行在里的桌面（提案 00039 第三步）：壳命令「图形」在私有根写下 /系统/请求进入桌面，行在看到后在私有根里起行在工具目录里的本机图形桌面（目录取 `豫言行在工具`，缺省是豫构所在目录下的 `行在工具/`，仓库目标「行在工具」编出图形桌面、桌面程序与市肆），并写下 /系统/桌面运行中，桌面退出就删去它。起不来时（如还没编过行在工具）行在把原因写进 /系统/进入桌面回执，发请求的壳等一小会儿读到就印出原因（议题 215）。起桌面前行在先在私有根的工具目录里给图形桌面、桌面程序与市肆放好符号链接（名字带“。豫行”，指到行在工具目录里带本机后缀的程序；2026-10-21，议题 244），桌面活动栏的“软件”与「辟窗」于「种类」曰『市肆』按 /工具/市肆。豫行 才找得到、起得来。桌面是屏幕的主人：画面发布在共享的屏块文件 `~/.豫言/行在/物块`，任何任务的「截屏」读它，「点击」「按键」等拟入写它的注入环。林檎上桌面窗口的大小取 `豫言行在屏尺`（缺省 1280x800），设了 `豫言行在屏后台` 就在后台开窗；林纳上没有显示，桌面照样无头运行。桌面的每个窗口（「辟窗」开的也是）由同目录的桌面程序在自己的进程里运行，加入行在、登在任务表里。行在起桌面时把子程序授权（同目录的桌面程序、`/工具/豫构。豫行`（桌面终端起壳会话要用）、`/工具/市肆。豫行` 与私有根的 `/软件`）与环境名授权（`豫言窗号`：每个窗口程序的环境里带它，子程序接口对每个环境名逐个授权）一并交给桌面，桌面起的窗口程序、终端的壳会话与市肆才起得来（2026-10-21，议题 223、244）。`/软件` 按目录授权（2026-10-21，议题 258：执行器认目录前缀，`/软件/筹策` 这样的名字解析到目录里的程序），因此桌面与它起的窗口程序能起市肆装上的图形软件，装新软件也不必重启桌面。余段里的 `..` 段、`.` 段与空段（连续斜线或末尾斜线）一律拒绝，拼出的路径出不了 `/软件`（2026-10-21 补漏）。`豫构 行在 停止`（以及「息」「更始」，关机、重启）请行在结束时先写下 /系统/请退桌面 请桌面退出并等它（至多三秒，逾时结束它）：桌面看见就自行退出，桌面程序随显示面关闭而退；行在被杀或崩掉时，桌面每秒看一次行在的进程号，不在了也自行退出，桌面程序照样随显示面关闭而退。此后行在结束自己起的任务（桌面、桌面程序与捉刀后台等它的子孙；别的终端登记的外来程序不杀，由连接断开时照常注销，议题 503）并退出，更始再在后台起一个新的行在。

预装的揽辔台（2026-10-23）：仓库目标「行在工具」还编出 `行在工具/揽辔台。<系>。豫行` 与 `行在工具/捉刀。<系>。豫行`，「行在备具」把揽辔台也链成 /工具/揽辔台。豫行，行在起桌面时一并授权，桌面的启动台与「辟窗」于「种类」曰『揽辔台』按这个名字开它。揽辔台在宿主桌面里不自己起捉刀（桌面起的程序受授权表限制，捉刀子会话里的开发工具用不上），而是写下 /系统/请求起捉刀（内容是篇的绝对路径），行在每一轮看一次，有就删去它，用行在工具目录里的捉刀在篇所在目录起 `捉刀 篇 --台 --豫构 本程序`，每轮收它的输出，退出了就丢开。

应用包：林檎上的“豫言.app”（如 `/Applications/豫言.app`）里，`Contents/MacOS/豫言` 是指到工具链 `豫构。林檎。豫行` 的符号链接，Info.plist 的 LSEnvironment 设 `豫言缺省命令=行在 桌面`；豫构没带参数而 `豫言缺省命令` 有值时按空格把它分成参数，双击应用就起行在、进桌面。豫构按真文件所在目录找执行器与工具，应用随工具链自动更新。

行在里的后台作业（2026-10-23，议题 445）：加入了行在的会话里，程序「开发」的「后台运行」（壳命令「后台行」）把请求写进 `/系统/作业`（附庸表把 /系统 对到私有根，所以写进去的是私有根的 系统/作业）。行在每二百毫秒一轮的主循环里每半秒扫一次那个目录，替会话起作业（模块「行在作业」，宿主后台作业）：读请求里的程序、参数们与目录（私有根下的 /系统、/数据、/软件、/工具 换回宿主路径），环境取请求里带来的提交会话的环境（含「设」的变量；旧请求没带时取行在的环境，议题 541），去掉附庸表与 `豫言附补过`、另设 `豫言行在目录`（子程序据此按自己的当前目录另建附庸表，仍加入本实例），用「东道带列」之「遣使于境」异步起子进程，不等它结束；此后每轮用「使节」之「取使者出」取新输出，攒满 64 KiB 或隔一秒写一段到 `日志/`，结束了就写完余下的输出、写状态与退出码；见到 `待终止` 标记就按「使者役号」得的任务号「辍役」。作业不随会话结束，有作业在运行时行在不因久闲退出；行在重启时把上一个行在留下的“运行中”作业标成“中断”。这与豫言操作系统的远程登录是同一套目录与协议（见 应用/百工坊/开发命令 与 应用/远程登录）。待办事项：行在收场时不结束正在运行的作业。

轩窗上的行在（2026-10-27，提案 00039 阶段 3，先不做附庸）：Windows 原生豫构与它起的程序也能起行在、登在任务表里、受仓与任务的管理，私有根与挂载留待后续版本。会所照旧是 HOME 下的 `.豫言/行在`（HOME 由执行器入口从 USERPROFILE 补，见[客体二号说明](../../豫言操作系统/裸机/客体二号/说明.汉语.md)），门文件与钥照旧；钥的 0600 落空：Windows 没有 POSIX 权限位，会所与钥文件只有默认 ACL（本用户与管理员可读写），改权返回“不支持”不当失败。登记报进程号用 `GetCurrentProcessId`；问父进程号（292）与累计处理器时间（293）分别走建进程快照（`CreateToolhelp32Snapshot` 加 `Process32FirstW`/`NextW`）与 `OpenProcess` 加 `GetProcessTimes`；结束宿主进程（265）与打断任务（161）走 `OpenProcess` 加 `TerminateProcess`——Windows 没有 SIGTERM 与 SIGINT，行在及其子孙各自脱开控制台、发不了 CTRL_BREAK，先温和再硬停那一套落空，只能硬停。行在由 `启动` 在后台起时，「遣离使于卷」带 `DETACHED_PROCESS` 与 `CREATE_NEW_PROCESS_GROUP`（调用方在不容脱离的作业对象里时去掉 `CREATE_BREAKAWAY_FROM_JOB` 重试一次）起它，与起它的控制台脱开、自成一组；执行器在起它之前先以 `STARTUPINFOEXW` 的 `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` 只把块里点名的标准输入（空设备）、标准输出与标准错误（`行在.输出`）交给它（创建标志加 `EXTENDED_STARTUPINFO_PRESENT`），行在只拿到这三支，不再占着交互会话的标准输出管道（#1138，2026-10-28 第二轮）；「遣使于境」（210）的工作目录经 `CreateProcessW` 的 `lpCurrentDirectory` 生效（块里的目录句柄用 `GetFinalPathNameByHandleW` 换回路径）。CI 的「轩窗行在」作业冒烟这一路：起行在、读状态里的端口与进程号、起一个常驻的原生程序看它登在任务表里、停止后核没有残留进程。

- `豫构 行在 运行 [--后台]`：运行行在（已有行在在运行就说一句返回一）。
- `豫构 行在 启动`：在后台起行在（用「东道带列」之「遣离使于卷」起，自成一个新会话，标准输出与标准错误都接到会所下的 `行在.输出`（追加写，满了四兆字节先改名为 `行在.输出。旧`），起它的进程退出以后行在的报错仍留得下；执行器还没有 299 时退回「遣离使」；#479、#545、#659），等它起来（至多五秒）。起子进程失败时印“未能起行在：<缘由>”，缘由是宿主错误码（原生执行器与诺驿都为底层状态码；2026-10-28，议题 1177）；遣立成功而五秒内连不上时印“行在已起（进程号 …）但五秒内连不上，见 <会所>/行在.输出”。
- `豫构 行在 重启`：请行在停止，等它退出，再在后台起新的。
- `豫构 行在 状态`：打印行在的况（进程号、端口、任务数、连接数、已运行多久、仓的上限、已用与排队数、会所）与各登记任务、排队中的任务（进程号、程序路径、已等几秒、缺内存还是排在前面的后头）；壳命令「行在态」印的也是它。
- `豫构 行在 停止`：请行在退出，先请桌面退出并只结束行在自己起的任务（桌面、桌面程序、作业、捉刀这类它的子孙，同「息」）；别的登记任务（构建、测试、工具）与排队中的任务不发信号，由连接断开时照常注销（议题 503、提案 00056 第一步）。
- `豫构 行在 桌面`：行在没在运行就先在后台起，再写下 /系统/请求进入桌面（同壳命令「图形」），等至多三十秒进入桌面；桌面已在运行就说一句（2026-10-23）。
- `豫言行在=关`、CI 环境（有 `CI` 环境变量）与林檎、林纳、轩窗以外的宿主不用行在，照旧独行（没有任务表，「列出役」印“本环境不能列出任务”）；交互会话不印“未起行在”。交互会话（`豫构 交互`）起不来行在时，退回不用行在之前先在标准错误印一行“未起行在（<缘由>），本会话直接执行”，缘由与 `行在 启动` 的相同（2026-10-28，议题 1177）。

一个目录一个行在实例（提案 00042）：各子命令前加 `--目录 目录`，或设环境变量 `豫言行在目录`，就用那个目录里的门文件、钥与私有根；执行器的行在门照同一个环境变量找门文件，设了它的程序加入那个实例，附庸表的私有根与屏块（物块文件）也用那个目录里的；行在起桌面时把 `豫言行在目录` 交给桌面，桌面和它起的程序都留在本实例里。实例目录下的 `实例/<名>` 是它的子实例（「诣行在」在实例里起的），可以层层嵌套。豫言操作系统里也能起行在，得到嵌套的系统实例（实例目录在 /数据/行在/<名>，壳命令「诣行在」起它并进入它的会话）：嵌套会话的「列出役」只列实例的任务，「息」「更始」只关、重起实例；豫言操作系统里没指明目录时 `豫构 行在 状态` 说明这里就是系统本身并列出各实例，别的子命令报错不办。

## 仓库目标：官网与文档站

云仓提案 C00005《静态站与动态站分离》的两个目标，都在仓库根目录运行，都不连带自举（用正在运行的豫构）：

| 目标 | 产物 | 做什么 |
| --- | --- | --- |
| `官网` | `dist/网站` | 先清空 `dist/网站`、写 `dist/语言来源.txt`，再用正在运行的豫构编出网站资料生成并运行，写出主站与 docs 站共用的页面（页面稿生成教程、指南、技术文档页，内容里的产品目录写成 `products/`，响应头与转址写成 `_headers`、`_redirects`）；最后用正在运行的豫构编出网站产物守卫并运行（纯豫言，编成本机程序），核对问答数据、静态正文、站内链接与技术文档索引。页面应用的网页汇编产物由别的流程构建。 |
| `文档站` | `dist/文档站` | 依赖 `官网`，先备好诺驿宿主旁的值桥、进程资源、文件定位与传输控制四个共享模块（用正在运行的豫构编出值桥生成程序并运行，产物写到 `豫言操作系统/宿主/节点/`），再在 `dist/网站` 上依次以模拟模式编出并运行共用界面、首页、技术文档、产品四个静态渲染脚本（发行的包根是 `库` 与 `应用/书院/门庭`，页面应用可以依赖门庭下的子包，如产品依赖页录），写成不带脚本与网页汇编文件的 HTML 与 CSS；最后由共用界面包里的收尾脚本给每页顶上挂横幅、清掉除横幅那一条以外的全部去主站链接，并核对产物（每页恰好一条带 `data-主站入口` 标记的主站链接、没有别的 `href`、`src`、`action` 指主站、没有死链、`_redirects` 无转主站规则、`sitemap.xml` 与 `robots.txt` 的主机是 docs 站），不合就让目标失败。上传 Pages 由社区包仓库的 CI 做。 |

## 构建日志

构建类命令（构建、类型检查、文件与仓库目标）每次在当前目录的 `.构建日志/运行/` 下新建一次运行（路径一律用正斜线，轩窗上也如此：执行器的绝对路径写作 `/C:/a/b`，宿主写文件补建上级目录时只认正斜线），记下命令、提交、负载、包发现与包图等区间的用时；它启动的嵌套豫构与编译器经环境变量加入同一次运行，各写一份事件文件。`豫言构建日志=0` 关闭，`豫言构建日志目录` 改根目录，`豫言构建日志标签` 贴标签。格式见[构建日志格式](../性能研究/构建性能/日志格式.汉语.md)，分析用 `构建性能`。
