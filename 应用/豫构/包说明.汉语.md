# 豫构

发现软件包、解析依赖并调度编译；构建云工、浏览器、节点、原生与豫行发行物；运行语言仓的仓库目标。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为可执行文件类型，不可被其他包依赖；包内模块仍可互相引用。类型典中的入口和文件名见包配置，程序产物为 `豫构`。

## 使用

在仓库根目录运行：

```sh
./豫构。林檎。豫行 检查 豫构
./豫构。林檎。豫行 构建 豫构
./豫构。林檎。豫行 发现 --树
```

最后一条按层级（「包含包」／「包含在」）打印全部包树，用来浏览仓库里的包。

## 运行脚本

`豫构 运行 路径 参数…` 把一个 `。脚本。豫`（或任何 `。豫` 程序文件）连同它依赖的模块编成装载单元（提案 00003），装进豫构自己的进程运行：

```sh
./豫构。林檎。豫行 运行 应用/豫构/脚本样例/例一。脚本。豫 甲 乙
```

- 脚本看到的程序名是脚本路径，命令行参数是路径之后的参数（原样交给脚本，不当作豫构选项）。
- 包与仓库根按脚本所在位置找：仓库根依次从脚本所在目录、当前目录、豫构所在目录往上找（含 `库/豫章` 的目录），再看豫构旁边的 `源`（日用发行）与 `/源`（豫言操作系统的工具链盘）；构建期间切到仓库根，运行脚本前切回原来的当前目录。不属于任何包的脚本（如 `/数据/甲。脚本。豫`）拷进自动生成的包「脚本运行」（`.豫构缓存/脚本外部包/豫言/脚本运行/`，依赖标准库与壳命令）再编译，程序名仍是原路径，改了原文件下次运行会重编。
- 单元放在当前目录 `.豫构缓存/单元运行/` 下按脚本绝对路径排的目录里，目录里的 `印记.txt` 记着豫构、单元目标、执行器与各模块源文件的摘要；印记相同就不再调用编译器，直接装入，打印探针这样的脚本整个运行约 30 毫秒。要重新编译时编译器只为改过的模块生成原生单元，其余从 `.豫构缓存/单元缓存/` 按内容取用。
- 设环境变量 `豫构运行计时` 时在标准错误打印构建与装入运行各用的毫秒数。
- 脚本首行可以写 `#!/usr/bin/env -S 豫构 运行`（`豫构` 在 PATH 里时），编译器把首行当作空白；`应用/豫构/脚本样例/首行。脚本。豫` 是例子。
- macOS ARM64 的原生豫构把原生单元装进自己的进程，豫构旁须有执行器 `执行器。树码`（或 `执行器.wasm`）。诺驿（`node 豫言操作系统/宿主/节点/宿主.cjs 豫构.wasm 运行 …`）、轩窗与 Linux 上编成网页汇编单元（放在 `.豫构缓存/单元运行诺驿/` 下，目录里的 `程序名.txt` 记脚本路径），由诺驿宿主另起子进程装入运行，脚本的退出码就是命令的退出码；缓存命中时约 0.2 秒。豫言操作系统两架构里同样装入原生单元：开机的豫构与盘上的 `/工具/豫构。豫行` 都能运行脚本（造盘时加 `--工具链`）。`应用/豫构/脚本样例/` 里是提案例一至例三的宿主版，两种运行方式输出相同。

## 交互

`豫构 交互` 逐句读入豫言并运行（提案 00003 第 3 步）：

```text
壳> 「案牍」之「列目」于『应用/豫构』
入口。豫
…
壳> 「源」者『应用/豫构/脚本样例』也
壳> 「藏书」之「列目」于「源」
「列」【『例一。脚本。豫』，…】
壳> 「加」于「12」于「30」
「42」
```

- 会话开头相当于已写了 `寻观「豫章」之书。寻观「诏令」之书。寻「诏令」之「案牍」之书。寻「诏令」之「实现」之书。寻「豫章」之「寓所」之「藏书」之书。寻「豫章」之「寓所」之「号令」之书。`（宿主与豫言操作系统相同）：[壳命令](../../库/诏令/包说明.汉语.md)（如 `「案牍」之「列目」于『/』`、`「行」于『/bin/echo』于「列」【『甲』】`）与标准库直接可用。一行里的句子都闭合时依次处理，行末的句号可以省略；没闭合时印续行提示 `…> ` 接着读。`「名」乃…` 与随后的同名定义合成一组。
- 每句（含壳命令）都编成组单元运行，不设快路；只有用户输入才编译（2026-10-14 用户定）。会话做法（「实现」之「登会话做法」）在装入前导单元时登记，请求文件、编译器与异常标志作为单元的命令行参数传入，会话开头不编译。豫言操作系统里的壳命令做法分部按需装入：每编一句之前，句中用到哪些部（见 [用户态桌面](../../库/几席/包说明.汉语.md) 的 `部居`），就装入这些部造盘时预编好的单元并运行登记脚本，开机壳、桌面终端与远程登录的会话相同。会话开头依次执行开头句（开机壳给开机自启的各句；`豫构 交互 --开头句 句` 给命令行上的各句，2026-10-14 起桌面终端把用户输入的第一行这样交给新会话）。开头句与读到的行一样先切成句子，一行可以有几句或只有注释。
- 每组在豫构进程里编译（语法分析、名称解析、类型检查、闭包转换），生成原生单元后装入运行；前面各组的定义在后面的组里可用，后定义遮住前定义。一组导入了还没装进来的模块时，先把这些模块编成单元装进来。
- 命令脚本：`「脚本」于『路径.txt』` 把文件的每一行当作交互的一句处理，先印 `+ 行`，出错继续；只有空白与注释的行跳过；`「脚本」于『甲。脚本。豫』` 交给 `豫构 运行`。
- 最后一句是裸式时按类型印值：整数与小数印成 `「…」`，字符串 `『…』`，爻 `「阳」` `「阴」`，列 `「列」【…】`，元组 `（… 与 …）`，无参函数印它的结果；类型为「有」的句子只运行。
- 编译出错或有异常没接住时，打印诊断并丢弃这一组，会话继续；读到输入末尾结束，退出码是最后一句出错为 1、否则为 0。输入分两种，命令行可指定（2026-10-16 用户定）：`豫构 交互 --组字` 是交互输入，逐键编辑，有输入法（拼音组字）、候选、补全与历史，用壳核心的「闻言」，与开机壳是同一个编辑器（读行时终端在原始模式，读完恢复；空行上按 Ctrl+D 结束会话，Ctrl+C 放弃正在输入的行）；`豫构 交互 --直读` 是非交互输入，原样按行读入，不经输入法与补全（豫言操作系统开机控制台上用壳核心的「直闻」逐键读，等键时照办子任务的消息与「图形」请求）。都不写时标准输入是终端（且没有 `--提示`）就组字，否则直读。宿主原生、豫行启动器与豫言操作系统里相同。`--编译器 路径` 另指编译器（缺省是豫构自己，执行器取编译器旁边的 `执行器。树码`）；`--先装前导` 在前导单元已经编好时一起来就装入（没编好不装，留到第一句）。直读时标准输入是终端才印提示符 `壳> `；`豫构 交互 --提示` 每行之前都印（桌面终端与远程登录把会话开在管道上，见提示符就知道上一句办完了）。`豫构 交互 --直读 --回执 标记` 每读新的一句之前印一行 `标记 成` 或 `标记 败`（上一句的成败，会话开头为成；败即上一句没编出来、编译出错或有异常没接住），续行印 `标记 续`，代替提示符，编程智能体捉刀（提案 00036）据此知道一句办完、成败如何。`豫构 交互 --预装` 一起来就装入前导单元（不印装入提示），开头句办完、第一次读行之前印一行 `豫构交互：备用会话已就绪`；远程登录预先起一个这样的备用会话，exec 来了直接接手。
- 只编译：`豫构 交互 --直读 --只编译 --开头句 句…` 把开头句逐句编译（裸式要印值的也编第二遍）、不装入运行，每句先在标准错误印 `+ 句`，编不过的句后跟诊断；编完就返回，不读标准输入，有一句没编过退出码为 1。`应用/豫构/林纳对照。测试。豫` 用它核对 LOCALAGENTS.md 第八节“壳命令与林纳命令对照”里的例句（`豫构 目标 豫构测试` 与全树测试都跑）。
- 会话的源文件写在仓库根的 `.豫构缓存/交互外部包/豫言/交互会话/` 下；仓库根先看豫构旁边的 `源` 目录（日用发行：单文件旁放一份源码树，在哪个目录起都用它，前导只编一次），再从当前目录往上找，找不到再从豫构所在目录往上找，都找不到时什么句子都运行不了（豫言操作系统里仓库根是 `/源`）。第一句（或预装）时准备会话包与前导单元；会话目录 `会话<纳秒><随机后缀>/` 里放各组的源文件、请求文件与异常标志。原生豫构（macOS ARM64、Linux x86-64、豫言操作系统两架构）与豫行启动器（macOS、Linux 两架构）里的豫构豫行上编成原生单元。单元目录的印记与单元缓存的键里记着单元的目标系统与架构，启动器里的豫构豫行与原生豫构共用一个仓库时互不误用。每句约 50 毫秒（实测见提案 00003 实施记录）。
- 预编前导：`豫构 预编前导 仓根 [-- 编译器参数…]` 照交互第一次编译时的做法，为仓根下的交互会话备好会话包与前导单元，为豫言操作系统预编时连同各部的单元，前导与各部在一次多程序调用里一起编（编译器是豫构自己，执行器是它旁边的 `执行器。树码`），单元与编译缓存留在仓根与编译器目录的 `.豫构缓存` 里；`--` 之后的参数接在单元参数之后交给编译器（如 `--目标系统 豫言 --目标架构 臂六十四`）。豫言系统造盘时在宿主上以照盘内摆好的树为虚根（客体二号的环境变量 `豫言根目录`）运行它，把结果放进盘。

## 开机程序

`开机。豫` 是豫言操作系统的开机程序入口（提案 00003 第 8 步）：造两架构启动盘时，豫言系统把它编成开机程序，开机就进豫构的交互模式（做法在 `开机壳。豫`）。文件与环境命令照库 用户态桌面 的命令壳（已授“桌面”根下的路径、.环境），「行」「营启盘」同步运行子程序，「图形」进入桌面，「辞」结束。全系统只有一个壳（2026-10-16）：开机壳与宿主、桌面终端、远程登录一样经「交互命令」进会话，输入方式也由交互参数选：`/系统/开机。数据。豫` 的「交互参数」（如 `「交互参数」者「列」【『--直读』】也。`），没有这个文件或这一项时为 `--组字`（逐键编辑：拼音组字、候选、补全、历史，Ctrl-C 放弃这一行）；`--直读` 原样按行读入，串口脚本整行送进来不经拼音。每句都用盘上的 `/工具/豫构。豫行`、`/工具/执行器。树码` 与源码树 `/源` 编译，编译缓存的程序标识取 `/工具/豫构。豫行。摘要`，与盘上的豫构共用缓存；造盘缺省带工具链，盘上没有工具链时什么句子都运行不了。开机自启（`/系统/开机自启`）的各句当会话的开头句（`--开头句`）编译执行；「图形」写下进入桌面的请求（见库 用户态桌面 的壳请求），读下一行之前与等键的空当在这里进入桌面。造盘时已预编前导单元（单元目录印记与盘上的相符）时，开机就把前导单元装进来再读第一句（`--先装前导`），第一句不再等编译与装载。开机最先看有没有「葺寓」暂存的 `/新版`（2026-10-17）：有就运行 `安装系统 换上`，这次开机是新系统的试启时把暂存的 `/源` 与 `/工具` 换上，否则删去暂存，之后才读程序标识、找仓根、进会话。带参数运行时就是普通的豫构。

## 发行

`豫构 发行` 把应用连同它用到的操作系统接口构建成能在云工、浏览器、节点或原生宿主上直接运行的发行物：读包描述、解析依赖、按宿主选适配并绑定、生成包上下文、编译、复制宿主外壳、封装接口清单，一条命令完成；编译器缺省用豫构自己。`豫构 接口检查`、`豫构 接口绑定` 与 `豫构 装载接口` 单独提供其中的接口检查、绑定与清单封装。源码在 `发行/`，用法见 [发行](文档/发行.汉语.md)、[接口检查](文档/接口检查.汉语.md)、[接口绑定](文档/接口绑定.汉语.md)、[装载接口](文档/装载接口.汉语.md)。

```sh
./豫构。林檎。豫行 发行 节点 豫言操作系统/宿主/节点/一致性验证/应用 dist/节点一致性
```

在 macOS 与 Linux 上跑过仓库目标「全部」后，还有原生豫构 `./豫构。林檎。豫行`：命令与上面相同（如 `./豫构。林檎。豫行 构建 豫构`），比 Node 版快，是日常构建的默认工具。豫构带着编译器（提案 00007 合一，见库 编译器入口）：没写 `--编译器` 时用自己当编译器，并行编译的工作进程也是同一个程序文件；首个参数是源文件、`stage`、`debug`、`--mode=…` 或 `--原生产物子进程` 时，豫构按编译器运行。原生豫构启动的 `.wasm` 子程序改经 node 运行。

默认产物（提案 00007 议一）：在 macOS、Linux 与豫言操作系统上，编译器旁有执行器 `执行器。树码`（仓库目标「全部」经「执行器」生成；豫言操作系统里是 AMD64 数据盘的 `/工具/执行器。树码`）时，`构建` 与 `文件` 默认产出本机原生可执行文件（macOS 为 Mach-O，Linux 为 ELF，豫言操作系统为豫行文件），由编译器在最终链接里直出，不经 `.wasm`：豫构给编译器加 `--目标 本机 --执行器 执行器。树码 --降级缓存 <共享缓存>/降级/产物名.机器片`（传的是绝对路径：执行器取编译器所在目录里的，降级缓存放在共享缓存里，见下节；编译器在自己的目录下运行）。`--输出` 以 `.wasm` 结尾时产出 `.wasm`，以 `。树码` 结尾时产出汇编树码；没写 `--输出` 时产物名是包的程序名加本机系统的后缀：macOS 加 `。林檎。豫行`，Linux 加 `。林纳。豫行`，豫言操作系统里产出豫行文件，不加后缀。编译器参数里已写 `--目标` 时豫构不再添加目标与执行器；写的是 `--目标 本机` 而没写 `--降级缓存` 时补上降级缓存，文件名带上目标系统与架构（如 `降级/豫构。豫行-豫言-兼容六十四.机器片`）；交叉目标（`--目标系统`、`--目标架构`）与底层程序的写法见[编译器包说明](../豫言编译器/包说明.汉语.md)“原生产物”。Windows 与找不到执行器时仍产出 `.wasm`。

依赖及说明路径以 [包配置](豫构。包。豫) 为准。构建不会自动运行程序；有发布或服务副作用的工具应先阅读其入口源码。

## 共享缓存与多程序构建

编译缓存放在共享缓存根里（提案 00034）：环境变量 `YY_CACHE_DIR` 给出的目录，没有时是 `/tmp/豫构缓存-<用户名>`（豫言操作系统里是当前目录的 `.豫构缓存`）。根下按编译语义号分目录，语义号写在库 译场 的 `译料/译设/语义号。数据。豫`，编译语义变了就换（规则见 AGENTS.md）。语义号目录里有：

- `引/<仓库根>/`：各工作树自己的阶段缓存，按修改时间判新旧；每份缓存旁边的“。记”记着写出时的阶段键与内容摘要。
- `键/` 与 `物/`：按内容寻址的共享阶段缓存。阶段键是输入清单的沙二五六：编译语义号、信息名、模块缓存身份，以及源文件摘要或本模块上一阶段与各导入模块同阶段产物的摘要。键库存产物摘要，旁边的“。料”存输入清单；物库按摘要存产物。本工作树的缓存过时时先按阶段键查这里，命中就直接取来。
- `产物/`：最终链接的成品，键是链接键清单（编译语义号、产物名、目标、执行器摘要、原生目标、各模块闭包形式与元数的摘要）的沙二五六；豫行文件旁的“。摘要”一起存取。
- `降级/`：原生产物的降级（机器片）缓存与整产物缓存，按产物名（与目标系统、架构）分文件。

模块缓存身份与包的缓存编号都去掉仓库根，名称解析起的各阶段与最终链接成品在不同工作树里命中同一份缓存；文件依赖、抽象语法与语义标记记着绝对路径，留在各工作树自己的阶段缓存里。编译器参数 `--do-not-load-cache` 让各阶段与最终链接都从头算；仓库目标「全部」的三级用它冷编，二、三级逐字节相同就证明编译语义号没有漏换。

一次豫构调用可以构建多个程序：

```sh
./豫构。林檎。豫行 构建 包甲 --输出 甲 --又 构建 包乙 [入口段…] --输出 乙 --又 文件 路径 --输出 丙 --编参 --开机程序 -j 24 -- 公共编译器参数…
```

前端只编一次各程序依赖的并集，再各自做最终链接；`--编参` 后面的一个参数只交给本组程序的最终链接，`--` 之后的编译器参数各程序共用。各程序的最终链接与原生生成由豫构另起进程并行，同时至多 `YY_链接并行数` 个（缺省为核数除以六、在一到三之间），依赖模块多的程序先链。造盘的开机程序与豫行工具就是这样一次编完的。加 `--链参存 文件` 时只编前端，把各程序的最终链接参数存进这个文件；之后 `豫构 链接 文件 [--只链 前缀] [--编译器 编译器]` 接着链，`--只链` 只链输出路径以前缀开头的程序（造盘时两种架构的前端由父进程一次编完，两边子进程各链各的）。
## 构建服务（将作）

每台机器每个用户一个常驻构建服务（提案 00035）。并行编译开头找本机服务，没有就在后台起一个（服务先脱离调用者的会话：macOS 上经借道调 setsid，Linux 上经 setsid 程序起；再切到会合点 `~/.豫构/将作`），此后每个任务交服务执行：全机按槽数（缺省在线核数减一，`YY_将作槽数` 可改）排队，先按优先级（`YY_将作优先`：交互、前台、后台），同级给在跑任务最少的构建。服务按工具链（程序文件的沙二五六，硬链接进 `~/.豫构/将作/工具链/<指纹>/`）起代役（`<工具链> 将作 代役`），任务在代役里执行：工作任务交代役的常驻工作进程（带境任务帧，每个任务在客的工作目录里、照客的环境变量执行），同一指纹的几个工作树共用一个代役与一池常驻工作进程；代役闲置十分钟退出。客的连接断了，它的任务撤销；代役断了，手上的任务退回各客本机执行；服务不在时照旧自己并行。连接的第一行都带令牌（`~/.豫构/将作/令牌`，权限 0600），服务只认同一用户。消息都是一行数据子语言（籍册）。服务启动时写门文件 `~/.豫构/将作/门。数据。豫`（端口与启动时刻）。

服务首次运行时生成虎符（`~/.豫构/将作/虎符`：三十二字节随机数的十六进制，权限 0600），所以缺省就在 0.0.0.0 监听，并开多播名籍（邻籍）：服务类型 `_yuyan-build._tcp.local`，实例 `将作＠<主机名>`，TXT 带节点号、虎符指纹、平台、核数与协议版本；启动时自报并查询，此后每六十秒一次，停止时告别。虎符指纹相同的服务互相发现，节点号（会合点下的 `节点`）小的一方主动连对方：双方各出随机数，以虎符对随机数与节点号的密钥杂凑码互证（合符），之后结为同僚链路，链路上每行附会话钥对行序与行文的杂凑码。同僚每秒互发报况（槽数、空槽、排队、一分钟负载与快照），五秒收不到就断开、标为离线，之后每十秒重试。设置文件 `~/.豫构/将作/设置。数据。豫` 的「同僚」列静态同僚（`「同僚」者「列」【『192.168.86.187』】也。`，每项“主机”或“主机:端口”），多播不通时照样结交。虎符指纹不同的机器列在同僚表下、标为未入盟：在一台上运行 `豫构 将作 入盟 <ssh 主机>` 把虎符拷过去，对方运行 `豫构 将作 重启` 后两边结交。有同僚链路的服务不因空闲退出。构建时设 `YY_将作=关` 则不用服务，也就不开局域网。`dns-sd -B _yuyan-build._tcp`（macOS）与 `avahi-browse _yuyan-build._tcp`（Linux）可以直接看到各服务。在 macOS 上，起服务的会话（终端或 ssh）要一直开着，服务才能收发局域网（系统的本地网络隐私按起它的会话放行）；由 launchd 托管留待后续版本。

同僚之间互借缓存、互托任务（提案 00035 第四步）：

- **邻家缓存**：托出办成、回本机重放的任务（服务派役时标邻取，代役给它加环境变量 `YY_将作邻取`），编译阶段在共享缓存里查不到阶段键时，请服务向各同僚要这一键（每次未命中都问会拖慢冷构建，所以只在重放时问）；同僚答来产物（卦文编码，核过沙二五六）就写进本机共享缓存，当作命中。
- **托役**：本机槽位全满、排队超过二百毫秒的编译阶段任务（类型检查与擦除、跨模块优化、闭包前优化、ANF、全码生成），托给报来有空槽的同僚（空槽按同僚的槽数、在跑任务与一分钟负载算）；同僚办完回托毕，本机把任务放回排队最前、马上重放，这时各阶段多半能从同僚取到（邻家缓存），重放只是取回与校验。同僚失败、拒绝或断线时任务照常在本机执行，结果总与全在本机执行相同。只托语义号相同的同僚；托主的仓库根要能补出同长的镜像根。
- **借场**：受托方为每个托主仓库根在临时目录下建一个与托主仓库根同字节长的镜像根，用自己的二进制、以镜像根为工作目录执行任务（环境变量 `YY_将作借场` 标明借场），缺的阶段缓存文件、包上下文与源文件按相对路径向托主要，含托主仓库根的内容按字节换成镜像根。受托方只接白名单里的阶段、参数里的绝对路径必须在托主仓库根下，托主只为自己托出过的仓库根答文件请求。

- **远作**：环境变量 `YY_将作远作` 给了云端缓存的根网址时，同僚也没有的阶段键再问远作：每个进程先探一次“根/语义号/有”，有才经系统的 curl 取“根/语义号/键/前二/阶段键”与“根/语义号/物/前二/摘要”，核对沙二五六后写进本机共享缓存。现在只用局域网发现，云端的读写接口留待后续版本。

`豫构 将作 状态` 的首行在有托役时显示托出与受托的任务数、从同僚取到的缓存条数（邻取）与借场取到的文件数（借取）。工具链按编译语义号认同一；在同僚上备工具链（利器）与抽验留待后续版本。

- `豫构 将作 运行 [--后台]`：在将作端口（缺省 37411，`YY_将作端口` 可改）运行服务，缺省监听 0.0.0.0（写不成虎符时只监听 127.0.0.1）；没有构建、没有同僚链路满三小时自动退出。
- `豫构 将作 启动`：在后台起服务（已在运行就不动）。
- `豫构 将作 重启`：请服务停止，等它退出，再在后台起新的（入盟或换了程序后用）。
- `豫构 将作 状态 [--数据]`：打印快照（槽位、排队、各构建及其任务图进度、运行中的任务、各代役，再接同僚表）；`--数据` 打印数据子语言的快照，便于程序读取。
- `豫构 将作 役 [--数据]`：打印运行中与排队中的任务（执行处、已运行或已等待时长）。
- `豫构 将作 同僚`：打印同僚表（名字、平台、核数、状态、负载、空槽与槽数、排队、地址与来源）；首行写本机实例名、节点号与已收的邻籍报文数；其下列五分钟内见到的未入盟机器（名字、平台、核数、地址）。
- `豫构 将作 入盟 <ssh 主机>`：本机没有虎符就生成一份，经系统的 ssh 与 scp 拷到对方的会合点；之后两边各运行 `豫构 将作 重启`。
- `豫构 将作 代役 <端口> <指纹>`：代役进程的入口，由服务起。
- `豫构 将作 停止`：请服务退出，各构建退回本机执行。
- `豫构 监工 [--全网]`：订阅服务，原地刷新显示本机各构建与运行中的任务；`--全网` 在本机快照之后接各在线同僚报来的快照；不是终端时每五秒打印一次。
- `YY_将作=关`、CI 环境（有 `CI` 环境变量）、`.wasm` 编译器不用服务。

## 构建日志

构建类命令（构建、类型检查、文件与仓库目标）每次在当前目录的 `.构建日志/运行/` 下新建一次运行，记下命令、提交、负载、包发现与包图等区间的用时；它启动的嵌套豫构与编译器经环境变量加入同一次运行，各写一份事件文件。`YY_BUILD_LOG=0` 关闭，`YY_BUILD_LOG_DIR` 改根目录，`YY_BUILD_LOG_TAG` 贴标签。格式见[构建日志格式](../性能研究/构建性能/日志格式.汉语.md)，分析用 `构建性能`。
