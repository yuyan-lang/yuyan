# 内建列表构造子

## 目标

把列表构造子变成内建，减少解析和类型检查开销，同时改善源码可读性。

预期的列表表面语法是：

```text
列
罄
缀
：：
【】
，
```

`多` 和 `空` 是历史名称，应迁移为：

```text
多 -> 缀
空 -> 罄
```

## 内建语义

新增内建列表常量：

```text
内建类型列
内建列罄
内建列缀
```

它们的类型是：

```text
列 : 元类型 -> 元类型
罄 : {甲 : 元类型} -> 列 甲
缀 : {甲 : 元类型} -> 甲 -> 列 甲 -> 列 甲
```

`缀` 和 `罄` 应该表现为构造器，而不是普通函数。

优先复用现有构造器路径：

```text
唯一构造器节点
展开后唯一构造器节点
```

编译器可以为内建列表构造器分配固定构造器序数，例如：

```text
内建列罄构造器序数 = -1001
内建列缀构造器序数 = -1002
```

使用负数序数前，需要确认后续阶段没有假设构造器序数必须为正。若存在正数假设，则改用保留的高位正数范围。

## 操作符

新增这些操作符：

```text
【】
〇：：〇
〇，〇
```

`：：` 是面向用户的 cons 操作符：

```text
甲 ：： 乙
```

展开为：

```text
缀 甲 乙
```

`：：` 应该右结合：

```text
甲 ：： 乙 ：： 罄
```

表示：

```text
甲 ：： (乙 ：： 罄)
```

列表字面量语法：

```text
【】
【甲】
【甲，乙，丙】
```

展开为：

```text
罄
缀 甲 罄
缀 甲 (缀 乙 (缀 丙 罄))
```

`，` 初期只作为列表字面量内部的解析期序列操作符使用，不应残留到类型检查阶段。

## 解析形态

推荐实现方式：

1. `，` 在列表括号内部构建解析期序列。
2. `【...】` 消费该序列，并右折叠为 `缀 ... 罄`。
3. 最终 AST 只包含普通的 `缀/罄` 应用；如果更干净，也可以直接生成内建构造器节点。

除非确实必要，不要新增需要序列化的列表字面量 AST 节点。

## 豫言编译器改动

更新豫言编译器：

1. 为 `列/罄/缀` 添加内建常量。
2. 添加这些内建常量的字符串表示。
3. 在解析或去糖化阶段直接解析源名：

```text
列 -> 内建类型列
罄 -> 内建列罄
缀 -> 内建列缀
```

4. 迁移期间可暂时保留兼容：

```text
多 -> 内建列缀
空 -> 内建列罄
```

5. 让 `内建物类型` 返回正确的依赖函数类型。
6. 让 `罄/缀` 通过现有构造器机制降到固定构造器序数。
7. 确保模式匹配、类型擦除、CPS 和代码生成仍通过现有构造器路径工作。

## SML 编译器改动

同步更新 SML 编译器：

1. 在 SML AST 层添加内建列表类型/构造器表示。
2. 更新表达式构造，使这些名称解析为内建：

```text
列
罄
缀
多
空
```

3. 为 `罄` 和 `缀` 添加固定构造器序数。
4. 复用现有 `CConsInfoTypeConstructor` / `CConsInfoElementConstructor` 路径。
5. 除非现有构造器路径无法支持，否则不要引入新的列表运行时。

## 迁移顺序

1. 先机械替换完整标识符：

```text
「多」 -> 「缀」
「空」 -> 「罄」
```

只替换完整引号标识符。不要误改这些复合名：

```text
多态列
空缺
空值节点
空串典
```

2. 添加 `列/罄/缀` 的内建支持。
3. 添加 `：：`。
4. 添加 `【】` 和 `，` 的列表字面量语法。
5. 自举成功后，再移除标准库中 `列/罄/缀` 的普通声明。
6. 可选：把嵌套 cons 表达式逐步迁移成列表字面量，提高可读性。

## 验证

编译器重新能解析后，先运行类型检查验证。

当豫言编译器和 SML 编译器都认同内建列表构造器及固定构造器序数后，再运行完整自举验证。
