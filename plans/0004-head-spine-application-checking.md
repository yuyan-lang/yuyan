# 函数应用头脊类型检查

## 目标

把函数应用的类型检查改成局部、可预测的 head-spine 问题。

目标形态是：

```text
h a b c
 -> 头 = h
 -> 脊 = [a, b, c]
```

这主要不是 AST 改动。真正重要的是类型检查算法：检查一次函数应用时引入的元变量，作用域必须限制在这一个应用问题内，不允许逃逸到后续类型检查。

## 当前问题

当前函数应用路径太接近重复二元应用：

```text
(((h a) b) c)
```

这会让隐式参数元变量过早创建，并且存活太久。结果是普通类型检查代码必须处理本该局部解决的未解元变量，整个系统会变得难以推理。

## 核心规则

类型检查函数应用时，先收集完整的头脊形态：

```text
h * [arg1, arg2, arg3]
```

然后把整个应用作为一个局部问题求解。

只有“有名字的隐式 Pi 参数”可以自动插入。普通箭头和无名 Pi 不应该被猜测。

应用问题结束时必须满足：

```text
所有应用局部元变量都已解析
```

若仍有未解元变量，立即报错。

## 检查模式

对于：

```text
h a b c <= T
```

步骤：

1. 合成 `h` 的类型，但不全局插入隐式参数。
2. 遍历整条 spine。
3. 只为有名字的隐式 Pi 参数插入局部元变量。
4. 用期望类型 `T` 约束最终结果类型。
5. 局部求解后，要求所有局部元变量都已解析。
6. 用已经确定的定义域检查各个参数。
7. 把检查后的表达式重建为普通嵌套应用。

重建后的 checked expression 可以继续使用现有表示：

```text
函数调用
CApp
```

head-spine 是算法内部表示，不一定要成为可序列化 AST 节点。

## 合成模式

合成模式应该保持简单，不做广义隐式参数猜测。

但可以保留一个有用的局部推断规则：

```text
h : {A : Type} -> A -> R[A]
x => X
-------------------------
h x => R[X]
```

也就是说：如果缺失的有名隐式类型参数后面紧跟一个显式参数，并且该显式参数可以合成类型，就用这个参数类型确定隐式参数。

初期规则应保持很窄：

```text
{A : Type} -> A -> ...
```

不要一开始就支持任意合一，例如：

```text
{A : Type} -> F A -> ...
```

这类能力以后确实需要时再加。

如果后续显式参数不能合成类型，则合成失败，要求用户添加类型标注或显式给出隐式参数。

## 结果影响

这允许常见的构造器式调用在第一个显式参数确定元素类型时完成合成：

```text
缀 1 ...
```

可以推出：

```text
A = 整数
```

但空的多态值仍然不能自行合成：

```text
罄
```

它必须在期望类型下检查，或由用户添加类型标注。

这是可接受且更理想的：有歧义的多态值不应静默创建会逃逸的元变量。

## 对列表字面量的影响

非空列表字面量如果通过 cons 类构造器展开，仍然可以在合成模式下工作：

```text
【1, 2, 3】
```

第一个元素可以确定元素类型。

空列表字面量保持为只能检查：

```text
【】
```

它需要期望类型或类型标注。

## 实现草图

豫言编译器和 SML 编译器都需要对应辅助函数：

```text
收集函数调用头脊
重建函数调用头脊
检查函数应用头脊
合成函数应用头脊
```

豫言编译器里已经有类似名称：

```text
收集函数调用头脊
重建函数调用头脊
```

需要复查这些已有 helper，并把它们接入主对象类型检查路径。

## 豫言编译器工作

1. 复查现有 `收集函数调用头脊` 和 `进行函数应用头脊类型合成`。
2. 用 head-spine 检查路径替换 `进行对象类型检查` 中的二元 `函数调用` 分支。
3. 把自动插入的元变量限制为应用局部的有名隐式参数。
4. 每个应用问题结束时立即检查是否还有未解元变量。
5. 检查后的输出仍保持为嵌套 `函数调用` 节点。
6. 新路径稳定后，移除或简化旧的全局隐式参数补全路径。

## SML 编译器工作

1. 把目前只用于模式匹配的 `toHeadSpineForm` 思路移动成共享表达式 helper。
2. 重写 `RApp` 的合成和检查，使其处理完整 spine。
3. 合成模式只实现 `{A : Type} -> A -> ...` 的窄局部推断规则。
4. 检查模式使用局部元变量，并在返回前要求全部解析。
5. 输出仍保持为嵌套 `CApp` 节点。

## 验证

先运行类型检查验证。

当豫言编译器和 SML 编译器实现一致后，再运行完整自举验证。
