# 定义级全局符号

## 目标

删除“每个文件在运行时对应一个全局元组”的表示。

文件仍然负责组织依赖和初始化顺序，但每个顶层定义拥有自己的全局符号。跨文件引用不再先读取文件元组，再按序数投影。

当前表示：

```text
文件定义引用(file, name, ordinal)
 -> 读取文件全局元组
 -> 元组投影 ordinal
```

目标表示：

```text
文件定义引用(file, name, ordinal)
 -> 读取该定义对应的全局符号
```

这里不是把定义内联到使用处。普通值仍然只初始化一次，所有引用共享同一个全局存储。

## 当前问题

类型擦除目前把所有 `文件定义引用节点` 统一降级为对文件全局元组的读取。随后，全局结构变量储存变换会：

1. 为文件分配一个元组。
2. 依次计算文件中的定义。
3. 把每个定义写入对应的元组槽位。
4. 把本文件和外部文件的定义引用改成元组投影。

因此，即使某个顶层名字是函数，它也会先成为文件元组中的闭包值。闭包转换看到的调用头不是 `函数引用节点`，而是运行时投影，所以无法生成直接函数调用。

## 核心规则

每个有运行时内容的顶层定义对应一个稳定符号：

```text
文件路径 + 定义名 + 定义序数 -> 全局符号
```

定义序数用于区分同文件中的内部名字；定义名用于可读性；文件路径用于跨文件唯一性。

文件初始化函数仍然存在，并保持依赖文件先初始化、当前文件后初始化的顺序。变化只是初始化目标从“文件元组槽位”变为“定义全局变量”。

## 第一阶段：删除文件全局元组

第一阶段只改变全局存储布局，不改变顶层函数的值语义。

现有的 `文件定义引用节点(file, name, ordinal)` 已经准确表示对某个顶层定义的引用。它不应在类型擦除时被转换成文件元组投影，而应保留到代码生成阶段，直接生成对定义级全局符号的读取。

因此不新增读取节点，只把现有两个文件级运行时节点替换为定义级节点：

```text
保留：文件定义引用节点(file, name, ordinal)
替换：全局路径变量存储节点(file)
   为：文件定义存储节点(file, name, ordinal)
替换：文件内存引用节点(file)
   为：文件定义内存引用节点(file, name, ordinal)
```

表达式值继续作为 `文件定义存储节点` 的普通 AST 参数，而不是节点名称参数。

这些节点保留文件、名字和序数，到代码生成阶段才转换成低级符号名。这样调试输出和序列化信息仍然明确。

现有的 `全局指针读取节点` 和 `全局指针更新节点` 不参与这次改造。它们操作的是运行时 `i128**` 指针全局变量，例如 GC 堆指针；顶层定义则是普通 `i128` 全局值，两者语义不同。

具体改动：

1. 删除类型擦除中对 `文件定义引用转运行时读取` 的调用，让 `文件定义引用节点` 保留到后续阶段。
2. 为 `文件定义引用节点` 补全正则变换和代码生成分支，直接读取对应的定义全局变量。
3. 文件定义列按原顺序求值，并通过 `文件定义存储节点` 分别写入对应的定义全局变量。
4. 代码生成器为当前文件的运行时定义生成 `i128` 全局变量。
5. 引用到依赖文件定义时，生成对应的 `external global i128` 声明。
6. 通过 `文件定义内存引用节点` 取得每个定义全局变量的地址，并注册为 GC root。
7. 删除文件元组的分配、填充和序数投影逻辑。

这一阶段中，顶层函数仍可作为闭包值存放在独立全局变量中。这样可以先验证新存储 ABI，而不同时修改函数调用和闭包转换。

## 第二阶段：顶层函数使用函数符号

第一阶段稳定后，再单独消除顶层函数闭包。

规则：

1. 顶层函数定义直接生成全局函数，不再生成保存闭包的 `i128` 全局变量。
2. 对顶层函数的引用在闭包转换前变成 `函数引用节点`。
3. 已完全应用的调用直接生成函数调用。
4. 顶层递归调用直接引用自身函数符号。
5. 普通顶层值继续使用定义级全局变量，并保持初始化一次的语义。
6. 类型定义在擦除后不产生运行时全局变量。
7. 构造器保留唯一构造器身份；是否进一步编译成直接函数符号另行处理。

部分应用暂不隐式制造顶层闭包。若调用处没有完全应用，应由此前约定的 eta 展开步骤生成显式 lambda；无法展开时报告错误。

## 导入与再导出

导入只改变名字解析，不产生新的运行时容器。

再导出优先直接指向原定义的全局符号，不复制值。若第一阶段暂时难以保留别名身份，可以先生成一个定义级别的别名全局变量，但最终应消除这层复制。

## GC 与初始化

删除文件元组后，原先只注册一个文件全局元组地址的做法不再正确。

第一阶段采用最直接的实现：通过 `文件定义内存引用节点` 取得当前文件每个运行时值全局变量的地址，并分别注册为 GC root。初始化顺序保持：

```text
初始化依赖文件
注册当前文件的定义全局变量
按源码顺序计算并写入当前文件定义
执行匿名顶层表达式
```

以后如果全局变量数量成为问题，可以生成静态 root 地址表；本次不引入该优化。

## 删除条件

以下旧设施应在第一阶段验证通过后删除，而不是长期并存：

```text
文件作为全局元组的代码生成
文件定义列全局结构变量储存转换
展开文件定义列
替换本文件定义引用
用于写入文件元组的全局路径变量存储节点
只取得文件元组地址的文件内存引用节点
只为文件元组注册 GC root 的逻辑
```

`文件引用节点` 若仍用于依赖和缓存身份可以暂时保留，但不能再表示运行时文件元组值。`文件定义引用节点` 则继续作为定义级读取节点使用。

## 不变量

第一阶段完成后必须满足：

```text
闭包转换后的树中不存在“文件全局元组 + 定义序数投影”
每个运行时顶层定义只初始化一次
跨文件引用读取唯一的定义级全局符号
所有定义级全局值均被 GC 正确追踪
```

第二阶段完成后额外满足：

```text
顶层函数不进入闭包转换
完全应用的顶层函数调用是直接调用
普通顶层值仍通过定义级全局变量共享
```

## 实施与验证顺序

1. 人工审查节点替换、符号命名和 GC 方案。
2. 实现第一阶段，删除文件元组表示。
3. 检查生成树中不再出现文件定义元组投影。
4. 运行类型检查验证。
5. 运行完整自举验证，确认新 ABI 可自举。
6. 单独实现第二阶段的顶层函数直调。
7. 再次运行完整自举验证，并检查闭包形式。

推荐严格分成两个阶段。第一阶段解决“文件不是运行时元组”，第二阶段解决“顶层函数不闭包转换”；这样失败时可以明确区分全局存储、GC、初始化和函数调用中的问题。
