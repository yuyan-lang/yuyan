# #711 余项：计算样式的键与值分型

现状（`d6d0447938` 之后）：计算样式已经按属性号存进槽，读写走「样式取值」「样式入」，不再是“键到文”的无类型簿。但「样式键」「样式值」还都是「文」的别名，调用处照旧传字符串名：拼错键名（『colr』）、把数值当颜色读、把关键词当长度用，都要到运行时才露。

这一页写改法与代价。分两步：先把**键**换成由属性表一份声明生成的不透明类型，再把**值**按属性分型。两步都可独立合入，第一步收益最大、代价最小。

## 一、键：每个属性一个常量，类型只此一家

### 目标

```豫言
「样式取值」于「样」于「色」        （「色」是属性常量，不是字符串）
「样式入」于「样」于「宽」于「一零px」  （宽只收长度；写成「色」编不过）
```

拼错的 `「色采」` 是未定义的名字，编译期即报；把颜色常量喂给只收长度的函数，也是编译期报。

### 做法

1. **一份声明**：`库/群书/网页部/装帧谱/属表。豫` 已经是唯一来源（307 条，含名、初值、是否继承）。在它上面加两列：**属性常量的雅名**（如 color → 「色」，width → 「宽」）与**值的类**（见第二步；第一步可先留空）。
2. **生成常量**：由属表生成一个新模块 `装帧/属性常量。豫`，形如

   ```豫言
   「属性」即「组类」【「号」乃「数」也】也。

   「色」乃「属性」者也。
   「色」者「组值」【「号」者「二」也】也。
   ...
   ```

   号写死不利于增删属性，改用 `「号」者（「属性号」于『color』）也`，常量在模块装入时求一次；常量名与表同源生成，改名只改表。
3. **接口换类型**：「样式取值」「样式入」「样式有号」「样式取或」四个入口收「属性」而不收「文」；内部仍按号走槽（`属性` 的号字段直取，零散列开销）。
4. **文本入口留一处**：解析外部 CSS、内联样式、CSSOM 取值仍以文为键，在 `装帧/语法` 与 `网页榫卯/样式声明` 里把文换成「属性」（查 `属性号`，查不到按现存行为丢弃该声明），转换错误就落在解析处，不再散到运行期。

### 代价

- 调用点：`样式取值` 684 处、`样式入` 104 处、`样式有号`／`样式取或` 25 处，全部机械替换成常量；`属性号` 只在文本入口出现。
- 新增一个生成模块（约 337 行：类定义 + 307 条常量 + 说明），随属表更新；生成步骤挂进「豫构 目标」或由属表模块直接导出全部常量（豫言无宏，倾向生成文件）。
- 兼容：`属性号 于 文` 保留给文本入口用，其余地方不再用它。

## 二、值：先分三类，再按属性收紧

### 目标

```豫言
「样式值」即「或」【「数」者「样式数」也，「色」者「样式色」也，「词」者「样式词」也】也。
「样式入长」乃化「计算样式」又化「属性」又化「样式数」为「计算样式」者也。
「样式入色」乃化「计算样式」又化「属性」又化「样式色」为「计算样式」者也。
```

### 做法

1. **三类**：`样式数`（长度、角度、时间、百分比、无单位数，内部存 `小数` + 单位枚举）、`样式色`（已有 `颜色` 类型与 `装帧/颜色` 的解析）、`样式词`（关键词与未识别的文）。
2. **表白名单**：属表再加一列“接受的类”（如 width 收数、color 收色与词、display 只收词），由它生成 `「属性类」于 属性 → 位掩码` 一张表。
3. **写入分型**：`样式入` 收 `样式值`，按 `属性类` 校验；编译期能定的（字面量）在编译期报，动态的（变量替换结果）在解析处报并退回初值——与现行“不合语法的声明整条丢弃”一致。
4. **读出分型**：`样式取值数`／`样式取值色`／`样式取值词` 三个读口，各自只在类允许时可用；`样式取值` 保留为“转回文”的兼容口，供 CSSOM 与序列化。
5. **内部存储**：槽仍存文（序列化后），三类只是出入口的类型；这样不必改槽的表示，也不影响另两路（样式变量、增量排版）。

### 代价

- 入口从 1 个变 4 个，调用点需按用途选读口；估 `样式取值` 的一半是“拿数值进布局”，可先只做 `样式取值数` 这一支，收益最大。
- 首期只做“数值类”分流，颜色与关键词留后；`calc`、`var()` 结果在替换后才定类，属于运行时校验，写清楚。

## 三、与另两路的边界

- **样式变量**：变量表按属性常量存（第一步落地后直接用「属性」）；变量替换写回时仍走 `样式入`。
- **增量排版**：只依赖 `级联算` 与 `样式取值`，键改成常量后调用签名不变（只是实参由文变常量），无需改它的脏标逻辑。
- **#768**：槽写入的越界保障与本次分型无关；`样式置皿` 的“已备足”前置条件可在第二步之后收进类型（`下标 于 长`），那时一并处理。

## 四、建议次序

1. 属表加“雅名”列 → 生成 `属性常量。豫` → 四个入口换类型 → 684+104+25 处替换 → 类型检查与 `网页一致性` 冒烟。工作量集中但机械，一次可完成。
2. 属表加“类”列 → `样式值` 三类 → 先只分流数值读口。
3. 其余（颜色、关键词、`calc` 后的动态校验），以及把“已备足槽”收进依值类型。


## 施工版（半页，2026-10-29）

**声明放哪**：唯一来源仍是 `装帧谱/属表。豫` 的「层叠属表」（现行 218 条：名、初值、是否继承）。加第四列「常量名」（`width` → 「性宽」，`margin-left` → 「性外边左」）。**号的次序由这张表的行序定**（属性号首次装表时按表序发号），不再由运行期先遇见谁决定，常量与号因此一一对应、可复现。

**常量怎么生成**：照 `应用/百工坊/网页一致性/实体生成。豫` 的样子写一只生成器 `应用/百工坊/装帧工具/属性常量生成。豫`：读属表 → 写成 `库/群书/网页部/装帧/属性常量。豫`：

```豫言
「属性」即「组类」【「号」乃「数」也】也。
「性色」者「组值」【「号」者（「属性号」于『color』）也】也。
「性宽」者「组值」【「号」者（「属性号」于『width』）也】也。
……
「性未知」乃化「文」为「属性」者也。   （文本入口用）
```

号在装入时求一次；生成物入库，步骤挂在 `豫构 目标`（名「属性常量」），CI 比对生成物是否与属表同步。

**接口**：`样式取值`／`样式入`／`样式有号`／`样式取或` 四口改收「属性」；旧按名版降为薄包装（`名样式取值` 等，内部 `「性未知」于名` 后转调），故可逐文件迁。

**迁移次序**：
1. 四口改类型 + 薄包装（一次改动，全树仍编得过）；
2. 热路第一批：`章法/块流`、`章法/随行`、`章法/弹性`、`章法/界格`（按采样排名取）；
3. 第二批：`章法` 其余（盒树、表格、内在、浮动…）与 `设色`；
4. 第三批：`篇象`、`网页榫卯`、`接引`；文本入口（解析样式表、CSSOM、脚本读写）只留 `「性未知」`。

**验收**：编译期——常量名写错即未定义，`样式入` 传文即类型不符；语义——`网页一致性` 的 css 目录同底对照 + 样式引擎对照冒烟；性能——`网页测速 量一 维基 0`、`量一 guanwang` 各两次取小，看「串散值／样式小写／属性号」是否退出前几名。
