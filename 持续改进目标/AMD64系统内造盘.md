# AMD64 系统内造盘

目标：在 yybs 最新代码上，AMD64 版豫言操作系统在自己里面用「构建启动盘」从源码造出与宿主逐字节相同的启动盘，并能用造出的盘再造一次自己。用户 2026-10-11 定。

由一个代理负责，工作树 `~/repos/yuyan-worktrees/AMD64系统内造盘`（分支同名）。与《[ARM64 系统内造盘](ARM64系统内造盘.md)》并行，协调办法见「规矩」。

## 验收

第一阶段（先做）：

1. 宿主用 yybs 最新提交造带工具链的启动盘；QEMU 里开机进开机豫构，输入「构建启动盘」，七步全部完成；系统里造出的 `/输出/yy豫言启动.iso` 与宿主同一提交造的逐字节相同。
2. 系统里造出的光盘在 SeaBIOS 与 OVMF 下都能启动进开机豫构。
3. KVM（pit-mbp13）与纯模拟（pit-mac 或本机）各跑通一次，各步耗时记进「进度」。

第二阶段（第一阶段通过后接着做）：

4. 系统里也造出合成镜像（光盘加数据区 `yy豫言启动盘.img`），与宿主同一提交造的逐字节相同；`系统内造盘` 去掉 `--只出光盘`。
5. 用系统里造出的合成镜像再启动、再「构建启动盘」一次，产物仍与宿主逐字节相同（不动点）。用户 2026-10-12 采纳评审：客体合成镜像与同源宿主逐字节相同，即具有相同的初始磁盘内容；在同样配置下再次启动造盘等同于已通过的首次运行，进度写明此论证即可验收，再造实测可最后后台执行。
6. 8 GiB 内存的客体用缺省参数「构建启动盘」能跑完：`--并行` 缺省按空闲内存（内核服务 45）与核数取小，不再只看核数。

用户 2026-10-12 采纳评审：当前诊断进程 293440 最终链接通过后，立即合入链接钩与清空任务图修复；在合入提交上用干净缓存跑 8 GiB、四核、缺省参数 KVM 全程，ISO 与合成镜像分别与同源宿主 cmp 通过即完成第六项。宿主继续以子进程链接，裸机以本进程链接，两者产物须逐字节相同。若当前轮仍在最终链接耗尽，则直接改为并行父进程退出后由调用方单独链接；此方案仍失败时停止并报告实测数字，结束新的诊断轮。

2026-10-11 节点额度修复后的全程复验：下列旧 1 GiB 命令保留作失败基线；新宿主参照的 `--盘容量` 用 `16777216`（8 GiB、262144 个文件节点），与修改后的 `系统内造盘` 相同。合成镜像仍复制后扩为 9 GiB；客体内存仍为 12 GiB、四核、缺省并行 4。第二阶段另按验收在 8 GiB 客体内存下使用缺省参数。

- 宿主造盘（仓库根，先照 AGENTS.md 起步得到原生工具链）：先 `./yy豫构.exe 文件 豫言操作系统/裸机/豫言系统。豫 --输出 yy豫言系统.wasm -j 24`，再 `YY_GC_INITIAL_HEAP_SIZE_MB=1024 node --max-old-space-size=24000 豫言操作系统/宿主/节点/宿主.cjs yy豫言系统.wasm 启动盘 --输出 目录 --预置 无 --工具链 --六十四位地址 --盘容量 2097152 --构 ./yy豫构.exe --编译器 ./yy4_bs.exe`（本机约 3 分钟），得宿主参照 `目录/yy豫言启动.iso` 与合成镜像 `目录/yy豫言启动盘.img`；造完 `git checkout -- 库/壳核心/拼音字库。豫`（造盘会改写它）。
- QEMU：合成镜像用 `cp -c` 复制后 `truncate -s 9G`。纯模拟 `qemu-system-x86_64 -machine q35 -accel tcg -cpu qemu64,+rdrand -m 12G -smp 4`，KVM 换成 `-accel kvm -cpu host`；共同部分 `-display none -no-reboot -monitor tcp:127.0.0.1:端口,server,nowait -chardev socket,id=s0,host=127.0.0.1,port=端口2,server=on,wait=off,logfile=串口日志 -serial chardev:s0 -drive if=none,id=yy_boot,format=raw,file=盘 -device qemu-xhci,id=xhci -device usb-storage,bus=xhci.0,drive=yy_boot,bootindex=1 -boot order=c`。串口出现“命令壳已就绪”后写入 `「构建启动盘」` 加回车（`\r`）。pit-mac 上的 `造盘测时.zsh` 可复制到自己的草稿目录改着用。
- 耗时：纯模拟全程约 4 小时（第 4 步约 47 分钟起）；KVM 约 1.5–2 小时。
- pit-mbp13 只有 8 GB 内存：以前给客体 24G 靠宿主换页也跑通过（约 6000 秒）。KVM 下宿主卡顿时，按轮询次数计的超时可能提早到期，表现为随机读坏数据（“阶段缓存须为树码”“找不到导出函数”之类），先怀疑这个。
- 取产物：数据区从合成镜像里光盘之后第一个 64 MiB 整数倍处起（现在光盘约 160 MB，数据区在 192 MiB），`dd` 出来后用 e2fsprogs 的 `debugfs`（`brew install e2fsprogs`）`dump /输出/yy豫言启动.iso`，或用 `持久盘读取。豫` 写个临时程序；`shasum -a 256` 比对。
- 冒烟：`yy豫言系统 冒烟 x.iso`（SeaBIOS），加 `--固件 /opt/homebrew/share/qemu/edk2-x86_64-code.fd --固件变量 /opt/homebrew/share/qemu/edk2-i386-vars.fd` 为 OVMF。
- 便宜检查：`./yy豫构.exe 类型检查 豫言内核 -j 24`、`./yy豫构.exe 类型检查 客体二号 -j 24`、`yy裸机验证`（342 项，约 70 秒，命令见 `ARM硬件交接.md`）。
