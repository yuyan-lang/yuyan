## pit-mac 用法

- 连接：`ssh pit-mac`（用户 zhiboc，免密，可加 `-o BatchMode=yes`；M2 Max、12 核、32 GB、Node 26）。非交互 ssh 的 PATH 没有 `/opt/homebrew/bin`，命令前加 `export PATH=/opt/homebrew/bin:$PATH` 或用 `zsh -lc "…"`。
- 每个任务一个克隆 `~/repos/yuyan-worktrees/<任务名>`：没有就 `git clone git@github.com:yuyan-lang/yuyan.git`，在同一基点建分支；已有同名目录先核对是不是本任务的。
- 同步：本机提交后 `git bundle create <文件> <基点>..<分支>`，scp 过去再 fetch（用户已在权限里放行 ssh、scp、rsync 到 pit-mac 与 git bundle）。`yy*.wasm`、`yy稳定节点宿主/`、`豫言操作系统/宿主/节点/yy节点值桥接.wasm` 等未跟踪的工具链另传，或在克隆里按 AGENTS.md 起步重建。远端提交用 `git -c user.name=zc`；带回本机任务工作树后，在本机 yybs 工作树按 sync 流程合入。
- 克隆里的坑：`yy草稿/` 下的包描述也会被豫构发现，临时包描述放仓库外（如 `~/yy草稿-<任务名>/`）；新克隆跑节点一致性前，先在仓根构建 yy豫言操作系统接口检查、yy豫言操作系统绑定、yy豫言操作系统装载包、yy双宿主构建；`yy4_bs.wasm`、`yy豫构.wasm` 嵌有工作树绝对路径，换目录构建的产物不会逐字节相同。云仓快照放在语言仓快照旁（`../yuyan`）；pit-mac 没有私有条款目录，云仓「网站构建」会停在条款检查。
- 长任务：远端 `nohup … > 日志 2>&1 < /dev/null & disown`，本机用后台命令或 Monitor 定时拉日志。前台 ssh 跑的任务会随会话被打断而中止。
- 各会话共用 zhiboc 账户：停进程只按自己克隆的路径或确切 PID，禁止 `pkill`、`killall` 泛匹配（node、宿主.cjs、qemu-system 之类）。用户 10-06 允许在 pit-mac 装软件，缺工具可直接 `brew install`。pit-mac 是开发机，可以随便操作（用户 10-06）；上面的 Ollama 随时可停。
