# 系统内工具链

目标：豫言操作系统里能跑**完整工具链**（豫构、编译器、预编二、格式化等），并放开内存与任务的上限。2026-10-06 用户定：

- 执行器的内存上限至少 **64 TB**；
- 任务数量至少与现代 Linux 同一水平，甚至更多；
- 系统里必须能跑完整工具链；
- 多任务要用多核（同日追加：多核也要做）。

由一个代理负责到底，工作树 `~/repos/yuyan-worktrees/系统内工具链`（分支 `codex/系统内工具链`），可以派子代理做调查或分块实现。

## 验收标准

1. **内存**：执行器管理的堆，设计上限不低于 64 TiB（64 位地址，按需提交物理页；实际可用量是机器的物理内存）。内核按固件内存表使用全部物理内存，不再只用写死的 64–128 MiB 池。
2. **任务**：任务号上限不低于 4,194,304（Linux 64 位系统常用的 pid_max）；能同时存在的任务数只受内存限制。起程序从盘上装载程序映像，不再复制父任务。
3. **多核**：内核启动全部处理器核，任务分到多个核上同时运行；系统里 `-j 24` 并行构建能用上多核。
4. **工具链**：在系统里用豫构构建并运行“你好世界”；再在系统里构建出编译器本身（与宿主上构建的逐字节相同，或说明差别）。
5. 以上在 QEMU（q35，SeaBIOS 与 OVMF）上验收；涉及实机的部分请用户在苹果笔记本上复测。

## 现状（2026-10-06 立项时）

- 内核（`豫言操作系统/裸机/库/裸机后端/`，豫言写的机器码）把动态内存块池写死在物理 64–128 MiB：32 块、每块 2 MiB，空闲位图只有一个 32 位字（0x121000），每个任务至多 32 块；不读固件内存表，16 GB 的机器也只用这一块。Limine 的模块落进这块池子时还会占块，苹果笔记本上桌面只拿到约 47 MB。
- 任务只有两个静态槽：代码区、页表、栈都在写死的物理地址上；「运行」靠复制父任务起子程序，桌面占满 32 块后复制失败，公测版里「运行」直接提示“还不能运行”。
- 执行器「客体二号」用底层模式写成，32 位地址：指针、对象引用、堆的位图与卡表都是 32 位偏移，按“内存上限”预先分配；裸机页上限 1024 页（64 MiB），macOS 原生 65535 页（约 4 GiB）。底层模式已支持 64 位地址内存（`声明内存六四`、`长址读四` 等），执行器与预编二还没用上。
- 编译器只产出 WasmGC；原生机器码由预编二从 Wasm 翻译（macOS、Linux 原生程序与裸机启动盘都这样来）。在 Mac 上不用缓存编译一个只打印一行的示例，进程峰值约 1.1 GB 内存。
- 只用一个处理器核（多任务也在一个核上轮转）。

## 做法（分步：先内存与任务，再多核与工具链，最后把上限推到 64 TB）

1. **内核按实际内存分配**：读固件内存表，建物理页分配器；用户地址空间用四级页表按需建（上限 128 TiB）；动态块池改由物理页分配器供给；执行器页上限先放到 Wasm32 的上限 65535 页（约 4 GiB）。
2. **任务数不设死**：任务表、页表、内核栈按需分配；任务号上限 4,194,304；「运行」改为装载程序映像（盘上的预编二原生映像或 Wasm），传参数、环境与工作目录；等待、退出、回收照旧。
3. **多核**：启动其余处理器核（ACPI MADT 找核，INIT-SIPI-SIPI 唤醒），每核一份内核栈与核内数据，调度队列加锁，改页表后跨核刷新 TLB；任务能在任一核上运行。
4. **系统里跑工具链**：造盘时把豫构、编译器、预编二等预编成原生映像放进系统；文件系统放大限额（单个文件句柄的 400 KB 内容缓冲、条目数等）、补齐工具链要的文件操作；豫构起编译器子进程；数据盘放仓库源码。验收：系统里构建并运行你好世界，再构建编译器。
5. **执行器 64 位**：预编二支持 64 位访存（memory64）；执行器指针与对象引用改 64 位，堆的位图、卡表按区按需提交；上限 64 TiB。Node、macOS/Linux 原生、裸机三处一起过。

- 2026-10-06：第一步（内核按实际内存分配）完成。AMD64 内核读 Multiboot 内存表（头标志加第 1 位），128 MiB 以上的整块 2 MiB 物理块记进 `0x130000` 的高区位图（覆盖 4 TiB）；动态区移到用户虚址 1 TiB（PML4 第 2 项，每槽一张 PDPT 加四张页目录），单任务上限 2048 块（4 GiB）；这部分代码放在 `0x1F0000` 的外置区。执行器页上限改由新的目标内建导入 `页容量` 给出（AMD64 裸机 65535 页，ARM64 裸机仍 1024 页）；增长助手用 movabs 装 1 TiB 基址；帧服务与字体服务的客体地址改按 64 位算（像素循环里一条 32 位的源指针加法曾把地址截断，进「图形」即内核缺页）。QEMU：2 GB 时最大块号 1022，进桌面后命令壳 128 块、执行器 4080 页；512 MB、1 GB 也进桌面，往返四轮正常，SeaBIOS 与 OVMF 冒烟通过。
  - 待办事项：执行器两次回收之间至少分配 32 MiB、翻倍到 1 GiB，原先被 1024 页上限压住，现在长命任务会长到约 1 GiB（1 GB 的机器上第三轮往返后停在约 751 MiB，靠物理内存用尽才回收）；第二步做多任务时要按空闲物理内存定回收下限。执行器的回收位图与卡表按上限预留，4 GiB 上限时每个任务先占约 144 MiB，第五步（执行器 64 位、按需提交）解决。
