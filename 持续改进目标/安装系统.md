# 安装系统

目标：ARM64 与 AMD64 启动镜像均提供「安装系统」命令，将当前启动介质安装到用户选择的内部磁盘。用户于 2026-10-12 确认本方案与 NVMe 优先顺序，并决定保留 `codex/光盘内存造盘` 分支，复用共用 AHCI、ATAPI 与内存写入层。

工作树：`~/repos/yuyan-worktrees/安装系统`，分支 `codex/安装系统`。本会话长期目标覆盖以下全部步骤，每项实现后做最少必要检查，及时合入并推送 yybs。

## 安装流程

1. 输入「安装系统」，列出内部磁盘的盘号、控制器、型号与容量。启动盘通过引导程序交给内核的 MBR 盘签名识别，候选清单排除启动盘。
2. 用户选择目标盘，并输入明确的整盘擦除确认；确认后开始写盘。
3. 以一 MiB 为段读取启动介质的合成镜像，包括 ISO 部分与数据区。读取盘首的块位图，复制范围截至数据区最后一个已用块。目标容量须容纳镜像声明的数据区。
4. 第零扇区最后写入。写入后同步，读回比对沙256；MBR 的第 440 字节起四字节改为新盘签名，核验时计入该差异。成功提示取出 U 盘或光盘并重启。
5. 安装后的盘继续使用混合 MBR、ESP 与 `EFI/BOOT/BOOT*.EFI`，沿用现有 BIOS 与 UEFI 引导。

## 实施顺序

1. 两架构共用的 NVMe 驱动，置于 `豫言操作系统/裸机/内核/`，用 `。底层。豫` 实现；复用现有设备枚举、内存与设备授权能力。
2. 多盘块服务：扩展现有服务 28–31 的单盘模型，支持列盘、按盘读取、写入与同步；同步接口声明、规范、执行器接线与适配清单。
3. 普通豫言安装程序与命令壳「安装系统」登记，使用列盘及按盘读写能力。两架构镜像均携带该程序。
4. 引导程序传递启动盘 MBR 签名；内核在各盘搜索数据区，挂载签名相符的启动盘。安装盘仍插着时，系统盘启动也挂载自己的数据区。
5. ARM64 镜像数据区增至八 GiB，与 AMD64 一致；U 盘需超过九 GB。
6. QEMU 的 edk2 与 NVMe 目标盘验证两架构安装及安装后开机；自建 Fusion 探针使用 NVMe 硬盘与 USB 安装盘验证。仅使用为本任务创建的测试盘与虚拟机。
7. 在光盘分支共用 AHCI 实现上补 ATA 硬盘读写与同步，验证 SATA 安装及光盘启动安装。

## 完成判据

- 两架构「安装系统」能列盘、排除启动盘、确认擦除、按规定复制、同步、读回核验与更新签名。
- 从已安装的 NVMe 盘启动后，数据区挂载正确；安装介质仍插着的情形通过。
- QEMU 两架构与自建 Fusion 探针取得安装和再次启动证据。
- AHCI 硬盘读写与光盘安装通过最少必要验证。
- 规范、双语使用文档与进度记录同步，全部实现合入 yybs 并推送。
