# 去网页汇编与 Windows 原生工具链

目标：把网页汇编（wasm）移出豫言体系，只留给浏览器与云工两个网页后端；顺带补齐 Windows 原生工具链。用户 2026-10-12 定（“除浏览器与云工目标外把 wasm 移出”“都要改，Windows 原生工具链顺带做了”）。

由一个代理负责，工作树 `~/repos/yuyan-worktrees/去网页汇编`（分支同名）。每一步各自合入 yybs，合入后照 AGENTS.md 删树再为下一步重建。

## 已完成的前一步

- 2026-10-12（yybs 87afbdcbd）：造盘工具缺省用六十四位原生豫构与编译器，新增仓库目标「造盘工具」；豫言终端编译器优先原生；AGENTS.md、贡献指南、快速开始、仓库包构建、包系统、裸机说明、全树测试与豫言终端说明的工具命令改为原生。

## 步骤

1. **全树测试原生化**：全树测试工具用原生豫构把单元测试、黄金样例、脚本测试编成本机原生程序并直接运行；脚本测试的“单元装载”方式改由原生豫构 `运行` 装载单元，不经诺节宿主。仓库目标「全树测试工具」出原生 `yy全树测试.exe`；CI 的「全树测试」二十片改用原生工具。原生下新出现的失败登记进测试规则表（写明原因），能顺手修的就修。JS 测试（`node --test`）只测网页后端的胶水，留着。
2. **造盘不经 .wasm**：豫言系统造内核镜像、设备驱动镜像时直接读汇编树码；「构建」「运行」子命令改走启动盘与原生开机程序，删去解释执行壳 `.wasm` 的旧路；「执行器状态」不再收网页汇编字节。
3. **裸机验证与底层探针原生化**：`yy裸机验证`、`yy普通豫言验证` 的客体改用豫行程序；12 个底层探针、样例包的默认产物名去掉 `.wasm`；执行器里只为网页汇编客体存在的解释执行路径删去。
4. **Windows 原生工具链**：执行器的 Windows 平台层补齐工具链要用的部分（目录列举与目录句柄、工作目录、控制台模式等）；在 macOS 或 Linux 上交叉直出 Windows 的 `yy豫构.exe`（兼容六十四，臂六十四随后）；CI 的 Windows 作业改用原生工具链构建、类型检查并跑测试。
5. **原生自举与原生工具链包**：「全部」改为原生自举（稳定原生编译器 → 二级 → 三级 → 四级，核对三、四级逐字节相同）；CI 按平台发布原生工具链包（macOS 臂六十四，Linux 兼容六十四与臂六十四，Windows 兼容六十四），`main.yml` 与 AGENTS.md 的起步改用它；工具链构建不再需要诺节。
6. **收尾**：文档与仓库里剩下的工具类 `.wasm` 说法改掉；诺节宿主只留给网页后端相关的测试（是否保留由用户定）。

## 验收

- 本机与 CI 上，构建、类型检查、全树测试、造盘、裸机验证、自举都不产出也不运行 `.wasm`（浏览器、云工目标与它们的测试除外）。
- 新检出的仓库只用原生工具链包起步，不装 Node 也能构建与测试（网页后端除外）。
- Windows 上用原生工具链能构建豫构、跑类型检查与全树测试的一部分（第一版允许登记已知失败）。

## 规矩

- 照 AGENTS.md 快速合入：合入前只跑便宜检查；完整验证交 CI。CI 不覆盖的（QEMU 全量、Windows 实机）合入后再跑，不空等。
- 原生与诺节结果不一致时以诺节为参照查原生（AGENTS.md「诺节后端」），一时修不了的登记已知失败并写原因。
- 原生链接的内存（四吉堆上限）由「压低链接内存」工作树的会话处理，本目标不改那部分；需要大堆的地方先用六十四位原生工具。
- 测试从简、能凑合着用就行；超出平台限制的边角写“待办事项”注释。
