# 原生工具链

目标：总体架构的 WP8。编译器与豫构经执行器「客体二号」预编二成原生程序（macOS、Linux、Windows），不要 Node 也能构建。原生在同机、同源码的冷编与完整构建中都达到或超过 Node（产物逐字节相同）以后，把默认工具链切成原生。

## 现状（2026-10-06）

### 冻结基准带着编译器退化

同一冷编打印探针（`--do-not-load-cache`，54 个模块全编），不同时期编译器在 Node 上的开销：

| 编译器 | 退休指令 | 墙钟 |
|---|---:|---|
| 10-01 稳定工具链（501f8d8e3） | 1450 亿 | pit-mac 9.2 秒（负载约 12） |
| c1a66871c（10-02 04:21） | 1476 亿 | pit-mac 11.0 秒（负载约 50） |
| 2c4aa4b7e（10-03 08:21） | 1.16 万亿 | pit-mac 67.5 秒（负载约 24） |
| e7300b791，即冻结基准 fc45 | 约 4.95 万亿 | pit-mac 安静时约 194 秒 |
| 今天的 yybs（yy4_bs 81554f7d…） | 1.24 万亿 | 本机 51.6 秒（负载约 13） |

- 根因：30e06cee9（10-02，构建基础“按有效包上下文分区编译缓存”）的「获取文件所属包缓存编号」只缓存最近一个文件；名称解析在文件间来回切换，缓存总落空，每次都走「所属包」，对全部约两百个包做「包目录」（获取文件夹名、末分隔位、从右逐字搜索）与前缀判断，外加 realpath。38355b656（树码缓存）让每次查名字都先求缓存路径，又放大了它。今天的剖析里，热点几乎全在这条链上（chars、join 与几个带闭包的高阶函数）。提案00002 会话独立剖析得出同一结论，二分（c1a66871c 快、2c4aa4b7e 慢）也吻合。
- 修复：由提案00002 会话把“按文件缓存”拆成独立提交合入 yybs（其分支上 `全部` 1086 → 107 秒、三级 484 → 32 秒）。本目标停掉了自己的二分与修复。
- 影响：10-03 以来所有原生对 Node 的冷编与完整构建测速，都建在这个退化上，且 fc45 比今天的编译器还多约 4 倍指令。热点（f947、m927、f933、chars 等）与带样本优化的目标多半就在退化代码里，结论未必能移到修好的编译器上。修复合入后要换一份新的冻结编译器重测。
- 另记：`全部` 里单模块类型检查极慢（本机高负载时 预编二转译 368 秒、寄存器降级 354 秒、回收运行时 148 秒），疑同一原因，修复后复核。

### 样本引导：用户 10-06 的答复

- 用户：构建速度很重要；同意采样能提速；要调研把采样做进 AOT 执行器本身；问是否“解释执行的 Wasm 比 AOT 好”——已答：Node 不是解释执行，V8 先用基线编译器收集间接调用目标，再由优化编译器推测内联，快在运行时反馈；AOT 拿到同样的反馈（样本）就能做同样的优化，带样本时已到 199.5 秒对 193.7 秒（fc45 口径）。
- 原型（分支 `静索-采样试验`，未合入）：原生生成加 `--采样调用`；转译器在原函数体的每个 call_indirect 处调执行器 `预编_记呼`（调用点号＝函数号×65536＋调用序，实际函数号）；执行器 `采样。豫` 用状态格 3848 指向启动时分配的 4 MiB 开放定址计数表（64 位次数），正常结束与两个退出函数里把计数一次追加写到当前目录 `yy采样计数.bin`（待办事项：Linux、Windows 尚未写出）。汇总草稿 `豫言操作系统/裸机/草稿/yy样本汇总。豫`（不入库）按次数下限与主目标占比选出调用点，写成 `--内联样本` 的 JSON 并列出最热调用点。代数闭包探针上端到端通过（输出合期望，样本合理）。
- 设想的集成（不拖慢构建）：工具链自举本来就要用新编译器再编一遍编译器，让这一遍用带采样的原生编译器跑，顺带产出样本，最后生成时带上；三级与四级逐字节相同，样本对两者都适用。
- 下一步要在修好的编译器上实测：自动样本对不带样本、对手工样本的收益，以及采样本身的开销。

### 常驻工作进程：用户 10-06 同意做

- 编译器 `--parallel` 模式下每个任务都是自启子进程（`--mode=worker --worker-task=…`，见 构建基础/并行编译。豫）。Node 宿主把这类子进程改成有界复用的工作线程与 GC 堆；原生每任务新起进程，在新页上分配（1 GiB 回收下限之前不回收），完整构建系统态 313 秒对 90 秒、缺页约 7900 万对 80 万次。
- 设想：执行器在子进程层把“自启的 worker 任务”交给常驻工作进程池；工作进程借“待重启”机制在同一进程里重新初始化客体、复用已触碰的堆页，回传退出码与标准输出、错误。编译器修好后完整构建约 30 秒，固定开销占比更大，这项更值得做。

## 已测得的情况（10-02，短探针口径）

1. **墙钟差在并行，不在指令效率**：Node 约有 1 秒 CPU 花在辅助线程上（并发标记、并行清道夫、后台编译）。原生的 CPU 总量早已比 Node 少。
2. **与缺页无关**：两者页回收约 8.3 万次；系统态原生 0.28 秒、Node 0.38 秒。
3. **回收**：次要标记每次 0.2–6 毫秒，扫卡 0.4–6 毫秒；清扫大部分交给后台线程（合计约 168 毫秒），主线程仍在 `pthread_join` 上等约 76 毫秒。fork 与“取空闲时游程用完”两条已排除。“清扫期间先增长堆”试过：正确但更慢（5.50 对 5.25 秒），峰值内存涨到 4.2 GB，已放弃。
4. **热点**：m923（链表上走 n 步，每圈约 54 条指令，含 `$box` 装箱即拆）；f943、f1670 整数比较；str_eq、chars、join；f900、f1220 变体分派；复制、填零助手各约 3%。
5. **间接调用**：闭包经 `call_indirect`，每次约 19 条指令，全程约 2.6 亿次。表零是静态的：11391 项，只有一个从下标 0 起的元素段，没有改表指令，也不导出。
6. **原生构建**：原生豫构每个编译任务另起进程，启动约 4400 万条指令；原生构建编译器 37–45 秒（`-j 8`），Node 约 36 秒。

- **测速**：
  - pit-mac 负载低于 3 再拿 `~/.yy测速锁`，每次不超过 30 分钟。冷编一对约 7 分钟、完整构建一对约 29 分钟，五轮交替要按轮拿锁、轮间放锁，与本地推理速度的测速错开。
  - 各版本同批交替多轮，报中位数；有别的重活时只看相对比较与指令数。

- **剖析**：`sample 进程 秒数 1` 按线程汇总，看 `__ulock_wait` 可知 join 等待；我们的帧没有帧指针，调用链只到桩。反汇编用 `llvm-objdump --disassemble-symbols=客:名`，客体 wat 用 `wasm-dis --all-features`。
- **合入**：实验性、待验证或自述退步的提交留在任务分支，不合入 yybs。
- **生成器与执行器同源**：生成原生程序时，yy原生生成.wasm 与执行器（客体二号）必须用同一份源码重建；二者共用对象布局，新旧混用会读错字段（b812e7f36 之后的旧生成器配新执行器即如此）。执行器导出布局标记 `预编布局_引用四字节`，预编与预编二并入时核对，缺了就报错；布局再改时两边一起改名。
- **基准要先看编译器本身**：换冻结编译器前，先用稳定工具链与候选编译器各冷编一次同一探针比较退休指令，排除编译器自身的退化（10-03 起的 fc45 就带着 30e06cee9 的退化）。
