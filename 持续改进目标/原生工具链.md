## 已测得的情况（10-02，短探针口径）

1. **墙钟差在并行，不在指令效率**：Node 约有 1 秒 CPU 花在辅助线程上（并发标记、并行清道夫、后台编译）。原生的 CPU 总量早已比 Node 少。
2. **与缺页无关**：两者页回收约 8.3 万次；系统态原生 0.28 秒、Node 0.38 秒。
3. **回收**：次要标记每次 0.2–6 毫秒，扫卡 0.4–6 毫秒；清扫大部分交给后台线程（合计约 168 毫秒），主线程仍在 `pthread_join` 上等约 76 毫秒。fork 与“取空闲时游程用完”两条已排除。“清扫期间先增长堆”试过：正确但更慢（5.50 对 5.25 秒），峰值内存涨到 4.2 GB，已放弃。
4. **热点**：m923（链表上走 n 步，每圈约 54 条指令，含 `$box` 装箱即拆）；f943、f1670 整数比较；str_eq、chars、join；f900、f1220 变体分派；复制、填零助手各约 3%。
5. **间接调用**：闭包经 `call_indirect`，每次约 19 条指令，全程约 2.6 亿次。表零是静态的：11391 项，只有一个从下标 0 起的元素段，没有改表指令，也不导出。
6. **原生构建**：原生豫构每个编译任务另起进程，启动约 4400 万条指令；原生构建编译器 37–45 秒（`-j 8`），Node 约 36 秒。

- **测速**：
  - pit-mac 负载低于 3 再拿 `~/.yy测速锁`，每次不超过 30 分钟。冷编一对约 7 分钟、完整构建一对约 29 分钟，五轮交替要按轮拿锁、轮间放锁，与本地推理速度的测速错开。
  - 各版本同批交替多轮，报中位数；有别的重活时只看相对比较与指令数。
  - 驱动是库外草稿 `yy交替冷编计时。豫`（本机只在 `原生引用紧排/应用/性能研究/横向复测/草稿/` 找到）与 `yy完整构建交替计时。豫`；原始记录在 pit-mac `~/wp8-scratch/` 下（如 `yy闭包融合交替六轮`）。
