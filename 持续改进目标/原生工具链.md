### 剖析：原生慢在小函数与串比较；第二、三批提速（待合入）

### 样本引导：用户 10-06 的答复与实测

- 用户：构建速度很重要；同意采样能提速；要调研把采样做进 AOT 执行器本身；问是否“解释执行的 Wasm 比 AOT 好”——已答：Node 不是解释执行，V8 先用基线编译器收集间接调用目标，再由优化编译器推测内联，快在运行时反馈；AOT 拿到同样的反馈（样本）就能做同样的优化。
- 原型（分支 `静索-采样试验`，未合入，已变基到 3ed5c9fc8 之前的候选上）：原生生成加 `--采样调用`；转译器在原函数体的每个 call_indirect 处调执行器 `预编_记呼`（调用点号＝函数号×65536＋调用序，实际函数号）；执行器 `采样。豫` 的 4 MiB 开放定址计数表在进程结束时一次追加写到当前目录 `yy采样计数.bin`（待办事项：Linux、Windows 尚未写出）。汇总草稿 `豫言操作系统/裸机/草稿/yy样本汇总。豫`（不入库）按次数下限与主目标占比选调用点，写成 `--内联样本` 的 JSON。
- 基准三上：带采样的编译器冷编 8.70 秒、1697 亿指令（不带采样 6.60 秒、1297 亿，约 +30%）。用它跑一次完整原生构建编译器（39 秒，1357 个进程追加写同一计数文件，共 74.7 亿次间接调用）得出他训样本，用在冷编探针上与探针自训样本一样（−4.2% 指令）：一次完整构建就够，样本能跨工作负载。
- 集成设想（不拖慢构建）：自举本来就要用新编译器再编一遍编译器，让这一遍用带采样的原生编译器跑，顺带产出样本，最终工具链带样本生成；三级与四级逐字节相同，样本对两者都适用。

### 常驻工作进程与回收下限：用户 10-06 同意做常驻进程

- 编译器 `--parallel` 模式下每个任务都是自启子进程（`--mode=worker --worker-task=…`，见 构建基础/并行编译。豫）。Node 宿主把这类子进程改成有界复用的工作线程与 GC 堆；原生每任务新起进程，在新页上分配，回收下限 1 GiB 之前不回收，fc45 口径下完整构建系统态 313 秒对 90 秒、缺页约 7900 万对 80 万次。
- 先做便宜的试验：回收下限 64 MiB（壬）、256 MiB（癸），已在 pit-mac 造好，排在五轮计时里，看缺页与系统态降多少，再定常驻进程怎么做（执行器在子进程层把自启的 worker 任务交给常驻进程池，借“待重启”机制在同一进程里重新初始化客体、复用已触碰的堆页）。

## 已测得的情况（10-02，短探针口径）

1. **墙钟差在并行，不在指令效率**：Node 约有 1 秒 CPU 花在辅助线程上（并发标记、并行清道夫、后台编译）。原生的 CPU 总量早已比 Node 少。
2. **与缺页无关**：两者页回收约 8.3 万次；系统态原生 0.28 秒、Node 0.38 秒。
3. **回收**：次要标记每次 0.2–6 毫秒，扫卡 0.4–6 毫秒；清扫大部分交给后台线程（合计约 168 毫秒），主线程仍在 `pthread_join` 上等约 76 毫秒。fork 与“取空闲时游程用完”两条已排除。“清扫期间先增长堆”试过：正确但更慢（5.50 对 5.25 秒），峰值内存涨到 4.2 GB，已放弃。
4. **热点**：m923（链表上走 n 步，每圈约 54 条指令，含 `$box` 装箱即拆）；f943、f1670 整数比较；str_eq、chars、join；f900、f1220 变体分派；复制、填零助手各约 3%。
5. **间接调用**：闭包经 `call_indirect`，每次约 19 条指令，全程约 2.6 亿次。表零是静态的：11391 项，只有一个从下标 0 起的元素段，没有改表指令，也不导出。
6. **原生构建**：原生豫构每个编译任务另起进程，启动约 4400 万条指令；原生构建编译器 37–45 秒（`-j 8`），Node 约 36 秒。

  - 驱动与脚本在 pit-mac `~/wp8-scratch/静索/`：豫言草稿 `yy静索冷编轮。豫`（一轮内按轮号轮换各配置先后、禁读缓存、与黄金产物比较；编译时须放进某个包目录，如 `库/构建基础/测试/草稿/`）、`轮测.sh`（按轮拿锁）、`全构测.sh`（完整构建每次一个锁窗口）、`全验.sh`、`变体构建.sh`。旧驱动 `yy交替冷编计时。豫` 与各实验原始记录（如 `yy闭包融合交替六轮`）在 `~/wp8-scratch/` 下与存档里。
- **剖析**：原生用 `sample 进程 秒数 1`（按线程汇总，看 `__ulock_wait` 可知 join 等待；我们的帧没有帧指针，调用链只到桩）；Node 用 `node --prof` 后 `node --prof-process 隔离日志`（取最大的那份，是客体工作线程；“自底向上”一节有调用链，可补原生缺的调用者）。两边函数名同为客体名（fNNN、mNNN、str_eq 等）。客体字面量全局 $sN 由数据段 N 初始化，解码数据段里的报错文字可辨认函数对应的源码。反汇编用 `llvm-objdump --disassemble-symbols=客:名`，客体 wat 用 `wasm-tools print` 或 `wasm-dis --all-features`。
- **合入**：实验性、待验证或自述退步的提交留在任务分支，不合入 yybs。
- **生成器与执行器同源**：生成原生程序时，yy原生生成.wasm 与执行器（客体二号）必须用同一份源码重建；二者共用对象布局，新旧混用会读错字段（b812e7f36 之后的旧生成器配新执行器即如此）。执行器导出布局标记 `预编布局_引用四字节`，预编与预编二并入时核对，缺了就报错；布局再改时两边一起改名。
- **基准要先看编译器本身**：换冻结编译器前，先用稳定工具链与候选编译器各冷编一次同一探针比较退休指令，排除编译器自身的退化（10-03 起的 fc45 就带着 30e06cee9 的退化）。
