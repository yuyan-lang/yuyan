# 云端开发

目标：在 yuyan-cloud 上完整地做开发。项目可以关联一个 GitHub 仓库；每个任务是一段对话，由 DeepSeek 代理用云命令完成；每个任务各有一个工作树和一个分支；构建与测试在网页临时算力上跑，数据一律存在云端；任务以 GitHub PR 合并结束：推送任务分支、开 PR、合并 PR。第一个用途：用它推进[提案 00004](../提案/00004-共用基础库.汉语.md)（豫言基础库）。

由一个新会话实施到底（可以派子代理）。工作主要在云仓（`/Users/zc/repos/yuyan-worktrees/yuyan-cloud`），缺接口或适配时改语言仓。

## 用户的决定（2026-10-06）

1. 项目仍是顶层，网址仍在 `/cloud/` 下，不分开发与运维。
2. 项目可以关联一个 GitHub 仓库；每个任务必须各用独立的工作树与独立的分支。
3. 第一版（MVP）只用 DeepSeek。
4. 构建一律在已连接的临时算力上跑，就是现有的「网页临时算力」（`/cloud/算力.html`）；数据一律存在云端，算力那边不留东西。
5. 每个任务一个对话界面；任务自动开工作树，以 GitHub PR 合并结束（10-06 用户更正：要开 PR、经 PR 合并，不直接调合并接口）。
6. 云端每个页面有唯一的网址，页脚有网址栏和「全部页面」链接，与 yuyan-lang.org 相同。
7. 不用沙箱或容器；代理的每个动作都是平台上真实的云命令。

## 现状（2026-10-06，云仓 ccacb46）

- 云工作台：项目是资源范围，每个账户目录与每个项目各有一个以 SQLite 为底的持久对象；服务页靠 `?service=`、`?project=` 切换；任务与闹钟一起持久保存，浏览器关了照跑；首版限额为每账户 20 个项目、每天 20 个任务、每项目 64 个文件、单文件 32 KiB、总量 256 KiB（`应用/豫言云工作台/说明.汉语.md`）。
- 代码仓（`应用/豫言云工作台/库/云台代码仓`、`代码仓应用`，页面 `/cloud/代码仓.html`）：GitHub App 授权，令牌只在服务器；经 Git 对象 API 保存完整树，文件正文按需读取；每个工作树有独立草稿与本地分支；提交后推送只传差集；拉取与本地合并用三方文件合并；PR 能列出、看差异、创建与合并。目前按账户组织。
- 网页临时算力（`应用/豫言云工作台/算力应用`）：网页领取已排队的编译任务，独占租约、定时续约，离线后别人可以接手；在浏览器后台线程跑真实的 Wasm 编译器；要求浏览器支持 WasmGC 与 JSPI。目前只做“云端编译”项目。
- 智能命令（`应用/豫言云工作台/智能命令.汉语.md`）：按钮、AI 与终端共用的中文命令，如「文件」之「读取」于「入口。豫」。
- 模型：DeepSeek 密钥已是 yuyan-cloud 的 Secret `DEEPSEEK_API_KEY`；`库/AI市场逻辑` 有严格的结森解析、SSE 帧、上游流式协议状态机与人民币账本。
- 官网的网址栏与全部页面：`应用/共用界面/入口。豫` 的 `造网址栏`；`应用/网站/网站资料生成/全部页面。豫` 生成 `/全部页面/`，现在只把 cloud 当作一个动态入口收进去。
- 云端编译服务 yuyan-cloud-compiler：单次 CPU 可达 5 分钟，只编「云项目＋标准库」。

## 设计

### 一、结构与网址

- 网址一律用路径，每页唯一，中文不做百分号编码：
  - `/cloud/`：项目列表；
  - `/cloud/项目/<项目号>/`：项目概览（关联的仓库、任务、各项服务）；
  - `/cloud/项目/<项目号>/任务/`：任务列表；`/cloud/项目/<项目号>/任务/<任务号>`：任务对话；`…/任务/<任务号>/改动`：差异；`…/任务/<任务号>/构建/<构建号>`：构建日志；
  - `/cloud/项目/<项目号>/代码/<路径>`：浏览代码；
  - `/cloud/项目/<项目号>/<服务>`：边缘计算、网站部署、文件系统、持久化存储、访问网关、日志；
  - `/cloud/算力/`、`/cloud/包管理/`、`/cloud/用量/`：账户级页面。
- 旧网址（`?service=…&project=…`、`/cloud/代码仓.html`、`/cloud/算力.html` 等）一律跳到新网址。
- 每页页脚上方有网址栏（复用 `造网址栏`），页脚有「全部页面」链接；`/全部页面/` 收入 `/cloud/` 的全部固定页面，项目与任务由各自的列表页列全，从全部页面链过去。

### 二、项目关联仓库

- 项目设置里绑定一个 GitHub 仓库（经已授权的 GitHub App）与基线分支（如 yybs）。
- 代码仓从按账户改为按项目：克隆、工作树、草稿都归项目。没关联仓库的项目照旧用自己的小文件区。

### 三、任务

- 状态：新建 → 开工作树 → 进行中 → 等待算力或构建中 → 合入中 → 已合入；另有已停止、已取消、失败。
- 每个任务一个持久对象，存对话消息、代理状态、云命令记录、工作树与分支、构建作业、合入结果与费用；大的日志与产物放 R2，列表索引放 D1。
- 工作树与分支：建任务时从基线分支的当前提交开，分支名 `云任务/<项目号>-<任务号>`。一个任务恰有一个工作树、一个分支，平台强制不得共用；合入后删掉工作树与分支。
- 合入：代理宣告完成后，平台把基线分支的新提交三方合并进任务分支（有冲突交给代理解决）→ 在临时算力上跑合入前检查（改动包的检查、类型检查、本包测试）→ 推送任务分支 → 开 PR（base 为基线分支，head 为任务分支；标题取任务名，正文带任务网址与对话摘要）→ 合并 PR（`PUT /repos/{owner}/{repo}/pulls/{number}/merge`，合并提交方式；照快速合入，不等 CI）→ 对话里贴 PR 与合并提交的链接 → 删工作树与分支。yybs 设有必需检查 `verification/cla-signed`：合并 PR 要么等它通过，要么用有绕过权限的身份，先查清再定。
- CI 回写：GitHub 回调（pull_request、check_suite、workflow_run）按 PR 与合并提交找到任务，把结果写进对话。CI 失败时自动建一个修复任务（新的工作树与分支），在原任务对话里给出链接。

### 四、对话界面

- 网址 `/cloud/项目/<项目号>/任务/<任务号>`。
- 消息种类：用户、代理、云命令卡片（命令、参数、结果摘要，可展开全文）、构建卡片（实时日志与结果）、差异卡片、合入卡片、CI 卡片；每条代理消息附用量与费用。
- 操作：随时发消息插话、停止、继续、取消任务。浏览器关了任务照跑。

### 五、DeepSeek 代理

- 用 DeepSeek 的 OpenAI 兼容接口与工具调用，模型 deepseek-chat；代理循环跑在任务的持久对象里，用闹钟分步推进。
- 云命令（代理的全部工具）：读文件、列目录、搜索、写文件、按补丁改、看差异、构建（检查、类型检查、构建、运行测试；作业排给临时算力）、读构建日志、在工作树内提交、问用户（暂停等回答）、完成（进入合入流程）。没有 shell。
- 系统提示：关联仓库的 AGENTS.md 全文、任务要求、云命令说明。大输出存 R2，只给代理摘要与引用；对话太长时自动摘要。
- 费用：每次调用记录词元数与费用，每任务设上限（默认值往大里定）；超限时暂停，在对话里问用户。
- 开发与调试用假模型，不在生产账户消耗 DeepSeek 额度；真实任务由用户发起。

### 六、网页临时算力跑构建

- 作业：仓库、基线提交、工作树改动集、命令列表；沿用现有的独占租约与续约。
- 网页领取作业后：从云端取基线提交的源码（R2 里按提交缓存的仓库快照，首次从 GitHub 取来存进 R2）与工作树改动，在浏览器的内存文件系统里展开；取工具链 Wasm（也缓存在 R2）跑豫构；日志流式传回；结果与产物存 R2；最后清空。构建缓存可以放 IndexedDB，只是可丢的副本，权威数据都在云端。
- 前提，第一步就要验证：豫构能在浏览器宿主里跑完整构建（检查、类型检查、构建、运行测试）。语言仓已有浏览器的文件、子程序等适配（`豫言操作系统/适配/文件浏览器`、`子程序浏览器`）；缺什么照语言仓 AGENTS.md 补接口或适配（诺节规矩不受影响）。并行度按浏览器可用的线程与内存定。
- 没有算力连着时作业排队，对话显示“等待算力”。

### 七、限额

首版限额（每账户项目数、每天任务数、每项目文件数与大小、模型上下文）一律放大，往大里定。
