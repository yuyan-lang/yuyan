# 开放硬件驱动

目标：豫言操作系统用自己写的驱动带动常用的、规格公开的硬件。有线网卡能联网（DHCP 取址、域名解析、TCP），声卡能出声（先放音，后录音）；常用虚拟机的虚拟设备与用户手头几台实机的网卡、声卡都在其内。驱动一律写成两架构共用的 `。底层。豫`，放在豫言内核 `豫言操作系统/裸机/内核/`。用户 2026-10-12 定设备支持方针（见《[总览](总览.md)》），2026-10-13 要规划。

规格封闭的芯片（如博通 BCM4360 无线网卡）走提案 00012 的驱动客体，由另一会话推进，不在本目标内。

用户 2026-10-13 定多开会话并行，分工与各会话共守的约定见「分工」「共用约定」两节。

## 现状（2026-10-13 调查）

已有：

- **扩展主控**（xHCI，两架构，`内核/扩展主控。底层。豫`）：HID 引导协议键鼠、U 盘 bulk-only、一层 USB 2 集线器；传输只有控制、中断、bulk 三种。
- **存储**：AHCI、NVMe、ATAPI 光驱（两架构）；ARM64 执行器里另有用户态 virtio 块设备。
- **显示**：固件帧缓冲（GOP）与「显示模式」驱动（迪斯派即 QEMU 标准显卡、内存帧即 ramfb、威睿二代与三代）。
- **输入**：PS/2 键鼠、USB 引导协议键鼠、威睿绝对坐标鼠标。
- **网络**：执行器（客体二号）里有以太网、ARP、IPv4、UDP、TCP、DHCP 与域名解析，经「网卡就绪」「网卡收帧」「网卡发帧」三个函数用网卡。后端两种：ARM64 执行器里的用户态 virtio-net（写死 PCI 0:5.0）；内核服务 61–63（网帧收、网帧发、网卡信息），只接驱动客体的设备环，ARM64 与未启动驱动客体时都返回 −1。所以 AMD64 不带驱动客体就没有网络。
- **声音**：没有驱动。接口「豫言操作系统声音输出」0.1.0 归《[设计语言前三期](设计语言前三期.md)》第二期第 2 步（提案 00018 第十节：打开流、写样本块、已播样本数与延迟、关闭）；壳里已有设计播放器的「播放」「暂停」「设音量」等命令。

各驱动共有的缺口：

- 外设互连（PCI）枚举各写一份：扩展主控「找主控」、存储「存储控制器查」、显示模式各扫各的；配置读写放在扩展主控里。
- 寄存器窗与直接访存块的页目录项号写死：AMD64 共享设备页目录里扩展主控用 511 项，显示模式与设备上下文表都用 510 项，存储控制块用 448–479 项、寄存器窗用 480–495 项；ARM64 设备二级表另有一套。
- 没有中断，全靠轮询；没有等时传输（USB 声卡要用）。
- EHCI 只有 AMD64 的手写那份（E40 只有 EHCI）。
- AMD64 执行器代码预算（1 MiB）余量很小，所以驱动放内核；内核模块区不够时照 AGENTS.md 的限额规矩放大。

## 设计

### 底座

1. **外设互连**（新文件，如 `外设互连。底层。豫`）：把配置读写从扩展主控挪出来；按类码或「厂商:设备」表枚举（游标续扫，含多功能设备与桥后总线）；BAR 解码（32 位、64 位与端口 BAR）；开访存与总线主控；遍历能力表（电源管理切到 D0）。扩展主控、存储、显示模式改调它，只挪公用函数，不重写原驱动。
2. **设备窗与直接访存块**：寄存器窗、控制块的页目录项改为统一分配，取代写死的 448–511 项与 ARM64 各项，顺带理清 510 项的两处共用；直接访存块从物理块分配器取 2 MiB 块，32 位设备限在 4 GiB 以下。QEMU 与 VMware 上设备访存当作缓存一致；ARM 实机的一致性写待办事项。
3. **设备表与「设备列表」**：开机枚举外设互连与 USB 设备，登记位置（配码或 USB 地址）、厂商设备号、类码、驱动名与状态（已驱动、无驱动、失败），经新内核服务读出；壳命令「设备列表」逐行打印。实机兼容靠它：用户在实机上跑一次，就知道缺哪些驱动。
4. **只轮询**：网卡在服务 61、62 被调用时收发；声卡在执行器写样本时补缓冲，缓冲取大（一秒以上）。中断与 MSI 写待办事项。

### 网卡

- 内核「网卡表」：每块网卡登记收帧、发帧、以太地址、链路状态四个函数。服务 61–63 先用原生网卡，没有再走驱动客体的环，两路并存；ARM64 也有了服务 61–63。执行器网络栈不改，走现有的服务 61、62 那条路。内核 virtio-net 好了以后删去执行器里的用户态 virtio-net。
- 有几块网卡时用第一块链路已通的；多网卡路由写待办事项。
- 查询命令「网络状态」：各网卡的驱动、以太地址、链路、收发计数，以及本机地址、网关、域名服务器。
- 只做最基本的收发：校验和卸载、分段卸载、巨帧、多队列留待后续。

### 声卡

- 接口用「豫言操作系统声音输出」0.1.0，本目标做它的裸机实现：执行器经新内核服务（开流、写样本、已播样本数、关流）交给内核「声卡表」里的驱动。设计语言会话还没定接口时，先做内核服务与命令「测试声音」，接口定好后接上；也可与该会话商定，由本目标按提案 00018 第十节代写接口。
- 格式先只做 48 千赫、16 位、立体声；接口的 32 位浮点在执行器里换成 16 位。设备只支持别的采样率时，用库「音频处理」的重采样。
- 音量先用软件缩放（设计播放器的「设音量」）；硬件放大器开到不失真的固定值。系统级音量命令以后再定。
- 查询命令「声音设备」：声卡、编解码器、所选输出端口、采样格式、已播样本数。命令「测试声音」放一秒正弦波，实机上靠耳朵验。
- 录音（麦克风）在放音全部做完后再做。

### USB 设备层

- 从扩展主控里分出 USB 设备层：描述符解析，选配置与接口，按类码或厂商设备号分派类驱动。已有的键鼠、U 盘挪成类驱动，再加网卡类、声卡类。
- 等时传输：扩展主控加等时环与等时传输块，给 USB 声卡用。
- EHCI：把手写的那份改写成两架构共用的底层豫言（AGENTS.md「手写机器码」条），放在 E40 实机测试之前做。

## 验收

- **QEMU**（自动；合入前的冒烟不超过 5 分钟）：网卡用 QEMU 用户网络，判据是 DHCP 取得 10.0.2.15、解析域名、与宿主 TCP 往返；声卡用 `-audiodev wav,path=…`，判据是跳过开头静音后与送出的样本逐样本相同。验收工具用豫言写，接进现有裸机验证，每种设备一个 `--只验` 名。
- **VMware Fusion ARM**（本机后台 `vmrun -T fusion start … nogui`，用草稿目录里的复本，别碰用户的虚拟机）：e1000e 联网；hdaudio 看已播样本数推进。
- **实机**（需用户，攒成一轮）：mbp13（AX88772、CS4208；Linux 对苹果机上的 CS4208 有专门修正，功放可能要靠 GPIO 打开）、E40（RTL8168、高清音频、EHCI）、pit-pc（I225-V、USB 音频类 2）。每台先跑「设备列表」「网络状态」「声音设备」，再「测试声音」听。
- **远程替代**（需用户授权一次）：在 mbp13、pit-pc 上用 KVM 把真设备直通给 QEMU 里的豫言（USB 设备用 `usb-host`，外设互连设备用 vfio-pci），不必插盘重启。直通前确认那台机器另有网络连着，免得断开。

## 不在本目标

- 无线：BCM4360 走驱动客体（另一会话）。开放的无线芯片（ath9k 不要固件；mt76、iwlwifi 要可再分发的固件）还得自写 802.11 与 WPA2，量大，另立目标。
- 蓝牙（USB 主机控制器接口类）、摄像头（USB 视频类）、I2C 触控板、HDMI 与 DP 音频（要显卡驱动配合）、英特尔 SOF 数字麦克风（要 DSP 固件）、显卡原生模式设置（英特尔、AMD、英伟达继续用固件帧缓冲）。

## 规矩

- 驱动放豫言内核，两架构共用；架构相关的只做最小原语；不新写手写机器码（AGENTS.md「设备驱动」「手写机器码」两条）。
- 动作经命令：每类设备有查询命令；新命令加在库「壳命令」，做法登记在 `库/用户态桌面/命令壳。豫`，候选补在 `库/壳核心/命令登记。豫`。
- 能凑合着用就行：只轮询，单网卡、单声卡，边角情形写待办事项注释。
- 新术语（virtio、高清音频、编解码器、芯片厂商名等）先按《翻译列表》开头的起名原则补进列表再用。
- 参考 Linux、BSD 驱动只看寄存器与流程，不照抄代码。
- 协调：声音输出接口归《设计语言前三期》，第 3 步开工前先与该会话对齐；服务 61–63 与林兼容（驱动客体网卡）共用，改动保留驱动客体那条路；动扩展主控、存储、显示模式时只挪公用函数。
- 原生驱动进两种 ISO（带林纳克斯兼容的与不带的）。

## 共用约定

### 底座接口（2026-10-13 已合入 yybs，各部分照用）

`外设互连。底层。豫`：

- 「配读」乃化「整数」而化「整数」而「整数」也：配码、偏移 → 四字节。配码＝总线左移 16、设备左移 11、功能左移 8 之和。扩展主控里的同名函数改为转调这里。
- 「配写」乃化「配码」为「整数」而化「偏」为「整数」而化「值」为「整数」而「有」也。
- 「外设下一个」乃化「整数」而「整数」也：游标首次给 0，之后给上次所得配码右移 8 再加 1；返回下一个存在的功能的配码，没有了返回 −1。
- 「外设厂商」「外设产品」「外设类码」乃化「整数」而「整数」也：配码 → 厂商号、产品号、24 位类码。
- 「外设栏」乃化「配码」为「整数」而化「序」为「整数」而「长整数」也：第 序 个 BAR 的物理地址（访存 BAR；64 位的自动拼上高半；端口 BAR 与未分配的返回 0）。
- 「外设授权」乃化「整数」而「有」也：开访存与总线主控，关传统中断（只轮询）。
- 「外设能力」乃化「配码」为「整数」而化「号」为「整数」而化「起」为「整数」而「整数」也：在偏移 起 之后（0 表示从头）找能力号为 号 的能力，返回其偏移，没有返回 0。
- 「外设醒」乃化「整数」而「有」也：有电源管理能力时切到 D0。

`设备窗。底层。豫`：

- 「设备寄存器映」乃化「长整数」而「长整数」也：寄存器物理地址 → 内核虚址（不可缓存的 2 MiB 窗，同一块重复映射时复用；失败返回 0）。寄存器区跨 2 MiB 边界的写待办事项。
- 「直访块取」乃化「有」而「长整数」也：取一块清零的 2 MiB 直接访存块，返回物理地址（AMD64 尽量低于 4 GiB；失败返回 0）。
- 「直访虚」乃化「长整数」而「长整数」也：直接访存块里的物理地址 → 内核虚址。
- 窗口池：AMD64 共享设备页目录第 384–447 项，ARM64 设备二级表第 440–503 项；别的代码不再新占这两段以外的项。

`设备表。底层。豫`：

- 「设备找」乃化「种类」为「整数」而化「位置」为「整数」而「整数」也：返回序号，没有返回 −1。种类 1 外设互连（位置是配码），2 通用串行（位置由通用串行会话定）。
- 「设备登记」乃化「种类」为「整数」而化「位置」为「整数」而化「标识」为「整数」而化「类码」为「整数」而「整数」也：标识＝厂商号加产品号左移 16；已登记的返回原序号。开机时底座把全部外设互连功能登记好，驱动只需「设备找」再「设备标驱动」。
- 「设备标驱动」乃化「序」为「整数」而化「驱动」为「整数」而化「状态」为「整数」而「有」也：状态 0 无驱动、1 已驱动、2 失败。
- 服务 65 设备数、66 设备信息（序号、用户缓冲偏移 → 32 字节记录）；接口「豫言操作系统设备」的「查询设备」；壳命令「设备列表」（驱动名表在 `库/用户态桌面/设备命令。豫`，各会话加自己的驱动名）。
- 内核函数至多四个参数（AMD64 寄存器参数个数）。
