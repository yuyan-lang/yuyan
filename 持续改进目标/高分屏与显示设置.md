# 高分屏与显示设置

目标：豫言操作系统的桌面在高分屏上按像素比清晰绘制，不再放大像素；系统设置里能改分辨率与缩放。用户 2026-10-11 定。

由一个代理负责，工作树 `~/repos/yuyan-worktrees/高分屏与显示设置`（分支同名）。与《[ARM64 系统内造盘](ARM64系统内造盘.md)》《[AMD64 系统内造盘](AMD64系统内造盘.md)》并行，协调办法见「规矩」。

## 现状（2026-10-11 调查）

画面发糊有三层原因，叠在一起：

1. **AMD64 内核两倍放大。** 帧缓冲宽超过 1920 或高超过 1200 时，手写帧服务（`豫言操作系统/裸机/库/裸机后端/帧服务。豫` 的「帧求倍」，外置区 0x1F5000）让服务 33 报一半宽高，服务 32 把每个像素写成 2×2。2560×1600 的屏上桌面只有 1280×800，文字按 1 倍栅格化后再放大。起因是 10-06 实机进桌面堆不足：一帧 16 MB，执行器当时只拿到 762 页（见《公开测试版》10-06 的进度）。现在执行器的裸机页容量是 65535 页（`裸机后端/降级目标。豫`「目标页容量上限」，两种架构都是；长不出来退回 1024 页，见 `客体二号/堆。底层。豫`「可行页上限」），Limine 也已换成自有引导，当初的理由基本不在了。ARM64 的服务 32、33 在豫言内核（`内核/帧控台。底层。豫` 的「提交帧服务」「帧缓冲信息服务」），不放大。
2. **执行器像素比写死为 1。** 见 `客体二号/裸显示。底层。豫` 的「裸显像素比」。显示控件（`库/显示控件/主循环。豫`）本来按像素比工作：逻辑尺寸＝物理×64÷比六四，文字量具按像素比造；macOS 原生窗口取 `backingScaleFactor`，所以同一个桌面在 macOS 上清晰。子程序显示代办在子程序一侧也答 1（`客体二号/显示原语。底层。豫`「显原像素比」，有待办“转交父程序设的像素比”）；macOS 管道代办已经转交（`--显示面代办 名=宽x高@画号,事号,比`）。
3. **分辨率由固件定。** UEFI 引导程序（「自有引导」的 BOOTX64.EFI、「臂引导」的 BOOTAA64.EFI）用 GOP 的当前模式，BIOS 引导按 EDID 首选设 VBE。VMware Fusion 的 ARM 虚拟机 GOP 是 1024×768（帧缓冲 0xFF0000000，BGRX），QEMU 标准显卡默认 1280×800，虚拟机软件再把客体像素放大到 Retina 屏上。实机固件一般给面板原生分辨率（如 2560×1600 的苹果笔记本）。

系统设置（`库/用户态桌面/系统设置。豫`）现在只有字体：「桌面设置」组类只有「字体名称」，`设置持久。豫` 把它存进授权目录的 `yy桌面设置.数据库`（键 `桌面/字体`）；平铺桌面改设置时保存（`库/平铺桌面/外壳。豫`「改桌面设置」），启动时装入（`运行。豫`）。平铺桌面经「运行界面尺寸比计时保位会话」拿到像素比；外部程序格（`格子。豫`）以「启动带显示面的子程序」「设置子程序显示面尺寸」把格子的物理尺寸与像素比交给子程序，现在只在格子尺寸变了时重设。

## 设计

### 缩放（像素比）

- **内核只管物理像素。** 服务 33 报物理宽高，服务 32 不再 2×2 复制。
- **自动像素比由执行器定：** 帧缓冲宽超过 1920 或高超过 1200 时为 2，否则为 1。门槛与现在的放大相同，所以 QEMU 默认 1280×800 的画面和 CI「系统公测发行」冒烟的耗时都不变（TCG 下桌面冒烟本就贴着 5 分钟门限）。
- **用户缩放在应用层生效。** 系统设置给「自动、100%、125%、150%、175%、200%、250%、300%」，存为比六四（0＝自动，其余为 64、80、96、112、128、160、192）。显示控件主循环接受一个缩放覆盖（0＝用宿主像素比）；主循环里用到像素比的地方（逻辑尺寸、文字量具、指针坐标换算、脏区、尺寸与像素比变化的检查）都改用有效像素比。平铺桌面把设置交给它。这样浏览器、macOS、诺节、裸机的行为一致，显示接口不必为缩放加函数。
- **外部程序跟着变。** 平铺桌面把自己的有效像素比交给子程序：像素比变了也要「设置子程序显示面尺寸」，不只看尺寸。裸机代办把父程序设的像素比（比六四，整数）带过内核邮箱，子程序一侧答它。
- **光标与指针。** 执行器叠画的 12×19 箭头按自动像素比放大（存光标下像素的 912 字节区随之放大，鼠标区 +64 起的布局要挪，见「裸鼠区」的注释）；PS/2 与 USB 的相对位移乘自动像素比，免得高分屏上指针变慢。VMware 的绝对坐标（服务 47）本来按帧缓冲宽高折算，换模式后用新尺寸。

### 分辨率（显示模式）

- **接口：** 显示接口升 0.9.0，只增不改，新增两项：
  - 「读取显示模式列表」（显示面）→ 宽高列表（物理像素，含当前模式）或系统错误；
  - 「设置显示模式」（显示面、宽、高，宽高带标签）→ 成功或系统错误（不支持、输入无效、资源已失效）。成功后「读取显示面尺寸」返回新尺寸，宿主交付「显示尺寸变化」。裸机的等待现在还不交这个事件（「裸显示」的待办），这里补上：设置成功后，下一次等待先交一次。
  - 浏览器、macOS、诺节：列表只有当前尺寸，设置答不支持（诺节适配按 AGENTS.md 只修不扩）。子程序代办里的显示面同样只答当前尺寸、不支持设置。改了声明就重生成各适配的 `宿主提供。数据。豫`。
- **内核**（豫言内核里两种架构共用的 `。底层。豫`）：新增服务「显示模式数」「读显示模式」「设显示模式」，服务号取 57 起的空号（文档里已用到 56，动手前查分派）。按 PCI 设备选驱动，PCI 配置空间读写与 BAR 映射照扩展主控驱动的做法：
  1. QEMU 标准显卡与 bochs-display（PCI 1234:1111）：DISPI 寄存器在 BAR2 偏移 0x500（MMIO，两种架构通用），帧缓冲在 BAR0；模式受显存限制（默认 16 MiB 正好放下 2560×1600×4，更大要 `vgamem_mb`）。
  2. QEMU ramfb（ARM64 测试用 `-device ramfb`）：经 fw_cfg 的 `etc/ramfb` 写配置（地址、格式、宽、高、行距，大端），帧缓冲由内核取连续物理块。virt 机型的 fw_cfg 在固定地址 0x09020000，先写死（待办事项：按 ACPI 找）。
  3. VMware SVGA II（15AD:0405，AMD64）与 SVGA3（15AD:0406，Apple 芯片上的 Fusion）：写 WIDTH、HEIGHT、BITS_PER_PIXEL、ENABLE 寄存器（SVGA3 经 BAR0 的 MMIO），不开 FIFO 与命令缓冲，靠宿主跟踪帧缓冲的写入。寄存器编号与访问方式照 Linux vmwgfx 的 `svga_reg.h` 与 `vmw_read`、`vmw_write` 核实。这一项先实测：改尺寸后直接写帧缓冲能上屏就接上，不能上屏就写待办事项，留待后续版本。
  4. 其余（实机）：模式只有固件给的当前一个，「设显示模式」答不支持；缩放照样可调。

  换模式后更新内核的帧缓冲记录（AMD64：0x103910 起的记录与 0x103930 的内核虚址；ARM64：开机参数 +48 地址、+56 宽高等，见 `豫言操作系统/裸机/文档/臂平台.汉语.md`）。新帧缓冲超出已映射的范围时，在 `。底层。豫` 里补映射（AMD64 映在 2–3 GiB 的写合并窗口，页属性同开机时的映射，见 `帧服务.汉语.md`“帧缓冲改为写合并”）。控制台画字若跟不上新尺寸，就在执行器归还显示面时恢复开机时的模式，桌面每次启动再按设置重设。
- **执行器：** 两项接内核服务；换模式后重新读尺寸；影子帧（「裸鼠影子初始化」在初始化堆之前、按开机时的帧缓冲尺寸取）按最大模式预取，或换模式后不再用影子帧（待办事项）；鼠标边界与光标位置按新尺寸截。
- **引导程序不改。** 在 GOP 里选模式要往手写机器码里加逻辑，AGENTS.md 要求这种情况停下、改写成 `。底层。豫`，ARM64 系统内造盘也规定引导程序只做最小改动；留待引导程序迁成 `。底层。豫` 之后（降级器先要支持 UEFI 应用目标）。

### 系统设置

- 「桌面设置」加「缩放」（比六四，0＝自动）与「分辨率」（0＝不改，否则 宽×65536＋高）；`设置持久。豫` 加键 `桌面/缩放`、`桌面/分辨率`，读不到用默认值。
- 系统设置页加「显示」一节，写法照「设置字体按钮」：
  - 分辨率：按「读取显示模式列表」列出按钮，当前项标“（当前）”；列表只有一项时只显示“分辨率：宽×高”。
  - 缩放：八个按钮，“自动”注明当前的自动值，如“自动（200%）”。
- 平铺桌面启动时装入设置：分辨率非 0 就「设置显示模式」（失败就忽略，设置保留）；缩放交主循环。改设置立即生效并保存。
- 待办事项：改分辨率后的确认倒计时（黑屏时自动退回）留待后续版本。

## 建议步骤（每步各自合入 yybs）

1. **去掉两倍放大，报自动像素比。** AMD64 服务 32–35 改走豫言内核里 ARM64 已在用的「提交帧服务」「帧缓冲信息服务」：两种架构不同的地方（帧缓冲记录的位置、红蓝格式、内核虚址）做成最小原语，删去手写帧服务的主体（含「帧求倍」）；`兼容核心。豫` 的分派让 32–35 交豫言内核（ARM64 已是如此）。「裸显像素比」按物理尺寸报自动值；光标放大，相对位移乘像素比。
   - `兼容核心。豫` 在 ARM64系统内造盘 工作树里有未提交的整篇重排。动手前看它合入没有；没有就先跟那边协调（SendMessage 找主人会话，或问用户），只改分派这一处。
   - 迁移卡住时的退路：只把手写帧服务的倍数固定为一（只删不加），写待办事项。
   - 验：QEMU `-vga none -device VGA,xres=2560,yres=1600`（SeaBIOS；BIOS 引导按 EDID 选 2560×1600）进桌面，文字边缘平滑、没有 2×2 方块，鼠标点按正确；默认 1280×800 下画面与以前相同。
2. **子程序像素比。** 裸机代办转交像素比；平铺桌面像素比变了也重设子程序。验：桌面里开一个外部图形程序，像素比为 2 时它的文字同样清晰。
3. **缩放设置。** 显示控件主循环的缩放覆盖、桌面设置与持久化、系统设置的「缩放」。验：macOS 原生窗口（后台，`--显示面后台`）与裸机 QEMU 上切 100%、150%、200%，立即重排；重开桌面后保留。
4. **显示模式。** 显示接口 0.9.0、内核服务、DISPI 与 ramfb 驱动、执行器两项、系统设置的「分辨率」。验：QEMU 两种架构在设置里切 1280×800、1920×1080、2560×1600，画面、光标、鼠标都正确；返回命令行后控制台正常。
5. **VMware。** 用探针虚拟机实测 SVGA3（ARM64），能用就接上；不能用就把原因与待办写进本文件和 `臂平台.汉语.md`。顺带查 VMware 虚拟机配置能否让固件 GOP 默认给更高的分辨率，能的话写进 `臂平台.汉语.md` 的 VMware 步骤。
6. **文档。** `豫言操作系统/裸机/文档/帧服务`、`臂平台`，`豫言操作系统/裸机/说明.汉语.md` 的“高分屏”一段，显示接口规范，`用户态桌面` 与 `平铺桌面` 的包说明（成对的双语文档同步改），本文件的「进度」。

## 验收

1. 2560×1600 帧缓冲（QEMU SeaBIOS 加 xres、yres）下，桌面按像素比 2 绘制：文字边缘平滑，没有 2×2 方块；1280×800 下画面不变（光标除外）。
2. 系统设置里改缩放、改分辨率（QEMU 两种架构）立即生效，重开桌面后保留；平铺桌面里的外部图形程序跟着变。
3. `yy裸机验证` 不比开工前多失败；CI「系统公测发行」冒烟的耗时不变。
4. VMware 一项有结论：能用，或写明不能用的原因与待办。

## 测试方法

- 造盘与 QEMU 进桌面：照《ARM 硬件》《公开测试版》的做法。监视器 `sendkey` 进「图形」；`mouse_move` 有加速，先 `-2000 -2000` 归角，再边截图边挪；`screendump` 的路径只用 ASCII。AMD64 高分屏用 `-vga none -device VGA,xres=2560,yres=1600`（显存不够加 `vgamem_mb=64`）；ARM64 用 edk2 加 `-device ramfb`，或 `-device bochs-display`。
- 显示控件与系统设置的改动先在 macOS 原生窗口后台验（`--显示面后台`，不把窗口调到前台）。
- VMware：用自己的探针虚拟机（勿碰用户的虚拟机），`vmcli <vmx> MKS captureScreenshot 文件.png` 截屏，`MKS sendKeySequence` 打字，VNC 注入鼠标；做法见《ARM 硬件》2026-10-10 的进度。
- 卡顿：像素多了四倍。整帧重画慢时，先查是否只提交了变化区域，再逐段计时找热点。

## 规矩

- 照 AGENTS.md：驱动写成两种架构共用的 `。底层。豫`，不新写手写机器码，手写部分只删不加；新函数与改动的签名按标签规则写；注释双语；能凑合着用就行，边角情形写待办事项；快速合入，推送后不等 CI。
- 不改引导程序（「自有引导」「臂引导」）。
- 与 ARM64系统内造盘协调：它在 `兼容核心`、`字体模块`、`内核/入口`、`内核准备`、`原生产物`、`设备驱动镜像`、`豫行程序`、`豫言系统`、`验证` 等文件有未提交的改动（10-11），并新增了 `内核/开机装载。底层。豫`。这些文件尽量不动，非动不可时先协调。AMD64系统内造盘在改 `客体二号/主机任务。底层。豫`。
- 两个造盘会话比对的是同一提交的宿主盘与系统内盘。本目标合入只让他们变基后重造，不影响结论。
