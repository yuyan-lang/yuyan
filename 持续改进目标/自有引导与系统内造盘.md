# 自有引导与系统内造盘

目标：启动盘上只有豫言自己的代码，造盘不依赖外部工具；最终在豫言操作系统里编译并造出系统自己的 ISO。2026-10-07 用户定。

由一个代理负责到底，工作树 `~/repos/yuyan-worktrees/自有引导`（分支 `codex/自有引导`）。

## 验收标准

1. **自有引导**：BIOS（MBR 与 El Torito 光盘）与 UEFI（`BOOTX64.EFI`）的引导代码都由豫言生成，按 Multiboot 1 把内核与模块交给现有内核；盘上不再有 Limine。
2. **自有造盘**：ISO 9660、El Torito、混合 MBR 与 EFI 分区的 FAT 映像都由豫言写出；造盘不再调 `limine`、`xorriso`。
3. 以上在 QEMU（q35，SeaBIOS 与 OVMF，光盘与 U 盘两种接法）上启动冒烟、在系统里构建并运行你好都通过；实机请用户复测。
4. **系统内造盘**：造盘程序在豫言操作系统里运行（不调宿主命令），数据盘放上造系统所需的全部源码与数据，预编二在系统里运行；系统里造出的 ISO 与宿主造的逐字节相同，并能在 QEMU 启动。

## 现状（2026-10-07 立项时）

- 盘上的外部代码只有 Limine 12.9.1（BIOS 引导扇区、`limine-bios.sys`、`BOOTX64.EFI`、UEFI 光盘映像，约 3.9 MB）。它按 `limine.conf` 把内核 `yyos.img` 与五个模块（控制台字模、文楷字体、预编机器码、两个工具映像）读进内存，按 Multiboot 1 交给内核。
- Limine 的交接（SeaBIOS、2 GB 实测）：引导信息在 0x10000，标志 0x124D（内存、命令行、模块、内存表、引导器名、帧缓冲）；模块表在 0x10080，五个模块从 8 MiB 起按 4 KiB 对齐紧挨着放到约 102 MiB；内存表原样转交 E820；帧缓冲 1280×800×32，色彩信息按四字节对齐放在 +112（规范是 +110，内核两种都认）。
- 内核按顺序认模块：第一个控制台字模、第二个桌面字体、第三个预编机器码（6–18 MiB），第四个起按魔数认工具映像。
- 造盘（`豫言操作系统/裸机/豫言系统。豫` 的「启动盘」）调 `limine`、`xorriso`，另调 `git`、`dd`、`cp`、`mkdir`、`mktemp`、`env` 等宿主命令；预编二只在宿主上跑。
- 文楷、思源字模、拼音词库是第三方字体与词库，属于数据，照旧随盘。

## 做法

1. **BIOS 引导**：MBR 引导扇区读入第二级；第二级在实模式下读盘（INT 13h 扩展读，兼容 512 与 2048 字节扇区）、取 E820 内存表、开 A20、用非实模式把内核与模块拷到 1 MiB 以上、设 VBE 线性帧缓冲、填 Multiboot 1 信息，切保护模式跳进内核。模块的位置由造盘定：从 8 MiB 起紧挨着放，碰到 124–128 MiB（USB 控制器的 DMA 区）就挪到 128 MiB 以上。同时写 ISO 9660、El Torito（不仿真）与混合 MBR，替掉 xorriso。
2. **UEFI 引导**：豫言生成 PE32+ 的 `BOOTX64.EFI`：找到带引导表的整盘块设备、读内核与模块、取 GOP 帧缓冲与内存表、退出启动服务，再回到 32 位保护模式跳进内核；EFI 分区的 FAT 映像也自己写。
3. **切换**：启动盘改用自有引导，去掉 Limine 与 xorriso；380 项裸机验证、SeaBIOS 与 OVMF 冒烟、系统里构建你好。
4. **造盘程序进系统**：宿主命令换成豫言的文件操作；数据盘放上造系统所需的源码与数据；预编二在系统里跑（用六十四位执行器）。
5. **系统里造盘**：在系统里造出 ISO，与宿主造的逐字节相同，并能在 QEMU 启动。

## 规矩

- 照 AGENTS.md：快速合入，合入前只跑最便宜而有用的检查；完整测试交给 CI。
- 图形测试只在后台（QEMU 无头加监视器截图）。造盘会重生成 `库/壳核心/yy拼音字库。豫`，提交前还原。
- 机器码照旧由豫言直接编码；宿主上的 `llvm-mc` 只用来对照指令字节，不进造盘流程。
