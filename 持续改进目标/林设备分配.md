# 林设备分配

目标：真实硬件运行豫言裸机宿主，由 Linux 客体（林客体）用现成驱动管理 GPU、网卡，并运行 Linux 应用及 CUDA。实机是 pit-pc-ubuntu（RTX 5090）。

## 现状（2026-10-06，等用户执行管理员只读采集）

软件路径已在 QEMU/KVM 中验证；真实 GPU 分配、CUDA 与实机裸机启动都还没验。采集工具已修好并备好最小采集包，下一步只差用户在 pit-pc-ubuntu 用管理员权限执行一次只读采集。全部软件改动在 7d7f2ed3a（75 个文件，合入 c7bce376f，已推送）。

### 已验证

- Linux 客体启动并运行原有服务程序；通用设备分配路径用现成 e1000e 驱动完成网络收发，六项 TCP 服务验收通过。
- PCI 配置、BAR/MMIO 映射、DMA 授权与设备中断转交已实现。DMA 正向测试完成数据传输；超出授权范围的负向测试触发 IOMMU 故障，哨兵未改。
- MSI-X：私有表、宿主向量分配、物理表转换与客体中断投递已实现。最新网络回归记 164 次转交，IOMMU 故障为零，临时映射窗口恢复为零。
- 表与 PBA 共用页的读取已修；32 位与 64 位读取、寄存器寻址、表外填充区读写经模拟对照；PBA 写入与未知设备地址访问被拒；高地址 BAR、跨映射块表项也有模拟验证。
- NVIDIA 原始 GSP 固件已由 Linux 原生 request_firmware 路径读取，现成 NVIDIA 内核模块已构建；没有 GPU 的客体返回 ENODEV 后服务照常。这些还不能证明 GPU 驱动绑定或 CUDA 可用。
- 原有网络镜像与极小客体回归通过。

### 实机资料与缺口

- 先前只读资料：RTX 5090 在 01:00.0（10de:2b85），I225-V 在 05:00.0（8086:15f3）。GPU 隔离组还含音频功能，网卡独占一组。
- 普通权限只能读 64 字节 PCI 配置；完整配置与 DMAR 表还没取得。已分配的 MSI-X 向量数不能代替能力表的最大数。
- 固件定位用传统 RSDP/RSDT 扫描，相关表须在已有的 2 GiB 宿主恒等映射内；UEFI/XSDT 支持未实现。
- 真实设备解绑、裸机启动与设备恢复未验；部分访存指令形式与页边界仍有待办限制。
