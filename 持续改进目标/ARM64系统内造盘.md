# ARM64 系统内造盘

目标：ARM64 版豫言操作系统在自己里面从源码造出自己的 ARM64 启动盘（也能交叉造 AMD64 启动盘），全程不经 `.wasm`。做法是把 AMD64 已有的豫行路径推广到 ARM64，架构相关的代码写成两种架构共用的 `。底层。豫`。用户 2026-10-11 定。

由一个代理负责，工作树 `~/repos/yuyan-worktrees/ARM64系统内造盘`（分支同名）。与《[AMD64 系统内造盘](AMD64系统内造盘.md)》并行，协调办法见「规矩」。

## 硬性要求一：去掉 .wasm

1. ARM64 上运行的每个程序——开机程序、`/工具` 下的工具、系统里构建出来再运行的程序——都是编译器从豫汇直出的 ARM64 豫行文件：`--目标 本机 --目标系统 豫言 --目标架构 臂六十四 --执行器 <绝对路径>/yy执行器.树码`，开机程序再加 `--开机程序`。与 AMD64 走同一条路径。
2. 造盘与开机流程不产出、不存放、不嵌入、不解释 `.wasm`。ARM64 启动光盘、内核镜像、数据盘 `/工具` 里都没有网页汇编字节。核验：在这些文件里找网页汇编魔数 `00 61 73 6D`，一处也没有（`/源` 是仓库原样，不算）。执行器以汇编树码 `yy执行器.树码` 提供。
3. 不修补旧路：不做“按豫行文件匹配工具映像”（`ARM硬件交接.md` 与 `豫言系统。豫`「写臂工具映像们」注释里的那条修法作废），不做 ARM64 开机壳的预编二。
4. 被取代的东西一次删掉，不留兼容（用户 10-08 定“直接切换”）：
   - ARM64 工具映像：`yy豫言系统 臂工具映像` 子命令与「写臂工具映像们」「造臂工具映像」「拼工具映像」；内核的工具映像表、映像区登记、服务 40、工具映像任务专用的页表与原生栈（`内核/装载。底层。豫`、`内核/内存。底层。豫`）；执行器的「映像号查」「映像样同」「文件映像号查」与远程原语 200 里的映像号；文档里用 QEMU `-device loader` 装映像的说明。
   - ARM64 启动盘与 `运行 --架构 臂六十四` 里“内核镜像嵌执行器 `.wasm` 与壳 `.wasm`、由执行器解释执行”的路径（「构建全部」「造系统镜像」的 ARM64 用法）。验证夹具若共用同一函数，函数留给夹具，只断开启动盘与 `运行` 的用法。`--依赖数据盘`（提案 00012 林兼容的图形验收用的 Virtio 盘）改用新的 U 盘数据区。
5. 执行器里的解释器、验证夹具（`yy裸机验证`、`yy普通豫言验证` 里嵌 `.wasm` 的 `-kernel` 镜像用例）不在本目标范围：不删，新代码也不依赖它们。

## 硬性要求二：架构相关代码写成两架构共用的 。底层。豫

照 AGENTS.md“设备驱动优先写成可移植的 `。底层。豫`”一条办：

1. 内核的新逻辑一律写进豫言内核（`豫言操作系统/裸机/内核/`）的 `。底层。豫`，两种架构共用一份。真正依赖架构的操作（缓存维护、指令同步、内存屏障、页表项格式等）做成最小的内核原语，声明在 `内核。底层接口。豫`，由降级器的内核态目标按架构展开。
2. 不新写架构专用的手写机器码或汇编。裸机后端的 `臂核心。豫`、`臂多核。豫`、`兼容核心。豫`、`字体模块。豫`、`外置初置。豫` 等手写部分不再加新逻辑；某一步要改它们时，先把那段逻辑迁成豫言内核里的 `。底层。豫`，再删手写部分，手写部分只留跳到共用代码的最小入口。已知要迁的一处：AMD64 开机程序的装载「兼容豫行模块初置」（`字体模块。豫` 里的手写机器码）改成两种架构共用的 `。底层。豫`，优先复用「按段建任务」（`内核/按段。底层。豫`，服务 43；ARM64 自 10-10 起已支持，含可执行段的页属性）起第一个任务，ARM64 开机程序也走它。
3. 引导程序（「自有引导」的 BOOTX64.EFI、「臂引导」的 BOOTAA64.EFI）必须改时只做最小改动（如多装一段），并写“待办事项：迁成 `。底层。豫`（降级器要先支持 UEFI 应用目标）”。
4. 执行器（客体二号）本来就是两架构共用的 `。底层。豫`：ARM64 直接用 AMD64 已有的豫行装载、程序缓存、远程分段读、扇区缓存与挂盘，删去只为工具映像存在的 ARM64 分支。
5. 生成器一侧（裸机后端「豫行程序」「原生产物」「设备驱动镜像」，`豫言系统。豫`）一份实现带架构参数，不按架构复制函数：例如「生成臂豫行程序」并进「生成豫行程序」；「开机内核镜像」按架构出镜像；「构建臂启动盘」与「构建混合启动盘」共用前面各步，只在写引导介质（自有引导或臂引导）处分开。
6. 收尾时在「进度」里记下两种架构手写机器码文件的行数（开工前、完成后），只减不增。

## 验收（全部满足才算完成）

1. 宿主：`yy豫言系统 启动盘 --架构 臂六十四 --工具链 --六十四位地址 --盘容量 2097152` 造出 ARM64 启动光盘与合成镜像。合成镜像与 AMD64 同构：数据区在光盘之后第一个 64 MiB 整数倍处；`/工具` 放 ARM64 豫行的豫构、编译器、豫言系统、源码格式化与 `yy执行器.树码`；`/源` 是整个仓库。
2. QEMU（本机 HVF、edk2-aarch64 固件、合成镜像经 `qemu-xhci` 加 `usb-storage` 接成 U 盘、四核 12 GiB）开机进开机豫构（`应用/豫构/开机。豫`，与 AMD64 相同），执行器挂上 U 盘数据区；快路命令与完整豫言句都能用。完整豫言句要装单元：ARM64 用户数据页不可执行，要内核给可执行映射与指令缓存同步。
3. 在里面输入「构建启动盘」：缺省造本机架构（ARM64）的启动盘，光盘与合成镜像都和宿主同一提交造的逐字节相同；加 `--架构 兼容六十四` 交叉造 AMD64 启动光盘，也逐字节相同。用系统里造出的 ARM64 盘再启动、再造一次，产物不变（不动点）。
4. 去 `.wasm` 的核验（要求一第 2 条）通过；要求一第 4 条列的东西确已删去，文档同步。
5. `yy裸机验证`（342 项，两种架构）通过，`yy普通豫言验证` 不比开工前多失败；AMD64 启动盘冒烟（SeaBIOS、OVMF）通过；AMD64 系统内造盘不退步（与 AMD64 目标的会话协调复验）。
6. VMware Fusion 的 ARM 虚拟机（自己建的探针虚拟机，勿碰用户的虚拟机；`vmcli` 截屏与发键的方法见 `ARM硬件.md` 2026-10-10 的进度）启动进开机豫构并挂上 U 盘数据区。

## 现状（2026-10-11 调查）

- 10-09 至 10-10：ARM64 在 HVF 下能跑系统内造盘（产物是 x86 光盘，与宿主逐字节相同），工具是 QEMU `-device loader` 塞进内存末尾的工具映像，执行器按客体 `.wasm` 的长度与三处样本认映像。10-10 起数据盘 `/工具` 只放 AMD64 豫行文件，ARM64 认不出映像，这条路已断。
- 编译器：`--目标系统 豫言 --目标架构 臂六十四` 报“豫言操作系统的 ARM64 还没有带执行器的豫行文件（待办事项）”（裸机后端 `原生产物。豫`）；只有底层程序有 ARM64 豫行（「生成臂豫行程序」，大码布局：机器码 0x60000000 起，栈顶 0x72000000）。「本机架构」在豫言操作系统上写死为兼容六十四。
- 内核：「按段建任务」两种架构都有；扩展主控驱动两种架构共用，ARM64 内核能认出 U 盘数据区，执行器开机不挂（ARM64 开机走「导出：启动」，把块态置 2）。
- ARM64 开机程序仍是旧壳 `.wasm`，嵌在内核镜像里由执行器解释执行，不能装单元（提案 00003 的待办）。
- 「构建臂启动盘」走「构建全部」造 `yy客体二号.wasm` 与 `壳.wasm`；光盘只有内核、字模、字体几段，没有数据区与工具链。它本身不调宿主命令（`dd` 只在 `--依赖数据盘` 时用），可以搬进系统里跑。
- `系统内造盘` 与 `--工具链` 写死只造 AMD64。
- 参考：`ARM硬件.md`（前七步、ARM64 内存布局与坑）、`ARM硬件交接.md`（测试法；工具映像部分作废）、`豫言操作系统/裸机/文档/臂平台.汉语.md`、`豫言操作系统/裸机/文档/豫行格式.汉语.md`、`提案/00005-自有可执行格式.汉语.md`、`提案/00007-实施记录.汉语.md`、`提案/00003-实施记录.汉语.md`。

## 建议步骤（每步各自合入）

1. 编译器直出 ARM64 带执行器的豫行文件（工具式布局），同时把「生成豫行程序」做成带架构参数的一份。先在现有 ARM64 系统里起一个 ARM64 豫行子程序（你好世界），跑通「按段建任务」。
2. 开机：「开机内核镜像」出 ARM64 版；ARM64 开机程序改为编译器直出的开机豫行（`开机。豫`），由豫言内核里两架构共用的 `。底层。豫` 装载（同时替掉 AMD64 的「兼容豫行模块初置」）；ARM64 启动光盘带上它；`运行 --架构 臂六十四` 改用 edk2 启动新光盘；删旧壳 `.wasm` 路径。
3. 数据盘：执行器在 ARM64 上开机挂 U 盘数据区；`启动盘 --架构 臂六十四 --工具链` 出合成镜像，`/工具` 放 ARM64 豫行工具。
4. 造盘：`系统内造盘` 与「构建启动盘」加 `--架构`（缺省本机架构；「本机架构」在豫言操作系统上改为查实际架构）；删工具映像机制。
5. 单元：ARM64 上单元机器码可执行（内核服务加指令缓存同步原语，写在豫言内核里），开机豫构的完整豫言句可用。
6. 跑完验收 1–6，结果写进「进度」；同步 `ARM硬件.md`、`ARM硬件交接.md`、`豫言操作系统/裸机/说明.汉语.md` 与相关双语文档。

## 测试方法

- 宿主造盘（仓库根，先照 AGENTS.md 起步得到原生工具链）：先 `./yy豫构.exe 文件 豫言操作系统/裸机/豫言系统。豫 --输出 yy豫言系统.wasm -j 24`，再 `YY_GC_INITIAL_HEAP_SIZE_MB=1024 node --max-old-space-size=24000 豫言操作系统/宿主/节点/宿主.cjs yy豫言系统.wasm 启动盘 --架构 臂六十四 --输出 目录 --预置 无 --工具链 --六十四位地址 --盘容量 2097152 --构 ./yy豫构.exe --编译器 ./yy4_bs.exe`；造完 `git checkout -- 库/壳核心/拼音字库。豫`（造盘会改写它）。
- QEMU：`qemu-system-aarch64 -machine virt,gic-version=3,virtualization=off,secure=off,highmem-ecam=off,iommu=smmuv3,default-bus-bypass-iommu=off -cpu host -accel hvf -m 12G -smp 4 -bios /opt/homebrew/share/qemu/edk2-aarch64-code.fd -display none -no-reboot -monitor tcp:127.0.0.1:端口,server,nowait`，串口接文件或套接字，U 盘 `-device qemu-xhci -drive if=none,id=yy_usb,format=raw,file=盘 -device usb-storage,drive=yy_usb`。盘用 `cp -c` 复制后 `truncate -s 9G`。串口出现“命令壳已就绪”后写入 `「构建启动盘」` 加回车（`\r`）。固件是调试版，串口上先有一堆固件日志。
- 取产物：数据区从合成镜像里光盘之后第一个 64 MiB 整数倍处起，`dd` 出来后用 e2fsprogs 的 `debugfs`（`brew install e2fsprogs`）`dump`，或用 `持久盘读取。豫` 写个临时程序；`shasum -a 256` 比对。
- 便宜检查：`./yy豫构.exe 类型检查 豫言内核 -j 24`（几秒）、`./yy豫构.exe 类型检查 客体二号 -j 24`；`yy裸机验证`（342 项，约 70 秒，命令见 `ARM硬件交接.md`）；AMD64 冒烟 `yy豫言系统 冒烟 x.iso`，加 `--固件 /opt/homebrew/share/qemu/edk2-x86_64-code.fd --固件变量 /opt/homebrew/share/qemu/edk2-i386-vars.fd` 为 OVMF。

## 规矩

- 照 AGENTS.md 快速合入：合入前只跑便宜检查（类型检查、`yy裸机验证`、冒烟）。ARM64 HVF 系统内造盘约 15–30 分钟，合入后再跑，期间做下一步，不空等。
- 动执行器、豫言内核或 `豫言系统。豫` 的造盘流程这些共享代码，合入后用 ListAgents／SendMessage 告诉 AMD64 目标的会话；对方正在跑长验证时先商量再合。
- ARM64 HVF 只在苹果芯片上（本机或 pit-mac），起重活前看负载。图形测试只在后台。
- 测试从简、能凑合着用就行；超出平台限制的边角写“待办事项”注释。
- 每做完一步在「进度」追加一行（日期、提交、验证、实测数），并更新「现状」。
