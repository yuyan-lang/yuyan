# 公开测试版

目标：发布**豫言操作系统第一公测版**（暂定版本号 `0.1.0-公测一`）。第一公测版只要求两件事：**能启动**，**有图形界面**。其余功能（在系统里写和运行程序、解释执行、网络、声音、装进内置硬盘等）留到后续版本补。

由一个代理负责到底（可以派子代理并行做调查或分块实现）。2026-10-06 用户定：停掉“图形界面”会话，由本目标的会话接管它的工作（工作树 `用户态图形桌面`，分支 codex/用户态图形桌面）。

## 验收标准

第一公测版合格的条件：

1. **能启动**：x86-64 的 BIOS/UEFI 混合 ISO，在 QEMU（q35，SeaBIOS 与 OVMF 两种固件）上用一条写在说明里的命令启动；另外至少在一种常见虚拟机（UTM、VirtualBox、VMware 任一）上启动成功。实机不作要求。
2. **有图形界面**：开机后能进入豫言桌面（开机直接进，或在命令壳输入「图形」进入），退出后回到命令壳。
   - 帧缓冲上画出窗口与中文。
   - 键盘可用（USB；PS/2 尽量），含拼音组字与 F2 切换。
   - 鼠标可用：至少支持虚拟机常用的 USB 绝对指针（QEMU `usb-tablet`），相对鼠标尽量。
   - 桌面现有的四个窗口（文件浏览器、命令行、系统设置、任务管理器）能打开、切换、关闭。
3. **能用、不崩**：在 QEMU 上交互流畅，从按键到画面更新不超过约 200 毫秒（加速与纯模拟各记一组数）；连续操作十分钟不崩溃、不耗尽内存。
4. **发行物**：CI 产出带版本号与 SHA-256 的 ISO 和发行说明，挂成 GitHub 草稿预发行（由用户决定何时公开）；网页版同步部署最新桌面。macOS 原生桌面应用、Node 版作为附带，不阻塞公测。
5. **说明与反馈**：
   - 官网有公测页：下载、启动命令、虚拟机与硬件要求、已知限制、反馈方式。
   - 仓库有 issue 模板与 CONTRIBUTING（写明要签贡献协议）。
   - 系统里的提示与实际能力一致，不再提示做不到的事。
6. **自动回归**：QEMU 无头启动 ISO、进入桌面、核对一帧画面（或串口标记）的冒烟测试，进 CI 或全树测试；过期的命令壳测试期望更新后恢复运行。

不在第一公测版范围内（后续补）：在系统里写和运行程序、解释执行、网络、声音、装进内置硬盘（AHCI、NVMe）、多核、实机兼容面、Windows 与 Linux 原生桌面、设置持久保存、苹果热插拔。

## 现状（2026-10-06）

- **桌面**（`库/用户态桌面`，细节见 [图形界面](图形界面.md)）：浏览器版已上线（需要 WasmGC 与 JSPI，只测过 Chrome 类）；Node 版能跑，但靠第三方 SDL；macOS 原生（arm64）能跑，完整桌面已过后台交互验收。桌面现有四个窗口：文件浏览器、命令行、系统设置、任务管理器。
- **裸机**：
  - x86-64 混合 ISO 能在 QEMU 启动，进入中文命令壳（拼音、行编辑）；造盘与启动命令见 `豫言操作系统/裸机/说明.汉语.md`（`启动盘` 子命令，要 `limine` 与 `xorriso`）。
  - 图形底座刚起步（13170a944）：内核新增服务 32「提交帧」、33「帧缓冲信息」；执行器有了裸机显示后端，整块帧缓冲当作一个显示面，键盘字节译成文字输入与按键，限时等待按时钟滴答。QEMU 上已验证 1280×800 的帧提交成功。图形界面会话停下时，`客体二号` 的显示原语、入口、布局三个文件有一处未提交改动（+138/−53），接手时先看清再续做或提交。
  - 还缺：鼠标驱动；裸机上的字体提供者（公共字体只有 macOS 实现；文楷 25.6 MB，裸机文件句柄缓冲只有 409600 字节）；资源太紧（单核，2 个任务槽，内存块池 64 MiB，每任务至多 32 MiB）；客体在裸机上解释执行，桌面能否流畅尚未量过；命令壳欢迎语提示“输入「图形」进入桌面”，但裸机上进不去。
- **发行**：CI 只发布 Wasm 工具链包，不出 ISO；没有系统版本号与发行说明；官网的操作系统页停在 09-30；没有 issue 模板与 CONTRIBUTING。

## 做法（建议顺序）

1. **接手**：读本文件、[图形界面](图形界面.md)、`库/用户态桌面/原生接入.汉语.md`、`豫言操作系统/裸机/文档/帧服务.汉语.md`；看清 `用户态图形桌面` 工作树里的未提交改动，续做或提交。三项新接口（指针形状、剪贴板读、预编辑事件）用户已准，按需做，不阻塞公测。
2. **裸机图形底座**：
   - 输入：键盘按键译成显示输入事件（含组字与 F2）；指针接 USB HID（先做 `usb-tablet` 绝对指针，再做相对鼠标），PS/2 鼠标可选。
   - 字体：给裸机做字体提供者。公测用一份够用的小字体（例如常用汉字子集，或预先栅格化的位图字形），随 ISO 带上；需要时放大文件句柄缓冲与盘的大小（限额往大里定）。
   - 资源：按固件内存表把可用内存交给任务，放大每任务内存与内存块池，任务槽加到够用。
   - 性能：先在 QEMU 量桌面每帧用时。太慢就做局部重绘与字形缓存；仍不够，就用预编二给裸机目标预编桌面客体（与「续作原生工具链，追平 Node」会话协调）。
3. **进桌面**：命令壳里「图形」能进桌面并能退回；可选开机直接进桌面的启动参数；修正欢迎语与提示，使之与实际能力一致。
4. **Node 版去掉 SDL**：Node 宿主的显示改为启动我们自己的原生显示程序（macOS 先做）；Linux、Windows 原生窗口做出来之前，Node 版在这两个平台不提供图形，写进已知限制。
5. **发行流水线**：CI 增加 ISO 作业（版本号、SHA-256、发行说明），生成 GitHub 草稿预发行；网页版重新部署（云仓，照云仓 AGENTS.md）；macOS 应用的签名与公证要用户的开发者账号，暂缓。
6. **说明与反馈**：官网公测页（云仓）；更新操作系统愿景页；仓库补 issue 模板与 CONTRIBUTING。
7. **自动回归**：QEMU 无头冒烟测试（启动 ISO → 进桌面 → 核对一帧画面或串口标记）进 CI 或全树测试；更新命令壳测试的期望。
8. **发布前**：照验收标准逐项自查，整理成清单交给用户；何时对外宣布由用户决定。
