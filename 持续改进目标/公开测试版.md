# 公开测试版

目标：发布**豫言操作系统第一公测版**（暂定版本号 `0.1.0-公测一`）。第一公测版只要求两件事：**能启动**，**有图形界面**。其余功能（在系统里写和运行程序、解释执行、网络、声音、装进内置硬盘等）留到后续版本补。

由一个代理负责到底（可以派子代理并行做调查或分块实现）。2026-10-06 用户定：停掉“图形界面”会话，由本目标的会话接管它的工作（工作树 `用户态图形桌面`，分支 codex/用户态图形桌面）。图形界面的细节记录仍在 [图形界面](图形界面.md)，其中与第一公测版有关的未完成项都已并入下文。

## 验收标准

第一公测版合格的条件：

1. **能启动**：x86-64 的 BIOS/UEFI 混合 ISO，在 QEMU（q35，SeaBIOS 与 OVMF 两种固件）上用一条写在说明里的命令启动；另外至少在一种常见虚拟机（UTM、VirtualBox、VMware 任一）上启动成功。实机不作要求。
2. **有图形界面**：开机后能进入豫言桌面（开机直接进，或在命令壳输入「图形」进入），退出后回到命令壳。
   - 帧缓冲上画出窗口与中文文字。
   - 键盘可用（USB；PS/2 尽量），含拼音组字与 F2 切换；只用键盘就能打开、切换、关闭桌面的四个窗口（文件浏览器、命令行、系统设置、任务管理器）并退回命令壳。
   - 鼠标尽量做（先做虚拟机常用的 USB 绝对指针，QEMU `usb-tablet`），不阻塞第一公测版；首版只用键盘是与裸机实机会话的既有约定。
3. **能用、不崩**：在 QEMU 上交互流畅，从按键到画面更新不超过约 200 毫秒（加速与纯模拟各记一组数）；连续操作十分钟不崩溃、不耗尽内存。
4. **发行物**：CI 产出带版本号与 SHA-256 的 ISO 和发行说明，挂成 GitHub 草稿预发行（由用户决定何时公开）；网页版同步部署最新桌面。macOS 原生桌面应用、Node 版作为附带，不阻塞公测。
5. **说明与反馈**：
   - 官网有公测页：下载、启动命令、虚拟机与硬件要求、已知限制、反馈方式。
   - 仓库有 issue 模板与 CONTRIBUTING（写明要签贡献协议）。
   - 系统里的提示与实际能力一致，不再提示做不到的事。
6. **自动回归**：QEMU 无头启动 ISO、进入桌面、核对一帧画面（或串口标记）的冒烟测试，进 CI 或全树测试；命令壳测试恢复运行（见“现状”里 15 个过期期望）。
7. **随附豫言基础库 0.1.0**（用户 10-06 定）：规格与发布门槛见 [提案 00004](../提案/00004-共用基础库.汉语.md) 第六节。基础库由用户指派的另一个代理实施，本目标的会话不做；发布时只核对门槛，把基础库清单与各库级别写进发行说明，把基础库的示例程序收进镜像。门槛未满足而其余已就绪时，问用户等还是先发。

不在第一公测版范围内（后续补）：在系统里写和运行程序、解释执行、网络、声音、装进内置硬盘（AHCI、NVMe）、多核、ARM64 图形、实机兼容面、Windows 与 Linux 原生桌面、设置持久保存、苹果热插拔。

## 现状（2026-10-06）

### 桌面与其他平台

- `库/用户态桌面` 现有四个窗口：文件浏览器、命令行、系统设置、任务管理器。
- 浏览器版已上线（需要 WasmGC 与 JSPI，只测过 Chrome 类），但 10-06 的光标闪烁、文本框选区，以及三项新接口（指针形状、组字预编辑、读剪贴板；显示 0.7、剪贴板 0.2）都还没重新部署。
- Node 版能跑，显示、指针形状、剪贴板都靠第三方 SDL，SDL 也不给组字事件。
- macOS 原生（arm64）完整桌面已过后台交互验收，原壳能原生运行并经「图形」往返桌面。

### 裸机

- x86-64 混合 ISO 能在 QEMU 启动，进入中文命令壳（拼音、行编辑）；造盘与启动命令见 `豫言操作系统/裸机/说明.汉语.md`（`启动盘` 子命令，要 `limine` 与 `xorriso`）。
- **图形第一阶段已完成**（13170a944）：
  - AMD64 内核新增服务 32「提交帧」、33「帧缓冲信息」（`裸机后端/帧服务。豫`，文档 `豫言操作系统/裸机/文档/帧服务.汉语.md`）。
  - 执行器新增 `客体二号/裸显示。豫`：整块帧缓冲当作一个显示面，像素比为一；键盘字节译成文字输入与按键（含 ESC 序列的方向键）。
  - QEMU 截屏颜色正确；`yy裸机验证` 380 项、普通豫言验证的“打印”“时间”双架构通过。
  - 坑：Limine 的 Multiboot 1 色彩信息比规范晚两字节；改内核后要重建 `yy豫言系统.wasm`。
- **桌面已能在裸机上带中文文字画出来**（10-06）：命令壳输入「图形」（拼音 tuxing 选 1 再回车），同一进程进入用户态桌面——桌面本来就编在壳里（`壳。豫` 导入「用户态桌面」之「运行」），不需要子程序授权。QEMU q35、SeaBIOS、纯模拟、512 MiB 下，「图形」后约 30 秒出首帧，四个按钮、文件浏览器与命令行窗口的中文都由文楷画出。前后三处问题：
  - **字体**：原先「打开」失败是因为裸机句柄打开时把整份文件读进 409600 字节的内容缓冲，25.6 MB 的文楷直接报溢出；而且常见虚拟机从光驱启动，内核读不到 ISO 里的文件。改为把文楷作为 **Limine 第二个模块**随 ISO（`boot/字体/文楷.ttf`，许可随附），内核在设备初置阶段映到 1 GiB + 32 MiB 的内核窗口，新增服务 34「读字体模块」、35「字体模块长度」（每次至多拷 64 KiB，界限同提交帧）；执行器在裸机上对任何族名都取这份字体，按偏移分段读（`显示原语。豫` 的「字体裸开」「字体裸定读」）。实测 Limine 把模块紧接内核放在 64 MiB 块池之下（SeaBIOS 14.1–38.5 MiB，OVMF 23.5–53.9 MiB）。主核已近 12608 字节上限，分派表改成一条 32–35 的区间判断（不增一字节），模块映射放进外置的设备初置。
  - **内存**：桌面一启动就“堆内存不足”——执行器的页上限是 512 页（32 MiB），堆基却在 21.8 MiB（值栈、边表、句柄缓冲等占了前面），只剩约 10 MiB，而一帧像素就要 4 MB。内核单任务本来就能拿 32 块（64 MiB），把「裸机页容量上限」与执行器裸机页上限都提到 1024 页即可；执行器在“堆内存不足”前另打一行堆诊断（请求、堆基、堆顶、堆限、页数、回收阈）。
  - **提交帧**：内核提交帧对像素地址有 32 MiB 的粗上界，页上限提到 1024 页后帧缓冲分配到 32 MiB 以上，提交一律失败、屏幕停在命令壳；上界放宽到 1 GiB。
- **键盘**：内核把 F2 译成字节 0x12，裸显示现在把它（以及串口来的 ESC O Q、ESC [12~）译成「功能二」键；回车、退格、制表、方向键等照旧。桌面的按钮都可制表键移焦点、回车按下。
- **速度**（纯模拟，解释执行）：字体解析不到 0.1 秒，每个字形栅格化约 0.3 秒；同一探针 macOS 原生解释执行每字 5–10 毫秒、预编二不到 1 毫秒，模拟约慢 30–40 倍。原生上桌面首帧栅格化 76 个字形；裸机首帧约 30 秒，交互还没量。
- **命令壳测试已恢复**（壳测试期望分支，已合入）：10-03 起壳只收正式句式，13 项测试的输入与期望都改写；在用的 7 项双架构全过，完整普通豫言验证 46 项双架构全过；就绪超时改为约 5 分钟并打印已收输出；交互项按终端回车语义整理后比较。运行、示例、崩溃、大程序、子进程文件、中断 6 项因裸机「运行」不可用暂停（公共子程序授权表在裸机上为空）。
- 其他限制：
  - 没有鼠标驱动。
  - 限时等待按时钟滴答忙等。
  - ARM64 没有帧服务与字体模块服务（执行器视为没有显示）。
  - 资源：单核，2 个任务槽，内存块池固定在 64–128 MiB（32 块，块 0 与 30、31 保留），桌面所在任务几乎占满，「运行」子程序会因复制任务缺块而失败；单个文件句柄缓冲 409600 字节。
  - 没有数据盘时文件浏览器显示“路径不存在”（桌面目录在 USB 数据盘上）。
  - 壳测试发现：同一会话第 5 次读文件就“堆内存不足”（每次读取按请求长度新建 1 MiB 数组，512 页时如此，1024 页后待复测）；Ctrl-C 不能放弃半行；说明里的壳功能表仍写着已不可用的 `tmp-*`、重定向与管道。
  - 「图形」后屏幕上会先印几行 USB 诊断（内核在首次访问存储时打印）。
  - 剪贴板在裸机上用执行器进程内的 256 KiB 区，复制粘贴能用。

## 做法（建议顺序）

1. **接手**：读本文件、[图形界面](图形界面.md)（尤其“裸机图形（进行中）”一节）、`库/用户态桌面/原生接入.汉语.md`、`豫言操作系统/裸机/文档/帧服务.汉语.md`。工作树已干净，图形界面会话的改动都已提交并合入 yybs（678a68127）。
2. **修好裸机字体**（第二阶段）：
   - 按上面的排查线索找出「打开」失败的原因并修好，让显示控件示例在 QEMU 里画出文字。
   - 然后解决字体的体积：换成第一公测版够用的小字体（常用汉字子集，或预先栅格化的位图字形，随 ISO 或数据盘带上），或者放大文件句柄缓冲与任务内存。限额往大里定。
3. **定下桌面在裸机上的启动方式**，二选一：
   - 让壳能启动数据盘上的桌面程序：给裸机的子程序定一个最小授权模型，至少放行系统自带的桌面。
   - 或者照 macOS 原生原壳的做法，把桌面编进壳里，「图形」在同一进程内进出。
   然后让「图形」进桌面、退回命令壳；可选加一个开机直接进桌面的启动参数；把欢迎语与提示改成与实际能力一致。
4. **输入**：键盘补齐组字与 F2，保证只用键盘能操作桌面四个窗口；鼠标尽量做（先 `usb-tablet` 绝对指针，再相对鼠标，PS/2 鼠标可选），不阻塞第一版。
5. **资源与速度**：
   - 资源：按固件内存表把可用内存交给任务，放大每任务内存与内存块池（提案00003 已定的“每任务 8192 页、块池按物理内存”可以先做），任务槽加到够用。
   - 速度：在 QEMU 量桌面每帧用时。太慢就先做局部重绘与字形缓存；仍不够，用预编二给裸机目标预编桌面客体（与「续作原生工具链，追平 Node」会话协调）。
6. **修命令壳测试**：更新 15 个过期 `.期望`，整套重跑核对；顺手让就绪等待不必等 50 分钟才超时。
7. **Node 版去掉 SDL**（照 AGENTS.md「诺节（Node）后端」的硬性要求：诺节只当胶水，不做诺节适配，不引第三方库）：显示、指针形状、剪贴板都改为经 `node:ffi` 调用我们自己用豫言写成的原生显示库，与原生执行器共用同一份实现（macOS 先做；原生生成器先要能产出动态库）。Linux、Windows 原生窗口做出来之前，Node 版在这两个平台不提供图形，写进已知限制。图形处理器（`@kmamal/gpu`）同理换掉，不阻塞第一公测版。
8. **发行流水线**：
   - CI 增加 ISO 作业（版本号、SHA-256、发行说明），生成 GitHub 草稿预发行。
   - 网页版重新部署（云仓，照云仓 AGENTS.md），带上 10-06 的光标闪烁、选区与三项新接口。
   - macOS 应用的签名与公证要用户的开发者账号，暂缓。
9. **说明与反馈**：官网公测页（云仓）；更新操作系统愿景页；仓库补 issue 模板与 CONTRIBUTING。
10. **自动回归**：QEMU 无头冒烟测试（启动 ISO → 进桌面 → 用 monitor 的 screendump 核对一帧、用 sendkey 验键盘），进 CI 或全树测试。
11. **发布前**：照验收标准逐项自查，整理成清单交给用户；何时对外宣布由用户决定。

## 规矩

- 一个代理负责到底，可以派子代理；子代理也守“一任务一工作树”：只读调查，或各用自己的工作树。
- 需要用户在场或操作的事一律暂缓（见上节）；生产部署若被自动模式拦下，把命令交给用户。
- 与其他会话协调：「续作原生工具链，追平 Node」管预编二与 `客体二号` 的性能；「续作提案00002」改编译器；裸机会话已停，xHCI 与 `兼容核心` 可以直接改。改动前变基 yybs，冲突用 SendMessage 商量。
- 合入照 AGENTS.md「验证」的快速合入：合入前只跑最便宜而有用的检查，完整测试交给 CI；CI 不覆盖的裸机验证 380 项、普通豫言验证、QEMU 冒烟在合入后跑，失败就尽快修。已知尚不能用的改动不得默认开启（ada241945 把“尚不能用”的字体代码合入就是反例）。走「sync … with yybs」，只推送 yybs。
- 图形测试只在后台：本机原生窗口加 `--显示面后台`，用后台 `app_*` 工具；裸机图形用 QEMU 无头截帧（screendump）或 VNC 截图核对。造盘时 `yy豫言系统 启动盘` 会重生成 `库/壳核心/yy拼音字库。豫`，提交前要还原。
- 生成原生程序时，生成器与执行器必须用同一份源码重建。
- 机器：本机与 pit-mac 平衡着用（见 [总览](总览.md)）。
- 每完成一项，就地更新本文件的「现状」，并在「进度」追加一行；图形界面的细节同步记进 [图形界面](图形界面.md)。
