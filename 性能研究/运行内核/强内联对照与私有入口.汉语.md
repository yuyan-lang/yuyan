## 比较方法

从本机 opam 已有的 OCaml 5.5.0 源码复制出独立构建目录，使用 `--enable-flambda` 构建并安装到临时目录。没有修改系统 OCaml 或默认 opam switch。实际 `ocamlopt -config` 确认为 `version: 5.5.0`、`flambda: true`；完整配置保存在 `Flambda复测/编译器配置.txt`。本次是官方 OCaml 的 Flambda，不是另外的 Flambda 2 工具链。

基准使用同一份 `原生内核.ml`、相同 `-O3`，保留安全数组访问；与原有非 Flambda OCaml、豫言 Wasm 交替运行。每项三进程，每进程六轮，首轮单列，后五轮共十五个样本取中位数。原配置也已保存；两套编译器的构建配置并非每项都相同，不能把其间全部波动都归因于 Flambda。Flambda 的启用与优化选项参考 [OCaml 官方手册](https://ocaml.org/manual/flambda.html)。

新增高阶调用：将两个函数放入数组，由命令行参数选择回调，尾递归进行四百万次累积。两端均使用相同算法和选择方式，没有为豫言静态指定回调。回调 0 为加一，回调 1 为乘三。所有 756 次调用均完成，各组结果值一致；仍只检验既有基准的结果值，不宣称逐元素比较矩阵与排序结果。

测量期间不并发构建。数字为进程内算法耗时，不包含启动；仍是豫言 Wasm/V8 对 OCaml 原生，不是同一后端的比较。

## 私有入口已经实现的范围

需要纠正此前对话给人的时间顺序印象：私有入口在前一轮已实现，包含在 `e55c39dc`。本次没有把它重复记作新实现或新提速。当前实现包括纯整数入口 `$n`、混合参数入口 `$m`，以及需要类型守卫时的通用后备体 `$b`；通用 `$f` 入口和值布局保留。

`Flambda复测/私有入口实例.wat` 是从此次实际斐波那契产物提取的代码片段。通用 `$f747` 接收和返回 `(ref null eq)`，入口拆箱，调用 `$n747` 后装箱。私有 `$n747` 接收和返回 `i64`；两处递归直接调用 `$n747`，其函数体中没有 `$box` 或 `$unbox` 调用。编号是编译器内部细节，不能作为外部接口。

实际模块导入导出清单存于 `Flambda复测/模块边界.json`；私有入口没有导出。原有 `yuyan:gc-host/v1.call` 宿主边界保留。未改变泛型数组布局、宿主协议或原生 128 位通用值表示，也没有新增专用数组 API。

新增 `测试/网页汇编/私有入口-1。豫` 验证引用包装入口、i64 私有签名、不导出私有函数，以及函数存入数组后仍可通过通用闭包调用；Wasm 与原生均运行通过，输出符合预期。它与既有整数极值、泛型回退、异常顺序等回归相互补充。编译器核心本轮未再修改，因此沿用上一轮已通过的完整原生自举、Wasm 固定点及冷缓存自举 18.16/18.30/18.68 秒成绩；这些是上一轮验证，不冒称本轮重新计时。

## 复现

```sh
# 在独立的 OCaml 5.5.0 源码副本中运行
./configure --prefix=/tmp/yy-ocaml-flambda-install --enable-flambda
make -j 12 world.opt
make install
/tmp/yy-ocaml-flambda-install/bin/ocamlopt -config

# 将原生内核.ml、单调钟.c、高阶调用.ml 复制到临时构建目录，避免混用 .cmx
/tmp/yy-ocaml-flambda-install/bin/ocamlopt -O3 -I /tmp/yy-ocaml-flambda-install/lib/ocaml -o yy内核Flambda /tmp/yy-flambda-bench/单调钟.c /tmp/yy-flambda-bench/原生内核.ml
./yy内核Flambda 斐波那契 40
./yy内核OCaml 斐波那契 40
node 工具/节点网页汇编宿主/宿主.cjs yy终核斐波那契.wasm 40

/tmp/yy-ocaml-flambda-install/bin/ocamlopt -O3 -I /tmp/yy-ocaml-flambda-install/lib/ocaml -o yy高阶Flambda /tmp/yy-flambda-bench/单调钟.c /tmp/yy-flambda-bench/高阶调用.ml
./yy高阶Flambda 4000000 0
node 工具/节点网页汇编宿主/宿主.cjs yy高阶内核.wasm 4000000 0
```

后续优化继续冻结现有通用 ABI。可优先研究把循环不变的闭包取函数操作移出循环、对可证明目标的调用使用私有入口，以及数组索引范围证明。新增紧凑数组表示暂不实施；此轮结果不能证明只靠私有入口就能消除所有数组差距。
