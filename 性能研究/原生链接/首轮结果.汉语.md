# 原生自举性能调查

日期：2026-09-19。起始提交：`03e4d5f4`。本机 macOS arm64，Homebrew clang 22.1.7，编译器默认 18 个工作进程。

最终指标是完整自举墙钟时间。本文中的链接及前端实验只用于定位成本，不能代替完整自举，也不能证明豫言已经达到 C、OCaml 或 Haskell 的一般运行性能。

## 已确认的基线

重建运行库后，执行仓库规定的稳定种子 → `yy2_bs` → `yy3_bs` → `yy4_bs`。最后一步使用新编译器身份对应的全新编译缓存，墙钟 **63.40 秒**，用户态 **137.58 秒**，系统态 **22.48 秒**。计时包含文件式入口的包准备、前端、默认双份阶段导出、C 生成、原生编译链接；复用已构建的原生运行库和操作系统页缓存，不代表磁盘物理冷启动。

第三、第四代逐字节相同，SHA-256 为：

`75c9bd734c42f702883155c64e66e3025ce814c4720560a4b14b8b2f3a689eb5`

这是加入新对照选项之前的源码基线，不能与后续版本混合计算正式加速比。该版本的并行类型检查通过。

## 同一份 C 的原生编译链接

输入是上述第四代生成的 C，19,103,066 字节、488,403 行。下面各项顺序执行，每项一个样本；没有同时运行其他本任务的构建。均复用同一个包原生归档与重建后的完整 LTO 运行库。

| 选项 | 墙钟秒 | 用户态秒 | 系统态秒 |
| --- | ---: | ---: | ---: |
| `-O3 -flto`，附带 `-ftime-report` | 42.36 | 40.39 | 1.93 |
| `-O2 -flto` | 39.94 | 39.31 | 0.61 |
| `-O3 -flto=thin` | 13.25 | 12.91 | 0.33 |

完整 LTO 这一独立样本约为完整自举墙钟的三分之二，但两者来自不同运行，不能当作同一次运行的精确阶段占比。clang 报告中的前链接编译时间为 5.6981 秒；该报告没有包含链接器内部的 LTO 阶段。尚未对链接器内部各优化阶段做归因。

`-O2` 的单样本差异不足以支持更改默认优化等级。ThinLTO 明显缩短了这一实验的构建时间，但生成程序运行速度必须另外检查。

## 生成的编译器运行速度

对同一份未修改源码，分别用完整 LTO 和 ThinLTO 生成的编译器执行：

```sh
./yy4_bs 豫言编译器/入口。豫 --parallel --no-link --do-not-load-cache
./yy性能薄链接 豫言编译器/入口。豫 --parallel --no-link --do-not-load-cache
```

两者均从头执行前端、保留默认阶段导出，不生成最终 C 和可执行文件。每项一个样本。

| 编译器构建方式 | 墙钟秒 | 用户态秒 | 系统态秒 |
| --- | ---: | ---: | ---: |
| 完整 LTO | 21.69 | 96.10 | 26.55 |
| ThinLTO 主程序＋完整 LTO 运行库 | 32.79 | 154.75 | 21.37 |

ThinLTO 版本在这次前端负载中慢约 **51.2%**。这是编译器真实工作负载的结果，不是其他豫言程序的退化比例。不能把 13.25 秒的链接成绩直接宣布为语言整体优化成功。

## 未通过的实验与环境修复

- 初始运行库归档比运行时源码旧，`处理豫言参数` 仍在旧 `入口.o` 中，使统一原生入口链接出重复的 `main`、全局参数符号。执行 `make yy_runtime_lib` 后解决。此前失败的 26.47 秒不计入自举成绩，磁盘上遗留的旧 `yy3_bs` 也不算新产物。
- 将整个运行库以 `-O3 -flto=thin` 单独重建，再与同一份生成 C 链接，本机工具链报 `LLVM ERROR: Unsupported stack probing method`，退出失败。没有禁用栈探测来掩盖错误，也没有用这个运行库替换正常运行库。
- 新增选项后，旧稳定种子的增量缓存没有反映修改；按仓库说明 `touch yy_bs_stable` 隔离旧缓存后重新验证。旧缓存那一轮不作为本次变更验证依据。

## 本次代码改动

增加 `--native-lto=full` 和 `--native-lto=thin`，供原生后端完整自举对照。默认仍为 `full`，保留 `-O3`；`--do-not-optimize` 仍使用 `-O0 -g`。两种选项不改变前端优化轮数、阶段格式或语言语义。ThinLTO 暂为实验路径，尚不能据此降低生成程序的性能要求。

手动审阅后，`./yy 豫言编译器/入口。豫 --type-check-only` 通过。隔离稳定种子的旧缓存后，严格执行：

```sh
./yy_bs_stable 豫言编译器/入口。豫 -o yy2_bs >/dev/null 2>/dev/null
./yy2_bs 豫言编译器/入口。豫 -o yy3_bs --parallel >/dev/null 2>/dev/null
./yy3_bs 豫言编译器/入口。豫 -o yy4_bs --parallel >/dev/null 2>/dev/null
cmp yy3_bs yy4_bs
./yy3_bs 豫言编译器/入口。豫 --type-check-only --parallel >/dev/null 2>/dev/null
```

均通过。最后一步自举单独计时 **64.97 秒**（user 138.22、sys 24.42），第三、第四代 SHA-256 均为 `f590ffc7dc659b44583ad08d0b3ef8303d98be8d141a7c3ede1090ee2ac915c4`。帮助包含新选项，非法 `--native-lto=invalid` 被拒绝。默认行为保留，尚未声称默认自举获得加速。

## 新选项的完整自举对照

采用上节相同源码，先用完整 LTO 编译器生成 ThinLTO 种子，再让该种子完整编译自身。保留 `-O3`、默认双份阶段导出和 18 个工作进程，显式禁止读取旧编译缓存，不同时运行其他本任务的构建。

```sh
./yy4_bs 豫言编译器/入口。豫 -o yy薄自举甲 --parallel --native-lto=thin --do-not-load-cache
./yy薄自举甲 豫言编译器/入口。豫 -o yy薄自举乙 --parallel --native-lto=thin --do-not-load-cache
./yy薄自举乙 豫言编译器/入口。豫 -o yy薄自举丙 --parallel --native-lto=thin --do-not-load-cache
cmp yy薄自举甲 yy薄自举乙
cmp yy薄自举乙 yy薄自举丙
cmp yy4_bs.c yy薄自举乙.c
cmp yy4_bs.c yy薄自举丙.c
./yy薄自举丙 豫言编译器/入口。豫 --type-check-only --parallel
```

| 执行者 → 生成方式 | 墙钟秒 | 用户态秒 | 系统态秒 |
| --- | ---: | ---: | ---: |
| 完整 LTO → 完整 LTO，规定自举最后一级 | 64.97 | 138.22 | 24.42 |
| 完整 LTO → ThinLTO，仅准备种子 | 37.14 | 110.83 | 24.13 |
| ThinLTO → ThinLTO，真正自身编译 | 48.79 | 169.06 | 21.36 |
| ThinLTO → ThinLTO，下一代复测 | 49.04 | 169.79 | 21.20 |

甲、乙、丙二进制相同，SHA-256 为 `591bb7b635da9229f6499b4692f94f9aaea21664616aa30a66cb0f196d67fd50`；生成的 C 也与同源完整 LTO 路线逐字节一致，丙的并行类型检查通过。**37.14 秒不是 ThinLTO 编译器的持续自举成绩**。持续自举两个样本平均 48.915 秒，比同源默认的单样本缩短约 24.7%，但同时存在前述生成程序运行速度退化。样本数量有限，不作统计显著性保证。默认设置因此尚未切换。

额外静态检查：对最初同源的完整 LTO 与混合 ThinLTO 二进制分别执行 `llvm-objdump -d`，计数指向 `_豫言_整数加` 的 `bl` 指令为 0／95，指向 `_读取元组` 的为 0／27,396。这里只统计静态调用点，不代表动态执行次数或精确耗时。结果支持继续调查跨运行库内联差异；不能断言 ThinLTO 本身必然导致同等退化。

ThinLTO 的模块摘要、并行后端及使用方式参见 [LLVM 官方文档](https://clang.llvm.org/docs/ThinLTO.html)。当前豫言主程序仍生成一个 C 翻译单元，因此没有实现按豫言模块并行执行原生后端。

## 复现原生编译链接实验

原始输入 C 的 SHA-256 为 `436d27ee8f28892834aa03a1c45360e9d4b0bff28588fe72a5f0383205e7592f`；本机保存在 `/tmp/豫言性能原基线.c`。当前源码重新自举会生成包含新增选项的不同 C，不能与原始样本混算。

```sh
/usr/bin/time -p clang -O3 -flto -DNDEBUG -Wl,-S -pthread -Wno-unused-value -I运行时支持库/原生 -ftime-report /tmp/豫言性能原基线.c -o yy性能原生三级 .yybuild/豫构原生/13.上下文/包原生.a 运行时支持库/lib豫言运行时包优化v0.1.0rc2+0019.a
```

其余对照只替换 `-O3 -flto` 为 `-O2 -flto` 或 `-O3 -flto=thin`，去掉 `-ftime-report`，使用独立输出名。包归档路径是本机包上下文的产物，其他工作区须使用其实际链接清单。完整剖析输出与统一薄链接的错误保存于本目录文本文件；原始运行日志位于 `/tmp/豫言性能*.log`、`/tmp/豫言性能*.err`。

## 后续方向与验收决策

优先研究保持生成代码性能的原生后端提速，包括统一运行库优化方式、定位 ThinLTO 工具链错误，以及分割大型翻译单元。随后按实际剖析数据处理前端阶段读写、进程调度、装箱值和闭包调用。任何更换值表示或 GC 协议的方案都需要单独验证，不能只用链接时间作结论。

需要用户确定完整冷编译缓存自举的验收门槛，以及是否允许为了自举墙钟时间而牺牲生成程序的运行速度。当前证据不足以宣布达到“商业级”或“与 C 相当”。
