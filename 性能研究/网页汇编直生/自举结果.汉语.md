# ANF → Wasm GC 编译器自举

已经打通真实自举：GC 编译器读取 `豫言编译器/入口。豫` 及其依赖，生成下一代 GC 编译器。串行生成的种子、第二代及显式大堆产物逐字节一致。这里只测完整编译器自举，没有采用斐波那契、数组或树等微基准的结果。

## 测量口径

输入为冻结后的同一份编译器源码，共 170 个模块。原生路线生成本机可执行编译器，GC 路线生成 Wasm GC 编译器。计时包含进程启动、依赖分析、语法分析、类型检查、优化、闭包转换及最终产物生成；原生包含 LLVM/Clang 编译与链接，GC 包含客体内的 ANF/WAT 生成及宿主 WAT 组装。

环境为 Apple M5 Pro、arm64、macOS；Wasmtime 为 48.0.1，Cranelift。GC 编译器预先 AOT 编译，每次测试启动新进程。AOT 预编译、引擎构建与依赖下载不在自举计时内。每个配置一个完整样本，编译缓存均为新身份下的冷缓存，文件系统页缓存可能已热；测试期间不并行运行其他本任务的编译测试。未固定 CPU 频率或核心，因此不把单个样本当作跨机器或跨负载的性能保证。

## 结果

| 后端与引擎配置 | 串行自举 | 四进程自举 |
|---|---:|---:|
| 原生 LLVM 后端 | 185.11 秒 | 68.71 秒 |
| GC copying，默认堆，未内联 | 866.28 秒 | 596.36 秒 |
| GC copying，128 MiB，未内联 | 809.59 秒 | 未测 |
| GC copying，128 MiB，启用内联 | 未测 | 346.54 秒 |

显式大堆串行配置为原生串行耗时的 **4.37 倍**；已测最快的 GC 四进程配置为原生四进程的 **5.04 倍**。当前实现已能自举，但仍不满足无性能损失的迁移条件。内联四进程同时改变了默认堆对照的堆容量与内联设置，不能把全部改善单独归因于内联。

原生使用现有运行时默认设置，GC 容量如表所列；两者没有施加相同的硬内存上限。

原生程序与 Wasm GC 产物的最终后端工作不同，这张表比较的是迁移后实际要完成的端到端自举任务，并非只比较 GC 分配器或一条机器指令。

## 正确性与边界

- 串行 GC 固定点 SHA-256：`890a79a282a9f055dce69134ba9ac309de43d5a2b646bd3177956b8662e08740`。
- 第二代 GC 编译器已实际执行四进程自举，1191 个任务成功，生成第三代 Wasm。相同第二代输入在默认配置和大堆内联配置下生成的并行产物逐字节一致，SHA-256 为 `db4f9bf6ef038902511848dfa2e2a3e1832c858fdace34a945462e7b33949b21`。后者日志中的文件名为 `yy回收四代.wasm`，表示另一个配置的产物，不是额外一次链式代际测试。串行和并行产物字节不同；串行固定点与并行配置一致性分别记录。
- 并行生成的 Wasm 已通过引擎验证，直接运行 `--help` 正常退出；独立直生工具已按最终源码重建。
- 原生二至四代自举与类型检查已通过，第三、第四代原生程序一致。旧 `yy_bs_stable` 不能识别当前包布局，首级按记录使用 `yy豫构` 与已有编译器生成，再执行后续自举检查。
- 默认堆串行计时最初用了 `/usr/bin/time -lp`；子进程结束后的附加资源统计受沙箱限制，包装器退出 1，但墙钟、用户及系统时间已经写出，编译器产物正确。后续全部改用 `-p`，并检查正常退出。
- 默认宿主入口曾绕过配置对象。相关早期 copying 成绩已纠正为默认堆；显式 128 MiB 和内联配置均通过已构造引擎的 getter 输出验证。
- 中止的诊断运行、原生链接清单遗漏导致的失败运行，均不计入有效结果。

## 已实现的后端与剩余开销

实现位于 `库/编译器核心/编译步骤/代码生成/网页汇编直生。豫`，目标为 `--target=wasmgc`。它直接生成 Wasm GC 引用、数组和结构体，不经过 LLVM，也不使用原有 C 虚拟栈。字符串字面量在启动时创建一次，热路径的字符串拼接、UTF-8/JSON 扫描在客体内执行。文件与进程等系统操作经显式宿主接口完成；宿主没有代替客体执行编译器算法。

为了支持真实编译器中的异常和可捕获续延，非尾调用的剩余计算保存为 GC 续延对象，并通过尾调用恢复。这仍有分配、字段读取和通用值装箱/解箱开销；“移除 C 虚拟栈”不等于这些开销自动消失。当前元组和代数构造器布局也没有充分利用专门的 GC 结构体类型。并行调度还会为 GC 路线已经跳过的 ANF/旧代码生成阶段启动工作进程，最终 GC 生成则集中在一个进程中。

诊断版自举采样确认 DRC 的空闲块维护是重要热点，因此正式对照采用 copying。默认堆串行日志按秒级阶段标记估算，语法分析阶段（含词法解析及缓存写入）约 534 秒；这是阶段归因，不是精确的函数级剖析。后续优化应继续在完整自举上验证，不能由这些数据推出所有 Wasm GC 程序都比 C 慢。

## 复现

先按 `工具/网页汇编宿主/复制回收构建.汉语.md` 构建复制宿主。上下文与原生链接清单路径是本机示例，应使用当前豫构生成的对应产物。

```sh
# 原生参考；touch 只更新缓存身份，不修改编译器字节。
touch yy3_bs
/usr/bin/time -p ./yy3_bs 豫言编译器/入口。豫 \
  --package-context .yybuild/豫构上下文/24.上下文 \
  --native-link-inputs "$PWD/yy自举原生链接清单" \
  --target=llvm --parallel -j 4 -o yy原生三代

# GC 编译器的 AOT 准备，不计入下面的自举时间。
YY_WASM_GC_CONFIG_LOG=1 YY_WASM_GC_INLINE=1 \
  ./yy网页汇编复制宿主 --预编译 yy回收二代.wasm yy回收二代大堆内联.cwasm

# 首次使用该 AOT 身份，或先 touch 以建立新的编译缓存身份。
YY_WASM_GC_INLINE=1 /usr/bin/time -p \
  ./yy网页汇编复制宿主 --运行预编译 yy回收二代大堆内联.cwasm \
  豫言编译器/入口。豫 --package-context .yybuild/豫构上下文/24.上下文 \
  --target=wasmgc --parallel -j 4 -o yy回收四代.wasm
```

原始日志、计时、配置输出、产物摘要及诊断状态保存在同目录 `自举记录/`。
