# WasmGC 自举性能优化过程

本轮目标：定位真实自举热点，优化到与同源码原生自举接近。以下是过程记录；最新实现、自举验证和性能验收阻碍见《优化结果.汉语.md》。最终稳定性能验收尚待开盖接电复测。所有有效计时都是完整编译器自举，170 个模块；没有使用微基准替代。各轮输入源码包含当轮改动，历史轮次之间不是严格的单变量消融实验。

## 已确认的热点与机制

初始 EH 自举在 10 秒采样窗口有 8338 个活动线程样本。将 AOT 符号与 vmmap 地址对应后，列表附加的两个函数占至少 3337 个样本，约 40%。第二次窗口的调用栈显示附加的主要上层调用者是反转。旧反转递归处理尾部，再追加单个元素，会重复遍历及分配，复杂度为 O(n²)；现在用尾递归首插累积，复杂度 O(n)。此标准库改动同时用于原生与 Wasm。

后续采样的 6498 个活动线程样本中，至少 3778 个直接落在 copying GC 的搬迁、收集、字段扫描、对象类别和数组长度读取函数中，约 58%，未把独立的 memmove 样本全部归给 GC。128 MiB 复制堆的活动半区约为 64 MiB。使用同一输入 Wasm、分别按匹配堆配置 AOT 后，512 MiB 将串行从 259.55 秒降到 216.26 秒。此优化增加了每个工作进程的内存预算；初始容量不是实测 RSS。

生成器曾把已知的小整数、布尔值和函数编号也经过通用包装/解码。现在小整数常量及比较结果直接生成 i31，函数编号直接提取；普通算术的解码在调用处展开，仍保留完整 i64 路径。函数和全局编号改用 4096 个桶的索引，按原遍历顺序分配编号；碰撞时比较完整名字。

宿主原来逐字节使用 C API 读取/写入 GC 数组，每字节重复类型和根操作。新增 C API 桥接包装引擎已有的整段字节复制接口，仍保留类型检查和 GC 根。普通宿主保留兼容实现，复制宿主使用批量路径。

并行 Wasm 从 1191 个任务先去掉 340 个空阶段，再将单个模块的语法、类型、跨模块优化和闭包转换合并到同一工作进程，最终为 341 个任务；依赖模块完成后才编译使用它的模块。仅类型检查保留原有阶段调度。

原语内联通过小型索引记录非递归的原语封装和文件别名，只在调用位置展开，别名展开有深度限制；实际递归定义不展开，函数值单独传递时不重建闭包。索引登记对擦除后形式的依赖，缺失或过期会重建。

短字符串缓存只得到小幅单次改善，已撤回，避免为不确定收益保留额外机制。空串拼接直接返回另一侧的优化保留。

最新前后缀判断按必要字节比较，不再把整个字符串拆成链表；检查 UTF-8 后续字节边界，保留原字符分段语义。WAT 转义的十六进制字表从每次调用重新构造改为全局一次初始化。

中间树缓存原来保留整个自举过程中所有阶段的树。现在类型检查后移除抽象语法树缓存根，优化后移除擦除树缓存根，闭包转换后移除优化树缓存根。磁盘缓存、检查后定义、原语索引和后端所需的闭包树都保留，后续若再次读取也可从磁盘恢复。

第一轮优化后的四进程完整自举为 69.89 秒，生成的 Wasm 与原生生成的种子逐字节一致；起点同为四进程的 237.27 秒。当时同源码原生四进程为 44.29 秒，Wasm 仍慢 57.8%。随后原生同版本冷缓存复测为 72.94 秒，说明机器负载或调度状态变化很大；最终结论必须依据交替重复的同源码样本。

## 测量与验证边界

原始数据、采样压缩包及构建日志位于 `优化记录/`。两个诊断自举进程在采样后被停止，不算完整性能样本。构建失败和配置不匹配另有日志，不计入有效耗时。前缀改动开发中修正了导入、C 调用类型标注和直接参数要求；原语内联开发中修正了匹配分支及缓存依赖登记。

每次正式计时使用新编译缓存身份，文件系统页缓存可能已热。计时不与本任务的其他编译或采样并发。AOT 准备不计时，启动、装载、实例化、前端与最终产物生成计时。原生生成本机编译器，Wasm 生成 Wasm 编译器，最终后端工作不同。没有固定 CPU 核心、频率或相同硬内存上限。

旧原生稳定器不识别当前包布局；首级通过豫构与已有编译器构建，其后执行规定的二至三代、三至四代命令，并检查字节一致与类型检查。当前最后一轮的一致性及性能验收仍在进行。

## 后续诊断与未采纳试验

尝试在 JSON 转义前调用四次现有子串搜索，普通字符串直接返回，未证明有效，已撤回。该版本四进程为 100.89 秒；运行期间有一次约 5 秒的本地分析，不纳入最终验收。撤回后、保留 AOT 文件映射入口的四进程为 98.06 秒，输出与种子一致。此时观察到其他应用持续占用 CPU，原生也从 44.29 秒变为 72.94 秒，不能把差异全部归因于实现。

AOT 宿主由读入整个文件再反序列化，改为 `wasmtime_module_deserialize_file`，免去每个工作进程预读约 21 MiB 文件。该入口仍只用于显式指定的本机构建 AOT，兼容性检查不变。其独立速度收益尚未在稳定负载下确认。

独立诊断运行只重做自举的最终生成阶段，不作为完整自举性能样本。活动线程共 3339 个样本；将映射基址 `0x10a8f8000`、AOT 符号和 5392 个函数名对应后，`抽象替换自由变量` 的四个提升函数在折叠栈顶表中合计至少 700 个样本，约 21%；直接 GC 栈顶为 1058 个，约 32%，另有 219 个 memmove 样本未全部归给 GC。诊断峰值物理占用约 538 MiB。

据此实现 Wasm 专用的有名 ANF 临时绑定：保留临时名字，生成 Wasm 局部变量时直接解析，避免每引入一个 let 都遍历并重建后续树；原有后端继续使用绑定序数。`let x = call in x` 的有名形式也恢复尾调用。此项已完成自举，输出与种子逐字节一致；四进程为 92.73 秒，相邻时段同源码原生为 74.64 秒。

## 叶节点共享与冻结源码对照（验收进行中）

`抽象替换自由变量` 原来连绑定变量和没有子表达式的节点也重新构造；它们不可能含有待替换自由变量，现在直接返回原节点。节点本身不发生修改，既有树共享方式不变。此外，ANF 内核直接递归传递策略参数，去掉每层临时构造的递归包装闭包。

当前源码通过原生三代、四代字节一致与类型检查。512 MiB 四进程 Wasm 自举为 87.90 秒；相邻原生同源码四进程为 74.55 秒。使用同一 Wasm、匹配配置重新 AOT 后，1 GiB 四进程为 82.94 秒。两种 Wasm 输出均与种子逐字节一致。2 GiB 配置及重复测量仍在进行，不能据单次样本宣称无性能损失。

## 最后两项实现与计时审计

在交流供电且未发现休眠事件的 17:01–17:05 窗口，文本片段版四进程两轮 Wasm 为 53.65、55.08 秒，原生为 47.34、45.01 秒。均值差约 17.7%，仍未达标；Wasm 最后生成阶段约 8 秒，原生最终链接约 1 秒。

其后将原有 let 也改为延后闭合。先生成专用的新名字，再通过原有解构逻辑检查自由变量冲突，避免阴影绑定捕获后续式。另在每次直生模块时预生成 256 项字节转义表，后续每个字节直接读取对应的三字符转义，保持任意字节的原语义。

最新种子 `yy转义表种子.wasm` 与 Wasm 自举得到的 `yy最终并行二代.wasm` 逐字节一致；原生三代、四代一致并通过类型检查。该轮 71.07 / 87.99 秒计时因合盖后的 DarkWake/休眠被剔除。电源日志还证实早前原生串行的 923.07 秒包含 737 秒低电量休眠，不能当成原生编译器性能。历史探索值不作为最终提速或无损结论。待保持开盖接电后复测，最新状态见《优化结果.汉语.md》。

## 开盖接电最终复测

2026-09-08 18:02:52 起，在相同最终源码、开盖交流电状态下，按 Wasm、原生、原生、Wasm 顺序运行四进程完整自举，每轮更新编译缓存身份。Wasm 为 49.05、51.65 秒，原生为 47.16、47.08 秒；均值 50.35 / 47.12 秒，差 6.9%。两轮 Wasm 输出都与种子逐字节一致。最后生成阶段从前一版本约 8 秒变为约 6 秒；日志仅秒精度，未分别消融原虑延后和转义表。

串行单轮为 Wasm 96.91 / 原生 111.74 秒。串行输出与并行种子不同，闭包缓存证实跨模块函数编号不同；将串行输出预编译后再次完整串行自举，98.09 秒成功，并与上一代逐字节一致。此验证轮输入产物不同，不混入性能均值。预编译本身为 51.14 秒，明确排除在上面的 AOT 已缓存计时口径之外。因此当前结论是该 bootstrap 口径接近原生，不能宣称包括 AOT 准备在内的全面迁移零损耗。
