# WasmGC 编译器自举优化结果

通用优化对原生编译器的收益另见 [原生主线对照](原生主线对照.汉语.md)：相对当前 yybs `bd069a15`，同源码四进程自举耗时减少 32.3%，串行单轮减少 61.3%。

**在输入编译器已缓存 AOT 的 bootstrap 口径下，最新 WasmGC 已接近原生：四进程两轮均值 50.35 秒，原生 47.12 秒，Wasm 慢 6.9%。** 两轮 Wasm 自举产物都与原生生成的种子逐字节一致；原生三代、四代也一致，类型检查通过。

最后两项优化之前的无休眠对照：四进程 Wasm 为 53.65、55.08 秒，原生为 47.34、45.01 秒；均值为 54.37、46.18 秒，Wasm 慢约 17.7%。随后实现原有 let 的延后闭合和 256 项字节转义表。最新两轮日志显示，Wasm 并行前段约 43、46 秒，最终生成约 6 秒；原生前段约 46、47 秒，最终链接约 1 秒。时间戳只有秒精度，这不是精确的分阶段计时；也没有将最后两项改动分别做消融实验。

串行对照为 Wasm 96.91 秒、原生 111.74 秒，该单轮 Wasm 快约 13.3%。这些结果仅评价当前编译器自举。新生成编译器的 AOT 准备另测为 51.14 秒，未计入上述数字；因此不能宣称未缓存 AOT 的全流程或“全面迁移零性能损失”。详细实现过程见 [优化过程](优化过程.汉语.md)。

## 具体慢在哪里，改了什么

1. **列表反转重复遍历、分配。** 旧实现先反转尾部，再追加单个元素，复杂度 O(n²)。初始采样的 8338 个活动线程样本中，附加函数至少占 3337 个，调用栈主要指向反转。改为首插累积的尾递归，变为 O(n)，同时加速原生与 Wasm。
2. **大量短命对象与过长的缓存生命周期触发复制式 GC。** 一次后续窗口中，6498 个活动样本至少有 3778 个直接落在 GC 搬迁与扫描。现在及时移除已消费的抽象树、擦除树、优化树的内存缓存根；磁盘缓存与后续必需的数据保留。自由变量替换对绑定变量和无子节点的叶子直接复用原节点。堆容量对照单独记录，不把增加内存当成全部算法收益。
3. **ANF 为每个临时 let 重写后续树。** 最终生成阶段的另一次 3339 样本窗口，`抽象替换自由变量` 的栈顶合计至少 700 个。Wasm 路线改为保留临时变量和原有 let 的名字，生成局部变量时直接解析；原有 let 先生成新的唯一名字，并使用既有解构函数检查自由变量冲突，避免捕获后续表达式。不再逐层闭合并重写后续整树。原有后端继续使用绑定序数，`let x = call in x` 仍恢复尾调用。
4. **WAT 文本和名字查找重复处理长前缀、长尾。** 连续 let 和顺序执行现在积累片段、最后一次拼接；局部名字使用 64 桶，函数与全局名字使用 4096 桶，碰撞仍比较完整名字。编号按原遍历顺序分配。最终转义预生成 256 项三字符表，逐字节查表，避免每字节反复计算十六进制和构造小字符串；任意字节仍精确转义，不假设有效 UTF-8。
5. **原语封装、整数包装和宿主字节桥接有额外开销。** 小型非递归原语封装只在调用位置内联；已知小整数和布尔结果直接使用 i31，通用整数解码就地展开，仍保留完整 i64 路径。宿主字节数组由逐字节 C API 操作改为整段复制，保留类型检查和 GC 根。
6. **并行阶段重复启动与装载。** Wasm 每个模块合并前端阶段，任务数从 1191 减到 341；依赖模块完成后再编译使用者。AOT 改用引擎的文件映射入口，避免每个工作进程先读入整份约 22 MiB 文件。文件映射的独立速度收益尚未在稳定负载下确认。

这些结论来自实际自举和采样。静态检查调用的数量不等于执行次数，也不能直接换算成耗时占比。采样百分比只描述对应窗口，不能当作整个自举的精确时间分解。

## 验证与复现

最后源码的原生三代、四代逐字节一致，类型检查通过。旧 `yy_bs_stable` 不识别当前包布局，首级使用豫构和已有工作编译器构建 `yy2_bs`，之后执行仓库要求的二至三代、三至四代命令及一致性检查。独立生成器也已更新。校验和见 `优化记录/最终校验和.txt`。

原生生成的 `yy转义表种子.wasm` 与 Wasm 自举生成的 `yy最终并行二代.wasm` 一致。宿主不替代客体执行编译算法，只提供运行时系统接口、字节桥接与 WAT 组装。

最新开盖复测的 `yy开盖并行一.wasm`、`yy开盖并行二.wasm` 都与该种子一致。串行生成的 `yy开盖串行一.wasm` 经 AOT 后再次完整串行自举，得到逐字节一致的 `yy开盖串行二.wasm`，因此串行也达到固定点；这次下一代验证用时 98.09 秒，不混入输入产物不同的性能均值。串行与并行不要求彼此字节相同：实际闭包缓存可见同一提升函数的序号分别为 5376 和 792，运行方式会改变跨模块编号。

```sh
# 先按工具/网页汇编宿主/复制回收构建.汉语.md 构建宿主。
export YY_WASM_GC_HEAP_MB=1024
export YY_WASM_GC_INLINE=1
./yy网页汇编复制宿主 --预编译 yy转义表种子.wasm yy转义表千兆种子.cwasm
# 每轮改变编译缓存身份；不改变输入机器码。
touch yy转义表千兆种子.cwasm
caffeinate -i /usr/bin/time -p ./yy网页汇编复制宿主 --运行预编译 yy转义表千兆种子.cwasm \
  豫言编译器/入口。豫 --package-context .yybuild/豫构上下文/24.上下文 \
  --target=wasmgc --parallel -j 4 -o yy复测.wasm

# 同源码原生对照，每轮也重置编译缓存身份。
touch yy最终优化原生
caffeinate -i /usr/bin/time -p ./yy最终优化原生 \
  豫言编译器/入口。豫 --package-context .yybuild/豫构上下文/24.上下文 \
  --native-link-inputs "$PWD/yy自举原生链接清单" \
  --target=llvm --parallel -j 4 -o yy原生复测
```

串行去掉 `--parallel -j 4`，本轮使用 2048 MiB 并重新生成匹配该配置的 AOT。原生对照使用同源码的 `yy3_bs` 副本、`--target=llvm` 和 `yy自举原生链接清单`，轮次之间同样更新缓存身份。上下文编号 24 是本机示例。AOT 配置不匹配会被引擎拒绝，不应绕过检查。

环境：Apple M5 Pro、48 GiB 内存、arm64、macOS 26.5.1，Wasmtime 48.0.1 / Cranelift / copying。未锁定频率、核心或相同硬内存上限；本任务的正式计时不与本任务的其他编译或采样并发。以上只评价 bootstrap，不能外推到其他程序或完整迁移的所有功能。

完整自举计时包含启动、AOT 装载、实例化、前端、客体内代码生成及宿主 WAT 组装；**不包含输入编译器的 AOT 准备、引擎构建或下载**。原生生成本机编译器，Wasm 生成 Wasm 编译器，不能把此口径当作未缓存 AOT 的冷启动或更新编译器后全流程成本。宿主默认仍为 128 MiB、默认关闭引擎内联；上面的性能配置必须显式设置。

最新对照使用 `yy转义表千兆种子.cwasm`、`yy转义表两吉种子.cwasm` 与同源码的 `yy最终优化原生`；原始日志为 `优化记录/开盖*时间.txt`。每轮通过 executable/AOT 的 mtime 改变编译缓存身份，重新编译全部模块；没有清空操作系统文件页缓存。两轮样本不足以给出统计置信区间，6.9% 是本机这两轮的均值差，不是跨机器、跨负载保证。
