# 网页自举考绩

今以本机冷编译缓存自举三十秒以内为限，且不许以所得程序之迟缓易其速。所考者 Node/V8 之 WasmGC；非谓诸引擎、诸程序皆已比肩 C。

机为 Apple M5 Pro，十八核，内存四十八 GB；Node 26.3.0，V8 14.6.202.34-node.20。编译之诸阶段皆行于 Wasm，末以既有原生宿主组装 WAT。包上下文先备。计时自 Node 起，至产物成，含即时编译、实例化、类型检查及组装。所谓冷者，豫言编译产物不得复用；非清操作系统页缓存也。

始以串行，费一百一十八点五四秒。通异步进程，十八工并行，费四十八点五八秒。继省原语名解码，以 Wasm 自成整数之文，短列径映，不变叶节点复用，无须转义之串径还，约三十八点八二秒。尝合任务、改引擎编译线程、提早优化、增堆，皆未取。癸象线性输出无显益，亦撤。

诸工旧各起引擎，反复编同一模块。今同次构建共用模块机器码，工各立新线程、新实例、新堆；任务图与编译算法仍出于豫言。终版三代费二十一点一四、二十一点四五、二十一点八二秒，种子与三代字节皆同。唯同编译器自派之工入此途，普通子进程如故。线程共宿主进程号，隔离之界异于进程；设 `YY_NODE_COMPILER_WORKERS=process` 可复旧制。每轮新起 Node，不借前轮即时编译之功。

复验串行，费八十三点三三秒，较初省约百分之二十九点七。故此编译器之功，非独并行而速；然不可据此谓诸程序皆然。原生亦依次自举至四代，三、四代字节同，类型检查皆过。

以同一终版复独立进程，十八工并行，费三十九点九七秒；所得字节与线程模式同。线程模式中位数较之省百分之四十六点三。

原生 ThinLTO 以摘要通诸模块，而并行优化、成机器码。虽链接速，实测前端反迟，故留为选项，默认仍完整 LTO。此非本次 Wasm 提速之要。

新增验例，察整数极值、短列顺序与异常、绑定替换、字符串转义、深层癸象及异步等待；又验长列与子进程。错误任务可返非零码而终；部分语法错误仍见旧有 `illegal cast`，诊断之善未可称成。

命令、分项数值及最终复验，具于同目录《结果.汉语.md》。浏览器、别种引擎、通用应用及商用稳定性，尚须各考。
