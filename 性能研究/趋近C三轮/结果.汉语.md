# 第三轮：还有多少优化空间

2026-09-19。结论：尚未证明接近极限；排序实验找到约 19% 的进一步空间，但不足以追平 C。这一轮是对真实编译产物的消融研究，没有把实验假设写入编译器，也没有修改公开 ABI。此前工作区的编译器改动保持不变。

## 同场对照

相同算法、倒序输入、相同 Node/V8，与前轮相同的 C/WASI 产物。每种实现五个独立进程，每进程六轮，第一轮单列，其余 25 个样本取中位数。相邻进程组反转执行顺序，计时期间没有本任务的并行构建。所有原始输出、首轮、范围和各进程中位数均保留。

| 项目 | 一百万项，毫秒 | 四百万项，毫秒 |
|---|---:|---:|
| 当前编译器产物 | 22.596 | 97.807 |
| 裸整数数组、裸整数局部值、分区内联原型 | 18.320 | 78.967 |
| C/WASI | 7.918 | 33.709 |
| 原型耗时减少 | 18.9% | 19.3% |
| 原型 / C/WASI | 2.31 | 2.34 |

正式数据为 `终比原始数据.json`、`终比汇总.json` 和 `终比-*.txt`。这里只研究排序；不能把收益推广到整门语言，也不能把手工特化原型称为正式编译器的新性能。

## 分别测试了什么

首先在现有产物中定位分区私有入口 `$m756`、排序入口 `$m762`。分区热循环已没有间接调用。

第一组消融在四百万项上得到：基线 96.723 毫秒，直接调用私有入口 94.190，省略两个热函数中的 i64 索引截断前检查 94.088，只保留小整数解码 95.605，三者合并 85.865。单项收益较小，样本范围重叠，不能将中位数差当成稳定收益保证。合并实验有更明显差异，但不保证一般程序正确：负数、大索引、大整数或未执行分支的类型检查都可能改变行为。

`汇总.json` 保存这一组结果。没有关闭引擎自己的数组边界检查。这组实验只是定位开销，不能作为删除安全检查的依据。

第二组研究数据表示，四百万项结果如下：

| 变体 | 毫秒 | 说明 |
|---|---:|---|
| 基线 | 98.867 | 上一轮已验证的编译器产物 |
| 直入 | 95.990 | 排序直接调用分区私有入口 |
| 裸组 | 146.922 | 私有 i64 数组，读取后仍装箱、写入前仍拆箱 |
| 裸值 | 83.901 | 私有 i64 数组，读取结果继续放在 i64 局部变量中 |
| 内联 | 100.571 | 引用数组不变，展开分区循环；未观察到稳定收益 |
| 裸联 | 78.948 | 裸值基础上展开分区循环 |

这一组保留原有 i64 索引范围检查及引擎数组边界检查。`布局汇总.json` 和 `布局原始数据.json` 保存全部结果。裸组的明显回退也完整保留。

仅仅换数组类型并不够，必须同时让整数值沿计算路径保持裸表示。裸组和裸值对照支持这一判断。数组布局、引用写入、装拆箱、引擎优化之间仍有相互影响；本实验没有分别量出 GC 写屏障或内存带宽的贡献。i64 数组也不必然比当前引用数组更省内存，因此不用“紧凑数组”作为结论。

## 原型范围与正确性

所有变体都是对 `yy本轮快速排序.wasm.wat` 的实验性补丁。裸数组变体只给填充、分区和排序创建私有克隆，并让该基准的局部数组流经这些克隆；普通函数表和公开入口保持原样。这不是已经实现的逃逸分析或通用特化算法。

直接私有调用原型提前解码枢轴，未证明一般调用中的异常时机不变；小整数实验不能用于大整数；省略截断前检查的实验不能用于任意 i64 索引。裸数组构造辅助函数也只针对本次合法长度。任何一项进入编译器前，都需要静态证明或守卫及后备路径。不能从本基准通过推断它们可直接发布。

额外验证在计时外执行：九种变体均以长度 1、2、128、一百万运行六轮，并检查排序后每一个元素，合计 216 次逐项检查。基线、裸值和裸联又在长度 1、2、128 上分别测试超过 i31 范围的大整数和负整数，合计 108 次逐项检查。检查补丁、结果分别见 `逐项*.补丁`、`值域*.补丁`、`逐项检查.json`、`值域逐项检查.json`。

这些检查覆盖固定生成的倒序数据，不覆盖随机数据、重复值、别名逃逸或异常时序。计时产物不含逐项检查代码。所有计时调用也核对了原有校验值。`产物摘要.json` 记录 Wasm 摘要；`模块边界.json` 保存导入导出清单。

## 自举约束

当前正式编译器保持不变。本轮额外运行一次完整冷编译缓存自举，871 个任务、18 路并行、新 Node 进程、`--do-not-load-cache`：墙钟 **19.06 秒**。生成结果与种子逐字节一致，SHA-256 均为 `628cd6ca8a304aede3f0550248b3d6ea3a089cdffde8648c0bfa4b4cb5f46ddb`。

这满足 30 秒约束，但不能归功于排序原型。前轮三次正式自举中位数仍是 18.69 秒，本轮 19.06 是单次复测，不代表统计上的速度变化。“冷”不包含清空操作系统文件页缓存。日志见 `自举输出.txt`、`自举计时.txt`。

## 依据实验调整后的实施次序

1. **局部整数数组特化与整数值传播一起做。** 仅接受可证明不逃逸、所有读写和别名已知的数组，把相关调用克隆为私有版本；无法证明时保留现有引用数组。保持公开数组 ABI。实验显示这是比单独删包装更值得投入的方向。
2. **建立跨函数私有签名和返回值分析。** 已证明的整数参数直接传 i64，已证明的整数返回值继续裸传；未知参数必须保留原有守卫和异常时机。仅绕过参数包装的单项收益不大，因此不应优先大规模铺开而忽略返回值。
3. **在表示特化之后做有限的循环内联与范围分析。** 单独展开分区没有稳定收益，不能无条件扩大内联。范围检查只有在证明成立时才能消除。

每一步进入源码后都应重新测量多种程序和自举，并执行规定的完整自举、类型检查及语义回归。任何公开表示、整数语义或安全保证的变化都需要另行决策。当前实验没有提出放宽这些约束。
