# 网页汇编性能实验复现

本实验使用真实豫言程序对比当前原生后端、WASI P1 核心模块、P1 适配成的 P2 命令组件。结果不等于跨语言调用基准。对应文言本见《复现说明.文言.md》。

## 环境与方法

- Apple M5 Pro，18 个逻辑处理器，arm64，Darwin 25.5.0；没有固定 CPU 核心或频率。
- 编译器使用工作区已有 `yy编译器`，源码基线 `1a1bb90f`；可执行文件身份与产物摘要见《构建记录.json》。没有为本实验重新自举编译器，因此记录的是该可执行文件与当前库源码的组合。
- 原生 LLVM/Clang 22.1.7，`--optimize --whole-program-opt`，底层 `-O3` 与 LTO；WASI SDK 34 / Clang 23.1.0，同样的豫言选项，但当前 Wasm 实现实际逐模块 `-O2`，没有全程序 LTO。运行时也是原生 `-O3`、Wasm `-O2`。
- Wasmtime 48.0.1，默认 Cranelift 和优化等级 2。所有运行加 `-C cache=n`。预编译用 `wasmtime compile`，运行用 `--allow-precompiled`，只加载本次自行生成的产物。
- 原生和 Wasm 每个测试使用相同的实际豫言栈 16 MiB、最大单堆 64 MiB。原生栈环境变量仍以百万个十六字节槽计，故填 `1`；Wasm 已按 MiB 计，故填 `16`。初始堆均为 4 MiB，只有百万元素素数筛双方设为 32 MiB。
- 计时器使用豫言 `获取当前纳秒时间`，底层 `CLOCK_MONOTONIC`，在启动子进程前后取时；包括进程启动、加载、初始化、运算、GC 和输出收集，不包括生成 Wasm 或 AOT 文件。原生额外经过 `/usr/bin/env` 设置环境。
- 每个工作负载先执行一次原生取得参照；各方式再预热一轮（CSV 轮次 0），然后交替测五轮（1–5），取中位数。每轮固定方式顺序，没有随机化；不同工作负载顺序运行。测试期间不同时运行编译任务。
- 每次校验进程成功与标准输出逐字节等于原生参照。矩阵与排序沿用原基准的摘要输出，未穷举校验整个结果数组。算法已知结果见报告。
- “即时编译”每次新进程禁用编译缓存，但操作系统文件页可能已热；“预编译”仍含 Wasmtime 新进程启动，并不等于常驻实例中的纯内核计时。零输入斐波那契用于观察初始化和启动基线，没有从各项样本中机械减掉它。

## 编译

最新豫构在 Wasm 编译时会传入尚不支持的原生清单。本次先让豫构生成包上下文，再用编译器直接构建。这是实验绕行，不是该问题的修复。

```sh
./yy豫构 构建 性能研究 跨语言比较 斐波那契 \
  --编译器 ./yy编译器 --输出 yy_互操作_斐波那契_原生 -j 2 \
  -- --target=llvm --optimize --whole-program-opt --do-not-load-cache

# 以下上下文编号是本次本机产物；新检出须使用豫构新生成的上下文路径。
./yy编译器 性能研究/跨语言比较/斐波那契。豫 \
  --package-context .yybuild/豫构上下文/16.上下文 \
  --target=wasm --optimize --whole-program-opt \
  -o yy_互操作_斐波那契_核心.wasm
```

素数筛、矩阵乘法、快速排序使用 `性能研究/跨语言比较` 下同名源码。递归回收使用本目录源码，它将既有回收用例的长度改为命令行输入。原生和 Wasm 均从同一份源码构建。

组件化没有重新生成算法：从 Wasm 编译日志取得最后的 Clang 链接命令，对同一命令追加 `-###`，提取底层 `wasm-ld` 参数。将链接器换为 SDK 的 `wasm-component-ld`，输出名改为 `_组件.wasm`，并追加：

```text
--wasi-adapter command
--validate-component=true
--wasm-ld-path /本机SDK绝对路径/bin/wasm-ld
```

保留相同对象文件、P1 libc、运行时、内存限制和 `--fatal-warnings`。实际完整参数保存在《构建记录.json》，其中缓存路径和绝对目录用于记录本次实验，跨检出不能直接照搬。SDK 此版本的 Clang `--ld-path` 对该目标没有起效，故实验直接调用组件链接器。

```sh
./yy_wasmtime compile -C cache=n yy_互操作_斐波那契_核心.wasm -o yy_互操作_斐波那契_核心.cwasm
./yy_wasmtime compile -C cache=n yy_互操作_斐波那契_组件.wasm -o yy_互操作_斐波那契_组件.cwasm
```

对其余四项同样分别预编译核心与组件。AOT 文件针对本机，不是通用可移植发布格式。[Wasmtime 预编译说明](https://docs.wasmtime.dev/examples-pre-compiling-wasm.html)。

## 测量

```sh
./yy编译器 性能研究/网页汇编比较/计时。豫 \
  --package-context .yybuild/豫构上下文/16.上下文 \
  --optimize -o yy_互操作计时
./yy_互操作计时 斐波那契 35 > 性能研究/网页汇编比较/斐波那契样本.csv
./yy_互操作计时 素数筛 1000000 > 性能研究/网页汇编比较/素数筛样本.csv
./yy_互操作计时 矩阵乘法 240 > 性能研究/网页汇编比较/矩阵乘法样本.csv
./yy_互操作计时 快速排序 100000 > 性能研究/网页汇编比较/快速排序样本.csv
./yy_互操作计时 递归回收 100000 > 性能研究/网页汇编比较/递归回收样本.csv
./yy_互操作计时 斐波那契 0 > 性能研究/网页汇编比较/启动样本.csv
```

CSV 无表头，五列依次是题名、输入、轮次、方式、墙钟秒数。启动样本的题名仍是斐波那契，但输入为 0。轮次 0 仅保留为预热记录。

## 已遇到的限制

旧 `./yy` 直接编译当前包布局时找不到标准库；本次改用已有 `yy编译器` 加包上下文。豫构的 Wasm 构建因原生链接清单失败，改用上述直接编译路径。百万元素素数筛在原生 4 MiB 初始堆下退出失败，不能把它记为 Wasm 特有错误；该项采用双方 32 MiB 初始堆后再测。失败样本不计入正式结果，相关限制不在本次修复范围内。

递归回收最初输入 200000，原生参照在 16 MiB 栈配置下明确报栈溢出，故正式测量改为 100000；未把增大输入后的原生默认栈结果与小栈 Wasm 比较。回收日志的额外验证与类型检查均在正式计时结束后进行。
