# Wasm 自举缓速之因

全自举之验亦成：内联栈检兼运行时 LTO，三百六十九点一一秒减至二百四十四点五五秒，减三成三点七，尚为原生参照三点九零倍。产物唯 name 节异，代码、数据及余节同。原录见《归因记录/完整自举结果.json》。

唯实验之器受此优化，所生后继仍循源码旧规则，不自承之。全举一验，共用已备输入而禁读编译缓存，未清系统文件缓存。

二〇二六年九月八日，以同器之别本试之，未改正用编译器与运行时。今尚不可许全面迁移而无损其速。

首因已明：栈检借通用外调之道。静态调用三万九千一百五十二处，先存栈堆指针，后又读堆指针，复经 i128 拆传与返回缓冲。检中值转换亦别作调用。检不分配、不移堆，其成功之路不必尽负此费。

又原生运行时用 O3 与 LTO，Wasm 用 O2 而无 LTO。独加运行时 LTO、仍守 O2，已有所得；未作全编译器之跨文件优化。

每例先暖一回，再测三回，取中数。字符串术类型检查，原生零点三四八秒，今 Wasm 二点八四二秒；内联检一点五零一秒，独加 LTO 二点零零三秒，两法并用一点四一六秒。总集代码生成，原生一点三九八秒，今 Wasm 八点零零九秒，两法并用四点六九九秒。所减约半与四成，然仍逾原生四点零六倍与三点三六倍。删检查之别本唯供归因，非可用之策。

增堆六十四至二百五十六 MiB，回收七十三次减至十八次，耗时未减；不可由此谓回收复制与清零无费。启动原生约一点八八一毫秒，Wasm 约三十九点九五八毫秒，非独足以解数秒之差。自举已用 AOT；类型检查不行终端 LLVM 生成而仍缓；今用 core module，非组件 WIT 之费。Wasmtime 常借虚拟内存守界，不可谓每访内存皆有软件检查。出处详汉语本。

余差未全采样，不虚列占比。宜察十六字节值与 i128 约定、频繁间接尾调用、反序列化、分配、回收与 WASI 读写。原生亦用十六字节值，不尽归装箱之费于 Wasm。

当先专化栈检，验其越界必拒；次齐运行时优化；再采余热点而定值表示与调用之变，后考常驻 worker。全面迁移之前，须同源、同机、同并发、同安全要求，明缓存之策，反复全自举而无可测退化，并察内存。不得以局部提速冒充全局达标，亦不得删必要之检以求速。

后试 ANF 直生 Wasm GC，详《../网页汇编直生/结果.文言.md》。彼原型未能自举，不代此完整自举之数。
