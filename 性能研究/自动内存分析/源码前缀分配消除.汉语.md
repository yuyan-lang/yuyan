# 源码前缀分配消除

2026-09-20。保留本轮编译器前端优化：名称定位使用纯字符串前缀比较，发现不等即停止；声明后缀直接匹配源码已有的字符列表。通用列表函数的求值语义保持原样，语言服务输出继续生成。

## 最终指标：完整冷自举墙钟时间

相同当前源码、相同宿主、18 个工作进程、默认 GC 编译路径、`--do-not-load-cache`。先按旧—新—新—旧，再按新—旧—旧—新的顺序运行；计时期间没有并发构建。旧编译器为 `yy栈向量三代.wasm`，新编译器为 `yy源码前缀种子.wasm`。

| 测量组 | 旧版墙钟秒数 | 新版墙钟秒数 |
|---|---|---|
| 第一组 ABBA | 23.00、23.48 | 21.86、23.32 |
| 第二组 BAAB | 22.84、23.66 | 21.71、23.05 |
| 四次平均 | 23.245 | 22.485 |
| 四次中位数 | 23.240 | 22.455 |

平均减少 **0.760 秒，约 3.27%**。新版四次均低于 30 秒；八次输出均与新版种子逐字节一致。不同次运行仍有波动，结论限定于这两组同机对照。数据见 [首组](源码前缀冷自举比较.json)、[反转顺序复测](源码前缀冷自举复测.json)、[验收摘要](源码前缀验收摘要.json)。

这里测量的是优化编译器本身后的自举速度。自动非 GC 栈分析尚未命中编译器自身的数组候选，本次收益不归因于启用栈分配。

## 改动依据与语义

[上一阶段剖析](向量后续筛选与自举分配定位.汉语.md) 将名称定位识别为真实自举热点。原来的 `声明后缀` 每次构造十个后缀的字符列表，并通过通用高阶函数检查它们；`源码状态以串开头` 使用严格求值的通用 `以起否`，即使首字符不同仍会处理剩余前缀。

现在新增 `源码字符前缀匹配`，其比较固定为纯字符串相等，对有限字符列表短路不会改变可观察结果。`声明后缀` 直接识别原有十个固定字符前缀，允许任意剩余字符，保留原来的前缀语义。这是编译器源码定位算法的通用优化，没有修改任何性能基准，也没有跳过类型检查、语言服务或源码范围输出。

对同一个 `统一网页汇编。豫` 类型检查与擦除任务进行单独 GC 诊断，工作线程已报告区间的累计分配由 **14.805 GiB 降至 10.886 GiB**，约减少 **26.5%**。这不是常驻内存，也不能外推为整个自举的分配降幅；诊断计时不作为墙钟验收。见 [分配对照](源码前缀类型阶段分配对照.json)。

- `测试/编译器/源码前缀。测试。豫` 保留旧实现作为参考，10,516 个输入、126,192 次比较全部通过。覆盖十种后缀、截断、单字变异、追加字符、空前缀、换行及 Unicode 字符，见 [差分记录](源码前缀差分验证.json)。
- [六个运行内核](源码前缀六核一致.json) 的 Wasm 产物与优化前逐字节一致；默认 GC 排序也一致。生成程序没有因本轮改动变慢，公开 ABI 及整数、数组运算代码保持原样。
- 六个内核的 [语言服务信息与语义标记](源码前缀语言服务一致.json) 共十二份文件逐字节一致。
- 按仓库规定执行 stable → 二代 → 三代 → 四代原生自举，最终第三代与第四代逐字节相同。两项类型检查通过。
- 首次原生比较曾因诊断字符串的临时名称出现差异；刷新第三代缓存身份并单独重跑末级后，生成 C 源码和原生可执行文件均逐字节一致。验收采用复验结果，后续应避免自举与类型检查并发写入同一缓存。初次差异记录见 [诊断记录](源码前缀原生首次差异.json)。
- 新版原生编译器生成的 Wasm 种子与八次冷自举输出一致，SHA256 为 `300463023705e570c237e6d1fb3713999ca93e37eeba4d53f6483b3864251834`。原生三、四代 SHA256 均为 `1a228f9e6f7573152b90ccb69e0c0e68f22223ee6346b5ef36e16e95ec46b558`。

源码位于 `库/编译器核心/编译数据/语言服务信息。豫`。本轮减少了一个实际自举热点的临时分配；更广泛的自动容器生命周期分析与运行内核稳定达到或超过 C 的目标仍未完成。
