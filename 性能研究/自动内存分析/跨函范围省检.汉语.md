# 跨函数范围省检实验

结论：本轮不接入编译器。省去检查没有稳定收益，不能据此宣称达到 C 水平。正式编译器源码与默认行为未改，因此本轮不重复完整自举。

## 方法与边界

以 `yy就绪索引核快速排序.wasm` 为原版，在 WAT 中分别让排序直接调用分区快速体、删除排序中的三组索引宽度及长度检查，再分别显式内联分区快速体。每个二进制经过 WebAssembly.Module 验证。每规模、每变体七个新 Node 进程，每进程六轮；循环轮换变体顺序，统计后五轮合并中位数，同时保留各进程中位数。所有基准输出校验和符合预期。

这些是仅用于估计收益的受限原型，不具备通用编译器自动证明；绕过守卫会改变任意私有入口非法参数的行为。正常基准校验和通过不等于完整正确性。不得发布这些原型，也不得用它们替代正式基准。

## 实测（毫秒，越小越好）

| 第一组 | 100 万元素 | 400 万元素 |
|---|---:|---:|
| 当前豫言 | 8.157 | 34.151 |
| 直接调用分区快速体 | 8.307 | 35.855 |
| 直接调用并删除三组检查 | 9.403 | 39.549 |
| 当前 C 对照 | 7.847 | 33.318 |

| 第二组 | 100 万元素 | 400 万元素 |
|---|---:|---:|
| 当前豫言 | 8.006 | 33.778 |
| 显式内联分区快速体，保留三组检查 | 7.807 | 33.783 |
| 显式内联分区快速体，删除三组检查 | 8.341 | 35.158 |

第二组小规模约 2.5% 收益尚未独立复现，大规模无收益；第二组没有重测 C，不能跨组比较来声称胜过 C。

## 引擎证据与下一步

Node 的 `--trace-wasm-inlining` 日志显示，原版排序函数 831 内联守卫函数 834 及其快速体 833。省检原型则内联四层函数 831 自递归，随后因预算不足拒绝内联函数 833。函数编号与当前 WAT 声明顺序核对一致。

这证明代码缩小改变了引擎的内联选择；其是否解释全部耗时变化尚未证明。显式内联只能消除部分退化，不能把检查条数当作速度指标。后续不以该原型为由优先实现复杂跨函数关系证明，转向扩大非 GC 分配的实际覆盖范围，并继续保留公共 ABI 与 GC 后备。

原始数据见 `跨函范围省检原型实测.json`、`跨函范围内联原型实测.json`；二进制哈希与引擎版本见 `跨函范围原型审计.json`。同目录保留四份原型补丁和三份内联日志，可从原版 WAT 复现。带日志运行仅作诊断，不计入性能样本。
