# 合并检查与离线优化实验

本轮没有修改编译器源码或默认流程。先测试合并已有长度局部后的范围判断，保留失败分支对原有异常的区分。首批热轮为 35.910 → 36.088 ms，九进程复测为 34.455 → 34.361 ms，改善约 0.3%，不足以采用。记录见 `栈合并检查原型实测.json` 与 `栈合并检查独立复测.json`。

## Binaryen 来源与配置

从 [Binaryen 官方 132 版发布页](https://github.com/WebAssembly/binaryen/releases/tag/version_132) 获取 arm64 macOS 归档，下载摘要与官方发布元数据一致：`98aad827847af7ef990ed7098d885725c8e5b5aae75073403635617ae4e259aa`。临时工具位于 `/tmp/yy二进制优化器132/bin/wasm-opt`，未加入仓库工具链。来源记录见 `二进制优化器来源.json`。

显式启用输入需要的 GC、引用类型、尾调用、批量内存、多值、符号扩展、非陷阱浮点转整数、SIMD 和异常处理特性。未启用 `ignore-implicit-traps`、`traps-never-happen`、`low-memory-unused` 或 `closed-world` 等额外假设。

O4 在本模块触发 `Flatten.cpp:231` 的 `unexpected expr type` 断言，退出 134，未继续采用；没有确认具体触发节点。O2、O3 与受限内联配置产生的模块均能由当前 V8 验证。单独允许循环内联的 O3 产物与普通 O3 完全相同。

## 排序测量

五个新进程各六轮，轮换顺序，四百万元素，校验和全部为 6000002。首批对照同时包含原始 C 和经 O3 后处理的 C：

| 版本 | 首轮 ms | 热轮 ms |
|---|---:|---:|
| 当前豫言 | 44.719 | 33.936 |
| 豫言 + O2 | 41.686 | 33.727 |
| 豫言 + O3 | 44.669 | 35.531 |
| 原始 C | 42.457583 | 32.811125 |
| C + O3 | 41.680084 | 33.555166 |

O3 对两者热轮均无益。另一批中，当前豫言热轮 34.205 ms，O2 为 34.460 ms，限制内联规模的 O2 为 34.525 ms，原始 C 为 33.204583 ms。O2 的首轮有所改善，但排序热轮收益不稳定，未达到 C。详见 `二进制优化器排序实测.json`、`二进制优化器定限内联实测.json` 和 `二进制优化器候选.json`。

## 编译器自身与完整自举

O2 将编译器模块从 3,848,573 字节缩小至 2,235,322 字节，处理耗时约 0.48 秒。优化后的编译器首次冷缓存自举为 21.98 秒，原始输出与当前未优化编译器逐字节相同。

随后两次计时包含完整冷缓存编译及 O2 后处理，采用外层 `time` 测量整个串行流程：分别为 **22.82、22.31 秒**。优化种子与优化后二、三代完全相同，SHA-256 为 `5db62d15227a348e3e80b7c7b7ddb9a9712e1a28eff00b71b52ef739191cd301`；两次后处理前的原始输出也均与当前编译器一致。见 `二进制优化器完整自举.json` 及配套计时记录。

这是可复现的离线发布实验，不是已接入默认编译流程的提速。现有标准自举流程及源码保持不变。

## 验证边界与结论

导入导出的名称与种类一致，完整自举能够通过现有宿主运行。针对先读、跨函数写入、再读的专用夹具，O2 后处理与原始模块的 1,134 组返回值、异常消息及异常后内容一致，见 `二进制优化器异常差分.json`。这不等于全部 ABI、语言特性或其他五个运行基准已经完成验证。

本轮不引入 Binaryen 依赖，不采用合并检查。保留离线优化实验与编译器产物作为后续研究证据；继续在现有编译器内研究递归范围证明和受控循环内联，以缩小排序热轮的剩余差距。目标尚未完成。
