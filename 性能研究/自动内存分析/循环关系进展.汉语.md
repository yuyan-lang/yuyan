# 从统一正则 IR 发现循环关系

新增 `网页汇编循环关系。豫`，把上一轮差分约束引擎用于实际的统一正则指令。模块仍未由默认代码生成导入，尚未改变正式编译器的运行性能。

`验循环关系` 接收函数、被建模的整数参数和入口约束，追踪参数及已证明结果位于 wasm32 范围的常量加减。整数相等和大于比较细化各自分支；相等的反面只有在原先已知大小方向时才能得到严格不等式。分支使用独立约束副本，函数内唯一 SSA 编号的表达式表依赖现有作用域验证器保证不会跨域使用。

每个自递归调用必须处于真正尾位置，参数数量匹配，并通过所有建模参数的同时代入验证。未知调用、非尾递归、复杂退出或无法维持入口条件均拒绝整个候选。数组读写仅记录当前已证明索引宽度合法的操作编号；未知索引仍保留检查。其他参数的整数资格、数组表示与副作用约定继续由现有私有入口分析负责。

`搜循环关系` 自动从函数首个参数比较提出候选，枚举两种方向及可选的第三参数：

```
0 ≤ 扫描 ≤ 上界 ≤ UINT32_MAX
0 ≤ 存放 ≤ 扫描 ≤ 上界 ≤ UINT32_MAX
```

这是一组有界的候选关系模板，不是按函数名识别排序，也不是完整的任意线性关系推断。每个候选都必须重新验证整个函数。最多八个候选整数参数、128 个局部编号，选择能证明更多数组操作的候选；收益相同时保留更早尝试的简单候选。入口参数必须先具备现有私有整数资格，实际调用还需要生成上述动态守卫。

## 验证结果

Wasm 测试通过十二项 IR 分析用例：正常递增、重命名及整体移动局部编号被接受；扫描或存放步长过大、仅存放递增、未知调用、非尾调用、递归换类、参数交换、缺少严格上界、全宽步长与负向越界被拒绝。

自动搜索另通过三项测试，覆盖改名、重编号和缺少整数资格。加入第二个数组写索引后，搜索自动选择第三参数的关系，准确返回读写操作编号。测试构造也通过现有统一正则 SSA 作用域验证器，避免用非法 IR 证明分析正确。

新测试类型检查、编译器入口类型检查通过。运行输出和产物摘要见 `循环关系测试输出.txt`、`循环关系产物摘要.json`。没有接入默认编译器，因此未重复完整自举，也没有新的正式性能数字。

## 下一步接线要求

只在已存在的整数数组、裸整数返回私有入口中先试用。保留原实现作为守卫失败后的后备；动态守卫用无符号比较建立整条非负关系链。获得证明的操作编号只在快体生效，不能写入普通入口或其他克隆的共享事实表。公开函数表、参数与返回 ABI 不变。

代码生成可选择独立快函数或同函数双分支，但需实测，不能假设其效果与上一轮手改 WAT 一致。接线之后必须检查真实基准确实触发、所有读取仍保留数组边界检查、非法路径及失败前写入一致，并完成规定自举、冷缓存 30 秒门槛和独占性能复测。

当前完成了自动候选发现和整函数验证；守卫与快体生成尚未接入。排序与 C 的差距仍未正式缩小，整体目标未完成。
