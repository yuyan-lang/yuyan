# 自动栈的重复边界检查消除

新增 `网页汇编栈重复访问。豫`，在每个正则区域中记录数组局部号与索引原子。相同数组、相同局部索引或相同整数常数已经访问过时，后续访问不再重复检查范围。第一次检查保留，数组读写指令及其顺序保持不变。

证明依赖上层已经验证的封闭栈调用图：数组头和长度不可变，无宿主重入、原始内存写入或子数组分配；输入已通过 SSA 与表示检查。静态调用可以改变载荷，但不能改变头，所以正常返回后原范围事实仍成立。此分析不能独立授权跨越不满足这些条件的调用。

每个子分支独立记录事实，不把分支内的访问传播给父区域或另一个分支。不同数组、不同索引、局部索引与整数常数不混同；不推测算术等价，也不推测数组别名。第一次访问若发生异常，执行不会到达省检处。

## 生成策略

正常私有体使用重复访问证书。范围守卫的检查后备体通过 `生成栈检查后备` 保留原检查形态；已有范围证书与载荷镜像路径保持原逻辑，重复访问证书不扩大镜像资格。

最初全路径去重也通过正确性验证，但额外缩小分区检查后备体后，首轮测量退步，热轮收益减弱。最终按生成路径保留后备体，不根据程序名称选择。最终真实编译器产物与先前两批测量中的去重原型逐字节相同，SHA-256 为 `02f92746762ccd6f4b8b48e493409e3ddaf3c5256937d03d5ea02834a92bb58a`。对应证据见 `栈保检去重产物对应.json`。

在当前排序产物中，仅 `$stack766_762` 的函数体改变，其范围检查从九处减少到三处。841 个具名函数签名及导入导出不变，分区检查后备体不变。详见 `栈保检去重接口审计.json`。

## 正确性与性能

`测试/编译器/栈重复访问。测试。豫` 的十三项测试覆盖首次检查、读写组合、数组与索引身份、整数常数和分支事实的保守范围。最终生成器通过 18,811 组、1,005,292 项检查；真实产物通过 6,919 组排序与 10,287 组分区，共 270,003 项检查，比较返回、异常及异常后的内容。原始记录为 `栈保检去重生成验证.json` 与 `栈保检去重排序差分验证.json`。

两批独立配对均为五个新进程、每进程六轮、轮换顺序。计时包含分配、填充、排序与校验和，校验和全部为 6000002。下表采用加入 C 对照的独立复测；最终产物与该测量产物二进制一致，因此复用其计时证据。

| 版本 | 首轮 ms | 热轮 ms |
|---|---:|---:|
| 载荷与无值控制基线 | 45.378 | 35.296 |
| 保留后备体的访问去重 | 44.921 | 34.332 |
| C/Wasm | 42.853667 | 33.064792 |

该批热轮减少约 2.7%，五个进程的热轮中位数均改善；第一批热轮为 35.850 → 34.151 ms。最终版本仍比 C 慢约 3.8%，目标尚未完成。记录见 `载荷去重组合原型实测.json` 与 `载荷去重组合独立复测.json`。`栈访问去重排序实测.json` 对应未采用的全路径版本，不能作为最终版本成绩。

新分区快体为 331 字节，排序去重后为 351 字节。`载荷去重内联轨迹.txt` 显示引擎先内联分区守卫及快体，再展开一层递归，并继续内联这一层的分区快体。它没有重现旧 355 字节分区快体时代先展开递归而耗尽预算的问题。此处记录具体引擎行为，不保证其他引擎采用相同内联策略。

完整本机自举与两项类型检查通过，`yy3_bs` 与 `yy4_bs` 逐字节一致。默认模式使用 `--do-not-load-cache --parallel -j 18` 的完整冷缓存 Wasm 自举为 23.95、24.34 秒，种子及二、三代产物一致，仍满足 30 秒标准。该自举未开启实验栈，不能解释为栈分配使编译器提速。详见 `栈保检去重本机验证.json` 与 `自动栈保检去重冷自举.json`。

本机与 Wasm 编译器生成的实验排序二进制一致。其余五个基准、关闭实验开关的排序产物与上一版逐字节相同，不重复测量未变化的程序。详见 `栈保检去重六核产物.json`。实验栈开关仍默认关闭。
