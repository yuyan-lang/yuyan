# 有界线程复用降低冷自举时间

本轮保留 Node/Wasm 自举宿主优化：默认复用内部编译工作线程，每线程最多四项任务，闲置 250 ms 后回收，空闲数量不超过可用处理器数。每项任务仍创建全新的 Wasm 实例、值桥实例、全局变量、入参和宿主状态，不缓存编译结果、文件或数组内容。任务图和并发数量继续由豫言调度器决定，JavaScript 只适配线程和完成事件。

## 最终墙钟对照

同一台机器、相同 Wasm 编译器和源码、18 个工作任务、`--do-not-load-cache`。每次使用独立 Node 进程，计入启动、JIT、实例化、完整编译及组装；未清空操作系统页缓存。按独立线程—默认复用—默认复用—独立线程顺序，无并发构建。

| 模式 | 两次完整冷自举秒数 | 平均秒数 |
|---|---|---:|
| 每任务独立线程 | 21.94、23.44 | 22.690 |
| 默认有界复用 | 16.26、16.55 | 16.405 |

平均用时减少 **6.285 秒，约 27.7%**。两次默认配置均低于 30 秒；第二次使用第一次输出的编译器继续自举。四次输出均与输入基线 `yy容器图三代.wasm` 逐字节一致，SHA256 为 `cf5b4bc9d90834d0c0139b239bf368ce62665b63398928212a87a83f0f77a45c`。见 [定稿冷自举数据](有界线程复用定稿冷自举.json)。随后补充的取消竞态处理只影响取消和错误路径，正常路径保持上述方案。

这里改进的是完整自举墙钟，不是六个算法内核的生成代码。C 等效容差问题仍等待用户决定，没有用这项收益替代整体 C 性能验收。

## 原因与资源代价

原宿主一次冷自举启动 1,096 个内部 Worker，启动延迟中位数约 10.7 ms，累计约 12.66 秒。累计值有并行重叠，不能当作可直接节省的墙钟。跟踪运行产物与基线相同；其约 21.96 秒总时长带有观测开销，不作为正式验收。见 [启动摘要](编译线程启动摘要.json) 与 [记录](编译线程启动剖析.json)。

不限制每线程任务数的原型约 15 秒，但 20 ms 采样的进程 RSS 峰值达到约 4.11 GiB，独立线程约 2.18 GiB。因此没有采用无限复用。先限制八项，再试四项及闲置回收，并修正回收时机：决定销毁的 Worker 必须真正退出后，才向调度器报告任务完成，以减少旧堆尚未释放时立即创建新线程的重叠。

最后方案的同类采样约 **15.67 秒、2.86 GiB RSS**。相对独立线程仍有约 **0.68 GiB** 的采样峰值代价。该数字包含本 Node 进程中的所有 Worker，不包含外部子进程；20 ms 采样可能漏掉瞬时峰值，也不构成堆容量硬上限。正式墙钟表采用不带 RSS 采样的运行。见 [独立及无限复用对照](线程复用峰值内存对照.json)、[八任务](线程八任务复用采样.json)、[闲置回收](线程闲时回收采样.json)、[四任务](线程四任务复用采样.json)、[最终回收方案](线程退毕回收采样.json)。

曾尝试系统 `time -l`，构建成功后该工具因沙箱禁止读取 `kern.clockrate` 而退出非零，因此不将该次当作内存验收；改用进程自身 RSS 采样。没有请求或绕过额外系统权限。

## 实例隔离及生命周期

模块缓存仍按设备号、inode、大小、mtime 和 ctime 校验；每项任务取得当前模块。复用同一 GC 堆的容量并不共享 Wasm 实例状态：每次调用都新建实例、值桥和原语名称弱缓存。异常使用本次任务的退出码，不写入跨任务的 `process.exitCode`。

任务输出和完成消息使用同一有序消息通道，输出被消费后才发出 `close`。任务取消立即把线程标成不可再用，即使完成消息已在路上也不能把该线程交给下一项任务。旧任务句柄只在仍是当前任务时才能终止线程。回收线程保存任务本来的退出码，不把主动终止空闲宿主线程产生的状态误报为编译失败。

线程模式原有的 256 MiB 单流输出上限和 4096 个未收取句柄上限保持不变。普通原生子进程、其他 Wasm 程序和非内部 worker 格式的命令不进入这个复用路径。主客体结束时清理活动与闲置线程。

## 验证与使用

`测试/节点宿主/线程复用。测试.cjs` 验证：普通任务不入池、默认复用及显式关闭、同线程中的全新实例、模块文件更新、同线程异常恢复、并发标准流完整性及不同参数、输出/完成竞态取消、旧句柄隔离、四任务后回收、闲置回收和池关闭。包含 Unicode、NUL 以及较大输出，实际比较全部字节；不是仅检查退出码。见 [宿主验证记录](线程复用宿主验证.json)。

六个已有内核各运行六轮，全部结果值正确；该项与原生构建并行，只用于正确性，不使用其运行时间判断性能。见 [内核回归](线程复用运行内核回归.json)。原生自举补充检查首次命中此前省清零候选的旧对象缓存，诊断后按仓库规则刷新 stable 可执行文件的缓存身份再完整重跑，详见 [缓存诊断](线程复用原生缓存诊断.json)。

默认采用有界复用。需要更低的线程堆保留或对照旧模式时，设置 `YY_NODE_COMPILER_REUSE=0`；需要独立进程时仍可设置 `YY_NODE_COMPILER_WORKERS=process`。旧的每线程单任务 CPU/GC 归因脚本须关闭复用，或改为按任务时间段归因。使用说明见 `工具/节点网页汇编宿主/说明.汉语.md`。

```sh
node 工具/节点网页汇编宿主/宿主.cjs yy容器图三代.wasm 豫言编译器/入口。豫 --package-context .yybuild/豫构上下文/11.上下文 --target=wasmgc --parallel -j 18 --do-not-load-cache -c -o yy复用二代.wasm
YY_NODE_COMPILER_REUSE=0 node 工具/节点网页汇编宿主/宿主.cjs yy容器图三代.wasm 豫言编译器/入口。豫 --package-context .yybuild/豫构上下文/11.上下文 --target=wasmgc --parallel -j 18 --do-not-load-cache -c -o yy独立二代.wasm
node 测试/节点宿主/线程复用。测试.cjs
```

包上下文编号依本机工程配置而定。

## 最终确认

原生稳定编译器 → 二代 → 三代 → 四代完整流水线通过，三、四代逐字节相同，哈希与本轮之前一致。随后 `./yy` 与 `./yy3_bs --parallel` 的两项类型检查通过。包含最后取消竞态修正的宿主再次以此前输出为种子完成禁用编译缓存的自举，墙钟 **15.84 秒**，产物仍与所有基线及新代完全一致。此独立确认不混入前述 ABBA 平均值。源文件和产物哈希、十类宿主回归、六核 36 轮回归记录见 [验收摘要](有界线程复用验收摘要.json)。
