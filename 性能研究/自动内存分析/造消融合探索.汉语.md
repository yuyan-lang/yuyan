# 构造与消费融合：内存优化的收益与实施条件

本轮没有修改默认编译器。调查的是树基准中已经存在的完整调用链：构造函数返回树，调用者立即把它交给只读求和函数，随后只使用整数结果。当前默认编译器已合并动态节点的载荷与构造器，仍需分配内部节点；叶子是共享常量。

在此调用链中，构造和求和都没有外部副作用。诊断原型把构造节点与消费节点合并为一个递归函数，仍执行两个递归表达式及 i64 回绕加法；不写闭式公式，不分配持久缓冲，也不更改公开入口。叶子仍读取原有常量对象的整数载荷。本轮只手改 Wasm 文本验证方向，尚未实现通用证明与自动生成，不能把结果计入默认编译器成绩。

## 同期原始算法对照

Node 26.3.0，相同 V8；C 为已有 clang 23.1.0 -O3 WASI 产物。每项五进程、每进程六轮，轮换版本顺序，无并发编译；首轮单列，后 25 次取中位数。各轮结果均为相应的叶子数。

| 深度 | 当前豫言稳态 ms | 融合原型稳态 ms | 原 C 稳态 ms |
|---|---:|---:|---:|
| 18 | 3.176 | 0.496 | 4.400 |
| 20 | 13.876 | 1.989 | 17.626 |
| 22 | 77.879 | 7.964 | 70.130 |

深度 22 当前版本仍落后原 C，因此完整目标未达成。融合的收益足以值得实现通用分析，但还不能据此宣称优于同等优化后的 C。

## 给 C 同样的融合机会

新增 `造消融合C.c`：仅把建树—求和—释放调用改为两个递归表达式相加，其他计时逻辑保留。clang 自动把两个相同的纯递归调用合并成一次调用与左移；优化后的 LLVM 摘录见 `造消融合C优化摘录.txt`。这不是本轮手写公式，C 编译器确实完成了进一步优化。

此 C 版本单次稳态约 0.0001 ms，豫言仅融合原型在深度 22 仍需 7.930 ms。极短 C 样本不足以计算可靠性能倍数，但已清楚说明：仅取消中间对象仍不够，还需要纯调用的结果复用。

另建“融合＋相同纯调用复用”的豫言诊断原型，把同样参数的第二次递归调用改为复用第一次的 i64 结果。仍不使用公式。为避免时间过短，在两个 Wasm 模块中增加相同批量接口：每次循环 500,000 次，深度依次在 20～23 之间变化，累加并核对返回结果。模块准备和叶子初始化在计时外。五进程、六轮，25 个稳态样本取中位数：

| 批量实现 | 稳态 ms | 首轮 ms |
|---|---:|---:|
| 豫言融合＋调用复用原型 | 4.490 | 5.779 |
| C 融合，clang 自动优化 | 3.747 | 4.953 |

这里豫言仍约慢 20%，不能称为已经追平。批量接口与原基准计时边界不同，数字不能直接混比。C 命令使用 `-O3 -Wl,-z,stack-size=16777216`，源文件和原始数据已保存。

## 正确性证据与限制

81 组比较覆盖最小 i64 深度、负深度、零深度、正深度到 16，以及零、正负一、i31 表示边界和 i64 极值叶子。每组比较原构造—消费结果、融合结果和独立回绕预期；调用复用版本也通过相同 81 组。此测试覆盖的是本调用链，不能证明任意程序都能融合。

默认源码和产物未修改，未重复完整自举；最近正式自举仍为 21.04、21.86 秒。原型不是默认功能，尚无自动融合后的自举结论。

## 通用实现必须证明什么

应在已验证统一正则 IR 上实现创建者—消费者组合特化，而不是按程序名称或函数编号匹配：

1. 创建结果只在已知消费链内使用，没有写全局、未知调用、对象身份观察、逃逸或其他别名用途。
2. 创建者的返回形状、标签、载荷字段及递归子对象均已知；消费者的标签分支与字段读取在这些形状上合法。
3. 创建和消费的可重排部分均无可观察副作用；先保守排除除法、未知内存访问、异常、动态调用及复杂控制。不能因“没有外存参数”就断言纯函数。
4. 每个递归子对象的消费次数、顺序和参数映射明确；重排不会改变异常与副作用。普通只读摘要尚不足以证明这一点。
5. 生成组合递归函数，以整数或原有受支持标量返回；先消除中间对象，再依据参数相同、无副作用且标量返回的证明做调用结果复用。对象返回函数不能直接套用标量调用复用规则。
6. 公共调用和未满足证明的调用保留原路径。最后用正反 IR 测试、真实多程序回归、完整自举和同期性能重新验证。

这一方向优先消除分配，避免先引入新的栈地址表示。它仍是自动分析，不要求作者标记 linear、local 或 unique。排序等其他落后项目仍需继续，不能以此单项替代完整目标。
