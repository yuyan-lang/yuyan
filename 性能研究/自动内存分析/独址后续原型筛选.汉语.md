# 独址之后的优化筛选

初轮筛选先以手改 Wasm 产物估计潜在收益，避免为没有收益的变换增加证明与代码生成复杂度。下列七项原型均不能计为已实现的通用优化，也没有通过完整语义回归；这里只验证了基准校验和。

每项独立配对：五个新进程、每进程六轮、轮换先后顺序。热轮为后二十五个样本中位数，全部校验和 6000002。不能将不同配对批次的时间直接横向比较。

| 原型 | 同批基线热轮 ms | 原型热轮 ms |
|---|---:|---:|
| 省去根数组清零 | 37.255 | 37.047 |
| 删除排序体重复边界检查 | 36.890 | 41.987 |
| 递归调用范围守卫 | 37.292 | 42.323 |
| 传递递归与分区范围事实 | 36.683 | 41.469 |
| SIMD 填充 | 37.779 | 38.640 |
| 范围传递并直接内联分区循环 | 37.268 | 37.955 |
| 私有单元函数无返回值 | 37.285 | 37.195 |

清零省略与单元返回的热轮变化很小，不足以支持在这一轮增加编译器变换。其他方案未显示收益。保留已有独址实现，不采用上述原型。

## 引擎内联证据

100 微秒采样、直接执行二十四次同一排序根函数，样本主要落在 `stack766_762`。填充约占 30.7 毫秒，排序函数约占 899.3 毫秒。内联函数的时间可能归入调用者，因此不能据此断言分区循环不热。该夹具用于定位，不能替代正式端到端计时。

随后只开启 `--trace-wasm-inlining` 读取引擎行为，没有将调参后的时间当作性能结果：

- 原实现的排序函数为 567 个 wire bytes。V8 内联了 53 字节的分区守卫及其 355 字节的循环快体，没有内联递归排序调用。
- 去除检查并传递范围后的排序快体为 243 字节。V8 先内联四层递归，耗尽预算，没有内联 355 字节的分区循环。
- 手动将分区快体放入调用者后，原型热轮恢复到接近基线，但仍未超过基线。

这支持一个具体判断：减少 Wasm 指令并不自动带来提速，函数大小会改变引擎选择内联哪些调用；但现有证据不足以将全部退步归因于内联，更不支持加入无意义填充来操纵引擎预算。

原始逐轮数据见 `独址后续原型汇总.json` 所列文件，剖析见 `栈独址直接采样.json`，轨迹见 `独址内联轨迹.txt` 与 `范围传递内联轨迹.txt`。

随后用本机 LLVM 反汇编实际的 `yy内核C.wasm`。C 的分区循环将共同扫描递进放在分支之外。据此新增的“共同递进”原型热轮为 35.972 ms，同批基线 37.265 ms。其原始记录见 `栈共同递进原型实测.json`。

该方向曾实现为通用变换：仅在进度证明与独址资格都满足时，将所有尾分支的扫描地址递进移到单步块之后，其他尾参数仍按旧值并行赋值。生成的真实排序二进制与原型完全一致。生成器通过 18,811 组、1,005,292 项检查；真实排序通过 6,919 组排序、10,287 组分区，共 270,003 项检查。

然而，独立测量未复现初次收益：

| 复测 | 基线热轮 ms | 候选热轮 ms | 基线首轮 ms | 候选首轮 ms |
|---|---:|---:|---:|---:|
| 五进程，加入 C 对照 | 36.862 | 36.839 | 47.260 | 46.045 |
| 七进程，再次配对 | 36.995 | 36.864 | 47.137 | 46.766 |

后两次热轮改善仅 0.06% 与 0.35%，进程间胜负混杂。因收益证据不足，已撤回候选生成器修改，恢复逐字节相同的已验证独址源码。候选差异留在 `共同递进候选.patch`，不参与编译；没有为未保留的候选运行完整本机自举。恢复后类型检查通过。本轮没有保留新的编译器变换。

最终证据为 `栈共同递进生成验证.json`、`栈共同递进排序差分验证.json`、`栈共同递进排序实测.json`、`栈共同递进独立复测.json`。不能引用最初原型结果宣称编译器又提速约 3.5%。后续应继续比较热点生成代码，并用独立复测筛除小样本波动。
