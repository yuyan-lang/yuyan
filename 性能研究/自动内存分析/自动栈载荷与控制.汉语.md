# 自动栈的载荷地址与单步控制

在已验证的独址实现上组合三项变换，未改变公开 ABI、数组布局或源码标注要求：

1. 地址镜像直接指向元素数据，即“数组基址 + 8 字节头 + 索引 × 8”。镜像访问使用 `offset=0`；恢复整数索引时先减去基址和头。未知仿射更新仍按新索引重算，普通访问及完整检查后备仍使用 `offset=8`。
2. 进度证明批准的单步只会尾递归续行，条件分支因而不需要结果值。生成器改用无结果的条件控制，尾参数更新后自然合流，去掉原先的单步跳出与丢弃结果。
3. 对已证明每条路径都加一、且不再维护数值状态的扫描参数，将共同地址递进放到单步之后。其他尾参数继续按旧状态并行求值和赋值。数值扫描参数仍在尾分支中更新。

这依赖既有 SSA、表示、范围、活性与进度证明。不是任意函数的控制流改写；提前返回、未知调用等无法通过单步证明的函数保持原生成路径。比较局部仍在步内置假、退出时置真；数组读写与除法没有删除或跨步重排。

## 从机器码筛选方案

本机 V8 TurboFan 的旧排序热点为 1,432 字节机器指令，C 对照为 668 字节。旧镜像访问常生成地址加法再用 8 字节偏移访问；C 对应访问可直接使用寄存器索引寻址。记录为 `豫言排序热点机器码.txt`、`C排序热点机器码.txt`。这里只用机器码定位，不根据指令数量直接宣称提速。

本轮先测了混合索引表示、载荷对齐、中点右移、单独前移载荷偏移，均未显示稳定收益。无值单步、共同递进及载荷地址的组合则在两批原型测量中改善；额外循环旋转没有继续改善，故未采用。相关原始记录为 `栈混合位置原型实测.json`、`栈载荷对齐原型实测.json`、`栈中点位移原型实测.json`、`栈载荷镜像原型实测.json`、`栈无值单步原型实测.json` 与 `栈无值载荷独立复测.json`。

## 通用实现的正确性与性能

生成器通过 18,811 组、1,005,292 项检查，覆盖不同帧起点、奇偶长度、所有小数组起点、交叉索引、负偏移重算、完整 i64 溢出求和、除法及越界异常和异常后的内容。真实产物另通过 6,919 组排序与 10,287 组分区，共 270,003 项检查。详见 `栈载荷控制生成验证.json` 与 `栈载荷控制排序差分验证.json`。

另外完成 35 项容量边缘与哨兵检查：三个帧基址的分配末端都恰好到达 64 MiB，验证末两项填充、读取、求和、参数交换、扫描的 one-past 终点，以及再多一个元素时的分配拒绝。不同帧哨兵不变。见 `栈载荷控制容量边界.json`。

与上一版实验产物比较，841 个具名函数签名及导入导出不变，只有填充和分区的两个私有快体改变；检查后备仍存在。代码选择检查确认实际使用 `offset=0` 和无值单步。详见 `栈载荷控制接口审计.json`。

四百万元素；每版五个新进程，各六轮，轮换版本顺序。计时包含分配、填充、排序与校验和，排除参数解析和打印。校验和全部为 6000002。首轮取五个样本中位数，热轮取其余二十五个样本中位数。

| 版本 | 首轮 ms | 热轮 ms |
|---|---:|---:|
| 旧独址实现 | 46.613 | 36.744 |
| 载荷地址与无值控制 | 45.337 | 35.710 |
| C/Wasm | 42.600750 | 33.302000 |

热轮相对旧版减少约 2.8%，仍比 C 慢约 7.2%，目标尚未达成。原始记录为 `栈载荷控制排序实测.json`。实验栈开关仍默认关闭。

新产物热点机器指令大小为 1,400 字节，记录于 `载荷控制排序热点机器码.txt`。代码尺寸仅稍减，不能用它代替运行时间证据。

完整本机自举与两项类型检查通过，`yy3_bs` 与 `yy4_bs` 逐字节一致。默认模式使用 `--do-not-load-cache --parallel -j 18` 的完整冷缓存 Wasm 自举为 22.96、23.30 秒，种子与二、三代产物一致。该时间未开启实验栈，不能归因于运行时栈分配提速。详见 `栈载荷控制本机验证.json` 与 `自动栈载荷控制冷自举.json`。

本机与 Wasm 编译器生成的实验排序二进制一致。其余五个基准及关闭实验开关的排序产物与上一版逐字节相同，故不重复测量未变化的程序。详见 `栈载荷控制六核产物.json`。
