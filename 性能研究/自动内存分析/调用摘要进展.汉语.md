# 跨函数调用摘要进展

本轮新增自动跨函数来源与逃逸摘要，目前作为分析报告使用，尚未据此改写对象布局或复用存储。本轮没有新的运行时提速数字；此前矩阵优化的实测仍有效，整体追平 C 的目标仍未完成。

摘要在统一正则模块上迭代求不动点，分别记录：

- 哪些参数及其可达对象可能被向外保存。
- 返回值可能来自哪些参数或其内部对象。
- 返回值是否可能包含本次创建的对象。
- 是否遇到当前无法精确分析的副作用。

局部值携带参数来源集合；构造元组和构造器合并字段来源；静态调用将被调用者摘要映射回实际参数；分支合并可能来源；递归调用通过单调迭代传播。未知调用、未知写入及复杂控制流保守处理。未知写入之后，不再沿用写入前的局部来源，以免漏掉新形成的别名。

这不是完整指向分析，也不区分所有字段路径。“返回可能可达参数”不是“必然返回同一对象”；“可能新建”也不是“必然新建且唯一”。摘要产生于后续常量共享之前，常量节点可能最终共享。不能直接把这些字段作为栈分配或线性复用的许可。

当前精确分析预算为每函数不超过八个参数、256 个局部值；超出预算用最宽摘要。迭代超限也将模块摘要保守扩大，不发布未收敛的安全结论。报告开关仍是 `--debug-print-add 内存分配`；默认不运行这项诊断分析。

八项独立中间表示回归通过，覆盖返回参数、容器携带参数、字段读取、标量计算、互递归、未知调用及写后读取。测试曾检出一次写后来源未扩大的错误，已修复。输出见 `调用摘要回归输出.txt`。

实际树程序的结果见 `树调用摘要.json`：建树函数及其递归主体没有参数外存，返回值具有新建来源；树和递归主体没有参数外存，返回值可能来自输入树的可达对象。这提示下一步应建立对象形状和字段路径，区分返回叶子数值与返回整棵树，再分析调用者区域内的生命周期。

开启和关闭摘要诊断生成的树 Wasm 逐字节一致，六轮结果均正确。此轮仅增强分析证据，不声称已经完成通用栈分配、所有权推导或存储复用；也没有采用被用户否决的私有持久缓冲。

范围说明：“可能新建对象”字段追踪显式元组、构造器和数组来源，以及未知调用的保守来源；它不统计整数装箱等隐式分配。“否”不能解读为函数不会分配内存。后续用于分配优化前还必须结合表示选择与装箱分析。

最终验证：本机规定自举与两种入口类型检查通过，三代四代一致；Wasm 完整冷编译缓存自举 19.32、19.43 秒，二代三代逐字节一致。源码及产物校验和见调用摘要源码补丁、调用摘要产物摘要。
