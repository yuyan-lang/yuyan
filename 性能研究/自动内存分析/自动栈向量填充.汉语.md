# 自动栈向量填充

2026-09-20。本轮将非 GC 栈数组的八项 SIMD 填充原型接入编译器，保留该优化。公开 ABI 不变，仍由 `--wasm-stack` 启用实验栈后端；默认 GC 路径未改变。

## 实测结果

同机 Node v26.3.0 / V8 14.6.202.34-node.20，快速排序 4,000,000 项。每个新进程执行六轮，首轮单独统计，热运行取后五轮；轮换版本顺序，计时期间没有并发构建。所有校验和均为 6000002。

| 独立测量组 | 上一版热运行 | 本轮热运行 | C/Wasm 热运行 | 本轮相对上一版 | 本轮相对 C |
|---|---:|---:|---:|---:|---:|
| 五进程，各六轮 | 34.388 ms | 33.901 ms | 33.979709 ms | 用时减少 1.4% | 快 0.2% |
| 九进程，各六轮 | 35.354 ms | 34.302 ms | 34.101667 ms | 用时减少 3.0% | 慢 0.6% |

首轮中位数：五进程组为上一版 44.569 ms、本轮 42.555 ms、C 43.054291 ms；九进程组为 45.649 / 43.044 / 43.623334 ms。原始数据见 [五进程定稿实测](栈向量填充定稿实测.json) 和 [九进程独立复测](栈向量填充九进程复测.json)。本轮已进入 C 的同一性能区间，波动仍大于与 C 的差距，不能据此认定稳定超过 C，更不能外推为所有程序都达到 C。

较早的 [诊断串行产物测量](栈向量填充接入实测.json) 使用了串行编译，公开函数存在额外局部声明，因此不作为最终归因数据。定稿表使用原生编译器并行编译的实际产物，且与最终 Wasm 自举编译器生成的排序逐字节相同。

## 自动分析与生成

`网页汇编栈填充证明。豫` 在既有 SSA、封闭调用图和表示证明之后识别循环：恰有一个数组参数，每步向扫描位置写入一次；扫描加一，其他参数不变；退出值为单元；没有读取、除法、其他调用或嵌套分支。填充值限于加减乘表达式，对扫描变量具有编译期常系数，系数在 -16 到 16 之间，表达式树最多 64 个节点。

`网页汇编栈向量填充。豫` 保留完整检查的标量后备入口。运行时先证明 `0 ≤ 扫描 ≤ 上界 ≤ 数组长度`，再以四个 `i64x2` 向量每批写八项，剩余项逐项写入。值与递推均遵守模 2^64 的整数运算。没有按基准程序名称特化，没有省略根数组初始化，也没有保存数组内容用于下一次调用。

自动非逃逸栈分配仍沿用既有容量与生命周期限制：整数载荷、封闭调用图、每实例最多 64 MiB，不能证明安全或容量不足时退回 GC。此次没有扩大到包含 GC 引用的记录或闭包，也没有要求用户标注 ownership、locality 或 linear 类型。

## 验证

- 16 项证明测试，包括非线性、运行时系数、除法、读取、错误步长、错误写索引、改变不变参数及非循环空体的拒绝路径。
- [填充差分](栈向量填充专用差分.json)：115,346 个案例、3,364,634 次检查，涵盖七种表达式、完整 i64 边界值、前缀保留、不足八项的尾部、非零帧基址、越界异常与异常后内容。
- [非连续编号差分](栈向量填充疏号差分.json)：48,216 个案例、1,382,192 次检查，形参编号为 8、9、10、11。
- [真实排序差分](栈向量填充排序差分.json)：6,919 个排序案例、10,287 个分区案例、270,003 次检查。另覆盖 [1 至 1024 项真实根入口与空数组异常](栈向量填充根差分.json) 及 [64 MiB 容量边界](栈向量填充容量验证.json)。
- [产物审计](栈向量填充变化函数.json)：841 个函数中仅 `$stack766_752q` 的函数文本变化。[接口验证](栈向量填充接口验证.json) 确认函数签名、导入和导出保持一致。
- [其他内核](栈向量填充其他内核.json)：相同原生编译流程下，斐波那契、素数筛、矩阵乘法、树基准、数组基准，以及默认 GC 排序均与上一版逐字节一致。

## 自举

按仓库要求完成 stable → 二代 → 三代 → 四代原生自举，第三代与第四代逐字节相同；`./yy` 和第三代编译器的类型检查均通过，见 [本机验证](栈向量填充本机验证.json)。

完整禁用编译缓存的两次 Wasm 自举墙钟时间为 **22.37 秒、22.88 秒**，满足 30 秒标准。此指标使用默认 GC 编译路径、18 个工作进程，不启用实验栈模式。种子、二代、三代产物逐字节一致，见 [冷自举结果](栈向量填充冷自举.json)。

复现冷自举的单代命令如下，下一代以输出文件作为输入编译器：

```sh
/usr/bin/time -p node 工具/节点网页汇编宿主/宿主.cjs yy栈向量定稿种子.wasm 豫言编译器/入口。豫 --package-context .yybuild/豫构上下文/11.上下文 --target=wasmgc --parallel -j 18 --do-not-load-cache -c -o yy栈向量二代.wasm
```

下一步仍需压缩实际生成代码的开销，争取超过当前噪声幅度的收益，并继续扩大自动非逃逸分析的对象覆盖。当前结果支持保留本轮优化，不代表商业性能目标已经全部完成。
