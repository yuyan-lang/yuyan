# 默认栈启用审计

结论：本轮不修改默认开关，也不接入新的 WAT 原型。当前自动栈路径在大数组中已有收益，但频繁创建极小数组存在明确退化，尚不满足直接默认启用的性能要求。

开启 `--wasm-stack` 编译编译器自身，产物与关闭时字节一致，未发现可用栈根。全部 41 个具有成功期望的网页汇编程序在开、关两种模式下编译、加载及运行通过，输出严格匹配期望；其中 6 个程序真正生成栈运行时。WASI 专用“不支持子进程”失败测试不属于本次 WasmGC 正例集合。

小数组测试在原排序产物中追加 Wasm 内部重复调用入口，算法不变。每规模每变体五个新进程，各六轮，轮换顺序，后五轮合并取中位数。每批调用次数为 `floor(1048576 / 长度)`，不同长度之间不可直接比较批次耗时。

| 长度 | GC 批次毫秒 | 栈批次毫秒 |
|---|---:|---:|
| 1 | 4.583 | 7.703 |
| 2 | 3.346 | 5.432 |
| 8 | 3.189 | 2.916 |
| 32 | 3.775 | 2.967 |
| 128 | 4.768 | 3.910 |
| 1024 | 7.025 | 5.298 |

根帧预留专化原型去掉恒零栈顶的冗余运算，未解决小数组退化，百万及四百万排序约慢 2.5%，不采用。

另测小于等于 4 或 8 个元素时用既有标量初始化循环代替 `memory.fill`。长度 1、2 的固定开销有所下降，但仍慢于 GC；长度 16、32 也有轻微退化，故尚不接入。该组长度 1 的 GC / 原栈 / 四元素阈值 / 八元素阈值批次分别为 4.471 / 7.639 / 5.684 / 5.914 ms。大数组变化在约 0.5% 范围，不能据此主张确定收益。下一步需要继续研究小对象标量替换或分配策略的成本，不能把不逃逸简单等同于应当栈化。

数据见 `默认栈自编译审计.json`、`默认栈完整回归.json`、`默认栈小数组实测.json`、`根栈预留专化实测.json` 和 `短数组清零原型实测.json`。本轮未修改编译器源码，前一轮最终自举验证仍适用于当前源码。
