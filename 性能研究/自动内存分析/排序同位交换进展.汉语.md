# 同位置交换消除实验

调用栈容量保留方案仍待用户决定，本轮仅研究已有 GC 数组路径，未改变存储方式或编译器源码。

分区比较前已经读取扫描位并完成检查。若存放位等于扫描位，则后续交换读写同一元素，可考虑省略。但这是受当前快速路径前提约束的原型，不能直接推广到任意数组访问、共享对象或可观察写入。

第一组五进程各六轮：当前版首轮 56.576 ms / 热轮 44.161；在比较成立分支内增加索引不等判断、相等则跳过交换，得到 60.966 / 48.585，变慢。

第二组同期对照：当前版 57.094 / 44.388；上述嵌套分支 61.835 / 49.310；合并两个条件为单个交换分支、将存放位置增量改成加比较结果，得到 79.284 / 68.059，同样变慢。每个进程六轮，首轮单列，其余二十五轮取中位数；全部输入四百万、校验和 6000002。

两个原型均不进入默认编译器；只验证了既有排序校验和，未完成全面语义证明，也不宣称 GC 方案已经达到极限。原始数据和差分补丁同目录保存。当前正式候选仍为已通过验证的递归形态版本，冷缓存自举记录为 22.45、22.87 秒，排序与 C 的差距尚未解决。线性调用栈未经用户决定，未实现。
