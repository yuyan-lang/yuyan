# C 对照构建与 SIMD 审计

本轮未改动豫言编译器。在等待用户决定最终统计容差期间，独立核对 C 对照的可复现性和 Wasm 特性选择。不能因为豫言已使用 SIMD，便假定未开启 SIMD 的 C 一定更慢，也不能为了通过验收选择较慢的对照。

原记录中的相对 SDK 路径在当前 worktree 不存在。找到可用的 SDK 为 `/Users/zc/repos/yuyan-worktrees/yuyan-wktree-4/yy_wasi_sdk/bin/clang`，版本 `23.1.0-wasi-sdk`，LLVM 提交 `895aa2c896ada719451be2e3673c83da8ddf1141`。只读使用其工具，没有修改该 worktree。

使用同一份 `性能研究/运行内核/原生内核.c`，分别构建：

```sh
/Users/zc/repos/yuyan-worktrees/yuyan-wktree-4/yy_wasi_sdk/bin/clang -O3 性能研究/运行内核/原生内核.c -Wl,-z,stack-size=16777216 -o yy内核C复构.wasm
/Users/zc/repos/yuyan-worktrees/yuyan-wktree-4/yy_wasi_sdk/bin/clang -O3 -msimd128 性能研究/运行内核/原生内核.c -Wl,-z,stack-size=16777216 -o yy内核C向量.wasm
```

旧 C 与标量重建文件的整体哈希不同，但逐节审计发现唯一差异是 `name` 自定义节：1348 字节变为 1354 字节。所有非自定义节完全相同；`llvm-objdump -d` 输出除首行文件名外完全相同。两者编译器版本和目标特性也相同。故没有发现原对照的可执行代码不可复现的问题。见 [逐节审计及工具链记录](C对照构建审计.json)。

旧版目标特性不含 `simd128`，新向量版明确包含该特性。三种实现各三个新进程，每进程六轮，交替顺序，无并发构建；首轮单列，后五轮合并取中位数。所有结果值一致。见 [全部原始样本](C向量选项对照.json)。

本组没有证据支持用向量版替换原 C；数组、矩阵和排序的回退尤其明显。继续以较快的原 C 为主要对照，并保留 SIMD 结果。未分析引擎机器码和向量成本，不能武断归因于某一条指令；也不把这组有限实验解释为穷尽 C 的优化选项。

百万项排序在本组略快于原 C，而上一组慢约 2.68%，再次说明完成判定不能择取一组中位数。2% 统计容差问题尚未得到用户答复，未修改完成标准、没有宣称目标达成，也没有重复提交相同问题。
