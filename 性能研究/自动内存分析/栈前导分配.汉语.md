# 分配前计算与非 GC 栈内存

本轮扩展自动栈分配覆盖范围：原先只能处理函数第一条指令创建的数组，现在允许在分配之前计算整数加、减、乘，数组长度和初始值可以依赖这些结果。例如先计算 `长度 = 输入 + 1`、`初值 = 输入 * 3 - 2`，再创建局部整数数组，无须手动标注。

## 实现与语义边界

`网页汇编栈前导。豫` 识别前导；栈调用图和私有体生成器消费同一规则。公开入口完成类型守卫后按原顺序执行前导，再检查容量、初始化栈内存。整数运算保持 i64 回绕语义。私有体可重复执行这些无效果、无算术陷阱的计算。

前导拒绝除法、数组读写、调用、分支和未知操作。结构识别本身不是证明，仍须通过合法 SSA、整数表示、不逃逸、封闭调用图、无宿主重入及单根分配资格检查。子函数创建数组、返回根数组或重新调用根函数等既有限制不变。容量不足和类型不符仍执行原 GC 后备。

端到端验证发现第二个障碍：前导整数计算往往使根函数具有原生整数私有入口，而旧栈后端拒绝这类根。现在为非纯数值函数的零/一类私有参数生成 `mN` 桥，装箱整数后尾调用公开栈守卫；原 GC 实现在 `fsgN/msgN`，不会经桥递归。引用数组私有参数暂不支持。公开 ABI 保持不变，私有调用方继续使用原签名。

数组载荷位于非 GC 线性内存；这不表示整个函数零 GC 分配，整数参数桥接和返回值仍可能装箱。本轮仍由 `--wasm-stack` 启用，未改默认策略，也未实现通用多对象栈帧。

## 效果

新增覆盖基准 `性能研究/运行内核/前导排序。豫` 与原排序算法相同，仅在根函数内部把输入加一作为数组长度。旧、新编译器编译完全相同源码，均启用栈选项；旧版不能栈化此根，新版能。每种规模七个独立进程交错执行，每进程六轮，后五轮合并取中位数。

| 实际数组长度 | 旧编译器 | 新编译器 | 耗时下降 |
|---|---:|---:|---:|
| 100 万 | 10.749 ms | 8.125 ms | 24.4% |
| 400 万 | 44.883 ms | 34.049 ms | 24.1% |

全部校验和通过。这是新增覆盖范围的收益，不能替代既有 C 对照，也不能证明所有程序达到 C 水平。原有六核及默认 GC 排序重新编译后，与上一正式版本的二进制逐字节一致。

## 验证证据

- `栈前导定稿入口验证.json`：新入口 5,904 个差分用例、原入口 6,033 个差分与单元返回用例；比较值、异常名称和消息，检查实际后备次数。覆盖稀疏 SSA 编号、i31 边界、i64 溢出、负长度、越界索引及 64 MiB 上限内外。
- `栈前导生成。测试。豫`：额外拒绝除法、读取、写入、未知原语四种前导。生成的夹具经过 Wasm 模块验证。
- `栈前导私门差分.json`：真实编译产物公开入口、私有桥与 GC 参考间 2,065 个差分用例；正常长度与极端整数、非法引用类型均覆盖。
- `栈前导六核验证.json`：原六核及默认排序字节一致；源码级初始化测试 516 项通过，确认生成了两个前导栈根、共六个前导局部值。
- `栈前导排序实测.json`：新增覆盖基准原始测量。
- `栈前导冷自举.json`：最终 Wasm 编译器冷缓存自举及固定点比较，运行时均为同机 Node，未清除操作系统页缓存。

原生验证链与 Wasm 冷自举应分别记录，不能将前者当作后者的计时。本轮未宣称全部性能目标完成。

最终 Wasm 冷自举分别为 15.55 秒、15.87 秒，种子与两代产物完全一致。最终原生验证链三步分别为 58.044、81.926、79.054 秒，第三、四代逐字节一致；`./yy` 与第三代编译器的类型检查均通过。完整命令、退出状态、源码及产物哈希见 `栈前导定稿原生自举.json`、`栈前导源码摘要.json` 与 `栈前导验收摘要.json`。这些原生验证时间不满足“原生每次冷自举低于 30 秒”的解释，不能用 Wasm 计时替其证明。
