# 手柄接口规范 0.1.0

本包规定宿主授予的游戏手柄能力：枚举手柄、读一份按钮与摇杆的状态、接收接入与拔出的热插拔事件、可选的手柄振动，以及按标准布局查按钮与摇杆的汉字名。应用直接依赖本包即要求宿主实现它；宿主没有手柄能力时，各函数按本规范答 `资源暂不可用`，装载不因此失败。

## 标准布局

状态里的按钮与摇杆按下表编号，所有宿主一致。钮们是十七个整数，零至一千：普通按钮按下为一千、松开为零，扳机「左弩」「右弩」为模拟量（零至一千）。枢们是四个整数，以千分计，负为左或上、正为右或下，满偏为 ±一千。

## 语义

- **枚举手柄**：`列辔` 无参数，返回此刻接着的全部手柄。空列是成功，表示宿主有手柄能力而眼下没有设备。宿主不能枚举手柄时返回 `资源暂不可用`。
- **读状态**：`问辔` 接收一个句柄，返回一份快照。钮们恰十七项、枢们恰四项；宿主应把设备实际的轴与钮按标准布局归一。手柄已拔出返回 `资源已失效`。同一手柄在两次调用之间可以变化，状态不保证跨调用持续。
- **热插拔**：`候辔` 接收毫秒数。正数时等到期限：期内有接入或拔出就交回该事件（同一期限内有多件时按发生次序一件一件交，其余留待下次），到期仍无变化返回 `辔无变`；非正数表示无限等待。接入事件带新句柄，拔出事件带原句柄；拔出后再 `问辔` 得 `资源已失效`。应用也可以只在每帧 `列辔` 比较前后两份列表，不依赖 `候辔`。
- **振动**：`振辔` 依次接收句柄、强度（零至一千，带标签「强」）与毫秒数（带标签「毫」，零表示宿主自定一个短时长）。强度零停止振动。宿主没有振动能力时返回 `资源暂不可用`；`振已发` 只表示请求已交给宿主，不表示振动已经开始或结束。振动是可选能力：林纳用 evdev 的 FF_RUMBLE（EVIOCSFF 上传效果、EV_FF 播放），林檎对不在的柄答 `资源已失效`、柄在答 `资源暂不可用`（GCHaptics 留待后续版本）。
- **名字**：`辔钮名` 依次接收句柄与按钮下标，返回汉字名；下标超出十七或手柄没有该按钮时返回空串。`辔枢名` 同理，下标范围为四。名字随设备而变，应用按名字显示提示，不按名字分支。

## 宿主

- **林纳（原生）**：执行器读 `/dev/input/event*` 的 evdev 设备（以 O_NONBLOCK 打开，ioctl 取设备名与能力），按设备能力认出手柄，键码与绝对轴按标准布局归一；热插拔靠重扫输入设备目录并比较事件号。适配在 `豫言操作系统/适配/辔原生`。没有读输入设备的权限时答 `资源暂不可用`；振动用 evdev 的 FF_RUMBLE。
- **林檎（原生）**：执行器经 Objective-C 运行时用系统自带的 GameController：`[GCController controllers]` 列出手柄，`GCExtendedGamepad` 的 `pressed` 读按钮、`value` 读扳机与摇杆，按标准布局归一；热插拔靠每二十毫秒重扫控制器数组并比较 `vendorName`；振动这一版答 `资源暂不可用`（GCHaptics 留待后续版本）。适配同是 `豫言操作系统/适配/辔原生`。
- **浏览器**：用页面的 Gamepad 接口，脚本胶水放在 `豫言操作系统/宿主/浏览器/操纵.mjs`；只在页面可见并取得手柄后才有状态，拔出后按规范答 `资源已失效`。适配包是 `豫言操作系统/适配/操纵浏览器`。
- **模拟宿主**：由 `豫言操作系统/适配/操纵模拟` 提供，测试用 `辔` 篇里的 `拟置柄`、`拟置态`、`拟推事`、`拟取振`、`拟清` 预置手柄、状态与事件，便于在没有设备的机器上验证动作映射。

裸机的实现与林檎的振动在后续版本补上（议题 #557）：裸机计划走通用串行总线的 HID 手柄，驱动写成两架构共用的底层豫言；林檎计划用 GCHaptics（要 GCHapticEngine 与 AHAP 模式数据，留待后续版本）。轩窗与裸机眼下没有手柄能力，各函数答 `资源暂不可用`。

## 错误

| 情形 | 错误 |
| --- | --- |
| 宿主没有手柄能力 | `资源暂不可用` |
| 手柄已拔出后问状态或振动 | `资源已失效` |
| 手柄没有振动能力 | `资源暂不可用` |
| 参数下标越界 | `输入无效`（问名返回空串，不报错） |

## 验收

规范样例须覆盖：空列、接入与拔出、拔出后问状态、按钮与扳机的取值、四个轴的符号方向、振动成功与不支持、按钮与摇杆名（含越界）、以及在没有手柄能力时各函数答 `资源暂不可用`。动作映射见游艺部的 `御术` 库。
