# 持久独占接口规范 0.3.0

本包让应用在持久对象（Durable Object）里开启一个**并发独占区**：区内应用可以等待外部输入输出（调用别的服务、读上游、跑较长的计算），而这段时间里发往该对象的其他事件（HTTP 请求、告警、套接字消息）**排队等候**，不与区内的读写交错。它对应平台的 `blockConcurrencyWhile`，典型用途是“读—改—外部调用—写”必须整体串行的请求，例如同一站点同一时刻只处理一个动态请求。

## 模型

独占区以**类型化回调**实现（提案 C0001，与[持久事务](../持久事务/规范.汉语.md)对称）：应用实现入口 `执行持久独占回调`（`独占处理。应用接口。豫`）。应用在持久对象里调用 `执行持久独占 持久仓 操作名 参数`（持久仓是[持久事务](../持久事务/规范.汉语.md)的 `持久仓`，0.3.0 起显式传入），宿主暂停向该对象投递其他事件，在平台的独占回调里调用这个入口（外层调用此时挂起），传入 `持久独占区`、操作名与参数文字；入口返回的结果文字就是 `执行持久独占` 的返回值，宿主随后恢复投递。`持久独占区` 只在这次回调内有效；区内用 `独占区持久仓` 取得所属对象的持久仓。

## 语义

操作名是 1 至 128 字节的文字，由应用约定，用来在回调里选择要做的事；参数与结果都是有效 JSON 文字，各不超过 8 MiB，由宿主验证（非法 JSON 使调用失败）。回调**看不到外层的 HTTP 请求**，外层需要交给它的请求资料（方法、路径、正文、标头等）应放进参数 JSON，结果再由外层据以构造响应。

区内应用可以用 `独占区持久仓` 读写持久仓（包括[持久事务](../持久事务/规范.汉语.md)的直接访问函数）、启动事务、读写[持久告警](../持久告警/规范.汉语.md)、等待任意外部输入输出；不能再开启独占区（用取自 `独占区持久仓` 的持久仓开启时报 `独占区内不可再启动独占区`），事务回调里也不能开启（用取自 `事务持久仓` 的持久仓开启时报 `持久事务回调内不可启动独占区`）。多个独占区依次执行，不会重叠；独占区进行期间到达的其他事件在区结束后才被投递。独占区期间该对象的吞吐被完全占用，因此区内的耗时越短越好。宿主可以在同一实例上依次或交错调用入口，应用不依赖两次调用之间的内存状态。

区内失败——回调抛出未捕获异常、结果不是有效 JSON 或超过 8 MiB——不会传给平台：宿主把失败作为返回值交给外层，`执行持久独占` 抛出可用「尝试运行」捕获的豫言异常，消息以 `持久独占失败：` 开头并保留原因文字（如 `持久独占失败：独占区结果不是有效 JSON`）；**对象不会被重置**。这是有意的设计：平台原生的 `blockConcurrencyWhile` 回调一旦抛错就会重置整个持久对象（丢弃内存状态、使正在进行的请求失败，本地 workerd 已验），而应用里的独占区失败是常见的业务情形。回调自己抛出而未捕获的豫言异常由标准库的默认处理写到标准错误，并以退出码 1 结束这次回调，消息为 `持久独占失败：豫言程序退出：1`；需要向外层报告具体原因时，回调应自己用「尝试运行」捕获，并把原因写进返回的结果。

平台在独占区回调超过 30 秒时重置对象（本地 workerd 已验：超过 30 秒后对象被重置，请求失败），应用应给区内的外部调用设置更短的超时。

## 函数

`执行持久独占 持久仓 操作名 参数`：返回结果 JSON 文字。`独占区持久仓 独占区`：返回独占区所属对象的持久仓。应用接口 `执行持久独占回调`：参数为 `持久独占区`、带标签 `名称` 的操作名与带标签 `参数` 的参数文字（与调用者传入的相同），返回结果 JSON 文字。

## 失败情形

| 情形 | 类别 |
| --- | --- |
| 操作名不是 1 至 128 字节；参数不是有效 JSON 或超过 8 MiB | 违规：`执行持久独占` 抛可捕获异常，消息 `持久独占失败：…` |
| 回调失败、结果不是有效 JSON 或超过 8 MiB | 抛可捕获异常，消息 `持久独占失败：…`，对象不重置 |
| 用取自 `事务持久仓` 或 `独占区持久仓` 的持久仓调用 `执行持久独占` | 违规：抛可捕获异常，消息 `持久独占失败：…` |
| 平台故障、独占区超过平台的 30 秒 | 平台故障：本次调用失败（超过 30 秒时对象被重置） |

## 跨宿主一致性

任何实现须保持：区内不与其他事件交错、区内到达的事件区后才投递；区内失败以可捕获异常报告且不重置对象；不可嵌套；参数结果按 JSON 文字原样传递（结果不必与回调返回的文字字节相同，但 JSON 意义相等）；上述限额与失败类别。

## 一致性样例

对象里键 `n` 初为 0，`仓` 为该对象的持久仓。五个并发请求各自 `执行持久独占 仓 "counter" 参数`，回调读 `n`、等待外部 30 毫秒、写回 `n+1` 并返回新值，则五个结果恰为 1 至 5 的一个排列，最终 `n` 为 5，外部等待的区间两两不重叠；同样的读—等—写若不放进独占区，五个并发请求的结果会都是 1、最终 `n` 为 1（更新丢失）。独占区进行中到达的 `durable-fetch` 请求在区结束之后才被处理。`执行持久独占 仓 "fail" "{}"` 而回调未捕获异常时，抛出以 `持久独占失败：` 开头的异常，其后对象照常服务且实例不变。`执行持久独占 仓 "" "{}"`、`执行持久独占 仓 "x" "不是JSON"` 抛异常。区内 `执行持久独占（独占区持久仓 区）…` 抛出 `持久独占失败：独占区内不可再启动独占区`。

## 边界

本包不提供带优先级的队列、超时后自动放弃的独占区、跨对象的分布式锁，也不把外层 HTTP 请求带进区内。它只用于已授权的持久对象，对象的名称与授权由宿主和部署配置决定。独占区不改变平台对存储读写的输入门规则，只是在区内额外挡住其他事件的投递。

后续版本的事项：独占区回调的宿主墙钟时限（短于平台的 30 秒重置线，使超时表现为可捕获异常）；从外层请求取得的持久仓带进区内再开独占区时的检查。
