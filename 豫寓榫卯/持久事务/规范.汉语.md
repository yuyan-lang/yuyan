# 持久事务接口规范 0.4.0

本包让应用读写持久对象（Durable Object）的持久仓，并在同一个原子事务里做多步读写。0.3.0 起用类型化回调（提案 C0001）：应用实现入口 `执行持久事务回调`（`事务处理。应用接口。豫`），事务内的函数以 `持久事务` 为第一个参数，回调的返回值就是事务结果。0.4.0 起持久仓显式传递：`持久仓` 是宿主构造的值，在持久对象收到的网页请求里用 `入站请求持久仓` 取得，在事务回调里用 `事务持久仓`、在独占区回调里用[持久独占](../持久独占/规范.汉语.md)的 `独占区持久仓`、在告警入口里用[持久告警](../持久告警/规范.汉语.md)的 `告警持久仓` 取得；直接访问持久仓、开启事务的函数以它为第一个参数。仓内每个键的值是一个 JSON 值：宿主以结构化值存入平台存储，因此与既有 JavaScript 对象写入的数据互通——读出时得到该值的 JSON 文字，应用写入 JSON 文字后，旧 JavaScript 代码读到的是同一个对象。仓由它所属的持久对象独占，宿主不得把另一个对象、另一次事务的状态暴露给调用方。

## 持久仓

`入站请求持久仓` 接受持久对象收到的 `入站网页请求`（事件种类 `durable-fetch`），得到该对象的持久仓；请求不是发给持久对象的时，抛出可捕获的豫言异常 `当前事件不属于持久对象`。`事务持久仓` 接受事务回调里的 `持久事务`，得到落在本事务上的持久仓：经它直接访问持久仓、读写告警，都属于本事务，随事务提交或回滚。持久仓只在取得它的这次调用或回调里有效。

## 事务

`执行持久事务` 接受持久仓与有效 JSON 文字，开启平台事务，在平台的事务回调里调用应用的入口 `执行持久事务回调`（外层调用此时挂起），把 `持久事务` 与参数文字传入；回调返回的有效 JSON 文字就是 `执行持久事务` 的结果。回调通过 `读取持久事务键值`、`写入持久事务键值`、`删除持久事务键`、`列举持久事务键值` 读写本事务的键，通过 `回滚持久事务` 放弃本事务已作的全部写入。输入 JSON 由宿主验证，回调的结果须为有效 JSON。`持久事务` 只在这次回调内有效。

所有读写属于同一个原子事务：回调抛错、结果不是有效 JSON 或存储失败时，已写入的键、已设置或删除的告警都不得提交。一个仓内并发事务串行执行，且回调运行期间平台不向该对象投递其他事件（它们排队等候，等价于[持久独占](../持久独占/规范.汉语.md)），所以事务里可以等待外部输入输出，但应尽量短：平台在事务回调超过 30 秒时会重置整个对象。`回滚持久事务` 之后不得再读写本事务的键（平台会拒绝这些调用），回调随后返回结果即可。回调内不能再启动事务或[持久独占](../持久独占/规范.汉语.md)区（取自 `事务持久仓` 的持久仓开启时抛出可捕获异常）；在回调里用取自 `事务持久仓` 的持久仓调用[持久告警](../持久告警/规范.汉语.md)函数时，告警的设置与删除与本事务同命运（事务提交则生效，回滚或失败则撤销）。

`执行持久事务` 失败时（回调抛出未捕获异常、结果不是有效 JSON、存储失败）抛出可用「尝试运行」捕获的豫言异常，消息以 `持久事务失败：` 开头并保留原因文字（如 `持久事务失败：事务结果不是有效 JSON`）；所有写入已回滚。回调自己抛出而未捕获的豫言异常由标准库的默认处理写到标准错误，并以退出码 1 结束这次回调，消息为 `持久事务失败：豫言程序退出：1`；需要向调用者报告具体原因时，回调应自己用「尝试运行」捕获，并把原因写进返回的结果。

## 直接访问持久仓

`读取持久仓键值`、`写入持久仓键值`、`删除持久仓键`、`列举持久仓键值`、`清空持久仓` 以持久仓为第一个参数，让应用不开事务直接访问持久仓，常用于只读一个键、写入后立即返回、扫描前缀或清库。持久仓取自 `入站请求持久仓`、`独占区持久仓` 或 `告警持久仓` 时作用于持久对象本身；取自 `事务持久仓` 时读写属于本事务、随事务提交或回滚，这时不能 `清空持久仓`。单次调用是平台的一次原子存储操作；多次直接调用之间不构成事务，其间对象可能处理其他事件（除非在[持久独占](../持久独占/规范.汉语.md)区内）。

## 函数总表

| 函数 | 使用位置 | 说明 |
| --- | --- | --- |
| `入站请求持久仓` | 持久对象的网页请求 | 0.4.0 新增 |
| `事务持久仓` | 事务回调 | 0.4.0 新增 |
| `执行持久事务` | 持久对象 | 0.1.0；0.4.0 起以持久仓为第一个参数；失败抛可捕获异常 |
| `执行持久事务回调`（应用接口） | 应用实现 | 0.3.0 新增：参数为 `持久事务` 与参数文字，返回结果文字 |
| `读取持久事务键值`、`写入持久事务键值`、`删除持久事务键`、`列举持久事务键值`、`回滚持久事务` | 事务回调 | 0.3.0 起以 `持久事务` 为第一个参数 |
| `读取持久仓键值`、`写入持久仓键值`、`删除持久仓键`、`列举持久仓键值`、`清空持久仓` | 持久对象 | 0.2.0 新增；0.4.0 起以持久仓为第一个参数 |

`读取持久事务键值` 与 `读取持久仓键值` 返回存在标记和值的 JSON 文字：缺键返回阴与空字符串，已存 JSON null 返回阳与 `null`，二者不混淆。`删除持久事务键` 删除一个键（键原本不存在时无事发生）；`删除持久仓键` 返回阳表示键原先存在。`列举持久事务键值`、`列举持久仓键值` 接受选项 JSON 对象文字，返回 JSON 数组文字 `[[键,值],…]`，按键的 UTF-8 字节序排列（`reverse` 为真时逆序），**值是存入的 JSON 值本身，不是再编码的字符串**；事务内的列举能看到本事务尚未提交的写入与删除。`清空持久仓` 清空所属对象的全部持久数据（键值；SQLite 存储上还含 SQL 表，平台按兼容日期决定是否连告警一并清除）。

## 键、值与列举选项

键按 UTF-8 计须为 1 至 2048 字节。值是有效 JSON 文字，不超过 2 MiB，嵌套不超过 32 层，且不含宿主保留的单键对象——即只有一个成员且成员名为 `$句柄`、`$未定义`、`$大整数` 或 `$数字` 的对象（这些名字留给宿主与豫言交换特殊值，写入会被拒绝）；含其他成员的对象、以及这些名字作为字符串值出现都是允许的。数字沿用 JSON 数字语义，绝对值超过 2^53−1 的整数应用字符串表达。

列举选项是 JSON 对象文字，字段均可省略：`prefix`、`start`（含）、`startAfter`（不含）、`end`（不含）为字符串，空字符串视同未指定；`limit` 为不小于 1 的整数；`reverse` 为布尔。`start` 与 `startAfter` 不能同时给出；出现其他字段、类型不符、`limit` 小于 1 时失败。省略 `limit` 时返回全部匹配项，但结果 JSON 文字超过 8 MiB 时失败，应用应按 `limit` 加 `startAfter` 分页。

## 失败情形

| 情形 | 类别 |
| --- | --- |
| 键长度越界；值不是有效 JSON、超过 2 MiB、嵌套过深或含保留单键对象；列举选项非法；列举结果超过 8 MiB | 违规或超限：抛可捕获的豫言异常，消息为中文原因 |
| `执行持久事务` 中回调失败、结果无效或平台报错；用取自 `事务持久仓` 的持久仓调用 `执行持久事务` | 抛可捕获的豫言异常，写入已回滚 |
| 对非持久对象的请求调用 `入站请求持久仓`；用取自 `事务持久仓` 的持久仓调用 `清空持久仓` | 部署错误：抛可捕获的豫言异常 |
| 存储后端故障、读到无法写成 JSON 的既有值 | 平台故障：抛豫言异常，本次调用失败 |

## 跨宿主一致性

任何实现须保持：值以 JSON 语义往返（`读取` 得到的文字与 `写入` 的值在 JSON 意义上相等，不承诺字节相同）；缺键与 JSON null 可区分；列举的顺序、边界与 `limit` 语义如上；事务原子、事务期间其他事件排队、回滚后写入不可见；持久仓按取得的位置作用于对象本身或本事务；上述限额与失败类别。宿主可以选择不同的存储后端，但不得改变这些可观察结果。

## 一致性样例

设仓为空，`仓` 为 `入站请求持久仓 请求`。`写入持久仓键值 仓 "p:a" "1"`、`"p:b" "2"`、`"p:c" "3"` 后：`读取持久仓键值 仓 "p:a"` 得（阳，`1`）；`读取持久仓键值 仓 "无"` 得（阴，空）；`列举持久仓键值 仓 {"prefix":"p:","limit":2,"reverse":true}` 得 `[["p:c",3],["p:b",2]]`；`列举持久仓键值 仓 {"prefix":"","startAfter":"p:a"}` 得 `[["p:b",2],["p:c",3]]`。写入 `null` 后读取得（阳，`null`）。写入 `{` 或 `{"$句柄":"1"}` 或长度 2049 字节的键抛异常且不改仓。

在事务回调里依次 `删除持久事务键 事务 "p:a"`、`写入持久事务键值 事务 "p:d" "4"`，此时 `列举持久事务键值 事务 {"prefix":"p:"}` 得 `[["p:b",2],["p:c",3],["p:d",4]]`；回调以它为结果返回后，仓中同样如此。若在写入 `p:e` 之后调用 `回滚持久事务 事务`，则仓仍为提交前的样子；回调里经 `写入持久仓键值（事务持久仓 事务）` 写入的键也随回滚撤销。回调抛出未捕获异常或返回 `不是JSON` 时，`执行持久事务` 抛出以 `持久事务失败：` 开头的异常且仓不变。对非持久对象的 `fetch` 请求调用 `入站请求持久仓` 抛出 `当前事件不属于持久对象`。

## 边界

本包不提供 SQL、同步事务、批量读写、`allowConcurrency`、`noCache`、`allowUnconfirmed` 等平台选项，也不提供二进制或非 JSON 结构化克隆值；需要这些的应用另用适配库。首版借标准库字符串承载 JSON 值，应用可用豫言 `结森` 在自身逻辑中解析与构造。本包只用于已授权的持久仓，仓的名称与授权由宿主与部署配置决定。

后续版本的事项：事务回调的宿主墙钟时限（短于平台的 30 秒重置线，使超时表现为可捕获异常）。
