# 内容摘要接口规范 0.2.0

本包是豫言操作系统的内容摘要接口，规定内容摘要、成批摘要、目录摘要、文件系统版本号与自版本变更的行为。接口只有类型与签名，实现见库「籍摘」（目录 `库/籍摘`）：原生宿主、豫言操作系统、壳命令与测试都直接用这一份纯豫言实现，不另设适配包。

## 摘要算法

内容摘要一律用**稽古的对象号**（与 Git 相同的对象标识）：把文件内容编码成 `blob <字节数>\0<内容>`，对它计算 SHA-1，输出恰好 40 个小写十六进制 ASCII 字符。这就是 `git hash-object` 对同一文件给出的对象号。摘要只由文件内容的字节决定：内容相同，摘要相同；与路径、修改时间、权限、文件号无关。空文件的摘要是 `e69de29bb2d1d6434b8b29ae775ad8c2e48c5391`。

目录摘要用**稽古的树对象号**（与 Git 相同的 tree 对象）。把目录下的普通文件按仓的暂存区（索引）建树，逐层编码成树对象：每一项是模式、名字、二十字节对象号；对编码后的树内容计算 SHA-1，输出 40 位小写十六进制。空目录的树号是 `4b825dc642cb6eb9a060e54bf8d69288fbee4904`。仓里只计暂存区跟踪的普通文件（与 `git write-tree` 的结果一致）；工作区里改过的文件按现内容重算对象号后再建树。仓外目录递归扫普通文件，用同一套对象号与树编码建树，深度至多 64 层。

路径的解析与「豫章」的「阅」一致：相对路径按宿主所记的当前目录解析，绝对路径原样。文件不存在、不是普通文件或读不到时，摘要为空文。目录不存在或不是目录时，目录摘要为空文。

## 成批摘要

`取内容摘要们` 按输入次序返回同长度的摘要列，每一项与 `取内容摘要` 同形同义；重复的路径各答一次，空组返回空组。这一组路径在同一次接口调用里办完：索引只读一次、写一次；命中的直接答旧对象号，未命中的按现内容重算。执行器侧的成批读接口留待后续版本。

## 构建索引

库「籍摘」不写仓的 `.git/index`。仓里跟踪的文件用**稽古的暂存区格式**（`目卷` 的读写）另存一份「构建索引」在共享缓存目录：`<宿根>/豫构缓存-<户名>/籍摘/仓/<仓键>/index`。开头可从仓的 `.git/index` 只读地取种子；读写都复用稽古的索引代码，经 `index.lock` 改名换上。仓外文件另存一份同格式索引，路径记绝对径去掉开头的斜线：`<宿根>/豫构缓存-<户名>/籍摘/仓外/index`。

索引每项记路径、对象号、模式、大小与修改时间；取摘要时先比索引里的签名：大小与修改时间未变就直接取旧对象号（命中），变了才读内容重算（未中）。同一秒里改过的边角沿用稽古的判断：修改时间相同且早于索引写出时刻就当未变；否则读内容算对象号再比。

## 版本号与计数

`问版本号` 返回从零开始的整数，单调递增。版本号与命中、未中计数存在 `<宿根>/豫构缓存-<户名>/籍摘/全局/计。数据。豫`，跨进程与重启保留。壳命令的文件写入、续写、删除、改名成功后调用 `记写入`（带路径）使版本号加一并记一条变更；摘要未命中重算、目录建树时签名核对发现已记录路径变化时也加一并记变更。新路径第一次入索引不加。版本号只增不减。

## 自版本变更

`自版本变更` 接收一个版本号，返回自该版本以来新增、修改、改名、删除的路径，按路径排序并去重。变更日志按（版本号、路径）记在 `<宿根>/豫构缓存-<户名>/籍摘/全局/变更。数据。豫`：壳命令的写入、摘要未命中重算、目录建树时的签名核对都记一条。日志只留最近 4096 条；截短后所问版本早于首条保留版本时答 `须全量重扫`，调用者不得把它当作空表。

## 各宿主

原生宿主（林檎、林纳、轩窗）与豫言操作系统（裸机）共用库「籍摘」这一份纯豫言实现，读内容、算对象号与建树都走同一组文件接口，结果逐字节相同。浏览器宿主没有可持久保存的真实文件系统，本版答空文与零版本；浏览器支持留待后续版本。诺驿与云工不是支持的目标。

## 一致性样例

| 情境 | 必须观察到 |
| --- | --- |
| 文件 `甲` 内容为 `abc` | 对象号为 `f2ba8f84ab5c1bce84a7b441cb1959cfc7093b7f`，两次查询相同 |
| 同样内容写到另一路径 | 对象号与 `甲` 相同 |
| 文件不存在 | 摘要为空文，`在` 为阴 |
| 只改修改时间、不改内容（用同样内容覆写） | 对象号不变 |
| 目录里新增或删除一个文件 | 树号改变；名字、模式、子树对象号都不变时树号不变 |
| 空目录 | 树号为 `4b825dc642cb6eb9a060e54bf8d69288fbee4904` |
| 同一组路径取两次 | 第二次全部命中，`未中` 不增，对象号与第一次相同 |
| 写入一个已记录的文件后再问版本 | 版本号至少增加一 |
| 索引存盘后清掉进程内的索引、重新读盘 | 版本号、条目、命中与未中计数都还在 |
| `自版本变更` 于任意版本 | 得 `变更未备`，不得当作空列 |

## 边界

本包不规定构建索引的并发写锁；同一份索引的并发写留待后续版本（当前按最后写入者胜，读者可能读到上一版）。不提供删除索引、压缩索引或按路径失效的单条命令。不保证外部写入在发生的那一刻就使版本号增加，只保证下一次核算时计入。不做文件内容的加密、去重或按内容寻址的存储。目录摘要只计暂存区跟踪的普通文件，不计未跟踪文件与子模块；仓外的目录摘要递归扫普通文件。
