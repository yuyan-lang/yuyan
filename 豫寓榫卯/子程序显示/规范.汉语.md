# 子程序显示接口 0.2.0

本包是桥接包，连接[子程序](../子程序/规范.汉语.md)与[显示](../显示/规范.汉语.md)两个接口：父程序启动子程序时转授一块显示面，子程序照常调用显示接口，宿主把它提交的画面交给父程序，把父程序送来的输入事件与尺寸交给它。平铺桌面（提案 00014）的外部程序格用它把图形程序的画面放进格子，子程序本身不必改写。

## 函数

| 函数 | 作用 |
| --- | --- |
| `启动带显示面的子程序(程序, 参数, 输入, 环境, 显示面名, 宽, 高, 像素比)` | 前四个参数同子程序接口的 `遣使`；另把名为“显示面名”的一块显示面转授给子程序，初始尺寸为宽、高（物理像素），像素比如给。结果同 `遣使`：`子程序已启动` 携带句柄，或 `子程序启动失败` 携带系统错误 |
| `取子程序画面(句柄)` | 交出子程序最新的整块画布与自上次取出以来的变化区域，见下文 |
| `送子程序输入事件(句柄, 事件)` | 把一个显示接口的输入事件排进子程序的事件队列 |
| `设置子程序显示面尺寸(句柄, 宽, 高, 像素比)` | 改子程序显示面的尺寸与像素比 |

句柄与子程序接口共用：`姑收使`、`取使者出`、`召回`、`问使者资` 照旧可用。收取完成后句柄失效，本包各函数返回句柄无效。

两个整数结果的函数：零成功、八句柄无效、二十九宿主失败、五十八暂不支持。

## 子程序一侧

子程序照常使用显示接口：

- 以转授的名字 `取已授映面` 成功，其他名字返回 `未获授权`。
- `读映面尺寸` 与 `读映面像素比` 交出父程序最近设的值。
- `呈像素画面` 与 `呈像素画面区域` 把画布交给宿主保存；宽高与当前尺寸不符时返回 `资源暂不可用`，同显示规范。
- `待入事` 与 `待入事限时` 按顺序交付父程序送来的事件。父程序改了尺寸，先交付 `显示尺寸变化`，子程序重读尺寸后重画整帧。
- 父程序终止子程序、关闭它所在的格子或归还父程序自己的显示面时，正在等待的子程序收到 `显示面已关闭`。
- `设指形状` 与 `设文字入区域` 照常返回。
- `归还映面` 结束本次显示会话，父程序随后取画面得 `子程序未取显示面`。

## 父程序一侧

- `取使者画面`：子程序还没取得显示面时得 `子程序未取显示面`；取得后没有新画面得 `子程序画面未变`；有新画面得 `子程序画面已更新`，携带画布宽、画布高、整块画布字节（RGBA8，同显示规范）与自上次取出以来变化区域的左、上、宽、高（几次提交取外包矩形）。子程序结束后、收取完成之前仍可取它的最后一帧。失败得 `子程序画面失败` 携带系统错误，句柄无效时为 `资源已失效`。
- `送使者入事`：坐标是子程序显示面上的物理像素，由父程序从自己的坐标换算。事件按送达顺序排队；队列满时丢掉最早的事件，相邻的两次指针移动合并为一次。
- `设使者映面尺寸`：宽高须为正，否则返回二十八（输入无效）；子程序随后收到 `显示尺寸变化`，在它按新尺寸提交整帧之前，`取使者画面` 交出的仍是旧尺寸的画布。

## 平台

- **裸机（AMD64、ARM64）**：客体二号经带类型导入直接实现（原语 182 启动、183 取画面、184 送事件、185 设尺寸）。父程序须是初始任务（只有它能读写别的任务的内存，平铺桌面因此在开机壳的任务里运行）；子程序是装载任务起的动态任务，AMD64 内存不到 256 MiB 时起不成，返回 `资源不存在`。子程序的显示请求经内核邮箱交给初始任务，画面只传变化区域所在的行；像素比在子程序一侧恒为 1。`召回` 对带显示面起的子程序是关闭它的显示面：正在等待的立刻收到 `显示面已关闭`，以后再等也是它，程序随后自行退出。协议见 `豫言操作系统/裸机/文档/客体二号.汉语.md` 的“子程序显示代办”。
- **原生 macOS**：执行器内的管道代办（原语 182–185）。父执行器起子进程时多建两条管道（子程序写画面、父程序写事件），在应用参数前加宿主选项 `--显示面代办 名=宽x高@画号,事号,比`（比是像素比乘六十四）、父程序的各项子程序授权（`--授权子程序 名=绝对路径`，子程序能起父程序获授的程序）与 `--`；子程序的执行器据此把显示原语改走管道：提交时把区域所在的整行写进画面管，等待时从事件管读事件记录（同底层显示的事件记录，尺寸变化带新宽、高与像素比），尺寸与像素比在本地答父程序最近设的值。父程序取画面时不阻塞地读画面管，提交的行直接读进常驻画布。事件管满时丢掉新送的事件；`召回` 直接结束子进程；事件管读到尾时子程序先收到一次 `显示面已关闭`。协议见 `豫言操作系统/裸机/文档/客体二号.汉语.md` 的“子程序显示代办”。
- **原生 Linux**：返回暂不支持，同下。
- **网页行在**（提案 00043）：浏览器工作线程里的豫寓实现（`豫言操作系统/宿主/浏览器/构建/豫寓.mjs`）经同步提问交主线程的行在代管。子程序是进程表里的一个任务；它提交的画面存成整块画布与变化区域，父程序送的事件排进它的显示面事件队列，请求与来信也由行在存放。父程序结束时子程序的显示面随之关闭：正在等待的立刻收到 `显示面已关闭`，以后再等也是它，程序随后自行退出。`召回` 直接结束子程序。
- **诺驿、浏览器原壳**：适配返回暂不支持：`遣使附映面` 得 `子程序启动失败` 携带 `资源暂不可用`，`取使者画面` 得 `子程序画面失败` 携带 `资源暂不可用`，另两个函数返回五十八。

## 外壳请求与来信（0.2.0）

0.2.0 增加子程序与父程序（外壳）之间的短消息，用于[提案 00015](../../提案/00015-桌面程序独立成任务.汉语.md)：桌面上的每个窗口是一个独立任务，打开文件、运行程序、设标签标题这类要外壳办的事经请求交给外壳，外壳经来信叫程序跳到某行或关闭。消息是字节串，内容由双方约定。

- `请外壳办(请求)`：子程序一侧，把一条请求交给转授显示面给它的父程序；结果零为成功，五十八为暂不支持（不是带显示面起的或宿主不支持）。
- `取外壳来信()`：子程序一侧，取父程序送来的下一封信；没有信得空字节串。
- `取外壳请求(句柄)`：父程序一侧，取这个子程序的下一条请求；没有请求得空字节串。
- `送程序来信(句柄, 信)`：父程序一侧，给这个子程序送一封信；结果零为成功，八为句柄无效或不是带显示面起的，五十八为暂不支持。

裸机由初始任务在子表项里替每个带显示面起的子程序存请求与来信（显示代办操作 8 交请求、9 取来信）。它启动的交互孙任务的输入也经显示代办（操作 10 至 12）由初始任务转交（见子程序 0.8.0）。网页行在由行在替带显示面起的子程序存请求与来信。macOS、节点与浏览器原壳返回五十八与空字节串，这些宿主上的桌面程序以嵌入方式在外壳里运行。
