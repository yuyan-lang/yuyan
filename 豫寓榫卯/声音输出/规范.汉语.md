# 声音输出接口规范 0.1.0

本包是已授权的声音输出流，供设计作品播放器等程序播放混好的样本（提案 00018 第十节“新接口「豫寓鸣」”）。应用依赖本包即要求宿主实现它，打开流还须宿主授权“声音输出”。

- `辟声出` 按采样率、声道数与块大小打开一条输出流。采样率与声道数须为正（宿主至少支持 48000 赫与一、二声道），块大小是每次写入的建议帧数，宿主可以忽略。未获授权返回 `未获授权`；暂时没有输出设备返回 `资源暂不可用`；参数不合返回 `输入无效`。宿主可以按自己的设备采样率重采样，`已播帧数` 仍按打开时的采样率计。
- `写声样本` 把一块样本排进播放队列：交错的十六位有符号小端整数，每帧依次是各声道一个样本，字节数须是“声道数×2”的整数倍，否则返回 `输入无效`。宿主可以限制排队的总量，超出时返回 `资源配额已尽`，应用等 `已播帧数` 增加后再写。流已关闭返回 `资源已失效`。
- `已播帧数` 是播放的主时钟：从打开起已经送到设备的帧数，单调不减。画面按这个时钟取帧，跳转时应用关闭旧流（或继续写新位置的样本）并重新计时。流失效返回负一。
- `声出延迟` 是已写入而还没播出的帧数加上设备延迟，以帧计。流失效返回负一。
- `阖声出` 停止播放、丢弃未播出的样本，流随即失效；再次关闭返回 `资源已失效`。

授权：宿主选项 `--授权声音输出` 授予本次运行打开声音输出的权利，写法与显示面授权一致，写在程序参数之前。

实现：浏览器用 Web Audio，按写入的先后把每块样本排在上一块之后播放；模拟宿主（`豫言操作系统/适配/声音输出模拟`）不发声，写入即算播出，测试可让它拒绝授权；诺驿暂用模拟宿主的实现。豫言操作系统（裸机）由执行器直接实现（2026-10-13，原语 250–254，经内核声卡表交给声卡驱动，现有虚拟声卡、高清音频、通用串行声卡即 USB 音频类）：全系统一条输出流，再打开就顶掉旧流；支持 48000 赫、一或两个声道，写入时放不下就整块退回（资源配额已尽），缓冲约三秒；声卡的情况用设备接口的 `问声卡` 查。macOS（Core Audio 或 AVAudioEngine）、Linux（ALSA）、诺驿（调用豫言自己的原生库）的实现，裸机的英特尔高清音频、授权核对与重采样，列为后续版本的事项。

网页行在（浏览器里的系统实例，提案 00043）中，工作线程（跑豫言任务）把样本写进一条共享内存的环形缓冲，音频线程里的 AudioWorklet 工作件读出来播放：缓冲空了工作件补静音，放不下一整块就整块退回（资源配额已尽）；采样率、声道按打开时的请求，浏览器采样率不同就在工作件里按线性插值重采样，`已播帧数` 仍按打开时的采样率计。控制字（写位置、读位置、设备延迟）在同一块共享内存里，`已播帧数` 与 `声出延迟` 直接读它。浏览器的自动播放规定要求页面先有用户手势，页面在第一次按键或点击时恢复 AudioContext。浏览器构建宿主没有声音外务，那里的 `辟声出` 得 `资源暂不可用`。
