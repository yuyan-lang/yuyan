# 日志接口规范 0.1.0

本包让应用向平台日志按三个级别各写一条文字：`记录错误日志` 对应 `console.error`，`记录警告日志` 对应 `console.warn`，`记录信息日志` 对应 `console.info`。每次调用写出一条日志，文字原样交给平台，换行、引号、控制字符都不改写，也不添加时间、级别或请求标识（这些由平台附加）。**单条日志不超过 8 KiB，即 8192 个 UTF-8 字节**：更长的文字在字符边界截断，末尾附省略标记 `…（已截断）`，截断后的总长（含标记）不超过 8192 字节，不会把一个字符切成两半；不超过上限的文字逐字节原样写出。空字符串是合法的日志文字。三个函数没有返回值，也不因文字内容失败；平台可以采样、限流或丢弃日志，应用不得依据日志是否出现来改变业务行为。

**不得把令牌、口令、密钥、邮箱地址等敏感信息写进日志，这是应用的责任。** 本包不检测也不脱敏：日志一旦写出便脱离应用控制，平台和运维人员都可能读到。写日志前应自行省略这些字段，或改写成不可还原的摘要。

## 一致性样例

| 输入 | 必须观察到 |
| --- | --- |
| 三个函数各写一条 `你好` | 平台分别收到一条 error、warn、info 日志，内容都是 `你好`，没有其他级别的日志 |
| 恰好 8192 字节的 ASCII 文字 | 原样写出，一次调用恰好一条 |
| 8193 字节的 ASCII 文字 | 写出的文字不超过 8192 字节，以 `…（已截断）` 结尾，其前部是原文的前缀 |
| 9000 字节的三字节汉字 | 只保留整字，写出的文字是有效 UTF-8，不超过 8192 字节 |
| 含换行、制表、双引号、反斜线的文字 | 原样写出 |
| 空字符串 | 写出一条空日志 |

## 边界

本包不提供 debug、log 级别，不提供结构化字段、采样、检索或脱敏，也不承诺日志一定被保存。截断标记固定为 `…（已截断）`；这里的“字符”指一个 Unicode 码点（运行时的通字符）：截断只发生在码点之间，绝不产生非法 UTF-8，但可能把由多个码点组成的可见字符（带组合记号的字母、emoji 序列等）拆开。云工适配把三个函数映射到 Worker 的 `console.error`、`console.warn`、`console.info`；其他宿主可以写入等价的分级日志，只要级别、单条上限和截断规则一致。
