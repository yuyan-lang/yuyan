# 本地模型豫言编程指南

这份指南供全新的本地编程代理独立使用。接到算法题时，先读完整份文件，再编写豫言源码。目标是首次提交就通过类型检查和题目测试。若题目接口、输入输出格式或可用工作目录未给出，应从任务说明确定，不擅自把 LeetCode 的函数题改成读标准输入的程序。

## 1. 工作顺序

1. 明确题目给出的输入、输出、边界和规模。选择满足**已给规模**的最短正确算法；不要为了想象中的极端输入改写成更复杂的数据结构。
2. 优先使用本指南中已验证的语法和标准库接口；不要猜英文函数名，也不要在确定一种正确算法后反复切换方案。
3. 写出带完整类型签名的函数。递归函数的签名与同名定义必须紧邻；算法需要多层扫描时，每层用一个职责明确的辅助函数。写完后对照每个辅助函数的签名，核对**所有**调用的实参数量，尤其从 `「解」` 发起的首次调用；初始累计值或初始权值也必须显式传入。
4. 若能调用编译器，在交付前做类型检查和边界测试。若当前请求**没有工具**，只依据本指南做一次有限静态核对，然后立即在本次响应中输出完整源码；不要等待编译器、续答或下一条消息。
5. 直接按已验证的表达式模板构造程序。某个调用若嵌套过深，就先给中间值命名；不要在思考中反复数括号或罗列假设的解析错误。选定实现后提交源码。

若在思考中已形成一份完整源码，最终答案必须**逐字复制那一份**，不可重新口述、改写标点或只摘录开头。特别是 `『]』`、`『}』` 这类字符串，不得在最终答案里换成 ASCII 引号、问号或说明文字。复制完毕后检查最后一行确实以 `。` 结束。

本地模型的验收以**单次请求的首次完整源码**为准。空答、只有思考、超出输出额度以及需要续答才给出源码，都算失败。这里的源码应是本次请求可直接交给编译器的内容，不应包含 Markdown 围栏或解释文字。

验收请求最多等待 900 秒。得到一份完整候选源码后，只作**一次**必要的类型、括号和边界核对，随即交付；不要在思考中把全篇源码反复抄写、推翻或重新论证。即使思考里已有正确代码，若到时仍未发出最终源码，也算失败。

## 2. 字符、字面量和文件形式

豫言使用中文全角标点。名称用 `「名称」`，字符串用 `『文本』`，语句以 `。` 结束，函数实参由 `于` 引入，括号是 `（ ）`，列表字面量用 `【 】` 和中文逗号 `，`。ASCII `()[]{},;` 不能代替这些字符。注释写作 `「：注释内容：」`。字符串中的换行转义是 `「：换行：」`，不是 `\n`。

数字也必须写在名称括号里：`「零」`、`「一」`、`「二三」`、`「123」`。汉字数字逐位读取，所以 `「一二三」` 是 123；`「十」` 和 `「负一」` 都不是数字。负一写作 `「减」于「零」于「一」`。布尔值是 `「阳」` 和 `「阴」`，单位值是 `「元」`。原始字符串值可以写 `『abc』`。

`」` 只用于关闭 `「名称」`，绝不用于关闭一般表达式。特别是 `于（「减」于「数目」于「一」）」 多了一个 `」`；正确结尾是 `于（「减」于「数目」于「一」）`。全角圆括号表达式闭合后，直接接 `也。` 或后续连接词，不再补 `」`。

文件顶层有三类常用语句：

```yuyan
寻观「标准库」之书。
「答案」乃化「整数」而「整数」也。
「答案」者会「数」而「加」于「数」于「一」也。
「打印行」于（「整数表示」于（「答案」于「四一」））。
```

`寻观` 导入并打开模块；`乃` 声明类型；紧随的同名 `者` 给出定义。这个相邻的签名与定义让顶层递归可用。没有签名的顶层定义可以用于简单值，但复杂函数和递归函数一律写签名。顶层裸表达式会在程序初始化时执行。

## 3. 类型与表达式

常用类型是 `「整数」`、`「爻」`、`「字符串」`、`「有」`、`「列」于「整数」`、`「数组引用类」于「整数」`。函数类型 `化「整数」而化「整数」而「整数」` 表示两个整数参数，返回整数；不是自动柯里化的函数。传参必须完整，不能先传一个参数再拿到函数。成对值的类型写 `「整数」合「整数」`，值写 `「一」与「二」`；静态取第一个、第二个字段分别为 `「对」中「零」`、`「对」中「一」`，索引不能是变量。

**元组字段读取若是 `鉴` 的分支结果，必须括成完整表达式。**写 `或有（「缀」于「头」于「尾」）则（「头」中「零」）也。`；直接写 `则「头」中「零」也。` 可能使 `中` 与下一分支的 `或` 发生优先级冲突。这一写法已用整数对列表类型检查并运行。

```yuyan
「两数和」乃化「整数」而化「整数」而「整数」也。
「两数和」者会「甲」而会「乙」而「加」于「甲」于「乙」也。

「大者」乃化「整数」而化「整数」而「整数」也。
「大者」者会「甲」而会「乙」而
  若「大于」于「甲」于「乙」则「甲」否则「乙」也。
```

局部绑定写 `虑「名」者 值 而 表达式`。分支写 `若 条件 则 真值 否则 假值`，两支必须类型相容。多步副作用可以用 `；` 顺序执行，用括号明确范围。表达式按值求值，实参从左到右求值；`「且」` 不保证短路，应嵌套 `若` 实现短路。

一个 `若` 的 `则` 分支即使包含多个 `虑 ... 而 ...`，也**不能**在 `否则` 前加 `也。`；`也。` 只在整个函数定义的末尾出现一次。正确结构为 `若「条件」则 虑「暂」者「甲」而「暂」 否则「乙」也。`。写成 `则 ... 也。否则 ...` 会提前结束函数，编译器报“无法解析”。这一规则已由真实源码删除多余的 `也。` 后通过类型检查及隐藏用例验证。

泛型函数显式传类型时用 `授以`，随后用 `于` 传普通值，例如 `「罄」授以「整数」`、`「缀」授以「整数」于「一」于（「罄」授以「整数」）`。若编译器报“隐式参数无法完全确定”，首先补全 `授以`，尤其是空列表、数字字面量和泛型函数调用。`「列」【「一」，「二」】` 是列表语法糖，但推断不稳时改用显式 `缀`、`罄`。

**把带 `授以` 的表达式传给另一个函数时，必须先用全角圆括号包起来。**例如 `「处理」于（「罄」授以「整数」）` 正确；`「处理」于「罄」授以「整数」` 会报 `未定义优先级关系：〇于〇 与 〇授以〇`。嵌套调用也应这样写：`「反转」授以「整数」于（「遍历」于「输入」于（「罄」授以「整数」））`。不要期待空白或换行改变结合顺序。

**避免在一个顶层输出语句里嵌套三层以上调用。**先用 `「样本」者 ... 也。`、`「结果」者 ... 也。` 给中间值命名，再写 `「打印行」于（「整数表示」于「结果」）。`。嵌套难以把握时，继续拆出中间值，不要花大量思考 token 反复数右括号。换行和缩进不会自动闭合括号。

多参数调用中，**作为某一个实参的函数调用必须加全角括号，或先绑定成一个值**。例如递归调用的第三参数要计算新最佳值时，采用经类型检查的写法：

```yuyan
虑「新最佳」者「大者」于「续」于「最佳」而
「推进」于「尾」于「续」于「新最佳」
```

若直接写 `「推进」于「尾」于「续」于「大者」于「续」于「最佳」`，编译器会把后半段也看作 `推进` 的额外参数；换行、缩进、函数名本身都不会自动分组。

## 4. 递归、匹配、列表

列表是持久单向链表，不支持 `list[i]` 或原地追加。空列表是 `「罄」授以「整数」`；非空列表可写 `「缀」授以「整数」于「头」于「尾」`。模式匹配：

```yuyan
「求和」乃化（「列」于「整数」）而「整数」也。
「求和」者会「数列」而鉴「数列」而
  有「罄」则「零」
  或有（「缀」于「头」于「尾」）则「加」于「头」于（「求和」于「尾」）也。
```

`鉴` 的分支只能按构造器写 `有 ... 则 ...`、`或有 ... 则 ...`；**不能**在 `鉴` 中用 `否则` 代替非空分支。`否则` 只属于 `若`。判断列表是否为空时，已验证的完整写法是：

```yuyan
「列为空」乃化（「列」于「字符串」）而「爻」也。
「列为空」者会「字符列」而鉴「字符列」而
  有「罄」则「阳」
  或有（「缀」于「头」于「尾」）则「阴」也。
```

两个列表同时递归时，直接在第一个非空分支内匹配第二个列表。以下模板已通过类型检查和运行；按题意替换两处空列表结果以及非空分支的计算即可：

```yuyan
「逐对相加」乃化（「列」于「整数」）而化（「列」于「整数」）而（「列」于「整数」）也。
「逐对相加」者会「甲」而会「乙」而鉴「甲」而
  有「罄」则（「罄」授以「整数」）
  或有（「缀」于「甲首」于「甲尾」）则鉴「乙」而
    有「罄」则（「罄」授以「整数」）
    或有（「缀」于「乙首」于「乙尾」）则
      「缀」授以「整数」于（「加」于「甲首」于「乙首」）于（「逐对相加」于「甲尾」于「乙尾」）也。
```

这段示例需接在 `寻观「标准库」之书。` 后。只有题目明确需要动态下标读写时才把列表换成数组；双列表顺序扫描通常无需构造“取首项”“取余列”等额外函数。

匹配分支从上至下选择。不要假设编译器能证明分支穷尽。题目未给出特别大的输入规模时，优先用上面这种直接递归，它的语法最简单；只有规模明确要求时才改成尾递归累积并 `反转`。不要仅因担心假设中的栈深度，把两个列表的合并改写为可变数组。局部尾递归函数模板：

扫描题若每个输出依赖输入位置的**左侧与右侧**，要分别维护两个方向的信息并组合；仅从右向左递归得到的后缀结果，不能直接当成左右两侧的合计。频次或成对消除题如未要求线性时间，先考虑已知的列表扫描、计数与比较；不要为避开普通扫描而临时发明按位运算或整数编码。

```yuyan
递归虑「遍历」其化（「列」于「整数」）而化「整数」而「整数」者
  会「余」而会「累计」而鉴「余」而
    有「罄」则「累计」
    或有（「缀」于「头」于「尾」）则「遍历」于「尾」于（「加」于「累计」于「头」）
而「遍历」于「输入」于「零」
```

`递归虑` 后的类型必须完整，定义体及后续表达式均可引用该名称。`循 x 以 e` 是过期写法，**不会**建立递归绑定，禁止用作递归。

尾递归若携带 `累计`、`最佳`、`答案` 等状态，遇到 `罄` 时须返回**对应状态**，例如 `有「罄」则「最佳」`；误写成 `有「罄」则「零」` 会把前面所有计算结果丢掉。把单元素、全负数等最短输入代入终止分支核对一次。

### 自定义树与其他代数数据类型

树、链表节点、枚举结果可以用 `立` 声明类型和构造器；构造器不是普通 `者` 函数。先声明类型，再声明构造器，随后用 `鉴` 按构造器匹配。下面的完整程序已通过类型检查与运行：

```yuyan
寻观「标准库」之书。
「树」立「元类型」也。
「叶」立「树」也。
「枝」立化「树」而化「树」而「树」也。
「叶数」乃化「树」而「整数」也。
「叶数」者会「树值」而鉴「树值」而
  有「叶」则「一」
  或有（「枝」于「左」于「右」）则
    「加」于（「叶数」于「左」）于（「叶数」于「右」）也。
「打印行」于（「整数表示」于（「叶数」于（「枝」于「叶」于「叶」）））。
```

输出为 `2`。真实树题按题目接口增添节点值和空节点构造器；例如 `「空树」立「树」也。` 与 `「节点」立化「整数」而化「树」而化「树」而「树」也。`。自定义类型及构造器必须在使用它们的函数之前声明。函数模式可加 `或有「其他」则 ...` 作兜底，但不能用兜底掩盖本应覆盖的构造器。

## 5. 算法题常用标准库

只需导入 `寻观「标准库」之书。` 即可使用以下导出的名称。函数调用统一写 `「函数」于「参数一」于「参数二」`；泛型推断不清时加 `授以「类型」`。不要把中文名称翻译成英文 API。

| 类型或用途 | 已知接口及参数顺序 |
| --- | --- |
| 整数 | `加(a,b)`、`减(a,b)`、`乘(a,b)`、`除以(a,b)`、`等(a,b)`、`小于(a,b)`、`大于(a,b)`、`整数表示(a)`；除法向零截断 |
| 布尔 | `非(x)`、`且(a,b)`、`或者(a,b)`；需要短路时用 `若` |
| 列表 | `长度(列)`、`反转(列)`、`附加(列一,列二)`、`第N个(索引,列)`；随机读取一般为线性时间 |
| 高阶列表 | `态射(列,函数)`、`滤(谓词,列)`、`从左折叠(组合,初值,列)`、`从右折叠(组合,初值,列)`；左折叠的组合函数先接元素、后接累计值 |
| 字符串 | `串转通字符(字符串)` 得到字符串字符列表；`通字符转串(字符列表)`；`串相等(甲,乙)`；`甲 附 乙` 拼接字符串 |
| 可变数组 | `新数组引用` 先接初值后接长度；`读数组引用` 先接数组后接从零开始的索引；`写数组引用` 接数组、索引、值；下标需自行检查 |
| 字符串键字典 | `空串典`、`串典插入(典,键,值)`、`串典查找(典,键)`；它是列表实现，查找为线性时间；整数键应另作表示或选择其他结构 |
| 输出 | `打印行(字符串)`；整数先用 `整数表示` 转字符串 |

泛型数组示例：`「新数组引用」授以「整数」于「零」于「一零」`。不要读取尚未初始化的数组。需要大量按下标更新时使用数组引用；需要顺序扫描和构造时使用列表。字符串的“字符”是单字符字符串而非 C `char`。

### 单字符字符串与括号字符

`串转通字符` 返回的每个元素仍是 `「字符串」`。比较一个字符与标点时，标点必须直接写在 `『』` 内；`『[』`、`『{』`、`『(』` 都是完整合法的字符串字面量。不要把它们改成 ASCII 引号，也不要在豫言源码里写 `then`、`EQUALITY` 之类的英文占位词。以下分类函数已通过类型检查和运行：

```yuyan
「是左括号」乃化「字符串」而「爻」也。
「是左括号」者会「字符」而
  虑「圆」者「串相等」于「字符」于『(』而
  虑「方」者「串相等」于「字符」于『[』而
  虑「花」者「串相等」于「字符」于『{』而
  「或者」于「圆」于（「或者」于「方」于「花」）也。
```

开闭括号配对也不要临时改写为 ASCII 引号。以下完整函数已编译运行：

```yuyan
「右左相合」乃化「字符串」而化「字符串」而「爻」也。
「右左相合」者会「右」而会「左」而
  虑「圆」者「且」于（「串相等」于「右」于『)』）于（「串相等」于「左」于『(』）而
  虑「方」者「且」于（「串相等」于「右」于『]』）于（「串相等」于「左」于『[』）而
  虑「花」者「且」于（「串相等」于「右」于『}』）于（「串相等」于「左」于『{』）而
  「或者」于「圆」于（「或者」于「方」于「花」）也。
```

把列表当栈时，栈顶放在表头：入栈用 `「缀」授以「字符串」于「字符」于「栈」`；出栈先用 `鉴「栈」` 匹配 `罄` 或 `缀`，在非空分支读取头与尾。不要对空栈直接取头。字符判断和栈操作分成辅助函数，避免把多层 `若` 写成一行。

### 小数题的独立导入

小数字面量如 `「1.5」`，类型为 `「小数」`。整数与小数模块都定义 `加` 等名称；小数题最好明确导入所需模块，避免按导入顺序选错同名函数。子模块自己的 `寻观` 不自动把其导入的类型重新导出，因此同时导入内建类型。以下程序已编译运行，输出 `4.000000`：

```yuyan
寻观「标准库」之「语言核心」之「内建类型」之书。
寻观「标准库」之「数据结构」之「小数操作」之书。
寻观「标准库」之「输入输出」之「笔」之书。
「和」乃「小数」也。
「和」者「加」于「1.5」于「2.5」也。
「打印行」于（「小数表示」于「和」）。
```

小数运行时通常按双精度浮点处理；不要用浮点相等代替题目规定的容差比较。实际显示格式通常保留六位小数。

### 可选值与无解情况

算法题可能要求“没有答案”。用类型 `「或可有」于「整数」` 或 `「或可有」于（「整数」合「整数」）`，有值用 `「可有」授以「整数」于「值」`，无值用 `「可无」授以「整数」`。模式匹配时先处理有值，再处理无值：

```yuyan
「取值或零」乃化（「或可有」于「整数」）而「整数」也。
「取值或零」者会「可选」而鉴「可选」而
  有（「可有」于「数」）则「数」
  或有「可无」则「零」也。
```

不要用未经检查的 `获取可有内容` 处理无解输入；对 `可无` 调用会报运行时事故。

返回两个下标时，可用 `「或可有」于（「整数」合「整数」）`。有解值 `「可有」授以（「整数」合「整数」）于（「左下标」与「右下标」）`，无解值 `「可无」授以（「整数」合「整数」）`。取出有解值后若要在 `鉴` 分支中投影元组，给投影表达式加括号：`有（「可有」于「双数」）则（「双数」中「零」）或有「可无」则「零」`；否则 `中` 与分支的 `或` 可能出现优先级关系错误。

### 两层列表扫描模板

需要寻找两个不同位置时，先扫描当前元素后面的尾列表，再把外层索引加一。下面的两数之和实现已通过类型检查和运行，展示了列表递归、可选下标与可选整数对的最小组合；别用反转的已见列表和哨兵下标把这个模式复杂化。

```yuyan
寻观「标准库」之书。
「查找补数」乃化（「列」于「整数」）而化「整数」而化「整数」而（「或可有」于「整数」）也。
「查找补数」者会「余」而会「目标」而会「下标」而鉴「余」而
  有「罄」则（「可无」授以「整数」）
  或有（「缀」于「头」于「尾」）则
    若「等」于「头」于「目标」则（「可有」授以「整数」于「下标」）
    否则「查找补数」于「尾」于「目标」于（「加」于「下标」于「一」）也。
「两数之和自」乃化（「列」于「整数」）而化「整数」而化「整数」而（「或可有」于（「整数」合「整数」））也。
「两数之和自」者会「余」而会「目标」而会「下标」而鉴「余」而
  有「罄」则（「可无」授以（「整数」合「整数」））
  或有（「缀」于「头」于「尾」）则
    虑「找到」者「查找补数」于「尾」于（「减」于「目标」于「头」）于（「加」于「下标」于「一」）而
    鉴「找到」而
      有（「可有」于「后标」）则（「可有」授以（「整数」合「整数」）于（「下标」与「后标」））
      或有「可无」则「两数之和自」于「尾」于「目标」于（「加」于「下标」于「一」）也。
「两数之和」乃化（「列」于「整数」）而化「整数」而（「或可有」于（「整数」合「整数」））也。
「两数之和」者会「数列」而会「目标」而「两数之和自」于「数列」于「目标」于「零」也。
```

这个模板为二次时间复杂度；题目输入若很大，需重新选数据结构，不能因代码易写就忽略复杂度。顶层 `「列」【…】` 样本应紧邻写出明确的 `乃「列」于「整数」也。` 签名，否则数字元素的泛型类型可能无法推断。

### 余数及下标

此仓库当前标准库**没有**导出的整数余数函数；不要反复搜索或猜测 `取余` 是否存在。需要余数时，按整数除法向零截断的语义在题目源码中定义：

```yuyan
「取余」乃化「整数」而化「整数」而「整数」也。
「取余」者会「甲」而会「乙」而
  「减」于「甲」于（「乘」于（「除以」于「甲」于「乙」）于「乙」）也。
```

除数不得为零。数组、列表序号从零开始；先判断界限，再读写。整数一般按有符号 64 位处理，溢出行为没有稳定承诺。

## 6. 可运行程序与编译

编译器的命令行只接收**一个入口源文件**。多个模块必须在入口中导入，不能写 `yy 甲。豫 乙。豫`。在本仓库优先使用已存在的 `./yy3_bs` 或 `./yy`；运行 `--help` 确认路径。只做类型检查：

```sh
./yy3_bs /绝对路径/题目/主。豫 --package-context /绝对路径/上下文 --type-check-only
```

编译并运行：

```sh
./yy3_bs /绝对路径/题目/主。豫 --package-context /绝对路径/上下文 -o /绝对路径/yy题目
/绝对路径/yy题目
```

`--package-context` 是豫构生成或任务环境提供的包解析文件；路径应使用真实绝对路径。任务若已提供可用上下文，直接使用。下面是**直接调用编译器**时已经验证的最小库包配置。文件名为 `验证包。包。豫`，同目录入口是 `主。豫`，配置内容：

```yuyan
「名称」者『验证包』也。
「所有者」者『豫言』也。
「版本」者『0.1.0』也。
「类型」者「典」【「种类」者『库』也，】也。
「简介」者『算法练习。』也。
```

如果任务环境没有提供上下文，可以在类 Unix 系统手工创建文本文件；以下每列之间必须是**实际制表符**，路径替换为 `realpath` 得到的绝对路径：

```text
豫构包上下文二
豫言<TAB>验证包<TAB>/绝对路径/验证包/验证包。包。豫<TAB>豫言<TAB>标准库
豫言<TAB>标准库<TAB>/绝对路径/库/标准库/标准库。包。豫
```

其中 `<TAB>` 仅用于展示，不是文件中的四个字符；第二行最后两列声明验证包直接依赖标准库。不要把 `.包。豫` 文件当成源码入口；入口是 `主。豫`。

在仓库内正式建包时，优先按 `工具/豫构/包系统.汉语.md` 填写完整包元数据，包括名称、所有者、版本、简介、说明、类型。可执行包的 `类型` 包含 `种类`、`入口`、`文件名`，并用 `依赖` 声明标准库。先检查是否存在 `./yy豫构`；若没有，按仓库的 `Makefile` 运行 `make 豫构` 构建当前包工具。之后运行 `./yy豫构 类型检查 包名` 和 `./yy豫构 构建 包名 --输出 yy程序`。若包类型为库，不要为默认库构建指定可执行输出路径。`yy豫构_stable` 只负责引导，不能假定它能读取当前包格式。单段 `寻观「标准库」之书。` 固定导入标准库的 `总集。豫`。

## 7. 首次提交检查表

- 所有代码名用 `「」`，字符串用 `『』`，所有源码标点用中文全角；裸 `1`、`-1`、`true`、`false` 都不是豫言值。
- 名称只用 `「」`，字符串只用 `『』`，表达式只用全角 `（ ）`；若需要连续很多右括号，先拆出一个具名中间值，再输出源码。
- 每个顶层声明以 `。` 结束；签名 `乃` 和同名定义 `者` 必须相邻；顶层定义顺序不能随意前向引用。
- 函数完整传参，必要时 `授以` 明确类型；一处应用若需当作另一处参数，使用 `（ ）`。
- `乃化「甲型」而化「乙型」而「结果型」` 的函数每次都须恰有两个普通实参；仅写第一个不会得到可继续调用的函数。递归辅助函数的初次调用与递归调用都按签名逐项核对。
- 列表模式仅用已知构造器 `罄`、`缀`；空列表显式给元素类型。
- 元组 `中` 只接静态数字索引；动态索引用数组或列表函数。
- 单入口编译，包依赖含标准库，运行编译后的实际产物；不要仅凭肉眼宣称通过。
- 用空输入、单元素、重复值、负数、极值等题目边界做测试；性能目标由题目约束决定，不把列表字典当哈希表。
- 布尔题在最终提交前只手算一例应为 `阳`、一例应为 `阴`，特别核对终止分支有没有误加 `非`；带累计状态的递归手算一例非空输入，确认最终返回累计值。这两项并入前述**一次**核对，不要反复重写源码。
- 若算法以多个状态量推进，终止分支要核对题意要求的**全部**状态。例如一个标志表示扫描中未出错，并不代表尚待处理的列表已经为空；不能只返回标志而漏检剩余状态。

### 常见诊断的直接处理

| 诊断或现象 | 首先检查 |
| --- | --- |
| `未定义优先级关系：〇于〇 与 〇授以〇` | `于` 后的泛型实参没有包成 `（「值」授以「类型」）` |
| `函数应用的隐式参数无法完全确定` | 给 `罄`、`缀`、`长度`、`反转` 等泛型接口补 `授以「元素类型」`，检查数字字面量所需的类型 |
| `无法解析` | `「」`、`『』`、`（ ）`、`【 】` 是否成对；逗号和句号是否为中文全角；表达式是否误写英文符号 |
| 未定义名称 | 导入是否在定义前；名称是否与标准库完全同字；前向引用是否需要调整顶层定义顺序 |
| 编译器拒绝多个文件 | 只传一个入口文件，其余模块由 `寻观` 导入 |
| 类型检查通过但结果不对 | 核对调用实参顺序、左折叠的元素与累计值顺序、零起索引和整数除法的截断规则 |

如果有工具且遇到本指南未覆盖的语法或接口，查本仓库的 `.汉语.md` 语言规范和对应标准库 `.豫` 定义，再写最小程序验证。无工具时只用本指南已经给出的基础构造表达解法，并在本次响应提交；不要猜未列出的接口，也不要等待下一轮。
