# 网页汇编后端考

此存实现前所考；今最小后端已具，其用与所限见《网页汇编后端使用.文言.md》。

所考之本为 `3b68f9ec`。Wasm 者，WebAssembly 也。此记考源码、试编译之所得，非谓后端已成。汉语本见《网页汇编后端调研.汉语.md》。

初议：因既有 LLVM 生码之术，增目标之配置，适配运行之库；值仍占十六字节，豫言之栈与垃圾回收之法亦暂存之。然独改目标三元组，不足以成事。所先运行之地，WASI 命令行环境乎，浏览器乎，尚待定。

## 考其流程

源码既入，先析依赖与语法，继验类型，去类型及隐参之标；乃为跨模块优化，转闭包，提升函数；又正则其求值，转其续延；末备生码之式，定栈位、续延标签与回收检查，乃生 LLVM 中间码，编而链接之。

| 所在 | 所司与所当增 |
| --- | --- |
| `编译步骤/总体过程/编译过程。豫`、`分布编译步骤。豫` | 司顺序、分阶段编译及缓存；旧制多可因，目标之配置须达诸阶段 |
| `编译步骤/求值正则变换/顶层。豫` | 正则求值而转续延；语义当守 |
| `编译步骤/代码生成准备变换/代码生成准备变换。豫` | 已定栈、返回、续延与回收之约，非全无后端之别 |
| `编译步骤/代码生成/代码生成入口。豫` | 今惟 `llvm` 有实现；可增 Wasm 分派而共用生码之术 |
| `编译步骤/代码生成/主程序生成入口。豫`、`低级虚拟机/主程序生成。豫` | 司模块初始化、链接与运行；初始化可共用，链接及启动须分 |
| `编译辅助工具/命令行/命令行参数处理。豫`、`编译数据/编译配置/全局配置。豫` | 司命令与配置；当明后端、目标、工具链、宿主、特性及内存之别 |

帮助犹列 `js`，参数亦受 `js`、`mlton`、`polyml`，然今生码入口惟 LLVM 有实现。不可据遗文谓诸后端尚存。

## 试其可行

本机有 Homebrew Clang 22.1.7，具 `wasm32`、`wasm64` 目标。试验之文皆置临时目录，未改项目源码。

| 所试 | 所得 |
| --- | --- |
| C 之 `__uint128_t` 传参与返回 | 可编；其 LLVM 码用 `i128` |
| 依旧式书 `i128` 外调 | 可降为 Wasm；一值之参分为二 `i64`，返回以隐含 `i32` 地址受之，与同工具链之 C 相应 |
| 标记地址之转换及十六字节值之存取 | 小试可编；诸指针及回收之全行尚须实证 |
| `void(i128, i128)` 间接 `musttail` | 加 `-mtail-call`，则生 `return_call_indirect`，用四 `i64` 为参，可成 Wasm 可重定位目标文件 |
| 禁尾调而编同式 | 报 `WebAssembly 'tail-call' feature not enabled` |
| 以 `wasm32-wasip1` 编原生值编解码 | 缺目标头文件，报无 `stdlib.h`；运行库之相容尚未得验 |

是故 Wasm 虽无标量 `i128` 指令，不必遂改值之制。LLVM 能分其运算与传递，然正式构建当定工具链而验全约。参 [WebAssembly C ABI](https://github.com/WebAssembly/tool-conventions/blob/main/BasicCABI.md)。

今函数之转移以强制尾调为本，非可有可无之优化。初版可明求宿主具尾调；若兼不具者，须另作循环分派，不可径代以普通调用。

## 所当补

### 外调名实

`低级虚拟机/代码生成。豫` 第 193 行以下，一概声明外调为 `i128(i128, …)`；`直接代码生成。豫` 第 185 行以下，亦以此调用。然有二者不合：

| 名 | 生码所约 | C 中其实 |
| --- | --- | --- |
| `豫言_登记垃圾回收根` | `i128(i128)` | `void(豫言值*)`，见 `运行时支持库/原生/垃圾回收器.c` 第 16 行 |
| `豫言_运行时报错并中止` | `i128(i128, i128)` | `uint64_t(豫言值, 豫言值)`，见 `运行时支持库/原生/异常.c` 第 26 行 |

`闭包转换/全局结构变量储存变换。豫` 第 18 行以下植入根登记之调用，故此失可及寻常模块初始化。试其签名，C 之登记为 `(i32) -> ()`，生码之约则为 `(i32, i64, i64) -> ()`，不得径相调。

宜增桥接入口，以豫言值受而返，内调原 C 辅助函数；或于生码器详定特殊外调之签名，明转其值。择一而遍核语言可调之诸名。链接宜设 `--fatal-warnings`，盖 LLD 遇签名不合，默认可仅警告而生陷阱之桩，成文件未必可运行。参 [LLD 签名检查](https://lld.llvm.org/WebAssembly.html#function-signatures)。

### 目标与缓存

`目标信息。豫` 默认取宿主 `clang -dumpmachine`。覆写三元组，今仅改中间码之文；`代码生成工具。豫` 第 116 行以下之 `llvm-as → opt → clang -c`，及最终链接，未传目标工具链、sysroot 与 Wasm 特性。原生 Makefile 犹造宿主静态库、动态库。

当共定目标配置，贯单模块、全程序优化链接与 C 库构建。Wasm 目标文件、静态库及 `.wasm` 产物须各有其处，不得混用原生库。运行须托所定宿主，不得如本机可执行文件径行。

`总体过程/编译过程工具。豫` 第 30–60 行之缓存，以编译器名、修改时刻及自举包之别为识，未识目标。初可全隔之，后再议共享前端缓存。其识至少纳后端、目标三元组、宿主 ABI、关键特性与运行库、工具链之配置，免旧完成标记误止新码之生成。

`parallel_compile.py` 已传全局参数于工作进程，旧流程可因；然 `--extra` 以空格析之。SDK 路径及宿主参数若含空格，须先正其参数边界，复验顺序与并行之同。

### 运行之库

| 所属 | 所议 |
| --- | --- |
| 值、元组、引用、字符串、字节串、基本运算 | 守旧语义，以目标工具链编而验之 |
| 栈、根、复制回收、续延、异常 | 暂因旧法；验根之更新、迁移之引用及函数表序数；语言异常今不必先赖 Wasm 异常指令 |
| 初始化、输入输出、参数、环境、时间、文件 | 各适宿主；WASI 文件之访问须得宿主所授目录之权 |
| 子进程、TCP、`poll`、终端原始模式 | 各定支持之界，不可径用 POSIX 实现 |
| 拉丁拼写 | 苹果框架、`iconv` 之路须核目标是否具之 |
| 协作异步 | 调度本单线程，可考共用；待输入输出之法须接宿主事件循环 |

`公共包含.h` 并引 POSIX、pthread 诸头，构建又遍收原生 C 文，宜分公共核心与宿主之用。见 pthread 声明，不足谓必需多线程；今 WASI SDK 于单线程亦具部分接口，须以所定版实编。参 [WASI SDK 所限](https://github.com/WebAssembly/wasi-sdk#notable-limitations)。

`藏书阁/标准库。豫` 总出操作系统、网络、控制诸模块；初始化又存并登记全局定义。故虽程序仅打印，亦不可先谓无用外调必尽删。须验依赖可达之实，定目标库之实现，或明报“不支持”而可捕获，或于相关使用处报编译之错；不得默然称成，亦不得尽放未解析之符号。

### 内存之量

原生默认栈有三千二百万余槽，每槽十六字节，共 512 MiB；优化构建初始堆 256 MiB，复制回收又需新堆。初版宜小其默认量，明线性内存之初值、上限及增长之法。

wasm32 之 `long`、指针、`size_t` 皆当核其三十二位之界。如 `垃圾回收器.c` 所书 `2L * 1024 * 1024 * 1024`，于三十二位有符号 `long` 溢出。栈之环境变量今乘 `1024 * 1024` 而作槽数，亦须一字节与槽位之量。皆当验边界，不得以编成自足。

## 择路与验收

| 路 | 得失 |
| --- | --- |
| 经 LLVM 生 Wasm，共用 C 核心库 | 所因最多，所补主在 ABI、目标构建与宿主；宜先行 |
| 径生 Wasm/WAT | 可自生码准备结果接入，然值拆分、结构化控制流、函数表、模块及链接皆须备；若志在去 LLVM 依赖，再专议 |
| 以 Wasm GC 表示对象 | 对象、闭包、引用与 C 边界皆须更定，接入之中间式亦须重择；另为运行时设计，非初版所必先 |

一、先验运行库之界。备工具链，正特殊外调，链接并运行值之往返、间接尾调与根登记，以严格链接诊断为验。

二、通全编译之路。增目标配置、隔缓存、备模块初始化与目标库，使豫言源码可成 Wasm 而运行。先验中文输出、整数、小数、元组、闭包、跨模块引用、递归及捕获、未捕获异常。

三、验其语义。以小堆迫多轮回收，验字符串、字节串、闭包及全局引用；以深递归、长续延链验宿主栈不随转移无穷增长；兼验顺序、并行及原生与 Wasm 更迭之缓存。

四、扩宿主之用。随所需，增文件、异步、网络或浏览器互操作，各明接口、权限与错误。

若先求命令行运行，可始于单线程、静态链接之 `wasm32-wasip1` 核心模块。若首版须网络，当考 WASIp2/WASIp3 或明定宿主导入；今 SDK 文谓 WASIp1 无网络，WASIp2/WASIp3 则有，不可一概论。参 [WASI SDK](https://github.com/WebAssembly/wasi-sdk#notable-limitations)。

若先求浏览器，当先定加载、初始化、导出、字符串与内存之传、JS 对象句柄、异步完成之约。可考 Emscripten，或限量明定宿主导入；旧 C 外调不自成浏览器公共接口。参 [Emscripten 互操作](https://emscripten.org/docs/porting/connecting_cpp_and_javascript/Interacting-with-code.html)。

## 所验之限

本工作区无 `yy`、`yy_bs_stable`；PATH 未有 `wasm-ld`、Wasmtime、Wasmer、`wasm-tools`、`wat2wasm`、Emscripten，常见处未见 WASI sysroot。现有 LLVM 足作目标文件之试，未足证完整程序与运行库可用。本次未安装工具，未行项目自举。

正式实现前，当备原生稳定自举编译器、目标 SDK、链接器及执行宿主。既改编译器，则循 `AGENTS.md` 人工审查、类型检查及三阶段自举，验 `yy3_bs` 与 `yy4_bs` 同；并行验证于沙箱外行之。原生之验既毕，仍须尽验前述 Wasm 语义之例。
