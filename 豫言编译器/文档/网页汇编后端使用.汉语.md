# 实验性网页汇编后端

现在可以用 `--target=wasm` 将豫言程序编译为单线程 WASI Preview 1 模块。它复用 LLVM 生成器、十六字节值、显式豫言栈和复制式垃圾回收器，要求执行宿主支持 Wasm 尾调用。当前只负责生成文件，运行由外部宿主完成。

## 编译与运行

在仓库根目录执行：

```sh
./yy 测试/网页汇编/基础-1。豫 --target=wasm -o yy_基础.wasm
./yy_wasmtime run -C cache=n yy_基础.wasm
```

本次开发已在当前工作区准备 `yy`、`yy_wasi_sdk` 和 `yy_wasmtime`，均为忽略的本地产物，没有改动系统安装。新检出需要准备原生豫言编译器，并从 [WASI SDK 官方发行](https://github.com/WebAssembly/wasi-sdk/releases/tag/wasi-sdk-34)下载适合宿主的 SDK，将其解压为 `yy_wasi_sdk`，使 `yy_wasi_sdk/bin/clang` 存在。使用其他目录时传入 `--wasi-sdk /绝对路径`。

执行宿主可采用 [Wasmtime 官方发行](https://github.com/bytecodealliance/wasmtime/releases/tag/v48.0.1)。这里将二进制命名为 `yy_wasmtime`；已有系统安装也可以直接调用 `wasmtime`。`-C cache=n` 禁用宿主的磁盘缓存，便于在受限工作区中验证。

已实测 WASI SDK 34（Clang 23.1.0）、Wasmtime 48.0.1，以及 Node 26.3.0 的 WASI 宿主。

基础示例输出：

```text
你好，网页汇编！
42
1.500000
已捕获异常
42
```

支持 `--parallel`，在 Codex 中按 `AGENTS.md` 要求于沙箱外运行并行编译。不传 `-o` 时，产物放在编译缓存中，编译结束会打印位置。`--target=llvm` 显式选择原生目标；原生与 Wasm 缓存分开，Wasm 缓存还区分传入的 SDK 目录。

## 首版范围

- 已验证中文输出、整数、小数、闭包映射、模块初始化、异常捕获、深递归、列表及多轮垃圾回收。
- 核心运行时静态编入模块，默认豫言栈为 4 MiB、初始堆为 4 MiB、最大单堆为 64 MiB，整个线性内存上限为 256 MiB。LLVM/C 栈另设为 1 MiB。
- 网络、子进程、拼音转换、异步 I/O 等待和终端按键暂不支持；调用时明确报错并以状态 1 退出。进入终端原始模式返回假，退出原始模式为空操作。
- 文件系统代码已编入运行时，访问目录需由宿主显式授权；尚未全面验证其接口。没有浏览器 JS 适配层，也不支持在 Wasm 内自举编译器。
- `--emit-bootstrap-bundle` 与 Wasm 目标组合会被拒绝。
- 这是最小实现：链接时重新构建 Wasm 运行时；运行时固定采用优化构建，尚无独立调试运行时。切换优化选项或原地替换 SDK 后，应使用 `--do-not-load-cache`。并行调度器仍按空格切分附加参数，含空格的 SDK 路径请使用顺序编译。

## 验证

```sh
./yy 测试/网页汇编/递归回收-1。豫 --target=wasm -o yy_递归回收.wasm
./yy_wasmtime run -C cache=n \
  --env YY_GC_INITIAL_HEAP_SIZE_MB=1 \
  --env YY_GC_MAX_HEAP_SIZE_MB=16 \
  --env YY_GC_DEBUG_FLAG=1 yy_递归回收.wasm
```

标准输出应为 `20000` 和 `200010000` 两行；本次在 1 MiB 初始堆下观察到七次回收。对应期望值位于 `测试/网页汇编/递归回收。成功`，基础用例也有同名期望文件。

`测试/网页汇编/不支持子进程-1。豫` 应能编译，但运行时须以状态 1 退出并输出对应“不支持”消息。不得以忽略未定义符号或放行链接警告替代运行时适配。

本次还完成编译器类型检查及规定的三阶段原生自举，`yy3_bs` 与 `yy4_bs` 逐字节相同。Wasm 链接使用 `--fatal-warnings`，GC 根登记和报错接口通过专用桥接维持正确的函数签名。
