# 实验性网页汇编后端用法

今可以 `--target=wasm` 编豫言为单线程 WASI Preview 1 模块。其生码因 LLVM，值仍十六字节，栈与复制回收亦因旧法。宿主须具 Wasm 尾调。编译器今但生文件，运行另托宿主。

## 编而行之

于仓库根目录行：

```sh
./yy 测试/网页汇编/基础-1。豫 --target=wasm -o yy_基础.wasm
./yy_wasmtime run -C cache=n yy_基础.wasm
```

此工作区已备 `yy`、`yy_wasi_sdk`、`yy_wasmtime`，皆本地产物，Git 忽略之，未改系统安装。若新取源码，当备原生豫言编译器，取适合宿主之 [WASI SDK 发行](https://github.com/WebAssembly/wasi-sdk/releases/tag/wasi-sdk-34)，解之于 `yy_wasi_sdk`，使 `yy_wasi_sdk/bin/clang` 存。若置他处，以 `--wasi-sdk /绝对路径` 指之。

宿主可取 [Wasmtime 发行](https://github.com/bytecodealliance/wasmtime/releases/tag/v48.0.1)。此处名其二进制为 `yy_wasmtime`；已有系统安装者，亦可径用 `wasmtime`。`-C cache=n` 禁其磁盘缓存，便于受限工作区中验证。

已试 WASI SDK 34（Clang 23.1.0）、Wasmtime 48.0.1，亦试 Node 26.3.0 之 WASI 宿主。

基础示例所出：

```text
你好，网页汇编！
42
1.500000
已捕获异常
42
```

可用 `--parallel`；在 Codex 中，循 `AGENTS.md` 于沙箱外行并行编译。未设 `-o`，则产物置编译缓存，事毕打印其所在。`--target=llvm` 选原生目标。原生与 Wasm 缓存异处，Wasm 又以所传 SDK 目录别之。

## 初版之界

- 已验中文输出、整数、小数、闭包映射、模块初始化、异常捕获、深递归、列表及多次回收。
- 核心运行库静态入模块。豫言栈默认 4 MiB，初始堆 4 MiB，单堆上限 64 MiB，全线性内存上限 256 MiB；LLVM/C 栈另置 1 MiB。
- 网络、子进程、拼音转换、异步 I/O 等待、终端按键尚未具；用之则明报错，以状态 1 退出。入终端原始模式返假，出之为空操作。
- 文件系统码已入库，访问目录须得宿主授权，诸接口尚未尽验。未有浏览器 JS 适配，亦不支持于 Wasm 内自举编译器。
- Wasm 目标不得并用 `--emit-bootstrap-bundle`。
- 此为最小实现：每链接则重建 Wasm 运行库；运行库固定用优化构建，未别置调试库。改优化选项，或原处更换 SDK，宜用 `--do-not-load-cache`。并行调度犹以空格析附加参数；SDK 路径含空格者，宜顺序编译。

## 验其行

```sh
./yy 测试/网页汇编/递归回收-1。豫 --target=wasm -o yy_递归回收.wasm
./yy_wasmtime run -C cache=n \
  --env YY_GC_INITIAL_HEAP_SIZE_MB=1 \
  --env YY_GC_MAX_HEAP_SIZE_MB=16 \
  --env YY_GC_DEBUG_FLAG=1 yy_递归回收.wasm
```

标准输出当为 `20000`、`200010000` 二行。本试初始堆 1 MiB，得七次回收。期望值见 `测试/网页汇编/递归回收。成功`，基础之例亦有相应期望文件。

`测试/网页汇编/不支持子进程-1。豫` 当可编成，然运行须以状态 1 退出，明告未支持。不得忽略未定义符号，亦不得放链接警告，以伪适配之成。

本次已验编译器类型，并依规定行三阶段原生自举，`yy3_bs` 与 `yy4_bs` 逐字节同。Wasm 链接用 `--fatal-warnings`；根登记与报错之接口皆设桥接，以合签名。
