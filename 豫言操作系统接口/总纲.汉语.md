# 豫言操作系统公共接口

状态：源级接口草案 0.1。这里是仓库根目录下的独立规范树，仅含接口包、纯声明和规范文字；浏览器、CF Worker、V8/Node.js 与裸机实现均在别处。

## 文件与身份

每个能力组是独立的包。`名称。包。豫` 使用现有包语法写所有者、名称、版本与直接依赖；接口文件使用豫言现有类型声明及函数签名，不写函数体、`C调用` 或宿主私有对象。`名称。接口。豫` 中的函数由宿主提供，`名称。应用接口。豫` 中的函数由应用提供，方向直接由后缀确定。包身份为所有者／名称／完整版本。应用依赖的每个接口包及其传递依赖均为必需；宿主缺少对应实现时构建或装载失败。接口实现与本次运行的资源授权须分别检查。

接口模块的逻辑名称去掉 `。接口。豫` 后缀。现有普通豫言模块解析器只把 `名称。豫` 当模块文件，而且普通源码要求函数签名后紧跟定义；所以这些纯声明文件仍是**规范输入，不能直接当普通程序编译**。`yy豫言操作系统绑定` 已能对单模块宿主接口核对规范和实现，在临时构建目录用接口身份生成可编译绑定包；官网首页与 Worker 已通过该步骤编译同一接口名。`yy豫言操作系统装载包` 及浏览器、云工入口已核对格式 4 的应用要求与独立宿主清单。多模块绑定、应用提供接口和编译器直接解析纯接口文件仍待完成；当前 Wasm 通用宿主导入也不能证明逐函数连通。规范树不加入空实现。

GPU 计算另立 `豫言操作系统图形处理器` 包，作为后续规范。CPU 图像绘制属于普通豫言库；画面呈现与 GPU 计算分开，驱动只存在于宿主实现下层。CF Worker 无显示面时不实现显示包。

基础、文件、网络、显示、网页界面、网页文树、网页消息、剪贴板、网址、网址定位、网页转发、网页入站、关系查询、网页答复、服务状态、环境文字、时间、持久事务、秘密文字、网页上游、命名持久服务和授权服务包规定应用调用宿主的能力；启动和网页服务包还规定宿主调用应用的入口。`启动程序` 与 `处理入站网页请求` 是应用导出。网页服务包中的请求读取函数由宿主提供，`造出站网页响应` 是应用可用的纯构造器。网页入站、关系查询、网页答复、持久事务、网页上游、命名持久服务和授权服务在当前 `_start` 边界提供过渡调用，待类型化入口可装载时再消除重复的文字传值、临时响应柄与事件重入。各签名方向依[接口文件规则](接口文件规则.汉语.md)逐项确定，不能仅凭 `乃` 推断方向。

首批可移植程序形态如下；“必需包”指该形态的应用必须声明的依赖，其余包按应用实际使用另加。

| 程序形态 | 目标宿主 | 必需包 |
| --- | --- | --- |
| 无界面启动程序 | 浏览器、Node.js | 基础、启动 |
| 像素画面交互程序 | 有显示面的浏览器或 Node.js 适配器 | 基础、启动、显示 |
| 入站 HTTP 服务 | CF Worker、Node.js 服务适配器 | 基础、网页服务 |

文件和出站网络均按实际应用依赖另加。Node.js 不因自身有终端就隐式具备显示面；CF Worker 不因可生成图像字节就实现显示包。

这些包仍是**源级规范草案**。完成规范不等于编译器已识别 `.接口。豫`，也不等于三个宿主已有符合规范的实现。GPU 的设备、缓冲区、命令与设备失效等接口尚未定稿；本版只规定显示与 GPU 是不同能力边界，不宣称 GPU 接口已完善。

## 共同检查

接口文件只出现导入、以 `立` 写的名义类型/构造器声明、以 `乃` 写的函数签名及双语语义注释；不得出现 `者` 函数定义或外调。`者` 仍用于普通 `。包。豫` 元数据。每项函数的行为、输入范围、返回值、错误、挂起与资源寿命在所属包的 `规范.汉语.md`、`规范.文言.md` 中约定。相同应用在不同宿主可以有不同二进制包装，但公开豫言签名和语义须一致。初版要求解析后的完整版本相等；现有 `。包。豫` 的依赖仅列包名，尚无版本锁文件，接口专用工具须记录并核对解析所得版本。

接口文件准入规则见[接口文件规则](接口文件规则.汉语.md)，跨宿主装载、授权、挂起与资源规则见[执行契约](执行契约.汉语.md)，未来共同验收见[一致性样例](一致性样例.汉语.md)。当前差距逐项列于[未决事项](未决事项.汉语.md)。架构与研究背景另见[规范设计背景](../文档/豫言操作系统接口规范.汉语.md)。
