# 接口文件规则 0.1

本规则适用于此规范树中的 `。接口。豫` 与 `。应用接口。豫`。包名和版本来自同目录的 `。包。豫`；文件的逻辑模块名是去掉相应后缀的名字，同包不能用两种后缀声明同名模块。公共名义类型身份由包所有者、包名、完整版本、逻辑模块名和类型名组成，不能只按字段形状或本地文件绝对路径判同一类型。

## 可接受的豫言语句

1. `寻`、`寻观`、`寻诵` 可引用本包的其他接口模块、直接依赖包的接口模块，或标准库中只需其检查后类型接口的模块。接口包的模块路径解析到 `名称。接口。豫`；普通标准库仍按现行包解析规则定位。本包内部引用不算作额外包依赖，但仍受循环导入检查。
2. `「类型名」立「元类型」也。` 声明名义类型；`立化……而「类型名」也。` 等现有构造器语法声明其公开构造器。没有公开构造器的资源类型由宿主产生，应用不可仅凭整数或字符串造出资源。
3. `「函数名」乃化……而「结果类型」也。` 声明函数类型。`乃` 后按豫言现有类型语法静态检查；同文件内可引用此前声明及导入的类型。跨文件引用须使用包路径导入。
4. 双语 `「：汉语：……文言：……：」` 注释及普通注释可写语义说明。

`乃` 只表示函数签名；文件后缀决定调用方向。`。接口。豫` 中的函数是宿主提供、应用导入，`。应用接口。豫` 中的函数是应用提供、宿主调用。类型和构造器可出现在任一文件中，但不会变成跨边界函数。基础、文件、网络、显示包的公开函数由宿主提供；启动包的 `启动程序` 及网页服务包的 `处理入站网页请求` 由应用提供。网页服务包的请求读取与上限读取函数由宿主提供。接口检查器必须按文件后缀核对应用导出与宿主导入，不能从函数名或宿主包装代码猜测。

接口文件不得出现 `「函数名」者……也。` 函数体、外调、宿主原语名、初始化表达式或以运行时计算得到的类型。`者` 只用于独立的 `。包。豫` 配置。接口检查器必须拒绝重名、重复声明、非法类型、循环导入和越过直接依赖的导入。任何无法静态判定是否为函数签名的语句须拒绝，不按普通程序求值。

## 默认效果与资源规则

可能挂起之处只有两类：调用「同步等待」处，以及结果类型为「异步返回」的函数（宿主导入的结果写成 `「异步返回」于T`，边界签名记作“异〔…〕”，见[网页汇编接口](../应用/豫言编译器/文档/语言技术规范/网页汇编接口.汉语.md)网五）；一个函数直接或间接调用了「同步等待」，调用它也可能挂起。其余函数编译器可假定不挂起；结果为普通类型的宿主导入，宿主须同步完成（必要时阻塞）。「同步等待」要求宿主能挂起（JSPI）或阻塞（原生执行器、Node 工具宿主），所有宿主现在都满足；将来若换用真正的异步运行时（支持没有 JSPI 的浏览器、请求内并发 I/O），用了「同步等待」的代码仍需要 JSPI，只有一路用「既而」组合的代码能受益。跨应用／宿主边界的函数一律按“分配、有外部效果”保守处理；可恢复失败只能按签名中的结果构造器返回。没有错误结果类型的操作须满足其包规范的成功承诺；无法满足时宿主可终止本次运行并报告宿主故障，不能伪造成功值。编译器不能因为某个实现看起来同步，就把结果为「异步返回」的接口当作不挂起，也不能推断任何公共接口无外部效果。详情见[执行契约](执行契约.汉语.md)。

抽象资源对象属于授予它的运行实例；跨实例传递只有接口明确允许时才合法。关闭或事件结束后的资源使用，若签名有错误分支则按包规范返回 `资源已失效`，否则终止本次运行并报告非法资源使用，不得伪造正常值。宿主仍须验证从二进制边界传入的对象确为本实例获授资源。接口包依赖表示**必需能力组**，宿主实现与实际授权分别检查。

构建时没有换成适配的接口包，编译器把 `。接口。豫` 里的函数编成带类型的 Wasm 导入：导入模块名是包名，字段名是函数名，参数与结果按边界类型传递（整数、小数、爻、字符串、字节串、元组、列、有构造器的类型；没有公开构造器的资源类型传宿主对象），见[网页汇编接口](../应用/豫言编译器/文档/语言技术规范/网页汇编接口.汉语.md)网五。函数类型、泛型与除列以外的递归类型不能出现在这些签名里，编译器报错。`。应用接口。豫` 的函数由应用在入口模块里定义同名函数实现，编成导出 `包名/函数名`。独立的接口检查工具在归并前读取这些声明。本规范树不放空函数定义或宿主适配；过渡适配与检查工具分别置于仓库其他目录。
