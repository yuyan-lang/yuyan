# 网页答复接口规范 0.4.0

`回应入站癸象文` 接受一段有效的 UTF-8 JSON 文字，返回给当前入站请求，状态码必须是 200 至 599，且不能是禁止正文的 204、205 或 304。宿主解析并验证 JSON，再序列化为响应正文，设置 `Content-Type: application/json; charset=utf-8`、`Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff`；无当前请求、状态码无效、正文超过 2 MiB 或本次请求已有最终响应时调用失败。调用不允许引用另一次请求的句柄。接口包本身只依赖标准库。

本包是在编译器仍以 `_start` 为入口期间使用的过渡宿主能力。长期入口契约由 `豫言操作系统网页服务` 的 `网页处理。应用接口。豫` 定义；后续接通带参入口后，应以该包的类型化响应替代此过渡调用。

`回应入站空答` 接受 200 至 599 的状态码，设置 `Cache-Control: no-store`，正文为空，不设置内容类型。无当前请求、状态码无效或本次请求已有最终响应时失败；204、205、304 在这里可用。

`回应入站文字` 接受 200 至 599 中允许正文的状态码、内容类型和纯文字，按 UTF-8 发出，正文不得超过 2 MiB；宿主设置 `Cache-Control: no-store` 与 `X-Content-Type-Options: nosniff`。内容类型按 HTTP 标头规则验证，非法值失败。`回应入站同源改址` 仅接受 301、302、303、307、308 与当前请求同源的绝对 `http:` 或 `https:` URL；非法网址、跨源目标或重复最终响应失败。此处四项答复函数合计每次请求只能成功调用一次。

`回应入站外址改址` 接受 301、302、303、307、308 与应用构造的绝对 HTTPS URL。宿主验证方案为 `https:`，目标由应用按自己的路由和配置选择；应用若把未验证的用户输入用作目标，会形成开放重定向。此函数与本包其余答复函数共用每次请求唯一的最终响应。
