# 持久告警之约 0.3.0

此包使客管持久对象（Durable Object）之告警（alarm）：读其已设之时，设之或易之，删之，且处告警之事。告警者，持久对象至期而由平台复唤之机也：至期则宿主呼客所具之入口 `处理持久告警`（`告警处理。应用接口。豫`），以此次告警为 `持久告警事件` 授之（提案 C0001）；是时无 HTTP 请，客当自[持久事务](../持久事务/规范.文言.md)之久仓复其所需之态。告警宜于“稍后再续”之后台事：长务分段而续、定期清理、败而重试。三版起告警之术以久仓（持久事务之 `持久仓`）为首参：告警入口中以 `告警持久仓` 自告警之事取之，网页之请、事务回调、独占区回调中，以持久事务与持久独占各自之取法取之。

## 义

一持久对象**至多一告警**。`设置持久告警` 设之于绝对 Unix 毫秒之时（自 1970-01-01T00:00:00Z 起之整数毫秒，取值 0 至 8640000000000000），已有者被易；时已过则平台速触之。`读取持久告警` 返（已设否，时）：未设则返（阴，零）。`删除持久告警` 去其告警，本无则无事。此三术施于久仓所属之对象；仓取自[持久事务](../持久事务/规范.文言.md)之 `事务持久仓` 者，告警之设与删与其事务同命：事务提交则行，回滚或败则撤（本地 workerd 已验，云端待验）。

告警之事始，其告警视为已清：入口中 `读取持久告警` 返（阴，零），入口可再 `设置持久告警` 以排下次（周期之务即如此成之）。入口败（抛未捕之异、为平台所止）则平台自退避而重试：败后、重试始前，告警视为已设（`读取持久告警` 返阳与重试之时）；`读取告警重试次数` 以 `持久告警事件` 为参，返平台于此告警已试之次（初次为零，首重试为一，以次递增），重试之事始，告警亦视为已清。重试之次数上限与退避之时以平台为准（平台文档现行：至多六次，指数退避，起约二秒；本地 workerd 已见重试次数 0、1、2 递增，上限待云端验），尽则平台弃其告警。按平台文档，告警至少触发一次（云端待验），故入口须**幂等**。宿主可于同一实例依次或交错呼入口，客不倚两调之间之内存。

`清空持久仓` 于 SQLite 之存，依兼容日期或并清告警，须告警者当于清仓之后复设之。告警入口之墙钟时限由平台定之。

## 术

`告警持久仓`：参为 `持久告警事件`，返久仓。`读取持久告警`：参为久仓，返（爻，整数）。`设置持久告警`：参为久仓与绝对毫秒整数，返有。`删除持久告警`：参为久仓，返有。`读取告警重试次数`：参为 `持久告警事件`，返整数。应用接口 `处理持久告警`：参为 `持久告警事件`，返有。

## 败之情形

时小于零或大于 8640000000000000，违约也：抛可捕之豫言异，辞曰 `持久告警时刻须在 0 至 8640000000000000 之间`。存后端故障，平台之故也：抛豫言异，此调败。`告警持久仓` 与 `读取告警重试次数` 不败。

## 跨宿主之一致

诸实现须守：一对象一告警、设即易、绝对毫秒；告警之事始，告警视为已清；败则重试且次数递增、败后待试之际告警视为已设；经事务之仓之告警变与事务同命；上述诸限与败类。

## 一致性样例

新对象（`仓` 为其久仓）`读取持久告警 仓` 得（阴，零）；`设置持久告警 仓 1900000000000` 后得（阳，1900000000000）；再 `设置持久告警 仓 1900000005000` 后得（阳，1900000005000）；`删除持久告警 仓` 后得（阴，零）。`设置持久告警 仓 -1` 与 `设置持久告警 仓 8640000000000001` 皆抛异。告警入口中（`仓` 为 `告警持久仓 告警`）：初触发 `读取告警重试次数 告警` 为 0 而 `读取持久告警 仓` 为（阴，零）；入口故意抛错后，下次入前 `读取持久告警` 为（阳，重试之时），重试之时次数为 1。事务回调中 `设置持久告警（事务持久仓 事务）T` 而调 `回滚持久事务`，事务之后 `读取持久告警` 仍为（阴，零）。

## 界

此包不供多告警、周期告警或依名之定时器；周期之务由入口重设告警而成。不保准点（平台于时后触发，或有延迟），亦不保恰一次。告警惟属持久对象，Worker 之 `scheduled` 定时之事另有其能。
