# 命名持久服务接口规范 0.1.0

`请求命名持久服务文字` 接受授权绑定名、对象名称、内部绝对网址、方法、查询键值列表、请求标头键值列表和文字正文。宿主先按当前程序的 `DO` 许可核对绑定名，再以 `getByName` 定位该绑定内的对象；不得以对象名选择其他绑定或外部网络。对象名称为非空且不超过 128 字符的 ASCII 字母、数字、下划线或连字符。内部网址只能位于 `https://asset/` 或 `https://internal/`，其路径拒绝反斜线、控制字符、`?` 和 `#`；不得携带自带查询或片段。方法限 GET、HEAD、POST。查询参数最多 16 项，由宿主编码；请求标头仅允许精确名称 `Origin`、`Content-Type`、`Cookie`，最多 8 项且不得重名；GET/HEAD 正文必须为空，POST 正文最多 2 MiB。

宿主返回有效 JSON 对象文字：`status` 为上游整数状态，`body` 为完整 UTF-8 文字正文，`headers` 只包含上游存在的 `content-type`、`location`、`set-cookie`、`x-yuyan-revision` 四个小写名称和值。正文最多 2 MiB，超出则失败；HTTP 4xx/5xx 仍是成功取得的响应。宿主不得泄露其他响应头、句柄或当前程序之外的对象。当前 `_start` 边界以 JSON 文字传递结果；长期类型化入口可将其改成豫言记录与字节流。
