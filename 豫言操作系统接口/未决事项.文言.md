# 接口规范未决事项

今诸接口包已成源级之约，未可谓全备。普通编译器今可导纯声明而依签名检其类（无体之签补占位，未绑定而调则报）；独立检查器读纯声明，核包版、直依、方向、名源与源型，且生载完整依闭之 JSON 清单，拒依环与版冲。Node 发行包于启动前核程序摘要、接口之版与签名、Wasm 导入导出之形。其一致驱动八十八事，于 macOS arm64 与 Linux 二架构皆过；Windows 犹待验。类型构造之全义、诸宿主同域之装载核对、跨宿主共验，犹待成。字体已成字体之包（以族名取文件而分段读之，解栅在纯豫言之库）；持久键值、流、队列、定时、邮件已各成持久事务、网页上游与命名持久服务之渐读、消息队列、定时事件、邮件发送诸包；GPU 之算与张量之算已各成图形处理器与张量计算二包；网页界面包仅备既有元素之文、受限属性及基本事件，造节点与选择符犹未定。图形处理器首版已定设备、缓冲、纹理、着色（WGSL 之文）、命令之列与设备之失，深度模板、多采样、间接绘制与计时犹未定；张量计算零点五版已具训练所需之跨步视图、逐元之算、按行累加与随机之填，混合专家与线性注意之算，及变换器推理之融合之算，犹无融合之优化、分段之旋转位置编码与写出张量，诺节之实有中央处理器、金属与统算之后端，网页图算待接；二者之宿主实现与跨宿主共验犹行，不得称全备。

欲称可执行且已验证之标准，尚须补类型之全义、诸宿主同域之装载核对，并以公共接口共验遍诸适用宿主。规范树仍惟载接口之约，适配与检查各居他目录。详见[汉语稿](未决事项.汉语.md)。
