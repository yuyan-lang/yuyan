# 网页服务接口规范 0.2.0

此包定入站 HTTP 之服：客具处理之入口，宿主具读请、造答与转请诸术，与客向外发请之网络包分。「网页处理。应用接口。豫」定客所具之「处理入站网页请求」；「入站网页。接口。豫」定请、答二型及宿主所具诸术。自〇点二始，原《豫言操作系统网页入站》《豫言操作系统网页答复》《豫言操作系统网页转发》三包之术皆并于此（提案 C0001），读术以请为参，答术改为返答。云工与节点之服可承之，浏览器页面不必承之。

## 入口、请与答

客依此包，必导出逻辑接口模块「网页处理」之「处理入站网页请求」；客源文件名可异，绑定者于客包所定入口源文件中惟一求得同名同型之实现，映于此模块。惟具此入口而不书「入口」之函者，`_start` 惟行静初。

每一获准之入站 HTTP 请（云工之 fetch、service-fetch、durable-fetch 三事），宿主造一「入站网页请求」而一调入口；入口所返之「出站网页响应」即此请之终答。宿主可于同一实例相继屡调入口，一实例同时惟行一调（见[执行契约](../执行契约.文言.md)）；模之状惟宜存可弃之缓，跨调须存者入久存之仓。入口抛异或返无效之答，宿主报败，传输之错页由宿主定。

「入站网页请求」惟宿主得造，效期止于此调；客欲跨调存者，须抄为己之豫言值。「出站网页响应」惟此包（或依此包之他接口包，如网页事件流、网页上游、授权服务、命名持久服务、对象存储）之术得造；客可造数答，惟入口所返者生效。网页事件流等包可于入口行中先交其答（即发响应头），是时入口终仍须返此答，宿主沿用所先交者。

诸术之参，同型而数者与义不显者皆带签（`名称`、`上限`、`路径`、`设置参数`、`删除参数`、`状态`、`类型`、`标头`、`正文`、`目标`、`绑定`、`保留标头`、`固定标头`），调之书 `于「状态」为「二零零」`；请之参不带签，恒居首。

## 读请

`读取入站事件种类` 返此请之事类：`fetch`（公开之入口）、`service-fetch`（由服务绑定而呼）或 `durable-fetch`（持久对象所受之请），客可据以辨请之所自。`读取入站方法` 返所受之法；`读取入站网址` 返全址；`读取入站原路径` 返未析百分号之径，无查询与片段；`读取入站解码路径` 严析一次百分号与 UTF-8，坏码则败。客若以径为档名或包名，仍须验解后斜线、控字符及己业务之规。

`读取入站标头值` 依 ASCII 不辨大小写之名取头，无则空文；`读取入站标头` 以列返其值，无则空列。`入站标头存在` 返请有无此头：头一出现即为阳，值空亦为出现。`读取入站标头值` 与 `入站标头存在` 之名，须为 RFC 9110 令牌字（数、字母及 ``!#$%&'*+-.^_`|~``）所成一至二五六字节之文，否则报可捕之事故，辞曰「入站标头名称无效」。读头不自授凭据使用或向外转请之权；网络、服务与久存另须能力及资源授权。

`读取入站查询参数` 循浏览器 URL 查询之法，取首个同名之值，已析百分号；无则空文。`入站查询参数存在` 察同名之参有无，值空亦为有。`读取入站来源` 返 URL 所定之 `origin`，可供同源之比；`读取入站主机名` 返小写而无端口之主机名；`读取入站原查询` 返原查询文，有则含首 `?`，不析参数。`构造入站同源网址` 受新绝对径、待设键值列与待删键列；空径守原。宿主复制请之网址，先删后设，余参皆留，返同源绝对址，不发请。新径须单一 `/` 起首，拒 `//`、反斜线、控制字、`?`、`#`；键值由宿主编码。设与删各至多十六项，逾限则败（「同源改写参数过多」）。

### 正文

`读取入站正文` 返全正文之字节，逾 `读取入站正文上限`（十六 MiB）则败。`读取入站正文上限`、`读取出站正文上限` 返此实例实行之正数字节之限。

`读取入站有限正文文字`（宽解 UTF-8）、`读取入站有限正文严格文字`（严解 UTF-8）与 `读取入站有限正文字节`（原字节）读正文，而蓄积永不逾所授之限。限须在一至一六七七七二一六（十六 MiB）之间，越界报可捕之事故（辞曰「入站正文字节上限须在 1 至 16777216」）。返二元组（状，果）：

| 状 | 义 | 果 |
| --- | --- | --- |
| 0 | 成，正文不逾限 | 文或字节，可空 |
| 1 | 正文逾限 | 空 |
| 2 | 无正文：法为 GET 或 HEAD，或宿主未予此请以正文之流 | 空 |
| 3 | 正文已被读：本包任一读术、宿主他读，或他读器已锁其流 | 空 |
| 4 | 惟严解之文：正文非有效 UTF-8 | 空文 |

断之序恒定：先验参数；次辨二与三；次若请之 `Content-Length` 全为一至十八位十进数字而已逾限，或长达十九位以上，则径返一，不读一字节；其余形之 `Content-Length` 一概不理，惟以流中计数断之。读时逐块累计字节，一逾其限，即废读取之流而返一，宿主至多蓄已受之字节与使总数越界之一块；废时上游取消之回调纵败亦吞之，仍返一。空之正文流返状零与空果。除状二、状三及由 `Content-Length` 预断所得之一外，读必耗或废请之体，此后同请再读得三。

宽解之文与 `TextDecoder` 整块解之默认行同：非法序列各代以 U+FFFD；惟全正文之首 BOM 剥去，正文中间之 U+FEFF 原样存之；多字节之字跨块亦能正解，果与分块之法无涉。解后之文逾十六 MiB 者，报可捕之事故（辞曰「宽松解码后的文字超过 16 MiB」）。严解之文依 fatal 而解：过长编码、代理对编码、越界码点、孤立之续字节及末尾残缺之序列皆为非法，得状四，且一见即废读取之流。字节之术原样返全部字节，BOM 与零字节皆存。读流自身败（如连线中断），报含因之可捕事故（辞曰「读取入站正文失败：…」）。

`读取入站结森正文文` 先以二 MiB 为限读字节，复授宿主析之，返宿主规范之 JSON 文（去冗白，数依 ECMAScript），可复以豫言 `结森解析` 析之。正文逾二 MiB（「入站 JSON 正文超过 2 MiB」）、无正文、正文已被读、JSON 无效或嵌套过深（辞以「入站 JSON 正文无效：」起，并含平台所报之因），皆为可捕之事故。

`读取入站有限结森正文文` 乃其有界而分状者：先依 `读取入站有限正文严格文字` 诸则读正文（限一至八三八八六〇八，即八 MiB，越界告「入站 JSON 正文字节上限须在 1 至 8388608」），严解 UTF-8（去字节序记），乃付宿主 `JSON.parse` 验之，由宿主 `JSON.stringify` 书为规范文。返（状，文）：

| 状 | 义 | 文 |
| --- | --- | --- |
| 0 | 成 | 规范之 JSON 文（去冗白；数依 ECMAScript 书；重键惟留末值而居初见之位；类整数之键依 JavaScript 物之则居前） |
| 1 | 正文逾限 | 空 |
| 2 | 无正文 | 空 |
| 3 | 正文已读或流已锁 | 空 |
| 4 | 正文非有效 UTF-8 | 空 |
| 5 | 非有效 JSON | 平台所报之因（以供诊断，不宜原样返客） |

状零之文可安付 `结森解析`。客仍须自验 `Content-Type` 与顶层值之类。

| 情 | 必见 |

| 限八，正文八字节分三块至 | （0，此八字节） |

## 造答

### 常用之答

- `造结森响应`：状须在二百至五百九十九，且非禁正文之二零四、二零五、三零四。宿主以 `JSON.parse` 验 JSON（无效则抛以「JSON 响应正文无效：」起首之异），书宿主规范之文，不逾二 MiB；置 `Content-Type: application/json; charset=utf-8`、`Cache-Control: no-store` 与 `X-Content-Type-Options: nosniff`。
- `造空响应`：状二百至五百九十九，以空体为答，置 `Cache-Control: no-store`，不置内容种类；二零四、二零五、三零四于此可用。
- `造文字响应`：状在二百至五百九十九而许正文者，内容种类不得含 CR、LF（「内容类型含换行」），以 UTF-8 发之，至多二 MiB；置无缓存与 `nosniff`。
- `造同源改址响应`：状惟三零一、三零二、三零三、三零七、三零八；目标须为宿主 `URL.canParse` 可析之绝对网址（否则「重定向目标不是有效的绝对网址」），且与请同源（否则「重定向目标不是同源」）。
- `造外址改址响应`：状同上，目标须为绝对 HTTPS 址（「外站重定向仅允许 HTTPS」）。目标由应用自守其来历；若径由客任意供给，或成开放改址。
- `造出站网页响应`：以状、头列与体字节径造其答。

### 带头之答

`造带头文字响应`、`造带头结森响应`、`造带头空响应`、`造带头字节响应` 与 `造带头改址响应` 以客所授之**有序头列**造答。头列之型为 `（列于（字符串合字符串））`，每项为（名，值），守其序，许同名多项。不暗增一头（内容种类惟由参数而置，JSON 之术固为 `application/json; charset=utf-8`）；同名之头依列序逐一追加，`Set-Cookie` 各项自独；严验，违者报可捕之事故，是时不生一答，客仍可别造误答。

- `造带头文字响应 状 类 头列 正文`：正文以 UTF-8 发之，不逾八 MiB（「文字响应超过 8 MiB」）。
- `造带头结森响应 状 头列 正文`：宿主验而正其文（JSON 无效者辞以「JSON 响应正文无效：」起），正其文后不逾二 MiB（「JSON 响应超过 2 MiB」）。
- `造带头空响应 状 头列`：无正文，不置内容种类；二零四、二零五、三零四可用。
- `造带头字节响应 状 类 头列 正文`：正文为任意字节（含零字节），不逾十六 MiB（「字节响应超过 16 MiB」）。
- `造带头改址响应 状 目标 头列`：状惟三零一、三零二、三零三、三零七、三零八（「重定向状态不受支持」）。目标惟二形之一：以单一 `/` 起首之径（次字节不得为 `/` 或 `\`）；或以 `http://`、`https://` 起首（方案不辨大小写）、可为 URL 之规所析、协议为 http 或 https、无用户名口令而主机非空之绝对址；全文惟含 0x21 至 0x7E 之 ASCII 而无反斜线，长一至八一九二字节（「重定向目标无效」）。头列不得复出 `Location`。

诸术共守之规（违者皆为可捕之违约）：

| 项 | 规 |
| --- | --- |
| 状 | 二百至五百九十九（「响应状态不在 200 至 599」）。二零四、二零五、三零四不得带非空正文（「该 HTTP 状态不得带非空正文」） |
| 头名 | RFC 9110 令牌字，一至六十四字节 |
| 头值 | 惟许可见 ASCII（0x20 至 0x7E）与水平制表；至多八一九二字节；`Set-Cookie` 每项至多四零九六字节 |
| 数 | 至多六十四项，多个 `Set-Cookie` 各计一项 |
| 客不得设者（不辨大小写） | `Content-Length`、`Transfer-Encoding`、`Connection`、`Keep-Alive`、`Upgrade`、`TE`、`Trailer`、`Content-Type`、`Content-Encoding`（「响应标头由宿主或参数管理，不得设置」） |
| 内容种类（参数） | 式如 `type/subtype`，其后惟许空白及以分号起首之参；全文限可见 ASCII 或水平制表，一至二五六字节（「内容类型无效」） |

HEAD 之请：宿主于 HEAD 之答不发正文，答仍依上规而造，客不必为 HEAD 别设一支。

| 情 | 必见 |
| --- | --- |
| 带头文字二零一，头 `X-A: 1`、`x-a: 2` 与二 `Set-Cookie` | 状二零一；`x-a` 并为 `1, 2`；二 Set-Cookie 各自独立；惟有 Content-Type 与所授之头 |
| 带头空答二零零，头列为空 | 无一头，正文为空 |
| 头值 `a\r\nInjected: 1`；头名 `Content-Length`、`content-type`、`TE` | 违约，不生答 |
| 带头文字二零四而正文非空 | 违约；正文空则成 |
| 带头改址三零二至 `/next?a=1` | 惟有 `Location` 与所授之头，正文空 |
| 带头改址目标 `//evil.example`、`http://u:p@h/`、`javascript:x` | 违约 |
| 六十五头，或四零九七字节之 Set-Cookie | 违约 |

## 转请与改址

- `造重定向响应 请 路径`：以三〇八转于本站之径。径以单 `/` 起，拒 `//`、反斜线、控制字、`?`、`#`（「重定向路径无效」）；宿主以请之协议与域构址而存原查询，不转于外站。
- `转发网页请求 请 绑定 路径`：转请于所授之绑，绑之答原样为果；`ASSETS` 为静资，余依 SERVICE 之授表；空名则败（「转发绑定名为空」），未授之名或无此绑者宿主拒之，报可捕之事故（部署之误）。径空则存原址，否则惟易其径（规同 `造重定向响应`，「转发路径无效」），法、查询、体流与头不易。所返之答指在途之请，入口既返宿主乃候上游，故转请全程不经 JSPI 挂起；上游败则此请败，欲捕上游之败者用 `转发网页请求并筛标头`。
- `转发网页请求并加标头 请 绑定 路径 标头`：绑与径之规同上。上游之答既至，存其状、正文流及原头，惟覆所授之头，不先读正文。所返之答如 `转发网页请求`，指在途之请，入口即返，宿主候上游；上游败则此请败。头列于发请之前验之，违者报可捕之事故。精确许 `Content-Security-Policy`、`X-Content-Type-Options`、`Referrer-Policy`、`Content-Type`、`Content-Disposition`、`Cross-Origin-Opener-Policy`、`Cross-Origin-Embedder-Policy`、`Cross-Origin-Resource-Policy`，至多八项；非法（「响应标头名称不允许覆盖」）或重名（「响应标头重复」）则败。

### 筛头转请

`转发网页请求并筛标头 请 绑定 路径 保留标头 固定标头` 以其请转于获授之 `SERVICE` 绑定，上游之答原样为果。

- 绑定：空名则败（「转发绑定名为空」）；静资之答用 `造静态资源响应`，此术惟按 `SERVICE` 类寻之。
- 径（含查询）：须单一 `/` 起首（次字节不得为 `/` 或 `\`），长一至八一九二字节，不含控字符、反斜线及 `#`；宿主以原请之源加新径成目标，不易其主机（「转发路径无效」）。
- 法与体：转原请之法，许 GET、HEAD、POST、PUT、PATCH、DELETE、OPTIONS（余法「转发方法不受支持」）。请体之流原样而转，不读不蓄（GET 与 HEAD 不带体）；请体已被读则败（「入站请求正文已被读取，无法转发」）；不随改址（`redirect: manual`）。
- 头：惟复保留标头所列之入站头（至多十六名；每名一至六十四字节之令牌；不辨大小写不得重；请中所无者略之），继叠固定标头（至多十六项；值惟许可见 ASCII 与水平制表，至多八一九二字节；覆同名之已复者；不得重）。`Host`、`Connection`、`Keep-Alive`、`Proxy-Connection`、`Proxy-Authorization`、`TE`、`Trailer`、`Transfer-Encoding`、`Upgrade`、`Expect` 不得保留或固定；固定头又不得设 `Content-Length` 与 `Set-Cookie`。所复入站头之值含控字符（水平制表除外）则拒转。
- 答：上游答之状、头与正文流原样为果，不读不蓄。服务绑定之 `fetch` 报错，转为可捕之事故（「转发到服务失败：名: 辞」）。

### 静资之答

`造静态资源响应 请 绑定 路径 状态 标头` 自获授之 `ASSETS` 绑定取所指之径而造答。参（绑名、径、状、头）于入口验之，违者报可捕之事故；继返指在途资源之请之答，入口即返，资源之答既至，宿主乃依下规易其状与头。

- 径：规同筛头转请之径，宿主以原请之源加径成目标，按 GET 取之，不转原请之头与体（「静态资源路径无效」）。
- 状：零者沿用资源答之状；余者须在二百至五百九十九（「静态资源状态须为零或 200 至 599」）。
- 头：以资源答之头为底，头列中某名初见之时，先去资源答中同名之头，再依序追加此名诸项；名、值、数与禁名之规同带头之答，资源自带之内容种类客不得改。
- 体：资源答之正文流原样而授，不蓄。请为 HEAD 则不带正文并废资源之正文流。终状为二零四、二零五或三零四，而资源答带正文且请非 HEAD 者，废资源之正文流，此请败（「该 HTTP 状态不得带静态资源正文」）。
- 资源不存在，ASSETS 常返四零四之答，此答如常为果，客可以状参覆之。ASSETS 之 `fetch` 同步报错则为可捕之事故，资源之请败（Promise 见拒）则此请败，其辞皆曰「读取静态资源失败：名: 辞」。资源既至而后之败，宿主报为此请之败。

转请之径与静资之径，其任一段为 `.` 或 `..`（含 `%2e` 大小写混写之形，后随 `/`、`?` 或径末）者拒之；形似而非点段者（`...`、`..b`、`.b`、`b..c`）不与焉。

| 情 | 必见 |
| --- | --- |
| 筛头转 POST，留 `Authorization`、`X-Keep`，固定 `Cookie: a=b` | 上游惟见此数头与固定头，法为 POST，径为新径，请体原样，`redirect` 为 manual |
| 上游返三零二与 `Location` | 果即此三零二，不发第二请 |
| 保留名含 `Host` 或 `transfer-encoding`，或固定头含二 `Cookie` | 违约 |
| 请体分二块，第二块须俟上游读毕首块而后生 | 转发成（证其未蓄） |
| 静资，状零，附 `Cache-Control: no-store`、`X-New: 1` | 沿资源之状；`Cache-Control` 被覆，`X-New` 被增，`Content-Type` 守资源之原 |
| 静资 HEAD | 状与头如常，正文空，资源正文流被废 |

## 后版之事

解 `Content-Encoding` 之压、析表单与 multipart、枚举诸头、内容协商、压缩、1xx 之状与 Trailer，留待后版。`Content-Type` 由客自验；带头之答惟置调用方所授之头。流式之答体由网页事件流包供之；队列、定时、持久对象告警诸事各有其入口之包。
