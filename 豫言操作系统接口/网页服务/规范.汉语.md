# 网页服务接口规范 0.2.0

本包是入站 HTTP 服务的接口：应用提供处理入口，宿主提供请求读取、造响应与转发函数，与 `豫言操作系统网络` 的出站请求能力分开。`网页处理。应用接口。豫` 声明应用提供的 `处理入站网页请求`；`入站网页。接口。豫` 定义请求、响应两个类型及宿主提供的全部函数。0.2.0 起，原 `豫言操作系统网页入站`、`豫言操作系统网页答复`、`豫言操作系统网页转发` 三个包的函数都在本包（提案 C0001），读取函数以请求为参数，回应函数改为返回响应。CF Worker 与 Node.js 服务适配器可以实现本包；浏览器页面无需实现。

## 入口、请求与响应

应用依赖本包须导出逻辑接口模块 `网页处理` 中的 `处理入站网页请求`；应用源文件可有不同名称，绑定工具从应用包指定的入口源文件唯一定位同名且同型的实现并映射到该逻辑模块。只实现这个入口、不写「入口」函数的程序，`_start` 只做静态初始化。

宿主为每次获准的入站 HTTP 请求（云工的 fetch、service-fetch、durable-fetch 三种事件）构造一个 `入站网页请求`，调用一次入口；入口返回的 `出站网页响应` 就是这次请求的最终响应。宿主在同一实例上多次调用入口，一次调用在等待宿主时，别的调用可以在同一实例上交错执行（见[执行契约](../执行契约.汉语.md)）；模块状态只适合放跨调用共享、可以丢弃的缓存与计数，本次请求的状态放参数或局部变量，跨调用要保存的数据放进持久存储。入口抛错或返回无效响应时，宿主报告失败，传输层错误页由宿主决定。

`入站网页请求` 只能由宿主构造，只在本次入口调用期间有效；应用需要跨调用保存的数据须复制为自身的豫言值。`出站网页响应` 只能由本包（或依赖本包的其他接口包，如网页事件流、网页上游、授权服务、命名持久服务、对象存储）的函数造出；应用可以造多个响应，只有入口返回的那个生效。网页事件流等包可以在入口执行中先行交付响应（立即发出响应头），此时入口最后仍须返回同一个响应，宿主沿用先行交付的那个响应。

函数参数里，同类型的多个参数与意义不显然的参数带标签（`名称`、`上限`、`路径`、`设置参数`、`删除参数`、`状态`、`类型`、`标头`、`正文`、`目标`、`绑定`、`保留标头`、`固定标头`），调用时写 `于「状态」为「二零零」`；请求参数不带标签，总是第一个参数。

## 请求读取

`读取入站事件种类` 返回本次请求的事件种类：`fetch`（公开入口）、`service-fetch`（经服务绑定调用）或 `durable-fetch`（持久对象收到的请求），应用可据此区分请求的来路。`读取入站方法` 返回宿主接收的方法文字；`读取入站网址` 返回完整网址；`读取入站原路径` 返回 URL 的百分号编码路径，不含查询串或片段；`读取入站解码路径` 对该路径严格解码一次百分号和 UTF-8，坏编码时报错。调用方若把路径当作文件名或包名，仍须验证解码后的斜线、控制字符与业务规则。

`读取入站标头值` 按 ASCII 不区分大小写的名称读取标头，缺失时返回空字符串；`读取入站标头` 以列表返回该名称的标头值，缺失时为空列。`入站标头存在` 返回请求是否含该标头：只要标头出现即为阳，值为空字符串也算出现。`读取入站标头值` 与 `入站标头存在` 的名称必须是 RFC 9110 令牌字符（数字、字母与 ``!#$%&'*+-.^_`|~``）组成的 1 至 256 字节字符串，否则抛出可捕获的豫言异常，消息为“入站标头名称无效”。标头读取不授予使用凭据或向外转发的权限；网络、服务绑定和持久存储仍需独立能力与资源授权。

`读取入站查询参数` 按浏览器 URL 查询参数规则读取第一个同名值，已经百分号解码；无该参数时返回空字符串。`入站查询参数存在` 按同一规则判断参数名是否出现，`?after=` 这样的空值仍返回阳。`读取入站来源` 返回 URL 标准的 `origin`，供应用比较同源请求；`读取入站主机名` 返回小写且不含端口的 hostname；`读取入站原查询` 返回原查询串，非空时保留开头 `?`，不做参数解码。`构造入站同源网址` 接受新绝对路径、待设置的键值列表及待删除的键列表；空路径保留原路径。宿主复制请求 URL，先删后设，未指定参数原样保留，返回同源绝对网址，不发起请求。新路径须以单个 `/` 起首，拒绝 `//`、反斜线、控制字符、`?` 和 `#`；查询键和值由宿主编码。设置或删除列表各最多 16 项，超限失败（“同源改写参数过多”）。

### 正文

`读取入站正文` 返回完整正文字节，超过 `读取入站正文上限`（16 MiB）时失败。`读取入站正文上限`、`读取出站正文上限` 返回本实例实际执行的正数字节限额。

`读取入站有限正文文字`（宽松 UTF-8 解码）、`读取入站有限正文严格文字`（严格 UTF-8 解码）与 `读取入站有限正文字节`（原始字节）读取正文，且从不缓冲超过所给上限。上限须在 1 至 16777216（16 MiB）之间，越界抛出可捕获的豫言异常（“入站正文字节上限须在 1 至 16777216”）。返回二元组（状态，结果）：

| 状态 | 含义 | 结果 |
| --- | --- | --- |
| 0 | 成功，正文不超过上限 | 文字或字节，可以为空 |
| 1 | 正文超过上限 | 空 |
| 2 | 没有正文：方法为 GET 或 HEAD，或宿主没有为该请求提供正文流 | 空 |
| 3 | 正文已被读取：本包任一读取函数、宿主的其他读取，或其他读取器已锁定正文流 | 空 |
| 4 | 仅严格文字：正文不是有效 UTF-8 | 空字符串 |

判定顺序固定：先验证参数；再判断 2 与 3；随后若请求的 `Content-Length` 全由 1 至 18 位十进制数字组成且已超过上限，或长达 19 位以上，立即返回 1 而不读取任何字节；其余形态的 `Content-Length` 一概忽略，只按流式计数判断。读取时逐块累计字节数，一旦超过上限就取消读取流并返回 1，宿主最多持有已接受的字节再加使总数越界的那一块；取消时上游的取消回调即使失败也被吞掉，仍返回 1。空正文流返回状态 0 与空结果。除状态 2、3 与由 `Content-Length` 预判得到的 1 之外，读取会消费或取消请求体，之后同一请求再读得到状态 3。

宽松文字的解码与 `TextDecoder` 整块解码的默认行为相同：非法序列各替换为 U+FFFD；只有整个正文开头的 BOM 被剥除，正文中间的 U+FEFF 原样保留；多字节字符跨块也能正确解码，结果与如何分块无关。解码后文字若超过 16 MiB，抛出可捕获的豫言异常（“宽松解码后的文字超过 16 MiB”）。严格文字按 fatal 解码：过长编码、代理对编码、越界码点、孤立的延续字节与末尾残缺序列都算非法，得状态 4，且发现后立即取消读取流。字节接口原样返回全部字节，BOM 与零字节都保留。读取流本身失败（如连接中断）抛出含原因的可捕获异常（“读取入站正文失败：…”）。

`读取入站结森正文文` 先以 2 MiB 上限读取字节，再交宿主解析，返回宿主规范化后的 JSON 文字（去冗白、数字按 ECMAScript 书写），可由豫言 `结森解析` 再次解析。正文超过 2 MiB（“入站 JSON 正文超过 2 MiB”）、没有正文、正文已被读取、JSON 无效或嵌套过深（消息以“入站 JSON 正文无效：”起首并含平台报告的原因）都是可捕获的豫言异常。

`读取入站有限结森正文文` 是它的有界、分状态版本：先按 `读取入站有限正文严格文字` 的全部规则读取正文（上限 1 至 8388608，即 8 MiB，越界抛出“入站 JSON 正文字节上限须在 1 至 8388608”），严格按 UTF-8 解码（剥除 BOM），再交宿主 `JSON.parse` 校验并由宿主 `JSON.stringify` 写成规范化文字。返回（状态，文字）：

| 状态 | 含义 | 文字 |
| --- | --- | --- |
| 0 | 成功 | 规范化 JSON 文字（去冗白；数字按 ECMAScript 书写；重复键只保留最后一次的值并停在第一次出现的位置；整数样式的键按 JavaScript 对象规则排在最前） |
| 1 | 正文超过上限 | 空 |
| 2 | 没有正文 | 空 |
| 3 | 正文已被读取或读取流已被锁定 | 空 |
| 4 | 正文不是有效 UTF-8 | 空 |
| 5 | 不是有效 JSON | 平台报告的原因（供诊断，不宜原样回给客户端） |

状态 0 的文字可安全交给 `结森解析`。应用仍须自行校验 `Content-Type` 并检查顶层值的类型。

### 读取的一致性样例

| 情境 | 必须观察到 |
| --- | --- |
| 上限 8，正文 8 字节分三块到达 | （0，该 8 字节） |
| 上限 7，同一正文 | （1，空），读取流被取消，读到越界块后不再拉取 |
| 声明 `Content-Length: 11`，上限 10 | （1，空），一个字节也不读 |
| GET 请求或没有正文的 POST | （2，空）；真实 workerd 上没有正文的 POST 也可能得（0，空），应用应把这两种结果都当作“没有正文” |
| 同一请求连续读两次 | 第二次为 3 |
| 正文为单字节 `ff` | 宽松：（0，`U+FFFD`）；严格：（4，空字符串） |
| 正文 `EF BB BF 68 69` | 文字：（0，`hi`）；字节：（0，五个原始字节） |
| 上限 0 或 16777217 | 抛出异常 |

| 有限 JSON，正文 `{"a":1,"b":2,"a":3}` | （0，`{"a":3,"b":2}`） |
| 有限 JSON，正文 `{"a":1e21}` | （0，`{"a":1e+21}`） |
| 有限 JSON，正文 `{bad` | （5，非空原因） |

## 造响应

### 常用响应

- `造结森响应`：状态须为 200 至 599，且不能是禁止正文的 204、205、304。宿主以 `JSON.parse` 校验 JSON（无效时抛出以“JSON 响应正文无效：”起首的异常），写出宿主规范化文字，不超过 2 MiB；设置 `Content-Type: application/json; charset=utf-8`、`Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff`。
- `造空响应`：状态 200 至 599，正文为空，设置 `Cache-Control: no-store`，不设内容类型；204、205、304 在这里可用。
- `造文字响应`：状态 200 至 599 中允许正文者，内容类型不得含 CR、LF（“内容类型含换行”），正文按 UTF-8 发出、至多 2 MiB；设置 `Cache-Control: no-store` 与 `X-Content-Type-Options: nosniff`。
- `造同源改址响应`：状态只能是 301、302、303、307、308；目标须是宿主 `URL.canParse` 可解析的绝对网址（否则“重定向目标不是有效的绝对网址”），且与请求同源（否则“重定向目标不是同源”）。
- `造外址改址响应`：状态同上，目标须是绝对 HTTPS 网址（“外站重定向仅允许 HTTPS”）。目标由应用按自己的路由和配置选择；应用若把未验证的用户输入用作目标，会形成开放重定向。
- `造出站网页响应`：以状态码、标头列表与正文字节直接构造响应。

### 带标头的响应

`造带头文字响应`、`造带头结森响应`、`造带头空响应`、`造带头字节响应` 与 `造带头改址响应` 以调用方给出的**有序标头列表**构造响应。标头列表的类型是 `（列于（字符串合字符串））`，每项是（名称，值），保持顺序，允许同名多项。它们不隐式添加任何标头（内容类型只经参数设置，JSON 版固定为 `application/json; charset=utf-8`）；同名标头按列表原序逐个追加，`Set-Cookie` 各项保持独立；严格校验，违者抛出可捕获的豫言异常，此时不产生响应，应用可另造错误响应。

- `造带头文字响应 状态 类型 标头 正文`：正文按 UTF-8 发出，不超过 8 MiB（“文字响应超过 8 MiB”）。
- `造带头结森响应 状态 标头 正文`：宿主校验并规范化 JSON（无效 JSON 的消息以“JSON 响应正文无效：”起首），规范化后不超过 2 MiB（“JSON 响应超过 2 MiB”）。
- `造带头空响应 状态 标头`：无正文，不设内容类型；204、205、304 可用。
- `造带头字节响应 状态 类型 标头 正文`：正文是任意字节（含零字节），不超过 16 MiB（“字节响应超过 16 MiB”）。
- `造带头改址响应 状态 目标 标头`：状态只能是 301、302、303、307、308（“重定向状态不受支持”）。目标只能是以单个 `/` 起首的路径（第二个字节不得是 `/` 或 `\`），或以 `http://`、`https://` 起首（方案不分大小写）、可被 URL 标准解析、协议为 http 或 https、无用户名口令且主机非空的绝对网址；全文只含 0x21 至 0x7E 的 ASCII 且不含反斜线，长度 1 至 8192 字节（“重定向目标无效”）。标头列表中不得再出现 `Location`。

共同规则（违者一律是可捕获的违规）：

| 项 | 规则 |
| --- | --- |
| 状态 | 200 至 599（“响应状态不在 200 至 599”）。204、205、304 不得带非空正文（“该 HTTP 状态不得带非空正文”） |
| 标头名 | RFC 9110 令牌字符，1 至 64 字节 |
| 标头值 | 只允许可见 ASCII（0x20 至 0x7E）与水平制表；至多 8192 字节；`Set-Cookie` 每项至多 4096 字节 |
| 数量 | 至多 64 项，多个 `Set-Cookie` 各计一项 |
| 禁止应用设置（不分大小写） | `Content-Length`、`Transfer-Encoding`、`Connection`、`Keep-Alive`、`Upgrade`、`TE`、`Trailer`、`Content-Type`、`Content-Encoding`（“响应标头由宿主或参数管理，不得设置”） |
| 内容类型（参数） | 形如 `type/subtype`，其后只能有空白和以分号起首的参数；全文限可见 ASCII 或水平制表，1 至 256 字节（“内容类型无效”） |

HEAD 请求：宿主对 HEAD 响应不发送正文，响应仍按上述规则构造，应用不必为 HEAD 另写分支。

| 情境 | 必须观察到 |
| --- | --- |
| 带头文字 201，头 `X-A: 1`、`x-a: 2`、两个 `Set-Cookie` | 状态 201；`x-a` 合并为 `1, 2`；两个 Set-Cookie 保持独立；只有 Content-Type 与所给标头 |
| 带头空响应 200，列表为空 | 没有任何标头，正文为空 |
| 标头值 `a\r\nInjected: 1`；标头名 `Content-Length`、`content-type`、`TE` | 违规，不产生响应 |
| 带头文字 204 且正文非空 | 违规；正文为空则成功 |
| 带头改址 302 到 `/next?a=1` | 只有 `Location` 与所给标头，正文为空 |
| 带头改址目标 `//evil.example`、`http://u:p@h/`、`javascript:x` | 违规 |
| 65 个标头，或 4097 字节的 Set-Cookie | 违规 |

## 转发与改址

- `造重定向响应 请求 路径`：以 308 重定向到本站路径。路径以单个 `/` 开头，拒绝 `//`、反斜线、控制字符、`?`、`#`（“重定向路径无效”）；宿主以请求的协议和域名构造地址并保留原查询串，不转往外站。
- `转发网页请求 请求 绑定 路径`：把请求转给获授权的绑定，绑定的响应原样作为结果；绑定名 `ASSETS` 是静态资源，其余按 SERVICE 授权表查找；空绑定名失败（“转发绑定名为空”），未授权名或不存在的绑定由宿主拒绝（部署错误，宿主中止本次请求）。路径为空时保留原网址，否则只改路径（规则同 `造重定向响应`，“转发路径无效”），方法、查询、正文流与标头不变。它返回指向在途请求的响应，入口返回后由宿主等待上游，转发全程不经 JSPI 挂起；上游失败使本次请求失败，需要捕获上游失败时用 `转发网页请求并筛标头`。
- `转发网页请求并加标头 请求 绑定 路径 标头`：绑定与路径规则同上。上游响应到达后，复制上游状态、正文流和原有响应头，只覆盖参数列表给出的响应头，不读取或缓冲正文。它与 `转发网页请求` 一样返回指向在途请求的响应，入口立即返回，上游响应由宿主等待；上游失败使本次请求失败。标头列表在发出请求前校验，违者抛出可捕获的豫言异常。允许精确名称 `Content-Security-Policy`、`X-Content-Type-Options`、`Referrer-Policy`、`Content-Type`、`Content-Disposition`、`Cross-Origin-Opener-Policy`、`Cross-Origin-Embedder-Policy`、`Cross-Origin-Resource-Policy`，最多 8 项，非法（“响应标头名称不允许覆盖”）或重复（“响应标头重复”）失败。

### 筛标头转发

`转发网页请求并筛标头 请求 绑定 路径 保留标头 固定标头` 把请求转给获授权的 `SERVICE` 绑定，上游响应原样作为结果。

- 绑定：空名失败（“转发绑定名为空”）；静态资源用 `造静态资源响应`，本函数只按 `SERVICE` 类查找。
- 路径（含查询）：须以单个 `/` 起首（第二个字节不得是 `/` 或 `\`），长度 1 至 8192 字节，不含控制字符、反斜线与 `#`；宿主用原请求的来源加新路径构造目标，不改变主机（“转发路径无效”）。
- 方法与正文：转发原请求的方法，允许 GET、HEAD、POST、PUT、PATCH、DELETE、OPTIONS（其他“转发方法不受支持”）。请求体流原样转发，不读取、不缓冲（GET 与 HEAD 不带体）；请求体已被读取时失败（“入站请求正文已被读取，无法转发”）；不跟随重定向（`redirect: manual`）。
- 标头：只复制保留标头列出的入站标头（最多 16 个名称，每个 1 至 64 字节的令牌，不分大小写不得重复，请求里缺失的略过），再叠加固定标头（最多 16 项，值只允许可见 ASCII 与水平制表、至多 8192 字节，覆盖同名的已复制标头，不得重复）。`Host`、`Connection`、`Keep-Alive`、`Proxy-Connection`、`Proxy-Authorization`、`TE`、`Trailer`、`Transfer-Encoding`、`Upgrade`、`Expect` 不得保留或固定；固定标头还不得设置 `Content-Length` 与 `Set-Cookie`。所复制的入站标头值含控制字符（水平制表除外）时拒绝转发。
- 响应：上游响应的状态、标头与正文流原样作为结果，不读取、不缓冲。服务绑定的 `fetch` 抛出时转为可捕获的豫言异常（“转发到服务失败：名称: 消息”）。

### 静态资源响应

`造静态资源响应 请求 绑定 路径 状态 标头` 从获授权的 `ASSETS` 绑定读取路径，造出响应。参数（绑定名、路径、状态、标头）先校验，违者抛出可捕获的豫言异常；随后在入口里等待资源响应（JSPI 挂起），再按下列规则改写状态与标头。

- 路径：规则同筛标头转发的路径，宿主以原请求的来源加路径构造目标，按 GET 读取，不转发原请求的标头或正文（“静态资源路径无效”）。
- 状态：0 表示沿用资源响应的状态；否则须在 200 至 599（“静态资源状态须为零或 200 至 599”）。
- 标头：以资源响应的标头为底，标头列表里某个名称第一次出现时先删除资源响应里的同名标头，再按列表顺序追加该名称的各项；名称、值、数量与禁用名规则同带标头的响应，资源自带的内容类型不能改写。
- 正文：资源响应的正文流原样交付，不缓冲。请求是 HEAD 时不带正文并取消资源正文流。最终状态是 204、205 或 304 而资源响应带正文且请求不是 HEAD 时，取消资源正文流并抛出可捕获的豫言异常（“该 HTTP 状态不得带静态资源正文”）。
- 资源不存在时 ASSETS 通常返回 404，它照常作为结果，应用可用状态参数覆盖。ASSETS 的 `fetch` 抛出或被拒绝时是可捕获的豫言异常（“读取静态资源失败：名称: 消息”）。

转发路径与静态资源路径中任一段是 `.` 或 `..`（包括 `%2e` 的任意大小写混写形式，后接 `/`、`?` 或路径结尾）时拒绝；形似而非点段的 `...`、`..b`、`.b`、`b..c` 不受影响。

| 情境 | 必须观察到 |
| --- | --- |
| 筛头转发 POST，保留 `Authorization`、`X-Keep`，固定 `Cookie: a=b` | 上游只看到这几个标头与固定头，方法为 POST，路径为新路径，请求体原样，`redirect` 为 manual |
| 上游返回 302 与 `Location` | 结果就是这个 302，不发第二次请求 |
| 保留名含 `Host` 或 `transfer-encoding`，或固定头含两个 `Cookie` | 违规 |
| 请求体分两块，第二块要在上游读完第一块之后才产生 | 转发成功（证明没有缓冲） |
| 静态资源，状态 0，附加 `Cache-Control: no-store`、`X-New: 1` | 沿用资源状态；`Cache-Control` 被覆盖，`X-New` 被追加，`Content-Type` 保持资源原值 |
| 静态资源 HEAD | 状态与标头照旧，正文为空，资源正文流被取消 |

## 后续版本的事项

解压 `Content-Encoding`、解析表单与 multipart、枚举全部标头、内容协商、压缩、1xx 状态与 Trailer 留待后续版本。`Content-Type` 由应用自行校验；带标头的响应只设置调用方给出的标头。流式响应正文由网页事件流包提供；队列、定时、持久对象告警等事件有各自的入口包。
