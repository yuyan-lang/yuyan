# 接口规范未决事项

本文件用于区分“已经写成可审阅的源级契约”与“可宣称完整并可执行的接口标准”。截至 2026-09-29，后者尚未成立。

1. **机器检查**：普通编译器可以导入 `。接口。豫` 并按签名做类型检查（无体签名由语法分析补占位定义，未经绑定调用时抛出“接口函数未绑定”）；纯声明的形状另由独立的[接口检查工具](../豫言操作系统/应用/豫言操作系统接口检查/说明.汉语.md)处理。该工具检查声明形状、包版、直接依赖、函数方向、类型名来源与实现的源级签名；类型构造的完整语义仍待补齐。
2. **版本锁定**：接口检查工具已生成包含完整依赖闭包、逻辑模块、函数方向及源级签名的 JSON 清单，能拒绝依赖环与版本冲突。Node 发行包在启动前核对程序摘要、接口版本、签名与 Wasm 导入导出形状；其他宿主仍须完成相同范围的装载验收。
3. **共同验收**：[一致性样例](一致性样例.汉语.md)仍须补成跨宿主的统一测试。Node 发行包已有 88 项一致性驱动，在 macOS arm64 与 Linux 双架构通过；Windows 尚待验收。浏览器与 CF Worker 的适配尚未与同一套公共接口样例逐项对照。
4. **新增能力包**：字体还没有定稿为公共能力包（持久化键值、流式网络、队列、定时和邮件已分别定为持久事务、网页上游与命名持久服务的渐读、消息队列、定时事件、邮件发送等包；GPU 计算与张量计算已分别定为图形处理器与张量计算包）。网页界面包只覆盖既有元素的文字、受限属性及基本事件；节点创建、选择器与默认动作仍未定义。应用若需要其余能力，须另定义必需包并规定语义、授权、限额、错误、资源寿命和跨宿主适用范围；不能把宿主私有 API 当作公共接口的一部分。
5. **图形处理器与张量计算**：图形处理器 0.1.0 已定设备、缓冲、纹理、着色程序（WGSL 源文字）、命令列表与设备丢失的源级签名，深度模板、多重采样、间接绘制与时间查询尚未定义。张量计算 0.1.0 尚无训练所需的反向算子、融合优化器与写出张量的函数。两者的宿主实现与跨宿主一致性验收仍在进行；不得称这两个接口已经完善。

现有接口包构成**源级接口规范**。要称“可执行且已验证的 0.1 标准”，仍须补齐类型语义检查、各宿主同范围的装载核对与跨宿主公共接口一致性验收。宿主适配的已实现范围见[总体架构](../豫言操作系统/文档/豫言操作系统总体架构.汉语.md)。
