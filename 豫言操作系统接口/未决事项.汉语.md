# 接口规范未决事项

本文件用于区分“已经写成可审阅的源级契约”与“可宣称完整并可执行的接口标准”。截至 2026-09-24，后者尚未成立。

1. **机器检查**：现有普通编译器要求 `乃` 后接实现，普通模块解析只查 `名称。豫`。2026-09-24 对当时的启动接口文件执行普通编译器类型检查，得到“类型声明之后必须紧接其定义：期待定义启动程序，但已经到达文件结尾”；该文件现名为 `程序入口。应用接口。豫`。独立的[接口检查工具](../工具/豫言操作系统接口检查/说明.汉语.md)复用归并前语法树，检查十包声明形状、包版、依赖、按文件后缀确定的函数方向、类型名来源与所给实现的源级签名；类型构造的完整语义仍待补齐。
2. **版本锁定**：现有包依赖只列名称。过渡适配的 `实现接口。豫` 已声明目标包完整身份，检查工具能拒绝版本不等；检查工具已能生成包含包身份、逻辑模块、函数方向及源级签名的 JSON 清单。发行产物仍须记录解析后的完整依赖闭包与内容摘要，并在宿主调用入口前核对；装载实现尚未完成。
3. **共同验收**：[一致性样例](一致性样例.汉语.md)仍是文本。浏览器、CF Worker、Node.js 尚未按这些精确签名做同一套适配和自动验收；各宿主现有私有 API 的存在不等于通过公共接口。
4. **新增能力包**：GPU 计算与字体还没有定稿为公共能力包（持久化键值、流式网络、队列、定时和邮件已分别定为持久事务、网页上游与命名持久服务的渐读、消息队列、定时事件、邮件发送等包）。网页界面包只覆盖既有元素的文字、受限属性及基本事件；节点创建、选择器与默认动作仍未定义。应用若需要其余能力，须另定义必需包并规定语义、授权、限额、错误、资源寿命和跨宿主适用范围；不能把宿主私有 API 当作公共接口的一部分。
5. **图形处理器**：已明确显示呈现与 GPU 计算分包、驱动在宿主下层，但尚未定设备、缓冲区、队列、着色程序表示和设备丢失恢复的源级签名；不得称 GPU 接口已经完善。

当前十包可作为首批**源级接口规范**的讨论基线。源级规范的审阅重点是声明、依赖、方向、错误、限额和生命周期是否足够明确；实现与验收工具不是本次“只定义接口”的交付物。若要进一步称“可执行且已验证的 0.1 标准”，则仍须完成第 1 项的静态检查、为第 2 项确定机器可读清单格式，并把第 3 项的样例落为可执行一致性检查。宿主适配与迁移另行进行。
