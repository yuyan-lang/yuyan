# 豫言系统编程语法与编译架构方案

状态：实施方案 v0.5；2026-09-22。用户已批准按此方向实现。当前已实现中文网页汇编整数核心、参考执行、ARM64/AMD64 整数提前编译及 QEMU 裸机用户态验证。完整指令集、包级无 GC 契约、完整自研 WasmGC、调度与通用操作系统服务仍未实现。文言提要见同名文言稿；评审时以本稿的字段和验收条目为准。

## 一、设计决定

1. 只有一门表层豫言，沿用现有词法、声明、函数、模式匹配和模块语法。
2. 系统约束统一放在包配置中；普通函数不新增 `系统`、`stack`、`linear` 等修饰语。
3. 对象表示、逃逸、借用和效果由编译器自动推断。普通模式允许保留现有实现，受约束模式不能悄悄回退到被禁止的实现。
4. 高层统一 ANF 保留对象、函数和原语语义；其后为直接对应标准 Wasm 的中文 IR，沿用豫言词法、声明与扩展表达式习惯。
5. Wasm 是统一执行边界。豫言应用、编译器和执行器自身均经过 Wasm；其他语言模块也进入同一执行器。自有机器码后端属于 Wasm 执行器，不能另建绕过 Wasm 的高层原生路径作为终局。
6. 最终不依赖 LLVM、clang、外部汇编器、外部链接器和 libc。迁移期建议保留旧后端作差分参考。Wasm 验证后可转为执行器内部 SSA/机器 IR，不要求机器码优化始终使用栈式表示。

统一路径：普通豫言 → 高层 ANF 与自动内存优化 → 中文 Wasm IR ↔ 标准二进制 Wasm → 豫言执行器（解释或编译执行）→ 硬件。中文与二进制是同一模块模型的表示，不要求每次执行都解析中文文本。硬件能力通过受控宿主导入提供，不私增标准指令。

## 二、包级语法

现有 `类型` 继续描述产物，新增同级 `执行约束`，不改变旧字段含义：

```text
「名称」者『初核』也。
「所有者」者『豫言』也。
「版本」者『0.1.0』也。
「类型」者「典」【
  「种类」者『可执行文件』也，
  「入口」者『入口』也，
  「文件名」者『yy初核.exe』也，
】也。
「依赖」者「列」【『机器基础』，『内存基础』】也。

「执行约束」者「典」【
  「规范版本」者『一』也，
  「运行环境」者『裸机』也，
  「托管分配」者『禁止』也，
  「垃圾回收」者『禁止』也，
  「动态分配」者『允许』也，
  「阻塞」者『允许』也，
  「挂起」者『允许』也，
  「异常跨界」者『禁止』也，
  「依赖宿主运行库」者『禁止』也，
】也。
```

这是结构草案，不是可直接交给现有豫构的配置。分发代码为 Wasm，可执行镜像由执行器的提前编译与镜像装配阶段产生。`.exe` 在此沿用工具产物命名约定，不决定对象格式；裸机镜像格式由目标配置决定。

| 字段 | 合法值 | 含义 |
|---|---|---|
| 规范版本 | 一 | 按固定版本解释字段；不认识的版本报错 |
| 运行环境 | 宿主、裸机、可移植 | 宿主允许平台接口；裸机不假定已有 OS；可移植库不声明平台专属依赖 |
| 托管分配 | 允许、禁止 | 是否允许创建由 GC 管理的对象，包括隐含装箱与闭包 |
| 垃圾回收 | 允许、禁止 | 是否允许执行可能触发回收的路径，不等同于是否直接分配 |
| 动态分配 | 允许、禁止 | 动态申请存储，包括托管堆、区域、页池以及可变大小栈申请；固定帧与静态存储不计入 |
| 阻塞 | 允许、禁止 | 是否可能等待外部事件、锁或资源；轮询到外部条件成立也不能冒充保证不等待 |
| 挂起 | 允许、禁止 | 是否允许主动交出执行并在之后恢复 |
| 异常跨界 | 允许、禁止 | 是否允许语言级非局部退出越过包的可调用边界；内部捕获可以允许，但其分配仍需另验 |
| 依赖宿主运行库 | 允许、禁止 | 禁止时产物不能隐含依赖 libc、pthread 等宿主用户态库；不禁止有明确契约的自有运行时 |

字段缺省：整个 `执行约束` 缺省时保持当前行为。版本一的约束典内部，缺省运行环境为宿主，各效果为允许；一旦指定裸机，必须显式写明托管分配、垃圾回收和宿主运行库策略，避免误以为裸机自动代表无 GC。未知键、重复键、非法值报错。`动态分配=禁止` 与显式 `托管分配=允许` 矛盾，配置时报错；省略托管分配时则由禁止动态分配派生禁止。

“允许”只是约束上界，不会自动提供分配器、调度器或硬件权限。“禁止 GC 但允许托管分配”不在首版支持组合中：首版报错，后续若引入明确的预留托管区域，应以新契约支持，不能靠关闭收集器无限泄漏。

命令行可以选择目标或请求更严格检查，不能把包中的禁止改为允许。`-O0` 同样必须满足契约；若当前优化级别无法证明无分配，则报出原因，而不是生成违反契约的程序。

## 三、仍在包内描述特殊入口

第一阶段可将中断代码独立成更严格的库包。需要同包多个入口时，预留包级 `入口约束`，不增加函数声明语法：

```text
「入口约束」者「列」【
  「典」【
    「函数」者『网卡/处理中断』也，
    「用途」者『中断处理』也，
    「动态分配」者『禁止』也，
    「阻塞」者『禁止』也，
    「挂起」者『禁止』也，
    「异常跨界」者『禁止』也，
  】，
】也。
```

函数路径采用包内模块路径加声明名，必须能解析且不能歧义。入口限制与包限制取交集，不能放宽。用途声明不自动生成完整 CPU 中断入口；架构入口桩仍要保存现场、选择栈并执行正确的返回序列。

对可执行包，从程序入口、初始化代码、外部导出、注册回调和中断入口开始分析。对库，公开可调用的导出构成承诺边界。依赖库只检查实际可达部分，内部无关的 GC 函数不使调用失败。间接调用必须有可证明的目标集合或效果摘要，不能遗漏未知目标。相同函数可用于不同上下文；若发生专门化，其代码和摘要必须独立标识。

## 四、机器类型与运算语法

新增类型与操作通过标准库形式公开，不增加一套类似 C 的表达式语法。拟议包 `机器基础` 提供 `无符号八位`、`无符号十六位`、`无符号三十二位`、`无符号六十四位` 及对应有符号类型；浮点类型、机器字和向量按目标能力扩展。普通 `整数` 的既有含义保持不变。

示意函数仍使用当前声明与定义形式：

```text
寻观「机器基础」之「字六十四」之书。

「累加字」乃化「无符号六十四位」而化「无符号六十四位」而「无符号六十四位」也。
「累加字」者会「甲」而会「乙」而
  「回绕加」于「甲」于「乙」也。
```

规则：

- 每个新机器类型是独立类型；不隐式在指针、整数或不同宽度间转换。
- 提供明确命名的 `回绕加`、`检查加`、`饱和加`，分别定义模运算、返回溢出结果、钳制结果；不由编译模式更改普通加法。
- 检查转换返回无堆分配的固定表示结果；截断转换显式命名，不能混称检查转换。
- 原始移位的超宽行为固定定义，建议模位宽；需要拒绝超宽时另用检查操作。除零及有符号最小值除负一提供明确失败结果或明确陷阱操作，不引入 C 式未定义行为。
- 初版不增加数字后缀，常量通过机器类型模块的转换/构造操作形成；编译器可在编译期折叠且必须检查可表示性。
- `机器字` 宽度属于目标参数，必须在模块与 ABI 校验中记录；可移植源码不得假定总是六十四位。

## 五、外部布局仍用包配置描述

普通元组、构造器和闭包继续由编译器选择布局。只有硬件、网络格式和外部接口需要固定布局时，给类型增加包级布局契约：

```text
「外部布局」者「列」【
  「典」【
    「类型」者『设备类型/描述符』也，
    「字节数」者『十六』也，
    「对齐字节数」者『八』也，
    「字节序」者『小端』也，
    「字段」者「列」【
      「典」【「名称」者『地址』也，「类型」者『无符号六十四位』也，「偏移字节数」者『零』也，】，
      「典」【「名称」者『长度』也，「类型」者『无符号三十二位』也，「偏移字节数」者『八』也，】，
      「典」【「名称」者『标志』也，「类型」者『无符号三十二位』也，「偏移字节数」者『十二』也，】，
    】也，
  】，
】也。
```

数值字段首版使用严格中文非负整数字符串，由配置检查器解析，不执行配置表达式。检查对齐、越界、重复字段和重叠；首版不支持隐式联合体。该契约针对具名的无托管引用记录，不能给任意多态对象强行加布局。需要补充“具名字段记录”类型时，优先复用现有名义类型与构造器机制，生成受类型检查的字段接口；不能仅由一段任意字符串替代类型定义。

固定布局的内存视图与按值记录区分。打包网络格式的非对齐字段通过明确的加载/存储操作处理，不能把它直接当作本机自然对齐结构地址。

## 六、内存、借用与自动分析

拟议 `内存基础` 提供名义类型：区域、只读视图、可写视图、拥有的内存块，以及物理地址、虚拟地址和设备地址。其构造权限不同，普通模块不能从整数伪造有效内存能力。

自动选择顺序不是硬性速度承诺：优先尝试对象消除/局部值；根据寿命和成本选择固定栈帧、调用者区域或允许的堆。局部不逃逸对象可以有多个局部别名；只有原地复用或所有权转移等操作才要求更强的唯一性证明。

长寿命非 GC 对象通过有明确生命周期的区域/页池承载，不要求所有非 GC 对象都上栈。设备缓冲区必须遵守地址稳定、对齐、DMA 映射和完成通知协议。跨线程/设备转交用接口状态描述，编译器检查使用关系；不会假装从普通程序控制流自动获知设备已经完成传输。

首版建议采用“在区域作用域内执行回调”的安全接口，区域身份由编译器生成并检查，禁止借用逃出区域。普通程序不写寿命变量；需要跨接口持久存储时，在区域/资源接口中明确承载关系。所有权错误须报出建立别名、逃逸与失效位置。

系统模式中的分配失败由显式结果处理，结果不得为错误报告再次分配。已有普通数组操作的语义不能被悄改：如果自动降级无法保留原失败行为，应拒绝该用法并建议采用系统内存 API。首版系统对象不允许在未追踪的裸内存里存 GC 引用。

## 七、原子、硬件与不受信任边界

原子操作与 MMIO 为不同的标准接口。高层原子内存序必须能保持语义地降到所选 Wasm 特性集，不假定每种原生内存序都有对应指令；MMIO 接口要求寄存器宽度、地址能力及平台规定的屏障。禁止把普通加载优化规则用于设备访问，也不能以 volatile 代替跨核同步或 DMA 协议。

硬件能力申请可在包中列出，但声明本身不授予权限。最终镜像的受信任平台配置决定哪些包可以构造能力；普通代码只能传递和使用获得的能力。页表、中断返回、特权寄存器与 MMIO 经版本化的平台宿主导入提供。执行器可为已授权且身份确定的导入生成内建机器序列；不能仅凭可伪造的模块名授予权限。普通线性内存加载不获得 MMIO 语义。最小平台机器序列由执行器后端生成，其余逻辑仍由豫言经 Wasm 实现。

初期平台支持限于单核。多核必须另行定义数据竞争语义、原子操作和所有权转移，不在未定义内存模型的情况下宣称类型安全即可避免竞争。禁止阻塞、禁止 GC 不等于硬实时；时间界、栈界与循环界是另外的验证目标。

## 八、模块互操作与 ABI

公共生态边界以 Wasm 导入/导出为基础，包级示意如下：

```text
「外部接口」者「列」【
  「典」【
    「方向」者『导入』也，
    「函数」者『系统服务/读取文件』也，
    「调用约定」者『Wasm核心』也，
    「模块」者『系统』也，
    「符号」者『read_file』也，
  】，
  「典」【
    「方向」者『导出』也，
    「函数」者『应用/处理请求』也，
    「调用约定」者『Wasm核心』也，
    「符号」者『handle_request』也，
  】，
】也。
```

第一版建议使用定宽数值、明确内存实例中的偏移与长度、资源句柄。内存归属、分配释放、借用期限、回调环境和重入均须有契约，不能将 WasmGC 引用当作其他语言的字符串或裸地址。不同实例的相同偏移不代表同一地址。C ABI 仅用于执行器与原生宿主的适配，不再是普通包的统一 ABI。

实例化器负责连接导入导出；运行时双向回调不等于能够无条件实例化循环依赖，循环需要连接和初始化协议。首版先验收无环装配加双向回调。默认独立内存，授权后共享；零拷贝要求同一存储及借用/同步协议。外部模块自报的无分配或无重入摘要不能直接信任。

Component Model/WIT/Canonical ABI 建议作为后续接口层，不作为首版全部实现的前置条件。WASI 是需另外提供的宿主接口，须声明版本和接口集合；浏览器专用模块也需适配。不能承诺所有 .wasm 无需适配即可运行。

## 九、中文 Wasm IR

### 9.1 现状与统一模型

已有表达式树阶段文本支持往返；独立高层 ANF 尚需完整文本编解码。现有 Wasm 后端生成 WAT，再由宿主组装；这不等于已有中文 Wasm IR。新增模块数据结构应由中文读写、二进制编解码、验证器、优化器和执行器共享。

文件建议为「名称.统一正则。豫」及「名称.网页汇编。豫」；后者声明格式版本与 Wasm 特性集合。沿用豫言词法和标点，但按 Wasm 模块规则解释，不执行普通豫言代码来解码。标准 .wasm 为必要交付格式。

### 9.2 语法与对应

推荐完整指令序列为规范形式，可折叠表达式为可读形式。折叠按固定求值顺序展开；规范形式覆盖多返回值、块参数、不可达代码及完整操作数栈规则。区域/所有权操作在高层降为标准操作或明确契约的调用，不私增 Wasm 指令。

```text
「求和」者「《《函数》》」【
  「参数」者「列」【
    「甲」者「《《整数三十二位》》」【】也，
    「乙」者「《《整数三十二位》》」【】也，
  】也，
  「结果」者「列」【「《《整数三十二位》》」【】】也，
  「函数体」者「《《整数三十二位加》》」【
    「《《局部读取》》」【『甲』】，
    「《《局部读取》》」【『乙』】
  】也，
】也。
```

这是未实现的函数片段，完整模块另含标头、特性及接口。中文操作名通过版本化映射表对应标准操作码和立即数。i32/i64 不分有符号/无符号，相关运算指令才区分；高层八/十六位及有符号类型正确降级，不冒充新的 Wasm 值类型。模块覆盖所选特性集中的类型、函数、表、内存、全局、段、启动函数和接口等结构。

数值溢出、端序、陷阱、浮点和引用均遵循锁定版本的 Wasm 语义；不能把某次执行的浮点 NaN 位模式误作标准唯一结果。中文操作不引入隐含分配。

### 9.3 往返与验证

支持的外部 .wasm 可读入中文 IR 再编码，保持标准允许的语义与接口；未知特性明确拒绝。名称、调试、自定义段另定保留规则，语义往返不等于二进制逐字节一致。优化改变索引或偏移时，相关元数据必须更新、拒绝或明确移除，不能保留失真证明。

Wasm 核心验证检查标准类型、索引、操作数栈和控制流；系统约束验证另行进行。合法 Wasm 不自动具备无 GC、区域安全或硬件权限证明，自定义段中的“已证明”不构成证据。

中文格式原则上覆盖锁定标准，执行器可分阶段实现特性，两者分别列支持清单。当前普通豫言已经使用 GC 结构/数组、引用转换及尾调用；最小 Wasm 执行器不能直接运行现有编译器。

### 9.4 内存与执行域

建议系统包使用无 GC 的线性内存子集；普通豫言保留 WasmGC，自研执行器逐步补齐 GC。不要为缩小首版执行器而默认重写普通豫言对象表示。

包级“禁止垃圾回收”约束该路径及调用，不天然保证其他模块回收时不会暂停它。若内核关键路径必须不受应用 GC 暂停影响，还需隔离回收域、根扫描、调度及执行器锁，校验跨域调用；独立线性内存本身不构成证明。此强保证待用户裁定。

Wasm 操作数栈不是可寻址对象栈。自动栈对象先用线性内存帧；执行器证明安全后可消除或放入机器栈。外部回调要求嵌套帧、重入和退出清理，现有依赖无重入条件的优化不能无条件延用。

## 十、效果推断与诊断

分析包含显式操作和降级隐含操作：装箱、闭包环境、错误消息、栈扩容、初始化、外部桥接和回收安全点。高层分析指导优化，低层复验最终承诺。消除掉且没有可观察效果的分配可以从最终摘要中去掉；未证明消除的不能省略。

递归调用组求保守不动点；跨模块摘要记录版本、源/IR 身份和目标参数，缓存失效必须传播。高阶函数摘要描述参数回调的效果，实例化后再检查。分析超预算时普通模式采用保守实现，系统模式给出“证明不足”，不得放过约束。

诊断至少包含包/入口、违反的要求、调用链、具体操作及可行的修复方向，例如：

```text
包「网卡中断」要求禁止动态分配。
调用链：处理中断 → 记录状态 → 整数转字符串。
整数转字符串需要托管分配；此分配未被消除。
可将日志写入预分配记录缓冲区，由普通线程格式化。
```

未使用依赖不应导致伪失败；注册到外部的回调、导出入口、模块初始化不能漏检。包中有不同约束时，有效要求随调用上下文传播，不由被调用方“允许”字段覆盖调用方的禁止。

## 十一、执行器与独立自举路线

机器码生成属于 Wasm 执行器，可使用内部 SSA/机器 IR。Wasm 边界不要求永久牺牲内联：固定装配图可在保持语义、权限与公共接口的前提下跨模块优化；动态替换须另定失效规则。

| 阶段 | 交付与验收 |
|---|---|
| A：统一表示 | 中文模型、文本读写、二进制编解码与验证；接入现有生成路径；外部模块往返 |
| B：最小执行器 | 豫言实现选定子集解释器；跨语言双向调用，验证内存、陷阱、重入与权限 |
| C：自有提前编译 | Wasm → 执行器内部 IR → 机器码；指令选择、寄存器分配、对象、重定位及镜像；无需外部汇编/链接器 |
| D：托管与系统能力 | 覆盖现有豫言所需 WasmGC 等特性与宿主服务，满足所选内核隔离契约 |
| E：独立自举 | 编译器和执行器都由豫言经 Wasm 生成，上一代提前编译下一代执行器，独立完成固定点验证 |

解释器用于正确性验证，不是性能终点。建议先提前编译（AOT），后即时编译（JIT）。动态加载可先解释；资源耗尽和权限需执行器管理，类型验证不限制无限循环或资源消耗。

执行器自身经过 Wasm，首次用已有工具种子引导；后继 AOT 生成原生执行器镜像。平台导入绑定到可信实现，必要特权操作由后端编码；不需要启动时无限嵌套解释器，也不宣称硬件动作可全部由标准 Wasm 指令独立表达。

已确定先实现编译与执行架构，再实现裸机操作系统。裸机目标为 ARM64 与 AMD64，均以 QEMU 验证，不再建议 RV64 作为首要目标。共用核心模块和平台接口，两套机器编码、启动及设备适配分别验收；宿主开发环境不等于最终 OS 平台。

LLVM 和 libc 分别验收。最终禁用 LLVM/clang、cc、as、ld 和系统 libc，仍能生成可运行镜像及后续编译器。检查实际构建调用、动态依赖、未定义符号和固定点。测试参考引擎与产品构建依赖分开；初始种子来源与后继独立性分论。

性能报告分别记录模块生成、AOT/缓存准备、运行及完整冷自举墙钟，不把必要 AOT 工作藏到计时外。完整冷自举 ≤30 秒仍为目标，部署模式确定后冻结计时边界，解释器成功不代表性能达标。

## 十二、第一批开发建议

已批准先实现架构。建议先冻结中文 Wasm 模型和特性清单、接通现有生成路径，再做互操作与最小执行器；包级效果分析逐步接入。不立即重写全部 GC、实现 JIT 或完整操作系统。

文档只做一致性及格式检查。编译器实现后按仓库要求运行类型检查、完整自举及 Wasm 回归。通用 Wasm 优化需外部语言模块和语义差分验证；既有豫言高层优化不能自动算作通用 Wasm 优化。

## 十三、已澄清方向与微内核边界

用户已明确：先实现架构，后开发裸机系统；裸机支持 ARM64、AMD64，使用 QEMU；机器码生成器用豫言编写，中文命名与说明，按架构规范直接编码字节，不编写英文汇编源文件、不依赖外部汇编器。普通豫言保留 WasmGC，系统模式约束非 GC 路径。

WAT 是标准文本表示，不规定机器寄存器、原生栈布局或 CPU 特权切换。中文 IR 对应标准模块类型和导入/导出；执行器内的调用桥按平台调用约定实现参数、结果、陷阱和回调传递。第三方模块的导入/导出名字属于外部数据，必须原样保留，不能为中文化改名而破坏互操作。自有代码、编码函数、诊断使用中文；标准 WAT 可作为导入/导出的交换格式，不作为必须人工维护的英文源码。

机器编码建议使用中文字段化构造函数，检查寄存器号、立即数范围、位域、位移和重定位后生成字节；不要在各处散写未经验证的字节常量。按两种架构规范分别测试编码和执行。此机制只属于受信任后端，不赋予普通 Wasm 模块执行任意机器字节的权力。

用户倾向微内核。建议最小特权核心仅保留地址空间与必要物理页管理、线程调度、中断分发、权限及进程间通信。完整 Wasm 加载器、解释器、AOT 服务和 WasmGC 放在用户态；文件系统、网络、一般驱动也是用户态服务。服务所需硬件能力由内核授权，设备 DMA 隔离还需平台设备隔离机制或受控缓冲区，Wasm 边界检查不能代替。

系统镜像包含自有执行器，不等于完整执行器必须运行在 CPU 特权态。核心可由豫言经无 GC Wasm 提前编译成原生镜像，运行时不必在核心内嵌一个完整解释器。若确实要求核心内动态解释模块，需要另定受限子集与可信边界；目前不将其设为默认。

建议每个隔离执行域有独立的托管堆及根，应用回收在用户态执行，可被内核抢占，不要求内核参加应用的全局停顿。标准 Wasm 不规定操作系统调度、GC 暂停上界或微内核架构；这里是系统设计约束，不以“符合标准”冒充已证明不会阻塞关键路径，也暂不承诺硬实时。

用户已确认默认所有组件在用户态，特权核心只保留无法安全委托的最小硬件机制；系统自带执行器作为用户态服务。此项不再待澄清。第一批实现从中文模块表示、严格编解码、独立验证及参考执行开始。

工程默认建议：先核心模块后组件模型；先 AOT 后 JIT；默认内存隔离、显式共享；语义往返优先；迁移期保留旧工具链参考，最终编译器和执行器自身独立。用户可在相应阶段调整。

## 十六、双架构裸机里程碑

2026-09-22，已用豫言生成 ARM64 ELF64 与 AMD64 多重引导镜像。用户模块先成为标准 Wasm，再由自有整数后端提前编译；平台层直接编码机器字节，配置静态页表并进入真实用户态。两种架构的正常计算、内核页隔离、错误结果、放开权限、操作数栈超限及调用栈超限共十二项 QEMU 检查通过。镜像生成器自身经过 Wasm 执行时，产物与原生生成器逐字节一致。

源码与可复现入口在「工具/豫言裸机」；限制及平台假设以其双语说明为准。本里程碑是微内核启动原型，不表示已具备进程调度、文件系统、动态 Wasm 加载或完整 WasmGC。它实现了有限整数子集的机器码后端，未把生产编译器全部迁入新路径。
