# 底层模式（无垃圾回收编译模式）

底层模式是豫言编译器的第二种编译模式：用**普通豫言语法**书写执行器、驱动、文件系统等系统代码，编译时不使用垃圾回收，也不依赖标准库运行时，直接生成只含整数指令的标准 Wasm 模块，可被豫言操作系统的寄存器降级后端编译成裸机机器码。它取代此前自造的括号式“低阶语言”：语言只有一种，差别在于编译模式。

## 一、声明模式：在包描述里

编译模式是**包的属性**，在 `包名。包。豫` 中用可选字段声明，不看文件扩展名，源文件仍一律是 `。豫`：

```
「编译模式」者『底层』也。
```

- 取值只有 `高级`（缺省，有垃圾回收）与 `底层`。
- 同一依赖闭包内的包必须同一模式。豫构在解析包图时检查，不一致即报错；因此底层包不能依赖标准库，只能依赖底层包（如 `底层库`）。
- 豫构读取该字段，把“底层包文件列表”写入传给编译器的包上下文（第三版格式，仅在含底层包时出现；无底层包时上下文与旧版字节相同，缓存不受影响）。编译器据入口文件所属的包选择管线。
- 底层可执行包的产物是 Wasm 模块而非原生程序：豫构不做原生链接，`「文件名」` 仍须以 `yy` 开头或以 `.exe` 结尾（如 `yy客体执行器.wasm`）。

## 二、语言子集

底层模式沿用全部豫言语法与类型检查；差别只在**后端能接受什么**。凡不可入无垃圾回收之境者，编译期明确报错，不会退回垃圾回收。

| 支持 | 不支持（报错） |
| --- | --- |
| 整数、爻、单元 `元`、`若…则…否则`、`虑`、`；` | 元组、构造器（枚举）、`鉴` 于构造器 |
| 对整数常量的 `鉴`（编译为分派） | 字符串值、小数、异常、续延 |
| 一阶函数：全局函数、局部函数（按调用处使用情况处理，见下） | 闭包、把函数当值传递、间接调用 |
| 自递归与尾调用（尾位置的自调用变成回跳） | 引用类型 `引用类`、数组、字典等运行时数据结构 |
| 外部调用原语（见 `底层库`） | 未在 `底层库` 中给出的外部调用名 |

所有值统一为**三十二位整数**（`i32`）：整数按补码回绕；爻为 0/1；单元为 0。函数恒返回一个整数。

## 三、函数与循环

- **顶层函数**：`「名」乃化…也。「名」者会…也。` 编译为 Wasm 函数；仅被导出函数（见下）沿调用图可达者才会生成。
- **自递归**：豫言编译器已把满参递归提升成全局函数；后端把尾位置的自调用改成回到函数起点的跳转（`br`），非尾位置的自调用是普通调用。互递归需要自行改写（豫言无前向引用）。
- **局部函数**（`虑「f」者（化…）也（会…）而`、`递归虑「f」其…者…而`）按使用情况三选一：
  1. 不被调用：丢弃；
  2. 只被调用一次且不自调：展开进调用处；
  3. 只被调用一次且自调都在尾位置：做成**内联循环**（共用外层函数的局部变量，可读写外层的可变格）；
  4. 其余：提升为全局函数，自由变量作为前置形参（**不能捕获可变格**，否则报错）。
- 因此惯用写法是“单次调用的局部递归函数 = 循环”。

## 四、可变格

`新格`、`读格`、`写格` 提供函数内的可变变量：

```
虑「和」者「新格」于「零」而
虑「位」者「新格」于「零」而
递归虑「当」其化「有」而「整数」者会「无」而
  若「小于」于（「读格」于「位」）于「数」
  则（（「写格」于「和」于（「加」于（「读格」于「和」）于（「读格」于「位」）））；（「写格」于「位」于（「加」于（「读格」于「位」）于「一」））；「当」于「元」）
  否则「读格」于「和」
而「当」于「元」
```

格编译为 Wasm 局部变量，必须直接由 `虑 名 者 新格 … 而` 绑定，且只能作 `读格`/`写格` 的首个实参；不能作为普通值传递或被提升函数捕获。

## 五、内存、静态数据与声明

- 线性内存的读写：`读四`、`读二`、`读二有符号`、`读一`、`读一有符号`、`写四`、`写二`、`写一`；`内存页数`、`内存增长`、`内存复制`、`内存填充`。
- 顶层值定义必须是**编译期常量**：整数常量、常量间的整数运算、对其他常量的引用、`静态串` 的结果。它们在函数里出现时被代入为数字。
- **声明**是顶层值定义：`「内存」者（「声明内存」于「初始页」于「最大页」）也。`；`「数据区」者（「声明数据区」于「起」于「止」）也。` 各只能声明一次；使用 `静态串` 前须先声明数据区（编译器先求含声明的定义，故书写顺序无关）。
- `「串址」者（「静态串」于『你好』）也。`：把字符串按 UTF-8 加零字节放入数据区，值为其地址；相同内容共用一份。

## 六、导入与导出

- **导出**：定义名以 `导出：` 开头的函数是模块的导出函数，导出名是其后的部分（`「导出：启动」` 导出为 `启动`）。只有导出函数及其调用图会被生成。
- **导出签名**：导出名后可再加 `：参数数：结果数` 指定 Wasm 签名，例如 `「导出：启动：0：0」`（豫言里 `有 → 有` 的函数导出成无参无果的入口）。总装时为它生成一个包装函数：形参比所定多出的补 0，所定结果数为 0 时丢弃返回值；没有后缀的导出函数照原样导出（每个豫言形参一个 i32，结果一个 i32）。
- **导入**：外部调用名 `导入：模块：字段：参数数：结果数` 是对宿主函数的导入，如 `《《C调用》》名『导入：平台：写字节：1：0』传「字节」`。结果数为 0 时值为单元 0。参数数为 0 的导入（如 `导入：平台：读字节：0：1`），调用处按豫言的写法传一个单元 `无`，生成指令时丢弃这个实参。

## 七、分派

对整数变量的等值判断链（包括对整数常量的 `鉴`）会合成分派：不多于四项时逐项比较，更多时按键折半。同键取先者。

## 八、编译管线

底层模式下每个文件依次做：语法分析、名称解析、类型检查、类型擦除、跨模块优化、**闭包前优化**（到此为止，不做递归转换、闭包环境、全局存储、函数提升）。入口文件的最终阶段由底层后端读取各文件的闭包前优化形式：

1. **读取**：把树转成无类型简树，给每个绑定分配全局唯一名，拉平柯里化调用，把局部函数收成 `局函`，拒绝闭包、元组、构造器、异常、续延、字符串值；
2. **顶层常量**：按需求值；先求含声明的定义；
3. **化简**：代入字面、折叠纯整数运算、静态串定址、常量引用取值，`令 x = v 于 若 x …` 且 x 不再出现时并成 `若 v …`；
4. **提升**：如第三节；全局函数里的尾自调化为回跳；等值链成分派；
5. **生成**：每个式在操作数栈上留一个 i32；局部下标形参在前、按作用域分配、同级分支复用；分派用嵌套块加决策树；
6. **总装**：从导出函数沿调用图收集可达函数，附导入、内存、数据段，编码并**验证**为标准 Wasm 二进制。

## 九、验证与工具

- **回归示例** `测试/底层示例`：底层包，只依赖 `底层库`，覆盖尾递归、非尾递归、分派、内联循环、可变格、位运算、多参数、无符号比较、静态串与内存。构建：`./yy豫构 构建 底层示例 --输出 /tmp/yy底层示例.wasm`。
- **宿主侧校验器** `工具/底层测试`：`yy底层测试 模块.wasm` 读入模块，做标准验证与二进制往返，装配成带内存与数据段的状态实例，在宿主整数执行器里逐项调用导出函数并核对结果（二十六项）。
- **试验工具** `工具/底层生成`：`yy底层生成 读|编译 …` 直接读阶段文本，便于检查简树与生成结果；开发后端时不必重建编译器。
- 豫构测试 `工具/豫构/包资料。测试。豫`、`包系统。测试。豫` 覆盖编译模式字段、依赖闭包同模式检查与第三版包上下文往返。
- 编译器改动按 `AGENTS.md` 三轮自举校验：`yy3_bs` 与 `yy4_bs` 字节一致，并通过 `--type-check-only`。
