# 中间阶段性能

测量日期：2026-09-08，本机 arm64，完整构建默认 18 个工作进程。按用户指定，以每种模式多次运行的**最短完成时间**比较，不用平均耗时判断回退。机器上其他任务仍在运行；本任务的基准顺序执行。

最终版本最短冷构建：JSON 单导出 **43.43 秒**，双导出 **45.16 秒**，额外 **1.73 秒（约 4.0%）**。热缓存最短时间为 **5.00／5.48 秒**，额外 **0.48 秒**。之前稳定的 80–92% 大幅增幅已不再出现，但本轮数据仍有小幅额外开销，不能称为零回退。

两种模式的下游都只读取 JSON，进程内已有 IR 则直接复用。源码解析时间不在正常双导出的读取路径上。

## 编码、写入和重解析

`阶段源码性能。豫` 先读取同一真实阶段 JSON 并恢复 IR，再分别计量 JSON 编码、源码编码、源码写入和源码重解析。文件最初的读取与 JSON 解码不计入编码时间。每个样本运行三次，下表每个耗时列各取最小值；各列的最小值不能相加当作一次完整运行时间。

| 样本 | JSON 字节 | 源码字节 | JSON 编码 ms | 源码编码 ms | 源码写入 ms | 源码重解析 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 多态列：词法形式 | 149,040 | 19,096 | 14.847 | 0.008 | 0.281 | 2.352 |
| 表达式解析：闭包形式 | 526,256 | 358,978 | 54.626 | 3.995 | 0.250 | 742.859 |
| 表达式解析：代码生成前形式 | 3,981,604 | 2,126,025 | 357.324 | 19.321 | 0.557 | 4,339.199 |

九次均将重解析后的 IR 再编码为 JSON，与输入 IR 的规范 JSON 逐字节比较，通过。深树样本也完成了重解析。文本重解析使用完整的共同语法解析器，成本明显高于单纯编码；正常编译不走这条读取路径。

词法文本直接保存原始源码，并用共同词法器恢复令牌。将令牌硬打印成长元组的初稿在同一样本上曾耗时约 84 秒，已移除该表示；当前约 2.35 ms。原始空白、注释和位置不因阶段标头改变。独立输入会验证源码与令牌一致，普通 JSON 缓存读取不会重做词法。

```sh

./yy源码性能 产物.json 阶段名 /tmp/产物。豫
```

## 已完成的性能修正

- 直接从有类型的 IR 字段输出源码，删除“节点 JSON 元数据再转文本”的过程。
- 保留自然定义、函数、调用、局部绑定、分支、元组和函数类型；仅降级操作用 `「《《扩展名》》」【…】`。
- 使用显式输出任务栈和片段合并，避免递归拼接整棵子树。
- 字符串转义及标识符检查直接扫描字节，不逐字符创建列表。
- 词法文本直接保留原始源码，避免展开巨大令牌元组再经通用表达式解析。
- 文件写入先直接打开，仅目录缺失时才创建父目录；不重复逐层执行 mkdir/stat。
- JSON 决定阶段缓存有效性。只缺文本时从 JSON 补导，不重跑编译阶段，不修改 JSON 时间戳。

缓存补导回归已验证：分别删去闭包文本与最终版本的词法文本后，均补回内容相同的文本，JSON 内容及修改时间不变，最终编译器也不变。另已通过源码往返、手写源码作用域、词法一致性、文件写入、逐阶段独立进程直到 LLVM、自举固定点与类型检查验证。独立对象链接运行输出“捕获值”。
