# 豫言操作系统底层接口方案

状：设计之议，二〇二六年九月二十六日，尚未成；文中目录、包名、函数名、布局，皆议案，非今之功能。汉语本见[汉语版](豫言操作系统底层接口方案.汉语.md)。本篇不改[豫言操作系统接口](../豫言操作系统接口/总纲.文言.md)（下称 GC 接口）与[统一接口方案](豫言操作系统统一接口方案.文言.md)，唯增一并列之非 GC 接口树。

## 术语

- **非 GC／底层**：编译之模曰“底层”之代码。值唯三十二位整数，无垃圾回收（[底层模式](底层模式.文言.md)）。
- **垫层**（shim）：以一种接口译为另一种接口之一层代码。
- **后端**：于某平台实现底层接口之实现包（Linux 后端、裸机后端之类）。
- **柄**（句柄）：平台所颁之非负整数，指一已开之文件、目录、套接字、管道或进程。
- **出址**：调用者所供之内存址，被调者书结果于其处。
- **HAL**（硬件抽象层）：内核中最近硬件之一层（中断、页表、设备寄存器、驱动），唯内核用之，应用不涉。本案不含 HAL。
- **裸机**：吾自造、径行于硬件（或 QEMU）之豫言操作系统。

## 一、目的与界

**目的。** 于仓库根目录增设 `豫言操作系统底层接口/`：一套无垃圾回收、数据形唯整数与地址之操作系统接口，以**至少之代码**接 Windows、macOS、Linux 与裸机，且诸平台不重复其共同者。

**用者唯二，应用不径呼之：**

1. **WASI 垫层**：使外来工具链（wasi-sdk 之 C／C++、Rust 等）所编之 WASI preview1 程序接于底层接口。
2. **GC 垫层**：使豫言 GC 程序经 `yuyan:gc-host/v1.call` 所发之系统原语（印、读写文件、环境、时间……）接于底层接口。

非 GC 应用径用 WASI，不另造应用面之 ABI。

**不为：**

- **不作 HAL。** 中断、分页、设备寄存器、驱动、调度，留于内核，属裸机后端之内（第九节）。底层接口唯载“应用日常求于系统者”：时钟、随机、读写文件、标准流、套接字、进程、等待。
- **不含垃圾回收、浏览器、Worker、云能。** 此皆 GC 接口树与各宿主之事。
- **不含垫层中可以豫言算得者：** HTTP、TLS、JSON、日期拆分、路径规整、当前目录。底层唯给原始之能。
- **不含线程。** 首版单线。
- **不含显示与输入。** 第六节预留，第二版再为。

**三约束（出于本案之志）：**

1. **豫言为先。** 垫层与诸平台后端，皆以豫言（底层模式）书之，不增 C 文件；非豫言者，唯许“入操作系统之入口表”（第十一节）。
2. **无重复之代码。** 凡可共者，写于垫层一次；诸平台后端，唯作“接口函数对本平台之呼”之薄映。
3. **小。** 第一版接口不逾五十函数。接口之大小，径定每平台之移植量。

## 二、今状（据今仓库）

- **GC 侧。** [豫言操作系统接口](../豫言操作系统接口/总纲.文言.md)凡五十二源级接口包、二百六十七函数之声明，以豫言值类型（字符串、列、变体……）书之。浏览器与 CF Worker 上，以豫言所书之适配包（`豫言操作系统/适配/`）行之，落于宿主库所声明之 `C调用` 名，皆经唯一之 Wasm 导入 `yuyan:gc-host/v1.call`（[规范](语言技术规范/网页汇编接口.文言.md)）。`call` 乃随需而增之外调之道：标准库声明一百零三名，云工宿主库三百三十六名。不冻结，亦不必与接口函数一一相应。
- **底层侧。** 执行器 `客体二号` 乃底层模式之豫言程序，诸值皆三十二位整数。其自平台导入内核服务十五（[平台。豫](../工具/豫言裸机/客体二号/平台。豫)：读写控制台字节、退出、二钟、询中断、复制／候／收任务、邮箱），文件系统与 virtio 块设备驱动在执行器之内（[客体文件系统](../工具/豫言裸机/客体文件系统.文言.md)）。其行 `call` 之七十二原语（`主机*.豫`，约一千四百行）。内核调用之约，今至多传二参。
- **桌面侧。** 原生 LLVM 一路之运行时以 C 书之（`运行时支持库/原生/`，`豫言_*` 入口，统一之 `豫言值` 型）；别有 Node 夹具，以调试执行器。
- **WASI。** 已析为独立之库[WASI库](../工具/豫言裸机/WASI库/说明.文言.md)（未接入，不保其可用），昔径倚执行器之内。
- **工具之缺。** 接口检查器唯能定位自身、`标准库` 与以 `豫言操作系统` 起首之包，不得 `底层库`。试之：一唯整数、含六参之函数及双语注释之底层接口包，可解析，而滞于依赖之定位。

## 三、总体之构

```text
WASI 应用（wasm32）                GC 应用（豫言，经 call）
       │                                   │
   WASI 垫层                         GC 垫层（今 主机*.豫）      ← 豫言底层模式，书一次，在执行器中
       └────────────────┬──────────────────┘
                        ▼
       豫言操作系统底层接口（本篇）           ← 源级接口包：整数之签；构建之时绑于某后端实现包
                        ▼
       平台后端实现包（每平台一，以豫言书之）
          ├ 裸机：内核服务，加执行器内之用户态文件系统
          ├ Linux：系统调用入口表
          ├ macOS：libSystem 导入表
          └ Windows：kernel32／ntdll 导入表
                        ▼
       操作系统之入口（非豫言者唯止于此层：调用号或导入符号之表）
```

要点：

- **接口为源级，其式同 GC 接口：** `名称。包。豫`、`名称。接口。豫`、`规范.汉语.md`、`规范.文言.md`。所异者：包描述书 `「编译模式」者『底层』也。`，依 `底层库`，签中唯有 `整数`。旧规“同一依赖闭包之内，编译之模必同；底层之包不得依标准库”（[包依赖。豫:60](../库/包配置/包依赖。豫)）保此诸包不混入 GC 之型。故“何包属非 GC 接口”，由包描述之编译模式定之，可由机器校之。
- **构建之时绑。** GC 接口以 `yy豫言操作系统绑定` 绑接口包于适配包；底层接口同然，构建之时绑接口包于平台后端实现包。接口函数乃源级函数，故呼之参数数，不受内核调用之约（至多二参）所限，落于内核调用者乃后端实现包。
- **垫层在执行器中。** 垫层书于底层模式，与执行器同一编译单元。GC 值与线性内存之间之搬运，即在于此：GC 字节数组之内容，本在执行器内存，可径以（址，长）授底层接口，不必复制。
- **与既有代码之应。** `主机*.豫` 为 GC 垫层；`WASI库/` 为 WASI 垫层；`平台。豫` 之内核服务导入，为裸机后端之内核调用层。

## 五、调用之约（第一版之要）

1. **唯整数。** 底层模式诸值皆三十二位整数（爻零一，单元零）。参不逾六，返一整数。
2. **返状态之码。** 返零为成，否则为状态之码（第七节）；结果一概书于调用者所供之出址。唯一之例外：`退出` 不返。
3. **址为调用者线性内存之偏移。** 缓冲为（址，长）二整数，UTF-8，不带尾零，属调用者。被调者不分配内存、不回调、不抛异常。
4. **六十四位之量**（纳秒、文件偏移、大小）：入则拆为（低三十二位，高三十二位）二参；出则以八字节小端书于出址。
5. **需长之出**（参数块、环境块、链接目标、初始柄之名）：缓冲不足，则返状态六十一（溢出），并书所需总长于出址，调用者依此重试。`读目录` 从 WASI 之义：已用字节数与缓冲长等，则或有余项，以游标续读。
6. **柄**乃非负整数，平台颁之。零、一、二恒为标准入、出、误；负一为无效；既闭，不得复用（号或复用）。柄兼为能：目录柄唯达其子树。
7. **路径**为 UTF-8，相对目录柄（openat 式）。无全局之 `打开(路径)`，无当前目录（当前目录与路径规整，垫层持之）。`..`、绝对路径、符号链接，皆不得越出目录柄之子树，越界返七十六。授权以启动之时初始柄表传入（预开之目录），与 WASI 之 preopen、GC 文件包之“目录权”同构。工具链类程序须访问全文件系统者，由启动之方以根目录授为预开之目录；授权之界，启动方裁之，非接口之默认。
8. **阻塞。** 函数阻塞至成；候多事则用 `等待`；柄可置为非阻塞，是时无数据则返六。
9. **块。** 参逾六者，改传一块址，块首四字节为块之大小，以便扩展。第一版唯 `运行程序` 用之。
10. **布局小端**，记录布局沿 WASI preview1（第八节）。
11. **不支持。** 平台所无之能，一概返五十八，不另设询问之函数；垫层径试之，依返值降级。

## 十一、“非豫言之代码至少”何以为之

- **入口表乃数据，非代码。** 后端与操作系统之间，唯一表：系统调用号（Linux）或导入符号（macOS 之 libSystem、Windows 之 kernel32 与 ntdll）。调用桩由工具据此生成。Linux 可径发系统调用；macOS 不保系统调用之稳，Windows 之调用号随版而变，此二平台必走库之导入，故至少须有一导入表。
- **落地之路（未定，三择其一，议取甲）：**
  - **甲、豫言自有之后端。** 以底层模式所产之 Wasm 模块，经寄存器降级后端编为各平台本机码，接口入口降为系统调用或导入表。须有可执行文件之写出器（ELF、Mach-O、PE）与 Apple 平台之代码签名。全程无非豫言之代码。
  - **乙、译为 C 或 LLVM IR，再交系统工具链。** 有非豫言工具链与焉，违本案之志，仅备而已。
  - **丙、任一 Wasm 引擎加薄胶水。** 今之 Node 夹具即是。仅供差分对照验证，不作交付。
- **内存增长不入接口。** 底层模式之 `内存增长` 乃语言之指令，由各平台后端之代码生成任之（mmap、VirtualAlloc 或内核内存块服务），非接口之函数。
- **此路亦为桌面一路脱 C 运行时与 V8 之法：** 执行器为各平台唯一之运行时，底层接口为其唯一须移植之一层。此不在本案之内，然本案不与之相悖。

## 十二、验收

1. **接口一致之试**：以豫言底层模式书之，每能一组，于 Linux、macOS、Windows、QEMU（ARM64、AMD64）之上，输出逐字相同。
2. **GC 垫层**：今之裸机验证与用户态验证，改接底层接口之后，悉数通过；桌面则以同一批普通豫言程序对照。
3. **WASI 垫层**：`WASI库/示例/` 之二十二 C 程序，于裸机、Linux、macOS 之上，输出与退出码，与 Node 自带之 `node:wasi` 逐字相同（沿用 `对照.cjs`）。
4. **体量**：接口不逾五十函数；不增 C 文件；平台后端之外，共用之代码中无任何平台分支。
5. **GC 适配**：彼方 GC 接口适配之一致用例（`适配/*/一致性验证`），能于裸机与桌面之适配包上通过。

## 十三、实施之序

0. **先决**：检查器改用包定位器，而受底层之包（与 GC 接口之维护者相商）。
1. **书接口包与规范**：基础、句柄、文件（含一致之试之骨架）。
2. **裸机后端**：以现有内核服务与执行器文件系统，按柄之模型包一层；`主机*.豫` 改调底层接口（GC 垫层），今之验证达至持平。
3. **WASI 垫层**：`WASI库/` 改调底层接口，接回执行器。
4. **Linux 后端与落地之路甲之最小闭环**（可执行文件之写出、系统调用之入口），继而 macOS、Windows。
5. **可选之能**（网络、终端、进程），其后显示与输入（第二版）。

## 十四、险与未定

- **`等待`。** epoll、kqueue、IOCP 三套之义各异，第一版唯保文件、套接字、管道与进程、时钟四类之订。
- **越界之防。** macOS 与 Windows 上须逐段解析，乃后端中最厚者，且易出安全之患，须专试之。
- **系统调用之稳。** 落地之路甲，必成 Mach-O 与 PE 之导入表及（Apple 平台）之代码签名，工不为小。
- **裸机文件系统**今为整文件读写之日志构，柄接口首版用整文件缓存，其性有限。
- **裸机之熵源与时钟精度**：无随机之源；墙钟唯秒精度，单调之钟十毫秒。
- **单线。** 他日加线程，须重审 `等待` 与柄。
- **记录布局借于 WASI**，则系于其快照之版；所异者（权限位、订与事）已列于第八节。
- **命名。** 包名与目录名，待与 GC 接口之维护者相对。
- **与包层级方案（另案）无所倚。** 他日可用之，合此树为一父包，然非先决。

## 十五、决议之录

下列乃与项目之主商定之前提：

1. 增并列之目录 `豫言操作系统底层接口/`，不并入 GC 接口树。
2. 底层接口用者唯二：WASI 垫层与 GC 垫层；非 GC 应用用 WASI，不另造应用面之 ABI。
3. “偏向硬件”者，谓接口之形（整数、址加长、状态之码），其容仍为应用级平台服务，不作 HAL。
4. `gc-host/v1.call` 不冻结、不退，随需而增；GC 接口于浏览器与 CF Worker 上，仍由豫言所书之适配包行之；不为 `call` 另定接口类型之 Wasm 表示。
5. 能以豫言者，尽以豫言，使非豫言之代码至少；共同者，唯书一次。
6. WASI 与 GC 接口，对称而架于底层接口之上，易此前“WASI 走 `call`”之设想。
