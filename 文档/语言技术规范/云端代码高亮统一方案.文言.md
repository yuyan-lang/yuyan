# 云端代码高亮统一方案

## 宗旨

一源同辞，各处同类；色可随明暗而异，词界与类别不可因处而迁。未竟之文、缺籍之包、编译不成之稿，皆须全呈而有词法之色。

## 所据

以 `yuyan-vscode/yuyan.tmGrammar.json` 之 `source.yuyan` 为今之词法准绳，以 `yuyan-vscode/test/grammar.test.js` 验其例。云端只读代码浏览之 `豫言语法.json` 今与之同哈希；云工作台、包服务之 JS 分词及豫言构建期高亮则各有词表，故 `否则`、`递归虑`、`者`、`而`、内建诸类、数名及句号易失其类。若准绳与编译器实法相违，先考语言规则而后同改，毋固其误。

## 三层

词法层循原文，产有序不重叠之半开区间及 TextMate scope，不待包籍与编器。语义层惟于源码版本相合、范围可验时覆其相应词法区间；无之或坏之，则仍存词法层。主题层以稳定类别配色与字重，不得改词界。

词法之类有注释、字符串、转义、内建类型、内建函数、内建常量、数值、标签、结构终止符、结构、类型、控制、操作、标点、标识与原文。语义更辨绑定与引用。注释、字符串先闭其域，转义得覆字符串；声明与函数类型为上下文，非颜色之类。

## 法度

嵌套注释、跨行字串、未闭之域皆延至其终；关键词必守词界，连书之关键词仍须析为组件。`记者信息` 不可截取 `者`，`「一二点三」` 当作数名，`《标签》` 不混于 `《《内建…》》`，`。` 为结构之终，`；` 为操作之词。`化「甲」而化「乙」而「丙」` 中之 `而` 从函数类型；`者` 随所处而定。`〇`、`两` 之数法先问编器而后齐之。

JS 偏移以 UTF-16 为准，编器语义 JSON 以 Unicode 字符为准；相叠之前须转换并验源码摘要。语义区间倒序、重叠、越界、异类或跨注释字串者，弃语义而留词法。原文拼合须丝毫不失；入 HTML 当为文本节点或转义之文。

## 行事

一曰以 grammar 为唯一受版本管束之源，构建时校验或生成云端镜像，不许手工分叉。二曰云工作台与包服务共用一词法模块；能行 TextMate 则径用之，若因体量与内联脚本之限而用轻量状态机，须逐字与 TextMate 差分。三曰豫言构建期高亮同用类别与语料，保其无编器依赖。四曰语义标记加版本与范围之验，旧包与败稿回退词法。五曰诸网页共用主题类别表，明暗各定其色。

## 验收

取 VS Code 既有语法测试、标准库与编译器实稿、旧包及未竟源码为黄金语料。逐字符比云 JS、豫言构建期、包 SSR 与 TextMate；相邻同类可并，不得异类。复验注释与字串内伪引用不成链接，声明提取不失完整名称，原文可复，过期或坏语义标记不令整页失色。浅色诸页及暗色 Monaco 并观其视觉层级；量大稿与增量编辑之耗时。增一规则，必增一例而验诸入口。
