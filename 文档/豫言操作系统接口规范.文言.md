# 豫言操作系统接口规范提要

草案初版，二〇二六年九月二十四日。公签名今置仓根[接口总纲](../豫言操作系统接口/总纲.文言.md)所辖诸包；详义、条款及所据，见[汉语稿](豫言操作系统接口规范.汉语.md)。

## 三分其职

接口之包，以 `。包。豫` 定名与版，以 `。接口。豫` 定型、函数、效果、误与资源之义。其文惟声明，不载宿主之调用名、驱动之寄存器及各地私法。应用所依之包，皆为必需。宿主若无其实现，则构建或载入之时明拒；虽有实现，具体资源亦须另授。

浏览器、云工、Node.js 各有实现之包，后可增裸机之包。实现可异，而所应之接口义须同，且共受一套样例之验。执行之器主网页汇编之验证、连入、施行；其内部约不得冒为应用之公约。豫言类型为上，网页汇编 GC 为向下之映。

## 图形之界

图像可由豫言常库在 CPU 绘之；今显示包兼收画面、尺寸与键鼠事，图形处理器另立，建多窗之术后定。显示可托帧缓冲；图形处理器之包后当定申请设备、建缓冲、交命令。云工虽无窗，可生图像之字而应网络之请。GPU 驱动在宿主实现之下，非应用直接所见之公共接口。即有图形处理器接口之实现，设备仍可能不可得，须以有型之结果告之。WASI 之 WebGPU 提案亦别 GPU 使用与窗口显示，汉语稿附其本源。

## 次第

今有基础、文件、出站网络、显示、启动、入站网页服务六包。基础之诊断与时钟为三宿主共面；启动与入站网页处理为客所具之入口，其余能由宿主具之。图形处理器与多窗之约未定。旧浏览器与云工之桥可为实现之材，而不得反以私名定公约。发行时记所依之包、所授之权及宿主实现，俾装载者核之。
