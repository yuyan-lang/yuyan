现行默认目标为 `native`：统一 ANF → C → clang，并使用影子根栈。`llvm`、`shadow` 是兼容别名。`wasmgc` 使用同一 ANF；`wasm`、`wasmgc-anf` 是其别名。旧手动栈 LLVM/WASI 代码生成器已移除。运行时仍保留旧种子所需 ABI；这不是可选后端。可移植自举包改为 C 源码。循环节点、完整原语效果表等后续事项仍以正文限制为准。

# 统一 ANF 架构审阅稿

状态：方案已进入实现。已确定带结果的 if、native 真实调用栈＋shadow stack、不允许保存 continuation、保留默认阶段导出。本文以下包含完整目标设计，不代表全部条目已经落地；当前实验目标为 `--target=shadow` 和 `--target=wasmgc-anf`。这里的示例是 IR 展示草案，不是已经支持的豫言源码语法。

首条可自举路径、性能对照与当前限制见 [实现与自举](../性能研究/统一正则/实现与自举.汉语.md)。

建议统一为 **结构化、带运行时类型的 ANF**：原子操作数、有序绑定、带结果的控制表达式。共同 IR 不再用普通函数或续延函数模拟分支合流，不开放任意 goto。native 的虚拟栈转换、Wasm 的操作数栈组织都放在后端。

## 1. 当前问题与统一位置

当前 [阶段驱动](../库/编译器核心/编译步骤/总体过程/分布编译步骤。豫) 的 native 路线依次执行纯 ANF、消冗、续延传递、代码生成准备。所谓“求值正则形式”实际已经过续延传递变换。WasmGC 则跳过这些入口，在 [生成器](../库/编译器核心/编译步骤/代码生成/网页汇编直生。豫) 内调用有名 ANF 转换。因此现在并不是两边共用一个明确的 ANF 产物。

[现有 ANF](../库/编译器核心/编译步骤/求值正则变换/无类型正则变换。豫) 的 `创建合并点` 用 `拉姆达抽象续延` 和 `函数调用续延` 表示共享后续；[代码生成准备](../库/编译器核心/编译步骤/代码生成准备变换/代码生成准备变换。豫) 再把这些形式映射到帧槽、返回参数槽和续延存储。相同的通用表达式树也承载前端类型节点、ANF、闭包和底层指针操作，非法组合主要靠后续模式匹配报错。

目标流程：

```text
源语言前端、类型检查、擦除、共享高层优化
    → 闭包转换与函数提升
    → 统一 ANF 构造及验证
    → 共享 ANF 优化及验证
        ├→ WasmGC 降低、编码 → V8 / Wasmtime
        └→ native 降低、代码生成 → 本机运行时
```

共同边界在 **当前纯 ANF 附近、续延传递之前**。不是在现有 C 栈操作之后再包一层格式。前序全局存储转换已经引入的地址式表达，进入共同 ANF 时也应还原为抽象的全局读写，不把字节偏移当成公共语义。

## 2. 格式骨架：让 if 本身交回结果

建议数据结构至少分为以下类别，不能都塞回 `节点名称＋表达式列表`：

```text
模块 = 版本、语义档案、依赖与导入、形状表、常量表、全局表、函数表、初始化顺序
函数 = 函数ID、参数及类型、返回类型、效果摘要、函数体、调试信息
函数体/区域 = 有序绑定序列 ＋ 结束式
绑定 = 结果值ID及类型 ← 简单式或结构式
原子 = 局部值ID | 标量常量 | 常量池引用 | 函数符号
简单式 = 原子别名 | 原语(原子们) | 调用 | 分配 | 字段/数组操作 | 全局操作
结构式 = 如果 | 标签分派 | 循环 | 尝试捕获 | 动态退出域
结束式 = 产出原子 | 返回原子 | 继续循环 | 退出循环
       | 抛出 | 提前退出 | 尾调用 | 不可达 | 不正常返回的结构式
```

普通操作和调用的所有操作数必须是原子；只有结构式显式包含子区域。首版每个正常返回的表达式产生一个值，无结果的操作产生 `单元`；多结果以后按需要扩展，不能默认借助堆元组模拟所有内部多值传递。

```text
函数 示例(%条件:爻, %输入:整数64) -> 整数64 {
  %结果:整数64 = 如果 %条件 {
    %甲:整数64 = 直调 @甲函数(%输入)
    产出 %甲
  } 否则 {
    %乙:整数64 = 直调 @乙函数(%输入)
    产出 %乙
  }
  %最终:整数64 = 整数加(%结果, 1)
  返回 %最终
}
```

`产出` 结束最近一层可产生正常结果的区域，回到该结构式之后；`返回` 退出整个函数。它们必须是不同的节点。分支内部的值不能被外部直接引用，必须经区域结果传出；结果绑定在两个分支内部都不可见。

若一支直接返回/抛出，只有另一支提供区域结果；若两支都转出，该结构式是“不正常返回”，放在段末，没有虚构的结果值或后续可达指令。“不正常返回”是控制流属性，不是可以当作普通值传递的类型。缺少正常分支结果应报错，不能补一个空值蒙混通过。

标签分派使用同样规则。后端把区域结果变为 Wasm `if/block` 结果，或 native 基本块参数/φ；这些基本块属于后端内部，不要求另设一套共同 SSA 阶段。

## 3. 绑定、存储和构造算法必须一起改

- 每个函数内的参数、绑定和循环参数使用唯一整数 ID；显示名、源码范围另放调试表。ID 不承担机器寄存器或 Wasm local 编号的含义。
- 不再混用自由变量名字与绑定序数。旧 ABT 输入只在边界通过作用域环境解析一次；后续优化按 ID 更新引用。
- 连续 let 保存为序列或分块序列，构造时使用局部 builder、最后冻结。避免每增加一个 let 就闭合并重写整个后续树，也避免反复在不可变列表尾部附加。
- 条件分支的共同后续只存一次。新构造器直接建立“带结果 if”，不先造旧合并点再全树转换，也不把后续复制进两个分支。
- 不变节点可共享；会重写的指令容器由当前 pass 明确拥有，不能原地修改其他阶段仍引用的共享对象。
- 内联时重命名被复制函数的 ID，不能直接拼接原编号。每个函数独立发号；模块和符号编号按确定性顺序生成，不依赖全局计数器或任务完成先后。

前序函数提升目前也会生成带计数器的名字，因此仅改本阶段不能保证所有串行、并行二进制立即相同。迁移初期先做按绑定 ID 归一化的 IR 对比，再收敛全链路确定性编号。

## 4. 循环也需要参数和结果

```text
%总和:整数64 = 循环 ^求和(%序:整数64 = 0, %积:整数64 = 0) {
  %继续吗:爻 = 整数小于(%序, %上限)
  如果[不正常返回] %继续吗 {
    %新积:整数64 = 整数加(%积, %序)
    %新序:整数64 = 整数加(%序, 1)
    继续 ^求和(%新序, %新积)
  } 否则 {
    退出循环 ^求和(%积)
  }
}
返回 %总和
```

循环 ID 是单独的名字空间，只能引用词法上包围当前代码的循环。`继续` 的参数同时替换下一轮参数，必须支持值交换，不能按顺序覆盖；`退出循环` 交出循环结果。允许跨层继续/退出，但禁止跳入兄弟区域、异常处理体或另一函数。

Wasm 对应外层带结果的 `block` 与内层 `loop`；native 可降低为循环头参数和退出块。首版不支持任意基本块跳转，也不自动把所有递归函数改成循环；不能表达的旧局部控制流必须在迁移时显式处理，不能静默复制大型后续。

## 5. 调用、异常和续延要各有语义

**普通调用是产生结果的简单式。** 区分直接函数符号和间接代码引用；参数顺序及元数来自签名表。已闭包转换的函数把环境作为显式参数，不把 C 虚拟栈指针加入公共签名。闭包对象的入口槽使用逻辑代码引用，不公开 native 地址或 Wasm 表下标。

**尾调用是结束式。** `let x = call …; return x` 只是候选，还要检查结果转换和活动的异常/退出范围。若调用抛出的异常本应被当前函数的处理器捕获，就不能直接丢掉该处理器所在帧。后端必须证明可以直接尾跳，或保留等价的处理范围；做不到时保留普通调用和返回，不能改变异常捕获行为。需要保证常量栈空间的尾调用应有明确能力要求，不能无提示退化。

**尝试捕获是带结果的区域。** 正常体及处理体通过 `产出` 交回同类型结果；异常参数只在处理体可见。抛出沿动态处理器链传播。跨循环退出、函数返回及区域退出必须结束实际离开的处理范围。

**动态提前退出是另一种带结果区域。** 它产生每次激活唯一的退出令牌；正常 `产出` 或携带结果的 `提前退出(令牌, 值)` 都结束对应激活。普通异常处理不能意外吞掉这种转移。令牌不是普通合并点标签；如果它经函数传递或闭包捕获，必须保留激活身份和生命周期。

用户已明确 continuation 不允许保存、不能逃出当前调用的动态范围。新路径据此实现动态提前退出，激活标识不复用，离开范围后的调用报告错误。Wasm 使用 EH，原生使用栈上的退出记录与 `setjmp/longjmp`；转移前恢复影子根链。普通调用不得被误认为提前退出，活动退出域内的调用不直接尾跳。
