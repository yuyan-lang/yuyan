# 统一 ANF 后端迁移

2026-09-09。默认 `native` 经统一 ANF 生成直接调用 C，再由 clang 编译链接；GC 根由影子栈维护。`llvm`、`shadow` 是其兼容别名。`wasmgc` 也从统一 ANF 生成，`wasm`、`wasmgc-anf` 是其别名。旧手动栈 LLVM/WASI 生成器、CPS 转换和机器栈准备阶段已删除，`--wasi-sdk` 不再接受。

前端并行默认拆分为依赖分析、解析、类型检查与擦除、跨模块优化、闭包转换，按此阶段顺序优先派发就绪任务。闭包转换之后，整模块构造统一 ANF 并生成目标代码；`--frontend-tasks=combined` 保留粒度对照。拆分性能的历史测量见[合并与拆分](../性能研究/前端调度/合并与拆分.汉语.md)，本次迁移验证不作为新的性能测量。

原生默认 `-O3 -flto`；`--do-not-optimize` 使用 `-O0 -g` 与调试运行时。可移植双种子包改为每个种子一份 `编译器.c` 和运行时源码，包内构建排除旧 `入口.c`，由生成代码提供 main。原生链接辅助代码保留包归档、系统库和静态链接检查。

运行时仍保留旧种子所需的手动栈 ABI，允许旧 native 种子引导新源码；编译器已没有可选的旧后端。旧纯 ANF 的独立阶段查看工具仍可用于调试，未参与可执行代码生成。统一 ANF 仍在整模块生成时构造，循环节点和完整原语效果表的既有实现限制没有在此次扩大。

原生连续自举 `yy2_bs → yy3_bs → yy4_bs` 通过，末两代逐字节相同，SHA-256：`7a1772bbf77494ffcceef8693e0c5084757fb33adadb77d65d48a45fcdc0483a`；随后并行类型检查通过。按仓库要求尝试旧 stable 首级时仍遇到“文件夹未找到”，诊断重跑亦如此；因此首级由已有可信编译器通过豫构准备，没有将旧 stable 的失败记为通过。

WasmGC 编译器在 Node/V8 下完整自举通过，与原生生成的同一串行目标逐字节相同，SHA-256：`152a254d358978cd8a262ef3179ba6ab5ee6c6b3fc10608ee3a988a361ce86b2`。导出的双种子 C 源码包用自身构建脚本成功链接，生成的编译器及豫构放在源码根目录后成功编译 `--target=llvm --do-not-optimize`；该调试产物和默认优化产物均通过 1 MiB 初始堆的影子根保活、深尾递归和异常测试。种子置于导出子目录直接调用时，包原生头文件定位失败；按包自述安装到源码根目录后通过。

可移植种子重新构建的调度器测试通过，包括动态优先级、同级顺序、并发上限及失败收拢。
