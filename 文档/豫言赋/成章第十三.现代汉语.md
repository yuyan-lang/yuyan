## 本章导读

前十二篇依次介绍了名称、类型、函数、条件、构造器、模式匹配、列、递归、多态、模块、副作用和错误处理。最后一篇把这些概念组合成一条数据流水。每个函数只负责一件事，并用明确的输入输出类型与下一步连接。

## 组合数据流水

示例按照以下顺序处理数据：

1. 从整数列 `[1, 2, 3, 4, 5]` 开始。
2. 用 `「态射」` 把每个数平方，得到 `[1, 4, 9, 16, 25]`。
3. 用 `「滤」` 保留大于十的数，得到 `[16, 25]`。
4. 用 `「从左折叠」` 求和，得到 `41`。

完整程序如下：

```yuyan
寻观「标准库」之书。

「平方」乃化「整数」而「整数」也。
「平方」者会「数」而「乘」于「数」于「数」也。

「逾十」乃化「整数」而「爻」也。
「逾十」者会「数」而「大于」于「数」于「一零」也。

「数列」乃「列」于「整数」也。
「数列」者「缀」于「一」于（「缀」于「二」于（「缀」于「三」于
    （「缀」于「四」于（「缀」于「五」于「罄」））））也。

「方列」乃「列」于「整数」也。
「方列」者「态射」授以「整数」授以「整数」于「数列」于「平方」也。

「大方列」乃「列」于「整数」也。
「大方列」者「滤」授以「整数」于「逾十」于「方列」也。

「总和」乃「整数」也。
「总和」者「从左折叠」授以「整数」授以「整数」
    于「加」于「零」于「大方列」也。

「打印行」于（「字符串拼接」于『大于十的平方之和：』于
    （「整数表示」于「总和」））。
```

输出为：

```text
大于十的平方之和：41
```

配套源码见[成章。豫](示例/成章。豫)。

## 为什么可以安全组合

各步骤的类型能够首尾衔接：

| 名称 | 类型关系 |
| --- | --- |
| `「平方」` | 整数变成整数 |
| `「态射」……于「平方」` | 整数列变成整数列 |
| `「逾十」` | 整数变成爻值 |
| `「滤」……于「逾十」` | 整数列变成整数列 |
| `「从左折叠」……于「加」` | 整数列收拢成整数 |
| `「整数表示」` | 整数变成字符串 |
| `「打印行」` | 字符串产生外部效果 |

如果要把平方改成立方，只需替换映射函数；如果要改变筛选规则，只需替换判断函数；如果要求积，只需替换折叠函数和初始值。程序的整体骨架不必改变，这就是组合式设计的价值。

## 继续学习

- 要了解精确语法，请阅读[语言规范](../语言规范.md)。
- 要观察实际规模的豫言程序，可以阅读 `藏书阁` 中的标准库和以豫言编写的自举编译器源码。
- 要练习程序设计，可以先把问题拆成若干输入输出类型明确的小函数，再把它们组合起来。

教程到这里结束，但函数式设计的主线可以继续用于编译器、网络、数据结构及更多领域：名称应当准确，函数应当遵守类型契约，数据形状应当明确，递归应当能够终止，副作用应当限制边界，小函数应当易于验证并能够组合。
