# 设备直接访存之界（已决：直立 IOMMU）

今惟初始任务可读固定设备配置，未启 DMA。将令设备写存储，须先定驱动是否可信、其失误是否必限；此关可信之界与微内核之职，非细末编码。

CPU 页表不自限设备。Virtio 无平台地址转换时，依驱动所授物理地址访存；驱动虽居用户态，不足证 DMA 已隔离。所据见 [Virtio 1.2](https://docs.oasis-open.org/virtio/virtio/v1.2/virtio-v1.2.html)。

一曰内核先守 DMA。用户块服务定请求之序与策略，文件、命令壳仍居用户。核暂掌受限传输、保护之队列与固定 DMA 区，受设备能力、操作、扇区、用户偏移与长度，不受任意物理地址。验权验界而自造描述符，写则先抄入，读毕再抄出。不可验用户可改之描述符而径交设备，以免验后偷改。完成或复位前，不复用其页。此少增核职与抄写，未量其速；防用户伪址，非防恶意物理设备。

二曰暂信用户驱动。独授专用任务设备权，普通程序与壳不得之。核较小，然无硬件 DMA 之限，驱动失误可害全机；须列其为可信之基，不得谓故障已隔离。退出前仍须止设备而后收页。

三曰先立 IOMMU。两机先成设备地址空间、映射、权限、撤销、失效与故障处理，再作磁盘驱动。核守映射，用户驱动掌传输，设备仅访获授之页。较合长期微内核，然使文件持久化之前多一大项。QEMU 臂机可具 SMMUv3，默认不设；兼容机另验其平台与 IOMMU，不以开关冒客体实现。见 [QEMU 文档](https://www.qemu.org/docs/master/system/arm/virt.html)。

诸案皆须实读写、验越界与无权、处只读与错误，刷新而重启复读；请求未毕，不遽收 DMA 页。一案另验用户不能伪物理址，三案另验硬件拒绝未映射页，二案明存隔离之缺。

用户已决直立 IOMMU：核守设备地址空间、映射与生灭，用户驱动掌 Virtio 传输。不先下移传输于核，亦不以暂信驱动代隔离。未验地址转换与拒绝越界，不启磁盘 DMA；浏览器 I/O 则由宿主供之。操作系统全目标仍存。
