# 豫构层级包设计

状态：第一版已在分支“层级包”实现并通过测试：两个字段与两向校验、依赖闭包含库类型后代、`E之A` 下钻、上下文第四版、`检查` 的额外输出。语言服务跳转（「包含在」跳到父包描述文件，「包含包」逐项跳到子包描述文件）已实现。尚未做：`发现 --树`、`--含子包`、升种子与试点；现有包文件均未使用新字段。文言本见[文言版](豫构层级包设计.文言.md)。

## 一、目标

让一个大包（父包）包含许多子包。原本要逐个依赖 A、B、C、D 的包，如果 E 包含它们，只依赖 E 即可，并用 `E之A` 引用 A。现有包与现有代码都不用改，本设计是纯增量。

保持不变：

- 包身份仍是（所有者，名称），全局唯一。子包名不因层级而改变，`E之A` 只是引用路径，不是新的包名。
- 包根仍由包文件所在目录决定。物理嵌套的目录仍只是边界，与这里的逻辑层级互相独立。
- 语言模块仍只能导入自身与直接依赖；依赖一个包，视作同时依赖它的全部库类型后代。
- 导入语法不变，单段导入取总集的规则不变；本设计不改总集。
- 配置仍只做静态解析，不执行豫言代码。

不做：重新导出（`E之A` 不经过 E 的总集；E 想含 A，仍可在 E 的总集里手写 `寻诵「E」之「A」之书。`）、继承依赖／版本／原生配置、路径式包身份、跨所有者包含、多个父包、依赖可执行文件包。

## 二、今状

本节依据当前仓库源码。

- 包记录是（所有者、短名、包文件、直接依赖）；同一身份全仓库只能出现一次，一个目录至多一个包文件（[包定位。豫](../库/构建基础/包定位。豫)）。
- 嵌套目录已经存在，但只是边界：文件归属取最长目录前缀，父包的模块路径不能越过子包目录，默认构建整棵跳过嵌套包。
- 可见性是自身加直接依赖，按短名匹配，重名报错。
- 编译器不读包配置，只读豫构序列化的包上下文（第二、三版）；上下文含全部已发现的包（[包上下文。豫](../库/构建基础/包上下文。豫)）。
- 符号名取自模块文件路径，不含包身份，所以逻辑层级不影响 ABI 与缓存路径。
- 包文件字段是白名单（[配置解析。豫](../库/包配置/配置解析。豫)），发现阶段会解析树下每一个包文件；旧稳定豫构因此拒绝任何含新字段的包文件。

## 三、模型

新增两个可选包字段：

```text
「包含在」者『安全外壳』也。                                     「：本包的父包；不写即为树根：」
「包含包」者「列」【『安全外壳密码』，『安全外壳协议』】也。         「：本包的直接子包；顺序有意义：」
```

规则：

1. 两个字段的值都是同所有者的包名。每个包至多一个父包。
2. **严格两向**：父包的「包含包」必须恰好等于声明「包含在」该父包的那些包。缺一向、多一向、父或子不存在、包含自身、重复、成环，都报错。未写「包含包」等于没有子包。
3. 层级是逻辑树，与磁盘目录无关：子包目录不必位于父包目录之下。现有的物理嵌套（如 `测试`、`工具/豫言裸机`）仍只是边界，不受影响。
4. 两个字段都不写的包一切照旧。

以安全外壳为例。新增父包，登记四个库：

```text
「包含包」者「列」【『安全外壳密码』，『安全外壳协议』，『安全外壳终端』，『安全外壳会话』】也。
```

四个库各加一行：

```text
「包含在」者『安全外壳』也。
```

某应用只依赖父包：

```text
「依赖」者「列」【『标准库』，『安全外壳』】也。
```

源码里引用子包的模块：

```text
寻观「安全外壳」之「安全外壳协议」之「通道」之书。
```

## 四、依赖语义

依赖父包 E，等于同时依赖 E 与 E 的全部库类型后代（子包、孙包……）。依赖闭包据此计算：原生链接、编译模式一致性检查、成环检测都覆盖这些后代。也可以只依赖某个子包，此时只带入该子包及其后代。

闭包顺序：先按声明顺序访问「依赖」，再按「包含包」的顺序访问库类型子包，最后是包自身。它影响原生链接顺序，所以「包含包」的书写顺序应保持稳定。

推论：

- 子包不能依赖祖先：祖先的闭包含全部后代，会成环。共用代码放到兄弟包，或放在该层级之外。
- 父包与其库类型子包须同编译模式（沿用"同一依赖闭包内同模式"）。
- 可执行文件类型的子包不进入闭包，也不能被导入，只能被登记归类（沿用"可执行文件包不可被依赖"）。
- 对能力包等要求最小授权的场景，应用应直接依赖具体子包，避免依赖父包。

## 五、导入解析

源码写法不变。设当前包为 X，导入路径为 `s₁之s₂之…之sₙ`：

1. **首段**：s₁ 必须是 X 自身或 X 的直接依赖的包名，得到包 Y。可见包名与冲突规则不变。
2. **下钻**：从 s₂ 起，若 sᵢ 是 Y 的登记库类型子包，则 Y 换成该子包并继续；否则停止。
3. **模块**：其余各段是 Y 的包内模块路径；没有其余各段时取 Y 的总集，规则同今日的单段导入。
4. **边界**：定位到的文件仍须归属 Y（按最长目录前缀），否则报"模块跨越子包边界"。物理嵌套却未登记的包，仍按边界处理。

要点：

- 子包优先于模块。父包自己的模块路径若以某个子包名开头（`<子包名>。豫` 或 `<子包名>/…`），会遮蔽该子包，由豫构检查时报错。
- 只依赖 E 时，A 不能作首段；要写 `寻观「A」…`，须另行直接依赖 A。已有的直接依赖与 `A之…` 写法照旧有效。
- `寻` 以路径末段命名空间（[类型与模块](语言技术规范/类型与模块.汉语.md)），所以 `寻观「E」之「A」之书` 绑定的仍是 `A`，正文里的 `A之…` 不必改，只换导入行和依赖声明。
- 首段是 X 自身时，可写 `X之子包…` 引用自己的子包。

## 六、校验

豫构解析全部候选包（与今日相同）时检查：

- 字段类型；名称是合法短包名。
- 两向一致、同所有者、无重复、无自包含、无环。
- 依赖闭包内：编译模式一致（父包与其库类型子包也须同模式）；成环时若环中含库类型子包，错误信息追加提示“子包不能依赖其祖先”。
- 遮蔽（见上）。

## 七、上下文协议

只有索引中存在库类型子包登记时才输出「豫构包上下文四」，否则仍是第二／三版，字节不变。第四版在第三版基础上：模式行恒存在；每条记录在文件与依赖之间加一列「父」（无父为空串）；可执行文件类型的子包不写父，因此不可下钻。解码同时接受二、三、四版，并检查父存在、同所有者、无环。旧编译器遇到第四版会报"不支持的包上下文格式"。

## 九、兼容与发布

- 纯增量：不含新字段的包不受影响；不出现库类型子包登记时，上下文仍是二／三版，字节不变。
- 手写的二版上下文（Makefile、各宿主与外部仓库）不受影响，但它们无法表达层级。
- 迁移不改名、不搬目录、不改导入，符号名与缓存路径不变。
- 种子门槛：旧稳定豫构拒绝含新字段的包文件，旧编译器不识别第四版上下文；CI 又用 `YY_BOOTSTRAP_URL` 固定了历史种子（[main.yml](../.github/workflows/main.yml)）。因此分三步：
  1. 落能力：实现与测试，不改任何现有包文件。
  2. 升种子：合并进 yybs，由 CI 发布新种子；随后另一次提交更新 `YY_BOOTSTRAP_URL` 与 sha256，并重装本地 `yy_bs_stable`、`yy豫构_stable`。
  3. 迁移包：此后才可使用新字段。

  第 2 步之前，任何提交都不得出现「包含在」「包含包」。

## 十一、试点与后续

试点：安全外壳（[会话](../库/安全外壳会话/安全外壳会话。包。豫)、[协议](../库/安全外壳协议/安全外壳协议。包。豫)、[密码](../库/安全外壳密码/安全外壳密码。包。豫)、[终端](../库/安全外壳终端/安全外壳终端。包。豫)）。新增父包 `安全外壳`（含包文件与两份说明），登记四个库；四个库各加一行「包含在」；现有使用方不改。四个库在自举闭包之外，依赖关系简单（密码 ← 协议 ← 会话 → 终端）。

后续：

- 操作系统接口与适配（各约五十个包）：各设一个父包。先改自写路径假设的工具（接口检查等）与外部仓库里的手写枚举，再迁移；应用仍应直接依赖具体接口包。
- 拓展库：把子目录升格为子包，可保持原目录，子目录里现成的总集自然成为子包的总集。子包名须全局唯一，需要避让；拓展库在自举闭包内，须先核对自举包导出器。
- 可选：`发现 --树`；`检查`／`类型检查`／`构建`（仅库）的 `--含子包`；"子包目录宜位于父包目录之下"的提示（不强制）。

## 十二、风险与待定

风险：

- 种子门槛（见上）。
- 闭包变大：依赖父包会带入全部库类型后代的原生组成。
- 父包与全部子包必须同时出现在发现范围内（外部包目录同理），否则两向校验报错。
- 名称全局唯一，子包名仍带前缀；升格既有目录时要避让。
- 子包不能依赖祖先，共用代码须放到兄弟包。
- 包管理服务等外部使用者是否用同一解析器读取包文件，尚未核实；若是，同样要升种子。

待定：

- 是否加"子包目录宜位于父包目录之下"的可选提示。
- `发现 --树` 与 `--含子包` 是否纳入首批。
- 总集机制不在本设计内，另议。
