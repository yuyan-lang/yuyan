# 仓库包构建

在仓库根目录运行豫构。包名取自 `。包。豫` 文件名，包根就是文件所在目录。配置只调用 parser，不执行代码。依赖声明和用户身份规则见[包系统](../工具/豫构/包系统.汉语.md)。

## 包边界

| 包 | 目录 | 职责 |
| --- | --- | --- |
| 标准库 | 藏书阁/标准库 | 语言核心与基础库；不依赖拓展库 |
| 拓展库 | 藏书阁/拓展库 | 解析组合子、测试框架等 |
| 工具包 | 藏书阁/工具包 | 数据库、绘图等库 |
| 构建基础 | 藏书阁/构建基础 | 包定位、上下文、并行调度；不依赖编译器 |
| 豫言编译器 | 豫言编译器 | 编译器；默认入口为入口。豫 |
| 包配置 | 藏书阁/包配置 | 静态配置解析与包依赖图；使用编译器的 parser |
| 豫构 | 工具/豫构 | 独立构建工具与自身测试；默认入口为入口。豫 |
| 工具 | 工具 | 网站生成、源码排版等多入口工具；不包含子包豫构 |
| 测试 | 测试 | 语言测试与从标准库移出的库测试 |
| 性能研究 | 性能研究 | 性能实验入口 |
| 文例 | 文档 | 文档中的可编译源码示例 |

核心依赖顺序为“标准库 → 构建基础／拓展库 → 豫言编译器 → 包配置 → 豫构”（箭头表示先构建者在前）。不能把构建基础放回依赖编译器的包配置或豫构，否则会形成包依赖环。

标准库中需要拓展库测试框架的测试已迁到 `测试/标准库`，防止基础库反向依赖测试框架。测试包中有预期失败用例，不能将其所有源码一律视为成功构建目标。`*_v0` 和历史设计文件 `藏书阁/design.yuyan` 不在本次源码迁移范围内。

## 导入

```text
寻观「标准库」之书。
寻观「标准库」之「数据结构」之「多态列」之书。
寻观「构建基础」之「包定位」之书。
```

单段“标准库”固定定位 `藏书阁/标准库/总集。豫`，导入后的模块名称仍为“标准库”。所有包遵循同一规则：总集必须手写，不存在就报错，不尝试其他文件，也不按当前目录搜索。内核位于 `标准库/豫言标准内核。豫`。总集与程序入口无关；“诵”的重新导出语义保持不变。

包外的 `藏书阁/标准库。豫` 仅转发总集，供旧稳定编译器以单文件模式启动自举。严格包构建不会访问该兼容文件。

## 构建与测试

```sh
make 豫构
make 类型检查 豫构测试
./yy豫构 检查 豫言编译器
./yy豫构 构建 豫言编译器 --输出 yy编译器
./yy豫构 构建 工具 源码树浏览器 --输出 yy源码树
./yy豫构 构建 工具 文档网站生成器 入口 --输出 yy文档网站
./yy豫构 构建 测试 标准库 数据结构 可选值。测试 --输出 yy可选值测试
./yy可选值测试
```

构建、类型检查命令可在包名后指定入口的各路径段；不带扩展名，不重复包名。省略时使用包文件中的入口字段。没有默认入口的库仍可被依赖，也能通过显式入口构建其中的程序。入口覆盖不允许跨越子包边界，不放宽直接依赖要求。

## 自举启动

`make` 依次完成：旧稳定编译器串行生成 `yy2_bs`；它以单文件兼容模式生成 `yy豫构引导`；之后引导工具按包图构建 `yy3_bs`、`yy4_bs`，比较两者，再以严格包模式构建正式 `yy豫构`。引导工具与正式工具源代码相同，仅构建方式不同。旧种子不要求已认识包上下文，因此没有工具自构环。

旧单文件编译入口仍可用于规定的兼容自举验证；常用 Makefile 和 CI 的后续编译、测试、网站生成器构建均经豫构。发布可移植自举包暂仍使用编译器的专用 `--emit-bootstrap-bundle` 命令。

更改依赖、包路径或子包边界后，上下文缓存会隔离，不复用旧绑定。原生 LLVM、运行时构建要求未变。此版本不获取远程依赖、不求解版本，也没有锁文件。
