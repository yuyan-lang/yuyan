# 双宿主构建

云工模式另生成 `动态资源.mjs`：它把宿主库的隔离入口、宿主桥和句柄桥源码以及值桥 Wasm 字节打包给 Dynamic Worker Loader；另附文件式程序的隔离运行入口 `隔离运行客.mjs` 与浏览器编译器宿主 `编译宿主.mjs`（内存文件系统与 `执行模块`），供[隔离运行接口](../../豫言操作系统接口/隔离运行/规范.汉语.md)的云工适配使用。业务仍只需编译豫言源码；若要使用 Loader，许可文件需在 `LOADER` 下列出绑定名，并在 Wrangler 中配置 `worker_loaders`。同一 `get` 标识必须使用不变的代码和限额。

本工具用豫言编写。它将应用豫言源码编译为 WasmGC，组装值桥，并从浏览器或云工宿主库复制固定的 JS 外壳。JS 外壳仅加载 Wasm、传递宿主能力；应用行为仍在豫言中。

先构建 `yy双宿主构建` 和 `yy网页汇编宿主`，然后从豫言仓库根运行：

```sh
./yy双宿主构建 浏览器 应用/入口。豫 dist/浏览器 ./yy3_bs 包上下文 -
./yy双宿主构建 云工 应用/入口。豫 dist/云工 ./yy3_bs 包上下文 许可.json
./yy双宿主构建 云工 应用/入口。豫 dist/云工 ./yy3_bs 包上下文 许可.json CloudModel
```

`许可.json` 按绑定种类列出可用名称，例如 `{"KV":["账户缓存"],"R2":["项目资源"],"D1":["项目数据库"],"SERVICE":["编译服务"],"DO":["项目对象"],"ASSETS":["ASSETS"],"QUEUE":["页面队列"],"EMAIL":["EMAIL"]}`。浏览器模式传 `-`。云工模式产物的 `入口.mjs` 是 Wrangler 的 `main`，同一豫言 Wasm 可由 `fetch` 或 `queue` 事件调用；浏览器模式由页面导入 `入口.mjs` 并调用 `启动豫言浏览器应用()`。构建器编译应用时禁用旧缓存，避免共享工作树中的过期产物；它不创建 Wrangler 部署配置，也不修改云仓代码。

第七个参数可选，仅云工模式使用：指定一个 ASCII 标识符作为命名 `WorkerEntrypoint` 导出名。上例生成 `CloudModel`，其 `fetch(Request)` 以 `service-fetch` 事件进入同一豫言 Wasm；公开默认入口继续以 `fetch` 事件进入，由豫言分别处理。Wrangler 的 Service binding 可配置 `{"binding":"内部服务","service":"当前Worker名","entrypoint":"CloudModel"}`。Wrangler 4.129.0 本地同 Worker 绑定已验证公开默认路径与内部服务路径分离；非法别名会被构建器拒绝。自定义 RPC 方法、多命名入口和云端部署尚待补齐。[Cloudflare 命名入口文档](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/rpc/#named-entrypoints)说明绑定配置。

浏览器模式还会复制 `自动启动.mjs`。页面直接写 `<script type="module" src="/产物/自动启动.mjs?标识=应用根"></script>` 即可启动，不需另写调用 JS；只有 `id="应用根"` 的元素存在时才加载 Wasm。省略 `标识` 时直接启动。真实 Chrome 已验证存在时执行豫言 Wasm、缺少标识时跳过且不请求 Wasm 文件。`入口.mjs` 的显式启动函数仍可用于需要自行控制生命周期的页面。

浏览器模式也复制 `工作线程自动启动.mjs`。将 Worker 的豫言程序另构建至页面产物子目录后，页面豫言可用 `浏览器工作线程新建("./子目录/工作线程自动启动.mjs", "{}")` 启动它。外壳在 Dedicated Worker 中加载同目录的 `程序.wasm` 与 `值桥.wasm`；Worker 业务须用豫言写，并调用 `浏览器工作线程自身句柄`、`浏览器事件订阅选项`、`等待浏览器事件` 及 `浏览器工作线程向主线程发值`。真实 Chrome 已验证两侧豫言 Wasm 的 ready 与回显往返。

云工模式的 `入口.mjs` 还导出通用 `豫言持久对象` 类，可在 Wrangler 的 Durable Object 绑定和 SQLite `exports` 中引用。类的 fetch、alarm 外层分派由宿主库完成，实际对象逻辑与持久数据读写由同一豫言 Wasm 执行；构建器仍不替应用生成 Wrangler 配置。

云工模式还会读取应用目录（`入口。豫` 所在目录）里的可选文件 `执行配置.json`，经 JSON 解析并规范化后写成产物 `动态资源.mjs` 的导出常量 `执行配置`，缺文件时写 `{}`（非法 JSON 使构建失败）。它只调整各事件种类的墙钟时限（如 `{"事件时限毫秒":{"durable-alarm":900000}}`），不属于 `许可.json`，也不改变许可的绑定种类结构；产物里的 `入口.mjs` 在加载时校验并使用它，非法配置使 Worker 加载失败。入口壳用命名空间导入读取该导出，所以新旧壳与新旧构建器可以混用（缺少该导出时按默认时限运行）。格式、默认值与上限见 `豫言操作系统/宿主/云工/说明.汉语.md`。

构建器调用编译器时恒带 `--parallel -j 24`（二十四路并行调度，用户要求构建并行度不低于二十），类型检查与最终链接的耗时明显缩短（实测应用类型检查由约 40 秒降到约 18 秒）；同一编译缓存同一时刻只应由一次构建使用，勿并发运行多个 `yy双宿主构建` 共享缓存。
