# 批量发布

此器以豫言作。常行惟列诸包，加“--打包”乃成档，加“--发布”乃上传。源码取 Git 所录及未忽略之新文，子包有界；拒敏感名及链接。

构建之档备所依、编译器、豫构与运行时，惟供当前平台；系统工具与 C 库仍须自备。可执行之包附当前平台之器。

上传之符藏于私有暂文，不列于命令；用毕即删。已成 ZIP 留以再传。异文可加“--重新打包”，版名不易而上传序增；同档重试仍归原序，旧籍可下载。

先行“yy豫构 构建 批量发布”，后行“yy批量发布 --所有者 豫言”观其计划。加“--打包”制档，加“--发布”上传；上传之符取 YY_UPLOAD_TOKEN。可用“--包”择一包。默认成档于 .yybuild/发布，工作副本不改。

文档以“构建包”成接口，以“构建源码”览本包，不纳所依及子包，不复立导入索引。首页列包籍、双语说明及成败，接口与源码互通；生成状态.json 各记其果。说明转义而陈，不行其 HTML。

接口败则明记之，残篇不入发行；源码不合语法者以纯文示之。源码站败则不成档。可读非谓可构建，库仍须验型，可执行之包仍须成器。重新打包者，新档既成乃备其旧于“旧档.XXXXXX/发布.zip”；败则原档不动。重传旧档不进其序，各次材料不相杂。

器之运行包惟附当前平台之程序，外部数据与动态库仍依其说明而备。敏感名之检非能尽察秘密，发布者须先审其文。测试惟传于本机，不入公府。

真档验收见内服取摘要时误析全档，今改惟取首六十四字节，并备一百二十八 MiB 之堆。公府须先部署此修复，乃可批量上传；此器不擅部署。
