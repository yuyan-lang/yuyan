# 客体表批量操作

后续进展：验证器已增加函数引用类型标签，并接入引用及其余基础表操作，见[客体函数引用](客体函数引用.汉语.md)。下文保留本阶段范围。

执行器新增标准 Wasm 的 `table.init`、`elem.drop` 和 `table.copy`，分别从元素段初始化函数表、丢弃元素段、复制表中引用。操作数均为 i32，因此仍可在当前整数操作数验证模型下严格验证；此实现没有把引用当作普通整数暴露给模块。

解码检查元素号和所有表号。初始化与复制消费目标偏移、源偏移、数量三个操作数；丢弃不消费操作数，也不要求模块存在表。当前仍只支持一张默认函数引用表。

所有范围按无符号数检查，并用减法计算剩余容量，避免相加溢出。目标和源两侧全部检查成功后才写入；零长度仍须检查两个偏移。表复制允许重叠，保持标准的先取源值再覆盖语义。失败返回客体陷阱负四，不修改本条指令的目标范围。

元素丢弃将该段的运行时可用长度变为零；重复丢弃合法。丢弃后 `table.init` 只允许源偏移与长度均为零，并仍检查目标偏移。主动、声明式元素在实例化后已经处于丢弃状态。当前固定工作区保留解析结果供再次实例化使用，尚未将丢弃转换成动态内存释放。

本轮新增三十一组标准模块用例，覆盖被动初始化、源切片、正负边界、空区间、丢弃、主动及声明式段、双向重叠复制、表号和元素号错误及缺少参数。全部静态结果与标准 Wasm 引擎一致；二十五组有效模块的返回值、陷阱以及完整三项函数表状态也逐项相同。裸机验收使用同一组字节输入。

当前尚未实现 `table.get`、`table.set`、`table.size`、`table.grow`、`table.fill`、多表和通用引用类型。后续涉及引用操作数的指令必须先扩展类型验证，不能只沿用整数栈计数。

规范依据：[WebAssembly 表操作](https://webassembly.github.io/reference-types/core/bikeshed/#table-instructions)。
