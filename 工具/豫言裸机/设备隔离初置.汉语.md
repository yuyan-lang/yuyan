# IOMMU 内核初始配置

已按用户决定实现直接 IOMMU 路线的初始配置代码。此阶段建立空授权表并等待硬件确认，尚未完成授权页映射、撤销和完整设备故障恢复，不能宣称驱动隔离已经全部实现。

`生成设备隔离镜像` 生成要求指定 IOMMU 平台的镜像。命令行第四参数 `设备隔离` 使用该路径；输入模块参数为空字符串时装入内置命令壳。旧的镜像入口保持兼容；只有显式选择隔离镜像才插入这段启动代码。模拟平台与启动镜像必须配套，当前使用固定 QEMU 平台地址，未来还需设备树或固件表发现。

```sh
./yy豫言裸机 臂六十四 "" yy隔离命令壳臂.elf 设备隔离
./yy豫言裸机 兼容六十四 "" yy隔离命令壳兼容.img 设备隔离
```

ARM64 的 QEMU `virt` 参数须增加 `iommu=smmuv3,default-bus-bypass-iommu=off,highmem-ecam=off`。AMD64 使用 `-machine q35 -device intel-iommu,intremap=off,caching-mode=on,dma-translation=on`。串口、处理器、模拟器退出设备等参数沿用命令壳运行说明。尚未配置磁盘 DMA 映射，不要把其他依赖 DMA 的启动程序当成已受支持。

ARM64：在进入用户态前检查 SMMUv3 的阶段一支持，关闭 CR0 并等待 CR0ACK；清零位于 `0x400c0000` 的四千零九十六字节流表，执行数据缓存清理及同步；设置线性流表与六位流标识范围，保持所有流表项无效；另清零并设置位于 0x400c1000 的故障事件队列，设置 SMMUEN 与 EVENTQEN，只有读回 CR0ACK 为五才继续启动。当前流表可表示包括测试设备在内的六十四个流标识，不是通用 PCI 拓扑支持。

AMD64：Q35 平台使用 VT-d。增加内核专有、不可由用户访问的高地址寄存器映射；页目录位于 `0x117000`，其中条目映射 `0xfec00000` 两兆字节块，按不可缓存属性访问 `0xfed90000` 的 VT-d 寄存器。两份任务页表都保留同一内核映射。清零 `0x118000` 的根表，写 RTADDR，发出根表指针设置请求并等待 GSTS 确认，然后开启翻译并再次核对状态。没有设置任何有效根表项。

确认轮询最多六万五千五百三十六次，失败进入启动失败路径；不以无限轮询掩盖错误。初始表由内核独占并在启动中清零，用户态不能修改。硬件确认后打印“设备地址隔离初置已确认”，随后继续运行原有用户程序和任务接口。

验证分为两个阶段：先确认带 IOMMU 的模拟平台能运行既有配置发现程序；再使用包含内核初始配置的镜像，要求先取得硬件确认，再完成真实 PCI 配置识别、权限拒绝和任务创建回收。另有不提供 IOMMU 的失败对照，要求启动失败且不得打印成功确认。最终结果见验证记录。

初置验证只覆盖空表与开启状态。后续的真实 DMA 拒绝诊断见[直接访存拒绝](直接访存拒绝.汉语.md)，分别检查实际故障与保护区。授权页、只读页、撤销后拒绝和生命周期仍待实现；磁盘 DMA 尚未启用。
