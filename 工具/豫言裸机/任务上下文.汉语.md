# 中断中的整数任务上下文

后续系统调用与缺页入口也已采用此布局，详[统一异常帧](统一异常帧.汉语.md)。以下保留最初定时中断接入阶段的范围。

定时中断入口现在保存完整整数通用寄存器及用户返回状态，处理后从同一帧恢复。保存、检查、恢复代码放在 `任务上下文。豫`，供后续调度路径复用；恢复片段最终直接返回用户态，不按普通子程序返回。

ARM64 的帧长为 272 字节，保持十六字节对齐：

| 字节偏移 | 内容 |
|---|---|
| 0–240，每八字节一项 | 零至三十号通用寄存器 |
| 248 | 用户栈指针 |
| 256 | 异常返回地址 |
| 264 | 保存的程序状态 |

AMD64 的帧长为 160 字节，其中软件保存十五个非栈通用寄存器，占 120 字节，后接处理器生成的返回帧：

| 字节偏移 | 内容 |
|---|---|
| 0–56，每八字节一项 | 第十五至第八号扩展通用寄存器，逆序 |
| 64–112，每八字节一项 | 目的索引、源索引、基址指针、基址、数据、计数、累加寄存器 |
| 120 | 返回指令地址 |
| 128 | 代码段选择子 |
| 136 | 状态标志 |
| 144 | 用户栈指针 |
| 152 | 栈段选择子 |

恢复前读取帧中的返回地址和用户栈，检查它们位于当前静态用户地址区间。检查使用额外临时寄存器，之后由上下文帧恢复，因此不再只依赖原计时处理恰好只修改少数寄存器的条件。该范围检查仍按现有单用户域布局实施，不是多进程地址空间策略。

2026-09-22，加入保存、检查、恢复路径后，包含定时器百万次循环、屏蔽中断负对照和独立 C 模块的 114 项双架构 QEMU 检查全部通过。实际核心字节已反汇编核对寄存器覆盖、帧偏移、返回状态写回和恢复顺序；类型检查通过。

```sh
./yy3_bs 工具/豫言裸机/验证。豫 -o yy裸机验证 -j 1
./yy裸机验证 --外部模块 yy外部C模块.wasm yy外部C错误.wasm
./yy3_bs 库/编译器核心/裸机后端/时钟编码。测试。豫 -o yy时钟编码测试 -j 1
./yy时钟编码测试
```

产物目录 `/tmp/yy裸机验证.CVKv5h`；记录见 `验证记录.json` 的“整数上下文扩展验证”。中断目前仍返回原任务，未创建多个任务或切换上下文。帧不含浮点、向量、线程局部基址和页表标识，不能据此声称完整进程上下文、抢占调度或进程隔离已经完成。系统调用和其他异常入口也尚未统一改用此帧。

原生与 WasmGC 生成器输出的双架构时钟镜像逐字节一致，且与本轮受测镜像一致。反汇编使用的核心代码也与这些镜像的实际代码区域逐字节一致。
