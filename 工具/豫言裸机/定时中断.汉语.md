# 用户态执行期间的定时中断

后续已改用完整整数上下文帧，详[任务上下文](任务上下文.汉语.md)。以下保留初版计时中断实现及其验证范围。

两种架构的内核现在默认启用周期性定时器，并允许在用户态执行期间响应硬件中断。中断进入内核后增加滴答计数，完成设备确认，然后返回原用户任务。新增标准平台导入 `平台/时钟滴答`，类型为无参数、一个三十二位整数结果，读取自启动以来已处理的滴答数；计数按三十二位回绕。

ARM64 使用 QEMU virt 的 GICv2 和非安全物理定时器，中断号为 30。新增仅内核可访问的设备映射，配置分发器、CPU 接口及优先级；定时周期取处理器频率寄存器除以一百。处理路径保存修改的四个通用寄存器，确认中断来源，计数并重新装载定时器，再写回确认号、恢复寄存器并异常返回。设备地址和连线依据 [QEMU virt 平台实现](https://github.com/qemu/qemu/blob/master/hw/arm/virt.c)，确认协议依据 [Arm GIC 规范](https://documentation-service.arm.com/static/5f8ff196f86e16515cdbf969)。

AMD64 使用传统 PIC 与 PIT，将计时中断映射到向量 32，屏蔽其他外设中断，设置 PIT 分频为 11932，约每秒一百次。中断门确认来源为用户态，保存修改的通用寄存器，计数、发送中断结束确认，再恢复寄存器并中断返回。用户返回标志启用可屏蔽中断；内核处理期间仍屏蔽它们。该路径以 QEMU pc 单处理器配置验证，设备模型见 [QEMU PIT 实现](https://github.com/qemu/qemu/blob/master/hw/timer/i8254.c)。

这一步没有实现任务切换。滴答反映已处理的中断次数，不是精确墙钟时间；长时间屏蔽、模拟器暂停等情况不能据此推算实际经过时间。多处理器中断路由、其他平台的设备发现和完整上下文保存仍待后续实现。

2026-09-22，双架构新测试让用户态执行两段各一百万次的累加循环。循环中没有系统调用；返回后检查算术结果和新增滴答，验证异步中断能进入内核并继续原程序，定时器也能再次触发。负对照仅将镜像中用户返回状态的中断允许位关闭，保留相同模块和硬件配置；此时滴答进展检查失败。补丁位置必须唯一，避免改错位置仍误报通过。

默认 110 项检查、带独立 C 模块的 114 项检查全部通过。后者产物目录为 `/tmp/yy裸机验证.RZ3ePo`，日志、散列和退出码见 `验证记录.json` 的“定时中断扩展验证”。实际核心中断处理字节已反汇编核对；设备偏移编码参数拒绝检查和类型检查通过。

```sh
./yy3_bs 工具/豫言裸机/验证。豫 -o yy裸机验证 -j 1
./yy裸机验证

./yy时钟编码测试
```

调度、故障任务独立退出、内核 IPC、文件系统、默认用户态 Shell、客体动态执行器和完整 WasmGC 仍未完成。本轮提供的是抢占调度所需的定时中断基础，不能视为抢占调度验收已经通过。

原生与 WasmGC 生成器的双架构时钟镜像逐字节相同，且均与受测镜像相同。两种负对照与正例使用完全相同的 Wasm，各镜像只变化一个字节中的中断屏蔽位；反汇编所用核心代码也与受测镜像一致。
