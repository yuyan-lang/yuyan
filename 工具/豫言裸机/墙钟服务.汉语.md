# 墙钟服务：读硬件实时钟

内核服务 26（平台导入 `平台.墙钟秒`，无参数、一个三十二位结果）返回自 1970-01-01 00:00:00 UTC 起的秒数，按无符号数解释（可用到 2106 年）。此前系统只有开机以来的时钟滴答（服务 5，每滴答 10 毫秒），说不出“今天几号”；现在用户态执行器据此实现标准库的 `当前日期时间表示`、WASI 的实时钟与壳的 `日期` 命令。内核不保存也不改写硬件时钟，时区一律是世界协调时。

## 两架构的读法

| | ARM64 | AMD64 |
|---|---|---|
| 硬件 | PL031 实时时钟，QEMU `virt` 里在 `0x09010000` | 传统 CMOS 实时时钟（MC146818），端口 `0x70`（索引）、`0x71`（数据） |
| 读法 | 一条加载：数据寄存器（偏移 0）本身就是秒数 | 读年月日时分秒，用民用历法折成秒数 |
| 权限 | 与串口（`0x09000000`）同在一个二兆字节的设备块里（二级页表第 72 项，设备内存属性，仅内核可读写、用户态不可访问），不需要新增映射 | 内核在零环，端口读写不需要页映射 |
| 代码 | 4 条指令：取常量地址、`ldr w0,[x1]`、跳回用户返回路径 | 约 320 字节，全部用带标号的相对跳转，无手算偏移 |

服务号 26 加在两个内核的服务比较链末尾（`cmp w2,#0x1a` ／ `cmp eax,0x1a`），返回值走原有的“写回保存帧、恢复上下文”的公共路径，所以和别的服务一样不改动调用者的其余寄存器。

### AMD64 的换算

1. 等 A 寄存器（0x0A）的“更新中”位（bit 7）清零；读 B 寄存器（0x0B）得数据格式，bit 2 为 1 表示二进制、为 0 表示 BCD（QEMU 默认 BCD、二十四小时制；十二小时制未处理）。
2. 依次读秒（0x00）、分（0x02）、时（0x04）、日（0x07）、月（0x08）、两位年（0x09）、世纪（0x32），每个都按 B 寄存器的格式解码（BCD 时 `十位×10 + 个位`）；世纪寄存器读得 0（硬件没有这个寄存器）则取 20。
3. 最后再读一次秒；与第一次不同（读的过程中恰好进位）则整个重读。这样年末进位（23:59:59 → 次年 00:00:00）不会读出“新秒、旧年”的怪时刻。
4. 折算用 Howard Hinnant 的 `days_from_civil`：先把一月二月算作上一年的十三、十四月（`y -= m < 3`），`era = y / 400`、`yoe = y % 400`，`doy = (153·(m>2 ? m−3 : m+9) + 2)/5 + d − 1`，`doe = yoe·365 + yoe/4 − yoe/100 + doy`，天数 = `era·146097 + doe − 719468`；秒数 = 天数·86400 + 时·3600 + 分·60 + 秒。三十二位乘法的低 32 位与无符号数一致，所以到 2106 年都对。同一算法先用 JavaScript 对照 `Date.UTC` 检查了 1970–2105 年每个月的 1 日、28 日、月末与 15 日的三个时刻（共 19 584 个），全部相同。

## 验收

`yy裸机验证` 新增四个方式，每个方式在两个架构上各起一个 QEMU，命令行带 `-rtc base=<日期时间>` 把模拟实时钟的起点设成一个刁钻的日子，用户模块调用 `墙钟秒`，用**无符号**比较断言（2038 年之后的读数在三十二位有符号数里是负的）：

| 方式 | `-rtc base=` | 想抓的错 |
|---|---|---|
| `墙钟闰世纪` | `2000-03-01T00:00:00` | 能被 400 整除的世纪年是闰年（二月有 29 天） |
| `墙钟年末` | `2026-12-31T23:59:50` | 年末进位；起点加四十秒的上界会跨到 2027 年 |
| `墙钟非闰世纪` | `2100-03-01T00:00:00` | 能被 100 但不能被 400 整除的世纪年不闰；读数大于 2³¹ |
| `墙钟闰日` | `2032-02-29T12:00:00` | 闰日本身与中午的时分秒 |

每个用户模块先读一次，断言在“起点”与“起点 + 40 秒”之间；空转三百万次后再读，断言不小于第一次、不大于第一次加 8 秒；最后打印 `普通程序已完成`，退出码与串口输出与其它常规方式一样检查。所以同一组期望值既验证了硬件接口（PL031 与 CMOS 两条路径），也验证了 AMD64 上的换算。

## 边界

- 只有秒的精度；没有设置时间、闹钟、时区、闰秒。
- AMD64 未处理十二小时制、也不检查 CMOS 的电池状态位；QEMU 里两者都是默认值。
- 用户态执行器把它和时钟滴答合起来使用（见[客体二号](客体二号.汉语.md)的“实时钟”一节）：WASI 的实时钟以第一次读到的墙钟秒为锚，之后靠滴答走，所以在一个程序里单调不减，精度是滴答（10 毫秒）。
