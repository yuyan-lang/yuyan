# 客体引用之参、果与局部

后续：默认函数引用之块果及标型选择已接，见[客体引用控制](客体引用控制.文言.md)。下存初验之范围。

今可于同一标准模块内，以直接或间接调用传递默认可空函数引用。签名与局部可杂整数、函数引用；参数仍限十六，结果至多一，参数与局部总数至多二百五十六。

类型索引记各参之型及果型。直接调用逐参验之；间接调用并验数量、参型序列与果型，异号而同结构者仍合。隐式归返、显式归返及跳函数标签皆守果型；未调用之函数亦须全验。

引用局部初为空，整数局部初为零。先复制实参，仅将额外引用局部初为空，故不毁传入之引用。局部取、赋、暂存皆守声明之型，不许整数与引用相冒。

类型记录偏移八记引用参数位图，偏移十二记引用果型。定义函数记录偏移二十记原始局部声明起点；导入函数此处仍记名字，依原有导入标志别之。

全验时据声明制三十二字节位图，尽覆二百五十六位。图存前四调用帧之末，各留一千零二十四字节，容三十二函数。帧仍四千零九十六字节，每次调用仅清前面三千零七十二字节之局部值与控制栈，留其型图。型图与操作数型标签异域，递归不相毁。

完整验栈今须八页工作区，与运行一致；独立索引及解码仍可用原较小工作区。不足则返资源限制之错，不越界。

平台服务与命令壳入口仍守整数协议，引用签名不误绑，宿主入口不裸返私有引用表示。模块内部传递无碍；跨模块引用须随链接与生命周期管理续成。

新增二十七试，静态判定皆与标准引擎同。十八试执行相同，含混合参、递归、默认值、最高参数位、跨字型图、最大局部号、间接异型及等价签名。七非法模块须拒；二合法模块另验宿主整数接口之限。

引用全局、引用块果、标型选择、通用堆型、多果及垃圾收集尚未成，不以此冒称引用型制完备。

二零二六年九月二十三日，两架构三百六十二项裸机回归皆过。产物在 `/tmp/yy裸机验证.Ofs0f5`，日志在 `/tmp/yy布局验证日志`。又解扩展后所遇半兆代码旧限，见[元数据布局](元数据布局.文言.md)。十六份相关模块经标准验证，四份默认命令壳镜像已更新，与实测逐字节同；独立读盘亦过。详见[验证记录](验证记录.json)之“客体引用传递扩展验证”。

## 具体结构引用之局部

二〇二六年九月二十四日始，定义函数之增局部可书规范 `(ref null 类型号)`，今仅许已录结构类型。索引核其号；验型时于 `[253952,254976)` 暂记一函数至多二百五十六局部之确型，`local.get/set/tee` 依型而断。运行仍循旧引用局部位图，空引初置与回收寻根不废。号越界、所指非结构及余未实现具体引用声明，皆拒。

独立规范模块八十七字节者，存宽字段结构之引于可空具体局部，造弃临时物一万，复以 `local.get` 取 `i64` 字段而得四十二；Node 与 ARM64、AMD64 裸机皆成。另二四十五字节非法模块，一以 `i32` 入引用局部，一用越界型号；Node 皆判非法，客体分别于验型、索引拒之。三模块原字于两客体镜像各现一次，裸机三百六十八试皆过，产物存 `/tmp/yy裸机验证.KmQyEM`。具体函数及数组引用局部、非空局部之确定赋值、引用参数与完整子型关系，犹待续成。

二〇二六年九月二十四日，函数**索引**更能循界读指向结构或数组之可空、非空具号引局部，兼及 `eqref` 局部，皆归引根类。原三千一百八十六字常语模块，遂不复停于第七、二十六个定义函数之局部声明；次拒移至全局段首个 `eqref` 全局（原模块偏移三百七十五）。双架构裸机三百六十八试皆过，产物在 `/tmp/yy裸机验证.SXfU9k`。此**未许执行**：静态验型犹拒非空引局部及 `eqref` 局部；后者须确型，前者须循规范记确定赋值，并于出控制块时复旧态。独立五十二字节先赋后取模块，Node 许之；四十五字节先取模块，Node 拒之。二者供次验型对照。规范见[局部初始化验证算法](https://webassembly.github.io/gc/core/appendix/algorithm.html)。
