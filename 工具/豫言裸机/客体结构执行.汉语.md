# 客体结构体指令执行

客体执行器现在为纯 `i32` 字段、最多 32 字段的结构体读取类型段，并处理标准 WasmGC 的 `struct.new`（`0xfb 0x00`）与 `struct.get`（`0xfb 0x02`）。解码记录类型号和字段号；静态验栈按类型号区分结构体引用，构造时逐个弹出声明字段类型，读取时拒绝整数冒充引用、错误类型号或越界字段。执行器经受检对象堆分配、保存字段；读取前核验句柄确实指向活对象且类型相符。

首个结构指令按模块生命周期初始化对象堆，重新装载模块会清除初始化标志，同一模块后续调用不会无故重置堆。当前堆占用原为客体线性内存预留的 `[393216,524288)`；若客体声明了自己的内存，运行前扫描整份指令记录并拒绝其中的结构指令，避免重叠或在副作用之后才发现限制。容量不足时会扫描活动值栈和局部帧、标记清扫后重试；其他字段类型与递归类型组仍不支持。纯 `i32` 数组子集另见《客体数组执行》，回收范围与限制见《客体自动根回收》。

标准有效的独立 WasmGC 客体夹具包含一字段结构体，实际执行 `i32.const 42 → struct.new 0 → struct.get 0 0` 并返回 42。另一无效夹具对整数直接执行 `struct.get`，在客体静态验栈拒绝；带自有内存的标准有效结构体模块在客体执行前返回不支持。这些客体字节码均与独立标准引擎核对。另用双 `i32` 字段模块核对构造时逆序弹栈与读取第二字段，标准引擎得到 42。ARM64、AMD64 QEMU 连同旧场景共 368 项全过，产物在 `/tmp/yy裸机验证.oD3tvN`；Shell 程序运行和重启用例也通过。

## 宽整数结构字段

`struct.new` 和 `struct.get` 现支持已索引的 `i64` 字段，可与 `i32` 字段混用。对象仍以四字节物理槽存储：字段 `i` 的首槽为 `i + popcount(宽字段位图中低于 i 的位)`；`i64` 占相邻两个槽，分配前核对总槽数不超过 32。构造时按逆序消费字段，宽值先弹高半字、再弹低半字；读取时按低、高顺序推回值栈并标记高半字，使其不作为 GC 引用根。字段索引继续按逻辑字段数检查，对象头记录实际物理槽数。

60 字节单宽字段模块和 68 字节 `(i32,i64,i32)` 混合字段模块均由 Node 标准引擎验证并返回 42；ARM64、AMD64 QEMU 客体实际执行也均返回 42。另有 49 字节错型模块把 `i32` 交给 `i64` 字段，Node 判为无效，客体静态验栈拒绝。三份原始字节在两种客体执行镜像中各出现一次，完整 368 项裸机回归通过，产物在 `/tmp/yy裸机验证.Z50aSm`。此前一次运行在 AMD64 Shell 串口检查遇到一处 UTF‑8 缺字，程序及其后续任务照常完成；此前同一产物重跑全套回归通过，本次新产物首次运行亦全过。

新增 80 字节独立标准 WasmGC 模块：把含 `i64` 字段的结构体引用留在操作数栈上，循环构造并丢弃 10,000 个同型临时对象，最后从存活对象读取宽字段并返回 42。Node 验证并返回 42；ARM64 与 AMD64 的 QEMU 客体实际执行均通过，完整 368 项回归通过，产物在 `/tmp/yy裸机验证.Pz5brY`。每个对象至少占 24 字节，累计分配超过当前 128 KiB 客体堆，成功运行证明回收与复用发生且栈根保住了对象；模块原始字节在两种客体镜像中各出现一次。

引用字段、`f64` 字段和 `struct.set` 仍未实现；此用例验证操作数栈根，具体引用局部值型仍被索引器拒绝。普通豫言最小模块含其他尚未支持的类型和指令，不能据本结果宣称已可整体运行。
