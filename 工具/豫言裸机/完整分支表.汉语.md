# 完整类型分支表验证

`br_table` 现在读取目标向量与默认深度，检查索引为 i32，并验证所有标签，包括运行时不会被当前常量索引选中的标签。每个目标的标签值数量必须与默认目标相同，实际分支操作数必须分别匹配每个目标的类型。

不要求各标签类型逐字相同：例如可空 none 引用能同时满足可空 eq 与 any 标签。不可达栈底的未知值也可能满足不同数值标签；但不可达路径上实际存在的错误值仍拒绝，标签数量不一致也仍拒绝。验证全部目标后才将当前路径标为不可达，不按运行时索引挑选一个目标进行静态检查。

12 个完整二进制模块测试通过，分类与 Node 标准引擎一致；21 个结构控制回归通过。类型检查与构建通过，日志为 `/tmp/yy分支表检查日志`、`/tmp/yy分支表构建日志`、`/tmp/yy分支表运行日志`、`/tmp/yy分支表结构回归运行日志`。

当前为完整类型指令验证扩展，并未改变裸机执行器。异常、尾调用、GC 对象指令和其余模块资源验证尚待，默认镜像不变。
