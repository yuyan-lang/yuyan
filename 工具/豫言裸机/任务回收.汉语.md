# 任务回收与带代际的句柄

任务现在使用带代际的句柄。低位选择内部槽，其余位区分该槽的不同使用期；初始句柄仍为 0、1，第二槽回收后依次使用 3、5 等新句柄。用户应保存系统调用返回的句柄，不推算它对应的物理位置。

任务状态、退出码、等待、终止和回收接口均先检查句柄与内核记录是否一致，且槽必须非空。调度器继续使用内部槽号。这样，在槽已经复用后，旧句柄也不能操作新任务。

## 回收协议

新增 `回收任务：(i32) → i32`。仅初始任务作为所有者可以回收已结束的第二槽；正常退出、故障退出或主动终止都属于已结束状态。成功返回 0，仍存活、自身、非所有者、空槽、旧句柄或非法编号返回 -1。

回收在内核内依次执行：

1. 清零第二物理区的两兆字节用户内存。
2. 清零第二上下文缓冲的五百一十二字节。
3. 分别读回两个区域，按位合并全部内容，确认没有残留非零值。
4. 清除核验计数、退出码、等待目标和所有者，递增句柄代际，最后将槽标为非占用。

内存仍归系统的固定任务池管理，之后可供下一次运行时复制使用；没有把它归还给通用页分配器。物理区域的私有内核映射保留，空槽不能调度，所有公开任务接口拒绝访问它。

句柄上限为 2147483647。最后一个有效句柄回收后，将槽标为永久退休；后续创建返回 -1，禁止溢出回绕到历史句柄。初始任务句柄 0 不复用。

ARM64 句柄记录位于 `0x400b0080`、`0x400b0084`；AMD64 位于 `0x103380`、`0x103384`。系统调用恢复保存帧仍遵循已有的整数上下文协议。

## 验收

连续三轮创建子任务、等待结束、回收并复用同一个物理槽；每轮都检查运行时数据、私有写入与新句柄。分别覆盖正常退出，以及终止阻塞任务后回收。

新任务存活时，使用上一轮的句柄调用状态查询、退出码查询、等待、终止和回收，必须全部返回 -1，新任务仍正常完成。回收完成后再次使用当前已失效句柄也必须拒绝；不能回收存活任务，子任务不能回收自己或所有者。

边界用例把空槽的下一句柄置为最后有效值，完成一次创建和回收，再确认创建被拒绝。此注入只用于加速到达耗尽边界，不改变正常分配算法。错误核验期望及错误句柄期望作为负对照。

实际结果见后续记录。当前仍只有两个任务槽；还没有通用多进程分配器、多等待者、独立程序装载或文件／IPC 资源回收，不能把固定任务池的复用称为完整内存管理。
