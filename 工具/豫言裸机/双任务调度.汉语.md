# 静态双任务抢占调度

此阶段为用户态 Shell 和服务进程建立调度基础。两个静态任务运行于真实用户态，使用相同虚拟地址、不同物理内存；定时中断保存完整整数帧、切换页表并恢复另一任务。它还不是完整进程管理。

## 地址空间与上下文

| 项目 | ARM64 | AMD64 |
| --- | --- | --- |
| 用户虚拟区 | 0x40200000–0x40400000 | 0x200000–0x400000 |
| 第一任务物理区 | 0x40200000–0x40400000 | 0x200000–0x400000 |
| 第二任务物理区 | 0x40600000–0x40800000 | 0x600000–0x800000 |
| 两个页表根 | 0x400a0000、0x400a4000 | 0x110000、0x113000 |
| 内核上下文缓冲 | 0x400b1000、0x400b1200 | 0x116000、0x116200 |
| 单帧字节数 | 272 | 160 |

内核、内核栈、设备映射与任务元数据在两个地址空间中一致，用户不得访问。第二任务启动帧含自己的入口、用户栈和允许中断的返回状态。切换 ARM 页表后执行屏障和地址翻译缓存失效；AMD64 写入页表根寄存器使旧地址翻译失效。当前单核，内核异常处理期间禁止中断。

调度器保存旧帧，选择另一个可运行任务，装入新帧并切换地址空间。若另一任务已完成，则继续原任务。任务完成时检查自己的四次核验结果并清除可运行位；两个任务全部完成后才能报告整体成功。完成任务的帧不会再次恢复。

平台导入新增：

- `任务编号：() → i32`：返回当前静态任务编号。
- `任务状态：(i32) → i32`：位值 1 表示可运行，2 表示曾运行，4 表示已完成；无效编号返回 -1。

状态分别从 3 和 1 开始；第二任务首次运行变为 3，完成变为 6。这只是本阶段测试接口，不是承诺稳定的进程 ABI。服务号 7 仍保留给生成代码的致命陷阱。

## 验收设计

两个标准 Wasm 模块分别期望编号 0、1，并持有初值 100、200 的私有全局。各自修改全局，运行没有系统调用的百万次求和循环，检查全局未被另一任务覆盖、求和值正确，并查询另一任务的“曾运行”位。第一个完成任务必须看到对方已运行，因此仅在退出后串行启动另一任务不能通过。

同一验证器另运行关闭第一任务中断的负对照，以及第二任务错误期望值的负对照；同时保留已有单任务回归。实际执行结果记录于验证记录，不以本设计描述代替测试证据。

## 尚未完成

动态任务创建、等待与终止；任务错误隔离退出；物理页动态分配与回收；IPC、文件系统、默认用户态豫言 Shell 和客体 Wasm 执行器仍待实现。当前保存整数状态，不支持浮点、向量、线程局部状态或多核调度。此阶段通过也不表示操作系统目标完成。

## 实测记录

2026-09-22，两架构共 124 项 QEMU 验证全部通过，包括双任务正常、错误期望和屏蔽抢占六项新增检查。原有单任务和独立 C 模块回归全部通过。正常双任务镜像两端均输出“豫言核心启动”和“双任务抢占验证通过”；负对照输出核验失败并使用失败退出码。

两个正常标准 Wasm 模块另经 V8 分别完成四次核验，错误模块在第三次核验拒绝。该独立检查使用测试提供的任务状态，只验证模块计算与格式；抢占和地址空间隔离的证据来自 QEMU。

类型检查通过，实际核心字节已反汇编核对。复现：

```sh
./yy 工具/豫言裸机/验证。豫 -o yy裸机验证 -j 1
./yy裸机验证 --外部模块 yy外部C模块.wasm yy外部C错误.wasm
```

产物及串口日志：`/tmp/yy裸机验证.Lbni9C`。哈希与范围见 `验证记录.json` 的“双任务抢占扩展验证”。不带外部模块参数时运行 120 项检查。

后续已实现用户数据访问异常和生成代码陷阱的独立故障退出，见[故障隔离](故障隔离.汉语.md)。本篇 124 项是静态调度阶段的历史证据；完整进程生命周期仍未完成。
