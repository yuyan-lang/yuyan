# 豫言双架构裸机原型

已实现 ARM64、AMD64 的 QEMU 裸机启动验证。标准 Wasm 整数核心模块经过自有提前编译后，在真实用户态执行；最小特权核心提供页权限、同步异常入口、定时中断和受控服务。机器字节、重定位、启动头和页表全部由豫言生成，没有汇编源文件，也不调用外部汇编器或链接器。

这是单核微内核原型，不是完整操作系统。已具备两任务池的运行时创建、等待、终止、回收及消息通信，并接入首版[用户态命令壳](用户命令壳.汉语.md)。不指定输入模块时，生成的镜像默认启动命令壳；目前只支持任务和控制台命令。抢占实现见[双任务调度](双任务调度.汉语.md)，各阶段实测证据见验证记录。通用多任务分配、文件系统、块设备持久化、完整 Shell、客体动态模块加载和完整 WasmGC 尚未完成。输入支持整数控制流、独立线性内存、全局、数据段及相关整数和内存指令；仍不能直接运行当前完整豫言编译器。普通豫言继续保留现有 WasmGC 后端。

## 一条命令验证

在仓库根目录、安装 QEMU 后运行：

```sh
./yy3_bs 工具/豫言裸机/验证。豫 -o yy裸机验证
./yy裸机验证
```

验证器使用豫言异步子进程，每项约三十秒等待预算；超时按本轮独立进程号文件终止模拟器。全部镜像、输入模块和串口日志保存到新建临时目录，最后打印路径。测试用到宿主的 `mktemp`、`dd` 和 `/bin/kill`；`dd` 只用于负对照改动页表或中断标志，不参与正常镜像生成。

最初的六项基础检查如下；当前验证器另包含定时器、抢占、结构控制、存储、算术及外部模块等扩展用例，具体数量由运行结果计算：

| 检查 | 客体必须发生的行为 |
|---|---|
| 正常 | 在用户态完成函数调用、局部更新、溢出回绕及乘法核验，然后正常退出 |
| 隔离 | 完成同样核验后，读取内核私有页，产生权限异常；核心核对异常来源及地址 |
| 错误结果 | 将预期四十二改为四十三，核心必须报失败 |
| 放开权限 | 只改受测页表的用户访问位；探测不再陷入，验证必须报失败 |
| 操作数栈越界 | 保持 Wasm 类型正确，压入超过客体栈限额的值；运行时必须报失败 |
| 调用栈越界 | 有效模块进入递归，调用帧越界前必须报失败 |

检查同时匹配退出码和串口文字；负对照禁止出现成功标记。AMD64 使用模拟退出设备：通过退出码为三十三，拒绝为三十五。ARM64 使用半主机退出：通过为零，拒绝为一。串口输出都来自客体实际访问设备；退出机制仅用于结束模拟，不承担程序计算或打印。

## 单独生成镜像

```sh
./yy3_bs 工具/豫言裸机/入口。豫 -o yy豫言裸机
./yy中文网页汇编 编码 工具/豫言裸机/启动验证.网页汇编。豫 yy裸机客体.wasm
./yy豫言裸机 臂六十四 yy裸机客体.wasm yy臂正常.elf 正常
./yy豫言裸机 兼容六十四 yy裸机客体.wasm yy兼容正常.img 正常
```

末参数可改为「隔离」，生成附带用户态内核页读取探针的验证镜像。探针是平台验证桩，不是私有 Wasm 指令。正常镜像不包含该探针。生成器只编译输入，不预先运行输入程序；计算结果在模拟的 CPU 上形成。

ARM64：

```sh
qemu-system-aarch64 -machine virt,gic-version=2,virtualization=off,secure=off \
  -cpu cortex-a53 -accel tcg -m 128M -smp 1 -display none -monitor none \
  -serial stdio -no-reboot -semihosting-config enable=on,target=native \
  -kernel yy臂正常.elf
```

AMD64：

```sh
qemu-system-x86_64 -machine pc -accel tcg -m 128M -smp 1 \
  -display none -monitor none -serial stdio -no-reboot \
  -device isa-debug-exit,iobase=0xf4,iosize=0x04 -kernel yy兼容正常.img
```

正常串口输出：

```text
豫言核心启动
用户程序已运行
用户态计算验证通过
```

## 模块契约与实现边界

输入必须导出无参数、无结果的「启动」。只允许以下函数导入，名字和签名均检查：

| 模块与名称 | 参数、结果 | 实现 |
|---|---|---|
| 平台／写字节 | 一个三十二位整数，无结果 | 经系统调用访问串口，检查字节范围 |
| 平台／核验 | 两个三十二位整数，无结果 | 比较实值与期值，失败立即停止验证 |
| 平台／用户态 | 无参数，一个三十二位结果 | 核心先检查保存的硬件用户态状态，才返回一 |
| 平台／读字节 | 无参数，一个三十二位结果 | 非阻塞读取串口，无数据返回负一 |
| 平台／时钟滴答 | 无参数，一个三十二位结果 | 返回已处理的定时中断计数 |
| 平台／任务编号 | 无参数，一个三十二位结果 | 返回当前静态任务编号 |
| 平台／任务状态 | 一个三十二位参数、一个三十二位结果 | 查询运行状态位，无效编号返回负一 |

当前启动验证协议要求正常结束前恰好完成四次核验；这属于测试协议，不是通用系统调用标准。不能将这些宿主接口误称为 WAT 规定的操作系统接口：模块导入及类型是标准的，平台服务语义由本项目定义。

函数参数、结果置于独立的非 GC 操作数栈，局部变量置于真实调用帧。两套后端均支持整数核心的所有现有指令。操作数栈限一百二十八千字节，调用栈约一百二十八千字节，二者有间隔；压值和分配调用帧时检查边界，超限进入失败路径。函数参数与附加局部合计至多一百二十八项；用户代码至多一兆字节。尚未做寄存器分配或跨函数栈检查消除，不据此宣称接近 C 性能。

ARM64 以自有 ELF64 头装载，在一级异常层安装页表和异常向量，通过异常返回进入零级用户态。AMD64 以多重引导首版地址头装载，从三十二位保护模式切换到六十四位长模式，安装页表、全局描述符、任务状态段及中断门，再进入第三特权环。QEMU 提供镜像装载入口；尚无磁盘启动扇区或实机固件移植。

两端采用静态两兆字节页映射。AMD64 核心位于低两兆，用户域位于二至四兆；ARM64 核心位于 `0x40000000` 区域，用户域位于 `0x40200000`，另有 `0x40400000` 私有受测页。串口只由特权核心访问。用户代码与用户栈尚在同一可读写用户映射中，未实现页级写入／执行互斥；这些限制不影响当前内核页隔离检查，但还不足以成为不可信程序的生产沙箱。

镜像生成阶段可以在无工具搜索路径时运行。生成器自身目前仍由既有豫言编译器和运行库构建；通过 Wasm 执行生成器也仍借助现有 Wasmtime 宿主。不能把客体无 LLVM/libc 依赖等同于整个自举工具链已经独立。

## 代码与规范

- `库/编译器核心/裸机后端/机器编码。豫`：字节序、两遍标号解析和重定位。
- `整数降级。豫`：标准整数模块验证、函数提前编译和平台导入桩。
- `臂核心。豫`、`兼容核心。豫`：平台启动、保护状态、异常和镜像装配。
- `任务上下文。豫`、`任务调度。豫`：统一整数帧和静态任务切换。
- `验证。豫`：双架构正常及负对照回归。

规范依据：[QEMU 臂虚拟平台](https://www.qemu.org/docs/master/system/arm/virt.html)、[多重引导地址头](https://www.gnu.org/software/grub/manual/multiboot/html_node/Header-address-fields.html)、[Intel 系统与指令手册](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)、[Arm 异常层切换说明](https://developer.arm.com/community/arm-community-blogs/b/tools-software-ides-blog/posts/changing-exception-level-and-security-state-with-an-armv8a-fixed-virtual-platform)。本次环境版本及验证记录见同目录验证稿。
