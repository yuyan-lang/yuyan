# 完整类型的结构化控制验证

实际指令验证现支持 block、loop、if、else、end、br 和 br_if。控制帧保存父类型栈、进入时的子栈、完整签名及局部赋值状态。块和条件标签使用结果类型，循环标签使用参数类型，函数自身作为最外层标签。

条件先弹出 i32 条件，再按块签名处理参数。显式 else 先检查前分支结果，再恢复进入分支时的栈和赋值状态；无 else 的条件块另检查隐式空分支，只有参数能够满足结果时才能通过。离开块恢复进入块时的额外局部赋值记录，避免分支内非空局部初始化逃出其有效作用域。br_if 检查标签值后保留对应值，br 则将当前路径标为不可达。

21 个完整模块覆盖宽结果、多结果、带参数的隐式 else、循环参数标签、跳转深度与类型错误、重复 else、父子栈边界以及非空局部赋值作用域，分类与 Node 标准引擎一致。类型检查、构建和运行通过；408 个标量模块回归通过。日志为 `/tmp/yy结构指令检查日志`、`/tmp/yy结构指令构建日志`、`/tmp/yy结构指令运行日志`、`/tmp/yy结构标量回归运行日志`。

br_table、异常、尾调用、GC 对象指令和完整模块资源验证仍待实现，当前不能据此运行普通豫言全程序，也未接入裸机执行器。默认镜像不变。
