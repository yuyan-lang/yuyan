# 运行时复制任务

新增平台导入 `复制任务：() → i32`：初始任务运行时创建独立副本，父任务返回新编号 1，子任务从同一个调用现场返回 0。没有空槽或非初始任务调用返回 -1。此接口是当前系统层实验接口，不是普通豫言语法的更改，也不代表已支持加载另一个程序。

启动镜像只装入一个用户任务。复制发生在客体系统调用期间：内核将完整两兆字节用户区复制到第二物理区，将保存的整数系统调用帧复制到新任务的上下文缓冲，单独设置子任务返回寄存器为零，初始化所有者、退出码、等待字段和核验计数，最后才发布可运行状态及任务数量。父任务走原返回路径取得新编号。

因此子任务继承运行时已经写入的全局、线性内存、操作数栈和调用栈；二者使用相同虚拟地址、独立物理内存。核验计数不继承，由新任务从零计数。内核私有状态不属于用户区复制范围。

## 内存与机器支持

ARM64 使用 `0x40600000–0x40800000`，AMD64 使用 `0x600000–0x800000` 作为新任务物理区，并建立仅内核可访问的直接映射。用户的正常映射地址保持不变。镜像装载范围为这一区域预留空间，不依靠另一静态用户载荷初始化子任务。

ARM64 逐八字节复制并清理相应数据缓存地址，最后执行屏障与指令缓存失效，保证复制出的代码可取指执行；此保守实现会重复清理同一缓存行，后续可优化。AMD64 使用整数串复制。两端都在内核屏蔽中断期间完成本次有限复制，尚未实现分页复制或写时复制。

## 验收设计

程序先把全局初值从 17 改为 100，把线性内存写为 123456，再在一个嵌套函数中调用复制。该函数的局部值为 37，调用者还在操作数栈中保留 123。父子必须结合返回码、任务编号、局部值和栈值完成核验，不能用从入口重新启动子程序替代恢复调用现场。

两者各自改写全局和线性内存，重复创建必须被拒且不损坏已有任务。子任务完成百万次求和后退出；父任务阻塞等待，再确认自己的值没有被子任务覆盖。错误返回值或错误数据期望均须失败。

## 尚未完成

当前是静态内存池中的运行时创建：只有一个新增任务槽，不复用结束任务的编号。尚无收尸、页回收、句柄代际、多任务分配器、独立程序装载、文件和 IPC 资源继承。复制普通用户内存不等于实现这些资源的复制语义。动态模块加载、用户态执行器和 Shell 仍按原目标继续推进。
