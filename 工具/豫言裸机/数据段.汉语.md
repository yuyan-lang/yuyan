# 用户态数据段初始化与丢弃

布局更新：固定半兆分割及固定全局基址已取消；当前按元数据实际长度布局，见[元数据布局](元数据布局.汉语.md)。下文涉及旧固定地址和容量的段落仅记录早期实现，当前以新布局为准。

后续已支持预留容量内的增长，现行布局和限制见[内存增长](内存增长.汉语.md)。以下保留该阶段实现与验证记录。

裸机后端已接入标准 `memory.init` 和 `data.drop`，正常操作均由豫言生成的用户态机器码执行。初始化复用双区复制编码，分别检查线性内存目标范围和数据段源范围，两个检查都通过才复制。源范围检查读取该段当前有效长度，丢弃将此长度置零；重复丢弃合法。

主动段在构建初始线性内存时已应用，运行时描述符初始长度为零。被动段保存原始字节与独立长度描述符，初始化不会自动丢弃它。丢弃后允许源偏移零、长度零的初始化，目标地址仍须在合法边界内。语义依据[标准 Wasm 数据段指令](https://webassembly.github.io/spec/core/exec/instructions.html#exec-memory-init)。

有数据段时，用户代码上限改为 512 KiB；其后 512 KiB 存放数据段描述符及载荷，再后仍是最多八页的固定线性内存。每段按四字节对齐，首四字节记录有效长度。描述符及载荷不在 Wasm 线性地址空间内，普通客体访存指令无法寻址它们。没有数据段时保留原一兆字节代码上限。超限明确报错。

这仍是单用户域、静态镜像布局。丢弃不会清擦载荷，也尚未把空间归还分配器；不能据此声称完成了资源回收或动态模块装载。机器页级代码、数据权限分离仍待后续完善。

2026-09-22，双架构六十六项 QEMU 验证全部通过。各新增七项：正常数据初始化、源越界、目标越界、丢弃后非空读取、主动段非空读取、丢弃后零长度源偏移越界、长度回绕。正例覆盖跨页、非零源偏移、多段独立状态、重复丢弃、已丢弃段的合法零长度初始化；六个负例都在核验前触发陷阱。相同标准模块在 V8 中结果一致。

类型检查通过，描述符加载及清零机器指令经反汇编核对。原有复制、填充、标量访存、控制流、控制台和隔离用例均在本轮回归中通过。
