# 真实 DMA 拒绝验证

此阶段用 QEMU EDU 设备验证 IOMMU 是否实际挡住未授权写入。EDU 是专用测试设备，不替代 Virtio 磁盘驱动，也不代表扇区读写或文件系统已经完成。它与磁盘协议分开，有利于直接验证设备地址隔离。

诊断镜像在内核初始配置之后，从固定 PCI `00:04.0` 验证 EDU 标识，分配固定 BAR，启用内存访问与总线主控并屏蔽 INTx。初始化保护区两个哨兵，再请求 EDU 把设备内四字节数据写入未授权地址。设备使用三十二位 DMA 地址掩码，避免 ARM 地址被其默认二十八位掩码截断。请求未打开设备中断。

ARM64 的目标为 `0x400c2000`，AMD64 为 `0x119000`，均是内核保留的测试区域。此时 IOMMU 的流表或根表仍无有效授权项。轮询设备命令位确认传输尝试结束，随后关闭总线主控，再检查哨兵和故障证据。轮询有上限，模拟器外层也有超时。

ARM64 增加了位于 `0x400c1000` 的故障事件队列，连同流表在启动时清零并处理 CPU 缓存。CR0 开启翻译和事件队列，CR0ACK 期望值相应为五。测试要求出现一个无效流表项事件，设备流编号为三十二；读取后推进消费位置。当前仅支持此次诊断的单条事件消费，不是完整的异步设备故障恢复系统。

AMD64 要求 VT-d 报告待处理故障，并从故障记录核对目标地址、设备编号、写访问及根表项缺席原因。核对后清除故障记录并确认待处理标记消失。两架构都要求目标值和相邻哨兵保持不变，然后继续运行真实用户态程序。

负对照使用相同设备和写入请求，但故意省略 IOMMU 初始配置。必须先观察到设备传输结束，再因目标哨兵被改写而失败，不得误报 DMA 拒绝成功。这用于排除设备未启动、地址掩码错误或测试实际上没有发出传输等假通过。

诊断代码由豫言产生原始机器字节，通过专用镜像构造入口注入。普通平台启动没有 EDU 探测，不增加用户态 MMIO 或物理地址系统调用。IOMMU 的事件队列属于正常隔离平台基础设施，始终由内核持有。

本轮验证范围是空授权表拒绝真实 DMA。获授权页的成功传输、只读页写保护、映射撤销与缓存失效、页回收、用户态驱动故障恢复仍需后续实现与验证。最终运行结果以验证记录为准。

依据：[QEMU EDU 设备协议](https://www.qemu.org/docs/master/specs/edu.html)、[SMMUv3 故障事件定义](https://github.com/qemu/qemu/blob/master/hw/arm/smmuv3-internal.h)、[VT-d 故障记录实现](https://github.com/qemu/qemu/blob/master/hw/i386/intel_iommu.c)。
