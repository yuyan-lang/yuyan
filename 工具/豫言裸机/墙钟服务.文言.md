# 墙钟之务：读硬件之钟

内核之务二十六（平台导入 `平台.墙钟秒`，无参，还一三十二位之数）返自 1970-01-01 00:00:00 UTC 起之秒数，以无符号数观之（可至 2106 年）。前此唯有开机以来之钟滴答（务五，每滴答十毫秒），不能言今日几何；今用户态执行器据此而成标准库之 `当前日期时间表示` 与壳之 `日期` 令。内核不存亦不改硬件之钟，时区一以世界协调时为准。

## 两机之读法

| | ARM64 | AMD64 |
|---|---|---|
| 硬件 | PL031 实时钟，QEMU `virt` 中在 `0x09010000` | 旧制 CMOS 实时钟（MC146818），端口 `0x70`（引）、`0x71`（数） |
| 读法 | 一载：数据寄存器（偏零）即秒数 | 读年月日时分秒，以民用历法折为秒数 |
| 权限 | 与串口（`0x09000000`）同处一二兆字节之设备块（二级页表第七十二项，设备内存之性，唯内核可读写，用户态不可及），不增新映射 | 内核处零环，端口出入不待页映射 |
| 码 | 四令：取常量之址、`ldr w0,[x1]`、跳回用户之返路 | 约三百二十字节，皆用有标号之相对跳，无手算之偏 |

务二十六附于两内核务比较链之末（`cmp w2,#0x1a`、`cmp eax,0x1a`），其返值循旧有“写回存帧、复上下文”之公路，故与他务同，不动呼者余下之寄存器。

### AMD64 之折算

一、待 A 寄存器（0x0A）之“更新中”位（第七位）清零；读 B 寄存器（0x0B）得数据之式，第二位为一则二进制，为零则 BCD（QEMU 之默认为 BCD、二十四时制；十二时制未理）。

二、依次读秒（0x00）、分（0x02）、时（0x04）、日（0x07）、月（0x08）、二位年（0x09）、世纪（0x32），各依 B 寄存器之式解之（BCD 则 `十位×10 + 个位`）；世纪寄存器得零（硬件无此寄存器）则取二十。

三、末复读秒一次；与初读异者（读时恰逢进位）则全重读。如此年末之进（23:59:59 而次年 00:00:00）不生“新秒旧年”之怪时。

四、折算用 Howard Hinnant 之 `days_from_civil`：先以一月二月为上年之十三、十四月（`y -= m < 3`），`era = y / 400`、`yoe = y % 400`，`doy = (153·(m>2 ? m−3 : m+9) + 2)/5 + d − 1`，`doe = yoe·365 + yoe/4 − yoe/100 + doy`，天数 = `era·146097 + doe − 719468`；秒数 = 天数·86400 + 时·3600 + 分·60 + 秒。三十二位乘法之低三十二位与无符号数合，故至 2106 年皆确。同一算法先以 JavaScript 对照 `Date.UTC` 检之，1970–2105 年每月之朔日、廿八日、月末与十五日各三时刻（共一万九千五百八十四），皆同。

## 验

`yy裸机验证` 增四式，每式于两机各起一 QEMU，令行带 `-rtc base=<日时>`，以模拟实时钟之始置于奇日，用户模块呼 `墙钟秒`，以**无符号**比较断言（2038 年后之读数在三十二位有符号数中为负）：

| 式 | `-rtc base=` | 所捕之误 |
|---|---|---|
| `墙钟闰世纪` | `2000-03-01T00:00:00` | 四百整除之世纪年为闰（二月二十九日） |
| `墙钟年末` | `2026-12-31T23:59:50` | 年末之进；始点加四十秒之上界跨入 2027 年 |
| `墙钟非闰世纪` | `2100-03-01T00:00:00` | 百整除而非四百整除之世纪年不闰；读数逾 2³¹ |
| `墙钟闰日` | `2032-02-29T12:00:00` | 闰日本身与午时之分秒 |

每用户模块先读一次，断言在“始点”与“始点加四十秒”之间；空转三百万回再读，断言不小于初读、不大于初读加八秒；末印 `普通程序已完成`，退出码与串口输出与他常规式同检。故同一期望之值，既验硬件之口（PL031 与 CMOS 二途），亦验 AMD64 上之折算。

## 界

- 唯秒之精；无设时、闹钟、时区、闰秒。
- AMD64 未理十二时制，亦不查 CMOS 之电池位；QEMU 中二者皆为默认。
- 用户态执行器以之成标准库之 `当前日期时间表示` 与 `格式化当前本地日期时间`（见[客体二号](客体二号.文言.md)“时与杂项之原语”）。昔 WASI 之实时钟（以初读之墙钟秒为锚、循滴答而行，其精十毫秒）随 WASI 而拆出，见 [WASI库](WASI库/说明.文言.md)。
