# 有界任务消息邮箱

每个任务有一个内核管理的邮箱，最多保存一条三十二位消息。用户内存仍相互隔离；发送不需要取得对方的内存地址。

平台接口：

| 接口 | 参数、结果 | 行为 |
| --- | --- | --- |
| 发送消息 | 目标句柄、消息值 → 状态 | 成功返回 0；目标无效、已结束、无权限或邮箱满返回 -1 |
| 接收消息 | 无参数 → 消息值 | 非阻塞，取出一条消息；为空时返回 0 |
| 消息来源 | 无参数 → 发送者句柄 | 返回最近一次接收的来源；最近一次接收为空或尚未接收时返回 -1 |

零和负一都是有效消息，必须用“消息来源”区分空邮箱。接收时记录来源快照，后续发送只改变排队消息，不改变这个快照，因此两次系统调用之间发生抢占也不会混淆已收到数据的来源。

发送使用完整的代际句柄校验；允许给自己、直接拥有的任务或自己的直接所有者发消息。已结束目标不能继续接收。邮箱满时保留原消息，不覆盖或隐式丢弃。

## 内核布局和生命周期

ARM64 邮箱位于 `0x400b0100`、`0x400b0110`，AMD64 位于 `0x103400`、`0x103410`。每个邮箱十六字节，依次为占用标记、消息值、排队消息来源、最近接收来源。初始化和清理将标记、值与排队来源置零，最近来源置为负一。

消息入队和出队在屏蔽中断的内核路径中完成。发送时从保存帧取回第二参数，避免句柄解码所用的临时寄存器覆盖消息值。接收后清除队列中的值和来源，再返回用户态。

运行时复制产生一个空邮箱，不继承父任务的待收消息或来源快照。任务回收同时清理自己的邮箱；父任务已经收到或仍在排队的消息可以保留原发送者句柄，这个历史句柄不因此重新获得操作新任务的权限。

## 验收设计

连续两轮创建子任务，进行准备消息、请求和响应。双方核对消息值和完整来源句柄，并保持各自全局独立。子任务还验证向自己发送零和负一、邮箱满拒绝但不覆盖原消息，以及失败的复制请求不破坏邮箱。

子任务结束时故意留一条未收消息；回收再创建后，初始邮箱必须为空、来源必须为负一。新任务存活时向上一轮句柄发送必须拒绝。

错误消息值、错误来源期望和撤销父子所有权关系均作为负对照。撤销关系只在测试镜像中修改初始化指令，验证器检查目标字节模式唯一；正常系统不允许用户修改所有权。

## 边界

这是单条整数消息、非阻塞接口。测试采用有界轮询；尚无阻塞接收、消息队列扩容、字节缓冲传输、通用端点能力、跨多个服务任务的路由或可靠投递协议。当前仍为两任务槽模型，后续用户态设备和文件服务需要在这些基础上扩展。
