# 文件系统提交日志

2026-09-22：两架构共 294 项 QEMU 自动验收通过，包含十四项新日志用例。类型检查及十四个标准 Wasm 模块的独立验证通过；另行逐记录解析十份磁盘，五组对应磁盘在两架构间完全一致。

这是用户态文件系统的持久化基础，尚不是完整的文件目录接口。它通过现有 Virtio 块驱动提供显式格式化、挂载与校验、追加提交、分段读取，并通过回调向上层重放已提交记录。磁盘格式目前是内部实验格式。

## 提交顺序

每条记录占用一个头扇区、若干数据扇区和一个提交扇区。追加时先写数据、记录头和新的结束标记，执行刷新；再写提交扇区，再次刷新；两次刷新都成功后才更新内存中的尾位置和序号。空记录也具有独立的头与提交扇区。

结束标记是一整扇区零字节。追加会先清除新尾位置，避免重用未完成区域或重新格式化后把旧内容误认为后续记录。最后一条记录恰好填满磁盘时，不向盘外写结束标记。

任何块 I/O 错误都会清除挂载标志并返回错误，调用者必须重新挂载确认结果。空间不足在写入前返回，尾位置和序号不变。

## 布局

| 区域 | 主要字段 |
| --- | --- |
| 扇区零 | 标识、版本一、可用扇区数、校验值 |
| 记录头 | 标识、连续序号、数据字节数、数据扇区数、数据校验、头校验 |
| 数据区 | 指定长度的原始字节，末扇区未使用部分填零 |
| 提交扇区 | 标识、序号、头校验、数据校验、下一尾位置、提交校验 |

所有整数均为小端 32 位。校验初值为 2166136261，逐字节异或后乘 16777619，按 32 位回绕。超级块校验覆盖前十二字节；头和提交校验各覆盖前二十字节；数据校验覆盖有效字节，不包括扇区填充。它是损坏检测，不是密码学认证。

线性内存零至 1023 字节属于块驱动；日志使用 1024、1536、2048、2560 处的扇区缓冲及 4096 起的状态。追加与读取的外部缓冲必须位于偏移 8192 之后，整个范围必须在当前线性内存中。

## 挂载与恢复

挂载先检查格式、容量和校验，再逐条检查序号、长度、盘内范围、头、提交及数据。每条完整记录校验成功后，回调取得序号、数据起始扇区与有效长度，供后续目录层建立索引。回调的内存索引必须由调用者在挂载前清空；只有整个挂载返回成功后才可开放文件接口。

全零记录头表示日志结束。有效头对应的提交扇区全零时，视为未完成尾部，保留之前记录并从该头的位置继续追加。非零但损坏的头、提交或已提交数据会导致挂载失败，不能继续追加。

当前恢复规则针对上述可识别的尾部状态；没有承诺任意掉电写撕裂恢复、整个尾部被抹零的检测或事务掉电一致性。格式化必须显式调用，未知或空白磁盘不会自动格式化。

读取按记录定位信息流式读取扇区，支持跨扇区片段，文件尾以实际可读长度返回。定位信息供受信任的文件系统层使用，不构成文件访问权限；后续目录层仍需验证文件句柄和权限。

## 验收

- 三条不同长度记录写入后，另起 QEMU 挂载并读取，包括零长度、513 字节和 4097 字节。
- 写入一条较长记录后清除其提交扇区并刷新，另起 QEMU 忽略该尾部，再用较短记录替换并重新挂载。
- 篡改已提交数据的一个字节，要求挂载失败且追加被拒绝。
- 空白磁盘拒绝挂载；显式格式化后可使用；再次格式化不恢复旧记录。
- 多次追加直到下一条放不下，验证已提交记录与尾位置不变，随后重新挂载全部有效记录。
- 越界缓冲拒绝，跨扇区片段与超过记录末尾的读取返回正确长度。
