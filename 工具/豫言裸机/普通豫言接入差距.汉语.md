# 普通豫言接入裸机执行器的差距

本记录以 2026-09-23 当前源码为依据。368 项裸机回归证明的是现有系统服务与已支持 Wasm 子集，不证明普通豫言或完整 WasmGC 已能运行。默认 Shell 目前由豫言代码构造整数 Wasm 指令，再降为用户态机器码；还不是普通豫言经完整 ANF/WasmGC 路线编译的 Shell。

## 已核对的真实输入

`工具/网页汇编直生/说明.汉语.md` 描述当前 `--target=wasmgc` 路线；`库/编译器核心/文档/网页汇编后端使用.汉语.md` 描述较早的 LLVM/WASI 路线，不能用后者推断当前目标依赖。

`工具/网页汇编直生/运行时.wat` 已声明：以 i64 字段结构体装箱大整数，以可变 eqref 数组表示元组和引用，使用 i31 小整数、具体引用转换与测试、引用相等、结构字段读取、数组创建/读写/复制/长度，以及异常标签。唯一的通用宿主入口是 `yuyan:gc-host/v1.call`，签名为两个可空 eq 引用参数、一个可空 eq 引用结果。

`统一网页汇编。豫` 生成可空 eq 引用全局、引用参数与结果、带引用字段的代数构造器、i64 数组、i8 数组及优化后的专门结构；`网页汇编编码基础。豫` 还发出 f64 常量及装箱。普通调用之外，尾调用与提前退出路径需要对应控制语义。不能只实现 `struct.new` 就宣称普通豫言已接入。

## 接入顺序与验收

|阶段|当前缺口|所需验收|
|---|---|---|
|类型及值表示|当前签名以数量、引用位图表示，数值栈只存 i32；无法表达完整字段类型、i64/f64、递归类型组及子类型|完整值类型描述与二进制读取；无损宽数值传递；类型等价、可空性、可变字段约束及错误拒绝|
|实例与内存布局|当前执行器依赖固定元数据、值栈、调用帧和客体线性内存区域；增加宽值与 GC 堆前须重新核算容量|布局互不重叠；各区独立边界检查；容量耗尽不破坏其他实例或内核|
|对象与回收|现有函数引用并不是 GC 对象；没有结构体、数组堆和实际回收|按字段类型扫描、循环对象、共享对象、不可达对象回收；回收后继续分配；越界、空引用及错误转换陷阱|
|根集合|局部引用位图只区分现有类型，运行值栈没有持久的 GC 根描述|操作数、调用帧局部、全局、表、宿主暂存和异常载荷中的活引用在回收时都保留；死引用能移除|
|控制与宿主|现有平台桥接仅支持少量 i32 接口，不等于普通豫言宿主协议|尾调用不累积调用帧；异常正确展开并释放帧；宿主调用中分配或失败仍保护根，权限受约束|
|真实端到端|普通豫言和普通语法 Shell 尚未接入|用普通编译器生成独立程序，动态加载、分配超过堆容量、观察实际回收，随后返回 Shell 继续文件操作；两种架构均通过|

先建立通用类型和值表示及内存容量基础，再接对象分配和根扫描。回收器采用何种内部对象地址表示不改变标准 Wasm 引用语义；不得把对象裸地址作为模块可构造的整数公开。首个可验证回收实现可以采用非移动标记清扫，但这只是实现顺序，不缩减递归类型、规范验证和普通程序支持的最终目标。

规范依据：[Wasm GC 类型](https://webassembly.github.io/gc/core/syntax/types.html)、[运行时结构](https://webassembly.github.io/gc/core/exec/runtime.html)。规范将函数引用、聚合对象引用和外部引用区分；i31 不是普通堆分配对象。执行器可选择内部存储和回收实现，但必须保持模块可观察语义。
