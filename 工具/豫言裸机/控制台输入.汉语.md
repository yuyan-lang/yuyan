# 用户态控制台输入

平台导入新增 `平台/读字节 : () -> i32`。无数据时返回负一，有数据时返回零至二百五十五；接口按字节传输，不在内核解析中文字符或命令。ARM64 读取 PL011 的接收状态与数据寄存器，AMD64 读取串口状态与接收端口。客体用户态通过标准 Wasm 导入调用，自有后端生成系统调用桥接。

读取接口不在内核等待输入。当前用户程序通过循环轮询，尚无阻塞唤醒或定时抢占；这一步不是完整终端驱动或默认 Shell。字符解码、行编辑和命令解释应继续在用户态实现。

## 验证

2026-09-22，ARM64／AMD64 共二十四项裸机检查通过。新增输入用例先核验空读，输出“输入就绪”，然后在用户态逐字节读取、回显并累计校验和。驱动程序观察到就绪后才发送“豫”与换行，核验四字节计数、校验和及读取完毕后再次空读。超过一百二十七的字节必须正确零扩展，不能与负一混淆。

错误对照发送“言”与换行，客体必须回显实际输入并报告校验失败。正常和错误用例均检查串口内容及 QEMU 退出码，保留其余权限、栈、算术和结构控制回归。

验证工具全部使用豫言。输入通过命名管道送入 QEMU 串口，输出存入独立文件；QEMU 就绪前不发送测试输入，不把字符串预置进客体镜像。[QEMU 管道后端源码](https://raw.githubusercontent.com/qemu/qemu/master/chardev/char-pipe.c)说明了输入、输出两个路径的打开方式。

```sh
./yy3_bs 工具/豫言裸机/验证。豫 -o yy裸机验证 -j 1
./yy裸机验证
```

本轮产物及串口日志位于 `/tmp/yy裸机验证.ThHhIA`。控制台正常日志包含：

```text
豫言核心启动
输入就绪
豫
用户态计算验证通过
```

后续仍需线性内存、用户态命令缓冲与 Shell、任务调度、持久文件系统及完整 WasmGC。本接口不代表那些目标已完成。

同一标准模块在 V8 完成四次核验与错误输入拒绝。生成器自身编译为 WasmGC 并运行后，输出的 ARM64、AMD64 控制台镜像均与原生生成、已通过 QEMU 的镜像逐字节一致。验证器类型检查通过。
