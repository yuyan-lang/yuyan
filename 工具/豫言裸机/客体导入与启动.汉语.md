# 客体导入、导出与启动

后续进展：默认 Shell 的文件加载已完成，见[命令壳程序运行](命令壳程序运行.汉语.md)；间接调用的受限实现及尚缺的元素段见[客体间接调用](客体间接调用.汉语.md)。下文保留本阶段验收范围。

解释器现在可以按导出名查找函数，连接一组明确的豫言平台函数，并在第一次调用指定函数前执行模块启动函数。所有绑定先核对名字及签名，全部通过后才允许执行。这是标准 Wasm 函数导入导出协议，未改动模块二进制或后端公共 ABI。

## 平台函数

当前支持模块名“平台”下的三个函数：

| 名字 | 签名 | 行为 |
| --- | --- | --- |
| 写字节 | `(i32) → ()` | 经执行器的控制台接口写入低八位 |
| 核验 | `(i32, i32) → ()` | 比较两值；不等时返回客体陷阱 |
| 用户态 | `() → i32` | 调用实际平台服务查询当前权限级别 |

名字逐字节匹配，参数及返回数量必须一致；当前类型层限定这些值为 i32。未知模块名、函数名或不符签名返回负二。绑定表全部建立后才发布可用标志，后面的导入失败不会让前面的函数先行产生输出。

平台核验在执行器内部比较，不用原生核验陷阱终止整个执行器任务。导入调用直接消费和产生解释器值栈上的参数及结果，不把客体整数当作原生函数地址。此版还没有任意导入、WASI 或设备访问接口。

## 导出与启动

`客体查找导出函数` 接收外层内存中的名字地址与字节长度，检查完整范围后查找。找到函数返回其编号；缺席返回负一，找到非函数导出返回负二，查询范围或索引状态无效返回负三。调用者须检查返回值，再交给运行入口。中文名字与其他 UTF-8 名字使用同一标准导出表。

资源初置仍是内部准备步骤。运行入口完成绑定后，在第一次请求函数调用时执行模块的启动函数，再执行所请求函数；启动函数的签名已由索引层要求为无参数、无返回值。两者共享该次执行步数预算。

启动成功后记录完成状态，后续函数调用不会重复启动。启动陷阱或耗尽预算时，该实例标记为启动失败，不能直接重试导出；必须重新进行资源初置才能作为新实例启动。这样不会因重试而悄悄重复启动中的外部副作用。没有启动段的模块也会完成这一准备状态转换。

导入调用额外扣一个预算单位；不能通过反复调用宿主函数绕过限额。每次运行尝试重置写字节及核验计数，仅用于验收观察，不决定导入权限。

## 函数表声明

为了读取常见 C 编译器输出，资源层新增默认空函数引用表的声明检查：当前最多一张 `funcref` 表，初始元素最多一千零二十四，显式最大值不得小于初始值。初置后表项为空引用。表导出检查真实表数量。

这不等于间接调用已经实现。元素段、间接调用、表指令和其他表类型仍未支持；执行入口继续拒绝尚未处理的元素与标签区段。带有未使用的合法空函数表的普通整数模块可以运行。

## 工作区与失效

29176、29180、29184 为表数量、初始及最大元素数。空引用表工作区位于 `[58368,62464)`，以负一表示空引用。导入绑定表位于 `[62464,62976)`，每个导入一个四字节服务编号；这些编号只在执行器的固定分派中使用。

29192 为绑定完成标志，29196 为本次写字节次数，29200 为本次成功核验次数。29204 为启动状态：零待启动，一成功，二启动中或已失败。新模块扫描废弃绑定及启动状态，资源初置也重置它们。固定表仍是单实例工作区。

## 验收范围

内建夹具覆盖十四个模块：导出导入函数、控制台写入、核验成功与失败、错误模块名和签名、全部导入成功前不得输出、启动一次、启动调用导入、启动失败及重新初置、空引用表与表导出范围。有效模块另与独立标准引擎比较；对照使用实际 Wasm 函数提供宿主接口，确保签名检查不被 JavaScript 的可变参数调用规则掩盖。

验证器还增加独立 C 编译模块的客体执行场景。原始外部字节完整复制到客体输入区，经历客体读取、解码、栈验证、资源初置、导出名字查找及解释执行；C 模块调用“平台·核验”回到豫言执行器。正常夹具须完成四次核验，错误夹具须在首次不匹配时返回客体陷阱，承载执行器的任务仍正常结束。

这证明的是标准模块与固定平台函数之间的双向调用。任意两个独立 Wasm 模块的通用链接、默认 Shell 文件加载、WASI、间接调用、通用实例分配和完整 WasmGC 仍待实现。
