# 客体元素段与函数指针

后续进展：表初始化、元素丢弃和表复制已接入，见[客体表批量](客体表批量.汉语.md)。下文保留元素段首次验收时的范围。

资源层读取标准元素段，运行时按主动段初始化函数表。模块中的间接调用由已验证的签名约束，不改变标准二进制格式或后端公共 ABI。此路径在用户态执行，不依赖宿主预先计算调用结果。

当前支持标志零至七的八种元素段编码：主动、被动、声明式，以及函数编号列表或引用表达式列表。引用类型限默认 `funcref`，表达式限 `ref.func` 和以单字节内置堆类型编码的 `ref.null func`；主动偏移限既有整数常量表达式。主动段检查表号，所有非空函数引用检查函数号。被动、声明式元素可以存在于没有表的模块中。

实例化先预检全部主动数据段和主动元素段。空段也必须满足偏移不超过表长度。任何主动段越界均返回负三，并保持原有客体内存、全局值和函数表内容不变；实例就绪标志保持为零。预检成功后清空表，再按段顺序复制，因此后段覆盖前段。主动、声明式段的运行时丢弃标志设为一，被动段保持可用；再次初始化可恢复初始函数表。

工作区：29208 保存段数，29212 保存引用总数；`[46080,47104)` 存放最多六十四个十六字节记录，字段依次为模式、主动偏移、引用池起点、引用数量；`[47104,49152)` 保存最多五百一十二个函数引用，负一为空引用；`[51256,51512)` 保存丢弃标志。函数表仍最多一千零二十四项。容量超限返回负二，这是当前实现限制，不能据此认定输入不符合标准。

尚未支持表修改指令、表增长、多表、导入表、通用引用类型、扩展常量表达式及完整 WasmGC。被动段已正确保存，但其后续 `table.init` 等指令仍待实现。

## 独立 C 输入

[函数指针夹具.c](函数指针夹具.c) 使用 `volatile` 函数指针数组，防止调用被优化为直接调用。启动函数核验两种目标及指针替换；“指针验收”导出通过两次间接调用返回八十四。它仅是外部兼容性输入，客体内核与执行器仍由豫言实现，不链接 C 运行库。

```sh
/Users/zc/repos/yuyan-worktrees/yuyan-wktree-4/yy_wasi_sdk/bin/clang \
  --target=wasm32-unknown-unknown -O1 -fno-builtin -nostdlib \
  -Wl,--no-entry -Wl,--strip-all \
  -Wl,--initial-memory=131072 -Wl,--max-memory=262144 \
  工具/豫言裸机/函数指针夹具.c -o yy函数指针.wasm
```

标准引擎对照覆盖二十五个可明确分类的模块及十五次执行；另外两例验证当前不支持的引用类型或表达式形式应拒绝。裸机新增场景包含二十七组元素段用例。Shell 夹具把相同 C 模块写入“指针.wasm”，首次启动及持久化重启均要求从该文件运行“指针验收”并返回八十四。

规范依据：[WebAssembly 元素段二进制编码](https://webassembly.github.io/spec/core/binary/modules.html#element-section)。
