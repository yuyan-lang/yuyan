# 用户态批量内存填充

裸机后端现将标准 `memory.fill` 降为双架构用户态机器指令，用于清零和初始化线性内存，不调用特权服务完成正常写入，也不分配临时缓冲区。仍使用固定大小内存声明，最大八页。

从操作数栈取出长度、填充值和目标地址；地址和长度按无符号三十二位解释，使用六十四位加法计算末端。先检查整个范围，再开始循环写入填充值的低八位。长度为零时也执行范围检查，合法的内存末端允许零长度操作。语义依据[标准 Wasm 内存指令](https://webassembly.github.io/spec/core/exec/instructions.html#exec-memory-fill)。

2026-09-22，双架构共四十项 QEMU 裸机验证通过。在原三十二项之上，各增加正常填充、越界填充、长度导致的地址回绕、零长度起址越界四项。正常模块覆盖跨页写入、低八位截断、合法零长度、全区填充及局部清零。负例后保留正常核验，避免错误地忽略指令也能通过测试。相同标准模块在 V8 中正例完成四次核验，负例在任何核验前触发陷阱。

机器循环及其分支已反汇编核对，验证入口类型检查通过。命令行原生生成器镜像与 QEMU 受测镜像逐字节一致。

```sh
./yy3_bs 工具/豫言裸机/验证。豫 -o yy裸机验证 -j 1
./yy裸机验证
```

产物目录 `/tmp/yy裸机验证.zY1hXx`；散列、串口日志和退出码见 `验证记录.json` 的“批量填充扩展验证”。本轮仍未实现裸机 `memory.copy`、`memory.init`、`data.drop`、动态页分配、抢占调度或默认用户态 Shell。非法访问仍结束测试客体，尚未实现故障任务退出后系统继续服务。

同一生成器编译为 WasmGC，在既有网页宿主中生成的双架构填充镜像与原生生成逐字节一致。这仅验证生成路径，不表示裸机客体已有 WasmGC 执行器。
