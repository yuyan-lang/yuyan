# 用户态虚拟磁盘读写

2026-09-22：ARM64、AMD64 共 280 项 QEMU 验收全部通过，含十二项新磁盘用例。类型检查、十二个标准 Wasm 模块的独立验证、八份整盘内容检查均通过；两架构写出的持久化磁盘文件完全一致。

用户态磁盘库提供初始化、单扇区传输和停用三个标准 Wasm 函数构造器。它通过已有的受限寄存器接口操作现代 Virtio 块设备，DMA 只使用内核授予的用户线性内存。队列协议、描述符、缓冲准备和完成检查均在用户态执行。

## 布局与调用

线性内存前 1024 字节保留给驱动。描述符表位于偏移零，可用环在 `0x100`，已用环在 `0x200`，请求头在 `0x300`，状态字节在 `0x320`，容量和队列状态在 `0x340` 起。队列大小为八，同时只有一个未完成请求；完成后复用描述符，环槽随序号推进。

设备地址等于线性偏移加 `0x1000`。调用者提供自己的 512 字节数据缓冲，偏移必须不小于 1024，整个缓冲必须在当前线性内存内。

| 传输操作 | 参数 | 返回 |
| --- | --- | --- |
| 0：读 | 扇区号、数据偏移 | 设备状态，成功为零 |
| 1：写 | 扇区号、数据偏移 | 设备状态，成功为零 |
| 4：刷新 | 数据缓冲不参与传输，请求扇区固定为零 | 设备状态，成功为零 |

不支持的操作、未就绪、缓冲越界、扇区越界或向只读磁盘写入，返回负一，不提交请求。扇区号目前为无符号 32 位；容量按低高两个 32 位值读取和比较。每次只传输一个 512 字节扇区，没有多扇区请求接口。

## 初始化和完成

初始化协商版本一、平台地址翻译、刷新特性，并接受设备提供的只读标志。通过有界 PCI 能力链验证通知和设备配置窗口，按配置世次一致性读取容量，配置分离式队列的三块地址，再设置设备就绪。当前窗口布局限定为项目支持的 QEMU 配置，不是通用 PCI 驱动。

读写请求使用头、数据、状态三个描述符；刷新跳过数据描述符。驱动先写好描述符和可用环，通过已有的寄存器调用执行平台内存屏障，然后发布可用索引并通知设备。轮询完成后再次使用屏障，核对已用索引、描述符编号、状态和成功请求的已用长度。请求完成前不复用缓冲。

停用函数仅在同步请求返回后使用：复位设备，等待状态归零，再清除驱动就绪标志。轮询有上限，超时或异常完成会触发任务陷阱；目前没有通用在途取消和故障后资源回收。此实现没有解决真实非一致性 DMA 平台的缓存维护，验收范围仍为 QEMU。

## 自动验收

- 写入第七至第二十二扇区，字节由位置、扇区号和种子在用户态实时计算，并显式刷新。
- 退出 QEMU 后，以同一磁盘文件重新启动第二个 QEMU，重新初始化设备并读回全部十六个扇区。
- 单次启动中反复写读，使用不同的源缓冲和目标缓冲，并预先污染读缓冲，覆盖八槽环的多次复用。
- 检查非法操作、越界扇区、缓冲侵入队列、上界越界及负偏移；拒绝后仍能完成正常传输。
- 只读磁盘拒写后仍能读取原始数据。
- 故意改变数据期望的负对照必须失败。

每个成功用例结束后，宿主独立逐字节核对整个一 MiB 磁盘文件。十六个目标扇区必须匹配公式，其余字节必须保持零。重启读取用例不清空或改写磁盘文件。这证明跨进程重启的数据保留，不代表掉电一致性或文件系统事务已经实现。

```sh
./yy设备配置编译器 工具/豫言裸机/验证。豫 --type-check-only --parallel
./yy设备配置编译器 工具/豫言裸机/验证。豫 -o yy裸机验证 -j 1
./yy裸机验证 --外部模块 yy外部C模块.wasm yy外部C错误.wasm
```

实际结果见验证记录。文件和目录、Shell 文件命令、设备服务进程化、动态执行器及 WasmGC 仍属于未完成的完整 OS 目标。

协议依据 [Virtio 1.2](https://docs.oasis-open.org/virtio/virtio/v1.2/virtio-v1.2.html) 的分离式队列、内存屏障与块设备请求规则。实现和工具使用豫言，客体不引入外部 Virtio 驱动。
