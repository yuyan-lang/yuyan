# 客体执行器二号（普通豫言 WasmGC）

## 何以有此

一号执行器（手写扁平指令列，约七百二十七千字节之源）唯能行整数之子集，模块窗口一百二十八千字节、函数百二十八、值槽四字节，不足以承普通豫言所编之 WasmGC 模块：带标准库打印之最小者，函数八百、全局一千三百五十七、被动数据段五百二十二、类型三十八，用 i64、引用、结构与数组、具体类型转换、异常及尾调用。二号执行器以**底层模式**之常豫言书之（详见 `文档/底层模式.文言.md`；此代昔所自造之括号式低阶语言），约四千五百行，源在 `工具/豫言裸机/客体二号/`，乃一包，书 `「编译模式」者『底层』也。`，唯依 `底层库`。译为 Wasm 模块，读成「网页状态模块」，经既有之寄存器降级入 ARM64、AMD64 用户镜像，于用户态行之。

## 值与对象

- **值槽**：操作数、局部、全局皆八字节槽 `[低字, 高字]`；i32、引用唯用低字，i64、f64 占满。
- **引用字**：零为空；奇数为 i31（`(值<<1)|1`）；低三位 010 为函数引用（`(函数号<<3)|2`）；八字节对齐之堆址为对象。
- **堆对象**：头八字节 `[类型号|种类<<24|标记位, 总字节数]`。结构 = 头 + 每字段八字节槽（压缩字段存低字）；数组 = 头 + `[长度][填充]` + 元素（按宽度一、二、四、八字节）；异常对象（种类四）存标签与载荷。
- **类型表**：每型三十二字节，记种类、参数／字段／元素之情、超类；字段类别零为四字节数值、一为八字节数值、二为引用、三为 i8、四为 i16。类型相涉以超类链断之，函数类型逐字节较其参数与结果之编码。

## 行

- **直解字节码**：每函数初次被召时扫其体，立边表（每字节偏移八字节：块起→end 之后、if→else 之后）；其后 `block/loop/if/br` 由运行时**标签栈**（每项 `[目标, 栈基, 元数, 种类]`）司之，`try_table` 之标签兼理**处理器栈**。
- **寄存器为循环之参**：主循环 `解释循环(指令针, 帧针, 边基, 栈针)` 乃自尾递归之函数，译为回跳；简单指令径续，控制转移类（throw、end、br 系、return、调用系、GC 前缀）经状态格 `新指令针／新帧针／边偏` 交回新现场，`新指令针` 为零则最外层函数已返。
- **显式调用帧**：帧栈项 `[返回址, 召者 fp, 召者函数, 标签栈顶, 处理器栈顶]`；尾调用（`return_call`、`return_call_indirect`、`return_call_ref`）复用当前帧；函数返回则复标签栈与处理器栈。
- 值栈、标签栈、帧栈、处理器栈、标记栈、边表池、堆皆在线性内存，大小由常量定（值栈五十二万四千二百八十八槽共四兆，标签栈六万五千五百三十六项共一兆，帧栈三万二千七百六十八项共一兆，可容数千层之深递归，更深则报“栈溢出：递归过深”，退出码一百二十二）；初逾八页则由寄存器降级之增长助手迁入内核动态块。
- 陷阱径印其因，以专属退出码（一二〇至一三七）退任务。

## 回收

非移动标记清扫：分配先取自由链（小块按八字节分类，大块首次适应而分之），次自堆顶划出，不足则先回收、再向内存请增。对象起始位图（每八字节一位）以辨候选之指针；根为值栈（保守，两字皆扫）、全局、表及异常载荷；堆内对象按类型精扫诸字段。每回收毕，阈值取存活字节与二兆字节之较大者。宿主原语执行时禁回收，免多次分配间之中间对象丢失。

## 宿主原语

`yuyan:gc-host/v1.call(名字节数组, 参数元组)` 按名分派：打印行、打印字符串、标准错误打印行、打印通用值、退出进程、命令行程序名与参数、工作目录、环境变量（恒空）、平台之判、读标准输入行、字节转字符串、字节串之空／长度／取字节／从字符串／单字节／拼接、整数加／乘／除、整数转字符串、字符串转整数，及文件与目录之原语（读写删、建目录、列目录、路径之判、切换目录、格式化与挂载）。整数依运行时之约装箱（i31 或 `$big`），对象类型号取自模块所导出之原型 `yy_bytes`、`yy_tuple`、`yy_big`、`yy_float`。同步子进程之原语见下节。**未实现**：小数精确表示；小数运算见“软浮点”一节，子进程见“子进程”一节。

## 子进程（复制任务、易以盘上之程序、重启）

宿主原语 `豫言_同步运行子进程并继承标准流`、`…并传递输出`、`豫言_同步运行子进程`（标准库「子进程」之 `运行并继承标准流`、`运行并传递输出`、`运行`）由模块 `主机任务` 行之，程序取诸持久文件系统：

1. **父任务**定路径为绝对，验其为普通文件而长合度（八字节至四兆字节），读其字节入堆中字节数组，书命令行参数与程序名于“送子任务之区”（`送参数区` 0xE000、`送程序名区` 0xF000），乃召内核之务 `复制任务`。
2. **子任务**（`复制任务` 返零者）携父任务之全内存而醒：以程序字节拷入模块窗口，以所送之参数与程序名拷为己有之 `参数区`（0xC000）、`程序名区`（0xD000），书新程序之长于状态格 `状态_待重启`（0x970）。其后调用链循原路而返；`调用`、`尾调用` 见待重启，则置新指令针为零，解释循环视为最外层函数已返而退。
3. 入口之**启动循环**于 `启动一次` 返后察待重启：非零则行 `重启准备`，自头再启，是时所读者新程序也。`重启准备` 先**清零**动态区（自 `区域起` 至内存末）——诸区与标记位图皆假定得全零之内存，而所复之内存乃父任务之旧数据（如旧“数据段已弃”之标，令新程序之字符串常量尽越界）；次清状态格区、还模块之长、标块设备为败（设备唯初始任务有之，子任务无文件系统）、去测试导出名与参数、撤待重启。子任务不印函数之果；程序自返则以零退任务，召退出进程则以其码退。
   - **大程序**：程序字节逾模块窗口（四百四十八千字节，即 `0x10000`–`0x7FFFF`）者，子任务不拷入窗口，而于动态区尾 `取区域` 一块（`暂存大程序`）、拷之，其址记于 `状态_暂存址`（0xE40）；`重启准备` 见 `状态_暂存址` 非零，则整搬程序至 `区域起`（memmove，与来源相叠亦可），其后至内存末尽清零，并置 `状态_主程序大`（0xE44）；重启后 `解析模块` 据之以 `状态_模块址` 为 `区域起`、`状态_区域顶` 置于模块之后，主程序遂居动态区之首，模块字节与值栈、堆等皆在动态内存。如是磁盘上至多四兆字节之程序皆可行（编译器库、JSON 库之属使 wasmgc 之产物至七八百千至一兆字节）；嵌入镜像之初始主程序仍受窗口所限。验 `壳/测试/大程序`：三程序（`去柯里化边界`、`整数专门化`、`私有入口`，取自 `测试/网页汇编`，各约零点七至零点九三兆字节）由壳 `运行`，其出与彼等 `.成功` 之期望同。
4. **父任务**复其己之 `状态_是子任务`，`等待任务` 阻塞至子任务退，`回收任务` 释其槽，以退出码为原语之果（`运行` 则返“退出码为零否”）。备阶段任一步败、无空闲任务槽，皆返一百二十七（合标准库“启动败为一百二十七”）。“弃其出”（`运行`）者，置子任务之 `状态_是子任务` 为二，其后 `写字节` 不书一字。

`获取命令行参数` 与 `获取命令行程序名` 所读者，本任务之 `参数区` 与 `程序名区`（初始任务为空参与 `/程序.wasm`）。内核唯两任务槽，故一时唯一子进程，子任务中再行子进程则得一百二十七。**出之捕获与异步子进程**：`豫言_同步运行子进程并获取输出`（四十六）置子任务之“输出模式”为三，子任务每 `写字节` 先攒至三字节（满三、遇换行或改流时）而打为一信 `0x40+16×流位+字节数` 附低三字节，经内核邮箱送初始任务（句柄零），复阻塞以待父任务之确认；父任务于 等待消息 循环收之，依流位追加于两可倍增之缓冲，回确认，待等待返空（子任务已退）乃 等待任务、回收任务，返（退出码为零否，标准输出，标准错误）；子任务每退出之前（退出任务、致命退出、启动毕）先冲刷。异步子进程（六十七启、六十八试收、六十九多路等待）用同法：启后即返句柄一，试收不阻塞而排空邮箱、察任务状态之位，多路等待于每关注项皆报“就绪”，使异步之框架回而轮询（子任务须赖父任务持续轮询确认乃得毕）。

### 子进程中之文件：远程文件之召

块设备唯属初始任务（子任务之 `块态` 为二，无设备窗口），故子任务中二十八至三十六、三十八、三十九号文件原语（读写删文件、列目录、路径之查、切换目录、建目录）不本地而行，乃**由初始任务代办**（`远程文件` 模块）：

- **约**：子任务序列化“原语号加参数元组”为字节流（种类字节加载荷：零空引用、一小整数、二大整数、三字节数组、四元组，至多三层），经内核邮箱（每信一 32 位整数）送初始任务。流之传：先一“头”信（高字节为流标 `0x60` 请求、`0x70` 应答，低二十四位为总长），后每信带一至三字节（高字节 = 流标加字节数）；收者每收一信即回一确认（值一），故两边皆阻塞往返。
- **父任务一侧**：候子之循环（`接收捕获`，今诸输出之模式皆由之）与异步之轮询（`排空捕获`）于 `处理捕获消息` 认流标 `0x60`，付 `服务远程调用`：确认其头、收齐其请求、反序列化得参数、召同一 `宿主文件调用`（故文件系统之状态唯一份而一致），复序列化“文件系统错误码加结果对象”为应答流以回之。
- **子任务一侧**：`文件原语分派`（`主机` 转二十八号以下诸原语于此）见 `状态_是子任务` 非零而号可远程，则行 `远程文件调用`：相对路径先依子任务自己之当前目录（父任务于复制任务之前写入 `送程序名区` 加二零四八，子任务改装拷之于 `程序名区`，重启后 `继承当前目录` 复之，故子进程承壳之当前目录）规为绝对而后送；三十八切换目录以三十四（存在）、三十五（是目录）二查确之，唯改自己之当前目录；三十七、四十至四十二仍本地处之。通讯败则书错误码 `错_未挂载` 而返形状合宜之空果。
- **费与界**：每信唯三字节，二十万字节之文件读、写、复读凡六十万字节，在 QEMU TCG 约数秒；宜于命令行程序之小文件，不宜搬运兆字节级之数据。子任务不得再起子进程（无第三任务槽），故无“孙进程”。
- **邮箱满与重试**：内核邮箱唯容一信，请求与应答又为“发一信、候确认”之乒乓，故对端方被唤醒而取确认、尚未被调度之时，本任务紧接所发之下一信（连续之远程调用即然）会因“邮箱满”得负一。`发送消息` 遂于败时重试（至多二十万次，每次皆入内核，时钟中断使对端得行），试尽仍败之目标记于 `状态_发送失联`，此后立败。此患于 WASI 文件层于子任务中连发数十调用时始露（约十余次运行遇一次），修复之后连行三十次无一败。
- **验**：壳之试 `子进程文件`：子程序 `文件工` 于子任务读预置文件、写新文件而复读、路径存在／是文件夹／是普通文件、列目录、删文件、写读六千字节之较大文件，其出与期望同；返壳之后壳自 `读`、`列` 亦见子程序所写之文件（文件系统之状态唯在初始任务）。

### 标准入之重定向、环境变量与顺序之管

子任务之标准入，昔唯控制台，环境变量亦不得。今补此三事，皆循旧径：父任务于复制之前，写信于 `送程序名区`，子任务改装拷之于己之 `程序名区`（同当前目录之承），不须新内核之服务：

- **新宿主原语二**（`主机名` 之七十、七十一号，普通豫言之程序以 `《《C调用》》名『豫言_设置子进程输入』` 之类声之，壳中即如此）：`设置子进程输入(路径)` 令下一子进程之标准入自该文件而读（路径先规为绝对，空串为清除），`设置子进程环境(块)` 予下一子进程一环境变量块（“名=值” 以换行相隔之串，空串为清除，总长至多一千零二十字节，过长则清而返负一）。二者皆写于 `送程序名区` 之定偏移（输入路径于二千五百六十，长四字节加路径字节；环境块于三千零七十二，总长四字节加以零终之诸串），`加载并复制` 于父任务一侧复制之后清之，故唯对紧随之子进程有效。
- **子任务中之标准入**：重启之后 `加载输入文件`（于 `挂载磁盘` 之后）读 `程序名区` 中之路径，以 `文件原语分派`（二十九，子任务经邮箱远读）读其全文入堆中之字节数组，存于 `状态_输入缓冲`（回收时为根，`标记瓦表` 兼标之），`状态_输入位` 置零；读败则当空文件。`读字节`（平台层）见 `状态_输入缓冲` 非零，即自其内容而取，尽则返负二（“文毕”，负一仍示控制台暂无输入）。上层三读者皆因之而改：`读行核` 于文件之制不回显、略回车、遇毕而已有字则先付之、无字则返负一；`输入行对象`（原语十五，标准库之 `尝试读取标准输入行`）遇文毕返 (0, 空)，即标准库文所谓“输入尽则返阴与空串”；WASI 之 `fd_read` 于文件之制，径依 iovec 自全文取字节（不成行、不补换行、二进制无损，尽则读零字节）。
- **环境变量**：`程序名区` 中之环境块，二处读之。`获取环境变量`（原语九，标准库之 `环境变量` 模块）依名（第零参数）而寻，返二元组（得与否、其值）；WASI 之 `environ_sizes_get`、`environ_get` 报个数与总字节，并拷整块入客体之缓冲、写各项之指针，故 C 之 `getenv`、`environ` 皆可用。
- **壳之一侧**（`壳/壳。豫`）：`设 名 值`、`取消 名`、`环境` 三令维护环境变量，存于文件 `/.环境`（每行 `名=值`，故重启而仍在）；每次 `运行` 之前，尽以诸条交 `设置子进程环境`。`运行 路径 参数… < 文件` 先验输入文件之在，再以 `设置子进程输入` 告执行器（可与 `>`、`>>` 并用，脚本中亦可用）。`运行 甲 … | 乙 … | 丙 …` 乃**顺序之管**：依 `|` 切为诸段，前段以“获取输出”取回标准出（标准错仍显），写于临时文件 `/.管道甲` 与 `/.管道乙`（更迭而用），为后段之标准入，末段如常处之（可加 `>`），毕则删临时文件。诸段一接一而行，非同时也（内核唯二任务槽），故前段必能自终。
- **验**：Node 夹具（带虚拟块设备，于 `0xD000+2560`、`+3072` 置输入路径与环境块，与 QEMU 中子任务改装所拷者同）验 C 程序 `字数`（`行 3 词 7 字节 64`，末行无换行而字节亦逐一相同）、`大写`（原样而出，不多补换行）、`回声`（按行读）及 `环境`；壳测试 `管道` 于二架构之 QEMU 验 `设`、`取消`、`环境` 与 C 程序之 `getenv`、`environ`、`< 文件` 之重定向（含输入文件不在之报错）、`猫 | 大写`、三段之管 `猫 | 大写 | 字数`、末段 `> 文件`、六过滤之器（`排序 | 去重 -c` 数词频、`猫 | 找 an | 排序 -r`、`头 -n 2`、`尾 -n 2 < 文件`、`倒行 | 头 -n 3`、`找 -c`、误参；其出与 macOS 自带之 sort、grep、head、tail 逐字相同；uniq、tac 唯于 BSD 特有之细节有异，其行为依 GNU 之约）；壳测试 `示例` 中二普通豫言程序 `行数`（以 `尝试读取标准输入行` 读至毕，末行无换行亦算一行）与 `环境变量`（以 `获取环境变量`）验标准库之一侧。连行 `管道` 十二次无一败。


## 小数：软浮点

标准库之小数运算皆宿主原语（`豫言_小数加`、`减`、`乘`、`除`、`小数转字符串`、`字符串转小数`、`小数转整数`、`整数转小数`，号四十九至五十七），小数于宿主为 `yy_float` 之结构（头加一八字节槽）。内核降级之后端无浮点指令，故执行器用**软浮点**（`软浮点` 模块，以整数指令行 IEEE 754 binary64，就近舍入取偶）：

- **加减乘除**：拆为“符号、指数、首位在第六十二位之六十四位尾数”，对阶、加减，或作一百二十八位之积、六十四次逐位试商，终由统一之打包函数归一、舍入、处次正规数与上溢；非数、无穷、零之诸组合皆依 IEEE 754。
- **整数与小数之互转**：整数（六十四位有符号）转小数，就近舍入；小数转整数，向零截断，非数为零，逾范围则饱和于极值。
- **小数转文**：定点六位，与 JS 之 `toFixed(6)` 全同（平局取绝对值大者）：以大整数精确算 ⌊值×10^6+½⌋；值不小于 10^21 者仍书全部数字（JS 改用指数记法）。
- **文转小数**：跳前导空白，可有符号、整数与小数位、`e`／`E` 指数、`inf`／`nan`；无可转者得零。诸有效数字累为大整数，D×10^E 以大整数精确舍入（十九位以内且 |E| 不逾二十二者，一乘或一除之快路），与 `Number()` 逐位相合。
- 未作：`小数精确表示`（最短往返之表示）。Wasm 之 f32、f64 指令见下一节。
- **验**：Node 脚本 `客体二号/软浮点对照.cjs` 直召执行器所导出之 `浮点运算`，随机对照 V8 之双精度（`node 工具/豫言裸机/客体二号/软浮点对照.cjs x.wasm 轮数 种子`）——加减乘除、整数转浮点、浮点转整数、定点串、文转小数，各数百万次无差（含次正规数、无穷、非数、平局、四十七例已知之舍入难题）；验收 `普通探针/小数。豫`（诸运算与转换）与 `小数压力。豫`（六百轮混合运算而累之，凡一次舍入之误皆改其果），参照取自 Node 宿主之硬件双精度，双架构 QEMU 逐字相同。
- **时与杂项之原语**（五十八至六十六）：`获取当前纳秒时间`（内核时钟滴答，每滴答十毫秒而换算）、`获取当前本地日期时间字符串`、`格式化当前本地日期时间`（读内核之墙钟务，即硬件实时钟，见[墙钟之务](墙钟服务.文言.md)；所得为 UTC 之时，式 `YYYY-MM-DD hh:mm:ss`，`格式化` 支持 `%Y %m %d %H %M %S` 与 `%%`）、`路径可执行`（即普通文件）、`查找可执行程序`（于 `/bin` 与 `/程序` 下寻）、`路径为符号链接`（恒否）、`取得真实路径`、`在线处理器数量`（恒一）、`字符串按字节在前`。

## Wasm 浮点指令

普通豫言之编译器不生浮点指令（小数走宿主原语），然他编译器所出之模块（C、Rust 之属）必用 f32、f64，故执行器尽作 Wasm 1.0 之浮点诸指令与 `0xFC` 前缀之饱和截断（`浮点指令` 模块，共六十六条，借软浮点为本）：

- **较**（f32 `0x5B`–`0x60`，f64 `0x61`–`0x66`）：eq、ne、lt、gt、le、ge，径较位型；有非数则唯 ne 为真，`+0` 等于 `-0`。
- **算**（f32 `0x8B`–`0x98`，f64 `0x99`–`0xA6`）：abs、neg、copysign 唯动符号位（非数之载荷不易）；add、sub、mul、div 用软浮点之解包、对阶、乘积与逐位试商，终由统一之打包为之；min、max（有非数则得非数；二零异号，取小得 `-0`，取大得 `+0`）；ceil、floor、trunc、nearest（就近取偶）于尾数上依 (六十二减指数) 位之掩码取整，必要则加一单位而后打包，其果必可精确表之；sqrt 以被开方数（尾数，指数为奇则左移一位）乘二之六十二次方为一百二十八位数，逐位试根以求整数平方根，根之平方不及被开方数则置粘位，指数取半。
- **转**：i32、i64 转 f32、f64（有符号与无符号，一舍而成，i64 转 f32 无重舍）；`f32.demote_f64`、`f64.promote_f32`（依源格式解包、依目标格式打包；非数得安静非数，无穷与零保其号）；截断为整数 `i32／i64.trunc_f32／f64_s／u`（非数陷“无效的整数转换”，越界陷“整数溢出”，皆以退出码一百二十五终；先取整数部而后判其范围，故 `-0.9` 转无符号得零）；`0xFC 0–7` 之饱和截断（非数得零，越界取极值）。
- **单精度**：值槽低字置 f32 之位型。运算前置状态格 `浮格_格式`（0xE30）为一，软浮点之解包、打包与特殊值之存，皆依之改用 binary32（二十三位小数自尾数第三十九位起，保护位三十九，指数偏置一百二十七），故 f32 之四则、开方、取整与整数之转，皆径以二十四位精度一舍而成，不经 f64；运算毕必置回零（宿主原语之小数恒为 binary64）。
- **非数**：算与转所生之非数，一律安静非数（f64 `0x7FF8000000000000`，f32 `0x7FC00000`）；规范所许载荷之异不作要求，abs、neg、copysign 按位为之，故载荷不失。
- **验**：Node 脚本 `客体二号/浮点指令对照.cjs` 直召执行器所导出之 `浮点运算`（运算号二百五十六加 Wasm 操作码，或五百一十二加饱和截断之子操作码，以合成之值栈径调 `执行浮点`、`浮饱和截断`），每指令各造仅含其一之小模块于 V8 运行，以随机与边界之入（非数、无穷、±0、次正规数、整数与小数之界、平局、2^31／2^32／2^63／2^64 上下之值）逐位相较，陷阱之有无亦须相合：六十六条指令，三种子各百万轮（凡约二亿次）无差（`node 工具/豫言裸机/客体二号/浮点指令对照.cjs x.wasm 轮数 种子`）。端到端之验 `普通探针/盘/浮点-一。豫`：由 `客体二号/造浮点模块.cjs` 生客模块 `浮点.wasm`（六十六导出 `op0…`，各遍历一千二十四项输入表，累其果之位为校验和；会陷阱之截断先夹其入于范围内），期望之校验和取自 V8 运行同一模块；普通豫言之驱动动态装之而逐一调用，ARM64 与 AMD64 之 QEMU 皆逐位相同，即译为机器码之执行器所行软浮点与 V8 合。

## 表与元素段指令

除 `table.get`、`table.set`、`table.size`（解释器内）外，`表指令` 模块尽作 `0xFC` 前缀之 `table.init`（十二）、`elem.drop`（十三）、`table.copy`（十四）、`table.grow`（十五）、`table.fill`（十七）：

- 表之存储于解析时依“上限”一次而分（有所声明之最大者用之，否则最小加一千零二十四），`table.grow` 唯于此容量之内增，逾之则返负一；所增之项以所给之引用填之（空引用为零，函数引用为 `函数号 << 3 | 2`）。
- 范围一律以无符号数检之，且防加法之溢，越界则以退出码一百二十四陷入；`table.copy` 许表内与表间之重叠复制；已弃之元素段与声明式之元素段（标志三、七）其可用长为零，故 `table.init` 唯许零长；`elem.drop` 重行亦合法。
- 元素段中之常量式元素（标志四至七）于运行时由 `求值常量式于` 于当前栈针之上之空闲区求之（实例化时仍用值栈基）。
- **验**：Node 脚本 `客体二号/表指令对照.cjs` 随机造小模块（二 funcref 表、五种元素段、三至九条随机表指令，参数间或越界），同一模块先于 V8 行之，复置于执行器，较其返回值或陷阱：三种子各二千场景（约四千有返回值、二千陷阱）无差；端到端之验 `普通探针/盘/表-一。豫` 于两架构之 QEMU 装十二模块（由 `表指令对照.cjs --造探针` 所生，各十四至二十一条表指令），返回值与 V8 逐一相同。

## WASI preview1 之子集：行外来工具链所成之命令行程序

他家编译器（wasi-sdk 之 C、C++，Rust 之 `wasm32-wasip1` 目标等）所成之命令行程序，依 WASI preview1 之约，导入 `wasi_snapshot_preview1`，导出 `_start` 与 `memory`。执行器径作其大半之函数，故此类程序不经转换即可于壳中 `运行`，示例与编译之法见 [WASI示例](WASI示例.文言.md)。其作分三模块：`WASI基础`（命令行、标准入出、时钟、随机数、轮询）、`WASI文件`（描述符三起之文件与目录）、`WASI`（依函数号而分派）。

- **接**：`解析导入段` 见导入之模块名为 `wasi_snapshot_preview1` 者，于 `瓦名表`（名以逗号相隔，序号自一起：`args_get`、`args_sizes_get`、`clock_res_get`、`clock_time_get`、`environ_get`、`environ_sizes_get`、`fd_close`、`fd_fdstat_get`、`fd_read`、`fd_seek`、`fd_write`、`proc_exit`、`random_get`、`sched_yield`、`fd_prestat_get`、`fd_prestat_dir_name`、`fd_filestat_get`、`poll_oneoff`、`fd_advise`、……、`path_open`、……、`sock_shutdown`，凡四十六名，表外者得九十九）依函数名查其号，函数条之宿主号记为三（`宿主号_WASI`），WASI 之函数号记于链接函数格；`调用` 与 `尾调用` 见宿主号三，径调 `WASI调用`，不经 `yuyan:gc-host/v1.call`。参数在值栈，每槽八字节（i32 用低字，i64 满之，高字别取），个数须合规范（不合返 EINVAL）；错误码回写于第一参数之槽，即函数唯一之果。
- **命令行**：`args_sizes_get`、`args_get` 予 argv[0]（壳所传之程序路径，未予则 `/程序.wasm`）与 `运行 路径 参数…` 之诸参数；环境变量取自壳之 `设` 令（见“标准入之重定向、环境变量与顺序之管”一节），`environ_get`、`environ_sizes_get` 与 C 之 `getenv` 可用。
- **标准出与标准错**：`fd_write` 唯认一与二，逐 iovec 付于 `写字节`（故子进程之出，捕获、丢弃及壳之 `>` 重定向皆如常），标准错暂置 `状态_输出流` 为二。描述符之问，报三标准流为字符设备，权限不含寻，wasi-libc 之 `isatty` 由是判其为终端而按行缓冲，交互程序之提示得以及时现。
- **标准入**：`fd_read` 逐行读（`读行核` 司回显与退格），行末补换行，按 iovec 依次交之；行首之 Ctrl-D（0x04）示文毕，此次读零字节；标准入若为 `<` 或管所重定于文件，则径依字节自全文取（不成行，见上一节）。
- **时钟、随机与睡眠**：`clock_time_get` 之实时钟（id 零）为自 1970 年起之纳秒：初取时读墙钟务得秒数，并当时之时钟滴答存为锚（`状态_实时锚秒`、`锚滴`），其后 = 锚秒 × 10^9 + （滴答 − 锚滴）× 10^7，故精为十毫秒、一程序之内单调不减；余钟（单调、进程与线程之 CPU 时）为开机以来之滴答乘十之七次方纳秒；`clock_res_get` 报十毫秒；`random_get` 用 xorshift32，种取时钟；`poll_oneoff` 支持时钟之订阅（相对与绝对之时）与文件之订阅（恒就绪）：有就绪者则立报之，否则忙候至最早之截止（滴答即十毫秒），故 C 之 `sleep`、`usleep`、`nanosleep` 可用。
- **文件与目录**：描述符三乃预开之根目录 “/”（`fd_prestat_get`、`fd_prestat_dir_name` 报之，wasi-libc 据此使程序中之绝对与相对之路径皆映于此），`path_open` 返描述符四起者（至多十六）。文件之全部内容缓于堆中之字节数组：只读而开，以 `读文件原语` 一次读入；写而开，缓冲而写（容量倍增，越末而再写所留之空洞为零，上限八兆字节），`fd_close`、`fd_sync`、`proc_exit` 及 `_start` 正常返回时，以 `写文件原语` 整个写回（整文件替换）；故程序以陷阱而终者，未关闭之文件内容失之，正常而退者（含未 `fclose` 之文件）则由执行器写回。描述符表由 `初始化区域` 分配于区域分配器，缓冲之字段为垃圾回收之根；每文件之操作始，先依阈而回收一次，其间禁回收（`文件操作始`、`文件操作终`），因宿主之局部变量非回收之根。**诸文件之操作皆经 `文件原语分派`**（二十八至三十六、三十九、七十二号），故子任务中亦可用（化为邮箱上之远程调用，缓而一致，见上一节）；WASI 之模块无 `yy_bytes`、`yy_tuple`、`yy_big` 之导出，`发现宿主类型` 乃于类型表之末补三条合成之类型（字节数组、元组、大整），文件原语与远程之调用遂得如常造字节数组与元组。所作：`path_open`（创建、必为目录、必新建、截断、追加）、`fd_read`、`fd_write`、`fd_pread`、`fd_pwrite`、`fd_seek`、`fd_tell`、`fd_close`、`fd_sync`、`fd_datasync`、`fd_fdstat_get`、`fd_filestat_get`、`fd_filestat_set_size`（截或增）、`fd_readdir`（含 “.” 与 “..”，`d_type` 为未知，付 stat 再问）、`path_filestat_get`（文件之大小取自原语七十二 `获取文件大小`：`主机文件` 之 `文件大小原语` 唯查路径之项，不读其内容，路径无有或非常文件则返负一；子任务中亦走邮箱远调，一往返唯带一整数）、`path_create_directory`、`path_remove_directory`、`path_unlink_file`、`path_rename`（文件；空目录）；`fd_advise`、`fd_allocate`、`fd_fdstat_set_flags`、`fd_*_set_times` 唯验描述符即成；`fd_renumber`、`path_link`、`path_symlink`、`path_readlink` 及套接字未作（前三者 ENOSYS，`path_readlink` 恒 EINVAL 即“非符号链接”）。错误号依 POSIX：不存在 ENOENT、已存在 EEXIST、父路径为文件 ENOTDIR、读写目录 EISDIR、非空目录 ENOTEMPTY、盘满 ENOSPC、所开过多 EMFILE。
- **退与陷**：`proc_exit` 先写回所写之文件而后 `退出任务`，退出码归于壳；`_start` 正常返则为零（`启动一次` 末亦写回文件）。C 之 `abort`（unreachable，一百二十八）、整数除零（一百二十五）、线性内存越界（一百二十七）、间接调用越界（一百二十四）皆唯止此子任务，壳照常印退出码而继行。
- **余**：`fd_fdstat_get`、`fd_filestat_get` 于标准流予最小之答（字符设备）；`environ_*`、`sched_yield` 同；余 WASI 函数返 ENOSYS（五十二）。诸指针皆依客体线性内存检之，越界返 EFAULT（二十一）。
- **内存之长**：C、Rust 之程序，其堆赖 `memory.grow` 而长，然其内存段多不声明上限。模块导入 WASI 函数而未声明上限者，`解析内存段` 以一百二十八页（八兆字节）为上限一次预留（他模块仍唯占其所声明）。此由 wasi-sdk 所编之 `计算` 程序所暴露：昔 `memory.grow` 一概败，dlmalloc 得空指针而暗写于地址零，二叉树之高遂少算一层。
- **邮箱发送之重试**：文件层于子任务中连发远程之调用甚多，遂露一共有之偶患：内核邮箱唯容一信，对端方被唤醒而取确认，往往未及被调度，本任务已发下一信，`发送消息` 返负一（“邮箱满”），远程调用遂判为通讯之败（约十余次运行遇一次：一次 `open` 报 EIO 而其后尽 ENOENT，一次子任务中途陷阱）。今 `发送消息` 败则重试（至多二十万次，每次皆入内核，时钟中断使对端得行而取走其信），试尽仍败之目标记于 `状态_发送失联`，此后发往彼者立败；壳测试 `WASI文件` 连行三十次（每次二架构）无一败。
- **验**：`WASI示例/程序` 下十二程序皆 wasi-sdk 所编。执行器（Node 夹具，带虚拟块设备）与 Node 自带之 `node:wasi`（以 “/” 预开于临时目录）行同一 `.wasm`，标准出与退出码逐字相同（`计算` 于 `-O0`、`-O1`、`-O2`、`-Os`、`-O3` 五等优化下皆同）；文件试之异，唯 Node 于目录之大小、于目录之 `read`（EBADF 而非 EISDIR）、于 `unlink` 目录（EPERM 而非 EISDIR）之宿主特有之答。`文件压力`（百千字节之文件整读四百次，约四十兆字节之堆分配，堆唯三十二兆字节之量）验文件缓冲之回收。壳测试 `WASI` 与 `WASI文件` 于二架构之 QEMU 行之：命令行参数与退出码、标准错、素数、排序、二叉树、八皇后、SHA-256、libm、`printf` 诸式、时钟与随机与睡眠、四陷阱、由串口输入之回声（行首 Ctrl-D 而止），及于子任务中建目录与文件、追加、读写万字节、寻与截、列目录、改名与删、诸错误号、未 `fclose` 之文件于退出时写回，且由另一子进程与壳自身（`读`、`列`）读得同样之内容。

## 多实例：动态装载之模块与跨模块之导入导出

执行器能于运行中更装诸 Wasm 模块，使之相调。初始之模块（普通豫言程序）为实例零，余者为**实例**；每实例各有类型表、函数表、全局、表、元素段、数据段、标签、线性内存与导出表（“默认独立内存”），实例之间唯换数值，不共 GC 之引用。

**宿主原语**（`yuyan:gc-host/v1.call` 之扩，号四十七、四十八；普通豫言以 `《《C调用》》名『…』` 明之，见 `普通探针/盘/动态-一。豫`）：

- `豫言_加载模块(路径, 名字)`：自持久文件系统读模块，成新实例而返其号（一以上）。败则返负一路径无效、负二不存在、负三非文件、负四长不合（八字节至四兆字节）或实例已满（并初始者至多十六）、负五读文件败。名字乃他模块 `导入` 之时所书“模块名”。
- `豫言_调用导出(实例, 导出名, 实参…)`：召某实例所导出之函数。实参为整数（i32 取低三十二位，i64 取全），返其首果（装为整数，无果则零）；唯支持至多一果，实参数须与函数合，否则致命而退。

**实例之上下文**：模块之类型表、函数表、全局表、表描述、元素段、数据段、标签、起始函数、客内存、节表、模块字节之址与长、宿主原型类型（`yy_bytes` 等）皆存于自 0x41C 起之一段状态格（`布局` 之 `上下文首`、`上下文长`），解释器恒只读此诸格；`切换实例` 者，存现上下文于实例记录，复以目标之记录拷入状态格（`实例` 模块）。值栈、标签栈、帧栈、处理器栈与 GC 堆，诸实例共之。

**堆与回收**：初始实例之元数据置于区域分配器；他实例之模块字节、元数据、诸表与客内存皆置 GC 堆之**原始块**（对象种五，回收时唯标而不扫），头址记于所属实例记录之块表，回收时以为根；回收又遍历诸实例之全局与表以为根。对象头字零之第十六至二十三位记造之之实例号（实例零则与旧头字节全同），故回收能以正确之类型表扫各实例之对象，`ref.test`、`ref.cast` 遇他实例之对象，一概判其不属。

**跨实例之调**：调用帧多记“调用者之实例”。导入若链于他实例所导出之函数，`调用`、`尾调用` 乃压帧、切至目标之实例、入目标之函数；`返回处理` 弹帧时，帧中之实例与现异，则切回。`调用导出` 则由驱动就地压一带“返回钩”之帧：返回时解释循环退出，入口之驱动循环装箱其果，自调用者之下一指令续行（宿主原语须返引用）。异常不越实例之界：处理器栈项记所属之实例，分发时跳过他实例之处理器。

**链接与延迟之链**：模块之导入项若非 `yuyan:gc-host/v1.call`，则依“模块名”求已装载之同名实例，再依“字段名”求其所导出之函数，核其函数类型（参数与结果之编码逐字节相同）后，改导入条为“链于 实例号加函数号”。装载时每导入试链一次；仍未连者，于初被调用时复试（**延迟之链**），故相互导入之二模块得先后而装：先装者对后装者之导入，待后装者装毕、被调用时乃链。

**驱动循环（请求）**：有宿主原语须用执行器余部（装载须解析模块、行起始函数），而底层模式不许互递归；故原语唯登记请求于 `状态_请求` 而返占位之果，`调用` 令解释循环退出（`状态_续*` 存续行之现场），入口之 `处理请求们` 办毕（如 `加载实例`）则写果于占位槽，复自所存之现场重入解释循环。子进程之“待重启”亦用此退出之法。起始函数中不得复发请求。

**界**：跨实例唯传数值（i32、i64），不传 GC 引用与函数引用；表与元素段之导入导出、内存与全局之导入导出、多果之 `调用导出` 皆未作；导出之函数本为导入者（转发）不支持；装载不验模块，不合规则致命而退。

## 持久文件系统与块设备

Virtio 块设备（现代之协议、单队列、一次一请求）之驱动行于用户态：初置时协商特性、核 PCI 能力链、配队列而读容量；队列、请求头与数据之缓冲皆在内核所授之静态窗内，用户态唯经 `搬入静态／搬出静态` 二内核服务存取。文件系统乃双区追加日志：超级块加两等长之记录区，记录由头扇区、数据扇区、提交扇区合成，挂载时顺次验之，遇无效之头或缺提交扇区即为日志之尾；空间不足则紧缩存活之条目入他区而换超级块。

## 构、调与验

```text
./yy豫构 构建 客体二号 --输出 /tmp/yy客体二号.wasm
```

所成者标准 Wasm 模块（导出 `启动`，签为 `() → ()`）。验证之器 `工具/豫言裸机/普通豫言验证。豫` 读之，附客体模块（0x10000 起，至多四百四十八千字节；盘上之程序至多四兆字节，见“子进程”一节）、模块之长（0x408）及标志数据段，生 ARM64 与 AMD64 镜像。`启动` 缺省召导出 `_start`，试验时可于 0x2400 置导出名、0x2440 置参数个数、0x2444 起置 i32 参数。同一 wasm 可于 Node 调试：宿主供 `平台` 模块之 `写字节`、`退出任务`、`读字节` 及设备诸函数，先写客体入内存再召 `启动`。

验：`yy普通豫言验证` 编 `普通探针/` 下诸 `.豫` 源（`./yy豫构 … --target=wasmgc`），嵌模块入执行器，生 ARM64 与 AMD64 镜像于 QEMU 行之，要求串口输出恰为「豫言核心启动」、与 `.期望`（宿主 Node 行同一模块之出）逐字同之程序输出、「用户任务全部退出」；磁盘之探针别带持久盘，涵跨重启之文件读写。用户态壳之试在 `工具/豫言裸机/壳/测试/`：`名.输入` 由串口送壳，`名.期望` 乃壳之全出；有 `名.预置` 目录树者，别挂离线所造之持久盘，树中以 `。豫` 终之文件先编为 wasmgc 模块，以 `.wasm` 之名入盘（如 `/程序/你好。豫` 成 `/程序/你好.wasm`），故 `运行` 命令之验乃真子进程：参数与程序名之传、退出码返于壳、启动败为一百二十七、弃其出、相对路径；`崩溃` 之试中子程序除以零（退出码一百二十五）、无止递归（栈溢出：递归过深，一百二十二）、内存耗尽（堆内存不足，一百二十）皆止于子任务，壳照常报其退出码而续行下一命令；`子进程文件` 验子任务中文件之读写（由初始任务代办）于壳中亦可见；`重定向` 验 `追加`、`复制`、`移动` 及 `>`、`>>`（含 `运行 … > 文件` 以“获取输出”取回子程序之出）；`脚本` 验 `脚本 路径` 逐行行文件中之令（先示 `+ 令`，`#` 起者与空行略）；`示例` 以符号链接令 `示例/` 之目录为预置之树，行其中六示例程序（见 [示例](示例.文言.md)）；`WASI` 与 `WASI文件` 行 wasi-sdk 所编之 C 程序（命令行、标准流、计算、时钟与睡眠、陷阱、回声，及子任务中目录与文件之读写），核其出与退出码（见 [WASI示例](WASI示例.文言.md)）；`普通-网页汇编-*` 十二例径取自语言测试集 `测试/网页汇编`（后端语义之回归试，`名-1。豫` 与期望之出 `名。成功`，如深栈、递归回收、大数组、长打表、癸象转义等），验证器于期望之末补换行而逐字相较；加 `--全部覆盖 是` 则取 `测试/网页汇编` 中除十三例（八者自行 fork 子进程而需第三任务槽，五者用编译器库而逾四百四十八千字节之窗）外之全部二十八例，两架构皆通过。

## 界

- 无 SIMD；多内存、导入内存/表/全局、外部引用未作；表之容量于解析时依上限一次而分。
- WASI 唯作 preview1 之大半：无套接字与符号链接、`fd_renumber` 未作；文件依整个内容而缓（上限八兆字节），目录项之 `d_type` 恒为未知，子任务中之文件因走邮箱而甚缓；以陷阱而终者，未关闭之文件内容失之；一时至多开十六文件；程序之当前目录由 wasi-libc 自司（起于根目录）。
- 内存：每任务之线性内存至多五百一十二页（三十二兆字节），其中值栈、标签栈、帧栈等约六兆，余以供模块、GC 堆与文件之缓冲；内核之物理块池共六十四兆（三十二块，二任务共之）。GC 堆尽则报“堆内存不足”（退出码一百二十）——如一次物化八十万项之整数列（每节点约二三十字节）即尽。
- 不验模块，信编译器之产物；`ref.cast` 用超类链，不作跨递归组之结构等价。
- 实时钟唯秒之精、唯 UTC（见[墙钟之务](墙钟服务.文言.md)），文件无修改时；子进程一时唯一（内核唯两任务槽），子任务不得再起子进程；子任务之文件事经邮箱转于初始任务办之（见“子进程中之文件”），量大则甚缓；多实例唯传数值，见上节。
