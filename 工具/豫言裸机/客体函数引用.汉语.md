# 客体函数引用与表

后续进展：引用参数、返回值与局部变量已接入，见[客体引用传递](客体引用传递.汉语.md)。下文保留本阶段首次验收范围。

验证器现在逐个记录操作数的类型，区分 i32 与函数引用。执行器支持 `ref.null func`、`ref.is_null`、`ref.func`，以及默认函数引用表的取值、赋值、长度、增长和填充。此前实现的初始化、丢弃与复制继续适用。

整数不能作为函数引用写入表、填充表或初始化增长的表项；引用也不能冒充整数参与算术、条件、局部赋值和整数函数调用。`drop` 接受任意已支持的类型，未标注类型的 `select` 仍仅接受数值。不可达代码允许栈底处的多态取值，但其后实际压入的值仍须符合期望类型。

函数引用必须在函数体之外声明。当前从函数导出和元素段收集可引用的函数号；仅在函数体中调用某函数，不会自动声明其引用。空引用表示为执行器私有的负一，其他函数引用使用已核验的函数号。这种内部表示不暴露为模块可伪造的整数接口。

表的初始长度、声明最大长度和运行时当前长度分别保存。增长成功返回旧长度，并以指定引用初始化新增项；超过声明上限或固定的一千零二十四项容量时返回负一，保留旧表。零增长合法。取值、赋值、填充、复制、元素初始化和间接调用均以当前长度检查边界。填充预检整个区间，越界不留下部分写入。再次实例化恢复初始表长和内容。

类型标签位于 `[245760,262144)`，每个操作数一个字节，最多一万六千三百八十四项；该区间在解码分支表之后、运行时值栈之前。函数引用声明位图位于 `[29344,29472)`，当前表长存放于 29188。类型验证辅助函数保持原有调用签名，以内部参数的高十六位传递期望类型、低十六位传递数量；普通整数调用保持兼容。这是执行器内部协议，不改变模块 ABI。

新增四十七组用例，其中四十六组静态判断与标准 Wasm 引擎对照；外部引用类型另作当前不支持的拒绝用例。二十九组执行结果、陷阱和函数表内容与标准引擎一致。固定物理容量用例单独核验本实现增长失败，不要求标准引擎在相同长度处耗尽资源。

本阶段函数参数、返回值、局部变量、全局变量和块结果仍限既有 i32 形式；函数引用可在操作数栈及表中流转。尚未支持通用引用签名、引用局部变量、引用块结果、带类型的选择、多表、导入表和 WasmGC。完整引用类型必须进一步保留堆类型、子类型和空值性信息，不能仅靠当前两种标签推断已实现。

规范依据：[函数引用声明规则](https://github.com/WebAssembly/spec/discussions/1759)、[WebAssembly 核心规范](https://www.w3.org/TR/wasm-core/)。
