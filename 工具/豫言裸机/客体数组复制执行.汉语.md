# 客体数组复制执行

客体解释器现可执行标准 `array.copy`（二进制子指令 `0xFB 0x11`）的同类型可变 `i8`、`i32` 数组子集。解码器读取目标、来源两个类型索引；静态验型检查数组种类、元素类型与目标可变性，并按“目标引用、目标起点、来源引用、来源起点、长度”消费五个操作数。当前要求两侧类型索引相同；规范允许的其他存储类型相容情形仍待实现。

执行器先核对两个活对象与实际类型，再以无符号比较分别验证起点和剩余长度。任一侧越界时，在写入前陷阱；即使长度为零，空引用或越过末端的起点也不能绕过检查。客体堆目前用四字节槽存储每个 `i8` 或 `i32` 元素，已写入的 `i8` 值保持八位截断。完成双侧检查后使用具重叠安全语义的内存复制，所以同一数组左右移动结果与 [WebAssembly 规范](https://webassembly.github.io/spec/core/bikeshed/)一致。

`客体数组复制正.wasm` 与 `客体数组复制越界.wasm` 都是独立有效的标准模块。标准引擎中，正例返回 42，负例在复制长度越界时陷阱。双架构裸机用例不仅检查返回码，还读取解释器对象堆：正例复制后四个目标元素为 `1、2、3、4`；随后用同一数组直接检验向右重叠复制得到 `1、1、2、3`，向左重叠复制得到 `1、2、3、3`；负例须返回运行时陷阱码 `-4`。验收命令：

```sh
YY_GC_INITIAL_HEAP_SIZE_MB=1024 ./yy设备配置编译器 工具/豫言裸机/验证。豫 -o yy数组复制裸机验证
./yy数组复制裸机验证 --外部模块 yy外部C模块.wasm yy外部C错误.wasm
```
