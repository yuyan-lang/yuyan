# 收客而再用其槽

任务号含世次，低位辨槽，其余辨先后。首号零、一，次槽收后用三、五，旧号不得及新客。诸查询、等待、终止、回收皆先核号与槽之占用；调度仍以内部槽数行之。

“回收任务”仅许所属之主收已毕次客。正常毕、故障止、主动止皆可收，成返零；尚行、自收、越权、空槽、旧号及越界皆返负一。

先清两兆客域与五百一十二字节帧，复读全域并合其位，须尽为零；乃清计数、退出码、所待与所属，进号之世，末还其槽。其存仍在固定池，不称已还通用页分配器。核私映射虽留，空槽不可调度，外问亦拒。

号至二一四七四八三六四七，收后永久退此槽，后求创建返负一，毋回绕旧号。首客号零不复用。

试三生三收，正常毕与被止者皆验；新客存时，遍以旧号问、待、止、收，皆须拒而不伤新客。又置号于末世，验最后一次生收后不复生。错期值为反证，实测另载。

今两槽之池，非通用多进程分配；多等待者、别程序加载、文件通信资源之回收犹未备。总目标不改。

二〇二六年九月二十二日，两机一七二试皆过，新增三途收客再用、世次耗尽及错期值反例一二。旧例、外来 C 模块与类型复核俱成。产物藏 `/tmp/yy裸机验证.VkC3zp`，散列见验证记录之“任务回收扩展验证”。

后进已立核中信函，生收之际亦清之，详[任务通信](任务通信.文言.md)。文件句柄及通用端点诸资源之收犹待。
