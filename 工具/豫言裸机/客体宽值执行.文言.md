# 客体宽值执行

用户态执行器今可行规范 `i64.const`、`i64.eqz`，并可弃宽值。解码器全取有号六十四位立即数，分高下二字；静态验栈别记 `i64` 型。运行值栈仍四字一物理槽，宽整据邻二槽。弃值之宽由静态验者写于指令录，行时据之退栈。

高半字槽于 `[29696,31744)` 之位图立记；常值推栈先除复用槽旧记，自动根扫描略过所记高半字，不妄作对象柄。此图为执行器私藏，不迁客体 Wasm 内存与公用接口。低半字仍循今保守辨根之法。

三独立规范模块实核：二之三十二次方之高半字参与 `i64.eqz`，返四十二；宽零判零，返四十三；弃宽值二槽后以 `i32.add` 仍返四十二。Node 标准引擎与臂六十四、兼容六十四 QEMU 客体之果同；三模块原字皆在所生镜像中核之。裸机三百六十八项全过，产物及串口日志在 `/tmp/yy裸机验证.B3zirH`。

今增规范 `i64.add`：静态验栈取二宽整、还一宽整；运行时高下二字各加，以无号较辨下字进位，且记结果高字。独立规范模块核 `0x00000000ffffffff + 0xffffffff00000001 = 0`，继以 `i64.eqz` 返四十二。Node 与双架构 QEMU 客体同果；原字于两镜像各现一次。裸机三百六十八项皆过，产物及串口日志在 `/tmp/yy裸机验证.Gi9RLc`。

局部今可宣 `i64`，以规范 `local.get`、`local.set`、`local.tee` 读写。验者于各函数别记宽值局部位图；行者存下字于旧四字槽，高字于同帧末所增等长域。帧之取、清、还皆及二域，而控制帧与引用局部之址不迁。独立规范模块六十字节，核宽值写读、`tee` 复写、弃值、跨字进位与判零；Node 及双架构 QEMU 皆返四十二。两客体执行镜像各含原字一次，裸机三百六十八试皆过，产物存 `/tmp/yy裸机验证.22BwJB`。

宽值运算今仅备 `i64.eqz`、`i64.add`。`i64` 函数签名、全局、访存、结构字段及余算术比较令未备；常语完整模块犹不可行。
