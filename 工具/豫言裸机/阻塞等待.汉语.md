# 任务阻塞等待

平台导入 `等待任务：(i32) → i32` 等待指定任务结束并返回退出码。已结束目标立即返回；无效编号、等待自身，以及当前两任务相互等待返回 -1。退出码约定沿用[故障隔离](故障隔离.汉语.md)。重复等待已结束目标仍返回退出码，不会回收任务槽。

未结束但可运行的目标使调用者进入状态 18：保留曾运行位（2），设置等待位（16），清除可运行位（1）。内核记录等待目标，将系统调用帧保存到该任务的内核上下文缓冲，并调度另一任务。定时器不会把等待态任务选回运行。

目标正常或异常退出都进入共同的退出调度路径。如果另一任务等待的正是当前目标，内核把退出码写入等待者保存帧中的返回寄存器槽，状态改回 3，清除等待目标，随后恢复该帧和页表。等待者从原系统调用后继续，调用栈、操作数栈和其他整数寄存器保持原值。

ARM64 等待目标位于 `0x400b0060`、`0x400b0064`，返回码写入保存帧偏移 0。AMD64 等待目标位于 `0x103368`、`0x10336c`，返回码写入保存帧偏移 112。两端均写完整八字节寄存器槽。状态更新与调度在禁止中断的内核路径内完成。

## 验收

等待者只调用一次阻塞等待，不在用户态轮询退出码。目标任务先用有界轮询等到对方的等待态，再验证反向等待被拒；长循环结束后再次检查对方仍为等待态，随后正常退出或触发故障。

等待者把额外的数值留在操作数栈中再发起等待，醒来后组合返回码进行核验，检查终态、私有全局和长循环结果，并验证再次等待已结束目标、非法目标与等待自身。反向等待用例交换两个任务的位置。错误返回码期望必须失败。

这验证保存帧的返回值写入、阻塞任务不再参与抢占、正常和故障退出唤醒，以及重复等待的立即返回路径。实际通过记录另载。

## 边界

当前只支持两个静态任务，拒绝互相等待的规则不是通用的多任务死锁检测。没有父子关系、等待权限、任务句柄代际、超时、取消等待或等待后回收。动态创建、主动终止、物理页与任务槽回收仍待实现；不把本接口视为完整进程管理。
