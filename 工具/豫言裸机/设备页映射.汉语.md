# 设备页映射、写保护与撤销

在空授权表拒绝 DMA 的基础上，增加专用诊断设备的一页映射。设备地址为 `0x1000`，ARM64 映射到 `0x400c2000`，AMD64 映射到 `0x119000`。设备地址与物理地址不同，不能用物理地址直通冒充转换成功。所有表和同步控制仍由内核持有，尚未开放通用用户态映射调用。

ARM64 为流编号三十二建立阶段一上下文与四级页表，四千零九十六字节粒度。上下文位于 `0x400c3000`，四级表位于 `0x400c4000` 至 `0x400c7000`，只设置最低一级的索引一。检查四千零九十六字节粒度支持，设置有效、访问标志、权限及内存属性，清理 CPU 缓存后发布流表项。命令队列位于 `0x400c8000`，提交配置失效、翻译缓存失效与同步命令；确认队列消费位置及命令错误状态后才继续。该初始化只用于尚未提交设备请求的首个映射，不是可反复重置活跃队列的接口。

AMD64 检查四级地址宽度支持，为 PCI `00:04.0` 建立域一的上下文与四级页表。上下文页位于 `0x11a000`，四级表位于 `0x11b000` 至 `0x11e000`。完成其他条目后发布根表指针，再执行全局上下文与 IOTLB 失效，并检查完成状态和实际作用范围。当前没有在途 DMA，不能据此推导页回收时的排空与撤销已经实现。

三类诊断共享同一 EDU 四字节写请求：

| 用例 | 实际授权 | 必须发生的结果 |
| --- | --- | --- |
| 设备页写入 | 读写 | 指定物理页内容被设备写为零，相邻哨兵不变，没有 IOMMU 故障 |
| 设备页只读 | 只读 | 目标与相邻哨兵不变，出现匹配设备及地址的写权限故障 |
| 设备页权限误开 | 故意读写，但要求只读效果 | 明确观察到保护区被改写，测试失败 |
| 设备页撤销 | 首轮读写成功后清除叶项，并完成失效同步 | 第二次传输被拒绝，目标不变且出现对应故障 |
| 设备页撤销漏刷 | 首轮成功后清除叶项，故意省略失效同步 | 在当前 QEMU 缓存模型下观察到陈旧映射仍可写入，负对照失败 |

ARM64 只读用例要求权限故障事件 `F_PERMISSION`，不能接受无效上下文或无效页表故障充数；AMD64 要求写权限故障原因五。失败对照必须在设备传输结束后确认保护区变化。真实运行结果见验证记录。

撤销用例要求先取得首轮授权写入成功标记，并实际完成两次 DMA。ARM64 将叶项清零，处理 CPU 缓存后向既有命令队列追加翻译失效和同步命令，等待新的消费位置；第二次访问要求翻译故障，而不是初始配置错误。AMD64 清零叶项，检查排空能力并提交带读写排空请求的全局 IOTLB 失效，核对完成范围；第二次访问要求对应地址的拒写故障。漏刷负对照必须明确观测保护区被改写，不能把任意失败算作有效对照。

此阶段是固定设备、固定一页的内核映射机制和硬件验证。撤销只在前一请求完成、设备总线主控已关闭之后进行；尚未处理取消在途 DMA。通用页分配、设备能力授予、多设备地址空间、页复用和用户态块驱动仍未完成。磁盘持久化与完整操作系统目标保持不变。
