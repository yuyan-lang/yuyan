# 客体宽值执行

用户态执行器现支持标准 `i64.const`、`i64.eqz`，并能对宽值执行 `drop`。解码器将完整的有符号 64 位立即数拆成高、低两个 32 位字；静态验栈给它保留独立的 `i64` 类型标签。运行值栈仍以四字节为物理槽，一个 `i64` 占相邻两槽。`drop` 的操作数宽度由静态验证写入指令记录，运行时按宽度弹栈。

高半字槽在 `[29696,31744)` 位图中标记。普通推栈清除复用槽的标记；自动 GC 根扫描跳过标记的高半字，避免将它误作对象句柄。此位图是执行器私有数据，不改变客体 Wasm 内存或对外 ABI。低半字仍按现有保守根识别规则处理。

三个标准有效的独立模块分别验证 `2^32` 的高半字参与 `i64.eqz`（返回 42）、零宽值判零（返回 43），以及 `drop` 消耗两个物理槽后 `i32.add` 仍返回 42。Node 引擎结果与 ARM64、AMD64 QEMU 中的客体执行结果一致；三个模块的字节均已在生成镜像中核对。完整 368 项裸机回归通过，产物与串口日志在 `/tmp/yy裸机验证.B3zirH`。

这是宽值执行的最小闭环。`i64` 函数签名、局部变量、全局、内存读写、结构字段、其他算术与比较指令尚未实现，普通豫言完整模块仍不可运行。
