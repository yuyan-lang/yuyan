# 客体宽值执行

用户态执行器现支持标准 `i64.const`、`i64.eqz`，并能对宽值执行 `drop`。解码器将完整的有符号 64 位立即数拆成高、低两个 32 位字；静态验栈给它保留独立的 `i64` 类型标签。运行值栈仍以四字节为物理槽，一个 `i64` 占相邻两槽。`drop` 的操作数宽度由静态验证写入指令记录，运行时按宽度弹栈。

高半字槽在 `[29696,31744)` 位图中标记。普通推栈清除复用槽的标记；自动 GC 根扫描跳过标记的高半字，避免将它误作对象句柄。此位图是执行器私有数据，不改变客体 Wasm 内存或对外 ABI。低半字仍按现有保守根识别规则处理。

三个标准有效的独立模块分别验证 `2^32` 的高半字参与 `i64.eqz`（返回 42）、零宽值判零（返回 43），以及 `drop` 消耗两个物理槽后 `i32.add` 仍返回 42。Node 引擎结果与 ARM64、AMD64 QEMU 中的客体执行结果一致；三个模块的字节均已在生成镜像中核对。完整 368 项裸机回归通过，产物与串口日志在 `/tmp/yy裸机验证.B3zirH`。

执行器进一步支持标准 `i64.add`：静态验栈消耗两个 `i64` 并产生一个 `i64`；运行时分别相加高低 32 位，以无符号比较计算低半字进位，再标记结果的高半字。独立标准模块验证 `0x00000000ffffffff + 0xffffffff00000001 = 0`，经 `i64.eqz` 返回 42。Node 标准引擎和两种架构 QEMU 客体执行结果一致；模块原始字节在两种生成镜像中各出现一次。368 项裸机回归通过，产物与串口日志在 `/tmp/yy裸机验证.Gi9RLc`。

局部变量现可声明 `i64`，并通过标准 `local.get`、`local.set`、`local.tee` 读写。验证器为每个函数记录独立的宽值局部位图；执行器将低半字保留在原四字节局部槽，高半字放在同一调用帧末尾的等长附加区。帧分配、清零与释放覆盖两区，控制帧和引用局部槽地址不变。一个 60 字节独立标准模块测试宽值写入、读取、`tee` 写回、宽值 `drop`、跨半字进位及判零；Node 与双架构 QEMU 均返回 42。两种客体执行镜像各包含该模块原始字节一次，完整 368 项裸机回归通过，产物位于 `/tmp/yy裸机验证.22BwJB`。

定义函数之间现可传递单个 `i64` 返回值。静态验栈沿用函数类型表中的原始结果类型；调用帧把这个结果计为两个物理槽，返回时先保存高半字、再保存低半字，恢复调用者栈后按低、高顺序推回并标记高半字。59 字节独立标准模块让第二个函数返回 `2^32`，调用者与 `-2^32` 相加后判零，Node 与双架构 QEMU 均返回 42。另两份标准有效模块分别验证 `i64` 参数和返回 `i64` 的导入仍被索引器明确拒绝；对外运行入口遇到 `i64` 结果也明确返回 `-2`，避免把它截断成单字结果。四份模块原始字节在两种客体执行镜像中各出现一次；368 项裸机回归通过，产物在 `/tmp/yy裸机验证.PmeW0j`。

定义函数之间现可传递 `i64` 参数，并可与 `i32` 参数混用。索引器把各类型前十六个参数中的宽值位置记录在辅助类型表偏移 12 的位图；静态验栈在调用点读取被调用类型的位图，在函数体内读取本函数的宽值局部位图。解释器按参数宽度从运行值栈取出低、高半字，分别写入调用帧原局部槽及尾部高半字区；参数数量与物理槽数分别计算。外部函数导入或对外执行入口遇宽值参数返回 `-2`，不改变现有外部 ABI。80 字节独立标准模块用 `(i32,i64,i32)→i64` 调用检查混合顺序与高半字，Node 和双架构 QEMU 均返回 42；53 字节标准导入模块验证宽值导入拒绝，36 字节标准模块验证对外入口拒绝。三份原始模块字节在两种客体执行镜像中各出现一次，完整 368 项裸机回归通过，产物在 `/tmp/yy裸机验证.viYz7Y`。

目前支持的宽值运算仍限于 `i64.eqz` 和 `i64.add`。跨模块宽值导入导出及对外结果接口、全局、内存读写、结构字段、其他算术与比较指令尚未实现，普通豫言完整模块仍不可运行。
