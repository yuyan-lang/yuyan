# 用户态批量内存复制

裸机后端现支持单内存的标准 `memory.copy`。目标地址、源地址和长度按三十二位无符号值解释，以六十四位算术分别检查两个完整范围；检查通过后才读写内存。目标在源之前时从前向后复制，目标在源之后时从后向前复制，不分配临时缓冲区。这样保留重叠区域的原始源字节。

零长度操作仍检查两个起始地址，允许地址恰好等于内存长度。编译器先独立解析每个复制机器片的内部标记，再嵌入用户函数，故同一函数中的多条复制不会发生标记冲突。正常复制完全在用户态执行。

2026-09-22，ARM64 和 AMD64 的 52 项 QEMU 验证全部通过。各新增六项：正常复制、源越界、目标越界、长度回绕、零长度源越界和零长度目标越界。正常模块包含两个方向的重叠、跨页、原地和合法零长度复制。负例保留后续正常核验；若错误地忽略非法复制，就不能通过负例验收。

相同标准模块在 V8 中完成四次正常核验，五类负例均在第一次核验前触发陷阱。机器片反汇编核对了两次范围检查、复制方向、循环分支和字节寄存器；重复连接机器片及非法参数测试通过，验证入口类型检查通过。

```sh
./yy3_bs 工具/豫言裸机/验证。豫 -o yy裸机验证 -j 1
./yy裸机验证
./yy3_bs 库/编译器核心/裸机后端/内存编码。测试。豫 -o yy访存编码测试 -j 1
./yy访存编码测试
```

本轮产物在 `/tmp/yy裸机验证.Pg853a`，完整散列、串口日志和退出码见 `验证记录.json` 的“批量复制扩展验证”。标准语义依据[Wasm 内存复制规范](https://webassembly.github.io/spec/core/exec/instructions.html#exec-memory-copy)。

当前仍限固定大小的单个自有内存。裸机数据段初始化指令、数据丢弃、动态页分配、调度、文件系统、默认用户态 Shell 和完整 WasmGC 尚未完成；故障仍结束整个测试客体。主动数据段的镜像初置已支持，与运行时 `memory.init` 是不同功能。

同一生成器的原生与 WasmGC 宿主运行结果逐字节一致，且均与 QEMU 受测镜像一致。此项不表示客体已具有 WasmGC 执行器。
