# 双架构裸机验收记录

日期：2026-09-22。宿主：macOS ARM64。QEMU：11.1.1，使用软件模拟，单处理器。范围为整数 Wasm 提前编译、平台启动、真实用户态及内核页隔离；不是完整操作系统验收。

## 十二项检查

| 检查 | ARM64 | AMD64 |
|---|---|---|
| 正常计算 | 通过，退出零 | 通过，退出三十三 |
| 内核页隔离 | 通过，退出零 | 通过，退出三十三 |
| 错误结果负对照 | 正确拒绝，退出一 | 正确拒绝，退出三十五 |
| 放开页权限负对照 | 正确拒绝，退出一 | 正确拒绝，退出三十五 |
| 操作数栈越界 | 正确拒绝，退出一 | 正确拒绝，退出三十五 |
| 调用栈越界 | 正确拒绝，退出一 | 正确拒绝，退出三十五 |

退出码三十三／三十五是兼容平台模拟退出设备的编码。所有检查同时核对串口消息；负对照若出现成功标记，验证器也会失败。完整串口内容、每项输入模块与镜像散列保存在同目录「验证记录.json」。执行「yy裸机验证」即可重新生成镜像并重复检查，不需保存本次临时目录。

正常输出来自客体串口：

```text
豫言核心启动
用户程序已运行
用户态计算验证通过
```

隔离试验在用户态读取内核私有内存。ARM64 检查来自低异常层的数据权限错误与故障地址；AMD64 检查第三特权环、用户缺页标记与故障地址。只有满足预期故障，并已完成四次计算核验，才报告隔离通过。

放开权限的负对照只修改受测页表条目。ARM64 使用独立内核数据页进行探测，避免修改内核代码页的用户权限同时改变特权执行权限，使负对照在进入用户态前就失效。

同一个输入模块也在 V8 标准引擎完成四次核验和相同的用户输出，未使用私有 Wasm 指令。重复调用验证局部清零，样例覆盖当前整数核心的全部指令。

## 生成链检查

1. 原生豫言生成器直接输出两种架构镜像。
2. 同一生成器源码经既有 WasmGC 后端编译，以现有 Wasmtime 宿主运行。
3. 两种路径产生的正常镜像逐字节相同，且与通过十二项检查的正常镜像相同。
4. 禁用工具搜索路径运行原生生成器，仍产生相同镜像。正常生成代码没有外部编译、汇编或链接步骤。
