# 客体执行器二号（普通豫言 WasmGC）

## 为什么需要

一号执行器（手写扁平指令列，约 727 KB 源码）只能执行整数子集，模块窗口 128 KiB、128 个函数、四字节值槽，无法承载普通豫言编译出的 WasmGC 模块：带标准库打印的最小模块有 800 个函数、1357 个全局、522 个被动数据段、38 个类型，用到 i64、引用、结构体与数组、具体类型转换、异常和尾调用。二号执行器用[低阶语言](低阶语言.汉语.md)重写，约 2600 行源码，源文件在 `工具/豫言裸机/客体二号/`，编译成 `网页状态模块` 后经既有的寄存器降级进入 ARM64／AMD64 用户镜像，在用户态运行。

## 值与对象

- **值槽**：操作数、局部和全局都是 8 字节槽 `[低字, 高字]`；i32、引用只用低字（高字不关心），i64、f64 占满。
- **引用字**：0 = 空；奇数 = i31（`(值<<1)|1`）；低三位为 010 = 函数引用（`(函数号<<3)|2`）；8 字节对齐的堆地址 = 对象。
- **堆对象**：头 8 字节 `[类型号|种类<<24|标记位, 总字节数]`。结构体 = 头 + 每字段 8 字节槽（压缩字段存于低字）；数组 = 头 + `[长度][填充]` + 元素（按元素宽度 1/2/4/8 字节）；异常对象（种类 4）保存标签与载荷。
- **类型表**：每类型 32 字节，记录种类、参数／字段／元素信息、超类型；字段类别 0 = 四字节数值、1 = 八字节数值、2 = 引用、3 = i8、4 = i16。类型关系用超类型链判定，函数类型按参数与结果编码逐字节比较。

## 执行

- **直接解释字节码**：每个函数第一次调用时扫描函数体，建立每个字节偏移 8 字节的边表（块起点 → end 之后的位置、if → else 之后的位置），此后 `block/loop/if/br` 由运行期**标签栈**（每项 `[目标, 栈基, 元数, 种类]`）处理，`try_table` 标签同时管理**处理器栈**。
- **显式调用帧**：帧栈项 `[返回地址, 调用者 fp, 调用者函数, 标签栈顶, 处理器栈顶]`，尾调用（`return_call`、`return_call_indirect`、`return_call_ref`）复用当前帧；函数返回时恢复标签栈与处理器栈。
- 值栈、标签栈、帧栈、处理器栈、标记栈、边表池、堆都在线性内存中，大小由常量决定；首次超过八页由寄存器降级的增长助手迁入内核动态块。
- 陷阱直接打印原因并以专属退出码（120–137）退出任务。

## 垃圾回收

非移动标记清扫：分配先取自由链表（小块按 8 字节分类，大块首次适应并分割），再从堆顶划出，不够时先回收再向内存申请。对象起始位图（每 8 字节 1 位）用于判定候选指针；根为值栈（保守，两字都扫）、全局、表和异常载荷；堆内对象按类型精确扫描字段。每次回收后回收阈值设为存活字节与 2 MiB 的较大者。宿主原语执行期间禁止回收，避免多次分配之间的中间对象丢失。

## 宿主原语

`yuyan:gc-host/v1.call(名字节数组, 参数元组)` 按名字分派：打印行、打印字符串、标准错误打印行、打印通用值、退出进程、命令行程序名／参数、工作目录、环境变量（空）、平台判断、读标准输入行（空）、字节转字符串、字节串的空／长度／取字节／从字符串／单字节／拼接、整数加／乘／除、整数转字符串、字符串转整数。整数按运行时约定装箱（i31 或 `$big`），对象类型号取自模块导出的 `yy_bytes`、`yy_tuple`、`yy_big`、`yy_float` 原型。**尚未实现**：小数运算（需要浮点）、文件与进程原语。

## 构建、调试与验收

```text
yy低阶编译 执行器.wasm 基础.低阶 跟踪关.低阶 模块.低阶 执行.低阶 解释.低阶 异常.低阶 堆.低阶 对象.低阶 主机名.低阶 主机.低阶 入口.低阶 嵌入 0x10000 客体.wasm 嵌长 0x408 客体.wasm
yy裸机入口 臂六十四 执行器.wasm 输出.镜像 运行
```

客体模块放在线性内存 0x10000 起（至多 448 KiB），长度写在 0x408；`入口` 默认调用导出 `_start`，测试时可在 0x2400 放导出名、0x2440 放参数个数、0x2444 起放 i32 参数。同一份执行器 wasm 也能在 Node 中调试：宿主提供 `平台` 模块的 `写字节`、`退出任务`，把客体写入内存后调用 `启动`；换用 `跟踪开.低阶` 构建可开启逐指令跟踪（写 0x858）、指定回收阈值（写 0x87C）和监视某个对象地址（写 0x85C）。

验收：`yy普通豫言验证` 编译 `普通探针/` 下每个 `.豫` 源程序（`./yy豫构 … --target=wasmgc`），把模块嵌入执行器，生成 ARM64 与 AMD64 镜像并在 QEMU 中运行，要求串口输出恰为“豫言核心启动”、与 `.期望`（宿主 Node 运行同一模块的输出）逐字相同的程序输出、“用户任务全部退出”。五个程序（打印、递归列表、代数闭包、字符串异常、回收压力）在两架构共十项全部通过。

## 限制

- 只有 f64 常量的搬运，**没有浮点运算**（遇到即陷阱）；没有 SIMD；多内存、导入内存／表／全局、外部引用未实现。
- 不做模块验证，信任编译器产物；`ref.cast` 用超类型链，不做跨递归组的结构等价。
- 客体模块须随镜像嵌入（尚未接入 Shell 的磁盘加载），文件、进程、时间等宿主原语待接入。
