# 客体执行器二号（普通豫言 WasmGC）

## 为什么需要

一号执行器（手写扁平指令列，约 727 KB 源码）只能执行整数子集，模块窗口 128 KiB、128 个函数、四字节值槽，无法承载普通豫言编译出的 WasmGC 模块：带标准库打印的最小模块有 800 个函数、1357 个全局、522 个被动数据段、38 个类型，用到 i64、引用、结构体与数组、具体类型转换、异常和尾调用。二号执行器用**底层模式**的普通豫言写成（见 `文档/底层模式.汉语.md`；它取代了早先自造的括号式低阶语言），约 4500 行，源码在 `工具/豫言裸机/客体二号/`，是一个声明了 `「编译模式」者『底层』也。` 的包，只依赖 `底层库`。编译成 Wasm 模块后读成 `网页状态模块`，经既有的寄存器降级进入 ARM64／AMD64 用户镜像，在用户态运行。

## 值与对象

- **值槽**：操作数、局部和全局都是 8 字节槽 `[低字, 高字]`；i32、引用只用低字（高字不关心），i64、f64 占满。
- **引用字**：0 = 空；奇数 = i31（`(值<<1)|1`）；低三位为 010 = 函数引用（`(函数号<<3)|2`）；8 字节对齐的堆地址 = 对象。
- **堆对象**：头 8 字节 `[类型号|种类<<24|标记位, 总字节数]`。结构体 = 头 + 每字段 8 字节槽（压缩字段存于低字）；数组 = 头 + `[长度][填充]` + 元素（按元素宽度 1/2/4/8 字节）；异常对象（种类 4）保存标签与载荷。
- **类型表**：每类型 32 字节，记录种类、参数／字段／元素信息、超类型；字段类别 0 = 四字节数值、1 = 八字节数值、2 = 引用、3 = i8、4 = i16。类型关系用超类型链判定，函数类型按参数与结果编码逐字节比较。

## 执行

- **直接解释字节码**：每个函数第一次调用时扫描函数体，建立每个字节偏移 8 字节的边表（块起点 → end 之后的位置、if → else 之后的位置），此后 `block/loop/if/br` 由运行期**标签栈**（每项 `[目标, 栈基, 元数, 种类]`）处理，`try_table` 标签同时管理**处理器栈**。
- **寄存器作循环参数**：主循环 `解释循环(指令针, 帧针, 边基, 栈针)` 是一个自尾递归的函数，编译成回跳；简单指令直接续行，控制转移类指令（throw、end、br 系、return、调用系、GC 前缀）经状态格 `新指令针／新帧针／边偏` 交回新现场，`新指令针` 为 0 表示最外层函数已返回。
- **显式调用帧**：帧栈项 `[返回地址, 调用者 fp, 调用者函数, 标签栈顶, 处理器栈顶]`，尾调用（`return_call`、`return_call_indirect`、`return_call_ref`）复用当前帧；函数返回时恢复标签栈与处理器栈。
- 值栈、标签栈、帧栈、处理器栈、标记栈、边表池、堆都在线性内存中，大小由常量决定（值栈 512 Ki 槽共 4 MiB，标签栈 64 Ki 项共 1 MiB，帧栈 32 Ki 项共 1 MiB，够几千层深的递归；再深会报“栈溢出：递归过深”，退出码 122）；首次超过八页由寄存器降级的增长助手迁入内核动态块。
- 陷阱直接打印原因并以专属退出码（120–137）退出任务。

## 垃圾回收

非移动标记清扫：分配先取自由链表（小块按 8 字节分类，大块首次适应并分割），再从堆顶划出，不够时先回收再向内存申请。对象起始位图（每 8 字节 1 位）用于判定候选指针；根为值栈（保守，两字都扫）、全局、表和异常载荷；堆内对象按类型精确扫描字段。每次回收后回收阈值设为存活字节与 2 MiB 的较大者。宿主原语执行期间禁止回收，避免多次分配之间的中间对象丢失。

## 宿主原语

`yuyan:gc-host/v1.call(名字节数组, 参数元组)` 按名字分派：打印行、打印字符串、标准错误打印行、打印通用值、退出进程、命令行程序名／参数、工作目录、环境变量（空）、平台判断、读标准输入行、字节转字符串、字节串的空／长度／取字节／从字符串／单字节／拼接、整数加／乘／除、整数转字符串、字符串转整数，以及文件系统与目录原语（读写删、建目录、列目录、路径判断、切换目录、格式化与挂载）。整数按运行时约定装箱（i31 或 `$big`），对象类型号取自模块导出的 `yy_bytes`、`yy_tuple`、`yy_big`、`yy_float` 原型。同步子进程原语见下节。**尚未实现**：小数精确表示；小数运算见“软浮点”一节，子进程见“子进程”一节。

## 子进程（复制任务、换成磁盘上的程序、重启）

宿主原语 `豫言_同步运行子进程并继承标准流`、`…并传递输出`、`豫言_同步运行子进程`（标准库 `子进程` 的 `运行并继承标准流`、`运行并传递输出`、`运行`）由模块 `主机任务` 实现，程序取自持久文件系统：

1. **父任务**把路径规范成绝对路径，确认是普通文件且长度合适（8 字节到 4 MiB），把程序字节读进堆里的字节数组，把命令行参数与程序名写进“送子任务之区”（`送参数区` 0xE000、`送程序名区` 0xF000），然后调用内核服务 `复制任务`。
2. **子任务**（`复制任务` 返回 0）带着父任务的整份内存醒来：把程序字节拷进模块窗口，把送来的参数与程序名拷成自己的 `参数区`（0xC000）与 `程序名区`（0xD000），把新程序长度写进状态格 `状态_待重启`（0x970）。此后调用链原路返回；`调用`／`尾调用` 见待重启就把新指令针置零，解释循环把它当作最外层函数已返回而退出。
3. 入口的**启动循环**在 `启动一次` 返回后检查待重启：非零则做 `重启准备`，再从头启动，这回读到的就是新程序。`重启准备` 先把动态区（`区域起` 到内存末）**清零**——各区与标记位图都假定拿到的是全零内存，而复制来的内存里是父任务的旧数据（例如旧的“数据段已弃”标志会让新程序的字符串常量全部越界）；再清空状态格区、写回模块长度、把块设备标为失败（设备只属于初始任务，子任务没有文件系统）、清掉测试导出名与参数、撤下待重启。子任务不打印函数结果；程序正常返回则以 0 退出任务，调用退出进程则以其码退出。
   - **大程序**：程序字节超过模块窗口（448 KiB，即 `0x10000`–`0x7FFFF`）时，子任务不把它拷进窗口，而是在动态区尾 `取区域` 一块（`暂存大程序`）、拷过去并把地址记入 `状态_暂存址`（0xE40）；`重启准备` 见 `状态_暂存址` 非零就把程序整体搬到 `区域起`（memmove，可能与来源重叠），其后直到内存末全部清零，并置 `状态_主程序大`（0xE44）；重启后的 `解析模块` 据此把 `状态_模块址` 设为 `区域起`、`状态_区域顶` 设在模块之后，于是主程序居动态区之首，模块字节和值栈、堆等都在动态内存里。这样磁盘上至多 4 MiB 的程序都能运行（编译器库、JSON 库之类会让 wasmgc 产物到 700 KB–1 MB）；嵌入镜像的初始主程序仍受窗口限制。验收 `壳/测试/大程序`：三个 0.7–0.93 MB 的程序（`去柯里化边界`、`整数专门化`、`私有入口`，取自 `测试/网页汇编`）由壳 `运行`，输出与这些测试的 `.成功` 期望一致。
4. **父任务**恢复自己的 `状态_是子任务`，`等待任务` 阻塞到子任务退出，`回收任务` 释放任务槽，把退出码作为原语结果（`运行` 则返回“退出码是否为零”）。准备阶段任何一步失败、没有空闲任务槽，都返回 127（与标准库“启动失败为一百二十七”一致）。“丢弃输出”（`运行`）把子任务的 `状态_是子任务` 置为 2，此后 `写字节` 什么也不写。

`获取命令行参数` 与 `获取命令行程序名` 读的是本任务的 `参数区` 与 `程序名区`（初始任务为空参数与 `/程序.wasm`）。内核只有两个任务槽，所以一次只能有一个子进程，子任务里再运行子进程会得到 127。**输出捕获与异步子进程**：`豫言_同步运行子进程并获取输出`（46）把子任务的“输出模式”置为 3，子任务的每个 `写字节` 先攒到最多三个字节（满三个、遇换行或改变流时）打成一条消息 `0x40+16×流位+字节数` 加低三字节，经内核邮箱发给初始任务（句柄 0）后阻塞等待父任务的确认；父任务在 等待消息 里循环收取、按流位追加到两个可倍增的缓冲、回复确认，等待返回空（子任务已退出）后 等待任务、回收任务，返回（退出码是否为零，标准输出，标准错误）；子任务每次退出前（退出任务、致命退出、启动结束）先冲刷。异步子进程（67 启动、68 尝试收取、69 输入输出多路等待）用同一套：启动后立即返回句柄 1，尝试收取 非阻塞地排空邮箱并看任务状态位，多路等待对每个关注项报告“就绪”使异步框架回来轮询（子任务必须靠父任务持续轮询确认才能跑完）。

### 子进程里的文件：远程文件调用

块设备只属于初始任务（子任务的 `块态` 是 2，没有设备窗口），所以子任务里 `28`–`36`、`38`、`39` 号文件原语（读写删文件、列目录、路径查询、切换目录、建目录）不在本地做，而由**初始任务代办**（`远程文件` 模块）：

- **协议**：子任务把“原语号 + 参数元组”序列化成字节流（种类字节 + 载荷：0 空引用、1 小整数、2 大整数、3 字节数组、4 元组，至多三层嵌套），经内核邮箱（一次一条 32 位整数）送给初始任务。流的传输是先一条“头”（高字节是流标 `0x60` 请求／`0x70` 应答，低 24 位是总长），再每条带 1–3 个字节（高字节 = 流标 + 字节数）；收方每收一条就回一条确认（值 1），所以两边都是阻塞式往返。
- **父任务一侧**：等待子任务的循环（`接收捕获`，现在所有输出模式都走它）与异步轮询（`排空捕获`）在 `处理捕获消息` 里认出流标 `0x60`，交给 `服务远程调用`：确认头、收齐请求、反序列化出参数、调用同一个 `宿主文件调用`（所以文件系统的状态只有一份，一致），再把“文件系统错误码 + 结果对象”序列化成应答流发回。
- **子任务一侧**：`文件原语分派`（`主机` 把 28 号及以后的原语转到这里）见到 `状态_是子任务` 非零且是可远程的号，就走 `远程文件调用`：相对路径先按子任务自己的当前目录（父任务复制任务之前写进 `送程序名区` + 2048，子任务改装拷到 `程序名区`，重启后 `继承当前目录` 恢复，所以子进程继承壳的当前目录）规范成绝对路径再送；`38` 切换目录用 `34`（存在）、`35`（是目录）两次查询确认后只改自己的当前目录；`37`、`40`–`42` 仍按本地处理。通讯失败时写错误码 `错_未挂载` 并返回形状合适的空结果。
- **成本与边界**：每条消息只带三个字节，200 KB 文件读、写、读回共 600 KB 约几秒（QEMU TCG）；适合命令行程序的小文件，不适合搬运兆字节级的数据。子任务不能再起子进程（没有第三个任务槽），所以没有“孙进程”。
- **邮箱满与重试**：内核邮箱只有一条容量，请求与应答又是“发一条、等确认”的乒乓，所以对端刚被唤醒去取确认、还没被调度时，本任务紧接着发出的下一条（连续的远程调用就是如此）会因“邮箱满”得到 -1。`发送消息` 因此在失败时重试（至多二十万次，每次都进内核，时钟中断让对端运行），试尽仍败的目标记进 `状态_发送失联`、此后立刻失败。这个缺陷是文件层在子任务里连发几十次调用时才暴露的（大约每十几次运行撞上一次），修复后连续 30 次运行无一失败。
- **验收**：壳测试 `子进程文件`：子程序 `文件工` 在子任务里读预置文件、写新文件再读回、路径存在／是文件夹／是普通文件、列目录、删文件、写读 6000 字节的较大文件，输出与期望一致，返回壳之后壳自己 `读`／`列` 也看得到子程序写的文件（文件系统状态只在初始任务里）。

### 标准输入重定向、环境变量与顺序管道

子任务的标准输入原来只能是控制台，也拿不到环境变量。这一节补上三样东西，全部靠“父任务在复制任务之前把信息写进 `送程序名区`，子任务改装时拷进自己的 `程序名区`”这一条老路（同当前目录的继承），不需要新的内核服务：

- **两个新的宿主原语**（`主机名` 的 70、71 号，普通豫言程序用 `《《C调用》》名『豫言_设置子进程输入』` 之类声明，壳里就是这样用的）：`设置子进程输入(路径)` 把下一个子进程的标准输入重定向到该文件（路径先规范成绝对路径，空串表示清除），`设置子进程环境(块)` 给下一个子进程一份环境变量块（“名=值” 以换行相隔的字符串，空串表示清除，总长至多 1020 字节，过长则清空并返回 -1）。两者都写进 `送程序名区` 的固定偏移（输入路径在 2560，长度 4 字节 + 路径字节；环境块在 3072，总长 4 字节 + 以零结尾的字符串们），`加载并复制` 在父任务一侧复制之后把它们清零，所以只对紧接着的那个子进程有效。
- **子任务里的标准输入**：重启之后 `加载输入文件`（在 `挂载磁盘` 之后）读 `程序名区` 里的路径，用 `文件原语分派`（29，子任务经邮箱远程读）把整个文件读进堆里的字节数组，存进 `状态_输入缓冲`（回收时作根，`标记输入缓冲` 标记它），`状态_输入位` 置 0；读失败当作空文件。`读字节`（平台层）看到 `状态_输入缓冲` 非零就从这份内容里取，取尽返回 -2（“文件结束”，-1 仍表示控制台暂时没有输入）。上层三个读者都据此改了：`读行核` 在文件模式下不回显、忽略回车、读到结束时若已有字符就先交出它们、没有字符返回 -1；`输入行对象`（原语 15，标准库的 `尝试读取标准输入行`）遇到文件结束返回 (0, 空)，也就是标准库文档说的“输入结束返回阴与空串”。
- **环境变量**：`程序名区` 里的环境块由两处读出。`获取环境变量`（原语 9，标准库的 `环境变量` 模块）按名字（第 0 个参数）查找，返回二元组（是否找到、值）。
- **壳一侧**（`壳/壳。豫`）：`设 名 值`、`取消 名`、`环境` 三个命令维护环境变量，存在文件 `/.环境` 里（每行 `名=值`，所以重启后仍在）；每次 `运行` 之前把全部条目交给 `设置子进程环境`。`运行 路径 参数… < 文件` 先检查输入文件存在，再用 `设置子进程输入` 告诉执行器（可以和 `>`、`>>` 同用，脚本里也可用）。`运行 甲 … | 乙 … | 丙 …` 是**顺序管道**：按 `|` 切段，前一段用“获取输出”取回标准输出（标准错误仍显示），写进临时文件 `/.管道甲` 与 `/.管道乙`（交替使用），作为后一段的标准输入，最后一段照常处理（可加 `>`），结束后删去临时文件。各段是一个接一个运行的，不是同时运行（内核只有两个任务槽），所以前一段必须能自己结束。
- **验收**：壳测试 `管道` 在两个架构的 QEMU 里验证 `设`、`取消`、`环境`、`日期 > 文件`、`< 文件` 重定向（含不存在的输入文件报错）、两段管道 `斐波那契 6 | 行数` 与 `统计 文件 | 行数`、三段管道 `斐波那契 4 | 行数 | 行数`、末段 `> 文件` 再 `读`；壳测试 `示例` 里普通豫言程序 `行数`（用 `尝试读取标准输入行` 读到结束，末行没有换行也算一行）与 `环境变量`（用 `获取环境变量`）验证标准库这一侧。


## 小数：软浮点

标准库的小数运算都是宿主原语（`豫言_小数加`／`减`／`乘`／`除`、`小数转字符串`、`字符串转小数`、`小数转整数`、`整数转小数`，编号 49–57），小数在宿主里是 `yy_float` 结构（头 + 一个 8 字节槽）。内核的降级后端没有浮点指令，执行器用**软浮点**（`软浮点` 模块，整数指令实现 IEEE 754 binary64，就近舍入到偶）：

- **加减乘除**：解包成“符号、指数、首位在第 62 位的 64 位尾数”，对阶、加减或 128 位乘积／64 次逐位试商，再由统一的打包函数归一、舍入、处理次正规数与上溢；非数、无穷、零的各种组合都按 IEEE 754 处理。
- **整数与小数互转**：整数（64 位有符号）转小数就近舍入；小数转整数向零截断，非数为 0，超范围饱和到极值。
- **小数转字符串**：定点六位，与 JS 的 `toFixed(6)` 完全一致（平局取绝对值大者）：用大整数精确算 ⌊值×10^6+½⌋；不小于 10^21 的值仍写出全部数字（JS 会改用指数记法）。
- **字符串转小数**：跳过前导空白，可选符号、整数与小数位、`e`/`E` 指数，`inf`/`nan`；无可转换内容得 0。全部有效数字累积成大整数，D×10^E 用大整数精确舍入（≤19 位数字且 |E| ≤ 22 走一次乘除的快路径），和 `Number()` 逐位一致。
- 尚未实现：`小数精确表示`（最短往返表示）。Wasm 的 f32/f64 指令见下一节。
- **验证**：Node 脚本 `客体二号/软浮点对照.cjs` 直接调用执行器导出的 `浮点运算`，随机对照 V8 的双精度（`node 工具/豫言裸机/客体二号/软浮点对照.cjs x.wasm 轮数 种子`）——加减乘除、整数转浮点、浮点转整数、定点串、字符串转小数各数百万次零差异（含次正规数、无穷、非数、平局、四十七个已知的舍入难例）；验收 `普通探针/小数。豫`（各运算与转换）与 `小数压力。豫`（600 轮混合运算累加，任何一次舍入错误都会改变结果），参照输出取自 Node 宿主的硬件双精度，双架构 QEMU 逐字相同。
- **时间与杂项原语**（58–66）：`获取当前纳秒时间`（内核时钟滴答，每滴答 10 ms 换算）、`获取当前本地日期时间字符串`／`格式化当前本地日期时间`（读内核的墙钟服务，即硬件实时钟，见[墙钟服务](墙钟服务.汉语.md)；结果是 UTC 时间，格式 `YYYY-MM-DD hh:mm:ss`，`格式化` 支持 `%Y %m %d %H %M %S` 与 `%%`）、`路径可执行`（即普通文件）、`查找可执行程序`（在 `/bin` 与 `/程序` 下找）、`路径为符号链接`（恒假）、`取得真实路径`、`在线处理器数量`（恒 1）、`字符串按字节在前`。

## Wasm 浮点指令

普通豫言编译器不产生浮点指令（小数走宿主原语），但别的编译器产出的模块（C、Rust 等）会用到 f32／f64，所以执行器把 Wasm 1.0 的全部浮点指令与 `0xFC` 前缀的饱和截断都实现了（`浮点指令` 模块，共 66 条，复用软浮点）：

- **比较**（f32 `0x5B`–`0x60`、f64 `0x61`–`0x66`）：eq、ne、lt、gt、le、ge，直接比较位型；有非数则只有 ne 为真，`+0` 等于 `-0`。
- **算术**（f32 `0x8B`–`0x98`、f64 `0x99`–`0xA6`）：abs、neg、copysign 只改符号位（非数载荷原样保留）；add、sub、mul、div 用软浮点的解包、对阶、乘积／逐位试商与统一打包；min、max（非数得非数，两个零异号时取小得 `-0`、取大得 `+0`）；ceil、floor、trunc、nearest（就近取偶）在尾数上按 (62 − 指数) 位的掩码取整，必要时加一个单位再打包，结果必可精确表示；sqrt 把被开方数（尾数，指数为奇则左移一位）乘 2^62 成 128 位数，用逐位试根求整数平方根，根的平方不等于被开方数就置粘位，指数取一半。
- **转换**：i32／i64 转 f32／f64（有符号与无符号，一次舍入，i64 转 f32 没有双重舍入）；`f32.demote_f64`、`f64.promote_f32`（按源格式解包、按目标格式打包，非数得安静非数、无穷与零保号）；截断转整数 `i32／i64.trunc_f32／f64_s／u`（非数陷阱“无效的整数转换”、超范围陷阱“整数溢出”，都是退出码 125，先取整数部分再判范围，所以 `-0.9` 转无符号得 0）；`0xFC 0–7` 饱和截断（非数得 0，越界取极值）。
- **单精度**：值槽的低字放 f32 位型。运算前把状态格 `浮格_格式`（0xE30）置 1，软浮点的解包、打包、特殊值写入都据此改用 binary32（23 位小数放在尾数第 39 位起，保护位 39 个，指数偏置 127），因此 f32 的加减乘除、开方、取整、整数转换都直接以 24 位精度一次舍入，不经过 f64；运算完必须置回 0（宿主原语的小数运算永远是 binary64）。
- **非数**：算术与转换产生的非数一律是安静非数（f64 `0x7FF8000000000000`、f32 `0x7FC00000`）；规范允许的载荷差异不做要求，abs／neg／copysign 按位操作故载荷保留。
- **验证**：Node 脚本 `客体二号/浮点指令对照.cjs` 调用执行器导出的 `浮点运算`（运算号 256 加 Wasm 操作码，或 512 加饱和截断子操作码，以合成的值栈直接调 `执行浮点`／`浮饱和截断`），对每条指令分别造一个只含它的小模块在 V8 里运行，随机加边界输入（非数、无穷、±0、次正规数、整数与小数的边界、平局、2^31／2^32／2^63／2^64 上下的值）逐位比较，含陷阱是否一致：66 条指令三个种子各 100 万轮（共约 2 亿次）零差异（`node 工具/豫言裸机/客体二号/浮点指令对照.cjs x.wasm 轮数 种子`）。端到端验收 `普通探针/盘/浮点-一。豫`：由 `客体二号/造浮点模块.cjs` 生成客模块 `浮点.wasm`（66 个导出 `op0…`，各遍历 1024 项输入表，把结果位累积成校验和；会陷阱的截断先把输入夹进范围内），期望校验和来自 V8 运行同一模块；普通豫言驱动程序动态加载它并逐个调用，ARM64 与 AMD64 QEMU 上都逐位相同，也就是编译成机器码的执行器的软浮点与 V8 一致。

## 表与元素段指令

除 `table.get`／`table.set`／`table.size`（解释器内）外，`表指令` 模块实现了 `0xFC` 前缀的 `table.init`（12）、`elem.drop`（13）、`table.copy`（14）、`table.grow`（15）、`table.fill`（17）：

- 表的存储在解析时按“上限”一次分配（声明了最大值就用它，否则最小加 1024），`table.grow` 只在这个容量之内增长，超出返回 -1；新增的项填成给定的引用（空引用是 0，函数引用是 `函数号 << 3 | 2`）。
- 范围一律按无符号数检查并防加法溢出，越界以退出码 124 陷入；`table.copy` 支持表内与表间的重叠复制；已弃的元素段与声明式元素段（标志 3、7）的可用长为 0，所以 `table.init` 只允许零长度；`elem.drop` 重复执行合法。
- 元素段里的常量式元素（标志 4–7）在运行期由 `求值常量式于` 在当前栈针之上的空闲区求值（实例化时仍用值栈基）。
- **验证**：Node 脚本 `客体二号/表指令对照.cjs` 随机生成小模块（两张 funcref 表、五种元素段、3–9 条随机表指令，参数偶尔越界），同一模块先在 V8 里运行再放进执行器，比较返回值或陷阱：三个种子各 2000 个场景（约四千个有返回值、两千个陷阱）零差异；端到端验收 `普通探针/盘/表-一。豫` 在两个架构的 QEMU 里加载 12 个由 `表指令对照.cjs --造探针` 生成的模块（各 14–21 条表指令），返回值与 V8 逐个相同。

## 多实例：动态装载模块与跨模块导入导出

执行器能在运行中装载更多 Wasm 模块，并让它们互相调用。初始模块（普通豫言程序）是实例 0，其余是**实例**；每个实例有独立的类型表、函数表、全局、表、元素段、数据段、标签、线性内存与导出表（“默认独立内存”），实例之间只交换数值，不共享 GC 引用。

**宿主原语**（`yuyan:gc-host/v1.call` 的扩展，编号 47、48；普通豫言用 `《《C调用》》名『…』` 声明，见 `普通探针/盘/动态-一。豫`）：

- `豫言_加载模块(路径, 名字)`：从持久文件系统读出模块，建成新实例并返回实例号（≥ 1）。失败返回 -1 路径无效、-2 不存在、-3 不是文件、-4 长度不合（8 字节到 4 MiB）或实例已满（含初始实例至多 16 个）、-5 读文件失败。名字是其他模块 `导入` 它时写的“模块名”。
- `豫言_调用导出(实例, 导出名, 实参…)`：调用某实例导出的函数。实参是整数（i32 取低 32 位，i64 取全部），返回第一个结果（装成整数，无结果为 0）；只支持至多一个结果，实参个数必须和函数一致，不符即致命退出。

**实例上下文**：模块的类型表、函数表、全局表、表描述、元素段、数据段、标签、起始函数、客内存、节表、模块字节地址与长度、宿主原型类型（`yy_bytes` 等）都存在 0x41C 起的一段状态格里（`布局` 的 `上下文首`、`上下文长`），解释器一直只读这些格；`切换实例` 就是把当前上下文存回实例记录、再把目标记录拷进状态格（`实例` 模块）。值栈、标签栈、帧栈、处理器栈与 GC 堆由所有实例共享。

**堆与回收**：初始实例的元数据放在区域分配器里；其他实例的模块字节、元数据、各表和客内存都放在 GC 堆里的**原始块**（对象种类 5，回收时只标记不扫描），头地址记在所属实例记录的块表里，回收时以它为根；回收还会遍历所有实例的全局与表作根。对象头字 0 的第 16–23 位记创建它的实例号（实例 0 时与旧头字节完全相同），所以回收能用正确的类型表扫描各实例的对象，`ref.test`/`ref.cast` 遇到别的实例的对象一律判为不属于。

**跨实例调用**：调用帧多记一个“调用者实例”。一个导入如果链接到别的实例的导出函数，`调用`/`尾调用` 就压帧、切换到目标实例、进入目标函数；`返回处理` 弹帧时若帧里的实例与当前不同就切回去。`调用导出` 则由驱动就地压一个带“返回钩”的帧：返回时解释循环退出，入口的驱动循环把结果装箱后从调用者的下一条指令续行（宿主原语要求返回引用）。异常不越过实例边界：处理器栈项记录所属实例，分发时跳过别的实例的处理器。

**链接与延迟链接**：模块的导入项若不是 `yuyan:gc-host/v1.call`，就按“模块名”找已装载的同名实例、再按“字段名”找它导出的函数，核对函数类型（参数与结果编码逐字节相同）后，把导入条改成“链接到 实例号+函数号”。装载时对每个导入尝试一次；仍未连接的在第一次被调用时再试（**延迟链接**），所以互相导入的两个模块可以先后装载：先装的那个对后装者的导入，等后装的装好、被调用时才链接。

**驱动循环（请求）**：有些宿主原语需要执行器的其余部分（装载要解析模块并运行起始函数），而低阶模式不允许互递归；所以原语只在 `状态_请求` 里登记请求并返回占位结果，`调用` 让解释循环退出（`状态_续*` 存续行现场），入口的 `处理请求们` 办完（例如 `加载实例`）后把结果写进占位槽，再从存好的现场重新进入解释循环。子进程的“待重启”用的是同一套退出方式。起始函数里不能再发请求。

**限制**：跨实例只传数值（i32/i64），不传 GC 引用与函数引用；表与元素段的导入导出、内存与全局的导入导出、多结果值的 `调用导出` 均未实现；导出函数本身是导入的（转发）不支持；一次装载对模块内容不做验证，不合规即致命退出。

## 持久文件系统与块设备

Virtio 块设备（现代协议、单队列、一次一个请求）的驱动运行在用户态：初始化时协商特性、核对 PCI 能力链、配置队列并读出容量；队列、请求头与数据缓冲放在内核授予的静态窗口内，用户态只经 `搬入静态／搬出静态` 两个内核服务存取。文件系统是双区追加日志：超级块 + 两个等长的记录区，记录由头扇区、数据扇区、提交扇区组成，挂载时顺序验证，遇到无效头或缺提交扇区即为日志尾；空间不足时把存活条目紧缩到另一区并切换超级块。

## 构建、调试与验收

```text
./yy豫构 构建 客体二号 --输出 /tmp/yy客体二号.wasm
```

产物是标准 Wasm 模块（导出 `启动`，签名 `() → ()`）。验证工具 `工具/豫言裸机/普通豫言验证。豫` 读入它，追加客体模块（0x10000 起，至多 448 KiB；磁盘上的程序至多 4 MiB，见“子进程”一节）、模块长度（0x408）与标志数据段，生成 ARM64 与 AMD64 镜像。`启动` 默认调用导出 `_start`，测试时可在 0x2400 放导出名、0x2440 放参数个数、0x2444 起放 i32 参数。同一份 wasm 也能在 Node 中调试：宿主提供 `平台` 模块的 `写字节`、`退出任务`、`读字节` 与设备函数，把客体写入内存后调用 `启动`。

验收：`yy普通豫言验证` 编译 `普通探针/` 下每个 `.豫` 源程序（`./yy豫构 … --target=wasmgc`），把模块嵌入执行器，生成 ARM64 与 AMD64 镜像并在 QEMU 中运行，要求串口输出恰为“豫言核心启动”、与 `.期望`（宿主 Node 运行同一模块的输出）逐字相同的程序输出、“用户任务全部退出”；磁盘探针另带持久盘，覆盖跨重启的文件读写。用户态壳的测试放在 `工具/豫言裸机/壳/测试/`：`名.输入` 经串口送入壳，`名.期望` 为壳的完整输出；有 `名.预置` 目录树者另挂离线造好的持久盘，树中以 `。豫` 结尾的文件先编成 wasmgc 模块、以 `.wasm` 之名入盘（如 `/程序/你好。豫` 成 `/程序/你好.wasm`），所以 `运行` 命令的验收是真的子进程：参数与程序名传递、退出码回到壳、启动失败为 127、丢弃输出、相对路径；`崩溃` 测试里子程序除以零（退出码 125）、无限递归（栈溢出：递归过深，122）、耗尽内存（堆内存不足，120）都只结束子任务，壳照常打印退出码并继续执行下一条命令；`子进程文件` 验证子任务里的文件读写（经初始任务代办）在壳里也看得见；`重定向` 验证 `追加`、`复制`、`移动` 与 `>`、`>>`（含 `运行 … > 文件` 用“获取输出”取回子程序的输出）；`脚本` 验证 `脚本 路径` 逐行执行文件里的命令（先示 `+ 命令`，`#` 起首与空行跳过）；`示例` 以符号链接把 `示例/` 目录当预置树，运行其中六个示例程序（见 [示例](示例.汉语.md)）；`普通-网页汇编-*` 十二例直接取自语言测试集 `测试/网页汇编`（后端语义的回归测试，`名-1。豫` 与期望输出 `名。成功`，如深栈、递归回收、大数组、长打表、癸象转义等），验证器在期望末尾补换行后逐字比较；加 `--全部覆盖 是` 则取 `测试/网页汇编` 里除十三例（八个自己 fork 子进程需要第三个任务槽，五个用了编译器库超出 448 KiB 窗口）以外的全部 28 例，两个架构都通过。

## 限制

- 没有 SIMD；多内存、导入内存/表/全局、外部引用未实现；表的容量在解析时按上限一次分配。
- 内存：每个任务的线性内存至多 512 页（32 MiB），其中值栈、标签栈、帧栈等约 6 MiB，其余给模块、GC 堆与文件缓冲；内核的物理块池共 64 MiB（32 块，两个任务共用）。GC 堆用尽报“堆内存不足”（退出码 120）——例如一次物化八十万项的整数列表（每个节点约 24–32 字节）就会用尽。
- 不做模块验证，信任编译器产物；`ref.cast` 用超类型链，不做跨递归组的结构等价。
- 实时钟只有秒的精度、只有 UTC（见[墙钟服务](墙钟服务.汉语.md)），文件没有修改时间；子进程一次只能有一个（内核只有两个任务槽），子任务不能再起子进程；子任务的文件操作经邮箱转给初始任务办理（见“子进程里的文件”），量大时很慢；多实例只传数值，见上节。
