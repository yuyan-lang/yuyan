# 客体执行器二号（普通豫言 WasmGC）

## 为什么需要

一号执行器（手写扁平指令列，约 727 KB 源码）只能执行整数子集，模块窗口 128 KiB、128 个函数、四字节值槽，无法承载普通豫言编译出的 WasmGC 模块：带标准库打印的最小模块有 800 个函数、1357 个全局、522 个被动数据段、38 个类型，用到 i64、引用、结构体与数组、具体类型转换、异常和尾调用。二号执行器用**底层模式**的普通豫言写成（见 `文档/底层模式.汉语.md`；它取代了早先自造的括号式低阶语言），约 4500 行，源码在 `工具/豫言裸机/客体二号/`，是一个声明了 `「编译模式」者『底层』也。` 的包，只依赖 `底层库`。编译成 Wasm 模块后读成 `网页状态模块`，经既有的寄存器降级进入 ARM64／AMD64 用户镜像，在用户态运行。

## 值与对象

- **值槽**：操作数、局部和全局都是 8 字节槽 `[低字, 高字]`；i32、引用只用低字（高字不关心），i64、f64 占满。
- **引用字**：0 = 空；奇数 = i31（`(值<<1)|1`）；低三位为 010 = 函数引用（`(函数号<<3)|2`）；8 字节对齐的堆地址 = 对象。
- **堆对象**：头 8 字节 `[类型号|种类<<24|标记位, 总字节数]`。结构体 = 头 + 每字段 8 字节槽（压缩字段存于低字）；数组 = 头 + `[长度][填充]` + 元素（按元素宽度 1/2/4/8 字节）；异常对象（种类 4）保存标签与载荷。
- **类型表**：每类型 32 字节，记录种类、参数／字段／元素信息、超类型；字段类别 0 = 四字节数值、1 = 八字节数值、2 = 引用、3 = i8、4 = i16。类型关系用超类型链判定，函数类型按参数与结果编码逐字节比较。

## 执行

- **直接解释字节码**：每个函数第一次调用时扫描函数体，建立每个字节偏移 8 字节的边表（块起点 → end 之后的位置、if → else 之后的位置），此后 `block/loop/if/br` 由运行期**标签栈**（每项 `[目标, 栈基, 元数, 种类]`）处理，`try_table` 标签同时管理**处理器栈**。
- **寄存器作循环参数**：主循环 `解释循环(指令针, 帧针, 边基, 栈针)` 是一个自尾递归的函数，编译成回跳；简单指令直接续行，控制转移类指令（throw、end、br 系、return、调用系、GC 前缀）经状态格 `新指令针／新帧针／边偏` 交回新现场，`新指令针` 为 0 表示最外层函数已返回。
- **显式调用帧**：帧栈项 `[返回地址, 调用者 fp, 调用者函数, 标签栈顶, 处理器栈顶]`，尾调用（`return_call`、`return_call_indirect`、`return_call_ref`）复用当前帧；函数返回时恢复标签栈与处理器栈。
- 值栈、标签栈、帧栈、处理器栈、标记栈、边表池、堆都在线性内存中，大小由常量决定；首次超过八页由寄存器降级的增长助手迁入内核动态块。
- 陷阱直接打印原因并以专属退出码（120–137）退出任务。

## 垃圾回收

非移动标记清扫：分配先取自由链表（小块按 8 字节分类，大块首次适应并分割），再从堆顶划出，不够时先回收再向内存申请。对象起始位图（每 8 字节 1 位）用于判定候选指针；根为值栈（保守，两字都扫）、全局、表和异常载荷；堆内对象按类型精确扫描字段。每次回收后回收阈值设为存活字节与 2 MiB 的较大者。宿主原语执行期间禁止回收，避免多次分配之间的中间对象丢失。

## 宿主原语

`yuyan:gc-host/v1.call(名字节数组, 参数元组)` 按名字分派：打印行、打印字符串、标准错误打印行、打印通用值、退出进程、命令行程序名／参数、工作目录、环境变量（空）、平台判断、读标准输入行、字节转字符串、字节串的空／长度／取字节／从字符串／单字节／拼接、整数加／乘／除、整数转字符串、字符串转整数，以及文件系统与目录原语（读写删、建目录、列目录、路径判断、切换目录、格式化与挂载）。整数按运行时约定装箱（i31 或 `$big`），对象类型号取自模块导出的 `yy_bytes`、`yy_tuple`、`yy_big`、`yy_float` 原型。同步子进程原语见下节。**尚未实现**：小数精确表示；小数运算见“软浮点”一节，子进程见“子进程”一节。

## 子进程（复制任务、换成磁盘上的程序、重启）

宿主原语 `豫言_同步运行子进程并继承标准流`、`…并传递输出`、`豫言_同步运行子进程`（标准库 `子进程` 的 `运行并继承标准流`、`运行并传递输出`、`运行`）由模块 `主机任务` 实现，程序取自持久文件系统：

1. **父任务**把路径规范成绝对路径，确认是普通文件且长度合适（8 字节到模块窗口的 448 KiB），把程序字节读进堆里的字节数组，把命令行参数与程序名写进“送子任务之区”（`送参数区` 0xE000、`送程序名区` 0xF000），然后调用内核服务 `复制任务`。
2. **子任务**（`复制任务` 返回 0）带着父任务的整份内存醒来：把程序字节拷进模块窗口，把送来的参数与程序名拷成自己的 `参数区`（0xC000）与 `程序名区`（0xD000），把新程序长度写进状态格 `状态_待重启`（0x970）。此后调用链原路返回；`调用`／`尾调用` 见待重启就把新指令针置零，解释循环把它当作最外层函数已返回而退出。
3. 入口的**启动循环**在 `启动一次` 返回后检查待重启：非零则做 `重启准备`，再从头启动，这回读到的就是新程序。`重启准备` 先把动态区（`区域起` 到内存末）**清零**——各区与标记位图都假定拿到的是全零内存，而复制来的内存里是父任务的旧数据（例如旧的“数据段已弃”标志会让新程序的字符串常量全部越界）；再清空状态格区、写回模块长度、把块设备标为失败（设备只属于初始任务，子任务没有文件系统）、清掉测试导出名与参数、撤下待重启。子任务不打印函数结果；程序正常返回则以 0 退出任务，调用退出进程则以其码退出。
4. **父任务**恢复自己的 `状态_是子任务`，`等待任务` 阻塞到子任务退出，`回收任务` 释放任务槽，把退出码作为原语结果（`运行` 则返回“退出码是否为零”）。准备阶段任何一步失败、没有空闲任务槽，都返回 127（与标准库“启动失败为一百二十七”一致）。“丢弃输出”（`运行`）把子任务的 `状态_是子任务` 置为 2，此后 `写字节` 什么也不写。

`获取命令行参数` 与 `获取命令行程序名` 读的是本任务的 `参数区` 与 `程序名区`（初始任务为空参数与 `/程序.wasm`）。内核只有两个任务槽，所以一次只能有一个子进程，子任务里再运行子进程会得到 127。**输出捕获与异步子进程**：`豫言_同步运行子进程并获取输出`（46）把子任务的“输出模式”置为 3，子任务的每个 `写字节` 先攒到最多三个字节（满三个、遇换行或改变流时）打成一条消息 `0x40+16×流位+字节数` 加低三字节，经内核邮箱发给初始任务（句柄 0）后阻塞等待父任务的确认；父任务在 等待消息 里循环收取、按流位追加到两个可倍增的缓冲、回复确认，等待返回空（子任务已退出）后 等待任务、回收任务，返回（退出码是否为零，标准输出，标准错误）；子任务每次退出前（退出任务、致命退出、启动结束）先冲刷。异步子进程（67 启动、68 尝试收取、69 输入输出多路等待）用同一套：启动后立即返回句柄 1，尝试收取 非阻塞地排空邮箱并看任务状态位，多路等待对每个关注项报告“就绪”使异步框架回来轮询（子任务必须靠父任务持续轮询确认才能跑完）。

## 小数：软浮点

标准库的小数运算都是宿主原语（`豫言_小数加`／`减`／`乘`／`除`、`小数转字符串`、`字符串转小数`、`小数转整数`、`整数转小数`，编号 49–57），小数在宿主里是 `yy_float` 结构（头 + 一个 8 字节槽）。内核的降级后端没有浮点指令，执行器用**软浮点**（`软浮点` 模块，整数指令实现 IEEE 754 binary64，就近舍入到偶）：

- **加减乘除**：解包成“符号、指数、首位在第 62 位的 64 位尾数”，对阶、加减或 128 位乘积／64 次逐位试商，再由统一的打包函数归一、舍入、处理次正规数与上溢；非数、无穷、零的各种组合都按 IEEE 754 处理。
- **整数与小数互转**：整数（64 位有符号）转小数就近舍入；小数转整数向零截断，非数为 0，超范围饱和到极值。
- **小数转字符串**：定点六位，与 JS 的 `toFixed(6)` 完全一致（平局取绝对值大者）：用大整数精确算 ⌊值×10^6+½⌋；不小于 10^21 的值仍写出全部数字（JS 会改用指数记法）。
- **字符串转小数**：跳过前导空白，可选符号、整数与小数位、`e`/`E` 指数，`inf`/`nan`；无可转换内容得 0。全部有效数字累积成大整数，D×10^E 用大整数精确舍入（≤19 位数字且 |E| ≤ 22 走一次乘除的快路径），和 `Number()` 逐位一致。
- 尚未实现：`小数精确表示`（最短往返表示）；Wasm 的 f64 指令（编译器不产生）。
- **验证**：Node 脚本 `客体二号/软浮点对照.cjs` 直接调用执行器导出的 `浮点运算`，随机对照 V8 的双精度（`node 工具/豫言裸机/客体二号/软浮点对照.cjs x.wasm 轮数 种子`）——加减乘除、整数转浮点、浮点转整数、定点串、字符串转小数各数百万次零差异（含次正规数、无穷、非数、平局、四十七个已知的舍入难例）；验收 `普通探针/小数。豫`（各运算与转换）与 `小数压力。豫`（600 轮混合运算累加，任何一次舍入错误都会改变结果），参照输出取自 Node 宿主的硬件双精度，双架构 QEMU 逐字相同。
- **时间与杂项原语**（58–66）：`获取当前纳秒时间`（内核时钟滴答，每滴答 10 ms 换算）、`获取当前本地日期时间字符串`／`格式化当前本地日期时间`（没有实时时钟，以 1970-01-01 00:00:00 为开机之时，故只是开机以来的时长）、`路径可执行`（即普通文件）、`查找可执行程序`（在 `/bin` 与 `/程序` 下找）、`路径为符号链接`（恒假）、`取得真实路径`、`在线处理器数量`（恒 1）、`字符串按字节在前`。

## 多实例：动态装载模块与跨模块导入导出

执行器能在运行中装载更多 Wasm 模块，并让它们互相调用。初始模块（普通豫言程序）是实例 0，其余是**实例**；每个实例有独立的类型表、函数表、全局、表、元素段、数据段、标签、线性内存与导出表（“默认独立内存”），实例之间只交换数值，不共享 GC 引用。

**宿主原语**（`yuyan:gc-host/v1.call` 的扩展，编号 47、48；普通豫言用 `《《C调用》》名『…』` 声明，见 `普通探针/盘/动态-一。豫`）：

- `豫言_加载模块(路径, 名字)`：从持久文件系统读出模块，建成新实例并返回实例号（≥ 1）。失败返回 -1 路径无效、-2 不存在、-3 不是文件、-4 长度不合（8 字节到 4 MiB）或实例已满（含初始实例至多 16 个）、-5 读文件失败。名字是其他模块 `导入` 它时写的“模块名”。
- `豫言_调用导出(实例, 导出名, 实参…)`：调用某实例导出的函数。实参是整数（i32 取低 32 位，i64 取全部），返回第一个结果（装成整数，无结果为 0）；只支持至多一个结果，实参个数必须和函数一致，不符即致命退出。

**实例上下文**：模块的类型表、函数表、全局表、表描述、元素段、数据段、标签、起始函数、客内存、节表、模块字节地址与长度、宿主原型类型（`yy_bytes` 等）都存在 0x41C 起的一段状态格里（`布局` 的 `上下文首`、`上下文长`），解释器一直只读这些格；`切换实例` 就是把当前上下文存回实例记录、再把目标记录拷进状态格（`实例` 模块）。值栈、标签栈、帧栈、处理器栈与 GC 堆由所有实例共享。

**堆与回收**：初始实例的元数据放在区域分配器里；其他实例的模块字节、元数据、各表和客内存都放在 GC 堆里的**原始块**（对象种类 5，回收时只标记不扫描），头地址记在所属实例记录的块表里，回收时以它为根；回收还会遍历所有实例的全局与表作根。对象头字 0 的第 16–23 位记创建它的实例号（实例 0 时与旧头字节完全相同），所以回收能用正确的类型表扫描各实例的对象，`ref.test`/`ref.cast` 遇到别的实例的对象一律判为不属于。

**跨实例调用**：调用帧多记一个“调用者实例”。一个导入如果链接到别的实例的导出函数，`调用`/`尾调用` 就压帧、切换到目标实例、进入目标函数；`返回处理` 弹帧时若帧里的实例与当前不同就切回去。`调用导出` 则由驱动就地压一个带“返回钩”的帧：返回时解释循环退出，入口的驱动循环把结果装箱后从调用者的下一条指令续行（宿主原语要求返回引用）。异常不越过实例边界：处理器栈项记录所属实例，分发时跳过别的实例的处理器。

**链接与延迟链接**：模块的导入项若不是 `yuyan:gc-host/v1.call`，就按“模块名”找已装载的同名实例、再按“字段名”找它导出的函数，核对函数类型（参数与结果编码逐字节相同）后，把导入条改成“链接到 实例号+函数号”。装载时对每个导入尝试一次；仍未连接的在第一次被调用时再试（**延迟链接**），所以互相导入的两个模块可以先后装载：先装的那个对后装者的导入，等后装的装好、被调用时才链接。

**驱动循环（请求）**：有些宿主原语需要执行器的其余部分（装载要解析模块并运行起始函数），而低阶模式不允许互递归；所以原语只在 `状态_请求` 里登记请求并返回占位结果，`调用` 让解释循环退出（`状态_续*` 存续行现场），入口的 `处理请求们` 办完（例如 `加载实例`）后把结果写进占位槽，再从存好的现场重新进入解释循环。子进程的“待重启”用的是同一套退出方式。起始函数里不能再发请求。

**限制**：跨实例只传数值（i32/i64），不传 GC 引用与函数引用；表与元素段的导入导出、内存与全局的导入导出、多结果值的 `调用导出` 均未实现；导出函数本身是导入的（转发）不支持；一次装载对模块内容不做验证，不合规即致命退出。

## 持久文件系统与块设备

Virtio 块设备（现代协议、单队列、一次一个请求）的驱动运行在用户态：初始化时协商特性、核对 PCI 能力链、配置队列并读出容量；队列、请求头与数据缓冲放在内核授予的静态窗口内，用户态只经 `搬入静态／搬出静态` 两个内核服务存取。文件系统是双区追加日志：超级块 + 两个等长的记录区，记录由头扇区、数据扇区、提交扇区组成，挂载时顺序验证，遇到无效头或缺提交扇区即为日志尾；空间不足时把存活条目紧缩到另一区并切换超级块。

## 构建、调试与验收

```text
./yy豫构 构建 客体二号 --输出 /tmp/yy客体二号.wasm
```

产物是标准 Wasm 模块（导出 `启动`，签名 `() → ()`）。验证工具 `工具/豫言裸机/普通豫言验证。豫` 读入它，追加客体模块（0x10000 起，至多 448 KiB）、模块长度（0x408）与标志数据段，生成 ARM64 与 AMD64 镜像。`启动` 默认调用导出 `_start`，测试时可在 0x2400 放导出名、0x2440 放参数个数、0x2444 起放 i32 参数。同一份 wasm 也能在 Node 中调试：宿主提供 `平台` 模块的 `写字节`、`退出任务`、`读字节` 与设备函数，把客体写入内存后调用 `启动`。

验收：`yy普通豫言验证` 编译 `普通探针/` 下每个 `.豫` 源程序（`./yy豫构 … --target=wasmgc`），把模块嵌入执行器，生成 ARM64 与 AMD64 镜像并在 QEMU 中运行，要求串口输出恰为“豫言核心启动”、与 `.期望`（宿主 Node 运行同一模块的输出）逐字相同的程序输出、“用户任务全部退出”；磁盘探针另带持久盘，覆盖跨重启的文件读写。用户态壳的测试放在 `工具/豫言裸机/壳/测试/`：`名.输入` 经串口送入壳，`名.期望` 为壳的完整输出；有 `名.预置` 目录树者另挂离线造好的持久盘，树中以 `。豫` 结尾的文件先编成 wasmgc 模块、以 `.wasm` 之名入盘（如 `/程序/你好。豫` 成 `/程序/你好.wasm`），所以 `运行` 命令的验收是真的子进程：参数与程序名传递、退出码回到壳、启动失败为 127、丢弃输出、相对路径。

## 限制

- Wasm 的 f64 指令只有常量搬运（编译器不产生浮点指令，小数运算走宿主原语，见“软浮点”）；没有 SIMD；多内存、导入内存／表／全局、外部引用未实现。
- 不做模块验证，信任编译器产物；`ref.cast` 用超类型链，不做跨递归组的结构等价。
- 实时时钟待接入；子进程一次只能有一个（内核只有两个任务槽），且子任务不能访问块设备；多实例只传数值，见上节。
