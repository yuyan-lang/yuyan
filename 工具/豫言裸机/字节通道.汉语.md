# 用户态字节通道

字节通道静态链接进用户程序，生成标准 Wasm i32 指令，复用平台的发送消息、等待消息、消息来源接口。内核不接触用户缓冲区，不增加系统调用。它是未来路径、命令和设备请求的传输基础，尚不是文件服务或 Shell。

`网页字节通道函数` 按顺序生成确认、发送、接收、带重试的单字发送四个函数。构造参数依次为发送消息、等待消息、消息来源、确认函数的索引，单参单结果、三参单结果类型索引，任务状态、任务编号的函数索引，以及双参单结果类型索引。发送参数为对端句柄、源偏移、长度；接收参数为对端句柄、目标偏移、容量。二者成功返回字节数，失败返回 -1。确认与单字发送函数供协议内部使用。

每次最多 256 字节。头部为 `0x59000000 + 长度`；随后每个 i32 消息按小端装载最多四字节。接收方确认头部及每个数据字，确认值为零，拒绝值为 -1。每次接收均检查完整来源句柄。零字节传输仍交换头部与确认。负句柄和向自身传输被拒绝。

单字发送遇到满信箱会检查对端状态，并在对端可运行或等待消息时重试，依靠定时抢占让接收方取得执行机会。对端退出或句柄失效则失败。该函数只用于已经具有双向通信权限的对端；目前两个任务槽满足这一关系，将来扩展任务与权限模型时必须补充权限查询或可区分的发送错误。它没有超时，活着但不消费消息的对端可能使其持续等待；这也是未来取消机制需要处理的情形。

发送前检查源范围，接收方在写入前检查魔数、长度、容量和目标范围，使用减法避免地址相加回绕。容量不得大于 256，即使实际消息更短。范围为空时允许指向线性内存末尾。非法接收参数在接到头部后拒绝，让发送方取得错误。非法源参数直接返回，不会通知尚在等待的接收方，因此上层必须先约定请求生命周期。

中途退出或来源不符返回 -1；已经写入的前缀不会回滚，调用者必须丢弃失败结果。确认只代表数据已接收，不代表文件已持久化，也不提供恰好一次执行保证。通道假定同一对端串行使用专用消息流；不支持多个并发发送者、取消、超时或复用请求编号。当前内核仍只有两个任务槽。后续设备批量吞吐应另行测量，再决定共享页等机制。

验证包含两任务双向传输 0、1、3、4、5、255、256 字节及全部字节值，缓冲区哨兵、容量不足、地址越界、空范围末尾、错误魔数、超长头部、中途退出、满信箱重试与对端退出，以及错误数据期望必须失败的负对照。验证结果见验证记录；本文件不代表整个操作系统已经完成。
