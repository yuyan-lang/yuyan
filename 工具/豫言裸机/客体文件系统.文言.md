# 客体文件系统与用户态块设备驱动

## 何以有此

寻常豫言之程，借标准库 `文件系统` 以读写文件。昔者于裸机，此诸原语徒为空桩，Shell 亦唯用镜像内预置之程。今使标准库之文件原语真落于磁盘：文件系统与 Virtio 块设备之驱动，皆书于客体执行器二号（以[底层模式](../../文档/底层模式.文言.md)之常豫言书之，运行于用户态）；内核唯供设备寄存器之窗、IOMMU 所授 DMA 之窗，及两内存搬运之服务。其久存之证，在真 QEMU virtio-blk 磁盘之文件：前后两 QEMU 之进程，后者不格式化，而读回前者所写。

## 文件

|文件（`工具/豫言裸机/客体二号/`）|所载|
|---|---|
|文件系统|双区追加日志之文件系统：校验、条目表、记录读写、挂载与格式化、紧缩、对外诸操作|
|主机文件|以标准库文件原语映于文件系统：路径规范（当前目录、`.`、`..`、重斜线）、补建祖先目录、列目录、宿主调用之分派|
|块设备虚拟|Virtio 块设备用户态驱动（真设备）|
|块设备宿主|Node 调试之体：宿主供块读写（唯于 Node 调试执行器）|
|块设备无|无盘之体：`块就绪` 恒为假|

`块设备虚拟` 无设备时（普通镜像中设备寄存器之服务一概拒之）初置败，`块就绪` 为假，文件原语返输入输出之错；故同一执行器，无盘镜像可行，带盘之设备驱动镜像亦可行。

## 盘之布局与提交

- 扇区零、一为轮流所写之超级块（魔数、代、活区号、区长、校验）；其后二等长之区，每区为记录之序。挂载则取代最高而校验合者。
- **记录**＝头扇区＋数据扇区若干＋提交扇区。头扇区含魔数 `YYR1`、代、序号、类型（一建目录、二写文件、三删除）、路径长、数据长、数据扇区数、数据校验、头校验（FNV-1a）及路径之字节。提交扇区含魔数 `YYC1`、代、序号、头校验、数据校验及自身校验。写记录之序：头、数据、提交，终而刷新；故唯提交扇区完整落盘之记录方生效。
- **挂载**依序验记录，遇无效之头或缺提交之扇区，即为日志之尾（断电时末一未提交之记录见弃）；已提交而数据校验败者，挂载败（报损，不默读其误）。诸记录依序施于内存之条目表（路径池与三十二字节之条目：路径、种类、数据扇区、数据长、序号）。
- **紧缩**：活区满，则以存活之条目依序重写于另一区，先使新区之首失效，写毕而易超级块（代加一）并刷新；中途败则复旧区之状，重挂载可返旧区。
- 文件之内容整体而写（覆盖则追加新记录）；旧本于紧缩时收之。读文件按条目所记之数据扇区读回，缓冲上取整至五百一十二字节。

## 用户态 Virtio 块设备驱动

协议同 `库/编译器核心/网页汇编核心/虚拟磁盘。豫`（现代 PCI、`VERSION_1` 与 `ACCESS_PLATFORM`、`FLUSH` 为必需、记只读位、有界遍历 PCI 能力链以核通知窗与设备配置窗、单队列大小八、同时一请求、配置世次前后一致方采容量、头／数据／状态三描述符（刷新则略数据）、轮询已用环而核描述符号、状态字节及已用长度）。所异者在 DMA 缓冲之所在：

- 执行器之线性内存逾八页，则迁入内核之动态块（见[内存块管理](内存块管理.文言.md)）；而设备唯经 IOMMU 访内核所授之**静窗**（用户空间静区 `0x40300000`／`0x300000` 起 0x80000 字节，设备址＝静偏移＋`0x1000`）。故驱动置描述符表、可用环、已用环、请求头、状态字节与五百一十二字节之数据缓冲于静窗内 `0x70000` 至 `0x70400`，用户态唯经二新内核服务以存取：
- **服务二四 `搬入静态(线性偏移, 静态偏移 | 长度<<20)`**、**服务二五 `搬出静态(…)`**：于任务之线性内存（基址寄存器 ARM64 x28／AMD64 r9，静或迁入动态块后皆可）与其静窗之间，复制至多四千零九十五字节。越界（静窗 0x80000；线性内存未迁时 0x80000，既迁则块数乘二兆字节）返负一，成则返零。窗属任务自己之地址空间，故任何任务用之，皆不出己之内存；内核关中断而逐字节复制，无抢占。
- 驱动唯于线性内存已逾八页（即已迁，静窗与线性内存不相叠）时始初置。
- `设备驱动镜像` 今受可增之线性内存：上限等于初值者（固定内存）仍只授此区间（旧用例不变），否则授整个八页静窗。

发布请求之序：写头、写描述符、写数据（写请求）、写环项，以设备寄存器一读为屏障，再进可用索引，终写通知寄存器；然后轮询状态寄存器与已用环索引，逾时（一百万次）或状态异则返负一。

## 宿主原语

标准库 `文件系统` 之 `读文件`、`读文件字节串`、`写文件`、`写文件字节串`、`删文件`、`读文件夹`、`路径存在`、`路径是文件夹`、`路径是普通文件`、`切换当前工作目录`、`创建文件夹`、`获取当前工作目录`，并新增 `格式化`、`挂载`、`错误码` 三原语（对应 `yuyan:gc-host` 之 `豫言_文件系统格式化` 等），皆映于上述文件系统；路径先规范为绝对路径，所缺祖先目录随需而建。

## 验

- Node 之参照：以执行器（`块设备宿主` 之体）与同一模块交 Node，用宿主所供之虚拟盘，文件读写探针之输出与标准库参照宿主逐字相合，重启（同盘再启）而读回前次之内容。
- 内核之服务：一底层模式之测试程序（`低阶探针/搬运`）于静态之阶与迁入动态块之后，各往返复制，测越界（静窗、线性之上限）、恰在边界、四千零九十五字节之整块，两架构串口皆报通过。
- 两架构 QEMU（ARM64 SMMUv3、AMD64 Q35/VT-d，virtio-blk 加 `iommu_platform`）：`yy普通豫言验证` 之 `普通探针/盘/文件-一`（多层目录、覆盖写、逾一扇区之内容、存在与类型之判、删除、列目录）及其后之 `文件-二`（新 QEMU 之进程，不格式化，读回文件-一所写者），输出与参照逐字相合。同一磁盘文件由 `文件-一` 格式化，于 `文件-二` 重挂载。
- 磁盘探针置于 `工具/豫言裸机/普通探针/盘/`，名曰 `组名-一。豫`、`组名-二。豫`……；同组诸阶依序行于同一磁盘，唯第一阶格式化。

## 离线造盘

`库/编译器核心/裸机后端/持久盘构造。豫` 依同一格式（三十二位 FNV-1a、`YYR1`／`YYC1`、超级块）于离线造整盘镜像：`造持久盘 容量 目录们 文件们` 与 `按参数造持久盘`（参数为 `+盘内目录` 与 `盘内路径=本地文件`，所缺祖先目录自补）、`目录树造盘参数`（以一棵本地目录树为盘根）。工具 `yy造盘 输出.盘 容量扇区 [+盘内目录]… [盘内路径=本地文件]…` 乃其命令行之壳。所产已格式化，充 QEMU 之 virtio-blk 磁盘，客体挂载即见诸文件，无须客体先格式化；离线之格式与文件系统.低阶必同步。

验：`普通探针/盘/预置.预置/` 目录树，由 `yy普通豫言验证` 造成一 MiB 之盘（内有跨扇区之文件，四千五百字节），`预置-一` 于两架构读预置之文件而再写一新文件，`预置-二`（新 QEMU 之进程）读回二者。又有底层模式之探针包 `低阶探针/搬运`（`搬运探针`），直作用户程序装入内核镜像，以验服务二四、二五。

## 界

- 条目表与路径池大小固定；单文件受一次内存读入之限；唯整体覆盖写，无追加与部分写；无权限、无时间戳（修改时间恒为零）、无链接。
- 文件系统行于执行器之单一任务；他任务经消息以访其接口，尚未接入；断电一致，恃“提交扇区最后落盘”之日志序与 FNV 校验，未作真实断电注入（磁盘故障注入之用例仍待补）。
- 无块设备之中断与并发请求；轮询上限一百万次。

```sh
./yy豫构 文件 工具/豫言裸机/普通豫言验证。豫 --编译器 ./yy4_bs --输出 yy普通豫言验证 -j 24 -- --do-not-optimize
./yy普通豫言验证 --只验 文件
```
