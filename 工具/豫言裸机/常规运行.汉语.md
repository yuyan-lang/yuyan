# 常规运行与程序退出码

裸机镜像现在区分常规运行和验收协议。这个区分只控制镜像的执行与测试策略，不替代包级“系统模式”的语言约束，也不表示已经支持完整普通豫言或 WasmGC。输入仍限于当前机器码后端支持的 Wasm 子集。

常规运行不要求程序调用测试用的“核验”。导出的无参数无结果“启动”函数返回时，任务以退出码 0 结束。新增 `平台／退出任务：(i32) → ()` 接受完整三十二位退出码并结束当前任务，不返回调用点；等待者和退出码查询可以获得该值。

正常结束的状态仍为 6，与退出码是否为零无关；发生陷阱为故障状态 14。这让调用者能区分“主动返回 132”和“发生陷阱而得到 132”。由于已有查询和等待接口也用 -1 表示失败，合法的 -1 退出码须结合任务已结束状态及有效句柄判断；不能仅凭返回值断言接口失败。

## 验收协议保留

旧“正常”“隔离”镜像仍启用验收模式，要求正常返回前恰好完成四次核验。显式退出不能绕过这个协议。运行模式由内核私有的镜像配置决定，用户任务不能修改；ARM64 字段在 `0x400b0090`，AMD64 在 `0x103390`。

常规模式下，即使程序调用调试“核验”，失败也只使调用任务进入用户陷阱退出路径，其他任务可以继续并读取故障原因。验收模式继续使用原来的全局失败报告，避免削弱既有测试。

## 命令行

省略最后一个参数，默认生成常规运行镜像：

```sh
./yy豫言裸机 臂六十四 程序.wasm yy程序.elf
./yy豫言裸机 兼容六十四 程序.wasm yy程序.img
```

也可以显式给出“运行”。旧参数“正常”“隔离”保留原验收含义。

当前 QEMU 启动器在所有任务结束后停止模拟。根任务退出码为零时，ARM64 宿主退出码为 0，AMD64 为 33；根任务非零时分别为 1、35。这个模拟器适配层只报告成功或失败，任务内部仍保留完整三十二位退出码。它不是通用空闲循环、系统关机或多服务生命周期的最终实现。

## 验收设计和边界

普通程序在自身控制流中检查实际运行结果，失败则触发不可达陷阱，成功后才打印完成标记；不靠四次核验计数取得正常退出许可。测试覆盖自动返回、显式退出不返回、子任务正负退出码传递、核验失败隔离及验收模式防绕过。

除故意触发调试核验失败的隔离用例外，新增常规程序不导入“核验”。此变化为 Shell 运行实际程序解除测试协议限制；动态加载、完整高级语言运行时、设备和文件系统仍待实现。
