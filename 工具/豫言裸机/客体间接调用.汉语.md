# 客体间接调用

后续进展：标准元素段验证与初始化已接入，见[客体元素段](客体元素段.汉语.md)。下文保留间接调用首次验收时的范围。

执行器支持当前全 i32 类型子集的标准 `call_indirect` 指令。二进制仍使用标准操作码与立即数，中文指令描述及运行时不改变公共 ABI。

解码时检查类型号及表号；栈验证先取出表下标，再按目标签名消费参数并产生结果。执行时检查下标、空引用和目标函数签名，随后复用直接调用路径，因此平台导入与本地函数共享调用规则。签名按结构比较：在当前全 i32 子集中，参数数量和结果数量相同即等价，不能只比较类型编号。

表下标越界、空引用及签名不符返回客体陷阱负四，运行入口清理操作数栈、调用深度和执行权限，不使执行器自身发生机器异常。资源初始化仍将函数表全部设为空引用。

此阶段尚未支持元素段、表修改指令或完整引用类型。成功调用用例由验收代码在资源初始化之后写入执行器内部表项；这是隔离的单元测试装置，不是程序可调用的接口，也不代表已经能够加载任意带函数指针的 C 模块。下一步须将标准元素段的验证与实例化接入，再完成端到端验收。

新增九组用例覆盖空引用、正负越界下标、等价异号签名、签名不合、缺表、错误表号、错误类型号和缺少实参。九组模块的静态有效性、其中五组的运行结果与标准 Wasm 引擎对照一致；标准引擎的测试通过导出表设置相同函数引用。

规范依据：[WebAssembly 间接调用验证规则](https://webassembly.github.io/spec/core/valid/instructions.html)。本实现只声明上述受限类型子集。
