# 系统调用与缺页入口使用统一整数帧

ARM64 同步异常入口、AMD64 系统调用和缺页入口现与定时中断使用同一套整数上下文布局。ARM64 为 272 字节，AMD64 为 160 字节，字段见[任务上下文](任务上下文.汉语.md)。这为后续在不同异常路径阻塞或结束任务提供共同的恢复基础。

ARM64 保存上下文时暂借返回值寄存器读取系统状态，所以在分派系统调用前从帧中恢复原参数。返回时先把服务结果写入帧中的零号寄存器槽，再检查返回地址及用户栈范围，最后恢复整数上下文并返回用户态。

AMD64 系统调用入口保留处理器生成的返回帧，在其前保存十五个通用寄存器。服务结果写入偏移 112 的累加寄存器槽，再走共同检查与恢复路径。其他寄存器从进入内核时的帧恢复。

AMD64 缺页异常比普通中断多一个硬件错误码。入口先确认来自用户态，在保留原累加寄存器的前提下，将错误码保存到内核私有位置 `0x103328`，移除栈中的错误码，再构造相同的 160 字节帧。既有缺页检查改从私有位置读取用户访问标志。此暂存方式目前用于单处理器、内核处理期间屏蔽中断的配置；尚未提供多处理器或嵌套故障状态管理。

2026-09-22，双架构 118 项 QEMU 检查全部通过。新增正常和错误期望值用例，在二十层、四十层等递归计算中调用用户态查询服务，检查服务返回值与仍保存在操作数栈、调用栈中的值；同时验证空输入返回负一。相同模块在 V8 中完成四次正常计算核验，错误期望值按预期失败。

原有定时中断、屏蔽中断负对照、用户／内核隔离、栈越界及独立 C 模块均通过回归。类型检查通过，新增参数恢复、结果写回和错误码归一化指令经反汇编核对。

```sh
./yy3_bs 工具/豫言裸机/验证。豫 -o yy裸机验证 -j 1
./yy裸机验证 --外部模块 yy外部C模块.wasm yy外部C错误.wasm
```

产物目录 `/tmp/yy裸机验证.EgUuS0`；记录见 `验证记录.json` 的“统一异常帧扩展验证”。缺页路径目前仍结束测试客体，没有恢复故障任务或让其他任务继续运行；任务创建、调度切换、阻塞等待与完整进程状态仍未实现。其他尚未支持的异常也没有统一为可恢复任务事件。

原生与 WasmGC 生成器的双架构系统调用用例镜像逐字节一致，且均与本轮 QEMU 受测镜像一致。

后续已在两架构实现静态双任务的定时抢占和地址空间切换，见[双任务调度](双任务调度.汉语.md)。本篇 118 项结果属于统一异常帧阶段的历史证据。
