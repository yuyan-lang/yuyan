# 受限设备配置读取

块设备先采用现代 Virtio PCI 传输，以便 ARM64 与 AMD64 共用用户态协议代码。当前阶段实现识别与能力表遍历，尚未协商特性、建立队列、启动 DMA 或读写扇区，不能据此宣称文件持久化已完成。

新增平台导入 `设备配置读(i32)->i32`，服务号为 19。参数是配置空间内的字节偏移，必须四字节对齐且处于 0 至 252。接口固定访问总线零、设备四、功能零，只允许初始任务（内部槽零）调用。复制出的子任务没有该权限。调用者不能提供总线号、任意物理地址或端口号；没有配置写接口。

结果是原始三十二位值。参数错误、未授权返回全一；不存在的设备也通常读到全一，因此当前接口不区分这些失败原因。设备存在时，用户态核对厂商与现代块设备标识，再遍历能力表，收集通用配置、通知、ISR 和设备配置的存在位。检查指针对齐、配置窗口边界、能力长度和最多四十八步，通知能力还要求包含乘数字段。该阶段只识别能力，不把未经验证的 BAR 地址用于访存。

ARM64 使用 QEMU `virt` 的低地址 PCI ECAM。设备测试指定 `highmem-ecam=off`，固定设备位于 `0x3f020000`；内核将 `0x3f000000` 所在两兆字节块映射为设备内存、仅内核可访问、不可执行。AMD64 使用配置地址与数据端口 `0xcf8/0xcfc`，中断处理期间串行完成访问，用户态不取得端口权限。两种实现均以豫言生成机器字节。

验收给 QEMU 挂接独立的一兆字节临时磁盘，设备参数为 `virtio-blk-pci,disable-legacy=on,addr=4,drive=yy_disk`。真实设备用例核对标识、类别、四类能力及非法参数拒绝，并创建子任务验证权限不继承；缺席用例不挂盘；错误标识期望必须使根任务失败。另用同一个解析函数检查十组正常与畸形配置表。

初始任务授权只是当前引导策略，尚不是完整的可转移设备能力系统。后续需要 BAR 范围验证与分配、受限寄存器访问、队列内存、DMA 生命周期和缓存一致性、完成通知、错误恢复及刷新，再实现用户态块服务和持久化文件系统。没有 IOMMU 时，掌握设备 DMA 编程的驱动仍属于可信计算基；不能仅凭其运行在用户态就宣称可约束任意恶意 DMA。

规范依据：[Virtio 1.2](https://docs.oasis-open.org/virtio/virtio/v1.2/virtio-v1.2.html) 的现代 PCI 传输与设备标识；[QEMU ARM virt 文档](https://www.qemu.org/docs/master/system/arm/virt.html) 的低地址 ECAM 选项；[QEMU virt 平台内存表](https://github.com/qemu/qemu/blob/master/hw/arm/virt.c) 的 ECAM 区域。当前固定平台配置并不替代未来的设备树与通用 PCI 枚举。
