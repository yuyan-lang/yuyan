# 客体文件系统与用户态块设备驱动

## 为什么需要

普通豫言程序通过标准库 `文件系统` 读写文件。此前在裸机上这些原语只是桩，Shell 也只能靠镜像里预先放好的程序。这一步把标准库的文件原语真正落到磁盘：文件系统与 Virtio 块设备驱动都写在客体执行器二号里（用[底层模式](../../文档/底层模式.汉语.md)的普通豫言编写，用户态运行），内核只提供设备寄存器窗口、IOMMU 授权的 DMA 窗口和两个内存搬运服务。持久性由真实的 QEMU virtio-blk 磁盘文件证明：两次独立的 QEMU 进程、第二次不格式化，读回第一次写入的内容。

## 文件

|文件（`工具/豫言裸机/客体二号/`）|内容|
|---|---|
|文件系统|双区追加日志文件系统：校验、条目表、记录读写、挂载／格式化、紧缩、对外操作|
|主机文件|把标准库文件原语映射到文件系统：路径规范化（当前目录、`.`、`..`、重复斜线）、创建祖先目录、列目录、宿主调用分派|
|块设备虚拟|Virtio 块设备用户态驱动（真设备）|
|块设备宿主|Node 调试变体：由宿主提供块读写（仅用于在 Node 里调试执行器）|
|块设备无|无盘变体：`块就绪` 恒为假|

`块设备虚拟` 在没有设备时（普通镜像里设备寄存器服务一律拒绝）初始化失败，`块就绪` 为假，文件原语返回输入输出错误——所以同一个执行器既能在无盘镜像里运行，也能在带盘的设备驱动镜像里运行。

## 磁盘布局与提交

- 扇区 0、1 是交替写入的超级块（魔数、代数、活动区号、区长、校验）；其后两个等长的区，每区是一串记录。挂载时选代数最高且校验有效的超级块。
- **记录** = 头扇区 + 若干数据扇区 + 提交扇区。头扇区含魔数 `YYR1`、代、序号、类型（1 建目录、2 写文件、3 删除）、路径长、数据长、数据扇区数、数据校验、头校验（FNV-1a）和路径字节。提交扇区含魔数 `YYC1`、代、序号、头校验、数据校验与自身校验。写记录的顺序是头、数据、提交，最后刷新；所以只有提交扇区完整落盘的记录才生效。
- **挂载**按顺序验证记录，遇到无效头或缺提交扇区即视为日志尾（掉电时最后一条未提交的记录被丢弃）；已提交却校验失败的数据使挂载失败（报告损坏，而不是静默读错）。所有记录按序应用到内存里的条目表（路径池 + 32 字节条目：路径、种类、数据扇区、数据长、序号）。
- **紧缩**：活动区写满时把存活条目按序重写到另一个区，先使新区起点失效，写完后切换超级块（代数加一）并刷新；中途失败则恢复旧区状态，重新挂载即可回到旧区。
- 文件内容整体写入（覆盖写追加一条新记录）；旧版本在紧缩时回收。文件读取按条目里的数据扇区读回，向上取整到 512 字节的缓冲。

## 用户态 Virtio 块设备驱动

协议同 `库/编译器核心/网页汇编核心/虚拟磁盘。豫`（现代 PCI、`VERSION_1` 与 `ACCESS_PLATFORM`、`FLUSH` 必需、只读位记录、有界遍历 PCI 能力链核对通知窗口与设备配置窗口、单队列大小 8、同一时刻一个请求、配置世次前后一致才采信容量、头／数据／状态三描述符（刷新跳过数据）、轮询已用环并核对描述符号、状态字节与已用长度）。差别在 DMA 缓冲的位置：

- 执行器的线性内存超过八页时会迁入内核的动态块（见[内存块管理](内存块管理.汉语.md)），而设备只能通过 IOMMU 访问内核授予的**静态窗口**（用户空间静态区 `0x40300000`／`0x300000` 起的 0x80000 字节，设备地址 = 静态偏移 + `0x1000`）。所以驱动把描述符表、可用环、已用环、请求头、状态字节和 512 字节数据缓冲固定放在静态窗口内的 `0x70000` 至 `0x70400`，用户态只通过两个新的内核服务存取：
- **服务二四 `搬入静态(线性偏移, 静态偏移 | 长度<<20)`**、**服务二五 `搬出静态(…)`**：在任务线性内存（基址寄存器 ARM64 x28／AMD64 r9，静态或迁入动态块后皆可）与其静态窗口之间复制至多 4095 字节。越界（静态窗口 0x80000、线性内存未迁移时 0x80000／迁移后块数×2 MiB）返回 -1，成功返回 0。窗口属于任务自己的地址空间，所以任何任务使用都不越出自己的内存；内核在中断关闭下逐字节复制，无抢占。
- 驱动只在线性内存已大于八页（即已迁移，静态窗口与线性内存互不重叠）时才初始化。
- `设备驱动镜像` 现在接受可增长的线性内存：上限等于初值的固定内存仍只授予这块区间（旧用例不变），否则授予整个八页静态窗口。

发布请求的顺序：写头、写描述符、写数据（写请求）、写环项，经一次设备寄存器读作为屏障，再推进可用索引，最后写通知寄存器；然后轮询状态寄存器与已用环索引，超时（一百万次）或状态异常返回 -1。

## 宿主原语

标准库 `文件系统` 的 `读文件`、`读文件字节串`、`写文件`、`写文件字节串`、`删文件`、`读文件夹`、`路径存在`、`路径是文件夹`、`路径是普通文件`、`切换当前工作目录`、`创建文件夹`、`获取当前工作目录`，加上 `格式化`、`挂载`、`错误码` 三个新原语（对应 `yuyan:gc-host` 的 `豫言_文件系统格式化` 等）都映射到上述文件系统；路径先规范化为绝对路径，缺失的祖先目录按需创建。

## 验证

- Node 参照：把执行器（`块设备宿主` 变体）与同一模块交给 Node，用宿主提供的虚拟盘，文件读写探针输出与标准库参照宿主逐字一致，重启（同一盘再启动）读回上次内容。
- 内核服务：一个底层模式的测试程序（`低阶探针/搬运`）在静态阶段和迁入动态块之后分别往返复制、测越界（静态窗口、线性上限）、恰好边界、4095 字节整块，两架构串口均报告通过。
- 两架构 QEMU（ARM64 SMMUv3、AMD64 Q35/VT-d，virtio-blk 加 `iommu_platform`）：`yy普通豫言验证` 的 `普通探针/盘/文件-一`（多层目录、覆盖写、超过一个扇区的内容、存在性与类型判断、删除、列目录）与其后的 `文件-二`（新的 QEMU 进程，不格式化，读回文件-一写入的内容）输出与参照逐字一致。同一磁盘文件由 `文件-一` 格式化后在 `文件-二` 中重新挂载。
- 磁盘探针放在 `工具/豫言裸机/普通探针/盘/`，命名为 `组名-一。豫`、`组名-二。豫`…，同组各阶按序运行在同一个磁盘上，只有第一阶格式化。

## 离线造盘

`库/编译器核心/裸机后端/持久盘构造。豫` 按同一格式（32 位 FNV-1a、`YYR1`／`YYC1`、超级块）在离线状态生成整盘镜像：`造持久盘 容量 目录们 文件们` 与 `按参数造持久盘`（参数是 `+盘内目录` 与 `盘内路径=本地文件`，缺失的祖先目录自动补建）、`目录树造盘参数`（把一棵本地目录树当作盘根）。工具 `yy造盘 输出.盘 容量扇区 [+盘内目录]… [盘内路径=本地文件]…` 是它的命令行外壳。产物已格式化，作为 QEMU 的 virtio-blk 磁盘，客体挂载即见这些文件，不需要客体先格式化；离线格式与文件系统.低阶必须同步。

验证：`普通探针/盘/预置.预置/` 目录树被 `yy普通豫言验证` 造成 1 MiB 的盘（含一个 4500 字节跨扇区的文件），`预置-一` 在两架构读到预置文件并再写一个新文件，`预置-二`（新的 QEMU 进程）读回二者。另有底层模式的探针包 `低阶探针/搬运`（`搬运探针`），直接作为用户程序装入内核镜像，验证服务二四、二五。

## 限制

- 条目表与路径池固定大小；单个文件受一次内存读入限制；只有整体覆盖写，没有追加或部分写；没有权限、时间戳（修改时间恒为零）与链接。
- 文件系统运行在执行器的单一任务里，别的任务经消息访问它的接口尚未接入；掉电一致性靠“提交扇区最后落盘”的日志顺序与 FNV 校验，未做真实掉电注入（磁盘故障注入用例仍待补）。
- 没有块设备中断与并发请求；轮询上限一百万次。

```sh
./yy豫构 文件 工具/豫言裸机/普通豫言验证。豫 --编译器 ./yy4_bs --输出 yy普通豫言验证 -j 4 -- --do-not-optimize
./yy普通豫言验证 --只验 文件
```
