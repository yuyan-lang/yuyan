# 豫言并行编译

编译器的 `--parallel` 使用豫言任务图和标准库异步调度器，在多个工作进程中编译；不依赖 Python。调度模块现位于 `库/构建基础` 包，由编译器与独立豫构工具复用。

```sh
./yy3_bs 豫言编译器/入口。豫 --parallel -j 4 -o yy新编译器
./yy3_bs 豫言编译器/入口。豫 --parallel --type-check-only
```

`-j N`（也可写 `--num-cpu N`）限制在途工作进程数，默认使用在线处理器数量。`--very-parallel` 和实验别名 `--yuyan-parallel` 使用同一实现。

每个文件依次执行依赖分析、解析、类型检查与擦除、跨模块优化、闭包转换、求值正则变换和代码生成。前三个依赖分析之后的阶段须等待直接依赖完成相同阶段；跨模块优化之后仅等待本文件的上一阶段。依赖分析动态加入文件和任务。最终链接的文件顺序与旧调度器一致，按排序后的候选文件反复进行拓扑扫描，不受进程完成顺序影响。

派发时先收取完成结果、展开新发现的依赖，再从已就绪任务中按阶段优先级选择：依赖分析 → 解析 → 类型检查与擦除 → 跨模块优化 → 闭包转换 → ANF → 代码生成。阶段越早越优先，同阶段保持加入顺序。优先级不抢占正在执行的进程；尚未就绪的高优先级任务不占槽，也不阻止已就绪的后续任务利用空闲槽位。最终链接仍等待所有模块成功。

`native`（默认）和 `wasmgc` 默认共用上述前端任务图，在闭包转换后直接进入整模块后端，不创建旧 ANF／CPS 和逐模块机器码任务。类型检查等阶段会在面板中分别显示。可以给编译器传 `--frontend-tasks=combined`，在每个模块的一个进程内完成解析到闭包转换，恢复合并前端的对照模式；`--frontend-tasks=split` 显式选择默认拆分模式。两种模式保留相同的阶段算法及导出规则，但进程边界可能改变诊断文字中的临时名称编号，因此跨模式不保证文件逐字节相同。这些粒度选项影响两个目标及其兼容别名的并行构建；仅类型检查和串行入口不改变执行方式。`llvm`、`shadow` 均为 `native` 的别名，不再选择旧手动栈后端。

```sh
./yy豫构 构建 豫言编译器 --编译器 ./yy3_bs --输出 yy拆分.wasm -j 18 -- --target=wasmgc-anf --frontend-tasks=split --do-not-load-cache -c
./yy豫构 构建 豫言编译器 --编译器 ./yy3_bs --输出 yy合并.wasm -j 18 -- --target=wasmgc-anf --frontend-tasks=combined --do-not-load-cache -c
```

需先用当前源码生成支持这些选项的编译器，旧稳定种子不识别新选项。测量结果与验证边界见[前端合并与拆分](../../性能研究/前端调度/合并与拆分.汉语.md)。

工作进程仍使用 `--mode=worker` 和原有缓存协议。类型检查模式截断到类型检查与擦除。依赖输出按换行解析，参数以独立字符串传递，支持路径中的空格。任务失败或启动异常后停止派发，等待在途进程回收，再返回非零状态；循环或缺失依赖会报告未完成任务。

`yy_parallel_log.txt` 保存各工作进程的进程号、退出码及两路输出，`yy_parallel_deps.txt` 保存文件依赖。在任务图结束和最终链接结束时保存日志；意外终止前的日志不保证落盘。与现有编译器相同，不应让多个构建同时写入同一个缓存目录和这些日志文件。

交互终端默认显示原地刷新的构建监视面板：总耗时、完成／运行／失败数量、各阶段统计，以及正在执行的文件与耗时，不显示 PID。面板最多每 200 毫秒刷新一次，使用限时 I/O 等待而非忙循环；长任务没有完成事件时，耗时仍会更新。面板先显示汇总和阶段统计，最后显示运行文件列表；按终端尺寸裁剪，优先保留统计；窗口缩放时保留旧快照并重新绘制，避免误擦历史输出。不进入原始输入模式，不隐藏光标。

任务总量随依赖发现而增加。“待依赖”与“待槽位”分列：后者是依赖全部成功、尚未启动的就绪任务，在本轮派发后统计；运行中任务不计入其中。失败停止派发后，不再标记等待槽位。完成数包含缓存命中的工作进程，不等于实际重编模块数。最终链接也纳入监视。正常结束清除面板并留下摘要；失败诊断在清除面板后打印，不会被刷新擦除。

stderr 重定向、`TERM=dumb`、缺少终端能力或窗口过小时，退回 `[启动]`、`[完成]`、`[失败]` 普通日志。编译器参数 `--no-debug-print` 关闭面板和状态行，错误仍保留。子进程内部输出仍先收集，完整结果写入 `yy_parallel_log.txt`；监视面板不是逐字节输出转发。

## 异步子进程

`标准库/操作系统/异步子进程` 提供 `异步获取输出`，接收程序名和参数列，立即启动进程，返回 `异步任务于子进程结果`。结果四项依次为进程号、退出码、标准输出和标准错误。对同一个任务可以重复等待。

启动失败返回进程号零、退出码 127 和系统错误说明；信号退出映射为 `128 + 信号号`；收集输出或等待失败返回 125。调用方须等待已启动的任务以释放原生记录和通知描述符。当前接口捕获文本输出，不提供取消或超时。

豫言异步调度器保持单线程。每个子进程有一个原生收集线程，排空非阻塞输出管道并执行 `waitpid`，随后通过通知管道唤醒豫言任务。收集线程仅操作原生分配的存储，不访问豫言堆。编译的多核并行来自工作进程。

## 自举与验证

稳定种子已更新为原生豫言调度。以下文件式命令也会委托同目录的豫构，因此全链路使用包构建：

```sh
./yy_bs_stable 豫言编译器/入口。豫 -o yy2_bs
./yy2_bs 豫言编译器/入口。豫 -o yy3_bs --parallel
./yy3_bs 豫言编译器/入口。豫 -o yy4_bs --parallel
cmp yy3_bs yy4_bs
```

上述命令用于文件式入口的包构建验证；`make 连续自举` 的后两级现经豫构按严格包图构建，启动步骤见[仓库包构建](../../文档/仓库包构建.汉语.md)。专项测试源码为 `测试/标准库/异步/子进程-1。豫` 和 `工具/豫构/调度器。测试。豫`，覆盖大量两路输出、信号与错误状态、重复等待、资源回收、并发上限、依赖顺序、动态任务和失败收拢。子进程测试可在 `ulimit -n 64` 后运行。
