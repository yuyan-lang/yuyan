# 豫构包系统：第一版

`yy豫构` 是用豫言编写的独立可执行工具。包与库合为一个概念；包文件只由 parser 解析，不执行配置代码。

## 包文件与静态配置

`应用。包。豫` 定义名为“应用”的包。文件所在目录就是包根目录，不声明名称、所有者、源码根或库列表。第一版接受两个可选字段：

```text
「依赖」者「列」【
  『基础』，
  「典」【「用户」者『王羲之』也，「包」者『日志』也，】，
】也。
「入口」者『入口』也。
```

入口可以是单个模块名，也可以是路径段列表，例如 `「列」【『程序』，『入口』】`，对应包根目录中的 `程序/入口。豫`。入口名不带扩展名。没有入口的包可以被其他包依赖，但不能直接构建可执行程序。

通用静态配置的键值映射使用 `「典」【……】`：

```text
「选项」者「典」【
  「名字」者『示例』也，
  「启用」者「阳」也，
】也。
```

这是通用配置解析示例；“选项”还不是包描述文件的合法字段。根字段直接书写，不需要外层典。典可嵌套，可带尾逗号，重复字段报错。旧的 `「条目」【……】` 不再接受。此版本不删除语言中的“诵”，但包系统不依赖它，也不自动重新导出任何模块。

## 发现与名称

工具从启动时的 `pwd` 递归发现所有普通 `。包。豫` 文件，先建立索引，再仅解析目标包的依赖闭包。无关包的配置内容不会被读取。每目录只允许一个包文件。

当前项目的包使用短名。通过 `--外部包目录` 指定外部包集合，其第一层目录必须是用户名：

```text
项目/
  应用/应用。包。豫
  基础/基础。包。豫
外部包集合/
  张三/
    日志/日志。包。豫
    基础/基础。包。豫
  李四/
    基础。包。豫
```

包身份是独立的（用户，包名）两个字段，不拼接成字符串。上述索引包含当前项目的应用、基础，以及张三的日志、张三的基础、李四的基础。第一层用户名以下的目录不参与包身份。

依赖列表可以混合字符串与典：字符串相对于声明者的用户解析；典必须且只能包含字符串字段“用户”和“包”。例如张三的日志声明字符串“基础”，会选张三的基础，不会使用当前项目的基础。跨用户依赖使用上述典写法。“的”“之”“氏”均不保留；字符串“张三的日志”只是一个完整短包名，不会拆出用户。名称段不能包含路径分隔符、换行、制表符或单独的点、双点。

相同命名空间内的重名包、同目录多包、自依赖、循环、重复依赖和缺失依赖均报错。不根据发现顺序覆盖包，也不尝试其他所有者。外部目录可位于当前项目内，发现本地包时会排除它；它不能等于或包含当前项目目录。

发现和源码收集跳过符号链接、`.git`、`.yybuild`、`.yybuild.nosync`、`*_v0` 目录，不自动扫描父目录。移动包之后，需仍让其位于发现范围内。

## 模块与边界

```text
寻观「基础」之「深」之「数值」之书。
寻观「日志」之「文本」之书。
```

第一段只写短包名，不写用户名；其余段唯一对应包内目录和 `。豫` 文件。第一条对应基础包中的 `深/数值。豫`。必须声明直接依赖；索引中存在或者被传递依赖引入，都不等于当前包可以导入它。

每个包的可见范围是“自身＋直接依赖”。此范围中出现重复短包名就报错，即使用户不同；不支持别名或在导入处补用户名消歧。不同传递依赖范围内的同名包可以共存，不作整个依赖图的短名唯一检查。

默认递归包含包目录下的普通源码，但遇到子包根目录就停止。包发现仍继续向下寻找子包。不能通过外层包的模块路径越过子包边界，也不能通过符号链接绕过边界。包文件不参与普通模块编译。

不支持省略包名的相对导入，不隐式选择总集。只写包名会报缺少模块名。`总集。豫` 若存在，也只是一个必须显式引用的普通模块。

## 命令

在豫言仓库中执行 `make 豫构` 生成 `yy豫构`。从待构建项目目录运行：

```sh
/路径/yy豫构 发现 --外部包目录 /路径/外部包集合
/路径/yy豫构 检查 应用 --外部包目录 /路径/外部包集合
/路径/yy豫构 定位 应用 基础 深 数值 --外部包目录 /路径/外部包集合
/路径/yy豫构 构建 应用 --外部包目录 /路径/外部包集合 --编译器 /路径/yy4_bs --输出 yy应用 -j 4
/路径/yy豫构 类型检查 应用 --外部包目录 /路径/外部包集合 --编译器 /路径/yy4_bs
```

目标包默认属于当前项目；操作外部目标时使用 `检查 日志 --用户 张三 --外部包目录 /路径/外部包集合`，其他命令同样支持 `--用户`。

“定位”的第一个包是引用者，后面的参数是完整导入名称段。“检查”检查包配置和依赖图，并统计源码，不对源码进行类型检查。

默认编译器是工具同目录的 `yy4_bs`；默认输出是项目目录下的 `yy` 加短包名。构建时切换至编译器所在目录，复用现有编译器的运行时构建支持；第一版要求该目录为完整工具链目录，包含运行时与 Makefile。`PATH` 中的 LLVM 必须与运行时库匹配，尤其不要混用 Homebrew LLVM 与 Apple 的 LTO。

当前标准库和编译器源码尚未整体迁移到严格包导入。旧单文件编译模式继续用于自举；通过豫构构建时，`--package-context` 启用严格模式，不回退到旧模块搜索。

## 上下文、缓存与验证

豫构向编译器传递已解析的包边界和直接依赖。各工作进程共享不可变上下文；编译器不再次调用配置 parser。上下文采用版本二的内部制表符记录，依赖按用户、包名成对保存，拒绝旧版；它不是用户配置格式。

上下文在工具链的 `.yybuild/豫构上下文` 中逐字去重保存，已有编号文件不覆盖。编译缓存按上下文编号隔离。改变包位置、依赖或发现的子包边界会使用新的上下文；普通源码修改仍使用编译器现有的增量检查。

`make 豫构测试` 运行异构依赖列与典解析、包发现与依赖、可见短名冲突、含“的”的结构化身份、子包和符号链接边界、大目录，以及真实构建测试。测试在临时目录创建工程，还会验证导入短名不变而依赖换用户时不能复用旧绑定、移除依赖后不能复用旧缓存，以及移动包目录后保持相同程序输出。

第一版没有远程获取、版本求解、锁文件、发布或依赖别名。
