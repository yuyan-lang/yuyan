# 包管理服务

## 同版本上传修订

包声明版本不变时可上传不同 ZIP。服务器在“所有者、包名、版本”范围内从 1 分配递增的 `revision`（上传序数），每次使用新的发布 ID 和 R2 目录；不删除旧 ZIP、源码、文档或运行材料。完全相同的 ZIP 按 SHA-256 去重复用原 ID/序数，旧 ZIP 重试不成为最新修订。

默认列表仅展示每个包版本的最新修订；市场再按包筛选最近发布的版本。`GET /api/releases/:id` 始终返回该次修订，并给出 `latestId` 和 `historyUrl`。`GET /api/releases/:id/history?offset=0` 按序数倒序分页，每页最多 50 条，返回 `revisions`、`nextOffset`，每条含固定 `downloadUrl`。页面可查看历史及下载旧 ZIP。最新修订登记后立即可见，缺失文件不回退混用旧修订。

上线必须执行 `0007_上传修订.sql`。旧数据保留原 ID，上传序数设为 1；上线迁移和新版容器须协调进行，旧容器不支持新表唯一约束。部署前备份 D1。该迁移不删除 R2 对象，不允许客户端指定序数，也不改变所有者身份验证。

提供软件包管理服务及其存储接口。

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为可执行文件类型，不可被其他包依赖；包内模块仍可互相引用。类型典中的入口和文件名见包配置，程序产物为 `yy包管理服务`。

## 使用

在仓库根目录运行：

```sh
./yy豫构 检查 包管理服务
./yy豫构 构建 包管理服务
```

依赖、原生源文件及说明路径以 [包配置](包管理服务。包。豫) 为准。构建不会自动运行程序；有发布或服务副作用的工具应先阅读其入口源码。
