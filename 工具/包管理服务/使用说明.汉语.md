# 豫言包管理服务

文档由发布者预先生成：在仓库根目录运行 `./yy文档网站生成器 构建包 包文件 发布目录/文档`，将整个目录放入发布 ZIP。生成器复用豫构的包身份和依赖解析，只输出目标包模块；服务不调用生成器。详见[文档生成器说明](../文档网站生成器/包说明.汉语.md)。

## 所有者绑定与单 ZIP 发布

先验证邮箱，在网页“所有者与发布”中绑定全站唯一名称。每个账户一个名称，绑定后暂不可修改；名称为 1–32 个汉字、小写字母、数字、下划线或短横线，不得以“用户-”开头。名称不代表身份认证。现有官方名称“豫言”保留，随机名称账户必须绑定后才能发布。

网页只需选择一个 ZIP；命令行使用同一接口：

```sh
curl --fail-with-body https://packages.yuyan-lang.org/api/releases/zip \
  -H "Authorization: Bearer $YY_UPLOAD_TOKEN" \
  -H "Content-Type: application/zip" --data-binary @发布.zip
```

归档根目录固定为：

```text
源码/
  例包。包。豫
  说明.汉语.md
  说明.文言.md
  …完整源码
文档/
  index.html
  …标准工具生成的文档
构建/
  …独立构建材料
运行/
  …平台运行包（可执行包必须提供）
```

“源码/”直接子级必须恰有一个“。包。豫”。名称、所有者、版本、类型、简介和说明路径均从该文件读取，只调用静态 parser，不执行代码、编译器或构建命令。所有者必须与账户绑定名称完全一致；双语说明文件、文档入口和构建材料必须存在，可执行包还须提供运行材料。尚不验证源码完整性、文档生成工具、构建可复现性或恶意代码，也不递归解开内层构建/运行归档。

支持经典 ZIP 的存储及 deflate 压缩，文件名使用 UTF-8。限制：压缩包 16 MiB，单文件 16 MiB，展开总量 64 MiB，最多 2048 项，包声明 64 KiB。不支持 ZIP64、加密或其他压缩算法。校验 CRC、实际展开长度、中央目录与本地头；拒绝越界路径、重复/冲突路径、符号链接、设备等特殊文件。原生读取器不向文件系统解压，而是逐个展开字节并通过内桥保存到 R2。

身份及基础归档检查通过后即创建公开版本，不等待内容审查。服务器保存原始 ZIP，并依次展开各类材料；发生存储失败时返回 `incomplete: true`，页面仍可查看。重传完全相同的 ZIP 可补齐；同一所有者、包名、版本不允许换成不同摘要的 ZIP。单文件原子写入且不覆盖，无全版本事务、准备/确认步骤或人工发布关卡。

### 接口与隔离

- `POST /api/account/owner`：本站已验证邮箱的登录会话，JSON `{"name":"王羲之"}`。上传令牌不能绑定名称。
- `POST /api/releases/zip`：ZIP 原始字节，Content-Type 为 application/zip；支持本站会话或上传令牌。服务器自行计算摘要，返回 id、url、incomplete。
- `GET /api/releases?offset=0`：最近版本；每页 50 条。
- `GET /api/releases/<编号>`：元数据和已展开文件，按 cursor 翻页。
- `GET/HEAD /api/releases/<编号>/files/<分类>/<路径>`：附件下载；分类为 source、docs、build、runtime、archive。原始归档路径为 archive/发布.zip。
- 旧 POST /api/releases、逐文件 PUT 以及旧 prepare/validate/complete 写接口均关闭，返回 410；旧版本下载保留。

门户 packages.yuyan-lang.org 保持登录，第三方文档只从 usercontent.yuyan-lang.org 提供，iframe 与文档响应均施加 sandbox allow-scripts，不允许 allow-same-origin、表单或顶层导航。内容域没有账户 API，不共享登录 Cookie。附件强制下载，缺失内容不缓存。

### 上线与测试

先备份 D1，依次应用尚未应用的迁移（包括 0005 与 0006），再完整部署 Worker 和豫言容器。0006 增加一次性名称绑定约束和版本归档摘要；历史版本不自动宣称已通过新检查，也不能用不同归档覆盖。此改动不自动执行线上迁移或部署。

`npm test` 检查 Worker、账户、材料桥和网页。`npm run 测试:归档` 通过豫构编译豫言测试入口，使用临时 SQLite、真实 ZIP/parser 验证绑定、归属、自动填充、补传及恶意归档。运行镜像使用 zlib，构建镜像安装 zlib1g-dev。

以下旧接口说明仅作历史协议记录；写接口已关闭，不应用于新发布。

## 结构

```text
上传者 ──准备/验证/完成──> Worker ──> 单例 Container（豫言服务）
   │                                  │
   └────携令的同域 PUT──────────> Worker ──R2 binding──> pending/
                                      ├──内部 HTTP──> D1
                                      └──内部 HTTP──> 同一个 R2 production bucket

下载者 ──匿名 GET /<包名>-<版本>.zip──> Worker ──> D1 + R2 正式桶
```

容器不能使用 SQLite 协议直接打开 D1，也不能直接取得 Worker binding。这里用 `outboundByHost` 截获容器对内部虚拟主机的 HTTP 请求，再由 Worker 使用已绑定的 D1/R2。容器磁盘只作 ZIP 校验的临时空间，不保存状态。

包文件名采用 `<包名>-<版本>.zip`。以最后一个连字符分隔包名和版本；包名可用中文或其他普通文字，版本是一个或多个点分隔的数字，例如 `parser-core-2.zip`、`豫言工具-0.1.0.zip`。同一包名和版本发布后不可覆盖。

## 需要在 Cloudflare 完成的配置

进入本目录并安装依赖：

```sh
cd 工具/包管理服务
npm install
npx wrangler login
```

创建一份 D1 和一个 production R2 bucket：

```sh
npx wrangler d1 create yuyan-package-registry
npx wrangler r2 bucket create yuyan-user-packages
```

上传和正式包都在 `yuyan-user-packages`：待验证对象位于 `pending/`，正式对象位于 `sha256/`。建议给 `pending/` 前缀增加“对象满一天自动删除”的 lifecycle rule，不要对 `sha256/` 设置自动删除。上传经同域 Worker 流式写入 R2 binding，无须 R2 S3 凭据，也无须 R2 CORS。

把 D1 命令返回的真实 `database_id` 写入 `wrangler.jsonc`，替换 `请替换为数据库标识`。

最后迁移数据库并部署：

```sh
npm run 迁移:远程
npm run 部署
```

部署容器时本机必须能运行 Docker，并需已为账户启用 Cloudflare Containers。域名已配置为 `包管理.yuyan-lang.org` 的 IDNA 形式；该域名所在 zone 必须属于同一 Cloudflare 账户。

本服务使用 256 MiB 的 `lite` 实例。现行豫言运行时的默认栈会预留 512 MiB，故镜像与 Container 类都固定设置 32 MiB 栈、4 MiB 初始堆和 64 MiB 最大堆。镜像级 `ENV` 不可删除：它保证 Cloudflare 直接运行 OCI 入口时也取得这些约束，避免内存申请失败后以退出码 139 终止。

## 上传、验证和发布

支持邮箱和密码注册，邮箱验证后才能上传。原“豫言”用户保留，未验证邮箱的旧令牌会撤销。令牌只保存 SHA-256；明文令牌不得提交到仓库。邮箱是登录标识，不表示已经验证邮箱所有权。

以下示例使用 ASCII 包名以免 shell 的 URL 编码掩盖协议本身；中文包名需先按 UTF-8 对文件名这一 URL 段进行百分号编码。

```sh
REGISTRY=https://包管理.yuyan-lang.org
FILE=parser-core-2.0.zip
TOKEN='在此填入上传令牌'
SHA256=$(sha256sum "$FILE" | cut -d ' ' -f 1)
SIZE=$(wc -c < "$FILE" | tr -d ' ')

PREPARED=$(curl --fail --silent --show-error \
  --request POST "$REGISTRY/upload/prepare/$FILE" \
  --header "Authorization: Bearer $TOKEN" \
  --header "X-Package-SHA256: $SHA256" \
  --header "X-Package-Size: $SIZE")

UPLOAD_PATH=$(printf '%s' "$PREPARED" | jq -r .uploadUrl)
curl --fail --request PUT "$REGISTRY$UPLOAD_PATH" \
  --header "Authorization: Bearer $TOKEN" \
  --header 'Content-Type: application/zip' \
  --header "Content-Length: $SIZE" \
  --header "X-Package-SHA256: $SHA256" \
  --upload-file "$FILE"

# 可选：只验证 production bucket 中的 pending 对象，不发布。
curl --fail --request POST "$REGISTRY/validate/$FILE" \
  --header "Authorization: Bearer $TOKEN"

# 校验通过后复制到正式桶，并原子登记 D1 版本。
curl --fail --request POST "$REGISTRY/upload/complete/$FILE" \
  --header "Authorization: Bearer $TOKEN"
```

准备接口返回同域上传路径。数据 PUT 必须再次携带发布者 Bearer token；Worker 先请豫言服务核对待发布记录，再把请求体直接流入 R2 binding。完成接口重新读取实际对象，核对大小、SHA-256、ZIP CRC、条目路径、条目类型、条目数（最多 2048）和总解压大小（最多 50 MiB）；符号链接与特殊文件会被拒绝。压缩文件本身最多 10 MiB。

下载不要求认证：

```sh
curl --fail --remote-name \
  https://包管理.yuyan-lang.org/parser-core-2.0.zip
```

## 本地检查

```sh
npm test
npm run 测试:豫言
```

`npm test` 会打包 Worker（不构建容器）并运行云桥单测。完整容器构建使用 `容器构建文件`：它校验自举包摘要、自举当前编译器、生成 `yy包管理服务`，然后放进最小运行镜像。连续自举包更新后，应审阅其来源并同步更新构建文件中的 SHA-256。

## 开源边界

本目录适合开源。仓库中允许存在 D1 schema、bucket 名和高熵令牌的单向摘要；不得提交账户凭据、明文上传令牌或 `.dev.vars`。若明文令牌曾泄露，应生成新令牌、只把新摘要写入 D1，并停用旧记录。

## 邮箱账户与第三方发布

包管理首页提供注册、登录、退出、生成及撤销上传令牌。注册只需邮箱和密码，邮箱去除首尾空格并按小写比较；密码至少 15、最多 128 个字符，不裁剪密码。没有邮件验证、邮件找回或第三方登录；不要依赖未经验证的邮箱证明身份。公开名称自动生成，不使用邮箱作为公开名称。注册必须接受当前版本的内测条款和隐私说明。

密码使用随机盐和 PBKDF2-SHA256（100000 次，适配 Workers Web Crypto）派生后保存；不保存明文。会话令牌随机生成，数据库保存摘要，Cookie 使用 Secure、HttpOnly、SameSite=Strict，七天到期；重新登录撤销以前的会话。上传令牌仅生成时返回明文，不写入浏览器持久存储。生成新令牌会撤销当前用户的全部旧上传令牌，退出登录不撤销 CLI 上传令牌。

账户接口位于 `/api/account/`：GET `session`；POST `register`、`login`、`logout`、`token`、`revoke`。POST 使用同源 Origin 与 JSON，请求体不超过 4096 字节。注册字段为 `email`、`password`、`acceptTerms: true`、`termsVersion: "2026-09-07"`。按 IP 和邮箱摘要限流，注册每来源十分钟最多五次尝试；摘要仍按可能关联个人的信息处理。过期会话和限流记录在后续账户写请求中清理，不保证定时删除。

登录后生成上传令牌，沿用上文准备、上传、验证和完成流程。首次成功准备上传即保留包名；后续只有包所有者可以准备或发布版本。待上传记录、数据 PUT、验证和完成都校验当前发布者；数据库触发器阻止并发请求越权登记。未发布的保留包名不自动释放，内测期间可通过人工联系处理。

### 发布顺序

先备份 D1 并检查 `0002_邮箱注册.sql`。该迁移保留旧数据、去除单用户限制，加入账户、会话、限流表及所有权触发器；上线前先在本地应用和验证。必须完整部署更新后的豫言容器与 Worker，不能使用 `--containers-rollout none` 仅更新 Worker：旧容器将发布者固定为用户 1，与多用户规则不兼容。

本地测试：`node --test 测试/*.test.js`（需要支持 node:sqlite 的 Node.js，推荐 24 或更新版本）。配置检查：`npm run 检查配置`。数据库迁移：`npm run 迁移:本地`；线上迁移及 `npm run 部署` 由操作者手动执行，本次代码修改不自动发布。固定自举种子必须支持当前完整包元数据；旧种子提示未知字段时应先更新经过摘要校验的工具链，不得跳过校验。

开放注册前同步仓库外的隐私说明：新增邮箱、密码派生值、随机显示名、条款接受记录、七天会话和限流处理；删除“公众注册尚未开放”的旧描述，并明确账户注销和删除请求通过既有隐私联系邮箱办理。条款正文仍不进入公开仓库。

## 发布者验证标识

迁移 `0003_发布者验证.sql` 新增用户验证状态，普通账户默认 `unverified`；只将已有编号 1 且名称为“豫言”的官方账户初始化为 `verified`。不根据邮箱、用户提交的字段或包名称自动授予标识，当前没有用户自助验证接口。此状态与邮箱是否经过验证无关，注册发送邮箱验证邮件，邮箱验证不授予身份认证标识。

账户面板显示自己的状态。按完整 ZIP 文件名查询包时，`GET /api/packages/<文件名>` 返回包及实际发布者的 `verification`，不公开邮箱；页面显示发布者名称和标识。包状态随该版本发布者的当前验证状态变化，不表示代码、安全或许可证已通过审核。查询使用 no-store，以便未来验证状态变更及时生效；原 ZIP 下载接口保持不变。

上传 Access Token 的权限固定为 `packages:upload`，仅用于本人有权管理的包的准备、PUT 上传、验证及完成发布；不能用于登录、读取账户资料或管理令牌。令牌生成接口必须使用登录会话，返回的 `scope` 仅描述服务端已授予的范围，客户端不能扩大权限。

## 邮箱验证与密码重置

先应用迁移 `0004_邮箱验证与密码重置.sql`，再部署新版 Worker 与容器。邮箱未验证时，不能生成上传令牌，也不能使用旧令牌准备、上传、验证或完成发布。迁移撤销所有尚未验证邮箱的旧令牌，包括未绑定邮箱的旧官方服务账户；官方身份认证不豁免邮箱要求。旧官方账户需由维护者为其绑定实际控制的邮箱账户并完成验证后，才可重新生成令牌，不能直接修改邮箱验证字段代替验证。

Cloudflare 控制台中开通 Email Sending 并验证 yuyan-lang.org 的 DNS；配置内的 EMAIL send_email binding 仅允许 noreply@yuyan-lang.org 发信。Email Routing 的收件转发功能不能代替面向注册用户的发信功能。

POST 接口：resend-verification（需登录）、verify-email（仅需邮件 token，无需登录）、forgot-password（email）、reset-password（token、password）。注册自动尝试发送验证邮件，失败时保留账户并允许登录后重发。验证链接有效 60 分钟，重置链接有效 30 分钟；打开验证链接后，页面自动提交验证，无需登录或二次确认；重置密码仍需输入新密码并提交。链接凭据只保存摘要，前端读取 fragment 后立即清除地址栏中的凭据。可跨设备直接验证，验证不会创建登录会话，也不会验证当前浏览器内其他账户。

重置密码证明邮箱控制权，并撤销该账户所有旧会话、上传令牌及邮件链接。密码更新与撤销在同一事务完成；重放无效。找回密码对不存在的邮箱返回相同提示。发信按邮箱每十分钟三次、全站每十分钟一百次限流，另受账户请求来源限流约束；投递失败也计入限流。

邮箱验证状态仅向账户本人返回 emailVerified。公开 verified / unverified 是独立的真实身份认证（例如经审核的企业），不能通过验证邮箱获得，不表示包的代码安全性。

## 包市场与个人管理

首页 `/` 是公开包市场，按所有者与包名展示最近发布版本，支持搜索和分页；`/release/<编号>` 展示公开版本详情，文档与源码在主站统一阅读。`/个人` 集中登录、邮箱验证、令牌、所有者绑定与 ZIP 上传。“我的包”使用 `GET /api/releases?mine=1`，服务端按会话用户过滤；无会话返回 401。市场使用 `catalog=1`，搜索参数为 `q`。旧首页上的验证与重置链接会携带原 fragment 转到个人页。

## 豫言阅读页面

公开版本的概览、文档目录与文件页面由容器中的 `页面渲染。豫` 生成。Worker 只读取既有公开接口与 R2 材料，向内部渲染端点传送数据；外部不能调用内部端点。网页不再用市场脚本拼装阅读内容。

文件树仅展示源码中的 `。豫` 文件，包定义也包含在内；存储前缀不作为包目录展示。文档与源码共用文件树，通过普通页面链接切换。包说明使用 `安全文档。豫` 渲染固定的 Markdown 标签，原始 HTML 转义显示，链接协议受限。旧上传 HTML 不直接插入账户站点。

阅读页面按修订、路径、模式和语言短时缓存；旧文档映射适配结果按修订缓存，失败不缓存。此变更不需要数据库迁移，也不重写发布 ZIP。部署时需要同时更新豫言容器、Worker 和样式资源，不能只部署 Worker。
