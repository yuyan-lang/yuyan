# Wasm 编译器自举验证

使用完整编译入口按相同输出文件名生成后，三级与第四代产物逐字节完全一致（cmp 返回 0），确认达到固定点。

2026-09-08，macOS arm64 / Apple M5 Pro。**Wasm 编译器已能编译自己的自举后继编译器**：二级生成三级、三级生成四级，均完整执行编译与链接并退出 0。

三级、四级原始模块仅在 name 自定义节的输出名“三级／四级”三个 UTF-8 字节上不同；代码、数据及其他全部字节一致。摘要与逐字节差异记录见《验证记录.json》和《../../性能研究/网页汇编比较/宿主自举记录/固定点比较.json》。两代约 10.45 MiB。

## 自举时间

| 测量 | 墙钟 | 用户态 | 内核态 |
| --- | ---: | ---: | ---: |
| Wasm 二级 → 三级 | 230.06 秒 | 684.07 秒 | 181.81 秒 |
| 带栈检查的 Wasm 三级 → 四级 | **369.11 秒** | 1219.72 秒 | 161.05 秒 |
| 同版本原生编译器 → 原生后继 | **62.72 秒** | 193.29 秒 | 45.41 秒 |

最终 Wasm 样本约为原生的 **5.89 倍耗时（增加约 488.5%）**。两者各一次、4 个 worker、独立运行、新编译器缓存并指定 `--do-not-load-cache`，没有清空操作系统文件缓存。Wasm 的计时从加载可信 AOT 编译器开始，到下一代 `.wasm` 链接完成；种子的 AOT 预编译另为 0.40 秒。计时包含编译器启动、宿主、子进程、LLVM 和链接，不是单独测量 Wasm 指令执行成本。原生 LLVM 为 22.1.7，WASI SDK 34 的 LLVM 为 23.1.0。

二级本身尚未包含新生成器插入的栈检查，三级包含；两代运行条件也并非严格隔离实验，不能把两次时间差全部归因于检查。正式性能结论采用 369.11 秒，未用 230.06 秒代替。此前 119.77 秒属于旧实验；本表使用本次同版本直接入口对照。原生直接入口需传豫构原生链接清单，漏库或清单格式错误的两次失败计时均作废。

## 复现命令

这些是本检出的实际路径；新检出需经豫构生成包上下文和原生归档。宿主构建与种子准备见《说明.汉语.md》，过渡种子处理见《自举修复.汉语.md》。

```sh
./yy网页汇编宿主 --预编译 yy_自举网页三级.wasm yy_自举网页三级.cwasm
/usr/bin/time -p ./yy网页汇编宿主 --运行预编译 yy_自举网页三级.cwasm \
  豫言编译器/入口。豫 --package-context .yybuild/豫构上下文/17.上下文 \
  --target=wasm --parallel -j 4 --do-not-load-cache -o yy_自举网页四级.wasm
/usr/bin/time -p ./yy_自举对照原生 豫言编译器/入口。豫 \
  --package-context .yybuild/豫构上下文/17.上下文 --parallel -j 4 \
  --do-not-load-cache --native-link-inputs "$PWD/yy_自举原生链接清单" -o yy_自举对照后继
```

原生清单首行为 `豫构原生链接二`，第二行为本检出 `.yybuild/豫构原生/3.上下文/包原生.a` 的绝对路径。为再次测量新缓存，应复制或 touch 运行中的编译器种子，避免误用同一身份的已有产物。

## 修复与验证

修复了小栈先写后验造成的堆破坏、编译宿主线性内存上限不足，并增加动态堆分配界限检查。编译宿主使用 512 MiB 豫言栈、64 MiB 初始堆、512 MiB 单堆上限和 4 GiB 线性内存上限。详细证据及六项通过的内存回归见《自举修复.汉语.md》。宿主畸形参数、内存及句柄边界测试也通过。

原生按仓库要求完成三级、四级自举，产物逐字节一致，完整类型检查成功。旧 `yy_bs_stable` 的规定首级命令已执行并去除重定向复跑，因不支持当前包布局而找不到标准库；首级改用当前编译器经豫构生成二级，后续规定命令成功。旧 `./yy` 也有包布局问题，新 `yy3_bs` 类型检查成功。原生性能对照使用显式包上下文，其产物不作为不同上下文的原生三级字节比较依据。

此前宿主参数、异步子进程（文件描述符上限 64）、普通 WASI 基础输出与无宿主进程调用失败回归均通过；原始历史失败日志仍保留用于追溯，已不代表当前状态。新增内存路径通过 WASI C 语法检查，`git diff --check` 通过。

这项结果证明豫言编译器在 Wasm 中可自举，但当前仍通过显式宿主执行原生 clang/wasm-ld；尚未把整个工具链迁入 Wasm，也尚未实现 Component Model 的 WIT 接口。

第四代 Wasm 编译器的完整类型检查通过（508 个步骤）。两个新增默认用例也在普通 Wasmtime CLI（关闭模块缓存，未启用宿主桥接）中分别输出 500500 和 42；随后已恢复桥接运行时归档。
