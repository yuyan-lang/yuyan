# 中文网页汇编整数核心验证

日期：2026-09-21。平台：macOS ARM64。此次验证的是架构首批整数子集，不能据此宣称完整 WasmGC、无宿主工具链、裸机系统或运行性能目标已经完成。

## 已完成

- 原生编译并运行「整数核心。测试。豫」通过：中文与二进制往返，手写中文及注释，正负常量边界，多结果，局部初始化/写入/暂存，回绕加减乘，导入回调，预算与递归限制，畸形输入，包含零字节的名称，以及一万条指令的往返。
- 命令行验证、编码、解码、规范化、执行通过。手写求和模块接收二十与二十二，返回四十二；规范文本与二进制读回文本相同。
- V8 标准引擎验证生成模块，并检查六个导出：求和、调用导入、溢出、负数、双返回和局部。
- 独立按标准字节构造外部模块：它导入豫言的二元求和，导出一元翻倍；豫言模块导入此翻倍。运行时调用链为豫言 → 外部模块 → 豫言求和。装配使用宿主转接函数，没有把循环实例化当作已实现功能。一千组确定性随机输入与三十二位预期结果相符。
- 外部模块读回中文并重编码后再次调用，输入二十一得到四十三。
- 对四十七字节求和模块的每个字节分别替换为零和二百五十五，共九十四项。新读取器接受十一项、拒绝八十三项；接受项全部通过标准引擎验证。此为有限差分测试，不代表完整验证器正确性证明。
- 编码失败时原有输出文件内容保持不变。
- 新增测试程序本身经既有 WasmGC 后端编译，在现有 Wasmtime 宿主下全部通过。说明这些豫言模块可以经过 Wasm 执行，不意味着已实现自研完整 WasmGC 引擎。
- 按仓库要求完成三阶段原生自举，第三、第四代逐字节相同，且与此前记录的固定点散列一致。原入口、自举后入口及新工具的类型检查均通过。

```sh
./yy3_bs 库/编译器核心/网页汇编核心/整数核心。测试。豫 --target=wasmgc -o yy中文网页汇编测试.wasm -j 2
./yy网页汇编宿主 yy中文网页汇编测试.wasm
```

自举使用仓库规定的三个命令，再比较第三、第四代文件；没有把新增工具作为既有生产编译器的依赖，也没有改变其代码生成语义。

## 已知限制与后续

当前 Node 构建宿主缺少「豫言_字节串_单字节」原语，因而不能直接运行整套自编译测试程序；同一测试在现有 Wasmtime 宿主通过。此限制与生成的标准整数模块能否在 V8 运行是两件事。

尚需扩展完整类型栈、结构化控制流、内存与 WasmGC，接入生产生成路径，并实现标准特性清单、模块装配、系统约束及独立机器码后端。ARM64/AMD64 裸机和微内核在架构阶段之后开展。本批没有性能提升结论，也没有开始删除 LLVM/libc。
