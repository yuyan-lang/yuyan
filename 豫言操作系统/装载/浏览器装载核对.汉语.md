# 浏览器接口装载核对

装载器先比较应用要求和宿主提供的接口清单、签名及规范摘要，然后检查 Wasm 只有 `yuyan:gc-host/v1.call` 一个函数导入且导出 `_start`。

部分 Safari 版本能编译模块，却在 `WebAssembly.Module.imports` 或 `exports` 读取模块表时抛错。浏览器入口现在把用于编译的原始字节同时交给装载器；仅当模块表 API 抛错时，装载器解析同一 Wasm 字节的导入节和导出节执行等价检查。正常可读取模块表时仍使用原 API，检查不通过不会转入回退。实例化阶段只提供固定导入，并再次检查 `_start` 可调用。

真实 Safari 上线复载后，旧的 `Module.imports unable to produce import descriptors` 错误不再出现；当前共享界面仍因该 Safari 缺少 JSPI、请求文字能力返回 Promise 而不能启动。静态导航保持可见。完整异步界面需要另建无 JSPI 的续执行路径。
