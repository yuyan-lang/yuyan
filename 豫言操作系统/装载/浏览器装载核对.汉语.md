# 浏览器接口装载核对

装载器先比较应用要求和宿主提供的接口清单（身份、依赖、方向与签名），然后检查 Wasm 的导入与导出：程序须带自定义段「豫言边界」，每个导入都是函数导入，并且是「豫言边界」里有签名、导入模块为标准库、构建基础、平台接口包（`接口核对.mjs` 的 `平台接口包们`：云工宿主、浏览器宿主、诺节宿主、中央张量宿主、系统库调用、安全外壳密码）或应用要求的接口包的带类型导入，不合的导入一次列全报出；并且导出 `_start`。工具模块与平台接口包，宿主没有实现的给桩，调用时才报错；应用要求的可移植接口（豫言操作系统…）须由宿主全部实现：调用方传入 `带型实现`（宿主的带类型导入实现表）时核对，缺的函数一次列全报出。调用方传入 `应用提供`（应用提供的接口清单组，如启动）时，其中方向为“应用”的每个函数都须有导出 `接口名称/函数名`（见网页汇编接口网五），缺的一次列全报出。

部分 Safari 版本能编译模块，却在 `WebAssembly.Module.imports` 或 `exports` 读取模块表时抛错。浏览器入口现在把用于编译的原始字节同时交给装载器；仅当模块表 API 抛错时，装载器解析同一 Wasm 字节的导入节、导出节与「豫言边界」段执行等价检查。正常可读取模块表时仍使用原 API，检查不通过不会转入回退。实例化阶段只提供固定导入，并再次检查 `_start` 可调用。

真实 Safari 上线复载后，旧的 `Module.imports unable to produce import descriptors` 错误不再出现；当前共享界面仍因该 Safari 缺少 JSPI、请求文字能力返回 Promise 而不能启动。静态导航保持可见。完整异步界面需要另建无 JSPI 的续执行路径。
