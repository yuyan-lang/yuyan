# 豫言双架构裸机之始

## 今之全系（先阅此）

豫言操作系统今为可启、可交互、有持久文件系统之双架构多核系统，ARM64 与 AMD64 皆于 QEMU 通过自动验收，亦已启于实体之机：

| 层 | 所载 | 文 |

**构与行**（于仓库根目录、已装 QEMU）：

系统之构依底层执行器之模块型择读取之途；含 f32、f64 局部型者，用裸机后端之数值转译（与编译器径出原生之产所用者同）而造镜。

```sh
./豫构。林檎。豫行 目标 造盘工具 -j 24
./豫言系统。林檎。豫行 运行 --架构 兼容六十四      # 造启盘而 QEMU 自 U 盘引之，交互；缺省带示例程序；壳中书“退出”以终，Ctrl-C 断所行之程序，卡死则按 Ctrl-A 继按 X 强止
./豫言系统。林檎。豫行 构建 --预置 某目录树       # 唯造二架构之启盘（八核以上二子进程同时造，各在输出下以架构名为名之子目录），不行
```

「造盘工具」之目标并生原生之工具链，由原生豫构径出本机之造盘器 `豫言系统。林檎。豫行`。造盘器默取 `./豫构。林檎。豫行`（`--构`）与 `./编译器。林檎。豫行`（`--编译器`）；无 `./编译器。<系统>。豫行`、亦无 `编译器.wasm`，则退用 `--构` 之豫构以编译（豫构自具编译器，提案〇〇〇〇七合一），印一行“没有 …，改用 … 编译”。造盘器不入宿主之行在（提案〇〇〇三九）：入口携 `豫言行在=关` 以 `/usr/bin/env` 重起自身一度，自环境中去 `豫言附庸`、`豫言行在目录`，本程与其所起之豫构、QEMU 皆依宿主之径读写，`--输出` 指于工作树外之目（如家目下之草稿）亦读得回。曾用之工作树造盘则省 `--不连带`，令目标先易 `豫构` 与 `编译器` 为今源自举之定点版；带 `--不连带` 则用树中已有之工具链（CI「系统公测发行」之作如此，起步之包与源同世）。第五步预编前导核宿主 `豫构` 与盘上 `/工具/豫构。豫行` 之摘，二者皆取今源自举之定点版。于 `git worktree` 之工作树造盘亦可：`.git` 为文者，版本索引在主仓之 `.git/worktrees/<名>/`；造盘器先拷入 `.豫构缓存/版本索引.<抽数>` 乃读，读毕焚之。「启动光盘」之目标（`./豫构。林檎。豫行 目标 启动光盘 -j 24`）并造盘器，造二构之启动光盘（预置空、带工具链）：`启动光盘/豫言系统-兼容六十四.iso` 与 `启动光盘/豫言系统-臂六十四.iso`，CI 取之发为发行之物。Windows 之原生工具链待后版，今以 `node 豫言操作系统/宿主/节点/宿主.cjs` 行 `.wasm` 之版。

**造双路启动 U 盘（x86-64）**：尽以豫言为之，引导之程与 ISO 之构皆豫言生之（见下「自有之引导」）：

```sh
./豫言系统。林檎。豫行 启动盘 --输出 启动介质 --预置 无
```

**开机与桌面**：两构启盘共用 `应用/豫构/开机。豫`。编译器以 `--目标 本机 --目标系统 豫言 --开机程序 --执行器 …` 自源码径出开机豫行，置于第三模块 `boot/开机程序`。共用核之 `开机装载。底层。豫` 读段表，依按段装载之理立数据、代码与四兆之栈，自文件入口行。壳入「图形」则入用户态桌面，文楷为第二模块随盘（`boot/字体/文楷.ttf`，核务三十四、三十五，见[帧之务](文档/帧服务.文言.md)）。行盘上豫行之文，执行器读其段表，以核务四十三立独立之任务，工具栈百二十八兆。址布见[豫行之式](文档/豫行格式.文言.md)，任务装载见[动态任务](文档/动态任务.文言.md)。

**多核（二〇二六年十月七日）**：兼容之核开机启诸处理器核（xAPIC，至多二百五十七），印“处理器核：N”；核内一大锁，任务分于诸核而并行，无可行者之核于核内开中断而止。制见[多核](文档/多核.文言.md)。

```sh
./豫言系统。林檎。豫行 启动盘 --输出 启动介质 --预置 无
```

**系统内之工具链**：启盘缺省带工具链（十月十四日起；加 `--不带工具链` 乃不带，其盘之壳诸句皆不能行），`/工具` 置编译器之本构豫行 `豫构`、`编译器`、`豫言系统`、`格式化`，并执行器汇编树码 `执行器。树码`。带工具链之盘，除 `豫构` 外诸器编为引用式清单（`--引用清单`）：`/工具` 惟置清单之文，单元依内容之摘置于 `/单元/`（同摘惟存一份，诸器共之）；`豫构` 自为静程，因盘上之清单由之而装，其行清单之器时依摘取单元于 `/单元/`。豫构依此树码并降新程与执行器为机器码，`构建`、`文件` 默书豫行。宿主预编前导之盘（十月十四日起），`/源` 惟置壳所用之源：标准库与壳命令二包之全文、仓中每包之目之包述与说明之文（寻包须核包含之系），及可执行包 `/源/你好`；阶段缓存惟置前导诸模者，前导与壳命诸部之单元预编入盘，系统中惟编用户所入之句。加 `--全仓源码` 则 `/源` 含版本所管之全仓：宿主依 Git 索引取文，复依其序书路径清单于 `/源/源码清单`，系统中造盘因其清单，隐文及诸文之序皆同；系统中造盘与远程开发须此盘。执行器于用户态读豫行段表，以核务四十三「按段建任务」装之；编译器工作之进程及其子进程，由初始任务代访文件。予 `--工具目录`，目标架构同者复用豫行之器，交叉之目标则自源码重生其器；复用现成清单器时，所引之元依摘取于器目旁之 `单元/` 或共储根下之 `单元/` 而入盘上 `/单元/`，取不得则于造盘时告祸而止，明其所缺与补之之法（议二八七）。见[客体二号](文档/客体二号.文言.md)与[动态任务](文档/动态任务.文言.md)。

```sh
./豫言系统。林檎。豫行 启动盘 --输出 启动介质 --盘容量 16777216
```

**预编前导（二〇二六年十月十三日）**：宿主带工具链造盘，豫言系统依盘内之 `/源`、`/工具` 于仓根之 `.豫构缓存/预编前导根/架构名` 下布一树（`/源` 置与盘同之源文，`/工具` 置宿主豫构与盘上之执行器），以之为虚根（客体二号之环境 `豫言根目录`）而行宿主豫构之 `预编前导`，为盘之目标架构编豫构交互之前导单元，乃以 `/工具/.豫构缓存` 下本摘要之编译缓存与 `豫构上下文`、`/源/.豫构缓存` 下之 `交互外部包` 与 `单元运行` 置于盘（约增十六兆）。开机壳见前导单元已编，则读首句前即装之，新盘之首句不复于系统中编前导。宿主豫构与盘上 `/工具/豫构。豫行` 须同源而编（客之摘要同）；摘要不同或预编败（前导或一部未成），则造盘告祸而止（十月十七日起）；`--不预编前导` 则不为此步。八核以上二构同时造盘，父进程先编执行器、内核，并一次编毕二构合编诸程之前端、存诸程之链参，二子进程惟链本构之程（`豫构 链接`），同时预编前导；链之并行数依物理内存而定（十月十七日）。系统内造盘不预编。

**以光盘之文径作盘用（十月二十二日）**：`--只出光盘` 所造之 ISO 与发行所传之光文，惟含数据区非零之前段，其后惟多一兆，小于盘上文件系统所言之容。接为 USB 存储之器而启，则挂载印“数据盘只有 N 个块，比文件系统小：写入只留在内存，关机即失；要持久请把光盘写进 U 盘，或把镜像扩成整盘”：所书皆留于内存（盘上旧有之字节一不易，未书之块依旧读之于盘），所书之块读之可得，关机则失，再启之状如初。欲存其文，先扩镜而后启（如 `truncate -s 8g 镜像` 或 `truncate -s +8G 镜像`）；书于真 U 盘则数据区至 U 盘之末，无所碍。合镜（`豫言启动盘.img`）亦然：径作盘用，则所书亦惟留于内存。

**安装于内盘**：臂与兼之启盘皆载 `/工具/安装系统。豫行` 与桌面程序 `/工具/桌面程序。豫行`（桌面每窗独立为任务）。独立安装程与开机程共六十四位址之执行器。于壳或桌面终端入 `「安寓」`，程列内置 NVMe、AHCI 硬盘之号、控器、型号及容量；每 NVMe 控器列其首个可用之名域（VMware 以 `nvme0:N` 之盘为名域 N+1）；不见可装之内盘，则告误而以退码一终。入目标盘号，复入数字再确之：初则 `1` 为否、`2` 为是，次则 `1` 为是、`2` 为否；再皆择是，则覆其全盘，他入则止。复制与读回核验之际，每成十分之一则书一行以示其进。引导程传 MBR 签以识启动盘，列盘除之，整盘写务亦核其身。USB 与光盘皆可为安装之源；惟有 EHCI 之机（如 ThinkPad E40），U 盘经增强主控（二架构共用之底层豫言驱）逐扇读写，亦挂数据区而为安装之源。SATA 硬盘须于固件之设择 AHCI 之式乃见列。旧 BIOS 之启，固件或留未用之内盘于低耗；内核先醒存储之控器（置 PCI 电源为 D0，并补回转时或为器所复位而清之 BAR 与命寄存器），AHCI 复给口上电起转、请其活跃而候链通，故固件未配之盘亦得列焉。

程以一兆为段，复制启介之 ISO 与数据区，止于末个已用之块；同步而逐段复读，核沙256，复生新 MBR 盘签，末写第零扇并验之；乃就地扩数据区至目标盘尾（十月十四日，见[客体文件系统](文档/客体文件系统.文言.md)之“扩容”；二 TiB 以上惟用其前二 TiB）。成则拔 U 盘或光盘而复启。内盘循同一 BIOS MBR 与 UEFI ESP 引导，文件系统挂启动盘之全数据区。两构默置数据区八吉，启介须九 GB 以上，目标盘须容引导区并全数据区。早装之八吉数据区以壳命令「扩数据盘」扩至全盘，以「磁盘态」观器容与其用。后版之事：为须手录之固件添 UEFI 启项，并列同 NVMe 控器之余名域。

**联网更新（二〇二六年十月二十一日）**：`「查更新」` 取更新之源上之发行清单（`SHA256SUMS`），依本机之构求光盘，印今版（读 `/系统/版本。数据。豫` 之「版本」）、最新之版与有无新者；惟读网与版文，不下光盘、不改盘。`「葺寓」` 无参则联网而更：自源取 `SHA256SUMS` 与 `SHA256SUMS.sig`，以盘上公钥 `/系统/更新/发行公钥`（三十二字公钥之小写十六进）核清单之 Ed25519 签，乃下光盘于数据盘 `/更新/`（每十之一印一行），核其沙256，过乃循上段写槽之程；签或散不合、下之有过，则删所下而告祸，不书槽。予目录之旧法如故。`「设更新来源」于「址」曰『https://…/』` 书源于 `/系统/更新/来源。数据。豫`（顶名「来源」，末不以斜终则补之）；无此文则用语言仓最新正式之发行 `https://github.com/yuyan-lang/yuyan/releases/latest/download/`。源许 `http://`（签保其完，试则用之）。造盘加 `--发行公钥 文件` 则书其公钥于盘上 `/系统/更新/发行公钥`，无则用仓中 `豫言操作系统/裸机/发行/发行公钥`。`豫言系统 生成发行钥 --输出 目录` 生 `发行私钥` 与 `发行公钥` 二文；`豫言系统 签发 清单 --钥 私钥文件 [--签 签名文件]` 依清单原字签出六十四字（缺则书 `清单.sig`），清单与签以 ASCII 为名。CI 之系统发行作算得 `SHA256SUMS` 之后，有密 `YY_OS_SIGN_KEY` 则签之，无则越之而示警。下前先以 HEAD 取远盘之 `Content-Length`，与数据盘剩字（任务监测之「问数据盘」：闲块乘块长）相较；不足则书“空间不足（要 X MiB，剩 Y MiB），不去下载。”，不下不书槽。删旧下而文不在者不为过。后版之事：真续传与逐段进度须 HTTP 库开 Range；光盘一次读入内存。

**系统双槽与更新失败之自回退（二〇二六年十月十四日）**：「安寓」所装之内盘有二系统槽：盘首为安装之源之系统部（引导程序与旧之内核诸模），其后为二槽区各一吉，数据区居二槽区之后，仍扩至盘尾；目标盘不容二槽区（较单槽多须二吉）则单槽而装。二千四十八与二千五百六十字起为二槽之引导表，第六扇（三千七十二字）为槽录：主槽、试启槽、本次所启槽、本次试启、二槽区与数据区之位、二槽之版本之说（来源加系统部摘要之前八位：系统部每一兆一段之沙256 相接而复取其沙256，同一镜装之与更之皆同）。「葺寓」以新镜之系统部书于不用之槽，引导表之盘偏加槽区之始而书于其表位，乃记试启槽为之；镜之引导表之构异于本机、系统部不容于槽区、或今启为未确之试启，则拒。引导程序（BIOS 第二级、BOOTX64、BOOTAA64）见试启槽则先清之书回，乃启之；开机壳行开机自启诸句之后（远程登录已于后台启），自行「确认系统槽」，记新槽为主槽。未确而重启（含断电），引导程序启旧主槽；试启时内核至死错之停机处（裸机核验失败、开机程序退出，及多核时开机程序终）则径重启，坏之新系统不待人至而归旧系统。试启时系统卡死，须断电重启，重启亦归旧系统。「系统槽状态」印二槽各为何版、孰为主槽、今启何槽、有无待试启；「回退系统」切主槽于他槽，次启乃效。内核取数据区之始于槽录。旧版所装之单槽之盘，「葺寓」仍改其系统部，并告一言；以新版 U 盘重装则有二系统槽。「葺寓」于盘首之部惟书槽区、槽之引导表与槽录（槽录待 `/新版` 暂存书齐乃书），引导程序之新以 U 盘重装。后版之事：单槽之盘书半断电之回退；新版之 `/源` 与 `/工具` 既易而新系统未确、归于旧槽，则旧系统仍用新版之二树；兼之引导表盘偏四字，槽区须居盘之前四吉。

**关机与重启（十月十三日，开放硬件驱动第九步）**：壳命「息」「更始」经设备接口之「息」「更始」（执行器之原语二百四十一、二百四十二）请核行硬件之事（核务六十七、六十八，核之模 `电源。底层。豫`）。兼读 ACPI：于 EBDA 与 BIOS 高区寻 RSDP，UEFI 启则复扫引导所交 Multiboot 内存表之 ACPI 可回收与 NVS 之段；由 XSDT 或 RSDT 得 FADT，关机则书 PM1a、PM1b 之控制寄存器（休眠之类取诸 DSDT 或 SSDT 之 `_S5_` 包），重启则依次用 FADT 之重置寄存器、端口 0xCF9 与键盘控制器；无 ACPI 之表则关机试 QEMU 与 VirtualBox 之旧端口。臂由 PSCI 之 SYSTEM_OFF、SYSTEM_RESET（核原语「超管调用」，hvc #0）。成则机断电或复位，命不复返，不能则返“错误：…”；动手之前核于控台印一行诊（如 `PWR OFF ACPI 0604 00`，式见模之注），实机不成则凭之以知所行之路。用户之数据先由呼者刷盘（文件系统直写，事务提交处已刷新）。QEMU 验收（不加 `-no-reboot`）：两构启光盘入命令壳，输入「息」则 QEMU 自退；输入「更始」则串口再见“命令壳已就绪”而 QEMU 仍行。兼于 KVM 之 BIOS 与 UEFI（OVMF）、臂于 hvf 皆过。

**UTM 与键盘（二〇二六年十月六日）**：于 UTM 4.7.5（QEMU 10.0.2，UEFI，IDE 光驱）实试，入桌面。UTM 默闭 i8042，接 usb-kbd、usb-tablet 于 `-usb` 之 ICH9 EHCI/UHCI（别有一 qemu-xhci，惟供 USB 之转），内核驱 PS/2、xHCI 上之 HID 键盘及增强主控（二〇二六年十月十三日起）所管 EHCI 之高速设备，UHCI/OHCI 伴随控制器上之全速键盘尚无驱（待办事项），故须于「QEMU」页勾「PS/2 控制器」，于「输入」页置「USB 支持」为「关」；惟开 PS/2 而不闭 USB，则 QEMU 送键于 USB 键盘，犹不得。显卡 virtio-vga 与 VGA 于 OVMF 皆有帧缓。QEMU 中接 `usb-kbd` 于 xHCI，亦入桌面。键盘与 USB 启时之诊（`PS2 STAGE=`、`USB PCI=` 等）惟书串口（主核之「串口裸字节」），不复绘于屏。开机不复候三十秒之 USB 热插拔观察（为林檎实机之察而设），开机至命令壳约三点四秒；PS/2 键盘之入环，正其写计逾二百五十六则尽以键为环满而弃之之误；出桌面之清屏改由内核涂黑（交帧像素址予零），不复于客堆新建四兆之数组。桌面通 PS/2 鼠、USB 鼠与绝对坐标之数位板（usb-tablet），滚轮可用；QEMU 默机自带 PS/2 鼠，监视器 `mouse_move`、`mouse_button` 可试。

**高分屏与显示之设（2026-10-11）**：核逐物理像素交画，执行器于宽逾1920或高逾1200时报自动比2，余为1。桌面依有效比直绘字，设置具八种缩放而存之。QEMU标准显卡、臂内存帧及威睿显卡由共用底层豫言之驱可改1280×800、1920×1080、2560×1600；还面则复开机尺。余器沿固件之尺。QEMU高分屏可用 `-vga none -device VGA,xres=2560,yres=1600`（BIOS引导依EDID择VBE，UEFI沿固件GOP）。详见[帧服务](文档/帧服务.文言.md)及[臂平台](文档/臂平台.文言.md)。

**USB 之鼠（二〇二六年十月六日）**：核之 xHCI 之驱识 HID 启动之约之鼠（类三、子类一、约二），开机前接好或开机后热插皆可；与键盘同器之鼠接口（如林檎笔记本内置键盘与触控板）亦各配一端。其报转为 PS/2 三字之包，书于与 PS/2 鼠同一之鼠环，执行器无须改。无 PS/2 控器（状态之口得 0xFF）则核略 PS/2 鼠之读与初置。QEMU 可以 `-device usb-mouse,bus=xhci.0` 接 USB 鼠，加 `-machine i8042=off` 去 PS/2，以拟惟有 USB 输入之机。详见 `文档/帧服务.文言.md`。

**自有之引导（二〇二六年十月七日）**：启盘之引导之程与 ISO 之构皆豫言生之（`豫言操作系统/裸机/库/冶铸/自有引导。豫`），造盘尽用豫言之码。BIOS 之启，MBR 读入第二级（光盘则 El Torito 径载之），第二级于实模式依盘上引导之表读内核与诸模，取 E820 内存表，依 EDID 首选之分辨设 VBE 帧缓，填 Multiboot 一之信，乃切保护模式而入内核。UEFI 之启，固件自一兆之 FAT12 分区映像载 `EFI/BOOT/BOOTX64.EFI`（PE32+；光盘由 El Torito、U 盘由 MBR 类 0x0C 之分区得之；林檎识此 FAT 之类，U 盘插之即见「YUYAN EFI」之卷；入内盘则复为 UEFI 所定之 0xEF），彼觅有引导表之全盘，读内核与诸模，取 GOP 帧缓与内存表，退启动之务，复归三十二位保护模式，拷内核于其载址而入之。引导之示皆中文：BIOS 装示字之点阵于显卡字库，UEFI 引导程序（兼与臂）先登中文之字体于固件之 HII 数据库（包「底层统一引导」），EDK2 之类固件屏显中文。诸模之实址：BIOS 自内核 bss 之末（十六兆，内核之模区之后）起紧排，入百二十四至百二十八兆（USB 控器之 DMA 区）者徙于百二十八兆以上；UEFI 则居固件所予四吉以下之高址。第三方字体与拼音词库之许可为 ISO 根目录之文件随盘（NOTO.TXT、SIYUAN.TXT、WENKAI.TXT、PINYIN.TXT）。

**安全之启与自署（二〇二六年十月二十二日）**：UEFI 安全之启既开，固件惟纳 db 所登之证所署者。豫言系统之引导可自署：先以 `豫言系统 生成签名钥 --输出 签名钥` 造二千零四十八位之李萨阿私钥与自签之告身（`签名钥.pem`、`签名证书.der`、`签名证书.pem`，持有者「豫言引导签名」）；造盘时加以 `--签名钥 签名钥/签名钥.pem --签名证书 签名钥/签名证书.der`，则 `启动盘` 依微软公开之 Authenticode 式为二构之 `BOOTX64.EFI`、`BOOTAA64.EFI` 署押：影像之摘用沙二五六（跳可选头之校验和与安全之目，不含证书之表），证书之表接于文末，信（SignedData）中藏间接之数，签以李萨阿补零之封。二者皆不与则仍不署。署及其所嵌字体之包与统一引导之模，改一字则摘不合，固件拒之。登证于 db：OVMF 以 `OVMF_CODE_4M.secboot.fd` 配 `OVMF_VARS_4M.fd` 之副本，入固件之设，先于 Device Manager → Secure Boot Configuration 改为 Custom（或清 PK 而入 Setup Mode），次至 Custom Secure Boot Options → PK Options → Enroll PK 选 `签名证书.der`，复于 DB Options → Enroll Signature → Using File 选同文，存而重启；其文置于 FAT 之 U 盘。常见之 PC 固件于 Security → Secure Boot → Key Management 有「Enroll EFI image」或「Append from file」，亦自 FAT 之 U 盘选 `签名证书.der` 而登之。既登，则固件惟启署过之盘，未署或署后复改者拒之；`sbverify --cert 签名证书.pem <自 EFI 分区映像取出之 BOOTX64.EFI>` 可先于宿主核其式。惟信微软之钥者，先经微软所署之 shim（外程）。

U 盘之接，易末三项为 `-device qemu-xhci -drive if=none,id=yy_usb,format=raw,file=启动介质/豫言启动臂.iso -device usb-storage,drive=yy_usb`；纯拟则易 `-cpu host -accel hvf` 为 `-cpu cortex-a57 -accel tcg`。UTM 之 QEMU 虚机（臂、UEFI）亦可启之。此盘亦可启于林檎芯片 Mac 上 VMware Fusion 之臂虚机（二〇二六年十月九日）：引导程序依内存之起算物理之偏，内核依 ACPI 之表寻串口与 GIC，屏显命令壳之出，VMware 之 USB 键鼠可用，「图形」桌面亦可行，其法与设见[臂六十四之平台](文档/臂平台.文言.md)。两构皆以豫构豫行之程开机，USB 合成镜之数据区存文件并供系统内造盘。Fusion 臂自建探针已验开机豫构与 USB 数据盘之挂。

**启盘兼数据盘（二〇二六年十月七日）**：启盘之令并生 `启动介质/豫言启动盘.img`：于 ISO 后首个六十四兆之整倍处接持久盘非零之前段（ext4 之诸元数据与已用之块皆在前段），加一兆之零，凡约百五十兆。写此镜于一 U 盘，则可启亦为数据盘。核之 USB 存储之驱依 ext4 超级块以识数据盘：首（始零）处不得者，于六十四兆之一至十六倍处复求之；得则以彼为数据盘之首，读写之扇号皆加此始，ISO 所在之分不改。数据盘之容于造盘时以 `--盘容量` 定之（ext4 之块数书于超级块，挂载不依 U 盘之容而扩；U 盘小于其容，则分配不越 U 盘之末）；欲尽用大 U 盘，则以 `--盘容量` 予数据区之容。前段唯书至末一已用块，镜仍约百五十兆，U 盘旧存之物不必清（见[客体文件系统](文档/客体文件系统.文言.md)）。QEMU 以镜像文件之大为 U 盘之容，故先复制一份，疏扩至所欲之大（下例十六 GiB），乃唯接此一 USB 存储：

```sh
cp 启动介质/豫言启动盘.img 测.img
dd if=/dev/zero of=测.img bs=1048576 count=0 seek=16384
qemu-system-x86_64 -machine q35 -accel tcg -m 8G -smp 4 -serial stdio -no-reboot \
  -drive if=none,id=yy_boot,format=raw,file=测.img \
  -device qemu-xhci,id=xhci -device usb-storage,bus=xhci.0,drive=yy_boot,bootindex=1 -boot order=c
```

以此一 U 盘可于系统中构建你好（缺省带工具链，四核 `-j 4` 约四十八秒），BIOS 与 UEFI 皆可启。核留旧池第三十、三十一块（物理百二十四至百二十八兆）为 USB 控器之 DMA 区，开机之分配最后乃用之；xHCI 之寄存区在四吉之上者（QEMU 之 OVMF 置于 0xC0_00000000），核映之于虚址 0xBFE00000 之二兆窗。

UEFI USB 之验以 QEMU OVMF。下为 Homebrew QEMU 之径；先复制可写变量模板，再以 pflash 挂代码与变量：

```sh
cp /opt/homebrew/share/qemu/edk2-i386-vars.fd ovmf-vars.fd
qemu-system-x86_64 -machine q35 -accel tcg -m 4G -smp 4 -display none -monitor none -serial stdio -no-reboot \
  -drive if=pflash,format=raw,unit=0,readonly=on,file=/opt/homebrew/share/qemu/edk2-x86_64-code.fd \
  -drive if=pflash,format=raw,unit=1,file=ovmf-vars.fd \
  -drive if=none,id=yy_iso,format=raw,file=启动介质/豫言启动.iso \
```


用法（二〇二六年十月九日）：诸项由「并行模拟」（`豫言操作系统/裸机/并行模拟。豫`）同行，`-j` 为同行之 QEMU 数，缺省为在线处理器之半。编探针仍于主线一一为之（同一编译之缓存同时惟一构），同源惟编一次（壳试八项共一次 壳。豫 之编）。仓根有原生之器（`豫构。林檎。豫行`、`编译器。林檎。豫行`）则缺省用之，否则用 Wasm 者，`--豫构`、`--编译器` 可另指。每项之镜、盘、串口与日志置于临时目录下以项名为名之子目录；同组诸阶共用之盘置于临时目录本层，同组诸阶依原序相继而行。果依原序而印；败不中止，前败则同组后项记为略；尽行之后印其总与败单，已录之败（见下）别列、不计，有败则退码为一。每候步至多五分，交互既毕候模拟器退至多一时。二〇二六年十月九日于 M 系列 Mac（十八核，他会话同用，负载约二十）实测：九十八项约四至六分（`-j 9`），时多费于豫构之编（七十一次，约二百四十秒）；同机串行（`-j 1`、Wasm 之器）四百一十一秒；未改之旧验证器约十分，且至兼之壳试即止。

**已知之败**（验证器「已知失败」之录：照常行之，印为“已知失败”，不计于败；录者既过，总时提醒除其录）：

- 兼之壳试（`普通-壳-*-兼容六十四`，八项）：壳由「中书」依「小学」，以「字书」之全拼候选表（约六兆半）与拼音转换表（约九兆）入被动数据段，壳.wasm 约二十兆，大段约十九兆。兼以 `-kernel` 启之镜，置大段区于用户基址后二兆（0x400000），至外置根端口扫描之码（0x7D0000）凡三点八兆（裸机后端 存储镜像「裸机大段区容量」、兼容核心「生兼自定镜像」），生镜之时报“裸机大段区超过上限”。臂之大段区自 0x50000000 起，凡六十四兆，此八项于臂皆过。修之留待后续版本：兼之 `-kernel` 镜依豫行之布置大段于 0x8000000 起（验证之机增内存，核依段映之），或令裸机之壳惟带简拼音之数据。

又：文件修改之时自十月七日起取写序（6befe3fed），二〇二六年十月十日起随 ext4 改为节点中之墙钟秒；`普通探针/盘/状态子任务-一。期望` 随改为“修改时间合理：是”（子程序核其在 QEMU 时钟起点前十秒至起点后一时之间）。

涵：普通豫言程序（打印、列表、闭包、异常、回收之压、小数、浮点指令、表指令）、壳（基本、ASCII 之入、终端键与中文组字、文件命令、文件之追加复制移动、脚本、环境变量；示例、崩溃、大程序、子进程文件与中断五项暂停，见下）、语言测试集 `应用/豫言编译器/校场/网页汇编` 之十二例、磁盘（跨重启读写、离线造盘）、动态装载（含回收之压）、内核服务之探针。内核本身别有 `裸机验证`（下文，三百余项）。

网卡（十月十三日，持续改进目标「开放硬件驱动」第一、二步）：`--只验 网卡` 行网卡之探针（`普通探针/网卡/网卡。脚本。豫`），于诸 QEMU 网卡之型（虚拟网卡 virtio-net-pci、英特尔千兆 e1000、英特尔千兆e e1000e、英特尔高级 igb、通用串行网卡 usb-net（挂于 xHCI；以太址明定为 40:54:00:12:34:56，盖 usb-net 书之于描述之 MAC 串，诸版 QEMU 所书首字不尽同也），期望之文 `普通探针/网卡/型号。期望`）各于二构行一项。QEMU 接用户网络，十、零、二、百之七号口转予宿主之 `cat`；探针询设备接口之「问网卡」（网络栈旋以 DHCP 得十、零、二、十五），印驱动名、以太址与址设，与宿主往返一行，复解 example.com（宿主须能上网）。余项不另接网卡，QEMU 依常予默认之卡（臂 virt 为 virtio-net-pci，兼 q35 为 e1000e），开机时核之网卡之驱亦初置之。

壳之试依壳命令之豫言句书之（如 `「复述」于『你好 世界』`，二〇二六年十月十一日起）。裸机之壳行逐键之编辑与中文组字：串口逐字而至；十月十日起无中英之易，ASCII 字母径书于输入之行，标前相续之字母有候选则出中多一行候选，所期依实出书之；输入文件中以 `@注` 起首之行为说明，不送。逐键之编辑每得一字即以回车重绘全行，验证器于壳之交互项依终端回车之义整之（每行惟留末一回车之后），乃与所期相校，整之之文另存于临时目录之 `项名.整理`；余项仍逐字校之。候之逾时或模拟器先退，败由附所收串口之出。示例、崩溃、大程序、子进程文件、中断五项暂停（验证器之「暂停壳测试名们」）：所期依旧出推而书之，复行之后须依整之之文重书。待办事项：同一会话第五次读文成，则壳报“堆内存不足”而退（二架构同），故重定向项限读文成者三次。


验证器以豫言异步子进程行 QEMU。父程先构豫言内核、验设备之能，乃依 `-j`（缺省为在线处理器之半）起同数之分片子程（即本程，带 `--分片 片号`）：每子程载父程所造之核，备本片诸项之镜，同时至多行二 QEMU，书每项之果于临时目录 `结果/序号`；父程依原序（臂先兼后）印之。`-j 1` 于本程行之，不起子程。分片依方式为组：一方式之二架构同片（共首次所算之客体模）；共持久盘、先书后读之二项（磁盘写入、磁盘重启读取）连二架构同片，片内依原序相继。每项之镜、模、串口与日志置于临时目录下以“架构-方式”为名之子目录，共用之持久盘置于其本层，诸项文名各异：QEMU 闭其监视器（`-monitor none`），串口各用己之管或标准出，进程号之文每项一份。败不中止：每项记其成败，前败则同链后项记为略；尽行之后印其总与败单，有败则退码为一；子程异退，其未交之项记为败，附其误出。候步可标为急候（标现则须即送次步，如客体步数有限之循环）：有急候之例，子程暂不启新例，改以十毫秒轮询。每候步与交互既毕之候各至多五分，逾则依本轮独立进程号之文止模拟器。豫构与编译器之缺省同普通豫言验证（有原生则用之）。所用宿主之器有 `mktemp`、`mkdir`、`mkfifo`、`dd` 与 `/bin/kill`；`dd` 惟负对照改页表或中断之标用之，不与常镜之生。

**WASI**：WASI preview1 之兼容层，今由 `客体二号/瓦西名称。底层。豫` 与 `瓦西分派。底层。豫` 部分接入。二十二样各至少于一原生目标行过；裸机之随机取处理器之随机令（RNDR、RDRAND；cortex-a53 与 qemu64 无之，则返败而不终其任务），底层文件代办犹待为（WASI 暂缓）。

**今之界**：内核为双架构微内核，任务、调度与内存之管皆由底层豫言书之豫言内核为之（见[动态任务](文档/动态任务.文言.md)、[多核](文档/多核.文言.md)），任务按需而生、子进程可复起子进程，AMD64 与 ARM64 共用一份实现。执行器之解释之途无 SIMD（径降为机器码之底层程序用硬件浮点、NEON／SSE 之向量与原子之令，见[数值之降](文档/数值降级.文言.md)）；墙钟之精一秒，单调之钟一内核滴答（十毫秒）；文件与目录内容之缓存上限四十万九千六百字节；接于 UHCI/OHCI 伴随控制器之全速 USB 键盘、租约之续与地址冲突之检，留待后版。各阶段之录见[阶段记录](文档/阶段记录.汉语.md)（汉文）。
