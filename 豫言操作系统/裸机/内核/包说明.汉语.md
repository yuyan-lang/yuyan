# 豫言内核

`网卡中断路由` 共用底层模块管理传统线路的物理屏蔽与应答；MacBookPro11,1 将输入输出中断控制器线路十八转交客体线路十，客体配置读取使用同一虚拟线路。`准备客体设备内存表` 分开网卡总线与总线零的上下文页，保留 USB 授权；`允许宿主多核` 在受托登记存在时返回零。

`读客体处理器能力` 接受主叶、子叶和已授权的十六字节结果缓冲，调用处理器信息原语并按客体模型筛选四个三十二位结果。普通叶零报告上限一，叶一按宿主能力保留基本指令、第二级标量指令与处理器随机数；扩展叶上限为 `0x80000008`，保留长模式、标量标志操作和最多四十八位的物理地址宽度。未知叶清零。需要额外状态管理的指令列为后续事项。

`网帧服务`：服务 61 网帧收、62 网帧发、63 网卡信息先用内核的原生网卡（见下面的 `网卡表`；有几块时用第一块链路已通的），没有原生网卡或链路都没通时走驱动客体的设备环：驱动客体每次退出前经导出 `设备环网帧` 登记网卡两环（全局区 +256 起：收环、发环物理址、容量与用户在用标记），初始任务经临时窗 6 存取两环（消息与设备环相同：十六字节首部加以太帧），一经取用，内核便不再自答地址解析；网卡信息读设备发往豫言之环首部 +40 的以太地址与 +48 的链路标记，由客体代理写入。原生网卡的收发也用同样的十六字节首部（类别 1、帧长）。两架构都有这三个服务；既没有原生网卡也没有环时返回 −1。服务 75 网卡记录（序号、用户缓冲偏移 → 48 字节：驱动号、链路、以太地址、收帧数、发帧数、发失败数、是否在用；驱动客体的网卡排在原生网卡之后，驱动号 0）给壳命令「网络状态」用。多网卡路由、多核与跨块的环留待后续版本。

`登记设备上下文表` 由可信单线程启动者登记总线零的传统设备上下文页和转换器寄存器物理地址，两址须非零且四 KiB 对齐。AMD64 把寄存器所在两兆块映到共享设备页目录第 510 项（虚址 0xBFC00000，不可缓存），成功返回零，参数错误返回二，ARM64 返回三；全局偏移 232、240 保存表址与寄存器虚址，内存初置清空。登记之后，共用扩展主控驱动用乙控制块偏移十六 KiB 的四张页表，为自己的两个两兆控制块建立独立设备地址域，域号二；按单元能力选择三级或四级根，地址宽编码分别为一、二，其他页保持无映射。随后屏障、全局上下文缓存失效及转换缓存失效，确认完成才启动设备。没有登记时沿用平台原有访问。多总线、多转换器、设备窗口冲突检查、域号分配和运行期撤销列为后续事项。

`构建设备控块域` 接受上下文项、十六 KiB 表区、两个两兆物理块。上下文十六字节对齐，表区四 KiB 对齐，两块低于五百一十二 GiB。成功返回一；参数错误返回零并保持内存。测试核对错误输入保持、相邻叶及其他页无权限、同一与不同一 GiB 区段的两块映射。

`受托中断开放` 接受已授权的传统中断号 0–15，开放对应屏蔽位；从片中断同时开放主片级联。成功返回零，号越界返回二，AMD64 之外返回三。仅供可信受托入口使用，归还时恢复宿主屏蔽字。

`处理传统伪中断` 读取第七或第十五号线路的服务位，主片伪中断直接返回，从片伪中断应答主片级联。

`处理宿主传统中断` 接住受托边界迟到的中断，将所授网卡请求排入客体，其余线路按实际服务位应答。AMD64 的传统中断门共用保存与恢复桥，全局偏移 280 暂存入口线路号。`处理客体物理中断` 接受退出信息中的物理向量，沿同一底层函数转交网卡请求。工作页 `0x06180300` 起记录最近线路、计数及主从服务位。当前单核使用该入口记录，多核记录列入后续事项。

`初置受托间歇` 接受授权记录、入口和页根三个六十四位地址，记录长 32 字节且八字节对齐，运行页根四 KiB 对齐；成功返回零，参数错误返回二并保持记录。布局为入口、页根各八字节，状态、结果各四字节，归还次数八字节。状态一就绪、二执行中、三完成、四失败。`登记受托间歇` 在可信启动代码关闭中断时登记一个记录，已登记返回一，参数错误返回二，当前单核 AMD64 之外的环境返回三。记录、内核代码和栈在两个页根中同址映射，入口有界返回一继续、零完成、负数失败，并负责保存恢复浮点状态。

普通调度和空闲选每次执行一个受托片期，保存当前完整页根、线程指针和双 PIC 屏蔽位、服务位，进入授权页根调用入口，再恢复宿主现场并记账。调用期间新增而遗留的服务位按具体中断号应答，保留调用前的服务位。用户任务全部退出后，有登记的受托工作时继续空闲调度；旧槽退出调用桥经 `有受托间歇` 查询，零表示无登记，一表示有登记。完成或失败清除登记；内存初置清空登记。全局区偏移 224 保存记录地址。`读页表` 是最小处理器原语，AMD64 读 CR3，ARM64 读 TTBR0_EL1。截获事件接回完整宿主分派、多核受托工作、用户任务的能力接口与故障资源回收列为后续事项。

光盘与硬盘的命令经 `串盘候令` 等完成：命令表位清除即成功；任务文件或主机总线出错（PxIS 位 27–30）时立即返回失败，并按 AHCI 规程复位端口（清启动位、等命令列表停止、清错误、再启动），下一条命令照常可发。

`光盘。底层。豫` 与 `内存盘。底层。豫` 是两架构共用的只读光驱与内存写入层。光盘使用 SATA AHCI 的 ATAPI 读命令；数据区挂入现有块服务，写入以四 KiB 块保留在内存，编译缓存和造盘输出沿用客体文件系统。

`初置浮点上下文` 接受十六字节对齐的六十四位地址，调用方授权至少 528 字节；AMD64 初置 512 字节 FX 保存格式，控制字为 `0x37F`、MXCSR 为 `0x1F80`，ARM64 初置 528 字节向量及控制状态为零。成功返回零，参数错误返回二并保持内存。`交换浮点上下文` 接受保存区、恢复区两个授权且独立的六十四位地址，先保存当前处理器浮点与向量状态，再恢复另一上下文；范围、配对及所有权由调用方管理。两项追加在导出表末。扩展向量状态列为公开相应处理器能力前的事项。

`复制连续表` 追加在导出表末，接受目的、来源两个六十四位地址与三十二位项数，调用共用底层地址表复制实现。调用方提供互不重叠且已映射授权的两段范围；内容、来源保持及边界约定见底层地址表包说明。私有硬件运行页根使用该入口复制普通页表。

`保留物理块` 接受起始块号与块数，块长为 2 MiB；在普通分配器中先核验整个范围空闲，再标为占用。返回零为成功、一为已有占用、二为参数越界；失败保持位图原状。AMD64 同时处理块号 32–63 的旧池与高区位图，ARM64 从块号 1024 起使用高区位图；上界取开机发现的实际内存最大块号。调用者在内存池初置后、分配锁内或多核任务启动前调用，并持有范围的管理权限。导出项追加在表末。ARM64 调用桥保存并恢复线性基址和容量，内核调用期间使用物理地址视图。运行期保留记录与成组回收列为后续事项。

`设备环网帧` 以共用底层实现处理网帧收发环，接受设备收环、设备发环和私有上下文三个六十四位地址，以及三十二位环授权容量。调用方映射并授权两环及 2112 字节上下文；上下文首六字节为以太地址、偏移八为网络字节序 IPv4 地址，十六与二十为收发计数，二十四为待发送标记，六十四起是 2048 字节连续消息缓冲。初置时清零计数与待发送标记。类别一表示设备上交的完整以太帧，类别二表示豫言下发的完整以太帧。当前处理本机 IPv4 地址解析请求，生成六十字节回应，保留调用序号，发送标志为零；其他协议及地址返回六。返回零表示已发送，二为空收环，一为发送环满；满环时上下文保留回应，下次调用先重试。其余状态沿用设备环校验。网际报文与更多协议列为后续事项。

`设备环投递` 与 `设备环取件` 追加在导出表末尾，接受六十四位环地址、环容量及连续消息缓冲地址，还有三十二位消息缓冲容量。消息首部与载荷连在同一缓冲，容量包含十六字节首部；具体校验及状态见底层设备环包说明。调用方提供已映射、已授权的收发缓冲。

`设备环显帧` 接受六十四位环地址、授权环容量、发送状态地址和源帧地址，复用底层设备环的连续帧发送器。发送状态为独占的四十八字节记录，布局和状态码见底层设备环包说明。调度者在环满后重复调用，即可从待发行继续；完成整帧后，下次调用发送当前源帧。调用方授权并映射状态、临时消息缓冲、环和源帧，负责源帧写入同步。

`绘制缓转交` 接受六十四位绘制指针槽地址、宿主缓冲地址和复制容量。可信启动者授权并映射指针槽、原绘制区和宿主缓冲；两段缓冲互不重叠，转交期间停止绘制。入口先复制原画面，再将绘制指针改为宿主缓冲，返回零。空地址、空容量及容量超过 2147483647 返回二十八，指针保持原值。实际设备地址继续存于设备描述，设备服务从宿主缓冲输出。测试核对复制边界、无效容量以及后续绘制与原设备区分离。运行期间换缓、撤销和并发转交列为后续事项。

内核接受零页、零容量的六十四位共享内存声明，作为物理地址视图。该声明确定地址宽度；调用方提供已映射、已授权的物理地址范围。`设备环初置` 复用共用设备环的初始化算法，接受六十四位地址与容量、三十二位槽数与槽长，返回初始化状态。跨客体共享页的保留与双向传输列为后续事项。

连续八字节表项生成由子包「底层地址表」提供，经导出「填连续表」供已有调用桥使用；跳转表的新项追加在末尾。宿主及硬件客体页表初始化共用此实现，调用者选择架构标志、首项与步长，授权可写范围并刷新映射。

豫言操作系统内核里与架构无关的部分：任务、调度与内存管理。用底层豫言写成，经编译器得到不带回收的 Wasm 模块，再由裸机后端降级器的内核态目标为 AMD64 与 ARM64 各生成一份机器码，与手写的入口部分（开机、异常与中断的进出、系统调用分派）连接成内核镜像。

- `内核。底层接口。豫`：特权操作（按内核虚拟地址读写四字节与八字节、清零、复制、按字节复制、刷新快表、刷新一页、屏障、架构号，以及 AMD64 的 I/O 端口读写，ARM64 读得 0xFF），编成导入模块「内核」的导入；只有内核态目标提供它们（出线的小桩）。
- `架构。底层。豫`：两种架构的差异集中在这里——内核数据地址、页表项格式、槽的容量、页表根与记账区的地址，以及内核访问物理内存的方式（ARM64 全部恒等映射；AMD64 低区恒等，其余经内核任务窗口的临时窗口）。
- `内存。底层。豫`：物理块（2 MiB）的分配与释放、四级页表的遍历与补页、动态区（用户虚址 1 TiB 起）的按需提交、任务内存的清理（顺带清掉本槽占的桌面占屏标志与按键事件模式）与复制、服务 22、24、25、44（归还内存块）、45（空闲内存块数）与开机初置。
- `任务。底层。豫`：动态槽（32 起）的分配与回收、句柄、调度环、调度（存帧、选槽、取帧、换页表与浮点状态）、空闲（「转空闲」「空闲选」：多核时本核没有可运行的任务，或单核而有任务在小睡）、服务 50 小睡（睡到下一个时钟滴答，有信或子任务结束提前醒，10-10）、处理器记账（换出时把本次切入以来的滴答记进累计滴答）、退出与唤醒主人、消息与句柄服务、服务 64 打断任务（打断目标与它的子孙，退出码 130；正在某个核上运行的在槽区 +0x54 记待打断，在它下一次系统调用或下一次时钟轮转时由入口结束，2026-10-12，见[控台输入](../文档/控台输入.汉语.md)）；两个旧槽沿用固定地址的字段，一视同仁。
- `装载。底层。豫`：服务 28–31 持久块服务、37 装载任务、38 读启动块、39 处理器核数、41/42 读写他任务、46 任务信息、47 鼠标位置、50 小睡、53 按键模式与 54 读按键、60 代码块映射，以及开机留模板和动态系统调用分派。豫行文件由服务 43 按段建任务装载，两种架构共用装载逻辑。
- `按段。底层。豫`：服务 43 按段建任务（[提案 00005](../../../提案/00005-自有可执行格式.汉语.md) 第 3 步，只做 AMD64）：执行器在用户态拆好豫行文件的段表交来，内核按段要块、拷入或清零，用户区段拷进用户区块，其余段按 2 MiB 大页映射，带上启动块，从文件头的入口起跑；段块记在槽区 +0x1000 起，「放资源」归还。入口模块把 43 转给它。不可写的大页段按内容在任务间共用物理块（见下条「共享段」）；可写的全零大页段（工具的原生栈）用到哪块、缺页时才提交哪块（延段，记在槽区 +0x3400）。
- `共享段。底层。豫`：只读段共享（[提案 00015](../../../提案/00015-桌面程序独立成任务.汉语.md) 议四）：共享段表记每个共用块的虚址、内容摘要、物理块号与引用数，按段建任务时内容相同就映同一块，放资源时引用数减到零才归还；任务管理器的常驻内存只算各自的那份。
- `平台。底层。豫`：ARM64 平台初置（开机最早由手写内核调用）：开机平台号为 1（按 ACPI 找设备的 UEFI 机器，如 VMware）时读 SPCR、MADT、MCFG 定串口、GIC 与 PCIe 配置空间，给预置页表里指向内核区的项加物理偏移，并把 GIC、配置空间、串口映进设备二级表；平台号为 0（QEMU virt）时什么也不做。见[ARM64 平台](../文档/臂平台.汉语.md)。
- `帧控台。底层。豫`：ARM64 帧缓冲控制台：有 GOP 帧缓冲时把控制台字节按 UTF-8 解码，用启动盘随带的控制台字模（虚址 0x56000000）白字黑底画到屏幕上，满屏上移半屏；手写串口输出例程经导出「帧控台字节」调用，开机内存初置之后启用。见[ARM64 平台](../文档/臂平台.汉语.md)。 另提供服务 32–35（提交帧、帧缓冲信息、读字体模块、字体模块长度），桌面因此能在 ARM64 上运行。
- `扩展主控。底层。豫`：两种架构共用的扩展主控（xHCI）主控一层（2026-10-10 起 ARM64，10-11 起 AMD64 也用，取代手写的那份；10-13 分出下面三个模块，这里只留主控，不调上层）：在 PCI 配置空间里找第一个扩展主控（ARM64 经映到 0x30000000 的 PCIe 配置空间，AMD64 经端口原语走配置机制一），从固件手里接过主控，复位后设命令环、事件环（只轮询），给根端口上电；给上层发命令、控制传输、排传输、等事件、按槽与端点取事件（「取端事」）、启用槽并编址、配端点、释放槽。等命令或传输时顺带取到的别的传输事件暂存起来，由设备层的轮询交类驱动。
- `通用串行。底层。豫`：USB 设备层（2026-10-13）：开机初置与轮询（手写的『控台收入』经导出「扩展主控轮询」调用，AMD64 返回 0 时照旧走手写的 EHCI 后备；AMD64 开机经导出「扩展主控开机」初置），给根端口（与一层 USB 2 集线器下游）的设备编址（失败重试三次），根端口的连接变化在轮询里重新编址或释放；读设备与配置描述符，选配置（第一个有类驱动可接的），逐个接口按类码或厂商产品号问类驱动认不认，设配置后交认下的类驱动接上，每个设备登记进设备表（种类 2，位置＝根端口号×2^20＋路由串）；传输事件按槽号、端点号交类驱动。

- `计时。底层。豫`：两架构共用的周期频率换算、处理器频率探测及计时器剩余计数。`换算周期频率` 接受六十四位无符号分母、分子、晶振 Hz 与回退 MHz；比率信息齐全时计算分子乘晶振除分母，其余取 MHz 乘一百万，全缺时返回零，由调用者进行硬件校准。`探测周期频率` 接受十六字节可写内核缓冲，先查询基本叶上界，再读取第 21、22 叶；ARM64 返回零。`计时剩余计数` 将装值、周期差与周期频率换算为剩余数，装值零按 65536 计，到期或频率零返回零。处理器信息、PIT 校准、PIT 周期装载与读剩余计数沿已有调用桥使用共用计算；导出表末尾追加三个函数。乘积溢出的扩展数值留待后续版本。

处理器信息原语 `读处理器信息` 的主叶、子叶为三十二位整数，输出地址为授权的十六字节内核缓冲。AMD64 执行 CPUID，依次写 EAX、EBX、ECX、EDX；ARM64 将缓冲清零。叶上界检查及能力解释由共用底层代码完成。

模块不声明线性内存、数据段与全局量，内核数据经原语按绝对地址读写；函数参数不超过四个（AMD64 的寄存器参数个数）。各函数的参数、结果与调用约定见各模块的注释。

## 运行页根间歇

`运行页根间歇` 接受目标页根、恢复页根和八字节管理记录，先进入目标页根递增交回次数，再恢复页根并返回次数。调用者授权两个页根及记录，保证内核代码、栈与记录在两根中同址映射，并串行持有记录。中断状态由调用者维持，计数按无符号六十四位回绕。此入口供客体时间片返回宿主地址空间的管理边界使用，任务调度接入留待后续。
