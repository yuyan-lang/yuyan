# 底层设备环 0.1.0

单生产者、单消费者共享消息环，供宿主与驱动客体双向交换设备消息。两方向各使用一个环。逻辑为两架构共用的底层豫言，只依赖底层库；内核、客体代理和兼容层可直接依赖此库。当前完成消息环基础，客体共享映射与设备服务接入列为后续事项。

调用方提供有效的六十四位地址、授权容量和各自拥有的收发缓冲。环基址按六十四字节对齐。首次连接前初始化；运行期间槽数与槽长固定。每个方向各有一个生产者、一个消费者，采用原子序号发布和回收。共享页的分配、地址映射、门铃和等待由调用方管理。

首部为六十四字节：偏移 0 为标识 1499027271，4 为版本 1，8 为槽数，12 为槽长，16 为生产序号，20 为消费序号，余下保留。槽数为二的幂，最大 1048576；槽长为六十四的倍数，范围 64 至 67108864。序号为三十二位无符号循环计数。

槽从偏移 64 开始。消息首部十六字节：0 类别、4 载荷字节数、8 调用方序号、12 标志，其后为载荷。类别由设备服务约定；环只转交这些字段。读写端先复制完整消息，再发布或回收槽。接收端按授权容量核验几何、计数距离和载荷长度；缓冲不足时保留消息。

入口 `器环所需` 计算容量，无效几何返回零；`器环初置` 写首部；`器环致` 写消息；`器环收` 将载荷和十六字节消息首部分别写入目的缓冲、元址。状态 0 成功、1 环满、2 环空、28 参数或共享元数据无效、61 接收缓冲不足。失败时序号保持原值。

`器环投递`、`器环取件` 接受环地址、授权环容量、连续消息缓冲地址与消息缓冲容量四个参数。连续消息的前十六字节为完整首部，载荷紧随其后；缓冲容量包含首部。投递先核验缓冲至少十六字节、首部长度在缓冲内，再复用发送算法；取件先核验首部容量，再复用接收算法，将首部与载荷放入连续缓冲。投递短缓冲返回 28，取件短缓冲返回 61，其余状态沿原收发入口。

`映块应用` 处理类别三的连续消息。载荷首部二十四字节：偏移 0 为版本一，4 横坐标，8 纵坐标，12 宽，16 高，20 源行距；其后是三十二位像素。源行距为宽乘四，目的帧缓冲可以有行尾留白。调用方提供帧地址、授权容量、宽、高及行距；函数先核验消息长度、矩形和帧容量，再逐行复制，保留矩形外内容。返回零成功、二十八参数错误。显示驱动负责像素格式协商和实际显存映射。测试用真实设备环传递二乘二像素块，核对行距、块外旧值及截短和越界消息。

`映块核验` 单独复用应用入口的几何与长度规则，返回同样的状态码，保持像素内存。使用定位写设备文件的客体代理可先调用此入口，再按设备行距逐行投递像素。

`映帧致` 将源帧按整行分块投递显示环。调用方独占四十八字节状态：0 为八字节临时消息地址，8 消息容量，12 帧宽，16 帧高，20 源行距，24 下一行，28 消息序号，32 为八字节源帧授权容量，40 已发帧数。状态和源帧须由调用方授权。入口核验容量和几何；目的像素块采用紧凑行距，源行距可以包含留白。环满返回一并保持待发行；成功投递才前进，整帧完成返回零、下一行归零且已发帧数加一。其余失败返回环状态或二十八，已成功投递的块保持发布。下一次调用开始发送当时的源帧；源帧在发送期间的写入由调用方同步。测试核对两槽环满后续发、整帧重建和行尾留白。

后续事项：跨客体并发验收、客体崩溃回收、门铃、块设备与网络、显示和计算服务路由。
