# 顺序函数指令验证

新增验证入口消费完整二进制模块读取结果，按每个函数的原始指令边界执行完整类型栈检查。当前覆盖不可达、空操作、返回、丢弃、i32/i64/f32/f64 常量、局部读取/写入/暂存、直接调用、空引用和引用判空。其他操作码明确报“尚不支持”，不会因边界检查通过而放行。

i32/i64 常量检查最大编码长度及末字节有效位，不将宽常量截成 i32。浮点常量按精确字节数读取；此阶段只验证类型，不解释其数值。直接调用按完整函数签名检查参数和结果。非空参数初始已定，非空额外局部必须先赋值；该检查在不可达代码中也执行。返回先核对声明结果再将当前路径标为不可达，最终结束必须正确消耗结果且没有多余操作数。

18 个完整标准模块测试通过，分类与 Node 标准引擎一致，覆盖宽常量溢出、过长编码、结果类型错误、直接调用参数错误、非空局部未赋值及不可达中的实际错误类型。类型检查、构建、运行日志为 `/tmp/yy顺序指令检查日志`、`/tmp/yy顺序指令构建日志`、`/tmp/yy顺序指令运行日志`。

当前只验证所列顺序指令。结构控制、算术、GC 对象指令、异常、尾调用及全局/表/内存操作仍待扩展，不能验证现有完整豫言程序。其他模块段也未全面验证，因此结果不是整模块执行许可；尚未接入裸机执行器，默认镜像不变。
