## 原生原型能力基线

本表记录既有原生原型能力。公共接口迁移后的最新平台验证范围见文首，原生复验待完成。

豫言操作系统现在是一个可以启动、可以交互、有持久文件系统的单核系统，ARM64 与 AMD64 都在 QEMU 里通过自动验收：

| 层 | 内容 | 文档 |
|---|---|---|
| 内核 | 手写机器码（由豫言源生成）：页权限隔离、定时抢占、两个任务槽的创建／等待／终止／回收／复制、单条整数消息邮箱与阻塞接收、动态内存块（线性内存可增长）、设备窗口与 IOMMU 隔离、Virtio 设备的用户态访问、控制台输入环与 Ctrl-C 标志、实时钟（[墙钟服务](文档/墙钟服务.汉语.md)：ARM64 读 PL031、AMD64 读 CMOS） | 本目录各专题文档 |
| 用户态执行器 | `客体二号`：用底层模式的普通豫言写成的 WasmGC 解释器（栈机、保守标记清扫回收、异常、尾调用、软浮点）；在用户态运行普通豫言程序 | [客体二号](文档/客体二号.汉语.md) |
| 文件系统 | 用户态 Virtio 块驱动 + 双区追加日志的持久文件系统（多层目录、崩溃安全的提交扇区、紧缩），离线造盘工具 `yy造盘` | [客体二号](文档/客体二号.汉语.md)、[文件系统提交日志](文档/文件系统提交日志.汉语.md) |
| 壳 | 普通豫言写的默认命令壳（`壳/壳。豫`）：目录、切换、列、读、写、追加、复制、移动、建、删、运行、脚本、加、回显、设、取消、环境；临时提供 ASCII 键盘验收命令 `tmp-help`、`tmp-echo 文字`、`tmp-exit`，后续可单独删除；启动时显示中英双语状态与 `Welcome to Yuyan Operation system`，帧缓目前仅能画 ASCII；命令输出可用 `>`、`>>` 写入文件，`运行` 可用 `< 文件` 重定向标准输入、`甲 \| 乙 \| 丙` 串成顺序管道；子进程里也能读写文件（由壳代办）；Ctrl-C 打断正在运行的程序（退出码 130）、放弃正在敲的一行（[控台输入](文档/控台输入.汉语.md)）| [客体二号](文档/客体二号.汉语.md) 的验收一节 |

YY_GC_INITIAL_HEAP_SIZE_MB=1024 node 豫言操作系统/宿主/节点/宿主.cjs yy豫言系统.wasm 构建 --预置 某目录树       # 只造镜像与盘并打印 QEMU 命令

**制作双模式启动 U 盘（x86-64）**需要安装 Limine 与 `xorriso`：

```sh
brew install limine xorriso
node 豫言操作系统/宿主/节点/宿主.cjs yy豫言系统.wasm 启动盘 --输出 yy启动介质 --预置 无
```

命令生成 `yy启动介质/yy豫言启动.iso`。这是可写入 U 盘的 BIOS/UEFI 混合 ISO：传统 BIOS/MBR 与 x86-64 UEFI 入口均由 Limine 启动，并以 Multiboot 1 装载现有无盘内核。仅支持 x86-64；它可不依赖 Virtio 数据盘先进入壳，已接入 xHCI USB bulk-only 数据盘的持久文件操作，未知盘不自动格式化；EHCI、AHCI 与实体机尚未验收。QEMU BIOS 测试把 ISO 作为 USB 大容量存储设备：

```sh
qemu-system-x86_64 -machine q35 -accel tcg -m 128M -smp 1 -display none -monitor none -serial stdio -no-reboot \
  -drive if=none,id=yy_iso,format=raw,file=yy启动介质/yy豫言启动.iso \
  -device qemu-xhci,id=xhci -device usb-storage,drive=yy_iso,bootindex=1 -boot order=c
```

UEFI USB 启动可用 QEMU 的 OVMF 固件验证。以下是 Homebrew QEMU 路径；先复制一份可写的变量模板，再以 pflash 挂载代码与变量文件：

```sh
cp /opt/homebrew/share/qemu/edk2-i386-vars.fd yyovmf-vars.fd
qemu-system-x86_64 -machine q35 -accel tcg -m 128M -smp 1 -display none -monitor none -serial stdio -no-reboot \
  -drive if=pflash,format=raw,unit=0,readonly=on,file=/opt/homebrew/share/qemu/edk2-x86_64-code.fd \
  -drive if=pflash,format=raw,unit=1,file=yyovmf-vars.fd \
  -drive if=none,id=yy_iso,format=raw,file=yy启动介质/yy豫言启动.iso \
  -device qemu-xhci,id=xhci -device usb-storage,drive=yy_iso,bootindex=1
```

Linux 等系统的 OVMF 固件文件路径依安装方式而异，替换上面两个固件路径即可。以上 BIOS 与 UEFI USB 路径已在 QEMU 中启动到 `壳>` 并执行 `回显`，测试未配置虚拟 IOMMU，也未附 Virtio 数据盘。另以 QEMU `pc`（i440fx）机型和 PIIX3 UHCI USB 控制器启动同一镜像；传统 BIOS 与 OVMF UEFI 均进入 `壳>`，执行 `回显`、`退出` 成功。又以 QEMU `-cpu Penryn`（较早一代 x86-64 CPU 模型）配 i440fx、PIIX3 UHCI 作 BIOS 与 OVMF UEFI USB 启动，均进入 shell 并通过 `回显`、`退出`；此为仿真结果，尚非 E40 实机验证。4 GiB 内存复测中，当前重建的混合 ISO 经 i440fx + PIIX3 UHCI + SeaBIOS 从 USB 启动，QEMU 默认 CPU 与 `-cpu Penryn` 均进入 shell 并通过 `回显`、`退出`；启用 QEMU `guest_errors,unimp` 诊断时日志为空。此前记录的同配置 30 秒无启动标记未能复现，旧镜像未保留，故原因未知。此前同容量下 BIOS 从 IDE 光驱、OVMF 经 UHCI USB、传统 BIOS 经 xHCI USB 启动也都通过。Secure Boot 暂须关闭，当前引导器未签名。当前内核壳通过 COM1 串口交互，并将 ASCII 输出绘入 Multiboot 1 提供的 32 位线性 RGB 帧缓冲；QEMU 已验证屏幕上的 ASCII 壳提示与 `help` 输出。实体电脑的帧缓冲模式尚未实测。AMD64 内核现已从 i8042/PS/2 接收 Set 1 美式布局 ASCII，支持左右 Shift、Caps Lock、大小写字母及常用美式移位标点（空格、回车、退格仍受支持）；帧缓冲仅绘 ASCII，非 ASCII 字节忽略；扩展键、中文输入法、实体机显示模式、USB HID 键盘，以及可读写的 SATA、NVMe、USB 磁盘仍待验证或驱动工作。该启动路径先覆盖标准 x86-64 BIOS/UEFI；不同电脑的固件实现与设备仍须逐台实测，不能据此视为已兼容所有硬件。镜像结构见 [Limine 使用手册](https://github.com/Limine-Bootloader/Limine/blob/v12.x/USAGE.md) 与 [配置手册](https://github.com/Limine-Bootloader/Limine/blob/v12.x/CONFIG.md)。

`--预置` 缺省就是 `豫言操作系统/裸机/示例`（写 `--预置 无` 得空盘），它指向的目录树整棵放进盘里（盘缺省 65536 个扇区即 32 MiB，`--盘容量` 可改）；树里以 `。豫` 结尾的文件先编成程序（`/程序/你好。豫` 成 `/程序/你好.wasm`），以 `.底层库` 结尾的标记文件构建同名底层包（`/库/库甲.底层库` 成 `/库/库甲.wasm`），壳里用 `运行 /程序/你好.wasm 参数…` 启动，普通豫言程序可用 `豫言_加载模块`／`豫言_调用导出` 装载并调用库。用法见 `豫言操作系统/裸机/豫言系统。豫`；可运行的示例程序（你好、回声、质数、斐波那契、统计、复制文件、行数、环境变量）见 [示例](文档/示例.汉语.md)。

EHCI 固件交接实现依据：[Intel EHCI 1.0 规范](https://www.intel.com/content/dam/www.public/us/en/documents/technical-specifications/ehci-specification-for-usb.pdf) §2.2.4、§5.1。驱动从 BAR0+`0x08` 的 HCCPARAMS[15:8] 读取 EECP，沿 PCI 配置空间扩展能力链查找 ID `0x01`；存在 USBLEGSUP 时置 OS Owned 位 24，并等待 BIOS Owned 位 16 清零后再操作控制器。实现应循能力链定位，不能依赖芯片组固定偏移 `0x68`。

QEMU 11.1.1 Q35 的 EHCI 只读基线（PCI `00:03.0`，`8086:24CD`）：SeaBIOS 的 BAR0=`0xFEBD5000`，OVMF 的 BAR0=`0x81085000`；两者 HCCPARAMS 均为 `0x00006880`，故 EECP=`0x68`。PCI 配置 `0x68` 的 USBLEGSUP 均为 `0x00000001`（ID=1，OS/BIOS 所有权位皆为 0），`0x6C` 的 USBLEGCTLSTS 均为 `0xC0000000`。SeaBIOS 操作寄存器为 USBCMD=`0x00080031`、USBSTS=`0x0000C00C`；OVMF 为 USBCMD=`0x00080000`、USBSTS=`0x00001004`。数值由 QEMU monitor 读取，内核未请求 EHCI 所有权。

ThinkPad E40 Pentium 的具体 MTM 与芯片组尚待实机或固件信息确认。若该机型使用 Intel 5 Series/HM55，芯片组资料列有两个 EHCI 功能 `D29:F0`、`D26:F0`；当前启动扫描记录只容一个主控制器，尚不足以驱动两个控制器覆盖的全部 USB 端口。[Intel 5 Series/3400 Series 芯片组资料](https://www.intel.com/content/dam/www/public/us/en/documents/datasheets/5-chipset-3400-chipset-datasheet.pdf)

2026-09-28 在 Node 26.3.0 上，`--no-liftoff` 使体积很大的「客体整数执行」夹具直接经优化编译器编译，避开 Liftoff 对单个函数的代码空间限制；上述命令的 380 项双架构验证全部通过，运行约 80 秒。

最初的六项基础检查如下；当前验证器另包含定时器、抢占、结构控制、存储、算术及外部模块等扩展用例，具体数量由运行结果计算：

| 检查 | 客体必须发生的行为 |
|---|---|
| 正常 | 在用户态完成函数调用、局部更新、溢出回绕及乘法核验，然后正常退出 |
| 隔离 | 完成同样核验后，读取内核私有页，产生权限异常；核心核对异常来源及地址 |

| 操作数栈越界 | 保持 Wasm 类型正确，压入超过客体栈限额的值；运行时必须报失败 |
| 调用栈越界 | 有效模块进入递归，调用帧越界前必须报失败 |

## 模块契约与实现边界

输入必须导出无参数、无结果的「启动」。只允许以下函数导入，名字和签名均检查：

| 模块与名称 | 参数、结果 | 实现 |
|---|---|---|
| 平台／写字节 | 一个三十二位整数，无结果 | 经系统调用访问串口，检查字节范围 |
| 平台／核验 | 两个三十二位整数，无结果 | 比较实值与期值，失败立即停止验证 |
| 平台／用户态 | 无参数，一个三十二位结果 | 核心先检查保存的硬件用户态状态，才返回一 |
| 平台／读字节 | 无参数，一个三十二位结果 | 非阻塞读取串口，无数据返回负一 |
| 平台／时钟滴答 | 无参数，一个三十二位结果 | 返回已处理的定时中断计数 |
| 平台／任务编号 | 无参数，一个三十二位结果 | 返回当前静态任务编号 |
| 平台／任务状态 | 一个三十二位参数、一个三十二位结果 | 查询运行状态位，无效编号返回负一 |

当前启动验证协议要求正常结束前恰好完成四次核验；这属于测试协议，不是通用系统调用标准。不能将这些宿主接口误称为 WAT 规定的操作系统接口：模块导入及类型是标准的，平台服务语义由本项目定义。

函数参数、结果置于独立的非 GC 操作数栈，局部变量置于真实调用帧。两套后端均支持整数核心的所有现有指令。操作数栈限一百二十八千字节，调用栈约一百二十八千字节，二者有间隔；压值和分配调用帧时检查边界，超限进入失败路径。函数参数与附加局部合计至多一百二十八项；用户代码至多一兆字节。尚未做寄存器分配或跨函数栈检查消除。

ARM64 以自有 ELF64 头装载，在一级异常层安装页表和异常向量，通过异常返回进入零级用户态。AMD64 以多重引导首版地址头装载，从三十二位保护模式切换到六十四位长模式，安装页表、全局描述符、任务状态段及中断门，再进入第三特权环。QEMU 提供镜像装载入口；尚无磁盘启动扇区或实机固件移植。

两端采用静态两兆字节页映射。AMD64 核心位于低两兆，用户域位于二至四兆；ARM64 核心位于 `0x40000000` 区域，用户域位于 `0x40200000`，另有 `0x40400000` 私有受测页。串口只由特权核心访问。用户代码与用户栈尚在同一可读写用户映射中，未实现页级写入／执行互斥；这些限制不影响当前内核页隔离检查，但还不足以成为不可信程序的生产沙箱。

镜像生成阶段可以在无工具搜索路径时运行。生成器自身目前仍由既有豫言编译器构建；通过 Wasm 执行生成器也仍借助现有宿主。不能把客体无外部编译器与库依赖等同于整个自举工具链已经独立。
