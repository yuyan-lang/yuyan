# 豫言双架构裸机原型

## 当前系统总览（先看这里）

豫言操作系统现在是一个可以启动、可以交互、有持久文件系统的单核系统，ARM64 与 AMD64 都在 QEMU 里通过自动验收：

| 层 | 内容 | 文档 |
|---|---|---|
| 内核 | 手写机器码（由豫言源生成）：页权限隔离、定时抢占、两个任务槽的创建／等待／终止／回收／复制、单条整数消息邮箱与阻塞接收、动态内存块（线性内存可增长）、设备窗口与 IOMMU 隔离、Virtio 设备的用户态访问、控制台输入环与 Ctrl-C 标志、实时钟（[墙钟服务](文档/墙钟服务.汉语.md)：ARM64 读 PL031、AMD64 读 CMOS） | 本目录各专题文档 |
| 用户态执行器 | `客体二号`：用底层模式的普通豫言写成的 WasmGC 解释器（栈机、保守标记清扫回收、异常、尾调用、软浮点）；在用户态运行普通豫言程序 | [客体二号](文档/客体二号.汉语.md) |
| 文件系统 | 用户态 Virtio 块驱动 + 双区追加日志的持久文件系统（多层目录、崩溃安全的提交扇区、紧缩），离线造盘工具 `yy造盘` | [客体二号](文档/客体二号.汉语.md)、[文件系统提交日志](文档/文件系统提交日志.汉语.md) |
| 壳 | 普通豫言写的默认命令壳（`壳/壳。豫`）：目录、切换、列、读、写、追加、复制、移动、建、删、运行、脚本、加、回显、设、取消、环境；命令输出可用 `>`、`>>` 写入文件，`运行` 可用 `< 文件` 重定向标准输入、`甲 \| 乙 \| 丙` 串成顺序管道；子进程里也能读写文件（由壳代办）；Ctrl-C 打断正在运行的程序（退出码 130）、放弃正在敲的一行（[控台输入](文档/控台输入.汉语.md)）| [客体二号](文档/客体二号.汉语.md) 的验收一节 |
| 进程 | 同步子进程：复制任务，子任务把磁盘上的程序换进执行器，父任务等待退出码；标准输入重定向、环境变量随复制交给子任务 | 同上“子进程”“标准输入重定向、环境变量与顺序管道”两节 |
| 动态装载 | 多实例：运行中从盘上装载 Wasm 模块，跨模块导入导出与双向回调（含延迟链接） | 同上“多实例”一节 |
| 数值 | 小数运算走 IEEE 754 软浮点（加减乘除、转换、定点六位转串、%.17g 精确表示、串转小数）；Wasm 的 f32/f64 全部指令（比较、算术、取整、开方、转换、饱和截断）同样由软浮点实现，逐位对照 V8 | 同上“软浮点”“Wasm 浮点指令”两节 |

**构建并运行**（在仓库根目录、已安装 QEMU 时）：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 文件 豫言操作系统/裸机/豫言系统。豫 --编译器 ./yy4_bs.wasm --输出 yy豫言系统.wasm
YY_GC_INITIAL_HEAP_SIZE_MB=1024 node 豫言操作系统/宿主/节点/宿主.cjs yy豫言系统.wasm 运行 --架构 兼容六十四      # 交互；缺省带上示例程序；壳里输入“退出”结束，Ctrl-C 打断运行中的程序，卡死时按 Ctrl-A 再按 X 强制结束
YY_GC_INITIAL_HEAP_SIZE_MB=1024 node 豫言操作系统/宿主/节点/宿主.cjs yy豫言系统.wasm 构建 --预置 某目录树       # 只造镜像与盘并打印 QEMU 命令
```

`--预置` 缺省就是 `豫言操作系统/裸机/示例`（写 `--预置 无` 得空盘），它指向的目录树整棵放进盘里（盘缺省 65536 个扇区即 32 MiB，`--盘容量` 可改）；树里以 `。豫` 结尾的文件先编成程序（`/程序/你好。豫` 成 `/程序/你好.wasm`），以 `.底层库` 结尾的标记文件构建同名底层包（`/库/库甲.底层库` 成 `/库/库甲.wasm`），壳里用 `运行 /程序/你好.wasm 参数…` 启动，普通豫言程序可用 `豫言_加载模块`／`豫言_调用导出` 装载并调用库。用法见 `豫言操作系统/裸机/豫言系统。豫`；可运行的示例程序（你好、回声、质数、斐波那契、统计、复制文件、行数、环境变量）见 [示例](文档/示例.汉语.md)。

**验收**：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 文件 豫言操作系统/裸机/普通豫言验证。豫 --编译器 ./yy4_bs.wasm --输出 yy普通豫言验证.wasm
YY_GC_INITIAL_HEAP_SIZE_MB=1024 node 豫言操作系统/宿主/节点/宿主.cjs yy普通豫言验证.wasm                       # 42 项 × 双架构，约 12 分钟；--只验 普通-壳- 只跑一类
```

覆盖：普通豫言程序（打印、列表、闭包、异常、回收压力、小数、浮点指令、表指令）、壳（基本、文件命令、运行子进程、子进程的文件、输出重定向、脚本、示例程序、环境变量与管道、子程序崩溃隔离、磁盘上的大程序）、语言测试集 `应用/豫言编译器/测试/网页汇编` 的十二例、磁盘（跨重启读写、离线造盘）、动态装载（含回收压力）、内核服务探针。内核本身另有一套 `yy裸机验证`（下文，三百余项）。

普通豫言壳在拆词前去掉行模式读入所含的末尾换行，使命令参数和 `退出` 恢复准确解析。交互就绪与模拟器完成的旧等待上限已各放大一百倍，便于检查较长的壳测试；`--只验 壳-基本`、`--只验 壳-运行`、`--只验 壳-子进程文件` 在双架构 QEMU 通过。验证器仍按输出与期望逐字比较。

**WASI**：WASI preview1 兼容层由 `客体二号/WASI名称。豫` 与 `WASI分派。豫` 部分接入，旧实现保存在 [WASI库](WASI库/说明.汉语.md) 供参考。22 个样例各至少在一个原生目标运行过；裸机子任务的随机数熵源与底层文件代办仍待实现。

**当前限制**：内核只有两个任务槽，所以一次只能有一个子进程、子进程不能再起子进程，管道也只能是顺序的（各段一个接一个运行，前一段必须自己结束）；子进程的文件操作由初始任务经邮箱代办（每条消息三个字节，量大很慢）；实时钟只有秒的精度与 UTC；跨实例只传数值；没有 SIMD。

已实现 ARM64、AMD64 的 QEMU 裸机启动验证。标准 Wasm 整数核心模块经过自有提前编译后，在真实用户态执行；最小特权核心提供页权限、同步异常入口、定时中断和受控服务。机器字节、重定位、启动头和页表全部由豫言生成，没有汇编源文件，也不调用外部汇编器或链接器。

内核是单核微内核：两任务池的运行时创建、等待、终止、回收、复制及消息通信，见[双任务调度](文档/双任务调度.汉语.md)；不指定输入模块时，生成的镜像默认启动早期的整数命令壳（[用户命令壳](文档/用户命令壳.汉语.md)）。以下各节描述内核的最小验证器 `yy裸机验证`：直接把标准 Wasm 整数模块提前编译成机器码运行，不经用户态执行器。普通豫言程序（完整 WasmGC）、持久文件系统、以普通豫言写的壳、子进程与动态装载都在用户态执行器 `客体二号` 上，见上文总览，各阶段实测证据见验证记录。

## 一条命令验证

在仓库根目录、安装 QEMU 后运行：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 文件 豫言操作系统/裸机/验证。豫 --编译器 ./yy4_bs.wasm --输出 yy裸机验证.wasm -j 24
YY_GC_INITIAL_HEAP_SIZE_MB=1024 node --no-liftoff 豫言操作系统/宿主/节点/宿主.cjs yy裸机验证.wasm
```

验证器使用豫言异步子进程，每项约三十秒等待预算；超时按本轮独立进程号文件终止模拟器。全部镜像、输入模块和串口日志保存到新建临时目录，最后打印路径。测试用到宿主的 `mktemp`、`dd` 和 `/bin/kill`；`dd` 只用于负对照改动页表或中断标志，不参与正常镜像生成。

2026-09-28 在 Node 26.3.0 上，`--no-liftoff` 使体积很大的「客体整数执行」夹具直接经优化编译器编译，避开 Liftoff 对单个函数的代码空间限制；上述命令的 380 项双架构验证全部通过，运行约 80 秒。

最初的六项基础检查如下；当前验证器另包含定时器、抢占、结构控制、存储、算术及外部模块等扩展用例，具体数量由运行结果计算：

| 检查 | 客体必须发生的行为 |
|---|---|
| 正常 | 在用户态完成函数调用、局部更新、溢出回绕及乘法核验，然后正常退出 |
| 隔离 | 完成同样核验后，读取内核私有页，产生权限异常；核心核对异常来源及地址 |
| 错误结果 | 将预期四十二改为四十三，核心必须报失败 |
| 放开权限 | 只改受测页表的用户访问位；探测不再陷入，验证必须报失败 |
| 操作数栈越界 | 保持 Wasm 类型正确，压入超过客体栈限额的值；运行时必须报失败 |
| 调用栈越界 | 有效模块进入递归，调用帧越界前必须报失败 |

检查同时匹配退出码和串口文字；负对照禁止出现成功标记。AMD64 使用模拟退出设备：通过退出码为三十三，拒绝为三十五。ARM64 使用半主机退出：通过为零，拒绝为一。串口输出都来自客体实际访问设备；退出机制仅用于结束模拟，不承担程序计算或打印。

## 模块契约与实现边界

输入必须导出无参数、无结果的「启动」。只允许以下函数导入，名字和签名均检查：

| 模块与名称 | 参数、结果 | 实现 |
|---|---|---|
| 平台／写字节 | 一个三十二位整数，无结果 | 经系统调用访问串口，检查字节范围 |
| 平台／核验 | 两个三十二位整数，无结果 | 比较实值与期值，失败立即停止验证 |
| 平台／用户态 | 无参数，一个三十二位结果 | 核心先检查保存的硬件用户态状态，才返回一 |
| 平台／读字节 | 无参数，一个三十二位结果 | 非阻塞读取串口，无数据返回负一 |
| 平台／时钟滴答 | 无参数，一个三十二位结果 | 返回已处理的定时中断计数 |
| 平台／任务编号 | 无参数，一个三十二位结果 | 返回当前静态任务编号 |
| 平台／任务状态 | 一个三十二位参数、一个三十二位结果 | 查询运行状态位，无效编号返回负一 |

当前启动验证协议要求正常结束前恰好完成四次核验；这属于测试协议，不是通用系统调用标准。不能将这些宿主接口误称为 WAT 规定的操作系统接口：模块导入及类型是标准的，平台服务语义由本项目定义。

函数参数、结果置于独立的非 GC 操作数栈，局部变量置于真实调用帧。两套后端均支持整数核心的所有现有指令。操作数栈限一百二十八千字节，调用栈约一百二十八千字节，二者有间隔；压值和分配调用帧时检查边界，超限进入失败路径。函数参数与附加局部合计至多一百二十八项；用户代码至多一兆字节。尚未做寄存器分配或跨函数栈检查消除。

ARM64 以自有 ELF64 头装载，在一级异常层安装页表和异常向量，通过异常返回进入零级用户态。AMD64 以多重引导首版地址头装载，从三十二位保护模式切换到六十四位长模式，安装页表、全局描述符、任务状态段及中断门，再进入第三特权环。QEMU 提供镜像装载入口；尚无磁盘启动扇区或实机固件移植。

两端采用静态两兆字节页映射。AMD64 核心位于低两兆，用户域位于二至四兆；ARM64 核心位于 `0x40000000` 区域，用户域位于 `0x40200000`，另有 `0x40400000` 私有受测页。串口只由特权核心访问。用户代码与用户栈尚在同一可读写用户映射中，未实现页级写入／执行互斥；这些限制不影响当前内核页隔离检查，但还不足以成为不可信程序的生产沙箱。

镜像生成阶段可以在无工具搜索路径时运行。生成器自身目前仍由既有豫言编译器构建；通过 Wasm 执行生成器也仍借助现有宿主。不能把客体无外部编译器与库依赖等同于整个自举工具链已经独立。

## 代码与规范

- `豫言操作系统/裸机/库/裸机后端/机器编码。豫`：字节序、两遍标号解析和重定位。
