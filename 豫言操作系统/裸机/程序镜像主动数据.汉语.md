# 程序镜像的主动数据初始化

用户态 Shell 的程序播种夹具原先把待写入磁盘的每个字节编成一组内存写指令。一个 3,186 字节的普通豫言模块使 ARM64 用户代码达到 1,351,660 字节，超过 1,048,572 字节的可用代码区，甚至无法开始 QEMU 启动。这不是磁盘或 Wasm 文件大小限制，而是测试程序代码膨胀。

现在播种模块把程序字节保留为 Wasm 主动数据段。裸机镜像构造器已有主动数据初始化机制，会把字节放进用户线性内存；Shell 仍通过文件接口写盘并随后从磁盘读取程序。去掉逐字节生成的写指令后，启动与执行路径不依赖测试程序大小生成相同比例的机器码。

以外部 C Wasm 模块运行完整 ARM64／AMD64 QEMU 验收，368 项全部通过，日志与产物位于 `/tmp/yy裸机验证.Jr5w13`。用 3,186 字节普通豫言模块作外部文件时，镜像成功生成并启动，Shell 可列出 `/外部.wasm`；执行该文件报告“程序读取失败，代码 -2”，而不再报告镜像容量错误。该拒绝来自客体 Wasm 执行器尚不支持 `eqref` 和 `struct` 类型，不能据此宣称普通豫言模块已能执行。该次串口日志位于 `/tmp/yy裸机验证.zRvscx/臂六十四-壳程序运行.日志`。

类型段缩减实验进一步确认：仅含 `i32` 返回值的单类型模块经过装载阶段；等形状的 `eqref` 返回值类型在装载阶段被拒绝。普通豫言最小模块的前 17 个函数类型在实验中改成 `i32` 后可通过，紧接着的 `struct` 类型仍被拒绝。这表明后续必须实现保留类型区别的 GC 复合类型表，以及足够宽且有标记的运行时值槽和受根跟踪的堆；不得把 `eqref` 简单当作 `funcref` 接受。
