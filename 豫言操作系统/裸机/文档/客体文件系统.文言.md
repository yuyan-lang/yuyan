# 客体文件系统与用户态块设备驱动

## 何以有此

寻常豫言之程，借标准库 `文件系统` 以读写文件。昔者于裸机，此诸原语徒为空桩，Shell 亦唯用镜像内预置之程。今使标准库之文件原语真落于磁盘：文件系统与 Virtio 块设备之驱动，皆书于客体执行器二号（以[底层模式](../../../应用/豫言编译器/文档/底层模式.文言.md)之常豫言书之，运行于用户态）；内核唯供设备寄存器之窗、IOMMU 所授 DMA 之窗，及两内存搬运之服务。数据盘用标准 ext4（附 jbd2 日志），Linux 之器可径检之。其久存之证，在真 QEMU virtio-blk 磁盘之文件：前后两 QEMU 之进程共一磁盘之文件，后者读回前者所写。

## 文件

|文件（`豫言操作系统/裸机/客体二号/`）|所载|
|---|---|
|文件系统|ext4 之子集：超级块与组描述符表、块缓存、事务、jbd2 日志之书与重放、块与节点之分配、区段树、线性目录、挂载、对外诸操作|
|主机文件|以标准库文件原语映于文件系统：路径规范（当前目录、`.`、`..`、重斜线）、补建祖先目录、列目录、文件原语之分派|
|块设备|Virtio 块设备用户态驱动；Virtio 初置败，则改用内核之 USB 持久块服务（见[持久块接口方案](持久块接口方案.文言.md)）|

`块设备` 无设备时（普通镜像中设备寄存器之服务一概拒之）初置败，`块就绪` 为假，文件原语返输入输出之错；故同一执行器，无盘镜像可行，带盘之设备驱动镜像亦可行。

## 盘之布局

数据盘乃整块之 ext4（不分区）：块设备之扇区零，即文件系统之字节零。盘面之整数皆小端，唯 jbd2 日志中之域皆大端。

- **几何**：块四千零九十六字节（八扇）；每组三万二千七百六十八块，每组四千零九十六节点（inode），节点二百五十六字节。块数 N＝设备扇数除八（末组不足六十四块则舍之）；N 至少二千零四十八，故数据盘至少八兆。
- **特性**：HAS_JOURNAL、SPARSE_SUPER2（超级块与组描述符表唯置于第零组，备份之组数为零）、FILETYPE、EXTENTS、FLEX_BG、LARGE_FILE、EXTRA_ISIZE；dir_index、metadata_csum、64bit 诸余特性皆闭。卷标曰「豫言数据」，UUID 定为 `YUYAN-EXT4-DATA1` 之十六字节。

诸元数据依 flex_bg 聚于盘首，其序如下：

|块|所载|
|---|---|
|0|字节一千零二十四起为超级块|
|1 起|组描述符表，每组三十二字节|
|次|各组块位图，每组一块|
|次|各组节点位图，每组一块|
|次|各组节点表，每组二百五十六块|
|次|jbd2 日志（节点八），连续一千零二十四块（四兆）|
|次|数据区：根目录（节点二）、lost+found（节点十一），次为他目录与诸文件|

- **位图与计数**：块位图之第 i 位示该组第 i 块已用（低位在前）；末组逾盘尾之位一律置一，节点位图自第五百一十二字节起尽填 0xFF，此 e2fsck 所要求也。超级块与组描述符中之空闲块数、空闲节点数，恒与位图相合。
- **节点**：节点一至十一恒为已用（二根目录，八日志，十一 lost+found，余者保留）；寻常节点自十二起，分配时取节点位图之首空位。
- **文件之数据**：以区段树（extent）述之。节点之 `i_block` 置树根：区段不逾四，则径置于节点中；更多则入一区段叶块（至多三百四十区段）。分块先求连续之空闲段，不得则分为数段，每段至多三万二千七百六十八块，且不跨组。
- **目录**：线性之目录项 `ext4_dir_entry_2`（节点号、记录长、名长、类型、名之字节），项不跨块，块内末项之记录长延至块末。删项则并其记录长于前项，块内首项则置其节点号为零。名可为除 `/` 与零字节外之任意字节（UTF-8 中文径用），至多二百五十五字节。
- **lost+found**：根目录下之 `lost+found`，e2fsck 所要求之目录也；列目录时隐之，依路径仍可访。
- **时刻**：执行器新书节点，时刻取墙钟之秒（见[墙钟之务](墙钟服务.文言.md)），墙钟不可得则取二〇二六年一月一日零时；离线造盘一律取二〇二六年一月一日零时。覆写时修改之时取 max(当前墙钟秒, 旧值加一)，使编译之缓存依修改时辨先后，同一秒内两次所写亦可分。

## 事务与断电之安

每改动之操作（写文件、建目录、删除）皆一同步事务，其序如下：

1. 所改之块先置于事务缓冲；提交之前，块缓存与磁盘皆守原样，故弃事务惟清其数。写文件，则先书文件之数据于**新分得之块**而刷新，旧块原封不动。
2. 书日志：描述块（块头加每被录之块一八字节之标签）、被录之块完整四千零九十六字节之副本、提交块；刷新（Virtio 之 FLUSH 请求，USB 存储之同步缓存令）。被录之块首四字节适为日志魔数者，标签带 ESCAPE，副本中书此四字节为零，重放时还之。
3. 书日志超级块，使 `s_start` 指此事务；刷新。此刻事务生效。
4. 诸块回写于原处；刷新。
5. 书日志超级块，`s_start` 清零、事务号加一；刷新。事务号存于日志超级块，重启后接用，不复重。

断电之后唯遇三态：第三步之前，日志无效，原处与旧块皆未动，新数据块亦未为任何元数据所引，文件系统为旧；第三步至第五步之间，下次挂载（豫言或 Linux）重放此事务，文件系统为新；第五步之后，文件系统为新。覆写已有文件，旧块于同一事务中释放，新数据绝不书于旧块，故文件或全旧或全新。重放乃整块复制，可复行，重放中途再断电亦可续放；日志超级块每次唯书一扇，赖设备单扇写入不可分。

读写有误：读盘之误一概报为输入输出之错（与“不存在”相别）；书日志败，则磁盘原处守原样，径弃事务；日志超级块既书之后任何败，皆使文件系统转为唯读，俟重挂载时重放日志。

超级块 incompat 特性中有 RECOVER 位，Linux 见之乃重放日志。豫言于**初开写事务之前**置之而回写超级块，Linux 与 e2fsck 故能于豫言断电之后重放日志；挂载唯读盘，故初次写事务之前，盘上之字节守原样。写之不入（唯读设备）则文件系统转唯读。

## 挂载与日志之重放

挂载唯读超级块、组描述符表与日志超级块，所费之时与盘上文件之数无关。依次校验：

- **超级块**：魔数 0xEF53，块长四千零九十六，节点二百五十六字节，`s_first_data_block` 为零，incompat 特性唯含 FILETYPE、RECOVER、EXTENTS、FLEX_BG 四位（有他位则返「错未挂载」）。compat 与 ro_compat 特性位不核。
- **日志**：循日志节点（`s_journal_inum`）之区段得日志之起块，要求首区段连续且不少于一千零二十四块；日志超级块之魔数、版本二、块长四千零九十六皆须相合，且无任何不兼容特性位。
- **重放**：日志非空（`s_start` 非零）者，自 `s_start` 起依事务号 `s_sequence` 逐事务扫之——块头魔数、类型、事务号皆须合；描述块之标签依次应其后之数据块，遇同事务号之提交块乃为完整；完整之事务依次将数据块回写于原处；位逾日志之末则绕回 `s_first`。诸事务既放，刷新，改日志超级块为 `s_start`＝零、`s_sequence`＝末事务号加一，复刷新。

挂载成功，执行器之诊断输出印“数据盘挂载完成：ext4，共 N 个块”。盘上之内容不合本格式（含全零之空盘，及二〇二六年十月十日以前之旧式盘，旧盘须以离线造盘重造）则挂载返「错未挂载」，读盘败则返「错输入输出」。执行器唯司挂载，数据盘由离线造盘之器造成（见下文“离线造盘”）；验收所用之空盘，乃仅有根目录与 lost+found 之空 ext4，亦由离线造盘所造。

## 对外之接口

文件系统向执行器余部供下列函数。路径皆已规范之绝对路径（`/` 或 `/甲/乙`，无末尾斜线），由呼者予址与长；项即节点号。

|函数|其行|
|---|---|
|`文件系统初始化`|备缓冲与状态（路径缓冲、当前目录初值 `/`、错误码）|
|`文件系统挂载`|读超级块与组描述符表，随需重放日志；成则返「错无」|
|`索引查`（路径）|返项；不得则为负一|
|`项种类`（项）|「种类文件」一、「种类目录」二；项无效或他类则零|
|`项长度`（项）|文件之字节数（目录为零）|
|`项时间`（项）|修改之时（秒）|
|`文件系统读文件`（项，缓冲）|读全文件入缓冲，缓冲至少有长度上取整至五百一十二字节|
|`文件系统读区间`（项，偏移，长度，目的）|读文件自第 偏移 字节起之 长度 字节|
|`文件系统写文件`（路径，数据）|建或整体替换寻常文件；父目录须已在（否则「错不存在」），路径为目录则「错类型」|
|`文件系统建目录`（路径）|父目录须已在；已有则返「错已存在」|
|`文件系统删除`（路径）|删文件或空目录；无则「错不存在」，目录非空「错非空」，删 `/` 返「错参数」|
|`目录遍历`（目录项，游标）|游标为目录内容中之字节偏移（自零起）；每次返一项，并书名、名长、项、种类于状态格，返下一游标，无更多项则返负一；略 `.`、`..`、空项及根目录下之 `lost+found`|

错误之码：「错无」零、「错不存在」一、「错类型」二、「错已存在」三、「错非空」四、「错空间」五、「错参数」六、「错输入输出」七、「错未挂载」八。

## 用户态 Virtio 块设备驱动

协议同 `库/编译器核心/网页汇编核心/虚拟磁盘。豫`（现代 PCI、`VERSION_1` 与 `ACCESS_PLATFORM`、`FLUSH` 为必需、记只读位、有界遍历 PCI 能力链以核通知窗与设备配置窗、单队列大小八、同时一请求、配置世次前后一致方采容量、头／数据／状态三描述符（刷新则略数据）、轮询已用环而核描述符号、状态字节及已用长度）。所异者在 DMA 缓冲之所在：

- 执行器之线性内存逾八页，则迁入内核之动态块（见[内存块管理](内存块管理.文言.md)）；而设备唯经 IOMMU 访内核所授之**静窗**（用户空间静区 `0x40300000`／`0x300000` 起 0x80000 字节，设备址＝静偏移＋`0x1000`）。故驱动置描述符表、可用环、已用环、请求头、状态字节与五百一十二字节之数据缓冲于静窗内 `0x70000` 至 `0x70400`，用户态唯经二新内核服务以存取：
- **服务二四 `搬入静态(线性偏移, 静态偏移 | 长度<<20)`**、**服务二五 `搬出静态(…)`**：于任务之线性内存（基址寄存器 ARM64 x28／AMD64 r9，静或迁入动态块后皆可）与其静窗之间，复制至多四千零九十五字节。越界（静窗 0x80000；线性内存未迁时 0x80000，既迁则块数乘二兆字节）返负一，成则返零。窗属任务自己之地址空间，故任何任务用之，皆不出己之内存；内核关中断而逐字节复制，无抢占。
- 驱动唯于线性内存已逾八页（即已迁，静窗与线性内存不相叠）时始初置。
- `设备驱动镜像` 今受可增之线性内存：上限等于初值者（固定内存）仍只授此区间（旧用例不变），否则授整个八页静窗。

发布请求之序：写头、写描述符、写数据（写请求）、写环项，以设备寄存器一读为屏障，再进可用索引，终写通知寄存器；然后轮询状态寄存器与已用环索引，逾时（一百万次）或状态异则返负一。

## 宿主原语

标准库 `文件系统` 之 `读文件`、`读文件字节串`、`写文件`、`写文件字节串`、`删文件`、`读文件夹`、`路径存在`、`路径是文件夹`、`路径是普通文件`、`切换当前工作目录`、`创建文件夹`、`获取当前工作目录`，经带型之宿主导入映于上述文件系统（挂载唯执行器启动时内用之）；路径先规范为绝对路径，所缺祖先目录随需而建。

## 离线造盘

`豫言操作系统/裸机/库/裸机后端/持久盘构造。豫` 依上文之盘面于离线造镜像，其式与 `客体二号/文件系统。底层。豫` 必同步。

- **所出确定**：目录（父先于子）先于文件，节点号与块号依入之次序顺序而分，文件之数据连续而置；日志洁净（日志超级块 `s_start` 为零、`s_sequence` 为一）；诸时刻皆取定值（二〇二六年一月一日零时）。同参所造，逐字节同；诺节与原生所造者亦同。
- **容量**：至少一万六千三百八十四扇（八兆）。`按参数造持久盘` 造全盘；`按参数造持久盘前段` 唯造至末一已用块而止，后皆为零，`yy豫言系统` 书其前段而以 dd 扩文件至全盘之大，成疏文件，数吉之数据盘亦不必于内存拼全盘。
- **参数**：`+盘内目录` 与 `盘内路径=本地文件`，所缺祖先目录自补；`目录树造盘参数` 以一棵本地目录树为盘根（依字节序排之）。不予一文件，则所造者乃仅有根目录与 lost+found 之空 ext4。
- **做法**：先依诸文件之长算布局，开全零之字节缓冲，书超级块、组描述符、位图、日志、节点与目录块，乃逐读诸文而书之，入缓即弃，内存中唯此缓冲与当前一文。
- **读器**：`持久盘读取。豫` 乃宿主侧至简之读器：予镜像之字节串，按路径列目录（名与类）、读文件（循区段树）、查位图与节点，供试验与他日自 U 盘取文。
- **命令行**：`yy造盘 输出.盘 容量扇区 [+盘内目录]… [盘内路径=本地文件]…`。所产已格式化，充 QEMU 之 virtio-blk 磁盘，客体挂载即见诸文件。

## 界与后版

界取其大：

- 路径至多一万六千字节，每段之名至多二百五十五字节。
- 一事务至多二百五十六已改之块；日志一千零二十四块，一描述块容二百五十六标签。
- 一文件至多三百四十区段（一区段叶块之容），连续分配时每段至多三万二千七百六十八块（一百二十八兆）；分段过多则书返「错空间」。
- 文件之长按三十二位计；扇号按三十二位计，数据盘之容以二 TiB 为限（离线造盘之块号容十六 TiB 以内之盘）。
- 元数据之读经二百五十六槽之块缓存（直接映射，每槽四 KiB）。
- 日志定为一段连续之区段。

文件接口供整体之书（建或整体替换）；欲追加，则呼者读出旧内容而整体书回。文件一律 0644、属主零，修改之时取自节点。

留待后版：

- 日志重放遇撤销块（类型五），则挂载返「错输入输出」；撤销块与带校验和之日志，留待后版支持，Linux 所遗之脏日志中或有撤销块。
- compat、ro_compat 特性位不核，带 dir_index、metadata_csum 之外来 ext4 盘因而可读；于此类盘之写，须维护散列目录与校验和，留待后版为之保护，今写以豫言自造之盘为准。
- 逾三百四十区段之文件（多叶块或更深之区段树）、二 TiB 以上之数据盘（须六十四位扇号与 64bit 特性）。
- 关机时清除 RECOVER 位（所写之盘恒带之，Linux 挂载时读一遍洁净之日志，其果不变）。
- 原地追加与部分之书、权限、符号链接与硬链接、扩展属性。
- 文件系统行于持盘之初始任务，子任务之文件事逐信转初始任务办之（见[客体二号](客体二号.文言.md)之“子进程中之文件”）。块设备之中断与并发请求留待后版，轮询之上限一百万次。
- QEMU 与实机上之真实断电注入（今之断电验以宿主侧模拟为之）。

## 验

- **两架构 QEMU**（ARM64 SMMUv3、AMD64 Q35/VT-d，virtio-blk 加 `iommu_platform`）：`yy普通豫言验证` 凡一百零六项：九十七项过，余九项为登记之已知失败（兼容壳试大段区不足诸旧事，不计为败）。其中 `普通探针/盘/文件-一`（多层目录、覆写、逾一扇区之内容、存在与类型之判、删除、列目录）及其后之 `文件-二`（新 QEMU 之进程，读回文件-一所写者），输出与参照逐字相合；同组诸阶依序行于同一磁盘，第一阶用宿主离线所造之空盘（十六兆之空 ext4，唯有根目录与 lost+found）。
- **新增之盘探针**：`ext4压力-一`（一目录纳一百五十长名之文使目录增为多块，删三之一，覆写大小各异之内容，书约一兆之大文，建多层目录而去之）、`ext4压力-二`（新 QEMU 之进程读回）、`ext4目录-一`（建目录、项数、根目录隐 lost+found）。
- **预置盘**：`普通探针/盘/预置.预置/` 目录树，由 `yy普通豫言验证` 造成十六兆（三万二千七百六十八扇）之盘，内有跨扇区之文件一，四千五百字节（壳试之盘为六万五千五百三十六扇）；`预置-一` 于两架构读预置之文而再书一新文，`预置-二`（新 QEMU 之进程）读回二者。
- **真 e2fsck 之检**：试验所遗二十九块盘，皆以 e2fsck 1.42.13 `-fn` 检之，无一问题；离线造盘之七况同无问题，且与 mke2fs 1.47.2 所造参考盘逐域对照（唯可选之域与块之位置异，见[裸机后端包说明](../库/裸机后端/包说明.文言.md)）。
- **断电与互通**（置于草稿目录之宿主侧夹具：内存盘、断电及读写误之注入）：约八百次模拟崩溃，以真 e2fsck `-fy` 重放豫言所书之日志，所得盘面与豫言自行重放者相合；豫言能读写 mke2fs 所造之盘。
- **离线造盘**：以 `库/` 目录树（六千八百七十六文）造四 GiB 盘之前段，约一百九十五 MB，用一至二秒，诺节与原生所造之镜像逐字节同。
- **内核之务**：一底层模式之测试程序（`底层探针/搬运`，包 `搬运探针`）直作用户程序装入内核镜像，于静态之阶与迁入动态块之后，各往返复制，测越界（静窗、线性之上限）、恰在边界、四千零九十五字节之整块，两架构串口皆报通过。
- 磁盘探针置于 `豫言操作系统/裸机/普通探针/盘/`，名曰 `组名-一。脚本。豫`、`组名-二。脚本。豫`……；同组诸阶依序行于同一磁盘，唯第一阶新造盘。

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 文件 豫言操作系统/裸机/普通豫言验证。豫 --编译器 ./yy4_bs.wasm --输出 yy普通豫言验证.wasm -j 24 -- --do-not-optimize
node 豫言操作系统/宿主/节点/宿主.cjs yy普通豫言验证.wasm --只验 文件
node 豫言操作系统/宿主/节点/宿主.cjs yy普通豫言验证.wasm --只验 ext4
```
