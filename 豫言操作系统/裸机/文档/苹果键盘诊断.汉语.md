# 苹果键盘实机诊断

用户实测 MacBookPro11,1：原候选 ISO 显示正常，内置键盘和后来接入的外接键盘均不能输入。经授权 SSH pit-mbp13 读取 Linux 信息：Intel xHCI 8086:9c31，BAR B0A00000、64 KiB，HCCPARAMS 200077C1，使用三十二字节上下文。外接 SONiX 413d:2114 直连 USB 2 根端口二，低速，接口零为 boot 键盘，IN 81、最大包长八、间隔十；内置 Apple 05ac:0259 直连根端口五，全速，接口零为 boot 键盘，IN 83、最大包长十、间隔八。两者不经过蓝牙集线器。

诊断产物使用原实测镜像的源码基线 00dc0cb1b，加入 USB 启动屏幕快照。当前 yybs 550386101 的启动盘构建报用户代码 701684 字节、可用 263592 字节，此布局阻塞已向终端会话报告；本任务不借机修改其界面、输入法、字体和用户布局。诊断镜像与正式候选分开保存，不据原基线验收声称当前全部上游已通过。

## 使用

端口路由核查依据：Linux `drivers/usb/host/pci-quirks.c` 的 `usb_enable_intel_xhci_ports` 在发现 Intel EHCI 同伴后，先把 PCI `DC` 的 USB3PRM 写入 `D8` 的 USB3_PSSEN，再把 `D4` 的 USB2PRM 写入 `D0` 的 XUSB2PR；无 Intel EHCI 则返回。源码见 https://github.com/torvalds/linux/blob/master/drivers/usb/host/pci-quirks.c 。当前豫言控制器初始化没有对应路由写入，但这一差异尚不能证明 Mac 根因；须核实该机 EHCI 清单和四个寄存器值，再决定是否适用。SSH 连接超时，尚未取得这些值。若路由已正确，继续检查复位后设备重新连接至首次扫描之间的等待。

把诊断 ISO 写到明确选定的测试 U 盘；外接键盘在开机前插好。Mac 按 Option 开机并选 EFI Boot。报告观察版显示“USB按住H六秒”后，按住外接键盘 H，直到诊断行出现，再拍下全部 USB 行；此前版本只显示启动快照。真实键盘修复尚未完成。

## 字段

所有数字为八位十六进制。内部端口表为 0x12B000 至 0x12CFFF，每端口三十二字节；诊断保存寄存器与标志，复用既有串口及帧缓输出，无新增应用 ABI。

| 行 | 各列含义 |
| --- | --- |
| USB PCI | PCI 配置地址、类码、BAR 低字、高字 |
| USB ROUTE | PCI 设备身份双字、D0 路由值、D4 USB 2 路由掩码、D8 SuperSpeed 使能值、DC USB 3 路由掩码 |
| USB CTRL | 控制器阶段、最后寻址状态、操作寄存器虚址、scratchpad 数 |
| USB ENUM | 最大端口数、成功寻址数、完整描述符数、扫描状态 |
| USB KEY | 键盘配置状态、端点初置状态、端点命令完成码、选定槽号 |
| USB EP | IN 端点地址、最大包长、报告完成码、累计成功报告数；报告观察版之前第三列为间隔 |
| USB P02、P05 | 初始 PORTSC、寻址状态、寻址完成码、首描述符状态、完整枚举状态、枚举步骤、当时全局键盘配置状态、VID/PID 双字 |

PID 在最后一字的高十六位、VID 在低十六位；只有完整描述符成功时才据它识别设备。键盘状态是全局选定键盘的状态，不能把它当作每个端口都已配置成功。

后续诊断源码增加 USB ROUTE 行，以 PCI 配置地址端口读取这些值，只写地址选择端口，不写设备配置寄存器。其镜像构建和运行验证尚待完成；上述 b9eb 镜像没有此行。D0 至 DC 的含义仅在对应 Intel 控制器上解释，其他控制器只记录原值。

路由诊断的裸机后端整包类型检查退出零，诊断系统工具构建退出零。以当前工作树生成启动盘仍失败：用户代码 701684 字节，可用 263592 字节；因此没有当前上游的可交付 ISO。另在干净的原苹果候选工作树应用已提交的诊断补丁和路由只读输出，该树后端原稿与 00dc0cb1b 相同，独立构建正在进行。它只用于收集实机根因证据，不能作为当前上游全部功能的验收。

人工复核表明：后续端口失败不会直接清除已选择键盘的槽号；首报告请求使用保存的键盘槽号，控台事件轮询以控制器启动状态一为入口条件，不以最后端口的寻址失败状态为条件。目前没有证据证明后续失败覆盖外接键盘配置。报告接收代码对匹配槽、端点和请求地址的事件只接受完成码一且剩余长度零；短包完成码十三会将端点状态置失败，尚未证明实机触发此路径。下一次诊断需要记录运行中的事件完成码和报告计数，并细分五端口的复位与槽等待失败；输入故障根因及修复仍未确认。
