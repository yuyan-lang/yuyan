# 原生终端适配核查

本次只接通既有公共终端能力。标准库 `宿主。接口。豫` 的读取、进入、退出签名保持原样，带型宿主编号九十三至九十五保持原样，接口清单与宿主提供 JSON 无需再生成。终端尺寸公共接口等待用户授权，本文范围为已有按键和模式能力。

`客体二号/平台。豫` 的 `读字节原始` 已调用 `原生_读(0,状态_林字节,1)`，读到一字节返回它，零长度返回负二。`主机。豫` 的等待函数只重试负一，九十三把负二映为失败和空字符串。模式缺口为九十四原生固定返回否、九十五直接无事。本次导入已有 `原生底层`，九十四调用 `原底_设终端模式(0,1)`，状态零映为阳；九十五调用 `(0,0)` 恢复。

底层已有 macOS TIOCGETA/TIOCSETA、Linux TCGETS/TCSETS 和 Windows 控制台分派。非终端返回既有状态码五十九。模式一保存原设置、关闭规范输入与回显，设置 VMIN 一、VTIME 零；恢复复制原设置。没有新 ABI，没有读取超时，没有阻塞终端尺寸探测。

以上命令尚未执行，包入口参数须在授窗后由当前豫构确认。PTY 启动前用现成 `stty -g` 记录模式，在同一 PTY 中运行原生程序；看到“原生终端按键就绪”后，工具 `write_stdin` 发送字节 `1B 7F E4 B8 AD 0D`，不追加换行。预期程序打印“原生终端按键通过”并退出零。退出后在同一 PTY 再取 `stty -g`，要求与进入前一致，证明恢复真实终端设置。另以重定向空标准输入运行，预期进入失败而快速退出，不能将此失败算作 TTY 验证成功。预编二模式另生成对应程序并重复同一 PTY 流程。

当前证据仅为源码核对、源格式化与差异检查。类型、构建、TTY 进入成功、实际按键消费和恢复均尚未实测。
