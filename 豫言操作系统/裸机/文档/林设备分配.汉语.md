## MSI-X 能力只读采集

`固件候选` 在 DRHD 候选选定后扫描所选物理功能的标准 PCI 能力链。结果从 `0x060140C0` 起为六个双字：状态、能力偏移、控制字、表字段、PBA 字段、向量数。状态零为未完成，一为无 MSI-X，二为采集完成，三为拒绝。链最多检查二百五十六项；指针须至少 `0x40`、四字节对齐，MSI-X 十二字节能力不得跨配置空间末端，表和 PBA 的 BAR 索引须为零至五。向量数取控制字低十一位加一，表及 PBA 字段保留原值供后续按 BAR 定位。[Linux PCI MSI-X 字段定义](https://raw.githubusercontent.com/torvalds/linux/v6.12/include/uapi/linux/pci_regs.h)

能力采集只读配置，不写控制字、不开放 DMA 或消息中断。状态二仅表示能力字段已取得；候选模式随后执行下节的宿主只读表采集。表项拦截、消息地址转换及 APIC 注入继续待接。记录不等于中断转交完成。其它设备模式不生成此采集代码，既有网卡路径保留。

2026-10-04 Q35/KVM 的 PCIe 根端口后 e1000e `01:00.0` 实测记录为 `2 / 0xA0 / 4 / 3 / 0x2003 / 5`：五个向量，表在 BAR 3 偏移零，PBA 在 BAR 3 偏移 `0x2000`；QEMU 记录 BAR 3 为 `0xFE640000`、16 KiB。配置控制字未置 MSI-X 使能，VT-d GSTS 与根地址仍零。[QEMU e1000e 的 MSI-X 初始化](https://raw.githubusercontent.com/qemu/qemu/v10.2.1/hw/net/e1000e.c)

同镜像换 e1000 后，状态为一，其余字段零。坏链负对照在真实能力指针读取后核对原值 `0xC8`，以人工寄存器输入 `0x41` 替换，状态三、其余字段零。三种环境均通过极小客体寄存器保存、末页写入、HLT、VMCS 回收与 VMX 退出回归。构建、类型检查、格式化、差异检查通过；固件网卡网络镜像与低地址 MMIO 轮的已验镜像逐字节相同。采集镜像 SHA-256 为 `7830a8db7ab942d0592f537bfc6bd01608ca974859328e6f9a7e3e0a03545649`。真实设备 MSI-X 与 GPU/CUDA 仍未验收。

## MSI-X 表宿主只读窗口

固件候选模式在能力采集后，先接已核验 QEMU e1000e `8086:10D3` 的十六 KiB BAR 3。要求内存解码开启、总线主控关闭、MSI-X 未使能；核对表和 PBA 的 BAR 索引、各自偏移及完整长度，偏移先独立检查，避免长度相加回绕。BAR 须为二至四 GiB 内、十六 KiB 对齐的三十二位内存资源，并避开已采集 DRHD 寄存器。此处复用现有保守的 128 KiB 寄存器重叠检查。[QEMU e1000e BAR 定义](https://raw.githubusercontent.com/qemu/qemu/v10.2.1/hw/net/e1000e.c)

宿主以 `0xFF800000` 私有窗口访问对应两 MiB 物理块，页项为 supervisor-only、不可缓存、只读，并开启 CR0.WP。重新挂接被 DRHD 只读采集撤下的高区页目录父项，再刷新 CR3。按实际向量数复制完整表到宿主 `0x06300000`，复制完整 PBA 到 `0x06308000`。`0x060140E0` 起五个双字依次为状态、BAR 基址、物理表地址、物理 PBA 地址、向量数；状态一为无能力，二为完成，三为拒绝。只有状态二的快照可用；窗口及快照均不加入客体 EPT。

2026-10-04 Q35/KVM 的桥后 e1000e 实测为 `2 / 0xFE640000 / 0xFE640000 / 0xFE642000 / 5`，五个表项各为消息低址零、高址零、数据零、掩码一，PBA 八字节零。读取后父项为 `0x0600C023`，窗口页项为 `0xFE6000B9`，均含硬件访问位；页项写位为零，CR0 为 `0x80010011`，包含 WP。VT-d GSTS 与根址仍零，客体 EPT 高区项仍零；极小客体寄存器、末页、HLT、VMCS 回收、VMX 退出均通过。首次遗漏父项导致的页故障已修复，失败尝试不计入验收。

写保护负对照在窗口建立后，GDB 核对 WP 已启，再用镜像既有 CPU 存储指令向 `0xFF840000` 写人工哨兵；CPU 发生页故障，CR2 为该址，物理表首项仍为 `0 / 0 / 0 / 1`。越界对照在表采集前把能力记录的原表字段三人工换为 `0xFFFFFFFB`，采集状态三、其它结果字段零，父项和窗口页项均零；随后微客体回归通过。无 MSI-X 的 e1000 返回状态一，窗口未建立，回归通过。构建、类型检查、格式化、差异检查通过；网络镜像与此前已验镜像逐字节相同。最终镜像 SHA-256 为 `66bb25499181354c43fa41fdb3056b75148f61d7fb27fd18f29985b5b4510315`。

## 宿主 xAPIC 接收与 EOI 基础验收

## 隔离下的设备 MSI-X 到达

`固件隔离` 在空 DMA 根表开启后，对已核验 e1000e 执行设备消息验收：`节点 yy林虚拟化探测.wasm yy林设备消息.bin 固件隔离 0 1 0 0`。要求消息表已采集、隔离就绪标记一、能力位于 `0xA0`、收发队列关闭、原 IMS 为零，且 BAR 0 与 BAR 3 同在一个两 MiB 块。此路径用于验证设备消息链路，最终网卡管理仍交由 Linux 客体现成驱动。

复用宿主 xAPIC 的临时入口，以设备触发片替代自投递。表窗口临时可写，在函数级屏蔽下设置零号表项的消息地址为宿主 APIC ID 对应地址、数据为向量 240，再设置 IVAR 的 OTHER 项与 IMS。临时开启总线主控及 MSI-X，写 ICS 的链路状态变化原因四；e1000e 将其并入 OTHER 原因并通知零号向量。[QEMU e1000e 中断原因与 MSI-X 通知](https://raw.githubusercontent.com/qemu/qemu/v10.2.1/hw/net/e1000e_core.c) 普通 DMA 根表保持空，中断重映射保持关闭，兼容消息路径转交宿主 APIC。[QEMU VT-d 消息路径](https://raw.githubusercontent.com/qemu/qemu/v10.2.1/hw/i386/intel_iommu.c)

宿主收到后先关闭 IF、屏蔽设备消息，恢复原命令字、MSI-X 控制、首表项、IVAR、IMS 和旧原因，再恢复窗口只读权限，最后恢复宿主中断设置。`0x06014140` 起十二个双字记录阶段、原命令字、寄存器窗口地址、表窗口地址、原 IVAR、原 IMS、原 MSI-X 控制、旧原因、原页项、触发后原因、恢复后命令字、恢复后控制。阶段一为已准备，二为已恢复，三为前置条件拒绝；到达次数仍读 `0x06014104`。

2026-10-04 默认及 `kernel-irqchip=split` 两种 Q35/KVM 环境均收到一次消息，宿主应答状态二、设备阶段二。原因记录 `0x81000004`，原与恢复后的命令字均 `0x103`、MSI-X 控制均四；首表项恢复为 `0 / 0 / 0 / 1`，窗口恢复为只读页项 `0xFE6000B9`。ISR/IRR 后验位零，GSTS 为 `0xC0000000`、根址 `0x0600D000`、根表为空，VT-d 故障状态零。split 的硬件跟踪确认 `e1000e_irq_msix_notify_vec` 发出零号向量，VT-d 收到 `0xFEE00000 / 0xF0` 并按同值转交；两种环境的极小客体回归皆通过。

前置条件负对照在设备触发前核对隔离就绪记录一，再人工改为零；设备阶段与宿主应答状态均三、次数零，首表项未改，窗口仍只读，微客体回归通过。此只验证就绪记录检查，硬件翻译仍开启。构建、类型检查、格式化、差异检查通过；原网络、自投递镜像逐字节不变。最终镜像 SHA-256 为 `8dda5ce1b35539fd0b3ec8050f2b2d74f98a9fdcad8321d71d9918594f43a69c`。Linux 客体消息注入、MSI-X 网络收发及真实设备、GPU/CUDA 仍待接入和验收。

## 二至三 GiB 的设备 MMIO

固件网卡接受的三十二位 BAR 0 范围扩展为 `[0x80000000, 0xFFE00000)`，仍要求 128 KiB 对齐。二至三 GiB 使用宿主专用页目录 `0x06017000`，PDPT 项 `0x00111010` 指向该页；三至四 GiB 沿用 IOMMU 私有窗口所在的原页目录。客体 EPT 按实际 BAR 的 GiB 区间只挂接一个设备页目录，不建立另一 GiB 区间的别名映射。设备仍只映其 128 KiB，I/O、DMA 和中断授权范围保持既有规则。

2026-10-04 Q35/KVM、二 GiB RAM、e1000 `00:04.0` 中，在完整启动至 BAR 读取前用 GDB 执行镜像既有端口写指令，将模拟设备真实 BAR 0 改为 `0x88100000`；随后实际 PCI 读取返回同值，QEMU `info pci` 也确认该地址。Linux 6.12.112 的两轮六项 TCP 应用验收均通过，第二串口为 `null`。宿主目录项 `0x06017200` 为 `0x8800009B`，EPT PDPT 项 `0x06004010` 为 `0x06015007`，下一项保持零；设备首个客体页 `0x06016800` 为 `0x88100003`。物理请求与客体注入计数均为一百零五。

同一修改后的生成器以 PCIe 根端口后 e1000 `01:00.0`、实际 BAR `0xFE600000` 回归，在 `kernel-irqchip=split` 下完整 TCP 验收通过；EPT PDPT 的低区项为零、高区项为 `0x06015007`。负对照在实际 BAR 读取后把输入寄存器人工改为 `0x40000000`，初始化拒绝，根表与所选上下文保持零、就绪标记一；此值只用于范围拒绝验证。首次跳过启动准备的调试尝试无效，不计入验收。构建、类型检查、格式化与差异检查通过；旧固定 `网卡` 镜像逐字节不变。低地址测试镜像 SHA-256 为 `40030aa0423bfdd0f923f34bca5407993d09008116743ed927eb126c59d98974`。

此项接通真实网卡所处地址区间的模拟 MMIO 路径。I225-V 的不同 BAR 大小、BAR 3、`igc` 与 MSI-X，以及 GPU 的六十四位大资源仍待接入和实测。

## DMA 页授权实测

2026-10-04 在同一 Q35/KVM 平台增加 EDU `00:04.0`，以真实设备传输验证 VT-d。BAR 为 `0xC0000000`，位于二 GiB RAM 之外；宿主以 supervisor-only、不可缓存大页访问。上下文与四级转换表保留在 `0x0600E000` 至 `0x06012000`；设备地址 `0x1000` 映到宿主 `0x58000000`，属于 Linux 客体的宿主物理区。客体 EPT 不含这些表页或设备寄存器。

EDU 先把设备内四字节零值写入授权页，核对目标确已改变及相邻哨兵未变。随后向 `0x2000` 发出未映请求、将原叶项改只读后重试、撤销原叶项后重试，均通过。每次改权限前等待设备传输完成并关闭总线主控；改叶项后刷新全局 IOTLB 并核对硬件完成与实际失效范围。每次拒绝均核对哨兵、故障待处理位、目标地址、设备编号 `0x20`、写访问与无写权限原因码五，再清故障记录并确认待处理位消失。[EDU 设备协议](https://www.qemu.org/docs/master/specs/edu.html)、[QEMU VT-d 寄存器与故障码](https://github.com/qemu/qemu/blob/v10.2.1/hw/i386/intel_iommu_internal.h)

`设备保护对照` 故意在只读阶段保留写权限。实测先观察保护区已被改写，随后保护核验失败并停机，未进入客体。正常路径四项 DMA 验收后，极小客体回归通过；完整 Linux 启到 PID 1，同一虚拟机两个独立客户端均通过六项服务验收。最终源码构建、类型检查通过，测试虚拟机均由外层超时结束。

## 固件基址动态寄存器访问

`固件定位` 模式继续调用 `林固件寄存器。豫`，遍历已核验 DMAR 的 DRHD，检查子表边界、基址非零、页对齐与五十二位范围，再将基址所在两 MiB 物理块映至宿主专用 `0xFFE00000` 窗口。页为 supervisor-only、不可缓存，切换映射后刷新 CR3；完成或可检测失败时移除 PDPT 高区入口并刷新。该模式使用初置时空闲的高区，不写 VT-d 控制寄存器，未开启 DMA 或分配设备。
