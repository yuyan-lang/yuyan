# 寄存器降级

## 为什么重写降级

旧降级把每个 Wasm 操作都过内存操作数栈：每次压栈要读栈指针、比较上限、写值、加十六，每次弹栈再减、读；比较、选择、除法各自展开十几条指令，平均每个操作约三十三字节机器码。ARM64 的文件命令壳因此已占用约 978 KB／1 MiB 代码预算（见[臂常量装载](臂常量装载.汉语.md)），而扩展执行器（具体类型 `ref.cast`、引用字段与数组、异常、尾调用等）几乎必然超限，运行也很慢。

寄存器降级（[寄存器降级。豫](../豫言操作系统/裸机/库/冶铸/寄存器降级。豫)）把虚拟操作数栈映射到寄存器，并做几项廉价而有效的融合。ARM64 命令壳从 978 KB 缩到 162,900 字节，AMD64 从 798,873 缩到 184,000 字节。

## 设计

- **栈槽即寄存器**：虚拟操作数栈第 d 项固定映射到物理寄存器，超出寄存器数的项溢出到帧槽。ARM64 用 x19–x22 共四个，AMD64 用 rbx、r12、r13 共三个；其余被调用者保存寄存器（ARM64 的 x23、x24、x26、x27，AMD64 的 r14、r15、rbp）留给局部。它们都由被调用者保存，函数只保存实际用到的那几个。栈深在编译期已知，所以“丢弃栈顶几项”“分支时调整栈高”都不产生代码。
- **基址寄存器**：ARM64 的 x28 是线性内存基址，x18 是当前内存字节数（页数左移十六位），x25 是全局值起址；AMD64 对应 r9、r8、r10。入口设置一次，之后不再保存。
- **内部临时**：ARM64 x9–x13；AMD64 的 rax、rcx、rdx、r11 供原语内部使用，rsi、rdi 是溢出操作数的临时。操作数栈项可能是寄存器局部的别名（`取读`），所以原语只读取读来的操作数，要改写时先拷进临时（如写八偏：ARM64 把地址加偏移写进 x12，AMD64 先把地址拷进 r11 再加偏移）。
- **访存寻址**：AMD64 可信代码的访存在静态偏移放得进 disp32 时，只把地址零扩展进 r11，用 `[r9 + r11 + 偏移]` 寻址，省掉单独的加法。
- **局部变量**：按活跃段分配寄存器（ARM64 另可用调用者保存的 x3–x8、x14，区间里有调用时前后存取；AMD64 在 Linux 上另用 r10，全部函数可信时（原生预编二构建）再加 r8，这时访存省去查界，页数改从页数格 `0x2FFFFC` 读，批量内存助手也按页数格算界），分不到寄存器的在帧槽。序言只给入口处活跃的局部（读前未写的那些）赋初值或清零。参数从 x0–x7（AMD64 为 edi、esi、edx、ecx）进入，序言写入局部寄存器或局部槽，多余参数经共用暂存区传递（ARM64 `0x40380000` 起、AMD64 `0x380000` 起，每个四字节）——这块地址原先是内存操作数栈，现已空出。
- **帧布局**：ARM64 自 sp 向上为 x30 与第一个被调用者保存寄存器（各八字节；帧不超过 504 字节时序言用一条前变址 stp 同时减栈与保存这两个，尾声用一条后变址 ldp 取回并加栈）、其余被调用者保存寄存器对（固定预留六十四字节，使局部偏移不随所用寄存器数而变）、局部槽、溢出槽，总大小十六字节对齐；AMD64 先 push 被保存寄存器，再 `sub rsp`，局部槽和溢出槽自 rsp 起。序言把 sp 与调用栈下界（ARM64 `0x403D0000`、AMD64 `0x3D0000`）比较，低于则陷阱。
- **陷阱指令**：`unreachable`、越界检查与栈下界检查的陷阱按目标出指令。裸机用户态是 ARM64 `svc #7`、AMD64 `mov eax, 7; int 0x80`，内核按用户陷阱终止任务；豫行程序经服务门第 7 项。宿主目标（Linux、macOS、Windows，2026-10-14 起）是 `brk #0`／`ud2`，进程收到 SIGTRAP／SIGILL（Windows 上是异常）立即结束，退出状态在 Linux 与 macOS 上 ARM64 为 133、AMD64 为 132。内核态见下文。
- **待发状态**：`i32.const` 与比较指令并不立即发码，而是登记为“待发常量”“待发比较”，由下一条指令决定如何融合：
  - 常量之后的加减、与或异或、乘、移位、比较改用立即数形式；
  - 六十四位常量之后的加减、与或异或、移位同样用立即数形式（宽立融合）：AMD64 的加减与或异或要求常量在有符号三十二位内，五种移位取低六位；ARM64 的加减要求绝对值不超过 4095，左移与两种右移取低六位。六十四位地址构建里执行器的址运算、回收算卡号多是这种形式；
  - 比较之后的 `br_if`、`if` 直接发条件分支，不再先 `cset` 成 0／1 再测；
  - `i32.eqz` 施于待发比较即取反条件，施于待发常量即折成新常量；
  - 其他指令前先把待发项落成真实寄存器值。
- **控制帧**：每个 `block`、`loop`、`if` 记录种类、基深、结果数、分支标号、结束标号与否则标号。跳到某帧时，把栈顶的结果数个值依次搬到该帧的基深槽，被丢弃的中间槽无需处理。`br`、`return`、`unreachable` 之后到匹配的 `else`／`end` 之间视为死代码，只按嵌套计数略过。
- **多结果**：函数与块至多返回若干个值，函数结果走结果寄存器（ARM64 x0–x3，AMD64 eax、edx、ecx），调用者随即搬入新的栈槽。
- **批量内存**：`memory.copy`、`memory.fill`、`memory.init`、`memory.grow` 各由整个模块共用的一份助手实现，越界一律陷阱，重叠复制按地址关系选择方向；数据段描述符是四字节有效长度后接原始字节，`data.drop` 把长度写零。
- **入口存根**：设基寄存器，读页数描述符，调用启动函数，探测模式再读一处内核私有地址（必然缺页，证明隔离），最后以退出码零请求完成服务。
- **函数内连接**：每个函数降级完立即在函数内连接：除函数入口外，标号都只在本函数内使用，指向它们的相对跳转（相对位移只看两址之差）就地编码，并与相邻的原字节并成一片；只留下入口标号、指向别的函数或助手的相对片与绝对地址片，交给最后的连接。几百万个片因此变成每个函数寥寥几片，大模块降级时的存活内存与最后的连接都省下大半。函数体按需取：模块里的函数项可以是占位，降级与内联前经 `降级取体` 的钩取真正的函数体（预编二借此按需转译客体函数）；遍历两万多个函数用尾递归的带序映射，栈帧里不留各函数降级的临时数据。

同一份遍历供两个架构使用，架构差异只在“指令原语”层：`指移`、`指二元`、`指载存`等包装函数按第一个参数分派到[臂降级原语](../库/裸机后端/臂降级原语。豫)或[兼降级原语](../库/裸机后端/兼降级原语。豫)，原语再由[臂汇编](../豫言操作系统/裸机/库/冶铸/臂汇编。豫)与[兼汇编](../豫言操作系统/裸机/库/冶铸/兼汇编。豫)编码。两个汇编器的编码器都有单元测试（ARM64 六十余例、AMD64 四百六十例）。

## 结果

| 用例 | 旧 ARM64 | 新 ARM64 | 旧 AMD64 | 新 AMD64 |
|---|---|---|---|---|
| 文件命令壳 | 约 978 KB | 162,900 | 798,873 | 184,000 |
| 程序壳播种 | — | 164,068 | 802,844 | 185,147 |
| 客体执行用例 | — | 136,472 | 731,372 | 156,906 |

不带外部模块两架构共 362 项，带外部模块 370 项，QEMU 全部通过，整轮约七十秒。

## 副作用与踩过的坑

- 用户代码快了二十倍以上：多任务用例里一百万次的“长循环”不再跨越一个时钟周期，`双任务`、`定时中断` 等验证抢占的场景因此失败。新增[长算常量。豫](../豫言操作系统/裸机/库/冶铸/长算常量。豫)，把这些循环改为两千万次，每个任务约百毫秒，横跨数十个时钟周期。
- 探测读必须在启动函数**返回之后**：`设备缺页退出` 等场景正是靠父任务返回后的那次读引发缺页。
- AMD64 的载入种类编号与 ARM64 不同（零扩展／符号扩展的顺序），首次移植时字节与半字有符号读错位，由 `固定访存` 场景发现。

## 内核态目标（2026-10-08）

内核里与架构无关的部分改用底层豫言写，放在包「豫言内核」（`豫言操作系统/裸机/内核/`）。裸机后端「降级核篇」以裸机目标、内核态降级它：降级期间「裸机核态引」为阳，降级完复位。

- **入口**：不生成用户入口桩。模块开头是跳转表，按「核篇」的「诸核出名」排列：ARM64 每项一条 `b 函数N`，AMD64 每项 `jmp rel32` 加三个 `int3`。模块连接在内核模块基址（ARM64 `0x40800000`，至多 8 MiB，2026-10-13 起恒等映在两个旧槽 1–2 GiB 二级表第 4–7 项，原在 `0x40100000`，至多 512 KiB；AMD64 `0x2400000`，至多 8 MiB，2026-10-13 起：两个旧槽的低区页目录第 18–21 项把它映到镜像里物理 `0x800000` 起的模块区；原在 `0x1A4000`，至多 288 KiB），手写内核按表项的绝对地址调用（ARM64 `blr x16`，AMD64 `cld; call r11`）。
- **原语**：导入模块「内核」的读四、写四、读八、写八、清零、复制、复制字节、刷新快表、刷新一页、屏障编成出线的小桩（表在寄存器降级「核本术表」：ARM64 `ldr w0,[x0]; ret` 等，AMD64 `mov eax,[rdi]; ret` 等；清零、复制按 16 字节，AMD64 用 `rep stosq`／`rep movsq`，复制字节用 `rep movsb`；刷新一页是 `tlbi vaae1is`／`invlpg`，刷新快表是 `tlbi vmalle1is`／重载 CR3；端口读字节、端口写字节在 AMD64 是 `in al, dx`／`out dx, al`，ARM64 读得 0xFF、写不做事，2026-10-11 起供 PS/2 键盘用）；「架构」是常量（AMD64 为 1，ARM64 为 2）。其他目标把「内核」导入绑成陷阱。
- **栈与陷阱**：函数序言的栈下界改为内核栈的下界（ARM64 `0x401E0000`，AMD64 `0x1EC100`）；陷阱改为 `brk #0`／`ud2`，进当前层的异常，内核转「失败」。
- **限制**：模块不声明线性内存、数据段与全局（内核数据经原语按绝对地址读写），不用批量内存操作（ARM64 的复制填充助手用浮点寄存器，内核不保存用户的浮点状态）；参数不超过寄存器个数（ARM64 八个、AMD64 四个），否则会写到用户区的传参暂存。
- **构建**：生成并运行内核镜像的工具（豫言系统、裸机验证、普通豫言验证、豫言裸机）开头调「备豫言核」：构建包、读出模块（用到长整数时先数值转译）、按两种架构各降级一次，存进「核篇字节引」；「生臂自定镜像」「生兼自定镜像」把它放进镜像。
- 已搬进来的：服务 23「内存块数」（第 2 步）；内存管理的全部逻辑（第 3 步：物理块分配、页表、按需提交、清理、复制任务、服务 22、24、25 与开机初置，见[内存块管理](内存块管理.汉语.md)的“豫言内核”一节）。
- **统一引导模块（2026-10-13）**：「降级核篇」是「降级核态篇」的一种用法；后者可指定导出名们、连接基址与容量，并可关掉序言的栈下界检查（降级公用的「裸机无栈界引」，栈界取零）。包「底层统一引导」（UEFI 引导程序登记中文字体）按导出「注册引导字体」、基址 0、容量 64 KiB、不查栈界降级，得到位置无关的机器码，嵌进 BOOTX64.EFI 与 BOOTAA64.EFI；「备豫言核」顺带构建它，存进「统一引导篇引」。它用内核原语「调用固件」（函数地址、四个八字节参数的参数块）按固件的调用约定调 UEFI 函数：AMD64 是微软 x64（存 r8–r10 与 rbx，栈对齐到 16 字节并留 32 字节影子区），ARM64 是 AAPCS64（存 x15 与 x30）。

## 栈图（提案 00020）

- **函数展开记**：模块带预编客体（导出“预编起号”）时，每个函数入口放一个长为零的「栈图记」机器片（种类一），内容是旗（一位为宽函数，二位为带调用点栈图的客体函数）、帧大与序言保存的被调用者保存寄存器的次序（`机器编码` 的「栈图术记」）。帧布局不变：ARM64 的 x30 在 sp、第一个保存寄存器在 sp+8、其余自 sp+16 起依次存放；AMD64 先依次压入保存寄存器再减栈帧大，返回地址在压入的寄存器之上。最后一个函数之后、表片之前另放一条旗为 4 的函数展开记作函数区末端（帧大与保存数为零），其后的表片、助手、线程桩与豫行桩没有展开信息，执行器查函数落到它就当作查不到。
- **栈图标记**（第 2 步）：预编二排令流时按豫汇类型给操作数栈与局部记引用位（`预二匣位`），转译时在宽函数体里放不发代码的标记（`栈图标记`，写成不压不弹的内在调用）：函数开头的局位记（各局部是否引用；转译中遇到带参数的块、闭包融合路径等跟踪不了引用位的情形改放函不精确记），每个可能回收的调用之前的栈位记（实参之下各栈深是否引用）与临引记（调用前后持引用、类型不固定的局部，如指令临时）。引用位用整数位集跟踪，只给可能发出调用的指令记基码（稀疏记录表：位置与基码成对，排完令流抄成恰长数组，转译时按令流位置二分查找）。小叶内联把被内联调用处的提示与被调函数体里的提示合成（「栈图内联逆」），判能否内联时不计标记。
- **调用点栈图**：带栈图的客体函数在每个非尾调用之后放一条栈图记（种类二），内容是调用前后都活着的引用的位置：实参之下的栈槽按栈位记（别名寄存器、固定的被调用者保存寄存器或帧里的溢出槽），局部按局位记与临引记中调用处与其后一处都在活跃段里的（被调用者保存寄存器里的记寄存器，其余记帧槽）；没有提示或栈深对不上时记为不精确，回收时这一帧保守扫描。持引用局部的活跃与否用事件扫描求（按活跃段在位置上挂启止事件，调用位置单调不减），位置升序编码；内容按值共用一份（内容池），连接时按内容去重。各函数共用降级暂存数组（局寄表、活集、戳、事件表等），免得每降一个函数都新建几个中等大小的数组——非移动的堆碎了以后取不到中等大小的块就要提前回收。
- **栈图表**：最后连接（「连接机器码」）把各展开记按地址收成一张表，按八字节对齐接在代码之后，标号“栈图表”：32 字节表头（魔数 YYZT、版本 2、总长、函数项数、表码偏、调点项数、运行时表址），每函数 32 字节的项（码偏与展开记内容），按返回地址递增的调点项（各 8 字节：返回地址码偏、内容相对表头的偏移），最后是去重后的调用点栈图内容；总长按八字节对齐。函数内连接把本函数的调用点栈图记合成一条函内调点集记（种类三：各调用点相对函数开头的偏移接内容）放在最前面，不再在调用处切开代码；降级缓存与并行降级原样携带栈图记（缓存编码的标签五）；栈图开关计入降级缓存键。
- **复制桩**：执行器的占位导出“栈图表复制”在栈图开时整个换成复制桩（`宽降级本术` 的「指栈图表摹桩」）：adr（AMD64 为 rip 相对 lea）取表的运行地址，总长不超过容量时按八字节复制到线性内存，并在副本 +24 写入表的运行地址。不认得它的旧降级器照常编出占位本体（返回零），旧工具自举新源码时执行器当作没有栈图表。
- **栈回写桩**（第 3 步）：执行器的占位导出“栈回写”（栈起、掩码、表、数）在栈图开时整个换成栈回写桩（`宽降级本术` 的「指栈回写桩」）。叶桩，与栈复制桩在回收函数里同一帧调用，sp 相同：先把表里不小于栈起的各格（栈复制缓冲里的线性地址）按缓冲偏移写回 sp 起的原生栈，再按掩码从栈复制头把置位的被调用者保存寄存器装回（ARM64 x19 至 x24、x26、x27，AMD64 rbx、rbp、r12 至 r15；不用分支，装进临时寄存器后按掩码位条件选择）。只用调用者保存的临时寄存器，返回零；旧降级器编出的本体返回负一，执行器启动时据此决定用不用精确客体帧。

## 边界

- 局部变量按活跃段分配寄存器；降级前做小叶函数内联（[内联小函数。豫](../库/裸机后端/内联小函数。豫)），预编二另在转译时内联小函数；没有公共子表达式与逃逸分析。
- 局部与操作数栈槽合计超过 3500 的函数，入口即陷阱（与旧降级“操作数栈越界即陷”一致）；结果数超过寄存器数的函数被拒绝。
- 全局值至多 4096 个（ARM64 单条载入的偏移范围）。
