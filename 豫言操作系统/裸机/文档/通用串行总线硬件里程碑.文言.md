# USB 硬件里程碑

此为硬件支持之最小次第。既有 xHCI 已具 PCI 寻器、固件交权、控器启动、DMA 环、根端复位、Enable Slot 与 Address Device 之码。持久文件系统今用 Virtio 块器；裸机源码未见 AHCI、NVMe 之驱。

此役先验首个直连根端设备寻址：候异步 Enable Slot 完事，免一巡即判其败；正 Address Device 待命之事件回收目标，使 ERDP 写于运行寄存器基址加 `0x38`；别存待命之数，免槽号与完毕标志覆之；槽态取自输出槽上下文原始双字，USB 地址仍存。循既有诊断区，不增 ABI。

集成在裸机后端 `兼汇编。豫` 之 `兼容根端口扫描`。`0x1039B0` 为寻址态（0 未试、1 待命、2 成、3 败），`0x1039B4` 为完码，`0x1039B8` 为完成槽号，`0x1039BC` 为 USB 地址，`0x1039C0` 为槽态，`0x1039C4` 为 EP0 态。控器运行寄存器基址存于 `0x10395C`，事件环软件出队指针存于 `0x10399C`，二者须别。

`兼容核心。豫` 验 BAR 映射，略共享 PDPT 项已访问位：帧缓冲先访其目录，硬件置此位，目录犹有效。旧逐位之验略过 BAR 映射，使后启控器访未映之址。

控器复位仍验内存位图已初置，去以首位为退出之旧验；首位属内核保留块，正常启时恒置。旧验使控器未复位而易内核 DMA 环，固件设备槽犹占其端，Address Device 回 TRB Error。

六十四位 BAR 高址之验，从 PCI 记录 `0x103948` 取 BAR0 高双字；旧码误读 `0x103940` 设备类码，使正常六十四位 BAR 亦略复位。前述二条件须俱正。

后续之序：由 EP0 取设备及配置描述符；置直连 HID boot 键盘，接既有字符收入；继于 AHCI 与 USB 大容量存储中择其一路，接读写于既有文件系统。欲增接口或 ABI，须先别请。

此役未作鼠标、显示模式切换、网络、音频、ACPI、多核、AHCI、NVMe、USB 大容量传输及完整 HID 收入。待办事项：六十四字节上下文、多器与集线器拓扑、热插拔，皆须别作。QEMU 之验，不代 ThinkPad E40 及他实体机之验。

寻址及事件回收据 [Intel xHCI 1.2 规范](https://cdrdv2-public.intel.com/625472/625472_xHCI_Rev1_2b.pdf) §4.6.5、§4.9.4、§5.5.2.3.3。
