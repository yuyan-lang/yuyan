# 苹果键盘实机诊断

用户实测 MacBookPro11,1：旧候选 ISO 显示常，内键盘、后接之外键盘皆不能入。承许 SSH pit-mbp13 读 Linux：Intel xHCI 8086:9c31，BAR B0A00000、六十四 KiB，HCCPARAMS 200077C1，用三十二字节上下文。外 SONiX 413d:2114 直连 USB 2 根二端，低速，接口零 boot 键盘、IN 81、最大包八、间隔十；内 Apple 05ac:0259 直连根五端，全速，接口零 boot 键盘、IN 83、最大包十、间隔八。二者不经蓝牙集线器。

诊断用旧实测镜源码 00dc0cb1b，加 USB 启屏快照。今 yybs 550386101 启盘构报用户码 701684 字节、可用 263592 字节，此布局阻碍已告终端会话；此事不旁改其界面、输入法、字体、用户布局。诊断镜、正式候选别存，不以旧基线之验称今上游全过。

## 使用

端口路由所据：Linux `drivers/usb/host/pci-quirks.c` 之 `usb_enable_intel_xhci_ports`，见 Intel EHCI 同伴，先以 PCI `DC` USB3PRM 写 `D8` USB3_PSSEN，继以 `D4` USB2PRM 写 `D0` XUSB2PR；无 Intel EHCI 则返。源码见 https://github.com/torvalds/linux/blob/master/drivers/usb/host/pci-quirks.c 。今豫言控器初置无此路由之写，然未足断 Mac 根因；须核其 EHCI 清单、四寄之值，乃决可用否。SSH 连接逾时，诸值未得。路由若正，则继核复位后设备复连至首巡之间所候。

定测试 U 盘而写诊断 ISO；外键盘先接乃开机。Mac 持 Option 启而择 EFI Boot。拍全 USB 诊断行，不待键盘可入；唯见“USB诊断开始”亦拍其画。实体键盘未修成。

## 字段

诸数皆八位十六进制。核内端口表据 0x12B000 至 0x12CFFF，各端三十二字节；存寄存器与标志，循旧串口、帧缓出之，不增应用 ABI。

| 行 | 诸列之义 |
| --- | --- |
| USB PCI | PCI 配置址、类码、BAR 低高字 |
| USB ROUTE | PCI 器身份双字、D0 路由值、D4 USB 2 路由掩码、D8 SuperSpeed 使能值、DC USB 3 路由掩码 |
| USB CTRL | 控器阶段、末寻址态、操作寄存器虚址、scratchpad 数 |
| USB ENUM | 最大端数、寻址成数、完整描述成数、巡态 |
| USB KEY | 键盘配置态、端点初置态、端点命令完码、所择槽 |
| USB EP | IN 端址、最大包长、间隔、累计报数 |
| USB P02、P05 | 初 PORTSC、寻址态、寻址完码、首描述态、全枚举态、枚举步、其时全局键盘配置态、VID/PID 双字 |

末字高十六位为 PID、低为 VID；完整描述成，乃据以识器。键盘态为全局所择者之态，不以此称各端皆配置成。

后续诊断源码添 USB ROUTE 行，以 PCI 配置地址端口读诸值，唯写地址择口，不写设备配置寄。其镜构、运行之验犹待；前述 b9eb 镜无此行。D0 至 DC 之义唯于相应 Intel 控器释之，余器唯记原值。

路由诊断之裸机后端全包类验退零，诊断系统工具构退零。以今树造启盘犹败：用户码 701684 字节，可用 263592 字节；故无今上游可交之 ISO。别于净旧苹果候选树施已提交诊断补丁、路由唯读之出，其后端原稿与 00dc0cb1b 同，独构方行。此唯采实体根因之证，不可据验今上游全功能。

## 验证

用户予 IMG_8139.HEIC，Mac 启路由诊断镜，显 `USB ROUTE=9C318086 000001FF 000001FF 0000000F 0000000F`。器身份合 Linux 所见 8086:9c31，D0 等 D4，D8 等 DC；无未循掩码启路由之证，不可以缺路由之写断根因。CTRL、ENUM、KEY、EP、P02、P05 同前图：寻址、全描述成数各一，键盘态零，二五端初 PORTSC 皆 000002A0、CCS 零。此记唯首枚之时；继核复位后连接稳定之候、巡扫缓存，根因与修成犹未证。

同一 `9a50da41` 路由诊断镜，又以 Q35、Haswell、TCG、五百一十二 MiB、单核、禁 PS/2、qemu-xhci、唯读 USB 存储模型，由 SeaBIOS 启。USB ROUTE 为 `000D1B36 00000000 00000000 00000000 00000000`，壳备，F2、H、Shift-H 得 `hH`；模拟器正常退。BIOS、UEFI 两模拟启路皆过；不可据代 E40、Mac 实体输入、持久存储之验。

路由诊断镜已成：旧候选 c5e139c9e 之后端与 00dc0cb1b 同，附已提交诊断、路由唯读之出；省重复提示，工具重构、混合启介质生成皆过。文件 `苹果二零一三启动/yy苹果路由诊断.iso`，SHA256 `9a50da41f18922ed0fb179207e30e85f1ea387ba0fd28ebe0b1b84ec28e245fa`。Q35、Haswell、TCG、五百一十二 MiB、单核、禁 PS/2、OVMF pflash、qemu-xhci USB 2 九端、USB 3 四端，自唯读 USB 存储模型启；USB ROUTE 为 `000D1B36 00000000 00000000 00000000 00000000`，首字合 QEMU 控器身份，余为其模型原值。图形截图 `yy苹果路由诊断UEFI.png` 已人观，诸诊断行皆全；F2、H、Shift-H 得 `hH`，模拟器正常退。此版俟 Mac 实体拍含 USB ROUTE 之全行；不可据模拟之验称 Intel 路由设置、实体键盘修复已成。今上游容量阻碍犹存。

用户予 IMG_8136.HEIC，实体已启诊断镜而入壳。PCI 为 `000000A0 0C033000 B0A00004 00000000`；CTRL 为 `00000001 00000003 BFE00080 00000010`；ENUM 为 `0000000D 00000001 00000001 00000002`；KEY、EP 四字皆零。P02、P05 首字皆 `000002A0`，余七字皆零。二端所记 CCS 连接位皆零，故未寻址此二键盘端；别有一器寻址、全描述皆成。继核 Intel USB 端口路由、固件交权、初置时序，未可以此断根因。此图证实体诊断可出、命令壳可启；键盘实机之验犹未过。

格式、全构、启介质、终稿核心类验、差异检皆过。诊断表先于 USB 初置清零，免启程既枚而抹其记。Q35、Haswell、TCG、五百一十二 MiB、单核、禁 PS/2、OVMF、qemu-xhci（USB 2 九端、USB 3 四端），从 USB 存储模型启诊断 ISO；屏上七行 USB 字段皆可读，P02、P05 八字之记，与模拟器物理内存逐项同。壳备，F2、H、Shift-H 得 hH，正常退。截图 yyUSBDebug.png 已人观。ISO SHA256：b9ebf3288d86e25b894410c1a1b9b08a02ae5cbc4fed797fefee35ed1d4195cc。此唯证诊断之出正、模拟输入仍存；Mac 实体之败，俟此镜之照片，尚未修成。
