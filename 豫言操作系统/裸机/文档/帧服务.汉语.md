# 帧服务：用户态把画面写进帧缓冲

内核服务 32「提交帧」与 33「帧缓冲信息」（平台导入 `平台.提交帧`、`平台.帧缓冲信息`）让用户态程序把整帧画面交给内核写进 Multiboot 帧缓冲。只在 AMD64 兼容核心实现；ARM64 没有帧缓冲，两个服务按未知服务返回 1，调用方当作没有显示。执行器「客体二号」据此在裸机上实现公共显示接口（见 `客体二号/裸显示。豫`）：一个显示面就是整块帧缓冲，输入只有键盘。

| 服务 | 参数 | 结果 |
|---|---|---|
| 33 帧缓冲信息 | 无 | 宽 × 65536 + 高（逻辑像素：高分屏两倍放大时为物理像素的一半，其余即物理像素）；没有可用的 32 位直接 RGB 帧缓冲时为 0 |
| 32 提交帧 | 像素在客体线性内存里的地址（为 0 时不读像素，把 宽×高 区域涂黑，两倍放大时涂 2宽×2高，10-06 起执行器归还显示面时用它清屏）；宽 × 65536 + 高（逻辑像素） | 成功 0，失败 -1 |
| 34 读字体模块 | 目的在客体线性内存里的地址；模块内偏移 | 拷了多少字节（至多 65536）；偏移到末尾为 0；没有模块或目的越界为 -1 |
| 35 字体模块长度 | 无 | 模块字节数；没有为 0 |
| 36 读鼠标字节 | 无 | PS/2 鼠标的一个辅助口字节；没有为 -1。第一次调用时清零鼠标环并向鼠标发 D4 F4 开数据报告（2026-10-06） |

- **像素格式**：画面是 RGBA8、行优先、没有行距。内核读帧缓冲记录里的红位：红位 16（QEMU 标准显卡的 BGRX）时交换红蓝，红位 0 时原样写入，其他格式失败。Multiboot 1 规范把色彩信息放在信息结构偏移 110，Limine 按四字节对齐放在 112，所以记录里的红位在 0x103926 或 0x103928；内核看 0x103927 是不是红宽 8 来区分。
- **检查**：宽高须为正且不超过逻辑尺寸（33 号返回的宽高）；像素须整段落在客体可用的线性内存里，界限与“块搬入静态”相同（线性基址为 3 MiB 时 512 KiB，否则为动态块数乘 2 MiB），像素地址另有 1 GiB 的粗上界（原为 32 MiB，裸机页上限提到 1024 页后帧缓冲会分配到 32 MiB 以上）。画面写在帧缓冲左上角，逐行按行距前进。
- **字体模块**（34、35，2026-10-06）：启动盘随带的第二个 Limine 模块是桌面用的 TrueType 字体（文楷）。设备初置阶段「兼容文楷模块初置」把它映到内核窗口 1 GiB + 32 MiB 起（页目录 0x125000 第十六项起），虚址、物理址、长度记在 0x103A00、0x103A04、0x103A08；34 号从内核窗口拷到 r9 加目的地址，目的界限同提交帧。执行器在裸机上对任何族名都取这份字体（`显示原语。豫` 的「字体裸开」「字体裸定读」）。Limine 把模块紧接内核放在 64 MiB 块池之下（SeaBIOS 实测 14.1–38.5 MiB，OVMF 23.5–53.9 MiB），映射时若落进块池也照首个模块的做法置位池位图。
- **代码位置**：服务体在 0x1F5000 起的外置区（帧缓映射代码所在 8 KiB 区间的后一半），按 eax 分 32、33、34、35；主核心的分派表只有一条区间判断（服务号 32–35 都跳到同一段经 r11 呼外置区的呼口，主核已近 12608 字节上限）；构建时核对两半各不超过 4 KiB。
- **验收**（2026-10-06）：`yy豫言系统 启动盘 --壳 库/显示控件/测试/原生显示提交探针。豫` 造的混合 ISO 经 QEMU q35、SeaBIOS、xHCI U 盘启动，探针串口输出“尺寸：1280×800、像素比乘六十四：64、提交：成功、等待：显示计时、归还：成功”，QEMU 监视器 screendump 得整屏 RGB(32,96,160)；`yy裸机验证` 380 项全部通过。

待办事项：只认红位 0 与 16 的 32 位格式；三倍及以上的放大与写合并映射（加快高分屏写帧）留待后续版本；写帧期间不关中断，也不与内核控制台绘字互斥（图形期间控制台的字仍会画到屏幕上）；执行器的等待是忙等；鼠标支持 PS/2 与 xHCI 上的 USB 启动协议鼠标（相对位移），滚轮与 usb-tablet 的绝对坐标留待后续版本。

**PS/2 鼠标**（2026-10-06）：键盘初始化的配置字改为 or 0x40、and 0xCC，开辅助口时钟（两路中断仍关）；主核「键盘收入」读状态口见辅助口位 0x20 时跳到外置区 0x1F5C00 的「鼠标字节入」，把字节存进 0x103B10 起的 64 字节环（0x103B00 魔数“MOUS”、0x103B04 写计数、0x103B08 读计数）；服务 36 读一字节，第一次调用时清零并向鼠标发 D4 F4。外置区布局改为：帧服务主体在 0x1F5000，补零到 3072 字节，后接「鼠标字节入」。执行器（`客体二号/裸显示。豫`）组三字节包、交指针事件，提交画面时叠画 12×19 的箭头光标，指针移动时重交上一帧。

**USB 鼠标**（2026-10-06）：xHCI 驱动在设备完整枚举时，键盘之后再找 HID 启动协议鼠标接口（类 3、子类 1、协议 2，零备用设置）。键盘那一路没给这个设备设过配置就先设配置，再设启动协议，然后用 Configure Endpoint 只加这个接口的中断 IN 端点（槽上下文的条目数取原值与本端点号的较大者）。三十二项中断环、报告缓冲与鼠标字段都放在该槽键盘记录之后（记录偏移 128 起是鼠标字段，320 起是报告缓冲，512 起是环）。苹果笔记本这类内置键盘与触控板同在一个 USB 设备的复合设备，两个接口各配一个端点。报告片按事件的端点号分流，把启动协议报告（键位、横移、纵移）换成 PS/2 三字节包（纵移取反）写进同一个鼠标环，执行器照旧按 PS/2 包解析。PS/2 一路的「鼠标字节入」与服务 36 的首次初始化先读状态口，读到 0xFF（没有 PS/2 控制器）就跳过，鼠标环里只有真实的字节。QEMU 实测：`-device usb-mouse,bus=xhci.0` 与默认 PS/2 鼠标并存时，USB 鼠标点开“系统设置”；`-machine i8042=off` 只接 usb-kbd 与 usb-mouse（与苹果笔记本一样没有 PS/2）时，USB 键盘打字进桌面，USB 鼠标点“返回命令行”回壳、再进桌面点“任务管理器”都正确，鼠标环字节数恰为报告数乘三；开机后 `device_add usb-mouse` 热插的鼠标分到新槽，同样可用。非启动子类的鼠标、usb-tablet 的绝对坐标、滚轮与触控板手势留待后续版本。

**高分屏两倍放大**（2026-10-06）：实机测试的屏幕是 2560×1600，一帧 16 MB，执行器的堆容不下，进桌面时报“堆内存不足”（堆诊断：请求 16384016，页数 762/1024）。内核现在按帧缓冲记录现算倍数（外置区的「帧求倍」，结果放在 r13）：宽超过 1920 或高超过 1200 时为二，其余为一。33 号返回物理宽高除以倍数；32 号的宽高上限随之减半，两倍时每个像素写成 2×2：像素换算后复制成两份，用一次八字节存储写入，每行像素写两遍；涂黑的区域也乘二。执行器、桌面、光标与鼠标坐标都按逻辑像素工作，2560×1600 的屏上桌面是 1280×800，一帧 4 MB。QEMU 用 OVMF 加 `-vga none -device VGA,xres=2560,yres=1600` 时 Limine 选 2560×1600，实测 2 秒进桌面，画面铺满整屏、红蓝正确。
