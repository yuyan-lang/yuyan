# 帧服务：用户态把画面写进帧缓冲

内核服务 32「提交帧」与 33「帧缓冲信息」（平台导入 `平台.提交帧`、`平台.帧缓冲信息`）让用户态程序把整帧画面交给内核写进 Multiboot 帧缓冲。只在 AMD64 兼容核心实现；ARM64 没有帧缓冲，两个服务按未知服务返回 1，调用方当作没有显示。执行器「客体二号」据此在裸机上实现公共显示接口（见 `客体二号/裸显示。豫`）：一个显示面就是整块帧缓冲，输入只有键盘。

| 服务 | 参数 | 结果 |
|---|---|---|
| 33 帧缓冲信息 | 无 | 宽 × 65536 + 高（物理像素）；没有可用的 32 位直接 RGB 帧缓冲时为 0 |
| 32 提交帧 | 像素在客体线性内存里的地址（为 0 时不读像素，把 宽×高 区域涂黑，10-06 起执行器归还显示面时用它清屏）；宽 × 65536 + 高 | 成功 0，失败 -1 |
| 34 读字体模块 | 目的在客体线性内存里的地址；模块内偏移 | 拷了多少字节（至多 65536）；偏移到末尾为 0；没有模块或目的越界为 -1 |
| 35 字体模块长度 | 无 | 模块字节数；没有为 0 |

- **像素格式**：画面是 RGBA8、行优先、没有行距。内核读帧缓冲记录里的红位：红位 16（QEMU 标准显卡的 BGRX）时交换红蓝，红位 0 时原样写入，其他格式失败。Multiboot 1 规范把色彩信息放在信息结构偏移 110，Limine 按四字节对齐放在 112，所以记录里的红位在 0x103926 或 0x103928；内核看 0x103927 是不是红宽 8 来区分。
- **检查**：宽高须为正且不超过帧缓冲；像素须整段落在客体可用的线性内存里，界限与“块搬入静态”相同（线性基址为 3 MiB 时 512 KiB，否则为动态块数乘 2 MiB），像素地址另有 1 GiB 的粗上界（原为 32 MiB，裸机页上限提到 1024 页后帧缓冲会分配到 32 MiB 以上）。画面写在帧缓冲左上角，逐行按行距前进。
- **字体模块**（34、35，2026-10-06）：启动盘随带的第二个 Limine 模块是桌面用的 TrueType 字体（文楷）。设备初置阶段「兼容文楷模块初置」把它映到内核窗口 1 GiB + 32 MiB 起（页目录 0x125000 第十六项起），虚址、物理址、长度记在 0x103A00、0x103A04、0x103A08；34 号从内核窗口拷到 r9 加目的地址，目的界限同提交帧。执行器在裸机上对任何族名都取这份字体（`显示原语。豫` 的「字体裸开」「字体裸定读」）。Limine 把模块紧接内核放在 64 MiB 块池之下（SeaBIOS 实测 14.1–38.5 MiB，OVMF 23.5–53.9 MiB），映射时若落进块池也照首个模块的做法置位池位图。
- **代码位置**：服务体在 0x1F5000 起的外置区（帧缓映射代码所在 8 KiB 区间的后一半），按 eax 分 32、33、34、35；主核心的分派表只有一条区间判断（服务号 32–35 都跳到同一段经 r11 呼外置区的呼口，主核已近 12608 字节上限）；构建时核对两半各不超过 4 KiB。
- **验收**（2026-10-06）：`yy豫言系统 启动盘 --壳 库/显示控件/测试/原生显示提交探针。豫` 造的混合 ISO 经 QEMU q35、SeaBIOS、xHCI U 盘启动，探针串口输出“尺寸：1280×800、像素比乘六十四：64、提交：成功、等待：显示计时、归还：成功”，QEMU 监视器 screendump 得整屏 RGB(32,96,160)；`yy裸机验证` 380 项全部通过。

待办事项：只认红位 0 与 16 的 32 位格式；写帧期间不关中断，也不与内核控制台绘字互斥（图形期间控制台的字仍会画到屏幕上）；执行器的等待是忙等；没有鼠标。
