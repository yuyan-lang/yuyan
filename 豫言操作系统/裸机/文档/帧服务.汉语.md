# 帧服务：用户态把画面写进帧缓冲

内核服务 32「提交帧」与 33「帧缓冲信息」（平台导入 `平台.提交帧`、`平台.帧缓冲信息`）让用户态程序把整帧画面交给内核写进 Multiboot 帧缓冲。只在 AMD64 兼容核心实现；ARM64 没有帧缓冲，两个服务按未知服务返回 1，调用方当作没有显示。执行器「客体二号」据此在裸机上实现公共显示接口（见 `客体二号/裸显示。豫`）：一个显示面就是整块帧缓冲，输入只有键盘。

| 服务 | 参数 | 结果 |
|---|---|---|
| 33 帧缓冲信息 | 无 | 宽 × 65536 + 高（物理像素）；没有可用的 32 位直接 RGB 帧缓冲时为 0 |
| 32 提交帧 | 像素在客体线性内存里的地址；宽 × 65536 + 高 | 成功 0，失败 -1 |

- **像素格式**：画面是 RGBA8、行优先、没有行距。内核读帧缓冲记录里的红位：红位 16（QEMU 标准显卡的 BGRX）时交换红蓝，红位 0 时原样写入，其他格式失败。Multiboot 1 规范把色彩信息放在信息结构偏移 110，Limine 按四字节对齐放在 112，所以记录里的红位在 0x103926 或 0x103928；内核看 0x103927 是不是红宽 8 来区分。
- **检查**：宽高须为正且不超过帧缓冲；像素须整段落在客体可用的线性内存里，界限与“块搬入静态”相同（线性基址为 3 MiB 时 512 KiB，否则为动态块数乘 2 MiB）。画面写在帧缓冲左上角，逐行按行距前进。
- **代码位置**：服务体在 0x1F5000 起的外置区（帧缓映射代码所在 8 KiB 区间的后一半），主核心只在分派表里加两项，并有一段经 r11 呼外置区的呼口；构建时核对两半各不超过 4 KiB。
- **验收**（2026-10-06）：`yy豫言系统 启动盘 --壳 库/显示控件/测试/原生显示提交探针。豫` 造的混合 ISO 经 QEMU q35、SeaBIOS、xHCI U 盘启动，探针串口输出“尺寸：1280×800、像素比乘六十四：64、提交：成功、等待：显示计时、归还：成功”，QEMU 监视器 screendump 得整屏 RGB(32,96,160)；`yy裸机验证` 380 项全部通过。

待办事项：只认红位 0 与 16 的 32 位格式；写帧期间不关中断，也不与内核控制台绘字互斥（图形期间控制台的字仍会画到屏幕上）；执行器的等待是忙等；没有鼠标。
