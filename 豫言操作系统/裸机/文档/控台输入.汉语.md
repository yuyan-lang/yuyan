# 控制台输入环与 Ctrl-C

## 桌面里的 Ctrl+C（2026-10-12）

桌面（按键事件模式）里的 Ctrl+C 只作按键事件交给占屏的程序，内核不置中断标志。平铺桌面的焦点终端正在运行程序时，Ctrl+C 按单向数据流办理：终端取运行中子程序的任务号（子程序接口的「子程序任务号」），在窗口里显示 `^C` 与 `壳> 「打断任务」于「号」为「N」`，再把这句交给系统壳执行，与在壳里输入这条命令相同。壳命令「打断任务」调子程序接口的「打断任务」，执行器经内核服务 64 打断这个任务与它的全部子孙。脚本在运行时 Ctrl+C 另清掉脚本余下的行。输入框可用（没有程序运行）时 Ctrl+C 由文本框复制选区。

服务 64「打断任务」（任务句柄）在内核里结束任务，所以预编成机器码、没有中断检查点的豫行工具（如 `/工具/yy豫构`、编译器）也能被打断。目标与它的子孙（调度环里主人链通到它的动态任务，至多 16 层）各自：已完成的不管；正在某个处理器核上运行的，在槽区 +0x54 记“待打断”，它下一次系统调用（入口的「导出：动态服务」）或那个核下一次时钟轮转（「导出：调度」）时先打断它此刻的子孙，再以退出码 130 结束它；其余的当场结束（冲刷、归还资源、状态置“被终止、已完成”、退出码 130），并唤醒主人。主人照常收取退出码，桌面终端随后显示 `退出码：130`。旧槽（槽 0、1）与无效句柄返回 −1；任何任务都可以打断别的动态任务。`「列出任务」` 印出任务号、名称与占用。

## 按键事件模式与共用解码（2026-10-11）

键盘解码写在两种架构共用的豫言内核里（`内核/按键。底层。豫`），手写内核只做调用。AMD64 的『控台收入』收完串口后经跳转表调「键盘收入」：它经内核原语「端口读字节」读 i8042 的状态口 `0x64` 与数据口 `0x60`（状态为 0xFF 即没有 PS/2 控制器），辅助口的鼠标字节组成四字节包放进鼠标环（见下文“鼠标包与滚轮”），键盘字节按 Set 1 解码（含 E0、E1 前缀与抬起码）换成 HID 用法。USB 引导协议键盘的报告由两种架构共用的 USB 设备层（`内核/通用串行键鼠。底层。豫`，xHCI 走扩展主控、EHCI 走增强主控）直接调它。它与上一份比对，得出修饰键与各键的按下、抬起，然后把新报告记成上一份。原先手写的扫描码表、报告解码与『鼠标字节』跳板已删。

键盘有两种模式：

- **文字模式**（缺省）：新按下的非修饰键按美式键位换成字节放进输入环，PS/2 与 USB 键盘相同。字母、数字与符号随 Shift 与大写锁定取上档；回车 13、退格 8、制表 9、Esc 27、F2 为 18，小键盘按数字键算（Num Lock 当作常开）；Ctrl 加字母出控制码，Ctrl-C 只置中断标志；方向键与起首、末尾出 `ESC [ A`…`ESC [ D`、`ESC [ H`、`ESC [ F`；删除出 4（命令壳删右边一字）。
- **事件模式**：服务 53「按键模式」（参数非零）打开，参数为零关；执行器取得显示面时开、归还时关，主人任务结束时「清理任务」也关。打开时键盘只进按键区的事件环，串口字节照旧进输入环。每个按下、抬起是一个事件，服务 54「读按键」逐个取出：HID 用法 + 按下×256 + 修饰位×65536（2026-10-13 起位 9–15 另有用处：键盘用法恒为 0，非零表示消费类控制键即 HID 用途页 0x0C 的音量、静音、播放、下一曲等多媒体键，位 0–7 是消费页用法的低 8 位，位 9–15 是用法高位加一，完整用法＝消费页用法＋256；这类事件文字模式下不出，执行器暂时丢掉，待办事项：接到设计播放器的「设音量」），修饰位按 HID 排列（位 0–3 左 Ctrl、Shift、Alt、Win，位 4–7 右边四个），环空为 −1；Ctrl 加 C 只作按键事件交出，不置中断标志（2026-10-12 起，见上文“桌面里的 Ctrl+C”）。

| | ARM64 | AMD64 |
|---|---|---|
| 按键区：+0 事件写计数、+4 事件读计数、+8 事件模式主人（槽号加一，0 为文字模式）、+12 PS/2 前缀状态、+16 PS/2 修饰位、+20 大写锁定、+24 起 PS/2 鼠标状态（见下文）、+64 起 128 项事件环（每项 4 字节） | 开机参数 +3584 | `0x103C00` |

执行器（`客体二号/裸显示。底层。豫`）把事件换成显示接口的按键事件：修饰键交「控制」「上档」「交替」「命令」的按下、抬起；其余键交语义键名（回车、退格、制表、退出、空格、功能二、方向、起首、末尾、删除、翻页）或单字符键名（字母小写）的按下、抬起；可打印键按下、且 Ctrl、Alt、Win 都松开时另交文字输入。平铺桌面的交替快捷键因此在裸机上可用；显示控件在按住交替时把回车、方向键等也直接交给应用，焦点在终端文本框里同样生效。

## 鼠标包与滚轮（2026-10-11）

鼠标也由两种架构共用的豫言内核（`内核/按键。底层。豫`）换包。内核放进鼠标环的一律是四字节包，与 PS/2 IntelliMouse 的包相同：首字节（位 3 恒为一，低三位是左、右、中键，位 4、5 是横移、纵移的符号）、横移、纵移（向上为正）、滚轮（有符号，向下滚动为正）。环里放不下整包就整包丢弃，包始终对齐；服务 36 仍逐字节取出。

- **PS/2 鼠标**（AMD64）：「键盘收入」第一次调用时（手写的键盘初置已开辅助口时钟）做「鼠标初置」：关数据报告（0xF5），依次设采样率 200、100、80 再读设备号（0xF2），得 3 即为滚轮鼠标（每包四字节），然后采样率设回 100、开数据报告（0xF4）。每个命令字节都先往命令口写 0xD4，再往数据口写，等鼠标应答 0xFA；等应答时收到的键盘字节照常解码。没有 PS/2 控制器或鼠标不应答关数据报告，就当没有鼠标、只记每包三字节。之后辅助口字节由「鼠字节入」组包：包首须有位 3、不得有溢出位 6、7（应答 0xFA、自检 0xAA 因此丢掉，顺带重新对齐），收齐一包再放进环，三字节鼠标的滚轮字节补零。
- **USB 引导协议鼠标**：两种架构共用的扩展主控驱动（`内核/扩展主控。底层。豫`，2026-10-11 起 AMD64 也用）按实收长度（请求长度减残余）调「鼠标报告」：收到至少 4 字节时第 4 字节是滚轮（HID 向前滚为正，取反后与 PS/2 一致），纵移同样取反；VMware 虚拟鼠标的两种格式经「鼠包入」出包，滚轮字节是 0。没有扩展主控时由增强主控驱动（2026-10-13 起）经同一设备层调「鼠标报告」。
- **执行器**（`客体二号/裸显示。底层。豫`）按四字节包解析，滚轮累计成未交付的格数，键位与指针移动交过之后交滚轮事件（类别 7，与 macOS 后端的记录相同）：甲乙是指针位置，丁是纵向滚动量，每格 48 像素（像素比为一，与显示接口“一行约 48 逻辑像素”一致），向下滚动为正。显示控件把滚轮交给指针下最内层可滚动的滚动区，原样热区（外部程序的格子）把它原样转给应用。

| | ARM64 | AMD64 |
|---|---|---|
| 鼠标环：写计数、读计数（自由递增），环体 | 开机参数 +3072、+3076，+3088 起 256 字节 | `0x103B04`、`0x103B08`，`0x103B10` 起 64 字节 |
| PS/2 鼠标状态（按键区 +24 起）：初置过、每包字节数（3 或 4）、包内已收字节数、包的前三个字节 | 不用 | `0x103C18` 起 |

同日修好拖滚动条：自绘后端给滚动区外包一层同标识的区域热区，热区先收进交互项，显示控件拖滑块时按标识先找到热区，拖动就没有效果（各后端都是这样，点轨道翻页不受影响）；现在按拖动标识只在可滚的滚动项里找，见显示控件的事件处理。

验收（2026-10-11，`yy豫言系统 启动盘 --预编二 --工具链 --六十四位地址` 造盘，QEMU q35 纯模拟，xHCI U 盘启动，监视器 `mouse_move`、`mouse_button` 注入、`screendump` 截屏核对）：

- PS/2 鼠标（缺省 i8042）：开机后按键区 +24、+28 为 1、4（认出滚轮鼠标）。桌面里展开文件浏览的 源、源/库，指针在列表上 `mouse_move 0 0 -1` 三次，列表下滚 144 像素，`mouse_move 0 0 1` 一次上滚 48 像素；按住滑块下拖 100 像素，滑块跟着走、列表下滚约 182 像素；点击照常。
- USB 鼠标（`-machine q35,i8042=off`，`usb-kbd`、`usb-mouse`）：没有 PS/2 控制器，按键区 +28 为 3；滚轮与拖滑块同上，鼠标环里滚轮包的第 4 字节为 1（向下滚一格）。
- ARM64（hvf，edk2、ramfb，`usb-kbd`、`usb-mouse`）：进桌面后鼠标移动、点开任务管理器照常。
- 冒烟测试（SeaBIOS 与 OVMF）通过，新加的一步 `mouse_move 0 0 1` 核对第三个包的滚轮字节为 0xFF；裸机验证 342 项、普通豫言验证 108 项全部通过（另有登记的已知失败）；显示控件交互测试新增“滚动区外包同标识热区时拖滑块”一项，改动前失败、改动后通过。

后续版本的事项：ARM64 USB 鼠标的滚轮；横向滚轮（IntelliMouse Explorer，设备号 4）。

E40 临时诊断：初始化及原始键码输出到 COM1（2026-10-06 起只写串口，不再画到帧缓，免得公测版屏幕上满是诊断行；实机没有串口时要恢复上屏）。`PS2 STATUS=XX` 是首次读状态口的十六进制值；`CONFIG=XX` 是原控制器命令字节；`STAGE=01` 表示将发送读命令字，`02` 表示将发送写命令字，`03` 表示将写入新命令字节，`04` 表示将明确启用第一端口，`05` 表示将发送键盘扫描启用命令。新配置关闭两个端口 IRQ 与辅助端口，保留 Set 2 到 Set 1 转换；`CONFIG2` 是启用第一端口后的配置回读，`ACK` 是扫描启用命令后读到的字节，`TIMEOUT STATUS` 是等待失败时的控制器状态。新增读写等待各至多轮询 6553600 次，此数为次数上界，非校准时长。后续每个从数据口收到的字节输出为 `PS2 RAW=XX`，包含应答与按下、松开扫描码。此为临时诊断，待定位后删除。

E40 首次照片记录：`STATUS=14`、`CONFIG=47`，旧诊断到 `STAGE=04`，内置键盘无响应，未见 RAW 或键盘应答。当前修改用于明确启用端口并确认配置及应答，真机结果仍待复测。读写等待及配置处理参照 [Linux i8042 驱动](https://github.com/torvalds/linux/blob/master/drivers/input/serio/i8042.c)。

此前内核对控制台输入什么也不缓存：服务 4 每次直接读一个串口字节，没人读就留在串口里。所以一个不读输入的死循环程序无法被打断——按下的 Ctrl-C 只是串口里的一个字节，没有任何代码会去看它。现在内核自己收下串口字节，并把 Ctrl-C 变成一个可查询的“中断标志”；AMD64 首次收入时有界初始化 i8042，启用键盘口与 Set 2 到 Set 1 转换，再把 PS/2 扫描码转换成 ASCII 字节，放进同一输入环。

## 设计

- **输入环**：内核在**每次时钟中断里**、以及**服务 4 读入之前**，把串口接收 FIFO 里的字节取出来；AMD64 收完串口后调豫言内核的「键盘收入」读 i8042/PS/2 键盘（解码与两种模式见上节）。串口与文字模式的键盘字节进入同一个 256 字节环。
- **Ctrl-C**：取到字节 3（0x03）不放进环，只把“中断标志”置 1。用户程序看不到这个字节，就像终端的行规程吞掉 `^C` 一样。
- **服务 4（读一字节）**：先 `控台冲刷当前`（原有行为：把待输出的整行先刷出去），再收入，然后从环里取一字节；环空返回 -1（与原来“串口没有字节”一致）。所以**提前敲入的命令仍按序留给下一个读者**——脚本一次性贴进串口，子进程不读输入，这些命令依旧原样留给壳。
- **服务 27（`平台.中断查询`，无参数、一个结果）**：返回中断标志（0 或 1）并清零。

| | ARM64 | AMD64 |
|---|---|---|
| 环头（头 4 字节、尾 4 字节、中断标志 4 字节，环体从偏移 16 起，共 272 字节） | `0x400B0400` | `0x103800` |
| AMD64 引导信息 | — | Multiboot 信息指针存于 `0x10380C`；帧缓冲元数据记录位于 `0x103910`，长 28 字节，紧接输入环之后 |
| 串口 | PL011 `0x09000000`，看 FR 的 RXFE 位（bit 4） | 16550 端口 `0x3F8`，看 LSR（`0x3FD`）的 DR 位（bit 0） |
| PS/2 键盘 | — | 首次收入时有界配置 i8042 并启用扫描；之后由豫言内核的「键盘收入」读状态口 `0x64`、数据口 `0x60`，解码见上节 |
| 收入子程序 | `控台收入`（`bl`／`call`，只用 x0–x8／eax、ecx、edx，中断上下文已整体保存） | 同 |
| 挂接点 | `时钟中断` 里在轮转任务之前调用一次；服务 4 内调用一次 | 同 |

新增的机器码全部是带标号的小片段（`豫言操作系统/裸机/库/裸机后端/控台输入。豫`，服务号在 `整数降级。豫` 的映射里加了 `中断查询` → 27），分支一律走标号重定位，没有手算偏移。

AMD64 启动入口先把 Multiboot 信息指针存于 `0x10380C`。若引导器提供帧缓冲字段，核心会把地址、行距、宽、高、色深、类型及六个 RGB 掩码字节复制到 `0x103910` 起的 28 字节记录；按规范偏移复制，即取 Multiboot 信息偏移 108 与 112 处各四字节放在记录 +20、+24。Limine 给的色彩信息比规范晚两字节（从偏移 112 起），所以经 Limine 启动时记录 +22、+23（`0x103926`、`0x103927`）为零、红位在 `0x103928`，蓝位两字节不在记录里；内核控台绘制不用这几个掩码，帧服务两种排法都认。待办事项：按引导器区分偏移、补齐蓝位。输入环占用 `0x103800` 起的 272 字节，初置魔数字另存 `0x1039F8`；键盘的修饰状态与事件环在按键区（见上节）。壳已接入 Noto UTF-8 帧缓显示、命令补全与简单拼音输入；串口保留 UTF-8。

## 用户态如何使用

内核只负责“记下 Ctrl-C”，怎么响应是用户态的事（见[客体二号](客体二号.汉语.md)的“控制台中断”一节）：

- **子任务里的程序**：执行器在每次进入 Wasm 函数体和每次跳回循环头时数一下，每 4096 次向内核问一次；问到标志就以退出码 130（128 + SIGINT，与 POSIX 相同）结束本任务，壳照常打印 `退出码：130`。所以死循环、深递归、忙等都能被打断；在等输入的程序也会在等待的循环里检查。
- **壳（首任务）**：读一行时先照常读完环里的字符（并回显），读不到字节且见到 Ctrl-C 标志才打印 `^C`、放弃这一行、回到提示符；起子进程之前先清掉遗留的标志；运行程序期间壳自己不占用 CPU，标志留给子任务。
- **逐键编辑（开机壳与开机豫构，2026-10-11，提案 00003 第 8 步）**：执行器的「等待终端键」在输入环空着时先问内核有没有 Ctrl-C（服务 27），有就当作字节 3 返回；编辑器见到 3 就打印 `^C`、放弃这一行、回到提示符。预编成机器码的程序里没有检查点，开机豫构正在运行一句纯计算的代码时 Ctrl-C 打断不了（待办事项）；这句里运行的子程序照旧以 130 退出。初始任务等键时办了子任务的消息就返回 −1（没有键，2026-10-14），编辑器借这个空当调「候键余事」看一眼壳请求（远程登录会话写下的进入桌面请求因此即时办理），再接着等键。
- **桌面终端与远程登录（2026-10-14）**：它们的壳会话是子任务，控制台的 Ctrl-C 标志与它们无关；Ctrl+C 经子程序接口的「打断任务」于负号只打断会话起的程序（它在内核里的子任务与经底层进程起的程序，见《客体二号》），会话停在提示符上时只丢掉正在输入的行。

## 验收

- 裸机验证新增 `控制台中断`：测试程序先打印“输入就绪”，harness 随后往串口写入 `a`、0x03、`b` 三个字节；程序（每一步限时三秒）依次读到 `a`、等到 `中断查询` 返回 1、再读到 `b`（0x03 不会出现在字节流里）、再查得 0；两个架构都通过。AMD64 的 16550 在无 FIFO 模式一次只收一个字节，后两个字节要等前一个被读走、内核在时钟中断里继续收入才到，所以这个方式同时覆盖“时钟中断里收入”与“服务 4 读环”。
- QEMU 手工键盘复测：SeaBIOS + i440fx/UHCI 与 OVMF + Q35/xHCI 均启动到 shell；向 PS/2 模型注入 `help`、回车，shell 收到完整 ASCII 行并返回“未知命令：help”。这是 QEMU PS/2 输入验证，尚未在 E40 或实体键盘上测试。
- 2026-10-02 修饰键复测：同一 BIOS/UEFI 混合 USB ISO 在 QEMU Penryn + Q35 + xHCI 下分别经 SeaBIOS BIOS/MBR 与 OVMF UEFI 启动到 `壳>`。监视器注入左 Shift+`a`、Caps Lock+`a` 得到 `A`；Caps Lock+Shift+`a` 得到 `a`；Shift+`1`、`2`、`-` 得到 `!`、`@`、`_`；另注入右 Shift+`b` 得到 `B`。这是 QEMU PS/2 模型验证，ThinkPad E40 实机尚待测试。
- 2026-10-02 USB 键盘缺口复测：QEMU 11.1.1 的 Q35 + Penryn + xHCI 挂载同一混合 ISO 与 `usb-kbd`（接在 `xhci.0`）；SeaBIOS 和 OVMF 都能启动到 `壳>`。QEMU `info usb` 显示 USB Keyboard 设备已挂到端口，但此时 `sendkey h/e/l/p/ret` 没有形成 shell 输入。移除 `usb-kbd` 后，相同 SeaBIOS 配置的 PS/2 注入可读出 `help` 并返回“未知命令：help”。这只证明 QEMU 设备模型配置下系统当前不能用 USB 键盘；QEMU 显示设备存在不代表内核已枚举它。xHCI 控制器启动、DMA 环与 HID 枚举仍待实现。
- 原有的控制台输入（`控制台输入`、`控制台错误`、`控制台行原子`）与依赖提前输入的全部壳测试（脚本一次性写进串口）都照常通过，说明环没有丢字节、没有乱序。
- 壳测试 `中断`（见[客体二号](客体二号.汉语.md)）在两个架构上逐字验证：豫言写的 `死循环`（尾递归空转）被 Ctrl-C 打断得到退出码 130，在提示符下敲了半行再按 Ctrl-C 得到 `^C`，之后壳仍可用。
- 2026-10-02 默认壳 ASCII 别名实测：新增 `help`、`echo 文字`、`exit`，`普通-壳-ASCII别名` 用例在 ARM64 与 AMD64 均通过。新版 BIOS/UEFI 混合 USB ISO 在 QEMU qemu64 + Q35 + xHCI 下，经 SeaBIOS 与 OVMF 启动后，monitor 向 PS/2 注入 `help`、`echo ps2 ok`、`exit`，三令皆正确回显并结束用户任务。此项只验 QEMU PS/2 模型，实体键盘与屏幕输出仍待实机验证。
- 2026-10-03 xHCI 命令完成复测：QEMU 11.1.1 Penryn + Q35 + qemu-xhci 挂载 USB 存储；同一 ISO 经 SeaBIOS BIOS/MBR 与 OVMF UEFI 均启动到 `壳>`。监视器读得 Enable Slot 槽号 2、槽状态 2、完成码 1，事件环出队指针前进一个事件。此项只验证命令环与命令完成事件处理；USB HID 键盘输入仍未实现。
- 2026-10-03 xHCI 根端口复位复测：启动阶段对首个已连接根端口置 PORTSC.PP 与 PR，并以掩码保留可写控制位；QEMU 11.1.1 Q35 + qemu-xhci + USB 存储下，默认 CPU 和 Penryn 分别经 SeaBIOS BIOS/MBR、OVMF UEFI 启动到 `壳>`。四种组合的 PORTSC 均读到 CCS、PED、PRC 置位且 PR 清零，证明 QEMU 端口复位完成。此项只验证模拟器中的根端口复位；USB HID、设备寻址、端点配置与 USB 存储传输仍未实现，ThinkPad E40 尚未实测。

## 边界

- 环满（256 字节的提前输入还没被读走）时后来的 Ctrl-C 要等环里腾出位置才会被收到；串口字节不会丢，只是 Ctrl-C 的识别被延后。
- 所有任务共用一个环与一个标志，谁先读谁得到；当前一次只有一个子进程，所以标志总是归它。
- 程序不能“捕获”Ctrl-C，也没有信号或前后台作业的概念；Ctrl-C 只对子进程生效（首任务壳自己按行处理）。
- 中断只在解释器的检查点被发现：一个陷在**宿主原语**里很久的调用（例如极大的文件读写）要等它返回后才会响应。
- **终端里的 Ctrl-C**：QEMU 的 `-serial stdio` 默认让终端的 Ctrl-C 产生 SIGINT、直接结束 QEMU（实测 “terminating on signal 2”），字节 3 到不了系统里。`yy豫言系统` 现在把串口接在 `-chardev stdio,mux=on,signal=off` 上（监视器仍是 `-monitor none`），Ctrl-C 于是作为字节 3 送进系统，行为如上；代价是终端不再能用 Ctrl-C 杀掉 QEMU，系统卡死时按 **Ctrl-A 再按 X** 强制结束（复用 QEMU 的 mux 快捷键，实测退出码 0）。自动测试仍用命名管道送入 0x03。
- 键盘按美式键位解码，PS/2 与 USB 相同（见上节）。默认壳保留 `help`、`echo 文字`、`exit`，以及基础中文版临时验收命令 `tmp-help`、`tmp-echo 文字`、`tmp-exit`。Tab 补令与 F2 拼音输入见《中文支持》，终端编辑按键见《终端编辑》。无 COM1 时，FF 状态直接转向键盘轮询。
