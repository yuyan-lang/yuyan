# Wasm 启动与内存声明验证

2026-09-23 恢复操作系统开发后，完整类型验证入口新增启动段与内存声明检查。两者在函数体遍历前执行，因此只含导入函数、没有定义函数体的模块也会受检。这是用户态执行器接收外部模块之前的静态安全边界。

启动段必须恰含一个合法 `u32` 函数索引，目标签名无参数、无返回值；无启动段合法。验证不执行启动函数。函数索引按导入加定义的顺序查找。重复启动段、空段、余字、越界及非法编码均拒绝。

内存段目前验证三十二位声明：最小页数不得超过最大值和 65536 页；共享内存必须声明最大值；内存导出索引必须指向已定义内存。函数体中的普通加载、存储及 `memory.size/grow` 现在检查内存存在、编号、对齐和数值类型，覆盖 i32、i64、f32、f64 与窄载入／存储；多内存加载存储的扩展立即数仍明确拒绝。两个定义内存可保留于模块结构，页数查询和增长可按编号验证，但客体执行器对多内存的动态语义仍需后续支持。内存 64 位标记被明确拒绝，属于当前实现范围限制，不代表标准 Wasm 禁止它。主动数据段及批量内存指令还没有完整地绑定到内存声明上下文；这一步不声称完成整个模块验证。

新增启动段 13 项、内存声明 14 项、内存指令 12 项单元测试，覆盖合法导入／定义启动、无函数体启动、错误签名、索引和段格式，以及内存上下界、共享标记、截断、导出索引、指令与声明的相容性。测试的标准分类与 Node WebAssembly.validate 对照；唯内存 64 位被当前执行器明确拒绝。旧异常验证回归通过。新构建的裸机验收器在 ARM64／AMD64 QEMU 完成包含外部 Wasm 夹具的 368 项回归。`yy优化器三代.wasm` 与 `yy栈默认回归GC重复索引边界.wasm` 经新静态入口检查通过；它们没有在客体完整执行。裸机镜像生成路径本次没有改变。

后续优先把主动数据段与批量内存指令关联，再完成普通豫言生成的 WasmGC 对象执行和真实回收，最终通过双架构 QEMU 中从 Shell 加载、运行、退出及资源再用的端到端验收。
