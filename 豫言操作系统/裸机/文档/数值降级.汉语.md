# 数值降级：浮点、长整数、向量与原子

裸机后端把底层模式程序编成的 Wasm 降级成 ARM64 与 x86-64 机器码。这一篇说明它怎样处理 i64、f32、f64、v128 与原子指令，使底层豫言写的张量内核能编进原生二进制（路二：macOS、Linux、Windows）并在豫言系统（裸机）里运行。

## 两条路径

底层模式用到 i64、f32、f64、v128、原子、共享内存或六十四位地址内存时，编译器走“新路径”，用通用编码器写出标准 Wasm（见 `应用/豫言编译器/文档/底层模式.汉语.md`）；只用 i32 的模块照旧走状态模块。裸机后端相应有两条入口：

- `数值转译。豫` 的 `需数值转译` 判断模块是否用到旧路径不认的东西（值类型、内存标志、指令）；
- 需要时用 `数值读取。豫` 读出标准模块，再由 `数值转译模块` 转成寄存器降级能接受的状态模块；否则仍用 `读取状态二进制`。

`原生生成。豫`（yy原生生成）与 `入口。豫`（yy豫言裸机）都按这个判断选路。只用 i32 的程序产物与改动前逐字节相同。

## 转译

转出的模块布局是：导入照旧，紧接导入的是一个窄的包装函数“启动”（调用原模块导出的“启动”或“_start”），其后是转译出的宽函数，导出“预编二起号”指向第一个宽函数。原模块的函数导出全部保留（定义函数的号随包装函数后移一位，原来的“启动”由包装函数取代）；六十四位地址内存的模块另加导出“长址内存”作标记（指向包装函数）。宽函数里每个值占六十四位（见 `宽降级原语。豫`），因此：

- i32 指令照旧（结果零扩展）；
- i64 指令写成已有的宽内在调用（加减乘除、移位、比较、扩展、截取、拼）；
- 浮点、向量、原子与带边界检查的 i64／f32／f64／v128 载存写成“数值内在码”（`数值码。豫`），由寄存器降级的数值挂钩展开。

初始内存超过八页时，状态模块只声明八页，包装函数在调用入口前把内存增长到原来的页数；主动数据段须在前八页之内。

降级前的小函数内联（`内联小函数。豫`）把数值内在码算作热调用，所以含这些码的函数不被内联（码里的帧槽号与栈深按所在函数编码）；内联按“预编二起号”分组，窄的包装函数与宽函数不互相内联。

## 浮点寄存器模型

浮点与向量值住在浮点寄存器里：操作数栈深为 d 的值住在第 d 个浮点寄存器（ARM64 为 v0 至 v23，x86-64 为 xmm0 至 xmm11），在虚拟栈上占一个槽，但寄存器降级的整数寄存器分配从不动它，因为产生与消费浮点值的都是数值内在码。转译保证浮点值只经数值内在码流动：

- **浮点局部**只用数值局部码读写（帧槽由转译分配，降级器看不到这些访问）；v128 局部占两个槽并按十六字节对齐；可能先读后写的浮点局部在入口清零；“写 L；读 L”合成“暂存 L”。
- **调用**前把参数区以下的浮点值存进“家”（参数槽之后每个栈深一个十六字节槽），调用后取回；浮点参数与结果在调用边界按位装进整数寄存器（v128 占两个），被调函数在入口把浮点参数复制进浮点局部。
- **跳转**携带的浮点结果由搬移码搬到目标块的结果位置；条件跳转需要搬移时写成“若（条件）则 搬移；跳”。
- **返回**前把浮点结果按位装进整数寄存器。

## 数值内在码

内在码为调用号减 `内在基`。数值所用的在四十万至六十四万之间（其余号见 `宽降级原语。豫`）：

| 段 | 码 | 含义 |
|---|---|---|
| 定码 | 四十万加 k（k 小于二千） | 标量浮点零至九十九，访存一百至一百一十二，浮点选择与向量拼拆一百二十至一百二十二，原子二百至二百一十七，向量三百加子码 |
| 车道码 | 四十万二千加 操作乘十六加车道 | 取车道、替换车道 |
| 局部码 | 四十一万加 种乘二万加槽号 | 浮点局部的读、写、暂存、清零、按位读 |
| 深度码 | 六十二万加 种乘一千加栈深 | 存家、取家、栈深处浮点值与整数寄存器按位互转 |
| 搬移码 | 六十三万加 源深乘一百加目深 | 浮点值在栈深之间搬移 |

挂钩在 `寄存器降级。豫` 的 `发内在` 开头：码落在这些段里就交给 `数值内在。豫` 分派。

## 两种架构

- **ARM64**（`臂数值汇编`、`浮点降级`、`向量降级`、`原子降级`）只用 ARMv8.0 指令，QEMU 的 cortex-a53 也能执行：标量浮点用 FP 指令，向量用 NEON，relaxed 点积用 smull、saddlp 与 addp 组合，原子用 ldar/stlr 与 ldaxr/stlxr 循环。有陷截断先与界比较，越界或非数跳到陷阱。
- **x86-64**（`兼数值汇编`、`兼浮点降级`、`兼向量降级`、`兼原子降级`）以 SSE2 为主，另用 SSSE3（pshufb、pabsd、pmaddubsw）与 SSE4.1（roundss/roundps、pmulld、pminsd、pmaxsd、pmovsx/zx、pextr/pinsr、insertps）。最小、最大按 Wasm 语义用比较与分支（标量）或两序运算合并（向量），饱和截断照 V8 的做法；原子用 lock xadd、xchg、lock cmpxchg 与 mfence。
- 访存都先查边界（地址加宽度不超过线性内存字节数），原子另查自然对齐。
- 等待与唤醒按单线程实现：值不等返回一，相等时当作超时返回二；唤醒返回零。

## 六十四位地址内存

用 `声明内存六四` 的模块（memory64）里地址是 i64，线性内存可以增长到 4 GiB 以上。数值转译给这样的模块加导出“长址内存”，寄存器降级在 `目标降级用户模块` 开始时据此把 `降级公用` 的 `长址引` 置为阳、降级完复位；入口、函数与助手据它生成六十四位的字节数运算。普通内存的模块生成的代码与原先逐字节相同。

- **字节数寄存器**：ARM64 的 x15 与 x86-64 的 r8 是页数左移十六位，按六十四位计算（`lsl x15, …, #16`、`shl r8, 16`）；`memory.size` 用六十四位右移取页数。
- **访存**：x86-64 的窄访存（i32 与一、二字节）把地址寄存器的全部六十四位移进 r11（`mov r11, 址`），按六十四位查界；ARM64 的访存用六十四位的索引寄存器。i64、f32、f64、v128 与原子的数值访存用六十四位有效地址。
- **增长、复制、填充、数据段初始化**：助手的增量、地址、长度、页数与字节数都取六十四位（x86-64 的 `mov r11, rdi`、`test rdx, rdx`、`mov rcx, rdx` 等；ARM64 的复制与填充用 x0 至 x2 的全部六十四位，增长把页数与字节数按六十四位移位）。`memory.grow` 的增量是 i64，失败时助手返回三十二位的负一，转译把它符号扩展成 i64 的负一。
- **入口映射**：Linux 与 macOS ARM64 的入口按页数上限映射动态区，长度或起址超过三十二位时用六十四位立即数装入（x86-64 `mov r64, imm64`，ARM64 movz 加 movk）。Linux x86-64 的六十四位地址内存把动态区放在 1 TiB，大代码段（0x110000000）留在它下面；ARM64 的动态区仍从 0x60000000 起。macOS x86-64 的动态区是数据段里的零填充区，长度是页数上限乘 64 KiB。
- **页数上限**（`降级目标` 的 `目标长址页容量上限`，目标内建导入“页容量”也返回它）：macOS 与 Linux 为 1073741824 页（64 TiB），裸机 AMD64 为 2130706432 页（127 TiB，动态区从 1 TiB 起），裸机 ARM64 为 1024 页，Windows 为 16384 页。模块声明的最大页数可以超过 65536，没声明时取这个上限。
- **验收**：`原生样例/长址`（包「原生长址」）把线性内存从一页增长到 82000 页（约 5.0 GiB），在 4 GiB 上下读写四字节整数、长整数、小数与一、二字节，读写最后四字节，填充 4 GiB 之上的一段，把横跨 4 GiB 的一段复制到 4 GiB 之上，做原子写、加、读，核对超过最大页数的增长返回负一。2026-10-07 在 macOS ARM64 以及 Docker 里的 Linux arm64、amd64 上运行通过；macOS x86-64 的产物经反汇编核对入口与助手。

## 内核的浮点上下文

`浮点上下文。豫`：启动时 ARM64 置 CPACR_EL1.FPEN，x86-64 置 CR4 的 OSFXSR 与 OSXMMEXCPT，并用 fxsave 给每个任务槽的保存区写入缺省状态（MXCSR 为 0x1F80）。所有处理程序都经“返回用户”回到用户态，这里比较当前任务槽与浮点寄存器的主人，不同时先把寄存器存进主人的保存区，再取回当前任务的保存区。保存区在 ARM64 的 0x400B4000（每槽一千零二十四字节，q0 至 q31 加 FPCR、FPSR），x86-64 的 0x124000（每槽五百一十二字节，fxsave64 格式）。

## 限制与待办

- 浮点值的操作数栈深超过浮点寄存器数（ARM64 二十四、x86-64 十二）时报不支持；待办事项：溢出到帧。
- 浮点局部常驻帧槽，每次访问一次载存；待办事项：给浮点局部分配寄存器。
- 含数值内在码的函数不参与小函数内联；待办事项：内联时平移码里的帧槽号与栈深。
- 不支持：多值块与块参数、br_table、间接调用、全局变量、表、i32/i64 的 clz/ctz/popcnt 与符号扩展指令、memory.init/data.drop、除载入外的非零静态偏移、带浮点参数或结果的导入（绑定为陷阱桩）。
- 只有 SSE2 的 x86-64 处理器（及 QEMU 缺省的 qemu64 型号）不能执行 SSSE3、SSE4.1 指令；在 QEMU 里运行须加 `-cpu max`。待办事项：给这些指令另写 SSE2 的替代序列。
- 等待与唤醒是单线程实现；待办事项：多线程时真正等待与唤醒。
- 六十四位地址内存：地址加静态偏移或加访问宽度超过 2^64 时回绕，越界检查留待后续版本；2^32 以上的静态偏移在 x86-64 上取低三十二位、在 ARM64 上报不支持；导入的线性地址参数是三十二位整数，4 GiB 以上的缓冲区留待导入改用长整数地址；Windows 与裸机 ARM64 的更大上限留待后续版本；macOS x86-64 的 64 TiB 零填充区留待在 Rosetta 上实测。
