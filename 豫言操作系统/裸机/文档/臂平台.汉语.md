# ARM64 平台：QEMU 与 VMware

ARM64 版豫言操作系统可以在两种平台上启动：QEMU 的 virt 机型（平台号 0），以及按 ACPI 表找设备的 UEFI 机器（平台号 1），现在实测的是苹果芯片 Mac 上 VMware Fusion 的 ARM 虚拟机（2026-10-09）。两者用同一张启动光盘 `yy豫言启动臂.iso`，由引导程序在开机时判断。

## 两种平台的差别

| | QEMU virt | VMware Fusion（ARM） |
|---|---|---|
| 内存 | 从物理 0x40000000 起 | 从物理 0x80000000 起，0x100000000 以上接着 |
| 物理 0x40000000 | 内存 | PCIe 配置空间（256 MiB） |
| 串口 | PL011，0x09000000 | 16550 兼容、按字节访问，0x3FFF03F8（虚拟机配了串口时才有） |
| GIC 分发器、重分发器 | 0x08000000、0x080A0000 | 0x2C010000、0x2C100000 |
| 实时时钟 | PL031，0x09010000 | 引导程序从 UEFI 取时间 |
| 设备发现 | 地址写死 | ACPI：SPCR、MADT、MCFG |

内核的虚拟地址布局在两种平台上相同：内核区是虚址 0x40000000–0x7FFFFFFF。VMware 上这一段映到物理 0x80000000–0xBFFFFFFF，两者之差叫物理偏移（QEMU 为 0，VMware 为 0x40000000）。手写内核里的地址常数都不用改，只有写进页表与 TTBR0 的物理地址加上物理偏移。

## 开机参数区

开机参数区在内核区开头（虚址 0x40000000，即物理 0x40000000 加物理偏移）。QEMU 直接装内核时只有前两项由 QEMU 的 loader 写入，其余为 0；UEFI 引导时由引导程序先清零 64 KiB 再写。

| 偏移 | 长度 | 内容 |
|---|---|---|
| +0 | 8 | 内存大小：内存末址减 0x40000000 |
| +8 | 8 | 映像区长度（工具映像在内存末尾，没有为 0） |
| +16 | 8 | 物理偏移 |
| +24 | 4 | 平台号：0 QEMU virt，1 按 ACPI 找设备 |
| +28 | 4 | 串口类：0 PL011 于 0x09000000，1 不用串口，2 16550 按字节于串口址，3 PL011 于串口址 |
| +32 | 8 | 串口址 |
| +40 | 8 | ACPI 2.0 根指针（RSDP） |
| +48 | 8 | 帧缓冲物理地址（UEFI GOP） |
| +56 | 4、4 | 宽、高（像素） |
| +64 | 4、4 | 每行像素数、像素格式（GOP 的编号，1 为 BGRX） |
| +72 | 8 | 开机墙钟秒（UEFI 时间折成 1970 年起的秒数） |
| +80 | 8 | 取时间时的虚拟计数（CNTVCT） |
| +88 | 4 | 保留区段数（至多 64） |
| +96 | 16×段数 | 保留区段：起址、末址 |
| +2048 | 8 | GIC 分发器（平台初置从 MADT 读出） |
| +2056 | 8 | GIC 重分发器发现区 |
| +2064 | 8 | PCIe 配置空间（MCFG） |
| +2080 | 4 | 重分发器发现区长度 |
| +2112 | 4、4 | 帧控台横、纵坐标（像素） |
| +2120 | 4、4 | 帧控台未完的码点、还差的续字节数 |
| +2128 | 4、4 | 帧控台已启用、正在画（防止异常处理里输出时重入） |
| +2136 | 4 | 桌面占用（提交帧服务置上，清屏时清掉；置上时帧控台不画字） |
| +2304 | 8 | USB 键鼠驱动的 2 MiB 物理块（0 为没有） |
| +3072 | 16 + 256 | 鼠标环：写计数、读计数，其后 256 字节 PS/2 包 |

## 引导程序（BOOTAA64.EFI）

启动光盘的内核分四段：0x40080000 起的内核、0x50000000 起的大段区、0x56000000 起的控制台字模、0x57000000 起的字体模块（桌面用的 TrueType 字体，头 16 字节是魔数“YYFONT01”与长度）。

在 QEMU 里的做法见[说明](../说明.汉语.md)的 ARM64 启动盘一节，这里只写为平台号 1 加的步骤：

1. 读完内核各段后再取一次 UEFI 内存表，可用内存（类型 1–4、7）的最低起址按 1 GiB 下取整、减 0x40000000，就是物理偏移；内核目标区间随之移到 0x40000000 加偏移起。
2. 退出启动服务之前取 GOP 的帧缓冲、配置表里的 ACPI 2.0 根指针，并调运行时服务 GetTime 取时间（按 UTC 折算）。
3. 退出启动服务后，按缓存行清洗内存表缓冲与 ACPI 区（类型 9、10），关 MMU 与缓存。
4. 清零开机参数区，写上表各项；从内存表抄出保留区段：类型不是 1–4、7，且小于 11 的区段（固件保留、运行时服务、ACPI 等）。平台号取“物理偏移不为 0”。
5. 把各段拷到载址加物理偏移。
6. 物理偏移不为 0 时，在引导程序自己的栈区底部建一张临时页表：虚址 0–1 GiB 设备内存恒等映射，1–2 GiB 映到物理 0x40000000 加偏移，2 GiB 以上 1 GiB 大块恒等映射到内存末；MAIR、TCR 与内核相同，开 MMU（缓存仍关），再跳到内核入口虚址 0x40080000。

## 内核

- **平台初置**：手写内核设好栈后最先调用底层豫言内核的「平台初置」（`内核/平台。底层。豫`）。平台号为 1 时，它读 SPCR 定串口类与串口址，读 MADT 定 GIC 分发器与重分发器，读 MCFG 定 PCIe 配置空间；给预置页表（虚址 0x400A0000 起七页）里指向内核区的项加物理偏移；把设备二级表里 GIC 那一项改指 0x400A7000 的三级表，使虚址 0x08000000、0x080A0000 落到实际的分发器与重分发器；把 PCIe 配置空间映到虚址 0x3F000000，把串口所在的 2 MiB 块恒等映射。手写内核随后把 TTBR0 设成预置零级表的物理地址（虚址加物理偏移），从此用内核自己的页表。
- **串口**：输出与输入按串口类走 PL011 或 16550 的寄存器；串口类为 1 时输出丢弃、没有输入。
- **内存池**：从物理 2 GiB 加物理偏移起（VMware 上从 0xC0000000 起，让开内核区），保留区段覆盖到的块置为占用。
- **页表根**：旧槽 0、1 的零级表物理地址是虚址加物理偏移；内核按物理地址读写页表时，经 2 GiB 以上的恒等大块访问（VMware 上虚址 2–3 GiB 正好是内核区的另一个映射）。
- **墙钟**：平台号为 1 时，墙钟秒 = 开机墙钟秒 +（当前虚拟计数 − 开机计数）÷ 计数频率。
- **单核**：平台号为 1 时只用开机的那个核。
- **帧控台**：有 GOP 帧缓冲（像素格式 0、1，地址在 2 GiB 以上）时，「平台初置」把帧缓冲所在的 1 GiB 恒等映射进页表，把启动盘随带的控制台字模（与 AMD64 同一份 `yy控制台字模.bin`，装在虚址 0x56000000）映进内核区；开机内存初置之后清屏并启用。手写的串口输出例程每输出一个字节，就调底层豫言内核的「帧控台字节」（`内核/帧控台。底层。豫`）：按 UTF-8 攒码点，白字黑底画 24×32 的字形（ASCII 宽 12），处理换行、回车、退格，一行写满自动换行，到屏底一次上移半屏。VMware 的 GOP 与 QEMU 的 `-device ramfb` 都能用。
- **USB 键盘与鼠标**：开机内存初置之后，有 ACPI 根指针时「键鼠初置」（`内核/键鼠。底层。豫`）在 PCIe 配置空间里找第一个 xHCI 主控（「平台初置」把 MCFG 给的配置空间起 32 条总线映到虚址 0x30000000），映它的寄存器（BAR 在 2–512 GiB 时恒等映射，否则映到虚址 0x32000000），要一个 2 MiB 物理块放环与上下文，复位主控，用命令环与事件环（轮询，不开中断）给各根端口上的设备编址，读描述符，配好 HID 键盘与鼠标的中断端点。VMware 默认带的“VMware Virtual USB Keyboard”是引导协议键盘；“VMware Virtual USB Mouse”没有引导协议，按它的报告格式认出相对（接口 1）与绝对坐标（接口 0）两个端点。手写的『控台收入』（时钟中断每 10 毫秒、读字节服务每次）先调「键鼠轮询」：新按下的键按美式键位换成字节放进控制台输入环（回车 13、退格 8、Esc 27、F2 为 18、Ctrl 加字母为控制码，方向、起首、末尾、删除、翻页键出 ESC [ 序列），鼠标报告换成 PS/2 三字节包放进鼠标环（绝对坐标按帧缓冲宽高折成位移）。
- **桌面服务**：服务 32–36 一律交豫言内核（旧槽也是）。有帧缓冲时：33 帧缓冲信息返回 宽×65536+高；32 提交帧把任务线性内存里的 RGBA 画面逐行拷进帧缓冲（像素格式 1 时交换红蓝），像素地址为 0 是清屏并把屏幕还给控制台；35、34 返回、读出字体模块；36 从鼠标环取一个字节。执行器的裸机显示后端因此在 ARM64 上照常运行桌面（「图形」）。

## 在 VMware Fusion 里运行

1. 新建虚拟机：选“创建自定虚拟机”，操作系统选“其他 → 其他 64 位 Arm”，固件为 UEFI；内存 2 GiB 以上（4 GiB 较宽裕）。
2. 光驱接 `yy豫言启动臂.iso`，开机时固件从光盘启动。屏幕上显示命令壳的输出（中文用控制台字模），点进虚拟机窗口就能用 VMware 的 USB 键盘打字；输入「图形」进入桌面，鼠标可用。
3. 串口可以另接，便于记录或从宿主打字：在 `.vmx` 里写

   ```
   serial0.present = "TRUE"
   serial0.fileType = "pipe"
   serial0.fileName = "/tmp/yy串口.sock"
   serial0.pipe.endPoint = "server"
   efi.serialconsole.enabled = "TRUE"
   ```

   开机后用 `nc -U /tmp/yy串口.sock` 连上，就能在命令壳里打字。

实测（2026-10-09，VMware Fusion，4 GiB、2 个虚拟处理器）：开机进到“壳>”；串口上输入「日期」得到正确的本地时间；连续输入八次「日期」，满屏后上移正常。QEMU 加 `-device ramfb` 时屏幕截图与串口输出一致。

USB 键鼠实测（2026-10-10）：QEMU（qemu-xhci 加 usb-kbd、usb-mouse，edk2 与 ramfb）里用监视器注入的按键运行命令、进入桌面，鼠标移动、点击「任务管理器」打开了窗口；VMware Fusion 里认出 xHCI 与键盘、鼠标设备并配置好端点，经串口进入桌面后虚拟机运行正常。

## 后续版本的事项

- 数据盘：VMware 的 NVMe、SATA 驱动，以及 PCIe 设备的配置空间读写。
- 多核：按 MADT 里各核的 MPIDR 叫醒其余核（VMware 第二核是 0x10000）。
- 鼠标滚轮、按键重复、大写锁定、USB 集线器后面的设备与热插拔。
- 只认 ACPI 2.0 的 XSDT；时区按 UTC 解释 UEFI 时间（VMware 给的是宿主本地时间，系统时区默认 0 时显示正好是本地时间）。
