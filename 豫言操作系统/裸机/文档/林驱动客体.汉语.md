# 内置 Linux 驱动客体

这是以豫言内核为宿主、以内置 Linux 虚拟机承载现成驱动与用户态组件的实施方案。本文记录拟议分工与验收条件；尚未实现虚拟机进入或 Linux 嵌套启动。

## 开发机核实

2026-10-03 只读检查：当前开发机为 ARM64 macOS；受信任开发机 pit-mac 为 Apple M2 Max、ARM64。它们不能提供本次所需的原生 x86 VMX 验收环境。

pit-pc-ubuntu 为 x86-64、Intel Core i9-14900K，CPU 报告 VMX、EPT，`/dev/kvm` 存在，`/sys/module/kvm_intel/parameters/nested` 为 `Y`。当前 SSH 用户 zc 的组列表未含 kvm，对 `/dev/kvm` 的读写检查未通过。标准 `/usr/bin`、`/usr/local/bin` 未找到 qemu-system-x86_64。须安装 QEMU 并取得 KVM 使用权，随后以豫言内核自身探测和真实虚拟机进入核实暴露给第一层客体的能力。检测到宿主标志尚不足以宣告嵌套虚拟机可用。

外层采用 QEMU/KVM、`-cpu host`；不把普通 TCG 当作 VMX/SVM 的替代验收。开发机的 Linux 是验证外层模拟器的环境，产品启动路径仍为豫言内核承载 Linux 客体。

## 三个里程碑

| 阶段 | 本方向负责 | 硬件方向依赖 | 验收 |
|---|---|---|---|
| 极小客体 | 约定客体 RAM、入口、串口端口与日志；准备只写串口后停机的受测指令字节 | 能力探测，VMXON/VMCS，客体寄存器，EPT，进入及退出分派，失败诊断 | 日志明确区分不支持、进入失败和客体实际写出的标记；HLT 退出后宿主继续运行 |
| Linux 启动 | 固定内核、装载参数、最小设备模型、串口日志 | 足够的客体内存、CPU/MSR 行为、中断注入及时钟推进 | 日志先达 Linux banner，再达 init 启动标记；不能把外层 QEMU 直接启动 Linux 计作通过 |
| 服务往返 | 先以第二串口承载请求和响应，客体服务以豫言编写；完成一条回声服务 | 串口读取引起的退出和响应注入，运行继续，虚拟机回收 | 豫言送出带编号请求，Linux 用户态服务返回同编号和内容；客体停止后豫言仍可操作 |

硬件会话尚未收到本次架构转向指令；本方向不会假定其已开始实现 VMX，也不重复修改内核虚拟化代码。下述为待联调的内部约定，具体代码接口在硬件分工确认后落定。

## 首个 Linux 客体

内核候选固定为 Linux 6.12.112（2026-10-03 官方长期维护版本）。源码已下载到 `/private/tmp/yyLinux-6.12.112.tar.xz`，SHA-256 为 `164dc9d1f6c93c61a15e1f071c48379b467f2b17c469cce7223471968208ed03`，与官网清单一致；已解压到 `/private/tmp/yy林客体源码/linux-6.12.112`，内核尚未构建。验收机当前缺少 flex、bison、libelf 与 OpenSSL 开发头文件；现有 `/boot/vmlinuz-7.0.0-34-generic` 无读取权限，未用它验证解析。Linux 内核作为外部客体组件保留其原有语言与构建系统；仓内装载器、设备模型、验证器和客体服务新增源码使用豫言，不转写 Linux 驱动。

第一版设一个 vCPU、512 MiB 独占 RAM，直接装载 x86-64 bzImage 和 initramfs，不引入客体 BIOS、UEFI、图形、PCI 扫描或真实设备直通。initramfs 只需 `/init`、控制台设备和用于验收的服务程序；初期服务可复用仓库已有 Linux 原生执行路径，须先确认生成物可作为独立 init 运行。

装载器核验 bzImage 的 boot flag、HdrS、协议版本、64 位入口支持、setup_sects、syssize、kernel_alignment、pref_address、init_size、命令行容量与 initrd 上界。按内核头部计算压缩主体位置，不把整个 bzImage 当作入口代码。建立全零 boot_params，复制 setup header，填写命令行、initrd 和 E820。64 位入口为装载主体地址加 0x200；RSI 指向 boot_params，按协议设置段寄存器、关闭中断，并恒等映射解压所需范围、参数页和命令行。布局必须由实际 init_size 与 initrd 大小计算，避免重叠。

## 最小设备与 CPU 契约

日志串口拟为 16550 COM1（0x3F8），服务串口拟为 COM2（0x2F8）。由豫言截获客体端口 I/O，模拟收发寄存器、线路状态及初始化所需寄存器；客体日志输出转到宿主日志，不能放行对实体串口的任意访问。

Linux 早期日志可用轮询串口，完整启动仍需可工作的计时和中断。已核对固定版本 `arch/x86/Kconfig`：X86_64 会选入 X86_LOCAL_APIC，其后选入 X86_IO_APIC，不能靠关闭 SMP 从构建中去掉它们。首轮评估单处理器、关闭 ACPI 与 PCI，`noapic` 禁用 IOAPIC 路径、`nox2apic` 禁用 x2APIC，保留 LAPIC 与 PIC/PIT；实际启动仍须验证，不能宣称只做 UART 就能启动 Linux。CPUID、控制寄存器、MSR、异常与 EPT 退出须与暴露给 Linux 的能力一致，不暴露尚未实现的 kvmclock 或其他半虚拟化特性。

先使早期串口 banner 可见，再完成时钟、中断和 init；每步保留完整启动日志及首个未处理退出原因。参照 QEMU microvm 的精简设备范围，不把其设备实现当作已存在于豫言。

## 首条服务

为最快完成往返，先用独立串口上的可打印单行协议：请求 `编号 回声 内容`，响应 `编号 成功 内容`。日志与服务分开；一时只有一个在途请求。请求单行预算先取 65536 字节，越界时返回错误；字节编码为 UTF-8，首轮测试内容不含换行。此为内部验收协议，不建立公开应用 ABI。

Linux 服务初期只返回所收内容；由豫言检查编号与内容，随后停机并确认宿主可继续运行。无线网络与 CUDA 将来在 Linux 客体内执行，通过专门服务提交任务、取结果；真实 DMA 设备分配、中断隔离、IOMMU、设备复位与 CUDA 驱动版本匹配属于后续阶段。E40 CPU、无线网卡 ID 与 VT-d 尚未知，本方案不据此承诺其设备直通可用。

## 装载准备代码

`林客体装载。豫` 已实现 bzImage 校验、主体截取、低于 4 GiB 的装载地址与 initrd 布局、4096 字节 boot_params、三项 E820 和零终止命令行。参数页地址为 0x9000，命令行地址为 0x20000。首版只接受至少 2.12 的六十四位可重定位高位装载镜像；内核初置区与 initrd 重叠时拒绝。

`林客体准备。豫` 生成内核、参数页、命令行和 initrd 四个原始二进制片段，并打印客体地址，供后续虚拟机装载端接入：

```text
节点 yy豫构.wasm 构建 豫言裸机 林客体准备 --输出 yy林客体准备.wasm -j 24
节点 yy林客体准备.wasm 内核bzImage 初盘或无 yy林客体
```

`林客体装载。测试。豫` 已在节点宿主通过 13 项产物核对及 14 项损坏／不支持输入拒绝检查，覆盖主体边界、initrd 指针与长度、命令行、E820、sentinel 清零、头部损坏、主体截断、错误对齐、高地址与内存重叠。此为离线装载验证；尚无真实 Linux bzImage 解析、VMX 客体执行或嵌套 Linux 启动结果。
