# 苹果笔记本启动验收

目标：用户要求支持 MacBook Pro（Retina，13 英寸，2013 年末）。用户确认当前已安装 Linux，可作 U 盘启动实测。独立工作树为 `~/repos/yuyan-worktrees/苹果二零一三启动`，基线 yybs `00dc0cb1b`。本阶段复用现有通用 EFI 启动介质，先验收 U 盘加载内核、图形命令壳与 USB 输入；内置键盘、触控板、内部存储和其他设备另据实体证据接线。

[Apple 官方规格](https://support.apple.com/en-us/111946) 记载 Intel Core i5/i7、Intel Iris Graphics、2560×1600 显示屏及两个 USB 3 接口。[Apple 启动按键说明](https://support.apple.com/en-us/102603) 说明 Intel Mac 启动时按住 Option 进入启动管理器。具体 USB 连接拓扑及设备身份尚待用户的 Linux `lsusb -t` 输出或实体启动日志。

## 候选介质

产物 `yy苹果启动.iso`，复用已构建的混合启动镜像，SHA256 为 `b5feac95b5a2b040dfaa2d74c201552b6f642a3ab40a336095261c3d3439cddb`。xorriso 核对 MBR 中存在 `0xEF` EFI 分区及 `0xAF` 分区；源介质含 `EFI/BOOT/BOOTX64.EFI`，file 确认为 x86-64 PE32+ EFI 应用。Limine 配置以 multiboot1 加载内核及默认字模；本阶段未新增系统 ABI 或苹果专用兼容层。

## 模拟器证据

Q35、Haswell、TCG、512 MiB、单核、禁 PS/2、OVMF、qemu-xhci。镜像作为只读 USB 磁盘接第二 USB 端口，第一端口接高速 USB 键盘，未附光盘。OVMF 日志明确从“UEFI QEMU USB HARDDRIVE”加载、启动；随后显示豫言核心与命令壳就绪。帧缓核对为 1280×800、32 位、行距 5120，截图确认图形中文命令壳实际显示；F2、H、Shift-H 输入 `hH`，正常退出。TCG 对 Haswell 部分 CPU 特性报告不支持，此测试不模拟完整 Mac 硬件或 Apple 固件。

最新候选刷新至上述 SHA256，包含已提交的双 EHCI 存储、集线器区域与额外周期队列接线。再次以同样 Q35/Haswell/OVMF 配置从 USB 磁盘启动，日志明确 USB HARDDRIVE 启动项；内核、命令壳就绪，F2、H、Shift-H 得 `hH`，正常退出。新截图 `yyMacLatest.png` 已人工查看，1280×800 中文图形画面与输入显示正常。此为模拟器回归，实体 Mac 的 Apple 固件、内置输入和内部存储仍未验收。

## 实体机验收仍待

把候选镜像写入明确选定的测试 U 盘，关机后接入 Mac，开机按住 Option，选择 EFI 启动项；记录是否出现内核、命令壳与图形显示，再验证键盘。写盘前须确认测试盘身份，避免误写当前 Linux 或 E40 数据盘。此文不据模拟器结果宣称 Mac 已兼容；Apple 固件识别、实际显示模式、内置输入与内部存储均未取得实测证据。
