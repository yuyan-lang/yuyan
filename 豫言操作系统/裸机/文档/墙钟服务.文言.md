# 墙钟之务：实时钟之基、毫秒墙钟与对时之偏

内核之墙钟凡三层：务二十六「墙钟秒」每次读硬件实时之钟，返自 1970-01-01 00:00:00 UTC 起之秒数（三十二位无符号，可至 2106 年）；务百二十一「读墙钟基准」以开机所读一次之基秒、基滴与务百二十二「设墙钟偏移」所设之偏授人；执行器之墙钟纳秒依基加单调之计时而推，又加对时之偏，得毫级之读数。务百四十二「读墙钟偏移」以百二十二所设之偏还于对时之客，客据此于今偏之上累加（十月二十二日，议三百二十六）。务百二十三「写起居注」使执行器书行于内核之注（网络对时之成败用之）。前此唯有开机以来之钟滴答（务五，每滴答十毫秒）与止于秒之墙钟，不能言今日几何、几分几秒几毫；今用户态执行器据此成标准库之 `今时` 与壳之 `日期`，网络对时之客（`库/几席/对时令。豫`）据此算偏。

## 硬件与读数

| | ARM64 | AMD64 |
|---|---|---|
| 硬件 | PL031 实时钟，QEMU `virt` 中在 `0x09010000` | 旧制 CMOS 实时钟（MC146818），端口 `0x70`（引）、`0x71`（数） |
| 读法 | 平台号零则一载得秒数；平台号非零（如 VMware）则取引导程序自 UEFI 书于开机参数 +72 之开机墙钟秒 | 读年月日时分秒，以民用历法折为秒数 |
| 码 | 取基时读一次 | 取基时读一次，约三百二十字节 |

务二十六之旧径犹存（臂读 PL031、兼读 CMOS、VMware 以开机参数加虚拟计数），备用随机四字等仍得用之。务百二十一之基惟初呼时取：读硬件之钟得基秒，并记此刻之全局滴答（务五之数）与已取之标；硬件钟不出则返负一，执行器退从每读硬件之旧路。兼之折算用 Howard Hinnant 之 `days_from_civil`：先以一月二月为上年之十三、十四月（`y -= m < 3`），`era = y / 400`、`yoe = y % 400`，`doy = (153·(m>2 ? m−3 : m+9) + 2)/5 + d − 1`，`doe = yoe·365 + yoe/4 − yoe/100 + doy`，天数 = `era·146097 + doe − 719468`；秒数 = 天数·86400 + 时·3600 + 分·60 + 秒。三十二位乘法之低三十二位与无符号数合，故至 2106 年皆确。同一算法先以 JavaScript 对照 `Date.UTC` 检之，1970–2105 年每月之朔日、廿八日、月末与十五日各三时刻（共一万九千五百八十四），皆同。

## 基、偏与诸务

全局之区记五格：基秒（+640）、基滴（+644）、偏移之毫（+648，有号）、已取（+652）、偏移之秒（+656，有号）。务百二十一以基秒、基滴、偏移之秒、偏移之毫各四字书于呼者（书于其线性内存，越界或基未得则返负一）；务百二十二受偏移之秒与毫二有号之数，秒毫分传，虽跨数年之跳亦容；务百四十二以百二十二所设偏移之秒与毫各四字书于呼者（目越线性内存或旧核则负一），对时之客据此于今偏之上累加；务百二十三取呼者线性内存之一段字入起居注（内核之注之二兆环），返所书之数；源须在低址中转之缓（六十四位址之构，回收之堆在四吉以上，平台之址惟受三十二位），执行器之「注起居」先抄之乃交。务号百二十一至百二十三与百四十二在手写内核付豫言内核之分派之内（务号不小于三十七者转于内核），二构共用一份豫言之码。

## 执行器之毫秒墙钟

执行器之「读墙钟纳秒」（`裸机底层基础。底层。豫`）于裸机如此算之：

一、初呼时问务百二十一取基，以基秒、基滴、偏移之秒、偏移之毫与此刻之周期计数记于本务之状态格；基不得则退从旧路（每读务二十六之秒、依见秒变以来之滴答补毫）。

二、每呼读务五之时钟滴答与目标内建导入「周期计数」（兼为 `RDTSC`，臂为 `CNTVCT_EL0`）。滴答行一格以上，则以这一段之（周期差÷滴差）重估每滴之周期数；格数逾十（约百毫）则周期计数或已绕，不估。

三、本格内已行之毫 =（周期计数 − 前见滴答变时之数）÷（每滴之周期数÷十），至多九毫；毫总 =（滴差×十）+ 格内之毫 + 偏移之毫；毫总负则借一于秒，得整秒与零至九百九十九之毫余。

四、秒 = 基秒 + 偏移之秒 + 所借之秒，乃乘为六十四位纳秒（秒×10⁹ + 毫余×10⁶）。

故墙钟一次开机惟读一次硬件之钟，秒与秒之界不复随本务见秒之刻而移；同一实例之内不退。取基时之秒内相位（真时那一刻在基秒之后几何）未测，对时之前或差一秒，对时所设之偏兼补之。

原生之系统（林檎、林纳、轩窗）上「读墙钟纳秒」仍径取系统之钟，不设偏移。

## 网络对时

壳之命「对时」依 RFC 4330 之简单网络时间协议第四版（SNTPv4）、RFC 5905 之客户端式取时：于服务器之 UDP 123 端口发四十八字之问（首字 `0x23`，余零），自答中之收时（偏三十二）与发时（偏四十）算

- 偏 =（（收刻 − 发出时本地之刻）+（发刻 − 收得时本地之刻））÷ 二
- 往返之迟 =（收 − 发）−（发 − 收）

时印自 1900-01-01 起之整秒与三十二位之分数；折为纪元之毫则秒减 2 208 988 800，分数取高十六位乘千而右移十六（误不逾一毫）。设墙钟偏移（务百二十二）所收为绝偏，故「施偏移」先经务百四十二读核此刻之偏，加所量之偏而后授核：偏逾一秒则先以初偏加于今偏而跳之，复询取残差，再以残差加于跳后之偏（首次往返之迟会歪其大跳），小于一秒亦径设。同一次开机再行「对时」，所量惟数十毫之残差，加于开机之大跳，不冲二十五年之正。服之缺省依 `pool.ntp.org`、`time.cloudflare.com`、`time.google.com` 次试；授「服务器」则惟试其一。每台之请（解名、发与候答合，执行器以单调之钟计期）至多二秒，期至则作其未答而及其次；三台皆不答则书“对时失败：…”而还，壳不滞（十月二十三日，议三百八十）。得手则以偏经务百二十二授核（原生之系统不改系统之时，惟印宿钟），并以上次对时之本地刻、偏、迟与服书于数据盘之 `/系统/对时。数据。豫`。

开机自启之首句有「自动对时」一句：设中「开」为阳（缺省）则开机联网后对一次，成否皆注起居一行，败不碍启；为阴则无为。开关以壳命「设对时」于「开」曰阳／阴 易之，`「时态」` 印钟之源、开关与上次对时之果。

## 验

`裸机验证` 原有四式照旧覆务二十六之两种硬件读法与兼之折算（`-rtc base=` 置于闰世纪朔日、年末前十秒、非闰世纪朔日与闰日正午；用户模块先读一次、空转三百万回再读，以无符号比较断其不退、不逾八秒）。

新增对时之验于 QEMU 为之：以 `-rtc base=2001-01-01T00:00:00` 启，使实时钟差二十五年；开机联网后「自动对时」行一次，`「日期」` 当与 `date -u` 相去一秒之内，`「对时」` 印偏与迟，`「时态」` 印钟之源与上次对时；既而于同一次开机再下「对时」一回，`「日期」` 仍与 `date -u` 相去一秒之内（不复退至 2001 年），所印之偏惟数十毫；不带网卡（`-nic none`）启则对时败，开机与他命皆不受其累。

## 界

- 务二十六仍止秒之精；毫来自基加单调之计时，开机之后不复从硬件之钟（改硬件之钟须重启乃见）。
- 执行器取基时未测秒内之相位，对时之前秒内之毫或整体偏至一秒；对时之后则确。
- 兼未理十二时制，亦不查 CMOS 之电池位；QEMU 中二者皆为默认。
- 用户态执行器以之成标准库之 `今时` 与 `今时依式`（见[客体二号](客体二号.文言.md)“时与杂项之原语”）。昔 WASI 之实时钟（以初读之墙钟秒为锚、循滴答而行，其精十毫秒）随 WASI 而拆出，见 [瓦西库](../瓦西库/说明.文言.md)。
