# 动态任务（AMD64）

AMD64 内核在原有的两个静态任务槽（槽 0、槽 1）之外，提供任意多个动态任务。动态任务由服务 37「装载任务」从开机时留下的用户区模板起一个全新的任务，不复制父任务；命令壳的「运行」经执行器的子进程路径使用它。

## 句柄与上限

- 动态任务的句柄是槽号乘二：偶数，至少 64。旧句柄只有 0 与奇数（槽 1 每复用一次加 2），两种句柄互不重叠。
- 动态槽号从 32 到 4,186,111，任务号（句柄）可到 8,372,222；能同时存在的动态任务个数由内存决定。
- 分槽用游标从小到大轮转，回收的槽要等游标转一圈才会再用，旧句柄不会马上指向新任务。

## 槽区与内核任务窗口

每个动态槽有 128 KiB 的槽区，映在内核任务窗口 0x8000000000（PML4 第 1 项，仅内核可访问）加槽号乘 128 KiB。十六个槽共用一个 2 MiB 物理块（组），组块在第一次分到这一组的槽时向内存管理要来并清零。

| 槽区偏移 | 内容 |
| --- | --- |
| 0x00 | 状态（位义同旧槽：1 可运行，2 曾运行，4 已完成，8 故障，0x10 等任务，0x20 被终止，0x40 等消息） |
| 0x04 | 退出码 |
| 0x08 | 主人句柄 |
| 0x0C | 等待目标句柄 |
| 0x10 | 本句柄 |
| 0x14 | 内存块数 |
| 0x18 | 页表根（物理地址，八字节） |
| 0x20–0x30 | 用户区块号、原生栈两块、启动块块号与长度 |
| 0x34、0x38 | 调度环的后继、前驱 |
| 0x40 | 邮箱（十六字节，格式同旧槽） |
| 0x50 | 子毕粘（子任务结束时主人没在等，置一；主人下一次等消息清掉并立即返回） |
| 0x100–0x12C | AMD64 工具映像子任务的十二块原生栈 |
| 0x130 | 工具映像号 |
| 0x140–0x158 | 启动块第 2 至 8 块的块号 |
| 0x200 | 保存帧（160 字节） |
| 0x400 | 浮点区（fxsave，512 字节） |
| 0x600 | 控台行缓冲（0x7FC 处是字节数） |
| 0x1000 | 原内存块号表（2048 项；10-08 起内存管理改在豫言内核，以页表记账，此区不再使用） |
| 0x4000 起 | PML4、低区 PDPT、低区页目录、动态区 PDPT 与四张动态区页目录 |
| 0xE000 | 高区记账：高区已提交块数、页表块数、末块已用页数，+0x10 起是页表块号（至多 8188 块；见[内存块管理](内存块管理.汉语.md)的“豫言内核”） |
| 0x16000–0x160FC | ARM64 工具映像子任务的六十四块原生栈 |

窗口的元数据在窗口最后 1 GiB（0xFFC0000000 起）：M0 块放窗口 PDPT、第 511 张页目录（其第 0、1 项映 M0、M1，第 2、3 项是两个 2 MiB 临时窗口）与槽位图；M1 块放其余 511 张页目录。窗口在第一次装载任务时建成；两个旧槽 PML4 的第 1 项同时指向窗口 PDPT，动态任务的页表从槽 0 拷来，所以所有地址空间看到同一个窗口。

全局量在 0x121F08 起：动态槽数（已装载未回收的个数）、窗口已建、M0、M1、模板块号、分槽游标、调度环头。

## 装载任务与启动块

- 开机初置在高区内存初置之后，若机器有 128 MiB 以上的内存，就要一块并把用户区 0x200000 起的 2 MiB 原样复制进去，作为模板（此时大码初置已写好预编二的跳板）。只有 128 MiB 的机器不留模板，装载任务返回 -1，行为与旧版完全一样。
- 服务 37 装载任务（启动块的线性地址、长度；长度参数低 24 位是长度，至多 16 MiB）：建窗、分槽；要用户区一块（拷模板）、预编二启动盘再要两块原生栈（清零，映到 0x1C00000 起）、有启动块再按长度要至多 8 块（第一块记在槽区 +0x2C，其余在 +0x140 起，按 2 MiB 一段从调用者线性内存拷入）；页表从槽 0 拷来再改用户区、原生栈与动态区；首帧 rip 0x200000、rsp 0x3F0000、rflags 0x202；浮点区置控制字 0x37F 与 MXCSR 0x1F80；主人是调用者；入调度环，动态槽数加一，返回新句柄。
- 服务 38 读启动块（目的线性地址、块内偏移）：偏移为 -1 时返回启动块总长；否则从偏移所在的块每次拷至多 64 KiB（不跨块），返回拷的字节数；旧槽与没有启动块的任务返回 0。
- 执行器约定的启动块：送参数区 64 KiB、送程序名区 64 KiB、程序字节，末尾 16 字节是魔数、程序长、子任务模式与父任务句柄（子任务的输出捕获消息送给它）。子任务开机先问总长，认出魔数后取回这些内容，照“子任务改装”拷成自己的参数、程序名、当前目录、输入路径与环境，再做重启准备，随后的启动循环直接运行新程序。程序长于模块窗口（448 KiB）时放到区域起，由重启准备落位。

## 工具映像

- 启动盘加 `--预编二 --工具链` 时，豫构与编译器各预编成一个工具映像，作第四、五个模块随盘（`boot/yytool1.bin`、`boot/yytool2.bin`），同样的 wasm 放进数据盘的 `/工具/`。映像开头 128 字节是头：魔数、版本，用户载荷、大段区与机器码各自的偏移与长度，客体（工具 wasm）的字节数，客体在开头、正中、末尾三处各 8 字节的样本，以及客体 SHA-256 的十六进制。
- 开机初置在留模板之后、多核开机之前登记工具映像（跳转表 +80）：逐个找带魔数的模块，记进 0x1F0000 起的映像表（每项 256 字节：载荷模板块、大段区两块、机器码物理址与长度、头的副本），载荷与大段区拷进新要的块，载荷开头跳板的入口槽写成 0xC0000000 加机器码物理址的 2 MiB 内偏移。旧池位图同时记下引导模块所在的块，开机时要块绕开它们。
- 服务 37 装载任务的长度参数第 24–31 位是映像号，0 是普通装载。按映像号起的子任务：用户区拷自该映像的载荷模板；机器码映到 3 GiB 起（低区 PDPT 第 3 项指向槽区 +0xC000 的页目录）；大段区只读，映到 0x400000 起（低区页目录第 2 项是第一块的大页，第 3 项指向槽区 +0xD000 的页表：前 0x1D0 页映第二块，后 0x30 页恒等映射外置的内核代码 0x7D0000–0x7FFFFF，内核在子任务的地址空间里也调用它们）；原生栈 24 MiB（低区页目录第 4–15 项，十二块）。
- 服务 39 处理器核数：返回其余核数加一。服务 40 映像信息（映像号从 1 起，目的线性偏移）：把映像头副本 128 字节拷给调用者，返回 0；没有这一号返回 -1。
- 执行器父任务按客体长度与三处样本找映像号（`映像号查`），找到就送程序长为 0 的启动块并带上映像号；子任务见程序长为 0，就跳过重启，块态记 2，照常运行嵌入的客体并使用预编代码。
- ARM64 的工具映像（2026-10-09）：豫言系统 `臂工具映像 --输出 目录 [--六十四位地址]` 造出 `yy臂工具1.bin`（豫构）、`2`（编译器）、`3`（豫言系统），头与 AMD64 相同。QEMU 用 loader 把它们按 2 MiB 对齐装在内存末尾的映像区，映像区长度预写在物理 0x40000008，物理池让开这一段；开机「臂映像初置」按 2 MiB 步长找魔数，把载荷、大段区与机器码拷进新要的块，记进 0x400B6000 起的映像表（每项 512 字节：+0 载荷模板块、+4 大段区块数、+8 机器码块数、+0x20 头副本、+0x100 起大段区块号、+0x180 起机器码块号）。映像任务在普通页表上再改二级表：第 128–159 项映大段区（0x50000000 起，只读），第 256 项起映机器码（0x60000000 起，只读可执行），第 336–399 项映 64 块原生栈（0x6A000000–0x72000000，128 MiB；ARM64 预编代码的栈帧较大，12 块时豫言系统在系统里造执行器镜像会栈溢出）；载荷开头 16 字节的跳板把栈指针设成 0x72000000 后跳到 0x60000000。

## 调度

定时中断、阻塞服务与退出后的调度一律由豫言内核的「调度」统一轮转：次序是槽 0、槽 1（旧槽数为二时）、调度环里的动态槽，再回到槽 0。切换时整帧存入旧任务的保存帧、取出新任务的帧并换页表根；浮点状态即时切换，主人记在 0x124400，所以系统调用返回处的惰性切换总看到“主人就是当前槽”。多核时只挑不在别核上运行的任务，没有可运行任务的核进入空闲，见[多核](多核.汉语.md)。

## 服务

- 动态任务的系统调用由外置模块分派：写字节（本槽行缓冲）、核验、完成与退出任务、任务编号、陷阱、句柄服务（状态、退出码、等待、终止、回收、发送）、接收、来源、等待消息、内存块（与旧槽同一套，按槽取址）、装载任务、读启动块、处理器核数、映像信息、读他任务、写他任务；时钟、读字节、墙钟、中断查询、设备与持久块服务回到原分派（后两类只许槽 0）；帧缓冲信息与字体模块长度返回 0，其余帧服务返回 -1。
- 服务 41 读他任务、42 写他任务（对方句柄、对方线性偏移、本方线性偏移、长度）：只许槽 0 调用，对方须是线性内存已迁到动态区的动态任务；对方的物理块由豫言内核的「提交块」给出（尚未提交就当场要块、清零、映进对方页表），经临时窗口 3 映射（ARM64 恒等映射，直接访问）后与本方之间按字节拷贝（41 由对方到本方，42 由本方到对方），两段都须整段落在各自的线性内存里，成功返回 0，否则 -1（见[内存块管理](内存块管理.汉语.md)的“豫言内核”）。初始任务用它整块收子任务的文件请求、送应答。
- 旧槽调用 37、38 也转到外置模块；旧槽对动态句柄调用状态、退出码、等待、终止、回收、发送时，句柄解码处转到外置模块。
- 消息语义同旧槽：邮箱一格，收信者正在等消息时立即交付；等待消息只在有“活伴”（主人可运行，或系统里还有别的可运行任务：调度环里别的动态槽或槽 0）时阻塞；孙任务要等初始任务代办文件的回信、初始任务要等孙任务的请求，中间那一代却可能正阻塞着，所以不只看自己的子任务。动态任务可以给句柄 0（初始任务，文件代办者）发消息，槽 0 也可以给任何动态任务发消息（给孙任务回信）；子任务结束时，若主人正等它或正等消息，按旧语义唤醒（等消息时来源为 -1）；主人两样都没在等，就给它置“子毕粘”（旧槽在 0x121F5C 起，动态槽在槽区 +0x50），它下一次等消息立即返回 0、来源 -1。执行器的输入输出多路等待据此阻塞：先查子任务、再等消息，其间子任务结束也唤得醒。

## 主核心的转接

外置模块（内存管理与动态任务合在一起）链接在 0x1A0000，开头是跳转表：+0 内存服务、+8 动态系统调用、+16 调度、+24 动态故障、+32 句柄服务、+40 旧槽等待消息、+48 开机留模板、+56 多核开机、+64 多核入、+72 多核出、+80 登记工具映像。主核心只加几处转接：系统调用入口（当前槽不小于 2 或服务号不小于 37 时转外置分派）、调度入口与退出后调度（有动态槽时转外置调度）、句柄解码（偶数非零句柄转外置句柄服务）、故障退出（动态槽故障转外置）、等待消息（有动态槽时转外置），都经主核心里的跳桩。外置模块调主核心的“返回用户”“调度复原”“串口字节”“系统调用分派”“接收消息”“失败”“时钟中断”“控台收入”，用链接时生成的跳桩。

## 豫言内核（2026-10-08）

动态任务的逻辑改用底层豫言写，放在包「豫言内核」的 `任务。底层。豫` 与 `装载。底层。豫`（见[豫言内核](../内核/包说明.汉语.md)），两种架构共用：分槽、组块、句柄、调度环、调度（存帧、选槽、取帧、换页表根与浮点状态）、退出与唤醒主人、消息、句柄服务、37 装载任务、38 读启动块、39 核数、40 映像信息、41/42 读写他任务、开机留模板。手写内核只留入口：

- ARM64：零级同步取出服务号后先到『动前查』——当前槽不小于 32 或服务号不小于 37 交给内核「动态服务」；有动态任务时，旧槽的 17 等消息交给「旧等消息」，8–11、13、14 用动态句柄时交给「句柄服务」。『调度返回』（时钟、等待、等消息、退出后调度）一律调内核「调度」，旧的两槽轮转已删；退出后调度在有动态任务时转『调度返回』；动态任务的陷阱与缺页经『动故障入』交给「动态故障」；开机第一次进用户态前『留模板入口』调「留模板」。
- ARM64 的槽区：任务窗口的 M0 块开头是组表（每 16 个槽一个 2 MiB 组块，记块号），+0x100000 起是槽位图；物理内存恒等映射，内核直接按物理地址访问槽区。新任务的页表：零级表在槽区 +0x4000，一级表拷自槽 0（含 2 GiB 以上的恒等大块），二级表拷自槽 0 并把第 1 项改映本任务的用户区；首帧 ELR 0x40200000、SP_EL0 0x403F0000、SPSR 0x340。
- AMD64：外置模块跳转表的 +8 动态系统调用、+16 调度、+24 动态故障、+32 句柄服务、+40 旧槽等待消息、+48 开机留模板改为小呼口（裸机后端「核任务呼口们」）：按入口约定把参数放进 edi、esi、edx、ecx（栈上帧的地址取 rsp）调内核，再按返回码收尾；主核心的调度入口『调度返回』一律转外置『动态调度』（旧的两槽轮转已删）；多核空闲的核被时钟唤醒后，『动闲选』调内核「空闲选」。开机登记工具映像（+80）、多核开机与大内核锁（+56、+64、+72）仍是手写。服务 37 的工具映像分支（映像号非零：用户区拷自映像的载荷模板，12 块原生栈，页表再映大段区、外置内核代码与机器码）在「装载」的「可装」「模板块」「建映像栈」「兼映像页表」里。
- 内核返回码：0 照栈上的帧回用户，1 交回原分派，2 单核没有可运行的任务，3 多核本核空闲。
- 陷阱诊断：动态任务以陷阱（退出码 132）或缺页故障（139）结束时，内核往控台写一行“任务陷阱 槽 码 址 栈 回”（十六进制；址为返回地址，栈为用户栈指针，回为 ARM64 的 x30，AMD64 写 0）。
- 验证：380 项裸机验证（ARM64 的双任务抢占、等待、通信都经内核「调度」）；ARM64 真壳在纯模拟与 HVF 下运行子程序走装载任务（37、38、10、13），普通豫言验证的 ARM64 壳测试（基本、文件、运行、管道、重定向、脚本、终端键）全部通过。

## 后续版本的事项

- 动态任务退出时它的子任务成为孤儿：不回收、不改主人。
- 动态任务对旧句柄只能发消息（发给自己的主人或句柄 0）；状态、等待、终止、回收旧句柄返回 -1。
- 动态任务暂不用帧服务与块设备；块设备文件经初始任务代办（远程文件，按旧协议逐条消息传递）。
- 单核没有空闲态：没有可运行任务时按失败停机；多核的空闲见[多核](多核.汉语.md)。
- 分槽时位图最坏要扫四百万位。
- 执行器的页上限是 65535 页（4 GiB），执行器改 64 位之后放大；回收位图与卡表按上限留在线性内存里，按需提交，只占堆用到的那一段。工具映像子任务的原生栈（AMD64 24 MiB、ARM64 128 MiB）、用户区与启动块在装载时就分配。
- 映像表容纳 60 个工具映像；大段区按 4 MiB 拷贝，更大的大段区留待后续版本；载荷与机器码放在 4 GiB 以下（Multiboot 1 的模块地址是 32 位）。
