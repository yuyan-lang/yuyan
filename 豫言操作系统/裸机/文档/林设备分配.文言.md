## 二至三 GiB 的设备 MMIO

固件网卡所受三十二位 BAR 0 范围广为 `[0x80000000, 0xFFE00000)`，仍须齐 128 KiB。二至三 GiB 用宿主专页目录 `0x06017000`，PDPT 项 `0x00111010` 指之；三至四 GiB 循 IOMMU 私窗所在旧页目录。客体 EPT 循实 BAR GiB 区间惟接一个设备页目录，不立另一 GiB 区间别名映射。设备仍惟映其 128 KiB，I/O、DMA、中断授权范围循旧。

## DMA 页授权实测

2026-10-04 于同一 Q35/KVM 台增 EDU `00:04.0`，实发设备传输以验 VT-d。BAR 为 `0xC0000000`，居二 GiB RAM 外；宿主以 supervisor-only、不可缓存大页访之。上下文、四级址转表留于 `0x0600E000` 至 `0x06012000`；设备址 `0x1000` 映宿主 `0x58000000`，属 Linux 客体之宿主物理区。客体 EPT 不含诸表页及设备寄存器。

EDU 先以设备内四字节零值写授权页，验目标已易、邻哨不变。继以 `0x2000` 为未映请求、改旧叶只读再试、撤旧叶再试，皆过。每易权前候设备传终且止总线主控；易叶后全局失效 IOTLB，核硬件完成及实失效范围。每拒皆核哨兵、故障待处位、目标址、设备编号 `0x20`、写访问与无写权原因码五，继清故障记录而验待处位消失。[EDU 设备协议](https://www.qemu.org/docs/master/specs/edu.html)、[QEMU VT-d 寄存器与故障码](https://github.com/qemu/qemu/blob/v10.2.1/hw/i386/intel_iommu_internal.h)

`设备保护对照` 于只读阶段故留写权。实测先见保护区已易，继保护核验失败而停，未入客体。常路四项 DMA 验毕，极小客体回归过；完整 Linux 启至 PID 1，同一虚拟机两独立客户端皆过六项服务验收。终码构建、类型检查皆过，验机皆由外层限时终之。

2026-10-04 终镜像置 e1000 于 `00:06.0`，实读 IRQ11，从 PIC 位 `0x08`、宿主向量四十三；默认、`kernel-irqchip=split` 各四独立连接，六项 TCP 皆过。两境物理请求、客体注入计数皆等，待应答录归零。默认 `00:04.0` 固件网卡镜像读 IRQ10、位 `0x04`、向量四十二，两完整 TCP 验皆过。第二串口皆 `null`，Linux 6.12.112 循既有 e1000 驱动行原生网络应用。

负对照以同六号设备镜像，GDB 停于实 PCI IRQ 读后范围检查，核实输入十一，再各以人工寄存器输入四、八易之而复行。两项皆拒网卡初置而停机，成标仍一，未发布网卡就绪二；四号输入未写路由录，八号输入录 IRQ8、位一、向量四十，电平位读回拒之。人工输入供拒绝分支之验，实固件所读仍 IRQ11。

构建、类型检查、格式化、差异复核皆过；旧 `网卡` 模式镜像逐字节同。造六号设备循位置参数 `固件网卡 0 0 6 0`；镜像 SHA-256 为 `53c68966a0e1ca402ffa81206e5506b0b23eebed9f45413b5b02b664b64849f9`，默认固件网卡镜像为 `d4dddcddb2c08811baebb8a5d6e296c40d0f3b119182d45c13d0f30a0deb10b9`。真桥后网卡、GPU/CUDA 犹待验。
## 桥后配置与 DMA 转交

配置端口转交别设物理地址生成引用，默认零则循客体址；非零则宿主书 CF8 前存所请寄存器偏移之低八位，易物理总线、设备及功能。默认及同址不增机器码。桥后设备于客体定现 `00:04.0`，DMA 根表循实物理总线索引，上下文循实设备号索引；今惟授一个功能零设备，共用一页上下文表。

`固件网卡 0 1 0 0` 择物理 `01:00.0`。授前遍 PCI 配置，验涵目标总线之桥皆具 PCIe 根、上行或下行端口能力；已验桥数书 `0x060140B0`。无 PCIe 能力、能力链不可释或端口类逾四至六，皆拒之，留空授权表。[PCIe 端口类型定义](https://raw.githubusercontent.com/torvalds/linux/v6.12/include/uapi/linux/pci_regs.h) 请求者别名分组、余功能、真设备适配、MSI 待接。

2026-10-04 于 Q35/KVM 之 `pcie-root-port` 下置 e1000，启既有裸机镜像后，固件授 `01:00.0`、BAR 0 `0xFE600000`、I/O BAR `0xC000`、IRQ10；桥内存窗涵其 BAR。此惟核模拟设备布局。传统 PCI 桥或以桥自身为 DMA 请求者，PCIe 至 PCI 桥另有次总线别名，后授须验拓扑。[QEMU 请求者地址处理](https://raw.githubusercontent.com/qemu/qemu/v10.2.1/hw/pci/pci.c)

2026-10-04 单层 PCIe 根端口后 e1000 位于物理 `01:00.0`，Linux 6.12.112 循既有 e1000 驱动枚客体 `00:04.0`，两轮六项 TCP 应用验皆过；第二串口为 `null`。物理总线一根项 `0x0600D010` 为 `0x0600E001`，物理功能零上下文为 `0x0600F001 / 0x102`，总线零根项、物理设备四上下文仍零；物理请求、客体注入计数皆一百零四，IRQ10。

三层 PCIe 根端口、交换机上行及下行端口后，e1000 位于物理 `03:00.0`，`kernel-irqchip=split` 下两轮六项 TCP 验皆过。桥数三，根项惟 `0x0600D030` 非零，物理请求、客体注入计数皆一百零三，IRQ11；两境 VT-d 故障态皆零。QEMU 许 e1000 模型接 PCIe 总线，此验涵模拟请求者之路，真 PCIe 网卡驱动、资源仍须适配。

PCIe 至 PCI 桥负对照中物理 `02:00.0` 存，普通 PCI 桥负对照中物理 `01:00.0` 存；两者皆拒，根表、上下文仍零，就绪标记一，未入 Linux。构建、类型检查、格式化、差异检查皆过；默认固件网卡镜像与前轮验镜像逐字节同。单层镜像 SHA-256 为 `40074171d2d2326af86cc5e1a740cbd5728da7bcdef85b35bbe00dae98cabfb1`，三层镜像为 `231e4e0c25b0b9255c0e9e0af33f3b4c0076d7403d403baca922ab076fd8e810`。

## 保留固件 BAR 布局

`固件网卡` 闭所择 e1000 总线主控、解码，乃读实 BAR，留固件所授址。内存基址六十四位存 `0x060140A0`，I/O 基址三十二位存 `0x060140A8`。今受 `[0x80000000, 0xFFE00000)` 内、齐 128 KiB 之三十二位 BAR 0，及 `[0x1000, 0xFFC0]` 内、齐六十四字节之 I/O BAR 1；大小循已验 e1000 类型，内存 128 KiB、I/O 六十四字节。[QEMU e1000 资源定义](https://raw.githubusercontent.com/qemu/qemu/v10.2.1/hw/net/e1000.c)

宿主循实物理块立 supervisor-only、不可缓存映射；客体循实 BAR PD、PT 索引，惟立三十二个四 KiB 读写页，I/O 转交限所择六十四字节。映前遍已采诸 DRHD，拒 BAR 与单元寄存器范围相交；范围取固件声明大小、CAP 故障记录末位、ECAP IOTLB 末位之最大者。寄存器声明大小循 `2^N` 个四 KiB 页之定义。[Linux DRHD 范围处理](https://raw.githubusercontent.com/torvalds/linux/v6.12/drivers/iommu/intel/dmar.c) 六十四位 BAR、余设备大小、客体 BAR 重定位待接。

2026-10-04 终六号设备镜像于 Q35/KVM 留 `00:06.0` BAR 0 `0xFEBC0000`，默认境四完整 TCP 验皆过。于 `kernel-irqchip=split` 双网卡境，同设备 I/O BAR 为 `0xC040`，四验过，Linux 惟枚所择网卡；未选四号设备 EPT 页仍零。又以默认固件网卡镜像择双卡 `00:04.0`，实 BAR 0 `0xFEBA0000`、I/O `0xC000`，两完整验过；PT `0x06016D00` 为 `0xFEBA0003`，此时未择六号设备起页 `0x06016E00` 仍零。六号镜像同页为 `0xFEBC0003`，四号起页零。两址皆出固件，EPT 索引循实基址而变。

负对照以 GDB 停于实 BAR 读后，核旧输入 `0xFEBC0000`，继各以人工值易之：`0xFED80000` 与单元 `0xFED90000` 寄存器范围相交，`0xFEBC0004` 含六十四位类型标志。两项皆拒初置，BAR 录仍零，就绪标记一，未入 Linux 客体。人工值供拒绝分支之验。构建、类型检查、格式化、差异复核皆过；旧 `网卡` 模式镜像逐字节同。六号镜像 SHA-256 为 `c57f0ceb47b96cf6a1c374b9d4caf981409c28b0d8d1970fc7f77c02d370cc7d`，默认四号镜像为 `3bb6a6978db3584a815cf5f298bd46f618da21717c29575674a1d8738533cf9d`。桥后配置、DMA 上下文接入，真设备、GPU/CUDA 验收，犹待成。
