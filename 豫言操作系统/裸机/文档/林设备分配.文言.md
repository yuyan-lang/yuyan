# Linux 客体设备分配

此乃“真实硬件 → 豫言操作系统 → Linux 客体 → GPU、网卡”之后续实施事。Linux 客体用既有驱动而行应用；豫言掌设备分配、CPU 址映、DMA 址空间及中断转交。既有 Linux 启、串口服务往返、极小客体验皆留。

## 今轮之状

专树为 `林设备分配`，起于已验 Linux 客体提交 `ebd67a092`。今固定 Linux 镜关闭 PCI、网络；客体物理零至 512 MiB 由 EPT 映宿主一 GiB 起。设备 DMA 须另经 IOMMU 转换，CPU EPT 映射不代之。[Intel VT-d 架构规范](https://cdrdv2-public.intel.com/831418/vt-directed-io-spec.pdf)

今已加明择 `设备隔离` 参数之初置码，于 2026-10-04 在 pit-pc-ubuntu 之 QEMU 10.2.1、Q35/KVM 验启确认已过。惟供明定 QEMU Q35、Intel VT-d 台：宿主专页表映 `0xFED90000` 寄存器所在块；验版本、四级址转之能；清 `0x0600D000` 根表，定根表指针，候 GSTS 确认，继启翻译而再候确认。根表留空授权，不开网卡 DMA；不以此称实 DMA 隔离已过。

有 IOMMU 之极小客体验 CPUID、跨退出寄存器、512 MiB 末页写、HLT 退出及 VMCS/VMX 回收皆成；同台去 IOMMU 则报能力或启确认失败，未入客体。完整 Linux 6.12.112 启至豫言 PID 1 服务就绪，同一虚拟机两独立客户端皆过编号、UTF-8、空白、错后续、空内容、超长行恢复之验。构建、类型检查皆过；外层限时终验机，未动实体设备。

## 继验之序

1. 空授权表启、缺 IOMMU 之败对照、极小客体及 Linux 服务回归皆已过。
2. 为所择模拟网卡立设备上下文、客体 DMA 址至宿主客体区授权映射，验实 DMA、未映址拒、只读页及撤销。循仓内已决之直接 IOMMU 路线。
3. 启固定 Linux PCI、网络、相应既有驱动；转配置、BAR/MMIO、设备中断，实验客体网络收发。QEMU 为硬件验境，产品宿主恒为豫言。
4. 据固件 DMAR 发现真实台，依授权设备范围验真网卡、GPU。真设备解绑、裸机启须由用户安排；未实测之设备、CUDA 不称可用。
