# Linux 客体设备分配

此乃“真实硬件 → 豫言操作系统 → Linux 客体 → GPU、网卡”之后续实施事。Linux 客体用既有驱动而行应用；豫言掌设备分配、CPU 址映、DMA 址空间及中断转交。既有 Linux 启、串口服务往返、极小客体验皆留。

## 今轮之状

专树为 `林设备分配`，起于已验 Linux 客体提交 `ebd67a092`。旧串口回归 Linux 镜关闭 PCI、网络，别已构启 e1000 之网络内核；客体物理零至 512 MiB 由 EPT 映宿主一 GiB 起。设备 DMA 须另经 IOMMU 转换，CPU EPT 映射不代之。[Intel VT-d 架构规范](https://cdrdv2-public.intel.com/831418/vt-directed-io-spec.pdf)

今已加明择 `设备隔离` 参数之初置码，于 2026-10-04 在 pit-pc-ubuntu 之 QEMU 10.2.1、Q35/KVM 验启确认已过。惟供明定 QEMU Q35、Intel VT-d 台：宿主专页表映 `0xFED90000` 寄存器所在块；验版本、四级址转之能；清 `0x0600D000` 根表，定根表指针，候 GSTS 确认，继启翻译而再候确认。根表留空授权，不开网卡 DMA；不以此称实 DMA 隔离已过。

有 IOMMU 之极小客体验 CPUID、跨退出寄存器、512 MiB 末页写、HLT 退出及 VMCS/VMX 回收皆成；同台去 IOMMU 则报能力或启确认失败，未入客体。完整 Linux 6.12.112 启至豫言 PID 1 服务就绪，同一虚拟机两独立客户端皆过编号、UTF-8、空白、错后续、空内容、超长行恢复之验。构建、类型检查皆过；外层限时终验机，未动实体设备。

## 继验之序

1. 空授权表启、缺 IOMMU 之败对照、极小客体及 Linux 服务回归皆已过。
2. 固定 EDU 页授权、实写、未映址拒、只读页及撤销皆已过；继以设备上下文、DMA 映射接所择模拟网卡。循仓内已决之直接 IOMMU 路线。
3. 启固定 Linux PCI、网络、相应既有驱动；转配置、BAR/MMIO、设备中断，实验客体网络收发。QEMU 为硬件验境，产品宿主恒为豫言。
4. 据固件 DMAR 发现真实台，依授权设备范围验真网卡、GPU。真设备解绑、裸机启须由用户安排；未实测之设备、CUDA 不称可用。

## DMA 页授权实测

2026-10-04 于同一 Q35/KVM 台增 EDU `00:04.0`，实发设备传输以验 VT-d。BAR 为 `0xC0000000`，居二 GiB RAM 外；宿主以 supervisor-only、不可缓存大页访之。上下文、四级址转表留于 `0x0600E000` 至 `0x06012000`；设备址 `0x1000` 映宿主 `0x58000000`，属 Linux 客体之宿主物理区。客体 EPT 不含诸表页及设备寄存器。

EDU 先以设备内四字节零值写授权页，验目标已易、邻哨不变。继以 `0x2000` 为未映请求、改旧叶只读再试、撤旧叶再试，皆过。每易权前候设备传终且止总线主控；易叶后全局失效 IOTLB，核硬件完成及实失效范围。每拒皆核哨兵、故障待处位、目标址、设备编号 `0x20`、写访问与无写权原因码五，继清故障记录而验待处位消失。[EDU 设备协议](https://www.qemu.org/docs/master/specs/edu.html)、[QEMU VT-d 寄存器与故障码](https://github.com/qemu/qemu/blob/v10.2.1/hw/i386/intel_iommu_internal.h)

`设备保护对照` 于只读阶段故留写权。实测先见保护区已易，继保护核验失败而停，未入客体。常路四项 DMA 验毕，极小客体回归过；完整 Linux 启至 PID 1，同一虚拟机两独立客户端皆过六项服务验收。终码构建、类型检查皆过，验机皆由外层限时终之。

生成用 `节点 yy林虚拟化探测.wasm yy林设备传输.bin 设备传输`；败对照末参为 `设备保护对照`。完整 Linux 回归于旧内核、初盘参数后加 `设备传输`。QEMU 于前述 Q35/IOMMU 参数外增 `-device edu,addr=04.0,dma_mask=0xffffffff`。无诊断参数则留旧客体之路。

## 既有网卡驱动之备

2026-10-04 已以固定 Linux 6.12.112 成别置 e1000 网络内核，实配置、哈希见[客体构建配置](../../宿主/林驱动客体/说明.文言.md)。Q35/KVM 直启对照识模拟网卡、成 `eth0` 而报 IRQ 10，豫言 PID 1 六项串口服务验皆过。今未验网络收发。

新网络内核入豫言 VMM，首遇 `0xCF8` 四字节 OUT，限定 `0x0cf80003`；旧字节端口之验拒之。继为所授网卡增 PCI 配置访问，配客体 BAR/EPT、DMA 授权，再转传统设备中断；旧串口之验仍留。QEMU 直启对照惟核外部内核及驱动，产品之路仍须由豫言宿主实测。
