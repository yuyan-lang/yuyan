# Linux 客体设备分配

此乃“真实硬件 → 豫言操作系统 → Linux 客体 → GPU、网卡”之后续实施事。Linux 客体用既有驱动而行应用；豫言掌设备分配、CPU 址映、DMA 址空间及中断转交。既有 Linux 启、串口服务往返、极小客体验皆留。

## DMA 页授权实测

2026-10-04 于同一 Q35/KVM 台增 EDU `00:04.0`，实发设备传输以验 VT-d。BAR 为 `0xC0000000`，居二 GiB RAM 外；宿主以 supervisor-only、不可缓存大页访之。上下文、四级址转表留于 `0x0600E000` 至 `0x06012000`；设备址 `0x1000` 映宿主 `0x58000000`，属 Linux 客体之宿主物理区。客体 EPT 不含诸表页及设备寄存器。

EDU 先以设备内四字节零值写授权页，验目标已易、邻哨不变。继以 `0x2000` 为未映请求、改旧叶只读再试、撤旧叶再试，皆过。每易权前候设备传终且止总线主控；易叶后全局失效 IOTLB，核硬件完成及实失效范围。每拒皆核哨兵、故障待处位、目标址、设备编号 `0x20`、写访问与无写权原因码五，继清故障记录而验待处位消失。[EDU 设备协议](https://www.qemu.org/docs/master/specs/edu.html)、[QEMU VT-d 寄存器与故障码](https://github.com/qemu/qemu/blob/v10.2.1/hw/i386/intel_iommu_internal.h)

`设备保护对照` 于只读阶段故留写权。实测先见保护区已易，继保护核验失败而停，未入客体。常路四项 DMA 验毕，极小客体回归过；完整 Linux 启至 PID 1，同一虚拟机两独立客户端皆过六项服务验收。终码构建、类型检查皆过，验机皆由外层限时终之。

生成用 `节点 yy林虚拟化探测.wasm yy林设备传输.bin 设备传输`；败对照末参为 `设备保护对照`。完整 Linux 回归于旧内核、初盘参数后加 `设备传输`。QEMU 于前述 Q35/IOMMU 参数外增 `-device edu,addr=04.0,dma_mask=0xffffffff`。无诊断参数则留旧客体之路。

## 网卡配置与 BAR 接入

2026-10-04 已加明择 `网卡` 模式，定 Q35 e1000 `00:04.0 [8086:100e]`。CF8 址客体私存，配置数据惟转此设备，余 PCI 功能报无；单次字节、字、双字书读循各自客体 RAX 之义，仍拒字符串、重复 I/O。初置去总线主控，验 VT-d 两 MiB 页之能，以四级上下文将客体零至 512 MiB DMA 址映宿主一 GiB 起，继失效上下文、IOTLB。惟授权确认后之网卡模式许书配置命令启总线主控。宿主页表、IOMMU 寄存器居授权区外。

BAR 0 定 `0xC0000000`，客体 EPT 以三十二四 KiB、不可缓存、读写页映其 128 KiB；余邻设备页不映。I/O BAR 定 `0xC000` 至 `0xC03F`，惟网卡授权模式转此六十四字节。宿主 BAR 页亦为 supervisor-only、不可缓存。配置阶段先遇 EPT 违规，再遇 `0xC000` 四字节 I/O 出；补二路后，Linux e1000 初置成而立 `eth0`，报 MAC `52:54:00:12:34:56`。此乃豫言宿主内驱动初置之实测。

同客体两独立客户端皆过六项串口服务验收；旧无设备极小客体之寄存器、512 MiB 末页、回收验皆过；EDU 四项 DMA 保护回归皆过。构建、格式化、差异检查、类型检查皆过，验机皆由外层限时终之。

## 网卡中断与网络收发

2026-10-04 已接固定 IRQ10：宿主 PIC 向量四十二，物理 PIC 惟开主级联、网卡；ELCR 设 IRQ10 为电平。截获则屏物理 IRQ，排入客体从 PIC，循客体屏蔽、IF、服务位及入口阻塞之验，经主 PIC 级联注之。客体毕两级应答，宿主行特定 EOI 而复开。恢复另验物理从 PIC 服务位，惟硬件已应而宿主未录待毕，乃补排一次。

开发时短请可用，长请或继连接超时。惟读 QEMU 监视，见物理 IRQ10 服务位恒置，客体队列、宿主待答记录皆空；加电平配置、恢复核对后，最终镜像于默认 `kernel-irqchip=on` 及 `kernel-irqchip=split` 各续验四独立客户端，编号、UTF-8、空白、错后续行、空文、过长行拒及恢复皆过。全用户态 `kernel-irqchip=off` 于此机启即报 KVM 不支持 userspace APIC，未作验境。未据此断上游 KVM 之失。

## 裸机固件表定位

明择 `固件定位` 惟读固件内存。今 Multiboot 1 传统入口，循十六字节界扫 EBDA 首 KiB、`0xE0000` 至 `0xFFFFF`，验 RSDP 签名、二十字节校验和，继遍 RSDT 求 DMAR；两表皆验签名、长、校验和，址须居今二 GiB 映射内，长至多一 MiB。RSDP、RSDT、DMAR 址及 DMAR 长，各存宿主专有 `0x06014020`、`0x06014028`、`0x06014030`、`0x06014038`；DMAR 败则后二项仍零。此模式略固定平台 VT-d 开启、设备分配，继留极小客体回归。[ACPI 根表发现规范](https://uefi.org/specs/ACPI/6.5/05_ACPI_Software_Programming_Model.html#finding-the-rsdp-on-ia-pc-systems)
