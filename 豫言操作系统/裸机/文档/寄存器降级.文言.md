# 寄存器降级

## 何以重写

旧降以内存之栈为本：每压一值，先读栈指，较其上限，写值，进一槽；每弹一值，退槽而读。比较、择一、除余，各展十余令，一操作平均约三十三字节。ARM64 命令壳因是几满一兆之预算（详[臂常量装载](臂常量装载.文言.md)），欲增执行器之能，必溢，而行亦迟。

今以寄存器为栈：虚拟栈项居于寄存器，而又并其常量与比较于后令。ARM64 命令壳自约九百七十八千字节减至十六万二千九百字节，AMD64 自七十九万八千八百七十三减至十八万四千。

## 制

- **栈槽即寄存器**：虚拟栈第 d 项恒居一物理寄存器，多于寄存器者溢于帧槽。ARM64 用 x19 至 x22 凡四，AMD64 用 rbx、r12、r13 凡三；余被调者所保之寄存器（ARM64 之 x23、x24、x26、x27，AMD64 之 r14、r15、rbp）留居局部。皆由被调者保存，函数但存其所用。栈深编译时已定，故“弃栈顶数项”“分支时改栈高”皆不生码。
- **基寄存器**：ARM64 之 x28 为线性内存基址，x18 为今字节数（页数左移十六位），x25 为全局起址；AMD64 相应为 r9、r8、r10。入口一立，不复存。
- **内部借用**：ARM64 借 x9 至 x13；AMD64 借 rax、rcx、rdx、r11 于原语内，rsi、rdi 供溢出之操作数暂居。操作数栈之项或为寄局之别名（`取读`），故原语唯读取读之操作数，欲改则先移于暂（如写八偏：ARM64 书址加偏于 x12，AMD64 先移址于 r11 而后加偏）。
- **访存寻址**：AMD64 可信之码访存，静偏容于四字节位移者，唯零扩址入 r11，以 `[r9 + r11 + 偏]` 寻址，省一加。
- **局部**：依活段配寄存器（ARM64 又得用调者所保之 x3 至 x8、x14，区间有呼则前后存取；AMD64 于 Linux 又用 r10，诸函皆可信者（原生预编二之构）益以 r8，是时访存省验界，页数读自页数之格 `0x2FFFFC`，整批内存之助亦依页数之格算界），不得寄存器者居帧槽。序言唯予入口所活之局部（未书而先读者）初值或清零。参数自 x0 至 x7（AMD64 为 edi、esi、edx、ecx）入，序言写之于局部寄存器或局部槽；逾者经共用暂存传之（ARM64 自 `0x40380000`，AMD64 自 `0x380000`，每四字节）。此址旧为内存操作数栈，今已空。
- **帧**：ARM64 自 sp 而上：x30 与首被调者所存之寄（各八字节；帧不逾五百零四者，序言以前变址之 stp 一令兼减栈而存此二，尾声以后变址之 ldp 一令取而加栈）、余被调者所存寄存器对（恒留六十四字节，使局部之偏不随所用寄存器之数而变）、局部槽、溢出槽，总数按十六字节对齐；AMD64 先 push 所存之寄存器，后 `sub rsp`，局部与溢出自 rsp 起。序言以 sp 较调用栈之下界（ARM64 `0x403D0000`，AMD64 `0x3D0000`），低则陷。
- **陷之令**：`unreachable`、越界之验与栈下界之验，其陷依目标出令。裸机客态，ARM64 `svc #7`，AMD64 `mov eax, 7; int 0x80`，内核以客陷终其任务；豫行之程经服务门之第七项。宿主之目标（Linux、林檎、轩窗，二〇二六年十月十四日起）出 `brk #0`／`ud2`，进程受 SIGTRAP／SIGILL（轩窗为异常）而立终，Linux 与林檎之退出之状，ARM64 百三十三，AMD64 百三十二。内核之态见下。
- **待发**：`i32.const` 与比较令不即发码，先记为“待发常量”“待发比较”，视后令而融之：
  - 常量后之加减、与或异或、乘、移位、比较，改用立即数式；
  - 六十四位常量后之加减、与或异或、移位，亦用立即数式（宽立之融）：AMD64 加减与或异或，常量在有符号三十二位之内，五移位取低六位；ARM64 加减，常量之绝对不逾四千九十五，左移与二右移取低六位。六十四位址之构，执行器之址算、回收之算卡号多此式；
  - 比较后之 `br_if`、`if`，径发条件跳，不先 `cset` 为零一而后测；
  - `i32.eqz` 加于待发比较则反其条件，加于待发常量则折为新常量；
  - 余令之前，先落待发者为真寄存器之值。
- **控制帧**：每 `block`、`loop`、`if` 记其类、基深、果数、分支标、终标、否则标。跳至某帧，则自栈顶取其果数之值，依次搬于该帧基深之槽，所弃中间槽不必理。`br`、`return`、`unreachable` 以后，至相配之 `else`、`end` 之前，皆死码，惟以嵌套之数略过。
- **多果**：函数与块可返数值，函数之果走结果寄存器（ARM64 为 x0 至 x3，AMD64 为 eax、edx、ecx），调者旋搬入新栈槽。
- **整批内存**：`memory.copy`、`memory.fill`、`memory.init`、`memory.grow` 各一助手，全模块共用；越界皆陷，重叠而复者按地址之势择其向；数据段之描述先四字节有效长，后接原字节，`data.drop` 则写长为零。
- **入口存根**：立基寄存器，读页数之描述，呼启动函数，探测之式再读一内核私有之址（必缺页，以证隔离），终以退出码零请求完成。
- **函内之连**：每函降毕即于函内连之：除函之入口，诸标唯本函用之，指之之相对跳（相对之移唯视二址之差）就地编之，与相邻之原字节并为一片；唯留入口之标、指他函或助手之相对片与绝址之片，付诸终连。数百万片遂为每函数片，巨模降时之存活内存与终连皆省大半。函体依需而取：模中之函项或为占位，降与内联之前经 `降级取体` 之钩取其真体（预编二借之依需而转客体之函）；遍两万余函以尾递归之带序映射，帧中不留诸函降时之临时。

两架构共此一遍历，异者唯在“令原语”一层：`指移`、`指二元`、`指载存` 诸包装，依首参分派于[臂降级原语](../库/裸机后端/臂降级原语。豫)或[兼降级原语](../库/裸机后端/兼降级原语。豫)，而原语复由[臂汇编](../库/裸机后端/臂汇编。豫)、[兼汇编](../库/裸机后端/兼汇编。豫)编码。二汇编之编码器皆有单元之试（ARM64 六十余例，AMD64 四百六十例）。

## 余波与所踩

- 用户码快逾二十倍：多任务用例中百万次之“长循环”，不复跨一时钟周期，验抢占之 `双任务`、`定时中断` 诸景遂败。新增[长算常量。豫](../库/裸机后端/长算常量。豫)，改为二千万次，每任务约百毫秒，跨数十周期。
- 探测之读必在启动函数**返回之后**：`设备缺页退出` 诸景正赖父任务返回后之一读以致缺页。
- AMD64 之载入种类编号异于 ARM64（零扩、符扩之次），初移植时字节与半字之有符号读错位，由 `固定访存` 一景所发。

## 内核态之目标（二〇二六年十月八日）

内核之不系于架构者，改以底层豫言书之，居包「豫言内核」。裸机后端「降级核篇」以裸机之目标、内核之态降之：降时「裸机核态引」为阳，降毕复阴。

- **入口**：不生用户入口之桩。模首为跳表，依「诸核出名」之序：臂每项一 `b`，兼每项 `jmp` 加三 `int3`。连于内核之模之址（臂 `0x40800000`，至多八兆，十月十三日起恒等映于旧二槽一至二吉二级表第四至七项，旧居 `0x40100000`，至多五百一十二 KiB；兼 `0x2400000`，至多八兆，十月十三日起：旧二槽低区页目第十八至二十一项映之于镜中实址 `0x800000` 起之模区；旧居 `0x1A4000`，至多二百八十八 KiB），手书之核依表项之绝址呼之。
- **原语**：导入模块「内核」之读四、写四、读八、写八、清零、复制、逐字复制、刷快表、刷一页、屏障、端口之读写（兼为 `in`／`out`，臂读得 0xFF、书则无事，十月十一日起供 PS/2 键盘）编为出线之小桩（表在「核本术表」）；「架构」为常（兼一臂二）。他目标绑之为陷。
- **栈与陷**：序言之栈界改为核栈之界（臂 `0x401E0000`，兼 `0x1EC100`）；陷改为 `brk #0`／`ud2`，入当前层之异常而转失败。
- **限**：模不声线性内存、数据段与全局，不用批量内存之操作，参不逾寄存器之数。
- **构**：生而行内核镜之器，于始呼「备豫言核」：构包、读模、臂兼各降一次，存于「核篇字节引」，生镜时纳之。
- 已迁者：二十三「内存块数」（第二步）；内存管理之全理（第三步：物理块之配、页表、按需提交、清、复任务、服务二十二、二十四、二十五与开机之初置，见《内存块管理》“豫言内核”一节）。
- **统一引导之模（二〇二六年十月十三日）**：「降级核篇」为「降级核态篇」之一用；后者可定导出名们、连址与容，并可免序言之栈界之验（降级公用之「裸机无栈界引」，界取零）。包「底层统一引导」（UEFI 引导程序登中文之字体）依导出「注册引导字体」、零址、六十四 KiB 之容、不验栈界降之，得无关其位之码，嵌于 BOOTX64.EFI 与 BOOTAA64.EFI；「备豫言核」并构之，存于「统一引导篇引」。其以内核原语「调用固件」（函之址、四八字参之参块）依固件之呼约呼 UEFI 之函：兼为微软 x64，臂为 AAPCS64。

## 栈图（提案 00020）

- **函之展开之记**：模带预编之客者，每函之入口置一长零之「栈图记」（种一），其容为旗（一位为宽函，二位为带呼处栈图之客函）、帧大与序言所保之被保之寄之次。帧之布不易：臂之 x30 居 sp，首保居 sp+8，余自 sp+16 依次；兼先依次压所保之寄而后减栈帧大，返址居所压之寄之上。末函之后、表片之前另置旗四之函展开之记为函区之末端（帧大与保存数皆零），其后表片、助手、线程桩与豫行桩无展开之记，执行器查函落此则以为不得。
- **栈图之记**（第二步）：预编二排令流时依豫汇之型记操作数栈与局部之引用位（`预二匣位`），转时于宽函之体置不发码之记（`栈图标记`，书为不压不弹之内在呼）：函首之局位记（诸局引用否；转中遇带参之块、闭包融合之途等不能循引用位者，改置函不精确记），每可回收之呼前之栈位记（实参之下诸深引用否）与临引记（呼前后持引用而型不定之局，如指令临时）。引用位以整数位集循之，唯或发呼之令记基码（疏记之表：位与基码成对，令流排毕抄为恰长之数组，转时依令流之位二分而查）。小叶内联合所内联呼处之示与被呼者体中之示（「栈图内联逆」），判可否内联不计其记。
- **呼处之栈图**：带图之客函于每非尾呼之后置一栈图记（种二），其容为呼前后皆活之引用之所在：实参之下之栈槽依栈位记（别名之寄、定之被保寄或帧中溢槽），局部依局位记与临引记，唯记呼处及其后一处皆在活段者（居被保寄者记寄，余记帧槽）；无示或栈深不合者记为不精确，回收时此帧保守而扫。持引用之局活否以事扫求之（依活段挂启止之事于位，呼位不降），诸位升序而编；容依值共一份（容池），连时依容去重。诸函共用降之暂存数组（局寄表、活集、戳、事表等），免每降一函新立数中等之数组——不移之堆既碎，不得中等之块即先收。
- **栈图之表**：终连收诸展开之记依址为表，依八字节齐接于码后，标“栈图表”：首三十二字（魔数 YYZT、版二、总长、函项数、表码偏、呼处项数、运行之表址），次每函三十二字之项（码偏与展开之记之容），次依返址递增之呼处项（各八字：返址之码偏、容距表首之偏），末为去重之呼处栈图之容；总长依八字节齐。函内之连合本函之呼处栈图之记为一函内呼处集之记（种三：诸呼处距函首之偏接其容）而置于首，不复断码于呼处；降缓与并行之降皆携栈图之记（缓编之标五）；栈图之关入降缓之键。
- **复制之桩**：执行器之占位“栈图表复制”于栈图开时尽易为复制之桩：取表之运行之址，总长不逾容则依八字节复于线性内存，副本二十四书表之运行之址。旧降级者不识之，如常编占位之体（返零），旧工具自举新源时执行器以为无表。
- **栈回写之桩**（第三步）：执行器之占位“栈回写”（栈起、掩码、表、数）于栈图开时尽易为栈回写之桩。叶桩，与栈复制之桩同于回收之帧而呼，sp 同：先以表中不小于栈起之格（栈复之缓中之线性址）依缓偏书回 sp 起之原生栈，次依掩码自栈复之首装回所置之被保寄存器（不用分支，装于暂寄而依掩码之位择之）。唯用呼者所保之暂寄，返零；旧降级者所编之体返负一，执行器启时据之定用精确客帧否。

## 界

- 局部依活段分寄存器；降前内联小叶函数（[内联小函数。豫](../库/裸机后端/内联小函数。豫)），预编二又于转译时内联小函；无公共子式与逃逸之析。
- 局部与操作数栈槽合逾三千五百之函数，入口即陷（与旧降“栈越界即陷”同）；果数逾寄存器数者拒之。
- 全局值至多四千零九十六（ARM64 单载偏移之限）。
- 旧内存操作数栈之降、内存编码及其试皆已除；[访存编码](访存编码.文言.md)、[结构控制](结构控制.文言.md)、[固定内存](固定内存.文言.md)、[批量复制](批量复制.文言.md)、[批量填充](批量填充.文言.md)所述行为之规与验收不易，其实现以此篇为准。
