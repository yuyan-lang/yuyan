# 帧之务：用户态以画书于帧缓

核务三十二「提交帧」与三十三「帧缓冲信息」（平台导入 `平台.提交帧`、`平台.帧缓冲信息`），使用户态之程以全帧之画交核，书于 Multiboot 之帧缓。惟兼容核心行之；臂无帧缓，二务皆按未知之务返一，呼者视为无显示。执行器「客体二号」据此于裸机行公共显示之约（见 `客体二号/裸显示。豫`）：一面即全帧缓，输入惟键盘。

| 务 | 参 | 果 |
|---|---|---|
| 三十三 帧缓之信 | 无 | 宽乘六万五千五百三十六加高（逻辑之素：高分之屏倍之，则半于物理之素，余即物理之素）；无可用之三十二位直接 RGB 帧缓则零 |
| 三十二 交帧 | 像素于客线性内存之址（为零则不读像素，涂 宽×高 之区为黑，倍则涂二宽乘二高；十月六日始执行器还显示面以之清屏）；宽乘六万五千五百三十六加高（逻辑之素） | 成零，败负一 |
| 三十四 读字体模块 | 目于客线性内存之址；模内之偏 | 所拷之数（至多六万五千五百三十六）；偏至末为零；无模或目越界为负一 |
| 三十五 字体模块长度 | 无 | 模之字数；无则零 |
| 三十六 读鼠标字节 | 无 | PS/2 鼠标辅口之一字；无则负一。初呼则清鼠标之环，向鼠标发 D4 F4 以开数据之报（二〇二六年十月六日） |

- **素之式**：画为 RGBA8，行优先，无行距。核读帧缓之录之红位：红位十六（QEMU 标准显卡之 BGRX）则易红蓝，红位零则如故，余式败之。Multiboot 1 之约置色彩之信于信息结构偏移百一十，Limine 四字节对齐而置于百十二，故录之红位或在 0x103926，或在 0x103928；核视 0x103927 是否红宽八以辨之。
- **验**：宽高须正而不逾逻辑之度（三十三所返之宽高）；像素须全在客可用之线性内存，界同“块搬入静态”（线性基址为三 MiB 则五百一十二 KiB，否则动态块数乘二 MiB），像素之址另有一 GiB 之粗界（旧为三十二兆，裸机页限增至千二十四页，帧缓或居其上）。画书于帧缓左上，逐行依行距而进。
- **字体模块**（三十四、三十五，二〇二六年十月六日）：启盘所带 Limine 第二模块，桌面所用之 TrueType 字体（文楷）。设备初置之时「兼容文楷模块初置」映之于核窗一 GiB 加三十二兆起（页目 0x125000 第十六项起），虚址、物理址、长度存于 0x103A00、0x103A04、0x103A08；三十四自核窗拷于 r9 加目之址，目之界同交帧。执行器于裸机诸族名皆取此体（`显示原语。豫` 之「字体裸开」「字体裸定读」）。Limine 置模紧随内核，居六十四兆块池之下（SeaBIOS 实测十四点一至三十八点五兆，OVMF 二十三点五至五十三点九兆）；若落块池，亦如首模标池图。
- **代码之居**：务体居 0x1F5000 起之外置区（帧缓映射代码所在八 KiB 之后半），依 eax 分三十二、三十三、三十四、三十五；主核分派表惟一区间之判（务号三十二至三十五皆至同一以 r11 呼外置区之呼口，主核近一万二千六百零八字之限）；构建时核两半各不逾四 KiB。
- **验收**（二〇二六年十月六日）：以 `yy豫言系统 启动盘 --壳 库/显示控件/测试/原生显示提交探针。豫` 所造混合 ISO，经 QEMU q35、SeaBIOS、xHCI U 盘而启，探针串口出“尺寸：1280×800、像素比乘六十四：64、提交：成功、等待：显示计时、归还：成功”，QEMU 监视器 screendump 得全屏 RGB(32,96,160)；`yy裸机验证` 三百八十项皆过。

待办：惟认红位零与十六之三十二位式；三倍以上之放大与写合并之映（以速高分之屏书帧）俟诸后版；书帧之际不闭中断，亦不与核之控台绘字互斥（图形之时控台之字仍画于屏）；执行器之候为忙候；鼠可用 PS/2 与 xHCI 上 USB 启动之约者（相对之移），滚轮与 usb-tablet 之绝对坐标俟诸后版。

**PS/2 鼠标**（二〇二六年十月六日）：键盘初置之配置字改为 or 0x40、and 0xCC，开辅口之钟（二路中断犹闭）；主核「键盘收入」读状态见辅口之位 0x20，则跃至外置区 0x1F5C00 之「鼠标字节入」，存字于 0x103B10 起之六十四字之环（0x103B00 魔数“MOUS”、0x103B04 写计、0x103B08 读计）；务三十六读一字，初呼则清之而向鼠标发 D4 F4。外置区之布改为：帧务主体居 0x1F5000，补零至三千七十二字，后接「鼠标字节入」。执行器（`客体二号/裸显示。豫`）成三字之包、交指之事，交画时叠绘十二乘十九之箭头光标，指移则重交末帧。

**帧缓改为写合并**（二〇二六年十月六日）：核旧映帧缓为强不可缓存（页目项 PCD|PWT）。实机每书一素、每读一字，皆一往返于总线：二千五百六十乘千六百之苹果笔记本，桌面一帧须书十六兆，迟滞可见；控台卷屏逐字而复全屏，每卷一行约十秒，目见其画如 CRT 自上而下扫。今帧缓映射先设 PAT 第四项为写合并（WC），页目项改为 P|RW|PS 加 PAT 位（0x1083），书则处理器合为整行之突发；控台至底一举上移半屏，八字一复，读显存之数减数十倍。QEMU 之帧缓本为常内存，此二者之异，惟实机乃见。

**USB 之鼠**（二〇二六年十月六日）：xHCI 之驱于全枚举时，键盘之后复寻 HID 启动之约之鼠接口（类三、子类一、约二，零备用）。键盘之途未为此器设配置，则先设之，次设启动之约，乃以 Configure Endpoint 惟加此接口之中断入端（槽上下文之条目数取旧值与此端号之大者）。三十二项之中断环、报告缓冲与鼠之诸字，皆居此槽键盘记录之后（记录偏百二十八起为鼠之字，三百二十起为报告缓冲，五百一十二起为环）。苹果笔记本内置键盘与触控板同为一 USB 器者，二接口各配一端。报告片依事之端号分流，以启动之报（键位、横移、纵移）转为 PS/2 三字之包（纵移反之），书于同一鼠环，执行器仍依 PS/2 之包解之。PS/2 之途，「鼠标字节入」与务三十六之初置先读状态之口，得 0xFF（无 PS/2 控器）则略之，鼠环惟有真字。QEMU 实试：`-device usb-mouse,bus=xhci.0` 与默认 PS/2 之鼠并存，USB 鼠点开“系统设置”；`-machine i8042=off` 惟接 usb-kbd 与 usb-mouse（如苹果笔记本，无 PS/2），USB 键盘打字入桌面，USB 鼠点“返回命令行”还壳、复入桌面点“任务管理器”皆正，鼠环之字数恰为报数之三倍；开机后 `device_add usb-mouse` 热插之鼠得新槽，亦可用。非启动子类之鼠、usb-tablet 之绝对坐标、滚轮与触控板之手势，俟诸后版。

**高分之屏倍之**（二〇二六年十月六日）：实机所试之屏二千五百六十乘千六百，一帧十六兆，执行器之堆不能容，入桌面则报“堆内存不足”（堆诊断：请求 16384016，页数 762/1024）。今核依帧缓之录现求倍数（外置区之「帧求倍」，果置于 r13）：宽逾千九百二十或高逾千二百则二，余则一。三十三返物理宽高除以倍；三十二之宽高上限随之减半，倍则每素书为二乘二：素既转，复为二份，以八字之存一书之，每行之素书二遍；涂黑之区亦乘二。执行器、桌面、光标与鼠标之坐标皆用逻辑之素，二千五百六十乘千六百之屏，桌面为千二百八十乘八百，一帧四兆。QEMU 用 OVMF 加 `-vga none -device VGA,xres=2560,yres=1600`，Limine 择二千五百六十乘千六百，实测二秒入桌面，画满全屏，红蓝不误。
