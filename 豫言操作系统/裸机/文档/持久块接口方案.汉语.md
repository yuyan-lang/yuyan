# 持久块接口方案

这是连接真实块设备与既有持久文件系统的最小接口方案。2026-10-04 用户已批准四个新导入，平台声明、服务分派、静态窗授权与 USB 文件系统接线已写入源码，正在验收。内核内部 USB bulk-only 的描述符、端点、容量、单块读写、同步及传输环周回已实现，并完成专用 QEMU 盘的写入、同步、关机重启后回读；证据见[硬件里程碑](通用串行总线硬件里程碑.汉语.md)。应用和文件系统已接线，完整文件持久化验收进行中，实体机未验；AHCI 路线可在同一块语义下另行实现。

现有 `客体二号/块设备。豫` 驱动 Virtio，设备配置读固定为 PCI 0:4.0，寄存器与静态窗口也有既定授权。真实 USB 存储不能直接套用该寄存器协议。因此向裸机的平台接口增加以下四个获批导入，保留现有 Virtio 导入与行为：

| 名称 | 参数 | 结果 |
| --- | --- | --- |
| 持久块容量 | 单位值 | 可用的 512 字节扇区数；0 表示没有可用设备 |
| 持久块读取 | 扇区号、静态窗参数 | 读取一个扇区，0 成功，否则错误码 |
| 持久块写入 | 扇区号、静态窗参数 | 写入一个扇区，0 成功，否则错误码 |
| 持久块同步 | 单位值 | 请求设备完成已写数据，0 成功，否则错误码 |

静态窗参数沿用现有「静偏或（长度左移二十）」编码，读写要求窗口覆盖一个扇区。内核从自身保留的 DMA 缓冲搬运，应用不提供设备物理地址；沿用现有静态窗口授权与越界检查，只向拥有块设备权限的任务开放。USB 设备身份和端点归内核驱动维护，文件系统仍调用既有「块容量」「块读」「块写」「块刷新」，由块设备模块选择可用驱动。

实施范围包括 USB 存储接口识别、bulk IN/OUT 端点、命令块与状态、容量、读写及同步；再以专用 QEMU 数据盘验证创建文件、写入、同步、关机重启后读取，并检查同时使用 USB 键盘的场景。实体机验收另取用户明确的数据盘与机器证据。待办事项：非 512 字节逻辑扇区、UAS、热插拔、错误恢复另行处理；未完成前不称真机持久存储已成。

新增 ABI 已获用户明确批准；语义见[持久块规范](../客体二号/平台接口/规范.汉语.md)。正式 AMD64 启动盘保留未知磁盘不自动格式化的行为，专用验收夹具可启用既有自动格式化标志。

## 确认后的接线范围

源码核对基线为 `dae59ca77`。现有服务号表止于 27，拟用 28 至 31 对应容量、读取、写入、同步；实施前复核最新表，避免并行会话占号。只有读写为双参服务，容量和同步沿用现有单位值服务的降级约定。

| 文件或范围 | 拟修改内容 |
| --- | --- |
| `客体二号/平台接口/平台。接口。豫` | 声明四个导入的类型 |
| `库/裸机后端/整数降级。豫` | 绑定服务号，登记双参服务 |
| `库/裸机后端/兼容核心。豫` 与服务实现 | 分派、调用者授权、静态窗口长度和越界检查；窗口与 `0x07C0B000` 之间复制 512 字节，复用根端内部请求 |
| `客体二号/块设备。豫` | 保留既有块函数，选择已有 Virtio 或可用 USB 服务，复用搬入静态、搬出静态 |
| 裸机说明与块接口文档双语对 | 记录服务语义、错误结果和验收范围 |

当前设备访问只授权初始用户任务，静态窗口固定为用户地址 `0x300000` 起的已授予区域；接线须沿用实际授权边界，拒绝未获授权任务与不足 512 字节或越界的窗口。USB 服务的容量来自内部探测，读写 LBA 仍须小于容量。读成功后才向窗口复制，写请求先从窗口复制，返回内部请求结果；同步不访问窗口。ARM64 与其他目标的 USB 后端未实现，不宣称这些目标支持该设备。

文件系统继续调用 `块容量`、`块读`、`块写`、`块刷新`，其双区追加日志格式不改。批准后先验证授权与边界拒绝，再用独立 USB 数据盘完成格式化、创建文件、写入、同步、关闭客体、重启挂载与读回，最后回归已有 Virtio 路径及同时使用 USB 键盘。上述接线已实施，验收结果另行记录，尚未作为实体机完成证据。
