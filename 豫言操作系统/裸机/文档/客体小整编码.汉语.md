# 客体小整数引用编码

普通豫言 WasmGC 使用 `i31`。客体执行器的整数值槽宽度为四字节，不能把完整 31 位小整数、空引用和堆对象地址当成没有类型标记的同一种整数。本阶段新增低位标记编码：`(输入 i32 << 1) | 1` 得到内部 `i31` 引用；`0` 留给空引用，非零偶数留给未来的 GC 堆句柄。`i31.get_s` 用算术右移一位恢复符号，`i31.get_u` 用无符号右移一位恢复低 31 位。两种解箱均先检查低位，空引用及偶数句柄必须陷阱。

这一编码覆盖 `i31` 的全部 2³¹ 个值，包括输入截断、最高有效位和 `-1`；内部引用的位形不能由 Wasm 整数指令直接伪造。编码现已接入 `0xfb` 的三条小整指令、客体静态栈验型与解释执行，并通过两架构 QEMU 验收；堆分配和普通豫言模块完整执行仍未实现。函数引用仍使用现有独立类型域，不与 `eqref` 混用。后续必须为偶数句柄建立受检堆表，并将操作数、局部、全局及表中的活引用纳入回收根集合。

`客体小整。测试。豫` 生成真实 Wasm 模块 `yy客体小整试模.wasm`，在豫言参考执行器中检查六组边界和四种非小整编码的两种陷阱。相同生成物再由 Node 标准 Wasm 引擎验证，六组边界和八次陷阱均通过。后续客体解释执行的验收见[客体小整执行](客体小整执行.汉语.md)。曾尝试直接把外层裸机线性内存额度升至十五页；因八页线性区之后为用户两栈，新 ARM64 场景在 QEMU 核验失败，改动已经撤回。进一步的大内存支持须先迁移两栈与映射。
