# 数值之降：浮点、长整、向量与原子

裸机后端以底层之程序所成之 Wasm 降为 ARM64 与 x86-64 之机器码。此篇述其处 i64、f32、f64、v128 与原子之令之法，使底层豫言所书之张量内核得编入原生之二进制（路二：macOS、Linux、Windows），并行于豫言系统（裸机）。

## 二途

底层之程用 i64、f32、f64、v128、原子、共享内存或六十四位址之内存者，编译器行“新路”，以通编码器书标准之 Wasm（见 `应用/豫言编译器/文档/底层模式.文言.md`）；唯用 i32 者仍行状态模块之旧路。裸机后端亦有二入：

- `数值转译。豫` 之 `需数译` 察模块有无旧路所不识者（值型、内存之标、令）；
- 有则以 `数值读取。豫` 读其标准模块，由 `数译篇` 转为寄存器降级所受之状态模块；无则仍以 `读态二进制` 读之。

`入口。豫`（豫言裸机）读 `.wasm` 之字则依此择途。编译器径出底层之程之原生之产（`--目标 本机`，裸机后端 `原生产物。豫` 之「写底本土产物」）则径得模块之产：旧路之状态模块径降之，新路之底层豫汇经 `数值豫汇。豫` 读为数值模块，乃由 `数译篇` 转之。唯用 i32 之程，所生与改前逐字节同。

## 转译

转出之模块：导入如旧；次于导入者，窄之包装函数“启动”，呼原模块所导出之“启动”或“_start”；其后为转出之宽函数，导出“预编二起号”指其首。原模之函数导出皆存（定义函数之号随包装后移一位，原“启动”以包装代之）；六十四位址内存之模另加导出“长址内存”为记（指包装函数）。宽函数之值皆占六十四位（见 `宽降级原语。豫`），故：

- i32 之令如旧，其果零扩；
- i64 之令书为既有之宽内在之呼（加减乘除、移位、比较、扩、截、拼）；
- 浮点、向量、原子与验界之 i64、f32、f64、v128 载存，书为“数值内在码”（`数值码。豫`），由寄存器降级之数值之钩展之。

初始之内存逾八页者，状态模块唯声八页，包装函数于呼入口之前增至原数；主动之数据段须在前八页之内。

降级前之小函数内联（`内联小函数。豫`）以数值内在码为热呼，故含之之函不内联（码中帧槽与栈深依本函而书）；内联依“预编二起号”分组，窄之包装与宽函不相内联。

## 浮点寄存器之制

浮点与向量之值居浮点寄存器：操作数栈深为 d 者居第 d 浮点寄存器（ARM64 为 v0 至 v23，x86-64 为 xmm0 至 xmm11），于虚栈占一槽，而整数寄存器之配不动之，盖生之用之者皆数值内在码也。深及寄存器之数（x86-64 十二，ARM64 二十四）者，值改居其帧中家槽（呼前后存浮点值之同排十六字节槽，见下“呼”）：位形之互转、浮点局部之读写、栈深间之搬移与向量之拼拆皆经家槽，复制借暂浮 xmm12，故一呼压十六向量之参（如矩阵乘十六路之累加）亦可降。转译使浮点之值唯经数值内在码而流：

- **浮点局部**唯以数值局部码读写（帧槽由转译分之，降级者不见其访）；v128 之局部占二槽，齐于十六字节；或先读后写之浮点局部，入口清之；“写 L；读 L”合为“暂存 L”。
- **呼**前存参区以下之浮点值于“家”（参槽之后，每栈深一十六字节之槽），呼后取回；浮点之参与果于呼界按位入整数寄存器（v128 占二），被呼者入口复其浮点之参于浮点局部。
- **跳**所携之浮点之果，以搬移码移至目标块之果位；条件之跳须移者，书为“若（条件）则 移；跳”。
- **返**前以浮点之果按位入整数寄存器。

## 数值内在码

内在码者，呼号减 `内在基`。数值所用在四十万至六十四万之间（余号见 `宽降级原语。豫`）：

| 段 | 码 | 义 |
|---|---|---|
| 定码 | 四十万加 k（k 小于二千） | 标量浮点零至九十九，访存一百至一百一十二，浮点之选与向量之拼拆一百二十至一百二十二，原子二百至二百一十七，向量三百加子码 |
| 车道码 | 四十万二千加 操作乘十六加车道 | 取车道、替车道 |
| 局部码 | 四十一万加 种乘二万加槽号 | 浮点局部之读、写、暂存、清零、按位读 |
| 深度码 | 六十二万加 种乘一千加栈深 | 存家、取家、栈深之浮点值与整数寄存器按位互转 |
| 搬移码 | 六十三万加 源深乘一百加目深 | 浮点值于栈深间之移 |

钩在 `寄存器降级。豫` 之 `发内在` 之首：码落此诸段者，付 `数值内在。豫` 分派之。

## 二构

- **ARM64**（`臂数汇编`、`浮降级`、`向量降级`、`一气降级`）唯用 ARMv8.0 之令，QEMU 之 cortex-a53 亦能行之：标量浮点用 FP 之令，向量用 NEON，宽松之点积以 smull、saddlp、addp 合成，原子用 ldar／stlr 与 ldaxr／stlxr 之环。有陷之截断先较其界，逾界或非数则跳于陷。
- **x86-64**（`兼数汇编`、`兼浮降级`、`兼向量降级`、`兼一气降级`）主用 SSE2，兼用 SSSE3（pshufb、pabsd、pmaddubsw）与 SSE4.1（roundss／roundps、pmulld、pminsd、pmaxsd、pmovsx／zx、pextr／pinsr、insertps）。最小最大依 Wasm 之义，标量以比较与分支，向量以二序之算合之；饱和之截断依 V8 之法；原子用 lock xadd、xchg、lock cmpxchg 与 mfence。
- 诸访存皆先验其界（址加宽不逾线性内存之字节数），原子又验其自然之齐。
- 候与唤依单线而为：值不等返一，等则作逾时返二；唤恒返零。

## 六十四位址之内存

用 `声明存六四` 之模块（memory64），其址为 i64，线性内存可增逾四吉。数值转译为之加导出“长址内存”，寄存器降级于 `鹄降级用户篇` 之始据之置 `降级公用` 之 `长址引` 为阳，降毕复之；入口、函数与助手据之生六十四位之字节数运算。常内存之模块，所生之码与旧逐字节同。

- **字节数寄存器**：ARM64 之 x15 与 x86-64 之 r8，为页数左移十六位，以六十四位计之（`lsl x15, …, #16`、`shl r8, 16`）；`memory.size` 以六十四位右移取页数。
- **访存**：x86-64 之窄访（i32 与一二字节）移址寄存器之全六十四位入 r11（`mov r11, 址`），以六十四位验界；ARM64 之访本用六十四位之索引寄存器。i64、f32、f64、v128 与原子之数值访存用六十四位之有效址。
- **增长、复制、填充、数据段之初置**：助手之增量、址、长、页数与字节数皆取六十四位（x86-64 之 `mov r11, rdi`、`test rdx, rdx`、`mov rcx, rdx` 等；ARM64 之复制与填充用 x0 至 x2 之全六十四位，增长以六十四位移页数与字节数）。`memory.grow` 之增量为 i64，败则助手返三十二位之负一，转译依符号扩为 i64 之负一。
- **入口之映**：Linux 与 macOS ARM64 之入口依页数上限映动态之区，长或始逾三十二位者以六十四位之立即装之（x86-64 `mov r64, imm64`，ARM64 movz 加 movk）。Linux x86-64 之六十四位址内存置动态区于一 TiB，大代码段（0x110000000）居其下；ARM64 之动态区仍始于 0x60000000。macOS x86-64 之动态区为数据段之零填，长为页数上限乘六十四 KiB。macOS ARM64 之六十四位址内存随需而映：入口以十六 TiB 为所示之址先映六十四吉，增长之助手于所需之块逾已映者续映于其后（扩至所需加六十四吉，不倍之：拆映之时随映之大而陡增），所得非紧接之址则增长败；一次映满其上限者，林檎每进程退出拆映多费系统时约零点二四秒，随需而映则唯偿所用。
- **页数上限**（`降级鹄` 之 `鹄长址页容量限`，目标内建导入“页容量”亦返之）：macOS 与 Linux 十一亿四千零八十五万六百八十八页（六十八 TiB，执行器之位图卡表居四吉之上约二点四 TiB，堆犹可逾六十四 TiB），裸机 AMD64 与 ARM64 二十一亿三千零七十万六千四百三十二页（一百二十七 TiB，动态区始于一 TiB，按需而提交），Windows 与 macOS x86-64 十三万一千零七十二页（八吉）。模块所声最多之页可逾六万五千五百三十六，未声则取此上限。
- **验收**：`原生样例/长址`（包「原生长址」）增线性内存自一页至八万二千页（约五吉），于四吉上下读写四字节整数、长整数、小数与一二字节，读写末四字节，填四吉之上之一段，复跨四吉之一段于四吉之上，原子书、加、读，核逾最多页之增返负一。二〇二六年十月七日于 macOS ARM64 与 Docker 中之 Linux arm64、amd64 行之皆过；macOS x86-64 之产物以反汇编核其入口与助手。

## 宽浮之内在（预编二）

预编二之宽函，值皆整数寄存器中六十四位之位形，浮点亦按位居于整数（f32 居低三十二位，高位为零）。豫行之文（启盘之开机程序、豫行工具与系统中之常程）、装载之单元（`豫构 运行`、`豫构 交互`、引用式清单豫行与行在之程）与诸原生之目标（林檎、林纳、轩窗，二构）之程皆由此途：预编二书客之浮点运算、比较、取整、开方、转换与饱和之截为“宽浮之内在”，其码为宽浮基（六十五万）加 k，k 与上表定码之标量浮点同义（饱和之截用定码九十至九十七，当客 0xFC 前子码零至七）；寄存器降级依目标之构展之。

- **x86-64**（`兼宽浮降级`）：移操作数自栈深之整数寄存器入暂之 xmm12、xmm13，依定码之 SSE2 之令算之，复移其果回整数寄存器；惟用暂寄，故宽函中任何栈深皆可用。取整惟用 SSE2：|x| 小于 2^52（f32 为 2^23）者经 cvttsd2si 与 cvtsi2sd 往返得截值，向下向上依比较减一或加一，就近取偶以 (|x| + 2^52) − 2^52，终复原值之号；非数与更大者原样还之。最小最大与非数依 Wasm 之义以比较与分支为之。饱和之截以比较夹于目标整数之最小最大，非数得零；有陷之截先较其界，越界或非数则投陷。
- **ARM64**（`臂宽浮降级`）：操作数经 fmov 自整数寄存器入暂之 v28、v29，以 FP 与 NEON 之令算之（取整用 frintn、frintm、frintp、frintz，开方用 fsqrt，饱和之截用 fcvtzs、fcvtzu：越界而饱和、非数而零，合 Wasm 之义），果复移回整数寄存器（f32 书 w 寄存器，高位清零）。最小最大与非数依 Wasm 之范以比较与分支；有陷之截先较其界，越界或非数则投陷。

二构皆惟用其基线之令（x86-64 之 SSE2、ARMv8.0 之 FP 与 NEON），故唯有 SSE2 之旧兼机与 QEMU 缺省之 qemu64 亦能行宽浮之内在。

核之以 `豫言操作系统/裸机/普通探针/硬浮探针。脚本。豫`：于一组边界之值行诸二元、一元、比较与转换，逐行印其果之位形，期望取自诺驿。`豫言系统 启动盘 --壳 豫言操作系统/裸机/普通探针/硬浮探针。脚本。豫` 造盘行之以核裸机之硬浮；`原生一致性 --只验 硬浮探针` 以同探针编为诸原生目标之可行之文而行之。二〇二六年十月九日裸机二构之出皆与期望逐字同（千八百一十行）；十月二十一日 Linux 兼容六十四与 macOS 臂六十四之原程、及 Linux 兼容六十四之装载单元（`豫构 运行`）之出亦逐字同，Linux 臂六十四与轩窗交 CI。

## 核之浮点之境

`浮点上下文。豫`：启时，ARM64 置 CPACR_EL1.FPEN，x86-64 置 CR4 之 OSFXSR 与 OSXMMEXCPT，并以 fxsave 书各任务槽之存区以缺省之态（MXCSR 为 0x1F80）。诸处理皆经“返回用户”而归用户态，于此较当前之任务槽与浮点寄存器之主，异则先存寄存器于主之区，复取当前任务之区。存区：ARM64 在 0x400B4000（每槽一千零二十四字节，q0 至 q31 加 FPCR、FPSR），x86-64 在 0x124000（每槽五百一十二字节，fxsave64 之式）。

## 所限与待办

- 浮点值之操作数栈深逾浮点寄存器之数（ARM64 二十四、x86-64 十二）者，位形互转、浮点局部读写、栈深搬移与向量拼拆经家槽；计算之类（标量之算与较、向量之算）其操作数或果落此深者报不支，待办：此亦改经家槽与暂浮算之。
- 浮点局部常居帧槽，每访一载存；待办：为浮点局部配寄存器。
- 含数值内在码之函不与小函数之内联；待办：内联时移码中之帧槽与栈深。
- 不支者：多值之块与块参、br_table、间接之呼、全局、表、i32／i64 之 clz／ctz／popcnt 与符号扩展之令、memory.init／data.drop、载入以外之非零静偏、带浮点参果之导入（绑为陷之桩）。
- 唯有 SSE2 之 x86-64 处理器（及 QEMU 缺省之 qemu64）不能行向量降级所用之 SSSE3、SSE4.1 之令；于 QEMU 行之须加 `-cpu max`。标量浮点与宽浮之内在惟用 SSE2，不在此限。待办：为此诸向量之令别书 SSE2 之代。
- 候与唤唯单线之为；待办：多线之时真候真唤。
- 六十四位址之内存：址加静偏或加宽逾 2^64 者回绕，其验留待后版；逾 2^32 之静偏，x86-64 取其低三十二位，ARM64 报不支；导入之线性址参为三十二位整数，四吉以上之缓冲留待导入改用长整数之址；轩窗与 macOS x86-64 之更大上限留待后版；macOS x86-64 六十四 TiB 之零填留待于 Rosetta 实测。
