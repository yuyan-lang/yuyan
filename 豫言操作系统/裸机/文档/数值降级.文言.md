# 数值之降：浮点、长整、向量与原子

裸机后端以底层之程序所成之 Wasm 降为 ARM64 与 x86-64 之机器码。此篇述其处 i64、f32、f64、v128 与原子之令之法，使底层豫言所书之张量内核得编入原生之二进制（路二：macOS、Linux、Windows），并行于豫言系统（裸机）。

## 二途

底层之程用 i64、f32、f64、v128、原子、共享内存或六十四位址之内存者，编译器行“新路”，以通编码器书标准之 Wasm（见 `应用/豫言编译器/文档/底层模式.文言.md`）；唯用 i32 者仍行状态模块之旧路。裸机后端亦有二入：

- `数值转译。豫` 之 `需数值转译` 察模块有无旧路所不识者（值型、内存之标、令）；
- 有则以 `数值读取。豫` 读其标准模块，由 `数值转译模块` 转为寄存器降级所受之状态模块；无则仍以 `读取状态二进制` 读之。

`原生生成。豫`（yy原生生成）与 `入口。豫`（yy豫言裸机）皆依此择途。唯用 i32 之程，所生与改前逐字节同。

## 转译

转出之模块：导入如旧；次于导入者，窄之包装函数“启动”，呼原模块所导出之“启动”或“_start”；其后为转出之宽函数，导出“预编二起号”指其首。原模之函数导出皆存（定义函数之号随包装后移一位，原“启动”以包装代之）；六十四位址内存之模另加导出“长址内存”为记（指包装函数）。宽函数之值皆占六十四位（见 `宽降级原语。豫`），故：

- i32 之令如旧，其果零扩；
- i64 之令书为既有之宽内在之呼（加减乘除、移位、比较、扩、截、拼）；
- 浮点、向量、原子与验界之 i64、f32、f64、v128 载存，书为“数值内在码”（`数值码。豫`），由寄存器降级之数值之钩展之。

初始之内存逾八页者，状态模块唯声八页，包装函数于呼入口之前增至原数；主动之数据段须在前八页之内。

降级前之小函数内联（`内联小函数。豫`）以数值内在码为热呼，故含之之函不内联（码中帧槽与栈深依本函而书）；内联依“预编二起号”分组，窄之包装与宽函不相内联。

## 浮点寄存器之制

浮点与向量之值居浮点寄存器：操作数栈深为 d 者居第 d 浮点寄存器（ARM64 为 v0 至 v23，x86-64 为 xmm0 至 xmm11），于虚栈占一槽，而整数寄存器之配不动之，盖生之用之者皆数值内在码也。转译使浮点之值唯经数值内在码而流：

- **浮点局部**唯以数值局部码读写（帧槽由转译分之，降级者不见其访）；v128 之局部占二槽，齐于十六字节；或先读后写之浮点局部，入口清之；“写 L；读 L”合为“暂存 L”。
- **呼**前存参区以下之浮点值于“家”（参槽之后，每栈深一十六字节之槽），呼后取回；浮点之参与果于呼界按位入整数寄存器（v128 占二），被呼者入口复其浮点之参于浮点局部。
- **跳**所携之浮点之果，以搬移码移至目标块之果位；条件之跳须移者，书为“若（条件）则 移；跳”。
- **返**前以浮点之果按位入整数寄存器。

## 数值内在码

内在码者，呼号减 `内在基`。数值所用在四十万至六十四万之间（余号见 `宽降级原语。豫`）：

| 段 | 码 | 义 |
|---|---|---|
| 定码 | 四十万加 k（k 小于二千） | 标量浮点零至九十九，访存一百至一百一十二，浮点之选与向量之拼拆一百二十至一百二十二，原子二百至二百一十七，向量三百加子码 |
| 车道码 | 四十万二千加 操作乘十六加车道 | 取车道、替车道 |
| 局部码 | 四十一万加 种乘二万加槽号 | 浮点局部之读、写、暂存、清零、按位读 |
| 深度码 | 六十二万加 种乘一千加栈深 | 存家、取家、栈深之浮点值与整数寄存器按位互转 |
| 搬移码 | 六十三万加 源深乘一百加目深 | 浮点值于栈深间之移 |

钩在 `寄存器降级。豫` 之 `发内在` 之首：码落此诸段者，付 `数值内在。豫` 分派之。

## 二构

- **ARM64**（`臂数值汇编`、`浮点降级`、`向量降级`、`原子降级`）唯用 ARMv8.0 之令，QEMU 之 cortex-a53 亦能行之：标量浮点用 FP 之令，向量用 NEON，宽松之点积以 smull、saddlp、addp 合成，原子用 ldar／stlr 与 ldaxr／stlxr 之环。有陷之截断先较其界，逾界或非数则跳于陷。
- **x86-64**（`兼数值汇编`、`兼浮点降级`、`兼向量降级`、`兼原子降级`）主用 SSE2，兼用 SSSE3（pshufb、pabsd、pmaddubsw）与 SSE4.1（roundss／roundps、pmulld、pminsd、pmaxsd、pmovsx／zx、pextr／pinsr、insertps）。最小最大依 Wasm 之义，标量以比较与分支，向量以二序之算合之；饱和之截断依 V8 之法；原子用 lock xadd、xchg、lock cmpxchg 与 mfence。
- 诸访存皆先验其界（址加宽不逾线性内存之字节数），原子又验其自然之齐。
- 候与唤依单线而为：值不等返一，等则作逾时返二；唤恒返零。

## 六十四位址之内存

用 `声明内存六四` 之模块（memory64），其址为 i64，线性内存可增逾四吉。数值转译为之加导出“长址内存”，寄存器降级于 `目标降级用户模块` 之始据之置 `降级公用` 之 `长址引` 为阳，降毕复之；入口、函数与助手据之生六十四位之字节数运算。常内存之模块，所生之码与旧逐字节同。

- **字节数寄存器**：ARM64 之 x15 与 x86-64 之 r8，为页数左移十六位，以六十四位计之（`lsl x15, …, #16`、`shl r8, 16`）；`memory.size` 以六十四位右移取页数。
- **访存**：x86-64 之窄访（i32 与一二字节）移址寄存器之全六十四位入 r11（`mov r11, 址`），以六十四位验界；ARM64 之访本用六十四位之索引寄存器。i64、f32、f64、v128 与原子之数值访存用六十四位之有效址。
- **增长、复制、填充、数据段之初置**：助手之增量、址、长、页数与字节数皆取六十四位（x86-64 之 `mov r11, rdi`、`test rdx, rdx`、`mov rcx, rdx` 等；ARM64 之复制与填充用 x0 至 x2 之全六十四位，增长以六十四位移页数与字节数）。`memory.grow` 之增量为 i64，败则助手返三十二位之负一，转译依符号扩为 i64 之负一。
- **入口之映**：Linux 与 macOS ARM64 之入口依页数上限映动态之区，长或始逾三十二位者以六十四位之立即装之（x86-64 `mov r64, imm64`，ARM64 movz 加 movk）。Linux x86-64 之六十四位址内存置动态区于一 TiB，大代码段（0x110000000）居其下；ARM64 之动态区仍始于 0x60000000。macOS x86-64 之动态区为数据段之零填，长为页数上限乘六十四 KiB。macOS ARM64 之六十四位址内存随需而映：入口以十六 TiB 为所示之址先映六十四吉，增长之助手于所需之块逾已映者续映于其后（扩至所需加六十四吉，不倍之：拆映之时随映之大而陡增），所得非紧接之址则增长败；一次映满其上限者，苹果每进程退出拆映多费系统时约零点二四秒，随需而映则唯偿所用。
- **页数上限**（`降级目标` 之 `目标长址页容量上限`，目标内建导入“页容量”亦返之）：macOS 与 Linux 十一亿四千零八十五万六百八十八页（六十八 TiB，执行器之位图卡表居四吉之上约二点四 TiB，堆犹可逾六十四 TiB），裸机 AMD64 二十一亿三千零七十万六千四百三十二页（一百二十七 TiB，动态区始于一 TiB），裸机 ARM64 一千零二十四页，Windows 一万六千三百八十四页。模块所声最多之页可逾六万五千五百三十六，未声则取此上限。
- **验收**：`原生样例/长址`（包「原生长址」）增线性内存自一页至八万二千页（约五吉），于四吉上下读写四字节整数、长整数、小数与一二字节，读写末四字节，填四吉之上之一段，复跨四吉之一段于四吉之上，原子书、加、读，核逾最多页之增返负一。二〇二六年十月七日于 macOS ARM64 与 Docker 中之 Linux arm64、amd64 行之皆过；macOS x86-64 之产物以反汇编核其入口与助手。

## 核之浮点之境

`浮点上下文。豫`：启时，ARM64 置 CPACR_EL1.FPEN，x86-64 置 CR4 之 OSFXSR 与 OSXMMEXCPT，并以 fxsave 书各任务槽之存区以缺省之态（MXCSR 为 0x1F80）。诸处理皆经“返回用户”而归用户态，于此较当前之任务槽与浮点寄存器之主，异则先存寄存器于主之区，复取当前任务之区。存区：ARM64 在 0x400B4000（每槽一千零二十四字节，q0 至 q31 加 FPCR、FPSR），x86-64 在 0x124000（每槽五百一十二字节，fxsave64 之式）。

## 所限与待办

- 浮点值之操作数栈深逾浮点寄存器之数（ARM64 二十四、x86-64 十二）者报不支；待办：溢于帧。
- 浮点局部常居帧槽，每访一载存；待办：为浮点局部配寄存器。
- 含数值内在码之函不与小函数之内联；待办：内联时移码中之帧槽与栈深。
- 不支者：多值之块与块参、br_table、间接之呼、全局、表、i32／i64 之 clz／ctz／popcnt 与符号扩展之令、memory.init／data.drop、载入以外之非零静偏、带浮点参果之导入（绑为陷之桩）。
- 唯有 SSE2 之 x86-64 处理器（及 QEMU 缺省之 qemu64）不能行 SSSE3、SSE4.1 之令；于 QEMU 行之须加 `-cpu max`。待办：为此诸令别书 SSE2 之代。
- 候与唤唯单线之为；待办：多线之时真候真唤。
- 六十四位址之内存：址加静偏或加宽逾 2^64 者回绕，其验留待后版；逾 2^32 之静偏，x86-64 取其低三十二位，ARM64 报不支；导入之线性址参为三十二位整数，四吉以上之缓冲留待导入改用长整数之址；视窗与裸机 ARM64 之更大上限留待后版；macOS x86-64 六十四 TiB 之零填留待于 Rosetta 实测。
