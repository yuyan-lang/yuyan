# 控台之入环与 Ctrl-C

## 今之中文交互

最终中文镜像已具 Noto UTF-8 帧缓绘字、Tab 全拼及首字母补令、F2 简拼音输入；能撤音、择字、翻页、退格。下文早期 ASCII 及输入法未备之记为往事。今之范围与实果见《中文支持》及《中文启动验收》。E40 旧内置键盘已验，新中文待真机。

二〇二六年十月三日 E40 内置键盘实机之报：第四版镜之图 IMG_8126 见 `UART LSR=FF`、`CONFIG2=64`、`ACK=FA`；次图 IMG_8127 见多组按释 RAW 键码与字之回显，用户报输出始见。此证 E40 由 USB 启而入壳，内置 PS/2 入路已通；图中所入尚非有效暂令，执行之果待验。RAW 暂记杂入回显，验成后除之。

二〇二六年十月三日无串口修复复验：类型检查与链接皆成。新 ISO 于 QEMU Penryn + Q35 + xHCI USB、`-serial none`，分经 SeaBIOS、OVMF UEFI，两路皆见 `UART LSR=FF`、`ACK=FA`，以 PS/2 入 `tmp-echo ok` 得 `ok`；屏录按释之 RAW。有 COM1 之 SeaBIOS 复验见 `UART LSR=60`，入 `a`、回车，得 RAW 与“未知命令：a”。新 ISO SHA-256：`a9a5d6457540ee568acb3c16120addccc98835a70f5f9924e9553682a2b226da`。旧镜无 COM1 之失已复现，E40 新镜实机之果待验。

二〇二六年十月三日无 COM1 复现：E40 次图见 `CONFIG2=64`、`ACK=FA`，内置键入犹无 RAW。读行代码实恒呼输入服务；其务先巡串口，后读 PS/2。以旧 ISO 于 QEMU Penryn + Q35 + SeaBIOS 置 `-serial none`，屏亦止于欢迎辞与提示，注 `a`、回车而无 RAW；监视器读 `0x3FD` 得 `FF`。旧码认 FF 之 Data Ready 位为有字，纳无端口之 FF，环满即返，PS/2 不得巡。今遇状态 FF 则直巡键盘，初置另录 `UART LSR`；E40 是否同因，待新记验之。

二〇二六年十月三日配置回读镜复验：类型检查与链接皆成。QEMU Penryn + Q35 + xHCI USB 盘，分经 SeaBIOS、OVMF UEFI，皆入壳，各回读 `CONFIG2=60`、`64`，皆得 `ACK=FA`；按 `a`、回车，得四个按释原码及“未知命令：a”。新 ISO SHA-256：`696595443f38a768529319b94ca1733d7c446a3df6f47ea074f78f9cd4a037f5`。今唯 QEMU 之验，E40 实机尚待测。

二〇二六年十月三日诊断镜复验：系统类型检查与链接皆成；QEMU Penryn + Q35 + xHCI USB 分经 SeaBIOS、OVMF UEFI，皆入壳，屏见诊断。两路入 `a`、回车，皆记原码 `1E`、`9E`、`1C`、`9C`，并报“未知命令：a”。诊断 ISO SHA-256：`14190818f42513fd764966767730864ab5bd4933f6c48c1200f07455b967f80a`。E40 用户报旧镜欢迎辞可见而键入不应，诊断镜实机之果待取。

E40 暂验：初置与原键码，并出于 COM1 及可用帧缓。`PS2 STATUS=XX` 为初读状态口之十六进制值；`CONFIG=XX` 为原命令字；`STAGE=01` 将送读命令字之令，`02` 将送写命令字之令，`03` 将写新命令字，`04` 将明启首口，`05` 将送扫描启令。新配置关两口 IRQ 与辅口，留 Set 2 转 Set 1 之译；`CONFIG2` 为启首口后之回读，`ACK` 为扫描启令后所收之字，`TIMEOUT STATUS` 为候之失时所读状态。新增读写之候，各至多巡六百五十五万三千六百次，乃次数之界，非校准之时。其后凡自数据口收字，皆出 `PS2 RAW=XX`，含应答及按、释之键码。此为暂验，既明则删。

E40 首图之记：`STATUS=14`、`CONFIG=47`，旧诊断至 `STAGE=04`，内置键盘不应，未见 RAW 与应答。今改明启首口、回验配置与应答，实机之果待复验。读写之候与配置之治，参 [Linux i8042 驱动](https://github.com/torvalds/linux/blob/master/drivers/input/serio/i8042.c)。

前此内核于控台之入一无所纳：务四每呼直读一串口字节，无人读则留于串口。故不读入之死循环，无以止之——所按之 Ctrl-C 不过串口中一字节，无任何码往观。今内核自收串口之字节，而以 Ctrl-C 化为可询之“中断之标”；AMD64 初收入时有界初置 i8042，启键盘口与 Set 2 转 Set 1 之译，复将 PS/2 键码转 ASCII，纳于同一输入环。

## 制

- **入环**：内核于**每逢时钟中断**、及**务四读入之前**，尽取串口接收 FIFO 中当有之字节；AMD64 又轮询 i8042/PS/2 键盘，以 Set 1 美式未移位键位化为字节。两路皆入二百五十六字节之环。
- **Ctrl-C**：取得字节三（0x03）者，不纳于环，唯立“中断之标”为一。用户程序不见此字节，一如终端之行规程吞 `^C`。
- **务四（读一字节）**：先 `控台冲刷当前`（旧制：先刷待出之整行），复收入，而后自环取一字节；环空则返负一（与旧时“串口无字节”同）。故**先敲入之令仍依序留于后读者**——脚本一举贴入串口，子进程不读入，此诸令依旧原样留于壳。
- **务二十七（`平台.中断查询`，无参、一果）**：返中断之标（零或一）而清之。

|---|---|---|
| 环头（首四字节、尾四字节、中断之标四字节，环体自偏十六起，共二百七十二字节） | `0x400B0400` | `0x103800` |
| AMD64 引导之记 | — | Multiboot 信息指针藏于 `0x10380C`；帧缓元数据记于 `0x103910`，长二十八字节，承输入环之后 |

| PS/2 键盘 | — | 初收入时读改写 i8042 命令字，启键盘口及 Set 2 转 Set 1 之译，并送扫描启令；后轮询状态口 `0x64`、数据口 `0x60`；Set 1 美式键位，暂不治 Shift、Caps Lock 与扩展码 |
| 收入之子程序 | `控台收入`（`bl`、`call`，唯用 x0 至 x8、eax、ecx、edx，中断之上下文已全存） | 同 |

所增机器码皆带标号之小片（`豫言操作系统/裸机/库/裸机后端/控台输入。豫`，务号入 `整数降级。豫` 之映射：`中断查询` 为二十七），分支一律循标号重定位，无手算之偏。

AMD64 启入口先藏 Multiboot 信息指针于 `0x10380C`。引导器若供帧缓字段，核心乃抄其址、行距、宽、高、色深、类型及六个 RGB 掩码字节于 `0x103910` 起二十八字节之记；输入环居 `0x103800` 起二百七十二字节。shell 并出于 COM1，亦绘 ASCII 于 RGB 帧缓；非 ASCII UTF-8 字节略之。启时中文状态书于串口，图形屏幕显其后之英文提示；欲全显中文，尚需字形数据。键盘可纳小写字母、数、常用标点、空格、回车及退格字节。中文输入、Shift/Caps Lock 与 USB HID 键盘尚未接入。

## 用户态之用

内核唯记 Ctrl-C，如何应之属用户态（见[客体二号](客体二号.文言.md)“控制台中断”一节）：

- **子任务中之程序**：执行器于每入 Wasm 函数体与每回跳循环之首计一数，每四千次问内核一回；问得其标则以退出码一百三十（128 + SIGINT，与 POSIX 同）终本任务，壳如常印 `退出码：130`。故死循环、深递归、忙等皆可打断；候入之程序亦于其候之循环中查之。
- **壳（首任务）**：读一行时先照常读尽环中之字符（并回显），读不到字节而见 Ctrl-C 之标，方印 `^C`、弃此行、返提示符；起子进程之前先清遗留之标；运行程序之际壳自身不占 CPU，标留于子任务。

## 验

- 裸机验增 `控制台中断`：测试程序先印“输入就绪”，harness 继而于串口写入 `a`、0x03、`b` 三字节；程序（每步限时三秒）依次读得 `a`、待 `中断查询` 返一、再读得 `b`（0x03 不现于字节流）、再查得零；两架构皆过。AMD64 之 16550 于无 FIFO 之式一时唯收一字节，后二字节待前者被读走、内核于时钟中断中续收方至，故此式兼验“时钟中断中收入”与“务四读环”二途。
- QEMU 手工键盘复验：SeaBIOS + i440fx/UHCI 与 OVMF + Q35/xHCI 皆入壳；向 PS/2 模型注入 `help`、回车，壳得整行 ASCII 而报“未知命令：help”。此为 QEMU 仿 PS/2 之验，未验 E40 或实体键盘。
- 旧有之控台入（`控制台输入`、`控制台错误`、`控制台行原子`）与凡赖先入之壳测试（脚本一举写入串口）皆如常过，明环无失字节、无乱序。
- 壳测试 `中断`（见[客体二号](客体二号.文言.md)）于两架构逐字验之：豫言所书 `死循环`（尾递归空转）被 Ctrl-C 打断而得退出码一百三十，于提示符下敲半行再按 Ctrl-C 得 `^C`，其后壳仍可用。

## 界

- 环满（二百五十六字节之先入未被读走）时，后至之 Ctrl-C 待环中腾位方得收；串口字节不失，唯 Ctrl-C 之识延后。
- 诸任务共一环一标，先读者得之；今一时唯一子进程，故标恒归之。
- 程序不能“捕”Ctrl-C，亦无信号与前后台作业之概念；Ctrl-C 唯于子进程生效（首任务之壳自按行理之）。
- 中断唯于解释器之检查点得察：陷于**宿主原语**中甚久之呼（如极大之文件读写）须待其返方应。
- **终端之 Ctrl-C**：QEMU 之 `-serial stdio` 默使终端之 Ctrl-C 生 SIGINT、径止 QEMU（实测 “terminating on signal 2”），字节三不达系统。`yy豫言系统` 今以 `-chardev stdio,mux=on,signal=off` 接串口（监视器仍为 `-monitor none`），Ctrl-C 遂为字节三入系统，其行如上；代价是终端不复能以 Ctrl-C 杀 QEMU，系统卡死则按 **Ctrl-A 继按 X** 强止（用 QEMU 之 mux 快捷键，实测退出码零）。自动之试仍以具名管送入 0x03。
- PS/2 键盘暂循 Set 1 美式未移位 ASCII；键盘 Ctrl-C、Shift、Caps Lock、扩展键与 USB 键盘皆未支持。今壳令多为中文，直键盘尚不可入中文，须后续增输入法；可暂用 `tmp-help`、`tmp-echo 文`、`tmp-exit` 验 ASCII 键盘，三令后可别删。帧缓唯绘 ASCII，中文启文之全辞从串口观之。
# 中文交互之键

字表已有 Tab（键码 `0x0F` → 字节 `0x09`）；新纳 Esc（键码 `0x01` → 字节 `0x1B`），以供取消候选。键入环者，未必壳已行其交互；补全与输入法犹待接。
