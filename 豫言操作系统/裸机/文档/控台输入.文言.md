# 控台之入环与 Ctrl-C

## 桌面之 Ctrl+C（二〇二六年十月十二日）

桌面（按键之事模）之 Ctrl+C 惟为按键之事交据屏之程，内核不置中断之标。平铺桌面焦点之终端方行程时，Ctrl+C 循单向之数据流而办：终端取行中子程序之任务号（子程序接口之「使者役号」），于窗示 `^C` 与 `壳> 「打断任务」于「号」曰「N」`，乃以此句付系统之壳行之，同于壳中入此命。壳命令「打断任务」呼子程序接口之「打断任务」，执行器经核务六十四断此任务及其诸子孙。脚本方行则 Ctrl+C 别清脚本之余行。入框可用（无程行）则 Ctrl+C 由文本框复制所选。

核务六十四「打断任务」（任务之柄）于内核终任务，故预编为机器码、无中断检查之点之豫行工具（如 `/工具/豫构。豫行`、编译器）亦可断。目与其诸子孙（调度环中主之链通于目之动任务，至多十六层）各：已毕者弗问；方行于某核者，于槽区 +0x54 记“待断”，俟其次呼核务（入口之「导出：动态服务」）或其核次轮之时（「导出：调度」）先断其今之子孙，乃以退码百三十终之；余者即终之（冲刷、还资、状置“见止、已毕”、退码百三十），而唤其主。主如常收退码，桌面终端旋示 `退出码：130`。旧槽（槽零、一）与无效之柄返负一；凡任务皆可断他动任务。`「列出役」` 印任务号、名与所用。

## 按键之事模与共用之解（二〇二六年十月十一日）

键盘之解书于两构共用之豫言内核（`内核/按键。底层。豫`），手书之核惟呼之。兼之『控台收入』收串口毕，经跳表呼「键盘收入」：以内核原语「端口读字节」读 i8042 之状态口 `0x64` 与数据口 `0x60`（状态为 0xFF 则无 PS/2 之控器），辅口之鼠字成四字之包入鼠环（见下文“鼠包与滚轮”），键字依 Set 1 解之（含 E0、E1 之前缀与抬起之码）而易为 HID 之用。USB 引导键盘之报，由二构共用之 USB 设备之层（`内核/通用串行键鼠。底层。豫`，xHCI 经扩展主控，EHCI 经增强主控）径呼之。彼与前报相较，得修饰与诸键之按、抬，乃记新报为前报。旧手书之扫描码表、报之解与『鼠标字节』之跳板皆已删。

键盘有二模：

- **文字之模**（缺省）：新按之非修饰键，依美式键位易为字节入输入之环，PS/2 与 USB 同。字母、数字、符号随 Shift 与大写之锁取上档；回车十三、退格八、制表九、Esc 二十七、F2 为十八，小键盘以数字键计（Num Lock 视为恒开）；Ctrl 加字母出控制之码，Ctrl-C 惟置中断之标；方向与起首、末尾出 `ESC [ A`…`ESC [ D`、`ESC [ H`、`ESC [ F`；删除出四（命令壳删右一字）。
- **事件之模**：服务五十三「按键模式」（参非零）开之，参零则关；执行器取显示面则开，还则关，主之任务终则「清理任务」亦关之。开时键惟入按键区之事环，串口之字仍入输入之环。每按、每抬为一事，服务五十四「读按键」逐一取之：HID 之用加按下乘二百五十六加修饰之位乘六万五千五百三十六（十月十三日起位九至十五别有所用：键盘之用恒零，非零则为消费类控制之键，即 HID 用途页 0x0C 之音量、静音、播放、下一曲等多媒体键，位零至七为消费页用法之低八位，位九至十五为用法高位加一，全用法为消费页用法加二百五十六；此类事文字之模不出，执行器暂弃之，待办事项：接设计播放器之「设音量」），修饰之位依 HID 列（位零至三左 Ctrl、Shift、Alt、Win，位四至七右之四者），环空则负一；Ctrl 加 C 惟为按键之事而交，不置中断之标（十月十二日起，见上文“桌面之 Ctrl+C”）。

## 鼠包与滚轮（二〇二六年十月十一日）

鼠亦由两构共用之豫言内核（`内核/按键。底层。豫`）换包。核入鼠环者皆四字之包，同 PS/2 IntelliMouse 之包：首字（位三恒一，低三位为左、右、中之键，位四、五为横纵之移之号）、横移、纵移（上为正）、滚轮（有号，下滚为正）。环不容全包则全弃之，包恒齐；服务三十六仍逐字取之。

- **PS/2 之鼠**（兼）：「键盘收入」初呼时（手书之键盘初置已开辅口之钟）为「鼠标初置」：关数据之报（0xF5），依次设采样之率二百、百、八十，乃读器号（0xF2），得三则为滚轮之鼠（每包四字），乃复率为百、开数据之报（0xF4）。每命令之字先书 0xD4 于命令口，乃书于数据口，候鼠应 0xFA；候应之时所收键字仍解之。无 PS/2 之控器或鼠不应关报之令，则视为无鼠，惟记每包三字。此后辅口之字由「鼠字节入」成包：包首须有位三，不得有溢位六、七（应 0xFA、自检 0xAA 以此弃之，兼以复齐），包齐乃入环，三字之鼠补滚轮之字为零。
- **USB 引导协议之鼠**：二构共用之扩展主控之驱（`内核/扩展主控。底层。豫`，十月十一日起兼亦用之）依实收之长（请长减余）呼「鼠标报告」：收不下四字则第四字为滚轮，纵移与滚轮皆反之；VMware 虚拟鼠之二式经「鼠包入」出包，滚轮之字为零。无扩展主控者，由增强主控之驱（十月十三日起）经同一设备之层呼「鼠标报告」。
- **执行器**（`客体二号/裸显示。底层。豫`）依四字之包解之，滚轮累为未交之格数，键位与指移既交，乃交滚轮之事（类七，录同林檎后端）：甲乙为指之位，丁为纵滚之量，每格四十八素（像素比一，合显示接口“一行约四十八逻辑之素”），下滚为正。显示控件以滚轮交指下最内可滚之滚动区，原样热区（外程之格）原样转于应用。

## 今之中文交互

二〇二六年十月六日正输入环之满判：写、读二计（`0x103800`、`0x103804`）皆自增不止，存取乃以二百五十六取余。PS/2 之途（`键盘字符完成`）旧读读计而不减，径以写计比二百五十六，写计逾之，则其后 PS/2 之键皆以为环满而弃；串口之途先减，故串口之试不觉，QEMU 进出桌面第九轮复现。今易为 `sub ecx,[0x103804]`（与旧 `mov edx,[0x103804]` 同为七字节）；USB 键盘报告之途本先减之。

今接入之类验与核心机器片回归皆成：普通核心一万零六百九十五字节，隔离核心一万一千一百零二字节，各较接前增九字节，犹少于 GDT 前一万二千六百零八字节之地；Esc、Tab、F2、字母与移位键表之验皆成。此为静态生成与回归之果，端到端 USB 输入犹待实测。

USB 键盘报告之轮询接入：事件周回位合后、析事件类型前，存 RAX 而调用已载于 `0x1F7000` 之报告片，复还 RAX。调用序为九字节，报告片存所用寄存器与标志；旧轮询犹主命令完成事件与 dequeue、周回位、ERDP 之回收。报告片依事件类型、别存之键盘槽号、端点与请求址筛之，沿旧字符环收入，不增应用取键 ABI。此接入之端到端 BIOS/UEFI 键盘输入，犹待硬件方向验收，不以前串口之果冒已过。

最终中文镜像已具 Noto UTF-8 帧缓绘字、Tab 全拼及首字母补令、简拼音输入（十月十日起恒以中文组字，F2 不复易，见《终端编辑》）；能择字、翻页、退格，Esc 留拼音为英文。下文早期 ASCII 及输入法未备之记为往事。今之范围与实果见《中文支持》及《中文启动验收》。E40 旧内置键盘已验，新中文待真机。

二〇二六年十月三日 E40 内置键盘实机之报：第四版镜之图 IMG_8126 见 `UART LSR=FF`、`CONFIG2=64`、`ACK=FA`；次图 IMG_8127 见多组按释 RAW 键码与字之回显，用户报输出始见。此证 E40 由 USB 启而入壳，内置 PS/2 入路已通；图中所入尚非有效暂令，执行之果待验。RAW 暂记杂入回显，验成后除之。

二〇二六年十月三日无 COM1 复现：E40 次图见 `CONFIG2=64`、`ACK=FA`，内置键入犹无 RAW。读行代码实恒呼输入服务；其务先巡串口，后读 PS/2。以旧 ISO 于 QEMU Penryn + Q35 + SeaBIOS 置 `-serial none`，屏亦止于欢迎辞与提示，注 `a`、回车而无 RAW；监视器读 `0x3FD` 得 `FF`。旧码认 FF 之 Data Ready 位为有字，纳无端口之 FF，环满即返，PS/2 不得巡。今遇状态 FF 则直巡键盘，初置另录 `UART LSR`；E40 是否同因，待新记验之。

E40 暂验：初置与原键码，出于 COM1（二〇二六年十月六日始惟书串口，不复绘于帧缓，免公测之屏满布诊语；实机无串口则当复上屏）。`PS2 STATUS=XX` 为初读状态口之十六进制值；`CONFIG=XX` 为原命令字；`STAGE=01` 将送读命令字之令，`02` 将送写命令字之令，`03` 将写新命令字，`04` 将明启首口，`05` 将送扫描启令。新配置关两口 IRQ 与辅口，留 Set 2 转 Set 1 之译；`CONFIG2` 为启首口后之回读，`ACK` 为扫描启令后所收之字，`TIMEOUT STATUS` 为候之失时所读状态。新增读写之候，各至多巡六百五十五万三千六百次，乃次数之界，非校准之时。其后凡自数据口收字，皆出 `PS2 RAW=XX`，含应答及按、释之键码。此为暂验，既明则删。

E40 首图之记：`STATUS=14`、`CONFIG=47`，旧诊断至 `STAGE=04`，内置键盘不应，未见 RAW 与应答。今改明启首口、回验配置与应答，实机之果待复验。读写之候与配置之治，参 [Linux i8042 驱动](https://github.com/torvalds/linux/blob/master/drivers/input/serio/i8042.c)。

前此内核于控台之入一无所纳：务四每呼直读一串口字节，无人读则留于串口。故不读入之死循环，无以止之——所按之 Ctrl-C 不过串口中一字节，无任何码往观。今内核自收串口之字节，而以 Ctrl-C 化为可询之“中断之标”；AMD64 初收入时有界初置 i8042，启键盘口与 Set 2 转 Set 1 之译，复将 PS/2 键码转 ASCII，纳于同一输入环。

## 制

- **入环**：内核于**每逢时钟中断**、及**务四读入之前**，尽取串口接收 FIFO 中当有之字节；AMD64 收串口毕，呼豫言内核之「键盘收入」读 i8042/PS/2 键盘（其解与二模见上节）。串口与文字之模之键字皆入二百五十六字节之环。
- **Ctrl-C**：取得字节三（0x03）者，不纳于环，唯立“中断之标”为一。用户程序不见此字节，一如终端之行规程吞 `^C`。
- **务四（读一字节）**：先 `控台冲刷当前`（旧制：先刷待出之整行），复收入，而后自环取一字节；环空则返负一（与旧时“串口无字节”同）。故**先敲入之令仍依序留于后读者**——脚本一举贴入串口，子进程不读入，此诸令依旧原样留于壳。
- **务二十七（`平台.中断查询`，无参、一果）**：返中断之标（零或一）而清之。

AMD64 启入口先藏 Multiboot 信息指针于 `0x10380C`。引导器若供帧缓字段，核心乃抄其址、行距、宽、高、色深、类型及六个 RGB 掩码字节于 `0x103910` 起二十八字节之记；循规范之偏而抄，即取 Multiboot 信息偏一百零八、一百一十二处各四字节，置于记之 +20、+24。Limine 所给色彩之信较规范晚二字节（始于偏一百一十二），故由 Limine 启者，记之 +22、+23（`0x103926`、`0x103927`）为零，红位居 `0x103928`，蓝位二字节不在记中；核之控台绘字不用此诸掩码，帧服务两式皆识。待办事项：依引导器别其偏、补蓝位。输入环居 `0x103800` 起二百七十二字节，初置之记别存 `0x1039F8`；键之修饰之态与事环在按键之区（见上节）。壳已纳 Noto UTF-8 帧缓显字、补命与简拼音；串口存 UTF-8。

## 用户态之用

内核唯记 Ctrl-C，如何应之属用户态（见[客体二号](客体二号.文言.md)“控制台中断”一节）：

- **子任务中之程序**：执行器于每入 Wasm 函数体与每回跳循环之首计一数，每四千次问内核一回；问得其标则以退出码一百三十（128 + SIGINT，与 POSIX 同）终本任务，壳如常印 `退出码：130`。故死循环、深递归、忙等皆可打断；候入之程序亦于其候之循环中查之。
- **壳（首任务）**：读一行时先照常读尽环中之字符（并回显），读不到字节而见 Ctrl-C 之标，方印 `^C`、弃此行、返提示符；起子进程之前先清遗留之标；运行程序之际壳自身不占 CPU，标留于子任务。
- **逐键编辑（开机壳与开机豫构，二〇二六年十月十一日，提案〇〇〇〇三第八步）**：执行器之「等待终端键」于输入环空时先问内核有无 Ctrl-C（服务二十七），有则作字节三返之；编辑之器见三则印 `^C`、弃此行、归提示。预编为机器码之程无检查之点，开机豫构正行一句纯算之码时 Ctrl-C 不能断之（待办事项）；此句所行之子程仍以百三十退。初始任务候键而办子任务之信则返负一（无键，十月十四日），编辑之器借此隙呼「候键余事」一视壳请（远程登录会话所书入桌面之请遂即办），乃续候键。
- **桌面终端与远程登录（十月十四日）**：其壳会话为子任务，控台之 Ctrl-C 之标不及之；Ctrl+C 经子程序接口之「打断任务」于负号惟断会话所起之程（其核中之子任务与经底层进程所起之程，见《客体二号》），会话停于提示则惟弃方入之行。

## 验

- 裸机验增 `控制台中断`：测试程序先印“输入就绪”，harness 继而于串口写入 `a`、0x03、`b` 三字节；程序（每步限时三秒）依次读得 `a`、待 `中断查询` 返一、再读得 `b`（0x03 不现于字节流）、再查得零；两架构皆过。AMD64 之 16550 于无 FIFO 之式一时唯收一字节，后二字节待前者被读走、内核于时钟中断中续收方至，故此式兼验“时钟中断中收入”与“务四读环”二途。
- QEMU 手工键盘复验：SeaBIOS + i440fx/UHCI 与 OVMF + Q35/xHCI 皆入壳；向 PS/2 模型注入 `help`、回车，壳得整行 ASCII 而报“未知命令：help”。此为 QEMU 仿 PS/2 之验，未验 E40 或实体键盘。
- 二〇二六年十月二日修饰键复验：同一 BIOS/UEFI 混合 USB 镜，于 QEMU Penryn + Q35 + xHCI 下，分别经 SeaBIOS BIOS/MBR 与 OVMF UEFI 入 `壳>`。监视器注入左 Shift+`a`、Caps Lock+`a` 得 `A`；Caps Lock+Shift+`a` 得 `a`；Shift+`1`、`2`、`-` 得 `!`、`@`、`_`；右 Shift+`b` 得 `B`。此乃 QEMU PS/2 模型之验，ThinkPad E40 实机尚俟验。
- 二〇二六年十月二日 USB 键盘之缺口复验：QEMU 11.1.1 Q35 + Penryn + xHCI 挂同一混合镜与 `usb-kbd`（接 `xhci.0`）；SeaBIOS、OVMF 皆入 `壳>`。QEMU `info usb` 示 USB Keyboard 已挂于端口，而此时 `sendkey h/e/l/p/ret` 未成壳之输入。去 `usb-kbd` 后，同 SeaBIOS 配置之 PS/2 注入可读 `help`，并报“未知命令：help”。此唯证 QEMU 设备模型中系统今不能以 USB 键盘输入；QEMU 示设备存在，不等于核已寻得之。xHCI 启动、DMA 环与 HID 寻举尚待成。
- 旧有之控台入（`控制台输入`、`案头误`、`控制台行原子`）与凡赖先入之壳测试（脚本一举写入串口）皆如常过，明环无失字节、无乱序。
- 壳测试 `中断`（见[客体二号](客体二号.文言.md)）于两架构逐字验之：豫言所书 `死循环`（尾递归空转）被 Ctrl-C 打断而得退出码一百三十，于提示符下敲半行再按 Ctrl-C 得 `^C`，其后壳仍可用。
- 二〇二六年十月二日壳之 ASCII 短令复验：增 `help`、`echo 文`、`exit`，`普通-壳-ASCII别名` 于臂、兼容两架皆过。新 BIOS/UEFI 混合 USB 镜于 QEMU qemu64 + Q35 + xHCI 下，经 SeaBIOS 与 OVMF 起机后，monitor 向 PS/2 注入 `help`、`echo ps2 ok`、`exit`，皆正确回显而毕用户任务。此唯验 QEMU PS/2 模型，实体键盘与屏幕输出尚待实测。
- 二〇二六年十月三日 xHCI 命令完成复验：QEMU 11.1.1 Penryn + Q35 + qemu-xhci 挂 USB 存储；同一镜经 SeaBIOS BIOS/MBR 与 OVMF UEFI 皆入 `壳>`。监视器见 Enable Slot 槽号二、槽态二、完码一，事件环出队指针前进一项。此唯验命令环与命令完成事件处理；USB HID 键盘输入尚未成。
- 二〇二六年十月三日 xHCI 根端口复位复验：启时于首个已连根端口置 PORTSC.PP 与 PR，并以掩码保留可写控位；QEMU 11.1.1 Q35 + qemu-xhci + USB 存储下，默认 CPU 与 Penryn 分经 SeaBIOS BIOS/MBR、OVMF UEFI，皆入 `壳>`。四式 PORTSC 皆见 CCS、PED、PRC 置位而 PR 清零，明 QEMU 端口复位已成。此唯验仿器之根端口复位；USB HID、设备寻址、端点设置及 USB 存储传送未成，ThinkPad E40 尚待实测。

## 界

- 环满（二百五十六字节之先入未被读走）时，后至之 Ctrl-C 待环中腾位方得收；串口字节不失，唯 Ctrl-C 之识延后。
- 诸任务共一环一标，先读者得之；今一时唯一子进程，故标恒归之。
- 程序不能“捕”Ctrl-C，亦无信号与前后台作业之概念；Ctrl-C 唯于子进程生效（首任务之壳自按行理之）。
- 中断唯于解释器之检查点得察：陷于**宿主原语**中甚久之呼（如极大之文件读写）须待其返方应。
- **终端之 Ctrl-C**：QEMU 之 `-serial stdio` 默使终端之 Ctrl-C 生 SIGINT、径止 QEMU（实测 “terminating on signal 2”），字节三不达系统。`豫言系统` 今以 `-chardev stdio,mux=on,signal=off` 接串口（监视器仍为 `-monitor none`），Ctrl-C 遂为字节三入系统，其行如上；代价是终端不复能以 Ctrl-C 杀 QEMU，系统卡死则按 **Ctrl-A 继按 X** 强止（用 QEMU 之 mux 快捷键，实测退出码零）。自动之试仍以具名管送入 0x03。
- 键依美式键位而解，PS/2 与 USB 同（见上节）。壳存 `help`、`echo 文`、`exit`，兼存基础中文版暂验之命 `tmp-help`、`tmp-echo 文`、`tmp-exit`。Tab 补命与 F2 拼音见《中文支持》，终端编辑键约见《终端编辑》。无 COM1，FF 之态径转键盘巡入。
