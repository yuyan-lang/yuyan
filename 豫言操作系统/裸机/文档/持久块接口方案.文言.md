# 持久块接口方案

此为真实块设备接既有持久文件系统之最小接口方案。2026-10-04 用户已许四新导入，平台声明、服务分派、静态窗授权及 USB 文件系统接线皆已入源码，方验之。内核内部 USB bulk-only 之描述符、端点、容量、单块读写、同步及传输环周回皆已作，专用 QEMU 盘之写入、同步、关机重启回读皆验；其证见[硬件里程碑](通用串行总线硬件里程碑.文言.md)。应用及文件系统已接，文件持久化全程之验方行，实体机未验；AHCI 之路可循同一块语义而别作。

既有 `客体二号/块设备。豫` 驱 Virtio，设备配置读定于 PCI 0:4.0，寄存器及静态窗亦有旧授权。真实 USB 存储不可径套其寄存协议。故于裸机平台接口加下列四获许之导入，旧 Virtio 导入及其行皆存：

| 名称 | 参数 | 结果 |
| --- | --- | --- |
| 持久块容量 | 单位值 | 可用五百一十二字节扇区数；零为无可用设备 |
| 持久块读取 | 扇区号、静态窗参数 | 取一扇区，零为成，否则错误码 |
| 持久块写入 | 扇区号、静态窗参数 | 写一扇区，零为成，否则错误码 |
| 持久块同步 | 单位值 | 请设备毕其已写之数据，零为成，否则错误码 |

静态窗参数仍用「静偏或（长度左移二十）」之编码，读写之窗须容一扇区。内核自其所留 DMA 缓冲搬运，应用不献设备物理址；仍守静态窗之授权及越界之验，唯授有块设备权限之任务。USB 设备身份及端点由内核驱动掌之，文件系统仍呼旧「块容量」「块读」「块写」「块刷新」，块设备模块择可用之驱。

所作包括识 USB 存储接口、bulk IN/OUT 端点、命令块及状态、容量、读写、同步；继以专用 QEMU 数据盘验建文件、写入、同步、关机重启后再取，并验 USB 键盘同时用之。实体机之验须另取用户明定之数据盘及机器证据。待办事项：非五百一十二字节逻辑扇区、UAS、热插拔、错误之复，皆须别治；未成，毋称真机持久存储已成。

新增 ABI 已获用户明许；其义见[持久块规范](../客体二号/平台接口/规范.文言.md)。正式 AMD64 启盘不自格式化未知之盘，专用验具可启旧自动格式化之标。

## 许后接线之范围

源码所核基线为 `dae59ca77`。旧服务号表止于二十七，拟以二十八至三十一，各应容量、读取、写入、同步；施作前复核最新之表，免并行会话占其号。唯读写为双参服务，容量、同步循旧单位值服务之降级约。

| 文件或范围 | 拟改之事 |
| --- | --- |
| `客体二号/平台接口/平台。接口。豫` | 声明四导入之型 |
| `库/裸机后端/整数降级。豫` | 绑服务号，录双参服务 |
| `库/裸机后端/兼容核心。豫` 及服务之作 | 分派、验调用者授权、静态窗长及边界；窗与 `0x07C0B000` 间移五百一十二字节，复用根端内部之请 |
| `客体二号/块设备。豫` | 留旧块函数，择旧 Virtio 或可用 USB 服务，复用搬入静态、搬出静态 |
| 裸机说明及块接口文档双语之对 | 记服务之义、错误结果及验收范围 |

今设备访问唯授初始用户任务，静态窗定于用户址 `0x300000` 起之已授区域；接线须循实授权之界，拒未授权任务及不足五百一十二字节或越界之窗。USB 服务容量取内部之探，读写 LBA 犹须小于容量。读成乃移入窗，写请先自窗移入，返内部请之结果；同步不访窗。ARM64 及余目标之 USB 后端未作，毋称其目标已支持此器。

文件系统仍呼 `块容量`、`块读`、`块写`、`块刷新`，双区追加日志之式如旧。已许而接线，继验授权及边界之拒，并以别置 USB 数据盘验格式化、建文件、写入、同步、关客体、重启挂载及读回，复验旧 Virtio 之路及 USB 键盘同时用之。验果另录，不以为实体机已成之证。
