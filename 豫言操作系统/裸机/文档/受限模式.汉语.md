# 受限模式与克隆任务

[提案 00012](../../../提案/00012-兼容林纳克斯程序与驱动.汉语.md) 第 1 步的头两个内核机制。它们是通用机制：内核只搬寄存器、报原因，系统调用号的含义由同一任务里的处理代码决定；林兼容层（`豫言操作系统/裸机/林兼容`）是第一个使用者。只有动态任务（槽 32 起）能用。

## 受限模式（服务 48 进入受限）

任务里的一个执行流可以把一组寄存器交给内核，以“受限”身份运行它们。受限的代码执行系统调用指令、调用内核服务或出故障时，内核把寄存器存回受限状态区，执行流就从「进入受限」返回，返回值是原因。执行流在普通模式下办完，改好状态区，再进入受限。

- 参数：受限状态区在调用者线性内存里的偏移。状态区须 64 字节对齐、长 1088 字节，整段落在已迁到动态区（1 TiB 起）的线性内存里，否则返回 −1。
- 返回原因：1 系统调用指令（AMD64 的 `syscall`、ARM64 的 `svc`），2 异常，3 打断，4 内核服务调用（AMD64 的 `int 0x80`）。时钟轮转时任务若正以受限身份运行，内核先替它受限退出（原因 3），任务下次运行就从「进入受限」返回 3；处理代码借此在自己的几个执行流之间轮换（林兼容层的线程）。
- 进入时内核存下调用者的帧与普通浮点状态，取状态区的浮点状态、通用寄存器、程序计数、标志与线程指针；退出时反过来，并把原因写进普通帧的返回寄存器。标志只取用户可改的位：AMD64 取 CF、PF、AF、ZF、SF、TF、DF、OF、AC 再置 IF；ARM64 取 NZCV。
- 受限运行时被定时中断换下，保存的就是受限现场，换回来接着以受限身份运行。

受限状态区布局：

| 偏移 | 内容 |
| --- | --- |
| 0 | 32 个八字节通用寄存器。AMD64 按编码序 rax、rcx、rdx、rbx、rsp、rbp、rsi、rdi、r8…r15，只用前 16 个；ARM64 是 x0…x30 与 sp |
| 256 | 程序计数 |
| 264 | 标志（rflags 或 pstate） |
| 272 | 线程指针（AMD64 的 FS 基址，ARM64 的 TPIDR_EL0） |
| 280 | 原因（四字节） |
| 284 | 向量：AMD64 的异常向量；ARM64 的异常类（ESR 第 26–31 位）或 svc 的立即数 |
| 288 | 错误码：AMD64 的异常错误码；ARM64 的 ESR |
| 296 | 故障址：AMD64 的 CR2；ARM64 的 FAR |
| 512 | 浮点区：AMD64 fxsave 512 字节，ARM64 q0–q31 与 FPCR、FPSR 528 字节 |

AMD64 的 `syscall` 指令：EFER.SCE 保持关闭，`syscall` 引发 #UD；受限运行时 #UD 落在 `0F 05` 上就报原因 1，返回地址先越过这两个字节，与真正的系统调用指令一样。

槽区里受限模式的字段在 +0x3000 起的 4 KiB：+0x3000 普通帧，+0x3200 普通浮点，+0x3600 受限态，+0x3604 打断待决，+0x3608 状态区的用户虚址，+0x3610 线程指针。

## 线程指针

任务切换时，「调度」把换出的动态槽的线程指针存进槽区 +0x3610，「切入」把它装回（新任务为 0）。新增内核原语：读线程指针、写线程指针（AMD64 经 rdmsr、wrmsr 存取 MSR 0xC0000100，ARM64 存取 TPIDR_EL0）、读故障址（CR2、FAR_EL1）、读异常综合症（ARM64 的 ESR_EL1）、同步指令缓存（ARM64 的 ic ialluis）。

## 用户态异常

AMD64 原先只有缺页（14）、系统调用（0x80）与时钟（0x20）进内核，其余向量一律整机停机。现在第 0、1、3–7、10–13、16、17、19–21 号向量改由外置模块的异常桩处理，交豫言内核「异常」：受限运行时受限退出；不受限的动态任务按陷阱结束（退出码 132）；旧槽照旧停机。第 3、4 号门的特权级改为 3，用户的 `int3`、`into` 能进来。ARM64 原本就把其余同步异常当陷阱结束任务；受限运行时的 svc 与各种中止经「动态服务」「动态故障」受限退出。

返回用户态前的现场核对放宽到整个用户地址空间：AMD64 返回地址在 [0x200000, 0x800000000000)、栈在 [0x3D0000, 0x800000000000]；ARM64 两者都在 [0x400000, 2^48)。受限运行的林程序与各线程的栈都在 1 TiB 以上的动态区里。

## 克隆任务（服务 49）

把调用者整个复制成一个新任务：用户区、原生栈、按段建任务的各段大页块与动态区里已提交的块，都给新任务要块拷一份，页表照调用者的映射建。新任务从同一处继续，返回值 0；调用者得新任务的句柄，新任务的主人是调用者。浮点状态与线程指针一并复制。

- 只做按段建任务起的动态任务（两种架构；ARM64 照用户二级表第 128–511 项抄大页段，建完同步指令缓存）。
- 待办事项：页在写时才复制（现在立即整块拷贝）；只读段共享。

## 共享区段（服务 51）

`共享区段(序, 块数)` 把调用者动态区第 序 块起的 块数 块提交（没提交的整块清零），并在它们的数据块项上置共享位（AMD64 第 9 位、ARM64 第 55 位，硬件不看这一位）。此后克隆任务遇到带共享位的块就把同一物理块映给新任务，不复制；任务清理与服务 44 归还块时，数据块项先写零，一个共享块只有在本槽别处与别的动态槽都不再映它时才归还（按槽位图走一遍各槽的动态区页表）。成功返回 0，超出容量或要不到块返回 −1。

林兼容层用它放管道：管道缓冲在兼容层线性内存 3 GiB 起的共享区里，fork 出来的进程映同一批物理块，所以父子进程看到同样的管道。

## 低区映射（服务 52）

`低区映射(序, 块数)` 把调用者动态区第 序 块起的 块数 块（至多 14 块）另映到用户低区 0x400000 起：第 i 块在 0x400000 + i×2 MiB，到 0x2000000 为止，两处是同一批物理块。块照旧在动态区里提交与归还，低区只是别名。AMD64 写本槽低区页目录第 2–15 项；ARM64 给 0–1 GiB 另建一张二级表（照槽 0 一级表第 0 项抄设备映射），再写第 2–15 项。参数记在槽区，克隆任务时新任务用自己复制来的块照样建一份。成功返回 0，块数超过 14 或要不到块返回 −1。

林兼容层用它运行链接在 0x400000 的非位置无关程序（如 Debian 的 python3.11），自己经动态区那一处读写这些页。

## 区段物块与映物块（服务 55、56）

`区段物块(序)` 把调用者动态区第 序 块提交（没提交的整块清零）并置共享位（同服务 51），返回它的物理块号（物理地址 ÷ 2 MiB）；超出容量或要不到块返回 −1。`映物块(物块号, 目序)` 把这个物理块映到调用者动态区第 目序 块，数据块项带共享位：这一块须正被某个动态槽当作共享块映着，否则返回 −1；目序处已是这一块返回 0，已有别的块或超出容量返回 −1。同一任务可以在几处映同一块；克隆任务时照样映给新任务；任务清理与服务 44 归还块时，数据块项先写零，共享块要等本槽别处与别的槽都不再映它才归还。

林兼容层用它实现内存文件（memfd）：对象的内容放在用服务 55 要来的物理块里，块号记在各进程共见的对象表；描述符经套接字传给别的进程后，对方用服务 56 把同一批块映进自己的地址空间，每次 mmap 都映到新地址。

后续版本的事项：映物块核对调用者与块的主人同属一家；内核的“持块”机制（没有任务映着时也保留对象的块）。

## 内存保留

用过受限模式的动态任务（槽区 +0x3608 受限状态区地址非零，即林兼容层的进程）新分数据块时，空闲块须多于总块数的十六分之一（至多 64 块即 128 MiB），否则分块失败：缺页的任务结束，克隆任务失败（按父任务判断）。余下的块留给初始任务——文件服务与网络栈都在它里面，它要不到块退出时全机就停住。别的任务照旧可以用完内存。
