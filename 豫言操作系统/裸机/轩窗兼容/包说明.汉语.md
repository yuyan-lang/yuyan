# 轩窗兼容

轩窗兼容层在豫言操作系统上原样运行轩窗（Windows）程序，与林兼容（林纳兼容层）同属蕃坊（外来程序登记）的蕃长。

- 兼容层是底层模式的普通豫言程序，编成静态豫行：`「构建」于「包」曰『轩窗兼容』于「输出」曰『轩窗兼容。豫行』于「编参」曰「列」【『--目标』，『本机』，『--目标系统』，『豫言』，『--目标架构』，『臂六十四』】`。
- 运行：`「行」于『/轩窗/轩窗兼容。豫行』于「列」【[『--根』，『轩窗根目录』，][『--跟踪』，][『--兼译』，『译码目录』，[『--兼级』，『2』，]]『程序路径』，『参数』…】`。置了轩窗坊以后（`「置坊」于「名」曰『轩窗』`），「行」一个 PE 可执行文件就由蕃坊交给本层。`--跟踪` 让每次接口调用印一行（门序、名字、前四个参数与结果）。
- 装载：整个读进 PE32+ 文件，核对 DOS 头、PE 签名、可选头与机器号（与本机指令集相同）；映像放在线性偏移 4 GiB，逐节拷入，需要时按基址重定位表（DIR64）改写；映像之后排栈（可选头的栈保留，至少 1 MiB、至多 1 GiB）、进程区（1 MiB）与堆。
- 兼译（「兼译」篇）：以 `--兼译 译码目录` 起时，程序与 DLL 是兼容六十四的 PE（机器号 0x8664），在臂六十四上跑象胥译好的译码：先在壳里「传译」程序与它的 DLL，译码按文件的内容散列与长度命名放在译码目录里。装节、重定位、导入照常；装好的映像按内容找到译码，码与入口表放进堆里，登进兼模册（兼核「兼模册」，与林兼容共用一份布局与查找）。传参与返回照兼容六十四的约定（rcx、rdx、r8、r9 与栈上的影子区，结果在 rax），寄存器号与象胥的映射相同；译码里的间接转移与返回经 SVC #0x87 回到本层：目标是门就办接口，不是就查兼模册改程序计数与 x23；CPUID、RDTSC 经 SVC #0x88、#0x89 答（`--兼级 2` 报 x86-64-v2，缺省报 v3）。线程指针（象胥译 gs 段前缀时加的基址）是线程块，x24 指 ymm 高半区。IsProcessorFeaturePresent、GetSystemInfo 与共享页的处理器特性按兼容六十四答。
- 动态库（「模块」篇）：程序与它装进来的 DLL 都记在模块表里。导入表与 LoadLibrary 按名找库（不分大小写，没有扩展名补“.dll”）：先找已装的，再读程序目录下的同名文件（带路径的直接读那个路径），读到的按 PE32+ 映射到堆游标上并重定位；读不到的当系统 DLL（kernel32、user32 之类），记成伪模块，它的函数一律登蕃门。真映像按导出表找函数（按名、按序号，转发项照“库.函数”再找），找不到的也登一门，程序真调到时报出“库!函数名”。带 TLS 目录的映像分一个线程本地存储序号、按模板分一块，块址填进线程块「局针」指向的指针数组。GetProcAddress、GetModuleHandleW/A/ExW、GetModuleFileNameW/A 都按模块表答；系统伪模块的 GetProcAddress 只给本层认得的接口（同一接口回同一门），认不得的答找不到。
- 回调（「回调」篇）：进程起来先按依赖顺序跑各 DLL 的 TLS 回调与 DllMain（DLL_PROCESS_ATTACH）和程序自己的 TLS 回调，再进入口；LoadLibrary 装进新 DLL、InitOnceExecuteOnce 要跑初始化函数时也一样。兼容层不在本机栈上递归：把要跑的函数排进待调表、压一帧存下受限状态，函数返回到回调返回门（第一门）时取下一个，跑完弹帧、按去向写回结果，帧可嵌套至多 48 层。
- 仿真：零异常级读 CurrentEL 与 ID 寄存器的 MRS 指令答零（同轩窗内核）；读 KUSER_SHARED_DATA（虚址 0x7FFE0000 那一页）的整数读指令从本层摆的模板取值（系统版本、处理器特性、时间）。
- 进程区：线程块（TEB：栈界、+0x30 自指、+0x40 进程号与线程号、+0x60 进程块、+0x68 末误、+0x1480 线程本地存储槽、+0x1780 扩展槽）、进程块（PEB：+0x10 映像基址、+0x20 进程参数、+0x30 进程堆、处理器数、系统版本 10.0.26100）、进程参数块（RTL_USER_PROCESS_PARAMETERS：标准句柄、当前目录、像路、命令行、环境），以及宽、窄命令行，宽、窄像路，宽当前目录，宽环境块。命令行的第零项是像路，其后各参数按 MSVC 的规矩加引号；环境块取自启动块的环境区；当前目录取自启动块的工作目录。ARM64 的 x18 是线程块，x0 是进程块，x30 是返回门。
- 路径：C: 盘对应轩窗根（`--根`；没给根时对应豫言的“/”），Z: 盘恒对应豫言的“/”，只有这两个盘；反斜线与斜线都是分隔符，“\\?\”前缀去掉，“.”与“..”由本层规范化，相对路径从当前目录算起；CONOUT$、CONIN$、NUL 是设备。豫言路径换回轩窗路径时，落在轩窗根下的写成 C: 盘，别处写成 Z: 盘。
- 代码页：ANSI、OEM 与控制台的代码页都是八位同文（UTF-8，65001），与豫言系统一致；别的代码页按拉丁一逐字节对应。
- 地址与结构：兼容层里有两种地址：程序看见的虚址「客址」与兼容层自己的线性偏移「本址」。「址型」篇用签名把它们藏成两种抽象类型，只能经「窗址」「窗虚」互换，读写原语只收本址；寄存器与程序内存里的裸值在边界上一次换成客址，布局常量与静态串的地址经「数作本址」换成本址。PE 的各头、节表、导入描述符、导出目录与线程本地存储目录，线程块、进程块、进程参数块与 UNICODE_STRING 写成「结构」篇的具名布局；句柄表项、模块表项、回调帧与待调项、门表项、堆块头、共享页模板，以及程序交来的出参结构（OVERLAPPED、SYSTEMTIME、MEMORY_BASIC_INFORMATION、OSVERSIONINFOEXW、SYSTEM_INFO 等）也都写成具名布局，按名取栏。
- 接口调用走蕃门：导入表里的每一项都指向虚址 2^39 起的一处门（每门 16 字节），这一段不映射；程序一调接口就取指出错，受限执行带着出错地址回到兼容层，兼容层由地址算出门序，查表得接口号办理，结果写进第一个寄存器，回到调用处。兼容层只解释门号，程序的机器码原样运行。
- 认得的 DLL：kernel32.dll、kernelbase.dll、接口集 api-ms-win-core-*（都映到 kernel32 的名字）、shlwapi.dll、ntdll.dll 与 bcryptprimitives.dll。认得的接口登在「接口表」一张表里（元类型「接口」每个接口一个构造器），名字与办法都按构造器鉴尽，共二百三十六个，分几类：
  - 进程与模块：ExitProcess、TerminateProcess、GetExitCodeProcess、GetCurrentProcess(Id)、GetCurrentThread(Id)、GetCommandLineW/A、GetModuleFileNameW/A、GetModuleHandleW/A、GetModuleHandleExW、GetStartupInfoW/A、LoadLibraryExW/ExA/W/A、FreeLibrary、GetProcAddress、RtlPcToFileHeader、CreateProcessW/A（答不支持）、作业对象一族、WaitForSingleObject(Ex)、SetConsoleCtrlHandler、SetHandleInformation、SetUnhandledExceptionFilter、UnhandledExceptionFilter（印诊断、答一）、AddVectoredExceptionHandler、EncodePointer、DecodePointer、IsDebuggerPresent、IsProcessorFeaturePresent。
  - 环境与错误：GetEnvironmentStringsW、FreeEnvironmentStringsW、GetEnvironmentVariableW、SetEnvironmentVariableW、GetLastError、SetLastError、FormatMessageW（系统错误码）。
  - 内存：GetProcessHeap、HeapAlloc、HeapFree、HeapReAlloc、HeapSize、HeapCreate、HeapDestroy、HeapValidate、HeapSetInformation、LocalAlloc、LocalFree、GlobalAlloc、GlobalFree、VirtualAlloc、VirtualFree、VirtualProtect、VirtualQuery。进程堆按大小分四十八级，释放的块挂回本级空闲链。
  - 线程本地存储与同步：TlsAlloc/GetValue/SetValue/Free、FlsAlloc/GetValue/SetValue/Free、InitializeCriticalSection(Ex/AndSpinCount)、Enter/Leave/TryEnter/DeleteCriticalSection、InitializeSListHead。本层只有一条线程，进出临界区直接返回。
  - 文件与控制台：GetStdHandle、SetStdHandle、SetHandleCount、CreateFileW/A、ReadFile、WriteFile、CloseHandle、GetFileType、GetFileSize(Ex)、SetFilePointer(Ex)、SetEndOfFile、FlushFileBuffers、DeleteFileW、CreateDirectoryW、RemoveDirectoryW、GetFileAttributesW、GetConsoleMode、SetConsoleMode、WriteConsoleW/A、ReadConsoleW/A、FindFirstFileExW、FindNextFileW、FindClose（答找不到）。标准输入、输出、错误的句柄是 4、8、12；文件经底层转送打开、定位读写、取状态、设长度，位置由本层记。
  - 时间：GetSystemTimeAsFileTime、GetSystemTimePreciseAsFileTime、QueryPerformanceCounter（频率 10 MHz）、QueryPerformanceFrequency、GetTickCount(64)、Sleep、SleepEx。系统时间由墙钟秒加滴答零头算出。
  - 本地化与路径：GetACP、GetOEMCP、GetConsoleCP、GetConsoleOutputCP、SetConsoleCP、SetConsoleOutputCP、GetCPInfo、IsValidCodePage、IsDBCSLeadByte(Ex)、MultiByteToWideChar、WideCharToMultiByte、GetStringTypeW、LCMapStringW/Ex、CompareStringW/Ex/Ordinal、GetCurrentDirectoryW、SetCurrentDirectoryW、GetFullPathNameW、GetTempPathW、SearchPathW（答找不到），shlwapi 的 PathRemoveFileSpecW、PathCombineW、StrStrIW。
  - 版本与系统信息：VerSetConditionMask、VerifyVersionInfoW、GetVersion、GetVersionExW、GetProductInfo（本层答 Windows 11，10.0.26100，专业版工作站）、GetSystemInfo、GetNativeSystemInfo、IsWow64Process、GetSystemDirectoryW、GetWindowsDirectoryW、GlobalMemoryStatusEx、GetComputerNameExW、进程缓解策略、区域（恒 en-US）、GetLocalTime、GetSystemTime、FileTimeToSystemTime、GetTimeZoneInformation（协调世界时）。
  - 同步（本层只有一条线程）：读写锁与条件变量（取锁即得，候即超时）、WaitOnAddress、事件、互斥体、信号量、InitOnceExecuteOnce。
  - 杂项：OutputDebugStringA/W（印到诊断输出）、RaiseException（给调试器命名线程的 0x406D1388 直接返回，别的印码结束）、ProcessPrng（伪随机，见后续事项）、线程栈界、进程堆列表、句柄信息与复制、lstrcmpi，ntdll 的 RtlFormatCurrentUserKeyPath、RtlInitUnicodeString 与注册表一族（一律答键不存在）。
- 程序调到认不得的接口时印出“DLL!函数名”并以 127 结束。
- 线性内存布局：16 KiB 以下是执行器实例约的协议区，本层的数据都放在 16 KiB 以上；数据区 16–64 KiB；受限状态区在 64 KiB；全局格在 128 KiB 起；句柄表、纤程本地存储表、私有当前目录在 144–200 KiB；底层请求块的地址写在零号核块的底层请求块格；蕃门表在 1–2 MiB；文字暂存在 2–3 MiB；模块表、名池、回调帧栈、待调表、程序目录、依赖边表、号门缓存、共享页模板与兼译的兼模册、译码路径、译码目录、ymm 高半区在 3–4 MiB；启动块在 64–80 MiB；读缓冲在 256 MiB 起；轩窗程序的映像、栈、进程区与堆在 4 GiB 以上。
- 受限执行的异常：程序计数正落在蕃门上的是接口调用；打断接着运行；别的异常印出向量、错误码、故障址与程序计数，以访问违例（0xC0000005）结束。
- 验收：MSVC 静态链接的 distlib 启动器（`t64-arm.exe`）跑完 CRT 启动、打开并读自己的文件、印出“Fatal error in launcher: Unable to find an appended archive.”，以码 1 结束；末尾接上 shebang 行与 zip 尾记录后，它解析 shebang、拼出带引号的命令行、调 CreateProcessW 得“The request is not supported.”；原生你好的轩窗入口与轩窗文件入口分别验控制台读写与文件的建、写、读、删。兼译（臂六十四上，2026-11-27）：同一启动器的 x64 版 `t64.exe` 经象胥译码跑出同样两种结果（找不到附档以码 1 结束；接上 shebang 与 zip 尾以后拼出命令行、CreateProcessW 答不支持），手拼的 x86-64 控制台 PE（导入 kernel32 的 GetStdHandle、WriteFile、ExitProcess）印两行后以零结束。谷歌浏览器 Windows ARM64 版（158.0.8127.89，chrome_elf.dll 摆在 chrome.exe 旁）：装进 chrome_elf.dll，跑完它的 TLS 回调与 DllMain，进入 wWinMain，chrome_elf 做完 PartitionAlloc 初始化，共一千七百多次接口调用，停在延迟装载 ADVAPI32!InitializeAcl。

后续版本的事项：

- advapi32 的安全描述符与令牌一族（InitializeAcl 起）、注册表的真实读写、user32 与 gdi32；DllMain 答 FALSE 时让装载失败；按清单里的并排程序集目录找 DLL（谷歌浏览器的 chrome_elf.dll 在版本号子目录里）。
- 系统熵源：ProcessPrng 眼下用 xorshift 伪随机。
- C 运行库的动态库（ucrtbase.dll、api-ms-win-crt-*.dll、vcruntime140.dll）：动态链接 C 运行库的程序要本层自己实现这些函数。
- 线程、子进程（CreateProcessW）、结构化异常与向量化异常处理的投递，FLS 回调。
- 目录枚举（FindFirstFileExW 一族）、MoveFileExW、GetFileInformationByHandle 等文件接口；SetEnvironmentVariableW 改环境块。
- AMD64 程序的线程块（gs 基址）与裸机 AMD64 上的验收。
- 兼译：x87、PCMPxSTR、PDEP/PEXT 与 XSAVE 的服务（林兼容有，拆进兼核两边共用）、即时翻译、代码节里被 DIR64 重定位改写的 imm64、x64 的结构化异常展开（UNWIND_INFO）。
- 用户界面（user32、gdi32）经显示代办接到豫言桌面。
