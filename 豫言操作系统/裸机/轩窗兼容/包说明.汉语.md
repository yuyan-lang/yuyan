# 轩窗兼容

轩窗兼容层在豫言操作系统上原样运行轩窗（Windows）程序，与林兼容（林纳兼容层）同属蕃坊（外来程序登记）的蕃长。

- 兼容层是底层模式的普通豫言程序，编成静态豫行：`「构建」于「包」曰『轩窗兼容』于「输出」曰『轩窗兼容。豫行』于「编参」曰「列」【『--目标』，『本机』，『--目标系统』，『豫言』，『--目标架构』，『臂六十四』】`。
- 运行：`「行」于『/轩窗/轩窗兼容。豫行』于「列」【[『--根』，『轩窗根目录』，][『--跟踪』，][『--兼译』，『译码目录』，[『--兼译服』，『端口』，][『--兼级』，『2』，]]『程序路径』，『参数』…】`。置了轩窗坊以后（`「置坊」于「名」曰『轩窗』`），「行」一个 PE 可执行文件就由蕃坊交给本层。`--跟踪` 让每次接口调用印一行（门序、名字、前四个参数与结果）。
- 装载：整个读进 PE32+ 文件，核对 DOS 头、PE 签名、可选头与机器号（与本机指令集相同）；映像放在线性偏移 4 GiB，逐节拷入，需要时按基址重定位表（DIR64）改写；没有重定位、首选基址在 64 KiB 至 2^39 之间的映像（豫言编的轩窗程序，首选 0x1f0000）照首选基址交给程序：低区三格记那段虚址的起止与平移，运行环每回进受限之前抄进受限状态区的低区三栏，虚机受限机照它映页，「窗址」「窗虚」也先认它（2026-11-28）；映像之后排栈（可选头的栈保留，至少 1 MiB、至多 1 GiB）、进程区（1 MiB）与堆。
- 兼译（「兼译」篇）：以 `--兼译 译码目录` 起时，程序与 DLL 是兼容六十四的 PE（机器号 0x8664），在臂六十四上跑象胥译好的译码：译码按文件的内容散列与长度命名放在译码目录里，「行」时蕃坊自动备好程序与程序目录里它导入的 DLL 的译码（也可先在壳里「传译」）。整译（2026-11-27，#1977）：加 `--兼译服 端口`（蕃坊自动找好象胥服加上）时，装到没有译码的 PE（运行时按路径 LoadLibrary 的 DLL 之类）就把它的豫言路径送给象胥服，象胥服把整个文件译进译码缓存、答回译码路径，本层读进来照常登记（兼译篇「兼整译」；请求布局在兼核「即约」，TCP 收发在「即客」篇，经转送的读写、等待与连接）；异常报告里的“整”“整败”是成、没成的次数。片段即时翻译（2026-11-27，#1977）：间接转移或返回的目标查兼模册查不到时，目标落在某个模块里就以那个模块的基址、落在堆里（程序 VirtualAlloc 来自己生成的码；本层的虚存都从堆游标分）就以堆起点作基址，把目标前后各至多一百二十八 KiB 的码送给象胥服即时翻译，收回的片段登进兼模册（兼核「片位」记成片段），再经「受限护页」（服务 421）把源码窗口设成零级只读；程序改写那里就撞权限故障，「兼写护故」作废那页上的片段、放开写权、重做那条写，下次跳进去再重译（兼译篇「兼即译」「兼护片」「兼写护故」）。异常报告的“护”“放”“护败”是写保护的页数、放开的次数与「受限护页」答负的次数。装节、重定位、导入照常；装好的映像按内容找到译码，码与入口表放进堆里，登进兼模册（兼核「兼模册」，与林兼容共用一份布局与查找）。传参与返回照兼容六十四的约定（rcx、rdx、r8、r9 与栈上的影子区，结果在 rax），寄存器号与象胥的映射相同；译码里的间接转移与返回先查 x25 指着的查表缓存（兼核「查缓」，线性「兼缓址」起，2026-11-28），命中就直接跳去；落空经 SVC #0x90（旧译码 SVC #0x87）回到本层：目标是门就办接口（门不进缓存，每次都回到本层），不是就查兼模册改程序计数与 x23，再照 x17 填进缓存（「兼缓记」；兼模册有条目作废时整表清空，异常报告的“缓填”“缓清”“缓误”是填了、清了与槽不合的次数）；CPUID、RDTSC 经 SVC #0x88、#0x89 答（`--兼级 2` 报 x86-64-v2，缺省报 v3）；x87、PCMPxSTR、PDEP/PEXT、XSAVE/XRSTOR（SVC #0x8A–#0x8F）交兼核的「浮办」「串比」「宽办」（与林兼容同一份），x87 状态与超越函数暂存各一份放在布局里。线程指针（象胥译 gs 段前缀时加的基址）是线程块，x24 指 ymm 高半区，x25 指查表缓存。IsProcessorFeaturePresent、GetSystemInfo 与共享页的处理器特性按兼容六十四答。
- 动态库（「模块」篇）：程序与它装进来的 DLL 都记在模块表里。导入表与 LoadLibrary 按名找库（不分大小写，没有扩展名补“.dll”）：先找已装的，再读程序目录下的同名文件（带路径的直接读那个路径），读到的按 PE32+ 映射到堆游标上并重定位；读不到的当系统 DLL（kernel32、user32 之类），记成伪模块，它的函数一律登蕃门。真映像按导出表找函数（按名、按序号，转发项照“库.函数”再找），找不到的也登一门，程序真调到时报出“库!函数名”。带 TLS 目录的映像分一个线程本地存储序号、按模板分一块，块址填进线程块「局针」指向的指针数组。GetProcAddress、GetModuleHandleW/A/ExW、GetModuleFileNameW/A 都按模块表答；系统伪模块的 GetProcAddress 只给本层认得的接口（同一接口回同一门），认不得的答找不到。
- 回调（「回调」篇）：进程起来先按依赖顺序跑各 DLL 的 TLS 回调与 DllMain（DLL_PROCESS_ATTACH）和程序自己的 TLS 回调，再进入口；LoadLibrary 装进新 DLL、InitOnceExecuteOnce 要跑初始化函数时也一样。兼容层不在本机栈上递归：把要跑的函数排进待调表、压一帧存下受限状态，函数返回到回调返回门（第一门）时取下一个，跑完弹帧、按去向写回结果，帧可嵌套至多 48 层。
- 仿真：零异常级读 CurrentEL 与 ID 寄存器的 MRS 指令答零（同轩窗内核）；读 KUSER_SHARED_DATA（虚址 0x7FFE0000 那一页）的整数读指令从本层摆的模板取值（系统版本、处理器特性、时间）。
- 进程区：线程块（TEB：栈界、+0x30 自指、+0x40 进程号与线程号、+0x60 进程块、+0x68 末误、+0x1480 线程本地存储槽、+0x1780 扩展槽）、进程块（PEB：+0x10 映像基址、+0x20 进程参数、+0x30 进程堆、处理器数、系统版本 10.0.26100）、进程参数块（RTL_USER_PROCESS_PARAMETERS：标准句柄、当前目录、像路、命令行、环境），以及宽、窄命令行，宽、窄像路，宽当前目录，宽环境块。命令行的第零项是像路，其后各参数按 MSVC 的规矩加引号；环境块取自启动块的环境区；当前目录取自启动块的工作目录。ARM64 的 x18 是线程块，x0 是进程块，x30 是返回门。
- 路径：C: 盘对应轩窗根（`--根`；没给根时对应豫言的“/”），Z: 盘恒对应豫言的“/”，只有这两个盘；反斜线与斜线都是分隔符，“\\?\”前缀去掉，“.”与“..”由本层规范化，相对路径从当前目录算起；CONOUT$、CONIN$、NUL 是设备。豫言路径换回轩窗路径时，落在轩窗根下的写成 C: 盘，别处写成 Z: 盘。
- 代码页：ANSI、OEM 与控制台的代码页都是八位同文（UTF-8，65001），与豫言系统一致；别的代码页按拉丁一逐字节对应。
- 地址与结构：兼容层里有两种地址：程序看见的虚址「客址」与兼容层自己的线性偏移「本址」。「址型」篇用签名把它们藏成两种抽象类型，只能经「窗址」「窗虚」互换，读写原语只收本址；寄存器与程序内存里的裸值在边界上一次换成客址，布局常量与静态串的地址经「数作本址」换成本址。PE 的各头、节表、导入描述符、导出目录与线程本地存储目录，线程块、进程块、进程参数块与 UNICODE_STRING 写成「结构」篇的具名布局；句柄表项、模块表项、回调帧与待调项、门表项、堆块头、共享页模板，以及程序交来的出参结构（OVERLAPPED、SYSTEMTIME、MEMORY_BASIC_INFORMATION、OSVERSIONINFOEXW、SYSTEM_INFO 等）也都写成具名布局，按名取栏。
- 接口调用走蕃门：导入表里的每一项都指向虚址 2^39 起的一处门（每门 16 字节），这一段不映射；程序一调接口就取指出错，受限执行带着出错地址回到兼容层，兼容层由地址算出门序，查表得接口号办理，结果写进第一个寄存器，回到调用处。兼容层只解释门号，程序的机器码原样运行。
- 认得的 DLL：kernel32.dll、kernelbase.dll、接口集 api-ms-win-core-*（都映到 kernel32 的名字）、shlwapi.dll、ntdll.dll、bcryptprimitives.dll，以及 C 运行库 ucrtbase.dll、接口集 api-ms-win-crt-*、msvcrt.dll 与 vcruntime140*.dll。认得的接口登在「接口表」一张表里（元类型「接口」每个接口一个构造器），名字与办法都按构造器鉴尽，共四百八十七个，分几类：

  - 环境与错误：GetEnvironmentStringsW、FreeEnvironmentStringsW、GetEnvironmentVariableW、SetEnvironmentVariableW、GetLastError、SetLastError、FormatMessageW（系统错误码）。
  - 内存：GetProcessHeap、HeapAlloc、HeapFree、HeapReAlloc、HeapSize、HeapCreate、HeapDestroy、HeapValidate、HeapSetInformation、LocalAlloc、LocalFree、GlobalAlloc、GlobalFree、VirtualAlloc、VirtualFree、VirtualProtect、VirtualQuery。进程堆按大小分四十八级，释放的块挂回本级空闲链。
  - 线程本地存储与同步：TlsAlloc/GetValue/SetValue/Free、FlsAlloc/GetValue/SetValue/Free、InitializeCriticalSection(Ex/AndSpinCount)、Enter/Leave/TryEnter/DeleteCriticalSection、InitializeSListHead。临界区记主人线程号与递归次数，被别的线程占着就等（「锁」篇，2026-11-28）。
  - 文件与控制台：GetStdHandle、SetStdHandle、SetHandleCount、CreateFileW/A、ReadFile、WriteFile、CloseHandle、GetFileType、GetFileSize(Ex)、SetFilePointer(Ex)、SetEndOfFile、FlushFileBuffers、DeleteFileW、CreateDirectoryW、RemoveDirectoryW、GetFileAttributesW、GetConsoleMode、SetConsoleMode、WriteConsoleW/A、ReadConsoleW/A、FindFirstFileExW、FindNextFileW、FindClose（答找不到）。标准输入、输出、错误的句柄是 4、8、12；文件经底层转送打开、定位读写、取状态、设长度，位置由本层记。

  - 版本与系统信息：VerSetConditionMask、VerifyVersionInfoW、GetVersion、GetVersionExW、GetProductInfo（本层答 Windows 11，10.0.26100，专业版工作站）、GetSystemInfo、GetNativeSystemInfo、IsWow64Process、GetSystemDirectoryW、GetWindowsDirectoryW、GlobalMemoryStatusEx、GetComputerNameExW、进程缓解策略、区域（恒 en-US）、GetLocalTime、GetSystemTime、FileTimeToSystemTime、GetTimeZoneInformation（协调世界时）。
  - 同步：读写锁（零空、一独占、偶数是共享者的两倍）、条件变量（当计数，唤醒加一；等的一方先放锁、计数变了或到时再取回）、WaitOnAddress（值不同或唤醒计数变了就返回）、InitOnceExecuteOnce（「锁」篇）；事件、互斥体与信号量（「同步」篇，2026-11-28）在句柄表里记状态（事件有无信号与是否手动复位、信号量的计数与上限、互斥体的持有次数），CreateEvent/Mutex/Semaphore 的宽窄与 Ex 形式、SetEvent、ResetEvent、PulseEvent、ReleaseMutex、ReleaseSemaphore、WaitForSingleObject(Ex)、WaitForMultipleObjects(Ex) 按状态答：有信号的取用并答零，等不到的答 WAIT_TIMEOUT（毫秒不为零时另印一行诊断）；进程与线程伪句柄、文件与控制台句柄当有信号。等不到时有别的线程就等（「需等」，到时答超时），只有这一条线程时直接答超时。互斥体在句柄项的「标」记持有者线程号。另有 GetProcessAffinityMask、SetProcessAffinityMask、OpenProcess（本进程）、Get/SetThreadContext。
  - 杂项：OutputDebugStringA/W（印到诊断输出）、RaiseException（给调试器命名线程的 0x406D1388 直接返回，别的印码结束）、ProcessPrng（伪随机，见后续事项）、线程栈界、进程堆列表、句柄信息与复制、lstrcmpi，ntdll 的 RtlFormatCurrentUserKeyPath、RtlInitUnicodeString 与注册表一族（一律答键不存在）。
- C 运行库（「运行库」「格式」「运行库文件」「运行库跳」「运行库浮转」「运行库时间」「运行库杂项」「运行库数学」八篇，2026-11-28）：mingw-w64（UCRT 版）与 MSVC 编的 C 程序动态链接的 UCRT 子集，一百六十四个：
  - 启动：__p___argc、__p___argv（_configure_narrow_argv 与 _configure_wide_argv 照轩窗的命令行规则切 argv：空白分隔、双引号成组、反斜杠后接引号时成对的折半）、_initterm（函数表里的非空项经「回调」一个个跑）、_crt_atexit、atexit、_cexit 与 exit（atexit 表倒着跑，exit 跑完以退出码结束，回调篇「去退出」）、_exit、abort，以及几个只记一下的设置接口；
  - 堆：malloc、calloc、realloc、free 接本层的堆；
  - 串与内存：memcpy、memmove、memset、memcmp、strlen、strcmp、strncmp、strcpy、strncpy、strcat、strchr、strrchr、strstr；
  - 标准输入输出：__acrt_iob_func 给 stdin、stdout、stderr 三个 FILE（库态里的三个八字节，按地址认出是第几个）；printf 一族（__stdio_common_vfprintf、__stdio_common_vsprintf）在「格式」篇照 UCRT 的样子格式化：整数、字符与串（宽字符转 UTF-8）、指针（十六位大写十六进制）、浮点（大数精确化成十进数位，再按精度五成双舍入；a 式缺省十三位；缺省非数出 -nan(ind)）；snprintf 按选项截断补零；puts、fputs、fputc、putchar、fwrite 直接写句柄。
  - 文件（「运行库文件」）：FILE 表六十四项，每项一条「流录」（句柄、旗、ungetc 退回的字节），第零至二项是三个标准流；fopen 照模式换成 CreateFile 的处置与访问权，路径照轩窗的规矩换成豫言路径；fread、fgets、getc、ungetc、feof、ferror、clearerr、fseek、ftell（连同六十四位的 _fseeki64、_ftelli64）、fclose、freopen、_fileno、_isatty、_lock_file；remove、rename 交转送；tmpfile 在 /tmp 下开临时文件，tmpnam 出名字；_popen 答空指针，_pclose 答负一。出错写 errno（_errno 指线性「误号址」），轩窗错误码换成 errno。
  - 跳转（「运行库跳」）：_setjmp、__intrinsic_setjmp 按 x64 与 ARM64 各自的 jmp_buf 布局存下非易失寄存器、栈指针、返回地址与浮点控制；longjmp 照存的样子复原，值为零时当一。
  - 串转浮（「运行库浮转」）：strtod、atof 认十进制、十六进制浮点、inf、infinity、nan(...)；十进制读至多十八位有效数字，尾数不超过二的五十三次方、十的幂在二十二以内时直接用双精度算准，别的用六十四位扩展精度乘除十的幂再舍入，endptr 写回停下的位置。
  - 时间（「运行库时间」）：_time64、_time32、clock、_gmtime64、_localtime64 与两个 _s 版本、_mktime64（越界的栏规格化，回写星期与年内日）、_difftime64、strftime（C 区域设置的二十多种转换；本地时区按协调世界时）。
