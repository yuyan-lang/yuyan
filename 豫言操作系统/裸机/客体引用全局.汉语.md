# 客体函数引用全局变量

定义的全局变量现在可使用默认 `funcref` 类型，与 i32 全局共存。支持空函数引用和函数引用初值；引用初值中的函数号必须存在，并会加入模块的已声明函数引用集合。

全局类型与可变性分别记录：类型标签位于 `[29504,29632)`，每个全局一个字节；原有记录仍保存可变标志及初值，运行值仍从 45056 开始。不可变引用全局不会因为类型标记非零而变成可写。

验证 `global.get` 时压入声明类型，验证 `global.set` 时要求栈顶类型匹配；不可变约束继续由解码层检查。整数不能写入引用全局，引用也不能冒充整数参与运算或作为整数结果返回。实例化复制已核验的初值，再次实例化恢复原值。

当前支持 i32 常量、`ref.func` 和默认 `ref.null func` 初值，包括非最短但合法的空引用堆类型编码。已知的初值类型不匹配、非法可变标志及越界函数号均拒绝。导入全局、`global.get` 初值、通用堆类型和扩展常量表达式仍待实现。

新增二十组用例，其中十九组静态结果与标准 Wasm 引擎对照，九组执行结果及全局值也一致。用例覆盖不可变引用、可变赋值与清空、整数与引用混合、仅由全局初值声明函数、类型不符、重新实例化，以及通过全局引用写表再间接调用。另有一个合法外部引用类型模块，验证当前不支持的明确拒绝。

此改动保留了后续扫描全局引用所需的类型信息，尚未实现 WasmGC 堆对象或垃圾回收。

规范对照：[官方全局变量测试](https://github.com/WebAssembly/spec/blob/main/test/core/global.wast)。

2026 年 9 月 23 日，两架构全部 366 项裸机回归通过，产物位于 `/tmp/yy裸机验证.yXM6uc`，日志为 `/tmp/yy引用全局验证日志`。二十个相关客体模块通过标准引擎验证；四个默认 Shell 镜像已更新，与实际验收镜像逐字节一致。元数据布局及磁盘持久化独立复核通过。详见[验证记录](验证记录.json)的“客体引用全局扩展验证”。

## `eqref` 全局与空引用初值

定义的可变 `eqref` 全局现在接受匹配的 `ref.null eq` 初值，实例化写入客体空引用值 0；静态验型用 `eqref` 标签检查 `global.get/set`，运行时沿用独立全局槽。53 字节标准 WasmGC 模块将 `i31` 写入该全局，再读出与新构造的同值 `i31` 比较，Node 与 ARM64、AMD64 QEMU 均返回 1。仅将初值改为 `ref.null func` 的 53 字节模块被 Node 判为无效，客体资源索引返回 `-2`。连同旧场景 368 项全过，产物在 `/tmp/yy裸机验证.kxIjEs`。全局值已纳入保守 GC 根扫描，见[客体自动根回收](客体自动根回收.汉语.md)；非空具体引用全局、分配型常量表达式、精确堆类型与完整普通豫言模块仍未支持。

## 复合引用全局的有界索引

非空具体结构或数组引用全局现在记录堆类型号和常量表达式起点。索引器有界读取 `array.new_default`、零元素 `array.new_fixed`，以及带一个数值字段的 `struct.new`；不匹配的类型、构造参数或越界输入仍返回错误。51 字节默认数组及 50 字节固定零元素数组标准模块均由 Node 判有效；双架构 368 项 QEMU 回归通过，产物在 `/tmp/yy裸机验证.QeeB0b`。这一步仅完成声明与常式索引：客体实例化仍明确拒绝复合引用全局，尚未分配对象或执行普通豫言模块。

## 零长度数组全局的实例化与保活

有对象堆的用户态执行器现在可以实例化非空具体数组全局，初值为长度零的 `array.new_default` 或 `array.new_fixed 0`。它按类型号分配真实对象，把句柄写入全局槽；静态验证器将 `global.get/set` 的具体类型按“标签高十六位、数量低十六位”传递。两份 51/50 字节标准模块在 Node 中执行 `f()` 均返回 0；裸机测试先触发 GC，再从全局读取对象执行 `array.len`，ARM64 与 AMD64 的 368 项回归全部通过，产物在 `/tmp/yy裸机验证.TWagRV`。客体若声明自己的线性内存，当前对象堆会与其工作区重叠，因此复合全局实例化仍明确拒绝。非零长度数组、结构体常量初值及完整普通豫言模块尚未支持。

## 单数值字段结构全局

资源索引按 GC 构造子操作码区分数组与结构，因而 `i32.const → struct.new` 不再被误判为数组。用户态实例化器现支持单个 `i32`、`i64` 或 `f64` 字段的结构全局：整数常量写入对象载荷，`i64` 的高半字按符号扩展，`f64` 复制原始八字节。四份独立标准模块在 Node 中分别返回 42、1、0、1；其中第四份以 `i64.const -42` 验证负数符号扩展。裸机在触发 GC 后，整数模块通过 `struct.get` 实际读取字段，`f64` 模块核验 3.5 的载荷位形 `0x400c000000000000`。ARM64 与 AMD64 的 368 项 QEMU 回归全部通过，产物在 `/tmp/yy裸机验证.PlLeTL`。索引器目前只接受其有符号读取器能表示的 `i64.const`，还不支持任意 64 位常量；多字段、引用字段、非零长度数组及客体自带线性内存的复合全局仍待实现。
