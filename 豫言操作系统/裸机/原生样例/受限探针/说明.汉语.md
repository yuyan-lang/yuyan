# 受限探针

受限模式（提案 00012 服务 48「进入受限」）的最小验收程序，底层模式，编成豫行在豫言操作系统里运行（行在虚机与裸机都用它）。2026-11-25 为行在虚机的受限模式（#1945 第四步，林檎经 Hypervisor.framework）而写。

程序在自己的线性内存里摆好：

- 偏移 0x1000 起六条臂六十四指令：`mov x8,#64`、`mov x0,#7`、`svc #0`、`mov x0,#9`、`svc #1`、`b .`；
- 偏移 0x1040 起五条浮点指令：`fadd v2.2d, v0.2d, v1.2d`、`eor v3.16b, v0.16b, v1.16b`、`mrs x1, fpcr`、`fdiv d6, d7, d8`、`svc #0`；
- 偏移 0x1080 起两条：`mov x3, #5`、`b .`（第四回用）；
- 偏移 0x2000 起一块受限状态区（一千零八十八字节），程序计数是 1 TiB 加 0x1000（受限执行的虚址是线性偏移加 1 TiB，同林兼容），栈指针是 1 TiB 加 0x4000。

然后进五回受限，逐项核对：

1. 第一回答原因一（系统调用指令），向量零，x8 是 64、x0 是 7，程序计数停在第一条 svc 之后。
2. 第二回答原因四（内核服务调用），向量一，x0 是 9，程序计数停在第二条 svc 之后。
3. 第三回（浮点往返）：状态区浮点区里 q0 为（1.5，2.25）、q1 为（0.25，4.0）、q7 为 1.0、q8 为零、q31 为一个花样、FPCR 为 0x00C00000（向零舍入）、FPSR 为零，从 0x1040 跑：答原因一；q2 为（1.75，6.25）、q3 为 q0 异或 q1（两半都核，一百二十八位整个进出）；x1 读到的是装进去的 FPCR；q6 低半是正无穷；q31 原样回来；FPCR 原样回来；FPSR 记下除以零（值二）。
4. 第四回（时间片）：程序计数指到 0x1080 的 `mov x3, #5`，执行完就在 `b .` 上原地死循环、不发系统调用；虚拟定时器一片（十毫秒）后答原因三、向量一，程序计数停在 `b .` 上（不是进入处的 mov：定时器退出没经异常向量，现场在 vCPU 的 PC 里），x3 为五，q2 不变。
5. 第五回（改过的浮点寄存器）：只把 q0 改成（2.0，3.0），再从 0x1040 跑：答原因一，q2 为（2.25，7.0）。受限机进入时只设与上回不同的浮点寄存器，这一回验改过的 q0 真设进去了。

每项印一行“受限探针：项 成”或“受限探针：项 败 得 N”，全过以退出码零结束，有一项不过以一结束。

构建与运行（在仓库根目录，壳里）：

```
「构建」于「包」曰『受限探针』于「输出」曰『受限探针。豫行』于「编参」曰「列」【『--目标』，『本机』，『--目标系统』，『豫言』，『--目标架构』，『臂六十四』】
「行」于『./受限探针。豫行』于（「罄」以「文」）
```

产物名要以“豫行”结尾：虚机按名字认静态豫行，不带后缀的当清单去找单元，报“不存在”（系统错误码 44）。这几条指令只属臂六十四，兼容六十四另写一份。

2026-11-25 在 pit-mac 测试虚机（d55606a5bc，林檎经 Hypervisor.framework）实跑，九项全过；同日加浮点往返、时间片、改寄存器三回后（3a853cdd40，测试根浮点）实跑，二十八项全过。

## 停候探针

同包另一个入口「停候探针」是行在虚机停世界挂候的回归验收：纯底层的静态豫行不照执行器的实例约用线性偏移 1372（执行器那里是停世界纪元），探针在那里写奇数 271，再逐字节印一行“停候探针 成”并以零退出。虚机只对多核任务做停世界挂候，单核任务照常从服务门回来，整行印出。

```
「构建」于「包」曰『受限探针』于「入口」曰「列」【『停候探针』】于「输出」曰『停候探针。豫行』于「编参」曰「列」【『--目标』，『本机』，『--目标系统』，『豫言』，『--目标架构』，『臂六十四』】
「行」于『./停候探针。豫行』于（「罄」以「文」）
```
