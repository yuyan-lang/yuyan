# 受限探针

受限模式（提案 00012 服务 48「进入受限」）的最小验收程序，底层模式，编成豫行在豫言操作系统里运行（行在虚机与裸机都用它）。2026-11-25 为行在虚机的受限模式（#1945 第四步，林檎经 Hypervisor.framework）而写。

程序在自己的线性内存里摆好：

- 偏移 0x1000 起六条臂六十四指令：`mov x8,#64`、`mov x0,#7`、`svc #0`、`mov x0,#9`、`svc #1`、`b .`；
- 偏移 0x2000 起一块受限状态区（一千零八十八字节），程序计数是 1 TiB 加 0x1000（受限执行的虚址是线性偏移加 1 TiB，同林兼容），栈指针是 1 TiB 加 0x4000。

然后进两回受限，逐项核对：

1. 第一回答原因一（系统调用指令），向量零，x8 是 64、x0 是 7，程序计数停在第一条 svc 之后。
2. 第二回答原因四（内核服务调用），向量一，x0 是 9，程序计数停在第二条 svc 之后。

每项印一行“受限探针：项 成”或“受限探针：项 败 得 N”，全过以退出码零结束，有一项不过以一结束。

构建与运行（在仓库根目录，壳里）：

```
「构建」于「包」曰『受限探针』于「输出」曰『受限探针』于「编参」曰「列」【『--目标』，『本机』，『--目标系统』，『豫言』，『--目标架构』，『臂六十四』】
「行」于『./受限探针』于（「罄」以「文」）
```

这几条指令只属臂六十四，兼容六十四另写一份。
