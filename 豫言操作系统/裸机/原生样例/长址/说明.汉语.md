# 原生长址

路二（直接生成原生二进制）的六十四位地址内存（memory64）样例，底层模式。程序声明六十四位地址内存（最大 1073741824 页，即 64 TiB），把线性内存从一页增长到 82000 页（约 5.0 GiB），在 4 GiB 之下与之上读写四字节整数、长整数、小数与一、二字节（含有符号读），读写线性内存最后四字节，批量填充 4 GiB 之上的一段，把横跨 4 GiB 的一段复制到 4 GiB 之上，再核对超过最大页数的增长返回负一、页数不变。全部相符时打印“长址原生：通过”并以 0 退出，否则打印第一个不符项的序号并以 1 退出。

核验写在 `核验。豫`，地址都是长整数，读写用底层库 `内存六四` 的 `长址…` 函数。`入口。豫` 是 Linux 版（直接发系统调用），`苹果入口。豫` 是 macOS 版（经 libSystem）。

构建与生成（在仓库根目录）：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 原生长址 苹果入口 --输出 yy原生长址苹果.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 文件 豫言操作系统/裸机/原生生成。豫 --输出 yy原生生成.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy原生生成.wasm 苹果 臂六十四 yy原生长址苹果.wasm yy原生长址苹果
./yy原生长址苹果
```

x86-64 版把 `臂六十四` 换成 `兼容六十四`。Linux 版：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 原生长址 --输出 yy原生长址.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy原生生成.wasm Linux 臂六十四 yy原生长址.wasm yy原生长址臂
node 豫言操作系统/宿主/节点/宿主.cjs yy原生生成.wasm Linux 兼容六十四 yy原生长址.wasm yy原生长址兼
```

Linux 版可在 macOS 上用 Docker 运行（`FROM scratch` 镜像，只含这一个文件，见 `原生样例/你好/说明.汉语.md`）。

线性内存只在用到的页上占物理内存：macOS 与 Linux 的动态区按 64 TiB 以 MAP_NORESERVE 映射（x86-64 的 macOS 是数据段里的零填充区），本样例只碰几页。

裸机版（AMD64）：`裸机入口。豫` 经 `平台。接口。豫` 调内核的写字节与退出任务服务，用 `豫言操作系统/裸机/入口。豫` 直接做成裸机镜像，在 8 GB 内存的 QEMU 里运行，核验内核在 4 GiB 以上以页表提交块（见 `豫言操作系统/裸机/文档/内存块管理.汉语.md` 的“AMD64 高区”）：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 原生长址 裸机入口 --输出 yy原生长址裸机.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 文件 豫言操作系统/裸机/入口。豫 --输出 yy豫言裸机.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy豫言裸机.wasm 兼容六十四 yy原生长址裸机.wasm 长址.镜像 运行
qemu-system-x86_64 -machine q35 -accel tcg -m 8G -display none -serial stdio -no-reboot -kernel 长址.镜像
```

串口印出“长址原生：通过”与“用户任务全部退出”。
