# 原生你好

路二（径生原生之二进制）于 Linux 之最小闭环，底层之模。书“你好”一行，自标准入读至多六十四字节而原样书之，终以退出码七。书、读、退皆径发 Linux 之系统调用：导入声于 `林纳。底层接口。豫`，导入之模块名即接口文件之名“林纳”，导入之名为中文名（`写`、`读`、`退出进程`，即系统调用 `write`、`read`、`exit_group`；原名唯记于裸机后端 `降级目标。豫` 之入口表）；寄存器之降依入口之表成系统调用之桩，址类之参入系统之前加线性内存之基址。

构之（于仓库之根）：编译器之参 `--目标 本机` 使编译器径降底层之模为原生可执行之文（底层之程不带执行器），`--目标系统`、`--目标架构` 定其目标。

```sh
./豫构。林檎。豫行 构建 原生你好 --输出 原生你好臂 -j 24 -- --目标 本机 --目标系统 林纳 --目标架构 臂六十四
./豫构。林檎。豫行 构建 原生你好 --输出 原生你好兼 -j 24 -- --目标 本机 --目标系统 林纳 --目标架构 兼容六十四
```

所成者，静态之 ELF64 可执行文件，于 Linux 之 arm64 与 x86-64 径行，不倚动态之库。

于 macOS 可以 Docker 验之（`FROM scratch` 之镜像，唯含此一文件）：

```sh
printf 'FROM scratch\nCOPY --chmod=755 原生你好臂 /hello\nENTRYPOINT ["/hello"]\n' > Dockerfile
docker build --platform linux/arm64 -t yy-hello .
printf '回声\n' | docker run --rm -i --platform linux/arm64 yy-hello; echo $?
```

当书“你好”与“回声”二行，退出码七。x86-64 则易以 `原生你好兼` 与 `linux/amd64`。

## macOS 之版

`林檎入口。底层。豫` 乃同一程序之 macOS 版：书、读、退经 libSystem 之 `write`、`read`、`exit`（导入之模块名为林檎，导入之名为 `写`、`读`、`退出`）；所生之 Mach-O 位置无关，由 dyld 绑其导入之槽，附特设之签名，可于本机（arm64）径行：

```sh
./豫构。林檎。豫行 构建 原生你好 林檎入口 --输出 原生你好林檎 -j 24 -- --目标 本机 --目标系统 林檎 --目标架构 臂六十四
printf '回声\n' | ./原生你好林檎; echo $?
```

Linux 之版，编译器之参则为 `--目标系统 林纳`，不书入口之段（见上）。

## 轩窗之版

`轩窗入口。底层。豫` 为同一程序之轩窗之版：经 kernel32 之 `GetStdHandle`、`WriteFile`、`ReadFile`、`ExitProcess`（导入之模块名为“轩窗”，导入之名为 `取标准句柄`、`写文件`、`读文件`、`退出进程`）。编译器之参书 `--目标系统 轩窗`，所成者 PE32+ 之可执行文件：AMD64 之版定其基址（名义之址同 Linux），ARM64 之版位置无关（其布同 macOS），导入之表唯列 kernel32 之函数。

```sh
./豫构。林檎。豫行 构建 原生你好 轩窗入口 --输出 hello-x64.exe -j 24 -- --目标 本机 --目标系统 轩窗 --目标架构 兼容六十四
./豫构。林檎。豫行 构建 原生你好 轩窗入口 --输出 hello-arm64.exe -j 24 -- --目标 本机 --目标系统 轩窗 --目标架构 臂六十四
```

于轩窗行 `hello-x64.exe`（或于 ARM64 之机行 `hello-arm64.exe`），当出“你好”与所回之文，退出码七。CI 之“轩窗原生样例”二作业于 Linux 生此二文件，乃于轩窗 x64 与 ARM64 之运行器行而核之。

## 豫行之版

`豫行入口。底层。豫` 经平台之导入（`平台。底层接口。豫`：写字节、退出任务，即内核服务零与十八）逐字书“你好”一行，以退出码七终。所编之豫行行于豫言操作系统，服务之呼经码段首之服务门（[提案〇〇〇二一](../../../../提案/00021-豫行跨平台运行.汉语.md)）；宿主之启动器亦以之验收。

```sh
./豫构。林檎。豫行 构建 原生你好 豫行入口 --输出 原生你好豫行臂 -j 24 -- --目标 本机 --目标系统 豫言 --目标架构 臂六十四
```
