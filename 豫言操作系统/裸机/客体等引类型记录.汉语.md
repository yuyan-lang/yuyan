# 客体等值引用类型记录

客体类型索引原来只接受 `i32`（`0x7f`）与 `funcref`（`0x70`）。普通豫言的最小 Wasm 模块从第一个函数类型起就使用 `eqref`（`0x6d`），因此此前无法保留其签名信息。

索引器现在识别函数参数和单个结果中的 `eqref`。每个类型原有的 16 字节记录继续保存参数数、结果数和结果类型；参数位图低 16 位仍标记 `funcref`，高 16 位标记 `eqref`，所以同一参数不会被误读为 `i32` 或 `funcref`。结果字段保留 `0x6d`。索引器发现 `eqref` 后会在完成类型段读取时返回“不支持”（`-2`）；这是一道执行许可边界，后续验证器和值栈未支持 GC 前不得放行。

裸机夹具以含两个函数类型的标准 Wasm 字节流验证：第一个类型参数为 `eqref`，第二个类型结果为 `eqref`。它直接检查位图值 `65536`、结果类型 `109`、拒绝返回码以及错误状态；随后重载普通 `i32` 模块，确认拒绝状态清零。ARM64 与 AMD64 共 368 项 QEMU 验收均通过，产物位于 `/tmp/yy裸机验证.hhWnqo`。真实普通豫言最小模块仍经 Shell 文件路径装载后以 `-2` 拒绝，未运行主体。

下一步是让客体类型表表示 `struct`、`array`、递归组、具体引用及子类型关系，再把 `eqref` 的类型标签传至操作数栈、局部、全局与 GC 堆。`i31` 编码函数已经单独验证，但尚未接进这些路径；本阶段不能称作 WasmGC 执行支持。
