# 客体对象堆自动回收

用户态 Wasm 执行器的结构体和数组分配现在先尝试对象堆；容量不足时自动扫描客体当前值栈与活动局部帧，从中筛选经对象堆核验的活句柄，标记可达对象、清扫其余对象，再重试分配一次。执行中的客体不必手工指定根。扫描读取当前栈长度与局部帧占用量，不把已退出帧或已弹出的值当作根。

目前运行时值槽尚无完整引用类型标签，因此根扫描是保守的：某个整数恰好等于活句柄时，可能多留一个对象，但不会据此释放活对象。全局槽的根扫描现已接入；`eqref` 等 GC 引用全局的类型、初值与执行仍未接通。复合对象中的引用字段及完整普通豫言模块尚未接入；现已可执行的结构体和数组字段仍限纯 `i32`。标记器尚有 128 层递归上限，自由块目前按等容量复用，不能将不同尺寸的空闲块合并。

压测客体是独立标准有效的 WasmGC 模块：它将一个数组引用留在值栈上，再循环创建并丢弃 5,500 个数组，超出当前堆可容纳的对象数。结束时读取保留数组的值 42，并加上实际循环次数，结果必须为 5,542；未触发回收、误删活对象或跳过循环均不能通过。标准引擎也返回 5,542。最终 ARM64、AMD64 QEMU 连同旧场景共 368 项全过，产物与日志在 `/tmp/yy裸机验证.9EiA1s`；三级自举产物一致，编译器入口类型检查通过。

## 全局值作为 GC 根

回收前现遍历最多 128 个客体全局值槽，并使用对象堆的句柄核验来筛出存活对象；宽整数或其他整数偶然等于活句柄只会造成保守保留。新增裸机专项测试先把唯一对象句柄放入全局槽，执行回收后要求句柄仍有效；清空全局槽再回收，要求句柄失效，防止“永不释放”冒充正确。ARM64 与 AMD64 连同旧场景共 368 项通过，产物在 `/tmp/yy裸机验证.NuPFfq`。该测试直接检验根扫描，尚不代表 WasmGC 全局声明、常量表达式和 `global.get/set` 已全部支持。
