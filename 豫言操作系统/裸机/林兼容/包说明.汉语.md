# 林兼容

进程域中的等待按保留的成员记录翻译退出进程号，直到父进程回收内核句柄。信号目标反查只匹配活成员。

`窗口沙箱` 是第八步的真实浏览器验收入口：初始用户与组号为 1000，默认参数保留 Wayland、软件绘制和测试页，Chrome 使用默认沙箱。辅助向量的真实与有效用户、组号取自当前身份。`窗口验收盘 架构 林根目录 输出目录 沙箱` 选择此入口；三参数用法沿用第六步入口。沙箱验收须核对真实页面和隔离行为。

用户与组身份转换先核验旧身份，全部通过后写入；普通进程只可选已有的真实、有效或保存身份。`setuid`、`setgid` 在特权身份下同时更换三身份，降权后只改有效身份；`setreuid`、`setregid` 按真实与有效身份的变更同步保存身份。永久丢弃零身份后恢复零身份返回 EPERM。独立能力、用户命名空间映射及文件权限核验继续实施。

第八步的经典过滤器位于 `过滤。底层。豫`。`过滤校验` 接收兼容层私有的八字节指令数组、指令数及工作区，返回零为有效、二十二为无效；指令数为 1 至 4096，工作区至少为指令数乘四字节。校验读取指令码、数据偏移与跳转目标，并交汇所有前驱的暂存初始化掩码，拒绝分支绕过写入后的读取。末尾须返回，跳转向前且落在数组内。

`过滤执行` 接收已校验且保持不变的程序、指令数、六十四字节调用快照、六十四字节暂存区，返回完整三十二位动作。调用快照按程序架构记录原始系统调用号、审计架构、指令地址和六个六十四位参数。支持三十二位绝对加载、立即数、十六字暂存、长度、算术、条件跳转、返回及累加器与索引寄存器转移；动态除零返回杀线程动作。调用方负责有效地址、容量和各缓冲互不重叠。

`沙箱。底层。豫` 接入 `seccomp` 和 `prctl`：禁止提权标记只增不减，安装前复制并校验过滤程序；线程克隆、进程复制与换程序保留策略。线程组同步先核对所有活线程的过滤链，再统一发布；分歧返回线程号，带同步错误标志时返回 ESRCH。每次调用先以原始调用号执行过滤链，再翻译架构调用号；叠加时采用优先级最严格的动作，同级采用最新数据。支持错误返回、允许、跟踪缺席、杀线程、杀进程和带调用元数据的 SIGSYS；严格模式仅允许读、写、线程退出与信号返回。

线程表尾偏移 48、56、60 分别保存私有过滤链、禁止提权标记及模式。过滤程序复制后保持不可变。双架构 QEMU 自检覆盖安装、私有复制、继承、同步、调用拦截与信号元数据。真实 Linux ELF、命名空间及去掉 `--no-sandbox` 的 Chrome 验收继续实施；过滤结点回收、映射权限细查及信号终止的等待状态编码列为后续事项。

KVM 桌面验收把启动盘、日志、截图放在磁盘上的独立目录，并将 `TMPDIR` 指向同目录下的临时目录，QEMU 快照沿用此环境。按宿主余量预留临时存储空间。

前台表面全部卸下时清除显示面的旧像素；跟踪日志记录前台表面号与映射数量。恢复后窗像素列为后续事项。

顶层窗口按首次带缓冲提交的顺序映射到同一个豫言显示面，最新映射的窗口取得键盘焦点。重绘保持前台窗口和焦点；销毁或卸下前台表面时回到下一个已映射窗口。多窗口布局、鼠标选窗和对象号复用代次留待后续。跟踪模式输出窗口名称和已提交缓冲的尺寸，供真实程序验收定位。

启动块沿用通用客体的八兆参数区，后接六十四千字节程序名区；环境、当前目录与显示授权按程序名区内的对应偏移读取。兼容层把启动块保存在 64–80 MiB，避开描述符路径和窗口服务缓冲。键盘每十个滴答检查一次，使用下一滴答作为此次检查的截止期。

桌面验收有「林终端」与「林浏览器」两个入口，共用「运行」中的启动、装载和受限线程逻辑。空参数且获授显示面时，终端运行 foot，浏览器运行 Chromium 并选择 Wayland、软件绘制与本地测试页；显式参数使用原命令行用法。第六步浏览器使用 `--no-sandbox`，沙箱验收在第八步启用。

窗口显示桥复用提案 00014 的子程序显示代办协议。豫言桌面授予显示面，兼容层经初始任务提交画面、获取尺寸和输入事件。`窗口自检` 入口可构建为两架构的豫行程序，供桌面中的画面与按键回传验收。

Wayland 服务由兼容层启动进程轮询，监听 `/tmp/wayland-0`，通过现有 Unix 管道与林程序通信。服务处理全局查询、同步、共享内存缓冲和窗口表面的配置与提交。桌面以空参数启动兼容层时运行 `/林/根` 中的 foot。ARM64 与 AMD64 已通过 foot 输入命令及 Chromium 窗口显示本地页面的验收。林根工具的 `窗口验收盘 架构 林根目录 输出目录` 入口统一构建原生预置和图形启动盘。

伪终端主从端复用双向共享管道，`/dev/ptmx` 创建主端，`/dev/pts/终端号` 打开从端。两端共享终端属性、窗口尺寸与前台进程组，描述符复制和关闭沿用管道端引用机制。XKB 映射通过内存文件传给 Wayland 客户端，桌面的基本按键转换成键盘事件。规范行编辑、修饰掩码和输入法列为后续事项。

桌面的指针移动、按下和抬起转交给前台表面的 Wayland 指针对象；坐标转换为八位小数，键号转换为左、中、右按钮。切换表面时先交离开，再交进入。滚轮和跨客户的离开事件留待后续。

消息式套接字的消息队列每条管道容纳 512 条，逐条记录发送者进程号，接收凭据随所收消息交付。队满时阻塞发送等待，非阻塞发送返回 EAGAIN。

消息式套接字的多段发送缓冲合成一条消息，多段接收缓冲从同一条消息依次填入。中转缓冲由本进程复用。截断消息的标志留待后续版本。

接收控制消息使用本次管道读取的发送者和结束位置。这些值在管道锁内存入接收进程自身，控制消息交付保持本次读取的范围。

发送控制描述符与消息数据共用一次管道锁定，先检查数据空间；等待重试时保留尚未发布的控制消息。多个描述符部分发布后发生错误时的回滚留待后续版本。

林兼容层（[提案 00012](../../../提案/00012-兼容林纳克斯程序与驱动.汉语.md)）：在豫言操作系统上原样运行林纳克斯（Linux）程序。

- 兼容层是底层模式的普通豫言程序，由编译器直出豫行文件（`豫构 构建 林兼容 --输出 yy林兼容 -j 24 -- --目标 本机 --目标系统 豫言 --目标架构 兼容六十四`，ARM64 把末项换成 `臂六十四`；不写 `--目标架构` 时按构建机的架构出，在 ARM 机器上造 AMD64 的盘要写明；编译器的 `--符号表 文件` 另写函数符号表），作为普通的子程序由命令壳启动：`「运行」于『/林/林兼容』于「列」【[『--根』，『林根目录』，][『--跟踪』，]『林程序路径』，『参数』…】`。`--根` 给出林根（林程序看到的 `/`）在豫言文件系统里的位置；`--跟踪` 让每个系统调用打印一行（线程号、号、参数与结果，带路径的调用还印出路径），林程序的异常也打印出来（向量、错误码、故障址、程序计数），用来与 strace 对照。
- 林程序的机器码直接在处理器上运行：兼容层用内核的通用机制「受限模式」（服务 48 进入受限）运行它，林程序执行系统调用指令或出故障时，内核把它的寄存器交回兼容层；兼容层按 Linux 的语义办完，再进入受限。内核不认识 Linux 的系统调用号。
- Linux 的语义（系统调用号、errno、文件描述符号、fork、信号、`/proc` 等）只写在本包里；豫言内核、接口包与标准库都不依赖本包。
- 林程序的文件由豫言的底层文件接口提供（经底层转送请初始任务办理，见 `转送`；提案 00021 第 11 步），兼容层只做翻译：路径解析（当前目录、`.`、`..`、符号链接）、文件描述符表、stat/statx、getdents64、readlink，以及建、写、截断、删除、建目录、改名（普通文件）、建符号链接（symlink、symlinkat）、改模式（chmod、fchmodat；mkdir 的模式位去掉掩码 022 后写进去）。flock 照收不管。连续的写先攒在 64 MiB 的待写缓冲里（同一描述符、位置相接），别的系统调用开始前先写出去。
- 进程与管道：fork/vfork/clone（不带 CLONE_THREAD）用内核服务 49 克隆任务，execve 在原任务里换程序（含 `#!` 脚本；路径 /proc/self/exe 换成当前程序；参数与环境拷好后把旧程序的内存块交还内核），wait4 查子任务状态；waitid 支持 P_ALL、P_PID、WEXITED、WNOHANG 和 WNOWAIT，按当前进程号域填写退出信息，用户号取分叉时的真实身份。停止与继续状态、进程组、进程描述符、退出用量和子进程变更身份后的用户号更新留待后续。管道放在线性内存 3 GiB 起的共享区（内核服务 51 共享区段，兼容层一启动就建好），fork 出的进程映同一批物理块。
- 管道共享区容量为 768 MiB；每条管道有 800 格待传控制描述符，供 Chromium 启动阶段集中传递句柄。内存文件块表位于共享区 256 MiB 起，各对象块号表容量为 65520 项，支持 foot 原样申请的 512 MiB 画面内存文件。
- 内存：林程序的地址空间就是兼容层线性内存平移 1 TiB；mmap 可映文件（读入内容，私有映射）。链接在 0x400000 的非位置无关程序（如 Debian 的 python3.11）放进低区：内核服务 52 低区映射把兼容层动态区的 14 块另映到 0x400000–0x1FFFFFF，兼容层经动态区那一处读写。
- 底层请求：初始任务的邮箱只存一条消息，几个林进程同时请求时消息可能被拒，兼容层小睡后重发。
- 线程：clone 带 CLONE_THREAD 建线程，同一进程的各线程在一个豫言任务里轮流运行（多对一）；futex（等、醒、移、醒兼运算）在兼容层里办，会阻塞的系统调用返回“需等”由主循环换线程、稍后重办；内核在时钟轮转时让受限执行退出（原因 3），兼容层借此在线程间轮换。
- 信号：sigaction、sigprocmask、sigaltstack、kill（自己与子进程）、tgkill、alarm、setitimer、POSIX 计时器（一个）、sigsuspend、pause、sigtimedwait、rt_sigreturn；线程运行前投能投的信号，在线程栈（或备用栈）上建与 Linux 同布局的信号帧（x86-64、ARM64），阻塞中的系统调用按 SA_RESTART 重做或得 EINTR；子进程结束时给父进程记 SIGCHLD；林程序的异常有处理函数时转成 SIGSEGV 等信号。
- /proc 与 /sys：兼容层按字面生成，不经文件服务：meminfo、cpuinfo、stat、uptime、mounts、self 下的 stat、status、maps、cmdline、environ、comm、fd、task（task/线程号只在线程活着时存在，task 目录的链接数是 2 加线程数）、exe、cwd，sys/kernel 与 sys/vm 的常见项，/sys 的处理器在线表等。
  内存文件可以经 `/proc/self/fd/N` 重开，同一对象使用新访问标志和独立偏移，支持 Chromium 取得只读共享内存描述符。
- 共享映射：MAP_SHARED 从线性 64 GiB 起的共享区分（内核服务 51 标共享），fork 出的进程看到同一块内存。
- 内存文件（memfd_create，描述符种类 16）：对象表在管道共享区，一棵进程树共见；内容在物理块里（内核服务 55 区段物块要块、56 映物块映块），描述符经套接字传给别的进程后两边读写同一份；每次 mmap(MAP_SHARED) 映到新地址。memfd_create 与 eventfd2 遇到不认识的标志位返回 EINVAL（Chromium 用它探测内核）。/dev/shm 是兼容层里的内存文件系统（同林纳克斯的 tmpfs）：其中的文件就是内存文件对象，按名登记在管道共享区，同名再打开得同一对象，unlink 只去掉名字；Chromium 的共享内存就建在这里。fallocate 对内存文件生效。
- 大程序的只读段共享：32 MiB 以上的位置无关主程序（如 279 MB 的 Chromium）装好后，只读段里整 2 MiB 的块标成共享块（内核服务 55），块号记在管道共享区的映像缓存里；fork 时映给子进程而不复制，别的进程再装同一个文件时改映这些块（服务 56，逐字节比对文件内容）。十几个 Chromium 进程只占一份程序的内存。
- 内存保护与退还：mprotect 去掉写权限的区间记进不可写区段表，prlimit 往这里写返回 EFAULT（Chromium 的 ProtectedMemory 这样验证只读）；madvise 的 MADV_DONTNEED、MADV_REMOVE 把私有区间清零，整 2 MiB 的块交还内核（PartitionAlloc 与 glibc 退还内存后认定再读到的是零）。
- futex 的优先级继承锁（LOCK_PI、UNLOCK_PI、TRYLOCK_PI）：锁字记持有者的线程号，抢不到时置“有等者”位、稍后重办。
- 多路等待与事件描述符：poll、ppoll、select、pselect6、epoll（水平触发）、eventfd（计数放在管道共享区，经 fork 或套接字传给别的进程后两边共用）、timerfd；等不到时返回“需等”，由主循环稍后重办。
- Unix 套接字：socketpair、socket、bind、listen、connect、accept、accept4、shutdown、send、recv、sendto、recvfrom、sendmsg、recvmsg（SCM_RIGHTS 传描述符）、getsockname、getpeername、getsockopt、setsockopt；连上的流套接字是共享区里的一对管道，SOCK_SEQPACKET 也是，只是保持消息边界（一次写一整条，一次读一条，读不完的截掉）；setsockopt 设了 SO_PASSCRED 的一端，recvmsg 附 SCM_CREDENTIALS（发送进程的进程号，用户与组都是 0；Chromium 的 zygote 靠它认出子进程），getsockopt SO_PASSCRED 读回设定；监听者记在共享区的登记表里（路径与抽象名都可以），fork 出的进程也连得上。写到没有读端的管道或套接字时发 SIGPIPE（MSG_NOSIGNAL 不发）。
- mremap：缩小原地办，变大时（MREMAP_MAYMOVE）新分一块并拷过去。
- IPv4 套接字（描述符种类 15）：TCP 与 UDP 的 socket、bind、listen、connect（非阻塞得 EINPROGRESS，阻塞的等连好）、accept、send/recv、sendto/recvfrom、sendmsg/recvmsg、sendmmsg/recvmmsg、shutdown、getsockname/getpeername、getsockopt（SO_ERROR 等），poll/epoll 可等；协议栈在初始任务的执行器里（网卡经内核服务 61–63，内核先用原生网卡驱动，见客体二号），兼容层经底层转送请它办（底层网络的监听、连接、接受、数据报与套接字地址，底层句柄的读写、等待与关闭），同一套接字被 fork 后几个进程共持时按引用数关闭。fork 出的子进程使用父进程建的套接字（初始任务按属主核对句柄）留待后续版本。地址按 QEMU 用户网络静态配置（本机 10.0.2.15，网关 10.0.2.2，域名服务 10.0.2.3），127.0.0.1 走环回。AF_INET6 返回 EAFNOSUPPORT（程序退回 IPv4）。
- kill 给子进程：SIGKILL 直接终止任务，其余信号投进共享区的信箱，子进程在信号收集里取走、按处置办；ioctl 的 FIONBIO、FIOCLEX、FIONCLEX 对任何描述符都行；开机的 0、1、2 以读写方式打开（libuv 按 F_GETFL 判断能不能写）。
- 子包「林根工具」（`yy林根 解包 林根目录 档案…`）把林纳克斯根文件系统的 tar 档（可以是 Docker 镜像的几层）解成林根目录，`yy豫言系统 启动盘 --林根 盘内目录=林根目录` 把它造进数据盘。

用户域由兼容层保存身份映射和能力。创建用户域后，身份先显示溢出号；一次写入自身的一项映射后，身份转换为域内号。组映射须先禁止附加组。映射重复写入返回 EPERM。能力可以丢弃，恢复已丢弃的能力返回 EPERM。嵌套用户域继承附加组禁用约束。多项映射、同域多进程共享状态及其他命名空间隔离留待后续。

`/proc/self/ns/user` 是当前用户域的身份链接，读链接返回 `user:[域号]`。新建域取得新号，分叉继承原号；状态查询返回相应节点号。只读打开保留当时域身份，后续创建新域保持旧描述符身份。命名空间描述符的读写返回 EINVAL。进程树共享区头部偏移八保存域号原子计数。其他进程的域路径、域描述符重新接入与设备号细化留待后续。

进程号域由兼容层维护共享成员表与祖域编号。`clone` 创建新域的首进程号为一；`unshare` 的进程号域影响下一次分叉，当前进程保留原域。查询自身、父进程、线程号、等待返回、信号目标与消息凭据中的进程号按观察者域翻译，域外目标返回 ESRCH。域首进程退出后标记域失活并终止登记的后代；再次分叉返回 ENOMEM。父子重复发布同一分叉记录保留退出状态。`/proc/self/ns/pid` 提供域身份链接与只读描述符。孤儿收养、进程组、任意同域进程的信号权限与域描述符重新接入列为后续事项。

## 分叉的文件系统状态

带共享文件系统旗的克隆共用根目录及当前目录状态，普通分叉取得独立副本。改目录、按当前目录解析路径、取当前目录及进程目录链接共用这一状态。状态放在兼容层已有共享区，使用独立锁；内核继续提供通用任务克隆与共享内存机制。

`chroot` 要求当前用户域的改根能力。绝对路径与绝对符号链接从新根起步，`..` 在新根停下；当前目录及预开目录描述符保留原路径锚点。`getcwd` 返回相对于新根的路径，当前目录在根外时返回 ENOENT。`/proc/self/fdinfo` 列出在用描述符的普通文件项；作为新根时绑定原进程对象的物理任务号及出生代次，主人退出或任务号复用后打开返回 ESRCH、旧目录描述符读取返回 ENOENT。虚拟进程目录的状态由已打开对象提供。
