# 用户态设备寄存器与驱动镜像

2026-09-22：两架构完整回归共 268 项通过，包含六项新增寄存器用例；类型检查及六个标准 Wasm 产物的独立格式验证通过。命令行生成的两架构镜像与自动验收产物逐字节一致。

新增“设备驱动”构建方式。它为根任务的一块固定线性内存建立 IOMMU 映射，再将经过验证的 Virtio 寄存器窗口授权给这个任务。设备协议由用户程序执行；内核只管理设备资源及访问边界。

## 接口

| 平台导入 | 参数 | 返回 |
| --- | --- | --- |
| 设备寄存器读 | 编码地址 | 读取值，拒绝时为 -1 |
| 设备寄存器写 | 编码地址、值 | 成功为 0，拒绝为 -1 |

编码地址的高十六位为访问宽度，必须是 1、2 或 4 字节；低十六位为窗口内偏移。窗口长度为 `0x4000`，地址必须自然对齐。例如，字节方式读取公共配置的设备状态使用 `(1 << 16) | 20`。两接口的参数与结果均为标准 Wasm 的 i32。读取值本身可能也是全一，调用者应结合寄存器语义判断。

所有访问都先核对当前任务和内核授权标志。默认镜像没有授权；复制出来的子任务不继承授权。窗口固定为物理 `0x10000000` 的 BAR4，不能提交任意物理地址，PCI 配置写入、IOMMU 控制寄存器以及 MSI-X 表均不在接口内。访问前后设置内存屏障。

## 初始化约束

当前支持 QEMU 的现代 Virtio 块设备，PCI 地址为 `00:04.0`。内核先确认设备标识并关闭总线主控，再遍历最多四十八项 PCI 能力；验证对齐、范围及公共配置位置。要求公共配置在 BAR4、偏移零、长度四 KiB。已开启 MSI 或 MSI-X 的设备被拒绝，MSI-X 表及待决位数组也不能位于 BAR4。

BAR4/5 必须是十六 KiB 的六十四位可预取内存窗口，尺寸探测及最终地址都要读回核对。内核设置窗口、复位设备并等候完成；只有在 IOMMU 映射建立之后才开启总线主控和用户访问标志。传统中断保持屏蔽。本步骤不宣称已实现中断重映射。

用户模块必须恰有一块固定大小的 Wasm 内存，最小值等于最大值，范围一至八页。设备地址从 `0x1000` 开始映射这块根任务内存。物理页表、能力判断和映射控制由内核持有。此初始化只适用于首次启动，不是活跃设备的重置或转授接口。

## 使用与验收

```sh
./yy豫言裸机 臂六十四 用户模块.wasm 输出.elf 设备驱动
./yy豫言裸机 兼容六十四 用户模块.wasm 输出.img 设备驱动
```

运行须使用项目的 IOMMU 模拟平台参数和现代 Virtio 磁盘参数，详设备地址隔离实施文档。普通模块仍使用默认“运行”方式。

用户态用例执行真实设备复位状态检查、状态写入、版本一及平台地址翻译特性协商、队列选择和队列大小读写。另行检查非法宽度、越界、未对齐、默认无授权和复制任务无权限；子任务试图复位设备后，父任务再次核对状态未变。错误特性期望是必须失败的负对照。

这一步尚未向 Virtio 队列提交磁盘读写请求，也未完成在途取消、设备转授、退出清理、持久化文件系统和通用任务池。实际结果见验证记录。

接口依据 [Virtio 1.2 规范](https://docs.oasis-open.org/virtio/virtio/v1.2/virtio-v1.2.html)；受支持的窗口布局参照 [QEMU Virtio PCI 实现](https://github.com/qemu/qemu/blob/master/hw/virtio/virtio-pci.c)，并由客体启动时检查。没有把外部实现引入客体。
