# 象胥

象胥（二进制翻译器）把兼容六十四（x86-64）机器码翻译成臂六十四（ARM64）机器码，让臂六十四的豫言系统原样跑兼容六十四的林纳与轩窗程序。名字取自《周礼·秋官》的象胥：掌管四方使者、传译言语的官。

## 做法

- 装程序时整体翻译：把程序的代码段按控制流解成指令，提升成带类型的操作，由象胥自带的臂六十四编码器直接出机器码，缓存在盘上。译出的码钉住兼容六十四的寄存器、用客体自己的栈，所以不经冶铸（原生后端）的降级。
- 运行时才生成的代码（即时编译器、自修改代码）另走即时翻译，按基本块翻译并缓存。
- 寄存器固定对应：兼容六十四的十六个通用寄存器各占一个臂六十四寄存器。
- 标志位按需计算，臂六十四有 FlagM、FlagM2 扩展时直接用。
- 内存次序：多线程程序的访存用 LDAPR、STLR 保持兼容六十四的强序，单线程程序用普通访存；林檎芯片的硬件强序开关作为可选的加速。
- 向量指令：SSE 译成 NEON；处理器识别（CPUID）报的向量特性到 SSE4.2 为止。
- 翻译后的程序在林兼容与轩窗兼容（蕃坊）里跑，系统调用照原样交兼容层。

## 已有

- **兼式**：兼容六十四指令的带类型表示。寄存器、操作宽、寻址的基与比例、存储元（连同 FS、GS 段前缀）、前缀、拓展前缀、编码种类与码表各有自己的类型；解码失败的缘由是「辨误」（截断、过长、无此令）。
- **码读**：按字节读机器码的游标，记着段首令址；签名把码流、指令起点与读到的位置藏起来，模块外只拿得到字节、令址与指令长度。一条指令读满十五字节报过长，码流读完报截断。
- **令址**：兼容六十四指令虚拟地址的抽象类型，整数只在边界进出。
- **兼辨**：指令解码器。`「辨兼令」于 码读` 得 `「成否」于（「兼令」合「码读」）于「辨误」`。认旧式前缀、拓展前缀（REX）、单字节与二三字节码表、向量扩展（VEX）与广向量扩展（EVEX），解 ModRM、SIB、位移与立即数，算操作宽与长度；段前缀记进存储元的地址。
- **流式、兼流**：控制流发现。`「寻块」` 从入口按直接转移与调用找全可达指令，切成基本块：调用与条件转移的下一条也是块首，解不出的地址成空块，转到段外的目标另记。切块尾递归，十万块也不加深调用栈。
- **兼作、兼义**：语义提升。`「义于令」` 把整数指令提升成带类型的操作「兼作」：三十二、六十四位与八、十六位的传送、算术逻辑、比较、测试、增减、取负取反、移位（立即数与按 CL）、乘、条件传送与置位、XCHG、推弹、扩展、FS 段取址、CPUID、RDTSC 与 syscall；暂不译的带缘由（高八位寄存器 AH 类、带进位的加减、单操作数乘除、循环移位、GS 段、SSE 与向量扩展等）。
- **标集、兼标**：标志活性。`「义图于」` 每条指令只提升一次，每块归成“生、杀”两集与后继下标，按块下标倒序迭代到不动点，求出每条操作之后还要用的标志；调用、间接转移、返回与停按调用约定当标志全死。
- **臂式、臂编**：带类型的臂六十四编码器，抽象的「臂字」只能由编码函数造出；立即数放不进时返回可无。
- **译式、兼译**：直译。`「译图」` 把义图逐块逐条译成臂六十四机器码，交出机器码、各块入口的偏移与没能翻译的指令。约定：通用寄存器按编码号放在 x0 至 x15；令址都按模块内地址算，运行时加基址寄存器 x23（林兼容设成模块的装入基址，固定地址程序为零），同一份译码装在哪里都能用；标志在 NZCV，块边界上 C 等于进位之反，只算之后要用的；八位、十六位操作把操作数左移到三十二位顶端再做带标志的运算，结果用 BFI 插回低位；FS 段取址读 TPIDR_EL0 加上；syscall 译成 SVC #0x86，CPUID 译成 SVC #0x88，RDTSC 译成 SVC #0x89；间接转移与返回把目标放进 x16，经 SVC #0x87 请林兼容查表转去。两遍汇编，够不着的条件转移展开成“反条件跳过一条加 B”，反复排到不再变。
- **兼程**：整个程序的翻译。`「译精灵」` 析兼容六十四的精灵（固定地址或位置无关的程序、共享库、动态链接器）：程序头、符号表、动态符号表、RELA 重定位与异常帧索引；以入口、有定义的函数与间接函数符号、RELATIVE 与 IRELATIVE 重定位的加数、异常帧索引里的函数起址、数据段里指向代码段的指针为根找块，再补上指令里程计相对取址的目标、以它为表址的程计相对跳转表各项与落在代码段里的立即数（位置无关的不收立即数）找一遍，逐段直译后首尾相接，写成译码文件（第二版）：文件头七个八字节（魔数“XIANGXU1”、版本二、入口的译码偏移（没有入口为负一）、码长、入口项数、模起、模止），接着是臂六十四码，再是按模块内地址排好的入口表（地址、译码偏移各八字节）。同时交出段数、码长、入口项数与没能翻译的指令（「兼程译果」）。`「兼卷散」` 是文件内容的六十四位 FNV-1a 散列，`「译码名」` 按它与文件长给译码缓存命名；`「兼依」` 读出解释器路径、DT_NEEDED 与库搜索目录。

## 接入林兼容

- 林兼容以 `--兼译 译码目录` 起动时认兼容六十四精灵：各段照常装到原址只当数据；装程序（起动与 execve）以后按主程序与解释器（ld-linux）的内容散列在译码目录里找到译码，映进林程序的地址空间、记进兼模表，起点换成入口的译码、x23 设成起点所在模块的基址；动态链接器以可执行权限映射共享库时同样按内容登记。SVC #0x86 按兼容六十四的林纳系统调用号办，SVC #0x87 按 x16 找到所在模块、在它的入口表里二分查到译码再接着跑（x23 换成那个模块的基址），查不到印出目标地址后当异常报出；SVC #0x88 答 CPUID（固定基线：SSE2，不报 AVX），SVC #0x89 答时间戳计数。林程序出异常时另印出事处所在模块与块的兼容六十四地址。
- 蕃坊在臂六十四主机上遇到兼容六十四的林纳程序时，先在坊的林根里找全要装的模块（程序本身、解释器与 DT_NEEDED 共享库；林根里的绝对符号链接读不到时按文件名在默认库目录里找），逐个备好译码（缓存在 `/tmp/象胥译码/`，按内容散列与文件长命名，删了下次重译），再交林兼容加 `--兼译 /tmp/象胥译码` 运行。
- 壳命令 `「传译」于「路径」曰『程序』`（可加 `于「根」曰『林根』`，连同解释器与共享库一起）重新翻译，每个模块印一行（段数、码长、入口项数、未译数与译码路径），再把没能翻译的指令按缘由归并列出。
- 开发用的量具 `测试/兼程量。测试。豫`：编成清单后在虚机里「行」，参数是精灵路径，逐个翻译并印用时与未译归并；开头写 `--写 目录` 时把译码按内容命名写进那个目录，不必等壳的前导重编。

## 现状

- 静态的固定地址与位置无关小程序端到端跑通。Debian amd64 的 /bin/true 能装、能找全 ld-linux 与 libc 并开始执行，停在 ld-linux 一开头的 SSE2 指令上。libc（一兆九）翻译约十五秒（虚机里单线程）。

## 后续版本

- SSE2 转 NEON（传送、整数逐道运算、比较、PMOVMSKB、拆并与洗牌、移位），标量浮点与转换，x87 少量。
- 高八位寄存器、带进位的加减、单操作数乘除、循环移位、BT 族、BSF/BSR/TZCNT/LZCNT/POPCNT、CMPXCHG/XADD、REP 串操作、奇偶标志。
- 信号处理函数在兼译模式下查表进入；即时翻译兜底；多线程的内存次序；查表改成客体里的散列表。
- 广向量扩展的压缩位移、码表四（APX）与 REX2，控制寄存器传送的特殊长度。

## 测试

- `测试/兼辨。测试。豫`：llvm-mc 生成的编码逐条核对长度与各字段，并核对三种报错。
- `测试/兼流。测试。豫`：两段代码的基本块、块尾与段外目标。
- `测试/兼义。测试。豫`：四十多条指令的提升（含字节式、XCHG、按 CL 移位、FS 与 GS 段）与两段代码的活标志。
- `测试/臂编。测试。豫`：一百零四条臂六十四指令字与 llvm-mc 比较，另核放不进的情形。
- `测试/兼译。测试。豫`：三段代码的译码（第三段是字节操作、XCHG、按 CL 移位、FS 取址与十六位存），期望值经 llvm-mc 反汇编逐条核过。
- `测试/兼程。测试。豫`：一个兼容六十四小程序的固定地址与位置无关两版整个翻译，核对第二版文件头、模块范围、码长与项数、入口偏移与入口表。
