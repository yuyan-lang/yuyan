# 裸机后端

Linux 原生导入表供 `映射内存`（mmap）之绑，用旧六参导入桩。址为用户绝对址，长、护、旗、柄、文件偏移皆以整数传之；返用户绝对址或错码。今绑用于低四吉共享物页，长址及长文件偏移列于后续之事。

自有引导之 ISO 9660 目录记录，调用磁盘格式库之定时记录编码，存定扇区之址、长、二〇二六年十月七日之期及原名之字。引导表与诸模之布皆仍旧值，正式造盘与公共库共此编码。`公共光盘接线。测试。豫` 以独立字节之列校正式之包装函数。

预编二之内联游程分配，以六十四位之算求候选末址而比游限，四字节引用之构存逾四吉之进位。所请逾游限者入执行器之慢途。`游程进位。测试。豫` 以压缩崩溃之界值，验两引用宽、适及界与界内之配。

臂六十四开机之大段，虚实皆自 `0x50000000` 起，独居六十四兆。动态物理块之池，自 `0x44000000` 起，凡一百二十八兆，位图六十四位；每任务限六十四兆，二任务各可同时满其域。系统之器模拟臂，取内存五百一十二兆。ELF 内存段之长随载荷而增。十五兆载荷、二任务页表之构及父子十八块隔离之例，随源码授 CI 行之。

系统库调用桩生苹果臂六十四内调块之机器码。块携全宽函址、八整槽、八浮槽、五百十二字节栈参及整浮果槽；呼前存线性存之长与返址，呼后复之。苹果原生函数表复用系统之 dlsym、malloc、free、posix_memalign、memset 与 memcpy；内调块则行自生之桩。相关系统库之试，付苹果 CI 以同客体双端核之。

`自有引导` 生启盘之引导之程与镜像之构（二〇二六年十月七日）：BIOS 之 MBR 与第二级（实模式读盘、E820、VBE、Multiboot 一之信、切保护模式），UEFI 之 `BOOTX64.EFI`（PE32+：觅盘、读内核与诸模、GOP、退启动之务、归三十二位而入内核），一兆之 FAT12 EFI 分区映像，ISO 9660 与 El Torito，混合之 MBR。机器码书为十六进之字，跳、呼与取址用标号之片。UEFI 之引导之示为中文（二〇二六年十月十三日）：引导程序始呼嵌于程序之末之统一引导之模（包「底层统一引导」，底层豫言书之，两构共用），登简字体之包于固件之 HII 数据库（「统一引导用字」诸字之十六乘十九宽形），乃以 OutputString 出 UTF-16 之中文示；BIOS 之示亦中文（见「引导字模们」）。`豫言系统` 之「启动盘」以之书混合之 ISO，不用 Limine 与 xorriso。系统双槽（十月十四日）：BIOS 第二级于扇长五百十二时读第六扇之槽录以择槽（有试启槽则清之书回而启之，否则启主槽），读所择槽之引导表；BOOTX64、BOOTAA64 读盘首后呼统一引导之「选系统槽」行同事（呼固件由新内核原语「调用固件六」）。

`臂引导` 生臂之启盘（二〇二六年十月九日，ARM 硬件第七步）：UEFI 之 `BOOTAA64.EFI`（PE32+，机器号 0xAA64：觅带臂引导表之全盘，读内核诸段入缓冲，取内存表，退启动之务，关 MMU 与缓存，拷诸段于载址而入内核），臂引导之表（入口与至多十五段），惟含 UEFI 项之 El Torito 引导目录，臂混合之 ISO（光盘、U 盘两用）。PE 之包与 FAT12 分区映像用 `自有引导` 之「引导程序映像」「引导分区映像」。`豫言系统` 之「启动盘 --架构 臂六十四」以之书 `yy豫言启动臂.iso`。

`动态任务` 为兼容手写核心入共用豫言内核之至小入口，与 `内存管理` 合外置之模，链于 0x1A0000。调度、任务之建与装载之理，在两架构共用之豫言内核；开机程序与数据盘之器皆豫行文，共用段装载器装之。制见 [动态任务](../../文档/动态任务.文言.md) 与 [多核](../../文档/多核.文言.md)。

选盘之验（旧双超级块之规，二〇二六年十月初）：BIOS 择零号有效块、UEFI 择唯一号块有效之第三盘，皆越前之启动 ISO、校验坏盘；BIOS 正式读 final.txt，返 ExternalABI512。全类验、系统构、介质造皆过，确界见硬件里程碑；实体读写犹未验。二〇二六年十月十日起，识别之规改为 ext4 超级块（见下段），逐候选而探、败则让位之选盘流程守原样。

数据盘识别候选（二〇二六年十月十日起依 ext4）：唯读核候选数据区之扇区二（字节一千零二十四起，即 ext4 超级块之首五百一十二字节）：偏五十六之魔数为 0xEF53，偏二十四之块大小对数为二（块四千零九十六字节）；合则留候选，挂载由执行器之 ext4 文件系统为之（读超级块与组描述符表，日志非空则重放）。候选数据区之始先取零；不合者（启动 U 盘兼数据盘，其首为 ISO），于六十四兆之一至十六倍处各读一次扇区二而复核，所得之始记于 130060480，此后读写之扇号皆加之。诸始皆不合则使后器代，免五百一十二字节扇区之启动 ISO 阻数据盘。执行器不格式化数据盘，空盘以离线造盘之器造一空 ext4。新规之运行验（U 盘与启盘兼数据盘）犹待。

内联体存复己之等长守卫表；长异则返之无否则条件，唯于真支已返后之假支记等长，用映后局号。早返入边仍原入之实，外层求交则去单边假定；书相关局仍去其事实。公开 ABI、对象布局及展境之签仍旧。

旧内联样明列径呼实目标者，此呼可用样体长限六千；仍验共预算、深及异常之形。不合之呼仍旧径展之判，径自展仍限二层。样之 JSON 式及公开 ABI 仍旧。

有热点样之函，径自呼亦可展前二层，仍守六千字节共预算及深护；无样之函仍旧途，余径呼限仍旧。今候选之语义验与测速犹待毕。

`持久盘构造` 于离线造扩展文件系统（ext4）之数据盘镜像（二〇二六年十月十日，代 YYR1 双区追加日志之式）：块四千零九十六字，每组三万二千七百六十八块、四千零九十六节点，诸元数据聚于盘首，次为洁净之日志一千二十四块，次为目录与文件之块；时刻恒定，同参所造逐字节同，Linux 可径挂载。`按参数造持久盘`、`按参数造持久盘前段`（至末一已用块而止，后皆零）与 `目录树造盘参数` 名与参数之式如旧，容至少一万六千三百八十四扇（八兆）。又有以 U+0001 分字段之扩展之参（提案〇〇〇一二，造林根用之）：造符号链接（的短于六十字节则藏于节点）与带式之常文。`持久盘读取` 乃宿主侧至简之读器：按路径列目录、读文件（循区段树）、查位图与节点。`持久盘构造。测试。豫` 以中文之名、空文、恰一块与跨块之文、逾一块之目录、二百五十五字之名、逾四千零九十六块之文、二组与舍末组之容、多区段与叶块造盘，读回核其文与目录，兼核超级块、位图、块之归属、目录块之构与日志。二〇二六年十月十日复以 e2fsck 一点四二点一三（安卓模拟器所附）逐检试验所导整盘之镜像（至小之盘、二组、舍末组、多区段与叶块、真树）及以 `库/` 之树所造四吉容之前段，皆无一问题（退码零）；同境之 mke2fs 一点四七点二所造参考之镜，其超级块、日志、目录块与本造器逐域相合，惟可选之域（散列之种与版、默认挂载之选、s_flags、写入之量、s_overhead_clusters、s_mtime、节点创建之时）与块之布局异。

豫言裸机（`豫言操作系统/裸机/`）之后端库：臂（AArch64）与兼容（x86-64）二构之机器编码与汇编，寄存器与整数之降级（依目标之述生入口、导入之桩与内存增长之助，目标有裸机、Linux、macOS 与 Windows；macOS 与 Windows ARM64 位置无关），内核之任务、内存、设备与控台，系统镜像与持久盘之造，商用平台可执行文件之写（Linux 之链接格式静态可执行；苹果之马赫格式可执行、dyld 导入之槽之绑及其特设签名所用之散列二五六；视窗之 PE32+ 可执行与 kernel32 之导入表；豫言操作系统自有之豫行，见 `豫言操作系统/裸机/文档/豫行格式.文言.md`），数值之降（数值读取、数值豫汇、数值转译与数值之钩：底层新路所产之模以网页汇编之字或汇编树码（底层豫汇，执行器 yy执行器。树码 径读为数值模块）给之，其中之 i64、f32、f64、v128 与原子之令，转为宽函数与数值内在码，于二构展为浮点、NEON／SSE 与原子之令；兼之预编二书客之浮点为宽浮之内在，降为 SSE2 之令，见 `豫言操作系统/裸机/文档/数值降级.文言.md`），核之浮点与向量之境（浮点上下文），及裸机验证器所用诸例。旧为编译器核心之子目 `库/编译器核心/裸机后端`，二〇二六年九月二十七日别为独包；编译器不用之，改之不必重举。

## 籍与用

初客之嵌入，由 `系统构造` 共理：不逾 448 KiB 者置旧模块窗，逾者末段暂藏旧窗、余前段藏于被动段。启动之包先以标准 Wasm 令长内存，循序合抄两段于动态区始 `0xC0000`，乃呼旧启动，循 `状态主程序大` 之标。静态八页、栈、传参区与应用 ABI 守旧约。`测试/初始大客体。测试。豫` 已实装而调用包装入口，验窗界、先抄后呼旧入口、尾字、模块长与大程序标；新壳旧基线与固定合并基线 36aa076c4 之 BIOS/UEFI USB 输入之验已成，所及见《智能命令》。

豫行开机程序与工具嵌 `预编侧表` 所生之元数（第二版）：类型、函数、元素段、数据段、标签诸表于生时算而定址，导入、导出、表、线性内存、起始之函书为简录，全局初值书为自有之方，函签之值类型各一字。执行器开机径建诸表，不读网页汇编之编码，用户代码行编译器所生之机器码。原生可执行文（Mach-O、ELF、PE）共侧表之式，侧表逾四百四十八 KiB 则为尾块。

所有者曰豫言，版本暂定 0.1.0。此包为库，依标准库、编译器核心（网页汇编之核）与结森工具。用之者，豫言裸机之主包「豫言裸机」也。

内联样本之读器解普通 JSON 之客体摘要与原模呼处，摘要须合客体 SHA-256 乃用；不合者配置空。原生产物与系统构造用之，皆予空配置；自命令行指定内联样本之文，留待后续之版。转译器存表界与空引之验；有本模定义、同型号且可展之目标者，迟验签于守卫之退，合目标则由模块声明证其同型。无可用目标仍旧验序，引用呼仍旧途。

降级之缓（`机器片缓存`，提案 00007）：编译器之参曰 `--降级缓存 文件`。模有预编之客（出“预编起号”）者，执行器诸函依键缓其降毕而函内已连之机器片；键为编译器之版、执行器之摘要、目标与布局、执行器诸函之签，并本函之号、签、体与其所实用而随客而变者（表零之序、所呼客函之签、数据段描述之址）之 SHA-256。中则径用所缓之片列，未中乃降；有未中则降毕重书缓文。文末书终记，书而中断之文视为无缓。仓库目标依产物各存一份于 `.yybuild/降级缓存/`。

原生之产（`原生产物`，提案 00007 第三步）：「原生产物字节」以执行器（汇编树码 yy执行器。树码，亦可为网页汇编之字）与客体之豫汇之模预编二为原生可执行之文之字；全由豫汇（提案 00007 收尾）：转译、内联与原键径读豫汇之模（`预二豫汇`），侧表与原键之模材取唯含元数之编码（`回收模块元编码`），客之摘要与整产之缓键取客体之汇编树码，大客体交子进程亦书汇编树码；「写原生产物」依原生之目标书之而加执行之权：系统与构缺省取本机，编译器之 `--目标系统 苹果|视窗|林纳克斯|豫言`、`--目标架构 臂六十四|兼容六十四` 可别定之（目标系统为豫言而未书构者取兼容六十四；豫言操作系统书工具之布之豫行，加 `--开机程序` 则书启盘开机程序之布）。编译器 `--目标 本机` 于终链时呼之，诸原生之产皆由编译器自豫汇径出（提案 00007 收尾）。底层之程不带执行器：编译器于底层之程得 `--目标 本机`，则以「写底层原生产物」依原生之目标径降其模块之产而书之，`--符号表 文件` 另书函数之符号表。有降缓之径，则客函之机器码依内容而缓（降缓之径加 `.客`），全产依编译器之版、目标、执行器与客体之摘要而缓（降缓之径加 `.产物N`）。原生之程而客体之汇编树码逾七兆（约当网页汇编四兆）者，另起子进程（本程加 `--原生产物子进程`）生之，其堆新也。

单文件之合（`单文件合成`，提案〇〇〇二一第六步）：「合成单文件」合豫行于宿主启动器之可执行之文：Mach-O 插豫行与尾标于签名之前，改签名命令与 __LINKEDIT 之长，依旧签之标识与可行段长重算特设之签（严签之验得过）；余式径接于文末。豫行启动器之 `--合成` 用之。

有样本之原呼者共六千原令字节之展预算，通深之护为六四；自呼取前二层而展，旧径内联之限仍旧。各层存复函、呼序与局映；全尾链返原函，有常呼续体之内尾呼出最近展层。二层展与尾链基线已有运行之验；免重验签候选之验与速犹待毕。

以模块导入，如 `寻观「裸机后端」之「机器编码」之书。`。此包之默认导入书空列，用者径导具体之模。

## 维护

原令可证二引用参出于读局，则传已知型与非空；长界与对象头缓存毋传，未知之源存其验。递归内联依今层映局号，各层存、清与复来路之记，毋误用外层之源事实。

预编二闭控制层，仍实入边之可达。环唯有回边者，其末仍不可达；外块唯合实出分支之事实，遂存不变数组之长与型，供后验之省。

宽函降前，简恒零之非参局及宽整加减零，省宽较果紧随之无号扩。零或单果块、无回跳环，体无控流者可展；直段记近书之三十一位界，普通块入口存其实，控流合处及未知令清之，据以去复验之转换及相邻同局宽较相等。含数值隐帧之访者审而略之。

实测及验录见[原生追平记录](../../../../应用/性能研究/横向复测/原生追平记录.文言.md)。

AMD64 xHCI 逐枚已接之根端，候各自异步 Enable Slot 完事，依槽号别置输出上下文及 EP0 环；Address Device 事件回收写控器运行寄存器，待数别存，USB 地址与槽态各取。诸合式键盘依槽别存态、报文缓冲、旧键及中断环，端配置成即请报；累计报数、Caps 态共用。回收事件后每百毫秒察根端连接，新连候稳定而枚，断器则停其记、释其槽，复用先清全槽。禁 PS/2 之 QEMU BIOS、UEFI 已验直连全速两键盘别入、去重不相覆、热接、换端及同端复插，BIOS 别验中断环周回；Mac 多键盘、热插拔犹待实测，集线器下游热插拔未于此轮作；EHCI 不在手书之部，归豫言内核之增强主控（十月十三日起，手书者已删）。范围及诊断地址见 [USB 硬件里程碑](../../文档/通用串行总线硬件里程碑.文言.md)、[苹果键盘诊断](../../文档/苹果键盘诊断.文言.md)。

寻址既成，由 EP0 之 Setup、IN Data、OUT Status 三段请设备描述符前八字节，验其类而记 EP0 包长；继以 Evaluate Context 更包长，取全十八字节设备描述符、九字节配置首及全配置。求零备用之 HID boot 键盘接口及中断 IN 端点，向合者发 SET_CONFIGURATION、SET_PROTOCOL，以择 boot 协议；继以别置输入上下文配置中断端点，置八字节报文之请，续排而接既有字符收入。

改接口则更此说明；变身份、版本或所依则修包籍。

AMD64 USB 存储枚举择 SCSI/BOT 接口及其 bulk 入、出两端，别存槽号及端点之参，设配置而启两端。启程之探行 INQUIRY、READ CAPACITY(10) 及 LBA 零单块之读；已枚之根端入口治内核内部单块读、写、同步之请，维护两环周回，候存储时治合式键盘报文。候存储之传至多轮询二之三十二次幂减一次（空转则 pause），逾时之数记于 0x7C09700；旧限一亿次，KVM 下约一秒即尽，宿主换页则读盘逾时，迟至之 DMA 坏次读之共缓。QEMU 已验容量、块内容、专用盘写入同步、周回及重启回读；其请未接应用 ABI、调度及持久文件系统，实体机未验，确切范围见 USB 硬件里程碑。

择盘改为逐器配置成即行唯读启探；探败，后器枚举清内态、共用传输环而复试。欲使空介质读卡器等败候选让位，未自格式诸介质。类验及 BIOS/UEFI 模拟之验皆过：空介质居前、有效数据盘居后，择次盘，容量与首块之读皆成。五百一十二字节扇区而无豫言文件系统之盘，犹或先选；探逾后端点之复犹待作。实体读写、文件系统挂载未验。

AMD64 键盘报告片外置 `0x1F7000`，已接旧 xHCI 之巡，择合之事、去重、化键码而续排，仍用字符收入环，Ctrl-C 写旧中断之记。片存寄存器及标志，其事仍由旧巡统收。关 PS/2 之 QEMU BIOS、UEFI 已验正式回显、中文组字及连续收入，且越环周回；范围及实体机未验之录，见控台输入与硬件里程碑。

闭包融合之候选，唯合冻结客体已验之纯构造、纯取用及定呼窗，且临局后无读取。首实目标与后函表项皆合，乃传所捕值及右参，径呼取用体之尾目标；不合者尽行旧径。旧表界、空验及退径验签皆存，公开 ABI 与对象布局不易。生成器之构建及八标准客体之合、退、陷阱皆验成；速仍在测。

静序候选先证单函表、单活动元素段，无表之导入导出，诸定义函皆不书表，并验取用函之定项；乃求构造函之实槽。合槽则径传所捕参，省两查表及临闭包。不合则复首呼之位及参；未能证者仍两实目标之守。公开 ABI 如故。十五标准客体之合、退、书表、导出表、越界及签误皆验成；冻结编译器候选仍在测速。

融合既合，预算及签许可则展取用体之比较包装函；复用已尽之参存段，去旧实而存真捕值及右参，乃循旧展法。预算不及仍径呼。旧十五标准客体及新未捕异常之例皆验成，公开 ABI 如故；速仍在筛。

预编与预编二并入执行器之前，核物之布：执行器须出布标之函 `预编布局侧表二`（结构引用之域占址宽，游标、游限、位图偏、卡表居 0x2100 起之宽格区，预编侧表为第二版之式），不得则报误，编译器与执行器（客体二号）须以同源重构；布再改，则转译器之 `预编布局标记` 与执行器之出同易其名。

预编二依引用之宽 W 而生码（二〇二六年十月七日）：执行器之内存声明为六十四位址者（数值转译据之为模加 `长址内存` 之出）W 为八，否则为四。W 八则结构引用之域（齐于八字节）、数组引用之元与表项皆占八字节，所生之码于引用以六十四位读写、验空、相比，堆址以六十四位之加（内在一），游标、游限、位图偏、卡表四宽格以八字节读写；值栈、暂区、全局表、表描述、函数表与模块字节居四吉之下，仍以三十二位之算求址。呼执行器之函（`预编` 所冠之运行时与解释之处理），依数值转译所记之原函型（`降级公用` 之 `原函型们引`）逐转其参与果：i32 之形参截之，i64 之形参如故，i32 之果零扩之。降者于六十四位址内存，以六十四位展预编二之验空、数组取书、带偏之八字节书、物之起始位与记卡（见 `宽降级原语` 首之内在号之说）。W 四则所生之码与旧逐字节同。六十四位址之执行器以预编二生之（编译器径出带执行器之原生之产，皆行预编二）；初版预编受八字节之引用，留待后续之版。

预编二并入时复算客体之 SHA256 小写十六进制摘要（由字并入者取客体之字，原生之产与汇编树码之豫行由豫汇之途者取客体之汇编树码），易执行器占位之出 `预编摘要可用` 为常数一、`预编摘要字零` 至 `预编摘要字一五` 为摘要依小端每四字所拼之字；执行器无此诸出则不易（`预找导出或负`）。原生程序起时故不必复算（编译器之客体约二点七兆，现算约八亿条指令）。
