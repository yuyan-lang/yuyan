# 裸机后端

自有引导的 ISO 9660 目录记录调用磁盘格式库的定时记录编码，保留固定扇区地址、长度、2026-10-07 日期及原名字字节。引导表与模块布局保持原值，正式系统造盘与公共库共用记录编码。`公共光盘接线。测试。豫` 以独立字节向量核对正式包装函数。

预编二的内联游程分配以六十四位算术计算候选末址并比较游限，四字节引用构建保留越过 4 GiB 时的进位。超过游限的请求进入执行器慢路径。`游程进位。测试。豫` 使用压缩崩溃现场的边界向量验证两种引用宽度、恰好到界和界内分配。

ARM64 开机大段映射使用虚拟及物理地址 `0x50000000` 起的 64 MiB 独立区域。动态物理块池位于 `0x44000000` 起的 128 MiB，使用六十四位位图；每任务保留 64 MiB 上限，两任务可以同时占满各自区域。系统工具的 ARM 模拟参数使用 512 MiB 内存。ELF 内存段长度随实际载荷增长。十五 MiB 载荷和两任务页表的结构回归，以及十八块父子隔离用例随源码提交供 CI 执行。

`系统库调用桩` 生成苹果 ARM64 内部动态调用块的机器码。调用块携带完整函数地址、八个整数槽、八个浮点槽、512 字节栈参数及双种结果槽；调用前保存线性内存长度与返回地址，调用后恢复。苹果原生函数表复用系统的 `dlsym`、`malloc`、`free`、`posix_memalign`、`memset` 与 `memcpy`；动态调用块由自身生成的桩执行。相关系统库测试在 macOS CI 的同一客体双端运行中核验。

`自有引导` 生成启动盘的引导程序与镜像结构（2026-10-07）：BIOS 的 MBR 与第二级引导（实模式读盘、E820、VBE、Multiboot 1 信息、切保护模式），UEFI 的 `BOOTX64.EFI`（PE32+：找盘、读内核与模块、GOP、退出启动服务、回到 32 位跳进内核），1 MiB 的 FAT12 EFI 分区映像，ISO 9660 与 El Torito，混合 MBR。机器码写成十六进制字节，跳转、调用与取址用标号片。`豫言系统` 的「启动盘」用它写出混合 ISO，不用 Limine 与 xorriso。

`臂引导` 生成 ARM64 启动盘（2026-10-09，ARM 硬件第 7 步）：UEFI 的 `BOOTAA64.EFI`（PE32+，机器号 0xAA64：找带 ARM64 引导表的整盘、把内核各段读进缓冲、取内存表、退出启动服务、关 MMU 与缓存、把各段拷到载址并跳进内核），ARM64 引导表（入口与至多 15 段），只含 UEFI 项的 El Torito 引导目录，ARM64 混合 ISO（光盘、U 盘两用）。PE 包装与 FAT12 分区映像复用 `自有引导` 的「引导程序映像」「引导分区映像」。`豫言系统` 的「启动盘 --架构 臂六十四」用它写出 `yy豫言启动臂.iso`。

`动态任务` 是 AMD64 内核的动态任务（2026-10-07）：在两个静态槽之外按需起任意多个任务，服务 37 装载任务、38 读启动块，有动态槽时由它统一调度；与 `内存管理` 合成一个外置模块链接在 0x1A0000，主核心经跳转表转入。设计与槽区布局见 [动态任务](../../文档/动态任务.汉语.md)。它也管多核（2026-10-07）：开机启动其余处理器核，大内核锁、各核区与空闲见 [多核](../../文档/多核.汉语.md)。AMD64 的工具（豫构、编译器与豫言系统）是数据盘上的豫行文件，由豫言内核的服务 43 按段建任务装载，见 [动态任务](../../文档/动态任务.汉语.md) 的“工具映像”。

选盘验收（旧的双超级块规则，2026-10 初）：BIOS 选择有效零号块、UEFI 选择仅一号块有效的第三盘，均跳过前面的启动 ISO 与校验损坏盘；BIOS 正式读取 final.txt 返回 ExternalABI512。完整类型、系统构建及介质生成通过，准确范围见硬件里程碑，实体读写仍未验收。2026-10-10 起识别规则改为 ext4 超级块（见下一段），逐候选探测、失败让位的选盘流程保持原样。

数据盘识别候选（2026-10-10 起按 ext4）：只读核对候选数据区的扇区 2（字节 1024 起，即 ext4 超级块的前 512 字节）：偏移 56 的魔数为 0xEF53，偏移 24 的块大小对数为 2（4096 字节块）；符合即保留候选，挂载由执行器的 ext4 文件系统完成（读超级块与组描述符表，日志非空则重放）。候选数据区的起点先取 0；不符合时（启动 U 盘兼作数据盘，开头是 ISO），在 64 MiB 的第 1 至 16 倍处各读一次扇区 2 再核对，找到的起点记在 130060480，此后读写的扇区号都加上它。全部起点都不符合时让后续设备接替，避免 512 字节扇区的启动 ISO 阻挡数据盘。执行器不格式化数据盘，空白盘用离线造盘工具造一块空的 ext4。新规则的运行验收（U 盘与启动盘兼数据盘）尚待。

内联体保存并恢复自己的等长守卫表；长度不等就返回的无 else 条件，只在真支已返回后的假支记录等长，使用映射后的局部号。早返回入边保持原入口事实，外层汇合求交后删除单边假定；写相关局部仍删除事实。公开 ABI、对象布局与展开上下文签名保持原样。

已有内联样本明确列出直接调用的真实目标时，该调用可采用样本体长上限 6000；仍核对共享预算、深度及异常形态。未匹配调用保持普通直接内联判定，直接自身展开仍限两层。样本 JSON 格式与公开 ABI 保持原样。

有热点样本的函数，直接自身调用也允许展开前两层，并沿用 6000 字节共享预算与深度保护；无样本函数保持原路径，其余直接调用保持原上限。此候选的语义验证与性能测速尚待完成。

`持久盘构造` 离线生成扩展文件系统（ext4）格式的数据盘镜像（2026-10-10，取代 YYR1 双区追加日志格式）：块 4096 字节，每组 32768 块与 4096 个节点，全部元数据挤在盘首，随后是 1024 块干净的 jbd2 日志，再后是目录与文件的数据块；所有时刻取固定值，同一组参数造出的镜像逐字节相同，Linux 可以直接挂载。`按参数造持久盘`、`按参数造持久盘前段`（只到最后一个已用块为止，其后全是零）与 `目录树造盘参数` 保持原名与参数格式，容量至少 16384 个扇区（8 MiB）。`持久盘读取` 是宿主侧最小的读取器：按路径列目录、读文件（走区段树）、查位图与节点。`持久盘构造。测试。豫` 用中文名字、空文件、恰一块与跨块的文件、超过一块的目录、255 字节的名字、大于 4096 块的文件、两组与舍掉末组的容量、多区段与区段叶块造盘，读回核对内容与目录，并核对超级块、位图、块归属、目录块结构与日志。2026-10-10 另用 e2fsck 1.42.13（安卓模拟器自带）逐个检查测试导出的整盘镜像（最小盘、两组、舍掉末组、多区段与叶块、真实目录树）和 `库/` 目录树造出的 4 GiB 容量前段，均无任何问题（退出码 0）；同一环境下 mke2fs 1.47.2 造的参考镜像与本构造器的超级块、日志、目录块逐字段一致，仅在可选字段（哈希种子与哈希版本、默认挂载选项、s_flags、写入量、s_overhead_clusters、s_mtime、节点创建时间）与块的布局位置上不同。

豫言裸机（`豫言操作系统/裸机/`）的后端库：臂（AArch64）与兼容（x86-64）架构的机器编码与汇编、寄存器与整数降级（按目标描述生成入口、导入桩与内存增长助手，目标有裸机、Linux、macOS 与 Windows；macOS 与 Windows ARM64 位置无关）、内核的任务、内存、设备与控制台，系统镜像与持久盘的构造，商用平台可执行文件的写出（Linux 的 ELF64 静态可执行文件；macOS 的 Mach-O 可执行文件、dyld 导入槽绑定及其特设代码签名所用的 SHA-256；Windows 的 PE32+ 可执行文件与 kernel32 导入表；豫言操作系统自己的豫行文件，见 `豫言操作系统/裸机/文档/豫行格式.汉语.md`），数值降级（数值读取、数值转译与数值挂钩：底层模式新路径产出的 i64、f32、f64、v128 与原子指令转成宽函数与数值内在码，在两种架构上展开成浮点、NEON／SSE 与原子指令；AMD64 的预编二把客体浮点写成宽浮点内在，降成 SSE2 指令，见 `豫言操作系统/裸机/文档/数值降级.汉语.md`），内核的浮点与向量上下文（浮点上下文），以及裸机验证器所用的各项用例。原为编译器核心的子目录 `库/编译器核心/裸机后端`，2026-09-27 起独立成包；编译器本身不用它，改动它不必重新自举。

## 包身份

所有者：豫言。包版本：0.1.0。本包为库类型，依赖标准库、编译器核心（网页汇编核心）与结森工具。使用者是豫言裸机主包「豫言裸机」。

内联样本读取器解析普通 JSON 的客体摘要与原模块调用点，摘要须与客体 SHA-256 相同才启用；不匹配时配置为空。生成器可选参数为 `--内联样本 文件`，须与 `--预编二` 同用。转译器保留表边界与空引用检查；有本模块定义、相同类型号且可展开的目标时，签名检查推迟至守卫回退，命中目标由模块声明证明同型。无可用目标时保持原校验顺序，引用调用保持原路径。

降级缓存（`机器片缓存`，提案 00007）：生成器可选参数 `--缓存 文件`。模块有预编客体（导出“预编起号”）时，执行器的函数按键缓存降级并做完函数内连接的机器片；键是生成器版本、执行器摘要、目标与布局、执行器函数签名，加上本函数的号、签名、函数体与它实际用到的随客体而变的量（表零序号、所调客体函数的签名、数据段描述地址）的 SHA-256。命中就直接用缓存的片列，未中再降级；有未中时降级完重写缓存文件。文件末尾写结束标记，写到一半被打断的文件当作没有缓存。仓库目标按产物各放一份在 `.yybuild/降级缓存/`。

原生产物（`原生产物`，提案 00007 第 3 步）：「原生产物字节」把执行器与客体字节预编二成本机原生可执行文件的字节（做法同 yy原生生成 的 `--预编二`），「写本机原生产物」按本机系统与架构写出并加执行位。编译器 `--目标 本机` 在最终链接时调用它，yy原生生成 的本机系统与架构判断也取自这里。给了降级缓存路径时，客体函数的机器码按内容缓存（降级缓存路径加 `.客`），整个产物按编译器版本、目标、执行器与客体的摘要缓存（降级缓存路径加 `.产物N`）。原生程序里客体超过 4 MiB 时，另起子进程（本程序加 `--原生产物子进程`）生成，子进程的堆是新的。

有样本的原调用者共享 6000 原指令字节的展开预算，通用深度保护为 64；自身调用选择前两层展开，普通直接内联限额保持原值。每层保存及恢复函数、调用序和局部映射；完整尾链返回原函数，带普通调用续体的内层尾调用退出最近内联层。两层展开与尾链基线已有运行验证；免重复验签候选的验证与性能测量尚待完成。

## 使用

初始客体嵌入由 `系统构造` 共用处理：不超过 448 KiB 时放在原模块窗口，超过时末段暂存原窗口、超出的前段保留为被动数据段。启动包装先用标准 Wasm 指令增长内存，将两段按序拼接到动态区起点 `0xC0000`，再调用原启动，沿用 `状态主程序大`。静态八页、栈、参数传送区及应用 ABI 保持原约定。`测试/初始大客体。测试。豫` 已实际装配并调用包装入口，验证窗口边界、复制先于原入口、尾字节、模块长度和大程序标志；新壳的旧基线与固定合并基线 36aa076c4 的 BIOS/UEFI USB 输入验收已通过，范围见《智能命令》。

预编二的裸机镜像（豫言系统 `--预编二`，提案 00005 第 5 步）嵌入的是 `预编侧表` 生成的侧表：生成时算好执行器开机要建的类型表、函数表、元素段表与数据段表（按嵌入后的基址重定位），附带原样拷来的类型、导入、表、内存、全局、导出、起始、元素、数据与标签几节，镜像不带客体的代码节与名字节。执行器认出侧表的魔数后直接装表，只解析导入、全局、表、标签、内存与起始几个小节。预编代码的指令立即数在生成时取出，当常数传给执行器的立即数版处理（`预编回收指令立` 等）。原生可执行文件仍嵌入客体模块，改用侧表留待后续版本。

原始指令可证明两项引用实参来自局部读取时，转存已知类型与非空事实；长度、界与对象头缓存不转存，未知来源保留检查。递归内联按当前层映射局部号，逐层保存、清除及恢复来源记录，避免使用外层的来源事实。

按模块导入，如 `寻观「裸机后端」之「机器编码」之书。`。本包的默认导入是空列表，使用者直接导入具体模块。

预编二关闭控制层时沿用真实入边的可达性。只有回边的循环末尾保持不可达，外层块仅合并实际退出分支的事实；由此保留不变数组的长度与类型事实，供后继检查消除使用。

## 维护

宽函数降级先简化恒零非参数局部和宽整数加减零，并省去宽比较结果的紧邻无号扩展。无控制流的零或单结果块、无回跳循环可展开；直线段内记录最近局部写入的三十一位范围，普通块入口保留事实，控制合流与未知指令清空事实，据此消除重复范围转换和相邻同局宽相等比较。含数值隐式帧访问的函数保守处理。

实测及验证记录见[原生追平记录](../../../../应用/性能研究/横向复测/原生追平记录.汉语.md)。

AMD64 xHCI 逐个枚举连接的根端口，等待各自的异步 Enable Slot 完成，按槽号独立分配输出上下文和 EP0 环；Address Device 事件回收写入控制器运行寄存器，等待预算独立保存，USB 地址与槽状态分别读取。各匹配键盘按槽保存状态、报告缓冲、旧按键和中断环，端点配置后立即请求报告；累计报告数与 Caps 状态共用。事件回收后每一百毫秒检查根端连接，新连接稳定等待后枚举，断开设备停用记录并释放槽，复用槽前清空整槽。禁 PS/2 的 QEMU BIOS/UEFI 已验证两个直连全速键盘分别输入、独立去重、热插入、换端口及同端重插，BIOS 另验中断环周回；Mac 多键盘与热插拔仍待实测，EHCI 多键盘及集线器下游热插拔未在此轮实现。范围与诊断地址见 [USB 硬件里程碑](../../文档/通用串行总线硬件里程碑.汉语.md)及[苹果键盘诊断](../../文档/苹果键盘诊断.汉语.md)。

成功寻址后，以 EP0 的 Setup、IN Data、OUT Status 三阶段请求设备描述符前 8 字节，校验描述符类型并记录 EP0 包大小；随后以 Evaluate Context 更新包大小，读取完整 18 字节设备描述符、9 字节配置头及完整配置。扫描零备用设置的 HID boot 键盘接口与中断 IN 端点，向匹配设备发送 SET_CONFIGURATION 与 SET_PROTOCOL，选用 boot 协议；再以独立输入上下文配置中断端点，提交八字节报告请求，持续重排并接入现有字符收入。

修改接口时更新本说明；修改包身份、版本或依赖时同步更新包配置。

AMD64 USB 存储枚举选择 SCSI/BOT 接口及其 bulk IN/OUT 端点，保存独立槽和端点参数，设置配置并启用两端点。启动探测执行 INQUIRY、READ CAPACITY(10) 及 LBA 0 单块读取；已枚举的根端入口处理内核内部单块读、写、同步请求，维护两环周回，并在存储等待时处理匹配键盘报告。存储传输的等待最多轮询 2^32−1 次（空转时 pause），超时次数记在 0x7C09700；原先的一亿次在 KVM 下约一秒就用完，宿主换页时读盘超时，迟到的 DMA 会写坏下一次读的共用缓冲。QEMU 已验容量、块内容、专用盘写入同步、周回及重启后回读；请求尚未接入应用 ABI、调度或持久文件系统，实体机未验，准确范围见 USB 硬件里程碑。

选盘改为每个设备配置成功后立即执行只读启动探测；探测失败后，下一设备枚举清除内部状态及共用传输环再尝试。目的是让无介质读卡器等失败候选让位，未自动格式化任何介质。类型检查及 BIOS/UEFI 模拟验收通过：空介质在前、有效数据盘在后时选中第二盘，容量及首块读取成功。512 字节扇区的非豫言文件系统盘仍可能先被选中；探测超时后的端点恢复仍待实现。实体读写与文件系统挂载未验。

AMD64 键盘报告处理片外置于 `0x1F7000`，已接现有 xHCI 轮询，筛选匹配事件、去重、转换键码并持续重排，沿用字符收入环，Ctrl-C 写既有中断标志。片内保存寄存器与标志，事件仍由原轮询统一回收。关闭 PS/2 的 QEMU BIOS/UEFI 已验证正式回显、中文组字与连续输入，并跨过环周回；范围及实体机未验记录见控台输入与硬件里程碑。

闭包融合候选只匹配冻结客体中已核对的纯构造、纯取用及固定调用窗口，确认临时局部没有后续读取。第一实际目标及第二函数表项同时命中才传捕获值和右实参直接调用取用体的尾目标；未命中执行完整原路径。原表边界、判空及回退验签保留，公开 ABI 和对象布局不变。生成器构建及八个标准客体的命中、回退和陷阱核对已通过；性能仍在测量。

静态索引候选先证明单函数表与单活动元素段、没有表导入导出、全部定义函数不写表，并核对取用函数固定项；再求构造函数的真实槽号。命中槽号时直接传捕获实参，省去两次查表与临时闭包。未命中恢复原首调用位置和实参；未能证明的模块沿用双实际目标守卫。公开 ABI 保持原样。十五个标准客体的命中、回退、写表、导出表、越界与错签验证通过；冻结编译器候选仍在测速。

融合命中后，预算与签名允许时展开取用体的比较包装函数；复用已用完的实参保存段，删除旧事实后保存真实捕获值及右实参，再按原展开规则处理。预算不足保留直接调用。原十五个标准客体及新增未捕捉异常客体验证通过，公开 ABI 保持原样；性能仍在筛选。

预编与预编二并入执行器前核对对象布局：执行器须导出布局标记函数 `预编布局宽格`（结构的引用字段占址宽，游标、游限、位图偏、卡表在 0x2100 起的宽格区），找不到就报错并提示用同一份源码重建 yy原生生成 与执行器（客体二号）；布局再改时，转译器的 `预编布局标记` 与执行器的导出一起改名。

预编二按引用宽度 W 生成代码（2026-10-07）：执行器的内存声明为六十四位地址时（数值转译据此给模块加导出 `长址内存`）W 为八，否则为四。W 为八时结构的引用字段（按八字节对齐）、数组的引用元素与表项都占八字节，生成代码按六十四位读写、判空与比较引用，堆地址用六十四位加法（内在一），游标、游限、位图偏、卡表四个宽格按八字节读写；值栈、暂存区、全局表、表描述、函数表与模块字节在 4 GiB 以下，照旧用三十二位运算求址。调用执行器函数（`预编` 开头的运行时与解释器处理函数）时，按数值转译记下的原函数类型（`降级公用` 的 `原函型们引`）逐个转换实参与结果：i32 形参截取，i64 形参原样，i32 结果零扩展。降级器在六十四位地址内存里把预编二的判空、数组取写、八字节写加偏、对象起始位与记卡按六十四位展开（见 `宽降级原语` 开头的内在号说明）。W 为四时生成的代码与原先逐字节相同。六十四位地址的执行器用 `--预编二` 生成；第一版预编（`--预编`）支持八字节引用留待后续版本。

预编二并入时还算好客体字节的 SHA256 小写十六进制摘要，把执行器的占位导出 `预编摘要可用` 换成常量 1、`预编摘要字零` 至 `预编摘要字一五` 换成摘要按小端每四个字符拼成的字；执行器没有这些导出时不替换（`预找导出或负`）。原生程序启动时因此不必再算一遍（编译器约 2.7 MB 客体，现算约 8 亿条指令）。
