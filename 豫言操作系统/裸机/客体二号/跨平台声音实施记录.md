# 原生跨平台声音输出实施记录

2026-10-13，提案 00018 第二期声音输出的平台补齐。

林纳克斯复用既有 `openat`、`ioctl`、`write` 与 `close` 系统原语，直接连接内核 PCM 接口。参数块按目标机 `/usr/include/sound/asound.h` 核对：硬件参数 608 字节，区间起点 260，请求掩码偏移 512，硬件参数控制值 3261088017，延迟控制值 2148024609。格式是交错十六位有符号小端整数；每块完整写入后返回。设备延迟来自内核，已播帧数按累计写入帧减待播帧计算。欠载后重新准备设备，关闭丢弃待播样本。

视窗复用系统 `winmm.dll` 的波形输出 API，固定入口登记七个函数。句柄采用现有长整数类型与参数类别六，完整保存用户态指针。AMD64 的固定导入桩对类别六省去三十二位自拷贝，后续转参使用既有六十四位转移；ARM64 已有类别六保持寄存器全宽的路径。所有新增驱动逻辑为普通底层豫言，调用头和样本存放在非回收区域，播放完的块复用，关闭时先复位设备、再解除所有头。已播帧数由系统播放位置取得。

声音接口身份与公开声明保持现有 0.1.0，原语 250–254 按平台选实现。新增的是执行器私有平台入口，宿主提供清单沿用原声音输出声明。

## 2026-10-24 林纳原生写法的补齐

林纳与裸机一样，声音输出由执行器的原语 250–254 直接提供：林纳经「林声音」连内核 PCM 设备（ALSA 的内核接口）；林檎原生走适配「声音输出原生」调系统播放器。原生 Linux 可执行文件是静态 ELF，链接时只带系统调用；用户态的 libasound 需要动态装载，故林纳用内核 PCM 接口，宿主自带的声卡驱动与内核混音照常生效。

本次修正了「林声写」与接口规范的偏差：设备以非阻塞方式打开（`O_NONBLOCK`），原先写满时系统返回 −11，被当成“资源暂不可用”，且可能半块写入。现在写之前先问 `SNDRV_PCM_IOCTL_DELAY`，整块放不下就整块退回“资源配额已尽”（−4），一个字节也不写；有空间才写完整块；欠载（−32）后重新准备设备再写；−11 也按配额已尽退回。同时删去「林声选器」里一次无效的 `fcntl` 调用（打开标志已带 `O_CLOEXEC`）。设备缓冲为 4096 帧。

## 验证（2026-10-24，pit-pc-ubuntu-wired，Linux x86-64）

- 类型检查：`混音`、`清浊`、`听位` 三篇已过；`声图` 仍在修语法（本轮未过）；`客体二号` 未跑（将作转发反复中断）。
- 以当前源码构建公共探针 `应用/百工坊/设计验收/声音公共探针。豫`（远端退出码 0），在 pit-pc 上运行：`未捕捉的豫言异常：公共声音设备暂不可用`，退出码 1。接口已走到执行器原语；失败在打开设备一步：`/dev/snd/*` 是 `root:audio 0660`，用户 zc 不在 audio 组（`groups` 无 audio），`/dev/snd/pcmC1D0p` 不可读写，`aplay -l` 也报 no soundcards found，无法用普通用户打开。
- 远端机器实际有声卡：卡 0 PCH（仅 HDMI 类 `pcmC0D3p/D7p/D8p/D9p`）、卡 1 USB Audio（`pcmC1D0p` 等，普通输出）、卡 2 NVidia HDMI。设备扫描会依次尝试 `pcmC0D0p` 至 `pcmC9D9p`，本机先遇到卡 0 的 HDMI 设备与全部不可读的设备。
- 真实发声未验：没有可写的 PCM 设备，且用户无 sudo（交互认证）。接口在打开失败时按规范返回“资源暂不可用”，关闭与时钟路径未执行。
