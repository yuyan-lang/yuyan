# 客体二号

用户态豫言客体执行器二号，以**底层模式**的普通豫言编写（旧的括号式 `.低阶` 源码由此取代）。它解释执行普通豫言编译得到的 WasmGC 模块：栈机解释器、分配与标记清扫回收、异常、结构与数组、宿主原语（输出、文件、命令行、同步子进程）、持久文件系统与 Virtio 块设备驱动。

## 构建

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 客体二号 --输出 /tmp/yy客体二号.wasm
```

产物是标准 Wasm 模块（导出 `启动`），由验证工具 `豫言操作系统/裸机/普通豫言验证。豫` 读入后追加客体模块与标志数据段，生成裸机镜像。内存布局常量（`布局`）的地址与验证工具约定一致，不得随意改动。

## 模块

`布局` 内存布局与状态格常量；`基础` 输出、变长整数、内存与宽整数助手；其余模块依依赖顺序排列。语言约定见 `应用/豫言编译器/文档/底层模式.汉语.md`。

## 豫言操作系统底层接口：裸机后端

`裸机底层状态码`、`裸机底层基础`、`裸机底层句柄`、`裸机底层文件`、`裸机底层终端`、`裸机底层网络`、`裸机底层进程` 七个模块，是[豫言操作系统底层接口](../../../豫言操作系统底层接口/总纲.汉语.md)在裸机上的实现（45 个函数，方案见[底层接口方案](../../../文档/豫言操作系统底层接口方案.汉语.md)）。它们是**新增、独立**的模块：直接复用既有的文件系统（`fs读文件`、`fs写文件`、`fs建目录`、`fs删除`等）、控制台（`读字节`、`读行`、`打印串`）与时钟（`时钟滴答`、`墙钟秒`）原语，不改动这些既有实现；入口只在启动时新增一次 `底柄_初始化` 调用（借用「暂存缓冲」头 8 字节存句柄表基址与终端模式，经 `取区域` 动态分配句柄表、路径缓冲与内容缓冲，不与既有状态格冲突）。

- **句柄模型**：句柄 0/1/2 是标准三流；句柄 3 恒为根目录（唯一的预开目录）；4 起的 13 个槽按需分配给已打开的文件与目录，每槽有独立的路径缓冲（224 字节）与内容缓冲（4096 字节，整文件缓存）。
- **路径解析**：相对目录句柄解析，不含当前目录，`..` 越出目录句柄子树报错，与既有 `主机文件` 里依赖“当前目录”状态的路径规范化是两套独立的逻辑。
- **已知限制**（均已在各文件的双语注释里逐条注明）：`底层网络`、`底层进程` 全部返回“不支持”（网络因裸机无网络栈；进程因桥接既有的 GC 对象参数子进程机制不在本轮范围）；`建管道`、`取终端尺寸` 返回“不支持”；`填随机字节` 返回“不支持”（裸机熵源未定）；文件与目录内容缓存上限 4096 字节，超过则相应操作返回“溢出”；单调时钟精度 10 毫秒（内核滴答），墙钟精度 1 秒（RTC）。
- **尚未做**：把现有 72 个 `gc-host` 原语的实现（`主机*.豫`）改接到这些新模块（即“GC shim”一段），目前新模块尚无任何调用方，只完成了类型检查与完整构建（`node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 类型检查|构建 客体二号`），未做 QEMU 动态验证——本仓库现有的两条动态验证路径（`普通豫言验证`、`裸机验证`）在本次改动的同时因仓库另一处并发的编译器后端改造而临时不可用（前者所需的 `运行时.wat` 已被该改造删除，替换机制尚未接上；后者构建时崩溃），均与本改动无关。
