## 构建

```sh
./豫构。林檎。豫行 构建 客体二号 --输出 /tmp/客体二号。树码 -j 24
```

产物是汇编树码（底层豫汇，导出 `启动`）。内存布局常量（`布局`）的地址与内核、造盘工具约定一致，不得随意改动。仓库目标「执行器」写出 `执行器。树码`，编译器直出的各种原生产物（豫构默认的原生产物、豫构发行原生等）与豫言系统造的豫行文件直接从它生成（提案 00007 收尾）。

## 模块

`构建摘要` 补齐构建基础的 `取今程序沙二五六` 与 `取卷沙二五六` 宿主导入，使用普通豫言底层三十二位运算返回小写十六进制摘要。当前程序取本实例嵌入的 Wasm 内容；文件摘要取指定路径的内容。AOT 程序的命令行程序名仍指可执行容器，核对程序摘要时须指定原始 Wasm 文件。预编二生成的原生程序里，生成器已算好客体的摘要（客体字节的 SHA-256；编译器直出的原生程序与由汇编树码造的豫行文件取客体汇编树码的 SHA-256）并写进 `预编摘要可用`、`预编摘要字零` 至 `预编摘要字一五` 这些占位导出（64 个十六进制字符按小端每四个拼成一个字），`取今程序沙二五六` 直接返回它，不再在每个进程启动后对整个客体算一遍；解释执行时这些占位为零，照旧现算。

`布局` 内存布局与状态格常量；`基础` 输出、变长整数、内存与宽整数助手；其余模块依依赖顺序排列。语言约定见 `应用/豫言编译器/文档/底层模式.汉语.md`。

`域名报文` 用普通豫言底层模式写 DNS 单问题查询及 A、AAAA 回答的编解码，支持回答名的压缩指针；原生进程在 Linux 上经 UDP 使用它。固定报文探针覆盖两种记录及无效指针。

`网卡`、`网络栈`（提案 00012 第 4 步）：初始任务里的网卡接口（2026-10-13 起两架构都经内核服务 61–63 收发，内核先用自己的原生网卡驱动，见内核 `网卡表`）与以太网、ARP、IPv4、UDP、TCP、环回的网络栈（本机 10.0.2.15/24，网关 10.0.2.2，32 个 TCP 连接、16 个 UDP 端点），经底层服务（底层网络的 TCP、数据报与套接字地址，见下文“底层转送”）供子任务与林兼容层使用；网络区在开机流程里（初始化堆之前）预留。

网卡（2026-10-13 起）：执行器只经内核服务 61 网帧收、62 网帧发、63 网卡信息（见平台接口规范）收发，内核先用原生网卡（虚拟网卡 virtio-net、英特尔千兆 e1000 与 e1000e 等），没有原生网卡或链路都没通时用驱动客体交来的网卡；以网卡自己的以太地址收发，链路通了才算就绪，未通时每次网络请求再问一次。原先 ARM64 执行器里的用户态 virtio-net 已删去。`裸机传输控制`（2026-10-13）：初始任务里，标准库的传输控制协议原语 77–90 直接用网络栈的套接字，开始连接的主机名按点分十进制、localhost 或向域名服务器查 A 记录解析，开机程序与壳里直接运行的豫言句因此能连网；子任务（没有网络区）仍返回不支持，待办事项。`公共网卡原语`（2026-10-13）：设备接口的「问网卡」（原语 245，壳命令「网络态」用），经服务 75 读各网卡记录，并报网络栈的地址设定。网卡第一次就绪时网络栈先用 DHCP 取址（广播 DISCOVER、REQUEST，每步至多约 1 秒、四轮），得到本机址、网关、掩码与域名服务器，失败则用默认的 10.0.2.15/24、网关 10.0.2.2、域名服务 10.0.2.3，并在控制台报一行。林程序发往 10.0.2.3 或 127.0.0.1（林根没有 resolv.conf 时 glibc 的默认）53 端口的报文改发实际的域名服务器，回报的来源再改回原址。租约续期与地址冲突检测留待后续版本。

## 豫言操作系统底层接口：裸机后端

`裸机底层状态码`、`裸机底层基础`、`裸机底层句柄`、`裸机底层文件`、`裸机底层终端`、`裸机底层网络`、`裸机底层进程` 七个模块，是[豫言操作系统底层接口](../../../豫寓底榫卯/总纲.汉语.md)在裸机上的实现（45 个函数，方案见[底层接口方案](../../../文档/豫言操作系统底层接口方案.汉语.md)）。它们是**新增、独立**的模块：直接复用既有的文件系统（`文件系统读文件`、`文件系统写文件`、`文件系统建目录`、`文件系统删除`等）、控制台（`读字节`、`读行`、`打印串`）与时钟（`时钟滴答`、`墙钟秒`）原语，不改动这些既有实现；入口只在启动时新增一次 `底柄初始化` 调用（在固定状态格 3664、3668 保存动态句柄表地址与终端模式；表头保存行输入剩余状态，经 `取区域` 分配句柄表、路径缓冲与内容缓冲，暂存缓冲仍供文件和时钟操作临时使用）。

子任务重启会清空动态区；`重启准备` 同时清除旧句柄表指针，下一次启动重新分配句柄表并建立根句柄 3。当前子任务没有块设备，底层文件操作仍需由初始任务经独立邮箱协议代办；GC 文件原语已有自己的对象协议。

- **句柄模型**：句柄 0/1/2 是标准三流；句柄 3 恒为根目录（唯一的预开目录）；4 起的 13 个槽按需分配给已打开的文件与目录，每槽有独立的路径缓冲（22400 字节）与内容缓冲（409600 字节，整文件缓存）。底层文件另从动态区取得临时路径和数据缓冲。
- **路径解析**：相对目录句柄解析，不含当前目录，`..` 越出目录句柄子树报错，与既有 `主机文件` 里依赖“当前目录”状态的路径规范化是两套独立的逻辑。
- **已知限制**（均已在各文件的双语注释里逐条注明）：`底层网络`、`底层进程` 全部返回“不支持”（网络因裸机无网络栈；进程因桥接既有的 GC 对象参数子进程机制不在本轮范围）；`建管道`、`取终端尺寸` 返回“不支持”；`填随机字节` 读处理器随机数（ARM64 RNDR、AMD64 RDRAND，目标内建导入“硬件随机”），处理器不支持时返回“不支持”（安全随机字节串原语 98 这时改用熵池，见下文“后备熵源”）；文件与目录内容缓存上限 409600 字节，超过则相应操作返回“溢出”；单调时钟精度 10 毫秒（内核滴答），墙钟精度 1 秒（RTC）。
- **GC shim 的改接**：控制台输出原语（1–4 号）经本接口的 `写`；Linux 上的文件原语经本接口的 Linux 后端（见下节）。裸机上的文件原语仍直接用执行器内的文件系统（待办事项：放大整文件缓存的上限后改经本接口）。

## 多平台：同一份执行器在 Linux 与 macOS 上运行

执行器是同一份整数 Wasm 模块，由寄存器降级按目标生成裸机镜像、Linux 可执行文件或 macOS 可执行文件。运行时靠目标内建导入 `导入：目标：平台号`（降级时绑定为常量：裸机 1、Linux 2、macOS 3）选择平台实现；其他目标的导入降级为陷阱桩，不会被执行。各平台的导入都声明在 `平台接口/` 的接口文件里（`林纳`、`林檎`、`轩窗`、`平台`、`目标`），导入模块名就是接口文件名。

- `林系统`、`苹系统`：Linux 系统调用包装（导入模块名“林纳”）与 macOS libSystem 包装（导入模块名“林檎”，返回 -1 时导入桩已换成 -errno），以及 `是林`、`是苹` 与各自的 errno 转换表（两个系统的 errno 编号不同）。`原生系统` 在两者之间分派写、读、退出、时钟与终端判断。
- `平台`：写字节、读字节、退出、时钟滴答、墙钟、中断查询在原生系统上改走系统调用或 libSystem；任务与邮箱服务在原生系统上尚未实现，按失败返回（待办事项）。
- `林启动`、`苹启动`：启动时写程序名区、参数区与环境块。Linux 读 `/proc/self/exe`、`cmdline`、`environ`；macOS 用 `sysctl` 的 `KERN_PROCARGS2`（缓冲是启动时新增长的两页）。之后的宿主原语不必区分平台。
- `轩窗系统`、`轩窗启动`、`轩窗底层`：Windows（平台号 4）。系统入口经 kernel32、ntdll、bcrypt（导入模块名“轩窗”）；标准流读写、单调与墙钟（64 位计数用本模块的逐位长除与 MulDiv 换算）、UTF-16 与 UTF-8 互转；启动时由 GetModuleFileNameW 与 NtQueryInformationProcess（命令行）写程序名区与参数区（按 Windows 规则拆参数），路径写成执行器内部的 `/C:/a/b` 形式；暂存区（1 MiB，前 256 KiB 保持 Linux 布局）与 Linux 后端共用同一个状态格。文件（CreateFileW 等，旗标 FILE_FLAG_BACKUP_SEMANTICS|FILE_ATTRIBUTE_NORMAL）、环境变量（GetEnvironmentVariableW）已实现。`轩窗进程`：建管道（CreatePipe）、运行程序（CreateProcessW，按 MSVCRT 规则拼命令行，环境块转 UTF-16，三个标准流临时设为可继承）、进程表（与 Linux 同布局）、取退出码、终止、关闭与轮询式等待（进程、管道、控制台、套接字）；管道可设为不阻塞（登记表，读前用 PeekNamedPipe 看可读字节数，没有数据回暂不可用）。TCP 经 ws2_32（套接字登记表区分套接字与其他句柄，Winsock 错误码按 Linux 映射对齐）。导入参数类别 5 为可空指针。待办事项：Windows 的 hosts 与 DNS、控制台模式、目录句柄与工作目录句柄。
- `轩窗缺页`：Windows 上碰到才提交（提案 00021）。Windows 上提交的内存不论碰没碰过都计入系统的提交上限；Windows AMD64 的执行器入口只预留动态区，并以 AddVectoredExceptionHandler 注册缺页桩（后端 `兼降级本术` 的「兼轩窗缺页桩」，只把 Win64 调用约定转成本降级的内部约定），缺页桩调导出「轩窗缺页处理」：访问违例的故障地址落在执行器自己的动态区，或落在豫行启动器给客体预留、已经求过块的动态区（状态视客记里的启动器记录）里时，就地提交所在的一块（32 MiB）再重新执行；同一块刚提交过又出错就交还系统；提交失败时往标准错误写一行再交还系统。进程于是只按碰过的内存计提交，`-j` 大时也起得来工作进程。Windows ARM64 的入口仍一次提交整个动态区（待办事项）。
- `林底层`、`苹底层`：底层接口 45 个函数的 Linux 与 macOS 后端，`原生底层` 按平台号在两者之间分派（函数名加前缀“原底”）；裸机后端各函数开头在原生系统上转到这里。句柄就是文件描述符，3 号是根目录“/”。Linux 打开用 `openat2` 加 `RESOLVE_BENEATH`（越界返回 76），`ENOSYS` 时逐段用 `O_PATH|O_NOFOLLOW` 解析；路径状态经受限句柄查询，建删、改名和读链接先安全打开父目录，双架构路径探针通过。macOS 打开用 `O_RESOLVE_BENEATH`，路径状态用 `AT_RESOLVE_BENEATH`，其他路径操作先受限打开父目录；本机 ARM64 路径探针覆盖树内链接、越界链接及文件变更，均通过。状态分别取自 `statx` 与 `fstatat`，目录分别取自 `getdents64` 与 `__getdirentries64`。待办事项：Linux 旧核逐段回退与两平台父目录打开后的并发更名竞态、旧版 macOS 不支持边界标志时的回退。终端模式：Linux 用 TCGETS/TCSETS，macOS 用 TIOCGETA/TIOCSETA（原始模式与 libuv 相同）。
- 虚根：环境变量 `豫言根目录` 给出宿主上的一个目录时，原生（Linux、macOS）进程把它当作根目录“/”：附庸表只有一行，「/」对到这个目录（可写，见下文“附庸”）；带路径的底层原语、切换目录（chdir）与启动子进程都按附庸表把路径改成宿主路径，启动时当前目录与程序名区里的程序路径换回系统路径（`附庸反改`）；子进程继承环境变量，也在同一虚根里。豫言系统造盘时用它在宿主上照盘内的 `/源`、`/工具` 预编豫构交互的前导单元。待办事项：轩窗没有虚根；以 `/dev/null` 为空设备的子进程原语在虚根下打不开空设备。
- `原生进程`：两个系统共用的进程、等待与网络实现，系统差别集中在“进”开头的小函数里。运行程序：fork（Linux 用 clone(SIGCHLD)），子进程接好标准流与工作目录后 execve，失败时经 O_CLOEXEC 管道把 errno 告诉父进程；进程句柄从 2^30 起编号，进程表在暂存区。等待用 ppoll（macOS 用 poll），进程订阅每轮检查（有运行中的进程时每轮至多等 10 毫秒）。TCP 支持 IPv4、数字 IPv6、localhost 与 `/etc/hosts` 名表；Linux 和 macOS 均依次尝试 `/etc/resolv.conf` 中的服务器，以 UDP 查询 A、AAAA，原名未解析时依次拼接 search 或 domain 后缀。Linux 空主机监听双栈，macOS 空主机仍用 IPv4；macOS 的 resolv.conf 未必涵盖系统全部 DNS 路由（待办事项：系统 DNS 路由接入、IPv4 嵌入式 IPv6 地址、区域号）。启动时忽略 SIGPIPE，子进程在 execve 前恢复默认。启动顺序上，底层句柄表与原生后端暂存区都用 `取区域`，必须在 `初始化堆` 之前（之后的区域顶就是堆起点，会与堆重叠）。
- `原生子进程`：原生系统上的同步子进程原语 43–46（程序名按 PATH 解析，经 `运行程序` 启动；45 接 /dev/null，46 用两条管道同时读取标准输出与标准错误）。切换当前目录时同步进程的真实工作目录，子进程因此在同一目录运行。异步子进程 67–69 也在这里：子进程表（至多 1024 个）在启动时用 `取区域` 分配，回收时整表作为根扫描；两条捕获管道设为不阻塞，收取与等待时读尽现有数据并查询退出码，等待时用底层接口的 `等待` 同时等全部管道与进程句柄，行为与 Node 宿主相同（豫构调度器测试在原生宿主上与 Node 输出逐字相同）。参数串平常放在工作区里（至多 65024 字节），更长时（如编译器入口的解析任务带着几百个依赖路径）放到堆里新分配的字节数组。子程序是 Wasm 模块时改经 Node 运行，与 Node 宿主一致：沿 env 与 timeout 包装找到最终命令，名字以 .wasm 结尾就在它前面插入“node 宿主.cjs”（宿主取当前目录下的 豫言操作系统/宿主/节点/宿主.cjs，其次 稳定节点宿主/宿主.cjs），原生豫构因此能运行仓库目标里的 .wasm 工具与 .wasm 编译器。待办事项：设置子进程输入、环境（70、71）尚未接到原生系统。待办事项：只按 .wasm 后缀认，不读文件头；Windows 上不改写。
- macOS 的底层运行程序通过 `posix_spawn` 启动子进程，以文件动作接标准流和工作目录，以进程属性恢复 SIGPIPE 默认处理，参数与环境沿用原来的指针表。启动成功后照旧登记进程句柄，失败返回原来的底层状态码；无需复制父进程堆或等待后台清扫。切换目录动作要求 macOS 10.15 及以后。Linux 的 clone 与错误管道路径沿用原实现。
- `原生网络原语`：TCP 宿主原语 77–90 与数据报交换 176（语义同 Node 宿主：不阻塞，返回（状态，值）），在原生系统与子任务里经底层网络包实现（子任务经底层转送）；裸机初始任务用网络栈（`裸机传输控制`），没有网络时返回 -58。 交给程序的连接句柄是底层句柄加 2²⁰（布局的「网柄基」，提案 00035），程序传回时再减去，连接句柄与异步子进程句柄（1–1024）不重号；多路等待（原语 69）据此分辨：不小于 2²⁰ 的按连接订阅底层句柄的可读、可写（`异步写网订阅`），先以零时限的「网候」查一次，其余照旧是异步子进程。原先多路等待只认异步子进程，关注连接的可等待任务（如构建服务）每轮都立即醒来，空转占满一个核。 原语 212–214（提案 00035 邻籍，标准库「东道」的「开播报」「投报」「收报」）：「开播报」建 IPv4 数据报套接字，设地址与端口复用（与系统的多播名籍服务同绑一个端口）后绑定给定端口，组播地址不为空时加入该组（组播跳数 255、回环开），设为不阻塞，返回（状态，连接句柄）；「投报」向（数字地址，端口）发一个数据报，返回（状态，字节数）；「收报」不阻塞地收一个数据报，返回（状态，来源地址，来源端口，内容），来源地址是按网络序拼成的整数。句柄同样加网柄基，可用「别」关闭。macOS、Linux 原生实现，Windows 与转送中返回 -58。
- 字节串原语：91 号 `豫言_字节串截取`（从起点取定长字节成新串，越界时以 134 退出）在各平台由执行器直接实现，原生运行的编译器写出产物时要用它。11 号“运行于苹果”在 macOS 上返回真。
- `原生文件原语`：原生系统上的文件宿主原语，路径仍由 `规范参数` 规范成绝对路径，再经底层接口访问宿主文件系统；启动时当前目录取自 `/proc/self/cwd` 或 `getcwd`。写文件（30、31）与改名（180）失败时（转送底层调用的子任务同样），`林抛祸` 按客体导出的异常标签 `yy_错误` 抛出豫言异常（消息“写文件失败：路径：原因”或“改名失败：旧路径 → 新路径：原因”，原因取底层状态码的名字；建上级目录失败的原因也带出），客体可用「姑试」接住，没接住即报“未捕捉的豫言异常”并以一退出；写了一半的文件先删去。

## 常驻工作进程（提案 00007 议三）

macOS 与 Linux 原生里，编译器并行编译起“本程序 `--mode=worker` …”的异步子进程时，执行器把参数写成任务帧交给常驻的工作者（本程序 `--常驻工作者`，标准输入接任务管、标准输出接结果管）。工作者读一个任务帧到参数区，`启动一次` 跑完任务；任务写往标准输出与标准错误的字节先截留在两块缓冲里（`常驻` 模块，各 16 MiB），任务结束后连同退出码作一个结果帧交回父进程；随后清场（`常驻清场`：清零回收堆里本任务用到的那段对应的标记位图与卡表，再清状态格与回收格），读下一个任务。任务中途调用退出、或回收堆用过 256 MiB 以上时，工作者发退出帧后退出，父进程照常继续调度，下次取闲时再收回它。父进程一侧（`原生子进程`）把派出的任务照常登记在异步表里，表项读工作者的结果管，凑满一帧就完成；结果管读到尾而帧没凑满（工作者意外退出）时以它的退出码完成。池满（64 个）、参数放不进参数区（64 KiB）时照常另起进程。省掉的是每个任务的进程启动、执行器与客体初始化与新内存的缺页：本机冷编豫言系统约快 4%，完整构建豫言编译器 24–28 秒降到约 23–24 秒，产物逐字节相同。清场按址读写堆基、位图、卡表与常驻顶。动态区与回收堆的字节都不清：清场把区脏顶（状态格 9116）抬到本任务的区域顶，之后 `取区域` 取到区脏顶以下的地方先清零，先写后读的栈与缓冲（值栈等栈、栈复制缓冲、截留缓冲、栈图表、中转缓冲、底柄内容缓冲、清扫线程栈）用 `取区域不清`；回收堆的分配本来就把要读的地方写好。栈图表每个任务落在同一处，第一个任务复制以后各任务直接用（常驻栈图，状态格 9332）。这样每个任务少清零约八十兆字节、少复制约十二兆字节（十程序无改动合编，原先清场与复制栈图表每个任务约十毫秒）。全局初值也不再每个任务都求（`全局初值`）：第一个任务求完后把回收堆里它分配的那段（连同位图、卡表、全局表、大块桶表与状态格里被它改过的字）拍成快照，放在线性地址 1.75 GiB 起的快照区；第二个任务先清零那段回收堆、照常求值并逐字节核对，相同才启用；之后的任务把快照放回（编译器约三万八千个全局、22 MB）：Linux 上回收堆那段能整页对齐的部分事先写进 /dev/shm 里的一个临时文件（放不下再放 /tmp，建好即删名，只留句柄），每个任务开始时按 16 KiB 页写时复制映射回去，没碰到的页（拼音表这类大常量多半整张不读）不拷，头尾不满一页的部分与位图、卡表、全局表照旧拷回，每个工作者第一次映回后逐字节核对一遍，十程序无改动合编的前端快约一成；macOS 上缺页比拷贝贵，整段拷回。动态区长到快照区时停用快照（状态格 9336）。豫行启动器下的豫行客体（提案 00021，宿主门中，2026-10-14 起）与原生走同一套：父客体按原生的做法建池、派任务（`原生子进程`），运行程序、建管道、等待经底层转送交启动器办理，豫行文件由启动器改起为“启动器 `--豫行` 程序 `--常驻工作者`”；工作者里的客体照样经句柄 0、1 收发任务帧（读写经「常驻门转」交启动器），任务输出截留在客体里，见 `豫行启动` 与下文“底层转送”。裸机与 Windows 的常驻工作进程留待后续版本。

## 预编：WasmGC 函数直接成为机器码（路二乙档第一版）

第一版预编的转译器（「预编并入」）已在 2026-10-11 删除（提案 00007 收尾），现在只用第二版（见下文“预编二”一节），执行器一侧的 `预编接口。底层。豫` 由第二版沿用；本节记录第一版的设计。第一版把客体 WasmGC 模块的每个函数转译成一个整数 Wasm 函数，并入执行器模块后一起经寄存器降级生成机器码；执行器照常解析模块、建类型表、初始化全局与数据，但不再解释函数体。转译器在 `库/裸机后端/预编转译。豫`，执行器一侧的运行时接口在 `预编接口。底层。豫`。编译器直出的原生产物现在都用下文的预编二。

- **值都在值栈上**：布局与解释器相同（每槽 8 字节，引用与 32 位整数在低字），所以保守回收照常看得见；转译函数的签名是（帧）→ i32，参数与局部变量从帧起，操作数栈在其上，调用者把参数放在栈顶、被调用者的帧就从那里开始。
- **简单指令内联，复杂指令调解释器的处理函数**：局部变量、常量、i32 运算与比较、少数 i64 指令、引用判空与相等、控制流直接写成整数指令；结构、数组、类型转换、i64 其余与浮点、访存、表与杂项指令调用执行器导出的“预编”函数（就是解释器的指令处理函数），传入立即数在模块字节中的地址。
- **控制流一一对应**：块、循环、条件对应整数 Wasm 的同名结构，分支先把携带的值搬到目标槽；尾调用（return_call 及间接、引用尾调用）先把参数搬到帧首，再“调用后立即返回”，寄存器降级把这种形状变成尾跳；间接调用经执行器导出的 `预编派发`（按函数号二分，叶子上尾跳到转译函数）。
- **异常用标志传播**：抛出时记下载荷并置 `状态预编异常`，每次调用转译函数后检查，在尝试表里就跳到它的处理代码，否则返回；最外层仍有异常即按未捕获异常退出（137）。
- **大模块**：超过 448 KiB 模块窗口的客体（如编译器）不嵌入窗口，而作为尾块写进可执行文件（Linux 附在文件末尾，macOS 放在 __LINKEDIT 里签名之前），执行器启动时读回到动态区开头；Linux 代码太大时单独放一个载入段（ARM64 在 0x10000000，x86-64 在 0x50000000）。预编二的原生文件（2026-10-09 起，提案 00007 第 1 步）嵌入的是预编侧表而不是客体模块，侧表超过 448 KiB 时同样作尾块，执行器认出侧表就直接装表，不解析模块。
- **降级器随之扩充**：“调用后立即返回”变尾跳；每 512 KiB 代码插一个陷阱岛，越界与除零检查跳到最近的岛；大函数（超过 2 万条指令）的条件跳转改用“反条件跳过 + b”；汇编器只在条件分支上计算 19 位位移（原先 b、bl 超过 1 MiB 也会误报超程）。

现状（2026-09-28）：macOS arm64 上普通探针、文件探针与原生探针共 12 项在预编模式下与参照输出逐字一致；短程序比解释执行快约两倍（多为启动开销）。待办事项：内联更多热指令（ref.cast、struct.get、array.get、i31）、非引用值留在寄存器里、Linux 上的预编验证、编译器本身的预编与原生自举。

## 预编二：客体的值放进寄存器与原生栈（路二乙档第二版）

结构对象头宽八字节。引用字段宽一个址宽（八字节，见下节），其他字段保留八字节，各字段按自身宽度对齐，对象总长按八字节对齐且至少十六字节。继承字段从完整字段序列计算偏移，父类型末尾的填充不参与子类型字段偏移。值栈槽宽八字节，引用读入值栈时高字清零；数组布局保持原有约定。执行器与预编生成器须使用同一份结构布局，变更布局后须成套重建，已有原生可执行文件保留其内嵌执行器和生成代码。

预编二用新的转译器（`库/裸机后端/预编二转译。豫`），编译器 `--目标 本机` 直出的原生产物都由它生成。与第一版的区别：

- **客体的值不再放在执行器的值栈上**：每个客体函数转译成一个宽整数函数（`库/裸机后端/宽降级原语。豫`），参数、局部变量与操作数就是这个函数自己的参数、局部与操作数；每个值六十四位（i32 与引用零扩展），由寄存器降级放进寄存器与原生栈帧。i64 运算写成内在调用，降级器就地展开为六十四位指令。
- **调用直接传参**：客体函数之间直接调用；call_ref 与 call_indirect 经跳表零（每个客体函数一项）；执行器经 `预编派发` 调用客体函数时走跳表一里的适配函数（从值栈帧读参数、写回结果）。客体导入由导入桩经 `预编调用导入` 调用执行器。
- **内联的热指令**：结构与数组的读写与长度、i31、判空、精确类型的 ref.test/ref.cast 直接写成整数指令；struct.new、struct.new_default 与 array.new_fixed 在当前游程里碰撞分配（游标、游限两个状态格；新游标用常址写四写回，两个头字拼成一个八字节常量一次写入，对象起始位由专用内在置位，ARM64 八条），不够时调用 `预编分配`。按常数下标的数组取值不装下标：长度直接与常数比较，元素按立即偏移读取。下标已知小于数组长度时（转译事实：br_if 落空路径上“下标局部无号小于某局部”，且那个局部是该数组的 array.len）不查界。其余指令把操作数写进执行器值栈的暂存区（起址在 `状态预编栈顶`，由适配函数设置），再调用解释器的处理函数。
- **转译时内联**：直接调用或直接尾调用另一个客体函数，且其代码体不超过 60 字节、不含尝试表与旧式异常指令时，不发调用，而在调用处接着转译它的体。参数与局部借一段块临时，实参弹进参数、其余局部清零，体包进一个结果数相同的块；被调函数里的 return 跳出这个块，尾调用改成普通调用加异常检查再跳出；展开在尾调用处时，二者照旧是调用者的返回与尾调用，块后补一个返回。转译事实（非空、类型、界）因此跨过函数边界。只内联一层，不内联自己。降级之前另有整数层的小叶函数内联（`库/裸机后端/内联小函数。豫`）。并入时客体定义函数只放占位（签名、零个局部、空体），降级与整数层内联要用函数体时才经 `降级取体` 的钩转译：内联准备只留下不超过内联上限的小函数体，大函数只留占位，降级完就把钩复位；遍历两万多个函数用尾递归的带序映射（标准库「遍序」经「遍二」非尾递归，原生保守扫描时两万多层栈帧里留着各函数降级的临时数据）。这样原生程序生成原生产物时，同时存着的只有执行器自身的中间表示、小函数体与已降级的机器码。
- **回收看原生栈**：`预编二可用` 为 1 时，启动时预留栈复制缓冲（原生 258 MiB，与 macOS、Linux 上 ARM64 约 256 MiB 的原生栈相配，只占虚拟地址；裸机见下）；回收时经目标内建导入 `栈复制` 把被调用者保存寄存器与当前原生栈复制进来，逐四字节保守扫描。
- **栈图**（提案 00020）：模块带预编客体时，降级器在每个函数入口放一条函数展开记（帧大与序言保存寄存器的次序），连接时在代码之后接一张栈图表（`冶铸` 机器编码的「写栈图表」）。执行器启动时调占位导出“栈图表复制”（新降级器把它换成复制桩，旧降级器编出的本体返回零）把表复制进动态区（`栈图` 模块「栈图表装入」，地址记在状态格 9072）；ARM64 的栈复制缓冲前 96 字节是 x19 至 x30，AMD64 前 48 字节是 rbx、rbp、r12 至 r15。编译开关「栈图诊断」为一时，每次回收在栈复制之后按表逐帧走一遍原生栈并打印帧数、停因与各帧码偏，回收照旧保守扫描。第 2 步起表里另有调用点栈图（栈图表第二版的调点项与内容，见 `冶铸` 机器编码的「写栈图表」），「栈图表装入」另取 256 字节记寄位表（状态格 9076）。编译开关「栈图核对」为一时，每次回收在栈复制之后逐帧走栈，并跟踪被调用者保存寄存器存在哪一格（栈复制头或某帧的保存格）：旗带二位的客体帧按调点项取精确根，核对每个指到堆里的都是对象起点（坏根），再逐个八字节看本帧的局部与溢出槽，数保守扫描找得到、精确根没报的对象指针（保守独有）；每次回收打印一行 `栈图核对：帧 … 客帧 … 精确 … 不精确 … 无图 … 根 … 坏根 … 保守独有 … 停因 …` 与至多若干条明细，回收照旧保守扫描。
- **精确客体帧**（提案 00020 第 3 步）：启动时「栈图表装入」以空表试调一次占位导出“栈回写”，新降级器的桩返回零，记状态格 9080 为一（旧降级器编出的本体返回负一，记零）。六十四位地址构建在有第二版栈图表、栈回写可用且编译开关「精确客帧」为一时，回收照常栈复制之后逐帧走栈（`堆` 模块「精确走栈」）：带精确调用点栈图的客体帧按栈图标记引用、不钉住，引用所在格（缓冲里的帧槽，或某帧的保存格、栈复制头里的寄存器）的线性地址记进缓冲里栈数据之后的槽表；执行器帧与没有精确栈图的帧标记局部与溢出槽，以及本帧序言保存过的寄存器此刻所在格的值；查不到函数、走出代码或到栈复制末尾时，其余的栈与各寄存器所在格一并保守扫描。保守扫到的对象在整理时照旧钉住。整理搬走了对象时，「精确改写」按槽表改写缓冲里的格，回收函数再直接调用“栈回写”桩：它与栈复制同在回收函数这一帧，sp 相同，把表里改过的帧槽按缓冲偏移写回原生栈，并把仍只在寄存器里的引用（走栈时没有哪一帧保存过，回收函数自己也不用）按掩码装回寄存器。整理压力打开时，搬移与改写之后把疏散的块填成 0xEE（「整理毒化」），漏改的引用一用就读到毒值。三十二位构建与开关为零时照旧整段保守扫描。
- **堆**：小块分配从游程里递增切出（游程取自堆顶的一段或空闲大块；都没有时取不小于所需的最大小类空闲块整块作游程，余下的由预编二的内联分配接着切，碎堆里不再一次分配调一次执行器），结束游程时按实际用量计入已分配字节数。回收只用标记位图（不写对象头），清扫后把标记位图拷成对象起始位图。
- **分代回收**：标记位图在回收后保留，已标记的对象就是老对象；第零次及每八次做全量回收，其余次要回收只标记新对象。写屏障是卡表（每 512 字节一字节）：struct.set、array.set 写引用前用内在九十一万、九十二万（窥看次顶、第三项的对象），引用数组的 array.copy 之后用内在九十万（弹出目标数组），把对象头所在的卡写零，ARM64 三条指令（ldr 卡表、add 加址右移九、strb wzr）；预编与解释器、宿主的 `设元组项` 用普通指令记卡。次要回收只扫描既脏又有老对象的卡（老卡表：清扫时给每个存活对象的卡记一）上起始的老对象。分配取不到空间时：上次回收以来分配的量不到先增堆界就先增长堆（回收刚做过，再收腾不出多少；非移动的堆碎片多时大块屡屡取不到，原先每次先回收，回收空转）。先增堆界在宿主上的非工作进程是回收阈本身，在裸机与编译器工作进程是回收阈的四分之一（提案 00020 第 2 步：最终链接按四分之一的界每轮只分配到阈的四分之一就因取不到中等大小的块而回收，回收次数翻倍；改后原生生成豫构回收约 230 → 85 次、墙钟约减四分之一到四成，峰值内存约多三成）；到了界时先照常回收一次、仍不够再增长堆；堆已到内存上限时强制做一次全量回收（次要回收不收老垃圾），之后仍不够才报堆内存不足。回收下限：编译器工作进程（命令行第一个参数是 --mode=worker）固定 64 MiB，其他进程从 32 MiB 起每次回收翻倍到 1 GiB（裸机到 256 MiB）；完整构建要起一千五百多个短命工作进程，下限一律 1 GiB 时它们不等回收就把全部分配落在新页上（本机一次完整构建缺页 6300 万次、系统态二百多秒），现在是一千多万次、三十多秒，单进程冷编不变。回收阈与回收后预留按存活量的三倍（回收倍数）定：原先阈值虽是两倍存活，堆限只预留到“存活＋下限”，实际约每分配一倍存活就回收一次；存活量大的任务每次清扫都要重走全部存活对象，次数一多就贵。改后编译器最终链接回收 26 → 13 次、指令 −26%，最慢的类型检查任务指令 −20%，代价是这两个任务的峰值内存多五到七成。原生的线性内存上限是 65535 页（约 4 GiB）；六十四位地址构建是 2^30 页（64 TiB），见下节。
- **复制式新生代**（提案 00020 第 4 步）：六十四位地址构建在精确客帧可用且编译开关「新生代开」为一时打开（新生记录在状态格 9084）。堆开头留一段新生区（小内存裸机保留 64 MiB，其余 1 GiB，只占虚拟地址；编译器工作进程短命、存活多，不开新生代，常驻工作者也不开），老区与堆顶从它之后的 2 MiB 边界起。不超过 256 KiB 的对象在新生区里碰撞分配（游程是新生区里钉住的对象之间的空隙，预编二的内联分配照旧用游标、游限），更大的直接在老区分配，并记进新大对象表（至多 65536 项），次要回收没标记到的当轮释放（保守根指到它内部也算标到），放不下的留给全量回收；新生区起始用 16 MiB，次要回收后老区跨度超过它的两倍时翻倍。新生区用完时做次要回收：先标记保守根（值栈、执行器帧与没有精确栈图的帧、全局与表等），落在新生区里的对象原地钉住（候选字指到对象内部也算）；再处理客体帧的精确根、脏卡上的老对象与标记栈：新生区里未钉住的对象复制到老区（旧头第 31 位置一表示已转发，新址写在 +8），老区里上次回收以来新分配的对象原地标记；复制出来的对象逐个扫描。之后由栈回写桩写回客体帧的根，新生区只剩钉住的对象，起始位图换成标记位图，对象之间的空隙重新排成游程，卡表全部置净。晋升与直接在老区分配的字节计入分配计，到了回收阈（三倍老区存活）或有强制、整理请求时，次要回收之后接着做全量回收：清标记位图、从根重新标记，按需整理，从老区起点清扫，再重置新生区。macOS 后台清扫与常驻清场都从老区起点起（常驻清场另清新生区用到的部分）。标记栈溢出后的重扫改按标记位图逐个取已标记的对象。整理压力下新生区的空隙填 0xEE。

## 六十四位地址：64 TiB 以上的回收堆

```sh
./豫构。林檎。豫行 构建 客体二号 --输出 执行器。树码
```

执行器入口声明 memory64（最大 2130706432 页），工具链只用这一种构建（2026-10-13 起），实际上限由降级器按平台定：macOS 与 Linux 68 TiB，裸机 AMD64 127 TiB。回收堆从 4 GiB 以上开始，一直用到这个上限（两张位图与两张卡表按上限预留，macOS 与 Linux 上约 2.4 TiB），所以堆本身能到 64 TiB 以上。Windows 与 macOS x86-64 的上限是 8 GiB（Windows 入口用 VirtualAlloc 一次提交，macOS x86-64 是数据段里的零填充区），回收堆约 3.7 GiB；这两个平台按需映射、堆更大，留待后续版本。

三十二位构建保留，用来做性能对比，工具链不启用：加编译开关 `--三十二位地址` 构建，`./豫构。林檎。豫行 构建 客体二号 --输出 执行器三二。树码 -j 24 -- --三十二位地址`；以它为 `--执行器` 编出的程序就是三十二位版（4 GiB 堆，引用四字节），例如 `./豫构。林檎。豫行 构建 豫构 --输出 豫构三二。林檎。豫行 -j 24 -- --目标 本机 --执行器 执行器三二。树码`。

- **址与引用宽度**：堆地址、对象引用、堆的大小与回收计数都写成“址”（`库/底层库/址运算`，执行器里是 i64）。引用宽度 W 取自 `基础` 的 `引宽于 零`（8）。它把参数原样转给原语，调用处直接是常量，热路径上的小函数照旧能被原生降级内联。
- **对象布局**：对象头 8 字节（字零是类型号、实例号与种类，字一是总字节数，单个对象小于 2 GiB）。结构的引用字段占 W 字节、按 W 对齐，其余字段占 8 字节；数组依次是头、长度 4 字节、填充 4 字节、元素，引用元素占 W 字节；表项占 W 字节，表描述每表 16 字节；全局变量与值栈每槽 8 字节，引用占低 W 字节。i31 引用与函数引用按 32 位算好再零扩展，空引用是 0。
- **宽格区**（8448–9215，每格 8 字节，一律用 `读址`、`写址` 读写）：游标 8448、游限 8456、位图偏 8464、卡表 8472；堆基 8480、堆顶 8488、堆限 8496、位图基 8504、位图字节 8512、游起 8520、分配计 8528、回收阈 8536、活字节 8544、回收下限 8552、扫描中 8560；自由表从 8576 起 33 格（每格 W 字节）；老卡 8840、输入缓冲 8848、请求参一 8856、请求参二 8864、远程结果 8872；输出捕获组 8880 与错误捕获组 8896（每组 16 字节：引用槽 8 字节，+8 长度，+12 容量）；临时根从 8912 起 16 格（每格 W 字节）；中转区从 9040 起 3 个槽（每槽 8 字节：低址、容量）。8480 起的 360 字节是回收格，重启准备时清零。预编栈顶（1520）、全局表（1080）、表描述（1088）等四字节格存放低于 4 GiB 的地址。
- **内存布局**：模块窗口、状态格、动态区（`取区域`）、各种栈与表、实例记录都在 4 GiB 以下，动态区的顶越过 4 GiB 时以 120 退出；两张位图从 4 GiB 起，卡表与老卡表紧随其后，回收堆再接在后面，所以堆地址都在 4 GiB 以上。内存长不到为页上限预留的位图与卡表时，页上限减半再试（不低于 8 GiB）。
- **平台边界**：平台接口的地址参数是三十二位，宿主原语经低址中转缓冲转手：`中转缓于 槽 长` 在动态区取缓冲（四个槽：路径、数据、第二个路径、显示画面；至少 64 KiB，八字节对齐并倍增，位于动态区末尾时原地扩容，否则另取缓冲），`低址副本` 把堆里的字节拷进缓冲，`低址目标` 与 `低址回写` 把平台写进缓冲的结果拷回堆；文件读写按 1 MiB 分段。
- **子任务表与异步表**：每项的捕获组 16 字节（引用槽 8 字节），子表项长 192 字节（+40 起是子程序显示代办的字段，+120 起是交互子程序的输入通道，+144 起是外壳请求队与外壳来信队，+176 起是初始任务替子任务起的子进程），异步项长 128 字节（+72 起是原生子程序显示代办的字段），异步表 131072 字节；异步项保存退出峰值及其可用标志。
- **回收**：保守扫描每个址宽读一个候选字，标记栈每项一个址宽。原生的标记栈 16 Mi 项（裸机 128 Ki 项）；结构对象的第一个引用字段最后入栈，列表单元的“首”先扫，栈深不随列表长度增长。清扫记录（64 字节）的 +40、+48、+56 是下段分界与两段存活字节数，各 8 字节。空闲块的长度写在四字节头字里，超过 1 GiB 的空隙按 1 GiB 切开再放回；单个数组载荷的上限是 2 GiB 减 64 字节。
- **原生生成**：六十四位执行器经数值转译（导出“预编二起号”），`库/裸机后端/系统构造` 把大客体的启动前奏（增长内存、从被动段复制客体）接在已有的窄入口“启动”开头。

## 装载单元（提案 00003 第 2 步）

`单元装载。底层。豫` 给豫构的「运行」提供装载单元用的原语 186–191（经「营造」的带类型导入调用，见 `库/营造/营东道。接口。豫`）。单元装进实例零：执行器只做随实例零内部布局而变的事，解析单元文件、规范化类型、解析跨单元名字与重定位都在豫构里用豫言做（`豫言操作系统/裸机/库/冶铸/单元装入。豫`）。

- **屏块与行在桌面**（2026-10-19，提案 00039 第三步，`屏块`、`子程序显示原语`、`显示代办`）：林檎与林纳原生上，行在起的桌面（环境变量 `YY_行在屏` 有值，见 `行在屏主`）是屏幕的主人。它在主机任务里分配子表，每次提交画面也把画面写进共享的屏块文件 `~/.豫言/行在/物块`（文件头 64 字节：魔数 YXP1、宽、高、帧号、主人进程号、注入写位；+64 起是一千零二十四项、每项八字节的注入环；2 MiB 起是像素，至多 4096×4096），取事件时先取注入环里别的任务写进来的拟入（种一按键、种二指针位置、种三鼠标键与滚轮），译成显示事件。别的任务的「截屏」（公共观屏）读屏块的像素与尺寸，「点击」「按键」等（屏键拟入）往注入环里写。屏块文件全用 pread、pwrite 读写；状态格 3420 记它的句柄，3424 记一百二十八字节的屏块区。林纳上没有显示，桌面登记了显示面尺寸以后（`屏块可显`）显示原语全走屏块：尺寸照授权、像素比为一、取事件按十毫秒一步等注入、到期给计时事件，因此无头的林纳也能开桌面、截屏；林纳的字体取系统里的思源字体（Noto CJK，见显示原语的「字体林开」），字体表放在裸机字体表区。桌面的每个窗口由桌面程序（环境变量 `YY_桌面程序` 给的本机程序，九宫据此用外部程序格）在自己的进程里运行，经管道代办（182–185）显示：子程序那两端管道在起之前设成可继承；外壳请求与来信也走同一对管道（画面管上消息类型 4 是外壳请求，事件管上记录类 11 是外壳来信，子程序这边改写成显示计时记录交给九宫），父进程把请求放进该子程序子表项的 +144 队、把 +160 队里的来信送出，与裸机同一套精确根；183 直接交出常驻画布，不再每帧拷贝。加入了行在的子程序由 `子程序起核` 补上 HOME 与 YY_附庸，桌面程序还补上可写的「桌面」授权（根句柄 3）。关机、重启（电源原语 241、242）在原生上问行在服务 241（息）、242（更始），行在结束全部任务后退出或重起。

## 后备熵源（2026-10-14）

处理器没有随机指令（RDRAND、RNDR）时，安全随机字节串（原语 98）由 `熵池。底层。豫` 产出，ThinkPad E40（Arrandale）与 QEMU 的 qemu64、cortex-a53 上也能做 SSH 握手、TLS 与主机钥生成。

- **熵池**：布局 `状态熵池`（9424 起 176 字节）里 32 字节的沙256 状态，加出计、已播标志、事件熵、存种秒与 128 字节消息区。
- **播种**：首次取用时混进任务号、时钟滴答、墙钟秒、周期计数、事件熵与数据盘上的种子文件 `/系统/随机种子`（前 64 字节），再采 512 次计时抖动（读周期计数、搅一段内存、再读，差值进池，每 16 次求一次沙256）。
- **周期计数**：目标内建导入“周期计数”，AMD64 是 RDTSC，ARM64 是 CNTVCT_EL0，各取低三十二位。
- **事件熵**：小睡醒来（时钟与设备中断的时刻）、按键、收包时把周期计数混进事件熵格（`平台` 的 `记熵事件`，网络栈的 `收包记熵`）。
- **种子文件**：播种后立即由池单向导出 64 字节写进 `/系统/随机种子`，此后每小时再写一次；壳命令「关机」「重启」动手前也写一次。下次开机读入的是新种子。
- **取数**：每 32 字节出计加一，把池、出计、周期计数、任务号、滴答、事件熵求一次沙256；取完池再单向更新。复制出来的子任务带着父任务的池，取数时混进自己的任务号与周期计数。
- 处理器有随机指令时照旧用它；原生平台照旧用操作系统的随机源。获取随机整数与获取随机小数（原语 96、97）照旧退用备用随机四字。

## 数据盘扩容（2026-10-14）
