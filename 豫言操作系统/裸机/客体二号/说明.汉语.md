用户态豫言客体执行器二号，以**底层模式**的普通豫言编写（旧的括号式 `.低阶` 源码由此取代）。它解释执行普通豫言编译得到的 WasmGC 模块：栈机解释器、分配与标记清扫回收、异常、结构与数组、宿主原语（输出、文件、命令行、同步子进程）、持久文件系统与 Virtio 块设备驱动。

## 构建

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 客体二号 --输出 /tmp/yy客体二号.wasm
```

产物是标准 Wasm 模块（导出 `启动`），由验证工具 `豫言操作系统/裸机/普通豫言验证。豫` 读入后追加客体模块与标志数据段，生成裸机镜像。内存布局常量（`布局`）的地址与验证工具约定一致，不得随意改动。

## 模块

`构建摘要` 补齐构建基础的 `获取当前程序SHA256` 与 `获取文件SHA256` 宿主导入，使用普通豫言底层三十二位运算返回小写十六进制摘要。当前程序取本实例嵌入的 Wasm 内容；文件摘要取指定路径的内容。AOT 程序的命令行程序名仍指可执行容器，核对程序摘要时须指定原始 Wasm 文件。

`布局` 内存布局与状态格常量；`基础` 输出、变长整数、内存与宽整数助手；其余模块依依赖顺序排列。语言约定见 `应用/豫言编译器/文档/底层模式.汉语.md`。

`域名报文` 用普通豫言底层模式写 DNS 单问题查询及 A、AAAA 回答的编解码，支持回答名的压缩指针；原生进程在 Linux 上经 UDP 使用它。固定报文探针覆盖两种记录及无效指针。

## 启动

`入口` 的 启动一次 先运行客体模块的 `_start`（按测试名运行时改为该名的导出），处理完挂起的请求后，若入口模块还导出了应用提供的 `豫言操作系统启动/启动程序`（→元），并且不是按测试名运行、没有待重启、本任务也不是复制出的子任务，就接着以空参数调用它；没有这个导出就不调。取消外调之后应用的主体在这个导出里，`_start` 只初始化各模块；导出里未接住的异常由编译器生成的包装交给与 `_start` 相同的未捕获处理（打印后以 1 退出）。

## 豫言操作系统底层接口：裸机后端

`裸机底层状态码`、`裸机底层基础`、`裸机底层句柄`、`裸机底层文件`、`裸机底层终端`、`裸机底层网络`、`裸机底层进程` 七个模块，是[豫言操作系统底层接口](../../../豫言操作系统底层接口/总纲.汉语.md)在裸机上的实现（45 个函数，方案见[底层接口方案](../../../文档/豫言操作系统底层接口方案.汉语.md)）。它们是**新增、独立**的模块：直接复用既有的文件系统（`fs读文件`、`fs写文件`、`fs建目录`、`fs删除`等）、控制台（`读字节`、`读行`、`打印串`）与时钟（`时钟滴答`、`墙钟秒`）原语，不改动这些既有实现；入口只在启动时新增一次 `底柄_初始化` 调用（在固定状态格 3664、3668 保存动态句柄表地址与终端模式；表头保存行输入剩余状态，经 `取区域` 分配句柄表、路径缓冲与内容缓冲，暂存缓冲仍供文件和时钟操作临时使用）。

子任务重启会清空动态区；`重启准备` 同时清除旧句柄表指针，下一次启动重新分配句柄表并建立根句柄 3。当前子任务没有块设备，底层文件操作仍需由初始任务经独立邮箱协议代办；GC 文件原语已有自己的对象协议。

- **句柄模型**：句柄 0/1/2 是标准三流；句柄 3 恒为根目录（唯一的预开目录）；4 起的 13 个槽按需分配给已打开的文件与目录，每槽有独立的路径缓冲（22400 字节）与内容缓冲（409600 字节，整文件缓存）。底层文件另从动态区取得临时路径和数据缓冲。
- **路径解析**：相对目录句柄解析，不含当前目录，`..` 越出目录句柄子树报错，与既有 `主机文件` 里依赖“当前目录”状态的路径规范化是两套独立的逻辑。
- **已知限制**（均已在各文件的双语注释里逐条注明）：`底层网络`、`底层进程` 全部返回“不支持”（网络因裸机无网络栈；进程因桥接既有的 GC 对象参数子进程机制不在本轮范围）；`建管道`、`取终端尺寸` 返回“不支持”；`填随机字节` 读处理器随机数（ARM64 RNDR、AMD64 RDRAND，目标内建导入“硬件随机”），处理器不支持时返回“不支持”；文件与目录内容缓存上限 409600 字节，超过则相应操作返回“溢出”；单调时钟精度 10 毫秒（内核滴答），墙钟精度 1 秒（RTC）。
- **GC shim 的改接**：控制台输出原语（1–4 号）经本接口的 `写`；Linux 上的文件原语经本接口的 Linux 后端（见下节）。裸机上的文件原语仍直接用执行器内的文件系统（待办事项：放大整文件缓存的上限后改经本接口）。

## 多平台：同一份执行器在 Linux 与 macOS 上运行

执行器是同一份整数 Wasm 模块，由寄存器降级按目标生成裸机镜像、Linux 可执行文件或 macOS 可执行文件。运行时靠目标内建导入 `导入：目标：平台号`（降级时绑定为常量：裸机 1、Linux 2、macOS 3）选择平台实现；其他目标的导入降级为陷阱桩，不会被执行。各平台的导入都声明在 `平台接口/` 的接口文件里（`林纳克斯`、`苹果`、`视窗`、`平台`、`目标`），导入模块名就是接口文件名。

- `林系统`、`苹系统`：Linux 系统调用包装（导入模块名“林纳克斯”）与 macOS libSystem 包装（导入模块名“苹果”，返回 -1 时导入桩已换成 -errno），以及 `是林`、`是苹` 与各自的 errno 转换表（两个系统的 errno 编号不同）。`原生系统` 在两者之间分派写、读、退出、时钟与终端判断。
- `平台`：写字节、读字节、退出、时钟滴答、墙钟、中断查询在原生系统上改走系统调用或 libSystem；任务与邮箱服务在原生系统上尚未实现，按失败返回（待办事项）。
- `林启动`、`苹启动`：启动时写程序名区、参数区与环境块。Linux 读 `/proc/self/exe`、`cmdline`、`environ`；macOS 用 `sysctl` 的 `KERN_PROCARGS2`（缓冲是启动时新增长的两页）。之后的宿主原语不必区分平台。
- `视窗系统`、`视窗启动`、`视窗底层`：Windows（平台号 4）。系统入口经 kernel32、ntdll、bcrypt（导入模块名“视窗”）；标准流读写、单调与墙钟（64 位计数用本模块的逐位长除与 MulDiv 换算）、UTF-16 与 UTF-8 互转；启动时由 GetModuleFileNameW 与 NtQueryInformationProcess（命令行）写程序名区与参数区（按 Windows 规则拆参数），路径写成执行器内部的 `/C:/a/b` 形式；暂存区（1 MiB，前 256 KiB 保持 Linux 布局）与 Linux 后端共用同一个状态格。文件（CreateFileW 等，旗标 FILE_FLAG_BACKUP_SEMANTICS|FILE_ATTRIBUTE_NORMAL）、环境变量（GetEnvironmentVariableW）已实现。`视窗进程`：建管道（CreatePipe）、运行程序（CreateProcessW，按 MSVCRT 规则拼命令行，环境块转 UTF-16，三个标准流临时设为可继承）、进程表（与 Linux 同布局）、取退出码、终止、关闭与轮询式等待（进程、管道、控制台、套接字）。TCP 经 ws2_32（套接字登记表区分套接字与其他句柄，Winsock 错误码按 Linux 映射对齐）。导入参数类别 5 为可空指针。待办事项：Windows 的 hosts 与 DNS、控制台模式、目录句柄与工作目录句柄。
- `林底层`、`苹底层`：底层接口 45 个函数的 Linux 与 macOS 后端，`原生底层` 按平台号在两者之间分派（函数名加前缀“原底_”）；裸机后端各函数开头在原生系统上转到这里。句柄就是文件描述符，3 号是根目录“/”。Linux 打开用 `openat2` 加 `RESOLVE_BENEATH`（越界返回 76），`ENOSYS` 时逐段用 `O_PATH|O_NOFOLLOW` 解析；路径状态经受限句柄查询，建删、改名和读链接先安全打开父目录，双架构路径探针通过。macOS 打开用 `O_RESOLVE_BENEATH`，路径状态用 `AT_RESOLVE_BENEATH`，其他路径操作先受限打开父目录；本机 ARM64 路径探针覆盖树内链接、越界链接及文件变更，均通过。状态分别取自 `statx` 与 `fstatat`，目录分别取自 `getdents64` 与 `__getdirentries64`。待办事项：Linux 旧核逐段回退与两平台父目录打开后的并发更名竞态、旧版 macOS 不支持边界标志时的回退。终端模式：Linux 用 TCGETS/TCSETS，macOS 用 TIOCGETA/TIOCSETA（原始模式与 libuv 相同）。
- `原生进程`：两个系统共用的进程、等待与网络实现，系统差别集中在“进_”开头的小函数里。运行程序：fork（Linux 用 clone(SIGCHLD)），子进程接好标准流与工作目录后 execve，失败时经 O_CLOEXEC 管道把 errno 告诉父进程；进程句柄从 2^30 起编号，进程表在暂存区。等待用 ppoll（macOS 用 poll），进程订阅每轮检查（有运行中的进程时每轮至多等 10 毫秒）。TCP 支持 IPv4、数字 IPv6、localhost 与 `/etc/hosts` 名表；Linux 和 macOS 均依次尝试 `/etc/resolv.conf` 中的服务器，以 UDP 查询 A、AAAA，原名未解析时依次拼接 search 或 domain 后缀。Linux 空主机监听双栈，macOS 空主机仍用 IPv4；macOS 的 resolv.conf 未必涵盖系统全部 DNS 路由（待办事项：系统 DNS 路由接入、IPv4 嵌入式 IPv6 地址、区域号）。启动时忽略 SIGPIPE，子进程在 execve 前恢复默认。启动顺序上，底层句柄表与原生后端暂存区都用 `取区域`，必须在 `初始化堆` 之前（之后的区域顶就是堆起点，会与堆重叠）。
- `原生子进程`：原生系统上的同步子进程原语 43–46（程序名按 PATH 解析，经 `运行程序` 启动；45 接 /dev/null，46 用两条管道同时读取标准输出与标准错误）。切换当前目录时同步进程的真实工作目录，子进程因此在同一目录运行。异步子进程 67–69 也在这里：子进程表（至多 1024 个）在启动时用 `取区域` 分配，回收时整表作为根扫描；两条捕获管道设为不阻塞，收取与等待时读尽现有数据并查询退出码，等待时用底层接口的 `等待` 同时等全部管道与进程句柄，行为与 Node 宿主相同（豫构调度器测试在原生宿主上与 Node 输出逐字相同）。待办事项：设置子进程输入、环境（70、71）尚未接到原生系统。
- macOS 的底层运行程序通过 `posix_spawn` 启动子进程，以文件动作接标准流和工作目录，以进程属性恢复 SIGPIPE 默认处理，参数与环境沿用原来的指针表。启动成功后照旧登记进程句柄，失败返回原来的底层状态码；无需复制父进程堆或等待后台清扫。切换目录动作要求 macOS 10.15 及以后。Linux 的 clone 与错误管道路径沿用原实现。
- `原生网络原语`：TCP 宿主原语 77–90（语义同 Node 宿主：不阻塞，返回（状态，值）），在原生系统上经底层网络包实现；裸机返回 -58。
- 字节串原语：91 号 `豫言_字节串_截取`（从起点取定长字节成新串，越界时以 134 退出）在各平台由执行器直接实现，原生运行的编译器写出产物时要用它。11 号“运行于MacOS”在 macOS 上返回真。
- `原生文件原语`：原生系统上的文件宿主原语，路径仍由 `规范参数` 规范成绝对路径，再经底层接口访问宿主文件系统；启动时当前目录取自 `/proc/self/cwd` 或 `getcwd`。
- `WASI名称` 与 `WASI分派`：识别 WASI preview1 的 46 个函数名，已实现参数与环境读取、时钟、随机数、标准流与文件读写、预开根目录、路径打开与变更、句柄及路径状态、寻址与定位读写、目录读取、等待与退出。时钟、流、文件和等待调用经底层接口；裸机尚无熵源，随机调用返回不支持。未实现的调用返回 ENOSYS。函数表分配后清零，使本地函数与导入函数准确区分。22 个现有样例各至少在一个原生目标运行过；其中 `文件测试`、`文件边界`、`睡眠` 的 Linux 双架构标准输出经 `cmp` 验证逐字相同，`出入` 的双架构标准输出与标准错误也分别逐字相同。全平台与参照实现的逐字一致性仍待验证。
- `带型名`：带类型的宿主导入（取消外调之后，标准库、构建基础、豫言裸机三包的宿主服务直接编成带类型的 Wasm 导入，共 76 个；另有可移植的显示接口 6 个、字体接口 4 个，见下条）。实例化时按（模块，字段）查表，绑成第 4 类宿主导入（函数条_链接函数 存原语号与标志）；调用时（`主机` 的 `带型调用`）按导入的 Wasm 签名把 i64 装箱成 i31 或 $big、f64 装成 $float、i32 装成 i31、引用照传，组成原语现有的参数元组，结果再按签名拆回；“列”参数与（数组，长度）结果按表中标志转换。原语 93–101 只经带类型导入调用（终端按键与原始输入模式暂报不支持，随机三项经底层熵源，拼音暂原样返回，绘监视面板为空操作）。同一模块里带类型导入与 gc-host.call 可以并存。原语 47（加载模块）与 48（调用导出）的结果由办理请求的一方事后写回：经带类型导入调用时，带型调用 不拆占位结果、置 状态_请求带型；调用导出把帧钩加 4；驱动循环按 i64 原样写回结果（i32 结果、加载模块返回的实例号或负的错误码都符号扩展），不装箱。
- `原生槽区`、`苹显示`、`裸机底层显示`、`显示原语`：原生窗口（macOS arm64，见[原生窗口方案](../../文档/原生窗口方案.汉语.md)）。`原生槽区` 是 32 KiB 常驻区（原生指针与 double 的 8 字节槽、串缓冲、显示面表与事件队列，布局见该文件注释）；`苹显示` 在运行时 dlopen AppKit，原生调用都经 `平台接口/苹果。接口。豫` 逐个声明的函数（objc_msgSend 按签名分开）：建窗口，画面做成 CGImage 设给内容视图的图层，取事件每次至多等 0.25 秒（超时就查窗口是否已关），输入法经透明的 NSTextView 组字；`裸机底层显示` 是底层显示包的 5 个函数（其他平台返回 58）；`显示原语` 是显示接口（6 个）与字体接口（4 个）的带型导入原语 102–111，以及宿主选项 `--授权显示面 名=宽x高`（可重复）、`--显示面后台`（窗口不激活、放在其他窗口之后）的解析：在 `启动一次` 里、`初始化堆` 之前从参数区开头取走，占去的参数也不交给程序。字体按族名打开系统字体文件（无衬线：华文黑体、Arial Unicode；衬线：宋体；等宽：Menlo），用 pread 分段读取。
- 生成与验证：`yy原生生成 Linux|苹果 臂六十四|兼容六十四 执行器.wasm 输出 客体.wasm` 把客体模块嵌进执行器，得到独立可执行文件（macOS 目前只有 arm64）；`yy原生一致性`（`豫言操作系统/裸机/原生一致性。豫`）把普通探针与文件探针在 Linux（两种架构；非 Linux 系统上加 `--经 docker`）或 macOS（`--系统 苹果`，本机运行）上运行，与裸机验证所用的期望输出逐字比较。

## 预编：WasmGC 函数直接成为机器码（路二乙档第一版）

`yy原生生成 … 执行器.wasm 输出 客体.wasm --预编`（或 `yy原生一致性 --预编`）把客体 WasmGC 模块的每个函数转译成一个整数 Wasm 函数，并入执行器模块后一起经寄存器降级生成机器码；执行器照常解析模块、建类型表、初始化全局与数据，但不再解释函数体。转译器在 `库/裸机后端/预编转译。豫`，执行器一侧的运行时接口在 `预编接口。豫`。

- **值都在值栈上**：布局与解释器相同（每槽 8 字节，引用与 32 位整数在低字），所以保守回收照常看得见；转译函数的签名是（帧）→ i32，参数与局部变量从帧起，操作数栈在其上，调用者把参数放在栈顶、被调用者的帧就从那里开始。
- **简单指令内联，复杂指令调解释器的处理函数**：局部变量、常量、i32 运算与比较、少数 i64 指令、引用判空与相等、控制流直接写成整数指令；结构、数组、类型转换、i64 其余与浮点、访存、表与杂项指令调用执行器导出的“预编_”函数（就是解释器的指令处理函数），传入立即数在模块字节中的地址。
- **控制流一一对应**：块、循环、条件对应整数 Wasm 的同名结构，分支先把携带的值搬到目标槽；尾调用（return_call 及间接、引用尾调用）先把参数搬到帧首，再“调用后立即返回”，寄存器降级把这种形状变成尾跳；间接调用经执行器导出的 `预编派发`（按函数号二分，叶子上尾跳到转译函数）。
- **异常用标志传播**：抛出时记下载荷并置 `状态_预编异常`，每次调用转译函数后检查，在尝试表里就跳到它的处理代码，否则返回；最外层仍有异常即按未捕获异常退出（137）。
- **大模块**：超过 448 KiB 模块窗口的客体（如编译器）不嵌入窗口，而作为尾块写进可执行文件（Linux 附在文件末尾，macOS 放在 __LINKEDIT 里签名之前），执行器启动时读回到动态区开头；Linux 代码太大时单独放一个载入段（ARM64 在 0x10000000，x86-64 在 0x50000000）。
- **降级器随之扩充**：“调用后立即返回”变尾跳；每 512 KiB 代码插一个陷阱岛，越界与除零检查跳到最近的岛；大函数（超过 2 万条指令）的条件跳转改用“反条件跳过 + b”；汇编器只在条件分支上计算 19 位位移（原先 b、bl 超过 1 MiB 也会误报超程）。

现状（2026-09-28）：macOS arm64 上普通探针、文件探针与原生探针共 12 项在预编模式下与参照输出逐字一致；短程序比解释执行快约两倍（多为启动开销）。待办事项：内联更多热指令（ref.cast、struct.get、array.get、i31）、非引用值留在寄存器里、Linux 上的预编验证、编译器本身的预编与原生自举。

续记（2026-09-29）：Linux ARM64 的完整预编一致性组 15 项通过，普通、文件与原生探针均与裸机或 Node 参照逐字相同。Linux x86-64 的解释模式打印探针通过；同机 Docker 的 Rosetta 在装载较大的预编产物时报告 `failed to mmap segment: 22`，尚须在真实 Linux x86-64 运行器上验预编。编译器自身的原生自举仍待完成。

## 预编二：客体的值放进寄存器与原生栈（路二乙档第二版）

结构对象头宽八字节。引用字段宽四字节，其他字段保留八字节，各字段按自身宽度对齐，对象总长按八字节对齐且至少十六字节。继承字段从完整字段序列计算偏移，父类型末尾的填充不参与子类型字段偏移。值栈槽宽八字节，引用读入值栈时高字清零；数组布局保持原有约定。执行器与预编生成器须使用同一份结构布局，变更布局后须成套重建，已有原生可执行文件保留其内嵌执行器和生成代码。

`yy原生生成 … 执行器.wasm 输出 客体.wasm --预编二` 用新的转译器（`库/裸机后端/预编二转译。豫`）。与第一版的区别：

- **客体的值不再放在执行器的值栈上**：每个客体函数转译成一个宽整数函数（`库/裸机后端/宽降级原语。豫`），参数、局部变量与操作数就是这个函数自己的参数、局部与操作数；每个值六十四位（i32 与引用零扩展），由寄存器降级放进寄存器与原生栈帧。i64 运算写成内在调用，降级器就地展开为六十四位指令。
- **调用直接传参**：客体函数之间直接调用；call_ref 与 call_indirect 经跳表零（每个客体函数一项）；执行器经 `预编派发` 调用客体函数时走跳表一里的适配函数（从值栈帧读参数、写回结果）。客体导入由导入桩经 `预编_调用导入` 调用执行器。
- **内联的热指令**：结构与数组的读写与长度、i31、判空、精确类型的 ref.test/ref.cast 直接写成整数指令；struct.new、struct.new_default 与 array.new_fixed 在当前游程里碰撞分配（游标、游限两个状态格；新游标用常址写四写回，两个头字拼成一个八字节常量一次写入，对象起始位由专用内在置位，ARM64 八条），不够时调用 `预编_分配`。按常数下标的数组取值不装下标：长度直接与常数比较，元素按立即偏移读取。下标已知小于数组长度时（转译事实：br_if 落空路径上“下标局部无号小于某局部”，且那个局部是该数组的 array.len）不查界。其余指令把操作数写进执行器值栈的暂存区（起址在 `状态_预编栈顶`，由适配函数设置），再调用解释器的处理函数。
- **转译时内联**：直接调用或直接尾调用另一个客体函数，且其代码体不超过 60 字节、不含尝试表与旧式异常指令时，不发调用，而在调用处接着转译它的体。参数与局部借一段块临时，实参弹进参数、其余局部清零，体包进一个结果数相同的块；被调函数里的 return 跳出这个块，尾调用改成普通调用加异常检查再跳出；展开在尾调用处时，二者照旧是调用者的返回与尾调用，块后补一个返回。转译事实（非空、类型、界）因此跨过函数边界。只内联一层，不内联自己。降级之前另有整数层的小叶函数内联（`库/裸机后端/内联小函数。豫`）。并入时客体定义函数只放占位（签名、零个局部、空体），降级与整数层内联要用函数体时才经 `降级取体` 的钩转译：内联准备只留下不超过内联上限的小函数体，大函数只留占位，降级完就把钩复位；遍历两万多个函数用尾递归的带序映射（标准库「态射序号」经「态射二」非尾递归，原生保守扫描时两万多层栈帧里留着各函数降级的临时数据）。这样原生程序跑原生生成时，同时存着的只有执行器自身的中间表示、小函数体与已降级的机器码。
- **回收看原生栈**：`预编二可用` 为 1 时，启动时预留 34 MiB 的栈复制缓冲；回收时经目标内建导入 `栈复制` 把被调用者保存寄存器与当前原生栈复制进来，逐四字节保守扫描。
- **堆**：小块分配从游程里递增切出（游程取自堆顶的一段或空闲大块），结束游程时按实际用量计入已分配字节数。回收只用标记位图（不写对象头），清扫后把标记位图拷成对象起始位图。
- **分代回收**：标记位图在回收后保留，已标记的对象就是老对象；第零次及每八次做全量回收，其余次要回收只标记新对象。写屏障是卡表（每 512 字节一字节）：struct.set、array.set 写引用前用内在九十一万、九十二万（窥看次顶、第三项的对象），引用数组的 array.copy 之后用内在九十万（弹出目标数组），把对象头所在的卡写零，ARM64 三条指令（ldr 卡表、add 加址右移九、strb wzr）；预编与解释器、宿主的 `设元组项` 用普通指令记卡。次要回收只扫描既脏又有老对象的卡（老卡表：清扫时给每个存活对象的卡记一）上起始的老对象。分配取不到空间时：上次回收以来分配的量不到回收阈的四分之一就先增长堆（回收刚做过，再收腾不出多少；非移动的堆碎片多时大块屡屡取不到，原先每次先回收，回收空转），否则先照常回收一次、仍不够再增长堆；堆已到内存上限时强制做一次全量回收（次要回收不收老垃圾），之后仍不够才报堆内存不足。原生的线性内存上限是 65535 页（约 4 GiB）。
