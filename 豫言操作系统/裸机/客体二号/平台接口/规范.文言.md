# 持久块服务

`代码块映射`（动区块序、块数）为核务六十。以二兆字节为块，核提交所指之块而映为可行；成返零，逾界或配败返负一。臂之代码块可读可行，常数据块仍不可行；核刷快表，同步指令之缓存。执行器为单元代码留独占之齐块，复制、重定位毕乃呼此务。

执行器之只读环境字段 `豫言处理器架构` 返 `arm64` 或 `x86_64`，以供系统内构建定本机之架构。

此为裸机初始任务取用 USB 数据盘（bulk-only 大容量存储）之接口，二构同之（自二〇二六年十月十一日，由豫言内核之扩展主控之驱供之，见 `豫言操作系统/裸机/内核/扩展主控。底层。豫`）。服务号二十八至三十一，各应容量、读取、写入、同步。容量报数据区之五百一十二字节扇区数（至多二十一亿四千七百四十八万三千六百四十七），无数据盘或呼者非初始任务则报零；读写与同步，零为成，一为设备之请败，负一为拒。

读写凡三参：始扇区号（自数据区计，无号）、呼者线性内存中之址、长（字节）。长为五百一十二之倍而非零，`[始扇, 始扇 + 长/512)` 在数据区之内，`[址, 址 + 长)` 在呼者线性内存之内（线性内存犹在静区则五百一十二 KiB，否则容乘二兆），否则拒之。惟初始任务（槽零）可呼，子任务皆拒。同步发 SYNCHRONIZE CACHE(10)，无参；盘报命败（有 U 盘不识此命）亦视为成，惟传误返一。

核依设备一命所可传之扇数分段（超速 U 盘二千零四十八即一兆，余二百四十），每段一 SCSI READ(10) 或 WRITE(10)，数据经核自有一兆之 DMA 缓冲与呼者之线性内存径拷，不经静窗；一务传几何由呼者定，长无他限。候时以主控之微帧计（每段至多三十秒），其间键鼠之报照交。bulk 端点停滞，则核复位端点、清其停而照收 CSW。

核开机探每 U 盘：TEST UNIT READY、READ CAPACITY(10)（扇长须五百一十二），复依 ext4 超级块寻数据区：第二扇偏五十六之二字为 0xEF53、偏二十四为二（四千零九十六字节之块）者是；先观盘首，否则观六十四兆（十三万一千零七十二扇）之一至十六倍处（启动 U 盘兼数据盘者，数据区在光盘之后）。首得者为数据盘，扇号与容皆自数据区计；识之不得者让位于后设备，执行器不格式化任何设备。数据盘拔则服务二十八返零、读写拒之；复插则核复探之。

兼无扩展主控（惟 EHCI）或豫言内核初置扩展主控而败者，同组之务逐扇交手书之驱（`0x7C0B000` 起五百一十二字之私缓，请字居 `0x7C09094` 起，扇数字数依一扇填之），义同，一次一扇；手书 xHCI 存储之途，其窗之验、命之备与环项之发，在共用之模 `内核/存储。底层。豫`。

执行器先择 Virtio，其初置败乃用 USB 数据盘；文件系统仍用块容量、块读、块写、块刷新，盘面为标准 ext4（见[客体文件系统](../../文档/客体文件系统.文言.md)）。整扇之大段读写，一务至多二千零四十八扇，经执行器之扇缓（见同篇“扇之缓存与光标随动”）：读则成段读入而记于扇缓，书则成段书出而直写扇缓。非裸机目标不呼此服务。

后续之事：非五百一十二字节之扇、READ CAPACITY(16)、UAS、多 LUN、择盘与分区；臂之执行器开机挂数据盘（核之一侧已能探而读写之）；实体机之验。

## 目标内建导入：页容量

`目标` 导入模块之 `页容量`，返本目标线性内存之页数上限，降级者依目标生其常数（裸机后端「目标页容量上限」）：兼容裸机六万五千五百三十五页（约四 GiB），臂裸机千二十四页（六十四兆），视窗一万六千三百八十四页，苹果与 Linux 六万五千五百三十五页。执行器起时记之为堆之页限，回收之位图与卡表依之预留；启动镜像线性内存之容，取模块所声最大页与此限之小者。六十四位址内存（memory64）之模取更大之限（裸机后端「目标长址页容量上限」）：兼容裸机二十一亿余页（一百二十七 TiB），苹果与 Linux 十亿余页（六十四 TiB），臂裸机与视窗同上。

## 装载任务与读启动块

`平台` 导入模块之 `装载任务`（启动块之线性址、长）为裸机之核之服务三十七：自开机所留用户区之模起一全新之子任务，返其句柄（不下六十四之偶数），败则返负一。启动块依所予之长原样授子任务。`读启动块`（目之线性址、块内之偏）为服务三十八：偏为负一则返启动块之总长，否则每次拷至多六十四 KiB 而返所拷之数。豫行任务由服务四十三按段装之，启动块亦以服务三十八读之。执行器所约启动块之式见 [动态任务](../../文档/动态任务.文言.md)。

## 处理器核数

`平台` 导入模块之 `处理器核数`（服务三十九）返核所启处理器核之总数。`在线处理器数量`（宿主原语六十五）用之；原生系统由执行器返一核。

## 读他任务、写他任务与任务编号

`平台` 导入模块之 `读他任务`、`写他任务`（对方句柄、对方线性之址、本方线性之址、长）为服务四十一、四十二：惟初始任务可召，于其与一动态任务之线性内存间整块拷之（四十一自彼至此，四十二自此至彼），成返零，败返负一。文件之代办以之收子任务之请、送应答，见 [客体二号](../../文档/客体二号.文言.md) 之“整块文件代办、孙任务与多异步子进程”。`任务编号` 为服务六，返本任务之句柄（初始任务为零）；父书之于启动块，子任务之捕获之信依之归父。臂之核于四十一、四十二返负一；原生由执行器径返负一，任务编号返零。

## 按段建任务

`平台` 导入模块之 `按段建任务`（描述块之线性址、描述块之长）为兼容裸机之核之服务四十三（[提案〇〇〇〇五](../../../../提案/00005-自有可执行格式.汉语.md)第三步）：依描述块为新任务建址空间而起之，返其句柄（不小于六十四之偶数），败返负一。执行器于用户态读[豫行之文](../../文档/豫行格式.文言.md)、拆段表而召之；读文拆表皆毕于用户态。

- 描述块首四十八字：+0 入口、+8 栈顶（各八字）、+16 段数（四字）、+24 启动块之线性址、+32 启动块之长（各八字），余留为零；其后每段四十八字，同豫行段表之项，惟 +24 之“文内之偏”易为段容于召者线性内存之址（全零之段书零）。块长须等（段数加一）乘四十八，段数一至二百五十六。
- 段惟居用户区 0x200000–0x3FFFFF（拷入新任务之用户区块），或依二兆对齐而全居 0x800000–0x1FFFFFF、0x8000000–0x1FFFFFFF、0x30000000–0x37FFFFFF、0xC0000000–0xFFFFFFFF 四处之一（每二兆一块，可写者用户读写，余唯读）；存长为正，虚址与长依四 KiB 对齐，容长不逾存长，容全在召者线性内存；大页之段合至多二千零四十七块。不合则负一。
- 启动块（至多十六兆）随任务存之，子任务以服务三十八取之，其式同装载任务。执行器为豫行所送之启动块惟含参、程序名与环境，子任务乃径行所嵌之客与预编之码。
- 新任务自入口起，栈针为栈顶；其主为召者，如装载任务入调度之环，终则还其诸块。

臂之核于四十三返负一；原生由执行器径返负一。

## 归还内存块

`平台` 导入模块之 `归还内存块`（起块号、块数）为裸机之核之服务四十四，二构皆有之：以本任务线性内存自第起二兆块之数块中已提交之物理块还核，返所还之数。容不易，后复触之则缺页复提交而尽清之；逾容者不问。块号以线性之偏除二兆计（线性内存迁入动区之后，偏零即动区第零块）。执行器惟于裸机（平台号一）召之：每收而扫毕，还其所空之整块，见[客体二号](../说明.文言.md)之“还内存”。旧核按未知之务返负一；原生由执行器径返负一。

`空闲内存块数`（无参）为服务四十五：返池中此时空闲物理块之数（每块二兆）。执行器于裸机每收之后据之压回收之阈（不逾空闲内存之半，不下十六兆）。旧核按未知之务、原生由执行器径返负一，执行器照常定阈。

`任务信息`（游标、目之线性址）为服务四十六：自游标起寻在用之任务，书其百二十八字之录于目，返次游标；尽则负一，越界负二。录依次为句柄、主人、状态、累计之滴答（正行者含此次切入以来者）、动区已提交之块数、定块之数、启动块之长、此时之全局滴答（各四字），后九十六字为启动块中程序名区之首（四字之长加名之字；无启动块则零）。执行器于裸机之原语百二十九（公任务监测）自游标零屡召之，尽得诸任务，以两采之差计 CPU 之用。旧核按未知之务、原生由执行器径返负一。

`读鼠标字节`（无参）为服务三十六：取鼠环之一字，环空则负一。环中皆四字之包（十月十一日起）：首字（位三恒一，低三位为左、右、中之键，位四、五为横纵之移之号）、横移、纵移（上为正）、滚轮（有号，下滚为正）。PS/2 之鼠由核开 IntelliMouse 滚轮之模而成包，USB 引导协议鼠之报由核换包；三字之 PS/2 鼠与臂之 USB 鼠滚轮之字为零。兼初呼时清鼠环，向鼠发 D4 F4 以开数据之报。裸机显示之后端依四字之包解之，交指移、按、抬与滚轮（每格四十八素）。

`鼠标位置`（无参）为服务四十七：臂之 VMware 虚拟鼠有新绝对之坐，则返横乘六万五千五百三十六加纵（屏之像素）而去其新标；无新坐或无此设备则负一；兼恒负一。裸机显示之后端每收鼠标之字前先取之，有新坐则径置光标于彼；按、抬仍以服务三十六之鼠包依次交之。

`小睡`（有信不睡）为服务五十（十月十日起）：让处理器，睡至次滴答（约十毫秒）；其间有信投至或子任务终则早醒；有信不睡非零而箱已有信，则不睡而即返。返零。单核无他可行者，核入空闲（止而候钟），处理器不复空转，任务管理亦不复记其时于呼者。执行器于裸机无可读之入则呼之：显示面候事、带子任务之显示面之候（有信不睡为一，以续收子之信）、命令壳读行、终端候键。旧核以未知之务返负一，呼者仍轮询。

`按键模式`（开）为服务五十三，`读按键`（无参）为服务五十四（十月十一日起，二构皆有）：开非零则键入事件之模，不复置字节于控台之环（串口如故），零则复文字之模，返零；主之任务终，核亦关之。读按键取一按键之事：HID 之用加按下乘二百五十六加修饰之位乘六万五千五百三十六，修饰之位依 HID（位零至三左 Ctrl、Shift、Alt、Win，位四至七右之四者），无事则负一。PS/2 之扫描码与 USB 引导键盘之报，皆由豫言内核易为此事（见[控台输入](../../文档/控台输入.文言.md)）。执行器之裸机显示后端取显示面则开，还则关，易其事为显示接口之按键之按抬、修饰之键（上档、控制、交替、命令）与文字之入。旧核以未知之务返负一，执行器仍以控台之字译按键。
