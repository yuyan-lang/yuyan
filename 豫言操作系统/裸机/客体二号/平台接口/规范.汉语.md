# 持久块服务

这是 AMD64 裸机初始任务访问内核 USB bulk-only 块设备的接口。服务号 28、29、30、31 分别对应容量、读取、写入和同步。容量返回可用的 512 字节扇区数，无设备、未授权时返回 0；读写和同步返回 0 表示成功、1 表示设备请求失败、-1 表示拒绝。ARM64 返回容量 0，其余 -1。

读写参数是无符号扇区号和静态窗编码 `静偏 | (长度 << 20)`。长度为 512 的正整数倍，高十二位编码容纳每批一至七个扇区。窗口末端位于镜像构造时授予任务零的静态范围内，起始扇区及整批扇区位于设备容量内。固定内存授初始页，可增长内存授八页；授权归初始设备任务所有。同步直接提交缓存同步命令。授权和设备探测完成后接受请求。

内核先将写入数据从 `0x300000 + 静偏` 复制到自身保留的 `0x07C0B000` 缓冲，读取成功后从该缓冲复制回静态窗。应用提交静态窗编码。每次传输一批扇区，复用 READ(10)、WRITE(10) 与 SYNCHRONIZE CACHE(10)。校验、命令准备、数据搬运和传输环项发布由两架构共用的底层豫言存储模块实现。

服务主体置于 `0x007DF000` 起的 4 KiB 外置代码页，主内核只保留调用入口；根端扫描代码限于 `0x007D0000` 起的前 52 KiB。设备初始化使主内核超过描述符表边界时，移到 `0x007DD000` 起的 8 KiB 区间，保留失败与串口调用；之后接服务页，再接 `0x007E0000` 的控制器代码。构造器检查各区长度，避免覆盖描述符表或相邻代码。

当前只使用首个匹配的 USB 大容量存储接口，尚无磁盘选择或分区接口。验收由光盘介质启动、另接专用 USB 数据盘；把启动 ISO 自身作为首个 USB 存储设备时，它也会成为探测对象；探测按 ext4 超级块识别数据盘，识别不出的候选让位给后续设备，执行器不格式化任何设备。

帧缓页目录独占 `0x11F000`，IOMMU 初始化使用 `0x11A000` 至 `0x11EFFF`，两者不共用。USB 验收路线没有启用 IOMMU，确认的是服务访问权限与设备传输；既有 Virtio 路线继续使用 IOMMU。

执行器保留 Virtio 优先选择，并在其初始化失败后尝试 USB 服务；文件系统仍使用块容量、块读、块写、块刷新，盘面是标准 ext4（见[客体文件系统](../../文档/客体文件系统.汉语.md)）；读写都经执行器的扇区缓存（2026-10-11 起，见同篇“扇区缓存与光标随动”），读过的扇区再读不再经过本服务。AMD64 启动盘授予初始执行器静态搬运窗，执行器不格式化数据盘。非裸机目标不调用这些服务。

待办事项：非 512 字节块、一次请求传多个扇区（等手写驱动迁到底层豫言）、UAS、热插拔、错误恢复、EHCI 与 AHCI 尚未实现；实体机尚未验收。

## 目标内建导入：页容量

`目标` 导入模块的 `页容量` 返回本目标线性内存的页数上限，由降级器按目标生成常量（裸机后端「目标页容量上限」）：AMD64 裸机 65535 页（约 4 GiB），ARM64 裸机 1024 页（64 MiB），Windows 16384 页，macOS 与 Linux 65535 页。执行器启动时把它记为堆的页上限，回收位图与卡表按它预留；启动镜像的线性内存容量取模块声明的最大页数与同一上限的较小者。六十四位地址内存（memory64）的模块取更大的上限（裸机后端「目标长址页容量上限」）：AMD64 裸机 2130706432 页（127 TiB），macOS 与 Linux 1073741824 页（64 TiB），ARM64 裸机与 Windows 同上。

## 装载任务与读启动块

`平台` 导入模块的 `装载任务`（启动块线性地址、长度）是 AMD64 裸机内核的服务 37：从开机时留下的用户区模板起一个全新的子任务，返回它的句柄（不小于 64 的偶数），失败返回 -1；启动块至多 2 MiB，原样拷给子任务。`读启动块`（目的线性地址、块内偏移）是服务 38：偏移为 -1 时返回启动块总长，否则每次拷至多 64 KiB 并返回拷的字节数；不是装载出来的任务返回 0。ARM64 内核对 37 返回 -1、对 38 返回 0；原生系统由执行器直接返回 -1 与 0。执行器约定的启动块格式见 [动态任务](../../文档/动态任务.汉语.md)。装载任务的长度参数第 24–31 位是工具映像号（0 是普通装载），按映像起的子任务直接跑预编的机器码。

## 处理器核数与映像信息

`平台` 导入模块的 `处理器核数`（服务 39）返回内核启动的处理器核数（其余核数加一），`在线处理器数量`（宿主原语 65）用它。`映像信息`（映像号、目的线性偏移；服务 40）把第 k 个工具映像的头（128 字节：客体字节数与三处样本等）拷到调用者的线性内存，返回 0；没有这一号返回 -1。执行器据此认出工具 wasm，见 [动态任务](../../文档/动态任务.汉语.md) 的“工具映像”。工具映像只在 ARM64 上有；AMD64 的工具是豫行文件（经 `按段建任务` 装载），AMD64 内核对 40 一律返回 -1。ARM64 内核对 39 返回 1；原生系统由执行器直接返回 1 与 -1。

## 读他任务、写他任务与任务编号

`平台` 导入模块的 `读他任务`、`写他任务`（对方句柄、对方线性地址、本方线性地址、长度）是服务 41、42：只许初始任务调用，在它与一个动态任务的线性内存之间整块拷贝（41 由对方到本方，42 由本方到对方），成功返回 0，失败返回 -1。文件代办用它收子任务的请求、送应答，见 [客体二号](../../文档/客体二号.汉语.md) 的“整块文件代办、孙任务与多个异步子进程”。`任务编号` 是服务 6，返回本任务的句柄（初始任务为 0）；父任务把它写进启动块，子任务的输出捕获消息据此送回父任务。ARM64 内核对 41、42 返回 -1；原生系统由执行器直接返回 -1，任务编号返回 0。

## 按段建任务

`平台` 导入模块的 `按段建任务`（描述块线性地址、描述块长度）是 AMD64 裸机内核的服务 43（[提案 00005](../../../../提案/00005-自有可执行格式.汉语.md) 第 3 步）：按描述块为一个新任务建地址空间并起跑，返回它的句柄（不小于 64 的偶数），失败返回 -1。执行器在用户态读[豫行文件](../../文档/豫行格式.汉语.md)、拆段表后调用它；读文件、拆段表都在用户态完成。

- 描述块头 48 字节：+0 入口、+8 栈顶（各八字节）、+16 段数（四字节）、+24 启动块线性地址、+32 启动块长（各八字节），其余保留为零；其后每段 48 字节，布局同豫行段表项，只是 +24 的“文件内偏移”换成段内容在调用者线性内存里的地址（全零段写零）。描述块长度须等于（段数 + 1）× 48，段数 1 至 256。
- 段只能落在用户区 0x200000–0x3FFFFF（拷进新任务的用户区块），或按 2 MiB 对齐、整段落在 0x800000–0x1FFFFFF、0x8000000–0x1FFFFFFF、0x30000000–0x37FFFFFF、0xC0000000–0xFFFFFFFF 四处之一（每 2 MiB 一块，用户可写的段可读写，其余只读）；内存长度为正、虚址与长度按 4 KiB 对齐，内容长度不超过内存长度、内容整段在调用者线性内存里；大页段合计至多 2047 块。不合就返回 -1。
- 启动块（至多 16 MiB）原样随任务保存，子任务用服务 38 取回，格式同装载任务。执行器为豫行文件送的启动块只含参数、程序名与环境，子任务据此直接运行嵌入的客体与预编代码。
- 新任务从入口起跑，栈指针是栈顶；主人是调用者，与装载任务一样入调度环，结束时归还全部块。

ARM64 内核对 43 返回 -1；原生系统由执行器直接返回 -1。

## 归还内存块

`平台` 导入模块的 `归还内存块`（起块号、块数）是裸机内核的服务 44，两种架构都有：把本任务线性内存第 起 个 2 MiB 块起的 数 块里已提交的物理块交还内核，返回交还的块数。容量不变，这些块以后再被访问时由缺页重新提交、整块清零；超出容量的部分不管。块号按线性偏移除以 2 MiB 算（线性内存迁入动态区后，偏移 0 就是动态区第 0 块）。执行器只在裸机（平台号 1）调用：每次回收清扫后交还空出来的整块，见[客体二号](../说明.汉语.md)的“交还内存”。旧内核按未知服务返回 -1；原生系统由执行器直接返回 -1。

`空闲内存块数`（无参数）是服务 45：返回池里此刻的空闲物理块数（每块 2 MiB）。执行器在裸机上每次回收后据此压低回收阈（不超过空闲内存的一半，不低于 16 MiB）。旧内核按未知服务、原生系统由执行器直接返回 -1，执行器照常定阈。

`任务信息`（游标、目的线性地址）是服务 46：从槽号 游标 起找第一个在用的任务，把 128 字节记录写到目的地址，返回下一个游标；没有了返回 -1，目的越界返回 -2。记录依次是句柄、主人句柄、状态、累计滴答（任务在处理器上跑过的全局滴答数，正在运行的含本次切入以来的部分）、动态区已提交块数、固定块数（用户区、原生栈、启动块与段块）、启动块长、此刻的全局滴答（各四字节），其后 96 字节是启动块里程序名区的开头（四字节长度加程序名字节；没有启动块为零）。执行器在裸机上的原语 129（公共任务监测）从游标 0 起反复调用它，取遍全部任务，按两次采样之差算 CPU 占用。旧内核按未知服务、原生系统由执行器直接返回 -1。

`读鼠标字节`（无参数）是服务 36：从鼠标环取一个字节，环空为 -1。环里一律是四字节包（2026-10-11 起）：首字节（位 3 恒为一，低三位是左、右、中键，位 4、5 是横移、纵移的符号）、横移、纵移（向上为正）、滚轮（有符号，向下滚动为正）。PS/2 鼠标由内核开 IntelliMouse 滚轮模式并组包，USB 引导协议鼠标的报告由内核换包；三字节的 PS/2 鼠标与 ARM64 的 USB 鼠标滚轮字节为 0。AMD64 第一次调用时清零鼠标环并向鼠标发 D4 F4 开数据报告。裸机显示后端按四字节包解析，交指针移动、按下、抬起与滚轮（每格 48 像素）。

`鼠标位置`（无参数）是服务 47：ARM64 的 VMware 虚拟鼠标有新的绝对坐标时返回 横×65536+纵（屏幕像素）并清掉新标，没有新坐标或没有这类设备返回 -1；AMD64 一律返回 -1。裸机显示后端每次收鼠标字节前先取它，有新坐标就把光标直接放到那里；按下、抬起仍经服务 36 的鼠标包按次序交付。

`小睡`（有信不睡）是服务 50（10-10 起）：让出处理器，睡到下一个时钟滴答（约 10 毫秒）；其间有消息投来或子任务结束就提前醒；有信不睡非零且邮箱已有信时不睡、立即返回。返回 0。单核没有别的可运行任务时内核进空闲（停机等时钟），处理器不再空转，任务管理器也不再把这段时间记到调用者头上。执行器在裸机上没有输入可读时调用它：显示面等事件、带子任务的显示面等待（有信不睡为 1，好接着收子任务的信）、命令壳读行、终端按键等待。旧内核按未知服务返回 -1，调用方照旧轮询。

`按键模式`（开）是服务 53、`读按键`（无参数）是服务 54（2026-10-11 起，两种架构都有）：开非零时键盘改走事件模式，键盘不再往控制台字节环里放字节（串口照旧），为零时回到文字模式，返回 0；主人任务结束时内核也关掉。读按键取出一个按键事件：HID 用法 + 按下×256 + 修饰位×65536，修饰位按 HID 排列（位 0–3 左 Ctrl、Shift、Alt、Win，位 4–7 右边四个），没有事件为 -1。PS/2 键盘的扫描码与 USB 引导协议键盘的报告都由豫言内核换成这种事件（见[控台输入](../../文档/控台输入.汉语.md)）。执行器的裸机显示后端在取得显示面时开、归还时关，把事件换成显示接口的按键按下、抬起、修饰键（上档、控制、交替、命令）与文字输入。旧内核按未知服务返回 -1，执行器照旧从控制台字节译出按键。
