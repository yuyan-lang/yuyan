# 持久块服务

这是 AMD64 裸机初始任务访问内核 USB bulk-only 块设备的接口。服务号 28、29、30、31 分别对应容量、读取、写入和同步。容量返回可用的 512 字节扇区数，无设备、未授权时返回 0；读写和同步返回 0 表示成功、1 表示设备请求失败、-1 表示拒绝。ARM64 返回容量 0，其余 -1。

读写参数是无符号扇区号和静态窗编码 `静偏 | (长度 << 20)`。长度必须恰为 512，窗口末端不得超过镜像构造时授予任务零的静态范围，扇区号必须小于容量。固定内存只授初始页，可增长内存授八页；子任务不继承。同步不访问静态窗。没有授权、没有完成设备探测时拒绝请求。

内核先将写入数据从 `0x300000 + 静偏` 复制到自身保留的 `0x07C0B000` 缓冲，读取成功后才从该缓冲复制回静态窗。应用不提交物理地址。每次只传一个扇区，复用既有 READ(10)、WRITE(10) 与 SYNCHRONIZE CACHE(10)。

服务主体置于 `0x007DF000` 起的 4 KiB 外置代码页，主内核只保留调用入口；根端扫描代码限于 `0x007D0000` 起的前 52 KiB。设备初始化使主内核超过描述符表边界时，移到 `0x007DD000` 起的 8 KiB 区间，保留失败与串口调用；之后接服务页，再接 `0x007E0000` 的控制器代码。构造器检查各区长度，避免覆盖描述符表或相邻代码。

当前只使用首个匹配的 USB 大容量存储接口，尚无磁盘选择或分区接口。验收由光盘介质启动、另接专用 USB 数据盘；把启动 ISO 自身作为首个 USB 存储设备时，它也会成为探测对象，未知格式不自动格式化。

帧缓页目录独占 `0x11F000`，IOMMU 初始化使用 `0x11A000` 至 `0x11EFFF`，两者不共用。USB 验收路线没有启用 IOMMU，确认的是服务访问权限与设备传输；既有 Virtio 路线继续使用 IOMMU。

执行器保留 Virtio 优先选择，并在其初始化失败后尝试 USB 服务；文件系统仍使用块容量、块读、块写、块刷新，磁盘格式不变。AMD64 启动盘授予初始执行器静态搬运窗，生产镜像不自动格式化未知磁盘。非裸机目标不调用这些服务。

待办事项：非 512 字节块、UAS、热插拔、错误恢复、EHCI 与 AHCI 尚未实现；实体机尚未验收。

## 目标内建导入：页容量

`目标` 导入模块的 `页容量` 返回本目标线性内存的页数上限，由降级器按目标生成常量（裸机后端「目标页容量上限」）：AMD64 裸机 65535 页（约 4 GiB），ARM64 裸机 1024 页（64 MiB），Windows 16384 页，macOS 与 Linux 65535 页。执行器启动时把它记为堆的页上限，回收位图与卡表按它预留；启动镜像的线性内存容量取模块声明的最大页数与同一上限的较小者。
