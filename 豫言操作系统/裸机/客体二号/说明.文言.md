# 客体二号

用户态豫言客体执行器二号，以**底层模式**之常豫言书之（旧括号式 `.低阶` 源码由此代之）。其所行者，普通豫言所编之 WasmGC 模块：栈机之解释、分配与标记清扫之回收、异常、结构与数组、宿主之原语（输出、文件、命令行、同步子进程）、持久之文件系统与 Virtio 块设备之驱动。

## 构建

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 客体二号 --输出 /tmp/yy客体二号.wasm
```

所成者标准 Wasm 模块（导出 `启动`），由验证之器 `豫言操作系统/裸机/普通豫言验证。豫` 读入，附客体模块与标志之数据段，生裸机之镜像。内存布局之常量（`布局`）其址与验证之器相约，不可妄改。

## 模块

`构建摘要` 补构建基础之 `获取当前程序SHA256`、`获取文件SHA256` 二宿主导入，以普通豫言底层三十二位之运算返小写十六进制摘要。今程序取本实例所嵌 Wasm 之文，文件取指定路径之文。AOT 之命令行程序名仍指可执行之容器，校程序摘要当指原 Wasm 文件。

`布局` 记内存布局与状态格之常量；`基础` 记输出、变长整数、内存与宽整数之助手；余者依依赖之序。语言之约见 `应用/豫言编译器/文档/底层模式.文言.md`。

`域名报文` 以普通豫言底层模式编解 DNS 一问及 A、AAAA 之答，可跳答名之压缩指针；原生进程于 Linux 以 UDP 用之。定报文之探针验二型与坏指针。

## 启动

`入口` 之 启动一次，先行客体模块之 `_start`（依测试名而行者，行其名之导出），办毕所挂之请求；入口模块若又导出应用所供之 `豫言操作系统启动/启动程序`（→元），而非依测试名而行、无待重启、亦非复出之子任务，则以空参续呼之；无此导出则不呼。取消外调之后，应用之主体在此导出，`_start` 唯初始化诸模块；导出中未接之异常，编译器所生之包装交与 `_start` 同之未捕处理（印之而以一退）。

## 豫言操作系统底层接口：裸机之后端

`裸机底层状态码`、`裸机底层基础`、`裸机底层句柄`、`裸机底层文件`、`裸机底层终端`、`裸机底层网络`、`裸机底层进程` 七模块，乃[豫言操作系统底层接口](../../../豫言操作系统底层接口/总纲.文言.md)于裸机之实现（四十五函数，案见[底层接口方案](../../../文档/豫言操作系统底层接口方案.文言.md)）。此皆**新增、独立**之模块：径用既有之文件系统（`fs读文件`、`fs写文件`、`fs建目录`、`fs删除`等）、控制台（`读字节`、`读行`、`打印串`）与时钟（`时钟滴答`、`墙钟秒`）原语，不改此诸既有之实现；入口唯于启动之时新增一次 `底柄_初始化` 之呼（固定格三六六四、三六六八存动态柄表之址与终端之模，表首存行入余态；经 `取区域` 分配柄表、路径缓、内容缓，暂存缓冲仍供文件与时钟之暂用）。

子任务重启清动态区，`重启准备` 并清旧柄表之址；次启复分配柄表而立根柄三。今子任务无块设备，底层文件诸事尚须初始任务以独立邮箱协议代行；GC 文件原语已有其对象协议。

- **柄之模**：柄零一二为标准三流；柄三恒为根目录（唯一之预开目录）；四起十三槽，按需授与既开之文件与目录，每槽各有专属之路径缓（二万二千四百字节）与内容缓（四十万九千六百字节，整文件缓存）。底文之暂径与数据缓亦取自动态区。
- **路径之解**：相对目录柄而解，不含当前目录，`..` 越出目录柄之子树则报错，与既有 `主机文件` 中倚“当前目录”之状态而规整路径者，各自独立。
- **已知之限**（皆于各文件双语之注逐条载明）：`底层网络`、`底层进程` 一概返“不支持”（网络因裸机无网络栈；进程因桥接既有 GC 对象参数之子进程机制，不在本轮之内）；`建管道`、`取终端尺寸` 返“不支持”；`填随机字节` 读处理器之随机数（臂 RNDR、兼 RDRAND，目标之内建导入“硬件随机”），处理器无之则返“不支持”；文件与目录内容缓存之限四十万九千六百字节，逾则相应操作返“溢出”；单调之钟精度十毫秒（内核滴答），墙钟精度一秒（RTC）。
- **GC 垫层之改接**：控制台输出之原语（一至四号）经本接口之 `写`；Linux 上文件之原语经本接口之 Linux 后端（见下节）。裸机上文件之原语犹径用执行器内之文件系统（待办：扩整文件缓存之限，乃改经本接口）。

## 多平台：一执行器行于 Linux 与 macOS

执行器乃一整数 Wasm 模块，寄存器之降依目标而生裸机之像、Linux 或 macOS 之可执行文件。运行之时，以目标之内建导入 `导入：目标：平台号`（降时绑为常量：裸机一、Linux 二、macOS 三）择平台之实；他目标之导入降为陷阱之桩，不行。诸平台之导入皆声于 `平台接口/` 之接口文件（`林纳克斯`、`苹果`、`视窗`、`平台`、`目标`），导入模块名即接口文件之名。

- `林系统`、`苹系统`：Linux 系统调用之包（导入模块名“林纳克斯”）与 macOS libSystem 之包（导入模块名“苹果”，返负一则桩已化为负 errno），并 `是林`、`是苹` 与各自 errno 之转表（二系统之号异）。`原生系统` 于二者之间分派书、读、退出、时钟与终端之验。
- `平台`：书字节、读字节、退出、时钟之滴答、墙钟、中断之询，于原生系统改走系统调用或 libSystem；任务与邮箱之服务于原生系统尚未为，按败返之（待办）。
- `林启动`、`苹启动`：启动时书程序名区、参数区与环境块。Linux 读 `/proc/self/exe`、`cmdline`、`environ`；macOS 用 `sysctl` 之 `KERN_PROCARGS2`（缓冲乃启动时新增之二页）。其后宿主之原语不复分平台。
- `视窗系统`、`视窗启动`、`视窗底层`：视窗（平台号四）。系统之入口经 kernel32、ntdll、bcrypt（导入之模块名“视窗”）；标准流之读写，单调之钟与墙钟（六十四位之计数，以本模之逐位长除与 MulDiv 化之），UTF-16 与 UTF-8 之互转；启动时以 GetModuleFileNameW 与 NtQueryInformationProcess（命令行）书程序名区与参数区（依视窗之规分参数），路径书为执行器之式 `/C:/a/b`；暂存（一兆，前二百五十六千依 Linux 之布）与 Linux 之后端共一状态之格。文件（CreateFileW 等，旗为 FILE_FLAG_BACKUP_SEMANTICS 与常属）、环境之变量（GetEnvironmentVariableW）已为之。`视窗进程`：建管道（CreatePipe）、运行程序（CreateProcessW，依 MSVCRT 之规合命令之行，环境之块化为 UTF-16，三标准流临时可承）、进程之表（同 Linux 之布）、取退码、终止、关闭与轮询之候（进程、管道、控台、套接字）。TCP 经 ws2_32（以登记之表辨套接字，Winsock 之误码依 Linux 之映）。导入之参类五为可空之址。待办事项：视窗之 hosts 与 DNS、控台之模、目录之柄与工作目录之柄。
- `林底层`、`苹底层`：底层接口四十五函数之 Linux 与 macOS 后端，`原生底层` 依平台号于二者之间分派（函数名冠以“原底_”）；裸机后端诸函数之首，于原生系统转之于此。柄即文件描述符，三号为根目录“/”。Linux 开用 `openat2` 加 `RESOLVE_BENEATH`（越界返七十六），遇 `ENOSYS` 则逐段用 `O_PATH|O_NOFOLLOW` 解之；路径状态经受限之柄查之，建删、改名与读链接先安全开父目录，双构之探针皆过。macOS 开用 `O_RESOLVE_BENEATH`，路径状态用 `AT_RESOLVE_BENEATH`，余诸径之作先受限开父目录；本机 ARM64 之探针验树内、出界链接与文件之变，皆过。状态各取自 `statx` 与 `fstatat`，目录各取自 `getdents64` 与 `__getdirentries64`。待办：Linux 旧核逐段退路与二平台开父目录后之并发更名竞态，以及旧版 macOS 不识守界标之退路。终端之模：Linux 用 TCGETS/TCSETS，macOS 用 TIOCGETA/TIOCSETA（原始之模同 libuv）。
- `原生进程`：二系统共用之进程、候与网络，系统之差聚于“进_”诸小函数。运行程序：fork（Linux 以 clone(SIGCHLD)），子接标准之流与工作之目录而 execve，败则经 O_CLOEXEC 之管告父以 errno；进程之柄自 2^30 起，进程之表在暂存之区。候以 ppoll（macOS 以 poll），进程之订每轮察之（有行中之进程则每轮至多候十毫秒）。TCP 可用 IPv4、数字 IPv6、localhost 与 `/etc/hosts` 名表；Linux 与 macOS 皆依 `/etc/resolv.conf` 次第问诸服务器之 A、AAAA，原名不获则次第附 search 或 domain 后缀再问。Linux 主机串空者听双栈，macOS 仍以 IPv4 听之；macOS 之 resolv.conf 未必尽载系统诸 DNS 路由（待办：系统 DNS 路由之接入、嵌四版之六版地址及区域号）。启动时忽 SIGPIPE，子于 execve 之前复其默认。启动之序：底层句柄之表与原生后端之暂存皆以 `取区域` 取之，必在 `初始化堆` 之前（其后区域之顶即堆之起，与堆相叠）。
- `原生子进程`：原生系统上同步子进程之原语四十三至四十六（程序之名依 PATH 解之，经 `运行程序` 起之；四十五接 /dev/null，四十六以二管并读常出与误出）。易当前目录时亦易进程之真目录，子进程故行于同一目录。异步子进程六十七至六十九亦在此：子进程之表（至多千二十四）启动时以 `取区域` 取之，回收时全表为根；二捕获之管设为不塞，收与候时尽读其见有之数据而询退码，候时以底层之 `等待` 并候诸管与诸进程之柄，其行同 Node 宿主（豫构调度器之试于原生宿主所出与 Node 逐字同）。待办：设子进程之入、环境（七十、七十一）尚未接于原生之系统。
- 苹果之底层运行程序以 `posix_spawn` 起子，以文件动作接标准流及工作目录，以进程属性复 SIGPIPE 默认之处；参数与环境仍用旧指针之表。成则仍登记进程柄，败返旧底层状态码；不复父堆，亦不候后台清扫。迁目录之动作须苹果十点一五以后。Linux 之 clone 与误码管道仍循旧途。
- `原生网络原语`：传输控制协议之宿主原语七十七至九十（义同 Node 宿主：不塞，返（状态，值）），原生之系统经底层网络之包行之；裸机返负五十八。
- 字节串之原语：九十一号 `豫言_字节串_截取`（自起点取定长之字节为新串，越界则以一百三十四退）于诸平台由执行器径行之，原生所行之编译器书其产物时用之。十一号“运行于MacOS”于 macOS 返真。
- `原生文件原语`：原生系统上文件之宿主原语，路径犹由 `规范参数` 规为绝对之径，乃经底层接口访宿主之文件系统；启动时当前目录取自 `/proc/self/cwd` 或 `getcwd`。
- `WASI名称` 与 `WASI分派`：识 WASI preview1 函数名四十六，已行取参数与环境、时钟、随机、读写标准流与文件、预开根目录、依径开与改、柄及路径状态、寻址与定位读写、目录读取、等待与退出。时钟、流、文件与等待诸呼经底层接口；裸机今无熵源，随机之呼返不支持。未行之呼返 ENOSYS。函数表分配后清零，使本地函数与导入函数得明辨。今二十二样各至少于一原生目标行过；`文件测试`、`文件边界`、`睡眠` 之 Linux 二架构标准出经 `cmp` 验逐字同，`出入` 之双架构标准出与标准错亦各逐字同。全平台与参照实现之逐字一致，犹待验。
- `带型名`：带型之宿主导入（去外调之后，标准库、构建基础、豫言裸机三包之宿主之服径编为带型之导入，凡七十六；又有可移植之显示接口六、字体接口四，见下条）。实例化时依（模块，字段）查表，绑为第四类宿主导入；呼时（`主机` 之 `带型调用`）依导入之签名，装 i64 为 i31 或 $big、f64 为 $float、i32 为 i31，引用照传，成原语之参元组，果亦依签名拆回；列之参与（数组，长）之果依表之标转之。原语九十三至百一唯带型导入呼之（终端按键与原始输入暂报不支持，随机三者经底层取熵，拼音暂原样返之，绘监视面板空行）。一模块之中，带型导入与 gc-host.call 可并存。原语四十七（加载模块）、四十八（调用导出）之果，由办请求者事后书回：经带型导入呼之者，带型调用不拆占位之果，置 状态_请求带型；调用导出加帧钩四；驱动之环依 i64 原样书回（i32 之果、加载模块所返之实例号或负之误码皆依符号扩之），不装箱。
- `原生槽区`、`苹显示`、`裸机底层显示`、`显示原语`：原生之窗（macOS arm64，见[原生窗口方案](../../文档/原生窗口方案.文言.md)）。`原生槽区` 为三十二 KiB 之常驻区（原生指针与双精之八字槽、串缓、显示面表与事之队，其布见其文之注）；`苹显示` 于运行时 dlopen AppKit，原生之呼皆经 `平台接口/苹果。接口。豫` 逐一所声之函（objc_msgSend 依签名分之）：建窗，以画为 CGImage 而设于内容视图之图层，取事每次至多候四分之一秒（逾时则察窗闭否），输入法经透明之 NSTextView 组字；`裸机底层显示` 为底层显示包之五函数（他平台返五十八）；`显示原语` 为显示接口（六）与字体接口（四）之带型导入原语百零二至百十一，及宿主之选 `--授权显示面 名=宽x高`（可重）、`--显示面后台`（窗不激活，置于他窗之后）之解：于 `启动一次` 中、`初始化堆` 之前，自参数区之首取之，所占之参亦不交程序。字体依族名开系统之字体文件（无衬线：华文黑体、Arial Unicode；衬线：宋体；等宽：Menlo），以 pread 分段读之。
- 生成与验：`yy原生生成 Linux|苹果 臂六十四|兼容六十四 执行器.wasm 输出 客体.wasm` 嵌客体于执行器成独立之可执行文件（macOS 今唯 arm64）；`yy原生一致性`（`豫言操作系统/裸机/原生一致性。豫`）以普通探针与文件探针行于 Linux（二架构；非 Linux 之系统加 `--经 docker`）或 macOS（`--系统 苹果`，本机行之），与裸机之验所用参照之出逐字相校。


WASI `path_readlink` 已验客体内存之界，而接底层文件接口；原生系统可读符号链接，裸机底层今返不支持。此呼尚未以外来程序验其始终。

## 预编：WasmGC 之函数径为机器码（路二乙档之初版）

`yy原生生成 … 执行器.wasm 输出 客体.wasm --预编`（或 `yy原生一致性 --预编`）转客体 WasmGC 模块之每函数为一整数 Wasm 之函数，并入执行器之模块而同降为机器码；执行器如常解模块、建类型之表、初全局与数据，唯不复解释函数之体。转译之器在 `库/裸机后端/预编转译。豫`，执行器之运行时之接在 `预编接口。豫`。

- **值皆居值栈**：布同解释（每槽八字节，引用与三十二位整数居低字），故保守之回收如常见之；转译之函数其签为（帧）→ i32，参数与局部自帧起，操作数其上，调用者置参数于栈顶，被调者之帧即自彼始。
- **简令内联，繁令呼解释之处理**：局部、常量、i32 之算与比较、若干 i64 之令、引用之空与等、控制之流，径书整数之令；结构、数组、类型之转、余 i64 与浮点、访存、表与杂项之令，呼执行器所导之“预编_”诸函数（即解释器之处理函数），携立即数于模块字节之址。
- **控制一一相应**：块、环、条件应整数 Wasm 之同名之构，分支先移所携之值于目标之槽；尾调（return_call 及间接、引用之尾调）先移参数于帧首，乃“调用而即返”，寄存器之降化之为尾跳；间接之调经执行器所导之 `预编派发`（依函数号二分，叶尾跳于转译之函数）。
- **异常以标传**：抛则记载荷而置 `状态_预编异常`，每调转译之函数后验之，在尝试表内则跳至其处理之码，否则返；至最外犹有异常，则以未捕之异常退（一三七）。
- **大模块**：逾四百四十八千字节模块之窗者（如编译器），不嵌于窗，而为尾块书于可执行文件（Linux 附文件之末，macOS 置 __LINKEDIT 中签名之前），执行器启动时读回于动态区之首；Linux 之代码过大则别为一载入段（ARM64 居 0x10000000，x86-64 居 0x50000000）。
- **降器因之而扩**：“调用而即返”为尾跳；代码每五百一十二千字节插一陷阱之岛，越界与除零之验跳至最近之岛；巨函（逾二万令）之条件跳改为“反条件跳过加 b”；汇编器唯于条件之分支计十九位之位移（旧时 b、bl 逾一兆字节亦误报逾界）。

今之状（二〇二六年九月二十八日）：macOS arm64 上普通探针、文件探针与原生探针凡十二项，于预编之式与参照之出逐字一致；短程序较解释约快二倍（多为启动之费）。待办：内联更多热令（ref.cast、struct.get、array.get、i31）、非引用之值留于寄存器、Linux 上预编之验、编译器自身之预编与原生之自举。

续记（二〇二六年九月二十九日）：Linux ARM64 预编一致之全组十五项皆过，普通、文件与原生诸探针，同裸机或 Node 之参逐字相符。Linux x86-64 解释之打印探针已过；本机 Docker 之 Rosetta 载较巨预编之物，报 `failed to mmap segment: 22`，犹须于真 Linux x86-64 运行器验之。编译器自身之原生自举犹待成。

## 预编二：客体之值居寄存器与原生之栈（路二乙档之二版）

`yy原生生成 … 执行器.wasm 输出 客体.wasm --预编二` 用新转译之器（`库/裸机后端/预编二转译。豫`）。异于初版者：

- **值不复居执行器之值栈**：客体之函数各转为宽整数之函数（`库/裸机后端/宽降级原语。豫`），参、局与操作数皆其所有；值皆六十四位（三十二位与引用零扩），降级者置之于寄存器与原生之栈。宽整数之算书为内在之呼，降级者就地展为六十四位之令。
- **呼则径传其参**：客体函数相呼径传；call_ref 与 call_indirect 经跳表零；执行器经 `预编派发` 呼客体者，经跳表一之适配函数，自值栈之帧读参而书其果。客体之导入由导入之桩经 `预编_调用导入` 呼执行器。
- **热令内联**：结构数组之读写与长、i31、验空、精确类型之测转，径书为整数之令；struct.new、struct.new_default 与 array.new_fixed 于游程内递增而取（新游标以常址之书还之，二头字合为八字节之常一书之，起始之位以专用之内在置之，臂八令），不足乃呼 `预编_分配`。以常下标取数组之值者不装下标：长径与常数较，元素径取于其偏。下标已知小于其长者（转译之事实：br_if 落空之途，下标之局无号小于某局，而某局为此数组之 array.len）不验界。余令书操作数于值栈之暂区（起于 `状态_预编栈顶`），而呼解释之处理。
- **转译时之内联**：径呼或径尾呼他客体函数，其体不逾六十字节、无尝试表与旧式异常之令者，不发呼，而于呼处续转其体。参与局借块临时一段，实参弹入参，余局清零，体包于结果数同之块；被呼者之 return 跳出此块，尾呼化为常呼加验异常而后跳出；展于尾呼之处者，二者仍为呼者之返与尾呼，块后补一返。转译之事实（非空、型、界）遂越函数之界。唯内联一层，不内联己。降级之前另有整数层小叶函数之内联（`库/裸机后端/内联小函数。豫`）。并入之时客体所定之函唯置占位（签名、零局、空体），降与整数层内联需其体时，乃经 `降级取体` 之钩而转：内联之备唯留不逾上限之小体，大函唯留占位，降毕复其钩；遍两万余函以尾递归之带序映射（标准库「态射序号」经「态射二」非尾递归，原生保守之扫时两万余帧留诸函降时之临时）。如是原生自跑原生生成，并存者唯执行器自身之中间表示、小函之体与已降之机器码。
- **回收观原生之栈**：`预编二可用` 为一者，启动预留三十四兆之栈复之缓；回收时经目标之内建 `栈复制` 复被调者所保之寄与原生之栈，逐四字节保守而扫。
- **堆**：小块自游程递增切出，游程取诸堆顶之一段或空闲之大块，退游程时依实用计其所分。收唯用标图（不书对象之头），扫毕拷标图为起始之图。
- **分代之收**：收后标图存之，已标者即老对象；第零次及每八次全收，余次收唯标新者。书障以卡表（每五百一十二字节一字节）：struct.set、array.set 书引用前以内在九十一万、九十二万（窥次顶、第三之对象），引用数组之 array.copy 后以内在九十万（弹目数组），书零于对象头所在之卡，臂三令（ldr 卡表、add 加址右移九、strb wzr）；预编、解释者及宿主之 `设元组项` 以常令记之。次收唯扫既脏且有老对象之卡（老卡表：扫时每存活者之卡书一）所始之老对象。分配不得空者：近收以来所配不及回收阈之四一，则先增堆（方收未久，再收亦无多空；不移之堆碎而大块屡不可得，旧每先一收，收遂空转），否则先常收一次、犹不足则增堆；堆已至内存之上限者强为全收一次（次收不收老垃圾），其后犹不足乃报堆内存不足。原生之线性内存上限六万五千五百三十五页（约四吉）。

今（二〇二六年十月一日）：macOS arm64 与 Linux 二架构上普通之探针于解释、预编、预编二三式皆合期望；pit-mac（M2 Max）上预编二之编译器单线程冷编打印之探针并标准库约五点九秒，所出与 Node 版逐字节同（九月二十九日二十点七秒，十月一日晨六点九秒；同机 Node 约五点四秒）。新为：数组诸令内联而取值合为一内在、转译之事实（非空、型、新造之果，依支配跨块而存）、无子型之 ref.test 败则径判、i31 之域一 sbfx、内联不抛之体后去验异常、常条件之 if 不生死支、局部依活段分寄存器、条件跳桩与冷区、复制填零之助小块之途、长游程与分桶之分配、分配之捷径（常址还游标、二头字一书、起始位专用之内在）、常下标之数组取值、依事实省数组之界验、经跳表尾呼己者径重入、转译时之内联。是日之暮：原生自跑原生生成既通——原生生成自身预编二为原生之程序，于 pit-mac 不经 Node 预编二 `yy4_bs.wasm` 为原生之编译器，所出与 Node 版逐字节同（百五十五秒，常驻约三吉；Node 约六十至八十秒）。待办：易默认之工具链（须先速过 Node）。
