## 构建

```sh
./豫构。林檎。豫行 构建 客体二号 --输出 /tmp/客体二号。树码 -j 24
```

所成者汇编树码（底层豫汇，出 `启动`）。内存布局之常量（`布局`）其址与内核、造盘之器相约，不可妄改。仓库目标「执行器」书 `执行器。树码`，编译器径出之诸原生之产（豫构默认之原生之产、豫构发行原生等）与豫言系统所造之豫行径由之生（提案 00007 收尾）。

## 模块

`构建摘要` 补构建基础之 `取今程序沙二五六`、`取卷沙二五六` 二宿主导入，以普通豫言底层三十二位之运算返小写十六进制摘要。今程序取本实例所嵌 Wasm 之文，文件取指定路径之文。AOT 之命令行程序名仍指可执行之容器，校程序摘要当指原 Wasm 文件。预编二所生之原生程序中，生成器已算客体之摘要（客体之字之 SHA-256；编译器径出之原生程序与由汇编树码所造之豫行，取客体汇编树码之 SHA-256），书于 `预编摘要可用`、`预编摘要字零` 至 `预编摘要字一五` 诸占位之出（六十四个十六进制字依小端每四字拼一字），`取今程序沙二五六` 径返之，不复于每进程起后对全客体算一遍；解释执行时诸占位为零，照旧现算。

`布局` 记内存布局与状态格之常量；`基础` 记输出、变长整数、内存与宽整数之助手；余者依依赖之序。语言之约见 `应用/豫言编译器/文档/底层模式.文言.md`。

`网卡`、`网络栈`（提案〇〇〇一二第四步）：初始任务之网卡之接（十月十三日起二构皆经核务六十一至六十三收发，核先用其原生网卡之驱，见核之 `网卡表`）及以太、ARP、IPv4、UDP、TCP、环回之网络栈，经底层之服（底层网络之 TCP、数据报与套接字之址，见下“底层之转送”）供子任务与林兼容之层用之；网区于开机初始化堆之前预留。

网卡（十月十三日起）：执行器惟经核务六十一网帧收、六十二网帧发、六十三网卡信息（见平台接口之规）收发，核先用原生网卡（虚拟网卡 virtio-net、英特尔千兆 e1000 与 e1000e 等），无原生网卡或链皆未通则用驱动客体所交之卡；以卡本之以太址收发，链通乃备，未通则每网请复问之。旧臂执行器中用户态之 virtio-net 已删。`裸机传输控制`（十月十三日）：初任务中，标准库传输控制之原语七十七至九十径用网络栈之套接字，启连之主机名依点分十进、localhost 或问域名之服以 A 录解之，开机程序与壳中径行之豫言句遂能连网；子任务（无网区）犹返不支持，待办。`公共网卡原语`（十月十三日）：设备接口之「问网卡」（原语二百四十五，壳命「网络态」用之），经服务七十五读诸网卡之录，并报网络栈之址设。卡初备，网络栈先以 DHCP 取址（广播 DISCOVER、REQUEST，每步至多约一秒，凡四轮），得本机址、网关、掩码与域名服务器；败则用默认之十、零、二、十五（掩二十四），网关十、零、二、二，域名十、零、二、三，并报一行于控台。林程序发十、零、二、三或一二七、零、零、一之五十三口者，改发实之域名服务器，归报复其源。续租与址冲之察，留待后版。

屏与入（十月十七日，远调界面）：设备接口之 `观屏`、`拟键`、`拟指`、`拟钮` 映于原语二百零五至二百零八（`屏键原语`）。观屏先经核务百零三以容零问尺，借第一中转之缓读回全屏之 RGBA，复拷为字节之串交 `屏照已得`；三拟入之原语编其参为务百零四之种与值。原生返资源暂不可用，豫行之启动器于二务返负一，亦得之。

## 豫言操作系统底层接口：裸机之后端

`裸机底层状态码`、`裸机底层基础`、`裸机底层句柄`、`裸机底层文件`、`裸机底层终端`、`裸机底层网络`、`裸机底层进程` 七模块，乃[豫言操作系统底层接口](../../../豫寓底榫卯/总纲.文言.md)于裸机之实现（四十五函数，案见[底层接口方案](../../../文档/豫言操作系统底层接口方案.文言.md)）。此皆**新增、独立**之模块：径用既有之文件系统（`文件系统读文件`、`文件系统写文件`、`文件系统建目录`、`文件系统删除`等）、控制台（`读字节`、`读行`、`打印串`）与时钟（`时钟滴答`、`墙钟秒`）原语，不改此诸既有之实现；入口唯于启动之时新增一次 `底柄初始化` 之呼（固定格三六六四、三六六八存动态柄表之址与终端之模，表首存行入余态；经 `取区域` 分配柄表、路径缓、内容缓，暂存缓冲仍供文件与时钟之暂用）。

子任务重启清动态区，`重启准备` 并清旧柄表之址；次启复分配柄表而立根柄三。今子任务无块设备，底层文件诸事尚须初始任务以独立邮箱协议代行；GC 文件原语已有其对象协议。

- **柄之模**：柄零一二为标准三流；柄三恒为根目录（唯一之预开目录）；四起十三槽，按需授与既开之文件与目录，每槽各有专属之路径缓（二万二千四百字节）与内容缓（四十万九千六百字节，整文件缓存）。底文之暂径与数据缓亦取自动态区。
- **路径之解**：相对目录柄而解，不含当前目录，`..` 越出目录柄之子树则报错，与既有 `主机文件` 中倚“当前目录”之状态而规整路径者，各自独立。
- **已知之限**（皆于各文件双语之注逐条载明）：`底层网络`、`底层进程` 一概返“不支持”（网络因裸机无网络栈；进程因桥接既有 GC 对象参数之子进程机制，不在本轮之内）；`建管道`、`取终端尺寸` 返“不支持”；`填随机字节` 读处理器之随机数（臂 RNDR、兼 RDRAND，目标之内建导入“硬件随机”），处理器无之则返“不支持”（安全随机字节串之原语九十八此时改用熵池，见下文“后备熵源”）；文件与目录内容缓存之限四十万九千六百字节，逾则相应操作返“溢出”；单调之钟精度十毫秒（内核滴答），墙钟精度一秒（RTC）。
- **GC 垫层之改接**：控制台输出之原语（一至四号）经本接口之 `写`；Linux 上文件之原语经本接口之 Linux 后端（见下节）。裸机上文件之原语犹径用执行器内之文件系统（待办：扩整文件缓存之限，乃改经本接口）。

## 多平台：一执行器行于 Linux 与 macOS

执行器乃一整数 Wasm 模块，寄存器之降依目标而生裸机之像、Linux 或 macOS 之可执行文件。运行之时，以目标之内建导入 `导入：目标：平台号`（降时绑为常量：裸机一、Linux 二、macOS 三）择平台之实；他目标之导入降为陷阱之桩，不行。诸平台之导入皆声于 `平台接口/` 之接口文件（`林纳`、`林檎`、`轩窗`、`平台`、`目标`），导入模块名即接口文件之名。

- `林系统`、`苹系统`：Linux 系统调用之包（导入模块名“林纳”）与 macOS libSystem 之包（导入模块名“林檎”，返负一则桩已化为负 errno），并 `是林`、`是苹` 与各自 errno 之转表（二系统之号异）。`原生系统` 于二者之间分派书、读、退出、时钟与终端之验。
- `平台`：书字节、读字节、退出、时钟之滴答、墙钟、中断之询，于原生系统改走系统调用或 libSystem；任务与邮箱之服务于原生系统尚未为，按败返之（待办）。
- `林启动`、`苹启动`：启动时书程序名区、参数区与环境块。Linux 读 `/proc/self/exe`、`cmdline`、`environ`；macOS 用 `sysctl` 之 `KERN_PROCARGS2`（缓冲乃启动时新增之二页）。其后宿主之原语不复分平台。
- `轩窗系统`、`轩窗启动`、`轩窗底层`：轩窗（平台号四）。系统之入口经 kernel32、ntdll、bcrypt（导入之模块名“轩窗”）；标准流之读写，单调之钟与墙钟（六十四位之计数，以本模之逐位长除与 MulDiv 化之），UTF-16 与 UTF-8 之互转；启动时以 GetModuleFileNameW 与 NtQueryInformationProcess（命令行）书程序名区与参数区（依轩窗之规分参数），路径书为执行器之式 `/C:/a/b`；暂存（一兆，前二百五十六千依 Linux 之布）与 Linux 之后端共一状态之格。文件（CreateFileW 等，旗为 FILE_FLAG_BACKUP_SEMANTICS 与常属）、环境之变量（GetEnvironmentVariableW）已为之。`轩窗进程`：建管道（CreatePipe）、运行程序（CreateProcessW，依 MSVCRT 之规合命令之行，环境之块化为 UTF-16，三标准流临时可承）、进程之表（同 Linux 之布）、取退码、终止、关闭与轮询之候（进程、管道、控台、套接字）；管可设不阻（登记之表，读前以 PeekNamedPipe 视可读之数，无则回暂不可用）。TCP 经 ws2_32（以登记之表辨套接字，Winsock 之误码依 Linux 之映）。导入之参类五为可空之址。待办事项：轩窗之 hosts 与 DNS、控台之模、目录之柄与工作目录之柄。
- `轩窗缺页`：轩窗触乃提交（提案〇〇〇二一）。轩窗所提交者无论触否皆计于提交之限；轩窗兼之执行器入口唯留动区，以 AddVectoredExceptionHandler 注缺页之桩（后端 `兼降级本术` 之「兼轩窗缺页桩」，唯转 Win64 之呼约为本降之内约），桩呼导出之「轩窗缺页处理」：访问违例之址落于执行器己之动区，或落于豫行启动器为客所留、已求块之动区（状态视客记之启动器之记）者，就提交其所在之一块（三十二兆）而重行之；同块方提交而复误者还于系统；提交不成则书一行于标准误而还于系统。进程乃唯依所触之存计提交，`-j` 大亦可起工作进程。轩窗臂之入口仍一次提交全动区（待办）。
- `林底层`、`苹底层`：底层接口四十五函数之 Linux 与 macOS 后端，`原生底层` 依平台号于二者之间分派（函数名冠以“原底”）；裸机后端诸函数之首，于原生系统转之于此。柄即文件描述符，三号为根目录“/”。Linux 开用 `openat2` 加 `RESOLVE_BENEATH`（越界返七十六），遇 `ENOSYS` 则逐段用 `O_PATH|O_NOFOLLOW` 解之；路径状态经受限之柄查之，建删、改名与读链接先安全开父目录，双构之探针皆过。macOS 开用 `O_RESOLVE_BENEATH`，路径状态用 `AT_RESOLVE_BENEATH`，余诸径之作先受限开父目录；本机 ARM64 之探针验树内、出界链接与文件之变，皆过。状态各取自 `statx` 与 `fstatat`，目录各取自 `getdents64` 与 `__getdirentries64`。待办：Linux 旧核逐段退路与二平台开父目录后之并发更名竞态，以及旧版 macOS 不识守界标之退路。终端之模：Linux 用 TCGETS/TCSETS，macOS 用 TIOCGETA/TIOCSETA（原始之模同 libuv）。

- `原生进程`：二系统共用之进程、候与网络，系统之差聚于“进”诸小函数。运行程序：fork（Linux 以 clone(SIGCHLD)），子接标准之流与工作之目录而 execve，败则经 O_CLOEXEC 之管告父以 errno；进程之柄自 2^30 起，进程之表在暂存之区。候以 ppoll（macOS 以 poll），进程之订每轮察之（有行中之进程则每轮至多候十毫秒）。TCP 可用 IPv4、数字 IPv6、localhost 与 `/etc/hosts` 名表；Linux 与 macOS 皆依 `/etc/resolv.conf` 次第问诸服务器之 A、AAAA，原名不获则次第附 search 或 domain 后缀再问。Linux 主机串空者听双栈，macOS 仍以 IPv4 听之；macOS 之 resolv.conf 未必尽载系统诸 DNS 路由（待办：系统 DNS 路由之接入、嵌四版之六版地址及区域号）。启动时忽 SIGPIPE，子于 execve 之前复其默认。启动之序：底层句柄之表与原生后端之暂存皆以 `取区域` 取之，必在 `初始化堆` 之前（其后区域之顶即堆之起，与堆相叠）。

## 常驻之工作进程（提案〇〇〇〇七议三）

林檎与 Linux 原生，编译器并行而起“本程 `--mode=worker`”之异步子进程者，执行器书参为务帧，交常驻之工作者（本程 `--常驻工作者`，标准入接务管，标准出接果管）。工作者读一务帧入参数区，`启动一次` 行之；务书于标准出、误之字先截留于二缓（`常驻` 模块，各十六兆），务毕并退码为一果帧交父进程；乃清场（`常驻清场`：清回收堆本务所用之段相应之标图与卡表，复清状态格与回收格），读次务。务中呼退、或回收堆所用逾二百五十六兆者，工作者发退帧而退，父如常调度，取闲时乃收之。父进程一侧（`原生子进程`）登所派之务于异步表，表项读工作者之果管，满一帧则毕；果管尽而帧未满者以其退码毕。池满（六十四）、参不容于参数区（六十四千）者照常另起进程。所省者每务之起进程、执行器与客体之初及新存之缺页：本机冷编豫言系统快约百分之四，全构豫言编译器自二十四至二十八秒降至约二十三至二十四秒，产物逐字相同。清场时依址读写堆基、位图、卡表与常驻顶。动区与回收堆之字皆不清：清场升区脏之顶（状态格九一一六）至本务之区域顶，其后 `取区域` 所得在其下者先清之，先书后读之栈与缓（值栈诸栈、栈复之缓、截留之缓、栈图之表、中转之缓、底柄容缓、清扫线程之栈）用 `取区域不清`；回收堆之分配本已书其所将读者。栈图之表每务落于同处，首务复之，后务径用（常驻栈图，状态格九三三二）。如是每务少清约八十兆字、少复约十二兆字（十程序无改合编，旧则清场与复栈图之表每务约十毫秒）。全局之初值亦不每务皆求（`全局初值`）：首务求毕，以回收堆中其所分之段（并位图、卡表、全局表、大块桶表与状态格中其所改之字）拍为快照，置于线性址一点七五吉起之快照区；次务先清其段、如常求之而逐字核之，同乃用之；其后之务以快照复之（编译器全局约三万八千、二十二兆）：林纳则回收堆之段能整页而齐者，先书于 /dev/shm 中一临时之文（不容则 /tmp，建毕即删其名，唯留其柄），每务之始依十六千之页写时复制而映回，未触之页（拼音表之类大常量多整张不读）不拷，头尾不满一页者与位图、卡表、全局表仍拷回，每工作者首映回之后逐字核之，十程序无改合编之前端快约一成；林檎缺页之费过于拷，全段拷回。动区长至快照之区则停之（状态格九三三六）。豫行启动器下之豫行客体（提案〇〇〇二一，宿主门中，十月十四日起）与原生同道：父客依原生之法建池、派务（`原生子进程`），运行程序、建管道与候经底层转送交启动器办之，豫行之文由启动器改起为“启动器 `--豫行` 程 `--常驻工作者`”；工作者中之客仍经柄零、一收发务帧（读书经「常驻门转」交启动器），务之出截留于客中，见 `豫行启动` 与下“底层之转送”。裸机与轩窗之常驻工作进程俟后版。

带境之务帧（提案〇〇〇三五）：原语二百一十「遣使于境」（标准库「东道带列」之「遣使于境」，受程名、参列、所居与环境之块）可交常驻工作者者，书为带境之务帧（魔数“YYCD”，帧首之后次以参区、所居与环境之块，环境之块为零终之“名=值”诸条）；工作者置所居与环境于参区之后，役境三格（状态格九一〇四环境址、九一〇八环境长、九一一二目录址）指之：`启动一次` 承今目录之前先迁进程之所居于役之目录，取环境（原语九）、取全部风俗（原语二百一十一「风俗」）与起子皆改用役之环境块。常帧清三格，用工作者启动之所居与风俗。不能交常驻者另起子进程：所居与环境抄于中转之缓三，暂书三格，`原生起程` 填环境块于运行程序块之二十、二十四，开所居为柄填于四十，起毕闭之、三格复之。将作之代役赖之，于诸树之所居、依各自之风俗行其役。林檎之管二端皆设执行即闭（Linux 之 pipe2 本带 O_CLOEXEC），子进程惟承经文件动作复至零、一、二之三流，长驻之子孙（如将作）不复握祖辈待尽之管。

## 预编：WasmGC 之函数径为机器码（路二乙档之初版）

初版预编之转译器（「预编并入」）已于二〇二六年十月十一日删之（提案〇〇〇〇七之收尾），今唯用第二版（见下“预编二”之节），执行器一侧之 `预编接口。底层。豫` 第二版沿用之；此节记初版之设计。初版转客体 WasmGC 模块之每函数为一整数 Wasm 之函数，并入执行器之模块而同降为机器码；执行器如常解模块、建类型之表、初全局与数据，唯不复解释函数之体。转译之器在 `库/裸机后端/预编转译。豫`，执行器之运行时之接在 `预编接口。底层。豫`。编译器径出之原生之产，今皆用下文之预编二。

- **值皆居值栈**：布同解释（每槽八字节，引用与三十二位整数居低字），故保守之回收如常见之；转译之函数其签为（帧）→ i32，参数与局部自帧起，操作数其上，调用者置参数于栈顶，被调者之帧即自彼始。
- **简令内联，繁令呼解释之处理**：局部、常量、i32 之算与比较、若干 i64 之令、引用之空与等、控制之流，径书整数之令；结构、数组、类型之转、余 i64 与浮点、访存、表与杂项之令，呼执行器所导之“预编”诸函数（即解释器之处理函数），携立即数于模块字节之址。
- **控制一一相应**：块、环、条件应整数 Wasm 之同名之构，分支先移所携之值于目标之槽；尾调（return_call 及间接、引用之尾调）先移参数于帧首，乃“调用而即返”，寄存器之降化之为尾跳；间接之调经执行器所导之 `预编派发`（依函数号二分，叶尾跳于转译之函数）。
- **异常以标传**：抛则记载荷而置 `状态预编异常`，每调转译之函数后验之，在尝试表内则跳至其处理之码，否则返；至最外犹有异常，则以未捕之异常退（一三七）。
- **大模块**：逾四百四十八千字节模块之窗者（如编译器），不嵌于窗，而为尾块书于可执行文件（Linux 附文件之末，macOS 置 __LINKEDIT 中签名之前），执行器启动时读回于动态区之首；Linux 之代码过大则别为一载入段（ARM64 居 0x10000000，x86-64 居 0x50000000）。预编二之原生文（二〇二六年十月九日起，提案〇〇〇〇七第一步）所嵌乃预编侧表而非客模，侧表逾四百四十八千字节者亦为尾块，执行器识之则径装其表，不解其模。
- **降器因之而扩**：“调用而即返”为尾跳；代码每五百一十二千字节插一陷阱之岛，越界与除零之验跳至最近之岛；巨函（逾二万令）之条件跳改为“反条件跳过加 b”；汇编器唯于条件之分支计十九位之位移（旧时 b、bl 逾一兆字节亦误报逾界）。

今之状（二〇二六年九月二十八日）：macOS arm64 上普通探针、文件探针与原生探针凡十二项，于预编之式与参照之出逐字一致；短程序较解释约快二倍（多为启动之费）。待办：内联更多热令（ref.cast、struct.get、array.get、i31）、非引用之值留于寄存器、Linux 上预编之验、编译器自身之预编与原生之自举。

续记（二〇二六年九月二十九日）：Linux ARM64 预编一致之全组十五项皆过，普通、文件与原生诸探针，同裸机或 Node 之参逐字相符。Linux x86-64 解释之打印探针已过；本机 Docker 之 Rosetta 载较巨预编之物，报 `failed to mmap segment: 22`，犹须于真 Linux x86-64 运行器验之。编译器自身之原生自举犹待成。

## 预编二：客体之值居寄存器与原生之栈（路二乙档之二版）

结构对象头八字节。引用字段一址宽（八字节，见下节），余者仍八，各以其宽齐之；对象总长以八齐，至少十六。继承字段依全字段之序计偏，父型末尾填充不计入子型字段之偏。值栈槽八字节，引用入栈则清高字；数组之约如故。执行器与预编生成器须同结构之约，更约则全套重造；既有原生可执行文件仍藏其执行器与生成之码。

预编二用新转译之器（`库/裸机后端/预编二转译。豫`），编译器 `--目标 本机` 径出之原生之产皆由之。异于初版者：

- **值不复居执行器之值栈**：客体之函数各转为宽整数之函数（`库/裸机后端/宽降级原语。豫`），参、局与操作数皆其所有；值皆六十四位（三十二位与引用零扩），降级者置之于寄存器与原生之栈。宽整数之算书为内在之呼，降级者就地展为六十四位之令。
- **呼则径传其参**：客体函数相呼径传；call_ref 与 call_indirect 经跳表零；执行器经 `预编派发` 呼客体者，经跳表一之适配函数，自值栈之帧读参而书其果。客体之导入由导入之桩经 `预编调用导入` 呼执行器。
- **热令内联**：结构数组之读写与长、i31、验空、精确类型之测转，径书为整数之令；struct.new、struct.new_default 与 array.new_fixed 于游程内递增而取（新游标以常址之书还之，二头字合为八字节之常一书之，起始之位以专用之内在置之，臂八令），不足乃呼 `预编分配`。以常下标取数组之值者不装下标：长径与常数较，元素径取于其偏。下标已知小于其长者（转译之事实：br_if 落空之途，下标之局无号小于某局，而某局为此数组之 array.len）不验界。余令书操作数于值栈之暂区（起于 `状态预编栈顶`），而呼解释之处理。
- **转译时之内联**：径呼或径尾呼他客体函数，其体不逾六十字节、无尝试表与旧式异常之令者，不发呼，而于呼处续转其体。参与局借块临时一段，实参弹入参，余局清零，体包于结果数同之块；被呼者之 return 跳出此块，尾呼化为常呼加验异常而后跳出；展于尾呼之处者，二者仍为呼者之返与尾呼，块后补一返。转译之事实（非空、型、界）遂越函数之界。唯内联一层，不内联己。降级之前另有整数层小叶函数之内联（`库/裸机后端/内联小函数。豫`）。并入之时客体所定之函唯置占位（签名、零局、空体），降与整数层内联需其体时，乃经 `降级取体` 之钩而转：内联之备唯留不逾上限之小体，大函唯留占位，降毕复其钩；遍两万余函以尾递归之带序映射（标准库「遍序」经「遍二」非尾递归，原生保守之扫时两万余帧留诸函降时之临时）。如是原生之程自生原生之产，并存者唯执行器自身之中间表示、小函之体与已降之机器码。
- **回收观原生之栈**：`预编二可用` 为一者，启动预留栈复之缓（原生二百五十八兆，配林檎、Linux 之臂约二百五十六兆之原生栈，唯占虚址）；回收时经目标之内建 `栈复制` 复被调者所保之寄与原生之栈，逐四字节保守而扫。
- **栈图**（提案 00020）：模带预编之客者，降级者于每函之入口置展开之记（帧大与序言所保之寄之次），连时于码后接栈图之表。执行器启时呼占位之出“栈图表复制”（新降级者易为复制之桩，旧者所编之体返零）复其表入动区（`栈图` 模之「栈图表装入」，址记于状态格九〇七二）；臂之栈复之缓首九十六字为 x19 至 x30，兼首四十八字为 rbx、rbp、r12 至 r15。编译之开关「栈图诊断」为一，则每收于栈复之后依表逐帧行原生之栈，印帧数、止因与诸帧之码偏，回收仍保守而扫。第二步以来表中复有呼处之栈图（栈图表第二版之呼处项与容），「栈图表装入」另取二百五十六字记寄位之表（状态格九〇七六）。编译之开关「栈图核对」为一，则每收于栈复之后逐帧行栈，并循被保之寄存于何格（栈复之首或某帧之保格）：旗带二位之客帧依呼处项取精确之根，核其指堆内者皆为物始（坏根），复逐八字视本帧之局与溢槽，数保守之扫得之而精确未报之物址（保守独有）；每收印一行 `栈图核对：帧 … 客帧 … 精确 … 不精确 … 无图 … 根 … 坏根 … 保守独有 … 停因 …` 与若干明细，回收仍保守而扫。
- **精确之客帧**（提案 00020 第三步）：启时「栈图表装入」以空表试呼占位之出“栈回写”一次，新降级者之桩返零，乃记状态格九〇八〇为一（旧降级者所编之体返负一，记零）。六十四位址之构，有第二版之栈图表、栈回写可用而编译之开关「精确客帧」为一者，回收如常栈复之后逐帧行栈（`堆` 模之「精确走栈」）：带精确呼处栈图之客帧依图标其引而不钉，引所在之格（缓中之帧槽，或某帧之保格、栈复之首之寄存器）之线性址记于缓中栈数据后之槽表；执行器之帧与无精图之帧，标其局与溢槽，及本帧序言所保诸寄此时所在格之值；不得其函、出码或至栈复之末，则余栈与诸寄所在之格并保守而扫。保守所得之物，整理时仍钉之。整理迁物，则「精确改写」依槽表改缓中之格，回收之函乃径呼“栈回写”之桩：桩与栈复同在回收之帧，sp 同，以表中所改之帧槽依缓偏书回原生之栈，并以犹唯在寄存器之引（行栈时无帧保之，回收之函亦不用）依掩码装回寄存器。整理之压开者，迁改之后以 0xEE 填疏散之块（「整理毒化」），漏改之引一用即读毒值。三十二位之构与开关为零者，仍全段保守而扫。
- **堆**：小块自游程递增切出，游程取诸堆顶之一段或空闲之大块；皆无则取不小于所需之最大小类空闲块全为游程，余者由预编二之内联分配续切，退游程时依实用计其所分。收唯用标图（不书对象之头），扫毕拷标图为起始之图。
- **分代之收**：收后标图存之，已标者即老对象；第零次及每八次全收，余次收唯标新者。书障以卡表（每五百一十二字节一字节）：struct.set、array.set 书引用前以内在九十一万、九十二万（窥次顶、第三之对象），引用数组之 array.copy 后以内在九十万（弹目数组），书零于对象头所在之卡，臂三令（ldr 卡表、add 加址右移九、strb wzr）；预编、解释者及宿主之 `设元组项` 以常令记之。次收唯扫既脏且有老对象之卡（老卡表：扫时每存活者之卡书一）所始之老对象。分配不得空者：近收以来所配不及先增堆之界，则先增堆（方收未久，再收亦无多空；不移之堆碎而大块屡不可得，旧每先一收，收遂空转）。先增堆之界，宿主之非工作进程为回收阈本身，裸机与编译器工作进程为回收阈之四一（提案 00020 第二步：终链依四一之界，每轮配及阈之四一即因不得中等之块而收，收数倍之；改后原生生成豫构之收约二百三十减为八十五，时减四分之一至四成，峰存增约三成）；及界则先常收一次、犹不足则增堆；堆已至内存之上限者强为全收一次（次收不收老垃圾），其后犹不足乃报堆内存不足。回收下限：编译器之工作进程（首参为 --mode=worker）定为六十四兆，余者起于三十二兆、每收倍之至一吉（裸机至二百五十六兆）；完整构建起短命之工作进程一千五百余，下限一律一吉则未收即尽配于新页（本机一构缺页六千三百万、系统之时二百余秒），今则一千余万、三十余秒，单进程之冷编不变。回收之阈与收后之预留依存活之三倍（回收倍数）：旧阈虽倍存活，堆限唯预留至“存活加下限”，实则每配一倍存活即一收；存活多者每扫必重历诸存活，收数多则费重。改后编译器之终链回收二十六次减为十三、指令减百分之二十六，最慢之类检之务指令减百分之二十，其价则二务之峰存增五至七成。原生之线性内存上限六万五千五百三十五页（约四吉）；六十四位址之构为二之三十次幂页（六十四太），见下节。
- **复制式新生代**（提案 00020 第四步）：六十四位址之构，精确客帧可用而编译之开关「新生代开」为一者开之（新生之记在状态格九〇八四）。堆首留新生之区（小存之裸机留六十四兆，余者一吉，唯占虚址；编译器工作进程命短而存多，不开新生代，常驻之工作者亦不开），老区与堆顶自其后二兆之界起。不逾二百五十六千之物于新生之区碰撞而分（游程为新生区中所钉之物间之隙，预编二之内联分配仍用游标、游限），大者径分于老区，并记于新大物之表（至多六万五千五百三十六项），次收所不标者当轮释之（保守之根指其内者亦为标），不容者留于全收；新生之区始用十六兆，次收后老区之跨逾之二倍则倍之。新生之区尽则次收：先标保守之根（值栈、执行器之帧与无精图之帧、全局与表等），落新生区之物原地钉之（候选之字指物内者亦然）；乃处客帧之精确根、污卡上之老物与标栈：新生区未钉之物复于老区（旧头第三十一位置一示已转，新址书于八），老区前收以来新分之物原地而标；所复之物逐一而扫。乃由栈回写之桩书回客帧之根，新生之区唯余所钉之物，起始之图易为标图，物间之隙复排为游程，卡表尽净。晋升与径分于老区之字入分配之计，及回收之阈（老区存活之三倍）或有强、整理之请者，次收之后续以全收：清标图，自根重标，依需整理，自老区之始而扫，复重置新生之区。林檎之后台清扫与常驻清场皆自老区之始（常驻清场另清新生区所用者）。标栈溢出后之重扫改依标图逐取已标之物。整理之压之下，新生区之隙填 0xEE。
- **精确之根**（提案 00020 第五步）：复制式新生代开而编译之开关「精确根」为一者（常然），回收不复保守而扫值栈、执行器之帧、余根、异常之槽与实例之全局。或收之执行器处置（struct.new、array.new、array.new_fixed 之操作数，单元派发之间导入之果）登值栈之活槽于值栈根之表（状态格九〇九六），回收依结构之类、数组元之类别或函数之类之码精处此诸槽，值栈之余不察；求全局初值之间禁收。异常物之槽与方传之异常之载，依标签函数之类之参码唯处引槽。临时之根、程序之缓、捕缓、入与请之格、子表与原生异步表中之引格、实例之全局与表，皆以引精处：次收复而改之，全收标而不钉，整理迁后改之。子表项之引格：八、二十四捕缓，四十画面，四十八事列，百二十入缓，百四十四外壳请队，百六十外壳来信之队（「其余根精确处理」）；子表项增引用之域，须并登于此。后二格十月十八日补入：前此精收不识此二队之字节数组，既收之，初始任务犹依悬引读写其队，所读已用之数乱，次入队则越界而陷（退码百三十二）；初始任务既止，桌面、网与远登皆随之止。桌面开任务管理器（其请外壳不绝）则一二分之内必见；十月十八日 mbp13 实机经 ssh 截屏而全机卡死者，即此初始任务之陷，截屏适同时而行耳。执行器之帧不扫（执行器原语行时禁收，或收之处置不留引于帧）；唯装载后回收、安全回收二处于宿主之召中自收时（宿主回收之窗，状态格九一〇〇）仍保守而扫执行器之帧。无精图之客帧与行栈不下者仍保守而扫，整理时钉之；栈复仍为执行器读原生之栈之法。开关为零则如旧。待办：全局依类唯处引用之全局；无精图之客帧补其图。
- **还内存**（裸机，二〇二六年十月九日）：每收而扫，以大隙首十六字之后之二兆整块、扫毕以堆顶之上至堆限之下之二兆整块，经平台之务 `归还内存块`（核之服务四十四）还核；核唯收已提交者，后复用之则缺页复提交而尽清（分配本清其载）。空闲块唯用首十六字（头与次块），扫与标唯读存者与位图，故还空闲块之内无碍回收；裸机无后台清扫，扫时亦无当前之游程。如是任务之物理内存随存活而涨落，所空者可予他任务。裸机之回收阈又依空闲之物理内存而压之（核之服务四十五 `空闲内存块数`：不逾空闲之半，不下十六兆），常驻进程之回收下限倍至二百五十六兆而止，诸任务合之不至远逾物理内存。林檎与 Linux 原生（六十四位址之构，提案 00020 第六步）亦还此诸整块：以此段易为新之匿零页（mmap MAP_FIXED，旧之物页随释），Linux 径呼映射内存长，林檎以启时依名所得之 mmap 经动态呼块呼之（不分配，后台清扫之线亦可呼）；本机一反复造大列之探针，最大常驻自一点六零吉降至一点零一吉。
- **整理回收**（提案 00017）：块表接老卡表之后（每二兆块一项：块内所始存者之字、钉与疏散之标、块内所始之物最远之末），其前为五百一十二字之整理之记。裸机三处起整理（默认迁之）：装载后回收（父务堆跨及一吉，并书其计）、分配不得地之强全收、每八收一全收而碎率高者（本务已提交之动态块不少于六十四，且块数乘二兆逾前收存活之倍，则先计之；标毕依有存之块数乘二兆逾此番存活之倍乃迁）。整理时，标根之前清块表，标根时根所指之物钉其块（`钉标候选`），扫异常之物时槽所指者亦钉之，标毕依标图逐块计存（一兆以上之大物钉其所覆之块），择疏散之块：全在 [堆基, 堆顶) 之中、未钉、存不及块长之半；不疏散之块所始之物伸入次块者，次块亦不疏散；依存分档自少而多取之，迁量受堆之内存上限与核池空块（减六十四块之余）所限。装载后回收之整理，裸机径书一行于控台：`整理：跨度 … 兆 已提交 … 块 有存活 … 块 存活 … 兆 钉住 … 块 候选 … 块 疏散 … 块 搬移 … 兆 填隙 … 兆 新占 … 块 空闲 … 块`（填隙者，填于不疏散块之隙之字；新占者，堆顶之上实所用之块），扫而还之后复书 `整理后：已提交 … 块 跨度 … 兆 交还 … 块`（交还者，此扫还核之块数）。迁：内存先长至堆顶加迁字，依块序逐疏散之块按址次迁其存者：不逾二千四十八字之物先填于不疏散块中存者之间之隙（其块本占；隙不跨块界，前块疏散者自其所始之物最远之末以后算之，不覆未迁之物），隙尽或物大则碰撞分配于堆顶之上；全复其物、置新物之标位，旧头首址宽书新址；乃逐块历不疏散之块（含新物）改结构之引用域与引用数组之元（指疏散块者易为旧头所书之新址；异常物之槽不动，所指皆已钉）；去疏散块之标位而如常扫之，疏散之块为隙而全还（扫以二兆以上之隙中之整块还核，夹于二留块之间之单疏散块亦得还），起始之图、卡表与老卡表仍由扫重立。压之模式（`布局` 之编译开关 整理压力）：为一或二则每全收疏散诸未钉之块、每二收一全收、疏散之余降至二块；为一则收阈定为四兆（小程亦屡收，验机用之），为二则收阈如旧（编译器诸大工用之）。宽格区八八四八至八八七九之四格（输入之缓、二请参、远程之果）改为全段为根，远程之果取之即清。宿主之验 `整理回收。底层。测试。豫` 须平台之导入，以编译器 `--目标 本机` 编为本机之程而行之（全树之验唯核其类）。

- **底层之转送**（二〇二六年十月十四日，提案〇〇〇二一第十一步，`底层转送`、`底层服务`）：子任务（裸机之子任务与豫行启动器中之客）之文件原语同原生自行之，底层之呼不自办：书服务之号与六参（各八字节）于底层请求块（启时取之，块址存于状态格三千六百一十二），发底层请求之信（标 0x64）于柄零，候其应答（标 0x74，低二十四位为状码）。裸机初始任务依转柄之表（二千零四十八项：主、inode、标志、位置、绝径）径以文件系统之读区间、书区间与续书办之，数据经服务四十一、四十二拷之，一次至多一兆；豫行启动器交己之宿主后端办之，客之文件柄即宿主之描述符。子任务起程之时，查长、读程与寻可执行亦走底层之呼，程序后备之录经扩展之服务百六十取之。裸机子任务之柄零、一、二不转送。传输控制之原语七十七至九十亦自行之（原生网络原语），套接之底层之呼转送之后，裸机初始任务以网络栈办之（套接为类别三之转柄），启动器以宿主之套接办之；候者裸机上子任务小睡十毫秒而复问。数据报之交换百七十六与林兼容之层（`林兼容/转送`）之文件与网络之呼亦经转送：底层文件〇点二之建链百六十三、改模式百六十四，底层网络〇点二之建数据报百六十五、连数据报百六十六、发数据报百六十七、收数据报百六十八、取套接字地址百六十九；裸机初始任务以文件系统与网络栈办之（数据报之端亦为类别三之转柄；读链接可用，取状态并书 inode、种、权位与链数），启动器以宿主办之。整块代办惟余系统库之原语。进程：子任务之子程序之原语依原生之法行之（`原生子进程`），读单调纳秒百一十、建管道百三十二、运行程序百五十二、取进程退出码百五十三、终止进程百五十四、打断进程百六十一、取进程信息百六十二经转送（原语百九十五、百九十六、百四十五用后二者）。裸机初始任务为子任务载而建任务，子进程登于初始任务之子表为代管之项，管为初始任务之管道表项（接出者收子之捕获之信，接入者经入之通道），/dev/null 为空设备之转柄；启动器交宿主办之。宿主门（状态格三千六百二十）：子任务读启动块毕，以扩展之服务百八十取服务之方，启动器回一（宿主门中：柄零、一、二亦转送，即宿主之标准流；命行之宿主之选照原生解之），裸机初始任务回二。宿主门中带面之子程序（百八十二至百八十五）行林檎之管道代办，子之二端经设可继承（百八十一）留予子程序。
- **每信视期**：显示面之候每办一信即视期一次（`显示轮办`），桌面依时取出至多办约三十毫秒（`排空捕获限`）。
- **初始任务之纯限时候**（二〇二六年十月二十日，提案 〇〇〇四二，`主机任务` 之「空候至」）：初始任务之多路之候（原语六十九）无所候而限在一毫秒至千万毫秒（「限时让」之纯候），则以一滴十毫秒折为期，候至其期，其间逐信办子任务之信，箱空则小睡一滴；开机壳候所起之后台子任务（如「诣行在」候实例之行在）时，子之代办常有所理。
- **影子之帧**：常构之裸机执行器开机依帧缓之尺取影帧一块，每交画之后拷区所在之行于其中，指移与光标随动皆以之补交光标；旧则用应用每帧暂复之字串，见收之后光标旧位常绘为黑块。

## 后备熵源（二〇二六年十月十四日）

处理器无随机之令（RDRAND、RNDR）者，安全随机字节串（原语九十八）由 `熵池。底层。豫` 出之，ThinkPad E40（Arrandale）与 QEMU 之 qemu64、cortex-a53 亦得行 SSH 之握手、TLS 与主机钥之生。

- **熵池**：布局 `状态熵池`（自九四二四始百七十六字）中三十二字之沙256 之态，并出计、已播之标、事熵、存种之秒与百二十八字之信区。
- **播种**：初取则混任务号、时钟滴答、墙钟之秒、周期之计、事熵与数据盘之种子文件 `/系统/随机种子`（首六十四字），复采计时之抖五百一十二次（读周期之计、搅存一段、复读，差入于池，每十六次求沙256 一次）。
- **周期之计**：目标之内建导入“周期计数”，兼为 RDTSC，臂为 CNTVCT_EL0，各取低三十二位。
- **事熵**：小睡醒（时钟与设备中断之时）、按键、收包，皆以周期之计混于事熵之格（`平台` 之 `记熵事件`，网络栈之 `收包记熵`）。
- **种子之文**：播种之后即由池单向导出六十四字书于 `/系统/随机种子`，此后每时复书之；壳命「关机」「重启」动手之前亦书之。次开机所读者为新种。
- **取数**：每三十二字出计加一，以池、出计、周期之计、任务号、滴答、事熵求沙256 一次；取毕池复单向更之。复制之子任务携父之池，取时混己之任务号与周期之计。
- 处理器有随机之令仍用之；原生之平台仍用系统之随机源。获取随机整数与获取随机小数（原语九十六、九十七）仍退用备用随机四字。

## 数据盘之扩（十月十四日）

`数据盘扩展` 就地扩数据盘之 ext4 至器末：旧组与文件仍其旧，新地以整组接于其末（每组自带位图与书零之节点表），组描述块不足则开 META_BG，终于一日志事务改超级块、旧末描述块与旧末组之位图；未挂之盘（安装系统所书之目标盘）径书之，超级块最后书。原语四十七询数据盘、四十八扩数据盘（任务监测接口〇点四）与四十九扩磁盘之数据区（磁盘接口〇点二）皆由持文件系统缓冲之初始任务办之，子任务经远程原语转之。文件系统之 `盘组描述块` 依 META_BG 求描述块。其法与盘面见 [客体文件系统](../文档/客体文件系统.文言.md) 之“扩容”。
