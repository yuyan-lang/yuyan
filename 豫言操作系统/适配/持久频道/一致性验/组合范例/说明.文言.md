# 组合范例：服务商连接缩影

以**网页事件流**与**持久频道**二接口，复云仓 AI 市场 `AI服务商连接` 持久对象（`应用/包管理服务/源码/服务商连接.js`）之接口行为：

- `GET /connect?心跳=毫秒`：出站所建之 SSE 长联。响应头固定为 `text/event-stream; charset=utf-8`，附 `X-Accel-Buffering: no`；首帧 `: connected`，其后每心跳周期书一帧 `: ping`（默认十五秒，测中缩为五十毫秒）；新联向频道发“替令”，旧联读之而正终其流并撤订；服务商之断由心跳之书察而清之。
- `POST /dispatch`：**他事**。校其请（编号、协议、体、二百五十六 KiB 之限），无联则返 503，同一时刻惟理一请（D1 唯一行占位，次者得 503）；订该请之分片频道，以任务帧经频道推于长联（大请求依每片至多一万六千码点切为多条讯，长联侧按序原样书回而成完整一帧），乃以事件流答调用方，转服务商所回之片；服务商报误则**止**调用方之流，逾时亦止，调用方断则向服务商发 `cancel` 帧。
- `POST /chunk`：**他事**。校序号（重复则略、跳号则 409）、片之大小与总量（二兆之限），以片经频道转与正读之调用方，`done` 与 `error` 收尾。
- `GET /status`：在线与否（读持久频道订阅数）与进行中之请求数。

其所示者，二接口如何相配：连接之事与派发之事不共内存，惟以频道相通；派发之事先订分片频道而后下任务，服务商之回传不遗；每订皆于诸出口配一撤，事毕之前以终或止收尾。`/connect` 为长联：薄宿主不另设每事之墙钟之限（`应用/执行配置.json` 乃旧宿主之限配，薄宿主不读），联断则令客重联（服务商软件本自如此）。

## 复行

于构建根行之（语言仓根本身即可，须已依今之源码成 `yy豫构`；用法与依赖之解见[豫构发行说明](../../../../../应用/豫构/文档/发行.文言.md)）。编译缓存以编译器可执行文件之修改时间为准，数构建同用一编译器则共其缓存（缓存原子而书，可并行）。

一、`./yy豫构.exe 发行 云工 <本目录>/应用 dist/服务商连接缩影`。
二、Node：`env 产物目录=<构建根>/dist/服务商连接缩影 node --test --test-force-exit 服务商连接缩影.test.mjs`（于此目录行之；`<构建根>` 谓构建根之绝径）（同一宿主对象上并发诸 `durable-fetch`；预期十一则尽通过）。
三、本地 workerd（真持久对象与 HTTP）：豫言之测 `../云端复验/服务商连接云端复验。测试。豫` 一令毕构建、起 wrangler、复验与止（其法同[上级说明](../说明.文言.md)“于本地 workerd 复行”，以此目录 `应用/建表.sql` 建表）：`./yy豫构.exe 文件 豫言操作系统/适配/持久频道/一致性验/云端复验/服务商连接云端复验。测试。豫 --输出 yy服务商连接云端复验.wasm -j 24`，复 `node 豫言操作系统/宿主/节点/宿主.cjs yy服务商连接云端复验.wasm`。薄宿主上已通过；所观：调用方断后服务商又回传三片，应用始察而发 `cancel`；服务商断后约三百零五至三百三十毫秒（心跳百毫秒）被察而清之。

## 与原 JS 之异（迁时当察）

一、原码之 `Content-Type` 随协议而变（`text/event-stream`、`application/x-ndjson`、`application/json`），网页事件流之内容种类固定为 `text/event-stream; charset=utf-8`：此范例统一调用方之答为事件流；欲存 NDJSON 与整段 JSON 二者，须另一流式响应之接口（宜于后续之版增带内容种类之 `开始入站流式回应`）。
二、单 SSE 帧、分片之讯、频道之讯皆受六十四 KiB 之限，原 JS 之二百五十六 KiB 请求帧因而切为多条频道讯；分片之数据于此范例限三万二千七百六十八字节（原为六万五千五百三十六），盖 JSON 转义之后须纳于一条频道讯。
三、长联存活之时，平台之 CPU 限额为之底；程序返而未终之响应流，网页事件流适配收尾终之，遗订则留至持久对象见逐（见持久频道适配说明之待办之事）。
