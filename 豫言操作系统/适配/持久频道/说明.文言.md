# 持久频道云工适配

`频道。豫` 纯以豫言书之，惟以云工薄宿主之通用原语（`库/云工宿主` 之物宿主与物）取 `scheduler`、`AbortController`、`Date`、`crypto`。其行[持久频道公约](../../../豫言操作系统接口/持久频道/规范.文言.md) 0.1.0：订、保序而发、限时而候、撤、闭与订数。

## 所以行之

- **频道之表**：频道表与订柄表皆此实例之顶层可变之格。薄宿主一持久对象惟一实例，同对象之诸事赖此二表相通，本为跨请所共之态：其域与持久对象同，对象见逐则失。读写之间无挂起之点，交错之事不相覆。频道表惟存有活订之频道（依订之先后），无订则删。
- **限额**：每实例至多六十四频道、每频道至多二百五十六订，逾则皆抛可捕之豫言异（“持久频道数已达上限 64”“持久频道订阅数已达上限 256”）；讯文至多六万五千五百三十六字节，不得以字节 0xFF 起首；每订之积压（未取之字节）至多一 MiB。
- **发**：讯文原样入各订待取之列（前段依至之先后，后段新至者居前，前段取尽则翻后段续之），依订之先后投之，返所达之数。积压加此讯逾一 MiB 之订断之：清其列，状态二，因曰“订阅积压超过 1 MiB，已被断开”，不计于所达。
- **候与逾时**：列中有讯则取一而返状态零；否则新造一 AbortController 登于其订，`scheduler.wait(余毫秒, {signal})` 寐至期或见醒；发、闭、撤皆止此 AbortController 以醒候者，醒则复察其列，余时依期重算，故读订数不使候久或暂。期至返状态一，零超时即立察。
- **闭**：频道即删于频道表（同名可复订），诸订先尽其已排之讯，乃得状态二与闭因；返所闭之订数。
- **撤**：幂等；终其订（因曰“订阅已取消”），离频道，醒候者；此后候之返状态二。
- **订阅柄**：取 `crypto.randomUUID()`，诸订不同，亦不可猜。订柄表新者居前；已终之订暂留，以令终后再候仍得二，惟留最近四千零九十六条，其前者弃之，后用其柄则得“订阅柄无效”。
- 用于持久对象之中，不察事类（提案 C0001）：于他事调之，频道属此程序之实例。
- 内部诸辅助之名皆以 `持久频道内` 起首。

待办之事：薄宿主不知事之何时毕，订柄不能随事而废，同实例他事得其柄亦可用；事毕亦不自撤其遗订，遗订恒占频道之额，至对象见逐乃已。应用须于诸出口撤其订。

## 部署之要

一、全局 `scheduler.wait`：Workers 自具；Node 宿主以 `node:timers/promises` 之 `scheduler` 垫片经 `创建云工宿主({全局})` 授之，见 `一致性验证/工具.mjs` 之 `造全局`。
二、存活之时：薄宿主不另设每事之墙钟之限，平台之 CPU 限额为之底；久候与转之循环，当带周期之逾时与心跳。

## 本地 workerd 之实测（Wrangler 4.129.0，兼容日 2026-09-10，同一持久对象实例上诸并发 `durable-fetch`，真实 HTTP 与真实 D1）

薄宿主上之复验（`持久频道云端复验.test.mjs` 九项、组合范例 `服务商连接云端复验.test.mjs` 一项）尽通：

- 跨请求订与发、多订者按序各得一份、逾时之精（探订数不改其久暂）、闭而先交后终、六十四 KiB 之讯与零长之讯、订限二百五十六与积压断之因文、一订之内收发三千条、先订后放之窗去重（真实 D1 上恰各一次），皆正。
- 已有六十四频道（前事之遗订）而再订新频道，则抛豫言之异，试验应用答 HTTP 500。
- **客断之后持久对象内之事续行**：订者之事于客去后犹为频道之讯所唤，断后又发三条乃察其断，而后应用撤订。阻候之时（无书）客断不醒候者，惟讯至或逾时至方复行，故长联之转，赖心跳与周期之逾时。
- 云端（Cloudflare 边缘）之行留待验之。

`一致性验证/` 含试验应用 `持久频道一致性应用`（实 Wasm）、Node 测试 `持久频道一致性.test.mjs`（同一宿主对象上并发诸 `durable-fetch` 以拟同一持久对象之诸事：跨事订与发、多订者、多发者保序、逾时与探、零超时、闭、撤、无效之订阅柄、二百五十六与六十四之限、积压断、万条之讯、文字之则、频道名之则、非持久对象之事不依事类而拒、实例相隔、先订后放去重之范）、组合范例 `服务商连接缩影应用`（以二包复 AI 服务商连接持久对象：`/connect` 事件流带心跳、`/dispatch` 与 `/chunk` 乃他事、新联代旧联）及其测试，并有真实 workerd 复验之驱动。复行之法见该目录说明。
