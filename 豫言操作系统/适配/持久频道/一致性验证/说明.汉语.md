# 持久频道一致性验证

本目录验证[持久频道接口](../../../../豫言操作系统接口/持久频道/规范.汉语.md)的云工适配。试验应用在 `应用/`（为免被全仓库包发现，包描述存为 `持久频道一致性应用。包。豫.txt`，构建时改回 `持久频道一致性应用。包。豫`），Node 测试是 `持久频道一致性.test.mjs`：**同一个宿主对象上并发多个 `durable-fetch`**，模拟同一个持久对象实例的多个事件（宿主对象上的频道注册表随该对象存续，作用域与真实 Durable Object 一致；`新宿主` 每次创建新的宿主对象，等于新的持久对象实例）。覆盖：跨事件订阅与发布（订阅之后必达、订阅之前不补发、事件结束后订阅数归零）；三个订阅者按序各得一份；多个发布者并发时每个订阅内同一发布者保序且无丢失；等待超时（不被订阅数探测拉长或缩短）、零超时轮询、越界超时抛异常；关闭（已排队的消息先交付、再得状态 2 与原因、同名可重新订阅）；取消幂等且取消后再等待得状态 2；无效柄与他事柄（含句柄号相同）抛异常；订阅上限 256（第 257 个抛可捕获异常）与频道上限 64（宿主拒绝）；积压超过 1 MiB 被断开（原因文字、之后不再送达）；单订阅内收发 5000 条不耗尽宿主句柄；文字规则（0 与 65536 字节可发，65537 与字节 0xFF 起首被拒，多字节按字节计）；频道名规则；普通 `fetch` 事件调用得可捕获异常；不同宿主对象互不相通；消息按字节原样往返（NUL、控制字节、换行、增补平面字符）；**先订阅、再回放、再合并实时**范例（含凭 `Last-Event-ID` 重连，订阅与读头之间窗口内到来的事件恰好出现一次，从中间序号续读，4 个追加者并发加 3 个不同时刻开始的流，每个流恰好各见每个事件一次）。另有一条“收尾流”测试：事件结束时宿主自动取消本事件遗留的订阅（宿主已并入 `收尾流`，见[网页事件流适配说明](../../网页事件流/说明.汉语.md)）。

`组合范例/` 是用两个包实现的“服务商连接”缩影，见[组合范例说明](组合范例/说明.汉语.md)。

## 复跑

在构建根里运行（语言仓根目录本身即可，需已构建 `yy双宿主构建`、`yy3_bs`、`yy豫言操作系统绑定`、`yy豫言操作系统装载包`；用法与依赖解析规则见[双宿主构建说明](../../../../工具/双宿主构建/说明.汉语.md)）。编译缓存由编译器可执行文件的修改时间决定，多个构建同时用同一编译器会共享缓存，勿并发。

1. 构建试验应用：`./yy双宿主构建 --自动 云工 <本目录>/应用 dist/持久频道一致性`，产物在 `dist/持久频道一致性/`。
2. 跑测试（Node 26 以上）：`env 产物目录=<构建根>/dist/持久频道一致性 node --test --test-force-exit 持久频道一致性.test.mjs`（在本目录里运行；`<构建根>` 指构建根的绝对路径）。预期 23 通过、0 待办。`scheduler.wait` 的垫片见 `工具.mjs` 的 `造全局`。

## 在本地 workerd 里复跑

1. 把 `dist/持久频道一致性/` 复制到空目录，去掉 `程序.wasm.wat`，放入本目录 `云端复验/` 的 `rig.mjs` 与 `wrangler.jsonc`（含兼容标志 `enable_request_signal`；事件流转发需要请求信号才能发现客户端断开）。
2. 建 D1 表：`wrangler d1 execute DB --local --persist-to <工作目录>/.state --file <本目录>/应用/建表.sql`。
3. 起服务：`wrangler dev --local --port <端口> --persist-to <工作目录>/.state`。
4. 复验：`env 远端地址=http://localhost:<端口> node --test --test-force-exit 持久频道云端复验.test.mjs`。每个测试用自己的频道名；“频道上限 64”一条用 `x-do` 请求头指向专属的持久对象实例，因为订阅不随事件结束回收，会把主实例的 64 个频道名额占满。

已在 Wrangler 4.129.0 上全部通过：跨请求订阅发布、超时精度、关闭、64 KiB 与零长消息、256 与积压、3000 条消息、64 频道上限（第 65 个得 HTTP 500）、真实 D1 上的回放去重、客户端断开后事件被消息唤醒并取消订阅（断开后又发布 3 条才发现）。云端行为待验证。
