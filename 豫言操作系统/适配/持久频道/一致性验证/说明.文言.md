# 持久频道一致性验证

此目录验[持久频道公约](../../../../豫言操作系统接口/持久频道/规范.文言.md)之云工适配。试验应用在 `应用/`（为免全仓库发现包时误析，包描述存为 `持久频道一致性应用。包。豫.txt`，构建时改回 `持久频道一致性应用。包。豫`），Node 之测为 `持久频道一致性.test.mjs`：**同一宿主对象上并发诸 `durable-fetch`**，以拟同一持久对象实例之诸事（宿主对象上之频道注册表随该对象而存，其域与真实 Durable Object 合；`新宿主` 每造新宿主对象，即新持久对象实例）。所涵：跨事订与发（订后必达、订前不补、事毕后订数归零）；三订者按序各得其一；诸发者并发则每订之内同一发者保序而无失；候之逾时（不为订数之探所增减）、零超时轮询、越界之时抛异；闭（已排之讯先交，再得状态二与因，同名可复订）；撤幂等而撤后再候得状态二；无效之柄与他事之柄（句柄号纵同）抛异；订限二百五十六（第二百五十七抛可捕之异）与频道限六十四（宿主拒之）；积压逾一 MiB 而被断（因文、其后不复达）；一订之内收发五千条而不尽宿主句柄；文字之则（零与六万五千五百三十六字节可发，六万五千五百三十七与字节 0xFF 起首者拒，多字节按字节计）；频道名之则；常 `fetch` 事调之得可捕之异；异宿主对象不相通；讯按字节原样往返（NUL、控制字节、换行、增补平面之字）；**先订、后放、再并即时**之范（含凭 `Last-Event-ID` 重联，订与读首之间窗内所来之事恰现一次，自中序号续读，四追加者并发加三于异时起之流，每流恰各见每事一次）。有“已知限制（待宿主改进）”之测别有一则“收尾流”之测：事毕时宿主自取本事所遗之订（宿主已并 `收尾流`，见[网页事件流适配说明](../../网页事件流/说明.文言.md)）。

`组合范例/` 乃以二包实现之“服务商连接”缩影，见[组合范例说明](组合范例/说明.文言.md)。

## 复行

于构建根行之（语言仓根本身即可，须已成 `yy双宿主构建`、`yy3_bs`、`yy豫言操作系统绑定`、`yy豫言操作系统装载包`；用法与依赖之解见[双宿主构建说明](../../../../工具/双宿主构建/说明.文言.md)）。编译缓存以编译器可执行文件之修改时间为准，数构建同用一编译器则共其缓存，勿并行。

一、构建试验应用：`./yy双宿主构建 --自动 云工 <本目录>/应用 dist/持久频道一致性`，产物在 `dist/持久频道一致性/`。
二、行测（Node 二十六以上）：`env 产物目录=<构建根>/dist/持久频道一致性 node --test --test-force-exit 持久频道一致性.test.mjs`（于此目录行之；`<构建根>` 谓构建根之绝径）。预期通二十三、待办零。`scheduler.wait` 之垫片见 `工具.mjs` 之 `造全局`。

## 于本地 workerd 复行

一、取 `dist/持久频道一致性/` 复制于空目录，去 `程序.wasm.wat`，纳此目录 `云端复验/` 之 `rig.mjs` 与 `wrangler.jsonc`（含兼容标志 `enable_request_signal`；事件流转发须请求信号方能察客断）。
二、建 D1 表：`wrangler d1 execute DB --local --persist-to <工作目录>/.state --file <本目录>/应用/建表.sql`。
三、起服务：`wrangler dev --local --port <端口> --persist-to <工作目录>/.state`。
四、复验：`env 远端地址=http://localhost:<端口> node --test --test-force-exit 持久频道云端复验.test.mjs`。每测用己之频道名；“频道限六十四”一则以 `x-do` 请求头指向专属持久对象实例，盖订不随事毕而收，会尽主实例六十四频道之额。

已于 Wrangler 4.129.0 上尽通过：跨请求订与发、逾时之精、闭、六十四 KiB 与零长之讯、二百五十六与积压、三千条之讯、六十四频道之限（第六十五得 HTTP 500）、真实 D1 上之放回去重、客断后事为讯所唤而撤订（断后复发三条而后察）。云端之行待验。
