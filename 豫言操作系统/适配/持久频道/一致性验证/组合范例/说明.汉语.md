# 组合范例：服务商连接缩影

用**网页事件流**与**持久频道**两个接口，复现云仓 AI 市场 `AI服务商连接` 持久对象（`工具/包管理服务/源码/服务商连接.js`）的接口行为：

- `GET /connect?心跳=毫秒`：出站建立的 SSE 长连接。响应头固定为 `text/event-stream; charset=utf-8`，附 `X-Accel-Buffering: no`；首帧 `: connected`，此后每个心跳周期写一帧 `: ping`（默认 15 秒，测试里缩为 50 毫秒）；新连接向频道发“替换令”，旧连接读到后正常结束流并取消订阅；服务商断开由心跳写入发现并清理。
- `POST /dispatch`：**另一个事件**。校验请求（编号、协议、体、256 KiB 上限），无连接返回 503，同一时刻只处理一个请求（D1 唯一行占位，第二个得 503）；订阅该请求的分片频道，把任务帧经频道推给长连接（大请求按每片至多 16000 个码点切成多条消息，长连接侧按序原样写回成完整的一帧），再以事件流回应调用方，转发服务商回传的分片；服务商报错则**中止**调用方的流，超时也中止，调用方断开则向服务商发 `cancel` 帧。
- `POST /chunk`：**另一个事件**。校验序号（重复忽略、跳号 409）、分片大小与总量（2 MB 上限），把分片经频道转给正在读取的调用方，`done` 与 `error` 收尾。
- `GET /status`：在线与否（读取持久频道订阅数）和进行中的请求数。

它演示了两个接口如何配合：连接事件与派发事件不共享内存，全靠频道通信；派发事件先订阅分片频道再下发任务，服务商的回传不会丢；每个订阅都在所有出口配一次取消订阅，事件结束前用结束或中止收尾。由于 `/connect` 是长连接，构建时带 `应用/执行配置.json`（`durable-fetch` 与 `fetch` 时限 15 分钟）；需要更久的连接应让客户端重连（服务商软件本来就会）。

## 复跑

在构建根里运行（语言仓根目录本身即可，需已构建 `yy双宿主构建`、`yy3_bs`、`yy豫言操作系统绑定`、`yy豫言操作系统装载包`；用法与依赖解析规则见[双宿主构建说明](../../../../../工具/双宿主构建/说明.汉语.md)）。编译缓存由编译器可执行文件的修改时间决定，多个构建同时用同一编译器会共享缓存，勿并发。

1. `./yy双宿主构建 --自动 云工 <本目录>/应用 dist/服务商连接缩影`。
2. Node：`env 产物目录=<构建根>/dist/服务商连接缩影 node --test --test-force-exit 服务商连接缩影.test.mjs`（在本目录里运行；`<构建根>` 指构建根的绝对路径）（同一宿主对象上并发多个 `durable-fetch`；预期 11 条全部通过）。
3. 本地 workerd（真实持久对象与 HTTP）：按[上一级说明](../说明.汉语.md)“在本地 workerd 里复跑”，用本目录 `应用/建表.sql` 建表，`env 远端地址=http://localhost:<端口> node --test --test-force-exit 服务商连接云端复验.test.mjs`。已通过；观察：调用方断开后服务商又回传了 3 个分片，应用才察觉并发出 `cancel`；服务商断开约 335 至 354 毫秒（心跳 100 毫秒）后被察觉并清理。

## 与原 JS 的差异（迁移时需注意）

1. 原代码的 `Content-Type` 随协议而变（`text/event-stream`、`application/x-ndjson`、`application/json`），网页事件流的内容类型固定为 `text/event-stream; charset=utf-8`：此范例把调用方响应统一为事件流；要保持 NDJSON 与整段 JSON 两种，需要另一个流式响应接口（建议 0.2.0 增加带内容类型的 `开始入站流式回应`）。
2. 单个 SSE 帧、分片消息、频道消息都受 64 KiB 上限，原 JS 的 256 KiB 请求帧因此被切成多条频道消息；分片数据在此范例限 32768 字节（原为 65536），因为 JSON 转义后要放进一条频道消息。
3. 长连接受每事件墙钟时限约束（默认 30 秒，配置至多 15 分钟）；被时限终止的连接，在当前宿主上会遗留未取消的订阅与悬挂的响应流（见适配说明“宿主改动请求”）。
