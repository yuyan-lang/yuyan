# 上游流一致性验证（命名持久服务 0.2.0）

此目录验授权服务〇点三、网页上游〇点二、命名持久服务〇点二之带正文请、渐读与转发。三能力包之一致性验证目录各存同一试验应用之副本，以便各自独立复行；此目录之测试文件重在 `命名持久服务`。

## 内容

- `应用/`：试验应用 `上游流一致性应用`，依三能力包及网页入站、网页答复。`POST /run` 受 JSON 之述（`op` 取 `svc`、`svcold`、`up`、`upjson`、`pub`、`do`、`dotext`、`multi`、`badhandle`），`/fwd`、`/svcpass`、`/uppass`、`/dopass` 行转发与原答；读果书为无控字之报（块以 `〔〕` 括之，段以 `‖` 分之）。内含仿 `AI市场应用/流式答复。豫` 之 SSE 渐析（惟测试用），示“读一五帧 SSE，边读边累计字节”。应用包描述存为 `上游流一致性应用。包。豫.txt`，以免被 `yy豫构` 之全仓库包发现所析；`yy双宿主构建 --自动` 自还原名而后构建。
- `测试/`：Node 测试，以类实例作服务绑定桩与持久对象桩（宿主桥惟对非纯物发句柄），皆连真 Wasm。`桩.mjs` 供慢速分块流、桩与宿主之装配。测试文件：`命名持久服务.test.mjs`（十五例：流读、查询之编与任意字正文、参违、期满/误/止/有限读、文字术八 MiB 之限与可捕之对象抛错、转入站请之 SSE 直通、白名之头、请体流式、违规、先请后作原答）。
- 真 workerd 冒烟见 `授权服务` 之一致性验证目录。

## 复行

于构建根行之（语言仓根本身即可，须已成 `yy双宿主构建`、`yy3_bs`、`yy豫言操作系统绑定`、`yy豫言操作系统装载包`；用法与依赖之解见[双宿主构建说明](../../../../工具/双宿主构建/说明.文言.md)）。编译缓存以编译器可执行文件之修改时间为准，数构建同用一编译器则共其缓存，勿并行。`<构建根>` 谓构建根之绝径。

```
./yy双宿主构建 --自动 云工 <语言仓>/豫言操作系统/适配/命名持久服务/一致性验证/应用 dist/上游流一致性
cd <语言仓>/豫言操作系统/适配/命名持久服务/一致性验证/测试
env "产物目录=<构建根>/dist/上游流一致性" node --test --test-timeout=200000 命名持久服务.test.mjs
```

环境变量 `产物目录` 指所构 `dist/上游流一致性`（缺省为当前目录下 `./dist/上游流一致性`）。测试之间须以有引用之定时器保活（测试文件已处），以 `AbortSignal.timeout` 之定时器不占 Node 事件循环也。

## 须知

- 构建须最新之接口与适配（含网页入站、网页答复）；他人改共享文档后，须先重生各适配之 `宿主提供.json`。
- 公网 HTTPS 上游经全局 `fetch` 而发：Node 测试以 `创建云工宿主({全局})` 注假 `fetch`，静态来源之术以 `网络` 注之；程序许可 `OUTBOUND_ORIGINS` 必含通配来源 `https://*` 方可用公网术。
- 宿主执行一事之默认时限为三十秒（`创建豫言实例`），流读逾此者，须宿主使时限可配。
- 真 workerd 冒烟会于当前目录生成 `.wrangler/` 之缓存，宜于语言仓之外之目录行之（如系统临时目录），毋留其缓存于仓中。
