# 网络接口节点适配

此为路一节点宿主之[网络接口](../../../豫言操作系统接口/网络/规范.文言.md)适配，宿主以节点自带之 `fetch` 发出站之 HTTP 请。

- 授权：所向之源（协议、主机、端口）须在启时之 `--允许源` 中，如 `--允许源 https://example.com`；否则 `未获授权`，不发。
- 核对：法限 `GET`、`HEAD`、`POST`、`PUT`、`PATCH`、`DELETE`、`OPTIONS`；址须为绝对之 `http:` 或 `https:`；标头不合、`GET` 与 `HEAD` 带正文者，皆 `输入无效`。
- 转址：以 `redirect: 'manual'` 发之，遇 301、302、303、307、308 即 `宿主操作失败`，不及次跳；304 及他状（含 4xx、5xx）皆为已得之答。
- 限额：`读取请求正文上限`、`读取响应正文上限` 皆十六兆字节（值桥单次交换之限）；请文逾之、答文累逾之，皆 `资源配额已尽`，答逾则即止其读。传输之败为 `宿主操作失败`。
- 答全存于豫言：状态、标头与正文；标头之名皆小写，`读取网页响应标头` 以 ASCII 不分大小写寻之，重名者依 Fetch 规范合为一值（`set-cookie` 各存）。

新增宿主原语（外调名）：`豫言_节点_网络发送`（可挂起，返（码，HTTP 状态，标头之结森文，正文，辞））与 `豫言_节点_网络正文上限`，实于 `豫言操作系统/宿主/节点/应用宿主.mjs`；码之编号同文件适配。此适配依基础接口之 `错误` 模。待办事项：请求之限时与取消。

**平台接口**：此适配之包之函转调平台接口之包中无体之声，编为带型之宿主导入（边界之签见《网页汇编接口》网五）：「诺节宿主」之「网络原语」之「诺节网络发送」（旧外调名 `豫言_节点_网络发送`）、「诺节网络正文上限」（旧外调名 `豫言_节点_网络正文上限`）。宿主实此诸导入，与旧原语同。
