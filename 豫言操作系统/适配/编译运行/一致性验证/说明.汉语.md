# 编译运行一致性验证

在真实豫言 Wasm、真实宿主运行器、真实豫言编译器与标准库资料上，分别于 Node 进程内与本地 workerd（Miniflare）验证[编译运行接口](../../../../豫言操作系统接口/编译运行/规范.汉语.md)的云工适配。

- `应用/`：试验应用 `编译运行一致性应用`（包描述存为 `.包。豫.txt`，避免被 `yy豫构` 的全仓库包发现当成包；构建脚本会把应用目录复制到暂存内的临时目录并改回原名）。它在**同一个事件里**依脚本逐步调用接口的五个函数并返回各步结果（详见 `应用/入口。豫` 的注释）：一个 HTTP 请求一段脚本，因为运行号只在启动它的事件内有效，Worker 也不允许一个请求启动的编译在另一个请求里继续。
- `编译运行一致性.test.mjs`：`node:test`，共 32 项：
  - **两种环境各跑同一组 12 个场景**：全流程（事件序列与标签、终止事件恰有一个、`artifact` 的格式与摘要、产物字节与 Base64 一致、输出逐字拼接、取尽后状态 2、结束后失效与重复结束）、产物可运行（用浏览器编译器宿主隔离执行，输出“你好，多文件”）、编译失败是返回值（`finished` 与 `ok` 为假、无 `artifact`、有 `diagnostic`、读产物抛异常）、请求违规 14 类与超大请求文字与编译器名 3 类、运行之间不遗留用户文件、同一项目两次编译产物逐字节相同、指定入口与 `entry` 为 null、接近单文件限额的源码、两次运行交错读取、等待毫秒与运行号校验、运行号跨事件无效、多个事件并发各编各的。
  - **Node 进程内专属 2 项**：未授权与不存在的绑定使事件失败（宿主错误）、全部结束后无残留运行。
  - **运行器级 6 项（Node 内，直接调运行器）**：同一运行至多一个等待者且结束使等待者得状态 2、等待期满得状态 1 后仍能取到后续事件、未终止运行的并发上限 8、已结束未开始的运行不再编译、已终止运行不占并发额度且至多保留 32 个、宿主故障是 `failed` 事件。
  约 21 秒。

## 复跑

1. 建私有暂存（符号链接语言仓的只读材料，复制编译器与工具，独立编译缓存）：主代理草稿区的 `建暂存.sh <暂存目录>`（若接口目录根下的公共 `.md` 变过而宿主提供清单未重生成，需先在暂存副本里重生成相关清单）。
2. 在暂存目录构建试验应用，输出名 `编译运行一致性`：`建应用.sh <暂存目录> 云工 <本目录>/应用 编译运行一致性`。
3. 在暂存目录里运行：`node --test --test-force-exit <本目录>/编译运行一致性.test.mjs`（Node 26 以上，需要 JSPI）。所需资源默认取相邻云仓 `../yuyan-cloud`：`工具/云端编译服务/` 的 `资源/编译器.wasm`、`资源/值桥接.wasm`、`资源/标准库.json.gz`、`组装器.mjs`（及其 `资源/组装器.wasm`），`应用/豫言体验/node_modules/binaryen`（Node 进程内用），`工具/包管理服务/node_modules/miniflare`（workerd 用）。环境变量 `YY_DIST_ROOT`（产物根，默认 `./dist`）、`YY_CLOUD_ROOT`、`YY_BINARYEN`、`E2E_MINIFLARE` 可改路径；缺任何一项测试立即报错并指出。
4. workerd 部分自己装配一个与云仓 `编译外壳.mjs` 同构的外壳（产物、运行器、编译资源放进临时目录树），标准库资料经服务绑定替身供给。

## 实测得到的平台事实

- Worker 运行时不允许一个请求启动的异步工作（定时器）在别的请求里继续：这就是“运行号只在启动它的事件内有效”的由来，也是本验证把每个场景放进同一个事件的原因。
- 同一编译（同一项目、同一编译器与标准库）在 Node 与本地 workerd 里产物逐字节相同（确定性）。
- 编译器 Wasm 同步运行，会独占 isolate；宿主不让出事件循环，故事件要等编译结束才能送出（旧云桥的“流式”同样如此）。
