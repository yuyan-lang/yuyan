# 日志云工适配

把三个函数映射到全局 `console` 的 `error`、`warn`、`info`。适配先在豫言里按 UTF-8 字节数核对上限，未超过 8192 字节的文字原样交给 `console`；超过时先减去标记 `…（已截断）` 的字节数得到余量，再在字节串里向前退到 UTF-8 字符边界（不会切断一个码点），用标准库的「截取字节串」在豫言里取出前缀（成本只与所取的长度有关，与输入大小无关，几十 MiB 的巨串也不会拆成字符列表而耗尽内存），交给全局 `TextDecoder`（`ignoreBOM: true`）还原成字符串后附上标记。日志文字不经 JSON，控制字符和换行原样到达平台，文首的 U+FEFF 也保留。适配不保存日志，不脱敏，也不区分请求；敏感信息不得写入日志是应用的责任。

适配经薄宿主的通用原语（`库/云工宿主` 的「物宿主」与「物」）调用全局 `console` 与 `TextDecoder`，云工宿主与诺节应用宿主用同一份物桥实现这些原语。在诺节上 `console.error`、`console.warn` 写标准错误，`console.info` 写标准输出，文字前不加级别。

真实本地 workerd 实测：三个级别在 workerd 日志里分别显示为 `[ERROR]`、`[WARNING]` 与普通日志行；超长文字被截断并以 `…（已截断）` 结尾，单条不超过 8192 字节。综合场景见 `../消息队列/一致性验证/真实工作者/`。

`一致性验证/` 里有试验应用、真实 Wasm 的 Node 测试和复跑说明。
