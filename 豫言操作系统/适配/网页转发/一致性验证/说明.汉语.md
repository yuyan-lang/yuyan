# 网页转发一致性验证（0.4.0）

本目录用真实的 Wasm 与 Node 宿主验证 `豫言操作系统网页转发` 0.4.0 的云工适配：

- `应用/网页转发一致性应用/`：试验应用。包描述存为 `网页转发一致性应用。包。豫.txt`，避免被 `yy豫构` 的全仓库包发现当成包解析；`yy双宿主构建 --自动` 会把它复制到构建根内的临时目录（`dist/.自动构建/<输出名>/应用`）并改回原名。
- `网页转发一致性.test.mjs`：Node 测试，加载构建产物（`程序.wasm`、`值桥.wasm`、`宿主.mjs`、`许可.json`）逐项断言。

## 复跑

在构建根里运行（语言仓根目录本身即可，需已构建 `yy双宿主构建`、`yy3_bs`、`yy豫言操作系统绑定`、`yy豫言操作系统装载包`；用法与依赖解析规则见[双宿主构建说明](../../../../工具/双宿主构建/说明.汉语.md)）。编译缓存由编译器可执行文件的修改时间决定，多个构建同时用同一编译器会共享缓存，勿并发。

1. 构建：`./yy双宿主构建 --自动 云工 <本目录>/应用/网页转发一致性应用 dist/网页转发一致性`，产物在 `dist/网页转发一致性/`。
2. 测试：`node --test <本目录>/网页转发一致性.test.mjs`。产物根默认为当前目录下的 `dist`，可用环境变量 `产物根` 改写。

## 覆盖

- `转发入站请求并筛标头`：七种方法、路径含查询、只带列出的头、固定头覆盖、`redirect: manual`、请求体与响应体流式且不缓冲、3xx 不跟随、上游状态与标头透传；
- 保留名与固定头校验（禁用名、令牌字符、重名、单个 Cookie、数量、值字符集、入站值控制字符）、路径校验、空绑定名、未授权与缺失绑定、上游失败、请求体已被读取；
- `回应入站以静态资源`：沿用与改写状态、标头覆盖与追加、`Set-Cookie` 多项、HEAD 不带正文并取消资源流、204、205、304 冲突、404 透传、路径与标头校验、授权与上游失败；旧函数回归。

每个测试都断言真实 Wasm 的可观察行为；期望值凡能由平台标准实现给出的（`URL`、`URLSearchParams`、`TextDecoder`、`Headers`）都取自同一标准实现，不手抄。
