# 邸阁对象存储适配

经邸阁协议（S3）访问远端的对象存储。一套实现可接 Cloudflare R2、AWS S3 以及其他遵循同一接口的对象存储，不绑在某一家云上。供豫言系统与原生宿主上的服务程序使用。

## 包与模块

- 包：`豫寓府库邸阁榫`，位于 `豫言操作系统/适配/对象存储邸阁/`。
- 模块：`对象`（实现），另有 `实现榫卯`、`宿主提供。数据。豫` 与 `说明`。
- 接口：`豫寓榫卯` 的 `豫寓府库` 0.5.0（`豫寓榫卯/对象存储/`）。
- 依赖：豫章、结绳、籍册、金匮、阴书、授时、驿址、尺素、易码、豫寓坐堂。

## 连接设置

连接设置从本机只读的数据文件读，每次请求重读，改了文件立刻生效：

```
<金匮根>/对象存储。数据。豫
```

缺省金匮根是当前目录下的 `.豫言金匮`，所以缺省路径是 `./.豫言金匮/对象存储。数据。豫`。部署时用 `「设匮根」于『/系统/九府』` 一类的话把根设到部署目录，路径即 `/系统/九府/对象存储。数据。豫`。文件权限按部署要求设成只读。

文件是数据子语言（`。数据。豫`），顶层一节 `对象存储` 是记录，五个字段：

```
「对象存储」者「存储」【
　「端点」者『https://<账号>.r2.cloudflarestorage.com』也，
　「地域」者『auto』也，
　「桶」者『<桶名>』也，
　「访问钥号」者『<访问钥号>』也，
　「密钥」者『<密钥>』也
】也。
```

- `端点` 是绝对网址（http 或 https），路径前缀可带（如 `https://example.com/s3`）。
- `地域` 是签名第四版凭证范围里的地域；R2 用 `auto`。
- `桶` 是唯一允许的桶；接口传入的 `桶名`（由 `验桶名` 构造）取得原文字后必须与它相同，否则报“桶不在连接配置内”。
- 访问钥号与密钥只在内存里用来加签，不进日志与错误消息。

文件不存在、顶层缺失、字段缺失或为空时报清楚的中文事故，例如 `对象存储配置不存在：…`、`对象存储配置缺少字段：密钥`。

## 接口语义

下列函数的签名与语义照 `豫寓府库` 0.5.0 规范：

| 函数 | 语义 |
| --- | --- |
| `取物元数据` | HEAD 对象；不存在返回 `null`；否则返回 `{size,etag,httpEtag,uploaded,httpMetadata,customMetadata}`。 |
| `读物文字` | 先 HEAD 取大小；不存在返回 `null`；超过上限返回 `{"tooLarge":true,"size":n}`；否则 GET 并按严格 UTF-8 校验，BOM 原样保留。 |
| `读物字节` | 先 HEAD 取大小；不存在得（阴，空帛）；超过上限报错；否则 GET 得（阳，帛）。 |
| `写物`、`写物文字` | PUT 对象，支持 `ifNoneMatch`、`ifMatch`、`sha256`、`contentType`、`cacheControl`、`customMetadata`。条件不成立返回 `{"written":false}`，对象不变；摘要不符在本地先核对，报错且不写。 |
| `删物` | 逐个 DELETE，至多 1000 个键；不存在的键不报错；先整批核对键，违规时不调用平台。 |
| `列举物` | 列举对象第二版（ListObjectsV2）：`prefix`、`limit`、`cursor`（续标）、`delimiter`、`include`；返回 `{objects,truncated,cursor,delimitedPrefixes}`。给了 `include` 时逐对象 HEAD 取自定义元数据。 |
| `来正文写物` | 读入站请求正文（至多 16 MiB）后按 `写物` 写入。 |
| `始分段写物` | POST `?uploads`，返回 `{"上传号":"…"}`；选项只认内容种类、缓存令与自定义元数据。 |
| `来正文写段` | 读入站请求正文后按 `写段` 上传一段。 |
| `终分段写物` | 按段号合并；选项里的 `摘要` 在收齐后 GET 回对象核对，不符时删掉对象并报错。 |
| `弃分段写物` | DELETE `?uploadId=`，丢弃已传的段。 |
| `物藏物作回书` | 先核对状态与附加标头，HEAD 判存在；HEAD 请求只回标头，其余 GET 正文后作答；不存在返回（阴，404 空回书）。 |

## 适配扩展

- `读物段`：带标签的 `桶`、`键`、`起`、`长`，用 `Range` 头读 [起, 起+长) 的字节；对象不存在或范围不合得（阴，空帛），否则得（阳，帛）。接口本身不做范围读取，这是本适配加的。
- `写段`：带标签的 `桶`、`键`、`上传号`、`段号`、`体`，直接把字节上传为一段；`来正文写段` 以入站请求正文调用它。
- 签名核心：`造规范请求`、`造待签串`、`导出签名钥`、`签名第四`、`造授权头`，以 `签料` 记录为参数；测试用它们逐字节核对 AWS 官方的四个例子。
- `读设置`、`配置位`、`须有` 等配置辅助函数公开，供部署脚本与验收测试调用。

## 签名第四版

- 算法：AWS4-HMAC-SHA256；签名钥按日期、地域、`s3`、`aws4_request` 逐层 HMAC 导出。
- 规范径：端点路径前缀 + `/` + 桶 + `/` + 逐段百分号编码的键；斜线保留，其余按 RFC 3986 转写。
- 规范查询：名与值各自百分号编码，按键排序，空值也写 `=`。
- 已签头：`host` 与全部 `x-amz-` 开头的头（含 `x-amz-date`、`x-amz-content-sha256`、`x-amz-meta-*`），名转小写、值压去多余空白。
- 请求另带 `Authorization: AWS4-HMAC-SHA256 Credential=…/…/…/s3/aws4_request,SignedHeaders=…,Signature=…`。
- 正文摘要：请求正文的沙二五六十六进；空正文用空载摘要。条件头（`If-Match`、`If-None-Match`）按需附加，不参与签名。

## 测试

- `测试/对象。测试。豫`：签名已知答案。用 AWS 官方文档公布的四个例子（取对象、写对象、取桶生命周期、列举对象），逐字节核对规范请求、待签串、签名与授权头，另核 HMAC-SHA256 的公开向量。
- `测试/语义。测试。豫`：本程序一身二用，主进程另起同程序子进程作只在本测试里用的假服务端（宾主 TCP 监听、验签名、状态存内存），跑写、元数据、读文字、读字节、按段读、条件写冲突、摘要不符、列举三页续标、分隔符、分段上传、错误摘要删对象、弃分段、删除与配置缺字段。

## 验收（接真 R2）

本会话没有测试用的 R2 凭据，真 R2 的互通留待拿到凭据后做。做法：

1. 在跑测试的机器上备一份只读配置 `<金匮根>/对象存储。数据。豫`，字段照上节；端点用 R2 的 S3 端点（`https://<账号>.r2.cloudflarestorage.com`），地域 `auto`，桶填测试桶，访问钥号与密钥填 R2 令牌的钥号与密钥。桶里可先用 `九府/测试/` 前缀，测试只读写该前缀下的键。
2. 用 `豫构 构建 豫寓府库邸阁榫 测试 互通。测试 --输出 邸阁互通测试。林檎。豫行`（林纳上换后缀）编出验收程序，在备好配置的机器上运行 `./邸阁互通测试。林檎。豫行`。
3. 全树测试里它以验收层登记，带 `--验收` 才跑：
   `./全树测试。林檎。豫行 --验收 --只 豫言操作系统/适配/对象存储邸阁/测试/互通。测试`
4. 验收程序做一轮：写 `九府/测试/互通-<时刻>`、取元数据、读文字、条件写冲突、按段读、删除；成功打印一行“邸阁对象存储互通验收通过”。配置缺失时打印清楚的错，不算通过。

## 后续版本

- `物藏物作回书` 目前把正文读进内存再作答；流式直通留待后续版本。
- `来正文写物` 与 `来正文写段` 受 16 MiB 缓冲限制；更大的入站正文应改用平台的分段上传，或由应用自己分块，留待后续版本。
- 自定义元数据的键与值按 HTTP 头规则只支持 ASCII；非 ASCII 的键值需要先编码，留待后续版本。
- 批量删除现为逐个 DELETE，未用 DeleteObjects；1000 个键会发 1000 次请求，留待后续版本。
- 不给 `x-amz-checksum-sha256` 请求头，摘要在本地核对；平台侧摘要校验留待后续版本。
- 没有重试、退避与并发上传；`物藏物作回书` 不支持范围请求；不实现预签名地址、桶管理、对象复制与移动、存储类别与加密选项。
- `httpMetadata` 只回内容种类、语言、处置、编码与缓存令；`cacheExpiry` 与自定义缓存元数据留待后续版本。
