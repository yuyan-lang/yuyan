# 邸阁对象存储适配

经邸阁协议（S3）访问远端之府库。一适可接 Cloudflare R2、AWS S3 及凡同此接口之府库，不系于一家之云。供豫言系统与本土宿主之服务程序。

## 包与模块

- 包曰 `豫寓府库邸阁榫`，在 `豫言操作系统/适配/对象存储邸阁/`。
- 模块曰 `对象`，另有 `实现榫卯`、`宿主提供。数据。豫` 与 `说明`。
- 接口为 `豫寓榫卯` 之 `豫寓府库` 0.5.0（`豫寓榫卯/对象存储/`）。
- 所依：豫章、结绳、籍册、金匮、阴书、授时、驿址、尺素、易码、豫寓坐堂。

## 连接设置

连接之设自本机只读之数据文件读，每请重读，改之即见：

```
<金匮根>/对象存储。数据。豫
```

金匮根缺省为今目下之 `.豫言金匮`，故缺省之径为 `./.豫言金匮/对象存储。数据。豫`。部署时以 `「设匮根」于『/系统/九府』` 一类之令定其根，径即 `/系统/九府/对象存储。数据。豫`。文之权限依部署设为只读。

文为数据子语言（`。数据。豫`），顶节 `对象存储` 为记，五栏：

```
「对象存储」者「存储」【
　「端点」者『https://<账号>.r2.cloudflarestorage.com』也，
　「地域」者『auto』也，
　「桶」者『<桶名>』也，
　「访问钥号」者『<访问钥号>』也，
　「密钥」者『<密钥>』也
】也。
```

- `端点` 为绝对之址（http 或 https），可带径之前缀（如 `https://example.com/s3`）。
- `地域` 为签名第四版凭证之域；R2 用 `auto`。
- `桶` 为唯一许入之桶；接口所传桶名须与之同，否则告“桶不在连接配置内”。
- 访问钥号与密钥惟在内存以加签，不入日志与误辞。

文无、顶缺、栏缺或空者，告明白之祸，如 `对象存储配置不存在：…`、`对象存储配置缺少字段：密钥`。

## 接口语义

下列诸函之签与义，依 `豫寓府库` 0.5.0 之规：

| 函 | 义 |
| --- | --- |
| `取物元数据` | HEAD 其物；无则还 `null`；有则还 `{size,etag,httpEtag,uploaded,httpMetadata,customMetadata}`。 |
| `读物文字` | 先 HEAD 取大小；无则还 `null`；逾限则还 `{"tooLarge":true,"size":n}`；否则 GET 而严校 UTF-8，BOM 原存。 |
| `读物字节` | 先 HEAD 取大小；无则得（阴，空帛）；逾限则告祸；否则 GET 得（阳，帛）。 |
| `写物`、`写物文字` | PUT 其物，受 `ifNoneMatch`、`ifMatch`、`sha256`、`contentType`、`cacheControl`、`customMetadata`。条件不立则还 `{"written":false}`，物如故；摘要先于本机校之，不合则告祸而不书。 |
| `删物` | 逐键 DELETE，至多千键；无者不为过；先核全批之键，违规则不召平台。 |
| `列举物` | 列举对象第二版（ListObjectsV2）：`prefix`、`limit`、`cursor`、`delimiter`、`include`；还 `{objects,truncated,cursor,delimitedPrefixes}`。与 `include` 者逐物 HEAD 取自定之元。 |
| `来正文写物` | 读入站之体（至多十六兆），依 `写物` 书之。 |
| `始分段写物` | POST `?uploads`，还 `{"上传号":"…"}`；选项惟受内容种、缓存令与自定之元。 |
| `来正文写段` | 读入站之体，依 `写段` 传一段。 |
| `终分段写物` | 按段号合之；选项之 `摘要` 于收齐后 GET 回而校之，不合则删物告祸。 |
| `弃分段写物` | DELETE `?uploadId=`，弃已传之段。 |
| `物藏物作回书` | 先核状与附头，HEAD 判其有无；HEAD 之请惟还头，余法 GET 其体而后答；无则还（阴，四零四空回书）。 |

## 适配之扩

- `读物段`：受带签之 `桶`、`键`、`起`、`长`，以 `Range` 头读 [起, 起+长) 之字节；物无或范围不合得（阴，空帛），否则得（阳，帛）。接口本无范围之读，此为本适所加。
- `写段`：受带签之 `桶`、`键`、`上传号`、`段号`、`体`，径以其体传为一段；`来正文写段` 以入站之体调之。
- 签名之核：`造规范请求`、`造待签串`、`导出签名钥`、`签名第四`、`造授权头`，皆以 `签料` 为参；试者用之以逐字节校 AWS 官样四例。
- `读设置`、`配置位`、`须有` 等配置之助公开，供部署之令与验收之试调用。

## 签名第四版

- 法：AWS4-HMAC-SHA256；签名之钥依日、地域、`s3`、`aws4_request` 逐层 HMAC 而导。
- 规范之径：端点径之前缀 + `/` + 桶 + `/` + 逐段百分号编码之键；斜存，余依 RFC 3986 转写。
- 规范之问：名与值各百分号编码，依名排序，空值亦书 `=`。
- 已签之头：`host` 与凡 `x-amz-` 起首之头（含 `x-amz-date`、`x-amz-content-sha256`、`x-amz-meta-*`），名转小写、值压去多余之空。
- 请另带 `Authorization: AWS4-HMAC-SHA256 Credential=…/…/…/s3/aws4_request,SignedHeaders=…,Signature=…`。
- 体之摘要：请体之沙二五六十六进；空体用空载之摘要。条件之头（`If-Match`、`If-None-Match`）按需附之，不入签名。

## 测试

- `测试/对象。测试。豫`：签名之已知答。取 AWS 官样四例（取物、写物、问桶生命周期、列举），逐字节校规范之请、待签之串、签名与授权之头，又校 HMAC-SHA256 之公开向量。
- `测试/语义。测试。豫`：此程一身二用，主程别起同程之子为惟用于此试之假服（宾主听之、验签名、藏于内存），行写、元、读文、读体、分段之读、条件之冲突、摘要不合、列举三页之续标、分隔、分段上传、误摘要删物、弃分段、删除与配置缺栏。

## 验收（接真 R2）

此会无测试之 R2 凭据，真 R2 之互通俟得凭据而后行。其法：

1. 于行试之机备一唯读之配置 `<金匮根>/对象存储。数据。豫`，栏如上节；端点用 R2 之 S3 端点（`https://<账号>.r2.cloudflarestorage.com`），地域 `auto`，桶填测试之桶，钥号与密钥填 R2 令牌之钥号与密钥。桶中可先用 `九府/测试/` 之前缀，试者惟读写其下之键。
2. 以 `豫构 构建 豫寓府库邸阁榫 测试 互通。测试 --输出 邸阁互通测试。林檎。豫行`（林纳易其后缀）编验收之程，于备好配置之机行 `./邸阁互通测试。林檎。豫行`。
3. 全树之试以验收层登记之，带 `--验收` 乃行：
   `./全树测试。林檎。豫行 --验收 --只 豫言操作系统/适配/对象存储邸阁/测试/互通。测试`
4. 验收之程行一轮：书 `九府/测试/互通-<时刻>`、取元、读文、条件之冲突、分段之读、删除；成则书一行“邸阁对象存储互通验收通过”。配置缺者书明白之误，不为成。

## 后续版本

- `物藏物作回书` 今以体入内存而后答；流式直通俟后续。
- `来正文写物` 与 `来正文写段` 受十六兆之限；更大之入站体当用平台之分段，或由应用自分，俟后续。
- 自定元数据之键与值依 HTTP 头之规惟受 ASCII；非 ASCII 者当先编码，俟后续。
- 批量之删今为逐键 DELETE，未用 DeleteObjects；千键则千请，俟后续。
- 不与 `x-amz-checksum-sha256` 之请头，摘要于本机校之；平台之校俟后续。
- 无重试、退避与并发之传；`物藏物作回书` 不受范围之请；不具预签名之址、桶之管、物之复制与移动、存储类别与加密之选项。
- `httpMetadata` 惟还内容种、语言、处置、编码与缓存令；`cacheExpiry` 与自定之缓存元俟后续。
