# 图形处理器原生适配

`图形。豫` 于林檎原生之执行器行[图形处理器之接口](../../../豫寓榫卯/图形处理器/规范.文言.md)零点一点零之计算部：设备、缓冲、MSL 着色模块、计算管线、计算绑定组与计算派发，皆经[金属库](../../../库/金/包说明.文言.md)（Objective-C 运行时与 Metal 框架，悉书于豫言）而成，无他人之库。`实现接口。豫` 定公包之身份与版，`宿主提供.json` 为接口之清单（同节点、浏览器之适配）。

## 行

- **设备**：`取得图形设备` 取默认之金属器而建一命令之队；无金属（非林檎、宿主不能调系统库、无默认之器）则返资源暂不可用。`读取设备着色目标` 恒为金属目标，`编译着色模块` 之源文为 MSL（豫言编译器之「金属源」）。
- **缓冲**：金属共享之存，CPU 与 GPU 共一存。`写入图形缓冲` 与 `读回图形缓冲` 径读写缓冲所容之址，一次不逾十六兆；`销毁图形缓冲` 释缓冲。字数须为正之四倍，不逾一吉。
- **着色模块与管线**：`编译着色模块` 以 MSL 授金属编之，误以图形校验错误附金属之辞而返；`新建计算管线` 依入口之名建管线，并读其每线程组之线数（MSL 入口之 `max_total_threads_per_threadgroup`，即着色源所明之工作组大小）。
- **绑定组与派发**：`新建计算绑定组` 受缓冲之绑；`提交图形命令` 以相续之 `计算派发` 录于一命令之缓，缓冲之槽号 = 派发中绑定组列之序 × 16 + 绑定号，每组之线数取管线之工作组大小，交而同步候其毕；`复制图形缓冲` 于 CPU 一侧抄之。故 `提交图形命令` 返时命令皆毕，`等待图形完成` 无事。
- **纹理**：红绿蓝透与蓝绿红透八位纹理（含标准色空间之式）用金属共享之存，初清零，依行密书而读回。`测试/纹理。测试。豫` 于真金属之器验建纹、书与逐字读回。
- **留待后版**：余纹理之式、采样器、渲染管线与通道、纹理资源之计算绑定。
