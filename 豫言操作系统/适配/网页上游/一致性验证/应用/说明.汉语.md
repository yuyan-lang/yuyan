# 上游流一致性应用

试验应用，验证授权服务 0.5.0、网页上游 0.4.0、命名持久服务 0.5.0 的带正文请求、增量读取、取消、有限整读、动态公网 HTTPS 上游与入站请求转发。只供一致性测试使用。

应用以网页服务 0.2.0 的处理入口 `处理入站网页请求` 接收请求（提案 C0001）：入站请求作参数传入，每个路由造出一个出站响应，作返回值交回宿主。

## 路由

- `POST /run`，正文为 JSON 描述。`op`：`svc`（授权服务带正文请求）、`svcold`（旧的授权服务请求，验证旧柄可读）、`up`（静态来源的网页上游）、`upjson`（旧的整体 JSON 读取）、`pub`（公网 HTTPS 上游）、`do`（命名持久服务流）、`dotext`（命名持久服务文字，返回摘要）、`multi`（`mode` 取 `many`、`interleave`、`guard`、`argcheck`）。
- 通用字段：`binding`、`object`、`url`、`method`、`headers`（二元数组列表）、`query`、`body`、`bodyPow`（2 的幂个 a）、`bodyExtra`、`timeout`、`read`（`chunks`、`limited`、`limitedtwice`、`mixed`、`sse`、`cancel`、`gated`、`none`）、`max`、`limit`、`header`。
- `/fwd`：由请求头 `x-cfg`（JSON）给出转发描述，以 `转发网页请求至命名持久服务` 把入站请求转给持久对象，对象的响应作为返回的出站响应。`/svcpass`：以 `请求授权服务` 转发入站正文，再以 `授权服务原答转为出站响应` 原样返回服务的回应。`/uppass`：以 `上游转为出站响应` 把网页上游的正文流作为返回的响应。`/dopass`：先流式请求对象，检查状态，再以 `命名持久服务原答转为出站响应` 把对象响应原样返回。
