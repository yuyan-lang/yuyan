# 云工网页上游适配

实网页上游之约〇点四（云工薄宿主）。悉以豫言书于云工薄宿主之通用原语（`库/云工宿主` 之物宿主与物）之上：请、读、解、止皆径操平台之物（`Request`、`Response`、`ReadableStream` 之读器、`TextDecoder`、`AbortSignal`、`TransformStream`、`URL`、`Headers`），宿主惟译名与值。

- 静源之请：先以宿主之物 `豫言授权取` 之 `已授权` 核其源（程序许可 `OUTBOUND_ORIGINS`），未授则败而不发；次验法、头、正文与期限，经 `豫言授权取` 发之（转址恒 `manual`，三百号视为败而消其体），`AbortSignal.timeout` 贯全程。法为 GET、HEAD、POST、PATCH、PUT、DELETE；许 GitHub 所需之 `User-Agent` 与 `X-GitHub-Api-Version`；时限至一千八百万毫秒；PATCH、PUT、POST 皆传正文。
- 动态公网 HTTPS：`豫言授权取` 之 `已授权('https://*')` 示许可有通配之源否；址逐条严验（可见 ASCII、`https://`、无用户信息与询串片段、主机名之则、端口白名），以 `URL` 规范之，经宿主之物 `豫言公网取` 发之，正文以字节发。
- 答：`网页上游响应` 包 Response、此请之断信与读态之格。读态随答而行，一实例中交错之诸请各用其答，不相涉。
- 渐读：初读乃造读器；有断信则以恒等 `TransformStream` 之 `pipeThrough(…, {signal})` 系之，期满则读败而源亦消。每读一块原字（块大则留其余为余字），授流式之 `TextDecoder`（去 BOM，坏序为 U+FFFD，跨块相衔），复依码点之界裁出不逾最大字节之文，余文留为待出之文。有限整读先观 `Content-Length`，乃循环累计，逾限即止。
- `上游转为出站响应`：以上游正文之流与所许之答头造二百之 Response，以网页服务适配之 `物出站响应` 包为出站网页之答，由处理入口返之。

一致之验见 `一致性验证/`。
