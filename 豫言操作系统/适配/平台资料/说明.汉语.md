# 平台资料云工适配

把公共[平台资料接口](../../../豫言操作系统接口/平台资料/规范.汉语.md)映射到云工宿主。适配本身很薄：参数检查（集名 1 至 64 字节且无控制字符、前缀至多 512 字节、键 1 至 512 字节，违规抛「平台资料参数无效」）和结果整形，真正的取资料、解压、筛键、排序与缓存在宿主 JS `豫言操作系统/宿主/云工/平台资料.mjs`。

适配经薄宿主的通用原语（`库/云工宿主` 的「物宿主」与「物」）使用宿主对象 `豫言平台资料`：调它的 `取()` 得到资料器（`创建平台资料` 的结果），再调资料器的 `列键(环境, 许可, 集名, 前缀)` 与 `读文字(环境, 许可, 集名, 键)`。

- **资料器只取一次**：资料器按器缓存解压后的资料，而每次 `取()` 都造一个新器，所以适配把资料器存进实例的格里，同一实例里交错的请求共用它（它只是跨请求共享的缓存）。
- **环境与许可由适配给出**：资料器只看参数，不看平台的 env。适配按资料集取它依赖的服务绑定（`标准库` 对 `BROWSER_COMPILER`，同宿主的 `默认资料集`），经「云工绑定」于 `SERVICE` 核对：授权且存在时环境含该绑定、许可列它；已授权而缺失时许可列它而环境没有，资料器报「标准库资料不可用」；未授权时许可不列它，资料器报「未授权的平台资料集：标准库」；未知集名交给资料器报「未知的平台资料集：<集名>」。
- **失败**：资料器的失败（未知集、未授权、资料不可用、参数无效）都转成以其消息为文的可捕获豫言异常；资料不可用后下一次调用会重新取。
- **为什么放宿主**：云工作台的资料集 `标准库` 是约 2.7 MB 的 gzip（解压后约 57 MB 的 JSON，共 1879 个条目，其中只有 51 个是豫言标准库源码）。豫言的 JSON 解析器不能吞下 57 MB，也不该每个事件解一次；宿主用 `DecompressionStream` 解压、解析，只保留键以 `/库/标准库/` 起首的字符串条目，应用每次只拿到需要的键列表或某个键的文字。
- **授权**：`标准库` 映射到许可授权的服务绑定 `BROWSER_COMPILER`（`许可.json` 的 `SERVICE` 里要有它），网址固定为 `https://playground.yuyan-lang.org/编译/资源/标准库.json.gz`，应用不能自选来源。

验证见 `一致性验证/`。
