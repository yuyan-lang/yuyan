# 图形显示浏览器适配

`呈现。豫` 于浏览器宿主行[图形显示接口](../../../豫言操作系统接口/图形显示/规范.文言.md) 零点一点零：以 WebGPU 所渲之画呈于[显示浏览器适配](../显示浏览器/说明.文言.md)所授之 canvas。`实现接口。豫` 定公约之身份与版。[图形显示节点适配](../图形显示节点/说明.文言.md)之 `呈现。豫` 与此逐句相同（惟私构之名异），改则两处同改。

**桥接何以通**：图形显示之接口包依显示与图形处理器二包；双宿主构建所生之包境中，绑定之 `豫言操作系统图形显示` 依绑定之 `豫言操作系统显示` 与 `豫言操作系统图形处理器`，而二绑定包之模即 `../显示浏览器/画面。豫` 与 `../图形处理器浏览器/图形。豫` 之副本。故此适配径 `寻观「豫言操作系统显示」之「画面」之书`、`寻观「豫言操作系统图形处理器」之「图形」之书`，即得用其私构（`浏览器显示面`、`浏览器图形设备`、`浏览器图形纹理`）与宿主之调；今之绑定之具与接口检查器（惟比签名）无须改。其价：此包离绑定之境而独验其类，则不见诸私名，惟随应用之构而验。

- `读取显示面纹理格式` 返 `navigator.gpu.getPreferredCanvasFormat()` 所应之格式（Chrome 于 macOS 为 `蓝绿红透八位`）。
- `取得显示面纹理` 初对一 canvas 则取其 `webgpu` 上下文，以此设备与首选之式 `configure` 之，面自此绑于此设备（易设备返 `输入无效`）；已用于 `提交像素画面` 之面返 `资源暂不可用`，反之亦然。所返之纹理乃宿主所持之离屏帧纹理（首选之式，渲染目标、采样、复制源与的之用），尺同面此刻之物理素数；呈现之前再取，得同一纹理。
- `呈现显示面` 复帧纹理于 canvas 之 `getCurrentTexture()` 而交之，废此帧纹理之号，候下一 `requestAnimationFrame` 之回调（又让事环一次）乃返 `画面已提交`；此帧未取纹理则返 `输入无效`。

**何以用离屏之帧纹理**：canvas 之当前纹理，浏览器每刷其画则过期；而应用于取纹理与呈现之间，因 JSPI 之挂起屡让事环（如每交命令须候误域），径交 canvas 之纹理则中帧而失效。离屏之纹理惟呈现时一复，多一整帧之复而已。

**宿主原语**：与图形处理器共用 `豫言_浏览器_图形`，操作为 `呈现.格式`、`呈现.取纹理`、`呈现.呈现`（`宿主/浏览器/图形.mjs`）。标签页在后，浏览器不行 `requestAnimationFrame`，`呈现显示面` 候至复前。

**验收**：`一致性验证/`：图形探针应用一次验显示、图形处理器、图形显示三接口，其说与真 Chrome 之行法见其中 `说明.文言.md`，验收之单见 `真实浏览器验收清单.文言.md`。
