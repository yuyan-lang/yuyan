# 图形显示浏览器适配

`呈现。豫` 在浏览器宿主上实现[图形显示接口](../../../豫言操作系统接口/图形显示/规范.汉语.md) 0.1.0：把 WebGPU 渲染的画面呈现到[显示浏览器适配](../显示浏览器/说明.汉语.md)授予的 canvas。`实现接口。豫` 固定公共包身份与版本。

**桥接怎样做通**：图形显示接口包依赖显示与图形处理器两个接口包，双宿主构建生成的包上下文里，绑定后的 `豫言操作系统图形显示` 依赖绑定后的 `豫言操作系统显示` 与 `豫言操作系统图形处理器`，而这两个绑定包的模块就是 `../显示浏览器/画面。豫` 与 `../图形处理器浏览器/图形。豫` 的副本。所以本适配直接 `寻观「豫言操作系统显示」之「画面」之书`、`寻观「豫言操作系统图形处理器」之「图形」之书`，就能用它们的私有构造器（`浏览器显示面`、`浏览器图形设备`、`浏览器图形纹理`）与宿主调用函数；现有绑定工具与接口检查器（只比对签名）无须改动。代价是本包脱离绑定环境单独类型检查会找不到这些私有名字，只能随应用构建检查。

- `读取显示面纹理格式` 返回 `navigator.gpu.getPreferredCanvasFormat()` 对应的格式（Chrome 在 macOS 上为 `蓝绿红透八位`）。
- `取得显示面纹理` 第一次对某个 canvas 调用时取 `webgpu` 上下文并以该设备与首选格式 `configure`，显示面从此绑定该设备（换设备返回 `输入无效`）；已用于 `提交像素画面` 的显示面返回 `资源暂不可用`，反之亦然。返回的纹理是宿主持有的离屏帧纹理（首选格式，渲染目标、采样、复制源与目标用途），尺寸等于显示面此刻的物理像素尺寸；呈现之前重复取得返回同一个纹理。
- `呈现显示面` 把帧纹理复制到 canvas 的 `getCurrentTexture()` 并提交，作废本帧纹理的句柄，再等下一次 `requestAnimationFrame` 回调之后（再让出一次事件循环）返回 `画面已提交`；本帧没有取得纹理时返回 `输入无效`。

**为什么用离屏帧纹理**：canvas 的当前纹理在浏览器每次刷新画面时过期，而应用在取纹理与呈现之间会因 JSPI 挂起多次让出事件循环（例如每次提交命令都要等错误域），直接交出 canvas 纹理会在帧中途失效。离屏纹理只在呈现时复制一次，多一次整帧复制。

**宿主原语**：与图形处理器共用 `豫言_浏览器_图形`，操作为 `呈现.格式`、`呈现.取纹理`、`呈现.呈现`（`宿主/浏览器/图形.mjs`）。标签页在后台时浏览器不调度 `requestAnimationFrame`，`呈现显示面` 会一直等到回到前台。

**验收**：`一致性验证/`：图形探针应用一次验证显示、图形处理器与图形显示三个接口，说明与真实 Chrome 运行步骤见其中的 `说明.汉语.md`，验收清单见 `真实浏览器验收清单.汉语.md`。
