# 定时事件云工适配

云工宿主以〔0, 控制器, 上下文〕调用入口 `处理定时事件`：`定时事件` 的构造器 `云工定时事件` 包着 `scheduled` 事件的控制器（ScheduledController）与上下文（ExecutionContext），都是资源「云工物」。`读取定时事件文` 读控制器的 `cron` 与 `scheduledTime`：`cron` 须是字符串；`scheduledTime` 须是非负的安全整数（其余如负数、小数、NaN、超出安全整数的数、字符串、undefined 都是无效时刻）；合格后造出 `{cron, scheduledTime}` 对象，由平台 `JSON.stringify` 写出，整数时刻不经过豫言的浮点。适配只用云工薄宿主的通用原语，不暴露控制器，也不调用 `noRetry`，不保存任何状态，没有顶层可变格。

事件寿命由云工宿主保证：`scheduled` 处理器返回的 Promise 在入口返回时才完成，所以应用的异步写入都在这一次调用之内；入口抛出未捕获异常时该 Promise 被拒绝，平台记为失败。

真实本地 workerd 实测：经 `/cdn-cgi/handler/scheduled?cron=…&time=毫秒` 触发，`cron` 与 `scheduledTime`（毫秒整数）原样到达豫言；不带 `time` 时 `scheduledTime` 是当前毫秒；事件内的 KV 异步写入在调用结束前完成。综合场景见 `../消息队列/一致性验证/真实工作者/`。

`一致性验证/` 里有试验应用、真实 Wasm 的 Node 测试和复跑说明。
