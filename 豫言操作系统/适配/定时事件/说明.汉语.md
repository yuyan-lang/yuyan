# 定时事件云工适配

云工宿主把 `scheduled` 事件的控制器登记进本次调用的句柄表，以 `定时事件`（构造器 `云工定时事件` 包着句柄）传给入口 `处理定时事件`（提案 C0001）。`读取定时事件文` 经句柄桥读控制器的 `cron` 与 `scheduledTime`，二者都是宿主 `JSON.stringify` 写出的文字：`scheduledTime` 核对为 1 至 16 位数字、没有多余前导零后原样拼入 JSON，不经过浮点；`cron` 须是字符串字面量，原样拼入。事件寿命由云工宿主保证：`scheduled` 处理器返回的 Promise 在入口返回时才完成，并同时交给 `ctx.waitUntil`，所以应用的异步写入都在这一次调用之内；入口抛出未捕获异常时该 Promise 被拒绝，平台记为失败。适配不暴露控制器句柄，也不调用 `noRetry`，不保存任何状态。宿主对每次调用另设 30 秒的运行时限，超时同样使调用失败。

真实本地 workerd 实测：经 `/cdn-cgi/handler/scheduled?cron=…&time=毫秒` 触发，`cron` 与 `scheduledTime`（毫秒整数）原样到达豫言；不带 `time` 时 `scheduledTime` 是当前毫秒；事件内的 KV 异步写入在调用结束前完成。综合场景见 `../消息队列/一致性验证/真实工作者/`。

`一致性验证/` 里有试验应用、真实 Wasm 的 Node 测试和复跑说明。
