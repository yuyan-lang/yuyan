# 定时事件云工适配

自当前 Worker 之 `scheduled` 控制器读 `cron` 与 `scheduledTime`。云工宿主以十进文授 `scheduledTime`，适配核其为一至十六位数字而无赘零，乃原文入 JSON，不经浮点；`cron` 则以豫言 JSON 编码器转义。适配先验事种，使非定时之事而呼此术者，得可捕之豫言异，而非宿主 JS 之误。事之寿，云工宿主保之：`scheduled` 处理器所返 Promise 待豫言程序毕乃成，并授 `ctx.waitUntil`，故客之异步书写皆在此一调用之内；程序抛未捕之异，则其 Promise 被拒，平台记为败。适配不露控制器之柄，亦不行 `noRetry`。宿主于每事另设三十秒之运行时限，逾则调用亦败。

真本地 workerd 实测：经 `/cdn-cgi/handler/scheduled?cron=…&time=毫秒` 而发，`cron` 与 `scheduledTime`（毫秒整数）原样达于豫言；不带 `time` 则 `scheduledTime` 为当下之毫秒；事内 KV 之异步书写，于调用终前已成。综合之场见 `../消息队列/一致性验证/真实工作者/`。
