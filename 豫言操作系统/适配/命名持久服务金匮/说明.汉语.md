# 命名持久服务落盘适配

持久对象按名定位、在盘上各有一个目录。宿主按名找到登记的处理器，把一份请求交给它，取回一份答复，再包成接口的回书，供整读、分块读、限长读与取消。供豫言系统与原生宿主上的服务程序使用。

## 名字与目录

- 对象名 1 至 128 字节，只许 ASCII 字母、数字、`_`、`-`、`/`；不合规报 `持久对象名不合规：…`。
- 每个对象一个目录 `<金匮根>/恒务/<转写后的名字>`，由 `恒务目` 造。
- `登命名恒务 名字 处理器` 登记处理器；处理器是 `化所请为所答`：收请求记（方法、查询、请求标头、正文、网址），回答复记（状态、响应标头、正文）。同名再登记以最后一次为准。

## 派发

`恒务派发 名字 请求记` 按名找处理器，**派发前把这个对象的目录写进金匮的今仓位置**（`设今仓位`），派发后清空；对象里的 `来索恒仓` 据此造仓，于是能用持久事务、告警与独占。名字未登记报 `命名恒务未登记：…`。

## 接口各函数

- `索命名恒务文字`：七参核对后派发，返回 JSON `{"status":…,"body":…,"headers":{…}}`，headers 只含上游有的 `content-type`、`location`、`set-cookie`、`x-yuyan-revision`。
- `索命名恒务流`：同前七项加超时毫秒（1 至 900000），成功返回 `命名持久服务请求成功` 带回书，失败返回 `命名持久服务请求失败` 带原因。
- 回书的读：`读命名恒务回书抬头`（不分大小写）、`读命名恒务回书态`、`读命名恒务回书文字块`（按字节取块，跨块不裂字）、`读命名恒务回书有限文字`（超限取消）、`罢命名恒务回书`（此后读得状态三）。
- `命名恒务原答作回书`：未读过的回书原样作终答；读过或已终局报 `回书已开始读取或已作终答`。
- `转发网页索至命名恒务`：从入站请求取方法、路径与保留标头、正文，派发后把答复作回书。

正文按缓冲处理：派发时一次取回整段答复，回书的“流式读取”是在内存里按块交出（上游真流式留给将来的 HTTP 服务端）。

## 用法

```yuyan
寻观「豫寓名恒金匮榫」之「请求」之书。

「登命名恒务」于「名」曰『站点甲』于「护」曰「我的处理器」。
「索命名恒务文字」于『站点』于『站点甲』于『https://internal/首页』于『GET』于（「罄」以（「文」合「文」））于（「罄」以（「文」合「文」））于『』。
```
