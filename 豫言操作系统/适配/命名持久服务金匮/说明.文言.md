# 命名持久服务落盘适配

持久之户按名而寻，盘上各有一目。宿主依名得其登之处理器，授一请，取一答，乃包为回书，以供整读、分块、限读与罢。供豫言系统与本土之宿主用。

## 名与目

- 名一至百二十八字节，惟 ASCII 字母、数、`_`、`-`、`/`；不合者告 `持久对象名不合规：…`。
- 一物一目 `<金匮根>/恒务/<转写之名>`，由 `恒务目` 造。
- `登命名恒务 名 处理器` 登处理器；处理器为 `化所请为所答`：受请记（法、问、头、文、址），还答记（态、头、文）。同名再登，以末次为准。

## 派发

`恒务派发 名 请记` 按名求处理器，**派发之前书其目之径于金匮今仓位置**，派发之后清之；物中之 `来索恒仓` 据此造仓。名未登者告 `命名恒务未登记：…`。

## 接口诸术

- `索命名恒务文字`：七参核而后派，还 JSON `{"status":…,"body":…,"headers":{…}}`，headers 惟四名之上游所有。
- `索命名恒务流`：前七加期限（一至九十万），成则 `命名持久服务请求成功`，败则以其故还。
- 回书之读：`读命名恒务回书抬头`（不辨大小写）、`读命名恒务回书态`、`读命名恒务回书文字块`（依字节取块，不裂字）、`读命名恒务回书有限文字`（逾限则罢）、`罢命名恒务回书`（此后读得三）。
- `命名恒务原答作回书`：未读之书原样作终答；已读或已终者告 `回书已开始读取或已作终答`。
- `转发网页索至命名恒务`：自来书取法、径、留头与文，派发后以答为回书。

文皆先蓄：派发时一次取回整答，回书之“流读”乃于内存中按块交出（上游真流留给 HTTP 服务端）。

## 用法

```yuyan
寻观「豫寓名恒金匮榫」之「请求」之书。

「登命名恒务」于「名」曰『站点甲』于「护」曰「我的处理器」。
「索命名恒务文字」于『站点』于『站点甲』于『https://internal/首页』于『GET』于（「罄」以（「文」合「文」））于（「罄」以（「文」合「文」））于『』。
```

## 后续之事项

- 文先蓄而非真流；上游流读、事件流直通留与 HTTP 服务端。
- 留头定头之全验、先观长后读之 8 MiB 预判未具。
- 绑定之名未分目录（今只一全局之表），将来依绑定分目。
