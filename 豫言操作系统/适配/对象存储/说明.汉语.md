# 对象存储云工适配

把公共[对象存储接口](../../../豫寓榫卯/对象存储/规范.汉语.md)映射到当前 Worker 许可中的 R2 绑定（许可例：`「许可」【「种类」者『R2』也，「名们」者「列」【『PACKAGES』】也】`，桶名由应用传入），全部用豫言写在云工薄宿主的通用原语之上：`云工绑定('R2', 桶名)` 取得桶对象，`云工调候` 调用并等待 R2 的方法，`云工取` 读属性，`全局造` 造 `Headers`、`TextDecoder`、`Response`。R2 返回的对象由资源「云工物」直接持有，生命周期交给垃圾回收。

| 接口函数 | R2 调用 |
| --- | --- |
| `取物元数据` | `head(键)`，读 `size`、`etag`、`httpEtag`、`uploaded`（Date 经 `getTime`）、`httpMetadata`、`customMetadata` |
| `读物文字` | `get(键)`；`size` 超过上限则不读正文；否则 `arrayBuffer()` 后用 `new TextDecoder('utf-8', {fatal: true, ignoreBOM: true})` 严格解码 |
| `读物字节` | `get(键)`；`size` 超过上限则不读正文并抛异常；否则 `arrayBuffer()` 的结果由宿主直接复制成字节串（不经 JSON） |
| `写物`、`写物文字` | `put(键, Uint8Array, {onlyIf: Headers, sha256, httpMetadata, customMetadata})`；返回 `null` 即前置条件不满足 |
| `删物` | `delete([键…])` |
| `列举物` | `list({limit, prefix, cursor, delimiter, include})` |
| `物藏物作回书` | 按入站请求的方法选择：GET 等用 `get(键)`，把 `body` 流放进 `new Response(body, {status, headers})`；入站请求的 Request 用网页服务适配的 `来索物` 取得，响应用 `物作回书` 包成出站响应返回；HEAD 用 `head(键)` 与无体的 Response；对象不存在返回阴与 `new Response(null, {status: 404})` |
| `来正文写物`（0.4.0） | `put(键, 入站请求的 body 流, 选项)`：Request 用网页服务适配的 `来索物` 取得，`body` 原样交给 R2，字节不经豫言内存；请求须带 `Content-Length`（R2 只收长度已知的流）；选项与返回同写入对象 |
| `始分段写物`（0.5.0） | `createMultipartUpload(键, 选项)`：选项只许 `httpMetadata`（由 `contentType`、`cacheControl` 拼成）与 `customMetadata`；读返回对象的 `uploadId`，写进 `{"上传号":"…"}` |
| `来正文写段`（0.5.0） | `resumeMultipartUpload(键, 上传号).uploadPart(段号, 入站请求的 body 流)`：字节不经豫言内存；读返回的 `partNumber` 与 `etag`，写进 `{"段号":N,"标签":"…"}` |
| `终分段写物`（0.5.0） | `resumeMultipartUpload(键, 上传号).complete([{partNumber, etag}…])`；选项带 `摘要` 时 `get(键)` 取回正文流，经 `crypto.DigestStream('SHA-256')` 流式算整份摘要，不符则 `delete(键)` 后抛异常 |
| `弃分段写物`（0.5.0） | `resumeMultipartUpload(键, 上传号).abort()`，成功返回空字符串 |

要点：

- **JSON 字面由 JS 编码**：对象的键、`etag`、`httpEtag`、`customMetadata`、正文文字、列举的续标与 `delimitedPrefixes` 都由 JS 的 `JSON.stringify` 写成字面，控制字符的转义与大文字的速度都由 JS 保证；整数（大小、毫秒）与 `httpMetadata` 的五个字符串字段逐项读取。`读物文字` 的上限取 2 MiB：控制字符最坏膨胀六倍，约 12 MiB。
- **条件写用真正的 `Headers`**：本地 workerd 的探测确认，`onlyIf` 必须是 `Headers` 才生效（纯对象会被 R2 静默忽略、照样覆盖），所以适配用 `全局造('Headers')` 造 `If-None-Match: *` 或 `If-Match: "etag"`，设到 `put` 选项对象的 `onlyIf` 上；其余选项拼成 JSON 后经 `JSON.parse` 成普通对象。
- **`list` 的结果是纯对象，`objects` 的元素是 `R2Object` 类实例**；未截断时 `cursor` 键存在而值为 `undefined`，适配只在 `truncated` 为真时取续标。含 `include` 时本地 R2 每页约 100 项，应用必须按 `cursor` 续列。
- **校验在豫言里做**：桶名、键、选项 JSON（未知字段、类型、互斥、长度、保留名）、标头名与值、状态；违规抛出豫言异常。平台故障得到「云工败」，适配以它的消息原文抛出豫言异常（如 R2 的错误码文字）。
- **直通的正文留在 JS**：GET 路径只读 `size`、`httpEtag`、`body`，正文流直接交给 Response；测试对 64 MiB 对象断言 `arrayBuffer/text/bytes/json/blob` 一次也没有被调用。
- **部署错误**：桶名不在许可内或许可内的桶未绑定时，「云工系」得到失败结果，适配把它转成豫言异常（消息为 `未授权的R2绑定：桶名` 或 `绑定不存在：桶名`）。规范要求的“宿主直接中止本次运行”留待后续版本。
- **分段写物**：段正文直接交给 R2 的 `uploadPart`，不经豫言内存；收尾的 `段们` 在豫言里校验（数组、段号 1 至 10000 升序不重复、标签非空），再拼成 `{partNumber, etag}` 数组交给 `complete`。摘要核对在收齐之后：`crypto.DigestStream` 随正文流边读边算，算完与 `摘要` 比较，不符时先删对象再抛异常，不留半成品。
- **跨请求无共享状态**：适配没有顶层可变格，同一实例里交错执行的请求互不影响。

验证：同一份测试在 Node（云工薄宿主，R2 为形状取自真实 workerd 的类实例模拟）与 `wrangler 4.129.0` 的本地 workerd（真实 R2 绑定，本地存储）里都通过。平台观察：`sha256` 不符的错误文字含 `(10037)`；键超过 1024 字节为 `(10020)`；`list` 的 `limit` 超过 1000 为 `(10022)`；本地 R2 先校验摘要再判前置条件；对可压缩类型且客户端接受 gzip 时，workerd 会改用分块传输而不保留 `Content-Length`。
