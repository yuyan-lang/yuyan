# 对象存储一致性验证

本目录验证[对象存储接口](../../../../豫言操作系统接口/对象存储/规范.汉语.md)的云工适配：试验应用在 `应用/`（为免被全仓库包发现，包描述存为 `对象存储一致性应用。包。豫.txt`，构建时改回 `对象存储一致性应用。包。豫`；`许可.json` 授权 `{"R2":["PACKAGES","SPARE"]}`），Node 测试是 `对象存储一致性.test.mjs`，R2 模拟器是 `模拟R2.mjs`。

模拟器是 R2 绑定的**类实例**（宿主桥只对非纯对象发句柄）：`head` 与 `put` 返回 `HeadResult`、`get` 返回带 `body` 流的 `GetResult`，`uploaded` 是 `Date`，`checksums` 有 `toJSON`，`list` 返回纯对象（未截断时 `cursor` 键存在而值为 `undefined`），`put` 的 `onlyIf` 只认真正的 `Headers`（纯对象被静默忽略）、先验摘要再判条件，错误文字与错误码（10037、10020、10022）取自真实 workerd 的探测；另有故障注入与调用记录，用来断言“直通不整读正文”“tooLarge 不读正文”“非法键不调用平台”。

测试覆盖：元数据；文字读取（多字节、BOM、非法 UTF-8、2 MiB 边界、控制字符最坏膨胀）；写入（条件写四种结果、sha256 相符与不符、选项校验、16 MiB 边界）；删除（1000 上限、空列表、非法键整批拒绝）；列举（前缀、分页、`delimiter`、`include`、1001 个对象）；直通（GET、HEAD、不存在、64 MiB 大对象、附加标头与状态校验）；桶隔离；许可外桶名；同一事件内 6000 次取元数据的句柄释放。

## 用私有暂存复跑

1. 建私有暂存：`建暂存.sh <暂存目录>`。
2. 构建试验应用：`cd <暂存目录> && 建应用.sh <暂存目录> 云工 <本目录>/应用 对象存储一致性`，产物在 `<暂存目录>/dist/对象存储一致性/`。
3. 跑测试（Node 装载真实 Wasm，桶为模拟器）：`env 产物目录=<暂存目录>/dist/对象存储一致性 node --test 对象存储一致性.test.mjs`。

## 在本地 workerd（真实 R2 绑定）里复跑

把 `dist/对象存储一致性/` 复制到一个空目录，去掉 `程序.wasm.wat`，补内容为 `{}` 的 `执行配置.json`，再放 `wrangler.jsonc`：`{"name":"对象存储检查","main":"入口.mjs","compatibility_date":"2026-09-04","r2_buckets":[{"binding":"PACKAGES","bucket_name":"pk"},{"binding":"SPARE","bucket_name":"spare"}]}`；`wrangler dev --local --port <端口>` 起来后：`env 远端地址=http://localhost:<端口> node --test 对象存储一致性.test.mjs`。此时桶是真实的本地 R2，依赖模拟器的用例（故障注入、调用记录、控制字符键、64 MiB 直通）自动跳过，其余在 wrangler 4.129.0 上全部通过。测试以运行号为键前缀并在用例末尾清理，可重复运行。
