# 网页服务造响应一致性验证

本目录用真实的 Wasm 与 Node 宿主验证 `豫言操作系统网页服务` 0.2.0 云工适配的造响应部分（原网页答复包的十个回应函数并入网页服务后改为“造…响应”，返回 `出站网页响应`，由处理入口交回宿主）：

- `应用/网页答复一致性应用/`：试验应用，实现网页服务的处理入口 `处理入站网页请求`（提案 C0001）。包描述存为 `网页答复一致性应用。包。豫.txt`，避免被 `yy豫构` 的全仓库包发现当成包解析；`yy双宿主构建 --自动` 会把它复制到构建根内的临时目录（`dist/.自动构建/<输出名>/应用`）并改回原名。
- `网页答复一致性.test.mjs`：Node 测试，加载构建产物（`程序.wasm`、`值桥.wasm`、`宿主.mjs`、`许可.json`）逐项断言。宿主复用同一实例处理各次请求。

## 复跑

在构建根里运行（语言仓根目录本身即可，需已构建 `yy双宿主构建`、`yy4_bs`、`yy豫言操作系统绑定`、`yy豫言操作系统装载包`；用法与依赖解析规则见[双宿主构建说明](../../../../应用/双宿主构建/说明.汉语.md)）。同一编译缓存同一时刻只跑一个构建。

1. 构建：`node 豫言操作系统/宿主/节点/宿主.cjs yy双宿主构建.wasm --自动 云工 <本目录>/应用/网页答复一致性应用 dist/网页答复一致性`，产物在 `dist/网页答复一致性/`。
2. 测试：`node --test <本目录>/网页答复一致性.test.mjs`。产物根默认为当前目录下的 `dist`，可用环境变量 `产物根` 改写。

## 覆盖

- 五个带头函数（`造带头文字响应`、`造带头结森响应`、`造带头空响应`、`造带头字节响应`、`造带头改址响应`）：保序同名头与多个 `Set-Cookie`、不隐式添加任何标头、正文原样（含全部 256 个字节值与零字节）；
- 状态 200 至 599 与 204、205、304 的正文冲突；标头名、值、数量、禁用名（不分大小写）、`Set-Cookie` 长度、内容类型的正反例，包括 CRLF 注入、非 ASCII、控制字符；
- 正文上限（8 MiB、2 MiB、16 MiB 及各加一）；改址的五个状态与二十余种目标正反例；HEAD 不特殊处理；造多个响应时只有入口返回的那个生效；`造结森响应`、`造空响应`、`造文字响应`、`造同源改址响应`、`造外址改址响应`（含自动添加 no-store 与 nosniff）。

每个测试都断言真实 Wasm 的可观察行为；期望值凡能由平台标准实现给出的（`URL`、`URLSearchParams`、`TextDecoder`、`Headers`）都取自同一标准实现，不手抄。
