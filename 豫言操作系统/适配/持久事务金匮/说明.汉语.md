# 持久事务落盘适配

把持久对象的持久仓落在本机盘上：一个对象一个目录，目录里一张键值表；开事务时抄一份草稿，成功换回、失败丢草稿。重启后数据还在。供豫言系统与原生宿主上的服务程序使用。

## 目录与卷

```
<金匮根>/<对象目录>/键值。数据      持久仓的表（JSON 对象：键 → 值的 JSON 文字）
<金匮根>/<对象目录>/事务/键值。数据  事务草稿（事务结束即删）
```

`恒仓` 携带对象目录的路径，用 `开恒仓` 按目录造出；重启后拿同一个目录再开，读到的就是原来的仓。`来索恒仓` 从持久对象收到的入站请求取仓（宿主先把当前仓写进 `设今仓`），事件种类不是 `durable-fetch` 时报 `当前事件不属于持久对象`。

## 直接读写

`读恒仓键值`、`写恒仓键值`、`删恒仓键`、`列举恒仓键值`、`清恒仓` 不开事务，每次调用都读一遍卷、写一遍卷，一次调用是一次原子换卷。键按 UTF-8 计 1 至 2048 字节，值须是有效 JSON 且不超过 2 MiB，不合时报中文事故且仓不改。列举照金匮键值：`prefix`、`start`、`startAfter`、`end`、`limit`、`reverse`。

## 事务

`行恒事务` 收持久仓与参数 JSON 文字：

1. 核对参数是有效 JSON；
2. 把正稿抄进 `事务/` 草稿；
3. 调用 `登恒事务回音` 登记的回调，传入 `恒事务` 与参数文字；
4. 回调结果须是有效 JSON，成功则把草稿换回正稿并返回结果；
5. 回调抛错或结果不是有效 JSON：删草稿、报以 `持久事务失败：` 开头的中文事故，正稿不动。

回调里用 `读恒事务键值`、`写恒事务键值`、`删恒事务键`、`列举恒事务键值` 读写草稿，用 `事务恒仓` 取得落在本事务上的仓，经它直接调用上面那组函数也记在草稿里。`回滚恒事务` 删掉草稿并置事务不可用，此后本事务的读写报错。

**登记回调**：服务程序在启动时调用 `登恒事务回音` 传入自己的入口（收 `恒事务` 与参数文字、返回结果文字），测试登记一个 λ。适配不直接调用应用的接口函数，因此服务程序与它在同一进程里即可。

## 用法

```yuyan
寻观「金匮」之「路」之书。
寻观「豫寓恒事金匮榫」之「键值」之书。

「设匮根」于『/某处的数据盘/豫言』。
「仓」者「开恒仓」于「址」曰（「存目」于『对象甲』）也。
「写恒仓键值」于「仓」于『p:a』于『1』。
「读恒仓键值」于「仓」于『p:a』。
```

## 测试

`测试/键值。测试。豫` 起两个对象（仓甲、仓乙），核对直接读写、列举选项、键与值的校验、事务提交、回滚、回调失败、两仓互不干扰，重开一次（模拟重启）读回，最后清理。

## 待办事项

- 每次调用整表读写，代价与表长成正比；五亿字节级的持久对象要改成追加式日志。
- 同一对象上两个事务同时开时共用 `事务/` 目录，会互相踩；服务程序串行办理即可，将来要按事务号分目录。
- 值的嵌套层数与保留单键对象（`$句柄` 等）尚未核对。
- 事务回调的墙钟时限、告警在事务里的同命运尚待与持久告警适配一起做。
