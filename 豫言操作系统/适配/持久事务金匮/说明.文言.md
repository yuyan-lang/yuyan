# 持久事务落盘适配

持久对象之仓落于本机之盘：一物一目，目中一表；开事务则抄草，成则换回、败则弃草。重启而在。供豫言系统与本土之宿主用。

## 目与卷

```
<金匮根>/<对象目录>/键值。数据      仓之表（JSON 之物：键 → 值之 JSON 文）
<金匮根>/<对象目录>/事务/键值。数据  契之草（契毕即弃）
```

`恒仓` 携物目之径，以 `开恒仓` 依目录造之；重启之后以同目再开，所读即旧仓。`来索恒仓` 自持久对象所受之请取仓（宿主先以 `设今仓` 书其今仓），事件之种非 `durable-fetch` 者告 `当前事件不属于持久对象`。

## 径读写

`读恒仓键值`、`写恒仓键值`、`删恒仓键`、`列举恒仓键值`、`清恒仓` 不入事务，一用则读一卷、写一卷，一用即一原子之换。键依 UTF-8 计一至二千零四十八字节，值须为有效 JSON 而不逾 2 MiB，不合者告祸而仓不改。列举循金匮键值之选。

## 事务

`行恒事务` 受仓与参之 JSON 文：

1. 核其参为有效 JSON；
2. 抄正稿于 `事务/` 之草；
3. 呼 `登恒事务回音` 所登之回音，授 `恒事务` 与参之文；
4. 果须为有效 JSON，成则换草为正而还其果；
5. 回音抛祸或果非法：弃草，告以 `持久事务失败：` 首之中文事故，正稿不动。

回音之中以 `读恒事务键值`、`写恒事务键值`、`删恒事务键`、`列举恒事务键值` 读写草稿，以 `事务恒仓` 取落于本契之仓，经之直呼诸术亦记于草。`回滚恒事务` 弃草而置契不可用，此后读写皆告祸。

**登记回音**：服务之程启时呼 `登恒事务回音` 授其入口（受契与参之文、还果之文），试者登一 λ。适配不径呼应用之接口，故服务之程与它同处一进程即可。

## 用法

```yuyan
寻观「金匮」之「路」之书。
寻观「豫寓恒事金匮榫」之「键值」之书。

「设匮根」于『/某处的数据盘/豫言』。
「仓」者「开恒仓」于「址」曰（「存目」于『对象甲』）也。
「写恒仓键值」于「仓」于『p:a』于『1』。
「读恒仓键值」于「仓」于『p:a』。
```

## 试

`测试/键值。测试。豫` 起二物（仓甲、仓乙），核径读写、列举之选、键值之验、契成、契撤、回音之败、二仓不相犯，重开一度（拟重启）而读回，终清之。

## 后续之事项

- 每用整表读写，费与表长俱增；五亿字节之持久对象宜改为追加之记。
- 一物之上二契同开共用 `事务/` 之目，将相踩；服务之程次第办理即可，将来宜依契号分目。
- 值之叠层与所留单键之物（`$句柄` 等）尚未核。
- 契回音之墙钟时限、告警在契中同命运，尚待与持久告警之适配共为之。
