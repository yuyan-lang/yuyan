# 云工持久事务适配

`键值。豫` 借 Durable Object 之对象状态（`DurableObjectState`）与其存，以承[持久事务之约](../../../豫言操作系统接口/持久事务/规范.文言.md)四版。适配惟用云工薄宿主之通用原语（`库/云工宿主` 之 物宿主、物、回调 三模），平台之物皆以资「云工物」径执之。

- **久仓**：`持久仓` 之构造器 `云工持久仓` 裹对象之态、读写所用之仓与所在（对象、事务、独占）。网页请中，`入站请求持久仓` 以网页服务适配之 `入站请求种类` 与 `入站请求上下文` 取对象之态（事类须为 `durable-fetch`，否则抛可捕之异“当前事件不属于持久对象”），仓即其 `storage`；事务回调中，`事务持久仓` 之仓乃平台授回调之事务。持久告警、持久独占之适配以此模之 `造持久仓`、`持久仓状态`、`持久仓物`、`持久仓所在`、`持久状态仓` 取用之。
- **事务**：`执行持久事务` 先以平台 `JSON.parse` 核其参，乃登一回调（`登记云工回调`），授之 `storage.transaction`。平台呼回调，则回调经宿主之物 `豫言应用导出` 呼客之入口 `执行持久事务回调`，参为 `持久事务`（JS 数组〔0，对象之态，事务〕）与参文；入口所返之文须为有效 JSON，否则回调败而事务撤。回调之败与平台之败皆转为可捕之豫言异（辞曰 `持久事务失败：…`），回调用毕即注销。事务之内（仓取自 `事务持久仓`）不得复启事务，亦不得清仓。
- **读写**：读则呼 `get`，缺键（undefined）为阴与空文，否则返平台 `JSON.stringify` 所书之文；书则先核键（一至二千零四十八字节）与值（不逾二 MiB、为平台 `JSON.parse` 所受之 JSON、嵌套不逾三十二层、不含宿主所留之单键对象），乃以 `JSON.parse` 所得之结构值呼 `put`；删则呼 `delete`；列则依旧宿主之规核其选（空串略之、`limit` 须为正之安全整数、`reverse` 须为爻、未知之字段与 `start`/`startAfter` 并用皆败），呼 `list` 而以 `Array.from` 与 `JSON.stringify` 书为 `[[键,值],…]`，逾八 MiB 则败；清则呼 `deleteAll`。事务内之术与直读写之术同循一径，惟仓异。
- 适配不存其态，无顶层可变之格；不露 `allowConcurrency`、`noCache`、`allowUnconfirmed`，亦不供 SQL 与同步事务。

后续诸版之事：旧宿主事务回调二十五秒之墙钟时限随薄宿主而去，回调逾平台三十秒则对象被重置；重键之属，平台 `JSON.parse` 与结森所析或异者，留单键对象之察以结森所析为准。

一致性验证之例，见 `豫言操作系统/宿主/云工/一致性验证/`（含持久事务、持久告警、持久独占三接口与宿主壳之 Node 测试及试验应用）。
