# 云工持久事务适配

`键值。豫` 用 Durable Object 的对象状态（`DurableObjectState`）与它的存储实现[持久事务接口](../../../豫言操作系统接口/持久事务/规范.汉语.md) 0.4.0。适配只用云工薄宿主的通用原语（`库/云工宿主` 的 物宿主、物、回调 三个模块），平台对象都以资源「云工物」直接持有。

- **持久仓**：`持久仓` 的构造器 `云工持久仓` 包着对象状态、读写所用的仓和所在（对象、事务、独占）。网页请求里，`入站请求持久仓` 用网页服务适配的 `入站请求种类` 与 `入站请求上下文` 取对象状态（事件种类须是 `durable-fetch`，否则抛出可捕获异常“当前事件不属于持久对象”），仓是它的 `storage`；事务回调里，`事务持久仓` 的仓是平台交给回调的事务对象。持久告警与持久独占的适配用本模块的 `造持久仓`、`持久仓状态`、`持久仓物`、`持久仓所在`、`持久状态仓` 取用。
- **事务**：`执行持久事务` 先用平台 `JSON.parse` 核对参数，再登记一个回调（`登记云工回调`），把它交给 `storage.transaction`。平台调用回调时，回调经宿主对象 `豫言应用导出` 调用应用入口 `执行持久事务回调`，参数是 `持久事务`（JS 数组〔0, 对象状态, 事务〕）与参数文字；入口返回的文字须是有效 JSON，否则回调失败，事务回滚。回调失败与平台失败都转成可捕获的豫言异常（消息 `持久事务失败：…`），回调用完即注销。事务里（持久仓取自 `事务持久仓`）不能再开事务，也不能清仓。
- **读写**：读取调 `get`，缺键（undefined）为阴与空字符串，否则返回平台 `JSON.stringify` 写出的文字；写入先核对键（1–2048 字节）与值（不超过 2 MiB、是平台 `JSON.parse` 接受的 JSON、嵌套不超过 32 层、不含宿主保留的单键对象），再以 `JSON.parse` 得到的结构化值调 `put`；删除调 `delete`；列举按旧宿主的规则核对选项（空字符串略去、`limit` 须为正的安全整数、`reverse` 须为爻、未知字段与 `start`/`startAfter` 并用都失败），调 `list` 后用 `Array.from` 与 `JSON.stringify` 写出 `[[键,值],…]`，超过 8 MiB 失败；清空调 `deleteAll`。事务内的函数与直接访问的函数走同样的路径，只是仓不同。
- 适配不保存状态，没有顶层可变格；不暴露 `allowConcurrency`、`noCache`、`allowUnconfirmed`，也不提供 SQL 与同步事务。

后续版本的事项：旧宿主为事务回调设的 25 秒墙钟时限随薄宿主去掉，回调超过平台 30 秒时对象被重置；重复键之类平台 `JSON.parse` 与结森解析结果不同的值，保留单键对象的检查以结森解析为准。

一致性验证用例见 `豫言操作系统/宿主/云工/一致性验证/`（含持久事务、持久告警、持久独占三个接口与宿主壳的 Node 测试和试验应用）。
