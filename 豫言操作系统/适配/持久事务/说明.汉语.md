# 云工持久事务适配

`键值。豫` 用当前 Durable Object 的存储实现[持久事务接口](../../../豫言操作系统接口/持久事务/规范.汉语.md) 0.3.0。

- **事务**：`执行持久事务` 先在豫言里规范化参数 JSON，再经宿主 `云工持久事务执行安全` 开启 `storage.transaction`；宿主在回调里从实例池另取一个实例（外层调用的实例仍被占用），把平台事务对象登记进该次调用的句柄表，以 `持久事务`（构造器 `云工持久事务` 包着句柄）连同参数文字调用应用入口 `执行持久事务回调`，回调返回的文字（宿主核对为有效 JSON）就是结果（提案 C0001）。宿主把回调或平台的失败作为值返回，适配转成可捕获的豫言异常（消息 `持久事务失败：…`）。事务内的读、写、删除、列举经宿主原语进行，宿主按本次调用取仓，所以作用于这个事务；`回滚持久事务` 经句柄桥调用事务对象的 `rollback()`。
- **直接访问**：`读取持久仓键值` 等五个函数调用 `storage.get/put/delete/list/deleteAll`，作用于持久对象本身：宿主按本次调用取仓，在事务回调里调用时读写同样落在本事务；在持久对象之外调用时宿主报错（写入、列举经安全原语转成可捕获异常，其余中止本次调用）。
- **值的处理**：写入经宿主原生 `JSON.parse` 校验并以结构化值存储（`云工持久写入值安全`：键 1–2048 字节、值 ≤ 2 MiB、嵌套 ≤ 32 层、拒绝宿主保留的单键对象，失败作为值返回再转成可捕获异常）；读取直接返回宿主序列化的 JSON 文字，不在豫言里解析再表示（因此控制字符、增补平面字符不会被豫言 JSON 编解码器影响）；列举经 `云工持久列举值安全` 规整选项（空字符串视同未指定）并限制结果 ≤ 8 MiB。事务内与直接访问的读写走同样的路径。
- **不做**：适配不保存状态，不解释应用的键与业务规则；不暴露 `allowConcurrency`、`noCache`、`allowUnconfirmed`，也不提供 SQL 与同步事务（另见`云工宿主`）。

一致性验证用例见 `豫言操作系统/宿主/云工/一致性验证/`（含持久事务、持久告警、持久独占三个接口与宿主壳的 Node 测试和试验应用）。
