# 真实工作者综合验证

Node 测试用模拟对象验证适配的逻辑，这里在**真实本地 workerd**（`wrangler dev --local`，Wrangler 4.129.0）上综合验证消息队列、定时事件、邮件发送、文字规整、日志五个接口，用来核对模拟无法证明的平台行为。

- `应用/`：试验应用 `平台综合一致性应用`（包描述存为 `.包。豫.txt`），同时依赖五个接口。
- `真实工作者.e2e.mjs`：驱动脚本。它把构建产物复制到临时目录，写入 wrangler 配置（队列生产者与消费者、cron、`send_email`、KV），启动 `wrangler dev`，逐场景发请求并读取 workerd 日志断言，结束时按进程组清理所有子进程。共 14 个场景，约 50 秒：事件种类、文字规整样例、日志三级与截断、队列单条与批量投递、消息体大小的平台边界、消费批次形状、延迟重试与 `attempts` 递增、未捕获异常整批重投、无显式确认视为成功、定时事件（毫秒 `scheduledTime`、事件内异步写入）、非对应事件调用的可捕获异常、邮件（本地平台收到的内容逐字相同、平台拒绝的原因不含地址、注入不到达平台）。

## 复跑

1. 在私有暂存里构建试验应用，输出名 `平台综合一致性`：`建应用.sh <暂存目录> 云工 <本目录>/应用 平台综合一致性`。
2. 在暂存目录运行：`node <本目录>/真实工作者.e2e.mjs`。环境变量：`YY_DIST_ROOT`（产物根目录，默认 `./dist`）、`E2E_WRANGLER`（`wrangler.js` 路径，默认取相邻云仓 `工具/包管理服务/node_modules` 里的 wrangler）、`E2E_PATCH_HOST=1`（旧宿主的 `宿主.mjs` 缺少原语 `豫言_云工_授权绑定存在` 时在临时副本里补上，见[邮件发送适配说明](../../../邮件发送/说明.汉语.md)；现宿主已含该原语，不需设此项）、`E2E_FILTER`（只跑名称含此文字的场景）、`E2E_SAVE_LOG`（保存 wrangler 输出）、`E2E_KEEP=1`（结束后保留临时 Worker 目录）。

## 实测得到的平台事实

- 队列：`send`/`sendBatch` 以 `contentType: "json"` 投递，消费者读到的 `attempts` 从 1 递增（`max_retries: 3` 时共投递 4 次后丢弃），`timestamp` 是当前 Unix 毫秒，`body` 与投递的 JSON 值相同；`retry({delaySeconds})` 按延迟重投；无显式确认或重试而正常结束视为成功；未捕获异常使**整批**重投。本地 Miniflare 的 broker 在处理失败时对已显式确认的消息也一并重投；Cloudflare 文档承诺已确认者不重投，两者不同，消费处理须幂等。
- 定时：`cron` 与 `scheduledTime` 原样到达；`/cdn-cgi/handler/scheduled` 的 `time` 参数按毫秒使用。
- 邮件：本地 `send_email` 接受结构化的 `{from,to,subject,text}`，并强制 `allowed_sender_addresses`。
- 日志：`console.error`、`console.warn`、`console.info` 在 workerd 日志里分别显示为 `[ERROR]`、`[WARNING]` 与普通日志。
