# 真实工作者综合验证

Node 之测试以模拟之物验适配之理，此处于**真本地 workerd**（`wrangler dev --local`，Wrangler 4.129.0）综验消息队列、定时事件、邮件发送、文字规整、日志五约，以核模拟所不能证之平台之实。

- `应用/`：试应用 `平台综合一致性应用`（包描述存为 `.包。豫.txt`），兼依五约。
- `真实工作者.e2e.mjs`：驱动之脚本。复构建之产物于临时目录，写 wrangler 之配（队列之生产与消费、cron、`send_email`、KV），起 `wrangler dev`，逐场发请、读 workerd 之日志而断之，终则按进程组尽清诸子进程。凡十四场，约五十秒：事种、文字规整之例、日志之三级与截断、队列之单投与批投、消息体大小之平台边界、消费批次之形、延迟重试与 `attempts` 之增、未捕之异整批重投、无显确认而正常毕者视为成、定时之事（毫秒 `scheduledTime`、事内异步之书）、非其事而呼其术之可捕之异、邮件（本地平台所收之文逐字相同、平台拒之则因不含址、注入不达平台）。

## 复行

1. 于私有暂存建试应用，输出名 `平台综合一致性`：`建应用.sh <暂存目录> 云工 <本目录>/应用 平台综合一致性`。
2. 于暂存目录行：`node <本目录>/真实工作者.e2e.mjs`。环境变量：`YY_DIST_ROOT`（产物之根，默认 `./dist`）、`E2E_WRANGLER`（`wrangler.js` 之径，默认取相邻云仓 `工具/包管理服务/node_modules` 中之 wrangler）、`E2E_PATCH_HOST=1`（旧宿主之 `宿主.mjs` 缺原语 `豫言_云工_授权绑定存在` 时，于临时副本补之，详[邮件发送适配说明](../../../邮件发送/说明.文言.md)；今宿主已含此原语，不必设此项）、`E2E_FILTER`（惟行名含此文之场）、`E2E_SAVE_LOG`（存 wrangler 之输出）、`E2E_KEEP=1`（毕后留临时之 Worker 目录）。

## 实测所得之平台事实

- 队列：`send`、`sendBatch` 以 `contentType: "json"` 而投，消费者所读 `attempts` 自一而增（`max_retries: 3` 则共投四次而弃），`timestamp` 为当下之 Unix 毫秒，`body` 与所投之 JSON 值同；`retry({delaySeconds})` 依延迟而重投；无显确认或重试而正常毕者视为成；未捕之异使**整批**重投。本地 Miniflare 之 broker 于处败之时，连已显确之书并重投；Cloudflare 之文档许已确者不重投，二者有异，消费之处必幂等。
- 定时：`cron` 与 `scheduledTime` 原样而达；`/cdn-cgi/handler/scheduled` 之 `time` 参数以毫秒用之。
- 邮件：本地 `send_email` 受结构化之 `{from,to,subject,text}`，并强行 `allowed_sender_addresses`。
- 日志：`console.error`、`console.warn`、`console.info` 于 workerd 日志中，分显为 `[ERROR]`、`[WARNING]` 与常日志。
