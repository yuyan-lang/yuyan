# 消息队列云工适配

生产用云工 `QUEUE` 绑定之 `send` 与 `sendBatch`；消费用 `queue` 事之 `MessageBatch`：云工宿主以〔0，批次，上下文〕呼入口 `处理队列批次`，`队列批次` 之构造器 `云工队列批次` 裹 `MessageBatch` 与上下文（皆资「云工物」），`ack`、`retry({delaySeconds})` 径呼平台之书物。适配惟用云工薄宿主之通用原语。适配之要：

- **消息体由平台规范**：豫言以消息体之文授平台之 `JSON.parse`，复以 `JSON.stringify` 得规范之文；规范之文核其大小与嵌套之层，乃复经 `JSON.parse` 得授 `send` 之值（`-0` 之属规范所去之异，不及平台）。规范文中不许有以 `{"$句柄":`、`{"$未定义":`、`{"$大整数":`、`{"$数字":` 起首之对象（接口之约所留宿主之记）；`1e999` 之属化为无穷之数，先以结森析而察之，拒之。
- **批量之数组由豫言拆之**：适配惟于规范文上作一遍兼记字符串与转义之状之括号扫描，拆得每项及其 `body` 之文，逐项验其形与限，复拼为 `{"body":…,"contentType":"json","delaySeconds":…}`，皆合乃以数组之文经 `JSON.parse` 授 `sendBatch`。`body` 恒为不透明之规范文，不经豫言 JSON 库之析。
- **绑定**：以 `云工绑定`（许可之类 QUEUE）取队列；未授或未配之绑名，抛可捕之豫言异，辞为宿主之因（如 `未授权的QUEUE绑定：名`）。
- **消费之读**：读批之 `queue` 与 `messages`，乃读各书之 `id`、`attempts`、`timestamp`、`body`；`queue` 与 `id` 须为串，时戳 `Date` 以 `getTime()` 取毫秒（试验之替身亦可径授毫秒）；`body` 须为 JSON 值（null、爻、有限之数、串、数组、原型为 `Object.prototype` 之常物，逐层察之），`Date`、`Map`、二进制、`undefined`、BigInt、NaN、类之实例之属，皆使读抛豫言异。合则造 `{queue, messages:[{id, attempts, timestamp, body}…]}` 之物，由平台 `JSON.stringify` 书之。
- **越界与延迟先由适配核之**：先以 `messages` 之数核其号，使越界为可捕之豫言异；`retry({delaySeconds})` 惟延迟大于零时用之。
- 适配不用 `ackAll`、`retryAll`，亦不触书之内容类。生产之投，恒定 `contentType: "json"`。适配无顶层可变之格（惟常量之限）。
- 真本地 workerd（Wrangler 4.129.0）实测：`send`、`sendBatch` 以 `contentType: "json"` 而投，消费者所读 `attempts` 自一而增，`timestamp` 为 Date，`body` 为同一 JSON 值；`retry({delaySeconds})` 依延迟而重投；单条消息体恰一二八零零零字节可投、一二八零零一字节则拒（其误辞惟 `Unknown Internal Error (15000)`，故适配自以一二八零零零字节校之而给中文之因）；`sendBatch` 中每条亦以一二八零零零字节为限（二条各一二八零零零字节，合二五六零零零字节之批量可投）；不显确亦不重试，即视为成；未捕之异使**整批**重投，连已显确者并重投（Miniflare 之 broker 于处败之时不别已确之书），故消费之处必幂等。
- 薄宿主一隔离体一实例，数批之书可于同一实例交错而处；适配不存任何态。宿主于 `queue` 事所返之 Promise 待入口返而成，入口抛未捕之异则被拒，平台据此重试整批。

后续诸版之事：无指数之记而逾三百位之整数，`JSON.parse` 亦读为无穷，今不拦。
