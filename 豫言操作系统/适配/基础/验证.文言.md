# 基础接口首轮共验

二〇二六年九月二十四日。基础规范定诊断与单调钟二术；适配复用旧标准宿主之术，`验收。豫` 两读微秒，后不得小于前，成则返“基础接口通过”。原生、节点 V8、实 Chrome 皆得此文；云工以本地 workerd 应 HTTP 二百，正文亦同。节点与浏览器用同一豫言样例所成 WasmGC；云工之入口另加旧请求术以显其果，所验单调钟函数则共用。

检查器今能读九接口文、核声明之形、包全版与直接所依；含「者」函数体之试文已拒。旧编译器仍未能直依纯接口包。此轮所证为三端旧宿主可行基础二术，非绑定器全成。详见[汉语稿](验证.汉语.md)。

后续又核六包整文与方向之全列；基础宿主适配之版与术型相合。误版、异型、虚列及未定义型名之负例皆拒。另以客具「启动程序」之样例验应用导出与节点 WasmGC。今可生 JSON 清单，载全身份、直接所依之实版、术向与签名；型构造之全义、导入之环及载入时核身份，犹待成之。

同日复验：旧清单未改者可核，改钟名者必拒。真适配与客入口皆有「者」之体；伪适配徒列「乃」二术，检查器拒之。今成之 WasmGC 导入通桥 `yuyan:gc-host/v1.call`，导出 `_start`；公共术名乃豫言源级之约，其与 Wasm 投影之配，尚待绑定工具明记而核之。

清单今升二版，增诸公开构造及术之源级声明，模块依 UTF-8 字节定序。六包皆生可读 JSON；基础清单复核可通，临时副本独改「资源配额已尽」之名则拒。规范正文之摘要未入清单，三宿主装载之核验亦未接成。

又置共享「装载核对.mjs」。节点以既成基础 Wasm、同版二清单与启动清单试之，可通；改宿主版为 `0.2.0` 或误取值桥 Wasm，皆于入口前拒。通桥之形不能反证每一豫言术在客器内之调用。

继以独立基础构建包装，存旧宿主入口而立新默认入口。启动样例之浏览器成品在实 Chrome 显“基础接口通过”；坏宿主版则页示装载败，客未行。云工成品在本地 workerd 应 HTTP 二百、文同；坏版则入口载入即拒。节点以同一浏览器成品之 Wasm、清单和值桥，先核后造实例，亦输出同文。此默认接入唯基础包装成品所行，旧双宿主构建仍如前。

浏览器成品今附「节点入口.mjs」，径以节点行之，得“基础接口通过”；坏宿主版则于造实例前拒。构建包装又拒所验启动实现与所编源码异径、及客包未直依基础适配二负例。

清单三版又录递归所析诸包之全身份。六包皆成；启动闭包载启动、标准库、基础。使基础反依启动之临时样本，判环而拒。节点、实 Chrome、本地 workerd 复验三版成品皆通；宿主清单之传递版若误，节点造客前拒。

四版再录包文、方向、接口源、包规范及根公共文之 SHA-256 摘要。基础有十七逻辑文摘要，诊断文之值与独立 `shasum -a 256` 同。临时副本仅增诊断注释，声明不变，清单仍拒；原包核对可通。六包四版清单皆成；节点、实 Chrome 与本地 workerd 重包共验，皆得“基础接口通过”，云工应 HTTP 二百。

适配别载[投影之录](投影.文言.md)，述二公术经标准库至宿主原语之配，亦录客器通桥导入及 `_start` 导出。三端入口皆核此录；节点改钟原语名，造客前拒。节点共验样例以原语覆口计之：诊断一召、钟二召；重包之实 Chrome 与本地 workerd 仍得“基础接口通过”。此证共验所行，非任意客器逐术绑定之尽验。

术向今随文缀：「。接口。豫」为宿主所具，「。应用接口。豫」为客所具；「方向。豫」已去。六包接口与豫构检查皆通；启动包宿主零、客一，网页服务宿主六、客一。临时误改启动文缀，则客实现核对拒；同名模块兼用二缀亦拒。重包后节点、实 Chrome 皆得“基础接口通过”，本地 workerd 应 HTTP 二百、文同。
