# 消息队列落盘适配

队落于本机之盘，重启而在。供豫言系统与本土之宿主用。

## 目与卷

```
<金匮根>/队列/<队名>/待办    待投之书
<金匮根>/队列/<队名>/在办    已授一批、俟客验试之书
<金匮根>/队列/<队名>/死信    试满三而仍败之书
```

每行一条 JSON 之书：`{"体":"体之 JSON 文","延":延秒,"试":已试之次}`。队名经 `遁名` 转写而为目名。

## 发

- `致序信 队名 体 延秒`：续一条于待办之卷。
- `批量致序信 队名 批文`：批文为 `{"messages":[{"body":…,"delaySeconds":…},…]}`，逐条续之。

延秒今惟记于书中，投时不依之而序（待办之卷先进先出）。

## 取批、验、试

宿主循环：`取序批 队名 限数` 自待办取前数行移于在办，还 `序批次`（消息带在办之行号）；以 `读序批次文` 之果授应用之口 `理序批次`；客于批上呼 `验序信 批 号` 与 `重试序信 批 号 延秒` 记其处置；宿主乃呼 `结序批 批`：

- 认者：自在办之卷去之；
- 试者：退于待办，试加一，加以延；
- 试满三者：入死信之卷；
- 余者：留在在办。

`读死信 队名` 还死信之数。

## 用法

```yuyan
寻观「金匮」之「路」之书。
寻观「豫寓驿递金匮榫」之「队列」之书。

「设匮根」于『/某处的数据盘/豫言』。
「致序信」于『页面渲染』于『{"路径":"/下载/"}』于「零」。
「批」者「取序批」于「队」曰『页面渲染』于「上限」曰「十」也。
```

## 后续之事项

- 延秒未行（须合漏刻）；
- 体之 2 MiB 上限、队名合法、每队死信之上限未核；
- 一队多程同取无锁，服务之程次第取之即可。
