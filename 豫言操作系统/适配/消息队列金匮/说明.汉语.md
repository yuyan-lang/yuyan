# 消息队列落盘适配

队列落在本机盘上，重启后仍在。供豫言系统与原生宿主上的服务程序使用。

## 目录与卷

```
<金匮根>/队列/<队列名>/待办    等着投递的消息
<金匮根>/队列/<队列名>/在办    已交出一批、等应用确认或重试的消息
<金匮根>/队列/<队列名>/死信    试满三次仍失败的消息
```

每行一条 JSON 消息：`{"体":"消息体的 JSON 文字","延":延迟秒,"试":已试次数}`。队列名经 `遁名` 转写后作目录名。

## 发送

- `致序信 队列名 体 延迟秒`：把一条消息追加到待办卷。
- `批量致序信 队列名 批文字`：批文字是 `{"messages":[{"body":…,"delaySeconds":…},…]}`，逐条追加入待办卷。

延迟秒数目前只记在消息里，投递时不按它排序（待办卷按先进先出）。

## 取批、确认、重试

宿主循环：`取序批 队列名 上限` 从待办卷取最前几行移到在办卷，返回 `序批次`（消息带在办卷里的行号）；把 `读序批次文` 的结果交给应用入口 `理序批次`；应用在批上调用 `验序信 批 序号` 与 `重试序信 批 序号 延迟秒` 记录处置；宿主再调用 `结序批 批`：

- 确认的：从在办卷删掉；
- 重试的：退回待办卷，已试次数加一，加上延迟；
- 试满三次的：进死信卷；
- 其余的：留在在办卷。

`读死信 队列名` 返回死信条数。

## 用法

```yuyan
寻观「金匮」之「路」之书。
寻观「豫寓驿递金匮榫」之「队列」之书。

「设匮根」于『/某处的数据盘/豫言』。
「致序信」于『页面渲染』于『{"路径":"/下载/"}』于「零」。
「批」者「取序批」于「队」曰『页面渲染』于「上限」曰「十」也。
```

## 待办事项

- 延迟秒数尚未生效（要配合定时器）；
- 消息体的 2 MiB 上限、队列名合法性、每队列的死信上限尚未核对；
- 同一队列多进程同取时无锁，服务程序串行取即可。
