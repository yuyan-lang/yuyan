# 环境文字一致性验证（0.2.0）

本目录用真实的 Wasm 与 Node 宿主验证 `豫言操作系统环境文字` 0.2.0 的云工适配：

- `应用/环境文字一致性应用/`：试验应用。包描述存为 `环境文字一致性应用。包。豫.txt`，避免被 `yy豫构` 的全仓库包发现当成包解析；构建脚本 `建应用.sh` 会把它复制到暂存内的临时目录并改回原名。
- `环境文字一致性.test.mjs`：Node 测试，加载构建产物（`程序.wasm`、`值桥.wasm`、`宿主.mjs`、`许可.json`）逐项断言。

## 复跑（用私有暂存）

1. 建暂存（一次）：`建暂存.sh <暂存目录>`，它把语言仓的只读材料符号链接进来并复制编译器与构建工具。
2. 构建：`建应用.sh <暂存目录> 云工 <本目录>/应用/环境文字一致性应用 环境文字一致性`，产物在 `<暂存目录>/dist/环境文字一致性/`。
3. 测试：`cd <暂存目录> && node --test <本目录>/环境文字一致性.test.mjs`。产物根默认为当前目录下的 `dist`，可用环境变量 `产物根` 改写。

## 覆盖

- `读取授权环境文字`：已授权有值、已授权缺失（返回空串）、为空、假值；未授权名与非文字值仍失败；
- `授权绑定存在`：D1、SERVICE、ASSETS、R2、ENV 的有与无，空文字环境变量得阴，未授权失败，空种类或名称抛出可捕获异常。

每个测试都断言真实 Wasm 的可观察行为；期望值凡能由平台标准实现给出的（`URL`、`URLSearchParams`、`TextDecoder`、`Headers`）都取自同一标准实现，不手抄。

**需要宿主补丁**：本测试要求宿主提供原语 `豫言_云工_授权绑定存在`（缺少时测试直接报错）。补丁加在 `豫言操作系统/宿主/云工/宿主.mjs` 的 `豫言_云工_绑定句柄` 一行之后：

```js
        // 文言：察绑定之在否；未授权者仍败，已授而阙者归阴，真值与 JavaScript 同。汉语：按种类与名称检查已授权绑定是否存在；未授权是部署错误仍抛出，已授权但缺失（undefined、null、空字符串等假值）返回 false。
        豫言_云工_授权绑定存在: (种类值, 名) => {
          const 种类 = 文字(种类值), 名称 = 文字(名);
          if (!许可[种类]?.includes(名称)) throw Error('未授权的' + 种类 + '绑定：' + 名称);
          return Boolean(环境?.[名称]);
        },
```
