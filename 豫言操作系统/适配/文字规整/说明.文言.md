# 文字规整云工适配

四术皆经云工通用句柄桥以呼宿主 JS：适配以入文之 UTF-8 字节授宿主，由 `TextDecoder`（`ignoreBOM: true`，文首之 U+FEFF 不失）还为 JS 字符串，复以 `云工构造对象『String』` 得 String 对象之柄，继以 `云工调用方法` 呼 `trim`、`toLowerCase`，以 `云工读取属性` 读 `length`；`全为字母或数字吗`（二版新增）另以 `云工构造对象『RegExp』` 造 `/^[\p{L}\p{N}]+$/u` 而对 String 对象呼 `test`。果文亦不经豫言之 JSON 析：宿主所返之 JSON 字面量再授 `TextEncoder` 编为字节而取回，豫言以 `TextDecoder` 还之，故控制之字、引号、反斜线、U+2028 及 BOM 皆精确往返，亦不受今 JSON 库于 `\u` 转义之限。每呼一次，用毕即释 String 对象、解码器、编码器与字节之柄，故单事之内可屡呼而不竭柄表。入文一 MiB 之限，由适配于授宿主之前验之。

真本地 workerd 实测：`去首尾空白`、`转小写`、`UTF16长度` 之果与 Node 同（皆 V8 也）。综合之场见 `../消息队列/一致性验证/真实工作者/`。

`一致性验证/` 有试应用、真 Wasm 之 Node 测试（含全 Unicode 码点分块对拍）及复行之说明。
