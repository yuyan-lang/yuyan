# 文字规整云工适配

四个函数都经云工通用句柄桥调用宿主 JS：适配把输入字符串的 UTF-8 字节交给宿主，由 `TextDecoder`（`ignoreBOM: true`，文首的 U+FEFF 不丢）还原成 JS 字符串，再用 `云工构造对象『String』` 得 String 对象句柄，随后 `云工调用方法` 调 `trim`、`toLowerCase`，`云工读取属性` 读 `length`；`全为字母或数字吗`（0.2.0 新增）另用 `云工构造对象『RegExp』` 造 `/^[\p{L}\p{N}]+$/u` 并对 String 对象调 `test`。结果字符串同样不经豫言的 JSON 解析：宿主返回的 JSON 字面量再交给 `TextEncoder` 编成字节取回，豫言用 `TextDecoder` 还原，所以控制字符、引号、反斜线、U+2028 与 BOM 都精确往返，也不受当前 JSON 库对 `\u` 转义的限制。每次调用用完即释放 String 对象、解码器、编码器和字节句柄，单个事件内可以调用任意多次而不耗尽句柄表。输入上限 1 MiB 由适配在交给宿主之前检查。

真实本地 workerd 实测：`去首尾空白`、`转小写`、`UTF16长度` 的结果与 Node 一致（同为 V8）。综合场景见 `../消息队列/一致性验证/真实工作者/`。

`一致性验证/` 里有试验应用、真实 Wasm 的 Node 测试（含全部 Unicode 码点分块对拍）和复跑说明。
