# 网页事件流一致性验证

本目录验证[网页事件流接口](../../../../豫寓榫卯/网页事件流/规范.汉语.md)的云工适配：试验应用在 `应用/`（为免被全仓库包发现，包描述存为 `事件流一致性应用。包。豫.txt`，构建时改回 `事件流一致性应用。包。豫`），Node 测试是 `事件流一致性.test.mjs`，在真实 workerd（持久对象内 `durable-fetch`、真实 HTTP、真实 D1）里复验的是豫言测试 `云端复验/事件流云端复验。测试。豫`。试验应用实现网页服务的处理入口 `理来书`（提案 C0001，同一实例处理多个请求）；开始事件流以请求作参数，只在 HTTP 事件里调用。Node 测试覆盖：响应头与帧序、固定内容类型与默认无缓存、UTF-8；响应头先于程序结束到达；2000 个小块与 120 个 64 KiB 块；64 KiB 边界（65536 通过、65537 抛异常、多字节按字节计）；背压（读者不读则写入不越过读者）；两种客户端断开——读端取消与请求信号中止（写入正阻塞在背压上、读者仍在读两种时机）——之后写入返回 1、应用继续完成收尾并写入 D1；只轮询“已断开”也能发现空闲连接的断开；中止使读者见到错误、之后写入返回 2；结束后写入返回 2、重复结束与中止幂等；无效流柄、已结束事件的流柄、同一请求重复开始都抛可捕获的豫言异常；多流并发互不串扰；`durable-fetch` 与 `service-fetch` 事件也可用，慢读者只阻塞它自己的事件；附加标头的全部校验分支（合法边界：64 字节名、8192 字节值、32 项、制表、引号与反斜杠、覆盖 `Cache-Control`；非法：越界与 204/205 状态、九个禁用名与 `Set-Cookie`、非 token 名、CR/LF/NUL/DEL/ESC/高位字节/`豫`、8193 字节值、33 项、重复）。“收尾流”一条验证程序返回而流未结束时，适配的收尾回调随入口运行完毕结束这条流（见[适配说明](../说明.汉语.md)）。同一实例里另一个仍在进行的事件用流柄应失败，这一条记为待办（薄宿主下无从区分交错的请求）。

## 复跑

在构建根里运行（语言仓根目录本身即可，需已按当前源码构建 `豫构`（云工模式复制 `物桥.mjs`）；用法与依赖解析规则见[豫构发行说明](../../../../应用/豫构/文档/发行.汉语.md)）。试验应用还用到网页服务与关系数据库两个云工适配。编译缓存由编译器可执行文件的修改时间决定，多个构建同时用同一编译器会共享缓存（缓存原子写入，可以并发）。

1. 构建试验应用：`./豫构。林檎。豫行 发行 云工 <本目录>/应用 dist/事件流一致性`，产物在 `dist/事件流一致性/`。
2. 跑测试（Node 26 以上：真实 Wasm 需要 JSPI，`node:sqlite` 模拟 D1）：`env 产物目录=<构建根>/dist/事件流一致性 node --test --test-force-exit 事件流一致性.test.mjs`（在本目录里运行；`<构建根>` 指构建根的绝对路径）。预期 20 通过、1 待办。Workers 的全局 `scheduler.wait` 在 Node 里没有，`工具.mjs` 的 `造全局` 用 `node:timers/promises` 的 `scheduler` 垫片，经 `创建云工宿主({全局})` 传入。

## 在本地 workerd 里复跑

`云端复验/` 是用[验收驱动](../../../../库/考成/包说明.汉语.md)写的豫言测试包，见[其说明](云端复验/包说明.汉语.md)。一条命令完成：找 wrangler（环境变量 `云工命令行路径`，或仓库旁云仓的 `../yuyan-cloud/应用/包管理服务/node_modules/.bin/wrangler`；都没有就打印“跳过”并以零退出）→ 产物 `dist/事件流一致性/` 不存在时用 `双宿主构建.wasm` 构建（环境变量 `重建云工应用=1` 强制重建）→ 在新的临时工作目录里放入产物、`云端复验/rig.mjs`（转发到持久对象的包装）与 `wrangler.jsonc`（**必须**含兼容标志 `enable_request_signal`，见适配说明），按 `应用/建表.sql` 建 D1 表 → 在空闲端口起 `wrangler dev --local`（Wrangler 4.129.0）→ 逐个运行用例 → 停 wrangler（含 workerd 子进程）。在构建根运行：

```sh
./豫构。林檎。豫行 文件 豫言操作系统/适配/网页事件流/一致性验证/云端复验/事件流云端复验。测试。豫 --输出 事件流云端复验.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs 事件流云端复验.wasm
```

同一个持久对象的 D1 日志跨用例累积，用例只看各自新增的记录；每次运行都用新的 `.state`。“中止”那条放在最后：Wrangler 4.129.0 的 dev 代理可能把被中止的响应流当成致命错误而退出（本地开发工具行为，直接运行 workerd 不受影响）。有失败时以退出码 1 结束，并保留工作目录与 `wrangler.log`。CI 没有 wrangler，全树测试对 `云端复验/` 只做类型检查。

薄宿主上已在 Wrangler 4.129.0 上全部通过（9 项），含观察记录（背压缓冲量、断开的发现时机、中止在 HTTP/1.1 上的可见形态），见[适配说明](../说明.汉语.md)。云端（Cloudflare 边缘）行为留待验证。
