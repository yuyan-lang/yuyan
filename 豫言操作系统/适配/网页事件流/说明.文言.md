# 网页事件流云工适配

`流。豫` 以豫言书于云工薄宿主之通用原语（`库/云工宿主` 之物宿主、物、回调）之上，行[网页事件流公约](../../../豫言操作系统接口/网页事件流/规范.文言.md) 0.2.0：即提响应头、逐块书文（受背压）、察断、正终与异终。豫言以资「云工物」径执 TransformStream、写器、AbortController 诸 JS 之物；宿主惟供一专用之物 `豫言先交响应`（先交其答）。

## 所以行之

- **响应与背压**：以 `Headers` 聚标头，造 `TransformStream`，其可读端授 `Response` 为体，乃呼宿主之物 `豫言先交响应(请, 答)` 先交之：宿主即以此 Response 答之，入口续行。还于应用之出站答，以网页服务适配之 `物出站响应` 包同一 Response，入口终返之；宿主既交，则不复理入口之返值。可写端之写器司书：`writer.write(字节)` 待读者来取而后成，此即背压。
- **察断**：造“断开候”之承诺——`scheduler.wait(二十四时, {signal: AbortSignal.any([请求信号, 我方信号])})` 再以 `Promise.allSettled` 裹之（永不拒）。每书与每闭，皆使操作之承诺与之 `Promise.race`，**断开候居前**：请求信号一止（客断），无论书能成与否皆返一；操作被拒（响应体读端已取消）亦返一。`入站事件流已断开` 读请求信号之 `aborted` 与写器之 `desiredSize`（误则 `null`）。流终、止或收尾之时，止“我方信号”，计时随撤，不留悬挂之时。
- **收尾**：`豫言先交响应` 返入口运行毕之承诺（入口正返得 `true`，抛则得 `false`）。适配以 `登记云工回调` 系一收尾之回调于其上：入口既毕，流犹开则终之（入口抛则以误止之），撤断开之候，除其登记，柄遂失效；回调既行则自注销。故程序返而忘终之流亦终，客不久候。
- **登记簿与流柄**：登记簿为顶层可变之格，每项为（柄、写器、状态、请求信号、断开候、我方控制器、请）。薄宿主一程序惟一实例，交错之诸请共此簿，本为跨请所共之态；读写之间无挂起之点，交错之请不相覆。柄取 `crypto.randomUUID()`，诸流不同，亦不可猜。同请（以 `Object.is` 辨同一 Request）再始则抛异。状态零开、一客断、二已终或止、三断而后终或止。
- **校验**：状态、标头（令牌、值字节、禁名、重复、数）皆于提响应头之前由豫言校之，违则抛豫言之异；书之大小先于状态之辨；请以参授之，始事件流惟在 HTTP 之处理入口。止用 `writer.abort(new Error(因))`，终用 `writer.close()`。
- 内部诸辅助之名皆以 `流内` 起首，免与客或他适配同名。

待办之事：流柄四术不带请，同实例中他请方行而得其柄者亦可书之；始之之请既毕，柄乃失效。

## 部署之要

一、**兼容标志 `enable_request_signal`**：工作者配置之 `compatibility_flags` 必含之，请求之 AbortSignal 乃于客断时止（本地 workerd 已验），断后之书乃即返一。云仓之 `wrangler.jsonc` 须为用此包之应用加此一项。
二、**全局 `scheduler.wait` 与 `AbortSignal.any`**：Workers 自具；Node 宿主以 `node:timers/promises` 之 `scheduler` 垫片经 `创建云工宿主({全局})` 授之，见 `一致性验证/工具.mjs` 之 `造全局`。
三、**宿主之物 `豫言先交响应`**：云工宿主（`豫言操作系统/宿主/云工/宿主.mjs`）供之，行于网页之事。
四、**存活之时**：薄宿主不另设每事之墙钟之限，平台之 CPU 限额为之底；长联当按期书心跳，并令客凭 `Last-Event-ID` 复联。

## 本地 workerd 之实测（Wrangler 4.129.0，兼容日 2026-09-10，`enable_request_signal`，持久对象内 `durable-fetch`，真实 HTTP）

薄宿主上之复验（`事件流云端复验.test.mjs`）九项尽通：

- 响应头先于程序毕而至；帧序、UTF-8、六十四 KiB 之界、大量之块、并发之流，皆正；线上见附加标头，`Content-Type` 不可覆。
- 程序返而未终之流，收尾之回调终之，客读得正终。
- 背压宽：读者止读八百毫秒，书者已出二百五十一个万字节之帧（套接字与管道之缓冲），而后乃阻。
- 客中止 `fetch` 后应用续行：约七十八毫秒后应用记“断开收尾”，书返一，终后书返二。空闲之联，待服务端再书而后见其断，故久持之流当按期书心跳。
- `止`：HTTP/1.1 之客所读者为正终（分块之尾照发），宿主志记一未捕之异；欲使客可靠知败者，当先于流中书一帧误事件。
- 云端（Cloudflare 边缘）之行——空闲流之限时、断是否即告、异终于 HTTP/2 之所见——留待云端验证。
