# 图形处理器浏览器适配

`图形。豫` 用浏览器的 WebGPU 实现[图形处理器接口](../../../豫寓榫卯/图形处理器/规范.汉语.md) 0.4.0（含深度、剔除、分段索引绘制与 0.4.0 的纹理、实例化与多重采样）。所有 WebGPU 调用在宿主 `宿主/浏览器/图形.mjs` 的纯工厂 `创建图形能力` 里；适配把豫言的枚举与列表编成 JSON 文字（对象用宿主对象号），经唯一的宿主原语 `豫言_浏览器_图形(操作, 参数, 字节)` 交给宿主，写入数据与 WGSL 源文字走字节参数，返回（状态码, 对象号, 文字, 读回字节）。`实现接口。豫` 固定公共包身份与版本。[图形处理器节点适配](../图形处理器节点/说明.汉语.md)的 `图形。豫` 与这里大体相同（外调名与私有构造器名不同，深度、剔除与分段绘制按诺驿只修不扩的办法返回校验错误），宿主的 `创建图形能力` 也由 Node 共用，改动时两边同步。

- **设备与限额**：`取图枢` 调 `navigator.gpu.requestAdapter()`，按适配器的最大值申请缓冲、存储绑定、二维纹理边长与工作组各项限额（申请失败时退回默认限额）；浏览器不支持 WebGPU 或没有适配器时返回 `资源暂不可用`。首版在浏览器里总是许可，不返回 `未获授权`。`读器限额` 的第六项固定为 16 MiB，即值桥的单值上限。设备的 `lost` 被兑现后 `读器态` 返回 `设备已丢失` 并附原因；`释图枢` 调 `destroy()`，此后状态为 `设备已丢失 设备已释放`。
- **对象与失效**：每个对象在宿主表里有一个单调递增、不复用的号，记着所属设备。带错误分支的函数遇到已销毁或设备已释放、已丢失的对象返回 `图形系统错误 资源已失效`；`呈图形令` 返回 `命令未提交`；没有错误分支的写入与销毁遇到已销毁的对象或已释放的设备时终止本次运行，设备已丢失时静默忽略（设备丢失是异步发生的，应用无法事先避免）。
- **校验**：创建类调用都用 `pushErrorScope('validation')` 与 `pushErrorScope('out-of-memory')` 包住，校验错误返回 `图形校验错误` 附 WebGPU 的消息，内存不足返回 `资源配额已尽`；管线用 `create…PipelineAsync`，`GPUPipelineError` 也作校验错误。`译点染篇` 取 `getCompilationInfo()` 的错误逐条写成“第几行第几列：消息”。宿主先按规范核对字节数须为 4 的倍数、纹理宽高范围、`存储纹理用途` 只许三种格式等，再交给 WebGPU。
- **读回**：宿主新建 `MAP_READ | COPY_DST` 暂存缓冲，复制后 `mapAsync`，自然等到此前提交的命令完成；纹理读回按 256 字节对齐每行，读回后去掉填充成紧密排列。超过 16 MiB 返回 `图形校验错误`；暂存复制与提交也包在错误域里，复制校验不通过时同样返回 `图形校验错误`。
- **命令**：`呈图形令` 先解析列表里的全部句柄（失效即整列不执行并返回资源已失效，不属于该设备的返回校验错误），再把整列录进同一个命令编码器、一次 `queue.submit`：任一条校验不通过时 WebGPU 使整个命令缓冲无效，整列都不执行；错误经错误域返回。渲染通道的每个绘制依次设管线、绑定组（序号即组号）、顶点缓冲（序号即槽号）；`索引绘制` 用 `uint32` 索引；`三角形带` 的管线带 `stripIndexFormat: uint32`。
- **深度（0.2.0）**：`深度单精度` 译作 `depth32float`，`深度目标用途` 译作渲染附件用途（深度纹理只有这一个用途位，不带复制位）；宿主先核对深度格式与深度用途互相配套，深度纹理写入终止本次运行、读回返回 `图形校验错误`。`置深度渲染管线` 在参数里多带 `深度`（比较名照 WebGPU 的 `GPUCompareFunction`、是否写深度），宿主加上 `depthStencil: {format: 'depth32float', depthWriteEnabled, depthCompare}`；`深度渲染通道` 在通道参数里多带 `深度`（深度纹理号、清深值或空），宿主录成 `depthStencilAttachment`（`depthLoadOp` 为 `clear` 或 `load`，`depthStoreOp: 'store'`）。管线与通道是否配套由 WebGPU 校验，不配套时整列不提交。
- **剔除与分段绘制（0.3.0）**：`不剔除`、`剔背面`、`剔正面` 译作 `none`、`back`、`front`，`置剔除渲染管线` 与 `置剔除深度渲染管线` 在参数里多带 `剔除`，宿主写进 `primitive.cullMode`（正面为 WebGPU 缺省的逆时针）。`索引段绘制` 的索引字段编成对象（缓冲号、首索引、基顶点），宿主 `setIndexBuffer` 后用 `drawIndexed(索引数, 实例数, 首索引, 基顶点)`；`索引绘制` 仍按缓冲号与 `drawIndexed(索引数, 实例数)`。
- **纹理、实例化与多重采样（0.4.0）**：`红单八位` 译作 `r8unorm`。`置多级图形纹理`、`置多采样图形纹理` 在 `纹理.新建` 的参数里多带 `层数`、`采样数`，宿主写进 `mipLevelCount`、`sampleCount` 并核对规范（多级纹理另加采样与渲染附件用途，多重采样纹理只有渲染附件用途）；深度纹理可兼 `采样` 用途。`置比较图形采样器` 在 `采样器.新建` 里多带 `比较`（WebGPU 的 `compare`）。`实例布局项` 编成带 `步进: 实例` 的布局，宿主写 `stepMode: instance`。`置全述渲染管线` 在 `渲染管线.新建` 里带 `鹄们`（各项格式名与混合名）、`采样数`、`深度`、`剔除`，片元入口为空文时宿主不设片元阶段，采样数大于一时设 `multisample`。`全述渲染通道` 编成带 `色附们`（各项纹理号、清屏色或空、合入纹理号或空）的 `通道`，宿主给合入的附件设 `resolveTarget`、`storeOp: discard`。`衍多级纹理` 编成 `衍层` 命令：WebGPU 没有现成的渐远层生成，宿主按设备与格式缓存一条内置渲染管线，逐层以线性过滤采样上一层画进下一层。
- **混合**：`透明混合` 颜色 `src-alpha / one-minus-src-alpha`、透明度 `one / one-minus-src-alpha`；`相加混合` 都是 `one / one`。
- **限额检查在豫言里先做**：值桥单值超过 16 MiB 会抛出捕获不到的 JS 异常，所以写入数据、着色程序源文字与参数 JSON 先在适配里核对长度：写入超限终止本次运行，源文字与参数超限返回 `图形校验错误`。

私有构造器（`浏览器图形设备`、`浏览器图形纹理` 等）不在规范里，应用不应使用；图形显示的桥接适配靠它们取出对象号。所有函数都可能挂起（JSPI）。宿主第一次调用时才动态导入 `图形.mjs`，不用图形能力的应用不请求它。

**验收**：`一致性验证/`（纹采探针应用、真实 Chrome 运行步骤；把原生纹采九项在真 WebGPU 上重跑，读回数值与金属比对）；`../图形显示浏览器/一致性验证/`（显示、图形处理器与图形显示的图形探针、真实 Chrome 运行步骤与验收清单）；宿主单元测试在 `宿主/浏览器/图形。测试.mjs`（伪 GPU）。

**平台接口**：本适配的包装函数转调平台接口包里的无体声明，编成带类型的宿主导入（边界签名见《网页汇编接口》网五）：「网览东道」之「图形本术」的「网览图形操作」（旧外调名 `豫言_浏览器_图形`）。宿主对这些导入的实现与旧原语相同。
