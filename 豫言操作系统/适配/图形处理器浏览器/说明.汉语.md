# 图形处理器浏览器适配

`图形。豫` 用浏览器的 WebGPU 实现[图形处理器接口](../../../豫言操作系统接口/图形处理器/规范.汉语.md) 0.1.0。所有 WebGPU 调用在宿主 `宿主/浏览器/图形.mjs` 的纯工厂 `创建图形能力` 里；适配把豫言的枚举与列表编成 JSON 文字（对象用宿主对象号），经唯一的宿主原语 `豫言_浏览器_图形(操作, 参数, 字节)` 交给宿主，写入数据与 WGSL 源文字走字节参数，返回（状态码, 对象号, 文字, 读回字节）。`实现接口。豫` 固定公共包身份与版本。[图形处理器节点适配](../图形处理器节点/说明.汉语.md)的 `图形。豫` 与这里逐句相同（只有外调名与私有构造器名不同），宿主的 `创建图形能力` 也由 Node 共用，改动时两边同步。

- **设备与限额**：`取得图形设备` 调 `navigator.gpu.requestAdapter()`，按适配器的最大值申请缓冲、存储绑定、二维纹理边长与工作组各项限额（申请失败时退回默认限额）；浏览器不支持 WebGPU 或没有适配器时返回 `资源暂不可用`。首版在浏览器里总是许可，不返回 `未获授权`。`读取设备限额` 的第六项固定为 16 MiB，即值桥的单值上限。设备的 `lost` 被兑现后 `读取设备状态` 返回 `设备已丢失` 并附原因；`释放图形设备` 调 `destroy()`，此后状态为 `设备已丢失 设备已释放`。
- **对象与失效**：每个对象在宿主表里有一个单调递增、不复用的号，记着所属设备。带错误分支的函数遇到已销毁或设备已释放、已丢失的对象返回 `图形系统错误 资源已失效`；`提交图形命令` 返回 `命令未提交`；没有错误分支的写入与销毁遇到已销毁的对象或已释放的设备时终止本次运行，设备已丢失时静默忽略（设备丢失是异步发生的，应用无法事先避免）。
- **校验**：创建类调用都用 `pushErrorScope('validation')` 与 `pushErrorScope('out-of-memory')` 包住，校验错误返回 `图形校验错误` 附 WebGPU 的消息，内存不足返回 `资源配额已尽`；管线用 `create…PipelineAsync`，`GPUPipelineError` 也作校验错误。`编译着色模块` 取 `getCompilationInfo()` 的错误逐条写成“第几行第几列：消息”。宿主先按规范核对字节数须为 4 的倍数、纹理宽高范围、`存储纹理用途` 只许三种格式等，再交给 WebGPU。
- **读回**：宿主新建 `MAP_READ | COPY_DST` 暂存缓冲，复制后 `mapAsync`，自然等到此前提交的命令完成；纹理读回按 256 字节对齐每行，读回后去掉填充成紧密排列。超过 16 MiB 返回 `图形校验错误`；暂存复制与提交也包在错误域里，复制校验不通过时同样返回 `图形校验错误`。
- **命令**：`提交图形命令` 先解析列表里的全部句柄（失效即整列不执行并返回资源已失效，不属于该设备的返回校验错误），再把整列录进同一个命令编码器、一次 `queue.submit`：任一条校验不通过时 WebGPU 使整个命令缓冲无效，整列都不执行；错误经错误域返回。渲染通道的每个绘制依次设管线、绑定组（序号即组号）、顶点缓冲（序号即槽号）；`索引绘制` 用 `uint32` 索引；`三角形带` 的管线带 `stripIndexFormat: uint32`。
- **混合**：`透明混合` 颜色 `src-alpha / one-minus-src-alpha`、透明度 `one / one-minus-src-alpha`；`相加混合` 都是 `one / one`。
- **限额检查在豫言里先做**：值桥单值超过 16 MiB 会抛出捕获不到的 JS 异常，所以写入数据、着色程序源文字与参数 JSON 先在适配里核对长度：写入超限终止本次运行，源文字与参数超限返回 `图形校验错误`。

私有构造器（`浏览器图形设备`、`浏览器图形纹理` 等）不在规范里，应用不应使用；图形显示的桥接适配靠它们取出对象号。所有函数都可能挂起（JSPI）。宿主第一次调用时才动态导入 `图形.mjs`，不用图形能力的应用不请求它。

**验收**：`../图形显示浏览器/一致性验证/`（探针应用、真实 Chrome 运行步骤与验收清单）；宿主单元测试在 `宿主/浏览器/图形。测试.mjs`（伪 GPU）。

**平台接口**：本适配的包装函数转调平台接口包里的无体声明，编成带类型的宿主导入（边界签名见《网页汇编接口》网五）：「浏览器宿主」之「图形原语」的「浏览器图形操作」（旧外调名 `豫言_浏览器_图形`）。宿主对这些导入的实现与旧原语相同。
