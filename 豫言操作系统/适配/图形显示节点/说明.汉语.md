# 图形显示节点适配

`呈现。豫` 在路一 Node 宿主上实现[图形显示接口](../../../豫言操作系统接口/图形显示/规范.汉语.md) 0.1.0：把 Dawn 渲染的画面呈现到[显示节点适配](../显示节点/说明.汉语.md)授予的 SDL 窗口。`实现接口。豫` 固定公共包身份与版本。模块与[图形显示浏览器适配](../图形显示浏览器/说明.汉语.md)的 `呈现。豫` 逐句相同，只是取纹理号的私有构造器叫 `节点图形纹理`；桥接做法也相同：绑定后的 `豫言操作系统显示`、`豫言操作系统图形处理器` 就是显示节点与图形处理器节点两个适配的源码，本适配直接导入它们，用私有构造器取显示面号与设备号。宿主运行时需要 `@kmamal/sdl` 与 `@kmamal/gpu`（待办事项同两个适配，暂记在包描述的注释里）。

- `读取显示面纹理格式`：显示面已接上设备时取 SDL 窗口渲染器的 `getPreferredFormat()`，否则取 Dawn 的 `getPreferredCanvasFormat()`；macOS 上两者都是 `蓝绿红透八位`。
- `取得显示面纹理`：SDL 的窗口在创建时就定下用途，普通窗口只能 `render` 像素，WebGPU 窗口（`webgpu: true`）只能用 WebGPU 画。所以显示面第一次取纹理时，宿主在原位置开一个同名同尺寸的 WebGPU 窗口换下原来的普通窗口（原窗口的关闭不算显示面关闭），再用 `renderGPUDeviceToWindow({device, window, presentMode: 'fifo'})` 接上设备，显示面从此绑定该设备（换设备返回 `输入无效`）。返回的纹理与浏览器一样是宿主持有的离屏帧纹理（窗口首选格式，渲染目标、采样、复制源与目标用途，可以读回），尺寸等于窗口此刻的物理像素；呈现之前重复取得返回同一个纹理。已用于 `提交像素画面` 的显示面返回 `资源暂不可用`，反之亦然。
- `呈现显示面`：用一个搬运管线（盖满画面的三角形，片元按像素坐标 `textureLoad`）把帧纹理画到窗口当前纹理（`getCurrentTextureView()`）并 `swap()`，作废本帧纹理，再让出一次事件循环（让 SDL 处理窗口事件）后返回 `画面已提交`。fifo 下交换链满时取窗口当前纹理会等到下一次刷新，所以连续呈现按屏幕刷新节奏进行。窗口像素尺寸变了（移到像素比不同的屏幕）先 `resize()`，下一帧的纹理随之改变尺寸。本帧没有取得纹理时返回 `输入无效`。

**为什么用离屏帧纹理再画一次**：窗口当前纹理只有渲染目标用途，既不能作复制目标，也不能读回；渲染器的 `getCurrentTexture()` 每调用一次就少记一次设备引用，进程退出时 Dawn 断言失败（2026-09-30 本机实测 SIGTRAP），所以宿主只取 `getCurrentTextureView()`，用绘制搬运。代价是每帧多一次整帧绘制。

**后台窗口**：宿主选项 `--显示面后台` 时窗口隐藏且不激活（见显示节点适配）；隐藏窗口上呈现照常返回（本机实测十帧约 96 毫秒），自动验收用它。

**宿主原语**：与图形处理器共用 `豫言_节点_图形`，操作为 `呈现.格式`、`呈现.取纹理`、`呈现.呈现`；通用部分在 `宿主/浏览器/图形.mjs`（与浏览器共用），窗口呈现器在 `宿主/节点/图形.mjs`。

**验收**：`一致性验证/`：同一个图形探针应用在 Node 上验证显示、图形处理器与图形显示三个接口，运行步骤与记录见其中的 `说明.汉语.md`。
