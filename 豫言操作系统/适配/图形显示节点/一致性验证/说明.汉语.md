# 显示、图形处理器、图形显示：Node 一致性验证

Node 与浏览器共用同一个图形探针应用：`../../图形显示浏览器/一致性验证/应用/图形探针/`。节点模式为显示、图形处理器、图形显示分别选用 `适配/显示节点/`、`适配/图形处理器节点/`、`适配/图形显示节点/`。

**自动验收一律用后台窗口**（`--显示面后台`：隐藏、不激活，不抢前台焦点），应用参数 `跳过输入` 跳过输入一组；输入事件只做人工验收，这时才开可见窗口。宿主逻辑（授权、依赖缺失、后台窗口、SDL 事件转换、换窗、搬运呈现、清理）另有不开窗口的单元测试 `豫言操作系统/宿主/节点/图形。测试.mjs`（伪 SDL 与伪 GPU），全树测试会自动运行。

**复跑**（在语言仓根目录；需已构建 `yy双宿主构建`、`yy4_bs`、`yy豫言操作系统接口检查`、`yy豫言操作系统绑定`、`yy豫言操作系统装载包`；勿与别的构建并发）

```sh
# 1. 构建探针
node 豫言操作系统/宿主/节点/宿主.cjs yy双宿主构建.wasm --自动 节点 豫言操作系统/适配/图形显示浏览器/一致性验证/应用/图形探针 dist/节点图形探针 --包根 库/着色库
# 2. 依赖装到仓库之外的目录（下称 依赖目录）
npm install --prefix 依赖目录 @kmamal/sdl @kmamal/gpu
# 3. 自动验收：后台窗口，跳过输入；应以“探针完成：通过 37 项，失败 0 项”结束（显示接口 0.2.0 起多像素比、文字输入区域两项），退出码 0
node dist/节点图形探针/启动.mjs --授权显示面 像素画面=64x48 --授权显示面 图形画面=64x48 --显示面后台 --原生依赖目录 依赖目录 -- 跳过输入
# 4. 依赖缺失：不给依赖目录；显示与取得设备两组失败于“资源暂不可用”，标准错误各提示一次，不崩溃，退出码 0
node dist/节点图形探针/启动.mjs --授权显示面 像素画面=64x48 --授权显示面 图形画面=64x48 --显示面后台 -- 跳过输入
# 5. 人工验收输入（开可见窗口）：探针打印“等待输入：…”后，在“输入画面”窗口里点按、移动指针、按键、输入文字（可用输入法），最后关闭窗口
node dist/节点图形探针/启动.mjs --授权显示面 像素画面=64x48 --授权显示面 图形画面=64x48 --授权显示面 输入画面=320x240 --原生依赖目录 依赖目录 -- 人工输入
# 6. 宿主单元测试（不开窗口）
node --test 豫言操作系统/宿主/节点/图形。测试.mjs
```

人工验收时逐行核对打印的“输入事件：…”：点按得 `指针按下 x,y,0` 与 `指针抬起 x,y,0`（坐标以窗口左上角为原点、物理像素；右键按钮号 2）；移动得 `指针移动`；方向键、回车、退格、空格得 `按键按下 左` 等语义键名；字母键得单个字符（Shift 下为大写）；输入法提交的文字得 `文字输入 …`；关闭窗口得 `显示面已关闭`，随后一行报告“通过：人工输入…”。这次运行开的是可见窗口，顺便目视核对：“像素画面”与“图形画面”两个窗口都是纯蓝（像素提交的一帧、GPU 呈现三帧中的最后一帧）；后台窗口隐藏，自动验收看不到窗口内容，只读回离屏帧纹理。 显示接口 0.2.0 另核：Delete、Home、End、PageUp、PageDown、Tab、Esc 依次得 `按键按下 删除`、`起首`、`末尾`、`上翻页`、`下翻页`、`制表`、`退出`；Shift、Ctrl、Alt（Option）、⌘ 按下与抬起得 `上档`、`控制`、`交替`、`命令`，按着修饰键切到别的窗口时补发抬起；滚轮与触控板得 `滚轮 x,y,横,纵`（向下滚为正，一格 48 逻辑像素乘像素比）。

## 验证记录

**2026-09-30，macOS arm64（Apple 芯片，Metal），Node 26.3.0，@kmamal/sdl 0.11.13（SDL 2.32.8），@kmamal/gpu 0.2.1（Dawn）。**

| 项 | 结果 |
| --- | --- |
| 显示接口 0.2.0（同日复跑第 3 步） | 通过 37 项，失败 0 项；像素比 2.000000（Retina），设置文字输入区域照常返回（SDL 绑定做不到，待办） |
| 自动验收（第 3 步） | 通过 35 项，失败 0 项，退出码 0，约 5.4 秒；连跑三次相同。改用环境变量 `YY_NODE_NATIVE_DIR`、`YY_NODE_DISPLAY_BACKGROUND=1` 代替两个选项，结果相同 |
| 显示 | 未授权名称返回 `未获授权`；64×48 点的窗口尺寸 128×96（Retina）；字节数不符、零宽返回 `输入无效`；宽多 1 返回 `资源暂不可用`；一帧不透明蓝色像素返回 `画面已提交` |
| 图形处理器 | 限额 30150672384、30150672384、16384、65535、1024、16777216；缓冲写读、计算着色加倍、不合法 WGSL 的逐条诊断、清屏读回、三角形中心为绿角落为黑、坏命令整列不执行、销毁后使用均通过 |
| 图形显示 | 纹理格式 `蓝绿红透八位`；未取即呈现返回 `输入无效`；三帧各取两次得同一纹理、帧纹理读回 49152 字节等于 128×96×4、清屏呈现返回 `画面已提交`、旧帧命令返回 `命令未提交`；两种提交互斥 |
| 后台窗口 | 运行期间每 0.2 秒采样一次前台应用（`lsappinfo front`），始终是原来的前台应用，本进程类型为 BackgroundOnly；隐藏窗口上像素提交十次约 146 毫秒、WebGPU 呈现十帧约 96 毫秒，不会卡在等刷新，所以没有改用屏幕外窗口 |
| 依赖缺失（第 4 步） | `取得已授显示面`、`取得图形设备` 返回 `资源暂不可用`，标准错误各一行提示，退出码 0 |
| 输入事件与窗口画面 | 待人工验收（第 5 步）；SDL 事件到输入事件的转换与搬运呈现由单元测试覆盖，搬运着色程序在 Dawn 上另验过逐字节相同。@kmamal/sdl 没有注入事件的接口，无法自动合成 |

**已知问题**：@kmamal/gpu 0.2.1 每约 100 毫秒才处理一次异步回调（弹出错误域约 100 毫秒、`mapAsync` 约 200 毫秒），探针每帧（读回、提交命令、呈现）约 0.3 秒，主要耗在这里；交互渲染每帧至少等一次提交命令的错误域，约每秒十帧。
