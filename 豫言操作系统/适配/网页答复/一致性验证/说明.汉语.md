# 网页答复一致性验证（0.5.0）

本目录用真实的 Wasm 与 Node 宿主验证 `豫言操作系统网页答复` 0.5.0 的云工适配：

- `应用/网页答复一致性应用/`：试验应用。包描述存为 `网页答复一致性应用。包。豫.txt`，避免被 `yy豫构` 的全仓库包发现当成包解析；构建脚本 `建应用.sh` 会把它复制到暂存内的临时目录并改回原名。
- `网页答复一致性.test.mjs`：Node 测试，加载构建产物（`程序.wasm`、`值桥.wasm`、`宿主.mjs`、`许可.json`）逐项断言。

## 复跑（用私有暂存）

1. 建暂存（一次）：`建暂存.sh <暂存目录>`，它把语言仓的只读材料符号链接进来并复制编译器与构建工具。
2. 构建：`建应用.sh <暂存目录> 云工 <本目录>/应用/网页答复一致性应用 网页答复一致性`，产物在 `<暂存目录>/dist/网页答复一致性/`。
3. 测试：`cd <暂存目录> && node --test <本目录>/网页答复一致性.test.mjs`。产物根默认为当前目录下的 `dist`，可用环境变量 `产物根` 改写。

## 覆盖

- 五个带头函数：保序同名头与多个 `Set-Cookie`、不隐式添加任何标头、正文原样（含全部 256 个字节值与零字节）；
- 状态 200 至 599 与 204、205、304 的正文冲突；标头名、值、数量、禁用名（不分大小写）、`Set-Cookie` 长度、内容类型的正反例，包括 CRLF 注入、非 ASCII、控制字符；
- 正文上限（8 MiB、2 MiB、16 MiB 及各加一）；改址的五个状态与二十余种目标正反例；HEAD 不特殊处理；重复答复只第一个生效；旧函数回归（含旧函数仍自动添加 no-store 与 nosniff）。

每个测试都断言真实 Wasm 的可观察行为；期望值凡能由平台标准实现给出的（`URL`、`URLSearchParams`、`TextDecoder`、`Headers`）都取自同一标准实现，不手抄。
