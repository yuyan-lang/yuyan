# 张量计算接口 Node 适配

路一 Node 宿主的[张量计算接口](../../../豫言操作系统接口/张量计算/规范.汉语.md)适配。张量存储是宿主内的 `SharedArrayBuffer`，不受 Wasm 内存上限约束，宿主的工作线程可直接读写；应用只持有随机句柄号，宿主每次使用都核对种类与有效期，与文件句柄共用一张资源表。

- 后端：本适配有中央处理器（宿主以 JS 计算）、金属与统算三个后端。`取得张量上下文` 先看宿主选项 `--张量后端`（测试用，写在 `--` 之前）：指定了就只用该后端，它不可用或不合必须加速时返回 `资源暂不可用`；没指定时按加速要求自动选：必须加速取第一个可用的加速后端，偏好加速与不限加速都先找加速后端（苹果上是金属，林纳克斯上是统算），没有时用中央处理器。加速后端只在宿主给了 `--允许系统库调用` 时可用，所以没给该选项时不限加速仍用中央处理器。金属可用的条件：苹果系统、给了该选项、能取得默认金属设备；统算可用的条件：林纳克斯、给了该选项、有 libcuda.so.1 与显卡（用第零块）。功耗偏好现在不起作用。`读取后端名称` 与 `上下文已加速吗` 按上下文的后端回答。网页图算以后接入：改写可用后端探测与「节点张量取得后端上下文」，设备表见 `库/张量后端`。
- 金属：金属上下文是宿主上下文加一个张量后端（`库/张量后端`：存储缓冲缓存、管线缓存、命令合批、延后释放；各上下文共用 `库/金属张量后端` 的同一个金属设备）。张量仍存在宿主里，金属缓冲零拷贝地包着宿主存储所在的整页（小存储绑定时带页内偏移）；金属张量带视图信息（存储地址、类型、起点、形状、步长）的缓存，GPU 结果与视图的信息直接推出，其余张量第一次用到时向宿主查（经 `系统库调用` 的张量存储与视图原语）。有「张量内核」内核且类型、布局合用的算子在 GPU 上算，只记进当前命令缓冲：矩阵乘（甲单精度；乙为单精度、半精度、脑浮点、Q8_0、Q4_K 或 Q6_K；块量化的乙按「量化宜分块」在矩阵向量乘与分块矩阵乘之间选；单精度的一边行不连续时先在 GPU 上紧致化，临时张量在下次同步后交还）、逐元二元、逐元一元、逐元标量（含数乘、数加）、软最大、末维求和、末维最大、均方根归一与层归一（权、偏为浮点）、二范数归一、旋转位置编码（角表在苹果系统上经 Accelerate 以双精度一次算好整张，再舍入到单精度，按（起位，词数，旋维，基数）缓存最近一张，各层共用；原先逐元素经系统库调用求三角函数与单精位型，641 个词元的提示为此约要 450 毫秒）、注意力（键值为单精度或半精度；解码等「注意力宜分段」为真时分段再合并，暂存张量按上下文缓存、各层共用，不够大时换新）、写入行（目标单精度或半精度）、取行（表为浮点或块量化）、按轴求和、按轴最大、三十二位类型的紧致化与切片、转置、拼接、写入视图（同类型且不共用存储）、填充常数（单精度与三十二位整数；整数先照宿主的规则舍入并饱和）、随机填充（均匀、正态、伯努利，与宿主逐位相同的 Philox 序列）、因果卷积、门控递推、按专家矩阵乘（权为浮点或块量化，专家下标留在 GPU 上读）、按行累加、就地线性组合、亚当更新（1 − βᵗ 由 C 数学库以双精度求）、取前 k、按行最大下标、类型转换（转单精度，或由单精度转半精度、脑浮点）；软最大与取前 k 在长行时按「软最大宜分段」「取前k宜分段」分成两次派发，暂存张量在下次同步后交还。其余情形（不连续或类型不合的输入等）交给宿主：交给宿主前先同步（提交并等完已记的派发），宿主就地改过的张量再调「节点张量主机已改」（金属是统一内存，不做事）。读字节、读小数、取最大下标、按概率抽样也先同步；形状、类型、步长以及改形、跨步视图不读写数据，不同步。GPU 算出的结果张量（单精度或三十二位整数）连同由它改形出的视图共用一块存储，适配记着在用的句柄数：释放时还有别的句柄就只释放这个句柄，最后一个句柄放进上下文的输出池（按类型与元素数分组，至多 4096 项、8 GiB）；下一个同类型、同元素数的结果经宿主改形直接用这块存储，省去新建宿主张量、取存储地址与零拷贝包裹。跨步视图等可能不连续的视图共用存储时，这块存储不再入池。其余张量释放时若还有未提交的派发用着这块存储，把句柄的释放连同缓冲记进延后释放，下次同步后再做（之后经宿主再用照常报资源已失效），否则先放掉缓冲再释放；释放上下文前先同步并放掉全部缓冲。2026-10-01 起千问三改用融合算子（0.5.0），0.6B 解码每个词元的派发由 564 次降到 198 次（上下文超过注意力分段阈值时由 592 降到 226）；这个模型的 attn_v 是半精度而 attn_q、attn_k 是 Q8_0，起初问键值三个投影按类型分两次派发（每层 7 次）；张量后端改用归一多重的混合类型入口后合成一次，每层 6 次，每个词元降到 170 次（长上下文 198）。待办事项：之前每个词元约五百六十次派发时，宿主侧（适配与后端的豫言代码、宿主张量原语）的逐次开销仍大于 GPU 计算本身：2026-09-30 本机安静时每个词元宿主线程时间约 10 毫秒、GPU 约 6 毫秒；每个算子宿主侧约 17 微秒，其中设备记派发约 6.4（两三次系统库调用约 3）、分配约 4.6（宿主改形与释放两次原语）、算子层约 4.3（内核表参数列表约 1.3 与各种核对）、派发内核约 1.1（参数字节约 0.6）。
- 统算：统算上下文与金属一样是宿主上下文加一个张量后端，各上下文共用 `库/统算张量后端` 的同一个统算设备（第零块显卡的主上下文）；在 GPU 上算的算子、交给宿主前的同步、主机已改与延后释放都同金属（段长、阈值按「后端种类」取统算的值）。不同的是显卡有自己的显存：张量仍存在宿主里，第一次在 GPU 上用到时上传一份到显存并常驻（权重只传一次）；宿主就地改过、调了「节点张量主机已改」的张量下次用到时重传；同步时把本批 GPU 写过的存储下载回宿主。派发在提交时连续发射，参数区与参数指针数组一次写好。2026-09-30 在 NVIDIA GeForce RTX 5090 上（显卡同时被别的进程占用）：节点一致性 137/138（唯「张量·后端」一行不同），深度学习框架测试 56/56，qwen3:0.6b-q8_0 贪心 64 个词元与中央处理器逐号相同，速度见本地推理与手写数字训练的说明。待办事项：同步时整块下载本批写过的存储（可改为宿主要读时才下载）；新建的结果张量也先上传一遍宿主的全零内容。
- 上限：`读取张量存储上限` 是本机物理内存（`os.totalmem()`）；`读取单次交换上限` 是 16 MiB（宿主值桥单次交换上限），适配在豫言里先核对字节串长度。
- 形状、行号等整数列表写成逗号分隔的十进制文字过值桥；元素类型、运算、旋转方式换成编号（元素类型 0 至 7 依次为单精度、半精度、脑浮点、八位整数、三十二位整数、块量化八位、超块量化四位、超块量化六位）。
- `由小数建张量` 先由宿主核对并建全零张量，再逐个写入元素；`读出张量小数` 先核对范围，再逐个取值。每个元素一次宿主调用，大块数据宜用字节函数。
- 计算：JS，结果先以双精度求得再舍入到单精度。乙为块量化的矩阵乘一律逐块在线解量化求点积（Q8_0 一次算甲一行乘乙两行或甲两行乘乙两行，乙的块读一次供多行共用），每个元素的运算次序与逐行点积相同，所以预填充与解码对同一行的结果一致；单精度、半精度的乙直接点积，脑浮点的乙逐行转成单精度。量化布局照 GGML：Q8_0 解量化与 `quantize_row_q8_0_ref` 量化、Q4_K 与 Q6_K 的 `dequantize_row_q4_K`、`dequantize_row_q6_K`。
- 参数不合规范（类型、形状、轴、范围不合，或张量属于不同上下文）时宿主抛出异常，终止本次运行；算子结果超过存储上限同样终止。带错误分支的函数遇到已释放的张量或上下文返回 `资源已失效`。
- `改形` 的结果与原张量共享同一块存储（按引用计数计入存储上限一次），释放其一不影响另一个。
- 视图（0.3.0）：宿主给每个张量记下步长与起点（以元素计）；`跨步视图` 只登记新的步长与起点，与原张量共用存储（同样按引用计数）。算子读到非连续的输入时先紧致化到一块临时共享缓冲（不计入存储上限，待办事项），逐元二元与逐元标量按步长直接读；`写入视图`、`填充常数` 与三种随机填充按步长写回共享存储。`改形`、`写入张量字节`、`写入行`、`按行累加` 遇到非连续的张量时终止本次运行。
- 随机（0.3.0）：Philox4x32-10 在宿主里用 32 位整数运算实现（乘积的高 32 位拆成 16 位两半求得），已用 Random123 的三组已知答案核对；正态分布用 Box–Muller。新增的原语都在主线程上单线程计算。
- 混合专家与线性注意力（0.4.0）：`按专家矩阵乘` 把选中同一专家的行聚成一个输入矩阵，用该专家的矩阵做一次矩阵乘（与 `矩阵乘` 同一套分块并行与融合量化点积，结果与对单个专家做矩阵乘逐位相同），再把结果放回原位；`门控递推` 按头分块交线程池，状态按单精度存回、中间量用双精度；`取前k` 逐个选最大（O(k × 行长)），`因果卷积`、`二范数归一` 单线程。待办事项：各专家的矩阵乘分开派发，解码时一层要派发三次八个专家，可合成一次派发；门控递推预填充仍逐词元，可改为分块算法。
- 训练提速（0.4.0）：逐元二元、逐元标量、逐元一元（含数乘、数加）、紧致化、同类型的写入视图与填充常数改由线程池按元素分块计算（块可从一行中间开始，直接按步长读写视图，不必先紧致化；加减乘除、比较与复制按每元素半个工作量单位计）；新增就地线性组合、亚当更新（按元素分块并行）、按轴求和与按轴最大（输入看作 [外, 轴长, 内]，按（外序，内段）分块并行，求和按轴序用双精度累加）、按行最大下标（同取前 k 取 1）。每个输出元素只由一个线程按固定次序求得，多线程结果与单线程逐位相同。
- 融合算子（0.5.0）：归一矩阵乘、归一门控矩阵乘、矩阵乘加、问键旋转写缓存、按专家门控矩阵乘。金属上下文先试 `库/张量后端` 的融合派发（`融合。豫`：张量内核有融合内核且类型、布局合用时一次派发算完，矩阵乘一族只在 `矩阵乘宜分块` 为阴的解码情形用融合的矩阵向量乘），做不了就退回小算子的组合；统算上下文暂时一律退回组合（张量后端的「融合后端合用吗」），组合里的每个小算子再各自在 GPU 或宿主上算；中央处理器上下文直接组合，所以结果与逐个调用小算子逐位相同。问键旋转写缓存的角表与旋转位置编码共用缓存。待办事项：统算版融合内核尚未在真卡上验证，验证通过后再对统算打开。
- 并行：矩阵乘按输出分块，注意力按（词元，问头）分块，工作量够大时由宿主的工作线程池一起算，线程数的取法与调整见[节点宿主说明](../../宿主/节点/说明.汉语.md)。各线程动态领块，每个输出元素只由一个线程按与单线程相同的次序求得，所以结果与单线程逐位相同；调用对应用仍是同步的。
