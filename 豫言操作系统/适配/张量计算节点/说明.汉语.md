# 张量计算接口 Node 适配

路一 Node 宿主的[张量计算接口](../../../豫言操作系统接口/张量计算/规范.汉语.md)适配。张量存储是宿主内的 `SharedArrayBuffer`，不受 Wasm 内存上限约束，宿主的工作线程可直接读写；应用只持有随机句柄号，宿主每次使用都核对种类与有效期，与文件句柄共用一张资源表。

- 后端：本适配有中央处理器（宿主以 JS 计算）与金属两个后端。`取得张量上下文` 先看宿主选项 `--张量后端`（测试用，写在 `--` 之前）：指定了就只用该后端，它不可用或不合必须加速时返回 `资源暂不可用`；没指定时按加速要求自动选：必须加速取第一个可用的加速后端（金属），偏好加速没有加速后端时用中央处理器，不限加速现取中央处理器（待办事项：金属证实更快后再改）。金属可用的条件：苹果系统、宿主给了 `--允许系统库调用`（没给时系统库调用不可用，金属不在可用之列）、能取得默认金属设备。功耗偏好现在不起作用。`读取后端名称` 与 `上下文已加速吗` 按上下文的后端回答。网页图算、统算以后接入：改写可用后端探测与「节点张量取得后端上下文」，设备表见 `库/张量后端`。
- 金属：金属上下文是宿主上下文加一个张量后端（`库/张量后端`：存储缓冲缓存、管线缓存、命令合批、延后释放；各上下文共用 `库/金属张量后端` 的同一个金属设备）。张量仍存在宿主里，金属缓冲零拷贝地包着宿主存储所在的整页（小存储绑定时带页内偏移）；金属张量带视图信息（存储地址、类型、起点、形状、步长）的缓存，GPU 结果与视图的信息直接推出，其余张量第一次用到时向宿主查（经 `系统库调用` 的张量存储与视图原语）。有「张量内核」内核且类型、布局合用的算子在 GPU 上算，只记进当前命令缓冲：矩阵乘（甲单精度；乙单精度或块量化八位；单精度的一边行不连续时先在 GPU 上紧致化，临时张量在下次同步后交还）、逐元二元、逐元一元、逐元标量（含数乘、数加）、软最大、末维求和、末维最大、均方根归一（权为单精度）、旋转位置编码（角表由 C 数学库以双精度求好再舍入到单精度，按（起位，词数，旋维，基数）缓存最近一张，各层共用）、取行（表为单精度或块量化八位）、按轴求和、按轴最大、三十二位类型的紧致化与切片、转置、拼接、写入视图（同类型且不共用存储）、填充常数（单精度）、按行累加。其余情形（超块量化、半精度与脑浮点、三十二位整数的填充、注意力、层归一、写入行、取前 k、随机填充、亚当更新等）交给宿主：交给宿主前先同步（提交并等完已记的派发），宿主就地改过的张量再调「节点张量主机已改」（金属是统一内存，不做事）。读字节、读小数、取最大下标、按概率抽样也先同步；形状、类型、步长以及改形、跨步视图不读写数据，不同步。释放张量时若还有未提交的派发用着这块存储，先建一个共用存储的视图顶住，立即释放原句柄（之后再用照常报资源已失效），视图与缓冲在下次同步后释放；释放上下文前先同步并放掉全部缓冲。待办事项：第二批内核（注意力、Q4_K、Q6_K、半精度、写入行等）合入后接上，分段解码注意力的暂存缓冲按上下文分配一块复用；解码时每层仍因注意力、写入行交给宿主而同步几次。
- 上限：`读取张量存储上限` 是本机物理内存（`os.totalmem()`）；`读取单次交换上限` 是 16 MiB（宿主值桥单次交换上限），适配在豫言里先核对字节串长度。
- 形状、行号等整数列表写成逗号分隔的十进制文字过值桥；元素类型、运算、旋转方式换成编号（元素类型 0 至 7 依次为单精度、半精度、脑浮点、八位整数、三十二位整数、块量化八位、超块量化四位、超块量化六位）。
- `由小数建张量` 先由宿主核对并建全零张量，再逐个写入元素；`读出张量小数` 先核对范围，再逐个取值。每个元素一次宿主调用，大块数据宜用字节函数。
- 计算：JS，结果先以双精度求得再舍入到单精度。乙为块量化的矩阵乘一律逐块在线解量化求点积（Q8_0 一次算甲一行乘乙两行或甲两行乘乙两行，乙的块读一次供多行共用），每个元素的运算次序与逐行点积相同，所以预填充与解码对同一行的结果一致；单精度、半精度的乙直接点积，脑浮点的乙逐行转成单精度。量化布局照 GGML：Q8_0 解量化与 `quantize_row_q8_0_ref` 量化、Q4_K 与 Q6_K 的 `dequantize_row_q4_K`、`dequantize_row_q6_K`。
- 参数不合规范（类型、形状、轴、范围不合，或张量属于不同上下文）时宿主抛出异常，终止本次运行；算子结果超过存储上限同样终止。带错误分支的函数遇到已释放的张量或上下文返回 `资源已失效`。
- `改形` 的结果与原张量共享同一块存储（按引用计数计入存储上限一次），释放其一不影响另一个。
- 视图（0.3.0）：宿主给每个张量记下步长与起点（以元素计）；`跨步视图` 只登记新的步长与起点，与原张量共用存储（同样按引用计数）。算子读到非连续的输入时先紧致化到一块临时共享缓冲（不计入存储上限，待办事项），逐元二元与逐元标量按步长直接读；`写入视图`、`填充常数` 与三种随机填充按步长写回共享存储。`改形`、`写入张量字节`、`写入行`、`按行累加` 遇到非连续的张量时终止本次运行。
- 随机（0.3.0）：Philox4x32-10 在宿主里用 32 位整数运算实现（乘积的高 32 位拆成 16 位两半求得），已用 Random123 的三组已知答案核对；正态分布用 Box–Muller。新增的原语都在主线程上单线程计算。
- 混合专家与线性注意力（0.4.0）：`按专家矩阵乘` 把选中同一专家的行聚成一个输入矩阵，用该专家的矩阵做一次矩阵乘（与 `矩阵乘` 同一套分块并行与融合量化点积，结果与对单个专家做矩阵乘逐位相同），再把结果放回原位；`门控递推` 按头分块交线程池，状态按单精度存回、中间量用双精度；`取前k` 逐个选最大（O(k × 行长)），`因果卷积`、`二范数归一` 单线程。待办事项：各专家的矩阵乘分开派发，解码时一层要派发三次八个专家，可合成一次派发；门控递推预填充仍逐词元，可改为分块算法。
- 训练提速（0.4.0）：逐元二元、逐元标量、逐元一元（含数乘、数加）、紧致化、同类型的写入视图与填充常数改由线程池按元素分块计算（块可从一行中间开始，直接按步长读写视图，不必先紧致化；加减乘除、比较与复制按每元素半个工作量单位计）；新增就地线性组合、亚当更新（按元素分块并行）、按轴求和与按轴最大（输入看作 [外, 轴长, 内]，按（外序，内段）分块并行，求和按轴序用双精度累加）、按行最大下标（同取前 k 取 1）。每个输出元素只由一个线程按固定次序求得，多线程结果与单线程逐位相同。
- 并行：矩阵乘按输出分块，注意力按（词元，问头）分块，工作量够大时由宿主的工作线程池一起算，线程数的取法与调整见[节点宿主说明](../../宿主/节点/说明.汉语.md)。各线程动态领块，每个输出元素只由一个线程按与单线程相同的次序求得，所以结果与单线程逐位相同；调用对应用仍是同步的。

新增宿主原语（外调名以 `豫言_节点_张量` 开头，共 58 个），实现在 `豫言操作系统/宿主/节点/张量.mjs`，由 `应用宿主.mjs` 并入能力表；发行启动文件把该模块内联进来。状态码同文件适配。待办事项：Q4_K、Q6_K 多行矩阵乘仍逐行点积；前 k 抽样改用部分选择；三十二位整数转脑浮点在绝对值超过 2^24 时两次舍入。
