# 邮件发送云工适配

用云工 `EMAIL` 绑定的 `send` 实现接口：适配先在豫言里逐字符解码 UTF-8 并按规范校验地址、主题、正文（空白、控制字符、多收件人、CRLF 注入都在这里被拒绝），再经薄宿主的通用原语（`库/云工宿主` 的「物宿主」与「物」）调用 `send`：同步异常和 Promise 拒绝都是失败结果，适配转成（阴，固定原因），只取错误的名称（JS 的 `name`）而不取消息。传给 `send` 的对象由「云工新对象」造成，恰为 `{from, to, subject, text}`。

**绑定**：经「云工绑定」于 `EMAIL` 于绑定名取得。宿主先核对许可：已授权而当前部署没有配置该绑定时宿主报“绑定不存在”，适配返回（阴，`邮件服务未配置`）；绑定的值不是对象或没有 `send` 方法时同样返回（阴，`邮件服务未配置`）。未授权的名称是部署错误：薄宿主的失败都是值，适配把它转成豫言异常，应用不接住时由标准库的默认处理中止当前请求。

真实本地 workerd（Wrangler 4.129.0，`send_email` 绑定配置了 `allowed_sender_addresses`）实测：`send({from,to,subject,text})` 对许可的发件地址被接受，本地平台收到的 From、To、Subject 与正文文件逐字等于输入（含换行、引号、反斜线、emoji 与 CRLF）；发件地址不在许可列表时 `send` 拒绝，错误名称为 `Error`，适配返回（阴，`邮件发送失败：Error`），不含任何地址；被本包校验拒绝的注入请求没有到达平台。综合场景见 `../消息队列/一致性验证/真实工作者/`。

`一致性验证/` 里有试验应用、真实 Wasm 的 Node 测试和复跑说明。
