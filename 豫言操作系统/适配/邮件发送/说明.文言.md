# 邮件发送云工适配

以云工 `EMAIL` 绑定之 `send` 承此约：适配先于豫言逐字符解 UTF-8，依规范校址、主题、正文（空白、控制之字、多收件人、CRLF 之注，皆于此拒之），复以薄宿主之通用原语（`库/云工宿主` 之「物宿主」与「物」）呼 `send`：同步之异与 Promise 之拒皆为败果，适配化为（阴，定因），惟取错之名（JS 之 `name`），不取其辞。授 `send` 之物，由「云工新对象」造之，恰为 `{from, to, subject, text}`。

**绑定**：以「云工绑定」于 `EMAIL` 于绑名取之。宿主先核许可：已授而当前部署未置此绑定，宿主告“绑定不存在”，适配返（阴，`邮件服务未配置`）；绑之值非物或无 `send` 之法者，亦返（阴，`邮件服务未配置`）。未授之名乃部署之误：薄宿主之败皆为值，适配化为豫言之异，客不接则标准库默认之处止当前之请。

真本地 workerd（Wrangler 4.129.0，`send_email` 绑定配 `allowed_sender_addresses`）实测：`send({from,to,subject,text})` 于许可之发件址则受，本地平台所收之 From、To、Subject 与正文之文件，逐字同于所入（含换行、引号、反斜线、emoji 与 CRLF）；发件址不在许可之列，则 `send` 拒之，误名为 `Error`，适配返（阴，`邮件发送失败：Error`），不含任何地址；为此包校验所拒之注入，未达平台。综合之场见 `../消息队列/一致性验证/真实工作者/`。

`一致性验证/` 有试应用、真 Wasm 之 Node 测试及复行之说明。
