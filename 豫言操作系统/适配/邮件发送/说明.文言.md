# 邮件发送云工适配

以云工 `EMAIL` 绑定之 `send` 承此约：适配先于豫言逐字符解 UTF-8，依规范校址、主题、正文（空白、控制之字、多收件人、CRLF 之注，皆于此拒之），复以 `云工调用方法安全` 呼 `send`，同步之异与 Promise 之拒，皆化为（阴，定因），惟自错误 JSON 取其名，不取其辞。授 `send` 之物，由豫言 JSON 编码器成之，恰为 `{from, to, subject, text}`。

**倚宿主之原语 `豫言_云工_授权绑定存在(种类, 名称)`**（今由 `宿主.mjs` 供之，环境文字适配亦用之）：先核 `许可[种类]` 含此名，未授则抛宿主之误（部署之误，豫言不可捕），已授则返环境中此绑定之真否。今之 `云工绑定句柄` 于绑定阙如则抛宿主 JS 之误，豫言不可捕，故“已授而当前部署未置此绑定”者，须此原语先告之。适配于己之模块以 `《《外调》》` 声明其包装；旧宿主无此原语，则每发皆以“未授权宿主能力”而止，一致性测试于篇首言之。

真本地 workerd（Wrangler 4.129.0，`send_email` 绑定配 `allowed_sender_addresses`）实测：`send({from,to,subject,text})` 于许可之发件址则受，本地平台所收之 From、To、Subject 与正文之文件，逐字同于所入（含换行、引号、反斜线、emoji 与 CRLF）；发件址不在许可之列，则 `send` 拒之，误名为 `Error`，适配返（阴，`邮件发送失败：Error`），不含任何地址；为此包校验所拒之注入，未达平台。综合之场见 `../消息队列/一致性验证/真实工作者/`。

`一致性验证/` 有试应用、真 Wasm 之 Node 测试及复行之说明。

**平台接口**：此适配之包之函转调平台接口之包中无体之声，编为带型之宿主导入（边界之签见《网页汇编接口》网五）：「云工宿主」之「环境与版本宿主」之「云工授权绑定存在」（旧外调名 `豫言_云工_授权绑定存在`）。宿主实此诸导入，与旧原语同。
