# 持久频道落盘适配

同一进程内、跨事件的具名文字频道：订阅得柄、发布按订阅先后送达、等待可限时、关闭先送已排队消息再报原因。状态在进程内存里，随服务程序起来而生、不落盘（规范如此）。供豫言系统与原生宿主上的服务程序使用。

## 语义

- `订阅恒频道 频道名`：核对名字（1 至 64 字节，字母、数字或 `.` `_` `:` `-`），新建订阅并返回订阅柄。
- `发布恒频道文字 频道名 文字`：文字 0 至 65536 字节；按订阅先后把文字追加到该频道每个活跃订阅，返回送达的订阅数；频道不存在返回 0。
- `待恒频道信 订阅柄 时限`：时限 0 至 3600000 毫秒。有待收消息时取首条返回（0，文字）；订阅已终止返回（2，原因）；到时限返回（1，空串）。等待期间用墙钟毫秒自旋。
- `罢订阅恒频道 订阅柄`：置为已终、原因“订阅已取消”；幂等。
- `阖恒频道 频道名 原因`：把该频道全部活跃订阅置为已终，返回被关闭的订阅数；已排队的消息先交付。
- `读恒频道订阅数 频道名`：活跃订阅数。

订阅之前发布的消息不补发；一个订阅内保序。频道名或文字越限、时限越界、订阅柄不存在时按规范报中文事故或给出状态。

## 用法

```yuyan
寻观「豫寓恒道金匮榫」之「频道」之书。

「柄」者「订阅恒频道」于『页面事件』也。
「发布恒频道文字」于『页面事件』于『甲』。
「果」者「待恒频道信」于「柄」于「三六零零零零零」也。
「罢订阅恒频道」于「柄」。
```

## 待办事项

- 等待用自旋，耗 CPU；服务程序有了事件循环后应改成挂起等待。
- 订阅积压超过 1 MiB 被断开的规则、每实例 64 个频道与每频道 256 个订阅的上限、跨事件的有效性（订阅柄只在创建它的事件内有效）尚未核对。
- 不落盘：进程重启即丢，这与规范一致。
