# 界面布局语言方案：豫言之 HTML 与 CSS

状：二〇二六年九月三十日起草，是日用户审定：嵌入式库、挂载式样式、弹性盒之子集、模型—视图—更新（先为其简）、浏览器文树与自绘二后端皆为之（其后接路二之原生窗口）、网页文树 0.4.0 增「添加页面样式规则」；记录更新之写法姑不加。是日界面核心、文树后端与自绘后端皆已成，待办之例行于浏览器文树、诺节窗口与浏览器 canvas。用户二〇二六年九月三十日提议：欲依 HTML+CSS 之法设计用户界面，须为豫言设其对应之版。本方案所设之“界面”，为一豫言库：以豫言书界面之结构、样式、布局与交互；同一界面之述，落于二后端：一曰浏览器文树（网页文树加页面之 CSS，排版委诸浏览器），一曰自绘（诺节窗口、浏览器 canvas，他日及于豫言系统，建于[图形界面地基方案](图形界面方案.文言.md)之上）。白话本见[汉语版](界面布局语言方案.汉语.md)。

全篇分十四部：一、结论与定议；二、分层与数据之流；三、语言之形；四、结构；五、样式；六、布局之模；七、文字与字体；八、控件与交互；九、二后端；十、所求于地基与对齐之约；十一、全例；十二、包与模块；十三、施行之序与验收；十四、此轮不为与待定之事。附录为接口草稿。

## 一、结论与定议

下列诸条，用户二〇二六年九月三十日皆已许之：

1. **形：嵌入式库，不改编译器。** 元素为函数，样式与属性为值，皆书于寻常之 `。豫` 文件。二〇二六年九月三十日以编译器实测（`yy4_bs.wasm --type-check-only`）：附录之接口草稿并第十一部之全例，皆过类型检查；带签名之视图函数中，不必书「授以」。
2. **样式：挂载式。** 样式为类型「样式」之值，挂于元素。命名样式犹 CSS 之类；同一元素之内，后书者覆先书者；文字属性沿树而承；「悬停时」「按下时」「焦点时」「禁用时」犹 CSS 之伪类。选择器与跨元素之层叠，此轮不为，后依需补“样式表”。
3. **布局：以弹性盒为主。** 取 CSS 弹性盒与绝对定位之子集（React Native 之 Yoga 布局引擎亦取此子集，足以书应用之界面），又加段落（行内富文本）与层叠；网格置于次期。长度为逻辑像素之整数与百分比，像素比惟见于自绘后端。
4. **状态：模型—视图—更新。** 应用书模型、消息、更新（消息、模型 → 新模型）、视图（模型 → 界面树）。光标、滚动偏移、悬停、焦点等控件内部之态，显示控件库依元素标识存之。用户二〇二六年九月三十日定：先为其简，每交互一次，则全树重算视图；组件局部之态与增量之算，俟后再议（见八·六）。
5. **二后端皆为，其后接原生窗口。** 用户二〇二六年九月三十日定：浏览器文树与自绘皆须为之；既成，乃使同一界面行于路二之原生程序，先书 macOS 之窗口接口，后及他系统。先后见第十三部：界面核心 → 文树后端与 HTML 之生成 → 自绘（诺节窗口、浏览器 canvas）→ 原生窗口。浏览器中默认走文树：界面译为 HTML 与 CSS 而授浏览器，排版、字体、绘制、输入法皆浏览器为之；canvas 自绘惟为备择。
6. **新接口（用户二〇二六年九月三十日许之）。** 静态之样式书入所生之 CSS 文件，不必改接口；运行时所算之样式须装入页面，而网页文树之白册拒 `style` 属性。故网页文树升 0.4.0，增「添加页面样式规则」：宿主依白册装 CSS 规则于一可构造之样式表，界面文树为每种样式生一类名。未用之二法见九·二。
7. **记录更新之写法姑不加。** 用户定“先为其简”。候选之写法 `甲 易「组值」【「字段」者 值 也，…】`，复制命名元组而惟改所列之字段（见三·四）；无之，则更新模型时须尽书诸字段，以辅助函数姑且应之。
8. **名称。** 包曰「界面」「界面自绘」「界面文树」；元素、属性、样式之名见第四、五部与附录，用户可随时改之。公开之名一律取二字以上之专名，其故见三·三。

## 二、分层与数据之流

```
应用：模型、消息、更新、视图（模型 → 界面树）；样式常量（相当于 CSS 文件）
  └ 界面库「界面」── 元素、属性、样式的类型与构造；元素标识；样式求值（继承、覆盖、状态变体）；
  │                    样式转 CSS、界面树转 HTML（构建工具、云工、浏览器里都能用）
      ├ 自绘后端「界面自绘」── 布局引擎（弹性、段落、层叠、绝对定位、滚动区）→ 显示树；标识→处理函数表
      │   └ 显示控件库（地基）── 绘制、控件行为、命中测试、焦点、主循环、文字量具
      │       └ 显示接口 0.2.0、字体接口、字体库（诺节 SDL 窗口；浏览器 canvas）
      └ 文树后端「界面文树」── 元素树差分 → 网页文树操作；样式 → 生成的 CSS 规则；委托订阅事件
          └ 网页文树、网页界面、网页事件（浏览器排版与绘制）
```

自绘后端一次交互之程：

1. 显示控件库呼视图回调，并交「视图环境」：文字量具、交互状态（悬停、按下、焦点所在元素之标识）、视口之宽高与像素比。
2. 界面自绘呼应用之视图而得元素树，依次定标识、求样式、排版，生显示树，并记“标识→处理函数”之表。
3. 控件库画显示树而候输入，化输入为交互事件（点击、文字改变、提交、焦点改变、按键），交诸处理回调。
4. 界面自绘查表，化交互事件为应用之消息，呼更新而得新模型；控件库乃复呼视图回调而重画。

文树后端之程亦同，惟第二步较新元素树与前一树，但书其异于页面；第三步之事件出于网页事件之委托订阅。

## 三、语言之形

### 三·一 三法

| 法 | 书法 | 所求于编译器 | 所长 | 所短 |
| --- | --- | --- | --- | --- |
| 甲、嵌入式库（所荐） | 寻常 `。豫` 文件：元素为函数，样式、属性为值 | 无 | 界面与应用之态同在一程序，事件之处理径出应用之消息；类型检查兼为样式之检（样式名书误、值之类型不合，皆报错）；复用可借函数、条件、列表与模块 | 较 HTML 多 `「列」【】` 与 `于`；多态之处间须标注类型 |
| 乙、新文件之种，如 `名。界面。豫` | 豫言之语法，编译器别解之 | 与着色语言同一套：模块查找、翻译器、构建集成、保留后缀 | 可于构建之期检其结构、抽出静态之样式 | 界面须读写运行时之态，终须译回豫言函数；多一套规则须维护 |
| 丙、二者相合 | 库，外加一种样式表文件 | 惟于样式表行乙之一套 | 静态之样式可于构建之期生 CSS | 动态之样式仍走运行时，二途并存 |

着色语言所以另立文件之种者，以着色程序行于 GPU，须译为 WGSL 或 MSL。界面之代码与应用行于同一 Wasm 程序，用库足矣。

### 三·二 书法之约

- 元素书作 `元素 于 样式列 于 内容`；可交互之控件多一属性列：`元素 于 样式列 于 属性列 于 内容`。
- 样式列与属性列皆书为 `「列」【…】`，空者书 `「列」【】`。样式列中，命名样式与单条样式可混书：`「列」【「主按钮」，「伸展」于「1」】` 犹 `class="主按钮" style="flex-grow:1"`。
- 界面树依应用之消息类型而参数化，其类型书作 `「界面」于「待办消息」`。属性径带消息：`「点击时」于「添加」`、`「输入时」于「改草稿」`；带参数之消息构造器可径作函数而传。
- 样式为单态之值（类型「样式」），可存于组值与列表，亦可由函数算出，故主题即寻常之数据。

### 三·三 已测之类型行为与取名之规

二〇二六年九月三十日，以编译器实测接口草稿与示例，所得如下：

- 视图函数有签名（结果类型为 `「界面」于「待办消息」`），则检查模式传期望类型直入列表之每项，`「按钮」于「列」【「主按钮」】于「列」【「点击时」于「添加」】于『添加』` 不必书「授以」。`「态射」于「条目们」于「条目视图」` 之隐参，由变量与顶层定义推定，亦不必书。
- 以「虑」绑一段界面，绑处无期望类型，须标注：`虑「头部」者（「界面」于「待办消息」）也 … 而 …`，或书为带签名之顶层函数。多态函数之实参若为复合之式（如 `「长度」于（「滤」于 …）`），先以「虑」绑为变量；此为语言今有之限（见 `LOCALAGENTS.md`）。
- **库之公开名，劫持应用「鉴」中同名之模式变量**；函数参数与「虑」之绑不受其扰。实测：库既导出「文」，应用书 `有（「改草稿」于「文」）则 …`，即报“函数应用的隐式参数无法完全确定”。故界面库之公开名，一律取二字以上、罕用为变量之专名（纯文、文片、带键、空元素、色码、宽度……）；显示控件库亦依此取名，已与地基之会话约定。

### 三·四 语言之阙

此方案无须新语法。有一可选之补，用户二〇二六年九月三十日定姑不加，俟模型字段既多再议：

**记录更新** `甲 易「组值」【「字段」者 值 也，…】`：复制命名元组甲，惟改所列之字段，类型同甲；所列之字段须为甲之字段，且类型相符。前端展之为 `虑 临 者 甲 而「组值」【各字段取新值或 临 中 字段】`，惟动语法分析与类型检查（依甲之类型补全其余字段），代码生成不易；此改在编译器，须完整自举。其用：模型—视图—更新之模型常有十余字段，每更新皆须尽书之（示例之「换条目」，即为此而书之辅助函数）；界面库内部之计算样式记录亦可用之。有之，则示例之一支可书为：

```yuyan
有（「改草稿」于「文」）则（「旧」易「组值」【「草稿」者「文」也】）
```

### 三·五 与 HTML/CSS 之系

界面语言为 HTML/CSS 一子集之别书，二者之间为单向之嵌入：每一界面皆可译为同义之 HTML 加 CSS（文树后端即此译），反之，惟落于子集之 HTML/CSS 乃能译回。

- **界面所无者**（举其例）：浮动、行内块、表格布局、外距折叠、fixed 与 sticky 定位、网格（次期补之）；选择器、特指度与伪元素；em、rem、calc；阴影、渐变、变换与动画；任意之标签与任意之脚本。
- **HTML/CSS 所无者**：类型检查、元素标识与键、消息与模型—视图—更新、由函数算出之样式与主题。
- **语义以所译为准**：布局之规取 CSS 之定义。除文字断行之细节外，同一界面于自绘所排之矩形，当与浏览器所排者同。故浏览器可为自绘布局引擎之参照实现：随机生界面树，译为 HTML/CSS，于无头 Chrome 中以同一字体文件（`@font-face`）排版，较诸元素之矩形。

## 四、结构（HTML 之对应）

### 四·一 类型

```yuyan
「界面」立化「元类型」而「元类型」也。「：块级元素，按消息类型参数化：」
「行内」立化「元类型」而「元类型」也。「：段落里的行内片：」
「属性」立化「元类型」而「元类型」也。「：控件的属性与事件处理：」
「样式」立「元类型」也。「：一条样式或一组样式：」
「颜色」立「元类型」也。
「对齐方式」立「元类型」也。
```

### 四·二 块级元素

| 书法 | 说 | 于文树 |
| --- | --- | --- |
| `「竖排」于 样式 于 子列` | 纵向而排子元素，亦充寻常之块 | `div`，弹性纵排 |
| `「横排」于 样式 于 子列` | 横向而排 | `div`，弹性横排 |
| `「层叠」于 样式 于 子列` | 子元素叠于同一区，后书者居上 | `div`，单格之网格 |
| `「滚动区」于 样式 于 子列` | 纵向而排，内容逾界则滚动 | `div`，`overflow: auto` |
| `「文字块」于 样式 于 文字` | 单一样式之一段文字，自动换行 | `div` |
| `「段落」于 样式 于 行内列` | 多样式之文字 | `p` |
| `「按钮」于 样式 于 属性 于 文字` | 按钮 | `button` |
| `「文本框」于 样式 于 属性 于 当前文字` | 单行文本框，支输入法 | `input` |
| `「复选框」于 样式 于 属性 于 是否选中` | 复选框 | `input type=checkbox` |
| `「可点」于 属性 于 元素` | 使任意元素可点、可聚焦（按钮之义） | 元素加 `role=button`、`tabindex=0` |
| `「分隔线」于 样式` | 分隔线 | `hr` |
| `「留白」于 样式` | 占位之空白，配「伸展」以为弹簧 | `div` |
| `「空元素」` | 一无所显，供条件之支用 | 不生节点 |
| `「带键」于 键 于 元素` | 予列表项一恒定之键 | —— |

容器之子元素皆为块级元素；文字须置于文字块或段落，此与 React Native 同。

### 四·三 行内

| 书法 | 说 | 于文树 |
| --- | --- | --- |
| `「纯文」于 文字` | 承段落样式之文字 | 文本节点 |
| `「文片」于 样式 于 文字` | 另带样式之一段文字（加粗、变色、删除线） | `span` |
| `「链接」于 样式 于 属性 于 文字` | 可点之文字；跨行则每行各一热区 | `a`（`href="#"`，点击则止其默认） |
| `「断行」` | 强制换行 | `br` |

### 四·四 属性与事件

| 书法 | 所施 | 说 |
| --- | --- | --- |
| `「点击时」于 消息` | 按钮、可点、链接 | 点击；焦点在其上时，按回车或空格 |
| `「输入时」于 函数` | 文本框 | 文字改变；函数由新文字得消息 |
| `「提交时」于 消息` | 文本框 | 按回车 |
| `「切换时」于 函数` | 复选框 | 函数由新选中之态得消息 |
| `「按键时」于 函数` | 可聚焦元素及其祖先 | 控件未用之按键；函数返 `「或可有」于 消息`，得「可无」则续问上一层之祖先 |
| `「聚焦时」于 消息`、`「失焦时」于 消息` | 可聚焦元素 | 焦点移入、移出 |
| `「占位」于 文字` | 文本框 | 空时所显之提示 |
| `「禁用」于 爻` | 按钮、文本框、复选框、可点 | 为阳则不应交互、不可聚焦，并启「禁用时」之样式 |
| `「自动聚焦」` | 可聚焦元素 | 元素初现则取焦点 |
| `「悬停提示」于 文字` | 任意元素 | 于文树书为 `title`；自绘留待办 |

### 四·五 标识

每元素有一标识：自根而下，各级子元素之序号以 `/` 相连；带键之元素以 `键:键文字` 代序号。根为 `0`，如 `0/4/键:7/2`。标识跨帧而恒，用于三处：显示控件库依之存光标、滚动偏移等控件之态；界面自绘依之由交互事件查回处理函数；文树后端书之于 `data-yy`，事件载荷之「操作键」即此标识。判祖先依路径之前缀（与之等，或以之加 `/` 为首）。

列表项须用「带键」：删去中间一项，其后诸项之标识不变，焦点与控件之态随原条目而行。

### 四·六 组件、条件与列表

- 组件即函数：`「条目视图」乃化「待办」而（「界面」于「待办消息」）也。`
- 条件：`若 条件 则 元素 否则「空元素」`；样式之条件书 `「条件样式」于 条件 于 样式`。
- 列表：`「态射」于 条目们 于「条目视图」`；拼接用「附加」。

## 五、样式（CSS 之对应）

### 五·一 样式为值

```yuyan
「主按钮」乃「样式」也。
「主按钮」者「样式组」于「列」
  【「内距横竖」于「16」于「8」
  ，「背景」于「主色」
  ，「字色」于「纸色」
  ，「圆角」于「6」
  ，「悬停时」于「列」【「背景」于「主色深」】
  】
也。
```

- **单条与成组**：一条样式声明为一「样式」值；「样式组」合一列样式为一，故命名样式与单条声明可混于同一样式列。
- **覆盖**：同一元素上之样式依源码之序生效，后书者覆先书者，样式组就地展开。
- **状态变体**：「悬停时」「按下时」「焦点时」「禁用时」各带一列样式，叠于常态样式之后；数态并立，则依悬停、焦点、按下、禁用之序叠之，后者胜。悬停与按下亦及于祖先，与 CSS 同：卡片中之按钮见悬停，则卡片亦算悬停。文树后端书之为 `:hover`、`:focus-visible`、`:active`、`:disabled` 之规则。
- **条件**：`「条件样式」于 爻 于 样式` 犹依条件增减类名；「无样式」为空样式。
- **继承**：文字属性（字体族、字号、粗体、字色、行高、文字对齐、字间距、换行方式）沿树而承，其余属性不承。此与 CSS 之继承属性一致，文树后端径委浏览器承之（按钮与文本框加 `font: inherit`）。
- **默认样式**：每种元素有一份默认样式，犹浏览器之用户代理样式表，如按钮之背景、内距、圆角与文字居中，文本框之边框与默认之宽，诸可聚焦控件之焦点环（「焦点时」之变体）。二后端用同一份默认之值，文树后端书之于界面文树自带之基础 CSS。
- **主题**：主题即一组颜色常量与命名样式。固定之主题书为一模块（如 `样式。豫`，犹 CSS 文件）；欲于运行时换肤（如暗色），则作主题为组值 `「主题」即「组类」【「主色」乃「颜色」也，…】也`，书样式为函数 `「主按钮」乃化「主题」而「样式」也`，视图自模型取当前之主题。

### 五·二 选择器与层叠

| 法 | 说 | 所长 | 所短 |
| --- | --- | --- | --- |
| 挂载式（所荐，首期） | 样式挂于元素，复用赖命名之常量与函数 | 有类型检查；无全局之效，改一处样式，惟及用此样式之元素；二后端皆易实现 | 不能远施样式于他处所生之内容（如由标记文所渲之文档）；换主题须传主题于视图 |
| 选择器与层叠 | 样式表加选择器（元素之种、类名、状态、后代）与特指度 | 最似 CSS；能一施样式于整棵子树 | 二后端皆须为选择器之匹配与特指度；类名成字符串，书误不报错 |

首期惟为挂载式。他日须一施样式于文档类之内容，乃补“样式表”：`「样式表」于「列」【「规则」于 选择器 于 样式列，…】`，选择器取元素之种、类名、状态与后代四者，与挂载式并存，挂载之样式胜。

## 六、布局之模

### 六·一 根元素与盒模型

视图所返之根元素，其宽高取视口之宽高，犹网页中令根容器 `height: 100%`；故根下之元素可以「伸展」分视口所余之高。内容逾视口，则全页不滚动；须滚动者，置于滚动区。

宽度与高度含内距与边框（`box-sizing: border-box`）。外距不折叠：竖排犹 CSS 之弹性纵排，段与段之隔用「间距」。最小、最大尺寸夹所算之尺寸。

### 六·二 弹性（竖排、横排、滚动区）

依 CSS 弹性盒规范第九节之算法，取其子集：

1. **基准尺寸**：取「基准」；无则取宽度或高度；又无则取最大内容尺寸（于文字，即不换行时之宽）。
2. **分行**：有「换行排」，则依主轴可用之空间，分诸子元素为数行；否则惟一行。
3. **伸缩**：余空间依「伸展」之比分之；空间不足，则依「收缩」乘基准尺寸之比缩之；某项触最小或最大尺寸则冻之，余者重算，至于尽定。自动最小尺寸取最小内容尺寸（于文字，即最长之不可断段），与 CSS 同，故按钮不为所挤而窄于最长之词；滚动区之自动最小尺寸为零。
4. **交叉轴**：默认拉伸；亦可靠起、居中、靠末，或依首行之基线对齐。
5. **主轴放置**：先留间距，再依主轴对齐分余下之空间。
6. **百分比**：包含块之尺寸已定则照算，未定则视为自动。

默认之值取 CSS 者：伸展零、收缩一、基准自动、交叉拉伸。故文树后端不必另设，两边之行一致。

### 六·三 层叠

子元素皆置于容器之内容盒，各依「自身对齐」定位（默认拉伸），后书者居上；用以于卡片上叠角标、于图片上叠文字。于文树书为单格之网格（`display: grid`，子元素 `grid-area: 1 / 1`）。

### 六·四 绝对定位与浮层

「绝对定位」之子元素不入父容器之排列，以父元素之内边距盒为准，依贴边之距定位；未予贴边之距，则置于起始之角。文树后端为诸元素皆加 `position: relative`，使包含块即父元素。

浮层（对话框、菜单、提示）置于次期：`「浮层」于 样式 于 子列` 可书于树之任处，排版时提至根层，以视口为准定位，于文树用 `position: fixed`。

### 六·五 滚动区

内容依“主轴不限长”排版，得内容之宽高；视口之大小由外层之弹性排版定之。显示树之滚动区节点，受视口矩形、内容宽高与依内容坐标排定之子节点；滚动偏移归控件库司之。

### 六·六 网格（次期）

取 CSS 网格之小子集：列轨道（定像素、依比例 `fr`、随内容）、行随内容、行列之间距、跨列。用于表格式之对齐，如文件列表、设置之页。

### 六·七 单位与像素比

- 长度为逻辑像素之整数，即 CSS 之 `px`；又有百分比（宽占、高占）与行高之倍数（小数）。em 与视口单位留待办。
- 布局引擎于内以六十四分之一逻辑像素之整数计算，与 Chrome 排版引擎 LayoutUnit 之精度同，不用小数之算。
- 像素比惟见于自绘后端：显示树之矩形与字号皆以六十四分之一逻辑像素计，控件库乘像素比，乃依边取整至物理像素，字形依物理字号栅格化，故高分屏上文字清晰；一逻辑像素之线，于二倍之屏占二物理像素。

## 七、文字与字体

- **属性**：字体族列、字号、粗体、字色、行高、文字对齐、换行、省略号与最多行数、字间距、下划线、删除线，见五·三。字重惟分常规与粗二档；字体无粗体之字面，则由字体库合成加粗。斜体留待办。
- **字体族与回退**：依族列次第求收有此字之字体，皆无则回退于「无衬线」，犹无则画方框（`.notdef`）。标准族名「无衬线」「衬线」「等宽」，由字体接口依平台求得带中文之字体（如苹果上之华文黑体、宋体）。文树后端书三标准族名为 `sans-serif`、`serif`、`monospace`，余族名照书。
- **空白与换行**：默认存空格与换行符，并自动换行，犹 CSS 之 `white-space: pre-wrap`；界面之文字多出于程序中之字符串，存其原样最为直观。断行之机，在空格之后、汉字与假名及全角标点之间、强制换行之处；词长于一行者，依字断之。
- **中文排版**：字体库行简单禁则（行首不置 `。，、；：？！）】」』》` 等，行尾不置 `（【「『《` 等）；文树后端书 `line-break: strict`，由浏览器同为之。中西文之间自动加空（CSS 之 `text-autospace`）、标点挤压、中文两端对齐、竖排，留待办。
- **行高与基线**：行高等于字号乘倍数，所余之空间上下平分（CSS 之半行距模型）；同一行中字号不同，则依基线对齐。
- **富文本**：段落由纯文、文片、链接而成，全段交文字量具一次排版；显示树之文字节点径受排版之果而绘，所量与所画一致。
- **二后端之异**：文树用浏览器之字体与断行，自绘用字体库，故同一界面于两边之字宽与换行之位略有不同。布局之规相同，其异惟出于字形。

## 八、控件与交互

### 八·一 模型—视图—更新

```yuyan
「运行界面」于『主窗口』于「初始模型」于「视图」于「更新」。
```

- **模型**：任意类型，常用命名元组。
- **消息**：应用以「立」声明之，如 `「删除」立化「整数」而「待办消息」也。`
- **更新**：`化 消息 而化 模型 而 模型`。可径呼宿主函数（如写文件），耗时之呼则滞界面；异步之务、定时与网络之果（订阅）留待办。
- **视图**：`化 模型 而（「界面」于 消息）`，为纯函数，每交互之后全树重算。

别有一组织之方，为可变引用加回调，即云工作台今行之写法：事件之处理径改引用、呼页面接口。所以择模型—视图—更新者，以视图为模型之纯函数，易测、易推，消息亦有类型；其价，则更新时须重建模型，三·四之记录更新写法可缓之。

### 八·二 控件之集

- 首期：按钮、文本框（单行，含输入法）、复选框、滚动区、链接、可点、分隔线。
- 次期：多行文本框、单选框、下拉选择、滑块、图像、浮层（对话框、菜单、提示）、网格表格。
- 再后：选区与剪贴板、拖放、撤销、无障碍、动画。

### 八·三 受控之控件

文本框每帧显模型中之文字（示例中之 `「文本框」于 … 于（「模」中「草稿」）`）。用户输入，则发「输入时」之消息，应用存新文字于模型；不存，则文字复原，与 React 之受控输入同。光标之位与水平滚动归控件库；程序缩短其文字，则光标夹至末尾。复选框同理：显模型所予之选中状态，点击则发「切换时」于 新状态。

### 八·四 事何以成消息

控件库所交回之交互事件，皆带元素标识。界面自绘依前一帧所记“标识→处理函数”之表处之：

| 交互事件 | 所查得之处理函数 |
| --- | --- |
| 点击(标识) | 其元素之「点击时」；复选框取「切换时」于（当前状态取反） |
| 文字改变(标识, 新文字) | 「输入时」于 新文字 |
| 提交(标识) | 「提交时」 |
| 焦点改变(新标识) | 旧焦点元素之「失焦时」与新焦点元素之「聚焦时」 |
| 按键(焦点标识, 键名, 修饰键) | 自焦点元素起，沿祖先（依标识前缀）求「按键时」，以首返「可有」者为准 |

得消息则呼更新；查无处理函数之事件，弃之。

### 八·五 焦点与键盘

- 可聚焦者：按钮、文本框、复选框、链接、可点（未禁用时）。Tab 与上档加 Tab 依树序轮换焦点，控件库为之。
- 焦点在按钮、链接、可点之上，则回车与空格触发点击；文本框中回车则发提交。
- 「自动聚焦」：元素初现则取焦点，控件库为之，文树后端呼「聚焦节点」。由消息所发之程序性聚焦，留待办。
- 焦点环：可聚焦控件之默认样式带「焦点时」之变体，应用可覆之。
- 快捷键：于根元素或容器挂「按键时」。键名用显示接口之键名（上、下、回车、退格、退出……）；界面库予组值「按键信息」：键名，加上档、控制、交替、命令四爻。

### 八·六 更新与差分

用户二〇二六年九月三十日定：先为其简，即 Elm 之式；组件局部之态（React 之 useState、Bonsai 之 state）与增量之算，俟后再议。

- 每一消息：更新得新模型，视图全树重算，得新元素树。组件为返界面之寻常函数，惟受参数，不带状态。
- 自绘：全帧重求样式、排版、重画，不为差分；光标、滚动、焦点、悬停依元素标识对回，标识之用犹 React 之 key。
- 文树：新旧元素树依位置与键而差分，惟改所变之节点，故文本框不失焦点、不断输入法（见九·二）。
- 他日依需加速，写法不变：模型未变（惟悬停、焦点变）则复用前一帧之元素树；`「缓存」于 键 于 子树函数`，键与前一帧同一标识处者同，则复用子树与布局（犹 Elm 之 lazy、React 之 memo）；长列表惟排视口内之行（须控件库回报滚动偏移）；较前后显示树，惟重画脏矩形；组件局部之态依元素标识存于运行时；增量之算。

## 九、二后端

### 九·一 自绘

视图回调中，依次定标识、求样式、排版、生显示树。元素与显示树节点之对应：

| 元素 | 显示树节点 |
| --- | --- |
| 带背景或边框之元素 | 「方框」：边框盒之矩形、背景、统一之边框、圆角，依需裁剪 |
| 单边边框 | 贴边之细方框 |
| 文字块、段落 | 「文字节点」：段落排版加片列 |
| 按钮、可点 | 「热区」（按钮热区），内含方框与文字节点 |
| 链接 | 每行之片段各一「热区」（链接热区，同一标识） |
| 余元素（容器、文字块、段落等） | 「热区」（区域热区：涉悬停、按下，点击循祖而上寻其处置） |
| 文本框 | 方框（外观）加「文本框节点」（内容区） |
| 复选框 | 热区（按钮热区），内含方框与勾（先画实心之内方块，后易为勾形） |
| 滚动区 | 「滚动节点」：视口、内容宽高、依内容坐标排定之子节点 |
| 分隔线 | 细方框 |

重画由控件库发之：交互状态或模型一变，则呼视图回调，全帧重算元素树、样式与布局。数百元素之界面足用；长列表惟排视口内之分（虚拟列表）、段落排版之缓存，留待办。

### 九·二 文树

浏览器本能读 HTML 与 CSS，故于浏览器中译界面为 HTML 与 CSS 而授之：排版、字体、绘制、输入法、滚动、选中复制、无障碍，皆浏览器为之；布局引擎、字体库、显示控件库于浏览器中一概不用。浏览器中所余，惟应用之逻辑（模型、更新、视图，编为 Wasm）、界面核心与文树后端之差分及事件，皆甚薄。

界面核心有一纯豫言函数，书界面树为 HTML 字符串加 CSS 之文，构建工具、云工、浏览器中皆可用。依页面之种，其法有三：

| 页面之种 | 法 | 浏览器所得 | 须 Wasm 否 |
| --- | --- | --- | --- |
| 纯静态（文档、官网之页） | 构建时书界面树为 `.html` 与 `.css` 文件，可与静态站、标记文二库相配 | 寻常 HTML、CSS | 不须 |
| 有交互之应用 | 首屏同上，或于云工由服务端生之；Wasm 既载，则接管此现成之节点（hydration），其后惟为差分更新 | HTML、CSS、`.wasm` | 须，惟司交互 |
| 纯动态 | Wasm 既启，乃建全页 | 空壳 HTML、CSS、`.wasm` | 须 |

- **元素至标签**：竖排、横排、层叠、滚动区、文字块、留白书为 `div`；段落书为 `p`；文片书为 `span`；链接书为 `a`；按钮书为 `button`；文本框与复选框书为 `input`；分隔线书为 `hr`。带处理函数之元素书 `data-yy`，其值为标识。
- **布局委诸浏览器**：样式属性一一书为 CSS 属性（五·三之右列）；弹性、换行、继承、伪类，皆浏览器依 CSS 为之。
- **样式何以入页面**：静态之样式（首屏所用者、顶层之命名样式）书入所生之 CSS 文件，由页面 `<link>` 引之，或径书于所生 HTML 之 `<style>`；此为页面文件本身，网页文树之限惟司运行时之呼，不必改接口。运行时所算之样式，与首屏未尝现之样式，须于运行时补装；用户二〇二六年九月三十日许第一法：
  1. **用之：网页文树 0.4.0 增「添加页面样式规则」。** 界面文树取每元素展开后之样式（常态加诸状态变体），序列化而取其散列，得类名（如 `豫样-3f2a9c`），初现则装一规则，状态变体装为伪类之规则；元素惟设 `class`。宿主置规则于一可构造之样式表（`document.adoptedStyleSheets`）：属性限于白册；值限于定式（长度、百分比、数、颜色、关键字），不许 `url()` 等函数；选择器惟许一类名，可带一白册内之伪类；规则总数之上限取大（如十万条）。运行时所算之样式（依数据而定之宽度、颜色）照样可用。
  2. 未用：惟恃构建期所生之 CSS 文件。其所能覆者惟顶层之命名样式，运行时所算之样式不能预生，且构建时须行应用之代码以求样式之值。
  3. 未用：预制之原子类（如 `宽度-200`）。值惟能取有限之刻度，任意之值不能书。
- **差分**：新旧元素树依位置与键而较：其种同，则改文字、类名、属性与控件之值；其种异，则替换之；子列表依键对齐，增、删、移皆以最少之文树操作。全树重建，则文本框失焦点与输入法之组字，故须为差分。
- **事件**：于容器以「订阅界面事件」委托订阅 `click`、`input`、`keydown`、`focusin`、`focusout`；事件载荷之「操作键」即元素标识，「值」为文本框之新文字；链接之点击，于订阅策略中止其默认。
- **受控文本框**：更新之后，模型中之文字与页面上之值不同，且不在组字之中，乃以「设置节点值」书回（此不触发 `input` 事件）。
- **页面**：应用之页面置一容器元素，并引界面文树之基础 CSS；`「运行界面」` 之第一参数为容器之 ID。
- **限额**：网页文树之柄表今为四千零九十六项，界面文树为每一活元素留柄，则不敷用；实现时依 AGENTS.md 放大百倍。

### 九·三 路二之原生窗口（其后）

详法见[原生窗口方案](原生窗口方案.文言.md)（二〇二六年十月一日用户许其开工）。下为当初之设想。

用户二〇二六年九月三十日定：二后端既成，乃使同一界面行于路二之原生程序，先书 macOS 之窗口接口，后及他系统，其详设计届时另书。今之途：图形界面在 GC 接口之上，触平台惟经显示接口与字体接口；路一由 JS 宿主（诺节 SDL 窗口、浏览器 canvas）实现，路二之底层接口 v1 不含显示与输入，故原生程序与裸机暂不能显示。所当为者三：

1. **底层接口 v2 增「豫言操作系统底层显示」**（包名早已预留）：与 GC 显示包同构，取显示面、尺寸、提交 RGBA8 像素、读输入事件，惟用整数与（址，长）。
2. **GC 垫层接之**：落 GC 之显示原语于底层显示；帧缓冲本为执行器内存中之字节数组，依（址，长）交下；字体无须新包，GC 垫层经「底层文件」读预开之字体目录。
3. **诸平台后端**：macOS 用 AppKit（经 Objective-C 运行时之导入，书写器须能链接系统之框架），Windows 用 user32 与 gdi32，Linux 可径于套接字上言 X11 或 Wayland 之协议，裸机书 virtio-gpu 与 virtio-input 之驱动；输入法诸平台各有一套入口（macOS 之 NSTextInputClient、Windows 之 IMM32）。

界面库、显示控件库与字体库皆不须改。裸机上同时开数图形应用，则尚须一合成窗口之程序，届时再议。

## 十、所求于地基与对齐之约

二〇二六年九月三十日，与“开发豫言图形界面：字体能力与控件布局库”之会话对齐，下列诸条对方皆已受之，显示控件库依此实现。显示树之类型草稿（`库/显示控件/显示树。豫`，尚未提交）已依此书成：节点为「方框」「文字节点」「热区」「文本框节点」「滚动节点」，热区之种为「按钮热区」「链接热区」「区域热区」，段落参数中之对齐与换行为「段落对齐」「单行排版」等，皆以「立」之构造器依位置取参；其细以实现为准。两边约定：显示树之名惟用于界面自绘内部，与界面库重名，则显示树改其名。

## 十三、施行之序与验收

用户二〇二六年九月三十日定：二后端皆为，其后接路二之原生窗口。

1. **界面核心**：类型与构造、标识、样式转 CSS、界面树转 HTML、事转消息、差分；单元测试核样式组之展开、覆盖、状态变体、所生 HTML 与 CSS 之文字、依事寻回之消息与差分所出之改。样式求值随自绘为之。
2. **文树后端**：网页文树 0.4.0 之接口改动（规范、宿主、适配、清单重生成），首屏 HTML 之生成与接管、差分、事件。此途无须布局引擎，最早可用于浏览器。验收：待办之例于无头 Chrome 中合成点击、按键、文字输入，而后核页面。
3. **自绘**：布局引擎以假量具（每字等宽，上升、下降皆定）为单元测试：竖排堆叠、伸展与收缩、最小内容之约束、换行排、诸种对齐、百分比、内距与边框、绝对定位、层叠、滚动区之内容尺寸、段落断行与链接热区。对照之测：同一树经第一步译为 HTML 与 CSS，于无头 Chrome 中以同一字体文件排版，较诸元素之 `getBoundingClientRect` 与引擎之果。乃接显示控件库，待办之例行于诺节窗口与浏览器 canvas；自动冒烟（诺节后台之窗画一帧即退、无头 Chrome 合成输入），人工验收约用户在场（中文输入、增删、勾选、滚动、Tab、悬停变色、高分屏之清晰）。进度（二〇二六年九月三十日）：假量具之单元测试四十项皆过；待办之例行于诺节后台之窗无误，于浏览器 canvas 核中英之输入、回车与钮之添加、勾选、删除、链接、悬停变色与滚动；与无头 Chrome 之对照、诺节窗口之人工验收待为。
4. **次期**：网格、浮层、多行文本框、单选与下拉、图像、窄屏之变体、样式表（选择器）。
5. **路二之原生窗口**（九·三）：底层显示 v2、GC 垫层、先 macOS 后他系统之窗口后端，另书方案。
