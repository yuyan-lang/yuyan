# 原生窗口方案：路二之显示与输入（先 macOS）

状：2026-09-30 起草；2026-10-01 依取消外调后之宿主边界，改第一、二、三、六节，是日用户审定第一节五条而许开工；是夜依“外部调用皆于接口文件声明、由宿主实之”，改第五节之通用外部调用桩为逐一所声之原生函（第一节第二条、第三、五、七、九节随之而改）。承[界面布局语言方案](界面布局语言方案.文言.md)九·三：二后端既成，乃使同一界面行于路二之原生程序，先书 macOS 之窗口，后及他系统。本方案所求：界面库、显示控件库所书之应用（如[界面自绘示例](../../库/界面/示例/自绘/包说明.文言.md)），编为路二之 macOS arm64 可执行文件，不经诺节，径开窗口而行：画面、指针、键盘、滚轮、中文输入法、高分屏、关闭窗口。界面库、显示控件库与字体库皆不改。白话本见[汉语版](原生窗口方案.汉语.md)。

全篇分十一部：一、当决之事；二、今之状与所阙；三、总体之法；四、新底层包「底层显示」；五、降级器之原生函之呼；六、执行器与 GC 之边界；七、macOS 后端；八、构建、运行与验收；九、他平台之法；十、施行之序；十一、此轮不为与风险。

## 一、当决之事

1. **新增底层接口包「豫言操作系统底层显示」**（包名早已预留），底层接口自 0.1 升 0.2，凡 5 函数（第四节）。此为新接口。
2. **所用之原生函皆于接口文件逐一声明**：dlopen、Objective-C 运行时、CoreFoundation、CoreGraphics 之函，与依签名分之 objc_msgSend，声于执行器之 `平台接口/苹果。接口。豫`，降级器依「苹果原生表」生其呼，带 64 位之值、双精度寄存器、栈参数与双精度结构之返回（第五节）。无依函数指针或名呼任意原生函之途。先为 macOS arm64。
3. **路二不书适配，由执行器径实现可移植之显示接口与字体接口。** 依取消外调后之新边界（第六节），接口函数未绑适配，则编为带类型之宿主导入（模块名即包名，字段名即函数名）：显示接口 0.2 之函数 6、字体接口 0.1 之函数 4，由执行器实现，应用不绑任何适配而径构建。不增外调名，亦不袭诺节之原语名。执行器与降级器归 WP8 会话（客体二号、原生性能）所司，此二处之改动先交之审，由之于 pit-mac 上为原生之验。
4. **输入法用隐形文本视图**（与浏览器宿主之隐形输入框同理），首版不为回调；首版之窗口不能拖动以改尺寸（与诺节 SDL 版同）。
5. **此轮惟为 macOS arm64**。macOS x86-64、Windows、Linux 与裸机俟后另为，第九节惟记其法。

## 三、总体之法

```text
应用（界面自绘示例；yy豫构 直接构建，不绑适配）
  └ 显示控件库 → 显示接口 0.2、字体接口 0.1（带类型导入：模块“豫言操作系统显示”“豫言操作系统字体”）
       └ 执行器「客体二号」实现这 10 个导入
            ├ 显示 → 底层显示（新包，5 个函数）→ macOS 后端：AppKit、CoreGraphics（dlopen 载入，经苹果接口所声之原生函呼之）
            └ 字体 → 底层文件「打开」与底层句柄「定位读」，只读系统字体目录
```

要：可执行文件犹惟链 libSystem，dyld 惟多绑 `dlopen` 与 `dlsym`；AppKit 于运行时载入；凡 Objective-C 之呼，皆经接口文件依签名所声之 `objc_msgSend`，降级器为每声生一桩，初呼时以 dlsym 解其符号；首版无任何“系统呼我”之回调。

## 四、新底层包「豫言操作系统底层显示」

目录 `豫言操作系统底层接口/底层显示/`，一模块 `显示。接口。豫`，依赖 底层库、底层基础、底层句柄，其性可选（无窗口之平台一概返 58）；于父包「包含包」中列于底层进程之后，总纲之表与函数之总数（45 → 50）随之同改。

## 五、降级器：原生函之呼

今之导入桩，惟能置 32 位整数至多 8 于 x0–x7、取回 i32；而 Objective-C 之呼，须传 64 位之对象指针与选择子、双精度之矩形与坐标，又须取回双精度及四双精度所成之矩形。凡所用之原生函，皆于接口文件声之，降级器依表生其呼：

- **声**：执行器之 `平台接口/苹果。接口。豫`（模块“苹果”，与 libSystem 之函同一接口文件）逐一声 dlopen、objc_getClass、sel_registerName、objc_autoreleasePoolPush/Pop、CFDataCreate、CGDataProviderCreateWithCFData、CGImageCreate、CFRelease、CGColorSpaceCreateDeviceRGB，及依签名分之 objc_msgSend：消息、消息整参、消息槽参、消息址参、消息双参、消息框参、消息开窗、消息取事件、消息取字节、消息得整、消息得双、消息得点、消息得框。
- **原生函表**（`降级目标。豫` 之「苹果原生表」）：每行为导入名、C 符号、参类、果类、栈补零之字数、惰绑与否。参类：32 位整数（零扩或符扩）、线性内存之址（加内存基址为绝对指针）、八字槽中之 64 位值（入 x 寄存器）、槽中之双精度（一，或 NSPoint 二、NSRect 四相连之槽，入 d 寄存器）、常数（不占导入之参，如 CGImageCreate 之 8、32、5 与取事件之 NSUIntegerMax）。果类：整数与 BOOL 径返其低 32 位；指针与双精度（一、二、四）书于首参之出槽，返 0。导入之签名于构建时与表核之。
- **桩之所为**（`宽降级原语。豫` 之「臂苹果原生桩」）：存 x15、x30 与 x0–x7，自本导入之槽取函数之址；惰绑而为零，则书符号之名于栈上之缓，呼 `dlsym(RTLD_DEFAULT, 名)`，存其果于导入之槽（不得则返 -1）；依类装 x 与 d 寄存器（二类各依次编号），栈参之区书零，`blr` 至目标，乃依果类书回。不触 x18。
- **符号之绑**：dlopen 在 libSystem 中，由 dyld 绑之；余在 AppKit 所载之框架中，初呼时以 dlsym 解之而缓于本导入之槽。`_dlsym` 自身由 dyld 绑于所留之末一导入槽（序 2047），惟模块导入惰绑之函乃绑之。Mach-O 写出器不改，犹惟链 libSystem。
- **64 位之值与双精度**：执行器纯为 i32，不用浮点指令；原生对象指针与双精度存于执行器常驻区之八字槽（见 `原生槽区。豫`），不交上层。整数与双精度位型，经执行器旧有之软浮点互易；窗口矩形、像素比、指针坐标、滚动量，依 1/64 定点换算（截断）。
- **macOS x86-64**：此诸导入绑为返 -1 之常量桩，执行器据之报“不支持”；他目标之“苹果”导入为陷阱桩。

## 六、执行器与 GC 之边界

依取消外调所定之边界：接口函数未绑适配，则编为带类型之 Wasm 导入，模块名即包名，字段名即函数名；值之形见取消外调之《导入形状定稿》。执行器实现下列 10 导入（“错”谓系统错误变体，“事件”谓输入事件变体）：

| 模块 | 字段 | 边界签名 |
| --- | --- | --- |
| 豫言操作系统显示 | 取得已授显示面 | 串 → 变〔资｜错〕 |
| 豫言操作系统显示 | 读取显示面尺寸 | 资 → 变〔整，整｜错〕 |
| 豫言操作系统显示 | 读取显示面像素比 | 资 → 变〔小｜错〕 |
| 豫言操作系统显示 | 提交像素画面 | 资，整，整，串 → 变〔｜错〕 |
| 豫言操作系统显示 | 等待输入事件 | 资 → 变〔事件｜错〕 |
| 豫言操作系统显示 | 设置文字输入区域 | 资，整，整，整，整 → 元 |
| 豫言操作系统字体 | 取得字体 | 串 → 变〔资｜错〕 |
| 豫言操作系统字体 | 字体文件长度 | 资 → 整 |
| 豫言操作系统字体 | 字体集序号 | 资 → 整 |
| 豫言操作系统字体 | 读取字体文件 | 资，整，整 → 变〔串｜错〕 |

- **值之表示**：显示面与字体为无公开构造器之资源，过边界为 externref，执行器依 WP8 之约编为低三位为 4 之句柄值，对应底层显示之句柄与字体文件之句柄；变体为元组（首项为构造器序号，自 0 起，其后为载荷）；像素比为双精度，执行器用与第五节同之整数换算助手，由物理、逻辑二整数造其位型；提交画面之时，字节串之内容本在执行器内存之中，依（地址，长度）交底层显示，不复制。
- **宿主选项**：原生入口于交程序之前，解析 `--授权显示面`、`--显示面后台`，书显示面之授权于初始句柄表；所占之参不交程序。
- **字体**：族名至文件之对照表置于执行器，依字体诺节适配中 macOS 之数项（无衬线：`STHeiti Medium.ttc` 第 1 面、`STHeiti Light.ttc` 第 1 面、`Arial Unicode.ttf`；衬线：`Songti.ttc` 第 6 面；等宽：`Menlo.ttc`），依次试开，惟用系统字体目录下此数文件；读取径用 pread，单次上限 16 MiB。
- **构建**：应用以 `yy豫构 构建` 径构建，不绑适配，显示与字体二接口自编为导入。路二自有之宿主支持清单（标此二接口为“宿主”），随取消外调第③步而定；届时若须经清单构建，则依其法补一原生清单。
- **他平台**：于 Linux 原生与裸机，显示之导入返“资源暂不可用”，字体之导入返“资源不存在”，程序照常报错而退。
- **协作**：执行器与降级器归 WP8 会话。第五节之原生函之呼、第四节之后端与此处之 10 导入，先以其设计交之过目；改动合入之前，由之于 pit-mac 上行双架构原生一致性。

## 七、macOS 后端

新模块（暂名 `苹显示。豫`，与 `苹系统。豫`、`苹底层。豫` 并列），经原生底层之分派，接于底层显示之 5 函数。

- **载入**：`dlopen("/System/Library/Frameworks/AppKit.framework/AppKit")`（连带载入 Foundation、CoreGraphics、QuartzCore、libobjc）；以下诸函声于苹果接口，初呼时由桩以 dlsym 解之：`objc_msgSend`、`objc_getClass`、`sel_registerName`、`objc_autoreleasePoolPush/Pop`、`CGColorSpaceCreateDeviceRGB`、`CFDataCreate`、`CGDataProviderCreateWithCFData`、`CGImageCreate`、`CFRelease`。选择子与类，初用时查定，存于对象表。
- **自动释放池**：每取事件、每提交画面，各裹以一层 `objc_autoreleasePoolPush/Pop`，以免所返之临时对象愈积愈多。
- **应用与窗口**：`NSApplication sharedApplication`、`setActivationPolicy:`（常规；面居后时亦常规，惟不激活，俾电脑操作之器得之）、`finishLaunching`；`NSWindow initWithContentRect:styleMask:backing:defer:`（标题栏、可关闭、可最小化，首版不可改尺寸）、`setReleasedWhenClosed:NO`、`setTitle:`（显示面名）、`center`、`makeKeyAndOrderFront:`、`activateIgnoringOtherApps:`；内容视图 `setWantsLayer:YES`，图层之 `contentsGravity` 设为 `resize`（其字符串以 `NSString stringWithUTF8String:` 造之，以避数据符号之导入）。显示面后台时不激活，以 `orderBack:` 置窗于他窗之后。
- **提交画面**：`CFDataCreate` 复制像素 → `CGDataProviderCreateWithCFData` → `CGImageCreate`（宽、高、8、32、宽×4、设备 RGB、不带透明度之 RGBX）→ 图层 `setContents:`；随即 `CFRelease` 三者（图层自持其图像）。随即 `CATransaction flush`；画与窗之尺寸不同，则图层伸之。
- **取事件**：己之队列空时，呼 `nextEventMatchingMask:untilDate:inMode:dequeue:`（任意事件、至多候四分之一秒、`kCFRunLoopDefaultMode`、出队）；逾时则察窗闭否（经辅助功能按关闭之钮，无事可得），并取文本视图待交之文；既取，先译为吾之事件，乃以 `sendEvent:` 交还 AppKit（标题栏之拖动、关闭按钮照常而行），然后查窗口之 `isVisible` 与 `isMiniaturized`，既不可见亦未最小化，则排入“已关闭”。无所在之窗之键事（应用未激时所注之键），亦属本窗；凡本窗之事，未译之前，先取文本视图待交之文。
  - 指针：`locationInWindow`（以点计，原点在左下）乘像素比、纵向翻转，成物理像素；键号取 `buttonNumber`。
  - 滚轮：`scrollingDeltaX/Y`；精确滚动（触控板）乘像素比，按行滚动者每行折 48 逻辑像素（同浏览器宿主）。
  - 修饰键：`flagsChanged` 依位之变发按下、抬起；窗口失焦时补发抬起（待办事项）。
  - 特殊键依 `keyCode` 译其名（回车、退格、方向键、制表、退出、删除、起首、末尾、翻页）。
- **输入法（不恃回调）**：于内容视图中置一透明之 `NSTextView`（`setAlphaValue:0`、不画背景）为第一响应者，系统输入法照常于其中组字。按键事件交还 AppKit 之前先分流：其不在组字（`hasMarkedText` 为否）而所按为特殊键，则截之而发按键事件，不转发；余键转发之，而后读其 `string`，非空且不在组字，则发一“文字输入”而后清之。故径键入、拼音上屏、⌘V 粘贴，皆走“文字输入”。`设输入区域` 移其框于所给之矩形（换为点、纵向翻转），候选框随之定位。组字中之预编辑文字不显示（与浏览器宿主同，待办事项）。
- **像素比与尺寸**：像素比取窗口之 `backingScaleFactor`；尺寸为内容视图之边框乘像素比。移至像素比不同之屏幕，尺寸随之而变。

1. **先测其速**（动手之前）：作一不开窗口之测速程序，令显示控件画待办清单于字节缓冲若干帧，分别于诺节与路二（预编、预编二）上计时。路二一帧若逾约 200 毫秒，先治其速（其法见第十一节），后接窗口。

3. **原生示例**：显示控件示例与界面自绘示例编为原生可执行文件，开窗口截图以核画面。
4. **人工验收（约君在场）**：拼音输入、增删、勾选、滚动、制表键轮换焦点、悬停变色、Retina 之清晰、关闭窗口。

## 九、他平台之法（俟后）

- **macOS x86-64**：原生函之桩依 System V 之约书之（xmm 寄存器传双精度）。
- **Windows**：PE 写出器已有依 DLL 导入之样板，user32、gdi32 可径导入。窗口类之消息处理函数用系统之 `DefWindowProcW`，输入消息于 `GetMessageW` 循环中先读后派发，故亦不须回调；画面用 `StretchDIBits`，文字用 `TranslateMessage` 之后之 `WM_CHAR`（输入法上屏亦经此），候选框之位用 IMM32。
- **Linux**：执行器为静态可执行文件，不 dlopen；径于 Unix 套接字上言 X11 协议（建窗口、PutImage、读事件），输入法（XIM）与 Wayland 俟后再议。
- **裸机**：virtio-gpu 与 virtio-input 驱动；同时开数图形应用之时，乃书合成窗口之程序。

## 十一、此轮不为与风险

**不为**（代码中留待办事项）：回调入口（NSView 子类、窗口委托、`NSTextInputClient`）；拖动改尺寸与改尺寸期间之重画；组字预编辑之显示；窗口图标、菜单栏、多显示面之窗口管理；显示面句柄入「等待」；macOS 以外之平台。

**风险**：

- **速度**：GC 程序行于执行器之上，小数走软浮点，结构与数组之指令经执行器之处理函数；显示控件每帧整幅重画（Retina 下 800×600 之窗口为 1600×1200，约 7.7 MB）。第八节第 1 步先量之；若慢，依次虑之：预编二；执行器为字节缓冲之填充与复制加快路径；显示控件惟重画所变之区域。
- **无包之可执行文件**：无 `.app` 包亦能开窗口，然须设常规激活策略，Dock 上所显者为可执行文件名。
- **隐形文本视图**：焦点、输入法切换、候选框之位等细节须实测；不可，则再为回调入口，改以自绘视图实现 `NSTextInputClient`。
- **运行循环**：惟于取事件时运行；画面提交之后若迟迟不呈现，则加 `CATransaction flush`。
- **取消外调之进度**：GC 侧依赖其带类型导入（第①、②步已合入，第③步定宿主支持清单与装载核对）；执行器之 10 导入须随其导入之形，形有变则同改。
