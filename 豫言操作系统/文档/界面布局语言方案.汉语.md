## 一、结论与已定事项

以下各条用户 2026-09-30 均已认可：

1. **形态：嵌入式库，不改编译器。** 元素是函数，样式与属性是值，都写在普通 `。豫` 文件里。2026-09-30 用编译器实测（`yy4_bs.wasm --type-check-only`）：附录的接口草稿加第十一部分的完整示例通过类型检查，带签名的视图函数里不必写「授以」。
2. **样式：挂载式。** 样式是类型为「样式」的值，挂在元素上。命名样式相当于 CSS 的类；同一元素内后写的覆盖先写的；文字属性沿树继承；「悬停时」「按下时」「焦点时」「禁用时」相当于 CSS 的伪类。选择器与跨元素的层叠这一轮不做，以后按需补“样式表”。
3. **布局：弹性盒为主。** 取 CSS 弹性盒与绝对定位的子集（React Native 的 Yoga 布局引擎也取这个子集，足够写应用界面），另加段落（行内富文本）与层叠；网格放第二期。长度是逻辑像素整数与百分比，像素比只在自绘后端出现。
4. **状态：模型—视图—更新。** 应用写模型、消息、更新（消息、模型 → 新模型）、视图（模型 → 界面树）。光标、滚动偏移、悬停、焦点等控件内部状态由显示控件库按元素标识保存。用户 2026-09-30 定：先做简单的，每次交互整棵重算视图，组件局部状态与增量计算以后再说（见八·六）。
5. **两个后端都做，之后接原生窗口。** 用户 2026-09-30 定：浏览器文树与自绘都要；这些做完，再让同一界面在路二的原生程序里跑，先写 macOS 的窗口接口，再写其他系统。先后见第十三部分：界面核心 → 文树后端与 HTML 生成 → 自绘（诺节窗口、浏览器 canvas）→ 原生窗口。浏览器里默认走文树：界面译成 HTML 与 CSS 交给浏览器，排版、字体、绘制、输入法都由浏览器做；canvas 自绘只作备选。
6. **新接口（用户 2026-09-30 同意）。** 静态样式写进生成的 CSS 文件，不必改接口；运行时算出的样式要装进页面，而网页文树的白册拒绝 `style` 属性。所以网页文树升 0.4.0，新增「添加页面样式规则」：宿主按白册把 CSS 规则装进一张可构造样式表，界面文树给每种样式生成一个类名。未采用的两种做法见九·二。
7. **记录更新写法先不加。** 用户定“先做简单的”。候选写法 `甲 易「组值」【「字段」者 值 也，…】` 复制命名元组、只改所列字段（见三·四）；没有它，更新模型时要把全部字段写一遍，用辅助函数凑合。
8. **名称。** 包「界面」「界面自绘」「界面文树」；元素、属性、样式的名字见第四、五部分与附录，用户可随时改。公开名一律取两字以上的专名，原因见三·三。

## 二、分层与数据流

```
应用：模型、消息、更新、视图（模型 → 界面树）；样式常量（相当于 CSS 文件）
  └ 界面库「界面」── 元素、属性、样式的类型与构造；元素标识；样式求值（继承、覆盖、状态变体）；
  │                    样式转 CSS、界面树转 HTML（构建工具、云工、浏览器里都能用）
      ├ 自绘后端「界面自绘」── 布局引擎（弹性、段落、层叠、绝对定位、滚动区）→ 显示树；标识→处理函数表
      │   └ 显示控件库（地基）── 绘制、控件行为、命中测试、焦点、主循环、文字量具
      │       └ 显示接口 0.2.0、字体接口、字体库（诺节 SDL 窗口；浏览器 canvas）
      └ 文树后端「界面文树」── 元素树差分 → 网页文树操作；样式 → 生成的 CSS 规则；委托订阅事件
          └ 网页文树、网页界面、网页事件（浏览器排版与绘制）
```

自绘后端的一次交互：

1. 显示控件库调用视图回调，交来「视图环境」：文字量具、交互状态（悬停、按下、焦点所在元素的标识）、视口宽高与像素比。
2. 界面自绘调应用的视图得到元素树，依次定标识、求样式、排版，生成显示树，同时记下“标识→处理函数”表。
3. 控件库画出显示树并等待输入，把输入变成交互事件（点击、文字改变、提交、焦点改变、按键），交给处理回调。
4. 界面自绘查表，把交互事件变成应用的消息，调更新得到新模型；控件库随后再调视图回调重画。

文树后端的流程相同，只是第 2 步把新元素树与上一棵比较，只把差别写进页面；第 3 步的事件来自网页事件的委托订阅。

## 三、语言形态

### 三·一 三种做法

| 做法 | 写法 | 对编译器的要求 | 长处 | 短处 |
| --- | --- | --- | --- | --- |
| 甲、嵌入式库（建议） | 普通 `。豫` 文件：元素是函数，样式、属性是值 | 无 | 界面与应用状态在同一个程序里，事件处理直接产出应用的消息；类型检查兼做样式检查（样式名写错、值的类型不配都报错）；复用可借函数、条件、列表与模块 | 比 HTML 多些 `「列」【】` 与 `于`；多态处偶尔要标注类型 |
| 乙、新文件种类，如 `名。界面。豫` | 豫言语法，编译器另作解释 | 与着色语言同样的一套：模块查找、翻译器、构建集成、保留后缀 | 可在构建期检查结构、抽出静态样式 | 界面要读写运行时状态，最终仍须译回豫言函数；多一套规则要维护 |
| 丙、二者结合 | 库，外加一种样式表文件 | 只对样式表做乙那一套 | 静态样式可在构建期生成 CSS | 动态样式仍走运行时，两条路并存 |

着色语言另立文件种类，是因为着色程序在 GPU 上运行，要译成 WGSL 或 MSL。界面代码与应用在同一个 Wasm 程序里运行，用库就够了。

### 三·二 写法约定

- 元素写作 `元素 于 样式列 于 内容`；可交互的控件多一个属性列：`元素 于 样式列 于 属性列 于 内容`。
- 样式列与属性列都写成 `「列」【…】`，空的写 `「列」【】`。样式列里命名样式与单条样式可以混写：`「列」【「主按钮」，「伸展」于「1」】` 相当于 `class="主按钮" style="flex-grow:1"`。
- 界面树按应用的消息类型参数化，类型写作 `「界面」于「待办消息」`。属性直接带消息：`「点击时」于「添加」`、`「输入时」于「改草稿」`；带参数的消息构造器可以直接当函数传。
- 样式是单态的值（类型「样式」），能存进组值与列表，也能由函数算出，所以主题就是普通数据。

### 三·三 已实测的类型行为与取名规则

2026-09-30 用编译器对接口草稿与示例实测所得：

- 视图函数有签名时（结果类型为 `「界面」于「待办消息」`），检查模式把期望类型一路传进列表的每一项，`「按钮」于「列」【「主按钮」】于「列」【「点击时」于「添加」】于『添加』` 不必写「授以」。`「态射」于「条目们」于「条目视图」` 的隐参由变量与顶层定义推定，也不必写。
- 用「虑」绑定一段界面时，绑定处没有期望类型，要标注：`虑「头部」者（「界面」于「待办消息」）也 … 而 …`，或者写成带签名的顶层函数。多态函数的实参若是复合式（如 `「长度」于（「滤」于 …）`），先用「虑」绑定成变量；这是语言现有的限制（见 `LOCALAGENTS.md`）。
- **库的公开名会劫持应用「鉴」里同名的模式变量**；函数参数与「虑」绑定不受影响。实测：库导出「文」以后，应用写 `有（「改草稿」于「文」）则 …` 就报“函数应用的隐式参数无法完全确定”。所以界面库的公开名一律取两字以上、不常用作变量的专名（纯文、文片、带键、空元素、色码、宽度……）；显示控件库也照此取名，已与地基会话约定。

### 三·四 语言缺口

方案不需要新语法。有一处可选的补充，用户 2026-09-30 定先不加，以后模型字段多了再议：

**记录更新** `甲 易「组值」【「字段」者 值 也，…】`：复制命名元组甲，只改所列字段，类型与甲相同；所列字段须是甲的字段，且类型相符。前端把它展开成 `虑 临 者 甲 而「组值」【各字段取新值或 临 中 字段】`，只动语法分析与类型检查（按甲的类型补全其余字段），代码生成不变；改的是编译器，要完整自举。用处：模型—视图—更新的模型常有十来个字段，每次更新都要全写一遍（示例的「换条目」就是为此写的辅助函数）；界面库内部的计算样式记录也用得上。有了它，示例的一支可以写成：

```yuyan
有（「改草稿」于「文」）则（「旧」易「组值」【「草稿」者「文」也】）
```

### 三·五 与 HTML/CSS 的关系

界面语言是 HTML/CSS 一个子集的另一种写法，两者之间是单向的嵌入：每个界面都能译成同义的 HTML 加 CSS（文树后端就是这个翻译），反过来只有落在子集里的 HTML/CSS 才能译回。

- **界面没有的**（举例）：浮动、行内块、表格布局、外距折叠、fixed 与 sticky 定位、网格（第二期补）；选择器、特指度与伪元素；em、rem、calc；阴影、渐变、变换与动画；任意标签与任意脚本。
- **HTML/CSS 没有的**：类型检查、元素标识与键、消息与模型—视图—更新、由函数算出的样式与主题。
- **语义以翻译为准**：布局规则取 CSS 的定义。除文字断行的细节外，同一界面在自绘里排出的矩形应与浏览器排出的相同。所以浏览器可以当自绘布局引擎的参照实现：随机生成界面树，译成 HTML/CSS，在无头 Chrome 里用同一个字体文件（`@font-face`）排版，比较各元素的矩形。

## 四、结构（HTML 的对应）

### 四·一 类型

```yuyan
「界面」立化「元类型」而「元类型」也。「：块级元素，按消息类型参数化：」
「行内」立化「元类型」而「元类型」也。「：段落里的行内片：」
「属性」立化「元类型」而「元类型」也。「：控件的属性与事件处理：」
「样式」立「元类型」也。「：一条样式或一组样式：」
「颜色」立「元类型」也。
「对齐方式」立「元类型」也。
```

### 四·二 块级元素

| 写法 | 说明 | 文树里 |
| --- | --- | --- |
| `「竖排」于 样式 于 子列` | 纵向排列子元素，也充当普通的块 | `div`，弹性纵排 |
| `「横排」于 样式 于 子列` | 横向排列 | `div`，弹性横排 |
| `「层叠」于 样式 于 子列` | 子元素叠在同一块区域，后写的在上 | `div`，单格网格 |
| `「滚动区」于 样式 于 子列` | 纵向排列，内容超出时滚动 | `div`，`overflow: auto` |
| `「文字块」于 样式 于 文字` | 单一样式的一段文字，自动换行 | `div` |
| `「段落」于 样式 于 行内列` | 多样式的文字 | `p` |
| `「按钮」于 样式 于 属性 于 文字` | 按钮 | `button` |
| `「文本框」于 样式 于 属性 于 当前文字` | 单行文本框，支持输入法 | `input` |
| `「复选框」于 样式 于 属性 于 是否选中` | 复选框 | `input type=checkbox` |
| `「可点」于 属性 于 元素` | 让任意元素可点、可聚焦（按钮语义） | 元素加 `role=button`、`tabindex=0` |
| `「分隔线」于 样式` | 分隔线 | `hr` |
| `「留白」于 样式` | 占位的空白，配「伸展」当弹簧 | `div` |
| `「空元素」` | 什么也不显示，供条件分支用 | 不生成节点 |
| `「带键」于 键 于 元素` | 给列表项一个稳定的键 | —— |

容器的子元素都是块级元素；文字要放进文字块或段落，这一点与 React Native 相同。

### 四·三 行内

| 写法 | 说明 | 文树里 |
| --- | --- | --- |
| `「纯文」于 文字` | 继承段落样式的文字 | 文本节点 |
| `「文片」于 样式 于 文字` | 另带样式的一段文字（加粗、变色、删除线） | `span` |
| `「链接」于 样式 于 属性 于 文字` | 可点的文字；跨行时每行一块热区 | `a`（`href="#"`，点击阻止默认） |
| `「断行」` | 强制换行 | `br` |

### 四·四 属性与事件

| 写法 | 用于 | 说明 |
| --- | --- | --- |
| `「点击时」于 消息` | 按钮、可点、链接 | 点击；焦点在上时按回车或空格 |
| `「输入时」于 函数` | 文本框 | 文字改变；函数由新文字得消息 |
| `「提交时」于 消息` | 文本框 | 按回车 |
| `「切换时」于 函数` | 复选框 | 函数由新的选中状态得消息 |
| `「按键时」于 函数` | 可聚焦元素及其祖先 | 控件没用掉的按键；函数返回 `「或可有」于 消息`，得「可无」时继续问上一层祖先 |
| `「聚焦时」于 消息`、`「失焦时」于 消息` | 可聚焦元素 | 焦点移入、移出 |
| `「占位」于 文字` | 文本框 | 空时显示的提示 |
| `「禁用」于 爻` | 按钮、文本框、复选框、可点 | 为阳时不响应、不可聚焦，并启用「禁用时」样式 |
| `「自动聚焦」` | 可聚焦元素 | 元素首次出现时取得焦点 |
| `「悬停提示」于 文字` | 任意元素 | 文树里写成 `title`；自绘留待办 |

### 四·五 标识

每个元素有一个标识：从根起，各级子元素的序号以 `/` 相连；带键的元素用 `键:键文字` 代替序号。根是 `0`，例如 `0/4/键:7/2`。标识跨帧稳定，用在三处：显示控件库按它保存光标、滚动偏移等控件状态；界面自绘按它从交互事件查回处理函数；文树后端把它写进 `data-yy`，事件载荷的「操作键」就是它。判断祖先按路径前缀（等于它，或以它加 `/` 开头）。

列表项要用「带键」：删掉中间一项后，后面各项的标识不变，焦点与控件状态跟着原来的条目走。

### 四·六 组件、条件与列表

- 组件就是函数：`「条目视图」乃化「待办」而（「界面」于「待办消息」）也。`
- 条件：`若 条件 则 元素 否则「空元素」`；样式的条件写 `「条件样式」于 条件 于 样式`。
- 列表：`「态射」于 条目们 于「条目视图」`；拼接用「附加」。

## 五、样式（CSS 的对应）

### 五·一 样式是值

```yuyan
「主按钮」乃「样式」也。
「主按钮」者「样式组」于「列」
  【「内距横竖」于「16」于「8」
  ，「背景」于「主色」
  ，「字色」于「纸色」
  ，「圆角」于「6」
  ，「悬停时」于「列」【「背景」于「主色深」】
  】
也。
```

- **单条与成组**：一条样式声明是一个「样式」值；「样式组」把一列样式合成一个，所以命名样式与单条声明能混在同一个样式列里。
- **覆盖**：同一元素上的样式按源码次序生效，后写的覆盖先写的，样式组就地展开。
- **状态变体**：「悬停时」「按下时」「焦点时」「禁用时」各带一列样式，叠加在常态样式之后；几个状态同时成立时，依悬停、焦点、按下、禁用的次序叠加，后者优先。悬停与按下也作用于祖先，与 CSS 相同：卡片里的按钮被悬停时，卡片也算悬停。文树后端把它们写成 `:hover`、`:focus-visible`、`:active`、`:disabled` 规则。
- **条件**：`「条件样式」于 爻 于 样式` 相当于按条件加减类名；「无样式」是空样式。
- **继承**：文字属性（字体族、字号、粗体、字色、行高、文字对齐、字间距、换行方式）沿树继承，其余属性不继承。这与 CSS 的继承属性一致，文树后端直接交给浏览器继承（按钮与文本框加 `font: inherit`）。
- **默认样式**：每种元素有一份默认样式，相当于浏览器的用户代理样式表，例如按钮的背景、内距、圆角与文字居中，文本框的边框与默认宽度，各可聚焦控件的焦点环（「焦点时」变体）。两个后端用同一份默认值，文树后端把它写进界面文树自带的基础 CSS。
- **主题**：主题就是一组颜色常量与命名样式。固定的主题写成一个模块（如 `样式。豫`，相当于 CSS 文件）；要在运行时换肤（如暗色），把主题做成组值 `「主题」即「组类」【「主色」乃「颜色」也，…】也`，样式写成函数 `「主按钮」乃化「主题」而「样式」也`，视图从模型里取当前主题。

### 五·二 选择器与层叠

| 做法 | 说明 | 长处 | 短处 |
| --- | --- | --- | --- |
| 挂载式（建议，第一期） | 样式挂在元素上，复用靠命名常量与函数 | 有类型检查；没有全局作用，改一处样式只影响用它的元素；两个后端都好实现 | 没法给别处生成的内容（如由标记文渲染出的文档）远程上样式；换主题要把主题传进视图 |
| 选择器与层叠 | 样式表加选择器（元素种类、类名、状态、后代）与特指度 | 最像 CSS；能统一给一整棵子树上样式 | 两个后端都要做选择器匹配与特指度；类名成了字符串，写错不报错 |

第一期只做挂载式。以后要给文档类内容统一上样式时，再补“样式表”：`「样式表」于「列」【「规则」于 选择器 于 样式列，…】`，选择器取元素种类、类名、状态与后代四种，与挂载式并存，挂载的样式优先。

## 六、布局模型

### 六·一 根元素与盒模型

视图返回的根元素，宽高取视口的宽高，相当于网页里让根容器 `height: 100%`；所以根下的元素可以用「伸展」分掉视口的剩余高度。内容超出视口时整页不滚动，要滚动的部分放进滚动区。

宽度与高度含内距与边框（`box-sizing: border-box`）。外距不折叠：竖排相当于 CSS 的弹性纵排，段与段的间隔用「间距」。最小、最大尺寸夹住算出的尺寸。

### 六·二 弹性（竖排、横排、滚动区）

按 CSS 弹性盒规范第九节的算法取子集：

1. **基准尺寸**：取「基准」；没有则取宽度或高度；再没有取最大内容尺寸（文字即不换行时的宽）。
2. **分行**：有「换行排」时按主轴可用空间把子元素分成几行，否则只有一行。
3. **伸缩**：剩余空间按「伸展」的比例分；空间不够时按「收缩」乘基准尺寸的比例缩；某项碰到最小或最大尺寸就冻结，其余重算，直到全部定下。自动最小尺寸取最小内容尺寸（文字即最长的不可断段），与 CSS 相同，所以按钮不会被挤得比最长的词还窄；滚动区的自动最小尺寸为零。
4. **交叉轴**：默认拉伸；也可靠起、居中、靠末，或按首行基线对齐。
5. **主轴放置**：先留间距，再按主轴对齐分配余下的空间。
6. **百分比**：包含块的尺寸确定时照算，不确定时当作自动。

默认值取 CSS 的：伸展 0、收缩 1、基准自动、交叉拉伸。文树后端因此不必另设，两边行为一致。

### 六·三 层叠

子元素都放在容器的内容盒里，各按「自身对齐」定位（默认拉伸），后写的在上；用于在卡片上叠角标、在图片上叠文字。文树里写成单格网格（`display: grid`，子元素 `grid-area: 1 / 1`）。

### 六·四 绝对定位与浮层

「绝对定位」的子元素不参加父容器的排列，相对父元素的内边距盒按贴边距离定位；没给贴边距离时放在起始角。文树后端给所有元素加 `position: relative`，使包含块就是父元素。

浮层（对话框、菜单、提示）放第二期：`「浮层」于 样式 于 子列` 可写在树的任意处，排版时提到根层，相对视口定位，文树里用 `position: fixed`。

### 六·五 滚动区

内容按“主轴不限长”排版，得出内容宽高；视口大小由外层的弹性排版决定。显示树的滚动区节点收视口矩形、内容宽高与按内容坐标排好的子节点；滚动偏移归控件库管。

### 六·六 网格（第二期）

取 CSS 网格的小子集：列轨道（固定像素、按比例 `fr`、随内容）、行随内容、行列间距、跨列。用于表格式的对齐，如文件列表、设置页。

### 六·七 单位与像素比

- 长度是逻辑像素整数，即 CSS 的 `px`；另有百分比（宽占、高占）与行高倍数（小数）。em 与视口单位留待办。
- 布局引擎内部用 1/64 逻辑像素的整数计算，与 Chrome 排版引擎 LayoutUnit 的精度相同，不用小数运算。
- 像素比只在自绘后端出现：显示树的矩形与字号都是 1/64 逻辑像素，控件库乘像素比后按边取整到物理像素，字形按物理字号栅格化，所以高分屏上的文字清晰；1 逻辑像素的线在二倍屏上占 2 物理像素。

## 七、文字与字体

- **属性**：字体族列、字号、粗体、字色、行高、文字对齐、换行、省略号与最多行数、字间距、下划线、删除线，见五·三。字重只分常规与粗两档；字体没有粗体字面时由字体库合成加粗。斜体留待办。
- **字体族与回退**：按族列依次找收有此字的字体，都没有就回退到「无衬线」，仍然没有就画方框（`.notdef`）。标准族名「无衬线」「衬线」「等宽」由字体接口按平台找到带中文的字体（如苹果上的华文黑体、宋体）。文树后端把三个标准族名写成 `sans-serif`、`serif`、`monospace`，其余族名照写。
- **空白与换行**：默认保留空格与换行符并自动换行，相当于 CSS 的 `white-space: pre-wrap`；界面文字多来自程序里的字符串，保留原样最直观。断行机会在空格之后、汉字与假名及全角标点之间、强制换行处；比一行还长的词按字断开。
- **中文排版**：字体库做简单禁则（行首不放 `。，、；：？！）】」』》` 等，行尾不放 `（【「『《` 等）；文树后端写 `line-break: strict`，由浏览器做同样的事。中西文之间自动加空（CSS 的 `text-autospace`）、标点挤压、中文两端对齐、竖排留待办。
- **行高与基线**：行高等于字号乘倍数，多出的空间上下平分（CSS 的半行距模型）；同一行里字号不同时按基线对齐。
- **富文本**：段落由纯文、文片、链接组成，整段交给文字量具一次排版；显示树的文字节点直接收排版结果绘制，量出的与画出的一致。
- **两个后端的差异**：文树用浏览器的字体与断行，自绘用字体库，所以同一界面在两边的字宽与换行位置会略有不同。布局规则相同，差异只来自字形。

## 八、控件与交互

### 八·一 模型—视图—更新

```yuyan
「运行界面」于『主窗口』于「初始模型」于「视图」于「更新」。
```

- **模型**：任意类型，常用命名元组。
- **消息**：应用用「立」声明，如 `「删除」立化「整数」而「待办消息」也。`
- **更新**：`化 消息 而化 模型 而 模型`。可以直接调宿主函数（如写文件），耗时的调用会卡住界面；异步任务、定时与网络结果（订阅）留待办。
- **视图**：`化 模型 而（「界面」于 消息）`，是纯函数，每次交互之后整棵重算。

另一种组织方式是可变引用加回调，即云工作台现行的写法：事件处理直接改引用、调页面接口。选模型—视图—更新，是因为视图是模型的纯函数，好测、好推理，消息也有类型；代价是更新时要重建模型，三·四的记录更新写法可以缓解。

### 八·二 控件集

- 第一期：按钮、文本框（单行，含输入法）、复选框、滚动区、链接、可点、分隔线。
- 第二期：多行文本框、单选框、下拉选择、滑块、图像、浮层（对话框、菜单、提示）、网格表格。
- 更后：选区与剪贴板、拖放、撤销、无障碍、动画。

### 八·三 受控控件

文本框每帧显示模型里的文字（示例里的 `「文本框」于 … 于（「模」中「草稿」）`）。用户输入后发「输入时」消息，应用把新文字存回模型；不存，文字就复原，与 React 的受控输入相同。光标位置与水平滚动归控件库，程序把文字改短时光标夹到末尾。复选框同理：显示模型给的选中状态，点击时发「切换时」于 新状态。

### 八·四 事件怎样变成消息

控件库交回的交互事件都带元素标识。界面自绘按上一帧记下的“标识→处理函数”表处理：

| 交互事件 | 查到的处理函数 |
| --- | --- |
| 点击(标识) | 该元素的「点击时」；复选框取「切换时」于（当前状态取反） |
| 文字改变(标识, 新文字) | 「输入时」于 新文字 |
| 提交(标识) | 「提交时」 |
| 焦点改变(新标识) | 旧焦点元素的「失焦时」与新焦点元素的「聚焦时」 |
| 按键(焦点标识, 键名, 修饰键) | 从焦点元素起沿祖先（按标识前缀）找「按键时」，第一个返回「可有」的为准 |

得到消息就调更新；查不到处理函数的事件丢弃。

### 八·五 焦点与键盘

- 可聚焦：按钮、文本框、复选框、链接、可点（未禁用时）。Tab 与上档加 Tab 按树序轮换焦点，由控件库做。
- 焦点在按钮、链接、可点上时，回车与空格触发点击；文本框里回车发提交。
- 「自动聚焦」：元素首次出现时取得焦点，由控件库做，文树后端调「聚焦节点」。由消息触发的程序性聚焦留待办。
- 焦点环：可聚焦控件的默认样式带「焦点时」变体，应用可以覆盖。
- 快捷键：在根元素或容器上挂「按键时」。键名用显示接口的键名（上、下、回车、退格、退出……）；界面库给出组值「按键信息」：键名，加上档、控制、交替、命令四个爻。

### 八·六 更新与差分

用户 2026-09-30 定：先做简单的，即 Elm 式；组件局部状态（React 的 useState、Bonsai 的 state）与增量计算以后再说。

- 每个消息：更新得出新模型，视图整棵重算，得到新元素树。组件是返回界面的普通函数，只收参数，不带状态。
- 自绘：整帧重新求样式、排版、重画，不做差分；光标、滚动、焦点、悬停按元素标识对回去，标识的作用相当于 React 的 key。
- 文树：新旧元素树按位置与键差分，只改变化的节点，文本框因此不丢焦点、不打断输入法（见九·二）。
- 以后按需加速，写法不变：模型没变（只是悬停、焦点变了）就复用上一帧的元素树；`「缓存」于 键 于 子树函数`，键与上一帧同一标识处的相同就复用子树与布局（相当于 Elm 的 lazy、React 的 memo）；长列表只排视口内的行（要控件库回报滚动偏移）；对比前后显示树只重画脏矩形；组件局部状态按元素标识存在运行时里；增量计算。

## 九、两个后端

### 九·一 自绘

视图回调里依次定标识、求样式、排版、生成显示树。元素与显示树节点的对应：

| 元素 | 显示树节点 |
| --- | --- |
| 带背景或边框的元素 | 「方框」：边框盒矩形、背景、统一边框、圆角，按需裁剪 |
| 单边边框 | 贴边的细方框 |
| 文字块、段落 | 「文字节点」：段落排版加片列 |
| 按钮、可点 | 「热区」（按钮热区），内含方框与文字节点 |
| 链接 | 每行的片段各一块「热区」（链接热区，同一标识） |
| 只带悬停或按下样式的元素 | 「热区」（区域热区，只参与悬停与按下） |
| 文本框 | 方框（外观）加「文本框节点」（内容区） |
| 复选框 | 热区（按钮热区），内含方框与勾（先画实心内方块，以后换成勾形） |
| 滚动区 | 「滚动节点」：视口、内容宽高、按内容坐标排好的子节点 |
| 分隔线 | 细方框 |

重画由控件库发起：交互状态或模型一变就调视图回调，整帧重算元素树、样式与布局。几百个元素的界面够用；长列表只排视口内的部分（虚拟列表）、段落排版的缓存留待办。

### 九·二 文树

浏览器本来就会读 HTML 与 CSS，所以在浏览器里把界面译成 HTML 与 CSS 交给它：排版、字体、绘制、输入法、滚动、选中复制、无障碍都由浏览器做，布局引擎、字体库、显示控件库在浏览器里一概不用。浏览器里剩下的只有应用逻辑（模型、更新、视图，编成 Wasm）、界面核心与文树后端的差分和事件，都很薄。

界面核心有一个纯豫言函数把界面树写成 HTML 字符串加 CSS 文本，构建工具、云工、浏览器里都能用。按页面种类有三种做法：

| 页面种类 | 做法 | 浏览器拿到的 | 要不要 Wasm |
| --- | --- | --- | --- |
| 纯静态（文档、官网页） | 构建时把界面树写成 `.html` 与 `.css` 文件，可与静态站、标记文两个库配合 | 普通 HTML、CSS | 不要 |
| 有交互的应用 | 首屏同上，或在云工上由服务端生成；Wasm 载入后接管这些现成的节点（hydration），之后只做差分更新 | HTML、CSS、`.wasm` | 要，只管交互 |
| 纯动态 | Wasm 启动后建出整个页面 | 空壳 HTML、CSS、`.wasm` | 要 |

- **元素到标签**：竖排、横排、层叠、滚动区、文字块、留白写成 `div`；段落写成 `p`；文片写成 `span`；链接写成 `a`；按钮写成 `button`；文本框与复选框写成 `input`；分隔线写成 `hr`。带处理函数的元素写 `data-yy`，值为标识。
- **布局交给浏览器**：样式属性一一写成 CSS 属性（五·三的右列）；弹性、换行、继承、伪类都由浏览器按 CSS 做。
- **样式怎样进页面**：静态样式（首屏用到的、顶层的命名样式）写进生成的 CSS 文件，由页面 `<link>` 引入或直接写在生成的 HTML 的 `<style>` 里；这是页面文件本身，网页文树的限制只管运行时的调用，不必改接口。运行时算出的样式与首屏没出现过的样式要在运行时补装，用户 2026-09-30 同意第 1 种做法：
  1. **采用：网页文树 0.4.0 新增「添加页面样式规则」。** 界面文树把每个元素展开后的样式（常态加各状态变体）序列化后取散列，得类名（如 `豫样-3f2a9c`），首次出现时装一条规则，状态变体装成伪类规则；元素只设 `class`。宿主把规则放进一张可构造样式表（`document.adoptedStyleSheets`）：属性限白册；值限定写法（长度、百分比、数、颜色、关键字），不许 `url()` 等函数；选择器只许一个类名，可带一个白册内的伪类；规则总数的上限取大（如十万条）。运行时算出的样式（按数据定的宽度、颜色）照样可用。
  2. 未采用：只靠构建期生成的 CSS 文件。它只能覆盖顶层的命名样式，运行时算出的样式事先生成不了，而且构建时要运行应用代码求样式值。
  3. 未采用：预制原子类（如 `宽度-200`）。值只能取有限的刻度，任意值写不出。
- **差分**：新旧元素树按位置与键比较：种类相同就改文字、类名、属性与控件值；种类不同就替换；子列表按键对齐，增、删、移动都用最少的文树操作。整棵重建会让文本框丢掉焦点与输入法组字，所以要做差分。
- **事件**：在容器上用「订阅界面事件」委托订阅 `click`、`input`、`keydown`、`focusin`、`focusout`；事件载荷的「操作键」就是元素标识，「值」是文本框的新文字；链接的点击在订阅策略里阻止默认。
- **受控文本框**：更新之后，模型里的文字与页面上的值不同、且不在组字中时，才用「设置节点值」写回（它不触发 `input` 事件）。
- **页面**：应用页面放一个容器元素并引入界面文树的基础 CSS；`「运行界面」` 的第一个参数是容器的 ID。
- **限额**：网页文树的句柄表现为 4096 项，界面文树给每个活元素留句柄时不够用；实现时按 AGENTS.md 放大百倍。

## 十、对地基的需求与对齐结论

2026-09-30 与“开发豫言图形界面：字体能力与控件布局库”会话对齐，下列各条对方均已接受，显示控件库按此实现。显示树的类型草稿（`库/显示控件/显示树。豫`，尚未提交）已按此写成：节点是「方框」「文字节点」「热区」「文本框节点」「滚动节点」，热区种类是「按钮热区」「链接热区」「区域热区」，段落参数里的对齐与换行是「段落对齐」「单行排版」等，全部用「立」构造器按位置取参；细节以实现为准。两边约定：显示树的名字只在界面自绘内部用，与界面库重名时由显示树改名。

| 项 | 约定 |
| --- | --- |
| 单位 | 显示树的矩形与字号都是 1/64 逻辑像素的整数；控件库乘像素比，左上、右下各自取整到物理像素，相邻方框不留缝 |
| 视图环境 | 视图回调收一个组值：文字量具、交互状态、视口宽高（1/64 逻辑像素）、像素比 |

| 交互状态 | 快照：悬停标识（指针下最内层的热区）、按下标识、焦点标识，没有时为空文字；三者变化时控件库重调视图 |
| 文字量具 | 输入片列（文字加文字样式：字体族列、字号、字重（常规、粗）、颜色、下划线、删除线、字间距）、段落参数（行高、对齐（起、中、末）、换行（换、不换）、最大行数与省略号）、最大宽（负数为不限）；输出「段落排版」：宽、高，各行的顶、高、基线、宽与片段（横坐标、宽、片序、字节起止），以及最小内容宽、最大内容宽。另有「字体度量」（上升、下降、行距） |

| 方框 | 背景、统一的边框宽与颜色、统一圆角（按覆盖度抗锯齿）、按矩形裁剪子节点 |
| 热区 | 标识、矩形、种类（按钮、链接、区域）、可否聚焦、禁用、自动聚焦、子节点，本身不画。命中、悬停、按下、焦点、点击、Tab 轮换、回车与空格触发点击归控件库；同标识的几块热区共享状态；区域种类只参与悬停与按下。控件库不另设带文字的按钮节点 |
| 文本框节点 | 标识、内容区矩形、当前文字、占位文字、文字样式、占位颜色、禁用、自动聚焦；只画内容区里的文字、占位文字与光标（水平滚动以露出光标）；输入法候选框由控件库定位 |
| 滚动节点 | 标识、视口矩形、内容宽高、子节点（内容坐标）；纵横滚动条由控件库画；焦点移入时滚到可见；视口外不画；偏移不回报 |
| 交互事件 | 点击(标识)、文字改变(标识, 新文字)、提交(标识)、焦点改变(新焦点标识或空)、按键(焦点标识或空, 键名, 修饰键)；修饰键是位掩码：上档 1、控制 2、交替 4、命令 8；按键只交回控件没用掉的 |
| 控件状态 | 按标识保存；标识在新一帧里消失就丢弃，它原是焦点时清空焦点并发焦点改变 |
| 自动聚焦 | 标识上一帧没有、本帧出现且「自动聚焦」为阳时取得焦点，照常发焦点改变 |
| 颜色 | 整数 RGBA（0xRRGGBBAA，直通透明度），另有辅助函数「颜色值」（红、绿、蓝、透） |
| 取名 | 两边的公开名与字段名都取两字以上的专名 |

## 十三、实施顺序与验收

用户 2026-09-30 定：两个后端都做，之后接路二的原生窗口。

1. **界面核心**：类型与构造、标识、样式求值、样式转 CSS、界面树转 HTML；单元测试核对样式组展开、覆盖、继承、状态变体与生成的 HTML、CSS 文字。
2. **文树后端**：网页文树 0.4.0 的接口改动（规范、宿主、适配、清单重生成），首屏 HTML 生成与接管、差分、事件。这条路用不着布局引擎，最快能在浏览器里用上。验收：待办示例在无头 Chrome 里合成点击、按键、文字输入后核对页面。
3. **自绘**：布局引擎用假量具（每字等宽，上升、下降固定）做单元测试：竖排堆叠、伸展与收缩、最小内容约束、换行排、各种对齐、百分比、内距与边框、绝对定位、层叠、滚动区的内容尺寸、段落断行与链接热区。对照测试：同一棵树经第 1 步译成 HTML 与 CSS，在无头 Chrome 里用同一字体文件排版，比较各元素的 `getBoundingClientRect` 与引擎的结果。然后接显示控件库，待办示例在诺节窗口与浏览器 canvas 上运行；自动冒烟（诺节后台窗口画一帧即退、无头 Chrome 合成输入），人工验收约用户在场（中文输入、增删、勾选、滚动、Tab、悬停变色、高分屏清晰度）。
4. **第二期**：网格、浮层、多行文本框、单选与下拉、图像、窄屏变体、样式表（选择器）。
5. **路二的原生窗口**（九·三）：底层显示 v2、GC shim、先 macOS 后其他系统的窗口后端，另写方案。

每步验证后只提交自己的路径并推送 yybs。地基会话做显示控件库，本线做界面各包，接口有变动时互相知会。

## 十四、本轮不做与待定事项

**本轮不做**（实现时在代码里留待办事项）：路二的原生窗口（九·三）；选择器与样式表；网格；浮层；多行文本框、单选、下拉、滑块、图像；动画、定时与异步订阅；程序性聚焦与滚动到元素；随视口变的样式（窄屏时）；em 与视口单位、小数长度；斜体；自绘的四边各异边框、阴影、透明度与圆角裁剪；中西文自动加空、标点挤压、两端对齐、竖排、双向与复杂文字；选区与剪贴板、拖放、撤销、无障碍；虚拟列表与排版缓存；组件的局部状态。

**先按以下取法，用户可随时改**：

4. 空白默认保留（`pre-wrap`）。
