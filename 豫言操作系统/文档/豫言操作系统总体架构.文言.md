# 豫言操作系统总体架构

状：架构与施行之案，二〇二六年九月二十八日审定。本篇为豫言操作系统之总览，代[统一接口方案](豫言操作系统统一接口方案.文言.md)（九月二十五日）与[底层接口方案](豫言操作系统底层接口方案.文言.md)（九月二十六日）中与之相违者，相违之目见第十四节；二接口逐条之规，仍以仓库根目录 `豫言操作系统接口/` 与 `豫言操作系统底层接口/` 二规范树为准。文中以【已成】【半成】【待为】标其成熟；数皆二〇二六年九月二十八日所计所测。审定之时依审阅之议修之：编译器唯存 Wasm 一后端，C 后端提于 WP1 而删；构建之器合为豫构一器；以原生为常用运行之方，Node 为备。汉语本见[汉语版](豫言操作系统总体架构.汉语.md)。

## 一、旨与则

豫言操作系统者，**有版之程序装载、执行与系统能力之约**，及行此约之宿主与系统也。其旨：使同一中文程序，于浏览器、云端 Worker、Windows／macOS／Linux 之桌面，及吾自造之裸机，得同一接口之义。

则六，前五既定，第六乃本篇所立运行之阵：

1. **豫言为先。** 编译器、运行时、垫层、平台后端、构建与验证之器，皆以豫言书之。非豫言之码，唯留于宿主环境所必自供者（浏览器与 Node 之 JavaScript 外壳），且渐减之。
2. **Wasm 为执行之通界。** 豫言应用、编译器、执行器自身皆经 Wasm；不复别立绕 Wasm 之原生之途以为终。
3. **编译器唯一后端：Wasm。** 不生 C，不赖 LLVM、clang、外部汇编器、外部链接器与 libc，不用 Wasmtime。今之 C 后端与 C 运行时，宜早删之（第十二节 WP1）；既删之后，路二之预编未成之前，开发之工具链以 WasmGC 之形行于 Node。
4. **接口二层，束其腰。** 应用之面用有 GC 之“豫言操作系统接口”，平台之面用无 GC 之“豫言操作系统底层接口”；每平台唯实现底层接口一次。
5. **能即授。** 应用所依之能力包皆必具；接口之实现与本次运行之资源授权，分而核之；宿主之 API 虽多，不尽示于程序。
6. **每商用平台，运行之路二，以原生为常。** 路一：Node.js、吾跨平台之 Wasm、一 JS 文件；路二：吾所径生之原生二进制，AMD64 与 ARM64 二指令集，用各平台正当之系统调用。路二既通，则为常用之方；路一为备，路二未通之前亦用之。

## 二、总览

自上而下，一程序所经之层：

| 层 | 路一（JS 之路） | 路二（原生之路） |
| --- | --- | --- |
| 源程序 | 高级模式（有 GC）之豫言程序 | 同左；又可行外来工具链所出之 WASI 程序 |
| 编译器 | 豫言自托之编译器：源码 → 类型检查 → 统一 ANF → Wasm 模型 → 标准 `.wasm` | 同左 |
| 程序之形 | WasmGC 模块 | WasmGC 模块；或 WASI 模块 |
| 应用之面之接口 | 豫言操作系统接口（GC 接口），能力包五十二 | 同左；WASI 程序用 WASI preview1 |
| 实现者 | JS 宿主：浏览器、Node.js、Cloudflare Worker | GC 垫层与 WASI 垫层，与执行器同为豫言底层模式之程序 |
| 平台之面之接口 | 无：JS 宿主径用 JS 环境之 API | 豫言操作系统底层接口：包六，函数四十五，三十二位整数，状态码 |
| 入操作系统 | JS 引擎任之 | Linux 径发系统调用；macOS 导入 libSystem；Windows 导入 kernel32 与 ntdll；裸机呼自造内核之服务 |
| 机器码 | JS 引擎任之 | 吾径生 ELF、Mach-O、PE 或裸机之像，AMD64 与 ARM64 |

观表之要：

- 编译器唯出标准 Wasm。有 GC 之程序出 WasmGC，底层模式之程序出唯含三十二位整数之 Wasm。
- **路一**行于有 JavaScript 引擎之处：桌面用 Node.js，网页用浏览器，云端用 Cloudflare Worker。JS 宿主径实现 GC 接口，**不经底层接口**。
- **路二**不须任何运行时：执行器（垫层）与平台后端合编为原生二进制。GC 程序经 GC 垫层，WASI 程序经 WASI 垫层，皆落于底层接口，乃由各平台后端发真系统调用。
- 二层接口不相依，亦不越级：应用不径呼底层接口；底层接口之用者，唯 GC 垫层与 WASI 垫层二者。

## 三、运行之阵：二路乘诸平台

| 平台 | 路一：Node.js＋跨平台 Wasm＋JS 文件 | 路二：自径生之原生二进制 |
| --- | --- | --- |
| Windows | 【待为】Node 宿主之适配 | 【待为】PE32+，x64 与 ARM64，导入 kernel32／ntdll |
| macOS | 【待为】Node 宿主之适配 | 【半成】Mach-O，x86-64 与 arm64，导入 libSystem，附代码签名：arm64 最小闭环（书、读、退）本机实试已通，降为位置无关；x86-64 未为 |
| Linux | 【待为】Node 宿主之适配 | 【半成】ELF64，x86-64 与 arm64，径发系统调用，静态而无 libc：最小闭环（书、读、退）二构实试皆通 |
| 裸机（自有之系统） | 无 | 【已成，唯 QEMU】ARM64 与 AMD64，内核与用户态皆豫言所生 |
| 浏览器 | 【已成】能力包二十有适配 | 无 |
| Cloudflare Worker | 【已成】能力包三十三有适配 | 无 |

二路之义：

- **路一（JS 之路）。** 所发者：一 `.wasm`（WasmGC）、一 JS 启动文件、一清单；机有 Node.js 即可行，同一 `.wasm` 通行诸平台。系统之能，由 JS 适配层经 Node 之文件、网络、进程诸 API 供之。**此 JS 文件乃 GC 接口之宿主适配，非底层接口之后端。**
- **路二（原生之路）。** 所发者：原生可执行文件，用者之机不须 Node 或任何运行时。按“操作系统 × 指令集”各出其一，凡三乘二为六，外加自有之裸机。二进制中含执行器与平台后端，后端用其平台**正当**之入系统之门：Linux 径发系统调用；macOS 与 Windows 无恒定之调用号，由系统库之导入表（第六节）。所发之形有二，出于同码（第四之四）：**原生宿主**，运行时装外来之 `.wasm`，亦能装合其所支特性之第三方标准模块；**独立可执行文件**，封程序于宿主之副本，一文件即可行。

**常与备。** 路二既通，乃为常用运行之方，用者之程序与吾开发之工具链皆然；路一为备，用于路二未通之前、无其原生二进制之平台，及须对照察误之时。

二路于同一程序，须给同一接口之义，以一致之验保之（第十节）。

## 四、编译与程序之表

### 四之一 前端之流【已成】

编译器以豫言自书（自托）。前端逐文件：解析、名称解析、类型检查、类型擦除、跨模块优化、闭包转换，得“闭包形式”。诸段依相依之序并行派之。闭包转换之后，全模块构**统一 ANF**（统一之中间表），乃授 Wasm 后端生 Wasm 模块。

### 四之二 唯一之后端：Wasm

编译器唯一后端，出标准 Wasm。语言之模二（第四之三），共用同一中文 Wasm 模型与二进制编码器：

| 模 | 何以择之 | 所出 | 状 |
| --- | --- | --- | --- |
| 高级模式（缺省） | 包描述不书编译模式 | 统一 ANF → 内存中之 Wasm 模块 → **径编为 `.wasm` 二进制**（WasmGC），含豫言所书之垃圾回收运行时；不经 WAT 之文，不呼汇编器；须宿主支 GC、异常处理与尾调用；对外唯一导入 `yuyan:gc-host/v1.call` | 【已成】 |
| 底层模式 | 包描述书 `「编译模式」者『底层』也。` | 闭包前之优化形式 → 唯含三十二位整数之 Wasm，不用标准库与垃圾回收 | 【已成】 |

机器码非编译器后端所出，乃路二之预编（寄存器之降，第六节）自 Wasm 生之；裸机之像即如是而得。

**已删之原生后端。** 前此编译器之缺省目标为 `--target=native`：由统一 ANF 生 C 源，乃由 clang 编之，与预建之 C 运行时相链，编译器自身、豫构与诸器皆赖之以行。WP1 已全删之，编译器唯出 Wasm，旧 `--target` 之选亦已删。

要：**路一与路二用同一 `.wasm`。** 同一 `.wasm`，可授 JS 宿主（路一），亦可授执行器（路二）。所异者唯“谁实现接口”，不在编译。

### 四之三 语言之模二

- 语言唯一，模乃**包之性**：`高级`（缺省，有垃圾回收，可用标准库）与 `底层`（无垃圾回收，不用标准库）。同一依赖之闭包须同一模，豫构解析包图时核之。
- 底层模式沿全部语法与类型检查，唯后端所受者寡：许整数、爻、单元、`若…则…否则`、`虑`、于整数常量之 `鉴`、一阶函数、自递归与尾调用（尾调用变为回跳）、函数内之可变格、外部调用之原语；不许元组、构造器、字符串、小数、异常、闭包、数组、引用类，越之则编译时报错，终不暗退于垃圾回收。诸值统为三十二位整数。
- 今底层之包十四：底层库及其示例、底层接口之规范包六、执行器 `客体二号`、`WASI库`、裸机之探针与样例库，及路二之原生样例“你好”。
- 底层模式代前此自造之括号式“低阶语言”；不复新造语言或领域专用之语。

### 四之四 路二之形与执行之二档

路二之可执行文件，乃同一豫言底层模式之程序，编为整数 Wasm，经寄存器之降与格式之书写器而得；其中次第为：平台后端（底层接口之函数四十五）、垫层二、执行器（含豫言所书之垃圾回收运行时）。其形有二：

- **原生宿主。** 命令行给 `.wasm` 之径，运行时装而行之。依《统一接口方案》既定，宿主按真导入处标准模块，不以豫言编译器之所出为唯一合法之入；导入由宿主明供之，否则装时拒之。
- **独立可执行文件。** 封 `.wasm` 于宿主之副本（附为数据段），得一文件。此唯移字节，不须编译。他日 AOT 既成，机器码亦并封之。

执行分二档，使路二速成闭环，而终及原生之速：

- **甲档：解释而行。** 执行器逐条解 Wasm。此裸机上已验之形（`客体二号`），用为正确之准。
- **乙档：预先编译（AOT）。** 编 WasmGC 程序为目标之机器码，与 GC 运行时、平台后端合链为一二进制，无解释器。此为终，亦路二中最巨之役（WP8）；先预编，后即编（JIT）。【半成】初版（“预编”）已可用：客体之每函数转为整数 Wasm 之函数（值犹居值栈，结构、数组、类型之转等繁令呼执行器之处理函数），并入执行器之模块，同经寄存器之降为机器码；尾调、间接之调、异常皆备，macOS arm64 上一致之探针十二项于预编之式皆逐字一致。说见 `豫言操作系统/裸机/客体二号/说明.文言.md` 之“预编”一节。

《系统编程语法方案》分全途为五段，今之所至如下：

| 段 | 事 | 状 |
| --- | --- | --- |
| A 统一之表 | 中文 Wasm 模型、文本读写、二进制编解与验 | 【已成】 |
| B 最小执行器 | 豫言所书、择子集之解释器 | 【已成】（`客体二号`） |
| C 自有预编 | 编 Wasm 为机器码，不须外部汇编器与链接器 | 【半成】唯整数子集，ARM64 与 AMD64 |
| D 托管与系统之能 | 覆今豫言所需之 WasmGC 等特性与宿主之服务 | 【半成】解释一子集 |
| E 独立自举 | 编译器与执行器皆经 Wasm 而生，前代预编后代，禁 clang、cc、as、ld 与 libc 而犹能自举 | 【待为】 |

生裸机之像与原生可执行文件之器（豫言系统、普通豫言验证、原生生成等），已改为 WasmGC 而行于 Node（WP1）；于 Node 上所构之像，与昔原生之器所构者逐字节同。工具链犹赖 Node，WP8 之后改为原生二进制。

## 五、接口二层与垫层二

### 五之一 豫言操作系统接口（GC 接口）

- 仓库根目录 `豫言操作系统接口/`，**纯源级之规**：唯接口包、纯声明与规之文；`。接口。豫` 之函数宿主供之，`。应用接口。豫` 之函数应用供之，其向以文件之后缀定。
- 【半成】凡能力包五十二，函数签名二百六十七，以能分五组：初六包（基础、启动、网页服务、文件、网络、显示）；浏览器之页（界面、文树、消息、事件、定时、储存、导航、环境、请求、事件源、编译、应用，及剪贴板）；跨宿主之器（时间、随机数、日志、文字规整、网址、网址定位、网址查询、密码摘要、口令派生、压缩）；服务端 HTTP 与凭据（入站、答复、转发、事件流、上游、授权服务、服务状态、环境文字、秘密文字）；持久与编译（持久事务、告警、独占、频道，命名持久服务，关系查询与数据库，对象存储，消息队列，定时事件，邮件发送，编译运行，隔离运行，平台资料）。
- 豫言之类型系统为规，WasmGC 唯其下投之影。Wasm 层今唯一通用之导入 `yuyan:gc-host/v1.call`（随需而增之外调之道，不冻）与一导出 `_start`。
- 装载之规：阙一包，或版与签名不合，即装载败；版须全等；依赖皆必具，授权另核。

### 五之二 豫言操作系统底层接口（无 GC）

- 仓库根目录 `豫言操作系统底层接口/`，亦纯规。规【已成】，实现有裸机后端、Linux 后端与 macOS 后端（后二【半成】，见六之三）。包六，函数四十五：基础十一、句柄十三、文件九，三者为核；网络七、终端二、进程三，为可选，平台无之则返五十八（不支）。
- 值唯三十二位整数，数据以（址，长）与出址传之，每函数返状态码；状态码取 WASI preview1 errno 之子集，号不改。记录之布（状态块、目录项、订阅、事件）沿 WASI。
- **柄即能**：初授者，启动时所预开之目录；路径皆相对于目录之柄，不得出其子树，越则返七十六。
- 无全局之“当前目录”“路径规整”“HTTP”“JSON”，此皆垫层以豫言为之，不入后端。首版单线，不含显示与输入，不含 HAL。
- **用者唯二**：GC 垫层与 WASI 垫层。应用不径呼之。

### 五之三 垫层二

| 垫层 | 所入 | 所出 | 状 |
| --- | --- | --- | --- |
| GC 垫层 | 豫言 GC 程序经 `yuyan:gc-host/v1.call` 所发之系统原语七十二 | 底层接口之呼 | 【半成】原语在 `客体二号/主机*.豫`；控制台之出（一至四号）、单调纳秒之时、文件原语二十八至三十九及七十二号已改经底层接口；Linux 与 macOS 上余文件原语经平台后端；裸机上余文件原语与子进程仍用执行器内文件系统及内核服务 |
| WASI 垫层 | 外来工具链（C、C++、Rust 等）所出之 WASI preview1 程序 | 底层接口之呼 | 【部分已为】`客体二号` 已识 preview1 之导入，接参数、环境、时钟、标准流与退出；余呼待补 |

## 六、路二：径生原生二进制

### 六之一 流水

底层模式（或经垫层之执行器）所出之整数 Wasm → **寄存器之降**（指令之择与寄存器之分，ARM64 与 AMD64 二后端，【已成】用于裸机与 Linux）→ **可执行文件之书写器**（ELF、Mach-O【已成】，PE【待为】）→ Apple 平台之**代码签名**（【已成】特设之签）。降依**目标之述**（操作系统 × 指令之集）生入口、导入之桩与内存增长之助；函数之降唯依指令之集。命令之器 `yy原生生成` 径以整数 Wasm 模块生 Linux 或 macOS 之可执行文件；与之客体模块，则嵌之于执行器，成行该 GC 程序之独立可执行文件。全程豫言之码，不呼任何外器。机器码由豫言中分字段之构造函数径编字节，核寄存器之号、立即数之域与位域，不书英文汇编之源。

### 六之二 诸平台何以入操作系统

后端与操作系统之间，唯一**入口之表**：此乃数据，非码。

| 能 | Linux（系统调用） | macOS（导入 libSystem） | Windows（导入 kernel32／ntdll） | 裸机（内核之服务） |
| --- | --- | --- | --- | --- |
| 时钟 | clock_gettime | clock_gettime_nsec_np | QueryPerformanceCounter、GetSystemTimePreciseAsFileTime | 滴答与墙钟之服务 |
| 随机 | getrandom | getentropy | BCryptGenRandom | 熵源未定 |
| 读写与位 | read、write、pread64、pwrite64、lseek | 同名之 POSIX 函数 | ReadFile、WriteFile、SetFilePointerEx | 控制台之服务与执行器内之文件系统 |
| 开与径 | openat2 加 RESOLVE_BENEATH、newfstatat、mkdirat、unlinkat、renameat、readlinkat、getdents64 | openat、fstatat 等 | NtCreateFile（RootDirectory）、NtQueryDirectoryFile | 执行器内之文件系统 |

- **macOS 与 Windows 何以由库导入。** Apple 不保系统调用之号恒定；Windows 之调用号随版而易。二平台所支之门乃系统库，故书写器必能生 Mach-O 与 PE 之导入表；此非赖 libc，所导入者唯操作系统自有之入口符号。Linux 有恒定之系统调用接口，径发之可也。
- **路径之编。** 接口皆 UTF-8；Windows 之路径乃 UTF-16，转之于后端。
- **越界之防，后端中最厚者。** Linux 有一举而成之 `RESOLVE_BENEATH`；macOS 之同类标志因版而异，Windows 无之，后端须逐段解径而拒其越。此处最易生安全之患，须专验之。
- **线性内存。** Wasm 线性内存映于向系统预留之一段虚址（`mmap` 或 `VirtualAlloc`），增则提交其页；内存之增乃语言之指令，代码生成任之，非接口之函数。
- **进程之入。** 书写器生入口之码：Linux 自初栈读参数与环境，macOS 与 Windows 经系统库取之，乃交底层接口之“取参数块”“取环境块”。
- **macOS 必位置无关。** 实试：arm64 之 macOS 不行无 MH_PIE 之可执行文件（内核径终之，零页四吉或一吉皆然），映像每行随机而移。【已成】降之“址式”：macOS 以名义之址皆书为“全局基址寄存器 x25 加偏移”，入口以 `adr` 取代码之始，加定之锚距而得 x25（数据段恒居映像之始后六十四兆字节）；导入经 dyld 所绑之槽呼 libSystem，返负一则经 `___error` 化为负 errno。苹果与视窗之 ARM64 皆保留 x18，故 ARM64 线性内存字节数之寄存器统用 x15。

### 六之三 GC 程序何以行于路二

有 GC 之程序编为 WasmGC，由**执行器**行之：先解释（正确之准），后预编（AOT，编 WasmGC 为机器码；运行时之垃圾回收器亦以豫言底层模式书之）。每隔离执行之域，各有托管之堆与根，回收行于用户态。裸机上之 `客体二号`，即此执行器之初版，今唯覆 WasmGC 之一子集（不验模块，不支 SIMD）。【半成】同一执行器已原生行于 Linux（arm64、x86-64）与 macOS arm64（甲档，解释而行）：运行之时，以目标之内建导入 `平台号`（降时绑为常量）择平台之实，他目标之导入降为陷阱之桩；程序名、参数与环境，于 Linux 读自 `/proc/self`，于 macOS 取自 `sysctl` 之 `KERN_PROCARGS2`；底层接口四十五函数有 Linux 后端（`openat2` 加 `RESOLVE_BENEATH`、`statx`、`getdents64` 等）与 macOS 后端（libSystem 之 `openat`、`fstatat`、`__getdirentries64` 等，导入之桩依 Apple 之约置可变之参于栈），GC 程序之文件原语经之访宿主之文件系统。普通探针与文件探针于 Linux 二构与 macOS arm64 之出，与 QEMU 裸机逐字一致（见十之三）。欲编译器自身亦行于路二，须覆其所用之全部 WasmGC、异常与尾调用之特性。AOT 与全 WasmGC，乃路二中最巨之役（第十二节）。

前此之原生 C 运行时（约四千七百行），乃同事之旧实现：自有垃圾回收器与系统之操作，然唯受豫言源经 C 所编之程序，不能装任意 Wasm。WP1 已随 C 后端而删之；路二之垃圾回收运行时，以豫言底层模式重书之（WP8）。

## 七、裸机之系统：吾自造之操作系统

【已成，唯行于 QEMU，未上真机】

- **引导。** ARM64 自造 ELF64 之头，于 EL1 建页表，乃 `eret` 入 EL0；AMD64 由 Multiboot，入长模式后落于 Ring 3。今唯以 QEMU 径装内核。
- **内核。** 机器字节由豫言源径生，不用汇编器与链接器；用户之码乃 Wasm 整数核经寄存器之降所得之机器码，二架构同一遍历。
- **内核之服务。** 号零至二十七，凡二十八：控制台之写字节与读字节；验收之核验与完成；入用户态；时钟之滴答；任务之号；用户之陷；任务之状与退出码；候、终止、复制、回收任务；发、收消息，问其来源与候消息；退出任务；设备配置之读与寄存器之读写；内存块之分与计；搬入、搬出静态区；墙钟之秒；中断之问。ARM64 用 `svc`，AMD64 用 `int 0x80`。
- **内存与隔。** 二兆大页，每任务各一页表，动态块之池三十二、各二兆；设备 DMA 以 SMMUv3 与 VT-d 隔之。W^X 未成。
- **任务。** 任务之槽二，每秒百次抢占轮转，任务之柄带代际；支复制、候、终止、回收；任务间之通，唯一三十二位邮箱加阻塞之收；有故唯终当前之任务。
- **执行器 `客体二号`。** 底层模式之豫言程序，约一万六千行，值皆三十二位整数；解释 WasmGC 之子集，自实现系统原语七十二（其五十四号未成），向内核导入服务二十（平台十五、块设备五）。装载之窗四百四十八 KiB，盘上之程序至多四 MiB，经复制任务原地重启，可多实例；不验模块。
- **存储与终端。** 用户态之 Virtio 块设备驱动，双区追加日志之文件系统；输入之环与 Ctrl-C；命令壳本身乃一寻常豫言程序，支文件之操作、运行程序、重定向、管道、环境变量与脚本。
- **限。** 任务之槽唯二，故一时唯一子进程；不支 SIMD；唯于 QEMU 之 TCG 单核一百二十八 MB 之配置验之。
- **与底层接口之系。** 裸机后端 `裸机底层*`（函数四十五）已成而验，其十五返“不支”；`客体二号` 与此诸模块已解其相依，GC 垫层之改接方始。

### 十之二 的：全验二分之内毕

所阻者，按已测之实列之：

1. **构建之迟，根在生 C。** 一五十九 MB 之单文件，授 clang 为全程序之优化，单线，不可并行。WP1 已删 C 后端，此项已消：诸器改以 `.wasm` 行于 Node，不复经 clang。
2. **运行器串行。** 普通豫言验证之主循环，于每试依次：编探针、行 ARM64、行 AMD64。八十四次互不相依之运行，于十八核之机，唯用其力约百分之十八。
3. **每试重付定本。** 每探针起一全 `yy豫构` 之进程（全仓包之发现）；每像皆重降执行器为机器码，而诸试之间所异者，唯所嵌客体之数据段。此二者乃自代码之构与总 CPU 时（约二千四百三十四秒，系统态与用户态相当）所推，**未分段剖之**，施行时先测而后改。
4. **要径有硬之下限。** 最迟之 AMD64 一试（QEMU TCG 单线）约需一分，任何并行不能压其下；或减其试之工，或受其限。
5. **超时之预算太紧。** 每次 QEMU 运行限六十秒（千二百 × 五十毫秒），机忙时最迟之试恒超时，而“首败即全止”使全验若坏。
6. **自举之链天然串行。** 三段相依。原生版约十分，不能容于二分；WP1 之后于 Node 上实测三级自举并重构豫构百零四秒，容于全验之预算，然犹逾快检之二分（又见第十三节 D4）。

设计：验分二级。**快检**（的在二分内）：类型检查、按所改之域择试、并行之 QEMU 冒烟；**全验**：自举、全量双架构与二路一致，许其久，然亦须并行、缓存与可增量。

### 十之三 一致之验之骨

【半成】骨：`yy原生一致性`（`豫言操作系统/裸机/原生一致性。豫`）嵌普通探针与文件探针于执行器，行于 Linux arm64 与 x86-64（非 Linux 之系统经 Docker）及 macOS arm64（本机），与 QEMU 裸机之验所用参照之出逐字相校；别有唯 Node 与原生之系统可行之原生探针（子进程自起其身、同进程 TCP 之回环），参照取自 Node 宿主。二〇二六年九月二十八日：Linux 二构二十四项、macOS 十二项皆一致。【待为】以豫言底层模式书接口一致之试，每能一组，于 Linux、macOS、Windows 与 QEMU（ARM64、AMD64）上所出须逐字相同；GC 接口适配一致之例，既行于路一之宿主，亦行于路二；WASI 之样二十二 C 程序，其出与退出码须与 Node 自带之 `node:wasi` 逐字同。试亦即接口之规样。

**WP7 WASI 续记（二〇二六年九月二十九日）：** `客体二号` 已直识 WASI preview1 函数名四十六，并于导入调用接豫言底层模式之分派；参数、环境、时钟、标准输出与错误输出、标准柄态、退出已通，标准流与时钟经底层接口。函数表分配后明清为零，以免本地函数误作导入。macOS ARM64 行既有 `你好.wasm`，出正文、程序名与浮点之果，依程序指定之三号退出；`环境.wasm` 于宿主环境清空后传一项，列之且以 `getenv` 取之。客体二号核型已过。余 WASI 函数仍返 ENOSYS，二十二样之逐字同尚待验。

**WP7 WASI 标准输入与随机续记（二〇二六年九月二十九日）：** `clock_res_get` 依平台报分辨率；`random_get` 经底层基础接口取随机字节，裸机无熵源犹返不支持；`fd_read` 于标准输入经底层句柄接口读向量，短读或文末则止。macOS ARM64 上 `记时.wasm` 出“分辨率 正”“随机 0 0 两次不同”，`大写.wasm` 易两行定输入为大写，`字数.wasm` 于同一输入报行二、词三、字节十三。客体二号核型已过。裸机随机之熵源与二十二样之双架构逐字同，犹待为与验。

**WP7 WASI 时钟精度与样例续记（二〇二六年九月二十九日）：** `clock_res_get` 改直读底层接口之 `取时钟精度`，由诸平台后端给其真精度；macOS ARM64 上 `记时.wasm` 之分辨率验犹过。无须增呼，`计算.wasm` 尽出素数、排序、二叉树、数学函数、八皇后与 SHA-256 之果，以零号退出；`回声.wasm` 于两行定输入出大写、二行与十一字节，亦以零号退出。此惟验本机之出，二十二样跨平台逐字对照犹待成。

**WP7 WASI 文件续记（二〇二六年九月二十九日）：** `客体二号` 以底层接口行预开根目录、`path_open`、文件读写与关闭、柄及路径状态、寻址、目录读取；底层状态块与目录项沿 WASI 布局，返状态块前清所增权限填充位。macOS ARM64 上 `猫.wasm` 读既有文本，与源卷逐字同；无卷则报错，以一号退出。`目录转储.wasm` 列二项及其四十四、四十一字节之长，与源卷同。向量数之限增至十万二千四百。权利继承、高位、非阻塞旗，及余文件诸呼与跨平台逐字对照，犹待成。

**WP7 WASI 文件变更续记（二〇二六年九月二十九日）：** `path_create_directory`、`path_remove_directory`、`path_rename`、`path_unlink_file` 已径接底层文件接口；`fd_datasync`、`fd_sync`、`fd_filestat_set_size` 与非阻塞之设，亦接底层句柄接口。`文件测试.wasm` 于一次性 Linux ARM64 与 x86-64 容器中成建目录、万字节读写、追加、寻址、列目录、改名与删，两架构皆以零号退出，标准出经 `cmp` 验逐字同。其固定 `/测试` 之径惟改临时容器。余 WASI 文件诸呼与二十二样之全验，犹待成。

**WP10 原生快验续记（二〇二六年九月二十九日）：** `yy原生一致性` 增 `--只验 名`，造程序前依探针之名筛之；无合者报错而止。macOS ARM64 上取 `--只验 盘-文件`，二依赖探针皆过；QEMU 二架构同组亦过。文件一之修改时刻改验非负，使裸机零值与原生真时共用一参照。全套快验之时限及 Windows、arm64 CI 之器，犹待验收。

## 十四、与旧文之系及已知之违

- 《统一接口方案》既立“桌面双宿主”（JS 加 Node，与原生宿主），并要原生宿主能装第三方标准模块；本篇沿此二者。彼书原生宿主“由 LLVM 原生后端发展而来”，并列 Wasmtime 之器之清退为后事；本篇改为：路二不经 LLVM 与 C，自径生机器码与可执行文件，Wasmtime 之器至 WP1 并删。
- 《底层接口方案》第十一节书落地之途为“待定，三择一，议 A”。本篇定为 A，并明排 B（译为 C 或 LLVM IR）与 C（任一 Wasm 引擎加薄胶）。
- 《接口总纲》“首批目标”一栏书 Node.js 与原生，实唯浏览器与云工有适配。
- 《未决事项》中“十包”“装载未成”之说已过时。
- `客体二号/说明.汉语.md` 之导入之数与控制台改接之状后于代码。
- 版本之要“全版相等”与“唯增函数”并存，今无兼容之制；须补于版本之规。
- 云仓之 AGENTS.md 与云仓构建，犹依“构建之器二”与原生之器而书，须依语言仓改书之。
- 《语言技术规范》所述定于提交 `4cdeca11` 之基线，方案之“执行约束”未依原样而成（今为包描述之编译模式）。
- 裸机验证之构建，于若干情形而崩（编译器 GC 初堆不足，须设环境变量以避）；普通豫言验证中最迟之 AMD64 一试，机忙则超时。

## 十五、名义

- **GC 接口**：豫言操作系统接口，有垃圾回收之应用之面。
- **底层接口**：豫言操作系统底层接口，无 GC 之整数束腰。
- **垫层**（shim）：以一种接口译为另一种接口之一层代码；GC 垫层与 WASI 垫层。
- **执行器**：行 Wasm 之程序；裸机上之 `客体二号` 为其初版。
- **后端**：于某平台实现底层接口之实现包（Linux、macOS、Windows、裸机各一）。
- **入口之表**：后端与操作系统间之数据表：系统调用之号，或系统库之导入符号。
- **柄**（句柄）：平台所颁之非负整数，亦即能。
- **路一／路二**：第三节所定运行之二路。
