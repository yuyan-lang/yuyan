# 豫言操作系统统一接口方案提要

稿修于二〇二六年九月二十五日，为架构及前贤之考；公接口之草案，另见[接口规范文言稿](豫言操作系统接口规范.文言.md)。已定以包立豫言能力之组，凡所依者皆必需；以豫言类型定接口之义，网页汇编 GC 则为向下之映。macOS、Linux 当并设二宿主：一以 JS 加 Node/V8 为之，一以 LLVM 原生后端及豫言原生运行时为基，另成网页汇编 GC 执行之链；二者皆为正途，同载豫言客体。原生宿主又当载他家合标准之客体，其发行包不含 Wasmtime。Windows 可后接。详制、验收及所据，见[汉语稿](豫言操作系统统一接口方案.汉语.md)。下述接口之文乃拟式，未谓今编译器已能读之。

## 宗旨

豫言操作系统者，程序所需之载入、施行、取系统之能，约为一体，按版而定。桌面、裸机、浏览器及云工，各依其地而成之。桌面二宿主分行而同守豫言接口之义：JS 宿主托 Node/V8；原生宿主承既有 LLVM 编译及原生运行时，须另备标准网页汇编 GC 之验证、装载、执行或编译。今 LLVM 原生路仅能编豫言源码，不可混称已能载任意网页汇编 GC。通用执行器当循标准验客体之字节、型、导入及指令，不得以豫言所出为独许。豫言程序若接口之版及所授之能皆合，则其接口义当同；不合者于载入之际明告。他家标准客体不必求豫言接口，惟所求导入须有同名同型之供者。

豫言源码与统一正则，主语言之义、类型与优化；其内部名号不足为天下共守之二进制约。别立 `。接口。豫`，循旧豫言之语法而明接口之型、误、资源、异步与权；版载 `。包。豫`。再降为中文网页汇编中介及标准 `.wasm` 导入导出，由豫言编码器生字节，不待 WAT。宿主乃按约接设备与系统，并备执行之器。

## 所守之界

豫言接口公开之约，以豫言类型为本。字节、记录、异类及资源之义，俱由接口定；借用、保留、释放、失效与重入，皆须载明。客体任造值，不得因此得权；宿主必验之。常误以有型之结果还之；非法之器于验证时拒之。通用客体之指令与型，则以网页汇编标准为准。

今有 `yuyan:gc-host/v1.call` 引用之桥，可供豫言向下映射之用；此桥乃可选宿主导入，非天下网页汇编 GC 客体之必备。其形制属编译器与执行器之事，不先决接口之义。接口之源可生客体封装、标准导入导出及各宿主桩；自定义段可记所求版本与权，然授予之权终由宿主裁定，且须核实二进制之导入与型。无豫言自定义段之标准客体，若指令合所宣之特性，导入亦可连，则当许行。

## 载入之序

先限字节，次验网页汇编与所需特性，次核导入之名与型，乃实例化、调用所定入口，终而归还资源。若客体求豫言接口，则更核其包版、签名及所授之权；他家标准 `.wasm` 不因无豫言桥而拒。无供者之导入，于载入之际明拒；未授之资源，不因可连而擅予。普通豫言 WasmGC 程序欲行于桌面自研宿主或裸机，尚须执行器备其 GC、异常、尾调用诸能；接口之立不能代此功。

## 次第

先使 macOS、Linux 各有 JS＋Node 与 LLVM 原生二宿主，均能载同一豫言客体，且各成可直行之包。原生宿主须先验标准网页汇编 GC，或释行，或以 LLVM 降为本机码；复按客体真导入之名与型连其供者，勿强求豫言桥与 `_start`。取他家工具所生、无豫言桥之真客体，于两地载行。继定受限接口声明，以输出字节及单调时钟为试；由一份接口生客体、宿主两端及标准字节，令同一豫言程序行于二桌面宿主及浏览器、云工，逐验失权与版异。二宿主各接窗格、画面与输入，以同一豫言图形程序验之。既有 Wasmtime 编译宿主之器，今可暂供组装与校验，不入桌面发行；替其构建所用之务后，方可删其源码。Windows 与裸机各循同约后接。既有异步任务及各宿主之实现，须合其完成、取消与事件寿命之义。接口之义可通定，而各地所备之能可异；程序所依之包皆必备，增能则另立包而组合之。

## 前贤之考

Inferno 以一语言及虚机，既行于实机，亦托于 Unix、Windows；其模块有明界。Drawbridge 以窄约隔库操作系统与宿主；MirageOS 合应用、所需系统库而成专用映像。网页汇编之 PLDI 论文定可验之执行界，WARDuino 示嵌入式之器可按导入连硬件。绑定生成器之研究又示：类型检查虽过，所生桥接仍当以异宿主实跑互校。今 Drawbridge 已终，MirageOS 续有新版，Inferno 仍有源码而官档旧，WARDuino 尚属研制；网页汇编之标准则续进。各篇原文、年份、今状及本方案之推论，见汉语稿第七节。诸研究各证其一端，未尝现成豫言全制。

所引外规及今工程之实情，俱录于汉语稿；此篇仅举纲纪。
