# 底层原生宿主

C 程序，以 Wasmtime C API 载[豫言操作系统底层原生后端](../底层原生后端/说明.文言.md)所编之 Wasm 模块，实其唯一之宿主导入 `底宿主.call(术码, 块址)`，以每术码译为真实之 POSIX 系统调用（`clock_gettime`、`open/read/write/close`、`openat` 一族等）。

**今状：已通，端到端自检皆过**——底层模式编译器原不导出 Wasm 内存之段一缺，今已补；`取初始句柄` 亦已改真 `open(".", ...)`。全说明见[底层原生后端之说明](../底层原生后端/说明.文言.md#状态已通端到端自检皆过)。

## 构建（手动，未接仓库构建之系统）

```sh
clang -O2 -I yy_wasmtime_c_api/include \
  豫言操作系统/宿主/原生/底层原生宿主/底层原生宿主.c \
  yy_wasmtime_c_api/lib/libwasmtime.a \
  -o yy底层原生宿主 -lpthread -ldl -lm
```

## 行之

```sh
./yy底层原生宿主 yy底层原生后端.wasm
YY_底层宿主_跟踪=1 ./yy底层原生宿主 yy底层原生后端.wasm   # 印每呼 底宿主.call 之术码、块址与返码
```

## Windows 之版（底层原生宿主Windows.c）

同目录之 `底层原生宿主Windows.c` 以 Win32 API（`CreateFileW`／`ReadFile`／`WriteFile`／`BCryptGenRandom`／`QueryPerformanceCounter` 等）实同一 `底宿主.call`，载**同一份** `.wasm`（此接口调度之约，与平台无涉，唯宿主侧译系统调用之部分因平台而异）。Windows 之 `HANDLE` 乃指针之大小、非若 POSIX 之 fd 为小整数，故宿主自持一张「小整数之柄 → HANDLE（目录则加其绝对路径）」之表，`打开`／`取路径状态`／`建目录`／`删文件`／`删目录`／`改名` 一类「相对某目录柄」之呼，靠拼其目录绝对路径而成（Win32 无 `openat` 一类之简易 API）。

**今状：书就，交叉编译与静态链接皆过，然未曾于真 Windows 编、行过。** 此机（macOS）无 Windows 之境，仓亦未带 Windows 版 Wasmtime C API 之库，故不能端到端而验；已为之最强静态之核：
- 以 `brew install mingw-w64` 装之 `x86_64-w64-mingw32-gcc`，对仓中自带（与平台无涉）之 `yy_wasmtime_c_api/include` 头文件，`-std=c11 -Wall -Wextra -c` 编之，无警无错。
- 以其产物配 `-lbcrypt -mconsole -municode` 全链（不含 Wasmtime 之库），除 `wasm_*`／`wasmtime_*` 一族之符（仓无 Windows 版 `libwasmtime`，理当解不出）外，**其余每一 Win32 API 之呼（`CreateFileW`、`BCryptGenRandom`、`GetActiveProcessorCount` 等）皆于 mingw-w64 真 Windows 之导入库中解得**——证函数签名、参数之型、库之属皆合，非凭印象妄书。

此较"看似应对"更实，然犹不足为"能行"之证。真接手时，寻一 Windows 之机（或装 Windows 版 Wasmtime 库之交叉链境），跑一遍 `底层原生后端/入口。豫` 之自检，乃此码见信前必补之末步。

`读目录`：与 macOS/Linux 之宿主同，未接（须 `FindFirstFileW`／`FindNextFileW` 持查找流之状态），恒返"未实现"（五二）。`读链接` 因 `FSCTL_GET_REPARSE_POINT` 一套颇繁且全未经验，姑返"不支持"（五八）。

### 交叉编译之核（供复现）

```sh
brew install mingw-w64
x86_64-w64-mingw32-gcc -std=c11 -Wall -Wextra -c \
  -I yy_wasmtime_c_api/include \
  豫言操作系统/宿主/原生/底层原生宿主/底层原生宿主Windows.c \
  -o /tmp/底层原生宿主Windows.o        # 无警无错
x86_64-w64-mingw32-gcc /tmp/底层原生宿主Windows.o \
  -o /tmp/底层原生宿主Windows.exe -mconsole -municode -lbcrypt
  # 所报当唯余 wasm_*/wasmtime_* 未定义之引；余 Win32 之符皆当解得
```
