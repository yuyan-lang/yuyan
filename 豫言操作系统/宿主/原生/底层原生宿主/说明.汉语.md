# 底层原生宿主

C 程序，用 Wasmtime C API 加载 [豫言操作系统底层原生后端](../底层原生后端/说明.汉语.md) 编出的 Wasm 模块，实现它唯一的宿主导入 `底宿主.call(术码, 块址)`，把每个术码翻成真实的 POSIX 系统调用（`clock_gettime`、`open/read/write/close`、`openat` 一族等）。

**现状：已打通，端到端自检通过**——底层模式编译器原先不导出 Wasm 内存段的缺口已修好，`取初始句柄` 也已改为真实 `open(".", ...)`。完整说明见 [底层原生后端的说明](../底层原生后端/说明.汉语.md#状态已打通端到端自检通过)。

## 构建（手动，尚未接入仓库构建系统）

```sh
clang -O2 -I yy_wasmtime_c_api/include \
  豫言操作系统/宿主/原生/底层原生宿主/底层原生宿主.c \
  yy_wasmtime_c_api/lib/libwasmtime.a \
  -o yy底层原生宿主 -lpthread -ldl -lm
```

## 运行

```sh
./yy底层原生宿主 yy底层原生后端.wasm
YY_底层宿主_跟踪=1 ./yy底层原生宿主 yy底层原生后端.wasm   # 打印每次 底宿主.call 的术码、块址与返回码
```

## Windows 版（底层原生宿主Windows.c）

同目录下 `底层原生宿主Windows.c` 用 Win32 API（`CreateFileW`/`ReadFile`/`WriteFile`/`BCryptGenRandom`/`QueryPerformanceCounter` 等）实现同一个 `底宿主.call`，加载**同一份** `.wasm`（这份接口的调度约定与平台无关，只有宿主侧翻译系统调用的部分因平台而异）。因为 Windows 的 `HANDLE` 是指针大小、不像 POSIX 的 fd 是小整数，宿主自己维护一张「小整数句柄 → HANDLE（目录再加绝对路径）」的表，`打开`/`取路径状态`/`建目录`/`删文件`/`删目录`/`改名` 这类「相对某目录柄」的调用靠拼接该目录的绝对路径实现（Win32 没有 `openat` 一类的简单 API）。

**现状：写就，交叉编译与静态链接皆过，但从未在真正的 Windows 上编译或运行过。** 本机（macOS）没有 Windows 环境，仓库也没带 Windows 版的 Wasmtime C API 库，所以做不到端到端验证；已经做到的最强静态核实是：
- 用 `brew install mingw-w64` 装的 `x86_64-w64-mingw32-gcc`，对着仓库自带的（平台无关的）`yy_wasmtime_c_api/include` 头文件，`-std=c11 -Wall -Wextra -c` 编译，零警告零错误。
- 把编译产物与 `-lbcrypt -mconsole -municode` 一起完整链接（不含 Wasmtime 库），除了 `wasm_*`/`wasmtime_*` 一族符号（仓库没有 Windows 版 `libwasmtime`，预期解不出）之外，**其余每一个 Win32 API 调用（`CreateFileW`、`BCryptGenRandom`、`GetActiveProcessorCount` 等）都在 mingw-w64 真实的 Windows 导入库里解析成功**——说明函数签名、参数类型、库归属全部对得上，不是凭印象瞎写的。

这比"看起来应该对"要扎实，但仍然不构成"能跑"的证据。真正接手时，找一台 Windows 机器（或装了 Windows 版 Wasmtime 库的交叉链接环境），把 `底层原生后端/入口。豫` 的自检跑一遍，是这份代码被信任前必须补的最后一步。

`读目录`：与 macOS/Linux 宿主一样未接（需要 `FindFirstFileW`/`FindNextFileW` 维护查找流状态），恒返回"未实现"（52）。`读链接` 因 `FSCTL_GET_REPARSE_POINT` 一套较繁且完全未经验证，姑且返回"不支持"（58）。

### 交叉编译核实（供复现）

```sh
brew install mingw-w64
x86_64-w64-mingw32-gcc -std=c11 -Wall -Wextra -c \
  -I yy_wasmtime_c_api/include \
  豫言操作系统/宿主/原生/底层原生宿主/底层原生宿主Windows.c \
  -o /tmp/底层原生宿主Windows.o        # 零警告零错误
x86_64-w64-mingw32-gcc /tmp/底层原生宿主Windows.o \
  -o /tmp/底层原生宿主Windows.exe -mconsole -municode -lbcrypt
  # 报错应仅剩 wasm_*/wasmtime_* 未定义引用；其余 Win32 符号应全部解析成功
```
