# 豫言操作系统底层原生后端

[豫言操作系统底层接口](../../../../豫言操作系统底层接口/总纲.汉语.md)在 macOS／Linux 上的后端。底层模式的 Yuyan 包，编译为标准整数 Wasm 模块（`yy底层原生后端.wasm`），设计上唯一的宿主导入是统一调度点 `底宿主:call(术码, 块址) → 状态码`；由 [底层原生宿主](../底层原生宿主/说明.汉语.md)（C，用 Wasmtime C API）加载并实现这个导入。

## 状态：设计与骨架已完成，被一处编译器缺口挡住，未跑通

**结论先说：这条路线（把底层模式编译成标准 Wasm、配一个用 Wasmtime 的原生宿主）目前跑不通，不是因为写错了什么，是因为豫言编译器的底层后端现在没有办法让 Wasm 模块导出它的线性内存。**

### 具体是什么问题

- `块`（本包用来在 Yuyan 和宿主之间搬运调用参数的共享暂存区）要求宿主能读写 guest 的线性内存。Wasmtime（以及任何通用 Wasm 引擎）只能通过**导出**访问 guest 的东西；豫言编译器的底层后端目前编译出的模块**只导出函数**，见 `库/编译器核心/网页汇编核心/二进制生成。豫` 的 `生成网页函数二进制`：导出段每一项固定写死 `种类=0`（函数），`网页导出`这个类型本身也只有 `(名字, 索引)`两个字段，没有"种类"，没法区分函数导出和内存导出。这条编码路径是底层模式和高级／WasmGC 模式共用的核心基础设施（`网页汇编核心`），现在仓库里另一个并发会话正在对这一整块做后端改造（把 WasmGC 代码生成从 WAT 改成直接写二进制，一系列"后端改造第 N 步"提交），改这段代码风险和影响面都不小，本轮不动它。
- 实测：本包编译出的 `.wasm` 导出段只有一项（`启动`），确认没有内存导出；[底层原生宿主](../底层原生宿主/) 里 `wasmtime_caller_export_get(客, "memory", ...)` 因此永远找不到，任何需要读写 guest 内存的调用（几乎所有函数）都会拿到空指针，返回参数无效。只有完全不碰内存的部分（比如 `导出：启动` 本身的调用）能走通。

### 已经做完、可用的部分

- **`术码。豫` + `入口。豫`**：45 个接口函数里，基础（11）、句柄（13）、文件（9）共 33 个已经写出真实的调用侧代码（把参数写进共享的 256 字节 `块`，调用 `底宿主_调用`，读回结果）；终端／网络／进程按裸机后端同样的思路占位，返回不支持。类型检查、完整构建都过（`./yy豫构 类型检查|构建 豫言操作系统底层原生后端`），产出合法的标准 Wasm 模块。
- **[底层原生宿主](../底层原生宿主/底层原生宿主.c)**：C 程序，Wasmtime 加载模块、`底宿主.call` 的调度实现（对应 33 个术码，真实调用 POSIX：`clock_gettime`、`open/read/write/close`、`openat` 一族等），状态码按 WASI errno 子集映射。这部分逻辑是对的、独立于内存导出问题可复核；只是运行时因为上面那条 guest 内存访问不到，实际调不通。
- 自检用例（`导出：启动` 里的 `自检_*`，测时钟／平台／处理器数／标准输出／文件创建-写-关-开-读-比对-删）已经写好，一旦内存导出问题解决，直接跑就是端到端验证。

### 要接着做，需要什么

以下二选一：
1. **给底层后端加内存导出**：改 `库/编译器核心/网页汇编核心/二进制生成。豫` 的导出段编码，让声明了内存的模块除了函数导出外，也发一条种类=2（内存）、索引=0 的导出项；连带 `模块结构。豫` 的 `网页导出` 类型可能需要加"种类"字段（否则没法在同一张表里区分函数与内存导出）。这是编译器改造，需要与正在改这一块的会话协调，且要过一遍自举与 `逐字节比较` 一类的既有回归（改了共用的导出编码，任何引用这条路径生成模块的既有产物都要重新核对）。
2. **换一种不依赖内存导出的通信方式**：目前想不出能同时满足"传变长字节数据（路径、文件内容）"又"不需要宿主读写 guest 内存"的办法——Wasm 的函数调用边界只能传标量（i32／i64／f32／f64），传字节缓冲区本来就只能靠共享内存或者 GC 引用（后者是 WasmGC 的机制，底层模式没有）。所以现实中大概率还是得走第 1 条。

## 设计（供接手时参考，内存导出问题解决后即可验证）

- **术码**（`术码。豫`）逐个对应接口函数，宿主据此分派到真实的系统调用。
- **块**是 256 字节的共用暂存（地址 0），按接口函数原参数顺序，每参数 4 字节；有 `出` 参数的函数，结果由宿主直接写回 guest 内存对应地址，不经调用的返回值。
- 本包单线程、每次调用都同步完成才返回，共用一块暂存是安全的。
- `取平台` 也经宿主：宿主用 `#ifdef __APPLE__`／`__linux__` 报告自己是哪个平台（3／2），同一份 `.wasm` 两边都能用。

## 构建

```sh
./yy豫构 构建 豫言操作系统底层原生后端 --输出 /tmp/yy底层原生后端.wasm
```

配合 [底层原生宿主](../底层原生宿主/说明.汉语.md) 构建、运行；`YY_底层宿主_跟踪=1` 环境变量打开逐次调用的调试输出。
