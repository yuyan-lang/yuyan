# Node 宿主一致性验证

这是路一 Node 发行包的本机验收。先在仓库根目录构建 `yy双宿主构建.wasm`，再构建验证应用并运行驱动：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy双宿主构建.wasm --自动 节点 豫言操作系统/宿主/节点/一致性验证/应用 dist/节点一致性
node 豫言操作系统/宿主/节点/一致性验证/运行.mjs dist/节点一致性
```

驱动在本机启动 HTTP 服务并创建临时文件夹具，故运行环境须允许本机回环监听。它逐行比较标准输出和标准错误，检查文件写入及七项装载拒绝情形。张量计算用例在豫言里按规范容差判定浮点结果，只打印“通过/失败”或精确的整数结果；张量文件用例读取夹具 `甲/张量.bin`（100 字节）。期望输出分别存于 `期望输出.txt`、`期望错误.txt`；确认行为变更后才以 `--记录` 更新期望。2026-09-29 重建同一发行包后，macOS arm64（Node 26.3.0）、Linux arm64 与 x86-64（均为 Node 26.10.0）各通过 88/88 项；Linux 两架构在只读挂载仓库的容器内运行。同日加入张量计算与张量文件用例后共 121 项，macOS arm64（Node 26.3.0）通过 121/121；新版在 Linux 与 Windows 仍待验收。9 月 30 日张量计算接口升到 0.2.0，加入后端用例（驱动以宿主选项 `--张量后端 中央处理器` 运行，各平台输出因此相同）后共 122 项，macOS arm64（Node 26.3.0）通过 122/122；同日升到 0.3.0，加入跨步视图、新增逐元运算、按行累加与随机填充用例后共 130 项，通过 130/130；升到 0.4.0，加入混合专家与线性注意力用例后共 135 项，通过 135/135。
