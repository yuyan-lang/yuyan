# 传输控制协议共享胶水

`创建传输控制协议系统调用` 以 `取内存` 回调取得纯豫共享核心的线性内存。它把苹果固定参数系统库函数接入导入模块“苹果”，失败时立即读取同线程 errno 并返回负误码。函数涵盖套接字、绑定、监听、连接、接受、选项、读写、轮询、时钟与关闭。非苹果平台及外部函数接口缺失返回状态 58。

`创建传输控制协议能力` 接收共享模块字节，调用核心的初始化，并按原语 77–90 转交参数与复制主机、正文缓冲。网络算法、地址解析和句柄状态由共享豫言核心执行。内存导出名为“内存”，整数结果由“结果值”读取。

苹果 `fcntl` 与 `openat` 分别绑定系统已有的固定参数入口 `__fcntl` 与 `__openat`。长整参数以 BigInt 传入；路径地址取共享内存指针；`signal` 的处理函数地址保持原始指针值。[苹果系统源码](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/libsyscall/wrappers/open-base.c) 提供这两个固定入口的声明。读取原语 81 与 82 均保留原始字节。

`node --experimental-ffi 豫言操作系统/宿主/节点/传输控制协议系统调用。测试.mjs` 验证真实苹果套接字、负 errno、非阻塞标志、只读系统文件及信号入口。本轮探针通过。完整共享核心网络验收列入后续事项。

共享模块实例化提供 `目标.平台号` 为 3，并为其他平台的静态导入设置明确未提供桩。苹果绑定缺失时报告完整符号名。`传输控制协议共享。测试.mjs [模块路径]` 输出实际导入清单并验证回环监听、连接、任意字节读取和关闭，默认模块路径为宿主旁 `yy传输控制共享.wasm`。共享模块构建后运行这项回环验证。

应用宿主把标准库现有77–90传输控制签名接到本共享核心。`--允许源 http(s)://地址:端口` 按地址与端口授权TCP监听、TCP连接和数据报交换；来源全开放配置用于连接，监听使用显式来源登记。网络句柄由本应用登记，接受的句柄继承监听授权，应用退出时关闭登记的全部句柄。读取字符串和字节串都保留原始字节。

节点发行构建内联系统胶水与授权胶水，并在发行目录构建`yy传输控制共享.wasm`，应用同时复用原公共文件目录权。工具链打包也纳入胶水与共享核心。共享私导出另含数据报交换和当前纪元毫秒；数据报实现复用现数字地址、连接UDP和等待能力，公共176的原生装箱与Node转交使用同一私核。Unix毫秒复用公共116已有的底层墙钟纳秒和有符号除法，失败由绑定抛出错误。

后续事项：Linux及Windows的Node系统库绑定、完整应用网络consumer运行与性能验证。已有原生Linux数据报路径继续由原生执行器提供。采样及其他后端验收按各任务保留实际证据。
