# 节点终端输入

同步终端读键在进入原始模式后把既有 TTY 句柄恢复为阻塞，首字节到达前保持等待。转义键尾部临时使用非阻塞读取，读完恢复阻塞；单独 Escape 可以立即交给编辑器。读取返回零字节表示 EOF，首字节读取的 EAGAIN 作为操作错误传播。工具与应用宿主继续共用这份实现。

标准输入不是终端（管道、FIFO、普通文件）时没有原始模式可进，读取直接走文件描述符零：管道与 FIFO 借 Node 为 `process.stdin` 建的流句柄切换阻塞，普通文件的读本来就不阻塞。「听键」把句柄恢复阻塞后读一字节，到文件尾答无键；「瞥键」把句柄设成非阻塞后试读，暂不可读答无键，读完恢复阻塞。取走的字节交给壳的读行编辑，与原始模式一支相同（2026-10-24，议题 574）。

受控测试覆盖中文、方向键、输入继承和模式恢复，以及句柄阻塞切换、Escape 尾部暂缺、EOF 和首字节错误区分。管道与普通文件两种非终端情形另起子进程验证：管道里没有字节时「瞥键」立即答无键，「听键」阻塞等父进程写来的字节，管道关闭后答无键；普通文件按序取出字节，到文件尾答无键。延迟到达的转义序列尾部留待后续版本。

真实PTY中原壳逐键输入 `「回显」于「终端验证」` 输出“终端验证”，继续出现提示符。`「图形」` 已进入桌面调用，随后原始未绑定产物在公共文件接口失败。终端模块改为 `终端输入.mjs`，工具宿主与应用宿主共用，Node发行内联它；下一步须构建绑定公共文件、显示、字体的原壳发行，不能把当前回显成功视为GUI往返成功。

这是标准库既有终端原语的Node实现。非TTY返回进入失败，原壳走逐字节读的非终端一支（见上）；TTY保存原始模式并进入逐键输入，恢复时还原旧状态。宿主解码UTF-8、分离字符并保留同一读取块中的转义键序列，壳编辑、拼音和命令语义仍由豫言实现。宿主在程序正常返回或异常退出时恢复终端模式，工具链打包登记新增模块。

两项受控TTY测试通过，原控制台壳Wasm在源码宿主下使用非TTY输入，完成启动、显示提示和正常退出，原“进入终端原始输入模式未绑定”错误消失。完整实际TTY逐键输入、正式图形指令启停与原会话恢复尚待验证。

待办事项：跨读取块的转义序列、混合粘贴边界与读取暂不可用时的忙等待另补；当前原壳已在无按键时重复读取。此实现不证明图形能力已经授予工具宿主。
