# 网页行在

网页行在（提案 00043）是浏览器里的豫言操作系统实例：标签页就是行在（宿主常驻系统实例，提案 00039），开机壳是豫构交互，与裸机、宿主上的行在同一份程序。壳里每句豫言都在浏览器里编成网页汇编单元，再装进开机壳所在的进程运行。

## 组成

- `行在.html`：页面。页面终端显示开机壳的输出，按键原样送进开机壳的标准输入；点屏幕即可打字。页脚写语言仓提交号（站点发布时写在 `/操作系统/来源提交`），报问题时对得上版本。发布时改名为 `行在/index.html`。
- `行在.mjs`：取快照展开到内存文件系统，接上秘府，建进程表，起开机壳 `/工具/豫构。豫行 交互`（交互参数取 /系统/开机。数据。豫 的「交互参数」，缺省 --组字，同裸机开机壳；标准输入当终端；当前目录 /，共享缓存根 `/tmp/豫构缓存`，不起将作与行在；/系统/开机自启 每行一句作开头句）。
- `秘府.mjs`：秘府（站点私有文件系统，OPFS）的读入与增量写回，见下文“秘府”。
- `终端.mjs`：页面终端。只认回车、换行、退格、制表与常用的 CSI 序列（移光标、擦行、清屏），非 ASCII 的字占两格（同组字编辑器的「输入格宽」）；开机壳进了原始模式（组字）时每个键直接送，否则页面自己回显、处理退格，按回车才送一行（同终端的规范模式）。中文输入法上屏的字照送。
- `声音.mjs`：主线程侧的声音输出。持一个 AudioContext 与声音工作件；每条流一个与工作线程共用的环形缓冲，工作件在音频线程里读出播放。第一次按键或点击时恢复声境（浏览器的自动播放规定要求页面先有用户手势）。
- `声音工作件.mjs`：音频线程里的工作件（AudioWorklet 处理器，`registerProcessor('豫寓鸣', …)`）。从环形缓冲读交错的十六位样本，缓冲空了补静音；浏览器采样率与打开时请求的不同就在这一侧按线性插值重采样。已播帧数就是它对缓冲的读位置。
- 进程表、工作线程与内存文件系统沿用浏览器构建宿主（`../构建/`）：每个任务一个 Web Worker，文件、子进程、标准输入经共享内存向主线程同步提问，所以页面要跨源隔离。

## 快照

- `源.tar.gz` 展成 /源：前导与行在五部要编的源码（豫章（标准库）、诏令（壳命令库）、几席、中书与豫寓榫卯，加屏键部截屏要的画谱、勘合、括囊三包的顶层源码），加全仓的包描述与说明。开机壳第一次编句时先编前导（三十多个模块），之后每句只编这一句。
- `工具.tar.gz` 展成 /工具：网页汇编的豫构 `豫构。豫行` 与诺驿值桥 `节点值桥接.wasm`。
- `桌面.tar.gz` 也展到 /工具：图形桌面 `图形桌面。豫行` 与桌面程序 `桌面程序。豫行`（压缩后约 18.6 MB），第一次进桌面时才取。/工具 里的名字与豫言操作系统 /工具 里的相同。
- 仓库目标「用户态系统浏览器发行」只生成网页行在：三个快照与页面（发行目录下的 `行在/` 与 `构建/`）以及三套字体及许可。云仓把发行目录发布到站点的 `/操作系统/`，官网路由给 `/操作系统/行在/` 与 `/操作系统/构建/` 加跨源隔离头。

## 秘府

盘上除了快照带来的 /源、/工具，其余部分（/数据、/系统、/软件 与根目录下的文件，如桌面设置库 /桌面设置.数据库）存在秘府（站点私有文件系统，OPFS）的 `网页行在` 目录里，重新载入页面后还在。共享编译缓存根 `/tmp/豫构缓存` 也存进秘府，其中别的 /tmp 是临时的，不留。

- 开机时把秘府里的整棵树读进内存文件系统，再撤下 /系统/桌面运行中（同裸机“开机时标阴”）。/系统/开机自启 每行一句，作开机壳的开头句，在第一个提示符之前执行，同裸机开机壳；留着的 /系统/请求进入桌面 开机后照办。
- 之后内存文件系统里这些路径的写、删、改名与建目录都记下，三百毫秒后写回秘府（同一路径连改几次只写一次），关页面时把积下的一并写回。写回按区段增量进行：每次写先与旧内容比较，只把改动过的区段按位置写进秘府，末尾再截到当前长度；有同步访问句柄 `createSyncAccessHandle` 就用它，没有就用可写流按位置写。大文件改一点不必整篇重写。
- 缓存根下的目录按编译语义号分（`/tmp/豫构缓存/<语义号>/`），开机时读 /源 里 库/译场/译料/译设/语义号。数据。豫 的编译语义号，只留当前语义号的目录，删掉旧语义号的目录；只删 UUID 形的名字，`交互缓存/` 等别的目录留着。交互会话的前导与各部的单元目录在缓存根的 `交互缓存/<仓库根摘要>/` 下（豫构的「交互缓存根」，议题 147），所以重新载入页面后前导单元与阶段缓存都在，第一句不必重编前导。
- 同一时刻由一个标签页写回（网页锁 `网页行在秘府`）；别的标签页照常读入，改动只留在本页内存里，开机时状态栏说明。
- 浏览器的“清除网站数据”清掉秘府。

## 双端对照

「原生对比」（`应用/百工坊/原生对比`）的「交互」场景把同一组句子（定义后再用、裸式印值、组合句、编译错误、没接住的运行时异常）分别交给原生豫构交互与 Node 上的 `豫构.wasm` 交互，输出须逐字相同；网页行在跑的就是 Node 这一边的同一份网页汇编程序。CI 抽样轮次的“原生与 Node 性能对比”一步缺省就跑它，两边不同即失败。

## 字体

发行目录的 `字体/` 带思源黑体、原始字体与默认等宽黑体三套字体及许可，`字体.ttf` 是文楷。页面按族名分别声明：`文楷` 用 `../字体.ttf`，`无衬线`、`汉字`、`符号`、`圆体`、`数学` 用 `../字体/思源黑体.otf`，`衬线`、`手写`、`装饰`、`仿宋` 用 `../字体/原始字体.ttf`，`等宽` 用 `../字体/默认等宽黑体.otf`；`Arial`、`Helvetica`、`黑体`、`Times New Roman`、`宋体`、`Courier New`、`Menlo` 等具体族名与 `serif`、`sans-serif`、`monospace`、`system-ui` 等通用族名也各声明一条。粗体族名不声明，字体选取取不到真粗面时回到常规面仿粗。`字体基` 网址参数另指字体目录，`字体` 参数把全部族名指到同一个文件。

## 本机验证

把三个快照放进一个资料目录，运行 `node 豫言操作系统/宿主/浏览器/构建。测试服务.mjs <资料目录> 18791`，浏览器打开 `http://127.0.0.1:18791/浏览器/行在/行在.html?源=/资料/源.tar.gz&工具=/资料/工具.tar.gz&桌面=/资料/桌面.tar.gz`。字体按族名取自 `字体基`（缺省是站点的 `/操作系统/字体/`）；本机开发时让 `字体基` 指向仓内 `豫言操作系统/裸机/字模生成/字体/` 的网址，`字体=` 仍可把全部族名指到同一个字体文件。

## 任务与标准输入

- 两种「亲行」都继承调用方的标准输入：子任务读的就是页面终端送进会话的那份输入，子任务退出后交还，会话接着读余下的输入。豫章 使者 的「亲行」三流都继承（同原生），子任务的输出随出随显示；豫寓 子程序接口的「亲行」只继承标准输入，输出与错误仍由宿主收下，随「使报」交给调用方（同原生）。
- 父任务先退时，它没人收取的子任务记录一并收拾：已结束的直接删去，还在运行的改挂给初始任务（开机壳），它们结束之后也不再留在进程表里。

## 桌面

开机壳的环境里 豫言行在=网页，壳就按宿主行在会话装「任务」「图形」「屏键」「声音」「电源」五部（部的源码在 /源，第一次用到时在浏览器里编）。「图形」写下 /系统/请求进入桌面，行在（主线程）删去它、写下 /系统/桌面运行中，让页面只留名为“主窗口”的画布，起 /工具/图形桌面。豫行，环境另加 豫言桌面程序=/工具/桌面程序。豫行；桌面退出后撤下标志、回到命令行。

图形桌面与壳的部用带类型导入直接调豫寓接口（同原生执行器的“路二”），工作线程里的实现见 `../构建/豫寓.mjs`：显示面、字体、剪贴板、读屏与合成输入在主线程办（显示面表与画布后端沿用 `../图形.mjs`），文件按授权根“桌面”=/ 读写内存文件系统，子程序经进程表起（交互子程序当终端，可入原始模式），任务表列进程表里运行着的任务，「辍役」销毁任务与它全部子孙的工作线程（退出码 130）；号为负而没有子孙可断时给会话的共享内存置打断标志并返回二，句子单元里的检查点见标抛出专用异常，会话在句子边界印“已打断”后接着读下一句（提案 00043 第六步）。桌面终端起的就是 /工具/豫构。豫行 交互 --组字 会话，与开机壳同一个壳。

每个窗口一个任务（提案 00015）：九宫（平铺桌面库）见到 豫言桌面程序，就照裸机用「遣使附映面」把每个窗口（终端、文件浏览、任务管理器等）起成一个 /工具/桌面程序。豫行 任务并转授一块显示面。行在替它代管这块显示面：窗口任务提交的画面存成整块画布与变化区域，桌面用「取使者画面」取走；桌面送的输入事件排进窗口任务的事件队列；尺寸与像素比由桌面设。窗口任务要外壳办的事（如终端里「辟窗」开新窗口）经「请外壳办」交给桌面，桌面的来信经「送程序来信」交回。终端窗口任务再起 /工具/豫构。豫行 交互 --组字 会话。桌面退出时各窗口任务的显示面随之关闭，窗口任务自行退出，终端会话读到输入结束也退出。

宫（工作区）各有一块显示面：主画布带 `data-yy-显示面前缀="宫"`，桌面取名为“宫二”“宫三”……的显示面时，行在（主线程）在浏览器里开一个同源小窗，把带 `data-yy-显示面="宫二"` 的画布与隐形输入框放进去，尺寸、像素比与输入事件都按小窗算。浏览器按弹出窗许可或用户手势拦下小窗时这块面取不到，桌面让那间宫共用主画布；用户关掉小窗即这块面「显示面已关闭」，归还这块面时小窗随之关上。「题映面」设小窗的标题，九宫把每间宫的标题设成它焦点窗口的标题。桌面的多面会话用「待诸面入事限时」同时等几间宫：交回事件所在面的序号（从零起），期限到时序号为负一、事件为「显示计时」；只等一块面时同「待入事限时」。

## 声音

声音输出接口（豫寓鸣）在网页行在里由 AudioWorklet 接到浏览器的 Web Audio：

- 工作线程跑豫言程序，`辟声出` 时造一条环形缓冲（SharedArrayBuffer，容量至少六万五千五百三十六帧，块大小更大时按二的幂放大），经同步提问把缓冲交给主线程，取回流号；主线程造 AudioWorkletNode，把缓冲放进处理器的选项里，工作件在音频线程里读。
- 控制字八个三十二位整数：写帧位置（工作线程写）、读帧位置（工作件写，就是已播帧数）、设备延迟帧（主线程写），其余留用；样本从第三十二字节起，交错的十六位小端。
- 缓冲放不下一整块就整块退回，得「资源配额已尽」（同接口规范里宿主限制排队总量的做法）；缓冲空了工作件补静音。已播帧数与声出延迟都读共享的控制字，不必再问主线程。
- 浏览器采样率与打开时请求的采样率不同时，工作件按线性插值重采样，「已播帧数」仍按打开时的采样率计。
- 浏览器的自动播放规定要求页面先有用户手势：`声音.mjs` 在第一次按键或点击（document 上的捕获阶段）时恢复声境，此后的流随开随播。开机自启里放的音，要等用户按一下键才出声。
- 程序退出时行在关掉它开着的流（进程表的「结务」），AudioContext 留着给下一个程序用。
- 壳里「试声」（放一秒七百五十赫测试音）走的就是这条路径，由声音一部的做法（`库/几席/声令。豫`）调豫寓鸣；放完印出已播帧数，实机靠耳朵听。
- 同一份工作线程实现在浏览器构建宿主里也用得上；那里没有主线程的声音外务，`辟声出` 照旧得「资源暂不可用」。

## 终端与打断

页面终端按 Ctrl+C 时除把控制字 3 送进开机壳，还经进程表以负的任务号调「辍役」（提案 00043 第六步）：壳正在运行一句时置打断标志，句子里的检查点抛出专用异常，壳会话印“已打断”后接着读下一句；正在运行子程序时结束子程序；停在提示符时只放弃正在输入的行，置下的标志随下一句开始清掉。
