# 浏览器宿主：统一事件队列、界面订阅器、页面控制与网页能力

`宿主.mjs` 在原有的“DOM、事件与网络原语”之外，新增三个**纯工厂函数**并导出（可脱离 Wasm、只用 JSDOM 单独测试），`创建浏览器宿主` 只负责把它们接到豫言原语上。它们服务于 `网页事件`、`网页界面`、`网页文树`、`网页消息` 四个接口包的浏览器适配。

## 一、统一事件队列 `创建事件队列`

- 所有事件来源共用一个先进先出队列；每个事件有类型（`界面 消息 定时 事件流 请求 编译 可见性 联机 历史 关闭 宿主`）与宿主分配的单调序号。`推事件(事件, 附加)` 仍是原始入口：旧式事件（不带 `类型` 字段）按名称归类——`click/input/change/submit`（无 `来源句柄`）归“界面”，`定时` 归“定时”，其余归“宿主”；新式事件自带合法 `类型` 字段，直接归该类型。
- 每类型独立上限（默认 1024，`创建浏览器宿主({队列上限:{界面:2048}})` 或 `豫言_浏览器_设置事件队列上限` 可调）；满时丢弃该类型最旧事件并计数（`宿主` 类型例外：满则报错，保持旧行为）。`合并键`：紧接尾部、同类型同键的高频事件就地替换。
- 三种取法：**原始**（`豫言_浏览器_等待事件`，取任意类型的下一个事件，返回原始 JSON，行为与旧宿主完全一致——旧事件的 JSON 形状不变）、**统一**（`豫言_浏览器_等待网页事件`，任意类型，返回统一 JSON）、**按类型**（`豫言_浏览器_等待界面事件`、`豫言_浏览器_等待网页消息`，只取自己的类型，返回元组）。等待者不接受的类型的事件留在队列里，绝不被吞。
- 宿主关闭后，统一与按类型的等待每次都异步返回“关闭”标记（避免不检查关闭的循环霸占线程）；原始等待保持旧行为（关闭后不再返回）。
- **给其他事件源的接入点**（事件流、请求、编译、以及将来的批事件）：宿主里任何原语要向豫言投递新类型的事件，调用 `推事件({类型:'事件流', 订阅号:整数, 名称:文字, 详情:JSON, …其他字段}, {合并键})` 即可；无需新增队列或等待函数，应用用 `等待网页事件` 就能收到。批事件（同一订阅号的多个事件合成 `详情.批`）可在投递前由该事件源自行完成。

## 二、界面订阅器 `创建界面订阅器`

`订阅界面事件` 的宿主实现：在目标（元素、文档、窗口）上安装原生监听，**同步**完成键规则匹配、`preventDefault`、`stopPropagation`、`stopImmediatePropagation`，再把不含原生对象的载荷投递进队列。要点：

- 委托：任意后代触发都投递；`标识` 为触发元素 ID，`操作键` 取最近的 `data-yy`（止于订阅边界）；不冒泡事件一律捕获阶段监听。
- 策略与键规则在订阅时严格校验（未知字段、类型错误、矛盾组合都报错）；键规则默认不匹配输入法组字期间的按键。
- 载荷不含 `password` 输入框的值；`值` 超过 65536 码元则省略并标记；消息订阅的详情在原生回调里就序列化并检查 1 MiB 上限。
- 旧式隐式监听（只报带 ID 元素）遇到已被订阅覆盖的同名事件时让路，避免重复。

## 三、页面控制 `创建页面控制`

按元素 ID 的读写（值、显示、焦点、光标、滚动、模态框、页面状态）与句柄型文树操作（建树、组合、释放、追加文字、iframe 地址、模板装入）。**标签、属性、链接、类名的白册与全部限额只在这里写一处**，四个适配都经它校验；宿主还在其上留有底层原语的旧防线（`豫言_浏览器_设置属性` 拒绝 `on*`、`srcdoc` 与 `javascript:` 地址）。句柄表上限仍是 4096（`句柄.mjs`，新增 `条目()` 与 `上限` 供整树释放与报错使用）；编号单调递增、绝不复用。

## 四、网页能力 `创建网页能力`（网页定时、储存、导航、环境、请求、事件源、编译、应用）

八个新接口包共用一个纯工厂 `创建网页能力({根, 全局, 网络, 路径, 储存, 队列, 已关闭, 定时, 编译客户端, 导入模块, 页面应用超时})`，适配经两个原语进入：`豫言_浏览器_网页能力(操作名, 一, 二, 三)`（同步）与 `豫言_浏览器_网页能力异步(操作名, 一)`（`请求.同步`、`应用.启动`），操作名形如 `定时.一次`、`请求.发起`，参数与结果都是文字，失败返回（阴，错误文）。校验与限额只在这里写一处。

- **事件进队**：定时（经宿主原有的 `造定时`，同时 ≤64）、请求、事件源、编译的结果都以“新式事件”（带 `类型`、`来源键`）投递进统一队列；取消或关闭时按 `来源键` 移除未取走的事件，保证其后不再收到该号的事件。
- **背压管线**（事件源、编译）：每个来源在队列里未取走的事件超过 8 个时，新事件暂存在宿主里，应用每取走一个补投一个；事件源的读流循环据此暂停读取（HTTP 流控把压力传回服务器），编译的进度则先缓存。所以事件流不会丢事件。`离队钩子` 把“事件离开队列”通知给管线与请求登记。
- **事件源不用原生 `EventSource`**：原生对象没有背压。宿主用 `fetch` 流读取，`创建SSE解析器`（导出，可单测）按 WHATWG 规则逐块解析，自己复现重连、`Last-Event-ID` 与 `retry:`。
- **请求**用注入的 `网络`（默认 `fetch`），固定 `credentials/mode: same-origin`；读流逐块累计并按上限中止，正文严格 UTF-8 解码；并发含“结果未被取走”的请求，至多 32。
- **编译**经“编译客户端”（默认页面基址目录下 `编译/客户端.mjs`，可注入对象或地址）；**应用**经 `导入模块`（默认 `import()`）加载同源 `入口.mjs` 并等子应用就绪，宿主关闭时子应用一并关闭。
- **可测试性**：`创建浏览器宿主` 新增选项 `编译客户端`、`导入模块`、`页面应用超时`；`状态()` 增 `定时数`、`请求数`、`事件源数`、`编译中`、`页面应用数`、`管线数`。

## 测试与诊断

- 事件、界面、文树、消息的单元测试与一致性测试见 `适配/网页事件浏览器/一致性验证/`；八个新包的见 `适配/网页定时/一致性验证/`。
- `创建浏览器宿主` 返回的对象新增 `状态()`：`{积压, 各类积压, 丢弃, 各类丢弃, 等待者, 序, 句柄数, 界面订阅数, 消息订阅数}`，只供测试与诊断。
- 构建器固定复制的宿主文件仍是 `值桥.mjs`、`句柄.mjs`、`宿主.mjs`、`入口.mjs`、`自动启动.mjs`、`工作线程自动启动.mjs`；本次改动没有新增文件，因此不需要改构建器。
