# 浏览器同步值桥

浏览器未提供 `WebAssembly.Suspending` 或 `WebAssembly.promising` 时，值桥直接调用 Wasm 的 `_start` 与启动导出 `豫言操作系统启动/启动程序`（有时），允许只使用同步宿主能力的豫言程序运行。某项宿主能力若返回 Promise，值桥立即报出该能力名称，避免把 Promise 当作普通豫言值传回程序。

有 JSPI 时仍使用挂起与恢复 Wasm 栈的原路径。同步路径不具备异步续执行能力，不能运行等待网络、DOM 事件或流的界面程序；也不能代替浏览器对 WasmGC 等模块功能的支持。

`同步值桥。测试.mjs` 使用真实豫言 Wasm 验证无 JSPI 同步运行与异步拒绝；`装载/浏览器入口。测试.mjs` 验证原 JSPI 浏览器入口。Safari 的完整界面运行仍需单独解决异步续执行与模块兼容问题。

## 失败时页面如何提示

`自动启动.mjs` 在应用启动失败（例如浏览器缺 WasmGC）或运行中失败（例如界面程序在没有 JSPI 的浏览器里调用了异步宿主能力）时，给 `<html>` 加上属性 `data-yuyan-app-error`（值是失败原因，至多 300 字），同时照常在控制台报错。静态页面不必写脚本，只需放一个默认隐藏的提示元素并用 CSS 属性选择器显示它，例如：

```css
.需要现代浏览器 { display: none; }
html[data-yuyan-app-error] .需要现代浏览器 { display: block; }
```

云工作台的 `首页.html` 与 `控制台.css` 就是这样提示“需要支持 WasmGC 与 JSPI 的浏览器”的。

## 平台接口的带类型导入

取消外调第③步起，浏览器宿主库（`库/浏览器宿主`）与中央张量宿主库（`库/中央张量宿主`）的函数编成带类型导入：导入模块是包名“浏览器宿主”“中央张量宿主”，字段是接口文件里声明的函数名。`宿主.mjs` 导出对照表 `浏览器平台导入`，把每个字段对到旧 call 路径的原语名，两条路径共用同一份实现；旧产物经 `yuyan:gc-host/v1.call` 照常运行。

- 只给真正可能返回 Promise 的 62 个实现套 JSPI：写成 async 的实现、取事件队列的四个等待、读同源资源文字、显示图形字体三个操作（首次要动态载入 `图形.mjs`），以及中央张量的启用与运行。其余同步调用，不再每次挂起。
- 没有 JSPI 时，`创建豫言实例` 把标“异步”的实现改为同步调用：真的返回 Promise 才报“此浏览器缺少 JSPI，程序调用了异步宿主能力：模块.字段”，所以只调同步能力的新产物照常运行。
- 中央张量在带类型路径上只有启用、运行可能异步；其余在内核还没启用时报“中央张量：尚未启用”（适配总是先取上下文）。读单精与数学的结果在旧路径包成 `{小数}`，带类型路径取出裸数。
- `宿主支持清单.tsv` 列出浏览器提供的接口及其适配，格式与 `节点/宿主支持清单.tsv` 相同；构建器在浏览器模式下按它选适配，表里没有的接口浏览器不提供。`宿主支持清单。测试.mjs` 核对清单格式、适配不依赖浏览器不提供的平台接口包、平台接口包的声明与对照表逐一相同，并用最小 Wasm 程序在有无 JSPI 两种情况下构造宿主。
