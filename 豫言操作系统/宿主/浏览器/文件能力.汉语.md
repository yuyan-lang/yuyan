# 浏览器文件能力接入

宿主现在可显式授予可写目录：名称表中的值写成 `{目录: FileSystemDirectoryHandle, 可写: true}`；直接给目录句柄仍默认只读。沿用公共文件接口0.5，可创建、覆盖、追加、按游标写入、创建单层目录及删除文件或空目录。每次写入关闭原生写流后才返回成功，使其他文件柄立即可见新内容；关闭公共句柄释放游标资源，不保留原生写流。并发写入协调仍待完成。

四组宿主协议测试通过，覆盖立即截断、连续中文写入与追加、创建与已有目录冲突、非空目录保留、只读内容保留、越界、缺父及失效句柄。此证据使用目录句柄替身与实际Blob；真实浏览器存储和公共Wasm调用尚待验收，已部署网页当前仍只授读取。下文的只读与三组测试是早期实现记录。

这是公共文件接口的浏览器宿主原语模块 `文件能力.mjs`。宿主以名称到原生 `FileSystemDirectoryHandle` 的表明确授目录，模块复用现有 `句柄.mjs`，以不透明句柄号供调用者持有。目录来自已授本地目录或宿主取得的站点私有文件系统；模块不弹授权框，也不自行取得其他目录。

目录列举、文件信息、只读打开、Blob字节分块、读尽与关闭使用与节点原语相同的结果元组约定。路径从授权根逐段解析，不创建文件；空路径指根目录，文件打开要求非空路径。绝对路径、空段、点与双点段返回输入无效。未授目录、原生权限拒绝、资源不存在与已关闭句柄分别返回对应公共状态。当前只读，写操作明确返回未获授权。

原生操作依照 [WHATWG File System 标准](https://fs.spec.whatwg.org/)。`文件能力。测试.mjs` 使用目录句柄替身与实际Blob，覆盖目录树、信息、UTF-8跨块读取、读尽、关闭、清理与失败状态，三组测试通过。

待办事项：把原语声明接入浏览器宿主及其支持清单，新增普通豫言文件浏览器适配并登记父包，绑定公共文件0.2接口；构建器复制本模块后，构建实际桌面发行，并在真实浏览器目录上验收。网页云资源名表是资源地址与元数据，后续通过已有云服务接入同一公共能力，不能把名表直接充作本地目录句柄。并发同柄读取与写入权限以后处理，当前桌面读文件按顺序执行。
