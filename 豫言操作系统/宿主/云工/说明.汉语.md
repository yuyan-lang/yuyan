# 云工宿主壳说明

本目录是构建产物里“云工外壳”的源码：`入口.mjs`（Worker 入口与通用类 `豫言持久对象`、`豫言服务入口`、`豫言工作流`）、`宿主.mjs`（能力桥与事件分派）、`值桥.mjs`（WasmGC 值转换与执行时限）、`句柄.mjs`（不透明句柄表）、`隔离入口.mjs`（Dynamic Worker 子入口）、`隔离运行客.mjs`（文件式程序的 Dynamic Worker 子入口，配合浏览器编译器宿主 `编译宿主.mjs`，见[隔离运行适配](../../适配/隔离运行/说明.汉语.md)）、`平台资料.mjs`（平台资料接口的宿主实现：取回并缓存只读资料集；`宿主.mjs` 登记原语 `豫言_云工_平台资料列键安全`、`豫言_云工_平台资料读文字安全`，第一次调用时才动态导入本文件、每个宿主创建一次（动态子 Worker 的模块表里没有它，静态导入会使子 Worker 装载失败），构建器把它复制进产物，见[平台资料适配](../../适配/平台资料/说明.汉语.md)）、`编译运行.mjs`（编译运行接口的宿主运行器：内存文件系统里运行豫言编译器 Wasm；由云端编译服务的外壳静态导入并放进 env，不经构建器复制，见[编译运行适配](../../适配/编译运行/说明.汉语.md)），以及与浏览器宿主共用的 `../浏览器/中央张量.mjs`（张量计算接口中央处理器后端的宿主部分：`宿主.mjs` 每个事件第一次调用 `豫言_中央张量_*` 原语时动态导入它、单线程创建能力；内核模块 `中央张量内核.wasm` 由构建器编出，`入口.mjs` 从 `动态资源.mjs` 取得后以 `中央张量内核模块` 传给 `创建云工宿主`，见[张量计算网页适配](../../适配/张量计算/说明.汉语.md)）。构建器 `yy双宿主构建` 把它们复制到产物目录，业务只写豫言；每个事件新建一个豫言 Wasm 实例，事件之间没有内存状态。宿主提供的原语清单见 `库/云工宿主/`；本文只写事件、时限、独占区、响应与交换上限这些**壳层行为**。带“本地已验”的结论来自 Wrangler 4.129.0 的本地 workerd（兼容日期 2026-09-05，SQLite 存储的持久对象）；“云端待验证”的条目汇总在文末。

## 入站事件种类

应用用 `读取入站事件种类`（或 `云工事件种类`）辨别当前事件；同一个 Wasm 处理所有种类。

| 种类 | 由谁触发 | 说明 |
| --- | --- | --- |
| `fetch`、`service-fetch`、`queue`、`scheduled`、`email` | Worker 处理器 | `service-fetch` 来自命名服务入口 |
| `durable-fetch`、`durable-alarm` | 持久对象的 `fetch`、`alarm` | 告警事件可读重试次数 |
| `durable-websocket-message`、`durable-websocket-close`、`durable-websocket-error` | 持久对象的休眠式套接字回调 | |
| `durable-transaction` | 豫言在持久对象事件里调 `执行持久事务` | 在 `storage.transaction` 回调里重入 Wasm，读写作用于事务对象 |
| `durable-block` | 豫言在持久对象事件里调 `执行持久独占` | **新增**：在 `blockConcurrencyWhile` 回调里重入 Wasm，见下 |
| `workflow`、`workflow-step`、`workflow-rollback` | Workflow 的 `run` 与步骤回调 | |
| `stream-pull`、`stream-cancel`、`html-*`、`websocket-*` | 豫言创建的回调流、HTMLRewriter、出站或入站套接字 | 重入事件，各有独立实例 |

## 每事件墙钟时限与 `执行配置.json`

每个事件的 Wasm 实例有一个墙钟时限：豫言每次调用宿主能力时检查，超过则抛出 `豫言执行超过时限`，事件失败（告警会因此被平台重试）。**默认 30 秒**。云端项目的告警要跑模型流、编译、发布，常超过 30 秒，所以时限可以按事件种类配置。

配置放在**应用目录**（`入口。豫` 所在目录，与 `许可.json` 同处）的可选文件 `执行配置.json`，它**不是** `许可.json`，不改变许可的绑定种类结构：

```json
{"事件时限毫秒": {"默认": 30000, "durable-alarm": 900000, "durable-fetch": 30000}}
```

规则：`事件时限毫秒` 的键是事件种类（上表，含 `html-*`、`websocket-*` 的具体名称；拼错会在加载时报错）或 `默认`；值是 1 至 900000 的整数毫秒（15 分钟，平台后台事件的墙钟上限）。选取顺序：显式配置的该种类 > 该种类的内置默认 > `默认` > 30 秒。`durable-block` 与 `durable-transaction` 有内置默认 **25 秒**，且**不受 `默认` 影响**，显式配置也不得超过 30 秒：这两类回调运行在平台的 `blockConcurrencyWhile` 与事务里，平台在回调超过 30 秒时会重置整个对象（本地已验），25 秒的内置线让超时表现为可捕获的 `豫言执行超过时限` 而不是对象重置。非法配置（未知字段、未知种类、非整数、越界）使 Worker **加载失败**（部署校验即可发现），不会在运行中静默失效。时限只在豫言调用宿主能力的边界检查，单次外部调用本身耗时过长不会被打断；CPU 时限是另一回事，由 Wrangler 的 `limits.cpu_ms` 控制。Dynamic Worker 子入口（`隔离入口.mjs`）不带配置，仍用 30 秒。

使用与云仓配合：（1）在应用目录放 `执行配置.json`，例如云端项目应用放 `{"事件时限毫秒":{"durable-alarm":900000}}`；（2）云仓构建程序 `yy云仓构建` 无需增加参数——构建时已把整个应用目录复制到构建目录，`yy双宿主构建` 自动读取 `<入口源码所在目录>/执行配置.json`，解析并规范化（非法 JSON 使构建失败）后写成产物 `动态资源.mjs` 的导出常量 `执行配置`，缺文件时写 `{}`；（3）产物里的 `入口.mjs` 用命名空间导入读取该导出，**新旧混用都安全**：新壳遇到旧版构建器的产物（没有该导出）按默认时限运行，Wrangler 打包时只有一条 `Import "执行配置" will always be undefined` 警告，正好提示构建器过旧；旧壳遇到新版构建器的产物则忽略多余导出。要让配置生效，壳与构建器都须是新版（`./yy云仓构建 准备种子` 会用当前语言仓源码重编该工具）；（4）同一个 Worker 里导出多个应用的类时，每个应用带自己的配置，互不影响。测试可直接向 `创建云工宿主({…, 执行配置})` 传对象，`解析执行配置`、`选事件时限` 也从 `宿主.mjs` 导出。

## `durable-block`：并发独占区

`执行持久独占` 的宿主实现是 `云工持久独占执行安全`：宿主调用 `ctx.blockConcurrencyWhile`，在回调里以 `durable-block` 事件重入 Wasm（事件里 `读取持久独占名`、`读取持久独占参数` 取入参，`完成持久独占` 设置一次结果），回调返回后平台恢复投递其他事件。要点：

- 回调期间到达的事件排队，区结束才投递；多个区依次执行（本地已验：五个并发的读—等—写在区内恰得 1 至 5，区外并发丢失更新；区内 100 毫秒后到达的普通请求在区结束时才被处理）。
- **区内失败不抛给平台回调**：宿主在回调内捕获，作为 `[false, 原因]` 返回，外层抛可捕获的豫言异常。平台原生的回调抛错会重置整个对象（本地已验：实例号变化、请求失败）。
- 参数与结果是 JSON 文字，各 ≤ 8 MiB，宿主用原生 `JSON.parse` 校验；操作名 1 至 128 字节。`durable-block` 事件不是 HTTP 事件，读请求或设响应的函数不可用（宿主 JS 错误，豫言捕获不到，处理入口不应调用）。
- 不可嵌套：区内、事务入口内、非持久对象事件里启动独占区都返回 `[false, 原因]`。区内可启动事务（`durable-block` → `durable-transaction`），告警入口里可开区（本地已验 `durable-alarm` → 区 → 事务）。
- 事务回调本身也是独占的：本地已验事务运行期间到达的事件排队，超过 30 秒平台重置对象。

## `durableFetch` 与 `ctx.waitUntil`：响应先返、失败与取消

宿主在 `fetch`、`service-fetch`、`durable-fetch` 事件里用 `Promise.race([响应已备, 运行毕])`：豫言一旦设置响应，`fetch` 立即返回该响应，Wasm 继续运行（用于流式响应和响应后的收尾）；豫言先失败则 `fetch` 拒绝，调用方得到异常（平台返回 500）。宿主始终把运行承诺交给 `ctx.waitUntil`。已确认（本地 workerd）：

- 设置响应后继续运行的部分照常完成（本地测试：响应 6 毫秒返回，800 毫秒后的持久写入成功）。**不用 `waitUntil` 的原生对象代码也同样存活**，故本地看不到 `waitUntil` 的差别；Cloudflare 文档称 `waitUntil` 在持久对象内不延长寿命（见 `库/云工宿主/持久对象接口.清单.tsv`），云端行为待验证——依赖响应后长任务的应用应改用告警（`设置持久告警`）续跑，不要依赖响应后的存活。
- 响应已交付后 Wasm 才失败：错误无法传给调用方，宿主写一行 `console.error("[豫言] 响应已交付后运行失败：…")`（以前是静默丢弃）。
- 客户端在请求中途断开：本地已验豫言运行**不会被取消**，继续到结束（`sleep` 6 次 × 300 毫秒，断开后仍执行完）；豫言侧只在下一次写流块时发现读者已取消（`可写流已关闭`）。云端行为待验证。
- 告警事件里失败会抛出，平台按退避重试；`fetch` 之外的事件不做“先返”。

## 交换上限（谁在哪里限制）

| 位置 | 上限 | 说明 |
| --- | --- | --- |
| 带类型导入的字符串、字节串 | 无宿主上限 | 不经值桥的交换缓冲，只受 Workers 内存约束（本地已验 17 MiB 可读入） |
| `宿主.mjs` 的 `限文` | 2 MiB | 只影响先整体读文字的原语：`读取请求`、`请求文字`、`服务请求文字`、`持久对象请求文字`、`对象读取`、`回应文字安全`；`Request.text()`、`json()` 经句柄桥调用**没有**这个限制 |
| 网页入站适配 `读取入站结森正文文` | 2 MiB | 适配自设（豫言代码里检查），不是宿主限制 |
| 网页答复适配 `回应入站文字`、`回应入站结森文` | 2 MiB | 适配自设 |
| 流块、广播 | 2 MiB 供块；广播单块 64 KiB、每订阅队列 1 MiB | |
| 持久仓（接口层） | 键 2048 字节；值 2 MiB；列举结果 8 MiB；独占区参数与结果各 8 MiB | 见持久事务、持久独占规范 |

站点发布请求含至多 4 MiB 的 base64，因此不能走 2 MiB 的 JSON 正文读取：HTTP 接口适配应另给“有限正文”读取函数，经 `云工请求句柄` 与 `云工物字文字`（即 `Request.text()`）取原文，本地已验 5 MiB、15 MiB 正文可读入豫言（旧产物超过 16 MiB 时被值桥拒绝；带类型导入没有这一限制）。为防止超大请求先被整体读入内存，适配应先检查 `content-length` 标头，或改用 `读取流块` 累计字节并在超限时取消；请求体上限本身仍受平台限制。宿主与值桥本身对这一放宽没有阻碍。

## 句柄号与值记号的防伪

- 句柄号不是自增序号，而是密码学随机的 53 位安全整数：应用 JSON 里即使写出 `{"$句柄":"1"}` 也指不到任何现存句柄，无法借它伪造宿主对象；号只由宿主结果给出，豫言库当作不透明字符串传递。
- 参数里的 `$大整数` 记号只接受最多 40 位的十进制串（可带负号），`$数字` 记号只接受 `NaN`、`Infinity`、`-Infinity`，其余一律抛错，避免用畸形记号消耗宿主算力或造出意外类型。
- 值桥读取豫言字符串用 `ignoreBOM: true` 的 `TextDecoder`，字符串开头的 U+FEFF 得以原样传给宿主原语。
- 仍须注意：把应用提供的 JSON 原样并入 `云工调用方法` 的参数文字时，记号形状的单键对象只要不指向现存句柄就会抛错而不是被静默接受；适配若接收结构化 JSON 输入，仍应在自己这一层拒绝宿主记号（消息队列适配已如此）。

## 通用句柄桥的白名单

- 全局句柄、构造对象、调用全局及其安全版只能取得白名单里的全局：与 Node 应用宿主的“可用全局”相同，另加云工库与适配用到的 `Request`、`Promise`、`Error`、`caches`、`scheduler`。`fetch`、`WebSocket`、`EventSource`、`Function`、`WebAssembly`、`globalThis` 等不在表内，取用时报“云工宿主不开放此全局”，应用（包括隔离运行里空许可的用户程序）不能借句柄桥绕过外发来源许可（`OUTBOUND_ORIGINS`）与绑定授权。外发请求一律走带许可核对的专用原语。网页上游规范的“请求公网HTTPS上游”用专用原语 `云工公网请求发起`：程序许可 `OUTBOUND_ORIGINS` 含 `https://*`（规范约定的“允许动态公网 HTTPS”）时才放行，宿主当场核对网址是 https、不带用户名或密码，并把 redirect 一律改为 manual；空许可的程序用它只得到错误。待办事项：句柄表仍在，云工宿主库一百多个原语还以字符串句柄传对象，先把它们改成资源（`资` 形），才能删去句柄表。

## 标准库宿主服务

- 标准库的带类型导入（导入模块“标准库”）经共用胶水接入：`值桥.mjs` 的 `创建豫言实例` 每次（即每个事件）新建一套导入闭包，签名表按模块缓存；这里提供二十个，其余给桩。带类型导入同样在每次调用时检查该事件的墙钟时限，但不经 `值桥.mjs` 的交换缓冲，不受上表 16 MiB 的限制。
- 退出进程的退出码为 0 时事件正常结束，非零以“豫言程序退出：码”失败；标准错误打印行缺省写 `console.error`（平台日志的错误级），`创建云工宿主` 可传 `错误输出` 改去向。其余语义与各宿主的分工见[标准库宿主服务](../标准库宿主.汉语.md)。
- 产物里的 `边界.mjs` 是胶水本体（仓库里同名文件只转出 `../网页汇编/边界.mjs`），动态子 Worker 的模块表也带上它。

## 平台接口的带类型导入

- 第③步起，云工宿主库（`库/云工宿主`）与中央张量宿主库（`库/中央张量宿主`）的无体声明（`。接口。豫`）编成导入模块“云工宿主”“中央张量宿主”的带类型导入，字段是函数名，共 339 与 15 个。这里提供全部。
- `宿主.mjs` 每个事件仍以旧原语名（`豫言_云工_…`、`豫言_中央张量_…`）建一张能力表，旧名只是宿主内部的键，程序看不到。`值桥.mjs` 导出对照表 `平台导入旧名`（包名 → 函数名 → 旧原语名），由第③步库改写的平台导入表生成，此后新增函数手工按码点次序补入；待办事项：能力表改以字段为键后删去此表。创建宿主时按程序模块算一次它实际导入的云工宿主、中央张量宿主函数；每个事件按对照表把能力表里的实现接到（模块，字段）上，交给共用胶水。对照表另收诺节宿主、系统库调用、安全外壳密码三个包，供 Node 应用宿主使用；程序若导入云工不实现的包，胶水给桩，调用时报“接口函数未绑定”。对照表里有、能力表里没有的旧名是宿主缺陷，本事件即失败。
- 每个事件一套新闭包，不共用“当前事件”的状态。只有 async 实现（105 个）标“异步”、由胶水套 JSPI，其余直接调用；带类型导入每次调用都检查该事件的墙钟时限。参数与结果按胶水的 JS 形转换：串是 Uint8Array，整是 BigInt，爻是布尔，旧能力本就兼收。
- 中央张量：启用标异步，第一次调用时动态导入 `中央张量.mjs` 并载入内核；其余 13 个同步，内核没启用时报“中央张量：尚未启用”（适配总是先启用）。运行在 Workers 上恒走单线程的同步分支，所以不标异步；浏览器宿主多线程时运行要等工作线程，那里标异步，这是两家宿主唯一的差别。读单精、数学的旧形结果 `{小数}` 在带类型路径上取成裸数。
- 句柄这一步仍是字符串，库签名与云仓前端入口都不变。

## 宿主支持清单

- `宿主支持清单.tsv` 列出云工上可用的豫言操作系统接口与所用的适配，格式与 `../节点/宿主支持清单.tsv` 相同：每行三列（接口名、适配目录、该接口的宿主支持清单文件），应用提供的接口写 `-`，宿主直接以带类型导入提供的写 `宿主`（现在没有）。双宿主构建在云工模式下按这张表选适配，表里没有的接口构建即失败，取代按目录名先找“X云工”再找“X”的猜法（那种猜法会把剪贴板、网页文树、网页消息、网页界面等浏览器适配选进云工产物）。
- 单测 `宿主支持清单。测试.mjs` 核对六件事：清单每行三列、接口名不重复、适配与清单文件存在且接口名称相符；所列适配只依赖云工提供的平台接口包，所依赖的豫言操作系统接口都在清单里；云工宿主、中央张量宿主接口文件里的声明与对照表逐一对应；对照表的旧名在能力表里都有实现（用一个导入全部这些函数的小 Wasm 跑一个事件）；标量结果的导入能调、中央张量未启用时同步报错；写“宿主”的接口，其函数宿主都直接实现。
