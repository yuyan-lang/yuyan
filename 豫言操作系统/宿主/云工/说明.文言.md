# 云工宿主壳说明

此目录乃构建产物中“云工外壳”之源：`入口.mjs`（Worker 之入口与通用类 `豫言持久对象`、`豫言服务入口`、`豫言工作流`）、`宿主.mjs`（能力之桥与事之分派）、`值桥.mjs`（WasmGC 值之转与行之时限）、`句柄.mjs`（不透明之柄表）、`隔离入口.mjs`（Dynamic Worker 子入口）、`隔离运行客.mjs`（文件式程序之 Dynamic Worker 子入口，配浏览器编器宿主 `编译宿主.mjs`，见[隔离运行适配](../../适配/隔离运行/说明.文言.md)）、`平台资料.mjs`（平台资料公约之宿主实：取而缓其只读资料之集；`宿主.mjs` 登原语 `豫言_云工_平台资料列键安全`、`豫言_云工_平台资料读文字安全`，初用乃动态载此篇，一宿主造之一次（动态子工之模表无此篇，静导则子工不起），构建器抄之入产物，见[平台资料适配](../../适配/平台资料/说明.文言.md)）、`编译运行.mjs`（编译运行公约之宿主行器：于内存文件系中行豫言编器 Wasm；由云端编译服务之外壳静态导入而置于 env，不由构建器抄，见[编译运行适配](../../适配/编译运行/说明.文言.md)），及与浏览器宿主共之 `../浏览器/中央张量.mjs`（张量计算公约中央处理器后端之宿主之部：`宿主.mjs` 每事初调 `豫言_中央张量_*` 之原语乃动态导之，单线而造其能；内核之模 `中央张量内核.wasm` 由构建器编之，`入口.mjs` 自 `动态资源.mjs` 取之而以 `中央张量内核模块` 付 `创建云工宿主`，见[张量计算网页适配](../../适配/张量计算/说明.文言.md)）。构建器 `yy双宿主构建` 抄之入产物目录，实务惟书豫言；每事新造一豫言 Wasm 之实例，事与事之间无内存之态。宿主所供之原语，其目见 `库/云工宿主/`；此文惟述**壳层之行**：事类、时限、独占区、应答与交换之限。凡云“本地已验”者，皆得于 Wrangler 4.129.0 之本地 workerd（兼容日期 2026-09-05，SQLite 存储之持久对象）；“云端待验”者，汇于文末。

## 入站之事类

客以 `读取入站事件种类`（或 `云工事件种类`）辨当前之事；同一 Wasm 理诸类。

| 类 | 何者触发 | 说 |
| --- | --- | --- |
| `fetch`、`service-fetch`、`queue`、`scheduled`、`email` | Worker 之处理器 | `service-fetch` 自命名服务入口而来 |
| `durable-fetch`、`durable-alarm` | 持久对象之 `fetch`、`alarm` | 告警之事可读重试次数 |
| `durable-websocket-message`、`durable-websocket-close`、`durable-websocket-error` | 持久对象休眠式套接字之回调 | |
| `durable-transaction` | 豫言于持久对象之事中调 `执行持久事务` | 于 `storage.transaction` 之回调中重入 Wasm，读写施于事务对象 |
| `durable-block` | 豫言于持久对象之事中调 `执行持久独占` | **新增**：于 `blockConcurrencyWhile` 之回调中重入 Wasm，详见下 |
| `workflow`、`workflow-step`、`workflow-rollback` | Workflow 之 `run` 与步骤回调 | |
| `stream-pull`、`stream-cancel`、`html-*`、`websocket-*` | 豫言所造之回调流、HTMLRewriter、出站或入站套接字 | 重入之事，各有独立实例 |

## 每事之墙钟时限与 `执行配置.json`

每事之 Wasm 实例有一墙钟时限：豫言每呼宿主之能则察之，逾则抛 `豫言执行超过时限`，其事败（告警因此为平台所重试）。**默为三十秒**。云端项目之告警须行模型流、编译、发布，常逾三十秒，故时限可依事类而配。

配置置于**应用目录**（`入口。豫` 所在，与 `许可.json` 同处）之可选文 `执行配置.json`，此文**非** `许可.json`，不易许可依绑定种类之结构：

```json
{"事件时限毫秒": {"默认": 30000, "durable-alarm": 900000, "durable-fetch": 30000}}
```

其规：`事件时限毫秒` 之键为事类（上表，`html-*`、`websocket-*` 用其具名；拼误则加载时报错）或 `默认`；值为一至九十万之整数毫秒（十五分，平台后台事之墙钟上限）。择限之序：显配之本类 > 本类之内置默认 > `默认` > 三十秒。`durable-block` 与 `durable-transaction` 内置默认**二十五秒**，且**不受 `默认` 所及**，显配亦不得逾三十秒：此二类之回调行于平台之 `blockConcurrencyWhile` 与事务中，平台于回调逾三十秒则重置整个对象（本地已验），二十五秒之内置线使逾时显为可捕之 `豫言执行超过时限`，而非对象被重置。配置非法（未知字段、未知事类、非整数、越界）则 Worker **加载败**（部署之验即可见），不至运行中默然失效。时限惟于豫言呼宿主能力之界察之，单次外呼自耗时过长不被打断；CPU 之限另属一事，由 Wrangler 之 `limits.cpu_ms` 掌之。Dynamic Worker 子入口（`隔离入口.mjs`）不携配置，仍用三十秒。

用法与云仓之配合：（一）于应用目录置 `执行配置.json`，如云端项目应用置 `{"事件时限毫秒":{"durable-alarm":900000}}`；（二）云仓构建程序 `yy云仓构建` 无须增参——构建时已抄整个应用目录入构建目录，`yy双宿主构建` 自取 `<入口源码所在目录>/执行配置.json`，析而规整之（JSON 非法则构建败），书为产物 `动态资源.mjs` 之导出常量 `执行配置`，无文则书 `{}`；（三）产物之 `入口.mjs` 以命名空间导入读此导出，**新旧相混皆安**：新壳遇旧器之产物（无此导出）则守默认时限，Wrangler 打包时仅一警 `Import "执行配置" will always be undefined`，恰示构建器过旧；旧壳遇新器之产物则略其余出。欲使配置生效，壳与构建器皆须为新版（`./yy云仓构建 准备种子` 以当前语言仓源码重编此器）；（四）同一 Worker 导出数应用之类，则各应用自携其配置，互不相扰。测试可径向 `创建云工宿主({…, 执行配置})` 传对象，`解析执行配置`、`选事件时限` 亦自 `宿主.mjs` 导出。

## `durable-block`：并发独占之区

`执行持久独占` 于宿主之实现为 `云工持久独占执行安全`：宿主呼 `ctx.blockConcurrencyWhile`，于回调中以 `durable-block` 之事重入 Wasm（事中以 `读取持久独占名`、`读取持久独占参数` 取入参，以 `完成持久独占` 定其果一次），回调返后平台复投他事。要点：

- 回调之际所至之事排队，区毕乃投；诸区依次而行（本地已验：五并发之读、候、写于区内恰得一至五，区外并发则遗失更新；区行百毫秒后所至之寻常请，于区毕时乃理）。
- **区内之败不抛于平台之回调**：宿主于回调内捕之，以 `[false, 因]` 而返，外层抛可捕之豫言异。平台原生回调一抛错则重置整个对象（本地已验：实例号易、请败）。
- 参与果为 JSON 文，各不逾八 MiB，宿主以原生 `JSON.parse` 验之；操作名一至一百二十八字节。`durable-block` 之事非 HTTP 之事，读请或设应之术不可用（宿主之 JS 误，豫言不可捕，入口不当呼之）。
- 不可嵌套：区内、事务入口内、非持久对象之事中启独占之区，皆返 `[false, 因]`。区内可启事务（`durable-block` → `durable-transaction`），告警入口中可开区（本地已验 `durable-alarm` → 区 → 事务）。
- 事务之回调自身亦为独占：本地已验事务行时所至之事排队，逾三十秒平台重置对象。

## `durableFetch` 与 `ctx.waitUntil`：先应、败与断

宿主于 `fetch`、`service-fetch`、`durable-fetch` 之事用 `Promise.race([响应已备, 运行毕])`：豫言一设应，`fetch` 即返其应，Wasm 续行（以成流式之应与应后之收尾）；豫言先败，则 `fetch` 拒，调用方得异（平台返五百）。宿主恒以运行之诺付 `ctx.waitUntil`。已确认（本地 workerd）：

- 设应之后所续行者照常完成（本地测：应于六毫秒而返，八百毫秒后之久写成）。**不用 `waitUntil` 之原生对象代码亦同存活**，故本地不见 `waitUntil` 之别；Cloudflare 文档谓 `waitUntil` 于持久对象内不延寿（见 `库/云工宿主/持久对象接口.清单.tsv`），云端之行待验——赖应后长务者，当改用告警（`设置持久告警`）以续，勿倚应后之存活。
- 应既交付而 Wasm 后败：误不能告调用方，宿主书一行 `console.error("[豫言] 响应已交付后运行失败：…")`（旧则默弃之）。
- 客户端中途断开：本地已验豫言之行**不被取消**，续行至终（`sleep` 六次各三百毫秒，断后仍行毕）；豫言惟于下次写流块时知读者已取消（`可写流已关闭`）。云端之行待验。
- 告警之事败则抛，平台依退避而重试；`fetch` 之外诸事不行“先应”。

## 交换之限（何处限之）

| 处 | 限 | 说 |
| --- | --- | --- |
| 带型导入之字符串、字节串 | 宿主不限 | 不经值桥之交换缓冲，惟受 Workers 之内存所约（本地已验十七 MiB 可读入） |
| `宿主.mjs` 之 `限文` | 二 MiB | 惟及先整读其文之原语：`读取请求`、`请求文字`、`服务请求文字`、`持久对象请求文字`、`对象读取`、`回应文字安全`；`Request.text()`、`json()` 经柄桥而呼者**无**此限 |
| 网页入站适配 `读取入站结森正文文` | 二 MiB | 适配自设（于豫言代码中察之），非宿主之限 |
| 网页答复适配 `回应入站文字`、`回应入站结森文` | 二 MiB | 适配自设 |
| 流块、广播 | 供块二 MiB；广播单块六十四 KiB、每订阅之队一 MiB | |
| 久仓（接口层） | 键二千零四十八字节；值二 MiB；列举之果八 MiB；独占区参与果各八 MiB | 见持久事务、持久独占之约 |

站点发布之请含至多四 MiB 之 base64，故不可行二 MiB 之 JSON 正文读取：HTTP 接口适配当另供“有限正文”之读取术，经 `云工请求句柄` 与 `云工物字文字`（即 `Request.text()`）取其原文，本地已验五 MiB、十五 MiB 之体可读入豫言（旧产物逾十六 MiB 则为值桥所拒；带型导入无此限）。为免超大之请先整读入内存，适配当先察 `content-length` 之头，或改用 `读取流块` 累计字节而逾限则取消；请体之上限本身仍受平台所限。宿主与值桥自身于此放宽无碍。

## 云端待验之目

一、`alarm()` 之墙钟上限（文档：十五分）与 `执行配置.json` 九十万毫秒之上限是否相合；CPU 之限（`limits.cpu_ms`）于长告警之影响。
二、`blockConcurrencyWhile` 与事务回调逾三十秒被重置：云端之阈与表现（本地已见）。
三、`ctx.waitUntil` 于持久对象内是否延寿；应返后续行之 Wasm 于云端是否存活；客户端断开是否取消其行。
四、事务回调内告警之变随事务回滚、径写 `storage` 者随事务回滚（本地已见）。
五、事务与独占区行时他事排队（本地已见）；云端输入门之表现。
六、`deleteAll` 是否并清告警（依兼容日期）；告警败而重试之次数上限与退避（本地见重试次数 0、1、2 递增）；处理中 `getAlarm` 为空、败而待试之际为已设（本地已见）。
七、SQLite 存储值大小之上限与逾限之误、键二千零四十八字节之界（本地约二 MiB 之值与二千零四十八字节之键可用，逾限之行未验）。
八、`list` 之序（本地为 UTF-8 字节序，含汉字、全角、增补平面字符）与旧 KV 后端之异。
九、大参数（四 MiB）于云端独占区与请体中之往返及其性能。

## 句柄号与值记号之防伪

- 句柄号非自增之序，乃密码学随机之五十三位安全整数：应用之 JSON 纵书 `{"$句柄":"1"}`，亦指不到现存之句柄，不能借之伪造宿主之物；号唯由宿主之果所授，豫言之库视为不透明之串而传之。
- 参数中之 `$大整数` 记，只受至多四十位之十进制串（可带负号），`$数字` 记只受 `NaN`、`Infinity`、`-Infinity`，余者皆抛，以免畸形之记耗宿主之力或造意外之类。
- 值桥读豫言之字符串，用 `ignoreBOM: true` 之 `TextDecoder`，字符串首之 U+FEFF 得原样授于宿主诸术。
- 犹须慎者：应用所供之 JSON 若原样并入 `云工调用方法` 之参数文，记形之单键对象但不指现存之句柄，则抛错而不默受；适配若受结构化 JSON 之入，仍当于己层拒宿主之记（消息队列之适配已然）。

## 通用句柄桥之白名单

- 全局句柄、构造对象、调用全局及其安全之版，惟得取白名单之全局：同 Node 应用宿主之“可用全局”，另加云工库与适配所用之 `Request`、`Promise`、`Error`、`caches`、`scheduler`。`fetch`、`WebSocket`、`EventSource`、`Function`、`WebAssembly`、`globalThis` 等不在表，取之则报“云工宿主不开放此全局”，应用（含隔离运行中空许之用户程序）不得借句柄桥越外发来源之许（`OUTBOUND_ORIGINS`）与绑定之授。外发之求皆由核许之专用原语。网页上游之约“请求公网HTTPS上游”用专术 `云工公网请求发起`：程序之许 `OUTBOUND_ORIGINS` 含 `https://*`（约所定“许动态公网 HTTPS”）乃许，宿主当场验其址为 https、无用户名与口令，而转址一律 manual；空许之程序用之惟得其错。待办之事：句柄之表犹在，云工宿主库百余原语仍以字符串句柄传物，先改为资源（`资` 形），乃可去句柄之表。

## 标准库之宿主服务

- 标准库之带型导入（导入模块“标准库”）经共用胶水接之：`值桥.mjs` 之 `创建豫言实例` 每次（即每事）新立一套导入之闭包，签名表依模块而存；此处供二十，余皆为桩。带型导入亦每调验其事之墙钟时限，然不经 `值桥.mjs` 之交换缓冲，不受上表十六兆之限。
- 退出进程之码为零则事正常而毕，非零以“豫言程序退出：码”败；标准错误打印行默书于 `console.error`（平台日志之误级），`创建云工宿主` 可授 `错误输出` 以易其所往。余义与诸宿主之分见[标准库之宿主服务](../标准库宿主.文言.md)。
- 产物之 `边界.mjs` 为胶水本体（仓中同名之文惟转出 `../网页汇编/边界.mjs`），动态子 Worker 之模块表亦附之。

## 平台接口之带型导入

- 自第③步，云工宿主库（`库/云工宿主`）与中央张量宿主库（`库/中央张量宿主`）之无体之声（`。接口。豫`）编为导入模块“云工宿主”“中央张量宿主”之带型导入，字段即函名，凡三百三十九与十五。此处尽供之。
- `宿主.mjs` 每事仍以旧原语之名（`豫言_云工_…`、`豫言_中央张量_…`）立一能表，旧名惟宿主内之键，程序不见。`值桥.mjs` 出对照之表 `平台导入旧名`（包名 → 函名 → 旧原语名），依第③步库改之平台导入表而生，其后新增之函依码点之序手补；待办之事：能表改以字段为键，乃去此表。宿主立时依程序之模一算其实导之云工宿主、中央张量宿主之函；每事依对照之表，接能表之实于（模，字段），授共用胶水。对照之表另收诺节宿主、系统库调用、安全外壳密码三包，供诺节应用宿主用之；程序若导云工所不实之包，胶水给桩，调之乃报“接口函数未绑定”。对照表有而能表无之旧名，宿主之疵也，本事即败。
- 每事一套新闭包，不共“当前之事”之态。惟 async 之实（百零五）标“异步”，胶水为之套 JSPI，余皆直调；带型导入每调皆验其事之墙钟时限。参与果依胶水之 JS 形相转：串为 Uint8Array，整为 BigInt，爻为布尔，旧能本皆兼受。
- 中央张量：启用标异步，初调乃动态载 `中央张量.mjs` 而载其核；余十三皆同步，核未启则报“中央张量：尚未启用”（适配必先启用）。运行于 Workers 恒行单线之同步之支，故不标异步；浏览器宿主多线之时运行须待工线，彼处标异步，此二宿主惟一之异也。读单精、数学之旧形之果 `{小数}`，于带型之途取其裸数。
- 句柄此步仍为字符串，库之签名与云仓前端之入口皆不易。

## 宿主支持清单

- `宿主支持清单.tsv` 列云工可用之豫言操作系统接口与所用之适配，其式同 `../节点/宿主支持清单.tsv`：每行三栏（接口名、适配目录、其接口之宿主支持清单文件），应用所供者书 `-`，宿主径以带型导入供之者书 `宿主`（今无）。双宿主构建于云工之模依此表择适配，表所无之接口，构建即败；以代依目录之名先求“X云工”后求“X”之猜（其猜或以剪贴板、网页文树、网页消息、网页界面诸浏览器之适配入云工之产物）。
- 单测 `宿主支持清单。测试.mjs` 核六事：清单每行三栏、接口名不重、适配与清单文件存而接口名称相符；所列适配惟依云工所供之平台接口包，所依之豫言操作系统接口皆在清单；云工宿主、中央张量宿主接口文件之声与对照之表一一相应；对照表之旧名于能表皆有其实（以一导尽诸函之小 Wasm 行一事验之）；标量之果之导入可调、中央张量未启则同步而报；书“宿主”之接口，其函宿主皆径实之。
