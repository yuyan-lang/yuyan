# 宿主壳一致性验证

本目录验证云工宿主壳（`../宿主.mjs`、`../入口.mjs`）与三个 OS 接口——[持久事务](../../../../豫言操作系统接口/持久事务/规范.汉语.md) 0.2.0、[持久告警](../../../../豫言操作系统接口/持久告警/规范.汉语.md) 0.1.0、[持久独占](../../../../豫言操作系统接口/持久独占/规范.汉语.md) 0.1.0——以及每事件时限配置、`durableFetch` 响应先返与 `waitUntil`。全部用**真实豫言 Wasm**，持久对象由本目录的模拟提供，另有一套对本地 workerd 的验证。

## 文件

| 文件 | 内容 |
| --- | --- |
| `模拟持久对象.mjs` | 可复用的 Durable Object 模拟：`storage`（get/put/delete/list/deleteAll/告警/事务）、输入闸、`blockConcurrencyWhile`、`waitUntil`、`id`，以及把 `fetch`/`alarm` 经输入闸交给宿主的 `模拟持久对象`（`触发告警` 模拟平台送出告警与失败重试） |
| `模拟慢网络.mjs` | 会等待 `ms` 毫秒的模拟上游，记录请求区间，用来判断并发或独占 |
| `持久对象壳.test.mjs` | 36 个 Node 测试：直接仓、事务、告警、独占区、时限配置、响应先返、大值与桥上限 |
| `额度回归.test.mjs` | 云仓额度应用的原验收断言（旧接口构建，须仍通过） |
| `应用/持久对象壳一致性应用/` | 试验应用源码（包描述存为 `.txt`，避免被 `yy豫构` 的全仓库包发现解析） |
| `本地工作者验证/` | 可选：对本地 workerd 的真实验证脚本与差分比对 |

## 复跑（私有暂存）

1. 建私有暂存，并让暂存里的 `豫言操作系统`、`豫言操作系统接口`、`工具` 指向待验的语言仓（默认即语言仓本身）。
2. 用暂存里**同版本**重编的 `yy双宿主构建`（工具源码 `工具/双宿主构建/入口。豫`）构建两个应用：试验应用（本目录 `应用/持久对象壳一致性应用`）与云仓 `应用/豫言体验/额度应用`。草稿区的 `建应用.sh <暂存> 云工 <应用目录> <输出名>` 会完成“绑定依赖的 OS 接口→写包上下文→`yy双宿主构建`→`yy豫言操作系统装载包`”四步，也可按云仓 Makefile 的同一顺序手工做。云仓的额度应用包描述没有列出 `豫言操作系统*` 依赖（云仓 Makefile 经包上下文提供），用草稿脚本构建时须先复制应用目录并在「依赖」里补上网页入站、网页答复、环境文字、时间、持久事务五个接口包。
3. 运行：`env "持久对象壳产物=<暂存>/dist/持久对象壳一致性应用" "额度应用产物=<暂存>/dist/额度应用" node --test 持久对象壳.test.mjs 额度回归.test.mjs`（Node 需支持 JSPI，如 v26）。测试所需的 `执行配置` 由试验应用目录里的 `执行配置.json` 经构建器写入 `动态资源.mjs`，个别用例另向宿主直接传配置对象。
4. 云仓迁移后应把两个 `*.test.mjs` 放进云仓验收，产物路径改为云仓构建目录。

## 模拟与本地 workerd 的关系

`模拟持久对象.mjs` 的行为按 Wrangler 4.129.0 本地 workerd（兼容日期 2026-09-05，SQLite 存储）实测校准：`list` 按 UTF-8 字节序；事务回调运行期间输入闸关闭、其他事件排队；事务回调内的告警变更和直接 `storage` 写入随事务回滚；回滚后再用事务对象报 `Cannot put() on rolled back transaction`；`blockConcurrencyWhile` 回调抛错或超过 30 秒记为对象重置；告警处理开始时告警视为已清除，失败后视为已设置以待重试。`本地工作者验证/` 里的差分比对把 82 项操作分别送给模拟和本地 workerd，输出完全一致。与真器仍有的差异：模拟没有输入门对存储读写的细粒度保护、没有真实的对象休眠与驱逐、`waitUntil` 只记录不延寿、告警不会自行按时触发（用 `触发告警` 手动送出）。这些以及其他云端行为见 `../说明.汉语.md` 的“待云端验证清单”。

## 试验应用协议

请求体 `{"op":…}`，应答纯文本：`OK`；`K|事件种类`；`E|值 JSON`（存在）与 `M|`（缺键）；`D|1`/`D|0`；`L|列表 JSON`；`T|事务结果`；`B|独占结果`；`A|1|时刻`/`A|0|0`；`R|重试数`；`N|长度`；`X|错误消息`。主要操作：`put`/`get`/`del`/`list`/`clear`（直接仓），`tx`（`args` 是事务参数 JSON，`name` 选用例）、`tx-outside`，`alarm-get`/`alarm-set`/`alarm-del`/`retry`，`block`（`name`、`args`）、`block-big`、`block-len`、`tx-big`，`counter-plain`（非独占的读—等—写）、`sleep`、`early`、`early-fail`、`boom`、`put-big`、`getlen`。请求头 `x-op: body-len` 时直接读取原始请求体并返回长度。
