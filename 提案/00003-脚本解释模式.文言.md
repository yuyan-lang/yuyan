# 提案 00003：脚本解释之式

| 项 | 文 |
| --- | --- |
| 号 | 00003 |
| 状 | 草案 |
| 提于 | 2026-10-04 |
| 所及 | 新源文之种 `。脚本。豫` 及其行之则；编译器核心前端逐组之入口；新库「脚本解释」（读句、求值、交互求值、库之缓存、句之缓存、代宿主之务）与「壳命令」；豫言操作系统默认之壳之行脚本、交互求值与所入之书（与豫言之句合一），并一新宿主之务；内核之块池与每任务内存之限；宿主之命令行工具 `yy脚本`；包源之收、造盘与全树之测之相应之则；云仓网页之壳之书；《执行与编译》《词法与语法》之相关规范 |

此篇为豫言增脚本解释之式之提案：以 `。脚本。豫` 为尾之文，乃普通之豫言源码，解释器逐行而读，每成一句，即验而行之，不待预编为 Wasm。脚本径行于豫言操作系统之壳，其用如 shell 之脚本：运行程序、读写文件、取参数与环境变量、依退出之码而分；欲书其理，则用豫言之条件、递归与模式之配。壳之交互所入，亦与豫言之句合一：每行交同一解释器求值而印其果，会话中之定恒有效。前端与编译器共之，故脚本与同源编译之程序，所受同、所得同；后端易为于擦除后之树径求其值之器。同一解释器亦行于 Node 宿主。

与[汉语稿](00003-脚本解释模式.汉语.md)相应。

## 一、所议之事

| 号 | 议 |
| --- | --- |
| 议一 | 增源文之种 `名。脚本。豫`：其文为普通之豫言源码，文法与类之系皆不易；顶层之裸式即所行之语，依《执行与编译》行一“源文件顶层裸式会执行”之旧则，以次行之。脚本不可导入；「收集包源码」与造盘之「编译预置们」皆略之，造盘时原样入盘 |
| 议二 | 逐句而行：逐行而读，依《词法与语法》语一切句之则（圆括号深零处之 `。`），句成即处之；`乃` 句与紧随同名之定义句合为一组。每组先过与编译器同一之前端（语法分析、名称解析、验类、模式展开、类型擦除），即求其值，然后读次句 |
| 议三 | 误与退出之码：某组有语法或类之误，报误句之文、起止之行与其诊，退出之码二，前诸句之效存焉；未接之异常，交标准库所录之顶层之处（“未捕捉的豫言异常：…”，退出之码一），另附其句之位；`退出进程` 所予之码照用；脚本中之陷阱，沿客体二号之码（整数除零与无效之转 125、数组越界 127、栈溢 122、堆存不足 120）；Ctrl-C 为 130。选项 `--先查` 先以全文过前端一遍，无误乃行 |
| 议四 | 求值之器：所入为“擦除后形式”之树（与编译器之缓存同段）；值依《总纲》总三无类之中间值而表；以显续延之栈循环而求，尾调用与深递归皆不占宿主之栈；异常、提前之返、递归之单元，依《执行与编译》行二、行三 |
| 议五 | 原语与宿主之导入：树中 `豫言_` 之原语，求值之器逐一实之；`宿主导入：模块：字段：签名`，依签之界形（《网页汇编接口》网五）转其参与果，交解释器自身同名之导入。无所代者，循宿主之法，召时报“接口函数未绑定：模块.字段”。程序名、命令行参数、退出、工作目录与环境变量，改指脚本自身者 |
| 议六 | 隔离：能陷之原语（整数除与取余遇零、小数转整数越界、引用数组越界等）先验而后召；失则中止进程之宿主导入（如读不存之文），先查其径，查不过以 1 终脚本；续延之栈设限（缺省一千万帧，嵌之者可改），逾之即报“栈溢出：递归过深”。此诸误惟终脚本，解释器所居之进程照常而行 |
| 议七 | 库之缓存：脚本所导之模，经同一前端而处，存前端所需之接口与求值所需之擦除后形式，其式用今之树码；宿主上应需而生且存之；豫言操作系统上由造盘预生、随盘只读。模始见引时，依定义之序初始化一次 |
| 议八 | 句之缓存：以（解释器之版、库缓存之版、自脚本之首至本组之末之文之摘要）为键，存每组过前端之果；句未改者，重行时略前端。造盘时为预置树中之脚本预生之 |
| 议九 | 豫言操作系统：解释器以库之形链入默认之壳，脚本行于壳之任务，故脚本能以内核惟一之子进程槽运行程序。`「运行」于『路径』…` 遇 `。脚本。豫`，则于壳内解释而行，余皆照旧；`「脚本」于『路径』` 依后缀而分，`.txt` 命令之脚本照旧逐行而行。脚本既终，壳复其原工作目录与环境变量。增宿主之务「取中断挂起」，供求值之器轮询 Ctrl-C（新 ABI，2026-10-04 用户已允） |
| 议十 | 宿主之工具 `yy脚本`，与壳同用一库：`yy脚本 路径 参数…` 以行，`--只查` 惟过前端，`--先查` 先验后行，`预备` 生库之缓存与句之缓存，不予路径则入交互求值。首行以 `#!` 起者，略其行 |
| 议十一 | 编译之式照旧：同一脚本可由 `yy豫构.wasm 文件` 编为 Wasm，顶层之裸式于模初始化时以次而行。二式依《总纲》总〇之“源语言兼容”而核，惟出误之时不同；全树之测，于有所期之出之脚本，二式皆行，逐字而较 |
| 议十二 | 壳命令之库：壳之命，以豫言之库「壳命令」予之，成员之路沿 `命令登记`（模「文件」中有「读取」「写入」等），不与 `寻观「标准库」之书` 所已出之名同（演示之「加」改用标准库同名之函）。命照壳之习印其果、返「有」；欲取值以编程，用标准库。参数之数可变之「运行」，改受参数之列。脚本与壳中皆书 `「文件」之「读取」于『/数据/说明.txt』` |
| 议十三 | 不为：于系统内编为 Wasm、为脚本别开进程、脚本相导、求值之器之加速（库函直连、即时编译）。留俟后日 |
| 议十四 | 交互求值（2026-10-04 用户定）：壳之每行交解释器，诸括皆闭即成一句，句末之 `。` 可省，未闭则续行；会话中之定恒有效；出误惟弃此句；裸式之值类为「有」则不印，余依类印为可贴回之豫言之书，值为无参之函则以「元」召之；Ctrl-C 断方求值之句 |
| 议十五 | 壳之所入与豫言之句合一（2026-10-04 用户定）：壳惟受豫言之句，字符串之参书 `『』`，角引号裹参之旧正式句式不复受；会话之始，犹已导标准库与壳命令之库。惟召壳命、参皆字面、名未为会话之定所蔽之句，由快路，依命之签核之而径召，其果同全前端。补全之候取于解释器之名境；`.txt` 命令之脚本，每行依交互之一句而处；云仓网页之壳随之改为豫言之句，别行之 |
| 议十六 | 放大内存（2026-10-04 用户定）：裸机每任务线性内存之限，由 512 页（32 MiB）放至 8192 页（512 MiB）；内核之块池由定 32 块（64 MiB）改为依启时之物理内存而分，位图与恒等之别名随之而宽；`yy豫言系统` 与诸 QEMU 之验之内存放至 2 GiB |

## 二、所以然

### 今之诸壳

下据 2026-10-04 yybs（8859ae0d1）与云仓之源码、文档而理之。

| 实现 | 所在 | 所行之处 | 所入之书 | 能书其理否 | 何以运行豫言程序 |
| --- | --- | --- | --- | --- | --- |
| 默认之壳 | `豫言操作系统/裸机/壳/壳。豫` | 豫言操作系统，客体二号解释而行 | 正式句式 `「文件」之「读取」于「入口。豫」` | 否：无变量之引、条件、循环与函数 | `「运行」于「/程序/甲.wasm」…`，程序须先编于宿主 |
| 早期整数命令之壳 | `豫言操作系统/裸机/库/裸机后端/用户命令壳。豫` 等 | 裸机内核之用户任务（降为机器码） | 以空白分词 | 否 | 惟运行整数子集之 Wasm |
| 豫言终端（yysh） | `应用/开发工具/豫言终端/` | Node | 以空白分词，支引号与转义 | 否 | 管理之命转于 `yy豫构` 诸器；外部程序依 PATH 而行 |
| 网页之壳 | 云仓 `应用/豫言云工作台/` | 浏览器（界面之命）与云端 Worker（文件、编译、运行） | 正式句式，成员二级、参数至多八；亦受空格句式 | 否：一次一命，无变量、管道、重定向 | `「程序」之「运行」`：编于云端，再行于隔离之 Worker（CPU 一秒） |
| 终端浏览器之脚本 | `应用/开发工具/终端浏览器/脚本*。豫` | Node | 网页中之 JavaScript 子集 | 能 | — |

所见数端：

1. 能书其理者，惟终端浏览器：其所解释者，网页中之 JavaScript 子集（词法、递归下降、遍树而求值，见 `脚本运行。豫` 之「执行」），与豫言无涉。仓内无于运行时求豫言语法树或中间之表之值之解释器（底层后端惟有编期之常量求值），亦无交互求值。
2. 默认之壳之 `脚本` 命（`壳。豫` 之「运行脚本」）读全文，空行与以 `#` 起之行略之，余者逐行依正式句式而析，先印 `+ 行` 后行之，误则印 `错误：…` 而续次行；脚本中不得复用 `脚本` 或 `退出`。豫言终端于标准输入出自文件或管道时，亦逐行而行（犹 `yysh < 文件`）。二者皆惟识己之命：行与行间不能传值，亦不能依果而分，后命不能取前命之退出之码。
3. 默认之壳与网页之壳之正式句式，已为豫言成员与施用之书：`之` 连成员，`于` 引参数。其异惟在参数：壳以角引号中之文为原文，豫言之字符串书于 `『』` 中。
4. 2026-10-03 之提交 1bb76a637，改默认之壳交互与脚本之入口皆为正式句式；旧之重定向（`>`、`>>`、`<`）与顺序管道（`|`）之码犹在，已无召之者（`壳。豫` 首之待办事项）；`壳/测试/` 之输入之文犹为旧句式。

### 系统中无编译器

程序皆离线编于宿主：`yy豫言系统 构建` 以预置目录树中以 `。豫` 为尾之文编为 `.wasm`，书于盘（`豫言操作系统/裸机/库/裸机后端/系统构造。豫` 之「编译预置程序」「编译预置们」，经宿主子进程召 `yy豫构.wasm 文件 … --编译器 yy4_bs.wasm`）。于系统中改源码，不能复行；欲于系统中为带判断之自动，惟返宿主改源码、复造盘。每一既编之程序，连标准库约 340 KB 起（《示例》），而盘缺省 32 MiB，双区日志可存约 16 MiB。

### 前端之费

1. **全编太迟**。2026-10-01 本机构建之志（`.yy构建日志/`）：`yy豫构.wasm 文件 豫言操作系统/裸机/示例/程序/你好。豫`，缓存已在，凡用 5971 毫秒。标准库所依之闭凡 54 模，各过依赖分析、语法解析、验类、跨模优化、闭包转换五务，加最终链接，凡 271 务（并行 24 路）；`你好。豫` 自身之五务，惟占 95、90、124、72、46 毫秒，最终链接 260 毫秒。2026-10-04 本机负载约八时，编一小测试之文，同流而用 15.2 秒。脚本若每行皆由此路，惟启已须数秒至十余秒。
2. **库之产不小**。根目录 `yy4_bs.wasm`（10-03 所构，先于树码之缓存）之缓存中，标准库 54 模：检查后对象 2.79 MB、检查后定义 3.62 MB、名称解析资料 1.36 MB、擦除后形式 1.79 MB（皆 JSON）；对之，标准库源码（除测试）0.32 MB。今源码之阶段缓存惟书树码（`编译文件缓存工具。豫`）；提案 00001 实测，树码约为同文 JSON 之五分之一至二十一分之一（第十节）。云工之编译运行，以全标准库之资随编译器而发：gz 约 2.6 MiB，解后之 JSON 约 57 MiB（`豫言操作系统/适配/编译运行/说明.汉语.md`）。
3. **求值之面甚小**。标准库之擦除后形式，惟见二十一种节点：函数调用、参数、拉姆达抽象、内联虑、文件定义引用、外部之召（解析后外部调用节点）、元组构造、元组解构、唯一构造器序数元组及其二种投影、爻分支、递归、展开后内建、整数、字符串、小数、空值、擦除后类型、续延调用及其返回。外部之召凡 157 名：`豫言_` 原语 92；`宿主导入：标准库：…` 65，带界之签，如 `宿主导入：标准库：打印行：串→元`。

### 客体二号之速、存与务

- **速**：客体二号于原生宿主解释编译器，单线程编标准库每文约 45 秒（《豫言操作系统总体架构》2026-09-28 之进）；同一编译器于 Node 冷编打印探针连标准库凡约 5 秒（《原生工具链》，pit-mac M2 Max），折每文约 0.1 秒，解释约迟五百倍。预编二之后，原生 5.24 秒对 Node 4.98 秒，其比约 1.05（同上，2026-10-02）。裸机无预编（预编惟在 `yy原生生成` 所生之原生可执行之文），壳由客体二号解释而行，QEMU 又有模拟之费；QEMU 上解释之速，犹未测。
- **存**：每任务之线性内存至多 512 页（32 MiB），其中值栈、标签栈、帧栈等约 6 MiB，余予模、GC 之堆与文件之缓冲；内核之物理块池凡 64 MiB，二任务共之（《客体二号》“限制”）。以为参照：Node 冷编打印探针连标准库，峰约 0.52 GB（《原生工具链》）。
- **文件**：经标准库读写文件，由裸机底层句柄，每柄内容之缓冲 409600 字节（`客体二号/裸机底层句柄。豫`），更大之文，依码推之，不能读写。JSON 缓存中最大者（`多态列工具` 之检查后对象，412084 字节）已逾之。子进程程序之限，码中为 64 MiB（`布局。豫` 之「最大主程序长」），文档犹书 4 MiB。
- **务**：构建宿主之「存放包上下文」（原语 73），裸机未实之，而编译器核心每编皆召之；`编译过程工具。豫` 又有一顶层之值，于模初始化时即召「获取当前程序SHA256」。

故于裸机，每行皆自首复行前端，其费太高：启时载标准库之接口、每组验类，皆当以“迟五百倍”度之，存亦窘。本提案因以“前端之果能存则存”（议七、议八）、壳中简命之快路（议十五）与放大内存（议十六）入设计，而置实测于施行之首步。

## 三、所求与所及

所求：

1. 豫言操作系统之壳中能径行 `。脚本。豫`：运行程序、读写文件、取参数与环境变量、依退出之码而分，不经宿主之编。
2. 脚本与同源编译之程序，受拒之界同，求值之迹与所出同（《总纲》总〇之源语言兼容）；惟出误之时不在此列。
3. 逐句而行：前句先效；误报于误句。
4. 脚本之误（含除零、越界、栈溢）惟终脚本，壳照常而作。
5. 宿主之 `yy脚本` 行同一脚本，以供开发与全树之测。
6. 速：第十四节之数，先为暂定之的，施行首步实测而后修之。
7. 壳之交互所入即豫言之句：惟召壳命之简句，其速如今；余句照常验之、求其值而印其果。
8. 内存既放大，壳能容解释器与常驻之库，而犹能起子进程。

所及：新文之种及其规范；编译器核心前端逐组之入口；新库「脚本解释」「壳命令」与新工具 `yy脚本`；默认之壳之行脚本、交互求值与所入之书；内核之块池与每任务内存之限；造盘之器；全树之测之则；云仓网页之壳之书。

今不及者：第一节议十三所列诸事；壳之重定向与管道（壳自身之待办，成则于脚本与交互亦效）；内核任务槽之数；云仓网页之壳之实施（别于云仓为之）。

## 四、设计：脚本之文

### 身

- 后缀 `。脚本。豫`，文置何处皆可；豫言操作系统上习置于 `/脚本/`。
- 其文依《词法与语法》之文法而析，用同一类之系，无新语法。
- 「收集包源码」（`库/构建基础/包定位。豫`）略 `。脚本。豫`，如略 `。包。豫`，故脚本虽置于包目，亦不作模而编；模之寻惟识「普通模块后缀们」，脚本本不可导入。
- 造盘之「编译预置们」以 `。脚本。豫` 原样书于盘，不编。

### 导入

- 书法照旧，如 `寻观「标准库」之书。`；导入之句亦一句，行至之乃载所导之模。
- 导入之析惟识包上下文（`语法分析/导入解析。豫`）。解释器为脚本合一包上下文：脚本自为一包，无包之描，所依为解释器所能见之诸包——宿主上，仓中依豫构之则所见之包；豫言操作系统上，随盘库缓存所有之包（缺省为标准库与壳命令之库）。

### 行之序

- 顶层诸句依所见之序而处：导入之句载模；定义之句求其值，存于脚本之全局之表；裸式求值而弃其值。
- 所导之模，始见引时初始化一次，所依先于用之者（《执行与编译》行一）。
- 跨句共用之值，当书为顶层定义 `「名」者 … 也。`；顶层 `虑` 之绑惟在本句之内。同名再定，沿编译器之则：引先中较早之定（《类型与模块》）。欲随行而变之量，用「新引用」「写引用」。

### 参数、环境与退出之码

- `获取命令行程序名` 得脚本之径，`获取命令行参数` 得脚本之后之参数，其形同于编译之程序。
- 环境变量与工作目录：脚本始时取召者之所有；行于壳中者，脚本既终，壳复其原，同于运行子进程。
- 退出之码：行毕无事为 0；`退出进程` 所予之码照用；未接之异常 1；语法与类之误 2；陷阱沿客体二号之码（议三）；Ctrl-C 130。

### 与编译之式之关

脚本亦合法之程序之文：`yy豫构.wasm 文件 甲。脚本。豫 --输出 甲.wasm` 照常而编，诸句于模初始化时以次而行。二式惟一处异：编译之式于行前尽报语法与类之误，解释之式行至其组乃报。`--先查` 令解释之式亦先验后行。

## 五、设计：逐句而行

### 读句

- 逐行而读。词法之扫持圆括号之深；名称 `「」`、字符串 `『』`、注释 `「：…：」` 中之 `。` 皆在令牌之内，注释可嵌。遇深零之 `。` 即得一句：一行可数句，一句亦可跨数行；文末无句号之非空尾句照常而处（皆同语一）。
- 首行以 `#!` 起者，略其行，惟脚本之式如是。
- `乃` 句姑不处，待次句：次句为同名之 `者` 或 `即` 之定，则合为一组；否则报误，同编译器“末尾独立签名、不同名或中间夹其他声明均拒绝”之则（语四）。

### 每组之处

1. **语法分析**：默认之符集有定，用户不能自定其符；编译器本逐句而析（`语法分析/抽象语法分析。豫` 每句召「解表达式默认操作符及语义标记」），与导入无涉。
2. **名称解析**：顶层名称解析本为依句序而进之循（`名称解析/名称解析。豫` 之「进行文件名称解析顶层」），导入惟效于其后之句。解释器存此循之状，每组进一步。脚本自身之定，以“文件定义引用”指脚本之文，文之身取脚本之绝对路径。
3. **验类**：「进行文件定义列检查」（`类型检查/文件结构检查。豫`）本为逐定而进、携「命名环境」而下之循，每定之后以「添加已检查文件定义」扩其境；所依之模之检查后定义，本应需而读（`类型检查/类型检查基础。豫` 之「文件定义引用类及物」）。析循之一步为可独召之入口；解释器每组召之一次，留其所返之境。
4. **模式展开与类型擦除**：此数步（模式展开、类型擦除、续延调用展开、隐式参数擦除）本逐定而变，于本组之定各行一次。
5. **求值**：依序求本组诸定；定之值存于脚本之全局之表，裸式之值弃之。

先例：着色分析于内存以次行词法、语法、名称解析、验类，其果惟书于内存之缓存（`着色翻译/着色分析。豫` 之「写内存检查后定义」）。解释器循之，不书编译之缓存。

所当避者：前端之入口不得召「存放包上下文」（裸机未实之）；编译之配多置于全局可变之引（`编译数据/编译配置/全局配置。豫`），解释器始时一次设之。

### 出误

- 前端于某组报误：印误句之文、起止之行与其诊，退出之码二。语法之误之诊本无精确之行列（`表达式解析。豫`），类之误可借源码范围之标而定其行列。
- `--先查`：先以全文逐组过前端，不求值；无误乃自首求值（是时前端之果径复用之）。
- `--只查`：惟过前端，以供全树之测与 CI 验脚本。

## 六、设计：求值之器

### 所入

擦除后形式之「表达式」（`库/编译器核心/编译数据/抽象绑定树结构/抽象语法树/抽象语法树数据。豫`）。第二节所计二十一种节点之外，擦除后形式或见之他节点，求值之器亦逐一实之；遇未实之节点，报“解释器尚不支持的节点：名”而终脚本（待办事项）。

### 值

《总纲》总三无类之中间值：单位、整数（64 位）、小数（binary64）、爻、字节串（字符串、字节串）、字节缓冲、元组、构造器之值（序数加载荷）、闭包（参数之数、函数之体、所捕之境）、引用与引用数组、宿主之资（界形“资”）、逸之续延（以当前续延调用所得）。

### 境与全局

- 局部变量依 de Bruijn 之序取于境；多参数拉姆达一次而绑相连之数参。
- 文件定义引用依（文之身，定之名）查模之全局之表；模未初始化，则先初始化之。
- 递归节点依《执行与编译》行二：先分单槽之递归单元，乃求其定，填其槽，返其闭包。

### 控制

- 求值为一循，其状为（待求之式或已得之值、境、续延之栈）；续延之栈置于堆。
- 尾位之召不压新帧，故以尾递归所书之循不增续延之栈；非尾之召，其深惟受续延之栈之限，与宿主之栈无涉。
- `豫言_抛出异常` 循续延之栈求最近之尝试运行之帧；`豫言_尝试运行` 压处理之帧，乃召其操作。异常至栈底，则召标准库以 `豫言_设置当前异常处理器` 所录之顶层之处，其行同编译之程序。
- 续延调用（以当前续延调用）压带新标识之标帧；召逸之续延时，循续延之栈求其标识之帧，送值而返，所经之尝试运行之帧不截之。标识已离栈，则报误而终脚本（《总纲》总一：失效之续延无定义）。
- `退出进程` 不经异常：求值之器径弃续延之栈，带码而终脚本。
- 每万步问中断一次（议九）；见中断则以 130 终脚本。

### 原语

92 `豫言_` 原语，各对解释器自身可召之同一运算：整数与小数之算、字符串与字节串、字节缓冲、引用与引用数组、类型之转、异常。能陷者先验之（议六），验不过则带客体二号之码而终脚本。

### 宿主之导入

- 外部之召，其名如 `宿主导入：标准库：打印行：串→元`：前二段定交何导入，签依网五之界形（整、小、爻、串、元、资、组、列、变），转于求值之器之值与解释器自身之值之间。
- 解释器所居之宿主实何导入，脚本即能用何者：Node 工具宿主实标准库 65 之 60（读终端按键、出入原始输入之式、二拼音之转为桩）；客体二号于 65 皆有所映（裸机上 TCP 返误，无硬件随机数则取熵败）。嵌解释器之程序（如壳）可别录其接口之函。余者召时报“接口函数未绑定：模块.字段”，同宿主之法。
- 改指脚本自身者：`获取命令行程序名`、`获取命令行参数`、`退出进程`；行于壳中者，又加 `切换当前工作目录`、`获取当前工作目录` 与环境变量（脚本终后复之）。标准之入出与标准之误，即用解释器所居进程者。
- 子进程之类之导入，遇 `。脚本。豫` 之径，则于同一进程嵌而解释之；取输出（「获取输出」）时，所嵌脚本之印书于缓冲。
- 宿主导入之败，多为中止进程：2026-10-04 于 Node 行例一之编译之产（读不存之 `/数据/说明.txt`），宿主抛 ENOENT，进程以 1 退。解释器于读、写、删、列目录、切换目录先查其径（议六），免累解释器所居之进程。

## 七、设计：库之缓存

- **所存**：每模存二物：前端处导入所需之产（名称解析资料、检查后定义等，同编译器缓存之数种），及求值所需之擦除后形式。其式用今之树码，其积约为 JSON 五分之一以下，单文亦远小于裸机底层句柄之 409600 字节。
- **所生**：以解释器自身之前端生之，不借 `yy4_bs.wasm` 之缓存，故其产与读之之码恒为同版。键为（模之身、源码之摘要、库缓存之式之版）。
- **宿主上**：`yy脚本` 始导某包时逐模生之（所依在先），置于仓根之 `.yybuild/脚本库/`，此后径读之。
- **豫言操作系统上**：造盘时于宿主行 `yy脚本 预备 标准库 壳命令 --输出 目录`，书其目于盘之 `/库/脚本库/`，只读。脚本导盘上所无之包，则报“脚本库里没有包：名”。
- **所载**：惟载实用之模；前端应需而读检查后定义，模之擦除后形式于始引其定时载而初始化之。行于壳中者，已载之模留于壳之内存以供后之脚本复用（常驻），重启乃复载。

## 八、设计：句之缓存

- 键：（解释器之版、库缓存之版、自脚本之首至本组之末之文之摘要）。前缀同则境同，故所中之组可径取前端之果而求值。
- 值：本组之擦除后形式，及后诸组验时所需之境之增（本组之检查后定义与名称解析之状）。
- 所置：宿主上置于 `.yybuild/脚本句/`；豫言操作系统上置于 `/缓存/脚本/`，以脚本之绝对路径别之。
- 造盘时，为预置树中每一脚本行 `yy脚本 预备 --句缓存`，故随盘之脚本于系统中初行即不必过前端。脚本于系统中既改，惟所改之处及其后之组须复验。

## 九、设计：接于豫言操作系统

- **链入壳**：默认之壳依「脚本解释」，脚本行于壳之任务。内核惟二任务槽，子进程不能复起子进程；脚本若为子进程而行，则不能复运行任何程序。行于壳中，则可用其惟一之子进程槽：「子进程」之「运行并继承标准流」等照常可用。
- **分派**：`「运行」于『路径』于「列」【…】` 之径以 `。脚本。豫` 为尾者，于壳内解释而行，退出之码照常而印；余者照旧装载 Wasm。`「脚本」于『路径』` 以 `。脚本。豫` 为尾者同上，否则依第十节逐行行命。
- **中断**：首任务见 Ctrl-C，惟记“中断挂起”（`客体二号/平台。豫`）。增宿主之务「取中断挂起」（`豫言操作系统/裸机/宿主服务。接口。豫`，取而清其挂起），求值之器每万步召之一次。此为新应用 ABI，2026-10-04 用户已允（议九）。
- **标准之流**：脚本之出即壳之出。壳异日复重定向与管道，但以脚本之印亦接于同一出口，脚本亦可重定向、入管道。
- **所链**：壳惟链前端诸步与求值之器。编译器核心有于初始化或每编时召构建宿主之务之模（`编译过程工具。豫` 之「当前编译器可执行文件标识」，初始化时召「获取当前程序SHA256」），壳当避之；不可避，则由客体二号补此诸务。
- **内存**：前端、求值之器与常驻之库皆在壳之任务，今之 32 MiB 不足，依第十一节放大之。
- **体积**：壳今约四十六万字节（《终端编辑》）；加前端与求值之器，度在 2–3 MB 之间（编译器 `yy4_bs.wasm` 全体 4.16 MB），由客体二号已有之初始大程序之路。

## 十、设计：交互求值与壳之所入合一

### 一行即一句

- 壳读一行，交解释器之读句之器：名称、字符串、圆括号、方括号与注释皆闭，则此行即一句，句末之 `。` 可书可不书，一行有数句则以次处之；未闭则印续行之示 `…> `，续读次行。
- 会话之始，犹已行 `寻观「标准库」之书。寻观「壳命令」之书。`。
- 会话即边书边行之脚本：前之导入与定，于后句皆有效。前端、求值之器与已载之库，常驻于壳之内存。

### 出误与中断

- 前端或求值出误：印其诊，弃此句（其定不入境），续读次行。脚本之式则出误即止（第五节）。
- Ctrl-C：编辑时照旧弃此行；求值时断此句，返于提示，会话之境存焉。
- `「退出」` 终壳，同于今；交互时召 `退出进程`，亦终壳。

### 印值

- 裸式之值之类，由此句之验类予之。类为「有」，则无所印。
- 值为无参之函（类为 `化「有」而…`），则以「元」召之，乃依其果而处；故 `「环境」`、`「帮助」` 之类无参之命，可不书 `于「元」`。此惟于交互成立，脚本中犹须书之，与编译之式一。
- 余依类印为可贴回之豫言之书：整数 `「42」`、小数 `「1.5」`、爻 `「阳」`、字符串 `『…』`、列 `「列」【…】`、元组 `（… 与 …）`、构造器 `「名」于 …`（构造器之名取于验类之境）；函数、引用与宿主之资，印为 `（函数）`、`（引用）`、`（资源）`。

### 快路

- 每行皆过全前端，于裸机太迟：前端由客体二号解释而行，约迟五百倍（第二节）。
- 故形如 `「名」于 参…` 或 `「名」之「名」于 参…`、参惟字符串与整数之字面或其列、名为「壳命令」中之命且未为会话之定所蔽之句，径依其命之签核参之数与种而召之，不载库，不过全前端。
- 快路所识之书，为全书之子集，其果相同；全树之测，于快路所能处之句，二路皆行，逐字而较。

### 壳命令之库

- 诸命皆在「壳命令」之库，成员之路沿 `命令登记`：「回显」「运行」「设」「取消」「环境」「日期」「脚本」「帮助」「退出」，及「文件」之「当前」「切换」「列出」「读取」「写入」「追加」「复制」「移动」「建目录」「删除」。
- 不与 `寻观「标准库」之书` 所已出之名同：去演示之「加」，`「加」于「12」于「30」` 即标准库之加，印 `「42」`。施行时逐一核之（如 `控制/异步。豫` 亦有「运行」）。
- 命照壳之习印其果、返「有」，交互时不复印之；欲取值以编程，用标准库（如「文件系统」之「读文件」）。
- 参数之数可变之「运行」，改受参数之列：`「运行」于『/程序/你好.wasm』于「列」【『甲』，『乙』】`；可省之参改为必予，如 `「文件」之「列出」于『.』`。
- 壳自行其命亦召此库，交互、脚本与快路所用同一实现。

### 输入之法与补全

- 已知之名之候，取于解释器之名境：所导之名、壳命、会话中之定；`之` 之后予其模之成员，`于` 之后予参数，路径照旧取今目录。
- 参数之位之字符串书 `『』`：所选路径之候填为 `『…』`，回车时以自由之参裹为 `『』`（纯数裹为 `「」`），中文之式之 Shift+[ 于参数之位先出 `『』`。
- 角引号裹参之旧正式句式不复受。`命令位置`、`命令登记` 中句式之析，代以读句之器与语法分析，登记之表留为补全与快路之名录。

### 命令之脚本与网页之壳

- `「脚本」于『路径.txt』`：每行依交互之一句而处，先印 `+ 行`，出误则续；`。脚本。豫` 依第九节。
- 云仓网页之壳，与默认之壳本同书，随之改为豫言之句（字符串用 `『』`）。网页之壳惟识命之召，不为一般之求值；别于云仓行之。

## 十一、设计：放大内存

- **今之状**：裸机每任务之线性内存至多 512 页（32 MiB），客体二号之页限依平台而取（原生 65535，裸机 512，`客体二号/入口。豫`）；内核之块池定为 32 块、每块 2 MiB，凡 64 MiB，二任务共之，已用之块录于一 32 位之位图；内核经页表之恒等别名读写池块（AMD64 页目录、ARM64 二级表各第 32–63 项）；任务之第 k 块映于 AMD64 页目录第 64+k 项、ARM64 二级表第 256+k 项（《内存块管理》）；`yy豫言系统 运行` 用 QEMU `-m 128M`。
- **改为**：
  - 裸机之页限放至 8192 页（512 MiB），即 ARM64 一二级表中任务所能映之块数之上限（第 256–511 项，凡 256 块）；AMD64 取同数。
  - 块池依启时所探之物理内存而分；位图自一 32 位之字宽至足用之字数，恒等别名同宽。
  - `yy豫言系统` 与 `yy普通豫言验证`、`yy裸机验证` 之 QEMU 内存放至 2 GiB。
- **起子进程**：复制任务以父任务之块全复于子任务，子任务随即清零动态之区、易为新程序（《客体二号》“子进程”）。壳既大，每起一子进程，皆多占同数之块、多费复制之时。第六步实测，若显，则令子任务惟复静态之区与程序之字节。
- 待办事项：每任务逾 512 MiB 者须用第二页表，留俟后日。

## 十二、设计：宿主之 `yy脚本`

- 包「豫言脚本」置于 `应用/开发工具/豫言脚本/`，可执行之文 `yy脚本`，依「脚本解释」。
- 用法：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy脚本.wasm 路径。脚本。豫 参数…
node 豫言操作系统/宿主/节点/宿主.cjs yy脚本.wasm --只查 路径。脚本。豫
node 豫言操作系统/宿主/节点/宿主.cjs yy脚本.wasm 预备 标准库 壳命令 --输出 目录
node 豫言操作系统/宿主/节点/宿主.cjs yy脚本.wasm
```

- 末行不予路径，入交互求值（第十节），便于 Node 上调试。
- 包之发现同豫构：自脚本所在之目上求仓根。
- 全树之测：每一 `。脚本。豫` 行 `--只查`；旁有同名 `.期望` 者，又以解释与编译二式各行一次，所出皆与所期逐字而较。

## 十三、例

例一至例三，2026-10-04 以 `yy4_bs.wasm` 依编译之式构之皆过（暂置于 `应用/豫言编译器/测试/网页汇编/` 而构，冷缓存 23.9 秒，热缓存每例 4–6 秒）。

### 例一：一句一行

壳测 `子进程文件` 之子程序 `文件工。豫`，今惟能嵌每步于一大 `虑…而` 之链。书为脚本，每步即一句：

```yuyan
寻观「标准库」之书。

「打印行」于（『读预置：』附（「文件系统」之「读文件」于『/数据/说明.txt』））。
「文件系统」之「写文件」于『/新/来自脚本.txt』于『脚本写入的内容』。
「打印行」于（『读回：』附（「文件系统」之「读文件」于『/新/来自脚本.txt』））。
```

某句出误，则前诸句之出与所书皆已效，其后之句不复行。

### 例二：依退出之码而分

```yuyan
寻观「标准库」之书。

「码」者「子进程」之「运行并继承标准流」于『/程序/统计.wasm』于（「列」【『/数据/文本.txt』】）也。
若「等于」于「码」于「零」则「打印行」于『统计完成』否则「进程」之「退出」于「码」。
```

### 例三：于目中每文运行程序

```yuyan
寻观「标准库」之书。

「逐个统计」乃化（「列」于「字符串」）而「有」也。
「逐个统计」者会「余」而
  鉴「余」而
    有「罄」则「元」
    或有「缀」于「首」于「尾」则（
      虑「码」者「子进程」之「运行并继承标准流」于『/程序/统计.wasm』于（「列」【『/数据/』附「首」】）而
      「逐个统计」于「尾」
    ）
也。

「逐个统计」于（「文件系统」之「读文件夹」于『/数据』）。
```

`乃` 句与随后之定合为一组；「逐个统计」为尾递归，续延之栈不增。

### 例四：自正式句式至豫言之句

```text
今天：壳> 「文件」之「读取」于「/数据/说明.txt」
合一后：壳> 「文件」之「读取」于『/数据/说明.txt』
```

合一之后，壳中与脚本中书法相同，脚本中句末再加 `。`；字符串之参自 `「」` 改为 `『』`。

### 例五：交互之会话

```text
壳> 「文件」之「列出」于『/』
程序
数据
壳> 「源」者『/数据』也
壳> 「文件系统」之「读文件夹」于「源」
「列」【『文本.txt』】
壳> 「加」于「12」于「30」
「42」
壳> 「运行」于『/程序/统计.wasm』于「列」【『/数据/文本.txt』】
文件：/数据/文本.txt
字节：132
行数：5
词数：8
```

第一、五二句由快路，余过全前端；第二句之定，于第三句可用。

## 十四、速与验

暂定之的（首步实测而后修之）：

| 境 | 的 |
| --- | --- |
| Node，库之缓存已生，十句之脚本（导标准库、运行一程序） | 二秒内毕，不计所运行程序之时 |
| Node，每组之前端（境已载） | 均五十毫秒以内 |
| QEMU，句之缓存中，同一脚本 | 十秒内毕，不计所运行程序之时 |
| QEMU，句之缓存不中 | 实测而录，不设其的；若一组逾十秒，先为第十八节第八步 |
| QEMU，壳中由快路之句 | 与今之正式句式相当 |
| QEMU，壳中过全前端之句（库已常驻） | 实测而录，不设其的 |
| 解释与编译二式之所出 | 全树之测中逐字相同 |

求值之器自迟于编译之码：Node 上度迟十至五十倍；裸机上又乘客体二号之倍。脚本宜于运行程序、移文件、为判断；大量之算，犹当书为程序而编之。

## 十五、兼容与迁

- 语言：无新语法，无新类之则；惟增一文之后缀与一行之式。
- 构建：「收集包源码」略 `。脚本。豫`。仓中今无此后缀之文，今之构建无所影响。
- 默认之壳：`.txt` 命令之脚本照旧逐行而行，每行改依豫言之句而处；`。脚本。豫` 由新路。壳因链前端而大，启时待实测。
- 壳之书：角引号裹参之旧正式句式不复受，改书豫言之句（字符串用 `『』`）；演示之「加」代以标准库同名之函。`壳/测试/` 之入与所期随之改书（此诸入今犹为更早之空白分词之书）。
- 云仓网页之壳：其书随之改为豫言之句，别于云仓行之，同改云仓之说明与测试。
- 新 ABI：宿主之务「取中断挂起」（2026-10-04 用户已允），其声加于 `豫言操作系统/裸机/宿主服务。接口。豫`，由 `客体二号/带型名。豫` 映于新原语之号。此组之声惟客体二号映之，与 `豫言操作系统接口/` 之接口清单无涉。
- 内存：内核之块池、页限与 QEMU 内存之改，及于诸裸机之镜像，`yy裸机验证` 之 380 项与 `yy普通豫言验证` 皆须复行。
- 编译器核心：惟析验类与名称解析之循之一步为可独召之入口，不易其义；犹须全自举（yy3 与 yy4 逐字节同）以确之。
- 与《豫言操作系统总体架构》D3（“解释器只作正确性基准，工具类程序必须 AOT”）之关：D3 所言，Wasm 程序于原生之路何以行之；本提案所解释者，脚本之源码，解释器自身照常编为 Wasm，随壳或 `yy脚本` 而行。

## 十六、他途

| 途 | 断与由 |
| --- | --- |
| 于系统中行全编译器，脚本先编为 Wasm 乃行 | 否。编译器由客体二号解释而行，原生上编标准库一文约 45 秒，QEMU 上更迟；其所需之「存放包上下文」裸机所无，Node 冷编峰约 0.52 GB，而每任务惟 32 MiB；编译器占惟一之子进程槽，所编之程序无所于行 |
| 逐句编为小 Wasm 之模，以多实例装而行之 | 否。跨实例惟传数值（《客体二号》“限制”），句与句间须传闭包、字符串与列；每句又须过代码生成一遍 |
| 惟于宿主预编脚本，随盘予 `.wasm` | 此即今之状：系统中改源码不能复行，亦不能于系统中书新脚本 |
| 为壳之命令之语增变量、条件、循环、函数 | 否。是别造一语，仓规不许自造语言或 DSL；豫言自有之 |
| 别书一惟识子集、动态之类之小解释器 | 否。所受之程序异于编译器，类之误至运行乃见，语法之糖须复实之 |
| 略验类，径解释名称解析后之树 | 否。验类兼行细化（命名元组依名之投影改为依序之投影、标签之参等），模式展开与擦除皆在其后；略之则义变 |
| 解释更后之段（跨模优化、递归转换或闭包转换之后） | 不取。彼诸段带顶层直调、全局存储、闭包之境等为代码生成所备之细，求值之器反繁；擦除后形式最近《执行与编译》行一至行三 |
| 解释器为独立之程序 `/程序/脚本.wasm`，壳以子进程行之 | 暂不取。内核惟二任务槽，脚本则不能运行程序；内核放其任务槽之后可改 |
| 库函直连：求值之器径召解释器中既编之库函，不解释库之树 | 留俟后日。须令求值之器之值与编译之值同表，须依类生全库之定之直连之表，或须新原语以构任意长之元组；其益：库之码以编译之速而行，亦不必载库之擦除后形式 |
| 存正式句式，别设一命以入交互求值 | 否。2026-10-04 用户定壳之所入与豫言之句合一，壳中惟一书 |
| 每行皆过全前端，不设快路 | 否。前端于裸机由客体二号解释而行，简命亦须待之；快路惟受全书之子集，其果相同 |
| 交互时亦令无参之命书 `于「元」` | 不取。交互时自以「元」召无参之函，省最常见之赘书；脚本中犹须书之，与编译之式同 |

## 十七、未决

1. 豫言操作系统上脚本所能导之库：惟随盘之标准库与壳命令之库，抑盘上诸库。
2. 始载标准库于 QEMU 上若太迟：常驻、裁剪、库函直连，先为何者。
3. 壳于裸机之预编（施 WP8 之预编二于裸机之镜像）：若可行，前端与求值之器皆可望近 Node 之速，交互时过全前端之句亦受其益。
4. 脚本尽内存则累及壳：为求值之器设堆之限否，抑待内核放任务槽之后令脚本别开进程。
5. 同名再定：书脚本者与交互之人易以为变量之再赋；同名再定示警否。
6. `#!` 之行：宿主上 `yy脚本.wasm` 须经 Node 宿主而启，`#!` 之行何以书，乃能于 macOS 与 Linux 径行。
7. 「运行」别予一依空白拆参之简书否（如 `「运行」于『/程序/你好.wasm 甲 乙』`）。
8. 网页之壳改用豫言之句之后，云端以何析之：链「脚本解释」之前端，抑惟析命之召（须为全书之子集）。
9. 会话中之定存于盘否，重启而复之。

## 十八、施行之序

依下之序为之，每步别入，入前毕本步之验。第一步之后，第二、三步互不相依；第五步不依他步，可最先始；第七、八步可并行。

1. **前端逐组之入口与 Node 上之最简解释器**（所依：无）
   - 编译器核心：析名称解析与验类之循之一步为可独召之入口；切句之后逐组语法分析之入口；「收集包源码」略 `。脚本。豫`。
   - 新库「脚本解释」：读句、每组之前端之召、求值之器（第二节之二十一种节点、92 原语、标准库之宿主导入）、库之缓存、出误之则、交互求值之读句与印值。新包「豫言脚本」与 `yy脚本`。
   - 实测：Node 上载标准库之时与存、每组前端之时、求值之器较编译之码之倍；录其数于本提案第十四节。
   - 验：一组脚本之例（含例一至例三）于二式下所出逐字相同；`yy脚本` 之交互求值行通例五中不依壳命之句；`全部 -j 24` 自举定点；全树之测之相关前缀。
2. **接全树之测**（所依：一）
   - 全树之测发现 `。脚本。豫`，行 `--只查`；有所期者二式皆行。其则书于 `测试规则.tsv`。
3. **壳命令之库**（所依：一）
   - 依 `命令登记` 之成员之路予库「壳命令」，核其与标准库之同名；「运行」受参数之列；壳自身之命改召同一库。
4. **造盘与库之缓存**（所依：一、三）
   - `yy脚本 预备`；「编译预置们」原样入盘 `。脚本。豫`；`yy豫言系统 构建` 书 `/库/脚本库/`。
5. **放大内存**（所依：无）
   - 内核：块池依物理内存而分，位图与恒等别名放宽；客体二号裸机之页限放至 8192 页；`yy豫言系统`、`yy普通豫言验证`、`yy裸机验证` 之 QEMU 内存放至 2 GiB。
   - 验：`yy裸机验证` 之 380 项与 `yy普通豫言验证` 二架构皆过；增一项：壳长至 256 MiB 之后犹能起子进程而收之。
6. **接于默认之壳**（所依：四、五）
   - 壳依「脚本解释」；`运行`、`脚本` 依后缀而分；脚本终后复工作目录与环境；新宿主之务「取中断挂起」（其声与 `带型名。豫` 之原语之号）；避初始化时召构建宿主之务之模。
   - 实测：QEMU 双架构上载标准库之时、每组前端之时、壳之积与存、起子进程时复制任务之时；复制若显迟，改为惟复静态之区与程序之字节。
   - 验：`yy普通豫言验证 --只验 壳-` 增 `豫脚本` 之测：例一至例三、出误之退出之码、Ctrl-C 之断、脚本中运行程序、脚本嵌脚本；二架构逐字而过。
7. **交互求值与所入合一**（所依：六）
   - 壳之「循环」改以每行交解释器：印值、无参之函之召、续行、出误则弃、Ctrl-C 断求值；快路；补全之候取于名境，参数之位用 `『』`；去旧正式句式之析；`.txt` 命令之脚本依交互之一句而处；改书 `壳/测试/` 之入与所期。
   - 验：`yy普通豫言验证 --只验 壳-` 皆过；增交互之测（例五、定跨句有效、出误则弃、续行、Ctrl-C 断求值）；快路与全前端之果逐字相同；依《终端编辑》之法复验 BIOS 与 UEFI 之键入。
8. **句之缓存与常驻**（所依：六）
   - 句之缓存之生、中与失效；造盘时为预置之脚本预生之；壳内常驻已载之库。
   - 验：第十四节之 QEMU 之的。
9. **网页之壳改用豫言之句**（所依：三、七；在云仓）
   - 依云仓之规施行与部署；同改云仓之《智能命令》与测试。
10. **文档**（与诸步同时）
   - 《执行与编译》增“脚本解释”一节（逐句之序、出误之时、退出之码、陷阱与中断、交互求值之印值）；《词法与语法》记 `。脚本。豫` 与首行 `#!`；裸机之说明、《客体二号》、《内存块管理》、《智能命令》、《终端编辑》与新包之双语包说明。

每步共同之规：

1. 行之变与双语之规范，同一提交而改。
2. 改编译器核心之步，行全自举（`全部 -j 24`，yy3 与 yy4 逐字节同）。
3. 诸步皆毕，改本提案之状为“已实现”，并注各步之提交。
