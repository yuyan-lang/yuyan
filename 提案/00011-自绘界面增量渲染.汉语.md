本文只写现代汉语（AGENTS.md）。

## 一、拟定事项

- **议一：文字排版缓存。** 段落排版结果按（文字、文字样式、最大宽、换行方式、限行、省略）缓存，跨帧复用，整形与断行不再每帧重做。
- **议二：渲染节点树。** 渲染器留住上一次的界面树，并挂一棵同形的渲染节点树（相当于 React 的 fiber 树）。新树来了与旧树比对：可见输入相同的节点沿用样式、排版与位置，变了的节点才重算。
- **议三：脏矩形重画。** 比对得出变化节点的新旧矩形，连同交互状态的变化（悬停、按下、焦点、光标闪烁、选区），合成脏区域；画布常驻，只在脏区域里裁剪重画。没有脏区域就不画、不提交。
- **议四：提交一块区域。** 显示接口 0.8.0 新增「提交像素画面区域」，只把画布的一个矩形交给宿主；裸机内核服务 32 加区域参数，鼠标光标的叠画与还原也只交光标所在的小矩形。宿主不支持时退回整帧提交。

## 二、动机

桌面每次更新都在处理器上整窗重画（`库/显示控件/主循环。豫` 的「画一帧」）：重建界面树，求全部样式，所有文字重新分段、双向分析、整形、断行，整块画布清空重画，再整帧拷贝提交。Mac 原生窗口、网页画布与裸机共用这条路；只有网页的 HTML 后端（`库/界面/差分。豫`）比较新旧树、只改变化的节点。Windows 与 macOS 的做法是保留式界面树、脏区域、每窗口一份像素缓存、GPU 合成；裸机没有 GPU，更需要少画。

实测与剖析：

- QEMU 纯模拟下桌面按键到画面约 0.5 秒（2026-10-09），一帧常比 250 毫秒的计时间隔还长，命令行跑程序时桌面一直在画，替子程序代办文件的时间被挤掉（2026-10-10，见公开测试版目标）。
- 2026-10-09 的源名剖析：剩余时间主要在每帧对全部文字重新分段、双向分析与整形（显示控件「上下文切列」等）。
- 自动换行排版耗时随行长平方增长：诺节上一千字一行约 0.05 秒、两千字 0.13 秒、四千字 0.49 秒。桌面命令行已先把每行截到 1000 字、只排最新 100 行（88e2ef605）。
- 光标每 530 毫秒闪一次就整帧重画；鼠标每动一下，裸机执行器都把上一帧整帧（1280×800，4 MB）重交一遍（`客体二号/裸显示。底层。豫`）。
- 一帧在裸机六十四位地址构建里要拷两次整帧（「画布转字节串」与「低址副本」），高分屏两倍放大时内核再写 16 MB。

## 三、现状流程（要改的地方）

1. `库/界面/自绘/运行。豫`「运行界面尺寸计时保位会话」：「画视图」= 视图 → 「求样式树」→ 「排版根」→ 「生成显示树」。
2. `库/显示控件/主循环。豫`「画一帧」：视图 → 「收集交互项」→ 「整理控件状态」→ 「取画布」（同尺寸复用）→ 「画显示树」→ 「画布转字节串」→ 「提交像素画面」。需要重画的时机：交互状态变了、有交互事件、尺寸或像素比变了、计时到期、光标闪烁。
3. 文字：`库/显示控件/文字排版。豫`（「排段」得「段落排版」）、`文字上下文。豫`、`文字绘制。豫`（按段落排版逐行画，不再断行）。字形位图已按（字体、像素字号、字形号）缓存在 `库/字体/字形库。豫`；圆角遮罩已缓存在 `画布。豫`。
4. 元素身份：`库/界面/标识。豫`（事件按元素标识找回处理函数）；`库/界面/差分。豫` 已有同位置、同种类、同键的比对规则，可以照搬。
5. 提交：显示接口 `豫言操作系统接口/显示/画面。接口。豫`「提交像素画面」（0.7.0）。裸机：`客体二号/显示原语。底层。豫`「显原提交」→ `裸机底层显示。底层。豫`「提交画面」→ `裸显示。底层。豫`「裸显提交」→ 内核服务 32（`库/裸机后端/帧服务。豫`，AMD64 手写机器码；ARM64 在 `豫言操作系统/裸机/内核/` 的豫言内核里）。macOS：`苹显示。底层。豫`（整帧拷进 CFData 做 CGImage 设给图层）。浏览器：`豫言操作系统/宿主/浏览器/图形.mjs`（putImageData 整帧）。

## 四、设计

### 4.1 文字排版缓存（议一）

- 在显示控件里加一张全局表：键是（文字、样式各字段、最大宽、换行方式、限行、省略、像素比），值是「段落排版」。命中就直接用，量与画仍保持一致。
- 上限往大里定（例如 8192 项），满了整表清空即可（能凑合着用就行）；待办事项：按最近使用淘汰。
- 这一步不动任何接口，单独就能把逐帧整形去掉大半。

### 4.2 渲染节点树与比对（议二）

- 每个渲染节点记：元素身份（路径加种类加键）、可见输入（种类、样式列、可见属性、文字、子节点身份列）、上次的约束（可用宽高）、排版结果（大小、子节点位置、段落排版）、上次画在屏幕上的矩形。
- 比对规则照 `差分。豫`：同位置、同种类、同键原地比；子列身份序列不同就整段重建该容器的子节点（待办事项：按键移动）。事件处理函数不比，按标识去找。
- 可见输入与约束都相同：整棵子树沿用（不往下走）。只有可见输入变了：重算本节点；大小变了再让父节点重排。
- 留一个口子给上层：元素可带“未变”标记（将来盆栽式静态图给出节点版本号时直接跳过比对）。本提案不做上层。

### 4.3 脏矩形重画（议三）

- 脏区域来源：变化节点的旧矩形与新矩形；位置变了的节点；交互状态变化涉及的交互项矩形（悬停、按下、焦点切换、光标闪烁只脏输入框的光标列、选区）；尺寸或像素比变化时整帧。
- 合并：矩形个数超过上限（例如 16）或总面积超过画布一半时，并成一个外包矩形或整帧。
- 画：画布常驻；对每个脏矩形先填背景，再把与它相交的显示树项按顺序裁剪重画。显示树项要带外包矩形以便剔除。
- 没有脏区域：不画、不提交。计时到期而状态没变的帧（命令行轮询没有新输出时）由此几乎零开销。

### 4.4 提交一块区域（议四）

- 显示接口 0.8.0 新增：

  ```
  「提交像素画面区域」乃
    化「显示面」而
    化「整数」而 化「整数」而        「：画布宽、高：」
    化「字节串」而                   「：整块画布（RGBA8，同提交像素画面）：」
    化「整数」而 化「整数」而 化「整数」而 化「整数」而   「：区域左、上、宽、高：」
    「画面提交结果」
  也。
  ```

  规范写进 `豫言操作系统接口/显示/规范.汉语.md`、`规范.文言.md`；接口声明变了要重生成 `豫言操作系统/适配/` 下各适配的 `宿主提供.json`。宿主做不到时按整帧处理（照常返回成功）。
- 裸机：内核服务 32 加区域（例如第三参为 左×65536+上、第四参为 区宽×65536+区高，旧调用方仍按整帧）；两倍放大时区域坐标也乘二。执行器的光标叠画与指针移动重交改为只交光标新旧两个小矩形。六十四位地址构建的「低址副本」只拷区域所在的行。
- macOS：可先整帧（保持现状），再改为只更新图层的一块；浏览器：`putImageData(图, 0, 0, 左, 上, 宽, 高)`；诺节显示适配照接口退回或实现。
- 「画布转字节串」的整帧拷贝：区域提交时只拷区域所在的行，或让宿主直接读画布的字节缓冲（待办事项，先不做也行）。

## 五、实施步骤

1. 议一（文字排版缓存）：只改显示控件；测按键到画面的时间。
2. 议二（渲染节点树与比对）：改界面自绘后端与显示控件，界面应用代码不变。
3. 议三（脏矩形重画、无变化不画）：改显示控件主循环与绘制树。
4. 议四（显示接口 0.8.0、裸机服务 32、执行器光标、各宿主）：按 AGENTS.md“豫言操作系统接口扩展”办理，规范、实现、验证一起改。

每一步单独合入 yybs。

## 六、验收

- **像素一致**：新增测试，对同一串状态（打字、开关窗口、拖窗口、命令行追加输出、光标闪烁、悬停）分别用整帧重画与增量重画，每一步两块画布逐像素相同。放在 `库/显示控件/测试/` 与 `库/界面/测试/`。
- **现有测试**：显示控件、界面、用户态桌面各测试照常通过；`yy豫言系统 冒烟`（SeaBIOS、OVMF 两路）通过。
- **速度**：冒烟子命令已量 d、e、f 三键从发出到画面变化的用时（QEMU 纯模拟），目标比现在快五倍以上；空闲时计时帧不提交；鼠标移动只交小矩形（看内核写帧缓冲的字节数或用时）。
- **桌面里造盘**：桌面命令行运行系统内造盘时，任务管理器里子任务占用明显高于现在（2026-10-10 约 30%）。
