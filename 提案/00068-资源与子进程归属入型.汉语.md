| 依据 | 建议表「资源与子进程归属入型」（39 个议题）；提案 00002、00057、00060、00063、00065；议题 #1078、#1097、#1098、#1116、#1120、#1138、#1164、#1165、#1166 |

本文只写现代汉语（AGENTS.md）。写法草样只用来说明设计意向，关键字与写法以语言提案核定者为准。

**否决理由（2026-10-28 用户议定）**：不改语言。语言本来就能用函数写出“用完即还”的作用域（如 Python 的 with）：资源一取得就记在某个主名下，出作用域时（含抛出事故）把还没交出的一并关掉，要长期留的明着交给别的主。分支漏关、出错跳过收场由此在库里解决；交出以后再用，在运行时报“已交出”。库的做法见议题 #1183（子进程与资源的归属写进类型）与 #1184（连接与链路状态写进类型）。本文以下内容保留作记录，不再实施。

## 一、拟定事项

- 议一：新增一元类型构造「独」于「甲」，表示只能消耗一次的资源柄。文件、套接字、子进程、装入的单元、缓存与副本凭证都用它。
- 议二：消耗分三式：关闭（「别」）、交出（「与」）、存进带「主」字段的记录。取得资源之后，函数生命期的每条出口都须恰好消耗一次。
- 议三：编译器按控制流核对消耗：漏消耗、重复消耗、消耗之后再使用、把「独」值复制进普通匣或普通列，都报编译错误，并带文件、行列与所在定义。
- 议四：起子进程时，标准输入、标准输出、标准错误三个去向写成必填标签参数，取值为「承」（继承）、「闭」（关掉）、「书」于路径（写文件）。后台服务没有缺省可走。
- 议五：子进程柄是「独」值。父进程用「候子」收取并取退出缘由，用「弃子」交给系统代收，或用「托子」把所有权转交别处；三条路都显式写出。
- 议六：记录字段可以声明「主」，用来接住一个「独」值；普通函数参数、返回值、记录字段都能传递所有权，传递即移动。
- 议七：垃圾回收与内存管理照旧。本提案只管显式取得、显式交还的资源，与提案 00017 的整理回收并行。

## 二、动机

### 现状

文件、套接字、内存段、页面、装入的单元这些资源，取得与释放散在几条出口路径上，谁起的子进程、父进程收场时跟不跟着退，全靠调用方记得。类型上，句柄与普通整数、普通记录没有分别，漏一处只在跑久了以后以端口耗尽、满核空转、磁盘塞满的形式露出来。

### 要防的错

建议表这条已记 39 个议题，近一批的例子：

- #1116：三副本快照测试的服务端不关对端已断的连接，两分钟积一万六千多条「对端已关闭、本端未关」的连接，本机临时端口耗尽。
- #1165：三副本快照测试主体退出时不收子进程，孤儿攒下一万三千条「对端已关闭、本端未关」的连接，全机新连接报「无法分配请求的地址」。
- #1084：网平测看门测试的“长眠”辅助进程是不设期限的死循环，漏收成孤儿后两台各满核空转近十五小时。
- #1098：将作每见一个新的客程序指纹就存一份一百二十四兆字节的工具链副本，从不回收，本机三百四十七份、四十二吉字节。
- #1164：盟台「开连」只等零毫秒就入门，没连成的套接字既不关也不留，谷歌云三台每秒各漏十来个，永远选不出盟主。
- #1166：客户端「随试」每次请求都先「客设」，「客设」悄悄关掉旧连接重开，一笔写要三秒。
- #1138：轩窗上后台行在继承了会话的标准输出句柄，经管道收输出的调用方永远等不到结束。
- #1078：共用的栈按位置删条目，自己那条已被弹走时删到别人的；仓外草稿脚本只能运行时发现。

### 数据

上面几条的数量取自各议题正文：#1116 的一万六千零四十八、#1165 的一万三千、#1098 的三百四十七份与四十二吉字节、#1084 的两台各近十五小时，都是 2026-10-27 至 10-28 在本机或谷歌云上实测。

## 三、目标与范围

做：资源与子进程句柄的「独」类型、消耗三式、控制流核对、起子进程的三个标准句柄去向、记录字段的所有权接住、编译器诊断。

不做：借用检查与生命周期参数；析构器与自动关闭；异步任务取消时的所有权规则（见未决问题）；垃圾回收对象的回收时机。

## 四、设计

### 4.1 类型

```
「独」乃凡「甲」属「类」而化「甲」为「类」者也。     「：汉语：只可消耗一次的资源柄：」
```

资源原语返回「独」值：

```
「连柄」即「独」于「传输连接」也。
「开连」乃化「文」又化「数」为（「成败」于「连柄」于「文」）者也。
「别」乃化「连柄」为「有」者也。
```

### 4.2 消耗规则

编译器为每个「独」值记一条消耗账，沿控制流传播：

- 每个出口上账须恰好清零。少一次即“资源未消耗”，多一次即“资源已消耗，不能再用”。
- 「独」值可以经参数、返回值、记录字段转手，转手即移动，原处作废。
- 「独」值可以存进带「主」字段的记录；记录本身可以复制时，「主」字段照移动规则处理。
- 循环与递归按不动点核对：每一轮进出账都要平。

报错样式：

```
编译错误：应用/豫构/行在。豫:412:7：套接字「连」在这条出口上没有消耗；请「别」掉、交出或存进带「主」的记录
```

### 4.3 起子进程

```
「柄去」即「和」
　【「承」乃「元」也
　，「闭」乃「元」也
　，「书」乃（「径」于「文」）也
　】也。

「起子」乃化「行」曰「文」
　　　又化「入」曰「柄去」又化「出」曰「柄去」又化「误」曰「柄去」
　　　为（「成败」于「子柄」于「文」）者也。
```

调用处三个去向都写出来，标签参数照提案 00065：

```
「起子」于「行」曰『豫构』于「入」曰「闭」于「出」曰（「书」于「日志径」）于「误」曰（「书」于「错误径」）
```

子进程柄的三个消耗者：

```
「候子」乃化「子柄」为（「成败」于「退出缘由」于「有」）者也。   「：汉语：收取并取缘由：」
「弃子」乃化「子柄」为「有」者也。                              「：汉语：交给系统代收：」
「托子」乃化「子柄」又化「托主」为「有」者也。                  「：汉语：转交所有权：」
```

### 4.4 记录与容器

普通「匣」「列」只收普通值；要接住「独」值，记录字段须写「主」：

```
「会话」即「组类」
　【「连」乃「主」于「连柄」也
　，「名」乃「文」也
　】也。
```

「主」字段的投影与「与」都消耗所有权；复制整个记录时，带「主」字段的记录照移动处理。测试框架给的“在作用域里起子进程”写法（#1165）由库在此之上实现，出错路径统一收场。

### 4.5 与现有提案的关系

- 提案 00057：可失败操作返回结果，取得资源失败的那一支不产出「独」值，账从成功那一支开始记。
- 提案 00060、00065：名义类型与标签参数给「独」值分型、给起子进程的标签用。
- 提案 00063：分支穷尽检查让每条路径都进消耗账；缺分支仍按提案 00063 报错。
- 提案 00066：装入的单元按其布局读写，单元柄同样是「独」值。

## 五、兼容与迁移

- 现有程序照常编译的条件是资源原语全部换成带「独」的签名。库按包分批迁移，编译器先接受旧签名并逐包报“该原语尚未迁移”，迁移完成的包改用新签名。
- 旧代码取得资源后不关，会从“编得过、跑久了出事”变成编译错误，这正是本提案要达到的效果。
- 确实要放弃的资源写「弃」并记一行缘由，审查与日志都看得见；「弃」也算一次消耗。
- 工具链、执行器、行在、将作的资源取得处先迁移，再迁应用与测试。

## 六、备选方案

- 命名约定加格式检查：改动最小，仍拦不住新增的漏关，也拦不住按位置删条目那一类错（#1078）。本提案不取。
- 析构器与自动关闭：与垃圾回收的时机、异常路径的收场纠缠，先不取。
- 借用检查与生命周期：能防“消耗之后再用”以外的更多错，代价远大于本提案，留待后续。

## 七、未决问题

- 异步任务之间转交「独」值怎么记账：转交成功、对方取消、消息丢失三种情形都要定。
- 「姑试」包住的试体抛出事故时，作用域内的「独」值由谁收场；测试框架的自动收场要不要写进类型。
- 「独」值可否作为「鉴」分支的返回值，分支合流时账怎么合。
- 记录带「主」字段时，记录整体可否作为普通参数复制，还是只能移动。

## 八、实施步骤与代价

1. 类型检查加消耗账：局部变量、参数、返回值、记录字段与分支合流；错误带源位与名（提案 00059）。约一千行以内。
2. 资源原语改签名：文件、套接字、子进程、装入单元、缓存与副本凭证；库与测试按包迁移。
3. 起子进程三个标准句柄的去向改成必填标签参数（提案 00065）。
4. 测试：漏关、重复关、消耗后再用、分支漏关、记录接住各一例，编译器须分别报错。
5. 文档：语言技术规范新增「归属与消耗」一篇，包说明与接口规范同步。

代价主要在库与应用的迁移面，编译器一侧是一次控制流分析，运行时没有开销。迁移可与提案 00057、00058 的实施并行，先迁资源原语，再迁调用处。
