## 一、拟定事项

- 议一：新增文件种类 `名。签名。豫`，与同目录同名的 `名。豫` 配成一对；底层模块配 `名。底层签名。豫`。签名写模块对外的名字与类型，没写进签名的名字在模块外看不见。
- 议二：签名里只用现有写法。类型与函数一律用「乃」给出类型；「即」导出透明的类型定义；「立」只在整块照抄类型块时出现，用来导出具体类型。
- 议三：签名里写成 `「T」乃「类」也` 的类型在模块外是抽象的：名义上与任何别的类型都不等，看不见它的定义，也没有构造器可用。
- 议四：没有签名文件的模块，签名自动生成：导出全部定义，类型照原样展开，与现在相同。
- 议五：导入方只依赖签名。实现改了而签名没改，导入方不必重新检查。

## 二、动机

### 现状

- 规范「词法与语法」语四：“所有普通命名声明初始公开；无普通私有声明关键字。”模块的定义、构造器、类型别名对导入方全部敞开。
- 所以写不出“只有本模块能造的值”：别的模块总能直接调用构造器。
- 「即」定义的类型透明，比较前展开：`「字节数」即「数」也` 与「数」处处相等，起不到区分作用。

### 先例

「帛」与「文」同质而类别（`库/豫章/形制/帛书。豫`），靠的是宿主实现。签名文件把这种做法开放给每个模块，不必经宿主。

## 三、目标与范围

做：签名文件的写法，签名与实现的核对，模块外的视角，自动生成的签名，底层签名。

不做：

- 文件内的子模块。一个文件就是一个模块，同一模块内部不区分。
- 单位的乘除（字节数除以秒得速率）、整数宽度与有无号：另议。
- 只露表示、不许构造的私类型（OCaml 的 private）：议定时去掉。模块外要读内部的值，由模块导出取值函数。
- 带参数的类型别名：现有的 `即凡…而…` 已表示全称类型的别名（仓里 2 处），不另立写法。带类型参数的抽象类型用「立」块加构造器，见例二。

## 四、设计

### 4.1 语法

签名文件里每条声明是下列之一。收尾照「雅言文体」：类型以化、凡开头且不在括号里时用「者也」，否则用「也」。

```
「T」乃「类」也。                 抽象类型
「T」乃化「类」为「类」者也。     抽象类型构造器（照写种）
「T」即 R 也。                    透明类型：连定义一起导出
「T」立「类」也。                 具体类型：整块照抄实现里的类型块
　「K」立 σ 也。                  （连同它的全部构造器，见提案 00061）
「f」乃 σ 者也。                  函数与值
寻观 路径 之书                    导入：签名里提到别的模块的类型时用
```

例一：零开销的抽象类型。

```
字节数。豫：
「字节数」即「数」也。
「字节」乃化「数」为「字节数」者也。
「字节」者得「量」而「量」也。
「字节值」乃化「字节数」为「数」者也。
「字节值」者得「量」而「量」也。

字节数。签名。豫：
「字节数」乃「类」也。
「字节」乃化「数」为「字节数」者也。
「字节值」乃化「字节数」为「数」者也。
```

模块里「字节数」就是「数」，「字节」「字节值」都是恒等函数；模块外「字节数」是另一个类型。

例二：带类型参数的抽象类型（#836）。

```
线程簿。豫：
「全集」立「类」也。
「子集」立「类」也。
「线程列」立化「类」为「类」者也。
　「编线程列」立凡「范围」而化（「列」于「线程」）为（「线程列」于「范围」）者也。

线程簿。签名。豫：
「全集」乃「类」也。
「子集」乃「类」也。
「线程列」乃化「类」为「类」者也。
「列有话线程」乃化「目录」曰「文」为（「线程列」于「子集」）者也。
「全部归档」乃化「线程们」曰（「线程列」于「全集」）为「有」者也。
「取线程」乃凡「范围」而化（「线程列」于「范围」）为（「列」于「线程」）者也。
```

模块外造不出、也拆不开「线程列」，子集传不进要全集的「全部归档」。

例三：只许本模块造的值。

```
核验。签名。豫：
「已验」乃化「类」为「类」者也。
「核验」乃化「文」为（「或可有」于（「已验」于「文」））者也。
「验后取」乃凡「甲」而化（「已验」于「甲」）为「甲」者也。
```

### 4.2 静态语义

1. **配对与查找**：导入路径末段 `名` 所指的模块若有 `名。签名。豫`，导入方从签名取得这个模块的接口；没有就照现在由 `名。豫` 生成。底层文件同理，用 `名。底层签名。豫`。
2. **签名自身先检查**：各声明的类型须能形成（规范「类型与模块」类一），签名里的名字不重复。签名里的类型可以引用签名里先出现的类型和导入的类型。
3. **实现须合签名**：在模块内的视角下比较，抽象类型照实现展开。
   - `「T」乃「类」也` 或带种：实现里须有同名、同种的类型，用「即」定义或用「立」块定义都行。
   - `「T」即 R 也`：实现里须是同一个定义。
   - 照抄的类型块：实现里须有同样的类型块，构造器一个不缺，类型与次序都相同。
   - `「f」乃 σ`：实现里须有同名定义，类型与 σ 相等。

   报错例：“签名里的「f」在 名。豫 里没有定义”“签名说「f」是 A，实现是 B”“签名里「T」的种是 K，实现是 K′”“签名照抄的类型块与实现不同：缺构造器「K」”。实现里有、签名里没有的名字，只在模块内可见。
4. **模块外的视角**：
   - 只看得见签名里列出的名字。
   - 抽象类型 T 是名义类型，身份是（声明文件，名）：T A1…An = T B1…Bn 当且仅当每个 Ai = Bi；T 与其他任何类型都不等，与它在实现里的定义也不等。
   - 抽象类型没有构造器可用：既不能用来造值，也不能写进鉴的模式。
   - 透明类型照常展开；照抄了类型块的具体类型照常造值、拆值。
5. **模块内的视角**：看得见全部定义，抽象类型照实现展开，与现在一样。
6. **宿主边界**：抽象类型过宿主边界时，按实现里的定义算边界形（规范「类型与模块」类六）。

模块外类型不合时，报错写明抽象类型的来历，例如：“类型不符：期望「字节数」（字节数。签名。豫 里的抽象类型），实际「数」”。

### 4.3 动态语义

不变。签名只影响类型检查与名字可见，生成的代码与链接方式都不变。抽象类型的值就是实现里定义的值。模块导出的造值、取值函数是普通函数，实现为恒等函数时，运行时就是一次普通调用。

## 五、兼容与迁移

- 现有模块都没有签名文件，按议四自动生成，行为不变。
- 新写签名的模块：导入方原先直接用的构造器、类型别名展开，若在签名里藏起来，会编不过，按报错改用模块导出的函数。
- 豫构：有签名时，导入方的依赖从 `名。豫` 改为 `名。签名。豫`，印记与缓存键随之改。

## 六、备选方案（议定时否掉的）

- 新类型声明加「封」「启」两个式子：要加关键词与式子。
- 签名里加「私」修饰（私即、私立）与单向转换「视」，即 OCaml 的 private：太繁，要加关键词。
- 实现里加「秘即」：要加关键词；可见性写在签名文件里更清楚。
- 复用 `。接口。豫`：它已表示“宿主提供实现、编成导入”的声明（仓里 137 个文件）。一个后缀两种意思，漏放实现文件时，签名会悄悄变成宿主导入。
- 签名里抽象类型写 `「T」立「类」也`：「立」是设一个没有定义的名义常量，签名只写判断，类型与函数一律用「乃」。
- 带参数的类型别名写成「即设」：给现有关键词新含义，不要。
