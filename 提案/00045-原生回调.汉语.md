本文只写现代汉语（AGENTS.md）。由来是议题 yuyan-lang/yuyan#111“在C调用里面加上函数闭包调用”。原文提出时豫言还有 `C调用` 写法，现已全删；今天对应的是接口文件里声明的原生函数、冶铸为每个声明生成的原生函数桩，以及执行器的原生槽区，缺的只是反方向：原生代码调用豫言闭包。

## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | **闭包不离开豫言堆。** 豫言侧的回音（回调）就是普通闭包；原生侧只拿到一个登记号和一个可调地址。原生代码不持有 GC 引用，不读豫言对象，也不参与回收。 |
| 议二 | **接口文件不新增回调类型。** 回音参数写成资源「回音柄」：只能由宿主产生，应用不能用整数伪造；函数类型只写在普通库 API 的签名里；“系统调我们”的固定入口写在 `。应用接口。豫`，照 `库/云工东道` 的「行云工回音」先例。边界规则“函数不能过宿主边界，回调请用应用接口”保持不动。 |
| 议三 | **每个登记项一个跳板。** 跳板里嵌着登记号，所以不依赖原生 API 的用户数据参数（qsort、讯（信号）处理都没有），也不用“调用前把当前回音写进全局格”这类一嵌套就坏的做法。跳板池在构建时由冶铸生成进可执行段，运行时不写可执行内存，不做 W^X 切换。 |
| 议四 | **跳板只搬寄存器，派发在执行器里。** 执行器导出「原生回音派发」把登记号与实参写成边界帧，经「预编派发」调应用接口入口；入口按号查库表里的闭包并调用。第一版只收整数与地址，小数、结构体与多结果留后。 |
| 议五 | **同线程同步，异线程入队。** 同线程调用直接在当前栈上派发（照 `预编调用导入` 的“导入返回后运行登记函数”）；异线程与讯号处理只把号与整数实参写进常驻区的环形队列，主循环在安全点排水。讯号处理函数里只做原子写，不分配、不回收、不调豫言。 |
| 议六 | **生存期由库表管。** 登记期间闭包是库表里的项，库表是普通全局，天然是回收根；注销即去掉该项。执行器只存号、签名与跳板地址，不存 GC 引用，因此不用钉住对象，也不用改回收器。原生侧必须保证注销后不再调用。 |
| 议七 | **各后端各用其长。** 林檎（macOS）臂六十四先做；林纳（Linux）与轩窗（Windows）照同一跳板模型；诺驿（Node 后端）用 `node:ffi` 的回调，只支持创建它的线程；浏览器与云工（Cloudflare Workers 后端）没有原生指针，用 JS 函数并经应用接口入口回来；裸机不做函数指针，用内核事件队列加主循环派发。 |
| 议八 | **分六步实施**（第八节），每步单独合入。本提案不含实现。 |

## 二、动机与现状

### 2.1 现在原生调用只有单向

底层接口文件用无体声明写原生函数，如 `豫言操作系统/裸机/客体二号/平台接口/林檎。底层接口。豫` 里的 dlopen、dlsym、Objective-C 运行时与按签名分开的 `objc_msgSend`。降级器（`豫言操作系统/裸机/库/冶铸/降级鹄。豫`）在「林檎入口表」里记 C 符号、参数类别与结果数，在「林檎本土表」里另记结果类别、栈补零与是否惰绑；「原生函数桩」（`豫言操作系统/裸机/库/冶铸/宽降级本术。豫`）按类别装寄存器；惰绑的函数第一次调用时经 dlsym 解析并缓存。

这条路的限制写在明处：

- 至多八个整数参数；六十四位指针与 double 放在 `豫言操作系统/裸机/客体二号/原生槽区。底层。豫` 的八字节槽里，参数传槽的地址，结果写进第一个参数给的出槽。
- 只有“豫言调原生”。`原生窗口方案` 第二节的表把回调的现状写成“唯一的原生入口是进程入口”、缺口写成“没有回调入口（首版绕开）”，第三节又说“首版没有任何‘系统调我们’的回调”。
- 林檎兼六十四（x86-64）上「林檎本土表」里的原生函数一律返回负一，原生调用本身还没通，回调更谈不上。
- 底层模式没有闭包、函数值与间接调用（`应用/豫言编译器/文档/底层模式.汉语.md` 的对照表），所以回调不能直接写在 `。底层接口。豫` 的签名里。
- 宿主边界也不收函数类型：类型检查报“函数不能过宿主边界，回调请用应用接口”（`应用/豫言编译器/文档/语言技术规范/网页汇编接口.汉语.md`）。这句话已经指明了方向。

### 2.2 已有的零件

反方向其实已经有几块现成的：

- **预编派发**：预编二把每个客体函数翻成“帧 → 无”的机器函数，导出「预编派发」按函数号调用（`豫言操作系统/裸机/客体二号/预编接口。底层。豫`）。所有值在值栈上每槽八字节，保守回收看得见。
- **导入返回后运行登记函数**：「预编调用导入」在原生导入返回时检查「单元运行请求格」，有请求就取当前栈针造帧、调「预编派发」运行登记的客体函数，把结果写回导入，异常以一百三十七退出（`单元装载。底层。豫` 的「运行」）。这正是“原生调用栈里再进豫言”的形状。
- **机器码进豫言**：林檎臂六十四的「线程入口桩」从 pthread 新线程的栈切到执行器栈，装好 x25、x28、x15，再调用导出「后台线程入口」（`豫言操作系统/裸机/库/冶铸/臂降级本术。豫`）。回调跳板可以照它的开头写。
- **JS 调豫言闭包**：`库/云工东道/回音。豫` 用一张“号 → 闭包”的表，`回音入口。应用接口。豫` 导出「行云工回音」，宿主造出的 JS 函数被调用时以号与实参进来，查表调闭包；注销即去项。这是本文在豫言侧要照抄的骨架。
- **边界值转换**：应用接口导出的包装负责把边界值装箱、拆箱；`宿主对象。底层。豫` 有「装箱」「拆箱」，`豫言边界` 段记着每个导出的签名。
- **间接调用**：执行器的客体元素段与函数表支持 `funcref` 与 `call_indirect`（`豫言操作系统/裸机/文档/客体元素段.汉语.md`），闭包本身就是“函数表号加捕获值”的元组（`网页汇编接口` 网三）。豫言内的函数值不缺通路，缺的是把原生地址接上去的这一小段。

## 三、目标与范围

目标：

1. 豫言闭包能登记成一个原生可调地址，交给 `qsort`、讯号处理、音频队列、Objective-C 委托这类 API。
2. 原生代码调用时，控制回到豫言，按闭包执行，整数结果能带回；调用期间回收照常正确。
3. 登记期间闭包不被回收；注销后原生侧不再调用；没有 GC 引用越过边界。
4. 同线程同步与异线程延迟两条路各有明确语义与限制。
5. 各后端语义一致；没有原生指针的后端（浏览器、云工、裸机）给出等价做法，而不是假装有指针。

不在范围：

- 小数、结构体按值、可变参数、多结果、按引用返回（第二版）。
- Objective-C 的 block 拷贝、delegate 对象与类的构造（要先有 objc 运行时建类与 block 支持；回调只是前置）。
- 跨进程、跨实例、跨豫行启动器的回调。
- 原生代码直接访问豫言堆或 GC 对象。
- 多线程同时进入执行器；执行器仍然单线程执行豫言。

## 四、设计

### 4.1 三层表示

```text
豫言闭包（普通函数类型）
  └ 库表：号 → 闭包（普通全局，回收根）
      └ 执行器：回音柄 → 槽号、签名、延迟标志、跳板地址
          └ 原生代码：调用跳板地址(整数实参…)
              └ 跳板 → 原生回音派发 → 预编派发 → 应用接口入口 → 闭包
```

- 闭包始终在豫言堆里，原生代码只见到整数号与地址。
- 回音柄是宿主给的资源，应用不能伪造，也不能把一个实例的柄拿到另一个实例用。
- 回调结果只经整数槽带回；豫言对象不出边界。

### 4.2 接口文件怎么写

新建库包「原生回音」（`库/原生回音`，本提案新拟，尚无此目录），照 `库/云工东道` 的布局：接口文件、应用接口文件与实现同包。接口放 `回音。接口。豫`（宿主提供）、入口放 `回音入口。应用接口。豫`（应用提供）、实现放 `回音表。豫`，三个逻辑模块不同名。

宿主提供的接口（`回音。接口。豫`）：

```yuyan
「回音柄」立「类」也。
「造回音果」立「类」也。
「回音已造」立化「回音柄」为「造回音果」者也。
「回音未造」立化「寓误」为「造回音果」者也。

「造原生回音」乃化「签」曰「整数」又化「迟」曰「爻」为「造回音果」者也。
「原生回音号」乃化「柄」曰「回音柄」为「整数」者也。
「原生回音址」乃化「柄」曰「回音柄」为「整数」者也。
「销原生回音」乃化「柄」曰「回音柄」为「有」者也。
```

「寓误」照 `豫寓榫卯/显示/画面。接口。豫` 的做法从「豫寓基」的错误篇取；成功带柄，失败带误，不返回假地址。`签` 是库与执行器共用的签名号：第一版四种，零至三个整数参数、结果整数；参数按 C 的类型做符号扩展或零扩展，结果按 C 的类型取低位或留六十四位。第二版再把小数与参数类别按位扩进去。

应用提供、宿主调用的入口（`回音入口。应用接口。豫`），每种签名一个：

```yuyan
「行原生回音整二」乃化「号」曰「整数」又化「甲」曰「整数」又化「乙」曰「整数」为「整数」者也。
```

库的公开 API 用普通函数类型，登记也按签名分成几个入口（如「登原生回音整二」）；调用处按闭包的参数个数选对应的入口，库内再转成执行器的签名号：

```yuyan
「登原生回音整二」乃化「回音」曰（化「整数」又化「整数」为「整数」）又化「迟」曰「爻」为「造回音果」者也。
「销原生回音」乃化「柄」曰「回音柄」为「有」者也。
```

应用真正看见的接口（如讯号）把回音写成「回音柄」：

```yuyan
「设讯号回音」乃化「讯」曰「整数」又化「回音」曰「回音柄」为「有」者也。
```

执行器实现这个函数时，用「原生回音址」把柄换成地址，再调底层声明的原生函数；应用代码不写函数类型，也不碰地址。

若某个原生能力仍由底层接口声明（如 `设信号处理`），回音参数写整数地址，不写函数类型。现有声明是两个不带标签的整数；按标签规矩重写就是：

```yuyan
「设信号处理」乃化「讯」曰「整数」又化「跳板」曰「整数」为「整数」者也。
```

这样分三层，各有各的道理：

- **函数类型只在库 API**：普通豫言代码能写闭包、能捕获，类型检查照常。
- **接口只收资源**：`回音柄` 没有构造器，只能由宿主经「造原生回音」产生；边界类型系统不必新增“函数”一形，`函数不能过宿主边界` 的规则也不用破。
- **原生入口写在应用接口**：宿主能按名找到导出，签名是边界类型（第一版全是整数），编译器已经会为 `。应用接口。豫` 的声明生成包装与导出；`库/云工东道` 的「行云工回音」就是这条路。
- **具体能力收柄**：讯号、定时器这类接口函数收「回音柄」，执行器用「原生回音址」换成地址再交给原生函数；应用代码不接触整数地址。网页宿主上「原生回音址」返回负一，柄里包的是 JS 函数。

将来若嫌“先登记再传柄”啰嗦，可以让接口函数的参数直接写函数类型，由编译器在调用处合成登记与注销；那是语法糖，等主路稳定再议（见第九节）。

### 4.3 跳板

`qsort` 的比较函数、讯号处理函数、Objective-C 委托方法都没有“用户数据”参数，回调函数指针本身必须带着登记信息。因此：

- **一个登记项一个跳板**。跳板是一小段机器码，里面嵌着槽号（即登记号）与签名号；同一签名的跳板可以批量生成，只是立即数不同。
- **环境指针就是槽号**。闭包与捕获值不放进原生指针；跳板把槽号交给派发，派发在库表里按号取闭包。原生 API 若另给用户数据参数（音频队列有），可以把这个号也传进去，但跳板不依赖它；没有用户数据的 API（qsort、讯号）照样能用。
- **跳板池在构建时生成**。冶铸按签名种类（零至三个整数参数，结果一律整数）各生成一千零二十四个槽，放进映像的可执行段；程序没有用到回音时不生成。无结果的 API 用一个薄包装把 `（化「整数」为「有」）` 一类的闭包包成返回零的 `（化「整数」为「整数」）`，原生侧丢弃返回值。每个槽的代码里已经嵌着槽号与签名号，登记只是把槽标为占用，不做运行时代码生成，不碰 MAP_JIT，也不做 W^X 切换。限额以后可以放大。
- **地址与位置无关**。跳板地址由「林檎代码起址」加固定偏移算出，与线程入口桩同一个办法；映像滑动不影响它。
- **林檎臂六十四的跳板开头照线程入口桩**：保存 x0 至 x3、x30 与用到的被调用者保存寄存器；按线程入口桩的办法装 x25（全局基址）、x15（线性内存字节数），x28 不动；把槽号与签名号放 w0、w1，整数实参放 w2 起；调用执行器导出「原生回音派发」；结果在 w0，恢复寄存器后返回。跳板不触发回收，也不碰 x18。
- **林纳与轩窗**：同样的形状，按 System V 或 Win64 的寄存器与栈规则生成；轩窗臂六十四要先补 `臂降级本术` 待办事项里的回调桩（影子空间、四个寄存器参数）。

### 4.4 派发

执行器新增导出「原生回音派发」，用底层豫言写成，参数是槽号、签名号与至多三个整数实参。它做四件事：

1. 按签名号选应用接口入口名（如 `原生回音/行原生回音整二`），在导出表里按名取函数号；第一次用到时取，取到后缓存。导出表没有名字时，由编译器在侧表里记下四个入口的函数号。
2. 在当前值栈顶造帧，把槽号与实参按边界形写进去（第一版全是整数，即 i64；按签做符号扩展或零扩展）。
3. 调「预编派发」，运行入口函数；入口函数把实参装箱、按号查库表、调用闭包，再把结果拆箱成整数。
4. 检查「状态预编异常」；有异常按未捕获处理（第一版以一百三十七退出，第二版改成回报并继续），否则取帧首的结果返回。

同线程同步调用就停在这里：跳板在原生调用栈上再压一层客体帧，回调跑完回到原生函数，原生函数返回导入桩，导入桩回到原客体帧。回收若在回调里发生，保守扫描会看到这层栈帧；库表是全局根，闭包不会丢。

异线程与讯号走延迟路：

- 登记时 `迟` 为阳，跳板不调派发，只把（槽号，签名号，实参们）原子写进常驻区的环形队列，并把“有待办”标志置一。
- 主线程在每次原生导入返回处（`预编调用导入`）与每次事件等待返回处检查标志，取出全部待办，逐条调派发。回调结果丢弃，所以延迟回音只用“结果无用”的原生 API。
- 讯号处理函数只做这次原子写；不分配、不取锁、不回收、不调豫言。队列满了记一次丢弃计数，不覆盖、不阻塞。
- 队列容量先取二百五十六条，满了只计数；以后按需放大。

重入：同线程回调里可以再调原生函数、再触发回调；深度先限三十二层，超过以一百三十七退出，免得把原生栈耗尽。

### 4.5 生存期与回收

- 每种签名一张 `号 → 闭包` 的普通列表（照 `云工回音表格`），挂在全局上；它天然是回收根，不需要执行器知道闭包在哪。
- 登记：调「登原生回音整二」一类的入口，库内再调「造原生回音」拿回音柄（执行器取一个空槽，槽号就是号）；用「原生回音号」取号，把号与闭包加进该签名的表，返回柄。槽可以复用，号随槽走。
- 注销：从该签名的表去项，调「销原生回音」还槽。原生侧必须先保证不再调用（例如先恢复讯号处理、先停音频队列），第一版不做引用计数，也不做“调用中”保护；这条契约写进包说明。
- 执行器只存号、签名与地址，不存 GC 引用，所以不用钉住闭包，也不用给回收器加根窗。回调帧里只有整数，装箱发生在入口函数里，是普通分配。
- 登记久了不注销会占槽（与 `云工回音` 的待办事项同病）；第一版要求显式注销，终结器留后。
- 程序退出或重启后所有柄失效；跨实例传柄非法。

### 4.6 线程

- 豫言执行器仍单线程；只有主线程碰堆、跑闭包、做回收。后台清扫线程不调回调。
- 同步回音必须由主线程调用；登记时 `迟` 为阴就是对原生 API 的承诺。qsort、Objective-C 委托、取事件期间的委托都属于这一类。
- 异线程回音（音频队列、金属完成回调、讯号）必须 `迟` 为阳；跳板只碰常驻区的环形队列与原子标志，不碰堆。
- 唤醒：讯号可以打断一部分原生等待（如 `poll` 一类），等待返回后排水；`nextEventMatchingMask` 是否被讯号打断要实测。没有讯号时，最迟在下一次原生导入返回或事件等待返回时排水。延迟上限写进包说明；以后需要更及时，再加自管道或事件描述符。
- 环形队列的生产者可能是多个原生线程；索引用原子比较交换推进，单生产者与多生产者都按同一条路走，第一版不追求快。

## 五、各后端做法

| 后端 | 跳板 | 派发与限制 | 步骤 |
| --- | --- | --- | --- |
| 林檎臂六十四 | 冶铸在可执行段生成跳板池，照线程入口桩开头 | 执行器「原生回音派发」直接可见；同步与延迟都做；先做 | 第一、二步 |
| 林檎兼六十四 | 同形，System V 寄存器 | 「林檎本土表」里的原生函数还绑成负一（`降级鹄`），等原生函数调用通了再接 | 暂不做 |
| 林纳兼容六十四、臂六十四 | 兼降级本术生成跳板；静态可执行文件 | 同线程同步；豫行启动器里的客体经服务门跑，回调要在门开着时重入执行器，需单独验证 | 第四步 |
| 轩窗兼容六十四、臂六十四 | PE 可执行段生成跳板；Win64 影子空间与四寄存器 | 臂六十四先补回调桩待办；波形输出的回调可以接上 | 第四步 |
| 诺驿 | `外部库.mjs` 加“造回调”原语，基于 `node:ffi` 的回调 | 只支持创建它的线程；JS 包装按号调应用接口导出；异线程回音不支持，「造原生回音」回报“资源暂不可用” | 第五步 |
| 浏览器、云工 | 没有原生指针；「造原生回音」返回包着 JS 函数的资源 | 宿主用 `实例.exports` 按号调应用接口导出；云工已有「行云工回音」先例；回调必须同步，回调里不能挂起 | 第五步 |
| 裸机 | 不做函数指针 | 内核事件源（定时、输入）把（槽号，签名号，实参）写进事件记录；主循环取出后调同一个入口；中断里只置标志 | 第六步 |

诺驿的“只支持创建线程”不是本文能绕开的：`node:ffi` 的回调本来就在创建它的线程上调用，而诺驿的主线程在原生调用期间是阻塞的。第一版就把这条写成限制；金属完成回调一类继续用同步等待，等诺驿支持跨线程投递再改。

浏览器的难点在“导出还在不在”：程序原本只导出 `_start`，应用接口的导出由编译器按声明生成，宿主建好实例后要一直留着 `exports`；`_start` 还没跑完时来的回调要么排队，要么拒绝，第一版选排队。回调里不能 `坐待`，因为 JS 回调的返回值必须当场给出。

裸机不做函数指针是刻意的：中断上下文里不能跑 GC，也不能碰豫言堆。事件队列加主循环派发与原生后端语义一致，只是“回调”晚一点到；需要同步返回的 API（qsort 一类）在裸机上继续用豫言实现。

## 六、安全与限制

- **原生代码是可信的**。传一个假地址给原生函数本来就能执行任意代码；回音柄只保证“号由宿主发、槽由宿主管”，不把原生调用变成安全边界。收地址的底层函数只给库与适配用，不直接开放给普通应用。
- **不回传 GC 引用**。回调参数与结果只有整数与地址；豫言对象不越过边界。地址若是线性内存地址，跳板可以先减去内存基址再交给豫言（第二步的“线址”类别，见第九节），让库能按字节读。
- **注销契约**。注销后原生侧再调用是未定义行为；库说明要求先停源（恢复讯号处理、停队列、撤委托），再注销。
- **同线程与异线程分开登记**。把异线程 API 登记成同步回音会破坏执行器；第一版靠约定与文档，不做运行时探测。
- **限额**：签名先限四种（零至三个整数参数），每种一千零二十四个槽，合计四千零九十六个登记；环形队列二百五十六条；重入三十二层。都用大值，失败时给明确状态，不静默回绕。
- **异常**：回调里未接住的异常第一版以一百三十七退出，与单元运行的未捕获异常一致；第二版改成打印、计数、返回零，让原生 API 自己处理错误。
- **不做异步**。回调必须当场返回；长任务要另起子程序或排队，不在回调里等。
- **不做运行时代码生成**。跳板池在构建时生成，避免林檎的可执行内存权限问题，也让产物可复现。
- **ABI 版本**：跳板池布局、签名号、派发入口与执行器绑定；改这些要换编译语义号（`库/译场/译料/译设/语义号。数据。豫`），并同步执行器与冶铸。

## 七、备选方案

| 方案 | 做法 | 不取的理由 |
| --- | --- | --- |
| 甲：接口文件直接写函数类型 | 接口里写 `（化「整数」为「有」）`，编译器在调用处合成登记与注销，语法最顺 | 要改边界类型系统、接口检查器与底层模式三处；第一版用资源已够用，留作语法糖 |
| 乙：把闭包对象地址直接交给原生 | 跳板按地址取闭包 | 回收会搬对象，原生侧就握着悬空 GC 引用；还要钉住与改写，风险大 |
| 丙：运行时生成跳板 | 照 libffi 的做法现写机器码 | 林檎要 MAP_JIT 与 W^X 切换，跨平台复杂；固定池够用 |
| 丁：全局“当前回音”加一个通用跳板 | 调原生前写全局格，跳板读它 | 一嵌套就坏；讯号、定时器这类存起来以后再调的 API 根本用不了 |

## 八、实施步骤

1. **接口与库的骨架**：新建 `库/原生回音`（本提案新拟），写接口、应用接口、库表与登记注销；执行器先给桩，让类型检查与文档先过。
2. **执行器与冶铸（林檎臂六十四）**：回音柄表、跳板池、「原生回音派发」、导出表查找；先用一个测试入口验证“原生调回豫言、整数结果正确”。
3. **第一条真实回调**：先用一个原生测试钩子（直接以整数调用跳板）验收同步回调；再验一个延迟回调（讯号或音频队列），核对入队、排水、结果丢弃与不回收；最后给林檎本土表加 `qsort` 一行，配一个“按线址读整数”的小口子，用比较函数排序一个整数列。
4. **林纳与轩窗**：兼降级本术与 PE 跳板；豫行启动器的服务门重入单独验；轩窗臂六十四补回调桩。
5. **诺驿与浏览器、云工**：`外部库.mjs` 的回调原语；浏览器宿主保留导出并按号调入口；云工沿用现有回音入口，补原生指针的等价物。
6. **裸机与收尾**：内核事件队列与主循环派发；包说明、接口规范、语义号、限额与待办事项一并写清；补一个跨后端的一致性测试（同一闭包在原生与诺驿上各跑一次）。

每步只提交自己的路径，验证按 AGENTS 的“最便宜且有用”办；第二、三步之后就能拿 qsort 做端到端验收。

## 九、未决问题

| 问题 | 现状与倾向 |
| --- | --- |
| 接口里要不要允许函数类型（语法糖） | 第一版不做；等库 API 稳定后再议，做的话编译成登记号，不放进边界签名 |
| 小数、结构体按值、多结果 | 第二版；按现有的参数类别与出槽办法扩，double 走浮点寄存器 |
| 异线程唤醒 | 第一版靠讯号打断与下一次导入返回；自管道或事件描述符留后 |
| 回调里的异常 | 第一版直接退出；第二版改成打印、计数并返回零，具体语义待定 |
| 槽复用与终结器 | 槽可以复用，第一版不做终结器；登记久了不注销就占槽，与 `云工回音` 同病 |
| Objective-C 委托与 block | 回调通了以后还要建类、拷贝 block、管生命周期，另写方案 |
| 轩窗臂六十四的桩 | `臂降级本术` 已有待办；Win64 的影子空间与浮点参数要单独验 |
| 与提案 00044 的关系 | 00044 做的是挂起与恢复的栈切换；回调若从挂起中的栈进来，要先定用哪条栈，第一版只在同步路径做 |
| 裸机的等价语义 | 事件队列的延迟上限、队列满时的丢弃与计数要写进规范；同步 API 在裸机上继续用豫言 |
| 原生地址与线性内存地址 | 第一版一律按不透明整数传；第二步加“线址”参数类别（跳板减内存基址），`qsort` 一类按址读值的回调要用 |
