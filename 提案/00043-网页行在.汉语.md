## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | **浏览器作行在的又一种宿主**：标签页的主线程就是行在（任务表、任务之间的消息、屏幕与键鼠），每个任务是一个 Web Worker。目的是应用层的缺陷在网页上与原生一样出现；代码生成（网页汇编对冶铸）、回收器与时序这类平台差别不在目标内 |
| 议二 | **同一份源码，同一条代码路径**：开机程序（`应用/豫构/开机。豫`，即豫构交互）、图形桌面、桌面程序与 /工具 里的程序，用同一个编译器前端编成网页汇编（WasmGC）程序。网页专用的壳（旧开机壳，网页上叫“原壳”）退役 |
| 议三 | **差别压到最低一层**：网页与原生的差别只留在东道（宿主接口）与豫言操作系统接口的宿主实现里。适配（`豫言操作系统/适配`）尽量用与原生相同的通用实现，网页专用的适配逐步换掉 |
| 议四 | **豫构交互在网页汇编上运行**：每句编成网页汇编单元，装进本进程（本 Worker）运行，与原生“装进本进程”同义。诺驿（Node）宿主与浏览器宿主各补一组装入网页汇编单元的宿主函数 |
| 议五 | **文件树同裸机**：/源（前导要用的源码与阶段缓存）、/工具（网页汇编版的工具）、/系统、/数据、/软件。/数据与/系统存进站点私有存储（OPFS），重新载入后还在 |
| 议六 | **页面只是屏幕与键盘**：页面把画布交给桌面任务（OffscreenCanvas），把键鼠事件送进行在，不承载命令或业务逻辑 |
| 议七 | **双端对照**：同一批壳脚本在宿主的行在里与无头浏览器里各跑一遍，比对输出与截屏，放进 CI 的抽样轮次 |
| 议八 | **分五步实施**（第八节），每步单独合入 |

## 二、现状（2026-10-19 调查）

网页版由仓库目标「用户态系统浏览器发行」构建（`应用/豫构/仓库目标。豫` 的「原壳发行步们」），与裸机只共用桌面界面这一层源码：

| | 裸机与行在 | 网页版（`/操作系统/原壳.html`） |
| --- | --- | --- |
| 壳 | 豫构交互（`应用/豫构/开机。豫`），每句编成单元装入 | 旧开机壳 `豫言操作系统/裸机/壳/壳。豫`，只走快路；别的句子报“这里只运行壳命令”（`库/诏令/快路。豫`「行壳令句」） |
| 输入 | 组字、直读，逐键 | 行模式；逐键未接 |
| 窗口 | 每窗一个任务（00015），外壳请求与来信经初始任务 | 全在一个 Wasm 实例里：「本机桌面程序」返回空串 |
| 终端窗口、「行」「营」 | 起 `/工具/豫构。豫行 交互` 子会话、子程序 | `豫言操作系统/适配/子程序浏览器` 只回“资源暂不可用”，终端起不了会话 |
| 文件 | /源 /工具 /软件 /数据 /系统 | 站点私有存储里授权的“桌面”根 |
| 宿主接口 | 内核与执行器原语 | `豫言操作系统/宿主/浏览器/宿主.mjs` 约 4200 行另写一遍；东道里的拼音等函数是桩（`库/豫章/东道。接口。豫`） |
| 代码生成与回收 | 冶铸（原生后端）与执行器回收器 | 网页汇编与浏览器回收 |

浏览器这边的验收文档停在 10-05；此后原生删了快路（10-14）、统一成唯一的壳（10-16）、上了行在（10-19），差距在变大。

已有可用的零件：

- **浏览器构建宿主**（`豫言操作系统/宿主/浏览器/构建/`）：内存文件系统、主线程进程表（每个豫言程序一个 Worker）、经共享内存同步提问主线程（`Atomics.wait`）、JSPI 独立栈；已能在浏览器里跑豫构的检查、类型检查、构建与测试，速度与诺驿相当。
- **试写间编译器**（`豫言操作系统/宿主/浏览器/编译器/`）：浏览器检查点（每 1024 次函数进入查一次时限）。
- **诺驿宿主的单元目录装载**（00003）：按“顺序.txt”逐个实例化网页汇编单元，共用零号表与两个异常标签，“单元”导入取先装入单元的同名导出。
- **九宫（平铺桌面库）**：同一份「行平铺桌面」既跑网页也跑裸机。

## 三、目标与范围

目标：

- 网页版开机进豫构交互，壳里能执行的句子与原生相同（每句编译，不设快路）；
- 「图形」进同一个桌面，每个窗口是一个任务；终端窗口里是豫构交互会话；「列出役」看得到全部任务；
- 文件树与裸机相同，/数据与/系统重新载入后还在；
- 同一个壳脚本在网页与宿主行在上输出相同（第六节列出的平台差别除外）。

不在范围：

- 冶铸降级、执行器回收器与多核时序的缺陷：这些是平台缺陷；
- 硬件与系统槽类命令（「器列」「安寓」「葺寓」「营启盘」「系统槽状态」等）照旧印“本环境不能……”；
- 远程登录与行在门：浏览器没有 TCP；「索书」走 fetch。

## 四、设计

### 4.1 浏览器里的行在

- **主线程是行在**：沿用构建宿主的进程表（`构建/进程.mjs`），每个任务一个 Worker；任务号从一起编，行在自己是零号。补上 00039 4.3 里交行在的服务：列任务、任务信息、结束（`Worker.terminate`，退出码 130）、打断，任务之间的消息经主线程转交。
- **标准流**：任务之间、任务与页面终端之间的管道放在主线程，读端经共享内存阻塞等待（同构建宿主的同步提问）。
- **打断**（「辍」）：编译器以 `--浏览器检查点` 编出的程序每 1024 次函数进入查一次共享标志，打断时抛出与原生相同的中断异常。
- **跨源隔离**：共享内存要求页面跨源隔离，`/操作系统/` 下的页面带 COOP、COEP 头（云仓改动）。

### 4.2 豫构交互在网页汇编上运行

- 豫构判断本进程能不能装原生单元（`应用/豫构/入口。豫`「运行」里已有的判断）；不能时，前导与每一组都编成网页汇编单元（`库/译场/分职/笔受/网汇单元。豫`），经新的宿主函数装进本进程：建单元表、装入一个单元目录（带命令行参数与程序名）、取退出码。宿主保留已装单元的导出，后装的单元按名取用，与原生同义。
- 诺驿宿主先实现（便于测试），浏览器构建宿主的工作线程同样实现。
- 前导预编：发行时以网页汇编为目标运行 `豫构 预编前导`，把前导单元与编句要读的阶段缓存一起放进 /源 的快照。

### 4.3 桌面与桌面程序

- **桌面是屏幕的主人**：「图形」照开机壳写下进入桌面的请求，行在起图形桌面任务，页面把画布以 OffscreenCanvas 交给它；显示原语在 Worker 里画。
- **桌面程序是独立任务**：行在给桌面设 `豫言桌面程序`，九宫照裸机把每个窗口起成桌面程序的任务（「遣使附映面」）；子任务的画面放在共享内存里，桌面合成，事件经管道送达，外壳请求与来信同走这对管道。
- **截屏与拟入**：「截屏」「点击」「击键」等照 00039 4.5 的屏块语义，在主线程读写桌面任务的画面与注入环。

### 4.4 文件树与持久化

- 内存文件系统摆出同裸机的树：/源 与 /工具 来自随站点发布的快照（gzip 的 tar，存进 Cache Storage，按语言仓提交号分）；/系统、/数据、/软件 在 OPFS 里，开机时读入，写入时回写。
- /系统/开机。数据。豫 等配置与裸机同一套写法。

### 4.5 页面与发行

- **页面**：`/操作系统/` 下一页全屏画布；进桌面以前显示文字控制台（同裸机开机时的控制台），页脚写语言仓提交号。
- **仓库目标**：新目标「网页行在发行」取代「用户态系统浏览器发行」：编出网页汇编的豫构、图形桌面、桌面程序与 /工具 里能在浏览器跑的程序，预编前导，打出快照，连同浏览器宿主的 `.mjs` 一起放进发行目录；云仓的自动发布照旧取用。

### 4.6 拟名

| 通称 | 名字 | 由来 |
| --- | --- | --- |
| 浏览器里的系统实例 | 网页行在 | 合成词：网页（宿主种类）加行在（00039）；与“宿主上的行在”“豫言系统里的行在”（00042）并列 |

仓库目标「网页行在发行」照「用户态系统节点发行」的写法。其余沿用现有名字。

### 4.7 声音

豫寓鸣（声音输出）在网页行在里由 AudioWorklet 接上 Web Audio：工作线程（跑豫言任务）造一条共享内存的环形缓冲，往里面写交错的十六位样本；音频线程里的工作件（AudioWorklet 处理器）读出来播放，缓冲空了补静音，放不下一整块就整块退回（资源配额已尽）。采样率、声道照接口规范，浏览器采样率不同就在工作件里按线性插值重采样。控制字（写位置、读位置、设备延迟）放在同一块共享内存里，已播帧数与声出延迟由工作线程直接读，不必再问主线程。页面已有跨源隔离（共享内存的前提）；AudioContext 要用户手势才能启动，页面在第一次按键或点击时恢复声境。

壳命令「试声」走的就是这条路径（声音一部的做法调豫寓鸣），用来验收。

## 五、兼容与迁移

- 原生与裸机不变；诺驿多出装入网页汇编单元的宿主函数，补上与原生相同的豫构交互（AGENTS.md 诺驿一节：原生已有的功能）。
- 第二步完成后，`/操作系统/原壳.html` 改为跳转到新页面；旧开机壳只留作 `-kernel` 验证夹具。
- 网页专用的适配随第五步逐个换成通用实现，`豫言操作系统/宿主/浏览器/宿主支持清单.tsv` 同步修改。

## 六、平台差别（不追求一致）

- 代码生成与回收：网页汇编与浏览器回收；
- 调度与时序：浏览器 Worker 的调度、单页面的事件循环；
- 内存上限：浏览器给每个 Worker 的堆上限与原生不同；
- 网络：没有 TCP；
- 声音：经 AudioWorklet 读共享内存的环形缓冲，浏览器采样率不同时在线性插值重采样；AudioContext 要用户手势才启动，页面在第一次按键或点击时恢复。缓冲放不下一整块时整块退回（资源配额已尽），应用等已播帧数增加后再写。

## 七、备选方案

1. **浏览器里仿真整机，装同一张盘**：平台缺陷也一致；要自写仿真器（不引第三方库），且慢。不取。
2. **把底层豫汇编成不带 GC 的 Wasm，连执行器回收器一起跑**：回收器与原生同一份，但精确栈图在 Wasm 里做不到，要改影子栈，代码路径照样不同。量大，不取。
3. **保留原壳、补快路**：违反“唯一的壳”（AGENTS.md）。不取。

## 八、实施步骤

1. **豫构交互在网页汇编上运行**：宿主函数（诺驿、浏览器工作线程）、豫构选网页汇编单元。验收：`node 豫言操作系统/宿主/节点/宿主.cjs 豫构.wasm 交互 --直读` 跑通「复述」、定义后再用、裸式印值与壳命令。
2. **网页开机进豫构交互**：新页面与浏览器行在的骨架（进程表、文件树、终端与标准流、跨源隔离），新的发行目标与云仓发布。验收：页面开场即壳提示符，「复述」「案牍」之「列目」与宿主输出相同。
3. **「图形」与桌面任务**：桌面任务拿画布，桌面程序独立成任务，终端窗口起豫构交互会话；「列出役」「辍役」「截屏」「辟窗」可用。
4. **文件树与持久化**：/数据与/系统存进 OPFS，/工具、/软件按盘的布局摆好。
5. **补齐与对照**：东道的桩、逐键组字、去掉网页专用的适配；双端对照测试进 CI 抽样轮次。

## 九、未决问题

1. 前导单元与阶段缓存的体积和首次载入时间（估计几十 MB）。
2. Safari 对 JSPI、共享内存与 OffscreenCanvas 的支持程度。
3. /工具 里哪些程序编成网页汇编（依赖 TCP 与设备的除外）。
4. 「辍」在 Worker 里只靠检查点够不够快。
