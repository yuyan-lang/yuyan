一句话：让每段要进共享地址空间的机器码随身带一份过所（携证凭据），装入前由司关（凭据检查器）核对它守不守关禁（边界政策）；司关的正确性在证明层里对着机器语义证一次。这样译场（编译器核心）、笔受（代码生成）与冶铸都退出隔离的可信基。

## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | **两道边界**：外界是任务与行在、与别的任务之间的界，在机器码（豫行、单元）这一层核对，只管访存、寄存器、控制流、指令与门，不管类型；内界是任务之内、封（隔离域）与单元之间的界，即引用不可伪造、节（能力）不可伪造，在树码（豫汇）这一层由类型保证，日后带到机器码 |
| 议二 | **不信编译器，验产物**：机器码要进共享地址空间（00067 第三版的单进程行在、00038 的同进程封、浏览器的页程），映成可执行之前先交司关核对；不过的不进，改作任务封（宿主进程或裸机页表隔离） |
| 议三 | **证一次，凭据随行**：每个单元带的过所只是数据，没有证明项：第一期只记版本、编译档、所用的门与重定位的用途，核对主要看代码自身的写法；第四期加块入口的类型。基础的部分是一条定理：司关收下的代码，在机器语义下守关禁。定理在证明层证一次，与程序多少无关 |
| 议四 | **关禁写在机器语义上**：关禁是机器状态上的谓词，机器语义是冶铸所用指令子集的可执行豫言模型；模型与真机对拍 |
| 议五 | **一份指令声明**：指令子集只声明一次，冶铸的编码器、司关的解码器、证明用的语义与文档都由它生成，三者不会走样 |
| 议六 | **界内之物不可信**：节的掩码、籍号与限额移出任务可写的内存，归行在核，门上核对；受限运行因“底层代码能改掩码”而拒收底层单元的限制，随之可以撤去 |
| 议七 | **证明语言改两处结构**：证核（证明检查核心）独立成包、不依赖译场；证明检查里的计算由证核自己的求值器做，不跑编译出来的代码。00016 的计算类型论、外延相等、一切可抛、两层与擦除照旧（第六节） |
| 议八 | **证明层的试点改为司关证成**：一条定理、停点清楚，正好检验证核要有的能力（定宽整数、内存映射、状态机不变式、反射式判定） |
| 议九 | **分五期**：外界检查（先能用、未证）→ 司关证成 → 树码内界定理 → 带类型的过所（GC 代码免掩、同进程封不信编译器）→ 执行器与行在核的证明（第十一节） |

每个任务一个宿主进程时，这些都只关乎程序自己对不对；一旦多个任务同在一个宿主进程（00067 第九步），或网页、市肆（软件目录）的代码进来，译场、笔受（连同省检查的十个证明函数 `库/译场/分职/笔受/网汇*证明。豫`，约一千四百行）、冶铸里的任何缺陷都可能成为越界的口子。这几样是全仓最大、改得最勤的部件，编译语义号常换。

### 2.2 代码生成器是沙箱最常破的地方

Wasmtime 的 CVE-2023-26489：Cranelift 在 x86-64 上折叠地址算式时把移位后的索引算宽了，有效地址越出 Wasmtime 依赖的保护区，客代码能读写沙箱外的内存，评分 9.9；AArch64 后端不受影响。Wasm 的类型检查一条没错，错在下一层。Crocus（ASPLOS 2024）后来逐条验证 Cranelift 的降级规则，重新找出这一条，另找出两个新缺陷。豫言的冶铸与 Cranelift 处在同一位置。

### 2.3 为什么不验证编译器，也不只靠硬件

- **验证编译器**（CompCert、CakeML 式）：要证的是译场与冶铸本身，几十万行、天天在改，证不过来；而且每改一处都要重证，与“每个功能以最快的速度完成”相反。验产物让编译器照旧随便改，可信基固定、小而少变。
- **只靠硬件隔离**：00067 第三版已定宿主上不用宿主进程隔离任务（记账、换页、调度都要归行在）；硬件虚拟化正是它要替掉的。裸机上照旧用页表，本提案只管共享地址空间的情形。

## 三、前例

| 工作 | 做法 | 与本提案的关系 |
| --- | --- | --- |
| 携证代码（Necula、Lee，1996–1997） | 代码带证明，消费方按验证条件生成器与安全规则核对 | 生成器与规则在可信基里 |
| 基础携证代码（Appel，LICS 2001） | 安全政策直接写在机器语义上（高阶逻辑，编码进 LF），可信基只剩证明检查器、机器语义与政策；普林斯顿组报告可信基可压到两千七百行以内，其中证明检查器 803 行 C | 本提案“关禁写在机器语义上”取此；逐程序的证明太大，不取 |
| 语法式基础携证（Hamid、邵等，LICS 2002）；TALT（Crary，POPL 2003） | 带类型的汇编加机械化的类型可靠性证明，类型推导即凭据 | 第四期“带类型的过所”取此 |
| Bartok 与 Singularity（PLDI 2008）；Verve（PLDI 2010） | 优化编译器输出带类型汇编，装前检查；Verve 的核心（回收器、调度、中断）用霍尔逻辑另证，其余每条指令由类型检查器核对 | 同进程隔离不信编译器的先例；执行器的证明（第五期）照 Verve |
| RockSalt（PLDI 2012） | 原生客户端（NaCl）式软件隔离检查器，在 Coq 里对着 x86 模型证明可靠；检查器约八十行，原版约六百行 | 外界检查器证一次的先例 |
| VeriWasm（NDSS 2021） | 检查 Wasm 编译器产出的 x86-64 机器码守不守堆、栈、控制流的隔离，可靠性论证在 Coq 里核过，用于 Fastly | 第一期的样子 |
| vWasm、rWasm（USENIX Security 2022） | vWasm 用 F* 证明沙箱化一步；rWasm 靠 Rust 的类型安全，论证非形式 | 验证编译器一路的代价参照 |

| Islaris（PLDI 2022） | 对着完整的权威指令集规格（Sail 版 Armv8-A、RISC-V）验证机器码 | 机器模型的可信来源 |
| cake_lpr（TACAS 2021） | 证明检查器经 CakeML 验证到机器码，已用于 SAT 竞赛核对证明 | 司关二进制日后可这样去掉 |

启示：

1. **证一次，凭据随行。** 豫构一个程序九十一兆，逐程序带完整证明不可行；实用的一脉（TALT、RockSalt、VeriWasm、Bartok）都是检查器证一次，每个程序只带小凭据，检查是线性的。
2. **边界分两层。** 隔离一层（不越界、不乱跳）只要一阶不变式，检查器与证明都小；类型一层（引用不可伪造）要逻辑关系，大得多。两层分开，前一层先做。
3. **余下的可信基是运行时与内核。** Verve 把回收器等另证；我们的执行器与行在核同此，排在最后。

## 四、两道边界

### 4.1 外界：关禁

任务的状态：区 R（2^k 字节、按 2^k 对齐的线性内存，状态格、全局、GC 堆与原生栈都在里面，两端各有保护区）、代码区（各任务共用，00067 9.6；里面每一字节或是过了司关的代码，或是陷阱填充）与共用的只读数据、门（服务门的门项、执行器跳板、行在核入口）、留用寄存器（线性内存基址与全局基址，以冶铸现行约定为准：AMD64 r9、r10，ARM64 x28、x25；另加掩码寄存器与专用地址寄存器，见 4.2）。

| 禁 | 内容 |
| --- | --- |
| 禁一 访存 | 访存地址只有三种写法：基址 + 专用地址寄存器 + 小常量；全局基址 + 小常量；sp + 小常量。小常量不超过保护区，所以每次访存落在 R、保护区（陷入）或只读的共用区里 |
| 禁二 寄存器 | 基址、全局基址、掩码寄存器，任务代码不写；专用地址寄存器只能由掩码指令写，任一指令处都在界内；sp 只能小步移动，移出 R 之前必先撞上保护区，或者经掩码重设 |
| 禁三 控制流 | 直接转移的目标是司关解码出的指令起点；间接转移与返回先把目标掩进代码区、对齐到块界；门项与跳板只经直接调用进入。掩过的跳转可能落到别的单元的代码里，无妨：那里的代码也过了司关，访存都相对当前任务的基址 |
| 禁四 指令 | 不出现系统调用（门项之外的 `svc`、`int`、`syscall`）、特权与系统寄存器指令；只出现指令声明里的子集；代码页只读可执行，不自改 |
| 禁五 门 | 所用的门 ⊆ 清单里的所需之节，这一条静态核对只为早报；把关的是门本身，按行在核里的掩码核节。门区放在代码区之外，或者每束都是一个完整的门项（NaCl 的跳板区同此） |
| 禁六 陷阱 | 保护区、`ud2`、`brk` 这类陷阱算作任务自己的结束，只结束出事的任务（00067 9.5） |

关禁不问类型：任务可以弄坏自己的堆，受害的只是它自己。

### 4.2 关禁带出的设计约束

00067 第九步落地时照办，否则司关无从核对：

1. **控制流取粗粒度。** 间接转移与返回都先掩进代码区、对齐块界（NaCl 与 RockSalt 的做法），返回地址就不必保护：原生栈放进 R，回收器回写栈槽、异常展开、执行器栈切换（00044）、原生回调（00045）都只是 R 里的普通读写加掩过的跳转，不另立规则。另一条路是细粒度：栈另成一段、栈上的写限在本帧、返回用原样的 `ret`（VeriWasm 的栈安全），省掉返回处的掩码，但回收器回写、展开、栈切换都要各立规则；留给第四期，那时司关推得出栈帧的类型。
2. **掩码用专用寄存器。** 原生产物默认六十四位地址（`应用/豫言编译器/文档/底层模式.汉语.md:115`），`[基址 + 六十四位偏移]` 关不住，保护区一法不够，要与 2^k−1 按位与（00067 9.5 已拟，原只用于不受信的底层代码）。专用地址寄存器只能由“置为掩码”与“与某寄存器按位与”两种指令写，任一指令处它都在界内，跳到哪里都不怕。可信构建的访存本来就经 r11 寻址（`豫言操作系统/裸机/文档/寄存器降级.汉语.md:14`），把它定为专用、别处不再拿它作临时即可。掩码超出三十二位立即数，AMD64 要多占一个掩码寄存器；ARM64 的 `and` 立即数放得下。
3. **AMD64 分束。** 指令变长，掩过的目标可能落进一条指令中间。照 NaCl：代码按三十二字节一束，束内指令不跨界，间接转移的目标与调用的返回点都对齐到束首。ARM64 指令定长四字节，不必分束。
4. **手写的桩同受检查。** 栈回写桩、栈图表复制桩、线程入口桩、门模板，或者照关禁的写法改写、过司关，或者移进行在核。
5. **让步不靠核对。** 粗粒度控制流下，任务能用掩过的跳转自造没有轮询的环，司关核不住“环上必有轮询”。所以行在要能异步抢占：时钟信号在任意指令处换下任务（各任务的回收器互不相干，换下不需安全点），冶铸插的轮询（00067 9.4）只作快路。
6. **界内之物不可信。** 节的掩码、籍号、限额不放在 R 里（议六、5.4）。

### 4.3 内界：树码的边界

**陈述。** 豫汇模块 M 通过验形后，与任意上下文只经导入相连：M 只能影响它自己分配的、别人传给它的，以及凭所授之节够得着的东西。形式上是豫汇语义上的一个逻辑关系及其基本定理（Iris-Wasm 的鲁棒安全）。这是严格意义上“从语言层面”的边界：它是豫汇这门语言的性质，对一切合法模块成立。

**要补的。** 一个独立于译场的豫汇验形器（执行器现在不验，网页的网汇经译场的网汇校验，捷思编出的豫汇无人验）；豫汇的形式语义。

**带到机器码。** 冶铸按豫汇类型给每个块的入口记寄存器与溢出槽的类型（引用指向哪种结构、可否为空、i31、带签名的函数引用），司关的类型档据此核对：经类型核过的对象访问可免掩码（寄存器降级里“可信代码省去查界”由此变成“核过的代码省去查界”），同进程封与节的不可伪造在机器码上也成立。

### 4.4 先后

外界先做：00067 第九步、浏览器页程、市肆都等它；一阶证明、检查器小、过所简单；执行器（GC、对象操作）也是编成机器码、在任务区里干活的代码，同样过司关，于是连执行器也退出外界的可信基。内界在外界之上加类型，排在后面。

## 五、过所与司关

### 5.1 过所

装载单元加一种段（编号实施时定），记：

- 第一期：关禁与司关的版本、编译档（共享模式）、所用的门与跳板、重定位的用途（重定位段已有类别，司关据此核填进去的值落在哪：全局偏移在全局区内，执行器函数地址只在跳板里）。核对主要看代码自身的写法（4.2），不必记函数与块。
- 第四期加：函数与块的起点、帧布局（引 00020 的栈图表，其中已有每函数的码偏、帧大与保存次序）、块入口的寄存器与溢出槽类型。

单元按摘要命名，过所随单元入单元仓库。

### 5.2 司关

- **写法**：普通带 GC 豫言的纯函数，`（码、过所、关禁参数）→ 成否`，不读写文件、不碰匣；纯函数正好落在 00016 第一阶段的语义范围里。跑在行在里、映码之前；若行在核最后只用底层豫言（00067 第七节第一问），司关另出底层版，证明要等 00016 的底层代码证明。
- **步骤**：从头顺序解码（AMD64 核束内指令不跨界）→ 核直接转移的目标都是解码出的指令起点 → 逐条核访存写法、寄存器的写法、间接转移与返回的掩码写法、禁用指令 → 汇总所用的门，比对清单。不建控制流图、不推抽象状态，一遍线性；第四期的类型档才要按块推类型。
- **解码**：由议五的指令声明生成，只认冶铸会出的子集，其余一律拒收。
- **先测后证**：反例集（每条禁至少一组手造的坏单元：写基址、绕过掩码的访存、sp 一步跨过保护区、裸 `syscall`、跳进指令中间、未掩的间接跳转）全拒；对好单元逐字节变异，司关要么拒收，要么收下的在监控下运行不越界；机器模型与真机对拍。

### 5.3 装入与缓存

- 行在把单元的机器码映成可执行之前先过司关（共享进程里映码归行在，00067 9.6）；结果按（单元摘要、司关版本、关禁参数）记进单元仓库，同一单元在一台机器上只核一次。
- 不过的单元不进共享进程：改作任务封；连任务封也不许时报出未过的禁与位置。
- 清单附录加一项（编号实施时定）：是否按共享模式编出。

### 5.4 门与节

- 门项照豫行格式的服务门（代码段开头 64 KiB，第 N 项在起址加 N×16）；司关核每次对外调用都落在门项或登记的跳板上。
- 节的掩码、籍号、限额改存行在核，按任务号索引；门上核对。掩码不在 R 里，底层单元改不到，受限运行可以收下过了司关的底层单元。

## 六、证明语言重审

### 6.1 证什么

外界定理（写法未定，示意）：

```
司关 ∈ (码 : 帛) → (证 : 过所) → (参 : 关禁参数) → 可抛 {判 : 爻 | 判 = 阳 ⇒ 守关禁(码, 参)}
守关禁(码, 参) ≝ ∀ 态. 初态(码, 参, 态) ⇒ ∀ n. 不越(参, 走(n, 态))
```

- **证法**：不变式“合式”与程序点无关：留用寄存器是原值，专用地址寄存器在界内，sp 在 R 与保护区的余量内，指令针在司关解码出的某条指令起点（AMD64 另在束内）。初态合式；合式的态走一步仍合式（每类指令一条引理）；合式蕴含不越。控制流在语法上已受限，不需要步进索引，RockSalt 一类证明小就小在这里。
- **门契约是公理**：行在核每个门对机器态的前后关系（不动留用寄存器、只按规定改 R、返回到调用点）记作假设，即 00016 议八“宿主实现记作假设”在机器层的形态。
- **内界定理**：豫汇语义上的逻辑关系与基本定理（4.3），要步进索引，排在第三期。

### 6.2 00016 照旧的部分

- **计算类型论正合用。** 司关、机器模型、关禁都是实现层的豫言函数，定理就是“实现层的函数属于某精化类型”（00016 写法乙），不必像高阶逻辑那一路先把程序抽取出来。用户定的 NuPRL 式由此得一个实际的理由。
- 外延相等、一切可抛、非终止同抛出、证明不进产物、完整证明存档逐步核对，都照旧。
- 整数定宽回绕的承诺（00016 第七节第 6 条）是机器推理的前提，照旧。

### 6.3 要改的部分

1. **证核独立。** 00016 第七节第 10 条定“证明检查器独立成包，依赖译场的抽象语法与类型检查资料”。基础携证的要害是可信基小，检查器依赖译场就把编译器前端带回可信基。改为两包：证核只依赖豫章（标准库），检查一种小的核心演算，是可信基；证场依赖译场，把 `。证明。豫` 解析、细化成核心项，不可信，出错只会让证核拒收（德布鲁因准则）。核心规则从少：NuPRL 的原始规则多，证核只收能推出其余的一小组。
2. **计算归核。** 00016 4.10 把“编译器对求值规则的忠实实现”列进可信基。证明检查里的化简与反射计算一律由证核自己的核心演算求值器做，不跑编译出来的代码。编译器只出现在“被证程序的二进制”（司关的二进制）这一处，见 6.4。
3. **第一阶段加机器推理。** 00016 第一阶段是纯计算、异常与接口契约；外界定理还要定宽整数、有限映射（内存）、状态机的归纳不变式。这些都是一阶的，不需要步进索引。
4. **判定过程经反射。** 00016 把证明自动化留到后面。机器码的证明处处是位运算（`(x & (2^k−1)) < 2^k`）与线性算术，判定过程写成豫言函数、证一次可靠、由证核执行，自动化不进可信基。
5. **试点改为司关证成。** 00016 实施步骤第 4 步的试点（云仓公共库的校验器）改为司关证成：一条定理，停点清楚，用到的正好是证核要有的能力。也满足 00016 的恢复条件（用户点名恢复）。
6. **有状态的契约先在机器层写。** 门契约是机器态上的前后关系，用普通谓词写即可；源语言的霍尔类型论（00016 第七节第 9 条）不必为此提前。

## 七、代价与风险

- **运行**：共享模式每次访存一条掩码，每次返回与间接转移多两三条，AMD64 分束要补空指令，另占一两个寄存器；第四期起核过类型的访问免掩、返回改回原样。照 00067 议十一与独行对比实测。
- **装入**：司关线性，按单元摘要只核一次；豫构这样的大程序首次装入多一遍扫描。
- **工程**：冶铸加共享模式与过所；司关数千行；指令声明覆盖冶铸所用的子集（两个汇编器的编码测试现有 AMD64 四百六十例、ARM64 六十余例，可作起点）；证明数万行，由代理写（00016 动机第 1 条）。
- **风险一**：冶铸有些写法司关核不了（省掉的检查、手写桩）。共享模式里照关禁的写法出码，独行的可信构建照旧。
- **风险二**：执行器在内界仍是可信的，它维持堆的不变式；外界不受影响，因为执行器同过司关。
- **风险三**：司关的二进制由冶铸编出，冶铸若把司关编错，可能放过坏代码。司关小而少变，二进制按摘要钉死，并用它核它自己（只查得出它不越界，查不出它对不对）；彻底去掉要验证一条朴素的编译路径（cake_lpr 的做法），列为后续。

## 八、兼容与迁移

- 独行（每任务一宿主进程）与裸机（页表隔离）不变；共享模式是冶铸的新编译档，只在进共享进程时用。
- 旧单元没有过所，照旧作任务封运行。
- 单元的过所段、清单附录的共享模式项都是新增，编号只增不改（00021 议八）。
- 00067 9.5 与 9.9 第九步照本提案细化（4.2），9.4 的抢占改为异步为主、轮询作快路；00038 第三步“同进程封靠类型安全”在第四期后改为“靠司关核过的类型”。
- 00016 的状态由用户定：本提案请按第六节恢复其第一至三步，试点换成司关证成。
- 名字第一次进代码时登记进翻译列表（第十二节）。

## 九、备选方案

- **验证编译器**（CompCert、CakeML 式）：要证的部件太大、改得太勤，不取（2.3）。
- **每个程序带完整证明**（Appel 原式）：证明比代码还大，豫构这种规模不可行，不取。
- **只验树码、信冶铸**（Wasm 引擎的做法）：CVE-2023-26489 一类的毛病正出在这里；树码验形照做（4.3），但不能代替机器码检查。
- **只靠硬件隔离**：00067 第三版已否。
- **借外部证明器**（Coq、Lean、Isabelle）：可信基跨了语言，违反只写豫言；证核本身不大，自己写。
- **只做软件隔离、永不做类型凭据**：外界够用，但同进程封与节的不可伪造始终信编译器，GC 代码永远要掩码，不取为终点。

## 十、未决问题（请用户定）

1. **先后**：先做外界（推荐），还是外界与内界并进。
2. **共享模式里 GC 代码先加掩码**（推荐，第一期即可用），还是等带类型的过所再进共享进程。
3. **控制流粒度**：第一期取粗粒度，返回也掩码（推荐）；细粒度留给第四期（4.2 第 1 条）。
4. **抢占**：行在以异步抢占为主、轮询作快路（推荐）；只靠轮询则粗粒度下让步核不住（4.2 第 5 条）。
5. **没过司关的单元**：改作任务封（推荐），还是一律拒收。
6. **00016 的两处结构改动**（证核独立、计算归核）与试点改为司关证成：照第六节改（推荐）。
7. **司关二进制留在可信基里**：眼下接受（推荐），验证编译路径列为后续。
8. **指令声明的形式**：先写成籍册（数据文件）加普通豫言的语义函数（推荐，不改语言）；若要做成指令子语言，另写提案。
9. **拟名**：第十二节。

## 十二、拟名

| 通称 | 雅名 | 由来 |
| --- | --- | --- |
| 携证凭据（certificate） | 过所 | 汉唐出入关津所持的通行文书。《释名》：“过所，至关津以示之。”《唐律疏议》：“关谓判过所之处。”代码进共享进程如人过关，出示凭据 |
| 凭据检查器（certificate checker） | 司关 | 《周礼·地官》：“司关掌国货之节，以联门市。”司关验出入之节，与能力称「节」（00038，《周礼·掌节》）同族 |
| 边界政策（safety policy） | 关禁 | 同上，司关“掌其治禁”：关上所禁之事 |
| 证明检查核心（proof kernel） | 证核 | 合成词，古书无成例；与行在核同取“核” |
| 外界、内界 | 外界、内界 | 今语，不另起雅名 |

出处已在殆知阁语料里核过（《太平御览》《容斋随笔》引《释名》，《周礼》原文）。仓里没有这四个顶层名。
