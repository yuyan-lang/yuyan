| 项 | 内容 |

| 状态 | 讨论中 |

| 范围 | 把豫构（构建工具）的构建、类型检查、运行从 `应用/豫构/入口。豫` 抽成库「营缮」（候选名）；请求写成类型「营务」；豫构命令行、九宫（工作台）、全树测试与壳命令「营」都改用它 |
| 相关 | 提案 00036 第九节第三轮（壳命令「营」）；提案 00003（脚本运行模式）；提案 00034（共享构建缓存与多程序构建） |

本文只写现代汉语（AGENTS.md）。

## 一、拟定事项

- 议一：新建库包「营缮」，把入口里构建（包或单文件）、类型检查、运行（源文件编成单元运行）的实现搬进去；豫构命令行只管解析参数与分派。
- 议二：请求写成和类型「营务」，公共选项写成命名元组「营设」。库给出三个函数：「办营务」在本进程办一项请求（豫构用）；「营务作参」把请求写成豫构命令行参数（另起进程的调用方用）；「参作营务」把命令行参数解析回请求（豫构用）。后两个放在同一模块，有往返测试。
- 议三：九宫、全树测试与诏令的「营」改成构造「营务」，不再手拼参数列。
- 议四：调用方照旧另起豫构进程（壳、工作台、测试工具都不把编译器链进自己），进程边界上的参数只由「营务作参」生成、只由「参作营务」解析。

## 二、动机

构建、类型检查与运行的实现（「执行豫构」「构建包」「构建单元」「运行脚本命令」）都在可执行包「豫构」的入口模块里，选项靠十几个全局匣传递（外部目录、目标所有者、编译器选项、输出选项、显式文件入口、并发选项、编译器附加参数、安静构建、又诸组等）。可执行包不能被依赖，所以别的程序只能起豫构子进程、自己拼参数列：

| 调用方 | 现在怎么拼 |
| --- | --- |
| 诏令「营」（00036 第三轮） | `「营」于「参数」曰「列」【『运行』，『乙。脚本。豫』】`；「脚本」运行 。脚本。豫 时拼 `【『运行』，路径】` |
| 九宫 `库/九宫/营行。豫` | 「书斋察参」「书斋营参」「书斋验类参」拼 `【『构建』，包名，『-j』，『24』】` 等，经「遣使候报」起豫构 |
| 全树测试 | 「构建产物」拼 `【『文件』，源径，『--输出』，产物，『-j』，并发】`，只检查的拼 `【…，『--』，『--type-check-only』】`，原生单元运行拼 `【『运行』，源径】` |
| 其余 | 原生对比、性能验证、社区包工具、批量发布、豫言终端，以及豫构自己的仓库目标与设计编译 |

子命令名、选项名、`--` 的位置写错，要到运行时才报错；壳里的模型拼错一个『运行』就只能去读豫构的帮助。各处拼法互相抄，豫构改一个选项要全仓去找。

底下的库已经部分带类型：牌记的「访具名包」「析包图」得到「包索引」「已解析包图」；营造的「并译」仍收编译器参数的文字列。缺的是“构建、检查、运行一个东西”这一层。

## 三、目标与范围

做：

- 构建：一个包（可带包内入口段）或按所属包构建一个源文件，出程序。
- 类型检查：一个包，或一个源文件。
- 运行：把源文件连同它导入的模块编成单元运行，带程序参数。
- 公共选项：并发数、所有者、外部包目录、编译器、编译器参数（现在的 `-j`、`--所有者`、`--外部包目录`、`--编译器`、`-- …`）。

不做：

- 发现、检查、定位、交互、将作、发行、设计、仓库目标、链接、预编前导这些子命令照旧在入口里。一次构建多个程序（`--又`）第一版也留在入口里。
- 结构化的结果（诊断列、产物清单）留作后续，第一版的结果是退出码，诊断照旧印到标准错误。
- 壳在本进程里构建（见备选一）。

## 四、设计

### 4.1 包与模块

- 新库包 `库/营缮`，登记在 `库/` 父包的「包含包」里。依赖豫章、牌记、营造、译场门、译场与冶铸（以搬过去的代码实际导入为准）。依赖顺序成为：豫章 → 营造／结绳 → 译场 → 牌记 → 营缮 → 豫构。
- 两个模块：
  - 「营牒」：类型与参数互转，只导入豫章。诏令、九宫、全树测试只导入这一个模块，不会把编译器编进自己。
  - 「兴作」：执行，即从入口搬来的代码。
- 诏令因此多依赖营缮包，但只导入「营牒」。

### 4.2 类型（草拟，名字见未决二）

```
「营件」：要编的东西
  「包件」于「包」曰「文」于「入口段」曰（「列」于「文」）   包名与包内入口段（空列为包描述的入口）
  「卷件」于「文件」曰「文」                                 按所属包编一个源文件

「营设」即「组类」【「并发」乃「数」也，「所有者」乃「文」也，「外部包目录」乃「文」也，「编译器」乃「文」也，「编译器参数」乃（「列」于「文」）也】也。

「营务」：
  「营建」于「件」曰「营件」于「输出」曰「文」            构建；输出为空文时按包描述取程序名
  「验型」于「件」曰「营件」                              类型检查
  「试行」于「文件」曰「文」于「参数」曰（「列」于「文」）  运行
```

三个函数：

- `「营务作参」乃化「设」曰「营设」又化「务」曰「营务」为（「列」于「文」）者也。` 写成现行命令行：`构建 包 段… --输出 … -j …`、`文件 路径 …`、`类型检查 包`、`运行 路径 参数…`，编译器参数接在 `--` 之后。
- `「参作营务」乃化（「列」于「文」）为（「营设」合「营务」）者也。` 解析不了时抛出错因（与现在豫构报的错因相同）。
- `「办营务」乃化「设」曰「营设」又化「务」曰「营务」为「数」者也。` 在本进程办，返回退出码。第一版可以在入口处按「营设」「营务」写好现有的全局匣，再把匣逐步改成显式参数。

命令行语法不变：现有脚本、CI、AGENTS.md 与 LOCALAGENTS.md 里写的命令照旧能用。

### 4.3 调用方改法

| 调用方 | 改后 |
| --- | --- |
| 豫构命令行 | 构建、类型检查、文件、运行四个子命令改为「参作营务」后交「办营务」 |
| 九宫营行 | `「营务作参」于「设」曰「设」于「务」曰（「营建」于「件」曰（「包件」于「包」曰「包名」于「入口段」曰（「罄」以「文」））于「输出」曰『』）`，照旧经「遣使候报」起豫构 |
| 全树测试 | 「构建产物」、只检查、原生单元运行三处改为构造营务 |
| 诏令「营」 | 收一个营务：`「营」于（「试行」于「文件」曰『乙。脚本。豫』于「参数」曰「列」【】）`，经「行」的实现起会话自己的豫构；「脚本」运行 。脚本。豫 也改用营务。LOCALAGENTS.md 第八节、捉刀的篇式说明随之改写 |

## 五、兼容与迁移

- 命令行不变。豫构二、三级逐字节相同的核对照旧（CI 与本地「全部」）。只搬代码、不改产物，不换编译语义号。
- 云仓不依赖豫构的内部（可执行包本来不能被依赖），只用命令行，不受影响。
- 壳里 `「营」于「参数」曰…` 的写法一次换成新写法，不留旧写法（用户定的“直接切换，不留兼容”）。

## 六、备选方案

1. **壳在本进程里调构建库。** 壳里每一句都编成单元装入会话进程；要在本进程里构建，会话前导就得把编译器整个编成单元（单元只能链接单元，用不上豫构程序里已有的编译器代码），光译场就有四百五十三个模块、冶铸一百六十二个，而现在的前导只有几十个模块。运行还会把脚本的单元装进壳自己的进程，脚本一崩，会话也就没了。不取。壳里的类型化请求由「营牒」写成参数，交给会话自己的豫构去办。
2. **只在诏令里加带标签的壳命令**（「营行」「营察」各一条），不抽库。壳这一处有了类型，九宫、全树测试照旧手拼，豫构照旧靠全局匣。只治一处，不取。
3. **进程边界改传请求文件**（用数据子语言写的营务），不传命令行参数。对另起进程的调用方好处不大，命令行还得留给人用。不取，等结果要类型化时再议。

## 七、未决问题

1. 包名：营缮（《明史·职官志》写工部的营缮清吏司“营缮，典经营兴作之事”）、匠作、工部。本文取营缮，模块「兴作」取同一句。
2. 类型与构造器的名字：营务、营件、营设；营建、验型、试行。
3. 诏令「营」是收一个营务（一条命令），还是每类请求各一条带标签的命令（如「营行」于「文件」曰…）。
4. 结果要不要类型化：退出码之外带产物路径与诊断列。诊断列要编译器先产出结构化诊断。
5. 第二批要不要把原生对比、性能验证、社区包工具、批量发布、豫言终端与豫构自己的仓库目标也改过来。

## 八、实施步骤

1. 建营缮包（包描述、双语包说明、登记父包）；「营牒」写类型与参数互转，往返测试（各种营务写成参数再解析回来，结果相同）。
2. 把构建、类型检查、单文件构建、运行的实现搬进「兴作」，豫构入口改为「参作营务」加「办营务」。在 pit-mac 跑 `豫构 目标 类型检查 豫构测试 -j 24` 与「全部」，核对二、三级逐字节相同。
3. 九宫、全树测试与诏令「营」改用营务，同步 LOCALAGENTS.md 第八节、捉刀篇式说明与各包说明；林纳对照测试、九宫的构建执行测试与篇式测试都通过。
4. 在 pit-mac 用钩深 flash 跑一场捉刀“写一个函数并验证结果”，核对壳里的新写法。
