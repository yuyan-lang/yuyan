## 一、拟定事项

- **议一：新增中缀关键词 `且`、`或`，短路求值。** `甲 且 乙`：甲为阴得阴，不求乙；甲为阳得乙。`甲 或 乙`：甲为阳得阳，不求乙；甲为阴得乙。两边都是爻。
- **议二：解析时展开成 `若`。** `甲 且 乙` 即 `若 甲 则 乙 否则 阴`，`甲 或 乙` 即 `若 甲 则 阳 否则 乙`，阳、阴用内建节点。类型检查、代码生成、底层模式与各后端都按 `若` 处理，不加新节点。
- **议三：优先级。** `且`、`或` 比 `于`、`之`、`中`、`授以`、`附` 松，比 `与`、`；` 紧；`且` 比 `或` 紧；同级右结合。`否则`、`而`、`则` 之后的式子照旧向右延伸，把 `且`、`或` 一并收进去。
- **议四：`或有〇则〇` 成为一个操作符，取代 `〇或〇`。** `或有` 两字相连时总按一个关键词认，`或` 单字留给议一。首个分支仍写 `有〇则〇`。
- **议五：遇 `或有`，前一分支体一律先收束，`鉴` 除外。** 分支体里没写完的 `虑…而`、`递归虑`、`会…而`、`若…否则`、`中`、`；`、`且`、`或` 等都在 `或有` 前结束；内层 `鉴` 照旧把其后的 `或有` 收作自己的分支。`或有` 的分支体照旧向右延伸到下一个 `或有`、`也`、`，` 或右括号。
- **议六：「且」「或者」「非」三个函数保留不变。** 它们仍是严格求值的普通函数，可以当值传递；新写的条件用关键词。

## 三、设计

### 写法

```
「大于」于「数」于「一」且「小于」于「数」于「一零」
「等零」于「长」或「等零」于（「取余」于「总长」于「长」）
```

第二行在「长」为零时不求取余。同级右结合，`甲 且 乙 且 丙` 展开为 `若 甲 则（若 乙 则 丙 否则 阴）否则 阴`。

议五之后，下面的写法不必再给分支体加括号：

```
鉴「可选」而
　有（「可有」于「数」）则
　　虑「乙」者「加」于「数」于「一」而
　　「乙」
　或有「可无」则「零」
```

### 词法

`或有` 两字相连时按一个关键词认，不拆成 `或`、`有`。`有` 不会开头一个爻式，所以这样认不会丢掉合法写法，也不会在每个 `或有` 处多出一条解析路径。

### 规约关系

左操作符在前、右操作符在后：

| 左 | 右 | 决定 |
| --- | --- | --- |
| `〇于〇`、`〇之〇`、`〇中〇`、`〇授以〇`、`〇附〇` | `〇且〇`、`〇或〇` | 左规约 |
| `〇且〇`、`〇或〇` | `〇于〇`、`〇之〇`、`〇中〇`、`〇授以〇`、`〇附〇` | 右规约 |
| `〇且〇` | `〇且〇` | 右规约 |
| `〇或〇` | `〇或〇` | 右规约 |
| `〇且〇` | `〇或〇` | 左规约 |
| `〇或〇` | `〇且〇` | 右规约 |
| `〇且〇`、`〇或〇` | `〇与〇`、`〇；〇` | 左规约 |
| `〇与〇`、`〇；〇` | `〇且〇`、`〇或〇` | 右规约 |
| `鉴〇而〇` | `〇或有〇则〇` | 右规约 |
| `*` | `〇或有〇则〇` | 左规约 |
| `〇或有〇则〇` | `〇也〇` | 左规约 |
| `〇或有〇则〇` | `*` | 右规约 |

后四条放在 `〇，〇` 与 `〇【〇】` 各条之后，并按表中次序排列。旧 `〇或〇` 的七条关系里，`有〇则〇`、`若〇则〇否则〇` 两条删去（改由后备规则右规约，分支体与否则支收下或式），`〇与〇` 一条改为右规约，其余四条（`于`、`授以`、`附` 左规约，`或` 自身右规约）照用。

## 四、兼容与迁移

- 旧代码照常解析，含义不变。裸 `或` 只出现在 `或有` 里（相连 28347 处）；只有一处把 `或`、`有` 分行写（`应用/开发工具/基础库验证/入口。豫` 第 213 行），改成相连。裸 `且` 没有用过。
- 议五只把现在报错的写法变成合法。现在能解析的代码里，`或` 的左边总是一个已收束的分支，挂在最内层的 `鉴` 上；议五给出同样的结果。实施时比对全仓新旧解析结果来核实。
- 嵌套 `鉴` 照旧：内层 `鉴` 收下其后所有 `或有`。末分支里直接嵌套 `鉴` 的写法靠这条；内层 `鉴` 不在末分支时仍须加括号。
- 工具链依赖闭包（标准库、编译器核心、包配置、豫构、裸机后端等）里的源码，要等 CI 发布含本改动的原生工具链包、`main.yml` 换钉之后才能用新写法；其余库与应用合入后就能用。
- 现有「且」「或者」调用不批量改写。写着“且不短路”注释的地方和以后改到的代码，顺手换成关键词。

## 五、备选方案

- **编译器把「且」「或者」调用自动改成短路：** 不取。约九千七百处现有调用的求值次序会随之改变，也违背《执行与编译》里“普通函数调用不能自动得到特殊条件求值规则”的规定。
- **按名传参（惰性形参）：** 不取。它更通用，但要动类型系统，每次调用还要分配闭包。
- **布尔或另取字（`或者`、`抑`），分支保持 `〇或〇`：** 不取。分支解析的坑会留着。

## 六、未决问题
