用户的要求（2026-10-21，原话为英文，此处译述）：现在有没有右键菜单，比如右键复制、粘贴文字，右键把窗口移进或弹出到一个工作区？能右键弹出上下文菜单仍然很要紧。设计要照旧经系统命令走，便于 AI 操作。调查该加什么，标准是一个成熟系统该有的全部菜单，连同支撑它们的功能；派并行的钩深实现。

## 一、拟定事项

- **议一：锦囊。** 右键菜单叫“锦囊”：李商隐《李贺小传》记李贺“背一古破锦囊，遇有所得，即书投囊中”，后世小说里诸葛亮授“锦囊妙计”，到了某个情形拆开照计行事；右键菜单正是“到了这个对象上，能做的几件事”。锦囊里的一项叫“策”（计策），子菜单叫“策囊”，分隔线叫“策隔”。剪贴板已叫“夹袋”（包「豫寓夹袋」），同是袋囊一族。
- **议二：菜单即命令。** 每一项都带等价的壳命令文字（「令」），图形界面选中一项时直接调用同一个库函数（AGENTS.md「图形程序」），悬停时把这句命令显示出来；壳命令「囊目」把桌面上各窗口的锦囊连同命令一并印出。人看了学会命令，AI 不点菜单也能做同样的事。只改本窗口视图的项（复制选区、全选、粘贴进编辑框）不必有命令，「令」写空串。
- **议三：框架代管弹出。** 应用只在元素上挂「锦囊」，给出各项；副击（右键单击）时由自绘后端在指针处弹出、处理指针与键盘、选中后把那一项的消息交给应用的更新。应用不必自己管菜单的状态与绘制。文本框与多行文本框不挂锦囊也有内建的剪切、复制、粘贴、删除、全选。
- **议四：补齐配套功能。** 菜单里的每一项都要先有能用的功能与命令：窗口命令「关窗」「拆窗」「全窗」「移窗」「凝窗」与查询「囊目」；剪贴命令「纳袋」「探袋」与豫言系统里跨任务的剪贴板；终端的选区、复制、粘贴与命令「拂屏」（清屏）；输入合成命令「右击」；显示接口的功能键与菜单键键名。

## 二、动机

1. 现在全系统没有任何弹出菜单。显示接口早就交付按钮编号（零主键、一辅助键、二次要键），林檎、浏览器、裸机与屏块也都送得出右键，触控板两指按下也折成右键；但控件库只处理主键，门面的「指针时」不带按钮，九宫与各程序都没有用到右键。
2. 用户要的几件事都缺：文字右键复制粘贴；终端连选区都没有；窗口移进或弹出到宫（00047）只有标签栏的小钮与快捷键。
3. 豫言系统里每个窗口是独立任务（00015），而林檎以外的平台剪贴板只在进程内：终端里复制的文字到编辑器里贴不出来。菜单上的“复制”“粘贴”要先有跨任务的剪贴板。
4. AGENTS.md 要求图形界面的每个可操作项都有等价的壳命令：关窗、拆分、全屏、移标签、聚焦现在只有按钮与快捷键，没有命令。

## 四、设计

### 4.1 菜单模型（议一、二；包「门面」模块「策府」，已合入）

```
「策」立化「类」为「类」者也。
　「良策」立（凡「消」而化「名」曰「文」又化「键」曰「文」又化「令」曰「文」又化「可」曰「爻」又化「信」曰「消」为「策」于「消」）也。
　「勾策」立（凡「消」而化「名」曰「文」又化「键」曰「文」又化「令」曰「文」又化「可」曰「爻」又化「勾」曰「爻」又化「信」曰「消」为「策」于「消」）也。
　「策囊」立（凡「消」而化「名」曰「文」又化「可」曰「爻」又化「策们」曰（「列」于（「策」于「消」））为「策」于「消」）也。
　「策隔」立（凡「消」而「策」于「消」）也。

「策述」乃凡「消」而化（「策」于「消」）为「文」者也。
「诸策述」乃凡「消」而化「缩进」曰「文」又化「策们」曰（「列」于（「策」于「消」））为「文」者也。
「择策」乃凡「消」而化「名路」曰（「列」于「文」）又化「策们」曰（「列」于（「策」于「消」））为「或可有」于「消」者也。
```

- 「名」是显示名；「键」是快捷键提示（如 `交替+W`，没有写空串）；「令」是等价壳命令，写成在壳里能直接执行的一句，号、宫、路径等照当时的对象填好（如 `「关窗」于「号」曰「三」`），没有写空串；「可」为阴时灰显、点了不交消息；「信」是选中时交给应用更新的消息。
- 「策述」把一项写成一行（名、键、令以全角空格隔开，勾策前加“✓ ”，策囊后加“ ▸”，不可用的后加“（不可用）”，策隔写“──”）；「诸策述」把整个锦囊写成多行（策囊的子项缩进两格）；「择策」按一串显示名模拟点选。测试一律用这两个函数核对菜单与点选结果。
- 元素属性（模块「元素」）：

```
「锦囊」立（凡「消」而化（化「有」为（「列」于（「策」于「消」）））为「属」于「消」）也。
「囊钮」立（凡「消」而化（化「有」为（「列」于（「策」于「消」）））为「属」于「消」）也。
```

  「锦囊」：副击这个元素（或它里面没有自己锦囊的元素）时弹出。「囊钮」：主键单击这个元素（焦点在它上面时按回车、空格、方向下）时，在元素下方弹出（下拉菜单）。用函数是为了只在弹出时才造各项，长列表（文件行）每行挂一个也不费事。「映射信」照样映射锦囊里各项的消息，所以子视图（书斋、终端、设置）里挂的锦囊经外壳映射后照常可用。

### 4.2 副击与弹出（议三；器物、门面自绘）

- **副击**：指针按下按钮二（右键；触控板两指按下）；林檎上控制加主键单击；键盘的“菜单”键或上档加功能十（对焦点元素，位置取它的左下角）。器物在原样热区（外部程序的画面、终端光标）以外的地方把副击交成新的交互事件「副击」（标识、横、纵），原样热区照旧把各按钮原样交给程序，程序自己的锦囊由它自己的自绘后端弹出。
- **找锦囊**：自绘后端从副击处的元素往上找第一个带「锦囊」的元素，调它的函数取各项；一路都没有、副击处是文本框或多行文本框时弹出内建编辑菜单；都不是就什么也不做。副击文本框时先让它取得焦点（不移光标、不清选区）。
- **弹出层**：画在应用视图之上，贴着指针（「囊钮」贴着元素下沿）；碰到显示面右边、下边时向左、向上翻；比显示面高时可滚动。纸色底、细边框，每项一行：左边勾或空、名，右边快捷键提示（灰）与策囊的“▸”；策隔是一条细线；不可用的灰字；指针下的一项与键盘选中的一项高亮；悬停在一项上时把它的「令」作为悬停提示显示。一次只开一个锦囊（含它展开的子囊）。
- **操作**：主键单击可用的良策、勾策：关掉锦囊，把「信」交给应用的更新（与应用自己的消息走同一条路）。指针停在策囊上或按方向右，展开子囊；方向左收回。方向上下移动选中（跳过策隔与不可用项），回车、空格选中，退出键关掉。在锦囊外按下指针关掉锦囊（副击时在新位置再弹出一个）；显示面失焦或尺寸变化时关掉。锦囊开着时键盘与指针都不交给应用。
- **内建编辑菜单**：剪切（控制加 X，林檎为命令加 X）、复制、粘贴、删除、全选；没有选区时剪切、复制、删除不可用，禁用的文本框只有复制、全选；动作与现有的剪贴键同一套函数，「令」为空串。
- 单面会话与多面会话（00047）都支持；多面时锦囊画在副击所在的那块显示面上。

### 4.3 壳命令（议二、四）

| 命令 | 作用 | 路 |
| --- | --- | --- |
| `「关窗」于「号」曰「三」` | 关掉窗口三（桌面程序先送“请关闭”，与标签上的 × 相同）；省「号」是发起者自己的窗口，没有发起窗口时取今宫的焦点窗口（同「徙窗」） | 乙 |
| `「拆窗」于「号」曰「三」于「向」曰『横』` | 拆分窗口三所在的组，新组里开一个同种窗口；「向」为『横』左右拆、『纵』上下拆，可省，缺省『横』 | 乙 |
| `「全窗」于「号」曰「三」` | 窗口三单格全屏，再执行一次还原 | 乙 |
| `「移窗」于「号」曰「三」于「向」曰『右』` | 把窗口三移到它所在组往『左』『右』『上』『下』的相邻组，那边没有组就拆出一组（同标签栏“移到右边”钮） | 乙 |
| `「凝窗」于「号」曰「三」` | 让窗口三取得焦点；它在别的宫时先入那座宫（有自己宿主窗口的宫只设焦点） | 乙 |
| `「辟窗」于「种类」曰『终端』于「宫」曰「三」` | 现有命令；「宫」给还没有的宫号时新开那座宫再开窗口（“在新宫打开”） | 乙 |
| `「囊目」于「号」曰「三」` | 查询：印窗口三的窗口菜单，每项一行：名、快捷键、等价命令；「号」为零或省了印全部窗口与桌面菜单 | 乙 |
| `「纳袋」于『文字』` | 把文字放进剪贴板（同 pbcopy） | 己 |
| `「探袋」` | 印出剪贴板里的文字（同 pbpaste） | 己 |
| `「拂屏」` | 清屏（同 clear）：印出 `ESC[H ESC[2J ESC[3J`，桌面终端收到 `ESC[2J` 即清屏，宿主上的真终端也照样清 | 戊 |
| `「右击」于「横」曰「三零零」于「纵」曰「二零零」` | 移指过去按一下右键（同 `xdotool click 3`）；00047 给「点击」加了可省的「面」，这里照加 | 庚 |

- 命令照 AGENTS.md 加在库「诏令」，做法登记在部居（窗口命令与「囊目」在「图形」一部，「右击」在「屏键」一部，剪贴命令在新的「剪贴」一部，「拂屏」放进「日用」），令籍补候选，`LOCALAGENTS.md` 第八节对照表补行，`应用/豫构/林纳对照。测试。豫` 补核对。
- 窗口命令照「徙窗」的路走：壳索（几席）把一条窗请写进 `/系统/请求打开窗口。数据。豫`，九宫每轮取走、在「办窗请」里按种类分派。新种类与参文：『关窗』【号】、『拆窗』【号，向】、『全窗』【号】、『移窗』【号，向】、『凝窗』【号】（号写成十进制文字，零或空表示省了）。九宫里各自调用现成的「关格」「剖」「切单格全屏」「按钮移标签」「凝神格」「临宫」。不认得的种类照旧不理。
- 桌面程序（独立格）与九宫外的程序要触发窗口动作时（如终端菜单的“拆分”“关闭”），直接用壳索的「添窗请」写一条窗请，「发窗」填自己的窗号（环境变量 `豫言窗号`），不拼成句子交给壳。

### 4.4 囊目快照（议二）

九宫在「同步窗列」写 `/系统/桌面窗列。数据。豫` 时，再写一个顶层绑定「窗囊」，值是一段文字：每个窗口一段，首行 `窗<号>　<种类>　<标题>`，下面是它的窗口菜单（「诸策述」于「缩进」曰『　』），最后一段首行 `桌面`，下面是桌面菜单。「囊目」读它：给了号只印那一段，没给印全部；桌面没在运行照「窗列」报错。窗口菜单与桌面菜单由同一组函数生成（模块「宫策」），所以快照与弹出的锦囊总是一致。

### 4.5 剪贴板（议四）

- 林檎（原生、行在）用系统剪贴板，浏览器用 `navigator.clipboard`，照旧。
- 豫言系统（裸机）：剪贴板改由内核保管一份，各任务读写的都是它（「写剪贴板文字」「读剪贴板文字」两个原语改调内核服务），终端里复制的文字到别的窗口里贴得出来。容量至少 256 KiB，超过时截断。
- 林纳（原生、无头行在）：剪贴板写进文件 `$HOME/.豫言/夹袋。文本`（行在里写进实例目录），同一用户的各进程共用；读写失败时退回进程内。
- 剪贴命令「纳袋」「探袋」在各处都调同一个剪贴板接口；宿主上的壳读写的就是宿主的剪贴板。

### 4.6 键名（议四；显示接口规范）

显示接口的语义键名加 `功能一` 至 `功能十二`（F1–F12）与 `菜单`（ContextMenu、Windows 的应用键）。只加键名，接口签名不变，不必重生成接口清单。林檎、浏览器、裸机与屏块的输入照此交付；没有菜单键的键盘用上档加功能十。「击键」认这些键名。

## 六、备选方案

- **应用自己管菜单状态**（锦囊开着与否、选中第几项放进应用模型）：每个应用都要写一遍，九宫、书斋、终端各写一份，不取。
- **每个菜单开成独立的宿主窗口**（像原生的 NSMenu）：裸机与屏块没有这种东西，各后端行为就不一致；先画在本显示面里。
- **菜单项只带消息、不带命令文字**：AI 与用户就看不出菜单项对应哪句命令，「囊目」也无从列出；所以每项带「令」。
- **右键菜单叫“菜单”“上下文菜单”**：AGENTS.md 要求新名取古雅之名；锦囊与夹袋同属袋囊，又有“到了情形拆开照计行事”之义，切合上下文菜单。
