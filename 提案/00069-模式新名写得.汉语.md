## 一、拟定事项

- 议一：鉴的模式里，`得「名」` 是新绑定。它匹配该位置上的任何值，把值绑到这个名字上，只在本分支的分支体里可见。
- 议二：模式里的裸名一律是引用，照表达式的规矩查名字。查到的须是构造器（含构造器的值别名）；底层代码里还可以是整数常量。查不到报“未定义的名字”，查到的不是构造器也报错。数、文、爻字面量照旧。
- 议三：`得「名」` 在本分支的分支体里遮住外层的同名者，同名的构造器也遮住。同一个模式里的裸名仍照议二查，不受它影响。
- 议四：模式的意思只由它自己的写法定，与本文件导入了什么、别处新加了什么无关。导入的查名规则不变：本文件的定义遮蔽导入，后打开的模块遮蔽先打开的，与 OCaml 的 open 同义。
- 议五：全仓的旧写法由编译器自动改写，分三步合入：先两种写法都收，等 CI 的连续版工具链带上；再全仓改写；最后把“裸名查不到就当绑定”改成报错。

## 二、动机

### 现状

规范「类型与模块」类五与名一：鉴的模式里，裸名与看得见的构造器（含构造器的值别名）同名时作构造器模式，只匹配这个构造器；其余裸名一律作新的局部绑定，匹配一切，并遮住外层同名的函数、类型与常量（议题 212、222、434）。

同一个写法「X」，既可能引用已有的构造器，也可能引出新名字，由“本文件看不看得见同名的构造器”来定。导入一变，模式的意思就跟着变。

### 要防的错

甲类：本想写构造器，漏了导入，变成兜住一切的变量。

- #1047：`起者。豫` 写 `或有「未获授权」`、`或有「资源暂不可用」`、`或有「其他」`，没有导入定义这些构造器的「错误」模块。第一支兜住所有失败，一律打印『未获授权』。
- #905（底层代码）：卷错（卷操作的错误码）常量没导入，卷错 7（输入输出）映成“成功”，写盘失败也回“已建立”。
- #939：错在嵌套位置。`（「内建节点」于「内建类型元类型」）` 漏导入本常量数据（内建常量表），所有内建常量都进这一支，构造器归属检查被整个跳过。编译器自身的类型检查、自编豫构都过了，验收命令意外返回零才发现。

乙类：本想绑定新名字，名字恰是看得见的构造器，变成构造器模式。

- #932：豫章（标准库）的默认导入加了构造器「成」「误」，全仓 265 处拿它们当绑定名的写法改了意思。这次「误」是一元构造器，所以报了错；零元构造器就会静默改义。
- #950：拿「声明」当绑定名，它恰是导入的类型名。报错落在后面的分支上，没有指出撞名。
- #985：绑定名「数物」恰是可见的构造器，覆盖分析报出缺例与不可达，同样没有指出原因。

提案 00063（鉴必穷尽）实施后，甲类在顶层位置多半会报“未使用的匹配分支”，可报错指在后面那一支，不指出漏了导入；顺着报错改，容易删掉后面那一支，反把错固定下来。甲类在嵌套位置（#939）仍然静默：变量只兜住那一个位置，后面的兜底分支照样走得到。

### 为什么改写法

凡是靠查名字来定“这是绑定还是引用”的规则，不论查看得见的构造器，还是查该类型的全部构造器，都会让模式的意思或能否编过，取决于别处新加了什么。初稿“裸名要作绑定、而该位置类型的构造器里有同名者，即报错”（与 Rust 的 E0170 同一思路）议定时否掉了：某个类型新加一个构造器，恰与别处已有的绑定同名，以前编得过的代码就编不过了。

OCaml、Haskell 没有这个毛病，因为它们用大小写区分构造器与变量。汉字没有大小写，「得」起的就是这个作用：新名字由写法标出，与表达式里 `得「x」而…`（函数收参数）、`令「x」为…而…` 引出新名字是同一个规矩。

### 数据

2026-10-28 在 yybs 上按行粗量（准数由第五节第一步的编译器开关给出）：

- 源文件 8230 个，鉴的分支约七万四千个。
- 裸名绑定约七万处，要加「得」。最常见的绑定名是「其他」（约四千六百处），其次是「余」「尾」「首」。
- 构造器头约四万处，裸名构造器引用约两万九千处，其中「罄」（空列）与「可无」（无值）各约九千八百处。这些都不用改。

## 三、目标与范围

做：

- 鉴的模式里的 `得「名」`；
- 裸名一律作引用；
- 相应的报错；
- 全仓自动改写；
- 规范与工具同步。

普通、底层与着色源文件，以及壳里输入的句子，都照同一规则。

不做：

- 导入的查名规则。2026-10-28 议定不改，理由是仓里没有由“后打开的覆盖先打开的”造成的缺陷。
- 另设兜底写法：兜底照样写 `或有得「其他」则 …`。
- 给模式加类型标注、守卫等新能力。
- 改动令、复令与匿名函数参数的写法：它们本来就只收名字，名字由关键词引出。

## 四、设计

### 4.1 语法

文法加一条：

```text
式 = … | "得" 名 ;
```

`得「名」` 与 `卦曰「名」` 一样，是前缀关键词接一个名称，自成一个原子。它只在鉴的模式里成立，写在别处报错：“「得」后面接名字、不接「而」时，只能写在鉴的模式里”。

它与匿名函数 `"得" 参名 { "又" "得" 参名 } "而" 式` 不会混：匿名函数的参名后面要接「曰」「属」「阙则」「又」或「而」；模式里的 `得「名」` 后面接的是「于」「与」「则」「也」、逗号或右括号，两组不重，解析时只有一种合法读法。

```
「计长」乃化（「列」于「数」）为「数」者也。
「计长」者得「项们」而
　鉴「项们」而
　　或有「罄」则「零」
　　或有（「缀」于得「首项」于得「后项」）则（「一」加（「计长」于「后项」））
也。
```

`或有得「其他」则 …` 读作“或有得其他者，则……”。

漏了导入时，报错就落在出错的那个名字上，嵌套位置也一样：

```
「说寓误」者得「错」而
　鉴「错」而
　　或有「未获授权」则『未获授权』
　　或有「资源暂不可用」则『暂不可用』
　　或有得「其他」则『其他错误』
也。
```

报错：`起者。豫:3:5：说寓误：未定义的名字「未获授权」。被鉴值的类型「寓误」有同名构造器，定义在 豫寓榫卯/基础/错误。接口。豫，本文件没有导入它；要绑定新名字，写 得「未获授权」`。「寓误」是豫言操作系统接口（豫寓榫卯）的错误类型。

```
或有（「式节点」于（「内建节点」于「内建类型元类型」）于得「忽略子」）则「阳」
```

没导入本常量数据时，报“未定义的名字「内建类型元类型」”（#939）。

```
或有（「图像解码失败」于得「误」）则 …
```

豫章以后再加名叫「误」的构造器，这一支也不变（#932）。

### 4.2 静态语义

1. **名称解析**：分支模式里的 `得「名」` 记作模式变量，带源码范围，进入本分支分支体的作用域。裸名照表达式查。
2. **类型检查**：设该位置期望的类型为 T。
   - `得「名」`：引入类型 T 的局部绑定，遮蔽外层。沿用现行的模式遮蔽做法，议题 434 的改名规则照旧。
   - 裸名查到构造器或构造器的值别名：构造器模式，照现行。
   - 底层文件里，裸名查到整数常量：常量模式，照现行。
   - 裸名查到别的定义（函数、类型、高级代码里的常量）：报“「名」不是构造器，模式里不能引用它；要绑定新名字，写 得「名」”。类型名出现在模式位置的现行定稿诊断（议题 #419）并入这一条。
   - 裸名查不到：报“未定义的名字「名」”。T 的构造器全集里有同名构造器时，附一句它定义在哪个模块、本文件没有导入。这句只是提示，不参与判定。
   - 应用模式的头照旧须是构造器。
3. **重复与数字名**：同一个模式里两次 `得` 同一个名字，报“模式里重复绑定「名」”。数字名照「词法与语法」的规矩不能作 `得` 的名字。
4. **报错格式**：一律照提案 00059 的统一格式，带文件、行列与所在定义。
5. **与提案 00063**：覆盖分析把 `得「名」` 当通配，照旧。00063 议五“兜底分支用现有的裸名模式写”改为写 `或有得「其他」则 …`。
6. **与提案 00061**：类型块给出的构造器全集照旧供覆盖分析与报错提示用，不参与“这是绑定还是引用”的判定。
7. **与提案 00060**：签名没列出的构造器在模块外看不见，模式里引用它，与在表达式里一样报未定义的名字。

### 4.3 动态语义

不变。`得「名」` 与原来作绑定的裸名编出同样的代码。

## 五、兼容与迁移

分三步，以过 CI 的自举：CI 自举的一级是连续版里的旧工具链，工具链源码要先等它认得新写法，才能改用新写法（AGENTS.md「包与接口」）。

1. **两种写法都收**：解析器认 `得「名」`；类型检查照 4.2 处理 `得「名」`，裸名查不到仍当绑定。编译器加一个开关，逐处印出“作绑定的裸名”的文件与行列。合入后，等 CI 的连续版工具链带上这一步。
2. **全仓改写**：用上面的开关列出全部旧写法，由豫言写的改写工具在这些位置前加「得」，再排版。语言仓与云仓（yuyan-cloud）各跑一遍。改写只加「得」，不动别的，改写前后的产物相同。
3. **改成报错**：裸名查不到报未定义的名字，查到非构造器报错，即 4.2 的完整规则。

LOCALAGENTS.md 里“模式变量须避开外层已绑定变量”“模式变量还须避开已导入的构造器名”“模式变量不能与类型同名”等几条坑，随第三步改写或删去。

## 六、备选方案（议定时否掉的）

- **与该位置类型的构造器同名即报错**（仿 Rust E0170，不改写法）：某个类型新加构造器，恰与别处已有的绑定同名，以前编得过的代码就编不过。
- **裸名一律是绑定，构造器引用另加记号**（Python match 的做法，常量要写带点的名字）：要标的地方少，约两万九千处，大半是「罄」「可无」；但没有合适的记号。带模块前缀写成 `「豫章」之「罄」` 太啰嗦，借别的现成关键词来标会给它添新义。
- **维持现状，只改报错措辞**：模式的意思仍随导入而变。
- **导入撞名报歧义，另加点名导入**：仓里没有由“后打开的覆盖先打开的”造成的缺陷；分厘（浮点运算模块）等 48 个文件反靠它有意覆盖整数的「加」「减」。撤回，导入规则不变。
