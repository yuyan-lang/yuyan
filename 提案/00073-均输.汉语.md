本文只写现代汉语（AGENTS.md）。

“均输”取《史记·平准书》：汉武帝时桑弘羊“置均输以通货物”，让各郡有余的物资调往不足之处。这里拿它比喻工作窃取（work stealing）：哪个处理器核闲了，就从忙的核那里把任务挪过来。

## 一、拟定事项

1. **开任务要和函数调用同价**。终局里，开一个任务的开销与一次函数调用同一个量级：几纳秒到几十纳秒，几百字节。起一个程序的开销也降到微秒级、几 KB。
2. **建在现有的「差遣」上，不改语言**。程序看得到的只有「差遣」已有的「遣」「待」「让」「行役」，以及新增的几个内建函数（原子匣、锁、核数等）。改动都在执行器、冶铸、回收器和虚机里，对写程序的人透明。
3. **与操作系统合一**。终局里，「差遣」的调度器就是操作系统（行在虚机、裸机内核）的调度器：每个处理器核一条任务队列，空闲的核去偷忙核的任务；输入输出的就绪由操作系统直接唤醒任务。
4. **不做隔离**。眼下只跑我们自己的代码，所有任务共用一个地址空间、一个堆。隔离留给证明层（00070、00016）以后补上。
5. **分四期走，第一期是单个虚机任务里的多核差遣**：每核一个新生区，堆由各核共用，回收改成全核停世界后并行回收，「差遣」改成每核一条双端队列、互相偷活。
6. **虚机必须十分可靠**。本提案改的是最核心的基础设施，实施期间可靠性压倒进度：每一期都有硬性的核对与验收（第七节），不合格不合入，上一期不验收不开下一期。

## 二、动机

### 2.1 现在有两个世界

| | 虚机任务（「列出役」里的役） | 「差遣」任务 |
| --- | --- | --- |
| 是什么 | 一台独立的小机器：自己的线性内存、回收堆、运行时 | 一个闭包，进同一任务里的运行队列 |
| 开一个要多少 | 空闲豫构任务常驻约 170 兆（「析役存」）；装入、初始化要毫秒到一秒 | 一次闭包分配加入队，几十纳秒 |
| 跑在几个核上 | 每个任务同一时刻只在一个核上 | 一个虚机任务里的所有差遣任务挤在一个核上 |
| 操作系统看得见吗 | 看得见，有账（析役存、观役） | 看不见，账都算在所在的虚机任务头上 |
| 隔离 | 有：各自的地址空间 | 无 |

虚机任务重，是因为要隔离：每个任务一份线性内存、一套运行时、一份固定预留。可我们眼下只跑自己的代码，这份隔离的钱白花了。差遣任务轻，却只能用一个核，操作系统也看不见。

### 2.2 目标

把两个世界合成一个：任务像差遣任务一样轻，又像虚机任务一样能用满所有核、操作系统看得见、有账。

### 2.3 为什么现在做

- 「析役存」已经把每个任务的内存按组成拆开了，空闲任务里约 155 兆是固定开销，现在看得清楚。
- 映像共用（#1617）正在做，它是第二期“起程序只要几 KB”的前提。
- 虚机已经有多处理器线程、抢占轮询、异步抢占（00067 第三段），多核调度的底子在。

## 三、前例

| 系统 | 做法 | 取舍 |
| --- | --- | --- |
| Cilk（MIT） | 每核双端队列、工作窃取；“先干活”原则（work-first）：开任务当场执行，只在被偷时才付建任务的钱 | 第四期采用“懒开”；第一期先用偷闭包（child stealing），不需要续体 |
| Chase–Lev 双端队列 | 本核在队尾无锁进出，偷活的从队首用一次比较交换取走 | 第一期直接采用 |
| OCaml 5 多核 | 每个“域”（核）一个次堆（新生区），主堆共用；次回收全核停世界、各核并行；主回收并发标记 | 和本提案的堆结构最接近，第一期照它的骨架 |
| Go | G-M-P 调度，每个 P 一份分配缓存（mcache），协程栈可增长 | 调度与分配缓存的分工照它；可增长栈留给第四期 |
| Java ForkJoinPool、Rust Rayon | 工作窃取线程池，「待」时帮工（help-first） | 「待」的帮工语义照它 |
| Erlang BEAM | 每进程一个小堆，消息拷贝 | 不采用：开任务要分配一个堆，消息要拷贝，做不到“和调用同价” |
| Singularity（微软研究院） | 经验证的代码共用一个地址空间，软件隔离 | 终局形态与它相同；隔离由证明层后补 |

## 四、终局形态

- **一个地址空间、一个堆**：所有程序的代码与只读数据（代码、常量、全局映像、栈图、侧表）只装一份；可变的东西才按程序实例各存一份。
- **程序实例**：一个“实例块”（这个实例的可变全局与状态格），加一个根任务。起一个程序就是建实例块、遣根任务，几 KB、微秒级。
- **任务**：一个闭包，加一个几十字节的描述（状态、结果、等待者、所属实例、账）。
- **处理器核**：每核一个新生区、一条双端队列、一个状态块。
- **调度**：「遣」进本核队尾；本核从队尾取（后进先出，缓存热）；闲核从别核队首偷（先进先出，偷大块）。
- **输入输出**：由操作系统（虚机主线程或内核）统一等就绪，就绪的任务进全局注入队列，由闲核取走。
- **账**：每核新生区里的分配记到当前任务、当前实例名下；回收后按实例汇总存活量。「列出役」「观役」「析役存」都按实例与任务列出。

## 五、分期

### 第一期：单个虚机任务里的多核差遣

只在一个虚机任务（一个程序实例）里面做，其余虚机任务不受影响。

**1. 每核状态块**

现在执行器的状态格（分配游标、游限、游起、活字节、分配计等）放在任务线性内存低址的固定偏移上，冶铸生成的代码（含预编二的内联分配）用基址寄存器加常数偏移去读写：臂六十四是 x25，兼容六十四是 r10。

改成：把“每核一份”的状态格挪进每核状态块，冶铸专门留一个寄存器指着本核的状态块；“全任务一份”的照旧放在线性内存里。哪些格属于每核，第一步列清单，按格逐个改。

**2. 每核新生区，堆共用**

- 每个核在共用的堆里有自己的新生区，内联分配只碰本核的游标、游限，不加锁。
- 晋升进老区：每核从老区领一段，在段里分配；段用完再领，领段时才加锁。
- 卡表写屏障照旧，记哪张卡被写过，本来就幂等，多核同时写也不出错。

**3. 回收：全核停世界，再各核并行**

- 每个函数入口与循环头都已有抢占轮询，直接拿它当安全点：要回收时置位，各核走到轮询处就停下汇合。
- 新生回收：每核扫自己的栈（有栈图的帧精确，其余保守）和自己的新生区，加上卡表记下的老区到新生区的指针，各核并行。
- 老区回收：沿用现有标记清扫与后台清扫线程；并行标记、并发标记留到后面。
- 停世界的次数与时长进账，在「观役」里看得到。

**4. 调度：每核一条 Chase–Lev 双端队列**

- 「遣」：分配任务描述与闭包，压进本核队尾。
- 本核执行：从队尾弹出。
- 偷活：本核队空就随机挑一个核，从队首偷一个。
- 「待」：目标还没完成就帮工：先跑本核队里的，再去偷。实在没活，就把自己挂到目标的等待者上，让本核休眠，由虚机的宿主等待唤醒。
- 「让」：语义不变，仍是在当前栈上嵌套跑一个别的任务。真正的挂起要靠协程，留给第四期。
- 「行役」不变。

**5. 输入输出交给虚机**

现在「差遣」自己维护一组门候，每十六次调度用 poll 查一次。改成把关心的描述符和事件登记给虚机，由虚机统一等就绪，再把就绪的任务放进全局注入队列；不再每个核各自 poll。

**6. 共享可变状态**

多核以后，同一实例里的任务真正并行，共用的「匣」可能被同时读写。

- 新增内建函数：原子匣（取、存、比较交换、加）和锁。
- 审一遍现有库里被多个任务共用的全局匣，改成原子匣或加锁。
- 迁移期间按实例开关：标了“多核差遣”的实例才多核跑，没标的照旧单核，语义和现在一样。先打开编译器（译场、豫构）这类审过的程序，逐个放开。

**7. 可观测（先于实现）**

- 「观役」加每核一行：队长、在跑的任务、偷来几次、被偷几次、新生区用量、停世界次数与总时长。
- 「析役存」加每核新生区一栏。
- 实例内的差遣任务数、就绪数、等待数，「列出役」里看得到。

**8. 第一期的验收数字**

- 开一个差遣任务（闭包、入队、执行、完成）在本核上不超过一百纳秒。
- 并行斐波那契 fib(30)：十八核比单核快十二倍以上。
- 编译器内部改用多核差遣后，一次全量构建的总耗时下降（以析役存、观役与构建日志为准）。
- 第七节的核对全部通过。

### 第二期：虚机任务变成程序实例

- 线性内存不再按任务一份。冶铸的基址寄存器改为指向实例块，实例块只放可变全局与“全实例一份”的状态格。
- 起程序：映射共用映像（#1617），建实例块，遣根任务。
- 行在、虚机门、将作、监工、回收役这些常驻服务，全都变成同一个堆里的实例，每个只占几 KB 到几百 KB。
- 账按实例记。「列出役」列实例和任务，「析役存」按实例拆。
- 不隔离：一个实例写坏内存会波及别的实例。在证明层到位之前，用核对模式（第七节）和差分测试兜底。

### 第三期：与操作系统合一

- 虚机启动器的主循环与处理器线程直接就是「差遣」的工作核：每个处理器线程从自己的双端队列取任务，不再有“虚机任务”这一层调度。
- 服务（系统调用）改成发起即返回，完成后唤醒等它的任务。
- 裸机内核用同一套调度代码（行在核里共用），内核的任务也是实例与差遣任务。
- 同一宿主上的壳、将作、编译工作件，全都是同一个堆里的任务。

### 第四期：后补

- 协程：帧段与续体，真正的挂起与恢复；「让」改为真挂起；抢占改成切栈。
- 懒开（Cilk 的先干活原则）：开任务当场当调用执行，没被偷就只多一两条指令，做到与调用同价。
- 迁移：任务带着帧和对象搬到别的机器。
- 隔离：由证明层（00070、00016）补上。

## 六、开销目标

| 动作 | 现在 | 第一期 | 第二、三期 | 第四期 |
| --- | --- | --- | --- | --- |
| 函数调用 | 1–2 纳秒 | 不变 | 不变 | 不变 |
| 开差遣任务 | 几十纳秒，只用一个核 | 不超过一百纳秒，可被别核偷 | 同第一期 | 调用加几纳秒（懒开，没被偷时） |
| 起一个程序 | 毫秒到一秒，约 170 兆 | 不变 | 微秒级，几 KB 到几百 KB | 同第二期 |
| 一个任务的内存 | 虚机任务约 170 兆；差遣任务几百字节 | 不变 | 几百字节 | 同第二期 |

## 七、可靠性：虚机必须十分可靠

本提案改的是虚机、执行器和回收器，任何一处出错都会让全系统停摆，所以实施期间照下面办：

1. **核对模式**：执行器加一个开关，打开后：
   - 每次回收后走一遍全堆，核对对象头、每个指针都落在活对象上、卡表与实际写入一致；
   - 每次停世界核对各核都确实停在安全点；
   - 双端队列的进出都核对下标不变量。
2. **折磨测试**：回收折磨（每 N 次分配就强制回收，测试时 N 取一）、调度折磨（随机偷活、随机让核休眠）、输入输出折磨（随机就绪顺序）。
3. **差分测试**：全树测试分别在单核差遣与多核差遣下各跑一遍，输出必须一致。
4. **内存次序**：臂六十四的内存次序是弱的，跨核发布对象必须先写完再发布（存释放、取获得）。冶铸给原子操作生成正确的屏障；双端队列照 Chase–Lev 原文的屏障位置实现，并用小规模穷举交错测试核对。
5. **浸泡**：每期验收前，本机连跑二十四小时的构建与壳负载，用「观役」「析役存」盯内存、窖和停世界时长，不许泄漏、不许涨窖。
6. **分步换链**：一律用带自动退回的安全换链，本机先上；本机浸泡通过后，再上 pit-pc、pit-mac。
7. **修根因**：撞到的缺陷一律追根因、修干净（AGENTS.md），不加开关绕开。
8. **观测先行**：每加一样新结构，同时给出看它的壳命令（AGENTS.md「可观测性是关键」）。
9. **不等 CI**：照「本地开发不管 CI」，核对与验收全在本机做。

## 八、代价与风险

- **共用堆的回收**是最难的部分：停世界汇合、各核并行扫描、晋升段分配，哪一处错都是随机崩溃。第七节的核对模式与折磨测试就是为它准备的。
- **共享可变状态的竞争**：现有库默认单线程，多核以后可能出现数据竞争。靠按实例开关逐步放开，加上审查；静态证明无竞争留给证明层。
- **冶铸的改动**：每核状态块要占一个寄存器，内联分配与状态格访问要改，执行器与编译器一起改，换链要走两级。
- **停世界的停顿**会随核数变长。第一期先量，必要时再做并行标记、并发标记。
- **浏览器（WasmGC）后端**没有共享内存的多核，照旧单核差遣，语义相同。
- **第二期取消线性内存隔离**以后，一个实例的缺陷能波及全系统。这是用户定的取舍，证明层补上之前，靠第七节兜底。

## 九、备选方案

- **每任务一个小堆（Erlang 式）**：隔离好，回收各管各的；但开任务要分配一个堆，消息要拷贝，做不到和调用同价。不采用。
- **只把虚机任务做轻，差遣仍单核**：vm-minor 正在做的那一路（映像共用、栈小起步、参数区按需、区域能还）能把虚机任务降到十几兆，但开任务仍是毫秒级，也用不满多核。作为过渡保留，不作终局。
- **一上来就做协程与可增长栈（Go 式）**：能一步到位做到懒开与真挂起，但要同时改帧的分配、栈图、回收器扫栈，风险集中在一期里。用户定协程之后再说，所以放到第四期。

## 十、待议定事项

1. 名字：均输（工作窃取调度）是否合适。
2. 第一期“多核差遣”默认开还是按实例开：推荐按实例开，先开编译器。
3. 第二期是否把所有常驻服务一次并进同一个堆，还是先并行在、虚机门、监工这些小服务。推荐先并小服务。
4. 实施期间，其他虚机与执行器的改动是否暂停（“停世界”）。推荐：只放行修缺陷，新功能暂停，直到第一期验收。
5. 第一期的验收数字（第五节第 8 条）是否合适。

## 十一、第一期实施步骤

1. 先做观测：「观役」加每核队列与停世界统计，「析役存」加每核新生区（先在单核下就有这些栏）。
2. 列出全部状态格，分成“每核一份”与“全任务一份”；冶铸留出每核状态块寄存器，改内联分配与状态格访问。
3. 每核新生区与晋升段分配，单核下先跑通，全树测试不变。
4. 停世界汇合与并行新生回收，核对模式与回收折磨全过。
5. 「差遣」换成每核双端队列与偷活，「待」帮工，输入输出登记交给虚机。
6. 原子匣与锁的内建函数；审一遍共用的全局匣。
7. 编译器（译场、豫构）的并行环节改用多核差遣，按实例开关打开。
8. 差分测试、折磨测试、二十四小时浸泡，验收第五节第 8 条的数字。
