# 豫章匣点审改表（1-10 第五批，3 处，2026-11-08 复核；2026-11-10 复判并补审表外 32 格）

豫章是标准库，所有程序都用。`水土` 的 `问俗备忘` 是「簿」的不可变快照，`问俗` 只做一次指针读、未命中时以新簿换旧簿；两个任务同抢时只会丢一条备忘，不会读到半截，丢了下次再问即可，故算原子匣（不改）。`差遣` 的 `役序`、`诸门候` 是旧单核调度队列：单核只有一个调度者任务在读写；多核时 `有备乎`/`入序` 走均输的每核队列，不再由这两个旧匣跨任务读写。

**合计**：派生前写定 0 处，单任务独用 2 处，加锁 0 处，原子匣 1 处（问俗备忘，现写法已是指针换，代码不改），每实例一份 0 处。代码 0 处改动。

**2026-11-09 补记（1-10 原子匣路）**：本表三处仍不改。豫章「一气」新加持锁辅助「持闩行」「闩读匣」「闩写匣」「闩改匣」（999e379ed9，闩内抛异常照样放闩），供各包给被多个任务共用的表加锁（豫构的将作、行在、代役已用上，见豫构分表）。`问俗备忘` 改成顶层原子匣（「置原子匣」）要等含原子匣第一趟（f08b10be93）的新链：旧链的顶层数据检查还不认「置原子匣」，在旧链上写会报顶层计算；补丁在原子匣第二趟里。

**2026-11-10 复判（1-10 余项第一批，均输一十）**：上面两条判断有两处不对，已改码。

- `问俗备忘` 不是“指针换就算原子”：普通匣写新簿不带释放，弱序的核（林檎的臂六十四）上别的核可能先看到新簿的指针、后看到簿里新建的节点，读到半截。现在源码的顶层数据检查已认「置原子匣」，改成顶层原子匣，读走获取、写走释放。
- `诸门候`、`轮察余` 在多核下并非没人碰：`行次多核` 每次调度都调 `轮察门`（读写 `轮察余`，清到期时读写 `诸门候`），`唤门候` 的多核分支也调 `唤门旧`（读写 `诸门候`），各核并发读写；只是多核开时登记都进均输的令牌表，门籍恒空，读写的都是空列，看一遍是白看。改法是多核路上不再碰旧格：`行次多核` 去掉 `轮察门`（多核下的等门任务由虚机经注入队交回，防饿靠均输「行常序」逢六十一步先取注入），`唤门候` 多核分支只叫醒均输登候表。这样 `役序`、`诸门候`、`轮察余` 只在旧路（多核关，一条线程跑差遣）上读写。`多核开乎` 在一次运行里经「一算」定死，不会一会儿新路一会儿旧路。
- 库外还有一处读 `诸门候`：将作的「将作可察」（同僚连接的读机会凭据）。将作在 1-11 标了多核，它读到的恒是空门籍，凭据一直不成立，满载时“两端都有读机会满五分钟判失联”那一路从不触发。改成问差遣的「门有候乎」：多核开时问均输的「有候乎」（持表锁扫令牌表，令牌项为此加一栏「事」记登记时关注的事件），关时读旧门籍（「旧门有候」）。库外要问“某描述符上有没有人在等”一律经它。

补审表外 32 格（壬路清点以后新加的，或当时判甲乙的），第二批（章句）又补两处：差遣新加「今役格」，簿录的索引匣改一算发布（问俗备忘存的就是簿，光把根指针改原子匣不够）。表外 32 格：改原子 6 格（了役累、入候累、析持累次、析持累纳改筹匣；协程醒钩、补让钩改「一算」较换发布），改加锁 1 格（协程锁的建锁改「一算」，免两核各建一把），每核一份的两格补关抢区（懒被偷、懒退旧），余下各格定案见下表。

**合计（复判后，表内三格加丙类转来的轮察余）**：原子匣 1 处（问俗备忘，已改），单核旧路独用 3 处（役序、诸门候、轮察余，多核路已不碰）。代码改动见 均输一十 分支提交。

## 附：边界

本表的结论依赖“豫章 的这些匣由上述那一条任务/循环独占”。若以后把该包的多个入口改成同进程并发的差遣任务（例如把浏览器渲染、脚本、样式拆成并行任务，或把壳的前台/后台命令改成真正并行），这些行要重新核，不是永久结论。
