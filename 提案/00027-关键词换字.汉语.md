本文只写现代汉语（AGENTS.md）。

## 一、约束

用户 2026-10-14 定：

1. **解析器照旧。** 仍用操作符表驱动的解析；各操作符的结构基本不变。
2. **允许少量调整参数次序，允许新增中缀与前缀写法。**
3. **避免跨句指代与颠倒参数次序。** 不用“当前之数”、先算后“名之曰”一类指代前文的写法，也不写“以乙除甲”这类读序与语义相反的式子。
4. **名字仍在「」，字符串仍在『』。**
5. **以文学性为准。** 单字同义替换出不了文采，要从整句着手。
6. **不新增标点。** 古书不加标点，句读由读者自断；断句靠虚词本身，排版一读一行。
7. **抛出与捕获仍是库函数**，不做成语言构造。

## 二、手段

1. **换字。** 函数类型 `化……为……`，匿名函数 `得`，局部名 `令……为……`，局部递归 `复令……属……即……`，类型实参 `以`（多个以“及”相连），默认值 `阙则`，匹配首支 `或有`（照提案 00024）。
2. **签名与构造器以“者也”收。** 签名或构造器的类型是函数类型（动词短语）时，加“者”使之名词化：`「平方和」乃化「数」及「数」为「数」者也`、`「枝」立化「树」及「树」为「树」者也`。类型是名词（如 `「小数」`、`「树」`）时照旧 `……也`。
3. **“名 属 类”一以贯之。** 凡“某名（或某值）是某类”，一律写“属”：类型标注 `「零点二五」属「小数」`、带类型的匿名函数 `得「项」属「数」而 体`、依值参数 `化「长」属「数」为……`、隐式值参数 `承「长」属「数」而……`、局部递归 `复令「名」属 类 即 值`。“者”只留给定义“者……也”。
4. **新增中缀、前缀。** 算术与比较（加、减、乘、除以、大于、小于、等于）、`非`、类型标注 `属`、先后 `而后`；都展开成现有的函数调用或节点。多参函数类型以“及”连接参数：`化「数」及「数」为「数」`；多个类型实参同样：`「态射」以「数」及「数」`。
5. **“曰”接标签，“为”给结果。** 标签一律写在“曰”后：类型里 `化「数」曰「起」`，匿名函数里 `得「甲」曰「起」`，调用里 `于「零」曰「起」`。
6. **库里改名。** 整数→数，字符串→文，打印行→书（待定），发生事故→告祸，尝试运行→姑试。
7. **虚词即句读，按位避复。** 不新增标点；函数体前可加“而”承接（不改读法）。第二个参数起写“又得”，免同一虚词复沓。格式化器排版一读一行，换行即句读；“而”一律留在行尾，换行在“而”之后。

## 四、整篇样例

```
现行：
「平方和」乃化「整数」而化「整数」而「整数」也。
「平方和」者会「甲」而会「乙」而
　虑「甲方」者「乘」于「甲」于「甲」而
　虑「乙方」者「乘」于「乙」于「乙」而
　「加」于「甲方」于「乙方」也。

提议：
「平方和」乃化「数」及「数」为「数」者也。
「平方和」者得「甲」又得「乙」而
　令「甲方」为「甲」乘「甲」而
　令「乙方」为「乙」乘「乙」而
　「甲方」加「乙方」也。
```

## 五、机制与风险

- **匿名函数 `得「甲」体`。** “得”后只取一个名字，名字之后即是函数体，界线清楚；体前的“而”只是承接。须原型实测。
- **局部名的值与体之间仍要一个虚词**（而），否则看不出值在哪里结束。
- **“为”的几处用法**：函数类型的结果、`令……为`，靠位置区分，须原型实测。“曰”后一律接标签；“为”不再作标签。
- **“即”的两处用法**：类型别名 `「名」即 类 也` 与局部递归 `复令「名」属 类 即 值`。现行“递归虑……者”与定义共用“者”，解析器已有先例；须原型实测。
- **“者也”收尾。** 签名以“乃”起、构造器以“立”起，“者也”只是收尾的另一写法；须核对它与定义“者……也”、函数类型内部不起冲突。
- **“属”的几处用法**：类型标注（`值 属 类`）、带类型的匿名函数与依值、隐式值参数、局部递归（`名 属 类`），都表“前者归于后者之类”。
- **“及”的两处用法**：多参函数类型与多个类型实参，都连接类型；类型实参的“及”须比“于”结合得紧（现行“授以”即如此），原型实测。
- **“而后”与“而”。** “而后”为中缀，与匿名函数、局部名的“而”同起一字，靠最长匹配区分，须原型实测。
- **新算术词与 `于` 混写不定优先级，须加括号**（同 00022 的且、或）。
- **抛出的类型实参**：今制常要写类型实参，`「告祸」以「数」于『……』` 读来拗口；能否省去看类型推断，原型实测。
- **库里改名**（数、文、书、告祸、姑试）先加别名，再分步迁移。

## 六、本约束下仍做不到的

- 普通函数的调用仍以“于”引出实参。
- 括号仍在，名字仍要「」。
- 数字逐位、注释写法、“。”与列的【，】不变。
- 取项仍写“中零”。

## 七、暂缓与否决

| 项 | 处理 |
| --- | --- |
| 库名「整数表示」→「称数」、「获取子字符串」→「截文」 | 暂缓 |
| 数字用古法（「一百二十三」） | 否决 |
| 标点作连接词（“，”“：”“；或有”） | 撤回（古文无逗号） |
| 介词标签（自、至）与“不然”标签 | 撤回 |
| 列的接头中缀“缀” | 撤回 |
| 多参“化二「数」为「数」” | 撤回，改“及” |
| 捕获的语言构造“姑试……如有不虞”、前缀“呜呼”“书” | 撤回，抛出捕获仍是库函数 |
| 并令（一个“令”领几项绑定：`令「甲方」为……` 下一行直接接 `「乙方」为……`） | 否决 |

## 八、实现与迁移要点

1. **原型。** 在临时工作树里改 `库/编译器核心/编译数据/操作符/内建操作符/`（内建操作符对象定义、文言符集、标签操作符）与规约关系表，用钉点工具链编一级豫构，按新写法改写若干文件，用新编的格式化器逐个解析，核对无歧义（00024 的原型就是这样做的）。
2. **格式化器。** `库/源码排版/源码排版。豫` 写死了“而”“会”“虑”等关键词，须同步，并加避复规则与一读一行的排版；“而”照现行留在行尾。
3. **迁移。** 会→得、授以→以（连续的“授以”第二个起改“及”）、`虑「甲」者`→`令「甲」为`、递归虑→复令、“；”→“而后”可按字替换；“化……而”的“而”、局部递归的“其……者”改“属……即”、签名与构造器末尾的“者也”、“遇 类 者 名”“承 类 者 名”“化 类 者 名”调作“名 属 类”，要按语法定位。若提案 00026 能按文体重印源码，迁移即重印。中缀与“属”是新增写法，旧代码可不改。
4. **换钉。** 编译器先两种写法都认，CI 发布新工具链后改钉，再整仓迁移、删旧写法；云仓须在删旧写法前迁完。
