这是给豫言加入“脚本运行”的提案。编译执行把整个程序静态链接成一个可执行文件（提案 00007 的默认产物），适合发布；可是哪怕只改一行，也要把运行时与标准库重新链接、生成、写出一遍。脚本运行模式下一切都动态装载（用户 2026-10-10 定）：每个模块单独编成一个装载单元（豫汇模块加预编的机器码），运行时按需装进进程，按导入导出链接；脚本自己逐组编成小单元，装入就执行。代码处处是机器码，不设解释器。做法同 SML/NJ 的交互环境：库早已编好装在进程里，输入的每一句编成机器码、链接进去执行。豫构的「运行」「交互」用这一套。做完之后，豫言操作系统的壳就是这个脚本运行器的交互模式，壳的命令语言就是豫言本身（议十四）。

本文只写现代汉语（AGENTS.md）。旧的[文言稿](00003-脚本解释模式.文言.md)是 2026-10-05 的“脚本解释模式”，保留，以本文为准，不再同步。

## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | 两种运行方式：编译执行（整程序静态链接，默认产物，提案 00007）与脚本运行（动态装载）。两者共用前端与代码生成，按《总纲》总〇的源语言兼容核对：接受与拒绝的程序相同，求值轨迹与输出相同。差别有三：出错的时机（脚本运行执行到那一组才报）、优化的范围（脚本运行不跨模块内联与特化）、启动的快慢。《执行与编译》新增一节（第四节） |
| 议二 | 装载单元：脚本运行时，每个模块单独编成一个装载单元，内含一个豫汇模块（按导入导出引用别的模块与运行时）、本模块函数的预编机器码与重定位表，以及前端检查导入它的代码时所需的模块接口。格式在豫行（提案 00005）的段表上加几种段。单元按内容缓存，键为（源码摘要、所依赖单元的接口摘要、编译器源码摘要、执行器摘要、目标架构），与编译器文件本身无关，所以宿主上生成的单元可以随盘带进系统（第五节） |
| 议三 | 装载与链接：执行器按豫汇（Wasm）的导入导出语义链接多个模块：类型跨模块规范化，同构的类型同号；GC 引用、函数引用、全局与异常都能跨模块。原生上把单元的机器码映进可执行内存直接运行。现有多实例的限制（至多 16 个实例、单个模块至多 4 MiB、跨实例只传数值、异常不越过实例）一并放开（第六节） |
| 议四 | 一切动态装载：脚本运行模式下，脚本用到的所有模块，包括标准库、其他库与脚本自己的每一组，都是装载单元，同一进程里同一模块只装一次。承载它们的程序 `yy豫构` 照旧静态链接，内含编译器、执行器与装载器；壳就是它（议十四） |
| 议五 | 逐组编译执行：逐行读入，按《词法与语法》语一的切句规则（圆括号深度零处的 `。`）凑满一句就处理一句；`乃` 句与紧随的同名定义句合成一组。每组过前端，编成一个小单元（引用此前各组与所导入的单元），装入并执行，然后才读下一句（第七节） |
| 议六 | 出错与退出码：某组有语法或类型错误，报出错句的文件、起止行与诊断，退出码 2，此前各句的效果保留；未接住的异常交给标准库登记的顶层处理，退出码 1；`退出进程` 给出的码照用；陷阱的退出码与编译后的程序相同；Ctrl-C 为 130 |
| 议七 | 豫构的子命令：`豫构 运行 路径 参数…` 以脚本运行模式运行；`--只查` 只过前端；`--先查` 先把全文过一遍前端，无错再运行；`豫构 交互` 进入交互求值。`豫构 文件` 能构建成程序的源文件都能这样运行，次序与编译后的程序相同（被导入的测试的程序体、本文件的程序体、入口函数）。`。脚本。豫` 首行以 `#!` 起头时，两种运行方式都跳过这一行（第八节） |
| 议八 | 系统里运行脚本：壳的「运行」「脚本」遇 `。脚本。豫` 时起子任务运行 `yy豫构 运行 路径 参数…`；造盘把标准库与壳命令库的单元随盘带上；内核新增“给本任务映射可执行段”的服务。先做 AMD64，豫行与预编机器码今天只在 AMD64 上运行（第九节） |
| 议九 | 壳命令库：壳的命令作为豫言库「壳命令」提供，成员路径沿用 `命令登记`（如「文件」之「读取」），脚本、交互求值与壳自己共用；不与标准库已导出的名字重名（演示用的「加」改用标准库的同名函数）；命令照壳的习惯打印结果、返回「有」；「运行」收参数列 |
| 议十 | 交互求值（2026-10-04 用户定）：壳的每一行就是一句，括号都闭合即成一句，句末 `。` 可省，未闭合则续行；会话里的定义一直有效；出错只丢弃这一句；值的类型为「有」时不印，其余印成可贴回的豫言写法，值是无参函数时以「元」调用；Ctrl-C 打断正在运行的一句。壳就是 `yy豫构` 的交互模式（议十四），每行编成单元装进同一个进程；新增宿主服务「设可打断」，打开时执行器的检查点见到 Ctrl-C 就抛出中断异常（新 ABI，2026-10-04 用户已同意为此新增中断服务）（第十节） |
| 议十一 | 壳的输入与豫言句合一（2026-10-04 用户定）：壳只收豫言句，字符串参数写 `『』`，角引号包参数的旧句式不再接受；会话开头相当于已导入标准库与壳命令库。每句（含壳命令）都编成组单元执行（2026-10-14 删快路）。补全候选取自前端的名称环境；`.txt` 命令脚本的每行按交互的一句处理；云仓网页壳随之改为豫言句，另行实施 |

| 议十三 | 全树测试：旁边有期望输出的 `。脚本。豫`，编译执行与脚本运行各跑一次，输出都与期望逐字比较；其余脚本照旧不由全树测试发现 |

## 二、动机

### 一行程序为什么也要一秒多

编译执行与 MLton 一样是整程序静态链接：每个可执行文件，哪怕是你好世界，都包含整个运行时（执行器的回收、异常、宿主接口）与它用到的标准库。每次构建都要对整个程序做最终链接（整程序生成豫汇，在内存里编码）与原生生成（转译、降级、连接），写出 Mach-O、ELF 或豫行，macOS 上还要签名。按函数的机器码缓存只省去重新降级没改过的函数，链接、写出与签名仍是整个程序。实测（00007 实施记录、「系统内工具链」）：

| 场景 | 环境 | 用时 |
| --- | --- | --- |
| 构建并运行一个小脚本（打印探针，热缓存） | pit-mac，原生 | 1.39 秒 |
| 你好的原生生成（10-09 剖析，加缓存之前） | 本机 | 逐函数降级 1.3 秒：执行器 0.3 秒，客体函数（主要是标准库）0.77 秒，适配函数 0.15 秒；程序自己的一行几乎不占时间 |
| 给豫言系统加一个函数后重建 | 本机，原生 | 9.3 秒：编译各阶段约 4 秒，最终链接约 2 秒，原生生成约 2.1 秒（其中 Mach-O 与签名约 0.87 秒） |
| 系统里 `构建 你好 -j 4`（AMD64，默认出豫行） | QEMU 纯模拟，四核 8 GB | 单是最终链接 59 秒 |

所以耗时跟程序的总大小成正比，跟改动的大小无关。

### 动态装载

SML/NJ 没有解释器：交互时每输入一句，就编成机器码链接进正在运行的堆，基础库与编译器早已编好装在堆映像里。Poly/ML 也是这样；MLton 只做整程序编译，所以没有交互环境。这和操作系统的动态装载器（ld.so、内核模块）是同一件事：把单独编好的代码装进正在运行的地址空间，按符号解析引用。壳本来就是装载、运行二进制的地方。

动态装载之后，一句的代价只剩这一句的前端、这一句几个函数的代码生成与降级、装载，宿主上估计几十毫秒；库的单元编一次，此后所有脚本与会话都直接装载。

### 壳不能写逻辑

今天的壳由开机壳与桌面命令行共用：会话在 `库/用户态桌面/命令壳。豫`，句式解析与命令登记在 `库/壳核心`。它只收正式句式：每段都包在「」里，`之` 连成员，`于` 引参数，如 `「文件」之「写入」于「/新/甲.txt」于「你好 世界」`。登记表共 21 项命令，没有变量、条件、循环与函数。`「脚本」于「路径」` 逐行执行命令，行与行之间不能传值，也不能按退出码分支。`「运行」` 每次起一个新任务：豫行文件跑预编的机器码（AMD64），其余当 Wasm 由执行器解释。`。脚本。豫` 是源码，不能直接运行。

壳的正式句式其实已经是豫言的成员与应用写法（`之` 连成员，`于` 引参数），只差参数的引号。脚本能逐句编译运行之后，壳就不必再是另一个程序、另一种语言：它就是豫言的交互运行器，壳命令只是一个库。

### 已有的基础

- **按函数的机器码与重定位**：提案 00007 的客体函数按内容缓存，链接时按稳定身份重定位（全局偏移、表零下标、调用目标）。链接器所需的符号机制已经有了，只是在构建时静态地做。
- **执行器的多实例**：执行器能在运行中装载更多 Wasm 模块、建成实例，按（模块名，字段名）链接导入，支持延迟链接（《客体二号》“多实例”）。限制是：每个实例有自己的类型表，`ref.test`/`ref.cast` 遇到别的实例的对象一律判为不属于；跨实例只传数值；表、内存与全局不能导入导出；异常不越过实例；至多 16 个实例，单个模块至多 4 MiB；装入的模块只能解释执行。
- **豫行格式**（提案 00005）：文件头加段表，每段写明种类、权限、虚拟地址与长度；第一版不做动态链接与重定位。
- **系统里**：有 `/工具/yy豫构` 等豫行工具，能构建你好、编译器本身与启动盘；两种架构都有动态任务，子任务能再起子任务；每任务至多 127 TiB，执行器页上限约 4 GiB；「存放包上下文」等构建宿主服务都已实现。

### 前两稿

- 2026-10-04 稿：壳里另链一个求值器，在擦除后的树上解释执行。
- 2026-10-10 上午稿：编译器兼做解释器（用户 10-06 定的方向），前端共用，后端是求值器。

## 三、目标与范围

目标：

1. 宿主上 `豫构 运行` 运行脚本，`豫构 交互` 进入交互求值。
2. 豫言操作系统的壳直接运行 `。脚本。豫`：运行程序、读写文件、取参数与环境变量、按退出码分支，不经整程序构建。
3. 两种运行方式源语言兼容，出错的时机除外。
4. 逐组执行：前面的句子先生效，错误报到出错的那一组。
5. 脚本出错只结束脚本；交互出错只丢弃这一句，壳照常工作。
6. 壳的交互输入就是豫言句；每句（含壳命令）都编成单元执行，靠预编与预装做快（2026-10-14 删快路）。
7. 速度达到第十二节的暂定目标（第 2 步实测后修订）。
8. 壳就是豫言：开机程序是 `yy豫构` 的交互模式，系统里没有另外的壳程序与壳语法。

范围见文首表格。第十五节的后续各项、壳的重定向与管道、云仓网页壳的具体实施（在云仓另做）、ARM64 上的脚本运行（等豫行能在 ARM64 上运行）都另行处理。

## 四、规范：两种运行方式

《执行与编译》新增“脚本运行”一节，要点如下：

- **编译执行**：整个程序先过前端，无错才生成并运行；运行时的次序按现行行一。
- **脚本运行**：逐组过前端、编成单元、装入并执行，一组的效果在下一组开始前已经发生；带入口函数的普通源文件处理完后，再调用入口函数一次，与编译执行相同。被导入的模块以单元装入，不执行计算：普通模块的顶层只有定义（提案 00006），顶层数据按值取用，「首次计算」的值在第一次取用时计算，与编译执行相同。
- **两者的关系**：接受与拒绝的程序相同，求值轨迹与输出相同（《总纲》总〇）。差别是出错的时机（编译执行在运行前报出全部语法与类型错误；脚本运行执行到那一组才报，`--先查` 时与编译执行相同）、优化的范围与速度。
- **同名再定义**：沿用编译器的规则，引用命中较早的定义（《类型与模块》）。要随执行改变的量用「新引用」「写引用」。
- **首行 `#!`**：`。脚本。豫` 首行以 `#!` 起头时，两种运行方式都跳过这一行（《词法与语法》同步）。

## 五、设计：装载单元

### 生成

- 前端各阶段照旧逐模块进行（依赖分析、语法解析、类型检查、跨模块优化、闭包转换），阶段缓存照旧。跨模块优化只用所依赖模块的接口信息（签名元数、顶层元数），不把别的模块的函数体内联进来。
- 新增“单元代码生成”：从本模块的闭包形式生成一个豫汇模块。
  - 导出：本模块的顶层定义（函数、顶层数据、「首次计算」的格）。
  - 导入：所引用的别的模块的定义、运行时支持函数、宿主接口函数（照旧是带类型的导入）。
  - 类型：各模块各自定义所用的 GC 类型，装载时按同构规范化。
- 豫言的回收运行时（编译器写出的装箱、拆箱等辅助函数）单独编成一个“运行时单元”，各单元从它导入。
- 原生上，预编二与降级只处理本模块的函数；对执行器、运行时单元与别的单元的引用都留成重定位，沿用 00007 的符号常量与按稳定身份重定位。机器码仍按函数缓存。

### 内容与格式

一个单元在豫行的段表上加这几种段：

- 豫汇模块：类型、导入、导出、全局、数据、函数签名。
- 机器码段与重定位表：本模块函数的预编机器码，以及待填的执行器函数、别的单元的导出、全局与类型号。
- 模块接口：前端检查导入它的代码时所需的名称解析资料、检查后定义等（树码）。
- 附录：符号表，供调用栈与剖析使用。

单元文件的后缀实施时定，登记进《文件后缀》。

### 缓存

- 键：（源码摘要、所依赖单元的接口摘要、编译器源码摘要、执行器摘要、目标架构）。用编译器源码的摘要，宿主上的豫构与系统里的豫构由同一份源码造出，所以宿主上生成的单元系统里也能用。
- 位置：宿主上在豫构的缓存目录里另设一处存单元；豫言操作系统上先查盘上随带的单元，再查系统里自己的缓存。
- 缺了就生成：豫构照并行编译的办法先把所缺的单元编出来；标准库的单元编一次，此后所有脚本与会话共用。

## 六、设计：装载与链接（执行器）

### 多模块链接

- **类型规范化**：各单元的类型按递归组同构规范化成全进程统一的类型号；对象头记规范的类型号，`ref.test`/`ref.cast` 跨单元照常成立。
- **跨单元的值**：整数、小数、GC 引用、函数引用都能作导入函数的实参与结果；全局可以导入导出；异常标签按规范身份共享，异常跨单元传播。
- **装入**：从单元取豫汇模块建成实例，链接导入；沿用现有的延迟链接，互相引用的单元可以先后装入。同一模块只装一次。
- **上限**：实例数与单个模块的大小往大里定（实例至多一百万个，单个模块至多 4 GiB）。

### 机器码

- 把单元的机器码映进可执行内存：豫言操作系统上用新的内核服务（第九节）；macOS 上用 MAP_JIT；Linux 上先映射可写、填好后改为可执行。
- 按重定位表填入执行器函数、运行时单元与别的单元的导出、全局与规范类型号的地址或编号，再登记函数入口。
- 检查点：函数入口与循环回跳处的中断检查照执行器现行的做法；第 2 步核对预编代码保留了它，没有就补上。
- 回收：单元的全局与常量登记为根；栈帧扫描沿用预编代码现行的办法。
- 单元装入后不卸载（待办事项）。

## 七、设计：逐组编译执行

### 读句

- 逐行读入。词法扫描维护圆括号深度；名称 `「」`、字符串 `『』`、注释 `「：…：」` 里的 `。` 都在令牌里，注释可以嵌套。遇到深度零的 `。` 就得一句：一行里可以有几句，一句也可以跨几行；文件末尾没有句号的非空尾句照常处理（都与语一相同）。
- `乃` 句先不处理，等下一句：下一句是同名的 `者` 或 `即` 定义，就合成一组；否则报错，与编译器“末尾独立签名、不同名或中间夹其他声明均拒绝”的规则相同（语四）。

### 每组的处理

以下路径都在 `库/编译器核心/编译步骤/` 下。

1. **语法分析**：编译器本来就逐句解析（`语法分析/抽象语法分析。豫` 对每句调用 `语法分析/表达式解析。豫` 的「解表达式默认操作符及语义标记」）。
2. **名称解析**：顶层名称解析本来就是按句序推进的循环（`名称解析/名称解析。豫` 的「进行文件名称解析顶层」），导入只对其后的句子生效。保留这个循环的状态，每组推进一步。
3. **类型检查**：「进行文件定义列检查」（`类型检查/文件结构检查。豫`）本来就是逐条定义、带着「命名环境」往下走的循环，每条之后用「添加已检查文件定义」扩展环境；依赖模块的检查后定义按需读取（`类型检查/类型检查基础。豫` 的「文件定义引用类及物」，脚本运行时从单元的模块接口里读）。把循环的一步拆成可以单独调用的入口，每组调用一次，留下返回的环境。
4. **模式展开、类型擦除与闭包转换**：对本组的定义各做一次。
5. **编成组单元并执行**：本组的定义成为组单元的导出，后面的组按导入引用它们；本组的裸式编进组单元的执行函数。装入组单元，调用执行函数一次。

先例：着色分析在内存里依次做词法、语法、名称解析、类型检查，结果只写进内存（`着色翻译/着色分析。豫` 的「写内存检查后定义」）。脚本自己的组单元也只放在内存里，不写缓存。编译配置放在全局可变引用里（`编译数据/编译配置/全局配置。豫`），开始时一次设好。

### 出错

- 前端在某组报错：打印出错句的文件、起止行与诊断，退出码 2；交互时只丢弃这一句。
- `--先查`：先把全文逐组过前端，不生成单元；无错再从头编成单元运行，前端的结果直接复用。
- `--只查`：只过前端。

## 八、设计：豫构的「运行」「交互」

```sh
豫构 运行 路径 参数…
豫构 运行 --只查 路径
豫构 运行 --先查 路径 参数…
豫构 交互
```

- **包上下文**与 `豫构 文件` 相同：从文件所在目录找所属的包与仓库，依赖照包描述。
- **参数**：`获取命令行程序名` 得脚本的路径，`获取命令行参数` 得脚本后面的参数，与编译后的程序相同。
- **交互**：会话开头相当于已导入标准库；读句、印值与出错照第十节，用于在宿主上调试。
- **首行**：macOS 与 Linux 上 `yy豫构` 是原生可执行文件，脚本首行可写 `#!/usr/bin/env -S yy豫构 运行`（`yy豫构` 在 PATH 里时）。
- **诺节**（Windows 与没有原生工具链的地方）：单元里的豫汇模块就是 Wasm 模块，诺节宿主按 Wasm 的导入导出实例化、链接，不用机器码段（第 6 步）。

## 九、设计：接入豫言操作系统

### 运行脚本

- `「运行」于『甲。脚本。豫』于「列」【…】` 与 `「脚本」于『甲。脚本。豫』`：壳起子任务运行 `yy豫构 运行 甲。脚本。豫 参数…`，退出码照常打印；开机壳同步、桌面命令行异步，与运行别的程序相同。
- 第 8 步之前，壳还是旧程序，子任务用盘上的 `/工具/yy豫构`；盘上没有它（造盘没带 `--工具链`）时报“这张盘没有工具链，不能运行脚本：造盘时加 --工具链”。第 8 步之后，壳就是 `yy豫构`（议十四），子任务用同一个程序，随启动盘带上。
- 脚本在自己的任务里运行，可以再运行程序（子任务能再起子任务）。工作目录与环境变量是脚本自己的，结束后壳不受影响。
- Ctrl-C：内核把它记成标志，子任务见到就以 130 退出（现行机制）。
- 内存：验收用的 QEMU 内存放到 2 GiB（议十二）。

### 单元随盘

造盘时在宿主上生成标准库与壳命令库的 AMD64 单元，写进盘里（位置实施时定）。系统里的豫构与壳先查这些单元，再查自己的缓存；`/源` 里别的包在系统里现编。

### 内核服务

新增服务“给本任务映射可执行段”：参数同豫行段表项（提案 00005 第 5.2 节，文件内偏移换成调用者缓冲里的地址），权限为读与执行，映到调用者给出的地址范围。编号与错误码写进平台接口规范。

### 架构

先做 AMD64：豫行与预编机器码今天只在 AMD64 上运行，ARM64 的启动盘关着预编二。ARM64 等豫行能运行之后跟上。

## 十、设计：交互求值与壳输入合一

### 壳就是豫言

- 开机程序就是 `yy豫构`，预编成豫行随启动盘带上，以交互模式启动（议十四）。它内含编译器（前端、单元代码生成、预编二与降级）与装载器；会话状态就在这个进程里：前端的名称与类型环境，以及已装入的单元。
- 每一行编成一个组单元，装进同一个进程执行。
- 印值的代码由编译器按这一句的类型生成在组单元里（调用标准库的显示函数，得出豫言写法的字符串），交互模式只打印返回的字符串。
- 行编辑、拼音输入、智能候选与补全（今天在 `库/壳核心`）并入交互模式。
- 「图形」把桌面的单元装入并运行，退出桌面后回到会话；桌面里的命令行窗口在同一个进程里另开一个会话。
- 原来的壳程序退役：`豫言操作系统/裸机/壳/` 的输入循环、`库/用户态桌面/命令壳。豫` 的会话与 `库/壳核心` 的正式句式解析。
- 宿主上的 `豫构 交互` 也预先装入壳命令库：在 macOS、Linux 的终端里与在豫言操作系统里是同一个程序、同一种行为。

### 一行就是一句

- 壳读入一行，交给读句器：名称、字符串、圆括号、方括号与注释都闭合时，这一行就是一句，句末的 `。` 可写可不写，一行里有几句就依次处理；没闭合就印续行提示 `…> `，接着读下一行。
- 会话开始时相当于已执行 `寻观「标准库」之书。寻观「壳命令」之书。`。
- 会话就是一份边写边跑的脚本：前面的导入与定义在后面的句子里都有效。

### 出错与中断

- 编译或运行出错：打印诊断，丢弃这一句（它的定义不进环境），接着读下一行。脚本则出错即止（第七节）。
- Ctrl-C：编辑时放弃这一行；运行时打断这一句，回到提示符，会话环境保留。首任务（壳）今天见到 Ctrl-C 只记下“中断挂起”。新增宿主服务「设可打断」：壳运行一句之前打开、之后关上；打开时执行器的检查点见到 Ctrl-C 就抛出中断异常，壳接住后回到提示符。声明加在 `豫言操作系统/裸机/宿主服务。接口。豫`，由 `客体二号/带型名。底层。豫` 映射，与 `豫言操作系统接口/` 的接口清单无关。
- 逐键编辑器今天不查中断标志（编辑到一半按 Ctrl-C 无效，壳测试「中断」已暂停），第 8 步一并接上。
- `「退出」` 结束壳，与今天相同；交互时调用 `退出进程` 也结束壳。

### 印值

- 裸式的值的类型由这一句的类型检查给出。类型是「有」时什么都不印。
- 值是无参函数（类型为 `化「有」而…`）时，以「元」调用它，再按结果处理；所以 `「环境」`、`「帮助」` 这类无参命令可以不写 `于「元」`。这条只在交互时成立，脚本里照样要写，与编译执行一致。
- 其余按类型印成可以贴回去的豫言写法：整数 `「42」`、小数 `「1.5」`、爻 `「阳」`、字符串 `『…』`、列 `「列」【…】`、元组 `（… 与 …）`、构造器 `「名」于 …`；函数、引用与宿主资源印成 `（函数）`、`（引用）`、`（资源）`。

### 不设快路（2026-10-14 用户定）

- 壳里每句（含只调壳命令、参数全是字面量的一句）都编成组单元装入执行。“一切动态装载”本身就排除了不编译、按名字直接调用命令的快路；原稿以“纯模拟下编一句要零点几秒到几秒”为由保留快路，2026-10-14 删去。
- 编译路径靠造盘时预编前导、开机时预装与会话里进程内逐组编译做快；造盘缺省带工具链，盘上没有编译器时壳里什么句子都运行不了。
- 同一宿主上所有壳能执行的句子完全相同（用户 2026-10-14 定）：开机壳、桌面终端与远程登录都是豫构交互会话，会话开头编一组登记系统里的壳命令做法（「命令壳」之「登记系统会话做法」）与会话做法（「实现」之「登记会话做法」）；「图形」「打开窗口」经壳请求交给初始任务办。实施见[实施记录](00003-实施记录.汉语.md) 2026-10-14 条。

### 壳命令库

- 新库「壳命令」（`库/壳命令`，依赖标准库），成员路径沿用 `库/壳核心/命令登记。豫` 的登记：「帮助」「图形」「回显」「运行」「设」「取消」「环境」「日期」「脚本」「退出」，以及「文件」之「当前」「切换」「列出」「读取」「写入」「追加」「复制」「移动」「建目录」「删除」。
- 文件与进程操作今天写在 `库/用户态桌面/命令壳。豫` 与 `豫言操作系统/裸机/壳/壳。豫` 里，搬进「壳命令」，壳与桌面命令行改调它。「图形」「退出」要回到壳，由壳登记处理函数。
- 不与 `寻观「标准库」之书` 已导出的名字重名：演示用的「加」去掉，`「加」于「12」于「30」` 就是标准库的加法，印出 `「42」`。实施时逐个核对（如 `控制/异步。豫` 也有「运行」）。
- 命令照壳的习惯打印结果、返回「有」，交互时不会再印一遍；要拿值来编程，用标准库（如「文件系统」之「读文件」）。
- 参数个数可变的「运行」改收参数列：`「运行」于『/程序/你好.wasm』于「列」【『甲』，『乙』】`；可省的参数改为必填，如 `「文件」之「列出」于『.』`。

### 输入法与补全

- 已知名称的候选取自前端的名称环境：导入的名字、壳命令、会话里的定义；`之` 之后给该模块的成员，`于` 之后给参数，路径照旧取当前目录。
- 参数位置的字符串写 `『』`：选中的路径候选填成 `『…』`，回车时把自由参数包成 `『』`（纯数字包成 `「」`），中文模式的 Shift+[ 在参数位置先出 `『』`。
- 角引号包参数的旧正式句式不再接受。`库/壳核心` 的 `命令位置` 句式解析由读句器与语法分析代替，`命令登记` 留作补全与快路的名录。

### 命令脚本与网页壳

- `「脚本」于『路径.txt』`：每行按交互的一句处理，先印 `+ 行`，出错继续；`。脚本。豫` 照第九节。
- 云仓网页壳原与默认壳同一写法，随之改为豫言句（字符串用 `『』`）。网页壳只认命令调用；在云仓另行实施。

## 十二、速度与验收

目标（2026-10-11 第 2 步实测后修订，实测见实施记录）：

| 场景 | 目标 |
| --- | --- |
| 宿主，单元已缓存，`豫构 运行` 十句的脚本（导入标准库、运行一个程序） | 0.1 秒内完成，不计所运行程序的时间（第 2 步实测：打印探针 0.03 秒，装入 22 个单元约 20 毫秒；对照：编译执行构建并运行 1.2–2.1 秒） |
| 宿主，脚本改过、库单元已缓存 | 0.3 秒内：整份脚本在豫构进程里编译（第 2 步实测 1.5–1.7 秒，编译器子进程做前端；第 3 步只把交互改成了进程内逐组编译，「运行」仍用子进程，改进程内编译是后续事项） |
| 宿主，交互一句（库已装入） | 平均 50 毫秒以内（第 3 步实测：裸式与定义每句约 50 毫秒，四百句的会话平均约 55 毫秒；会话启动 0.5 秒） |
| 宿主，第一次为标准库生成单元 | 实测记录（只做一次；第 2 步：打印探针的 22 个单元连同编译 4.1–4.4 秒） |
| 豫言操作系统 AMD64，`--预编二 --工具链` 盘，单元随盘，同一脚本 | 实机或 KVM 下 1 秒内；QEMU 纯模拟实测记录（实测：QEMU 纯模拟四核，印记命中时例一 写读 约 5 秒，新盘第一次 98 秒；单元在第一次运行时于系统里生成、缓存在数据盘，没有随盘；KVM 未测） |
| 壳里走快路的一句 | 与今天的正式句式相当（实测：即时） |
| 壳里编成组单元的一句 | 实测记录（QEMU 纯模拟：新开机第一句 30–51 秒，含建会话与装前导单元；定义一句不到 40 秒，用到定义的一句约 5 秒；新盘第一句先在系统里编前导 322 秒） |
| 两种运行方式的输出 | 全树测试与壳测试里逐字相同（实测：全树测试 18 个有期望输出的脚本两种方式逐字相同，快路 12 句与直接调用逐字相同） |
| 代码的速度 | 单元里与编译执行一样是机器码；跨单元的调用不内联（第 2 步实测：每次多约 3 纳秒，一千万次调用 62 对 30 毫秒） |

## 十三、兼容与迁移

- **语言**：没有新语法与新类型规则；多一种运行方式；`。脚本。豫` 首行可写 `#!`。
- **编译执行**：照旧，整程序静态链接仍是默认产物。
- **编译器核心**：新增按模块生成豫汇的单元代码生成，与整程序的最终链接并存；前端循环的一步拆成可单独调用的入口；词法跳过脚本首行 `#!`。其余语义不变；三四级自举逐字节相同。
- **执行器**：多模块链接的扩展与机器码装载影响所有用执行器的地方，`yy裸机验证` 380 项、`yy普通豫言验证`、「原生对比」都要重跑。
- **豫行格式**：新增几种段，同步《豫行格式》（`豫言操作系统/裸机/文档/豫行格式.汉语.md`）。
- **内核与宿主服务**：新增“给本任务映射可执行段”的内核服务与「设可打断」宿主服务，写进平台接口规范与《客体二号》。
- **壳**：开机程序换成 `yy豫构` 的交互模式，旧壳程序退役；写法改为豫言句（字符串用 `『』`）；演示用的「加」由标准库的同名函数代替；`壳/测试/` 与 `库/壳核心/测试/` 的输入与期望随之改写。
- **造盘**：开机模块换成预编成豫行的 `yy豫构`；桌面与壳命令库以单元随盘带上。
- **云仓网页壳**：写法随之改为豫言句，在云仓另行实施，同步云仓的说明与测试。
- **全树测试**：`测试规则.tsv` 里针对脚本的跳过规则，第 4 步逐条核对。
- **文件后缀**：单元文件的后缀登记进《文件后缀》。

## 十四、备选方案

| 方案 | 结论与理由 |
| --- | --- |
| 每次都编译执行（整程序静态链接） | 现状。一行也要一秒多，系统里单是链接就一分钟；交互的每一行若都编成新程序，句与句之间无法共享值。编译执行仍是正式程序的默认方式 |
| 解释执行：壳里另写求值器（10-04 稿），或编译器兼做求值器（10-10 上午稿） | 不取（用户 2026-10-10 定）。要维护第二套执行引擎并与编译执行保持一致；代码慢十到五十倍；动态装载的单元还能给操作系统当动态模块与共享库 |
| 库动态装载，脚本自己解释执行（GHCi 的做法） | 不取。用户定一切动态装载、处处是机器码 |
| 单元只用自定的机器码格式与符号表，不带豫汇模块 | 不取。豫汇是执行边界；单元带着豫汇模块，诺节与浏览器上可以直接按 Wasm 的导入导出链接，各后端功能一致；原生的重定位沿用 00007 |
| 每句一个进程，靠共享库链接 | 不作交互的做法：句与句之间的值要留在同一进程里。脚本整份在一个进程里运行 |
| 交互放在常驻的豫构子任务里，壳只转发行 | 不取。现行 Ctrl-C 机制会直接结束子任务，会话随之丢失；补全要读名称环境，与会话在同一进程最直接 |
| 保留独立的壳程序，只把编译器与装载器链进去 | 不取。壳与 `豫构 交互` 就成了两份交互实现；壳就是豫言的运行器，宿主与系统里同一个程序、同一种行为 |
| 跳过类型检查，直接编名称解析后的树 | 否。类型检查还做细化（命名元组的按名投影改成按序投影、标签参数等），模式展开与擦除都在它之后 |
| 给壳的命令语言加变量、条件、循环、函数 | 否。那是另造一门语言，仓库规矩不许自造语言或 DSL；豫言本身已有这些 |
| 每一行都编成单元，不设快路 | 采用（2026-10-14 用户定，见“不设快路”一节）。原稿以纯模拟下编一句要零点几秒到几秒为由不取，与“一切动态装载”相悖 |
| 保留正式句式，另设一条命令进入交互求值 | 否。2026-10-04 用户定壳的输入与豫言句合一 |
| 交互时也要求无参命令写 `于「元」` | 不取。交互时自动以「元」调用无参函数；脚本里仍须写，与编译执行一致 |

## 十五、后续

- **开机程序变小**：编译器的大部分也做成单元，第一次编译时才按需装入。
- **跨单元内联**：把小函数的体随模块接口带上，单元的键随之含被内联者的摘要。
- **系统里的程序改用动态链接**：编译执行产出的程序共用一份标准库与运行时单元，程序变小、装得更快，就是共享库；单元的代码页再在进程之间共享。
- **编译期求值**：编译器能装入并运行单元之后，可以在编译时算出顶层可算的值，写成数据（提案 00006 留下的口子）。
- **其他**：卸载单元；会话存盘；ARM64。

## 十六、未决问题

1. 系统里脚本能用的库：只限随盘带了单元的，还是 `/源` 里全部的包（系统里现编）。
2. 同名再定义：脚本作者与交互用户容易把它当作变量重新赋值；要不要给警告。
3. 「运行」要不要另给一个按空白拆参数的简写（如 `「运行」于『/程序/你好.wasm 甲 乙』`）。
4. 网页壳改用豫言句后，云端用什么解析：链进编译器的前端，还是只解析命令调用（须是完整写法的子集）。
5. 会话里的定义要不要存盘，重启后恢复。

## 十七、实施步骤

按下面的次序做，每一步单独合入，合入前完成本步的验收。

1. **单元生成**（宿主；依赖：无）
   - 编译器核心：单元代码生成（按模块生成豫汇，导出本模块的顶层定义，导入别的模块与运行时单元）；跨模块优化只用接口信息。
   - 裸机后端：按模块预编与降级，写出单元（豫行加新段）；按内容缓存。
   - 验收：标准库全部模块与运行时都生成单元；同一函数的机器码与整程序构建的对照；`豫构 目标 类型检查 豫构测试 -j 24`。
2. **装载与链接，`豫构 运行`**（宿主原生；依赖：1）
   - 执行器：类型规范化，引用、全局与异常跨单元，上限放开；macOS 与 Linux 上映射可执行内存、重定位、登记根；核对检查点。
   - 豫构：「运行」子命令，先把整份脚本编成一个单元再运行（逐组留到第 3 步）。
   - 实测：装入标准库单元的耗时与内存、十句脚本的总用时、跨单元调用的开销，记入第十二节。
   - 验收：一组脚本样例（含例一至例三）两种运行方式输出逐字相同；`yy裸机验证` 380 项与 `yy普通豫言验证` 通过。
3. **逐组与交互**（依赖：2）
   - 前端逐组入口；组单元；`豫构 交互`；词法跳过首行 `#!`。
   - 验收：`豫构 交互` 跑通例五里不依赖壳命令的句子；出错丢弃、定义跨句有效。
4. **全树测试接入**（依赖：2）
   - 有期望输出的 `。脚本。豫` 两种运行方式都跑，规则写进 `测试规则.tsv`；核对针对脚本的旧跳过规则。
5. **壳命令库**（依赖：无）
   - 新库「壳命令」，核对与标准库的重名；「运行」收参数列；壳与桌面命令行改调它。
6. **诺节上的脚本运行**（依赖：2）
   - 诺节宿主按 Wasm 的导入导出实例化、链接单元里的豫汇模块；Windows 上 `豫构 运行` 可用。
7. **系统里运行脚本**（AMD64；依赖：2、5）
   - 内核服务“给本任务映射可执行段”；造盘带上标准库与壳命令库的单元；壳的「运行」「脚本」遇 `。脚本。豫` 起 `/工具/yy豫构 运行` 子任务；盘上没有工具链时的提示；QEMU 内存 2 GiB（议十二）。
   - 实测：系统里运行例一至例三的用时，QEMU 纯模拟与 KVM 各一组。
   - 验收：`yy普通豫言验证` 新增脚本测试（例一至例三、出错的退出码、Ctrl-C、脚本里运行程序、脚本里运行脚本）逐字通过（AMD64 的壳测试今天登记为已知失败，先用启动盘冒烟）；`yy裸机验证` 380 项。
8. **壳换成运行器：交互求值与输入合一**（AMD64；依赖：3、7）
   - 开机程序换成预编成豫行的 `yy豫构`，以交互模式启动；造盘随之改；起脚本子任务用同一个程序。
   - 行编辑、拼音输入、智能候选与补全并入交互模式；「图形」把桌面作为单元装入；桌面命令行窗口另开一个会话；「设可打断」；逐键编辑器接上中断标志。
   - 每行编成组单元执行：印值、无参函数调用、续行、出错丢弃、Ctrl-C 打断；快路；补全候选取自名称环境，参数位置用 `『』`；`.txt` 命令脚本按交互的一句处理。
   - 旧壳程序与正式句式解析退役；`壳/测试/` 与 `库/壳核心/测试/` 的输入与期望改写后随之搬家；宿主上的 `豫构 交互` 也预先装入壳命令库。
