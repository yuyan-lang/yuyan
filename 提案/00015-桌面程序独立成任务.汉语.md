## 一、拟定事项

- **议一：画面直接映射。** 子程序的显示面放在共享物理块里，复用内核服务 55「区段物块」与 56「映物块」，子任务与初始任务各映一份：子任务画，初始任务读。子程序提交画面时只给初始任务发一条“哪块区域变了”的短消息，像素不再经服务 41 拷贝，也不进消息。
- **议二：初始任务直接合成。** 外壳把每个显示面在屏幕上的矩形登记给执行器；初始任务收到变化区域，就从映射的显示面把这块直接写进帧缓冲（裁到格子以内），外壳界面不用重画。外壳自己的标签栏、边框与弹出层照常提交；弹出层盖住某一格时，那一格暂停直贴，弹出层关掉后整格重贴一次。
- **议三：桌面上的程序全部独立成任务。** 外壳只管平铺（分割树、标签组）、活动栏、启动程序与合成画面。终端、文件浏览、任务管理器、设置、编辑、搜索、构建输出、差异与会话都是独立程序，各是一个子任务。
- **议四：一个程序可以开多个显示面。** 程序向外壳要新的显示面，外壳新开一个标签放它；每个显示面各自提交画面、各自收输入。编辑器一个任务管所有打开的文件，每个文件一个显示面。
- **议五：外壳请求与外壳来信。** 程序请外壳办事：新开显示面、打开文件（可带行号）、运行程序、重读设置、结束程序。外壳把“打开文件”转给能打开它的程序：编辑器在运行就交给它，不在就先启动它；程序经“外壳来信”收到。文件浏览点开文件、搜索结果与构建错误跳到代码，都走这条路。
- **议六：轻量的桌面程序框架。** 新库「桌面程序」：程序照今天格子程序的写法（初态、更新、视图、计时，加外壳请求与来信），框架提供两种跑法——独立任务（取转授的显示面，可开多个）与嵌入（浏览器里没有子任务，外壳在自己里面跑它）。同一份程序代码两处用。
- **议七：一个程序出错只影响它自己的显示面。** 子任务陷阱、缺页或退出时，内核收回它的块，初始任务停止贴它的画面，外壳把它的各个标签换成“程序已结束”（原因与退出码）和“重新运行”“关闭”两个按钮，其余程序与外壳照常运行。任务管理器里每个程序有自己的处理器与内存读数，可以结束。

## 二、动机

1. 用户 2026-10-11 在 AMD64 实机上看到：开了终端、文件浏览与任务管理器，任务管理器里没有它们，因为这些格子程序和桌面同在初始任务里。用户定：画面直接映射，程序分开，一个程序崩了不带崩整个图形界面；编辑、搜索、构建输出也做成独立程序，外壳做成轻量框架。
2. Windows 与 macOS 都由系统组件合成窗口（DWM、WindowServer），程序把画面画在与合成器共享的内存里。资源管理器、访达、终端、任务管理器（活动监视器）都是普通进程，出错不影响合成。
3. 现在的子程序显示代办（00014 议四）每次取画面都经初始任务整块拷画布（1280×800 约 4 MB，00014 第九节），再让外壳重画像素图；外部程序的画面越大越慢。
4. 外壳越小越不容易出错。现在外壳带着工作台与源码文档用的编译器核心，开机程序大；初始任务还兼管全部文件代办，界面一忙文件也跟着慢。

## 三、目标与范围

做：

- 裸机，AMD64 先验收。内核与执行器是两种架构共用的底层豫言，ARM64 等 ARM 工作恢复后验收。
- 议一至议七。

留待后续：

- 原生 macOS 的共享内存代办（现走管道，功能相同）。原生图形桌面先以嵌入方式跑这些程序，共享内存代办做好再切。
- 几个程序共用同一份执行器与库的机器码（豫行只读段按内容共享，见《动态任务》后续事项）。
- 孙任务（程序再起的程序）取显示面：先经外壳请求新开显示面。
- 编辑器出错时自动保存草稿。

## 四、设计

### 4.1 共享显示面（议一）

- 子任务的执行器取得显示面时（转授的第一个面，或经外壳请求新开的面；代办开关见 00014 §4.6），在自己动态区顶端留出整块（2 MiB）放画布：宽×高×4 字节，向上取整到块。用服务 55 逐块取物理块号，随“已取得显示面”的代办消息交给初始任务。尺寸变了就另留一批块，再交一次。
- 初始任务用服务 56 把这些块映进自己动态区里预留的一段，每个显示面一段，按（句柄、面号）记录，只读使用。
- 子程序提交画面时，执行器把变化区域的行从客体的画面字节串拷进共享块（本任务内拷贝），再发一条短消息（面号、区域矩形）。初始任务贴完回确认，子程序收到确认才写这个面的下一帧，画面不会撕裂。
- 子任务结束时按服务 55、56 的规则归还块：初始任务先撤下自己的映射（数据块项写零），两边都不再映着时块才归还。

### 4.2 初始任务直接合成（议二）

- 外壳每次排版后，对每个显示面调「设子程序画面位置」（句柄、面号、屏幕矩形、可见）；被弹出层盖住、切到后台标签或缩成零的面设为不可见。
- 初始任务在显示轮办里收到变化区域：可见时把区域与屏幕矩形取交，从映射块按行写进帧缓冲（同提交帧的区域写入，服务 32），随后补画鼠标光标；不可见时只记下脏区，重新可见时整面重贴。
- 外壳一侧：在支持直贴的宿主上，程序的标签画成占位，不画像素图；其余宿主照旧取画面贴像素图。

### 4.3 桌面程序框架（议六）

- 新库「桌面程序」（`库/桌面程序`）。程序描述：初态、更新、各显示面的视图、计时需求、外壳来信的处理；程序可以发外壳请求。
- 独立跑法：取转授的显示面，开显示控件主循环；要新显示面时发外壳请求，外壳来信“新显示面”后多一个面，每个面一个视图，输入按面分派。
- 嵌入跑法：外壳把程序当格子程序在进程内跑，请求与来信改成进程内调用，显示面就是外壳里的一个标签。
- 现有格子程序（`库/平铺桌面` 的格子、`库/用户态桌面`、`库/工作台`）改写成框架下的程序。格子之间共享的工作台状态拆开，各程序各管各的：编辑器管打开的文档，文件浏览管文件树，构建输出管构建，搜索管搜索。

### 4.4 程序拆分（议三）

- 可执行包放在 `豫言操作系统/应用/桌面程序/` 下：终端、文件浏览、任务管理器、设置、编辑、搜索、构建输出、差异、会话（包名实施时定）。每个包只有一个入口，调框架的独立跑法。
- 启动盘把它们编成豫行文件放进 `/程序/`（依赖 00007 续：编译器直出豫行）。
- 外壳：活动栏按钮与“打开”都启动程序；默认布局（左边文件浏览、右边编辑）在进桌面时启动这两个程序。找不到程序文件或宿主不支持直贴时，照旧嵌入运行。
- 裸机的外壳只链平铺、合成与框架，开机程序随之变小；浏览器与原生入口链进全部程序，以嵌入方式跑。

### 4.5 外壳请求与来信（议四、议五）

接口「豫言操作系统子程序显示」0.2.0：

```
「外壳请求」立「元类型」也。
  「外壳新开显示面」立化「字符串」而「外壳请求」也。
  「外壳打开文件」立化「字符串」而化「整数」而「外壳请求」也。
  「外壳运行程序」立化「字符串」而化（「列」于「字符串」）而「外壳请求」也。
  「外壳重读设置」立「外壳请求」也。
  「外壳结束程序」立化「整数」而「外壳请求」也。

「外壳来信」立「元类型」也。
  「来信新显示面」立化「整数」而化「字符串」而「外壳来信」也。
  「来信打开文件」立化「字符串」而化「整数」而「外壳来信」也。
```

- 程序一侧：「请外壳办」（请求）、「取外壳来信」。外壳一侧：「取外壳请求」（句柄）、「送程序来信」（句柄、来信）、「设子程序画面位置」（句柄、面号、屏幕矩形、可见）。取画面、送输入事件、设尺寸三个旧函数加面号参数，0.1.0 的写法指第一个面。
- 打开文件的路由：外壳按文件类型找程序（可执行文件新开外部程序格运行，其余交编辑器）；编辑器在运行就送来信，不在就先启动再送。
- 裸机经代办消息传递；原生 macOS 经事件管的反向通道；嵌入跑法里是进程内调用；诺节、浏览器的独立跑法返回五十八（暂不支持）。

### 4.6 出错与结束（议七）

- 外壳每轮查子程序状态（现有子程序接口）。程序结束（正常退出、陷阱、缺页、被结束）时，它的各个标签显示原因与退出码，下面是“重新运行”“关闭”两个按钮。
- 编辑器重新运行时，外壳把它出错前打开过的文件再送一遍；没存的改动随出错丢失（同今天整个桌面出错）。
- 结束程序：任务管理器经外壳请求请外壳结束；外壳只结束自己起的程序及其子孙。

### 4.7 任务管理器

每个程序都出现在系统任务里，处理器与内存读数来自内核服务 46。“桌面里的程序”一节（2026-10-11 加，16b952be1）只在嵌入跑法时有内容。

## 五、兼容与迁移

- 「豫言操作系统子程序显示」0.1.0 → 0.2.0：新增函数；旧函数加面号参数，0.1.0 的调用指第一个面。接口清单与各适配的 `宿主提供.json` 重生成。
- 没带这些程序的旧启动盘、浏览器、诺节与原生照旧嵌入运行。

## 六、备选方案

| 方案 | 结论 |
| --- | --- |
| 内核替初始任务把子任务画面合成进帧缓冲 | 不取。裁剪、弹出层与光标的规则写在执行器的底层豫言里更好改，内核只管块与映射 |
| 子程序直接写帧缓冲里自己那一格 | 不取。子程序会写坏外壳的边框与弹出层，出错时也收不回来 |
| 另设一套内核共享内存服务 | 不取。服务 55、56 已能把同一批物理块映给两个任务，林兼容的内存文件在用 |
| 每个打开的文件一个编辑器任务 | 不取。每个任务各带一份执行器与库，编辑器还带编译器核心，开十个文件就是十份；一个编辑器任务开多个显示面 |
| 外壳整个拆成独立程序 | 留待后续。显示与块设备只许初始任务用（00014 第九节） |

## 七、未决问题

1. 程序放 `/程序/` 还是 `/工具/`，默认 `/程序/`。
2. 双缓冲（子程序不等确认）值不值得：先用确认，量过再定。
3. 各程序常驻内存多大（编辑器带编译器核心最大）：实施时量，超出预期再做只读段共享。

## 八、实施步骤

1. 内核：核实服务 55、56 对初始任务可用（槽 0 的动态区、映物块的目序范围），缺的补上；裸机验证。
2. 执行器：共享显示面（子任务留块、取物理块号、提交只发区域）；初始任务映射与直接合成（画面位置、脏区、光标补画）；子任务结束时撤映射。QEMU 探针：两个子程序并排画动画，量帧延迟与初始任务的处理器占用，与 0.1.0 对比。
3. 接口 0.2.0：多显示面、外壳请求与来信、画面位置，裸机与 macOS 实现，诺节、浏览器返回五十八；接口清单重生成。
4. 库「桌面程序」：独立与嵌入两种跑法；外壳改为经框架托管程序；出错显示与重新运行。
5. 先拆没有跨程序状态的四个：终端、任务管理器、设置、文件浏览（打开文件先交外壳里的编辑格）；QEMU 验收。
6. 再拆编辑、搜索、构建输出、差异与会话：工作台状态按程序拆开，打开文件与跳转走外壳来信；裸机外壳不再链工作台与编译器核心，量开机程序体积与进桌面时间。
7. 启动盘带上全部程序；QEMU 与实机验收：多个程序并排使用，结束或弄崩其中一个时其余照常，任务管理器显示各程序的处理器与内存。
8. 文档：子程序显示规范、客体二号说明、《动态任务》、新库与平铺桌面、用户态桌面、工作台的包说明、提案 00014 的相关小节。

依赖：读盘缓存（2026-10-11 造盘时桌面卡死的修复；程序启动要从 U 盘读）；00007 续（启动盘由编译器直出豫行）。
