# 进程资源节点接线记录

节点工具进程桥保留真实系统进程号，资源动作返回五元组：状态、当前可用、当前常驻字节、操作系统峰值可用、峰值字节。结束的进程返回状态 0 与两项不可用，失效句柄返回 8。编译线程池任务没有独立进程号，返回 58。

`进程资源.cjs` 只负责 `node:ffi` 系统库接线，直接把共享 Wasm 的线性缓冲地址交给苹果 `proc_pid_rusage`；常驻数据的解释与低高字读取由共享豫言底层核心执行。查询失败返回 29，能力、模块缺失返回 58。真实节点采样入口需要主线程带 `--experimental-ffi`。林纳克斯与视窗接线留待后续。

具名子程序资源查询复用原生子程序服务。标准 JSON 动作“资源”返回整数状态与其余四个资源字段。应用宿主当前的标准异步进程查询返回 58，具名子程序查询转发服务结果。

仓库值桥目标用第四级编译器构建 `客体二号 进程资源共享`，写入宿主旁；工具链打包复制资源模块与胶水文件，并登记构建输入及输出。

本轮完成五个 JS 宿主文件的 `node --check` 与两个豫言文件的 `yy格式化 120`，差异检查通过。未启动重构建。共享核心导出契约与应用接口依赖由统筹合入后验证，真实苹果 FFI 采样与服务 JSON 硬验尚待安排。

## 共享内存导出诊断

首次苹果 Node 26.10.0 真实测试发现共享模块只导出采样、读取低字、读取高字，未导出内存，胶水读取缓冲时返回 29。共享入口需显式声明名为“内存”的内存导出，胶水直接取该导出并核对 WebAssembly.Memory。正式 `进程资源。测试.cjs` 检查此契约，再采样测试进程，断言状态 0、当前可用且字节大于零。
