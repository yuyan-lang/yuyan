## 二、动机

### 现在一个程序一个内核

- 00021 第 11 步以后，启动器把每项服务直接交给宿主后端，不再仿真初始任务；原生程序本来就直接调用宿主。每个程序各成一套，宿主上没有共享的任务表、消息与屏幕。「列出役」（列任务）在宿主上印“错误：本环境不能列出任务”（`库/诏令/实现。豫`），「截屏」「辟窗」（开窗口）「图形」（开桌面）也只能在豫言操作系统里用。
- 宿主上的平铺桌面把终端、任务管理器这些窗口放在自己的进程里显示（`豫言操作系统/应用/桌面程序/包说明.汉语.md`）；裸机上它们各是一个任务，经初始任务的子表收发外壳请求与外壳来信。两边的拓扑不同，代码路径也就不同。

### 裸机上的毛病在宿主上复现不了

- 2026-10-18 的任务管理器卡死：执行器的精确根漏了子表里的外壳请求队与外壳来信队（yybs 72b06af3f），开着任务管理器一两分钟，初始任务就陷阱退出，整机冻住。这段代码只在“桌面程序是独立任务”时运行，宿主上走不到；查它要造盘、上 QEMU，从监视器导出内存再反汇编。
- 初始任务里的桌面、合成、壳请求、子表与显示代办都是这样，只能在 QEMU 或实机上测。

### 程序之间看不见

- 宿主上的任务管理器看不到别的豫言程序，程序之间也没有消息可发。
- 代码共享由 00038 的单元仓库解决：单元按内容存一份、只读映射，程序不必同在一个进程里。缺的是一个容纳这些程序的系统。

### 前例

- **Inferno**：同一套系统既在裸机上运行，也作为一个宿主进程（emu）运行在林纳、林檎、轩窗（Windows）上；程序是同一份 Dis 码，每个进程有自己的命名空间，宿主文件经 `#U` 绑进命名空间。行在照这个做法。
- **User-Mode Linux**：内核是一个宿主进程，它的“物理内存”是一个宿主文件，各进程共享映射；宿主目录经 hostfs 挂进来。行在的物块文件照这个做法（4.5）。
- **WSL1**：每个发行版一个实例，有自己的 init，系统调用在进程内翻译，宿主盘挂在 /mnt/c。
- **Docker**（林檎上是 Docker Desktop）：每台机器一台 Linux 虚拟机，`-v "$PWD:$PWD" -w "$PWD"` 按原路径挂入当前目录。外形与行在相似，目的相反：Docker 把各容器隔开，行在把各程序合成一个系统。
- **Fuchsia**：每个组件的命名空间由授予它的能力拼成。附庸即案牍节，照这个做法。

## 三、目标与范围

目标：

- 林檎与林纳上，同一用户同时运行的豫言程序同属一个系统：同一张任务表、同一个屏幕与桌面、同一套壳请求；
- 初始任务、桌面与桌面程序的毛病在宿主上可以复现：同一批豫行文件，同一条代码路径；
- 程序缺省只看得到私有根与自己的当前目录，当前目录的路径与宿主相同；
- 数据面的速度不变：文件、网络与子程序照 00021 第 11 步在本进程办理。

不在范围：

- 轩窗：路径带盘符，做不到同路径附庸，留待后续版本（附在 /宿主/盘符/… 之下）；
- 宿主本机程序（vim、git 等）：用户 2026-10-16 定壳里不运行；
- 调度、内存管理、驱动与盘上 ext4 的复现：照旧用 QEMU 或实机；
- 硬件虚拟化：00021 议四。

## 四、设计

### 4.1 行在

- **是什么**：豫构的一个子命令（`豫构 行在 运行`，模块 `应用/豫构/行在。豫`），常驻做内核的共享部分：任务表与问答（第一步），私有根与附庸（第二步），共享块、屏幕与桌面（第三步）。桌面、合成与壳请求用开机程序里的同一份库（几席、九宫），裸机上由初始任务跑，宿主上由行在跑。
- **目录**：每个用户一个 `~/.豫言/行在/`（权限 0700）：
  - `根/`：私有根（4.4）；
  - `门。数据。豫`：端口、行在的进程号与启动时刻（数据子语言）；
  - `钥`：三十二个十六进制字符，权限 0600，连接都要出示它；
  - `物块`：共享块文件（4.5）。
- **起停**：`豫构 行在 运行|启动|重启|停止|状态`，用法照 `豫构 将作`；豫构交互会话找不到行在时在后台自动起一个（照将作，先脱离调用者的会话；Linux 上经 setsid）。没有任务、没有连接满三小时自动退出。壳里「息」（关机）结束行在里的全部任务后退出，「更始」（重启）重起行在，与裸机上的关机、重启同名同义（第三步）。
- **连接**：本机 TCP，与将作相同，端口缺省从 37431 起，被占就往后试；不新加套接字种类。执行器发二进制帧（见客体二号平台接口规范“行在门”），壳命令与 `豫构 行在 状态|停止` 发一行数据子语言。

### 4.2 加入与登记

- **加入**：宿主上的豫言程序起来时读门文件与钥、连上行在、发登记帧（钥、宿主进程号、程序路径），不等回答；连接一直开着，断开即注销。任务号就是宿主进程号，行在自己是零号（同裸机的初始任务）。
- **在哪里做**：执行器（客体二号）的新模块「行在门」，在启动一次里、原底初始化之后做，林檎与林纳都走它。常驻工作者、编译工作进程（`--mode=worker`）与启动器里的客体不加入（启动器自己加入）。起来时没有行在的程序，问任务、打断任务时再试一次加入；豫构交互会话自起行在后问一次任务表，借此补加入。
- **子程序**：父进程照今天在本进程起子进程，子程序自己登记；父子关系由行在拍任务表时问 ps 的父进程号得出，继承父方的附庸表见 4.4。
- **独行**：环境变量 `YY_行在=关` 时不找行在，照今天的方式运行：透明的宿主文件系统，没有任务表（「列出役」印“本环境不能列出任务”）。CI 环境（有 `CI` 环境变量）的会话不自起行在，起步与自举不受影响。

### 4.3 哪些服务交行在

服务号沿用 00021 第四节第 6、13 小节。

| 底层接口（文件、网络、进程、终端） | 110–169 | 本进程办理，路径按附庸表改写并限定（4.4） |

### 4.4 私有根与附庸

- **附庸**：一个任务的命名空间由附庸拼成，子程序继承。附庸有两种：
  - 同路径附庸：宿主路径原样出现在系统里；
  - 系统目录：汉字顶层目录对到某个宿主目录。
- **缺省附庸表**：

| 系统里的路径 | 宿主上的位置 | 读写 |
| --- | --- | --- |
| / | `~/.豫言/行在/根/`（影子根：预先建好通往各附庸的空目录） | 只读 |
| /系统、/数据、/软件 | `~/.豫言/行在/根/` 下的同名目录 | 读写 |
| /工具、/源 | 行在工具目录（4.6）与工具链旁的 `源/`（没有就在私有根下） | 只读 |
| 起程序时当前目录所在的仓库（同路径；往上找 `.git`，没有就是当前目录） | 同左 | 读写 |
| 共享构建缓存根（同路径；`YY_CACHE_DIR`，缺省 `/tmp/豫构缓存-<用户名>`） | 同左 | 读写 |
| `~/.豫构`、`~/.豫言`（同路径） | 同左 | 读写 |
| 豫构所在的工具链目录（同路径） | 同左 | 只读 |
| /bin /sbin /usr /etc /private/etc /System /Library /proc /opt（同路径） | 同左 | 只读 |
| /dev /tmp /private/tmp /var/folders /private/var/folders（同路径） | 同左 | 读写 |

- **不撞名**：豫言系统的顶层目录全是汉字（/系统 /数据 /软件 /工具 /源），宿主根下是英文（Users、Library、System、private、tmp 等）。同路径附庸以上的各级（如 /Users、/Users/zc）是影子根里的空目录，只含通往附庸的那一支。
- **符号链接**：林檎的 /tmp、/var 是 /private 下的符号链接，/tmp 与 /private/tmp、/var/folders 与 /private/var/folders 都按原路径附入；壳里的当前路径照宿主的 `$PWD` 写。附庸里的符号链接照宿主解析（待办事项：指到附庸以外的符号链接也打得开）。
- **实现**：执行器按附庸表把路径改写成宿主路径（最长前缀，一样长时可写的一行优先），再照旧相对宿主根句柄打开；路径里有“..”段的拒绝。附庸表就是环境变量 `YY_附庸` 的值，接在环境块末尾，子程序继承。现有的虚根（环境变量「豫言根目录」）是只有一行的附庸表，已并进来。豫构的将作与行在两个服务照宿主的命名空间运行。
- **更多附庸**：起程序时环境变量 `YY_附` 列出要附入的宿主路径（冒号分隔，同路径，读写）；`YY_全宿主` 把宿主根整个按同路径附进来（今天的透明方式），汉字顶层目录照旧来自私有根。两者都用环境变量，子程序随环境继承（第二版的 `--附`、`--全宿主` 命令行写法改为环境变量，免得每个程序各自解析）。
- **查询**：壳命令「附庸」印出本任务的附庸表（系统里的路径、宿主上的位置、读写）。运行中增减附庸留待后续版本。
- **与节的关系**：附庸是限定在子树上的案牍节。00038 第二步做节时，附庸表就是案牍节的那一部分，不另成一套。

### 4.5 共享块、显示与键鼠

- **桌面是屏幕的主人**：壳命令「图形」照开机壳写下 /系统/请求进入桌面；行在看到后在私有根里起行在工具目录里的本机图形桌面（环境变量 `YY_行在屏` 标明它是屏幕的主人）。这个桌面进程就是宿主上初始任务的那一侧：子表、外壳请求队与来信队、画面合成都在它里面，与裸机同一套代码与精确根。
- **物块文件（屏块）**：屏幕画面发布在 `~/.豫言/行在/物块`：64 字节的头（魔数、宽、高、帧号、主人进程号、注入写位）、+64 起的注入环、2 MiB 起的像素。桌面每次提交画面就写进去；任何任务的「截屏」读它写 PNG，「点击」「按键」等拟入写注入环，桌面取事件时先取注入环。读写一律用 pread、pwrite。
- **显示**：林檎上桌面是一个原生窗口（执行器现有的林檎窗口代码 `苹显示`）；林纳上无头运行，显示原语全走屏块，字体取系统里的思源字体。林纳的窗口留待后续版本。
- **键鼠**：桌面窗口的输入事件与注入环里的拟入一起，由桌面派给有焦点的程序。
- **桌面程序是独立任务**：九宫见到环境变量 `YY_桌面程序` 就照裸机把每个窗口起成桌面程序的进程，经管道代办（原语 182–185 的画面管与事件管）显示，外壳请求与来信也走这对管道；这些进程各自加入行在、登在任务表里。《桌面程序》包说明里“原生 macOS 上在本进程里显示”一句随之改写。
- **关机与重启**：「息」「更始」在宿主上问行在服务 241、242，行在结束全部任务后退出，更始再起一个新的行在。
- **设置**：「设分辨率」「设缩放」「设字样」作用于桌面的屏幕。
- **共享块**：服务 55、56（分块号、把物块的一段映射进动态区）留待后续版本，画面直接映射时再做；裸机上的桌面程序画面也是经消息整块拷给父程序。

### 4.6 同一批豫行文件

- **行在工具**：新的仓库目标「行在工具」照造盘编 /工具 的那一步，为本机架构编出开机程序与 /工具 里的各个豫行，产物与同架构启动盘上的逐字节相同。
- **配置**：私有根里的 `/系统/行在。数据。豫` 写「工具目录」「源码目录」两项宿主路径；缺省取装好的工具链目录旁的行在工具与 `源/`。开发时指向仓里新编的行在工具与仓库检出：改了源码，重编、重开窗口即生效，不必造盘。
- **一致性**：普通、交互、底层探针在行在里运行，输出与 QEMU 逐字相同。
- **仍然不同**：调度、内存管理、驱动、盘上的 ext4（私有根是宿主文件系统，林檎缺省不分大小写）、子任务的文件经初始任务代办的那条路（宿主上在本进程办理）、时序与多核。

### 4.7 壳命令

- 加入行在的会话照豫言操作系统登记做法（几席（桌面库）`库/几席` 的各命令模块），按部居（壳做法的分部表）装入。「列出役」「辍役」（结束任务及其子孙）「辍」（打断）「截屏」「辟窗」「图形」「击键」「移指」「点击」「滚轮」「息」「更始」在宿主上可用，与豫言操作系统里是同一份做法。
- 新命令两条：「行在态」印出行在的进程号、私有根、任务数、屏幕开着没有、运行了多久；「附庸」见 4.4。照 AGENTS.md，命令加在诏令（壳命令库），部与命令名登记在 `库/几席/部居。豫`，输入候选补进 `库/中书/令籍。豫`，`LOCALAGENTS.md` 第八节的对照表同步修改。

## 五、兼容与迁移

- **独行就是今天的行为**：CI、自举与没装行在工具的机器照常运行。
- **ABI 新增**（豫言内核 ABI，编号只增不改，00021 议八）：加入与登记的协议；服务 55、56 在行在里的语义（块在物块文件里）；宿主后端加“共享映射文件”一项（mmap），裸机不用。
- **两段合入**：新原语照 AGENTS.md“包与接口”，先合入执行器与启动器的支持，等连续版本换上新包，再在豫构与各工具里用。
- **文档**：《桌面程序》包说明、豫构包说明（`行在` 子命令与 `--独行`）、诏令包说明与 `LOCALAGENTS.md` 第八节随实施修改。
- **私有根**：第一次起来时建目录，不迁移任何宿主文件。

## 六、备选方案

1. **维持一个程序一个内核（现状）**：不取，见第二节。
2. **所有程序装进行在一个进程**（同进程封，Inferno emu 的做法）：不作第一步。裸机上程序各是一个任务，宿主上各是一个进程，两边同构；一个程序崩了不带垮系统；底层代码要硬件隔离。00038 第三步做同进程封时，裸机与行在一起做。
3. **一台硬件虚拟机跑整套系统**（Docker Desktop 的做法）：不取。要 HVF、KVM 这类条件（00021 议四），文件要经虚拟化转发，与宿主的集成差。
4. **当前目录附在 /宿主/<绝对路径> 或固定的 /工作 之下**：不取。路径与宿主不同，错误信息与参数里的宿主路径都要换算；汉字顶层目录与宿主不撞名，同路径更直接。轩窗例外（第三节）。
5. **私有根用 ext4 映像文件**（与裸机同一个驱动）：不作缺省。慢，在宿主上看不见；以后作选项，用来在宿主上测文件系统。
6. **每台机器一个行在**：不取。要处理跨用户的权限与隔离；每个用户一个就够。
7. **控制连接用本机域套接字并传文件描述符**：不作第一版。底层网络要新加套接字种类；本机 TCP 加钥与将作相同，共享内存用物块文件即可。

## 七、未决问题

1. 开机程序的豫行（以 `--开机程序` 编出）能否原样由启动器装入，还是行在要另编一份不带开机布局的。
2. 林檎上单元执行页的跨进程共享：MAP_JIT 的匿名页不能共享，用文件映射作执行页要带代码签名，要先实测（影响 00038 议六在林檎上的落法）。
3. 环境变量：HOME 等指向没有附庸的目录时程序读不到，要不要给每个任务在私有根里设一个家目录。
4. 运行中增减附庸的语义。
5. 行在要不要起远程登录（ssh 服务端），让宿主上的系统也能 ssh 进来。
6. 将作何时并进行在，作为一项系统服务。
