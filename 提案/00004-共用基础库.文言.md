| 项 | 文 |

| 状 | 草案 |

| 所及 | 新增纯豫言共用之基础诸库（压缩、图像编解码、统一码与编码之转、正则、密码、证书、安全传输、网络协议、字体整形、数据之式、归档、二维之绘等），置于 `库/` 下，依领域分组，以供操作系统、浏览器、桌面之应用、工具链与云端共用之；同类操作系统接口于原生与裸机之适配，改以此诸库为之；语言与编译器不易 |

此篇为豫言补其基础诸库之提案。常见之 Linux 发行版中，几一切程序皆间接依同一小群之基础库（zlib、libpng、libjpeg、ICU、PCRE2、OpenSSL、libcurl 等）。今以之为参照，先计豫言之所缺，后依用者之急缓，以纯豫言一一书之；实惟一份，于浏览器、诺节、原生与裸机同源可用。譬如图像解码之库书之一次，浏览器显网页之图、桌面预览之图、裸机观图之程序，皆用之。

与[汉语稿](00004-共用基础库.汉语.md)相应。

## 二、所以然

### 同一之能，或惟一宿主有之，或各书一份

2026-10-06 于 yybs（400b5ba35）检 `库/`、`应用/`、`豫言操作系统/` 与 `豫言操作系统接口/` 所得：

- `豫言操作系统接口/` 已有「压缩」「密码摘要」「口令派生」「文字规整」「网址」诸接口，其适配惟在云工或浏览器，皆转交宿主之 JS（DecompressionStream、Web Crypto、String 与 RegExp）；原生与裸机无其实。
- `库/云工宿主` 之压缩流、密码、编码与持久对象 SQL，皆云端平台之接口；`库/安全外壳/安全外壳密码` 之 SHA-256、X25519、Ed25519、AES-256-GCM 由宿主实之，诺节工具宿主用 `node:crypto`。
- `库/标准库/网络` 之 TCP 为宿主接口，其上有纯豫言 HTTP/1.1 报文之编解，不解分块之码；终端浏览器取网页，经宿主 HTTP(S) 请求之接口；诸平台皆无纯豫言之 TLS。
- 纯豫言之实散处诸方：终端浏览器有 ChaCha20、Poly1305、HKDF、SHA-256、HMAC，惟其自测用之，其中 SHA-256 与 ChaCha20 以 `0`/`1` 之串表比特，甚缓；深度学习之预分词，以“仓无正则之擎”，依码点手书 Qwen2 之正则，`\p{L}`、`\p{N}` 惟以近似之码段表判之；UTF-16 列号之换算，包配置之语言服务别书一份。
- 发布之器打包时，召系统之 zip、unzip 与 tar（`应用/发布/批量发布/发行材料。豫`）。
- 无图像之解码：终端浏览器之 `<img>` 惟显替代之文，仓中无 PNG 或 JPEG 之解码器。
- 无通用之正则：终端浏览器 JavaScript 之串法尚不受正则（见其包说明）。

### 用者待之

- 豫言操作系统：观图、解安装之包、验签、联网而下载。
- 浏览器：图、正则、HTTPS（今宿主代为之）、字体整形。
- 桌面之应用：图之预览、归档、数据之式。
- 工具链与包之管理：压缩、归档、验签。

### 与规矩合

AGENTS.md 既定诺节不引第三方之库，诸后端以“惟用豫言自有之库”而功能一致；共用基础诸库，乃此规得行之前提。

## 三、所求与所及

- 所求：第四节所缺清单之第一批，于浏览器、诺节、原生、裸机皆可用，附测试向量，各接其第一用者。
- 所及：纯计算之库（编解码、压缩、密码、解析、文字之处、二维光栅化）；与平台无涉之协议层（HTTP、TLS、DNS 之报文与状态机，读写经公共接口）；同类操作系统接口于原生与裸机之适配。
- 所不及（别立其目）：设备驱动与内核之 TCP/IP 协议栈；音视频之编解；完整之 JavaScript 引擎；与既有 C 库接口之兼容（惟求其能，不求同名同参）。

## 五、设计：共守之规

- **纯豫言，与宿主无涉**：惟依标准库与豫言自有之库；入出用字节串，文件与网络经公共接口读写；于浏览器、诺节、原生、裸机同源可用。
- **接口**：对外予“字节串入、结构之果出”之函，需则加流式之接口；名用中文；可复之数据之误以果值返之（循「压缩」接口状态码之例），参数违规则抛豫言之异常。
- **测试**：每库附公开之测试向量与对照之测，并注其源；解码与解析之器为模糊之测；速之基准，与同机系统之器相较。
- **速**：先书普通豫言，量之而后优之；热点可改为底层之式（无回收），或交原生工具链优之；密码之比较与标量之乘须恒时。
- **上限**：输入之长、解压之比、图像之尺寸、递归之深，皆设上限（宜大），逾之则明报其误。
- **组织**：于 `库/` 下依领域设父包（如「媒体」「密码学」「网络协议」「文字」），子包各自独立；依 AGENTS.md，于父包「包含包」登之，并书「包含在」。
- **第一用者**：每库入主线时，至少接一真实之用者，如 PNG 接桌面之文件预览与浏览器之 `<img>`。

## 六、兼容与迁

- 语言与编译器不易，惟增库。
- 迁：终端浏览器之密码诸模入「密码」，改以字节表之；深度学习之预分词改用「正则」与「统一码」；语言服务 UTF-16 之换算改用「编码转换」；发布之器之打包改用「归档」与「压缩」。
- 操作系统接口：「压缩」「密码摘要」「口令派生」「文字规整」「网址」之签不易；原生与裸机之适配以新库为之；云工与浏览器之适配姑留宿主之实，俟纯豫言之实量其速而后定（见未决之一）。
- 安全外壳密码：于原生与裸机，改由「密码」实之；诺节与云工亦改用「密码」否，与未决之一同定。

## 七、他途

- 以 zlib、libpng 等 C 库编为 Wasm 而包之：违“不引第三方之库”与“豫言书一切”，裸机又须别移，不取。
- 惟赖宿主之能（浏览器与云端之平台接口、诺节内置之模）：原生与裸机无之，诸后端功能不一，不取。
- 用时乃书：既见重复之实与手书之代（终端浏览器之密码、预分词之正则），故改为先计、统而谋之；然其施行，犹依用者之急缓分批。

## 八、未决

1. 宿主已有同等之能时（Web Crypto、DecompressionStream、`node:crypto`），云工、浏览器与诺节仍用宿主之实以求速乎（云工之 CPU 时有限），抑一律改用纯豫言乎。
2. TLS 惟为 1.3 乎，抑兼为 1.2 以容旧站。
3. 根证书之库何所取、何以更（如随发行附 Mozilla 之根证书一份，其许可与更新之程）。
4. 正则之文法：容 ECMAScript 乎（浏览器之 JavaScript 需之），抑取 RE2 或 PCRE 之子集；反向引用之类须回溯之性，为之否。
5. 父包之分组与包名。
6. 速之目标，如解压较系统 gzip 缓几何以内可受。

## 九、施行之序

1. **计**：本第四节逐项复核仓之今（含诸宿主接口与适配已有之能），补全清单与用者，书回本提案，定第一批。
2. **第一批**：压缩（DEFLATE、zlib、gzip）→ 图像编解码（PNG，依压缩；次 JPEG、GIF、BMP）→ 统一码与编码转换 → 正则 → 密码（迁入既有之实而补之）。
3. **第二批**：证书与 TLS 1.3 之客户端、HTTP/1.1 之客户端与 URL、DNS 之报文、归档、XML、二维绘图与 SVG 之子集、字体整形。
4. **第三批**：嵌入数据库、时间与时区。
5. 每库：先书最小集与测试向量，验于诺节与原生，次验于裸机；接其第一用者而后入主线。
6. 一代理任之至终，可遣子代理分库并行，各用其工作树；每成一库，登于本提案末之进度表。
