本文只写现代汉语（AGENTS.md）。

用户的想法（2026-10-20，原话为英文，此处译述）：窗口要有工作区。一个窗口可以弹出去，成为一个新的工作区，即另一块面板；这牵涉多显示器；在宿主上的系统实例里，新工作区就是一个新的宿主窗口，图形程序因此接近原生窗口。移出去的窗口可以移回原来的工作区；任何窗口都可以在它的工作区里再开别的窗口。

## 一、拟定事项

- **议一：室。** 工作区叫“室”，取《老子》“凿户牖以为室，当其无，有室之用”：开了户牖才成室，窗口所在即是室。一间室是一棵分割树（00014）连同它的焦点组与单格全屏。桌面上至少有室一（主室），别的室空了即撤。格子表仍是整个桌面一份：窗口在室间移动只改它挂在哪棵树上，程序不重起，任务号不变。
- **议二：徙与归。** 「徙窗」把一个窗口移进另一间室，不给室就新开一间，这就是“弹出”。窗口第一次被徙出时记下故室与故组，归回后清掉，中途再徙也不改。「归窗」把窗口送回故室的故组；故组没了放进故室的焦点组，故室没了放进室一。
- **议三：新窗口生在发起者的室里。** 从某个窗口开出来的窗口（终端里的「辟窗」，文件浏览的运行与打开，编辑格的右侧打开，桌面程序的外壳请求，启动台开的程序）放进发起窗口所在的室；没有发起窗口时（开机壳、远程登录）放进今室，即最近收到输入的室。「辟窗」可以用「室」指定。
- **议四：室显示在显示面上。** 宿主能开窗口的（林檎上的行在与原生桌面、浏览器），每间室取一块自己的显示面，也就是一个宿主窗口，可以拖到任何一块屏上，像素比随所在的屏变。取不到显示面的（裸机、林纳（Linux）无头、浏览器小窗被拦），室与主屏共用一块显示面，主屏同一时刻显示一间，用「入室」切换，同 i3 的工作区。
- **议五：显示接口 0.10.0 加两个函数。** 「待诸面入事限时」在一组显示面上同时等输入事件，交回事件所在的面；「题映面」设显示面的标题，即宿主窗口的标题栏。
- **议六：多面会话。** 器物与门面加多面会话：一个应用状态，每块显示面各有自己的视图、控件状态、画布与增量绘制记录，一处等待。九宫以它运行。

## 二、动机

1. 林檎上行在的桌面是一个原生窗口（00039），程序再多也挤在这一个窗口里，不能各自拖到另一块屏，也用不上系统的窗口切换。图形软件（00046）要像原生程序那样各占一个窗口。让桌面把窗口放进别的宿主窗口最省事；若让每个程序自己去开原生窗口，裸机上没有对应的东西，程序就分成了宿主版与系统版，窗口也回不到桌面里。
2. 单屏平铺满了要有地方放别的事。i3、sway、niri、macOS 的空间、Windows 的虚拟桌面都用工作区。
3. 底下的能力大半现成：林檎显示后端已支持多块显示面（每面一个 NSWindow，至多八面，各面的事件同在一队、各取各的）；浏览器的显示面就是带名字的画布；子程序显示代办（00014、00015）在格子变大小、变像素比时会重设程序的显示面。缺的是桌面这一层。

## 三、目标与范围

本提案做：九宫的室与徙、归；五条壳命令（含查询）与对应的图形入口；显示接口 0.10.0；多面会话；林檎显示后端、浏览器宿主与行在的显示面授权。

后续版本的事项：

- 裸机多显示器：驱动能出多路画面时（如 virtio-gpu 的多路扫描输出、威睿的多屏），每路授成一块固定显示面（“屏二”“屏三”……），各显示一间室，室比屏多时多出来的共用主屏。
- 跨室拖标签（从一个宿主窗口拖进另一个）。
- 新室的宿主窗口按原格子的大小与位置开出（第一版取授权里的缺省尺寸）；「入室」把有自己窗口的室提到前面（显示接口要加“请上前”）。
- 程序自己要第二块显示面时（子程序显示的多面代办），开成同一间室里的新窗口。
- 豫言系统里的行在（00042）把它的室开成外层桌面的窗口。
- 布局连同各室存盘、开机恢复。

## 四、设计

### 4.1 九宫的室（议一至三）

- 外壳状态加「室们」（每间室：室号、分割树、焦点组、上次焦点组、单格全屏、视图宽高与像素比、分割条与标签的拖动态、显示面名）、「今室」与「屏室」（主屏现在显示的室）。格子表、下一号、工作台状态与设置仍是全局一份。新室取二起最小的空号。故处另存一张表（格号到故室、故组），格子类型不改。
- 现有的更新与视图都按“一棵树”写，不改：处理某间室的消息、画某间室的视图之前，把那间室投影成现有的外壳状态字段，办完写回（同书斋格（编辑格）把共享的工作台状态投影成本格路径）。各室视图发出的消息包一层「室内信」（室号、外壳信）。
- 主屏（显示面“主窗口”）照旧画活动栏与状态栏，中间是它现在显示的室；状态栏列出各室，点共用主屏的室即「入室」。有自己宿主窗口的室只画标签栏与各组，看去接近原生窗口；在这种室里开别的窗口用拆分钮、快捷键、终端里的「辟窗」或启动台（议三）。
- 非主室的最后一个窗口关掉或徙走，室即撤，它的显示面归还，宿主窗口随之关闭。主室空了照旧画题壁（桌面壁纸）。
- 窗口进了大小不同的格子，外部程序格与桌面程序格照现有的办法重设子程序显示面的尺寸与像素比，程序只收到一次尺寸变化。任务管理器的窗口列表（「诸桌面程序」）加室号。

### 4.2 命令（议二、三；AGENTS.md「图形程序」）

| 命令 | 作用 |
| --- | --- |
| 「徙窗」于「号」曰「三」于「室」曰「二」 | 窗口三移进室二。省「室」即新开一室；省「号」即发起者自己的窗口（桌面终端里就是这个终端），没有发起窗口时取今室的焦点窗口 |
| 「归窗」于「号」曰「三」 | 窗口三回故室；改给「室」时，那间室里的窗口全部回去 |
| 「辟窗」于「种类」曰『终端』于「室」曰「二」 | 现有命令加可省的「室」（00019），省了照议三定 |
| 「入室」于「室」曰「二」 | 主屏换成显示室二（室二共用主屏时）；室二有自己的宿主窗口时印一行说明 |
| 「窗列」 | 查询：每间室一段（室号、显示在哪块显示面或“共用主屏”、窗口数），每个窗口一行（号、种类、标题、任务号、故室） |

- 照「辟窗」的路走：命令在几席（壳库）的壳索（壳请求）里把请求写进 /系统 下的请求文件（记录写成 。数据。豫，「辟窗」现在的纯文字请求一并改成记录），九宫每轮取走办理。「窗列」读九宫每次布局变动后写下的快照 /系统/桌面窗列。数据。豫。新命令登进部居（命令分部）的「图形」一部，令籍（输入候选表）补上候选；开机壳、桌面终端、远程登录与行在会话都能下。
- 发起者：九宫起终端（嵌入的与桌面程序的）时在环境里放「豫言窗号」，终端的壳会话继承它，请求里带上；九宫据此找发起者的室。桌面程序的外壳请求本来就知道是哪个格子发的。
- 图形入口：标签栏加“出”钮（徙窗，新开一室）；非主室的标签栏加“归”钮；快捷键交替加 O 徙窗、交替加上档加 O 归窗、交替加控制加一至九入室、交替加上档加一至九把当前窗口徙进那间室。关掉一间室的宿主窗口等于「归窗」于那间室：窗口回去，没存的编辑照旧在。

### 4.3 显示面（议四、五）

| 宿主 | 主室 | 别的室 |
| --- | --- | --- |
| 林檎上的行在与原生桌面 | 显示面“主窗口” | 显示面“室二”“室三”……，每面一个 NSWindow。授权写法新增前缀：`--授权显示面 室*=960x640` 授权以“室”起头的全部名字，行在起桌面时加上；「苹显面数」八放大到六十四 |
| 浏览器（网页行在） | 页面里的“主窗口”画布 | 取“室N”时宿主 `window.open` 一个同源小窗，把带 `data-yy-显示面="室N"` 的画布放进去；小窗被拦返回资源暂不可用，小窗关掉即显示面已关闭 |
| 裸机、林纳无头（屏块） | 帧缓冲或屏块 | 取不到，共用主屏 |

- 「待诸面入事限时」于「面们」于「毫秒」：同「待入事限时」，只是等一组显示面，交回（面序、事件）。林檎后端各面的事件本在一队，浏览器各画布的事件也进同一个队列，都只改取法。只有一块面的宿主（裸机、林纳无头、诺驿（Node））可以返回暂不支持，多面会话退回各面轮流限时等待。
- 「题映面」于「面」于「题」：设宿主窗口的标题，只是提示，做不到照常返回（裸机与屏块不理会）。九宫把每间室的标题设成它焦点窗口的标题。
- 声明变了，照 AGENTS.md 重生成接口清单与各适配的 宿主提供。数据。豫。

### 4.4 多面会话（议六）

- 器物把「行映控件计时保位缩放会话」里属于一块显示面的东西（显示面、控件状态、保位存、画布缓存、增量绘制记录、光标闪烁）收成一个“面局”；现有的单面会话成为只有一个面局的多面会话，签名不变。
- 多面会话的参数是应用状态到「列」于（面名、标题、视图）的函数：列里多了名字就取显示面、开一个面局，少了就归还。取不到时把「映面未得」于面名交给更新；显示面被用户关掉时交「映面已闭」于面名。计时与提前醒对整个应用一份；每次更新之后只重画状态变了的面。
- 门面的「行门面尺寸比计时保位会话」同样加多面版。九宫的「行平铺桌面」改用它：主屏一个面局，每间有自己显示面的室一个面局。收到「映面未得」就把那间室改成共用主屏，收到「映面已闭」就「归窗」于那间室。

## 五、兼容与迁移

- 只有一间室时，外观、快捷键与命令都与现在相同；现有的单面会话签名不变。
- 「辟窗」加的是可省参数，旧调用照旧。
- 显示接口 0.10.0 只增不改；不支持的宿主照旧运行，室共用主屏。
- 行在多授权了室的前缀；不取这些名字的程序不受影响。

## 六、备选方案

1. **每个程序直接开自己的原生窗口，不经桌面**：最像原生，但裸机与浏览器没有对应的东西，程序要有两种跑法，窗口也回不到桌面里。不取。
2. **每间室一个九宫进程**：徙窗要把运行中的程序连同画面管道交给另一个进程。不取。
3. **室只做虚拟桌面，不开宿主窗口**：省掉显示接口与会话的改动，但得不到接近原生的窗口。作为取不到显示面时的退路保留。
4. **用轮询代替「待诸面入事限时」**：每多一间室就多一路空转等待。作为宿主不支持时的退路保留。

## 七、未决问题

- 浏览器的 `window.open` 要用户手势：从点“出”钮到真正取显示面要经过一轮 Wasm 更新，超过手势的时效会被拦，被拦就共用主屏。实施时量。
- 主窗口关掉时整个桌面退出（现状）；要不要改成先把别的室收回主屏，待定。
