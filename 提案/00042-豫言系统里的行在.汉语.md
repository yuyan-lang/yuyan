## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | **豫言系统作行在的第三种宿主**：同一份 `豫构 行在`（豫构即构建工具，系统里是 `/工具/豫构。豫行 行在 运行`）在豫言系统里起一个嵌套的系统实例。外层的内核与初始任务照常运行；实例里跑的是同一批豫行（豫言可执行文件），走同一条代码路径 |
| 议二 | **按名起多个**：实例目录是 `/数据/行在/<名>/`；程序加入哪个实例，由环境变量 `豫言行在目录` 决定，子程序随环境继承。不设时，宿主上照旧是 `~/.豫言/行在`，豫言系统上不加入，同今天 |
| 议三 | **执行器在豫言目标上也开行在门、附庸与屏主**：连本机环回 TCP；本进程号取本任务的内核句柄；附庸照宿主的做法改写路径原语里的路径 |
| 议四 | **任务表问内核**：行在在豫言系统上不问 `ps`，改问服务 46；实例里的「列出役」「辍役」「辍」只管登记在实例里的任务 |
| 议五 | **屏块放共享块**：实例的桌面无头运行（同林纳），屏块（00039 4.5 的头、拟入环与像素）放在服务 55 要来的物理块里，块号写进实例目录；看屏与拟入的一方用服务 56 映同一批块，不写盘 |
| 议六 | **观行在窗口**：外层桌面里一个桌面程序窗口，按帧序读屏块画出实例的屏幕，把窗口里的键鼠写进拟入环 |
| 议七 | **命令先行**：「诣行在」开一个加入实例的壳会话（实例没起就先起）；「观行在」在外层桌面开它的窗口；实例会话里的「图形」「截屏」「息」等作用于实例 |
| 议八 | **分四步实施**：起得来与任务表；附庸；无头桌面与屏块；观行在窗口 |

## 二、动机

- **测新版不必重启**：开机程序、桌面、桌面程序与 /工具 的新版，今天要么在宿主的行在里测（执行器与回收按宿主配置），要么造盘重启或「葺寓」（系统升级）。在运行着的豫言系统里起一个实例，把实例的工具目录指到新编的工具，就能试；实机（如 pit-mbp13）ssh 进去就能做，外层不受影响。
- **初始任务一侧的毛病在宿主上复现不了**：子表、外壳请求与来信、合成这些代码，裸机上在初始任务里跑。2026-10-18 的任务管理器卡死（72b06af3f），在宿主的行在里撤回修复连跑十四分钟也没复现（00039 实施记录第三步）：宿主的回收节奏与内存复用和裸机不同。实例的桌面是裸机上的一个普通任务，用裸机的执行器与回收，跑同一份子表与合成代码；坏了只坏这个实例，外层照常能看「起居」（内核日志）、截屏、列任务。
- **今天做不到**：执行器（客体二号）的行在门、附庸与屏主只在林檎（macOS）、林纳（Linux）原生上开（`豫言操作系统/裸机/客体二号/行在门。底层。豫`、`附庸。底层。豫`、`屏块。底层。豫`）；豫言系统里 `豫构 行在 状态` 印“这里就是豫言操作系统本身，没有行在。”

## 三、目标与范围

目标：

- 豫言系统里能起一个或几个行在实例，各有任务表、私有根与桌面；
- 实例里的程序只看得到实例的私有根与附庸；
- 外层桌面里有窗口看实例的屏幕、操作它的键鼠；没有外层桌面时（ssh 进来），实例会话里「截屏」照样取得到实例的画面；
- 每个操作都有壳命令。

不在范围：

- 内核、调度、内存管理、驱动、盘上的扩展文件系统四：实例共用外层的内核，这些照旧用 QEMU 或实机测；
- 硬件虚拟化：见备选方案第 1 条；
- 强制隔离：附庸由执行器改写路径，实例里的底层代码仍能绕开；强制把关等 00038 的节（能力，#121）。节做好以后附庸就是案牍节的一部分（00039 4.4），本提案不另做一套。

## 四、设计

### 4.1 实例目录

| 文件 | 内容 |
| --- | --- |
| `/数据/行在/<名>/门。数据。豫` | 端口、实例行在的任务句柄、启动时刻（同 00039 4.1） |
| `/数据/行在/<名>/钥` | 三十二个十六进制字符 |
| `/数据/行在/<名>/根/` | 私有根，布局同 00039 4.4 |
| `/数据/行在/<名>/屏块。数据。豫` | 屏块的物理块号、宽、高（4.5） |

实例的工具目录与源码目录照 00039 4.6，写在私有根的 `/系统/行在。数据。豫` 里，缺省取外层的 /工具 与 /源。测新版时改成新编工具所在的目录。

### 4.2 加入与任务表

- **行在服务**：`豫构 行在 运行|启动|停止|状态` 在豫言系统上照 `豫言行在目录` 找实例目录（没设时报错，不起），端口、门与钥写进去。监听 127.0.0.1：裸机网络栈有环回队列（`客体二号/网络栈。底层。豫`），子任务的 TCP 原语经底层转送由初始任务的网络栈办理（`客体二号/裸机传输控制。底层。豫`）。
- **拍任务表**：问服务 46 取父任务、滴答与常驻块，代替宿主上的 `ps`；记录格式本来就同服务 46。打断与结束问内核，代替宿主上的 SIGINT、SIGKILL。
- **加入**：执行器的行在门在豫言目标上，环境变量 `豫言行在目录` 有值才加入，照它读门与钥；本进程号取本任务的内核句柄（今天裸机上为零；内核没有现成的服务就补一个）。实例的行在自己不加入。
- 实例里的「列出役」照 00039 走行在任务列表，只列实例的任务；外层的「列出役」照旧列全机，实例的任务也在里面。

### 4.3 附庸

- 子任务的路径原语与原生是同一份代码，只有底层调用经底层转送交初始任务（客体二号说明“底层转送”），附庸的改写照搬：
  - 「/」对到实例私有根（只读的影子根）；
  - /系统、/数据、/软件 对到私有根下同名目录（可写）；
  - /工具、/源 对到实例配置的工具与源码目录（只读）；
  - 起实例时的当前目录按原路径附入（可写）。
- 外层的 /数据 等不附入；要附更多，照 00039 用环境变量 `豫言附`。

### 4.4 无头桌面

- 实例会话里的「图形」照旧在私有根写下 /系统/请求进入桌面；实例的行在起工具目录里的图形桌面，环境带 `豫言行在屏`，与 00039 4.5 相同。
- 豫言系统上的屏主无头：显示原语全走屏块，同林纳；字体用系统的字体表。
- 图形桌面今天只为宿主编：仓库目标「行在工具」加豫言目标，造盘把图形桌面放进 /工具。
- 实例里窗口（桌面程序）的显示：裸机上子程序显示的父方须是初始任务（客体二号说明“子程序显示”），实例的桌面不是。做法见未决问题第 1 条。

### 4.5 屏块放共享块

- 屏主起来时按尺寸用服务 55 要物理块：头与拟入环一块，像素按宽×高×4 字节取整块（1280×800 要两块，共三块）；块号、宽、高写进实例目录的 `屏块。数据。豫`。头、拟入环与像素的布局同 00039 4.5。
- 实例里任务的「截屏」与拟入、外层的观行在窗口，都用服务 56 把这些块映进自己的动态区读写。
- 服务 56 要求块正被某个任务当共享块映着：屏主退出时删去 `屏块。数据。豫`，块随之作废。

### 4.6 观行在窗口

- 桌面程序新种类「行在」：读实例目录的 `屏块。数据。豫`，映块；每帧比帧序，有变就把像素按窗口大小画进画布（最近邻缩放）；窗口里的键鼠换算坐标后写进拟入环。
- 实例没开桌面时，窗口里印一行提示。

### 4.7 壳命令

| 命令 | 做什么 |
| --- | --- |
| `「诣行在」于「名」曰『甲』` | 实例甲没起就起，再在当前终端开一个加入它的壳会话（如 `docker exec -it`）；会话里「辞」回到外层 |
| `「观行在」于「名」曰『甲』` | ★ 在外层桌面开实例甲的观行在窗口 |
| `「行在态」` | 在实例会话里印实例的状态；在外层印各实例的名、任务数、屏幕开着没有 |
| 「图形」「截屏」「击键」「点击」「列出役」「辍役」「辍」「息」「更始」 | 在实例会话里作用于实例，同 00039 4.7；「息」结束实例的全部任务、退出实例的行在 |

照 AGENTS.md，命令加在诏令（壳命令库），部与命令名登记在 `库/几席/部居。豫`，输入候选补进 `库/中书/令籍。豫`，`LOCALAGENTS.md` 第八节对照表同步修改。

### 4.8 拟名

| 通称 | 雅名 | 由来 |
| --- | --- | --- |
| 进入嵌套系统实例（壳命令） | 诣行在 | 《史记·卫将军骠骑列传》“遂独遣浑邪王乘传先诣行在所”：诣，往见；臣下往天子所在之处。会话加入实例，就是诣行在 |
| 看嵌套实例的屏幕（壳命令、窗口种类） | 观行在 | 合成词，古书无成例；“观”同观屏原语 |
| 实例目录（环境变量） | 豫言行在目录 | 照 AGENTS.md 环境变量的取名 |

《史记》原句已在殆知阁语料里核过（卷一百一十一）。仓里目前没有「诣行在」「观行在」这两个名字。

## 五、兼容与迁移

- 不设 `豫言行在目录` 时，豫言系统照今天运行，宿主上照 00039 运行。
- ABI：行在门协议不变；豫言目标上新加取本任务句柄（内核没有现成的服务时）。
- 新原语照 AGENTS.md“包与接口”两段合入：先合入执行器的支持，等连续版本换上新工具链包，再在豫构与诏令里用。
- 文档：00039 与客体二号的说明、诏令包说明、`LOCALAGENTS.md` 第八节随实施修改。

## 六、备选方案

1. **硬件虚拟机套整个系统**：复用 00012 林客体的 VMX/EPT（`豫言操作系统/裸机/林虚拟化运行。豫`），引导一个豫言内核。能测内核本身，但只有英特尔 AMD64、单核、客体只有串口；还要补虚拟盘、显示与网卡，ARM64 要另做 EL2；用户 2026-10-14 定暂不管林虚拟机。不取。
2. **桌面套桌面**：实例的桌面作外层的一个桌面程序，画面经子程序显示交外层。要把子程序显示的父方从初始任务放宽到任意任务，任务表与附庸照样得做；屏块加观行在窗口与宿主同一套格式，实例与外层互不牵连。不取。
3. **屏块用文件**（同宿主）：每帧写盘，还要经初始任务代办，慢。不取。
4. **等节（#121）做完再做**：附庸今天由执行器改写，宿主上已经在用；节做好以后附庸就是案牍节，不另成一套。不等。

## 七、未决问题

1. 实例里窗口的显示走哪条路：
   - 甲：把裸机子程序显示的父方放宽到任意任务：子任务的显示请求发给父任务而不是句柄 0，父方读写子任务内存（服务 41、42）要内核放行；
   - 乙：裸机上也走管道代办（同林檎、林纳）：画面管与事件管经底层转送。
   倾向乙：协议现成，宿主上已经在用。
2. 实例里任务的「起居」：内核日志是全机的，要不要只列实例任务的条目。
3. 实例用的内存与处理器没有配额。
4. 实例里再起实例（套三层）：行在门只认一个 `豫言行在目录`，按理可行，不专门做。

## 八、实施步骤

1. **起得来与任务表**：`豫构 行在` 在豫言系统上运行（实例目录、环回端口、服务 46 拍表）；行在门在豫言目标上按 `豫言行在目录` 加入；「诣行在」与「行在态」。验收（QEMU，pit-pc-ubuntu-wired）：
   - ssh 进系统，`「诣行在」于「名」曰『甲』` 开出实例会话，会话里「列出役」只列实例的行在、本会话与会话起的程序；
   - 「辍役」结束实例里的任务；
   - 「辞」回到外层，外层「列出役」照常。
2. **附庸**。验收：
   - 实例会话里 `「案牍」之「列目」于『/』` 只见汉字顶层目录与附入的目录；
   - 写 /工具 报越出授权，外层 /数据 下别的目录看不到。
3. **无头桌面与屏块**：「行在工具」加豫言目标、造盘带图形桌面、屏块放共享块、窗口显示（未决问题第 1 条）。验收：
   - 实例会话里「图形」后「截屏」写出实例桌面的 PNG；
   - 「辟窗」开出的任务管理器所列任务与「列出役」相同。
4. **观行在窗口**。验收：
   - 外层桌面 `「观行在」于「名」曰『甲』` 开出窗口，看得到实例的桌面；
   - 在窗口里点击、键入作用于实例，外层「截屏」核对。
