## 读法

- 示例按 yy格式化 的排版写：每层缩进一个全角空格，列表逗号在行首，数字用中文数字（「一九二零」是 1920，「一点五」是 1.5，「负四零零」是 −400）。
- 真实源文件的注释要写成汉语、文言双语（AGENTS.md）；示例里只在第一节写全，其余为节省篇幅从略。
- 构造写法 `「头」【项，…】` 的三种项（00018 议十九）：
  - **命名项** `「名」者 值 也`：构造的属性，对应头函数的带标签参数 `于「名」为 值`，名称与类型按参数检查；签名里是「可化」的参数（提案 00019）可以不写，取定义里「默认」给的值；
  - **字符串项** `『…』`（或类型为「字符串」的表达式）：子项类型是「字符串」时直接放入；子项类型是和类型且恰有一个只收字符串的构造器时，用它包一层（例如「段」的「文字片」）；其余情况报错；
  - **子项**：其余的项，按构造函数「子项」参数的元素类型检查，可以是别的构造、组件调用、变量。
- 构造写法不改语法分析器：阐述时保留构造节点；名称解析按普通名字找头（一个函数）；类型检查按“构造调用约定”逐项检查，然后降为普通调用（2.4）。
- 属性类型是「信号 于 甲」时，写常量甲即可，类型检查自动提升为常量信号；写关键帧、表达式就是动画。

## 一、文件与作品

### 1.1 最小的作品

一个设计源文件就是一个模块。名为「作品」的顶层绑定是作品的入口（普通程序的入口是「入口」）。

```
寻观「设计」之书。

「：汉语：最小的视频：纸色底上一行字，持续三秒。
　　文言：最小之影：纸色之底一行字，历三秒。：」
「作品」者
　「视频」
　【「画幅」者（「尺寸」于「一九二零」于「一零八零」）也
　，「时长」者（「秒」于「三」）也
　，「画面」【「文字」【「位置」者（「点」于「九六零」于「五四零」）也，『你好，设计语言』】】
　】
也。
```

- 「视频」是作品构造：属性「画幅」「时长」，子项是各条轨，「画面」是画面轨。
- 「秒」是表达式层的函数，顶层在编译期求值（00018 第五节“编译期常量折叠”），结果是整数刻（一秒 705600000 刻）。
- 编译：`豫构 设计 编译 你好。设计。豫 --输出 你好。设计`；播放：壳命令 「播放」于「文件」为『你好。设计』。

### 1.2 作品构造与目标

作品构造的名字就是格里的常用点，「视频」默认目标是“视频”。用「目标」可以把检查收得更紧：

```
「作品」者
　「视频」
　【「目标」者「动态图形」也
　，「画幅」者（「尺寸」于「一九二零」于「一零八零」）也
　，「时长」者（「秒」于「六」）也
　，「画面」【「片头画面」】
　，「声轨」【「采样」【「素材」者「片头音乐」也】】
　】
也。
```

用了“动态图形”之外的能力（例如三维物体、离线程序），类型检查报错，见 14.2。

### 1.3 素材

素材绑定写文件路径（相对源文件），编译时整份嵌进素材块，按内容散列寻址：

```
「宋体」者「字体素材」【「文件」者『字体/思源宋体.otf』也，「子集」者「按用到的字」也】也。
「片头音乐」者「音频素材」【「文件」者『声音/片头.opus』也】也。
「封面图」者「图像素材」【「文件」者『图/封面.png』也】也。
「茶壶」者「网格素材」【「文件」者『模型/茶壶.glb』也】也。
「街景」者「视频素材」【「文件」者『实拍/街景.av1』也】也。
```

- 字体按用到的字自动取子集；同一子集在多个作品里只下载一次。
- 素材的解码尺寸写进素材块头，加载时比对宿主预算。

### 1.4 模块与导入

组件、样式、片段可以放在别的设计源文件里，按普通豫言的规则导入：

```
寻观「设计」之书。
寻观「我的片头」之「样式」之书。
寻观「我的片头」之「组件」之书。
```

设计源文件只能导入能力不高于自己的模块（00018 第四节）：一个声明为“图标”的模块导入了带声音的片段，类型检查报错。

## 二、构造写法总则

### 2.1 三种项

```
「文字」
【「样式」者「大标题」也
，「颜色」者「朱色」也
，『设计语言』
】
```

「样式」「颜色」是属性；『设计语言』是字符串项，「文字」的声明接受字符串项，作为正文。

```
「组」
【「位置」者（「点」于「一零零」于「一零零」）也
，「矩形」【「宽」者「二零零」也，「高」者「一二零」也，「填充」者「纸色」也】
，「文字」【『标签』】
】
```

「组」的子项是场景节点；字符串项「组」不接受，写了报错。

### 2.2 名称解析的报错

```
「园」【「半径」者「五零」也】
```

```
错误：未定义的构造「园」（片头。设计。豫 第 12 行第 3 列）。
　　作用域里相近的构造：圆、团块。
```

构造名与函数名、类型名一样在作用域里找；没导入「设计」时，「圆」也是未定义的构造。

### 2.3 类型检查的报错

```
「圆」【「半经」者「五零」也，「填充」者『红色』也】
```

```
错误：构造「圆」没有属性「半经」（第 14 行）。可用的属性：圆心、半径、填充、描边、不透明度、名。
错误：构造「圆」的属性「填充」要求「颜料」，写的是「字符串」（第 14 行）。
错误：构造「圆」缺少必填属性「半径」（第 14 行）。
```

### 2.4 构造调用约定（库作者写）

构造不需要专门的声明语法，语法分析器也不改。头是一个普通函数，参数合乎约定就能用构造写法调用：

- 命名项 `「名」者 值 也` 对应带标签参数 `于「名」为 值`。可省的属性在签名里写「可化」，默认值写在定义里（提案 00019《可省参数》）；其余带标签参数必填。
- 字符串项与其余子项依次放进带标签参数「子项」（列）；元素类型甲决定子项怎么检查，也决定字符串项怎么处理（见“读法”）。没有「子项」参数的构造不接受子项。
- 头的参数都要带标签；有不带标签的参数，就不能用构造写法调用。
- 类型检查通过后，`「圆」【「半径」者「五零」也】` 降为普通调用 `「圆」于「圆心」为（「常量信号」于「原点」）于「半径」为（「常量信号」于「五零」）于「填充」为（「常量信号」于「透明」）…`：常量「五零」提升为常量信号，省掉的属性补上默认值。
- 构造调用就是当场调用，合乎 00019“带可省参数的函数只能当场调用”。同一个函数也能用普通调用写法 `（「圆」于「半径」为（「常量信号」于「五零」））`，省参数的规则相同；常量自动提升只在构造写法里。

只有属性的构造——「圆」：

```
「圆」乃
　可化「圆心」为（「信号」于「点」）而
　化「半径」为（「信号」于「长度」）而
　可化「填充」为（「信号」于「颜料」）而
　可化「描边」为「描边样式」而
　可化「不透明度」为（「信号」于「小数」）而
　可化「名」为「字符串」而
　「场景节点」
也。
「圆」者
　会「圆心」为「圆心」默认（「常量信号」于「原点」）而
　会「半径」为「半径」而
　会「填充」为「填充」默认（「常量信号」于「透明」）而
　会「描边」为「描边」默认「无描边」而
　会「不透明度」为「不透明度」默认（「常量信号」于「一」）而
　会「名」为「名」默认『』而
　「形状节点」
　　于「路径」为（「圆路径」于「圆心」为「圆心」于「半径」为「半径」）
　　于「填充」为「填充」
　　于「描边」为「描边」
　　于「不透明度」为「不透明度」
　　于「名」为「名」
也。
```

默认值只能是数据（00019 规则三）：「常量信号」是「信号」的构造器，「原点」「透明」「无描边」是设计库的顶层数据，「一」『』是字面量。

属性加子项的构造——「声轨」：

```
「声轨」乃
　可化「音量」为（「信号」于「小数」）而
　可化「语言」为「字符串」而
　化「子项」为（「列」于「声音片段」）而
　「轨」
也。
「声轨」者
　会「音量」为「音量」默认（「常量信号」于「一」）而
　会「语言」为「语言」默认『』而
　会「子项」为「子项」而
　「声轨节点」于「音量」为「音量」于「语言」为「语言」于「片段们」为「子项」
也。
```

接受字符串项的构造——「段」：子项类型「行内」是和类型，恰有一个只收字符串的构造器「文字片」，字符串项就用它包一层。

```
「行内」立「元类型」也。
　「文字片」立化「字符串」而「行内」也。
　「强调片」立化（「列」于「行内」）而「行内」也。
　「公式片」立化「数学式」而「行内」也。

「段」乃化「子项」为（「列」于「行内」）而「文档节点」也。
「强调」乃化「子项」为（「列」于「行内」）而「行内」也。
```

于是 `「段」【『由』，「强调」【『质能关系』】，『可知……』】` 里的『由』『质能关系』『可知……』都包成「文字片」。

能力不进签名，挂在节点种类上：设计库里一张普通的“节点能力”表，作品在编译期求值后，编译器遍历节点树取各节点能力的并。

```
「节点能力」乃化「设计节点」而「能力集合」也。
「节点能力」者会「节点」而
　鉴「节点」而
　　有（「声轨节点」于「轨资料」）则「能力集合」【「声音采样」】
　　或有（「合成节点」于「合成资料」）则「能力集合」【「声音合成」】
　　或有（「三维物体节点」于「物体资料」）则「能力集合」【「三维」】
　　或有「其他节点」则「空能力」
也。
```

不合约定的报错：

```
错误：「圆」没有参数「颜色」（第 18 行）。
错误：「圆」不接受子项：它没有「子项」参数（第 24 行）。
错误：「组」的子项类型是「场景节点」，不接受字符串项『标签』（第 31 行）。
错误：「混色」不接受构造写法：它有不带标签的参数（第 40 行）。
```

### 2.5 组件

组件就是返回节点的普通函数，用普通调用写在构造的子项里：

```
「标题卡」乃化「题」为「字符串」而化「副题」为「字符串」而「场景节点」也。
「标题卡」者会「题」为「题」而会「副题」为「副题」而
　「竖排」
　【「间距」者「二四」也
　，「文字」【「样式」者「大标题」也，「题」】
　，「文字」【「样式」者「小标题」也，「副题」】
　】
也。

「片头画面」者
　「组」
　【「位置」者（「点」于「九六零」于「五四零」）也
　，（「标题卡」于「题」为『设计语言』于「副题」为『视频即文档』）
　】
也。
```

「标题卡」的参数都带标签，所以也能用构造写法调用，下面两种写法等价：

```
「标题卡」【「题」者『设计语言』也，「副题」者『视频即文档』也】
（「标题卡」于「题」为『设计语言』于「副题」为『视频即文档』）
```

副题常常不写，就把它声明为可省参数（提案 00019）：

```
「标题卡」乃化「题」为「字符串」而可化「副题」为「字符串」而「场景节点」也。
「标题卡」者会「题」为「题」而会「副题」为「副题」默认『』而
　「竖排」
　【「间距」者「二四」也
　，「文字」【「样式」者「大标题」也，「题」】
　，「文字」【「样式」者「小标题」也，「副题」】
　】
也。

「标题卡」【「题」者『设计语言』也】
```

二进制保留“组件定义与组件实例”：「标题卡」的定义存一份，每次使用记一个实例（实参）；由默认值补齐的实参带“缺省”标记，反编译回来仍是 `「标题卡」【…】` 或 `（「标题卡」于…）`，带标记的实参照旧省略。

## 三、值与单位

| 写法 | 类型 | 说明 |
| --- | --- | --- |
| （「秒」于「一点五」）、（「毫秒」于「二零零」）、（「分」于「二」） | 时间 | 整数刻，一秒 705600000 刻 |

| （「百分比」于「五零」） | 长度 | 相对父容器 |
| （「度」于「四五」） | 角度 | |
| （「点」于「九六零」于「五四零」）、「原点」 | 点 | |
| （「三维点」于「零」于「二」于「六」） | 三维点 | |
| （「尺寸」于「一九二零」于「一零八零」） | 尺寸 | |
| （「色码」于『#A33C2C』）、「墨色」「朱色」「纸色」 | 颜色 | 主题色在「设计」之「色板」 |

属性写常量就是不动的值；写信号就是动画：

「圆」【「半径」者「五零」也】
「圆」【「半径」者「关键帧」【「帧」【「在」者「零秒」也，「值」者「零」也】，「帧」【「在」者（「秒」于「一」）也，「值」者「五零」也】】也】
```

## 四、二维场景

```

「圆」【「圆心」者（「点」于「五零零」于「三零零」）也，「半径」者「八零」也，「填充」者「朱色」也】
「椭圆」【「圆心」者「原点」也，「半径横」者「一二零」也，「半径纵」者「六零」也】
「线」【「起」者（「点」于「零」于「零」）也，「止」者（「点」于「二零零」于「一零零」）也，「描边」者（「描边样式」于「颜色」为「墨色」于「宽」为「二」）也】
「路径」【「数据」者『M10 80 C40 10 65 10 95 80 S150 150 180 80』也，「描边」者（「描边样式」于「颜色」为「墨色」于「宽」为「三」于「线帽」为「圆头」）也】

```

路径数据沿用 SVG 的路径写法（字符串项里不受标识符规则约束）。

### 4.2 组与变换

```
「组」
【「名」者『标志』也

## 十八、待确认的写法

下列写法各有可选方案，本文按推荐写；请逐条确认或改：

1. **作品入口名「作品」。** 也可以用「入口」与普通程序一致；推荐「作品」，与作品构造呼应。
2. **时间写法。** 推荐 `（「秒」于「二」）`（函数，编译期求值），不改词法；另一方案是数字带单位的字面量（如「二秒」），要改词法分析。
3. **关键帧写法。** 推荐「帧」子构造（`「帧」【「在」者…也，「值」者…也】`）；另一方案是（时刻与值）的对组列表，更短但不能逐帧写缓动。
4. **常量自动提升为信号。** 推荐提升（属性写常量即不动）；不提升就要处处写「常量信号」于…。
5. **构造调用约定。** 本文定：命名项对应带标签参数，可省属性用提案 00019 的「可化」与「默认」，其余项交给标签名为「子项」的参数；「子项」也可以换成别的名字（如「子」）。不改语法分析器，只改阐述、名称解析与类型检查。
6. **节点命名与引用。** 推荐「名」属性加字符串引用（『球』），驱动、事件、对焦都用它；另一方案是用顶层绑定的变量引用节点，类型更严但写法更绕。
7. **合成图连线。** 推荐节点起名加「连线」【『甲』，『乙』，…】；另一方案是嵌套写法（子项即输入），简单链路更直观、分叉与汇合难写。
8. **音高写法。** 推荐音名字符串（『C4』『F#3』）；另一方案是数字（MIDI 音高号）或构造（「音高」于「C」于「四」）。
9. **数学写法。** 推荐 LaTeX 数学串；中文构造写法列为后续版本事项。
10. **界面的视图与推进。** 推荐「界面」作品带「初值」「推进」「视图」三个属性（Elm 式）；状态机写法（10.2）用于动画。
11. **字幕时刻。** 推荐（「秒」于…）；另一方案是 `『00:00:01.000』` 这类字符串时间码，便于从 SRT 粘贴。
12. **样式叠加。** 推荐 `「样式」者「列」【甲，乙】也` 后者覆盖前者；另一方案是「继承」属性。
