本文只写现代汉语（AGENTS.md）。

## 一、拟定事项

- **议一：签名用「可化」标出可省参数。** `可化「标签」为 类型 而` 与 `化「标签」为 类型 而` 并列；可省参数必须带标签。
- **议二：定义用「默认」给出默认值。** 每个可省参数在定义的参数处写 `会「标签」为「局部名」默认 值 而`；可省参数必须写默认值，必填参数不许写。
- **议三：调用写法不变。** 可省参数可以不传，传了就和必填的标签参数一样写 `于「标签」为 值`。
- **议四：函数体里参数总有值，不引入可选类型。** 类型检查时把省掉的实参补成默认值，调用降为参数齐全的普通调用；标签照旧在类型检查后擦除，没有运行时开销。
- **议五：带可省参数的函数只能当场调用。** 出现处必须是调用；要当值传递就包一层 λ。函数值的类型里因此没有「可化」。

## 二、动机

很多函数的一串标签参数里，大半在多数调用中取同一个值（图标钮的宽、高、边长，渲染图标的画法，界面元素常为空的样式与属性列）。现在每处调用都得写全。提案 00018 的构造写法也需要它：设计构造有十几个属性，多数可省。

OCaml 的可选参数在函数体里是可选类型，要逐个拆开；本提案让默认值必须写明、由编译器补齐，函数体照常使用参数。

## 三、写法

签名：

```
「图标钮」乃
　可化「宽」为「整数」而
　可化「高」为「整数」而
　可化「边」为「整数」而
　化「消息」为「外壳消息」而
　化「提示」为「字符串」而
　化「图标」而
　（「界面」于「外壳消息」）
也。
```

定义：

```
「图标钮」者
　会「宽」为「宽值」默认「二六」而
　会「高」为「高值」默认「二六」而
　会「边」为「边值」默认「一六」而
　会「消息」为「消息」而
　会「提示」为「提示」而
　会「标」而
　「可点」
　　于（「列」【「点击时」于「消息」，「悬停提示」于「提示」】）
　　于（「层叠」于（「列」【「宽度」于「宽值」，「高度」于「高值」】）于（「列」【（「定位图标」于「标」于「边长」为「边值」）】））
也。
```

调用：

```
「图标钮」于「消息」为「关闭标签」于「提示」为『关闭』于「关闭图标」
「图标钮」于「宽」为「三六」于「高」为「三六」于「边」为「二零」于「消息」为「退出外壳」于「提示」为『返回命令行』于「返回图标」
```

第一处省掉宽、高、边，取 26、26、16；第二处全部给出。

## 四、规则

1. **标签。** 可省参数必须带标签；`可化「整数」而` 这类不带标签的写法报错。
2. **默认值必填。** 签名里是「可化」的参数，定义里必须写「默认」；签名里是「化」的参数，定义里写了「默认」报错。
3. **默认值只能是数据。** 字面量、构造器作用于数据、顶层数据的名字（与提案 00006 顶层只放数据的规则一致）；类型按签名检查。默认值引用前面的参数留待后续版本。
4. **配对。** 实参按标签与签名配对，次序照签名；可省参数省掉就补默认值，必填参数缺了报错，标签写错报错。
5. **降级。** 类型检查后调用是参数齐全的普通调用，后续编译步骤不变。
6. **跨模块。** 默认值随模块的签名信息导出（编译缓存里记下），别的模块调用时照样补齐；改了默认值，调用方随依赖重新编译。
7. **只能当场调用。** 带可省参数的函数，出现处必须是调用的头（`「函」于 …`，含构造写法与 `授以`）；当值传递、存进组值、作返回值都报错：“「函」带可省参数，只能当场调用；要当值用，请包一层 λ”。所以函数值的类型里不会出现「可化」，也就不涉及「可化」参数与「化」参数在类型上是否相等；默认值总由调用方补齐，不需要隐藏的调用约定。
8. **接口文件。** `。接口。豫`、`。应用接口。豫`、`。底层接口。豫` 只有签名、没有定义，暂不许用「可化」。
9. **底层文件。** `。底层。豫` 照样可用，机制相同。
10. **转发。** 包装函数要把可省参数转给内层函数时，自己也声明为可省参数并写默认值。

## 五、兼容与迁移

- 「可化」「默认」是新关键字，写在「」之外，不与现有名字冲突；现有代码含义不变。
- 语法分析器要认这两个词：签名的参数位置认「可化」，定义的参数处认「默认」。稳定工具链认这两个词之前，编译器、豫构等工具链自身的源码先不使用新写法。
- 格式化器（yy格式化）支持新写法，签名里每个可省参数单独占一行；高亮与语言服务标出「可化」「默认」，悬停显示默认值。
- 语言技术规范《标签函数类型》篇（汉语、文言）补一节“可省参数”。
- 提案 00018 议十九的构造写法已按本提案改写：命名项对应带标签参数（「可化」参数可省），其余项进「子项」列；原“构造调用约定”里的属性组类与「或可有」已删去。

## 六、备选方案

- **可省参数在函数体里是可选类型（OCaml 的做法）。** 函数体要逐个拆开，默认值散落各处。不取。
- **带可省参数的函数可以当值传递（类型保留「可化」，被调函数入口补默认值）。** 经由函数值调用也能省参数，但要隐藏的调用约定（“已传”位掩码），类型相等规则也更复杂。用户定只能当场调用，不取。
- **默认值写在签名里。** 调用方读签名即见默认值，但签名里混入值；用户定默认值写在定义里，签名只标“可省”。
- **用符号标出（如 `＝「二六」`）。** 豫言一向用字词，不取。

## 七、未决问题

- 默认值引用前面的参数（如「止」默认取「文」的长度）。
- 接口文件里的可省参数（需要在接口里另给默认值的写法）。
- 调用处“显式取默认值”的写法（转发时有用）。

## 八、实施步骤

1. 语法分析：签名参数位置的「可化」、定义参数处的「默认」。
2. 类型检查：可省参数的配对、补齐与报错；默认值的数据检查与类型检查；跨模块导出默认值；“只能当场调用”的检查。
3. 格式化器、高亮、语言服务。
4. 测试：黄金样例（成功：省掉、部分给出、全部给出、跨模块；失败：缺默认值、必填参数写默认值、不带标签、默认值非数据、标签写错、当值传递）。
5. 语言技术规范《标签函数类型》篇补“可省参数”一节。
6. 稳定工具链支持后，按需在库里使用（图标钮、渲染图标、界面元素与设计库的构造等）。
