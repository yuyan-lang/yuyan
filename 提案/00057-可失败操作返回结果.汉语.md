## 一、拟定事项

- 议一：豫章新增结果类型「成否」，是一个普通的类型块：「成」带成功的值，「误」带失败的缘由。缘由由各库写成自己的枚举（类型块），不用整数、空串或哨兵值。
- 议二：可失败的操作一律返回「成否」：读文件、写文件、取径、取缓存、取字形、壳命令、远行与交役、跨进程取数都算。成功与失败不再共用一个整数、空串或「或可有」。
- 议三：调用方用鉴分别处理成与误。鉴必须穷尽（提案 00063），漏一支就编不过；结果不许经「而后」悄悄丢掉（提案 00062），真要丢，写 `令「名」为（…）而 …`。不设专门的丢弃函数。
- 议四：几步可失败的操作串起来，用豫章的普通函数「既成」：成了接着做，误了原样传出。不加传播语法。
- 议五：「告祸」只留给程序缺陷（如下标越界）；预料之中的失败一律返回「成否」。
- 议六：编译各阶段的定稿诊断与内部错误也返回结果，调度对各支分别处理，诊断不再以“未捕捉的豫言异常”印出（#823）。
- 议七：旧接口不批量迁移；改到哪个包，哪个包的新写接口与调用处照本条办，旧写法留着待办事项。

## 二、动机

建议表里这条已有 66 个议题，是全部建议中最多的一条。共同点是失败折进返回值：

1. 文件与原语：读文件打不开就直接结束进程（#589、#219）；空路径当当前目录、整读报错码 31 硬退出（#658）；建两级祖先目录失败、「藏境」写失败返回空路径，调用方当路径继续传（#647）。
2. 壳与跨进程：「读行」起子程序失败只印退出码 127，回执仍报「成」（#127）；交役与远行失败被当成空结果（#530）；网页格发命的返回值被丢掉，界面看不出命令送到没有（#639）。
3. 各宿主不一致：整读文件失败时原生、诺驿、浏览器直接结束进程，豫言系统初始任务却抛可接异常（#723）。
4. 诊断被当成异常：编译期定稿诊断在全构建路径里印成“未捕捉的豫言异常：编译错误：…”（#823）。
5. 静默降级：取面失败从屏块当成功返回（#679）；字体取不到整页排版失败，再被冒烟当成页面载入失败（#848）；读资原语把宿主返回值丢给「无」，读回失败也照交缓冲（#844）；零字节单元当成编好的单元跨轮沿用，造出的盘开机即下标越界（#851）。

## 三、设计

语言不变：下面全是现有写法，靠提案 00061（类型块）、00062（而后不丢值）、00063（鉴必穷尽）把规矩管住。

### 3.1 结果类型（豫章）

```
「成否」立化「类」又化「类」为「类」者也。
　「成」立凡「甲」又凡「因」而化「甲」为（「成否」于「甲」于「因」）者也。
　「误」立凡「甲」又凡「因」而化「因」为（「成否」于「甲」于「因」）者也。
```

原稿把类型叫「结果」。仓里拿「结果」当局部名用了 798 处（yybs bbcdaf1aa1，2026-10-27），作类型名会常被遮住，所以改叫「成否」。

### 3.2 失败缘由与接口

```
「读误」立「类」也。
　「无此文件」立「读误」也。
　「无权限」立「读误」也。
　「输入输出」立「读误」也。
　「路径不合法」立「读误」也。

「取文」乃化「路径」为（「成否」于「文」于「读误」）者也。
```

### 3.3 调用处

```
鉴（「取文」于「某径」）而
　或有（「成」于「内容」）则 …
　或有（「误」于「无此文件」）则 …
　或有（「误」于「余」）则 …
```

三支合起来是穷尽的。少了哪一支，鉴就编不过（提案 00063）。

真要丢掉一个结果，明写出来，并在注释里说明缘由：

```
令「无」为（「写文」于「某径」于「帛」）而「：此处不处理写盘失败，因为 …：」…
```

写成 `「写文」于「某径」于「帛」而后 …` 就编不过，因为「写文」返回的是「成否」，不是「有」（提案 00062）。

### 3.4 串联

```
「既成」乃凡「甲」又凡「乙」又凡「因」而化（「成否」于「甲」于「因」）又化（化「甲」为（「成否」于「乙」于「因」））为（「成否」于「乙」于「因」）者也。
```

第一步成了，就把值交给第二步；误了，就原样传出，第二步不跑。

### 3.5 与别的建议协同

与「失败缘由用枚举分办」「可抛与退出须入效应」两条协同：成功值不折进零，失败缘由不折进一个负一；会在出错时退出的调用方显式写出来，不靠各宿主各自的默认。

## 四、兼容与迁移

旧原语与旧库接口保留，新的结果型接口另立名字或按包替换；调用处改到时一并换。全仓不批量重写，按包逐个迁移，CI 只对新写的接口核对。缓存目录、包描述与执行器原语号不变。

## 五、备选方案

- 只改壳命令与跨进程接口，原语层不动：能挡住 #127、#530、#639，挡不住 #589、#658、#723，留下一半。
- 用异常接住失败：执行器与各后端要统一异常语义，且初始任务这类不能死的上下文仍需不抛，故不取。
- 专门的丢弃函数「忽略其误」（原稿）：为一条规则专设的名字，重议时去掉；明写丢弃用现有的 `令`。
- 一句式的传播语法，如「否则退」（原稿未决问题）：新写法，重议时不取；用普通函数「既成」。
- 类型名「结果」（原稿）：仓里当局部名用得太多，改为「成否」。

## 六、未决问题

无。原稿的两个未决问题重议时定下：结果类型是豫章里一个普通的类型块；不加传播语法。

## 七、实施步骤

1. 豫章加「成否」与「既成」，写测试。
2. 原语层先改读文件、写文件、取径三组，各后端同一次改齐，用同一组用例对拍（#723）。
3. 壳命令与远行、交役的返还改成「成否」，壳按结果印回执。
4. 编译各阶段的诊断与内部错误改成结果，调度分办（#823）。
5. 按包迁移旧调用，每个包改完跑该包的类型检查与相关测试。

“漏处理即编不过”要等提案 00062、00063 实施后才完全生效；在那之前，靠警告与审查。

## 八、代价

中到大。原语与壳接口的改动是主要工作量，调用处的迁移可分包进行。结果类型是豫章里的普通类型块，不改编译器。
