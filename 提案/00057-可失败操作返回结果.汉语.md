## 一、拟定事项

- 议一：豫章新增结果类型，写成 `「结果」于「成」于「误」`，两个构造子，成功带值、失败带缘由；失败缘由用枚举，不用整数、空串或哨兵值。
- 议二：可失败的操作一律返回结果类型：读文件、写文件、取径、取缓存、取字形、壳命令、远行与交役、跨进程取数都算。成功与失败不再共用一个整数、空串或「或可有」。
- 议三：调用方必须 `鉴` 分办成功与失败两支；`鉴` 的穷尽检查已在做，缺一支即编译报错（#610）。确实要忽略的，写显式的「忽略其误」，并在注释里说明缘由。
- 议四：编译各阶段的定稿诊断与内部错误也返回结果（成、定稿诊断、内部错误三支），调度对三支分别处理，诊断不再以“未捕捉的豫言异常”印出（#823）。
- 议五：旧接口不批量迁移；改到哪个包，哪个包的新写接口与调用处照本条办，旧写法留着待办事项。

## 二、动机

建议表里这条已有 66 个议题，是全部建议中最多的一条。共同点是失败折进返回值：

1. 文件与原语：读文件打不开就直接结束进程（#589、#219）；空路径当当前目录、整读报错码 31 硬退出（#658）；建两级祖先目录失败、「藏境」写失败返回空路径，调用方当路径继续传（#647）。
2. 壳与跨进程：「读行」起子程序失败只印退出码 127，回执仍报「成」（#127）；交役与远行失败被当成空结果（#530）；网页格发命的返回值被丢掉，界面看不出命令送到没有（#639）。
3. 各宿主不一致：整读文件失败时原生、诺驿、浏览器直接结束进程，豫言系统初始任务却抛可接异常（#723）。
4. 诊断被当成异常：编译期定稿诊断在全构建路径里印成“未捕捉的豫言异常：编译错误：…”（#823）。
5. 静默降级：取面失败从屏块当成功返回（#679）；字体取不到整页排版失败，再被冒烟当成页面载入失败（#848）；读资原语把宿主返回值丢给「无」，读回失败也照交缓冲（#844）；零字节单元当成编好的单元跨轮沿用，造出的盘开机即下标越界（#851）。

## 三、设计

结果类型的写法：

```
「读误」即「和」【「无此文件」，「无权限」，「输入输出」，「路径不合法」】也。
「取文」乃化「路径」为（「结果」于「文」于「读误」）者也。
```

调用处必须分办：

```
鉴（「取文」于「某径」）
　或有「文」则 …
　或「无此文件」则 …
　或「无权限」则 …
　或「输入输出」则 …
　或「路径不合法」则 …
```

要忽略时显式写出：

```
令「其误」为（「忽略其误」于（「写文」于「某径」于「帛」））而
（待办事项：此处不处理写盘失败，因为 …）
```

返回结果类型与「失败缘由用枚举分办」「可抛与退出须入效应」两条协同：成功值不折进零，失败缘由不折进一个负一；会在出错时退出的调用方显式写出来，不靠各宿主各自的默认。

## 四、兼容与迁移

旧原语与旧库接口保留，新的结果型接口另立名字或按包替换；调用处改到时一并换。全仓不批量重写，按包逐个迁移，CI 只对新写的接口核对。缓存目录、包描述与执行器原语号不变。

## 五、备选方案

- 只改壳命令与跨进程接口，原语层不动：能挡住 #127、#530、#639，挡不住 #589、#658、#723，留下一半。
- 用异常接住失败：执行器与各后端要统一异常语义，且初始任务这类不能死的上下文仍需不抛，故不取。

## 六、未决问题

结果类型用泛型组类还是「或可有」的扩展，留待实施时按译场的类型表示定。是否引入一句式的传播语法（如「否则退」），留待有更多用例再议。

## 七、实施步骤

1. 豫章加结果类型与「忽略其误」，写测试。
2. 原语层先改读文件、写文件、取径三组，各后端同一次改齐，用同一组用例对拍（#723）。
3. 壳命令与远行、交役的返还改成结果，壳按结果印回执。
4. 编译各阶段的诊断与内部错误改成结果，调度分办（#823）。
5. 按包迁移旧调用，每个包改完跑该包的类型检查与相关测试。

## 八、代价

中到大。原语与壳接口的改动是主要工作量，调用处的迁移可分包进行；类型与穷尽检查已有，结果类型只用豫章现成的和类型，不改编译器。
