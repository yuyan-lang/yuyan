# 提案 00002：广义代数之类与简易依值之类

| 项 | 文 |
| --- | --- |
| 号 | 00002 |
| 状 | 讨论中 |
| 提于 | 2026-10-04 |
| 所及 | 编译器前端之验类（模式之配、类之成、类之等、隐参之推）；标准库「列」改为内建之类及其运行之表；相关之语言技术规范 |

此篇为豫言增广义代数之类（GADT）与简易依值之类之提案：模式之配于支内细化其类，构造器可带存在之类；类可依内建之类之值（整数、爻、字符串、列），类中惟行内建之算，不行用户之函；「列」改为内建之类，后易其表，自链改为组段。验类仍为一阶、局部、必止。

与[汉语稿](00002-广义代数类型与简单依值类型.汉语.md)相应。

## 一、所议之事

| 号 | 议 |
| --- | --- |
| 议一 | 模式之配行类之细化：构造器之果类与所配者之类行双向一阶之合一，外层之刚变于本支可解；所得之代换施于本支之所期之类、境及支中所书之类 |
| 议二 | 许存在之类：构造器之隐参不能由果类定者，配时取为新刚变；合成之式下验其不逸出于支 |
| 议三 | 合一相冲之支判为不可达，示警而略其体之验 |
| 议四 | 某支细化外层之变者，`鉴` 必有所期之类（验之式），否则报“须标其类” |
| 议五 | 类可依内建之类之值：「整数」「爻」「字符串」「列」；「小数」不收；他自定之类之值不可依 |
| 议六 | 类中惟许索引之式：字面、内建之类之变、内建之算；不许召用户之函。余实参先以 `虑` 绑为变，于类中为不透之名 |
| 议七 | 索引之式化为规范之形而后较：整数依多项，列依“附加”之结合与空列，字符串依拼接与字面之并；不判不等；整数依数学之整数，运行之溢今不处 |
| 议八 | 不验终止：类之层惟行内建之算，必止；仍设规约步数之限以为保。证之参显传、严求、不擦 |
| 议九 | 书法沿语法所已有之 `化 A 者「x」而 B`（显之依值之函）与 `承 A 者「x」而 B`（隐之值参，编后擦之），放其定义域自元类型至内建之值类；带标则书 `化（「签」为 A）者「x」而 B`（`为` 之右既松，括号可省）；类之构造器可受内建之类之参 |
| 议十 | 隐参之推仍为有序之配：索引之变惟独见时求之，复合之式代入而后核 |
| 议十一 | 依值之模式配：所配者为变，则于支中代之以其模式，与议一同一代换 |
| 议十二 | 「列」「罄」「缀」、列之字面与列之模式改为编译器内建；先易其身，不易其运行之表 |
| 议十三 | 「列」运行之表改为组段（VList 之类），依尾递归之遍改为下标之循；先作原型而测，达标乃换 |
| 议十四 | 不为：一般依值之类、终止之验、SMT 之求、单构造器单字段之类之自动拆包 |
| 议十五 | `为` 之右松于诸二元之符：规约关系表增左为 `〇为〇` 之关系十一行；带标之实参照旧自带括号，缺之则予专门之报误 |

## 二、所以然

### 今之状

豫言之类系（见《类型与模块》）：

- 双向之验：合成与验二式。
- 显式多态：隐参 `承「甲」` 惟绑元类型；`元类型` 亦为类，不分宇宙之层。
- 名义代数数据之类：构造器以 `立` 别声其全类，书法同于 GADT，如 `「缀」立（承「甲」而化「甲」而化（「列」于「甲」）而「列」于「甲」）也。`
- 类之等：结构之较加局部之 η，不行 β 之规约，不展普通值函之体。
- 隐参：有序之配，惟解签名一侧待求之变，不行全局之搜。
- 模式：构造器之果类须“配”所配者之类，刚变惟等于己。
- 无穷尽之验：所缺之支生运行报错之路。
- 类之构造器之显参惟元类型。

### 所测

2026-10-03 于本机以 `yy豫构.wasm 文件` 构六例（编译器为其时 yybs 之 `yy4_bs.wasm`）：

| 例 | 果 |
| --- | --- |
| 误造 `若式 于（整字 于 一）…` | 见拒（“整数 != 爻”）：构造之端今已安 |
| 索引已知之用 `求整：式 于 整数 → 整数` | 过，运行出 7 |
| 多态之求值 `求值：承甲. 式 于 甲 → 甲` | 见拒：于 `整字` 之模式报“整数 != 甲” |
| 拆存在之类 `包可示：承甲. 甲 →（甲 → 字符串）→ 可示` | 见拒：“函数应用的隐式参数无法完全确定：未能确定 甲” |
| 不可能之支（于 `式 于 整数` 书 `爻字` 之支） | 报类之误“爻 != 整数” |
| 相等之证加 `不安全转换` 之旧编 | 过，运行出 7；其类之安，全恃“「相等」惟可由「同」造”之约 |

是故带索引之类，惟可用于索引已知之时；于索引泛之遍，不可书也。据所查，全仓非测试之码，果类特化之构造器惟见于着色库之数字面构造器（如「新浮三二」）。

### 往事

- 2022 年 SML 之版有依值之 Π 与依值之模式配（91499e69b、b8600fb42）；是年十二月，自举之编译器增依值之函之书 `化 A 者 x 而 B`（a0647e60d）。
- 2026 年六至七月，为求“局部、可预测”，去依值之 Π（f3a53b0a9）、顶部归一化（fa6d7daf3）与模式合一之大半（8430c0e07）。计划 0004 所书之由：元变量“过早创建，并且存活太久”，“整个系统会变得难以推理”。
- 本提案循此向：所增之推，皆成于一支或一召之内，类中不行用户之码。

### 码中之缺

下列之数，2026-10-03 至 10-04 于 yybs 计之。

1. **伪三元**。树码缓存（38355b656）惟一果类 `表达式树组`。串列之产（文件依赖、代码生成形式）裹为 `名 与 阳 与 待定节点` 之伪三元以存取，读出复以 `三对子取零` 拆之（`编译文件缓存工具。豫` 之「读串列缓存」「写串列缓存」）。产用何式、何后缀、书依赖快照与否，散于五六函，较 `信息名` 之串而定。
2. **同类二表**。裸机后端「局部寄配」返入口活跃之表（「局数＋1」格）与死写之表（「指令数＋2」格），其类皆 `数组引用类 于 整数`。先后有“惟开一格”（e8a09b4e7）与“二表次序倒置”（b20fe3f12）二越界，皆惟于生 x86-64 时见。
3. **名义之长**。着色库以十七名义之类（「定长一」至「定长八千一百九十二」）表长，译器依名识之；`点积：承甲. 甲 → 甲 → 浮三二` 无所不受；`读共享数组` 之下标为任意 `无三二`，GPU 上共享内存越界惟予误值。据所查，着色内建之签名百一十九，其八十五为无约之 `承`。
4. **帧槽**。b2f7d1771：数值内在码中，帧槽之号与栈深依所在之函编之，内联后未移，于苹果 ARM64 陷而退。其时之修，含数值内在码之函不内联，并留待办之事。
5. **张量之形**。形与元类皆在运行之时（`后端张量` 以整数之列与类号表之）；「拆成多头」恃运行时之改形；千问三之头维缺省依「嵌入维 ÷ 问头数」推之，而千问三某尺寸「问头数 × 头维」不等于嵌入维。
6. **列之费**。全仓列之字面 12308 处，每处造 n 缀格；`长度` 约 1228 处、`第N个` 880 处，皆 O(n)。生成代码性能之录，原生最热之函 m923 所为者，即“链上行 n 步”。

所求：

## 五、设计：广义代数之类

所改聚于 `库/编译器核心/编译步骤/类型检查/模式匹配类型检查。豫` 之「检查模式函数应用」。今之所为：先单向求构造器之隐参，后断构造器之果类等于所配者之类。改为：

1. **双向一阶之合一**。可解之变有二：构造器自身之隐参，及外层 `受`／`承` 所引之刚变（境中类为元类型之自由变）。类惟名义之首、箭、元组数形，一阶合一加出现之验足矣。合一得代换 σ。
2. **支内施 σ**。σ 施于所期之返类、境中局部绑定之类（境为条目之列，`式替换` 已具），及支中所书之类（如 `授以「甲」`、`（「甲」也 …）`）。
3. **不可达之支**。合一相冲（如“零”对“后继”）者，其支不可达：示警，略其体之验。
4. **存在之类**。果类所不能定之构造器隐参，取为新刚变；合成之式下验其不见于支之果类。
5. **合成之则**。`鉴` 今“首支合成、余支验之”；某支细化外层之变者，改为须有所期之类。OCaml 与 GHC 亦如是。

所不涉：

- 隐参之推仍为有序之配。多态之递归恃显式之签名足矣：递归之引本得全 `承` 之类。
- 擦除与代码之生：索引皆类，擦除之阶已去，运行之表不易。去装箱之类别取于顶层所声之签名（工名类别表），不为支之细化所动。
- 宿主之界：先拒果类特化之构造器，留待办之事。

度此分约四百至七百行豫言（含新合一之器），另加正反之测与规范。

## 六、设计：依内建之值之类

### 可依之值

类可依「整数」「爻」「字符串」「列」之值。「小数」不收：今之结构之较依字面之文较小数（整部与小部二串），`0.5` 与 `0.50` 乃成二类；NaN 与正负零亦令“等”难定。Rust 之常量泛型亦不收浮点。

### 索引之式

类中惟许索引之式：

- 字面：整数、爻、字符串、列之字面（其元亦为索引之式）；
- 变：类为上述内建之类之变；
- 内建之算：整数之加、减、乘；爻之与、或、非；字符串之拼接；列之罄、缀、附加、长度、第N个、乘积。

类中不召用户之函，故不须展函之体，亦不须验其纯。余实参先以 `虑` 绑为变，是变于类中为不透之名。

### 书法

```yuyan
「定长表」立化「整数」而化「元类型」而「元类型」也。
「新定长表」乃承「甲」而化「甲」而化「整数」者「长」而（「定长表」于「长」于「甲」）也。
「点积」乃承「整数」者「维」而承「甲」而
  化（「向量」于「维」于「甲」）而化（「向量」于「维」于「甲」）而「甲」
也。
```

- `化 A 者「x」而 B`：显之依值之函，果类 B 中可见 x。
- `承 A 者「x」而 B`：类为 A 之隐之值参，编后擦之。
- 类之构造器可受内建之类之参。

此二书语法本有之（规约关系表之 `化〇者□而〇`、`承〇者□而〇`，源于 2022 年之 a0647e60d），今惟为旧式之兼容：定义域惟许元类型，转为隐之全称之类；全仓无一处用之。2026-10-04 实测：解析之器已能读 `化（「长」为「整数」）者「n」而「整数」` 与 `承「整数」者「n」而 …`，二者皆见拒于「旧类型参数定义域检查」（`库/编译器核心/编译数据/操作符/内建操作符/内建操作符类型定义。豫`），报“已不再支持非元类型的依赖函数类型参数”。于语法，惟须放此一验，改为构依值之箭。

### 与标签之参相配

标签函数之类（2026-10-02 始，见《标签函数类型》）以 `「签」为 式` 书标项：依位而核，标不绑名，可重，验后擦之；首版不支乱序之召、默认之值、部分之施与标之简书，类之构造器之参与着色之语中之标报误。依值之书与之相配如下：

| 位 | 无标 | 带标 |
| --- | --- | --- |
| 依值之函之类 | `化 A 者「x」而 B` | `化（「签」为 A）者「x」而 B` |
| 带类之匿函 | `遇 A 者「x」而 e` | `遇（「签」为 A）者「x」而 e` |
| 无类之匿函 | `会「x」而 e` | `会（「签」为「x」）而 e` |
| 召 | `f 于 v` | `f 于（「签」为 v）` |
| 隐之值参 | `承 A 者「x」而 B` | 首版不许带标 |

类之书与已有之 `遇（「签」为 A）者「x」而 e` 同形：`遇` 之绑名，即依值之箭之绑名。

1. **标与绑名各司其事**。标为外之名，依位而核，与于类之等；绑名为 B 中所用内之名，较等时依换名而较。`化（「长」为「整数」）者「n」而（「定长表」于「n」于「甲」）` 与易 n 为 m 之书同，与易标为「宽」之书异。易内名不易接口，易标乃易接口，与今之则合。
2. **依位而施，令依值之验简**。验之序即声之序，亦即源码之序：验一位毕，代其值于后诸位之类。异日若增乱序之召，须先依源码之序求值而绑为暂名，后依声之序验之；或不许越依值之参而乱其序。
3. **依值之位，其实参须为索引之式**。去标之后之实参须为索引之式，否则报误，示以先用 `虑` 绑之。
4. **箭之组如故**。`化 A 者「x」而化 B 而 C` 仍并为一组，多参饱和之则不易；组中每位可带标、可带绑名。内表自“域之列”改为“带绑名之域之列”，标仍依位裹于诸域。
5. **匿函**。`会（「签」为「n」）而 e` 依依值之箭而验时，n 即其位依值之变之实例。`遇` 合成其类时，体之类若及绑名，则合成依值之箭，否则合成常（带标）之箭。
6. **隐之值参首版不带标**。沿《标签函数类型》“隐参不受标项”之规，`授以` 仍依位而予。依名予隐参（类 Agda 之 `{n = 3}`）即许跳位，与“依位、不乱序”相冲，列于未决。
7. **构造器之依值之项**。构造器可有依值之项，犹依值之对；标令模式易读。下之「带长表」，以 `有（「带长表」于（「长」为「m」）于（「元素」为「表」））则 …` 配之，m 之类为「整数」，「表」之类为 `定长表 于 m 于 甲`。
8. **类之构造器之参与着色之语**：守《标签函数类型》首版之诊；索引之参依位而书，例二之着色之书不带标。
9. **旧式兼容之去留**：`化「元类型」者「甲」而 B` 今表隐之全称，全仓无一处用之；改为报误，示以改书 `承「甲」而 B`。如是，`化` 皆为显，`承` 皆为隐。
10. **`为` 之右宜松**。标项 `「签」为 式`，其左恒为一名，其右为所标之全体，故 `为` 之右宜松于诸二元之符，延至外层之括号或混合之符之键字（`而`、`者`、`则`、`或`）而止。规约关系表增此数行（左为 `〇为〇`）：

| 右符 | 决 |
| --- | --- |
| `〇于〇`、`〇授以〇`、`〇之〇`、`〇中〇`、`〇附〇`、`〇与〇`、`〇合〇`、`〇也〇`、`〇；〇` | 右规约 |
| `〇者〇也`、`〇或〇` | 左规约 |

右为 `〇为〇` 之关系仍不定：带标之实参照旧自带括号，书 `f 于（「签」为 …）`；不然，松之右将吞其后之实参，`f 于「甲」为 a 于「乙」为 b` 将读为 `f 于（「甲」为（a 于「乙」为 b））`。是时之报误改为“带标签的实参须加括号”。

2026-10-04 实测今状：`化「长」为「整数」者「n」而「整数」` 报“未定义优先级关系：〇为〇 与 〇者〇也”；`（「被减数」为「加」于「一」于「二」）` 与 `化「表」为「列」于「整数」而「整数」` 报“〇为〇 与 〇于〇”；`「差」于「被减数」为「一零」于 …` 报“〇于〇 与 〇为〇”。改后前三书皆可过，第四书照旧报误而示以加括号：

```yuyan
「新定长表」乃承「甲」而化「初值」为「甲」而化「长」为「整数」者「n」而（「定长表」于「n」于「甲」）也。
「新定长表」于（「初值」为「零」）于（「长」为「加」于「局数」于「一」）
```

此条惟改规约关系表（实现于 `库/编译器核心/编译数据/操作符/内建操作符/文言符集。豫`），旧程序之义不易，可先于本提案之余单独为之；编译器源码须待稳定之工具链更新，乃可用省括号之书。

```yuyan
「某表」立化「元类型」而「元类型」也。
  「带长表」立（承「甲」而化（「长」为「整数」）者「n」而化（「元素」为（「定长表」于「n」于「甲」））而「某表」于「甲」）也。

「新定长表」乃承「甲」而化（「初值」为「甲」）而化（「长」为「整数」）者「n」而（「定长表」于「n」于「甲」）也。
「新定长表」于（「初值」为「零」）于（「长」为（「加」于「局数」于「一」））
```

是召之中，二位互易则标不合，长误则果类 `定长表 于 …` 不合：前者标所已有之护，后者依值之类所予。

### 等

索引之式先化为规范之形而后较：

- 整数：多项之规范形（交换、结合、并常数）；
- 列：依“附加”之结合与空列化简；`长度 罄 = 〇`，`长度（缀 头 尾）= 加 一（长度 尾）`，`长度（附加 甲 乙）= 加（长度 甲）（长度 乙）`；`乘积` 亦然；
- 字符串：依拼接之结合并相邻之字面；
- 爻：惟并字面。

不判不等：“小于”之类之实，由运行之验经可信之函出之，如 `下标 于 n`。整数依数学之整数规范之，运行之溢今不处（待办之事）。

### 推与细化

- 隐参之推沿有序之配：索引之变惟独见时求之（`向量 于 维` 对 `向量 于 三` 得 维＝三）；复合之式（如 `加 左 右`）代入而后核之。
- 模式之细化兼施于类与索引：以 `空：定长列 于「〇」` 配 `定长列 于 n` 时，本支 n＝0。规范之后，一侧为独变则绑之；两侧为异常数则判不可达；余报“不能细化”。
- 依值之模式配：所配者为变 xs，则于 `有（缀 头 尾）` 之支以 `缀 头 尾` 代 xs，`长度 于 xs` 乃可规约为 `加 一（长度 尾）`。此与第五节之 σ 同一代换；2022 年 SML 之版尝为同事（b8600fb42）。

### 不验终止之约

1. 类之层惟行内建之算，于有限之项必止。仍设规约步数之限（取其大）以为保，逾之则报“类型规约超出步数”。
2. 证之参（如 `相等 于 a 于 b`、`下标 于 n`）显传、严求、不擦。以无穷之循或 `发生事故` 伪造之证，惟令程序于用之前滞或抛，不挟误前提以行。其费几无：`下标` 即其整数，`同` 为构造之常。
3. `不安全转换` 仍为惟一显出之逃口。

### 于编译器余部之影响

- 擦除：隐之值参随类而擦；显依值之参照常而传。
- 去装箱：`定长表 于 n 于 甲` 之类别为“通”；整数之参仍为“整”。
- 接口与缓存：接口之类增索引之式（「表达式」本能表之）；类中不展用户之函，接口不须附函之体。
- 底层之式：整数之索引亦可用，类于擦除时去之。
- 宿主之界：带索引之类，去其索引而依其形处之。

## 七、设计：内建之列

### 第一步：识其身，不易其表

「列」「罄」「缀」、列之字面与列之模式，改由编译器径识之；标准库「多态列」之定义改为内建之别名，源码不改。宿主边界之验今依径识「多态列」（留“改依包之身识之”之待办），此步并解之。第六节列之诸则，亦恃此步。

### 第二步：组段

所益（2026-10-04 于 yybs 计之）：列之字面 12308 处，每处惟须一分配；`长度`（约 1228 处）与 `第N个`（880 处）为 O(1)；遍之缓存局部性更佳。

所险：今之书法恃 O(1) 之接首与共享之尾。全仓以 `缀` 接首者 3834 处，配 `罄`、`缀` 者 3356 处，“逆积而后反转”者 412 处。编译器之命名环境即条目之列，「添加声明」以 `缀` 接其首，同一父境为诸支所共。易为朴素之组，则每接首须全复，是诸处退为 O(n²)。

设计之要：

1. **组段**。取 Bagwell 之 VList（2002）之类，以几何增长之组段相链。接首之时，段前之空位无人占则径书之（O(1)）；已为人占（其尾为共享）则新开一段。取尾、接首皆 O(1)，长度记于段中亦 O(1)，依下标平均 O(1)，字面一次成段。
2. **取尾**。WasmGC 无内指针，组中之“尾”惟可别分配一（段，偏移）之视。今配 `缀 头 尾` 无所分配；改后每取尾一分配，遍或反迟。其解：由编译器以“依尾递归”之遍改为下标之循，（段，偏移）留于二局部之变，惟尾外逸乃造其视。成败系于此步，须先作原型。

验之准：E1a（163118d41）所录 pit-mac、Node、三轮之中：列表造遍每次 34.4 纳秒、态射 10.0 纳秒、从左折叠 3.71 纳秒；兼观自举之时与 WP8 原生之指令数。

另二事：

- 「串典」立于列上（裹键值对之列之单构造器之类），随列而为组段。其查仍为自首而扫之线性之查，欲速须易为散列或树，与本提案无涉。
- 「字符串」本为内建之字节之组，为索引惟较其等，主用为名或标。

```yuyan

「读定长表」乃承「整数」者「长」而承「甲」而
  化（「定长表」于「长」于「甲」）而化（「下标」于「长」）而「甲」

「局部寄配」乃
  化「爻」而
  化「整数」者「局数」而
  化「整数」而
  化（「列」于「网页指令」）者「令们」而
  化（「列」于「整数」）而
  （…）
    合（「定长表」于（「加」于「局数」于「一」）于「整数」）
    合（「定长表」于（「加」于（「长度」于「令们」）于「二」）于「整数」）
```

- 惟开一格（e8a09b4e7 之前）：`「新定长表」于「一」于「一」` 之类为 `定长表 于 一`，与 `定长表 于（加 局数 一）` 不等，于非 ARM64 之支当即报之。



## 九、所不及

- **依自定之类之值**：如以 `列 于 值型` 之字面述 Wasm 操作数之栈（值型为自定之类），须放至“凡构造器之项皆可为索引”乃可，见第十二节。
- **高阶之算**：`态射` 须行用户之函，类中不能算之。`长度（态射 f xs）= 长度 xs` 之类不须行 f 之则，可别增为内建之则。
- **须归纳而证之性**：如 `长度（反转 xs）= 长度 xs`。或增为内建之则，或于运行时验之。
- **不等**：惟恃运行之验出其证。
- **手算之偏与同类返值之错位**：5c3c85dfd（捕获之记之偏误算）须由编译器算偏之结构；135afbbed（同长同类四路之返次序错位）须具名之项。二者皆在本提案之外。

## 十、兼容与迁

- 今之程序：细化与存在之类，惟令昔见拒者得过。惟一之行变：不可能之支由类之误改为示警；非测试之码无此构造器，实无所影响。
- 新书法乃放已有之书之定义域，旧书不易；惟一之外：旧式兼容之 `化「元类型」者「甲」而 B`（全仓无一处），改为报误，示以改用 `承「甲」而 B`。
- 「列」内建：「多态列」之定义改为内建之别名，源码不易。「列」之类身若随之而易，接口清单中涉「列」之签名之表亦易，须依接口清单之则重生诸适配之 `宿主提供.json` 与 `启动接口.json`。
- 列之组段之表：运行之内表易，宿主之界出入之转函随之而改，界之式不易。
- 工具链：编译器源码欲用新能，须先由 CI 发支持之之工具链于 historical-binaries，后改 `.github/workflows/main.yml` 之 `YY_WASM_TOOLCHAIN_URL` 与 `YY_WASM_TOOLCHAIN_SHA256`，并更本机稳定之器。
- 每步皆易编译器之义：须全自举（yy3 与 yy4 逐字节同），行相关前缀之全树测，交 WP8 作原生全验。

4. 依内建之值之类：放「旧类型参数定义域检查」，类之构造器受内建之参、`化…者…而`、`承…者…而`、规范、推之扩、依值之模式配；同改《类型与模块》《词法与语法》《标签函数类型》。
