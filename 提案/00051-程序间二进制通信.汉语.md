## 一、缘起

现在豫言程序之间的消息是“一行籍册文字”：发的一方用「写数据文」把数据根写成一行，收的一方按换行切开（「将作读行」，`库/营造/交役。豫`），再用「析数据文」走一遍完整的语法解析，读回数据值。文件内容要先编成卦文，再塞进行里。

这一套已经出过事：

- #441：跨片的长行先是被平方复制；改法又把片的先后拼错，代役解不出长派役行，将作每五秒重派一次，一件任务打转了两百多圈（225c5a5ab 修）。原有测试的长行全是同一个字母，次序错了也测不出来。
- 卦文让文件大三分之一，行内还要再转义一层。取引上限三十二兆、连接积压上限二百五十六兆都由此而来（#179）。
- 将作日志里，一条同僚报况常常要处理七八百毫秒以上（“慢的一趟 … 最慢一件 同僚 …「报况」… 911 毫秒”）。

所需的底层能力都已具备：

- 传输层有二进制收发「告帛」「续告帛」「听帛」（`库/豫章/驿/宾主。豫`），异步版在 `将宾主。豫`；
- 可写字节数组「牍」有「置牍」「写牍帛」「读牍四字节」「牍作帛」（`库/豫章/形制/简牍。豫`）；
- 小数与六十四位位型互转有「小数作位」「位作小数」（`库/豫章/算术/变通。豫`）；
- 字符串转 UTF-8 字节有「作帛」；反过来用「本术」之「强作」，因为文与帛是同一种内存表示（群书、诏令里的「帛作文」就是这么写的）。

缺的只是数据值的二进制编码和分帧。

## 二、目标

1. 读一条消息只是按长度收满字节再解码：没有换行切分，没有转义，没有语法解析。
2. 文件按字节原样传，大小只受内存限制。
3. 一次切换：新协议上线后不留文字协议的兼容路径；两边版本不合时，客退回本机执行，与将作没起时一样。
4. 给人读写的仍用 `。数据。豫` 文字：配置、数据文件、日志，以及 `豫构 将作 状态` 的打印。

## 三、籍帛：数据值的二进制编码

籍册的数据值现有八种（`库/籍册/籍册。豫:23`），本提案新加第九种「数据帛」（化「帛」为「数据值」），专门装字节。每个值以一个字节的类别号起头：

| 类别号 | 值 | 后接 |
| --- | --- | --- |
| 0 | 数据空 | 无 |
| 1 | 数据爻，阴 | 无 |
| 2 | 数据爻，阳 | 无 |
| 3 | 数据整数 | 之字形变长整数：先把有符号数折成无符号数，再按七位一组、低位在前写出，最多十字节 |
| 4 | 数据小数 | 八字节，「小数作位」得到的位型，低字节在前 |
| 5 | 数据字符串 | 变长整数写字节数，再接 UTF-8 字节 |
| 6 | 数据符号 | 同数据字符串 |
| 7 | 数据列 | 变长整数写项数，再接各项 |
| 8 | 数据记录 | 记录名（变长整数字节数加 UTF-8），变长整数写栏数，再接各栏（栏名加值） |
| 9 | 数据帛 | 变长整数写字节数，再接原样字节 |

一条消息就是一个数据根，写法是：变长整数写栏数，再接各栏（栏名加值）。

籍册加两个函数：

- 「编籍帛」：数据根编成帛。先一遍算出总字节数，「置牍」一次，再一遍写进去，最后「牍作帛」。
- 「解籍帛」：帛解回数据根，返回成败。截断、类别号不认、长度越界都报败，不抛异常。解码时按下标读，不另外复制。

「数据帛」只在籍帛里出现。`。数据。豫` 文字里不收它：「写数据文」遇到它只写一个占位（如 `「帛」于「三千」`，表示三千字节），供日志用，「析数据文」不读回。

拟名“籍帛”，取《墨子·明鬼》“书之竹帛，传遗后世子孙”：竹简（`。数据。豫` 文字）写给人看，帛书（字节）交程序传递。帛在豫言里本来就指字节串（提案 00029）。

## 四、封：长度前缀分帧

- **开门先递刺**：客一连上先写八字节的刺：“籍帛”两个字的 UTF-8（六字节），版次一字节（取 1），零一字节。服务验过客的刺才回写自己的。收到的头八字节对不上，就立即关门；换链前的旧版文字客没有刺，服务关门前照旧版写法答一行“令牌不符”，旧客立刻报错退出（用户 2026-10-24 定）。
- **一条消息一封**：八字节无符号长度（低字节在前），后接那么多字节的籍帛。协议不规定长度上限；实现上长度大于一太字节就当坏封，关门。
- **收**：每条连接有一个封积。先收满八字节的长度，再按长度「置牍」一次，后来收到的片用「写牍帛」依次填进去，填满了就「牍作帛」，交给「解籍帛」。不扫换行，不反复拼接，片怎么切结果都一样。非阻塞读的结果仍分三种：整封、未整、门绝，与「将作读行」相同。
- **发**：「编籍帛」得到帛，前面接上八字节长度，用「告帛」发出，一次写不完就用「续告帛」接着写。

拟名“封”，取“封事”（《汉书·宣帝纪》“令群臣得奏封事”）：外面题写长短，里面封着正文。收发两个函数拟名「投封」「拆封」。

## 五、文件按帛直传

借场取引的答复、托役回传的产物与阶段缓存、过录的文件，一律作为「数据帛」放进消息，不再编卦文。取引上限与积压上限随之去掉，只受内存限制。大文件分段（每封几兆、多封续传）留待后续版本。

## 六、迁移顺序

1. **籍册**：加「数据帛」「编籍帛」「解籍帛」。测试覆盖每种值的往返、截断、坏类别号和超长字符串。
2. **封**：「投封」「拆封」与封积，放在籍册里（籍册依赖豫章，驿在豫章里）。测试覆盖逐字节切片、跨多片、超过六十四千字节与三十二兆的长封。
3. **将作一族一次换**：交役（客）、将作（服务）、代役、同僚（结交、报况、托役、托毕、取引、问沙、过录、整客转发）、监工订阅。删掉「将作读行」和卦文收发。全部在同一次合入里完成，合入后三台机器（本机、pit-mac、pit-pc）一并换链。
4. **行在服务连接**：`应用/豫构/行在。豫` 里按行收发的部分。
5. **邻籍**（局域网多播发现）：一个数据报就是一封，免去开门递刺，放在最后改。

第一、二步可以并行。第三步要从 yybs 开工，「钩议将作三事」（#450、#460、#461）已于 75fec4af5 合入。第三、四步改的文件不重叠，也可以并行。

## 七、新旧工具链怎么处置

照“直接切换不留兼容”：新将作只认封，不留文字路径。版本不合时，各处的表现如下：

| 情形 | 表现 |
| --- | --- |
| 旧客连新将作 | 新将作读到的头三个字节是“「”（旧版文字消息），关门前照旧版写法答一行“令牌不符”（用户 2026-10-24 定）：照常的旧构建立刻报“令牌不符”退出，设了 `豫言将作=关` 的退回本机执行，不再卡住。没加这一行时实测旧客会一直重试，见实施记录 |
| 新客连旧将作 | 旧将作在等换行，没有回音；新客收到的头几个字节不是刺，或连接开着、三十秒里一个字节都没收到，就认作旧版将作，印一行提示，整次构建在本机执行（「将作旧版弃」）；对方一个字节都没发就关了门的，照连接出错重试。一个进程只等这一次 |
| 代役 | 由客的工具链起；能登门的客都是新版，起出来的代役也是新版 |
| 三台换链有先后 | 刺对不上就不结交，监工里显示未结交；三台都换完即恢复 |
| 旧监工 | 订阅不上，一直显示“等待将作”；换上新工具链即可 |
| CI | CI 不起将作，不受影响 |
| 自举 | 旧的稳定工具链当一级驱动时连不上新将作，一级在本机执行；二级起就是新版 |

编译语义号不必换：协议不属于编译产物。

上线步骤：第三步合入后，在同一时段给三台换链，并重装本机工具链；各任务仓根硬链共用链的，随之一起换上。先停掉在跑的旧构建（不停的话，它们碰上新将作会报“令牌不符”失败，要重跑）；旧将作用旧工具链的 `豫构 将作 停止` 停，或按进程号停（新豫构发的停止请求旧将作听不懂，新豫构收不到刺时印一行说明）。

## 九、定稿时的决定

用户 2026-10-24 审定，四条原先待定的都照草案：

1. 封的长度用定长八字节。
2. 「数据帛」在 `。数据。豫` 文字里写占位。
3. 用文件交换的几处（壳请求的窗请文件 `库/几席/壳索。豫`，行在作业与远程登录作业管理的 `状态。数据。豫`）都是「定稿」原子写的，没有分帧问题，保持文字。
4. 新客连旧将作，等五秒收不到刺就退回本机执行，可以接受。实施时放宽到三十秒（见实施记录“旧版判定放宽”）。
