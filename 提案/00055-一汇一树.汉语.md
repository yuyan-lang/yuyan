## 一、缘起

用户 2026-10-25 提出：捷思引擎不写解释器，直接编成豫言的某一中间层；网汇也编进豫言的中间阶段，执行与优化用同一套框架；HTML、CSS 与设计语言几乎共用一套框架。理由是 AGENTS.md 要求同类的功能不维护两份实现。用户随后确认：网汇与捷思的后端用同一套豫汇，这样就能共享底层的优化结构。

## 三、定论

### 一汇：凡是代码都编成豫汇

豫汇以下（冶铸出原生机器码，笔受出网页后端的网汇回收版，裸机，诺驿）只有一份，优化做在这一份上，捷思、网汇、豫言与设计表达式一起受益。

1. **捷思。** 急就的解析器出语法树，直接生成编译器类型擦除后的「无类」表达式树（正体之前那一层），不经刊定、正名、证义：捷思的值一律是同一个动态类型，类型检查没有东西可查，又是编译里最慢的一段。此后走现成的正体、闭包转换、函数提升、笔受出豫汇；原生上由冶铸出机器码，经执行器的单元装载装进页程运行。
2. **运行时照用。** 捷思的闭包就是豫言的闭包，回收就是豫言的回收；急就现有的内建对象、属性表、形状与运行时（约三万行）原样保留，编出的代码调用它们。属性读写的快路照形状加内联缓存生成。
3. **惰性编译与缓存。** 脚本先整篇解析，函数第一次被调用才编；编出的单元按内容摘要落盘缓存，跨页面、跨重启命中，常用库只编一次。`eval`、`new Function`、事件处理器属性走同一条路。生成器与异步函数按续延改写（蜕类已有当前续延调用的展开）。
4. **首屏延迟。** 冶铸加一档不做优化的快编，冷代码用它；热函数再按优化档重编。不保留解释器。
5. **网汇。** 用译场 `网汇` 的二进制读与校验把模块读成豫汇篇结构，交冶铸与单元装载；网汇的 JS 接口（`WebAssembly.instantiate` 等）照旧。浏览器网汇包的解码、验形与执机退役。捷思与网汇互调就是豫汇函数之间的调用。
6. **网页后端。** 豫汇经笔受出网汇回收版，交宿主浏览器的引擎编译；网汇模块原样交宿主。
7. **匠心式。** 设计树码里的式码也编成豫汇，匠心式求值器退役。

### 一树：设计作品并入一体引擎

00052 已让系统界面与网页共用篇象、计算样式、章法、映元与交互；本节把设计作品也放进去，两种写法从此只差入口。

1. **场景节点即篇象节点。** 组、矩形、圆、椭圆、线、径就是篇象里的 SVG 元素 g、rect、circle、ellipse、line、path；文字、段落是文字节点与段落盒；图像是替换元素；横排、竖排是弹性盒；图层的模糊、投影、颜色矩阵、混合模式、遮罩是 CSS 的 filter、mix-blend-mode 与 mask；三维视口、面板、公式是篇象的替换元素，画法仍在匠心。
2. **设计属性就是计算样式。** 作品直接填 00052 第二条的计算样式槽列，不走层叠。
3. **动画一套。** 信号（关键帧、缓动、弹簧、表达式）是唯一的动画引擎；CSS transition、@keyframes 与网页动画接口（Web Animations）都编成信号。网动自带的缓动与时间线退役。
4. **推演即一帧。** 推演就是一体引擎在时刻 t 出的一帧：按信号取各属性在 t 的值，章法排版，设色出映元，匠心渲染。推演自己的排版退役。
5. **交互一层。** 作品的交互状态机改为篇象事件，处理器表达式照“一汇”编成豫汇。
6. **SVG 一份。** 白描的文档模型并入篇象：SVG 元素就是篇象节点，设色直接画；白描的路径解析、滤镜运算、渐变留作库。内联 SVG 不再序列化转交。
7. **一种存档。** 设计树码是这棵树的二进制存档：设计作品与网页都能存成设计树码再放出来；网作匠（网页转设计）缩成“存档”一步。

## 四、分步

1. **网汇编豫汇（先做）。** 浏览器网汇包改用译场 `网汇` 的读与校验，接冶铸与单元装载；执机删去。验收：网汇规范测试集与 WPT `wasm/jsapi` 的通过数不少于现在；整数与浮点计算样例比解释器快一个数量级以上；网页后端原样交宿主。
2. **量冶铸。** 把官网、维基、github 的脚本按函数估出豫汇的规模，量冶铸每千行豫汇的编译耗时与单元装载耗时，定快编档要做到多快。
3. **急就编豫汇。** 以新核心的解析器出语法树，写无类树生成：表达式、语句、函数与闭包、异常、生成器与异步；属性快路接形状与内联缓存；内建与运行时照用。test262 不少于虚拟机再切换，切换后字节码与虚拟机删去。
4. **匠心式编豫汇。** 式码改出豫汇，匠心式求值器删去。
5. **设计作品并入篇象。** 场景节点映成篇象节点，信号接管 CSS 动画，推演改走一体引擎，白描并入，设计树码存档化。与 00052 第二、三期同步推进。

## 五、风险与对策

- **首屏延迟。** 惰性编译、摘要缓存与快编档三条兜底；第二步先量后定。
- **编译器进页程。** 页程要带编译后段（正体到冶铸）与单元装载，壳已经这样用；程序体积按 #409 的只读数据办法控制。
- **网页后端太碎。** 每个函数一个网汇模块开销大：按脚本或按批合成一个模块再交宿主。
- **捷思语义。** `with`、直接 `eval` 的作用域、`arguments` 映射、生成器：按续延改写，或走运行时的慢路；test262 兜底。
- **在跑各路。** 云页脚本路的形状、驻留与内联缓存直接用在编出的代码上；国际化、脚本测两路做内建与接口，不受影响；网汇包眼下没有在跑的路。
