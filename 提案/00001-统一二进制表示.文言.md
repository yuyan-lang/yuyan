# 提案 00001：统一二进制之表

| 项 | 文 |
| --- | --- |
| 号 | 00001 |
| 状 | 草案 |
| 提于 | 2026-10-03 |
| 所及 | 编译器核心中间产物之缓存；云端所存签名与终链所需之物 |

此篇为豫言语法树统一二进制之表（下称“树码”）之提案：编译器诸阶之「表达式树组」，以一种紧而有定之二进制编码存取之，以代今之 JSON 缓存，亦为云端存签名与链接单元之式。

与[汉语稿](00001-统一二进制表示.汉语.md)相应。

## 一、所议之事

| 号 | 议 |
| --- | --- |
| 议一 | 名其式曰「树码」，文件之后缀为 `.树码`；首六字节为“树码”二字之 UTF-8：`E6 A0 91 E7 A0 81` |
| 议二 | 一式统诸阶：凡「表达式树组」（即「文件定义列」）皆用之；别设「串列」一种，以存依赖表等串之列 |
| 议三 | 其构以构表定之：「节点名称」及诸嵌枚举之构造器，依表中之次编号；表之摘要书于文件之首；摘要不合者，以缓存未中处之 |
| 议四 | 串惟存一次：定义之名、串之载、自由变量之名、绑定之名示，皆入串表，正文惟书串号 |
| 议五 | 文件之径入径表，记为所有者、包名、包内之径三段，正文惟书径号 |
| 议六 | 有定之形：同树组配同构表，所编之字节必同，摘要可径用以去重与签名 |
| 议七 | 初版不为子式之共享，留标 4 以待之；既测而后定其入二版与否 |
| 议八 | 先以可选之式接于编译器之缓存，验而合格乃改为默认，并改「导出中间文本」为默认关闭，`。豫` 文本惟调试时书之 |
| 议九 | 绑定之名示依“前缀加末之十进制序号”拆而书之：前缀入串表，序号书于正文。编译器所生之名示多为“常量内联参数值58”之类带序之名，拆之则同前缀惟存一次 |

## 二、所以然

下列之数，2026-10-03 于本机测之。

1. **缓存过巨**。本机 `.yybuild` 共 325 GB，缓存目录一百六十三；`yy4_bs` 编译器之缓存目录 22 GB，所涉源文件 3916。「导出中间文本」默认开，每阶于 JSON 之外别书 `。豫` 文本一份：是目录中 JSON 居 14.3 GiB，`。豫` 居 7.5 GiB。
2. **其冗在构**。中间之物为层层展开之 JSON 树，每节皆重书其键与名，如 `{"类型":"式节点","节点名称":{"名称":"拉姆达抽象","参式":"显式"},"参数":[…]}`。取「闭包形式」之文件二百，原文 31.8 MB，`gzip -9` 之后 0.77 MB，约四十一分之一。
3. **读写皆迟**。读缓存者，先尽析 JSON 之文为「结森」之值，再转为表达式：9 MB 之「闭包形式」读之须 484 毫秒，析居 74%；写同文件，JSON 编码须 1.72 秒。二进制可一过而径成表达式，见第十节之较。
4. **云端需之**。依《重建豫言云开发平台》之新向，构惟行于所接之机，云上惟存各文件之「签名元数」（编译器一构共 36.4 MiB）与终链之入「闭包形式」（JSON 共 582.2 MiB）。体之大小，即上传所占带宽之所系。
5. **摘要须恒**。内容寻址、去重与构建之签名，皆求同物得同字节；今之产物犹带本机之绝对径（如 `豫言模块__Users_zc_…`），二机所得之字节乃异。

## 三、所求与所及

所求：

1. 未压之前，「闭包形式」之树码小于同物 JSON 之什一。
2. 读速胜 JSON，写速不逊 JSON。
3. 编码有定：同入必得同字节。
4. 与径无涉：同包于二机所编之树码相同（以第七节所言编译器之改为前提）。
5. 一编解器通诸阶；增节点名称者，惟改构表与其载之编解。

所及：编译器核心缓存中之「表达式树组」与「串列」；云端所存之签名元数与链接单元。

今不及者：供人读之书法（仍用 `。豫` 文本，调试时生之）；传输之压缩（付之 HTTP）；就地之改与随写；Wasm 产物本身（已为二进制）。

## 四、所表之物

树码所表之值，即编译器中此诸类，定于 `库/编译器核心/编译数据/抽象绑定树结构/抽象语法树/抽象语法树数据。豫`：

```yuyan
「表达式」立「元类型」也。
  「式节点」立化「节点名称」而化（「列」于「表达式」）而「表达式」也。
  「绑定」立化（「或可有」于「字符串」）而化「表达式」而「表达式」也。
  「绑定变量」立化「整数」而「表达式」也。
  「自由变量」立化「字符串」而「表达式」也。

「文件定义列」即「列」于（「字符串」合「爻」合「表达式」）也。
「表达式树组」即「文件定义列」也。
```

- 「式节点」者，有名之节，其名为「节点名称」九十三构造器之一，各有其载。
- 「绑定」引一变量，其名惟为示；「绑定变量」以 de Bruijn 之序指外层之绑定。
- 「自由变量」以名引之。
- 一树组者，数定义也，各有名、公开与内容，其先后有义。

载中所见之类：整数（六十四位有号）、小数（六十四位浮点）、串、爻、列、或可有、元组，及五嵌枚举——「参数形式」五构造器、「内建常量」十七、「结构名称操作」七、「定义透明性」二、「注释方向」二。「源码范围」者，（文件，始行，始列，终行，终列）也。

## 五、编码

### 5.1 基本之单位

| 所书 | 编法 |
| --- | --- |
| 无号整数 | LEB128，取最短 |
| 有号整数 | 有号 LEB128（与 Wasm 同），取最短 |
| 小数 | 八字节小端 IEEE 754；NaN 皆书 `7FF8000000000000` |
| 爻 | 一字节，阴为 0，阳为 1 |
| 串号、径号、个数、序数 | 无号整数 |

LEB128 之编，沿用 `库/编译器核心/网页汇编核心/二进制生成。豫` 之「网页无符号编码」「网页有符号编码」；其解，用同目录二进制读取之篇。

### 5.2 文件之布

```text
文件       = 魔数 版本 种类 结构表摘要 串表 路径表 内容
魔数       = E6 A0 91 E7 A0 81
版本       = 无符号整数，本提案为 1
种类       = 字节长 UTF-8字节，如“闭包形式”“签名元数”“串列”
结构表摘要 = 32 字节 SHA-256
串表       = 个数 { 字节长 UTF-8字节 }
路径表     = 个数 { 路径条目 }
内容       = 树组内容 | 串列内容
树组内容   = 定义个数 { 名串号 公开 体字节长 体 }
串列内容   = 个数 { 串号 }
```

- 每定义记其体之字节长，读者可越所不用之定义，亦可并解之。
- 种沿今缓存之信息名（「闭包形式」「签名元数」等），文件名为 `<源文件之径>.<信息名>.树码`。

### 5.3 表达式

表达式依先序书之，每节以一标（无号整数）始：

| 标 | 义 | 其后 |
| --- | --- | --- |
| 0 | 自由变量 | 串号 |
| 1 | 绑定变量 | 序 |
| 2 | 绑定，无名示 | 体 |
| 3 | 绑定，有名示 | 前缀串号、序号加一、体 |
| 4 | 留待子式之共享（初版不用） | — |
| 5 以上 | 式节点，节点名称之构造号为标减五 | 载、子式之数、诸子式 |

九十三节点名称之标，皆在五至九十七之间，各占一字节。

名示之拆号：名示之末若为十进制之数（恰为 0，或不以 0 始），则与前缀分之，前缀入串表，正文书序号加一；余名示全串入串表，正文书 0。如“常量内联参数值58”书为“常量内联参数值”之串号与 59。

### 5.4 载

每构造器之载，依构表次第书之：

| 载之类 | 编法 |
| --- | --- |
| 整 | 有号整数 |
| 小 | 小数 |
| 串 | 串号 |
| 径 | 径号（见 5.6） |
| 爻 | 爻 |
| 列于 T | 先书其数，次书各项 |
| 可 T | 0 为无；1 为有，其后书值 |
| 组〔T…〕 | 各项依次书之 |
| 枚举之名 | 其枚举之构造号，次书其构造器之载 |

如「源码范围」为 组〔径，整，整，整，整〕；「小数节点」之载为 小 加 组〔串，串〕（十进制之二段）。

### 5.5 串表

- 诸串皆入串表，正文惟书串号：定义之名、串之载、自由变量之名、绑定之名示（带序者惟存前缀），及径之三段。
- 编码器之串表须用散列之表。标准库之「串典」依列逐一而查，一文件中各异之串逾三万，则编码退为平方之时。
- 编号依初引之先后：先首定义之名，次首定义之体（先序），然后第二定义，以此类推。

### 5.6 径表

构表中标为 径 之载，文件之径也，如「文件引用节点」「文件定义引用节点」「唯一构造器节点」诸节之径，及「源码范围」之文件；全目以构表为准。皆入径表：

```text
路径条目 = 0 所有者串号 包名串号 包内路径串号
         | 1 绝对路径串号
```

- 编时依包上下文，易绝对之径为所有者、包名与包内之径；读时依本机之包上下文复为绝对之径。
- 无所属之包者，书为第二式。此文件出本机则不能复其原径，构建清单当标为“系于本机”。
- 径号依初引之先后编之，径之三段随之依次入串表。

### 5.7 有定之形

同树组配同构表，惟一种字节：

1. 定义守其原次。
2. 串号、径号依 5.5、5.6 初引之次编之。
3. 整数取最短；NaN 惟一位型；负零依原保之。
4. 名示依 5.3 之则拆号，可拆者皆拆。
5. 初版无可选之项：不压、不共、不齐。

文件之摘要，即全文件字节之 SHA-256，可径为内容之址。

### 5.8 例（示意）

设「拉姆达抽象」之构造号为 0，「显式」为「参数形式」之构造号 1；下式为定义「恒同」之体，「恒同」居串号 0。

```text
式节点（拉姆达抽象（显式），【绑定（可有『甲』，绑定变量 0）】）
```

于 JSON 为 147 字节：

```json
{"类型":"式节点","节点名称":{"名称":"拉姆达抽象","参式":"显式"},"参数":[{"类型":"绑定","可能名":"甲","绑定体":0}]}
```

于树码之正文为 8 字节：

```text
05        式节点，构造号 0（拉姆达抽象）
01        载：参数形式之构造号 1（显式）
01        子式之数 1
03        绑定，有名示
01        前缀串号 1（『甲』）
00        无序号
01        绑定变量
00        序 0
```

另加串表中『甲』之四字节（字节长 `03`，加 `E7 94 B2`）；此后『甲』再见，惟书一串号。

## 六、构表与版

- 构表列「节点名称」及诸嵌枚举之构造器，每构造器书其名与载之类，如：

```text
节点名称 拉姆达抽象 参数形式
节点名称 字符串节点 串
节点名称 文件定义引用节点 径 串 整
参数形式 多参数形 整
```

- 构造号即构造器于所属枚举中之次，自 0 始。
- 定文：每行书“枚举名 构造器名 载之类…”，行以换行相间，枚举依定次排列；摘要为此文 UTF-8 字节之 SHA-256。
- 构表书为豫言之数据，与编解器同目录：`库/编译器核心/编译数据/抽象绑定树结构/抽象语法树/序列化/树码结构表。豫`。豫言无反射，载之编解依构造器逐一手书，与今 JSON 序列化同法；测试逐构造器往返之，以核构表与编解器相合。
- 摘要于构建时求之而书为常量（构建宿主已有「获取文件SHA256」），测试核其与定文之摘要相同。
- 增删或易构造器之次，摘要皆变。编译器读摘要不合之缓存，以未中处之而重构；工具可依摘要自内容库取当时之构表，以解旧文件。
- 版号惟编码之则自变时加一，如增子式之共享。

## 七、与径无涉

径表已治结构之载中之径，然犹有二处携本机之径入产物：

1. 模块之名由绝对之径转义而生：`库/编译器核心/编译步骤/总体过程/编译过程工具。豫` 中 `『豫言模块_』附（「标识符转义」于「路径」）`，所得如 `豫言模块__Users_zc_repos_…`，散于诸串之载。
2. 「源码范围」之文件。

其一须改编译器：模块之名改由所有者、包名与包内之径生之。此为独立之改，树码不待之亦可用；惟其未成之前，异机所编之树码字节不同。其二入径表。

## 八、接于编译器之缓存

1. 编解器入编译器核心之序列化目录，分「树码编码」「树码解码」「树码结构表」三篇。
2. 新增编译之选项 `--中间格式 结森|树码`，先默认 `结森`。
3. `库/编译器核心/编译步骤/总体过程/编译文件缓存工具。豫`：
    - 「写树组缓存」依选项书 `.树码` 或 `.json`；`。豫` 文本仍由「导出中间文本」司之。
    - 「读树组缓存」先求 `.树码`，无则读 `.json`；依首之魔数辨其式。
    - 「读串列缓存」「写串列缓存」与文件依赖之读写，改用「串列」之种。
4. 文件之读写，用标准库 `操作系统/文件系统` 之「读文件字节串」「写文件字节串」。
5. 验而合格，改默认为 `树码`，改「导出中间文本」为默认关闭；JSON 之读留供调试之器。

## 九、器

新增开发之器 `yy树码`，居 `应用/开发工具/树码/`，以豫言书之：

- `转换 <文件>`：`.json`、`.树码` 与 `。豫` 三书互转。
- `统计 <缓存目录>`：依阶列文件之数、JSON 与树码之字节及其比。
- `核对 <缓存目录>`：每文件为“JSON → 树码 → 表达式”之往返，与径析 JSON 所得逐树相较。

## 十、三书之较

依 2026-10-03 于本机所测：读 JSON 者，其劳多在析；`。豫` 之重析，迟于读 JSON 约三十倍；树码之读估速 1.1 至 4.6 倍、写估速 1.3 至 25 倍，文件愈大其差愈著；全缓存约为 JSON 之十二分之一，并默认所书之 `。豫` 计之，自 21.7 GiB 降至约 1.2 GiB。

### 10.1 测法

- 样取自本机 `yy4_bs` 编译器之缓存目录，凡四文件：「多态列」之签名元数与词法形式、「表达式解析」之闭包形式、「客体执行用例」之闭包形式（9 MB，为大样）。
- JSON 与 `。豫` 之读写：用「阶段源码性能」测器（`库/编译器核心/编译步骤/总体过程/阶段源码性能。豫`；本提案于其中补读文件、JSON 析、树组还原三项之计时）。每样行三次，各项取其最小；十二次皆精确往返而合。
- 树码之体：依第五节之则逐文件编为树码，惟量其字节；另量“名示拆号”（见 5.3）与“子式共享”（标 4）二法。全缓存每阶各抽四十文件，以所得之比推之。
- 树码之时：今未有其实，依二保守之设估之。读 ≈ 读文件 × 字节之比 ＋ 树组还原：解树码与“由结森之值还原树组”所建之节同多，且省依键名逐一相较之劳。写 ≈ 源码编码 ＋ 写入 × 字节之比：二者皆一过行树、逐段而出。

### 10.2 体

单位字节。“树码”为第五节不拆号、不共享之书。

| 样 | JSON | `。豫` | 树码 | 树码·拆号 | 树码·拆号并共享 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 签名元数 | 11,803 | 3,904 | 712 | 712 | 712 |
| 词法形式 | 192,064 | 23,092 | 39,042 | 39,042 | 39,042 |
| 表达式解析·闭包形式 | 430,839 | 297,536 | 69,793 | 59,469 | 58,656 |
| 客体执行用例·闭包形式 | 9,238,892 | 5,068,072 | 1,250,549 | 433,517 | 314,492 |

`gzip -9` 之后，单位字节：

| 样 | JSON | `。豫` | 树码·拆号 |
| --- | ---: | ---: | ---: |
| 签名元数 | 439 | 436 | 319 |
| 词法形式 | 13,684 | 6,281 | 8,806 |
| 表达式解析·闭包形式 | 17,950 | 18,764 | 12,317 |
| 客体执行用例·闭包形式 | 159,205 | 214,955 | 85,621 |

- 树码之字节多在串表。大样 125 万字节，串表居 84 万，其中 80 万为 31,332 各异之绑定名示（如“常量内联参数值58”），正文惟 41 万；既拆号，降至 43 万，约 JSON 之二十一分之一。此议九之所由也。
- 词法形式之 `。豫` 最小：惟存源码，令牌于读时以词法器重算；树码与 JSON 皆存「令牌」一项。
- 既压之后其差乃缩：树码（拆号）小于同压之 JSON 1.4 至 1.9 倍，传输时仍宜加 HTTP 之压。

### 10.3 读之时

单位毫秒。

| 样 | JSON 读文件 | JSON 析 | 树组还原 | JSON 合 | `。豫` 析 | 树码（估） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 签名元数 | 0.32 | 2.34 | 18.36 | 21.0 | 25.2 | 18.4 |
| 词法形式 | 0.71 | 8.87 | 22.71 | 32.3 | 3.1 | 22.9 |
| 表达式解析·闭包形式 | 1.23 | 16.03 | 27.40 | 44.7 | 247.0 | 27.6 |
| 客体执行用例·闭包形式 | 20.60 | 358.80 | 104.33 | 483.7 | 14,540.6 | 105.3 |

- 读 JSON，析居其多：大样 484 毫秒，析居 359（74%）。
- `。豫` 之重析迟于读 JSON 约三十倍（14.5 秒对 0.48 秒），宜供人读，不宜为缓存之读径；词法形式例外，所读惟源码。

- 依大小折之（以二闭包形式之样拟之）：读 JSON 约 23 毫秒加每 MB 50 毫秒，读树码估约 24 毫秒加每 MB 9 毫秒。

## 十一、测与验

样：本机 `yy4_bs` 编译器一构之缓存目录（22 GB），及其中「闭包形式」之文件二百。

| 所验 | 准 |
| --- | --- |
| 往返 | 诸阶诸文件，经树码往返，与原树结构相等 |
| 体 | 「闭包形式」未压之前小于 JSON 之什一；并报树码与 JSON 各经 gzip 之大小 |
| 速 | 编译器一全构中读缓存之总时少于 JSON；写不逊 JSON |
| 定 | 同树组二编得同字节；与径无涉之改成后，二机得同字节 |
| 自举 | 以 `--中间格式 树码` 行全自举，`yy3_bs.wasm` 与 `yy4_bs.wasm` 逐字节相同 |

## 十二、兼容与迁

- 缓存目录依编译器之径与修改之时而分，新旧编译器各用其缓存，稳定之编译器不遇新式之文件。
- 读依魔数辨式，同目录中新旧可并存。
- 摘要不合者以未中处之，至劣不过多一重构。
- 云端惟受树码；所接之机于上传前转之。

## 十三、他途

| 途 | 所以不取 |
| --- | --- |
| 压缩 JSON（gzip、zstd、brotli） | 体可减约四十倍，然读之仍须尽析 JSON，串亦不能共存一份；宜置于传输之层，与树码并用 |
| 通用二进制之式（CBOR、MessagePack） | 犹须逐书键名，或另配结构之说；于绑定与 de Bruijn 之序亦无专法 |
| Protocol Buffers 之属 | 须外器与别种结构之述语，与“惟书豫言、不自造 DSL”之约不合 |
| 惟留 `。豫` 文本 | 人可读之，然体大而析迟 |

## 十四、未决

1. 子式之共享：同定义内重出之子树书为回指（标 4）。依第十节之测，既拆号而加共享，全缓存惟再省一成余（1,243 MiB 降至 1,100 MiB），然「检查后定义」「检查后对象」可省半以上；二版宜否惟于此二阶开之，待定。
2. 源码范围宜否别为一段，使去位置之树码于仅改注释、空行之后犹同，以便跨提交去重。
3. 构表定文之格式与所居是否得宜，摘要宜否兼覆编码之版。
4. 小数之负零宜否规为正零。
5. 名「树码」与后缀 `.树码` 宜否。

## 十五、施行之序

1. 构表与编解器（含名示拆号与散列之串表），并逐构造器往返之测（编译器核心之单元测试）。
2. `yy树码` 之转换、统计与核对，于 `yy4_bs` 之缓存测出体之大小与往返之果。
3. 接缓存之读写与编译之选项，行全自举。
4. 测读写之时，合准乃改默认之式，并改「导出中间文本」为默认关闭。
5. 改模块之名使与径无涉（独立之改），而后验二机得同字节。
6. 依测之果定子式之共享。
