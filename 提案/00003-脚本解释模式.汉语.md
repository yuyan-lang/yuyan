# 提案 00003：脚本解释模式

| 项 | 内容 |
| --- | --- |
| 编号 | 00003 |
| 状态 | 草案 |
| 提出 | 2026-10-04 |
| 范围 | 新的源文件种类 `。脚本。豫` 及其执行规则；编译器核心前端的逐组入口；新库「脚本解释」（读句、求值、库缓存、句缓存、宿主代办）与「壳命令」；豫言操作系统默认壳的脚本执行与一个新宿主服务；宿主上的命令行工具 `yy脚本`；包源码收集、造盘与全树测试的相应规则；《执行与编译》《词法与语法》的相关规范 |

这是给豫言加入脚本解释模式的提案：以 `。脚本。豫` 结尾的文件是普通豫言源码，解释器逐行读入，每凑满一句就检查并执行这一句，无须事先编译成 Wasm。脚本在豫言操作系统的壳里直接运行，用法同 shell 脚本：运行程序、读写文件、取参数与环境变量、按退出码分支；要写逻辑时，用豫言的条件、递归与模式匹配。前端与编译器共用，所以脚本与编译后的同一份源码接受同样的程序、得出同样的结果；后端换成在擦除后的树上直接求值的求值器。同一个解释器也在 Node 宿主上运行。

本文与[文言稿](00003-脚本解释模式.文言.md)同步。

## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | 新增源文件种类 `名。脚本。豫`：内容是普通豫言源码，文法与类型系统都不变；顶层裸式就是要执行的语句，按《执行与编译》行一“源文件顶层裸式会执行”的既有规则依次执行。脚本不能被导入；「收集包源码」与造盘的「编译预置们」都跳过它，造盘时原样入盘 |
| 议二 | 逐句执行：逐行读入，按《词法与语法》语一的切句规则（圆括号深度零处的 `。`）凑满一句就处理一句；`乃` 句与紧随的同名定义句合成一组。每组先过与编译器相同的前端（语法分析、名称解析、类型检查、模式展开、类型擦除），立即求值，然后才读下一句 |
| 议三 | 出错与退出码：某组有语法或类型错误，报出错句的文件、起止行与诊断，退出码 2，此前各句的效果保留；未接住的异常交给标准库登记的顶层处理（“未捕捉的豫言异常：…”，退出码 1），另附所在句的位置；`退出进程` 给出的码照用；脚本里的陷阱沿用客体二号的码（整数除零与无效转换 125、数组越界 127、栈溢出 122、堆内存不足 120）；Ctrl-C 为 130。选项 `--先查` 先把全文过一遍前端，无错再执行 |
| 议四 | 求值器：输入是“擦除后形式”的树（与编译器缓存同一阶段）；值按《总纲》总三的无类型中间值表示；用显式续延栈的循环求值，尾调用与深递归都不占宿主栈；异常、提前返回、递归单元按《执行与编译》行二、行三 |
| 议五 | 原语与宿主导入：树里的 `豫言_` 原语由求值器逐个实现；`宿主导入：模块：字段：签名` 按签名的边界形（《网页汇编接口》网五）转换参数与结果，转给解释器自己的同名导入。没有代办的，照宿主的做法在调用时报“接口函数未绑定：模块.字段”。程序名、命令行参数、退出、工作目录与环境变量改指脚本自己的 |
| 议六 | 隔离：会陷阱的原语（整数除与取余遇零、小数转整数越界、引用数组越界等）先检查再调用；失败即中止进程的宿主导入（如读不存在的文件）先查路径，查不过以 1 结束脚本；续延栈设上限（缺省一千万帧，嵌入者可改），超过即报“栈溢出：递归过深”。这些错误只结束脚本，解释器所在的进程照常运行 |
| 议七 | 库缓存：脚本导入的模块经同一前端处理，存下前端所需的接口与求值所需的擦除后形式，格式用现行的树码；宿主上按需生成并缓存；豫言操作系统上由造盘预先生成、随盘只读。模块在首次被引用时按定义次序初始化一次 |
| 议八 | 句缓存：以（解释器版本、库缓存版本、脚本开头到本组末尾的文本摘要）为键，存每组过前端的结果；未改动的句子重跑时跳过前端。造盘时给预置树里的脚本预先生成 |
| 议九 | 豫言操作系统：解释器以库的形式链进默认壳，脚本在壳的任务里执行，所以脚本能用内核唯一的子进程槽运行程序。`「运行」于「路径」…` 遇 `。脚本。豫` 时在壳内解释执行，其余照旧；`「脚本」于「路径」` 按后缀分派，`.txt` 命令脚本照旧。脚本结束后壳恢复原来的工作目录与环境变量。新增宿主服务「取中断挂起」，供求值器轮询 Ctrl-C |
| 议十 | 宿主上的工具 `yy脚本`，与壳用同一个库：`yy脚本 路径 参数…` 执行，`--只查` 只过前端，`--先查` 先查后跑，`预备` 生成库缓存与句缓存。首行以 `#!` 开头时跳过该行 |
| 议十一 | 编译模式照旧：同一份脚本可由 `yy豫构.wasm 文件` 编成 Wasm，顶层裸式在模块初始化时依次执行。两种模式按《总纲》总〇的“源语言兼容”核对，只有出错的时机不同；全树测试对有期望输出的脚本两种模式都跑、逐字比较 |
| 议十二 | 壳命令库：壳的正式命令（`命令登记` 里的成员路径）同时作为豫言库「壳命令」提供，模块「文件」里有「读取」「写入」等。脚本里写 `「文件」之「读取」于『/数据/说明.txt』。`，与壳里输入的正式句式同形，参数写成字符串 |
| 议十三 | 不做：交互求值（读一句、印一值）、把壳的交互输入改为豫言句、在系统内编译成 Wasm、给脚本另开进程、脚本互相导入、求值器的提速（库函数直连、即时编译）。留作后续 |

## 二、动机

### 现有的壳

以下据 2026-10-04 yybs（8859ae0d1）与云仓的源码、文档整理。

| 实现 | 位置 | 运行在 | 输入写法 | 能写逻辑吗 | 怎样运行豫言程序 |
| --- | --- | --- | --- | --- | --- |
| 默认壳 | `豫言操作系统/裸机/壳/壳。豫` | 豫言操作系统，客体二号解释执行 | 正式句式 `「文件」之「读取」于「入口。豫」` | 否：没有变量引用、条件、循环与函数 | `「运行」于「/程序/甲.wasm」…`，程序须先在宿主上编好 |
| 早期整数命令壳 | `豫言操作系统/裸机/库/裸机后端/用户命令壳。豫` 等 | 裸机内核的用户任务（降级成机器码） | 空白分词 | 否 | 只运行整数子集的 Wasm |
| 豫言终端（yysh） | `应用/开发工具/豫言终端/` | Node | 空白分词，支持引号与转义 | 否 | 管理命令转给 `yy豫构` 等工具；外部程序按 PATH 运行 |
| 网页壳 | 云仓 `应用/豫言云工作台/` | 浏览器（界面命令）与云端 Worker（文件、编译、运行） | 正式句式，成员两级、参数至多八个；也收空格句式 | 否：一次一条命令，没有变量、管道、重定向 | `「程序」之「运行」`：云端编译，再在隔离 Worker 里运行（CPU 一秒） |
| 终端浏览器的脚本 | `应用/开发工具/终端浏览器/脚本*。豫` | Node | 网页里的 JavaScript 子集 | 是 | — |

几点观察：

1. 能写逻辑的只有终端浏览器：它解释网页里的 JavaScript 子集（词法、递归下降、树遍历求值，见 `脚本运行。豫` 的「执行」），与豫言无关。仓内没有在运行时求值豫言语法树或中间表示的解释器（底层后端只有编译期的常量求值），也没有交互求值。
2. 默认壳的 `脚本` 命令（`壳。豫` 的「运行脚本」）读入整个文件，空行与 `#` 起首的行跳过，其余逐行按正式句式解析，先印 `+ 行` 再执行，出错印 `错误：…` 后继续下一行；脚本里不能再用 `脚本` 或 `退出`。豫言终端在标准输入来自文件或管道时也逐行执行（相当于 `yysh < 文件`）。两者都只认自己的命令：行与行之间不能传值，也不能按结果分支，后面的命令取不到前面的退出码。
3. 默认壳与网页壳的正式句式已经是豫言的成员与应用写法：`之` 连成员，`于` 引参数。差别只在参数：壳把角引号里的文字当原文，豫言里字符串写在 `『』` 里。
4. 2026-10-03 的提交 1bb76a637 把默认壳的交互与脚本入口都改为正式句式；旧的重定向（`>`、`>>`、`<`）与顺序管道（`|`）的代码还在，已没有调用点（`壳。豫` 开头的待办事项）；`壳/测试/` 的输入文件还是旧句式。

### 系统里没有编译器

程序都在宿主上离线编译：`yy豫言系统 构建` 把预置目录树里以 `。豫` 结尾的文件编成 `.wasm` 写进盘（`豫言操作系统/裸机/库/裸机后端/系统构造。豫` 的「编译预置程序」「编译预置们」，经宿主子进程调用 `yy豫构.wasm 文件 … --编译器 yy4_bs.wasm`）。在系统里改了源码不能重新运行；要在系统里做带判断的自动化，只能回宿主改源码、重新造盘。每个编好的程序连同标准库约 340 KB 起（《示例》），而盘缺省 32 MiB、双区日志能存约 16 MiB。

### 前端的代价

1. **整套编译太慢**。2026-10-01 本机构建日志（`.yy构建日志/`）：`yy豫构.wasm 文件 豫言操作系统/裸机/示例/程序/你好。豫`，缓存已在，总用时 5971 毫秒。标准库依赖闭包共 54 个模块，各过依赖分析、语法解析、类型检查、跨模块优化、闭包转换五个任务，再加最终链接，共 271 个任务（24 路并行）；`你好。豫` 自己的五个任务只占 95、90、124、72、46 毫秒，最终链接 260 毫秒。2026-10-04 本机负载约 8 时编一个小测试文件，同样的流程用了 15.2 秒。脚本若每次都走这条路，单是启动就要几秒到十几秒。
2. **库的产物不小**。根目录 `yy4_bs.wasm`（10-03 构建，早于树码缓存）的缓存里，标准库 54 个模块：检查后对象 2.79 MB、检查后定义 3.62 MB、名称解析资料 1.36 MB、擦除后形式 1.79 MB（都是 JSON），对照标准库源码（不含测试）0.32 MB。现行源码的阶段缓存只写树码（`编译文件缓存工具。豫`）；提案 00001 实测树码约为同内容 JSON 的五分之一到二十一分之一（第十节）。云工的编译运行把整套标准库资料随编译器分发：gz 约 2.6 MiB，解压后的 JSON 约 57 MiB（`豫言操作系统/适配/编译运行/说明.汉语.md`）。
3. **求值面很小**。标准库的擦除后形式只出现 21 种节点：函数调用、参数、拉姆达抽象、内联虑、文件定义引用、外部调用（解析后外部调用节点）、元组构造、元组解构、唯一构造器序数元组及其两种投影、爻分支、递归、展开后内建、整数、字符串、小数、空值、擦除后类型、续延调用及其返回。外部调用共 157 种名字：`豫言_` 原语 92 个；`宿主导入：标准库：…` 65 个，带着边界签名，如 `宿主导入：标准库：打印行：串→元`。

### 客体二号上的速度、内存与服务

- **速度**：客体二号在原生宿主上解释编译器，单线程编译标准库每个文件约 45 秒（《豫言操作系统总体架构》2026-09-28 的进度）；同一编译器在 Node 上冷编打印探针连同标准库共约 5 秒（《原生工具链》，pit-mac M2 Max），折合每个文件约 0.1 秒，解释约慢五百倍。预编二之后，原生 5.24 秒对 Node 4.98 秒，比值约 1.05（同上，2026-10-02）。裸机上没有预编（预编只在 `yy原生生成` 生成的原生可执行文件里），壳由客体二号解释执行，QEMU 另有模拟开销；QEMU 上解释执行的速度还没有测过。
- **内存**：每个任务的线性内存至多 512 页（32 MiB），其中值栈、标签栈、帧栈等约 6 MiB，其余给模块、GC 堆与文件缓冲；内核的物理块池共 64 MiB，两个任务共用（《客体二号》“限制”）。作为参照，Node 上冷编打印探针连同标准库峰值约 0.52 GB（《原生工具链》）。
- **文件**：经标准库读写文件走裸机底层句柄，每个句柄的内容缓冲 409600 字节（`客体二号/裸机底层句柄。豫`），更大的文件按代码推断读写不了。JSON 缓存里最大的一个（`多态列工具` 的检查后对象，412084 字节）已经超过它。子进程程序的上限在代码里是 64 MiB（`布局。豫` 的「最大主程序长」），文档仍写 4 MiB。
- **服务**：构建宿主的「存放包上下文」（原语 73）裸机上没有实现，编译器核心每次编译都要调用它；`编译过程工具。豫` 还有一个顶层值在模块初始化时就调用「获取当前程序SHA256」。

所以在裸机上，每次运行都把前端从头跑一遍代价太高：启动时载入标准库接口、每组做类型检查，都要按“慢五百倍”估，内存也紧。本提案因此把“前端的结果能存就存”（议七、议八）放进设计，并把实测放在实施的第一步。

## 三、目标与范围

目标：

1. 豫言操作系统的壳里能直接运行 `。脚本。豫`：运行程序、读写文件、取参数与环境变量、按退出码分支，不经宿主编译。
2. 脚本与编译后的同一份源码接受与拒绝的边界相同、求值轨迹与输出相同（《总纲》总〇的源语言兼容）；出错的时机除外。
3. 逐句执行：前面的句子先生效；错误报到出错的句。
4. 脚本出错（含除零、越界、栈溢出）只结束脚本，壳照常工作。
5. 宿主上的 `yy脚本` 跑同样的脚本，供开发与全树测试使用。
6. 速度：第十二节的数字先作暂定目标，实施第一步实测后修订。

范围：新文件种类及其规范；编译器核心前端的逐组入口；新库「脚本解释」「壳命令」与新工具 `yy脚本`；默认壳与造盘工具的接入；全树测试的规则。

暂不涉及：第一节议十三列出的各项；壳的重定向与管道的正式句式（壳自己的待办，做好后对脚本同样有效）；内核任务槽的数目；云仓网页壳。

## 四、设计：脚本文件

### 身份

- 后缀 `。脚本。豫`，文件放在哪里都行；豫言操作系统上习惯放在 `/脚本/`。
- 内容按《词法与语法》的文法解析，用同一套类型系统，没有新语法。
- 「收集包源码」（`库/构建基础/包定位。豫`）像跳过 `。包。豫` 一样跳过 `。脚本。豫`，所以脚本放在包目录里也不会被当作模块编译；模块查找只认「普通模块后缀们」，脚本本来就不能被导入。
- 造盘的「编译预置们」把 `。脚本。豫` 原样写进盘，不编译。

### 导入

- 写法照旧，例如 `寻观「标准库」之书。`；导入句也是一句，执行到它时才载入被导入的模块。
- 导入解析只认包上下文（`语法分析/导入解析。豫`）。解释器给脚本合成一个包上下文：脚本自成一包，没有包描述，依赖为解释器能找到的全部包——宿主上是仓库里按豫构规则发现的包，豫言操作系统上是随盘库缓存里有的包（缺省为标准库与壳命令库）。

### 执行次序

- 顶层各句按出现次序处理：导入句载入模块；定义句求出值，存进脚本的全局表；裸式求值后丢弃其值。
- 被导入的模块在首次被引用时初始化一次，依赖先于使用者（《执行与编译》行一）。
- 跨句共享的值要写成顶层定义 `「名」者 … 也。`；顶层 `虑` 的绑定只在本句之内。同名再定义沿用编译器的规则：引用先命中较早的定义（《类型与模块》）。要随执行改变的量，用「新引用」「写引用」。

### 参数、环境与退出码

- `获取命令行程序名` 得脚本的路径，`获取命令行参数` 得脚本后面的参数，形状与编译后的程序相同。
- 环境变量与工作目录：脚本开始时取调用者的；在壳里执行时，脚本结束后壳恢复原样，与运行子进程相同。
- 退出码：顺利执行完为 0；`退出进程` 给出的码照用；未接住的异常 1；语法与类型错误 2；陷阱沿用客体二号的码（议三）；Ctrl-C 130。

### 与编译模式的关系

脚本也是合法的程序文件：`yy豫构.wasm 文件 甲。脚本。豫 --输出 甲.wasm` 照常编译，各句在模块初始化时依次执行。两种模式只有一处差别：编译模式在执行前就报出全部语法与类型错误，解释模式执行到那一组才报。`--先查` 让解释模式也先查后跑。

## 五、设计：逐句执行

### 读句

- 逐行读入。词法扫描维护圆括号深度；名称 `「」`、字符串 `『』`、注释 `「：…：」` 里的 `。` 都在令牌里，注释可以嵌套。遇到深度零的 `。` 就得一句：一行里可以有几句，一句也可以跨几行；文件末尾没有句号的非空尾句照常处理（都与语一相同）。
- 首行以 `#!` 起头时跳过这一行，只在脚本模式下这样做。
- `乃` 句先不处理，等下一句：下一句是同名的 `者` 或 `即` 定义，就合成一组；否则报错，与编译器“末尾独立签名、不同名或中间夹其他声明均拒绝”的规则相同（语四）。

### 每组的处理

1. **语法分析**：默认操作符集是固定的，用户不能定义操作符；编译器本来就逐句解析（`语法分析/抽象语法分析。豫` 对每句调用「解表达式默认操作符及语义标记」），与导入无关。
2. **名称解析**：顶层名称解析本来就是按句序推进的循环（`名称解析/名称解析。豫` 的「进行文件名称解析顶层」），导入只对其后的句子生效。解释器保留这个循环的状态，每组推进一步。脚本自己的定义以“文件定义引用”指向脚本文件本身，文件身份取脚本的绝对路径。
3. **类型检查**：「进行文件定义列检查」（`类型检查/文件结构检查。豫`）本来就是逐条定义、带着「命名环境」往下走的循环，每条之后用「添加已检查文件定义」扩展环境；依赖模块的检查后定义本来就按需读取（`类型检查/类型检查基础。豫` 的「文件定义引用类及物」）。把循环的一步拆成可以单独调用的入口；解释器每组调用一次，留下返回的环境。
4. **模式展开与类型擦除**：这几步（模式展开、类型擦除、续延调用展开、隐式参数擦除）本来就逐个定义变换，对本组的定义各做一次。
5. **求值**：按次序求本组各定义；定义的值存进脚本全局表，裸式的值丢弃。

先例：着色分析在内存里依次做词法、语法、名称解析、类型检查，结果只写进内存缓存（`着色翻译/着色分析。豫` 的「写内存检查后定义」）。解释器照此办理，不写编译缓存。

要避开的：前端入口不能调用「存放包上下文」（裸机上没有实现）；编译配置大多放在全局可变引用里（`编译数据/编译配置/全局配置。豫`），解释器在开始时一次设好。

### 出错

- 前端在某组报错：打印出错句的文件、起止行与诊断，退出码 2。语法错误的诊断本来没有精确行列（`表达式解析。豫`），类型错误可借源码范围标注定位到行列。
- `--先查`：先把全文逐组过前端，不求值；无错再从头求值（这时前端的结果直接复用）。
- `--只查`：只过前端，供全树测试与 CI 检查脚本。

## 六、设计：求值器

### 输入

擦除后形式的「表达式」（`库/编译器核心/编译数据/抽象绑定树结构/抽象语法树/抽象语法树数据。豫`）。第二节统计的 21 种节点之外，求值器对擦除后形式可能出现的其他节点也逐一实现；遇到未实现的节点，报“解释器尚不支持的节点：名”并结束脚本（待办事项）。

### 值

《总纲》总三的无类型中间值：单位、整数（64 位）、小数（binary64）、爻、字节串（字符串、字节串）、字节缓冲、元组、构造器值（序数加载荷）、闭包（参数个数、函数体、捕获的环境）、引用与引用数组、宿主资源（边界形“资”）、逃逸续延（以当前续延调用所得）。

### 环境与全局

- 局部变量按 de Bruijn 序数取自环境；多参数拉姆达一次绑定连续的几个参数。
- 文件定义引用按（文件身份，定义名）查模块的全局表；模块尚未初始化就先初始化它。
- 递归节点按《执行与编译》行二：先分配单槽递归单元，再求定义，填槽，返回闭包。

### 控制

- 求值是一个循环，状态为（待求的式或已得的值、环境、续延栈）；续延栈放在堆上。
- 尾位置的调用不压新帧，所以尾递归写的循环不增长续延栈；非尾调用的深度只受续延栈上限限制，与宿主栈无关。
- `豫言_抛出异常` 沿续延栈找最近的尝试运行帧；`豫言_尝试运行` 压入处理帧，再调用操作。异常到达栈底时，调用标准库用 `豫言_设置当前异常处理器` 登记的顶层处理，行为与编译后的程序相同。
- 续延调用（以当前续延调用）压入带新标识的标记帧；调用逃逸续延时，沿续延栈找到该标识的帧，送值返回，途经的尝试运行帧不拦截。标识已不在栈上时报错并结束脚本（《总纲》总一：失效续延没有稳定语义）。
- `退出进程` 不经异常：求值器直接丢下续延栈，带码结束脚本。
- 每一万步询问一次中断（议九）；见到中断就以 130 结束脚本。

### 原语

92 个 `豫言_` 原语各对应解释器自己可以调用的同一运算：整数与小数的运算、字符串与字节串、字节缓冲、引用与引用数组、类型转换、异常。会陷阱的先检查（议六），检查不过就带客体二号的码结束脚本。

### 宿主导入

- 外部调用的名字形如 `宿主导入：标准库：打印行：串→元`：前两段决定转给哪一个导入，签名按网五的边界形（整、小、爻、串、元、资、组、列、变）在求值器的值与解释器自己的值之间转换。
- 解释器所在的宿主实现了哪些导入，脚本就能用哪些：Node 工具宿主实现了标准库 65 个里的 60 个（读终端按键、进出原始输入模式、两个拼音转换是桩）；客体二号对 65 个都有映射（裸机上 TCP 返回错误，没有硬件随机数时取熵失败）。嵌入解释器的程序（如壳）可以另登记自己的接口函数。其余调用时报“接口函数未绑定：模块.字段”，与宿主的做法相同。
- 改指脚本自己的：`获取命令行程序名`、`获取命令行参数`、`退出进程`；在壳里执行时另加 `切换当前工作目录`、`获取当前工作目录` 与环境变量（脚本结束后恢复）。标准输入输出与标准错误就用解释器所在进程的。
- 子进程类的导入遇到 `。脚本。豫` 路径时，在同一进程里嵌套解释执行；取输出（「获取输出」）时，嵌套脚本的打印写进缓冲。
- 宿主导入失败时多是中止进程：2026-10-04 在 Node 上运行例一的编译产物（读不存在的 `/数据/说明.txt`），宿主抛出 ENOENT，进程以 1 退出。解释器对读、写、删、列目录、切换目录先查路径（议六），免得连带解释器所在的进程。

## 七、设计：库缓存

- **内容**：每个模块存两样东西：前端处理导入所需的产物（名称解析资料、检查后定义等，与编译器缓存同样的几种），以及求值所需的擦除后形式。格式用现行的树码，体积约为 JSON 的五分之一以下，单个文件也就远小于裸机底层句柄的 409600 字节。
- **生成**：用解释器自己的前端生成，不借用 `yy4_bs.wasm` 的缓存，这样产物与读它的代码总是同一个版本。键为（模块身份、源码摘要、库缓存格式版本）。
- **宿主上**：`yy脚本` 第一次导入某个包时逐个模块生成（依赖在先），放在仓库根的 `.yybuild/脚本库/`，此后直接读。
- **豫言操作系统上**：造盘时在宿主上运行 `yy脚本 预备 标准库 壳命令 --输出 目录`，把目录写进盘的 `/库/脚本库/`，只读。脚本导入了盘上没有的包，就报“脚本库里没有包：名”。
- **载入**：只载入实际用到的模块；前端按需读检查后定义，模块的擦除后形式在首次引用其定义时载入并初始化。在壳里执行时，已载入的模块留在壳的内存里供后面的脚本复用（常驻），重启后才重新载入。

## 八、设计：句缓存

- 键：（解释器版本、库缓存版本、脚本开头到本组末尾的文本摘要）。前缀相同则环境相同，所以命中的组可以直接取出前端的结果求值。
- 值：本组的擦除后形式，以及后面各组检查时要用到的环境增量（本组的检查后定义与名称解析状态）。
- 位置：宿主上放在 `.yybuild/脚本句/`；豫言操作系统上放在 `/缓存/脚本/`，以脚本的绝对路径区分。
- 造盘时给预置树里的每个脚本运行 `yy脚本 预备 --句缓存`，所以随盘的脚本在系统里第一次运行就不必过前端。脚本在系统里改动后，只有改动处及其后的组要重新检查。

## 九、设计：接入豫言操作系统

- **链进壳**：默认壳依赖「脚本解释」，脚本在壳的任务里执行。内核只有两个任务槽，子进程不能再起子进程；脚本若作为子进程运行，就不能再运行任何程序。在壳里执行则可以用那唯一的子进程槽：「子进程」的「运行并继承标准流」等照常可用。
- **分派**：`「运行」于「路径」于「参数」…` 的路径以 `。脚本。豫` 结尾时，在壳内解释执行，退出码照常打印；其余照旧装载 Wasm。`「脚本」于「路径」` 以 `。脚本。豫` 结尾时同上，否则照旧按行执行命令。
- **中断**：首任务见到 Ctrl-C 只记“中断挂起”（`客体二号/平台。豫`）。新增宿主服务「取中断挂起」（`豫言操作系统/裸机/宿主服务。接口。豫`，取出并清除挂起），求值器每一万步调用一次。这是新的应用 ABI，属于本提案的拟定事项（议九）。
- **标准流**：脚本的输出就是壳的输出。壳日后恢复重定向与管道时，只要把脚本的打印也接到同一个出口，脚本就同样可以重定向、进管道。
- **链进什么**：壳只链进前端各步与求值器。编译器核心里有在初始化或每次编译时调用构建宿主服务的模块（`编译过程工具。豫` 的「当前编译器可执行文件标识」在初始化时调用「获取当前程序SHA256」），壳要避开它们；避不开就由客体二号补上这些服务。
- **内存**：前端、求值器与常驻的库都在壳的任务里，32 MiB 可能不够。第一步实测；不够就照仓库规矩放大每任务内存上限与内核块池，直到 QEMU 与实机内存允许为止。
- **体积**：壳现在约 46 万字节（《终端编辑》）；加上前端与求值器之后，估计在 2–3 MB 之间（编译器 `yy4_bs.wasm` 全体 4.16 MB），走客体二号现有的初始大程序路径。

## 十、设计：宿主上的 `yy脚本`

- 包「豫言脚本」放在 `应用/开发工具/豫言脚本/`，可执行文件 `yy脚本`，依赖「脚本解释」。
- 用法：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy脚本.wasm 路径。脚本。豫 参数…
node 豫言操作系统/宿主/节点/宿主.cjs yy脚本.wasm --只查 路径。脚本。豫
node 豫言操作系统/宿主/节点/宿主.cjs yy脚本.wasm 预备 标准库 壳命令 --输出 目录
```

- 包发现与豫构相同：从脚本所在目录向上找仓库根。
- 全树测试：每个 `。脚本。豫` 跑 `--只查`；旁边有同名 `.期望` 的，再以解释与编译两种模式各跑一次，输出都与期望逐字比较。

## 十一、例子

例一至例三于 2026-10-04 用 `yy4_bs.wasm` 以编译模式构建通过（临时放进 `应用/豫言编译器/测试/网页汇编/` 构建，冷缓存 23.9 秒，热缓存每例 4–6 秒）。

### 例一：一句一行

壳测试 `子进程文件` 的子程序 `文件工。豫` 今天只能把每一步嵌进一个大 `虑…而` 链里。写成脚本，每一步就是一句：

```yuyan

「打印行」于（『读预置：』附（「文件系统」之「读文件」于『/数据/说明.txt』））。
「文件系统」之「写文件」于『/新/来自脚本.txt』于『脚本写入的内容』。
「打印行」于（『读回：』附（「文件系统」之「读文件」于『/新/来自脚本.txt』））。
```

某一句出错时，此前各句的输出与写入都已生效，其后的句子不再执行。

```yuyan

若「等于」于「码」于「零」则「打印行」于『统计完成』否则「进程」之「退出」于「码」。
```

```yuyan
寻观「标准库」之书。

「逐个统计」乃化（「列」于「字符串」）而「有」也。
「逐个统计」者会「余」而
  鉴「余」而
    有「罄」则「元」
    或有「缀」于「首」于「尾」则（
```

## 十二、速度与验收

暂定目标（第一步实测后修订）：

| 场景 | 目标 |
| --- | --- |
| Node，库缓存已生成，十句的脚本（导入标准库、运行一个程序） | 两秒内完成，不计所运行程序的时间 |
| Node，每组前端（环境已载入） | 平均五十毫秒以内 |
| QEMU，句缓存命中，同一脚本 | 十秒内完成，不计所运行程序的时间 |
| QEMU，句缓存未命中 | 实测记录，不设目标；若一组超过十秒，先做第十六节第 5 步 |
| 解释与编译两种模式的输出 | 全树测试里逐字相同 |

求值器本身慢于编译后的代码：Node 上估计慢十到五十倍；裸机上再乘客体二号的倍数。脚本适合运行程序、搬文件、做判断；大量计算仍应写成程序编译。

## 十三、兼容与迁移

- 语言：没有新语法，没有新类型规则；只多了一种文件后缀和一种执行方式。
- 构建：「收集包源码」跳过 `。脚本。豫`。仓库里现在没有这种后缀的文件，现有构建不受影响。
- 默认壳：`.txt` 命令脚本照旧；`。脚本。豫` 走新路径。壳因链进前端而变大，启动时间待实测。
- 新 ABI：宿主服务「取中断挂起」，声明加在 `豫言操作系统/裸机/宿主服务。接口。豫`，由 `客体二号/带型名。豫` 映到新的原语号。这组声明只由客体二号映射，与 `豫言操作系统接口/` 的接口清单无关。
- 编译器核心：只把类型检查与名称解析循环的一步拆成可单独调用的入口，不改语义；仍须完整自举（yy3 与 yy4 逐字节相同）以确认。
- 与《豫言操作系统总体架构》D3（“解释器只作正确性基准，工具类程序必须 AOT”）的关系：D3 说的是 Wasm 程序在原生路上怎样执行；本提案解释的是脚本源码，解释器本身照常编译成 Wasm，随壳或 `yy脚本` 一起执行。

## 十四、备选方案

| 方案 | 结论与理由 |
| --- | --- |
| 在系统里运行完整编译器，脚本先编成 Wasm 再运行 | 否。编译器由客体二号解释执行，原生上编一个标准库文件约 45 秒，QEMU 上更慢；它要用的「存放包上下文」裸机上没有，Node 上冷编峰值约 0.52 GB，而每任务只有 32 MiB；编译器占了唯一的子进程槽，编出的程序就无处运行 |
| 逐句编成小 Wasm 模块，用多实例装载执行 | 否。跨实例只传数值（《客体二号》“限制”），句与句之间要传闭包、字符串与列表；每句还要过一遍代码生成 |
| 只在宿主上预编译脚本，随盘提供 `.wasm` | 这就是现状：系统里改了源码不能重跑，也不能在系统里写新脚本 |
| 给壳的命令语言加变量、条件、循环、函数 | 否。那是另造一门语言，仓库规矩不许自造语言或 DSL；豫言本身已有这些 |
| 另写一个只认子集、动态类型的小解释器 | 否。接受的程序与编译器不同，类型错误到运行时才暴露，语法糖要再实现一遍 |
| 跳过类型检查，直接解释名称解析后的树 | 否。类型检查还做细化（命名元组的按名投影改成按序投影、标签参数等），模式展开与擦除都在它之后；跳过它，语义就变了 |
| 解释更靠后的阶段（跨模块优化、递归转换或闭包转换之后） | 不取。那些阶段带着顶层直调、全局存储、闭包环境等为代码生成准备的细节，求值器反而更繁；擦除后形式最接近《执行与编译》行一至行三 |
| 解释器做成独立程序 `/程序/脚本.wasm`，由壳作为子进程运行 | 暂不取。内核只有两个任务槽，脚本就不能运行程序；内核放开任务槽之后可以改 |
| 库函数直连：求值器直接调用解释器里编好的库函数，不解释库的树 | 留待后续。要让求值器的值与编译后的值同一表示，要按类型生成全部库定义的直连表，可能还要新原语来构造任意长的元组；收益是库代码以编译后的速度运行，也不必载入库的擦除后形式 |

## 十五、未决问题

1. 交互求值：壳里输入一句豫言立即执行并印出值。读句器与求值器都已具备，难在值的打印（需要按类型打印）。要不要同期做。
2. 壳的交互输入要不要直接收豫言句（参数写成 `『』` 字符串），与正式句式合一；这要与云仓的网页壳一起定。
3. 豫言操作系统上脚本能导入的库：只随盘的标准库与壳命令库，还是盘上所有的库。
4. 首次载入标准库在 QEMU 上若太慢：常驻、裁剪、库函数直连，先做哪一个。
5. 壳在裸机上的预编（把 WP8 的预编二用到裸机镜像）：若可行，前端与求值器都可望接近 Node 的速度。
6. 脚本耗尽内存会连带壳：要不要给求值器设堆上限，还是等内核放开任务槽后让脚本另开进程。
7. 同名再定义：脚本作者容易把它当作变量重新赋值；要不要在脚本模式下对同名再定义给警告。
8. `#!` 行：宿主上 `yy脚本.wasm` 要经 Node 宿主启动，`#!` 行怎么写才能在 macOS 与 Linux 上直接执行。
9. 壳命令库（议十二）的命令该“打印结果”（与壳相同）还是“返回结果”（便于编程），或两种都给。
