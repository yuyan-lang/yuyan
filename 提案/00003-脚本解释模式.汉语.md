这是给豫言加入解释执行的提案。豫言程序今天只有一种执行方式：编译成本机原生可执行文件再运行（提案 00007 起是默认，`.wasm` 是显式目标）。本提案加上第二种：逐句读入源码，每凑满一句，就过一遍与编译相同的前端，然后立即求值，不做整程序链接与原生生成。解释执行由编译器兼做（用户 2026-10-06 定方向）：`yy豫构` 本身就是编译器（提案 00007），它多一个「解释」子命令；前端与编译共用，阶段缓存也共用，后端换成在擦除后形式上求值的求值器。解释执行用在三处：`。脚本。豫` 写完就跑；豫言操作系统的壳把每一行当一句豫言求值；宿主上的交互求值。两种执行方式接受同样的程序、得出同样的结果，只有出错的时机不同。

本文只写现代汉语（AGENTS.md）。旧的[文言稿](00003-脚本解释模式.文言.md)是 2026-10-05 的版本，保留，以本文为准，不再同步。

## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | 两种执行方式：编译执行（默认出本机原生可执行文件，提案 00007）与解释执行。两者共用前端（语法分析、名称解析、类型检查、模式展开、类型擦除），按《总纲》总〇的源语言兼容核对：接受与拒绝的程序相同，求值轨迹与输出相同。出错的时机不同：编译执行在运行前报出全部语法与类型错误，解释执行执行到那一组才报。《执行与编译》新增一节（第四节） |

## 二、动机

### 编译执行的代价

默认原生之后（提案 00007），编译执行一次要做：每个模块的依赖分析、语法解析、类型检查（含名称解析与擦除）、跨模块优化、闭包转换；再对整个程序做最终链接（整程序生成豫汇，在内存里编码）与原生生成（转译、降级、连接），写出 Mach-O、ELF 或豫行，macOS 上还要签名。阶段缓存与按函数的机器码缓存让没改的部分不重做，最终链接与原生生成仍对整个程序做。实测见下表（出处：00007 实施记录、「系统内工具链」）：

| 场景 | 环境 | 用时 |
| --- | --- | --- |
| 构建并运行一个小脚本（打印探针，热缓存） | pit-mac，原生 | 1.39 秒 |
| 给豫言系统加一个函数后重建 | 本机，原生 | 9.3 秒：编译各阶段约 4 秒，最终链接约 2 秒，原生生成约 2.1 秒，其余是进程启动与调度 |
| 系统里 `构建 你好 -j 4`（AMD64，默认出豫行） | QEMU 纯模拟，四核 8 GB | 单是最终链接 59 秒 |
| 系统里构建你好（ARM64 盘出 `.wasm`） | QEMU HVF，四核 | 约 13 秒 |

解释执行省掉最终链接、原生生成与写出可执行文件。前端两种方式都要做，但解释执行每次只检查新的一组，导入的库直接读阶段缓存。逐句执行与交互求值则是编译执行做不到的：交互的每一行若都编成新程序，句与句之间无法共享值。

### 壳不能写逻辑

今天的壳由开机壳与桌面命令行共用：会话在 `库/用户态桌面/命令壳。豫`，句式解析与命令登记在 `库/壳核心`。它只收正式句式：每段都包在「」里，`之` 连成员，`于` 引参数，如 `「文件」之「写入」于「/新/甲.txt」于「你好 世界」`。登记表共 21 项命令，没有变量、条件、循环与函数。

- `「脚本」于「路径」` 读入全文，去掉「：…：」注释，逐行执行命令：先印 `+ 行`，出错印“错误：…”后继续。行与行之间不能传值，也不能按退出码分支。
- `「运行」` 每次起一个新任务：豫行文件跑预编的机器码（AMD64），其余当 Wasm 由执行器解释。`。脚本。豫` 是源码，不能直接运行。
- 仓库里没有在运行时求值豫言语法树的解释器：运行时的解释器只在 Wasm 一层（`豫言操作系统/裸机/客体二号/解释。底层。豫`、`库/编译器核心/网页汇编核心/客体执行。豫`）；编译期的求值只有代码生成之后对静态初始化的符号执行（`库/编译器核心/编译步骤/代码生成/网页汇编常量初值。豫`）与底层模式的常量求值（同目录 `底层后端/底层求值。豫`）。

### 旧稿的前提已变

| 2026-10-04 旧稿的前提 | 现在 |
| --- | --- |
| 编译产物是 `.wasm` | 默认是本机原生可执行文件，豫言操作系统上是豫行；`.wasm` 是显式目标（提案 00007） |
| 系统里没有编译器，程序都在宿主上编 | 系统里有 `/工具/yy豫构` 等工具，能构建你好、编译器本身与启动盘（「系统内工具链」） |
| 前端与求值器要在客体二号里解释执行，约慢五百倍 | 系统里的豫构是预编的机器码；`--预编二` 盘上壳与桌面也是机器码（只限 AMD64，ARM64 的壳仍由执行器解释） |
| 内核两个任务槽，子进程不能再起子进程 | 两种架构都有动态任务，子任务能再起子任务，一个执行器能同时管 1024 个异步子进程；只有 AMD64 内存为 128 MiB 时退回两槽 |
| 每任务 32 MiB，块池固定 64 MiB | 执行器页上限 65535 页（约 4 GiB）；内核按物理内存划分、按需提交，每任务至多 127 TiB |
| 「存放包上下文」裸机上没有；编译器初始化时就取程序摘要 | 都已实现；可执行文件标识改为首次取用时才算 |
| 文件句柄缓冲 409600 字节，大文件读写不了 | 句柄仍是 409600 字节（大内存的初始任务 16 MiB），标准库整文件读写已绕开它，系统里写出过约 105 MB 的启动盘 |
| `。脚本。豫` 是新后缀 | 提案 00006 已登记它，按编译执行构建，仓库里有 348 个；收集包源码已跳过它 |

所以旧稿为“慢五百倍”和内存紧而设的另一套库缓存与句缓存都不再需要，放大内存也只剩 QEMU 内存一项（议十三）。快路保留：ARM64 和不带 `--预编二` 的盘上，壳仍由执行器解释（第十节）。

## 三、目标与范围

目标：

1. 宿主上 `豫构 解释` 解释执行脚本；不给路径时进入交互求值。
2. 豫言操作系统的壳直接运行 `。脚本。豫`：运行程序、读写文件、取参数与环境变量、按退出码分支，不经构建。
3. 两种执行方式源语言兼容，出错的时机除外。
4. 逐组执行：前面的句子先生效，错误报到出错的那一组。
5. 脚本出错只结束脚本；交互求值出错只丢弃这一句，壳照常工作。
6. 壳的交互输入就是豫言句；只调壳命令的简单一句与今天一样快。
7. 速度达到第十二节的暂定目标（第 1 步实测后修订）。

范围见文首表格。第十五节的后续各项、壳的重定向与管道、云仓网页壳的具体实施（在云仓另做）、Windows 原生工具链都另行处理；Windows 上 `豫构 解释` 照旧经诺节宿主运行 `yy豫构.wasm`。

## 四、规范：两种执行方式

《执行与编译》新增“解释执行”一节，要点如下：

- **编译执行**：整个程序先过前端，无错才生成并运行；运行时的次序按现行行一（测试与脚本的程序体依次执行，最后调用入口函数一次）。
- **解释执行**：逐组过前端并立即求值，一组的效果在下一组开始前已经发生；带入口函数的普通源文件处理完后，再调用入口函数一次，与编译执行相同。被导入的模块只过前端，不执行计算：普通模块的顶层只有定义（提案 00006），顶层数据按值取用，「首次计算」的值在第一次取用时计算，与编译执行相同。
- **两者的关系**：接受与拒绝的程序相同，求值轨迹与输出相同（《总纲》总〇）。差别是出错的时机与速度：编译执行在运行前报出全部语法与类型错误；解释执行执行到那一组才报，`--先查` 时与编译执行相同。
- **同名再定义**：沿用编译器的规则，引用命中较早的定义（《类型与模块》）。要随执行改变的量用「新引用」「写引用」。
- **首行 `#!`**：`。脚本。豫` 首行以 `#!` 起头时，两种执行方式都跳过这一行（《词法与语法》同步）。

## 五、设计：豫构的「解释」子命令

```sh
豫构 解释 路径 参数…
豫构 解释 --只查 路径
豫构 解释 --先查 路径 参数…
豫构 解释
```

- **包上下文**与 `豫构 文件` 相同：从文件所在目录找所属的包与仓库，依赖照包描述。被导入模块的阶段缓存缺了，就照豫构的并行编译先编到类型检查为止，不做跨模块优化、闭包转换与链接。
- **参数**：`获取命令行程序名` 得脚本的路径，`获取命令行参数` 得脚本后面的参数，与编译后的程序相同。
- **交互求值**：不给路径时进入交互求值（第十节的读句、印值与出错规则），会话开头相当于已导入标准库；在宿主上用于调试求值器与印值。
- **首行**：macOS 与 Linux 上 `yy豫构` 是原生可执行文件，脚本首行可写 `#!/usr/bin/env -S yy豫构 解释`（`yy豫构` 在 PATH 里时）。

## 六、设计：逐组执行

### 读句

- 逐行读入。词法扫描维护圆括号深度；名称 `「」`、字符串 `『』`、注释 `「：…：」` 里的 `。` 都在令牌里，注释可以嵌套。遇到深度零的 `。` 就得一句：一行里可以有几句，一句也可以跨几行；文件末尾没有句号的非空尾句照常处理（都与语一相同）。
- `乃` 句先不处理，等下一句：下一句是同名的 `者` 或 `即` 定义，就合成一组；否则报错，与编译器“末尾独立签名、不同名或中间夹其他声明均拒绝”的规则相同（语四）。

### 每组的处理

以下路径都在 `库/编译器核心/编译步骤/` 下。

1. **语法分析**：编译器本来就逐句解析（`语法分析/抽象语法分析。豫` 对每句调用 `语法分析/表达式解析。豫` 的「解表达式默认操作符及语义标记」）。
2. **名称解析**：顶层名称解析本来就是按句序推进的循环（`名称解析/名称解析。豫` 的「进行文件名称解析顶层」），导入只对其后的句子生效。解释器保留这个循环的状态，每组推进一步。脚本自己的定义以“文件定义引用”指向脚本文件本身。
3. **类型检查**：「进行文件定义列检查」（`类型检查/文件结构检查。豫`）本来就是逐条定义、带着「命名环境」往下走的循环，每条之后用「添加已检查文件定义」扩展环境；依赖模块的检查后定义按需读取（`类型检查/类型检查基础。豫` 的「文件定义引用类及物」）。把循环的一步拆成可以单独调用的入口，解释器每组调用一次，留下返回的环境。
4. **模式展开与类型擦除**：这几步本来就逐个定义变换，对本组的定义各做一次。
5. **求值**：按次序求本组各定义，值存进脚本的全局表；裸式求值后丢弃其值（交互时印出）。

先例：着色分析在内存里依次做词法、语法、名称解析、类型检查，结果只写进内存（`着色翻译/着色分析。豫` 的「写内存检查后定义」）。解释器照此办理，脚本自己的各组不写阶段缓存。编译配置放在全局可变引用里（`编译数据/编译配置/全局配置。豫`），解释器在开始时一次设好。

### 出错

- 前端在某组报错：打印出错句的文件、起止行与诊断，退出码 2；交互时只丢弃这一句。语法错误的诊断今天没有精确行列，类型错误可借源码范围标注定位到行列。
- `--先查`：先把全文逐组过前端、不求值，无错再从头求值，前端的结果直接复用。
- `--只查`：只过前端。

## 七、设计：求值器

### 输入

擦除后形式的「表达式」（`库/编译器核心/编译数据/抽象绑定树结构/抽象语法树/抽象语法树数据。豫`，共 93 种节点名，擦除后只出现其中一部分；2026-10-04 统计标准库的擦除后形式用到 21 种）。求值器对擦除后可能出现的节点逐一实现；遇到未实现的节点，报“解释器尚不支持的节点：名”并结束脚本（待办事项）。

### 值

《总纲》总三的无类型中间值：单位、整数（64 位）、小数（binary64）、爻、字节串（字符串、字节串）、字节缓冲、元组、构造器值（序数加载荷）、闭包（参数个数、函数体、捕获的环境）、引用与引用数组、宿主资源（边界形“资”）、逃逸续延（以当前续延调用所得）。

### 环境与全局

- 局部变量按 de Bruijn 序数取自环境；多参数拉姆达一次绑定连续的几个参数。
- 文件定义引用按（文件身份，定义名）查全局表。被导入模块的定义第一次被引用时载入它的擦除后形式；顶层只有数据与函数，载入时不做计算。
- 递归节点按《执行与编译》行二：先分配单槽递归单元，再求定义，填槽，返回闭包。

### 控制

- 求值是一个循环，状态为（待求的式或已得的值、环境、续延栈）；续延栈放在堆上，设上限（缺省一千万帧，嵌入者可改），超过即报“栈溢出：递归过深”并结束脚本。
- 尾位置的调用不压新帧，所以尾递归写的循环不增长续延栈；非尾调用的深度只受续延栈上限限制，与宿主栈无关。
- `豫言_抛出异常` 沿续延栈找最近的尝试运行帧；`豫言_尝试运行` 压入处理帧，再调用操作。异常到达栈底时，调用标准库用 `豫言_设置当前异常处理器` 登记的顶层处理，行为与编译后的程序相同。
- 续延调用（以当前续延调用）压入带新标识的标记帧；调用逃逸续延时，沿续延栈找到该标识的帧，送值返回，途经的尝试运行帧不拦截。标识已不在栈上时报错并结束脚本（《总纲》总一：失效续延没有稳定语义）。
- `退出进程` 不经异常：求值器直接丢下续延栈，带码结束脚本。
- 在壳里交互求值时，每一万步用「查询中断」问一次，见到中断就放弃这一句（第九节）。在子任务里执行脚本时，Ctrl-C 由现行机制直接结束子任务。

### 原语

`豫言_` 原语各对应解释器自己可以调用的同一运算：整数与小数的运算、字符串与字节串、字节缓冲、引用与引用数组、类型转换、异常。会陷阱的（整数除与取余遇零、小数转整数越界、引用数组越界等）先检查，检查不过就带与编译后程序相同的码结束脚本。

### 宿主接口

- 标准库的宿主接口函数（`库/标准库/宿主。接口。豫` 等）按签名的边界形（`库/编译器核心/编译数据/宿主边界。豫`：整、小、爻、串、元、资、组、列、变，异步返回另有“异”）在求值器的值与解释器自己的值之间转换，转给解释器所在程序自己的同名导入。
- 解释器所在的程序实现了哪些导入，脚本就能用哪些：宿主上是豫构所在的宿主（原生或诺节），豫言操作系统上是执行器。嵌入解释器的程序（如壳）可以另登记自己的接口函数。其余调用时报“接口函数未绑定：模块.字段”，与宿主的做法相同。
- 改指脚本自己的：`获取命令行程序名`、`获取命令行参数`、`退出进程`。子任务里的工作目录与环境变量本来就是脚本自己的；壳里交互求值时就是壳的。
- 宿主接口失败时多是中止进程（如读不存在的文件）。解释器对读、写、删、列目录、切换目录先查路径，查不过以 1 结束脚本，交互时只丢弃这一句，免得连带解释器所在的进程。

## 八、设计：库与缓存

- **内容**：豫构的阶段缓存本来就逐模块存下前端与求值所需的一切：类型检查任务写出名称解析资料、检查后定义、检查后对象、擦除后形式等，格式是树码。缓存目录按编译器的摘要区分，所以写缓存与读缓存的总是同一个程序。
- **生成**：缓存缺了，解释器照豫构的并行编译先编到类型检查为止。
- **载入**：只载入实际用到的模块；前端按需读检查后定义，擦除后形式在首次引用其定义时载入。交互会话里，已载入的模块留在内存里供后面的句子复用。
- **豫言操作系统上**：系统里的豫构按自己的摘要建缓存目录，第一次导入某个包时在系统里编出它的阶段缓存，之后复用；盘上 `/源` 里的包都能现编。壳链进的解释器同理。在系统里第一次编标准库太慢（QEMU 纯模拟下以分钟计），所以造盘时用同一份源码在宿主上预先生成标准库与壳命令库的阶段缓存，按 `/工具/yy豫构` 与壳各自的摘要写进盘里对应的缓存目录。

## 九、设计：接入豫言操作系统

### 运行脚本

- `「运行」于『甲。脚本。豫』于「列」【…】` 与 `「脚本」于『甲。脚本。豫』`：壳起子任务运行 `/工具/yy豫构 解释 甲。脚本。豫 参数…`，退出码照常打印；开机壳同步、桌面命令行异步，与运行别的程序相同。
- 盘上没有 `/工具/yy豫构`（造盘没带 `--工具链`）时报“这张盘没有工具链，不能运行脚本：造盘时加 --工具链”。
- 脚本在自己的任务里执行，可以再运行程序（子任务能再起子任务）。工作目录与环境变量是脚本自己的，结束后壳不受影响。
- Ctrl-C：内核把它记成标志，子任务见到就以 130 退出（现行机制）；第 4 步核对豫行子任务也照此退出。
- 内存：AMD64 内存为 128 MiB 时内核退回两个任务槽，所以验收用的 QEMU 内存放到 2 GiB（议十三）。

### 交互求值链进壳

- 壳依赖编译器核心的 `解释执行/`，会话在壳的任务里。壳今天约 20 MB（含拼音数据），`--预编二` 后机器码约 40 MB；链进前端与求值器后会更大，第 5 步实测体积与启动时间。
- 编译器核心里在初始化时调用构建宿主服务的模块要避开；可执行文件标识已改为首次取用时才算。

### 中断

- 首任务（壳）见到 Ctrl-C 只记下“中断挂起”。底层接口已有「查询中断」（读并清除，`豫言操作系统底层接口/底层基础/环境。底层接口。豫`），客体二号也已实现，普通程序调不到它。在 `豫言操作系统/裸机/宿主服务。接口。豫` 加一个声明，经 `客体二号/带型名。底层。豫` 映到同一实现，求值器每一万步问一次（新 ABI，2026-10-04 用户已同意）。这组声明只由客体二号映射，与 `豫言操作系统接口/` 的接口清单无关。
- 逐键编辑器今天不查中断标志，编辑到一半按 Ctrl-C 无效，壳测试「中断」已暂停；第 5 步一并接上，编辑时按 Ctrl-C 放弃这一行。

## 十、设计：交互求值与壳输入合一

### 一行就是一句

- 壳读入一行，交给解释器的读句器：名称、字符串、圆括号、方括号与注释都闭合时，这一行就是一句，句末的 `。` 可写可不写，一行里有几句就依次处理；没闭合就印续行提示 `…> `，接着读下一行。
- 会话开始时相当于已执行 `寻观「标准库」之书。寻观「壳命令」之书。`。
- 会话就是一份边写边跑的脚本：前面的导入与定义在后面的句子里都有效。前端、求值器与已载入的库常驻在壳的内存里。

### 出错与中断

- 前端或求值出错：打印诊断，丢弃这一句（它的定义不进环境），接着读下一行。脚本则出错即止（第六节）。
- Ctrl-C：编辑时放弃这一行；求值时打断这一句，回到提示符，会话环境保留。
- `「退出」` 结束壳，与今天相同；交互时调用 `退出进程` 也结束壳。

### 印值

- 裸式的值的类型由这一句的类型检查给出。类型是「有」时什么都不印。
- 值是无参函数（类型为 `化「有」而…`）时，以「元」调用它，再按结果处理；所以 `「环境」`、`「帮助」` 这类无参命令可以不写 `于「元」`。这条只在交互时成立，脚本里照样要写，与编译执行一致。
- 其余按类型印成可以贴回去的豫言写法：整数 `「42」`、小数 `「1.5」`、爻 `「阳」`、字符串 `『…』`、列 `「列」【…】`、元组 `（… 与 …）`、构造器 `「名」于 …`（构造器名取自类型检查的环境）；函数、引用与宿主资源印成 `（函数）`、`（引用）`、`（资源）`。

### 快路

- `--预编二` 盘上壳是机器码，过完整前端的一句在 QEMU 纯模拟下估计为百毫秒级（第 5 步实测）；ARM64 与不带 `--预编二` 的盘上，壳由执行器解释，前端慢百倍以上。
- 所以形如 `「名」于 参…` 或 `「名」之「名」于 参…`、参数只有字符串与整数字面量或它们的列、名字是「壳命令」里的命令且没被会话里的定义遮蔽的一句，直接按该命令的签名核对参数个数与种类后调用，不载入库，不过完整前端。
- 快路认得的写法是完整写法的子集，结果相同；壳测试对快路能处理的句子两路都跑，逐字比较。

### 壳命令库

- 新库「壳命令」（`库/壳命令`，依赖标准库），成员路径沿用 `库/壳核心/命令登记。豫` 的登记：「帮助」「图形」「回显」「运行」「设」「取消」「环境」「日期」「脚本」「退出」，以及「文件」之「当前」「切换」「列出」「读取」「写入」「追加」「复制」「移动」「建目录」「删除」。
- 文件与进程操作今天写在 `库/用户态桌面/命令壳。豫` 与 `豫言操作系统/裸机/壳/壳。豫` 里，搬进「壳命令」，壳与桌面命令行改调它。「图形」「退出」要回到壳，由壳登记处理函数。
- 不与 `寻观「标准库」之书` 已导出的名字重名：演示用的「加」去掉，`「加」于「12」于「30」` 就是标准库的加法，印出 `「42」`。实施时逐个核对（如 `控制/异步。豫` 也有「运行」）。
- 命令照壳的习惯打印结果、返回「有」，交互时不会再印一遍；要拿值来编程，用标准库（如「文件系统」之「读文件」）。
- 参数个数可变的「运行」改收参数列：`「运行」于『/程序/你好.wasm』于「列」【『甲』，『乙』】`；可省的参数改为必填，如 `「文件」之「列出」于『.』`。

### 输入法与补全

- 已知名称的候选取自解释器的名称环境：导入的名字、壳命令、会话里的定义；`之` 之后给该模块的成员，`于` 之后给参数，路径照旧取当前目录。
- 参数位置的字符串写 `『』`：选中的路径候选填成 `『…』`，回车时把自由参数包成 `『』`（纯数字包成 `「」`），中文模式的 Shift+[ 在参数位置先出 `『』`。
- 角引号包参数的旧正式句式不再接受。`库/壳核心` 的 `命令位置` 句式解析由读句器与语法分析代替，`命令登记` 留作补全与快路的名录。

### 命令脚本与网页壳

- `「脚本」于『路径.txt』`：每行按交互的一句处理，先印 `+ 行`，出错继续；`。脚本。豫` 照第九节。
- 云仓网页壳原与默认壳同一写法，随之改为豫言句（字符串用 `『』`）。网页壳只认命令调用，不做一般求值；在云仓另行实施。

## 十二、速度与验收

暂定目标（第 1 步实测后修订）：

| 场景 | 目标 |
| --- | --- |
| 宿主，缓存已在，`豫构 解释` 十句的脚本（导入标准库、运行一个程序） | 0.5 秒内完成，不计所运行程序的时间（对照：编译执行构建并运行小脚本 1.39 秒） |
| 宿主，交互求值一句（库已载入） | 平均 50 毫秒以内 |
| 豫言操作系统，`--预编二 --工具链` 盘，缓存已在，同一脚本 | 实机或 KVM 下 2 秒内；QEMU 纯模拟实测记录 |
| 壳里走快路的一句 | 与今天的正式句式相当 |
| 壳里过完整前端的一句（库已载入） | 实测记录，预编二盘与 ARM64 各一组 |
| 两种执行方式的输出 | 全树测试与壳测试里逐字相同 |

求值器本身慢于编译后的代码，估计慢十到五十倍。脚本适合运行程序、搬文件、做判断；大量计算仍应写成程序编译执行，或等库函数直连（第十五节）。

## 十三、兼容与迁移

- **语言**：没有新语法与新类型规则；多一种执行方式；`。脚本。豫` 首行可写 `#!`。
- **构建**：`豫构 文件` 等照旧；豫构多一个子命令。造盘规则照旧（预置树里的 `。脚本。豫` 编成程序）。
- **编译器核心**：把名称解析与类型检查循环的一步拆成可单独调用的入口，词法跳过脚本首行 `#!`，其余语义不变；三四级自举逐字节相同。
- **壳**：写法改为豫言句（字符串用 `『』`）；演示用的「加」由标准库的同名函数代替；`壳/测试/` 与 `库/壳核心/测试/` 的输入与期望随之改写。
- **云仓网页壳**：写法随之改为豫言句，在云仓另行实施，同步云仓的说明与测试。
- **新 ABI**：「查询中断」的宿主服务声明，加在 `豫言操作系统/裸机/宿主服务。接口。豫`，由 `客体二号/带型名。底层。豫` 映射。
- **全树测试**：`测试规则.tsv` 里针对脚本的跳过规则，第 2 步逐条核对。
- **与《豫言操作系统总体架构》D3（“解释器只作正确性基准，工具类程序必须 AOT”）的关系**：D3 说的是 Wasm 程序在原生路上怎样执行；本提案解释的是豫言源码，解释器本身照常编成原生代码，随豫构或壳一起运行。

## 十四、备选方案

| 方案 | 结论与理由 |
| --- | --- |
| 每次都编译执行：脚本先构建成原生程序再运行 | 不作脚本与交互的主路。系统里能编，但最终链接与原生生成每次都对整个程序做：宿主上构建并运行小脚本 1.39 秒，系统里纯模拟下单是最终链接就 59 秒；交互的每一行若都编成新程序，句与句之间无法共享值。编译执行仍是正式程序的默认方式 |
| 解释豫汇，或把豫汇交给执行器解释 | 不取。豫汇只在最终链接时为整个程序生成，没有按模块的豫汇缓存，解释它省不掉整程序链接；那时已做过闭包转换、去装箱等为代码生成准备的变换，求值器反而更繁 |
| 另写 `yy脚本` 工具、独立的「脚本解释」库与库缓存格式（旧稿） | 改为编译器兼做（用户 2026-10-06 定方向）：少一个工具与一套缓存格式，解释与编译用同一份前端与同一份阶段缓存 |
| 跳过类型检查，直接解释名称解析后的树 | 否。类型检查还做细化（命名元组的按名投影改成按序投影、标签参数等），模式展开与擦除都在它之后；跳过它，语义就变了 |
| 解释更靠后的阶段（跨模块优化、闭包转换之后） | 不取。那些阶段带着顶层直调、全局存储、闭包环境等为代码生成准备的细节；擦除后形式最接近《执行与编译》 |
| 系统里的脚本在壳的任务里解释执行（旧稿） | 不取。动态任务已有，子任务把脚本与壳隔开：脚本的工作目录、环境变量与退出是它自己的，出错或耗尽内存不连带壳，Ctrl-C 也照现行机制结束它 |
| 交互求值放在常驻的豫构子任务里，壳只转发行 | 不取。现行 Ctrl-C 机制会直接结束子任务，会话随之丢失；补全要读名称环境、值要印回壳的窗口，链进壳最直接 |
| 给壳的命令语言加变量、条件、循环、函数 | 否。那是另造一门语言，仓库规矩不许自造语言或 DSL；豫言本身已有这些 |
| 另写一个只认子集、动态类型的小解释器 | 否。接受的程序与编译器不同，类型错误到运行时才暴露，语法糖要再实现一遍 |
| 每一行都过完整前端，不设快路 | 不取。ARM64 与不带 `--预编二` 的盘上壳由执行器解释，前端慢百倍以上；快路只收完整写法的子集，结果相同 |
| 句缓存（旧稿） | 移到后续。系统里的豫构是预编的机器码，前端不再慢五百倍；先实测 |
| 保留正式句式，另设一条命令进入交互求值 | 否。2026-10-04 用户定壳的输入与豫言句合一 |
| 交互时也要求无参命令写 `于「元」` | 不取。交互时自动以「元」调用无参函数；脚本里仍须写，与编译执行一致 |

## 十五、后续

- **库函数直连**：标准库与壳命令库在豫构和壳里本来就是编好的原生代码。让求值器直接调用它们，库代码就以编译后的速度运行，也不必载入库的擦除后形式。要让求值器的值与编译后的值同一表示，按类型生成直连表，可能还要新原语来构造任意长的元组。
- **编译期求值**：有了求值器，编译器可以在编译时算出顶层可算的值，写成数据（提案 00006 留下的口子）。
- **句缓存**：脚本没改动的组跳过前端。
- **热函数交给原生生成**：求值器把反复调用的函数交给原生生成，换成机器码。
- **其他**：脚本互相导入；宿主上交互求值时 Ctrl-C 打断一句；ARM64 的壳预编。

## 十六、未决问题

1. 系统里脚本能导入的库：盘上 `/源` 里全部的包（系统里现编），还是只限随盘带了阶段缓存的那些。
2. 造盘预生成阶段缓存的做法：缓存目录按程序摘要区分，壳与 `/工具/yy豫构` 各写一份；或者改按前端版本区分，两者共用一份。
3. 同名再定义：脚本作者与交互用户容易把它当作变量重新赋值；要不要给警告。
4. 「运行」要不要另给一个按空白拆参数的简写（如 `「运行」于『/程序/你好.wasm 甲 乙』`）。
5. 网页壳改用豫言句后，云端用什么解析：链进编译器的前端，还是只解析命令调用（须是完整写法的子集）。
6. 会话里的定义要不要存盘，重启后恢复。
