### 终端浏览器是原型

2026-10-09 实测：`应用/开发工具/终端浏览器` 有 25 个源文件、26,486 行。其包说明记录的限制：

- 脚本是语句级解释器。字符串长度与下标以 Unicode 字符为单位（JavaScript 以 UTF-16 码元为单位）；`finally`、`do/while`、错误对象与堆栈、对象原型链、正则、默认参数与剩余参数与解构都待实现；`async`、`defer`、`type="module"` 与动态插入脚本没有按浏览器语义处理；事件只覆盖 `click`、`input`、`change`、`keydown`、`submit`、`focus`、`blur` 与页面载入的 `DOMContentLoaded`、`load`。
- DOM 用值语义的树加“内部身份”表示：追加与移除时重建祖先路径，绑定在对象或数组里的节点引用不会同步更新。
- CSS 的伪类只到结构类与少数状态类，选择器没有 `:not()`、`:is()`、`:has()`；布局覆盖块、弹性盒与表格的子集。
- 抓取不处理分块响应；Cookie 的 `Path`、`Domain`、`Secure`、`SameSite`、`Expires` 等属性没有处理；没有 CORS 与 CSP。

这些限制来自表示本身（值语义的树、字符粒度的字符串、语句级的脚本解释），所以网页组的各库重新设计。终端浏览器已迁入基础库的部分（网址处理、密码模块）保持原样。

### 豫言自己的网页是现成的验收对象

2026-10-09 在云仓（yuyan-cloud）统计，按文本匹配计数；各网页应用各带一份相同的宿主胶水，所以先按内容去重：

- 页面脚本取云仓 `网页`、`网站`、`共用界面` 目录下排除产物与资源的 `.mjs`、`.js` 文件，覆盖试写间、包管理、云工作台的各网页应用，共 21 个不同的文件、约 409 KB，其中宿主胶水 `宿主.mjs` 约 234 KB。脚本用到：箭头函数 1,174 处、可选链 235 处、`await` 144 处、ES 模块导出 78 处、`WebAssembly` 48 处、`BigInt` 36 处、`addEventListener` 29 处、`new URL(` 26 处、`FormData` 9 处、`MutationObserver` 6 处、`fetch(` 6 处、`indexedDB` 5 处、`WebSocket` 5 处、`Worker(` 3 处、`SharedArrayBuffer` 3 处。
- 样式取云仓里 git 跟踪的全部 `.css` 文件，共 18 个不同的文件、约 177 KB。用到：`var(--` 858 处、`gap` 219 处、`display:flex` 145 处、`display:grid` 60 处、`grid-template-*` 92 处、`@media` 75 处、`:not()` 53 处、`:has()` 29 处、`clamp()` 26 处、`:is()` 9 处、`position:sticky` 8 处、`writing-mode` 5 处；没有出现容器查询、级联层、样式嵌套与 `color-mix()`。
- 页面逻辑主要是豫言编译出的 Wasm，浏览器只需要运行少量宿主胶水加 WebAssembly（含 WasmGC、JS Promise 集成、共享内存与工作线程）。

这组数据决定了里程碑二、三的特性范围：捷思引擎与浏览器接口先覆盖这些用法，样式先覆盖这些特性，再向标准的其余部分扩展。

## 三、目标与范围

- 目标：第四节的库按第五节验收。到里程碑一能看官网的静态文档，到里程碑二能浏览并操作官网，到里程碑三能在豫言浏览器里运行试写间。
- 范围内：浏览器引擎的全部纯计算与协议层（解析、样式、布局、绘制到 RGBA 缓冲、脚本、Web API、导航、安全策略）；最小壳；测试设施（官方测试集的运行器与服务器替身）；本组需要的数据包。
- 范围外（另立目标）：音视频播放与视频编解码（`<audio>`、`<video>` 只做占位盒与脚本接口；原生与裸机上还没有音频输出接口，现有的「网页媒体」只适用于浏览器）；WebGL 与 WebGPU（等图形处理器接口与着色语言库）；WebRTC；HTTP/3；PDF 阅读；AVIF、HEIC、JPEG XL（同 00004）；无障碍树与开发者工具；浏览器扩展；Service Worker 与 Web Push；多标签、书签、同步、设置等浏览器产品功能；打印与分页媒体；站点隔离与沙箱（每个源一个任务）；JIT 编译。
- 规模判断：捷思引擎与网页布局是本组最大的两个库。里程碑一不需要捷思引擎，所以先开工的次序让有价值的成果早出现。

## 四、设计：库清单

### 读法

- 每个库一节：标题写包名与批次。「必须有」是最小可用（甲级）的要求，「完整版」是完整（乙级）另外要做的，「测试」是测试与对照的来源，「依赖与使用者」写依赖哪些库、先接哪个使用者。格式同提案 00004。
- 目录为 `库/基础库/网页/<包名>/`。组父包「网页基础库」登记在「豫言基础库」的「包含包」里，并写「包含在」。数据包与库同目录，包名以「数据」结尾。
- 2026-10-09 已核对本节十三个库、三个数据包、测试工具与壳的包名，在语言仓与云仓都没有重名。
- 批次对应里程碑：第一批对应里程碑一，第二批对应里程碑二、三，完整版对应里程碑四。
- 外部标准的版本在第一次下载时锁定，记入各库的包说明；WPT 等测试集的目录名以下载版本为准。

### 依赖关系

- 超文本标记、层叠样式、捷思引擎、网页安全只依赖提案 00004 的基础库，彼此独立，可以并行开工。
- 文档对象依赖超文本标记（实现它的树建造器接口）与层叠样式（选择器匹配用树视图接口）。这两个库各自定义抽象接口，不依赖文档对象，因此没有环。
- 字体选取依赖层叠样式、字体与文字排版；网页布局依赖文档对象、层叠样式与字体选取；网页绘制依赖网页布局与二维绘图。
- 抓取依赖网页安全与超文本传输。
- 浏览器接口依赖捷思引擎、文档对象、层叠样式、字体选取、抓取、网页安全与网页布局（几何查询），并装配事件循环。
- 网页载入依赖浏览器接口、文档对象、抓取、网页安全、网页布局与网页绘制，拥有 `Window`、`Location`、`History` 与导航。
- 表单控件依赖文档对象、网页布局与网页绘制。
- 壳依赖全部。

### 第十三组 网页（`库/基础库/网页`）

#### 「网页测试设施」 · 第一批（先做）
- 必须有：
  - html5lib-tests 运行器：读 `tokenizer/*.test`（结森）、`tree-construction/*.dat`、`encoding/*.dat`、`serializer/*.test`，比对词元流、树的缩进文本与序列化结果；脚本开关两种都跑。
  - 参照测试运行器：读 WPT 的 `<link rel=match>` 与 `<link rel=mismatch>`，测试页与参照页由本引擎各渲染一遍再比较像素；支持 `reftest-wait`、`<meta name=fuzzy>` 容差。
  - WPT 脚本测试运行器：在本引擎里加载 `testharness.js` 与 `testharnessreport.js` 原文件，运行 `*.html`、`*.any.js`、`*.window.js`、`*.worker.js`，收集子测试结果（里程碑二起）。
  - test262 运行器：解析文件头的 YAML 元数据（`includes`、`flags`、`negative`、`features`），注入 `assert.js`、`sta.js` 与 `$262` 宿主对象（`createRealm`、`evalScript`、`detachArrayBuffer`、`agent`、`gc`）。
  - 期望表：每套测试集一份“测试号 → 通过、失败、跳过”的表，提交入库；运行器报告新增失败、新增通过与按目录汇总的通过率。
  - 简易 wptserve：WPT 要的静态服务（`.headers`、`.sub` 替换、`.asis`）和常用处理器（回显请求头、重定向、设置 Cookie、延迟响应）用豫言重写，基于简易网页服务器（`应用/开发工具/简易网页服务器`）。需要 Python 处理器、HTTP/2 或 WebSocket 服务的目录先跳过。
  - 数据整理工具：从仓外数据目录读测试集与 webref，生成提交入库的表格与 CI 用的黄金子集。
- 完整版：wptserve 全量替身（WebSocket、HTTP/2、带自签证书的 HTTPS 与第二个源的跨源主机名）；与别的浏览器的结果对照（wpt.fyi 的公开数据），别人也失败的用例单独标记。
- 测试：运行器自身的单元测试（用小型样例集）。
- 依赖与使用者：标准库、基础库测试设施、结森工具、简易网页服务器；本组其余各库的验收用它。命令行工具放 `应用/开发工具/网页一致性`（可执行名 `yy网页一致性`）。

#### 「超文本标记」 · 第一批
- 必须有：WHATWG HTML 解析标准：输入流预处理与编码嗅探（BOM、传输层声明、`<meta>` 预扫描，经编码转换）；词法分析的全部状态与命名字符引用（约两千二百个，由 WHATWG 的 entities.json 生成表）；树构造的全部插入模式（含表格、选择框、模板、框架集，外来内容的 SVG 与 MathML，收养机构算法）；片段解析（`innerHTML` 用）；`<template>` 内容；序列化（片段序列化算法，`outerHTML` 用）；解析错误码；输出到“树建造器”接口——一组由使用者提供的函数（建元素、插入、追加属性、取父节点等），超文本标记不依赖具体的树；增量输入（分块喂入，脚本处可暂停）。
- 完整版：预加载扫描器（先扫出 `<link>`、`<script>`、`<img>` 的地址供提前抓取）；`document.write` 的重入；XML 文档的解析（XHTML，经可扩展标记）。
- 测试：html5lib-tests 全部（tokenizer、tree-construction 含脚本开关两种、encoding、serializer）；WPT `html/syntax`。
- 依赖与使用者：编码转换、统一码；文档对象实现树建造器；终端浏览器的标记词法改用它；静态站可用它校验生成的页面。

#### 「层叠样式」 · 第一批
- 必须有：
  - 语法：CSS Syntax 3 的词法与解析（含容错规则、`@` 规则、声明、嵌套规则）；样式表、`style` 属性与 `<style>`、`<link>` 来源；CSS 嵌套。

- 设计要点：
  - 字符串是 UTF-16 码元序列，有 Latin-1 紧凑形式与 UTF-16 形式两种，拼接用绳并惰性展平；长度与下标按码元，孤立代理项可以存在；与豫言字符串互转经编码转换。
  - Number 是双精度，小整数走快路径；数值转字符串与解析经数值格式（最短往返）。
  - 字节码虚拟机的帧在堆里，生成器与 `async` 函数的挂起与恢复只是保存与恢复一个帧。
  - 对象先用属性表（哈希加有序键数组）。
  - 脚本堆里的对象是豫言的结构值，回收交给豫言运行时；脚本对象与 DOM 节点互相引用形成的环由回收器处理。
- 完整版：对象形状与内联缓存；稠密数组的快速存储；字节码优化（常量折叠、窥孔）；`Intl` 全量（`DateTimeFormat`、`NumberFormat`、`Collator`、`PluralRules`、`ListFormat`、`RelativeTimeFormat`、`Segmenter`、`DisplayNames`、`Locale`，经本地化，地区数据需扩充）；`Temporal`（标准稳定后）；调试钩子（断点、单步、作用域查询）；堆快照加速启动；热点函数编译到底层豫汇或原生（性能探索）。
- 测试：test262 的 `test/language`、`test/built-ins`、`test/annexB`（`intl402` 与 `Temporal` 在完整版跑；`staging` 与未入标准的 `features` 排除）；与诺节的 V8 对同一批随机程序做差分；引擎自写的表格测试。
- 依赖与使用者：正则（须支持码元序列输入，见第六节）、统一码、大数、数值格式、数学函数、日历、本地化、随机数、编码转换；浏览器接口、网页载入、壳。

### 写法

- **纯豫言、宿主无关**：同 00004。浏览器引擎的输入输出用字节串、结构与回调；窗口、网络、字体、剪贴板经公共接口；各库的功能在诺节、原生与裸机上一致。
- **规范驱动**：每个库的包说明注明所跟随的标准文档与版本；规范里的算法逐步翻译成同名的豫言函数（函数名用中文），注释标出规范章节，便于对照与升级。
- **容错而继续**：未实现的元素、CSS 属性与 Web API 保持页面可用——未知元素当作普通元素，未知属性忽略，未实现的 API 抛 `NotSupportedError` 或读作 `undefined`，同时记录一条诊断。超出平台限制的边角情形在代码里留待办事项，不追求现在就正确。
- **上限**：解析深度、DOM 节点数、样式规则数、布局深度、脚本调用栈、字符串与数组长度、请求数、重定向次数、缓存与 Cookie 容量，都设上限（往大里定），超限明确报错。
- **数据**：外部数据（测试集、webref、公共后缀表、HSTS 预载表）下载到仓外的数据目录 `/Users/zc/repos/yuyan-worktrees/豫言数据`；生成工具用豫言写，产出的表格提交入库；超过 1 MiB 的表另立数据包；包说明写明出处、版本与许可。
- **对照数据**：可以用别的浏览器与诺节的 V8 一次性生成参考输出（截图、序列化文本、随机程序的结果），提交为样例数据；仓内不提交 Python、shell 或 JS 脚本（AGENTS.md）。WPT 与 test262 的原始 JS 文件是下载的测试数据，留在数据目录，由运行器加载，不入库。
- **测试布局**：测试放各包的 `测试/`。进 CI 的测试（`X。测试。豫`，由全树测试自动发现）每个包合计在一分钟以内，使用数据整理工具生成的黄金子集；WPT 与 test262 的全量运行放 `测试/全量/`，在本机或 pit-mac 上跑，在 `应用/开发工具/全树测试/测试规则.tsv` 登记为跳过；期望表入库，CI 抽样检查期望表不退步。
- **各平台的验收**：诺节用豫构构建后直接运行；原生用 `yy原生生成.wasm` 生成原生程序运行；裸机在乙级时跑基本测试（QEMU）。含窗口的验收一律在后台显示面运行。
- **安全期待**：里程碑四之前，壳只用来打开自己信任的站点（官网、试写间、本地文件）；捷思引擎有调用栈与执行步数上限，没有站点隔离。
- **组织**：组父包「网页基础库」（「包含在」豫言基础库）；每个库一个子包；照 AGENTS.md 在父包的「包含包」登记并写「包含在」，测试包登记在上一级父包；版本统一从 0.1.0 起。

### 译名

起名的原则照 00004 第五节「译名」：短、能猜、像专名，四种办法按术语挑，固定语素。按提案 00013，外来的缩写、专名与接口名一律起中文名；英文原名只留在字符串、下载的数据与规范原文里。

「已定译名」一表 2026-10-09 已收进 `库/编译器核心/文档/翻译列表` 与官网[译名](https://yuyan-lang.org/译名/)页。其后各表是 2026-10-10 补拟的译名，交用户审定；审定后收进翻译列表的汉语稿、文言稿与官网译名页，本文正文里的英文写法随之换成译名。此后改名先改翻译列表与官网，再同步本文。表外的名词，实施者照同样原则自拟，第一次进代码时登记；用户改名时全树替换。

#### 接口成员与其他代码名（拟定规则）

第四节反引号里的网页接口名约 690 个：捷思内置与语法约 65 个，文档对象与浏览器接口约 235 个，层叠样式的属性、伪类、函数与单位约 200 个，超文本标记元素与属性约 80 个，超文本传输首部与内容安全策略、小饼指令约 75 个，事件约 27 个；全部网页接口数以千计。上面各表收概念级的名字，其余照下列规则办：

## 七、设计：里程碑

### 里程碑一「静态文档」（第一批 + 最小壳）

- 验收：壳能打开 `file:` 与 `http(s)` 页面，滚动、点链接、前进后退、选中并复制文字；验收页清单入库（官网文档页、阅读页、提案、包说明渲染页等，初值 30 页），每页与别的浏览器的一次性截图比对版面，由实施者与用户一起过一遍，之后以本引擎渲染的黄金图防回归。
- 测试集：html5lib-tests 全部通过；其余库达到甲级初值（脚本相关的用例除外）。
- 脚本关闭：`<script>` 当作数据块。

### 里程碑二「脚本与交互」（第二批的页面脚本子集）

- 页面脚本子集：`document`、`window`、`Element` 的 DOM 接口，事件，定时器，`fetch`、`XMLHttpRequest`、`URL`、`localStorage`、`history`、`FormData`、`MutationObserver`、`ResizeObserver`、`getComputedStyle`、`matchMedia`、`<dialog>`。
- 验收：test262 达甲级初值；云仓各网页应用的 21 个不同脚本文件原样运行，页面可交互；表单可编辑可提交；导航、历史、CORS、CSP 生效。
- 此时壳的简单载入换成网页载入与抓取。

### 里程碑三「豫言在豫言浏览器里」

- 前置：执行器的栈切换（议十二）。然后补齐浏览器接口的其余部分：`WebAssembly` JS API（含 WasmGC 与 JSPI）、`Worker`、`SharedArrayBuffer` 与 `Atomics`、Streams 与压缩流、`indexedDB`、`WebSocket`、`EventSource`。
- 验收：试写间在豫言浏览器里完成“输入豫言程序 → 浏览器内编译 → 运行 → 显示输出”；`豫言操作系统/宿主/浏览器/*.mjs` 与 `边界.mjs` 原样加载。

### 里程碑四「一致性」

- 各库达到乙级初值；完整版项目完成；适用的库在裸机上跑通基本测试。
- 性能另立目标：捷思引擎的速度决定可用性，里程碑二后单独测量（对诺节的 V8 与对 QuickJS 一类小型引擎），不作验收条件。

## 八、兼容与迁移

- 终端浏览器：停止扩展功能。里程碑一达成后，由用户决定退役，或改作新库的文字前端（布局度量用字符格）。已迁入基础库的网址处理与密码模块保持原样。
- 界面库：现有的「界面文树」（把界面树译成 HTML 交给宿主浏览器）不动；自绘后端的布局与样式模块暂时保留。里程碑二之后评估让自绘后端改用网页布局与网页绘制，使界面树经 HTML 与 CSS 在两个后端画出同样的像素。
- 操作系统接口：本提案不要求现有接口变更。需要时按 AGENTS.md 的授权补齐新接口，候选有光标形状、文件选择对话框、拖放、输入法组字事件、音频输出。
- 云仓：官网与试写间的页面脚本保持原样，作为验收对象；验收发现问题时先改引擎。
- 提案 00004：「范围外」一行的“完整的 JavaScript 引擎”后注明“见提案 00009”；第六节的前置项在 00004 进度表登记。

## 九、备选方案

- **嵌入现成的 JavaScript 引擎**（QuickJS、V8）经外部函数调用：违反“只用豫言”与“不引入第三方库”的规矩，裸机上也无法使用。
- **只做 HTML 与 CSS，不做脚本**：里程碑一就是这条路线的终点，可以在那里暂停；官网自身依赖脚本与 WebAssembly，所以需要继续做下去。
- **捷思引擎做成 AST 或闭包解释器**：起步快；生成器与 `async` 函数的挂起与恢复要靠整段 CPS 变换，难以兼顾。因此选堆上帧的字节码虚拟机。
- **把界面库的自绘布局扩成完整 CSS 布局，不另起网页布局**：自绘后端面向应用界面，样式模型是它自己的子集。两条线的合并留到里程碑二之后评估。
- **Web IDL 绑定全部手写**：接口数量大，容易遗漏；选“生成工具加手写实现”。

## 十、未决问题与默认办法

用户 2026-10-09 对第 1 条定了需求（议十二），对其余各条表示不熟悉细节，交给实施者。每条写明默认办法，实施者照办，用户有异议再改。

1. **JSPI 的实现方式**（需求已定）：默认在执行器里做栈切换。解释档保存运行状态后返回调用者，恢复时接着执行；预编二的客体函数直接用原生栈，所以给每个挂起的调用分配独立的原生栈，回收时一并扫描。执行器说明把原生系统上的任务与邮箱服务记为尚未实现，因此默认不走“每个客体实例一个任务、挂起即阻塞等待”的路线。实施时发现另一条路更快，可以改，改前在本节登记。
2. **弱引用**：默认暂用强引用，代码里留待办事项。2026-10-09 统计的 21 个页面脚本里没有 `WeakRef` 与 `FinalizationRegistry`，`WeakMap` 出现 5 处；强引用只影响内存回收，页面照常工作。真有页面依赖弱引用语义时，再给运行时加原语。
3. **正则的输入抽象**：默认在正则库新增码元序列入口（第六节第二行）；JavaScript 的非 `u` 模式按码元匹配，现有入口按码点串工作。
4. **捷思引擎的规模与速度**：先求正确，里程碑二后测量并另立性能目标；原生工具链的速度（提案 00007）决定上限。
5. **工作线程与任务**：每个工作线程一个任务，利用现有的多核与多任务支持；任务数、线程内存上限与 `Atomics.wait` 的阻塞语义需要在实现时对着内核确认（原生系统上的任务服务见第 1 条）。
6. **字体接口**：操作系统字体接口按族名给字体文件，系统字体的族枚举与通用族映射是否够用，字体选取开工时核对，缺口按 AGENTS.md 的授权直接补齐。
7. **输入法**：组字事件与候选窗位置需要显示接口的支持，表单控件开工时核对，缺口同样直接补齐。
8. **官网的非静态依赖**：默认里程碑二的验收只含匿名可见的页面（文档、包列表、阅读页、试写间）；登录、OAuth 跳转与第三方嵌入留到里程碑四评估。
9. **命名**（已定）：JavaScript 译为「捷思」（用户 2026-10-09 定），库名「捷思引擎」。不用「脚本引擎」，因为「脚本」在仓里已指豫言自己的脚本（`。脚本。豫`、提案 00003）。译名的由来已收进翻译列表与官网译名页。浏览器壳的名字暂用「浏览器」。
10. **版本节奏**：默认不挡提案 00004 的 0.1.0 公测；网页组在里程碑一达成后，作为预览随基础库发布。
