## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | **执行器自己保存调用栈，不靠宿主。** 在宿主原语返回处挂起，把正在跑的原生栈留在一条独立栈上，控制权交回宿主；宿主拿到令牌，等期约（Promise）兑现后带着结果恢复。 |
| 议二 | **每个根调用一条原生栈。** 根调用是一次从宿主进入执行器的导出调用；同一次根调用里多次挂起复用同一条栈。没有声明「诺」（异步返回）导入的模块照旧走原来的直接调用路径，不分配栈、不切换。 |
| 议三 | **挂起点只在带类型宿主导入的返回处。** 宿主原语先返回一个令牌并把「挂起请求」格置成它；`带型调用` 看到请求就调执行器的 `挂起`，把当前现场存进栈记录并切回宿主。恢复时 `带型调用` 从结果槽按导入类型写回结果，照常做结果转换。 |
| 议四 | **对外三个导出、两个豫言侧原语。** 导出是 `运行`、`恢复`、`取消`（另有 `挂起数`、`设可挂起` 两个辅助导出）；豫言侧原语是 `挂起` 与 `挂起请求`。令牌由宿主给，执行器只按令牌找记录。 |
| 议五 | **回收把挂起栈当根。** 第一版逐栈保守扫描并钉住指到的对象，保证不漏根；第二版复用 00020 的栈图精确走栈，搬移后改写栈上的根。每条栈记录保存该次调用占用的执行器全局格（当前实例、预编栈顶、栈针、异常态、回收禁、值栈根表深度）。 |
| 议六 | **两架构各四条最小原语。** 一律由冶铸生成，不新写手写机器码：`栈换`（保存当前上下文、切到另一条上下文并跳入）、`栈复制于`（按给定栈顶复制原生栈）、`取栈顶栈限`（或由状态格给出）、`建栈现场`（造第一次切进客栈的上下文）。函数序言的栈界检查改成读固定状态格，不再用编译期常量。 |
| 议七 | **解释档只写历史设计，不实现。** 解释执行路径已于 2026-10-13 删去（`说明.汉语.md`“预编侧表第 2 版与删去解释执行”、`指令处理。底层。豫` 篇首），执行器现在只跑预编二程序。第九节写清若将来恢复解释执行该保存哪些状态；本轮不改代码。 |
| 议八 | **原型不做。** 任务书要求的原型在解释档上做，而解释档已不存在；在预编二上做原型又必须先加冶铸的切换原语与序言改动，超出“不改冶铸代码生成、不新写手写机器码”的边界。第十三节写明原因与将来的做法。 |

## 二、动机

提案 00009 的议十二把“网页汇编调用栈的挂起与恢复”列为里程碑三的前置：页面里的异步宿主调用要在宿主导入处把正在跑的网页汇编栈挂起，等期约兑现后恢复。00009 第十节第 1 条定的默认做法是：解释档保存运行状态后返回调用者，恢复时接着执行；预编二的客体函数直接用原生栈，所以给每个挂起的调用分配独立的原生栈，回收时一并扫描。

现状与 00009 提出时（2026-10-09）已经不同，方案要按现状写：

- **解释档没有了。** 2026-10-13 起，解释循环、解释器的调用与尾调用、网页汇编模块解析、运行时装载模块的 `加载模块` 与 `调用导出` 都删了；执行器只运行编译器直出的预编二程序（豫行文件与原生可执行文件）。留下的只有预编二用的指令处理函数（`指令处理。底层。豫` 篇首）。所以“解释档保存运行状态”只能是历史设计，不能再做原型。
- **预编二的客体函数用原生栈。** 客体函数之间直接调用，参数、局部与操作数在寄存器和原生栈帧里；导入桩把参数写进执行器值栈的暂存区，再经 `预编调用导入`、`调用导入`、`带型调用` 进宿主原语（`豫言操作系统/裸机/库/冶铸/预编二译。豫` 5100–5155 行、`主机。底层。豫` 688–728 行）。挂起必须在这条调用链上把整段原生栈留住。
- **原生/裸机上的「诺」导入现在靠阻塞。** 接口文件里结果写成 `异步返回 于 T`（标准库的「诺」于 T）的导入，边界签名记作“异〔T 的形〕”；网页汇编接口的规范写的是“原生执行器与 Node 工具宿主照常阻塞完成”。豫言的 `坐待` 只是类型转换，生成代码为空；真正的等待发生在宿主原语里，原生执行器就在原语里开嵌套循环等（例如显示等待、终端读行）。这不能把控制权交回宿主：浏览器的事件循环推不动，原生/裸机的宿主也没机会办别的事。
- **浏览器后端现在不走执行器。** 浏览器把豫言程序编成网页汇编（WasmGC），由浏览器自己的引擎执行；`豫言操作系统/宿主/网页汇编/边界.mjs` 只给签名带“异”而实现标了异步的导入套 `WebAssembly.Suspending`，给导出套 `WebAssembly.promising`（183–185 行、253–259 行）。没有 JSPI 时，同步值桥只允许同步宿主能力，遇到返回期约的能力直接报错（`豫言操作系统/宿主/浏览器/同步值桥说明.汉语.md`）。执行器是原生程序，只在原生与裸机上跑。
- **原生上的任务与邮箱服务还没实现。** 00009 第十节第 1 条因此不选“每个客体实例一个任务、挂起即阻塞等待”的路线；裸机有任务，但任务是整份内存的复制（`主机任务。底层。豫` 27 行），原生只有一个进程、没有任务服务。

所以要做的是：在执行器里加一条与 JSPI 等价的挂起/恢复机制，让预编二的客体在宿主导入处把整段原生栈留住，控制权交回宿主；宿主恢复时把结果送回去接着跑。它对原生与裸机都成立；浏览器一侧用不用它，取决于 00009 的 `WebAssembly` 接口最后把引擎放在哪里（00043 的网页行在走的是浏览器自己的 WasmGC 引擎）。两条路在语义上对齐，接入方式分开定。

浏览器一侧还有一层前提：执行器现在是原生程序，00009 说它充当网页汇编引擎，而网页汇编程序由浏览器的 WasmGC 引擎执行。要让执行器在浏览器里跑，得先定它怎么进浏览器：把预编二的目标改成网页汇编，或由 JS 宿主用执行器协议驱动一个原生/Wasm 版的执行器。本提案先把执行器在原生/裸机上的栈切换做出来；浏览器一侧的引擎选型与接入另议，JSPI 语义的对应见第八节。

## 三、目标与范围

目标：

1. 预编二客体在带类型宿主导入里可以挂起；挂起后宿主拿回控制权，可以办别的事、等期约、再恢复。
2. 挂起期间回收照常进行，挂起栈上的引用一个不漏；搬移回收不把挂起栈指到的对象搬坏。
3. 同一次根调用可以多次挂起、多次恢复；可以同时有多条挂起的根调用；可以取消。
4. 没有「诺」导入的模块不付代价：不分配栈、不切换、序言与栈复制行为不变。
5. 语义与 JSPI 的 `WebAssembly.promising`、`WebAssembly.Suspending` 对得上：导出返回期约，导入可以等；期约兑现后从挂起点继续。

范围：

- 冶铸：新增目标内建原语、按栈的栈界与栈顶、可切栈的序言变体；预编侧表若要记“本模块有可挂起导入”则加一位（也可以由宿主设标志，见第五节）。
- 执行器二号：栈记录与栈池、挂起/恢复/取消、导出接口、`带型调用` 的挂起检查、回收的挂起栈扫描、常驻清场与任务重启的清理。
- 宿主一侧：原生宿主可继续阻塞（不启用）；网页汇编胶水按 JSPI 语义接；没有 JSPI 的浏览器可用执行器协议（前提是执行器作为引擎跑在浏览器里，见第五节的 3.3 与 8 小节）。
- 文档与测试。

不在范围：

- 不改解释执行路径（已删），不恢复解释器。
- 不实现完整的捷思期约作业队列、微任务检查点与拒绝语义；这些在浏览器接口/捷思引擎那一层。
- 不做多线程、抢占、任务迁移；挂起恢复都在同一线程、同一份线性内存里。
- 不改对象布局、豫汇、接口文件语法；`诺` 与 `坐待` 已经够用。
- 不在本轮改冶铸代码；本提案只写方案，原型见第十三节。

## 四、现状调查

### 1. 一次导出调用怎样进客体

`入口。底层。豫` 的 `启动一次`（620–696 行）在初始化完堆、全局、数据、栈复制缓冲、栈图表之后：

1. 按测试名或缺省 `_start` 查导出函数号；
2. 把测试参数压到值栈基（`状态值栈基`）；
3. 调 `预编运行函数`（`预编接口。底层。豫` 262–272 行）：帧 = 栈针 − 8×参数个数，清异常标志，调 `预编派发`；
4. `预编派发` 是转译器换成的真正派发函数（`预编接口。底层。豫` 20–23 行是占位）；它按函数号调预编二的适配函数，适配函数把 `状态预编栈顶` 设到值栈帧之后，从帧读参数调客体宽函数，把结果写回帧，再恢复 `预编栈顶`（`预编二译。豫` 5137 行起）；
5. 客体宽函数之间直接调用；导入由导入桩处理：把参数写进 `状态预编栈顶` 起的暂存区（每值八字节），调 `预编调用导入(号, 栈针)`，再读回结果（`预编二译。豫` 5100–5135 行）；
6. `预编调用导入` 调 `调用导入`，后者把 `状态栈针` 记下、按函数条取宿主号，再调 `带型调用`；
7. `带型调用`（`主机。底层。豫` 688–716 行）把 `状态回收禁` 加一，按导入的类型编码把暂存区的槽装成豫言元组 `参`，调 `按号执行原语`，按结果标志算出豫言值 `果`，把它写回暂存区，`回收禁` 减一，返回新的栈针；
8. `按号执行原语`（`主机。底层。豫` 369–639 行）按原语号分派到宿主实现：控制台、文件、显示、网络、子进程、单元装载等。

这条链上的所有帧（客体宽函数、导入桩、`预编调用导入`、`调用导入`、`带型调用`、`按号执行原语` 与宿主实现）都在同一条原生栈上。挂起要留住的就是这条栈从当前栈针到栈顶的整段。

### 2. 栈、帧与栈图

- **原生栈**：每条任务一条，由宿主或内核给。原生可执行文件的栈约 256 MiB（macOS/Linux arm64），裸机开机程序 4 MiB、豫行工具 128 MiB。栈复制缓冲按平台取 258 MiB、4 MiB 加 64 字节、128 MiB 加 64 字节（`布局。底层。豫` 809–813 行；`堆。底层。豫` 246–250 行）。
- **帧布局**（`臂降级本术。豫` 455–460、560–600 行；`兼降级本术。豫` 377–382、419–440 行）：
  - ARM64：帧大是 80 字节加局部与溢出槽，按 16 对齐；sp 处存 x30（返回地址），其后按序言保存的被调用者保存寄存器；上一帧的 sp 是本帧 sp 加帧大。客体帧的返回值在 x0，参数在 x0–x7，其后经暂存槽。
  - AMD64：先按序 push 被调用者保存寄存器（rbx、rbp、r12–r15），再减帧大；返回地址在本帧 sp 加帧大加八倍保存数；上一帧的 sp 再加八。
  - 函数入口的栈界检查用编译期常量：ARM64 通常比较 0x403D0000（裸机用户程序；内核与大字码另有常量），AMD64 比较 0x3D0000（裸机内核另有常量），低于即陷阱（`臂降级本术。豫` 522–545 行；`兼降级本术。豫` 48–70 行）。
- **栈图**（`栈图。底层。豫` 篇首；提案 00020）：降级器给每个函数入口放一条函数展开记（帧大、保存了哪些寄存器、存在哪一格），给每个可能回收的调用点放一条栈图（活着的引用在哪些帧槽或寄存器）。连接时把表接在代码之后，执行器启动时 `栈图表装入` 复制进动态区，地址记在 `状态栈图表`（9072）；`状态栈图寄位`（9076）是走栈时的寄位表，`状态栈图回写`（9080）记栈回写桩是否可用。
- **栈复制**：目标内建 `栈复制`（`宽降级本术。豫` 293–330 行 ARM64、682–720 行 AMD64）先把 x19–x30（ARM64，96 字节）或 rbx、rbp、r12–r15（AMD64，48 字节）写到缓冲头，再把当前 sp 到**编译期栈顶常量**之间的字节复制进去。栈顶来自 `鹄栈顶`（每个目标一个编译期常量）。
- **栈回写**（`宽降级本术。豫` 1129–1182 行）：搬移回收改了栈复制缓冲里的根之后，由与 `栈复制` 同帧调用的桩把改过的格按缓冲偏移写回原生栈，并按掩码把寄存器装回新值。

### 3. 回收与根

`回收`（`堆。底层。豫` 3757–3772 行）先等后台清扫、保存当前实例上下文、退游程、按需更新回收下限，再按新生代开不开走 `新生回收` 或 `老回收`。标记根的顺序（`堆。底层。豫` 3706–3727 行）：

1. 值栈：`标记根区(值栈基, 状态栈针)`（精确根打开时改按 `状态值栈根` 表逐项处理）；
2. 原生栈：在本函数里直接调 `栈复制`（与后面的 `栈回写` 同帧，sp 相同），有精确客帧时交 `精确走栈`，否则整段保守扫描；
3. 各实例根：全局、表、实例记录里的块；
4. 其余根：临时根、程序缓存、捕获缓冲、输入与请求格、子表、异步表、实例全局与表等；异常槽与异常载荷另按标签类型处理。

`精确走栈`（`堆。底层。豫` 3059–3152 行）从栈复制头的 x30（AMD64 是栈起处的返回地址）开始，二分查函数项与调用点栈图，逐帧上行；带精确栈图的客体帧把引用格记进槽表并标记（不钉住），执行器帧与没有栈图的帧交 `保守帧`（标记并钉住）；查不到函数、走出代码或到栈顶时其余部分保守扫描。搬移后 `精确改写` 按槽表改缓冲里的格，再由 `栈回写` 写回原生栈与寄存器。

`回收禁`（`布局。底层。豫` 591 行）非零时禁止回收；`带型调用` 在整个宿主原语调用期间把它加一。`宿主回收窗`（9100）非零时 `精确走栈` 才保守扫描执行器帧；执行器在宿主调用里主动回收（装载后回收、安全回收）时开窗。`状态值栈根`（9096）是值栈上活槽的登记表，`值栈根入`/`值栈根出` 在可能回收的处理前后增删。

### 4. 任务、常驻与实例

- 裸机的任务由内核复制整份内存得来，子任务换模块窗口后从头启动（`主机任务。底层。豫` 27 行）；任务之间用邮箱与子表通信。任务重启时 `重启准备` 清动态区与状态格。
- 原生只有一个任务，没有任务服务；常驻工作者（`--常驻工作者`）在一个进程里反复跑任务帧，任务之间用 `常驻清场` 把状态恢复成刚装载完的样子（`入口。底层。豫` 146–182 行）。
- 多个实例（`状态当前实例`、`实例` 模块）共用一份值栈与回收堆；执行器在宿主调用之间保存、切换当前实例的上下文。

### 5. 解释档

2026-10-13 删去解释执行路径后，执行器只剩预编二。旧解释器留下的状态格还在：`状态续指令针`（2532）、`状态帧针`（1540）、`状态帧顶`（1552）、`状态标签栈基/限`、`状态处理栈基/限`、`状态帧栈基/限`、`状态值栈基/限`（`布局。底层。豫` 517–539、823–852、1182 行）。`状态续指令针` 的注释还写着“请求处理完后继续解释的现场：指令针、帧针、栈针”。这些格现在没有解释循环去读，属于遗留。

### 6. 异步接口现状

- 类型：`「诺」于 T`（`库/豫章/本原/然诺。豫`）；`即得` 把现成值当已完成的诺，`坐待` 同步取值，`既而` 接续。三者运行时擦除：`即得`、`坐待` 是类型转换，生成代码为空；`既而` 是一次调用。
- 边界：结果类型 `异步返回 于 T` 记作“异〔T 的形〕”，只许作结果最外层；Wasm 类型与 T 相同（`网页汇编接口.汉语.md` 77–80 行）。
- 浏览器：JS 胶水只给“签名带异、实现标异步”的导入套 `WebAssembly.Suspending`，给导出套 `WebAssembly.promising`；没有 JSPI 时同步值桥拒绝异步能力。
- 原生/裸机：`诺` 导入照常阻塞完成；`坐待` 不产生等待。
- 豫章另有一套协作式异步调度（`差遣`、`待`、`让`），靠嵌套调用推进其他任务（`库/豫章/御/异步使用说明.汉语.md`）。它在同一线程、同一条栈上跑，不能把控制权交回宿主事件循环，不能代替栈切换。

## 五、设计

### 1. 总模型

把“从宿主进入执行器的一次导出调用”叫一次**根调用**（root invocation）。每次根调用有一条自己的原生栈（下称**客栈**），从客栈上进入客体代码；客体调用宿主原语、原语要等期约时，在客栈上挂起，控制权切回宿主栈；宿主等期约兑现后，带着结果切回客栈，从挂起点继续。

```
宿主栈：  运行(函数号, 参数)  ──切栈──▶ 客栈：客栈入 → 预编运行函数 → 客体函数们
                ▲                                              │
                │                                            导入桩
                │                                              ▼
                └──────── 挂起(令牌) ◀── 带型调用 ◀── 调用导入 ◀── 预编调用导入
宿主栈：  运行 返回 1（挂起，令牌）
          ……宿主等期约、办别的事、回收……
宿主栈：  恢复(令牌, 结果槽) ──切栈──▶ 客栈：挂起 返回（结果在槽里）→ 带型调用续 → … → 客栈入切回
宿主栈：  恢复 返回 0（这次根调用完成）
```

- 根调用完成、挂起、取消各有一个状态码；令牌由宿主给（见第 3 节），执行器按令牌找栈记录。
- 同一次根调用里多次挂起复用同一条客栈；多条根调用可以同时挂着，各有各的客栈。
- 没有「诺」导入的模块不启用：`运行` 直接调原来的路径（或宿主继续用 `启动`），不分配客栈、不切换。是否启用由宿主调 `设可挂起` 决定；这是一个显式开关，默认关。
- 客栈和宿主栈之间的切换只发生在执行器的 `栈换` 原语里；客栈上的所有帧（客体与执行器）原样保留，不需要逐帧搬运。

### 2. 挂起点与恢复点

**挂起点选在 `带型调用` 的宿主原语返回之后**，理由：

- 这里已经知道导入的类型编码与结果个数，能正确做 `存带型果槽`；
- 宿主原语的参数已经装成豫言元组 `参`，暂存区里的参数槽已经可以丢弃；
- 再往下一层（`按号执行原语` 或具体宿主实现）挂起，恢复后还要把原语的局部状态接上，牵扯面大；
- 再往上一层（`预编调用导入`）挂起，`调用导入` 与 `带型调用` 的结果转换还没做，恢复后要重做一遍。

做法：

1. 宿主原语要等外部结果时，把令牌写进状态格 `状态挂起请求`（新格，0 表示不挂起），返回一个占位结果。
2. `带型调用` 在 `按号执行原语` 返回后、算 `果` 之前检查 `状态挂起请求`。非零就调 `挂起(令牌)`；`挂起` 保存现场、切回宿主，宿主恢复后它返回；`带型调用` 用 `存带型果槽` 从结果槽按结果编码写回暂存区。
3. `挂起` 返回时，4.3 节已经把这些全局格写回本次调用的值；`带型调用` 仍从格重读 `状态回收禁`、`状态栈针`，不依赖寄存器里的旧副本。
4. 恢复的结果按导入签名的结果形写成**原始槽**：宿主把 i32、i64（低高两字）、f64（低高两字）或引用（一个址）按边界形写进一段缓冲，`恢复` 把缓冲地址交给执行器；`带型调用` 用一个新函数 `存带型果槽` 按结果编码把原始槽装箱/拆装后写回暂存区。这样宿主不必在客体堆里造豫言对象，装箱规则也只留在执行器一处；`存带型果` 保留给原有的豫言值路径。

`带型调用` 的伪代码（只示意，实际写法照现有代码的风格）：

```
令「无」为 回收禁加一 而
令「参」为 新元组(参数数) 而
令「无」为 填带型参(参, 编码, 栈针, 参数数, 参标) 而
令「原果」为 按号执行原语(号, 参) 而
若 状态挂起请求 非零 则
  令「令牌」为 状态挂起请求 而
  令「无」为 写四(状态挂起请求, 零) 而
  令「无」为 挂起(令牌) 而
  令「无」为 存带型果槽(栈针, 参数数, 结果编码, 读记录结果槽址) 而
  ...
否则
  令「果」为 按结果标志(原果) 而
  令「无」为 存带型果(栈针, 参数数, 结果编码, 果) 而
  ...
而
回收禁减一
```

**恢复点**在 `挂起` 内部：`栈换` 恢复现场后，`挂起` 从调用 `栈换` 的地方返回；结果已经由 `恢复` 写进记录里的结果槽。`带型调用` 的帧、`参` 元组、`栈针`、`果标`、类型编码都在客栈上，原样保留。

**异常**：期约被拒绝时，`恢复` 带一个错误标记。第一版直接把这次根调用按未捕获异常结束（退出码 137，打印原因），与现在浏览器里未接住的拒绝同类；可捕获的异常跨挂起留到后续版本（见第十一节）。挂起期间不允许已经有一个异常在传播：`挂起` 检查 `状态预编异常`，非零就拒绝挂起并按未捕获异常结束。

### 3. 宿主接口

#### 3.1 执行器导出

新增导出（签名按豫言写；参数标签按 AGENTS.md 的标签规定加）：

| 导出 | 签名 | 含义 |
| --- | --- | --- |
| `运行` | `化「函数号」曰「整数」又化「参数栈针」曰「整数」又化「令牌出址」曰「整数」为「整数」` | 在客栈上运行一个导出函数。0 完成，1 挂起（令牌写到出址），负数为错误 |
| `恢复` | `化「令牌」曰「整数」又化「结果槽址」曰「整数」又化「异常」曰「整数」又化「新令牌出址」曰「整数」为「整数」` | 用令牌恢复挂起的根调用。结果按原始槽放在结果槽址；0 完成，1 又挂起（新令牌写到出址），负数为错误 |
| `取消` | `化「令牌」曰「整数」为「整数」` | 丢弃挂起的根调用，释放客栈。0 成功，负数为错误 |
| `挂起数` | `化「有」为「整数」` | 当前挂起的根调用数（诊断用） |
| `设可挂起` | `化「有」为「整数」` | 打开可挂起路径；在 `运行` 之前调一次。返回 0 |

说明：

- `运行` 的参数栈针与现在的 `预编运行函数` 一致：参数已经按值栈槽压好，`参数栈针` 指向最后一个参数之后。结果留在值栈上，宿主按导出签名的结果形读取。`令牌出址` 是线性内存里的一个八字节格（或四字节，按宿主定；建议八字节，方便 64 位宿主）。
- `恢复` 的 `结果槽址` 指向一段按导入结果形排好的原始槽：每槽八字节，i32 放低字，i64 与 f64 低高两字，引用放一个址；零结果的导入忽略它。多个结果的导入按结果个数逐个槽给出；元组结果是一个引用槽。宿主按边界签名写槽，`带型调用` 用 `存带型果槽` 装箱/拆装后写回暂存区；结果个数与结果编码都来自导入的函数条，宿主不必知道装箱规则。`异常` 为零表示正常恢复，非零表示期约被拒绝（第一版按未捕获异常结束根调用，返回 −7）。`新令牌出址` 在返回 1 时写新令牌，返回 0 或其他状态时不动。
- 根调用完成时，`运行`/`恢复` 把最终的栈针写进 `状态运行栈针`，宿主据此读取结果槽；`启动` 路径也写这一格。`恢复` 按记录里的结果个数把宿主交来的结果槽拷进记录里的结果槽区，再切栈；记录区按根扫描，宿主缓冲随即可以复用。结果个数与结果编码由 `挂起` 从导入的函数条存进记录。
- 令牌由宿主给，执行器不分配：宿主用单调计数器，从 1 起，0 保留给“没有挂起”。执行器只检查非零、不重复；重复令牌 `运行`/`恢复` 返回负错误码。同一次根调用每挂起一次，宿主给一个新令牌；旧令牌在恢复后作废。
- `运行` 与 `恢复` 都可以返回 1：`运行` 第一次挂起，`恢复` 之后又挂起。宿主循环处理，直到 0 或负。
- 状态码建议：0 成功；1 挂起；−1 令牌无效；−2 没有空闲客栈；−3 在不允许挂起的状态（回收禁、异常传播、正在回收）；−4 函数号或参数不合法；−5 栈溢出；−6 已取消；−7 根调用因期约拒绝而结束。具体数字在实施时定，这里只定语义。

`启动`（`_start`）与 `运行` 的关系：`启动` 现在是 `化「有」为「有」`，没有返回值，宿主拿不到状态。可挂起模式下，`设可挂起` 之后 `启动一次` 把 `_start` 交给 `客栈入`，把状态写进状态格 `状态运行结果`（0、1 或负），把令牌写进 `状态挂起令牌`，完成时把最终栈针写进 `状态运行栈针`；`启动` 照常返回，宿主读这些格决定是否 `恢复`、到哪里读结果。状态为 1 时 `启动一次` 不打印结果，结果留给宿主。`运行` 用于宿主在启动之后再调应用接口导出：参数由宿主压好，状态直接作返回值，不必读格。两者共用同一套栈记录与令牌表。`设可挂起` 要在 `启动` 之前调；原生进程的入口直接是 `启动`，没有这个调用，照旧阻塞。

#### 3.2 豫言侧原语

给宿主实现（原生执行器里的宿主原语）用：

| 原语 | 签名 | 含义 |
| --- | --- | --- |
| `挂起` | `化「令牌」曰「整数」为「有」` | 由 `带型调用` 调用：保存现场、切回宿主；恢复后返回。结果在记录的结果槽里，不由它带回 |
| `挂起请求` | `化「令牌」曰「整数」为「有」` | 宿主实现要挂起时调它，只置 `状态挂起请求`；由 `带型调用` 统一挂起 |

`挂起` 只允许在 `带型调用` 的宿主原语返回处调用；在其他地方调（回收中、GC 栈扫描中、异常传播中）返回 −3。实现时这些函数名照《取名规范》取，本文的名字只作说明。

#### 3.3 与浏览器接口的用法

浏览器一侧的 JS 胶水如果走执行器的协议（执行器作为引擎跑在浏览器里，见第八节），按下面的方式接。两张表：`根表` 把当前令牌对到一次根调用的期约，`导入表` 把令牌对到发起挂起的那次导入的期约。

```
const 根表 = new Map();     // 令牌 -> { 兑现, 拒绝, 读结果 }
const 导入表 = new Map();   // 令牌 -> { 期约, 结果槽, 错, 可恢复, 已恢复 }

function 运行期约(函数号, 参数栈针) {
  const 令牌出 = 分配八字节();
  let 状态 = 实例.exports.运行(函数号, 参数栈针, 令牌出);
  if (状态 === 0) return 读结果();
  if (状态 !== 1) throw Error(...);
  return new Promise((兑现, 拒绝) => {
    const 根 = { 兑现, 拒绝, 读结果: () => 读结果(读八字节(状态运行栈针), 签名) };
    const 令牌 = 读八字节(令牌出);
    根表.set(令牌, 根);
    const 项 = 导入表.get(令牌);
    if (项) 项.可恢复 = true;
    试恢复(令牌);
  });
}

function 异步导入实现(...) {
  const 令牌 = 取下一个令牌();          // 从 1 起的单调计数器
  const 项 = { 期约: 实(...), 结果槽: 分配八字节槽们(结果数),
               错: undefined, 可恢复: false, 已恢复: false };
  导入表.set(令牌, 项);
  项.期约.then(
    值 => { 造原始槽(项.结果槽, 值); 试恢复(令牌); },
    错 => { 项.错 = 错; 试恢复(令牌); }
  );
  写四(挂起请求格, 令牌);
  return 哑元;                          // 按签名造成类型相合的空值
}

function 试恢复(令牌) {
  const 根 = 根表.get(令牌);
  const 项 = 导入表.get(令牌);
  if (!根 || !项 || !项.可恢复 || 项.已恢复) return;
  if (项.结果 === undefined && 项.错 === undefined) return;  // 期约还没兑现
  项.已恢复 = true;
  const 新令牌出 = 分配八字节();
  let 状态 = 实例.exports.恢复(令牌, 项.结果槽, 项.错 ? 1 : 0, 新令牌出);
  if (状态 === 1) {                    // 又挂起：换新令牌，等下一次
    导入表.delete(令牌);
    根表.delete(令牌);
    const 新令牌 = 读八字节(新令牌出);
    根表.set(新令牌, 根);
    const 新项 = 导入表.get(新令牌);
    if (新项) { 新项.可恢复 = true; 试恢复(新令牌); }
    return;
  }
  if (状态 === 0) {
    根表.delete(令牌); 导入表.delete(令牌);
    根.兑现(根.读结果());
  } else {
    根表.delete(令牌); 导入表.delete(令牌);
    根.拒绝(项.错 ?? Error(...));
  }
}
```

要点：

- 异步导入的期约可能先兑现、执行器后返回“挂起”。所以 `试恢复` 要等 `运行`/`恢复` 真正返回 1、根表里有了令牌之后才动作；`可恢复` 标志在 `运行`/`恢复` 返回 1 之后设，`试恢复` 再看期约是否已兑现。
- 返回 1 时执行器换一个新令牌；`根表` 把根记录搬到新令牌，`导入表` 里新令牌的项由那次导入的包装函数事先登记。
- 同一时刻一条客栈上只会有一个挂起请求；多条根调用各有各的令牌。
- 期约兑现后由胶水把结果按边界形写成原始槽（`造原始槽`），再调 `恢复`；`造原始槽` 与现在 `包装实现` 的 `果造器` 同一套拆装，只是写进缓冲而不是交给引擎。
- 期约拒绝第一版按未捕获异常结束（见第 2 节末）。

### 4. 客栈、栈池与现场

#### 4.1 栈池

- 栈池在 `初始化堆` 之前用 `取区域不清` 取，避开堆；每栈固定大小，按 16 字节对齐。原生默认 64 条、每条 1 MiB（共 64 MiB 虚拟地址，用多少占多少）；裸机默认 16 条、每条 128 KiB（共 2 MiB，裸机的线性内存实占物理页，按小值定）。宿主选项 `--栈池 数=大小` 可改，限额往大里定（原生可到 1024 条）。
- 每栈下面留一段守卫（原生 64 KiB、裸机 16 KiB），栈限 = 栈基加守卫。函数序言的栈界检查读 `状态栈限`，sp 低于它即陷阱；守卫本身在线性内存里是已映射的，序言先减栈再检查时写进守卫不会踩到别的栈。守卫小于最大帧大时，序言可能先写到守卫外；实施时把可切栈变体的序言改成**先检查、后减栈存寄存器**，或把守卫定得大于编译器允许的最大帧大（取两者较小者）。
- `栈换` 装新上下文时把目标栈的顶与限写进 `状态栈顶`、`状态栈限`：切进客栈写客栈的顶与限，切回宿主写宿主的顶与限（启动时由平台常量填入）。记录里同时存客栈与宿主两套；这两个格必须在跳转之前写好，新栈上的第一个函数序言才能用对新界。
- 栈池耗尽时 `运行` 返回 −2；宿主可以退回阻塞路径（原生）或报错（浏览器）。不自动增长栈池，避免在回收/挂起中途分配。

#### 4.2 栈记录与令牌表

每条栈记录（建议 512 字节，令牌表用 `取区域` 在初始化堆之前取，原生 1024 项、裸机 64 项）：

| 偏移 | 内容 |
| --- | --- |
| +0 | 上下文头：ARM64 x19–x30（96 字节），AMD64 rbx、rbp、r12–r15（48 字节）；与栈复制头同布局，回收直接用它 |
| +96/+48 | sp、pc（或返回地址）、入参址、状态、令牌、代际、栈基、栈顶、栈限、栈大小、宿主栈顶、宿主栈限 |
| +… | 保存的执行器全局格：当前实例、预编栈顶、栈针、异常标签/个数/标记、回收禁、宿主回收窗、值栈根表项数与前若干项（放不下就拒绝挂起） |
| +… | 待恢复的结果槽（每槽八字节，按导入结果形；槽里的引用要作根）、结果个数与编码、错误码 |
| +… | 下次挂起的令牌出址、本次根调用的最终栈针 |

- 令牌表按令牌线性查找（1024 项以内够快）；要更快就做开放寻址。令牌重复时拒绝。
- 代际：记录复用后旧令牌不能恢复新调用；令牌里带记录号与代际，或表项存代际并核对。
- 上下文头与栈复制头同布局，是为了回收时把记录头直接当栈复制头用，不必另写一套寄存器名表。

#### 4.3 每次根调用要保存的全局格

挂起还要保存执行器的全局格：这些格由所有根调用共用，挂起期间别的调用会改它们。挂起时存进栈记录、恢复时写回：

| 格 | 为什么 |
| --- | --- |
| `状态当前实例` | 多条根调用可能属于不同实例；恢复时要换回自己的实例 |
| `状态预编栈顶` | 客体代码调指令处理函数时按这个固定格取暂存区；恢复后必须指向本次调用的暂存区 |
| `状态栈针` | `调用导入`/处理函数用的临时栈针；恢复后下一次导入调用会重设，但为稳妥一并保存 |
| `状态例外标签`、`状态例外数`、`状态例外载荷`、`状态预编异常` | 挂起时不允许异常在传播；保存是为了恢复后不把别的调用的异常状态带进来 |
| `状态回收禁` | `带型调用` 在宿主原语期间加一；挂起后别的根调用要能回收，所以挂起时记下本调用的值并清零，恢复时写回 |
| `状态宿主回收窗` | 同理；挂起栈的执行器帧要保守扫描，不能沿用别的调用的窗 |
| `状态值栈根` 表（项数与各项） | `预编调用导入` 的单元运行路径在调客体前登记结果槽；挂起期间表会被别的调用改写，要保存本调用的部分 |

不需要保存的：栈图寄位表（回收时临时填）、预编立即数缓冲（每次处理重填）、标记栈与整理状态（只在回收内部有效）、栈复制缓冲内容（每次回收重填）。

`状态值栈基/限`、`状态栈复制缓`、`状态栈图表`、`状态全快`、堆的格都是全进程共享的，不随根调用变，不保存。

### 5. 切换原语（两架构）

#### 5.1 需要的最小原语

由冶铸在目标内建导入里生成，豫言侧只写声明，不写机器码：

| 原语 | 签名 | 作用 |
| --- | --- | --- |
| `栈换` | `化「旧处」曰「址」又化「新处」曰「址」为「有」` | 把当前被调用者保存寄存器、sp、pc 存进 `旧处` 的上下文；从 `新处` 装寄存器、sp、pc，并把新处的栈顶、栈限写进固定状态格，然后跳过去。不按普通函数返回 |
| `栈复制于` | `化「目的」曰「整数」又化「容量」曰「整数」又化「栈顶」曰「址」为「整数」` | 同现有 `栈复制`，栈顶由参数给出；仍先写寄存器头再复制 sp 到栈顶 |
| `栈顶栈限` | `化「有」为「址」`（两个：`取栈顶`、`取栈限`） | 读当前栈顶/栈限；或改成读固定状态格的普通函数，由执行器自己维护 |
| `建栈现场` | `化「栈顶」曰「址」又化「入参」曰「址」为「址」` | 造一个“从客栈入进入”的初始上下文（pc 指向冶铸生成的固定入点桩，sp 按 ABI 摆好，返回地址放哨兵）。只用于第一次切到客栈 |

其中 `栈换` 是唯一真正碰 sp/pc 的原语；它是不带帧的桩，保存的是调用者（`挂起`）的现场，冶铸不为它生序言与尾声。`栈复制于` 与现有 `栈复制` 一样是叶桩，不改 sp，才能与 `栈回写` 在同一个 GC 函数里按缓冲偏移对应。`建栈现场` 是为了不在豫言源码里取函数地址（底层豫言没有一等函数）。四条都由冶铸生成，两架构各一份，约几十条机器指令。

#### 5.2 上下文内容

| | ARM64 | AMD64（SysV） | AMD64（Windows） |
| --- | --- | --- | --- |
| 整数被调用者保存 | x19–x28、x29（帧链）、x30（返回地址） | rbx、rbp、r12–r15 | 同 SysV |
| 栈针/程序计数器 | sp、pc | rsp、pc（返回地址可由 pc 兼） | 同 SysV |
| 浮点被调用者保存 | d8–d15（若冶铸生成代码会用；现序言不保存，可先不存） | 无（SysV 全部调用者保存） | xmm6–xmm15 |
| 对齐 | sp 16 字节对齐 | 入函数时 rsp % 16 = 8（返回地址已压） | 同 SysV |

- ARM64 的上下文头与栈复制头一致：x19–x30 依次放 +0 至 +88；`栈换` 存/取这 12 个寄存器。sp、pc 放头之后。
- AMD64 的头是 rbx、rbp、r12–r15（48 字节）。`栈换` 存的 sp 指向返回地址，pc 就是 [sp] 里的返回地址；恢复时把 sp 加八跳过返回地址，再跳到 pc。这样栈图走栈在 AMD64 上看到的返回地址位置与普通调用一致。
- 初始现场：`建栈现场` 按各架构的 ABI 摆 sp，并在 sp 处放哨兵 0 作返回地址；恢复后 sp 跳过哨兵进入 `客栈入`，`客栈入` 不返回，真返回会跳到 0 触发陷阱，便于发现错误。
- 上下文里带栈顶、栈限：`栈换` 在装新上下文时一并写 `状态栈顶`、`状态栈限`，再跳；这样旧栈在改格之后不再执行任何带序言的函数。
- 浮点寄存器：现行冶铸序言只保存整数寄存器，说明生成代码不跨调用用 d8–d15/xmm6–15；第一版上下文不存浮点寄存器。若将来生成器用它们，必须在序言与上下文里一并加，否则恢复后浮点值会变。

#### 5.3 栈界与栈顶改成运行时的

这是本方案对冶铸最大的改动，也是必须的：

- **栈界**：可切栈变体的序言不再比较编译期常量，而是从固定状态格 `状态栈限` 读当前的栈限再比较。两格在 `初始化堆` 之前、任何回收可能发生之前填好平台原值；填之前读到零，序言的比较不拦（sp 大于零），启动阶段照常。ARM64 现在用 `臂装址` 装常量到 x9 再比较；改成从固定地址装 x9。AMD64 现在 `cmp rsp, imm32`；改成从固定地址装到 r11 再比较。两格由 `栈换` 在装新上下文时改写，所以不开可切栈的程序行为不变。
- **栈顶**：`栈复制` 改成读 `状态栈顶`（或新原语 `栈复制于` 显式传顶）。启动时把平台栈顶常量填进格，不开可切栈的程序行为不变。
- **编译开关**：新增 `可切栈` 开关（名字在实施时定），只给执行器本身和要挂起的程序开；内核、引导程序、普通工具不开，序言与栈复制保持原样。这样不改变现有默认行为，也不影响内核的固定栈界。
- **裸机的地址问题**：裸机线性内存实占物理页，不能像原生那样在 3–4 GiB 留大栈池；客栈从动态区取（低地址），所以栈界必须是运行时的，不能再用 1 GiB 的常量。这也是必须改序言的原因之一。

### 6. 回收挂起栈

#### 6.1 总则

- 每条挂起的栈记录是一条根：回收开始时逐条扫描，与当前栈并列。
- 挂起栈不在 CPU 上跑，扫描期间不会被改写；可以直接在客栈内存上扫，也可以复制进栈复制缓冲扫。第一版用复制，复用现有 `精确走栈` 与 `保守帧`。
- 当前栈照旧：在本函数里调 `栈复制于(复缓, 容量, 状态栈顶)`，与后面的 `栈回写` 同帧，sp 相同。

#### 6.2 第一版：保守扫描并钉住

第一版不追求精确，先把“不漏根”做对：

1. 对每条挂起记录，把上下文头（96/48 字节）与 [sp, 栈顶) 复制进栈复制缓冲（一条一条来，缓冲够大；单条客栈不超过缓冲容量，超过就按栈大小上限拒绝挂起）。
2. 用现有的 `标记根区(缓, 缓+字节, 8)` 整段保守扫描。候选字指到堆里的对象就标记；整理时 `标记根区` 会走 `钉标候选` 把对象所在块钉住。执行器帧与客体帧一视同仁，不做栈图。
3. 标完清空缓冲，处理下一条。
4. 搬移回收时，被挂起栈指到的对象都被钉住，不会搬走，所以不需要改写挂起栈；恢复后栈上的引用仍然有效。
5. 值栈：挂起时按第 4.3 节保存 `状态预编栈顶`、`状态栈针` 与值栈根表；暂存区的内容不必保存：参数已经装进 `参` 元组，结果等恢复后由 `存带型果` 写入。挂起栈上的 `参` 元组在客栈上（执行器帧里），保守扫描会钉住它。

代价：挂起栈上的整数、旧值可能被当成指针，钉住一些本该搬走的对象，碎片多、常驻高。第一版可以接受；挂起调用通常不多、栈不深。

#### 6.3 第二版：精确走栈

第一版稳定后，复用 00020 的精确栈图：

1. **标记阶段**：对每条挂起记录，把上下文头与 [sp, 栈顶) 复制进缓冲，调 `精确走栈(缓, 字节, 槽表, 槽容, 阳)`。带调用点栈图的客体帧精确标记、不钉住；执行器帧与没有栈图的帧保守扫描并钉住（扫描挂起栈时临时把 `宿主回收窗` 加一，或给 `精确走栈` 加一个“强制扫执行器帧”的参数）。
2. **搬移阶段**：照常搬移。
3. **改写阶段**：再复制一次同一条栈（内容没变），调 `精确走栈(..., 阴)` 收集槽表（不标记），再调 `精确改写(缓, 槽表, 数)` 改缓冲里的格；然后把槽表里指向栈数据的格按缓冲偏移写回客栈内存，把指向上下文头的格写回栈记录的寄存器头。挂起栈不在跑，直接写内存安全，不需要 `栈回写` 桩。
4. **两次走栈**：标记与改写各走一次，省掉为每条栈长期保存槽表；代价是每条挂起栈每次搬移回收多走一遍。挂起调用多时再改成一次走栈 + 栈记录里存槽表。

边界情形：

- 走栈到客栈入口（`客栈入`）时返回地址是哨兵 0，`栈图查函数` 得零，`精确走栈余` 把剩余部分保守扫描；`客栈入` 的帧里只有入参与少量局部，保守扫描足够。
- 栈记录头里的寄存器值（x19–x30/rbx–r15）是走栈起点；`精确走栈` 从 x30/返回地址开始，与当前栈一致。
- 挂起栈的 `栈顶` 是客栈顶，由栈记录给出；`精确走栈` 用复制后的字节长度判断到顶。
- 整理压力、毒化、交还整块等现有机制不变；被钉住的块不参与疏散。

#### 6.4 挂起期间发生的回收

- 挂起时 `状态回收禁` 清零（本调用的值存在记录里），所以宿主等期约期间分配可以触发回收。恢复时写回原值。
- 宿主在等期约时可以调 `安全回收`（宿主回收窗），回收扫描所有挂起栈与当前栈；挂起栈的执行器帧保守扫描，钉住。
- 后台清扫线程（macOS）只清老区，不碰栈；与挂起栈无交互。
- 回收正在扫某条挂起栈时，不允许该栈被恢复或取消：用一条“扫描中”标志或全局锁（执行器是单线程，实际只需在扫描循环里不调宿主）；`恢复`/`取消` 遇到正在扫描返回 −3。

#### 6.5 根表与异常

- `状态值栈根` 表：挂起时把本调用登记过的项复制进记录，清空表；恢复时写回。表项里的地址指向值栈槽，值栈槽在挂起期间可能被别的调用写；第一版的 `值栈根` 项只出现在 `预编调用导入` 的单元运行路径，默认禁止在该路径挂起（返回 −3），留待办事项。
- 异常对象与载荷：挂起时不允许异常在传播；记录里保存异常格的副本只用于恢复后不串状态，不把它们当根（它们指向的对象若只被挂起调用持有，会被保守扫描的 `参` 或栈上的其他引用保住；若没有别的引用，异常对象本来也该随调用结束回收）。
- 结果槽：`恢复` 的结果槽在切换前登记为根（保守扫描或临时根），免得 `恢复` 里分配时回收把它指到的对象搬走；第一版保守扫描记录里的结果槽。
- 保存的值栈根表：记录里复制的那份表项也要在回收时处理（第一版禁止单元运行路径挂起，表为空；第二版按 9096 的格式精确处理）。

### 7. 生命周期

- **运行**：`运行` 检查 `设可挂起`、函数号、参数；分配或复用一条客栈记录；参数已经由宿主按值栈槽压好；填上下文；`栈换` 到客栈。
- **挂起**：`带型调用` 看到请求，调 `挂起`；`挂起` 复用当前根调用的记录（令牌由请求格给），把导入的结果个数与编码存进记录，保存 4.3 节的全局格，把宿主归处上下文存进记录，置状态为挂起，`栈换` 回宿主。`运行` 或 `恢复` 返回 1，令牌写出；结果等 `恢复` 写进结果槽。
- **恢复**：`恢复` 按令牌找记录，核对状态与代际；把结果放进记录；恢复 4.3 节的全局格；把 `恢复` 自己的归处上下文存进记录的“宿主归处”；`栈换` 到客栈。`挂起` 返回，结果在记录的结果槽里，`带型调用` 续跑并写回结果。根调用完成时 `客栈入` 把控制权切回记录的“宿主归处”，`恢复` 返回 0；若又挂起，`挂起` 切到最新的“宿主归处”，返回 1。
- **完成**：`客栈入` 拿到 `预编运行函数` 的终栈针，存进记录；切回宿主；宿主读结果、释放客栈记录（放回空闲表）、清令牌。
- **取消**：`取消` 核对令牌；把记录标为取消、放回空闲表、清令牌。客栈上的对象不再被扫描，等回收收掉；宿主负责关掉外部资源（连接、定时器）。被取消的调用以后不会再恢复。
- **重入**：宿主在一条根调用里回调进执行器（例如单元运行、宿主原语调用客体回调）时，如果已经在客栈上，就直接在同一客栈上调用，不另建记录；这次调用里挂起会把整条客栈（含外层帧）挂起，外层 `启动`/`运行` 返回 1；恢复后内层调用照常返回。语义与 JSPI 的可重入调用一致。实现上用一个 `状态当前客栈` 格判断。
- **多实例**：每条记录保存 `状态当前实例`，恢复时换回；值栈与暂存区按 4.3 节保存 `预编栈顶`。第一版按单实例验证，多实例留待办事项。
- **常驻工作者**：`常驻清场` 要把栈池记录全部标为空闲、清令牌表、复位栈池游标；有挂起调用没完成时，清场前按取消处理（或拒绝清场并报错，默认取消）。
- **裸机任务重启/子任务复制**：`重启准备` 把栈池与令牌表清零（记录不能跨程序）；子任务复制父任务内存时，父任务的挂起记录不应被继承，重启准备时清掉。
- **进程退出**：挂起调用随进程结束；宿主负责外部资源。
- **上限**：挂起数不超过栈池条数；令牌表满返回 −2；单条栈超过容量返回 −5；不允许在回收中、异常传播中、GC 扫描中挂起（−3）。

### 8. 与网页汇编 JSPI 语义的对应

| JSPI | 执行器栈切换 |
| --- | --- |
| `WebAssembly.promising(f)` 包装导出，调用返回期约 | 宿主调 `运行`；返回 0 是已完成的期约，返回 1 是挂起，宿主用令牌造一个未兑现的期约，`恢复` 返回 0 时兑现 |
| `WebAssembly.Suspending(f)` 包装导入，导入返回期约时挂起 | 导入实现把令牌写进 `状态挂起请求`，`带型调用` 调 `挂起`；期约兑现后 `恢复` 把结果送回 |
| 导入返回非期约 | 不写请求格，照常同步返回；与现在一样 |
| 期约兑现 | `恢复` 把结果写进结果槽，`挂起` 返回，`带型调用` 用 `存带型果槽` 做结果转换 |
| 期约拒绝 | 第一版按未捕获异常结束根调用（137）；后续可做可捕获异常 |
| 多个并发根调用 | 每条根调用一条客栈；每次挂起一个令牌；宿主自己管期约与令牌的对应 |
| 可重入调用 | 已在客栈上就直接在同一客栈调用；挂起整条栈 |
| 取消/丢弃 | `取消(令牌)`；JSPI 没有标准取消，这是执行器的扩展 |
| 同步导出（没有异步导入） | 宿主继续用 `启动`/原来的直接路径，不切换 |

语义差别：

- JSPI 的挂起发生在 Wasm 引擎内部，期约的作业队列由 JS 引擎管；执行器的挂起只把控制权交回宿主，期约、微任务、拒绝传播由宿主（JS 胶水或原生事件循环）管。
- JSPI 对 `Suspending` 导入的拒绝会抛进 Wasm 栈；执行器第一版只结束根调用，可捕获异常留待后续。
- JSPI 的 `promising` 导出在同一实例上可重入；执行器第一版支持重入，但不支持同一令牌并发恢复（令牌是单次的）。

### 9. 解释档怎样保存与恢复（历史设计）

解释执行路径已于 2026-10-13 删去，这一节只记录“如果将来恢复解释执行，挂起/恢复该怎么做”，本轮不实现。

旧解释器的状态分两部分：

- **堆上的客体状态**：值栈（`状态值栈基/限`，每槽八字节）、调用帧栈（`状态帧栈基/限`，每项 32 字节：返回位置、帧针、函数号、标签顶、处理顶）、标签栈（每项 16 字节）、处理器栈（每项 32 字节）、当前实例与全局、异常格。这些都在线性内存里，不需要原生栈切换。
- **解释循环自己的状态**：指令针、帧针、栈针、当前函数、当前标签顶/处理顶、步数计数等，在原生栈的局部变量里。

挂起做法（若恢复解释器）：

1. 在宿主原语返回处，把循环的局部状态写进 `状态续指令针` 起的一组格（`布局。底层。豫` 1182 行就是为此留的：指令针、帧针、栈针、结果槽在栈针之下）；把值栈上 [本帧基, 栈针) 的内容留在原地（值栈是全局的，别的调用可能覆盖，所以要么给这次调用保留一段值栈，要么把这段复制进堆里的续延记录）。
2. 从宿主原语正常返回到解释循环，循环看到“挂起”标志就退出、返回宿主；不需要 `栈换`，因为客体状态都在堆上。
3. 恢复时把续延记录里的值栈段写回、把 `状态续指令针` 起的格写回，以恢复标志重新进入解释循环的“继续”入口（不重新分派函数），从保存的指令针接着跑。
4. 回收：解释器的值栈按类型位图或按 `状态值栈根` 表精确处理；帧栈里的引用按函数类型的局部编码处理；续延记录本身是一条根，按记录里的类型表扫描。

与预编二的差别：解释档不需要独立原生栈，只要把堆上的状态与循环局部保存好；预编二的客体值在寄存器和原生栈上，所以必须切栈。两者对外的 `运行`/`恢复`/`取消` 接口可以相同。

## 六、兼容与迁移

- **默认不启用**：可切栈是编译开关，执行器与程序不开时，序言、栈复制、`启动` 路径、产物字节都与现在相同；已发布的原生文件与豫行文件照常运行。
- **运行时格**：`状态栈顶`、`状态栈限` 在启动时填平台原值，所以可切栈构建的普通路径也与现在一致；只有切到客栈时才改。
- **内核与引导程序**：不开可切栈，固定栈界与固定栈顶不变。
- **工具链耦合**：新目标内建与可切栈序言要先由冶铸支持，合入、自举、连续版本工具链发布后才在执行器与程序里用（AGENTS.md“包与接口”）。旧稳定编译器编当前源码时看不到新内建，所以第一步只改冶铸且不让旧编译器用到它。
- **侧表**：不在预编侧表加必填字段；可挂起由宿主 `设可挂起` 打开。这样侧表版本不变，旧执行器/旧工具链不会因为新字段报错。
- **浏览器**：现有 `边界.mjs` 的 JSPI 路径不动；执行器协议是新增的可选路径，按 00043 的部署决定是否接。没有 JSPI 的浏览器仍走同步值桥的拒绝路径，直到执行器协议接上。
- **32 位构建**：不启用可切栈（性能对比用，工具链不启用）；上下文与栈记录按 64 位地址写，32 位构建留待办事项。
- **对象布局、豫汇、接口文件、豫行格式**都不变。

## 八、风险

1. **栈溢出与守卫**：客栈小，深递归或大帧会溢出；序言先写后检查可能踩守卫外的内存。对策：守卫不小于最大帧大，或序言先检查后写；溢出按 −5 结束根调用并打印诊断；栈大小可调。
2. **回收漏根**：挂起栈上的引用没扫到，对象被回收；或搬移后没改写，恢复后悬空。对策：第一版保守扫描 + 钉住，保证不漏；第二版精确走栈加“两次走栈”改写；大量 GC 压力测试（挂起前后各分配、强制全量、整理压力）。
3. **全局格串状态**：挂起期间别的根调用改了 `状态预编栈顶`、`当前实例`、`回收禁`、`值栈根` 表，恢复后用到错的值。对策：4.3 节逐格保存/恢复；测试里同时挂起两条根调用并互相分配。
4. **重入与嵌套**：宿主回调进执行器、又挂起，或同一实例多个根调用交错；令牌与客栈对应错。对策：单线程、每根调用一条栈、令牌单次；重入走同一客栈；测试覆盖。
5. **工具链自举**：新内建与新序言需要新冶铸；旧稳定编译器不认新内建。对策：先合冶铸支持，等连续版本工具链，再用；执行器与冶铸同源重建。
6. **地址与平台差异**：原生栈顶常量、裸机低地址、Windows x64 的 xmm6–15 与展开信息、macOS x64 的 8 GiB 限制；对策：可切栈变体用运行时栈界/栈顶，平台各自的上下文表，Windows 单独验证。
7. **浮点寄存器**：现行序言不保存 d8–d15/xmm6–15；若生成器将来用了，恢复后浮点值会坏。对策：第一版确认生成器不用；要用时同时改序言与上下文。
8. **语义**：期约拒绝、取消、微任务顺序、JSPI 一致性；对策：第一版拒绝按未捕获异常、取消是扩展；浏览器一侧与现有 JSPI 路径分开测，逐步对齐。
9. **安全**：挂起让客栈在宿主手里停留，宿主可能误改线性内存；令牌校验、栈记录边界检查、取消后不恢复；不把 `栈换` 暴露给客体代码，只给执行器内部。
10. **性能**：可切栈序言每次函数入口多一次内存读（读栈限格）；可切栈程序每次根调用多两次 `栈换`；回收多扫挂起栈；栈池占虚拟地址。对策：默认不开；只有声明「诺」导入的模块开；测量原生/裸机构建与桌面帧时间。
11. **测试困难**：浏览器 JSPI 与执行器协议两条路、裸机 QEMU 慢、GC 时序不确定。对策：先用原生探针与确定性测试，再上浏览器与裸机；GC 用压力开关。

## 九、验证办法

本轮只写方案，不跑构建。实施时按下面的顺序验证：

1. **类型检查**：`豫构 类型检查 客体二号 -j 8`（远端检查副本）；冶铸的包也做类型检查。
2. **单元/探针**：新 `栈切换。底层。测试。豫` 用一个只在该测试里注册的宿主导入：客体调它，它置挂起请求并返回占位；测试宿主循环 `运行`→等一拍→`恢复`，核对结果；覆盖一次挂起、连续两次挂起、两条根调用交错、取消、拒绝。
3. **回收压力**：在挂起与恢复之间分别做：小分配、强制全量回收、整理压力（`整理压力` 开关）、新生代开着与关着、精确根开着与关着；核对恢复后栈上的引用仍指向正确对象（用带哨兵的结构/数组）。
4. **回归**：没有「诺」导入的程序照旧走原路径；现有普通探针、文件探针、原生探针、编译器自举产物逐字节相同。
5. **原生**：macOS arm64 与 Linux 两架构；`豫构 全部 -j 8` 自举定点；运行探针。
6. **裸机**：QEMU 上跑探针；注意裸机内存小，栈池用默认小值。
7. **浏览器**：有 JSPI 时现有路径回归；无 JSPI 时用执行器协议（若执行器作为引擎跑在浏览器里）跑一个调异步导入的页面；没有这条路径就只测胶水的同步拒绝。
8. **格式检查**：`./格式检查。林纳。豫行 --标识符 <改过的目录…>` 与 `--标签 yybs`，改过的文件 0 处。

## 十、备选方案

- **整段续延变换（CPS / Asyncify）**：把每个函数改写成可保存/恢复的状态机，挂起时逐帧保存局部到堆，恢复时逐帧重建。不选的理由：要改整个代码生成与所有间接调用、异常与尾调用，代码体积和运行开销大；预编二已经有栈图与精确根，栈切换的元数据已经具备；CPS 还要处理宿主回调与重入，复杂度不低于切栈。
- **每个挂起调用一个 OS 线程，挂起即阻塞线程**：不选。原生没有任务/线程创建接口（只有 macOS 后台清扫线程），裸机线程栈与调度更重；线程间共享堆与回收要加锁；JSPI 语义是单线程协作，不需要真并行。
- **每个客体实例一个任务，挂起即阻塞等邮箱**：00009 第十节第 1 条已排除；原生任务与邮箱服务没实现，裸机任务复制整份内存，代价大。
- **只靠浏览器的 JSPI**：能覆盖浏览器，不覆盖原生/裸机；Safari 等浏览器对 JSPI 的支持不齐；执行器自己的程序（工具链、桌面）用不上。可以作为浏览器后端的短期路径，不能代替执行器能力。
- **挂起时把当前栈整段复制到堆，恢复时复制回来**：不选为默认。复制要在挂起点做，栈上可能有指向栈内的指针（帧链、局部地址、传给宿主实现的栈地址），复制后要逐处重定位，和 CPS 一样难；而且每次挂起 O(栈) 复制。独立客栈从开始就在自己的栈上跑，不搬。
- **用宿主 C 的 `setjmp`/`longjmp` 或 `ucontext`**：不选。要引入宿主 C 代码，裸机没有；`longjmp` 不保存被调用者保存寄存器与浮点状态，跨客体帧不安全；违反“只写豫言、不新写宿主代码”的规矩。
- **把挂起点放在 `预编调用导入` 或 `按号执行原语`**：不选。前者还没做结果转换，恢复后要重做；后者不知道导入的结果类型，挂起后无法正确写回。

## 十二、实施步骤

1. **冶铸原语与序言**：加 `栈换`、`栈复制于`、`建栈现场`、`取栈顶/栈限`；可切栈序言与运行时栈界；先用不启用可切栈的构建验证现有程序产物逐字节不变。
2. **执行器栈池与 `运行`**：栈池、记录、令牌表、`客栈入`、`运行`；先不做挂起，只验证“在客栈上跑一个普通导出，结果与原来相同”。
3. **挂起/恢复**：`带型调用` 检查请求、`挂起`、`恢复`、`取消`；测试宿主循环；先只支持一次挂起。
4. **回收第一版**：挂起栈保守扫描 + 钉住；4.3 节全局格保存/恢复；GC 压力测试。
5. **生命周期**：多次挂起、多根调用、重入、取消、常驻清场、任务重启；上限与错误码。
6. **回收第二版**：精确走栈、两次走栈改写、执行器帧保守；整理压力测试。
7. **浏览器胶水**：按第 3.3 节接；有 JSPI 的路径保持；无 JSPI 的路径按 00043 的部署决定。
8. **文档与收尾**：说明、包说明、接口规范、00009 进度表；清理待办事项。

## 十三、原型说明

任务书要求“原型（可选，做得出才做）：只在解释档实现挂起与恢复原语，加一个测试（客体里调宿主函数挂起、宿主稍后恢复、结果正确）”。本轮没有做，原因：

1. **解释档不存在**。2026-10-13 起解释执行路径已删（`说明.汉语.md`、`指令处理。底层。豫` 篇首），执行器只运行预编二程序；没有“解释档”可以加挂起/恢复原语。
2. **预编二原型越界**。要在预编二上做真正的挂起/恢复，必须先有 `栈换`、`建栈现场`、按栈的栈界与栈顶，这些都要改冶铸的代码生成并新增机器片段；任务书的边界是“不改冶铸的代码生成、不新写手写机器码”。
3. **只做一半的原型没有意义**。只把当前栈复制一份登记成“挂起栈”能测回收扫描，但测不到“宿主稍后恢复、结果正确”的核心语义，反而给执行器加一段默认不走的代码与状态，风险大于收益。

将来做原型的最小路线（在边界放开之后）：

1. 先实现第十二节第 1 步（冶铸原语与可切栈序言），用现有探针确认不启用时产物逐字节不变。
2. 实现第十二节第 2 步的 `运行` 与 `客栈入`，跑一个普通导出，确认结果与 `启动` 相同。
3. 实现第十二节第 3 步的一次挂起/恢复，测试宿主是执行器里的一个假宿主原语：客体调它，它置令牌并返回占位；执行器的测试驱动调 `运行`，拿到 1 后等一拍（或直接）调 `恢复`，核对客体拿到的结果。
4. 在挂起与恢复之间做一次强制全量回收，核对栈上的哨兵引用仍有效。
5. 再补多次挂起、取消、两条根调用交错。

这个路线不碰解释档，也不需要解释档；它是预编二的正路。任务书之所以写解释档，是按 00009 提出时的现状写的；现状已经变了，方案按现状办。
