| 项 | 内容 |

| 状态 | 已接受 |

| 范围 | 豫构与编译器的默认产物；豫构与编译器合成一个程序；构建缓存（豫汇与机器码）；原生生成器；原生可执行文件的格式；测试与 CI |

这是把豫言的构建生态整体换到原生上的提案：可执行包默认产出本机原生可执行文件，`.wasm` 改为显式目标；豫构与编译器合成一个程序；构建按模块缓存豫汇与机器码。用户 2026-10-09 定：这些都做，完全把生态换到原生上；前提是原生的所有构建都不慢于 Node，否则不切。

本文只写现代汉语（AGENTS.md）。

## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | 可执行包的默认产物是本机原生可执行文件：macOS 写 Mach-O，Linux 写 ELF，豫言操作系统写豫行（提案 00005）。`.wasm` 改为显式目标，供浏览器、诺节、云工使用。Windows 的原生工具链补齐前，Windows 上仍默认 `.wasm` |
| 议二 | 原生可执行文件同豫行一样嵌入预编侧表，不再嵌入客体 `.wasm` 模块（提案 00005 第 5 步的做法推广到 Mach-O 与 ELF） |
| 议三 | 豫构与编译器合成一个程序（一个文件）：编译器作库被豫构直接调用；并行编译仍用工作进程，由同一个程序以工作模式启动，进程常驻、按任务复用 |
| 议四 | 构建缓存：每个源文件的豫汇按内容缓存（汇编树码，提案 00001 议十）；预编二与降级的机器码按函数缓存，链接时只重做变了的部分；执行器运行时每个工具链只降级一次，各程序共用 |
| 议五 | 速度门槛：每一类构建（冷编、完整构建、改一个文件后的增量构建、小程序构建并运行、测试套件）原生都不慢于 Node；任何一类不达标就不切默认。「原生对比」扩展到这些场景，CI 照旧在慢时警告 |

## 二、动机

1. 原生工具链（`yy4_bs.exe`、`yy豫构.exe`）在 macOS、Linux 已经是默认，并在 pit-mac 的同机对比里冷编快约 14%、完整构建不慢于 Node（持续改进目标《原生工具链》基准七、八）；但用户程序仍默认产出 `.wasm`，原生文件要另跑「原生生成」。
2. 原生生成慢且不增量：本机 2026-10-09 实测，生成器在 Node 上把豫构预编成原生要 18 秒、编译器要 80 秒；每个程序都把执行器运行时与客体一起整个重新降级。照现在的样子切默认，构建会从几秒变成几十秒。
3. 原生可执行文件仍嵌入客体 `.wasm`，每个进程启动时都要解析一遍（编译器约 4 MB，完整构建要起一千五百多个工作进程）。

## 三、目标与范围

做：

- 原生可执行文件嵌入预编侧表（议二）。
- 原生生成提速：生成器本身预编成原生；按程序摘要缓存产物；执行器运行时预降级一次并缓存；客体函数按函数缓存机器码，链接时重定位。
- 豫构与编译器合成一个程序（议三），编译器以库的形式提供“编译一个模块”“最终链接”“原生生成”的调用。
- 豫汇按模块缓存（议四），最终链接直接从缓存的豫汇出原生文件，不经 `.wasm`。
- 默认产物切换（议一）：豫构、仓库目标、全树测试、CI 一起改；`--目标 网页汇编` 显式产出 `.wasm`。
- 豫言操作系统里同样默认产出豫行文件。

留待后续：

- Windows 的原生工具链与默认切换。
- 预编二转译器直接读豫汇模型（现在先编码成二进制再交给它；这一步只是名字解析加序列化，耗时远小于降级）。

## 四、设计要点

### 4.1 合一程序

豫构的入口逻辑移进库，新的可执行包「豫言工具链」同时带豫构与编译器：`yy豫言 构建 …` 走豫构，`yy豫言 编译 …` 走编译器，工作进程用同一个文件。原生上并行仍靠进程（执行器的状态在固定地址，一个进程里不能开多个实例），工作进程常驻、经管道领任务，省掉每个任务的启动。

### 4.2 缓存

- 豫汇：编译每个源文件的末段产物改存汇编树码（与现在的闭包形式缓存并列），最终链接把各模块的豫汇拼成一个模块。
- 机器码：缓存键是函数的豫汇内容、类型布局摘要与生成器摘要；函数间的调用与对全局、类型的引用写成重定位，链接时填。
- 执行器运行时：每个工具链版本降级一次，存成带符号表的目标块。

### 4.3 门槛的度量

「原生对比」（`应用/开发工具/原生对比`）加四个场景：改一个文件后的增量构建、小程序（你好）构建并运行、测试套件子集、原生产物生成本身。每个场景在 pit-mac 安静窗口跑五轮取中位，原生与 Node 之比不大于 1。

## 五、实施步骤

1. 原生可执行文件嵌入预编侧表；原生生成的产物变小、启动不再解析模块。验收：原生工具链冷编整个豫言系统与 Node 产物逐字节相同；原生对比不变差。
2. 原生生成提速：生成器预编成原生、按摘要缓存、执行器运行时预降级复用。验收：小程序原生生成在一秒级。
3. 机器码按函数缓存与重定位链接。验收：改一个文件后的增量原生生成在一秒级。
4. 豫构与编译器合一，豫汇按模块缓存，最终链接直出原生文件。验收：完整构建、增量构建不慢于 Node。
5. 默认产物切换：豫构、仓库目标、全树测试、CI 与文档；豫言操作系统里默认产出豫行文件。验收：议五的全部场景达标后才合入切换。
6. Windows 原生工具链（另议）。
