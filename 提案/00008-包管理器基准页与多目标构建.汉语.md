| 项 | 内容 |

这是给包管理器补两块展示能力的提案，分工只有一句话：**构建、测试、判定、告警全在 yybs 的 GitHub CI 里完成，yuyan-cloud 只记录与展示 CI 的结果。**

- **基准页**展示各包的性能数字。第一批内容是提案 00004 的六十三个基础库与提案 00007 的“原生对比”。
- **可执行下载**为每个可执行包展示各目标平台的构建产物。产物由 CI 在包内容变化后为全部目标自动构建。

本文只写现代汉语（AGENTS.md）。用户 2026-10-09 定：CI 直接在 yybs 上跑，与测试一样，不定时；yuyan-cloud 只记录和展示数据。

## 暂缓说明

用户 2026-10-09 定：yuyan-cloud 暂时保持现状，本提案暂缓实施，内容保留。

- **先行的部分**：CI 一侧作为独立任务先做，与本提案互不依赖。性能验证在 yybs 的 CI 里按改动运行，原生比诺节慢时直接发 GitHub 警告并写步骤摘要；记录上传与长期跟踪留待恢复本提案时再做。对应本文 4.1、4.2 的入口、判定与警告。
- **暂缓的部分**：yuyan-cloud 的记录、展示与下载接口和页面（4.4、4.5），CI 的上传作业与摘要查询，可执行包的多目标构建与按目标下载（4.3），以及 4.6 里的云仓落点。
- **恢复条件**：需要长期跟踪性能数字，或需要在包页提供各平台的下载时，从 4.4 起实施。CI 工具的记录格式预留了向 4.1 记录的转换，接上传作业即可。

## 二、动机

### 基准数据散在文档里

2026-10-09 对提案 00004 的六十三个库逐库调查（读各库包说明与记录文档，不运行测试）：

- 22 个库没有任何性能数字，其中邮件格式、列存数据、矢量图、数值格式、统计 5 个库的入口已写好，没跑过。
- 29 个库只有原生对诺节的数字，没有同机 C 对照。
- 12 个库有 C 对照：全部达标的有命令行解析（比值 1.03，对照含进程启动）；部分达标的有可扩展标记（解析 3.04 倍、DTD 校验 4.50 倍）、音频的 WAV（1.77 倍）、压缩的莱齐4 解压（1.8 倍）；其余约 5 倍到数百倍，多数对照含进程启动，口径不一。
- 已有数字写在各库文档里，多为单次测量，机器与负载不统一（记录的负载从 20 到约 150），测于 2026-10-08 前后，早于 2026-10-09 的原生工具链合入。
- 性能入口几乎都在 `测试/全量/` 下或不以「。测试。豫」命名，CI 不运行。

### CI 警告只活一轮

`应用/开发工具/原生对比` 在原生慢于 Node 时打印 `::warning`，表写进作业摘要（`.github/workflows/main.yml` 的“原生与 Node 性能对比”步骤）。警告只出现在那一轮的运行页，没有历史，也看不出趋势。把每轮的数字存进包管理器，就有了固定的落脚点。

### 可执行下载只有发布者本机那一份

- `yy批量发布` 用 `uname -s`、`uname -m` 取发布者本机的系统与架构（只接受 macOS 与 Linux），生成 `运行/<系统>-<架构>.tar.gz`，内容是编译好的 `.wasm` 程序。
- 服务端把 `运行/` 当作普通材料存取，没有“目标”的概念。整档 ZIP 与单文件各限 16 MiB，装不下多个原生目标（2026-10-09 在 pit-mac 量得：`yy豫构.exe` 约 10 MB，`yy4_bs.exe` 约 32 MB）。
- 访问者在包页拿不到自己系统的可执行文件，除非发布者恰好在同一系统上发布。

### CI 已有现成的做法

- 原生生成器 `yy原生生成` 在任意一台主机上都能生成 Mach-O、ELF、PE32+。“视窗原生样例生成”作业在 ubuntu-latest 上生成 Windows 两个架构与 macOS x86-64 的可执行文件，“视窗原生样例运行”与“苹果 x86-64 原生样例运行”作业再在 windows-latest、windows-11-arm、macos-15-intel 上运行验证。
- “Wasm 包起步”作业在 ubuntu-latest、ubuntu-24.04-arm、macos-latest 上生成本机原生工具链并运行“原生对比”。
- 仓库约有 104 个可执行包（2026-10-09 统计 `。包。豫` 里类型为可执行文件的包）。

## 四、设计

### 4.1 性能入口与基准记录

- **入口约定**：性能入口是包 `测试/` 下的 `X。性能。豫`，由 `git ls-files` 发现，与测试一样无需登记。全树测试对它们只做类型检查（保证不腐烂），实际运行在性能作业里。现有的 `性能。豫`、`性能。测试。豫` 等入口随提案 00004 的补验收逐步改名。
- **记录**：入口运行时每个项目打印一行 `基准记录 {…}`（结森对象）。入口打印的字段：

| 字段 | 含义 |
| --- | --- |
| `项目` | 包内的基准项目路径，用 `/` 分层，如 `泽标/解压/混熵262144` |
| `中位纳秒`、`轮数`、`预热`、`噪声` | 计时结果，先预热再重复取中位数；`噪声` 是各轮相对中位数的绝对偏差的中位数 |
| `规模` | 每次操作处理的字节数或次数，用来换算吞吐 |
| `对照` | 可选：`名称`、`版本`、`中位纳秒`、`口径` |
| `目标` | 可选：`对照倍数`（豫言÷对照）与 `诺节倍数`（原生÷诺节） |

- **口径**：`同进程内核`（对照方只计内核，如 C 循环吞吐）、`端到端`（双方都含启动与读写）、`含启动`（只有一方含启动）。前两种参与判定，第三种只展示比值，标“参考”。
- **默认目标**：`对照倍数` 取提案 00004 第五节的 3（第一批）或 5（其余）；`诺节倍数` 取提案 00007 议五的 1.0。
- **工具补全**：性能工具在记录上补 `版本`（格式版本，现为 1）、`包`、`后端`（原生、诺节）、`平台`（`<系统>-<架构>`）、`提交`、`工具链`（构建所用工具链的提交）、`机器`（类别、处理器、核数、内存），并算出 `倍数`（对照、诺节）与 `达标`（所有给出目标的倍数都不超过目标；没有目标或没有可比项时为空）。
- **输出方式**：基础库「测试设施」的基准库增加 `记录基准`，入口调用它即可。

示意：

```json
{"版本":1,"包":"豫言/压缩","项目":"泽标/解压/混熵262144","后端":"原生","平台":"苹果-臂六十四","提交":"42d48207a","工具链":"42d48207a","中位纳秒":3969000,"轮数":9,"预热":2,"噪声":0.04,"规模":{"字节":262144},"对照":{"名称":"zstd","版本":"1.5.7","中位纳秒":20500,"口径":"同进程内核"},"目标":{"对照倍数":3,"诺节倍数":1.0},"倍数":{"对照":193.6,"诺节":0.63},"达标":false,"机器":{"类别":"共享机","处理器":"Apple M1","核数":3}}
```

### 4.2 CI：性能验证

- **触发**：推送 yybs 与手动触发（`workflow_dispatch`，可选“全部”），步骤带 `if` 限定，拉取请求中的同一作业跳过它。不设定时。
- **位置**：作为“Wasm 包起步”作业（ubuntu-latest、ubuntu-24.04-arm、macos-latest）的一步，那里已有本机原生工具链，与“原生对比”相邻。
- **选包**：每个包算「包内容摘要」——包目录及其依赖闭包（不含标准库与工具链路径）各目录的 git 树哈希，排序后连接再取 SHA-256。工具向 yuyan-cloud 查询各包最近一次记录的摘要，摘要不同的包才运行其性能入口；查询失败时按本次推送改动的文件选包。与云端记录比较，使被取消的旧轮（同一分支新推送会取消旧轮）留下的改动也能在下一轮补上。
- **运行**：同一个入口先经诺节运行，再预编译为原生运行，沿用“原生对比”与现有基准入口的做法；每平台总时限 30 分钟，超时的入口记“未运行”并列进摘要。
- **判定与告警**：整个作业只发一条 `::warning title=基准::未达标 N 项，详见 https://yuyan-lang.org/基准`，前 30 个差距写进步骤摘要；作业保持成功。
- **上传**：记录写成构件，独立的小作业取构件、用仓库机密 `YY_UPLOAD_TOKEN` 调 `yy基准上报` 上传；该作业只运行上传工具。上传失败只发警告。

### 4.3 CI：多目标构建

目标矩阵：

| 目标 | 常用名 | 产物 | 原生生成参数 | 冒烟运行器 | 成熟度 |
| --- | --- | --- | --- | --- | --- |
| 苹果-臂六十四 | macOS（Apple 芯片） | Mach-O，tar.gz | `苹果 臂六十四` | macos-latest | 稳定 |
| 苹果-兼容六十四 | macOS（Intel） | Mach-O，tar.gz | `苹果 兼容六十四` | macos-15-intel | 稳定 |
| 林纳克斯-兼容六十四 | Linux x86-64 | ELF，tar.gz | `Linux 兼容六十四` | ubuntu-latest | 稳定 |
| 林纳克斯-臂六十四 | Linux ARM64 | ELF，tar.gz | `Linux 臂六十四` | ubuntu-24.04-arm | 稳定 |
| 视窗-兼容六十四 | Windows x64 | PE32+，zip | `视窗 兼容六十四` | windows-latest | 预览 |
| 视窗-臂六十四 | Windows ARM64 | PE32+，zip | `视窗 臂六十四` | windows-11-arm | 预览 |
| 网页汇编 | 跨平台（Node／浏览器） | `.wasm` 加 Node 宿主，tar.gz | `豫构 构建 … --输出 x.wasm` | ubuntu-latest | 稳定 |

作业链，仿“视窗原生样例生成／运行”的结构：

1. **可执行包构建**（ubuntu-latest）：选出摘要变了的可执行包（规则同 4.2）；对每个包先经 `双宿主构建 --自动 原生` 的路径绑定接口适配、编译成客体，再对每个原生目标运行 `yy原生生成`；打包（Unix 目标 tar.gz 保留 755，视窗 zip），算 SHA-256，作为构件传给后续作业。
2. **可执行包冒烟（<运行器>）**：六个真机运行器各取自己目标的构件，限时运行每个产物（默认无参数、标准输入关闭、5 秒），记录退出码与装载错误。
3. **上传可执行包**：签名（沿用《产物签名规范》的 DER 旁签，私钥种子放仓库机密），用 `YY_UPLOAD_TOKEN` 上传各目标的产物与状态。

要点：

- **不支持**：构建工具按包的接口依赖闭包对照各目标的“宿主提供”清单（`豫言操作系统/适配/` 下各适配的 `宿主提供.json`），缺接口的目标记「不支持：缺接口 X」，不算失败。
- **失败与冒烟**：目标构建失败、冒烟失败都作为状态记录上传，页面可见；作业发一条汇总警告，保持成功。
- **交叉参数**：`双宿主构建` 的自动原生模式目前固定以 `本机 本机` 调用生成器（`宿主构建。豫` 的 `按原生构建`），需要增加 `--系统`、`--架构` 才能交叉生成。这是语言仓一侧的小改动。
- **全量**：日常只构建摘要变了的包；首次回填与需要全量重建时手动触发“全部”，按包分组分片并行。
- **Windows**：PE32+ 写出器已在 windows-latest 与 windows-11-arm 上实跑，宿主接口覆盖仍少于 macOS 与 Linux，所以标“预览”：状态照常显示，不影响页面的“完整”标记。

### 4.4 yuyan-cloud：接口与存储

接口（身份是现有的上传令牌，令牌所属账户绑定的所有者须等于路径或记录里的所有者）：

| 方法与路径 | 用途 | 身份 |
| --- | --- | --- |
| `POST /api/benchmarks/runs` | 上传一次运行：`{运行, 样本[]}`，单次至多 16 MiB | 上传令牌 |
| `GET /api/benchmarks/digests?owner=…&platform=…` | 各包最近一次记录的内容摘要 | 公开 |
| `GET /api/benchmarks/summary?package=…`、`/series?…`、`/gaps` | 页面用的最新值、序列、差距总表（JSON） | 公开 |
| `PUT /api/artifacts/<所有者>/<包名>/<版本>/<提交>/<目标>` | 上传产物字节 | 上传令牌 |
| `POST /api/artifacts/<所有者>/<包名>/<版本>/<提交>/<目标>` | 上传该目标的状态与元数据（状态、原因、冒烟、SHA-256、旁签、来源） | 上传令牌 |
| `GET /api/artifacts?package=…`、`/digests?owner=…` | 页面用的产物清单；各包最近一次构建的内容摘要 | 公开 |

存储（D1 新增三张表，迁移编号取实施时的下一个，当前最新为 0024；列名用中文，沿用 `云端构建任务` 的风格）：

| 表 | 用途 | 主要列 |
| --- | --- | --- |
| `基准运行` | 一次上传 | 编号、所有者、提交、工具链提交、来源（CI 运行网址）、平台、机器、时间 |
| `基准样本` | 一个项目的一次测量 | 运行、包、项目、后端、中位纳秒、轮数、噪声、规模、对照、目标、倍数、达标、包内容摘要 |
| `构建产物` | 一个包版本在某个提交、某个目标上的构建 | 所有者、包、版本、提交、目标、状态、原因、冒烟、字节、SHA-256、产物键、旁签键、来源、包内容摘要、时间 |

- 服务端不判定：`倍数`、`达标`、`状态` 都原样存 CI 给的值。
- 产物字节存 R2 的 `构建产物/<所有者>/<包名>/<版本>/<提交>/<目标>/<文件名>`；服务端只核对字节数与 SHA-256、文件头魔数与目标一致（Mach-O、ELF、PE），不改字节。
- 保留：每个（包、目标）留最近 20 次构建，上传时清理更早的；基准样本保留 800 天。
- 限额往大里定：单个产物 100 MiB（取当前套餐的请求体上限）；单次基准上传 16 MiB、20 万条样本；每个所有者每天 200 次上传。

### 4.5 yuyan-cloud：页面

路由：`/基准`、`/基准/<所有者>/<包名>`、`/基准/<所有者>/<包名>/<项目>`、对应的 `….svg` 徽章。官网路由的包服务前缀表（`应用/网站/入口/路由。豫` 的 `包府路径`）加入 `/基准`。

- **总览**：顶部统计（达标、未达标、参考、无对照的项数，按包组汇总，包组取“包含在”层级）；「差距总表」按倍数降序，列有包、项目、后端、平台、耗时、对照（名称与口径）、倍数、目标、达标、趋势小图；筛选项有包组、后端、平台、达标。
- **包页**：该包全部项目的最新值与趋势小图。
- **项目详情**：折线图两张（耗时、倍数），按后端×平台出线，横轴是提交时间，悬停显示提交与机器；运行表；对照说明；原始记录下载（JSON、CSV）。
- **徽章**：显示“达标”或“N 倍”，可贴进包说明。
- **可执行下载**：包页的新区块，列各目标的最近构建（目标、状态、大小、提交、时间、SHA-256、旁签、冒烟、下载）和最近 20 次的历史；页面脚本按访问者的系统与架构高亮对应行；永久链接 `/packages/<所有者>/<包名>/最新/下载/<目标>`。所有“稳定”目标都是“成功”或“不支持”时，区块标“完整”，显示“已完成 n／m”。
- **渲染**：服务端用豫言生成 HTML 与内联 SVG。SVG 里的文字由浏览器用页面字体绘制，服务端不需要字体。图（折线、小图、徽章）由包服务私有库实现，约二三百行；基础库「图表」暂不接入，免得把二维绘图与字体带进 Worker。
- **无脚本可用**：表与图都是静态内容；筛选沿用包列表的纯 CSS（`:has`）做法，样式沿用包服务页面的外壳。

### 4.6 落点

yuyan-cloud（云仓，云端功能只写豫言）：

- `应用/包管理服务/库/基准`、`应用/包管理服务/库/构建产物`（新库）：记录校验、存取、图、页面数据。
- `应用/包管理服务/库/阅读处理`：页面路由；包页新区块。
- `应用/网站/入口/路由。豫`：包服务前缀加 `/基准`。
- `应用/包管理服务/迁移/`：新迁移，生产迁移先于部署。
- `应用/包管理服务/验收/`：豫言验收（假记录驱动存取、越权、限额、页面数据；假产物驱动魔数与摘要核对）。

语言仓：

- `库/基础库/测试设施`：`记录基准`。
- `应用/开发工具/原生对比` 或新应用「性能验证」：选包、双后端运行、判定、警告、摘要。
- `应用/发布/基准上报`、`应用/发布/产物上传`：新工具，复用 `yy批量发布` 的令牌读取。
- `应用/开发工具/全树测试`：把 `X。性能。豫` 列为只做类型检查的种类，并同步包说明。
- `应用/发布/批量发布`：产物签名入口从 `发布.zip` 推广到任意产物文件。
- `豫言操作系统/应用/双宿主构建`：自动原生模式加 `--系统`、`--架构`。
- `.github/workflows/main.yml`：性能验证步骤、可执行包构建／冒烟／上传作业、上传性能记录作业。

## 五、兼容与迁移

- yuyan-cloud 的接口都是新增，旧整档上传与旧接口不变；已有修订的 `运行/` 原样保留。
- `yy批量发布` 的正式发布不变。包页的“可执行下载”显示 CI 的最近构建，并标明构建所用提交；与正式发布版本的绑定留待后续。
- 回填：首次手动触发“全部”，把现有可执行包构建一遍。
- 文档同步：包服务使用说明、批量发布包说明、提案 00004 的性能验收条款（以基准页为准）、全树测试包说明（性能入口只做类型检查）。

## 六、备选方案

- **服务端判定与基线**（初稿方案）：判定、基线、退步检测、告警都放在 yuyan-cloud。复杂度高，CI 内判定已够用，所以只留记录与展示。
- **外部构建器协议**（初稿方案）：服务端派任务、独立仓库的工作流取源码构建并回传。适合第三方包，列为后续；第一版不需要。
- **github-action-benchmark、Bencher、CodSpeed 等现成服务**：数据在站外，页面与账户体系各立一套；仓库的工具都用豫言写，所以自建。
- **只放 GitHub Pages 静态页**：缺账户与所有者体系，与包页割裂，难做按包的页签与徽章。
- **定时运行**：共享机噪声大，定时运行对“包内容没变”的包重复测量；按包内容变化触发更省，也更贴近测试的习惯。

## 七、未决问题

1. **全量运行时间**：日常只跑变化的包；标准库与工具链变更不改变包内容摘要，只触发“原生对比”，是否需要给它们配一组“核心”入口自动运行，待头几周的耗时数据再定。手动“全部”的单平台耗时待测，必要时按包分组分片。
2. **性能入口的现有存量**：现有入口分散在 `测试/全量/` 和各兄弟包里，改名为 `X。性能。豫` 的节奏（属提案 00004 的工作）。
3. **构建产物与正式版本的对应**：包页现在显示“最近构建”并标明提交；正式发布时是否把同提交的产物挂到该修订下。
4. **冒烟约定**：默认“无参数启动不报装载错误”够不够；包声明里是否增加冒烟参数与期望退出码的字段。
5. **单个产物超过 100 MiB**：改用 R2 分段上传。
6. **macOS 隔离属性与公证、Windows SmartScreen**：浏览器下载的未公证可执行文件会被系统拦一道，页面需要给出放行步骤。
7. **共享机噪声**：CI 的数字用于趋势参考；权威数字可以由开发机（pit-mac）手动上传，`机器` 字段的类别区分，页面可切换显示。
8. **查询摘要的失败回退**：yuyan-cloud 不可达时按改动文件选包，会漏掉被取消的旧轮的改动，下次成功查询时补上。

## 八、实施步骤

基准页（1 至 4）与可执行下载（5 至 6）可以并行；上传令牌与目标词表先定。

1. **记录与入口**：`记录基准`、字段校验与解析、`X。性能。豫` 的发现与全树测试的类型检查。验收：诺节与原生各一个入口输出合法记录。
2. **yuyan-cloud 基准**：迁移、`POST /api/benchmarks/runs` 与查询接口、页面（总览、包页、项目详情、徽章）、路由前缀。验收：豫言验收（存取、越权、限额）；浏览器检查（桌面与窄屏）。
3. **CI 性能验证**：选包、双后端运行、判定、汇总警告与摘要、上传作业；先接已有 C 对照的 12 个库和“原生对比”的构建场景。验收：一次推送后页面有数据，运行页有警告。
4. **其余库的入口**：按提案 00004 补空白入口，接入即可（属 00004 的工作）。
5. **yuyan-cloud 产物**：迁移、产物上传与下载接口、魔数与摘要核对、包页“可执行下载”区块。验收：假产物驱动全部状态；旧修订页面不变。
6. **CI 多目标构建**：`双宿主构建` 加交叉参数；可执行包构建／冒烟／上传作业；签名。验收：三个真实可执行包（如 `豫言/云设备代理`）端到端，六个原生目标在真机冒烟通过，页面可下载。
7. **回填**：手动“全部”，把现有可执行包构建一遍。
8. **后续**：第三方包云端构建、与正式版本绑定、豫行目标、Windows 转正、公证与代码签名。
