## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | **零损耗的分法**：计算与数据面在本进程以本机机器码直接跑——内存访问、算术、文件、网络、终端经执行器的宿主后端办理，路径按附庸表改写（00039 §4.4），不拦截、不模拟；控制面——进程身份与生灭、准入、内存、处理器、任务归属、任务之间的消息、共享块与显示——交行在，按进程、按块、按件这样的粗粒度来往。没有指令模拟、没有设备模拟、没有第二个内核，所以没有 QEMU、VMware 那样的损耗 |
| 议二 | **行在是唯一的账**：宿主上豫言进程的进程表、父子、内存（已给、限、峰给）、处理器租约与“谁在跑哪件任务”只记在行在里。豫言程序——连同将作、代役、监工与行在自己——不向宿主操作系统打听别的进程：不问进程号对应、父进程号、实占、常驻与处理器时间 |
| 议三 | **自报不旁查**：每个进程关于自己的事，经自己的行在连接告诉行在（登记、领存、还存、领役、毕役、处理器时间）；行在不替它去问内核 |
| 议四 | **籍号**：进程登记时由行在发籍号，与裸机内核的任务号同义；任务表、`列出役`、`豫构 行在 状态`、将作与监工都只用籍号。宿主进程号只留在行在内部，结束进程、发信号时用。改 00039 §4.2 的“任务号就是宿主进程号” |
| 议五 | **父子由登记带来**：执行器起子进程时，把本进程的籍号经环境变量 `豫言行在父籍` 交给子进程，子进程登记时带上；行在凭此建进程树，不再问宿主的父进程号（原语 292） |
| 议六 | **任务记进行在**：代役给每件任务的环境块补一条 `豫言将作役号`（它本来就逐件补内存上限与软额）；执行器在任务开跑时发“领役”问帧，做完发“毕役”问帧，行在当场答，本机回环一来一回，相对任务可以忽略。行在任务表多一栏“役” |
| 议七 | **将作只问行在**：将作每秒问一次的“余”，答复里带上任务表快照（籍号、父籍号、役、已给、限、峰给）；将作按役号对上在跑的任务，运行中每行末尾印“N 槽 · 已给 X/限 Y 兆”，原生生成连同它起的分片进程（按父籍号）合计。监工照将作的况显示。将作与代役里量内核的代码删去 |
| 议八 | **与裸机同一套 ABI**：籍号、父籍号、领役与毕役、已给与限，在裸机内核与行在上同义；裸机内核把领役与毕役记进任务表 |
| 议九 | **损耗要量**：同一构建、同一测试在行在里与独行（`豫言行在=关`）各跑三遍，墙钟差不超过百分之一；另记一组同一测试在 QEMU（KVM 与纯模拟）、VMware 里的耗时作对照 |

## 二、动机

### 零损耗是行在的立身之本

在豫言操作系统里测程序，现在要造盘、上 QEMU 或 VMware：KVM 下也要整机起、整盘写，纯模拟慢几十倍。00039 让行在在宿主上做内核的共享部分，任务表、桌面、壳请求与资源管理以本机速度跑，裸机上的毛病在宿主上就能复现。要行在真正顶替虚拟机，有两条缺一不可：程序在行在里和在裸机上表现一样，跑起来又和独行一样快。

### 现在行在还离不开宿主操作系统

行号按 yybs c629e9ef0f。

- **任务号就是宿主进程号**：00039 §4.2；`应用/豫构/行在。豫:31`「行在役录」的「号」是宿主进程号。
- **行在自己问内核**：父子关系由 `应用/豫构/行在。豫:527`「行在取父」问原语 292「问号父」；处理器时间由 `:568`「行在取时」问 293。
- **将作量内核**：`应用/豫构/将作。豫:2318`「将作代存」用 264「问使众」量代役进程树的实占，连不上行在时按它折算占槽（`:2335`「将作已占」）；`:1568`「将作量实占」用 291「问号实占」记日志。
- **代役量内核**：`应用/豫构/代役。豫:126`「代役问峰」用 145「问使」每秒量每件任务的常驻，只在林檎上有，林纳上答五十八。
- **常驻工作者藏在执行器里**：`豫言操作系统/裸机/客体二号/原生子进程。底层。豫:751`「常驻槽址」的常驻池，哪件任务在哪个工作进程只有执行器知道；「遣信」对常驻句柄答“句柄无效”（`:1865`）。
- **00056 议十**写的“系统按进程号量实占”，用户 2026-10-26 已改为“行在不问内核，用量就是已给合计”（`应用/豫构/行在。豫:30`）。

### 后果

- 监工看不到每件任务占多少内存：要么问内核（违背“内存归行在”，林纳上还取不到），要么拿宿主进程号去对（又把行在绑在宿主上）。
- 同一个工具在行在与裸机上走两条路：裸机上任务号、父子、内存都是内核的账，宿主上一半问行在、一半问内核，“各宿主行为一致”靠不住。
- 每加一种量法，林檎（proc_pid_rusage）、林纳（/proc）各写一遍，轩窗、裸机还得另补。

## 三、设计

### 3.1 界线

| 事 | 在哪里办 | 与行在来往 |
| --- | --- | --- |
| 计算与内存访问 | 本进程，本机机器码 | 无 |
| 文件、网络、终端、声音 | 本进程经执行器的宿主后端，路径按附庸表改写 | 无 |
| 起子进程 | 本进程直接起，执行器给子进程补 `豫言行在父籍` | 子进程登记一次 |
| 准入与内存 | 行在（00056 司阍与仓） | 每个进程一次许行；每块一次领存或还存 |
| 处理器 | 将作向行在按件租（00056 议九） | 每件一次 |
| 任务归属 | 行在（领役、毕役） | 每件两个问帧，当场答 |
| 任务之间的消息、共享块、显示与键鼠 | 行在（00039 §4.3） | 按需 |

热路径上没有一处经行在，每件任务多出的来往是固定的几帧。

### 3.2 籍号与进程树

- **放行答帧带籍号**：“许行”的答帧数据由零字节改为四字节籍号。执行器记下本进程的籍号，在起子进程处统一给子进程环境补 `豫言行在父籍=<籍号>`，豫言代码不用管。
- **登记帧 YXZ3**：在 YXZ2 之后加四字节父籍号（取 `豫言行在父籍`）与四字节役号（取 `豫言将作役号`），没有的为零。行在照收 YXZ2，父籍与役都记零。
- **行在任务表**：「行在役录」加「籍」「父籍」两栏，籍号从一起（零号是行在自己，同裸机的初始任务）；拍表、`豫构 行在 状态`、`列出役` 一律用籍号与父籍号。宿主进程号只在行在内部用于结束进程、发信号。
- **删去问内核的两处**：「行在取父」（292）由父籍号代替；处理器时间改由执行器自报——随 300 问额与每次还存，把本进程的累计处理器毫秒带上，删去「行在取时」（293）。

### 3.3 领役与毕役

- **代役**：给每件任务的环境块补 `豫言将作役号=<役号>`，与补 `豫言内存上限`、`豫言内存软额` 在同一处（`应用/豫构/代役。豫`「代役加限」）。
- **执行器**：常驻工作者换上任务的环境块时，读到 `豫言将作役号` 就发“领役”问帧（新服务号，甲为役号），结果帧写完发“毕役”；普通子进程把役号带进登记帧（YXZ3），退出即毕。两帧都是问帧，行在当场答。
- **行在**：「行在役录」加「役」与「峰给」（已给的最大值）；领役写入、毕役清零。

### 3.4 将作取快照、监工显示

- **快照随“余”来**：「余」答复加「籍们」，每个已登记进程一条：籍、父籍、役、已给千字节、限千字节、峰给千字节。将作本来每秒问一次「余」，顺带拿到，不新开连接。
- **对上任务**：将作按役号找进程，连同父籍链上的子孙合计已给与限；运行中每行末尾写“N 槽 · 已给 X/限 Y 兆”（N 照「将作占槽数」，原生生成按分册数）；`--数据` 的运行中各项加槽、已给、限三栏。监工照将作的况显示，同僚段由各机的将作各自给出。
- **删去量内核的代码**：将作的「将作代存」「将作量实占」，以及「将作已占」里按实占折槽的分支（连不上行在时只数槽）；代役的「代役问峰」，役毕日志里的峰值改取行在记的峰给。

### 3.5 裸机

裸机内核的任务号就是籍号，父任务号本来就有；领役、毕役两个服务号在内核里记进任务表，不影响调度。将作在裸机上跑起来以后（#545）走同一条路。

### 3.6 东道里的内核量法

实施完以后查调用处：「问使」（145）、「问使众」（264）、「问号实占」（291）、「问号父」（292）、「问号时」（293）在豫言程序里没有人用的，从东道接口删去；执行器内部只留行在门与仓用得着的。

## 四、兼容与迁移

- **新执行器配旧行在**：许行答帧不带籍号，执行器不补父籍，领役帧旧行在答负三十八（不支持），执行器此后不再发；监工照旧只显示槽数。
- **旧执行器配新行在**：登记帧是 YXZ2，行在照收，父籍记零（这个进程挂在根下），役记空。
- **工具链用新原语**：将作、代役只读行在的答复、补环境变量，不调执行器新加的东道原语，所以不用分两段等连续版本；执行器的新帧只在行在门内部。换链照旧先编执行器再编豫构，先换行在再换将作。

## 六、备选方案

- **执行器给“按句柄取宿主进程号”的原语，将作拿宿主进程号去对行在任务表**（2026-10-27 讨论过）：任务表仍绑在宿主进程号上，常驻工作者还要另开口子，不取。
- **代役问内核量每件任务的常驻**（同日前一版）：违背内存归行在，林纳上取不到，不取。
- **进程一律经行在起**（行在代父进程起子进程）：每起一个进程多一个来回，行在还要替子进程接管标准流；父籍号随登记带来已足够建树，不取。

## 七、未决问题

- 行在重启后籍号从头编还是续编：建议从头编（同裸机重启），在跑的进程重新登记时换新籍号；监工按役号对任务，不受影响。
- 处理器时间自报的频度：随问额与还存够不够，长时间不领不还的进程要不要每十秒补一帧。
