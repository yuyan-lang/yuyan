# 提案 00010：文本子语言

| 项 | 内容 |
| --- | --- |
| 编号 | 00010 |
| 状态 | 草案 |
| 提出 | 2026-10-09 |
| 范围 | 新增字面形式「文块」`｛…｝`（词法、表达式解析）；新库「文本」（文档结构与标准组件）。渲染器、论文网站、投稿系统不在本提案内 |

本提案给豫言加一个描述结构化文档（尤其是中文学术论文）的子语言，下称文本子语言（`text`）。它是豫言自身的一种字面写法，展开成普通豫言表达式，类型、模块、导入全部沿用现有机制。

本文只写现代汉语（AGENTS.md）。

## 一、拟定事项

- **议一：文块。** 新增字面形式 `｛…｝`（全角花括号），括号里是文本模式。文块的值是 `「列」于「文节点」`。
- **议二：文本模式只有四条规则。** 见第三节。
- **议三：按名展开。** 文块在语法分析时展开成普通豫言：文字段落调用「文字」，空行调用「分段」，组件就是普通函数调用。这些名字按当前作用域查找，由库「文本」提供。
- **议四：库「文本」。** 定义文档结构「文节点」与标准组件（论文、节、定理、证明、公式、引用等）。组件都是普通豫言函数，用户自己写函数即可新增组件。
- **议五：结构与渲染分离。** 文块只产生「文节点」树；网页、LaTeX、PDF 等渲染器各自遍历这棵树，另行实现。

## 二、动机

论文需要两样东西：正文像普通中文一样直接书写；结构（章节、定理、公式、引用）能被程序检查、生成和变换。豫言已有类型、模块和函数，缺的只是“直接写中文正文”的写法：现在正文只能写成 `『…』` 字符串。文块补上这一点，其余全部复用。

## 三、文本模式

文块 `｛…｝` 里：

1. **文字照写。** 中文、标点、西文、`（）`、`。`、`，` 都是文字，不用引号，不用转义。
2. **空行分段。** 空一行（或多行）是段落分界；单个换行把前后两行接起来，两侧都是西文字母或数字时补一个空格；行首缩进忽略。
3. **`「名」` 调用组件。** 紧跟其后的 `｛…｝` 是文字参数，`〔…〕` 是豫言表达式参数，可以连写多个；不带参数时取它的值。
4. **`「：…：」` 是注释。**

`「」` 在豫言里本来就表示名字，简体中文正文里又很少用，所以拿它作文本里唯一的“进入代码”记号。`〔〕` 只在组件名之后才算参数，所以“国发〔2020〕1号”这类正文照样是文字。

## 四、展开

| 文块里 | 展开成 |
| --- | --- |
| 一段文字 | `「文字」于『…』` |
| 空行 | `「分段」` |
| `「节」｛引言｝｛…｝` | `「节」于（文块）于（文块）` |
| `「文字」〔「版本号」〕` | `「文字」于（「版本号」）` |
| 整个文块 | `「列」【…】` |

代码里名字紧跟文块时就是调用：`「论文」｛…｝` 等于 `「论文」于｛…｝`。展开之后照常做名称解析与类型检查，报错指向展开后的调用。

## 五、库「文本」

```yuyan
「属性」即「字符串」合「字符串」也。

「文节点」立「元类型」也。
  「文字」立化「字符串」而「文节点」也。
  「分段」立「文节点」也。
  「块」立化「字符串」而化（「列」于「属性」）而化（「列」于「文节点」）而「文节点」也。
  「行内」立化「字符串」而化（「列」于「属性」）而化（「列」于「文节点」）而「文节点」也。
```

「块」「行内」的第一个参数是种类名（如 `『定理』`），第二个是属性，第三个是子节点。标准组件都是构造这两种节点的小函数：

| 种类 | 组件 |
| --- | --- |
| 文档 | 论文（全文）、标题、作者、模型（版式模板名）、摘要、关键词 |
| 章节 | 节（题目、正文；节套节即小节）、段 |
| 数学 | 公式（独立公式）、行内公式、定理、引理、定义、证明 |
| 引用 | 引用〔键〕、参考文献、文献〔键〕｛条目｝、标签〔名〕、参见〔名〕 |
| 行内 | 强调、代码 |

另有「规整」：把内容里的「分段」与块级节点整理成「段落」块，渲染器先调用它。组件只构造节点、不做计算，所以文档可以直接写成顶层定义（提案 00006 的可定值）。

新增组件就是写一个函数，例如：

```yuyan
「猜想」乃化（「列」于「文节点」）而「文节点」也。
「猜想」者会「正文」而「块」于『猜想』于「罄」于「正文」也。
```

## 六、示例

```yuyan
寻观「文本」之书。

「本文」乃「文节点」也。
「本文」者「论文」｛
  「标题」｛豫言的文本子语言｝
  「作者」｛张三｝
  「作者」｛李四｝
  「模型」｛期刊论文｝

  「摘要」｛
    本文给出豫言的文本子语言：正文直接书写，结构由组件给出。
  ｝

  「节」｛引言｝｛
    学术论文既要便于书写，又要便于程序处理。

    本文所用编译器版本为「文字」〔「版本号」〕。
  ｝

  「节」｛方法｝｛
    「定理」｛「标签」〔『求和』〕对任意正整数 n，前 n 个正整数之和为 n(n+1)/2。｝
    「证明」｛对 n 归纳即得。｝
    「公式」｛\sum_{k=1}^{n} k = \frac{n(n+1)}{2}｝
    由「参见」〔『求和』〕及「引用」〔『王二〇二五』〕可知……
  ｝

  「参考文献」｛
    「文献」〔『王二〇二五』〕｛王五：《豫言程序设计》，二〇二五。｝
  ｝
｝也。
```

程序生成内容用普通豫言函数，结果嵌回文块：

```yuyan
「运行记录」乃化「整数」而「文节点」也。
「运行记录」者会「次数」而「段」｛共运行「文字」〔「整数表示」于「次数」〕次。｝也。
```

## 七、备选方案

- 只写库、正文用 `『…』` 字符串：中文正文要处处包引号，不合要求。
- 另起 Markdown 或 LaTeX 式的独立语言：类型、模块、函数都要另做一套。
- 整篇文本模式的文件（如 `名。文。豫`）：可以在文块之上后加，先做文块就够用。

## 八、未决问题

- 正文里要写字面的 `｛`、`｝`、`「` 时，暂用 `「文字」〔『｛』〕`；是否另加转义，用起来再定。
- 章节、定理的编号与交叉引用的解析由渲染器做。
- 编辑器高亮：先把整个文块按字符串着色，组件名单独着色留待后续版本。

## 九、实施步骤

1. 编译器：词法器把 `｛…｝` 读成一个文块词元；表达式解析把它当原子，解析后按第四节展开（`〔…〕` 里的代码用同一个解析器递归解析）；名字后紧跟文块时合成调用。
2. 排版器、语义标记、源码文档：文块按原文保留，不改其中文字。
3. 库「文本」：「文节点」、标准组件、「规整」，以及展开与组件的测试。
4. 文档：语言技术规范加《文本子语言》一篇（汉语、文言两稿）。
