# 提案 00002：广义代数类型与简单依值类型

| 项 | 内容 |
| --- | --- |
| 编号 | 00002 |
| 状态 | 讨论中 |
| 提出 | 2026-10-04 |
| 范围 | 编译器前端的类型检查（模式匹配、类型形成、类型相等、隐式参数推定）；标准库「列」改为内建类型及其运行时表示；相关的语言技术规范 |

这是给豫言加入广义代数类型（GADT）与简单依值类型的提案：模式匹配在分支里细化类型，构造器可以带存在类型；类型可以依赖内建类型的值（整数、爻、字符串、列表），类型里只做内建运算，不运行用户函数；「列」改为内建类型，之后把它的表示从链表改为数组段。类型检查仍然是一阶的、局部的、必停的。

本文与[文言稿](00002-广义代数类型与简单依值类型.文言.md)同步。

## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | 模式匹配做类型细化：构造器的结果类型与被匹配式的类型做双向一阶合一，外层的刚性类型变量在该分支内可解；得到的代换作用于该分支的期望类型、环境和分支里写出的类型 |
| 议二 | 支持存在类型：构造器的隐式参数若不能由结果类型定出，匹配时取作新的刚性变量；合成模式下检查它不逃出分支 |
| 议三 | 合一冲突的分支判为不可达，给警告并跳过分支体的检查 |
| 议四 | 某支细化了外层变量时，`鉴` 必须有期望类型（检查模式），否则报“需类型标注” |
| 议五 | 类型可以依赖内建类型的值：「整数」「爻」「字符串」「列」；「小数」不收；其他自定义类型的值不可依赖 |
| 议六 | 类型里只许出现索引式：字面量、内建类型的变量、内建运算；不许调用用户函数。其余实参先用 `虑` 绑成变量，在类型里当作不透明的名字 |
| 议七 | 索引式化成规范形后比较：整数按多项式，列表按“附加”的结合律与空列，字符串按拼接与字面合并；不判定不等式；整数按数学整数计算，运行时溢出暂不处理 |
| 议八 | 不做终止检查：类型层只运行内建运算，必定停止；仍设规约步数上限作保险。证据参数显式传递、严格求值、不擦除 |
| 议九 | 写法沿用语法里已有的 `化 A 者「x」而 B`（显式依值函数）与 `承 A 者「x」而 B`（隐式值参数，编译后擦除），把定义域从元类型放开到内建值类型；带标签时写 `化（「签」为 A）者「x」而 B`（`为` 的右边放松后括号可省）；类型构造器可以收内建类型的参数 |
| 议十 | 隐式参数推定仍是有序匹配：索引变量只在单独出现时求解，复合式代入后再核对 |
| 议十一 | 依值模式匹配：被匹配的是变量时，在分支里把它代换成模式，与议一用同一套代换 |
| 议十二 | 「列」「罄」「缀」、列表字面量与列表模式改为编译器内建；先改身份，不改运行时表示 |
| 议十三 | 「列」的运行时表示改为数组段（VList 一类），对尾递归的遍历改写成下标循环；先做原型实测，达标后切换 |
| 议十四 | 不做：一般依值类型、终止检查、SMT 求解、单构造器单字段类型的自动拆包 |
| 议十五 | `为` 的右边比所有二元操作符都松：规约关系表加十一行左为 `〇为〇` 的关系；带标签的实参照旧自带括号，缺括号时给出专门的报错 |

## 二、动机

### 现状

豫言的类型系统（见《类型与模块》）：

- 双向检查：合成与检查两种模式。
- 显式多态：隐式参数 `承「甲」` 只绑定元类型；`元类型` 本身也是类型，不分宇宙层级。
- 名义代数数据类型：构造器用 `立` 单独声明完整类型，写法与 GADT 相同，例如 `「缀」立（承「甲」而化「甲」而化（「列」于「甲」）而「列」于「甲」）也。`
- 类型相等：结构比较加局部 η，不做 β 规约，不展开普通值函数的函数体。
- 隐式参数：有序匹配，只解签名一侧的待求变量，不做全局搜索。
- 模式：构造器的结果类型须与被匹配式的类型“匹配”，刚性变量只等于自身。
- 没有穷尽检查：缺的分支生成运行时报错路径。
- 类型构造器的显式参数只能是元类型。

### 实测

2026-10-03 在本机用 `yy豫构.wasm 文件` 构建六个样例（编译器为当时 yybs 的 `yy4_bs.wasm`）：

| 样例 | 结果 |
| --- | --- |
| 误造 `若式 于（整字 于 一）…` | 被拒（“整数 != 爻”）：构造端今天就是安全的 |
| 索引已知的消费 `求整：式 于 整数 → 整数` | 通过，运行输出 7 |
| 多态求值 `求值：承甲. 式 于 甲 → 甲` | 被拒：在 `整字` 模式处报“整数 != 甲” |
| 拆存在类型 `包可示：承甲. 甲 →（甲 → 字符串）→ 可示` | 被拒：“函数应用的隐式参数无法完全确定：未能确定 甲” |
| 不可能的分支（对 `式 于 整数` 写 `爻字` 支） | 报类型错误“爻 != 整数” |
| 相等见证加 `不安全转换` 的老式编码 | 通过，运行输出 7；类型安全全靠“「相等」只能由「同」构造”的约定 |

带索引的类型因此只能在索引已知时使用，对索引泛型的遍历写不出来。据盘点，全仓非测试代码里，结果类型特化的构造器只见于着色库的几个字面量构造器（如「新浮三二」）。

### 历史

- 2022 年的 SML 版有依值 Π 与依值模式匹配（91499e69b、b8600fb42）；同年 12 月，自举编译器加了依值函数写法 `化 A 者 x 而 B`（a0647e60d）。
- 2026 年 6 至 7 月，为求“局部、可预测”，拆掉了依值 Π（f3a53b0a9）、顶部归一化（fa6d7daf3）和大部分模式合一（8430c0e07）。计划 0004 写的理由是：元变量“过早创建，并且存活太久”，“整个系统会变得难以推理”。
- 本提案沿着这个方向走：新增的推理都在单个分支或单次调用之内完成，类型里不运行用户代码。

### 代码里的缺口

以下数据于 2026-10-03 至 10-04 在 yybs 上统计。

1. **假三元组**。树码缓存（38355b656）只有一个结果类型 `表达式树组`。串列产物（文件依赖、代码生成形式）被包成 `名 与 阳 与 待定节点` 的假三元组存取，读出后再用 `三对子取零` 拆回（`编译文件缓存工具。豫` 的「读串列缓存」「写串列缓存」）。产物用什么格式、什么扩展名、要不要写依赖快照，分散在五六个函数里，靠比较 `信息名` 字符串判断。
2. **同类型的两张表**。裸机后端「局部寄配」返回入口活跃表（「局数＋1」格）与死写表（「指令数＋2」格），类型都是 `数组引用类 于 整数`。先后出过“只开一格”（e8a09b4e7）与“两表次序颠倒”（b20fe3f12）两次越界，都只在生成 x86-64 时暴露。
3. **名义长度**。着色库用 17 个名义类型（「定长一」到「定长八千一百九十二」）表示长度，翻译器按名字识别；`点积：承甲. 甲 → 甲 → 浮三二` 什么类型都收；`读共享数组` 的下标是任意 `无三二`，GPU 上共享内存越界只给错值。据盘点，着色内建的 119 个签名里有 85 个是无约束的 `承`。
4. **帧槽**。b2f7d1771：数值内在码里的帧槽号与栈深按所在函数编号，内联后没有平移，在苹果 ARM64 上陷阱退出。当时的修法是含数值内在码的函数不内联，并留了待办事项。
5. **张量形状**。形状与元素类型都在运行时（`后端张量` 用整数列表与类型号表示）；「拆成多头」靠运行时改形；千问三的头维缺省按「嵌入维 ÷ 问头数」推算，而千问三有些尺寸里「问头数 × 头维」不等于嵌入维。
6. **列表开销**。全仓有 12308 处列表字面量，每处造 n 个缀格；`长度` 约 1228 处、`第N个` 880 处，都是 O(n)。生成代码性能记录里，原生最热的函数 m923 做的就是“链表上走 n 步”。

## 四、目标与范围

目标：

1. 第二节六个样例里被拒的三个（多态求值、存在类型、不可能的分支）按 GADT 的语义通过或给出警告。
2. 第八节的五个例子都能写出来，并在编译期挡住对应的错误。
3. 类型检查不运行用户代码，不需要终止检查；新增的推理局限在单个分支或单次调用之内。
4. 运行时零代价：索引随类型擦除；显式的依值参数本来就是运行时参数。
5. 「列」内建并换成数组段后，第七节的基准不变慢。

范围：编译器前端的类型检查；「列」的内建化与运行时表示；《类型与模块》《词法与语法》《规约关系表》《标签函数类型》《网页汇编接口》《底层模式》中相关的规范。

暂不涉及：一般依值类型；终止检查与宇宙层级；SMT 与不等式判定；穷尽检查（列为可选的最后一步）；单构造器类型的自动拆包。

## 五、设计：广义代数类型

改动集中在 `库/编译器核心/编译步骤/类型检查/模式匹配类型检查。豫` 的「检查模式函数应用」。现在的做法是先单向求出构造器的隐式参数，再断言构造器的结果类型等于被匹配式的类型。改为：

1. **双向一阶合一**。可解的变量有两类：构造器自己的隐式参数，以及外层 `受`／`承` 引入的刚性类型变量（环境里类型为元类型的自由变量）。类型只有名义头、箭头、元组几种形状，一阶合一加出现检查即可。合一得到代换 σ。
2. **分支内套用 σ**。σ 作用于期望返回类型、环境中局部绑定的类型（环境是条目列表，`式替换` 现成），以及分支里写出的类型（如 `授以「甲」`、`（「甲」也 …）`）。
3. **不可达分支**。合一冲突（例如“零”对“后继”）时，该分支不可达：给警告，跳过分支体的检查。
4. **存在类型**。结果类型定不出的构造器隐式参数，取作新的刚性变量；合成模式下检查它不出现在分支的结果类型里。
5. **合成规则**。`鉴` 现在是“首支合成、余支检查”；某支细化了外层变量时，改为要求有期望类型。OCaml 与 GHC 也这样处理。

不受影响的部分：

- 隐式参数推定仍是有序匹配。多态递归靠显式签名即可：递归引用拿到的本来就是完整的 `承` 类型。
- 擦除与代码生成：索引都是类型，擦除阶段已经去掉，运行时表示不变。去装箱的类别取自顶层声明的签名（工名类别表），不受分支细化影响。
- 宿主边界：先拒绝结果类型特化的构造器，留待办事项。

估计这一部分约 400 至 700 行豫言（含新的合一器），另加正反测试与规范。

## 六、设计：依内建值的类型

### 可依赖的值

类型可以依赖「整数」「爻」「字符串」「列」的值。「小数」不收：现在的结构比较按字面文字比较小数（整数部分与小数部分两个串），`0.5` 与 `0.50` 会成为两个类型；NaN 与正负零也让“相等”难以规定。Rust 的常量泛型同样不收浮点。

### 索引式

类型里只许出现索引式：

- 字面量：整数、爻、字符串、列表字面量（元素也是索引式）；
- 变量：类型为上述内建类型的变量；
- 内建运算：整数的加、减、乘；爻的与、或、非；字符串的拼接；列表的罄、缀、附加、长度、第N个、乘积。

类型里不调用用户函数，所以不必展开函数体，也不必检查纯性。其余实参先用 `虑` 绑成变量，这个变量在类型里是不透明的名字。

### 写法

```yuyan
「定长表」立化「整数」而化「元类型」而「元类型」也。
「新定长表」乃承「甲」而化「甲」而化「整数」者「长」而（「定长表」于「长」于「甲」）也。
「点积」乃承「整数」者「维」而承「甲」而
  化（「向量」于「维」于「甲」）而化（「向量」于「维」于「甲」）而「甲」
也。
```

- `化 A 者「x」而 B`：显式依值函数，结果类型 B 里可以出现 x。
- `承 A 者「x」而 B`：类型为 A 的隐式值参数，编译后擦除。
- 类型构造器可以收内建类型的参数。

这两种写法语法里本来就有（规约关系表的 `化〇者□而〇`、`承〇者□而〇`，源自 2022 年的 a0647e60d），现在只作旧式兼容：定义域只许元类型，并转成隐式全称类型；全仓没有一处在用。2026-10-04 实测：解析器已能读 `化（「长」为「整数」）者「n」而「整数」` 与 `承「整数」者「n」而 …`，两者都在「旧类型参数定义域检查」（`库/编译器核心/编译数据/操作符/内建操作符/内建操作符类型定义。豫`）处被拒，报“已不再支持非元类型的依赖函数类型参数”。语法上只需放开这一处检查，改为构造依值箭头。

### 与标签参数的配合

标签函数类型（2026-10-02 起，见《标签函数类型》）用 `「签」为 式` 写标签项：按位核对，标签不绑定名字，可以重复，检查后擦除；首版不支持乱序调用、默认值、部分应用与标签简写，类型构造器参数与着色语言里的标签报错。依值写法与它这样配合：

| 位置 | 不带标签 | 带标签 |
| --- | --- | --- |
| 依值函数类型 | `化 A 者「x」而 B` | `化（「签」为 A）者「x」而 B` |
| 带类型的匿名函数 | `遇 A 者「x」而 e` | `遇（「签」为 A）者「x」而 e` |
| 不带类型的匿名函数 | `会「x」而 e` | `会（「签」为「x」）而 e` |
| 调用 | `f 于 v` | `f 于（「签」为 v）` |
| 隐式值参数 | `承 A 者「x」而 B` | 首版不许带标签 |

类型写法与已有的 `遇（「签」为 A）者「x」而 e` 同形：`遇` 的绑定名对应依值箭头的绑定名。

1. **标签与绑定名各管一事**。标签是对外的名字，按位核对，参与类型相等；绑定名是 B 里用的内部名字，相等时按换名比较。`化（「长」为「整数」）者「n」而（「定长表」于「n」于「甲」）` 与把 n 换成 m 的写法相同，与把标签换成「宽」的写法不同。改内部名不改接口，改标签才改接口，与现行规则一致。
2. **按位应用让依值检查简单**。检查顺序就是声明顺序，也就是源码顺序：检查完一位，把它的值代入后面各位的类型。日后若加乱序调用，须先按源码顺序求值并绑成临时名，再按声明顺序检查；或者不许跨过依值参数乱序。
3. **依值位的实参须是索引式**。剥去标签后的实参须是索引式，否则报错，提示先用 `虑` 绑定。
4. **箭头组照旧**。`化 A 者「x」而化 B 而 C` 仍并成一组，多参数饱和规则不变；组内每一位可以带标签、可以带绑定名。内部表示从“域的列表”改为“带绑定名的域的列表”，标签仍按位包在各个域上。
5. **匿名函数**。`会（「签」为「n」）而 e` 按依值箭头检查时，n 就是该位依值变量的实例。`遇` 合成类型时，体的类型若提到绑定名，就合成依值箭头，否则合成普通的（带标签的）箭头。
6. **隐式值参数首版不带标签**。沿用《标签函数类型》“隐式参数不收标签项”的规定，`授以` 仍按位给出。按名给隐式参数（类似 Agda 的 `{n = 3}`）等于允许跳位，与“按位、不乱序”相冲，列入未决问题。
7. **构造器的依值字段**。构造器可以有依值字段，相当于依值对；标签让模式好读。下面的「带长表」用 `有（「带长表」于（「长」为「m」）于（「元素」为「表」））则 …` 匹配时，m 的类型是「整数」，「表」的类型是 `定长表 于 m 于 甲`。
8. **类型构造器参数与着色语言**：维持《标签函数类型》首版的诊断；索引参数按位写，例二的着色写法不带标签。
9. **旧式兼容的去留**：`化「元类型」者「甲」而 B` 现在表示隐式全称，全仓零处使用；改为报错，提示改写成 `承「甲」而 B`。这样 `化` 一律显式，`承` 一律隐式。
10. **`为` 的右边放松**。标签项 `「签」为 式` 的左边总是一个名字，右边是被标注的整个东西，所以 `为` 的右边应比所有二元操作符都松，一直延伸到外层的括号或混合操作符的关键字（`而`、`者`、`则`、`或`）为止。规约关系表加这几行（左为 `〇为〇`）：

| 右操作符 | 决定 |
| --- | --- |
| `〇于〇`、`〇授以〇`、`〇之〇`、`〇中〇`、`〇附〇`、`〇与〇`、`〇合〇`、`〇也〇`、`〇；〇` | 右规约 |
| `〇者〇也`、`〇或〇` | 左规约 |

右为 `〇为〇` 的关系仍不定义：带标签的实参照旧自带括号，写 `f 于（「签」为 …）`；否则松的右边会吞掉后面的实参，`f 于「甲」为 a 于「乙」为 b` 会读成 `f 于（「甲」为（a 于「乙」为 b））`。这时的报错改为“带标签的实参须加括号”。

2026-10-04 实测现状：`化「长」为「整数」者「n」而「整数」` 报“未定义优先级关系：〇为〇 与 〇者〇也”；`（「被减数」为「加」于「一」于「二」）` 与 `化「表」为「列」于「整数」而「整数」` 报“〇为〇 与 〇于〇”；`「差」于「被减数」为「一零」于 …` 报“〇于〇 与 〇为〇”。改后前三种写法都能通过，第四种照旧报错并提示加括号：

```yuyan
「新定长表」乃承「甲」而化「初值」为「甲」而化「长」为「整数」者「n」而（「定长表」于「n」于「甲」）也。
「新定长表」于（「初值」为「零」）于（「长」为「加」于「局数」于「一」）
```

这一条只改规约关系表（实现在 `库/编译器核心/编译数据/操作符/内建操作符/文言符集。豫`），原有程序的含义不变，可以先于本提案的其余部分单独做；编译器源码要等稳定工具链更新后才能用省括号的写法。

```yuyan
「某表」立化「元类型」而「元类型」也。
  「带长表」立（承「甲」而化（「长」为「整数」）者「n」而化（「元素」为（「定长表」于「n」于「甲」））而「某表」于「甲」）也。

「新定长表」乃承「甲」而化（「初值」为「甲」）而化（「长」为「整数」）者「n」而（「定长表」于「n」于「甲」）也。
「新定长表」于（「初值」为「零」）于（「长」为（「加」于「局数」于「一」））
```

在这个调用里，两位对调会使标签不符，长度写错会使结果类型 `定长表 于 …` 不符：前者是标签已有的保护，后者由依值类型提供。

### 相等

索引式先化成规范形再比较：

- 整数：多项式规范形（交换律、结合律、合并常数）；
- 列表：按“附加”的结合律与空列化简；`长度 罄 = 〇`，`长度（缀 头 尾）= 加 一（长度 尾）`，`长度（附加 甲 乙）= 加（长度 甲）（长度 乙）`；`乘积` 同理；
- 字符串：按拼接的结合律合并相邻的字面量；
- 爻：只合并字面量。

不判定不等式：“小于”这类事实由运行时检查经可信函数产出，例如 `下标 于 n`。整数按数学整数规范化，运行时溢出暂不处理（待办事项）。

### 推定与细化

- 隐式参数推定沿用有序匹配：索引变量只在单独出现时求解（`向量 于 维` 对 `向量 于 三` 得 维＝三）；复合式（如 `加 左 右`）在代入之后核对。
- 模式细化同时作用于类型与索引：用 `空：定长列 于「〇」` 匹配 `定长列 于 n` 时，该分支里 n＝0。规范化之后，一侧是单独的变量就绑定它；两侧是不同的常量就判为不可达；其余情形报“无法细化”。
- 依值模式匹配：被匹配的是变量 xs 时，在 `有（缀 头 尾）` 分支里把 xs 代换成 `缀 头 尾`，`长度 于 xs` 就能规约成 `加 一（长度 尾）`。这与第五节的 σ 是同一套代换；2022 年的 SML 版做过同样的事（b8600fb42）。

### 不做终止检查的规矩

1. 类型层只运行内建运算，对有限的项必定停止。仍设规约步数上限（取大值）作保险，超出时报“类型规约超出步数”。
2. 证据参数（如 `相等 于 a 于 b`、`下标 于 n`）显式传递、严格求值、不擦除。用死循环或 `发生事故` 伪造的证据，只会让程序在用到之前卡住或抛错，不会带着错误的前提往下跑。代价基本为零：`下标` 就是那个整数，`同` 是构造常量。
3. `不安全转换` 仍是唯一的显式逃生口。

### 对编译器其余部分的影响

- 擦除：隐式值参数随类型擦除；显式依值参数照常传递。
- 去装箱：`定长表 于 n 于 甲` 的类别是“通”；整数参数仍是“整”。
- 接口与缓存：接口里的类型多了索引式（「表达式」本来就能表示）；类型里不展开用户函数，接口不必附带函数体。
- 底层模式：整数索引同样可用，类型在擦除时去掉。
- 宿主边界：带索引的类型按去掉索引之后的形处理。

## 七、设计：内建列表

### 第一步：认身份，不改表示

「列」「罄」「缀」、列表字面量与列表模式，改由编译器直接认得；标准库「多态列」里的定义改为内建的别名，源码不用改。宿主边界检查现在按路径识别「多态列」（留着“改按包身份识别”的待办），这一步一并解决。第六节的列表规则也要靠这一步。

### 第二步：数组段

收益（2026-10-04 于 yybs 统计）：12308 处列表字面量每处只需一次分配；`长度`（约 1228 处）与 `第N个`（880 处）变成 O(1)；遍历的缓存局部性更好。

风险：现有写法依赖 O(1) 的接头与共享尾巴。全仓有 3834 处用 `缀` 在表头接一项，3356 处匹配 `罄`、`缀`，412 处“逆着积累再反转”。编译器的命名环境就是条目列表，「添加声明」用 `缀` 接在表头，同一个父环境被各个分支共享。换成朴素数组后，每次接头都要整份复制，这些地方会退化成 O(n²)。

设计要点：

1. **数组段**。采用 Bagwell 的 VList（2002）一类结构，把几何增长的数组段链起来。接头时，段前的空位若无人占就直接写入（O(1)）；已被占（说明尾巴是共享的）就新开一段。取尾、接头都是 O(1)，长度在段里记着也是 O(1)，按下标平均 O(1)，字面量一次成段。
2. **取尾**。WasmGC 没有内部指针，数组里的“尾”只能另分配一个（段，偏移）视图。今天匹配 `缀 头 尾` 不分配；改了之后每取一次尾就要分配一次，遍历反而可能变慢。解法是由编译器把“对尾递归”的遍历改写成下标循环，（段，偏移）留在两个局部变量里，只有尾巴逃出去时才造视图。这一步决定成败，要先做原型。

验收基准：E1a（163118d41）记录的 pit-mac、Node、三轮中位数：列表造遍每次 34.4 纳秒、态射 10.0 纳秒、从左折叠 3.71 纳秒；另看自举耗时与 WP8 的原生指令数。

另外两点：

- 「串典」建在列表上（包着键值对列表的单构造器类型），会随列表一起变成数组段。它的查找仍是从头扫的线性查找，要提速得换成散列或树，与本提案无关。
- 「字符串」本来就是内建的字节数组，作为索引只比较相等，主要当名字或标签用。

## 九、覆盖不了的

- **依赖自定义类型的值**：例如用 `列 于 值型` 的字面量描述 Wasm 的操作数栈（值型是自定义类型），要放开到“任何构造器项都可作索引”才行，见第十二节。
- **高阶运算**：`态射` 要运行用户函数，类型里算不了。`长度（态射 f xs）= 长度 xs` 这类不必运行 f 的规则，可以另加为内建规则。
- **需要归纳证明的性质**：例如 `长度（反转 xs）= 长度 xs`。要么加成内建规则，要么在运行时检查。
- **不等式**：只能靠运行时检查产出证据。
- **手算偏移与同类返回值错位**：5c3c85dfd（捕获记录偏移算错）需要由编译器计算偏移的结构体；135afbbed（同长同类的四路返回次序错位）需要具名字段。两者都在本提案之外。

## 十、兼容与迁移

- 现有程序：细化与存在类型只让原先被拒的程序通过。唯一的行为变化是不可能的分支由类型错误改为警告；非测试代码里没有这样的构造器，实际影响为零。
- 新写法是放开已有写法的定义域，旧写法不变；唯一的例外是旧式兼容的 `化「元类型」者「甲」而 B`（全仓零处），改为报错并提示改用 `承「甲」而 B`。
- 「列」内建：「多态列」里的定义改为内建的别名，源码不变。若「列」的类型身份随之改变，接口清单里涉及「列」的签名表示也会变，需按接口清单的规则重新生成各适配的 `宿主提供.json` 与 `启动接口.json`。
- 列的数组段表示：运行时的内部表示变化，宿主边界的出入转换函数跟着改，边界格式不变。
- 工具链：编译器源码要用新特性，须先由 CI 把支持它的工具链发布到 historical-binaries，再改 `.github/workflows/main.yml` 的 `YY_WASM_TOOLCHAIN_URL` 与 `YY_WASM_TOOLCHAIN_SHA256`，并更新本机的稳定工具。
- 每一步都改变编译器语义：须完整自举（yy3 与 yy4 逐字节相同），跑相关前缀的全树测试，交 WP8 做原生全验。

## 十一、备选方案

| 方案 | 结论与理由 |
| --- | --- |
| 一般依值类型，带终止检查 | 否。要在类型里规约用户函数（加回顶部归一化并做成按值求范式），要纯性与终止检查、宇宙层级（`元类型:元类型` 不一致）、高阶模式合一、擦除标注，接口还得附带函数体，等于推翻 7 月的简化。它能挡的约 14% 多数还需要算术推理 |
| 一般依值类型，不查终止 | 收窄为本提案：类型里一旦运行用户函数，纯性、接口附带函数体、值层隐式参数的推定这些问题都会回来 |
| 只用 GADT 加类型层副本（单例、皮亚诺数或字面量类型、关系见证） | 能覆盖第八节的例子，但数据要写两遍，算术要靠见证，存在类型的打包拆包随处可见；本提案让整数直接作为参数传递 |
| 精化类型加 SMT（Liquid Haskell、F*、Dafny 一类） | 否。本仓只写豫言，求解器的规模与维护负担都过大 |
| 单构造器单字段类型的自动拆包（擦除式 newtype） | 否。要改构造器的运行时表示，规模与 E1a 相当（E1a 改了八个分析与四个测试）；零开销的名义类型今天已能写：声明一个没有构造器的类型，在一个模块里用 `不安全转换` 进出，常量内联会去掉这层转换（字节串就是这样做的） |
| 幻影类型加构造器里存函数 | 今天可行，许多场合够用（例四也能这样做），保留为现行写法；GADT 让种类保持为可匹配、可穷举的普通值 |
| 只做穷尽检查 | 抽样里只挡住 1 例；约 6950 个 `鉴` 中约 2743 个带「其他／忽略」兜底支，收益有限；列为可选的最后一步 |

2. 「串典」是否一并内建。
3. 是否放开到“任何构造器项都可作索引”：构造器项是死数据，比较的代价与字面量相同。
4. 字符串作索引是否值得。
5. 不可达分支给警告还是报错。
6. 内建索引运算的清单：是否收除法、取余与比较。
7. 整数溢出的语义。
8. 列表的数组段：用 VList 还是别的结构；改写成下标循环的适用范围；整数列表是否特化为 i64 数组。
9. 带索引的类型、结果类型特化的构造器如何过宿主边界。
10. 穷尽检查做不做、何时做。
11. 标签简写（标签兼作绑定名，省写 `者「x」`）做不做。
12. 日后若加乱序调用，依值参数按哪种方式检查（见第六节“与标签参数的配合”第 2 条）。
