## 一、缘起

问簿（SQL，翻译列表的译名）现在是写在 `.豫` 里的字符串。云仓有 39 个源文件写着约 350 条 SQL，表结构是 29 个 `.sql` 迁移文件。例如账户服务里的一句：

```
『SELECT "用户编号" AS id FROM "邮箱账户" WHERE "邮箱"=?』
```

表名、列名拼错，参数个数不对，结果列的类型对不上，都要到运行时才报错；每次执行还要重新做词法分析与解析，再由芥子的执行模块逐句解释。自建动态站（C00005）要把这些数据从 D1 搬进芥子，正好一并改写。

第二稿（用户 2026-10-24 定）：全走编译。初稿的第一版把查询编成芥子的语法树，仍交执行模块解释；第二稿里查询本身就是豫言代码，与别的代码一样编成机器码，SQL 文字也先译成豫言再编译。这样就用不着单独的文件种类、生成模块与问簿内建声明：表和查询照常写在 `。豫` 文件里，编译器只多两条按类型补值的规则（第六节）。本提案不新增语法。

## 二、目标

1. **表结构写成豫言**：一张表是一个行类型（命名元组）加一条表声明（名、主键、唯一、索引、外系）。
2. **查询写成豫言**：条件、投影、排序、分组、连接都是以行为参数的匿名函数，编成机器码逐行执行；查询参数就是函数参数，带标签。
3. **编译期检查**：栏名、栏的类型、参数个数与类型、结果的类型都由类型检查核对，与普通豫言代码相同。
4. **全走编译**：运行时不解析 SQL，也不解释执行。
5. **SQL 文字先译成豫言再执行**：导入 D1 转储、运维时的临时查询、迁移期间的旧代码都走这一路（第七节）。

## 三、做法总览

- 「册府」是芥子里新加的模块（`库/群书/藏时部/芥子/册府。豫`，内部辅助放 `册府/` 下），给表、查询、写入与事务的类型和函数（第五节）。「检」「登」「改」「删」等都是有函数体的普通函数：先按取径拿候选行，解成命名元组，再用调用方给的匿名函数筛、排、截、投，全部是编好的机器码。
- 编译器补两样东西，都在共用前端里按类型做，任何高级文件都适用（第六节）：
  1. **行谱**：构造写法里没写的、类型为 `「行谱」于 甲` 的项，编译器按甲（命名元组）合成栏目表与编码、解码函数。
  2. **取径**：调用里没写的、类型为「取径」或 `化 甲 为「取径」` 的可省参数，编译器从同一调用的「择」里找能按键取行的等值条件补上；找不到就照常取默认值「全扫」。
- 表与查询写在普通 `。豫` 文件里，习惯上一个应用一个 `名册。豫`；高级代码照常导入，直接调用查询函数。
- 芥子能跑的地方册府都能跑：原生、裸机、诺驿（Node.js 后端）、浏览器、云工（Cloudflare Workers 后端）。
- 第一版的存储沿用芥子现有的库态：库状态在内存里，经「关系问」的藏库写进芥子文件库落盘。册府建的表照现有建表的路子登进库态，过渡期里 SQL 文字入口看得见同一批表。库比内存大与页式存储上的取径放第二期。

- 「库」写在查询函数的签名里，类型是芥子的库句柄「问库」。
- `「行」中「邮箱」` 是命名元组的按名投影：栏名写错，类型检查就报“没有这一项”。条件、投影里能写任意豫言式子，照常编译。
- 「置册」是「册」的值构造器，表声明是数据，可以写在顶层（《执行与编译》行一）。表声明要写签名 `「名」乃（「册」于 行类型）者也`，编译器从这里得知行类型。唯一、索引、外系写成构造写法的子项，没有就不写；行谱一项由编译器补（第六节第一条）。

- 「次」是比较函数的列：先按第一个比，分不出先后再按下一个，排序稳定。比较函数照豫章（标准库）「排次」的约定，甲应排在乙前面时返回阳；「升数」「降数」「升文」「降文」由取键函数造比较函数。
- 可空栏的类型是 `「或可有」于 甲`，条件里照豫言的写法判断（鉴、豫章的可选值函数），不另设三值逻辑。
- 实参按签名次序写（签六第三条）。

### 语义

- 「辟问库」：打开路径上的芥子文件库，没有就新建；「新问库」：内存里的空库。
- 「建册」：照第八节核对并建表；一张表调一次，程序启动时逐表调。
- 「检」：按「径」取候选行（「全扫」取全表；「键等」在该栏有主键、唯一或索引时按键取，否则全表）→ 用表的行谱解成甲 → 经「择」筛 → 按「次」排 → 去掉前「跳」行 → 取前「限」行 → 经「遍」投影。
- 「检二」：左表按「径」取候选；每个左行，右表按「右径」于左行取候选；成对经「择」筛，经「遍」投影，再按「次」排结果、跳、限。只做内连接。
- 「聚」：候选行经「择」筛后，按「分」得的键文字分组（组的先后照组里第一行出现的先后，组内行照原先后）；每组交「合」得一个结果，经「留」筛（相当于 HAVING），再按「次」排、跳、限。计数、求和、最大、最小、平均在「合」里用豫章的列函数算。
- 「登」：用行谱编码，核主键、唯一、非空与外系，写入并维护索引，返回新行的行号。
- 「改」：候选行经「择」筛，每行算「成」，核约束后写回，返回改了几行。
- 「删」：候选行经「择」筛后删去，返回删了几行；被外系引用的行第一版报错。
- 「同办」：开一个写事务，把「办」于同一个库执行；成则提交并落盘，出祸则整体回滚，再把祸照原样抛出。不在「同办」里的「登」「改」「删」各自一个事务。
- 违反约束、表不存在、结构不合，都以写明表名、栏名与原因的祸抛出。

## 六、编译器补的两样

两样都按类型头名认（与签七第七条表达式码同法），不看类型所在的模块；测试可以用同名的替身类型。

### 1. 行谱

- 时机：构造写法（签七）降成带标签调用时，签名里类型为 `「行谱」于 甲` 的参数没写，编译器补上合成的行谱；写了就用写的。造值用这个类型唯一的构造器（「造行谱」）。
- 甲取自期望类型：表声明 `「名」乃（「册」于 行类型）者也` 给出行类型。推不出甲时报“合成行谱要知道行类型：给表声明写上签名”。
- 甲须是命名元组，各项的类型限于「数」「小数」「文」「帛」「爻」与这五种的 `「或可有」于 …`；别的类型报“表的行类型「甲」里「名」一项的类型「…」存不进表：只收数、小数、文、帛、爻与它们的或可有”。
- 合成的值：
  - 「栏们」：按命名元组项的次序一项一栏；名取项名；型照项的类型取「整栏」「实栏」「文栏」「块栏」「爻栏」（或可有取里面的类型）；可空在或可有时为阳，否则为阴。
  - 「编」：`（得「行」而「列」【编一，编二，…】）`。数作值整，小数作值实，文作值文，帛作值块，爻作值整（阳为一，阴为零）；或可有：可无作值空，可有照里面的类型编。
  - 「解」：按次序把问值解回各项（值整到爻按非零为阳）；栏数不对、值的种类对不上时，以“行与表结构不合：第几栏应为……，实得……”抛祸。
- 合成的值只含匿名函数、列与构造器，是数据，表声明照样能放顶层。

### 2. 取径

- 时机：签六第三条补齐可省参数之后，凡是取了默认值、而类型头名为『取径』（或类型为 `化 甲 为「取径」`）的参数，编译器改从同一调用里标签为「择」的实参推：「择」是字面的匿名函数时照下面的规则补，补不出就留着默认值。造值用构造器「键等」。
- 单表（「检」「聚」「改」「删」）：「择」是 `得「行」而 体`。沿体最外层的短路且（`（甲）且（乙）`，可以嵌套）逐项看，取第一个合下列之一的项，其中 X 里不出现「行」（「行」指匿名函数的参数，名字照用户写的）：
  - `（「行」中「名」）等于 X` 或 `X 等于（「行」中「名」）`：补 `「键等」于「栏名」曰『名』于「值」曰（「值整」于 X）`；
  - `「文同」于（「行」中「名」）于 X` 或 `「文同」于 X 于（「行」中「名」）`（「文同」指豫章的那一个）：补 `「键等」于「栏名」曰『名』于「值」曰（「值文」于 X）`。
- 连接（「检二」）：「择」是 `得「左行」又得「右行」而 体`。「右径」取第一个“右行的栏与 X 相等”的项，X 里不出现「右行」，可以有「左行」，补 `（得「左行」而「键等」于…）`；「径」照单表的规则找左行的栏，X 里「左行」「右行」都不出现。
- 补的只是候选行从哪里来，条件本身不变：候选行照样经「择」筛一遍，结果与全扫相同。范围条件、或、排序走索引放第二期。

## 七、SQL 文字一路

- 「重译」是芥子新加的模块（`库/群书/藏时部/芥子/重译。豫`，内部辅助放 `重译/` 下）。它把一条 SQL 文字连同所涉各表的建表语句译成豫言源文字：查询与写入译成一个函数（参数「库」，再加每个 `?` 一个带标签参数，标签依次为「参一」「参二」……，类型照它所比的栏推定），函数体调册府；建表语句译成行类型与表声明，导入 D1 的表结构就用它。
- 支持：SELECT（单表；两表内连接；WHERE 里的比较、AND、OR、NOT、IS NULL、IS NOT NULL、IN 列表、LIKE 前缀；ORDER BY；LIMIT 与 OFFSET；COUNT、SUM、MIN、MAX、AVG，带或不带 GROUP BY 与 HAVING）、INSERT（VALUES）、UPDATE、DELETE、CREATE TABLE、CREATE INDEX。别的写法报错，写明哪一处、为什么。
- 空值：SQL 的三值逻辑由重译写成显式判断，可空栏参与比较时遇可无为假，外面再套 NOT 也照 SQL 的结果写（仍为假）。
- 执行：译出的源编成单元，经豫构交互的单元编译与动态装载执行，与壳每句同一条路。第一版先接豫构交互（壳里的临时查询、D1 转储导入）；服务程序里的动态 SQL 等单元装载接口就绪后再接。
- 接上以后删去芥子 `问簿/` 下的执行模块与只供它用的部分；词法、解析、语法树留给重译用。

## 八、表结构与库的核对

- 「建册」按表核对：库的目录里一表一条，记着这张表的结构摘要（栏们、主键、册约的规范文字）。
- 库里没有这张表：建表、建索引，记下摘要。
- 摘要相同：直接过。
- 只在末尾加了可空栏、只加了索引：自动补上（旧行的新栏为空），更新摘要。
- 其余变化（删栏、改名、改类型、改次序、改主键、改唯一或外系）：以“表「名」的结构与库里的不同：……；第一版只自动补加末尾的可空栏与索引，别的改动要写迁移（第二期）”抛祸。

## 九、步骤

第一批，四路并行（互不依赖，各改各的文件）：

1. 可省参数的类型可以引用类型参数（议题 #510）：隐藏的默认值定义带上同样的类型参数，调用处照常推定；《标签函数类型》签六同步。
2. 编译器的行谱合成与取径补值（第六节），新写语言技术规范《问簿》篇；测试用替身类型，不依赖芥子。
3. 芥子「册府」（第五节、第八节）及其测试；测试里的行谱先手写，第 2 步合入后改用编译器合成。
4. 芥子「重译」（第七节第一至三条）及其测试：SQL 文字与建表语句译成豫言源文字。

第二批（第一批合入后）：

5. 册府的择、次、右径、留改回可省（等第 1 步）；用编译器合成的行谱与取径重跑册府的测试（等第 2、3 步）；重译的产物交编译器类型检查一遍（等第 3、4 步）。
6. SQL 文字一路接上豫构交互的单元编译与动态装载；D1 转储导入；删去执行模块。
7. 云仓改写：先账户服务（表少、语句多），再包管理服务、云工作台、项目管理；全部改完删去 SQL 字符串与 `.sql` 迁移文件。

第二期：页式存储上的取径与库比内存大、范围与排序走索引、外连接、UPSERT、显式迁移步骤、服务程序里的动态 SQL。
