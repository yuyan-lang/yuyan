# 行在门籍号实施记录

改动仅位于本工作树的 `豫言操作系统/裸机/客体二号/`，遵照任务书目录的《协议约定》，保留未提交状态。

## 各项实施

| 项 | 结果 |
| --- | --- |
| 一、认籍号 | 门文件按现有“司阍”字样匹配方式识别“籍号”，据此选择新登记。 |
| 二、YXZ3 | 魔数、父籍、役号、路径长度与路径按约定编码；父籍取启动环境，常驻任务役号取本件环境。非法与溢出十进制数归零。 |
| 三、收籍号 | 新版许行要求四字节，旧版要求零字节；初入、等待许行时重连、断仓重连均更新籍号。 |
| 四、传父籍 | 传籍（父籍环境项）集中编码；林檎、林纳在统一环境指针表处加入或替换，轩窗在统一环境转宽处替换。同步、异步、带境与常驻工作者启动均走这些入口。 |
| 五、领役毕役 | 登记后、任务开跑前发 320；所有常驻结果帧写完后发 321，包含主动退出。负三十八禁发后续通知，传输失败交入口断仓处理。裸机通知留待后续任务。 |
| 六、辍籍 | 持籍的新版登记进程把原语 265 参数按籍号交 322，乙零；新版负答保持籍号域，旧版及独行沿宿主进程号办理。 |
| 七、处理器时间 | 300、301、303、304 的丙填本进程累计处理器毫秒；林檎取进程时钟十二，林纳取进程时钟二；查询失败填零。 |
| 八、文档 | 平台接口规范与客体说明的汉语、文言稿同步。 |

状态格 2688、2692、2696、2700 分别记协议版、本进程籍号、役通知状态、当前役号，位于原有七个中转槽之后的空区，跨常驻清场保留。门帧（行在协议传输）抽出已有读写满、限时等待与共用问帧编码，使常驻结果发送能够直接报毕役，并保持平台层下方的依赖方向。

## 验证范围与防错

本机为旧行在，真实运行覆盖旧协议与独行。新登记的字段、父籍与数值边界另由合成帧测试核对；新版行在联调、林纳和轩窗的运行验证留给主线合验。

[1101：YXZ3 的 64／65 返回籍号后，执行器仍按宿主进程号发信号](https://github.com/yuyan-lang/yuyan/issues/1101)：用户统一修订协议第五、七节后，本路已将新版打断、打断子孙、打断单个与原语二百六十五统一接到三百二十二。打断乙二，三百毫秒未注销补九；结束乙零。新版负三十八与断连均返回原答并保持编号域；这遵照用户最新“一律经行在、不得把籍号交进杀”的要求。旧版路径保留。逐个打断之前先复制子孙名单，避免三百二十二及六十四的回答覆盖剩余名单。未对真实目标发送信号。

另提防错议题：[1094：由同一协议声明生成初次登记与重登记](https://github.com/yuyan-lang/yuyan/issues/1094)、[1096：用时间单位类型核对换算](https://github.com/yuyan-lang/yuyan/issues/1096)。任务限定只改客体二号目录，因此建议表待主线整合时登记：1094 加入已有“进程间消息由声明生成”，1096 加入已有“量的语义与单位分型”，1101 加入已有“名义类型（新型）”及“进程间消息由声明生成”。议题保留开启。

本轮另发现 [1104：底层函数值调用类型检查通过，最终链接才报不支持间接调用](https://github.com/yuyan-lang/yuyan/issues/1104)。回调桩第一次因输出助手名字写错而类型检查失败，改用已有打印零串；随后回调调用通过类型检查、最终链接失败，报“〈籍发〉不是已知函数，不支持间接调用”。最终采用显式发送帧，把生产发送与测试记录置于共用帧生成之后，保持底层仅直接调用的设计。编译器缺口在本路范围外，已提议题；建议以调用能力类型在类型检查阶段核对后端能力。用户明确建议表由主线合入时代登记。

测试程序均前台运行。进程清单检查被沙箱以 `operation not permitted: ps` 拒绝；未人工启动后台测试循环。

本路交付未提交的源文件、执行器与测试产物，交主线审查；新版行在合验及建议表登记由主线办理。
