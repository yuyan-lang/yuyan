# 几席匣点审改表（1-10 第五批，24 处，2026-11-08 复核）

几席是壳的命令层。`壳令实现格` 在壳启动时登记命令，之后只读；命令处理在一次壳行里由同一个任务跑；后台任务是另起的差遣，但它们不写这些命令表/行状态，只经壳的命令接口。

**合计**：派生前写定 0 处，单任务独用 24 处，加锁 0 处，原子匣 0 处，每实例一份 0 处。代码 0 处改动。

**2026-11-10 复判（1-10 余项第一批，均输一十）**：上文“同一条任务”的判断成立，依据补实如下。全仓在进程里派生差遣任务（「遣」「遣可待」「题遣」诸名）的只有二十三篇：豫章的差遣、使者、将使、将宾主，营造的交役，豫构的入口、将作、行在、代役，群书的模府两篇、静态载、尺素五篇、津梁两篇，网页服务原生的来网页，浏览器的异步载入，百工坊的济津与浸泡（`git grep -l -E '「(题遣|遣|遣可待…)」(于|以)' -- '*。豫'`，测试除外）。几席、中书、诏令、九宫、开机壳与交互入口一处也不派生。壳这一族所在的实例（豫构交互、开机壳与桌面所在的初始任务、远程登录与桌面终端起的会话）里，派生出来的只有豫章的帮手任务（「候使步」等子进程等待、「将宾主」各步网络收发）、营造的交役步与写步（壳里跑构建时）与入口的多程序链接；这些任务只调豫章、营造、驿、籍册这些更底层的包，营造与豫章不依赖几席、中书、诏令（见各包「依赖」），既不收这三包的函数作回调、也不读它们的钩。所以这些格在任何实例里都只由该实例的主任务读写；多核下主任务换核续跑仍是同一任务的先后，不并发。表外格（壬路清点以后新加的，或当时判甲乙的）同此。本包顶层可变格共 45 格，表内 24 格，表外 21 格。另：使者务的「壳会话闩」（2026-11-03 加，注释说“桌面的终端起壳会话与轮询会从不同的任务改这张表”）护的其实是同一任务里的先后，留着不碍事，不改。

## 附：边界
