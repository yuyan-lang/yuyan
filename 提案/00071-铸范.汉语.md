## 一、拟定事项

- 议一：执行边界由豫汇（与网页汇编 WasmGC 一一对应）改为「铸范」：编译器自己的、有类型的中间表示。WasmGC 降为网页后端的一种输出。
- 议二：铸范有类型。类型一直保留到选定表示之后才擦，所有优化都在有类型的铸范上做。
- 议三：铸范里的函数是多元的，柯里化只是表层写法。调用分三种：直接调用、已知闭包调用、未知闭包调用。
- 议四：控制流显式（A 正规式加汇合点）。递归保持为递归组，不提早转成可变单槽；闭包转换放到优化之后。
- 议五：每个值带表示：不装箱的整数、小数、爻，引用，值聚合。分配点显式；回收用的指针图由表示导出。
- 议六：每个函数带两类事实：副作用（纯、可抛、有副作用，由 #1458 定的推断给出）与可内联性（可内联体、不透明体；不透明体即编译后会被换掉的函数体，见 #1437）。
- 议七：模块接口带可内联体与特化要用的信息，跨模块照样内联、特化。
- 议八：动态边界（单元装载、壳里每句编成的单元、引用式清单）上用统一表示加包装函数；边界以内放开特化。
- 议九：铸范配带类型的校验器，每一步优化之后都过一遍。
- 议十：普通豫言与底层豫言共用铸范，以“有无回收”能力位区分；执行器、内核也吃同一套优化。
- 议十一：名字取「铸范」。范是铸器的模子，《荀子·强国》：“刑范正，金锡美，工冶巧，火齐得，剖刑而莫邪已。”先正其范，冶铸才能照范铸出好器；与原生后端「冶铸」同用一个比喻，范又有“法式”之义。
- 议十二：分六步实施（第八节），每步可单独合入，每步量一次基准（第九节）。

## 二、动机

### 现状

规范《执行与编译》列的阶段次序是：

| 阶段 | 做什么 |
| --- | --- |
| 检查 | 名称树 → 已检查类型与对象 |
| 模式展开 | 模式 → 单次分析、标签测试、字段投影 |
| **类型擦除** | 已检查对象 → 无类型对象 |
| 局部规范化 | 显式参数组 |
| **递归转换** | 递归 → 可变单槽单元 |
| **闭包转换** | 局部函数 → 代码与捕获元组；除明确直接函数外，调用都传闭包自身 |
| 全局存储、提升 | 定义 → 全局槽 |
| A 正规式 | 复杂表达式 → 命名中间值 |
| 代码生成 | → WasmGC |

闭包前优化、跨模块优化（常量内联）都排在类型擦除之后。原生这一路，执行器（客体二号）本身是底层豫言写的 WasmGC 虚机：解析模块、类型表、i31、`ref.cast`，回收堆在线性内存里，热函数由冶铸预编成机器码。

### 信息丢在哪

1. **类型擦得太早。** 优化器看不见类型，就没法单态化、去装箱、选表示；内联只能按“繁度小于六十四”加几种薄函数形状一刀切（`库/译场/分职/刊定/跨卷/常量内联。豫`「内联候选筛选」）。
2. **递归提早转成可变单槽。** 递归调用变成“读槽再间接调用”，挡住内联与已知调用。
3. **闭包转换早、调用约定统一，函数又是柯里化的。** 多元调用要靠去柯里化补救。
4. **表示到代码生成时才定，而且只有一种。** 值一律是 WasmGC 引用或八字节值槽，六十四位整数装箱，类型细化靠运行时转换（#1437 报的“类型转换失败”就在这一层）。去装箱只在最终链接按顶层签名补一点（`库/译场/分职/笔受/主程序生入口。豫`「去装箱签名表」）。
5. **看不见、不知道。** 跨单元看不见函数体（动态装载、引用式清单）；优化器不知道哪些调用有副作用（#1458），也不知道哪些函数体编译后会被换掉（#1437：#357 放宽内联候选后，导出占位函数被展开，执行器误编，自举崩了一天多）。
6. **后端简单。** 冶铸没有寄存器分配与循环优化，消除抽象的担子全压在前端的常量内联上。

### 代价（实测）

- #357：五百万次绝对值调用，不内联 16.85 毫秒，内联后 4.75 毫秒。函数本身只有一次比较加一次取负，开销几乎全在调用：经单元调度表间接跳转、参数放进统一值槽并装箱检查、进出的栈与回收检查。
- #345：按引用式清单编的远程登录 sftp，比静态链接慢 14–27 倍。
- #1431：密壳引用式清单版的加密热路径，仍比静态版慢两到五倍（本地闭包间接调用与新生代回收）。

### 为什么是现在

当初选 WasmGC 作边界，是为了网页、诺驿、云工用同一份产物，自举也从 `.wasm` 起步。诺驿、云工 10-29 起不再支持，wasm 只留给网页；工具链早已原生自举；网页行在复刻的是原生虚机的系统层。主战场是原生，原生却在为统一表示付全部代价。

### Rust 为什么能零成本

| 手段 | Rust | 豫言现在 |
| --- | --- | --- |
| 类型留到优化之后 | MIR 有类型 | 检查后不久即擦 |
| 特化 | 泛型单态化，每个闭包一个类型 | 擦除后一份代码通吃 |
| 值的位置 | 元组、结构体放栈上或寄存器里 | 多在堆上分配，事后回收 |
| 跨单元 | 泛型与 `#[inline]` 函数体随元数据带过 crate；链接期优化 | 引用式清单看不见对方函数体 |
| 后端 | LLVM | 冶铸（较简单） |

豫言有回收，不追求 Rust 的所有权；其余四项都能做。

## 三、目标与范围

做：

- 铸范的定义、树码种类与校验器；
- 新管线：检查之后精化成铸范，优化全在铸范上做，最后选表示、擦类型、降级；
- 原生出口：冶铸直接从铸范降级，执行器退成运行时（回收、调度、宿主原语、动态装载）；
- 网页出口：从铸范降成 WasmGC，浏览器照用自带回收；
- 基准与每步的量测。

不做：

- 改语法。第五节的语言层事项另行审定。
- 把执行器编成普通 Wasm 进浏览器、WasmGC 整个退出（第七节备选一）。
- 接 LLVM 等现成后端（只写豫言）。

## 四、设计

### 4.1 铸范的形状

- **定义**：顶层定义与局部定义都是“函数或值”；函数是多元的，形参各带类型与表示，返回带类型。递归函数成组（递归组）。
- **函数体**：A 正规式的语句序列加汇合点；分支（由模式展开来）、循环（由尾递归与汇合点得来）都显式。
- **调用**：直接调用（目标是已知函数，参数个数饱和）、已知闭包调用（闭包的代码已知）、未知闭包调用（统一约定）。部分应用显式造闭包。
- **分配与访问**：造对象、造闭包、取字段、写匣都是显式节点，带对象布局。
- **异常与续延**：告祸、捕获、以当前续延调用各有节点，标明会不会穿出本函数。
- **事实**：每个函数带副作用类别与可内联性；不透明体（编后换体）只有签名、没有可见的体。
- **安全点**：可能触发回收的点显式，选表示之后由表示导出指针图。

### 4.2 类型与表示

- 铸范保留普通豫言的类型（多态、代数数据、依值类型里已检查的部分）。依值类型的索引在检查后只留作事实，不参与表示。
- 特化之后，每个值有确定的表示：不装箱的整数、小数、爻，引用，值聚合（字段逐个放寄存器或栈上）。仍是多态的地方取统一表示，与现在相同。
- 选表示在特化与逃逸分析之后、降级之前一次做完；擦类型放在选表示之后。

### 4.3 新管线

检查 → 模式展开 → **精化成铸范** → **化简**（按代价模型内联、β 归约、分支化简、常量折叠、删死代码，借副作用信息）→ **特化**（单态化、按闭包特化、去柯里化）→ **工包分拆**（不装箱的工函数，加统一表示的包装函数）→ **逃逸分析**（标量替换、栈上分配）→ **闭包转换** → **选表示、导出指针图** → **擦类型** → **降到低层**（静态单赋值）→ **冶铸**（寄存器分配、循环优化）；网页则降成 WasmGC。

### 4.4 优化

- **内联**：代价模型取代“繁度小于六十四”：看调用处的已知信息（常量实参、已知闭包、分支能否化掉）估收益，按体积估代价。不透明体一律不内联；有副作用的调用不删、不并、不调序。
- **特化**：多态函数在已知类型处出专用副本，设代码体积上限；高阶函数（「遍」「折」「择」等）配字面闭包时出专用副本，相当于 Rust 对闭包类型单态化。
- **工包分拆**：函数拆成不装箱的工函数和统一表示的包装函数；包装函数供动态边界与未知闭包调用，已知调用直接调工函数。
- **逃逸分析**：不逃出本函数的元组、记录、闭包拆成标量或放栈上。
- **递归**：递归组保持为直接调用；只有作为值逃出去的递归函数，才在闭包转换时建环。

### 4.5 动态边界

- 单元装载、壳的每一句、引用式清单之间，调用一律走统一表示与包装函数，单元可以各自编、各自装。
- 边界以内（一次静态构建、一个包或一个单元之内）放开特化与内联；模块接口带可内联体，跨模块也能内联。
- 发行构建缺省走整程序静态链接；引用式清单留给壳与开发期。

### 4.6 两个出口

- **原生**：冶铸从铸范降级出机器码，按选定的表示安排寄存器、栈槽与对象布局，生成精确栈图。执行器不再解析、解释 WasmGC 模块，留下回收、调度、宿主原语、文件系统与动态装载。
- **网页**：从铸范降成 WasmGC，需要处装箱、转换，浏览器照用自带回收；让行检查点在这一降级里插。

### 4.7 校验器

- 每步优化之后核对：类型与表示相合、变量先定义后使用、汇合点的参数个数与类型、调用的元数与约定、不透明体没被展开、有副作用的调用没被删。
- 校验失败是编译器内部错误，报出是哪一步、哪个函数，不留到运行时。

### 4.8 与底层豫言、着色语言的关系

- 底层豫言（无回收）就是铸范去掉回收能力的子集：没有回收堆、没有安全点，其余同。执行器与内核用同一套化简与内联。
- 着色语言照旧走自己的后端；铸范的事实与表示以后可供它复用，本提案不改。

## 五、要用户另定的语言层事项

1. **值类型**：组类能否声明成“值”（没有身份，不可共享修改），好放进寄存器；可变的匣照旧是引用。不定也可以，先只靠逃逸分析。
2. **多元函数的语义保证**：饱和调用就是一次调用，部分应用才造闭包。
3. **编后换体的定义入型**（#1437，已登进建议表）：在语言里声明“函数体由链接步骤给出”。
4. **内联、特化提示**（如「宜内联」）：倾向不加，交给代价模型。

## 六、兼容与迁移

- **自举**：CI 第一级用连续版本的旧链编新源码。执行器、冶铸要用的新东西分两次合：先合支持，等连续版本换上新包，再在工具链代码里用。
- **缓存**：铸范进树码，加一个种类；各步换编译语义号。
- **豫汇与汇编树码**：降为网页后端的内部格式；读写它的工具与测试，按盘点（#1484）逐一改读铸范或保留在网页一侧。
- **文档**：AGENTS.md、《设计动机》、规范里“执行边界是豫汇，与 Wasm 一一对应”的说法，在第六步一并改写。

## 七、备选方案（否掉的）

1. **WasmGC 整个退出，执行器编成普通 Wasm 进浏览器**：提案 00043 第七节已否过——Wasm 里做不了精确栈图，回收要改影子栈，代码路径照样不同；Safari 与 iOS 至今不支持六十四位线性内存（memory64），执行器 10-13 起只剩六十四位构建。
2. **保留 WasmGC 作边界，只在上面加特化**：统一表示的根子不去，原生仍背装箱、i31、转换检查。
3. **只放宽内联阈值**：#1437 已经示险；没有类型、副作用与不透明体的信息，放宽一点就误编。
4. **接 LLVM 等现成后端**：违反只写豫言；也解决不了前端擦类型太早。

## 八、实施步骤

1. **立铸范与校验器**：检查、模式展开之后精化成铸范，再降回现在的流程，两条出口的产物逐字节不变。改动范围按 #1484 的盘点定。
2. **有类型的化简与内联**：代价模型、副作用、不透明体，替换现在的常量内联；量 #357。
3. **特化与工包分拆**：单态化、按闭包特化、去柯里化、去装箱；量 #345、#1431。
4. **原生直接吃铸范**：冶铸从铸范降级；执行器退成运行时（分两次合）。
5. **逃逸分析与栈上分配；冶铸补寄存器分配与循环优化。**
6. **网页从铸范降 WasmGC；改写 AGENTS.md、《设计动机》与规范。**

## 九、基准与验收

- 每一步：原生「全部」三级定点；旧链与新编译器各编一次执行器；全树测试相关分片。
- 基准，每步量一次并记进实施记录：
  - #357：五百万次小函数调用（现在不内联 16.85 毫秒、内联 4.75 毫秒）；
  - #345：sftp 引用式对静态（现在慢 14–27 倍）；
  - #1431：密壳热路径（现在慢两到五倍）；
  - 编译器自举耗时与产物体积（看特化的代价）。
- 目标：静态构建下，小函数调用接近手写；引用式与静态的差距在第三步后收窄。具体目标值在第一步量出起点后定。

## 十、未决问题

1. 壳里每句编成的单元要不要也特化：编译耗时与运行快慢的取舍。
2. 单态化的代码体积上限怎么定。
3. 以当前续延调用、异常与安全点在铸范里怎么配合。
4. 冶铸由铸范的表示生成精确栈图，与执行器现有回收器的接口怎么改。
5. 第一步“产物逐字节不变”是否做得到，取决于盘点；做不到时改为语义不变加定点一致。

## 十一、静态防错

- 校验器把“类型与表示不合”“不透明体被展开”“有副作用的调用被删”这类误编挡在编译器里，不再变成运行时陷阱（#1437 正是这样撞出来的）。
- 副作用与不透明体写进铸范，优化步骤从类型上就拿不到不透明函数体，也删不掉有副作用的调用；语言层还要的声明（编后换体）见第五节第三条。
