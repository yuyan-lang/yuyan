## 一、拟定事项

- **议一：全程序分析留在链接时。** 豫汇（GC 层中间表示）照旧由最终链接的整程序生成（「统一直生篇」）产出，各项全程序分析不动，生成的代码与现在相同。
- **议二：降级产物按函数跨程序、跨工作树共用。** 客体函数与执行器函数的机器片按内容键存进提案 00034 的共享缓存（`<语义号>/降级/…`），写后不改；同一架构、同一执行器的所有程序共用，取代现在按产物名分文件、每次重写的做法。
- **议三：键与机器码不含程序内编号。** 类型按名字、字面量全局与数据段按内容、函数按稳定身份进键；机器码里的类型号、对象头、函数引用、字面量全局偏移都写成符号常量，链接时按本程序的编号填。
- **议四：最终链接每个程序只做一次。** 两种架构的豫汇逐字节相同，造盘时父进程把各程序的最终链接（整程序豫汇）做一次，两个架构的子进程只做各自的原生生成。
- **议五：链接编排跟着改。** 先链函数最多的程序（开机程序）把共享缓存填满，其余程序随后几乎全命中；全命中的原生生成不起分片，几个程序同时链。

## 二、实测

2026-10-18 在 pit-pc-ubuntu-wired（28 核、123 GB）上测 yybs e627f6cb9，临时插桩（不入库）给最终链接、原生生成子进程与分片打时间戳，并记每个函数的身份与摘要。测时该机另有别的会话的造盘、QEMU 与训练，负载 20–60：绝对值比安静时大，各部分的比例可用。

### 2.1 冷造盘全程（两架构、空缓存）

| 段 | 用时 |
| --- | --- |
| 父进程：二十二个程序的前端（执行器、内核并行） | 9.5 分 |
| 子进程：每架构十一个链接，串行（每份一个链接） | 12.8 分 |
| 子进程：预编前导（与链接并行） | 8.0 / 8.5 分 |
| 写持久盘、内核镜像、ISO | 约 4 秒 |

### 2.2 一种架构的十一个链接（单独重放，冷降级缓存，无预编前导）

| 程序 | 最终链接（秒） | 原生生成（秒） |
| --- | --- | --- |
| 开机程序 | 26.6（整程序生成 18.6，其中常量初值 14） | 65.1 |
| 桌面程序 | 12.0 | 49.8 |
| 远程登录 | 10.4 | 44.1 |
| 豫构 | 9.7 | 35.5 |
| 编译器 | 10.3 | 33.5 |
| 捉刀、吉特（就地生成） | 约 3–4 | 32.9、31.9 |
| 豫言系统、开发 | 4.4、3.6 | 22.6、16.0 |
| 格式化、安装系统（就地生成） | 约 1 | 7.6、3.0 |
| 合计 | 约 86 | 约 342 |

串行合计约 428 秒，与造盘里每架构约 6.5–7 分钟的链接段相符；三个链接并行时 150 秒。原生生成的大头是降级循环：寄存器降级约 67%，转译与内联约 25%，原键约 5%，其余是读客体、执行器状态、登记、元数据编码、侧表、写缓存、连接与写出（每个程序合计约 6–14 秒，全命中时就剩这些）。

现在的降级缓存按产物名分文件，读入超过 96 MiB 就把余下的片当作空：开机程序、桌面程序不改代码重建时仍有近半函数重新降级。

### 2.3 跨程序、跨架构的重复

- 一种架构十一个程序共 280,533 个客体函数，按名去重后 77,553 个：**72% 的降级是重复的**。
- 按现行原键去重只少 22%：原键里的类型号、字面量全局名是程序内编号，同一个函数在不同程序里键不同。
- 同名而豫汇不同的函数抽样 200 个，差别全是编号：字面量全局 `$s号` 与数据段 `$d号`，以及闭包表下标常量（原生路径已改写为“表序:身份”）。同名类型在各程序里 521 个全部同体。**全程序分析没有让同一函数在不同程序里生成不同的豫汇。**
- 两种架构同一程序的客体（整程序豫汇的汇编树码）摘要相同，各函数的原键摘要逐个相同：最终链接的产物与架构无关，转译的输入也相同；机器码不同。

## 三、为什么不在模块编译完就降级

提案 00007 第 4 步原设计是模块编译完就把它的函数降级，链接时只填重定位。豫汇却是最终链接才由「统一直生篇」对整个程序生成的：私有签名、私有整组、整拼字节、双整组、私有构造、融合入口、私有数返回、栈后端、虚组入口、确知签、常量初值这些分析都要看整个程序。按模块生成豫汇的路现成有一条，就是装载单元（提案 00003 的「单元直生篇」），代价是：引用别的模块一律走导入，跨模块调用经单元调度表，私有签名只在模块内，顶层常量不写常量初值、改由启动时写全局。用它出静态链接的程序，工具链自身的代码会变慢，与提案 00007 的门槛“原生构建不慢于诺驿”相冲。

2.3 的实测说明：同一函数在不同程序里的豫汇只差编号。把编号挪进重定位，链接时按函数共用就拿到按模块降级的收益（每个函数每种架构只降级一次），代码一字不变。所以本提案把全程序分析留在链接时（议一），按模块降级以“按函数共用降级产物”实现。

## 四、设计

### 4.1 产物形式与存放

- 产物仍是每个函数的机器片列（「机器片储」现有编码：本函数标签记“@本”，指向客体函数的标签记“@身份”，符号常量记名字），取用时按本程序的编号换回。
- 存进共享缓存的降级层：`<语义号>/降级/客/<键前两位>/<键>`，一个函数一个文件，先写临时文件再改名，写后不改；两个程序同时写同一键，内容相同，谁先谁后都对。执行器函数同样存放（键里有执行器摘要）。
- 原来的 `产物名-系统-架构.机器片` 与 `.客.N` 六十四片文件不再用，96 MiB 读入上限随之没有；整产物缓存（`.产物N`）照旧。
- 分片工作者只读自己那份函数的条目。

### 4.2 键

- 降级上下文照旧：目标与布局各开关、执行器各函数的签名摘要、宽起、导入数、页容量等。
- 规整函数体：类型立即数换成类型名；全局按符号名（字面量全局与数据段按内容起名，见 4.3）；调用、尾调用、函数引用换成被调者的稳定身份与签名（签名里的引用类型也按类型名）；闭包表下标照旧换成“表序:身份”；导入按（模块名，字段名）。原长不超过内联界的被调者照旧递归四层计入。
- 模块上下文（现“原境”）去掉类型段与导入段的摘要，只留内存、标签、引用宽度与硬件浮点开关。
- 规整不了的立即数（如交给执行器解释处理的指令里含类型号）照原值进键：这类函数只在本程序内复用，不跨程序共用，不会错。

### 4.3 机器码里的编号改成重定位

单元模式（提案 00003）已经把这些量写成符号常量，由装载器按名字填；这里在静态链接里照做，名字改用与程序无关的：

| 量 | 现在（非单元模式） | 改为 |
| --- | --- | --- |
| 类型号（ref.test、ref.cast、call_indirect 等） | 常量 | 符号常量“型:类型名” |
| 对象头低字（类型号加种类） | 常量 | “型头:类型名:种类” |
| 函数引用（ref.func，号乘八加二） | 常量 | “函引:身份” |
| 全局偏移 | 符号常量“全局:名字” | 照旧；字面量全局 `$s号` 改按内容起名（`$s` 加内容摘要，同摘要不同内容时加序号） |
| 数据段（array.new_data 等用的段描述地址） | 常量 | 段按内容起名，地址写成符号常量 |
| 闭包表下标 | 符号常量“表序:身份” | 照旧 |

链接时由「机器数值码」按本程序的类型表、函数表、全局表、数据段表登记的值填写。符号常量是定长装数指令，比短立即数多一两条指令；提案 00007 对全局偏移量过同样的改法，冷编豫言系统用户时间 75.5 对 76.0 秒，看不出差别。

### 4.4 两种架构

- 最终链接的产物（客体汇编树码）两架构相同。造盘时父进程编完前端就把十一个程序的最终链接各做一次（可几个同时做，内存约 1–3 GB 一个），存下客体与原生生成参数；两个子进程只做原生生成。父进程现在的“链参存”改成“客体存”。
- 转译加内联后的中间表示（宽函数）两架构多半相同，可再共用，省第二种架构约 25% 的降级；要给宽函数定一种存放格式，留待后续。

### 4.5 链接编排与内存

- 子进程先链开机程序（函数最多，68k 个），共享缓存随之填满；其余十个程序的函数约九成命中。
- 原生生成先在主进程算出全部原键、查共享缓存，未中的函数超过一定数目（初定八千）才起分片，只把未中的函数分给分片；全命中的程序单进程完成，内存约 1–2 GB。
- 链接并行数照旧按物理内存定，但每个链接的内存随未中数变小，开机程序之后同时链两到三个。

### 4.6 对「全部」定点核对与内存的影响

- 「全部」的二级用共享缓存，三级以 `--do-not-load-cache` 冷编，三级同时不读降级共享缓存；键漏了某个随程序而变的量、或某个编号没改成重定位，二级会用上别的程序的机器片，与三级不同，定点核对报错。
- 另加核对开关（环境变量 `YY_降级核对`）：命中时照样降级一遍、与缓存逐字节比较，不同就报出函数身份；全树测试里挑几个程序打开。
- 编译器语义号要换（降级产物格式与键都变）。共享缓存的降级层随用随长，按提案 00034 不做回收。

### 4.7 预编前导（不属降级，但改完后它在关键路径上）

链接段缩短后，预编前导（安静时约 3.7 分钟：在虚根里重编八百一十一个模块的前端，再链十五个单元）成为两架构造盘的关键路径。可以：①在父进程一开始就起，与前端并行；②开跑前把父进程已编好的阶段缓存复制进虚根（虚根里的执行器只准写虚根，坑⑪），省掉它的前端。这两项单独定。

| 段 | 现在 | 改后（估算） |
| --- | --- | --- |
| 前端 | 约 2 分 | 约 2 分 |
| 最终链接（每程序一次，父进程） | 每架构各做一遍，约 1.5 分串行 | 约 0.5 分（同时做，开机程序最长） |

此外：不改代码再造盘、改一个文件后重建大程序，都不再因 96 MiB 上限重降近半函数；不同工作树、不同程序之间的降级全部共用。

## 六、实施步骤

1. 共享降级层：「机器片储」改按函数存取共享缓存，去掉按产物名的 `.机器片`、`.客.N` 与 96 MiB 上限；执行器函数一并迁过去。验收：同一程序冷、热两次产物逐字节相同。
2. 键与重定位：类型、对象头、函数引用改写符号常量（类型按名），字面量全局与数据段按内容起名，原键按 4.2 规整，模块上下文去掉类型段与导入段；链接时登记各符号的值。换语义号。验收：先链开机程序再链豫构，豫构的客体函数九成以上命中，产物与清缓存单独链接逐字节相同；「全部」二、三级逐字节相同；`--只验 普通-打印` 两架构通过。
3. 原生生成主进程先算原键、只把未中的函数分给分片（4.5）。
4. 造盘：父进程每程序做一次最终链接，子进程只做原生生成；先链开机程序，其后按内存同时链。验收：两张 ISO 造出、预编前导摘要核对通过；与改前在同一时段交替冷造，记录用时。
5. （若定）预编前导提前并复用阶段缓存（4.7）。

## 八、实施要点（2026-10-18）

- 共享库：「机器片储」按函数存取 `<语义号>/降级/片/<键首字节>/<其余字节>`（「降储取」「降储存」「降储有」），键前缀是生成器（做原生生成的程序文件的修改时间与路径）与执行器摘要；客体函数与执行器函数同存。`.机器片`、`.客.N` 与 96 MiB 上限去掉。核对开关 `YY_降级核对` 照 4.6。
- 稳定键与符号常量（4.2、4.3）：降级共享时，「预二豫汇」排原键令流把类型、异常标签、数据段、元素段、表的号换成稳号（稳名摘要的前六字节），原长里这些号按三字节定长计；字面量全局（$s、$n、$k 加数字）按初值内容起名；内容相同的字面量全局与数据段共用一个稳名（它们都不可变，可以互换。字符串字面量每个用处一个全局，同一字符串在不同模块各有一个，若第二个起补上程序内的号，名字就随程序变：实测远程登录与豫构共有的函数里约两成因此对不上）。「预编二译」把型号、型头、函号、函引、异常标签号与执行器处理函数的三个立即数字写成符号常量（“立”加各域稳名），链接时按本程序登记，库里取来的机器片由缺值钩（「机器数缺钩引」）按本程序现算。
- 全局值后置（实施时查出）：全局基址原是“页数描述符减去全局值与数据段的总长”，随程序的数据段大小而变；它进了降级上下文，相对址式（豫行、macOS）里每个函数的栈界检查、状态格访问也嵌着“固定地址减全局基址”，各程序的降级产物因此对不上。「藏镜像」改为数据段片按段号倒序在前（零号段紧挨全局值，执行器的段在各程序里地址相同）、全局值紧贴页数描述符，全局基址只随执行器的全局个数而变。macOS 与 Windows ARM64 的锚距按全局基址所在的十六千字页推数据段起址，这两个目标照旧全局值在前，降级产物在程序之间不共用（待办）。
- 开机程序与工具共用（实施时查出）：降级上下文原含栈顶与“兼映像栈”开关，豫行工具的 AMD64 栈放在映像里（栈顶不同），开机程序的十三万多条降级产物与工具一条也不共用，第一个链的工具几乎全未中。这两样只进入口与导入桩，不进共享库，从降级上下文里去掉；先链开机程序再链桌面程序（兼容六十四），桌面程序九万多条只多出 27 条，核对 0 处不同。
- 分片（4.5）：原生生成的主进程先算客体函数的原键，数共享库里没有的（只看条目文件在不在），不少于 `YY_降级分片界`（缺省四千）才起分片工作者；分片照旧按序号取余分工。
- 多程序链接（议四、议五）：豫构的「多程序链接」把同客体键（参数去掉 `-o`、`--降级缓存`、`--目标架构` 后相同）的几组只做一次最终链接，带编译器参数 `--原生全交`（客体总是交出、不查整产物缓存）；各组用同一个客体按自己的输出、降级缓存与架构起原生生成，原生生成子进程另写豫言操作系统产物的“。摘要”。原生生成先等同架构参数最多的那组（开机程序）。
- 造盘（议四、4.7）：父进程编完两种架构合编的前端，就用「豫构 链接」（不带 `--只链`）链好两种架构的全部程序，链接并行数取物理内存吉数除以三十二（一到四）。能并行预编时两种架构的预编前导也在父进程跑：前端编完就开始，与链接同时；开跑前把共享缓存的「键」「物」硬链接进虚根（Linux `cp -al`，macOS `cp -cR`）。虚根里的豫构不能写虚根以外的文件，指向共享缓存的符号链接写入时报“越出授权”，所以用硬链接。子进程只核对摘要、写盘、出镜像与光盘。
