| 日期 | 2026-10-25 |
| 范围 | 行在（宿主常驻系统实例，提案 00039）：本机全部豫言进程一律是行在的任务；行在按处理器与内存的余量放行（司阍）；全部任务共用一个有上限的内存池（仓），超出上限的冷页由行在换到自己的换页区（窖），程序无感 |

## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | **一律入行在**：本机起的每个豫言进程都是行在的任务，构建也不例外：豫构的构建类命令不再「辞行在」，只是不开附庸（照宿主路径），行在停止时也不杀它们。只有 CI、虚根与明设 `豫言行在=关`（同 `豫言将作=关`，须用户批准）独行 |
| 议二 | **司阍（准入）**：进程登记时等行在一声“许行”才往下跑；处理器与内存的余量不够就在门口排队，按优先（交互、前台、后台）先到先放。长命进程（代役、常驻工作者、编译驱动）每领一件活也先问行在一次 |
| 议三 | **仓（内存池）**：行在设内存上限 X，全部任务的实占合起来不超过 X；每个任务有额度，执行器的堆长过额度先向行在要，要不到就先回收、再等 |
| 议四 | **窖（换页区）**：仓满时，行在挑闲着的、优先级低的任务，让它把冷页写进行在的换页文件，再把那段地址换成这个文件的写时复制映射，物理页随之释放；再用到时由缺页从文件读回。宿主的压缩区与系统交换区就不再被豫言进程挤爆 |
| 议五 | **量实占**：行在按进程号量每个任务的实占（林檎 `ri_phys_footprint`，林纳 `VmRSS` 加 `VmSwap`），不量常驻（#653） |
| 议六 | **将作只管分发**：本机放不放行由行在定，将作的槽数退为它自己的上限；将作派役前先问行在 |
| 议七 | **各宿主一致**：林檎、林纳同一套做法，写在执行器与行在里；不用林纳的 cgroups（林檎没有，两边会不一样，见 AGENTS.md「各宿主行为一致」）。裸机内核以后照同一套接口 |

## 二、动机

2026-10-25 本机（四十八吉、十八核，将作设了八槽）当天又死机重启。死机前的快照（12:55）：

- 内存已用 47G，压缩区 24G，空闲 276M。豫构相关进程二十来个，各占二到四点四吉：将作八个槽里的代役进程树约 22 GB（`ps` 量到的常驻合计只有约 4 GB）；换链重起留下的孤儿五个约 18 GB（#654）；客自己起的最终链接三个约 13 GB（f64c769231 已改）；客的编译驱动十来个约 3.5 GB。
- 处理器满载（用户态 77%、内核态 23%），将作槽里的活只占约 2.3 核。其余是代理直接运行的测试与工具、每秒约 63 个短命进程、另一会话的盯梢脚本、压缩与换页的内核开销。

将作只管它派出去的那几件任务，量的又是不含压缩区的常驻（#653）。槽外的进程它看不见，也管不着。每次多补一处漏算，总还有下一处。要真正兜住，得有一个看得见本机全部豫言进程、手里握着放行与内存的地方。行在本来就有本机全部豫言程序的任务表（00039 第一步），由它来做最直接。

## 三、设计

### 3.1 一律入行在

- 执行器启动时照旧加入行在（`客体二号/行在门`，登记帧“YXZ1”）。
- 豫构的构建类命令（构建、类型检查、目标、全部、代役、将作）改为“登记不附庸”：进任务表、受司阍与仓管，命名空间照宿主路径，不开附庸。原先「辞行在」整个退出，是怕行在停止时 `kill -9` 杀掉构建（#503），也怕附庸改了路径。这两件分开处理：附庸不开，行在停止时对这类任务不发信号。
- 行在没起时，进程照将作的做法在后台起一个再登记；起不来就一直等，不独行（独行要明设开关）。

### 3.2 司阍（准入）

- 登记帧加一个应答：行在回“许行”，进程才往下跑；排队时每三十秒回一封“候行”（附排在第几、缺的是处理器还是内存），客端印一行提示。
- 放行条件：放行后预计实占不超过 X 减预留，且正在运行的任务数不超过核数。新进程的预计实占先取同一程序上次的峰值，没有就取一个缺省值。
- 优先：交互（壳、桌面、带 `豫言将作优先=交互` 的构建）不排在前台、后台的后面；同级先到先放。
- 长命进程：代役每把一件活交给常驻工作者之前、编译驱动每起一件本地活之前，先向行在“领资”，做完“还资”。将作的派役也算一次领资。

### 3.3 仓（内存池）

- 行在按任务记额度（初值同预计实占），全部额度之和不超过 X。
- 执行器的堆要长过额度时，先做一次回收、用「宿主交还」把空块还给宿主；仍不够就向行在要额度，要不到就等，期间不分配。
- 行在缺额度时，先请闲着的任务交还：闲着的常驻工作者回收后交还空块；代役闲满一分钟照旧退出。

### 3.4 窖（换页区）

- 窖是行在目录下的稀疏文件（缺省 `~/.豫言/行在/窖/`），按任务分段。
- 换出：行在挑中一个任务（闲着的先，优先级低的先，额度超得多的先），请它换出若干块。执行器把这些块写进窖里自己的那一段，再用「宿主映档」把这段线性地址换成窖文件的写时复制映射（MAP_PRIVATE），原来的物理页随之释放。映射是干净的文件页，宿主回收时不必写回。
- 换入：再读到时由宿主的缺页从窖文件读回；写的时候写时复制成匿名页，额度重新计入。程序看不出差别，只是慢一些。
- 挑哪些块：先挑回收器知道的老年代与大块只读数据，再按块的最近使用顺序（执行器在回收时记下）。
- 「宿主映档」现在只在林纳的常驻工作者用（把全局快照映回回收堆）；林檎也要能用，换页的块大小取两边页面的公倍数（16 KiB 的倍数）。

### 3.5 量实占

- 行在按进程号量各任务的实占，一秒一次：林檎 `proc_pid_rusage` 的 `ri_phys_footprint`（偏移 72），林纳 `/proc/<号>/status` 的 `VmRSS` 加 `VmSwap`；系统空闲内存照旧问「问寓概况」。
- 执行器原语「问使众」同时改量实占（#653）。

### 3.6 将作

- 将作派役前向本机行在领资；行在不许就排着，不另外按自己的槽数硬派。槽数保留，作为将作自己的上限。
- 托役、整客远行照旧：替别台干活的远行进程也是本机行在的任务，同样受司阍与仓管。

## 四、实施步骤

1. **司阍与量实占**：登记帧加“许行”与“候行”；行在按 X 与核数放行；按进程号量实占；构建类命令改登记不附庸；将作派役前领资。做完这一步，新起的进程就不会把机器压垮。
2. **仓**：任务额度、堆长过额度时向行在要、要不到先回收再等；行在请闲任务交还。
3. **窖**：换出与换入；林檎接通「宿主映档」；回收器记块的使用顺序。
4. **收尾**：监工与「行在态」显示仓与窖（各任务额度、实占、换出量、排队）；裸机内核照同一接口的事项另立。

## 五、缺省值与待定

- X 缺省取物理内存的七成，处理器上限取核数；设置文件与环境变量可改，单位兆。
- 窖的大小缺省同 X，满了就不再换出，只排队。
- 是否允许在内存告急（空闲低于物理内存一成）时先暂停（SIGSTOP）最后放行的后台任务、等内存回来再继续：暂停不释放内存，只是止住增长。缺省不开，待实测后定。
