## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | **分工**：系统（宿主上是行在，裸机上是内核）管一切与机器资源和进程生命周期有关的事；将作管一切与构建本身有关的事：跨构建的任务队列、工具链与代役池、缓存、分发（托役、整客远行、候簿）、令牌与结盟、监工；执行器是两层之间的桥；客（豫构的构建命令）照旧拿着依赖图、先探缓存，把就绪的任务交给将作 |
| 议二 | **一律入系统**：本机起的每个豫言进程都是系统的任务，构建也不例外。构建类命令只撤附庸（「辞附庸」，照宿主路径），不再辞出行在；系统停止时不杀它们。只有 CI、虚根与明设 `豫言行在=关`（须用户批准）独行。行在是必须一直在的基础设施：没起就自动起，断了任务自己重连 |
| 议三 | **上限与实给**：将作（或启动方）声明的槽数、每槽额只是上限。系统不预留上限，进程实际要多少给多少，按块给（块缺省每槽额的八分之一、至少六十四兆）；只有进程要的超过自己的上限时，上限才起作用。池的上限 X 缺省取物理内存的七成 |
| 议四 | **司阍（准入）**：进程登记时等系统一声“许行”才往下跑：按实际余量放行——池里实际余量至少一块，本机豫言进程实际占用的处理器加一不超过核数上限。不预先划给它什么，起来以后用多少领多少 |
| 议五 | **仓（按块给内存）**：执行器的堆回收之后仍要长过已给的，就向系统领一块。在自己的上限内、池里有实际余量就当场给；超过上限时，池里有余量、又没有人排在前面才给，并把上限抬上去；给不了就照进程自选的缺存办法（议六） |
| 议六 | **缺存三法，进程自选**：候——让出处理器、停在分配处，等别的任务做完放出内存，在等的任务排在新任务前面，领到后接着跑；窖（缺省）——把自己的冷块换进窖，留在已有槽数里接着跑（软暂停）；止——报“内存不够”退出（退码一百二十）。登记时带上选择，环境变量 `豫言缺存` 可改，程序也可以在开头经东道改。都停在执行器的分配路径上，不用 SIGSTOP |
| 议七 | **窖（换页区）与破死锁**：执行器把块写进系统的换页文件，再把那段地址换成该文件的写时复制映射，物理页随之释放；再用到时由缺页读回。全部任务都在候、谁也做不完时，系统请在候的任务整堆换进窖，放排头的那个先跑 |
| 议八 | **闲时交还**：进程回收后还出至少一块、或闲下来（如两件任务之间的常驻工作者）时，把还出的内存告诉系统，账按实际减 |
| 议九 | **将作向系统租处理器**：将作经一条常连接（将作通道）按件向系统租处理器，系统按实际余量许；工作进程的内存由它的执行器自己领。将作手里的租约不超过它自己声明的槽数；系统说本机没有，将作就让任务排队，或把任务、整次构建转给同僚。将作删去按内存折算的占槽、内存空等这些资源代码，槽数只作它自己的上限 |
| 议十 | **量实占与收拾进程**：系统按进程号量实占（活动监视器的口径，#653）；按进程树收拾进程，代役退出时它的子孙不留孤儿（#654）；系统停止时只结束自己起的任务（#503） |
| 议十一 | **各宿主一致**：林檎、林纳同一套做法，写在执行器与行在里，不用林纳的 cgroups；裸机内核实现同一套接口，将作在四种宿主上走同一条路 |

## 二、动机

2026-10-25 本机（四十八吉、十八核，将作设了八槽）当天又死机重启。死机前的快照（12:55）：

- 内存已用 47G，压缩区 24G，空闲 276M。豫构相关进程二十来个，各占二到四点四吉：将作八个槽里的代役进程树约 22 GB（`ps` 量到的常驻合计只有约 4 GB）；换链重起留下的孤儿五个约 18 GB（#654）；客自己起的最终链接三个约 13 GB（f64c769231 已改）；客的编译驱动十来个约 3.5 GB。
- 处理器满载（用户态 77%、内核态 23%），将作槽里的活只占约 2.3 核。其余是代理直接运行的测试与工具、每秒约 63 个短命进程、另一会话的盯梢脚本、压缩与换页的内核开销。

根子在分工：将作兼做了一部分系统的活（槽数、按内存折算的占槽、内存空等、单件上限），却只看得见自己派出的任务，量的还是不含压缩区的常驻；行在看得见本机全部豫言进程（00039 第一步的任务表），却不管资源。两边各做一半，补一处漏一处。资源与进程生命周期交给系统统一管，将作专心做构建与分发，才兜得住。

## 三、设计

### 3.1 分工

| 层 | 管什么 |
| --- | --- |
| 系统（行在、内核） | 准入；按实际余量给处理器与内存；池的上限与换页（窖）；缺存三法；进程树收拾；优先级（交互、前台、后台）；实占计量 |
| 将作 | 跨构建的任务队列（整次构建先来后到）；工具链与代役池；缓存（共享缓存、同僚取键、过录）；分发（托役、整客远行、候簿）；令牌、虎符与结盟；监工；声明自己的上限（槽数、每槽额） |
| 执行器 | 登记时等许行；问额；堆回收后仍要长就按块领存；还存；缺存三法的执行（候时让出处理器，窖时换出冷块，止时退出） |
| 客 | 依赖图、先探缓存、把就绪任务交给将作 |

协议（登记帧、答帧、服务 300 问额、301 领存、303 换毕、304 还存、将作通道、窖文件）以《平台接口规范》“司阍与仓”一节为准。

### 3.2 一律入系统

- 执行器启动时照旧加入行在（`客体二号/行在门`）。门文件里有“司阍”二字时发 YXZ2 登记帧并等许行，没有就照旧发 YXZ1、不等，新旧兼容。
- 常驻工作者也登记（原先不登记），标“随作”：它的处理器由将作按任务租，登记时不看处理器余量，内存照样受仓管。
- 构建类命令调「辞附庸」（只撤附庸、留在行在，环境设 `豫言全宿主=1`，子进程照宿主路径加入），开头保起行在。

### 3.3 司阍

- 放行按实际余量：池里实际余量至少一块，且（不带“随作”的）本机豫言进程实际占用的处理器加一不超过核数上限，就许行；否则排队回候行。不预先划给进程什么，起来以后用多少领多少。
- 次序：在候的任务先于新任务，优先号小的先，同级先到先放，排头的放不下时后面的也不越过它。
- 带“免”的任务（将作、行在、交互壳、监工）与系统自己起的子进程（桌面、桌面程序）立刻放行。
- 处理器的实际占用：各任务一秒内处理器时间的增量（原语 293）求和。

### 3.4 仓与缺存三法

- 许行后执行器问额（服务 300），得到块、自己的上限与已给。上限取进程环境里的 `豫言内存上限`（将作给代役的任务设成每槽额），没设就等于池的上限 X。
- 堆回收之后仍要长过已给：用「宿主交还」把空块还给宿主；仍不够就领存（服务 301），一次领一块或几块。
  - 在上限内、池里有实际余量：当场给。
  - 超过上限：池里有余量、又没有人排在前面等，照样给，上限随之抬高；不然照缺存三法。上限只在这时起作用。
  - 池里没有实际余量：照缺存三法。
- 缺存三法：
  - **窖**（缺省）：行在答“自换”，执行器把自己的冷块换进窖（3.5），再重领；窖满了或没有可换的，改按候。
  - **候**：让出处理器、停在分配处，等别的任务做完放出内存；在等的任务先于新任务得到。等的时候它不在跑，行在可以请它换出。
  - **止**：印“内存不够（豫言缺存=止）”退出，退码一百二十。
- 还存：执行器回收后用「宿主交还」还了至少一块，或常驻工作者做完一件任务后，告诉行在（服务 304），账按实际减。代役闲满一分钟照旧退出。
- 没有行在或旧行在（问额答负三十八）时，执行器照旧模式：只受 `豫言内存上限`（单件硬上限）管，超了止。
- 缺省：缺存三法一律窖；要尽早发现内存失控的测试可设止；几个大构建挤在一起、窖里颠簸时可设候。

### 3.5 窖

- 每个进程一个稀疏文件 `<行在目录>/窖/<进程号>`（0600），执行器头一次换出时建，行在在它注销后删。窖的总量缺省同 X，满了就不再换出。
- 怎么换：以执行器的堆块（2 MiB）为单位，写进文件，再用「宿主映档」把这段线性地址换成该文件的写时复制映射（MAP_PRIVATE），原来的物理页随之释放；映射是干净的文件页，宿主回收时不必写回。再读到时由缺页读回，写时写时复制成匿名页。程序看不出差别，只是慢一些。
- 换谁：在候的任务与闲着的任务整堆换出；选了窖的任务换出自己的冷块（先老年代与大块只读数据，再按块的最近使用顺序）。
- 破死锁：全部任务都在候、谁也做不完时，行在请其余在候的任务换出，放排头的那个先得。
- 「宿主映档」现在只在林纳的常驻工作者用；林檎要接通。
- 要实测的风险：回收器全量标记会把换出的块读回来，换得越多越像颠簸；换出以老年代为主，回收少做全量标记。

### 3.6 将作与系统

- 第一期：将作每秒问一次『余』，派役时取槽数与余件中小的（6a3a87b8fc）。
- 第四期：将作经将作通道按件向行在租处理器（『领』『许』『还』），行在按实际余量许；工作进程的内存由它的执行器自己领。租约不超过将作自己的槽数（它声明的上限）。删去将作按内存折算的占槽、内存空等；给代役的任务环境设 `豫言内存上限`＝每槽额（上限，不是硬顶），常驻工作者设 `豫言行在随作`。候簿与转发看租约：本机租不到、排得久的，优先转给同僚。
- 托役、整客远行的进程在本机也是系统的任务，同样受司阍与仓管。

### 3.7 量实占与收拾进程

- 系统按进程号量实占（原语 291 问号实占、292 问号父、293 问号时、294 问众实占，已合入 110ec52aa7），一秒一次；不再起 `ps`。
- 代役退出前召回它的子进程与常驻工作者，系统也按进程树兜底，不留孤儿（#654）；系统停止时只结束自己起的任务（#503）。

## 五、缺省值与待定

- 池的上限 X 缺省物理内存七成；核数上限缺省在线核数；块缺省每槽额的八分之一、至少六十四兆；窖的总量缺省同 X。设置文件与环境变量（`豫言行在内存上限`、`豫言行在核数上限`）可改，单位兆。
- 待实测：回收器全量标记读回换出块的颠簸；领存与租约的往返开销（必要时一次多领几块、多租几件）；块取多大合适。
