## 一、拟定事项

| 编号 | 拟定 |
| --- | --- |
| 议一 | **分工**：系统（宿主上是行在，裸机上是内核）管一切与机器资源和进程生命周期有关的事；将作管一切与构建本身有关的事：跨构建的任务队列、工具链与代役池、缓存、分发（托役、整客远行、候簿）、令牌与结盟、监工；执行器是两层之间的桥；客（豫构的构建命令）照旧拿着依赖图、先探缓存，把就绪的任务交给将作 |
| 议二 | **一律入系统**：本机起的每个豫言进程都是系统的任务，构建也不例外。构建类命令只撤附庸（「辞附庸」，照宿主路径），不再辞出行在；系统停止时不杀它们。只有 CI、虚根与明设 `豫言行在=关`（须用户批准）独行。行在是必须一直在的基础设施：没起就自动起，断了任务自己重连 |
| 议三 | **两种槽**：运行槽管处理器，个数是核数上限；内存槽管内存，每槽是每槽额（内存上限 X 除以内存槽数）。X 缺省取物理内存的七成，内存槽数缺省等于运行槽数 |
| 议四 | **司阍（准入）**：进程登记时等系统一声“许行”才往下跑：要有一个空运行槽和起步的内存。构建任务起步一个内存槽；普通程序起步零头（四分之一槽），免得几十兆的小工具攥着一整槽 |
| 议五 | **仓（按槽给内存）**：执行器的堆上限等于所持内存槽乘每槽额；回收之后仍要长过上限，就向系统再领一槽，领到了把上限抬高一槽接着跑。领不到时照进程自选的缺存办法（议六） |
| 议六 | **缺存三法，进程自选**：候——让出运行槽、停在分配处，等别的任务做完放出内存槽，在等的任务排在新任务前面，领到后拿回运行槽接着跑；窖（缺省）——把自己的冷块换进窖，留在已有槽数里接着跑（软暂停）；止——报“内存不够”退出（退码一百二十）。登记时带上选择，环境变量 `豫言缺存` 可改，程序也可以在开头经东道改。都停在执行器的分配路径上，不用 SIGSTOP |
| 议七 | **窖（换页区）与破死锁**：执行器把块写进系统的换页文件，再把那段地址换成该文件的写时复制映射，物理页随之释放；再用到时由缺页读回。全部任务都在候、谁也做不完时，系统请在候的任务整堆换进窖，放排头的那个先跑 |
| 议八 | **闲时交还**：进程闲下来（如两件任务之间的常驻工作者）先回收，把多余的内存槽还给系统 |
| 议九 | **将作向系统领槽**：将作派任务前向系统领一个运行槽，工作进程的内存槽由它的执行器自己领；系统说本机没有，将作就让任务排队，或把任务、整次构建转给同僚。将作删去自己的槽数、按内存折算的占槽、内存空等与单件内存上限这些资源代码 |
| 议十 | **量实占与收拾进程**：系统按进程号量实占（活动监视器的口径，#653）；按进程树收拾进程，代役退出时它的子孙不留孤儿（#654）；系统停止时只结束自己起的任务（#503） |
| 议十一 | **各宿主一致**：林檎、林纳同一套做法，写在执行器与行在里，不用林纳的 cgroups；裸机内核实现同一套接口，将作在四种宿主上走同一条路 |

## 二、动机

2026-10-25 本机（四十八吉、十八核，将作设了八槽）当天又死机重启。死机前的快照（12:55）：

- 内存已用 47G，压缩区 24G，空闲 276M。豫构相关进程二十来个，各占二到四点四吉：将作八个槽里的代役进程树约 22 GB（`ps` 量到的常驻合计只有约 4 GB）；换链重起留下的孤儿五个约 18 GB（#654）；客自己起的最终链接三个约 13 GB（f64c769231 已改）；客的编译驱动十来个约 3.5 GB。
- 处理器满载（用户态 77%、内核态 23%），将作槽里的活只占约 2.3 核。其余是代理直接运行的测试与工具、每秒约 63 个短命进程、另一会话的盯梢脚本、压缩与换页的内核开销。

根子在分工：将作兼做了一部分系统的活（槽数、按内存折算的占槽、内存空等、单件上限），却只看得见自己派出的任务，量的还是不含压缩区的常驻；行在看得见本机全部豫言进程（00039 第一步的任务表），却不管资源。两边各做一半，补一处漏一处。资源与进程生命周期交给系统统一管，将作专心做构建与分发，才兜得住。

## 三、设计

### 3.1 分工

| 层 | 管什么 |
| --- | --- |
| 系统（行在、内核） | 准入；运行槽与内存槽；内存上限与换页（窖）；缺存三法；进程树收拾；优先级（交互、前台、后台）；实占计量 |
| 将作 | 跨构建的任务队列（整次构建先来后到）；工具链与代役池；缓存（共享缓存、同僚取键、过录）；分发（托役、整客远行、候簿）；令牌、虎符与结盟；监工 |
| 执行器 | 登记时等许行；堆上限随所持内存槽变；领槽、还槽；缺存三法的执行（候时让出运行槽，窖时换出冷块，止时退出） |
| 客 | 依赖图、先探缓存、把就绪任务交给将作 |

### 3.2 一律入系统

- 执行器启动时照旧加入行在（`客体二号/行在门`）。门文件（`门。数据。豫`）里有“司阍”二字时发 YXZ2 登记帧并等许行，没有就照旧发 YXZ1、不等，新旧兼容。
- YXZ2 登记帧（三十二位小端）：+0 魔数“YXZ2”；+4 钥，三十二字节；+36 进程号；+40 标志（第零位“免”：首参为将作、行在、交互、监工，或设了 `豫言行在免`）；+44 优先（零交互、一前台、二后台，取 `豫言将作优先`）；+48 缺存（零窖、一候、二止，取 `豫言缺存`）；+52 程序路径长；+56 起程序路径。
- 答帧（八字节头：状态、数据长，后接数据）：状态零“许行”；状态一“候行”，数据为排第几与缺什么（一内存、二处理器）。执行器等候行时三十秒内至多印一行“等本机行在放行：排第 N（缺内存）……”；等的时候连接断了每秒重连，六十秒连不上就独行。
- 构建类命令调「辞附庸」（只撤附庸、留在行在，环境设 `豫言全宿主=1`，子进程照宿主路径加入），开头保起行在。

### 3.3 司阍与两种槽

- 放行：有空运行槽，内存槽（或零头）够起步，就许行；否则排队。次序是在候的任务先于新任务，优先号小的先，同级先到先放，排头的放不下时后面的也不越过它。
- 带“免”的任务（将作、行在、交互壳、监工）与系统自己起的子进程（桌面、桌面程序）立刻放行，它们用系统预留的一份，不占槽。
- 系统给将作的请求『余』：答还能放几件、内存余量、上限与已用，将作每秒问一次（第一期已用这个）；第四期起将作改为按任务领运行槽。

### 3.4 仓与缺存三法

- 执行器启动时，堆上限取起步所给（一槽或零头）乘每槽额；`豫言内存上限`（单件硬上限）照旧，超了一律止。
- 堆要长过上限：先回收，用「宿主交还」把空块还给宿主；仍不够就向系统领一槽。
- 领不到就照缺存三法：
  - **窖**（缺省）：执行器把自己的冷块换进窖（3.5），腾出空间就在已有槽数里接着跑；窖满了退成候。
  - **候**：让出运行槽、停在分配处，等内存槽；领到后拿回运行槽接着跑。等的时候它不在跑，系统可以请它整堆换出。
  - **止**：印“内存不够（豫言缺存=止）”退出，退码一百二十。
- 闲时交还：进程闲下来先回收，把多余的内存槽还给系统；代役闲满一分钟照旧退出。
- 缺省：缺存三法一律窖；要尽早发现内存失控的测试可设止；几个大构建挤在一起、窖里颠簸时可设候。

### 3.5 窖

- 窖是行在目录下的稀疏文件（缺省 `~/.豫言/行在/窖/`），按任务分段，大小缺省同 X，满了就不再换出。
- 怎么换：执行器把块写进自己的那一段，再用「宿主映档」把这段线性地址换成窖文件的写时复制映射（MAP_PRIVATE），原来的物理页随之释放；映射是干净的文件页，宿主回收时不必写回。再读到时由缺页读回，写时写时复制成匿名页。程序看不出差别，只是慢一些。
- 换谁：在候的任务与闲着的任务整堆换出；选了窖的超额任务换出自己的冷块（先老年代与大块只读数据，再按块的最近使用顺序）。
- 破死锁：全部任务都在候时，系统请其余在候的任务整堆换出，放排头的那个先跑。
- 「宿主映档」现在只在林纳的常驻工作者用；林檎要接通，块大小取两边页面的公倍数（16 KiB 的倍数）。
- 要实测的风险：回收器全量标记会把换出的块读回来，换得越多越像颠簸；换出以老年代为主，回收少做全量标记。

### 3.6 将作与系统

- 第一期：将作每秒问一次『余』，派役时取槽数与余件中小的（6a3a87b8fc）。
- 第四期：将作派任务前向系统领一个运行槽、做完归还；工作进程的内存槽由它的执行器自己领。删去将作的槽数、按内存折算的占槽、内存空等与单件上限；候簿与转发按系统给的余量决定：本机领不到槽、排得久的，优先转给同僚。
- 托役、整客远行的进程在本机也是系统的任务，同样受司阍与仓管。

### 3.7 量实占与收拾进程

- 系统按进程号量实占（原语 291 问号实占、292 问号父、293 问号时、294 问众实占，已合入 110ec52aa7），一秒一次；不再起 `ps`。
- 代役退出前召回它的子进程与常驻工作者，系统也按进程树兜底，不留孤儿（#654）；系统停止时只结束自己起的任务（#503）。

## 四、实施（分五期）

1. **第一期 放行与计量**（在做）：执行器原语 291–295、YXZ2 登记与等许行（110ec52aa7）；行在门文件标司阍、收 YXZ2、按“已用加预计实占不超过 X、负载小于核数”放行、排队与候行、『余』请求、停止只收自己起的、状态显示仓（钩司阍）；将作派役前看余件（6a3a87b8fc）。这一期行在暂用 `ps` 量。
2. **第二期 改用原语、构建入系统**：等 CI 发出含原语 291–295 的工具链包后，行在改用原语量实占、不再起 `ps`；构建类命令改「辞附庸」并保起行在；放行改按两种槽。
3. **第三期 按槽给内存**：执行器堆上限随所持内存槽变，领槽、还槽；缺存三法（候、止先做，窖在第五期）；常驻工作者闲时交还。
4. **第四期 将作的资源代码交给系统**：将作按任务领运行槽，删去自己的资源代码；候簿与转发按系统余量；代役退出不留孤儿。
5. **第五期 窖与裸机**：换出、换入、破死锁；林檎接通「宿主映档」；裸机内核实现同一套接口；监工与「行在态」显示两种槽与窖。

## 五、缺省值与待定

- X 缺省物理内存七成；运行槽数缺省在线核数；内存槽数缺省等于运行槽数；普通程序起步四分之一槽；窖大小缺省同 X。设置文件与环境变量（`豫言行在内存上限`、`豫言行在核数上限`）可改，单位兆。
- 待实测：回收器全量标记读回换出块的颠簸；每件任务领槽的往返开销（必要时一次批领几槽）；起步零头取多少合适。
