## 内嵌框架（同进程版，2026-10-24，钩深嵌页）

- 载入：`载网页` 在父页脚本跑完、读样式与渲染之前，把文档里的 `iframe` 各载成一个子浏览上下文。`src` 按父文档基址解析成绝对网址，`srcdoc` 取内嵌源码，都没有时载空白文档；子页走同一个载页通路递归载入，自己执行脚本、读样式并排版。父页记下每个框的子文档、网址、父窗与顶层窗、脚本环境与文档绑定，嵌套至多十层。

## 开媒影帧边扭曲预测越界（#583，2026-10-24）

- 根因：本地扭曲预测总入口「开媒扭铺」按未裁的块宽高算最后一块 8×8 瓦片的上限。三十帧样第三帧（帧间）右下角块的底边在帧外（纵+高 = 724，帧高 720），上限 = min(4, 724 − 716 − 4) = 4，扭纵列于是把第 716..723 行写进面；面只有 720 行，写到第 720 行时下标 720×1280+1216 = 922816 越过面长 921600，陷入。
- 修法：扭铺入口先把块宽高夹到面内（min(宽, 面宽−横)、min(高, 面高−纵)）；扭纵列写画面前再查一次行、列，出界不写。两处都只夹写，不改帧内样值。
- 验证状态：修后帧内首帧三面样和与 ffmpeg 解出的同帧逐面和完全一致（亮 116093090、色甲 29207972、色乙 28935378）；帧间次帧仍不符——我亮 117072779 对参亮 116133322、色甲 29207972 级别的小差、色乙 29089194 对 28949904，逐像素比亮度面 921600 样中 581055 样不同、首个不同就在 (0,0)。把编码器的扭曲与全局运动关掉另编一条，次帧仍不符，故这是独立的帧间预测偏差（八抽插值取整、重叠块混合或复合预测一路），不是扭铺越界引起的。
- 结论：#583 的越界已定位并修在「开媒影/图解。豫」（两处夹取）；三十帧逐帧解完与逐像素比尚未过，卡在帧间预测偏差，需继续查。临时诊断程序已删，工作树只留这一处修复与本节记录。

给 `开媒变块` 加一条按追踪开关的残差标注（每变换块印 `RS 面 横 纵 eob`；`负一` 表示该块按"无残差"走），配合帧 1 的八乘八块图做联合分析：

- 帧 1 亮度共 16386 个变换块：**8722 块按无残差走、3648 块 eob 为零、只有 4016 块真有残差**——七成半的变换块像素就是纯预测。
- 块图上差样数到十（记作 `＊`）的 8×8 块共 4365 个：覆盖它的变换块**无残差的 2281 个、有残差的 2084 个**。即**过半数坏块根本没有残差**，错在预测。
- 这 2281 个"大差且无残差"的块里：**998 个落不到任何帧间块上**（即落在帧间帧里的帧内块上），763 个落在整像素位移的帧间块上，520 个落在分数位移的帧间块上。

结论：**帧间帧里的帧内块（约 998 个 8×8 块，折合约一成样）是第一个明确缺陷**——帧 0 全帧内精确，说明帧内预测本身对；帧间帧里的帧内块另有岔子（模式符集/邻块可用性/调色板或滤内之类）。余下部分要分两条查：整像素位移块（763 个，说明不只是插值取整）与分数位移块（520 个）。

下一轮就从"帧间帧里的帧内块"这条查起：先看这些块的帧内模式读法与帧 0 是否用了同一套符号集与上下文，再看滤内（filter intra）与色度自亮（CFL）在这类块上的取法。

### 三个入口查证结果（2026-10-25，均未查出能解释现状的缺陷）

1. **模式符号集与上下文**：`开媒读模` 对帧内帧用 `表号 零`（kf_y_mode，上下文取上左模组），对帧间帧里的帧内块用 `表号 一`（y_mode，按块尺取上下文），与 AV1 一致。
2. **色度模式符数**：`符数 = 若 表号=三 则 一四 否则 一三`，其中 `表号 三/二` 由**调色板条件**（`参三零`＝帧参四零，即 allow_screen_content_tools，配块尺不超三二）选出，而规范里该符数应由 **CFL 是否允许**（序列 CFL 开关、宽高不超三二、非无损）决定。本流里 `参三零` 为 0，两条条件恰好重合（块尺不超三二即 14 符），故不影响现状；这是**潜在缺陷**，遇屏幕内容流会错。
3. **滤镜内与调色板/CFL 读取**：`开媒读滤内`、`开媒调色亮/色`、`开媒色亮读`（CFL）都在读模与变块的正确位置。
4. **另发现一处混用**：`参三零`（allow_screen_content_tools）同时被当作**无损标志**用——`参五三`（是否走沃什反变换）、`存一列` 的位移、`参四四`（行移）都由它取反得到。本流 `参三零` 为 0，行为与无损关闭一致，故不错；一旦遇到无损或屏幕内容流，这几处会一起错。

### 上一轮"帧间帧里的帧内块"这条线索不成立

上一轮判"998 个坏块落不到帧间块上"用的块尺寸换算是猜的（按 AV1 的 BLOCK_SIZES 标准表），实际这个解码器的块尺换算是 `开媒块宽四/块高四` → 常数表偏移四四/六六。按猜测表算出的块面积合计是帧面积的一一一点七成（重叠），说明尺寸表用错了，因此"落不到任何帧间块"的 998 个位置是换算错误的产物，不能作为结论。要重做这条，得先把帧间块追踪里的块尺按 `开媒块宽/块高` 打成像素尺寸再分析。

### 编码器侧逐项关工具的对照（本轮新增）

关 CFL（`-enable-cfl-intra 0`）→ 帧 1 差 500822；关滤内（`-enable-filter-intra 0`）→ 537776；关调色板（`-enable-palette 0`）→ 564177。三者都比基线（228883）更差，说明差异不是某一件帧内工具的读取错，而是随编码器设置整体漂移的多处问题。

### 参考帧存储次序核对（2026-10-25，结论：次序对）

### 变换集这条：我又看错了一次（自我更正）

`开媒变集` 只按变换尺取集，**不带"是否帧间块"这个入参**：

```
若 变换方上 > 三 则 零
否则若 变换方上 = 三 则 零
否则若 帧参三九（精简变换集）= 一 则 二
否则若 变换方 = 二 则 二
否则 一
```

返回的只有零、一、二三个值。规范里变换集枚举是：零＝只用 DCT，一＝帧内集一（七符），二＝帧内集二（五符），三～五＝帧间集一/二/三（七至十六符）；`get_ext_tx_set_type` 的入参里就有 `is_inter`，帧间块八乘八取帧间集一（精简时取帧间集二）、十六乘十六取帧间集三，四乘四与三十二以上取零。

也就是说：**帧内块拿到一/二恰好等于帧内集一/二（所以帧 0 精确），而帧间块也拿到一/二，按帧内集去读帧间的变换型**——两者符号数不同（七对十六等），读出来的变换型必错。这与"只用 DCT 编码的流差异减半"、"帧间块三成有差"都对得上。

**更正**：这条不成立。`开媒变集` 只被"帧内块"那条分支调用（帧间亮度块走 `开媒间变`，它已按规范实现了帧间集：无损或长边三十二以上取零或二符、十六取二符、八乘八取十二符、其余十六符，另有 `开媒面在集` 管色度帧间的在集判定）。所以帧内块拿到一/二恰好就是帧内集一/二，**没有错位**；帧间那几张表也已经在别处实现，常数表 684 以后不是位图而是别的数据（值为十一、二十一之类），我按"每集十六项位图"去找自然对不上。

### 根因：全动矢读错了表

逐块印出"候选源"：`(1,6)` 是帧内第一个带位移的块，其上、左邻皆帧内，候选取自全动矢。两边：

- libaom：`pred=(-31,-198)`；全局运动参数 `type=2`（旋转缩放）、`hp=1`（高精度位移位）。
- 我们：全动矢 `(-30,-198)`。

两处错：

1. `开媒全动折` 判"是否高精度"时读的是**参表**一四五——那是"新移计数"（`参一四五` 在同一轮里被 `开媒间栈` 当计数器反复加减），不是帧头的高精度位；`开媒全动整矢` 同病，读参一五九。两处都该读**帧参**（帧头）。
2. `开媒取整有号` 是"四舍五入远离零"（负值先取绝对值再舍入），而 libaom 的 `ROUND_POWER_OF_TWO` 是"加半再算术右移"（负值朝下取整）。凡 `xc、yc` 为负且带零头，两者差一。

两处合起来正好让全动矢的行多一，经"邻块位移 → 候选 → 预测子"逐块传下去，整帧所有预测子偏一。

### 修法

- `开媒取整有号`：去掉负值分支，统一 `降位(值加半, 位)`。
- `开媒全动折`、`开媒全动整矢`：改读 `帧参` 一四五、一五九。
- `开媒位漂`：照 `av1_drl_ctx` 四分支重写（前重后重得零、前重后轻得一、前轻后轻得二、前轻后重得零），替掉原来"前轻一律得二"的三分支。

## 色度变换集错传模式：块态对齐 101 → 616（2026-10-25 午后，整轮）

### 手段：逐符号带态对表

给 `(24,12)`、`(40,28)` 两块在两边各开逐符号追踪：libaom 在 `od_ec_decode_cdf_q15`／`od_ec_decode_bool_q15` 印 r／c／符数／符号，另在 `read_coeffs_txb` 印 TXB 入口（面、块内坐标、变尺）、all_zero、变换式、尾点、逐系数级与符号；我方在 `开媒概符`／`开媒概爻`／`开媒概二` 与 `开媒系`／`开媒系基读`／`开媒系号读`／`开媒哥` 同位印同样字段，另有块入口 `BQ 纵= 横= 尺= 范= 值=` 与「主扫栈」`tag=main`。两边按 (类, r, c, 值) 归一对表，第一个不同的符号即失步点。

### 病根：色度间块的集合判据传了 `参二二`

`开媒系非跳` 的色度分支里，`开媒面在集`（照 `av1_get_ext_tx_set_type` 判集合）的「变」参写成 `（「开媒参」于「二二」）`，而 `参二二` 是**帧内色度模式**（`开媒读模` 写它，间帧块不写），于是间帧色度块拿到上一帧内块的残值当变换尺。8x8 色度 TXB 里这个残值让 `开媒面在集` 走「长边满三二」一路，判 `式` 不在集内，得零（DCT_DCT，二维类），而 libaom 取亮度式 15（H_FLIPADST，一维类）。

后果不止变换：`eob_multi_ctx = (tx_class == 2D) ? 0 : 1` 随之取 0 而 libaom 取 1，同一 eob 符号 5 读的是色度表的第 6 行而非第 7 行，概率值不同，读出的区间态不同 —— 逐符号表上正是「同一符号、后态不同」，自此残差整段错位。

### 修法

`开媒面在集` 的「变」参改传当前变换块的色度变换尺 `尺`（即 `tx_size`）：

`　　　　若（「开媒面在集」于「变」曰「尺」于「式」曰「基式」）则「基式」否则「零」`
