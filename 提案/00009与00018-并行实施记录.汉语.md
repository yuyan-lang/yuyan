## 内容安全策略的违规事件与上报（2026-10-23，钩深内容安全）

- 网页安全新增「违规报告」：违规记录（违反指令、生效指令、被阻地址、原始策略、处置、源文件、行列、样本、状态码、文档地址、来源页）、违规桥（宿主装派事与上报）、违规境（只报不拦的策略、文档地址、来源页）、同一违规只报一次、按违约的那一份策略取 `report-uri` 并按文档地址补成绝对地址、`csp-report` 结绳报文体。`report-to` 的 Reporting API 投递留待后续版本。
- 抓取主算法在内容策略拦下时记一条处置 enforce 的违规；许可后再核只报不拦的策略记一条处置 report 的违规；目的为 `report` 的报告请求不受策略约束，免得报告自身再触发报告。
- 网页榫卯新增「内容安全事」：`SecurityPolicyViolationEvent` 构造器（缺文字字段给空串、缺数值字段给零、缺处置给 `enforce`、没有事件类型抛类型错误）与冒泡派发的 `securitypolicyviolation` 事件，十二个字段经「篇系」的事件包装交给脚本；页面接口装配时装上构造器。
- `fetch` 读初值的模式、凭据、缓存与转向，并把页面内容安全策略交给抓取主算法；`XMLHttpRequest` 改走主算法（来源取页面地址、凭据随 `withCredentials`），跨源预检与响应许可随之生效。
- WebSocket 在构造前按 `connect-src` 拦下时先记违规、派事并按 `report-uri` 上报，再抛安全错误。
- 浏览器资源读取按导航响应记只报不拦的策略、文档地址与来源页；违规桥在文档上派事件并按 `report-uri` 投报告，报告请求走抓取主算法、目的记 `report`；入口换页时清已报违规并重设违规境。
- 测试：网页安全「违规报告」、抓取「内容策略违规」、网页榫卯「内容安全事」三篇新测通过；页面接口、网页笔谈与浏览器综合冒烟不退回。
- 未接入：内联脚本、eval、内联样式与内联事件处理器的策略判定（浏览器与脚本测都还没有这条路径）；脚本测的运行器不把响应头带进页面载入，CSP 的拦截与上报在网平测里还看不见（运行器与 `接引` 的缺口）。

## 行内盒边框内边距与外边距一簇（2026-10-24，钩深背景）

已合入的部分：行内盒的片段按自身边框与内边距向外扩成边框盒再登记（`07d41143f`），`border-padding-bleed-001..003` 三例转为通过；行内盒首末片的横向占位计入边框与内边距（`27d66fe4b`），文字不再压在自己的边框上。以上均零退步。

「祖先片段沿链累进外边距」（`2b8d9c619`）已撤回（`70b1a16f4`）。撤回前查明的结论如下，后续再做这一簇时照此入手：

- **祖先累进与片落点分属两个函数**：祖先登记那段所在函数里，片记录绑定名是 `待`（`网页随行待置`）；而 `样左距`、`首片吗`、`左距`、`本左距` 在另一个函数里，绑定名是 `片`（`网页行内片`）。两段的 `前祖序`、`祖先` 可见性对不上，跨函数引用 `片` 会直接编译失败（`未定义的名字「片」`），这也是几轮「改了没生效」的原因。
- **文字片（盒为 `#text`）的 `本左距` 在整页路（`析篇`）上恒为零**：`左距 → 样左距` 读的是「样」，即文字盒自己的样式，不带外层行内盒的 `margin-left`；片段路（`析片段`）最终显示 +100 是别处登记碰巧补上的，不是这条链的功劳。
- **两路收片一致，分岔在落点与累进的配合**：同一份 IFC-002 原页字节，`析篇` 与 `析片段` 的 `收网页随行片` 序列（盒名、显示、祖先条数）完全相同；分岔发生在「片落点」与「祖先累进」两步——累进把内层盒的外边距减进了外层矩形，而落点从未加上它，于是外层被挤到负坐标（实测 `析篇` 外 div 横 = −92，`析片段` 为 60/160）。
- **IFC-002/003 现状**：两例仍失败（像素差约 2.4K / 0.8K），IFC-004/005 的 100 像素边框在真页面上只画出约三像素（同一 CSS 在片段探针里能画满，差异待查）。`empty-inline-002/003` 未动：空行内盒要先按「只有边框加内边距」量算，再补零内容片（此前直接补片会按块级整行宽排，已回退）。
- 复现办法：临时的「原页探」程序把 IFC-002 原文件字节（去掉 match 与 ahem 两个链接）分别用 `析篇` 与 `析片段` 解析、`生网页盒树`、`布局网页`，逐盒打印 `显示` 与 `边框矩形`；本记录成稿时该探针已删，按此描述可重建。
