## 内容安全策略的违规事件与上报（2026-10-23，钩深内容安全）

- 网页安全新增「违规报告」：违规记录（违反指令、生效指令、被阻地址、原始策略、处置、源文件、行列、样本、状态码、文档地址、来源页）、违规桥（宿主装派事与上报）、违规境（只报不拦的策略、文档地址、来源页）、同一违规只报一次、按违约的那一份策略取 `report-uri` 并按文档地址补成绝对地址、`csp-report` 结绳报文体。`report-to` 的 Reporting API 投递留待后续版本。
- 抓取主算法在内容策略拦下时记一条处置 enforce 的违规；许可后再核只报不拦的策略记一条处置 report 的违规；目的为 `report` 的报告请求不受策略约束，免得报告自身再触发报告。
- 网页榫卯新增「内容安全事」：`SecurityPolicyViolationEvent` 构造器（缺文字字段给空串、缺数值字段给零、缺处置给 `enforce`、没有事件类型抛类型错误）与冒泡派发的 `securitypolicyviolation` 事件，十二个字段经「篇系」的事件包装交给脚本；页面接口装配时装上构造器。
- `fetch` 读初值的模式、凭据、缓存与转向，并把页面内容安全策略交给抓取主算法；`XMLHttpRequest` 改走主算法（来源取页面地址、凭据随 `withCredentials`），跨源预检与响应许可随之生效。
- WebSocket 在构造前按 `connect-src` 拦下时先记违规、派事并按 `report-uri` 上报，再抛安全错误。
- 浏览器资源读取按导航响应记只报不拦的策略、文档地址与来源页；违规桥在文档上派事件并按 `report-uri` 投报告，报告请求走抓取主算法、目的记 `report`；入口换页时清已报违规并重设违规境。
- 测试：网页安全「违规报告」、抓取「内容策略违规」、网页榫卯「内容安全事」三篇新测通过；页面接口、网页笔谈与浏览器综合冒烟不退回。

## 内嵌框架（同进程版，2026-10-24，钩深嵌页）

- 载入：`载网页` 在父页脚本跑完、读样式与渲染之前，把文档里的 `iframe` 各载成一个子浏览上下文。`src` 按父文档基址解析成绝对网址，`srcdoc` 取内嵌源码，都没有时载空白文档；子页走同一个载页通路递归载入，自己执行脚本、读样式并排版。父页记下每个框的子文档、网址、父窗与顶层窗、脚本环境与文档绑定，嵌套至多十层。
- 排版与绘制：父页排版之后，绘制侧的排版钩按每个框的实际内容盒宽高再排一次子页、生图；子页图走已有的替内容绘制通路按内容盒原样绘入，不另缩放。命中在父页显示列表上找到框之后，把点换成子文档视口坐标，再在子页显示列表里命中，指针因此落到子页的节点上。
- 脚本接口：子页窗口装 `parent`、`top`、`frameElement`、`frames` 与长度；父文档里框元素的包装装 `contentWindow` 与 `contentDocument`（后者只在同源时给子文档，`about:blank` 与 `about:srcdoc` 算继承父页来源）。`postMessage` 换成按接收者分派的窗投术（父投子、子回投都到得了对方，`message` 事件带 `data`、`origin`、`source`、`ports`），跨源只走这条路。框载好之后在框元素上派发 `load`。
- 结构：接引新增 `嵌页` 一篇管载入、登记、窗口接线、排版钩、命中钩与事件；`静态载` 记下每页的整页渲染闭包供子页按内容盒重排；网页榫卯新增 `窗接` 一篇装 `parent`、`top`、`frameElement`、`frames` 与窗投，并在元素包装新造时留一个装钩；设色新增 `嵌页绘` 三个可装的钩子，故设色不反向依赖接引。规范行为，不为某个网站或测试写特判。

## 视频元素的 VP8 解码播放（2026-10-24，钩深影播）

- 新库「影播」（`库/群书/丹青部/影播/`）：网影播放的解码核心。`影播开` 用影匣解卷、取首画面轨的帧列与宽高，时长取末帧时刻加一帧之期；`影播取` 按毫秒找应显之帧，用影格从最近的关键帧逐帧解到目标帧，同一帧再问不重解、倒退时重解，交出解码位置与当前帧的红绿蓝透明像素。影匣与影格是现成的网影解封装与 VP8 解码，影戏与浏览器共用这一份核心。
- 媒体态（篇象）、媒体宿主（网页榫卯）与绘制（设色）接上画面：宿主新增第三术「开影」，按字节串与类型开视频解码器（影像宽高、时长与按毫秒取画的术）；媒体态保存解码器与当前帧画面，`video` 元素的载入先问开影，开得成时以解码器的时长与尺寸载入并解出首帧，播映中每推进一拍按当前时铺一帧；设色的视频图读器先取当前帧造图像，没有画面时才退回 poster，`object-fit` 仍由图像显示项处理；`videoWidth`、`videoHeight` 与布局的固有尺寸都取解码器的影像宽高。浏览器计时间隔在有视频在播时取十六毫秒，其余仍按音频的二百五十毫秒。媒体接线在装媒体节时登记媒体态，浏览器计时更新里的自动播放与时钟推进据此找到元素。

## 动专四（MP4）与开媒（AV1）播放（2026-10-24，钩深影播第二项）

- 新模块「动专四」（`库/群书/丹青部/影匣/动专四。豫`）：按 ISO/IEC 14496-12 与 14496-14 读 MP4 的文件类型盒、影片盒、轨盒、媒体盒、媒体信息盒与样本表（样本描述、时间到样本、样本尺寸、样本到块、块偏移、同步样本），按块与样本表从 mdat 截出样本，摆成与网影同一套影匣卷／轨／帧：轨号取轨道头、时间尺度与时长取媒体头、声画类别看处理器、编码四字与宽高、采样率、声道取样本描述首项，编码配置盒（`av1C`、`esds` 等）的内容作私有数据（`av1C` 去掉四字节记录头，只留配置单元），帧时刻由时间到样本表累加换成毫秒。分片 MP4（`moof`、`traf`）留待后续版本。
- 新模块「媒解」（`库/群书/丹青部/影播/媒解。豫`）：开媒（AV1）的播放解码位置，按毫秒找应显之帧、从最近关键帧逐帧交开媒影解流，同帧不重解、倒退先清态再重解；清态后的第一帧把编码私有数据接在样本前。开媒影新增「开媒清态」清参考帧、序列头与概率三匣。
- 共用类型与取帧帮手抽到新模块「播式」（`库/群书/丹青部/影播/播式。豫`）：影播画、影播卷、影播应、影播键。原先媒解要导入播、播要导入媒解，成了包内模块环。
- 影播改按容器分派：`影播开` 先试影匣解卷（可扩展二进制标记语言的文头），不成再交动专四解卷；`影播卷` 增编码四字与编码私有数据；`影播进` 按编码分派到影格（VP8）或媒解（AV1），`影播取` 倒退时对开媒轨先清开媒影的三匣。
