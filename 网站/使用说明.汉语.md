# 官网与共用界面

主站由 Jekyll 构建，源码浏览器由豫言生成器构建。旧 `/文档/` 页面已删除，不提供重定向；文档导航直接进入包管理器的标准库文档。包文档生成器仍保留供发布包使用。共用资源唯一来源为 `网站/共用/`：`主题.css`、`界面.js`、`示例.mjs`。试写间和包管理站在检查配置、开发或部署前执行 `npm run 准备界面`，将资源复制到各自静态目录；这些副本不提交。

导航的「豫言」链接到主站，站点名称链接到各自首页。默认汉语，顶部可切换文言。URL 的 `lang=han|wen` 优先，其次是 `yuyan_lang` cookie，最后为汉语。线上 cookie 使用 `Domain=yuyan-lang.org; Path=/; Secure; SameSite=Lax`，因此子域共享偏好；本地预览使用当前主机 cookie。偏好只有语言值，不含身份信息。移动端导航可展开，切换按钮反映当前状态。

主站内容使用 `data-han` / `data-wen` 对应文案。已存在双语原文的教程与指南切换到同一篇的另一版本；代码、类型签名、源码注释和原始日志保持原文。原文区用 `data-原文` 标注，自动翻译只匹配可信界面词典；缺少译文的内容保留原文，不伪造译本。

`工具/网站资料生成/入口。豫` 从文档生成教程与指南页面，正文不另行维护。运行：

```sh
./yy_bs_stable 工具/网站资料生成/入口。豫 -o /tmp/yy网站资料
/tmp/yy网站资料
mkdir -p 网站/教程/示例
cp 文档/豫言赋/示例/* 网站/教程/示例/
jekyll build --source 网站 --destination /tmp/yy网站预览
```

共用界面测试：执行 `npm ci --prefix 网站 && npm test --prefix 网站`；临时依赖可通过 `YY_DOM_MODULE` 指定模块入口。测试覆盖默认语言、切换回原文、跨子域 cookie、动态状态和原始日志保护。首页三例须实际编译运行。发布由本地豫言程序手动执行，先生成双语正文，再生成接口文档和源码树。

包管理首页只在浏览器请求 HTML 时呈现；根路径的 JSON 请求、`/health`、下载和发布接口仍按原协议工作。首页不宣称提供尚未实现的包搜索或上传表单。

主域名直接由 Cloudflare Workers Static Assets 提供 `dist/网站` 中的完整静态站，不再代理 GitHub Pages。`入口/发布配置.jsonc` 保留既有域名绑定，不含 Worker 脚本。显式保留 `.html` 地址，目录首页由 `_redirects` 重写；`_headers` 设置响应头。网站不使用 GitHub Actions 构建或发布，也不需要仓库部署 Secret。

## 文档命名与旧地址

仓库文档使用 `.汉语.md` 或 `.文言.md` 后缀；同篇两种语言使用相同的中文基名。《豫言赋》不再使用 `.现代汉语.md`，文言篇也不再省略后缀。`AGENTS.md` 保留工具约定的入口名；`yuyan-vscode` 与 `*_v0` 目录遵循仓库既有例外。`npm test --prefix 网站` 检查受版本管理的文档及待加入的新文档，防止旧命名再次引入。

网站生成器读取规范后的源文件，为教程和指南设置同篇双语链接，并生成旧 HTML 地址的跳转页。重建时应先清理 `网站/教程/`、`网站/指南/` 中的旧生成副本，再生成页面；这两处不保存手写正文。编译流程与相等性检查旧笔记已注明历史性质，当前语言行为以语言规范与实现为准。

## 手动构建与发布

在仓库根目录执行。先按[快速开始](../文档/快速开始.汉语.md)准备 `yy_bs_stable`，安装 Node.js/npm、make、clang，以及 Ruby/Jekyll、kramdown-parser-gfm 和 jekyll-sitemap（例如 `gem install jekyll kramdown-parser-gfm jekyll-sitemap`）。工具使用 macOS/Linux 的标准命令。

```sh
./yy豫构_stable 构建 网站发布 --编译器 ./yy_bs_stable --输出 yy网站发布
./yy网站发布 构建
./yy网站发布 检查
# 本地预览 dist/网站 并确认内容后再发布
npx --yes wrangler@4.129.0 login
./yy网站发布 发布
```

不带参数显示帮助。构建会依次运行界面测试、编译生成器、清理并重建 `网站/教程`、`网站/指南` 与 `dist/网站`，然后检查必要产物。任何步骤失败都会停止。首次完整构建可能较慢；构建期间不要同时运行另一个编译任务。

“发布”检查必要文件后，只上传现有 `dist/网站`，不会重新构建；修改源码后应重新执行“构建”。首次用 Wrangler 登录，以后的发布复用本机登录；也可由本地环境提供 `CLOUDFLARE_API_TOKEN`，不要写进源码。推送分支不会触发网站发布。
