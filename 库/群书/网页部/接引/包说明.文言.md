# 网页载入

载页受页面接口之主录（采书之交换、本地与会话之簿、持久之诺），设共享脚本之境时，先绑 `document`，次装窗位、页面诸器与网页剪拖，页脚本由是得 `DataTransfer`、`ClipboardItem` 与 `navigator.clipboard`。试与无壳之场，用「网页榫卯」之 `无壳交换`、`新储籍簿` 及 `页面空持久` 以充主录。

外部常篇与模块本篇循 `integrity` 之属验原始资源字节，验合乃依脚本之类解之；完整性不合则循旧载败之路记而越之。

模块本篇及所依皆用八位统一码。常外篇与样式之资，先取字节序标，次循资源编码标签及媒体牒之参数，终用八位统一码；传输编码之空值可越而求后。承自应用之远程字体，仍归原集之读取器；页面新字则循页面之源。

资源之藏去请求之片段，以请求与应答终址共其主体，还资则存本次之片段；读败者容后复求。一页惟立一藏，样式、图像、字体与脚本皆自是一藏取之。应用与页面之字面合而序其身份，藏字据此辨源。

文档既析、样式与脚本未取之先，先为预取：扫 `script[src]`、`link[rel=stylesheet]` 及 `img[src]`，依网址之所出而分群，每群同时至多三连而取；衣样既得，展其中之 `url()` 及 `@font-face` 之源，依同一之法复取一轮。预取惟实其藏，后之同步读取撞键即还。预取以「网页预取开」为开关，缺省开之，同源之限三：十月二十三日于 pit-mac 以六、三、二各量首载六次取小，三为最速（九秒〇六），二次之（九秒九七），六又次之（十秒六七），闭则十二秒四六；执行器之域名解析既有进程内之藏，并发之握手亦不复中断。闭其开关，则惟留一页共藏而不预取。脚本之取与行循文档载入之规：常篇依文档之序，延后之篇于解析毕后依序，异步之篇取到即行。模块所依之图，预取已接：得其源码，先依字面轻扫「from」及「import」二辞，以其后之符析为绝对之址，依同一同源之限并发取之入共藏，乃自藏取回已取之篇、展其下层，层数由「网页预取层限」限之。此路缺省闭之（层限零）：十月二十三日于 pit-mac 以同源之限三交替配对量首页十二次，开者六度皆慢（逐对多〇点三至五点二秒，中位多一九秒；最小九五三八对七九〇二毫秒），盖模块之文多不逾百毫秒，每批并发皆开新连而握手二百至四百毫秒，复用一连逐条而取者更速；俟连与握手更廉，启之即行。

传输编码受标签及全媒体之牒；依次析其参数，引内分号与反斜线之引皆存，首见 `charset` 则用之。模块之载受绝对网址与 `/`、`./`、`../` 之径，裸名留待后续；以应答终址为模块之识及后引之基，页面常篇与模块所依共用一页之藏。

普通页面脚本成或异而终，行微任务检查点（「网页微役察点」：捷思期约之作业与文档之微任务），使脚本所排之微任务先于后续脚本毕；回调之异循文档任务诊断。

外篇存应答之终址，模块相对之引依转向后之址而解；执行诊断亦以终址告之。脚本未承之异按籍取真而述其文：误物则名与消息，余值则其字面；取之不得则书 `<未取回:键>`，不复默退为裸键；主自抛之文仍其旧。有抛点则诊断冠以“网页脚本：地址:行:列：”，行、列为抛点于脚本源码之位；脚本所抛之值与引擎之异文皆经捷思祸位之籍而取抛点。祸值与祸位之探皆不删其籍：一异于网页之侧数问之（误文、行、列、诊断），删则惟首问有果，其后前缀与原语皆空。行每段脚本之前以址授捷思（`急就设源址`），误物之 `stack` 故带此址。

`行网页脚本资` 依调用者所授之序于共享捷思境行脚本，还诸脚本之地址、可选结果及诊断；载入之败及脚本之异各记之，后续脚本续行。每段脚本之故亦为 `error` 之事，派于篇上：事带 `message`、`filename`、`lineno`、`colno` 四数据，`error` 留空；页之 `window.onerror` 与 `error` 之听由此受之；事之处理器与定时之回调中所抛之异常亦由同一报误之路，依页之址与零行列派为 `error` 之事。常脚本全段而行；模块脚本以脚本之址为规范键，经「网页篇载器」（说明符依引用者之址而析、源码经页面资源之读取器取之而解码、皆严格）载其所依而后行。「行网页篇脚本」先行不延后之常脚本，乃依文档之序行延后之常脚本与模块脚本，终于文档派 DOMContentLoaded 与 load。导入之映射、裸说明符、页面解析之阻及安全之检，留待后续之版。

`载网页脚本` 依文档之序收内嵌及外部脚本，解相对地址，复用资源缓存及文本解码。诸项存地址、可选正文、外部、异步、延后及模块之标；载入之败以空正文记之。捷思媒体之名通大小写，兼收旧牒；无类型则取 `language` 之属，明定类型则涤首尾之白，`module` 守本字。模块既具，带 `nomodule` 之常篇不采。内嵌常篇守其常序，外篇 `async` 先于 `defer`，异步模块列于先行之队。解析之阻、依就绪之异步调度及安全之检，留待后续。

静态载入受应用所授资源读取器，读取器次收其绝址与此次取资之目的（样式、图像、字体、脚本、文档），依址还最终地址、原始主体及编码之名；目的随请付采书之主法，内容之策按所对之令而核。载入器析文档与首基址，依视口条件载内联及外链之样，装配计算样式与图像读取器，图像读取器依视窗宽高及像素之比自 srcset、sizes 与 picture 之 source 择当前图源，成布局及绘制。资源依地址藏之，图像及矢量图诸资源同由读取器取之。页面结果存地址、基址、文档及页面图。

读样、装字、排版与绘形这一段别立「排绘网页」：受带藏之读取器、字体之集、样数之境、语、资源终址、基址、视口宽高与既析之文档，还静态之页；「载网页带篇理」与浏览器之渐进重排共之，后者以只读藏之读取器易之，故样式或图像未至则缺而画、至则补之。页图缺省不含固着之素，浏览器交窗别叠片层；「网页页图含固着」置阳则出图之先把固着之素依位叠还页图，截屏与网平测据此见固着之素。

接口之行依网超组超文本标记之文档载入与网址解析算法渐接之。网络及文件之访由应用授，纯算之路诸后端共之。

外链样式依响应之最终地址递归改写 `url()`，含嵌套规则、变量之值及字体来源。内联及文档样式之计算值依文档基址改之，节点原始之属存焉。背景图遂循所属样式表之地址，重定向后之样式表依最终地址读相对资源。

展有效媒体、支持条件及层规则而集 `@font-face`，合应用已有字面，成独立页面字体之集。远程来源网址依所属样式之址析之，字体字节循页面资源之藏按需读之；本地字体循应用本地之源取之。页面结果存字体之集，供后续布局及绘制复用。

「嗅探网页码」先字节序标记，次所支持之传输编码，次元声明，终缺省编码，以择文档之编码。元声明预扫首千二十四字节（超文本标记包之「预扫码」，行于字节，循规之预扫之算），受 `charset` 及有 `content-type` 令之 `content`；十六位统一码元声明取八位统一码，用户自定编码取轩窗西文编码。缺省用八位统一码。「解网页篇」依所择编码解之；样式诸资源仍依各自传输编码。依据：[超文本标记规范13.2.3.2](https://html.spec.whatwg.org/multipage/parsing.html#determining-the-character-encoding)。

`image-set()` 及 `-webkit-image-set()` 之字符串候选，循所属样式表之终址，展为绝对 `url()`；候选之分辨率、类型与嵌套图像函数皆存。所成网址之串，饰双引、反斜及换行。

后续事项：父文档编码继承、迟至声明复启、字体载入之态及异步复排、脚本调度、安全策略、导航历史及异步资源失效。
# 文档脚本之境

「行网页篇脚本」为既成文档设页面脚本之境，以 `document` 绑定此文档，依文档基址收资源，于共享之境行普通脚本。其返者为环境、文档绑定及诸项执行之果；脚本改节点，则原文档随之。「载网页」于文档既解、读样式与渲染之前，行页中之常脚本（内嵌及外部，依文档之序），脚本所改入于渲染，诸故逐印而照常渲染；「载静态网页」不行脚本，二者共用「载网页带篇理」。三者皆于载前以所与视口宽高经「设网页窗尺」书为脚本所见之窗尺与观察之视口，版视口取同一对数，宿主由是不必别书一套；「载网页静」与「载网页」同，惟不派载入之事，网平测脚本之行者由此路。每脚本之步数上限取「网页脚本步限」（默认十亿），事件之听与定时器之回调亦取之。定时器由库「网页榫卯」之定时器模块录之，宿主依页面之时钟行之。解析时之调及安全之策，留待后版。

页面接口之主带「媒体」一项：接引以主者原样交「安装网页接口」，由榫卯媒体之接线书于篇象媒体主之匣；无壳之试用「无媒体宿主」充此一项。

## 内嵌之框

「载网页」于页面脚本既毕、读样式与渲染之前，以篇中之 `iframe` 各载为一子游之所：`src` 依父篇之基址析为绝址，`srcdoc` 取其内嵌之源码，皆无则载空白之篇。子篇由同一载页之途递归而载，自其脚本、自衣其样而排版；父篇记每框之子篇、址、父与顶之窗、脚本之境与文档之绑定。子篇读不得（网之误、解之败）者依载败收场：框中载一空白之错页，子篇之窗与文档如故而出，`load` 事派一次；框录仍记所请之址与内嵌之文，故再读 `contentWindow`、`contentDocument` 认为同一次之载，不复载之。子页初排之尺寸取宽高之性（缺者三百乘一百五十）；父篇排版之后，绘之排版钩依每框实际内容之盒宽高再排一次、生图，子图依内容之盒原样而入，不别缩放。命中于父篇显列得框之后，以点换为子篇视口之坐标，再于子篇显列求中，故指针落于子篇之节。嵌套至十层。

`loading="lazy"` 之框以懒载处之：装篇之时先记于待载之懒籍而不载，排后与页卷之后各一查，框入视口三千里之内乃载（未登几何之源者依旧载之）；`loading` 亦装为活读，改为他值或去之则即查一遍，故改为 `eager` 者当场而载。待载之懒籍于顶层载页之时清空。

子页之窗装 `parent`、`top`、`frameElement`、`frames` 与长；父篇框节之函装四活读：`contentWindow` 每现取框录之窗物，`contentDocument` 惟同源之时与子篇之函（`about:blank` 与 `about:srcdoc` 算承父篇之来源），`src` 与 `srcdoc` 读内容之属、写入则改属而排一次延后之载。脚本书 `src`、`srcdoc` 或删其属之后，再读其内容或待一次页面漏刻，框即依其时之属重载。动态新造之 `iframe` 于其函新造之时即装四读：所属之篇每读而循父现取，故未入篇之框所读皆空、入篇之后复读则按需而载；其载排于页面漏刻，待今务毕、属备而后载。框节之函别有 `sandbox` 词元列（`length`、`value`、`item`、`contains`、`add`、`remove`、`toggle`、`replace`、`supports`、`toString`，实时读写 `sandbox` 之属）与 `getSVGDocument()`（同源而子篇之根为 SVG 则与子篇，否则空值）。窗之具名访问依读名时之全局之物现查本篇：带 `id` 或 `name` 之节入篇之后即以名取之，裸名与 `window.名` 之性访二路归一，父篇与诸子篇各查其份。子页脚本载时即读得 `window.parent`。`postMessage` 由「嵌页投术」依受者分派，父投子、子还投皆达对方，`message` 事带 `data`、`origin`、`source` 与 `ports`；跨源惟由此路。框载毕乃于框节之上派 `load`；址析不出或方案不受者，依 `about:blank` 载空篇。跨源之异进程隔与子页之滚留待后日。

## 动态取资

载页之时为篇装取资之钩（见网页榫卯「取资钩」）：页中脚本行时动态所入之外链脚本、图与图标之链，由榫卯之侧认节、去重、核策而排漏，取回之后以脚本之帛还于本篇之境而行，有误则依载页时静态脚本之同一路报之；图与图标之链取回则记其帛、派 `load`。装钩之后另扫篇中已有之图与图标之链，标记所书者亦由此始取。元素之函 `srcdoc` 与 `src` 同反射于内容之属，脚本先造框、后设 `srcdoc`、乃入树者亦载得出内嵌之源：框之读器于其函新造之时即装，所属之篇每读而现取，入篇而复读或改属则按需而载。

`loading="lazy"` 之框以懒载处之：装篇之时先记于待载之懒籍而不载，排后与页卷之后各一查，框入视口三千里之内乃载（未登几何之源者依旧载之）；`loading` 亦装为活读，改为他值或去之则即查一遍，故改为 `eager` 者当场而载。待载之懒籍于顶层载页之时清空。

子页之窗装 `parent`、`top`、`frameElement`、`frames` 与长；父篇框节之函装四活读：`contentWindow` 每现取框录之窗物，`contentDocument` 惟同源之时与子篇之函（`about:blank` 与 `about:srcdoc` 算承父篇之来源），`src` 与 `srcdoc` 读内容之属、写入则改属而排一次延后之载。脚本书 `src`、`srcdoc` 或删其属之后，再读其内容或待一次页面漏刻，框即依其时之属重载。动态新造之 `iframe` 于其函新造之时即装四读：所属之篇每读而循父现取，故未入篇之框所读皆空、入篇之后复读则按需而载；其载排于页面漏刻，待今务毕、属备而后载。框节之函别有 `sandbox` 词元列（`length`、`value`、`item`、`contains`、`add`、`remove`、`toggle`、`replace`、`supports`、`toString`，实时读写 `sandbox` 之属）与 `getSVGDocument()`（同源而子篇之根为 SVG 则与子篇，否则空值）。子篇载时依 `sandbox` 之属析沙盒之旗（脚本、同源、表单、弹窗、顶层导航、顶层导航凭用户之动、弹窗逃逸、情态、下载、存储、指针、呈现、取向、协议），与本篇之旗相并而付子篇：未许 `allow-scripts` 者子篇之脚本不收不行（`脚本载` 读今之旗）；未许 `allow-same-origin` 者子篇之源不透明，`contentDocument` 与 `getSVGDocument()` 与空值，其见之父与顶易为受限之观（`postMessage` 依旧投于真窗，`document`、`location`、`frames`、`length`、`top`、`opener`、`frameElement`、`localStorage`、`sessionStorage` 与 `indexedDB` 一取即报 `SecurityError`），`document.cookie` 读写皆报 `SecurityError`。未许 `allow-modals` 者 `alert`、`confirm`、`prompt` 即还。窗之具名访问依读名时之全局之物现查本篇：带 `id` 或 `name` 之节入篇之后即以名取之，裸名与 `window.名` 之性访二路归一，父篇与诸子篇各查其份。子页脚本载时即读得 `window.parent`。`postMessage` 由「嵌页投术」依受者分派，父投子、子还投皆达对方，`message` 事带 `data`、`origin`、`source` 与 `ports`；跨源惟由此路。框载毕乃于框节之上派 `load`；址析不出或方案不受者，依 `about:blank` 载空篇。跨源之异进程隔与子页之滚留待后日。


内嵌之源之框（`srcdoc`、`about:blank`）本无其址：载框之前以父篇今之基址记于待继之所，载页之首取用而清之，故子篇之 `document.baseURI` 与相对之址皆依父篇之基址；子篇之参照策仍父篇所记之策，不复以（空）合成之应首掩之。载框前后暂存父篇之策、载毕书还，故同页他框与父篇漏中之取皆依父篇自记之策而发。载页之时以应首之 `Content-Security-Policy` 与 `Content-Security-Policy-Report-Only` 书于页面笔谈与违规境，篇首 head 中 `meta[http-equiv]` 之同名策亦于脚本未行之前并入，head 之外之元不行；脚本与诸资即依此策而断；无此二首之页清其旧境，免循前页之策；源文之框仍循父篇之境的。为内容之策所禁之内辞脚本，惟派 `securitypolicyviolation`，窗上不派 `error` 事，载页之时惟留诊断一行。
