# 网页载入

页面载入接受页面接口宿主（抓取交换、本地簿、会话簿与持久回调），建共享脚本环境时依次绑 `document`、装窗口位置、页面接口与网页剪拖，页面脚本因此得到 `DataTransfer`、`ClipboardItem` 与 `navigator.clipboard`。测试与无壳场景用「网页榫卯」提供的 `无壳交换`、`新储籍簿` 与 `页面空持久` 填宿主任录。

外部普通脚本与模块根脚本按 `integrity` 属性校验原始资源字节，通过后按脚本类型解码；完整性失败沿既有加载失败路径记录并跳过执行。

模块根脚本和依赖固定采用八位统一码。普通外链脚本、样式等资源以字节序标记优先，其次采用资源编码标签或媒体类型的编码参数，缺省使用八位统一码；传输编码参数中的空值可继续查找后项。继承自应用的远程字体保持原字体集合的读取器，页面新增字体由页面资源读取器取得。

资源缓存以去除片段的请求地址和响应最终地址共享主体，返回资源保留本次请求的片段，读取失败允许下次重试。整页只建一份缓存，样式、图像、字体与脚本都从它读。应用字体与页面字体合并后统一编排字面身份，字体缓存据此区分来源。

文档解析之后、样式与脚本取用之前先做预取：扫出 `script[src]`、`link[rel=stylesheet]` 与 `img[src]`，按网址来源分组，每组同时至多三条连接取；样式表取回后展开其中的 `url()` 与 `@font-face` 来源，按同一规矩再取一轮。预取只填资源缓存，后续同步读取命中即返。预取由开关「网页预取开」控制，缺省打开，同源限三：2026-10-23 在 pit-mac 上让开关分别以同源限六、三、二各量六次首载并取最小，限三最快（九点〇六秒），限二九点九七秒，限六十点六七秒，关着十二点四六秒；执行器的域名解析缓存就绪后并发握手也不再中断。关掉开关时只留整页共用一份缓存、不做预取。脚本的取用与执行次序循文档载入规范：普通脚本依文档序、延后脚本解析完后依序、异步脚本取到即行。模块依赖图预取已经接入：取到模块源码后，先按字面量轻扫「from」与「import」两辞，把其后的说明符解析成绝对网址，按同一同源限并发取进同一份缓存，再从缓存里取回已取的模块展开下一层，层数由「网页预取层限」限住。这一路缺省关着（层限零）：2026-10-23 在 pit-mac 上以同源限三交替配对量首页十二次，开着六次全部更慢（逐对多 0.3 至 5.2 秒，中位多 1.9 秒；最小 9538 对 7902 毫秒），原因是模块文件多在一百毫秒以内，每批并发取都要新开连接、握手二百至四百毫秒，复用一条连接逐条取更快；连接与握手更便宜后就打开即用。

传输编码可直接给出编码标签或完整媒体类型；媒体参数按顺序扫描，保留引号中的分号和反斜线引用，首个 `charset` 参数生效。模块加载器拒绝裸说明符，接受绝对网址与 `/`、`./`、`../` 路径，以响应最终地址作为模块身份和后续相对导入基址；页面普通脚本和模块依赖共用整页那一份资源缓存。

普通页面脚本成功或异常结束后执行微任务检查点（「网页微役察点」：捷思期约作业与文档微任务），使脚本排队的微任务在后续脚本前完成；微任务回调的异常沿用文档任务诊断。

外部脚本保存响应的最终地址，模块中的相对导入以重定向后的脚本地址为基址；执行诊断同时报告最终地址。脚本未接住的异常按内部登记取回原值再转成文字：错误对象印“名称: 消息”，其余的值印字面；宿主自己抛出的异常文原样记录。有抛点时诊断前置“网页脚本：地址:行:列：”，行、列是抛点在脚本源码里的位置；脚本抛出的值与引擎的异常文都经急就的祸位登记取得抛点。执行每段脚本前把地址交给急就（`急就设源址`），错误对象的 `stack` 因此带着这个地址。

`行网页脚本资` 按调用者提供的顺序在共享捷思环境执行脚本，返回各脚本的地址、可选结果与诊断；加载失败和脚本异常各自记录，后续脚本继续执行。普通脚本整段执行；模块脚本以脚本地址为规范键，经「网页篇载器」（说明符按引用者地址解析、源码经页面资源读取器取来并解码、一律严格模式）载入依赖后执行。「行网页篇脚本」先执行不延后的普通脚本，再按文档顺序执行延后的普通脚本与模块脚本，最后在文档上派发 DOMContentLoaded 与 load。导入映射、裸说明符、页面解析阻塞与安全检查留待后续版本。

`载网页脚本` 按文档顺序收集内嵌与外部脚本，解析相对地址并复用资源缓存、文本解码。每项保留地址、可选正文、外部、异步、延后和模块标记；加载失败以空正文记录。普通捷思媒体类型忽略大小写，接受旧式媒体类型和未指定类型时的 `language` 属性；显式类型去除首尾超文本空白，`module` 保留大小写。模块环境跳过带 `nomodule` 的普通脚本。内嵌普通脚本按普通顺序执行，外部脚本的 `async` 优先于 `defer`，异步模块归入先执行队列。解析阻塞、就绪驱动的异步调度与安全检查留待后续实施。

静态载入接受应用提供的资源读取器，读取器按绝对地址返回最终地址、原始主体与编码名称。载入器解析文档和首个基址，按视口条件载入内联与外链样式，装配计算样式和图像读取器，图像读取器按视口宽高与设备像素比从 srcset、sizes 与 picture 的 source 选当前图源，完成布局与绘制。资源以地址缓存，图像与矢量图子资源经同一读取器取得。页面结果保存地址、基址、文档与页面图。

读样式、装配字体、排版与绘制这一段另立「排绘网页」：接收带缓存的读取器、字体集合、样式数值环境、语言、资源最终地址、基址、视口宽高与已解析的文档，返回静态页面；「载网页带篇理」与浏览器的渐进重排共用它，后者把读取器换成只读缓存的读取器，于是样式或图像没到时缺着画、到了再补。

接口行为依网超组超文本标记的文档载入与网址解析算法逐步接入。网络和文件访问由应用提供，纯计算通路在各后端共用。

外链样式在响应的最终地址下递归改写 `url()`，包括嵌套规则、变量值和字体来源。内联样式与文档样式的计算值按文档基址改写，文档节点原始属性保留。背景图因此跟随所属样式表的地址，重定向后的样式表沿最终地址读取相对资源。

有效媒体、支持条件和层规则展开后收集 `@font-face`，与应用已有字面装配成独立页面字体集合。远程来源网址按所属样式地址解析，字体字节经页面资源缓存按需读取；本地字体沿应用本地来源取得。页面结果保存字体集合，供后续布局和绘制复用。

「嗅探网页码」按字节序标记、受支持的传输编码、元声明、缺省编码的顺序选择文档编码。元声明预扫描前一千零二十四字节（超文本标记包的「预扫码」，在字节上按标准的预扫描算法工作），接受 `charset` 与带 `content-type` 指令的 `content`，十六位统一码元声明采用八位统一码，用户自定编码采用轩窗西文编码。缺省使用八位统一码。「解网页篇」按选定编码解码；样式等资源继续使用各自传输编码。依据：[超文本标记规范13.2.3.2](https://html.spec.whatwg.org/multipage/parsing.html#determining-the-character-encoding)。

`image-set()` 与 `-webkit-image-set()` 的字符串候选按所属样式表的最终地址展开为绝对 `url()`；候选分辨率、类型和嵌套图像函数保留。生成的网址字符串保护双引号、反斜线与换行。

后续事项：父文档编码继承、迟到声明重启、字体载入状态与异步重排、脚本调度、安全策略、导航历史与异步资源失效。

「行网页篇脚本」为已有文档建立页面脚本上下文，将 `document` 绑定到该文档，按文档基址收集资源并在共享环境中执行普通脚本。返回环境、文档绑定与逐项执行结果，脚本对节点的修改直接反映到原文档。「载网页」在文档解析之后、读样式与渲染之前执行页面里的普通脚本（内嵌与外部，按文档顺序），脚本对文档的改动进入渲染，故障逐项打印后照常渲染；「载静态网页」不执行脚本，两者共用「载网页带篇理」。每个脚本的步数上限取「网页脚本步限」（默认十亿），事件监听与定时器回调的步数上限也取它。定时器由库「网页榫卯」的定时器模块登记，宿主按页面时钟执行。解析期间调度和安全策略留待后续版本。

页面接口宿主带「媒体」一项：接引把宿主原样交给「安装网页接口」，由网页榫卯的媒体接线写入篇象的媒体宿主匣；无壳测试用「无媒体宿主」填此一项。

## 内嵌框架

`载网页` 在页面脚本跑完、读样式与渲染之前，把文档里的 `iframe` 各载成一个子浏览上下文：`src` 按父文档基址解析成绝对网址，`srcdoc` 取内嵌源码，都没有时载空白文档。子页由同一个载页通路递归载入，自己执行脚本、读样式并排版；父页记下每个框的子文档、网址、父窗与顶层窗、脚本环境与文档绑定。子页的头两次排版的尺寸取自宽高属性（缺省三百乘一百五十）；父页排版之后，绘制的排版钩按每个框的实际内容盒宽高再排一次、生图，子页图按内容盒原样绘入，不另缩放。命中在父页显示列表上找到框之后，把点换成子文档视口坐标，再在子页显示列表里命中，指针因此落到子页的节点上。嵌套至多十层。

子页的窗口装有 `parent`、`top`、`frameElement`、`frames` 与长度；父文档里框元素的包装装有 `contentWindow` 与 `contentDocument`，后者只在同源时给子文档（`about:blank` 与 `about:srcdoc` 算继承父页来源）。子页脚本载入时即读得到 `window.parent`。`postMessage` 由「嵌页投术」按接收者分派，父投子、子回投都到得了对方，`message` 事件带 `data`、`origin`、`source` 与 `ports`；跨源只走这条路。框载好之后在框元素上派发 `load`。跨源的不同进程隔离、子页滚动与活动的 `contentWindow` 读取器留待后续版本。
