# 径求（XPath over the DOM）

给网页文档树做 XPath 1.0 求值，接在 `document.evaluate` 一族后面。分两篇：

- `径求。豫`（1374 行）：纯求值。按「先摊平、再按轴走」组织——先把「篇节」树按先序摊成带下标的表（下标即文档序），再按「轴＋名测试＋谓词」逐段选。
- `径线。豫`（121 行）：DOM 接线。把 `径求` 挂到文档对象上：`document.evaluate`、`document.createExpression`、`document.createNSResolver`，以及全局 `XPathResult`（十个类型常量）与 `XPathEvaluator`。挂接点在 `网页榫卯/篇系。豫` 的 `封装网览节`（文档节点）与 `网览装窗`。

## 已做

- **值模型**：`径值`（节点集／串／数／布四格）与四个构造、`径值之数`／`径值之串`／`径值之布` 互转。
- **文档序**：`径先序` 摊平（下标即文档序）、`径序号`、`径去重`、`径按序`。
- **轴**：child／descendant／descendant-or-self／self／parent／ancestor／ancestor-or-self／following-sibling／preceding-sibling／attribute／following／preceding 十二条，另 namespace 一条按元素上的 `xmlns` 声明匹配（不造命名空间节点）。
- **谓词**：`[n]`、`[last()]`、`[position() 比较]`、`[@a]`、`[@a='v']`、`[text()='v']`、`[contains(text(),'v')]`。
- **函数库**：count／string／number／boolean／not／true／false／name／local-name／text／normalize-space／contains／starts-with／concat／floor／ceiling／round。
- **结果**：`径果`（XPathResult 的豫言形）带 `resultType`、`snapshotLength`、`snapshotItem`、`iterateNext`、`singleNodeValue`、`numberValue`、`stringValue`、`booleanValue`、`invalidIteratorState` 九员；`径表达式`（XPathExpression）、`径求值器`（XPathEvaluator）。

## 已知问题（2026-11-08）

1. **命名空间**：`namespace` 轴只收元素上的 xmlns 声明，不造命名空间节点；带前缀的名测试按「前缀:名」原样比，没做真解析；`createNSResolver` 暂回空值，evaluate 的第三个实参（解析器）不看。
2. **迭代位置**：`装结果` 没把 `径迭代取` 前进后的结果存回去，`iterateNext` 每次从首节点起；`snapshotItem` 与 `singleNodeValue` 不受影响。
3. **XPathEvaluator**：全局名字在，`new XPathEvaluator()` 的实例暂不带三方法；`document` 上有三方法。
4. **数值**：只收整数（`number('3.7')` 得 0，XPath 1.0 的双精度数用豫言整数近似），`floor`／`ceiling`／`round` 因而是恒等。
5. **前导 `//`（读码所见，待跑验）**：`径求节们` 把 `//p` 从「根」这一层起走子轴，等价于 `/p`；式内的 `//` 也被 `径式切` 当单斜杠。要改成「空段即后代或自身」。
6. **上下文与根（读码所见，待跑验）**：`径求` 收到的「根」既当上下文又当绝对路径的起点；上下文不是文档节点时，`/p` 会从上下文起算。
7. **属性节点**：attribute 轴每次临时造种类二的节点（名、值取自属性对，命名空间空），没有父链；从属性节点走父轴、祖先轴走不通，节点身份也不跨次稳定。
8. **冒烟待验**：`document.evaluate('//p', document, null, XPathResult.ORDERED_NODE_SNAPSHOT_TYPE, null).snapshotLength` 待浏览器冒烟。林纳版 `网页测速` 交叉编两次都在「最终链接」撞 119（执行器陷阱：未捕获的异常），没出新产物，冒烟记待验。
