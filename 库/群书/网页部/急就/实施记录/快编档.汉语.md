# 快编档方案（提案 00055 一汇第四步）

目标：首屏要编的捷思函数按一百个算，编译加装载压到一百毫秒以内，即**每函数一毫秒**。现状与量测见[量冶铸](../../../../../应用/度量/冶铸量/量冶铸.汉语.md)。

## 一、钱花在哪

按已量的数拆成三份：

| 份 | 现值 | 说明 |
| --- | --- | --- |
| 执行器现降级 | 几十秒 | 冷降级共享库时，执行器上千个函数一并降级；小程序（源码格式化，一万九千行源）的最终链接要四十一秒，几乎全是它 |
| 每函数固定开销 | 每函数 30–65 毫秒里的多数 | 模块装配、类型与表登记、异常侧表、栈图、重定位，逐函数各做一遍 |
| 逐条豫汇 | 每千条零点七到一点五秒 | 寄存器分配、指令选择、内联与 peephole 都在这一份 |

单元装载另算：每函数一至四毫秒、整批固定二百到三百毫秒（豫章前导）。首屏一百个函数就装一百个单元的话，光装载也要零点一到零点四秒。

## 二、三条杠杆

### 1. 单趟模板式出机器码

不建中间表示、不做寄存器分配与优化，直接照豫汇指令一条一条展开成机器码：

- 每个豫言局部固定占一个栈槽，栈槽即寄存器，取值一律 `[rbp-偏移]` 与 `[rbp+偏移]`；
- 表达式按后序写，结果放临时栈槽，不做活跃分析、不做合并；
- 不做内联、不做循环展开、不做常量折叠（字面量另算），不做 peephole；
- 栈图按固定帧算：帧里没有引用局部时整帧免记，有引用局部时按槽位记一张满图，不做稀疏化；
- 表登记、侧表与重定位照旧，但一次模块只做一遍。

预计省下每函数固定开销的大头（寄存器分配、栈图稀疏化、内联与 peephole），**每函数从三十至六十五毫秒降到五到十毫秒**；目标一毫秒要靠再把逐指令那份压到约二十微秒，只有把指令选择的常见形（整数四则、比较、局部读写、调用、返回）做成查表套模板才够，冷僻形走慢路。

### 2. 单元按批装

首屏要编的函数不一个一个成单元，按脚本或按批（如六十四个函数一批）装：

- 一批一个单元，单元里各函数各自导出，装载只做一次表追加与代码映射；
- 每函数固定开销从“一至四毫秒”摊到“一批二百到三百微秒”；
- 失败与重编的粒度仍是函数（缓存键按函数内容），只是装的时候合批。

预计首屏一百个函数省零点一到零点四秒。

### 3. 执行器预装，不现降级

页程起动时把执行器与豫章预先降级、装好（就是今天豫构交互会话的先导单元那条路），捷思脚本的函数走另一条只降客体的路：

- 冷档的几十秒整个消失；
- 页程体积与起动时间按 #409 的只读数据办法控制。

### 4. 缓存与惰性

函数第一次调用才编，编出的单元按内容摘要进缓存（脚本内容、函数身份、编译器版本、执行器摘要、目标），跨页面、跨重启命中；缓存命中时只做装载，不再编译。首屏真正要编的函数通常只有脚本函数的一成上下。

## 三、预计合起来

| 步 | 每函数 | 一百个函数 |
| --- | --- | --- |
| 今天（冷客体） | 30–65 毫秒 | 3–6.5 秒 |
| 加执行器预装 | 30–65 毫秒 | 3–6.5 秒（去掉了冷启动的几十秒） |
| 加模板出码 | 5–10 毫秒 | 0.5–1 秒 |
| 加批装 | 5–10 毫秒＋摊薄 | 0.5–1 秒 |
| 加惰性（只编一成） | — | 0.05–0.1 秒 |

结论：**执行器预装保底，模板出码与批装是能不能进一帧的关键；三者到位后首屏一百个函数约零点一秒，够用。** 模板出码要落到每函数一毫秒，得把逐条豫汇的生成做成查表套模板，先做整数与局部、调用三族，浮点、异常与闭包照现成的慢路走。

## 四、验证办法

用 `生成。脚本。豫` 造同样形状的函数（十句、约四十条豫汇），先量今天的单函数耗时，再量模板出码的单函数耗时，同一台机器、同一缓存状态各跑三遍取中位；另一头用 `量。脚本。豫` 在进程内冷热各量一次，确认模板出码没有把固定开销挪到别处。验收线：每函数一毫秒、每千条豫汇二十五毫秒、首屏一百个函数一百毫秒。
