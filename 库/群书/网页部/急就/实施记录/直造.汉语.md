# 直接造式树（提案 00055 一汇第三步，第二段）

不再拼豫言源文：在豫言里直接用译场（编译器核心）的类型构造器造出「文件定义列」与「式」，同一进程里依次走闭包、正体与笔受（出豫汇），交冶铸出原生单元。生成器是 [直造](../../../../../库/群书/网页部/急就/编豫汇/直造。脚本。豫)，样例在 `编豫汇/样例/`，对照用 [虚跑](../../../../../库/群书/网页部/急就/编豫汇/虚跑。脚本。豫)。

## 一、段序与入口

```
造文件定义列（主、源文诸函数、报）
→ 递归作树组 → 闭包作树组 → 通藏树组 → 提升藏树组
→ 纯推演正体顶层 → 正体消冗顶层
→ 单元直生篇（先写匣 常祸理定义 可无，再写匣 单元入口术召）
→ 单元产物字节（执行器状态 = 单元行者态(读行者字 执行器。树码)；臂阳；系统林檎）
→ 装入诸单元
```

- `闭包作树组` 只到「闭包环境形式」，产物里函数与环境还是一对（元组）；要再走 `通藏树组`（全局存储形式）与 `提升藏树组`（闭包形式）才是正体要的裸多参拉姆达。`理包术定义` 只认 `式节点(拉姆达抽象(多参数形 个数), 列【一条绑定的链】)` 这一种形。
- **结果怎么取出来**：单元装入后 `_start` 先调静态初始化（把各定义的闭包写进全局），再调入口函数的包装 `$入口调用`。`单元入口术召`（`网汇单元` 的匣）写成 `可有（工函数名＝空串，模块径，定义名）` 时，包装从那个定义名的全局取柯里化闭包、按公开约定逐参施用，因此它调的函数必须恰好一个参数、返回「有」。直造把「主」（顶层末句的值）与「报」（先调「主」、经 `豫言_本述数` 成文、再调宿主导入 `宿主导入：豫章：书：串→元` 印一行）都造一个参数的拉姆达，入口指向「报」。印值这一段不链豫章单元，走的是笔受的宿主导入名。
- 模块径是个常量『试一』，同时用作通藏、提升、单元直生与文件定义引用的键。**待办事项**：改取源文实际路径（见第五节末尾的议题）。

## 二、无类式的正确形（第一节的结论，照读源码与探针定）

初版照「自由变量『豫言_本加』再调用」造，走不通；正确的形是：

| 要造的东西 | 无类式 |
| --- | --- |
| 整数 | `式节点(整数节点 于 值, 罄)` |
| 参数 | `绑定变量(序数)`，序数自最近的绑定起算 |
| 顶层名 | `式节点(文件定义引用节点 于 径于 名于 序, 罄)` |
| 算术与比较 | `式节点(解析后外部调用节点无类型 于 『豫言_本加』…, 列【甲，乙】)`，笔受与网汇编基按名认 |
| 调用 | `式节点(函数调用, 列【头，式节点(参数节点 于 多参数形 个数, 参列)】)`；第二个子式是一个参数节点 |
| 分支 | `式节点(爻分支节点, 列【爻式，阳式，阴式】)` |
| 顺序 | `式节点(顺序执行节点, 列【前，后】)` |
| 函数 | `式节点(拉姆达抽象 于 多参数形 个数, 列【绑定链】)`；零参数时子列只有体 |
| 空值 | `式节点(空值节点, 罄)` |

三条要点：

1. **原语名**：`豫言_本加`、`豫言_整数减`、`豫言_本乘`、`豫言_本除`、`豫言_整数相等`、`豫言_整数大于`、`豫言_本述数` 是网汇编基认的名字；`宿主导入：豫章：书：串→元` 这类带包名与签名的名字由 `东道引召令` 生成宿主调用（`库/译场/分职/笔受/网汇编基。豫:1113`）。
2. **分支与 `<=`**：可用的比较原语只有「整数大于」与「整数相等」。`a < b` 造 `大于(b, a)`；`a <= b` 造 `大于(a, b)` 再把阳阴两支对调；`a >= b` 造 `大于(b, a)` 再对调。`===`、`==` 造「整数相等」。
3. **归值在尾位展开**：没有早退，`if (c) return A; return B;` 编成 `c ? A : B`。生成器按「尾位句列」编：跳转取其内式，分支把阳支与其余诸句各在尾位编一式，表达句居末取其值。

## 三、定位索引异常（本轮修掉的一处）

初版在 `提升藏树组` 抛「未捕捉的豫言异常：索引异常」，前五段都过，看不出崩在哪。打四段探针（递归、闭包、通藏、提升各印一行）后认出：**崩在 `今径作通术名` 于『试』**——`术提升顶层` 用它给提升出的函数起名，模块径只有一个字时它抛索引异常（『试二』『甲乙』『试一二』都照常得名）。换成两字径『试一』即通，提升段以后再没崩过。

- 根因在 `译场` 而非直造：这条路上模块径是个裸「文」，合不合规由内部的分段逻辑暗定。正常构建的径都是含斜线与后缀的完整路径，所以现网不露。
- 已提议题 **#1242**（「防错：模块径只有一字时「今径作通术名」抛索引异常」，标签「静态防错」），建议把模块径立成变体类型，或让这类“由径求名”返回「成否」；登进建议表「可失败操作返回结果」一条。
- 直造现在用常量『试一』，注释里留了待办事项。

## 四、结果（本机，林檎臂六十四）

四例结果与虚跑逐位相同：

| 样例 | 直造 | 虚跑 |
| --- | --- | --- |
| 斐波那契（fib(30)） | 832040 | 832040 |
| 阶乘（fact(10)） | 3628800 | 3628800 |
| 分支（两百走阳支、五走阴支） | 3 | 3 |
| 调用（两参函数 + 跨函数调用） | 42 | 42 |

同一台机器上，fib(30) 直造装的单元「装入」一段（含跑完 fib(30)）15.25 毫秒，虚跑「装入并运行」21,286 毫秒。四例都验通了多参函数、递归、跨函数调用、跨文件定义引用与两种比较的换支。

## 七、留档：装入陷阱 138 的根因（已修）

探针早先给 `单元产物字节` 的「臂」传「阴」（兼容六十四），本机是林檎臂六十四，单元文件头偏移十二记的指令集不对而 `单元装入` 原先不核，落成陷阱 138。修法：`装入一个单元` 先取偏移十二、经「臂名表」换成架构名，再与「本机架构」比对，不合即报出两边的名字。修好后同一份探针（臂改阳）六段全通。
