# 直接造式树（提案 00055 一汇第三步，第二段）

不再拼豫言源文：在豫言里直接用译场（编译器核心）的类型构造器造出「文件定义列」与「式」，同一进程里依次走闭包、正体与笔受（出豫汇），交冶铸出原生单元。生成器是 [直造](../../../../../库/群书/网页部/急就/编豫汇/直造。脚本。豫)，样例在 `编豫汇/样例/`，对照用 [虚跑](../../../../../库/群书/网页部/急就/编豫汇/虚跑。脚本。豫)。

## 一、段序与入口

```
造文件定义列（主、源文诸函数、报）
→ 递归作树组 → 闭包作树组 → 通藏树组 → 提升藏树组
→ 纯推演正体顶层 → 正体消冗顶层
→ 单元直生篇（先写匣 常祸理定义 可无，再写匣 单元入口术召）
→ 单元产物字节（执行器状态 = 单元行者态(读行者字 执行器。树码)；臂阳；系统林檎）
→ 装入诸单元
```

- `闭包作树组` 只到「闭包环境形式」，产物里函数与环境还是一对（元组）；要再走 `通藏树组`（全局存储形式）与 `提升藏树组`（闭包形式）才是正体要的裸多参拉姆达。`理包术定义` 只认 `式节点(拉姆达抽象(多参数形 个数), 列【一条绑定的链】)` 这一种形。
- **结果怎么取出来**：单元装入后 `_start` 先调静态初始化（把各定义的闭包写进全局），再调入口函数的包装 `$入口调用`。`单元入口术召`（`网汇单元` 的匣）写成 `可有（工函数名＝空串，模块径，定义名）` 时，包装从那个定义名的全局取柯里化闭包、按公开约定逐参施用，因此它调的函数必须恰好一个参数、返回「有」。直造把「主」（顶层末句的值）与「报」（先调「主」、经 `豫言_本述数` 成文、再调宿主导入 `宿主导入：豫章：书：串→元` 印一行）都造一个参数的拉姆达，入口指向「报」。印值这一段不链豫章单元，走的是笔受的宿主导入名。
- 模块径是个常量『试一』，同时用作通藏、提升、单元直生与文件定义引用的键。**待办事项**：改取源文实际路径（见第四节末尾的议题）。

## 二、无类式的正确形

| 要造的东西 | 无类式 |
| --- | --- |
| 整数 / 文 | `式节点(整数节点 于 值, 罄)`、`式节点(字符串节点 于 文, 罄)` |
| 参数、循环参、续延令牌 | `绑定变量(序数)`，序数自最近的绑定起算 |
| 局部量与对象的属性 | 一格 = `式节点(解析后外部调用节点无类型 于 『豫言_本置匣』, 列【初值】)`；读 `豫言_本读匣(格)`；写 `豫言_本写匣(值，格)`（**先值后匣**，见 `库/豫章/本原/匣椟。豫` 与 `洒扫运行时` 的 `$set_ref`） |
| 顶层名 | `式节点(文件定义引用节点 于 径于 名于 序, 罄)` |
| 算术与比较 | `式节点(解析后外部调用节点无类型 于 『豫言_本加』…, 列【甲，乙】)`，笔受与网汇编基按名认 |
| 调用 | `式节点(函数调用, 列【头，式节点(参数节点 于 多参数形 个数, 参列)】)`；第二个子式是一个参数节点 |
| 构造（`new F(…)`） | 当函数调用编：取其子（调用节点）交编式。本子集不造对象、不接原型，`this` 也还没有；测试架里 `new Test262Error(…)` 这类写法照常求值。虚跑还不能跑 `new`（跑它会陷阱），故未列样例 |
| 分支 | `式节点(爻分支节点, 列【爻式，阳式，阴式】)` |
| 顺序 / 局部绑定 | `式节点(顺序执行节点, 列【前，后】)`；`式节点(内联虑, 列【值，绑定原】)` |
| 函数 | `式节点(拉姆达抽象 于 多参数形 个数, 列【绑定链】)`；零参数时子列只有体 |
| 早退 | 整个函数体包一层 `式节点(续延调用节点, 列【绑定原(令牌, 体)】)`，体内 `return` 落成 `式节点(续延调用返回节点, 列【令牌，值】)` |
| 抛出 | `式节点(解析后外部调用节点无类型 于 『豫言_抛出异常』, 列【文】)` |
| 真爻、假爻、空值 | `式节点(展开后内建节点 于 内建爻阳/内建爻阴, 罄)`、`式节点(空值节点, 罄)` |
| 真值判断 | 条件位置先看「编类」：比较、取反、真伪字面、装爻的格本就是爻，原样当条件；其余（数、读格、调用结果）编成 `豫言_整数相等(值，零)` 再把两支对调（「须换」报阳），也就是“等于零则走阴支” |

要点：

1. **原语名**：`豫言_本加`、`豫言_整数减`、`豫言_本乘`、`豫言_本除`、`豫言_整数相等`、`豫言_整数大于`、`豫言_本述数`、`豫言_本置匣/本读匣/本写匣`、`豫言_抛出异常` 是网汇编基认的名字；`宿主导入：豫章：书：串→元` 这类带包名与签名的名字由 `东道引召令` 生成宿主调用（`库/译场/分职/笔受/网汇编基。豫:1113`）。
2. **分支与比较**：可用的比较原语只有「整数大于」与「整数相等」。`a < b` 造 `大于(b, a)`；`a <= b` 造 `大于(a, b)` 再把阳阴两支对调；`a >= b` 造 `大于(b, a)` 再对调；`!==`、`!=` 造「整数相等」再对调（值位置则造 `爻分支(相等, 假爻, 真爻)`）。`===`、`==` 直接造「整数相等」。
3. **归值在尾位展开**：尾位句列里，跳转取其内式、分支把阳支与余句各在尾位编一式、表达句居末取其值。只有出现「不在本块末位」的 return（`有早退` 为阳）才整段包续延；`if (a !== b) { fail(); }` 这种末位返仍走老路，短路与省栈都不变。
4. **环境列与格名前缀**：环境是「自最近者起排」的名字列。参数、循环参、续延令牌直接绑值，名字照原样；局部量与对象属性是格，名字加 `匣.` 前缀（对象属性再写成 `匣.对象名.键名`）。读到带前缀的名字就知道要先 `豫言_本读匣`，赋值与自增写那一格、写完再读回当值。对象字面先按 `匣链` 把各格绑成空格、再 `属填们` 逐个填值；`var a = 3, b = 4;` 同理（**待办事项**：多个声明的初值不能互相引用，JS 的 var 语义允许）。
5. **循环**：`造闭` 先在环境里绑一格 `↻n`，把「条件不成立就收、成立就走环体」的闭包 `↺n` 写进格，再以空值呼它；环体走完后由 `续于更` 先算更新式（`for` 的第三段）再呼格里的闭包。条件用 `条式` 并照 `须换` 对调两支，所以 `i <= 10000` 与 `i < 10` 都对。环体与条件都在 `[参, 格, 其余]` 的环境里编，捕获的外层格是同一只匣，写在环里、环外都看得见。`do-while`（「后验循环」）是「先编一遍体、再把这同一块当 `while` 的体」，体在两层各编一份，语义等于先做一次再查条件。
6. **格名、径名各是一个类型**：格的名（「匣.名」「爻.名」）立成「格名」一类，只有「匣名」「爻名」两个构造函数造得出，「格之文」取出里面的文。查格（「格处」）、读写格（「读格」「写格」）、匣链都只收「格名」。**另立「径名」**：赋值目标的名字（局部量的名、`对象.键`）是一类，经「径名之文」才取出文、再经「匣名」成格名，于是属性名与格名两种文不会互串。**这一层是防错**：把一段裸文当格名传，编译期就报「文 != 格名」——上一轮“格里存匣.流、查时用裸名流”那种静默失效不会再出现（实测：把「读格」的实参改回裸的「取匣名」结果，类型检查当场报 编式：不相等！文 != 格名）。
7. **真值判断与三种格前缀**：装爻的格用「爻.」、装文的格用「文.」、其余用「匣.」，读写格与名式都经「格处」三样一起找。条件分三路：先问「编文类」——字符串字面与「文.」格里的名字，编成 `豫言_整数大于(豫言_本计文字节(值)，零)`（文非空为真），「须换」报阴；再问「编类」——比较、取反、真伪字面、装爻的格，原样当条件；其余（数、读格、调用结果）编成 `豫言_整数相等(值，零)` 并把两支对调。于是 `if (n)`、`if (1)`、`if (b)`、`if (s)`（s 是文）都对。取反同理：文走“字节长等于零”，爻走爻分支，其余走“等于零”，不再给非爻值造嵌套爻分支（那会撞正体的合并点）。**待办事项**：格的前缀在声明时按初值定，之后若给它赋了别的类（`var b = false; b = 1;`）就说不准，得改成“赋值时查类、要么报错要么两边都按值编”。
8. **break 与 continue 走流标志＋环栈**：环体每次进入先绑一格『流』（初值零）；「编列」每条语句之后先看这格，为零才接着走。「编列」的守卫是 `爻分支(流==0, 体, 空式)`；环的续造是 `爻分支(流==0, 续于更, 空式)`，所以 break（写一）与 continue（写二）都能让本层余句停住、并让闭包不再自召。**continue 另走环栈**：造闭时把「环记」（门、格名、环境）压进编译期的匣「环栈」，编完再弹回；`continue` 取栈顶那一笔，按**环那一层的环境**编更新式、再自召（`续于更`），于是它能从任意深处接回环的“更新式＋自召”，而不会误用本层余句的续造。环记的三样各有取用的函数（环记之门、环记之格、环记之环），门与格名都带类型（急就语法、格名），环境是文列。
9. **带 else 的分支与续跑**：三分支的「分支」节点（条件、阳支、阴支）里，阴支不是余句而是第三个子节点；两支都要接同一份「续造余」（先编余句）。**留值**只在余句为空时才传给两支——否则那一支会把自己的值当整个分支的值、跳过余句（本轮踩过：`if (a < 0) { a = 0 - a; } else { a = 0; } a * 10 + n;` 少了这一步就只印 `n`）。
10. **条件里的 `!`**：`!(...甲...)` 不造嵌套爻分支（爻分支当条件是正体的合并点不认的），而是剥掉 `!`、用甲的条件式、把 `须换` 取反——两支对调即可。值位置的 `!` 仍造 `爻分支(甲, 假爻, 真爻)`，只用于真爻运算。

## 三、定位索引异常（上一轮修掉的一处）

初版在 `提升藏树组` 抛「未捕捉的豫言异常：索引异常」，前五段都过，看不出崩在哪。打四段探针后认出：**崩在 `今径作通术名` 于『试』**——`术提升顶层` 用它给提升出的函数起名，模块径只有一个字时它抛索引异常（『试二』『甲乙』『试一二』都照常得名）。换成两字径『试一』即通。

- 根因在 `译场` 而非直造：这条路上模块径是个裸「文」，合不合规由内部的分段逻辑暗定。正常构建的径都是含斜线与后缀的完整路径，所以现网不露。
- 已提议题 **#1242**（「防错：模块径只有一字时「今径作通术名」抛索引异常」，标签「静态防错」），建议把模块径立成变体类型，或让这类“由径求名”返回「成否」。
- 顺带把直造的 `种子`（取第 n 个子节点）加了越界检查：越界时报出结的种类与位次，不再抛裸的索引异常。`continue`、`break` 现在会报「跳转 没有第 0 个子；这一形还没接」这样一句。

## 六、还没接的

## 七、留档：装入陷阱 138 的根因（已修）

探针早先给 `单元产物字节` 的「臂」传「阴」（兼容六十四），本机是林檎臂六十四，单元文件头偏移十二记的指令集不对而 `单元装入` 原先不核，落成陷阱 138。修法：`装入一个单元` 先取偏移十二、经「臂名表」换成架构名，再与「本机架构」比对，不合即报出两边的名字。修好后同一份探针（臂改阳）六段全通。
