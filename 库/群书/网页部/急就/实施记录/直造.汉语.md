# 直接造式树（提案 00055 一汇第三步，第二段）

不再拼豫言源文：在豫言里直接用译场（编译器核心）的类型构造器造出「文件定义列」与「式」，同一进程里依次走闭包、正体与笔受（出豫汇），交冶铸出原生单元。探针在 `编豫汇/试/试造二。脚本。豫`，样例是一个两参数的函数（体取第二参数，`绑定变量 一`）。

## 造法与段序

```
式节点(拉姆达抽象(多参数形 二), 列【绑定(可无, 绑定(可无, 体))】)   // 一个函数
列【（『试一』 与 函）】                                          // 文件定义列
→ 递归作树组 → 闭包作树组 → 通藏树组 → 提升藏树组
→ 纯推演正体顶层 → 正体消冗顶层
→ 单元直生篇（先写匣 常祸理定义 可无）
→ 单元产物字节（执行器状态 = 单元行者态(读行者字 执行器。树码)；臂阴；系统林檎）
→ 装入诸单元
```

要点：`闭包作树组` 只到「闭包环境形式」，产物里函数与环境还是一对（元组）；要再走 `通藏树组`（全局存储形式）与 `提升藏树组`（闭包形式）才是正体要的裸多参拉姆达。`理包术定义` 只认 `式节点(拉姆达抽象(多参数形 个数), 列【一条绑定的链】)` 这一种形。

## 结论

- 前端之外的各段总计不到五毫秒，**冶铸是唯一的大头**（667 毫秒），且这一份里含执行器的并入与降级；单元本身只带一个函数，所以“每函数冶铸耗时”要拿不含执行器热身的第二、三次量才能分出（下一步）。
- `装入诸单元` 目前在本进程里以陷阱 138 结束（单元已生成、字节数正确），前八段与产物都成功；这一处要单独查（可能是单元启动时调「豫言_登记垃圾回收根」等执行器内建时的约定问题），见汇报。

## 二、装入陷阱 138 的根因（已修在源头）

**根因**：探针给 `单元产物字节` 的「臂」传的是「阴」（兼容六十四），而本机是林檎臂六十四。单元文件头偏移十二记着指令集（一为兼容六十四，二为臂六十四），`单元装入` 原先不核对这一项，把别种架构的机器码照装照跑，于是落成陷阱 138，且没有任何可读的说明。

**修法**：`豫言操作系统/裸机/库/冶铸/单元装入。豫` 的 `装入一个单元` 在读段之前先取文件头偏移十二，经「臂名表」（号与架构名唯一的一处对应：一为兼容六十四，二为臂六十四）换成架构名，再与「本机架构」（`本土产物。豫`，与「原生目标」同一套名字）比对；不合即以「告祸」报出两边的名字：

```
单元装入：单元的指令集是 兼容六十四，本机是 臂六十四；单元要照本机架构重编
```

修好后同一份探针（臂改「阳」）六段全通、退出码 0。
