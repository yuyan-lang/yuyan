# 现有消费者接线

此篇用主线既有原始收缩、泽压库、吉压一次入口，及原始与泽压库之前缀入口。包直依「压缩」，导其模块乃可召。

## HTTP 内容编码

受HTTP消息，先循消息长及传输编码取正文，乃循内容编码复其表示。Content-Encoding为gzip者，召「吉压」之「解压吉压」，授正文与最大出字节数；为deflate者，召「泽压库」之「解压泽压库」，亦授二者。数种内容编码，逆其施次而解，各层明定出限。

发端各召「压缩吉压」及「压缩泽压库」，授正文与零至九之级。状零乃取所得，定内容编码及终消息长。吉压可解相连成员、可选首字段并验之；泽压库验首及阿德勒32。

一次之果，中零为状，中一为正文。零成，一出逾限，二损坏，三为预设字典待供或术未备；败文为空。受端状零乃交正文，余状归消息解码之败。

网页套接字permessage-deflate之接线在超文本传输库「网页压缩」。其用原始收缩前缀，复同步尾，存近三二七六八字节之上下文，各消息计出限。此依RFC7692；HTTP之deflate内容编码用RFC1950泽压库封装。

## Git 对象与 PACK

版本库「压缩对象」召「压缩泽压库」「解压泽压库」治松散对象。正文含对象首及载荷，以完整泽压库入口验之。

版本库「接收包」「接收解析」于PACK今对象载荷，召「解压泽压库前缀」，授余包字节及最大出字节数。果之中零、中一、中二，各为状、载荷、食长。食长含泽压库首、压文及阿德勒32；状零乃进当前位置以其长，续读后物。前缀解留余字，以供后物及包尾之验。

Git受端今授十亿七千三百七十四万一千八百二十四字节之出限。偏移增量、引用增量之对象首，版本库先读之；解压后由其增量模块复物。出逾限、损坏及需典皆归受包之败。
