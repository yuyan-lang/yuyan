# 迅压静态收敛记录

依据 [Google Snappy 原始块说明](https://github.com/google/snappy/blob/main/format_description.txt) 与 [Google Snappy 分帧说明](https://github.com/google/snappy/blob/main/framing_format.txt) 逐项核对现有字节串接口。2026-10-08 仅完成源码静审和格式化，以下测试入口尚待统筹队列运行。

| 官方项目 | 实现与源码覆盖 |
| --- | --- |
| 压缩块 0x00、原始块 0x01 | 两类有效块、输出超限、65536 边界及 65537 损坏 |
| 可跳过 0x80 至 0xfd、填充 0xfe | 非空载荷可跳过，填充载荷直接跳过 |
| 必须识别 0x02 至 0x7f | 范围两端返回损坏 |
| 流标志 0xff | 首帧验证，合法重复、错误文本、错误长度；连接两流累计限额 |
| 遮罩 CRC32C | 完整标准向量、拆分续算、错误校验；内部种子先反转再调用共用续算 |
| 原始块长度 | 五字节至 32 位无符号上限；截断、溢出、巨大声明在分配前处理 |
| 复制一、二、四字节距离 | 三种合法重叠向量；复制长度上下界、2047 和 65535 距离上界及 65536 四字节长距；零距离、尚无历史、截断距离返回损坏 |
| 直写长度附加字节 | 一至四字节附加量均有源码向量，另含 60/61、256/257、65536/65537 与末字节截断 |

发现的最小修正：测试断言失败入口改为实际越界读取，确保断言失败可见。主体语义经静审保持原样，ABI 保持当前签名。

新增静态候选将原始编码、分帧编码和分帧解码的输出块逆序存列，按真实总长度分配一次汇总缓冲；分帧解码用累计长度核对余限。公开四个整块编解码入口签名保持原样。内部累积辅助函数改用块列。

百万核验源码增加三种合法重叠复制原始块的声明、标记、距离定点字节扰动及各位置截断，并封装成压缩帧入口。每轮同时执行随机短块和结构变异。源码执行尚待统一队列。

工具移至 `测试/全量/迅压/迅压百万变异核验。脚本。豫`。每五轮保留一个合法种子；成功原始块依据实际解码输出重算 CRC 后封帧，要求帧解码成功；将同一 CRC 翻转一位，要求状态 2 且返回空字节串。该断言源码尚未执行。

静核汇总与限额：块列总长按当前整数的六十四位宽度累计；实际超过客体数组平台限制的分配边角留待平台大数组支持，源码有待办事项。每个解帧块使用剩余限额，加入块后累计长度增加实际输出长度。负限额入口返回状态 1 及空输出。损坏与超限分支返回空输出，已解码前缀留在内部块列。

全量工具另立 `测试/全量/迅压/` 包，依赖压缩、标准库与基础库测试设施；父包登记由统筹同步。编号重放覆盖长直写与三类大距复制，并逐字节核对实际输出及末字节截断。编号 10 构造三字节附加量最大值对应的 16777216 字节直写，专门单项运行。输出限额按实际声明设置。

百万模式分别打印两类入口的实际调用计数；隔离工具的批模糊协议每批只运行一种入口，可分两批各一百万次。设施接入目前仅源码，尚未构建运行。

真实剩余差距：新增边界测试、编号重放与百万工具尚未运行；官方实现交叉互解与隔离设施接入尚待运行；按需汇总路径需实测性能；原生与裸机尚未核验。现有 API 整块接收与返回字节串，增量流输出留待统筹确认 API 方案。
