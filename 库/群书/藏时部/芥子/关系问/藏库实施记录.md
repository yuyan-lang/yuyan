# 关系库藏表（藏库）阶段性实施记录

2026-10-24，钩芥子关系。云仓提案 C00005 的芥子一路，第一阶段：SQL 的表与索引改存进芥子的页式键值库，提交只写改动的键，旧版整份快照仍可读入。

## 分工与边界

- 键值库的增量提交、检查点、前缀游标等落盘能力归钩芥子存储一路；本路只用现有接口：`构造数据库`、`启只读事务`、`启写事务`、`读事务`、`事务写`、`事务删`、`提交事务`、`回滚事务`、`前缀遍`、`域遍`。
- 本路只改芥子的 `关系问/`、`问簿/` 测试与 `豫言操作系统/适配/关系数据库通用` 的文档。
- SQL 语义仍是现有 SQLite 兼容引擎的语义；本阶段只换存储布局与持久路径。

## 键的布局

调用者给的键（帛，如『关系库甲』）之下以零字节分段：

| 键 | 值 |
| --- | --- |
| 键 零 「模式」 | 模式快照文字：结绳数组，各元素为快照记录（表、索引、视图、触发器的建立原文，次序同快照） |
| 键 零 「元」 | 最后插入行号（结绳整数文字） |
| 键 零 「表」 零 表名 零 「行」 零 行号八字节 | 一行：结绳数组 `[行号, [各列值的类型标记写法]]`，与快照的行值写法相同 |

- 行号写成八字节大端序：高四字节在前、低四字节在后，字节序即行号序；前缀遍历得到的次序就是行号升序。
- 表名前缀末尾留一个零字节，避免表「甲」的前缀误含表「甲乙」的键。
- 键段以零字节分隔，表名里出现零字节以外的字节都不与段界混淆；UTF-8 文字不会含零字节。
- 索引目前只存模式原文（模式快照里有），尚未落索引项；索引项与索引扫描列入下一阶段。

## 保存（藏库录）

1. 会话有未结束事务时报『关系库须在事务结束后保存』。
2. 按授权名与键取已存库底（库状态、键、最后插入行号）；名字未登记或键不同则当空库底。
3. 开写事务；“写事务繁忙”返阴。
4. 模式文字（`存照模式文`）与库底不同才重写模式键；最后插入行号不同才重写元键。
5. 逐表比较新旧行：两边按行号升序并进，新有旧无则写，两有而 `值列同` 为阴则写，旧有新无则删；只碰这几类行键。
6. 库底有、新库状态没有的表，按其前缀与已存行号清掉旧行键。
7. 提交；成功才更新库底并返阳，失败返阴。提交失败时写锁未解，与键值库现有行为一致。

## 恢复（藏库复）

1. 以只读事务看模式键：有则解析模式快照文字，逐个记录复原出空表、索引、触发器与视图（复用存照的 `复原结构`，会重新解析建立原文）。
2. 对每张表按表前缀做 `前缀遍`，把行记录解析成 `数据行` 后按行序灌入；`换诸表行` 重算最大行号。
3. 读元键得最后插入行号，重造会话、写入库与行号、登记授权名，并把当前库状态记为库底。
4. 模式键缺失时读旧版整份快照（调用者给的键本身）：解析成全会话，登记授权名后立即以空库底全量写成新布局；写入失败也照样返回阳（内存已恢复），库底留空，下次保存会全量重写。
5. 两处都没有返阴。

`行问簿脚本` 已能执行 `wrangler d1 export` 风格的 SQL：PRAGMA、BEGIN TRANSACTION、带引号的名字、CREATE TABLE、CREATE INDEX、成批 INSERT、COMMIT。榫合新增 `导关系转储`：先解析全部语句，记下执行篇不认识的 PRAGMA 名字，再依次执行，返回一行说明并在末尾列出略过的名字；执行出错照旧抛出。导入后调用 `藏恒关系会话` 存进藏库即可。测试里放了一份带引号名字、成批插入与一条不认识的 PRAGMA 的转储，核对返回的说明，重开后查询与唯一索引都正确。

## 第二阶段：游标、索引编码与索引维护

2026-10-24，同一任务第二轮。

### 新增

- `关系问/游标。豫`：只读事务上的薄游标。`启游标`（只读事务、前缀 → 游标）、`游标取`（游标 → 可有的键值对）。首次取时按前缀把项列一次取出，此后只移位置。底下仍是现有 `前缀遍`，等键值库的 `前缀游标` 到了换底层。
- `关系问/藏目。豫`：索引项编码、键与查询。
  - `目值帛`（问值 → 保序帛）：空 `00`；数 `01` 加八字节保序双精度（负数位型取反，非负数翻符号位）；文 `02`、块 `03` 加转义字节与双零收束（零字节写 `00 FF`）。
  - `藏目前缀`、`藏目行键`（前缀＋编码值＋八字节行号）、`藏目册们`（可取索引的册：所属表在、无条件、各列无校对）、`藏目点`（等值，按编码前缀一次取回行号）、`藏目范`（范围，一游标按下界、上界早停）。
  - `藏库删目行`、`藏库写目行`、`藏库建目行`、`藏库清目行`：索引项的删、写、整表建、整表清。
- `藏库录表` 改为同时维护索引：两版都有的索引按改动行删旧写新；新版新增的索引整表建项；旧版有而新版无的索引整表清项。`藏库删表` 同时清旧表索引项。
- 测试 `测试/关系查询/藏目。测试。豫`：编码序（空、负数、零、正数、文、块混排逐对比字节序与值序）、二千行两索引的项数、等值取行号、范围取行号、改行/删行后的增量维护、重开后数据与索引都在。

### 修掉的旧缺陷

`写四字节`（键值藏）是**小端**，第一阶段的行号键用它写高、低两半，实际不是大端：行号过二五五之后前缀遍历不再按行号升序。本轮在藏库与藏目各加 `藏库大四`／`藏目大四`（真大端）与对应读取，行号键已改成真正八字节大端。旧数据（第一阶段写的）不再可读，尚无生产数据。

### 规模与耗时

- 二千行、两个索引（四千索引项）：首存加全部检查约二十三秒（pit-mac，经将作）。
- 五千行与两万行：初存逐项线性插入加自写归并排序，分别在十一分钟与约两分钟被系统杀掉（`Killed: 9`，内存与时间都撑不住）。**二十万行验收等批量写接口。**

### 已收到的键值接口（尚未合入本树）

- `事务写删批`（写事务、批 → 爻）：批项为 `（键 与（可有 值））` 写入／改值，`（键 与（可无 帛））` 删除；可乱序、内部排序去重、同键后写遮前写。
- `事务删界`（写事务、起、止 → 爻）：删 [起, 止)。
- `前缀游标`（只读事务、前缀、起（可有的末键）、最多 → 键值对列）：按键升序；下一批「起」传本批末键，严格大于；空列即尽，逐条取「最多」传一。

变基后改三处：游标底层换 `前缀游标`；保存与初存换 `事务写删批`；删表、删索引、清范围的逐项删换 `事务删界`。之后再做执行篇、推演篇按游标扫表与二十万行验收。
