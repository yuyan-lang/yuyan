# 域名全量验收准备

官方驱动覆盖 Unicode、非过渡 ASCII 与过渡 ASCII 三个模式，选项分别为 15、47、63。所有可表示的官方行都比较转换内容和错误标志。UTF-16 单独代理码点依官方说明跳过并计数。

驱动比较错误码集合是否为空，并在失败诊断中保留官方完整状态串。IdnaTestV2 文件第 97 行允许实现只报告是否有错，无须复现精确状态码。因此当前公开接口的错误爻可以用于官方一致性验收；驱动没有逐项证明 P4、V7、Bn、Cn 等精确原因集合。

源码按处理步骤补强了两个规则：ToASCII 从 Unicode 阶段的完整转换内容重新切分标签；IgnoreInvalidPunycode 只容忍解码异常，ACE 原文含非 ASCII 字符与成功解码为空或 ASCII 的错误仍被报告。ASCII 点号在 Punycode 载荷中按字面保留，域名处理先将它识别为分隔符。新增协议样例须在恢复验证后核验。

`测试/全量/域名百万变异。测试。豫` 默认执行一百万轮，默认种子 20261007。可传“次数”和“种子”缩小复现。变异覆盖插入、删除、替换、重复点号、连接符、62 至 65 字符标签、双向混排与随机统一码标量。每轮检查 UTF-8 与 Punycode 往返；域名转换成功时检查基本转换幂等性和统一码往返；严格转换须拒绝零字节与超长纯 ASCII 标签。失败打印轮次、随机状态与完整码点序列，使用“一轮、该状态”可重放失败输入。

2026-10-08 已在 pit-mac 使用最新 25a 完整工具链完成类型检查、官方全集与千轮变异，结果见《域名验收记录.汉语.md》。百万轮持续运行。域名原始数据位于仓外 `豫言数据/统一码/18.0.0/`。

后续静态审查按 RFC3492 附录 C 发现首位置分隔符的处理问题：仅当分隔符前已经复制基本字符时，解码入口越过分隔符。首位置 `-` 仍由数字读取拒绝。该修正对应官方第 551 行 `xn---` 的原文保留与错误标志，已通过官方全集。
