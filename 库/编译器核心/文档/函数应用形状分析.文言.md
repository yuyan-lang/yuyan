# 函数应用隐式参数求解

其实现见 `编译步骤/类型检查/函数应用隐式参数合成。豫`。此阶段惟答一问：一次函数调用中，哪些未写出之隐式类型实参，可由现有信息唯一确定？

## 顶层接口

`求解函数应用隐式参数` 接收命名环境、完整调用表达式、函数头类型、源参数脊与可选之期望结果类型，返回：

```text
列 表达式
```

返回列惟含须自动插入之隐式类型实参，并保其于函数类型中之出现顺序。函数头、参数规划、合一上下文与结果类型，皆不返回。

- 合成模式传入 `可无`，故不可自结果类型取信息。
- 检查模式传入 `可有 T`，故可以 `T` 接地隐式参数。
- 用户已写出之隐式类型实参，不出于返回列中。

## 可用于求解之信息

每个隐式绑定，皆先实例化为本次调用独有之新鲜类型变量，登记于 `var → optional expression` 之模式合一上下文中。用户显式写出之隐式参数，立记为该变量之 `Some expression` 解；缺省、待推断之隐式参数，初记 `None`，候普通实参或结果类型接地之。键不存在，表该名非本次待求变量。惟缺省变量记于最终返回列。求解器惟读下列信息：

- 用户写出之隐式类型实参。
- 普通实参为自由变量，则自命名环境径读其类型。
- 普通实参为文件定义引用，则自文件定义径读其类型。
- 检查模式中之期望结果类型。

λ 式、函数调用等复杂普通实参，不参与推断，留予后续常规类型检查。如此可免为合成隐式参数而递归预检实参。

每条可用信息，皆惟作单向合一（matching unification）：左侧类型可含上下文中登记之变量；右侧对此诸变量必为接地（ground）。匹配成功，方提交新 `var → expression` 解；任一子结构不匹配，则整次匹配回滚，求解阶段不报参数类型错误。真错误由重放检查报之。求解既毕，再以全部参数信息与可选结果类型，检一切待求变量是否已接地。

模式合一径复用原有结构比较递归，并以同一 `串典` 上下文随递归传下。普通节点仍循原规比较；惟比较遇左侧自由变量时，方查上下文：未登记之变量仍须两侧同名；已登记而未解之变量，写 `Some 右式`；已有解者，则以该解续与右式比较。全过程不预“应用上下文”，亦不执行表达式级局部替换；求解既毕，径自 `串典` 读各隐式参数之类型表达式。

求解器不读或应用此上下文以改写当前函数类型。外层调用检查先沿函数头原始类型骨架，拆出当前参数组；当前组检毕，常规依赖类型替换给真实结果类型；若源参数脊尚有剩余参数，则以该结果为新函数头，续检下一组。如 `readRef : {A} -> Ref A -> A` 先惟检 `readRef ref`；若 `A` 接地为 `X -> Y`，再以此结果检后续参数。如此无须设“惟读顶层已解变量”之特支。

## 完全应用语义

函数名本身仍可为函数值。惟语法树已入函数调用节点时，方要求本次调用完全饱和：

1. 遇隐式派类型与源隐式实参，则消费该实参。
2. 遇隐式派类型，而下一源实参非隐式实参，则为该位创待求解之隐式参数，不消费源实参。
3. 遇函数原始类型骨架中之箭头，必消费一源显式实参；源参数已尽，则报不许部分应用。
4. 当前类型已非函数，而源参数尚有剩余，则报参数过多。
5. 遍历既毕，仍有隐式类型变量未定，则报无法完全确定隐式参数。

裸函数名于检查模式中，可用期望箭头类型接地前置隐式参数，后停于箭头类型上，作为函数值。此非源码部分应用；然 `f [String]` 已为调用节点，仍须补足后续显式参数。

完整调用之结果，本身可为函数值。如 `readRef ref` 已消费 `readRef` 之全部参数；若引用中所存为函数，其结果类型仍为箭头，然此非部分应用。外层检查器将扁平源码参数脊重建为 `(readRef ref) arg`，不误传 `arg` 于 `readRef`。

故若 `f : {A : Type} -> {B : Type} -> X -> R`，则：

- `f [String] x` 可自 `x` 之直接可读类型或期望结果类型推断 `B` 时，成立。
- `f [String] x` 无法确定 `B`，则报错误，不返保留 `{B}` 之部分应用类型。
- `f [String]` 纵能确定 `B`，仍因缺显式参数 `X` 而报错误。

## 重放检查

求解既毕，表达式检查与模式检查，分别复沿函数类型与源参数脊前进：

- 于缺省位置，依次取用求解器返回之类型表达式。
- 对显式写出与自动补入之隐式实参，执行类型之类型检查。
- 对普通表达式实参，执行对象类型检查；对模式实参，执行模式类型检查并更新环境。
- 每消费一隐式参数，即以检查后之类型表达式代入依赖值域。
- 终检结果类型与期望类型一致，并重建完整调用 AST。

求解与检查由此而分：前者惟一小而稳之返回值；后者司一切真实类型错误与语法树构造。

## 擦除后之调用约定

类型检查阶段要求源码调用完全应用；类型标注擦除阶段则统一用内部柯里化表示。每显式实参皆降为一嵌套 `Multi1` 调用；连续运行时拉姆达亦保为逐层 `Multi1`：

```text
f a b          => (f a) b
λa. λb. body   => λa. (λb. body)
```

此区分至关紧要：箭头类型 `A -> B -> C` 本身无法说明其实现为一次收二参数，抑或先收 `A` 再返 `B -> C`。统一之一元运行时约定，无须自类型猜代码元数（arity），亦自然覆盖“自引用读函数后续调用”诸情。源码层仍由类型检查拒参数不足；内部逐层调用，不表重新许源码部分应用。

顶层定义与普通函数值，走同一闭包转换路径；文件定义引用读相应全局定义槽。旧之“顶层函数直接化”，不复司扫描优化结果、猜元数、eta 展开，或改文件定义引用为函数符号。
