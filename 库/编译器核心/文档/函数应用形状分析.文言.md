# 函数应用隐式参数求解

其实现见 `编译步骤/类型检查/函数应用隐式参数合成。豫`。此阶段惟答一问：一次函数调用中，哪些未写出之隐式类型实参，可由现有信息唯一确定？

## 顶层接口

`求解函数应用隐式参数` 接收命名环境、完整调用表达式、函数头类型、源参数脊与可选之期望结果类型，返回：

```text
列 表达式
```

返回列惟含须自动插入之隐式类型实参，并保其于函数类型中之出现顺序。函数头、参数规划、合一上下文与结果类型，皆不返回。

- 合成模式传入 `可无`，故不可自结果类型取信息。
- 检查模式传入 `可有 T`，故可以 `T` 接地隐式参数。
- 用户已写出之隐式类型实参，不出于返回列中。

## 可用于求解之信息

每个隐式绑定，皆先实例化为本次调用独有之新鲜类型变量，登记于 `var → optional expression` 之模式合一上下文中。用户显式写出之隐式参数，立记为该变量之 `Some expression` 解；缺省、待推断之隐式参数，初记 `None`，候普通实参或结果类型接地之。键不存在，表该名非本次待求变量。惟缺省变量记于最终返回列。求解器惟读下列信息：

- 用户写出之隐式类型实参。
- 普通实参为自由变量，则自命名环境径读其类型。
- 普通实参为文件定义引用，则自文件定义径读其类型。
- 检查模式中之期望结果类型。

λ 式、函数调用等复杂普通实参，不参与推断，留予后续常规类型检查。如此可免为合成隐式参数而递归预检实参。

每条可用信息，皆惟作单向合一（matching unification）：左侧类型可含上下文中登记之变量；右侧对此诸变量必为接地（ground）。匹配成功，方提交新 `var → expression` 解；任一子结构不匹配，则整次匹配回滚，求解阶段不报参数类型错误。真错误由重放检查报之。求解既毕，再以全部参数信息与可选结果类型，检一切待求变量是否已接地。

模式合一径复用原有结构比较递归，并以同一 `串典` 上下文随递归传下。普通节点仍循原规比较；惟比较遇左侧自由变量时，方查上下文：未登记之变量仍须两侧同名；已登记而未解之变量，写 `Some 右式`；已有解者，则以该解续与右式比较。全过程不预“应用上下文”，亦不执行表达式级局部替换；求解既毕，径自 `串典` 读各隐式参数之类型表达式。

求解器不读或应用此上下文以改写当前函数类型。外层调用检查先沿函数头原始类型骨架，拆出当前参数组；当前组检毕，常规依赖类型替换给真实结果类型；若源参数脊尚有剩余参数，则以该结果为新函数头，续检下一组。如 `readRef : {A} -> Ref A -> A` 先惟检 `readRef ref`；若 `A` 接地为 `X -> Y`，再以此结果检后续参数。如此无须设“惟读顶层已解变量”之特支。

## 完全应用语义

函数名本身仍可为函数值。惟语法树已入函数调用节点时，方要求本次调用完全饱和：

1. 遇隐式派类型与源隐式实参，则消费该实参。
2. 遇隐式派类型，而下一源实参非隐式实参，则为该位创待求解之隐式参数，不消费源实参。
3. 遇函数原始类型骨架中之箭头，必消费一源显式实参；源参数已尽，则报不许部分应用。
4. 当前类型已非函数，而源参数尚有剩余，则报参数过多。
5. 遍历既毕，仍有隐式类型变量未定，则报无法完全确定隐式参数。

裸函数名于检查模式中，可用期望箭头类型接地前置隐式参数，后停于箭头类型上，作为函数值。此非源码部分应用；然 `f [String]` 已为调用节点，仍须补足后续显式参数。

完整调用之结果，本身可为函数值。如 `readRef ref` 已消费 `readRef` 之全部参数；若引用中所存为函数，其结果类型仍为箭头，然此非部分应用。外层检查器将扁平源码参数脊重建为 `(readRef ref) arg`，不误传 `arg` 于 `readRef`。

故若 `f : {A : Type} -> {B : Type} -> X -> R`，则：

- `f [String] x` 可自 `x` 之直接可读类型或期望结果类型推断 `B` 时，成立。
- `f [String] x` 无法确定 `B`，则报错误，不返保留 `{B}` 之部分应用类型。
- `f [String]` 纵能确定 `B`，仍因缺显式参数 `X` 而报错误。

## 重放检查

求解既毕，表达式检查与模式检查，分别复沿函数类型与源参数脊前进：

- 于缺省位置，依次取用求解器返回之类型表达式。
- 对显式写出与自动补入之隐式实参，执行类型之类型检查。
- 对普通表达式实参，执行对象类型检查；对模式实参，执行模式类型检查并更新环境。
- 每消费一隐式参数，即以检查后之类型表达式代入依赖值域。
- 终检结果类型与期望类型一致，并重建完整调用 AST。

求解与检查由此而分：前者惟一小而稳之返回值；后者司一切真实类型错误与语法树构造。

## 擦除后之调用约定

类型检查阶段要求源码调用完全应用；类型标注擦除阶段则统一用内部柯里化表示。每显式实参皆降为一嵌套 `Multi1` 调用；连续运行时拉姆达亦保为逐层 `Multi1`：

```text
f a b          => (f a) b
λa. λb. body   => λa. (λb. body)
```

箭头类型 `A -> B -> C` 本身不明其实现为一次收二参数，抑或先收 `A` 再返 `B -> C`；故一元之约为通用之运行时约定：函数值、闭包、自引用所读之函数，皆循逐层 `Multi1` 而调。源码层仍由类型检查拒参数不足；内部逐层调用，不表重新许源码部分应用。

## 顶层直接调用

已知之顶层定义另有径调之约，其实现见 `编译步骤/优化/跨文件优化/顶层直接调用。豫`，行于跨模块优化之末。

1. 元数取于类型检查所得之签名。类型检查之阶，依函数应用之骨为每定义算其元数：去其首之一组隐式参数，数既展箭头类型之定义域；构造器取其构造器类型。此即上文“完全应用语义”中一次调用所消费之显式参数数。其果书于阶段产物 `签名元数`。
2. 签名元数 N 不小于一，且既优之定义（去其顶层递归节点）首有不少于 N 层单参拉姆达者，此定义有工函数。工函数为 N 参之全局函数，其体为去前 N 层拉姆达之定义体；顶层递归节点之自引改为文件定义引用。定义本身化为“先声工函数，后与柯里化之门”：门有 N 层单参拉姆达，最内一并授 N 参于工函数。全局定义槽所存者，门也。
3. 工函数之名、定义序数与元数，书于阶段产物 `顶层元数`，先于优化后形式而书。他模于其跨模块优化之末读此产物；并行调度保依赖之模跨模块优化先毕，依赖之优化后形式一更，下游之优化后形式随之重建，故分编与缓存之下两端相合。
4. 调用脊之头为有工函数之文件定义引用，且实参不少于 N 者，前 N 实参一并授工函数（`函数调用 (函数引用 工) (多参数形 N)`），余参依一元之约逐一施于其果。实参少于 N、头非已知顶层定义、或定义用为值（为返、存于数据之构、为高阶之实参）者，仍读全局定义槽所存之门。

```text
f a b c        （f 之签名元数为二）   =>   (工f a b) c
```

此改不易可见之求值次序：旧之逐层施用，前 N−1 次惟新建闭包，无副作用；实参仍依源码次序而求，皆先于工函数之体。果本身为函数之满参调用（如 `readRef ref` 后复被调），惟满参之部径调，余依一元之约。尾位之径调，由尾调用优化标为尾调；自递归之尾调，后端化为循环。

签名元数少于拉姆达层数者（如返回类型书作函数类型之别名），工函数返闭包，余参依一元之约施之。拉姆达层数少于签名元数者（如 `会「格」而「读引用」于「格」`、别名 `「f」者「g」也`），不生工函数，调用仍经全局槽：此时先求后参，或易中间函数体之行序。

去柯里化惟复变顶层定义内之局部递归；顶层定义自身之递归，统归于此。异常、续延之模（`路径不应当优化`）、底层模式、`-O0` 与 `-fno-func-uncurry`，皆不生工函数，亦不改调用。模块初始化时径调前已初始化之定义，不读全局槽；顶层无前向引用，依赖之模先初始化，故径调不先于受调定义之初始化。

旧之“顶层函数直接化”（二〇二六年八月删）自优化结果猜元数，并于别名与部分应用行 eta 展开；今惟用签名元数，不行 eta 展开。

## 去装箱

整数、小数常装为 `(ref null eq)`（i31 或 `$big`、`$float`）。编译器确知某参、某果、某局部为整数或小数者，以 i64、f64 径存径传，算前算后不复装解。其实有二处：类别随签名至代码生成，代码生成通全程而推其表示。

1. 类别。类型检查书签名元数时，并算每显式参与果之类别：内建整数为整，内建小数为小，余（类变、组、列、函、不透明之类、爻、字符串）为通。签名元数、顶层元数二产物皆载类别；代码生成读诸模之顶层元数，得“工名 → 类别”。调者之优化后形式惟依元数，不依类别，分编与缓存不受其扰。
2. 确知之函。工函数有类别签名，且无整组克隆、私形、虚组诸变体者，参依其用择其表示：签为整而于体中以整用（整数之算、数组之下标、确知调用之整参）者用 i64，签为小而以小用者用 f64，静态自递之函中为数组读写之对象者用 `(ref $tuple)`，余（惟转手者）仍用 eqref。果之类别取于签，然须尾调之安：函于尾位惟调己（化为循环）或果类同之确知之函者，乃以 i64、f64 返；否则（尾调闭包、调非确知之函）果降为通，反复至不变。纯整之函（参皆于入口受整数之算之检，体惟整数之算）亦为确知之函，其快体即旧之 `$n`。
3. 生成。确知之函有通门 `$f号`（参与果皆 eqref，留于函数之表，应用接口导出亦调之：解参而调快体，果非通则装之）与快体 `$m号`。凡径调确知之函者（本模、他模、柯里化之门之最内、闭包之体），皆依确知签名解参，径调快体；类别确知，不书守。尾位而果类同者尾调，异者调后转而返；尾调之安保此转不在尾调之环。
4. 局部。代码生成于正则前推局部之表示：整数之算、小转整、原语登记表中果为整之原语（如取余、位算）、果为整之确知调用，得 i64 之局部；小数四则、整转小、原语登记表中果为小之原语（如开方、取整）、果为小之确知调用、两支皆产小数之若，得 f64 之局部。整数之算之外，诸推惟行于无变体之函。登记之原语，其果之局部为相应之 i64、f64 者，参依所登之类径书，就地生令，不装。入元组、构造器、闭包、全局，或授多态之函、闭包、宿主者，当场装之；自多态之代码出之值，于以整、以小用之处解之。
5. 循环。自尾调仍化为循环，回环时确知之整参、小参径书 i64、f64，小数累加之器不复每轮分配。
