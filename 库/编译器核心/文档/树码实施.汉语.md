# 树码实施

这是提案00001的实施记录。结构表与编解码器在 `编译数据/抽象绑定树结构/抽象语法树/序列化/`，缓存接入在 `编译步骤/总体过程/树码缓存支持。豫` 与 `编译文件缓存工具。豫`，转换与核对工具在 `应用/开发工具/树码/`。下文测量保留第一版验收记录。

当前第二版的文件定义列只含名字与表达式，删除无实际导出作用的公开性爻；文件头版本改为二，定义编码依次为名串号、体字节长与体。旧版树码按缓存未命中重建。编译器只写树码，移除 JSON 缓存、附加文本导出和相应命令行选项；`yy树码 转换` 默认把树码转成同名豫言文本，文本标头版本为三。

语言服务、语义标记及包描述语言服务也使用树码。其资料对象复用现有节点编码，串表共用字段名与内容；VS Code 调用豫言 Wasm 工具读取资料和显示阶段文本。两类真实二进制样本的跨语言互操作、插件 lint、编译和相关回归已通过。完整「全部」构建通过，共 1,585 秒；三级、四级逐字节相同，SHA-256 为 `3996951b9665942245537d551c520a23140f33c1e1158b97a91b26ce090552fa`。最终类型检查及包配置、豫构七项测试通过。该编译器的缓存中已核实 10,947 个树码文件，JSON 与豫言文本缓存均为零；工具的二进制→文本→二进制转换逐字节一致。

结构表有九十三种节点名称，五种参数形式、十六种内建常量、七种结构名称操作、两种定义透明性与两种注释方向。规范文本按这一次序排列，各行以一个换行分隔，末尾无换行；SHA-256 为 `d0e190951b1aee7a253106686ad73097c9f1bedda1e92d727684e64f700a809f`。原提案内建常量数量的十七项以源码实际十六项为准。

六十四位 LEB128、浮点位型、名示拆号、散列串表、包路径表、逐构造器载荷、树组与串列已实现。表达式按先序积片段，最后分层合并，避免逐层复制子树；定义体共用读取游标并各设终点。第一版拒绝共享标签四，NaN 编码归一，负零保留。编码结果可附「与本机有关」标记，供构建清单记录；未知包路径保留本机路径。

`--中间格式 结森|树码` 选择缓存写入格式，默认树码；中间文本默认关闭，用 `--导出中间文本` 打开。读取优先树码、回退 JSON，按魔数判断格式。版本或结构摘要不符按未命中重建；切回 JSON 写入会移除同产物旧树码。依赖与依赖快照写树码串列，补导文本由统一基径定位。独立阶段显式装入树码输入，继续保持禁止磁盘缓存回退的约束。

模块名改由所有者、包名、包内路径生成，各段冠以长度再沿用标识符转义，包上下文之外仍用原本机名字。顶层直调、局部直调、满参递归与提升函数名也使用这一身份；缺分支异常消息先按最长包目录换成包身份，再截取诊断文本。
