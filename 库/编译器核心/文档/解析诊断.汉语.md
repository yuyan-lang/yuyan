# 解析诊断与长源码编译

表达式解析没有可行解释时，默认错误显示文件路径、源码风格的令牌片段和检查建议，不展开整个内部 AST。片段最多取 32 个词；标识符或字符串内容最多显示 64 个通字符。裸写的元、阳、阴若出现在失败语句中，会提示检查是否应写为「元」、「阳」、「阴」。字符串内容和已经引用的标识符不触发该提示。提示不改变语法，也不自动修改源码。

目前词法已经丢弃空白，表达式不附带原始坐标，因此简报明确说明“省略空白，无精确行列”。精确定位需要后续在词法令牌中保存范围并贯穿语句拆分。`-vv` 详细调试输出仍保留失败分支的完整栈。

## 长源码调用栈

真实 Worker 对约 30 KiB 中文字符串源码暴露了连续的线性递归路径。通用标准库实现现在使用尾递归：

- 「打表」：词法将完整源码字符数组转换为列表时，顺序回调、逆序积累后反转。
- 「整数范围」与「态射」：代码生成按 UTF-8 字节转义字符串时，保留区间和映射顺序。
- 「长度」：列表转数组之前计数，使用整数累加器。
- 「附加」：反转前列后搬到后列之前，保留后列共享及两列顺序。

没有提高源码配额、裁剪字符串或隐藏编译失败。修改涉及 `库/标准库/数据结构/多态列。豫` 与 `多态列工具。豫`。

## 验证

`测试/语法/表达式构造/裸内建值-*。豫` 应失败并提示对应角引号；`引用内建值-1。豫` 和 `诊断简报-1。豫` 验证合法值、字符串不误报及截断。`测试/网页汇编/长打表-1。豫` 检查 32,000 项打表、映射、长度、区间、附加、回调次数与顺序，以及空表和逆向区间。

完整编译探针复用平台内存文件系统、Wasm 宿主与 Binaryen 组装器，先预热同版标准库，再编译由 10,000 个“甲”构成的 30,090 字节源码，执行生成物并逐字比较输出。最终版本在默认 Node 栈下生成 346,309 字节合法 Wasm，执行输出恰为 10,000 个“甲”加换行。128 KiB 极小栈会触及标准库总集 AST 解码深度，不能用它代替生产 Worker 的实际验收；生产 Worker 测试由平台工程负责。

## 构建与资源同步

使用独立原生编译器种子，避免在它仍运行时覆盖同路径可执行文件。提供指向当前工作树标准库、拓展库、构建基础、编译器核心及豫言编译器的有效包上下文：

```sh
./yy长文构建种子.exe 豫言编译器/入口。豫 --package-context /tmp/yy诊断包上下文 --target=wasmgc -o yy完整长文编译器.wasm
```

现有平台 Binaryen 组装器优化模式处理 `.wasm.wat`，得到 `yy完整长文编译器优化.wasm`。本轮产物为 1,780,893 字节，SHA-256 `fd69cf02e23c43b83570cc372c6081a2803d08042831d358f4f6e52a52204333`，模块结构验证通过。

发布时同步两个标准库源码，清除全部 `/.yybuild/` 派生缓存后重新预热并打包。其他模块可能内联旧实现，不能只删除同名缓存。更新浏览器和云端编译器资源及清单摘要，再走真实 Worker 回归；本编译器仓库不发布用户应用。

最终验收：三段自举与正式类型检查全部通过，`yy3_bs`、`yy4_bs` 逐字节相同，SHA-256 均为 `7538210751fec57ab8456c71c482ba6dd4ef55ed55b50d5ceaf4b8d5aa9dc37e`。平台工程确认真实 workerd 七项回归全部通过，包含 30,090 字节万甲源码编译（该次 891 ms）、多文件、产物执行、隔离、流式输出及简洁诊断。
