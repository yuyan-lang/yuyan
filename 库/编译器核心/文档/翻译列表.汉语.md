# 翻译列表

本篇记录英文术语的中文译名。字母的写法见[英文字母翻译](英文字母翻译.汉语.md)与[希腊字母音译表](希腊字母音译表.汉语.md)。起名的原则与诺节、结森的由来见官网[译名](https://yuyan-lang.org/译名/)；豫言基础库用到的格式与协议的译名见[提案 00004](../../../提案/00004-共用基础库.汉语.md)「译名」一节。

格式名用固定的字收尾，表明类别：图（图像格式）、档（归档）、压（压缩）、码（文本记法）、象（对象表示）、列（列式数据）、量（张量）、浮（浮点）。

| 英文 | 译名 | 由来 |
| --- | --- | --- |
| Token | 符记 | |
| Lexer | 词法分析器 | |
| JSON | 结森 | 音译，读如“杰森”：结与 J 的音译“杰”同音，森取 son 的音；结有“结构”的意思，森比喻层层嵌套如林。旧译“癸象”，2026-09-30 改 |
| Node.js | 诺节 | 诺取 Node 的音；节代表 JS 的 J（与音译的“杰”同音），也保留“节点”的意思 |
| npm package | 诺节库 | 诺节使用的库，与“系统库”对称 |
| CPU | 中央处理器 | 通行译名 |
| WebGPU | 网页图算 | 网页（Web）加图算（在图形处理器上计算） |
| Metal | 金属 | 直译 |
| CUDA | 统算 | 取 Compute Unified（统一计算）的意思 |
| YAML | 雅码 | 音义兼译：音近 YAML；雅指便于人读，码表示文本记法 |
| TOML | 通明 | 音义兼译：音近 TOML，指配置文本清晰易读 |
| CBOR | 简象 | 意造：Concise Binary Object Representation，简洁的对象表示 |
| PNG | 便图 | 意造：Portable Network Graphics 的“便携”加“图” |
| JPEG | 捷图 | 音义兼译：捷取 J 的音，又有编码高效之意；图表示图像格式 |
| WebP | 网图 | 意造：网页（Web）加图片（Picture） |
| DEFLATE | 缩流 | 意造：压缩的数据流 |
| gzip | 吉压 | 音义兼译：吉取 g 的音，压表示压缩 |
| Zstandard（zstd） | 泽标压 | 音义兼译：泽取 Z 的音，标即标准（standard），压表示压缩 |
| tar | 合档 | 意造：把多个文件合成一个档；.tar.gz 即合档再经吉压 |
| zip | 压档 | 意造：压缩加归档 |
| Apache Arrow | 箭列 | 直译加语素：箭即 arrow，列表示列式数据 |
| Feather | 羽列 | 直译加语素：羽即 feather，列表示列式数据 |
| Parquet | 拼花 | 直译：parquet 即拼花地板 |
| safetensors | 安量 | 意造：安全的张量文件，量表示张量 |
| bfloat16 | 脑浮16 | 直译：brain floating point，浮表示浮点 |
| CRC | 循环校验 | 沿用：通行全称“循环冗余校验”的简称；变体名把位数与字母照原样接在后面，如循环校验32C |
| hash | 散列 | 沿用，仓内已用 |
| Adler-32 | 阿德勒32 | 音译：作者 Mark Adler，位数照原样接在后面 |
| FNV-1a | 福诺沃1a | 音译加版本：FNV 取 F、N、V 三个字母的音（福、诺、沃），1a 是变体名 |
| SipHash-2-4 | 啜饮散列2之4 | 音义兼译：Sip 音近“啜”（小口喝），散列即 hash，2 是压缩轮数、4 是终轮数 |
| xxHash | 极速散列 | 意造：作者称它是极快的散列算法 |
| XXH32、XXH64、XXH3 | 极速散列32、极速散列64、极速散列3 | 沿用：同 xxHash，后缀标位数与版本 |
| MurmurHash | 低语散列 | 直译：murmur 意为低语 |
| hexadecimal | 十六进制 | 沿用：通行译名；本包「十六进制文字」模块用它译 hex |

上表末十行由「校验」库（2026-10-07）首次用于代码；提案 00004 第五节「格式与协议的译名」有同一批行的对应表。
