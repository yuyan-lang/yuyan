# 内府（自己的对象存储）

通称内府（own object storage）。这是提案 00064《内府》第一步与第二步的库：跑在自己机器上的对象存储的协议、服务核心、三副本驱动与客户端。

## 范围

- 协议（券）：请求是一个籍册记录，栏为号、术、桶、键、键们、约束、读限、正文；术有六：元（取元数据）、读（读正文）、写、列（按前缀列举）、删、息（停服务）。应答是号与果；果有四变：成（元数据、正文、有无正文）、无物、条件不合、器误。编号由客户端给，服务端原样带回。
- 服务核心（受藏）：收请求、交给本机落盘的库「金匮」办、回话。迎到的一条连接在「同生」作用域里投刺、送问，成则把券交给出归藏的属主、放进客们；投刺或送问不成、门绝、凭不合与收场都按券还。读在收到时即办；写与删排成一列依次办，每批写办完先把这些写碰过的卷册同步到盘，才回应答。一条连接上一建立就先合符（虎符凭证）：服务端先送一个随机数，客户端用虎符对它算沙二五六作证，服务端拿文件里的虎符重算核对。
- 客（客户端）：一条连接复用，断了重连一次；一条连接上一次等一个答复，按请求号核对；超时可设。连接由「连有」「入有」在「同生」作用域里取得：成则把券交给出归藏的属主、按连接号记进券录，败或中途抛出事故由作用域关掉；标断、重设与收场都按券还。
- 落盘（落盘）：按宿主授予的目录权，用豫寓榫卯「文件」的「同步卷」把刚写过的卷册刷到盘上。没有授目录时起不了内府台（写入要落盘才回话），错误消息里写明授权办法。
- 台署（台署）：读内府台的配置 `内府台。数据。豫`（数据目录、地址、端口、虎符、桶名单、授权目录名、可选的盟署），缺项取缺省。
- 台行（台行）：按配置起一台并走主循环：没有「盟」一节时起单机内府台（受藏、落盘），有「盟」一节时起三副本的盟台。
- 盟署（盟署）：三副本的配置——本员号与全部员的员号、地址、端口。
- 盟文（盟文）：三副本的编码与落盘格式——信编成籍帛过网，命令（写或删的请加盟主定下的上传时刻）编成籍帛入载书，快照的照始、照块、照终也各编成籍帛过网；盘上分盟态一卷与载书一目录：盟态记任期、所投、已执行到的序号与快照点（照号、照期），用籍帛写、原子换名、写完同步；载书按起始序号分成若干段，每条记录是八字节小端长度加籍帛（序号、任期、命令帛）；快照清单也按籍册记录编解，随照始过网，并落成快照目录里的 `清单。数据。豫`。
- 载段（载段）：载书各段的读写。按段名次序逐段扫、逐条核长度与籍帛、核序号连续，末段末尾写了一半的残条截掉再起；追加只往末段写，一段过六十四 MiB 就另开一段（快照门限调小时段限也按门限缩小，好让删前删得掉整段）；冲突时把含截点后一条的段截短、删掉其后的整段；前缀删除只删整段都在删点以前的段，跨过删点的段里旧条留着，重起时按盟记里的照点舍掉；装快照则用「清空」把各段全删、前缀记成照点。
- 盟台（盟台）：三副本的驱动。发起与迎到的连接都在「同生」作用域里托起、成则交出，放弃的连同门绝、认阴、收场都按券还。持着盟府的一员，把收到的信、钟的滴答、客户端的献令与请读交给「步」；每一步先落盘后发信（存单写进盟态一卷与载书各段并同步，凭持证启封才发信、才交付）；交付的条按序号执行，空令跳过、实令交本机金匮办，已执行到的序号写回盟态；员间用合符认人、用封与籍帛收发，连接复用、断了重连；开连只投刺、不在原地等回答，合符由每一拍的「理出一」推进，认成之前的信先记在去连接的待发列里，认成后一齐冲出；客户端与盟员共用一个端口，认后按第一封的顶层名分辨；不是盟主时答非主并附所知盟主的地址。盟台另管快照：载书各段字节总数过门限时在两次交付之间把金匮抄成 `快照/<至号>/`、立照并截段；盟主按盟府的送照项把最新快照按照始、照块（一块一兆）、照终发给落后的远员；从员在 `快照/<至号>。备` 收全、核大小与沙二五六后，先落盘盟记与清载书，再把 `对象/` 换名成新的，答盟主载成；重起先读清单定照点，再读照后的载书，用「开府带照」。
- 归藏（归藏）：客、受藏、盟台三处取得的套接字都包在「同生」作用域里「托」：成则「交出」新券、按连接号记进券录，败由作用域收尾关掉；此后按连接号取券「还」一项，模块收场时「收主」兜底，把券录里剩下的全关掉。连接号只经券录出现：按券还、关过即忘，重关不响第二声。
- 随主（随主）：客户端侧的多台选址——按地址列逐台试，得到非主就改连所附盟主，连不上就轮下一个，退避重试有上限；随主只择地址与重试，请求仍由客发。

## 三副本

配置里加一节「盟」就是三副本，不写这一节照旧是单机模式：

```yuyan
「盟」者 「典」
　【「本员号」者『甲』也
　，「员们」者「列」【
　　　「典」【「员号」者『甲』也，「地址」者『127.0.0.1』也，「端口」者「二一零零一」也】，
　　　「典」【「员号」者『乙』也，「地址」者『127.0.0.1』也，「端口」者「二一零零二」也】，
　　　「典」【「员号」者『丙』也，「地址」者『127.0.0.1』也，「端口」者「二一零零三」也】
　　】
　】
也。
```

- 本员按本员址的地址与端口听客与盟员；别的员按名单里的地址与端口连过去。
- 客户端与盟员共用一个端口：认过之后按第一封的顶层名分辨（「请」是客户端，「信」是盟员）。这样配置里每员只写一个端口，一台上只有一门。
- 写的次序：盟主把客户端的写或删编成一条实令、带上盟主定下的上传时刻（元数据里的 `uploaded` 取它，各员执行时不再各取各的钟），献进盟书；等这条交付、在本机执行完，才按执行结果回客户端。
- 交付落盘：各员执行写删后先同步本次改过的对象卷册，再把已执行序号写进盟态并同步，最后更新内存中的已行、回复客户端。命令解码失败、对象执行故障或同步失败时报告事故，已行保持原值。行果（交付结果）只含已同步的成功与条件不合，答议（提议应答）按这两种结果回复。
- 条件在交付执行时按本机状态判：各员按同一序号执行，结论一致。执行幂等靠两件事：盟态里记已执行到的序号，重起只执行其后的条；条件写重放时条件已不成立、无条件的写重写同一份正文，效果相同。
- 读与列举先向盟府要读确认，得到许读的序号后等本机执行到那里再从金匮读。不是盟主答「非主」并附所知盟主的地址。
- 重起时从数据目录下的 `盟态` 与 `载书/` 各段恢复：先按段名次序读各段，核长度与籍帛、核序号连续，截掉末段末尾写了一半的残条；再按盟态里的任期、所投与已行开府。起台前先核已行不超过现存条数。
- 发不出的信丢掉（盟府容丢、容重、容乱序）；连接断了下次发信再连。

## 落盘格式

单机模式的数据都在数据目录下由金匮管：索引与对象各成卷，格式见金匮包说明。

三副本模式的数据目录下有：

- `盟态`：一卷籍帛，记任期、所投、已执行到的序号与快照点（照号、照期；旧版没有后两项，读时按零算）。用「定稿帛」先写临时文件再改名，写完同步。
- `载书/`：一目录，存若干段。段名是这一段的起始序号，二十位十进制左补零，后接 `。段`，如 `00000000000000000001。段`；补零后按名字排序就是按序号排序。每段只往末尾追加，一段写到六十四 MiB 就另开一段，新段的起号接在上一段末条之后。
- 每条是一条记录：八字节小端长度，后接籍帛；籍帛里是序号、任期与命令帛。序号也写在记录里，重起时逐条核对。
- 落盘：一批追加或截短办完，把碰过的段同步一次；盟态变了再同步盟态。两处都成功，才把存单交成存证，才发信、才交付。
- 尾部截断：冲突时盟府要求截掉某条及以后。载段按内存里每条所在的段与偏移，把含截点后一条的段截短到那条的开头，删掉其后的整段；截短后同步。
- 重起：按段名次序逐段读，核长度与籍帛、核序号连续。末段末尾若有写了一半的残条（断电时写了一半），截掉那半条再起，不报错；别的段有半条、长度不合、籍帛解不开或序号不连续都报中文错误并以非零退出。
- 前缀删除：载段另有「删前」，只删整段都在删点以前的段，跨过删点的段留着，重起时按盟记里的照点舍掉旧条；装快照另有「清空」，把各段全删、前缀记成照点。
- `快照/`：一目录，存快照各份；每份为 `快照/<二十位至号>/`，内含 `对象/` 与 `清单。数据。豫`。只留最新一份。收照时的临时照目是 `快照/<二十位至号>。备`。
- `装照/`、`装照。成`、`装照。毕`、`对象。旧`：装快照的临时目录与两个小记；换名时旧的 `对象/` 先挪到 `对象。旧`。
- 崩在装照中途的行与收拾办法见上一节「快照」。

## 快照

三副本模式下每个员各自按载书目录的大小立照，门限写在 `内府台。数据。豫` 的「盟」一节：

```yuyan
「盟」者 「典」
　【「本员号」者『甲』也
　，「员们」者「列」【…】也
　，「快照门限」者「六五五三六」也
　】
也。
```

- 门限以字节计，缺省 268435456（256 MiB）。载书各段文件的字节总数超过门限，就在两次交付之间（本机单线程，不在交付中途）立一份快照。门限调小时每段的上限也按门限的四分之一缩小（夹在 4 KiB 与 64 MiB 之间），删前才删得掉整段，载书目录的总量便贴着门限而不随写入一直涨。
- 快照目录是 `快照/<至号>/`，至号写成二十位十进制、左补零。里面放金匮在已行等于至号时的完整状态：金匮根下 `对象/` 树的副本，路径照旧（逐文件用分块拷卷抄写，正文与索引都照抄当时的字节），与一份清单 `清单。数据。豫`。
- 清单顶层一项 `照单`，栏为 `至`（序号）、`期`（任期）、`文件们`（列）；每项为 `路径`、`大小`、`沙`。路径相对数据目录，以 `对象/` 起头；沙是文件内容的沙二五六十六进文。
- 立照的次序：先抄照、写清单、把每个文件与清单同步到盘；再调盟府「立快照」；照存单先把带新照点的盟记写进盟态并同步，再删掉整段都在照点以前的载书段；最后删掉旧的快照目录，只留这一份。崩在中间时，重起按盟记里的照点舍掉旧条；与照点不匹配的快照目录会被清掉。
- 送照：盟府在发件里报「送照」（给某员、至号、任期）时，盟主从 `快照/<至号>/` 读清单，先发照始（自、至、期、清单），再按文件逐块发照块（自、至、路径、偏移、块帛，一块一兆），末了发照终（自、至）。同一员同一至号只送一份，送往途中不重复起送；送完三秒还没等到载成回音（断线或对方没收全）就在盟府下次再要时从头再送。
- 装照：从员收到照始就在 `快照/<至号>。备` 建临时照目、写入清单；照块按偏移接在文件末，偏移对不上就丢掉整份临时照目；照终到了逐个核大小与沙二五六。核过了把临时照目改名成正式照目、写 `装照。成`，再调盟府「装快照」：带新照点的盟记先落盘、载书各段全清；然后把正式照目里的 `对象/` 逐文件抄到 `装照/对象`，旧的 `对象/` 改名成 `对象。旧`，新的换上去，写 `装照。毕`，删旧的与临时目录。核不过就丢掉临时照目，不装，等盟主再送。
- 换名崩在中途时（`装照。成` 或 `装照。毕` 在、`对象。旧` 在），重起先「收拾装」：有 `装照。毕` 就只清旧目与临时目录；有 `装照。成` 且与盟记照点同号，就照正式照目再装一遍；记与照点不同号（崩在写盟记之前）就弃掉临时目录与记。结果总是旧的完好或新的完好。
- 重起：先收拾装、清掉不匹配照点的快照目录；读盟记，有照点就读 `快照/<照点>/清单。数据。豫`，核清单的至号、任期与盟记一致；再读载书各段，把照点以前的条舍掉，用「开府带照」；最后核照点不大于已行、已行不大于载书末号、清单里有文件时 `对象/` 在；已行正停在照点时还逐个核快照里的文件与 `对象/` 里的大小、沙二五六（这一处最能看出“照记下了、金匮还没换”的残局）。任一项对不上就报中文错误并以非零退出。
- `装照。成` 与 `装照。毕` 都是数据目录下的小记，顶层 `装记`，栏为 `至`、`期`、`主`；`毕` 记只作标记。

## 与别处的关系

内府台的存储直接用接口适配「豫寓府库金匮榫」的五术：根设在内府台的数据目录下。三副本的共识用库「盟府」（纯状态机，不碰网、盘、钟，网、盘、钟由盟台接）。服务程序「内府台」在 `应用/百工坊/内府台`；客户端适配「豫寓府库内府榫」在 `豫言操作系统/适配/对象存储内府`。

## 限额

- 单次读写正文至多 16 MiB（与对象存储接口的写入上限相同）。
- 列举一页至多 1000 项。
- 删物一批至多 1000 个键。
- 读请求的字节上限须在 1 至 16777216 之间。

## 待办事项

- 旧版单卷 `载书` 文件不做迁移，起台时遇到会报中文错误并要求先移走。
- 成员增减还没做（三副本的成员写死在配置里）。
- 三副本连互联网时由封缄（TLS）加密，留待第三步。
- 落盘同步要宿主按名授予数据目录：宿主上以 `--授权目录写 内府=<数据目录>` 启动内府台，豫言操作系统上在常役的参数里写同一对选项；未授目录时内府台起不来并报中文错误。浏览器之类的宿主没有同步能力。
- 直通出站响应、入站正文写入、分段写物在客户端适配里答「暂不支持」，第三步补上。
