SQLite 同步 `storage.kv` 今有豫言读、写、删、列诸门。同步读以有无标志别阙键与癸象空；列举于一宿主调用取尽。Wrangler 4.129.0 本地验异步写而同步读、同步写而异步读、逆序限数、删果及重启存续。旧 KV 仓无此门，异类克隆值待验。详 [Cloudflare 同步 KV 文档](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#synchronous-kv-api)。

`云工持久SQL游标新建` 还本事游标柄；`下一行`、`余行` 可取具名物或 `raw()` 值列，二者共一序。`单行安全文` 还 `one()` 之成败；属性门还列名、读写行数，亦可察库大小。Wrangler 4.129.0 本地 SQLite 已验混合遍历、单行及零行多行之败、读数递增与一行写数。`rowsRead` 可含扫描诸行，非仅返行数；游标越异步候不保快照，欲稳则用一次性 `云工持久SQL执行`。详 [Cloudflare 游标文档](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#exec)。

`云工持久读取值安全文` 以一 JSON 文还缺键或有值之果，事务内亦循 `txn.get`。最小事务已验阙键与癸象物；额度稿旧有模式不配，根在业务 `字段` 之嵌套鉴别，单文门未解其故。别云仓任务今以显式递归遍历治之并验；两宿主值桥能报模式不配，免「未授权打印」掩本因。

命名服务入口 `豫言服务入口` 可由构建器第七参别名出之，如 `CloudModel`；其请为 `service-fetch` 事，公域之请仍为 `fetch`，分路之断由豫言。Wrangler 4.129.0 本地服务绑定已验二路。可选密文门 `云工秘密文字安全文` 于已许可而阙值时还 `{"存在":false}`，空文则还真有；本地假绑定已验三态，回应不载密。未许可之名仍报错，生产密与轮换待验。详 [Cloudflare 命名入口文档](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/rpc/#named-entrypoints)。

对象每应 fetch 或 alarm，皆新造豫言 Wasm 实例而行入口；客栈与柄不越事而存。对象重建，豫言须自 `ctx.storage` 之 KV 或 SQLite 取旧态。上述重启之验已证此恢复之路；并发交错、重试与云上故障恢复尚未验。

# WebSocket

`物字与文件。豫` 备 Blob/File 原字与合件之造、察元、截取、原生 `arrayBuffer()`/`bytes()`、`text()`、`stream()`；`流。豫` 又可逐块读文字。Wrangler 4.129.0 本地 workerd 已验 `00 FF 41` 无损、Blob 合 UTF-8 文、负索引截取及 File 名、类、修改时。此版本有 `Blob.bytes()` 而无实验性 `Blob.textStream()`，后者安全门归阴。FileReader、FileList 与大物流界尚待补，详 `物字文件接口.清单.tsv` 及 [W3C File API](https://w3c.github.io/FileAPI/)。

`流。豫` 今有通用可写流写器：取柄、察锁与容量、候 ready/closed、先发写与闭之待柄，客可先读下游再候诸果。本地 workerd 以 gzip 验两块在途写、闭、读及 `00 FF 41` 解还；有效写器之中断与无效柄之安全归误亦验。Wrangler 4.129.0 原生最小例见：流已闭或已中断，虽释写锁，`writable.locked` 犹真；流尚开而释则假。宿主如实归平台之值，待新版再核。满载背压与读端错事尚待验，详 `可写流接口.清单.tsv` 与 [Cloudflare WritableStreamDefaultWriter 文档](https://developers.cloudflare.com/workers/runtime-apis/streams/writablestreamdefaultwriter/)。

`压缩流。豫` 有 CompressionStream、DecompressionStream 造流、读写端柄及短字安全转换。本地 workerd 三式 gzip、deflate、deflate-raw 以原字 `00 FF 41` 往还；按需源复两次入豫言，供块经压解双管而六字复得。坏 gzip 与无效格式归阴及 UTF-8 误字。坏 gzip 同使 workerd 记 `Uncaught TypeError`，虽写、读二 Promise 皆显候，请事犹成，此运行时之迹待究。一次转换于宿主聚全出字，大流宜执端柄；满载背压与取消尚待验。Cloudflare 文档今唯列三式，详 `压缩流接口.清单.tsv` 与 [Workers Web standards](https://developers.cloudflare.com/workers/runtime-apis/web-standards/)。

`事件源。豫` 可依址联、依所授服务取流，或以 Cloudflare `EventSource.from(ReadableStream)` 接既有流；客可订名、候事、察态而闭联。本地 workerd 从 SSE 服务与豫言按需流皆得 `notice`、文「甲」及号 `7`；双豫言云工亦经所授 SERVICE 绑定得同信。重联、错事及跨请之寿尚待验，详 `事件源接口.清单.tsv` 与 [Cloudflare EventSource 文档](https://developers.cloudflare.com/workers/runtime-apis/eventsource/)。

`消息通道。豫` 使豫言于同次云工事造二端、传象值与原字、候信及闭事。本地 workerd 已验物值、`00 FF 41` 与断端之告。Cloudflare 今惟许同一 Worker 实例内用，不许转移列或转移消息端；此乃平台之界。复杂克隆、错事与跨事存续尚待验，详 `消息通道接口.清单.tsv` 及 [Cloudflare MessageChannel 文档](https://developers.cloudflare.com/workers/runtime-apis/messagechannel/)。

Console 子书 `控制台。豫` 有五等文字志门，亦有以癸象列文传诸参数之通门。Wrangler 4.129.0 本地 workerd 五等皆见，多参 `log` 仍存数与物。`count`、`assert` 可调，然平台诸法有仅部行及无为者，`createTask` 于云上则抛错，不可因可调而谓皆有效。详 `控制台接口.清单.tsv` 及 [Cloudflare Console 文档](https://developers.cloudflare.com/workers/runtime-apis/console/)。

TCP 子书 `传输控制。豫` 依 Workers `cloudflare:sockets`。豫言可择 `off`、`on`、`starttls` 与半开之义，候开，逐字读写，闭联或升密；事故由安全门归文。Wrangler 4.129.0 本地 workerd 连本地回声，原字 `00 FF 41` 往还而闭，逐字皆合；联无可达之埠，开联之误亦归客。升密、久联及云上限尚待验，详 `传输控制接口.清单.tsv`。[Cloudflare TCP sockets 文档](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/)载其接口与平台约束。

常工之子协议今由豫言读取 `Sec-WebSocket-Protocol` 请标，择请中一名，宿主于 HTTP 101 回写。真 Chrome 提 `yuyan.v1`、`backup.v1`，豫言择前者，浏览器读 `WebSocket.protocol=yuyan.v1` 而信往返。非法 token 之界未验；协商之据见 [WebSocket 子协议标头](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Sec-WebSocket-Protocol/)。

持久对象亦有同一择协议之径：`云工持久套接字建对并应答协议` 使豫言于对象升请中择所提之名。真 Chrome 提 `yuyan.do.v1`、`backup.v1`，读回前者；静答、附件、断联仍得验。非法 token 与拒协之界尚待验。

云工外发 `new WebSocket(url)` 今有豫言门与诸事复入。真 workerd 连本地 Node `ws` 服务：开则客送「豫言」，得「回:豫言」复送 `00 FF 41`，逐字验返，断联记 1000 与「完成」。连不可达端口，则豫言得错事与 1006、非正常之断联事。宿主置 `binaryType=arraybuffer`，以 `ctx.waitUntil` 候至断联，并记回调事故；今唯短联得验，长联寿命与子协议尚待验。[Cloudflare 示例](https://developers.cloudflare.com/workers/examples/websockets/)列二外发径。

第二外发径 `云工套接字请求出站` 以 `fetch` 携 `Upgrade: websocket` 求原生长联而接之。真本地 workerd 与 Node `ws` 验开、文、`00 FF 41` 字及常断。半开为阳，远端先断，豫言于断事读 `readyState=2`，再自断以终握手。长联寿命、拒升、子协议与代理竞态尚待验；半开之据见 [Cloudflare WebSocket 示例](https://developers.cloudflare.com/workers/examples/websockets/)。

持久对象之长联休眠接口今入通用外壳：`webSocketMessage`、`webSocketClose`、`webSocketError` 皆转豫言 Wasm；对象内可接联、按标签取联、读写附件。Wrangler 4.129.0 本地 workerd 与真 Chrome 验两信之间附件「始」转「续」、标签寻联，断联回调入持久仓，代码 1000、原因「完成」、正常为阳。依 [Cloudflare 文档](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)，本地可交休眠式回调而不真逐对象；云上休眠后重建与附件恢复尚未验。

# HTML 改写

`云工HTML改写响应` 受原答柄与选择器，还流式新答柄，可交 `云工设置响应句柄`。每中一元，复启同一豫言 Wasm，以 `html-element` 事相告；客取元素柄，当回调未竟之时，察而改之。回调可候异步术。Wrangler 4.129.0 真本地 workerd 验二元各依 `data-n` 得别字及新内文。异步处理之据见 [HTMLRewriter 文档](https://developers.cloudflare.com/workers/runtime-apis/html-rewriter/)。

`云工HTML改写响应全` 受诸事件之列，可登元、文、注、篇首、篇文、篇注、篇终；`云工HTML改写响应规则` 受诸选择器及篇事之列。事名冠 `html-`，以 `云工HTML当前句柄` 取当时之物。元事可行 `云工HTML登记尾签`，及尾以 `html-end-tag` 复入客器。真 workerd 验二选择器与尾签前后所插之文；分块一文节得「甲」「乙」及空之终块，须据 `lastInTextNode` 理之。余元法可循通用柄而须逐验。答为流，事故或于答已始后传之。

元具名诸术今及属性之枚举、察有、增删、签名与命名空间、改名、已移之态、前后与内首尾插、替换、移元、去签留文。插文之为正文抑原 HTML，由客定；正文依平台转义。六元合验于真 workerd，见 `HTML元素全法。测试。豫`。

`云工HTML内容句柄操作` 可以客造 Response 或 ReadableStream 入改写器。真 workerd 验答物替换与三块流物内文。元回调之中若主动写流两块，解析器与写者互候而悬；`云工创建回调可读流` 使下游索块时以 `stream-pull` 复入豫言 Wasm，客以 `云工流回调供块` 还字、后态与终否，故三块皆出。客于回调发事故，则本地已送 HTTP 200 与一段 HTML，后文截断并记事故；欲得全答，须先消费验之而后送。客断连及供者之误尚待验，详 `流接口.清单.tsv`。

按需流之取消又验于真 workerd：客取首块，行 `云工取消流读取器`，底层以 `stream-cancel` 复入豫言 Wasm；客读后态「次」与原因「停」，写 KV，原请候毕复读得同标。此唯显式 reader 取消之验；HTTP 客断连及取消回调自误尚待验。

`云工读取流块安全` 归成否与癸象块文或误文；成则以 `云工解安全流块` 取有字否与原字节，随释暂柄，终则归无字。真 workerd 验「甲」之 UTF-8 字无损、终记，且供者回调发事故时，原 HTTP 客可得显式误而正常作答。余误类与客断连尚待验。
