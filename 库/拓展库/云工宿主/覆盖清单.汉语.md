# Cloudflare Workers 宿主覆盖清单

TextEncoderStream/TextDecoderStream 已有豫言接口。Wrangler 4.129.0 本地 workerd 验证两段文字写入得到六字节 UTF-8、三字节汉字拆成两段后完整读回、跨块 BOM 默认去除，并核对 `encoding`、`fatal`、`ignoreBOM` 属性；坏 UTF-8 在严格模式下经安全读取返回 TypeError，非严格模式产出替换字符。背压与云端部署待验，详 `流式编码接口.清单.tsv`。[Encoding 标准](https://encoding.spec.whatwg.org/#interface-textdecoderstream)规定流式转换。[Cloudflare Web 标准接口](https://developers.cloudflare.com/workers/runtime-apis/web-standards/)列出两种转换流。

可取消 fetch 已在 Wrangler 4.129.0 本地 workerd 验证：豫言先取得在途请求句柄，再中止 AbortSignal，安全等待返回 AbortError；未中止的本机 HTTP 请求返回 Response 句柄、状态 200 和正文。预先中止的自定理由及无效 Promise 句柄也已验，云端待验，详 `网络中断接口.清单.tsv`。[Cloudflare Request 文档](https://developers.cloudflare.com/workers/runtime-apis/request/)列出 `signal` 选项。

AbortController/AbortSignal 子库已在 Wrangler 4.129.0 本地 workerd 验证控制器中断、对象与文字理由、重复中断、`abort()`/`any()`/`timeout()` 静态方法、`throwIfAborted()` 安全检查和 `abort` 事件等待。本地 workerd 的 `timeout(-1)` 会创建随后中断的信号，真实 Chrome 则返回 RangeError；库保留原生差异，云端待验。详 `中断接口.清单.tsv`。[Cloudflare Web 标准接口](https://developers.cloudflare.com/workers/runtime-apis/web-standards/)列出 AbortController/AbortSignal。

URI 与 URI 成分的四种编解码方法已在 Wrangler 4.129.0 本地 workerd 验证，坏 `%` 转义和非法 UTF-8 返回 `URIError` 文本。`云工调用全局安全` 也已验证同步异常和 Promise 拒绝均变成显式结果，详 `网址编解码接口.清单.tsv`。[ECMAScript URI 函数](https://tc39.es/ecma262/multipage/global-object.html#sec-decodeuricomponent-encodeduricomponent)定义错误语义。

`云工调用方法安全` 已在 Node 宿主用真实 Wasm 验证：句柄方法成功时返回真与结果 JSON，同步异常（如 `JSON.parse` 的 SyntaxError）和不存在的方法返回假与含名称、消息的错误 JSON；关系数据库适配用它读到 D1 的 SQL 语法错与批内约束冲突原文。workerd 与 Promise 拒绝路径待验，详 `句柄接口.清单.tsv`。

FormData 子库已在 Wrangler 4.129.0 本地 workerd 验证：重名字段顺序、文字与文件的追加和设置、删除与查询、键值迭代，以及 Request/Response 的 multipart 往返；文件 `00 FF 41` 无损。云端部署待验，详 `表单数据接口.清单.tsv`。[Cloudflare Request 文档](https://developers.cloudflare.com/workers/runtime-apis/request/)确认 FormData 可作请求体及由 `request.formData()` 读取。

Workflows 回滚现通过独立 `workflow-rollback` 事件重新进入豫言 Wasm。本地 workerd 中，前向步骤成功并进入等待后，`terminate({rollback:true})` 触发豫言回滚分支，读取前向步骤输出并写入 KV；终止前 KV 为空，终止后读到“豫言回滚已行”。多步骤逆序、回滚失败重试及生产行为待验，详 `工作流接口.清单.tsv`。

Workflows 批量接口和绝对时间休眠已增加豫言入口。本地 workerd 一次创建两实例，批量删除返回两条成功和一条不存在实例的逐项错误；豫言以 `Date.now()` 计算一秒后的目标，CLI 记录一秒 `Sleeping` 步骤。重复批量创建未重跑实例，但本地仍返回原有两个 ID，与官方文档描述不同，待云端或新版模拟器核对；过去目标时刻会报错。Worker 时钟其余接口见 `时钟接口.清单.tsv`，工作流边界见 `工作流接口.清单.tsv`。

Workflows 已有首批豫言接口和构建导出的通用 `WorkflowEntrypoint`。Wrangler 4.129.0 本地 workerd 中，豫言创建实例、执行持久 `step.do`、等待 `waitForEvent`，另一次 HTTP 请求发送事件后完成；第二个实例在固定持久目录下停止并重启 workerd，仍保持等待，收到事件后完成。CLI 步骤历史显示成功的豫言步骤输出。回滚、更多实例管理、非 JSON 值和云端语义待补；本地一次完成后出现请求挂起告警，见 `工作流接口.清单.tsv`。

同版本 workerd 又验实例暂停、恢复、从指定步骤重启、终止与删除：状态分别经过 `paused`、`running`、`complete`、重启后的 `running`，另一个实例到 `terminated`，删除后 `get` 报 `instance.not_found`。回滚选项、批量边界、订阅与云端限制仍待补；暂停附近出现的本地引擎中断及请求挂起告警仍需定位。

Encoding 与 Scheduler 已有专门豫言接口。Wrangler 4.129.0 本地 workerd 以真实豫言 Wasm 验证 UTF-8 往返、跨三个字节的流式解码、`encodeInto` 的容量边界、`scheduler.wait` 正常完成及 `AbortSignal` 取消返回 `AbortError`。编码异常、计时精度、云端时钟行为及资源释放仍待验，详 `编码调度接口.清单.tsv`。

Secrets Store 账号级异步 `get()` 已以本地假 Secret 经真实 workerd 验证；它使用独立 `SECRETS_STORE` 许可，生产数据、轮换及缺失值语义待验，详 `密仓接口.清单.tsv`。

环境变量、Secrets、Version metadata 和 Analytics Engine 已有具名豫言接口。Wrangler 4.129.0 本地 workerd 验证文本、空值、JSON、无敏测试 Secret、版本三字段及两种 Analytics 数据点调用；Analytics 的云端持久化与查询仍待验，见 `基础绑定接口.清单.tsv`。

Rate Limiting 绑定已由豫言以具名许可调用；本地 workerd 的 1 次/10 秒配置验证同键拒绝与异键放行。生产多地区和最终一致性边界待验，详 `限流接口.清单.tsv`。

密钥生命周期扩展已在 Wrangler 4.129.0 本地 workerd 验证：可导 AES-GCM 钥的生成、导出和再导入；PBKDF2、HKDF 以 SHA-256 派生 256 位字节与不可导 AES 钥，并互通加解密。其他密钥格式、用途、算法及异常边界仍待逐项补齐。

Web Crypto 的随机 UUID、随机字节、SHA-256、AES-GCM 与 HMAC 已在 Wrangler 4.129.0 本地 workerd 用真实豫言 Wasm 验证；其他算法、密钥格式、派生、密钥封装与 Workers 扩展仍待补，详 `密码接口.清单.tsv`。

Dynamic Worker Loader 已通过真实本地 workerd 验证：豫言父 Worker 接收子程序 Wasm 字节，分别经 `load` 和 `get` 装载豫言子 Worker、取得入口并转发原生 Request；两条路径均返回子程序 HTTP 200，`get` 的同标识重复调用也成功。子 Worker 模块源码和值桥由豫言构建器打包。当前只封装固定豫言子程序、空绑定、禁外发网络和 CPU/子请求限额；命名入口、RPC、限额触发与生产缓存行为待补，见 `动态工接口.清单.tsv`。

基线日期：2026-09-24。范围以 Cloudflare 官方[运行时 API](https://developers.cloudflare.com/workers/runtime-apis/)和[绑定 API](https://developers.cloudflare.com/workers/runtime-apis/bindings/)目录为准。当前只完成部分文字请求与绑定操作；下列“接口已有”不代表该能力完整覆盖。

`接口能力.清单.tsv` 固定了运行时与绑定的一级能力，并补录官网目录之外的 Send Email 绑定，共 47 类（运行时 22 类，绑定 25 类）。`事件接口.清单.tsv` 开始逐项记录事件方法与验证方式。`部分` 只表示已有示例通路，`待补` 表示尚无专门封装；还需要把每类展开为具体构造器、属性、方法、事件和兼容日期，逐项验收。

`云仓能力验收.汉语.md` 按当前 `yuyan-cloud` 的实际业务入口记录 Assets、Service、Durable Object、Queue、Send Email、Worker Loader 等依赖及本地验收状态；业务代码没有迁移。

通用句柄桥已验证由豫言读取原始 Request 正文，以及构造并返回原生 Response；句柄调用支持 Promise 等待与保留原始 Promise。它为后续 API 提供通路，尚未替代逐项能力授权与真实 workerd 行为验证。

二进制桥已用真实 Wasm 验证 `Request.arrayBuffer()` 到豫言字节串，再由豫言构造二进制 Response；`0x00`、`0xff` 均无损。另以 Wrangler 4.129.0 的本地 workerd、compatibility date `2026-09-10` 实测三字节 POST 返回 HTTP 201，响应字节与输入逐字节相同。当前单次值交换上限为 16 MiB，长流与取消仍待验证。

流桥已在同版本本地 workerd 验证：豫言以读取器逐块读取请求，在设置 Response 后继续向 `ReadableStream` 写入三块数据，HTTP 201 响应依次得到 `00 FF 41`。这是短流验收；长流、取消、错误后的流终止及真实云端限制尚待验证。

Cache 子库已通过 Wrangler 4.129.0 本地 workerd 测试：取得 `caches.default`、打开具名缓存，将豫言构造的 Response 写入，匹配后读取正文，再删除并确认未命中；请求返回 HTTP 200“缓存往返通过”。[Cloudflare Cache 文档](https://developers.cloudflare.com/workers/runtime-apis/cache/)说明它与浏览器 Cache API 有差异，尤其是响应缓存控制和查询选项。当前仅覆盖 `open`、`default`、`put`、`match`、`delete` 的基本路径，未测试真实云端的数据中心行为。

Assets 与 Service binding 已新增原生句柄路径。Wrangler 4.129.0 本地 workerd 将豫言构造的改址 Request 交给 `ASSETS.fetch`，真实静态文件返回 HTTP 200、`asset-ok`；两份豫言 Wasm Worker 经 Service binding 相连，POST 请求得到 HTTP 201，`00 FF 41` 三字节响应无损。测试覆盖请求方法、标头和正文在改址后的传递；真实云端与完整路由行为仍待验。[Assets binding](https://developers.cloudflare.com/workers/static-assets/binding/)和[Service binding HTTP](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/http/)为接口依据。

Queue 子库现有 `send`、`sendBatch`、`metrics` 和消费者批次、逐条 `ack/retry` 的豫言接口。Wrangler 4.129.0 本地 workerd 实测 HTTP 投递返回 202，随后消费事件把状态写入 KV，另一次 HTTP 请求读到“已消费”；Node/V8 上真实 Wasm 还验证逐条确认与延后重试。生产者选项、结构化克隆的全部值类型、批次失败与重试时序尚未完整验收。邮件子库的 `EmailMessageBuilder` 文字字段已用模拟绑定和真实 Wasm 验证，未实际发送邮件。[Queue JavaScript APIs](https://developers.cloudflare.com/queues/configuration/javascript-apis/)与[Email Workers API](https://developers.cloudflare.com/email-service/api/send-emails/workers-api/)为接口依据。

事件分派现支持 `fetch`、`queue`、`scheduled`、`email`，均由同一豫言 Wasm 程序按 `云工事件种类` 处理。定时事件的 cron、计划时刻和 `noRetry` 已在本地 workerd 验证；入站邮件的信封、标头、MIME 原文首块及拒收已在本地邮件端点验证。入站转发及附自定义标头的转发已在真实 Wasm 与模拟对象中验证；回复已由豫言生成 MIME、经本地 workerd 验证；完整 MIME 解析尚待补齐。[Scheduled handler](https://developers.cloudflare.com/workers/runtime-apis/handlers/scheduled/)及[Email handler](https://developers.cloudflare.com/email-service/api/route-emails/email-handler/)列出平台接口。

Workers 的 URL 与 URLSearchParams 已有具名豫言入口，并在 Wrangler 4.129.0 本地 workerd、兼容日期 `2026-09-10` 验证真实请求的 URL 解析、活动查询参数修改及静态相对解析；响应返回 `http://127.0.0.1:8805/a/b?x=1&y=a+b#done`。该兼容日期晚于 `url_standard` 默认启用日。对象 URL 在同一 workerd 明确报未实现，云工库不对其提供具名入口。其余成员与边界见 `网址接口.清单.tsv`。[Cloudflare 兼容标志](https://developers.cloudflare.com/workers/configuration/compatibility-flags/)列出 `url_standard` 的生效条件。

Durable Object 已由构建外壳导出通用类，同一豫言 Wasm 接收 `durable-fetch`、`durable-alarm`、`durable-transaction` 和休眠式套接字事件。Wrangler 4.129.0 本地 SQLite 对象实测：默认 Worker 向同名桩发请求，对象写字符串 KV、执行参数化 SQL、设置 alarm，告警事件写入标记；停止并重启本地 workerd 后，另一请求仍读到“已持久|已触发|SQL已持久”。`持久对象接口.清单.tsv` 逐项区分已测与待补能力。此验证只证明本地持久化路径；旧 KV 后端事务、非 JSON 结构化克隆值、对象并发控制与真实 WebSocket 休眠恢复仍待验收。[SQLite 存储文档](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)与[告警文档](https://developers.cloudflare.com/durable-objects/api/alarms/)为接口依据。

Durable Object 的 JSON 兼容值与同步 SQL 事务又通过本地 workerd 验证：豫言写入含布尔值与数组的对象，两条参数化 INSERT 在同一 `transactionSync` 中提交；另一事务的第二条 SQL 故意引用不存在的表，返回 SQLite 错误，再次查询仍只有原先两行。停止并重启 workerd 后，对象、告警标记与 SQL 行仍可读取。异步 `storage.transaction` 回调亦已重入豫言，验证两键条件提交后从 `10|3` 变为 `9|4`，显式回滚和豫言异常均保持 `9|4`。旧 KV 后端、并发冲突、任意结构化克隆类型和生产故障恢复尚待验收。[Cloudflare 事务文档](https://developers.cloudflare.com/durable-objects/api/legacy-kv-storage-api/#transaction)说明回调与 `txn` 的语义。

Durable Object 的 `list` 已提供豫言接口。本地 workerd 验证前缀、范围、逆序、数量限制、分页起点、JSON 对象值，以及事务内新键可见且回滚后消失。旧 KV 后端及特殊结构化克隆值仍需验收，详 `持久对象接口.清单.tsv`。[Cloudflare 列举文档](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#list)为选项依据。

多键 `get/put/delete` 亦有豫言接口。本地 workerd 验证批读排序与缺失键省略、批写 JSON 对象、批删计数，并验证事务内批读新值及回滚后值不变；选项、旧 KV 后端与特殊结构化克隆值仍待验。[Cloudflare 异步 KV 文档](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#asynchronous-kv-api)为重载依据。

`sync` 与 `deleteAll` 已接入豫言。Wrangler 4.129.0 本地 SQLite 对象中，`allowUnconfirmed` 写入经 `sync` 后重启仍在；清仓删除 KV、SQL 表和 alarm，重启后仍为空。workerd 对清仓的 `allowUnconfirmed` 选项提示禁用，旧 KV 后端和云端行为待验。[Cloudflare 存储文档](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#deleteall)为接口依据。

SQLite 同步 `storage.kv` 的读写删除列举已接入豫言。本地 workerd 验证同步与异步接口读写互见、缺键与 null 区分、逆序限量、删除返回值和重启持久性。事务缺键的单文读取也已通过最小测试；先前额度应用的模式匹配失败已定位为业务侧嵌套匹配问题，由独立云仓任务修正。[Cloudflare 同步 KV 文档](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#synchronous-kv-api)为接口依据。

构建器可将通用 `WorkerEntrypoint` 导出为 `CloudModel` 等单个应用别名。本地 workerd 的同 Worker Service binding 已验证公网默认请求为 `fetch`、命名入口请求为 `service-fetch`，由豫言分别响应。可选 Secret 读取已用本地假绑定验证缺失、空串及有值，响应不含密钥。自定义 RPC 方法、多别名、生产 Secret 和云端部署待验。[Cloudflare 命名入口文档](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/rpc/#named-entrypoints)为接口依据。

SQLite `SqlStorageCursor` 已有逐行对象、`raw()` 原始行、余行、`one()` 安全结果、列名、读写行数及数据库大小的豫言接口。Wrangler 4.129.0 本地 workerd 验证混合迭代、三种单行结果和统计；跨异步边界的快照限制仍按平台语义。[Cloudflare 游标文档](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#exec)为接口依据。
