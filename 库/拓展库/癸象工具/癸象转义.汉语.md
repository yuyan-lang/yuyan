# 癸象 JSON 字符串转义

本文说明 `癸象解析` 与 `癸象表示` 如何处理 JSON 字符串里的转义。

- 解码由运行时内建原语 `豫言_字符串获取JSON字符串` 完成。WasmGC 目标（凡由 `豫言操作系统/宿主/网页汇编/运行时.wat` 组装的程序，含云工与浏览器）实现在其 `$json_string`；原生目标实现在 `豫言操作系统/宿主/原生/运行时/字符串.c`。两处行为一致。
- 编码由本目录 `癸象数据结构。豫` 的 `癸象字符串转义` 完成（键名与字符串值都经过它）。

## 解码

| 写法 | 结果 |
| --- | --- |
| `\"` `\\` `\/` | 双引号、反斜杠、斜杠 |
| `\b` `\f` `\n` `\r` `\t` | 退格（8）、换页（12）、换行（10）、回车（13）、制表（9） |
| `\uXXXX`（四位十六进制，大小写均可） | 该码点的 UTF-8。例：`中` 得「中」，`\u001b` 得字节 27，`é` 得两字节 |
| 高代理项 `\uD800`–`\uDBFF` 之后紧随低代理项 `\uDC00`–`\uDFFF` | 合并为一个码点，写成四字节 UTF-8。例：`😀` 得 U+1F600 |
| 孤立的高代理项或低代理项 | 替换为 U+FFFD（EF BF BD），与 `TextEncoder` 对 JS 字符串中孤立代理项的处理一致 |
| `\u0000` | 字节 0（见下文取舍） |
| 其余任何反斜杠写法：`\u` 后不足四位或含非十六进制字符、`\x41`、`\0`、`\a`、末尾的孤反斜杠 | 畸形。运行时中止：WasmGC 为 `unreachable` 陷阱，原生为报错退出。豫言的 `尝试运行` 捕获不到；云工应用里表现为本次事件失败（壳边界的 `RuntimeError`） |

- 字符串里未转义的原始字节（含原始控制字符与任意 UTF-8）依旧宽容，原样保留，不校验 UTF-8 是否有效；这是旧行为，未改。
- 宿主 JS 的 `JSON.stringify` 对控制字符输出 `\u00xx`，对孤立代理项输出 `\udXXX`（良构 JSON.stringify）。经句柄桥传回豫言的 JSON（查询参数、标头值、`request.json()` 的结果……）因此可含 `\u001b` 之类，现在都能正确解码。
- 应用若把**不可信的原始 JSON 文本**直接交给 `癸象解析`，畸形转义会使整个事件中止而不是返回 400。应像 `读取入站癸象正文文` 那样，先让宿主 `JSON.parse` 校验，再由宿主 `JSON.stringify` 交给豫言。

## 编码

`癸象表示` 输出的字符串与 ECMAScript 的 `JSON.stringify` 逐字节一致：

| 字符 | 输出 |
| --- | --- |
| `"` `\` | `\"` `\\` |
| 退格、制表、换行、换页、回车 | `\b` `\t` `\n` `\f` `\r` |
| U+0000–U+001F 中其余的控制字符 | `\u00xx`，四位、十六进制**小写**（如 `\u001b`） |
| `/`、U+007F（DEL）、U+2028、U+2029 与所有其他字符 | 原样输出，不转义 |

快速路径 `癸象字符串无需转义` 把小于 0x20 的字节、双引号、反斜杠视为需要转义，其余字节的字符串原样返回。不含控制字符的字符串，输出与旧版逐字节相同，编译缓存 JSON 不受影响；含 `\n` `\t` `\r` `\b` `\f` 的输出也与旧版相同；只有过去被原样写出的其他控制字符（如 ESC）现在写作 `\u00xx`，从而成为宿主 `JSON.parse` 能接受的合法 JSON。

## 取舍与边界

1. `\u0000` 解出字节 0。豫言字符串是带长度的字节数组（WasmGC 为 `$bytes` 数组，原生为“长度加隐藏结尾零”的缓冲区），字节 0 不作串尾，`癸象表示` 会把它再写回 `\u0000`，往返无损。代价是：把这样的字符串交给按 C 字符串处理的宿主原语（例如文件路径、进程参数）时可能在 0 处截断，使用者自行判断。
2. 孤立代理项有损：UTF-8 无法表示它们，只能替换为 U+FFFD。不采用“中止”（公开接口会被一条畸形数据拒绝服务），也不采用把代理项直接编成三字节（那会产生非法 UTF-8，`TextDecoder` 与 `JSON.parse` 都会改写或拒绝）。
3. 畸形转义仍然中止，与旧行为一致；库没有提供“容错解析”。
4. 编码器不转义 U+2028、U+2029 与 DEL，与 `JSON.stringify` 一致；合法 JSON 允许它们出现在字符串里。
5. JS 的“逐 UTF-16 码元”视角与本库无关：豫言字符串按 UTF-8 字节存储，`串长度` 按码点计数；非 BMP 字符在本库里是一个字符（四字节），不是两个码元。

## 验证

- `癸象数据结构。测试。豫`：编码器（全部 31 个控制字符、DEL、U+2028/2029、`/`、键名、数组）与宿主无关的解析；原生与 WasmGC 都可运行。（其中三个小数用例 `1.2`、`12.12`、含小数的数组因 `小数表示` 输出 `1.200000` 而失败，与转义无关，改动前已如此。）
- `癸象转义。测试。豫`：`\u` 解码（大小写、代理对、孤立代理项、`\u0000`、DEL、U+2028/2029、往返），需 WasmGC 运行时，或重建原生运行时库（`make 运行时`）后原生运行。
- `豫言操作系统/宿主/网页汇编/一致性验证/`：`$json_string` 的穷举低层对拍（全部 65536 个 `\uXXXX`、全部 1048576 个代理对、畸形必陷阱）与端到端云工应用对拍，见其中 `说明.汉语.md`。
