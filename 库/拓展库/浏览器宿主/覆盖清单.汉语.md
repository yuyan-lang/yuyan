# 浏览器宿主覆盖清单

BroadcastChannel 子库已在真实 Chrome 验证：页面内两个豫言频道双向传 JSON 兼容值，单向传 `00 FF 41` 原始字节；页面与 Dedicated Worker 中的豫言 Wasm 还经同名频道跨上下文通信。`messageerror`、复杂结构化克隆和跨标签页场景待验，详 `广播频道接口.清单.tsv`。[HTML 广播频道规范](https://html.spec.whatwg.org/multipage/web-messaging.html#broadcasting-to-other-browsing-contexts)定义通信范围与关闭语义。

TextEncoderStream/TextDecoderStream 已有豫言接口。真实 Chrome 验证两段文字写入得到六字节 UTF-8、三字节汉字拆成两段后完整读回、跨块 BOM 默认去除，并核对 `encoding`、`fatal`、`ignoreBOM` 属性；坏 UTF-8 在严格模式下经安全读取返回 TypeError，非严格模式产出替换字符。背压待验，详 `流式编码接口.清单.tsv`。[Encoding 标准](https://encoding.spec.whatwg.org/#interface-textdecoderstream)定义跨块解码语义。

可取消 fetch 已在真实 Chrome 验证：豫言先取得在途请求句柄，再中止 AbortSignal，安全等待返回 AbortError；未中止请求返回 Response 句柄、状态 200 和正文。预先中止的自定理由及无效 Promise 句柄也已验，详 `网络中断接口.清单.tsv`。[Fetch 标准](https://fetch.spec.whatwg.org/#dom-global-fetch)定义 signal 与中止行为。

AbortController/AbortSignal 子库已在真实 Chrome 验证控制器中断、对象与文字理由、重复中断、`abort()`/`any()`/`timeout()` 静态方法、`throwIfAborted()` 安全检查和 `abort` 事件等待。`timeout(-1)` 返回 RangeError，详 `中断接口.清单.tsv`。[DOM 中断标准](https://dom.spec.whatwg.org/#aborting-ongoing-activities)规定信号语义。

URI 与 URI 成分的四种编解码方法已在真实 Chrome 验证，坏 `%` 转义和非法 UTF-8 返回 `URIError` 文本。`浏览器调用全局安全` 也已验证同步异常和 Promise 拒绝均变成显式结果，详 `网址编解码接口.清单.tsv`。[ECMAScript URI 函数](https://tc39.es/ecma262/multipage/global-object.html#sec-decodeuricomponent-encodeduricomponent)定义错误语义。

Event/EventTarget 已增加具名豫言接口。真实 Chrome 验证了原生捕获与目标阶段、`once`、AbortSignal 撤听、同目标同名多监听器独立撤销、`passive` 不取消默认动作、同步止传播与同处后续监听器、`dispatchEvent()` 返回值，以及在回调当刻保存 target、currentTarget、composedPath 和 eventPhase。默认被动策略和旧属性边界仍待验，详 `事件接口.清单.tsv`。[DOM 标准](https://dom.spec.whatwg.org/#events)规定传播和监听选项。

FormData 子库已在真实 Chrome 验证：空构造、从表格和提交按钮构造、重名字段顺序、文字与文件的追加和设置、删除与查询、键值迭代，以及 Request/Response 的 multipart 往返；文件 `00 FF 41` 无损。更多表格控件待验，详 `表单数据接口.清单.tsv`。[XMLHttpRequest 标准](https://xhr.spec.whatwg.org/#interface-formdata)规定 FormData 语义。

FormDataEvent 的构造、事件队列读取和原生 `formdata` 投递已在 Chrome 验证。事件同步触发，豫言稍后读取队列，因此不能据此修改已完成的原生提交；业务可预先拦截 `submit`，由豫言读取 `SubmitEvent.submitter` 并构造、修改和发送 FormData。该路径已以真实 `requestSubmit` 及 multipart 往返验证，详 `表单数据接口.清单.tsv`。[HTML 表单提交标准](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#form-submission-algorithm)规定事件顺序。

Blob/File 子库已在真实 Chrome 验证原始 `00 FF 41`、BlobPart 组合、负索引切片、原生 `bytes()`、字节流与 `textStream()`，以及文件名、MIME 和修改时间。FileReader 四种读取方式、生命周期事件和 FileList 已通过真实 Chrome 测试；文件由程序注入输入框，真实用户选择文件流程及错误事件待验。详 `物字文件接口.清单.tsv` 与 `文件读取接口.清单.tsv`。[W3C File API](https://w3c.github.io/FileAPI/)规定这些对象的字节、事件和元数据语义。

WritableStream writer 已在真实 Chrome 验证：豫言先发两块原字和关闭操作，在读取 gzip 输出后逐一等待成功，解压读回 `00 FF 41`；锁定、初始 ready、关闭后的 closed、释放及有效写器中止也通过。满载背压待验，详 `可写流接口.清单.tsv`。[Streams 标准](https://streams.spec.whatwg.org/)定义写器状态与背压。

CompressionStream 与 DecompressionStream 已有豫言入口。真实 Chrome 验证 gzip、deflate、deflate-raw 的 `00 FF 41` 无损往返，以及坏 gzip 和无效格式的安全错误；豫言主动写两块字节，经压缩与解压两层管道后亦逐字节读回。满载背压与浏览器差异待验，详 `压缩流接口.清单.tsv`。[Compression 标准](https://compression.spec.whatwg.org/)列出格式和错误条件。

浏览器定时子库已把一次和周期定时转为豫言事件队列消息；真实 Chrome 收到三次周期事件、取消后返回正确状态，再收到一次性事件。事件含编号、标记、种类和实际触发时刻，业务刷新由豫言决定；后台页的节流与长时间运行尚待验，详 `定时接口.清单.tsv`。[HTML 定时器规范](https://html.spec.whatwg.org/multipage/timers-and-user-prompts.html)说明回调时序与取消。

EventSource 子库已在真实 Chrome 从跨源本地 SSE 服务接收自定义 `notice`、数据“甲”和事件号 `7`，随后由豫言关闭。普通 message、错误、重连及含凭据模式待验，详 `事件源接口.清单.tsv`。[HTML EventSource 规范](https://html.spec.whatwg.org/multipage/server-sent-events.html)规定连接与重试行为。

MessageChannel 子库已在真实 Chrome 用豫言 Wasm 验证：两端传 JSON 对象，转移二进制缓冲区并读回 `00 FF 41`；第二个通道的端口经第一个通道转移，转入后继续通信。复杂结构化克隆、跨 Worker 传端口与错误事件仍待验，详 `消息通道接口.清单.tsv`。[HTML 消息端口规范](https://html.spec.whatwg.org/multipage/web-messaging.html)规定转移与事件语义。

WebSocket 子库已与云工 WebSocketPair 双端实测：真实 Chrome 的豫言 Wasm 收 open、发送文字“豫言”、收到回文，再发送 `00 FF 41`，逐字节核对二进制回显并在 close 事件后释放句柄。子协议、错误事件、异常关闭、Blob 模式与缓冲边界待验，详 `套接字接口.清单.tsv`。[WebSocket API](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket)列出浏览器接口。

`浏览器请求文字安全` 现在把 fetch 或正文读取失败作为“无响应”返回错误文字，HTTP 错误响应仍返回状态与正文。真实 Chrome 中连接拒绝得到阴和 `TypeError`，本地 HTTP 404 得到阳及状态 404，豫言继续更新页面；重试、取消和超时待补，见 `网络请求接口.清单.tsv`。[Fetch 标准](https://fetch.spec.whatwg.org/)区分网络错误与已取得的 HTTP 响应。

IndexedDB 又增原生 `IDBKeyRange` 句柄和游标快照。真实 Chrome 验证 only、bound、lowerBound、upperBound、includes，bound 范围作为 getAll 参数；对象仓 `prev` 游标和索引 `openKeyCursor` 返回键、主键与值。游标在同一事务的请求回调中继续，豫言决定来源、范围、方向及上限。动态推进、写入游标与非文字键仍待补，详 `索引库接口.清单.tsv`。

IndexedDB 有首批具名豫言接口：豫言声明升级时的 stores/indexes，并一次给出同一事务内的有序操作列表；宿主在事务活动期同步排队，提交后才返回各请求结果。真实 Chrome 验证建仓建索引、批量 put、count、get、getAllKeys、索引 get、缺失值标记、关闭重开、数据库枚举和删除；重复键的 `add` 使同批先前 `put` 回滚，安全入口返回 `ConstraintError`。无头 Chrome 的虚拟时间快照对原生 IndexedDB 探针也未等待完成，最终结果由实际运行的 Chrome 页面验证。游标、键范围、跨事件动态事务、非 JSON 结构化克隆和跨标签页边界待补，详 `索引库接口.清单.tsv`。[Indexed Database API 3.0](https://www.w3.org/TR/IndexedDB/)规定请求及事务生命周期。

受限文档的 Cookie/History `SecurityError` 现有明确适配。新豫言接口返回是否获准；原有接口遇这两类权限拒绝时继续执行，其他 JS 异常仍抛出。使用旧版已编译豫言界面 Wasm 的 JSDOM 沙箱测试在 Cookie getter/setter 和 `history.replaceState` 抛 `SecurityError` 时仍能切换语言；新接口测试确认返回受限状态。正常路径的重新构建产物在真实 Chrome 显示“导航与饼通过”，详 `导航接口.清单.tsv`。

Web Storage 已有两个区域的具名豫言接口：`getItem` 保留缺失值与空字符串的区别，`setItem`、`removeItem`、`clear`、`key`、`length` 已在真实 Chrome 验证。同源 iframe 内的第二个豫言 Wasm 程序写入本地储存，父页豫言程序收到真实 `storage` 事件并验证区域、键与新值。跨标签页、会话区域事件、异常与多文档并发仍待验，详 `储存接口.清单.tsv`。规范依据为 [HTML Standard Web Storage](https://html.spec.whatwg.org/multipage/webstorage.html)。

页面调用豫言的公开操作协议已在真实 Chrome 验收：命名空间注册、事件入队、参数传递、按调用号异步完成与拒绝、并发逆序回复和退出清理均通过；自动启动的就绪 Promise 与既有条件启动也通过。同步返回值仍缺少豫言 Wasm 导出入口，见 `公开操作接口.清单.tsv`。

通用 `浏览器调用方法原始` 的 `Node.appendChild` 返回值已在 Chrome 单独验证，且在注册 MutationObserver 后仍可取回相同 Node 句柄。增强观察样例此前出现的 `illegal cast` 没有在这条最小调用路径复现，具体触发条件仍待定位。

Cookie Store 的异步读、枚举、写、删及 `change` 事件已在 Chrome 经豫言 Wasm 验收；History 回退/前进的 `popstate`、MutationRecord 的类型、目标与新增节点句柄也已验证。Cookie Store 的分区与过期选项、跨文档历史遍历，以及完整 MutationRecord 字段仍需逐项验收。

官网共享界面所需的 Cookie 读写、Location URL、History 推入和替换、MutationObserver 回调及 TreeWalker 文本遍历已有豫言接口并经真实 Chrome 验收；Location 跨页导航、History.go、MutationRecord 全属性和 TreeWalker 过滤器仍待补验，见 `导航接口.清单.tsv` 与 `文树观察接口.清单.tsv`。

密钥生命周期扩展已在真实 Chrome 验证：可导 AES-GCM 钥的生成、导出和再导入；PBKDF2、HKDF 以 SHA-256 派生 256 位字节与不可导 AES 钥，并互通加解密。其他密钥格式、用途、算法及异常边界仍待逐项补齐。

Web Crypto 的随机 UUID、随机字节、SHA-256、AES-GCM 原始钥及 HMAC 原始钥已有具名豫言接口，并在真实 Chrome 中通过摘要长度与首字节、加解密往返和正反验签；其余密钥格式、算法与派生等方法仍待补，见 `密码接口.清单.tsv`。

基线日期：2026-09-24。接口形状以 [W3C Webref 的 curated Web IDL](https://github.com/w3c/webref) 为主，是否已在浏览器提供以 [MDN Browser Compatibility Data](https://github.com/mdn/browser-compat-data) 的 `api` 数据核对。仓库已收录 MDN 8.1.2 的 `api` 原始路径清单及 Chrome、Firefox、Safari 支持摘要，共 10,265 项，来源、哈希与判定规则见 `接口路径来源.json`。支持摘要只表示 BCD 中有无标志且未移除的支持记录；不核对浏览器当前版本、部分实现、实验性或弃用状态。这些路径与 Webref IDL 仅作第一轮同名配对；不得把条数当作待实现 API 数量或覆盖率。

仓库还收录 `@webref/idl` 3.84.0 的原始规范成员清单：334 份规范、3,648 个顶层定义、11,519 个成员，另有 999 个无成员定义，共 12,518 行。来源、解析器版本和哈希见 `规范成员来源.json`。这份清单包含字典字段、常量及不能直接调用的定义，不等于 12,518 个浏览器 JS API；尚需合并 partial、mixin、继承及 BCD 特殊路径。

`规范兼容对齐.清单.tsv` 已对同名 interface、callback interface、namespace 与 BCD `api` 做第一轮机械配对：5,336 行直接找到路径。其余状态及哈希见 `规范兼容对齐来源.json`。直接命中只证明 BCD 有该路径；无同名路径也不证明浏览器无此 API。mixin、includes、继承、别名、特殊功能路径及 BCD 独有路径仍待处理。

`Headers` 的 15 条 BCD 路径已在 `工具/宿主接口清单/标头覆盖.清单.tsv` 逐项记录两端验证与剩余工作；其中一条 BCD 路径并不一定对应一个独立方法。

`Cache` 与 `CacheStorage` 的 17 条 BCD 路径已在 `工具/宿主接口清单/缓存覆盖.清单.tsv` 逐项记录。浏览器 Cache 子库已提供规范中的全部具名方法的基础入口：`Cache.add/addAll/put/match/matchAll/delete/keys` 与 `CacheStorage.open/has/delete/keys/match`。本地真实浏览器加载豫言 Wasm，三份静态资源分别经 `add`、`addAll` 进入缓存，句柄列表与跨缓存匹配、删除均通过，页面显示“缓存往返通过”。[Service Workers 规范](https://w3c.github.io/ServiceWorker/#cache-interface)中的查询选项、批量失败的原子性、异常及 Worker 暴露仍待逐项验证。

`URL` 和 `URLSearchParams` 的 40 条 BCD 路径已在 `网址接口.清单.tsv` 逐项映射。浏览器子库提供构造、相对解析、URL 属性读写、活动 `searchParams`、查询参数修改和数组化枚举、静态解析及 Blob 对象网址入口。真实 Chrome 加载豫言 Wasm 后显示“网址操作通过”，覆盖查询参数修改同步回 URL、重复名称、记录与有序双项构造、静态解析及迭代结果。`forEach` 的原生回调语义、符号迭代及部分属性边界还未验。[WHATWG URL 标准](https://url.spec.whatwg.org/)是接口依据。

当前已验证：豫言 WasmGC 经 JSPI 等待网络结果，按标识更新 DOM；另有点击、输入、变更、提交事件和 Web Storage 基础操作。通用句柄桥已验证豫言调用异步对象方法，并提供构造器、属性、方法及事件订阅入口。现有实现尚未按 Web IDL 逐接口核验，不能记为完整 Fetch、DOM 或 Storage API 覆盖。

`Headers` 的构造、成对初值、get、getSetCookie、has、set、append、delete、entries/keys/values 数组化，以及原生 entries 游标的开启、逐项读取、结束判定和释放，已通过 Node/V8 上的豫言 Wasm 与浏览器宿主桥测试；本地真实浏览器加载构建产物也显示预期结果 `one, two|a=1|b=2|set-cookie|set-cookie|a=1|set-cookie|b=2`。`forEach` 有豫言快照回调。尚未逐项核验遍历期间修改标头的实时语义、保护状态和不同浏览器间的差异。[Fetch 规范](https://fetch.spec.whatwg.org/#headers-class)列明接口形状。

二进制桥已用 Node/V8 上的真实 Wasm 验证：豫言字节串经 `Uint8Array` 句柄交给 Blob，再由 `arrayBuffer()` 返回；零字节与高位字节均无损。单次值交换上限目前为 16 MiB，大文件与长流仍待验证。

流桥已用真实 Wasm 验证三块 `00`、`FF`、`41` 经 `ReadableStream` 进入 `Response.arrayBuffer()`；本地浏览器测试页显示“浏览器流式往返通过”。事件订阅亦通过 Node/V8 的 `EventTarget` 回调测试。长流、取消与跨浏览器行为仍待逐项验证。

完成判据：对基线中每个适用接口记录规范、运行环境、浏览器支持、豫言声明、JS 适配、行为测试及不支持理由。每个能力子库须覆盖该能力可用的构造器、属性、方法、事件、异步结果、异常与对象生命周期。新增规范及浏览器版本另立增量，不以只存在声明视为完成。

浏览器构建产物现包含 `自动启动.mjs`：页面仅用 module script 标签即可启动豫言 Wasm，可选 `标识` 查询参数控制是否启动。真实 Chrome 已验证有指定 DOM id 时显示“网址操作通过”，缺少 id 时保留“未启动”，静态服务器日志确认后者没有请求 Wasm 文件。此模块只负责加载及生命周期入口，页面行为仍由豫言执行。

DOM 子库现有 Document、Element、Node 的具名豫言接口，覆盖按 id 与 CSS 选择符查询、创建元素和文本节点、插入与删除、文字及属性读写，并将 NodeList 转为节点句柄列表。`文树接口.清单.tsv` 对这批 BCD 路径逐项记录已测、仅封装及待补状态。真实 Chrome 加载豫言 Wasm 后显示“文树往返通过”，验证创建、属性、查询、枚举及移除；带选项的 `createElement`、Trusted Types、完整事件语义与其余大量 DOM 接口仍待逐项补齐。接口语义依据 [WHATWG DOM 标准](https://dom.spec.whatwg.org/)。

`类名与样式。豫` 提供活动 `classList` 和元素内联 `style` 的具名豫言接口。`类名样式接口.清单.tsv` 与 BCD 的 32 条 DOMTokenList、CSSStyleDeclaration 路径逐项对齐。真实 Chrome 运行豫言 Wasm 后显示“类名样式通过”，验证类名添加、删除、切换、替换，以及 CSS 属性、优先级、删除和 `cssText` 往返。迭代器、回调、旧式 CSSOM 方法及浏览器差异仍待补齐。接口依据 [WHATWG DOM](https://dom.spec.whatwg.org/#interface-domtokenlist) 与 [CSSOM](https://drafts.csswg.org/cssom/#the-cssstyledeclaration-interface)。

事件子库新增由豫言预先登记的默认动作取消策略及显式取消订阅。`事件接口.清单.tsv` 对 Event、EventTarget、SubmitEvent 的 38 条 BCD 路径逐项标注状态。真实 Chrome 中，豫言订阅 `submit` 后，普通 GET 表单点击没有导航，Wasm 收到的 `已阻止默认` 为真。原生监听选项、每次事件的同步豫言判定、传播控制和完整事件属性仍待补齐。[WHATWG DOM 标准](https://dom.spec.whatwg.org/#events)说明 `preventDefault()` 必须在适用的事件监听期间执行。
