# 张量后端

金属分组解码满足原矩阵双头条件，并且值维128、半精度值、键缓存及段长为64倍数、值起点按8元素对齐时，使用八行低存分段注意力内核；其余路径保留。该内核写既有分段输出布局，仍由注意力合并归一，段长沿用256。短提示回退与跨1024阈值输出已验证。

这是张量计算的 GPU 后端公共层，与设备无关。它规定设备要提供的一张操作表（「张量设备」），为每个张量上下文维护后端状态（「张量后端」：存储缓冲缓存、管线与模块缓存、命令合批、延后释放），并按「张量内核」的内核表实现各算子（「算子」模块）。金属、网页图算、统算各自实现设备表（金属见 `库/金属张量后端`，统算见 `库/统算张量后端`），张量计算适配（`豫言操作系统/适配/张量计算节点`）只经本层使用 GPU。浏览器与云工的张量计算适配（`豫言操作系统/适配/张量计算`）也经本层用中央张量内核：它的中央处理器设备把缓冲号取作存储地址，记派发时当场在宿主里运行内核入口。

## 包身份

所有者：豫言。包版本：0.1.0。本包为库类型，依赖标准库与张量内核，登记在「共用库」之下。

## 设备表（`设备` 模块）

「造张量设备」依次接十四项，后端只经这张表用设备：

| 项 | 类型 | 含义 |
| --- | --- | --- |
| 名称 | 字符串 | 如 `金属` |
| 源种 | 字符串 | 取内核源码的哪一种：`金属` 取 MSL，`网页图算` 取 WGSL，`统算` 取 PTX；`中央处理器`（中央张量内核）不用源码，照入口名选内核入口 |
| 统一内存 | 爻 | 阳：设备直接读写宿主存储（金属零拷贝）；阴：设备有自己的显存，要上传下载（统算） |

| 释放缓冲 | 缓冲号 → 元 | |
| 新建数据缓冲 | 字节串 → 缓冲号 | 设备自有、按给定字节初始化（如旋转位置编码的角表），下次提交并等待后自动释放 |
| 编模块 | 源码 → 模块号 | 编译失败时抛出事故，附编译器的消息 |
| 取管线 | （模块号，入口名）→ 管线号 | |
| 记派发 | （管线号，缓冲号列，参数区字节，gx，gy，每组线程数）→ 元 | 缓冲依次绑到 1、2……，参数区绑到 0；只记进当前批 |
| 提交并等待 | 元 → 元 | 把已记的派发交给设备并等到全部完成 |
| 交回主机 | 存储地址 → 元 | 设备写过的存储在宿主读之前交回（统一内存的设备不做事） |
| 主机已改 | 存储地址 → 元 | 宿主就地改了存储之后，令设备副本作废（统一内存的设备不做事） |

后两项与“交回主机”“主机已改”是给没有统一内存的设备（统算）准备的：张量常驻显存，只在宿主要读、宿主改过时上传下载。

缓冲号、模块号、管线号对后端都是不透明的正整数（零表示失败），设备可以自定编码（金属张量设备在缓冲号里带页内偏移）；缓冲可以是 GPU 对象，也可以是宿主内存区段（地址加长度），如网页宿主的中央处理器设备。记派发可以只记进当前批，也可以当场同步执行完（此时提交并等待不做事）；后端只要求提交并等待返回后，已记的派发都已完成。

## 后端状态（`后端` 模块）

- `「新建张量后端」于 设备`：每个张量上下文一个后端，设备可由多个上下文共用。
- `「后端存储缓冲」于 端 于 存储地址 于 字节数`：按存储地址缓存缓冲号；同一存储的多个视图共用一个缓冲。缓存是 4093 个桶的散列表，桶号取地址除以 16 再对桶数取余，页对齐的地址也散得开。
- `「后端取管线」于 端 于 源码 于 入口名`：按入口名缓存管线，同一源码只编译一次。
- `「后端按键取管线」于 端 于 键 于 取源 于 取入口`：先按键查缓存，命中时不求源码与入口名；没命中才调两个函数求出设备的源码与入口名，编译、建管线，记在键下。算子层以内核的原入口名为键，所以统算在源表里找 PTX、把入口名改写成 ASCII 只在第一次做（原来每次派发都做，约 20 微秒）；金属每次派发取管线由约 0.3–0.4 微秒降到约 0.06–0.07 微秒。`「后端取管线」` 就是以入口名为键的按键取管线。
- `「后端派发」于 端 于 管线 于 缓冲们 于 参数区字节 于 组数 G 于 每组线程数 于 写址们`：组数拆成 (gx, gy)，gx = min(G, 65535)，gy = ⌈G/65535⌉；G 为零时不派发。写址们是这次派发会写的存储，非统一内存的设备据此在同步时交回主机。
- 命令合批：派发只记进当前批。`「后端同步」` 在有待提交的派发时提交并等待，最后执行延后释放；宿主要读、改这个上下文的张量之前都要先同步。非统一内存的设备写过的存储留在设备上（后端按地址记下），宿主要读写哪块，同步之后再用 `「后端交回存储」于 端 于 存储地址` 交回哪块；延后释放与 `「后端释放存储」` 放掉缓冲之前，也先把仍记着的存储交回主机（同一存储可能还有别的视图在用）。`「后端有待提交吗」` 查询是否有未提交的派发。适配在宿主新建结果张量（全零）后调 `「后端新零存储」于 端 于 存储地址 于 字节数`：非统一内存的设备当场分配显存并在显存里清零，不必上传宿主的全零。
- 延后释放：`「后端延后释放」于 端 于 存储地址 于 释放函数` 记下一项，下次同步（已记的派发都执行完）之后先放掉这块存储的缓冲，再调释放函数；用于派发还在用的临时张量（如矩阵乘前紧致化出的张量）与宿主要释放的张量。`「后端存储已用吗」` 查询这块存储现在有没有缓冲。
- `「后端主机已改」于 端 于 存储地址`：宿主就地改了存储之后调用。
- `「后端释放存储」`：宿主释放张量之前调用，先同步、交回设备写过的这块存储，再放掉它的缓冲（零拷贝的缓冲必须先于宿主存储释放）；同一存储另有张量共用时，下次用到再取。`「后端释放全部」`：上下文释放之前调用，同步并把设备写过而尚未交回的存储都交回主机，再放掉全部缓冲。
- 矩阵乘暂存环：张量后端第八项，`「后端暂环」` 读出、`「后端换暂环」` 换上（每项为宿主句柄、存储地址、字节数与释放函数）；算子层「矩阵乘暂存」从中取小批分段瓦乘的部分和暂存（至多 4 格，取最久未用的，不够大时换新，旧的延后交还），`「后端释放全部」` 时逐项交还宿主。
- `「字们转字节」`：把整数列按小端 32 位字写成参数区字节串（负数即二补码）；`「后端单精位型」` 求小数的 binary32 位型：用「双精转单精位型」由「小数位」取出符号、阶码与尾数后纯整数运算就近取偶（正规、次正规、溢出、无穷、非数都与设备原生舍入逐位相同），不调设备与系统库。`「双精余弦」` `「双精正弦」` 于 备 于 数：照 fdlibm（k_sin、k_cos 与 e_rem_pio2 的中等大小归约）的纯豫言实现，常数由位型构造，|数| 不超过 2^19 · π/2 时纯计算，否则交给「备」；`「双精正余弦」于 备余 于 备正 于 数` 一次归约同时得（cos，sin），与分开求逐位相同；Linux 上旋转位置编码的角表用它代替逐元素调用 C 数学库。

## 算子层（`算子` 模块）

「后端张量」描述一个张量视图：宿主句柄、存储地址、存储字节数、元素类型号（同张量适配：0 单精度、4 三十二位整数、5 块量化八位……）、起点与步长（以元素计）、形状。调用者给「后端分配」（元素类型号，形状）→ 新建的连续张量，每个算子核对类型与布局、按内核表打包参数区（单精字经设备的单精位型）、取管线（按设备源种取 WGSL、MSL 或 PTX 与入口名）、按张量取存储缓冲（依次绑到 1、2……）、求组数并派发，返回结果；做不了（类型、布局、参数不合）时返回可无或阴，调用者退回中央处理器。

金属启用子组时，四类融合算子的 Q8_0/Q4_K 入口让每个甲值片段供两个相邻输出列共用。矩阵乘加与按专家门控按 8 列派发；归一多重与归一门控原有组宽为 8。其他类型与非金属后端沿用原入口，中央处理器后端由调用方退回小算子组合。

另有「后端视图」「后端改形视图」「换句柄」「造连续后端张量」供调用者由已知视图推出新视图的信息。段长、分段阈值与量化分块阈值按「后端种类值」（由设备源种得出：统算、网页图算、中央处理器，其余为金属）从内核表取；「用子组吗」按内核表的「后端宜用子组」（金属为阳；统算暂为阴，开子组时端到端解码慢约 6%，原因未明；中央处理器为阴；待办事项：网页图算建设备时还没有请求 subgroups 特性，暂传阴）。问头数多于键头数且内核表的「后端宜分组注意力」为真时注意力用分组版：中央处理器（中央张量内核没有分组注意力）为阴，照用逐头的注意力；统算在每个键头只有 2、3 个问头且分组后组少时为阴；分组时判断要不要分段所用的头数由内核表的「注意力分段头数」给出。

独立解码入口候选：金属后端分组注意力在词数为 1 时选择四路归约的独立入口，词数大于 1 时仍选择二路归约入口。分段与单组各有对应入口，绑定、参数与输出格式相同。此派发选择的稳定提速仍待短提示空闲复核，实测见张量内核包说明。

## 融合算子层（`融合` 模块）

Metal 的归一矩阵乘与归一门控矩阵乘在归一码非零时退回现有组合，先归一一次再调用普通算子，避免每个工作组重复归一。大词表投影的输出列数大于 8192 时也退回组合。2026-10-03，pit-mac 的 Qwen3 0.6B Q8_0 短提示解码由约 57.5 提到 66–68 词元/秒，长提示由 47.9 提到 54.8；64 个词元逐号相同。叠加金属分段提交后短提示为 111–112、长提示 82.2。记录见[本地推理测速](../../应用/人工智能/本地推理/测速.汉语.md)。

2026-10-06 起，适配层对带归一的门控先单独归一，再以不归一（归一码 0）调用后端归一门控矩阵乘；Metal 在归一码为 0 时只用内核表的「门控快核」（乙为 Q8_0 时为「子组门控四行块八」，前馈的门、升、激活、相乘一次派发），其余类型返回可无、退回组合，不走带工作组暂存的通用融合核。Q8_0 矩阵乘加的子组入口改为「子组矩阵乘加相邻块八」。pit-mac 上短提示解码每词元 GPU 执行时间由约 5.9 降到 5.0 毫秒，生成词元逐号相同。

2026-10-06 起，后端矩阵乘加先试批小深矩阵乘加：甲为单精度、连续 [B, 1, K]（K ≤ 64），乙为单精度 [B, N, K]、可为跨步视图（步长不为负），丙为单精度、连续 [B, 1, N] 时一次派发算完（混合专家按权重合并各专家输出并接残差，原先要跨步复制、矩阵乘、逐元相加三次派发）；中央处理器与统算不用。pit-mac 上 30b 解码每词元少 96 次派发，两轮交替解码 52.3、52.6 → 56.3、56.2 词元/秒，生成词元逐号相同。

张量计算接口 0.5.0 的融合算子。每个函数在张量内核有对应的融合内核（内核表的选核函数给出，中央处理器后端没有）且类型、布局合用时一次派发算完，返回结果；否则返回可无，由适配退回小算子的组合。统算后端用原版融合内核（2026-10-07 在 NVIDIA GeForce RTX 5090 上核对通过）。矩阵乘一族只在 `矩阵乘宜分块` 为阴（解码等行数少）时用融合的矩阵向量乘，预填充退回分块矩阵乘与组合。

## 参数直接写入实验（2026-10-04，已撤回）

现有「参数字节」先把参数字列态射为整数列，再转字节；候选直接逐项写四字节，保持整字低32位、设备单精位型与小端布局不变。pit-mac既有开销剖析工具，原、新、新、原：30整字打包为771、472、473、775纳秒；完整逐元二元宿主耗时为7823、7342、7284、7733纳秒。缓存管线查找为23纳秒，派发记录约5.2～5.6微秒；这些线程CPU计时不能当作纯GPU执行时间。

同一Qwen3 0.6B Q8_0、贪心64词元，20词元短提示五组原版解码120.16、121.28、122.37、124.01、122.72，候选126.47、124.94、120.84、122.63、124.94词元/秒，三快两慢；预填充约344～358，基本持平。1984词元长提示原版预填充2128.02、2121.99，候选2168.71、2123.46；原版解码91.15、90.91，候选90.62、91.08，亦基本持平。全部长短候选生成64词元与各自对照逐号一致；包检查与类型检查通过。局部打包快约39%，整模型收益未稳定确认，源码撤回，补丁另存；未据此宣称追平Ollama。

### 完整矩阵片直接存储

Metal矩阵乘已经选择矩阵片分块且行、列均为64的倍数时，改用完整矩阵入口；新结果的输出起点为零，满足直接存储的八元素对齐要求。其他尺寸和后端沿用原入口。完整入口将16×16累加块直接写入结果缓冲，用编译时常量去掉输出暂存路径；M2 Max实测工作组存储由12288降到8192字节。分批偏移、权重解码与半精度乘加方式保持原样。

### 双头解码实验

Metal单词元解码、问头数恰为键头数两倍时，分组单组与分段注意力选择双头入口；组数、暂存记录与合并入口保持原约定。其他头比、预填充及其他后端使用原入口。双头内核的51项数值与回归测试在pit-mac通过，单组及分段管线实际工作组存储均由12KiB降至6KiB。同Qwen3 0.6B Q8_0正反序十六轮，1984词元长提示解码快约1.4%，短解码未确认稳定收益，全部64输出词元逐号一致；详情见张量内核包说明。

2026-10-06 起，单组路径（短上下文，不分段）在用子组、维与值维 128、键值半精度、键值起点按 8 对齐时改用「子组双头注意力内核」，其余仍用原双头单组入口。金属单词元解码时每个键头对应偶数个问头（如 30b 每键头 8 个）的分组注意力在同样条件下也改用它（组数 词数 × 问头数 / 2，每组一个键头的一对问头），否则仍用解码分组注意力。分段路径（长上下文）同理改用「子组双头分段注意力内核」（组数再乘段数，每组写一条记录给注意力合并）。

### 推理派发的读写信息

设备表的记派发回调增加末参数「写缓冲们」。新入口「设备记派发读写」传入写缓冲号列；原「设备记派发」把全部绑定缓冲视为可写。后端从写入存储地址查缓冲表，未命中得到零，设备须保守处理；全部绑定均视为可读。Metal用此信息识别依赖，统算沿用原顺序执行。
Metal单词元双头分组注意力在键为半精度、维度128、有效键长至少1024、键起点为8的倍数时，使用八行矩阵片入口。查询转半精度，点积按单精度累加；归约和值累加顺序沿用原双头入口，缓存尾部不足完整块时采用原标量点积。其余条件使用原入口。58项注意力数值回归及不同长度提示的64词元生成检查通过；同编译器1984词元提示交替测得解码均值100.3475→105.7575词元/秒，约快5.4%，预填充基本持平。详见张量内核包说明及本地推理测速。
