# 后续验收入口

本轮官方静态TrueType窄配对、真实CFF2单轴与真实彩色PNG消费已在Node及同客体原生运行通过。证据与工具身份见《后续窄验实测记录》；其余格式及性能继续分项验收。

## 官方独立配对

固定 Adobe 发布提交与八文件哈希见《现代官方网页字体配对准备报告》。这四组原件与预压件均来自上游发布树，原件单独承担逻辑轮廓、度量及栅格的参照。

构建 `字体测试 官方网页字体。测试` 后，可从静态 TrueType 的最窄固定配对开始：

```text
node 豫言操作系统/宿主/节点/宿主.cjs yy字体官方测试.wasm SourceSerif4-Regular.ttf SourceSerif4-Regular.ttf.woff2 /private/tmp/yy字体现代官方配对/
```

随后同入口分别核静态 OTF、可变 TTF 与可变 OTF 的同名预压件。第三参数仅选择测试目录；缺省仍是历史目录，默认完整二十原样清单及强失败出口保持原值。历史原始宽度数组、压缩原流、自研与系统独立解压的一致性见《官方网页字体诊断报告》。

## 真正非默认轴

构建 `字体测试 真实非默认轴。测试` 后，默认使用 SFNS；以参数输入 Adobe 官方可变原件可分别触及 gvar/HVAR 和 CFF2 blend/HVAR。入口只将 `wght` 轴取最大值，余轴默认；A、g 的默认与非默认轮廓必须至少一个坐标发生变化。用户 16.16、归一 F2Dot14 及前进宽度完整打印，失败计数触发异常。

```text
node 豫言操作系统/宿主/节点/宿主.cjs yy字体真实轴测试.wasm /private/tmp/yy字体现代官方配对/SourceSerif4Variable-Italic.otf
```

首轮只需一个原件、两个字形；参数保持其他轴默认，便于准确定位轴映射、blend 区域或字形增量问题。

## 彩色 PNG 消费

构建 `字体测试 彩色便图消费。测试` 后，入口使用现有 `字体彩色位图载荷` 读取真实 Apple Color Emoji，交正式 `解码便图`。测试核独立 IHDR 宽高与完整像素长度，打印宽高、格式、行距及像素字节数，运行后保存 `/private/tmp/yy字体彩色原载荷.png` 与 `/private/tmp/yy字体彩色解码像素.bin`。

这是待验消费源；旧彩色测试仅验证载荷定位，PNG 解码与像素产物证据在真实运行后登记。字体生产包继续使用原有接口，图像编解码依赖只加在测试包。

现有 `字体性能` 同源驱动准备 16、32、64 像素字号、相同文字与校验量。下一时段先以一轮核原生和节点的实际产物，再按已备《验收驱动》的五轮中位数步骤收集各平台数据。各格式原生证据与跨平台性能值在运行后登记，甲乙规格完成状态由完整证据确定。
