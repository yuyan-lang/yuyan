# 字体

WOFF1 循 W3C 第三、第五节拒非空字体表载荷之域相叠；相邻之域及逆序载荷之位可解。`网页字体表重叠。测试` 验此诸界，及空表零偏移之旧容。

WOFF2 简形坐差依真型零值、短差、向旗书之，还后存头所定位置格式。实官方 Source Serif TTF 与 WOFF2 成对、实 CFF2 非默认轴、彩色 PNG 消费之双后端证，见《后续窄验实测记录》。

此纯豫言之字体库也：解 TrueType 之字体与字体集，栅字形为灰度覆度之图，依体链而回退、存其字形，量文之宽而断其行。惟依标准库，可于工具之宿主行单元之试；与宿主字体接口（依族名取字体之文、分段而读）相接者，在显示控件之库。

## 用法

```yuyan
寻观「字体」之书。
```

先裹字体之文为源，解之得体，乃造字形之库：

```yuyan
「源」者「内存数据源」于（「读文件字节串」于『/System/Library/Fonts/Menlo.ttc』）也。
「结果」者「解析字体」于「源」于「零」也。
```

`「解析字体」` 还 `「字体已解析」于 字体` 或 `「字体解析失败」于 其故`。

### 度之单位

- 字体单位：字体文中之整数坐标，每 em 之单位数见 `「字身单位数」`。
- 像素字号：一 em 所占之像素（整数）。
- 前进之宽、行之度、断行之极宽与横坐标：六十四分像素之一。
- 图之宽、高、左偏、上偏：像素。左偏者原点至图左边之距（右为正），上偏者基线至图上边之距（上为正）。

### 诸类

- `「字体数据源」`：组类，`「长度」`（文之总长）与 `「读取」`（偏移，长 → 字节串）。读之不得，则还短于所求之字节串，解时据此判败。宿主之字体接口裹为同形之组值即可。
- `「字体」`：组类，含 `「字身单位数」「字形数」「上升」「下降」「行距」`（字体单位，下降取正）等，及全表读入之 hmtx、loca、cmap。
- `「字形轮廓」`：`「点数」「横」「纵」「在线」「轮廓数」「轮廓终点」`，坐标为字体单位，纵者向上。
- `「字形位图」`：`「宽」「高」「左偏」「上偏」「前进宽度」「覆盖度」`，覆度为宽乘高之字（零至二百五十五，行先）。
- `「字形库」`：`「字体们」`（体链）、`「位图缓存」`、`「码点缓存」`。
- `「行度量」`：`「上升」「下降」「行高」`（六十四分像素之一）。
- `「排版行」`：`「字节起」「字节止」`（UTF-8 之字，不含换行之符）、`「行宽」`（不计行尾之空格）、`「字形们」`。
- `「排版字形」`：`「码点」「字体序」「字形号」「横坐标」`（自行首，六十四分像素之一）。

## 术之要

- 解惟依需而读：先读表目，head、hhea、maxp、hmtx、cmap、loca、OS/2 全表入字节缓冲，glyf 依形而读。cmap 择于平台三编码一、十与平台零之子表，格式十二先于四。OS/2 之旗第七位（USE_TYPO_METRICS）立，或 hhea 之升降皆零，则度改用 OS/2 之排版之度。
- 简形读其旗（兼重复之位）与坐标之增；复形读件之偏移（一字或二字）与缩、横纵之缩、二乘二之变（F2Dot14 定点整数），递取其件，深至十六而止。同路重见形号即取空廓，兄弟合法复用各存；常廓、变廓及变度继承皆循此则。
- 栅格先缩坐标为二百五十六分像素之一之整数，图取诸点之包围而外扩至整像素。二次贝塞尔依弦与曲之差不过十六分像素之一而均分为线段；二控点相邻，则补其中点为在线之点。每线段依行、依格切之，格内一段于本格加纵差乘（五百一十二减二横），于右邻加纵差乘二横之和；逐行前缀之和取绝对而夹于十三万一千零七十二为全满，化为零至二百五十五。
- 可断之处：空格之后，及汉字（兼扩展与兼容之区）、假名、中日韩之符与全角标点之两侧；码点十则必断。行首不置 `。，、；：？！）】」』》〉…—～%` 及其半角、全角之对与右引号，行尾不置 `（【「『《〈` 及其对与左引号。空格可出极宽。过宽则退至本行末一可断之处，本行无之则断于当前字前。

## 所未能

代码中以“待办事项”记之：

- CFF/CFF2 字符程序之小数标今循字体单位取整。
- 复形之点对（参为二点之号）作零偏移；ROUND_XY_TO_GRID 与微调之指令不理，字形依整像素而定。
- 字距（kern、GPOS）、连字、繁杂之文、双向之文、表情之序，暂不之理；回车与制表之符同常字；UTF-8 过长之编与代理区之码点不之验。
- 图之尺寸上限待后世之版。


又有 `解析。测试`、`排版。测试` 与 `真字体。测试`。

「字体取表」受字体与四字之签，还字节缓冲；字体集用已择之面目。「彩色字体。测试」验 COLR 之层、CPAL 之色序转换、CBDT 十七至十九之载荷、sbix 之 PNG 载荷与截断之入。位图载荷可付图像编解码库解之。

「解析字体」可径读 WOFF、WOFF2 之字；「解网页字体一」「解网页字体二」还故与复成之字体串，成则故空。WOFF2 复字形、位置、横度之变表，复计目与字体之校验。WOFF2 字体集先依诸面择共表，乃复 TTC 绝对表址；求面数可径读压封之目。

「读字体紧凑段」还紧凑段之列：类零为移、一为直、三为三次曲，横纵为末点，控横甲、控纵甲、控横乙、控纵乙存两控点。「读字形轮廓」十六等分三次曲而取在线点，旧字形之存与栅格可径用之。

「字体归一化坐标」受字体与循轴之次十六位小数定点用户值，项缺则取轴之常值，还十四位小数定点标。「读可变字形轮廓」施 gvar 稀疏点与廓之插值；「可变字形前进宽度」施 HVAR 度量之增。

复形先依件号施 gvar 偏移，乃递读诸件之变体廓。前进之宽先用 HVAR，表缺则取 gvar 左右虚点之横增差；度量之件循 USE_MY_METRICS 而继。

「读字体彩色图层」与「字体调色板颜色」径依字体读 COLR、CPAL。「字体彩色位图载荷」受字体、像素组序与形号，循 CBLC 索一至五定位 CBDT 之 PNG 数，或读 sbix 图数。位图字体存通用之目及度。

网页之封循 [W3C WOFF 规范](https://www.w3.org/TR/WOFF/)与 [W3C WOFF2 规范](https://www.w3.org/TR/WOFF2/)。「网页字体变换。测试」验空、简、复字形、四种坐标之长、指令、包围盒、短长位表与横度侧承之复。
# 速测之实

二〇二六年十月八日，pit-mac 以同客体比验。生产栅格化每字号百轮，先暖一次、五量取中：CFF 十六／三十二／六十四像素，节点耗时 0.076009／0.051069／0.087823 秒，硬原生 0.126150／0.119692／0.152115 秒；TrueType 节点 0.005571／0.008700／0.031529 秒，硬原生 0.019514／0.025838／0.050396 秒。六组校量两端同，绝对录径、输入及同客体摘要见《性能验收记录》。原生耗时之改及余平台续验。

二型程序之转义首令在篇末者，常止其程序而存既解之廓段；转义字惟读于当前程序之界内。紧凑截断转义之试，复正式模糊序一万八千一百三十六之原样全 OTF 与两字直程序。

二型转义依运算所需参之数察数栈；瞬时数组以旧六万五千五百三十六项存储之后三万二千七百六十八项为界，roll 依实可卷栈项为界。未知令、参不足及索越界者止当前之解，存已得之廓段。紧凑转义边界之试，含十三非法参止例及十合法算例。

循 [Adobe #5177 附录C，第三十五页](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5177.Type2.pdf)，全 dotsection 令 `12 0` 作空操作而存数栈，后续路径之令续行；兼容之验察栈守及续绘至 `(10,20)`。

循 [Adobe Type2 数值编码及子程序规范](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5177.Type2.pdf)与 [OpenType CFF2 变体指令规范](https://learn.microsoft.com/en-us/typography/opentype/spec/cff2#charstring-variation-operators)，释器读数之前察编码全长：二十八需三字，二百四十七至二百五十四需二字，二百五十五需五字。子程及变体指令先察栈顶之需；blend 依所选域数验常值、差值及计数之参，合法零保留量常弹计数。短数、栈空及无效混合者止当前之解，合法六万五千五百三十六项栈容量存焉。紧凑指令边界之自动试，含三十三负向、全合法数值、有效子程、混合及容量边界断言。

循 [Adobe Type2 §4.1 路径构造及宽度注记](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5177.Type2.pdf)，旧移动令先察坐标之最少参，守可选宽及末坐之用；直曲诸线依实读之二、四、六项分组而察。参不足及末组不全者止当前之解。紧凑路径参数之自动试，含五十一不足参及合法宽、专曲余一参、多曲与负坐之回归。

## 旧 PDF CFF 标准编码与复合查询

标准编码复合字之模由总集出，授常豫言之接口，供 PDF 字体诸件之存。循 [Adobe CFF #5176 附录乙丙及 charset 规范](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5176.CFF.pdf)与 [Type2 #5177 附录丙旧式 endchar](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5177.Type2.pdf)。

- 标准编码字符标识：整数号至整数SID。零至二百五十五中未编码者为.notdef之SID零，界外负一；bchar、achar循此标准编码而查。
- 紧凑字符标识字形：紧凑字体、整数SID至整数GID。读TopDICT之charset字段十五，解自设格式零、一、二及预设ISOAdobe、Expert、ExpertSubset之前nGlyphs；以ROS识CID。无所得、CID及CFF2皆还负一，CID之映射由调用者处之。
- 紧凑字形复合参数：紧凑字体、整数GID至整数列。以名为键之CFF实至四参或五参之endchar者，还尾四参adx、ady、bchar、achar；五参之可选宽在前，余则空列。
- 紧凑程序复合参数：字节缓冲、局部及全局紧凑索引至整数列，供原程与旧上下文复用。子程共原数栈；return还调用者，实endchar终全查询。EOF残栈及截断转义还空查询。

执行紧凑程序收尾受旧释器五参及状态至有之收尾回调，惟实endchar触之。常执行紧凑程序守旧签名，以空回调入同一释器。此诸查询识旧PDF之复合请求；绘件、递存及附录丙之毋嵌约束由PDF调用者处之。基础试含二条标准表与实子程收尾之回归，本轮惟静交。
