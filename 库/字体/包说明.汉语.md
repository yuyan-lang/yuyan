# 字体

这是纯豫言的字体库：解析 TrueType 字体与字体集，把字形栅格化成灰度覆盖度位图，按字体链回退并缓存字形，测量文字宽度并断行。它只依赖标准库，能在工具链宿主上做单元测试；与宿主字体接口（按族名取字体文件、分段读取）的衔接放在显示控件库里。

## 包身份

所有者：豫言。包版本：0.1.0。本包为库类型，只依赖标准库。

## 模块

| 模块 | 内容 |
| --- | --- |
| `数据源` | 字体数据源（总长度与按偏移读取）、内存数据源、大端读数 |
| `解析` | 字体集取字面、表目录、head、hhea、maxp、hmtx、cmap（格式 4 与 12）、loca、OS/2；码点查字形号、前进宽度 |
| `字形` | glyf 的简单字形与复合字形，得字形轮廓 |
| `栅格化` | 轮廓到覆盖度位图（1/256 像素定点整数） |
| `散列表` | 整数键散列表，值的类型任意，装载过半时自动扩容 |
| `字形库` | 字体链、字体回退、位图缓存与码点缓存、行度量 |
| `排版` | UTF-8 解码、测量宽度、断行 |
| `彩色字体` | COLR 零版图层、CPAL 调色板、CBDT 与 sbix 位图载荷 |
| `整数工具` | 向下取整与四舍五入的除法、绝对值、较大较小、位测试 |

## 用法

```yuyan
寻观「字体」之书。
```

先把字体文件包成数据源，解析出字体，再建字形库：

```yuyan
「源」者「内存数据源」于（「读文件字节串」于『/System/Library/Fonts/Menlo.ttc』）也。
「结果」者「解析字体」于「源」于「零」也。
```

`「解析字体」` 返回 `「字体已解析」于 字体` 或 `「字体解析失败」于 原因`。

### 单位

- 字体单位：字体文件里的整数坐标，每 em 的单位数见 `「字身单位数」`。
- 像素字号：一个 em 占的像素数（整数）。
- 前进宽度、行度量、断行的最大宽度与横坐标：六十四分之一像素。
- 位图的宽、高、左偏、上偏：像素。左偏是原点到位图左边的距离（向右为正），上偏是基线到位图上边的距离（向上为正）。

### 类型

- `「字体数据源」`：组类，`「长度」`（文件总长）与 `「读取」`（偏移，长度 → 字节串）。读不到时返回比所求短的字节串，解析据此判为失败。宿主的字体接口包成同样的组值即可。
- `「字体」`：组类，含 `「字身单位数」「字形数」「上升」「下降」「行距」`（字体单位，下降取正值）等，以及整表读入的 hmtx、loca、cmap。
- `「字形轮廓」`：`「点数」「横」「纵」「在线」「轮廓数」「轮廓终点」`，坐标为字体单位，纵向朝上。
- `「字形位图」`：`「宽」「高」「左偏」「上偏」「前进宽度」「覆盖度」`，覆盖度为宽×高个字节（0–255，行优先）。
- `「字形库」`：`「字体们」`（字体链）、`「位图缓存」`、`「码点缓存」`。
- `「行度量」`：`「上升」「下降」「行高」`（六十四分之一像素）。
- `「排版行」`：`「字节起」「字节止」`（UTF-8 字节，不含换行符）、`「行宽」`（不计行尾空格）、`「字形们」`。
- `「排版字形」`：`「码点」「字体序」「字形号」「横坐标」`（自行首起，六十四分之一像素）。

## 算法要点

- 解析只按需读取：先读表目录，head、hhea、maxp、hmtx、cmap、loca、OS/2 整表读入字节缓冲，glyf 按字形读。cmap 在平台 3 编码 1、10 与平台 0 的子表里选，格式 12 优先于格式 4。OS/2 的旗标第七位（USE_TYPO_METRICS）置位，或 hhea 的上升下降都是零时，度量改用 OS/2 的排版度量。
- 简单字形读旗标（含重复位）与坐标增量；复合字形读部件偏移（一字节或两字节）与缩放、横纵缩放、二乘二变换（F2Dot14 定点整数），递归取部件，深度至多 16。
- 栅格化先把坐标缩放成 1/256 像素的整数，位图取点的包围盒外扩到整像素。二次贝塞尔按弦与曲线的偏差不超过 1/16 像素均分成线段；两个相邻控制点之间补出它们的中点作在线点。每条线段按行、按格切开，格内一段在本格加 纵差×(512−横一−横二)，在右邻格加 纵差×(横一+横二)；逐行前缀和的绝对值夹到 131072 即全满，换算成 0–255。
- 断行机会在空格之后，以及汉字（含扩展区与兼容区）、假名、中日韩符号与全角标点的两侧；码点 10 强制换行。行首不放 `。，、；：？！）】」』》〉…—～%` 及其半角、全角对应与右引号，行尾不放 `（【「『《〈` 及其对应与左引号。空格可以伸出最大宽度。超宽时退回本行最后一个断行机会，本行没有机会时在当前字前断开。

## 性能

2026-09-30 在本机测得（高级模式，华文黑体，负载均值约 160，取多次中最好的值）：

| 项目 | 用时 |
| --- | --- |
| 16 像素栅格化 500 个不同汉字（含读取字形） | 约 46 毫秒 |
| 32 像素栅格化 500 个不同汉字 | 约 90 毫秒 |
| 64 像素栅格化 500 个不同汉字 | 约 190 毫秒 |
| 只读取并解析 500 个字形轮廓 | 约 6 毫秒 |

| 断行 1140 字（码点已缓存） | 约 0.9 毫秒 |
| 解析华文黑体（表目录与小表） | 约 7 毫秒 |

## 已知限制

代码里以“待办事项”注明：

- CFF 轮廓（OTTO）暂不支持，解析返回“暂不支持 CFF 轮廓”；苹方、思源黑体等中文字体的字形是 CFF。
- 复合字形的点对齐（参数为两个点号）按零偏移处理；ROUND_XY_TO_GRID 与微调指令不处理，字形按整像素定位。
- 字距（kern、GPOS）、连字、复杂文字、双向文字、表情序列暂不处理；回车与制表符按普通字处理；UTF-8 的过长编码与代理区码点不作检查。
- 复合字形每层有多个部件引用回自己时，读取次数随深度指数增长；位图尺寸不设上限。

测试在 `测试/`，是独立的「字体测试」包（需要单元测试框架）。在仓库根目录运行（以栅格化测试为例）：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 文件 库/字体/测试/栅格化。测试。豫 --输出 yy字体栅格化测试.wasm -j 24

```
