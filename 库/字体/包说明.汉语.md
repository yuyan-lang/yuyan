# 字体

WOFF1 按 W3C 第三节与第五节拒绝非空字体表载荷范围互相重叠；相邻范围和倒序载荷位置可以解码。`网页字体表重叠。测试` 覆盖这些边界及空表零偏移兼容行为。

这是纯豫言的字体库：解析 TrueType 字体与字体集，把字形栅格化成灰度覆盖度位图，按字体链回退并缓存字形，测量文字宽度并断行。它只依赖标准库，能在工具链宿主上做单元测试；与宿主字体接口（按族名取字体文件、分段读取）的衔接放在显示控件库里。

## 包身份

所有者：豫言。包版本：0.1.0。本包为库类型，依赖标准库与压缩库。

## 用法

```yuyan
寻观「字体」之书。
```

先把字体文件包成数据源，解析出字体，再建字形库：

```yuyan
「源」者「内存数据源」于（「读文件字节串」于『/System/Library/Fonts/Menlo.ttc』）也。
「结果」者「解析字体」于「源」于「零」也。
```

`「解析字体」` 返回 `「字体已解析」于 字体` 或 `「字体解析失败」于 原因`。

### 单位

- 字体单位：字体文件里的整数坐标，每 em 的单位数见 `「字身单位数」`。
- 像素字号：一个 em 占的像素数（整数）。
- 前进宽度、行度量、断行的最大宽度与横坐标：六十四分之一像素。
- 位图的宽、高、左偏、上偏：像素。左偏是原点到位图左边的距离（向右为正），上偏是基线到位图上边的距离（向上为正）。

### 类型

- `「字体数据源」`：组类，`「长度」`（文件总长）与 `「读取」`（偏移，长度 → 字节串）。读不到时返回比所求短的字节串，解析据此判为失败。宿主的字体接口包成同样的组值即可。
- `「字体」`：组类，含 `「字身单位数」「字形数」「上升」「下降」「行距」`（字体单位，下降取正值）等，以及整表读入的 hmtx、loca、cmap。
- `「字形轮廓」`：`「点数」「横」「纵」「在线」「轮廓数」「轮廓终点」`，坐标为字体单位，纵向朝上。
- `「字形位图」`：`「宽」「高」「左偏」「上偏」「前进宽度」「覆盖度」`，覆盖度为宽×高个字节（0–255，行优先）。
- `「字形库」`：`「字体们」`（字体链）、`「位图缓存」`、`「码点缓存」`。
- `「行度量」`：`「上升」「下降」「行高」`（六十四分之一像素）。
- `「排版行」`：`「字节起」「字节止」`（UTF-8 字节，不含换行符）、`「行宽」`（不计行尾空格）、`「字形们」`。
- `「排版字形」`：`「码点」「字体序」「字形号」「横坐标」`（自行首起，六十四分之一像素）。

## 算法要点

- 解析只按需读取：先读表目录，head、hhea、maxp、hmtx、cmap、loca、OS/2 整表读入字节缓冲，glyf 按字形读。cmap 在平台 3 编码 1、10 与平台 0 的子表里选，格式 12 优先于格式 4。OS/2 的旗标第七位（USE_TYPO_METRICS）置位，或 hhea 的上升下降都是零时，度量改用 OS/2 的排版度量。
- 简单字形读旗标（含重复位）与坐标增量；复合字形读部件偏移（一字节或两字节）与缩放、横纵缩放、二乘二变换（F2Dot14 定点整数），递归取部件，深度至多 16。同一递归路径重见字形号时立即取空轮廓，兄弟组件的合法复用各自保留；普通、可变轮廓与变体度量继承共用此规则。
- 栅格化先把坐标缩放成 1/256 像素的整数，位图取点的包围盒外扩到整像素。二次贝塞尔按弦与曲线的偏差不超过 1/16 像素均分成线段；两个相邻控制点之间补出它们的中点作在线点。每条线段按行、按格切开，格内一段在本格加 纵差×(512−横一−横二)，在右邻格加 纵差×(横一+横二)；逐行前缀和的绝对值夹到 131072 即全满，换算成 0–255。
- 断行机会在空格之后，以及汉字（含扩展区与兼容区）、假名、中日韩符号与全角标点的两侧；码点 10 强制换行。行首不放 `。，、；：？！）】」』》〉…—～%` 及其半角、全角对应与右引号，行尾不放 `（【「『《〈` 及其对应与左引号。空格可以伸出最大宽度。超宽时退回本行最后一个断行机会，本行没有机会时在当前字前断开。

## 已知限制

代码里以“待办事项”注明：

- CFF/CFF2 字符程序的小数坐标当前按字体单位取整。
- 复合字形的点对齐（参数为两个点号）按零偏移处理；ROUND_XY_TO_GRID 与微调指令不处理，字形按整像素定位。
- 字距（kern、GPOS）、连字、复杂文字、双向文字、表情序列暂不处理；回车与制表符按普通字处理；UTF-8 的过长编码与代理区码点不作检查。
- 位图尺寸上限留待后续版本。

测试在 `测试/`，是独立的「字体测试」包（需要单元测试框架）。在仓库根目录运行（以栅格化测试为例）：

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 文件 库/字体/测试/栅格化。测试。豫 --输出 yy字体栅格化测试.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy字体栅格化测试.wasm
```

另有 `解析。测试`、`排版。测试` 与 `真字体。测试`。

`彩色字体。测试` 检查 COLR 图层、CPAL 的 BGRA 颜色转换、CBDT 的格式 17、18、19 载荷、sbix 的 PNG 载荷与截断输入。位图载荷可交图像编解码库的 PNG 解码器。

`解析字体` 可直接读取 WOFF 与 WOFF2 字节；`解网页字体一` 与 `解网页字体二` 返回原因字符串与重建字体字节串，成功原因为空。WOFF2 还原字形、位置与横度量的变换表，重算目录及字体校验。WOFF2 字体集先按每面选择共享表，再重建 TTC 的绝对表地址；字面数查询可以直接读取压缩封装的目录。

WOFF2 简单字形坐标差使用真型零值、短差与方向旗编码，恢复后保持头部指定的位置格式。真实官方 Source Serif TTF 与 WOFF2 配对、真实 CFF2 非默认轴及彩色 PNG 消费的双后端证据见《后续窄验实测记录》。

`读字体紧凑段` 返回紧凑段列表：种类零为移动、一为直线、三为三次曲线，横纵为终点，控横甲、控纵甲、控横乙、控纵乙保留两控制点。`读字形轮廓` 把三次曲线十六等分成在线点，既有字形缓存与栅格化可直接消费。

`字体归一化坐标` 接收字体与按轴次序排列的十六位小数定点用户值，缺项取轴默认值，输出十四位小数定点坐标。`读可变字形轮廓` 应用 gvar 稀疏点与轮廓插值；`可变字形前进宽度` 应用 HVAR 的度量增量。

复合字形先按组件编号应用 gvar 偏移，再递归读取每个部件的变体轮廓。前进宽度优先用 HVAR，缺表时取 gvar 左右虚点的横增量差；度量部件沿 `USE_MY_METRICS` 继承。

`读字体彩色图层` 与 `字体调色板颜色` 直接按字体读取 COLR 与 CPAL。`字体彩色位图载荷` 接收字体、像素组序号与字形号，依据 CBLC 的索引一至五定位 CBDT 的 PNG 载荷，或读取 sbix 图片载荷。位图字体保留通用字体目录与度量。

网页封装依据 [W3C WOFF 规范](https://www.w3.org/TR/WOFF/)与 [W3C WOFF2 规范](https://www.w3.org/TR/WOFF2/)。`网页字体变换。测试` 覆盖空、简单、复合字形、四种坐标长度、指令、包围盒、短长位置表与横度量侧承恢复。
# 性能实测

2026-10-08 在 pit-mac 同客体对照，生产栅格化每字号 100 轮、预热一次及五次中位：CFF 的 16／32／64 像素节点耗时 0.076009／0.051069／0.087823 秒，硬原生 0.126150／0.119692／0.152115 秒；TrueType 节点 0.005571／0.008700／0.031529 秒，硬原生 0.019514／0.025838／0.050396 秒。六组校验量两端一致，绝对日志、输入与同客体摘要见《性能验收记录》。原生耗时优化及其余平台继续验收。

二型程序的转义前缀位于程序末尾时正常终止当前程序，保留已解析的轮廓段；转义字节在当前程序边界内读取。`紧凑截断转义。测试` 重放正式模糊编号18136的原样完整 OTF 与两字节直接程序。

二型转义按运算所需的参数数目检查操作数栈；瞬时数组以既有65536项存储的后32768项为界，roll 范围以实际可卷栈项为界。未知命令、参数不足或越界索引停止当前解释，保留已有轮廓段。`紧凑转义边界。测试` 包含十三条非法参数停止回归及十条合法运算回归。

依据 [Adobe #5177 附录C，第35页](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5177.Type2.pdf)，完整 `dotsection` 指令 `12 0` 按保留操作数栈的空操作处理，后续路径指令继续执行；其兼容回归验证栈保持及继续绘制到 `(10,20)`。

依据 [Adobe Type2 数值编码及子程序规范](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5177.Type2.pdf)和 [OpenType CFF2 变体指令规范](https://learn.microsoft.com/en-us/typography/opentype/spec/cff2#charstring-variation-operators)，执行器在读数前检查编码完整长度：28需三字节，247至254需两字节，255需五字节。子程序与变体指令先检查所需栈顶；blend 按选定区域数核对默认值、差值及计数操作数，合法零保留量正常弹出计数。短数据、空栈或无效混合停止当前解释，合法65536项栈容量保持。自动字体测试 `紧凑指令边界。测试` 覆盖三十三条负向、完整合法数值、有效子程序、混合与容量边界断言。

依据 [Adobe Type2 §4.1 路径构造及宽度注记](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5177.Type2.pdf)，现有移动指令先检查最少坐标参数，保留可选宽度和尾坐标行为；直线和曲线按其实际读取的二、四或六项分组检查。参数不足或尾组不完整时停止当前解释。自动 `紧凑路径参数。测试` 包含五十一条不足参数及合法宽度、特殊曲线余一参数、多曲线、负坐标回归。

## 旧 PDF CFF 标准编码与复合查询

`标准编码复合字` 模块列入包的默认导入，提供普通豫言接口，供 PDF 字体组件保留使用。依据 [Adobe CFF #5176 附录B/C及 charset 规范](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5176.CFF.pdf)与 [Type2 #5177 附录C旧式 endchar](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5177.Type2.pdf)。

- `标准编码字符标识`：整数代码→整数 SID。0..255中的未编码项为.notdef的SID零，界外负一；bchar/achar依据这个标准编码查SID。
- `紧凑字符标识字形`：紧凑字体→整数 SID→整数 GID。读取 TopDICT 的 charset 字段15，支持自定义格式0/1/2及预定义 ISOAdobe、Expert、ExpertSubset 的首 nGlyphs；ROS 字段识别CID。未找到、CID、CFF2返回负一，CID映射由调用方处理。
- `紧凑字形复合参数`：紧凑字体→整数 GID→整数列。name-keyed CFF 实际执行到有四或五项的 endchar 时，返回四项 `[adx,ady,bchar,achar]`，可选宽度为第五项时取尾四项；其他情形为空列。
- `紧凑程序复合参数`：字节缓冲→局部紧凑索引→全局紧凑索引→整数列，供已有原程序与上下文复用。子程序共享原操作数栈；return 返回调用者，实际 endchar 结束整个查询。EOF 残栈及截断转义保持空查询结果。

`执行紧凑程序收尾` 接收原执行器的五参数与一个状态→有的收尾回调，仅实际 endchar 触发。普通 `执行紧凑程序` 保持原签名，以空回调调用同一解释器。以上查询识别旧PDF复合请求，组件绘制、递归保留和附录C的禁止嵌套约束由 PDF 调用方办理。基础测试包含两条标准表及实际子程序收尾回归，本轮只静态交付。
