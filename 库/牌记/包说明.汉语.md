# 包配置

以 parser 解析静态包配置并验证依赖图。

非法配置表达式通过式告（以式报错）报告，带可用的源码位置、固定节点类别和至多一百五十字的表达式打印。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为库类型，可被其他包依赖；模块按包名和包内路径访问。本包没有程序入口和文件名；默认构建编译库模块而不链接程序，测试或示例须显式指定模块。

## 使用

在仓库根目录运行：

```sh
./豫构。林檎。豫行 检查 牌记
```

依赖及说明路径以 [包配置](牌记。包。豫) 为准。

包描述的字段与校验见[豫构包系统](../../应用/豫构/包系统.汉语.md)。可选字段「平台」的解析结果用「包诸平台」（按书写顺序的各项）与「包平台依」（包在某平台上的诺驿库与系统库，不能用于该平台时为「可无」）读取；包图解析完之后用「验包图平台」核依赖闭包的平台交集（目标平台不在某包所列平台及其子平台里时报以「平台不合：」开头的错，构建时调用）；解析包图时用「验包图试包」核生产包不依赖测试包（包描述声明测试种类、或包目录在 `测试/` 之下的包是测试包，库包与可执行文件包依赖它时报“生产包依赖测试包：”，写明两包）；可选字段「许可」（SPDX 许可表达式）用「包许可」读取，没写时为空串；可选字段「实现接口」用「包实现接口」读取：所实现接口包名的列，按书写顺序，每名须是合法的短包名，包图里须有同名包，该包须有 `。接口。豫`、`。应用接口。豫` 或 `。底层接口。豫` 文件（包是否存在、是否接口包在解析包图时核验）；所列的包不必在「依赖」里，没写时为空列；解析包图时把所列接口包当包图节点补齐直接依赖、默认导入与依赖闭包，接口包只进补齐名册、不进构建闭包，包上下文据此写出接口包的真实依赖，读接口声明不再误报“未声明直接依赖”（2026-10-29，修议题 1385）。

可执行文件的可选字段「界面」解成「界面类」（「图形界面」「终端界面」，不写为终端界面），区分图形软件与仅终端软件；用「包界面」「包为图形」读取，「述界面」把它写回“图形”“终端”（提案 00046）。

包描述的「类型」新增“测试”种类，与“库”“可执行文件”并列：种类写『测试』的包没有入口，携带「默认导入」（与库同形），只供测试使用；用「包为测试」「包为库」「包可下钻」「述包类」判断种类与库形、能否作层级包里可下钻的子包。生产包依赖测试包时由「验包图试包」在包图解析时报错，判据见上段。测试种类的子包只登记归类，不填父包名、不进隐式依赖闭包。这是新增的种类：先推送支持它的工具，等 CI 一轮自举通过、连续版本换上支持它的原生工具链包，再在包描述里写（见 `AGENTS.md`「包与接口」）。

## 维护

包描述的跳转与悬停资料写入 `.豫构缓存/豫构语言服务/<包描述基名>。语言服务。树码`。它与编译器语言服务缓存共用第二版树码，由豫言 `树码 读取编辑器资料` 解码后交给编辑器。

语言服务的 UTF-16 列号使用「易码」的「文十六位同文长度」计算，补充平面字符占两个码元。

修改接口时更新本说明；修改包身份、版本或构建组成时同步更新包配置。说明文件不参与模块导入。

补全包图时，同时填写实现接口与缺标签只警告属性，并把实现接口所列接口包的元信息补齐（见「析包图已补」）。后者按每个包附近的迁移名单判定，随后随第七版包上下文传给编译器；进程内的「为卷启包境」（为单个源文件启用包上下文）共用这条路径。
