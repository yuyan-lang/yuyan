# 包配置

以 parser 解析静态包配置并验证依赖图。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为库类型，可被其他包依赖；模块按包名和包内路径访问。本包没有程序入口和文件名；默认构建编译库模块而不链接程序，测试或示例须显式指定模块。

## 使用

在仓库根目录运行：

```sh
./豫构。林檎。豫行 检查 包配置
```

依赖及说明路径以 [包配置](包配置。包。豫) 为准。

包描述的字段与校验见[豫构包系统](../../应用/豫构/包系统.汉语.md)。可选字段「平台」的解析结果用「包诸平台」（按书写顺序的各项）与「包平台依」（包在某平台上的诺驿库与系统库，不能用于该平台时为「可无」）读取；包图解析完之后用「验包图平台」核依赖闭包的平台交集（目标平台不在某包所列平台及其子平台里时报以「平台不合：」开头的错，构建时调用）；解析包图时用「验包图试包」核生产包不依赖测试包（包目录在 `测试/` 之下的包是测试包，库包与可执行文件包依赖它时报“生产包依赖测试包：”，写明两包）；可选字段「许可」（SPDX 许可表达式）用「包许可」读取，没写时为空串；可选字段「实现接口」用「包实现接口」读取：所实现接口包名的列，按书写顺序，每名须是合法的短包名，包图里须有同名包，该包须有 `。接口。豫`、`。应用接口。豫` 或 `。底层接口。豫` 文件（包是否存在、是否接口包在解析包图时核验）；所列的包不必在「依赖」里，没写时为空列；可选字段「文体」（提案 00026）用「包声明文体」读取：名字须是译场登记的文体（文体榫卯的「文体已知」校验，现在只登记雅言），缺省为『雅言』，包记录的「文体」项由它填入。

可执行文件的可选字段「界面」解成「界面类」（「图形界面」「终端界面」，不写为终端界面），区分图形软件与仅终端软件；用「包界面」「包为图形」读取，「述界面」把它写回“图形”“终端”（提案 00046）。

## 维护

包描述的跳转与悬停资料写入 `.豫构缓存/豫构语言服务/<包描述基名>。语言服务。树码`。它与编译器语言服务缓存共用第二版树码，由豫言 `树码 读取编辑器资料` 解码后交给编辑器。

语言服务的 UTF-16 列号使用「易码」的「文十六位同文长度」计算，补充平面字符占两个码元。

修改接口时更新本说明；修改包身份、版本或构建组成时同步更新包配置。说明文件不参与模块导入。

补全包图时，同时填写实现接口与缺标签只警告属性。后者按每个包附近的迁移名单判定，随后随第七版包上下文传给编译器；进程内的「为卷启包境」（为单个源文件启用包上下文）共用这条路径。
