# 金属张量后端

这是张量计算的金属设备：用「金属」库实现「张量后端」的设备表（`库/张量后端`）。苹果芯片是统一内存，宿主的张量存储（SharedArrayBuffer）连同所在的整页零拷贝包成金属缓冲，CPU 与 GPU 共用同一块内存，不上传下载。

## 包身份

所有者：豫言。包版本：0.1.0。本包为库类型，依赖标准库、系统库调用、金属与张量后端，登记在「共用库」之下；只用于诺节之苹果。

## 用法

```yuyan
寻观「金属张量后端」之书。
```

`「取金属张量设备」于「元」` 得「或可有」于「张量设备」：进程里只建一次金属设备与命令队列，各上下文共用；没有金属（在苹果以外的系统上、宿主不能调用系统库或没有设备）时为可无。得到设备后用 `「新建张量后端」于 设备` 为每个上下文建后端。

## 实现

- 取存储缓冲：`newBufferWithBytesNoCopy` 包住存储 [地址, 地址 + 字节数（补到 4 的倍数）) 所在的整页，只发这一条消息（不取内容地址）；存储不在页首时（小的 SharedArrayBuffer 常是这样）绑定时带页内偏移。缓冲号是金属对象号加页内偏移 × 2⁴⁸（页首对齐时就是对象号），后端只把它当不透明的号。包裹与释放一次约 5 至 10 微秒，128 MiB 约 40 微秒。
- 记派发：同一批的派发都记进一个命令缓冲的一个计算编码器（串行派发，缓冲按默认方式跟踪读写依赖），每批包在一个自动释放池里。每次派发把两个 MTLSize、缓冲地址表、偏移表与参数区在字节缓冲里拼成一段，一次写进派发环（4 MiB 的共享金属缓冲）的空处；绑定 0 就是派发环（偏移指向这段里的参数区），绑定 1、2……是各张量，用一次 `setBuffers:offsets:withRange:` 设全；管线与上一次相同时不再设；最后 `dispatchThreadgroups:threadsPerThreadgroup:`。一次派发写原生内存一次、发消息两或三次（原来是设管线、每个缓冲一次 `setBuffer`、`setBytes` 与派发，另写原生内存两次），同一管线、三个缓冲时每次编码的线程 CPU 时间由约 13–15 微秒降到约 6.5–7 微秒。环写不下时先提交并等待本批，再从头用；一次派发的整段超过 4 MiB 时抛出事故。
- 提交并等待：结束编码、提交、`waitUntilCompleted`；命令缓冲出错时抛出事故（附金属的错误描述）；然后弹出自动释放池、释放本批的临时数据缓冲，派发环从头用。
- 单精位型：经八字节原生暂存写单精度、再按 32 位整数读回。
- 交回主机与主机已改：统一内存，不做事。

## 测试

`测试/` 下的「金属张量后端测试」包：用本包测试目录里的着色源「仿射」（构建时译成 MSL）检验单精位型、存储缓冲与管线的缓存、两次派发合进一批（同步前不执行，同步后数值正确）、参数区超过 4 KiB 时也正确、组数为零不派发、释放存储后重取与释放全部。另有两项只打印不断言的计时：`派发计时。测试`（每次派发的编码、同步、一次消息、一次写原生内存与一次单精位型的线程 CPU 时间）与 `开销剖析。测试`（豫言各种语言操作与后端各层的单价）。没有金属时打印“跳过”。

```sh
node 豫言操作系统/宿主/节点/宿主.cjs yy豫构.wasm 构建 金属张量后端测试 设备。测试 --输出 yy金属张量后端测试.wasm -j 24
node 豫言操作系统/宿主/节点/宿主.cjs yy金属张量后端测试.wasm
```

## 限制

待办事项：只支持 arm64；一次派发的缓冲表与参数区合计超过 4 MiB 时抛出事故；没有完成回调，一律同步等待；管线与编译好的函数库不释放。
