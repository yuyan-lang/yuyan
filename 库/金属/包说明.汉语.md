# 金属

这是苹果金属（Metal）计算的豫言封装，供以后张量的金属后端使用。金属的接口都是 Objective-C 消息：本库经 `库/系统库调用` 调用 Objective-C 运行时（libobjc 的 `objc_getClass`、`sel_registerName`、`objc_msgSend`），全部逻辑写在豫言里，诺节宿主只提供通用的系统库调用原语。

本库不含内核源码。金属着色语言（MSL）是 C++ 系的语言，手写的 MSL 不入库；以后的内核由着色语言翻译成 MSL，再交给 `「编译金属源码」`。

## 包身份

所有者：豫言。包版本：0.1.0。本包为库类型，依赖标准库与系统库调用，登记在「共用库」之下。

## 要求

苹果系统、arm64，宿主能调用系统库（工具宿主自动开放；应用宿主须给 `--允许系统库调用`，见 `豫言操作系统/宿主/节点/说明.汉语.md`）。`「金属可用」` 为阴时不要调用其余函数。

## 模块

| 模块 | 内容 |
| --- | --- |
| `消息` | Objective-C 运行时：取类、取选择子（`「惰取选择子」` 用顶层的引用格缓存）、按参数个数发消息、自动释放池、保留与释放对象、文字与 NSString 互转 |
| `金属` | 默认设备、命令队列、由 MSL 源码编译函数库、计算管线、共享缓冲与零拷贝缓冲、命令缓冲、计算编码器、设缓冲与设字节、派发、提交与等待 |

## 用法

```yuyan
寻观「金属」之书。
```

- 设备：`「金属可用」`、`「取默认金属设备」`（MTLCreateSystemDefaultDevice，只取一次）、`「金属设备名」`、`「金属设备统一内存」`。
- 编译：`「编译金属源码」于 设备 于 源码` 得「金属已编译」或「金属编译失败」（附编译器的错误描述）；`「新建金属管线」于 设备 于 函数库 于 函数名` 得「金属管线已建」或「金属管线失败」；`「管线每组最多线程」`、`「管线执行宽度」`。
- 缓冲：`「新建金属缓冲」于 设备 于 字节数`（共享存储，CPU 与 GPU 共用同一块内存，`「金属缓冲地址」` 可直接用系统库调用的内存函数读写）；`「包裹原生内存为金属缓冲」于 设备 于 地址 于 字节数` 零拷贝地把页对齐的原生内存包成缓冲（地址未按页对齐时得可无），缓冲释放前这块内存不可释放。张量存储（诺节宿主的 SharedArrayBuffer）是页对齐的，可以零拷贝。
- 设备家族：`「金属设备支持家族」于 设备 于 家族号` 问设备是否属于某个 GPU 家族（supportsFamily:），如 1010 为 MTLGPUFamilyApple10（M5、A19 及以后，GPU 带做张量运算的神经加速器）。
- 常驻集：`「新建金属常驻集」于 设备` 新建空的常驻集（MTLResidencySet，macOS 15 起），得对象号，没有这个类或金属拒绝时得零；`「常驻集加入」于 集 于 对象` 把一个分配（如缓冲对象）加进集里，提交并请求常驻；`「队列加常驻集」于 队列 于 集` 把集挂到命令队列上。集里的分配请求常驻之后一直钉在内存里，系统不会换出或压缩。常驻集不释放（待办事项）。
- 命令：`「新建金属队列」`；`「新建金属命令」`、`「新建无保留金属命令」`（commandBufferWithUnretainedReferences：不保留所绑定的缓冲，调用者须保证它们活到命令执行完）、`「新建计算编码器」`、`「设计算管线」`、`「设金属缓冲」`、`「设金属字节」`（不超过 4 KiB）、`「设三十二位整数参」`、`「设单精度参」`、`「按线程组派发」`、`「按线程派发」`、`「结束编码」`、`「提交金属命令」`、`「等待金属命令」`、`「金属命令状态」`（4 为已完成）、`「金属命令错误」`。
- 命令缓冲、编码器与错误对象都是自动释放的：每次派发包在 `「在自动释放池中」授以 类型 于（会「无」而 …）` 里，否则会一直泄漏。`新建`、`编译` 得到的对象归调用者所有，用完调用对应的 `「释放金属…」`。

## 实测（2026-09-30，Apple M5 Pro，诺节 26.3.0，工具宿主）

草稿目录里用手写的 MSL 小内核验证了整条链路：加倍内核、零拷贝缓冲上的加倍、64×64 单精度矩阵乘（4096 个元素全部正确）。往返时间（提交并同步等待，取 200 次平均；本机当时负载很高，数值偏大且有波动）：

| 项目 | 往返 |
| --- | --- |
| 空命令缓冲 | 66 至 89 微秒 |
| 一个线程的空派发 | 244 至 314 微秒 |
| 64×64 矩阵乘 | 290 至 354 微秒 |
| 一条 Objective-C 消息（宿主调用开销） | 约 2 微秒 |

直接用诺节写同样的派发，空派发约 265 至 335 微秒，可见时间主要花在 GPU 一侧，豫言与宿主的开销（一次派发约二十次宿主调用）只占小部分。

## 限制

待办事项：只支持 arm64（MTLSize 等大于 16 字节的结构体按“指向副本的地址”传，x86-64 上按值压栈，未支持）；完成回调未支持，一律同步等待；内核测试等着色语言能翻译成 MSL 后再补。

## 测试

`测试/` 下的「金属测试」包（不含内核源码）：设备名字、命令队列、共享缓冲读写、零拷贝包裹（未对齐得可无）、空命令缓冲与只含空计算编码器的命令缓冲的提交与等待、非法源码的编译错误。没有金属时打印“跳过”。

### 深度学习并发计算

为深度学习推理提速提供「新建并发计算编码器」与「计算缓冲屏障」。前者按MTLDispatchTypeConcurrent建立编码器，后者以MTLBarrierScopeBuffers排序屏障前后的缓冲访问。调用者须核对存储读写依赖，在有依赖时设置屏障；提交、等待及对象寿命仍按原命令流程处理。
