# 安全外壳文件传输

纯豫言的安全外壳文件传输（SFTP 第 3 版，draft-ietf-secsh-filexfer-02，OpenSSH 使用的版本）服务端库。豫言操作系统的远程登录程序（`豫言操作系统/应用/远程登录`）在 `subsystem sftp` 通道上用它办请求，标准的 `sftp` 与 `scp`（OpenSSH 9 起默认走 SFTP）可以上传、下载、续传、改名文件与目录。

## 用法

- `新传文态`（已授目录权、起始目录）建立一个会话状态；客户端看到的路径都是这个目录权里以 `/` 起头的绝对路径，起始目录是 REALPATH 对 `.` 的回答。
- `传文输入`（状态、通道数据）收一段客户端发来的字节：攒成完整的包，逐个办理，返回（要发回的输出，会话是否已结束）；空字节串表示对端发了 EOF，收尾并结束会话。
- `传文轮询`（状态）每一轮调用一次，继续办输入缓冲里还没办的包（一批的输出攒到 256 KiB 就停，剩下的下一轮再办），返回值同上。
- `传文收尾`（状态）在连接结束时调用，关掉所有还开着的句柄。

## 支持的操作

- INIT 回 VERSION 3，宣告扩展 `posix-rename@openssh.com`（版本 1）。
- OPEN：只读（READ）开成读柄；写（WRITE）开成写柄，可带创建（CREAT）、截断（TRUNC）、追加（APPEND）、独占（EXCL）；READ 与 WRITE 同时给时用 `打开读写文件`，同一个柄能读能写（带 TRUNC 时打开后截成零长）。
- CLOSE、READ（按偏移读一块，至多 256 KiB；读写柄先刷写攒着的块）。
- WRITE：写在请求给的偏移上。偏移正好接着攒着的块末尾时只攒起来，攒到 1 MiB 才真写一次（裸机上大文件每次写是一个 ext4 事务，攒大块才快）；不接续时先把攒着的块刷写，再从新偏移重新攒。刷写时块起点正好是文件柄的顺序位置就顺序写（`写入文件`），否则定位写入（`定位写入文件`，越过末尾的部分补零）。所以 `reput` 续传、乱序与多路并行上传都写对位置。追加柄不看偏移。写失败在刷写时报告（CLOSE、FSTAT、下一次攒满或下一个不接续的 WRITE）。
- LSTAT、STAT、FSTAT：经 `查询文件详情` 回真实大小与修改时间（访问时间也填修改时间），权限按种类取 0755 与 0644；写柄的 FSTAT 先刷写。
- SETSTAT、FSETSTAT：属性带 SIZE 时设置文件长度（截短或补零加长；SETSTAT 以可写方式打开后设，FSETSTAT 用写柄，读柄回成功）；其余属性回成功。
- OPENDIR、READDIR（一次至多 64 项；长名是 ls -l 的样子，带真实大小与修改时间，时间按 UTC 写成“年-月-日 时:分”）、REMOVE（普通文件）、MKDIR、RMDIR（空目录）。
- REALPATH：规范化路径，不要求存在，支持 `.`、`..` 与重复的 `/`。
- RENAME：经 `改名路径` 改名，文件与目录都行，可跨目录；新路径已存在时按 SFTP 第 3 版的规定回失败。扩展 `posix-rename@openssh.com` 同样改名，新路径已存在时原子替换（OpenSSH 的 `sftp` 有它就用它，`rename` 因而能覆盖已有文件）。
- READLINK、SYMLINK 与其他扩展回“不支持”（SSH_FX_OP_UNSUPPORTED）；格式不对的包回 SSH_FX_BAD_MESSAGE。

## 文件操作

库只依赖豫言操作系统文件接口（0.7.0）：目录权加相对路径、文件柄、`定位读取文件`、`定位写入文件`、`打开覆盖文件`、`打开追加文件`、`打开可写文件`、`打开读写文件`、`写入文件`、`设置文件长度`、`改名路径`、`列出目录`、`查询文件信息`、`查询文件详情`、`创建目录`、`删除路径`。读写都是流式的：一个 READ 对应一次定位读取，WRITE 攒成至多 1 MiB 的块再写，内存里只有当前一块，因此可以传输几百 MiB 的系统镜像。路径按 UTF-8 字节处理，可以有中文名。文件柄表复用已关闭的表项，长驻的远程登录可以无限次开关文件。

## 验证

宿主（macOS arm64 原生）上用 OpenSSH 10 的 `sftp` 与 `scp`（默认 SFTP 模式）核对：mkdir、put、get、`reput` 续传（先传前 2 MiB 再续传 5 MiB 文件，取回后沙256 与原文件一致）、`rename` 覆盖已有文件（posix-rename）、`rename -l` 碰到已有目标失败、目录改名、`ls -l` 显示真实大小与时间、中文文件名、`scp -r` 递归上传与下载都正确。协议级探针 `测试/乱序写入探针。脚本。豫`（宿主上用 `--授权目录写 桌面=目录` 运行）直接把请求包交给 `传文输入`，核对乱序 WRITE、STAT 大小、读回内容、FSETSTAT 截短、读写同开、posix-rename 覆盖、旧式 RENAME 失败与目录改名。100 MiB 随机文件的 `sftp put` 12.3 秒、`sftp get` 13.1 秒、`scp` 上传 13.8 秒、下载 13.1 秒（约 7–8 MiB/s），时间主要花在 AES-256-GCM（见 安全外壳密码 的快速实现）。

## 后续版本的事项

- 符号链接、真实的权限、64 位偏移的高位（定位写入现在支持 2 GiB 以内的偏移；更大的文件从头顺序上传照常可用）。
- SETSTAT、FSETSTAT 改修改时间与权限（`scp -p`、`sftp put -p` 现在只得到成功回答）。
- 被替换的文件还开着时它的数据随即释放（POSIX 要等最后一个柄关掉）。
