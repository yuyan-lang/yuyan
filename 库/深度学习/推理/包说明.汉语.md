# 深度学习推理

这是经[张量计算接口](../../../豫言操作系统接口/张量计算/规范.汉语.md)在宿主上做大语言模型推理的库：从 GGUF 文件载入权重、Qwen3 前向与逐词元生成。文件头解析、分词器与伪随机数来自「深度学习」；它还依赖文件、张量计算、[张量文件](../../../豫言操作系统接口/张量文件/规范.汉语.md)三个操作系统接口，只能在同时实现这三个接口的宿主上运行（现为路一 Node 宿主）。

## 包身份

所有者：豫言。包版本：0.1.0。本包为库类型，依赖标准库、深度学习、豫言操作系统基础、豫言操作系统文件、豫言操作系统张量计算与豫言操作系统张量文件。

## 模块

| 模块 | 内容 |
| --- | --- |
| `模型文件` | `「打开模型文件」于 目录名 于 路径`：取已授目录、只读打开、顺序读出文件头（每次至多 16 MiB，解析报不足时目标加倍续读）并解析。`「载入张量」于 上下文 于 模型文件 于 名`：按数据段起点加偏移，经「由文件载入张量」直接载入宿主张量，数据不经豫言字节串。GGML 类型 0、1、30、8、12、14、24、26 依次对应单精度、半精度、脑浮点、块量化八位、超块量化四位、超块量化六位、八位整数、三十二位整数。另有 `「打开授权文件」`、`「读完文件」`（读小文件）与 `「系统错误文字」` |
| `千问三` | `「载入千问」`：核对 `general.architecture = qwen3`，读超参数（`qwen3.block_count`、`embedding_length`、`attention.head_count`、`attention.head_count_kv`、`attention.key_length`、`rope.freq_base`、`attention.layer_norm_rms_epsilon`）并载入全部权重，`output.weight` 缺失时与 `token_embd.weight` 共用。`「新建千问缓存」`：每层一对键、值缓存，形状 [上下文长, 键值头数, 头维]、半精度（与 llama.cpp 缺省相同）。`「千问前向」于 模型 于 缓存 于 词元号们 于 起位`：返回最后一个词元的对数几率 [1, 词表大小] |
| `生成` | `「千问生成」`：先整段预填充，再逐词元解码；温度为零时取最大下标，否则「按概率抽样」（前 20 个、累积概率 0.8，Qwen3 非思考模式的推荐值；随机整数来自可设种子的伪随机源）；遇停止词元或达到上限即止，每个非停止词元调用一次回调；返回提示词元数、预填充用时、解码步数、解码用时（微秒）与生成的词元号 |

## 前向

每层（x 形状为 [n, 嵌入维]，p 为起位）：

1. h = 均方根归一(x, attn_norm)。
2. q = 旋转位置编码(均方根归一(改形(矩阵乘(h, attn_q), [n, 问头数, 头维]), attn_q_norm), p)；k 同理（键值头数，attn_k_norm）；v = 改形(矩阵乘(h, attn_v), [n, 键值头数, 头维])。旋转位置编码为前后半成对（NEOX），基数取 rope.freq_base。
3. k、v 用「写入行」写进这层缓存的第 p 行起。
4. a = 注意力(q, 键缓存, 值缓存, p + n, p, 1/√头维)，改形为 [n, 问头数 × 头维]；x = x + 矩阵乘(a, attn_output)。
5. h2 = 均方根归一(x, ffn_norm)；x = x + 矩阵乘(反曲加权(矩阵乘(h2, ffn_gate)) × 矩阵乘(h2, ffn_up), ffn_down)。

全部层之后取最后一行，做均方根归一（output_norm）再乘 output 得对数几率。每层用完的中间张量立即释放。注意力缩放用单精度张量算出，与 llama.cpp 的 `1.0f/sqrtf(头维)` 相同。

## 已知限制

- 只支持 qwen3 架构；缓存按调用者给的上下文长一次建好，不会增长。
- 矩阵乘的激活以单精度参与，llama.cpp 在 CPU 上会先把激活量化成 Q8_0 或半精度，所以对数几率与 llama.cpp 有小差异；贪心生成在前两名概率很接近时可能分歧。
- 速度取决于宿主。路一 Node 宿主单线程 JS，Qwen3-0.6B（Q8_0）在 macOS arm64 上约为预填充 2.4 词元/秒、解码 2.9 词元/秒。
