# 深度学习

此深度学习之纯豫言者也：GGUF 模型文件头之解、字级 BPE 之分词器、散列之表与伪随机。惟依标准库，不依宿主之接口，故可于工具之宿主行单元之试。张量之算与模型之推，在同目 `推理/` 下之「深度学习推理」包，诸架构之前向在 `模型/` 下之「深度学习模型」包；通用训练之框架，在 `框架/` 下之「深度学习框架」包。

## 籍

所有者曰豫言，版本 0.1.0。此包为库，惟依标准库。

## 诸模

| 模 | 所含 |
| --- | --- |
| `模型格式` | GGUF 文件头之解（第二、三版）：元数据之项、张量之信、数据段之始 |
| `分词` | 字级 BPE 之分词器（`tokenizer.ggml.model = gpt2`）：特殊之词之切、BPE、解码与流式之解 |
| `预分词` | Qwen2 预分词正则之手书扫具 |
| `散列表` | 字键之表与整数键之表：开址线探，容量造时即定，倍所需之数而加一 |
| `随机` | 共用随机数包 Xoshiro256** 可复之源，张量之口取高二十四位 |
| `字节工具` | 小端之整数、单精度之位、字段之较与成文、UTF-8 码点之编解 |

## 用法

```yuyan
寻观「深度学习」之书。
```

要术：

- `「解析模型头」于 字节串`：受文件首之字，还「模型头已解析」「模型头不足」（字不足，多读而再解）或「模型头有误」。已解之头为（头字，元数据之项，张量之信，数据段之始）。数据段之始依 `general.alignment` 对齐，缺则三十二。
- `「元整数值」「元小数值」「元文字值」`：依键名取元数据；`「查张量信息」`：依名取（名之起，名之长，形，GGML 类号，于数据段之偏），形已由 GGUF 之 ne 倒为外维居前。文与数组惟记其位，不抄之。
- `「由模型头建分词器」于 模型头`：还「分词器已建」或「分词器有误」。十五万词之表建为散列，十五万合并之规化为整数之表，Qwen3 之表约需半秒。
- `「分词」于 分词器 于 文`：还词号之列；又有 `「解码」`、`「流式解码」`（配 `「新流式解码器」`）、`「查词元号」`、`「词元文字」`、`「词元类型」`。
- `「新伪随机源」于 种`、`「下一随机数」于 源`。

## 分词之行

从 llama.cpp 之法：

1. token_type 为三（控制）或四（自定）之词，依文长自长而短，逐一于原文依字面切出（自左而右，不相叠），径得其号。
2. 余文依 Qwen2 之正则预分：`(?:'[sS]|'[tT]|'[rR][eE]|'[vV][eE]|'[mM]|'[lL][lL]|'[dD])|[^\r\n\p{L}\p{N}]?\p{L}+|\p{N}| ?[^\s\p{L}\p{N}]+[\r\n]*|\s*[\r\n]+|\s+(?!\S)|\s+`。扫具依码点，逐支循正则先得、贪取、回溯之义取词。
3. 每词之字依 GPT-2 之 bytes_to_unicode 映而查初词之号，屡合名次最小而最左之一对。合并之表于建分词器时化为整数：（左号，右号）映于（名次，合后之号）。
4. 解码：常词以映后之字逆映为字；控制之词不出；自定之词依字面出之。流式之解，以未完之 UTF-8 尾字留待次词。

2026-09-30 以 Qwen3-0.6B 之 GGUF 词表与 llama.cpp 对九组之文（英文、中文、代码、数字、表情、连白、英文缩写、对话之模、豫言之源），词号逐一皆同；对拍之步见「本地推理」之说。

## 所未及

码中以“待办事项”注之：

- `\p{L}`、`\p{N}` 与非 ASCII 之白，以近似之码段表判之，罕见之文与附加之符，其类或与 llama.cpp 异。
- 惟支 gpt2（字级 BPE）之分词器；`tokenizer.ggml.pre` 为他值者，仍依 qwen2 预分之。llama.cpp 改形似控制符之常词（如 `</s>`）为控制之词，此则依其本类。
- 合后不在词表之合并之规径略之（llama.cpp 则退为逐字之词）；等长特殊之词，其切之先后依号自小而大。
- GGUF 之双精度元数据与嵌套之数组不解；单精度之无穷与非数，以有限数解之。
- 字段成文时弃零字。
- BPE 每步线扫，一词之内为平方之级；数千字而无白之长文则缓。
