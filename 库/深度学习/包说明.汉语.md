# 深度学习

这是深度学习的纯豫言部分：GGUF 模型文件头解析、字节级 BPE 分词器、散列表与伪随机数。它依赖标准库、随机数、共用分词器与张量格式库，可以在工具链宿主上做单元测试。张量计算与模型推理在同目录 `推理/` 下的「深度学习推理」包，各架构的前向在 `模型/` 下的「深度学习模型」包，通用的训练框架在 `框架/` 下的「深度学习框架」包。

## 包身份

所有者：豫言。包版本：0.1.0。本包为库类型，依赖标准库、随机数与共用分词器。

## 模块

| 模块 | 内容 |
| --- | --- |
| `模型格式` | GGUF 文件头解析（版本二与三）：元数据项、张量信息、数据段起点 |
| `分词` | 字节级 BPE 分词器（`tokenizer.ggml.model = gpt2`）：特殊词元切分、BPE、解码与流式解码 |
| `预分词` | Qwen2 预分词正则的手写扫描器 |
| `散列表` | 字节键表与整数键表：开放寻址、线性探查，容量在创建时定为所需项数的两倍加一 |
| `随机` | 共用随机数包的 Xoshiro256** 可复现源，张量接口输出高二十四位 |
| `字节工具` | 小端整数、单精度位型、字节段比较与转文字、UTF-8 码点编解码 |

## 用法

```yuyan
寻观「深度学习」之书。
```

主要函数：

- `「解析模型头」于 字节串`：参数是文件开头的一段字节，返回「模型头已解析」「模型头不足」（字节不够，多读一些再解析）或「模型头有误」。已解析的模型头是（头部字节，元数据项，张量信息，数据段起点）。数据段起点按 `general.alignment` 对齐，缺省 32。
- `「元整数值」「元小数值」「元文字值」`：按键名取元数据；`「查张量信息」`：按名字取（名字起点，名字长度，形状，GGML 类型号，相对数据段的偏移），形状已由 GGUF 的 ne 倒成最外层维度在前。字符串与数组只记位置，不复制。
- `「由模型头建分词器」于 模型头`：返回「分词器已建」或「分词器有误」。十五万词的词表建散列表，十五万条合并规则换成整数表，Qwen3 词表约需 0.5 秒。
- `「分词」于 分词器 于 文字`：返回词元号列表；`「解码」`、`「流式解码」`（配合 `「新流式解码器」`）、`「查词元号」`、`「词元文字」`、`「词元类型」`。
- `「新伪随机源」于 种子`、`「下一随机数」于 源`。

## 分词器的行为

照 llama.cpp 的做法：

1. token_type 为 3（控制）或 4（用户定义）的词元按文字长度从长到短，依次在原文里按字面切出（自左至右、不重叠），直接得号。
2. 其余文字按 Qwen2 正则预分词：`(?:'[sS]|'[tT]|'[rR][eE]|'[vV][eE]|'[mM]|'[lL][lL]|'[dD])|[^\r\n\p{L}\p{N}]?\p{L}+|\p{N}| ?[^\s\p{L}\p{N}]+[\r\n]*|\s*[\r\n]+|\s+(?!\S)|\s+`。扫描器按码点逐项照正则的“先到先得、贪婪、回溯”语义取词。
3. 每个词的各字节按 GPT-2 的 bytes_to_unicode 映射查出初始词元号，反复合并名次最小、最靠左的一对。合并表在建分词器时换成整数：（左号，右号）映到（名次，合并后号）。
4. 解码：普通词元把映射后的字符逆映射回字节；控制词元不输出；用户定义词元按字面输出。流式解码把不完整的 UTF-8 尾部字节留到下一个词元。

2026-09-30 用 Qwen3-0.6B 的 GGUF 词表与 llama.cpp 对拍九组文字（英文、中文、代码、数字、表情、连续空白、英文缩写、对话模板、豫言源码），词元号逐个相同；对拍步骤见「本地推理」的说明。

## 已知限制

代码里以“待办事项”注明：

- `\p{L}`、`\p{N}` 与非 ASCII 空白用近似的码点区段表判断，少见文字与组合附加符号的分类可能与 llama.cpp 不同。
- 只支持 gpt2（字节级 BPE）分词器；`tokenizer.ggml.pre` 为其他值时仍按 qwen2 预分词。llama.cpp 会把形似控制符的普通词元（如 `</s>`）改作控制词元，这里照原类型处理。
- 合并结果不在词表里的合并规则直接跳过（llama.cpp 此时退回逐字节词元）；等长特殊词元的切分先后按号从小到大。
- GGUF 解析由张量格式库提供，双精度可取值，嵌套数组保留字节位置，单精度支持无穷与非数。
- 字节段转文字时丢弃零字节。
- BPE 每步线性扫描，一个词内是平方级；数千字节的无空白长文会慢。
