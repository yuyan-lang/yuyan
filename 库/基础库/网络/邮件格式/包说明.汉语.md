# 邮件格式

这是纯豫言邮件格式库，版本为0.1.0，代码遵循仓库许可。

`解析邮件` 接收任意八位字节串，返回 `邮件成功` 或 `邮件错误`。`邮件正文` 保存有序字段与字节串正文，保留重复字段，展开续行。`查邮件头` 按ASCII大小写无关规则返回全部同名字段。`生成邮件` 返回字节串，校验字段名、控制字节及998字节单行上限，按78字节软折行，使用回车换行。非法生成参数抛出豫言异常。

`解析邮件部件` 返回 `部件成功` 或 `部件错误`，解析MIME媒体参数、引号与反斜线转义、嵌套多部分、前言和后言。`单邮件部件` 保存头部与原始字节载荷；`多邮件部件` 保存头部、前言、子部件和后言。`查媒体参数` 返回可选参数。`生成邮件部件` 接收边界及部件树，返回字节串，各层使用自身Content-Type的boundary。

头部、多部分及编码字按原文位置扫描。邮件输入上限1073741824字节，头部上限67108864字节，单字段上限1048576字节，多部分嵌套上限1024层，边界上限70字节；超限返回结构化错误。叶部件构造结果时复制正文。

## 编码与正文

`解码邮件载荷(方式,字节串)`、`编码邮件载荷(方式,字节串)` 返回 `邮件载荷成功` 或 `邮件载荷错误`，处理Base64、quoted-printable、7bit、8bit与binary。Base64生成按76字节折行，MIME解码忽略非编码字符；quoted-printable复用字节编码库。

`解码邮件编码字(文本)` 返回 `邮件编码字成功` 或 `邮件编码字错误`，处理RFC2047的B、Q及相邻编码字间空白。`编码指定邮件编码字(字符集,B或Q,文本)` 按字符边界分段，各编码字最多75字节；`编码邮件编码字(文本)` 使用UTF-8与B。字符集调用编码转换库的IANA传统接口，包含UTF-8、GBK、GB18030、ISO-8859-1与US-ASCII。

`解码邮件正文载荷(头列,字节串)` 根据Content-Transfer-Encoding解码；`解码邮件正文文本(头列,字节串)` 根据Content-Type的charset转换文本，默认使用US-ASCII，返回 `邮件文本成功` 或 `邮件文本错误`。ISO-8859-1按字节直映，US-ASCII严格校验高位字节。

## 简单邮件传输

`建立邮件字节通道` 接收写入、读取与安全升级回调。`发送简单邮件` 接收通道、主机、招呼域名、信封发件人、收件人列表、报文字节串和要求安全标志，返回接收与拒收记录或失败原因。流程处理分片、多行回复、EHLO/HELO、MAIL FROM、RCPT TO、DATA点转义及QUIT。报文使用七位字节、回车换行和最多998字节的行。响应文本最多510字节，回车与换行可跨分片，控制字节返回结构错误。

`连接邮件服务器` 发起TCP连接，`邮件连接通道` 包装现有连接，由调用者关闭。要求安全时检查STARTTLS、调用升级回调并重新EHLO；回调接收主机及已读后续字节。

## 测试与验收

第一个使用者为开发工具「邮件查看」。既有邮件与SMTP测试自行编写，覆盖头部、重复字段、嵌套多部分、分片回复、拒收、点转义与安全升级回调。2026-10-08新增35项独立向量，在节点及相同客体的硬浮点原生两端全部通过：编码21项，正文7项，SMTP响应边界7项。向量包含UTF-8与GBK的B/Q、长词分段、IANA C1语义、NUL/255/128二进制正文及CRLF极限分片。完整记录见《实施记录》。

协议依据：[RFC5322](https://www.rfc-editor.org/rfc/rfc5322.html)、[RFC2045](https://www.rfc-editor.org/rfc/rfc2045.html)、[RFC2046](https://www.rfc-editor.org/rfc/rfc2046.html)、[RFC2047](https://www.rfc-editor.org/rfc/rfc2047.html)、[RFC5321](https://www.rfc-editor.org/rfc/rfc5321.html)、[RFC3207](https://www.rfc-editor.org/rfc/rfc3207.html)。
