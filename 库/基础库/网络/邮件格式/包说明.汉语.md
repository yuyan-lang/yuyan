# 邮件格式

这是纯豫言邮件格式库，版本为 0.1.0，代码遵循仓库许可。

`解析邮件` 接收任意八位字节串，返回 `邮件成功` 或 `邮件错误`。`邮件正文` 保存有序头部字段与字节串正文；重复字段保留，续行展开。`查邮件头` 按 ASCII 大小写无关规则返回全部同名字段。`生成邮件` 返回字节串，校验字段名、值中的控制字节与单行 998 字节上限，按 78 字节软折行，使用回车换行。非法生成参数抛出豫言异常。

`解析邮件部件` 返回 `部件成功` 或 `部件错误`，解析 MIME 媒体参数、带引号及反斜线转义的参数、嵌套多部分、前言与后言。`单邮件部件` 保存头部与原始字节串载荷；`多邮件部件` 保存头部、前言、子部件和后言。`查媒体参数` 返回可选参数值。`生成邮件部件` 接收边界及部件树，返回字节串。

测试自行编写，依据 RFC 5322 与 RFC 2046 的报文规则，覆盖折叠头部、重复字段、畸形输入、多部分、中文头部及含 NUL、255、128 字节的二进制正文往返。第一个使用者是开发工具「邮件查看」。

当前状态是头部、MIME 多部分与 SMTP 字节通道模块已实现，甲级与乙级验收继续实施。传输编码、RFC 2047 编码字、字符集转换与 SMTP STARTTLS 认证适配在后续实现。原生验收、模糊测试与性能测量在后续验收。

## 简单邮件传输

`建立邮件字节通道` 接收写入、读取和安全升级回调，建立带响应缓冲的字节通道。`发送简单邮件` 接收通道、主机、招呼域名、信封发件人、收件人列表、报文字节串和要求安全标志；返回已接收收件人、被拒收件人与响应码，或失败原因。它处理分片和多行响应、EHLO/HELO、MAIL FROM、RCPT TO、DATA 点转义及 QUIT。报文使用七位字节、回车换行和最多998字节的行。

`连接邮件服务器` 发起真实 TCP 连接，`邮件连接通道` 包装现有连接，连接由调用者关闭。要求安全时，流程检查 STARTTLS、调用升级回调并重新 EHLO；升级回调接收连接中已读的后续字节。真实安全传输库的认证握手适配列入后续实施。

协议依据：[RFC 5321](https://www.rfc-editor.org/rfc/rfc5321.html)、[RFC 3207](https://www.rfc-editor.org/rfc/rfc3207.html)。测试包含自行构造的SMTP服务响应、分片、多行、拒收、点转义、安全升级回调与参数注入。实际 TLS 与跨平台验收继续实施，甲乙级保持未验收。
