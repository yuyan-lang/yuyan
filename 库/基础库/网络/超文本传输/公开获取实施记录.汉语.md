# 公开获取实施记录

2026-10-14，把安全传输（TLS 1.3 客户端）、证书链核验、Mozilla 根证书、当前时刻与安全随机接成默认可用的 HTTPS 客户端，并对真实公网站点互通。

## 交付

- 新模块 `简单获取`（已加进默认导入）：`获取网址` 以 GET 取 http 或 https 网址，跟随转向至多十跳，整条转向链共用一个毫秒期限，按 Content-Encoding 解码；`获取网址字节` 在最终状态为 200–299 时返回正文，其余情形报事故。
- https 的默认配置：根证书取 `根证书数据` 的 Mozilla 快照；当前时刻取 `豫言操作系统时间` 的「读取当前纪元毫秒」（标准库没有墙钟；原生与裸机的执行器都提供这个带型导入）；安全随机由安全客户端驱动调用标准库的「获取安全随机字节串」。
- 证书链不过时，核验回调把证书库给的原因记下，报成 `证书验证失败：<原因>`；安全传输客户收到对方警报时写出警报码，常见几种附名称。
- 报文的「读分块」原先逐块把正文拼进累积字节串，每次解析都是平方级，接收过程中又每读一次解析一次；现在先扫一遍记下各块位置，再一次拷进标准库的 `字节缓冲`，每次解析是线性的。豫言操作系统的网络栈每连接收缓冲 32 KiB，读得碎，大的分块正文（如 GitHub 接口）原先会很慢。
- 包依赖新增 `证书` 与 `豫言操作系统时间`。

## 互通结果

联网验收程序是 `测试/公开安全获取。测试。豫`，编成本机程序运行；全树测试只检查它的类型。

| 项 | 网址 | macOS arm64 原生（本机） | Linux x64 原生（pit-mbp13-wired，首轮） |
| --- | --- | --- | --- |
| 1 | `https://yuyan-lang.org/` | 200，16724 字节，5.8 秒 | 200，3.6 秒 |
| 2 | `https://github.com/` | 200，572800 字节，7.7 秒 | 200，9.9 秒 |
| 3 | GitHub 发行附件（302 转到 `release-assets.githubusercontent.com`） | 9860011 字节，沙256 相符，65.3 秒 | 相符，139.2 秒 |
| 4 | `http://yuyan-lang.org/豫/豫言/包/标准库/最新` | 正文 `0.1.0`，5.5 秒 | 1.0 秒 |

证书链分别是 Cloudflare 的 ECDSA 链、GitHub 的 Sectigo ECC 链与 githubusercontent 的 DigiCert RSA 链。第 3 项附件的长查询串原样转发，对方签名核对通过。中文路径按网址解析库的百分号编码发出，服务器认可。

改完「读分块」后在 pit-mbp13-wired 上用最终代码重跑：第 1、3、4 项通过（那台机器同时有别的构建，负载约 12，耗时 10.9、305.6、1.3 秒）；第 2 项那一轮报 `安全连接未经认证关闭`（25.7 秒），负载降到 2 以下后连跑两次都通过（10.4、10.1 秒）。CPU 被挤占、解密太慢时，github.com 会在响应收完前断开连接。

本机的耗时里每次域名解析约占 4 秒：执行器自带的解析器按 `/etc/resolv.conf` 逐个试服务器，本机前两个是不通的 IPv6 服务器。pit-mbp13-wired 用本机 127.0.0.53 解析，没有这段等待。

其余核对（本机原生）：

- `http://httpbin.org/redirect/10` 得 200；`/redirect/11` 报 `转向超过十跳`。
- `http://httpbin.org/gzip` 的 gzip 正文解码后去掉 Content-Encoding、改写 Content-Length。
- `http://httpbin.org/status/404` 经 `获取网址字节` 报 `网址获取失败：状态 404：http://httpbin.org/status/404`。
- `http://httpbin.org/delay/5` 限时 2000 毫秒报 `异步任务超时`。
- GitHub 接口 `releases?per_page=100`（3.2 MB 分块正文）32.8 秒取完。
- `https://expired.badssl.com/`（只支持 TLS 1.2）报 `对方安全传输警报 40（握手失败，对方可能只支持 TLS 1.2）`（pit-mbp13-wired，最终代码）。
- 最终代码在 pit-mbp13-wired 上取 GitHub 接口 3.2 MB 分块正文 53.5 秒（负载约 12 时）。
- `http://127.0.0.1` 上用 nc 回一个无长度、发完即关的响应，正文读到关闭为止，27 字节无误。
- 本机 OpenSSL 4.0.3 起 TLS 1.3 服务：自签证书报 `证书验证失败：证书路径未通至可信根`，备用名称不含 localhost 报 `证书验证失败：主机名与备用名称不匹配`，2020 年的证书报 `证书验证失败：叶证书超出有效期`。

## 吞吐与剖析

第 3 项扣去两次域名解析后约 57 秒，纯豫言 AES-128-GCM 的吞吐约 170 KB/s（Apple M 系列）；pit-mbp13-wired 的老款 Intel 处理器上约 71 KB/s。

macOS `sample` 采样下载过程约 1.3 万次：约 85% 落在 AES，其中 `高级加密域幂`（S 盒按常数时间以有限域求 254 次幂现算）最多，其次是轮函数、`高级加密扩展密钥`（计数模式每个 16 字节块都重做一次密钥扩展）与 GHASH 的逐位乘法；拼接与复制约 7%。

## 待办事项

- AES-GCM 吞吐：计数模式只做一次密钥扩展即可省下约两成；S 盒可改用常数时间的位切片电路。是否改用查表 S 盒涉及常数时间取舍，须用户定。
- 接收正文时每读一次就把已收字节整段重拼并从头解析一遍（各次线性，合起来平方级）。眼下 AES 慢，每次读入较大，这部分开销小；AES 提速后宜让接收态按片累积、凑够长度再成型。
- 只支持 TLS 1.3。只支持 TLS 1.2 的站点（如 badssl.com）回警报 40，报 `对方安全传输警报 40（握手失败，对方可能只支持 TLS 1.2）`；安全传输已有 TLS 1.2 客户（旧版客户），回退留待后续版本。
- 证书吊销（OCSP、CRL）不查。
- 域名解析在开始连接里同步完成，超时管不到这一段。
