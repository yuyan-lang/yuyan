# 网页载入

普通页面脚本成功或异常结束后执行微任务检查点（「网页微任务检查点」：捷思期约作业与文档微任务），使脚本排队的微任务在后续脚本前完成；微任务回调的异常沿用文档任务诊断。

`执行网页脚本资源` 按调用者提供的顺序在共享捷思环境执行脚本，返回各脚本的地址、可选结果与诊断；加载失败和脚本异常各自记录，后续脚本继续执行。普通脚本整段执行；模块脚本以脚本地址为规范键，经「网页模块加载器」（说明符按引用者地址解析、源码经页面资源读取器取来并解码、一律严格模式）载入依赖后执行。「执行网页文档脚本」先执行不延后的普通脚本，再按文档顺序执行延后的普通脚本与模块脚本，最后在文档上派发 DOMContentLoaded 与 load。导入映射、裸说明符、页面解析阻塞与安全检查留待后续版本。

`载入网页脚本` 按文档顺序收集内嵌与外部脚本，解析相对地址并复用资源缓存、文本解码。每项保留地址、可选正文、外部、异步、延后和模块标记；加载失败以空正文记录。脚本类型支持普通捷思和模块，数据脚本按类型筛选。解析阻塞、模块依赖调度、安全检查与脚本执行留待后续实施。

静态载入接受应用提供的资源读取器，读取器按绝对地址返回最终地址、原始主体与编码名称。载入器解析文档和首个基址，按视口条件载入内联与外链样式，装配计算样式和图像读取器，完成布局与绘制。资源以地址缓存，图像与矢量图子资源经同一读取器取得。页面结果保存地址、基址、文档与页面图。

接口行为依网超组超文本标记的文档载入与网址解析算法逐步接入。网络和文件访问由应用提供，纯计算通路在各后端共用。

外链样式在响应的最终地址下递归改写 `url()`，包括嵌套规则、变量值和字体来源。内联样式与文档样式的计算值按文档基址改写，文档节点原始属性保留。背景图因此跟随所属样式表的地址，重定向后的样式表沿最终地址读取相对资源。

有效媒体、支持条件和层规则展开后收集 `@font-face`，与应用已有字面装配成独立页面字体集合。远程来源网址按所属样式地址解析，字体字节经页面资源缓存按需读取；本地字体沿应用本地来源取得。页面结果保存字体集合，供后续布局和绘制复用。

「嗅探网页编码」按字节序标记、受支持的传输编码、元声明、缺省编码的顺序选择文档编码。元声明预扫描前一千零二十四字节（超文本标记包的「预扫描编码」，在字节上按标准的预扫描算法工作），接受 `charset` 与带 `content-type` 指令的 `content`，十六位统一码元声明采用八位统一码，用户自定编码采用视窗西文编码。缺省使用八位统一码。「解码网页文档」按选定编码解码；样式等资源继续使用各自传输编码。依据：[超文本标记规范13.2.3.2](https://html.spec.whatwg.org/multipage/parsing.html#determining-the-character-encoding)。

`image-set()` 与 `-webkit-image-set()` 的字符串候选按所属样式表的最终地址展开为绝对 `url()`；候选分辨率、类型和嵌套图像函数保留。生成的网址字符串保护双引号、反斜线与换行。

后续事项：父文档编码继承、迟到声明重启、字体载入状态与异步重排、脚本调度、安全策略、导航历史与异步资源失效。

「执行网页文档脚本」为已有文档建立页面脚本上下文，将 `document` 绑定到该文档，按文档基址收集资源并在共享环境中执行普通脚本。返回环境、文档绑定与逐项执行结果，脚本对节点的修改直接反映到原文档。「载入网页」在文档解析之后、读样式与渲染之前执行页面里的普通脚本（内嵌与外部，按文档顺序），脚本对文档的改动进入渲染，故障逐项打印后照常渲染；「载入静态网页」不执行脚本，两者共用「载入网页带文档处理」。每个脚本的步数上限取「网页脚本步限」（默认十亿），事件监听与定时器回调的步数上限也取它。定时器由库「浏览器接口」的定时器模块登记，宿主按页面时钟执行。解析期间调度和安全策略留待后续版本。
