# 消息私有语法与恢复

现有 `读取便携消息` 入口收集完整 `msgid_plural` 引文及续行，按目录字符集严格解码后采纳其译形。八进制/十六进制字节可跨引文组合为合法字符。复数声明依次跟随单数声明，缺少单数的条目返回原文；非法复数引文使当前项返回原文，后续合法声明继续读取。

引号内物理换行结束该行扫描，未闭合引文所在项略过，后续合法项恢复解析。未知语法行保存此前已完成项并使未完成项失效，普通注释及旧项注释保留当前合法声明状态。裸 `msgstr` 跟随有效声明后才进入目录。

现有 `读取编译消息` 入口验证普通表每个原译字段描述长度之后的真实终止零字节；先检终止位置仍在文件内，再读其值。内部零字节仍按既有复数格式处理。格式依据 [GNU PO 语法器](https://raw.githubusercontent.com/autotools-mirror/gettext/master/gettext-tools/src/read-po-gram.y) 与 [GNU MO 文件规格](https://www.gnu.org/s/gettext/manual/html_node/MO-Files.html)，来源许可沿既有消息说明。

源文只把CRLF归一为LF，引文中的单独CR保留为字段字节。引文外的空格及字节9至13按词法空白归一，fuzzy标志词首尾同样采用此集合；目录头CRLF字段的字符集赋值去除行尾CR。此顺序依据GNU词法器827、1099、1182行。下载源码SHA256 `a34b9110bd7ba907d145ff1c365592f2a7af3f9173304f1ac9c5fc13379fce14`，许可沿GNU GPL v3或后续版本，源码只供语义核对，算法以豫言独立实现。

CRLF归一后，词法归一器在解码字符副本中单次消去反斜杠接物理LF，支持引文、关键字及注释续行。引导字符副本先拼接ASCII目录头的跨行charset字段，完整原源字节保持不变；按已取得字符集严格解码后再处理正文续行，GBK尾字节5C保留为完整字符。这一步依据GNU词法器851行lex_getc循环。反斜杠接未被消去的物理换行由既有错误恢复处理。

模板charset=CHARSET沿既有未知编码返回空目录约定；POT文件角色留给统筹接口决策。未知控制序沿既有严格略坏项约定，GNU诊断流由官方工具提供。

引号前的声明头仅采用四个既有字段词或完整msgstr十进制数字壳，独立续引采用空头。多余NAME、壳后的字、空下标及中文数词下标使该项按既有错误恢复返回原文。编号采用ASCII0至9，保留数字内部空白供严格解析，外侧空白归一；`msgstr [ 0 ]`仍可读，`msgstr[1 0]`按两个数字标记的坏语法略过。

合法声明词或完整ASCII数字壳后，首引用可位于后续物理行；其间的普通注释按词法空白处理。归行器识别当前逻辑行仍候首引用，保留已完成引用的换行与原有错误恢复。此流程同用于ASCII目录头引导与正式源解码，跨行声明的真实Latin1目录可读。数字壳内部空白仍供常数解析严格检查。

私有六字段状态及现有公开接口保留。domain、显式空上下文复数消歧由统筹决定；Intl 对照待用户授权。本增量公开入口测试为 `测试/消息恢复。测试。豫`，包含35项PO恢复与4项MO合法/畸形终止向量；`测试/消息声明布局。测试。豫`另有9项合法布局及错误恢复向量。实际验证状态见消息恢复验证记录。
