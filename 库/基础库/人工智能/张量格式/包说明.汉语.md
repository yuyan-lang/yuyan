# 张量格式

纯豫言张量文件读写。提供安量读取与编码、GGUF 第二三版头部解析，安量验证类型、形状和偏移，GGUF 支持双精度元数据及嵌套数组跳过。公开接口：解析安量、编码安量、解析模型头及查询函数。单精度位型解码使用数值类型库，支持无穷与非数。

格式据 Hugging Face safetensors 文档与 GGUF 格式说明；实现遵循仓库许可。

NPY 提供第一至三版的头部和原始载荷读写，保留类型描述符（含字节序与结构字段）、形状及 Fortran 顺序；载荷按原存储顺序保留。接口为 `解析NPY` 与 `编码NPY`。ONNX 经协议缓冲保留模型、图、节点、张量及外部数据全部字段，提供初始化器查询与替换；接口为 `解析ONNX`、`编码ONNX`、`ONNX图`、`ONNX节点`、`ONNX初始化器`、`ONNX外部数据` 与 `ONNX改初始化器`。ONNX 数据保持消息字段形式。

格式依据：[NPY官方说明](https://numpy.org/doc/stable/reference/generated/numpy.lib.format.html)、[ONNX官方协议定义](https://github.com/onnx/onnx/blob/main/onnx/onnx.proto)。合成测试覆盖三版NPY、大端描述符、Fortran标志及ONNX初始化器往返与替换；诺节运行通过。

GGUF 写出采用第三版：`编码GGUF` 接受对齐、元数据项与张量列表，重算相对偏移、维度倒序及数据段对齐，检查块存储大小。元数据项保存名字、类型号与该类型的原始编码载荷，十三种元类型都可写；便捷构造提供整数、双精度、文字与数组，嵌套数组传入带元素类型和计数的载荷。调用者的元数据项省去 `general.alignment`，编码器加入该项。`GGUF块规格` 与 `GGUF张量字节数` 的表据 [GGML 类型编号](https://github.com/ggml-org/ggml/blob/master/include/ggml.h) 和 [GGML 块结构](https://github.com/ggml-org/ggml/blob/master/src/ggml-common.h)，核对日期为 2026-10-07；当前有效类型全覆盖，撤销编号保留零项。

`安量转GGUF` 的目标类型号为 0（单精度）、1（半精度）、30（脑浮16）或 8（Q8_0）；`GGUF转安量` 保留前三类并把 Q8_0 解量化为单精度。互转保留名字与形状，元数据映射留待后续。Q8_0 元素数取三十二的倍数。诺节合成测试覆盖四种类型、名字与载荷长度往返，并核对 Q8_1、Q2_0 块大小。

安量目录解析接收头部字节和完整文件长度，返回张量的绝对偏移及载荷长度。分片索引读写 `weight_map` 与元数据，支持按名字查找文件。文件载入模块通过现有系统张量文件接口加载 F32、F16、BF16、I8、I32。

火炬拾存模块以数据栈解释权重说明，接纳白名单存储类型与张量重建符号。火炬权重装配支持连续、跨步及大小端存储；NPZ 读写压档中的 NPY。`解析NPZ`、`解析火炬权重` 直接接收文件字节串，`编码NPZ` 接收数组列表。压档桥接调用归档库的便用模块，解压总长度上限为一百 GiB；新增对接源码与 NPZ 压档往返测试等待统一运行核验。

测试源码统一放在 `测试/`。目录、分片、火炬权重与文件载入的新增源码已排版，类型和运行核验等待统一构建时段。深度学习框架检查点桥接保存模块参数，并按名字、类型、形状核对后写回常驻参数；真实后端测试源码覆盖 F32、F16、BF16 与线性层输出恢复，运行核验等待统一时段。
