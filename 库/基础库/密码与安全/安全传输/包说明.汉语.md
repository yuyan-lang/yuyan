# 安全传输

`客户协商协议` 接收客户会话并返回可选协议字符串。握手完成后可以查询实际 ALPN 协商值；握手未成或协议缺席返回可无，查询保留会话内容。HTTP/2 使用者核对值为 `h2` 后发送连接前言。

记录模块以字节串解析 TLS 记录及握手消息，保留尚未收全的字节。编码器产生网络字节序的头部。握手模块编码 TLS 1.3 客户问候，写入三种套件、SNI、ALPN、版本、群组、签名与密钥份额扩展；调用者提供 32 字节随机数与密钥交换的公开份额。

密钥日程模块桥接字节串与密码数组，提供 HKDF-Expand-Label、Derive-Secret、握手秘密、主秘密、Finished 证明和流量秘密更新；通过传入散列函数、块长与摘要长选用 SHA-256 或 SHA-384。握手模块解析服务问候的套件、随机数及扩展。

测试按 RFC 8448 第三节核对早期秘密、衍生盐、握手秘密、主秘密、服务握手流量秘密、AES 密钥及初始化向量。

加密记录模块生成序号与初始化向量的异或随机数、网络序附加认证数据及内部明文；支持内容类型和零填充，认证失败返回错误。对称记录模块调用密码库的 AES-GCM 和 ChaCha20-Poly1305 实现。

客户端实现 TLS 1.3 的 AES-128-GCM/SHA256、AES-256-GCM/SHA384、ChaCha20-Poly1305/SHA256 三种套件，支持 X25519 与 HelloRetryRequest 选择的 P-256。重试握手核对单次重试、群变化、套件一致、令牌及合成消息散列；服务问候核对会话标识、扩展长度、种类及重复。

`客户配置` 保存主机名、ALPN 候选、证书链核验函数及握手签名核验函数；证书链核验接证书库，握手签名函数取得叶证书与待签名正文。`开始客户` 接收配置、32 字节随机数与 32 字节 X25519 私钥，产生独立会话。`喂入客户` 接收网络字节，`取客户待发` 与 `取客户明文` 取走输出，`客户握手已成` 查询完成状态，`客户错误` 和 `客户已关闭` 查询终态，`写入客户` 分片发送应用数据。`请求客户密钥更新` 与 `关闭客户` 发送 KeyUpdate 和 close_notify。

TCP 薄层的 `发送密文` 返回累计写入偏移，等待时保留该偏移；`读取传输记录` 优先交付已有缓冲中的完整记录。

客户完成 Finished 后派生恢复主秘密，认证后的 NewSessionTicket 进入严格长度与重复扩展解析，保存最近一张有效票据；寿命为零清除保存票据。`取客户票据` 接收会话与票据接收 Unix 毫秒，返回绑定主机、ALPN、套件、寿命的票据。`开始恢复客户` 接收配置、随机数、X25519 私钥、票据及当前 Unix 毫秒，编码最后一项 PSK 扩展及恢复 binder，处理单身份选择、完整握手回退、重试合成前缀和恢复 ALPN 校验。票据失效或主机改变时发起完整握手。

客户收到 close_notify 时先将本方关闭响应排入待发队列，再公开关闭状态。传输驱动取走待发数据后结束连接。

测试按 RFC 8448 重放完整 Finished 加密记录，逐字节核对密文，验证开封及篡改拒绝。纯豫言互通消费者在 pit-mac 上完成 OpenSSL TLS 1.3 的 X25519、AES-128-GCM、RSA-PSS-SHA256、ALPN 与 HTTP 200 往返；测试证书作为明确的信任锚，私钥与随机输入保存在仓外。

互通消费者将 localhost 服务器证书原文作为唯一测试信任锚，并取其起效时刻后一秒作为路径验证时刻；路径检查核对主机名和有效期，CertificateVerify 回调实际核对该证书公钥的 RSA-PSS-SHA256 签名。客户配置中的两项验签回调由调用者提供，随机数与 X25519 私钥亦由调用者提供。通用发行链签名、Mozilla 根数据默认连接、真实当前时刻装配、安全随机默认装配及相应互通测试列为后续事项。

客户会话提供“客户错误”和“客户已关闭”查询。错误正文保留到关闭之后，查询保持会话内容；关闭状态包含主动关闭与收到 close_notify。传输驱动可据此传播失败和结束接收。
“默认客户配置”接收主机名与明确的 Unix 秒，协议限定为 http/1.1。证书链调用证书库的“验证服务器证书”，复用根证书数据及完整证书验签；握手签名调用“核对握手签名”。调用方在每次请求时提供当前时刻。回归覆盖空链、损坏证书与无效握手签名的拒绝，实际 HTTPS 互通继续验收。
三种套件及 P-256 重试路径均在 pit-mac 对接强制配置的 OpenSSL@3 参考服务，完成证书认证与 HTTP 200 字节往返。测试证书时间采用其有效期起点加一秒，以重放固定夹具；生产调用者传入当前时刻与信任策略。

旧版客户模块实现 TLS 1.2 的 X25519 ECDHE、AES-128-GCM/SHA256 与 ChaCha20-Poly1305/SHA256，提供 RSA 和 ECDSA 两类套件标识。服务问候强制协商扩展主密钥；主秘密以包含 ClientKeyExchange 的握手摘要生成。ServerKeyExchange 的随机数与曲线参数交给既有签名回调核验，证书链使用既有配置核验。客户与服务 Finished 各取 SHA256 PRF 的十二字节证明。记录层生成显式 GCM 随机数、ChaCha 异或随机数与包含序号、类型、版本、明文长度的附加数据。

`开始旧版客户`、`喂入旧版客户`、`写入旧版客户` 与 `关闭旧版客户` 使用独立旧版状态机；输出、错误及终态查询复用客户接口。`测试/旧版客户。测试。豫` 由全树测试 CI 自动发现，覆盖两类 AEAD 的完整确定性握手、分片输入、应用数据与缺失 EMS 的拒绝。测试采用明确的协议回调夹具，证书真实性由生产配置验证。

`开始混合客户` 保持原客户配置，提供RFC10024的X25519MLKEM768首问，服务份额接入64字节握手共享秘密；支持混合群重试切到X25519或P-256，使用安全随机回调独立取得新私钥。非法份额与内部解封错误分别产生警报47与80。接口及状态布局见《混合交换.汉语.md》，两个混合测试由全树CI发现。

服务端实现 TLS 1.3 三种套件与 X25519 的证书认证握手。`服务配置` 按顺序保存 DER 证书链、签名算法号、签名回调、ALPN 优先列表和套件优先列表。签名回调接受算法号与完整 CertificateVerify 正文，返回签名字节或失败；应用负责让算法、叶证书与签名密钥相符。`开始服务` 接受配置与各 32 字节的安全随机数、交换私钥，调用者每次会话从安全随机源取得新值。`喂入服务`、`取服务待发`、`取服务明文` 完成字节进出，`服务握手已成`、`服务错误`、`服务已关闭` 公开状态；`写入服务`、`请求服务密钥更新`、`关闭服务` 处理应用记录、KeyUpdate 与 close_notify。

服务端核对客户版本、压缩向量、套件、群与密钥份额、签名算法、重复扩展及 ALPN，拒绝全零共享秘密和不符的 Finished。握手完成证明结束当前握手记录后切换接收密钥；应用流量秘密取服务 Finished 为止的握手录。证书消息与应用数据按 16384 字节分片，签名回调失败保留终态错误。

提案必需的 P-256 与 HelloRetryRequest 属于 TLS 1.3 客户端范围，现由客户状态机及混合重试路径实现。服务端 P-256 与 HelloRetryRequest 是额外增强事项；客户证书认证属于额外功能。提案甲乙级运行、互通及完整出错样例验收待完成。

总集导出 `服务传输`：`接入服务传输` 绑定已有 TCP 连接与服务会话，`刷新服务传输` 保留部分写偏移，`推进服务传输` 推进握手和应用读写，`写入服务传输` 与 `结束服务传输` 发送应用数据和关闭队列。客户端与服务端都复用纯豫言记录、密码和证书能力。
