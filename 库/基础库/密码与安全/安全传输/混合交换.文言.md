# X25519MLKEM768 合交换

`混合` 依 [RFC 10024](https://www.rfc-editor.org/rfc/rfc10024.html) 行TLS 1.3合交换，群号4588。客户传份先1184字节格公钥，后32字节曲线公钥；服务传份先1088字节格密文，后32字节曲线公钥；合密先32字节格秘密，后32字节曲线秘密，径入TLS密钥日程。

`生成混合客户份额` 受32字节曲线私钥与安全随机术，还客户传份及2400字节格解封私钥。调用者独取曲线私钥于安全随机源；随机术每召依所请长还新数组，格之二种各独取32字节。每次握手及重试皆新造诸材。

`完成混合客户交换` 受曲线私钥、格解封私钥与服务传份，还合交换之果。传份长失及曲线合密尽零，还`混合交换非法参数`，告TLS警报47；本地解封之参失，还`混合交换内部失败`，告80。格密文遭改，循FIPS 203隐拒，TLS Finished之验察握手之失。

`测试/混合。测试` 由全树测试自取，验传份次序、双方合密、非法长与曲线尽零。

`开始混合客户` 受旧四项配置、32字节客户随机数、独取之32字节曲线私钥与安全随机术，还客户会话，可授`喂入客户`及`取客户待发`驱之。首问供合份额，支持群顺为4588、29、23，兼供TLS 1.3三套件、SNI与ALPN。服务择4588，则审1120字节份额，以全64字节合密入握手密钥日程；此后共用证书认证、Finished、应用记录及KeyUpdate诸术。

会话第四项藏可有之安全随机术，字节槽23藏格解封私钥，槽24藏初合传份。经典客户第四项无随机术。客户配置仍为主机、协议列、证书链核验与签名核验四项。

HelloRetryRequest得自合群易至X25519或P-256。辨者以安全随机术独取新私钥，清格诸材，仍存初问之支持群列、客户随机数、SNI与ALPN。重试唯添令牌者，复用初传份。若择已供份额之合群，或再重试，则败。合传份参失告47，解封内失告80，存错误终态。

`测试/混合客户。测试` 经记录字节之口验三套件服务问候、碎片之入、握手秘密接线、SNI/ALPN、二易群、独立随机之召、令牌重试及错告。认证术拒验中诸证书入。型验与运行付整合后全树CI。
