# Argon2id

`Argon2id` 实现 RFC 9106 的版本十九，口令与盐均以字节数组及有效长度传入。随后传入内存 KiB、轮数、逻辑并列数、输出字节数。

`Argon2id完整` 在口令与盐之后接收秘密及其长度、附加数据及其长度，随后接收四项资源参数。并列数在一至 33554432 之间，内存在八倍并列数至 268435456 KiB（256 GiB）之间，轮数为正，输出至少四字节。资源参数是公开值，实际可分配规模由平台决定。

记忆划分为四片，每片按逻辑并列顺序填充。初始两块、独立地址段、数据依赖段、多轮旧块异或与最终汇合均按标准计算。秘密引用块采用全记忆固定次序扫描与整数掩码取得。

秘密六十四位词采用两个带固定标记的三十二位肢。BlaMka 的低三十二位乘法由四项带标十六位积与固定进位相加组成；宽加、异或、旋转与扫描选择保留固定装箱类别。秘密引用号的余数以固定三十二轮二进制算法计算。J1 平方及引用面积乘积全程带标，已证明小于公开面积的高三十二位结果化为 i31 小整数。索引与掩码运算处于固定 i31 范围。BLAKE2b 与 H′ 依赖定标散列实现。逐中间量区间见《阿贡恒时核验》。

固定表示实现已通过25a843完整配套链的包检查与整包类型检查。RFC9106第5.3节完整32KiB、三轮、四并列、含秘密及附加数据向量，以及带标词边界在Node与同客体原生运行通过，输出一致。轻量格式化与差异复核已通过。机器代码、运行时路径与实际性能测量留待后续核验，证据见《阿贡恒时核验》。

BLAKE2b 的摘要长度写入初始化参数块。长摘要使用标准 H′ 链式扩展。

规范来源：[RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html)。
