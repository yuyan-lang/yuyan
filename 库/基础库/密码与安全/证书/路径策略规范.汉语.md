# 证书路径策略

路径搜索在抵达可信根时，按根之后至叶的顺序处理 certificatePolicies、policyMappings、policyConstraints 与 inhibitAnyPolicy。默认初始策略是 anyPolicy。显式策略、策略映射与任意策略各有独立计数；自颁中间证书保留计数，叶证书执行最终计数处理。显式策略计数为零时要求有效策略集合含有项目。策略映射禁止 anyPolicy，并在禁止映射时删除相应发行者策略。

颁发者名称使用目录名称规范比较。候选颁发者同时核对 AKI 的 keyIdentifier 与现存 SKI、authorityCertSerialNumber，以及 authorityCertIssuer 中的 directoryName。标识筛选之后仍执行原有证书签名核对。缺少上级 SKI 时，候选继续通过名称与签名选择。

基础测试覆盖缺少策略的默认路径、显式策略交集、策略映射、禁止映射、显式策略零计数、任意策略允许与禁止，以及畸形映射。

`策略树` 的 `验证路径策略树` 接收叶至根的证书结构列、用户初始策略集合及显式策略、映射禁止、任意策略禁止三个开关，返回有效策略树或错误。节点保留编号、父编号、深度、有效策略、预期策略集、限定集和临界位。算法先添普通策略，再用 anyPolicy 补预期节点；逐层剪除无下级分支；映射更新预期集并按 anyPolicy 补发行者策略兄弟节点；最终按用户策略过滤父分支并展开终叶 anyPolicy。原路径验证在到根时调用完整策略树核验。

`策略限定` 解码 CPS 绝对 URI、UserNotice、NoticeReference 与 DisplayText，保留机构、原整数编码的通知号码和明确文字。DisplayText 支持 IA5、Visible、BMP 与 UTF8 编码，并接纳超过二百字符的通知。临界策略的未知限定语及 anyPolicy 的未知限定语产生拒绝，非临界策略保留未知限定节点，供应用读取。客户端可以按机构和通知号码查找本地通知文本，再选择明确文字展示。

AKI 的 authorityCertIssuer 与上证发行者目录名及 issuerAltName 进行通名身份交合。各 GeneralName 身份规则见[通用名称规范](通用名称规范.汉语.md)。

后续验证事项：完整 RFC 策略树一致性向量、原生与全量互通核验。

依据：[RFC 5280 第 4.2 节与第 6.1 节](https://www.rfc-editor.org/rfc/rfc5280.html)。
