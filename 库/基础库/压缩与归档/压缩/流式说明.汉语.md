# 流式输入与输出

格式编号 0 为原始收缩，1 为泽压库，2 为吉压。

`新建压缩流` 接收格式和级别，`压缩流追加` 推进编码，`压缩流读取` 取走已生成的块，`压缩流结束` 返回状态与尚未读取的尾部。调用者按次序拼接各次读取和结束输出即可取得完整码流。

`新建解压流` 接收格式与累计输出上限，`解压流追加` 推进解析，`解压流读取` 取走已生成的输出，`解压流结束` 验证完整性并返回尚未读取的输出。解码器保存 32 KiB 回溯窗口，跨输入片段保留解析状态。包装层验证增量校验与吉压成员边界。

原有调用者只追加、最后结束时仍取得完整结果。读取入口适合每次追加后取出结果，以控制调用者侧输出积存。

## 预设字典

`新建压缩流带字典(格式, 级别, 字典)` 和 `新建解压流带字典(格式, 最大输出, 字典)` 初始化原始收缩或泽压库流。低层入口为 `新建增量收缩带字典`、`新建增量解收缩带字典` 与 `新建增量解封装带字典`。字典尾部最多 32768 字节用于回溯匹配；实际输出长度、输出限额和输出校验从新数据开始累计。

泽压库编码器设置 FDICT，并以完整字典的共用阿德勒32写入大端 DICTID。解码器在四个 DICTID 字节到齐后核对身份并装入窗口。未设置 FDICT 的泽压库流按空字典解析。`解压泽压库带字典(输入, 最大输出, 字典)` 与 `解压原始收缩带字典(输入, 最大输出, 字典)` 提供完整输入入口。

追加入口返回「有」并记录推进结果；结束及完整输入入口使用 0 成功、1 超限、2 损坏、3 未支持或缺字典。DICTID 与所供字典不符返回 2，所需字典未提供返回 3。内部推进保存暂停、完成与字典需求状态，流式入口据此续读。空字典可显式提供，身份为阿德勒32初值 1。吉压的带字典构造在结束时返回 3。

依据 [RFC 1950](https://www.rfc-editor.org/rfc/rfc1950) 的 FDICT、DICTID 与输出校验规定，并按 [RFC 1951](https://www.rfc-editor.org/rfc/rfc1951) 的固定码构造向量 `7820062c0215031300062c0215`：字典与输出均为 `hello`，正文只有长度五、距离五和结束码。此为据规范独立构造的测试源码。

## 后续验收事项

增量编码零级采用存储块，一至三级采用固定码，四至九级采用动态码，并保存跨片词典与惰性匹配状态。固定、码树、封装、分级短客体已在 Node 与同客体原生通过；两种正文、三个格式、十个级别的六十项系统全文互解及二十入口各百万调用已完成。完整资源、性能与裸机验收按用户指令延期。公开布局与签名见[流式接口规范](流式接口规范.汉语.md)。
