# 压缩

提供纯豫言字节串压缩与解压。原始收缩解压读取存储块、固定哈夫曼码与动态哈夫曼码；压缩按零级存储、一至三级固定、四至九级动态霍夫曼编码，采用三十二千字节哈希链、最长二百五十八字节匹配与惰性选择。泽压库封装检查头部及阿德勒32校验，输出标准泽压库流。

`解压原始收缩`、`解压泽压库` 依次接收输入字节串和最大输出字节数；`压缩原始收缩`、`压缩泽压库` 接收输入字节串和压缩级别。结果为状态整数与输出字节串。状态 0 表示成功，1 表示超过输出上限，2 表示损坏，3 表示尚待实现的预设字典；失败结果为空字节串。原始流末尾附带多余字节返回损坏。

测试采用公开固定码的hello向量、标准泽压库hello向量、阿德勒32的123456789校验值、存储块与泽压库往返、输出超限、尾随字节与坏块。实现依照收缩和泽压库公开格式规范；源码与测试随本仓库许可。

预设字典、增量输出与有界流式状态留待后续实现。原生、百万变异输入、性能量测与裸机验收留待后续。本包当前为部分实现。

`解压原始收缩前缀`与`解压泽压库前缀`返回三项：状态、输出字节串、消费长度，分别以`中零`、`中一`、`中二`读取。后续流和对象可以使用余下输入。输出缓冲从至多64KiB起步，按实际输出增长，最大输出限额仅作为上限。

莱齐4块帧与布罗压解压接口、验证与后续事项见各格式说明。迅压原始及分帧编解码接口见《迅压格式》。

吉压支持多成员、可选头字段、头部及成员校验，详见《吉压格式》。比压2支持常用块的完整解码，详见《比压2格式》。

比压2官方随机原字、25块强输入及40万字节长随机构造已在Node与同客体苹果臂64原生通过；两端各完成百万编号、200万目标调用与独立重放。强输入性能实测原生相对系统12.195712倍、Node2.781148倍，现场并发压力和稳态待验范围详见[比压2全量核验记录](比压2全量核验记录.汉语.md)。原生三倍性能目标差距、公共峰值资源及裸机实跑列为后续验收。

上述强输入性能为逐位校验版本。校验独立实测后，既有比压校验改为闭包一次建立256项非反射表，签名与参数保持；40万字节系统向量原生单CRC中位8.004ms，原逐位36.431ms。固定标准、三样本双端及完整类型均通过，精确版本见同一核验记录。

查表版本两端百万及独立重放已完成。强输入查表性能原生相对系统5.160984倍、Node4.146948倍；原生三倍目标差距与稳态复测分别登记。官方38良流、8坏流在Node严格全文核验通过，原生官方全量异常定位及宿主资源旁证见同一记录。

叉泽压及莱齐马二真实压缩块解码见《叉泽压格式》。三格式流入口积存分块输入并在结束时处理，实际行为见《流式说明》；三格式分块往返已在pit-mac诺节验证。增量输出留待后续。

分级编码在pit-mac完成十万字节样本的十级往返与空输入测试；系统吉压解码器校验十级编码全部通过。编码器接口及测试范围见《收缩编码说明》。

泽标压帧、熵表、字典、一至三级压缩接口及验收范围见《泽标压格式》。泽标压校验依赖共用「校验」库的「极速」模块，调用零种子「极速六四」并取低三十二位。窗口修复、双端边界与合法字典百万见《泽标窗口约束核验》；五组硬原生解码百万及精确计数见《泽标原生五组百万》。

官方decodecorpus语料的准备与重放入口为「泽标语料准备」「泽标语料重放」，计划、逐项清单字段、上游许可与实际覆盖差距见《泽标官方语料计划》。两工具调用既有泽标压公开帧接口，逐项保存系统oracle、SHA与本库全文重放证据，完整79872项继续验收。

大语料、百万变异及独立边界向量位于「测试／全量／泽标」独立包「泽标全量测试」，构建入口为「泽标全量测试 工具名」。泽标压压缩概率表核验至少两个非零符号。

叉泽压与裸莱齐马二的真实性能计量采用预热两组、计时七组取中位，每组一百次解码并逐次全字核对黄金输出。原生优先、同客体Node对照的全部十八种当次结果见[叉泽性能验证记录](叉泽性能验证记录.md)；并行宿主负载影响当次计量，跨环境性能继续测量。Node与苹果臂六十四原生两个入口分别各百万的精计数与限时重放见[叉泽百万与重放验证记录](叉泽百万与重放验证记录.md)。

叉泽官方固定快照全部71个XZ文件已在苹果臂六十四原生及同客体Node上通过：22个成功样本与独立参考原字全字核对，44个损坏及5个扩展样本按现ABI拒绝，完整证据见[叉泽官方整集验证记录](叉泽官方整集验证记录.md)。

叉泽八架构BCJ的非零起址、差分、莱齐马二与SHA256组合，已使用独立系统编码器对两种非空原字在原生和同客体Node完成32项全字核验，材料与覆盖范围见[叉泽系统过滤验证记录](叉泽系统过滤验证记录.md)。

叉泽后续验收事项：公共RSS阈值、各ISA专用分支扩充、裸机QEMU与实机验证。

莱齐4热接口与对称原生命令行性能实测见[《莱齐4性能报告》](莱齐4性能报告.汉语.md)。性能入口位于独立包「莱齐4全量测试」，使用两次预热及七次重复中位值；第一批3倍目标的实测差距交原生工具链继续分析。
