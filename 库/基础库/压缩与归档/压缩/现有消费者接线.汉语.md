# 现有消费者接线

本说明使用主线已有的原始收缩、泽压库与吉压一次入口，以及原始和泽压库前缀入口。包直接依赖「压缩」，导入相应模块即可调用。

## HTTP 内容编码

HTTP 消息接收先按消息长度及传输编码取得正文，再按内容编码还原表示。`Content-Encoding: gzip` 使用「吉压」模块的 `解压吉压(正文, 最大输出字节数)`；`Content-Encoding: deflate` 使用「泽压库」模块的 `解压泽压库(正文, 最大输出字节数)`。多个内容编码按编码顺序的逆序解码，每层都传入明确的输出上限。

发送端分别调用 `压缩吉压(正文, 级别)` 与 `压缩泽压库(正文, 级别)`，级别取零至九。结果状态零时采用输出并设置对应内容编码与最终消息长度。吉压解码支持连续成员、可选头字段及校验；泽压库解码核对头与阿德勒32。

一次结果用 `中零` 读取状态，`中一` 读取正文。状态零为成功，一为输出超限，二为损坏，三为预设字典待提供或未支持；失败正文为空。接收方在状态零时交付正文，其余状态作为消息解码失败处理。

网页套接字的 permessage-deflate 接线位于超文本传输库「网页压缩」模块。它使用原始收缩前缀，恢复同步尾并保存最近32768字节上下文，输出上限按消息计。该接线依据 RFC7692；HTTP deflate 内容编码采用 RFC1950 泽压库封装。

## Git 对象与 PACK

版本库「压缩对象」模块调用 `压缩泽压库` 与 `解压泽压库` 处理松散对象。松散对象正文包含对象头及载荷，由完整泽压库入口校验。

版本库「接收包」「接收解析」模块对 PACK 当前对象载荷调用 `解压泽压库前缀(剩余包字节, 最大输出字节数)`。结果通过 `中零`、`中一`、`中二` 读取状态、载荷、消费长度。消费长度包含泽压库头、压缩正文与阿德勒32；状态零后将当前位置推进该长度，继续解析下一对象。前缀解码将余下字节保留给后续对象和包尾校验。

Git 接收端现有调用传入1073741824字节输出上限。偏移增量与引用增量的对象头由版本库先解析，解压后由其增量模块还原对象。输出超限、损坏和字典需求作为包接收失败处理。
