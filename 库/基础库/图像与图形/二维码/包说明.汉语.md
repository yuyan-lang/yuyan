# 二维码

纯豫言 QR Model 2 编码。版本一至四十，四级纠错，数字、字母数字、字节与汉字模式，统一码 ECI，以及模块矩阵和灰度图像输出。

汉字模式输入采用 Shift JIS 双字节码。统一码文字以 UTF-8 字节段与 ECI 26 编码。

`编码二维码段` 接受数据段列表、纠错级别、最小版本、最大版本和掩模。纠错级别按 L、M、Q、H 分别取 0、1、2、3；掩模取 0 至 7，负一按四项罚分选择。结果为 `二维码编码成功` 携带矩阵，或 `二维码编码失败` 携带诊断。矩阵的 `模块` 是按行保存的字节串，黑色为 1，白色为 0；`二维码矩阵模块` 按横、纵坐标读取。

`编码二维码文字` 自动选择可容纳 UTF-8 文字的最小版本。`二维码转图像` 接受矩阵、整数倍率、留白模块数，返回 `灰度8` 图像。分享图像采用四模块留白。

网址分享示例：以 `豫构 构建 二维码 分享示例 --输出 yy二维码分享.wasm -j 24` 构建，再以节点宿主运行 `yy二维码分享.wasm 网址 yy分享二维码.pgm`。输出为 PGM 灰度图。

已检验原创教程的 HELLO WORLD 1-M 数据与纠错码字、1-Q 成品图的全部 441 个模块、汉字与 ECI 位流、格式与版号校验位、40 个版本和四级纠错的功能区容量，以及图像倍率与留白。网址分享应用入口已在诺节上构建运行。同一客体已在诺节与原生运行核验。

二维码矩阵解码、里德所罗门纠错、图像定位、四点透视采样、EAN-13 与 Code 128 编解码及灰度扫线识别现已实现。六版本四级八掩模共192组、五误码修正、独立条码模块向量与 ZXing 原始拍摄图已在诺节与原生通过。详细接口见解码接口。

后续验收事项：百万变异、性能对比、裸机验证。独立版本一透视图片由公共线代LU生成，识别已在诺节与原生通过。

后续核验向量包含 ZXing `EncoderTestCase.testEncode` 的 ABCDEF 1-H、掩模0成品矩阵（2026-10-08快照，Apache 2.0）。源码保存全部441个模块，并直接以原创条码模块向量核验解码与扫线；该441模块向量已在诺节与原生逐项通过。

格式参数核对来源：[QR Code generator](https://www.nayuki.io/page/qr-code-generator-library)、ISO/IEC 18004；码字核对来源：[Thonky 原创教程](https://www.thonky.com/qr-code-tutorial/error-correction-coding)。

对照数据记录：Nayuki 的 QR 格式参数表采用 2026-10-07 所见主分支快照，原代码许可为 MIT。Thonky 的码字教程页面更新于 2021-11-09，成图教程页面更新于 2023-02-20，网站标注 CC BY-NC 4.0；测试表保存 QR 标准的确定输出值。Code 128 标准条空参数和 EAN-13、Code 128 对照模式采用 2026-10-07 所见 ZXing 主分支快照，原代码及测试许可为 Apache 2.0。外部原始图像存于仓外的豫言数据目录，采样核对工具采用豫言编写。

ISO/IEC18004:2015附录I.2数字01234567的16数据码字、10纠错码字和441个成图模块已核验。完整模块来自[JIS X0510:2018采用稿](https://kikakurui.com/x0/X0510-2018-01.html)原书成图独立像素，公开编码入口按版本1-M与给定掩模2生成矩阵，诺节与原生逐项通过。原标准版权归标准发布者，原页保存仓外，仓内保存制式确定输出值与豫言采样器。
