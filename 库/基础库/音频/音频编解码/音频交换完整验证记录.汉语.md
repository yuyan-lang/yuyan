# 音频交换完整验证记录

## 规格依据与实现

2026-10-08 核对 Apple Computer 发布的 [AIFF 1.3 原文](https://blog.jacobvosmaer.nl/0042-akwf-tx16w/assets/AIFF-1.3.pdf)：第 4 页的 FORM 长度涵盖其子块，第 6 页规定零帧音频可省略 SSND，第 8–9 页规定 sampleSize 为一至三十二位并在向上取整的字节容器中左对齐。本次按这三项原文补实现与直接字段向量；这些向量由原文规则构造，属于规范参考，并非官方发布的语料集。

公共接口保持 `解码音频交换` 与 `编码音频交换` 的既有签名。整数解码覆盖全部一至三十二位；AIFC 另读 NONE、twos、sowt、fl32、fl64，后者复用同包波形的单精度位型转换。采样率继续使用现有音频数据的整数表示；有损 AIFC 压缩作为后续事项。

## 独立外部参考

使用本机 FFmpeg 9.0.2（libavcodec 63.1.102、libavformat 63.1.102）生成七个格式，每个为 8000 赫兹双声道、0.02 秒、160 帧、320 交错样本。左右声道为数学合成曲线 `0.2*sin(2*PI*997*t)` 与 `0.17*sin(2*PI*541*t)`，无外部录音版权。编码器依次为 `pcm_s8`、`pcm_s16be`、`pcm_s24be`、`pcm_s32be`、`pcm_f32be`、`pcm_f64be`、`pcm_s16le`，容器选 `-f aiff`。每份经 FFmpeg 独立解码为全部小端 f64 PCM，参考均为 2560 字节。

```text
ffmpeg -v error -f lavfi -i 'aevalsrc=0.2*sin(2*PI*997*t)|0.17*sin(2*PI*541*t):s=8000:d=0.02' -c:a pcm_s16be -f aiff -y 音频交换十六位.aiff
ffmpeg -v error -i 音频交换十六位.aiff -map 0:a:0 -c:a pcm_f64le -f f64le -y 音频交换十六位参考.pcm
```
