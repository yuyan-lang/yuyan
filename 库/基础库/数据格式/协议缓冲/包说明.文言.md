# 协议缓冲

版为 0.1.0。以纯豫言编解协议缓冲之线格式。

`字段` 合字段号、线类、原载为三元。`读取消息` 还状态与字段列；零为成，一为截断或长度之失，二为变长整数逾域，三为线类待备。`写入消息` 存诸字段及其次，未知字段亦可往返。

`整数字段`、`字节字段` 造变长整数与长度前缀字段。定长六十四位、三十二位之线类各为一、五，载荷以小端序存。`之字形编码`、`之字形解码` 治有号整数。

旧组可嵌，验其终标，递归深限一万。`紧凑整数字段`、`读取紧凑整数` 治紧凑重复整数。

`描述符` 模块析消息、字段之声明，存标签、型、号、选项词列，受嵌套消息及单选组。`动态消息` 模块据描述符验线类、必需字段；五为线类不合，六为必需字段缺。原字段列存重复项及未知项。

今增源码具限定名与枚举解析、默认值、单选语义、文本及结森树映射、类型生成器。二〇二六年十月八日，以 d25c7a52886cfcc700b716a066c7ec0c85048e46 成套诸器，于最新基线独立树验整体之型，行线格式及模式十二短试、官方综合样例结森及文本映射五短试，皆成而退。

`读取文件消息` 据描述符验之而还诸原字段，存重复项、未知项及原载。结森映射、递归消息之验用内部语义投影：闭合枚举未声明之数归未知值，单值消息合并，同一单选组取最后激活之成员。原字段列可直授 `写入消息` 而往返。

析模式则验顶层声明之词、syntax 赋值及分隔、声明之闭合；顶层声明未知者还失。枚举须有项，成员之名各异，编号在 int32 域；proto3 首项之号为零。`模式语义。测试` 验十三项合法与非法边界。正式模糊目标用基础库测试设施五参 `执行变异批次`，循编号录进度，由已验强父核诸批末号；短分类样本含官方原种及前二十五变异。

布尔映射之 JSON 对象键用 `true`、`false` 二小写文字，余文则映射报失。结森数值试具三非法键拒之断言及一双键往返之断言。

文件组解析容缺失而未用其类型之 weak 导入，现存 weak 源码仍析之；生成工具循同律载文件。跨文件扩展之目标及值型须见于声明文件之直接导入及递归 public 导入，private 间接目标则报失。扩展可见 CI 具正常 weak/public 与错误 private 二基本断言。

模式解析验消息、枚举之 reserved 名、单号、闭区间及 `to max` 声明，今成员占保留之名或号段则报失。消息号段循字段编号之域，枚举号段循 int32 之域；嵌套声明各验其域。保留声明 CI 具正常名号声明与错误字段占号二基本断言。

单文件模式之消息字段用已声明消息、枚举或标准标量；无导入文件而类型未定者报失。具 import 之模式以文件组解析验导入之可见。类型声明 CI 具正常已定类型与错误未定类型二基本断言。

文本格式受浮点之 `f`、`F` 后缀。单值字段再见及同一单选组之重复成员皆报失，重复字段仍以列治之。文本语义 CI 具正常浮点后缀与错误单值重复二基本断言。

类型生成工具仍受源文件、输出文件二参，按 import 之径递归载源文件目录下诸模式，付文件组解析而验之。所生源码具消息、单选联合、顺序编号之整数枚举别名及成员常量；枚举字段以整数表之。proto3 隐式标量生普通值参，显式 optional 与消息字段表其有无。生成导入 CI 具正常导入生成与错误缺失导入二基本断言。

JSON 对象之重复字段按消息描述符编号存其末项，原字段名与 JSON 别名皆循此律。子消息之后项独编，未知字段仍报失。CI 重复字段试具正常末项覆盖与错误未知键二基本断言。

枚举同号之成员以本枚举之 `option allow_alias=true` 声明。省此选项或设为 `false`，则验编号唯一；选项值用布尔文字。模式语义试具正常声明与错误同号二基本断言，全树测试自发现之。

`校验文件消息` 按字段所出之版本验 proto3 字串 UTF8 之码，递归消息、映射之字串键值皆循此律；字节字段存其原载。CI 字串校验试具正常消息与错误嵌套字串二基本断言。

结森整数映射验目标整数之域及非零小数。六十四位之数字输入循双精度之义，十进制字串存全整数；无号六十四位受其正域及指数串。有限小数验目标之域，非数、无穷以标准特殊字串表之。字节字段受标准、网址安全六十四码，可省补符；出则用标准字母而具补符。据[官方 ProtoJSON 规范](https://protobuf.dev/programming-guides/json/)，二十九边界已于诺节及同源 ARM64 原生试成，WKT 十九项及官方 Vector/ONNX/SentencePiece 七项复试皆成。

`写入消息` 汇标签、长度前缀及原载诸片，按总长造一标准库字节缓冲而逐片抄之。接口、字段之次皆如故。性能入口在模糊测试包之 `性能`，复综合原种二百五十六份，得三万一千四百八十八字节，预热三次、量五次取中位。pit-mac 单缓冲版之诺节解/编中位为 1.143/0.502 毫秒，ARM64 原生为 0.247/0.227 毫秒；前同篇编码中位为诺节 4.609 毫秒、原生 5.289 毫秒，运行负载亦致波动。官方 protoc 36.2 `--decode_raw` 同样本首尾计 0.06 秒，含进程起始及五千八百八十八行文本之出；等价纯核 C 倍数之较留后量。旧十二线/模式试于诺节、原生皆成，两真实模型原字节之复试亦成。

后版之事：扩展与导入全义之验、闭合枚举边界之验、标准特殊消息映射及真实 ONNX、SentencePiece、训练记录之对照、生成类型之实编、压力与性能之验。特殊消息源码已参与此次整体验型，其运行样例另验。

格式据协议缓冲公开线格式规范，源码从仓库之许可。今正在造，甲乙之验待其毕。

文本转义据[官方文本格式规范](https://protobuf.dev/reference/protobuf/textformat-spec/)之统一码标量规则，以四位或八位转义表码点，代理码点及逾统一码域者报失。JSON 字串由结森解析治 UTF-16 代理之配对。官方编译器所造之微型 ONNX、SentencePiece 及综合对照样例见[样例说明](测试/样例/说明.文言.md)。
