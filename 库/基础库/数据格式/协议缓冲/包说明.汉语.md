# 协议缓冲

版本 0.1.0。纯豫言的协议缓冲线格式编解码。

`字段` 为字段号、线类型和原始载荷组成的三元组。`读取消息` 返回状态与字段列；零表示成功，一表示截断或长度错误，二表示变长整数溢出，三表示线类型尚待实现。`写入消息` 保留全部字段及排列，未知字段可以往返。

`整数字段` 和 `字节字段` 构造变长整数及长度前缀字段。固定六十四位与三十二位分别使用线类型一与五，载荷采用小端序。`之字形编码` 与 `之字形解码` 处理有符号整数。

旧式分组支持嵌套和闭合标签校验，递归深度上限为一万。`紧凑整数字段` 与 `读取紧凑整数` 提供紧凑重复整数。

`描述符` 模块把消息和字段声明解析为描述符，支持标签、字段类型、编号、选项词列、嵌套消息和单选字段组。`动态消息` 模块按描述符校验线类型和必需字段，状态五表示线类不合，六表示必需字段缺失。原始字段列保留重复项和未知项。

当前增量源码提供限定名与枚举解析、默认值和单选语义、文本与结森树映射及类型生成器。2026 年 10 月 8 日使用 d25c7a52886cfcc700b716a066c7ec0c85048e46 完整工具链在最新基线独立树完成整体类型检查、十二项线格式与模式短测、五项官方综合样例结森及文本映射短测，均正常退出。

`读取文件消息` 在描述符校验后返回全部原字段，保留重复项、未知项及原载荷。结森映射与递归消息校验使用内部语义投影：闭合枚举的未声明数字作为未知值处理，单值消息合并，同一单选组取最后激活的成员。原字段列可以直接交给 `写入消息` 往返。

布尔映射的 JSON 对象键使用 `true` 与 `false` 两个小写文字，其他文字返回映射失败。结森数值测试包含三个非法键拒绝断言及一个双键往返断言。

文件组解析容许缺失而未使用其类型的 weak 导入，现存 weak 源码正常参与解析；生成工具采用同一规则加载文件。跨文件扩展的目标与值类型须在声明文件的直接导入及递归 public 导入范围内可见，private 导入的间接目标返回失败。扩展可见 CI 包含正常 weak/public 场景与错误 private 场景两个基本断言。

模式解析校验消息和枚举的 reserved 名字、单号、闭区间及 `to max` 声明，当前成员占用保留名字或号段时返回失败。消息号段按字段编号范围处理，枚举号段按 int32 范围处理；嵌套声明分别校验各自作用域。保留声明 CI 包含正常名字与号段声明、错误字段占用号段两个基本断言。

单文件模式的消息字段使用已声明消息、枚举或标准标量类型；无导入文件的未定义类型返回失败。包含 import 的模式由文件组解析完成导入可见性检查。类型声明 CI 包含正常已定义类型与错误未定义类型两个基本断言。

文本格式接收浮点数的 `f`、`F` 后缀。单值字段的第二次出现及同一单选组的重复成员返回失败，重复字段继续按列表处理。文本语义 CI 包含正常浮点后缀与错误重复单值两个基本断言。

类型生成工具沿用“源文件、输出文件”两个参数，递归加载源文件目录下按 import 路径组织的模式，并交给文件组解析检查。生成源码包含消息、单选联合、顺序编号的整数枚举别名及成员常量；枚举字段使用整数表示。proto3 隐式标量生成普通值参数，显式 optional 与消息字段使用存在性表示。生成导入 CI 包含正常导入生成与错误缺失导入两个基本断言。

JSON 对象中的重复字段按消息描述符编号保留最后一项，原字段名与 JSON 替代名字遵循同一规则。子消息的后项独立编码，未知字段继续返回失败。CI 重复字段测试包含正常后项覆盖与错误未知键两个基本断言。

枚举同号成员通过本枚举的 `option allow_alias=true` 声明。省略该选项或设为 `false` 时校验编号唯一；选项值采用布尔文字。模式语义测试包含正常声明与错误重复编号两个基本别名断言，接入全树测试自动发现。

`校验文件消息` 按字段来源版本校验 proto3 字符串的 UTF8 编码，递归消息与映射的字符串键和值使用同一规则；字节字段保留原载荷。CI 字符串校验测试包含正常消息与错误嵌套字符串两个基本断言。

模式解析校验顶层声明关键字、syntax 赋值与分隔、声明闭合；未知顶层声明返回失败。枚举须非空、成员名字唯一，编号处于 int32 范围；proto3 的首项编号为零。`模式语义。测试` 覆盖十三项合法与非法边界。正式模糊目标使用基础库测试设施的五参数 `执行变异批次`，按编号写进度，交由已验证强父核对每批末号；短分类样本包含官方原种与前二十五变异。

结森整数映射校验目标整数域与非零小数部分。六十四位数字输入按双精度语义处理，十进制字符串保留完整整数；无号六十四位接受相应正域与指数串。有限浮点数校验目标范围，非数及无穷使用标准特殊字符串。字节字段接受标准与网址安全六十四进制，填充可省略；输出为标准字母并带填充。依据[官方 ProtoJSON 规范](https://protobuf.dev/programming-guides/json/)，二十九项边界已在诺节和同源 ARM64 原生通过，WKT 十九项与官方 Vector/ONNX/SentencePiece 七项回归通过。

`写入消息` 汇总标签、长度前缀及原载荷片段，按总长分配一个标准库字节缓冲逐片复制。接口与字段次序保持一致。性能入口位于模糊测试包的 `性能`，对综合原种重复二百五十六份形成 31488 字节样本，预热三次、测五次取中位。pit-mac 上单缓冲版本的诺节解码/编码中位为 1.143/0.502 毫秒，ARM64 原生为 0.247/0.227 毫秒；此前同脚本编码中位为诺节 4.609 毫秒、原生 5.289 毫秒，运行负载参与波动。官方 protoc 36.2 `--decode_raw` 同样本端到端为 0.06 秒，包含进程启动与 5888 行文本输出；纯核等价 C 倍数比较列入后续测量。原有十二项线/模式回归在诺节和原生通过，两真实模型原字节回归通过。

后续版本事项：扩展与导入的完整语义验收、闭合枚举边界验收、标准特殊消息映射及真实 ONNX、SentencePiece、训练记录对照、生成类型的实际编译、压力与性能验收。特殊消息源码参与本次整体类型检查；对应运行样例另行验收。

格式依据协议缓冲公开线格式规范；代码依仓库许可。当前为实现中，甲级与乙级验收留待完成。

文本转义依据[官方文本格式规范](https://protobuf.dev/reference/protobuf/textformat-spec/)的统一码标量规则，使用四位或八位转义表示码点，代理码点与超出统一码范围的值报错。JSON 字符串由结森解析处理 UTF-16 代理配对。官方编译器生成的微型 ONNX、SentencePiece 及综合对照样例见[样例说明](测试/样例/说明.汉语.md)。
