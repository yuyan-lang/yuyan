# 编码转换

此包以豫言编解 UTF-8、UTF-16LE、UTF-16BE、UTF-32LE、UTF-32BE，惟依标准库。

国标之术受 GBK 与 gb18030，共解码之术，含四字节之域及旧国标十八项非对称之编。`国标解码` 受字节串及严爻；`国标编码` 受码点列及限 GBK 之爻，码不可表则无。西文之术受 windows-1252。

`解码文本` 受码名、字节串、严爻，还可有之串；`编码文本` 受码名及文，还可有之字节串。网页之口循 WHATWG，以 ISO-8859-1、US-ASCII 为 windows-1252 之标签。`解码传统文本`、`编码传统文本` 供邮件诸 IANA 之约，拉丁一逐字节直映，美式码严验拒高字节。

`UTF8解码` 受字节串及严验之爻，还可有之码点列；`UTF16解码`、`UTF32解码` 又受小端之爻。严验拒坏列，宽验代以 U+FFFD。首记定端而去之。编码受码点列，出字节串而不置首记；非法标量代以 U+FFFD。

`字符串UTF16长度` 计串之双八位码元。包配置之语言服务以此换算列数。

试验之口为 `测试/统一编码。测试。豫`，验平面字、域外字、极标量、零字节、两端、首记及坏列。

规取 WHATWG Encoding Standard（https://encoding.spec.whatwg.org/）及 Unicode Standard。实现从仓库之许可，试数于本仓独作。

国标索引取官方 `index-gb18030.txt`（2024-09-18，SHA-256 `746b3c55f1a8ec4b90b451f384437a17fd37cd51cd668456a28071a758d10784`）及 `index-gb18030-ranges.txt`（SHA-256 `874c6b6f6f74cf7d427ad228d5b41ddd9354fffd92a2259bf429f86e6baa7a1e`）。原表下载于仓外，`工具/索引生成。豫` 生十进之密文，始而化数组。WHATWG 著作权属 Apple、Google、Mozilla、Microsoft；源码之数据从 BSD 3-Clause，许可原文存 `数据许可.txt`。

此阶段以 pit-mac 新工具构建、运行统一编码之试，诸 UTF、首记、坏列、西文、国标双字节、四字节之首末界、特指针 7457 及表情往返皆过。传统文本之类验亦过。

此包今备 WHATWG 诸码及官标签二百二十八，增 Big5、EUC-JP、Shift_JIS、EUC-KR、ISO-2022-JP、单字节诸码、replacement 及 x-user-defined，亦受 UTF-32 两端。标签依七位字母大小与首尾空白归一。

`新文本解码态` 受码名与严爻；`解码文本块` 受态及字节块，还可有之态与文；`终结文本解码` 出余文。态存未足字节与日文转义之模式。`新文本编码态`、`编码文本块`、`终结文本编码` 供分块编文，日文转义终而返 ASCII。统一文本之口依标签定端，去首 U+FEFF，存后续 U+FEFF。

`工具/全部索引生成。豫` 次第调索引生成器，生官表三十四，含映射及范围记录七万六千九百八十一。`工具/标签生成。豫` 读官 encodings.json。诸源 SHA-256 存 `官方来源SHA256.txt`，官试许可存 `官方测试许可.txt`。
