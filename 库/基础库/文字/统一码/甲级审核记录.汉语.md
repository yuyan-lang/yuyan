# 统一码甲级审核记录

2026-10-08 按提案 00004 第四节「统一码」的必须有项及第五节甲级定义逐项审核。结论为甲级达标；乙级继续执行完整资源、性能、平台与迁移验收。

## 功能、数据与依赖

| 必须项 | 实际实现与依据 |
| --- | --- |
| 当时最新字符数据库 | Unicode 18.0.0，官方稳定版于 2026-09-16 发布；生成器读取仓外 `豫言数据/统一码/18.0.0`，生成一般类别、文字、东亚宽度、行断、字素词句、双向、组合类、分解、大小写、折叠、表情等属性表 |
| 四种规范化 | `文字规整` 提供 NFC、NFD、NFKC、NFKD；`规整` 实现递归分解、稳定组合类排序、组合阻塞及算法式谚文拆合 |
| UAX 29 | `切分` 提供字素、词、句字符串片段与码点边界，分别采用最新字素、词与句属性 |
| 大小写及折叠 | 使用完整无条件特殊映射、默认标题映射及 CaseFolding；条件小写读取原文 Cased/Case_Ignorable 上下文，标题保留全文上下文；展开映射按原序尾递归累积 |
| 东亚宽度 | `码点列宽` 读取官方 EastAsianWidth 与一般类别；`文字列宽` 按字素最大列宽累加，涵盖宽字、组合记号、连接表情与地区旗帜对 |
| 纯库闭包 | 统一码直接依赖标准库与两数据包；两数据包仅依赖标准库，生产计算使用豫言实现；父文字基础库登记统一码及排序数据，统一码登记自身数据子包 |
| 说明及许可 | 包说明双稿已列功能、实际模块签名、默认规则、后续事项、来源与 Unicode 数据许可；`数据许可.txt` 保存 Unicode License V3，版权为 1991—2026 Unicode, Inc. |

额外 LineBreakTest 19,346 例在相同切分客体两端也为零失败。官规范化驱动加入独立负控制 `0041;0042;0043;0044;0045;`，两端均报告一例失败并退出 1，证明错误期望会触发失败。

规范化诺节为 68.56 秒墙时、28.95 秒用户 CPU、最大常驻 104,742,912 字节；原生为 73.32 秒墙时、38.58 秒用户 CPU、最大常驻 1,137,950,720 字节。切分四官集诺节为 1.44 秒、最大常驻 110,936,064 字节；原生为 0.92 秒、最大常驻 302,841,856 字节。上述为完整驱动生命周期，包含读取与对照。原生资源差距如实保留，后续向原生工具链目标交付测量依据。

原始日志位于 `/private/tmp/yy统一码甲规整{诺节,原生}.log`、`/private/tmp/yy统一码甲切分{诺节,原生}.log` 及同前缀的各短测试日志。整包类型日志为 `/private/tmp/yy统一码甲整包类型.log`。全部过程实际结束后的退出码已逐个收取。

## 首使用者及适配

行编辑提交 `fd89710c4` 的 `编辑。豫` 直接导入 `统一码/切分` 的字素切分，`展示。豫` 直接导入 `统一码/列宽` 的文字列宽。消费驱动直接读取官方 853 例期望，逐次向左移动并比较原始码点边界，在诺节及同源 16c 原生均零失败。随后真实终端会话 `861f41526` 的 42 状态、8 消费者及 6 布局测试在 25a 与 E44/E801 同源原生均通过。此处作为统一码首消费证据，行编辑整体等级独立审核。

`豫言操作系统文字规整共用适配` 直接依赖统一码，重导出本库完整小写与文字判别能力，供原生和裸机执行器接线。裸机实际运行及其它旧适配迁移继续列入乙级验收。

同一文字客体在 Chrome 现有浏览器宿主运行 22 断言，通过页面实际输出 `统一码文字测试通过`，退出码 0、40 毫秒，作业结果 `ok:true`；此为额外抽样证据。
