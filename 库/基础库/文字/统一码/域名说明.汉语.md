# 域名编码

`域名码编码` 将统一码标量列表编码为 RFC 3492 Punycode。`域名码解码` 将 Punycode 解码为标量列表。接口处理不带 `xn--` 的载荷，基本 ASCII 字符按原次序保留，编码器输出小写数字字母。

数据与算法出处：[RFC 3492](https://www.rfc-editor.org/rfc/rfc3492)。

`国际化域名` 模块提供 `域名转基本` 与 `域名转统一`，接收字符串并返回“转换后的字符串、错误标志”；错误标志为阳表示转换失败。默认使用非过渡处理，检查双向与连接符，适用于 WHATWG 网址主机转换。

`域名按选项转换` 接收选项整数、基本输出开关与输入字符串。选项按位相加：STD3 为 1、连字符为 2、双向为 4、连接符为 8、过渡为 16、DNS 长度为 32、忽略非法 Punycode 为 64。Unicode 输出保留可转换内容并标记错误。`国际化域名核心` 提供可注入属性与规范化查询的算法。

`码点` 模块提供 `字符串码点` 与 `码点字符串`，以纯豫言读写 UTF-8，检查截断、冗长编码、代理码点与标量范围。

`域名状态表`、`域名映射表` 来自 Unicode 18.0.0 的 [IdnaMappingTable](https://www.unicode.org/Public/idna/latest/IdnaMappingTable.txt)，下载日期 2026-10-07。数据使用 [Unicode 数据许可](https://www.unicode.org/license.txt)。表格由统一码包的 `属性生成` 豫言工具生成，状态取字段 1，映射取字段 2，模式均为 0；输入保存在仓外数据目录。

协议样例检查大小写映射、过渡与非过渡规则、ACE 解码、ContextJ、双向标签、连字符、DNS 长度以及 UTF-8 标量边界。官方 IdnaTestV2 一致性测试驱动另行运行。
