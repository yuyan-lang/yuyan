# 文字整形

开放字型字形替换、定位与复杂文字整形。输出字形号、横纵前进、横纵偏移与输入码点簇序。位置以六十四分之一像素计，横向右、纵向上为正。簇序从零开始，对应原输入码点序号；右向左段输出视觉顺序。

`整形文字` 接受字体、像素字号、码点列表与方向标签；方向取 `ltr`、`rtl`、`ttb`。`整形文字参数` 另接受文字、语言与特性标签。排版库按字体回退切分后调用此接口。

排版表按 [Microsoft OpenType 排版表规范](https://learn.microsoft.com/en-us/typography/opentype/spec/chapter2) 与 [字距表规范](https://learn.microsoft.com/en-us/typography/opentype/spec/kern) 解析。数据由调用者提供的字体携带。竖排读取 vmtx 名义前进，以 VORG 或字形边界取得纵向原点，缺表时使用字体高度。

查找执行包括 GSUB 八类、GPOS 九类与上下文三种格式。阿拉伯连接选择逐簇启用起始、中间、末尾与孤立特性。文字预处理保持原簇，支持印度前置元音、分裂元音与雷法、缅甸金齐、高棉前置辅音。旧字体通过 kern 表取得字距。

GPOS 查找依字体的 GDEF 分类与 LookupFlag 过滤，支持忽略类、标记附件类与标记筛选集合，嵌套查找各用自己的标志。显式组件入口可指定标记所附的连字组件。

实现使用「统一码」包的官方属性与扩展字素边界，并经「字体取表」取得当前字面排版表。GSUB 依 GDEF 过滤并传递组件来源，右向左反转前换算簇内横偏移；Arial 四个 HarfBuzz 参考向量已通过，核验范围见[后续实施记录](后续实施记录.汉语.md)。

后续版本事项：复杂上下文的组件来源覆盖、设备与变体修正、完整 USE 属性状态机。

后续候选在实际 GSUB 查找中记录多重替换输出身份和连字消费组件，同时传递跨阶段原预处理来源。私有设备读取器解码二、四、八位像素增量，定位值与格式3锚点接入像素修正。变体候选读取真实GDEF项目变体存储，复用字体求值器与默认fvar/avar坐标。USE 阶段接线与候选验证进展见实施记录。

后续验收包括真实字体的 HarfBuzz 对照、百万变异输入、原生与裸机测试及性能测量。当前提交为实现阶段，甲乙验收仍待上述事项。
