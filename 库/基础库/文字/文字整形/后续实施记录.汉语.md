# 文字整形后续实施记录

正式阶段已通过主接口、GSUB 八类与 GPOS 九类合成测试。后续源码以正式 `yybs` 为基线继续；以下各项已完成源码整合，验证窗口由根代理统筹。

| 项目 | 源码与验证安排 |
| --- | --- |
| 统一码预处理 | 使用统一码属性包的连接类、印度音节类、印度位置类与扩展字素边界；字形保持原字素簇，破损音节补圆点 |
| 文字选择 | 按官方 Script 属性选择文字标签，印度文字选择字体实际提供的排版表 |
| GSUB 过滤 | 每个查找使用自身 GDEF 与 LookupFlag，回插忽略字形，保存连字标识与零起组件序 |
| GPOS 组件 | 主接口把 GSUB 组件序交给标记到连字定位 |
| TTC 与竖排 | 通过字体库的当前字面表目录取表，读取 vhea/vmtx 名义前进量，依据 VORG 或字形边界求纵向原点；竖排选择 vkrn |
| 查找次序 | 合成与语言特性先行，再执行连接形与后续特性；各阶段去重并按查找序执行 |

真实字体用例来自本机 HarfBuzz 12.3.2 对 `/System/Library/Fonts/Supplemental/Arial.ttf` 的输出，字体 SHA-256 为 `525979822591a3447cfc49d943d6f7683508e25543407871c0ed8fed05fd2bd9`。向量仅记录字形、簇及位置，字体由运行环境提供。`测试/参考整形对照.tsv` 保存 AV 字距、阿拉伯连字、希伯来附标及 AV 竖排向量；`测试/真字体。测试。豫` 在对应样本环境中逐项对照。竖排原点算法参照 [vmtx 规范](https://learn.microsoft.com/en-us/typography/opentype/spec/vmtx) 与 [VORG 规范](https://learn.microsoft.com/en-us/typography/opentype/spec/vorg)。

HarfBuzz 的希伯来过程把辅音点排在元音点之前。后续源码据此使用整形组合次序，阿拉伯重辅音符也先于元音符；统一码规范化沿用统一码包的官方组合类。算法资料见 [HarfBuzz 组合类说明](https://github.com/harfbuzz/harfbuzz/blob/main/src/hb-unicode.hh) 与 [希伯来整形器](https://github.com/harfbuzz/harfbuzz/blob/main/src/hb-ot-shaper-hebrew.cc)。

下一验证窗口依次执行公开总集类型检查、过滤组件合成测试、预处理回归与真实字体向量。字体驱动的印度后置重排、完整 USE 一致性、设备与变体调整、百万变异输入、原生与裸机验证继续按提案推进。甲乙验收依全部门槛核定。
