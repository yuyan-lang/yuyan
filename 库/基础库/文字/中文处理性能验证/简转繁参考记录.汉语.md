# 简转繁同机官方参考冷进程测量

2026-10-08，在 Apple M5 Pro、arm64、Node v26.3.0 上顺序测量 OpenCC CLI、诺节客体及同客体原生程序。新增入口 `简转繁冷测。脚本。豫` 以纯豫言读取一个固定输入文件，调用既有 `转繁体`，写出结果；生产接口及正式数据保持原样。

## 参考来源与范围

仓外参考为 `/opt/homebrew/bin/opencc`，实运行 `--version` 得 `1.4.2`。来源为 [OpenCC 官方仓库](https://github.com/BYVoid/OpenCC) 与 [Homebrew 官方 opencc 配方](https://formulae.brew.sh/formula/opencc)，OpenCC 官方许可为 Apache-2.0。此次通过本机已安装 CLI 运行参考，项目运行依赖保持豫言自有库。

固定输入为既有 `中文处理/测试/官方/简转繁输入.txt`，870字节，SHA-256 为 `918841ded96e47bd39ac5a7ddb2042ba2f43b2a4467b8f9946d4e8af3c92a965`。三种程序均处理同一个文件一次并写输出；OpenCC 使用 `s2t.json`。

测量为新进程启动至退出的整体时长，包含各自程序加载、词典初始化、读文件、转换和写文件。豫言简繁模块在启动阶段初始化其现有各组转换索引，OpenCC CLI 按指定配置初始化。表格对应当前实际冷进程使用成本；内循环热点性能另行测量。

## 实际结果

三种程序均退出0，两个 `cmp` 均退出0。诺节和原生输出皆打印 `简转繁冷测 输入字节=870 输出字节=870`。三份输出的 SHA-256 均为 `45bb03649193b78798d196f208acdad6ab28716e909fa50459ec10a548934f18`。

资源来自 macOS `/usr/bin/time -l`。它的秒数输出保留两位小数，短 CLI 时间及倍数受此分辨率影响，倍数取近似值。此阶段每实现测一次，程序间顺序运行且本任务原生生成器已退出；机器上其他任务仍可能影响调度。此表记录生命周期峰值常驻而非采样值。

此次原生冷进程相对官方 C++ 实现 CLI 约111.6倍，超过提案第二批五倍目标。差距记入后续原生工具链与正式数据初始化优化事项，依提案性能条继续合入阶段结果。该项仅为简转繁冷进程比较；分词、全拼与内循环热性能继续沿用各自证据，系统实现热性能后续测量。
