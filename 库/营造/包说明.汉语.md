# 构建基础

提供包定位、上下文与异步构建调度。

## 包身份

所有者：豫言。包版本：0.1.0（本轮初始包版本，不代表编译器命令行版本）。

本包为库类型，可被其他包依赖；模块按包名和包内路径访问。本包没有程序入口和文件名；默认构建编译库模块而不链接程序，测试或示例须显式指定模块。

## 模块

- 包定位、包上下文：发现包与写包上下文。发现前先确认项目目录与外部包目录是目录：不是目录、读不到，或行在的附庸表里没有它（附庸表以外的路径连列目也看不见，看起来与不存在一样）时报错，写明目录与出路（放进工作树或 /tmp，或设 `豫言附`、`豫言全宿主=1`）。包上下文一律写第五版；读到旧日带“文体”一列的第六版时略去这一列。存放目录（`.豫构缓存/豫构上下文`）里的上下文头一次启用时，旁边另写一份境检（包上下文二进制索引，`号.上下文。境检`）：记着上下文原文、仓库根前缀和每个包的目录、身份与预先算好的缓存号，目录按散列分桶。此后每个编译任务启用这份上下文时只读境检，按目录查所属包与缓存号，整份文本到真要用（如导入解析）时才解析；境检缺了、坏了或记的原文与上下文不符时照旧解析文本。
- 模块定位（`访包。豫`）：按包名与包内路径找模块文件；包根之后的目录段逐段查符号链接，经符号链接的包内模块报“包内模块不能通过符号链接或非规范路径访问”，紧随其后的真实路径比较再拒非规范路径，原生与诺驿宿主同报此句。
- 调度器：构建任务图的并行调度；每个任务记录加入、就绪、开始、结束四个时刻与开始时的在途数。调度开销与任务数成线性：任务完成只唤醒等它的下游，就绪任务进按（优先级，加入次序）排的最小堆，每轮只看在途任务与新加入的任务；运行中任务图匣当收件箱用，每轮取空，结束时按加入次序写回全部任务。无面板调度在队列空时至多每 200 毫秒复查一次子进程完成状态，即使子进程没有输出。
- 并行编译、构建监视：编译器的阶段任务图与终端监视面板；完成进度条由终端界面库生成。
- 交役（`交役。豫`，提案 00035）：构建服务客户端。并行编译开头「探将作」找本机构建服务「将作」（没有就在后台起一个），此后「将交役」把每个任务交服务：一个客只开一条连接（多路复用），先登门（令牌、客号、工作目录、工具链的编译语义号、全部环境变量，带“合门”），服务答“门合”后，每个任务一行交役、带客内序号“序”，服务交该工具链的代役执行，答一行役毕（退出码与两路输出，也带“序”），客按序号分给各任务；登门里的编译语义号由编译器的入口（译场主）经「将作设语义号」写好，将作只把语义号与受托同僚相同的编译阶段任务外派，旧客不带语义号、任务只在本机执行；五秒内没答“门合”的旧服务，退回每个任务一条连接；服务答自行时它已给本任务留出一个槽，客在本机执行，执行完在同一连接上答自毕还槽。服务起得慢就等（三秒后印一行提示），起不来就一直等（每三十秒重起一次服务、印一行提示），不退回本机全速执行；连接出错先重交，再出错同样等到服务回来。服务明答“令牌不符”、不认本构建的令牌时不再重试：照常的构建印出 HOME 与令牌路径，并译报“构建失败”后退出，提示设 `豫言将作=关`，或用与将作同一个 HOME；设了 `豫言将作=关` 的构建照服务不在的办法在本机直接执行（印一行说明）。旧服务不答这一行，与连接暂断一样照旧重试。客等任务超过三十秒没有进展时，服务发来一行提示（排队数、在跑数、等的任务），客印到标准错误（每次构建一行），任务照旧等。一条连接上等过三十秒没有答复时（议题 #206），并行编译的主循环在「将作对账」里从那条连接上送一行问客役，列出在途任务的序号与任务名（共用连接上的任务带序号，每任务一条连接的任务不带，服务按任务名认），服务只答哪些在排队、在跑、借行（借槽任务已由客在本机作它），哪些不认识：不认识的照连接出错处理、重交；服务连本客也不认识（登门记录丢了）时先重送登门行，再重交；借槽任务的“自行”答复丢了（服务说这件还在借行），就地在本机执行并照常答自毕还槽。全进程每三十秒至多问一次；旧服务不答这一行，客照旧等。消息都是一行数据子语言（籍册，「将作成牒」「将作析牒」），服务与代役共用这里的读行、写尽、令牌等函数。CI 环境、`.wasm` 编译器不用服务；`豫言将作=关` 时只借槽：交役带“借”栏，服务只排槽、不派代役，任务都在本机执行（将作不在也不起它）。用服务时并行编译同时交出的任务放宽到 `-j` 的两倍加八，多交的在服务里排队，本机槽满时便有任务可托给同僚。工作任务一侧另有两件（提案 00035 第四、五步）：「将作取键」在共享缓存未命中时，若本机将作有在线同僚（会合点下有“同僚在”标记）且本任务是托出办成后的重放（环境变量 `豫言将作邻取`），请服务向同僚要这一键与产物，再不然按 `豫言将作远作` 向云端缓存要；「将作取引」在替同僚执行任务（环境变量 `豫言将作借场` 有值，即借场）时，缺的阶段缓存文件与源文件向托主要，取来写到镜像根下的原位，访包的「实径」与包境的「启包境」借它补源文件。
- 构建日志：把构建事件写进半永久的日志目录（依赖结森工具写 JSON），格式见[构建日志格式](../../应用/度量/构建性能/日志格式.汉语.md)。
- 构建宿主（`构建宿主。接口。豫`）：宿主服务包括存放包上下文、可绘监视面板、绘监视面板、获取当前程序 SHA-256 和获取文件 SHA-256，以及装载单元用的单元现况、单元存、单元并入、单元带型码、单元装代码与单元运行（提案 00003，原生执行器原语 186–191，豫构的「运行」经 裸机后端 的 单元装入 调用；诺驿与浏览器宿主只供单元现况，报“可用”为零，其余没有这些函数）。获取当前程序 SHA-256 返回程序内容的身份：Node 上是 Wasm 文件内容的 SHA-256，编译器直出的原生程序与由汇编树码造的豫行文件是程序汇编树码的 SHA-256（提案 00007 收尾），所以原生编译器与 Node 上的 .wasm 编译器各用各的编译缓存目录；获取文件 SHA-256 返回指定文件内容的 SHA-256。它们编成导入模块“构建基础”的带类型导入；模块名不叫“宿主”，免得与标准库的“宿主”模块同名而互相遮蔽。

## 使用

并行编译完成前端任务并写出任务耗时与依赖记录后，清空已完成的调度任务图，释放回调与异步结果；最终链接使用文件依赖图，阶段总量由已知文件计算。

并行编译支持最终链接参数交接。调用方通过编译器参数 `--链接参数输出 文件` 指定结森文件，前端完成后写出工作模式的链接参数并退出；豫构在裸机宿主上读取此文件，再启动最终链接，使前端进程的整份堆先归还。豫构起最终链接时再加 `--原生参数输出 文件`：大客体要另起原生生成时，最终链接只写出客体文件与原生生成参数就退出，豫构接着起原生生成（同一编译器加 `--原生产物子进程`），完后删掉客体与参数文件，最终链接进程的整份堆也先归还。宿主上单程序编原生可执行文件时，前端自己也做这份交接（议题 216）：给最终链接加 `--原生参数输出`，客体超过 7 MiB（子进程生成下限）时最终链接只写出客体文件与原生生成参数就退出，前端接着起原生生成子进程，完后删掉客体与参数文件；小客体照旧在最终链接进程里就地生成，不额外起进程。这样最终链接与原生生成不同时活着，峰值取两者大的一个。裸机与多程序构建的交接由豫构做（裸机一直如此，宿主多程序自 2026-10-17 起）。写 `.wasm` 的程序仍由编译器在自己的子进程里链接。

在仓库根目录运行：

```sh
./豫构。林檎。豫行 检查 构建基础
```

## 程序标识

`程序标识。豫` 给出本程序的摘要「本程序沙二五六」：编译缓存目录名、装载单元缓存键与单元目录印记都用它。缺省是构建宿主的「取今程序沙二五六」；豫言操作系统的开机程序（提案 00003 第 8 步）开机时把「程序沙二五六覆盖」设成盘上 /工具/豫构。豫行 的摘要（造盘时写在 /工具/豫构。豫行。摘要），与它共用编译缓存。
