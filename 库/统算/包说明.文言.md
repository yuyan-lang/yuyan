# 统算

此乃英伟达统算（CUDA）驱动之口之豫言封装，以供他日张量之统算后端。此库由 `库/系统库调用` 径调驱动之库 libcuda（`libcuda.so.1`）之驱动之口，诸理皆书于豫言，诺节宿主惟供通用之系统库调用原语。此库不用运行时之库（cudart）、NVRTC、cuBLAS、cuDNN 诸厂商之库，亦不经 C 与 C++。

此库无核之源。核以 PTX 之文付 `「载入统算模块」`，驱动当即编为本器之码。PTX 由着色语言译出（着色语言之规“着十：统算之的”）：高级之代导着色之源所得之模之「PTX源」与“入口项名PTX名”之常量，分付 `「载入统算模块」` 与 `「取统算函数」`；发射之时每块之线取工作组之大，参依次为入口所用诸缓（依组号、绑号升序）之「统算显存参」。「着色库测试」之 `统算运行。测试` 即如此行加倍、求和、缩放三样例。

## 包之身

所有者：豫言。包之版：0.1.0。此包为库，依标准库与系统库调用，登于「共用库」之下。「平台」惟列诺节之林纳克斯，系统库 `libcuda.so.1`。

## 所须

林纳克斯之上具英伟达之显卡与驱动（有 `libcuda.so.1`），不须统算之工具包（nvcc）。宿主须能调系统库：工具宿主自开；应用宿主须予 `--允许系统库调用`（见 `豫言操作系统/宿主/节点/说明.文言.md`）。`「统算可用」` 为阴，则勿调余函。待办事项：视窗之驱动为 `nvcuda.dll`，无器可验，暂不支。

## 模

| 模 | 所含 |
| --- | --- |
| `驱动` | 开 `libcuda.so.1`、依名取驱动之函（址存于调处顶层之引格；参不逾六之函初调则登为柄，后依柄号调之，免每调以签名之文与参之列授宿主）、察果码、出参暂存之区、误名与误述、初始、驱动之版 |
| `设备` | 器数与 `「统算可用」`、依序取器、名、显存总量、属性与算力；主上下文之留、设为当前、释；上下文之同步；显存之余与总 |
| `显存` | 分与释、原生之存与显存相抄、显存相抄、依字置值、以字节串往返 |
| `流` | 流（阻塞之流、传统默认之流、同步、毁）与事（新建、记、同步、间隔之毫秒、毁） |
| `内核` | 以 PTX 之文载模（败则附 JIT 之误志）、卸模、取核函、依参列发核 |

## 用法

```yuyan
寻观「统算」之书。
```

- 器：`「统算可用」`、`「统算设备数」`、`「取统算设备」于 序`、`「统算设备名」`、`「统算设备显存」`、`「统算设备属性」于 器 于 属性号`、`「统算计算能力」`（主次之版号）、`「统算多处理器数」`、`「统算每块最多线程」`、`「统算驱动版本」`（若 13020）。
- 上下文：`「取统算主上下文」于 器`（留器之主上下文而设为今线之上下文）、`「设当前统算上下文」`、`「同步统算上下文」`、`「释放统算主上下文」`、`「统算显存空闲与总量」`。
- 显存：`「分配统算显存」于 字数` 得「或可有」于「统算显存」（显存不足则可无，不清零）；`「释放统算显存」`；`「复制到统算显存」于 显存 于 原生之址 于 字数`；`「复制到原生内存」于 原生之址 于 显存 于 字数`；`「统算显存间复制」于 的 于 源 于 字数`；`「统算显存置字节」于 显存 于 字值 于 字数`；`「字节串到统算显存」`、`「统算显存到字节串」`（一次不逾宿主值桥之限十六兆字）。字数逾显存则以事故终。
- 核：`「载入统算模块」于 PTX之文` 得「统算模块已载入」或「统算模块载入失败」（附误名、误述与 JIT 之误志）；`「取统算函数」于 模 于 名`（PTX 中 `.entry` 之名）得「或可有」于「统算函数」；`「发射统算内核」于 函 于 网格宽 于 网格高 于 网格深 于 块宽 于 块高 于 块深 于 动态共享之字数 于 流 于 参列`；`「卸载统算模块」`。参为「统算显存参」「统算整数参」（三十二位）「统算长整数参」（六十四位，亦可传既加偏移之器址）「统算单精度参」「统算双精度参」，其数、类与序须合 `.entry` 之参（驱动不核）。封装书各参值于原生之存（各八字），乃拼为驱动所需之 `void**` 之组，一发至多四千零九十六参。
- 流与事：`「新建统算流」`、`「默认统算流」`、`「同步统算流」`、`「销毁统算流」`；`「新建统算事件」`、`「记录统算事件」于 事 于 流`、`「同步统算事件」`、`「统算事件间隔毫秒」于 始 于 终`（计于 GPU 之侧）、`「销毁统算事件」`。
- 误：`「统算错误名」于 码`（若 `CUDA_ERROR_OUT_OF_MEMORY`，码不识则曰“未知错误码 N”）、`「统算错误说明」于 码`。余驱动之调有误，则以事故终，其辞若“统算：cuMemcpyHtoD_v2 失败：CUDA_ERROR_INVALID_VALUE（invalid argument）”。

慎之：

- 驱动所出新版之函缀 `_v2`（`cuMemAlloc_v2`、`cuMemFree_v2`、`cuMemcpyHtoD_v2`、`cuMemcpyDtoH_v2`、`cuMemcpyDtoD_v2`、`cuMemsetD8_v2`、`cuMemGetInfo_v2`、`cuDeviceTotalMem_v2`、`cuStreamDestroy_v2`、`cuEventDestroy_v2`、`cuDevicePrimaryCtxRelease_v2`），无缀之同名者旧三十二位之口，不可用。此库依名取所出之符号，不用 `cuGetProcAddress`：宿主惟认经取符号所登之址。
- 同步之抄与置行于传统默认之流。`「新建统算流」` 所建者阻塞之流（标志零），与传统默认之流相候，故发核之后径 `「复制到原生内存」` 亦得其果。非阻塞之流与异步之抄未封。
- 主上下文，每进程每卡一；驱动之调施于今线之当前上下文，宿主于一线行豫言之程，故设一次可也。
- PTX 之文惟许 ASCII 之字，注中亦然，否则 ptxas 报“Unexpected non-ASCII character”。于 RTX 5090（算力 12.0，驱动 595.91.07，统算 13.2），自 `.version 6.0 .target sm_52` 至 `.version 9.2 .target sm_120`（及 `sm_120a`）皆可即时编之，驱动一编为 sm_120a。
- 驱动存即时编之果于 `~/.nv/ComputeCache`；欲勿书之，设环境变量 `CUDA_CACHE_DISABLE=1`。

## 张量之存入显存

张量之存为诺节宿主之 SharedArrayBuffer（`「张量存储原生地址」` 取其原生之址），乃寻常可分页之主存，不可径作显存。今之法为抄：`「分配统算显存」` 之后以 `「复制到统算显存」` 自张量之存之址（加视图之起之字偏）上传，算毕以 `「复制到原生内存」` 读回；张量常驻显存，主机欲读乃下之。所传者巨，可以 `cuMemHostRegister_v2` 锁张量之存之页（实测 SharedArrayBuffer 之址虽不齐于页亦可登），抄之带宽自可分页之存约九至十八 GB/s 升至约二十二至二十四 GB/s；锁页须于张量释前解之。待办事项：锁页与映射（`CU_MEMHOSTREGISTER_DEVICEMAP`，核经总线径读主存）暂不封。

## 实测（二〇二六年九月三十日，RTX 5090，驱动 595.91.07，诺节 26.10.0，工具宿主）

时显卡并为他进程所占（显存约二十九 GB、算力八成八至九成），GPU 之侧之时受时片之调所制，下之数偏大而多动，惟供量级之参。“经豫言”一栏以此库行草稿之目中手书之 PTX（向量加四千零九十六元、64×64 单精之矩阵乘，果皆对），“诺节”一栏径以 `node:ffi` 调同驱动之函。

| 项 | 经豫言 | 诺节 |
| --- | --- | --- |
| 空核往返（发核加流之同步） | 八十八至一百四十六微秒 | 三十至一百一十四微秒 |
| 空核往返（默认之流，发核加上下文之同步） | 四十九至二百三十七微秒 | 五至一百零六微秒 |
| 空核惟发（不同步） | 六至十四微秒 | 一点五至二微秒 |
| 最简驱动之一调 | 二点五至七点七微秒 | 零点一五至零点一七微秒 |
| 64×64 矩阵乘（发核加流之同步） | 九十一至二百七十八微秒 | 约一百四十微秒 |
| 64×64 矩阵乘往返（二上传、发核、同步、下载） | 三百七十四至五百零一微秒 | 二百四十四至三百二十微秒 |
| 百次矩阵乘连发，事之计时均每次 | 十一至三十三微秒 | 三点九微秒 |
| 十六兆字可分页之存上传／下载 | 十六点九至十七点八／十点七至十二点八 GB/s | 十七点四／十三点三至十三点五 GB/s |
| 十六兆字锁页之存上传／下载 | 未封 | 二十二点五／二十二点九至二十三点九 GB/s |
| 即时编而载此三小核（去其存） | 十点六至十点八毫秒 | 六点五毫秒 |

经豫言之一调，较径用 `node:ffi` 多数微秒，耗于豫言之侧组参列、值桥与宿主依签名之转；发一带四参之核须九越宿主（每参书值、书指各一，又加发核）。连发之时，GPU 毕一 64×64 矩阵乘惟约四微秒，速于豫言之一发，故“经豫言”一栏之事之计时所见者发核之间隔也。彼机之卡行 PCIe 5.0 ×8，锁页之存约二十二至二十四 GB/s，已近其限。

## 限

待办事项：视窗（`nvcuda.dll`）；非阻塞之流、异步之抄、锁页与映射之主存；逾八字之结构之参；JIT 之信息志与余 JIT 之选；驱动之调有误一以事故终，他日依需改为返果；毕事之回调（`node:ffi` 之回调惟可于造之之线调之）未支，一以同步候之；矩阵乘等较大之核之试，俟着色语言之张量内核之库成乃补。
